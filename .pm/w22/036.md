# The off state of the app's switches is drawn at 1.72:1 (light) and 2.45:1 (dark) against the page, and `trackColor.false` does not set the fill it was written to set

**Trivial · mobile · 15–20m · A2.** Native mobile QA, 2026-11-10, repository HEAD `59f13b939`, development build `io.beancount.ios` 1.20261002.50 on iPhone 17e / iOS 27.0, English, signed in as the QA account on its synthetic `example` ledger. Read-only pass: the switch was looked at and **never toggled** (its state is stored on the device). Found while testing Increase Contrast, which changed nothing in the app (below). The state is still distinguishable (a thumb at the other end, and the on state is green), so this is a margin below the app's own bar, not a missing cue.

## Repro (measured on the rendered screenshot, 1170×2532)

1. Drawer → **Merchants** → any merchant (for example the first row) → the **Recurring** row's switch, left in its off state.
2. Measure the switch's off track against the page behind it.

| theme | page | off track | thumb | track vs page |
| --- | --- | --- | --- | --- |
| light | `#ffffff` | `#c5c5c7` | `#ffffff` | **1.72:1** |
| dark | `#171a14` | `#565857` | `#171a14` | **2.45:1** |

**Expected:** the app's own standard for a control's boundary is 3:1 (`mobile/src/common/theme/palette.ts:66-92`, `controlBorder` is 3.67:1 in light and 4.07:1 in dark, and `control-contrast.test.ts` pins it). A switch in its off state is a control boundary.
**Actual:** 1.72:1 and 2.45:1. In light mode the white thumb on the grey track is the same 1.72:1, so the thumb itself is faint.

**Increase Contrast** (`xcrun simctl ui <udid> increase_contrast enabled`, cold launch): Home is pixel-for-pixel the baseline (8.8 million channel values compared against the same screen with the setting off, below the status bar and above the floating tab bar: 0 differ). The app draws its own colours and reads only Reduce Motion and the screen reader from the OS (`use-reduce-motion.ts`, `receipt-capture-screen.tsx:75`), so the setting has no effect on it. That is a gap by omission, not a defect found here.

Evidence is local only (`.tmp/qa-20261110/w22k/`): `01-home-ic.png`, `02-merchant-detail-light.png`, `03-merchant-detail-dark.png`.

## Root cause

`mobile/src/screens/merchant-detail-screen/merchant-detail-screen.tsx:676-686` passes `trackColor={{ false: theme.black20, true: theme.primary }}` and `thumbColor={theme.white}`. React Native iOS maps `trackColor.false` to the native switch's **`tintColor`**, its outline (`node_modules/react-native/Libraries/Components/Switch/Switch.js:279`, `RCTSwitchComponentView.mm:87-89`), and the off-state **fill** to a separate prop, `ios_backgroundColor` (`Switch.js:270-273`), which these call sites do not set. So the fill is iOS's default grey, which is what the screenshots show (`#c5c5c7`, not `black20`'s `#eeece2`), and the token written for the off track is applied only to the outline, where it is 1.18:1 against white and effectively invisible. The same props are on `create-ledger-screen/create-ledger-screen.tsx:397-400`; the third switch, in `components/text-input-modal/index.tsx:289`, sets no colours at all. In dark mode `thumbColor={theme.white}` is the near-black page colour, so the thumb is the same colour as the page.

## Fix

Set the off-state fill explicitly: `ios_backgroundColor={theme.controlBorder}` (3.67:1 on white, 4.07:1 on the dark page) and `trackColor.false` to the same, so fill and outline agree; keep `trackColor.true` and the thumb. Check natively in both themes that the thumb stays distinguishable from the track (a `controlBorder` track with a `white` thumb is 3.67:1 in light; in dark the thumb is the page colour on a `controlBorder` track, 4.07:1). Add the three call sites to `control-contrast.test.ts` as a source guard that a `<Switch>` sets `ios_backgroundColor`, and the measured pair to the contrast cases. Mobile only; no API surface.

## Blast radius

The three switches: the merchant Recurring toggle, the create-ledger screen's switch and the text-input modal's toggle (the last on the system defaults, so its look is iOS's). Only the merchant one was seen on a device; the other two were not opened.

## Adjacent states

The on state (green `#307d04` on white, 5.17:1, unchanged), disabled and pressed states, and Android (`trackColor` is the track there, so the same props behave differently).

## Dedupe

Searched `.pm/**` (including `done/`) for `trackColor`, Switch, toggle with contrast, track and 1.4.11. `w2/done/066` and `w22/027` are the weak-token icon colours; `control-contrast.test.ts` and `palette.ts` cover fills, borders and placeholders. Nothing covers the switch.

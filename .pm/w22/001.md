OFX single-account check misses mixed-case ACCTID tags.

The engine's multi-account refusal scans the raw text with upstream's
case-sensitive `<ACCTID>` regex, but the soup parser lowercases tags, so
a file mixing `<ACCTID>1` with a differently-cased second account id
would import both statements under one `--account` instead of refusing.
Spec-violating files only (OFX tags are uppercase), so rare; when fixed,
case-fold the scan in `cli/src/bea_engine/ofx_importer.py` and mirror it
in the frontend memory key (`_ofx_acctids` in
`cli/src/cli/commands/import_.py`).

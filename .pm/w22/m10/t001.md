## Objective

Add a pure function that decides what "set this target account for the selected rows" does, so the control in t002 is a thin wrapper and the rules are unit-tested without rendering. Given the selected row ids, the current target map, the chosen account, and a mode, it returns the new map plus how many rows it set and how many it left alone.

## Context

- Package: `dashboard/` (see `dashboard/AGENTS.md`). Feature code, helpers, and tests stay inside `src/features/plaid/`.
- The review table keeps targets in `useState<Map<string, string>>` keyed by the row's `id` (`src/features/plaid/components/transaction-review-table.tsx`). Submit acts on every selected row, visible or not, so the helper takes ids, not the filtered list.
- Modes: `fill-blank` (default) sets only rows whose current target is empty or missing; `overwrite` sets every selected row.
- An empty chosen account must be a no-op, never a way to clear targets.

## Steps

1. Add `src/features/plaid/utils/apply-target-account.ts` exporting the function and its mode type.
2. Return a new `Map` (never mutate the input) with `applied` and `kept` counts.
3. Add tests under `src/features/plaid/utils/__tests__/`: fill-blank keeps a hand-picked and an AI-suggested target; overwrite replaces them; ids that are not selected are untouched; ids hidden by a filter are included because the helper never sees the filter; an empty account changes nothing; the input map is not mutated.

## Files

- `dashboard/src/features/plaid/utils/apply-target-account.ts`
- `dashboard/src/features/plaid/utils/__tests__/apply-target-account.test.ts`

## Acceptance criteria

- [ ] `fill-blank` never replaces a non-empty target; `overwrite` always does.
- [ ] Only the ids passed in change; counts match the rows changed and kept.
- [ ] The input map is not mutated and an empty account is a no-op.
- [ ] `yarn test` passes for the new file from `dashboard/`.

## Out of scope

- The control, translations, and any API change.

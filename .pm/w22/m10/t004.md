## Objective

Prove the control in the running dashboard, not only in component tests: with several staged bank rows, one of them hidden by a filter, select all, set one target account once, and submit in a single action.

## Context

- Use the dashboard QA workflow (`.agents/skills/qa-find-bugs-dashboard/SKILL.md`, shared helpers in `.agents/skills/qa-shared/`): headless Playwright with `QA_EMAIL` and `QA_PASSWORD`.
- The check needs a ledger with a connected bank and staged (unsynced) transactions. If the QA account has none, block this task with that exact condition and its **Unblock:** (a QA ledger with staged rows, for example through a Plaid sandbox connection) rather than skipping it. The component tests from t002 stand as the verified baseline.
- No credentials, ledger names, or user data go into the board record.

## Steps

1. Open the Bank Sync review table for the QA ledger and apply a filter that hides at least one row.
2. Select all visible rows, add one hidden selection, and confirm the hidden-selection notice.
3. Open "Set for selected", pick one open account, read the counts, Apply.
4. Confirm every selected row shows the account, the alert is gone, edit one row to another account, then Submit once and confirm the entries land.
5. Repeat the panel in Persian (RTL) once.

## Files

- none (evidence goes in the commit message and, if the run finds a bug, an inbox note)

## Acceptance criteria

- [ ] One Apply sets the target on every selected row including the hidden one, and Submit succeeds in one action.
- [ ] A row edited after Apply keeps its own account.
- [ ] The RTL panel renders correctly, or the gap is recorded as a follow-up note.

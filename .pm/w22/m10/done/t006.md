## Notes

Four reviewers (reuse, simplification, efficiency, altitude) read the committed range `ed6774b17..HEAD`. What was done, and what was left alone:

**Fixed**

- The popover and its state are now `components/bulk-target-popover.tsx` (`BulkTargetPopover`, with `BulkTargetForm` as the content). The table went from 1014 to 858 lines, with the panel's state, two handlers, three derived values and about 100 lines of JSX gone. Closed Radix content is unmounted, so the form starts fresh on every open and the reset-on-open handler is gone; the preview is computed only while the panel is open, and Apply reuses it instead of calling the helper a second time.
- The disabled reason had two defects the reviewers found. The shared `Button` sets `disabled:pointer-events-none`, so the `title` never showed on hover; and the `sr-only` span sat inside the column header's `<th>`. It now follows `bank-item.tsx`: a `Tooltip` around an inline wrapper for the mouse, and a `hidden` span referenced by `aria-describedby` for assistive technology.
- The dialog has an accessible name (`aria-labelledby` on the visible title), as every other popover in the dashboard has.
- In the helper, `kept` and `blank` were read only by tests (`kept` always equalled the selection size minus `applied`). `applyTargetAccount` now returns `{ targets, applied }`, `countSelectedTargets` became `countSelectedWithTarget` returning one number, and the result type is no longer exported. t001's note that it returned "applied/kept counts" describes the earlier shape.

**Skipped, with the reason**

- Exporting `hasTarget` for the three inline "has a target" checks already in the table: those lines are not part of this milestone's diff.
- A shared test preamble for the plaid table tests (the mocks are copied across five files): no shared helper exists and creating one is new work outside this milestone.
- Dropping the disabled state, or the reason, to simplify: the milestone's definition of done requires the control disabled with a stated reason, and `title` alone does not show for a disabled button.
- Delete and Submit are also disabled with no reason when nothing is selected: that predates this milestone.
- Efficiency: the always-on preview cost about 0.1 ms at 3000 rows, well under the table's own per-row rendering; the extraction removes it anyway.

**Accepted trade-off:** reopening the panel during Radix's brief exit animation reuses the old form instance (the explicit reset it replaced had no such gap). The state is harmless and the window is a fraction of a second.

**Not verified in a browser** (none available): the hover tooltip and how a screen reader announces the reason. Both move to t004's browser check.

**Evidence:** the 8 component tests and 12 helper tests pass; six mutations of the extracted component (Apply ignores the replace option, reaches only visible rows, the control not disabled with nothing selected, the panel left open after Apply, the reason detached from the control, Apply enabled before an account is chosen) each fail them. `yarn format:check`, `yarn lint`, `yarn test` (803 files, 8084 tests) and `yarn build` exit 0.

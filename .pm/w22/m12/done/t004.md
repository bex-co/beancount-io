## Objective

Make signing out of `bea` also end Git's access: the credential Git was given stops working.

## Context

- If t001 chose a token, logout revokes it (`DELETE /api-gateway/v1/api-keys/{id}`) and removes it from `bea`'s credentials file, alongside what logout already clears.
- The Git config from `setup` can stay; with no login, the helper answers nothing and Git prompts.

## Steps

1. Revoke and forget the Git credential in `cloud_logout`.
2. Keep logout's existing behavior when the server cannot be reached: clear locally and say what could not be revoked.

## Files

- `cli/src/cli/commands/cloud/app.py`
- `cli/tests/`

## Acceptance criteria

- [x] After logout, a `git fetch` that worked before is refused with 401, and the token shows as revoked in Settings.
- [x] Logout with the server unreachable still clears local state and names the token it could not revoke.

## Out of scope

- Removing the Git config `setup` wrote; `setup --undo` does that.

## Done

**Shipped 2026-11-18.** `bea cloud logout` revokes the Git token (`DELETE /api-gateway/v1/api-keys/{id}`) before it revokes the session, and removes it from `git-credential.json`; a 404 counts as revoked. If the token cannot be revoked, the local copy still goes, the error names the token and the Settings page, and its id is kept so the next login's first mint retires it. The Git config entry stays. With `BEA_TOKEN` set, logout changes nothing, as before.

Tests: the logout cases in `cli/tests/test_cloud_git_sign_in.py` (order of the two requests, server unreachable, token already gone, another server's token left alone). **The 401 on a `git fetch` after logout, and the token shown as revoked in Settings, are t006.**

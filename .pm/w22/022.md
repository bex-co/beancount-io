# After a live text-size change the transaction detail's payee, note, date, "Money flow" title and "Entry Context" row are cut off

**Minor · mobile · 30–40m · A2.** Native mobile QA, 2026-11-10, repository HEAD `59f13b939`, development build `io.beancount.ios` 1.20261002.50 on iPhone 17e / iOS 27.0, light, English, signed in as the QA account on its synthetic `example` ledger. Read-only pass: the pencil and the `…` at the top right were not touched.

## Repro (reproduced twice, the second from a fresh relaunch)

1. Terminate the app, `xcrun simctl ui <udid> content_size large`, relaunch, dismiss the dev toast.
2. **Transactions** tab → the first entry.
3. With the detail open, `xcrun simctl ui <udid> content_size accessibility-large` (AX2, the supported ceiling in `.pm/DO_NOT_DO.md`).

**Expected:** the payee, the signed amount, the note, the date, the `Money flow` title and the `Entry Context` card read whole, as they do from a cold AX2 launch.
**Actual:** the payee shows `China …` cut to its top, the note `nmko…` and the date `October` likewise, `Money flow` and the card's `Entry Context` title and `main.bean:…` source line are cut to slivers. The hero amount (`+$12.00`) is whole (it has its own handling, `w4/005`) and so are the TO and FROM posting rows below it, which are keyed.

**Control (cold):** terminate, set AX2 first, launch and open the same entry: `China Garden`, `+$12.00`, the note, `October 2, 2026`, `Money flow` and `Entry Context` are all whole.

Evidence is local only (`.tmp/qa-20261110/w22b/`): `49-txn-detail-live-ax2.png`, `53-txn-detail-live-ax2-repeat.png` (and `-crop`) against `51-txn-detail-cold-ax2.png`.

## Root cause

Only `posting-row.tsx` in this screen reads `fontScale`. In `mobile/src/screens/transaction-detail-screen/transaction-detail-screen.tsx` the hero Texts `heroTitle` (`:832`), `heroSubtitle` (`:845`) and `heroDate` (`:855`), the badges (`:860-864`) and the `sectionTitle`s (`:926`, `:951`) are plain, as is the Entry Context card's header (the exact site is untraced).

## Fix

Key those Texts on `fontScale` (distinct key per sibling), never the screen, so the expanded Entry Context and the scroll position survive. Add the file to the `KEYED_TEXTS` table in `mobile/src/__tests__/live-font-scale-remeasure.test.ts`, then verify default → AX2 → default natively against a cold AX2 launch. Mobile only.

## Blast radius

The one transaction detail screen. The New Transaction form (the multi-postings screen) is `w22/024`; the Edit transaction screen (the raw source editor, not a form) is `w22/030`. Filed beside `w22/017`–`021`, `023`–`029`, `030`.

## Dedupe

Searched `.pm/**` including `done/` for `transaction-detail`, `heroTitle`, `fontScale`, live text size. `w4/done/005` fixed the hero amount, `w21/done/111` and `684` other aspects of this screen. Nothing covers live size changes on its text.

## Unverified

A transaction with several postings or a status badge, the Entry Context expanded, the shrink direction here (observed on Settings, `w22/021`), dark mode, Android.

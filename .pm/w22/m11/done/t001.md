## Objective

Give the backend one answer to "which commit am I?": a small pure function that reads it from the environment, and `AppConfig.revision` holding the result, so every later surface reads one validated value and nothing can publish arbitrary text.

## Context

- Package: `backend-cluster/backend-v2` (see its `AGENTS.md`, "Environment and deployment": add the value to `AppConfig`, parse it once in `src/config/config.ts`, document it in `.env.example` and `README.md`).
- Nothing in backend-v2 reads a commit today. The value genuinely varies by deployment, so it earns an environment variable.
- Order: `BEANCOUNT_REVISION`, then `RENDER_GIT_COMMIT` (Render-compatible platforms set it at runtime; the repository already reads their `RENDER_EXTERNAL_URL`).
- Accept only a 7–40 character hexadecimal string, lowercased and trimmed. Anything else counts as unset, including the literal `unknown` that a Dockerfile default sets in t003, so a platform variable is never shadowed. Nothing set gives `unknown`.

## Steps

1. Add a pure function (for example `parseRevision(env)` in `src/config/revision.ts`) and use it from `config.ts` to fill `AppConfig.revision`.
2. Unit tests: `BEANCOUNT_REVISION` wins over `RENDER_GIT_COMMIT`; the latter is the fallback; `unknown`, empty, whitespace-only, garbage, 6 characters, 41 characters, and non-hex all count as unset; upper case is lowercased; surrounding whitespace is trimmed; a valid second variable is used when the first is invalid; nothing set gives `unknown`.
3. Document `BEANCOUNT_REVISION` in `.env.example` and the README environment table.
4. Run `yarn typecheck`, `yarn lint:deadcode`, `yarn format:check`, and `yarn test` from `backend-cluster/backend-v2/`.

## Notes

- `src/config/revision.ts` exports `parseRevision(env)` and `UNKNOWN_REVISION`, beside `self-host.ts`, which it follows. The literal `unknown` needs no special case: it is not hexadecimal, so it fails the same pattern as any other garbage and the next source is tried.
- `config.revision` is `parseRevision(process.env)`, captured at startup like `config.selfHost`.
- Tests: 10 in `revision.test.ts` (several of them tables) and one in `config.test.ts` that reloads the config with the variable set. Seven mutations each fail them: swapped precedence, a six-character value accepted, a forty-one-character value accepted, no lowercasing, no trimming, an invalid first source shadowing a valid second one, and `config` not carrying the parsed value. (An earlier attempt at the last one only broke the build with an unused import, so it was redone as a break that compiles; the assertion then failed with `Expected "2144cdbb2e6f", Received "unknown"`.)
- Documented in `.env.example` and the `README.md` paragraph after `SELF_HOST`. The docs describe only what exists so far; reporting the value on the MCP discovery documents is t002, and the build and deployment instructions are t003.
- Gate: backend `yarn format:check`, `yarn typecheck`, `yarn lint:deadcode`, and `yarn test` (481 suites, 10703 tests) exit 0.

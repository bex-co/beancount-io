# The New ledger screen marks the selected Template with the same invisible 1.10:1 fill that `palette.ts` says the drawer and menu rows had to stop using, and it is the only selected state left on it

**Severity:** minor (accessibility: WCAG 1.4.11 and the app's own rule). **Estimate:** 10 minutes. Owner: mobile. A2/A3.

Environment: `main` at `bf758df8d` (this includes the new Currency field of `w3/m62/t003`; the selected-state code is older), dev build `io.beancount.ios` on iPhone 17e / iOS 27.0, light, large text, English, QA account on the hosted server, its synthetic `example` ledger. Read-only: the screen was opened from the drawer's **New ledger** row, one field was focused, nothing was typed and nothing was created.

## Repro

1. Drawer → **New ledger**.
2. Under **Template**, **Starter** is selected and **Sample** is not. The only difference is the row's background: on the screenshot, `rgb(246,243,236)` for the selected Starter row against `rgb(254,254,254)` for the unselected Sample row, a **1.10:1** ratio. There is no check mark, radio, border or text change.

**Expected:** a selected state at 3:1 or better (WCAG 1.4.11), as the other selected rows in the app have.
**Actual:** the selection is almost invisible, most of all outdoors or on a dim screen. VoiceOver is fine (`accessibilityState.selected` is set).

## Evidence

Local, gitignored capture `.tmp/qa-20261112/loop78/13-create-ledger.png`.

## Root cause

- `mobile/src/screens/create-ledger-screen/create-ledger-screen.tsx:147-149` (`templateSelected`, used at `:481` and `:502`) is `backgroundColor: theme.black10`.
- `common/theme/palette.ts:105-110` documents this exact failure: "a selected drawer row or a pressed menu item is marked by a tint, and on `black10` that tint was the same invisible 1.10". It introduced `controlSelected` (the brand green at 12%, flattened: `#e6efe1` in light, `#202f18` in dark) for them.
- The drawer, the account picker, the menu button, the segmented pages, the text-input screen, the date picker and the New Transaction postings screen's active tag chip already use `controlSelected`. This is the only selected style I found still filled with `black10`.

## Fix

Use `theme.controlSelected` for `templateSelected`, and optionally add a check mark so the state does not rely on colour alone. Add a case beside `common/theme/__tests__/control-contrast.test.ts`, or a source check, that `templateSelected` takes `controlSelected`; revert the fix and watch it fail.

## Blast radius

This screen only.

## Not part of this

The new Currency field (a free-text input that prefills `USD` and shows the caret on tap; it behaves as `w3/m62` intends) and the VoiceOver label and hint, which are right.

## Dedupe

Searched `.pm/**` including `done/` for `templateSelected`, `createLedgerTemplate`, "Template" with selected, fill, indicator and contrast. `w21/142` (the template descriptions as a VoiceOver hint) and the `w4` notes on the web Create Ledger form touch the template choice, none its visual selected state. `w22/027` and `w2/066` are the same class on icons, not on this fill.

## Unverified

The dark theme (the fill is `black10` there too, `#282a21` on the charcoal base; not measured); AX2; Persian; Android. The cause is read from the source, the screenshot confirms the symptom.

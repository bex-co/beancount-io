## Objective

Make the running commit visible on the two MCP discovery surfaces an agent reads first: the `initialize` answer's `serverInfo.version` and the `revision` field of `/.well-known/mcp.json`. With nothing set, both stay exactly as they are today.

## Context

- `MCP_SERVER_INFO = { name: "beancount-mcp", version: "1.0.0" }` is a constant in `src/server/api/composition-root.ts` (about line 526); `mcpManifest` in `src/features/well-known/api/well-known-route.ts` also writes `version: "1.0.0"`. Build `serverInfo` from `AppConfig.revision` instead of the constant.
- Known: `serverInfo.version` becomes `1.0.0+<first 7 characters>` (semver build metadata); unchanged when the revision is `unknown`. The manifest's `revision` is the full value or `unknown`; its `version` stays `1.0.0`.
- `health` is not changed (its GraphQL form returns a bare string and is already on REST, GraphQL, and MCP). The two documents are protocol-specific discovery metadata; run the parity gate to confirm no REST or GraphQL counterpart is owed.
- Tests and docs that pin `1.0.0` (`mcp-doc-claims`, the well-known route test, MCP client tests that read `serverInfo`) must keep passing with the revision unset.

## Steps

1. Replace the `serverInfo` constant with a value derived from config; add `revision` to the manifest.
2. Tests: a valid revision appears on both surfaces (`1.0.0+<first 7>` and the full value); unset and malformed never put anything on either; `version` and every other manifest field are unchanged.
3. From `backend-cluster/backend-v2/`: `yarn typecheck`, `yarn lint:deadcode`, `yarn format:check`, `yarn test` (including `surface-parity`, `op-class-coverage`, and `always-public`), and `yarn generate-v1-openapi` with no snapshot drift.
4. Report in the commit that no REST or GraphQL change was needed.

## Notes

- `serverInfo` now comes from `mcpServerInfo(revision)` in `composition-root.ts` (the constructor and the `initialize` override both call it; the doc comment that had drifted away from `assembleMcpRegistry` is back above it). The manifest reports `revision: publishedRevision(config.revision)` beside an unchanged `version: "1.0.0"`. `revision.ts` gained `publishedRevision` (the value if it is a commit, else `unknown`) and `shortRevision` (the seven characters, or `undefined`).
- Both helpers tolerate a missing value on purpose: more than twenty parity tests build the registry with a partial config cast `as AppConfig`, which has no `revision`. They and the surfaces also re-validate, so a bogus `config.revision` still cannot reach a public document.
- **No REST or GraphQL change was needed.** `yarn test` (481 suites, 10718 tests, including `surface-parity`, `op-class-coverage`, `always-public`, and `openapi-completeness`) passes, and `yarn generate-v1-openapi` regenerates with no change to any tracked file, so `cli/openapi/v1.json` needs no re-pin. `health` is untouched.
- One sentence in `docs/mcp.md` that said the `serverInfo` version moves only with the contract was given the build-metadata qualification; the fields themselves are documented in t005.
- Tests: 15 new, in `revision.test.ts` (the two helpers), `well-known-route.test.ts` (4: a commit is reported beside `1.0.0`; unknown or absent says `unknown`; a non-commit never appears; nothing else in the manifest changes), and `mcp-request-parameters.test.ts` (2: `1.0.0+2144cdb` on `initialize` and on the handshake `connect` performs; exactly `1.0.0` for unknown, absent, or malformed). `withClient` there takes an optional config.
- Mutations that fail the tests: `initialize` answering without the revision; eight characters of build metadata; the manifest printing `config.revision` unchecked; the manifest without the field; an unknown revision still adding `+…`. **Not covered, and not observable:** passing the revision to the `McpServer` constructor. The custom `initialize` handler overrides the SDK's, so the constructor's identity never reaches a client; it is kept consistent only so a future SDK default would agree. Two earlier attempts at the manifest mutations only broke the build with an unused import and were redone so they compile.
- Gate: backend `yarn format:check`, `yarn typecheck`, `yarn lint:deadcode`, and `yarn test` exit 0.

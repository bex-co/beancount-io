## Notes

Four reviewers (reuse, simplification, efficiency, altitude) read the committed range `57d7aaa13..HEAD`. What was done, and what was left alone:

**Fixed**

- `revision.ts`: one private `isRevision` guard replaces the checks `parseRevision` and `publishedRevision` each wrote inline, and `shortRevision` no longer round-trips through the `"unknown"` sentinel. `UNKNOWN_REVISION` is no longer exported (nothing outside the file needed it), and a tautological assertion and a duplicated length case in `revision.test.ts` are gone.
- One contract version: `MCP_CONTRACT_VERSION` is defined beside the manifest and used by both the manifest's `version` and `serverInfo.version`. The two `"1.0.0"` literals, and the unwritten rule that they move together, are now one constant. `mcpServerInfo` runs once per registry assembly instead of twice.
- `describeRevision` lost two single-use aliases and a branch (the reviewer compared old and new over 63 input pairs with identical output), and `observeRevision` scans for the `+` once.
- **A real divergence between the two observers, fixed:** the conformance run took any non-empty `+suffix` for a build and printed `revision: +foo` as if it were a commit, while the replay requires 7–40 lower-case hexadecimal characters. Conformance now does the same (a suffix that is not a commit counts as naming no build), with four new cases.
- The `observeRevision` tests close their fake deployments in one `afterEach` instead of five `try/finally` blocks, and a doc comment that said the manifest value was "a commit, `unknown`, or `undefined`" now says it is passed through as served.

**Skipped, with the reason**

- Dropping the second validation (`publishedRevision`, and `shortRevision`'s own check). Two reviewers argued that production never reaches it, since `config.revision` has one producer, and that the tests of it exercise a state only a fixture can create. It is deliberate: the value lands in a public, unauthenticated document, the check is one regex, and removing it would also delete the tests that keep a non-commit out of that document. Tolerating an absent value (the partial `as AppConfig` fixtures, 89 test files) would have been enough without it; if this repository decides public sinks do not re-validate, the removal is about ten source lines and twenty-five test lines.
- Sharing the hex rule between the conformance script and `revision.ts`. The conformance run is an independent observer of a remote deployment, so reusing the server's own parser would weaken the cross-check; the replay's copy cannot be shared at all (a different package, plain `.mjs`).
- Collapsing the junk-value cases in the route and server tests: they are what pin the second validation kept above.
- Hoisting `mcpServerInfo` to a module constant, and running the manifest request and the handshake concurrently: measured and not worth it (about 45 ns per request; one saved round trip on an operator-run diagnostic).

**Found, outside this task's scope, filed separately:** `scripts/mcp-agent-eval.ts` still reports `deployedRevision: "unavailable (the endpoint does not report one)"` and `docs/mcp-agent-eval.md` still says the endpoint exposes none. Both become false once a deployment reports a commit, and `.pm/DO_NOT_DO.md` requires real-client MCP evaluation to record it. t006 missed that surface. **Also found:** `/.well-known/mcp.json` is served with `Cache-Control: public, max-age=3600`, so the manifest can show the previous build's `revision` for up to an hour after a deploy; this is documented in t008.

**Evidence:** every mutation from t001, t002 and t004 still fails the revision tests (checked again, 18 in all), plus the new non-commit-suffix case; two of the re-runs first broke the build with an unused variable and were redone so they compile. Backend `yarn format:check`, `yarn typecheck`, `yarn lint:deadcode`, and `yarn test` (481 suites, 10743 tests) and the qa-shared node tests exit 0.

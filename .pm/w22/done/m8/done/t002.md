## Objective

On a self-hosted deployment, `signUp` completes the registration and returns the session token (also set as the auth cookie), and the dashboard skips the code page entirely instead of accepting any code.

## Context

- `SignUpResponse` gains nullable `token` and `tokenExpireAt`; absent means the emailed code is still required, so older clients are unaffected.
- The dashboard's register page and the three OAuth consent pages share one sign-up hook; each handles a signed-in answer.
- `dashboard/src/graphql/definitions.ts` was patched by hand at the three affected spots because codegen refuses the stale schema snapshot.

## Steps

1. Finish the session inside the `signUp` resolver through the same checked workflow, then set the cookie.
2. Add `onSignedIn` to `useRegisterForm` and a shared `finishSignUp` for the post-sign-up redirect.
3. Wire the register page and the OAuth, mobile-consent and identity-consent steps.

## Files

- `backend-cluster/backend-v2/src/features/auth/api/auth-resolver.ts`, `dashboard/src/features/auth/`, `dashboard/src/features/oauth/pages/`, `dashboard/api-gateway.graphql`, `dashboard/src/graphql/`

## Acceptance criteria

- [x] A browser sign-up on a self-hosted stack sends one `SignUp` request and no `VerifySignUpOtp`, lands on the welcome page signed in, and never shows the code form.
- [x] When no token comes back the code step is offered as before.
- [x] A failed completion sets no cookie.

## Out of scope

- Mobile app changes: it talks to the managed service, which never sets `SELF_HOST`.

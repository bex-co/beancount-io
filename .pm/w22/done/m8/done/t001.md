## Objective

Replace the interim `AUTH_SKIP_EMAIL_VERIFICATION` flag with one operator switch, `SELF_HOST=true`, and make it lift every plan limit.

## Context

- Package: `backend-cluster/backend-v2/` (follow its `AGENTS.md`).
- Every limit and paid-plan gate (ledgers, collaborators, directives, AI-assistant tokens, API-key minting) resolves through `getUserTier`, so one early return covers them all.
- Off unless the variable is exactly `true`: a managed deployment that mis-sets it must not relax.

## Steps

1. Add `src/config/self-host.ts` (`isSelfHost()`) and `config.selfHost`.
2. Return the unlimited tier from `getUserTier` before any Stripe call.
3. Drop the old flag and its any-code bypass in `verifySignUpOtp` / `finishSignupSession`; add a boot warning.

## Files

- `backend-cluster/backend-v2/src/config/`, `src/features/stripe/operations/get-user-tier.ts`, `src/features/auth/service/auth-service.ts`, `src/server/start-server.ts`

## Acceptance criteria

- [x] With `SELF_HOST=true`, `getUserTier` returns the top tier and never calls Stripe; every limit reads `-1`.
- [x] With the variable unset or any other value (`false`, `1`, `TRUE`, empty), the user's own plan applies.
- [x] The verify endpoints reject a wrong code even when self-hosted.

## Out of scope

- Mobile app changes: it talks to the managed service, which never sets `SELF_HOST`.

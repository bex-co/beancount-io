# In light mode four controls draw their only visual cue in `black60` at 1.6–1.8:1: Accounts' expand chevron, Budget's entries toggle, Open Account's prefix dropdown and the filter sheet's "clear account" button

**Minor · mobile · 20–30m · A2.** Native mobile QA, 2026-11-10, repository HEAD `59f13b939`, development build `io.beancount.ios` 1.20261002.50 on iPhone 17e / iOS 27.0, English, signed in as the QA account on its synthetic `example` ledger. Read-only pass: the Open Account form and the filter sheet were opened and cancelled with nothing applied or saved. This is the residual of `w2/done/066`, which fixed the same token on the same surface for Reports only.

## Repro (each icon measured on the rendered screenshot, light theme)

1. Accounts tab: the chevron left of `Assets` (the only cue that the row expands).

4. Transactions → the filter icon → the Account row → pick any account (the Recent row) → the circled ✕ at the end of the Account row. Cancel the sheet afterwards.

## Root cause

All four take their colour from `theme.black60`, which `mobile/src/common/theme/palette.ts` documents as the "placeholders / disabled" step (`:178`) and measures at 1.78:1 against white (`:71`). That module added a separate control role (`controlBorder`, `controlPlaceholder`) for exactly this reason, and `w2/done/066` moved Reports' chevrons to `black80` (`category-breakdown.tsx:246`, `:327`). The four sites kept `black60`:

- `mobile/src/components/account-table/account-table.tsx:303-308` (its comment says "dimmer than the label ... so the chevron reads as a control rather than competing with the account name");
- `mobile/src/screens/budget-screen/components/budget-history-rows.tsx:177-181`;
- `mobile/src/screens/open-account-screen/open-account-screen.tsx:506-510`;
- `mobile/src/screens/transaction-filters-screen/transaction-filters-screen.tsx:421` (`close-circle`, inside a button labelled `clearAccount`).

## Fix

Give each the same foreground `w2/done/066` gave Reports' chevrons (`black80`), or `controlBorder` for the circled ✕ (3.67:1 on white). Keep each icon's size, position, hit target and accessibility label; do not retune `black60` globally, since it is also the placeholder ramp and the disabled state (`66` made the same choice). The Accounts comment about not competing with the label is answered by `black80` still being lighter than `black90` text and by the size. Add the four files to the contrast guard in `mobile/src/__tests__/text-style-contrast.test.ts` (or `control-contrast.test.ts`) as cases that measure the icon's real colour against its real surface in both themes, and verify natively in light and dark. Mobile only; no API surface.

## Adjacent states

## Dedupe

Searched `.pm/**` (including `done/`) for the four sites, `black60`, "chevron", "contrast", "faint". `w2/done/066` is this defect for Reports (measured `#c2c3b6` on `#f6f4ec` = 1.6195:1, the same numbers) and fixed it locally; `w21/done/1000` made the Accounts chevron a 44 pt target without changing its colour; `w21/done/925` and the contrast guards (`text-style-contrast.test.ts`, `control-contrast.test.ts`) cover other sites by an explicit list. Nothing covers these four.

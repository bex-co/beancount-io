# After a live text-size change the Open Account, Add Budget and New Transaction forms cut their labels, values and header "Done" to slivers

**Minor · mobile · 40–50m (three forms, one shared header action) · A2.** Native mobile QA, 2026-11-10, repository HEAD `59f13b939`, development build `io.beancount.ios` 1.20261002.50 on iPhone 17e / iOS 27.0, light, English, signed in as the QA account on its synthetic `example` ledger. Read-only: each form was opened and left untouched, and no Done, row, picker or field was tapped. This is the same mechanism as `w22/017`–`023` and `025`, `026`, on the write forms.

## Repro (each form reproduced twice, the second from a fresh relaunch)

1. Terminate the app, `xcrun simctl ui <udid> content_size large`, relaunch, dismiss the dev toast.
2. **Open Account:** Accounts tab → `+`. **Add Budget:** Home → the Budget card's **See all** → `+`. **New Transaction:** Home `+` → *Enter new transaction* (the first row; the second is *Scan Receipt*, a black camera preview here, never tap its shutter or library).
3. With the form open, `xcrun simctl ui <udid> content_size accessibility-large` (AX2, the supported ceiling in `.pm/DO_NOT_DO.md`).

**Expected:** every label, value, the helper text and the header action read whole and the rows grow, as they do from a cold AX2 launch.
**Actual, all three:** the header's `Done` is a sliver (`D…`, `Don`). **Open Account:** `Account`, `Currency` and `Open date` show only their upper halves, the prefix `Assets:` is `Ass…` cut at the top, and the values `USD` and `2026-…` are cut at the side. **Add Budget:** `Date`, `Account`, `Interval`, `Amount`, `Currency` and every value (`…roceries`, `ly`, `10`) are cut, and the helper `Budgets apply to one account…` stays on one line past the screen edge. **New Transaction:** `DATE`, `PAYEE` and `NARRATION` and the date value are cut to slivers, `Add posting` is `Add p…`, and the `Remaining` row reads `Rema…` / `$0.0`. The posting account names wrap correctly in all of this, because they are keyed (`w21/029`).

**Control (cold):** terminate, set AX2 first, launch and open the same forms: every label, value and `Done` is whole, the helper wraps onto five lines, and `Add posting` and the posting rows are complete.

Evidence is local only (`.tmp/qa-20261110/w22c/`): `09-open-account-live-ax2.png`, `13-open-account-live-ax2-repeat.png`, `16-add-budget-live-ax2.png`, `20-add-budget-live-ax2-repeat.png`, `24-new-txn-live-ax2.png`, `35-new-txn-live-ax2-repeat.png` (and the `-crop`s) against `11-open-account-cold-ax2.png`, `18-add-budget-cold-ax2.png`, `32-new-txn-cold-ax2.png`.

## Root cause

None of the three screens keys its Texts on `fontScale`; only the New Transaction posting account is (`mobile/src/screens/multi-postings-transaction/multi-postings-transaction-screen.tsx:394`, `w21/029`). Plain Texts: Open Account `fieldLabel` (`open-account-screen.tsx:480`), `prefixText` (`:502`), `preview` (`:547`), the two `value`s (`:563`, `:583`) and the header `Done` (`:459-467`); Add Budget's `FormRow` (`add-budget-screen.tsx:167-190`: `label` and `value`), the `Amount` label (`:454`), `help` (`:495`, `:497`) and `Done` (`:409-416`); New Transaction's field labels and values, `addPostingText` (`:909`) and the remaining row, and `Done` (`:780-795`). The `Done` Text takes `headerActionStyle` (`mobile/src/common/theme/typography.ts:108`) and `maxFontSizeMultiplier` from the same module, so one change reaches all three.

## Fix

Key those Texts on `fontScale`, a distinct key per sibling (`mobile/src/__tests__/font-scale-key-collisions.test.ts`). `FormRow` is one component in Add Budget: key its two Texts there. For `Done`, key the Text where each screen builds `headerRight` (or in a small shared `HeaderAction` if the three already agree, since `edit-transaction-screen.tsx` uses the same helper and should be checked in the same pass). Never key a screen, a form or a `TextInput`, so typed values, focus and the keyboard survive; verify that with a screen that already has text in a field. Add the files to the `KEYED_TEXTS` table in `mobile/src/__tests__/live-font-scale-remeasure.test.ts`, then verify default → AX2 → default natively against cold AX2 launches. Mobile only; no API surface.

## Blast radius

The three forms, the Edit transaction screen (shares `headerActionStyle`; `w22/030`) and the text-input modals behind these rows (`TextInputModal`, not opened). Do not type into a form to verify: this machine has no keyboard entry, and a form with unsaved changes asks to discard on leaving.

## Adjacent states

A form that already holds typed text or a selected account, an open picker or date wheel, the saving state (`Saving…` replaces `Done` in Open Account), and a validation error line.

## Dedupe

Searched `.pm/**` (including `done/`) for `open-account`, `add-budget`, `multi-postings`, "New Transaction", `fontScale`, live text size. `w21/029` (done) fixed the posting account names at a cold AX2 launch by keying only them; `w21/027`, `w21/1013` and `w2/069` are other cold-size or accessibility items. `w4/blocked/002` is the owner's manual VoiceOver and Inspector pass. Nothing covers live size changes on these forms.

## Unverified

the pickers and modals behind the rows (Edit transaction is `w22/030`), the shrink direction here (observed on Settings, `w22/021`), a form with typed content (no text entry here), dark mode, Android.

---

**Resolved 2026-11-10** — the three forms' header `Done`, Open Account's field label, prefix, name preview and Currency / Open date rows, Add Budget's form rows, Amount label and help lines, and New Transaction's Date / Payee / Narration rows (the shared `ListItem`, also used by the transaction filters), sign toggle, Auto tag, Add posting and Remainder label are now keyed on the live text scale (distinct keys per sibling), so they re-measure when the text size changes while a form is open; no screen, form or `TextInput` is keyed, so typed values, focus and the keyboard are untouched. Shipped in `30e85ceee` (`mobile`). Tests: the four files join the `KEYED_TEXTS` source scan in `live-font-scale-remeasure.test.ts` (their new cases fail with the fix reverted); the scan now compares style attributes ignoring wrapping whitespace and a trailing comma, so a style array prettier wraps still matches. Verified natively on iPhone 17e / iOS 27.0, light, from a cold launch of the fixed bundle, with no field touched: each form opened at `large`, switched live to AX2 and back — `Done`, every label and value, the five-line Budget helper, the postings, the Auto tag and Add posting read whole at AX2. Not observed: New Transaction's Remainder row at AX2 (below the fold; the harness has no scroll tool), a form with typed content (no text entry here), the pickers and modals behind the rows, the saving state, a validation error line, dark mode, Android. Edit Transaction's own `Cancel` / `Save` stay with `w22/030`.

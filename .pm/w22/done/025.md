# After a live text-size change the Plan screen's plan name and its three lines are cut to their top halves

**Minor · mobile · 10–15m · A2.** Native mobile QA, 2026-11-10, repository HEAD `59f13b939`, development build `io.beancount.ios` 1.20261002.50 on iPhone 17e / iOS 27.0, light, English, signed in as the QA account. Read-only: the screen has no control to submit, and nothing was written. This is the same mechanism as `w22/017`–`024`, on the smallest screen.

## Repro (reproduced twice, the second from a fresh relaunch)

1. Terminate the app, `xcrun simctl ui <udid> content_size large`, relaunch, dismiss the dev toast.
2. Open the drawer, then **Settings** (`automation_tap` on testID `drawer-identity-row`), then **Plan** (testID `setting-plan`).
3. With Plan open, `xcrun simctl ui <udid> content_size accessibility-large` (AX2, the supported ceiling in `.pm/DO_NOT_DO.md`).

**Expected:** the plan name and its cycle, renewal and billing-source lines read whole.
**Actual:** the plan name (`Growth` shows as its top half), `Yearly`, `Renews on Oct 21, 2027` and `Billed through Stripe` are each cut to their upper halves in the old line heights.

**Control (cold):** terminate, set AX2 first, launch and open the same screen: all four lines are whole.

Evidence is local only (`.tmp/qa-20261110/w22c/`): `40-plan-live-ax2.png`, `44-plan-live-ax2-repeat.png` (and `-crop`) against `42-plan-cold-ax2-crop.png`.

## Root cause

`mobile/src/screens/plan-screen/plan-screen.tsx:101-108` renders the plan name and its lines as plain Texts (`styles.plan`, `styles.line` three times); the screen does not read `fontScale`.

## Fix

Key those Texts on `fontScale`, a distinct key per sibling (`mobile/src/__tests__/font-scale-key-collisions.test.ts`), and add the file to the `KEYED_TEXTS` table in `mobile/src/__tests__/live-font-scale-remeasure.test.ts`; then verify default → AX2 → default natively against a cold AX2 launch. Mobile only; no API surface.

## Blast radius

The one Plan screen. The Referral screen has the same defect and is filed as `w22/029`. Filed beside `w22/017`–`024`, `026`–`029`, `030`.

## Dedupe

Searched `.pm/**` (including `done/`) for `plan-screen`, `PlanCard`, "Plan page", `fontScale`, live text size. `w7/blocked/m7/t005` (blocked) is the visual check of a future mobile-billing plan screen, not this one. Nothing covers live size changes on Plan.

## Unverified

Plan states other than this account's (a free plan, a lapsed or managed-elsewhere one), the shrink direction here (observed on Settings, `w22/021`), dark mode, Android.

---

**Resolved 2026-11-11** — the Plan screen's plan name and its cycle, renewal, billing-source and managed-on lines are now keyed on the live text scale (a distinct key per sibling), so they re-measure when the text size changes while the screen is open; the scroll view and the query stay mounted. Shipped in `12d2cdd0f` (`mobile`). Tests: the screen joins the `KEYED_TEXTS` source scan in `live-font-scale-remeasure.test.ts`; both new cases fail with the fix reverted. Verified natively on iPhone 17e / iOS 27.0, light, from a cold launch of the fixed bundle, with taps by testID only: Plan opened at `large`, switched live to AX2 and back — all four lines read whole at AX2 and the screen returned to its `large` form. Not checked: plan states other than this account's (free, lapsed, managed elsewhere), dark mode, Android.

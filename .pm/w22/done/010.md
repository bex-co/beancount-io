# In Persian a commit's short SHA comes apart in Notifications, and the author/date line puts the day on the wrong side of the author name

**Minor · mobile · 20–30m · A2.** Native mobile QA, 2026-11-10, repository HEAD `6183533d9`, development build `io.beancount.ios` 1.20261002.50 on iPhone 17e / iOS 27.0, light, app language Persian (after the layout restart), signed in as the QA account on an authenticated ledger whose recent commits have Latin author names. Read-only pass.

## Repro (reproduced on two screens in one fresh session)

1. Switch the app to **فارسی** (Settings → Language → Restart now).
2. Bell → **Notifications** → *Recent changes*. Each row's muted line is `author · date` followed by the short SHA.
3. For the newest row the SHA is drawn as its last four characters at the end of the line, with its first three **detached and drawn on the other side of the date**, next to the day number. Opening the row shows the complete SHA in the screen title (seven characters, starting with three digits). The other eight rows show the same split: only the digits at the start of the SHA are displaced, and the visible tail plus the displaced digits add up to seven characters each (checked by length; only the first row was opened).
4. Open that commit. Its *Author* line reads `<label>: <day> · <author> <month> <year>, <time>` right to left: the day number sits beside the label while the month, year and time sit after the author name, so the date no longer reads in one piece. (The exact order of the small Persian digits could not be read reliably at 3× capture size; treat the precise glyph order as unverified.)

**Expected:** the SHA reads as one contiguous token, a copied or compared SHA matches the screen title, and the date reads as one phrase next to the author.
**Actual:** in Persian the SHA's leading digits are separated from it, so a row can show a SHA that is not the commit's. English and German rows are fine (the same screens were captured earlier in this session).

Local evidence: `.tmp/qa-20261110/fa/notif-row-zoom.png`, `commit-detail-fa.png`, `commit-meta-zoom.png`.

## Root cause

Bidirectional text, from plain concatenation (mechanism inferred from the split pattern, not traced through a native bidi instrument):

- `mobile/src/screens/notifications-screen/formatting.ts:67-72`: `formatCommitAuthorLine` returns `` `${name} · ${moment}` `` with a localized date that begins with Persian digits. Digits are weak characters, so they attach to whichever run precedes them: the Latin author name and the `·`.
- `mobile/src/screens/notifications-screen/notifications-screen.tsx:518-528`: the SHA is appended as an inline `Text` in the same paragraph. Its leading digits are weak characters after the Persian date and join the right-to-left run, while its hex letters start a new left-to-right run. A SHA starting with a letter does not split, which is why not every row is hurt.
- `mobile/src/screens/commit-detail-screen/commit-detail-screen.tsx:297` reuses the same function.

The app already has the tool: `mobile/src/common/bidi.ts` (`isolateLtr`, first-strong isolates), applied to the same class of problem in `w21/095`, `w21/249`, `w21/743` and `w21/824`.

## Fix

Target: in Persian the SHA is one left-to-right token (`isolateLtr`), and the author name and the localized date are each their own isolate, so `author · date` and the date read in order next to each other. Do it in `formatCommitAuthorLine` and at the SHA site so both screens agree. Keep the spoken row label clean: `formatting.ts:56` reuses the same function for the accessibility label, so check that isolate marks are not read aloud (VoiceOver normally ignores them) or build that label from the plain strings. Add cases to `notifications-screen/__tests__/format-commit-author-line.test.ts` for a Latin author with `fa`, and for an SHA that starts with digits (for example a synthetic `123abcd`). Owner: mobile only; no API surface.

## Blast radius

Callers of `formatCommitAuthorLine`: Notifications row, Commit detail, and the row's spoken label. The SHA is shown inline only in the Notifications row (the Commit detail title shows it alone). Persian is the only RTL locale; LTR locales add no visible change from an isolate.

## Dedupe

Searched `.pm/**` (including `done/`) for `formatCommitAuthorLine`, commit row and Notifications together with Persian, and for `bidi`, `isolateLtr` and short SHA. `w4/done/008` (and `w21/487`) added the date to this line and was accepted in English; nothing covers it in Persian. The `w21/095`–`824` fixes above are the precedent, on other strings.

## Unverified

The exact glyph order of the Persian day digits at this capture size, rows 2–9 of the SHA split beyond the length check, a commit whose author name is itself Persian, and Android.

---

**Resolved 2026-11-10** — in Persian a commit's "author · date" and its short SHA now read in order: the author and the localized date are each their own first-strong isolate, and the Notifications row's SHA is one left-to-right token. Shipped in `943ddee6f` (`mobile`). The new `isolateParts` in `common/bidi.ts` is content-driven like its siblings (a line with no Hebrew or Arabic-script letters comes back unchanged, so the other twelve languages draw what they drew), and `formatCommitAuthorLine` uses it for both screens that show the line. The spoken row label is built from the plain parts, so no direction marks reach VoiceOver; that was the alternative the note offered over trusting the screen reader to ignore them. Tests: `isolateParts` (five cases), the Persian line, a Persian author in a left-to-right app, the unmarked author-alone and Latin-language cases, the plain spoken label, and the SHA site; eight fail with the fix reverted. Verified natively on iPhone 17e / iOS 27.0 in Persian: the nine Notifications rows show whole seven-character SHAs, the first row's SHA matches the commit screen's title (`917f5d8`), and the detail's Author line reads the date in one piece beside the author. Because every part of the line now sits in an isolate, the line's base direction comes out left to right: it reads author, date, SHA from the left within a right-aligned block. That is the contiguous reading the note asked for; whether a right-to-left base would read better is a styling call left open. Not checked: a commit whose author name is itself Persian on screen, rows 2–9 beyond the length check (all nine now show full SHAs in one capture), and Android.

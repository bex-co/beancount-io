# After a live text-size change the Edit Transaction screen cuts its header `Cancel` and `Save` and shows its one-line hint cut at the screen edge

**Minor · mobile · 10–15m · A2.** Native mobile QA, 2026-11-10, repository HEAD `59f13b939`, development build `io.beancount.ios` 1.20261002.50 on iPhone 17e / iOS 27.0, light, English, signed in as the QA account on its synthetic `example` ledger. Read-only: the screen was opened from a transaction's pencil and left untouched, `Save` was disabled throughout (nothing was changed) and `Cancel` was never needed. This is the "Edit transaction form" that `w22/022` and `w22/024` listed as unexercised, and the same mechanism as `w22/017`–`029`. Note: Edit Transaction is not a form; it is the **raw beancount source editor**, the same embedded editor as the file editor.

## Repro (reproduced twice, the second from a fresh relaunch)

1. Terminate the app, `xcrun simctl ui <udid> content_size large`, relaunch, dismiss the dev toast.
2. **Transactions** tab → the first entry → the **pencil** at the top right of its detail (the `…` beside it is a different control; do not tap it).
3. With **Edit Transaction** open, `xcrun simctl ui <udid> content_size accessibility-large` (AX2, the supported ceiling in `.pm/DO_NOT_DO.md`). Take screenshots only; do not tap `Save`.

**Expected:** `Cancel` and `Save` read whole, and the hint `Edit raw beancount source below. A stale checksum or invalid beancount will be rejected with an error.` wraps, as from a cold AX2 launch.
**Actual:** `Cancel` and `Save` show only their upper halves (`Canc`, `Sav`); the hint is **one line cut at the screen edge** (`Edit raw beancount source bel`) and its remaining lines are gone. The editor itself re-lays out correctly (larger text, wrapped lines, line numbers), because the screen passes it `fontScale`.

**Control (cold):** terminate, set AX2 first, launch and open the same screen: `Cancel` and `Save` are whole and the hint wraps onto four lines.

Evidence is local only (`.tmp/qa-20261110/w22f/`): `03-edit-live-ax2.png`, `08-edit-live-ax2-repeat.png` (and `-crop`) against `05-edit-cold-ax2.png` (and the `large` frame `02-edit-form.png`).

## Root cause

`mobile/src/screens/edit-transaction-screen/edit-transaction-screen.tsx` reads `fontScale` (`:136`) only to hand it to the editor (`:745`). Its own Texts are plain: the header `Cancel` (`:679-684`) and `Save` (`:698-706`) inside `headerLeft` / `headerRight`, both on `headerActionStyle` (`mobile/src/common/theme/typography.ts:108`), and the hint (`:714`, `styles.hint`).

## Fix

Key those three Texts on `fontScale`, a distinct key per sibling (`mobile/src/__tests__/font-scale-key-collisions.test.ts`), exactly as `w22/024` asks for the shared header `Done` in the other three forms; do the four header actions in one pass (the same `headerActionStyle` is the common thread). Never key the editor or the screen, so the unsaved buffer, the caret and the checksum state survive. Add the file to the `KEYED_TEXTS` table in `mobile/src/__tests__/live-font-scale-remeasure.test.ts`, then verify default → AX2 → default natively against a cold AX2 launch, again without tapping `Save`. Mobile only; no API surface.

## Blast radius

The one Edit Transaction screen, every transaction's edit path, and its error line (`InlineError`, `:716`), which was not on screen. The unsaved-changes dialog and the stale-checksum rejection were not exercised (they need a typed edit, which this machine cannot do). Filed beside `w22/017`–`029`.

## Dedupe

Searched `.pm/**` (including `done/`) for `edit-transaction`, "Edit Transaction", `editTransactionSource`, `fontScale`, live text size. `w3/done/151` fits navigation action labels at a **cold** large size; `w4/done/011` is the New Transaction discard warning. `w22/022` and `w22/024` listed this screen as unexercised. Nothing covers live size changes here.

## Unverified

The shrink direction here (observed on Settings, `w22/021`), the error and unsaved-changes states, dark mode, Android.

**Resolved 2026-11-11** — Edit Transaction's header `Cancel` and `Save`, its source hint and its load-error line are now keyed on the live text scale (distinct keys per sibling), so they re-measure when the text size changes while the screen is open; the editor and the screen are not keyed, so the unsaved buffer, the caret and the checksum state survive. Shipped in `8b88240e1` (`mobile`). Tests: the screen joins the `KEYED_TEXTS` source scan in `live-font-scale-remeasure.test.ts`; both new cases fail with the fix reverted. Verified natively on iPhone 17e / iOS 27.0, light, from a cold launch of the fixed bundle: Edit Transaction opened from a transaction's pencil at `large`, switched live to AX2 and back, with `Save` disabled throughout and never tapped — `Cancel`, `Save` and the four-line hint read whole at AX2. Not checked: the error and unsaved-changes states (they need a typed edit), dark mode, Android. Observed, not part of this note: two other header actions on `headerActionStyle` are still unkeyed — the New Ledger form's `Done` (`create-ledger-screen.tsx`, which reads no `fontScale`) and the file editor's own `Save` (`ledger-file-editor-screen/index.tsx`) — and would show the same clipping after a live change.

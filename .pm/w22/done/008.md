# Files list names, the Reports "Showing through…" note and every chart legend clip after a live text-size change

**Minor · mobile · 30–40m · A2.** Native mobile QA, 2026-11-10, repository HEAD `6183533d9` (`mobile/` source equal to `main`; generated GraphQL aside), development build `io.beancount.ios` 1.20261002.50 on iPhone 17e / iOS 27.0, light, English, signed in as the QA account on an authenticated ledger. Read-only pass; nothing was written.

## Repro (reproduced twice, each from a fresh relaunch)

1. `xcrun simctl ui <udid> content_size large`, relaunch the app, open **Reports**, then **Files**.
2. With those screens mounted, `xcrun simctl ui <udid> content_size accessibility-large` (AX2, the supported ceiling in `.pm/DO_NOT_DO.md`).
3. **Files:** each row name shows only its top half (`main.bean`, `README.md`); the row height did not change.
4. **Reports, 6M:** the note `Showing through October 2026, the latest month with entries.` is one line cut at the screen edge ("…through October 202"); the rest is gone. The chart legend (`Income`, `Expenses`, `Net Profit`) shows only the upper part of each label.

**Control (cold):** relaunch at AX2 and open the same screens. The note wraps to three lines, the legend wraps to two, and the file names render whole. A screen that launched at AX2, shrank to `large` and was enlarged again also renders whole, because its cached measurement matches. Only text first measured at a smaller size clips.

Evidence is local only (`.tmp/qa-20261110/ax2/`): `r2-files-live-AX2.png`, `r2-reports-live-AX2.png` against `cold-files.png`, `cold-reports.png`.

## Root cause

The mechanism `mobile/AGENTS.md` documents under "Live text-size changes — key the Text on `fontScale`": a Text whose props do not change keeps its old native measurement. Unkeyed sites:

- `mobile/src/screens/ledger-file-browser-screen/index.tsx:318` and `:323` — the file row's `rowLabel` and `rowNote` Text.
- `mobile/src/screens/reports-screen/reports-screen.tsx:282` — the `anchorNote` Text.
- `mobile/src/common/d3/chart-chrome.tsx:133` — `LegendItem`'s `legendText`, shared by the income/expense chart (`income-expense-bar-chart.tsx:220-222`), Cash flow (`cash-flow-sankey.tsx:444-447`) and the budget chart (`budget-bar-chart-d3.tsx:147-148`).

Working control: `DateSectionHeader` keys its container on `useWindowDimensions().fontScale` (`mobile/src/screens/transactions-screen/date-section-header.tsx:67-72`).

## Fix

Key those Texts (the row's text view, the note, and `LegendItem`'s Text) on `fontScale`, as the existing sites do. Do not key the list, the screen or the chart, so query, scroll and selection state survive. Add the three to the dynamic-type tests beside `mobile/src/__tests__/*-dynamic-type.test.ts`, then verify default → AX2 → default natively in both themes. Mobile only; no API surface involved.

## Dedupe

`w2/m37` (done) fixed this class for date headers, picker rows, range pills and the file read-only notice. Its definition of done names those four renderers and not these three, so this extends it rather than regressing it. Searched `.pm/**` (including `done/`) for fontScale, live text size, legend, file list and "Showing through". `w0/041`–`044` and `w21/052` reproduced only at AX5 and are unrelated.

## Unverified

Dark mode, the budget and Cash flow legends (same Text, not observed live), a merchant or account-detail legend if one exists, and Android. The cause is read from source and the cold/live contrast, not from a native instrument trace.

---

**Resolved 2026-11-10** — the Files row's name and note, the Reports "Showing through…" note and every chart legend entry are now keyed on the live text scale (`useWindowDimensions().fontScale`), so each remounts and re-measures when the text size changes while the screen is open; the list, scroll position, query and selection are untouched. Shipped in `8dfb7e7b4` (`mobile`). Each Text carries its own key (`label-`, `note-`, `anchor-note-`, and the legend's bare scale), which keeps siblings from colliding. Tests: the three sites join the font-scale source scan in `live-font-scale-remeasure.test.ts`, `LegendItem` is rendered at two scales, and the w21/771 source pin expects the note's new key; seven of the new cases fail with the fix reverted. Verified natively on iPhone 17e / iOS 27.0, light, from a cold launch of the fixed bundle: with Reports and Files mounted at the default size, switching to AX2 and back left the file names whole, the note on three lines and the legend on two at AX2, and back to two lines and one at the default. Not checked: dark mode, the Cash flow and budget legends on screen (same `LegendItem`), and Android.

# In German at AX2 the New Transaction caption "ZAHLUNGSEMPFÄNGER" breaks mid-word and leaves a lone "R" on its own line

**Minor · mobile · 15–25m · A2.** Native mobile QA, 2026-11-10, repository HEAD `59f13b939`, development build `io.beancount.ios` 1.20261002.50 on iPhone 17e / iOS 27.0, light, German (Settings → Language → Deutsch; no restart needed from English), signed in as the QA account on its synthetic `example` ledger. Read-only: the form was opened and left with Back, nothing was typed or saved, and the app language was restored to English afterwards. First check of the **language × text-size** combination: every earlier text-size pass was English and every language pass was at the default size.

## Repro (reproduced twice, each from a cold launch at AX2)

1. Settings → **Language** → **Deutsch** → Confirm (the layout stays left to right, so no restart prompt).
2. `xcrun simctl terminate <udid> io.beancount.ios`, `xcrun simctl ui <udid> content_size accessibility-large` (AX2, the supported ceiling in `.pm/DO_NOT_DO.md`), relaunch, dismiss the dev toast.
3. Home → the `+` at the top right → the **first** row, `Neue Transaktion erfassen` (the second row, `Beleg scannen`, is the camera; never tap its shutter or library).

**Expected:** the three field captions `DATUM`, `ZAHLUNGSEMPFÄNGER`, `BESCHREIBUNG` each read as whole words, as `PAYEE` does in English.
**Actual:** `ZAHLUNGSEMPFÄNGE` fills the line and the last letter `R` sits alone on the next line, above the row's empty value (`—`). The other two captions fit. A reader sees a nonsense word and a stray letter in the form where they confirm who was paid.

**Control:** the same form at `large` is fine, and so is English at AX2 (`PAYEE`, seen in an earlier pass): `Zahlungsempfänger` is 17 letters, the longest of the three captions in German and longer than any other language's `payee` string (the next are 12), and only at AX2 does it exceed the column.

Evidence is local only (`.tmp/qa-20261110/w22i/`): `13-new-txn-de-ax2.png`, `15-new-txn-de-ax2-repeat.png` (and `-crop`).

## Root cause

`mobile/src/screens/multi-postings-transaction/multi-postings-transaction-screen.tsx:818` passes `t("payee").toUpperCase()` as the `ListItem` title. In `mobile/src/screens/multi-postings-transaction/list-item.tsx` the title is a plain `<Text style={styles.title}>` (`:94`) with no `numberOfLines` and no `adjustsFontSizeToFit`, in a column that shares its row with the disclosure chevron (`textWrap: { flex: 1 }`, `container.gap: 12`). Its style is `fontSizes.xs` with `letterSpacing(0.8)` (`:37-45`), uppercase. At AX2 the word does not fit one line, and iOS breaks an unbreakable word by character. The German string is `payee: "Zahlungsempfänger"` (`mobile/src/translations/de.ts:307`); it has no soft hyphen, so there is no break opportunity inside it. For scale, the next longest `payee` strings are 12 letters (`pt`, `fr`, `fa`, `es`) and fit.

## Fix

Give the caption a way to fit or to break cleanly; any one of these:

- `numberOfLines={1}` with `adjustsFontSizeToFit` and a `minimumFontScale` on the `ListItem` title, as the Android tab labels (`ledger-tabs/index.tsx:58`) and the drawer header title (`ledger-drawer-header.tsx:197`) already do. The caption is a label, not content, so shrinking it slightly is the usual treatment, and it fixes every locale and every caption in one place.
- or a soft hyphen in the German string (`Zahlungs­empfänger`), so iOS breaks it as `ZAHLUNGS-` / `EMPFÄNGER`; check natively that it survives `toUpperCase()` and the letter spacing.
- or the shorter, still correct term `Empfänger`.

Add a unit case so this cannot return unseen: render the title through the same path and assert the caption is single-line-or-shrunk (the `ListItem` source test beside `multi-postings-transaction/__tests__/`), then verify natively in German at AX2, again without saving. Mobile only; no API surface.

## Blast radius

`ListItem` is shared by New Transaction (`:813-835`: `DATUM`, `ZAHLUNGSEMPFÄNGER`, `BESCHREIBUNG`) and the Transaction Filters sheet's custom-range rows (`transaction-filters-screen.tsx:366`, `:372`), whose German captions are `Von` and `Bis` and so cannot show this; those rows appear only after choosing *Custom*, which was not done in this run. The sheet's own captions and chips (`STATUS`, `ZEITRAUM`, `KONTO`, `Benutzerdefiniert`, `Abbrechen`, `Zurücksetzen`) all fit in German at AX2 (`.tmp/qa-20261110/w22i/11-filter-de-ax2.png`). The Settings rows use their own `list-item.tsx`. Other languages were not run at AX2: by length, none of them has a caption that approaches 17 letters, so only German is expected to show it, which should be rechecked after any translation change.

## Adjacent states

`Eröffnungsdatum` in Open Account's label column also wraps by character at AX2 (`Eröffnungs` / `datum`), but it lands on the compound boundary and leaves no stray letter, so it reads acceptably and is not filed.

Searched `.pm/**` (including `done/`) for mid-word, orphan, stranded letter, `ListItem`, `PAYEE`, "Zahlungs" and German at large sizes. `w4/done/014` (Money flow `FROM` breaking mid-word) and `w21/done/1013` (account names breaking mid-word on the Accounts tab) are the same class on other strings and fixed those sites only; `w21/done/029` is New Transaction's posting accounts at AX2. **Resolved 2026-11-11** — the shared `ListItem` caption is now one line that shrinks to fit (`numberOfLines={1}`, `adjustsFontSizeToFit`, `minimumFontScale={0.7}`), as the tab labels and the drawer title already do, so New Transaction's `DATUM` / `ZAHLUNGSEMPFÄNGER` / `BESCHREIBUNG` (and the Transaction Filters custom-range rows, which share the component) fit in every language instead of breaking a word by character. Shipped in `935a3df2a` (`mobile`). Tests in `list-item-caption.test.ts`: a source pin for the rule (fails with the change reverted), and a guard that no caption word in any locale is longer than German's 17 letters, the longest it was checked with, so a longer translation has to be looked at before it passes. Verified natively on iPhone 17e / iOS 27.0, light, German, from a cold launch at AX2: the form opened from Home's `+` first row, and `DATUM`, `ZAHLUNGSEMPFÄNGER` and `BESCHREIBUNG` each read whole on one line, slightly shrunk, with no stray letter; nothing was typed or saved. Not checked: the shrink floor on a caption wider than German's, the custom-range rows, other languages at AX2, dark mode, Android. Left as the note decided: the soft-hyphen and the shorter-term alternatives were not taken.

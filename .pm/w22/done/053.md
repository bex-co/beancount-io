Dashboard `yarn test` intermittently exits 1 although every test passes. Observed 2026-11-14 from `dashboard/`: one full run printed 803 files passed and 8084 tests passed, then "Unhandled Errors: Vitest caught 1 unhandled error" and exit code 1:

`TypeError: Failed to execute 'dispatchEvent' on 'EventTarget': parameter 1 is not of type 'Event'`

It is thrown from `@radix-ui/react-focus-scope`'s unmount timer (`dist/index.mjs:92`) and attributed to `src/features/ledger-editor/directory-browse/components/__tests__/zip-download-blocked.test.tsx`. The full runs just before and after exited 0, and that file alone passed 8 of 8 isolated runs, so it is timing-dependent.

The dashboard gate (`yarn format:check`, `yarn lint`, `yarn test`, `yarn build`) is the only check before every dashboard ship, so a red exit with every test green makes the gate ambiguous.

Likely cause to confirm, not yet proven: the test leaves a Radix dialog or popover open at its end, so FocusScope's `setTimeout` fires after the jsdom window is torn down.

Repro: repeat `yarn test` from `dashboard/` and watch for exit 1 with no failing test.

Acceptance: root-cause it (reproduce, then show the timer outliving the test), fix the nondeterminism in the test or its setup, and show 20 consecutive full `yarn test` runs exiting 0.

Out of scope: any change to the shared Radix primitives.

Found while shipping w22/m10 (Bank Sync "Set for selected"); unrelated to that change.

**Resolved 2026-11-14** — root cause confirmed and fixed in `dashboard/src/test/` (`dashboard`), shipped in the commit that moves this note.

Cause. Radix `FocusScope` (every Dialog, Popover and Select) hands focus back in a `setTimeout(..., 0)` queued by its unmount cleanup (`@radix-ui/react-focus-scope` `dist/index.mjs:92`). React Testing Library unmounts in the last test's `afterEach`, so a file that ends with one open has that timer pending when Vitest tears jsdom down. Vitest's jsdom teardown (`vitest/dist/chunks/index.CyBMJtT7.js`, `teardown`) deletes the jsdom globals and puts Node's own `CustomEvent` back; the late timer then builds that and dispatches it on a jsdom element, which throws the observed `TypeError`. That is an unhandled error, so `vitest run` exits 1 with every test green, and only when the timer loses the race, which is why it came and went. The note's "likely cause" held, with one correction: the test is not special. Any file whose last test leaves a Radix dialog or popover open is exposed, and `zip-download-blocked.test.tsx` just lost the race that time.

Evidence. With the timer queued and jsdom's `CustomEvent` swapped for a non-jsdom class before it fires, the exact message from the note is thrown; yielding one macrotask after the unmount first throws nothing. It did not reproduce naturally: the file alone passed 30 of 30 runs under CPU load, and a full run passed once before the fix and once more before the baseline was abandoned, so the baseline carries no failure to compare against and the proof of the mechanism is the staged ordering above, not a before/after rate.

Fix. `src/test/settle-deferred-unmount.ts` waits one turn of the event loop, and `src/test/setup.ts` registers it as an `afterAll` in DOM environments, so the timer fires while jsdom's `CustomEvent` is still the global. The shared Radix primitives are untouched. `src/test/settle-deferred-unmount.test.tsx` stages the ordering by hand (a dialog that closes and must hand focus back, and a dialog unmounted before `CustomEvent` is swapped), and both cases fail with the `TypeError` when the helper only yields a microtask.

Checks. `yarn format:check`, `yarn lint`, and `yarn build` exit 0, and 20 consecutive full `yarn test` runs exited 0 (803 files, 8093 tests each, no unhandled errors).

Not verified: the `afterAll` registration in `setup.ts` is not itself under test (a hook there cannot observe its own effect), so removing it is caught only by the full runs, not by a unit test.

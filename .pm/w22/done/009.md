# In Persian the bottom tab bar is not mirrored on iOS 27: Home stays leftmost while the rest of the app reads right to left

**Minor · mobile · 30–45m (cause unverified) · A2.** Native mobile QA, 2026-11-10, repository HEAD `6183533d9`, development build `io.beancount.ios` 1.20261002.50 on iPhone 17e / iOS 27.0 (the only runtimes on this machine are 27.0 and 27.1), light, signed in as the QA account on an authenticated ledger. Read-only pass.

## Repro (reproduced twice, the second from a cold relaunch)

1. Settings → Language, pick **فارسی**, and tap **Restart now** in the layout prompt. (Second run: `xcrun simctl terminate` then `launch`.)
2. On **Home** the chrome mirrors: menu and bell on the right, `+` on the left, the card's tab strip and range pills run right to left, list rows have the icon on the right and the amount on the left. Open the bell: the pushed screen's native back button is on the right and points `>`.
3. Read the bottom tab bar left to right: `خانه · حساب‌ها · تراکنش‌ها · گزارش‌ها · فایل‌ها` — Home is at the **left** edge, Files at the right.

**Expected:** the tab bar mirrors with everything else, Home at the right edge. `w4/done/066` recorded exactly that on iOS 26.5 at `038faeeb`: "tab bar reversed (`خانه` rightmost)".
**Actual:** the tab order is left to right, so in Persian the first tab sits at the end a Persian reader reaches last and the bar disagrees with the header above it.

Evidence is local only (`.tmp/qa-20261110/fa/`): `tabbar-crop2.png` (full-width capture with the tab bar), `notifications-fa.png` (the mirrored pushed header, for contrast).

## Root cause (unverified)

- The bar is `NativeTabs` (`mobile/src/components/ledger-tabs/index.tsx:91-133`). Its configuration is unchanged since `038faeeb`: the same props moved from `app/(app)/(tabs)/_layout.tsx` into `ledger-tabs` in `7e452b513`, and `expo-router ~57.0.4`, `react-native 0.86.0`, `react-native-screens 4.25.2` are identical at both commits. No tab-bar direction code exists in `mobile/src`.
- `react-native-screens/ios/tabs/` has no `semanticContentAttribute` handling, while `ios/RNSScreenStack*.mm` does, which fits the stack header mirroring and the tab bar not.
- What differs from the `w4/066` run is the OS (26.5 → 27.0) and the installed native binary (built after `ca4bc3cd8`, which declared the 13 languages to iOS). Which of the two stopped the bar from following `I18nManager` is **not established**; this machine has no iOS 26 runtime to check.

## Fix

Target: in Persian on iOS 27 the tab bar has Home at the right edge; LTR locales are unchanged. First establish which side flips the bar (a throwaway build on a second runtime, or reading UIKit's layout direction for the bar at runtime). Then set the native bar's direction from `isRtlLocale` (`mobile/src/common/rtl.ts`) rather than reversing the trigger order, which would double-flip wherever UIKit already mirrors. Owner: mobile only; no API surface.

## Blast radius

One `NativeTabs` instance serves all five tabs, and the signed-out Examples tabs reuse it through `LedgerTabLayout`. The Android branch (`Tabs`, same file) and Arabic-script locales other than Persian were not exercised; Persian is the app's only RTL locale.

## Dedupe

Searched `.pm/**` (including `done/`) for tab bar together with RTL, mirror, Persian and right-to-left. The only hit is the `w4/done/066` observation above (its DoD was the Accounts magnitude bars, not the tab bar), so this is a new, possibly OS-driven, regression rather than reopened work.

## Unverified

Cause (OS vs binary), iOS 26.x behavior, Android, and VoiceOver order in the bar.

---

**Resolved 2026-11-10** — the iOS tab bar now takes its direction from the live layout: `NativeTabNavigator` passes `unstable_nativeProps={{ direction: isRtlLayout() ? "rtl" : "ltr" }}` to the host, so in Persian Home sits at the right edge with the rest of the screen. Shipped in `1a1b2193e` (`mobile`). Cause established from the dependency, not from an OS comparison: `react-native-screens` documents that on iOS the host's `direction` falls back to the *native* app's direction (the device language) and ignores `I18nManager.forceRTL`, and its own advice is to pass `ltr`/`rtl` from `I18nManager.isRTL`. The earlier `w4/066` sighting on iOS 26.5 is therefore a difference in how the bar defaulted, not something this change needs to explain. The prop is already in the installed native binary, so no rebuild is needed. The tab order is left alone, so a bar UIKit already mirrors is not flipped back. Tests render the real navigator and read the host's direction in both layouts (three fail with the fix reverted) and pin the tab order; the examples navigation test stubs the new import. Verified natively on iPhone 17e / iOS 27.0, light: English unchanged (Home at the left), Persian after the restart prompt shows خانه at the right edge, then حساب‌ها, تراکنش‌ها, گزارش‌ها, with فایل‌ها at the left and the selected pill on the right. Not checked: Android (its JavaScript tab bar is a different component), iOS 26.x, VoiceOver order, and dark mode.

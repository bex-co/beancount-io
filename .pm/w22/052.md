Production does not say which revision it runs. `/.well-known/mcp.json` reports `version: 1.0.0`, MCP `serverInfo` says `beancount-mcp 1.0.0`, and nothing else in backend-v2 exposes a build commit. On 2026-11-13, checking that `f58c89d64` was live meant calling a tool that fails on purpose and looking for the JSON line that commit added to refusals. `.pm/DO_NOT_DO.md` asks real-client MCP evaluation to record the deployed revision, and `w23/m44/t001` and `yarn mcp:conformance` need one too.

Bake the git commit into the backend-v2 image at build time (a Docker build arg, filled by the deploy platform or `git rev-parse` locally, with `unknown` when absent) and expose it read-only, for example as `revision` in `/.well-known/mcp.json` and as the MCP `serverInfo.version` suffix. Then have `yarn mcp:conformance` and the contract replay print it. A commit sha of this public repository is not a secret. Do the same for the ledger service if the platform passes the sha to it too.

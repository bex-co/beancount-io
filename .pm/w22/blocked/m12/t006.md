## Objective

Prove the whole flow on a real self-hosted stack, from a profile with no Git or `bea` state, then delete the stack.

## Context

- Create the stack from the root Blueprint; it takes about half an hour. Delete every resource afterwards and confirm each answers 404.
- Isolate the client: an empty `BEA_CONFIG_DIR`, and `GIT_CONFIG_GLOBAL` pointing at an empty file, so no Keychain entry or old helper answers instead.

## Steps

1. Sign up, create a ledger, `bea cloud login`, `bea cloud git setup`.
2. `git clone`, commit, `git push`, `git pull`: no prompt at any step.
3. Check the token in Settings → Personal access tokens (if t001 chose one).
4. `bea cloud logout`; the next `git fetch` is refused.
5. Against the managed service, `bea cloud git setup` refuses and writes nothing.
6. Delete the stack.

## Files

- none; record the facts (date, commit, result) in this task

## Acceptance criteria

- [ ] Every step above passed, recorded here with the date and the commit it ran.
- [ ] The stack is deleted.

## Out of scope

- The mobile app and OAuth MCP sign-in.

## Blocked

**Blocked 2026-11-18.** The live check was not run. Creating a stack from the root Blueprint is a call to the bex API (`deploy/bex/README.md`, "Deploy": the bex CLI can only validate a Blueprint), which needs `BEX_ACCESS_TOKEN`, and the worker's environment had none. A local stand-in (the `deploy/docker-mac` stack with `SELF_HOST=true` and `GIT_PUBLIC_URL` on the API's Git proxy) was tried and abandoned: the machine has no Docker Compose, and its container runtime could not pull images from Docker Hub.

What is verified without a server: everything in t002–t005's Done notes (real `git`, stubbed API). What only this task can show: that the login may mint the token on a running stack (t001's precondition), that the Git proxy accepts it for clone, pull and push, that it appears under Settings → Personal access tokens, and that a fetch after `bea cloud logout` is refused.

**Unblock:** the owner (or anyone with a bex API token) runs the six steps above against a temporary bex stack built from `main` at `5c9a3da1d` or later, with an empty `BEA_CONFIG_DIR` and `GIT_CONFIG_GLOBAL` pointing at an empty file, records the date, commit and result here, and deletes the stack. Alternatively, export `BEX_ACCESS_TOKEN` (and name the workspace to use) for the next `/loopx w22` run, which will do it.

## Objective

Add `bea cloud git setup`, which tells Git to ask `bea` for credentials for this deployment's Git host, and only that host.

## Context

- Git reads helpers from `credential.<url>.helper`; a URL-scoped entry keeps `bea` out of every other host. Helpers configured globally (the macOS Keychain, Git Credential Manager) are still asked too, so a stale entry there could answer first; check whether an empty `credential.<url>.helper=` before ours resets the list for that URL, and do it if so.
- `!bea cloud git credential` relies on `PATH`; record the absolute path of the running `bea` if Homebrew and `uv tool` installs differ.
- On the managed service (`deploymentInfo.selfHost` is false) the command refuses and explains SSH-key setup instead (`.pm/DO_NOT_DO.md`, "No hosted-ledger export without SSH setup").

## Steps

1. Add the command under `cli/src/cli/commands/cloud/` with bea's JSON envelope and exit codes.
2. Refuse on the managed service; refuse with a clear message when not signed in.
3. Write the URL-scoped config to the global Git config; running it twice changes nothing; `--undo` removes exactly what it wrote.
4. Mint or fetch the credential per t001.

## Files

- `cli/src/cli/commands/cloud/` (new `git` group)
- `cli/tests/`

## Acceptance criteria

- [x] After `setup`, `git config --global --get-urlmatch credential.helper https://<git host>/` names `bea`, and no other URL's config changed.
- [x] Running it twice, and `--undo`, leave the config exactly as expected.
- [x] On a deployment that is not self-hosted it refuses, writes nothing, and says how to add an SSH key.

## Out of scope

- Cloning; `bea cloud ledger clone` behavior is t005.

## Done

**Shipped 2026-11-18.** `bea cloud git setup` writes two values under `credential.<git address>.helper` in the global Git config: an empty one and `!<path to bea> cloud git credential`. Checked with real `git` 2.54: the empty value does reset the helper list for that address (a machine-wide `store` helper was not run for it, and still answers for other hosts). The path is the `bea` that was run, unresolved, so a Homebrew upgrade does not break it. It mints the token before touching the config, so a server that refuses leaves Git as it was. A second run changes nothing and mints nothing; `--undo` removes exactly the two values and revokes the token. It refuses on the managed service (exit 1, SSH-key steps in the details), on a server that does not report `selfHost`, with no login (exit 3), with no ledger (exit 2), for an address that is not plain https, and for a second server until the first is undone.

Tests: `cli/tests/test_cloud_git_sign_in.py`, against real `git` and a stubbed API. **Not yet run against a live server**: that is t006.

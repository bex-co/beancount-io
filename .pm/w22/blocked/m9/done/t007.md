## Objective

Tests for the behavior this milestone shipped, including its failure modes.

## Context

- Public-URL derivation (each host form, a collision suffix, the unset default), cookie behavior, and a guard that fails when `bex.yaml` regains a hard-coded `onbex.co` host or an unrequired `sync:false` prompt.

## Steps

1. Add the tests beside the code.
2. Add the manifest guard as a script or test that runs where `bex.yaml` can be read.

## Files

- `__tests__/` beside each change, plus the manifest guard

## Acceptance criteria

- [x] Tests fail when each change is reverted: each guarantee below was broken on purpose and a test went red (see Done).
- [x] No test only asserts that a mock was called: they check the real backend parser accepts a derived key, that it signs and verifies, that quoted output round-trips through `sh`, that the guard flags the real pre-milestone manifest, and that the Gitea wrapper creates a schema in a real Postgres.

## Out of scope

- Changing the managed service's behavior: every new switch is off unless set.

## Done

Coverage added across the milestone, each guarantee checked by breaking it:

- **Public-address resolver** (`scripts/resolve-public-url.js`, 22 tests): does nothing without `PUBLIC_URL_FROM`; fails instead of starting with beancount.io's default when it cannot learn the address; retries; refuses plain http, credentials, a query or fragment; quotes for the shell (round-tripped through `sh`, including `$(…)` and backticks); bounds each attempt. Broken on purpose: acting when unset, a silent wrong default, no escaping, no attempt timeout.
- **OAuth key derivation** (`src/config/jwks`, 14 new tests): accepted by the backend's own production parser; stable; differs per secret; signs and verifies; refuses a missing secret; derives only when opted in and never over a supplied key; a known-answer pin on the derivation constants. Broken on purpose: a changed constant, deriving without being asked.
- **Dashboard handlers** (`server/__tests__`, 13 tests): which paths are forwarded, that both handlers are invisible when their variable is unset, and the public-address answer. Broken on purpose: answering without a platform address, no longer forwarding `/.well-known/*`.
- **Blueprint guard** (`scripts/check-bex-blueprint.py`, 11 tests): a hostname, a `sync: false` input, a per-service `repo`/`branch`, a literal internal address, and a reference to an undeclared resource each trip it; comments do not. Run against the manifest as it was before this milestone it reports 37 problems, and 0 now. Each rule was switched off in turn and a test failed. It runs in a new workflow, `CI (deploy)`, whenever `bex.yaml` or `deploy/bex/**` changes.
- **Gitea wrapper** (`deploy/bex/gitea/test-entrypoint.sh`, 8 checks against a real Postgres in Docker): creates the schema before Gitea starts, is idempotent, refuses a bad name without starting Gitea, and waits for a database that is not up yet. With the schema step removed all 8 fail. Its first draft hung rather than failed when the refusal was missing; the check is now detached and time-boxed.
- **Test of the test, found on the way:** the guard double-reported a public hostname that contains a service name as a literal internal address; a test caught it and the pattern was fixed.

**Not covered:** the resolver's process exit code and the 5-minute give-up (the budget is a constant, so a test would take five minutes); the platform behavior on a suffixed host end to end (t004); the dashboard's behavior with a real proxy upstream (the forwarding itself is bex's and h3's, the handler's gating is tested).

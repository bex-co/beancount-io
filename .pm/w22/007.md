# A self-hosted stack's AI pull-request link falls back to someone else's Git host

Why: the AI assistant's open-pull-request tool builds the link it returns from `EXTERNAL_GITEA_HOST_NAME`, which falls back to the code default (`git.beancount.io`); on a self-hosted stack that sets nothing, the link points at a host that is not theirs.

- Found while removing the hard-coded hostnames from `bex.yaml` (w22/m9/t001): the variable can no longer be written down there, and the Gitea service now derives its own address from the platform, but the API has no way to learn it.
- Options: derive the host from Gitea itself (its user JSON `html_url` is built from `ROOT_URL`), expose it through a tiny responder in the Gitea wrapper, or omit the link when the host is not configured. Pick the smallest that keeps the link correct on a stranger's deployment.
- Check `backend-cluster/backend-v2/src/features/ai-agent/workflow/open-pull-request-tool.ts` (`externalGiteaBase`) and `src/config/config.ts` (`gitea.hostname`).
- Needs a test that a self-hosted config never produces a `git.beancount.io` link.

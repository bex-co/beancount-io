# After a live text-size change the Accounts tab's "Account / Balance" header row is cut to its top half

**Minor · mobile · 15–20m · A2.** Native mobile QA, 2026-11-10, repository HEAD `59f13b939`, development build `io.beancount.ios` 1.20261002.50 on iPhone 17e / iOS 27.0, light, English, signed in as the QA account on its synthetic `example` ledger (the app's own example data). Read-only pass; nothing was written.

## Repro (reproduced twice, the second from a fresh relaunch)

1. `xcrun simctl terminate <udid> io.beancount.ios`, `xcrun simctl ui <udid> content_size large`, relaunch the app and dismiss the dev toast.
2. Open the **Accounts** tab (it renders at the default size).
3. With the tab still mounted, `xcrun simctl ui <udid> content_size accessibility-large` (AX2, the supported ceiling in `.pm/DO_NOT_DO.md`).

**Expected:** the column header reads whole, `Account` at the start and `Balance` at the end, as the rows below it do.
**Actual:** the header row keeps its old height and shows only the upper half of both labels (`Account`, `Bala…`). The rows below it re-lay out correctly, and the table starts about 19 pt higher than it should.

**Control (cold):** terminate, set AX2 *first*, then launch and open Accounts: the header is whole, the row is its full height and the table starts lower. Only text first measured at the smaller size clips (the mechanism `mobile/AGENTS.md` documents under "Live text-size changes").

Evidence is local only (`.tmp/qa-20261110/w22b/`): `06-accounts-live-ax2.png`, `11-accounts-live-ax2-repeat.png` (and its `-crop`) against the control `09-accounts-cold-ax2.png`.

## Root cause

`mobile/src/components/account-table/account-table.tsx:605-610`: the list header is `<View style={styles.columnHeader}>` holding two plain Texts, `columnLabel` (`:99`) and `columnLabelRight` (`:105`), with no key. The component reads `fontScale` (`:508-509`) only to choose the stacked row layout, and that restructuring is why the rows remount and re-measure while the header does not.

## Fix

Key the two header Texts on `fontScale` with distinct keys (siblings may not share one: `src/__tests__/font-scale-key-collisions.test.ts`), as `DateSectionHeader` and the three sites of `w22/008` do. Key only the Texts, never the list, so scroll and expansion state survive. Add the file and its two styles to the `KEYED_TEXTS` table in `mobile/src/__tests__/live-font-scale-remeasure.test.ts`, then verify default → AX2 → default natively against a cold AX2 launch. Mobile only; no API surface.

## Blast radius

`AccountTable` backs the Accounts tab; the Account picker's rows were keyed by `w2/m37`. The same live-change defect, on other screens, is filed as `w22/018`–`030` with independent evidence each; the mechanism is shared, the sites are not.

## Dedupe

Searched `.pm/**` (including `done/`) for `fontScale`, live text size, re-measurement, `columnLabel`, "Account / Balance". `w2/m37` (done) keyed date headers, picker rows, range pills and the file read-only notice; `w22/008` (done) the Files rows, the Reports note and chart legends; `w21/015` Home's lower cards. `w21/1013` is the cold-AX2 wrapping of long account names, not this. No item covers the Accounts header.

## Unverified

The shrink direction on this screen (observed on Settings in `w22/021`: rows keep their AX2 heights and leave blank bands; the same keys cover it), dark mode, Android, and a screen reader's reading of the header.

Customer skills still route OFX around `bea import`.

`bea import` now reads OFX/QFX with no importer (`--ofx`, auto-detected,
account remembered per ACCTID), but the skill tree still describes the
old world:

- `skills/beancount-import/SKILL.md` "Prefer `bea`" routes "OFX/QIF or
  unsupported CSV semantics" to the manual normalization stages and JSON
  batch recipe. OFX should route to `bea import --ofx` (like the CSV
  bullet routes to `references/bea-import.md`), leaving QIF and
  unsupported CSV on the manual path.
- `skills/beancount-import/SKILL.md` import-log convention records every
  non-CSV source (OFX included) as a `format:` line; an OFX source now
  wants the durable account/rules record the no-code path replays.
- `skills/beancount-import/references/dedup.md` says `bea import` writes
  `csv:sha256:` for rows without a native ID; `--ofx` rows without a
  FITID get `ofx:sha256:` (older `csv:` spellings still match).
- `skills/beancount-init/references/bea-cli.md` Version notes need an
  entry for the release that ships `--ofx` (detection, memory,
  beangulp requirement).

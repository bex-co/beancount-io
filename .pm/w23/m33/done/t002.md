## Objective

Extract backticked tool and parameter names from `docs/mcp.md`, tool and prompt descriptions, and error hints; fail when one is not in `tools/list`, allowing an explicit list of historical renames.

## Context

- Allow-list must name the 2026-10-18 renames.

## Steps

1. Write the extractor.
2. Add the allow-list with reasons.
3. Prove the test fails on a misspelled name.

## Files

- backend-cluster/backend-v2/src/features/ai-agent/api/__tests__/

## Acceptance criteria

- [x] Misspelling a tool or parameter in the docs fails the test

## Out of scope

- Prose accuracy beyond names

## Result

`src/server/api/__tests__/mcp-reference-resolution.test.ts` checks that every camelCase or snake_case name in a code span exists in the published surface (a tool name, a prompt name, or a property or enum value in any published input or output schema) for: tool descriptions, server instructions, prompt descriptions and playbook text (strict); the docs an agent follows, from "Connect a client" up to "Resources" minus the historical renames section (tool-shaped names only, because the prose also cites OAuth, config and GraphQL names); and every hint in the source (comment-stripped scan of the features and shared errors). Each of the three fails when a name is misspelled (`dry_runn` in a description, `removeLedgerFilez` in the docs, `allow_invalidd` in a hint; each proven and reverted). Allow-lists carry a reason per entry and a fourth test fails when an entry stops being needed. First run found no stale name: the two hint-source hits (`updateLedgerFile`, `getLedgerDirContent`) are GraphQL operations named on purpose, and `generated_from` is a real `getEntryContext` result key whose outputSchema is `z.unknown()`. Limit, stated in the test: one-word spellings such as the `replace` of w23/217 look like prose and are not checked.

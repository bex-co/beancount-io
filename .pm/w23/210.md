# 210 — A NUL byte in a string parameter that is forwarded to the git host answers `SERVICE_UNAVAILABLE` / `INTERNAL_SERVER_ERROR` instead of `BAD_USER_INPUT`

**Severity:** minor. Malformed input is reported as an outage or an internal fault, so a client retries it with backoff and a monitor counts it as a dependency failure. **Estimate:** 30–45 minutes including tests. **Owner:** `backend-cluster/backend-v2`. **Surfaces:** REST, GraphQL and MCP share the service; REST and MCP were exercised. **Pillar:** A1.

## Environment

Production `https://beancount.io`, `serverInfo` `beancount-mcp` 1.0.0, protocol `2025-11-25`, local HEAD `85739b2bc` (2026-11-01). API key with `ledger.read`/`write`/`admin`, synthetic ledger.

## Repro (`node .agents/skills/qa-shared/scripts/qa-mcp.mjs read <uri>`)

| URI (MCP resource) | Answer |
| --- | --- |
| `beancount://catalog/ledgers/search?q=%00` (also `q=a%00b`) | `-32000` `SERVICE_UNAVAILABLE` "Ledger API is temporarily unavailable" |
| `beancount://social/profile?username=a%00b` | `-32000` `INTERNAL_SERVER_ERROR` "Failed to fetch user from Gitea" |
| `beancount://puncsky/mcp-agent-eval/collaborators/permission?collaborator=a%00b` | `-32000` `INTERNAL_SERVER_ERROR` "Internal server error" |

REST control for the first: `GET /api-gateway/v1/ledgers/search?q=%00` → `503 {"error":{"code":"SERVICE_UNAVAILABLE","message":"Ledger API is temporarily unavailable","metadata":{"service":"Ledger API"}}}`.

## Controls

- Other control characters in the same `q` (`%01`, `%1f`, `%7f`, `%0a`, `%C2%A0`, lone surrogates) answer `ok`.
- A NUL in `ledger` is refused `BAD_USER_INPUT` (slug rule); in a file path, `Invalid file path`; in an `appendLedgerText` narration, a BQL string, a `listLedgerEntries` `account`, a branch name, a `sha`, `payee-transactions/{payee}`, `register/{account}`, `narration` and `social/followers`/`starred-repositories` `username`, it is accepted and answers an ordinary empty or `NOT_FOUND` result.
- A NUL in typed parameters (`starredBy`, `topic`, `prNumber`) is refused `BAD_USER_INPUT`.

## Expected / actual

Expected `BAD_USER_INPUT` (`-32602` / `400`) naming the parameter. Actual a 5xx-class code that says the dependency is down (`q`) or an internal fault (`username`, `collaborator`); the last also names the vendor ("Gitea").

## Root cause (partly traced)

`backend-cluster/backend-v2/src/features/ledger/workflow/ledger-workflow.ts` (~line 1734) passes `q` straight to the git host's repository search (`gitea-api.ts`); the host rejects a NUL (it cannot be stored in its text columns) with a 5xx, which the gateway maps to `SERVICE_UNAVAILABLE`. The `username` and `collaborator` calls fail the same way. Not confirmed against the host; the three cases are assumed to share a cause.

## Fix

Refuse a string containing U+0000 as `BAD_USER_INPUT` at the boundary for every parameter forwarded to the git host (`q`, `username`, `collaborator`, and the other free-text ones), through one shared string schema so REST, GraphQL and MCP agree. Tests per surface for the three cases above. Do not strip the byte silently.

## Dedupe

Searched `.pm` for NUL / `%00` / "null byte": `w21/680` (a NUL committed in a payee), `w5/744` (`bea ask` BQL), `w5/738` are different surfaces. No existing item covers the catalog search, `social/profile` or `collaborators/permission`.

## Unverified

GraphQL for the three parameters; whether other `…/social/*` or admin reads that take a login behave the same.

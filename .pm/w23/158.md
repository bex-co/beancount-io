# 158 — Journal `time` filter passes all Opens through regardless of month (`time=2026-08` → 9 August rows + 12 January Opens, `total: 21`)

## Summary
`time=2026-08` returns `total: 21`: the 9 genuine August entries plus all 12 January `open` directives. Every month shows the same +12 January tail (`2026-07` → 5+12=17; `2026-02` → 1+12=13); BQL ground truth confirms August holds exactly 9 entries. Only Opens pass — the January opening *transaction* and the August *balance* filter correctly — and the sibling scoping mechanisms disagree: `filter date:"2026-08"` → 9 (correct), `account=` never passes non-matching opens (verified via with_children true/false). Same philosophical family as w23/150 (structural passthrough with misleading totals), but a different param and mechanism; the `total` counts rows outside the requested window.

## Repro (prod, puncsky/mcp-agent-eval, read-only)
- `listLedgerEntries {"time":"2026-08","limit":50}` → total 21 = 9× `2026-08` + 12× `2026-01` (all `directive_type: Open`).
- `{"time":"2026-07"}` → 17 (5+12); `{"time":"2026-02"}` → 13 (1+12); `{"time":"2026-01"}` → 13 (12 opens + 1 txn, consistent).
- Ground truth: `SELECT date FROM entries` → Aug 9, Jul 5, Feb/Mar 1, Jan 13 (29 total).
- Controls: `filter date:"2026-08"` → the same 9 August rows, no opens; `account-journal?account=Expenses:Food&with_children=false` → 0 (non-matching opens correctly excluded there).
- Resource twin: `journal?time=2026-08` → identical total 21 (shared clamp path; earlier twin-agreement masked this — twins agreed with each other, not with ground truth).

## Root cause (main)
The journal `time` path runs Fava report-clamp semantics (`clampDirectives` → `summarizeBefore`, `backend-cluster/ledger/src/foundation/rustledger/time-clamp.ts:614`: "preserving active Opens"), which is correct for *balance computation* but leaks into the journal *listing*: opens kept as report context surface as result rows with no marker, inflating `total`. Nothing documents open-passthrough in the `time` description ("Time expression, e.g. 2026-08").

## Expected
One of: (a) exclude out-of-window opens from journal listings (clamp for balances, truncate for display); (b) keep them but mark them as context rows and exclude them from `total`; or at minimum (c) document that `time` preserves opens and that `total` includes them. (c) is a one-line doc fix; (a)/(b) is the design question. Cross-check `account-journal`/`plaintext-journal` (shared clamp) and REST (shared service).

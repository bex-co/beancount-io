# 182 — Cross-type scalar `=`/`!=` silently constant where stock refuses (w23/128+152, scalar legs)

## Summary
w23/128+152 made *composite* `=`/`!=` refuse (stock: `operator "equal(…)" not supported`; engine: silent constant-False/True). The same split holds for *scalar* cross-type pairs, unguarded: `date = 'str'`, `date = 5`, `number = 'foo'`, `account = 5`, `date = payee`, `payee = NULL` all evaluate silently on the engine (`=` → 0 rows, `!=` → all 34 rows) while stock refuses each at compile time. A mistyped literal (`date = '2026-01-01'`, which a user reasonably expects to coerce) thus reads as "no matches" instead of an error.

## Repro
- `call runBqlQuery {"ledger":"puncsky/mcp-agent-eval","query":"SELECT count(*) WHERE date = '2026-01-01' LIMIT 1;"}` → `1 row / 0` (GraphQL `queryShell` twin: same silent `0`, engine-level, all surfaces).
- Stock control: `CompilationError: operator "equal(date, str)" not supported`. Same refusal for `notequal(date,str)` (MCP: 34), `equal(date,int)`, `equal(decimal,str)`, `equal(str,int)`, `equal(date,str)` column-vs-column, `equal(str,NULL)` (MCP: 0 each).
- Controls that agree: `number = 5` (numeric tower, 0 both), `date = today()` (0 both), same-type `=` (match).

## Expected
Extend the composite-comparison-guard pattern to scalar cross-type `=`/`!=` the engine constant-folds but stock refuses (date/str/int, decimal/str, str/int, any/NULL), or teach the engine the refusal; keep the numeric tower and same-type pairs accepted. Owner decides guard-vs-engine, mirroring w23/128.

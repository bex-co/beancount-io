# `appendLedgerText` `dry_run` reports ok for text the live path refuses with 3 bean-check errors

**Severity:** minor (a preview agents trust to mean "this will commit" says ok; the live call then fails — wasted round trip, and agents may loop on the discrepancy). **Estimate:** 1–2 hours. **Owner:** `backend-cluster/backend-v2`, directive-append workflow (preview vs commit validation). **A1/A2:** agents preview before every write; a false-ok preview breaks the preview→commit contract.

## Repro (production, 2026-10-26, API key pinned to `puncsky/mcp-agent-eval`)

Identical text both calls:

```
2026-10-26 * "QALOW" "lower currency"
  Expenses:Food:Groceries  1.00 usd
  Assets:Cash  -1.00 usd
```

- `appendLedgerText {text, dry_run: true}` → `ok: true` ("No new bean-check errors").
- `appendLedgerText {text}` (live) → `VALIDATION_FAILED`: "appending it would introduce 3 new bean-check errors: interpolation failed: cannot infer currency … (main.bean:89); parse error: unexpected input (main.bean:90); parse error: unexpected input (main.bean:91)". Nothing committed.

Real beancount agrees with live: lowercase `usd` is a lexer error ("Invalid token", verified on PyPI beancount 3.2.3) — so the engine is right and the preview's validation pass is the lighter one. (Preview does catch some things: garbage text and `2026-02-30` are refused in dry too — the gap is the posting-level bean-check, not all validation.)

Supporting wording bug in the same refusal: the live hint says "The text is valid Beancount but would break the ledger", yet two of the three errors are parse errors — the text is not valid Beancount. The hint should not claim validity when parse errors are present.

## Fix (keep REST/GraphQL/MCP in parity)

Run the same bean-check validation in preview as in commit for the append path. The file-edit preview does NOT share the gap: `updateLedgerFiles` dry with a surgically inserted unbalanced transaction reports it (`1 new bean-check error: Transaction does not balance: residual 0.50 USD (main.bean:87)`, `E3001`) — so the lighter pass is append-specific. (`addLedgerEntries` has no `dry_run` to audit.) Fix the hint to distinguish "invalid text" from "valid text that breaks the ledger".

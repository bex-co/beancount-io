# Same unbalanced transaction is `UNBALANCED` on add but `VALIDATION_FAILED` on update

**Severity:** minor (both codes are honest refusals; agents matching one code miss the other path's imbalance). **Estimate:** 30–60 minutes (return `UNBALANCED` from the update path, or document the split). **Owner:** `backend-cluster/backend-v2` entry write paths (add vs update validation mapping). **A1:** an agent that keys imbalance handling on `UNBALANCED` silently misclassifies every update-path imbalance as generic validation failure.

## Repro (production, 2026-10-25, API key pinned to `puncsky/mcp-agent-eval`)

Same residual (-0.50 USD), four calls:

| op | MCP | REST |
| --- | --- | --- |
| add unbalanced txn | `UNBALANCED` "entry 0: Transaction does not balance: residual -0.50 USD" | `UNBALANCED` (HTTP 400, same message + `metadata.residual`) |
| update entry to unbalanced content | `VALIDATION_FAILED` "Validation failed for entry: this edit would introduce 1 new bean-check error: Transaction does not balance: residual -0.50 USD (main.bean:89)" | `VALIDATION_FAILED` (same message) |

Cross-surface parity holds on each row — the split is add-vs-update, not MCP-vs-REST. `docs/mcp.md` says "`UNBALANCED` when a transaction does not balance" in the append section, which reads as a general rule the update path breaks. All probe entries deleted after; fixture byte-identical, `checkLedger` clean.

## Fix (pick one)

1. Return `UNBALANCED` (with the residual) from the update path when the only new bean-check error is imbalance, keeping `VALIDATION_FAILED` for genuinely mixed/other errors — on REST/GraphQL/MCP together; OR
2. Document the split where agents will find it (`docs/mcp.md` error-code table + the `updateEntrySource` description): imbalance-on-update is `VALIDATION_FAILED`, never `UNBALANCED`.

## Dedupe

No `.pm` item covers validation-code taxonomy across add/update (searched: UNBALANCED, VALIDATION_FAILED, validation code, error code; open milestones + m1 tasks). w23/m1 t003 owns commit-failure mistranslation (`FORBIDDEN` → retryable), a different axis — this is validation taxonomy, not commit errors.

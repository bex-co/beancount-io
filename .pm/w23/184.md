# 184 — BQL `value(pos, target)` silently ignores the target (`BOGUS`/`usd`/unpriced → units)

## Summary
The engine's two-argument `value(position, target)` (a Beancount.io extension — stock has only one-arg `value`) silently returns unconverted units no matter what target is passed: `'EUR'` with no price path, lowercase `'usd'`, and outright-invalid `'BOGUS'` all yield `3000.00 USD` with no error and no warning. The report APIs learned to refuse unresolvable `conversion` (w23/156) and still disclose-or-refuse known-but-unpriced (w23/180); BQL `value()` has neither. Sibling `cost()` correctly refuses a second argument, so the dead parameter is `value()`-specific.

## Repro
- `call runBqlQuery {"ledger":"puncsky/mcp-agent-eval","query":"SELECT value(position, 'BOGUS') LIMIT 1;"}` → `3000.00 USD` (GraphQL `queryShell` twin: `[[{"USD":"3000.00"}]]`, engine-level, all surfaces).
- Same silent units for `'EUR'` (0 `FROM prices` rows on the ledger) and `'usd'`.
- Whether `value()` converts at all when a price path exists is unverified from here (no priced fixture on the QA ledger); the `BOGUS` leg needs no prices to judge — an invalid code can never resolve, so silent acceptance is unambiguous.

## Expected
Refuse invalid targets (`BOGUS`, bad case/shape) outright, and refuse-or-disclose unresolvable-but-wellformed ones (`EUR` without a price path), mirroring the w23/156 report rule. Owner decides refusal vs disclosure, and confirms the with-prices conversion path works.

## Status
Open (inbox). Engine BQL function semantics (rustledger 2-arg `value`); report-side precedent in `cost-valuation.ts` / `api/reports.ts`.

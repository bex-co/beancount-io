## Result

`hung-ledger-call.test.ts` runs a real `ApiClient` against a server that accepts the request and never answers, then pushes the failure through the shared error translation and the MCP envelope. Observed: the call ends at the deadline with a 504 (not forever), the client closes its socket so the engine is not left holding it, and an agent receives `SERVICE_UNAVAILABLE` with a non-empty hint and no internal text. So a hung ledger call holds a request for at most the deadline (30 s reads, 90 s writes), then lets go. The characterization also exposed a fragility: the timeout branch tested `e instanceof Error`, which is false when the abort reason (a `DOMException`) comes from another realm, as it does under Jest, so the real-socket case fell into the generic path with no status. `api-client.ts` now matches on `name === "TimeoutError"`; a new unit case pins a non-`Error` timeout. This is a robustness fix, not a demonstrated production defect (in a single Node realm `DOMException` is an `Error`).

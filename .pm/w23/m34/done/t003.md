## Objective

Bound the call and map expiry to a hinted error; for writes the hint points at a `requestId` retry.

## Context

- Parity: REST, GraphQL and MCP must behave identically.
- Error categories are pinned by w23/226.

## Steps

1. Pick the deadline with the owner-visible constant.
2. Map the error and hint.
3. Test all three surfaces.

## Files

- backend-cluster/backend-v2/src/

## Acceptance criteria

- [x] Stub call ends with a hinted error within the deadline on all three surfaces

## Out of scope

- Per-tool custom deadlines

## Result

Reshaped by t001's finding (the shared deadline already exists): no new deadline. A request that outlives it now says so. `FavaApiError` carries `timedOut`, `favaApiErrorToDomainError` turns it into `ServiceUnavailableError("Ledger API", undefined, hint)`, and the throw site's hint is the canonical one every surface reads: *the ledger did not answer before the deadline; a read is safe to retry; a write may already have committed, so re-read the ledger before repeating it, or resend an entry write with the same `requestId`*. A ledger that is simply down keeps the generic "A dependency is down" hint. `hung-ledger-call.test.ts` shows the same hint on MCP (`hint`), REST (`error.metadata.hint`, 503) and GraphQL (`extensions.hint`) from one error, and fails without the change. `ServiceUnavailableError` gained an optional third `hint` argument.

## Result

`yarn mcp:conformance` has a 17th check, `17 output-schema-conformance`. It uses the MCP SDK's own client (which compiles each published `outputSchema` when it lists tools and validates every successful call), runs `runBqlQuery` and one `appendLedgerText` `dry_run` preview that reports a new bean-check error, and writes nothing. A refused call is an error result the SDK does not validate, so it is reported as "not compared", never as a pass; without a credential the check skips. A new `--ledger owner/name` flag names the ledger for credentials not pinned to one (checks 5, 10 and 17 use it; before this they could not run against an unpinned key).

Unit tests (`scripts/__tests__/mcp-conformance.test.ts`): pass with `code` present, fail with an unpublished key, read-only credential compares only the read, `--ledger` reaches the call, skip without credentials; removing `code` from the schema turns the pass test red.

Hosted run, 2026-11-08, `beancount-mcp 1.0.0` (the deployed build is not exposed beyond that version), QA credentials, ledger `mcp-agent-eval`: checks 1–16 pass (5 and 10 now run), and **check 17 fails with the w23/230 signature** — `data/result/validation/newErrors/0 must NOT have additional properties` — because production still serves the build before `597aa09dc`. That is the live failure this task's acceptance allows for; it is already filed as w23/230 and fixed on `main`. The milestone Closeout must rerun this check after the fix deploys.

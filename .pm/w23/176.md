# BQL column/alias references are case-sensitive; stock is case-insensitive (tables + functions agree)

**Severity:** minor (loud `column not found`, one wasted turn; but every all-caps query fails). **Estimate:** 1–4h depending on fix layer (engine case-folds, or TS pre-pass normalizes identifiers outside string literals). **Owner:** ledger engine (`@rustledger/wasm` resolution) + TS shell. **A1:** agents writing `SELECT PAYEE`, `WHERE Account = …`, or `ORDER BY P` for alias `P`.

Stock beanquery resolves every identifier case-insensitively; the engine resolves only tables and function names that way — column and alias references must be exact lowercase:

- `SELECT PAYEE LIMIT 1;` / `SELECT Payee LIMIT 1;` → MCP `BAD_USER_INPUT: … column 'PAYEE' not found`; stock returns the column.
- `SELECT count(*) WHERE PAYEE = 'VISA' LIMIT 1;` → MCP refuses; stock `2`.
- `SELECT upper(PAYEE) LIMIT 1;` → MCP refuses (column, not the function); stock works.
- `SELECT payee AS P ORDER BY P LIMIT 1;` works; `… ORDER BY p …` → MCP `column 'p' not found`; stock accepts both.
- Controls, both agree: `FROM Postings` / `FROM "postings"` → 34/34 (tables insensitive), `UPPER(payee)` works both (functions insensitive).

REST and GraphQL twins refuse identically (`Invalid BQL query: Query execution error: column 'PAYEE' not found`) — one shared engine path, not a surface gap. Root cause layer: rustledger 0.24.0 resolves SELECT/WHERE/GROUP-BY/ORDER-BY names (per the `unresolved-name-guard.ts` header comment, which already documents its lazy-resolution quirks for w23/135); the TS tree has no Rust sources, so the fold belongs in the engine or a careful TS pre-pass (identifiers only — string literals like `payee = 'VISA'` must not be touched).

Dedupe: no prior art — searched column case sensitivity, `PAYEE`, alias case; distinct from w23/132 (function outtypes), w23/134-136/164 (dtype fallbacks), w23/139 (windows), w23/022's it.6130 (`LIKE`/`GLOB`/`REGEXP` co-absent) and it.5905 (WHERE can't see aliases on either). Open: 143–175 except done moves.

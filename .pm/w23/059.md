# Every ledger the product creates ships `plugin "beancount.plugins.auto_accounts"`, so writes never catch a misspelt account

**Severity:** major. A typo silently creates a new account, and the write reports "No new bean-check errors". **Estimate:** 30–60 minutes once the owner picks an option. **Owner:** `backend-cluster/backend-v2`: `defaultLedgerTemplate` in `src/features/ledger/utils/ledger-template.ts` (STARTER, also the signup `Default` ledger), and the guided setup header in `src/features/ledger/setup/build-ledger.ts:200`. **A1/A2:** an agent's only guard against a misspelt account is the write path's "never opened" refusal, and on these ledgers it never fires.

## Repro (production, 2026-10-22, `beancount-mcp` 1.0.0, OAuth `ledger.admin` account-wide)

1. `createLedger {name: "qa-…", private: true}` (STARTER).
2. `appendLedgerText {dry_run: true, text: "2026-01-07 * \"typo\"\n  Assets:Csah  -3 USD\n  Expenses:FoodAndDinning  3 USD\n"}`.

Actual: "Would add 1 directive to main.bean. No new bean-check errors." `2026-01-08 balance Assets:Chekcing 0 USD` gives the same result.

Control: the same balance line on a ledger without the plugin returns "1 new bean-check error: Account Assets:Chekcing was never opened". `docs/mcp.md` (`addLedgerEntries`) promises that kind of refusal: "a balance against an account never opened — are refused with `VALIDATION_FAILED`".

## Why it matters

STARTER is the default for `createLedger` on REST, GraphQL and MCP, and for the dashboard and mobile create forms and the signup `Default` ledger. Since w3/m53 it is also the header of every guided `setup` preset, so every new hosted ledger has the plugin. The suite's own skills (`beancount-import`, `beancount-options`, `beancount-reconcile` evals) expect an explicit `open` for every new account. ADR021 lists the plugin under "As built" without deciding to keep it.

## Options (owner decision)

1. Drop the plugin from STARTER and the setup header; existing ledgers are unchanged. Both templates already open the whole chart, so the plugin only matters for accounts that are not in the chart, which is where typos land.
2. Keep the plugin, but have every write result name the accounts it implicitly opens (`validation.newAccounts`), with a summary such as "opens 2 new accounts: Assets:Csah, Expenses:FoodAndDinning". Optionally refuse them unless `allowInvalid` is set.

Option 1 is smaller and makes hosted ledgers behave the way the docs describe. Option 2 also helps existing ledgers that carry the plugin. Tests: on a STARTER ledger, a misspelt account is refused (1) or reported (2), and a ledger created from SAMPLE is unaffected.

## Dedupe

The `auto_accounts` notes w3/301 and w5/134 cover CLI display and import, not hosted templates. w23/048 covers guided setup's duplicate `Equity:OpeningBalances`, a different defect in the same header.

---

**Unblocked 2026-10-31** — the owner chose option 1: drop `plugin "beancount.plugins.auto_accounts"` from STARTER (`ledger-template.ts`) and the guided setup header (`build-ledger.ts`); existing ledgers are unchanged. Accepted consequence: AI categorization and Plaid sync on new ledgers can only use accounts that already exist (the `autoAccounts` checks in `llm-service.ts` and `plaid-item-service.ts` then read false). Blocked since 2026-10-22 on this decision.

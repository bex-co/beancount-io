# 208 — A non-string `cursor` on the four list methods answers JSON-RPC `-32603` with a raw Zod array dump; every other method answers `-32602` `BAD_USER_INPUT`

**Severity:** minor. A malformed request is reported as an internal error that leaks schema internals, and a client cannot tell it from a server fault. **Estimate:** 30–45 minutes including tests. **Owner:** `backend-cluster/backend-v2` (MCP transport only; REST and GraphQL have no equivalent request). **Pillar:** A1.

## Environment

Production `https://beancount.io`, `serverInfo` `beancount-mcp` 1.0.0, protocol `2025-11-25`, local HEAD `7a86dc2a2` (2026-11-01). API key, synthetic ledger; the methods are not ledger-scoped.

## Repro (`node .agents/skills/qa-shared/scripts/qa-mcp.mjs rpc <method> '{"cursor":123}'`)

`tools/list`, `resources/list`, `resources/templates/list` and `prompts/list` with `params: {"cursor": 123}` each return HTTP 200 and:

```json
{"jsonrpc":"2.0","id":1,"error":{"code":-32603,"message":"[\n  {\n    \"expected\": \"string\",\n    \"code\": \"invalid_type\",\n    \"path\": [\"params\",\"cursor\"], \"message\": \"Invalid input: expected string, received number\" } ]"}}
```

There is no `error.data`.

## Controls

- `{"cursor":"bogus"}` on the same methods is accepted and ignored (the first and only page).
- A malformed parameter on `tools/call`, `resources/read`, `prompts/get` and `initialize` (`{"name":5}`, `{"uri":5}`, `{"arguments":"x"}`, `{"protocolVersion":5}`) returns `-32602` with `data: {code: "BAD_USER_INPUT", message, hint}`.

## Expected / actual

Expected `-32602` with `data.code` `BAD_USER_INPUT`, the offending field named (`params.cursor`), and a hint, as the other four methods answer. Actual `-32603` with the Zod issue array as the message.

## Root cause

`backend-cluster/backend-v2/src/server/api/composition-root.ts` wraps request validation for `tools/call` (~line 627), `resources/read` (~784), `initialize` (~894) and `prompts/get` (~922) so a parameter failure is classified as `BAD_USER_INPUT` (`mcp-errors.ts`). The four list handlers keep the SDK's own request-schema parse, whose `ZodError` falls through to the SDK's internal-error mapping.

## Fix

Give `tools/list`, `resources/list`, `resources/templates/list` and `prompts/list` the same parse-and-classify wrapper, so a malformed `params` or `cursor` answers `-32602` with the standard `data` envelope and no Zod dump. Add cases beside `mcp-route-methods` / `mcp-errors` tests for all four.

## Dedupe

Searched `.pm` for `cursor`, `-32603`, "Zod array dump": the `mcp-errors.ts` header comment records the old tools/call and resource dialects, which earlier work already fixed; none covers the list methods.

## Unverified

Whether a non-object `params` (for example a string) on the list methods has the same effect; the `tools/list` probe with a bare number is refused earlier as an invalid JSON-RPC body.

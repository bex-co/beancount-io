# REST and GraphQL refuse the owner-case variant of a pinned ledger that MCP admits

**Bug · backend-v2 · minor · ~45m · A1.** Found by the `w23/m38` audit, 2026-11-10, from source; the runtime repro is unverified.

- **Where:** `identityAllowsLedgerScope` (`src/server/api/identity.ts`) and the pin check in `src/server/api/authorization/authorization-service.ts` compare the credential's `ledgerScope` with the request's ledger spelling using `===`.
- **MCP:** resolves `PUNCSKY/x` to the pin `puncsky/x`, because host usernames are case-insensitive (`ledgerIdMatchesPin`, `w23/078`).
- **Expected:** a credential pinned to `puncsky/x` reaches `PUNCSKY/x` on REST and GraphQL too, or none of the surfaces admits it. Today REST and GraphQL answer "credential is not authorized for this ledger". It fails closed, so this is a spelling inconsistency, not a hole.
- **Fix:** one `sameLedger(a, b)` built on `canonicalLedgerId` (`src/shared/str.ts`), used by `ledgerIdMatchesPin`, `identityAllowsLedgerScope` and the authorization pin check. `ledgerIdMatchesPin` must keep treating a malformed id or pin as no match.
- **Check:** a pinned-credential row in `ledger-spelling-matrix.test.ts` that reads and writes with the owner in another case on REST, GraphQL and MCP.

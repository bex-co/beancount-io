# REST bank queries silently drop unknown keys instead of refusing them

**Severity:** minor (silent wrong filter; bodies already refuse). **Estimate:** 0.5h (one-word fix + regression test). **Owner:** backend-v2. Found by w23/m8/t005 while verifying the bank-alias docs.

## Observation (main, 2026-10-26)

`bankAccountQuery` (`banks-handler.ts:31`) is a non-strict `z.object`, so `GET .../bank-transactions/unsynced?account_id=acc_1` returns 200 with the filter silently dropped (service called with `accountId: undefined`) instead of 400. Same for `suggested-categories`, which shares the schema. Pinned as current behavior in `bank-preview.test.ts` ("ignores a snake_case staged query instead of filtering").

MCP strictifies this exact schema at use (`mcp-list-tools.ts:61`, `.strict()`), and the sibling `noPreviewQuery` is strict — so the REST leniency is incidental, not a decision. An agent pasting `account_id` into REST gets an unfiltered list with no error.

## Fix

`.strict()` on `bankAccountQuery`, flip the pinned test to expect 400, run the backend-v2 gates. Blast radius: REST clients passing unknown query params to these two routes start getting 400 instead of silently unfiltered 200s.

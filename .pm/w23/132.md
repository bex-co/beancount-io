# 132 — Mixed-type `=`/`!=` never coerces: `date`/`number` vs string silently filters everything out (it.4986)

## Summary
MCP evaluates cross-type equality without any coercion, so `WHERE date = '2026-01-01'` matches zero rows even though the day has 4 postings, and `WHERE number = '3000'` matches zero rows though one posting has number 3000. The `!=` mirror is always-TRUE (`date != '2026-01-01'` → all 34). Stock beanquery 0.2.0 refuses every form at compile time (`operator "equal(date, str)" not supported`), forcing the explicit `date('…')` spelling. Unlike the benign int/str cells of the it.3215 family (`1 = 'a'` → sensibly FALSE), date/str and decimal/str have an obvious correct coercion, so MCP's uncoerced FALSE/TRUE silently misleads instead of merely being lenient. MCP should coerce (or refuse like stock).

## Repro (prod, puncsky/mcp-agent-eval; stock = beanquery 0.2.0 on the byte-identical fixture)
- `SELECT date = '2026-01-01' LIMIT 2;` → MCP `FALSE, FALSE` on rows whose dates ARE `2026-01-01`; stock `CompilationError`.
- `SELECT count(*) WHERE date = '2026-01-01';` → MCP `0`; stock refuses. Typed control `WHERE date = date('2026-01-01')` → `4` on both.
- `SELECT count(*) WHERE date != '2026-01-01';` → MCP `34` (should be 30); stock refuses.
- `SELECT count(*) WHERE number = '3000';` → MCP `0`; stock refuses. Typed control `WHERE number = 3000` → `1` on MCP.
- Family context: it.3215 (int/str `=`/`!=` benign leniency), it.2342 (`= NULL`), it.3211 (bool/bool) — this note covers the date/str and decimal/str cells where leniency produces wrong answers.

## Expected
Coerce across the comparison (string → date/decimal where the literal parses) or refuse mixed-type equality like stock. Never silently return FALSE/TRUE for values the typed comparison would match.

## Status
Open (inbox). MCP-side (engine comparison coercion), not an upstream divergence — stock's refusal is the correct side.
- Control it.5659: the leniency is `=`/`!=`-specific — `WHERE date BETWEEN '2026-01-01' AND '2026-06-30'` refuses on BOTH (`cannot compare values` on MCP, `operator "date BETWEEN str AND str" not supported` on stock). Same for ordering: `WHERE date < '2026-06-30'` refuses on both (it.5660). A fix should align `=`/`!=` with BETWEEN/ordering strictness (or coerce all), not loosen the strict operators.
- Extended it.6336: `IN` shares the no-coercion wrong-answer — `WHERE date IN ('2026-01-01')` → MCP `[[0]]` (same silent zero as `=`), stock TypeError (`'in <string>' requires string as left operand`). The leniency covers `=`/`!=`/`IN`; BETWEEN/ordering stay strict (it.5659-5660). Mirror it.6337: `NOT IN` → MCP `[[34]]` (same silent-all as `!=`), stock TypeError. Extended it.6338: decimal `WHERE number IN ('3000')` → MCP `[[0]]`, stock TypeError (Decimal left operand) — same no-coercion class on the decimal side.

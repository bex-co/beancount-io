## Objective

Where `discrepancy` is used outside a plain projection (WHERE, ORDER BY, GROUP BY, an aggregate or function argument, or a grouped/aggregated/distinct query), the engine sees NULL and would answer silently wrong, for example `WHERE discrepancy` matching nothing. Refuse it with an error that names the supported form (select `discrepancy` alongside `date` and `account` without grouping), instead of returning wrong rows.

## Context

- Existing guards in `src/foundation/rustledger/*-guard.ts` and the shell's refusal wording (position-named errors) are the pattern.

## Steps

1. Add the refusal with the supported form in its message
2. Test each unsupported use

## Acceptance criteria

- [ ] No unsupported use returns silently empty or wrong rows
- [ ] The refusal names how to ask correctly

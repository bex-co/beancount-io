# `listLedgerEntries` / journal returns `is_empty: false` alongside `total: 0`

**Severity:** minor (misleading flag; `total`/`data` are correct). **Estimate:** 0.5–1h (one-line fix + regression test). **Owner:** ledger service. **A1/A2:** any consumer using `is_empty` to detect empty results (pagination, filtered views, agents).

## Observation (production, 2026-10-26)

A filter matching nothing returns a self-contradictory envelope on both MCP and REST:

- MCP `listLedgerEntries` `{"account":"NoSuch:Account","limit":50}` → `total: 0`, `data: []`, `is_empty: False` (it.1907)
- REST `GET /api-gateway/v1/ledgers/puncsky/mcp-agent-eval/journal?account=NoSuch:Account&limit=5` → `{"total":0,"data":[],"is_empty":false}`
- Same on an out-of-range page with matches elsewhere: `offset: 100` → `total: 29`, `data: []`, `is_empty: False` (it.1899) — consistent with a total-based reading there, but the filtered-to-zero case is not.

- GraphQL `getLedgerJournal(ledgerId: "puncsky/mcp-agent-eval", query: {account: "NoSuch:Account", limit: 5}) { total is_empty data }` → `{"total":0,"is_empty":false,"data":[]}` (it.1911) — all three surfaces agree.

Root cause is shared, in the ledger service: `backend-cluster/ledger/src/features/ledger/service/ledger-journal-service.ts:745` computes `const isEmpty = snapshot.directives.length === 0` — ledger-level emptiness, not result-level — and returns it at :796.

The backend-v2 side expects the result-level reading: `journal-parity.test.ts:552-560` pairs `total: 0` with `is_empty: true`, and the MCP output schema (`mcp-list-tools.ts`, `listLedgerEntriesOutput`) carries the boolean with no description, so consumers can only read it as "this result is empty". The ledger OpenAPI says "Whether the journal is empty" (`beancount-ledger.openapi.json`), which does not disambiguate filtered queries.

## Fix

Compute the flag from the filtered result (`is_empty: total === 0` after display filters), keeping the ledger-level check only where the whole journal is genuinely meant. Add a regression test with a filter matching zero rows on a non-empty ledger, asserting `total: 0, data: [], is_empty: true`, plus the out-of-range-page case. Document the field on the MCP output schema.

## Dedupe

Result-envelope semantics, not a naming or error-code gap — distinct from w23/102 (int32 offset error) and w23/109 (bare-FROM regression). Searched: is_empty, isEmpty, empty page, total 0; open: m7, 095–110.

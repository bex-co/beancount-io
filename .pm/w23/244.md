# docs/mcp.md says a resource URI under another scheme "still returns the SDK's own refusal", but production answers it as a coded NOT_FOUND with a hint

**Trivial · docs · backend-v2 · 10m · A1.** Found by MCP QA, 2026-11-14, against `https://beancount.io` (`beancount-mcp 1.0.0`, 47 tools), read-only. Docs-only: the behavior is the intended one and its own test asserts it.

`backend-cluster/backend-v2/docs/mcp.md`, "Failure codes" (about line 1711), ends its resource-refusal paragraph with: "A URI under another scheme is not this server's to answer and still returns the SDK's own refusal." The server does answer it, with the same coded envelope as any other unmatched URI.

Repro, with any MCP key (read-only is enough):

```sh
node .agents/skills/qa-shared/scripts/qa-mcp.mjs read https://example.com/x
```

Result: JSON-RPC error `-32002`, `data.code` `NOT_FOUND`, message

```
NOT_FOUND: Resource with ID 'https://example.com/x' not found
Hint: No resource template matches that URI. Call `resources/templates/list` for the inventory; a ledger read is `beancount://{owner}/{name}/<segment>`.
```

Control: `beancount://nope` answers the same `-32002`/`NOT_FOUND` with the same hint. So the documented "SDK's own refusal" (an uncoded, double-prefixed `-32602`) is not what a client receives.

Cause: the `resources/read` handler in `src/server/api/composition-root.ts` parses the URI itself, tries every template, and ends in one `NotFoundError` with that hint for any unmatched URI, whatever its scheme. `src/features/ai-agent/api/__tests__/mcp-resources.test.ts`, "refuses a URI in another scheme as a coded NOT_FOUND", asserts `-32002`, `data.code: NOT_FOUND` and a hint naming `resources/templates/list`. That came with w5/041 (`83c13deb5`, 2026-10-03). The doc sentence was written in `c86144b3b` (2026-09-16), before that fix, from the then-true behavior; the w4/070 closeout paragraph "Not fixed: a URI under another scheme" is the same stale claim and stays as history.

Expected: the sentence says a URI under another scheme is refused as `NOT_FOUND` (`-32002`) with the same hint, or is dropped. No code change, no REST or GraphQL surface involved (the resource read is MCP-only), and no tool-list or template change.

Dedupe: searched `.pm/**` including `done/` and `blocked/` for "another scheme", "other scheme" and "SDK's own refusal". Only w4/070 (the shipped closeout above) and w5/041 (the fix) match.

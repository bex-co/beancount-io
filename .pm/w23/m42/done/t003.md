## Objective

Write the service that reverts one commit: a preview under the `w23/m21` rule (verdict, files, no writes), then one revert commit that names the original, refusing when a later commit touched the same lines.

## Context

- `w23/m21` preview rule; `w1/228` bullet on revert
- Authorization: a write action; a read-only credential is refused FORBIDDEN

## Steps

1. Compute the reverse change from the commit
2. Refuse a conflict with a later commit and name it
3. Write the revert commit with a message naming the original sha

## Files

- backend-cluster/backend-v2/src/features/ledger/

## Acceptance criteria

- [x] A revert of the latest commit restores the previous file contents and verdict
- [x] A revert blocked by a later commit is refused and nothing is written

## Out of scope

- Adjacent work not named above

## Result

`LedgerWorkflow.revertLedgerCommit` (the pure plan is `utils/commit-revert.ts`): authorizes as a file write, resolves a sha or branch name through the git host, refuses a merge or root commit (`BAD_USER_INPUT`) and an unknown commit (`NOT_FOUND`), reads each touched file at the commit, its parent and now, plans the inverse operations or refuses with `CONFLICT` naming every file a later commit changed, previews through an `onProjectedFiles` hook (the MCP tool projects bean-check over the files it would leave, as the rename does) and commits through `change-files` with git's message wording, answering the revert's own `commit`. Tests: `commit-revert.test.ts` (the plan, every conflict), and the differential harness runs three revert cases (restore, delete an added file, a refusal) with the preview and the commit giving the same verdict.

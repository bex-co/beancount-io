# `renameLedgerFile` takes `message` where its file-write siblings take `description`

**Severity:** minor (strict schemas; agents copy the commit-message arg from create/update/delete to rename and get a refusal). **Estimate:** 30–60 minutes incl. parity. **Owner:** `backend-cluster/backend-v2`, rename tool + REST/GraphQL counterparts. **A1/A2:** rename is one of five file mutations; it alone spells the commit message differently.

## Repro (production, 2026-10-26, API key pinned to `puncsky/mcp-agent-eval`)

Schemas via `tools/list`, strictness verified live:

| tool | commit-message arg | sibling spelling |
| --- | --- | --- |
| `createLedgerFiles` / `updateLedgerFiles` / `deleteLedgerFiles` | `description` | `message` → `BAD_USER_INPUT: Unrecognized key` |
| `renameLedgerFile` | `message` | `description` → `BAD_USER_INPUT: Unrecognized key` |

(`createPullRequest`'s `title`/`description`/`clearCommitMessage` are PR-domain fields, not the file-commit message — out of scope.) Neither spelling is aliased.

## Fix (keep REST/GraphQL/MCP in parity)

Accept `description` on rename (or `message` on the file writes — prefer aliasing toward `description`, the 3-of-4 majority) with an alias for backwards compat, following the w23/m3 (done) alias pattern. Document in `docs/mcp.md`.

## Dedupe

Same naming family as w23/m3 (done, entry tools), w23/096 (bank args), w23/097 (universal flags), w23/098 (resource params), w23/100 (object keys) — distinct args, filed separately so each can close independently. Searched: rename message, commit message arg; open: m4, 092–100.

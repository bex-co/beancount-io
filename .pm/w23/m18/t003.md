## Objective

Issue a `ledger_repo_id` claim next to `ledger_id` when a token is minted for a pinned grant, and resolve it to the current name when the token is verified. A token without the claim (issued before this change, or from an old refresh grant) falls back to the name and gets the claim at its next issue.

## Context

- `src/features/oauth/api/oidc-route.ts` (`extraTokenClaims`), `src/features/oauth/utils/oauth-token-gen.ts`, `src/features/oauth/utils/oidc-verify.ts:154`.
- Do not change `sub` (`userId:ledgerId`): released clients persist refresh grants against it.

## Steps

1. Add the claim at issuance (the lookup is asynchronous)
2. Resolve it at verification into the identity
3. Keep name-only tokens working

## Acceptance criteria

- [ ] A pinned token addresses its ledger by the new name after a rename
- [ ] A pinned token for a deleted repository is refused
- [ ] `sub` is unchanged

## Objective

Add a small service that turns a ledger name into its stable numeric repository ID (`ledgers.getLedger`, which returns `id`) and a repository ID back into the ledger's current `owner/name` (`admin.getLedgerByRepoId`, which returns `full_name`), with a short per-process cache. A deleted repository resolves to nothing; a failed lookup is an error, never a silent pass.

## Context

- `backend-cluster/backend-v2/src/features/ledger/utils/ledger-access-check.ts` already reads `ledgerData.id`; `ledger-asset-service.ts` already uses `admin.getLedgerByRepoId`.
- Cache entries must be short-lived (a rename should show within seconds) and keyed by repo ID, never by name.

## Steps

1. Write the resolver behind a narrow interface
2. Cover rename, delete and lookup failure in unit tests

## Acceptance criteria

- [ ] Name to ID and ID to current name work, including after a rename
- [ ] A deleted repository and a failing lookup are distinguishable and never read as a match

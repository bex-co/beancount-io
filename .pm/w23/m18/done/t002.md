## Objective

Add a nullable `ledger_scope_repo_id` column to API keys (drizzle migration) and store the repository ID when a ledger-scoped key is minted. When a key's identity is built, resolve the stored ID to the ledger's current name so every existing string comparison sees the canonical name. A legacy key (name only) binds to the ID on first use, with the ID the name resolves to at that moment.

## Context

- `src/features/apikeys/service/api-key-service.ts` (mint, `ledgerScope`), `src/features/apikeys/data/api-key-model/schema.ts`, `src/server/api/identity.ts:449` (key to identity).
- Drizzle migrations live in `src/drizzle/migrations`; generate with the package's drizzle tooling, never hand-edit a lockfile.

## Steps

1. Add the column and migration
2. Store the ID at mint
3. Resolve ID to current name in the key's identity
4. Lazily bind legacy keys on first use
5. Tests, including a rename

## Acceptance criteria

- [x] A key minted for `a/p1` still works as `a/p2` after the rename
- [x] A key whose repository was deleted is refused, not matched to a recreated name

Shipped: migration `0026_api_key_pin_repo_id` adds `api_keys.ledger_scope_repo_id` (run it on deploy); mint records the ID and refuses a ledger that does not exist; `resolveIdentity` resolves a key's ID to the ledger's current name (`Identity.ledgerScope`, plus `ledgerScopeRepoId`), refuses a key whose repository is gone, and binds a legacy name-only key on first use. Tests in `api-key-identity.test.ts` and `api-key-service.test.ts`.

# 168 — Text results render zero rows as the empty string (no headers, no marker)

## Summary
`queryResultToText` (shared by MCP `runBqlQuery` and GraphQL `queryShellText`) returns `""` for zero-row results — no headers, no row count, no marker. An agent reading text alone cannot tell an empty result's columns, or distinguish it from a swallowed error, without calling the structured tool. (Errors do throw rather than swallow, so `""` unambiguously means zero rows today — but only if the agent knows that.)

## Repro (prod, puncsky/mcp-agent-eval)
- Any zero-row query on either text surface renders `""` — no headers, no `0 rows` marker — while the structured twin reports columns + dtypes (it.6115).

## Expected
Owner/product call on the empty marker: either render headers (+ optional `0 rows` marker) for zero-row text results, or document `""` as the established empty marker with `rowCount` beside it. Changing `""` redefines a contract text parsers may rely on — do not change it as a drive-by.

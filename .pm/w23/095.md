# Five mutation tools have no `dry_run`: rename, typed add, and all three entry-source writes

**Severity:** minor (agents must commit a rename — which can rewrite `include` lines in other files — an entry rewrite, an entry delete, or a typed insert to see what it does). **Estimate:** 2–4 hours incl. parity. **Owner:** `backend-cluster/backend-v2`, rename + entry workflows + REST/GraphQL counterparts. **A1/A2:** agents preview writes before committing; nearly half the mutation surface cannot be previewed.

## Repro (production, 2026-10-26, API key pinned to `puncsky/mcp-agent-eval`)

Full mutation-preview matrix (MCP surface; each `dry_run: true` rejected or honored):

| tool | `dry_run` |
| --- | --- |
| `createLedgerFiles` / `updateLedgerFiles` / `deleteLedgerFiles` / `appendLedgerText` | honored (previews run the full bean-check per w23/093's audit) |
| `renameLedgerFile` | `BAD_USER_INPUT: Unrecognized key: "dry_run"` |
| `addLedgerEntries` | `BAD_USER_INPUT: Unrecognized key: "dry_run"` (with an otherwise valid typed transaction) |
| `updateEntrySource` | `BAD_USER_INPUT: Unrecognized key: "dry_run"` |
| `deleteEntrySource` / `deleteEntrySources` | `BAD_USER_INPUT: Unrecognized key: "dry_run"` (schemas confirmed via `tools/list`) |

The rename gap was first noted as an aside in w23/029 (2026-10-21, "(Separately, `renameLedgerFile` has no `dry_run`...)") and never spun out; the entry-tool gaps were found extending that probe this session (it.469). All five verified live on production.

## Fix (keep REST/GraphQL/MCP in parity)

Add `dry_run` to all five paths on every surface: rename previews the move plus the `updateIncludes` rewrites (paths and new include lines); entry add/update/delete preview the resulting entry source (rendered text + validation) with the same bean-check the commit runs. Document alongside the other write previews in `docs/mcp.md`.

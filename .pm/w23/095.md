# `renameLedgerFile` has no `dry_run`, unlike every other file write

**Severity:** minor (agents must commit a rename — which can rewrite `include` lines in other files — to see what it does). **Estimate:** 1–2 hours incl. parity. **Owner:** `backend-cluster/backend-v2`, rename workflow + REST/GraphQL counterparts. **A1/A2:** agents preview file writes before committing; rename is the one they cannot preview, and with `updateIncludes` it touches files beyond the renamed one.

## Repro (production, 2026-10-26, API key pinned to `puncsky/mcp-agent-eval`)

`renameLedgerFile {oldPath: "main.bean", newPath: "main2.bean", dry_run: true}` → `BAD_USER_INPUT: Unrecognized key: "dry_run"`. The tool schema is `oldPath/newPath/message/updateIncludes/ledger` — no preview flag, while `createLedgerFiles`, `updateLedgerFiles`, and `deleteLedgerFiles` all take `dry_run` (and their previews run the full bean-check per w23/093's audit).

First noted as an aside in w23/029 (2026-10-21, "(Separately, `renameLedgerFile` has no `dry_run`...)") and never spun out; re-verified on production this session.

## Fix (keep REST/GraphQL/MCP in parity)

Add `dry_run` to the rename path on all surfaces, previewing the move plus the `updateIncludes` rewrites (paths and new include lines) with the same validation the commit runs. Document alongside the other file-write previews in `docs/mcp.md`.

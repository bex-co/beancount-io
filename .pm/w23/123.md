# CLI OpenAPI pin drifted behind the file-write preview flag

Follow-up from `w23/114`: `cli/openapi/v1.json` is a pinned copy of
`backend-cluster/backend-v2/docs/openapi/v1.json` with a
`make spec-check` drift gate, and the 114 fix drifted it — `FileWrite` /
`FileDelete` gained the `dryRun` / `dry_run` twins and `FileCommitAck`
gained the `dryRun` echo, so `make spec-check` fails on `main` today.
(CLI CI is path-filtered to `cli/**`, which is why nothing went red.)

Fix is the documented two-step in `cli/Makefile`: `make spec-sync &&
make codegen`, then commit the regenerated REST client. Verified 2026-10-26
that the regen touches only the two files-path endpoint wrappers plus
`file_write.py`, `file_delete.py`, and `file_commit_ack.py`; keep any
generator-version churn in unrelated models out of the diff. No CLI
command is broken, only the gate.

Update 2026-10-26: `w23/106` drifted the pin further (open `currencies`
optional in `EntriesRequest`); the same re-pin picks up
`entries_request_entries_item_type_1_entry.py` alongside the file
models. Verified the combined regen touches only those files.

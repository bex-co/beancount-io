`addLedgerEntries` writes a `document` directive's tags and links with no separator between them (`#t1#t2^l1^l2`), where stock beancount prints `#t1 #t2 ^l1 ^l2` and the same tool prints a transaction's with spaces. Repro (production `beancount-mcp 1.0.0`, 2026-11-11, disposable `puncsky/mcp-agent-eval`; REST `POST …/entries` is identical, both a `dry_run` preview and a commit): `addLedgerEntries { entries: [{ type: "document", entry: { date: "2026-11-11", account: "Assets:Cash", filename: "qa.pdf", tags: ["t1","t2"], links: ["l1","l2"] } }] }` previews and commits the line `2026-11-11 document Assets:Cash "qa.pdf" #t1#t2^l1^l2`. A transaction in the same tool renders `#t1 #t2 ^l1 ^l2`. Of 21 typed variants (every `type`, plus tolerance, cost, price, flag, meta and tags/links on transactions) compared byte for byte with stock beancount 3.2.3 `printer.format_entry` plus `align_beancount(currency_column=61)`, 20 are identical and this is the only difference.

Nothing breaks today: stock 3.2.3 parses the unspaced form as two tags and two links, the hosted engine reads them back as `["t1","t2"]` and `["l1","l2"]`, and the `tag:`/`link:` filters and the `tags` and `links` resources all find them. The cost is the file the owner keeps: an unusual line a later `bean-format` or any other formatter rewrites, and a break with the module's own contract, which says its output is byte-identical to `fava.file.format_entries` (`backend-cluster/ledger/src/foundation/rustledger/entry-build.ts` header, golden-validated).

Cause: `tagsLinksSuffix` in `backend-cluster/ledger/src/foundation/rustledger/journal-serialize.ts:726-731` returns `parts.join("")`; the `document` case of `directiveToText` (`:837-846`, and the `note` case at `:829`) appends it after the filename, while `renderTransaction` (`:745-746`) joins its `#tag`/`^link` header parts with a space. `entry-build.ts:362` and the plaintext journal export (`ledger-journal-service.ts:996`) both go through `directiveToText`, so a ledger's existing documents with tags or links export the same way.

Fix, sub-hour: make `tagsLinksSuffix` join with a single space (its callers already put one space before it), keeping the sorted tags-then-links order; add golden cases from stock beancount for a document with tags only, links only and both (the existing goldens have none), and assert the rendered line re-parses to the same tags and links.

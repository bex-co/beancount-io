# 169 — `weight` and `account_balance` dtypes flip on empty input (wrong-family rule / missing rule)

## Summary
Two more bare columns join w23/167's flip family, found by auditing the dtype name table against the 31-column postings star. `weight` reports `Amount` with rows but `Decimal` on empty input — and stock settles which endpoint is right: `@columns.register(amount.Amount) def weight` in beanquery's `sources/beancount.py`, so the name table's `Decimal` rule is simply the wrong family. `account_balance` reports `Inventory` with rows but `str` on empty — it has no name rule at all (stock has no such column; MCP-only, so the value shape is the only contract). Both flip exactly when a branch-on-dtype consumer is most exposed, like w23/136/167.

## Repro (prod, puncsky/mcp-agent-eval; stock = beanquery 0.2.0 sources + CLI on the byte-identical fixture)
- `SELECT weight, account_balance FROM postings LIMIT 1;` → dtypes `Amount`/`Inventory`, row `[{"USD":"3000.00"}, {"USD":"3000.00"}]`.
- Same `WHERE FALSE LIMIT 1;` → dtypes `Decimal`/`str`, zero rows.
- `weight` true type: stock registers `amount.Amount` (`beancount.py:566-569`, "The computed weight used for this posting") and renders `3000.00 USD` — Amount, matching MCP's valued endpoint, contradicting its empty endpoint.
- `account_balance` true type: no stock column (grep-clean in `beancount.py`); MCP's own valued shape is Inventory (`{"USD": …}` currency-keyed map), so the empty endpoint should be `Inventory`, not `str`.
- Audit completeness: every other postings-star column holds across the full/empty pair (date/int/set/Position/Inventory/Decimal/str rules all fire; `price` is w23/167; `filename`/`lineno`/`location` blanks are the w23/016 upstream gap, dtype moot).

## Root cause (main)
`dtypeFromColumnName` (`backend-cluster/ledger/src/features/ledger/service/ledger-shell-mappers.ts:159-167`): `weight` sits in `DECIMAL_COLUMNS` (wrong family — value-inference says Amount whenever values exist, so valued and empty endpoints disagree by construction), and `account_balance` sits in no set (falls to `str`). Fix mirrors w23/136 + w23/167: move `weight` into the new `AMOUNT_COLUMNS` set 167 proposes, add `account_balance` to `INVENTORY_COLUMNS`, pin both endpoints.

## Expected
`weight` reports `Amount` and `account_balance` reports `Inventory` with zero rows, matching their valued endpoints and (for `weight`) stock's registered type. The audit above is the completeness argument — no further bare-column flips remain on postings star.

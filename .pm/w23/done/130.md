# 130 — Inner bare-`FROM <table>` (no clause before `)`) resolves column-first: real tables error, `accounts` folds (it.4203–4207)

## Summary
MCP resolves a subquery's clauseless `FROM <name>` (terminated by `)`, not `;`) column-first: unquoted real tables (`postings`, `entries`, `prices`) fail with `column '<table>' not found`, while `accounts` silently folds to the 34-row postings scope. Stock beanquery 0.2.0 tables the real names and folds `accounts` (w23/124). Adding any inner clause (`LIMIT`, `WHERE`, `GROUP BY`) or quoting the table name rescues MCP, so the broken path is specifically inner bare-`FROM <unquoted-table>`. Looks like w23/116's normalize-pipeline fix handles `;`-terminated bare FROM but not `)`-terminated inner bare FROM.

## Expected
Inner bare-`FROM <table>` resolves exactly like top-level bare-`FROM <table>` (post-116: real tables table, true columns fold, `accounts` per whatever w23/124 decides). At minimum the `column '<table>' not found` misdiagnosis should name the real problem.

**Resolved 2026-10-28** — fixed in `backend-cluster/ledger`: the engine resolves FROM names by terminator (`;`/`)` column-first, bare-EOF/clause table-first), so a new `rescueInnerTableFrom` pipeline stage (after the terminator, before the fold) gives `)`-terminated bare names an identity `WHERE true` (`true`-filter verified identity on stock 0.2.0 and the pinned engine), putting inner tables on the table path at any nesting depth. Fold columns and the dual pass through (native `)` resolution is correct for both; the dual exclusion is flagged for revisit if w23/124 lands table-first), and unknown/keyword names now table-error exactly like top-level. Also fixed in passing: the note's "quoting rescues" premise holds only for postings — quoted inner `"entries"` ran in postings scope (2, not 3) because unquote rejected `)` continuations — so `)` joins the continuation set and quoted≡unquoted now holds in inner position too. Pinned by 20 rescue unit tests + unquote case and a 10-assert live pin (raw misresolution + raw postings-scope accidents as load-bearing checks, rescued/quoted/depth-2/fold/dual/unknown asserts; rescue asserts fail pre-fix by construction).

## Objective

Add a `commit` field with the sha to the results of the writes that go through the ledger service's `change-files` (the file tools, the text append, rename and revert) so a follow-up can name exactly the change just made. The entry, source-slice, receipt and GraphQL file writes are `t010`.

## Context

- `w1/228`: `diff` is empty on commits and no sha is returned
- All three surfaces share the write services; OpenAPI and the CLI pin follow the REST shape (`make spec-sync && make codegen`)

## Steps

1. Add the field to the service results and each surface's schema
2. A preview returns no commit
3. Regenerate the OpenAPI snapshot and re-sync the CLI pin

## Files

- backend-cluster/backend-v2/src/features/ledger/
- backend-cluster/backend-v2/docs/openapi/
- cli/openapi/

## Acceptance criteria

- [x] Every committed write returns `commit` on REST, GraphQL and MCP; a preview does not
- [x] OpenAPI drift check and `make spec-check` pass

## Out of scope

- Adjacent work not named above

## Result

Done for the writes that go through the ledger service's `change-files` (scope narrowed from "every write result"; the rest is t010). The ledger package's `changeExistingFiles` returns the sha Gitea reports and `change-files` answers `{commit}`; the IDL is updated and the fava client regenerated; `LedgerRepoService.changeFiles` and `changeGeneratedFiles` return `{commit?}`. `commit` is now on: the MCP file tools (`createLedgerFiles`, `updateLedgerFiles`, `deleteLedgerFiles`) and the REST file `PUT`/`DELETE` ack; `appendLedgerText` on REST, GraphQL and MCP; `renameLedgerFile` on REST, GraphQL and MCP; and `revertCommit`. A preview has none, and a write that landed and lost its answer names none rather than a wrong one. OpenAPI regenerated and the CLI pin re-synced. Tests: the ledger package's `changeExistingFiles` returns the sha, the parity test checks the revert's `commit` is the new head on all three surfaces, and the file, append and rename suites run with the new return.

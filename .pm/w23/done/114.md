# REST file writes take no `dryRun` while MCP previews them

**Severity:** minor (parity gap; REST callers cannot preview file writes). **Estimate:** 1–2h incl. parity (service flag + REST schemas + tests). **Owner:** backend-v2. Found by w23/m9/t001 while mapping flag spellings.

## Observation (main, 2026-10-26)

MCP `create/update/deleteLedgerFiles` accept `dry_run` (`edit-ledger-files-tool.ts`), but the REST file routes (`files-handler.ts`) declare no `dryRun`/`dry_run` at all — grep finds zero flag references in the file. GraphQL has no file-content writes either (only reads plus `createLedgerFile`, which creates a ledger, not a file in one).

m9 aliases flag spellings only where flags exist, so this stays open: a REST caller has no way to preview a file write on any spelling.

## Fix

Thread a preview flag through the file-write service path and the REST schemas (and decide whether GraphQL grows file writes or documents the exception), with parity tests on the surfaces that gain it.

**Resolved 2026-10-26** — fixed in `backend-cluster/backend-v2`: REST PUT/DELETE file routes take `dryRun` / `dry_run` twins (shared fragment, `resolveFlagAlias` semantics with conflict refusal) threaded to `changeFiles`, which already supported preview; the ack echoes `dryRun` (mirroring `renameFileResult`). Tests pin both spellings threading through, the `false` echo on plain writes, and conflict refusal; break-verified. GraphQL decision: documented exception — GraphQL has no file-content writes at all, so there is no preview flag to add there. OpenAPI regenerated. Follow-up: `w23/123` (CLI re-pin).

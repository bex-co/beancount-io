# 164 — Statically type SELECT expressions for empty/all-NULL dtypes

## Summary
w23/136 fixed the core (derived columns `id`/`other_accounts`/`accounts` keep schema dtype on empty results), but its extensions show the general rule: on empty input EVERYTHING except stored-column references falls back to `str` (or `unknown` for aliases since w23/134), including constants and expressions whose type is knowable at parse time. `SELECT upper(payee), number + 1, year(date) WHERE FALSE` → `str`/`str`/`str` (unfiltered: `str`/`Decimal`/`int`); `SELECT 1, 'a', 1.5, TRUE, NULL WHERE FALSE` → all `str` (unfiltered: `int`/`str`/`Decimal`/`bool`/`str`); aggregates `sum(number)`/`min(date)` flip to `str` while `count(*)` holds `int` by schema. The dtype system needs an expression typer — literals, per-table columns (needs FROM resolution), function outtypes (w23/132's tables are the foundation), operators, aggregates — layered above the value/name fallbacks so typed expressions report their type with zero rows or all-NULL cells.

## Repro (live engine, October 2026 triage; see w23/136 for the full matrix)
- `SELECT upper(payee), number + 1, year(date) WHERE FALSE` → `str`/`str`/`str`; unfiltered → `str`/`Decimal`/`int` (it.5725).
- `SELECT count(*), sum(number), min(date), max(payee) WHERE FALSE` → `int`/`str`/`str`/`str`; unfiltered → `int`/`Decimal`/`date`/`str` (it.5726). `count(*)` holds `int` even on HAVING-emptied zero-row output (it.6037); `count(col)` too (it.6038).
- `SELECT 1, 'a', 1.5, TRUE, NULL WHERE FALSE` → all `str`; unfiltered → `int`/`str`/`Decimal`/`bool`/`str` (it.5727).
- `row_number()` flips `int`→`Decimal` on empty (it.6157): the name table's `endsWith("_number")` rule catches the function name (it.6160) — a typer keyed on the call, not the name, kills the phantom. Phantom map is exactly {`row_number`→Decimal, `count`→int} over 19 swept aliases (it.6161-6162, it.6324).
- The flip keys on delivered rows (`LIMIT 0` behaves like `WHERE FALSE`, it.6072-6073, it.6075, it.6077); all-NULL input behaves like empty for expressions (it.5730).

## Expected
A SELECT-expression typer (literals, columns via FROM resolution, function/aggregate outtypes, operators) reports the static type whenever values are absent or all NULL, on all three empty paths (WHERE FALSE, HAVING-emptied, LIMIT 0). Bare stored/derived columns keep today's name rule; the `row_number` phantom dies; w23/134's `unknown` remains for expressions the typer cannot type (and should shrink to complements like `NULL AS x`). Never report a confidently wrong concrete type.

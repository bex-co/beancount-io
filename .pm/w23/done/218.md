# 218 — A NUL byte in a bank id (`accountId`, `itemId`, `transactionIds`) answers `INTERNAL_SERVER_ERROR` / `SERVICE_UNAVAILABLE`, not `BAD_USER_INPUT`

**Severity:** minor. **Owner:** `backend-cluster/backend-v2` (`features/plaid`; REST, GraphQL and MCP). **Estimate:** ~45m. **Pillar:** A1.

Found by `qa-find-bugs-mcp` on 2026-11-05 against production (`serverInfo` `beancount-mcp` 1.0.0, protocol `2025-11-25`, local HEAD `963729ffe`; the deployed revision was not confirmed to match HEAD). Same class as [w23/210](./done/210.md), which covered git-host strings only and listed other parameters as unverified.

## Repro

Synthetic ledger `<owner>/mcp-agent-eval`, QA key, fresh requests, repeatable.

- MCP `listStagedBankTransactions {"ledger":"<o>/<n>","accountId":"a\u0000b"}` → `isError`, `INTERNAL_SERVER_ERROR` "Internal server error".
- REST `GET /api-gateway/v1/ledgers/<o>/<n>/bank-transactions/unsynced?accountId=a%00b` and `.../bank-transactions/suggested-categories?accountId=a%00b` → `500 INTERNAL_SERVER_ERROR`.
- With a read/write credential (lookups only, nothing changes): MCP `mapBankAccount` and `setBankAccountCurrency` (`accountId`) and `discardStagedBankTransactions` (`transactionIds[0]`) → `INTERNAL_SERVER_ERROR`; `syncBankTransactions`, `refreshBankConnection`, `reconcileBankAccounts` and `unlinkBankConnection` (`itemId`) → `SERVICE_UNAVAILABLE` "Authorization relationship source unavailable".
- Control: the same calls with `ab` or `qa-nonexistent` answer `NOT_FOUND` "Bank connection not found".
- Path-segment form (`banks/a%00b`) is stopped by Cloudflare with a 400, so only query, body and tool arguments are reachable.

## Expected

`BAD_USER_INPUT` naming the parameter, on REST, GraphQL and MCP alike, as w23/210 did through `src/shared/assert-no-nul.ts` (7 callers, none in `features/plaid`).

## Cause (unverified)

The id reaches a Postgres text lookup (`authorizedAccount` in `src/features/plaid/service/plaid-item-service.ts`, ~line 435; `getUnsyncedByAccountId`) or an OpenFGA tuple, and neither can hold U+0000.

## Fix

Reject NUL in every bank id (`itemId`, `accountId`, `transactionId(s)`) at the shared service boundary with `assertNoNul`, on all three surfaces, with a regression test per entry point. Then sweep the remaining id-like parameters (`entryHash`, `prNumber`, `sha`, `requestId`, `objectKey`) the same way.

## Dedupe

Searched `.pm` (including `done/`) for NUL / bank / "Authorization relationship source": only w23/210 (git-host strings) is related; no open item covers bank ids.

---

**Resolved 2026-11-05** — A NUL (U+0000) in a bank id is now refused `BAD_USER_INPUT` naming the parameter (`itemId`, `accountId` or `transactionIds`), before any policy check or database lookup, instead of `INTERNAL_SERVER_ERROR` / `SERVICE_UNAVAILABLE`. The guard sits in the service chokepoints all three surfaces share (`PlaidItemService` and `PlaidSyncService`: `authorizeBankAction`, `authorizedAccount`, `getItem`, `loadAuthorizedTransactionBatch`, `syncItemTransactions`, `getUnsyncedTransactionsForCategorization`), through the new `assertNoNulIn` beside `assertNoNul`; the byte is not stripped. `plaid-nul-ids.test.ts` drives 14 entry points with dependencies that fail the test if reached; all 14 fail with the service change reverted. Not done: the sweep of the other id-like parameters named above (`entryHash`, `prNumber`, `sha`, `requestId`, `objectKey`) and a GraphQL probe remain unverified. Shipped in the commit that moves this note (`backend-cluster/backend-v2`).

## Verified 2026-11-01

Production, backend-v2 as deployed 2026-11-01. On a disposable ledger, an API key (`ledger.read`, `ledger.write`) was minted pinned to `owner/name`, then the ledger was renamed. After the pin's 30-second name cache expired: the new name was accepted, an omitted ledger resolved to it, the old name was refused with `FORBIDDEN`, and the key listing showed the new name. Immediately after the rename the old name still answered, within that documented 30-second window. The recreate-old-name case cannot arise: a former name stays reserved (`CONFLICT`). The key was revoked and the ledger deleted. The deployed revision was not exposed by the service; the owner reported it as the latest `main` as of this date.

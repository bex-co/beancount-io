# REST and GraphQL rename return no validation block; MCP's rename does

**Gap · backend-v2 · minor · ~1h · A1.** Found by the `w23/m39` review, 2026-11-10.

- **What:** `renameLedgerFile` on MCP returns `validation` (`errorsBefore`, `errorsAfter`, `newErrors`, `valid`) for a preview and a commit, since `w23/m39` the same on both. REST `POST …/rename-file` and the GraphQL `renameLedgerFile` mutation return the move and the include rewrites and no verdict, so a REST or GraphQL caller cannot learn that a rename broke the ledger without a second `errors` read.
- **Parity:** the root `AGENTS.md` asks for equivalent results on every eligible surface. The file tools' REST and MCP results carry the verdict; GraphQL's file mutations do not either (check before building on this).
- **Fix:** build the overlays and the `{oldPath: newPath}` map in the workflow and return the verdict on `RenameLedgerFileResult` for REST, GraphQL and MCP (the check services must be reachable from the workflow, or a `validateRename` helper beside `gateFileWrite` that the three adapters call); regenerate OpenAPI and re-sync the CLI pin; replace the `onProjectedFiles` hook; drop the `exception` on `renameLedgerFile` in `write-preview-matrix.test.ts`.
- **Check:** a rename parity case on REST, GraphQL and MCP for a file that carries errors: `newErrors: []` in the preview and the commit on all three.

---

**Resolved 2026-11-10** — REST and GraphQL rename, and revert (the same gap from `w23/m42`), now carry the verdict MCP did. The workflow computes it (`runWriteWithValidation`: a projection of the files for a preview, the ledger's errors read back for a commit, the moved file's errors carried to its new path), REST publishes it flat (`errorsBefore`, `errorsAfter`, `newErrors`, `valid`, and `checked`/`checkError` when bean-check could not run), GraphQL the same fields on the response, and MCP nests it under `validation` as before. The `onProjectedFiles` hook left the workflow's contract, and the generic write-validation helpers moved from the agent tools into `features/ledger/utils` so the workflow does not import the agent feature. Tests: `rename-parity.test.ts` and `revert-commit-parity.test.ts` assert the verdict on all three surfaces, for a preview and a commit; the preview matrix's exception no longer says MCP-only. OpenAPI regenerated, CLI pin re-synced. Shipped in `b614c313d` (`backend-v2`).

# 180 — Known-but-unpriced report `conversion` still degrades to units silently

## Summary
w23/156 made unknown `conversion` codes refuse (`BOGUS`, `usd`, ledger-absent `EUR` → `Unsupported conversion …`), but a target the ledger *knows* without a usable price path still degrades to units figures downstream without surfacing anything: `?conversion=EUR` on a USD-only-prices ledger returns USD figures with no error and no `missing_prices`-style disclosure. Holdings already discloses per-leg (`missing_prices` + `valuation: "partial"`); the five Fava-API reports (balance-sheet, income-statement, trial-balance, interval-totals, account-journal) and the hierarchy endpoint do not.

## Repro (expected after w23/156)
- `statements/balance-sheet?conversion=EUR` on a ledger that names EUR (e.g. an `open … EUR` or a price leg) but holds no EUR-convertible prices → full USD report, no error, no warning. (Pre-156 the same held for every unresolvable value; post-156 only known-but-unpriced remains.)

## Expected
Either refuse known-but-unpriced targets (needs a price-path check per held→target leg at resolve time) or disclose them holdings-style (`missing_prices` legs + partial valuation) on all five reports. Disclosure is a three-surface response-shape contract change; refusal needs the price map at the `resolveConversion` call sites (already threaded for valuation). Owner decides which.

## Status
Open (inbox). Split from w23/156 (the "larger half" its Expected names); ledger `cost-valuation` + report response shapes.

**Unblocked 2026-10-30** — the owner chose to disclose, holdings-style (not refuse): the five reports (balance-sheet, income-statement, trial-balance, interval-totals, account-journal) and the hierarchy endpoint keep returning, and add `missing_prices` legs plus a partial-valuation marker on REST, GraphQL and MCP. Rationale (checked 2026-10-30): valuation looks prices up per held lot and per date and falls back to cost or units like Fava (`lot-inventory.ts` `valueLot`), so a resolve-time price-path check cannot decide it and a refusal would fail calls that produce a usable report today; the purely additive field is backward compatible. Implement in ledger `cost-valuation`/lot valuation (collect the legs that fell back) and the report response shapes, update OpenAPI + CLI re-pin, docs and parity tests.

# 153 — Ledger projects numeric `id`s where stock projects hash hex strings

## Summary
Stock types the `id` column `str` on both `entries` and `postings` and projects `hash_entry` hex (`2e3795ae…`). The ledger engine projects small numbers (`[[3],[3]]` for the first postings) — different values in a different type. Any `id`-keyed join, filter, or display ported from stock silently mismatches, and w23/132's guard types `id` as stock-str, so `id = '…'` stays unrefused while the engine answers FALSE.

## Repro (live engine + stock beanquery 0.2.0, October 2026 triage)
- `SELECT id FROM postings LIMIT 3` → MCP `[[3],[3]]` (numbers); stock `[('2e3795ae6ca0a531f99478ee8332b47b',), …]` (hex strs).
- Stock dtypes (read from `beanquery/sources/beancount.py`): `id: str` on `entries` and `postings`.

## Expected
Project stock's `hash_entry` hex ids (or refuse `id` projection/comparison loudly until the engine can). At minimum the mistyping should be loud rather than a silent value change.

# 155 — BQL `str()` refuses composite inputs stock stringifies (position, inventory, set)

## Summary
MCP's `str()` accepts only `string, integer, number, boolean, date, or amount` and refuses the three composite types with `type error: STR expects …`, while stock beanquery 3.2.3 stringifies all of them. `str(position)` → stock `3000.00 USD`, MCP refuses; `str(balance)` → stock `(3000.00 USD)`, MCP refuses; `str(tags)` → stock `frozenset()`, MCP refuses. Scalar inputs agree exactly (`str(number)` → `3000.00`, `str(date)` → `2026-01-01`, `str(cost(position))` → `3000.00 USD` on both). w23/129's resolution cites "str() rejects inventories" only as the reason no GROUP-BY rewrite exists — the input-domain gap itself has no note, no expected, and no owner. Companion to w23/146 (which covers `str()` *output* mistyping); this is the *input* side, a different mechanism.

## Repro (prod, puncsky/mcp-agent-eval; stock = 3.2.3 on the byte-identical fixture)
- `SELECT str(position) AS s LIMIT 1;` → MCP `BAD_USER_INPUT: type error: STR expects a string, integer, number, boolean, date, or amount`; stock `3000.00 USD`.
- `SELECT str(balance) AS s LIMIT 1;` → MCP refuses; stock `(3000.00 USD)`.
- `SELECT str(tags) AS s LIMIT 1;` → MCP refuses; stock `frozenset()`.
- Controls, all agree: `str(number)`, `str(date)`, `str(cost(position))` (amount) identical both sides.

## Root cause (main)
Engine-level input whitelist: the `STR expects …` type error originates in the rustledger WASM engine (same family as the `UPPER`/`LENGTH`/`arithmetic requires numeric` engine texts), which lacks str() overloads for position/inventory/set. No TS service code involved.

## Expected
Accept position, inventory, and set inputs in engine `str()` with stock's renderings (`3000.00 USD`, `(3000.00 USD)`, `frozenset()`-or-documented-set-shape), or document the input whitelist as the deliberate subset. Engine work if supported; sub-hour to document.

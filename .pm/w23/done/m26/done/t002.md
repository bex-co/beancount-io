## Objective

A call carrying `dry_run` or `dryRun` true is charged to a preview operation with the wider limit; the commit is charged as before. The MCP, REST and GraphQL spellings are all recognized, including the alias twins.

## Context

- Parity rule: accepted inputs and failure behavior are the same on every surface (root `AGENTS.md`).

## Steps

1. Add the preview op class and limit.
2. Route the three surfaces through it.
3. Keep the response `RATE_LIMITED` shape unchanged.

## Files

- `backend-cluster/backend-v2/src/server/api/composition-root.ts`
- `backend-cluster/backend-v2/src/server/rest/`
- `backend-cluster/backend-v2/src/server/graphql/`

## Acceptance criteria

- [ ] Sixty-one previews in a minute do not trigger `RATE_LIMITED`
- [ ] The sixty-first commit still does

## Out of scope

- Exempting previews entirely

## Resolution

`isPreviewRequest` (strictly boolean `true` on `dry_run` or `dryRun`) feeds a `preview` argument on `consume`/`enforceRateLimit`; only an op classified `write` earns the bucket (`verb:<verb>#preview`, budget x`PREVIEW_BUDGET_MULTIPLIER` = 3). Wired in the REST middleware (body), the GraphQL middleware (root args) and `gateMcpCall` (parsed tool input). Reads and admin ops are unchanged; a conflicting twin pair is refused by the handler before any work.

## Objective

Decide the preview bucket (wider than the 60/min per credential and tool write budget) and confirm how `setRouteRateLimitPolicy` charges a per-body operation.

## Context

- Owner decision 2026-11-07: widen. [w23/222](../done/222.md) recorded that a preview and its commit cost two write units and named the per-body hook as the way to change it.
- `gateMcpCall` in `composition-root.ts` ignores `dry_run`; REST and GraphQL key on the operation alone.

## Steps

1. Measure a preview-then-commit loop against the current budget.
2. Pick the preview limit and write the reason in the resolution.
3. Confirm the hook can charge a REST body, a GraphQL argument and an MCP argument identically.

## Files

- `backend-cluster/backend-v2/src/server/rate-limit.ts` (or the file `setRouteRateLimitPolicy` lives in)

## Acceptance criteria

- [ ] A numeric preview limit with its rationale is recorded
- [ ] The hook is shown to cover all three surfaces

## Out of scope

- Changing commit limits

## Resolution

Read the gate: `consume`/`enforceRateLimit` (`rate-limit.ts`) are the one charge point for all three surfaces; REST already hands them `ctx.request.body`, GraphQL the root-field `args`, MCP the parsed tool input. Chose three times the operation's own write budget (60 -> 180 per minute per credential and tool; an op with a smaller deliberate budget keeps the ratio), in its own `#preview` bucket. The per-body route hook (`setRouteRateLimitPolicy`) was not needed: it only redirects to another op id, while the preview bucket needs a budget multiplier, so the flag is passed to `consume` directly.

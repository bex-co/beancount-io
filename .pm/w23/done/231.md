# Probe `resources/read` template query keys and percent-encoding

Sibling of `w1/201` (invalid percent-encoding in a resource query value is accepted and answers an empty success). m12 made REST GETs refuse unknown keys; check whether MCP resource templates do the same.

- Probe with the in-process route tests: an unknown key, `?account=%ZZ`, a duplicated key, on three templates.
- If any is accepted silently, refuse it with `BAD_USER_INPUT` and a hint, with a test; if all refuse, record the evidence and close.
- Unverified: filed from a brainstorm, not from a reproduction.

---

**Resolved 2026-11-10** — probed in-process: unknown and repeated query keys were already refused on every template (`mcp-resources.test.ts`); an invalid percent-encoding in a query *value* was accepted and read as a different value (`?account=%ZZ` answered an empty journal). Query names and values are now decoded as the path is and refused `BAD_USER_INPUT` naming the parameter, shipped in `c3d261834` (`backend-v2`). REST query strings were not changed; they decode through the framework and are outside this probe.

# A request over the 2 MiB cap gets 413 "the body could not be read as a JSON-RPC request", which doesn't say it was too large

**Severity:** minor. **Estimate:** 15–20 minutes. **Owner:** `backend-cluster/backend-v2`, `mcpBodyParseFailure` in `src/features/ai-agent/api/mcp-route.ts`. **A1:** an agent writing many files in one `createLedgerFiles`/`updateLedgerFiles` call is the case `docs/mcp.md` covers with "Split large batches into separate requests". The refusal it actually gets reads like a protocol bug in its client, not a size limit.

## Repro (production, 2026-10-22, OAuth token pinned to the QA fixture)

`POST /api-gateway/mcp` with a valid JSON-RPC `ping` whose `params` hold one 2.2 MB string:

```
413 application/json; charset=utf-8
{"jsonrpc":"2.0","error":{"code":-32600,"message":"Invalid Request: the body could not be read as a JSON-RPC request"},"id":null}
```

Control: the same request at 2.0 MB answers `200`. `docs/mcp.md` documents the cap: "The complete JSON request has an independent **2 MiB** cap … Split large batches into separate requests."

## Cause

`mcpBodyParseFailure` sees only `rawBody`. For a body the parser refused for size, `rawBody` is not a string, so it falls into the generic "could not be read" branch. The status is already right (413).

## Fix

Pass the parser's error, or the response status, to `mcpBodyParseFailure`. For a size refusal, answer `-32600` with "Request body exceeds the 2 MiB limit (including JSON escaping and the envelope); split large batches into separate requests", taking the number from the configured limit. Keep the other branches. Test: a body over the limit gets 413 with that message; one under is unaffected; non-JSON is still `-32700`.

## Dedupe

w5/048 (done) introduced the JSON-RPC answers for unreadable bodies; size was not distinguished. No item covers the over-cap message.

**Resolved 2026-10-23** — an MCP request over the JSON body cap now says so. It still gets 413, and the body reads `{"jsonrpc":"2.0","error":{"code":-32600,"message":"Invalid Request: the body exceeds the 2 MiB limit (including JSON escaping and the envelope); split large batches into separate requests"},"id":null}`.

`bodyParserMiddleware` (`backend-cluster/backend-v2/src/server/middleware/body-parser-middleware.ts`) passes `mcpBodyParseFailure` (`mcp-route.ts`) the limit's label when the parser refused with 413. The label comes from the same `JSON_LIMIT` constant that sets `jsonLimit`, so the message and the cap cannot drift. A scalar (`-32600` "must be a JSON-RPC request object"), malformed JSON (`-32700`) and every non-MCP path are unchanged. `docs/mcp.md` names the refusal next to the cap.

**Tests:** `body-parser-middleware.test.ts`'s over-cap case, on a real socket with a chunked body just past 2 MiB, now asserts the exact envelope. The scalar, malformed-JSON and at-limit (1 MiB base64 upload admitted) cases are unchanged. Reverting the fix fails it.

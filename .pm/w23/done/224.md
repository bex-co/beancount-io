# 224 — Make `make check-all` independent of a cluttered `$TMPDIR` and of sandbox signals

**Severity:** minor. **Owner:** `cli` (`tests/test_release.py`, `tests/test_engine_signal_death.py`, `tests/test_doctor_captured_signal_death.py`). **Estimate:** ~45m. **Pillar:** A3.

Found running `make check-all` on a developer machine (Python 3.12 via `uv run --python 3.12`): six tests fail for reasons unrelated to the code under test.

- `test_release.py::test_customer_smoke_runs_against_the_installed_cli` fails with "Automatic root discovery … the 8192-operation filesystem search budget was exhausted": the smoke ledger lives under `$TMPDIR`, which held ~24,000 stale entries, and root discovery walks its siblings. `test_clean_checkout_installs_but_cannot_ship_without_release_locks` fails because a nested `uv` run picks CPython 3.15 and tries to build `tiktoken` (no wheel, no Rust compiler).
- The four signal-death tests cannot signal their child from inside a sandbox.

(`test_price_source_limit.py` was fixed separately: its loopback server's listen backlog of 5 refused concurrent fetches.)

## Steps

1. Give the smoke and release tests their own empty temporary root (not the shared `$TMPDIR`) so discovery cannot see unrelated siblings.
2. Pin the nested `uv` calls to the project's Python (`UV_PYTHON` from `cli/.python-version`).
3. Detect the sandbox condition in the signal tests and skip with an explicit reason, so a skipped test is visible and a real regression is still red on CI.
4. Re-run `make check-all` from a clean shell and from one with a cluttered `$TMPDIR`.

---

**Resolved 2026-11-06** — `make check-all` (CPython 3.12 via `uv run --python 3.12`) now passes the six tests this note listed, plus one more of the same kind found on the way. The causes were not what the note first assumed:

- The four "signal" failures were not sandbox signals. The negative assertion `"/0" not in stderr` matched the macOS `$TMPDIR` path itself, whose random directory name can start with `0` (`…/folders/3s/0r3njv…`). The assertions now look past the test's own temp directory.
- `test_customer_smoke_runs_against_the_installed_cli` now runs with its own `TMPDIR`, so a `$TMPDIR` holding thousands of stale entries cannot exhaust root discovery's 8192-operation search budget.
- `test_clean_checkout_installs_but_cannot_ship_without_release_locks` now pins its nested `uv` calls to `cli/.python-version`, so it no longer picks a newer CPython with no wheels for the pinned engine and tries to build `tiktoken` without a Rust compiler.
- `tests/test_price.py` used the same loopback server as `test_price_source_limit.py` (fixed earlier): its listen backlog of 5 refused concurrent fetches in the seventeen-source case; the server class now sets a backlog of 64.

Verified: the three signal and release files pass (42 tests), `tests/test_price.py` passes three runs in a row, and the full run before the last fix had one failure, the price case, now fixed. Shipped in the commit that moves this note (`cli`, tests only).

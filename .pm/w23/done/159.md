# 159 — Report `interval` is ignored on four surfaces and unvalidated on the fifth (`month`≡default, `BOGUS`≡`month`)

## Summary
`trial-balance`, `income-statement`, `balance-sheet`, and `overview` all advertise `interval` but return byte-identical output whether it is omitted, `month`, or `BOGUS` — the parameter is accepted and ignored. Only `interval-totals` honors it, and even there `interval=BOGUS` silently yields monthly buckets. An agent requesting a quarterly trial balance receives full-period hierarchies labeled identically to default. Same bare-string disease as w23/156 (`conversion`): no enum, no refusal, silent fallback — except here four surfaces ignore even *valid* values.

## Repro (prod, puncsky/mcp-agent-eval, read-only)
- `trial-balance?interval=month` ≡ `trial-balance` (byte-identical, full-period hierarchies); `?interval=BOGUS` → same report, no error.
- `income-statement?interval=month` ≡ default; `balance-sheet?interval=month` ≡ default; `overview?interval=month` ≡ default (all byte-identical).
- `interval-totals?interval=BOGUS&account=Expenses:Housing:Rent` → monthly buckets (Jul-31, Aug-31), i.e. BOGUS silently means month. (Valid `interval=month` works correctly there — it.51.)
- Controls: `shape=bogus` → `-32602 Invalid option` (the strictness `interval` lacks everywhere); `entries-handler` already uses `z.enum(["daily","weekly","monthly","quarterly","yearly"])` for its own interval — the codebase knows the pattern.

## Root cause (main)
Two links: (1) schemas declare `interval` as a bare string — `z.string().optional()` (`analysis-handler.ts:38`) and `z.string().default("monthly")` (`reports-handler.ts:56`), MCP templates likewise; (2) the ledger service consumes it only on the interval-totals paths (`const key = (interval ?? "month") as IntervalKey`, `ledger-data-service.ts:842,910`) — a blind cast that defaults BOGUS to month — while the TB/IS/BS/overview paths never read it.

## Expected
Validate `interval` against the real key set everywhere it is advertised (refuse `BOGUS` like `shape` does), and either honor it on TB/IS/BS/overview (interval series where the shape allows) or remove it from those templates so agents stop requesting breakdowns they never receive. Blind-cast-then-ignore is the unacceptable middle.

## Resolution (shipped 2026-10-28)
- Unknown spellings refuse everywhere: `resolveInterval` (the single funnel behind every series path) throws `Unsupported interval …` instead of falling back to monthly, so `interval=BOGUS` is loud on interval-totals, account-report, overview, income-statement, and balance-sheet. `""` still means unset (monthly).
- Trial-balance `interval` removed from every template it was advertised on: REST query (strict, so `?interval=` now 400s), MCP resource query names (shared `ANALYSIS_READS`), GraphQL args (`TrialBalanceArgs`), and the service params. OpenAPI regenerated, CLI re-pinned.
- Premise correction: overview, income-statement, and balance-sheet honored valid non-default intervals all along (their series bucket through the same machinery — `quarter` yields quarterly buckets, verified live); the note's byte-identical reads were default-equality (`month` ≡ omitted) plus the silent fallback. Only the hierarchy-only trial balance truly ignored the parameter.

## Objective

Add a registry of paginated reads and a test that fails when one lacks the signal on any surface.

## Context

- Follows the registry-plus-proof pattern of m21.

## Steps

1. Register every audited read.
2. Write the test and break one read to prove it fails.

## Files

- backend-cluster/backend-v2/src/server/

## Acceptance criteria

- [x] Test fails if a registered read drops the signal
- [x] `yarn test` passes

## Out of scope

- Exemptions for missing adapters

## Result

`src/server/api/__tests__/page-signals.test.ts` fails when a REST route, MCP resource or MCP tool that takes `limit`, `offset` or `page` is missing from the table (proved by removing one `pagedRead`), and drives the REST headers over HTTP and the GraphQL plugin through Apollo. `catalog-parity.test.ts` asserts REST, the MCP resource and the MCP tool give the same signal.

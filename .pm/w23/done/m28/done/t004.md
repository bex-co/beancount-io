## Objective

Bring REST and GraphQL to the same signal and regenerate the OpenAPI snapshot.

## Context

- Per the owner decision, REST adds response headers (`Link`, `X-Total-Count`, `X-Has-More`) and GraphQL adds `extensions.page`; response bodies and field types are unchanged.
- Follow the backend API parity workflow in `backend-cluster/backend-v2/AGENTS.md`.
- CI checks drift with `yarn generate-v1-openapi`.

## Steps

1. Edit handlers and resolvers.
2. Run `yarn generate-v1-openapi` and commit the snapshot.

## Files

- backend-cluster/backend-v2/src/features/ledger/api/
- backend-cluster/backend-v2/docs/openapi/

## Acceptance criteria

- [x] Same signal on all three surfaces
- [x] OpenAPI drift check passes

## Out of scope

- Cursor-based redesign

## Result

REST: `pagedRead` on a route sets `X-Has-More`, `X-Total-Count` and `Link` beside an unchanged body, documents them on the 200 in `docs/openapi/v1.json` (312 added lines, none removed), and CORS exposes them to allowed origins. GraphQL: `pageExtensionsPlugin` reads each root field's arguments and result and writes `extensions.page`, keyed by response key; no resolver changed.

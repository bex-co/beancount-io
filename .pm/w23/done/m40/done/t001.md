## Objective

Collect the BQL statements embedded in `prompts/get` bodies and the column and function lists in tool and resource-template descriptions into one checked-in list.

## Context

- `backend-cluster/backend-v2/src/features/ai-agent/api/mcp-prompts.ts` (the spending-report prompt, step 3)
- `src/features/ai-agent/tools/bql-query-tool.ts` description column list
- Pattern: `mcp-doc-claims.test.ts` (w23/m37)

## Steps

1. Parse the prompt bodies and descriptions served by `assembleMcpRegistry`
2. Write each statement and list as data with where it is served

## Files

- backend-cluster/backend-v2/src/features/ai-agent/api/__tests__/

## Acceptance criteria

- [x] Every served BQL statement and column list appears in the list, and a new one fails until it is added

## Out of scope

- Adjacent work not named above

## Result

`served-bql-claims.test.ts` reads what an MCP client reads that speaks BQL (the `runBql*` tool descriptions and every prompt body, rendered with sample arguments) and extracts three kinds of claim: the `Columns:` list (16 columns), the statement forms after `|` (`JOURNAL`, `BALANCES`) and the code-span expressions of the form `fn(...)` (`sum(weight)`, `cost(position)`). It compares them with `backend-cluster/ledger/scripts/served-bql/served-bql-claims.json`, so changing the served text fails the test until the list is regenerated (`UPDATE_SERVED_BQL=1 yarn jest served-bql-claims`). The list lives in the ledger package because that is the package with the engine; the backend test pins it the way the CLI's `openapi/v1.json` is pinned to this package's REST spec. The prompts hold two expression spans and no whole statements, so the list is small by nature.

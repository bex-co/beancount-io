## Objective

Reuse the m22 schema walker to send, for every input leaf, a lone surrogate (`"\ud800"`), an oversize string, a 1000-level nested object and a 1e5-element array, and record which ones answer 5xx or hang.

## Context

- `backend-cluster/backend-v2/src/server/api/__tests__/mcp-nul-contract.test.ts` holds the walker and the in-memory MCP client; `src/shared/assert-no-nul.ts` the central guard.
- [w23/209](../done/209.md) saw ledger calls fail for ~12 minutes after a 100 KB `runBqlQuery`; the cause was never reproduced.

## Steps

1. Add a `hostile-values` generator beside the NUL cases.
2. Run it against the service-less context, then against the in-process services for the tools that reach storage.
3. Write the findings (tool, path, value shape, outcome) into the task resolution.

## Files

- `backend-cluster/backend-v2/src/server/api/__tests__/mcp-hostile-values.test.ts` (new)

## Acceptance criteria

- [ ] The test enumerates every leaf and reports the count per value shape
- [ ] Unguarded shapes show as failing cases, the input to t002

## Out of scope

## Resolution

`mcp-hostile-values.test.ts` (backend-v2, `src/server/api/__tests__/`) derives every input leaf from the tool schemas and sends four hostile shapes (lone surrogate, 2 MiB string, 200-level nesting, 20000-member array): 825 cases over 44 tools. Before the guard, 19 failed: a lone surrogate or an oversize string reached the handler of `deleteLedger`, `leaveLedger`, `updateLedger`, `refreshManagedPrices`, `setLedgerCollaborator`, `removeLedgerCollaborator`, `generateTempAssetUploadUrl` (`filename`, `mimeType`) and `parseFile` (`fileFormat`), which have no field-level check of their own. Nesting and array shapes were already refused by the schema types.

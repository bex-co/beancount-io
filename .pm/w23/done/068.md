# File writes accept a path that differs from an existing file only by case, so a checkout on macOS or Windows silently loses one of them

**Severity:** minor (portability and silent data loss on clones; the hosted ledger itself is intact). **Estimate:** 30–45 minutes with tests. **Owner:** `backend-cluster/backend-v2` and `backend-cluster/ledger`: the new-path checks behind `createLedgerFiles`, `renameLedgerFile`'s target, pull-request changes, and routed writes on REST, GraphQL and MCP. These are the call sites w23/054 gave `assertPortableRepoPath`. **A1/A2:** a ledger cloned for `bea` or local editing (the default macOS and Windows filesystems are case-insensitive) must check out as the hosted ledger has it.

## Repro (production, 2026-10-22, `ledger.read ledger.write` token pinned to the QA fixture, dry run only)

The fixture has `main.bean`. `createLedgerFiles {dry_run: true, files: [{path: "MAIN.bean", content: "; qa\n"}]}` previews a create with "No new bean-check errors". Control: `path: "main.bean"` is refused with `CONFLICT` "main.bean already exists". The same holds for any pair, such as `txns/2026.bean` vs `Txns/2026.bean` or `TXNS/2026.bean`.

Once committed, `git clone` on a case-insensitive filesystem warns "the following paths have collided", and the working tree keeps only one file's content. `bea`, local editors and Fava then read a ledger that differs from the hosted one, without any error. For `main.bean`, the clone may even load the wrong root file.

## Fix

For every new path, refuse with `CONFLICT` when the tree already holds a path that is equal under Unicode case folding (compare per segment, so directory names count too), naming the existing path: "`MAIN.bean` would collide with `main.bean` on case-insensitive checkouts". Apply the same rule within one call (two new paths differing only by case). Leave existing collisions readable and deletable, as 054 does. Tests on REST, GraphQL and MCP: create and rename-to a case variant of a file or directory is refused; the dry run is refused the same way; a genuinely new path is unchanged.

## Dedupe

w23/054 (done) covers characters, device names and segment length, but not case. w1/075 and w5/862 are CLI-local case issues. w5/945 covers `bea init` case-variant ledger names. No item covers hosted file paths.

**Resolved 2026-10-23** — w21/770 (`7be2a2212`, shipped after this note was filed) had already refused a new file that is an existing path's case or Unicode twin, folders included, on `createLedgerFile` and on a batch's `create` (`changeFiles`, behind `createLedgerFiles`, dry run included, with twins within one call refused too). That covers this note's repro, pending a backend-v2 deploy. Two new-path call sites still lacked the check, and they now have it:

- **`renameLedgerFile`** (`ledger-workflow.ts`) checks `newPath` against the tree the rename already walks, minus the file it moves, through `listingOf` (`portable-twin.ts`). So `old.bean` → `OCCUPIED.bean` beside `occupied.bean`, or → `Txns/old.bean` beside `txns/2026.bean`, is a `CONFLICT` naming the existing path. Changing only the moved file's own case (`old.bean` → `Old.bean`), or its folder's case when it is the folder's only file, still works.
- **Pull requests** (`pull-request-service.ts`) check each file a change creates against the head branch's listing, including files created earlier in the same request. A twin is a `CONFLICT`, and the branch is deleted as for any other refused name.

The refusal keeps 770's wording ("MAIN.bean already exists as main.bean", with its hint), not the note's suggested sentence. Existing collisions stay readable, editable and deletable. The ledger service's own file routes are reached only through backend-v2, so they were left alone.

**Tests:** `rename-parity.test.ts` on REST, GraphQL and MCP covers a file twin and a folder twin (refused, nothing written, REST `CONFLICT` naming the twin) and the two self-case renames (allowed). `pull-request-parity.test.ts` on all three surfaces covers a twin of `main.bean`, two twins in one request, and a folder twin of a file (`CONFLICT` with the message, no pull request, branch deleted). `portable-twin.test.ts` adds `listingOf`. Reverting the rename check fails 6 cases and reverting the pull-request check fails 3. The pull-request fakes gained a branch listing.

**Gates:** backend-v2 typecheck, ESLint, Knip, 6866 unit tests. `upstream-survival.test.ts` failed as usual (environment-only), and `archive-parity` failed under full-suite load and passes alone (16/16). Needs a backend-v2 deploy.

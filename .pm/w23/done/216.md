# BQL names a boolean-literal column `true` where stock beanquery 0.2.0 keeps the source spelling `TRUE`

**Severity:** cosmetic (header text only; values and dtype agree). **Owner:** `backend-cluster/ledger` (column naming for literal projections). **Estimate:** 30m. **Pillar:** A1.

Found by the w23/m20 oracle replay, query id `empty-literals`: `SELECT 1, 'a', 1.5, TRUE, NULL WHERE FALSE` names its fourth column `true`; stock names it `TRUE`. A client that selects by header text breaks when it copies the spelling it wrote.

Decide whether the engine should echo the source spelling (`TRUE`, `True`, `true`) as stock does, or document the lowercase header.

The same query also differs in the dtype of `NULL` (`str` here, `NoneType` in stock); that one is the deliberate neutral marker recorded in `w23/done/134.md`, so only the header is open here.

Once resolved, drop the `columns` difference from the `empty-literals` entry in `backend-cluster/ledger/scripts/bql-oracle/allowlist.json`.

---

**Resolved 2026-11-05** — reproduced on `main`, and the gap is wider than the boolean literal. Stock beanquery 0.2.0 names an unaliased SELECT item with its verbatim source text (`1+1`, `UPPER( payee )`, `year  +  1`, `not TRUE`, `TRUE`, `null`), while the engine re-renders the parsed expression (`1 + 1`, `UPPER(payee)`, `year + 1`, `NOT true`, `true`, `NULL`), so a client that reads a column by the text it wrote found nothing.

Fixed in `backend-cluster/ledger`: the new `sourceSelectHeaders` (`bql-select-aliases.ts`) returns, per top-level SELECT item, the source text for an unaliased expression and `undefined` for an alias, a bare column (stock and the engine both name it canonically, `Year` → `year`) or a wildcard; `TRUE`, `FALSE` and `NULL` count as expressions. `LedgerShellService.runQuery` applies it through `withSourceHeaders` only when the list lines up with the engine's columns one for one, so REST, GraphQL and both MCP BQL tools (structured and text) change together.

12 unit cases in `bql-source-select-headers.test.ts`. 11 `header-*` queries were added to the w23/m20 oracle; with the hook disabled the gate fails on 10 queries (9 of them `header-*`, plus `empty-literals`), and with it enabled they pass. The `empty-literals` allowlist entry lost its `columns` difference and keeps only the `NULL` dtype one (`w23/done/134.md`). `backend-cluster/ledger/README.md` ("BQL column types") documents the rule.

Not changed: the integer-arithmetic dtype (`w23/blocked/215.md`, waiting on an owner decision) and the wildcard column set (`w23/done/022.md`). Verified: typecheck, `lint:deadcode`, `yarn test` 211 suites / 3218 tests, and `yarn verify:rustledger` (533 existing checks plus 78 oracle queries, 36 documented deviations) (`backend-cluster/ledger`).

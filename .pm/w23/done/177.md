# 177 — String literals behind aliases still sniff dtypes (w23/146 followup)

**Severity:** minor (same mistype as w23/146, narrower trigger). **Owner:** ledger shell mappers. **A1:** agents branching on BQL dtypes.

## Gap

w23/146 expression-types bare string literals and string-function calls (plus aliases over calls, via map roots). But a literal behind an alias still sniffs: `SELECT '3000.00' AS x LIMIT 1` reports `Decimal` (verified live during 146 triage), because `extractSelectAliases` keeps roots only and a literal's root is empty (`sourceRoot` returns `""` for quote-first heads).

## Fix shape

Track each alias's SELECT-item head text (not just its root) so the mapper can apply the literal rule to `'…' AS x`. Touches the shared `extractSelectAliases` helper and its w23/134 consumers — size carefully; the map shape is pinned by tests.

# 221 — `updateEntrySource` / `deleteEntrySource` previews need `allowInvalid` to show a breaking edit; `addLedgerEntries` still refuses a budget on an unopened account on a preview

**Severity:** minor. **Owner:** `backend-cluster/backend-v2` (`features/ledger`; REST, GraphQL, MCP). **Estimate:** ~45m. **Pillar:** A1.

Left open by [w23/219](./done/219.md): write previews now return the diff, `newErrors` and `valid:false` instead of refusing (`appendLedgerText`, `addLedgerEntries`, the `…LedgerFiles` tools). Two previews still refuse or hide the result:

- Entry-source edits (`updateEntrySource`, `deleteEntrySource`, `deleteEntrySources`): a preview of an edit that breaks the ledger answers only with `allowInvalid: true`; without it, the refusal hides the diff (see `source-slice-parity.test.ts`, "forced breaking preview").
- `assertBudgetAccountsExist` in `ledger-entry-service.ts` refuses a budget on an unopened account even for a preview.

## Fix

Make the entry-source previews return the projection with `valid:false`, as the other write families do, and downgrade the budget check to a `newErrors`-style warning on a preview while keeping the refusal on commit. REST, GraphQL and MCP together, with a test per family. Do this before [m21](./m21/README.md) t003 so the parity matrix does not start red on a known gap.

---

**Resolved 2026-11-05** — Entry-source edit previews (`updateEntrySource`, `deleteEntrySource`, `deleteEntrySources`) now send the ledger `allowInvalid` on a `dry_run`, so a preview of an edit that breaks the ledger returns success with the projection, `newErrors` and `valid:false` on REST, GraphQL and MCP; the commit is still refused `VALIDATION_FAILED` with the named error. `addLedgerEntries` no longer refuses a budget on an unopened account on a preview: the commit throws the first finding as before, and a preview adds each as a new error with `valid:false` and a raised `errorsAfter`. The nine source-slice cases that pinned "the preview is refused" became a preview-is-invalid case plus a commit-still-refused case per surface and operation; a new service test covers two unopened budgets in one preview. Reverting the two services fails 10 of the changed or new cases. Shipped in the commit that moves this note (`backend-cluster/backend-v2`).

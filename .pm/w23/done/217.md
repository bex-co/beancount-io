# MCP `createLedgerFiles` CONFLICT hint says to overwrite "with `replace`", which no published MCP tool has

**Severity:** minor (wrong remediation text; the refusal itself is correct). **Owner:** `backend-cluster/backend-v2`. **Estimate:** 15–30m. **Pillar:** A1.

## Repro (production 2026-11-05, `beancount-mcp` 1.0.0, protocol 2025-11-25, read/write API key; synthetic ledger `puncsky/mcp-agent-eval`, file `qa-20261105-hint.bean` created then deleted)

Call `createLedgerFiles` with `{files:[{path:"qa-20261105-hint.bean", content:";\n"}]}` twice. The second call, and a `dry_run: true` call, return `isError` with `CONFLICT`:

- message: `commit failed: File conflict: qa-20261105-hint.bean already exists` (dry run: `preview refused: …`)
- hint: ``"`create` is for a new file. Overwrite this one deliberately with `replace` (REST: `PUT` with its `sha`), or choose another path."``

No MCP tool schema contains a `replace` operation or field: `tools/list` (44 tools) shows `createLedgerFiles` takes only `path` + `content`, and `updateLedgerFiles` overwrites with `content` (+ the file's `sha`) or edits with `old_string`/`new_string`.

## Expected

The hint names a remedy valid on the surface that raised it, e.g. overwrite with `updateLedgerFiles` (pass `content` and the `sha` from `readLedgerFiles`), REST `PUT` with its `sha`, or choose another path. The `main.bean` delete and rename refusals (w23/031) already do this: "`updateLedgerFiles` with `content`".

## Root cause

`backend-cluster/backend-v2/src/features/ledger/service/ledger-repo-service.ts:514` hard-codes the legacy `editLedgerFiles` vocabulary (`create` / `replace`) written for w5/035. w23/032 later routed MCP `createLedgerFiles`, REST and GraphQL over an existing path to the same `CONFLICT`, so the legacy word now reaches MCP callers. `docs/mcp.md` (the `editLedgerFiles` mapping table) maps `updateLedgerFiles` to `editLedgerFiles` `update` and `replace`.

## Fix

Use surface-neutral wording that names `updateLedgerFiles` and REST `PUT` (or one hint per surface). The same service backs REST and GraphQL, so check their hint text in the same change. Add a contract assertion in the `mcp-errors` suite that every tool name quoted in a hint exists in `tools/list`.

## Dedupe

Searched `.pm/**` (including `done/`) for the hint text and hint + `replace`: only w5/035 (the original `editLedgerFiles`-era hint) and w23/032 (status-code alignment) touch it, and neither covers the wording.

---

**Resolved 2026-11-05** — reproduced at the source on `main`: `ledger-repo-service.ts` raised the CONFLICT for a create over an existing path with the legacy `editLedgerFiles` hint ("Overwrite this one deliberately with `replace`"), and the one test that pinned it, `edit-ledger-files-refusals.test.ts`, asserted that `error.hint` contains "replace", so the defect was enforced.

The hint is now the exported `FILE_EXISTS_HINT`: "Creating is for a new file. To overwrite this one deliberately, update it: MCP `updateLedgerFiles` with `content`, GraphQL `updateLedgerFile`, or REST `PUT` with its `sha`. Or choose another path." REST, GraphQL and MCP share the service, so all three get it, each in its own vocabulary.

New contract assertion in `ledger-repo-service.test.ts`: every MCP tool the hint quotes (names ending `LedgerFiles`) must be in `MCP_TOOLS`, which is what `tools/list` publishes, and the word `replace` must not return. The dry-run conflict test also pins `metadata.hint`, and the refusals test now expects `updateLedgerFiles` and no `replace`. Reverting the hint text to the old wording fails the new assertion.

Backend-only text change: no new capability and no parity gap. Verified: backend-v2 `yarn typecheck` and the full `yarn test` (427 suites, 8173 tests) (`backend-cluster/backend-v2`).

# 186 — 2-arg `joinstr(set, sep)` appends `sep` as a trailing element instead of joining with it

## Summary
The engine's two-argument `joinstr` (MCP-only arity — stock refuses `joinstr(set, str)`) does not use its separator: it appends `sep` as a final element and joins everything with the hardcoded `", "`. `joinstr(other_accounts, ',')` → `Assets:Bank:Savings, Assets:Cash, Equity:Opening-Balances, ,` (trailing `, ,`); `joinstr(accounts, ';')` → `…Equity:Opening-Balances, ;` (interior joins stay `", "`, the `;` dangles at the end); on an empty set it returns the bare separator (`joinstr(tags, ',')` → `,`). The 1-arg form is correct (`", "`-joined, empty → blank). Join semantics are universal enough to judge without a stock oracle: separators go between elements, and joining zero elements yields `""`.

## Repro
- `call runBqlQuery {"ledger":"puncsky/mcp-agent-eval","query":"SELECT joinstr(other_accounts, ',') LIMIT 1;"}` → `…Equity:Opening-Balances, ,`.
- `… joinstr(accounts, ';') FROM transactions …` → `…Equity:Opening-Balances, ;` (the `;` never separates).
- `… joinstr(tags, ',') …` → `,` (GraphQL `queryShell` twin: `[[","]]`, engine-level, all surfaces).
- Shape fits `[...parts, sep].join(", ")` exactly (empty → `[,].join` → `,`).

## Expected
Join with the given separator (`parts.join(sep)`), so empty → `""` and non-empty has no trailing junk; or refuse the 2-arg form like stock until it works. Owner decides fix-vs-refuse.

## Status
Open (inbox). Engine BQL function (rustledger 2-arg `joinstr`); 1-arg form + stock agree.
- Extended it.1107: N-arg form shares the bug — `joinstr(tags, ',', 'x')` on empty → `,, x`, i.e. `[...parts, ...extra].join(", ")`. Any arg past the first is appended as an element.
- Extended it.6362: no separator type check — `joinstr(tags, 5)` → `5` (number appended as an element: `[5].join(", ")`); stock refuses (`no function matches "joinstr(set, int)"`). Same mechanism, untyped extra args.
- Extended it.6363: NULL separator formats empty — `joinstr(tags, NULL)` → `""` (dtype str; `[""].join`). The text surface then shows zero row lines for the 1-row result — that half is w23/194's trim, not joinstr; the value itself is `""` on structured. Core `,` repro re-verified live this loop (still open).

**Resolved 2026-10-28** — the note left fix-vs-refuse to the owner; refusal is the stock-parity choice (stock has no `joinstr(set, sep)` overload) and removes only output that was always wrong, so the query path now refuses any `joinstr` call with more than one argument (the 2-arg separator, the N-arg extras, a number or NULL separator) naming the one-argument form `joinstr(set)`. A true separator-aware join would be an engine change; if the owner prefers that, it is a follow-up that retires the guard. Unit tests plus three live `verify:rustledger` pins (raw engine still accepts it; query path refuses; one-argument form answers); shipped in `d2807deb8` (`backend-cluster/ledger`).

# 129 — `GROUP BY` on inventory keys collapses all rows into one group (it.3960)

## Summary
MCP's `GROUP BY balance` returns ONE group with count 34, while `SELECT DISTINCT balance` correctly returns 15 distinct values. Grouping by position (26 groups) and by amount (`cost(position)`, 26 groups) both work — only inventory-typed group keys collapse. Stock beanquery refuses all of these (`GROUP-BY a non-hashable type is not supported`), so there is no stock target; the defect is MCP-internal inconsistency (DISTINCT right, GROUP wrong).

## Repro (prod, puncsky/mcp-agent-eval)
- `SELECT balance, count(*) FROM postings GROUP BY balance;` → MCP 1 row: `[{USD: 3000.00}, 34]`.
- `SELECT DISTINCT balance FROM postings;` → MCP 15 rows (3000.00, 13000.00, 13200.00, {}, …).
- Controls agree: `GROUP BY position` → 26 = DISTINCT 26; `GROUP BY cost(position)` → 26 = DISTINCT 26.
- Stock: `CompilationError: GROUP-BY a non-hashable type is not supported: "Column(name='balance')"` (and likewise for position/tags — it.3958/3959).

## Expected
GROUP BY inventory should yield the same 15 groups DISTINCT finds (or refuse like stock). A single 34-row group with an arbitrary representative balance is a silent wrong result.

Open (inbox). MCP-side (group-key hashing/comparison for inventories), not an upstream portability note.

# A ledger-pinned credential refuses its own ledger when the owner's case differs: `Puncsky/mcp-agent-eval` is "outside this credential's ledger restriction"

**Severity:** minor (fails closed, wrong message). **Estimate:** 15–20 minutes. **Owner:** `backend-cluster/backend-v2`, `resolveMcpLedger` in `src/features/ai-agent/api/mcp-context.ts` (`ledger !== context.identity.ledgerScope`). The same string comparison backs resource URIs. **A1:** agents take the owner name from a user's sentence ("my PUNCSKY books") or a URL, not from `listLedgers`. An account-wide credential accepts that spelling, a pinned one does not, and the refusal says the ledger is a different one.

## Repro (production, 2026-10-24, two OAuth tokens on a QA account, read-only)

`checkLedger` and `beancount://<ledger>/accounts` with the ledger id spelled:

| spelling | account-wide token | token pinned to `puncsky/mcp-agent-eval` |
| --- | --- | --- |
| `puncsky/mcp-agent-eval` | `ok` | `ok` |
| `PUNCSKY/mcp-agent-eval` | `ok` | `FORBIDDEN` "The selected ledger is outside this credential's ledger restriction" |
| `Puncsky/mcp-agent-eval` | `ok` | `FORBIDDEN` (same) |
| `puncsky/MCP-Agent-Eval` | `BAD_USER_INPUT` "Ledger name slug must contain 1-100 lowercase letters…" | same |

The hint says "This credential is pinned to one ledger and cannot reach another", which is false here: the ledger is the same one.

## Cause

Host usernames are case-insensitive, and the unpinned path resolves the owner that way (w23/025 compares logins case-insensitively for the same reason). Ledger names are lowercase-only and validated. The pin check compares the raw strings, so only an exact spelling matches.

## Fix

Compare the owner case-insensitively and the name exactly, then keep using the pin's canonical spelling downstream. Keep refusing everything else. Apply the same comparison to the prompts' "outside this credential's ledger restriction" text (`mcp-prompts.ts`), which uses the same string test. Tests: `PUNCSKY/x` and `puncsky/x` both resolve to the pin; a different owner or name still gets `FORBIDDEN`; the case of an unrelated owner never matches.

## Dedupe

w23/061 (done) covers pins across a rename; w23/025 compares logins case-insensitively for collaborators only; w23/068 is file-path case. No item covers the pin's owner case.

---

**Resolved 2026-10-25** — `ledgerIdMatchesPin` compares the owner case-insensitively and the name exactly; `resolveMcpLedger` and the prompts' ledger line use it, and resolution returns the pin's canonical spelling, shipped in the commit that moved this note (`backend-cluster/backend-v2`).

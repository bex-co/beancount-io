# `renameLedgerFile` refuses `./`-prefixed paths that read/create/update/delete all normalize

**Severity:** minor (honest `BAD_USER_INPUT`, trivial workaround: strip `./`). **Estimate:** 20 minutes. **Owner:** `backend-cluster/backend-v2`, `renameLedgerFile` in `src/features/ai-agent/api/mcp-tools.ts` — apply the existing `normalizeAgentRepoPath` (`src/features/ai-agent/tools/agent-repo-path.ts`) to `oldPath`/`newPath` like the other file tools do. MCP-only: REST/GraphQL stay strict behind the shared validator. **A1:** models spell shell-style paths; one tool refusing what four accept is a papercut in every rename.

## Repro (production, 2026-10-25, API key pinned to `puncsky/mcp-agent-eval`)

With `qa-20261025-px.bean` present (created and deleted after):

| call | result |
| --- | --- |
| `readLedgerFiles {files: [{path: "./main.bean"}]}` | OK, reports canonical `main.bean` |
| `createLedgerFiles {files: [{path: "./qa-dot.bean", …}]}` dry-run | OK |
| `updateLedgerFiles {files: [{path: "./qa-20261025-px.bean", …}]}` dry-run | OK, diff reports `qa-20261025-px.bean` |
| `deleteLedgerFiles {files: [{path: "./qa-20261025-px.bean"}]}` dry-run | OK |
| `renameLedgerFile {oldPath: "./qa-20261025-px.bean", newPath: "qa-20261025-px2.bean"}` | `BAD_USER_INPUT` "Invalid file path" |

`sub/../main.bean`, `/abs.bean` and `../evil.bean` are refused on every tool (verified on read and create) — only the harmless leading `./` differs.

## Cause

`normalizeAgentRepoPath` strips leading `./` (and deliberately nothing else) in `read-ledger-files-tool.ts:82` and `edit-ledger-files-tool.ts:287`, before the strict `assertSafeRepoPath` (`src/features/ledger/utils/safe-repo-path.ts:20-23` rejects every dot segment). The rename tool never calls it, so `./x` reaches the validator raw. Its own docstring says models commonly spell `./main.bean` — rename missed the memo.

## Fix

Apply `normalizeAgentRepoPath` to rename's `oldPath` and `newPath` at the tool layer (not the service — REST/GraphQL strictness is intentional), plus a contract test that `./old` → `new` renames and reports canonical paths, and that `../x` still refuses.

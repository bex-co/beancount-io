## Objective

Walk every MCP tool input schema, collect each string-typed leaf (including nested objects and array items), and generate one NUL case per leaf with a valid baseline request.

## Context

- `MCP_TOOLS` and the zod input schemas live under `backend-cluster/backend-v2/src/features/ai-agent/`.
- The existing guard is `assertNoNul` / `assertNoNulIn` in `src/shared/assert-no-nul.ts`.
- File `content` legitimately holds NUL (w23/220 control); allowlist it with a reason.

## Steps

1. Write a schema walker returning JSON paths of string leaves.
2. Build a valid baseline per tool (reuse parity fixtures).
3. Generate cases and run them through the MCP dispatcher with dependencies that fail the test if reached.

## Files

- `backend-cluster/backend-v2/src/features/ai-agent/api/__tests__/nul-contract.test.ts` (new)

## Acceptance criteria

- [ ] The test enumerates every string leaf and reports the count.
- [ ] Parameters not yet guarded show as failing cases (the input to t002).

## Out of scope

- Fixing failures (t002).

## Resolution

`mcp-nul-contract.test.ts` (backend-v2, `src/server/api/__tests__/`) derives every string leaf of every MCP tool's input schema with `z.toJSONSchema` (199 cases across 44 tools, including nested arrays and record values), places `"a\u0000b"` there and calls the tool through a real in-memory MCP client whose context holds no services, then asserts `BAD_USER_INPUT` naming the NUL. A new parameter is covered without editing the test. Removing the guard fails 197 of the 199 cases (the other two assert the case floor and the exempt set).

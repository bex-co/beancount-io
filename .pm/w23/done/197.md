# 197 — rustledger accepts stock-invalid mid-currency balance tolerance (`49.75 USD ~ 0.05 USD`) as check-clean

**Severity:** moderate (narrow trigger; breaks stock interop silently — a file MCP calls clean fails stock parse).
**Estimate:** upstream grammar fix or local guard. **Owner:**
ledger engine pin / check parity. **A1:** agents hand-writing tolerances; stock-interop readers.

Beancount's tolerance rule is `number ~ number currency` (grammar.y:629:
`number_expr TILDE number_expr currency`) — the currency comes once, at
the end. rustledger also accepts the mid-currency spelling, and the
ledger check shares the engine grammar, so the invalid line commits as
clean and serves values:

- `2026-08-30 balance Assets:Cash 49.75 USD ~ 0.05 USD` via
  `updateLedgerFiles` → `Committed … No new bean-check errors`, and BQL
  `SELECT tolerance FROM balances` serves `0.05` (dtype Decimal).
- Stock `bean-check` on the identical bytes: `syntax error, unexpected
  TILDE, expecting end of file or EOL` (verified on two local fixtures).
- Correct `49.75 ~ 0.05 USD`: stock-clean; stock renders tolerance `0.05`
  (number), matching MCP's Decimal — value parity on the valid spelling.
- Distinct from w23/149 (blocked): 149's writes REPORT the new errors
  post-commit (`1 new bean-check error`); here the check reports NONE —
  a parser differential, not a missing gate. 149's commit-invalid doc
  does not cover "check says clean".
- REST file writes share the ledger check path (149-established), so the
  acceptance is service-wide; GraphQL has no file-write path (149 N/A).
- Root cause: `@rustledger/wasm 0.24.0` grammar superset (upstream);
  local check inherits it.
- Fix: upstream grammar report (reject mid-currency `~`, or document as
  deliberate with a stock-compat warning); locally, refuse-or-warn on
  the spelling until the pin is fixed, and pin a stock-parity check test
  (`USD ~` must error like stock).
- QA ledger untouched net (disposable lines committed, read, full-content
  restored; byte-identical f1a0b83c/size 2817 + `cmp` + stock `bean-check`
  + MCP `checkLedger` clean after).

---

**Resolved 2026-10-28** — the engine's grammar superset stays upstream, but the local guard the note asks for is in: a text-level pass in the ledger snapshot (`balance-tolerance-syntax.ts`) reports a `balance` line written `number CCY ~ tolerance CCY` as an error (code `TOLERANCE`) at its file and line, in the entry point and every included file. Checks, post-write reports, and entry gates now see what stock `bean-check` would; the valid `number ~ tolerance CCY` spelling, comments, strings, and other directives stay clean. Unit tests plus live `verify:rustledger` pins (invalid line reported at line 6; valid spelling clean); shipped in `cc143ad6c` (`backend-cluster/ledger`). Filing the grammar gap upstream remains a w23/022-style external-tracker action.

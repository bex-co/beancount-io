## Objective

Using the existing BQL scanner, decide for a query whether it reads `discrepancy` from `balances` as a plain projection (bare `discrepancy`, or `*`, in the SELECT list of a row-wise query) and where in the engine's result that column sits. Classify the other uses: `discrepancy` in WHERE, ORDER BY, GROUP BY, an aggregate or a function argument, and queries that group, aggregate or de-duplicate, where a row no longer maps to one assertion.

## Context

- `backend-cluster/ledger/src/features/ledger/service/bql-scan.ts`, `ledger-shell-service.ts`, `ledger-shell-mappers.ts` (the dtype half already shipped: `discrepancy` is an Amount column).
- Design from the 2026-10-28 triage: a row maps to a balance directive only through its `date` and `account` (and `amount`); `SELECT account, discrepancy` carries neither the date nor the amount, so the keys must be added, not guessed.

## Acceptance criteria

- [x] Plain projections are recognized, including `*` and aliases; grouped/aggregated/distinct shapes and `discrepancy` outside the SELECT list are classified separately

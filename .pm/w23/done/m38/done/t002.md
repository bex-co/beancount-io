## Result

`canonicalLedgerId` in `src/shared/str.ts` (owner lowercased, name as sent: the rule `ledgerIdMatchesPin` already applies) is applied inside `CACHE_KEYS.ledger.entryWriteRequest`, so every writer gets it and a new per-ledger key cannot skip it. Deviation from the task text: the key folds the owner's case locally instead of resolving the repository ID, because ledger names are lowercase-only and owners are case-insensitive, and a lookup would add a ledger-service call to every write that carries a `requestId`; a retry across a rename within 24 hours is the one case it does not cover. Tests: `entry-write-idempotency.test.ts` (case variants write once; a different ledger, owner or name does not) and `structured-entry-parity.test.ts` ("owner in another case": ten REST, GraphQL and MCP pairs commit once). Reverting the fold fails all of them.

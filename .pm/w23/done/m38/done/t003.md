## Objective

The MCP tools refuse a malformed `ledger` as if none were given. Name the failing rule the way the resource, REST and GraphQL already do.

## Context

- `w1/235`: whitespace, extra or missing slashes and encoded characters all answer "Select a ledger using ledger: owner/name"
- The resource, REST and GraphQL answer "Owner slug must contain only letters…" or the name-slug rule

## Steps

1. Find where the MCP tool input resolves `ledger`
2. Route a malformed value to the same slug validation the other surfaces use, keeping the `listLedgers` hint
3. Test one spelling per rule

## Files

- backend-cluster/backend-v2/src/features/ai-agent/

## Acceptance criteria

- [x] A malformed `ledger` on an MCP tool names the failed slug rule and keeps an actionable hint
- [x] A missing `ledger` still says to select one

## Out of scope

- Adjacent work not named above

## Result

`resolveMcpLedger` no longer gates on a regex before parsing: a ledger that was sent but is malformed is refused through `assertLedgerSpelling` (`mcp-ledger-selection.ts`), which names the slug rule `parseLedgerId` broke, keeps `field: ledger` and a hint naming `owner/name` and `listLedgers`. "Select a ledger using ledger: owner/name" is left for a call that named none. The prompt argument `ledger` uses the same check, and `LEDGER_ID_PATTERN` is gone.

# A posting dated before its account's `open` is reported as "Account … was never opened", which invites a duplicate `open`

**Severity:** minor. **Estimate:** 30–45 minutes. **Owner:** `backend-cluster/ledger`. The message comes from the bundled engine (`@rustledger/wasm` 0.24.0) and reaches every write summary and `checkLedger` on REST, GraphQL and MCP. **A1:** an agent that believes the message adds a second `open`, and that `open` is itself an error ("duplicate open") or moves the account's start date.

## Repro (production, 2026-10-22, disposable `qa-` ledger, since deleted)

```beancount
2020-01-01 open Assets:Live USD
2020-01-01 open Equity:Init USD
```

`appendLedgerText {dry_run: true}` with

```beancount
2019-01-01 * "early"
  Assets:Live 1 USD
  Equity:Init
```

returns "2 new bean-check errors: Account Equity:Init was never opened (main.bean:47)". Both accounts are opened, on 2020-01-01.

Controls: a posting to an account that really is unknown gets the same text, which there is correct. A posting after `close` gets the precise "Posting to inactive account Assets:Old on 2020-04-01 (closed on 2020-03-01)". Python Beancount distinguishes the cases: "Invalid reference to inactive account" vs "unknown account".

## Fix

When the diagnostic names an account that has an `open` directive in the loaded ledger, report "Posting to Assets:Live on 2019-01-01, before it opens on 2020-01-01". Do this either in the ledger service's diagnostic mapping or upstream in the engine, followed by a version bump; check the engine's changelog first. Tests: pre-open posting names the open date; a truly unknown account keeps "never opened"; a post-close posting is unchanged.

---

**Resolved 2026-10-23** — a use dated before its account's `open` now says when the account opens: "Account Equity:Init used on 2019-01-01 but not opened until 2020-01-01".

That is the engine's own wording, which `@rustledger/wasm` 0.24.0 already gives a posting with an amount. Probed live, it said "never opened" or "unknown account" for every other use before the open: an interpolated posting (the repro's `Equity:Init`), a `balance`, a `pad` ("Pad target account … was never opened"), a `note` or `document` ("Invalid reference to unknown account"), and a `close`. `reportPreOpenUses` (`backend-cluster/ledger/src/foundation/rustledger/pre-open-uses.ts`) rewrites each such `E1001` when it sits on a directive dated before the account's earliest `open`. A truly unknown account keeps "never opened", and an error dated on or after the open, or with no location, is unchanged. It runs in `engine.ts` after the close reconcilers, which match the old text, so it reaches every write summary and `checkLedger` on REST, GraphQL and MCP. The engine's `1.0.0-rc` line was not adopted for this: a major engine bump is out of scope for a wording fix.

**Tests:** `pre-open-uses.test.ts` covers the five engine wordings, a truly unknown account, an on/after-open or unlocated error, the earliest of two opens, and a post-close `E1003` (unchanged). `scripts/verify-rustledger.ts` adds a live-engine check: an interpolated posting, a posting with an amount and a balance before the open name the date, and an unknown account keeps "never opened". Removing the engine call fails that check.

**Gates:** ledger typecheck, ESLint, Knip, build, 1898 unit tests, and all 259 live engine checks (`yarn verify:rustledger`). Needs a ledger deploy to reach production.

Shipped in the commit that moved this note (`backend-cluster/ledger`).

## Objective

Feed the journal JSON of a fixture holding every directive type with metadata back through `addLedgerEntries` `dry_run` and assert the parsed result is identical to the source.

## Context

- `w1/233`: 261 entries round-tripped by hand; only 10 commodity and 6 open metadata sets were lost

## Steps

1. Build the fixture with every directive type and metadata
2. Round-trip it through the typed path
3. Fail naming the directive type that changed

## Files

- backend-cluster/backend-v2/src/features/ledger/api/rest/v1/__tests__/

## Acceptance criteria

- [x] The round trip passes and fails when any type's metadata rendering is removed

## Out of scope

- Adjacent work not named above

## Result

`scripts/journal-round-trip.ts`, run by `yarn verify:rustledger` against the live engine: a fixture with every typed directive and awkward string metadata is read through the journal service, each row is mapped onto the typed input, rendered by the real `entryInputToText`, loaded again, and the second journal must equal the first, entry hash included, per directive type. It also fails if the fixture loses a type or a type's metadata. Sabotage: dropping the pad's or the note's metadata mapping fails the check naming that directive type. It runs in CI with the rest of `verify:rustledger`.

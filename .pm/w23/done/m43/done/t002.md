## Objective

Render the new `meta` with the directive-text serializer's token check and escaping, and refuse the parser's reserved keys as `w1/217` does for posting meta.

## Context

- `w1/217` (reserved meta keys) and `w23/done/053` (caller-supplied meta is always quoted)
- The ledger renderer currently receives only transaction and posting meta

## Steps

1. Pass directive meta to the renderer
2. Apply the token check, escaping and reserved-key refusal
3. Test an escaping edge case and a reserved key

## Files

- backend-cluster/backend-v2/src/features/ledger/
- backend-cluster/ledger/src/features/ledger/

## Acceptance criteria

- [x] Metadata on each variant renders valid beancount and survives a parse
- [x] A reserved key is refused with a field-level error

## Out of scope

- Adjacent work not named above

## Result

The ledger renderer maps `meta` for each of the nine types (`metaOf` in `entry-build.ts`) and the token check holds a directive's metadata keys to the same rule as a posting's, so a reserved key (`filename`, `lineno`) or a key with a space is refused naming `meta.<key>` (`entry-tokens.ts`). Values are written quoted as given, so a quote, a backslash, and number- or date-shaped strings survive. Tests: `entry-build.test.ts` renders each type's metadata with escaping edge cases and none when absent (removing the mapping for one type fails its row), and `entry-tokens.test.ts` checks the key rule for each type.

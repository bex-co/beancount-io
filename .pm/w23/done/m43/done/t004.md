## Objective

An `updateEntrySource` with identical text makes no commit and keeps the hash but still says "Updated entry" and lists `wrote`. Report it as unchanged.

## Context

- `w1/233` nit; the three surfaces share the service

## Steps

1. Detect the unchanged text
2. Return a no-op result with no `wrote` on all surfaces
3. Add a parity test

## Files

- backend-cluster/backend-v2/src/features/ledger/

## Acceptance criteria

- [x] A byte-identical update returns a no-op result on REST, GraphQL and MCP

## Out of scope

- Adjacent work not named above

## Result

An `updateEntrySource` whose edit leaves the file as it was reports `unchanged: true` on REST, GraphQL and MCP: the message says `No change` (`Would change nothing` on a preview), `wrote` and `files` are empty, and there is no `commit`. The decision is the ledger service's, from the file's bytes before and after (`AppliedReplace.previous`), so an edit that changes only a comment stored beside the entry is a change even though the entry's served checksum is the same; the IDL and the fava client carry the new field and backend-v2 passes it through (a ledger service that predates it reports a change). Tests: the ledger service's slice tests (identical text, real edit and comment-only edit, dry run and commit), `ledger-journal-service.test.ts` (pass-through, not inferred from the checksum) and `unchanged entry edit via %s` in `source-slice-parity.test.ts`.

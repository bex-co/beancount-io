## Objective

Reproduce the w23/085 corruption with overlapped same-entry updates against a local ledger and pin the exact mechanism: where the loser's commit stops being a fenced conflict and becomes a duplicate (round 1), a deletion (round 2), or an honest failure (round 3).

## Context

- backend-v2 `updateSourceSlice` (`backend-cluster/backend-v2/src/features/ledger/service/ledger-journal-service.ts`) is a thin pass-through; the read-modify-write lives in the ledger package: `backend-cluster/ledger/src/features/ledger/service/ledger-journal-service.ts` (`updateSourceSlice`, `makeReplaceTransform`, `relocateSlice`, `findEntrySliceBySourceSha`) plus the re-read/re-apply retry in `backend-cluster/ledger/src/features/ledger/operations/commit-ledger-files.ts`.
- Puzzle for this task: `relocateSlice` already throws `ConflictError`/`NotFoundError` on sha mismatch, and the commit helper does not retry a throwing transform — so trace how the loser still lands a misapplied write (occurrence-index fallback matching the wrong block? an empty-range replace turning into an insert? a lost CAS?).
- The `FORBIDDEN` body (`Operation 'commit ledger files' not allowed: request failed with status 500`) comes from the ledger's `giteaWriteErrorFromCause("commit ledger files", …)`; trace how it crosses into backend-v2 as `FORBIDDEN` for t003.

## Steps

1. Build a local overlapped-updates harness (two racers, same hash+sha, different content) and reproduce at least the duplicate and the deletion.
2. Trace each outcome to its code path and record the mechanism in the task file.
3. Name the smallest fence point(s) for t002 and the translation point(s) for t003.

## Findings (2026-10-25, worker1)

Three experiments, real code throughout (backend-v2's update is a confirmed thin pass-through; all racing lives in the ledger package).

**Experiment 1 — unit-level race, fake Gitea answering stale blob SHA with an unrecognized 500 (the w23/072 signature):** loser throws `OperationNotAllowedError("commit ledger files", …)` — exactly the production `FORBIDDEN` body — winner `OK`, single entry. Confirms the round-3 code path and the t003 translation bug. (Scratch test, deleted.)

**Experiment 2 — live race: real `LedgerJournalService` + real engine + real Gitea 1.24.7 (prod's version), one unique entry, 6 rounds:** every round ends one `OK` + one honest `ConflictError` ("it has changed since it was loaded"), single entry carrying the winner's content. The CAS + `relocateSlice` + recognized-conflict retry fence HOLDS on current main for unique entries. The production duplicate/deletion does NOT reproduce.

**Experiment 3 — live race, two IDENTICAL entries, 4 rounds:** every round ends `OK` + `OK` with AAA in one block and BBB in the other — the loser silently edits the entry it did not address. CONFIRMED fence hole: `relocateSlice` (`ledger-journal-service.ts:146`) matches by (`sha256sum`, `localOccurrence`) without verifying entry identity, so after the winner rotates one identical block the stale pair addresses the surviving twin. `SliceTarget.base` (the addressed entry's identity) is carried into the transform but used only for error messages, never for matching.

**Why the single-entry 1→2/1→0 counts cannot come from this path on main:** every commit through `makeReplaceTransform` preserves block count — it replaces exactly one slice located by exact-sha match, throws `Conflict`/`NotFound` (never retried, never committed) when the sha matches nothing, and no code path inserts or deletes. A 2-block or 0-block commit has no producer. The production counts therefore implicate older deployed code, a Gitea-layer anomaly, or a probe artifact — settling that needs the production deployed revision plus the Gitea server log for one losing commit (same owner evidence w23/072 already asks for).

**Fix points.** t002: verify entry identity at relocate — the sha-matched block must still be the addressed entry (re-resolve its ID at that span), else `ConflictError`; plus durable race regression tests (unique-entry overlap → 1 `OK` + 1 `Conflict`, single winner-content entry, repeated; identical-entry overlap → never a silent wrong-entry edit). t003: unchanged — unrecognized commit-step 500s (Gitea lock and siblings) must surface `SERVICE_UNAVAILABLE` (retryable), never `FORBIDDEN`, on REST, GraphQL, and MCP.

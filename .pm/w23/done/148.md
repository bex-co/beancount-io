# 148 — `account-directives` counts postings under an open/close description (`entryCount: 9` where 1 open, 0 closes exist)

## Summary
The `account-directives` resource is described as "Each account's open and close directives — which accounts are usable on a given date", but its `entryCount` field counts *postings*, not directives: `Assets:Bank:Checking` reports `entryCount: 9` while the ledger holds exactly 1 open and 0 closes for it (12 opens / 0 closes total). Per-account counts match `postings-per-account` exactly and sum to 34 (total postings), never to 12 (total opens). An agent reading the resource at face value concludes Checking has 9 open/close directives. Same description-precision family as w23/142 (description promises what the shape is not).

## Repro (prod, puncsky/mcp-agent-eval, read-only)
- `read beancount://puncsky/mcp-agent-eval/account-directives` → 12 items; Checking `entryCount: 9`, Cash `5`, Groceries `4`, Visa `4` (sum 34).
- `entries-count` → Open 12, Close 0: no account can have more than 1 open/close directive, yet six accounts report `entryCount ≥ 2`.
- `postings-per-account` (unfiltered) → Checking 9, Cash 5, Groceries 4, … — identical per-account counts, so `entryCount` is the posting count.
- Controls: `openedAt`/`entryHash` are correct — `entryHash 186eed…` resolves via `getEntryContext` to the `Open Equity:Opening-Balances` directive. Only the count's semantics (and the description covering it) mislead.
- REST twin: `GET /api-gateway/v1/ledgers/puncsky/mcp-agent-eval/account-directives` → identical 12 items, sum 34, Checking 9. Shared service, all surfaces agree on values.

## Root cause (main)
`getAccountDirectives` (`backend-cluster/ledger/src/features/ledger/service/ledger-account-service.ts`) sets `entryCount: accountEntryCounts(directives)` — documented in its own comment as "per-account posting counts … exactly as the former fava path did". The value is deliberate fava inheritance; the MCP template description ("open and close directives") and the field name never caught up. Fix is description/field clarity, not a value change.

## Expected
Either describe the resource as open directives *with posting counts* (and document `entryCount` as postings per account), or rename/split the field so directive counts and posting counts cannot be confused. Keep all three surfaces identical. Sub-hour.

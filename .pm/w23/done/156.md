# 156 — Report `conversion` silently ignores unresolvable targets (`BOGUS`, `EUR`-with-no-prices → USD figures, no error)

## Summary
Every `conversion`-taking report (balance-sheet, income-statement, trial-balance, holdings, interval-totals, account-journal) silently returns USD/units figures for any unresolvable `conversion` value — including `BOGUS`, which is not even currency-shaped. `balance-sheet?conversion=BOGUS` → `ok` with `currency: "USD"`, `valuation: "units"`, full figures, no error, no warning. Same for `EUR` (valid currency, no prices) and `usd` (wrong case). The response echoes the *actual* units honestly, but an agent that doesn't re-check the `currency` echo reports USD numbers as EUR. Every neighboring constrained param refuses precisely (`shape` enum, `preset` enum, `operatingCurrency` pattern, subtype enums) — `conversion` is the odd one out.

## Repro (prod, puncsky/mcp-agent-eval, read-only)
- `statements/balance-sheet?conversion=BOGUS` → full USD report, `valuation: "units"`. Identical for `EUR`, `usd`.
- Same silent accept on income-statement, trial-balance, holdings, interval-totals, account-journal (`?conversion=BOGUS` all `ok`).
- REST twin: `GET …/statements/balance-sheet?conversion=BOGUS` → identical USD report, no error.
- Controls: `conversion=units` → same figures with `valuation: "units"` (the fallback target, reached honestly); `shape=bogus` → `-32602 Invalid option: expected one of "summary"|"fava"` (the strictness conversion lacks); BQL `convert(position, 'EUR')` with no prices → unconverted `3000.00 USD` on *both* MCP and stock (engine-level agreement — the report layer is where the silence lives).

## Root cause (main)
Two links: (1) schemas declare `conversion` as a bare `z.string()` (`backend-cluster/backend-v2/src/features/ledger/api/rest/v1/journal-reads.ts:110`, MCP templates likewise) — no enum/pattern; (2) `resolveConversion` (`backend-cluster/ledger/src/foundation/rustledger/cost-valuation.ts:27`) passes any other string through as `target: conversion` (default branch), and the unresolvable target degrades to units figures downstream without surfacing anything.

## Expected
Refuse currency-shaped-but-unresolvable and non-currency `conversion` values (unknown → `BAD_USER_INPUT` naming the accepted modes/currencies; valid-but-unpriced → error or an explicit `missing_prices`-style disclosure like holdings carries), matching the surface's strictness norms. At minimum, validate the shape (known modes + `^[A-Z]{3}$`) so `BOGUS`/`usd` fail fast.

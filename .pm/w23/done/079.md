# A posting with a `price` but no `units` is accepted and written without the price

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** `backend-cluster/backend-v2`, the structured posting schema (`postingSchema` in `src/features/ledger/api/rest/v1/entries-handler.ts`, and the GraphQL input mirroring it) and `LedgerEntryService.addBulkEntries`. Shared by REST, GraphQL and MCP `addLedgerEntries`. **A1:** an agent that sends `{account, price}` meant a conversion; it reads "Added 1 entry" and moves on, while the ledger holds a different transaction than the one described.

## Repro (production, 2026-10-24, account-wide OAuth token, disposable `qa-` ledger, since deleted)

`addLedgerEntries` with one transaction, postings:

```json
[{"account": "Assets:Cash", "price": {"number": "1", "currency": "USD"}},
 {"account": "Equity:Initial", "units": {"number": "-10", "currency": "USD"}}]
```

returns "Added 1 entry to main.bean. No new bean-check errors." The file then holds

```beancount
2021-01-01 * "px"
  Assets:Cash
  Equity:Initial                                        -10 USD
```

and `Assets:Cash` interpolates to 10 USD. The price vanished with no warning. Controls: `{account, units: 10 EUR, price: 1.1 USD}` renders `10 EUR @ 1.1 USD`; a posting with neither units nor price is written elided, which the tool documents ("One posting per transaction may omit its amount and is written elided").

## Fix

A price without units has no meaning, so refuse it with `BAD_USER_INPUT` "postings[0].price needs `units`; a posting without an amount can't carry a price" in the shared schema (`superRefine` on the posting) so all three surfaces refuse alike. Tests: `{account, price}` is refused on REST, GraphQL and MCP; `{account}` (elided) and `{account, units, price}` are unchanged.

## Dedupe

w2/m26 introduced elision; w23/033 validated tag, link, flag, account, currency and meta values but not the price/units pairing. No item covers it.

---

**Resolved 2026-10-25** — `writeBulkEntries` refuses a posting with `price` but no `units` with `BAD_USER_INPUT` naming the entry and posting, next to the elision check so REST, GraphQL and MCP refuse alike; shipped in the commit that moved this note (`backend-cluster/backend-v2`). Deviation from the note: the refusal lives in the service rather than a zod `superRefine`, because GraphQL does not use the zod schema — the service is the established all-surfaces choke point.

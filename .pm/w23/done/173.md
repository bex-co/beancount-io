# MCP-only required-ness lies, bank-id and file-message aliases: schema optional, runtime required

**Severity:** minor (every refusal names the missing arg, so agents recover in one retry; still, 11 tools' schemas lie). **Estimate:** 1–2h (mark required via anyOf-required in 2–3 MCP zod schemas + tests; no REST/GraphQL change — those surfaces are already honest). **Owner:** `backend-cluster/backend-v2`, MCP tool schemas. **A1/A2:** agents build calls from `tools/list` and omit the documented-optional id/message first.

Same pattern as w23/172 (entryHash) and w23/107 (resource params), two more alias families — but MCP-only this time: REST and GraphQL mark every one of these required (or server-defaulted), only the MCP schemas say optional.

## Bank ids (8 tools, `bank-id-alias.ts`)

MCP schemas declare `itemId`/`item_id`, `accountId`/`account_id`, `transactionIds`/`transaction_ids`, `ledgerAccount`/`ledger_account` all `.optional()` (`bank-import-tool.ts:112-145`), and `tools/list` publishes `required: None` (or `['currency']`/`['transactions']` only). Every executor calls `resolveBankIdAlias`, which throws unless one spelling is present (`bank-id-alias.ts:14-19`). Live (prod, QA ledger; all throw before the service call, no mutation):

- `syncBankTransactions {}`, `reconcileBankAccounts {}`, `refreshBankConnection {}`, `unlinkBankConnection {dry_run}` → `BAD_USER_INPUT: itemId is required — item_id works too.`
- `mapBankAccount {}`, `setBankAccountCurrency {currency}` → `BAD_USER_INPUT: accountId is required — account_id works too.`
- `discardStagedBankTransactions {}` → `BAD_USER_INPUT: transactionIds is required — transaction_ids works too.`
- `importStagedBankTransactions {transactions:[{}],dry_run}` → `BAD_USER_INPUT: transactionId is required — transaction_id works too.` (per-item `transactionId`/`targetAccount` optional in `submitInput`, required in `submitTransactions`, `bank-import-tool.ts:381-388`)

REST twins are honest: `itemId` rides in path params (`banks/{itemId}/sync|reconcile`, `banks-handler.ts:196,283`), `transactionIds` is `z.array().min(1)` in the body (:267), submit items require `transactionId` + `targetAccount` (:228-232). GraphQL is honest too: `@Arg("itemId", () => String) itemId: string` (non-nullable, `plaid-resolver.mutation.ts:42,68,141,155,171`), same for `accountId` and `transactionIds`.

## File-tool commit message (3 tools, `commit-message-alias.ts`)

`createLedgerFiles`, `updateLedgerFiles`, `deleteLedgerFiles` publish `description`/`message` optional (`required: ['files']`) but share one executor gate: `resolveCommitMessage(input, { required: true })` (`edit-ledger-files-tool.ts:296`; the requiredness split is even documented in `commit-message-alias.ts:8-10`). Live:

- all three, dry_run, no description/message → `BAD_USER_INPUT: A commit message is required — description or message.`

REST/GraphQL leave the message optional with a server-side per-operation default (`files-handler.ts:212,249`, `rename-handler.ts:58` use `required: false`) — honest. (`renameLedgerFile` on MCP also uses `required: false`, so it is not affected.)

## Fix direction

Either spelling satisfies the runtime, so plain `required` on one name is wrong; publish the disjunction (`anyOf: [{required:[primary]},{required:[legacy]}]`) or a zod `.refine()` that survives JSON-Schema export, plus keep the exact runtime messages. Same fix shape as w23/172 — consider one change for both notes.

Dedupe: pattern-sibling to w23/172 (entry-hash alias, all three surfaces) and w23/107 (resource templates); distinct helpers and tool families, and this one is MCP-only. Searched: "is required —", alias required, bank-id-alias, commit-message-alias; open: 140–172.

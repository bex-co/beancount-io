# CLI OpenAPI pin drifted behind the typed entry fields

Follow-up from `w23/m6/t005` (adoption walk): `cli/openapi/v1.json` is a
pinned copy of `backend-cluster/backend-v2/docs/openapi/v1.json` with a
`make spec-check` drift gate, and it has drifted — the m6 slices (posting
cost, meta/tags/links, booking, tolerance, total price, pad, plus the new
field descriptions) are in the canonical spec but not in the CLI copy, so
`make spec-check` fails on `main` today. (CLI CI is path-filtered to
`cli/**`, which is why nothing went red.)

Fix is the documented two-step in `cli/Makefile`: `make spec-sync &&
make codegen`, then commit the regenerated REST client and cloud command
stubs. Sub-hour if the regen is clean; the risk is generator-version churn
in unrelated models, which should be kept out of the diff. The CLI does
not consume the new entry fields yet, so this is pin hygiene, not a
behavior gap — no CLI command is broken, only the gate.

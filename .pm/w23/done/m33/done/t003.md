## Objective

Mark runnable blocks in "The agent happy path" and "Inspect the protocol with curl" and execute them through an in-process SDK client or route harness on synthetic fixtures.

## Result

`mcp-doc-recipes.test.ts` lifts the requests out of "Inspect the protocol with curl" itself (the `mcp_post '…'` lines and the standalone `resources/read` block) and replays them in the document's order against the real route, with the document's headers and the protocol version negotiated by `initialize`. It asserts what the prose claims: the negotiated version is read from `result.protocolVersion`, an accepted notification is `202` with no body, `tools/list` contains `runBqlQuery`, the BQL call succeeds, `prompts/get` returns text at `.result.messages[0].content.text`, and the resource read returns the named URI. A first guard fails if the recipe loses one of its requests. Misspelling the tool name or the resource URI in the docs turns the test red (proven and reverted). Deviation from the plan: no separate marker convention, because the recipe's own `mcp_post` lines and JSON block are already machine-readable; and "The agent happy path" is prose with placeholder arguments (`{"entries": [...]}`), so it is not executed — the names and parameters it cites are covered by the t002 resolution check and the preview-commit sequence by the write-preview and retry parity suites.

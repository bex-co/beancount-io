## Objective

Check on the hosted endpoint that a burst of `dry_run` previews does not exhaust the write budget, and that previews get the wider bucket from m26.

## Context

- m26 gave previews their own bucket at three times the write budget.
- Probes spend the QA account's budget; run this probe last and keep it bounded.

## Steps

1. Read the documented budgets in `docs/authentication-rate-limits.md`.
2. Send previews up to just above the write budget; confirm a write still succeeds.
3. Stop at the first `RATE_LIMITED` and record `retryAfter`.

## Files

- .agents/skills/qa-shared/scripts/qa-contract-replay.mjs

## Acceptance criteria

- [x] Probe reports preview and write outcomes separately
- [x] Probe is bounded and never loops unbounded

## Out of scope

- Load testing

## Result

Added `--bucket-probe`: 70 previews (above the 60/min write budget, below the 180/min preview bucket), then an unbalanced commit that must answer `UNBALANCED`, not `RATE_LIMITED`. Live run on 2026-11-07: `bucket` ok, so previews stay off the write bucket.

The same live run showed `surrogate`, `string`, `array` and `depth` not yet enforced on production (the schema or downstream layer answers first), while `nul`, `preview` and `commit` matched. m23 was committed about an hour earlier and the deployed revision cannot be read from the endpoint, so this is a suspected deploy lag, unconfirmed. Re-run the replay after the next backend deploy; a mismatch that persists is a regression to file.

# The MCP endpoint's `Allow` header lists methods it refuses: `OPTIONS` and `PUT` advertise `GET, DELETE, HEAD`, while those methods answer `405` with `Allow: POST`

**Severity:** minor. **Estimate:** 20 minutes with a test. **Owner:** `backend-cluster/backend-v2`, `src/features/ai-agent/api/index.ts:28` (`aiRouter.allowedMethods()`) and `mcp-route.ts` (the explicit 405 for non-POST).

## Repro (production, 2026-11-08, `beancount-mcp 1.0.0`, authenticated API key)

| Request to `/api-gateway/mcp` | Status | `Allow` |
| --- | --- | --- |
| `GET` / `DELETE` | 405 | `POST` |
| `HEAD` | 405 | `POST` |
| `OPTIONS` | 200 | `POST, HEAD, GET, DELETE` |
| `PUT` | 405 | `POST, HEAD, GET, DELETE` |

The endpoint is stateless and serves POST only (`docs/mcp.md`, "`405`, `Allow: POST`, on authenticated GET/DELETE"). `mcp-route.ts` answers `GET`, `DELETE` and `HEAD` itself with `Allow: POST`, but `OPTIONS` and unsupported verbs fall through to Koa's `allowedMethods()`, which reports every registered route method. A client that probes `OPTIONS` to learn whether the server offers a standalone `GET` SSE stream is told it does, then gets `405`.

## Fix

Answer `OPTIONS` (and any non-POST verb) from `mcp-route.ts` with `Allow: POST`, so one header value describes the endpoint on every verb. Test: `OPTIONS` and `PUT` return `Allow: POST`.

## Dedupe

Searched `.pm/**` (including `done/`) for `allowedMethods`, `Allow: POST` and `OPTIONS`; nothing covers this route. Not documented in `docs/mcp.md`.

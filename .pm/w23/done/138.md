# 138 — Text renderer truncates column headers to the widest value (it.6111-6114)

## Summary
`runBqlQuery` (and GraphQL `queryShellText` — shared renderer) sizes each text column to the widest *value* and cuts the header to fit, so the header lies about the column name whenever values are narrower than the name. `SELECT payee, number … LIMIT 1` (empty payee) renders the header as `p`; with a 4-char value (`VISA`) it renders `paye`. Only when a value reaches 5+ chars does the real name `payee` appear. An agent reading the text surface sees phantom columns `p`/`paye` that match nothing in the structured result (`types: [{payee, str}, …]`), in `getLedgerContext`, or in stock output.

## Repro (prod, puncsky/mcp-agent-eval)
- `SELECT payee, number FROM postings LIMIT 1;` via `runBqlQuery` → `"p  number \n-  -------\n   3000.00\n"`.
- `… WHERE payee = 'VISA' LIMIT 1;` → `"paye  number \n----  -------\nVISA  -120.40\n"`.
- `… LIMIT 5;` (NETFLIX present) → full `" payee    number …"` header — the name appears only once a value is wide enough.
- GraphQL `queryShellText` renders byte-identical truncated headers — same renderer, both text surfaces.
- Structured (`runBqlQueryStructured`, REST `/query`) always reports the true name `payee`.

## Expected
Size text columns to `max(header width, value widths)` like every table renderer (including stock `bean-query`), so headers are never cut. At minimum, never truncate a header below its full name.

## Status
Open (inbox). Text-renderer side (backend-v2 or ledger service shared text path); structured surfaces already correct.
- Extended it.6115: zero-row results render as the empty string — no headers, no row count, no marker — on both text surfaces (`queryShellText` identical). An agent cannot tell an empty result's columns, or distinguish it from a swallowed error, without calling the structured tool.
- Extended it.6116: a newline inside a column *name* (string-literal target) drops the header's second line — `SELECT 'a<LF>b' …` renders `'a`, ``, `---`, `a`, `b` (the `b'` line vanishes). Newlines inside *values* render fine (aliased control: ` v / --- / a / b`). Same renderer, header-side only.
- Extended it.6326: values are never truncated or wrapped — a 200-char literal renders full 200-wide with no cap — while the header is still cut to the value width (202-char `'AAA…'` header renders 200). The sizing bug is header-side only; value fidelity is complete.

**Stock-parity correction, worker1 it.255 (before deploy):** the note's Expected line claims stock sizes to `max(header, values)` — it does not. Stock beanquery 0.2.0 (beancount 3.2.3, the repo oracle) truncates headers exactly like the pre-fix renderer: `SELECT payee, number FROM postings LIMIT 1;` → `p   number`, `WHERE payee = 'VISA'` → `paye   number`, `LIMIT 5` (NETFLIX) → full `payee` — cell-for-cell the reported MCP behavior modulo trailing-space. So the current renderer is stock-faithful, and this fix DIVERGES from stock (full headers always). The fix is still the right call — phantom `p`/`paye` columns mislead agents, and no gate pins MCP-text-to-stock-text byte parity (the updated goldens are MCP's own) — but its justification is agent-ergonomics, not parity restoration. Do not "fix" full headers back to truncated in the name of stock parity; text header width is intentionally better-than-stock now.

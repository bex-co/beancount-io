# 152 — Same-type composite equality escapes w23/128's guard on bare amount/set columns

## Summary
w23/128's `compositeComparisonError` refuses `=`/`!=` over `tags`, `links`, `position`, `balance`, `meta`, `entry`, `cost(`/`value(` and composite aggregates — but stock has more same-named composite columns the list misses: `weight` and `price` (amount), `amount` (prices/balances tables), `other_accounts` and `accounts` (sets). On MCP, `weight = weight`, `amount = amount`, `other_accounts = other_accounts`, and `accounts = accounts` all read constant-False; stock refuses each (`equal(amount, amount)` / `equal(set, set)` not supported). w23/132's guard catches their *mixed* comparisons (`weight = 'x'` refuses); the *same-type* self-comparisons stay silent-False.

## Repro (live engine + stock beanquery 0.2.0, October 2026 triage)
- `SELECT weight = weight AS e FROM postings LIMIT 1` → MCP `[[false]]`; stock `CompilationError: operator "equal(amount, amount)" not supported`.
- `SELECT amount = amount AS e FROM prices LIMIT 1` → MCP `[[false]]`; stock `CompilationError: operator "equal(amount, amount)" not supported`.
- `SELECT other_accounts = other_accounts AS e FROM postings LIMIT 1` → MCP `[[false]]`; stock `CompilationError: operator "equal(set, set)" not supported`.
- `SELECT accounts = accounts AS e FROM postings LIMIT 1` → MCP `[[false]]`; stock `CompilationError: operator "equal(set[str], set[str])" not supported`.
- Suspect, needs a cost-bearing fixture to confirm: `price = price` reads `[[null]]` on a costless fixture (price is NULL there); with costs it should read constant-False by the same root.
- Excluded: `discrepancy` — stock cannot parse the name at all, so no contract constrains the engine there.

## Expected
Extend 128's composite-column list with the four verified names (plus `price` once confirmed on costs), with unit + live pins mirroring 128's. The `!=` mirrors refuse symmetrically.

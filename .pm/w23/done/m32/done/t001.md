## Result

Reproduced at HEAD with the route test's real socket: `OPTIONS` answered 200 with `Allow: POST, HEAD, GET, DELETE` and `PUT` 405 with the same list. `mcp-route.ts` now registers `OPTIONS`, `PUT` and `PATCH` on the path so the one handler refuses them with 405 and `Allow: POST` (a CORS preflight never reaches it: `@koa/cors` answers first), and `always-public.ts` lists the three new verbs like GET and DELETE. Test `mcp-route-methods.test.ts` covers all three and fails without the route change. Behavior change worth knowing: an unauthenticated non-preflight `OPTIONS` now gets the 401 discovery hint like GET and DELETE do, instead of a 200 from the router. `docs/mcp.md` says "any authenticated non-POST method". w23/229 is closed separately.

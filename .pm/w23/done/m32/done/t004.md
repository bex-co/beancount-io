## Out of scope

## Result

`yarn mcp:conformance` now covers the transport rows: check 3 also refuses `OPTIONS` and `PUT` (each must be 405 with `Allow: POST`; it fails naming the method that advertised more), and new check 18 `browser-discovery` sends an anonymous cross-origin POST from `http://localhost` (trusted by every deployment) and requires `WWW-Authenticate` in `Access-Control-Expose-Headers`; check 18 needs no credential. Unit tests cover both pass paths and a fail path each (a server that lies in `Allow`, a server that sets the header without exposing it).

Hosted run, 2026-11-08, `beancount-mcp 1.0.0`: checks 3, 17 and 18 **fail on production**, each with the exact signature of the gap it guards (`OPTIONS: expected 405, got 200; PUT: 405 without Allow: POST (got POST, HEAD, GET, DELETE)`; the w23/230 schema mismatch; `Access-Control-Expose-Headers is "X-Has-More,X-Total-Count,Link"`). Production predates commits `435cef7cf` and `2028eb90a`; the fixes are on `main`, so this is deploy lag, not a regression. The milestone Closeout reruns the hosted check after the deploy.

# Append refusal hint claims "valid Beancount" when the errors include parse errors

**Severity:** minor (wording only — the message itself names each error correctly). **Estimate:** 30 minutes. **Owner:** `backend-cluster/backend-v2`, directive-append workflow refusal hints. **A1/A2:** agents told the text is valid will look for the breakage in the ledger instead of fixing the text.

## Repro (production, 2026-10-26, API key pinned to `puncsky/mcp-agent-eval`)

`appendLedgerText` with unbalanced-lowercase text (lowercase `usd` postings) → `VALIDATION_FAILED`, message: "appending it would introduce 3 new bean-check errors: interpolation failed …; parse error: unexpected input (main.bean:98); parse error: unexpected input (main.bean:99)". The hint says: "The text is valid Beancount but would break the ledger — the message names each new error. Fix the directives, or pass `allowInvalid: true` to record them anyway."

Two of the three errors are parse errors — the text is not valid Beancount. (Real beancount 3.2.3 agrees: lowercase `usd` is a lexer error.)

## Fix

Choose the hint by error kind: when any new error is a parse error, say the text itself is invalid and point at the lines; keep the "valid but breaks the ledger" wording for the semantic-only case (unbalanced, unopened account, used-before-open).

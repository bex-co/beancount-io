# 207 — A read-only credential gets `NOT_FOUND` / `BAD_USER_INPUT`, not `FORBIDDEN`, from the file-write tools when the file or edit text does not match

**Severity:** minor. Credential-boundary dialect plus an MCP/REST parity gap. No write happens and the caller can already read the files. **Estimate:** 30–45 minutes including tests. **Owner:** `backend-cluster/backend-v2`. **Pillar:** A1.

## Environment

- Production `https://beancount.io`, `serverInfo` `beancount-mcp` 1.0.0, protocol `2025-11-25`, local HEAD `cb1900e0e` (2026-11-01).
- API key with `ledger.read` only, unpinned, on a synthetic ledger (`puncsky/mcp-agent-eval`).

## Repro (`node .agents/skills/qa-shared/scripts/qa-mcp.mjs call <tool> <json>`, read-only key)

1. `deleteLedgerFiles {"ledger":"puncsky/mcp-agent-eval","dry_run":true,"message":"x","files":[{"path":"nope-qa.bean"}]}` → `NOT_FOUND` "preview refused: File with ID 'nope-qa.bean' not found". Without `dry_run`: `NOT_FOUND` "commit failed: …". The same call with `{"path":"main.bean"}` → `FORBIDDEN` requires `ledger.write` (correct).
2. `updateLedgerFiles` with `{"path":"main.bean","old_string":"zzzqa-not-there","new_string":"b"}` → `BAD_USER_INPUT` "old_string does not occur in the file".
3. `updateLedgerFiles` on a missing `path` → `NOT_FOUND`.

## Controls

- REST `DELETE /api-gateway/v1/ledgers/puncsky/mcp-agent-eval/files/nope-qa.bean?dry_run=true&message=qa` with the same key → `403 FORBIDDEN` (`ledger.files.write`, `credential_not_permitted`) for a missing and an existing file.
- MCP `renameLedgerFile`, `updateEntrySource`, `deleteEntrySource`, `appendLedgerText`, `addLedgerEntries`, `createLedgerFiles` and every `ledger.admin` tool answer `FORBIDDEN` for the same key.
- A read/write key gets `NOT_FOUND` for the missing file (correct for it).

## Expected / actual

A credential without `ledger.write` is refused `FORBIDDEN` before any file lookup or edit-text matching, on commit and `dry_run`, as REST does. Actual: the outcome depends on whether the file and text match.

## Root cause

`backend-cluster/backend-v2/src/features/ai-agent/tools/edit-ledger-files-tool.ts`: `prepare()` (≈ line 411) reads the files and folds the operations before any authorization. It throws `NotFoundError("File", path)` (≈ line 237) for a missing file and `BAD_USER_INPUT` for a non-matching `old_string`. The write authorization runs only later, inside `services.ledgerRepo.changeFiles({ dryRun: true })` (≈ lines 427, 452, 478). An existing-file delete passes `prepare()` and so reaches the check.

## Fix

Authorize the write before `prepare()` for `createLedgerFiles`, `updateLedgerFiles` and `deleteLedgerFiles`, using the same check `changeFiles`' dry run performs. Add a test beside `file-write-gate-parity.test.ts`: a read-only identity gets `FORBIDDEN` for a missing-file delete, a missing-file update and a non-matching `old_string` on MCP, and `403` on REST.

## Dedupe and blast radius

- Searched `.pm` for `deleteLedgerFiles`, "preview refused", and read-only `NOT_FOUND`: only unrelated w23/031, 028, 058.
- The three tools share one file; the other write tools were verified correct.

## Unverified

OAuth-token variant of a read-only credential; whether GraphQL exposes a file-write mutation.

**Resolved 2026-11-01** — `createLedgerFiles`/`updateLedgerFiles`/`deleteLedgerFiles` now authorize write access before reading any file or matching edit text, so a read-only credential gets `FORBIDDEN` (REST already answered 403); an authorization-only (empty-operations) dry run returns right after the check without opening a repository client. Shipped in the commit that moves this note (`backend-cluster/backend-v2`: `edit-ledger-files-tool.ts`, `ledger-repo-service.ts`; regression in `file-write-gate-parity.test.ts`, which fails without the fix).

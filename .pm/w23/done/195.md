# 195 — Bare `entry`/`open`/`close` flip object→`str` without values (no object name rule)

## Summary
`entry` (postings, Transaction), `open`/`close` (accounts table, Open/Close structures) are object-typed bare columns: valued samples report dtype `object` (the classifier's fallthrough), but with zero rows or all-NULL cells the name rule has no object family and they fall through to `str`. Same consumer hazard as w23/167 (branch-on-dtype breaks exactly when data is absent), disproving 167's audit premise that "object [has] no bare columns". `meta` (dict) is the same flip but stays owned by w23/170 (serialization + dtype together); `currencies`/`booking` on the stock-less `open` table have no stock BQL oracle and stay engine-side decisions.

## Repro (stock registry + engine probes, byte-identical audit fixture)
- Stock registry (`beanquery/sources/beancount.py`): postings `entry` → `data.Transaction`; accounts `open`/`close` → `Open`/`Close` structures.
- Stock answers `SELECT entry FROM postings LIMIT 1` with a Transaction object; `SELECT open FROM "accounts" LIMIT 1` (quotable-only, like `balances`) with an Open structure.
- Engine serves both (`SELECT entry FROM postings LIMIT 1` → txn object rows).
- Mapper reading (`ledger-shell-mappers.ts`): valued object sample → `"object"` (fallthrough past Inventory/Position/Amount); empty/all-NULL → `dtypeFromColumnName` → `"str"` (no object arm). Flip follows by inspection; live repro is `SELECT entry FROM postings WHERE FALSE` → `str` vs valued `object`.

## Correction it.6376 (open/close are DATE, not object — fix line split)
- `open` valued is `date`, not `object`: `SELECT * FROM accounts LIMIT 1` (quoted and unquoted identical) → `open` dtype `date`, value `2026-01-01`. `close` valued is `date` too: disposable `open`+`close Expenses:QAX` pair → `close` dtype `date`, value `2026-10-28` (restored byte-identical f1a0b83c/2817 + stock-clean after). Both flip date→`str` on empty (`WHERE FALSE` → `str`), NOT object→`str`.
- Only `entry` is object→`str` as filed (valued `object`, `WHERE FALSE` → `str` — confirmed live). The note's `entry` leg and object-rule fix stand for `entry` alone.
- Root of the error: this note engine-probed `entry` only and inferred open/close from the stock registry — but MCP's `accounts` is a different 5-column table (`account/open/close/currencies/booking`) vs stock's 3-column (`account/Open-structure/Close-structure`), so the oracle doesn't transfer.
- Fix correction: `OBJECT_COLUMNS = {"entry"}` (meta still excluded per w23/170); `open`/`close` belong in `DATE_COLUMNS` alongside `date`/`open_date`/`close_date` (`ledger-shell-mappers.ts:159`). Implementing the as-filed `{"entry","open","close"}` object set would MISTYPE date-valued columns as `object` on empty. Keep the bare-keyword-name collision check for all three.

## Root cause (main)
`dtypeFromColumnName` has a rule per value family (date/int/Decimal/set/Inventory/Position/Amount after w23/167) but no object rule, so object-typed bare columns fall through to `str`. One-set fix mirroring w23/167 (`OBJECT_COLUMNS = {"entry", "open", "close"}` + pins) — but `open`/`close` need a collision check (directive keywords as bare names) and `meta` must stay out (w23/170 owns its dialect decision).

## Expected
Bare `entry` reports `object` with zero rows or all-NULL cells, matching its valued dtype (CORRECTED per it.6376 above: `open`/`close` report `date`, not `object`). Keep `meta` untouched for w23/170.

## Objective

Add the registry check that a tool classified as a projection must name its differential case, so a new write tool cannot ship without one.

## Context

- `write-preview-matrix.test.ts` already fails a tool that is not classified

## Steps

1. Require a differential case per projection tool
2. Document the rule in the test header and `docs/api-parity.md`

## Files

- backend-cluster/backend-v2/src/features/ai-agent/api/__tests__/
- backend-cluster/backend-v2/docs/api-parity.md

## Acceptance criteria

- [x] Removing a tool's differential case fails the test run naming the tool

## Out of scope

- Adjacent work not named above

## Result

`write-preview-matrix.test.ts` gives every projection tool a `differential`: a case in `preview-commit-differential.test.ts` (checked by tool name), or a written reason. `createLedgerFiles`, `updateLedgerFiles`, `deleteLedgerFiles` and `renameLedgerFile` have cases; `renameLedgerFile` moves from "summary" to "projection", since it now projects. The entry, append and source-slice tools carry the reason that their preview and commit share one projection call. Removing a case makes the registry test fail naming the tool.

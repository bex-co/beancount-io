## Objective

Trace a tool call from `mcp-tools.ts` through the ledger shell to the ledger service and list every existing timeout, deadline or abort signal.

## Context

- `mcp-route.ts` and `mcp-tools.ts` contain no `AbortSignal` or timeout.
- The deadline must live in the layer shared by REST, GraphQL and MCP (root AGENTS.md parity rule).

## Steps

1. Trace the path.
2. Write the table in the milestone notes.

## Files

- backend-cluster/backend-v2/src/

## Acceptance criteria

- [x] A current-state table exists and states where a deadline belongs

## Out of scope

- Changes

## Result

Current-state table (2026-11-08), traced from the MCP tool to the ledger service:

| Layer | Deadline or cancellation today |
| --- | --- |
| `mcp-route.ts`, `mcp-tools.ts` | none of its own; no `AbortSignal` is passed down |
| `foundation/fava/api-client.ts` (every REST, GraphQL and MCP ledger call goes through it) | `AbortSignal.timeout`: 30 s default, 90 s for authenticated write-capable clients (`FAVA_WRITE_TIMEOUT_MS`, raised so a slow commit is not aborted after it landed, w3/003); expiry throws `FavaApiError("Fava API request timed out", 504)` and is logged; the client accepts a caller signal but no tool path passes one |
| `foundation/fava/error-to-domain.ts` | 503 and 504 become `ServiceUnavailableError("Ledger API")`, so a timeout reaches every surface as `SERVICE_UNAVAILABLE` |
| tests | `api-client.test.ts` pins the 504 and the log line at the client; nothing pins what an agent receives |

Finding: the deadline this milestone set out to add **already exists in the one layer REST, GraphQL and MCP share**, so no new deadline is needed. What is missing is what the agent is told: a timeout reads exactly like a down dependency ("A dependency is down. Retry with backoff"), with no guidance that a write may have committed before the deadline. The milestone is therefore reshaped: t002 characterizes the hung call end to end, t003 gives a timeout its own hint instead of adding a deadline, t004 (cancel on disconnect) is dropped with its reasoning on record, t005 documents it.

# 222 — Does a `dry_run` consume the write rate budget? Measure it, then decide

**Severity:** unknown. **Owner:** `backend-cluster/backend-v2` (`server/api/rate-limit.ts`, `op-class.ts`). **Estimate:** ~30m. **Pillar:** A1.

The standard agent flow is preview, then commit. `rate-limit.ts` and `op-class.ts` show no `dry_run` handling, so a preview probably spends the same write budget as the commit, doubling the cost of the recommended workflow. The w23/219 parity tests hit `RATE_LIMITED` in-process once each case sent two MCP writes, the same effect on a small scale. Not verified against a deployed budget.

## Steps

1. Read how an op is classified and charged (`CLASS_BUDGETS`, `OP_BUDGETS`) and confirm whether the body's `dry_run`/`dryRun` is ever inspected (`setRouteRateLimitPolicy` is the existing per-body hook).
2. Reproduce locally: send N previews and count charged units.
3. If previews are charged as writes, decide with the owner: charge them as reads, or a separate small budget; implement through the route policy hook so REST, GraphQL and MCP agree.
4. Document the budget in `docs/mcp.md` (agent-facing) either way.

---

**Resolved 2026-11-06** — Measured by reading the gate: `gateMcpCall` (`composition-root.ts`) charges the tool's operation by class and never inspects `dry_run`/`dryRun`, and the REST and GraphQL limiters key on the operation alone, so a preview spends the same write budget as its commit (60 per minute per credential and tool; a preview plus its commit is two units, about 30 pairs a minute per tool). Decision: keep it. A preview runs the same authorization and the full bean-check projection, so it is real work, and the ceiling is far above an agent's preview-then-commit flow; the budget exists for load, and discounting previews would be a protection change with no reported harm. The rule is now stated in `docs/mcp.md` next to the budgets, with the advice to batch directives. If production shows agents hitting `RATE_LIMITED` on preview pairs, charge previews through the existing `setRouteRateLimitPolicy` hook (a per-body op) rather than exempting them. Shipped in the commit that moves this note (`backend-cluster/backend-v2`, docs only).

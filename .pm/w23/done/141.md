# 141 — `readLedgerFiles` echoes `startLine`/`endLine` but refuses them as input (output camelCase, input snake_case)

## Summary
Intra-tool paste split: the result echoes camelCase `startLine`/`endLine`/`totalLines`, but the input requires snake_case `start_line`/`end_line` — sending the echoed spelling back fails with `BAD_USER_INPUT: files.0: Unrecognized keys: "startLine", "endLine"`. An agent paging through a file by copying the previous result's range into the next call burns a turn every time. The tool's own description teaches both spellings at once ("startLine/endLine it spans … Use start_line/end_line per file"), so the split is documented instead of fixed. Same defect class as m3's `entry_hash` (list says snake, mutation required camel) — fixed there by aliasing; this is the file-read remainder.

## Repro (prod, puncsky/mcp-agent-eval, read-only)
- `readLedgerFiles {"files":[{"path":"main.bean","start_line":1,"end_line":3}]}` → `ok: true`, result echoes `startLine: 1, endLine: 3, totalLines: 87`.
- `readLedgerFiles {"files":[{"path":"main.bean","startLine":1,"endLine":3}]}` → `isError: true`, `BAD_USER_INPUT: files.0: Unrecognized keys: "startLine", "endLine"`.

## Root cause (main)
`backend-cluster/backend-v2/src/features/ai-agent/tools/read-ledger-files-tool.ts`: input `files[]` items define `start_line`/`end_line`, output defines `startLine`/`endLine`/`totalLines`. w23/057 (done) made the refusal explicit but left the echo casing split in place.

## Expected
Accept `startLine`/`endLine` as input aliases (the m3/m8 pattern), or echo snake_case; one rule per split, documented. REST single-file reads take no line ranges (whole file), so the split is MCP-intra-tool only — no cross-surface divergence to chase.

# 146 — Value-shape dtype sniffing mistypes strings on full input (`'3000.00'`→Decimal, `str(date)`→date)

## Summary
Beyond w23/136's empty-input flips: on full non-empty input, any computed string column whose values all look decimal reports `Decimal`, and all-ISO-date strings report `date` — regardless of expression type. `SELECT '3000.00', 'abc'` → dtypes `Decimal`/`str` for two literals of the same syntactic class; `str(number)` → `Decimal`, `upper(str(number))` → `Decimal`, `str(date)` → `date`. A consumer branching on dtype (136's own case: parse Decimal as a number) mis-handles string codes, reference numbers, and `str()` output that happen to look numeric — with rows present, no empty-input trigger needed. Only six column names (`account`, `currency`, `flag`, `payee`, `narration`, `type`) are allowlisted out of the Decimal sniff; the date sniff has no name guard at all.

## Repro (prod, puncsky/mcp-agent-eval, `runBqlQueryStructured`)
- `SELECT '3000.00', 'abc' LIMIT 2` → types `Decimal`/`str`, rows `[["3000.00","abc"]]` — same literal class, different dtype by value shape.
- `SELECT str(number) LIMIT 2` → dtype `Decimal` (values `"3000.00"`); `SELECT upper(str(number)) LIMIT 2` → dtype `Decimal`; `SELECT str(date) LIMIT 2` → dtype `date`.
- Controls: `upper(narration)` → `str` (non-numeric values); `length(str(number))` → `7, 8` dtype `int` (the value IS a string at eval — only the dtype lies); stock `bean-query` renders the same values (it has no dtype channel to compare).

## Root cause (main)
`classifyColumnDtype` (`backend-cluster/ledger/src/features/ledger/service/ledger-shell-mappers.ts`): "rustledger does not expose cursor schema", so dtypes are sniffed from values — all-decimal strings → `Decimal` unless the name is in `STRING_COLUMNS`, all-ISO-date strings → `date` unconditionally. The sniff is load-bearing (engine decimals arrive as strings and need recovery), so it cannot simply be deleted: a fix needs engine type info or function-aware rules (e.g. `str()`/`upper()` always `str`), plus a name-guard review for the date sniff.

## Expected
Expression-typed dtypes: string functions and string literals report `str` regardless of value shape; engine decimals keep `Decimal`. The mapper is the shared shell behind every surface, so one fix covers MCP/REST/GraphQL/dashboard.

## Status
Open (inbox). Ledger package (shell mappers; possibly rustledger cursor schema). Estimate uncertain: sub-hour for function-aware rules, larger if engine schema exposure is required — triage should size it before promoting.

**Resolved 2026-10-28** — fixed in `backend-cluster/ledger` (`ledger-shell-mappers.ts`). `classifyColumnDtype` now checks expression form before value sniffing on full input: quote-first names (string literals — double quotes proven literals live, quoted aliases are a syntax error) and calls to 18 verified string functions report `str`; an alias over a string call resolves via its map root. The function set comes from stock beanquery 0.2.0's str-typed functions, each verified live against the engine (`repr` excluded — unimplemented). Bare columns and non-string functions (`date()`, `decimal()`, `year()`) keep sniffing, and the date sniff stays unconditional for bare columns (load-bearing like Decimal; the note's `str(date)` case is rescued by the function rule). Pinned by 5 unit tests (break-checked: the 2 function tests fail with the set emptied) and 6 live pins. Full ledger gates green (178 suites / 2527 tests, typecheck, lint, build, live verify). Residual → w23/177: string literals behind aliases (`'3000.00' AS x`) still sniff — the alias map keeps roots only, and a literal's root is empty.

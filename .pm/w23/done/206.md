# 206 — `createLedgerFiles` with `dry_run` refuses batches over 50 files that the real commit accepts, and only after one repository lookup per file (about 100 ms each)

**Severity:** minor (a preview that contradicts the commit, plus a linear-cost refusal; no data change). **Estimate:** 30 minutes with tests. **Owner:** `backend-cluster/backend-v2` — the per-file `assertNoPortableTwin` loop in `src/features/ledger/service/ledger-repo-service.ts` (~L350–371) runs before the preview reaches `MAX_PROJECTED_FILES` (`backend-cluster/ledger/src/features/ledger/service/ledger-data-service.ts` ~L84, ~L556). **A1:** agents preview a large import folder before committing it.

## Repro (production, 2026-10-30, API key pinned to the disposable QA ledger; probe files deleted afterwards)

`createLedgerFiles` with N one-line `qa-20261030-many/fK.bean` files:

| N | `dry_run: true` | time |
| --- | --- | --- |
| 10 | ok | 2.2 s |
| 50 | ok | 5.9 s |
| 51 | `BAD_USER_INPUT` "preview refused: at most 50 files may be projected at once" | 5.4 s |
| 100 | same refusal | 10.3 s |
| 150 | same refusal | 16.2 s |

- The refusal costs about 100 ms per file, so the cap is evidently applied after per-path work. The per-path case-twin lookup in `ledger-repo-service.ts` is the likely cause (cause unverified from here, no logs). A 500-file request did not answer within 30 s, and the 2 MiB request cap is the only bound on N.
- The real call with 60 files commits ("Committed 60 change(s)", 9 s). `docs/mcp.md` promises that a preview runs "the same checks the commit runs" and publishes no 50-file cap for these tools, so a caller who is told to preview first is refused for a batch the commit accepts.

## Fix

1. Check the count before any repository lookup (cheap, immediate refusal) — or drop the cap for previews of plain creates, which parse nothing heavy.
2. Decide the contract: either the commit enforces the same bound (and `docs/mcp.md` and the tool descriptors state it), or the preview chunks its projection so the two agree.
3. If the per-path twin lookup is the cost, list each distinct folder once per batch instead of once per file.

Tests: 51 files refused in under a second; 60 files previewed and committed with the same outcome; one folder holding 100 files lists the folder once.

## Dedupe

Searched `.pm/**` for "projected at once", MAX_PROJECTED_FILES and preview-versus-commit file counts: only w23/103 mentions the cap for another tool. Related to, but not the same as, w23/205 (batched reads capped at 30) and w23/204 (preview approves path conflicts).

---

**Resolved 2026-10-30** — the ledger service no longer caps a projected preview at 50 files (the commit accepts any count; the 5 MB byte cap still bounds the parse), and `assertNewPathsPortable` lists each folder once per batch instead of once per new file. Tests: `check-projected-errors.test.ts` (`backend-cluster/ledger`), `ledger-repo-service.test.ts` (`backend-v2`).

**Verified in production 2026-10-31 (MCP QA loop, after the redeploy carrying `4e31782a4`).** `createLedgerFiles` with `dry_run` previews 51, 100, 150 and 300 files in 0.8–1.8 s (was 5–16 s and refused over 50), 1000 files in 3.1 s and 3000 files in 11.6 s (about 4 ms per file, linear and bounded by the 2 MiB request cap). Real commits of 60 and 45 files succeed, so preview and commit now agree.

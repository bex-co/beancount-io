# 185 — Text renders net-zero sums as `0.00 USD` while structured says `{}` and stock blank

## Summary
`SELECT sum(position)` over balanced postings nets to zero. The text channel prints `0.00 USD` — inventing a zero amount in a currency the empty result does not hold — while the structured channel reports `{}` (dtype Inventory, via the fava zero-drop in `unitsToCurrencyMap`) and stock prints a blank cell. So the two MCP channels disagree with each other on the same cell, and text disagrees with stock. Same shape for `sum(value(position))`; nonzero sums agree everywhere (`17251.76 USD`). Which currency a multi-currency net-zero would print is unverified from here (QA ledger is USD-only).

## Repro
- `call runBqlQuery {"ledger":"puncsky/mcp-agent-eval","query":"SELECT sum(position) LIMIT 1;"}` → text `0.00 USD`.
- `call runBqlQueryStructured` same query → rows `[[{}]]`; GraphQL `queryShell` twin: `[[{}]]` (structured-consistent, all surfaces).
- Stock control: `bean-query … "SELECT sum(position) LIMIT 1;"` → blank cell.
- Root cause on `main`: the engine hands back a zero amount/position rather than an empty inventory; `toShellCell` drops the zero net (`{}`) but `formatTextCell`→`formatCellValue` prints it (`0.00 USD`) — `backend-cluster/ledger/src/features/ledger/service/ledger-shell-mappers.ts` vs `backend-cluster/ledger/src/foundation/rustledger/mappers.ts`.

## Expected
Render net-zero sums the same in both channels and like stock: blank/empty. Either the engine returns an empty inventory, or the text cell path applies the same zero-net drop the structured path does. Owner decides engine-vs-mapper, mirroring the fava convention already in `unitsToCurrencyMap`.

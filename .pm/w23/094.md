# Typed entry insert has `price` but no `cost`: agents cannot record lot costs except as raw text

**Severity:** minor (workaround exists — `appendLedgerText` with `{100 USD}` lots validates fine — but the safe typed path cannot express investments). **Estimate:** 2–4 hours incl. rendering + parity. **Owner:** `backend-cluster/backend-v2`, entry schema + directive text renderer. **A1/A2:** agents booking investments through the typed API hit `Unrecognized key: "cost"` and must drop to raw text, losing the typed path's field-level validation.

## Repro (production, 2026-10-26, API key pinned to `puncsky/mcp-agent-eval`)

`addLedgerEntries` with a posting carrying `cost: {number: "1.00", currency: "USD"}` → `BAD_USER_INPUT: entries.0.entry.postings.0: Unrecognized key: "cost"`. The tool schema's posting shape is `account/units/price/flag` only. `price` (`@`, per-unit price annotation) is not a substitute: beancount cost (`{…}`, lot basis) drives bookings and capital gains, and the raw-text path accepts it (`appendLedgerText` dry with `10 VHT {100.00 USD}` → ok).

The gap is shared, not MCP-specific: `backend-cluster/backend-v2/src/features/ledger/api/rest/v1/entries-handler.ts` (`postingSchema`) mirrors the GraphQL input union field for field and both feed `LedgerEntryService.addBulkEntries` — no surface takes `cost`.

## Fix (keep REST/GraphQL/MCP in parity)

Add an optional `cost` (and, for completeness, posting-level `tags`/`links`/`meta`, which the transaction level already has) to the shared posting schema, render it through the directive-text serializer with the project's string escaping, and document the cost-vs-price distinction next to the tool. Refuse cost on postings where beancount forbids it with the usual field-level error.

**Severity:** minor (same wrong-pointer class as w23/147, one surface left). **Owner:** backend-v2 fava error mapping. **A1:** REST agents retrying file writes.

## Gap

w23/147 tailored the MCP stale-`sha` hint at the tool's version check. REST file writes (`PUT` with `sha` → `ledgerRepo.changeFiles`) enforce the `sha` in Fava, and a stale one returns a generic 409 that `notFoundFromUpstream`'s sibling 409 mapping (`error-to-domain.ts`) converts to a hintless `ConflictError("Ledger resource", …)` — so REST falls back to the CONFLICT category's entry-`sha256sum` hint, which cannot satisfy a file check.

That 409 path is shared with entry-slice conflicts (where the current hint is correct), and Fava's stale-`sha` message text is unknown (not in the IDL, no test pins it), so the file leg cannot be scoped by message match yet.

## Fix shape

Capture Fava's actual stale-`sha` 409 text (live probe with a stale `sha` against a scratch ledger), then scope the 409 mapping like w23/047's `Entry` hint: file-shaped messages get the file re-read hint, everything else keeps the fallback.

# `account-journal` takes `filter_account`/`with_children` where every other resource param is camelCase

**Severity:** minor (strict param validation; agents guessing the documented camel convention get a refusal). **Estimate:** 1 hour incl. parity. **Owner:** `backend-cluster/backend-v2`, resource URI parsing + REST/GraphQL counterparts. **A1/A2:** agents filter journals by counterparty account; the two snake params are the only ones in 60 resource templates that break the camel convention.

## Repro (production, 2026-10-26, API key pinned to `puncsky/mcp-agent-eval`)

Full audit of all 60 resource templates (`resources/templates/list`): 16 camelCase params (`accountId`, `accountName`, `branchName`, `prNumber`, `userId`, `objectKey`, `directiveTypes`, …) and exactly 2 snake_case params — `filter_account` and `with_children`, both on `beancount://{owner}/{name}/account-journal`. Resource params are strict:

- `account-journal?account=Expenses:Food:Groceries&filter_account=Assets:Cash&limit=2` → `ok`, filtered items.
- `account-journal?account=Expenses:Food:Groceries&filterAccount=Assets:Cash&limit=2` → `Unknown or repeated resource parameter: filterAccount`.

No alias either way (same strictness as the tool-arg splits in w23/096 and w23/097).

## Fix (keep REST/GraphQL/MCP in parity)

Accept `filterAccount`/`withChildren` as aliases (or rename with alias for backwards compat) on every surface, following the w23/m3 (done) alias pattern. Document the canonical spelling in `docs/mcp.md`.

**Cross-surface scoping 2026-10-26** (it.753): REST matches MCP exactly (`filter_account` + `with_children`, both snake). GraphQL's `AccountJournalQueryInput` is already mixed: `filterAccount` (camel!) beside `with_children` (snake). So the `filterAccount` alias on MCP/REST aligns them with GraphQL's existing spelling — clearly correct — while `with_children` is snake on all three surfaces (consistent everywhere, if unidiomatic on GraphQL). Prioritize the `filterAccount` alias; `withChildren` is lower value but completes the camel convention.

Same naming family as w23/m3 (done, entry tools), w23/096 (bank tool args), w23/097 (universal flags) — distinct params, filed separately so each can close independently. Searched: filter_account, with_children, resource param naming; open: m4, 092–097.

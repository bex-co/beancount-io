## Objective

Add meaningful tests for the gate itself: assert real behavior and failure modes, not trivial or snapshot-everything checks.

## Context

- The gate's value is that it fails when it should; the tests must prove that.
- The package's jest suite cannot load `@rustledger/wasm`, so tests cover the pure parts (diffing, normalization, allowlist and hash checks) with synthetic inputs.

## Steps

1. Unit-test the comparison: a differing cell, a differing dtype, a missing column, and an error-vs-rows mismatch each produce the expected diff text.
2. Unit-test the allowlist: an entry without a reference is refused, and an entry matches only its exact query and difference class.
3. Unit-test the staleness hash: changing a query changes the hash and yields the regeneration message.
4. Run the manual sabotage check once: reintroduce the w23/212 wrap in `bql-from-fold.ts`, confirm `yarn verify:rustledger` fails naming the affected queries, then revert.

## Files

- `backend-cluster/ledger/scripts/bql-oracle/` tests, or `backend-cluster/ledger/src/**/__tests__/` for the pure helpers

## Acceptance criteria

- [ ] Each tested failure mode fails before the behavior exists and passes after.
- [ ] The sabotage check was run and the result is recorded in the closeout.

## Out of scope

- Testing beanquery itself.

## Result

Done 2026-11-05.

- **Tests.** 47 jest tests in `backend-cluster/ledger/scripts/bql-oracle/__tests__/` (`bql-oracle-compare.test.ts`, `bql-oracle-source-hash.test.ts`). `jest.config.js` `roots` now include `scripts/` so they are collected. One test pins that the Node hash equals the `sourceHash` the Python generator recorded for the real corpus, so the two implementations cannot drift apart unnoticed.
- **Mutation check.** Eleven deliberate breaks of the compare, allowlist and hash logic each made at least one test fail by assertion (each run executed all 47 tests): two refusals versus one answer, a dtype difference, a row-count difference, a cell difference, an Amount pair versus map, an allowlist reference that does not resolve, an allowlist entry that excuses every kind, stale entries not flagged, fixture sub-directories skipped, fixture names left out of the hash, and a stale oracle accepted. A first pass counted three mutants as killed because the suite failed to compile; those were redone in a compiling form.
- **Sabotage check.** Reverse-applying the w23/212 fix (`dbdc195d1`) to `backend-cluster/ledger/src/features/ledger/service/bql-from-fold.ts` made `yarn verify:rustledger` exit 1 with 6 unexpected differences: `from-account-regex`, `from-date-gt`, `from-month-eq`, `from-year-and-month`, `from-year-eq` and `from-year-gt`. Each showed the original refusal, `syntax error at position 325` (327 for the `~` query). `from-year-gt` also left one stale allowlist entry, because its documented row-count difference turned into a refusal. Restoring the file made it exit 0 with 67 queries matched and 35 documented deviations.
- **Suites.** Full `yarn test`: 210 suites, 3206 tests green. `yarn typecheck` and `yarn lint:deadcode` clean.

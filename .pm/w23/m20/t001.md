## Objective

Add a generator that runs stock beanquery 0.2.0 over checked-in fixture ledgers and writes `bql-oracle.json`: for each query its result rows, column names, dtypes, and error category. The format must be stable and diffable so the replayer (t003) and reviewers can read it.

## Context

- Model on `backend-cluster/ledger/scripts/rustledger-shadow/generate-python-oracle.py` and its `python-oracle.json`.
- Stock beanquery reads a local ledger loaded by `beancount.loader`; it has no data source of its own and makes no network requests.
- The generator is run by hand and its output is checked in; CI does not run Python for this gate.

## Steps

1. Choose the directory next to the shadow corpus (for example `backend-cluster/ledger/scripts/bql-oracle/`) and record the pinned beanquery and beancount versions in the output header.
2. Define the entry shape: query text, ledger fixture name, columns with dtype names, rows as strings or typed values, and `error` category when stock refuses the query.
3. Normalize values that differ only in representation (decimal formatting, set ordering) in one documented place, so the allowlist (t004) stays short.
4. Make the generator deterministic: stable ordering, no timestamps, no absolute paths in the output.

## Files

- `backend-cluster/ledger/scripts/bql-oracle/generate-bql-oracle.py` (new)
- `backend-cluster/ledger/scripts/bql-oracle/bql-oracle.json` (generated)

## Acceptance criteria

- [ ] Running the generator twice produces byte-identical output.
- [ ] The output records the beanquery and beancount versions and contains no absolute paths or timestamps.
- [ ] A query that stock refuses is recorded with an error category, not omitted.

## Out of scope

- Choosing the queries and fixtures (t002).
- Comparing against the engine (t003).

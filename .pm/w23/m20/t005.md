## Objective

Make sure the replay runs in `CI (ledger)` through `yarn verify:rustledger`, and that an out-of-date oracle (a changed query list or fixture without a regenerated `bql-oracle.json`) fails with a message that names the regeneration command.

## Context

- `.github/workflows/ci-ledger.yml` already runs `yarn verify:rustledger` for `backend-cluster/ledger/**`; check whether the new directory is covered by that path filter.
- CI does not run Python for this gate, so staleness is detected by comparing a hash of the query list and fixtures stored in the oracle header.

## Steps

1. Store a content hash of `queries.json` and the fixtures in the `bql-oracle.json` header.
2. In the replayer, recompute the hash and fail with a message naming the regeneration command when it differs.
3. Confirm the workflow already triggers on the new paths; adjust only if it does not.

## Files

- `backend-cluster/ledger/scripts/bql-oracle/` (hash check)
- `.github/workflows/ci-ledger.yml` (only if the path filter misses the new directory)

## Acceptance criteria

- [ ] Editing a query without regenerating fails `yarn verify:rustledger` with a message that names the generator command.
- [ ] A pull request touching only the new directory triggers `CI (ledger)`.

## Out of scope

- Running the Python generator in CI.

# `meta` dict cells render as blank `str` on every surface (stock returns the dict)

**Severity:** minor (silent data loss on one column family: `SELECT meta` reads empty though every row carries `{filename, lineno, …}`). **Estimate:** 1–2h (render dict cells like `entry` objects instead of blanking + dtype). **Owner:** ledger shell cell mapper (same area as w23/m14's `toShellCell`). **A1/A2:** agents reading provenance (`filename`/`lineno` per row) get empty strings.

## Repro (production 2026-10-27, API key pinned to `puncsky/mcp-agent-eval`)

| surface | `SELECT meta FROM postings LIMIT 1;` | stock beanquery 0.2.0 |
| --- | --- | --- |
| MCP structured | `[['']]` dtype `str` | `{'filename': <path>, 'lineno': 22}` (dict) |
| MCP text (`runBqlQuery`, 2 rows) | `m\n-\n \n \n` (blank cells) | (same dicts) |
| REST `/query` | `{"types":[{"name":"meta","dtype":"str"}],"rows":[[""]]}` | — |

All three surfaces agree on the blank, so the bug sits below them in the shared cell-rendering path.

## Controls

- `SELECT entry FROM postings LIMIT 1;` renders FINE on MCP structured: dtype `object`, value `'flag=*, tags=, links=, meta=, narration=Opening balances, date=2026-01-01'`. So the mapper handles `entry` objects but blanks `meta` dicts — the defect is dict-specific, not object-general.
- `SELECT filename, lineno FROM postings LIMIT 1;` returns real values on MCP (the underlying data exists; only the packed-dict projection blanks).
- Adjacent but distinct from w23/m14 (NULL→`""`) and w23/119 (set join style): this is dict→blank with a wrong `str` dtype. A dict cell should render like `entry` (structured object + `object` dtype, or a stable string form), never `""`.

## Probes (it.3322)

- Structured/text/REST parity triple; `entry` control (renders, dtype `object`); stock dict ground truth (keys `filename`/`lineno`, first row lineno 22).

# 163 — Typed balance pre-check ignores `cost` and `totalPrice`, refuses stock-valid transactions

## Summary
`addLedgerEntries` refuses transactions whose postings carry a cost spec (`{}`) or total price (`@@`) with `UNBALANCED`, even when stock beancount accepts them. The pre-check sums raw units and only cost-converts per-unit `price` (`@`) — the `@` leg was fixed for w21/647 while `{}`/`@@` were left out, so the three price spellings behave inconsistently: `@` passes the balancer, `{}`/`@@` never can unless raw units already net to zero. The schema advertises `cost`/`totalPrice`, the renderer prints them correctly (`10 HOOL {100 USD}`), and the backend bean-check itself passes the entry — only the pre-check is wrong. Workaround is `allowInvalid: true` (ironic: the entry is valid) or raw file writes.

## Repro (prod, puncsky/mcp-agent-eval; `dry_run` unless noted)
- Cost: postings `Expenses:Food:Groceries 10 USD {2 USD}` + `Assets:Cash -20 USD`, `dry_run` → `UNBALANCED: entry 0: Transaction does not balance: residual -10 USD` (raw 10 + -20 summed; `{2 USD}` ⇒ 20 USD ignored).
- Total price: `10 USD @@ 20 USD` + `-20 USD` → same `UNBALANCED`, residual `-10 USD`.
- Per-unit price control: `10 HOOL @ 100 USD` + `-1000 USD` → passes the balancer; fails only on the account currency constraint (`Invalid currency HOOL not allowed`), the same rule stock enforces.
- Stock control (`bean-check` on the fixture + each txn): cost variant exit 0, `@@` variant exit 0. Multi-currency cost variant (`10 HOOL {100 USD}` vs `-1000 USD`, relaxed open) also exit 0.
- Same cost entry + `allowInvalid: true`, `dry_run` → `ok: true`, preview renders `10 HOOL {100 USD}` exactly, backend validation reports no new errors — proving the entry was valid all along and only the pre-check objected.

## Root cause (main)
The ledger service casts postings to `BalancePosting`, which carries only `units` + `price` (`backend-cluster/ledger/src/features/ledger/utils/transaction-balance.ts:22-27`); `checkTransactionBalance` weighs `price` (`units × price`, :168-174) and `entries.ts:284-287` passes the cast array straight in, so `cost`/`totalPrice` are silently dropped before the math. Shared ledger-service path — every surface (MCP/REST/GraphQL) inherits the refusal.

## Expected
Weigh cost specs as `units × cost` in the cost currency and total prices at face value in their currency, exactly as stock interpolation does and as `@` already is — or drop `cost`/`totalPrice` from the schema if the typed path will not support them. No new refusal text needed: correct weights make these entries pass.

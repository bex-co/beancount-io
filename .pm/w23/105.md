# Typed entry path has no `custom`, `query`, `option`, or `plugin` directive

**Severity:** minor (coverage gap; the four directives are addable only as raw text via file writes/append). **Estimate:** 1–3h per directive incl. parity, or 30m to document as deliberately excluded. **Owner:** `backend-cluster/ledger` (renderer) + `backend-cluster/backend-v2` (contracts). **A1/A2:** agents building ledgers programmatically hit a discriminator wall on directives stock beancount supports.

## Repro (production, 2026-10-26, API key pinned to `puncsky/mcp-agent-eval`)

`addLedgerEntries {entries: [{type: "custom", entry: {}}]}` (and `query`, `option`, `plugin`) → `BAD_USER_INPUT: entries.0.type: Invalid discriminator value. Expected 'transaction' | 'open' | 'close' | 'balance' | 'price' | 'commodity' | 'note' | 'budget' | 'document' | 'event'`.

Same refusal on REST (`POST /v1/ledgers/{owner}/{name}/entries` → `VALIDATION_FAILED`, shared zod schema, verified live) and the same 10-variant shape on GraphQL (`AddEntryInput`: `type` + `transaction/commodity/price/note/balance/open/close/budget/document/event`, verified via introspection). Parity holds — all three surfaces refuse identically — so this is pure coverage, not skew.

## Fix

Either add the missing directive types to the typed path on all three surfaces (m6 owns `pad` in t010; these four are outside its goal), or document per type that it is deliberately excluded and why (`option`/`plugin` are arguably file-level config, not entries; `custom`/`query` are real entry directives with no typed form). If excluded, the discriminator error should say so instead of just listing the accepted set.

No `.pm` item covers these four types (searched: discriminator, custom directive, typed entry; w23/m6 owns cost/tags/links/booking/tolerance/total-price/pad only). Open: m6, 095–104.

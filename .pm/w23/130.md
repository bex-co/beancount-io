# 130 — Inner bare-`FROM <table>` (no clause before `)`) resolves column-first: real tables error, `accounts` folds (it.4203–4207)

## Summary
MCP resolves a subquery's clauseless `FROM <name>` (terminated by `)`, not `;`) column-first: unquoted real tables (`postings`, `entries`, `prices`) fail with `column '<table>' not found`, while `accounts` silently folds to the 34-row postings scope. Stock beanquery 0.2.0 tables the real names and folds `accounts` (w23/124). Adding any inner clause (`LIMIT`, `WHERE`, `GROUP BY`) or quoting the table name rescues MCP, so the broken path is specifically inner bare-`FROM <unquoted-table>`. Looks like w23/116's normalize-pipeline fix handles `;`-terminated bare FROM but not `)`-terminated inner bare FROM.

## Repro (prod, puncsky/mcp-agent-eval; stock = beanquery 0.2.0 on the byte-identical fixture)

| query | MCP | stock |
| `SELECT count(*) FROM (SELECT * FROM postings);` | `column 'postings' not found` | `34` |
| `SELECT count(*) FROM (SELECT * FROM entries);` | `column 'entries' not found` | `29` |
| `SELECT count(*) FROM (SELECT * FROM prices);` | `column 'prices' not found` | no rows (empty-set quirk, covered) |
| `SELECT sum(1) FROM (SELECT * FROM postings);` | `column 'postings' not found` | `34` |
| `SELECT * FROM (SELECT * FROM postings) WHERE date > 2020-01-01 LIMIT 1;` | `column 'postings' not found` | 1 postings row |
| `SELECT count(*) FROM (SELECT * FROM postings LIMIT 5);` | `5` | `5` (agree — inner clause rescues) |
| `SELECT count(*) FROM (SELECT * FROM "postings");` | `34` | `34` (agree — quoted rescues) |
| `SELECT * FROM (SELECT * FROM postings LIMIT 1);` | 31-col row | same (agree) |
| `SELECT count(*) FROM (SELECT * FROM accounts);` | `34` (fold) | `34` (fold, w23/124 — agree in value) |
| `SELECT count(account) FROM (SELECT * FROM postings);` | `column 'postings' not found` | `column "account" not found in table ""` (both refuse, different cause) |

## Expected
Inner bare-`FROM <table>` resolves exactly like top-level bare-`FROM <table>` (post-116: real tables table, true columns fold, `accounts` per whatever w23/124 decides). At minimum the `column '<table>' not found` misdiagnosis should name the real problem.

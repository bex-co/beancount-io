# Journal `filter` fields `tag:`/`link:` never match and `account:` misses transaction postings

**Severity:** minor (silent empty results; an agent concludes "no tagged entries" or "no activity" wrongly — the top-level `account` param is the workaround for postings, but nothing covers tags/links). **Estimate:** 2–3 hours (match txn postings/tags/links in the filter evaluator + tests + document the mini-language). **Owner:** `backend-cluster/backend-v2` journal filter evaluator (shared by `listLedgerEntries` and the `journal` resource). **A1:** agents filtering journals by tag, link, or account silently get wrong-empty answers.

## Repro (production, 2026-10-25, API key pinned to `puncsky/mcp-agent-eval`)

With probe transactions present carrying tag `#qafilt`, link `^qal1nk`, and postings to `Assets:Bank:Checking` (all deleted after; fixture byte-identical):

| filter | expected | actual |
| --- | --- | --- |
| `payee:qa` | 2 probe txns | 2 ✓ (control: field queries work) |
| `narration:Groceries` | 3 | 3 ✓ |
| `account:Checking` | 11+ (top-level `account` param finds 11 incl. txns) | **1** — only the `Open` directive; no transaction postings scanned |
| `account:Assets:Bank:Checking` | same | `BAD_USER_INPUT` "Trailing tokens" — a full path is unexpressible (colons are lexer operators) |
| `tag:qafilt` | 1 (txn carries `#qafilt`) | **0** |
| `tag:#qafilt` | 1 or a syntax hint | `BAD_USER_INPUT` "Expected STRING, got TAG" |
| `link:qal1nk` | 1 (txn carries `^qal1nk`) | **0** |

The `journal` resource (`?filter=tag:qafilt`) returns total 0 too — the evaluator is shared backend-wide, not MCP-specific. The tool description never documents the mini-language (the `filter` property says only "Filter expression: payee, narration, tag, or link" — no `field:value` syntax, no `account:` at all), so agents can neither discover nor work around the dead fields.

## Fix

1. Match `account:` against transaction postings (substring, like the top-level `account` param) as well as directive-level accounts.
2. Match `tag:`/`link:` against transaction (and posting) tags/links, or refuse them as unsupported rather than answering empty.
3. Accept quoted/escaped values so full `a:b:c` account paths are expressible.
4. Document the `field:value` syntax, the field list, and the escaping rules on the `filter` property and in `docs/mcp.md`; keep REST/GraphQL/MCP in parity.

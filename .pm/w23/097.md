# The two universal write flags disagree: `dry_run` vs `allowInvalid`

**Severity:** minor (strict schemas; agents must remember which convention each flag uses — and one tool takes both). **Estimate:** 1–2 hours incl. parity. **Owner:** `backend-cluster/backend-v2`, tool schemas + REST/GraphQL counterparts. **A1/A2:** every write path takes one or both flags; the spelling split is load-bearing on every mutation call.

## Repro (production, 2026-10-26, API key pinned to `puncsky/mcp-agent-eval`)

Schemas via `tools/list` (no alias spellings exist — every tool below rejects the other convention with `BAD_USER_INPUT: Unrecognized key`, verified live for `dry_run` on entry tools under w23/095):

| flag | spelling | tools |
| --- | --- | --- |
| preview | `dry_run` (snake) | `appendLedgerText`, `create/update/deleteLedgerFiles`, `syncBankTransactions`, `import/discardStagedBankTransactions`, `reconcileBankAccounts`, `unlinkBankConnection` (9 tools) |
| commit-despite-errors | `allowInvalid` (camel) | `addLedgerEntries`, `appendLedgerText`, `updateEntrySource`, `deleteEntrySource(s)` (5 tools) |

`appendLedgerText` takes **both** — `dry_run` and `allowInvalid` side by side in one schema — so no single convention can be inferred. Found by a systematic audit: it is the only tool whose own arguments mix conventions (all other tools are internally consistent).

## Fix (keep REST/GraphQL/MCP in parity)

Alias one spelling to the other on every surface (e.g. accept `allow_invalid` wherever `allowInvalid` is accepted, or vice versa), following the alias pattern w23/m3 (done) established — do not break existing callers by renaming without an alias. Document the canonical spelling in `docs/mcp.md`.

# w23/120 — lifecycle mutations take no `dry_run` while every content mutation previews (m7 follow-up)

Status: inbox
Opened: 2026-10-26 (loop it.2983)
Surface: MCP (lifecycle tools)
Severity: minor for `updateLedger`, major-adjacent for `deleteLedger` (irreversible, unpreviewable)

## Summary

w23/m7 ("Preview every mutation with dry_run") is closed, and every CONTENT
mutation on production honors it — `addLedgerEntries`, `appendLedgerText`,
`create/update/deleteLedgerFiles`, `renameLedgerFile`, `updateEntrySource`,
`deleteEntrySource(s)` all take `dry_run`/`dryRun` (verified live it.2955–2981,
including conflict-vs-agreeing twin behavior and "preview refused" guards).

The LIFECYCLE mutations do not:

| tool | preview on prod |
|---|---|
| `createLedger` | no `dry_run`, but HAS a separate `previewLedgerSetup` tool (alternative preview path — covered) |
| `updateLedger` (`name`/`description`/`private`) | NO `dry_run`, NO preview tool — a rename/re-privacy commits blind |
| `deleteLedger` (just `ledger`) | NO `dry_run`, NO preview tool — destroys the ledger blind |
| `setLedgerCollaborator` / `removeLedgerCollaborator` / `leaveLedger` / `setLedgerStar` | no `dry_run` either (smaller blast radius; collaborator changes still access-affecting) |

Nothing in `.pm/w23/done/m7/` (README + t001–t009) mentions lifecycle, so the
exclusion — if deliberate — is undocumented. HEAD source confirms the gap is not
prod lag: `mcp-lifecycle.ts` builds each lifecycle tool from "exactly REST's
input for that operation plus the ledger target", and REST's lifecycle inputs
carry no preview flag either.

## Why it matters

- `deleteLedger` is the most destructive call in the 44-tool inventory and the
  only content-or-lifecycle destroy operation with no preview of any kind
  (`deleteLedgerFiles` and `deleteEntrySource` both preview).
- `updateLedger` with `private: false` publishes the ledger to anyone (the tool
  itself warns "Open world" in HEAD source) — exactly the kind of call a preview
  exists for.
- An agent doing routine maintenance (the m7 persona) gets previews everywhere
  except where the blast radius is largest — the safety gradient points the
  wrong way.

## Suggested fix

Either extend `dry_run` to the lifecycle mutations (at minimum `updateLedger`
and `deleteLedger`), or document the deliberate exclusion in the m7 milestone
record and the tool descriptions. `createLedger`'s separate-preview-tool pattern
is a precedent for "preview, but not via the flag" — `deleteLedger` could grow a
`previewLedgerDelete` the same way if the flag does not fit the lifecycle shape.

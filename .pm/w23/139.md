# 139 — Window functions work only with omitted FROM; any explicit FROM fails as "subquery" (it.6146-6148)

## Summary
MCP's window functions (`row_number`, `rank`, `dense_rank` — stock has none, it.4538) run only when no table is named. Omit FROM, or use the table-less scope form (`FROM OPEN ON …`), and windows number rows; name any table — `FROM postings`, quoted `FROM "postings"`, `FROM entries` — and the identical window fails with `Window functions not supported in subquery expressions`, though the query contains no subquery. The error message is doubly wrong: it names a subquery that isn't there, and it refuses a placement (top-level SELECT target) the engine otherwise supports.

## Repro (prod, puncsky/mcp-agent-eval)
- `SELECT row_number() OVER () LIMIT 3;` → `[[1],[2],[3]]`.
- `SELECT payee, row_number() OVER (ORDER BY payee) LIMIT 3;` → rows.
- `SELECT row_number() OVER () FROM postings LIMIT 3;` → `evaluation error: Window functions not supported in subquery expressions`.
- Same with `FROM "postings"`, with `OVER (ORDER BY payee)`, with `rank()`, and with `FROM entries` — all named-table forms fail identically.
- Refined it.6149: `FROM OPEN ON 2020-01-01` + window WORKS (`[[1],[2]]`) — the scope form names no table. Rule is unnamed-vs-named, not bare-vs-explicit.
- Corrects the it.4538 verdict ("No defect in the implemented subset"): the subset has a FROM-form hole. The it.4545-4547 subquery refusal uses this same message, suggesting the engine routes explicit FROM through its subquery path.

## Expected
Named-table FROM behaves like omitted FROM for top-level windows (or all top-level windows are refused with an accurate message — but bare works today, so parity means fixing named, not breaking bare).

## Status
Open (inbox). MCP-engine-side (FROM-form routing into the window evaluator); no stock differential exists.
- Extended it.6150: a derived-table FROM breaks top-level windows too (`SELECT row_number() OVER () FROM (SELECT …) ` → same subquery error). Windows survive only bare and table-less-scope FROM; any table name or derived table routes into the refusing path.

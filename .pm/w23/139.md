# 139 — Window functions work only with omitted FROM; any explicit FROM fails as "subquery" (it.6146-6148)

## Summary
MCP's window functions (`row_number`, `rank`, `dense_rank` — stock has none, it.4538) run only when FROM is omitted. Add any explicit FROM — `FROM postings`, quoted `FROM "postings"` — and the identical window fails with `Window functions not supported in subquery expressions`, though the query contains no subquery. The FROM form decides: bare works, explicit breaks. The error message is doubly wrong: it names a subquery that isn't there, and it refuses a placement (top-level SELECT target) the engine otherwise supports.

## Repro (prod, puncsky/mcp-agent-eval)
- `SELECT row_number() OVER () LIMIT 3;` → `[[1],[2],[3]]`.
- `SELECT payee, row_number() OVER (ORDER BY payee) LIMIT 3;` → rows.
- `SELECT row_number() OVER () FROM postings LIMIT 3;` → `evaluation error: Window functions not supported in subquery expressions`.
- Same with `FROM "postings"`, with `OVER (ORDER BY payee)`, and with `rank()` — all explicit-FROM forms fail identically.
- Corrects the it.4538 verdict ("No defect in the implemented subset"): the subset has a FROM-form hole. The it.4545-4547 subquery refusal uses this same message, suggesting the engine routes explicit FROM through its subquery path.

## Expected
Explicit FROM behaves like omitted FROM for top-level windows (or all top-level windows are refused with an accurate message — but bare works today, so parity means fixing explicit, not breaking bare).

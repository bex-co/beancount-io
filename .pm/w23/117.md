# w23/117 — `prompts/get` silently ignores unknown string arguments while tools refuse unknown keys

Status: inbox
Opened: 2026-10-26 (loop it.2693–2694)
Surface: MCP (`prompts/get`)
Severity: minor (consistency; no wrong data — an ignored arg only drops caller intent)

## Summary

`prompts/get` type-checks every argument as a string but silently IGNORES unknown
argument names. MCP tools, in contrast, refuse unknown keys (`Unrecognized key`).
So within the MCP surface alone, strictness depends on which method you call:

| call | result |
|---|---|
| `prompts/get close-month {"month":"2026-01"}` | OK, renders prompt |
| `prompts/get close-month {"month":202601}` | `-32602` BAD_USER_INPUT (sensible) |
| `prompts/get close-month {"month":"2026-01","bogus":"x"}` | OK — `bogus` silently ignored, prompt renders normally |
| `prompts/get close-month {"month":"2026-01","bogus":1}` | `-32602` BAD_USER_INPUT (`expected string, received number`) |
| `tools/call runBqlQuery {"query":"…","dryRun":true}` | BAD_USER_INPUT `Unrecognized key: "dryRun"` (it.2525; the key the caller most plausibly typo'd) |

The last two rows are the oddest combination: unknown args are pointless-ly
type-checked (a number is refused) and then ignored anyway (a string passes and
does nothing). The type gate serves no purpose for keys the server never reads.

## Full-surface strictness map (unknown keys)

| surface | unknown key behavior |
|---|---|
| MCP tools | refused (`Unrecognized key`) |
| MCP prompts | silently ignored (this note) |
| REST GET | silently ignored (w23/113) |
| REST POST body | silently ignored (w23/112) |
| GraphQL | refused by spec validation |

Three strict-or-spec behaviors vs two silent-ignore behaviors, and the split runs
*inside* MCP (tools vs prompts), not just across protocols.

## Why it matters

A caller that misspells a prompt argument (`{"montth":"2026-01"}`) gets a rendered
prompt with the default/empty slot and no signal anything was dropped — the same
silent-intent-loss class as w23/112/113, with a smaller blast radius (prompt text
only, no ledger writes). The tools side already sets the repo's stricter precedent.

## Suggested fix

- Either reject unknown prompt arguments like tools do (`Unrecognized key`), or
- drop the purposeless string type-check on keys that will be ignored anyway —
  but (a) matches the tools precedent and the w23/112/113 direction.

## Repro

```bash
node .agents/skills/qa-shared/scripts/qa-mcp.mjs prompt close-month \
  '{"month":"2026-01","bogus":"x"}'
# → renders normally; bogus ignored
node .agents/skills/qa-shared/scripts/qa-mcp.mjs prompt close-month \
  '{"month":"2026-01","bogus":1}'
# → -32602 params.arguments.bogus: expected string, received number
```

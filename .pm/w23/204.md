# 204 — A file batch holding a path and one of its sub-paths commits "N changes" but silently drops a file; the dry run says it is fine

**Severity:** major (silent data loss behind a success message; the preview that is supposed to run "the same checks the commit runs" approves it). **Estimate:** 40–60 minutes with tests. **Owner:** `backend-cluster/backend-v2` — the batch guards in `src/features/ai-agent/tools/edit-ledger-files-tool.ts` (`assertFoldable`) and `src/features/ledger/service/ledger-repo-service.ts` (`assertNoTwinsAmong` / `assertNoPortableTwin`, ~L350–371, shared with `src/features/ledger/utils/portable-twin.ts`); MCP `createLedgerFiles` / `updateLedgerFiles`, and the same service for the other surfaces. **A1:** agents write scaffolding such as `reports` then `reports/q3.bean`, in one call or across calls, and report "done".

## Repro (production, 2026-10-30, API key pinned to the disposable QA ledger; all probe files deleted afterwards, `main.bean` untouched at blob `f1a0b83`)

Case 1 — a file, then a path beneath it, in one `createLedgerFiles` call:

```json
{"description": "probe", "files": [
  {"path": "qa-f.bean",        "content": ";\n"},
  {"path": "qa-f.bean/child.bean", "content": ";\n"}]}
```

- `dry_run: true` → `ok`, "Dry run: 2 change(s) previewed (qa-f.bean, qa-f.bean/child.bean) — not committed. No new bean-check errors."
- Real call → `ok`, "Committed 2 change(s) to qa-f.bean, qa-f.bean/child.bean."
- `listLedgerFiles` afterwards: `qa-f.bean` is `type: "dir"`, `size: 0`; `readLedgerFiles qa-f.bean` → "is a directory, not a file". Only `child.bean` exists; the file `qa-f.bean` was lost without a word.

Case 2 — the reverse order (`qa-d/child.bean`, then `qa-d`): the same "Committed 2 change(s)", and now `qa-d` is a file and `qa-d/child.bean` → `NOT_FOUND`. The last write wins.

Case 3 — an existing file as the parent: `createLedgerFiles` of `main.bean/x.bean`.

- `dry_run: true` → `ok` ("No new bean-check errors").
- Real call → `BAD_USER_INPUT` "commit failed: a file exists where you’re trying to create a subdirectory [path: main.bean]"; nothing written. Safe, but the preview contradicts the commit.

Controls that work: the same path twice in one call is refused ("is created twice in one call"), a case-twin (`MAIN.BEAN`, `QA-…-T.bean` beside `qa-…-t.bean`) is refused with `CONFLICT`, `/abs`, `//`, `\`, NUL and `.git/…` paths are refused, and 255-character names commit (256 is refused).

## Root cause

The batch guards look only at equality and at portable case/Unicode twins. `assertFoldable` folds operations per identical path, and `assertNoTwinsAmong` / `assertNoPortableTwin` compare names by `portablePathKey`. Nothing asks whether one path is a directory prefix of another, either inside the batch or against a file the repository already holds. Git cannot hold both, so the commit either errors from the host (case 3, after the preview approved it) or resolves the collision by keeping the last path in the batch (cases 1–2) while the response still lists both paths as written.

## Fix

Add one prefix check next to the twin checks, used by the preview and the commit alike: for every created or renamed path, refuse with `BAD_USER_INPUT` (or `CONFLICT`, matching the twin check) naming both paths when (a) another path in the batch is a `/`-prefix of it or it is a prefix of another, or (b) an existing repository file equals one of its parent folders (the case-3 situation), or an existing folder equals the new file's path. Include `renameLedgerFile`'s `newPath` and its `dry_run`. Tests: file-then-child and child-then-file batches, existing-file-as-parent, existing-folder-as-file, and a case where a delete in the same batch removes the blocker (allowed). Confirm the result's `wrote` list matches the tree after commit.

Cross-surface: the guards live in the shared ledger service, so REST and GraphQL file writes inherit the fix; add one assertion per surface that the refusal is identical. MCP was the only surface exercised here.

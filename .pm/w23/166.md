# 166 — Mid-period `FROM OPEN ON` drops stock's opening-summary rows (26/36, 0/12)

## Summary
Stock's `FROM OPEN ON <date>` returns the postings from `<date>` onward plus a synthetic opening-balances entry dated `<date>−1` summarizing everything before it (offsetting `Equity:Opening-Balances` legs plus an `Equity:Earnings:Previous` leg). MCP returns only the suffix rows and silently drops the summary block: `OPEN ON 2026-06-01` → 26 vs stock's 36 (10 summary postings missing); `OPEN ON 2026-12-31` → 0 vs 12 (all summary, all missing). The only agreeing date is a period start with no pre-activity (`2026-01-01` → 34/34) — which is exactly the vacuous cell behind blocked/022's it.3414–3415 "proper forms agree at 34/34" claim. The mirror scope is clean: `FROM CLOSE ON` agrees row-for-row (8/8 mid-period, 34/34 full), so the gap is OPEN-summarization only.

## Repro (prod, puncsky/mcp-agent-eval; stock = beanquery 0.2.0 on the byte-identical fixture)
- `SELECT count(*) AS n FROM OPEN ON 2026-06-01;` → MCP 26; stock 36.
- `SELECT count(*) AS n FROM OPEN ON 2026-12-31;` → MCP 0; stock 12.
- `SELECT count(*) AS n FROM OPEN ON 2026-01-01;` → 34 both (no pre-activity, vacuous).
- Row evidence (Jun-01, `ORDER BY date`): stock leads with ten `2026-05-31` summary postings (`Assets:Bank:Checking 2484.51`, `Assets:Bank:Savings 10500.00`, `Assets:Cash 200.00`, `Equity:Earnings:Previous 15.49`, each offset to `Equity:Opening-Balances`); MCP's first row is the `2026-07-01` salary posting. The 26 suffix rows match stock exactly.
- REST twin: `POST …/ledgers/puncsky/mcp-agent-eval/query` with Jun-01 OPEN ON → `[[26]]`, identical (shared engine path).
- Controls: `FROM CLOSE ON 2026-06-01` → 8/8 with byte-identical rows; `CLOSE ON 2026-12-31` → 34/34. Bad-date `OPEN ON 2026-13-45` refuses both (MCP names the wrong token, stock `ValueError` — message nit, below bar).

## Root cause (main)
Engine-side (rustledger): the OPEN scope evaluates as a plain date-suffix filter with no opening-summary synthesis, and no `OPEN ON` handling exists in TS service code to rewrite around it. Same upstream-engine class as w23/154/157/165. Corrects blocked/022 it.3414–3415 (agreement holds only where no summary rows exist).

Emit the opening-summary entry (dated `<date>−1`, opening legs per balance account offset to `Equity:Opening-Balances` plus the earnings leg) exactly as stock does, or document that MCP's OPEN scope is suffix-only. Counts and `sum(position)` over OPEN scopes are wrong until then.

# 154 — BQL `+` refuses string concatenation stock performs (`'a'+'b'` → `ab`; `payee+'!'` works)

## Summary
Stock beanquery defines `add(str, str)` as concatenation, but MCP's engine rejects it (`type error: arithmetic requires numeric values`). `'a' + 'b'` → stock `ab`, MCP `BAD_USER_INPUT`; `payee + '!'` → stock `CITY BUS!`, MCP refuses. Every neighboring cell co-refuses (`-`, `*` on strings; `+` with mixed str/int), so the gap is exactly str+str `+`. Stock offers no `concat()` function either (`no function matches "concat(str, str)"`), so `+` is the only concat spelling and MCP has no workaround.

## Repro (prod, puncsky/mcp-agent-eval; stock = 3.2.3 on the byte-identical fixture)
- `SELECT 'a' + 'b' AS s;` → MCP `BAD_USER_INPUT: arithmetic requires numeric values`; stock `ab` (×34 implicit-scope rows both sides for the shape).
- `SELECT payee + '!' AS s WHERE payee ~ 'CITY' LIMIT 2;` → MCP refuses; stock `CITY BUS!` ×2.
- Controls, all co-refused: `'a' - 'b'` (`sub(str, str)`), `'a' * 2` (`mul(str, int)`), `'a' + 1` (`add(str, int)`).
- Unary minus (`-number` → `-3000.00`) and modulo (`7 % 3` → 1 ×34) agree exactly.

## Root cause (main)
The refusal text (`arithmetic requires numeric values`, like the `UPPER expects a string` family) originates in the rustledger WASM engine, not TS service code — no service-level rewrite target exists (stock has no `concat()` to rewrite to). Engine feature or documented gap.

## Expected
Support `add(str, str)` as concatenation in the engine to match stock, or document that MCP BQL has no string-concat spelling (with the refusal message pointing at the limitation rather than the generic numeric hint). Sub-hour to document; engine work if supported.

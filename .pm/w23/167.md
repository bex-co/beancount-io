# 167 — Bare `price` flips Amount→`str` when all values are NULL (no Amount name rule)

## Summary
`price` is an Amount-typed column when values are present (`[[{"USD":"2"}]]`, dtype `Amount`), but with all-NULL cells — or zero rows — the bare column reports dtype `str`. Every sibling holds its schema type on the same input (`cost_number`→`Decimal`, `cost_date`→`date`, `position`→`Position`, `balance`→`Inventory`, `tags`→`set`): `price` is the only stored column whose type depends on value presence. Same consumer hazard as w23/136 (branch-on-dtype breaks exactly when data is absent), but a different trigger (all-NULL-with-rows, not just zero-row) and a different miss — and neither shipped fix covers it: w23/136 added only `id`/`other_accounts`/`accounts` to the name tables, and w23/164 explicitly leaves bare columns on the name rule while typing expressions.

## Repro (prod, puncsky/mcp-agent-eval; QA fixture carries no `@` prices, so `price` is all-NULL)
- `SELECT price, cost(position) LIMIT 1;` → dtypes `str`/`Amount`, row `["", {"USD":"3000.00"}]` — the bare column flips while the function holds.
- `SELECT price, cost_number LIMIT 1;` → dtypes `str`/`Decimal` — sibling holds, `price` flips.
- `SELECT price WHERE FALSE LIMIT 1;` → dtype `str`, zero rows (same fallback on the empty path).
- Control with values (it.112 live pin, `@`-price fixture since removed): `SELECT price … WHERE price IS NOT NULL` → `[[{"USD":"2"}]]`, dtype `Amount`. The true type is Amount; `str` is the fallback lie.
- REST twin: `POST …/ledgers/puncsky/mcp-agent-eval/query` with `SELECT price LIMIT 1;` → identical `types:[{price,str}]`, row `[[""]]` (shared shell mappers; GraphQL `queryShell` rides the same).

## Root cause (main)
`dtypeFromColumnName` (`backend-cluster/ledger/src/features/ledger/service/ledger-shell-mappers.ts:159-167`) has a rule per dtype family — date, int, Decimal, set, Inventory, Position — but no Amount rule and no `price` entry, so Amount-typed bare columns fall through to `str`. One-set fix mirroring w23/136 (`AMOUNT_COLUMNS = {"price"}` + pins); `price` is the only Amount-typed bare postings column (`position`→Position and `balance`→Inventory are covered under their own families).

## Expected
Bare `price` reports `Amount` with zero rows or all-NULL cells, like every other stored column keeps its schema dtype. Audit for further missing families while touching the table (today: date/int/Decimal/set/Inventory/Position covered, Amount missing, bool/object have no bare columns).

# 191 — BQL `BETWEEN` refuses strings the ordering operators accept (`payee BETWEEN 'A' AND 'M'`)

**Severity:** minor (loud refusal; same-type operands). **Estimate:** 1–2h (route
string BETWEEN through the ordering path). **Owner:** ledger engine
(`@rustledger/wasm` BETWEEN evaluation). **A1:** agents range-filtering any
string column.

MCP's `<`/`>` compare strings fine (`WHERE payee < 'M'` → 16, agrees with
stock), but `BETWEEN` on the same column refuses with `type error: cannot
compare values` while stock answers:

| predicate | MCP | stock |
|---|---|---|
| `payee BETWEEN 'A' AND 'M'` | `cannot compare values` | `16` |
| `number BETWEEN 100 AND 5000` | `9` | `9` (agree) |
| `date BETWEEN 2026-01-01 AND 2026-03-31` | `8` | `8` (agree) |

- REST twin refuses the string case identically (shared engine path).
- Not w23/132: that note's BETWEEN legs are *mixed-type* (`date BETWEEN str`)
  where both sides refuse; this is *same-type* str BETWEEN, refused only here.
- QA ledger untouched (read-only probes; byte-identical + stock-clean re-verified
  this loop: blob f1a0b83c, SHA-256 77c3a591, 2817 B).

# 191 — BQL refuses dot-decimal literals stock accepts (`.5`, `5.`, `-.5`)

**Severity:** minor (loud refusal; stock-only spellings). **Estimate:** 1–2h (lexer:
optional digits on either side of `.`). **Owner:** ledger engine lexer
(`@rustledger/wasm`) or TS pre-pass. **A1:** agents writing `.5`-style fractions.

Stock beanquery accepts decimals with digits missing on either side of the point;
the engine refuses all three (`.5`/`-.5` with the bogus position-0 error, `5.`
with a mid-query error):

| literal | MCP | stock |
|---|---|---|
| `SELECT .5` | `syntax error at position 0: unexpected token 'SELECT'` | `0.5` |
| `SELECT 5.` | `syntax error at position 16: found '1' …` | `5` |
| `SELECT -.5` | position-0 error | `-0.5` |

- REST twin refuses `.5` identically (shared engine path).
- Neighboring cells agree in refusal: `1e3`/`.5e1` (no exponent grammar either
  side), `0x10` (no hex either side) — the gap is exactly dot-decimals.
- Not w23/043 (that normalized leading-dot *amounts on the write path*;
  `toBeancountNumber` writes `0.5` for `.5` — this is the BQL *read* lexer, a
  different mechanism with no shared code).
- QA ledger untouched (read-only probes; byte-identical + stock-clean re-verified
  this loop: blob f1a0b83c, SHA-256 77c3a591, 2817 B).

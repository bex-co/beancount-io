# Typed `open` requires `currencies`; stock beancount does not

**Severity:** minor (valid Beancount rejected on the typed path; workaround is raw text). **Estimate:** 30–60m incl. parity. **Owner:** `backend-cluster/backend-v2` (contracts) + `backend-cluster/ledger` (renderer). **A1/A2:** agents mirroring a currency-less `open` from an existing file get a refusal for a valid directive.

## Repro (production, 2026-10-26, API key pinned to `puncsky/mcp-agent-eval`)

`addLedgerEntries {entries: [{type: "open", entry: {date: "2026-10-26", account: "Assets:New"}}]}` → `BAD_USER_INPUT: entries.0.entry.currencies: Invalid input: expected array, received undefined`.

Control: `bean-check` accepts both `2026-01-01 open Assets:Nolag` and `2026-01-01 open Assets:Withlag USD` (verified against local beancount 3.2.3). The constraint list is valid on stock; the typed path invents a requirement.

Same refusal on REST (`POST /v1/ledgers/{owner}/{name}/entries` → `VALIDATION_FAILED`, verified live) and GraphQL (`LedgerOpenInput.currencies` is `NON_NULL`, verified via introspection). Parity holds — all three over-require identically — so one shared fix covers every surface.

## Fix

Make `currencies` optional on the typed `open` (absent/empty renders a bare `open` line), on REST, GraphQL, and MCP together. Neighbor: w23/m6/t009 adds `booking` to the same `open` input — whoever lands second rebases onto the first.

## Dedupe

No `.pm` item covers `open` currencies (searched: currencies required, open currencies; w23/m6 owns cost/tags/links/booking/tolerance/total-price/pad and the four uncovered directive types are w23/105). Open: m6, 095–105.

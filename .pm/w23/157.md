# 157 — Double-quoted identifiers silently become string literals outside FROM (`SELECT "account"` → `account`, not the column)

## Summary
Stock resolves `"name"` as a column when one exists (falling back to a string literal only for unknown names), but MCP reads `"…"` as a string literal in every position except FROM — silently returning wrong data with no error. `SELECT "account" LIMIT 1` → stock `Assets:Bank:Checking`, MCP the literal `account`; `WHERE "account" = 'Assets:Cash'` → stock 5 rows, MCP 0; `ORDER BY "date" DESC` → stock's latest row (`Produce`), MCP the unscanned first row (`Opening balances`, ordering by a constant). FROM is the sole exception: the normalize pipeline unquotes `FROM "<table>"` (w23/115, w23/130), so quoted tables work while quoted columns silently don't — an intra-query inconsistency.

## Repro (prod, puncsky/mcp-agent-eval; stock = 3.2.3 on the byte-identical fixture)
- `SELECT "narration" LIMIT 1;` → MCP literal `narration` (header `"narratio`); stock `Opening balances`.
- `SELECT "account" LIMIT 1;` → MCP literal `account`; stock `Assets:Bank:Checking`.
- `SELECT count(*) AS n WHERE "account" = 'Assets:Cash';` → MCP `0`; stock `5`.
- `SELECT narration ORDER BY "date" DESC LIMIT 1;` → MCP `Opening balances`; stock `Produce`.
- Control, the lenient half both share: `SELECT "nonexistent" LIMIT 1;` → literal `nonexistent` on *both* (stock falls back to string for unknown names — MCP matches only this half).
- FROM contrast (w23/130): `SELECT count(*) FROM (SELECT * FROM "postings");` → `34` both (pipeline unquotes; quoted tables resolve).

## Root cause (main)
`unquoteBqlFromTables` (`backend-cluster/ledger/src/features/ledger/service/bql-from-quotes.ts`) is deliberately FROM-only ("Only a `\"` immediately after FROM + whitespace is touched … Anything else is left for the engine"), and the engine lexes `"` as a string literal with no column-resolution fallback. Stock's rule (column-if-known-else-literal) needs the same treatment in SELECT/WHERE/ORDER BY/GROUP BY — or an explicit refusal of quoted non-FROM names.

## Expected
Resolve `"name"` as a column where one exists (matching stock, including its unknown-name literal fallback), or refuse quoted identifiers outside FROM with a message naming the supported spelling. Silent literal substitution is the unacceptable state — every current case returns plausible-looking wrong data. Extends the 115/130 unquote family to the remaining clause positions.

## Status
Open (inbox). Ledger normalize pipeline + engine string/identifier lexing. Not sub-hour (position-aware rewrite or engine lexer change).

# `well-known-route.test.ts` registry-listing test fails on clean `main`: `server.json` is 1.0.1, the manifest and MCP `serverInfo` are 1.0.0

**Severity:** minor (red full `yarn test` in `backend-cluster/backend-v2`, which gates `CI (backend parity)`; no runtime effect). **Owner:** `backend-cluster/backend-v2`. **Estimate:** 15–30m. **Pillar:** A1. **Parity:** not applicable (discovery metadata only; no REST/GraphQL/MCP capability changes).

## Repro

`cd backend-cluster/backend-v2 && yarn jest src/features/well-known` → `lists the manifest's endpoint in the MCP Registry listing` fails: `Expected: "1.0.0"`, `Received: "1.0.1"` (`well-known-route.test.ts:194`). Reproduces on a clean `main` (checked 2026-11-05 with local changes stashed), so it predates `w23/213`.

## Cause

`58ea680e5` (2026-11-04, "link marketplace descriptions to the product website") edited the registry listing and bumped `server.json` to `1.0.1`, as required: published registry versions are immutable, so any listing change needs a new version (`docs/mcp.md`, publish section). The manifest version (`src/features/well-known/api/well-known-route.ts:34`) and the MCP `initialize` `serverInfo` (`src/server/api/composition-root.ts:519`) still say `1.0.0`. The test asserts `listing.version === manifest.version`, which couples two different things: the registry-listing version (bumps on every listing edit) and the server version clients see.

## Fix (pick one)

- **(a)** Bump the manifest and `serverInfo` to `1.0.1` together. Check `yarn mcp:conformance`, `docs/mcp.md` and any other test or doc that pins `1.0.0`. Every later listing-only edit will repeat this.
- **(b)** Drop the version-equality assertion and keep the name (`io.beancount/beancount`) and single-remote endpoint guards. Listing edits then bump `server.json` alone. Recommended: the two versions have different lifecycles.

Either way, add a one-line note in `docs/mcp.md` stating which version the listing tracks.

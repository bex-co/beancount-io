# `createPullRequest` fails on production: Gitea 500 while creating the `pr-patch-*` branch, on MCP and REST alike

**Severity:** major (a documented write workflow fails single-flight with no workaround; cause unverified — may be incident-related, see below). **Estimate:** 30–60 minutes once the Gitea cause is read. **Owner:** `backend-cluster/backend-v2`, `pull-request-service.ts` step 3 (`repoCreateBranch`), plus whoever runs Gitea. **A1/A2:** agents open PRs to propose ledger changes for review; onboarding points at the same flow.

## Repro (production, 2026-10-25 ~04:20–04:30 UTC, API key pinned to `puncsky/mcp-agent-eval`)

`createPullRequest` with `title`, `description`, `clearCommitMessage` and `changes: [{path: "qa-20261025-pr.bean", content: "2026-01-01 open Expenses:Qa:Pr USD\n"}]` — 4 attempts over ~10 minutes, all:

```json
{"ok": false, "error": {"code": "SERVICE_UNAVAILABLE",
  "message": "Could not create the pull request: Gitea 500 while creating branch pr-patch-<ts>-<rand> (Gitea gave no reason; its server log has the cause). No pull request was opened."}}
```

REST `POST /api-gateway/v1/ledgers/puncsky/mcp-agent-eval/pull-requests` with the same body fails identically (503, same message), so this is backend→Gitea, not MCP-specific. Controls pass: `mergePullRequest {prNumber: 999999}` → `NOT_FOUND`, `pull-request?prNumber=1` → `NOT_FOUND`, and every other write tried this session (append, add, entry-source update/delete, file create/edit/rename/delete) succeeds — only branch creation fails. No PR or branch is left behind (w5/053).

## Cause (unverified)

Step 2 (read base branch `main`) succeeds; step 3 (`client.repos.repoCreateBranch`, `backend-cluster/backend-v2/src/features/gitea/pull-request/service/pull-request-service.ts:335-347`) gets Gitea 500 with an empty detail. The backend logs owner/repo/step/status/detail (`pull-request-service.ts:299`), and Gitea's server log has the cause. Possibly related to the 04:04–04:05 UTC MCP-route 502 incident the same night (Cloudflare `origin_bad_gateway`, every `POST /api-gateway/mcp` affected, recovered in ~2 minutes) — or an independent Gitea fault.

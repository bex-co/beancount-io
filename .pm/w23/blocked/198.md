# 198 — entries tags/links are empty sets on MCP but NULL on stock (13 rows flip IS NULL)

## Summary
On the `entries` table, rows for non-transaction directives (e.g. `open`) carry
`tags`/`links` as empty sets on MCP but as NULL on stock. The split is
query-observable: `SELECT COUNT(*) FROM entries WHERE tags IS NULL` returns `0`
on MCP and `13` on stock; `tags IS NULL` on row 1 reads `FALSE` vs `TRUE`;
`length(tags)` reads `0` vs blank; and `str(tags)` hard-errors on MCP (`STR
expects a string, integer, number, boolean, date, or amount` — it sees a set)
while stock blanks it (NULL passthrough). `links` behaves identically
(`links IS NULL` FALSE vs TRUE, `length(links)` 0 vs blank). Postings agree
(row 1 `tags/links IS NULL` FALSE on both), so the split is entries-table-only:
stock leaves set columns NULL where the directive has none, MCP materializes
empty sets.

## Repro
- `call runBqlQuery {"ledger":"puncsky/mcp-agent-eval","query":"SELECT COUNT(*) FROM entries WHERE tags IS NULL;"}` → `0` (GraphQL `queryShellText` twin: `0`, engine-level, all surfaces). Stock: `13`.
- `… SELECT tags IS NULL, tags FROM entries LIMIT 2` → `FALSE, FALSE` (MCP) vs `TRUE, TRUE` (stock).
- `… SELECT length(tags) FROM entries LIMIT 2` → `0, 0` (MCP) vs blank, blank (stock).
- `… SELECT str(tags) FROM entries LIMIT 1` → MCP `type error: STR expects…`; stock blank row.
- Controls: postings row 1 `tags/links IS NULL` FALSE both; txn rows with real tags agree.

## Expected
Pick one model deliberately and document it: either materialize empty sets on
both (stock-side upstream fix) or preserve NULL on both (engine fix). At minimum
`str()` on a set-typed column should not hard-error where stock passes NULL
through — the error is reachable only because of the model split. Owner:
rustledger engine (entries row builder) + `STR` outtype; portability note for
the upstream report either way.

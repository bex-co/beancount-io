# Typed BQL results return SQL NULL as `""`: `runBqlQueryStructured` can't tell a missing payee or price from an empty string

**Severity:** minor. **Estimate:** 15 minutes for the doc; 45–60 minutes to emit `null`. **Owner:** `backend-cluster/ledger`, `toShellCell` in `src/features/ledger/service/ledger-shell-mappers.ts` ("The pre-migration backend-v2 adapter converted Fava's nullable cells to an empty string"), shared by MCP `runBqlQueryStructured`, REST JSON query and GraphQL `queryShell`. **A1:** "which transactions have no payee?" or "which postings carry no price?" from typed rows reads `""` as a value.

## Repro (production, 2026-10-22, QA fixture, read-only)

| query | result |
| --- | --- |
| `SELECT count(*) WHERE payee IS NULL` | 6 |
| `SELECT count(*) WHERE payee = ''` | 0 |
| `SELECT payee, price LIMIT 1` (structured) | `["", ""]`, `price` labelled `str` |
| `SELECT NULL`, `SELECT 1/0` (structured) | `""` |

`docs/mcp.md` documents that `dtype` labels are inferred and can be wrong, and says "Scalar text and decimal strings preserve their values". It does not say NULL becomes `""`.

## Fix

Owner decision:

- (a) Document it now in `docs/mcp.md` and `ledger/README.md#bql-column-types`: "NULL cells are returned as an empty string; use `IS NULL` in the query to tell them apart."
- (b) Emit `null` on REST and MCP (keeping `""` only where the GraphQL scalar cannot carry null). This is a contract change on all three surfaces, so it should land with a parity test.

(a) is the minimum. Test for (b): `SELECT payee, price` returns `null` for missing values, while `""` stays `""`.

## Dedupe

The documented `dtype` limitation (`ledger/README.md#bql-column-types`) covers labels, not values. The w4 BQL items cover dashboard rendering. No item covers NULL serialization.

---

**Blocked 2026-10-23** — option (a), the note's stated minimum, shipped in the commit that blocked this note. Option (b) is the owner's contract decision.

Shipped for (a): `backend-cluster/ledger/README.md#bql-column-types` and `backend-cluster/backend-v2/docs/mcp.md` (the BQL `dtype` paragraph) now say that a NULL cell is returned as `""`, the same as an empty value, and that `IS NULL` in the query tells them apart. `ledger-shell-null-cells.test.ts` pins that behavior (`toShellCell`), so the docs cannot drift from it unnoticed. The ledger's typecheck, ESLint and Knip pass, and 1902 unit tests pass.

Not done, (b): emitting `null` on REST JSON and MCP `runBqlQueryStructured` while GraphQL `queryShell` keeps `""` (its cell scalar), or `null` on all three. Either changes a published result contract that clients may parse (the dashboard reads `queryShell`; agents read the MCP rows), and it splits the surfaces this note found sharing one producer.

**Unblock:** the owner chooses: (b1) `null` on REST and MCP with `""` kept on GraphQL, (b2) `null` everywhere including a GraphQL schema change, or (b3) keep `""` as documented, in which case close this note as done. For (b1) or (b2), the parity test the note asks for: `SELECT payee, price` gives `null` for missing values, and `""` stays `""`.

## Objective

Let a host that shows only a resource's text tell whether more pages remain. Today the signal travels only in `_meta`.

## Context

- `pagedResourceContent` in `backend-cluster/backend-v2/src/server/api/page-signals.ts` returns the body as `JSON.stringify(result)` and puts `page` in `_meta`.
- For offset reads (`ledgerJournal`, `ledgerAccountJournal`, `getFeed`) the body has a `total`, so the answer can be worked out. For bare-array reads (`accessibleLedgers`, `ownedLedgers`, `searchLedgers`, `ledgerCommits`, `ledgerCollaborators`, `ledgerPublicKeys`) it cannot.
- The body matches the REST JSON body, so reshaping it would break parity. A `resources/read` result may carry more than one `contents` item.

## Steps

1. Choose a carrier that leaves the first `contents` item byte-identical to today's. For example, a second `text/plain` item stating `returned`, `hasMore` and, when known, `total`.
2. Apply it to every paged resource through `pagedResourceContent`.
3. Document it in `docs/mcp.md` beside the existing `_meta` description.

## Files

## Acceptance criteria

- [x] Reading a bare-array resource whose page is full shows `hasMore: true` in the text a client receives, not only in `_meta`.
- [x] The first `contents` item is unchanged for every paged resource (a test compares it to the REST body).

## Out of scope

- Unpaged resources.

## Result

`makeMcpResourceHandler` (`composition-root.ts`) appends a second content item, `{"page": …}` as `application/json` on the same URI, whenever a resource read returns a page signal in `_meta`. The first item, and its `_meta`, stay as they were, so the body still equals REST's. This covers every paged resource through `pagedResourceContent`, including the staged-transactions resource from t003. `catalog-parity.test.ts` ("says the same thing about what remains") reads `beancount://catalog/ledgers?page=2&limit=1`, a bare-array page that is full. It checks that the first item's text is byte-identical to the REST body, that the second item carries `hasMore: true` and `nextPage: 3`, and that there are exactly two items. `docs/mcp.md` § Pagination names the carrier.

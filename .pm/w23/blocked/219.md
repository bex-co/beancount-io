# 219 — `appendLedgerText` `dry_run` previews an unbalanced transaction as a success while the commit is refused `UNBALANCED`; sibling `addLedgerEntries` refuses on `dry_run` too

**Severity:** minor. **Owner:** `backend-cluster/backend-v2` (`src/features/ledger/utils/directive-text-contract.ts`; REST, GraphQL, MCP). **Estimate:** ~45m. **Pillar:** A1.

Found by `qa-find-bugs-mcp` on 2026-11-05 against production (`beancount-mcp` 1.0.0, protocol `2025-11-25`, local HEAD `97093a477`, read/write key, synthetic ledger `<owner>/mcp-agent-eval`). `main.bean` sha was unchanged before and after; nothing was written.

## Repro

Accounts open; the text is unbalanced by 1.00 USD.

- MCP `appendLedgerText {"ledger":"<o>/<n>","dry_run":true,"text":"2026-10-05 * \"qa\" \"\"\n  Expenses:Food:Groceries  1.00 USD\n  Assets:Cash  -2.00 USD"}` → no `isError`, `ok:true`, summary "Would add 1 directive to main.bean. 1 new bean-check error: Transaction does not balance: residual -1.00 USD (main.bean:89)", `validation.newErrors` code `E3001`.
- The same call without `dry_run` → `isError`, `UNBALANCED` "Appending this text would leave a transaction unbalanced", hint "add a posting or pass allowInvalid: true".
- Control: `addLedgerEntries` `dry_run` with the same unbalanced typed transaction → `isError`, `UNBALANCED` "entry 0: Transaction does not balance: residual -1.00 USD". With `allowInvalid: true` it previews with `newErrors`.
- Control: the `…LedgerFiles` tools refuse `VALIDATION_FAILED` on `dry_run` (`docs/mcp.md`).

## Why it matters

`docs/mcp.md` (~line 463) says `dry_run` "returns the unified diff and the projected errors without committing", so the append behavior is documented. It still splits the preview contract two ways between sibling write tools, and an agent that gates on `isError` reads the append preview as safe and then meets a refusal on the real call. [w23/149](./done/149.md) asked for "`dry_run` refuses exactly as the commit would"; [w23/034](./done/034.md) only aligned the error set.

## Fix

Pick one rule and apply it to `appendLedgerText` and `addLedgerEntries` on REST (`dryRun`), GraphQL and MCP, with the docs. The smallest change: make the append `dry_run` refuse `UNBALANCED` / `VALIDATION_FAILED` like the commit unless `allowInvalid`, matching `addLedgerEntries`.

**Blocked 2026-11-05** — Triaged on `main`. The note's smallest fix (make `appendLedgerText` `dry_run` refuse `UNBALANCED` / `VALIDATION_FAILED` like the commit) reverses a shipped, deliberate decision: [w1/037](../../w1/done/037.md) (commit `0d61414c1`) made directive-text previews return the diff plus `newErrors` instead of a refusal, because a refusal left `allowInvalid` as the only way to see the diff, and the documented preview-then-commit workflow then committed the invalid content. `docs/mcp.md` documents this ("`dry_run` returns the unified diff and the projected errors without committing"), and `directive-append-workflow.ts` (the `!dryRun` guard) plus `directive-append-workflow.test.ts` (`dryRun ? 0 : 1`) pin it. The sibling tools disagree: `addLedgerEntries` and the `…LedgerFiles` tools refuse on `dry_run`. The three write families split two ways, and either direction changes a documented contract on REST, GraphQL and MCP. Nothing was changed in code.

**Unblock:** the owner picks one rule:

- **(a)** previews never refuse: `addLedgerEntries` and the `…LedgerFiles` tools also return the diff plus `newErrors` on `dry_run`, and every preview carries a top-level validity flag so a gate on `isError` cannot misread it. Recommended: it keeps w1/037's reason and the safe preview-then-commit workflow.
- **(b)** previews refuse exactly as the commit does unless `allowInvalid`, which reverts w1/037 for append.
- **(c)** keep the split and only document it next to the append tool.

**Who can clear it:** the repository owner (a public contract decision).

# Report rustledger BQL gaps upstream: multi-currency `cost(sum(position))`, `neg`/`filter_currency` signatures, empty `meta('lineno')`, `AT value`, `BALANCES FROM` lot booking

Split from `w23/012` (resolved 2026-10-20 in `20b15532e` with an in-repo guard). `@rustledger/wasm` 0.24.0 returns `cost(sum(position))` over several currencies as one `Amount`: the cost numbers of every currency summed under the first currency's label. beanquery returns one inventory entry per currency.

**Reproducer** (no network):

```beancount
2024-01-01 open Assets:Hours
2024-01-01 open Assets:Broker
2024-01-01 open Assets:Cash
2024-01-01 open Equity:Opening
2024-01-02 * "hours"
  Assets:Hours  -13 VACHR
  Equity:Opening
2024-01-03 * "buy"
  Assets:Broker  17 GLD {268.22 USD}
  Assets:Cash
```

```text
SELECT cost(sum(position)) WHERE account ~ '^Assets:(Hours|Broker)'
  → [{"number":"4546.74","currency":"VACHR"}]      expected: -13 VACHR, 4559.74 USD
SELECT sum(cost(position)) WHERE account ~ '^Assets:(Hours|Broker)'
  → -13 VACHR, 4559.74 USD                         (correct)
```

**Also from `w23/016`** (same engine, same report): `neg(sum(position))` and `-sum(position)` are refused ("NEG expects a number or amount" / "negation requires numeric value"), and so is `filter_currency(position, 'USD')` ("FILTER_CURRENCY expects (inventory, string)"). beanquery accepts all of these forms. `SELECT meta('lineno')`, `lineno` and `entry_meta('lineno')` return null, while beanquery returns the posting's line. On the ledger above:

```text
SELECT account, neg(sum(position)) WHERE account ~ '^Income' GROUP BY account   → type error
SELECT account, sum(filter_currency(position, 'USD')) GROUP BY account          → type error
SELECT meta('lineno') LIMIT 1                                                    → [[null]]
```

**Also from `w23/020`:** `BALANCES … AT value` and `JOURNAL … AT value` ignore the clause and return units. On a holding of `4 VHT` priced at `120.00 USD`, beanquery returns `480.00 USD` and rustledger returns `4 VHT`; `value(sum(position))` is correct. `BALANCES FROM year = 2021` fails with "No matching lot for VHT in Assets:Broker" when the window sells a lot bought before it. `SELECT account, sum(position) FROM year = 2021 GROUP BY account` runs. Separately, `BALANCES FROM CLOSE ON 2016-01-01` omits beanquery's `Equity:Conversions:Current` row. The reproducer ledger is in `w23/020` (`.pm/w23/done/020.md`) and in `verify:rustledger`.

**Also confirmed 2026-10-25** (same accessor family): `entry_meta('filename')` returns `""` on MCP while beanquery returns the path; `meta('lineno')`/`entry_meta('lineno')` still `""`/`null`. Include the filename accessor in the upstream report.

**Also confirmed 2026-10-26** (aggregate-of-aggregate): beanquery refuses `SELECT sum(cost(sum(position)))` (`CompilationError: aggregates of aggregates are not allowed`) while MCP answers one row of `""`. Same family as the `cost(sum(position))` collapse — include the silent-`""`-vs-refusal difference in the upstream report.

# REST GET query schemas silently drop unknown keys instead of refusing them

**Severity:** minor (silent wrong filter; same family as w23/112, but repo-wide). **Estimate:** 1–2h (`.strict()` on every REST GET query schema + regression tests). **Owner:** backend-v2. Found by the QA loop while sweeping w23/112's pattern across REST GET routes.

## Observation (production, 2026-10-26)

Every validated REST GET query schema probed is non-strict: undeclared keys get 200-and-dropped while mistyped *declared* keys fail loudly. Lead case is the journal route:

- `GET .../journal?bogus_param=1&limit=1` → 200, dropped; but `?limit=abc` → `VALIDATION_FAILED: … query.limit …` — so an agent pasting `account_name` for `account` gets an unfiltered page with no error.

Same split verified live (it.2159, it.2163) on seven more routes (`?bogus_param=1` → 200 on each; mistyped declared param → loud failure):

| route | junk `?bogus_param=1` | mistyped declared param |
| --- | --- | --- |
| `plaintext-journal` | 200 | `?limit=abc` → 400 |
| `account-journal` | 200 | `?limit=abc` → 400 |
| `entries-count` | 200 | `?time=not-a-time` → `BAD_USER_INPUT: Failed to parse date` |
| `account-last-entries` | 200 | `?time=not-a-time` → `BAD_USER_INPUT: Failed to parse date` |
| `commits` | 200 | `?page=abc` → 400 |
| `commit-details` | 200 (with valid `sha`) | missing `sha` → 400 |
| `latest-commit` | 200 (with `branchName=main`) | `branchName=no-such-branch-qa` → 404 |
| `files` | 200 | `?dir=/` → 400 `Invalid file path` |

Parity, verified live (it.2157): MCP `listLedgerEntries {"limit": 1, "bogus_param": 1}` → `BAD_USER_INPUT: Unrecognized key: "bogus_param"`; GraphQL `getLedgerJournal` rejects unknown args by construction (`GRAPHQL_VALIDATION_FAILED`; cf. w23/112 it.2153). Of the three surfaces, only REST drops the key.

Non-cases (checked, not this bug): `bank-accounts` takes no query params at all, so its 200-with-junk is plain pass-through with no schema to strictify; `GET bank-transactions` is 405. POST bodies vary but are out of scope: `entries` is strict (`VALIDATION_FAILED: Unrecognized key`), while the single-key `BqlQuery` body drops junk harmlessly (it.2161 — nothing to misspell into, so no filing).

## Fix

`.strict()` on every REST GET query schema (journal + the four above + the w23/112 bank pair + an audit for the rest), with a regression test per route asserting 400 on an undeclared key. Blast radius: REST clients passing unknown query params start getting 400 instead of silently unfiltered 200s.

# 128 — Set equality is constant-False on MCP (`tags = tags` → False) (it.3936)

## Summary
MCP evaluates set-typed `=`/`!=` but gets it wrong: `SELECT tags = tags` returns `False` (and `!=` returns `True`) even when both sides are the identical empty set. Stock beanquery refuses set comparison at compile time (`operator "equal(set, set)" not supported`) — honest, if less capable.

## Repro (prod, puncsky/mcp-agent-eval)
- `SELECT tags, links FROM postings LIMIT 1;` → both empty sets (stock: `(frozenset(), frozenset())`).
- `SELECT tags = tags AS e FROM postings LIMIT 1;` → MCP `[[False]]` (should be True).
- `SELECT tags != tags AS e FROM postings LIMIT 1;` → MCP `[[True]]` (should be False).
- `SELECT tags = links AS e ...` → MCP `[[False]]`; stock `CompilationError: operator "equal(set, set)" not supported`.
- Fixture has no non-empty tags/links (`length(tags) > 0` → 0 rows), so non-empty set equality is untested — the constant-False may or may not extend there.

## Expected
Either implement set equality correctly (empty == empty → True, with proper element comparison for non-empty sets) or refuse like stock. `x = x → False` is a silent wrong result — the worst cell in the cross-type-equality family (cf. it.3211/3212, where MCP's leniency at least produced correct values).

# 142 — `source-files` resource description promises subtype filters the surface refuses

## Summary
The `ledgerSourceFiles` template publishes `beancount://{owner}/{name}/source-files` with the description "List the ledger's source files. Subtype filters are JSON-encoded string arrays." — but the resource takes no query parameters at all. Any filter attempt fails: `source-files?subtype=["bean"]` → `-32602` `BAD_USER_INPUT: Unknown or repeated resource parameter: subtype` ("This resource takes no query parameters"). An agent reading the description burns a turn discovering the sentence is false. The sentence is true for the sibling `journal` template (which takes `directiveTypes`, `transactionSubtypes`, `documentSubtypes`, `customSubtypes` plus paging) — it was overgeneralized to the one filterless read.

## Repro (prod, puncsky/mcp-agent-eval, read-only)
- `resources/templates/list` → `source-files` template has no `{?...}` params yet carries the subtype-filters sentence.
- `read beancount://puncsky/mcp-agent-eval/source-files?subtype=%5B%22bean%22%5D` → `-32602 BAD_USER_INPUT: Unknown or repeated resource parameter: subtype`.
- Control: `read beancount://puncsky/mcp-agent-eval/journal?limit=2` → 200 with contents; journal filter params work.

## Root cause (main)
`backend-cluster/backend-v2/src/features/ai-agent/api/mcp-resources.ts` appends ". Subtype filters are JSON-encoded string arrays." to every `JOURNAL_READS` description unconditionally, while `source-files` in `src/features/ledger/api/rest/v1/journal-reads.ts` defines `query: z.object({}).strict()` — no filters. Same on prod and main; not deployment lag.

## Expected
Append the sentence only when the read declares query params (or drop it from `source-files`); one-line fix plus a template/description consistency test. REST/GraphQL unaffected — the shared `journal-reads` query shape is already correct; only the MCP description overclaims.

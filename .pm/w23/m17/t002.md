## Objective

Replace steps 3 and 4 (branch create, then a read/update-or-create per file) with a single `repoChangeFiles` commit that names `new_branch` from the base branch. One request makes the branch and the commit together, so the failing standalone branch-create call is gone, a half-applied change cannot exist, and no `pr-patch-*` branch is left on failure. Keep the pre-write refusals (empty fields, safe and portable paths, portable twins) and their messages.

- Gitea's contents API `ChangeFiles` accepts `branch` plus `new_branch`; confirm with the generated client types (`repoChangeFiles`) and t001's findings.
- `commitLedgerFiles` in `backend-cluster/ledger/src/features/ledger/operations/commit-ledger-files.ts` is the ledger service's pattern for operations with `sha` on updates; PR changes need the same create-vs-update decision per path, read from the base branch.

2. Send one `repoChangeFiles` with `new_branch`
3. Keep the step-naming error path and the no-residue guarantee

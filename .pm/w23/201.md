# 201 — number() of an empty inventory invents 0.00; get()/weight()/sum() blank

## Summary
`number()` on an empty inventory returns `0.00` (Decimal, in structured as
well as text) where every sibling reads empty-as-absent:
- `SELECT number(balance), weight(balance), get(balance, 'USD') FROM postings
  LIMIT 4` → row 4 (empty running balance) reads `0.00`, blank, blank.
- `SELECT number(sum(position)) FROM postings` (whole-ledger sum nets to
  empty) → structured `['0.00']`, text `0.00`.
- Controls: `weight(sum(position))` → blank; `get(sum(position), 'USD')` →
  blank (missing-currency blanks per w23/022 it.531); `sum(number) … WHERE
  FALSE` → blank (empty-set aggregates read NULL per w23/m14).

Stock offers no oracle — `number(inventory)` is an MCP-only overload (stock:
`no function matches "number(inventory)"`, same family as w23/022 it.2082's
`number(position)`) — so the case is internal consistency: three of the four
empty-tolerant readers agree on absent, and `number()` is the lone inventor.
A `0.00` where the inventory holds nothing can mislead threshold checks
(`WHERE number(balance) > 0` correctly excludes it, but `SELECT` consumers
and `= 0` comparisons see a zero that stock-conceptually is not there).

## Repro
- `call runBqlQueryStructured {"ledger":"puncsky/mcp-agent-eval","query":"SELECT number(sum(position)) FROM postings;"}` → types `[Decimal]`, rows `[['0.00']]` (value-level, not a text-render artifact — contrast w23/200's `{}`-renders-`0.00 USD` leg, where structured is honest).
- `… "SELECT number(balance), weight(balance), get(balance, 'USD') FROM postings LIMIT 4;"` → row 4 `0.00 / blank / blank`.

## Expected
Blank `number()` of an empty inventory like `get()`/`weight()` (and like
empty-set aggregates) do — or document why `number()` alone coerces empty to
zero. Owner: rustledger engine (`number()` inventory overload); upstream
report either way since the overload is MCP-only surface.

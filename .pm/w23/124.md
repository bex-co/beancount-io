# Unquoted `FROM accounts` resolves table-first on MCP vs column-first on stock (12 vs 34) — and w23/116's "stock is table-first" premise is wrong

**Severity:** major (silent wrong scope on the only dual name: every unquoted `FROM accounts` query returns 12 account rows on MCP where stock returns 34 postings-fold rows; the `WHERE date` form errors on MCP but returns 34 on stock). **Estimate:** 2–4h (restore column-first/table-fallback for the one dual name on the unquoted path + regression test against the stock oracle below). **Owner:** ledger `normalizeBqlQueryForEngine` pipeline (w23/116's fix site). **A1/A2:** agents querying `FROM accounts` get a different table than stock gives for the same text.

## Repro (production 2026-10-27 vs stock beanquery 0.2.0, API key pinned to `puncsky/mcp-agent-eval`, fixture snapshot 2817 B sha `77c3a591efd3`)

`accounts` is the ONLY dual name (live inventory: 10 stock tables, and `accounts` is the only one also a postings column):

| query | stock 0.2.0 | prod MCP |
| --- | --- | --- |
| `SELECT count(*) FROM accounts;` | `34` (column-fold) | `12` (AccountsTable) |
| `SELECT count(*) FROM accounts LIMIT 1;` | `34` (fold) | `12` (table) |
| `SELECT count(*) FROM accounts WHERE date > 2020-01-01;` | `34` (fold; postings scope) | `BAD_USER_INPUT: column 'date' not found…` (table scope) |
| `SELECT count(*) FROM "accounts" LIMIT 1;` (quoted) | `12` (pure table ref) | `12` — agrees |

Extended it.5536: the shape splits too, not just the count — `SELECT * FROM accounts LIMIT 3` returns accounts columns (`account/open/close/currencies/booking`) on MCP but postings columns (`date/flag/payee/narration/position`) with postings rows on stock.
Extended it.5538: even the QUOTED form (12 rows both) differs in shape — MCP flattens to 5 scalar columns (`open` a date, `currencies` joined `'USD'`), stock returns 3 columns with `open` as the raw Open-directive object. So quoted agrees on scope but not on projection.

So MCP is now self-consistent across clause forms (w23/116's clause-flip is gone) but consistently table-first where stock is consistently column-first — for unquoted duals the fix traded inconsistency for a steady divergence.

## The w23/116 "Resolved" premise is disproven (correction)

Done/116's Resolved note (2026-10-26) says: *"Running stock beanquery directly showed the note's stock column-first claim is wrong: stock is table-first with column-fold fallback (`FROM accounts` tables 3/12 in every form including quoted…)"*. Three independent facts contradict this:

1. Released beanquery 0.2.0 source (`compiler.py`, `_compile_from`, From branch): *"Check if the FROM expression is a column name belonging to the current table… When it is not, [treat] it as a table name"* — column-first, table-fallback, in code.
2. Beanquery `master` on GitHub (unreleased) carries the identical branch, typo included — no flip upstream.
3. Direct execution of released 0.2.0 just now (it.3280): unquoted `FROM accounts` → `34` in bare, `LIMIT`, and `WHERE` forms; only QUOTED `FROM "accounts"` → `12` (the separate `ast.Table` branch, pure table lookup).

PyPI confirms 0.2.0 is the latest beanquery release (`Available versions: 0.2.0, 0.1.0`), so no released stock behaves the way the Resolved note describes. The ORIGINAL w23/116 note's stock premise (column-first 34) was right; the "correction" inverted it. A correction appendix is appended to done/116.md with this note. (Plausible cause of the sibling's misread: testing only quoted forms — quoted is table-only on stock — and overgeneralizing to "every form".)

# 147 — File-write `CONFLICT` hints the entry lookup (`getEntryContext`/`sha256sum`) instead of the file `sha`

## Summary
A stale file `sha` on `updateLedgerFiles`/`deleteLedgerFiles` answers `CONFLICT: File conflict: main.bean changed since you read it; re-read it and retry` — then hints "`getEntryContext` returns the entry's current `sha256sum`." That lookup returns an *entry* hash, which cannot satisfy a *file* version check; the agent needs `readLedgerFiles`/`listLedgerFiles` for the file's current `sha`. Same hint-quality family as w23/143 (generic fallbacks naming lookups outside the failing family) and the exact gap w23/008 closed for creation conflicts (which now carry their own hint) — file writes never got theirs.

## Repro (prod, puncsky/mcp-agent-eval, `dry_run` — no writes)
- `updateLedgerFiles {"files":[{"path":"main.bean","content":"…","sha":"000…0"}],"dry_run":true}` → `CONFLICT: preview refused: File conflict: main.bean changed since you read it…` + the entry-`sha256sum` hint.
- `deleteLedgerFiles` with the same stale `sha`, `dry_run` → identical code/hint.
- Control: `updateEntrySource` with a stale entry `sha256sum` → `CONFLICT` with the same hint — correct there, since an entry hash is what that call needs.

## Root cause (main)
The file-write `ConflictError("File", …)` (`backend-cluster/backend-v2/src/features/ai-agent/tools/edit-ledger-files-tool.ts`, w23/039's version check) carries no custom hint, unlike creation's 008 fix (`ConflictError` with a `hint` option in `ledger-workflow.ts`), so MCP falls back to `CATEGORY_HINTS[CONFLICT]`. The throw sits in the MCP adapter; REST/GraphQL stale-`sha` paths need the parity check per the backend workflow.

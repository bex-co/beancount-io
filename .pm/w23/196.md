# 196 — BQL `balances.discrepancy` never populates (blank on failing balances; stock reports the diff)

**Severity:** moderate (silent data loss; a failing assertion's diff is invisible in BQL on all three surfaces).
**Estimate:** engine pin or service enrichment (see Root cause). **Owner:**
ledger engine/service. **A1:** agents auditing balance health via BQL.

`SELECT account, discrepancy FROM balances` returns blank `discrepancy`
even for a balance assertion that fails loudly everywhere else:

- `2026-08-30 balance Assets:Bank:Checking 999.00 USD` (true balance
  6702.01) → commit reports `Balance failed … expected 999.00 USD, got
  6702.01 USD`, but BQL reads `[["Assets:Bank:Checking", ""]]` —
  identical blank on MCP structured, REST `POST …/query`, and GraphQL
  `queryShell` (triple-verified live; shared engine + mapper).
- Stock on the identical bytes reports the diff: `Assets:Bank:Checking,,
  5703.01 USD` (CSV).
- The dtype half is already fixed on main (`discrepancy` in
  `AMOUNT_COLUMNS`, `b2772ed19`, prod still `str` pre-deploy) — this note
  is the VALUE half: no population, not a mistype.
- Root cause: the rustledger engine (`@rustledger/wasm 0.24.0`) does not
  surface the diff into the `balances` table (the mapper passes values
  through; only dtype rules touch the column). The ledger service HAS the
  figure — the journal path carries `diff_amount: balanceDiff ?? null`
  "from the validator (w21/087)"
  (`ledger-shell` `ledger-legacy-journal.ts:148`) — so BQL is the lone
  blind surface.
- Fix: populate `discrepancy` from the validator diff (upstream engine
  fix, or service-side enrichment of the BQL table like the journal);
  pin with a failing-balance live test asserting the diff value, not
  just the dtype.
- QA ledger untouched net (disposable failing balance committed, read,
  full-content restored; byte-identical f1a0b83c/size 2817 + `cmp` +
  stock `bean-check` + MCP `checkLedger` clean after).

`entries-count` leaves out the price directives that managed price includes supply, while `listLedgerEntries`, the journal and BQL count them, and neither the customer contract nor the published description says so. Repro (production, 2026-11-11, read-only, public synthetic ledger `puncsky/example`, which has `include "https://beancount.io/prices/BTCUSD"`): `beancount://puncsky/example/entries-count` returns Price 846 and a sum of 2064 over the twelve types (`GET …/entries-count` on REST is identical); `listLedgerEntries {directiveTypes:["price"]}` reports `total: 936`, `SELECT count(*) FROM #prices` returns 936, and an unfiltered `listLedgerEntries` reports `total: 2154`. The 90 missing entries are the managed feed, excluded on purpose (`backend-cluster/ledger/src/features/ledger/service/ledger-data-service.ts` `getEntriesCountPerType`, ADR 015 section 9: the dashboard sums this report as the tier-usage counter, so a feed never consumes the directive allowance). Every other type agrees with `listLedgerEntries` and BQL (Balance 82, Open 63, Transaction 1050, and so on).

The gap is wording only. The resource description reads "How many transactions, opens, balances, and so on the ledger holds." (`analysis-handler.ts:322`, repeated in the MCP template and the OpenAPI route), and the `entries-count` paragraph of `docs/mcp.md` (the Time filters sentence) never mentions managed prices, so an agent that reconciles "how many entries does this ledger have" between `entries-count` and the journal total finds two answers 90 apart and has no stated reason.

Fix, sub-hour: say in the description and in `docs/mcp.md` that managed price feed directives are excluded (it is the count the plan limit uses), that `listLedgerEntries` and BQL include them, and give the GraphQL field `getLedgerEntriesCountPerType` the same sentence; add a test that the published description names the exclusion so it cannot drift from the code comment.

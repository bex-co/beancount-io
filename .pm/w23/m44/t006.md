## Objective

Make sure a host whose model cannot read resources on its own can still finish every playbook the server serves.

## Context

- `backend-cluster/backend-v2/src/server/api/op-class.ts` lists 14 operations reachable on MCP only as resources. Among them are `pullRequestDetails` (read before merge/reject), `ledgerCollaborators` (read before set/remove), `bankSuggestedCategories` and `bankSuggestedMapping`. Ledger reads such as `trial-balance`, `holdings`, statements and commits are also resource-only, and most of those have a BQL or `checkLedger` route.
- `docs/mcp.md` says ChatGPT calls tools only and that every id a tool argument needs is returned by another tool. ADR 0008 D2 keeps bank reads as resources by design.
- The served prompts (`backend-cluster/backend-v2/src/features/ai-agent/api/mcp-prompts.ts`) tell the agent to read `…/bank-transactions/suggested-categories` (no tool twin) and the spending report tells it to read `…/errors` without naming `checkLedger`.

## Steps

1. In every prompt, name a tool for each resource it points at, or say how to continue without it.
2. If t001 found that claude.ai's model cannot read resources unprompted, add tool twins for the resource-only reads a write workflow depends on: pull-request details, the collaborator list, and the suggested categories. Give each twin REST/GraphQL/MCP parity, and amend ADR 0008 D2 with the reason.
3. If t001 found that it can, record that and limit this task to step 1.

## Files

## Acceptance criteria

- [ ] Every `beancount://` URI in a served prompt sits beside a named tool or an explicit way to continue without it.
- [ ] Any added tool passes the parity zero-debt gate and the output-schema conformance test.

## Out of scope

- Reads that BQL already answers.

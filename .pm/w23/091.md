# `deleteLedgerFiles` deletes a file that is still `include`d, breaking the ledger; rename refuses the same thing

**Severity:** minor (loud failure — `checkLedger` reports a `LOAD` error with file and line — and recovery is one edit; but one removal path guards includes and the other does not). **Estimate:** 1–3 hours incl. parity. **Owner:** `backend-cluster/backend-v2`, ledger workflow (delete path) + REST/GraphQL counterparts. **A1/A2:** agents deleting a split-out file leave the ledger unloadable where a rename would have been refused with guidance.

## Repro (production, 2026-10-26, API key pinned to `puncsky/mcp-agent-eval`)

Multi-file setup on the disposable QA ledger: created `q-inc/second.bean` (one transaction), added `include "q-inc/second.bean"` to `main.bean` → 30 entries, `checkLedger` clean. Renamed with `updateIncludes: true` → include rewritten, still 30. Then:

- `renameLedgerFile {oldPath: "q-inc/renamed.bean", newPath: "q-inc/second.bean", updateIncludes: false}` → refused: `BAD_USER_INPUT: q-inc/renamed.bean is still included by main.bean; pass updateIncludes: true to rewrite it in the same commit` ✓
- `deleteLedgerFiles {files: [{path: "q-inc/renamed.bean"}]}` → success — the ledger now fails to load: `checkLedger` reports `LOAD` `Included file not found: q-inc/renamed.bean` (`main.bean:8`), and reads degrade (30 → 29 entries).

Restored `main.bean` byte-identical from snapshot afterward; `checkLedger` clean, no residue.

## Fix (keep REST/GraphQL/MCP in parity)

Mirror the rename guard on the delete path: refuse to delete a file still included by another ledger file, naming the includers — or accept an `updateIncludes`-style flag that comments out / removes the include lines in the same commit. Document the rule next to the rename rule in `docs/mcp.md`.

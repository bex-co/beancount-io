# 220 — A NUL byte in a file-tool commit message (`message` / `description`) answers `SERVICE_UNAVAILABLE` on commit, while `dry_run` accepts it

**Severity:** minor. **Owner:** `backend-cluster/backend-v2` (REST, GraphQL, MCP). **Estimate:** ~30m. **Pillar:** A1. Sibling of [w23/218](./218.md) and the same class as [w23/210](./done/210.md); best done together with 218 as one NUL sweep.

Found by `qa-find-bugs-mcp` on 2026-11-05 against production (`beancount-mcp` 1.0.0, protocol `2025-11-25`, local HEAD `d403925d6`, read/write key, synthetic ledger `<owner>/mcp-agent-eval`). Nothing was committed; `listLedgerFiles` showed only `main.bean` afterward.

## Repro

- MCP `createLedgerFiles {"ledger":"<o>/<n>","message":"qa a\u0000b","files":[{"path":"qa-x.bean","content":"; x\n"}]}` → `isError`, `SERVICE_UNAVAILABLE` "commit failed: Ledger API is temporarily unavailable", hint "A dependency is down. Retry with backoff". The `description` alias answers the same.
- REST `PUT /api-gateway/v1/ledgers/<o>/<n>/files/qa-x.bean {"content":"; x\n","message":"qa a\u0000b"}` → `503 SERVICE_UNAVAILABLE` "Ledger API is temporarily unavailable".
- The same MCP call with `dry_run: true` → success preview ("Dry run: 1 change(s) previewed"), so the preview promises a commit that then fails. The retry hint is also wrong: the request itself is the problem.
- Controls: a NUL in the file path → `BAD_USER_INPUT` "Invalid file path". A NUL in file content commits and reads back (`; a\u0000b`), so only the message is affected.

## Expected

`BAD_USER_INPUT` naming `message` / `description`, on preview and commit, on REST, GraphQL and MCP.

## Fix

`assertNoNul` (`src/shared/assert-no-nul.ts`, w23/210) has no caller on the commit-message path. Apply it where `src/features/ledger/utils/commit-message-alias.ts` resolves the message, so every tool taking `message` / `description` is covered (`createLedgerFiles`, `updateLedgerFiles`, `deleteLedgerFiles`, `renameLedgerFile`, `updateEntrySource`, `deleteEntrySource(s)`, `createPullRequest`), with a regression test per tool.

## Dedupe and unverified

w23/210 listed other git-host free-text parameters as unverified; w23/218 covers bank ids only. `updateLedgerFiles`, `deleteLedgerFiles`, `renameLedgerFile` and the PR tools with a NUL message were not exercised. The cause (git cannot store U+0000 in a commit message) is assumed from 210.

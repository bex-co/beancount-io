# Bank tool arguments mix `snake_case` and `camelCase` with no alias

**Severity:** minor (strict schemas reject the sibling spelling; agents guess wrong and retry). **Estimate:** 1–2 hours incl. parity. **Owner:** `backend-cluster/backend-v2`, bank tools + REST/GraphQL counterparts. **A1/A2:** agents drive bank sync/import; one tool spelling `accountId` where its siblings spell `account_id`/`item_id` is a guaranteed retry loop.

## Repro (production, 2026-10-26, API key pinned to `puncsky/mcp-agent-eval`)

Schemas via `tools/list`, refusals verified live (bogus ids, no state changed):

| tool | accepted id arg | sibling spelling |
| --- | --- | --- |
| `syncBankTransactions` / `refreshBankConnection` / `unlinkBankConnection` / `reconcileBankAccounts` | `item_id` (snake) | `itemId` → `BAD_USER_INPUT: Unrecognized key` |
| `mapBankAccount` | `account_id` (snake) | `accountId` → `BAD_USER_INPUT: Unrecognized key` |
| `importStagedBankTransactions` / `discardStagedBankTransactions` | `transaction_ids` / `transactions` (snake) | — |
| `listStagedBankTransactions` | `accountId` (**camel**) | `account_id` → `BAD_USER_INPUT: Unrecognized key` |

So the bank family is snake_case everywhere except `listStagedBankTransactions`, which is camelCase — and neither side aliases the other (all strict `Unrecognized key` refusals).

Deeper split (it.1264): `importStagedBankTransactions` takes `transactions` while `discardStagedBankTransactions` takes `transaction_ids` — same concept, different names, both snake. So even a full camelCase alias pass leaves the pair inconsistent (`transactions` vs `transactionIds`); the fix should converge on one name (plus alias) across both tools, not just per-tool case aliases. The same split exists on REST (`BankTransactionSubmission.transactions` vs `BankTransactionDiscard.transactionIds`, OpenAPI-verified it.1265) and GraphQL (`submitPlaidTransactionsToLedger.transactions` vs `deletePlaidTransactions.transactionIds`, introspected it.1267) — consistent across all three surfaces, so the convergence fix spans all three.

## Fix (keep REST/GraphQL/MCP in parity)

Accept both spellings as aliases on MCP (same alias pattern as w23/m3 (done) established for entry tools).

**Cross-surface correction 2026-10-26** (it.751): the live OpenAPI + GraphQL schemas show REST and GraphQL use camelCase bank ids exclusively (`{itemId}` path params, `accountId` query params, `itemId`/`accountId`/`plaidItemId` GQL args — zero snake_case). So MCP's snake_case seven are the cross-surface outliers, and `listStagedBankTransactions`' camelCase `accountId` is the one MCP tool that already matches REST/GraphQL. Alias toward camelCase (`item_id` → `itemId`, `account_id` → `accountId`), not the reverse — renaming `accountId` to snake would move the conforming tool away from both sibling surfaces.

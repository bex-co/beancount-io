# Resource templates mark required params `{?...}` (optional) but refuse bare URIs

**Severity:** minor (refusals name the missing param, so agents recover in one retry; still, every template lies about optionality). **Estimate:** 1–2h (template or validation change + docs). **Owner:** `backend-cluster/backend-v2`, resource templates. **A1/A2:** agents read `resources/templates/list` and try the advertised bare URI first.

## Repro (production, 2026-10-26, API key pinned to `puncsky/mcp-agent-eval`)

Templates use RFC 6570 `{?param}` (optional query expansion), but most such params are effectively required — the bare URI refuses:

| bare URI | result |
| --- | --- |
| `beancount://{owner}/{name}/pull-request` | `BAD_USER_INPUT: prNumber: Invalid input: expected number, received NaN` |
| `beancount://{owner}/{name}/commit-details` | `BAD_USER_INPUT: sha: Invalid input: expected string, received undefined` |
| `beancount://social/profile` | `BAD_USER_INPUT: username: Invalid input: expected string, received undefined` |
| `beancount://{owner}/{name}/collaborators/permission` | `BAD_USER_INPUT: collaborator: …` |
| `beancount://assets/download-url` | `BAD_USER_INPUT: ledgerRepoId: …` |
| `beancount://temp-assets/download-url` | `BAD_USER_INPUT: objectKey: …` |
| `beancount://{owner}/{name}/import/suggest-categories` | `BAD_USER_INPUT: transactions: …` |

Controls that genuinely work bare: `journal`, `commits`, `accounts`, `payees`, `errors`, `metadata`, `source-files`, `collaborators`, `latest-commit`, `configuration/*`, `archive-download-url`. So `{?...}` on this server means "query string", not "optional" — a dialect mismatch with RFC 6570, not a validation bug.

## Fix (MCP-internal; no REST/GraphQL surface has URI templates)

Pick one: (a) document in `docs/mcp.md` that `{?...}` params may still be required and the refusal names them; (b) split templates so required params are path segments or separate listings exist (e.g. a bare `pull-request` that lists PRs); or (c) annotate required-ness in `resources/templates/list` metadata if the SDK supports it. (a) is the 30-minute version; (b) is the real fix for `pull-request` (no list operation exists anywhere on MCP — `merge/rejectPullRequest` need a number agents cannot discover).

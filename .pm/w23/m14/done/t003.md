## Objective

All-null and empty columns report their natural dtype (`sum`→numeric, `int(NULL)`→int, `last(payee)`→str) instead of the `str` fallback, on every surface.

## Context

- t001's map defines the target dtype per case; t002's null rendering is in place.
- Classifier: `classifyColumnDtype` + `dtypeFromColumnName` in `backend-cluster/ledger/src/features/ledger/service/ledger-shell-mappers.ts`. rustledger exposes no cursor schema, so the fix is inference (expression shape, cast target, column name) — not a lookup that does not exist.

## Steps

1. Propagate natural dtypes for null/empty columns per t001's contract.
2. Keep the name fallback for genuinely unknowable columns; document which those are.
3. Pin break-verified tests per dtype case.

## Resolved 2026-10-28

Re-probed every t001 dtype case through the live engine and mapper at HEAD. Unaliased cases already held through earlier shipped work (static expression typing, w23/164 and siblings): `sum`/`min` over an empty filter → `Decimal`, `max(date)` → `date`, `first`/`last(payee)` → `str`, `count(*)` → `int`, `int/decimal/bool/str(NULL)` → `int/Decimal/bool/str`, `year/month/day(NULL)` → `int`, `quarter(NULL)` → `str` (stock's quarter is a string). The gap that remained was an *aliased* computed column (`sum(number) AS total` over no rows reported `unknown`). Fixed in `fec84861e` (`backend-cluster/ledger`): the alias's head text is kept (`extractSelectAliasHeads`) and a computed head reports its static type; a bare-column head still reports `unknown` (alias may shadow a lookalike, w23/134), and values win whenever any cell is non-NULL. Genuinely unknowable columns (bare-column alias, `NULL AS n`) keep `unknown`. Nine unit cases (the suite does not compile without the mapper change) plus two live `verify:rustledger` dtype pins.

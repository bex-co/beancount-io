# The temp-asset object key has three spellings: `receiptObjectKey`, `objectKey`, `s3ObjectKey`

**Severity:** minor (strict schemas; agents doing receipt/import flows guess wrong twice before landing). **Estimate:** 1–2 hours incl. parity. **Owner:** `backend-cluster/backend-v2`, receipt/import tools + REST/GraphQL counterparts. **A1/A2:** the upload→parse→insert chain passes one key through three tools that each spell it differently.

## Repro (production, 2026-10-26, API key pinned to `puncsky/mcp-agent-eval`)

Schemas via `tools/list`, strictness verified live with bogus keys (all refuse before any state change):

| tool | key arg | sibling spelling |
| --- | --- | --- |
| `insertReceiptTransaction` | `receiptObjectKey` | — |
| `parseReceipt` | `objectKey` | `s3ObjectKey` → `BAD_USER_INPUT: Unrecognized key` |
| `parseFile` | `s3ObjectKey` | `objectKey` → `BAD_USER_INPUT: Unrecognized key` |

(The `temp-assets/download-url` resource uses `objectKey`, matching `parseReceipt`.) All three name the same caller-owned `tmp/…` key minted by `generateTempAssetUploadUrl`, and none aliases the others.

## Fix (keep REST/GraphQL/MCP in parity)

Accept a single canonical spelling plus aliases on every surface (e.g. `objectKey` everywhere with `s3ObjectKey`/`receiptObjectKey` aliased), following the w23/m3 (done) alias pattern — do not break existing callers by renaming without an alias. Document in `docs/mcp.md`.

**Cross-surface scoping 2026-10-26** (it.754): the live OpenAPI + GraphQL schemas show all three spellings on both sibling surfaces too (REST: `receiptObjectKey`×2, `objectKey`×4, `s3ObjectKey`×4; GraphQL: ×1/×2/×2). Same three-way split everywhere — the canonical choice + aliases must land identically on all three surfaces.

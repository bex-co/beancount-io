## Objective

Make the file-mutation tools accept one commit-message spelling everywhere — alias, not rename — on REST, GraphQL, and MCP, and document which tools compose their own message.

## Context

- Note: `w23/090` (promoted to this milestone). The note's repro: `createLedgerFiles` / `updateLedgerFiles` / `deleteLedgerFiles` take `description`; `renameLedgerFile` takes `message` (passing `description` → `Unrecognized key: "description"`); `addLedgerEntries`, `appendLedgerText`, and the entry-source tools take neither (server-composed message).
- Prefer aliasing both names on the four file tools. If both are passed with different values, refuse rather than guess.

## Steps

1. Accept both `description` and `message` on the four file tools (MCP schemas, REST handlers, GraphQL inputs).
2. Decide and pin the both-passed behavior (refuse on conflict).
3. Record which tools compose their own message and why (feeds t003's docs).
4. Add cross-surface parity tests for both spellings.
5. Run the backend-v2 gates; regenerate OpenAPI if a description changed.

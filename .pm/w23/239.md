`plaintext-journal` holds only a ledger's transactions, balance assertions and pads, but nothing the customer reads says so, and `docs/mcp.md` calls it "the export the dashboard downloads". Repro (production `beancount-mcp 1.0.0`, 2026-11-11, read-only, the synthetic `puncsky/example`, REST `GET /api-gateway/v1/ledgers/puncsky/example/plaintext-journal` with no `limit`, which returns every entry): the response is `total: 1132`, `truncated: false`; the unfiltered journal (`listLedgerEntries`) reports `total: 2154`. The 1132 are exactly the 1050 transactions and 82 `balance` assertions. Missing from the export: 63 `open` (the file carries `plugin "beancount.plugins.auto_accounts"` instead, so stock beancount loads 60 generated opens), 10 `commodity`, 846 `price` (936 on the journal, 90 of them the managed feed), 9 `event`, 3 `custom` and 1 `close`. A third count disagrees as well: `entries-count` sums to 2064 (`w23/236`).

The scope is deliberate: `plaintextExportDirectives` (`backend-cluster/ledger/src/features/ledger/service/ledger-journal-service.ts:305`) keeps transactions, balances and pads, and the dashboard's Export journal button uses it. Inside that scope it is faithful: loading the export and the source `main.bean` with stock beancount 3.2.3 `loader` gives 1132 transaction and balance entries whose canonical `format_entry` text is identical in both directions, and the export loads with 0 errors. The gap is that the published text hides the scope: the REST and MCP description is "Read Beancount journal text with account, time, and expression filters" (`docs/openapi/v1.json`, the MCP template), the GraphQL field's is "Get plaintext journal in beancount format" (`ledger-journal-resolver.query.ts:311`), and the `docs/mcp.md` plaintext paragraph describes paging and `total` ("the entries the filters select") without naming what is left out. An agent or a person who takes it for a copy of the ledger, as `w23/044` read it ("the whole ledger's text"), loses prices (so every market valuation), commodity declarations, events, custom directives, closes and the real open dates.

Fix, sub-hour: state the contents in the description on all three surfaces and in `docs/mcp.md` ("transactions, balance assertions and pads only; read the source files with `readLedgerFiles`, or the archive, for a full copy"), and add a test that pins the description to `plaintextExportDirectives`. Whether the export should carry the other directive types is an owner decision, not part of this note.

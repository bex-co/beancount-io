# BQL names a boolean-literal column `true` where stock beanquery 0.2.0 keeps the source spelling `TRUE`

**Severity:** cosmetic (header text only; values and dtype agree). **Owner:** `backend-cluster/ledger` (column naming for literal projections). **Estimate:** 30m. **Pillar:** A1.

Found by the w23/m20 oracle replay, query id `empty-literals`: `SELECT 1, 'a', 1.5, TRUE, NULL WHERE FALSE` names its fourth column `true`; stock names it `TRUE`. A client that selects by header text breaks when it copies the spelling it wrote.

Decide whether the engine should echo the source spelling (`TRUE`, `True`, `true`) as stock does, or document the lowercase header.

The same query also differs in the dtype of `NULL` (`str` here, `NoneType` in stock); that one is the deliberate neutral marker recorded in `w23/done/134.md`, so only the header is open here.

Once resolved, drop the `columns` difference from the `empty-literals` entry in `backend-cluster/ledger/scripts/bql-oracle/allowlist.json`.

# On a new ledger, `appendLedgerText` puts the first transactions above the template's `* Transactions` heading, unlike `addLedgerEntries`

**Severity:** minor (layout only; balances are unaffected). **Estimate:** 30 minutes. **Owner:** `backend-cluster/backend-v2` `DirectiveAppendWorkflow` (date-ordered insertion for `appendLedgerText`) versus the bulk entry writer behind `addLedgerEntries`. Both are shared by REST, GraphQL and MCP. **A2:** the starter ledger's org sections (`* Options`, `* Accounts`, `* Transactions`) are what a newcomer opens in Fava, an editor, or the dashboard's file view. After an agent's first writes, transactions sit inside `* Accounts` and `* Transactions` is an empty heading at the bottom.

## Repro (production, 2026-10-22, fresh `qa-` ledgers from the default template, since deleted)

1. `appendLedgerText` with a 2021-06-01 transaction, then `addLedgerEntries` with a 2021-07-01 one. The file then reads (directive and heading lines only):

   ```
   1970-01-01 open Equity:Initial
   2021-06-01 * "via-append"
   * Transactions
   2021-07-01 * "via-add"
   ```

2. Seven appends in mixed date order, with a tie, all land in correct date order, and all of them above `* Transactions`.

## Cause

Date-ordered insertion places new text right after the last directive dated on or before it. On a template ledger that is the last `1970-01-01 open`, which sits before the `* Transactions` heading. The bulk writer evidently appends after the heading when no later directive exists. The two writers disagree on the same input.

## Fix

Use one placement rule for both writers. When the insertion point is followed only by blank lines and org headings (`^\*+ `) before the next directive or the end of the file, insert after those headings. Equivalently, a transaction goes under the last heading that precedes the following directive. Tests: the first append and the first add on a template ledger both land under `* Transactions`; ordering among existing transactions is unchanged; a ledger without headings is unchanged.

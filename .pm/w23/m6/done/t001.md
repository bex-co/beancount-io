## Layer map (2026-10-26)

The typed path is four layers: backend-v2 input schemas → Fava IDL contract (`Posting` etc.) → ledger `LedgerEntryInput`/`toDirective` → `directiveToText` over engine `DirectiveJson`. Evidence per gap:

| Gap | Fava IDL | Ledger input/map | `directiveToText` | Engine type |
|---|---|---|---|---|
| posting cost | ✅ `Cost` | ❌ add | ✅ renders `{…}` | ✅ all-optional |
| total price `@@` | ❌ add | ❌ add | ❌ add branch | ❌ render-side extension only |
| posting meta | ✅ | ❌ add | ✅ | ✅ |
| posting tags/links | ❌ add | ❌ add | ❌ add | ❌ render-side extension only |
| open booking | ❌ add | ❌ add | ✅ | ✅ |
| balance tolerance | ❌ add | ❌ add | ✅ (`~`) | ✅ |
| pad | ❌ add variant | ❌ add case | ✅ | ✅ |

Notes for implementers:

- Total price and posting tags/links have no engine representation (price is a bare `AmountValue`; `PostingJson` has no tags). Both are still implementable in-repo: the IDL gains the fields, `toDirective` carries them on a render-side extension of the posting shape, and `directiveToText` (ours) renders `@@` / `#tag` / `^link`. The built `DirectiveJson` is render-intermediate only — projections bean-check the appended text, so the engine never sees the extension.
- Cost date: Fava marks it required, but the engine takes it optional and beancount allows dateless `{100 USD}`. Recommend the typed API accept date-optional cost and omit it on the wire when absent (never default it to the txn date — that changes booking meaning).
- Cost validation: refuse cost-without-units at the API (mirror the price rule, w23/079) and run cost numbers through the decimal validators; the projected engine check refuses exotic misuse (same-currency cost etc.) with real errors.
- The note's repro (`cost: {number, currency}`, no date) must commit under the recommended design.

The t002/t003/t009/t010 split stands: cost, then meta/tags/links, then booking/tolerance, then total-price/pad — each a vertical slice through the layers above, sequenced through the shared renderer and schema files.

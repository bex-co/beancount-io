# 144 — `holdings` echoes `group_by` but refuses it as input (output snake, input camel)

## Summary
Same paste-split class as w23/141, on the holdings analysis read: `holdings?groupBy=account` answers with `"group_by":"account"` in the payload, but sending the echoed spelling back — `holdings?group_by=account` — fails with `-32602 BAD_USER_INPUT: Unknown or repeated resource parameter: group_by` ("This resource accepts `account`, `conversion`, `groupBy`"). An agent copying the output's grouping key into a follow-up call burns a turn. The rest of the payload (`cost_basis`, `market_value`, `missing_prices`, `as_of`) is snake_case too, but those are output-only — only `groupBy`/`group_by` forms an input/output loop.

## Repro (prod, puncsky/mcp-agent-eval, read-only)
- `read beancount://puncsky/mcp-agent-eval/holdings?groupBy=account` → 200, `{"group_by":"account","groups":[],...}`.
- `read beancount://puncsky/mcp-agent-eval/holdings?group_by=account` → `-32602 BAD_USER_INPUT: Unknown or repeated resource parameter: group_by`.

## Root cause (main)
The holdings `query` schema (`backend-cluster/backend-v2/src/features/ledger/api/rest/v1/analysis-handler.ts`) declares only `groupBy` (strict); the `group_by` echo comes from downstream (`ledgerFinance.getHoldings` → ledger-service fava passthrough). MCP and REST share the seam, so both refuse `group_by` identically — all surfaces consistent, all split the same way.

## Expected
Accept `group_by` as an alias (the m10 account-journal twin pattern: `filter_account`/`filterAccount`, `with_children`/`withChildren`, both verified live), or normalize the echo; one rule documented. Sub-hour: alias + parity test.

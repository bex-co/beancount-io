The `private: false` preview on the API surfaces warns only "This would make the ledger public, readable by anyone.", while the dashboard's confirmation (w3/633) tells the owner that "anyone with the link, and search engines, will be able to see this ledger's transactions, balances, files and history". The preview is the one confirmation step an agent has before it flips a ledger's visibility for a user, so it is the sentence the agent will show. Repro (production `beancount-mcp 1.0.0`, 2026-11-11, read/write key, disposable `puncsky/mcp-agent-eval`, `dry_run` only so nothing changed): `updateLedger { ledger, private: false, dry_run: true }` returns `preview.warnings: ["This would make the ledger public, readable by anyone."]` and `private: { from: true, to: false }`; REST `PUT /api-gateway/v1/ledgers/{owner}/{name}` with `dry_run: true` returns the same warning, and all three surfaces build it in one place (`backend-cluster/backend-v2/src/features/ledger/workflow/ledger-workflow.ts:207`; the field descriptions at `ledger-resolver.types.ts:362` and `:411` say "readable by anyone" too). Dashboard text: `dashboard/src/features/ledger-data/settings/visibility-section/locales/en.ts:14`.

Why the missing half matters: a private ledger's git history is public with it. Commit metadata is not redacted by the service (`commits-service.ts:326`, `ledger-repo-service.ts:219` pass `author.email` and `committer.email` through), and on three third-party public ledgers sampled with a different account (counts only, no address recorded) all 12 of the most recent commits carried an author email that is not a noreply address, 2 of them on free-mail domains; `commits` and `commit-details` return them to any reader with read access. Exposing commit authorship is normal for a public git repository, but an owner who hears only "readable by anyone" does not learn that every earlier version of every file, including entries since deleted, and the name and email on every commit, are readable as well, and a user who confirmed through an agent never saw the dashboard's sentence.

Fix, sub-hour: put the dashboard's content in the API warning (and the two descriptions): the ledger's transactions, balances, files and full commit history, with each commit's author name and email, become readable by anyone with the link and by search engines; keep one source for the sentence so the three surfaces cannot drift, and test that the warning names the history. Whether the service should hide commit emails on public ledgers is a separate owner decision, not part of this note.

# 137 — Ledger `permissions` report the user's repo access, not the credential's effective scopes (it.6059-6061)

## Summary
`permissions: {admin, pull, push}` on the ledger metadata answers the wrong question: it reflects the token owner's repository access, not what the calling credential may do. A `ledger.read`-only credential sees `admin:true, pull:true, push:true` on all three surfaces — while `listBankConnections` answers `FORBIDDEN` "requires the `ledger.admin` scope" and `addLedgerEntries` (even `dry_run`) answers `FORBIDDEN` "requires the `ledger.write` scope" for that same credential. Worse, those `FORBIDDEN` hints tell the agent to "Check `beancount://{owner}/{name}/metadata` for your permission on the ledger" — the resource that just lied to it. An agent following the hint concludes it has admin and retries, or reports a permissions bug that does not exist.

## Repro (prod, puncsky/mcp-agent-eval, read-only credential)
- MCP `read beancount://puncsky/mcp-agent-eval/metadata` → `permissions: {admin:true, pull:true, push:true}`.
- REST `GET /api-gateway/v1/ledgers/puncsky/mcp-agent-eval` → same `permissions` object, byte-identical envelope.
- GraphQL `getLedger(ledgerId){ permissions{ admin pull push } }` → `{admin:true, pull:true, push:true}`.
- Same credential: `listBankConnections {}` → `FORBIDDEN` "requires the `ledger.admin` scope"; `addLedgerEntries {dry_run:true, …}` → `FORBIDDEN` "requires the `ledger.write` scope"; `runBqlQueryStructured` reads fine (34).
- The full-scope credential sees the identical `permissions` object — the field does not vary with the caller at all.

## Expected
One of: (a) `permissions` reflects effective access (user's repo rights ∩ credential scopes), so a read-only caller sees `admin:false, push:false`; or (b) the `FORBIDDEN` hints stop directing agents to `metadata` for "your permission" and instead name the missing scope (they already do — the hint's second half is the lie). Option (a) fixes the data; option (b) fixes the pointer. Doing neither leaves a self-contradicting auth story on all three surfaces.

# 179 — `GROUP BY balance` silently collapses every inventory into one group

## Summary
Grouping by an inventory column returns a single group keyed by the first row's balance with the whole-table count — a silent wrong result, not a refusal. `SELECT balance, count(*) GROUP BY balance;` over 34 postings with distinct balances returns one row (`3000.00 USD`, 34) on MCP, REST, and GraphQL alike. Stock refuses the query (`GROUP-BY a non-hashable type is not supported`), which is the honest answer. Sibling amount-bearing keys group correctly on MCP (`position`, `weight`, `number` all split into distinct groups), so only the inventory key hash is broken.

## Repro (prod, puncsky/mcp-agent-eval; stock = beanquery 0.2.0 on the byte-identical fixture)
- `SELECT balance, count(*) GROUP BY balance;` → MCP/REST/GraphQL: one row `[{"USD":"3000.00"}, 34]` (structured `rowCount: 1`). Stock: `CompilationError: GROUP-BY a non-hashable type is not supported: "Column(name='balance')"`.
- Narrowed: `Assets:Cash` has 5 distinct balances (200.00/140.00/133.25/73.25/49.75 USD) but `... WHERE account = 'Assets:Cash' GROUP BY balance` returns one row (`200.00 USD`, 5) — the collapse key is the first row's balance.
- Controls that group correctly on MCP: `GROUP BY position`, `GROUP BY weight`, `GROUP BY number` (distinct groups, count 1 each). `GROUP BY tags` also returns one group but is correct there (all tags empty, it.3958).

## Root cause
Grouping executes inside the pinned `@rustledger/wasm` 0.24.0 engine; the JS layer only guards GROUP-BY *coverage* (`backend-cluster/ledger/src/foundation/rustledger/group-by-coverage-guard.ts`, the w23/131 bare-column refusal) and rewrites known gap messages (`ENGINE_GAPS` in `backend-cluster/ledger/src/features/ledger/service/ledger-shell-service.ts:183`). Neither touches key hashing, so the engine's inventory key hash — one bucket for every `Inventory` — reaches all three surfaces unchanged. Stock's refusal shows the upstream-expected behavior for unhashable keys.

## Fix
1. Short term (ledger service): refuse `GROUP BY` over inventory-typed keys with stock's message (`GROUP-BY a non-hashable type is not supported`), via a guard in the `group-by-coverage-guard.ts` family — a loud refusal beats a wrong count. Extend the guard's text analysis to flag `balance`/`account_balance` (the postings inventory columns) as keys, or check the engine's returned dtype.
2. Long term (engine): hash inventories by value so the groups split, matching `position`/`weight`/`number`.
3. Add a `verify-rustledger.ts` live check (`GROUP BY balance` refuses or splits) so an engine bump retires the guard, per the `ENGINE_GAPS` convention.

Parity note: all three surfaces share the engine result today, so the fix lands in one place and propagates. Owner: `backend-cluster/ledger`. Estimate: ~45m for the guard + tests.

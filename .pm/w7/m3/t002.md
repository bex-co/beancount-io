## Objective

Add `Mutation.confirmStorePurchase` for `APP_STORE` (D7): verify the signed transaction with Apple's App Store Server Library (bundle ID, environment, catalog product, and token owner), read current state from the App Store Server API when needed, and upsert the row in one transaction. Accept sandbox evidence and record it (D8). Store a purchase without a known token unclaimed and let the first signed-in account that presents it claim it; refuse one owned by another account with a typed conflict that carries the owner's masked email (D9).

## Context

- Milestone: [w7/m3](./README.md). Design: [ADR 001](../../../docs/adrs/ADR001-mobile-billing.md). Package: `backend-cluster/backend-v2/` (see `backend-cluster/backend-v2/AGENTS.md`; follow its Required API parity workflow).
- Adds a dependency: get the user's approval first (root `AGENTS.md`), and install it with the package's own package manager, never by editing the lockfile. Candidate: Apple's App Store Server Library for Node.
- The In-App Purchase key comes from the environment (m2/t002). Tokens, signed transactions, and keys are never logged.
- Record redacted sandbox fixtures once the m2 products exist.

## Steps

1. Add the verifier and the upsert.
2. Handle unclaimed and conflicting purchases.
3. Register the verb as in t001.

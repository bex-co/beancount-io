# The ledger service's repository-size limit is never enforced

`assert-repo-size-within-limit.ts` reads `maxRepoSizeKb` from backend-v2's `/api/admin/ledger-limits/{ledgerUsername}`, but backend-v2 never returns that field (it appears nowhere under `backend-cluster/backend-v2`), so the check treats every owner as unlimited. Each append still makes the call, and backend-v2 answers it through `getUserTier`, which costs a Stripe payer a full subscription list. Decide whether a plan sets this limit: either return the field, or delete the check and its call. Found by the w7/m1/t008 review.

**Blocked 2026-11-01** — this is a product decision: enforcing a repository-size limit could refuse writes on ledgers that pass today, and deleting the check gives the idea up. **Unblock:** the owner chooses whether a plan sets this limit. Who can clear it: the owner.

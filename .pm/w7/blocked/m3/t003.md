## Objective

Add one REST callback for production and sandbox notifications. It verifies the signed payload, records the event in `store_billing_events` idempotently, re-reads the subscription, and maps renewals, renewal-preference changes (`pending_product_id`), billing retry, grace, expiry, refund, and revocation (`revoked_at`, D11) to the normalized status.

## Context

- Milestone: [w7/m3](./README.md). Design: [ADR 001](../../../docs/adrs/ADR001-mobile-billing.md). Package: `backend-cluster/backend-v2/` (see `backend-cluster/backend-v2/AGENTS.md`; follow its Required API parity workflow).
- Public provider callbacks are listed in `backend-cluster/backend-v2/src/server/api/always-public.ts` (see the Stripe webhook entries) and wired in `composition-root.ts`.
- Notifications only trigger a re-read; they are never trusted as state (D3).

## Steps

1. Add the route and register it as a provider callback.
2. Map each notification type through a re-read.
3. Store raw payloads only redacted.

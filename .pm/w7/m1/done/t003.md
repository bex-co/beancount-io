## Objective

`getUserTier` returns the highest of the Stripe tier and the tiers of the user's granting store rows (D3). The merge runs after the Stripe read and its cached fallback have finished, and the Stripe-only cache is never written with the merged tier.

## Context

- Milestone: [w7/m1](./README.md). Design: [ADR 001](../../../docs/adrs/ADR001-mobile-billing.md). Package: `backend-cluster/backend-v2/` (see `backend-cluster/backend-v2/AGENTS.md`; follow its Required API parity workflow).
- `backend-cluster/backend-v2/src/features/stripe/operations/get-user-tier.ts`: a non-transient Stripe error returns Free from inside its `try`, which must not hide a store plan.
- `paid_customers.period_tier` is written only by `backend-cluster/backend-v2/src/features/stripe/operations/refresh-subscription-periods.ts`.
- Callers include ledger creation, collaborators, the entry-limit lookup, AI usage, the account profile, and API-key creation; none changes.

## Steps

1. Compute the Stripe tier, including its fallback, first.
2. Read the user's granting store rows; a failed read logs and keeps the Stripe tier.
3. Return the highest tier.

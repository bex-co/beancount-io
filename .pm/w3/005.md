# Income Statement links its Net Profit summary to a nonexistent account

**Severity:** minor. **Estimate:** 35–50m including a focused regression; keep
this as an inbox item. **Pillar:** A2 — public-example report exploration must
lead to useful account detail instead of a fabricated empty account.

Reproduced 2026-09-07 on `https://beancount.io`, Chrome 152, English/light,
1440×1000 and 390×844, authenticated public-example reader (`pull: true`,
`push/admin: false`). Source and fetched `origin/main`: `57fc1c27`; deployed
SHA unverified.

1. Fresh-load `/ledger/open_ledger/example/income-statement`.
2. In the Net Profit summary card, click the **Net Profit** account-style link.
3. Observe `/ledger/open_ledger/example/account/Net%20Profit` and the settled
   **No Data Available / No account data found for this account** state.
4. Repeat from a fresh report load. The same destination occurs at both widths.

Expected: the aggregate label is plain localized summary text; only real
accounts offer account drill-down. Actual: the client invents an account named
`Net Profit`. The actual `GetLedgerAccountReport` request sends
`accountName: "Net Profit"`, `ledgerId: "open_ledger/example"`,
`interval: "monthly"`, `conversion: "at_cost"`, and empty time/filter/account
values. HTTP 200 returns an empty linechart and 33 empty-balance points in each
other series, without a GraphQL error. The API's empty result is expected for
this nonexistent account. The real **Salary** link on the same Income Statement
opens `Income:US:Hoogle:Salary`, populated charts and payroll journal rows.

Root cause: `dashboard/src/features/reports/income-statement/income-statement-content.tsx:123`
constructs `netProfitTreeNode` with `account: "Net Profit"` at line 135 and
passes it as real tree data at lines 379–387.
`reports/balance-sheet/hierarchy-list.tsx:207–218` links every tree node to its
account. This violates `features/reports/CLAUDE.md`'s real-account-only tree rule.

Fix in **dashboard**: render this aggregate through the existing
`HierarchyListCard` `summaryRows` path with empty detail data and the translated
Net Profit label. Reuse its amount columns, primary currency and inversion
option; preserve current totals and the intended no-data behavior. Do not make
the account route recognize a fake account or remove legitimate account links.
Cover summary label/amount rendering and absence of a drill-down link, with a
real-account link as a positive control.

Blast radius: the shared card is used by Balance Sheet, Income Statement and
Cash Flow. Only Income Statement constructs this `Net Profit` synthetic node;
Cash Flow already supplies unlinked `summaryRows`. One Income Statement route
was found. No API or accounting calculation change is needed. Empty/all-zero
reports, currency conversion, other locales, expired sessions and network
failure were not exercised for this finding; preserve their established states.

Dedupe: searched open and completed `.pm` notes/milestones for Net Profit,
synthetic account links, hierarchy links and summary rows. Completed
`w4/done/m2/CONTEXTS.md` documents the shared plain-summary implementation for
Cash Flow, without fixing this Income Statement caller. No open overlap or
newer repair on fetched main. `git log -S 'account: "Net Profit"'` traces the
caller to `af5339de`; this is not an established regression.

Local evidence: `dashboard/tmp/qa-20260907-w3-loop/net-profit-evidence.json`,
`net-profit-1440.png` and `net-profit-390.png`. No console errors accompanied
the observed destination. Text above is sufficient to reproduce without the
ignored artifacts. No ledger data was changed.

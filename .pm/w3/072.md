# Account search calls loading and failed reads an empty ledger

Severity: **minor**. Package: **dashboard**. Estimate: **35–55m**.
A2: users can distinguish an unavailable account list from a ledger with no
accounts and retry without guessing that they must close the search.

Production client `https://beancount.io`, 2026-09-08, Chrome 152, English/light,
QA reader of public `open_ledger/example` (pull true, push/admin false).
Fresh 1440×1000 and 390×844 contexts. Local `a315c273`, fetched main
`790791ac`; implicated sources unchanged, deployed SHA unverified.
**Controlled read delay and network failure**, not a naturally occurring outage.

1. Load `/ledger/open_ledger/example/journal?lang=en` fully. At narrow width,
   open the sidebar. Hold its next GetLedgerAccounts request before transmission.
2. Open **Search accounts...** beside Accounts. While that read is pending,
   the popup says **No accounts found** with zero options and no loading state.
3. Abort the held read. The settled popup still says **No accounts found**,
   with no error or retry action. Fresh desktop/narrow repeats agree.
4. Close the popup with Escape, restore the real network and reopen it. The
   real HTTP 200 response contains 60 account names and no GraphQL errors;
   the popup correctly displays 91 options including generated parent paths.
   REST GET `/api-gateway/v1/ledgers/open_ledger/example/accounts` also returns
   HTTP 200, 60 names, including Assets:US:BofA:Checking.

Expected: show loading before an uncached read settles, then an actionable
failure if it fails. Show the existing empty/no-match message only for a
successfully loaded list/search with no matches. The 91 options after recovery
are intentional: `generateAllAccountPaths` adds distinct hierarchy prefixes.

Root: `dashboard/src/common/components/ledger-layout/go-to-account.tsx:40–50`
destructures only data from useQuery and replaces absent data with an empty
array. Lines61–65 always mount CommandEmpty. The wrapper at
`common/components/ui/command.tsx:69–74` delegates to cmdk. Its pinned **1.1.1**
implementation renders Empty whenever filtered.count is zero; it has no
knowledge of the caller's request state. The archive matches npm registry
integrity. The defect belongs to this caller, not the shared empty primitive.

Producer/contract: `graphql/query/report.graphql:38–40` reads a string array;
backend-v2 `features/ledger/api/resolvers/ledger-account-resolver.query.ts:47–58`
delegates to the same getAccounts service as REST's
`api/rest/v1/reports-handler.ts:70–87`. The service at
`service/ledger-account-service.ts:61–78` maps authorized account detail records
to names. The healthy reads agree; no backend, REST or schema change is needed.
Live MCP was not exercised.

Fix: handle this query's loading, error and refetch state explicitly in the
popover. Provide localized loading and error/retry feedback through
`src/i18n/locales/common/` for all supported languages, reusing existing keys
where suitable. Keep the search usable and preserve its text across retry;
show true empty/no-match feedback only after success. Retain on-demand fetching,
ledger-scoped cache identity, generated parent paths, Escape focus return and
the working narrow-sidebar dismissal after selection. Do not move this optional
read into the route's critical loader or globally change CommandEmpty.

Acceptance: a delayed first read never claims no accounts, failure exposes a
keyboard-operable retry, and retry renders real options without reopening.
Cover a successful empty response, no matching search, cached reopen and a
ledger change. The normal controls already pass at both widths: no-match Enter
keeps the popup/route intact, Escape returns focus, and keyboard selection
opens the intended account and closes the narrow sidebar. Use real query-state
transitions in focused regressions and run the dashboard gates.

## Objective

Expose the optional `requestId` on every adapter that reaches the three services, with identical behavior and errors.

## Context

- REST `POST …/entries`, `…/directives/text`, `…/import/insert-receipt`, legacy `/legacy/entries`; GraphQL `bulkEntries`, `addEntries`, `appendLedgerText`, `insertReceiptTransaction`; MCP `addLedgerEntries`, `appendLedgerText`, `insertReceiptTransaction`.
- Regenerate the OpenAPI snapshot (`yarn generate-v1-openapi`) and the IDL/CLI generated clients if they change.

## Acceptance criteria

- [x] Parity tests drive all three surfaces through the real service: replay returns the first result, mismatch is refused, and in-progress is retryable, with the same codes and hints.
- [x] MCP tool descriptions tell agents to reuse the same `requestId` when retrying.
- [x] `yarn typecheck`, `yarn test`, and OpenAPI drift check pass.

## Out of scope

- Client changes.

## Done 2026-11-03

- An optional `requestId` is accepted on every adapter that reaches the three services:
  - REST: `POST …/entries`, `…/directives/text`, `…/import/insert-receipt`, and legacy `/legacy/entries`.
  - GraphQL: `bulkEntries`, `appendLedgerText`, `insertReceiptTransaction`, and legacy `addEntries` (`EntriesInput.requestId`).
  - MCP: `addLedgerEntries`, `appendLedgerText`, and `insertReceiptTransaction`.
  - REST and GraphQL carry the shared `ENTRY_REQUEST_ID_DESCRIPTION`, and REST also the 1–200 bound; the service enforces that bound everywhere.
- MCP's field has no description. `tools/list` sits at its 120 KB budget with about 130 bytes of headroom, which three described fields would exceed. Instead, the MCP server instructions state the contract once, kept under their 1,500-character budget, and a mismatched or in-progress id explains itself in its refusal.
- The OpenAPI snapshot is regenerated, and the CLI's `openapi/v1.json` and generated REST client are synced (`make spec-sync codegen`). The IDL package carries only the admin API, so it needed nothing.
- Parity tests run through the real services with the `fake-redis-idempotency` module double:
  - `structured-entry-parity`: replay, mismatch (`VALIDATION_FAILED`), in-progress (`CONFLICT`), and Redis down, on REST, GraphQL, and MCP.
  - `directive-text-parity` and `receipt-insert-parity`: replay on all three surfaces. The receipt is promoted once and posted once.
- Gates: typecheck; full `yarn test` (8166); OpenAPI drift is only the intended additions; Knip, whose only finding is the existing oauth export; ESLint and Prettier on changed files. On the CLI side, `make spec-check`, the contract tests (139), and mypy on the client pass.

## Done 2026-11-03

- `mobile/src/common/entry-write.ts`: `useEntryWrite()`, the same client contract as the dashboard's (t003), written separately because packages share no code.
  - `withRequestId(variables)` names a save `<screen nonce>-<fingerprint>`.
  - `send` retries an in-progress `CONFLICT` after 1, 2, and 4 s with the same id, then throws `EntryWriteMaybeSavedError` and refreshes the ledger data (`invalidateLedgerData(client, "entries")`).
  - The nonce renews after each save.
  - `ledgerWriteFailureMessage` reports a maybe-saved write with the existing `ledgerWriteUnconfirmed` text ("The server didn't confirm the save. Check before trying again."), so no new strings were needed.
- Wired into every mobile entry save:
  - `use-save-budget.ts` (`bulkEntries`).
  - `use-open-account.ts` (`bulkEntries`).
  - `use-add-entries-to-remote.ts`, the legacy `addEntries`. It carries both the New Transaction screen and receipt capture, which saves through that screen.
- The operations `BulkEntries` and `addEntries` take `$requestId`. `src/generated-graphql` was regenerated from backend-v2's printed schema; the stale snapshot also gained billing fields already live on the backend, which no mobile operation uses.
- Tests:
  - `common/__tests__/entry-write.test.ts` (8): backoff, bounded give-up, other errors passed through, the unconfirmed message, fingerprint, and id stability, renewal and retention, with the real hook loaded in a vm sandbox.
  - `use-add-entries-to-remote.test.ts` checks that all three hooks send through `useEntryWrite`.
  - The `use-save-budget` sandbox gained a pass-through stub.
- Gates: `yarn format:check`, `yarn lint` (Knip and the operations check), `yarn typecheck`, and `yarn test:unit` (5069) pass.
- **Deploy order:** backend-v2 (`fcf984b59`) before a mobile release or OTA, because an older schema rejects the `requestId` argument.

## Objective

Expose the optional `requestId` on every adapter that reaches the three services, with identical behavior and errors.

## Context

- REST `POST …/entries`, `…/directives/text`, `…/import/insert-receipt`, legacy `/legacy/entries`; GraphQL `bulkEntries`, `addEntries`, `appendLedgerText`, `insertReceiptTransaction`; MCP `addLedgerEntries`, `appendLedgerText`, `insertReceiptTransaction`.
- Regenerate the OpenAPI snapshot (`yarn generate-v1-openapi`) and the IDL/CLI generated clients if they change.

## Acceptance criteria

- [ ] Parity tests drive all three surfaces through the real service: replay returns the first result, mismatch is refused, and in-progress is retryable, with the same codes and hints.
- [ ] MCP tool descriptions tell agents to reuse the same `requestId` when retrying.
- [ ] `yarn typecheck`, `yarn test`, and OpenAPI drift check pass.

## Out of scope

- Client changes.

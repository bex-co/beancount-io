# Saving a file shows "Out of date — click to refresh" for the user's own write

Reported by a user 2026-11-01 and reproduced on production with the QA account on its disposable ledger: open a file, Edit, change a line, save. Within ~3 s of "File saved successfully" the header shows the refresh button with its orange dot, although the page already shows the saved version. Clicking it only refetches what is on screen.

Cause (`dashboard/src/common/components/ledger-layout/ledger-out-of-date-indicator.tsx`): the indicator pins the ledger's latest commit SHA at mount and only re-pins it when its own button is clicked. Every dashboard write ends with `useApolloCacheClear()`, which evicts `ROOT_QUERY`, so every active query — including the indicator's `GetLatestLedgerCommit` — refetches. The page is now current, but the pinned SHA is not, so the user's own commit reads as someone else's.

Fix: a cache clear means everything on screen is being refetched, so it is the moment the indicator should re-baseline. Have `useApolloCacheClear` signal that, and have the indicator adopt the next fetched SHA as its baseline. This covers every write path that already clears the cache (file save, entry edits, imports, …) at one choke point. A commit made elsewhere after that still raises the indicator.

Acceptance: a regression test saves a file through the real file view and asserts no out-of-date button appears; the existing case — a commit from elsewhere shows the button — still passes.

Source: user report 2026-11-01. Pillar A2 — a false "out of date" after every save reads as data loss to a new user. (≤ 1h)

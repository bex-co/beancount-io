# `bea list transaction` human POSTING AMOUNTS omit cost and `@`/`@@` prices JSON includes

**Severity:** minor. **Estimate:** 20–35 minutes. **Owner:** cli. **A1:** an agent
that lists holdings after `add transaction` with `{cost}`, `@`, or `@@` sees
only bare units (`5 HOOL`) in the default table while `--json` exposes full
`cost`/`price` and `--details` shows Beancount source.

Found 2026-09-16 by continuous CLI QA ([c1090 hunt](1e1a0952-e911-4665-942a-3eab93031f27)),
HEAD `a9a7314d`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Evidence:
`cli/tmp/qa-20260915/c1090/`.

## Repro

```sh
# Assets:Broker  5 HOOL {50 USD}
bea --file main.bean list transaction --search Buy
# POSTING AMOUNTS: Assets:Broker: 5 HOOL  (no {50 USD})

bea --json --file main.bean list transaction --search Buy
# postings[0].cost present

bea --file main.bean list transaction --search Buy --details
# Assets:Broker  5 HOOL {50 USD, …}

# @ price similarly: human "1 HOOL", JSON postings[0].price set
```

## Expected

Default human POSTING AMOUNTS include cost/price annotations (or document that
only `--details` / `--json` show them).

## Actual

`list.py` `_transaction_table` formats with `_amount(p["units"])` only; `cost`
and `price` are ignored.

## Fix

Append `{cost}`, `@ price`, or `@@ total` when present. Regression: cost/`@`/`@@`
show in the default table; unit-only postings unchanged.

Same human/JSON parity class as w3/293 / 316, but not those symptoms. Not

in human `list transaction` POSTING AMOUNTS.

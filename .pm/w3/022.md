# Global statement print CSS blanks Journal and Accounts printing

**Severity:** minor — ordinary browser printing produces an empty page outside
the supported statement routes. **Estimate:** 20–35m, conditional print isolation
and focused regression coverage. **Pillar:** A3 — readers can share ordinary
dashboard pages without their content disappearing.

Reproduced 2026-09-08 on production, Chrome 152, English/System-light,
authenticated reader of synthetic `open_ledger/example`, source `a315c273`;
deployed SHA unverified. Desktop 1440×1000 and Journal at 390×844 after a fresh
load. No global filters. A4 browser PDF output.

1. Open `/ledger/open_ledger/example/journal` and wait for transactions and
   posting controls to render. The normal main surface contains over 3,000
   characters of report text.
2. Print through the browser. QA exercised Chromium print media/PDF generation.
   All content disappears; the saved PDF contains no non-whitespace text.
3. Reload and repeat at narrow width: another empty PDF.
4. Open `/ledger/open_ledger/example/accounts` and wait for its populated
   account directory. Its normal main surface has over 3,500 text characters;
   browser printing again yields an empty PDF.
5. Leave print media: normal Journal/Accounts content returns immediately.

Both failing routes have zero `.statement-print-root` elements. In print
media, each non-script/style body child has computed `display:none`; the body's
visible text is empty. This is not a loading, authentication, no-data or API
failure. A fresh Income Statement browser PDF in the adjacent export pass
contains its semantic statement and financial values as expected.

Root cause in **dashboard**: `src/style.css:5` globally imports
`features/reports/export/statement-print.css`. Its print rule at 13–15 hides
**every** `body > *:not(.statement-print-root)` without checking whether a
replacement statement portal exists. Only Balance Sheet, Income Statement
and Cash Flow mount that portal through `StatementExportMenu`. Journal and
Accounts therefore have no remaining printable content.

Fix: apply statement-specific app/chrome isolation only while an actual
statement print surface is present. Keep the stylesheet in the inline root
bundle so its screen-hiding rule still ships; reverting to a bare CSS import
would restore the earlier production leak. Ordinary pages should retain
their normal browser-print content. This does not add a new financial
statement renderer or promise a specialized Journal/Accounts export layout.

Blast radius: the rule ships on every dashboard route; all routes without a
statement portal are exposed. Journal and Accounts were independently checked.
The three supported statement routes remain the working conditional-isolation
case and must still hide dashboard chrome while printing their portal.

Acceptance: fresh Journal/Accounts browser PDFs contain their visible page
content; normal screen rendering is unchanged. Supported statement PDFs still
show only the semantic statement. Verify with a real rendered print-media
control both with and without the body-level portal; a test checking only for
the stylesheet import cannot catch this behavior.

Dedupe: searched all open/completed board files for blank printing, print CSS
and statement-print-root. `w4/done/001` fixed a different bug: print text leaking
onto the normal screen because CSS was not delivered. `7d219b23` made these
existing unscoped print rules global, exposing the no-portal case. Preserve
that completed fix's full screen/print DoD while narrowing this rule. No open
duplicate or later CSS correction found. `w3/020` concerns stale portal data
when a portal exists, a separate mechanism.

Unverified: actual Cmd/Ctrl+P interaction, physical printer output, other
browsers/routes and specialized non-statement pagination. No response/DOM
content was mocked; print emulation was removed after each check. No product
fixes, ledger writes or shipping included.

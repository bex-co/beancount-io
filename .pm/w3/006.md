# Journal pagination cannot be reached by keyboard

**Severity:** major for keyboard users: entries after page one cannot be reached
through the visible pagination controls. **Estimate:** 40–55m, including a real
Tab/Enter/Space regression. **Pillar:** A2 — public-ledger exploration must be
usable with a keyboard.

Reproduced 2026-09-07 on production, Chrome 152, English/light, 1440×1000,
authenticated reader of `open_ledger/example`. Source and fetched main
`57fc1c27`; deployed SHA unverified.

1. Fresh-load `/ledger/open_ledger/example/journal` with Transaction selected
   and no subtype/date/account filters.
2. Focus the final row's **Toggle postings** button, then press Tab.
3. Focus jumps directly to Related Pages → **Overview**, skipping Previous,
   every page number and Next. A fresh-load repeat behaves identically.
4. On `/ledger/open_ledger/example/account/Income%3AUS%3AHoogle%3ASalary`,
   the same step skips pagination and focuses Related Pages → **Journal**.
5. Click page 2 or Next with the mouse as a control.

The accessibility tree exposes pagination labels as list-item text, without
link or button roles. Its anchors have no href, explicit role, tabindex or
keyboard handler. Mouse Next on Journal sends `GetLedgerJournal` with
`offset: 60, limit: 60`, returns HTTP 200, total 1044, 60 rows starting
2017-07-11. Mouse page 2 on Salary sends `GetLedgerAccountJournal` with
`offset: 20, limit: 20`, returns HTTP 200 and 20 rows starting 2016-12-01.

Root cause: `dashboard/src/common/components/ui/pagination.tsx:47–68`
renders an anchor; `features/journal/components/journal-pagination.tsx:43–113`
supplies only click handlers. The component is used by
`features/journal/pages/journal-page.tsx:266` and
`features/reports/account/index.tsx:258`; both were exercised. A source-wide
caller search found no other production consumers of this pagination primitive.

Fix in **dashboard**: use native buttons for these local state changes, keeping
translated accessible names, visible focus, current-page indication, and native
disabled boundary controls. Enter and Space must perform exactly one page
change, with focus remaining coherent when results load. Preserve actual
navigation links if the primitive later supports them; adding tabindex alone
does not supply native activation semantics. Do not change paging arithmetic.

Acceptance: Tab reaches every enabled page control in both journeys; Enter
and Space change the result page; disabled Previous/Next cannot activate at
the boundaries; focus remains usable after loading; mouse paging still works.
Use a keyboard interaction test through the rendered controls, rather than
only invoking click handlers. Empty/single-page results keep pagination absent.

Dedupe: searched all open/completed board files for pagination, keyboard and
accessibility. Completed `w5/done/m2` covers sidebar/gallery accessibility,
not journal pagination; no open overlap. Targeted history traces both files
to `af5339de`, with no newer repair on fetched main. Screen readers,
other browsers, native mobile, and a patched implementation remain unverified.
No console errors or ledger mutations accompanied these checks.

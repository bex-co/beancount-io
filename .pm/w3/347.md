# `bea add transaction --meta` stores invalid calendar dates as quoted strings

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** cli. **A1:**
`--meta 'received: 2020-13-01'` exits **0**, writes a quoted string, and
`check` stays green — while unquoted invalid dates fail check and bulk JSON
rejects tagged dates.

Found 2026-09-16 by continuous CLI QA ([c890 hunt](601f5f93-5d84-4ada-80ca-155ebe6ad682)),
HEAD `a5cacb68`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Confirmed
`cli/tmp/qa-20260915/c891/`. Evidence: `c890/`.

## Repro

```sh
bea --file main.bean add transaction --date 2020-08-01 -n bad \
  --meta 'received: 2020-13-01' -p 'Expenses:Food 1 USD' -p 'Assets:Cash'
# exit 0 — received: "2020-13-01"; check exit 0

# control: --meta 'received: 2020-01-15' → unquoted date on disk
```

## Expected

Reject invalid `YYYY-MM-DD` meta at add time (same as bulk JSON tagged dates).

## Actual

`_parse_metadata` falls back to raw string when Beancount date parse fails.

## Fix

Reject date-shaped values that fail calendar validation. Regression:
`2020-13-01` exits nonzero; valid dates stay unquoted.

## Dedupe

Not w3/235 (boolean meta strings). Not w3/245 (bulk row date). No open note
covers invalid date `--meta` string fallback.

**Severity:** minor. **Estimate:** 45–60 minutes. Owner: ledger service. Preserve the pinned engine's precision guard; this is error classification, not a request to implement arbitrary-size integer support.

Root cause in backend-cluster/ledger: src/foundation/rustledger/engine.ts:698 calls ledger.query without normalizing this known result-conversion exception. rustledger-worker.ts:46–58 sends it as a failed task; rustledger-worker-pool.ts:292–297 wraps every failed task as InternalServerError. LedgerShellService at93/109 therefore never receives a QueryResult for assertQuerySucceeded at127–135, which otherwise correctly classifies ordinary query errors as BadUserInputError. The backend-v2 adapter foundation/fava/error-to-domain.ts:110–117 then maps upstream5xx to ServiceUnavailableError as designed. The dashboard renders that category faithfully; this is not a missing browser table or a false zero result.

Fix at the engine/query boundary: normalize the narrowly identified unsupported-integer-result exception into the existing query-validation/error path before generic worker-failure wrapping. Preserve the underlying integer range restriction and include a useful range/decimal diagnostic in the API error. Both shell table and shell text must receive the same client-error category. Keep unknown engine exceptions, actual worker failure, timeout, queue saturation and dependency outages classified as service/internal failures. Do not catch every engine exception as bad input, pre-rewrite arbitrary BQL text, round/cast the integer to JS number, fork the engine, change the API schema, or add a dependency. Use the existing structured QueryResult error path or an equally narrow typed propagation that survives the worker boundary.

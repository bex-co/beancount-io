# `bea query '.run NAME'` for a missing stored query exits 0 with empty output

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** cli. **A1:** an
agent running a named/saved query via `.run` cannot tell failure from an empty
result; the only signal is a stderr note while the command succeeds.

Found 2026-09-15 by continuous CLI QA against `main`, HEAD `e093cc4b`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
bea --file main.bean query '.run missing'
echo exit=$?
# stderr/stdout: error: query "missing" not found
# exit 0
```

Engine envelope (text format):

```json
{"ok": true, "data": {"text": "", "errors": []}}
```

with `error: query "missing" not found` on the helper's stderr (surfaced as a
note). Working control: a real BQL miss fails nonzero:

```sh
bea --file main.bean query 'SELECT nope'
# exit 2, usage error naming the unknown column
```

## Expected

A missing stored query is a usage failure (nonzero exit, clear error category),
not a successful empty answer. Prefer the same shape as other query failures.

## Actual

Beanquery's `.run` prints to stderr and returns success; `text_answer` records
empty `text` and `ok: true`; `helper_json` only notes stderr. Frontend exit is
0.

## Root cause

```text
beanquery BQLShell.do_run → stderr "query … not found", no exception
bea_engine.query.text_answer → envelope ok/empty text
cli.engine.launch.helper_json → output.note(stderr); return data
```

## Fix

Detect a failed `.run` (stderr pattern or shell return status) and raise
`UsageError` / protocol failure before answering ok. Regression:
`bea query '.run missing'` exits nonzero with a usage/validation error; a
fixture that defines `query name …` then `.run name` still exits 0 with rows.

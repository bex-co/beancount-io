# Converted report amounts print unbounded repeating decimals when the target currency lacks display precision

**Severity:** minor. **Estimate:** 25–40 minutes. **Owner:** cli. **A1:** an
agent converting a USD ledger to EUR with `balance -x EUR` / `report … -x EUR`
gets totals like `2,681.818181818181818181818182 EUR` instead of a readable
money amount — copy/paste and downstream parsing break, and the human report
looks broken next to same-day `0.00 EUR` zeros that already use two decimals.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `19128ce1`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
# main.bean: operating_currency USD, Cash 2950.00 USD, price EUR 1.10 USD
bea --file main.bean balance -x EUR
# Assets / Cash → 2,681.818181818181818181818182 EUR
# Equity → -909.0909090909090909090909091 EUR

bea --file main.bean report balance-sheet -x EUR
# same repeating decimals on converted rows (exit 1 if prices incomplete is OK;
# the printed converted lines still show full Decimal exponents)

# Control — native currency stays quantized:
bea --file main.bean balance -x USD
# Cash → 2,950.00 USD
```

## Expected

Human reports round converted amounts to a sensible display precision (ledger
`display_precision`, operating-currency precision, or a money default such as
2) so EUR totals read like `2,681.82 EUR`, matching how USD rows already print.

## Actual

`bea_engine/report._display_precision` only records currencies that already
appear in Beancount’s `dcontext` from ledger writes. A conversion target that
never posted (EUR) is absent, so `cli/commands/report._quantize` returns the
raw Decimal and `_amounts` formats with `max(2, -exponent)` — producing ~28
fractional digits for `2950/1.1`. JSON still keeps full-precision strings
(documented); the defect is human rendering for missing conversion targets.

## Fix

When rendering a converted currency missing from `display_precision`, fall back
to the operating currency’s precision, then to 2. Optionally seed the
conversion target into the precision map when `-x` is set. Regression: the
repro prints two-decimal EUR; USD control unchanged; JSON unchanged.

## Dedupe

Not w3/260 (JSON float pollution on write). Not w3/291 (duplicate same-day
price). No open note covers human conversion display for currencies never
written in the ledger.

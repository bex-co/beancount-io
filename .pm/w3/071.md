# A removed upload file cannot be selected again

Severity: **minor**. Package: **dashboard**. Estimate: **25–40m**.
A2: users can correct a file selection without reloading or selecting an
unrelated file first.

Production `https://beancount.io`, 2026-09-08, Chrome 152, English/light;
fresh 1440×1000 and 390×844 QA contexts. Public `open_ledger/minimax` grants
pull/push, not admin, and is not a disposable ledger. Local `a315c273`, fetched
main `853a4942`, implicated source unchanged; deployed SHA unverified.

1. Open `/ledger/open_ledger/minimax/files/upload/main/`. Use **Choose your
   files** to stage the small synthetic `qa-20260908-first.csv`.
2. Remove that staged file with its X button. The row disappears and Upload
   Files becomes disabled, but the hidden native input's files list still
   contains `qa-20260908-first.csv`.
3. Open the chooser again and select that same file. The chooser closes, but
   no row returns and Upload Files stays disabled. Fresh desktop and narrow
   repeats both reproduce the failure.
4. Working controls at both widths: choosing `qa-20260908-second.csv` adds a
   row and enables upload; reloading then choosing the original file also works.

Expected: after removal, selecting the file adds it to the current staged list
again. Actual: the browser considers its native file selection unchanged. The
first selection emits trusted input/change events; the same-file reselection
emits a trusted cancel event and no change. In a separate isolated runtime
control, clearing only the input's value after removal makes the same chooser
selection emit input/change and restore exactly one row at each width. No app
source was patched. No file upload or repository commit was attempted.

Root: `dashboard/src/features/ledger-editor/upload-files/index.tsx:152–156`
copies the input FileList into React selectedFiles but never resets the native
input. Removal at lines198–200 changes only selectedFiles. The chooser at191–192
reuses the same input mounted at240–246. The native picker therefore retains a
selection the UI already removed. This is client-state synchronization; no API
or serialized file-content change is needed.

Fix: reset the native file input when consuming/removing its selection, after
copying the File objects needed by the staged list. Keep selectedFiles as the
source for upload and removal. Canceling a later chooser must preserve existing
staged files; do not remount the whole page, clear the entire queue, or require
a second file to recover. Preserve size checks and existing upload behavior.
The [file input documentation](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/file)
describes the native files/value boundary; the retained trusted-event trace
establishes this browser's same-selection behavior.

Verify a real browser chooser through select → remove → reselect at desktop and
narrow widths, plus different-file, reload, multi-file and chooser-cancel
controls. Assert visible staged rows and enabled upload state; a test that
unconditionally dispatches a synthetic change event would hide this bug.
Run the dashboard gates when implementing.

Blast radius: this one UploadFilesPage serves root/nested
`/files/upload/$branch/$` routes and the legacy upload redirect. Drag/drop
bypasses the native input and was not exercised. Receipt's independent upload
zone passed unsupported/oversized-file checks and a controlled presign failure
→ Try Again → same-file retry at both widths; it remounts the input on reset.

Dedupe: searched all open/completed board records for same-file reselection,
file input reset and upload cancellation. 070 is the same row's missing action
name; 041 concerns an existing file editor's unsaved draft, and068 a separate
AI attachment callback race. Targeted history traces this input handling to
`af5339de`; fetched main contains no repair. Other browsers, actual storage
uploads, duplicate destination filenames and patched production are unverified.

All documents return HTTP 200, no console/page errors, and mutation guards see
zero attempts. Temporary contexts closed. Verified ignored evidence under

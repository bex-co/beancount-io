# `bea import` sticky recall hard-fails when a remembered `--rules` path is missing or corrupt

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** cli. **A1:** after
one successful `import … --rules rules.toml`, the documented flag-free re-import
(“next import needs no flags”) dies with `Cannot read rules file … No such file
or directory` (or a TOML parse error) if that rules file was moved, deleted, or
corrupted — even though column mapping memory is otherwise valid. Agents must
discover the undocumented escape hatch `--csv auto` (which clears `rules` in
memory).

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `1cdd53ca`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only. Evidence: `cli/tmp/qa-20260915/c514/`.

## Repro

```sh
# fresh BEA_CONFIG_DIR; ledger with Checking / Food / Uncategorized open
printf '%s\n' '[[rule]]' 'match = "Food"' 'account = "Expenses:Food"' > rules.toml
printf '%s\n' 'Date,Amount,Description,FitId' '2024-06-01,-4.50,Food Mart,F1' > week1.csv
printf '%s\n' 'Date,Amount,Description,FitId' '2024-06-08,-5.50,Food Place,F2' > week2.csv

bea --json --file main.bean import week1.csv \
  --csv auto --account Assets:Checking --rules rules.toml
# exit 0 — remembers mapping + absolute rules path

rm rules.toml

bea --file main.bean import week2.csv --account Assets:Checking
# exit 2
# Using remembered column mapping for week2.csv …
# Error: Cannot read rules file …/rules.toml: [Errno 2] No such file or directory
```

Working control — `--csv auto` clears sticky rules and succeeds (unmatched →
`Expenses:Uncategorized`). Corrupt-rules variant: overwrite `rules.toml` with
`NOT TOML {{{` instead of deleting → exit 2 `Cannot parse rules file … as TOML`.

## Expected

A missing optional rules file should not brick sticky mapping — warn and
proceed without rules, or clear the stale path and say how to restore
`--rules` / refresh with `--csv auto`.

## Actual

`cli/commands/import_.py` unconditionally restores `remembered["rules"]` into
`csv_rules_arg` with no existence check; `bea_engine/csv_mapper.load_rules`
then fails the whole import before preview. Ledger unchanged (good). Message
does not say the path came from memory.

## Fix

Before applying remembered `rules`, if the path is missing or unreadable: drop
it for this run, note it, and rewrite sticky `"rules": null`. Keep explicit
`--rules` failures as usage errors. Regression: the delete-then-reimport
sequence previews without exit 2.

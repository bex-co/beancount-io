# `bea` treats NFC and NFD account names as different accounts (split balances + false “unknown account”)

**Severity:** major. **Estimate:** 45–75 minutes. **Owner:** cli. **A1:** on
macOS, account strings typed or pasted as NFD (`Cafe` + combining acute) can
already exist in a hand-edited or imported ledger; `bea add` with the visually
identical NFC `Café` then opens a second account or refuses the posting as
unknown, so balances silently split across doppelgängers agents cannot tell
apart in the terminal.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `59ff7a32`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
# Ledger already contains an NFD account (combining acute), which bean-check accepts:
python3 - <<'PY'
import unicodedata
nfd = unicodedata.normalize("NFD", "Assets:Café")
open("main.bean", "w").write(
    'option "operating_currency" "USD"\n'
    "2020-01-01 open Assets:Cash USD\n"
    f"2020-01-01 open {nfd} USD\n"
    "2020-01-01 open Equity:Opening-Balances\n"
    '2020-01-01 * "seed"\n'
    "  Assets:Cash  100 USD\n"
    "  Equity:Opening-Balances\n"
)
PY
bea --file main.bean check
# exit 0

# NFC posting (what most agents / non-macOS keyboards emit) does not hit the NFD open:
bea --file main.bean add transaction --date 2020-03-01 --narration x \
  --posting 'Assets:Cash -1 USD' --posting 'Assets:Café 1 USD'
# exit 1 — Invalid reference to unknown account 'Assets:Café'
#          Did you mean Assets:Café, Assets:Cash?
#          To create it, use bea add open --account 'Assets:Café' …

# Following that suggestion creates a second, visually identical account:
bea --file main.bean add open --date 2020-01-01 --account 'Assets:Café'
# exit 0 — ledger now has BOTH NFD and NFC opens; check stays green

bea --json --file main.bean list open -a Cafe
# returns only the NFD row (substring "Cafe" matches base letters + mark, not NFC é)
```

Working controls: posting with the exact NFD bytes succeeds; ASCII `Assets:Cafe`
filters and opens behave normally.

Related list/`--search` narration misses are w3/275; this note is the account
identity / write path.

## Expected

Account names used in `add open` / postings / `--account` filters should apply
one Unicode normalization (NFC recommended) before validate, compare, and write,
so NFC and NFD forms of the same visible name are one account. Suggestions must
not invite a second open of a canonically equivalent name.

## Actual

Beancount’s loader accepts NFD opens; `parse_account` / posting identity use
raw code-point equality. NFC and NFD are different strings, so add can refuse a
correct visual match, suggest opening the NFC twin, and leave two opens that
split inventory.

## Fix

Normalize account segments to NFC (or the documented form) in `parse_account`
and when matching `--account` / suggestion candidates; reject or coalesce a
second open that normalizes equal to an existing account. Regression: NFD ledger
+ NFC posting writes to the existing account; `add open` NFC beside NFD is
refused as duplicate; `list open -a` finds the account from either form.

## Dedupe

Not w3/275 (narration `--search` / BQL `~` only). Not upstream-only: CLI write
and filter paths amplify the loader’s raw-string identity into a actionable
doppelgänger. No other open `.pm` note covers NFC/NFD account identity.

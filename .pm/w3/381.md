# `bea ask` with a rejected credential exits 1 with a raw SDK dump instead of exit 3

Severity: minor. **Estimate:** ~1h. **Owner:** cli. No-creds and
bad-creds take different categories, and the bad-creds message leaks
proxy internals.

`ask` without credentials exits **3** with the standard "Not logged
in…" message. `ask` with a *rejected* credential (same meaning: fix
your login) exits **1** with the AI SDK's raw exception string,
including the internal model name:

```
Error: status_code: 401, model_name: gpt-4o, body: {'code': 'UNAUTHENTICATED', 'message': 'Authentication required'}
```

Scripts branching on exit 3 for re-login never trigger, and users get
`status_code`/`model_name`/`body` instead of a remedy.

## Repro (synthetic, no quota — rejected at auth)

```sh
cd cli
cat > /tmp/a.bean <<'EOF'
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Expenses:Food USD
EOF
BEA_TOKEN=bogus-token-xyz uv run bea --file /tmp/a.bean ask "hi" --print
# exit 1 + raw SDK dump (expected: exit 3, "Not authorized …" + remedy)
uv run bea --file /tmp/a.bean ask "hi" --print
# exit 3, 'Not logged in…' — the working no-creds control
BEA_TOKEN=invalid-token-12345 uv run bea cloud status
# exit 3, clean BEA_TOKEN remedy — the cloud-command control
```

HEAD `b94d9461`, bea 0.2.0, Darwin arm64, isolated config/cache.
Reproduced 2/2.

## Root cause

`ask` (`cli/src/cli/commands/ask.py`) calls the pydantic-ai agent's
`run_sync` against `{api_url}/api-gateway/ai/openai/` with no error
translation, so the SDK's 401 exception reaches
`_GuardedGroup.invoke`'s generic handler → `to_bea_error` → catch-all
exit 1 with `str(exc)` verbatim. `cloud` commands instead go through
`cli/api/client.py` → `error_from_status`, which maps 401/403 to
`AuthError`/exit 3 with the credential-aware remedy. `ask` bypasses
that client (it speaks OpenAI-protocol through the AI SDK), so it
misses the mapping the exit table promises for auth failures.

## Fix direction

Catch the SDK's auth failure (401/403 from the proxy) in the `ask`
command and raise `AuthError` with the same remedy wording `cloud`
uses (including the BEA_TOKEN-vs-login distinction in
`errors._auth_remedy`, since a BEA_TOKEN caller is exactly who hits
this). Strip SDK internals (`model_name`, raw `body` dict) from the
message. Consider mapping the other obvious SDK failures while here
(rate-limit, server 5xx → clean exit-1 messages), but auth is the
contract fix. Regression tests: 401 → exit 3 + remedy with no
`model_name`/`status_code` in output (mock at the SDK/proxy boundary
and label it a simulation per QA rules); no-creds message unchanged.

## Blast radius / dedupe

- Affected: `ask --print` and the REPL's first call with any rejected
  credential (expired/revoked/wrong-env token). Interactive and
  print paths share `run_sync` with no translation.
- Not affected: local no-creds refusal (exit 3 ✓), `cloud` 401 mapping
  (exit 3 ✓), successful asks.
- Searched all `.pm/**/*.md` for ask-auth/401/UNAUTHENTICATED: no match.

# Cancel leaves drafts behind in SSH setup and Open Account

Severity: **minor**. Package: **dashboard**. Estimate: **45–60m**.
A2: starting a new SSH-key setup or Open Account form after cancelling opens
a clean form. Both callers bypass their existing reset-aware dismissal path.

Production `https://beancount.io`, 2026-09-08, Chrome 152, English/light,
authenticated QA account. Fresh 1440×1000 and 390×844 contexts. Local
`a315c273`, fetched main `790791ac`, source unchanged; deployed SHA unverified.
Only synthetic local fields are used. Mutation guards see zero requests;
no credential is created, modified or removed and no existing key data is retained.

1. Open `/settings/ssh-keys?lang=en`, then **New SSH key**.
2. Set Key Title to **qa-20260908-discard** and Public Key to the deliberately
   non-key text **qa-20260908-public-key-placeholder**. Do not submit Create Key.
3. Focus **Cancel** and press Enter. The dialog closes and focus returns to
   New SSH key correctly.
4. Open New SSH key again. Both discarded values are still present. Fresh
   desktop/narrow repeats reproduce this stale draft.
5. Working controls: Escape and the named Close button both clear the fields
   before reopening. The separate Personal access tokens dialog also resets its
   synthetic name and restores the read permission after keyboard Cancel at
   both widths, with correct focus return.

Expected: Cancel follows the same draft-reset path as the other dismissal
controls. Reopening starts from the existing empty defaults, without a stale
validation/server message. Do not change the current loading-disabled Cancel
behavior or add a new confirmation policy to this small form.

Root: `dashboard/src/features/user-settings/pages/ssh-keys/key-create-dialog.tsx:107–113`
resets the form and error in handleOpenChange(false), which is wired to Dialog
at116. Cancel at184–192 calls only setOpen(false), bypassing that cleanup.
The form instance/defaults at80–87 survive while this controlled dialog closes.
This is a caller state transition, not a failure of the shared close controls.
The API-token caller at `pages/api-keys/api-key-create-dialog.tsx:128–132,363`
uses its own reset-aware handler and is the passing sibling control.

Fix the SSH Cancel callback to use its existing cleanup-aware close path.
Verify Cancel, Escape and Close each reopen with empty title/key and no old
error, while the opener regains focus. Use real form/dialog interactions in
regression coverage: the current SSH test file replaces Dialog with an always
rendered div and ignores onOpenChange at45–63, so it cannot prove this lifecycle.
Apply the same caller correction to Open Account as described below, then run
the dashboard gates. No schema, API, shared primitive or translation change
is needed for this finding.

Blast radius: three KeyCreateDialog placements in the same SSH settings page:
the failed-list action at `pages/ssh-keys/index.tsx:61`, ordinary top action at136

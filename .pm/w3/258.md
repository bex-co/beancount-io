# `bea add` / `import` append LF-only lines to CRLF ledgers, leaving mixed endings

**Severity:** minor. **Estimate:** 25–40 minutes. **Owner:** cli. **A1/A2:** a
Windows (or CRLF-checked-out) ledger stays CRLF until the first `bea add` /
`import` write; the new directives are LF-only, so the file mixes `\r\n` and
`\n`. Diffs and some editors flag noise; `bea format -i` later rewrites the
whole file to LF.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `6fe71e6d`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
# pristine ledger rewritten with CRLF only
python3 -c "
from pathlib import Path
p=Path('crlf.bean')
p.write_bytes(Path('main.bean.pristine').read_text().replace('\n','\r\n').encode())
b=p.read_bytes(); print(b.count(b'\r\n'), b.count(b'\n')-b.count(b'\r\n'))
"
# → 32 0

bea --json --file crlf.bean add note --date 2024-05-01 \
  --account Assets:Cash --comment hi
# exit 0

python3 -c "
from pathlib import Path
b=Path('crlf.bean').read_bytes()
print(b.count(b'\r\n'), b.count(b'\n')-b.count(b'\r\n'))
print(repr(b[-60:]))
"
# → 32 2
# tail ends with: ...Checking\r\n\n2024-05-01 note Assets:Cash \"hi\"\n
```

Working control: the same add on an LF-only pristine ledger stays LF-only.

## Expected

Appended text uses the destination file’s existing newline convention (CRLF if
the body is CRLF; LF if LF), so one `add` does not introduce mixed endings.
`format -i` may still normalize; that is separate.

## Actual

`bea_engine/ledger/write.py` `appended_content` keeps `original` verbatim, then
joins the new blocks with `"\n"`:

```python
return text + "\n".join(tail) + "\n"
```

The aligner path even normalizes the draft to LF for bean-format, then still
appends with `\n`. Comments nearby already protect against Windows translation
turning CRLF into CRCRLF, but do not mirror the file’s newline for new lines.

## Fix

Detect the predominant (or last) newline in `original` (`\r\n` vs `\n`) and use
that separator when joining `tail` and the final terminator. Keep the binary
write/`newline=""` path. Regression: CRLF-only fixture + add → still zero bare
`\n`; LF fixture unchanged; mixed pre-existing files do not get worse.

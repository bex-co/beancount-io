# Open Account accepts names that are not complete account tokens

**Severity:** minor. **Owner:** dashboard. **Estimate:** 50–60 minutes.
**A2:** newcomers can correct an account name before the form prepares an
invalid or differently interpreted Open directive.

Production `https://beancount.io`, 2026-09-08, Chrome152, English/light,
1440×1000 and390×844. Existing QA session, public `open_ledger/minimax`.
Checkout HEAD rechecked at `a623f745`, fetched main `120f940d`; implicated
product sources unchanged from the initial `a315c273`. Deployed SHA unverified.
Every mutation was intercepted and aborted
before transmission. These are synthetic drafts, not created accounts.

1. Open Journal → New Entry → Account using
   `/ledger/open_ledger/minimax/journal?lang=en&action=new-entry&directive=account`.
2. Type **Assets:**. The form has no field error, enables its submit button,
   and clicking it prepares `OPEN` with
   `open.account: "Assets:"`, `currencies: []`.
3. Repeat with **Assets::Cash** and **Assets:Emergency Fund**: each also passes
   validation and reaches the guarded write.
4. Open Accounts → **Open Account** (**New** at390px) and repeat. It has the
   same failure. Fresh isolated documents reproduce both forms at both widths.
5. Enter **Assets:Emergency USD**. This also prepares that entire string as
   the account with no currencies. A separate fresh repeat confirms this case.
6. Controls: an empty value after a valid draft and **Checking** correctly
   disable submission and show required/prefix errors. **Assets:QaSyntaxDraft**,
   **Assets:Emergency-Fund**, **Assets:401K**, and **Assets:Épargne** prepare their
   exact valid account values. Lowercase **Assets:checking** also slips through
   and is invalid in the local parser control.

Expected: these forms accept one complete account identifier under a configured
root, display a useful localized name error, and block malformed values before
preparing a mutation. Do not silently turn spaces into colons/dashes, remove
empty segments, or reinterpret part of a name as a currency.

The [upstream syntax introduction](https://beancount.github.io/docs/getting_started_with_beancount/#brief-syntax-overview)
requires colon-separated components and disallows spaces in account names.
The actual local ledger formatter, `entryInputToText`, followed by the pinned
WASM0.21.0 provides the concrete consequence: **Assets:** and **Assets::Cash**
produce parse errors; **Assets:Emergency Fund** produces a parse error with a
recovered partial directive. **Assets:Emergency USD** produces valid source
whose account is **Assets:Emergency** and whose allowed currency is **USD**.
Beancount3.2.3 independently confirms the failures and the latter interpretation.
That valid source is not the structured account value the form claimed to submit.

These are local formatter/parser results. No production success response, commit,
account-list change, or persisted corruption was observed. The UI alert after
a guarded click is the deliberately aborted network request, not evidence of
the server's validation behavior.

Root: Journal `features/journal/components/new-directive-dialog/open-account-form.tsx:55–72`
checks only nonempty input and `startsWith(prefix + ":")`; it copies the whole
string into `open.account` at83–99. Accounts
`features/ledger-data/accounts/open-account-dialog.tsx:32–46` repeats that
prefix-only rule and forwards the string at114–133. Neither checks the complete
token. Both run Zod through the existing resolver in onChange mode.

The GraphQL producer/consumer path does not normalize it:
`graphql/query/journal.graphql:9` sends `AddEntryInput`;
backend-v2 `features/ledger/api/resolvers/ledger-entry-resolver.mutation.ts:157–167`
declares an ordinary String account and `toServiceEntry` preserves the Open
payload; `features/ledger/service/ledger-entry-service.ts:315–321` forwards it.
Ledger `src/api/entries.ts:33–41,58–74` invokes the actual structured formatter;
`foundation/rustledger/entry-build.ts:135–142` copies the account, and
`journal-serialize.ts:580–590` renders it unquoted before the currency list.
The append path at `api/entries.ts:98–119` is source-traced only.

Fix the two dashboard schemas with one small shared account-token validation
rule tied to the supported grammar and configured roots; keep the existing
required/prefix explanations and add localized syntax feedback. Validate the
whole string, including empty components and whitespace. Preserve hyphens,
numeric child components and supported Unicode names. Keep the user's original
draft available for correction. Do not reuse the editor's highlighting pattern:
`common/lib/editor/beancount-syntax.ts:39–45` is an unanchored, ASCII-only
highlighter with hardcoded roots, not a form validator. No new parser dependency
or cross-package import is needed.

The two real component callers are `new-directive-dialog/index.tsx:104` and
`ledger-data/accounts/index.tsx:525`. Route action links and the source-traced
Overview onboarding link share those forms. Do not turn this into validation
changes for every existing-account selector, bank linking, or the raw file editor.

Compatibility control: accented **Épargne**, digits and hyphens round-trip under
both engines. A local-only **Assets:中文** probe is accepted by WASM0.21.0 but
rejected by Beancount3.2.3's account validator. This discrepancy is outside the
finding; do not introduce an ASCII-only validator or silently narrow currently
supported Unicode identifiers as part of this repair.

Acceptance: at both widths and through both forms, the reproduced malformed
values never invoke BulkEntries and show a field error; valid controls preserve
the exact account and empty currency list. Exercise actual forms and resolver
behavior in regression tests, including correcting a rejected value and keeping
the configured-prefix rule. Reuse the translation work in084 where appropriate;
retain its scope separately. Run dashboard gates when implementing. Successful
creation, denied writes, option-load failures, native clients and other browsers
remain unverified in this pass.

# `bea report … -a ''` silently means unfiltered (whitespace `-a` correctly empties)

**Severity:** minor. **Estimate:** 10–20 minutes. **Owner:** cli. **A1:** an
agent with a template hole (`-a ""`) thinks it filtered the report but gets the
full unfiltered statement — while `-a '   '` / `-a Nomatch` correctly collapse
to “no dated activity”.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `cda5f986`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Evidence:
`cli/tmp/qa-20260915/c783/`, `c784/`.

## Repro

```sh
bea --file main.bean report income-statement -a Food
# filtered to Food expenses only

bea --file main.bean report income-statement -a ''
# exit 0 — same totals as omitting -a; header “account: all”

bea --json --file main.bean report income-statement -a ''
# data.account_filter is "" / falsy — full window

bea --file main.bean report income-statement -a '   '
# exit 0 — “no dated activity” (spaces never match an account)
```

Same empty-string acceptance on `overview` / `balance-sheet` / `trial-balance`
(shared `_load` → `get_filtered(account=…)`).

## Expected

Empty `-a` / `--account` is a usage error (exit 2), matching the empty-filter
policy of w3/286–287 / w3/294 / w3/327 — not “omit the flag”.

## Actual

Fava/`get_filtered(account='')` treats empty as no account filter. Human
header uses `account_filter or 'all'`, so `''` displays as “all”.

## Fix

Reject `account` that is empty (and optionally whitespace-only) before
`get_filtered` (UsageError naming `-a`). Regression: `-a ''` exits 2; omitting
`-a` and valid `-a Food` unchanged; whitespace policy aligned with chosen
empty-filter rule.

## Dedupe

Not w3/294 (`balance ''` positional substring). Not w3/287 (`list --account
''`). Not w3/327 (`report -t ''`). Not w3/292 (Nomatch → no dated activity).
No open note covers empty report `-a ''`.

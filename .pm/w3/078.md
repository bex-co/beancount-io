# SSH setup describes the key as an API credential

Severity: **minor**. Package: **dashboard**. Estimate: **25–40m**.
A2/A1: Git and API users can identify which credential they are registering.

Production `https://beancount.io`, 2026-09-08, Chrome 152, authenticated QA
account, light theme. Fresh English/Chinese contexts at 1440×1000 and 390×844.
Local `a315c273`, fetched main `5b70f569`, implicated source unchanged;
deployed SHA unverified. Only empty dialogs are inspected. All mutation guards
see zero attempts; no existing key information is retained.

1. Open `/settings/ssh-keys?lang=en` and **New SSH key**.
2. The resulting dialog is titled **Create New API Key** and says
   **Add a new public key to authenticate with the Beancount API.**
   Its two fields are Key Title and Public Key. Fresh desktop/narrow repeats
   give the same SSH-trigger/API-purpose contradiction.
3. Repeat with `?lang=zh`, then **新 SSH 密钥**. The dialog says
   **创建新 API 密钥** and **添加新的公钥以通过 Beancount API 进行身份验证。**
   Both Chinese widths reproduce it; this is translated content, not fallback.
4. Working control: `/settings/api-keys?lang=en` → **New token** correctly
   opens **Create personal access token**, with name, permissions, optional
   ledger restriction/expiry and no public-key textarea. Both widths pass.

Expected: the SSH action names an SSH public key and explains its Git repository
access purpose. Users obtaining an API credential should use the distinct
Personal access tokens page. Do not claim registering an SSH key issues a
Beancount API token or add a new authentication mechanism to make the copy true.

Root: `dashboard/src/features/user-settings/pages/ssh-keys/key-create-dialog.tsx:127–129`
uses userSettings.createNewApiKey and createNewApiKeyDescription. Their real
English values at `features/user-settings/locales/en.ts:54–60` and Chinese
values at `locales/zh.ts:82–88` name API credentials. All 15 locale modules
define these keys. The existing unit test substitutes the correct SSH title
and description in its translation mock at `__tests__/key-create-dialog.test.tsx:19–21`,
so it never checks the text actually shipped.

Fix the two SSH-specific title/description messages in every supported locale
and their description metadata, using clear SSH/Git wording. These keys have
only this production caller; a broad shared settings/API-token copy change is
unnecessary. Cover the rendered dialog with real English/Chinese translations
and retain the all-locale shape checks. Run dashboard gates. Credential formats,
authorization, endpoint behavior and key-creation lifecycle are outside this
copy repair.

# `bea add` accepts empty strings for required non-account fields (`event ""`, `document ""`, …)

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** cli. **A1:** an
agent that passes `--type ''`, `--comment ''`, `--path ''`, or
`--description ''` (Typer “required” satisfied by an empty argv token) gets a
successful write of `event "" "…"`, `note … ""`, `custom "" …`, or
`document … ""`; accounts are rejected, so the inconsistency is easy to miss.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `94be5377`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
bea --json --file main.bean add event --date 2024-05-01 --type '' --description x
# exit 0; ledger: 2024-05-01 event "" "x"; bea check exits 0

bea --json --file main.bean add note --date 2024-05-01 \
  --account Assets:Cash --comment ''
# exit 0; ledger: 2024-05-01 note Assets:Cash ""

bea --json --file main.bean add custom --date 2024-05-03 \
  --type '' --value 'text:x'
# exit 0; ledger: 2024-05-03 custom "" "x"

bea --json --file main.bean add document --date 2024-05-04 \
  --account Assets:Cash --path ''
# exit 0; ledger: 2024-05-04 document Assets:Cash ""
```

Working control — empty account is refused:

```sh
bea --json --file main.bean add open --date 2024-05-01 --account ''
# exit 2 usage: Invalid account '' …
```

## Expected

Required string fields that are not intentionally optional reject empty (and
whitespace-only) values with a usage error before write, matching account
validation. Document paths especially should be non-empty.

## Actual

`bea_engine/ledger/adding.py` `_text()` only checks `isinstance(value, str)`:

```python
def _text(request, field):
    value = request.get(field)
    if not isinstance(value, str):
        raise protocol.UsageError(...)
    return value
```

CLI Typer marks `--type` / `--comment` / `--path` / `--description` required,
but `""` counts as provided. Beancount accepts the empty quoted form, so
`check` stays green.

## Fix

Reject empty/whitespace-only strings in `_text` for directive fields that the
CLI documents as required (or add `_nonempty_text`), with a clear usage
message naming the field. Keep intentional empty narration on transactions if
that remains supported. Regression: each empty `--type` / `--comment` /
`--path` / `--description` above exits 2 with no ledger change; nonempty
controls still write.

## Objective

Preserve each owner/repository coordinate across the ledger service's outgoing
Gitea requests, completing the URL-encoding defense through both service hops.

## Context

- Found while reviewing t002: backend-v2 encodes its request to the ledger
  service, but `backend-cluster/ledger/src/api/ledgers.ts` passes decoded route
  parameters to a separately generated Gitea client with raw interpolation.
- t001 rejects malformed input at the public gateway. This task protects the
  subsequent hop independently if a low-level caller bypasses that boundary.
- Keep this implementation scoped to the ledger package; t002 owns backend-v2.

## Steps

1. Read ledger package guidance and inspect its client generation workflow.
2. Encode owner/repository parameters through that workflow, preserving nested
   file-path and query semantics; regenerate rather than hand-editing clients.
3. Exercise read/update/delete requests with slash, query, fragment, and encoded
   separator inputs against controlled upstream dependencies.
4. Prove regression tests fail against pre-fix code, then run package gates.

## Files

- `backend-cluster/ledger/src/api/ledgers.ts`
- `backend-cluster/ledger/src/features/gitea/client/gitea-api.ts`
- Ledger package code-generation configuration and relevant tests.

## Acceptance criteria

- [x] Decoded owner/repository values cannot change the subsequent Gitea request
  path, query, fragment, or endpoint for read/update/delete operations.
- [x] Regeneration preserves the encoding and valid nested file operations.
- [x] Meaningful regression tests fail before the fix and pass after; package
  checks pass without touching production ledgers.

## Out of scope

- Boundary validation (t001), backend-v2 generation (t002), privacy decisions
  (t003), and CLI response parsing (t004).

## Implementation and verification

- Added a ledger-local, pinned generation command and parameter hook. All 516
  owner/repository interpolations in the generated Gitea client are encoded;
  the generated diff contains only those changes and formatting.
- A thin template extends the bundled HTTP client while preserving this
  service's `format: "raw"` behavior. Exact-match checks fail if the generator's
  base template changes. Regeneration is byte-identical.
- Twenty-five real-client URL regressions failed before the change and passed
  afterward, covering read/update/delete, separators, query/fragment injection,
  encoded separators, and nested file paths with branch queries. Existing
  credential-forwarding and raw streaming tests also pass.
- Synced the existing lockfile's dependencies to replace a stale installed
  TypeScript version; no package dependency or lockfile was added/changed.
- Passed lint/dead-code detection, typecheck, build, and all 80 suites / 1,165
  tests. Jest emitted a worker teardown warning; assertions and exit status
  passed. No production ledger writes were performed.

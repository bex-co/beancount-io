## Objective

Add meaningful tests for the behavior this milestone shipped: boundary
rejection, upstream encoding, fail-closed privacy, and the CLI error path.

## Context

- Assert real behavior and failure modes, not trivial or snapshot-everything
  tests.

## Steps

1. REST: parametrized test that `{name}` with `/`, `%2f`, `%252f`, `?`, `#`, `..`, uppercase, space is rejected before any upstream call (GET/PUT/DELETE).
2. Upstream: test that a path param containing `/` or `?` is percent-encoded and cannot alter the request path or route DELETE elsewhere.
3. Probe: test that a 200 body without `private` fails closed.
4. Parity: test MCP and GraphQL lookups reject the same malformed inputs.
5. CLI: test that a malformed 200 yields a clear error, not `KeyError: 'id'`.

## Files

- `backend-cluster/backend-v2/src/**/__tests__/`
- `cli/tests/`

## Acceptance criteria

- [ ] Each of the five behaviors above has a test that fails against the pre-fix code and passes after.

## Out of scope

- Load/fuzz testing beyond the enumerated cases.

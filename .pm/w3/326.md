# `bea import --apply` on ID conflicts says choose `--duplicates skip/include`, which does not resolve them

**Severity:** minor. **Estimate:** 15–25 minutes. **Owner:** cli. **A1:** an
agent that re-imports a bank row whose stable ID already exists with different
amount/date/narration is told to “Resolve ID conflicts or choose `--duplicates
skip/include`” — then both `--duplicates skip` and `include` still exit **4**
with the same conflict. Docs say ID reuse with different data requires review,
not the possible-duplicate decision.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `4c54b7d8`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only. Evidence: `cli/tmp/qa-20260915/c717/`.

## Repro

```sh
# ledger + first import with FitId ID1 → written
printf '%s\n' 'Date,Amount,Description,FitId' \
  '2020-03-01,-12.34,Coffee,ID1' > a.csv
bea --file main.bean import a.csv --csv auto --account Assets:Bank:Checking \
  --apply --duplicates include
# exit 0

# same FitId, different amount
printf '%s\n' 'Date,Amount,Description,FitId' \
  '2020-03-01,-99.00,Coffee,ID1' > b.csv
bea --file main.bean import b.csv --csv auto --account Assets:Bank:Checking \
  --apply --duplicates include
# exit 4
# Error: Import needs review; nothing was written. Resolve ID conflicts or
#   choose --duplicates skip/include.
#   Row 1 (conflict): Stable ID matches an entry with different transaction data.

bea --file main.bean import b.csv --csv auto --account Assets:Bank:Checking \
  --apply --duplicates skip
# exit 4 — same conflict message (skip does not help)
```

Preview correctly labels `STATUS conflict` and does not claim the row is ready.

## Expected

Apply refusal for `conflict` rows must not recommend `--duplicates
skip/include` (those only cover *possible* duplicates per IMPORTING.md). Say
that a stable ID already points at different ledger data — edit/remove the
existing entry, change the bank ID, or drop the row — and leave
`--duplicates` out of the advice.

## Actual

The apply gate’s review message always mentions `--duplicates skip/include`,
including when every blocked row is an ID `conflict`.

## Fix

Specialize the exit-4 copy by row status: conflicts → ID/data mismatch
guidance; possible_duplicates → `--duplicates skip/include`. Regression: the
repro’s message no longer mentions `--duplicates`; a possible-duplicate-only
batch still does.

## Dedupe

Not w3/237 (`--id-key` disabling conflicts). Not possible-duplicate review
itself (documented). No open note covers conflict apply advice naming
`--duplicates`.

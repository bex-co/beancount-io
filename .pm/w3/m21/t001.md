## Objective

Let the Followers hook request and append subsequent pages while retaining a reliable per-profile lifecycle.

## Context

- Dashboard-only pagination repair from the reproduced public Followers journey in this milestone's README.
- Existing API total values count the returned page; do not redefine the backend contract.

## Steps

1. Keep the existing page-one/limit-twenty query and lazy enabled gate. Add a single-flight next-page action with append/deduplication by username.
2. Determine continuation from the received page length under the existing API contract; total is the returned page size, not the size of the collection. Do not silently increase the fixed limit and call the list complete.
3. Reset page/result/loading state when username changes and prevent a previous username's pending completion from entering the current list. Keep loaded items available during an incremental request.
4. Expose initial versus additional loading/error state and retry the failed page without duplicating earlier items.

## Files

- dashboard/src/features/user-profile/hooks/use-user-followers.ts

## Acceptance criteria

- [ ] A local 38-user fixture requests page 1 then page 2 at limit 20 and produces 38 unique items.
- [ ] A final 18-item page stops continuation; exact multiples handle the following empty page safely.
- [ ] Duplicate activation and a changed username cannot append duplicate or stale data.
- [ ] The existing lazy gate and GraphQL contract remain unchanged.

## Out of scope

Backend/API redesign, avatar delivery, social relationship writes, private user data,
and changing the intentionally capped activity feed.

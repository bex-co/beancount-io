## Objective

Let a profile visitor reach the remaining list items using visible, named controls while retaining useful pending and failure states.

## Context

- Dashboard-only pagination repair from the reproduced public Followers journey in this milestone's README.
- Existing API total values count the returned page; do not redefine the backend contract.

## Steps

1. Wire the three hooks into UserProfileTabs and add localized continuation controls and progress/end feedback using the existing UI primitives.
2. Keep existing cards visible while requesting the next page; disable duplicate requests and show retryable client/network errors without pretending they are an empty successful page.
3. Preserve tab URL synchronization and keyboard operation. Keep focus usable after loading, including when the final-page continuation control disappears.
4. Verify Followers (38) progresses from twenty to thirty-eight cards at desktop and narrow widths without modifying social relationships. Keep the existing Ledgers collection search/show-more behavior separate.

## Files

- dashboard/src/features/user-profile/components/user-profile-tabs.tsx
- dashboard/src/features/user-profile/locales/

## Acceptance criteria

- [ ] Tab/Enter can request and reach the remaining eighteen Followers cards in the public reproducer.
- [ ] There are no duplicate cards and the final state offers no spurious next page.
- [ ] Loading, retry, exhausted and empty states have appropriate names and visible feedback.
- [ ] Existing localized tabs, small/empty controls and the separate Ledgers collection remain usable.

## Out of scope

Backend/API redesign, avatar delivery, social relationship writes, private user data,
and changing the intentionally capped activity feed.

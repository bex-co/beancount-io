# `bea list event` / `list custom` expose `type` but offer no `--type` filter

**Severity:** minor. **Estimate:** 30–45 minutes. **Owner:** cli. **A2:** after
`add event --type location`, agents cannot `list event --type location` and
must fetch all rows or drop to BQL — unlike `--account` / `--currency` on peer
list commands.

Found 2026-09-16 by continuous CLI QA ([c920 hunt](221600bc-b7be-4bfb-a4d2-cb05b1d1f021)),
HEAD `d069dbf0`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Confirmed
`cli/tmp/qa-20260915/c921/`. Evidence: `c920/`.

## Repro

```sh
bea list event --help
# no --type

bea --json --file main.bean list event
# all events; no server-side type filter
```

Same for `list custom`.

## Expected

`--type` / `-t` on `list event` and `list custom` (case-insensitive), documented
in USAGE beside other list filters.

## Actual

Both use `_plain_command` with `supported_filter=None`; type is display-only.

## Fix

Add `--type`, thread to `list_events` / `list_customs`, update USAGE.
Regression: `--type location` returns only location rows.

## Dedupe

Not w3/289 (meta on list). Not w3/255 (empty add `--type`). No open note
covers missing list `--type` for event/custom.

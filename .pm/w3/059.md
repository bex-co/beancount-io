# Switching ledgers leaves the narrow sidebar over the destination

Severity: **minor**. Owner: **dashboard**. Estimate: **35–50 minutes**.
A2: choosing a ledger on a narrow screen reveals its page and releases the
navigation drawer, as ordinary sidebar navigation already does.

Production `https://beancount.io`, 2026-09-08, Chrome 152, English, System/light;
authenticated QA account. Public `open_ledger/example` → `open_ledger/minimax`.
Fresh 390×844 keyboard and pointer repeats; 1440×1000 keyboard control.
Local HEAD `a315c273`, fetched main `cc3f4c2f`, implicated code unchanged;
deployed SHA unverified. Minimax is public company data, not a disposable ledger.

1. At 390px open `/ledger/open_ledger/example/journal` and **Toggle Sidebar**.
2. Open **Select a ledger**, search for the available public Minimax ledger,
   and activate **minimax Public** with Enter or a pointer.
3. Wait for `/ledger/open_ledger/minimax/journal`, title **Journal - minimax**,
   and its latest public transaction narration to render. The picker closes,
   but the modal **Sidebar** drawer remains over the destination.
4. Focus returns to the Select a ledger combobox inside that drawer. Journal's
   Export control is present behind the modal but excluded from the accessible
   page. Escape closes the drawer; after its exit animation, Export is usable.

Expected: selecting a ledger closes the narrow navigation drawer, exposing the
destination when its data is ready. It should also release the modal focus
scope so keyboard navigation reaches the destination's controls. This is an
extra dismissal step, not a permanently trapped screen or failed ledger read.

Working controls: at 1440px the same selection changes ledger, closes the
picker and leaves Export accessible; the desktop sidebar is intentionally not
modal. At 390px ordinary Overview and Journal sidebar links close the drawer,
including reselecting the current Overview. Both failed narrow repeats wait
for real Minimax journal content, not a skeleton, and have no page/console
errors. Escape recovery succeeds. A direct GetLedger control returns HTTP200,
the exact target ID and `private: false` with pull/push true and admin false.
No write action or private ledger was selected or captured.

Root cause: `dashboard/src/common/components/ledger-layout/ledger-switcher.tsx:130–150`
navigates and closes only its local Popover `open` state. It never closes
SidebarProvider's separate `openMobile` state. The layout retains that provider
when ledger parameters change; `common/components/ui/sidebar.tsx:251–255`
still renders `<Sheet open={openMobile}>`. Ordinary navigation explicitly calls
`setOpenMobile(false)` in `ledger-sidebar.tsx:309–312` and wires that handler to
its links at lines334 and406. Account navigation has the same working pattern.

Close the enclosing mobile drawer as part of successful ledger selection,
using the existing sidebar state/callback convention. Preserve the selected
ledger, current subpage/search behavior, desktop expanded/collapsed state and
width, and normal picker dismissal. Ensure nested Popover focus restoration
does not trap focus in the drawer as it closes. Do not remount all ledger
routes or redesign shared Sheet/Popover primitives for this handler omission.

Blast radius: LedgerSwitcher has one production caller, LedgerSidebar. Every
ledger subpage using that narrow layout shares this selection handler; Journal
was exercised. Guest and legacy native-bridge branches render noninteractive
switcher content. Owner/profile/manage destinations and ledger creation are
not part of the observed failure or this repair.

Acceptance: fresh pointer and keyboard selections at 390px close both picker
and drawer and expose the selected ledger's content after loading. Destination
controls are reachable, and normal Escape/cancel and sidebar links still work.
The desktop control retains its nonmodal sidebar and current subpage. Add a
focused integration regression using the sidebar provider and actual modal
state; an assertion that mocked navigate was called is insufficient.

Dedupe: searched all open/completed board records for ledger switching,
drawers, sheets and mobile sidebar dismissal and reviewed open milestone
summaries. 055 is stale BQL data after a ledger switch; this failure happens
with correct Journal data and has a separate handler repair. Completed w5/m2
and later `b3411c4e` fix ledger-row semantics and picker scrolling, respectively.
Neither closes the enclosing drawer. Targeted history traces the missing
drawer update and the working ordinary-link update to `af5339de`.

Slow/failed navigation, same-ledger picker selection, other pages, browsers,
locales and patched focus behavior remain unverified. Initial locator and

## Objective

Honor an incoming file fragment after asynchronous content or the explicit
large-diff load makes its target available.

## Context

- Freelancer-invoicing fresh desktop/narrow loads and reloads retain the hash
  while leaving its mounted target far outside the viewport.
- Crypto's explicit large-diff load succeeds but loses a pending file target.

## Steps

1. Tie a requested fragment to the current ledger and commit, and pass it through
   the navigation mechanism from t001 when the relevant parsed content is ready.
2. Support initial loads, reloads and fragment/history changes without repeatedly
   scrolling on unrelated renders or carrying targets into another commit.
3. Preserve the explicit large-diff gate; resolve a pending destination after the
   user's load action. Reject malformed/unknown IDs harmlessly.

## Acceptance criteria

- [ ] A fresh freelancer-invoicing file URL reaches sales-tax.bean after loading.
- [ ] Reloading a selected file retains the destination at desktop and narrow widths.
- [ ] Crypto's pending transfers.bean target is revealed after Load Large Diff.
- [ ] Commit changes cancel stale destinations; ordinary scrolling stays put.

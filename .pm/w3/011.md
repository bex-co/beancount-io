# Yearly account grouping hides real activity and the controls needed to recover

**Severity:** major — real borrowing/repayment history disappears behind a false
empty state. **Estimate:** 45–60m, dashboard rendering and focused regression.
**Pillar:** A2 — readers of the public example can inspect settled positions
without being told that their account history does not exist.

Reproduced 2026-09-08 on production, Chrome 152, English/light, authenticated
QA account, synthetic public `open_ledger/crypto-example`. Source `57fc1c27`,
rechecked against `a315c273` after the checkout advanced; deployed SHA unverified.

1. Fresh-load `/ledger/open_ledger/crypto-example/account/Liabilities%3ACrypto%3ABinance%3AMargin`
   at 1440×1000 with no Time/Account/expression filters.
2. Monthly shows a nonzero balance during June–August 2024 and a journal with
   the June 1 borrowing and September 15 repayment.
3. Change the Monthly selector to **Yearly**.
4. After the successful response, the page says **No Data Available / No account
   data found for this account.** The journal, chart tabs, interval/conversion
   selectors and related links disappear. There is no selector to switch back.
5. A fresh desktop load restores Monthly; repeating Yearly reproduces the loss.
   Resizing that failed state to 390×844 preserves the false empty message.
   Fresh narrow selection was not exercised: the interval control is hidden
   below the existing `sm` breakpoint.

Expected: zero net annual change and zero year-end balance remain valid report
values; the two transactions stay inspectable and the interval can be changed.
Actual `GetLedgerAccountReport` is HTTP 200 with `interval: "yearly"`,
`conversion: "at_cost"` and empty filters. `linechartData` contains
`2024-06-01: {USD: "-2850"}` and `2024-09-15: {USD: "0"}`. Both annual
aggregate series have empty balance maps for 2024/2025, correctly reflecting
the repaid loan. REST `/api-gateway/v1/ledgers/open_ledger/crypto-example/account-report?accountName=Liabilities%3ACrypto%3ABinance%3AMargin&interval=yearly&conversion=at_cost`
returns HTTP 200 and the same three series. The account-journal control returns
HTTP 200, total 3: those two transactions plus its Open directive. No console
errors. This is neither a missing account nor an API error.

Root cause: `dashboard/src/features/reports/account/lib/account-report-empty.ts:27–29`
tests only nonzero values in `accountBalanceData` and `intervalTotalsData`.
`reports/account/index.tsx:347–363` then returns before the selectors at 388–398
and the independently fetched `AccountJournalTable` at 443–462. It treats a
zero aggregate as absence of all account data. `linechartData` is ignored;
checking just its nonzero values would still miss activity that nets to zero
on the same day.

Producer trace: ledger `src/features/ledger/service/ledger-data-service.ts:472–541`
constructs event-date and grouped series separately; gateway
`src/features/ledger/service/ledger-data-service.ts:347–365` forwards the request,
and `src/features/ledger/api/resolvers/ledger-data-resolver.query.ts:539–555`
maps the three arrays without dropping the event history. REST and MCP share
`ANALYSIS_READS`; REST was exercised, MCP was traced only. No calculation/schema
change is needed.

Fix in **dashboard**: limit the chart empty-state decision to the chart area.
Keep report controls and the independently loaded account journal mounted
when aggregate balances are zero, letting the journal report its own loading,
empty or error state. Preserve a designed empty chart instead of blank cards,
and do not claim that an account has no history solely from chart aggregates.
The initial report loading/error handling must remain distinct from a settled
zero result; changing intervals must not strand the user.

Acceptance: the exact Monthly → Yearly → Monthly journey retains both
transactions and a usable selector; annual zero totals remain numerically
correct. Cover same-day net-zero activity and a truly empty journal separately
using meaningful component interactions. The existing empty-state test may
still assert the designed empty chart, but must not require hiding recovery
controls or infer journal emptiness from a mocked chart-only result.

Dedupe: all open/completed `.pm` records and all open milestone summaries were
checked for account empty/zero/yearly/history loss. No overlap was found.
`w3/m13` fixes ignored journal selectors and does not repair this parent-page
gate. Only one production `isAccountReportEmpty` caller and one account route
were found. Targeted history and `git log -S isAccountReportEmpty` trace the
gate to `af5339de`; no newer source fix is present after the checkout advanced
to `a315c273`. No verified earlier working implementation establishes a
historical regression.

Working control: fresh Monthly displays both transactions and its balance
history. Network failure, denied/expired sessions, a patched implementation,
other browsers/locales and direct native-mobile behavior remain unverified.
No production data was changed.

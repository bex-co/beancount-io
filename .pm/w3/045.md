# Smart Import silently treats a real first transaction as a CSV header

Severity: **major** — a valid transaction disappears before preview without
any validation error. Owner: **dashboard**. Estimate: **35–50 minutes**.
A2: importing a supported CSV should preserve every valid transaction,
regardless of ordinary words in its payee or description.

Production `https://beancount.io`, 2026-09-08, Chrome 152, English,
System/light; authenticated QA reader of public synthetic
`open_ledger/crypto-example`. Desktop 1440×1000 and fresh 390×844.
Local HEAD `a315c273`, fetched main `cc3f4c2f`, deployed SHA unverified.
The header heuristic is unchanged on fetched main.

1. Open `/ledger/open_ledger/crypto-example/import` and choose this valid
   two-transaction CSV without a header:

   ```csv
   2025-12-01,QA Date Shop,Prepaid amount,-4.50
   2025-12-02,QA Grocery,Regular purchase,-45.67
   ```

2. Preview reports **1 Valid**, with only the December 2 grocery transaction.
   There is no validation warning or indication that December 1 was skipped.
3. Continue to Configure: only that grocery row remains and the action says
   **Import 1 Transaction**. Do not submit it.
4. A fresh narrow page repeats the same preview and configuration loss.
5. As a control, prefix the same two records with
   `Date,Payee,Description,Amount`. Both are now present, including the
   unchanged `QA Date Shop / Prepaid amount / -4.50` transaction.
6. A headerless control whose first row is
   `2025-12-01,QA Coffee,Regular purchase,-4.50` also retains both records.

Expected: both headerless files preview two valid transactions; the explicit
header is skipped exactly once while preserving both following records.
Optional headers are an existing supported behavior: the actual browser control
works, and `hooks/__tests__/use-csv-parser.test.ts:22–37,55–67` explicitly covers
single and multiple records without headers. This does not request a new import
format or arbitrary column mapping.

Root cause: `dashboard/src/features/importer/utils/csv-validator.ts:90–98`
searches the entire raw first line for `date` plus any of `payee`, `description`
or `amount`, ignoring field position and value type. The transaction's payee
supplies `date`, and its description supplies `amount`, so it is classified as
a header. `hooks/use-csv-parser.ts:83–84` then removes it with `slice(1)` before
CSV field parsing or validation at86–109. It cannot become an error row because
it has already been discarded.

The FileReader producer supplies the complete local file at161–172.
`use-multi-stage-parser.ts:26–35` accepts the remaining valid grocery row and
returns the incomplete result. The workflow stores that result at
`hooks/use-import-workflow.ts:22–25`; the configure wrapper passes its rows
unchanged at `components/steps/configure/index.tsx:24`. The missing transaction
therefore never reaches the account-mapping stage. No server response causes
this loss.

Fix header recognition using parsed field boundaries and the supported header
schema, rather than substring matches in arbitrary transaction text. A first
field containing a calendar date must be treated as data, regardless of words
elsewhere. Preserve ordinary optional-header behavior, canonical header case
handling, quoted fields and existing four-column/date/amount validation.
An invalid first data record must remain an actionable validation error rather
than being silently discarded. Keep error row locations coherent. Coordinate
with015's logical-record parsing without broadening into a new import engine
or adding a dependency.

Blast radius: `isHeaderRow` has one production caller, useCSVParser. That hook
serves the active multi-stage CSV path and FileUpload's fallback callback path.
The active path was exercised; the fallback branch is source-traced. Other
formats use the separate AI parser and are not established as affected.

Acceptance: the exact two-record headerless fixture and its explicit-header
control each retain both dates, payees, descriptions and signed amounts through
preview and configuration, with two valid rows and no invented error. Cover
ordinary words containing header tokens in the first record, case variations,
and a malformed first data row that must not vanish. Use the real parser hook
and FileReader/preview path; an isolated predicate assertion alone would miss
the silent row-removal outcome. Run dashboard checks when implementing.

Dedupe: searched all open/completed board files for headerless CSVs, header
detection and skipped first records, and checked open milestone summaries.
015 splits multiline quoted records; this reproducer has no quotes or embedded
line breaks.037 changes row identity after deletion; no row was deleted here.
038 parses incomplete numeric tokens; both amounts here are valid.039 reverses
posting signs after configuration. None repairs header detection. Targeted
history traces the heuristic to `af5339de`;6304627a changed calendar dates only.

The fresh narrow run had no page errors. Parsing produced no API operation;
continuing to configuration requested only GetLedgerAccounts and
GetLedgerCurrencies. No AI call, storage upload or import submission occurred.
All previews/configuration were discarded using Back and Upload Different File.
Single-record all-misclassified CSV fallback, actual persistence, other locales
and a patched implementation remain unverified.

# Missing commits are reported as a server outage

Severity: **minor**. Owning package: **backend-v2**. Estimate: **45–60 minutes**,
using the existing commit-read adapter harness; verify the actual upstream
missing-revision response before choosing its narrow classification rule.

Production `https://beancount.io`, 2026-09-08, Chrome152, English, System/light,
authenticated QA reader of public `open_ledger/walmart`; desktop1440×1000 and
fresh narrow390×844. Deployed SHA unverified. Source `a315c273` and fetched
`origin/main cc3f4c2f` contain the same implicated service.

1. Open `/ledger/open_ledger/walmart/commit/0000000000000000000000000000000000000000?lang=en`.
2. Wait for loading to settle. The page displays **Something went wrong on our
   end. Please try again later.** and **Try Again** instead of **Commit not found**.
3. Reload at390px: same result. A separate fresh request for SHA
   `1111111111111111111111111111111111111111` also produces this outage state.
4. Working control: use **Version History** to select
   `752d3b5750e84a0b02ac642bc4708da17e312fcf`. The existing commit loads normally,
   the narrow sheet closes, and the error disappears. History and ledger access
   remain available throughout.

API evidence for the all-zero SHA:

- GraphQL `getCommitDetails(ledgerId:"open_ledger/walmart", sha:...)` returns
  HTTP200, `data:null`, code **INTERNAL_SERVER_ERROR**, message **Internal server
  error**, path `getCommitDetails`.
- REST `/api-gateway/v1/ledgers/open_ledger/walmart/commit-details?sha=...`
  returns **HTTP500** and `{ok:false,error:{code:"INTERNAL_SERVER_ERROR",message:"Internal server error"}}`.
- The real SHA returns200 through both reads, including seven files and the
  expected diff. No console errors were captured on the UI repeats; the explicit
  REST control is an intentionally exercised failing HTTP request.

Expected: an authorized read of an absent revision has the shared **NOT_FOUND**
category (REST404); the dashboard's existing **Commit not found** branch renders
without presenting a server-retry action. Genuine source outages retain their
error category and recovery behavior.

Root cause: `backend-cluster/backend-v2/src/features/gitea/commits/service/commits-service.ts:212–234`
looks up the requested revision and throws a plain `Error` for an empty result.
Its catch at303–312 also replaces every upstream or domain error with another
plain `Error`, losing classification. The generated Gitea client at
`src/features/gitea/client/gitea-api.ts:3094–3121` throws its non-OK Response with
status and parsed error attached; replacing it discards that structured signal.
The upstream production status/body was not directly inspected, so whether this
specific missing revision takes the non-OK or empty-result path is unverified.
Both source paths currently collapse to the reproduced category.

`src/server/graphql/format-error.ts:69–99` preserves categories only for
`DomainError`; `src/server/rest/error-middleware.ts:58–113` maps an unexpected
plain error to500. Those adapters correctly apply their existing policy.
Dashboard `features/git/commits/components/commit-detail.tsx:41–64` already
recognizes NOT_FOUND and suppresses **Try Again** for it, and
`features/git/commits/locales/en.ts:40` defines **Commit not found**. Fixing display
copy alone would leave REST and MCP consumers with the wrong contract.

Fix: normalize a confirmed missing revision at the commit-service boundary into
the existing `NotFoundError`, including an empty successful lookup. Preserve
existing `DomainError` instances rather than rewrapping them. Inspect the actual
SDK error shape and distinguish absence from source401/403/429/5xx and network
failures; do not blanket-map failures to404. Keep the existing authorization
check before the lookup and retain production masking of unexpected details.

Callers: `features/gitea/commits/api/commits-resolver.ts:31–40` delegates GraphQL;
`api/commit-reads.ts:56–67` delegates the REST `commit-details` read, and
`features/ai-agent/api/mcp-resources.ts:625` registers the same COMMIT_READS for
MCP. The dashboard CommitDetail caller is used by the commit list/detail split
view. No changed API shape or new endpoint is needed. Live MCP, missing branches
in listCommits, private-ledger denials, expired sessions and source outages were
not exercised; do not claim those as additional live findings.

Acceptance: absent and existing revision cases reach the real service and actual
REST/GraphQL/MCP adapters through the existing test harness, using a controlled
Gitea boundary rather than a mocked commit service. Assert NOT_FOUND/404 for
absence and preserved non-absence failures, including a preexisting domain
error. Fresh desktop/narrow UI shows **Commit not found**, no outage/retry claim,
and working history recovery. Run backend-v2 typecheck, tests and OpenAPI drift
check; preserve the existing zero-debt API-parity gate.

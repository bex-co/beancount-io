# Public-reader Settings mounts an admin-only collaborator panel and reports a missing ledger

**Severity:** minor — a valid public ledger's Settings page displays an
avoidable error in place of an administrative section the reader cannot use.
**Estimate:** 20–35m, dashboard permission gating and focused regression.
**Pillar:** A2 — exploring public-ledger settings should retain useful public
information without misleading failure states.

Reproduced 2026-09-08 on production, Chrome 152, English/light, authenticated
QA account, synthetic public `open_ledger/example`, source `a315c273`;
deployed SHA unverified. Fresh desktop 1440×1000 and narrow 390×844 repeats.

1. As the QA public reader, open `/ledger/open_ledger/example/settings`.
2. Sharing and the Beancount/Fava options load successfully.
3. The Collaborators card says **Error Loading Collaborators / Ledger not
   found**. Reloading repeats it.

The actual `ListLedgerCollaborators` request sends only
`ledgerId: "open_ledger/example"`. HTTP 200 contains `data: null` and GraphQL
error `NOT_FOUND`, message `Ledger not found`, path `listLedgerCollaborators`.
The independent `GetLedger` permission control is HTTP 200 with
`{admin: false, pull: true, push: false}`. REST
`GET /api-gateway/v1/ledgers/open_ledger/example/collaborators` returns 404,
`NOT_FOUND`, with the protected action's `relationship_denied` reason.
That deliberate REST control produces one expected failed-resource console
message; there were no earlier settings console errors.

Expected: for a known non-admin reader, omit the administrative collaborator
section or show a neutral permission explanation without requesting its list.
Preserve the useful public settings/sharing view. The backend correctly denies
the collaborator read under its existing concealment policy; granting public
access or changing that policy is not the fix.

Root cause: `dashboard/src/features/ledger-data/settings/index.tsx:77–79`
mounts `CollaboratorsSection` for every authenticated user. Its query at
`collaborators-section/index.tsx:54–58` skips only a missing ledger ID.
Only the administrative actions inside the section are permission-gated, so
the protected list request runs before those child gates can help.

The server contract is explicit: gateway
`src/features/ledger/workflow/ledger-collaborators-workflow.ts:193–205`
authorizes `LEDGER_COLLABORATORS_LIST` before fetching data.
`src/server/api/authorization/authorization-service.ts:390–397` requires
`READ_COLLABORATORS` and conceals denied access as ledger-not-found;
`authz/model.fga:75` defines that relationship as administrator. REST and MCP
delegate to the same protected workflow; REST was exercised, MCP only traced.

Fix in **dashboard**: gate mounting the whole collaborator section with the
existing `LedgerAdminPermission` (which already combines authentication and
the current ledger's admin permission), or equivalently gate the query before
execution. Do not hide an error after already issuing the forbidden request.
Keep the actual loading/error/empty/list states for eligible admins and stop
showing old collaborator data when ledger identity or permission changes.

Working controls: public options and sharing load; the visibility switch and
delete-ledger action are already absent for this reader. There is one Settings
caller of the collaborator section. Actual admin success/revocation, expired
sessions and source outages were not exercised in production; cover those
relevant boundary transitions with controlled component tests.

Acceptance: a fresh public-reader load and reload issue no collaborator-list
request and show no missing-ledger error. An eligible admin still gets the
existing list and its genuine failure states. Public sharing/options remain
available. No backend authorization or parity behavior changes.

Dedupe: searched all open/completed records for public collaborator errors,
permission gating and missing-ledger messages. Completed
`w2/done/m18` establishes the protected administrative boundary;
`w1/done/m10/done/t010.md` preserves its concealment across surfaces. This
finding concerns the caller failing to honor that already-shipped contract.
No overlapping open UI item or newer main fix was found. The mount/query
trace to `af5339de`; a historical working non-admin implementation was not
established. `w3/m11` is a separate entry-editor permission defect.

No production data, collaborator membership or visibility was changed.

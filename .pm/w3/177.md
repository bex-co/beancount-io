# Keep merchant and transaction search feedback above the keyboard

Severity: minor. Estimate: 50–60m. Package: mobile. A2: searching a ledger's merchants gives a newcomer an immediate, readable no-results explanation.

Environment: production API, authenticated QA session, public open_ledger/minimax; HEAD f1965988, mobile source 7538fb0d, development client 1.20260906.47, iPhone 17e / iOS 26.5, English, default text size/light appearance.

Repro:
1. From Home open drawer → Merchants. MiniMax Group Inc. is the one merchant, with five transactions; its recurring section also appears.
2. Tap the search field and type qa-no-such-merchant. The results disappear, but the explanatory message is hidden by the keyboard and its suggestion area. Only the upper part of the search illustration is visible.
3. Tap the keyboard Search key. The keyboard dismisses and “No merchants match your search.” appears. Native inspection records the same message rectangle y=538.33, height=24.00 in both states; hittable changes from0 to1. The keyboard's native element excludes part of the suggestion area, so its bounds alone are not treated as the entire obstruction; screenshots establish the coverage.
4. Terminate/relaunch, wait for Home, use the actual drawer route, dismiss the development warning banner, and repeat. Fresh PID96715 reproduces the same keyboard-covered message and dismissal control.

Expected: once filtering settles, the no-results explanation is readable while the user is still entering or revising the search. Actual: the empty state centers against the full list area, which continues behind the keyboard. This is a visual layout failure, not a failed query or missing localized string.

Controls: keyboard Search reveals the unchanged message without changing the query. Clearing the field restores the MiniMax rows (merchants-clear-second.jpg; the first coordinate tap only refocused the native field). Discovery's separately implemented no-match state was visible with the keyboard during this same native sweep. No recurring overrides were toggled, and no ledger data changed.

Root cause: mobile/src/screens/merchants-screen/merchants-screen.tsx:69–98 uses a flex-growing list container and a flex:1, justifyContent:center empty container; the same screen at288–341 renders SectionList inside a plain full-height View without keyboard avoidance or keyboard inset adjustment. keyboardDismissMode=on-drag only dismisses on a gesture. The app/(app)/merchants.tsx route and resolved LedgerGuard add no keyboard-aware wrapper. This layout dates to76b9ce33, with subsequent recurrence and analytics changes retaining it.

Fix: lay out the search result area against the usable height above the keyboard, or position its empty feedback below the search field so it remains visible without dismissing the keyboard. Preserve focus, query, clear action, sort action, scrolling, pull-to-refresh and normal populated rows. Verify no-match typing → editing/clearing → restored rows; keyboard opening/dismissal must not jump the search input or hide the message. Cover default and enlarged text and both themes in the native follow-up. Use existing platform/layout primitives, no new dependency.

Blast radius: searched MerchantsScreen/MerchantsDirectory callers; one production route, reached by the drawer. The shared SearchBar does not itself position this screen's empty state; keep the fix in the affected result layouts rather than imposing list behavior on SearchBar or Account Picker. Initial loading/error/true-empty states share surrounding layout and must remain honest, but their behavior under an open keyboard was not reproduced here. API/auth, denied, expired session, network failure, Android, hardware keyboards and physical devices remain unverified. Bounded JS error capture empty.

Dedupe: searched all root .pm queues including done for merchant keyboard/empty/search findings and scanned open milestones. w3/112 concerns the detail query serializer; w3/111 the recurring switch label; neither owns this list layout. No matching fix or current-main repair found. Report only; no product code changed or shipped.

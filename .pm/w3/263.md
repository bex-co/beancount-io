# `bea import --csv` treats blank / whitespace-only rows as hard date-parse failures

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** cli. **A1:** bank
CSVs commonly end with a trailing blank line (or have blank separators). One
empty row aborts the whole preview/apply with `cannot parse date ''`, so an
agent cannot import an otherwise clean export without hand-editing the file.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `ae50515f`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
# main.bean has Assets:Cash + Expenses:Uncategorized open
printf 'date,amount,description\n2020-02-01,-1.00,a\n\n2020-02-02,-2.00,b\n' \
  > bank.csv

bea --file main.bean import bank.csv --csv auto --account Assets:Cash
# exit 2
# Error: Row 3: cannot parse date '' in column 'date' with format '%Y-%m-%d'.

printf 'date,amount,description\n2020-02-01,-1.00,a\n\n' > trail.csv
bea --file main.bean import trail.csv --csv auto --account Assets:Cash
# exit 2 — same empty-date error on the trailing blank line
```

Working control — header-only (no data rows) succeeds with `0 ready`:

```sh
printf 'date,amount,description\n' > empty.csv
bea --file main.bean import empty.csv --csv auto --account Assets:Cash
# exit 0 — 0 ready, preview empty
```

## Expected

Rows whose every mapped cell is empty/whitespace are skipped (not counted as
ready or duplicate), matching common CSV export hygiene. Real rows with a
missing date still fail with the current message.

## Actual

`bea_engine/csv_mapper.py` enumerates every `csv` record and calls date parsing
on the date cell with no all-blank short-circuit, so `''` becomes a usage
error and stops the import before later valid rows are considered.

## Fix

Before required-field parsing, if all mapped cells in the row are
empty/whitespace, `continue` (optionally track `skipped_blank`). Keep failing
rows that have any non-empty cell but a bad/missing date. Regression: trailing
and mid-file blank lines around two valid rows → 2 ready, exit 0 preview;
whitespace-only row skipped; a row with narration but empty date still errors.

## Dedupe

Not w3/226 (semicolon delimiter). Not w3/256 (amount spellings). Not w3/257
(UTF-8 BOM on ledgers — CSV BOM already works). No open note covers blank CSV
row hard-fail on import.

# `bea report … -t ''` silently means all-time (whitespace-only `-t` errors)

**Severity:** minor. **Estimate:** 10–20 minutes. **Owner:** cli. **A1:** an
agent with a template hole (`-t ""` / `-t ''`) thinks it filtered the report to
an empty period but gets the full dated window — while `-t '   '` correctly
exits 2 as an invalid time filter.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `1b1ab289`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only. Evidence: `cli/tmp/qa-20260915/c722/`, `c723/`.

## Repro

```sh
# ledger with activity spanning 2020–2021
bea --file main.bean report overview -t ''
# exit 0 — full period (e.g. 2020-01-15 through 2021-03-01), same as omitting -t

bea --json --file main.bean report overview -t ''
# data.period matches the unfiltered overview

bea --file main.bean report overview -t '   '
# exit 2 — Invalid time filter '   '. Use month, year, …
```

Same empty-string acceptance on `income-statement` / `balance-sheet` /
`trial-balance` / `balance` (they share `_load`’s `time=` path).

## Expected

Empty `-t` / `--time` is a usage error (exit 2), matching the whitespace-only
rejection and the empty-filter policy of w3/286–287 / w3/294 — not “omit the
flag”.

## Actual

Fava/`get_filtered(time='')` treats empty as no time filter; only non-empty
unparseable strings raise. `bea_engine/report.py` `_load` forwards `time`
unchanged.

## Fix

Reject `time` that is empty or whitespace-only before `get_filtered` (UsageError
naming `-t` / `--time`). Regression: `-t ''` and `-t '  '` exit 2; omitting
`-t` and valid `-t 2020` unchanged.

## Dedupe

Not w3/292 (Nomatch account → “no dated activity”). Not w3/294 (`balance ''`
account substring). No open note covers empty `--time` / `-t ''`.

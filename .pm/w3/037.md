# Import preview shows different transactions from its data after deleting a row

Severity: **major**. Owning package: **dashboard**. Estimate: **45–60 minutes**,
scoped to preview row identity, form state and regression coverage.

Production `https://beancount.io`, 2026-09-08, Chrome 152, English, System/light;
authenticated QA reader of public `open_ledger/crypto-example`. Desktop
1440×1000 and fresh narrow 390×844. Local `a315c273` and fetched
`origin/main cc3f4c2f` have the same implicated importer files; deployed SHA
unverified. Only local preview/configuration state was changed.

1. Open `/ledger/open_ledger/crypto-example/import?lang=en`. Download the page's
   CSV reference and select that same file. It parses locally as **10 Valid**,
   starting with Starbucks, Walmart, Employer Inc and ending with Insurance Co.
2. Desktop: click **Delete row** on the first row, Starbucks. The count becomes
   **9 Valid**, but Starbucks remains visible and Insurance Co disappears.
3. Fresh narrow page: upload the original sample and focus + Enter on the second
   row's **Delete row**, Walmart. Again, the preview shows the first nine
   original rows, including Walmart, and hides Insurance Co.
4. Press **Continue to Configure**. It correctly lists Starbucks, Employer Inc,
   …, Insurance Co: Walmart was removed from the actual workflow data. The
   preview the user just reviewed represented a different set of transactions.
   Press **Back**: remounting the preview restores that correct list.
5. Stronger local-state control: upload the original file, delete Starbucks,
   then edit the still-visible first row's payee to **QA Local Edit**. Preview
   shows Dec1 / Coffee Shop Purchase / -4.5. Configuration instead shows
   **Dec2 / Grocery Store / -45.67** with that edited payee: the edit acted on
   the underlying Walmart row while showing Starbucks's other fields.

Expected: deleting a transaction immediately removes that exact row from the
preview. Remaining rows keep their own fields, edits and validation state; the
same values proceed to configuration. Display row numbers may change, row
identity must not.

Working controls: deleting only the last row removes Insurance Co correctly;
reopening Preview from Configure reflects the actual remaining rows. Before
deletion, keyboard Enter opens a cell, Escape cancels its draft, and Tab commits
an amount change correctly. The shipped reference CSV is a valid 10-row input.

Root cause: `dashboard/src/features/importer/components/steps/preview/import-preview-table.tsx:73–91`
correctly filters the selected index and notifies the workflow. At155–162 it
renders `EditablePreviewRow` with **key={index}**. React reuses each surviving
component at that index for a different transaction after a first/middle deletion.
`editable-preview-row.tsx:34–43` initializes React Hook Form from `defaultValues`
only and never resets it when the row identity changes. The reused form therefore
keeps the previous transaction's values. At65–76, edits spread the new `row` prop
and replace one field, causing the observed mismatch. `EditableCell`'s local
value sync cannot repair the row form's stale field values.

Pinned dependency check: Yarn locks React Hook Form **7.71.0**. Its matching
published package artifact initializes `_defaultValues`/`_formValues` once in
`dist/index.esm.mjs:1400–1405`, creates the control only when its ref is empty
at2839, and resets reactively for `props.values` at2905–2914. This caller supplies
only static `defaultValues`, consistent with the reproduced reused-form state.
The artifact was inspected under ignored package tmp; no dependency was installed
or changed.

Producer/consumer chain: browser FileReader and `use-csv-parser` produce the
correct ten rows; `use-multi-stage-parser` returns them directly because they
are valid. `use-import-workflow.ts` holds the updated parse result.
`import-workflow-container.tsx` passes that result to Preview and then Configure;
`transaction-config-form.tsx:112–133` initializes from the real remaining rows,
explaining the working configuration and Back/remount controls. The same preview
also consumes AI-parser results, but that branch was only source-traced.

There is no failing API response behind the deletion. The monitored upload →
delete → edit → Configure → Back → clear repeat made **zero GraphQL requests**
and captured no console errors. No AI Fill, storage upload or Import button was
invoked. Actual submission and persisted ledger effects remain unverified; the
confirmed defect is that the preview differs from the data passed forward.

Fix: give each parsed transaction stable local identity retained across edits
and deletion, and keep the row form attached to that identity. Reset/reconcile
form values only for a true row replacement/new file, without overwriting an
active draft or moving validation errors to another transaction. Do not key by
array position or mutable field values; identical CSV rows must remain separate
editable records. Preserve identity through the workflow's row updates, and
keep any UI-only identity out of transaction submission data. No dependency or
API change is required.

Acceptance: real PreviewTable + EditablePreviewRow + form tests delete first,
middle and last rows and compare visible fields with the updated workflow data.
Edit a remaining row after deletion and verify that exact transaction reaches
configuration. Cover duplicate rows, validation errors, repeated deletion,
empty preview, file replacement, Enter/Escape/Tab and narrow horizontal access.
A filter-only test cannot catch this reused-form defect. Run dashboard format,
lint, tests and build; verify the browser controls without booking transactions.

Dedupe: searched all open/completed `.pm` for import preview, row deletion,
inline editing and stale form identity. `w3/015` is logical CSV record parsing,
not an initially correct preview becoming stale. Completed w2/m23's full DoD
concerns optional route requests and does not cover importer form identity;
CLI import and bank-preview tasks use different implementations. History traces
the index key/default-values pattern to `af5339de`; `aeec496b` localizes copy

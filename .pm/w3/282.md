# `bea query` with two SELECT statements joined by `;` runs only the first (exit 0, no warning)

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** cli. **A1:** an
agent that packs two BQL statements into one argv (`SELECT …; SELECT …`) gets
exit 0 and only the first result table/JSON — the second statement is dropped
with empty stderr, so automation can think both queries succeeded.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `18bb0e6e`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
bea --file main.bean query 'SELECT account LIMIT 1; SELECT narration LIMIT 1'
# exit 0 — prints only the account column / Assets:Cash
# no stderr about the second statement

bea --json --file main.bean query 'SELECT account LIMIT 1; SELECT narration LIMIT 1'
# exit 0 — data.columns/rows are only the first SELECT

# Trailing semicolon alone is fine:
bea --file main.bean query 'SELECT account LIMIT 1;'
# exit 0 — same single result
```

Working control: each SELECT in its own `bea query` invocation returns its own
table.

## Expected

Either run every statement (multiple result sets / concatenated output with
clear separators) or refuse with a usage error naming the extra statement
(“one BQL statement per invocation; got 2”). Do not exit 0 while discarding
work.

## Actual

The engine/CLI accepts the string, executes the first statement only, and
reports success. JSON carries a single `columns`/`rows` payload from that
first statement.

## Fix

Detect a second top-level statement after `;` (ignoring a single trailing
`;`) in the one-shot query path and raise `UsageError`, or execute all and
return a documented multi-result shape. Regression: the two-SELECT string
above exits 2 (or returns both); trailing `;` and single SELECT stay green.

## Dedupe

Not w3/262 (whitespace-only query). Not w3/234 (`--json` shell utilities). No
open note covers multi-statement `;` dropping.

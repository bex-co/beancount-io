# Mobile Reports plots profitable months as negative Net Profit

**Severity:** major — the chart reverses the meaning of profit and loss. **Estimate:** 35–50m, mobile presentation conversion and focused regression coverage. **Pillar:** A2 — readers can trust the example ledger's financial summaries.

Reproduced 2026-09-08 on local native build 1.20260906.47, source a315c273, production https://beancount.io, Expo MCP, iPhone 17e / iOS 26.5, English/light. Authenticated reader of synthetic public `open_ledger/example`; native sign-in survived relaunch.

1. Select the public example through discovery, then open the Reports tab.
2. In the default 6M view, April–September income bars exceed expense bars, yet the blue Net Profit line is below zero throughout.
3. Select 1M. September has income $4,639.70 and expenses $2,284.81, but its blue Net Profit dot lies at -$2,354.89, below the -$2K tick.
4. Terminate/relaunch the app, dismiss the development warning banner if present, and open Reports again. The 6M negative profit line repeats.

Expected September display: **+$2,354.89 profit**, since 4,639.70 - 2,284.81 = 2,354.89. Actual is the inverse sign. The corresponding income/expense bars and the Savings flow use the expected presentation convention.

Actual authenticated `IncomeStatement` GraphQL read with `ledgerId: "open_ledger/example", conversion: "at_cost"` succeeds. September 30 row values are:

| series | API USD balance | correct chart value |
| --- | ---: | ---: |
| incomeData | -4639.7 | 4639.70 |
| expensesData | 2284.81 | 2284.81 |
| netProfitData | -2354.89 | 2354.89 |

Authenticated REST `GET /api-gateway/v1/ledgers/open_ledger/example/statements/income-statement?conversion=at_cost` returns the same signed values in `income_data`, `expenses_data`, and `net_profit_data`. Anonymous REST requires authentication; that response is not counted as a product failure. A bounded JS error-log capture returned no text, which is not complete runtime-log coverage.

Root cause in **mobile**: `src/screens/reports-screen/reports-screen.tsx:97–109` negates income after `pointsToMonthlySeries`, but passes `netProfitData` through unchanged at 103. `src/common/series-util.ts:44` retains the source sign. `src/common/d3/income-expense-bar-chart.tsx:97–98` includes these negative values in the y-domain and at 141–145/190–196 plots the line/dots at their supplied values. Its documented contract calls negative net a loss month; the legend labels it Net Profit.

Producer/serializer trace: ledger `src/features/ledger/service/ledger-finance-service.ts:153–162` sums income and expense accounting balances into net_profit_data. Gateway `src/features/ledger/api/resolvers/ledger-finance-resolver.query.ts:248–251` preserves the balance map. Both successful API reads therefore have the established accounting signs. No API/schema or stored-ledger change is required.

Fix: negate the net-profit series at the Reports presentation boundary, just as income is converted there. Keep a real loss negative and zero at zero; do not use absolute value. Preserve currency selection, date alignment, range filtering, and existing loading/error behavior. Avoid changing the shared generic balance-series helper, which must retain signed asset/liability balances.

Acceptance: the exercised 6M and 1M journeys plot profit above zero, including September +2354.89. A focused check through the real Reports series transformation must cover profitable, loss, zero and single-month cases and verify alignment with the income/expense bars. Keep loss months below zero; define empty/loading/network-failure behavior independently from zero profit. No production write is needed.

Blast radius: one production `IncomeExpenseBarChartD3` caller, Reports at line160; `app/(app)/(tabs)/reports.tsx` is its native route. One mobile netProfitData consumer was found. Working control: the same screen converts income -4639.7 to a positive $4.6K bar and leaves expense +2284.81 positive; Home 1M shows the corresponding +$2,354.89 net-worth change for this fixture. Other generic signed-balance chart consumers should remain unchanged.

Dedupe: searched all open/completed `.pm` for net profit, sign, inversion and Reports, and scanned open milestone summaries. `w3/005` concerns a dashboard synthetic-account link, not this sign conversion. No overlapping native item or already-landed fix found. `git log -S 'const net = pointsToMonthlySeries'` traces the omission to `0bf3e112`; subsequent Reports changes retain it. No verified earlier correct combined chart establishes a historical regression.

Unverified: live loss-month fixture, permission/session failures, network outage, dark mode for this chart, Android and physical hardware. The loss behavior is source-inferred and a required regression case, not a live observation. No fixes or shipping included.

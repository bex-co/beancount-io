# Statement account expanders expose no accessible name or state

Severity: minor. Owner: dashboard. Estimate: 20–35 minutes. A2: keyboard and
screen-reader users can identify which account a disclosure controls and
whether its children are expanded.

Environment: production https://beancount.io, Chrome 152, authenticated QA
public reader on synthetic `open_ledger/example`, English/System light.
Desktop 1440×1000 and fresh narrow 390×844 on 2026-09-08. Source HEAD a315c273;
fetched origin/main cc3f4c2f has no matching correction. Deployed build identity
is not proven identical to the checkout.

Reproduce:

1. Open `/ledger/open_ledger/example/balance-sheet?time=2016` and wait for the
   Assets List. Inspect/focus the chevron beside the Assets account link.
2. The accessible subtree is an unnamed `button`, followed by the separate
   `link "Assets"`. The button has empty text and no aria-label, title or
   aria-expanded; the adjacent sibling link does not name it.
3. Click the chevron: Checking and other child links disappear, but the button
   exposes exactly the same unnamed/state-free accessibility subtree.
4. Focus it and press Enter at desktop or Space at narrow width: children
   return. Fresh narrow loading and collapse/expand repeat the same missing
   semantics. Keyboard activation itself works and is not the defect.

Expected: each native disclosure button has a localized name identifying its
account, and its expanded/collapsed state tracks actual child visibility.
Use the full account path to distinguish repeated labels such as US. Keep
activation on Enter/Space and the separate account-navigation link. This follows
the W3C [disclosure pattern](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/).

Root cause: `dashboard/src/features/reports/balance-sheet/hierarchy-list.tsx:189`
renders an icon-only native button and toggles the children at `:237`, without
accessible name/state attributes. SVG chevrons have no textual label. The shared
TreeNode handles both top-level and nested accounts.

Fix that button with existing localization conventions and `aria-expanded`
bound to `isExpanded`. If a controlled-region relationship is added, use stable
unique IDs; do not require a custom tree widget or keyboard model to repair
this native disclosure. Preserve row-click expansion, propagation guards,
account links and focus after toggling.

Blast radius: HierarchyList is shared by Balance Sheet, Income Statement, Cash
Flow and Trial Balance. This live reproducer covers Balance Sheet at both
widths; other report routes are source-traced callers. The account link is
already named and working. Fresh desktop console has zero errors/warnings;
expansion changes local UI without an API call or ledger mutation.

Acceptance: the accessibility tree identifies the account on every expander,
reports expanded=true initially and false after collapse, and keeps state in
sync after keyboard/mouse toggles. Confirm a nested repeated-label account and
fresh narrow rendering. A focused accessibility-tree/browser check is enough
for this small semantic correction; avoid tests that only mirror class names.

Dedupe: searched all open/done board records for hierarchy/tree accessibility,
expander names/state and account labels. No overlap found. Journal pagination
`w3/006`, Files keyboard access `w3/008` and Sharing copy labels `w3/013` use
different components. Targeted history traces this unlabelled control to
af5339de, with no subsequent semantic fix.

Unverified: actual VoiceOver/NVDA speech, other locales, native app and every
shared report route. No product implementation or shipping included.

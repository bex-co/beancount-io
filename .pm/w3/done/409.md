# doctor roundtrip deletes pre-existing sibling files, including ledger includes

**Major · 35–50m · cli · A1/A2.** Running a diagnostic can destroy existing
files beside the ledger and report success. Native roundtrip uses predictable
output names, overwrites whatever is there, then deletes both names. The bea
wrapper does not check for collisions before delegating.

Found 2026-09-21 at HEAD `d5e8e06d`, checkout `bea 0.3.0`, Python 3.13.0,
macOS 26.5.1 arm64. Two pristine synthetic directories, fresh real commands,
isolated config/cache, closed stdin, bounded subprocesses. No real ledger used.

## Reproduce

Create these three files together in a disposable directory.
`main.bean`:

```beancount
include "main.roundtrip1.bean"
2026-01-01 open Assets:Cash USD
2026-01-02 * "Opening"
  Assets:Cash 5 USD
  Equity:Opening
```

`main.roundtrip1.bean`:

```beancount
; User-owned included accounts
2026-01-01 open Equity:Opening USD
```

`main.roundtrip2.bean`:

```beancount
; User-owned unrelated notes
2026-01-03 note Assets:Cash "Keep this file"
```

```sh
bea --json --file /absolute/main.bean check
# exit 0, valid=true
bea doctor roundtrip /absolute/main.bean
# exit 0; stderr: Entries are the same. Congratulations.
bea --json --file /absolute/main.bean check
# exit 1: missing main.roundtrip1.bean and unknown Equity:Opening
```

Actual: both sibling files are **absent** after roundtrip. The root's hash is
unchanged, but the included account declaration and unrelated note file are
gone. Captures retain their prior complete contents/hashes and null after
hashes. Both pristine repetitions agree; stdout is empty and stderr contains
the success trace with no collision warning. This is source-file loss, not
just a misleading exit status.

Control: a valid ledger with neither sibling name present completes normally
and preserves its source. An invalid ledger likewise leaves its root intact
and reports the existing nonzero diagnostic policy. Preserve those behaviors.

## Cause and bounded repair

`cli/src/cli/commands/doctor.py:161` `_forward_roundtrip` prechecks syntax,
then calls `launch.run_native("bean-doctor", ["roundtrip", ...])` or, for
invalid input, `capture_native` with the same arguments. Neither branch
guards the native output paths. `cli/src/cli/engine/launch.py:76` forwards
the absolute original filename to the installed engine command.

The pinned installed `beancount/scripts/doctor.py` `roundtrip` implementation
derives `<stem>.roundtrip1<suffix>` and `<stem>.roundtrip2<suffix>` at lines
140/161, opens each with `w`, then unconditionally removes the paths in its
`finally` block around line 190. Its input comparison succeeds because it
loaded the original include before overwriting it. This is an upstream
temporary-file behavior exposed by bea; do not fork or reimplement upstream.

Add a wrapper boundary that refuses existing artifact paths **before either
native execution branch can write**, naming the conflicting paths. Account
for symlinks, including dangling symlinks, and native filename resolution;
do not back up, overwrite or delete another file to make the diagnostic run.
Alternatively isolate native artifacts while preserving correct includes and
plugin context if that can be done with existing helpers. A simple accurate
refusal is sufficient for this item. Keep root/include bytes unchanged,
retain normal diagnostics, and add a real-command regression for the three
file fixture plus the no-collision control. No dependencies or API work.

---

**Resolved 2026-09-22** — `doctor roundtrip` refuses when its scratch names are
already taken, instead of overwriting and deleting whatever is there.

Upstream derives `<stem>.roundtrip1<suffix>` and `<stem>.roundtrip2<suffix>`
beside the ledger, opens both with `w`, and removes them in a `finally`
unconditionally — so a ledger include or any unrelated file at those paths was
destroyed while the diagnostic reported `Entries are the same.
Congratulations.` at exit 0.

`_refuse_roundtrip_collisions` runs before *either* forwarding branch, so the
valid and invalid paths are both covered, and exits **4** naming the
conflicting paths, with the two-line remedy. Upstream is neither forked nor
reimplemented, exactly as the note required — the wrapper simply declines to
let it run.

`_roundtrip_artifacts` derives the names the way upstream does, and a test
reads that off `beancount.scripts.doctor`'s own source. If upstream renames or
relocates its scratch files the test fails, rather than the guard quietly
protecting paths nobody writes any more.

Symlinks are handled with `os.path.lexists`, not `exists`: a **dangling**
symlink at an artifact path is not an absent file, because opening it for
write would create its target and the cleanup would then remove it. Verified —
the refusal fires and the link itself survives.

Verified on the note's three-file fixture: exit 4, all three files
byte-identical, no congratulations, and `bea check` still exits 0 afterwards.
Controls hold — a ledger with the names free runs the diagnostic unchanged and
leaves no artifacts, and an invalid ledger keeps w3/371's behaviour (non-zero,
no congratulations, source untouched).

Regression coverage is `cli/tests/test_doctor_roundtrip_collisions.py`,
including that one colliding file is enough. Reverting the guard fails 6 of
its 9; the upstream pin and both ordinary-run controls pass either way.
`cd cli && make check-all` passes (1946 tests).

Chosen deliberately: the note offered isolating the native artifacts as an
alternative and said "a simple accurate refusal is sufficient". Refusal is what
shipped — isolating would mean relocating the ledger for the duration, which
risks include and plugin resolution for a diagnostic that is meant to be
read-only.

Unverified, as in the note: other platforms, symlink *aliases* of the ledger
itself, and an artifact created concurrently between the check and the run.

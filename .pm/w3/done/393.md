# JSON listings still drop metadata from balance, price, pad, and close directives

**Severity:** minor. **Owner:** cli. **Estimate:** 40–55 minutes.
**A1:** agents inspecting reconciliation provenance or quote sources need the
metadata already present in the ledger. This completes the read contract from
[w3/289](./done/289.md), whose repair covered six other directive types.

Found 2026-09-21 by repeated CLI QA on `main`, HEAD `e213e53b`, checkout
`cli/.venv/bin/bea` 0.3.0, Python 3.13.0, macOS 26.5.1 arm64. Two pristine
synthetic fixtures, fresh subprocesses, closed stdin, captured stdout/stderr,
35-second timeouts, isolated config/cache/data directories; no login needed.
Concurrent changes to CLI text sanitization were recorded and do not touch
the affected models, reader, or listing adapter.

## Reproduce

In a disposable directory, create `main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Cash USD
  audit: "open-control"
2026-01-01 open Equity:Opening USD
2026-01-02 pad Assets:Cash Equity:Opening
  audit: "opening-pad"
2026-01-03 balance Assets:Cash 5 USD
  audit: "bank-statement"
2026-01-03 price HOOL 25 USD
  audit: "manual-quote"
2026-01-04 close Assets:Cash
  audit: "closed-by-user"
```

Run each command with an absolute root path:

```sh
bea --json --file "$PWD/main.bean" check
bea --json --file "$PWD/main.bean" list pad
bea --json --file "$PWD/main.bean" list balance
bea --json --file "$PWD/main.bean" list price
bea --json --file "$PWD/main.bean" list close
bea --json --file "$PWD/main.bean" list open
bea --file "$PWD/main.bean" query PRINT
```

Both runs: all commands exit **0**, stderr is empty, and file hashes remain
unchanged. Check reports `valid: true`. The four affected listings return
these `data` arrays, with no `meta` key:

```json
[{"date":"2026-01-02","account":"Assets:Cash","source_account":"Equity:Opening"}]
[{"date":"2026-01-03","account":"Assets:Cash","amount":{"number":"5","currency":"USD"},"tolerance":null}]
[{"date":"2026-01-03","currency":"HOOL","amount":{"number":"25","currency":"USD"}}]
[{"date":"2026-01-04","account":"Assets:Cash"}]
```

Controls: `list open` returns `"meta":{"audit":"open-control"}` for
`Assets:Cash`. `query PRINT` retains each of the four omitted `audit` values.
The metadata is loaded successfully and lost only in the listing conversion;
the on-disk ledger is intact.

## Expected and cause

Each JSON row includes user metadata under `meta`, using the same typed-value
serialization and source/internal-key exclusions as the other list commands.
That is the explicit expected contract in w3/289 and the behavior of the
working open/transaction controls. Compact human tables need not gain columns.

- `cli/src/bea_engine/ledger/models.py:221`, `:228`, `:237`, `:263`:
  `CloseDirective`, `BalanceDirective`, `PadDirective`, and `PriceDirective`
  omit `meta`, unlike the six models changed by w3/289.
- `cli/src/bea_engine/ledger/reader.py:280`, `:308`, `:369`, `:559`:
  their list constructors omit `metadata_to_json(entry.meta)`.
- `cli/src/bea_engine/ledger/listing.py:20` dispatches all four commands to
  these readers; `:44` serializes exactly the model fields. The frontend
  cannot recover the discarded keys.

Caller search covered all `list_prices`, `list_balances`, `list_closes`, and
`list_pads` references: the shared listing dispatcher serves the four CLI
commands. The same models also serve add/writer paths; preserve those paths
when adding default-empty metadata fields. This finding requires no new
metadata flags and no REST/GraphQL/MCP behavior changes.

## Fix and acceptance

Reuse `metadata_to_json` for these four readers and add their model fields.
Extend `tests/test_list_directive_metadata.py`, whose current case table only
covers commodity/note/event/open/custom/document.

- [ ] All four commands retain their fixture's `audit` value under `meta`.
- [ ] The open and transaction controls still retain user metadata, while
  `filename`, `lineno`, and internal keys stay excluded consistently.
- [ ] Empty metadata serializes consistently, existing filters and generated
  markers remain correct, and reading never changes the source files.
- [ ] Add meaningful regression coverage and run `make check-all` in `cli/`.

---

**Resolved 2026-09-21** — `list balance`, `list price`, `list pad` and
`list close` now report user metadata under `meta`, completing w3/289's read
contract.

The note's location work was exact. `CloseDirective`, `BalanceDirective`,
`PadDirective` and `PriceDirective` gain `meta: dict[str, Any]` with a
default-empty factory, matching the six models w3/289 repaired, and their four
reader constructors call the same `metadata_to_json(entry.meta)` the others
use — so the source/internal-key exclusions come along for free.

On the note's caution about the shared add/writer paths: they are safe by
construction, not by care taken. `write_close`, `write_balance`, `write_pad`
and `write_price` build their Beancount entries with a literal `meta={}` and
never read the model's field — exactly as `write_note` and `write_event`
already do for models that have carried `meta` since w3/289. The new field is
read-only on these paths.

Acceptance, all verified on the note's own fixture:

- [x] All four commands retain the fixture's `audit` value under `meta`.
- [x] `list open` and `query PRINT` controls unchanged; `filename` and
      `lineno` stay excluded (the shared helper is what guarantees this, and
      the existing assertions cover it).
- [x] Empty metadata serializes as `{}` rather than a missing key, so a
      consumer can index it — pinned by a new test on `Equity:Opening`.
- [x] Reading never rewrites the source: hashed before and after all four
      listings.
- [x] `cd cli && make check-all` passes (1697 tests).

`tests/test_list_directive_metadata.py` gains the four kinds to its case table
plus the empty-metadata, no-rewrite and `query PRINT` tests; its docstring now
says that adding a directive kind to `list` means adding a row there.
Reverting the fix fails the case table on `pad`.

One test outside that file needed updating: `test_engine_helper.py`'s
`test_items_are_business_json_with_no_beancount_objects_on_the_wire` pinned the
exact `list price` payload and now sees `"meta": {}`. That is the intended
shape — the same one the six already-fixed kinds emit — so the expectation was
corrected rather than worked around, with a comment saying why.

Unverified, as the note says: managed-feed and plugin-generated metadata, and
non-macOS platforms.

## Objective

Remove both truncating writes from the in-place format path so an interrupted or
killed run can never leave a partial or empty ledger: produce the formatted
bytes without touching the target, then replace the target in one atomic step.

## Context

- Two unstaged truncating writes exist today: upstream `bean-format --in-place`
  (launched from `cli/src/cli/commands/format.py` ~l.165) and the CLI's own
  `file.write_bytes(fixed)` in `_format_in_place`. `_strip_bom` writes too.
- Measured on a 3.2 MB fixture (`w3/435`): the target passes through **0 bytes
  twice** in every uninterrupted run
  (`3228995 -> 0 -> 3308995 -> 0 -> 3228995`), and a SIGINT fired the instant the
  size reads 0 leaves a 0-byte ledger with exit 130 in 5/5 runs.
- The engine already has the pattern to copy: `candidate_file` +
  `os.replace` in `cli/src/bea_engine/ledger/write.py` (design note ~l.181–196),
  with its `finally` cleanup of `.bea-*` candidates.

## Steps

1. Stop using upstream `--in-place`: run `bean-format` to a staged path (or
   capture its stdout) and apply the CLI's canonical-indent pass to those bytes
   in memory, so the target is read but never written until the end.
2. Write the final bytes to a staging candidate in the target's directory and
   `os.replace` it over the target — one atomic replacement per file, under the
   lock from t001.
3. Fold the BOM strip into the same in-memory pass instead of a separate write.
4. Ensure the staging candidate is removed on every exit path, including
   `KeyboardInterrupt`, so an interrupted run leaves no `.bea-*` litter.
5. Keep the existing "formatted / unchanged / failed" accounting and exit codes
   based on a byte comparison of the input against the final bytes.

## Files

- `cli/src/cli/commands/format.py`
- `cli/src/bea_engine/ledger/write.py` (reuse of the candidate helper)

## Acceptance criteria

- [x] Sampling a target's size throughout an uninterrupted `format -i` run never
      observes 0 bytes and never observes a half-written size.
- [x] SIGINT at any offset, including the former zero-byte windows, leaves each
      target byte-identical or fully formatted; exit 130; no `.bea-*` file left.
- [x] `format -i` twice in a row reports no change the second time and
      `format --check` on the result exits 0.
- [x] Recursive formatting still names the affected files when one of several
      fails, and unaffected files are untouched.

## Out of scope

- SIGTERM/SIGHUP handling in the engine entry point (`w3/440`).
- The padding-width and multi-line-string correctness bugs (`w3/441`, `w3/415`).

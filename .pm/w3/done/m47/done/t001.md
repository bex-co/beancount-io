## Objective

Make `bea format --in-place` take the same file lock every engine-side writer
takes, so it can no longer interleave with a concurrent `bea add` / `import` /
`ask` write and overwrite a snapshot that has already been superseded.

## Context

- `cli/src/cli/commands/format.py` `_format_in_place` (~l.150–180) reads each
  file, runs upstream `bean-format --in-place`, then may `file.write_bytes(...)`.
  It takes no lock.
- `cli/src/bea_engine/ledger/write.py` `append` (~l.822–824) is today the only
  caller of `lock_file(...)`; it locks the root and the destination, re-verifies
  the snapshot, then replaces atomically.
- Reproduced in `w3/434`: `format -i` started ~2.5 s into a `bea add` on a
  40 000-transaction ledger leaves `add` at exit 0 ("Added 1 transaction") with
  the transaction absent from the file.

## Steps

1. Expose the engine's locking helper to the CLI-side formatter (or move the
   in-place write behind an engine entry point that already locks), so the lock
   covers reading the file, running upstream, and writing the result back.
2. Lock the root ledger and each target file for the whole in-place pass, in a
   deterministic order, so two concurrent `format -i` runs cannot deadlock.
3. Keep recursive formatting's partial-failure reporting intact: a file that
   cannot be locked is reported like any other failed file, not skipped
   silently.

## Files

- `cli/src/cli/commands/format.py`
- `cli/src/bea_engine/ledger/write.py` (helper exposure only)

## Acceptance criteria

- [x] `grep -rn lock_file cli/src/` shows the in-place format path among the
      callers.
- [x] With an `add` in flight, `format -i` never produces "`add` exit 0 and the
      directive missing": across the `w3/434` offset sweep every run either
      keeps the directive or fails `add` with exit 4.
- [x] Two concurrent `format -i` runs on the same ledger both terminate, and the
      result is a fully formatted file.

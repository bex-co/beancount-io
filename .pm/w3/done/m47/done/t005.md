## Objective

Add tests that would have caught both symptoms — the lost concurrent append and
the interrupted zero-byte ledger — and that fail against the pre-fix code.

## Context

- `cli/tests/test_interrupt_contract.py` already drives signal cases and is the
  natural home for the interrupt test.
- The reproducers from `w3/434` and `w3/435` are timing-based; the tests must be
  deterministic instead of sweeping offsets.

## Steps

1. Concurrency: hold the ledger lock from the test (or block the formatter at a
   seam) while an `add` commits, then let `format -i` proceed, and assert the
   appended directive survives — and that when `add` loses the race it exits 4
   and writes nothing.
2. Atomicity: assert the target is never truncated in place — e.g. that the
   final replacement is an `os.replace` of a staged candidate, and that no
   `write`/`open(..., "w")` targets the ledger path — plus a test that samples
   the file size during a run and never sees 0.
3. Interrupt: extend the interrupt contract test so a SIGINT during an in-place
   format leaves the file byte-identical or fully formatted, exits 130, and
   leaves no `.bea-*` candidate.
4. Idempotence: format twice, assert no second change and `--check` exit 0.
5. Confirm each new test fails when the fix is reverted.

## Files

- `cli/tests/test_interrupt_contract.py`
- `cli/tests/` (format command tests)

## Acceptance criteria

- [x] Each new test fails on the pre-fix code and passes after.
- [x] Tests assert observable file state and exit codes, not internal call
      counts alone, and none is timing-dependent enough to flake in CI.
- [x] `make check-all` passes inside `cli/`.

## Out of scope

- Performance benchmarks for large-ledger formatting.

# Scroll only beancount files to the end on open, not every text preview

Source: continuous dashboard QA, 2026-10-04.
Pillar: A2 — opening a README or config preview at its last line looks broken and buries the file's introduction.

The file preview's "no target line: scroll to end so users see the latest transactions" behavior applies to every text file. The rationale fits chronological `.bean` ledgers, but `README.md` also opens at its final lines (verified on `/ledger/open_ledger/example/files/blob/main/README.md`, fresh load, scrollbar at bottom).

Root cause: `dashboard/src/features/ledger-editor/file-editor/components/ledger-file-view/text-editor.tsx:183` reveals the last line unconditionally; the component already knows the file `language` (line 143 uses it for the beancount mode) but does not consult it here. Explicit `?line=`-style deep links already bypass this path and are unaffected.

Repro: fresh-load any non-ledger text blob (e.g. the example ledger's `README.md`) — the preview starts at the end of the file instead of line 1. Repeat for `main.bean` to confirm the intended ledger behavior stays.

Acceptance: non-beancount text previews open at line 1; `.bean` previews keep the scroll-to-latest behavior; deep-linked lines still center. Add a test for both branches, run the dashboard checks, and ship.

Scope: dashboard ledger-editor only. Estimated under one hour.

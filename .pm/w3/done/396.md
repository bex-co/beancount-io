# Filtering balances to a child account still includes its unmatched parent's direct postings

**Severity:** major. **Owner:** cli. **Estimate:** 35–50 minutes.
**A1:** `bea balance Fund` can report 125 USD for a fund that holds 25 USD.
The extra 100 USD belongs to its parent account, which is retained only to
show the tree structure. This also affects report trees when the parent and
child occur in the same transaction.

Found 2026-09-21 on `main`, HEAD `ada8bb97`, checkout `cli/.venv/bin/bea`
0.3.0, Python 3.13.0, macOS 26.5.1 arm64. Fresh synthetic fixtures and
subprocesses, absolute `--file`, isolated config/cache/data, closed stdin,
35-second timeouts. All captures exit 0 with empty stderr and unchanged file
hashes. No hosted account is involved.

## Reproduce

Create `main.bean` in a disposable directory:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Brokerage USD
2026-01-01 open Assets:Brokerage:Fund USD
2026-01-01 open Equity:Opening USD
2026-01-02 * "Both"
  Assets:Brokerage 100.00 USD
  Assets:Brokerage:Fund 25.00 USD
  Equity:Opening
```

```sh
bea --json --file "$PWD/main.bean" check
bea --file "$PWD/main.bean" balance Fund
bea --json --file "$PWD/main.bean" balance Fund
bea --json --file "$PWD/main.bean" report trial-balance -a Fund
bea --json --file "$PWD/main.bean" report overview -a Fund
bea --json --file "$PWD/main.bean" query \
  "SELECT account, sum(position) WHERE account = 'Assets:Brokerage:Fund' GROUP BY account"
```

Check reports valid. The human balance says:

```text
Valuation: USD; account: Fund
  Assets       125.00 USD
    Brokerage  125.00 USD
      Fund      25.00 USD
```

JSON retains `Assets:Brokerage.balance.USD = "100.00"` even though its name
does not match `Fund`. Its `balance_children` and the Assets root therefore
report `"125.00"`. Trial balance returns the same tree; overview reports
`totals.assets.USD = "125.00"`. The independent BQL control returns exactly
`25.00 USD` for Fund. Repeating balance and trial balance from a pristine
copy produces the same incorrect rollup.

Expected: retain the Brokerage and Assets ancestors as structure, but give
their displayed filtered subtree totals 25.00 USD and exclude Brokerage's
own unmatched 100.00 USD. `cli/docs/USAGE.md` specifies balances for matching
subtrees with ancestors retained for structure; w3/322 explicitly requires
report totals for matching accounts as well.

## Controls and boundary

- `balance Brokerage` and `report trial-balance -a Brokerage` correctly
  report 125.00 USD because that filter includes both direct parent postings
  and child postings. Preserve this result.
- With the parent and child contributions in **separate** transactions,
  `balance Fund` still incorrectly reports 125.00, while `report trial-balance
  -a Fund` and overview correctly report 25.00. Reports prefilter whole
  transactions, hiding the parent-only transaction before the faulty tree
  pruning; balance builds the whole tree first. The combined fixture exposes
  the same helper defect through both paths.
- Source data and the Fund leaf are correct. This is erroneous aggregation
  of out-of-scope postings, not a lost write or arithmetic rounding issue.

## Root cause and fix

`cli/src/bea_engine/report.py:537` `_prune_tree` keeps a node when it matches
or when any child survives. At `:567` it always sums **`node.balance`** with
the retained child totals, even when the node survives solely as an ancestor:

```python
return dataclasses.replace(
    node,
    children=kept,
    balance_children=_sum(node.balance, *(child.balance_children for child in kept)),
)
```

Keep the original direct balance only when the node itself satisfies the
caller's matcher and closed-account policy. Otherwise preserve the node as
structure with an empty direct balance and a total computed from retained
children. Keep the corresponding direct-activity metadata honest. Preserve
substring matching for `balance` and parent/regex matching for reports.

Caller search: `_balances` at `report.py:85` calls this helper directly;
`_prune_sections` at `:534` feeds overview, income statement, balance sheet,
and trial balance. Runtime coverage here is balance, trial balance, and
overview; the other two report paths share the helper but remain unverified
for this fixture. No REST/GraphQL/MCP change is needed.

- [ ] Child-only filters produce 25.00 USD at the leaf and structural
  ancestors for both combined and separate transaction fixtures.
- [ ] Selecting Brokerage still includes its own 100.00 USD plus the child's
  25.00 USD; unfiltered values remain intact.
- [ ] Cover the shared prune with real command regressions, including the

---

**Resolved 2026-09-21** — an ancestor kept only for structure no longer
contributes its own postings to a filtered total.

`_prune_tree` keeps a node when it matches *or* when a child survived, but
always summed `node.balance` into the subtree total. Now the node's own balance
is included only when the node itself is in scope; otherwise it is kept as
structure with an empty direct balance, and the total comes from the retained
children alone.

The note's "keep the direct-activity metadata honest" is done too: a structural
ancestor reports `balance: {}` and `has_txns: false`, so a consumer reading the
node gets the same answer as the rollup rather than a 100.00 that contradicts
its own 25.00 total.

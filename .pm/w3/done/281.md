# `bea import --csv auto` swallows narration-column ambiguity (and never treats `Original Description` as narration)

**Severity:** minor. **Estimate:** 25–40 minutes. **Owner:** cli. **A1:** an
export with both `Description` and `Memo` (or two other narration synonyms)
fails with a generic “Cannot read a column mapping… Name them with --csv”
instead of the documented “Several columns could be narration (…)” hint; and
the docs’ own `Description` + `Original Description` example never triggers
ambiguity at all — `Original Description` is not a synonym, so the longer bank
text is silently ignored while `narration=Description` is chosen.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `0f91a9cf`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
# Contested narration, no payee — ambiguity computed then discarded
printf '%s\n' 'Date,Description,Memo,Amount' \
  '2024-03-10,Cafe,MEMO TEXT,-4.50' > dm.csv
bea --file main.bean import dm.csv --csv auto --account Assets:Bank:Checking
# exit 2
# Error: Cannot read a column mapping from the header row of dm.csv.
#   Its columns are: Date, Description, Memo, Amount. Name them with --csv …
# (no “Several columns could be narration …” note)

# Docs example — Original Description never competes
printf '%s\n' 'Date,Description,Original Description,Amount' \
  '2024-03-10,Cafe,POS CAFE XYZ,-4.50' > od.csv
bea --file main.bean import od.csv --csv auto --account Assets:Bank:Checking
# exit 0 — config narration=Description; narration is "Cafe"
# Original Description "POS CAFE XYZ" is dropped with no ambiguity warning
```

Working control: a single narration synonym (`Description` only) infers cleanly;
an explicit `--csv …,narration=Memo` selects Memo.

## Expected

Per `IMPORTING.md`: when two columns claim the same role, report the ambiguity
and leave that role unmapped (or fail naming the contested columns). Include
`original description` (and similar) in the narration synonyms so the documented
pair actually contests. When inference otherwise fails only because the
ambiguous role was required, still surface the ambiguity list in the usage
error.

## Actual

`infer_mapping` records `ambiguities` for Description+Memo, then `return None`
because neither `payee` nor `narration` was filled — the caller’s `inferred is
None` branch never reads `ambiguities`. `Original Description` is absent from
`_HEADER_SYNONYMS["narration"]`, so it never contests `Description`.

## Fix

1. Add `"original description"` (and optionally `"orig description"`) to
   narration synonyms.
2. When returning `None` for missing date/amount/payee|narration, still raise
   (or return a structured failure) that includes any collected `ambiguities`,
   matching the existing notes path in `import_._inferred_mapping`.

Regression: Description+Memo names narration ambiguity; Description+Original
Description either warns or requires `--csv`; single-Description control
unchanged.

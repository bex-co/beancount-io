## Objective

Ensure no ledger path parameter can inject `/`, `?`, or `#` into an upstream
Fava or Gitea request path — defense in depth behind t001's boundary
validation.

## Context

- Raw interpolation, no encoding: `src/foundation/fava/Api.ts:4170` (DELETE),
  `:4193` (PUT), `:4211` (GET); Gitea `src/features/gitea/client/gitea-api.ts:5668-5690`.
- Passthrough client `src/foundation/fava/api-client.ts` forwards `path` untouched.

## Steps

1. Wrap each path segment with `encodeURIComponent(...)` in the generated-client path templates, or add a single request-level hook in `api-client.ts` / the Gitea client that encodes segments.
2. Confirm the upstream services expect percent-encoded segments (they do — Gitea's repo API takes encoded owner/repo).
3. Verify `undefined.git` responses no longer occur for odd inputs (they are now rejected upstream in t001, but this guarantees correctness if any path param is ever unvalidated).

## Files

- `backend-cluster/backend-v2/src/foundation/fava/Api.ts`
- `backend-cluster/backend-v2/src/foundation/fava/api-client.ts`
- `backend-cluster/backend-v2/src/features/gitea/client/gitea-api.ts`

## Acceptance criteria

- [x] A unit test proves a param containing `/` or `?` cannot alter the upstream request path (it is percent-encoded).
- [x] DELETE routes to exactly the authorized `owner/name` endpoint; a `name` like `x?y` or `x/star` can no longer reach a different Gitea endpoint.

## Out of scope

- Boundary validation (t001); the fail-open probe (t003).

## Implementation and verification

- Both backend-v2 generation commands now use a shared generator hook that
  percent-encodes owner/repository coordinates in every affected route. The
  generated diff contains only those interpolation changes; regeneration is
  byte-for-byte stable. Existing file-path and query semantics are preserved.
- Seven real-client request tests cover Fava GET/PUT/DELETE, Gitea GET/PATCH/DELETE,
  and nested file reads. Every case failed before regeneration and passed after.
- Passed typecheck, lint/dead-code detection, OpenAPI regeneration, and all
  293 unit suites / 4,693 tests. Jest emitted a worker teardown warning, but
  all assertions and the command exit status passed.
- Review found a separate unencoded ledger-service-to-Gitea hop. It is tracked
  by t008 in the ledger package before milestone closeout; this task proves
  backend-v2's outgoing URLs, not independent protection of that second hop.

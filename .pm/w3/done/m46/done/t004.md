## Objective

When the server returns a 200 whose body does not match the expected ledger
schema, the CLI must report a clear "unexpected server response" error instead
of the raw `KeyError: 'id'` surfaced as `category: validation, message: 'id'`.

## Context

- `cli/src/cli/api/rest_client/api/ledger_v_1/get_ledger.py` parses 200 bodies
  with `GetLedgerResponse200.from_dict`, which does `d.pop("id")` and raises
  `KeyError('id')` on a body missing `id`.
- `cli/src/cli/api/client.py:96-116` (`unwrap`/`unwrap_or_none`) does not guard
  the parse; the `KeyError` propagates and is rendered as `validation: 'id'`.
- Reproduced (2026-09-26): `bea --json cloud ledger show 'OWNER/NAME%2fbranches'`
  → exit 1, `{"error": {"category": "validation", "message": "'id'", ...}}`.
  (Backend tasks t001/t002 remove the malformed-200 trigger; this task makes the
  CLI robust regardless of what a server returns.)

## Steps

1. Guard the parse seam so a `KeyError`/schema mismatch on a 2xx body becomes a `BeaError` like "Unexpected server response (HTTP 200)." with the request id, consistent with `cli.errors` categories.
2. Keep the generated files untouched; add the guard in the hand-written seam (`cli/src/cli/api/client.py`) rather than editing generated `from_dict`.

## Implementation and verification

- The hand-written `cli.api.client.call` seam retains HTTP status and request ID
  while generated operations parse their response. Rejected 2xx bodies become
  `Unexpected server response (HTTP <status>).`, category `validation`, exit 1.
  Pre-response failures and existing HTTP error handling remain intact.
- All current hosted callers and the command generator use the guard. The
  OpenAPI pin and generated client were refreshed from the canonical backend
  contract, including already-shipped slug rules, feed types, and starter copy;
  no generated parser was hand-edited.
- Eight synthetic malformed-200 cases (JSON objects/arrays/null and HTML, text
  and JSON output) failed before the fix and pass after. These are simulations,
  not claims about a live server response. 137 focused cloud/device-flow/contract
  tests also passed.
- The full gate exposed stale empty-cost assertions left behind by `78217b30`
  and a terminal test sending Ctrl-C before its first answer completed. The
  stale assertion reproduced on archived HEAD; expectations now include the
  documented `number_total`. The terminal driver now waits for ordered answer
  and prompt markers; its unchanged baseline passed separately, confirming the
  timing sensitivity rather than a deterministic response-guard regression.
- Final `make check-all` passed: lint, dead-code detection, formatting, mypy,
  2,170 tests passed / one skipped, spec drift, and generated documentation.
  Existing PTY deprecation warnings remain. Code generation also retains the
  existing warnings for unsupported optional pull-request path parameters.

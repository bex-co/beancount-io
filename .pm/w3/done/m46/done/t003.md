## Objective

The anonymous-access probe must treat a missing or unexpected `private` field
in an upstream response as private (fail closed), so a malformed or wrong-shape
200 can never be read as "public".

## Context

- `src/foundation/clients/fava-client-factory.ts:81-96` and
  `src/foundation/clients/gitea-client-factory.ts:49-64` read
  `response.data.data.private`; `undefined` currently means "not private".
- `src/features/ledger/utils/ledger-access-check.ts:91-127` consumes this and,
  once any 200 is seen with `ledgerOwner === caller`, grants admin without
  re-validating `name`.

## Steps

1. In both factories, require an explicit boolean `private`; on missing/non-boolean, treat as private (deny anonymous access).
2. In `ledger-access-check.ts`, do not grant admin from an owner-name match alone when the probe body is malformed; require a well-formed repo record.
3. Confirm legitimate public ledgers (well-formed body, `private: false`) are unaffected.

## Files

- `backend-cluster/backend-v2/src/foundation/clients/fava-client-factory.ts`
- `backend-cluster/backend-v2/src/foundation/clients/gitea-client-factory.ts`
- `backend-cluster/backend-v2/src/features/ledger/utils/ledger-access-check.ts`

## Acceptance criteria

- [x] A test feeding a 200 body without a `private` field results in access denied (fail closed), not granted.
- [x] A well-formed public ledger (`private: false`) still resolves as public; a private one stays private.

## Out of scope

- Boundary validation (t001) and upstream encoding (t002), which remove the
  malformed-body trigger; this task hardens the decision if any remains.

## Implementation and verification

- Both anonymous client factories require `private: false` explicitly. Missing
  or non-boolean visibility denies access, including a successful envelope with
  no repository body.
- Metadata permission resolution validates a positive safe-integer repository ID
  and boolean visibility before owner, collaborator, or anonymous grants.
- Before the fix, 67 unit cases failed across malformed records and caller roles;
  three actual REST/GraphQL/MCP adapter cases also failed on an isolated baseline.
  All pass with the fix, and legitimate public/private/owner/collaborator cases pass.
- Passed typecheck, lint/dead-code detection, OpenAPI regeneration, and all
  293 suites / 4,771 tests. Jest emitted a worker teardown warning; assertions
  and command exit status passed. All malformed responses were simulated;
  no live ledger writes were performed.

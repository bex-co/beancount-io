# Stop clipping multi-digit posting counts in narrow journal rows

Source: continuous dashboard QA, 2026-10-04.
Pillar: A2 — phone-width readers must see the true posting count, not a truncated digit.

At 390px width, a journal row with 16 postings renders its toggle count as "1" — the second digit is cut off. Single-digit counts fit, so only busy entries mislead.

Root cause: the mobile postings cell is fixed at `w-10` (`dashboard/src/features/journal/components/journal-table.tsx:185`, `sm:hidden` variant) while the toggle button inside needs chevron + gap + two tabular digits + padding (~44px in ~36px of space). The desktop `w-24` cell is roomy and unaffected.

Repro: at 390×844 open `/ledger/open_ledger/example/journal`; the Hoogle Payroll row's toggle shows "1" instead of "16".

Acceptance: one- and two-digit counts render fully at 390px with no page-level horizontal overflow and no change to desktop rows. Add a narrow-viewport render test (or a width assertion on the mobile cell), run the dashboard checks, and ship.

Scope: dashboard journal table only. Estimated under one hour.

---

**Resolved 2026-10-04** — The root cause, measured in a browser at 390px, differs from the note. A `truncate` (nowrap) payee such as "Metro Transport Authority" set the description column's minimum to its full text width. That pushed the auto-layout table to 393px inside its 372px `overflow-x-auto` container, so the rightmost column, the posting count, was clipped; the `w-10` cell alone was not the cause. Below `sm` the description column is now `w-full max-w-0`, so the table fits and the count stays whole. From `sm` up the original auto sizing is restored, and desktop column widths were confirmed unchanged at 1280px. jsdom has no table layout, so the `journal-table` regression test pins that class contract with a 16-posting long-payee row (it fails on the old classes); the layout itself was verified live. Dashboard format, lint, 4,966 tests and build passed. Shipped in `57adab6c` (`dashboard`).

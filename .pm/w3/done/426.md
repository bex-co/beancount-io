# `format -i` partial failure: `result.failed` is empty, never-attempted files go unmentioned, and a BOM-only change reads as "formatted"

**Severity:** minor. **Estimate:** 30–45 minutes. **Owner:** cli. **A1:**
follow-up to w5/004. An agent reading the documented result to decide what
to retry cannot tell which files are still unformatted.

Found 2026-09-26 by CLI QA (`qa-find-bugs-cli`) against `main` HEAD
`8cd9732b`, `uv run bea` 0.3.0, Darwin 26.5.1 arm64. Synthetic files only.

## Repro

```sh
mkdir -p tree/a tree/z
U='2026-01-01 * "x"\n  Assets:A   1.00 USD\n  Assets:B      -1.00 USD\n'
printf "$U" > tree/a/1.bean
printf '\xef\xbb\xbf'"$U" > tree/z/3.bean      # BOM-marked, unaligned
printf "$U" > tree/ro.bean && chmod 444 tree/ro.bean
bea --json format -i tree; echo "exit=$?"
bea format --check tree/z
```

Exit 1 with message `bean-format could not finish in-place formatting …
Permission denied: '…/tree/ro.bean'` and
`result: {"formatted": [".../a/1.bean", ".../z/3.bean"], "failed": [], ...}`.
Upstream stops at `ro.bean` (sorted order), so `z/3.bean` was never
aligned: `format --check tree/z` still says `would format`. Without a BOM on
`z/3.bean` the file is simply absent from the result and from human output.

Expected (USAGE "Exit codes": read the operation result before retrying):
`failed` names `ro.bean` with its reason; files never attempted are listed
(e.g. `not_attempted`) and in the human details; `formatted` lists only files
whose alignment was actually written.

## Root cause

`cli/src/cli/commands/format.py:159-195`: `_strip_bom` rewrites every
formattable file *before* the single upstream `bean-format --in-place a b c`
call; `changed` is computed as "bytes differ from before", so a BOM strip
alone counts as formatted. `failed` is only populated from
`_syntax_failures` (`:96`), so a write failure never enters it, and nothing
records which files upstream did not reach.

## Fix

Run upstream once per file (or check each file's post-state against
`_would_change`) so each file ends in exactly one bucket: formatted, failed
(with reason), or not attempted. Put the unwritable file in `failed`; list
the rest as not attempted; report a BOM-only change separately or only
after upstream wrote the file. Optionally pre-check writability before any
write so the common case fails without a partial rewrite.

## Acceptance

- The repro's JSON result has `ro.bean` under `failed`, `z/3.bean` as not
  attempted (or formatted, if per-file runs continue past the failure), and
  `format --check` agrees with `formatted`.
- Human output names the same three buckets. Regression in `cli/tests/`.

## Dedupe

changed paths; w3/251 covered non-UTF-8 files. Neither covers the empty
`failed`, unlisted unattempted files, or BOM-only "formatted" entries.

# `bea add transactions` accepts JSON floats for amount fields, writing binary junk (`0.30000000000000004`)

**Severity:** major. **Estimate:** 30–45 minutes. **Owner:** cli. **A1:** an
agent (or JSON emitter) that puts bare JSON numbers in `units.number`,
`cost.number`, or `price.number` — despite USAGE promising decimal **strings** —
can permanently book IEEE-754 noise such as `0.30000000000000004 USD` into the
ledger (including inside `{…}` cost lots).

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `128872a7`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
# 0.1+0.2 in JSON is 0.30000000000000004
printf '%s\n' '[{"date":"2024-09-01","narration":"path","postings":[
  {"account":"Assets:Cash","units":{"number":0.30000000000000004,"currency":"USD"}},
  {"account":"Expenses:Transport","units":{"number":-0.30000000000000004,"currency":"USD"}}
]}]' > float.json

bea --json --file main.bean add transactions --from float.json
# exit 0 — written: 1

grep -A3 path main.bean
#   Assets:Cash                             0.30000000000000004 USD
#   Expenses:Transport                     -0.30000000000000004 USD

# Same pollution on cost.number:
#   Assets:Broker  1 AAPL {0.30000000000000004 USD}
```

Working control — string decimals:

```sh
# units.number / cost.number as "0.3" writes 0.3 USD
```

`cli/docs/USAGE.md` (JSON envelope section): “Amounts use decimal **strings** —
never floats.”

## Expected

Reject non-string numeric amount fields with a usage/validation error that
names the field and shows the string form (`"0.3"`), matching the documented
contract. Do not coerce JSON floats through `Decimal(str(float))`.

## Actual

Pydantic `Amount.number: Decimal` accepts JSON numbers; float values become
`Decimal(str(n))` (still polluted for many binary fractions) and are printed
into the ledger. `1.5` / `"0.1"` look fine, so the footgun is easy to miss.
`cost.number` / `price.number` share the same coercion.

## Fix

Constrain amount `number` (and string `amount` tokens) to strings (or
Decimals already quantized from strings) in the bulk schema; reject `int`/
`float` JSON types with a clear message. Optionally accept integers only if
product wants whole-unit convenience — still reject floats. Apply to units,
cost, and price. Regression: the repro exits 1 with nothing written; `"0.3"`
still writes `0.3 USD`.

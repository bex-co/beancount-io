# `bea add transaction` drops a currency-only cost constraint (`{EUR}`) and books a different lot than asked

**Severity:** minor. **Estimate:** 30–45 minutes. **Owner:** cli. **A1:** the
command writes different accounting than it was given and reports the
original in its JSON answer, so an agent cannot detect the change.

Found 2026-09-25 by CLI QA against `main` HEAD `8cd9732b`, `uv run bea` 0.3.0,
Darwin 25.5.0 arm64, isolated config/cache. Synthetic ledger only.

## Repro

Use the ledger from `w3/414` (10 HOOL held at `{100.00 USD}`).

```sh
bea --json --file "$PWD/main.bean" add transaction --date 2026-03-02 \
  -p 'Assets:Brokerage -5 HOOL {EUR}' -p 'Assets:Cash 500.00 USD' Sell
# exit 0; data.directive.postings[0].cost = {"number":null,"currency":"EUR",…}
tail -3 main.bean
#   Assets:Brokerage   -5 HOOL {}      <- EUR constraint gone
```

Control: the same posting written by hand (`-5 HOOL {EUR}`) fails `bea check`
with `No position matches … against balance (10 HOOL {100.00 USD, …})`, which
is Beancount's answer. `{USD}` is also written as `{}` — harmless there, but
the same loss.

## Root cause

`cli/src/bea_engine/ledger/writer.py` `format_entry` renders through the
upstream `EntryPrinter`, which prints a `CostSpec`'s currency only alongside
a number. Validation then runs on the rendered text, so the relaxed `{}`
passes.

## Fix

Refuse (exit 2) or faithfully render a cost spec whose currency or label the
printer would drop — e.g. keep the user's raw `{…}` text for the posting,
as the `@@` path already does. Either way the validated text and the JSON
answer must describe the same constraint.

## Acceptance

`{EUR}` against a USD lot is refused and nothing is written; `{USD}` is
written as `{USD}` (or refused with the same message); regression tests.

## Dedupe

Searched `.pm/**` for cost currency, currency-only cost, `{EUR}`/`{USD}`.
Only mobile w4/m11 (display of cost basis) mentions cost currencies.

# `bea init DIR` succeeds beside existing `main.beancount`, shadowing real books

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** cli. **A1:** with
only `main.beancount` present, `bea init .` exits **0**, creates `main.bean`,
and cwd commands silently use the new template while the real ledger is
untouched.

Found 2026-09-16 by continuous CLI QA ([c880 hunt](dd9da000-dd5c-4dd8-8778-b4cb0726482a)),
HEAD `45fe5b2d`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Confirmed
`cli/tmp/qa-20260915/c874/`. Evidence: `c880/`.

## Repro

```sh
mkdir books && cd books
printf 'option "title" "My Books"\n2020-01-01 open Assets:Cash USD\n' > main.beancount
bea --no-input init . --currency USD
# exit 0 — creates main.bean; main.beancount unchanged
bea list open
# template accounts dated today (main.bean), not My Books
```

## Expected

`ConflictError` exit **4** when a root ledger (`main.beancount` / existing
books) is already present — same “never overwrites” policy as existing
`main.bean`.

## Actual

`init.py` only preflights `directory / "main.bean"`; ignores sibling
`main.beancount`. Cwd discovery then prefers `main.bean`.

## Fix

Refuse when `main.beancount` (or documented root ledger) exists. Regression:
repro exits 4 with both files unchanged; empty dirs still succeed.

## Dedupe

Related to w3/307 (cwd skips sole `.beancount`) and w3/343 (directory `--file`
hint) — this is **init creating** the shadow file. Not w3/336 (`example -o`).

---

**Resolved 2026-09-17** — `bea init` refuses when a sibling default root ledger (`main.beancount` / `main.bean`) already exists, so it cannot shadow real books. Covered by `cli/tests/test_init_refuses_sibling_beancount.py`. Shipped with this board close.

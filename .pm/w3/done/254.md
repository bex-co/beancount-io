# `bea query --format csv` pads numeric cells with spaces for text alignment

**Severity:** minor. **Estimate:** 30–45 minutes. **Owner:** cli (managed
beanquery / query CSV path). **A1:** an agent that exports
`bea query … --format csv` into a spreadsheet or `Decimal()` / `float()` parse
gets leading spaces in shorter numbers (`"  97.25"`, `" -2.75"`), so string
equality and strict numeric parsers fail while `--json` is clean.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `94be5377`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only. Reproduced with both `bea --file … query --format csv` and
native `bean-query --format=csv` from the managed engine.

## Repro

```sh
bea --file main.bean query --format csv \
  'SELECT account, sum(number) WHERE account ~ "Assets" GROUP BY 1'
# stdout (exit 0), repr of body:
# 'account,sum(number)\r\nAssets:Bank:Checking,3357.83\r\nAssets:Cash,  97.25\r\n'
# csv.reader → ['Assets:Cash', '  97.25']

bea --file main.bean query --format csv \
  'SELECT date, account, number, currency WHERE account ~ "Cash"'
# number cell for -2.75 is ' -2.75' (leading space for sign/alignment)

bea --file main.bean query --format csv \
  'SELECT account, sum(position) WHERE account ~ "Broker" GROUP BY 1'
# inventory cell is ' 2 AAPL { 50 USD}' — spaces inside the lot braces too
```

Working control:

```sh
bea --json --file main.bean query \
  'SELECT account, sum(number) WHERE account ~ "Assets" GROUP BY 1'
# rows: [["Assets:Bank:Checking","3357.83"],["Assets:Cash","97.25"]]
```

## Expected

`--format csv` cells are unpadded machine values (no leading/trailing spaces
added for decimal-point alignment). Text alignment belongs only to
`--format text`.

## Actual

Managed `beanquery/query_render.py` `render_csv` primes the same column
renderers used for text tables, then writes `renderer.format(value)` into
`csv.writer`. `DecimalRenderer.format` right-pads/left-pads so decimal points
line up across rows:

```python
left = self.nintegral - (max(1, len(n.digits) + n.exponent) + n.sign)
return f'{"":>{left}}{value:<{self.maxwidth - left}}'
```

That padding is correct for TTY tables and wrong for CSV. Bea’s one-shot
`--format csv` path goes through this renderer; `--json` uses `rows_answer`
and stays clean.

## Fix

For CSV only: format scalars without alignment padding (e.g. `str(value)` /
unpadded amount/position strings), or strip renderer padding before
`csv.writer`, or teach amount/position renderers an `align=False` mode that
`render_csv` enables. Keep text tables unchanged. Regression: the Assets
`sum(number)` CSV row for Cash is exactly `97.25` with no spaces; signed
`number` cells have no leading pad; inventory cells have no alignment spaces
inside units/cost; `--json` unchanged.

## Dedupe

Not w3/242 (`PRINT` ignores `--format csv`). Not w3/253 (text `narrow`
header width). No open note covers CSV inheriting text decimal alignment

**Resolved 2026-09-16** — `--format csv` uses an unpadded CSV writer so numeric cells are not text-aligned. Covered by `cli/tests/test_query_csv_unpadded.py`. Shipped with this board close.

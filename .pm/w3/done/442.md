# `bea --json format` reports a multi-file target as one comma-joined string under an undocumented `files` key

**Severity:** minor. **Owner:** cli. **Estimate:** 20–30 minutes. **A1:** an
agent that formats a split ledger (`bea --json format --check main.bean`) cannot
read which files were in scope from `target`: the paths arrive glued into one
string, and a path containing `", "` makes the value ambiguous.

Found by continuous CLI QA 2026-09-26, `uv run bea` 0.3.0 at HEAD `8cd9732b`,
Darwin 26.5.1 arm64, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, closed stdin,
synthetic ledgers only, no network or account.

## Repro

```sh
mkdir -p books/sub
cat > books/main.bean <<'EOF'
option "operating_currency" "USD"
include "sub/a, b.bean"
2024-01-01 open Assets:Bank USD
EOF
printf '2024-02-01 note Assets:Bank "hi"\n' > 'books/sub/a, b.bean'

bea --json format --check books/main.bean
# exit 0
# {"bea":"0.3.0",
#  "target":{"files":"/abs/books/main.bean, /abs/books/sub/a, b.bean"},
#  "data":{"scanned":2,"formatted":[],"failed":[],"missing":[],
#          "check":true,"dry_run":false},
#  "truncated":false}
```

The same shape appears for any multi-file scan: two named files
(`bea --json format --check a.bean b.bean`) and the ordinary split-ledger case
(a named root whose include closure has more than one file, no comma needed).
Working controls: one file → `{"file": "<abs path>"}`; one directory →
`{"directory": "<abs path>"}`; stdin → `{"stdin": "-"}`.

## Expected

`docs/USAGE.md` ("JSON output") defines `target` as `{"file": …}`,
`{"directory": …}` or `{"server": …}` — `files` is a fourth, undocumented
shape, and a `", "`-joined string is not a machine-readable list of paths.
Emit an array (`{"files": ["/abs/a.bean", "/abs/b.bean"]}`) and document it
alongside the other three, or report the named root as `{"file": …}` and leave
the closure to `data.scanned`/`data.formatted`, which are already arrays.

## Root cause

`cli/src/cli/commands/format.py:580`:

```python
return {"files": ", ".join(str(f) for f in files)}
```

`_target()` returns `dict[str, str]`, so the list is flattened to satisfy the
type rather than the contract. No test asserts this key (`grep '"files"'` in
`cli/tests` only matches fixture dicts in `test_exit_contract_matrix.py`), and
`docs/USAGE.md` never mentions it.

## Fix

Widen the target type to allow a list, return the scanned paths as an array,
and add the shape to the `target` list in `docs/USAGE.md` (§ JSON output).
Regression coverage: `--json format --check` over a two-file include closure
asserts `target["files"] == [root, child]`, including a child whose name
contains `", "`.

## Dedupe

`.pm/**` searched for `format` + `target`/`files`/envelope, and for `error.result`
(w3/425, w2/done/019, w5/done/004 — unrelated). Not w3/441 (`format -i`
alignment padding) or w3/436 (`price export` overwrite). `git log -S '", ".join'`
over `cli/src/cli/commands/format.py` shows the line arrived with `a90b1706`
(ADR014 engine split) and was never revisited.

---

**Resolved 2026-10-02** — Shipped in `40ec9597`. Multi-file formatter targets
now return a sorted, deduplicated JSON array, preserving filenames containing
commas. The usage guide documents this shape alongside file, directory, stdin,
and server targets. Six real CLI regressions failed before the fix and pass
across check, dry-run, and in-place modes with include and explicit-file inputs;
three controls preserve the other formatting target shapes. `make check-all`
passes (2,488 tests, one skip); the public-tree secret scan is clean.

# The `ask` write-approval panel names the root ledger even when `--into` sends the directive somewhere else — and truncates the path it does name

**Severity:** major (the consent dialog misstates which file the approved write
touches). **Owner:** cli. **Estimate:** 20–30 minutes. **A1:** `ask --into` is
the documented way to keep AI writes in an included file; the confirmation must
name the file that will change.

Found 2026-09-26 by CLI QA (`qa-find-bugs-cli`) against `main` HEAD `8cd9732b`,
`uv run bea` 0.3.0, Darwin 26.5.1 arm64, isolated `BEA_CONFIG_DIR` /
`XDG_CACHE_HOME`, synthetic split ledger, real PTY, local stub model server
(`BEA_API_URL` at 127.0.0.1 — no hosted AI call needed).

## Repro

Synthetic ledger: `main.bean` with `include "side.bean"`, both holding ordinary
transactions.

```sh
bea --file /abs/path/main.bean ask --into side.bean    # interactive, needs a TTY
```

1. Ask for an entry ("add a 7 usd food expense"). The model proposes a
   `write_directive` call.
2. The confirmation panel appears, titled:

   ```
   ╭─ Write to /abs/path/fixture/main.─╮
   │ Allow the AI to append this directive to your ledger?
   │ 2024-03-05 * "qa-stub" "into-side"
   │   Expenses:Food   7.00 USD
   │   Assets:Cash
   ```

3. Approve (`Yes`).
4. `tail main.bean` → unchanged. `tail side.bean` → the new transaction.

Two defects in one panel: the file it names is not the file it writes, and the
name it does print is cut off mid-path (`…/fixture/main.`) with no ellipsis,
because the panel title is trimmed to the frame width. At 100 columns the user
cannot even read the (wrong) destination.

## Expected

The panel names the actual append destination — the included file under
`--into`, resolved the way the engine resolves it — and does so readably (a
shortened middle, or the destination on its own body line rather than in the
frame title). `cli/docs/USAGE.md:1024-1027` documents that interactive writes
are confirmed and that `--into` chooses an included destination; the
confirmation is the only place that pairing is visible.

## Root cause

`cli/src/cli/ask/agent.py:163-184` already has the right answer and throws it
away: the pre-approval dry run returns `{"count", "target", "warnings",
"token"}` and only `preview["token"]` is used. The confirm callback is built in
`cli/src/cli/ask/repl.py:157-171` from `deps.file` (the **root** ledger,
`make_confirm_fn(deps.file, …)` at `repl.py:195`), so the title can never
reflect `--into`. `bea_engine/ledger/appending.py:39` computes the true target
via `ledger_write.destination(file, into)` — that is what `preview["target"]`
carries.

## Fix

Pass the preview's `target` (and, worth considering, its `warnings`) into
`confirm_fn` and title the panel with it; change `make_confirm_fn` to take the
destination per call rather than binding the root file once. Render the path so
it survives narrow terminals — Rich will trim a title silently, so put the
destination in the panel body, or shorten it explicitly.

Regression coverage: a stub-model PTY test with a split ledger and `--into`
asserting the panel text contains the included file's path and that the
approved write lands there; and a narrow-terminal case asserting the path is not
silently truncated.

## Blast radius

Only the `ask` confirmation. Everything else about the flow verified correct in
the same run: `--print`/`--no-input` never write (tool returns "Write skipped"),
global `--yes` does not grant AI write permission, `No` / `Deny all` leave the
file byte-identical, a `--into` path outside the include graph is refused before
any prompt, a concurrent hand edit during the prompt makes the approved write
refuse with the conflict message and keeps the user's edit, and the approved
write does take the `bea` write lock (it blocks while another process holds it,
then completes).

## Dedupe

Searched `.pm/**/*.md` including `done/` and `blocked/` for `write_directive`,
approval/confirmation panel and `--into` terms: nothing covers the `ask`
confirmation's destination. `w3/434` (open) is `format --in-place` versus the
write lock, a different mechanism. Open `ask` items `445`–`449` are the JSON
envelope, the `max_tokens` cap, the zero-total render, the unbounded tool result
and the Ctrl-C exit. `git log -S"make_confirm_fn"` shows the helper has not been
revisited since it arrived.

## Unverified

Whether the hosted dashboard shows an equivalent destination for AI writes (out
of scope here). Live model behavior was not exercised; the model side was a
local stub, so nothing here describes the hosted AI service.

**Resolved 2026-09-27** — fixed in `w3/m50` ("Make the `ask` consent surface
honest and its session survivable"): the engine append path refuses control
characters in raw directive text, the approval panel and both answer prints
neutralize them, the panel names the destination the dry run resolved in a body
line that cannot be trimmed, a Ctrl-C or a failed turn costs one turn instead of
the session, and `ask` sets its own per-question request budget and retells the
AI SDK's failures in the CLI's own words. Regression coverage in
`cli/tests/test_ask_consent_surface.py`,
`cli/tests/test_ask_session_resilience.py` and the shared stub-model/PTY harness
in `cli/tests/conftest.py`. Before/after evidence was captured locally against a
local stub model server on a real terminal (no hosted AI calls); it is not on
this board.

# `bea import` preview and a *rejected* `--into` write both create the destination file

**Severity:** minor. **Owner:** cli. **Estimate:** 20–30 minutes. **A1:** an
agent that previews an import (or whose write is rejected) is told "Preview
only" / "nothing was written", yet a new empty `.bean` file appears in the
user's books and in their next `git status`.

Found by continuous CLI QA 2026-09-26, `bea` 0.3.0 at HEAD `8cd9732b`, Darwin
26.5.1 arm64, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, closed stdin,
synthetic ledgers only, no network or account.

## Repro

```sh
mkdir -p books/parts
cat > books/main.bean <<'EOF'
option "operating_currency" "USD"
include "parts/*.bean"

2024-01-01 open Assets:Bank:Checking USD
2024-01-01 open Expenses:Uncategorized USD
2024-01-01 open Equity:Opening USD

2024-01-02 * "Opening"
  Assets:Bank:Checking  1000.00 USD
  Equity:Opening
EOF
printf 'Date,Amount,Description\n2024-03-01,-12.34,COFFEE SHOP\n' > books/bank.csv

# 1. preview only — no --apply
bea --file books/main.bean import books/bank.csv --csv auto \
    --account Assets:Bank:Checking --into parts/march.bean
# exit 0, ends with "Preview only. Review the entries, then repeat with --apply to write."
ls books/parts
# march.bean   <-- created, 0 bytes

# 2. a write that is rejected
bea --file books/main.bean add transaction --date 2024-04-01 -n rejected \
    --into parts/may.bean -p 'Assets:Nope 1.00 USD' -p 'Expenses:Uncategorized -1.00 USD'
# exit 1: "The change would leave the ledger invalid; nothing was written."
ls books/parts
# march.bean  may.bean   <-- may.bean created too, 0 bytes
```

The same happens for a **literal** include (`include "parts/june.bean"` with the
file absent) and with `--json`.

## Expected

A preview and a rejected write leave the ledger tree byte-identical, including
its file list. Create the `--into` destination only on the successful write
path, or remove a file this command created when nothing is written.

## Actual

`bea_engine/importing.py:305` calls `LedgerSnapshot.require_target(target)`
before it knows whether anything will be written, and the glob/literal branch in
`bea_engine/ledger/write.py:99` does `resolved.write_bytes(b"")`. The same call
runs inside `validate_append` (`write.py:776`), which is the validate-only path.

## Fix

Move the auto-create into `append()` (under the lock, on the write path), or
give `require_target` a `create: bool` parameter that the preview and
validate-only callers pass as `False` — reporting "destination will be created"
in the preview instead of creating it. Regression coverage: preview and rejected
`--into` runs leave `os.listdir` of the include directory unchanged; `--apply`
still creates the glob/literal member as w3/228 and w3/344 require.

## Dedupe

Side effect of the w3/228 + w3/344 fixes (`a65c9a3e`), which added the
auto-create to satisfy `--apply`; neither covered the preview/rejected path. Not
w3/431 (`ingest extract -o`) or w3/436 (`price export --output`) — those
overwrite existing files, this creates one.

## Objective

Do the same for the sync service, and give the callers that genuinely have no request identity an explicitly-named system identity — so the exemption is a decision someone wrote at the call site, not a default hidden in every method.

## Context

- `src/features/plaid/service/plaid-sync-service.ts` — `syncItemTransactions`, `getUnsyncedTransactionsForCategorization`, `submitTransactionsToLedger`, `deleteTransactions`.
- `src/scheduler/jobs/plaid-sync-job.ts` and `plaid-webhook-processor-job.ts` call these with **no caller at all** — a cron run and a webhook have no user driving them. That need is real and this task does not remove it.
- Export something named for what it is — `systemIdentity(userId)` — with a comment saying it claims full capability on a user's behalf and belongs only to unattended paths. `trustedIdentity` can remain its implementation; what changes is that claiming it becomes visible in a grep of call sites rather than invisible inside fifteen methods.
- A webhook is *user-triggered but not user-authenticated*: the exemption is right there too, and the comment should say why rather than leaving the reader to assume.

## Steps

1. Change the sync-service signatures to take `identity`.
2. Add `systemIdentity` beside `trustedIdentity` and use it at the scheduler and webhook call sites.
3. Grep for remaining `trustedIdentity` uses and either convert or justify each in place.

## Files

- `src/features/plaid/service/plaid-sync-service.ts`
- `src/scheduler/jobs/plaid-sync-job.ts`, `src/scheduler/jobs/plaid-webhook-processor-job.ts`
- `src/server/api/identity.ts`

## Acceptance criteria

- [ ] Every remaining full-capability claim is at a call site and named, not inside a service.
- [ ] The scheduler and webhook paths still work — their tests pass.

## Out of scope

- Changing what the scheduler is allowed to do.

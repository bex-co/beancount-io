## Objective

Keep the other two paginated social tabs under the same complete-list lifecycle, without changing their distinct result shapes.

## Context

- Dashboard-only pagination repair from the reproduced public Followers journey in this milestone's README.
- Existing API total values count the returned page; do not redefine the backend contract.

## Steps

1. Apply the established paging behavior to Following (identity: username) and Starred (identity: fullName), preserving their query documents and existing lazy gates.
2. Keep state separate by username and list kind. A slow request from another profile or tab must not replace the active list or advance its page.
3. Preserve observed small/empty behavior: open_ledger Following has one card; Starred has no cards and its honest empty message.
4. Cover multiple pages with local synthetic API fixtures; production lists above twenty were verified only for Followers. Do not change follow/star relationships to create fixtures.

## Files

- dashboard/src/features/user-profile/hooks/use-user-following.ts
- dashboard/src/features/user-profile/hooks/use-user-starred-repos.ts

## Acceptance criteria

- [ ] Local paginated Following/Starred fixtures append the right items exactly once and terminate on the final page.
- [ ] The observed one-item Following and empty Starred controls still render correctly.
- [ ] Late completions, duplicate activation and username changes retain list isolation.
- [ ] No API or permission changes and no new cross-package imports.

and changing the intentionally capped activity feed.

# Mid-period `report` / `balance` shows phantom `Equity:Opening-Balances` (0.00)

**Severity:** minor. **Estimate:** 30–45 minutes. **Owner:** cli. **A1:** an
agent filtering a balance sheet or trial balance to a mid-ledger day sees
`Equity:Opening-Balances` at 0.00 even though that account was never opened —
`list open` and BQL `accounts` disagree with the report tree while totals stay
correct.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `345aa97a`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
cat > main.bean <<'EOF'
option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Food USD
2024-01-01 open Income:Salary USD
2024-01-01 open Equity:Opening USD
2024-01-02 * "Opening balance"
  Assets:Cash     1000 USD
  Equity:Opening -1000 USD
2024-01-15 * "Grocery"
  Expenses:Food    50 USD
  Assets:Cash     -50 USD
2024-02-01 * "Salary"
  Assets:Cash    2000 USD
  Income:Salary -2000 USD
EOF

bea --file main.bean report balance-sheet -t '2024-01-15 - 2024-01-15'
# Equity:
#   Opening            -1,000.00 USD
#   Opening-Balances        0.00 USD   ← not in the ledger

bea --file main.bean balance -t '2024-01-15 - 2024-01-15'
# same phantom under Equity

bea --json --file main.bean report balance-sheet -t '2024-01-15 - 2024-01-15'
# data.equity.children includes Equity:Opening-Balances with empty balances

bea --file main.bean list open --account Opening-Balances
# No open directives found.
```

Working control — period starting at first activity has no phantom:

```sh
bea --file main.bean report balance-sheet -t '2024-01-02 - 2024-01-02'
# Equity only: Opening
```

## Expected

Report / balance trees list only accounts that exist in the loaded ledger (here
`Equity:Opening`). Period clamping must not surface Beancount’s default
`account_previous_balances` name as a visible sibling.

## Actual

Any `-t` / `--time` range whose start is **after** the ledger’s first dated
activity injects a zero `Equity:Opening-Balances` row. Net worth stays correct;
the hierarchy lies about which equity accounts the books contain.

## Root cause

Fava `TimeFilter` → Beancount `summarize.clamp_opt` opens
`options_map["account_previous_balances"]` (default `Opening-Balances`) for the
pre-period transfer. Summarization nets that account to zero, but the report
tree still renders the empty child. See vendored
`cli/src/fava/core/filters.py` and upstream `beancount.ops.summarize.clamp_opt`.

## Fix

When building the account tree for clamped periods, omit synthetic previous-
balances / earnings transfer accounts that have empty inventories and no open
directive in the original entries (or rename/hide them behind a documented
“period adjustment” line). Regression: the mid-period repro above shows only
`Equity:Opening`; the start-anchored control stays unchanged; totals unchanged.

## Dedupe

Not w3/278 (NFC/NFD account doppelgängers — different account identity). Not
w3/246 (balances command). No open note covers clamp-injected
`Opening-Balances` phantoms on mid-period reports.

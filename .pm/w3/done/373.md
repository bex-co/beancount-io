# `report income-statement -x units` monthly breakdown drops explicit zero P&L months that default conversion keeps

**Severity:** minor. **Estimate:** 20–35 minutes. **Owner:** cli. **A1:** an
agent comparing default and `-x units` income statements sees inactive months
flip from `0.00 USD` / `{"USD":"0"}` to `—` / `{}` — silent loss of “zero
activity” vs “no row”.

Found 2026-09-16 by continuous CLI QA ([c1180 hunt](f8f82612-407e-4749-add5-5ba4eb6bc4d8)),
HEAD `de21ec33`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Evidence:
`cli/tmp/qa-20260915/c1180/`.

## Repro

```sh
bea --file main.bean report income-statement
# 2020-01-31 / 2020-04-30 → 0.00 USD columns

bea --file main.bean report income-statement -x units --allow-errors
# same months → —

bea --json … report income-statement
# net_profit {"USD":"0"}

bea --json … report income-statement -x units --allow-errors
# net_profit {}
```

## Expected

`-x units` should not change zero-month semantics for USD-only P&L buckets, or
document that units mode treats quiet months as absent.

## Actual

Units conversion renders empty buckets as `—` / `{}` while default keeps
explicit operating-currency zeros for the same months.

## Fix

Preserve explicit zeros under `-x units` when amounts are operating-currency
only, or document the difference. Regression: quiet months match across modes;
active multi-currency months unchanged.

## Dedupe

Not w3/313, 304, 327, 292. No open note on units conversion changing
income-statement monthly zero rendering.

---

**Resolved 2026-09-17** — Took the note's second branch: the difference is real
and is now a documented rule rather than an accident. The conversion decides how
an interval row spells itself — a currency conversion names that currency in
every row (quiet month `0.00 USD` / `{"USD": "0"}`, unvaluable month
`Unavailable USD` / `{"USD": null}`), a per-unit conversion names only the
commodities the row actually holds (`—` / `{}`). Units mode is not made to
invent a currency it was explicitly told not to use: `-x units` is also the
default when a ledger declares zero or several operating currencies, so
zero-filling would apply in exactly the cases where no single currency exists.
The quiet row keeps its place in the series in both modes, which is what
distinguishes "zero activity" from "no row"; `cli/docs/USAGE.md` now says to
compare rows by date, not by the presence of a currency key.

To make that rule true everywhere, the net-worth series now spells a quiet row
the same way the income statement always has — `0.00 USD` under a currency
conversion instead of `—`. Covered by
`cli/tests/test_interval_zero_rows_across_conversions.py`. Shipped with this
board close.

# Keep React icons out of the native wheel scroll worklet

Major · 35–50m · mobile. A2: opening an account must allow choosing its account type without a render error.

Environment: September 13, 2026, main 84231f9c; https://beancount.io; authenticated QA reader of public synthetic open_ledger/minimax; io.beancount.ios 1.20260906.47 (47), iPhone 17e/iOS 26.5, Expo 57/RN 0.86, English/System/light/default large text. No ledger mutation.

Repro:
1. Actual MiniMax Home -> Accounts tab -> plus (`open-account-button`) -> Open Account. Blank Done is disabled. Entering `Qa draft` shows the invalid-character message; replacing it with `QaDraft:Checking` enables Done. Do not submit.
2. Tap `open-account-prefix-picker`. Before a wheel can be used, the app displays Render Error: `[Worklets] Cannot copy value of type \`FiberNode\`.` The displayed stack points to serializable.native.ts:215 and Picker index.tsx:168.
3. Terminate and freshly launch PID69785, wait for Home, dismiss the development warning banner, and repeat actual Accounts -> plus. Leave the form empty and keyboard closed. Currency opens normally with No currency/MUSD and MUSD selected. Cancel that wheel, then tap the Assets prefix. The identical FiberNode render error returns immediately. This rules out keyboard state, invalid draft input and a general inability to open a modal.

Expected: Choose account type opens and permits a pending selection among the account roots. Actual: the root picker cannot render; the user cannot select a nondefault root through this form. This is a development-build render error, not an observed termination of the native process. Release-build behavior was not separately exercised.

Root: `mobile/src/components/picker/index.tsx:262–270` captures `items` in `useAnimatedScrollHandler` solely to read `items.length` for wheelIndexAtOffset. The worklet serializes the captured array. `mobile/src/screens/open-account-screen/open-account-screen.tsx:237–251` constructs rootItems with React View/Ionicons elements in each item's icon; their owner graph contains a FiberNode that installed react-native-worklets rejects at `src/memory/serializable.native.ts:215`. At line414, switching picker state to root supplies this icon-bearing array. Currency items at253–256 contain only values/labels and work in the same fresh process. The failure occurs while rendering the new worklet, before scrolling.

Fix: compute a numeric item count on the JavaScript side and capture only that primitive in the scroll worklet. Keep React elements and the full items array on the JavaScript side for rendering and selection. Audit the component's other UI-runtime closures for the same capture mistake. Preserve pending-index highlighting, clamping, untouched non-first confirmation, Cancel and reopened selection. No dependency or API change is needed.

Acceptance: fresh native Open Account -> Assets opens with icons, an actual wheel scroll to Expenses highlights the pending row and picker Done changes only the unsaved draft root. Cancel preserves the previous root. Repeat empty/no-keyboard and valid-input/keyboard cases. Currency No currency/MUSD, Settings theme/language and Add Budget interval/currency remain usable. Include a meaningful regression guard for an icon-bearing item array crossing the worklet boundary; a pure index helper test cannot catch this serialization failure. Retain completed167's enlarged-text header/row geometry. Run mobile checks after implementation.

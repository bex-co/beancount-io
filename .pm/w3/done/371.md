# `bea doctor roundtrip` exits 0 with “Congratulations” on ledgers `bea check` rejects

**Severity:** minor. **Estimate:** 25–40 minutes. **Owner:** cli. **A1:** a CI
or agent gate using `bea doctor roundtrip` gets exit **0** and “Entries are the
same. Congratulations.” on syntax-invalid or garbage input while `bea check`
exits **1** — a stronger false-green than `doctor parse` / `lex` (w3/345).

Found 2026-09-16 by continuous CLI QA ([c1150 hunt](cd16ab15-8a4d-4e3e-949d-1ef513e3fb3a)),
HEAD `1ff95c56`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Confirmed
`cli/tmp/qa-20260915/c1150/confirm-bad.bean`. Evidence: `c1150/`.

## Repro

```sh
printf '2020-01-01 open\n' > half.bean
bea --file half.bean check
# exit 1 — syntax error, unexpected EOL

bea doctor roundtrip half.bean
# exit 0 — logs error, then “Congratulations.”
```

## Expected

Nonzero exit when loader/`check` would reject the file, or document as
debug-only — no success copy after syntax/token errors.

## Actual

Wrapper forwards bean-doctor exit **0**; upstream still compares recovered
entry sets and prints Congratulations after load failures.

## Fix

Fail when load logged errors / invalid input produced no usable entries.
Regression: half/garbage exit **1**; valid ledger unchanged.

## Dedupe

Related to w3/345 (parse/lex) — different subcommand and “Congratulations”
success. Not w3/273. No open note on `doctor roundtrip` false-green.

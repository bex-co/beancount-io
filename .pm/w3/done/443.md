# `cloud ledger create --clone` creates a hosted ledger but its JSON error carries no `result`

**Severity:** minor. **Owner:** cli. **Estimate:** 20–30 minutes. **A1:** the
exit-code contract tells an agent to "read the operation result before retrying
mutations", but on this exact documented partial-success path the only record of
the ledger that now exists on the server is prose inside `error.message` — so a
retry hits a 409 or leaves an orphan hosted ledger behind.

Found by continuous CLI QA 2026-09-26, `uv run bea` 0.3.0 at HEAD `8cd9732b`,
Darwin 26.5.1 arm64, isolated `BEA_CONFIG_DIR`, QA account signed in with
`bea cloud login` (`cloud status` exit 0), production API. Only disposable
`qa-20260926-run8*` ledgers were created, and all were deleted afterwards.

## Repro

On a machine whose SSH key is not registered with the git backend (any clone
failure reproduces it — a wrong `--dir`, no `git`, no SSH access):

```sh
bea --json cloud ledger create qa-20260926-demo --clone --dir ./demo
# exit 1, stdout empty, stderr:
# {"error": {"category": "validation",
#            "message": "Ledger 'owner/qa-20260926-demo' was created but could not be cloned (...).
#                        Clone it manually with: git clone ssh://…/owner/qa-20260926-demo.git",
#            "exit_code": 1}}
bea --json cloud ledger list | jq -r '.data[].full_name'   # the ledger is there
```

Working controls: `bea --json cloud ledger create qa-20260926-demo` (no
`--clone`) emits the full ledger envelope; `bea --json format --check` on a
failing scan carries the scan in `error.result`; `bea --json add transactions
--partial` carries `result.written`.

## Expected

`docs/USAGE.md` (§ Exit codes) names this case explicitly — "`cloud ledger
create --clone` can create a ledger before cloning fails. Read the operation
result before retrying mutations" — and defines `result` as "the partial effects
when the command wrote some of what it promised". The JSON error should carry
the created ledger, e.g.
`error.result = {"id": …, "full_name": …, "ssh_url": …, "http_url": …,
"private": …}`, so a script can record or clone it without parsing the message.
Human output should likewise print the ledger's `fullName`/`sshUrl` lines it
already knows before the error.

## Root cause

`cli/src/cli/commands/cloud/ledger/app.py:83`:

```python
except manager.CloneError as e:
    raise LedgerError(_clone_failure_message(ledger.full_name, e)) from e
```

`ledger` is in scope and is exactly what the success path emits three lines
later (`output.emit(asdict(ledger), …)`), but `LedgerError` is raised without
the `result=` argument `cli/src/cli/errors.py:46` already supports and
`format`/`add transactions` already use.

## Fix

Pass `result=asdict(ledger)` (plus the manual `git clone` remote) when the
clone step fails, and echo the ledger's identifying lines in human mode before
the error. Regression coverage: a `create --clone` whose clone step raises
`CloneError` exits 1 with `error.result["full_name"]` equal to the created
ledger and `error.result["ssh_url"]` matching the remote in the message.

## Out of scope

The clone failure itself — this run had no registered SSH key, so live
`create --clone` / `cloud ledger clone` success stayed unverified.

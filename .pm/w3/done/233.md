# `bea query` `.help` / `help` / `.parse …` write past the engine JSON envelope, so the CLI reports “engine did not answer”

**Severity:** major. **Estimate:** 30–45 minutes. **Owner:** cli. **A1:** an
agent discovering BQL shell utilities via one-shot `bea query '.help'` (or
`help`, `help <topic>`, `.parse SELECT …`) gets a false failure instead of the
help/AST text that the engine already produced.

Found 2026-09-15 by continuous CLI QA against `main`, HEAD `e093cc4b`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated `BEA_CONFIG_DIR` /
`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`. Synthetic fixtures only.

## Repro

```sh
bea --file main.bean query '.help'
echo exit=$?
# exit 1
# Error: The Beancount engine did not answer
#   'bea-engine query --file … .help --format text' (exit 0).
# details include the help banner, then a JSON line with "text": ""

bea --file main.bean query 'help'
bea --file main.bean query 'help format'
bea --file main.bean query '.parse SELECT account'
# same shape: exit 1, “did not answer”, help/AST leaked into details
```

Working controls (same one-shot path, text lands in the envelope):

```sh
bea --file main.bean query '.tables'     # prints table names, exit 0
bea --file main.bean query '.set'        # prints settings, exit 0
bea --file main.bean query '.errors'     # “(no errors)”, exit 0
bea --file main.bean query '.explain SELECT account LIMIT 1'
```

Raw engine stdout for `.help` (plain help text *prepended* to the JSON line):

```text
Shell utility commands (type help <topic>):
…
{"engine":"0.2.0","command":"query","ok":true,"data":{"text":"","errors":[]}}
```

`launch.helper_json` requires one JSON object on stdout, so this is exit 1 even
though the helper itself exited 0.

## Expected

Help and `.parse` output must go into the shell `outfile` / envelope `data.text`
the same way `.tables` does, so `bea query '.help'` prints the banner and exits
0. The JSON protocol must remain a single object on stdout.

## Actual

Beanquery/`cmd.Cmd` help (and `.parse` printing) write to the process stdout
while `text_answer` only captures `outfile`. The envelope returns empty `text`,
and the leaked banner corrupts the protocol so the frontend raises
“engine did not answer”.

## Root cause

```text
cli/src/bea_engine/query.py text_answer → PreciseShell.onecmd
  buffer = StringIO(); shell outfile = buffer
  # .tables / .set / .explain write to outfile → envelope text OK
  # .help / help / .parse write to real stdout → corrupt stdout + empty text
cli/src/cli/engine/launch.py:_parse
  json.loads(stdout) fails → BeaError “did not answer”
```

## Fix

Override `do_help` / parse rendering (or redirect `sys.stdout` for those
commands) so all one-shot shell utilities write only to `outfile`. Add a
regression: `bea query '.help'` and `bea query '.parse SELECT account'` exit 0
with non-empty human text; engine stdout is a single JSON object whose
`data.text` holds that content. Keep `.tables` as the control.

---

**Resolved 2026-09-16** — `PreciseShell.do_help` / `do_parse` write to `outfile` so one-shot `bea query '.help'` / `.parse` keep a single engine JSON envelope with the text in `data.text`. Covered by `cli/tests/test_query_help_parse_envelope.py`. Shipped with this board close.

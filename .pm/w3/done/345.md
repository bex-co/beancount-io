# `bea doctor parse` / `lex` / `print-options` exit 0 on syntax-invalid ledgers that `bea check` rejects

**Severity:** minor. **Estimate:** 25–40 minutes. **Owner:** cli. **A1:** a CI
or agent gate using `bea doctor parse`, `lex`, or `print-options` gets exit
**0** on truncated/invalid syntax while `bea check` exits **1**.
`print-options` is worse: it dumps default options (`title: Beancount`) as if
the named file loaded cleanly.

Found 2026-09-16 by continuous CLI QA ([c870 hunt](bbf53c50-27f4-48bc-b334-cece81e345f8)),
HEAD `7138997c`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Confirmed
`cli/tmp/qa-20260915/c871/`. Evidence: `c870/`. Extended 2026-09-16 for
`print-options` ([c1160 hunt](e13ff7b7-7676-40b7-bd24-775b24166b8a)), HEAD
`4e1ec8d2`; evidence `c1160/`.

## Repro

```sh
printf '2020-01-01 open\n' > half.bean
bea --file half.bean check
# exit 1 — syntax error, unexpected EOL, expecting ACCOUNT

bea doctor parse half.bean
# exit 0 — yacc recovery noise on stderr, no failure status

bea doctor print-options half.bean
# exit 0 — title: Beancount; operating_currency: []

# control (valid ledger with option "title" "QA …"):
bea doctor print-options main.bean
# exit 0 — real title / operating_currency
```

## Expected

These doctor ops exit nonzero on unparseable input, or USAGE documents them as
debug traces only (not validity gates). Prefer exit **1** when recovery ran /
load failed.

## Actual

`doctor.py` forwards bean-doctor’s exit unchanged; upstream recovers and
returns 0. `print-options` then renders defaults for a failed load. `bea check`
exits 1 on the same file.

## Fix

Map parse/load failure to exit 1 after these subcommands (or document + warn).
Regression: `half.bean` exits 1 for parse/lex/print-options; valid ledger stays
0; `check` unchanged.

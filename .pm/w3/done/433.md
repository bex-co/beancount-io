# Managed price-include failure text: a doubled full stop signed out, and a literal `None` offline

**Severity:** minor (wording and a leaked Python `None`). **Owner:** cli.
**Estimate:** 20–30 minutes for both symptoms.
Residual of w3/387, whose fix removed the double full stop only on the
`--strict-prices` path.

Found by continuous CLI QA 2026-09-26, `uv run bea` 0.3.0 at HEAD `8cd9732b`,
signed out, isolated config/cache.

```sh
# main.bean contains: include "https://beancount.io/prices/BTC-USD"
bea --file main.bean check          # exit 1
bea --file main.bean price status   # same line on stderr
# "... fetch failed (auth): Not logged in. Run bea cloud login, or set/replace BEA_TOKEN.. Run bea price status to inspect the source."
```

Expected: one full stop, as the strict path now produces.

Root cause: `cli/src/bea_engine/managed_load.py` ~l.404 formats
`f'...: {cause}. Run bea price status ...'` where `cause` already ends with
`.`. Apply the same "add the full stop only when missing" rule used in
`managed_price_cache.py` (~l.296–300); add the signed-out non-strict case to
`cli/tests/test_price.py`.

## Folded in 2026-09-26: `w3/439` — `--offline` with no cached revision reports the cause as `None`

Consolidated during the CLI QA verification round: `w3/439` is the **same six

computation and the single f-string that formats it into both the user-facing

**Severity:** minor. **Owner:** cli. **Estimate:** 15–20 minutes. **A1:** the
first `bea --offline` run on a new machine — the headline offline case — ends in
a message whose reason field is the literal Python `None`, and the same `None`
is written into the comment that replaces the include line during the load.

Found by continuous CLI QA 2026-09-26, `bea` 0.3.0 at HEAD `8cd9732b`, Darwin
26.5.1 arm64, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, closed stdin,
synthetic ledger, local-only (no fetch — `--offline`).

## Repro

```sh
cat > books/main.bean <<'EOF'
option "operating_currency" "USD"
include "https://beancount.io/prices/BTC-USD"
2024-01-01 open Assets:Crypto BTC
2024-01-01 open Equity:Opening
2024-01-05 * "buy"
  Assets:Crypto  0.5 BTC
  Equity:Opening
EOF

#### a cache directory that has a head for this feed but no usable revision
XDG_CACHE_HOME=$(mktemp -d) bea --offline --file books/main.bean check
```

Output (exit 1):

```
Error: .../books/main.bean: 1 error(s).
  .../books/main.bean:2: managed price source unavailable: include "https://beancount.io/prices/BTC-USD" in .../books/main.bean:2: None. Run bea price status to inspect the source.
```

## Expected

A human reason — `no cached revision` for offline-with-nothing-cached, or the
recorded fetch error when there is one. Never `None`.

## Actual

`bea_engine/managed_load.py:399`:

```python
cause = result.head.last_error if result is not None else "no cached revision"
```

The `"no cached revision"` fallback only covers a missing `ResolvedFeed`. In
offline mode `resolve_feed` always returns a `ResolvedFeed` whose head carries
`last_error=None` when nothing has ever failed, so `cause` is `None` and gets
formatted into both the user-facing error (`managed_load.py:405`) and the
`; managed price source unavailable: … (None)` comment (`managed_load.py:400`).

## Fix

```python
cause = (result.head.last_error if result is not None else None) or "no cached revision"
```

Regression coverage: offline load with an empty cache reports `no cached
revision` in the error text and in the swapped-in comment; a load whose head
records a fetch failure still reports that failure.

## Dedupe

No board item covers this string. Not w3/413 (portable export overwriting a local

`add price`).

## Objective

`run_bql_query` handed the model the engine's rendered text table verbatim. That
shape cannot say how many rows it has, what a row is, or whether a blank cell is
a zero — and three wrong-answer notes follow from it. Ask the engine for rows and
columns instead, and render them here.

## Context

- `cli/src/cli/ask/agent.py::run_bql_query` called the engine with
  `--format text`; the engine also answers `--format json` with
  `{"columns": [{"name", "type"}], "rows": [...]}` (`bea_engine/query.py`).
- The declared column type is what tells an empty Inventory from an empty tag
  set: both arrive as `[]`.
- `--format json` runs `SELECT` (and `BALANCES` / `JOURNAL`); `PRINT` and dot
  commands go through the shell path and are not reachable from the tool, which
  the prompt now says.

## Steps

1. Add `cli/src/cli/ask/results.py` with `format_result(query, answer)`.
2. Prefix every result with `N row(s) from the <relation> table`, and for the
   default relation add "one row per posting".
3. Derive the relation from the query's `FROM`, defaulting to postings.
4. Point `run_bql_query` at `--format json` and return `format_result(...)`.

## Files

- `cli/src/cli/ask/results.py`
- `cli/src/cli/ask/agent.py`

## Acceptance criteria

- [x] Every tool result opens with a row count and the relation it read.
- [x] A postings result states that a row is a posting.
- [x] `SELECT count(*)` over postings carries a note that it counted postings,
      with the entry-count query spelled out.

## Out of scope

- The zero rendering (t002) and the truncation budget (t003).

## Objective

Two question shapes were answered wrong because the prompt had no example of
them, and one line actively steered the model away from the only correct entry
count. Fix the prompt, and prove the examples run.

## Context

- `w3/455`: "how many transactions?" → 22 (the posting count) 2/2; "largest
  expense" right in 1 of 4 runs, one naming the smallest.
- The prompt said `FROM OPEN ON <date> / FROM CLOSE / FROM CLEAR` are "temporal
  modifiers, not table names", which reads as "`FROM` never names a table" —
  `FROM #entries` is how the entry count is reached.
- `count(DISTINCT x)` is a syntax error in this dialect.

## Steps

1. Say the default relation is postings and that `FROM #entries` selects entries;
   correct the `FROM` line to cover both relations and temporal modifiers.
2. Add worked examples: entry count vs posting count, `ORDER BY … DESC LIMIT 1`
   for "largest", a balance as of a date filtered to `^(Assets|Liabilities)`, and
   single-currency holdings filtered by account.
3. State that an unfiltered `sum(position)` is zero by construction and that a
   `0` is a real zero.
4. Run every documented example against the engine.

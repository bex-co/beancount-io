## Objective

An empty Inventory printed as a run of spaces, so a correct query
(`sum(position)` restricted by date or by currency) reached the model as a blank
cell and was read as "your ledger has no entries". Make the zero visible, and
say why a whole-ledger sum is zero.

## Context

- `w3/447`: live, twice, on a ledger worth 4500.00 USD; and again as
  "there is no EUR balance" on one holding 800.00 EUR.
- Every transaction balances, so any unfiltered `sum(position)` is zero by
  construction — no number of prompt examples covers every filter that happens
  to net to zero, which is why the result itself has to say it.
- `bea query`'s own text rendering is upstream beanquery's and is unchanged.

## Steps

1. Render an `Inventory` cell with no positions as `0`; render a `null` as
   `(none)` and an empty set as `(empty set)` so no cell is blank.
2. When a result contains a zero inventory, append the note explaining that the
   matched postings cancelled out and naming the account filter that answers the
   question.
3. Report an empty result as `0 row(s) … not an error and not a zero`.

## Files

- `cli/src/cli/ask/results.py`

## Acceptance criteria

- [x] `SELECT sum(position) WHERE currency = 'EUR'` comes back as `1 row(s)` with
      a `0` cell and the explanation, never as whitespace.
- [x] No line of a rendered result is whitespace only.
- [x] Live: "how much EUR do I hold?" answers `800.00 EUR`; "net worth as of
      2024-03-01" answers `4,500.00 USD`.

## Out of scope

- Changing `bea query`'s own text output, which is upstream's rendering.

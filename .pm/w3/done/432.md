# `bea add price` treats managed-feed points as ledger prices: "already recorded" at a cache path, or `--force` to "record another quote"

**Severity:** minor. **Owner:** cli. **Estimate:** 30–45 minutes. **A1:** the
documented override path ("a price you declare yourself wins") is blocked or
mis-explained when a ledger includes `https://beancount.io/prices/<ALIAS>`.

Found by continuous CLI QA 2026-09-26, `uv run bea` 0.3.0 at HEAD `8cd9732b`,
Darwin 25.5.0, signed-in QA account (device flow, isolated config), synthetic
ledger.

## Repro

```beancount
option "operating_currency" "USD"
include "https://beancount.io/prices/BTC-USD"
2024-01-01 open Assets:Crypto BTC
```

```sh
bea --file main.bean list price --to-date 2025-02-28   # feed point: 2025-02-28 BTC 84619.57 USD
bea --file main.bean add price --date 2025-02-28 -c BTC --amount '84619.57 USD'
# exit 0 "Price already recorded at <cache>/bea/managed-prices/<hash>/<rev>.effective.<id>.beancount:17; nothing was written."
bea --file main.bean add price --date 2025-02-28 -c BTC --amount '84000 USD'
# exit 2 "BTC already has a 2025-02-28 price of 84619.57 USD (at <same cache path>:17); refusing 84000 USD. Pass --force to record another quote."
bea --file main.bean add price --date 2025-02-28 -c BTC --amount '84000 USD' --force
# writes; `price status` SHADOWED=1 and `list price` shows ONE 2025-02-28 price (84000) — not "another quote"
```

## Expected

Per `docs/USAGE.md` "Managed price includes" and ADR015 §precedence, a
ledger-authored price for the same date/pair shadows the managed point. So
the duplicate/conflict checks in `add price` should consider only
ledger-authored prices: a differing amount writes without `--force` and says
it shadows the managed point; an exact match of a feed point either writes
(pinning it in the user's file) or, if kept as a no-op, names the managed
source URL rather than an internal cache file.

## Root cause

`cli/src/bea_engine/ledger/adding.py` ~l.395–433 scans all loaded `Price`
entries, including feed entries whose `meta.filename` is in the managed cache.
`bea_engine/managed_price_cache.managed_source_for_path` already identifies
those paths (used by the write boundary in `ledger/write.py:77`); the
duplicate/conflict scan should skip or specially report them.

Dedupe: w3/291 (same-date conflict, done) introduced this check for ledger
prices; w3/387, w3/412/413, w4/171/172/180 cover other managed-price paths.
Nothing covers feed entries in the `add price` duplicate scan.

---

**Resolved 2026-10-02** — `bea add price` now checks only ledger-authored quotes for duplicates and conflicts. Matching feed points can be pinned locally, differing points override without `--force`, and successful writes name each shadowed managed source, including reciprocal pairs. Local included-file duplicate/conflict rules and read-only feed protections remain intact. Shipped in `a277d4e2` (`cli`). Six real-feed regressions failed before the fix; the focused suite passed 199 tests with one skip, and `make check-all` passed 2,412 tests with one skip. All fixtures use isolated synthetic ledgers and a local HTTP server; the public-tree secret scan passed.

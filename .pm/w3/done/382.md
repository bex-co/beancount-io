# `bea doctor linked` with a malformed location dumps a 118-line traceback (string exit code crashes `int()`)

Severity: minor. **Estimate:** 30m. **Owner:** cli. Exit code
accidentally right (1); output is bea internals instead of upstream's
one-line message.

```sh
cd cli
cat > /tmp/d.bean <<'EOF'
option "operating_currency" "USD"
2026-01-01 open Assets:Cash USD
EOF
uv run bea doctor linked /tmp/d.bean 2026-01-10
# exit 1, stderr = 118-line rich traceback ending in:
# ValueError: invalid literal for int() with base 10: 'Invalid line number or link format for location.'
```

Upstream's actual complaint is the quoted sentence; it should be the
whole output (as `python -m` semantics print a string `sys.exit`
message and exit 1). Reproduced 2/2, HEAD `b94d9461`, bea 0.2.0.

## Root cause

`scoped._invoke` (`cli/src/bea_engine/scoped.py:39-45`), which runs
`doctor region`/`linked` in-process, assumes `SystemExit.code` is
int-or-None:

```python
except SystemExit as exit_status:
    return int(exit_status.code or 0)
```

Upstream `bean-doctor linked` validates the location itself and raises
`SystemExit("Invalid line number or link format for location.")`
(beancount `scripts/doctor.py:308`) — a *string* code. `int(...)` blows
up, and the engine's rich traceback handler prints bea internals. Only
reachable with values that pass click's arg parsing but fail
`parse_location` (a bare date for `linked`); a mistyped `region` fails
earlier in click with a clean exit-2 usage error (verified control),
and valid-link match/miss paths exit 0/1 cleanly per the doctor table.

## Fix direction

Handle string codes in `_invoke`: print the message to stderr, return
1 — exactly CPython's `sys.exit(str)` semantics, and exactly the
"usage errors and status are its own" passthrough the docstring
promises. Regression test: malformed `linked` location asserts exit 1
with stderr equal to upstream's sentence (no traceback frames). Check
`sibling int(...)` conversions of `SystemExit.code` for the same
assumption while here.

## Blast radius / dedupe

- Affected: `doctor linked` (and any `scoped` op whose location fails
  `parse_location` post-click). Other doctor ops run via `run_native`
  in a real upstream process and are unaffected.
- Searched all `.pm/**/*.md` for scoped/parse_location/doctor-traceback:
  no match.

---

**Resolved 2026-09-21** — `bea doctor linked` with a malformed location now
prints upstream's one sentence and exits 1, instead of 118 lines of bea
internals.

`scoped._invoke` assumed `SystemExit.code` was int-or-None and did
`int(exit_status.code or 0)`. Upstream `bean-doctor linked` validates the
location itself and raises `SystemExit("Invalid line number or link format for
location.")` — a *string* code. `int()` raised `ValueError`, and the engine's
rich traceback handler rendered it.

The conversion moved into a `_status` helper that reproduces CPython's own
`sys.exit(code)` rule, which is what upstream is written against and what the
docstring's "its usage errors and status are its own" already promised: None is
0, an int passes through, and anything else is printed to stderr with exit 1.
Note that `SystemExit("0")` is therefore a message and exits 1 — only the int
0 means success, which is also CPython's rule and is pinned in the tests.

The sibling check the note asked for: `int(...)` on a `SystemExit.code` appears
nowhere else in `cli/src` — the other `SystemExit` sites in `protocol.py` and
`main.py` raise with ints they own.

Verified: stderr is now exactly `Invalid line number or link format for
location.` at exit 1, with no traceback frames. Controls unchanged and measured
against the doctor exit table — a valid link match exits 0, a link miss exits 1
with `matched no entries`, and a mistyped `region` still fails earlier in click
with exit 2.

Regression coverage is `cli/tests/test_doctor_string_exit_code.py`. Reverting
just the call site (keeping `_status` so the module still imports) fails the
behavioral test with the full traceback. `cd cli && make check-all` passes
(1557 tests).

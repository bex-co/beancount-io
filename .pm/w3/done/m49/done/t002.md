## Objective

`bea add custom -v number:5 -v number:-2` must write a line Beancount reads
back as two values. Today the upstream printer joins them with a space and the
grammar reads `5 -2` as a subtraction, so the file holds `3`.

## Context

- `cli/src/bea_engine/ledger/writer.py` `format_entry` (Custom branch) and
  `write_custom`; write validation only looks for load errors, so the merged
  value passes.
- Verified against the engine parser: `custom "b" 5 (-2)` reads as `[5, -2]`
  and `custom "b" 100 (-20) USD` as `[100, -20 USD]`.
- `bea query 'PRINT' -f beancount` uses the upstream printer directly; note
  whether the parenthesized form survives it.

## Steps

1. Render a negative number — and a negative amount's number — in parentheses
   in the Custom branch so no pair can merge.
2. Add a round-trip assertion: parse the rendered line and compare the values
   to the request, refusing a write that would reload differently.
3. Keep positive-value output byte-identical.

## Files

- `cli/src/bea_engine/ledger/writer.py`
- `cli/tests/`

## Acceptance criteria

- [x] `number:5` + `number:-2` reloads as `5` and `-2`.
- [x] `number:100` + `amount:-20 USD` reloads as `100` and `-20 USD`.
- [x] Positive values, and a negative after a bool/date/text value, are unchanged.

## Out of scope

- Upstream `PRINT -f beancount` rendering, if the loss is upstream's printer.

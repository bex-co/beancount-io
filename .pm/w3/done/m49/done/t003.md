## Objective

A currency-less cost (`{}`, `{2026-03-01}`) must not crash after the entry is
already on disk, a total cost (`{{250.00 USD}}` must not report the wrong
number, and a currency-only cost (`{EUR}`) must not be written as `{}`.

## Context

- `cli/src/bea_engine/protocol.py` `_jsonable` (~l.175–190) does not pass a
  CostSpec's `currency` through `_jsonable`, so the parser's `MISSING` class
  reaches `json.dumps`; the encode happens after `write.append` and outside the
  `try`, so no error envelope is produced and each retry appends again
  (`w3/414`, a regression of `w3/240`/`0d47a757`).
- The same branch reports `number_per` and drops `number_total`.
- The frontend mirror `cli/src/cli/output.py` (~l.343–348) has the same shape.
- `format_entry` renders a CostSpec through the upstream `EntryPrinter`, which
  prints a currency only alongside a number (`w3/416`).

## Steps

1. Serialize a CostSpec explicitly: MISSING → `null` for every field, and keep
   the total so the documented `add transactions` round trip holds.
2. Build (or at least prove serializable) the answer before `write.append`, so a
   response failure can never follow a committed write.
3. Render a currency-only or label-only cost faithfully, or refuse it — the
   validated text and the JSON answer must describe the same constraint.
4. Report an engine that dies without an envelope during a write as exit 4
   ("outcome unknown"), per the exit-code table.

## Objective

An import into an account opened for a single currency must book that currency,
and a cell whose unambiguous currency symbol contradicts the resolved currency
must be refused rather than relabelled.

## Context

- `cli/src/bea_engine/importing.py:127–134` passes the ledger's single
  `operating_currency` and never consults the source account's open directive.
- `cli/src/bea_engine/csv_mapper.py:64–95` `_split_amount_sign` strips any
  Unicode `Sc` symbol and discards it.
- `importing.py:540–541` `_blocked_reason` always advises widening the open
  directive — advice that books euros as dollars if followed.
- `--csv …,currency=EUR` is rejected because no such column exists.

## Steps

1. Resolve the row currency as: currency column → the source account's single
   open currency → the single operating currency → refuse naming the remedy.
2. Keep stripping symbols, but refuse (exit 2, row named) a cell whose
   unambiguous symbol contradicts the resolved currency; `$`/`¥` stay ambiguous
   and accepted.
3. Accept a constant currency and remember it with the mapping.
4. When a blocked row's cells carried another symbol, point the hint at the
   currency setting instead of the open directive.

## Files

- `cli/src/bea_engine/importing.py`

## Acceptance criteria

- [x] `Assets:EurBank EUR` in a USD ledger imports `-4.50 EUR` with no flags.
- [x] A `€` cell posted to a USD account is refused naming the row and symbol.
- [x] A constant currency can be named without editing the bank CSV.
- [x] A `$` column in a USD ledger is unchanged.

## Out of scope

- Multi-currency accounts choosing among several open currencies.

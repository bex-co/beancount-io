# A failed `--into` write tells you to "run against the root with `--into`" — which is exactly what you ran

**Severity:** minor. **Owner:** cli. **Estimate:** 20–30 minutes. **A1:** every
unknown-account failure on a `--file root --into part.bean` write appends a hint
instructing the agent to rerun the command it just ran, once per error. It reads
as "your invocation was wrong" when the invocation was right, and it crowds out
the real remedy (`bea add open …`).

Found by continuous CLI QA 2026-09-26, `bea` 0.3.0 at HEAD `8cd9732b`, Darwin
26.5.1 arm64, isolated config/cache, closed stdin, synthetic ledgers.

## Repro

```sh
mkdir -p books/parts
cat > books/main.bean <<'EOF'
option "operating_currency" "USD"
include "parts/*.bean"
2024-01-01 open Assets:Bank:Checking USD
2024-01-01 open Expenses:Uncategorized USD
EOF
printf '2024-01-03 * "seed"\n  Assets:Bank:Checking  -1.00 USD\n  Expenses:Uncategorized  1.00 USD\n' \
  > books/parts/existing.bean

bea --file books/main.bean add transaction --date 2024-04-01 -n x \
    --into parts/existing.bean -p 'Assets:Nope 1.00 USD' -p 'Expenses:Uncategorized -1.00 USD'
```

Output (exit 1):

```
Error: The change would leave the ledger invalid; nothing was written.
  Proposed append (not written): Invalid reference to unknown account 'Assets:Nope' To create it, use bea add open --account Assets:Nope --date YYYY-MM-DD.
  existing.bean is included by .../books/main.bean; on its own it lacks the accounts and options that root provides. Run against the root and pick the destination with --into: bea --file .../books/main.bean <command> --into parts/existing.bean.
```

## Expected

The "run against the root with `--into`" recipe appears only when the user
pointed `--file` at an included leaf — the case it was written for. A write that
already names the root plus `--into` gets the account remedy alone.

## Actual

`bea_engine/ledger/write.py:541` calls `root_ledger_hints(file)` with the write
*target*, not the ledger the command was run against, so the hint fires whenever
the target happens to be an included file — including when `--into` was used
correctly. Control: `bea --file books/parts/existing.bean add transaction …`
(leaf as `--file`) produces the same hint, and there it is correct.

## Fix

Pass the snapshot root (or the invoked `--file`) alongside the target and emit
the hint only when they differ; `adding.py:533` is the other caller and needs the
same guard. Regression coverage: root + `--into` failure carries the `add open`
remedy and no root-ledger hint; leaf-as-`--file` failure still carries it.

## Dedupe

No board item mentions `root_ledger_hints`. Hint introduced in `24204071`
("close the gaps a first-time beancount user hits"); not w3/228 or w3/344, which
are about the *destination-missing* message, not this one.

# Mobile transaction detail crashes because its write-action selector is not imported

Severity: major. Estimate: 20m. Package: mobile. A2 — users must be able to inspect transactions after opening a ledger.

Environment: HEAD 27873fc2, native development build 1.20260906.47 loading current JS from local Metro 8083; iPhone 17e, iOS 26.5, English, System/light; signed-in QA session on https://beancount.io with read-only public open_ledger/example.

Repro (September 10):
1. Open beancount:///ledger/open_ledger/example/entry/c94ed5271c6df2e9a494015d1dcb6121 from the running app.
2. Instead of the Hoogle transaction detail, the development client displays Render Error: Property 'shouldShowTransactionWriteActions' doesn't exist.
3. Terminate and relaunch io.beancount.ios. Tap Hoogle in Home's Recent Transactions card (logical x180,y612 on this device). The same render error recurs.

Expected: September 7, 2017 Hoogle transaction with its postings; read-only readers see no edit/delete actions. Actual: rendering stops at transaction-detail-screen.tsx:409. A production build's error presentation was not tested; the unbound identifier is not a simulator permission or development-warning issue.

Root cause: mobile/src/screens/transaction-detail-screen/transaction-detail-screen.tsx:409 calls shouldShowTransactionWriteActions(canWrite, sha256sum) without importing it. The export exists in selectors/select-transaction-write-actions.ts:5. Commit 41de310c added the call and helper while fixing the former w3/021 inert read-only actions, but omitted the import. yarn typecheck fails with TS2304: Cannot find name 'shouldShowTransactionWriteActions' at (409,28), independently confirming the live ReferenceError.

Fix: import the existing selector into its actual screen and run the package checks. Verify the live transaction screen renders through both a Home row and an entry link, preserves read-only hiding, and enables writer actions only with ready source context. Keep loading/empty/error handling and the permission gate intact. The isolated selector tests do not exercise the missing import; retain typecheck and a native screen smoke check as integration validation.

Blast radius: openTransactionDetail callers in Home Recent Transactions, Transactions, account detail, Reports account-transactions card, and merchant detail all target this screen; app/(app)/transaction-detail.tsx mounts it and entry app-links also resolve there. Home and the entry link reproduced live; other callers are source-traced. The failing call runs once a real entry is available regardless of canWrite. Writer sessions, empty/denied/expired/network-failure states and Android were not exercised.

Controls/evidence: Home and Transactions render normally; the immediately preceding shared commit link opened valid +4/-4 detail and one Back returned to the retained Mr. Marcel search. A read-only GetLedgerEntryContext query for the same public ledger/hash returns the Hoogle entry plus source context, saved in mobile/tmp/qa-2026-09-10/entry-api.json. This API helper uses its own in-memory session and is not native auth injection. entry-link.jpg and entry-home-repeat.jpg show both crashes; typecheck.log contains TS2304. entry-error-logs.json is a bounded capture with no additional emitted messages, so the on-screen stack and typecheck are the error evidence.

Dedupe: searched all .pm markdown including done for the selector name, transaction crash, render error and 41de310c. No open overlap. This is a regression introduced by the completed w3/021 fix (its inbox file was removed in 41de310c), not a duplicate of its original inert controls report. Current main still has the missing import. No product code changed, no production write, and no shipping performed by this QA run.

## Objective

Read the budget funnel shipped in m1/m2 and make the two deferred product decisions with data: (1) does /budget need an interval filter, (2) keep/tune/hide the Home panel's zero-budget CTA state.

## Status (2026-08-24) — review run, both decisions recorded

The wait condition cleared: builds carrying the instrumentation have been out for a real window — 1.20260814.42 (2026-08-14) shipped the full budget feature (`6119176`), followed by .43 and .44. Pulling the funnel, though, finds the pipeline itself dead, and that is the finding that decides both questions.

**Numbers.** `page_view_budget` = 0, `budget_panel_see_all` = 0, `budget_add_submitted` = 0, `budget_deleted` = 0 — not over the last week, but ever, for every event in the app. Root cause, verified in the shipped tag `mobile-v1.20260814.42`: `mobile/src/config.ts` ships `analytics.mixpanelProjectToken: ""` (a `// TODO` since the monorepo move), and `MyAnalytics` (`mobile/src/common/analytics.ts`) only constructs the Mixpanel client when the token is non-empty, so `track()` is a silent no-op in every production build. There is no Mixpanel project to query and no credentials in the repo — correctly, for a public repo. Budgets-per-ledger distribution: unavailable, same cause. Waiting longer cannot change these numbers; only configuring the sink can.

**Decision 1 — interval filter on /budget: no.** The spec cut it pending usage evidence; the evidence is zero because none can exist. Building it now would be exactly the speculative UI this task exists to prevent. Reopen only after the analytics sink is live and shows /budget sessions where the card list is long enough to need filtering.

**Decision 2 — Home panel empty-state: keep the CTA.** The spec chose the CTA for discoverability with an explicit "revisit with analytics" note; with no data, that original reasoning stands unchanged. No copy softening, no hiding.

**Follow-up recorded** (w3 inbox): the dead sink is app-wide — every `analytics.track` call no-ops in production, so any future analytics-gated decision on this board hits the same wall. Fix means provisioning a Mixpanel project and feeding the token at build time (EAS secret → `EXPO_PUBLIC_*`), never committing it here; or deleting the wrapper honestly. Product/infra call, out of m3's scope.

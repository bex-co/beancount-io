# `bea add transaction` with bare `@` / `@@` surfaces Python `MISSING` class tokens in the error

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** cli. **A1:** an
agent that mistypes a price (`1 AAPL @` without an amount) gets
`Invalid token: '<class'` / `Invalid token: ''beancount.core.number.MISSING'>'`
instead of a usage error naming the posting — looks like an internal crash, not
a fixable argv mistake.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `e0a3679c`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
bea --file main.bean add transaction --date 2020-02-01 --narration y \
  --posting 'Assets:Broker 1 AAPL @' \
  --posting 'Assets:Cash -100 USD'
# exit 1 — nothing written
# …/main.bean:7: Invalid token: '<class'
# …/main.bean:7: Invalid token: ''beancount.core.number.MISSING'>'

bea --file main.bean add transaction --date 2020-02-01 --narration y \
  --posting 'Assets:Broker 1 AAPL @@' \
  --posting 'Assets:Cash -100 USD'
# same MISSING class-token errors
```

Working control — incomplete cost braces fail cleanly at parse:

```sh
bea --file main.bean add transaction --date 2020-02-01 --narration y \
  --posting 'Assets:Broker 1 AAPL {150' \
  --posting 'Assets:Cash -100 USD'
# exit 2 — Invalid transaction options … unexpected EOL, expecting RCURL …
```

## Expected

Reject incomplete `@` / `@@` (price present but number/currency `MISSING`) with
a usage error on `--posting N` before any candidate ledger text is built — e.g.
require `@ NUMBER CURRENCY` / `@@ NUMBER CURRENCY`.

## Actual

The posting parser accepts bare `@`/`@@` and leaves Beancount `MISSING`
sentinels on the price. `format_transaction` then stringifies those sentinels
into the candidate append (`<class 'beancount.core.number.MISSING'>`). Validate
lexes that garbage and reports `Invalid token` with the class repr. Nothing is
written (good), but the message is not actionable.

## Fix

After parsing each posting (alongside the existing `units is MISSING` checks in
`adding.py`), if `price` or `cost` components are `MISSING`, raise
`UsageError` naming the posting and the required `@`/`@@` shape. Do not call
`format_transaction` until all cost/price fields are concrete or intentionally
absent. Regression: the two bare `@`/`@@` repros exit 2 with a clear posting
message and no `MISSING` / `<class` text; valid `@ 160.00 USD` still writes.

# `bea add custom` silently merges a negative value into the value before it (`5`, `-2` → `3`)

**Severity:** major (silent data change, exit 0). **Owner:** cli. **Estimate:**
30–45 minutes. **A1:** an agent recording a budget/target `custom` with a
negative number or amount gets a different directive than it asked for, and
every later read (`list`, `check`, reports, Fava budgets) agrees with the wrong
one.

Found by continuous CLI QA 2026-09-26, `uv run bea` 0.3.0 at HEAD `8cd9732b`,
Darwin 25.5.0, isolated config/cache, synthetic ledger, closed stdin.

## Repro

```sh
# any valid ledger, e.g. one with `2024-01-01 open Expenses:Food USD`
bea --file main.bean add custom --date 2024-02-05 -t budget -v number:5 -v number:-2
# exit 0; JSON echo says values [5, -2]; file gets:  2024-02-05 custom "budget" 5 -2
bea --file main.bean list custom          # VALUES: number:3
bea --file main.bean add custom --date 2024-02-06 -t target \
  -v account:Expenses:Food -v number:100 -v 'amount:-20 USD'
# file:  custom "target" Expenses:Food 100 -20 USD
bea --json --file main.bean list custom   # values: [account, {amount 80 USD}] — two values became one
bea --file main.bean check                # exit 0
```

Reproduced twice from a pristine fixture in fresh processes.

## Expected

The written line reloads as exactly the requested values (`5`, `-2`;
`100`, `-20 USD`). Beancount's grammar reads `NUMBER - NUMBER` as a
subtraction, but a parenthesized value is a separate value — verified with the
engine's parser: `custom "b" 5 (-2)` → `[5, -2]`, `custom "b" 100 (-20) USD` →
`[100, -20 USD]`. Other orderings (`TRUE -20 USD`, a date followed by `-3`) are
already unambiguous.

## Root cause

`cli/src/bea_engine/ledger/writer.py` `format_entry` (Custom branch, ~l.199–203)
passes number/amount values to the upstream printer, which joins them with
spaces; a negative value following a bare number is re-parsed as `a - b`.
`write_custom` (~l.385) feeds it. Write validation only checks for ledger
errors, so the merged value passes.

## Fix

In `format_entry`, render a negative number (and a negative amount's number)
in parentheses whenever it follows a numeric value — or always, for
simplicity — and add a round-trip assertion (parse the rendered line, compare
values to the request) so a write that would reload differently is refused.
Regression: number+negative number, number+negative amount, and controls that
must stay byte-identical (positive values, negative after bool/date/text).

## Blast radius

`bea query 'PRINT' -f beancount` on a ledger containing `custom "b" 5 (-2)`
prints `custom "b" 5 -2` (upstream printer), so a re-imported export has the
same corruption; `bea format` preserves the parenthesized form correctly. The
hosted custom writer was not exercised.

Dedupe: searched `.pm/**` for custom + negative/merge/subtract; w3/232
(empty custom), w3/305 (list prefixes), w3/419 (number spellings) are
different. `git log -S` shows the Custom value path unchanged since
`ff47e5c6`.

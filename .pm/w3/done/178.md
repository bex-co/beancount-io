# Retain directive types in the mobile account journal

Severity: minor. Estimate: 35–50m. Package: mobile. A2: a newcomer can distinguish an account opening, balance assertion and padding instruction while reviewing account history.

Environment: production API; authenticated QA session using public open_ledger/minimax; HEAD f1965988, mobile source 7538fb0d, client 1.20260906.47, iPhone 17e / iOS 26.5, English/default text/light appearance. Read-only.

Repro:

2. Compare the December31,2025 row with the non-transaction row on December30,2025: both display Assets:Current:Cash, the same wallet icon and +0.00 MUSD. No Balance or Pad type is shown. December31,2025 hash337f22929f1b864dc0ed7b9040cf85a6 is Balance; December30 hash e1fecec9fdf8778fe2d6fe087a213424 is Pad with source_account Equity:Adjustments. The oldest item is Open. These types are supplied by the server, not inferred from the screenshot. Running-balance values remain distinct where appropriate and scrolling reaches No more entries. There is no demonstrated arithmetic or pagination failure.

Expected: a mixed account journal identifies each non-transaction directive's type along with its account. Actual: distinct directive kinds become generic zero-change account rows, and their type cannot be recovered by tapping: AccountDetailScreen intentionally only attaches navigation to transaction entries. The missing label is the finding; this does not require adding new directive navigation.

Root cause: mobile/src/screens/account-detail-screen/selectors/select-account-journal.ts:111–119 entryTitle chooses entry.account before directive_type, and the display AccountJournalRow carries no directive type. components/account-entry-row.tsx displays that title, account icon, change and running balance without a separate type label. Existing translations include open/balance/pad. Only AccountDetailScreen consumes this row selector/component; its app/(app)/account-detail.tsx route is used by account selection and external account links. No API change needed.

Fix: retain the server directive_type in the row model and render a concise recognizable localized type for non-transactions, preserving the relevant account identity. Keep transaction payee/narration, pending indication, changes, running balances, date grouping, pagination and transaction navigation intact. Verify Open, Balance and Pad from this native journey remain distinguishable at default/enlarged text sizes; cover other supported non-transaction types in selector/render coverage without asserting they were exercised live. Do not hide non-transactions or relabel them as transfers.

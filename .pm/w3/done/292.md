# `report *` with a non-matching `--account` collapses to “no dated activity”

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** cli. **A1:** a
typo’d or over-narrow `-a` / `--account` filter makes overview, income
statement, balance sheet, and trial balance look like an empty ledger
(`period.start` / `as_of` null, title “no dated activity”) even though the books
have dated transactions — while `bea balance Nomatch` keeps the real ledger
period.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `d6f132a1`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
# Fixture with dated txns 2020-01-01 … 2020-03-10 (any non-empty ledger)

bea --file main.bean report income-statement -a Nomatch
# Income Statement — no dated activity

bea --file main.bean report overview -a Nomatch
bea --file main.bean report balance-sheet -a Nomatch
bea --file main.bean report trial-balance -a Nomatch
# each title: “… — no dated activity”; account: Nomatch

bea --json --file main.bean report income-statement -a Nomatch
# data.period.start / end_exclusive / as_of are all null

# Control — same filter on balance keeps the ledger window:
bea --file main.bean balance Nomatch
# Trial Balance — 2020-01-01 through 2020-04-01
# (and “No accounts match Nomatch.” when using positional balance filters)
```

## Expected

A non-matching account filter still reports against the ledger’s dated window
(or the requested `-t` range), with empty totals and a clear “no accounts
matched” note — not “no dated activity”.

## Actual

All four `report` commands derive the displayed period from filtered entries
only. Zero matches → null period → “no dated activity”, which agents read as
“this ledger has no transactions”.

## Root cause

Report period metadata is taken from the post-filter entry set / Fava
`TimeFilter` result (`cli/src/cli/commands/report.py` uses
`period["start"]` else `"no dated activity"`). Account filtering empties that
set before period inference.

## Fix

Compute the display period from the unfiltered ledger (or the explicit `-t`)
before applying `--account`, and surface a zero-match message when the filter
hits nothing. Regression: the Nomatch repro keeps the real dates; a real
`-a Cash` filter still narrows balances; empty ledgers still say no dated
activity.

## Dedupe

Not w3/288 (phantom Opening-Balances on mid-period clamp). Not w3/246
(`bea balance` semantics). No open note covers “no dated activity” from a
failed account filter on a non-empty ledger.

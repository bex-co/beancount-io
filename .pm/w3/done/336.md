# `bea example -o PATH` silently overwrites an existing ledger (exit 0)

**Severity:** major. **Estimate:** 20–30 minutes. **Owner:** cli. **A1:** an
agent that runs `bea example … -o main.bean` on an existing ledger **destroys
the books** with exit **0** and no warning, while `bea init` on the same path
refuses with exit **4**.

Found 2026-09-16 by continuous CLI QA ([c780 hunt](a1bc5bd1-a483-4aab-8155-044e66518236)),
HEAD `cda5f986`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Confirmed
`cli/tmp/qa-20260915/c786/`. Evidence: `c780/`.

## Repro

```sh
# main.bean contains “Real books”
bea example --date-begin 2020-01-01 --date-end 2020-01-31 -o main.bean
# exit 0 — file grows to ~15KB example; “Real books” gone

bea init main.bean --currency USD
# exit 4 — Already exists … init never overwrites a ledger.
```

## Expected

Refuse existing `-o` targets like `init` (`ConflictError`, exit **4**) unless
`--force`, or document that `-o` clobbers.

## Actual

`example.py` forwards to `bean-example`, which truncates `-o` with no existence
check.

## Fix

Preflight `-o`/`--output`; raise ConflictError if the path exists. Regression:
repro exits 4 with bytes unchanged; fresh path and stdout-only OK.

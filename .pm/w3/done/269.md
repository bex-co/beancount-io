# `bea query --format beancount` on a column SELECT exits 0 with “(no rows)” when empty, but exit 2 when rows exist

**Severity:** minor. **Estimate:** 15–25 minutes. **Owner:** cli. **A1:** an
agent that validates `--format beancount` against a SELECT on an empty or
filtered-empty ledger sees success and “(no rows)”, then the same query fails
once data appears — format compatibility looks ledger-dependent.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `891f54bb`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
# empty.bean: option + open only (no postings)
bea --file empty.bean query --format beancount 'SELECT account LIMIT 1'
echo exit=$?
# exit 0 — stdout: (no rows)

# full.bean: same opens + one balanced transaction
bea --file full.bean query --format beancount 'SELECT account LIMIT 1'
echo exit=$?
# exit 2
# Error: --format beancount prints directives, so the query must return entries;
# use PRINT, or --format text or csv for a column result.

bea --file full.bean query --format beancount 'SELECT account WHERE false'
# exit 0 — (no rows)  again, because the result set is empty
```

Working control: `SELECT … GROUP BY` with rows always hits the exit-2 message;
`PRINT … --format beancount` succeeds on entries.

## Expected

Refuse column-result queries under `--format beancount` up front (same usage
error) whether the result set is empty or not — emptiness must not hide an
incompatible format.

## Actual

The beancount-format guard runs only when there is a non-empty row/entry
payload to render. An empty table short-circuits to “(no rows)” / exit 0 before
that check.

## Fix

Detect statement kind (or result type) before the empty short-circuit: if the
cursor is a column table (not entries) and `--format beancount`, raise the
existing usage error even when `rows == []`. Regression: the three empty
SELECT cases above exit 2 with the directives message; `PRINT` and text/csv
unchanged.

## Dedupe

Not w3/242 (`PRINT` with `--format csv` ignores csv). That note’s control even
documents nonempty `SELECT … --format beancount` → exit 2; it does not cover
the empty-result false success. No open note covers empty vs nonempty asymmetry.

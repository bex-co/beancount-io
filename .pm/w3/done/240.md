# `bea add transaction` JSON returns cost as `number_per`/`number_total`, which `add transactions` rejects (`number` required)

**Severity:** major. **Estimate:** 30–45 minutes. **Owner:** cli. **A1:** an
agent that copies a successful `add transaction` JSON `directive` (or its
postings) into `add transactions` gets a schema failure on `cost.number`, even
though `list transaction` already returns the writeable `{number, currency}`
shape.

Found 2026-09-15 by continuous CLI QA against `main`, HEAD `1bb7d4c0`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only (`Assets:Investments:HOOL` opened).

## Repro

```sh
bea --json --file main.bean add transaction --date 2024-03-02 --narration buy \
  --posting 'Assets:Investments:HOOL 5 HOOL {10.00 USD}' \
  --posting 'Assets:Bank:Checking -50 USD'
# data.directive.postings[0].cost =
#   {"number_per":"10.00","number_total":null,"currency":"USD",
#    "date":null,"label":null,"merge":false}

# paste that directive's postings into rows.json and:
bea --json --file main.bean add transactions --from rows.json
echo exit=$?
# exit 1
# "Row 1, postings.0.cost.number: Field required"
```

Working controls:

```sh
# documented write schema succeeds:
{"cost":{"number":"10","currency":"USD"}}

# list / query inventory return the writeable shape:
bea --json --file main.bean list transaction --account HOOL --limit 1
# postings[0].cost = {"number":"10","currency":"USD","date":"2024-03-02","label":null}
# feeding list JSON into add transactions succeeds

bea --json --file main.bean query \
  'SELECT account, sum(position) WHERE account ~ "HOOL" GROUP BY 1'
# inventory cost cells also use {"number","currency","date","label"}
# — same writeable shape; only add-transaction's response uses number_per
```

`USAGE.md` documents bulk cost as `{"number","currency","date?"}` only.

## Expected

Every customer-facing JSON cost on the write/read path uses one schema. Prefer
the documented `{number, currency, date?, label?}` everywhere (add response,
list, bulk input). Accepting `number_per` as an alias is optional.

## Actual

`add transaction` serializes Beancount's `Cost` namedtuple via a path that
exposes `number_per`/`number_total`/`merge`. Bulk `Posting.cost` is a Pydantic
model requiring `number`. List goes through a different serializer that already
emits `number`.

## Root cause

```text
add response: metadata_to_json / directive dump keeps Cost._asdict()-like keys
list/read:    business JSON maps Cost → {number, currency, …}
bulk write:   models.Cost(number=…, currency=…)
```

## Fix

Serialize costs in `add` responses the same way `list` does (`number`, not
`number_per`). Optionally accept `number_per` as an input alias with a clear
error if neither is present. Regression: after `add transaction` with
`{10 USD}`, the returned `directive.postings[].cost` must round-trip through
`add transactions` without schema errors; list shape unchanged.

---

**Resolved 2026-09-16** — CostSpec JSON now emits `{number, currency, …}` like Cost/list, so add-transaction responses round-trip into `add transactions`. Covered by `cli/tests/test_add_cost_roundtrip.py`. Shipped with this board close.

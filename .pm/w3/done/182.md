# Let the filter Apply button fit enlarged text

Severity: minor. Estimate: 45–60m. Package: mobile. A2: users who enlarge text can read the action that applies their transaction filters.

Environment: production API, authenticated QA on public open_ledger/freelancer-invoicing, HEAD f1965988/mobile source7538fb0d, native1.20260906.47, iPhone17e/iOS26.5, English/System-light.

Repro:
1. Set content_size to accessibility-extra-extra-extra-large, relaunch and settle. Dismiss any development banner. Use the actual Transactions tab → filter icon.
2. The bottom green Apply control stays short while its text scales. Only the upper part of Apply is visible inside the button; the lower part is cut off. The failure is visible without a keyboard or nested picker.
3. Repeat after another fresh launch: initial11014/fresh11651 show the same clipped footer. Cancel/Reset in the native header also clip, but are covered separately by w3/151.
4. Restore ordinary large and relaunch12048: the same filter footer shows the complete Apply label. Ordinary-size Reset → Apply was exercised earlier and returns the transaction list with filters cleared; no server data is written. Leave the filter draft canceled and default text size restored.

Expected: the footer button contains the complete enlarged label and remains reachable while the filter body scrolls. Actual: the scaled label exceeds the fixed-height shared control. This is a readability failure; activation under maximum text size was not exercised, so do not claim the button stops responding.

Root cause: mobile/src/components/button/index.tsx:27–45 gives buttonBase a fixed height44 and the primary Text fontSize16 without an adaptive height. The scaling Text is rendered at125 inside this constraint. transaction-filters-screen.tsx:310–312 uses this shared Button in its footer; the footer has padding but no label-fitting policy. The native screenshots establish the clipping; this is independent of filter-query results.

Fix: allow the shared Button to accommodate its scaled label and vertical padding, using44 as a minimum rather than a fixed height. Keep text within the visible background and preserve ordinary-size geometry, rounded corners, press feedback, enabled/disabled/loading behavior and hit targets. Preserve the filter screen's scrollable body and bottom safe area when its footer grows. Do not disable all text scaling, hide part of the action or fix only the caller with a larger magic height. Check short Apply plus a longer translated label, primary/outline variants and loading indicator alignment. Use meaningful component/layout coverage plus native maximum/default screenshots.

Blast radius: nine Button instances across seven consumers: Transaction Filters; Welcome (two); Server Settings (two); Referral; Budget empty CTA; OAuth callback error; not-found page. These imports all resolve to the same Button. Only the filter footer was reproduced at the failing setting here; other consumers and nested custom label children require regression inspection, not speculative bug claims. No dependency/backend changes required. Header actions do not use this Button and are outside the fix.

**Severity:** minor. **Estimate:** 30–45 minutes. **Package:** mobile.
**Goal:** A2 — enlarged-text users can read the complete server-settings actions while entering a URL.

Cause: `mobile/src/screens/welcome/server-settings-screen.tsx:204–216` mounts `KeyboardAvoidingView behavior="padding"` inside a bottom-safe-area view below a visible Stack header, but supplies no `keyboardVerticalOffset`. Installed RN `Libraries/Components/Keyboard/KeyboardAvoidingView.js:80–110,128–132` compares its parent-relative layout frame with the screen-relative keyboard Y, subtracting `keyboardVerticalOffset` (default0). The missing screen-origin/header adjustment underestimates avoidance; the measured101-point origin matches the overlap. The ScrollView itself can scroll and its controls expand for Dynamic Type.

Fix: derive the actual navigation/screen offset and pass it to keyboard avoidance, or use an equivalent layout that measures both in the same coordinate space. Avoid a fixed magic101 or font-size cap, and avoid double safe-area subtraction. At maximum text size, scrolling with the keyboard open must expose every line of Restore and allow the whole control into the usable viewport. Keep the URL editable and Test/Save reachable; dismissing/reopening the keyboard must preserve the local draft. Verify ordinary and enlarged text and differing header heights.

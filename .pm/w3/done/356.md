# `bea cloud ledger create` skips local name validation when signed out

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** cli. **A1:**
signed-out `create UPPERCASE` / `create 'My Ledger'` exits **3** “Not logged
in” instead of exit **2** naming slug rules — unlike `show`/`clone`/`delete`
path validation before auth.

Found 2026-09-16 by continuous CLI QA ([c980 hunt](28740a0e-f1af-4d2c-afec-b2e88b26ba12)),
HEAD `eb3ee986`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Confirmed
`cli/tmp/qa-20260915/c981/`. Evidence: `c980/`.

## Repro

```sh
bea cloud ledger show noslashonly
# exit 2 — expected 'owner/name'

bea cloud ledger create UPPERCASE
# exit 3 — Not logged in
```

## Expected

Invalid slugs exit 2 with lowercase/hyphen/underscore guidance before auth.

## Actual

`ledger_create` authenticates first; no local slug check.

## Fix

Validate name before `authenticated_client()`. Regression: signed-out invalid
create exits 2; valid name still exits 3 when unsigned.

## Dedupe

Not w3/337 (delete confirm-before-auth). No open note covers create slug
validation before auth.

---

**Resolved 2026-09-17** — `cloud ledger create` now checks the name before
`authenticated_client()`, the way `clone` and `show` already check theirs: an
invalid name exits **2** naming the rule and a slugified suggestion
(`'My Ledger'` → `Try 'my-ledger'.`) instead of exiting **3** with "Not logged
in", which said nothing about the name. The check mirrors the service's own rule
exactly — `^[a-z0-9_-]+$`, at most 100 characters, identical in REST v1
(`lifecycle-handler.ts`) and GraphQL (`ledger-resolver.types.ts`) — so it can
never refuse a name the service would have taken. A valid name still reaches the
auth gate unchanged. Documented in `cli/docs/USAGE.md`; covered by
`cli/tests/test_cloud_ledger_create_name_validation.py`, which runs signed out
against an isolated config directory. Shipped with this board close.

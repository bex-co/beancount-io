# `bea add transactions` rejects numeric `date` with an opaque “zero time” datetime message

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** cli. **A1:** agents
that emit JSON dates as numbers (`20240401`) or short years (`2024`) get a
Pydantic/Beancount datetime residual — “Datetimes provided to dates should have
zero time” — instead of a clear “use a `YYYY-MM-DD` string” usage error.

Found 2026-09-15 by continuous CLI QA against `main`, HEAD `d2a0ba34`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
printf '%s\n' '[{"date":20240401,"narration":"t","postings":[
  {"account":"Expenses:Food:Groceries","amount":"1 USD"},
  {"account":"Assets:Bank:Checking"}]}]' > rows.json

bea --json --file main.bean add transactions --from rows.json
```

Exit 1:

```text
Row 1, date: Datetimes provided to dates should have zero time - e.g. be exact dates
  Example posting: {"account":"Assets:Checking","amount":"-30 USD"}. Use bea add transactions --help for a complete row.
```

The trailing “Example posting” line is always appended for any rejected row
(including pure `date` failures such as `"02/01/2020"` or `null`), which steers
agents toward postings when the path already names `date`.

Same “zero time” wording for `"date": 2024`. Contrast:

- `"date": null` → `Input should be a valid date`
- `"date": "01/04/2024"` → `Input should be a valid date or datetime, invalid character in year`
- `"date": "2024-04-01T12:00:00"` → same “zero time” message (appropriate for a
  real datetime with a time component)
- `"date": "2024-04-01"` → writes successfully

## Expected

Non-string / non-ISO date values should fail with an explicit contract message:
dates must be strings `YYYY-MM-DD`. Reserve the “zero time” wording for actual
datetime strings that include a non-zero time.

## Actual

Numeric JSON values are coerced far enough into a date/datetime path that the
failure reads like a time-component problem, not a type/format problem.

## Fix

Tighten the bulk transaction date field (Pydantic / directive model) to accept
only `date` or `YYYY-MM-DD` strings; reject `int`/`float` before the datetime
coercion with a clear message. Regression: `date: 20240401` and `date: 2024`
name `YYYY-MM-DD`; `2024-04-01T12:00:00` may keep the zero-time hint.

## Dedupe

No open `.pm` note covers numeric bulk `date` messaging. Related meta/number
opacity is w3/230 (bare numbers in **meta**, different field).

---

**Resolved 2026-09-16** — bulk/directive `date` fields reject numeric JSON with an explicit `YYYY-MM-DD` message instead of the datetime “zero time” residual. Covered by `cli/tests/test_bulk_numeric_date.py`. Shipped with this board close.

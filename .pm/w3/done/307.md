# Cwd discovery ignores `main.beancount` (only `./main.bean`)

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** cli. **A2:** a
newcomer whose books live at the common Beancount name `main.beancount` gets
“No ledger file at 'main.bean'” from every command that relies on cwd
discovery, while `bea format -i .` already scans `*.beancount` and `bea init`
accepts a `.beancount` path.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `f60bbc67`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
mkdir books && cd books
printf 'option "operating_currency" "USD"\n2020-01-01 open Assets:Cash USD\n' \
  > main.beancount

bea --json list open
# exit 2 — No ledger file at 'main.bean' (from the working directory)…

# Control — same dir with the documented name:
cp main.beancount main.bean
bea --json list open
# exit 0 — opens Assets:Cash

# When both exist, only main.bean is used (expected if .bean stays preferred).
```

## Expected

Cwd fallback should accept `./main.beancount` when `./main.bean` is absent
(prefer `.bean` when both exist), matching format’s `*.bean`/`*.beancount`
suffixes and USAGE’s “`.bean`/`.beancount`” language elsewhere — or the error
must name `main.beancount` as an explicit `--file` option.

## Actual

`cli/config.py` `DEFAULT_ENTRY_FILE = Path("main.bean")` only; `RunContext`
resolves `--file` → `$BEA_FILE` → that single name. No `.beancount` fallback.

## Fix

Try `main.bean` then `main.beancount` for cwd discovery; keep `.bean` first when
both exist. Update USAGE’s precedence bullet and the missing-file message.
Regression: sole `main.beancount` cwd works; both present → `main.bean`.

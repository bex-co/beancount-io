## Objective

Make the BQL result table render an object-valued cell as ledger amounts instead of `JSON.stringify` output, using the shared formatter from t001. Drive the decision from the column's declared `dtype` in `result.table.types` (`Inventory`, `Position`, and the bare-`Amount` shape the ledger service maps into the same currency map), and keep a safe fallback for an unrecognized object shape rather than crashing or printing `[object Object]`. A zero-net inventory (`{}`) must render as an empty cell, not the literal `{}`.

## Context

- Defect site: `dashboard/src/features/bql/components/query-result-card.tsx:128-130`.
- The payload already declares the type: the JSON response carries `types: [{"name":"total","dtype":"Inventory"}]` next to the rows. See the parent README for the captured response.
- The cell values are decimal **strings** (`{"USD":"-3623.17"}`); do not convert them through `Number`.
- `{}` is fava-parity behavior from `backend-cluster/ledger/.../ledger-shell-mappers.ts:34-57`. Render it as empty; do not "fix" it upstream.

## Steps

1. Read the column dtype alongside each cell in the virtualized row component.
2. Format recognized object cells with the shared t001 display formatter; keep the current `String(cell ?? "")` path for scalars.
3. Keep an unrecognized object shape rendering as something readable and non-crashing, and keep it out of the amount path.

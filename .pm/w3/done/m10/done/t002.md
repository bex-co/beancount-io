## Objective

Add a dedicated Dashboard settings page where users can create, copy once, review, and revoke Personal Access Tokens without confusing them with the existing SSH public-key page.

## Context

- `dashboard/src/features/user-settings/pages/ssh-keys/` manages SSH public keys and is not an API-token issuer.
- API-key minting is paid-plan only; a key cannot mint a successor and cannot exceed the caller's authority.
- Dashboard user-facing text must exist in every supported locale through the feature locale modules.

## Steps

1. Add a thin `/settings/api-keys` route and a feature-owned page under user settings.
2. Build list, loading, empty, error, revoked, and expired states from the typed operations.
3. Build creation inputs for name, scopes, optional ledger restriction, and optional expiry, with least-privilege defaults and clear paid-plan handling.
4. Show the new plaintext exactly once in a focused success dialog with copy and explicit unrecoverability language; do not log, persist, or re-query it.
5. Add a confirmation-gated revoke action and refresh the list after success.
6. Add the settings navigation entry and all locale keys.

## Acceptance criteria

- [ ] API tokens have a distinct, discoverable settings page and are never presented as SSH keys.
- [ ] Creation supports the backend's scopes, ledger restriction, and expiry contract with accessible validation.
- [ ] Plaintext appears only in the create-success path, is copyable, and disappears permanently when dismissed or refreshed.
- [ ] Existing keys display prefix, scopes, ledger restriction, created/last-used/expiry information, and status without exposing secret material.
- [ ] Revoke requires confirmation and the resulting state is visible without a full-page refresh.
- [ ] Empty, loading, error, paid-plan, narrow-screen, keyboard, and screen-reader paths are usable.
- [ ] Translation shape remains green across every Dashboard locale.

## Out of scope

- Changing API-key pricing or backend scope semantics.
- Replacing OAuth for interactive clients.

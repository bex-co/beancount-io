## Objective

Add meaningful automated coverage for the API-key settings journey and its failure modes, then run the owning package gates.

## Context

- Manual docker-mac proof in t003 covers integration; this task makes the UI contract repeatable in CI.
- Tests must prove behavior, especially one-time plaintext handling and revocation, rather than snapshotting the page wholesale.

## Steps

1. Test list loading, empty, error, active, expired, and revoked states with typed GraphQL mocks.
2. Test validation, scope selection, optional ledger/expiry inputs, paid-plan rejection, and successful creation.
3. Prove plaintext appears after creation, can be copied, is cleared on dismissal, and never reappears from the list query.
4. Test confirmation-gated revoke and post-mutation list state.
5. Cover keyboard/accessibility behavior and settings navigation.
6. Run the Dashboard handoff gate; run backend focused checks if t003 or t004 changed backend behavior or contract generation.

## Files

- `dashboard/src/features/user-settings/pages/api-keys/__tests__/`
- Adjacent Dashboard route/navigation tests
- Backend-v2 API-key/OpenAPI tests when backend files changed

## Acceptance criteria

- [ ] Tests fail if plaintext is rendered from a list response, retained after dismissal, or exposed without a fresh successful mutation.
- [ ] Tests cover revoke confirmation, paid-plan failure, validation, and lifecycle states.
- [ ] Dashboard `yarn format:check`, `yarn lint`, `yarn test`, and `yarn build` pass from `dashboard/`.
- [ ] Relevant backend-v2 tests, lint, typecheck, and build pass if backend files changed.
- [ ] Tests assert behavior and failure modes without tautological or snapshot-everything coverage.

## Out of scope

- Replacing the manual full-stack verification from t003 with browser E2E infrastructure.

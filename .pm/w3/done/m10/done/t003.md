## Objective

Run the complete user journey against the real local stack, fix any integration gaps it exposes, and leave reproducible evidence that the Dashboard-issued key works and revokes as documented.

## Context

- `deploy/docker-mac/` runs Dashboard on port 42600 and backend-v2 on port 42601 with the ledger, Gitea, PostgreSQL, and Redis dependencies.
- The local run must exercise the real GraphQL issuer and `/api-gateway/v1` identity path, not mocked browser data.
- No plaintext token, local credential, database row, or user financial data may be written to `.pm/`, logs committed to git, fixtures, or screenshots.

## Steps

1. Validate Compose configuration, build/start the stack, run the post-start provisioning script, and confirm service health.
2. Use a local paid-plan test user and ledger to create a read-only, ledger-scoped key through the new Dashboard page.
3. Copy the one-time plaintext and call a safe local v1 read with `x-api-key`; exercise at least ledger listing and one ledger read or BQL query.
4. Attempt a write with the read-only key and confirm the documented scope denial.
5. Revoke the key in Dashboard and confirm the next API request is refused.
6. Reload and revisit the page to prove the plaintext is not recoverable; fix any UI, schema, proxy, or local-environment gap found.
7. Record commands, status codes, and redacted observations in this task's closeout notes.

## Closeout notes

- `docker compose config --quiet`, the full image build/start and post-start provisioning completed; all seven services were healthy and both Dashboard and backend health endpoints responded successfully.
- A paid local test account created a `ledger.read`, single-ledger token through `/settings/api-keys`. With the plaintext held only in transient browser state, `x-api-key` returned 200 for ledger listing and account data, while a schema-valid `POST .../entries` returned 403 with `FORBIDDEN` before the write handler ran.
- Dismissing and reloading removed the plaintext from the DOM. Revocation changed the visible lifecycle state and the next request with the same transient token returned 401. All verification keys were revoked afterward.
- The real run exposed and fixed three reproducibility/contract gaps: a fresh container dependency-resolution incompatibility, a development-only paid-user override for local testing, and the identity extractor not honoring the OpenAPI-advertised `x-api-key` header. Explicit headers now take precedence over session cookies so a signed-in browser cannot mask a scoped-key test.
- Regression evidence: backend 213 suites / 2,860 tests passed, plus typecheck and lint; no plaintext, local login credential, user identifier, or financial data is recorded here.

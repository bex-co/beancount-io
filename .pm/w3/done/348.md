# `bea format -w` / `-W` unbounded values bloat ledgers on `-i`

**Severity:** major. **Estimate:** 20–30 minutes. **Owner:** cli. **A1:** a typo
`-w 99999` with `format -i` exits **0** and pads posting lines with tens of
thousands of spaces (158 B → ~100 KiB); `check` still passes.

Found 2026-09-16 by continuous CLI QA ([c900 hunt](b42adec2-0131-4cbd-857b-a256bd4ad5c9)),
HEAD `d743e163`, `uv run bea` 0.2.0, Darwin arm64. Confirmed
`cli/tmp/qa-20260915/c902/`. Evidence: `c900/`.

## Repro

```sh
bea format -i -w 99999 main.bean
# exit 0 — file balloons with space padding
bea format -i -W 99999 main.bean
# same class
```

Negatives correctly exit 2.

## Expected

Reject or clamp absurd `--prefix-width` / `--num-width` (same policy as
w3/331 for `--currency-column`).

## Actual

`format.py` `_alignment()` only rejects negatives; no upper bound.

## Fix

Shared upper bound / UsageError for `-w`/`-W`/`-c`. Regression: `99999` exits
2 (or caps); sane widths still work.

## Dedupe

Not w3/331 (only `-c`). No open note covers unbounded `-w`/`-W` bloat.

---

**Resolved 2026-09-17** — Already satisfied by w3/331 (`5dad6d1f`): `_alignment` refuses `-w`/`-W`/`-c` above 200. Covered by `cli/tests/test_format_rejects_huge_currency_column.py` and the shared cap. Shipped with this board close.

# `bea ask` prints the AI proxy's raw JSON error envelope when the message is nested one level deeper

**Severity:** major (every quota rejection today takes this path). **Owner:**
cli. **Estimate:** 20–30 minutes. **A1:** an agent or person who runs out of AI
budget gets a wall of JSON instead of the one sentence the rest of the CLI
promises, and `bea ask` is the only command that does this.

Found 2026-09-26 by CLI QA (`qa-find-bugs-cli`) against `main` HEAD `8cd9732b`,
`uv run bea` 0.3.0, Darwin 26.5.1 arm64, isolated `BEA_CONFIG_DIR` /
`XDG_CACHE_HOME`, synthetic ledger. Reproduced live against the hosted AI proxy
and offline against a local stub.

## Repro (offline, no account needed)

Stub the proxy with the envelope shape it really sends — a wrapper whose
`error.message` is itself a JSON document:

```python
# stub.py — returns 402 with a nested envelope
import json
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer
INNER = json.dumps({"success": False, "error": {
    "code": "QUOTA_EXCEEDED", "message": "API usage quota exceeded", "help": "upgrade"}})
BODY = json.dumps({"ok": False, "error": {"code": "INTERNAL_SERVER_ERROR", "message": INNER}}).encode()
class H(BaseHTTPRequestHandler):
    def do_POST(self):
        self.rfile.read(int(self.headers.get("content-length") or 0))
        self.send_response(402); self.send_header("content-type", "application/json")
        self.send_header("content-length", str(len(BODY))); self.end_headers(); self.wfile.write(BODY)
ThreadingHTTPServer(("127.0.0.1", 8912), H).serve_forever()
```

```sh
BEA_API_URL=http://127.0.0.1:8912 bea --file main.bean ask --print "hello"
# Error: {"success": false, "error": {"code": "QUOTA_EXCEEDED", "message": "API usage
#   quota exceeded", "help": "upgrade"}}
# exit 1
```

Control, same command against a stub whose `error.message` is a plain sentence
(HTTP 429): `Error: Rate limited (Too many requests; retry in 60s). Wait a
moment and retry.` — correct.

Live confirmation: with the QA account's AI window exhausted, every
`bea ask --print` printed the upstream provider's whole JSON document
(`QUOTA_EXCEEDED`, plus that provider's own pricing and chat links) as the
error message, exit 1.

## Expected

One sentence from the documented table — `Error: API usage quota exceeded …`
with the CLI's own remedy — and never a JSON document. `cli/docs/USAGE.md`
§ Ask and the exit-code table promise the server's own message, not its
envelope, and `w3/done/381` shipped `_server_message` for exactly that reason.

## Root cause

`cli/src/cli/ask/agent.py::_server_message` only reads a **top-level**
`message` key. The gateway nests it (`{"ok": false, "error": {"code": …,
"message": …}}`), and the OpenAI SDK hands `ModelHTTPError.body` the inner
`error` object, whose `message` is another JSON document — so the lift returns
that document verbatim. `cli/src/cli/api/client.py::_error_message` (the path
every `bea cloud` command uses) already handles both shapes: it reads
`error.message`. The two error readers have drifted.

## Fix

1. In `_server_message`, unwrap like `_error_message` does: accept
   `error.message` as well as `message`, and when the extracted message is
   itself JSON, recurse once more (bounded) so a stringified envelope collapses
   to its sentence; keep the `HTTP <status>` fallback.
2. Prefer sharing one helper between `cli/src/cli/ask/agent.py` and
   `cli/src/cli/api/client.py` so a third shape cannot diverge again.
3. Regression coverage: table-driven test over the four bodies
   (`{"message": …}`, `{"error": {"message": …}}`, stringified-JSON message,
   plain text) asserting the rendered sentence and exit code, plus one asserting
   no `{` reaches the user.

## Dedupe

`w3/done/381` created `_server_message`/`translated_failures` (commit
`778cb007`) and scoped only exit-code mapping and stripping SDK internals; the
nested-envelope shape was never covered. `git log -S"_server_message"` returns
only that commit. No other `.pm` item mentions `_server_message`,
`QUOTA_EXCEEDED`, or a nested error envelope in `ask`. `w3/428` (open) is a
whitespace-only question, different mechanism.

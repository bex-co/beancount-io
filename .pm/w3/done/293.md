# `bea list balance` human table omits tolerance (JSON includes it)

**Severity:** minor. **Estimate:** 10–15 minutes. **Owner:** cli. **A1:** a
human or agent reading `list balance` text cannot see `~ 0.01` tolerances that
were written and that JSON already returns — easy to think the assertion is
strict when it is not.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `476beb05`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
bea --file main.bean add balance --date 2020-06-01 -a Assets:Cash \
  --amount '2950.00 ~ 0.01 USD'

bea --json --file main.bean list balance
# {"amount":{"number":"2950.00","currency":"USD"},"tolerance":"0.01", …}

bea --file main.bean list balance
# DATE        ACCOUNT      AMOUNT
# 2020-06-01  Assets:Cash  2950.00 USD
# ← no tolerance column / no "~ 0.01"
```

## Expected

Human output shows the tolerance when present (column or `2950.00 ~ 0.01 USD`),
matching the JSON `tolerance` field and the on-disk directive.

## Actual

`BalanceDirective` carries `tolerance`, JSON serializes it, but the human table
renderer only prints date / account / amount.

## Root cause

List formatting for balance directives does not render `tolerance` (command
table in `cli/src/cli/commands/list.py` / shared row formatter). Reader already
populates the field.

## Fix

When `tolerance` is not null, show it in the AMOUNT cell (`NUMBER ~ TOL CUR`)
or add a TOLERANCE column. Regression: the fixture above shows `~ 0.01`;
balances without tolerance stay unchanged; JSON unchanged.

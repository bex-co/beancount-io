# Stale `$BEA_FILE` blocks cwd `./main.bean`; error still suggests cwd discovery

**Severity:** minor. **Estimate:** 15–25 minutes. **Owner:** cli. **A1:** a
shell with stale `$BEA_FILE` fails every local command inside a tree that has
`./main.bean`; the usage error still says “run from a directory containing
main.bean”, which cannot work while `$BEA_FILE` is set.

Found 2026-09-16 by continuous CLI QA ([c820 hunt](47811610-5ea6-4af6-bdf8-c9cccf96fb49)),
HEAD `5a08eb9f`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Confirmed
`cli/tmp/qa-20260915/c821/`. Evidence: `c820/`.

## Repro

```sh
export BEA_FILE=/abs/missing.bean
cd /project/with/main.bean
bea list transaction
# exit 2 — No ledger file at '…/missing.bean' (from $BEA_FILE).
#   … or run from a directory containing main.bean …

unset BEA_FILE
bea list transaction
# exit 0 — cwd main.bean works
```

## Expected

Fall through to `./main.bean`, or keep strict precedence but drop the cwd hint
when `$BEA_FILE` was the selected (missing) source — tell the user to unset/fix
`$BEA_FILE`.

## Actual

`context.py` `entry_file()` errors on missing `$BEA_FILE` without cwd fallback;
message always lists the cwd option.

## Fix

Fallback or rewrite the message. Regression: stale `$BEA_FILE` + valid cwd
either loads cwd or errors without the misleading hint; valid `$BEA_FILE`
still overrides; `--file` still wins.

## Dedupe

Not w3/307 (`main.beancount` vs `main.bean`). No open note covers stale
non-empty `$BEA_FILE` + misleading cwd hint.

---

**Resolved 2026-09-17** — Missing `$BEA_FILE` errors tell the user to unset/fix `BEA_FILE` and no longer suggest cwd `main.bean` discovery (which is skipped while the env var is set). Covered by `cli/tests/test_stale_bea_file_message.py`. Shipped with this board close.

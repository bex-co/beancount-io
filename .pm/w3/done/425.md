# A failed `bea import --csv` preview still replaces the remembered mapping (and drops its `--rules`)

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** cli. **A1:** an
agent that tries a wrong `--csv` once loses the working remembered mapping;
every later flag-free import replays the broken one instead of the header
reading that would have worked.

Found 2026-09-26 by CLI QA (`qa-find-bugs-cli`) against `main` HEAD
`8cd9732b`, `uv run bea` 0.3.0, Darwin 26.5.1 arm64, isolated
`BEA_CONFIG_DIR`. Synthetic ledger only.

## Repro

```sh
cat > main.bean <<'EOF'
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Expenses:Uncategorized USD
EOF
printf 'Date,Description,Amount\n2026-02-01,Coffee,-4.50\n' > s.csv
# fresh BEA_CONFIG_DIR: flag-free works (header inference)
bea --file main.bean import s.csv --account Assets:Checking            # exit 0, 1 ready
# a mistaken explicit mapping fails before anything is written
bea --file main.bean import s.csv --account Assets:Checking \
  --csv date=Date,amount=Description,narration=Amount                  # exit 2
# now the flag-free run fails too
bea --file main.bean import s.csv --account Assets:Checking            # exit 2
```

The third run prints
`Using remembered settings for s.csv: --csv date=Date,amount=Description,narration=Amount …`
then `cannot parse amount 'Coffee' in column 'Description'`. With a prior
good memory that carried `--rules rules.toml`, the failing run also prints
`Discarded remembered settings … --rules …`, and the rules are gone for
later runs even though that run was refused.

Expected: a refused run changes no persistent state; the remembered mapping
is written only after the engine returned a preview.

## Root cause

`cli/src/cli/commands/import_.py:592` calls `_remember_csv(...)` before
`launch.helper_json(argv)` at `:617`. The Python-importer path already does
the right thing: `_remember_config` runs at `:629`, after success.

## Fix

Move the `_remember_csv` call (and the "Discarded remembered settings" note)
after a successful `helper_json` preview/apply, mirroring
`_remember_config`. Decide explicitly whether a preview that succeeded but
was blocked for review (exit 4 with `error.result`) should remember; a
parse/usage failure (exit 2) must not.

## Acceptance

- The repro's third command uses header inference and exits 0.
- A good remembered mapping with `--rules` survives a failed explicit run.
- Regression test in `cli/tests/test_import.py`.

## Dedupe

Searched `.pm/**` for remembered/sticky mapping terms; w1/m24/t007, w3/310,
w5/003 cover visibility, stale rules and header inference, not persistence
of a failed run. `git log -S _remember_csv` shows no ordering fix.

# `bea query 'PRINT' -f beancount` reprints a parenthesized `custom` value as a subtraction

**Severity:** minor (export only; the ledger on disk is correct). **Owner:** cli
(engine query). **Estimate:** 30–45 minutes. **A1:** an agent that exports with
`PRINT -f beancount` and re-imports the result gets `custom "budget" 5 -2`,
which reloads as the single value `3`.

Found 2026-09-27 while implementing [w3/m49](./m49/README.md) (w3/430).

## Repro

```sh
printf 'option "operating_currency" "USD"\n2024-01-01 open Expenses:Food USD\n' > main.bean
bea --file main.bean add custom --date 2024-02-05 -t budget -v number:5 -v number:-2
grep custom main.bean            # 2024-02-05 custom "budget" 5 (-2)   <- correct
bea --file main.bean format | grep custom   # 5 (-2)                    <- correct
bea --file main.bean query PRINT -f beancount | grep custom  # 5 -2      <- reloads as 3
```

## Root cause

The `beancount` renderer for query results is upstream
`beancount.parser.printer.EntryPrinter.Custom`, which joins values with spaces
and never parenthesizes a negative number. `bea add`'s writer no longer goes
through it (w3/m49 renders custom negatives in parentheses and parses the line
back before writing), and `bea format` preserves the file's own text — only the
query export path still uses upstream's printer unchanged.

## Fix

Render directive exports through a printer that applies the writer's rules —
parenthesized negative custom values, and a whole cost spec (`{EUR}` rather than
`{}`, a total kept as `{# 250.00 USD}`) — so a `PRINT -f beancount` export
reloads as the entries it described. `bea_engine.ledger.writer.format_entry` and
`_cost_spec_text` already hold those rules; the export path needs to use them
instead of upstream's `EntryPrinter` directly.

## Dedupe

Grew out of the "Blast radius" paragraph of [430](./430.md), which recorded the
symptom but scoped the fix to the writer. No other note covers the query export

**Resolved 2026-10-02** — Query directive exports now share `DirectivePrinter`
with the writer, preserving separate negative custom numbers and amounts,
fixed-point decimal metadata, escaped strings and complete cost specifications.

multiline text. Explicit zero per-unit costs and missing-total `#` markers stay
distinct, preserving their booking/interpolation meaning. `PRINT`, entry
`SELECT`, stored queries, interactive queries and output files use this renderer;
explicit native `--source` retains Beanquery's documented behavior. The note's
add → format → export repro now reloads as separate `5` and `-2` values. Twenty
new regression/control cases include parser-produced unbooked costs and actual

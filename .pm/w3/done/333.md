# `bea list transaction --tag ''` / `--link ''` poison combined filters to zero rows

**Severity:** minor. **Estimate:** 15–25 minutes. **Owner:** cli. **A1:** an
agent that appends an empty `--tag ''` / `--link ''` beside a real filter
(template hole) gets exit **0** and “No transactions found” even though
`--tag grocery` alone matches — opposite footgun from `--search ''` (w3/286).

Found 2026-09-16 by continuous CLI QA ([c760 hunt](e1de5b24-6076-40c1-b16c-132b825e1c9d)),
HEAD `c1daf758`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache.
Evidence: `cli/tmp/qa-20260915/c760/`, `c761/` (confirm).

## Repro

```sh
# ledger has 2020-02-01 * "Coffee" #grocery
bea --file main.bean list transaction --tag grocery
# one row

bea --file main.bean list transaction --tag grocery --tag ''
# exit 0 — No transactions found.

bea --file main.bean list transaction --link order1 --link ''
# same silent empty when order1 exists alone
```

## Expected

Empty `--tag` / `--link` tokens are usage errors (exit 2) or dropped before
AND — same cleanup planned for `--search` in w3/286. Must not silently zero
a otherwise-matching combined filter.

## Actual

`reader.py` `list_transactions` builds `wanted_tags` / `wanted_links` including
`""`; `issubset` fails for every entry. `--search` keeps `""` with
`'' in text` (always true) — inconsistent.

## Fix

Reject or strip blank tag/link tokens before the set check. Regression:
`--tag grocery --tag ''` returns the grocery row (or exits 2); lone `--tag ''`
is empty or usage error, not an unbounded match.

## Dedupe

Not w3/286 (empty `--search` matches all). Not w3/287 (empty `--account`).
No open note covers empty `--tag` / `--link` AND poisoning.

# `bea import` hard-codes comma CSV, so semicolon/tab bank exports fail and the suggested `--csv` recovery cannot work

**Severity:** major. **Estimate:** 45–60 minutes. **Owner:** cli. **A2:** a
newcomer (or agent) with a typical EU bank export (`Date;Description;Amount`)
cannot import via the documented no-code CSV path; the error tells them to name
columns with `--csv`, but that same mapping still fails because the file is
never split on `;`.

Found 2026-09-15 by continuous CLI QA (`qa-find-bugs-cli`) against `main`,
HEAD `11f45c1d`, using `uv run bea` 0.2.0 on Darwin 25.5.0 arm64 with isolated
`BEA_CONFIG_DIR` / `XDG_CACHE_HOME` and `BEA_NO_UPDATE_NOTIFIER=1`. Synthetic
local fixtures only; no credentials.

## Repro

```sh
bea --no-input init books --currency USD --date 2024-01-01
printf 'Date;Description;Amount\n2024-03-10;Cafe;-4.50\n' > semi.csv

bea --no-input --file books/main.bean import semi.csv --csv auto \
  --account Assets:Bank:Checking
# exit 2
# Error: Cannot read a column mapping from the header row of semi.csv.
# Its columns are: Date;Description;Amount. Name them with --csv
# date=Date,amount=Amount,narration=Description.

bea --no-input --file books/main.bean import semi.csv \
  --csv date=Date,amount=Amount,narration=Description \
  --account Assets:Bank:Checking
# exit 2
# Error: The mapping names column 'Date' for date, which semi.csv lacks.
```

Same shape for tab-separated headers (`Date\tDescription\tAmount`): one
combined "column", and an explicit `--csv` mapping still fails.

Working control (identical cells, comma-separated):

```sh
printf 'Date,Description,Amount\n2024-03-10,Cafe,-4.50\n' > comma.csv
bea --no-input --file books/main.bean import comma.csv --csv auto \
  --account Assets:Bank:Checking
# exit 0 — preview shows 1 ready row
```

## Expected

Either detect `;` / tab (csv.Sniffer or a first-line heuristic) and parse the
file, or expose `--delimiter` and make the auto/`--csv` error name the real
blocker ("delimiter is comma-only; convert the file or pass --delimiter ';'").
An explicit `--csv date=Date,...` on a semicolon file must not claim the
`Date` column is missing when that name is present in the header text.

## Actual

`open_records` always uses `csv.reader(..., strict=True)` with the default
comma delimiter. A semicolon header becomes a single field
`Date;Description;Amount`, so inference fails and mapped column names never
match.

## Root cause

- `cli/src/cli/csv_mapper.py` — `open_records` (~line 206):
  `reader = csv.reader(stream, strict=True)` (no `delimiter=`).
- Twin used by extraction: `cli/src/bea_engine/csv_mapper.py` (~line 208),
  same call.
- `bea import` has no `--delimiter` option; docs/examples assume comma CSV
  (`cli/docs/IMPORTING.md`, `cli/docs/examples/`).

## Fix

1. Detect delimiter for `--csv` / `auto` (prefer `;` or tab when the header
   line has no commas but has those separators; keep comma as default).
2. Add `--delimiter` so agents can set it explicitly; pass it through both
   frontend inference and `bea-engine` extraction.
3. When the header looks like `A;B;C` under comma parsing, say so instead of
   suggesting a `--csv` mapping that cannot succeed.
4. Keep BOM stripping and strict quoting behavior; add regression tests for
   `;` and tab fixtures (and the misleading recovery path).

Related (not required to close this note): European decimal commas in amounts
(`-4,50`) still fail after a comma-delimited parse with
`cannot parse amount '-4,50'` — handle in the same change or a follow-up.

---

**Resolved 2026-09-16** — CSV import detects comma/semicolon/tab from the header (and accepts --delimiter), so EU semicolon and TSV exports work with --csv auto and explicit mappings; forced comma on a semicolon file names --delimiter instead of a fake missing-column recovery. Covered by cli/tests/test_csv_delimiter_import.py. Shipped with this board close.

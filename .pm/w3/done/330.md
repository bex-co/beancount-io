# `bea list transaction` human table drops posting-level flags

**Severity:** minor. **Estimate:** 25–40 minutes. **Owner:** cli. **A1:** an
agent reviewing `!` posting flags in the default `list transaction` table
cannot see them — FLAG shows only the transaction header (`*`), while JSON,
`--details`, and BQL `posting_flag` retain `!`.

Found 2026-09-16 by continuous CLI QA ([c710 hunt](548a6dd4-9c84-4d87-8248-4f0ed1409fa3)),
HEAD `b85e2621`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache.
Evidence: `cli/tmp/qa-20260915/c710/`, `c750/` (confirm).

## Repro

```sh
# ledger with:  ! Assets:Cash  -10 USD
bea --file main.bean list transaction
# POSTING AMOUNTS: Assets:Cash: -10 USD; …  ← no !
# FLAG column: *

bea --json --file main.bean list transaction
# data[0].postings[0].flag == "!"

bea --file main.bean list transaction --details
# renders: ! Assets:Cash  -10 USD
```

`list transaction --flag '!'` only matches the **transaction** flag, so
posting-flagged rows with header `*` are excluded from that review filter.

## Expected

Human POSTING AMOUNTS (or a column) shows posting flags; optionally
`--flag` documents that it filters transaction flags only, or also matches
posting flags.

## Actual

`list.py` builds posting cells from account + amount only; reader `--flag`
filters `t["flag"]` (transaction).

## Fix

Include posting `flag` in the compact human cell (e.g. `! Assets:Cash: -10 USD`).
Regression: the repro’s human table shows `!`; JSON/`--details` unchanged.

## Dedupe

No open note covers posting-flag visibility on human `list transaction`. Not
w3/316 (document tags).

---

**Resolved 2026-09-17** — Human `list transaction` POSTING AMOUNTS include posting flags (e.g. `! Expenses:Food`). Covered by `cli/tests/test_list_posting_flags_human.py`. Shipped with this board close.

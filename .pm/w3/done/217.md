## Extended by w4/012

Folded in on 2026-09-14 from `w4/012`, filed 2026-09-13 at HEAD `038faeeb` on iPhone 17e / iOS 26.5 against the public `open_ledger/alphabet`. That note duplicated this item's row and cause and asked to be read together with it; it was dropped from w4 after this section was added.

**Why the severity is major.** This item's evidence came from `open_ledger/airbnb`, whose balances run to about 11 characters and survived intact. On `open_ledger/alphabet`, whose balances run to 19 characters, the balance itself is truncated, not just the name. That is a mis-stated balance, not an inconvenience. At `accessibility-medium` (AX1, the first size past `common/theme/dynamic-type.ts`'s 1.3 threshold):

| Row | Shown | Actual |
| --- | --- | --- |
| Assets | `$921,983,000.6` | `$921,983,000,000.00` |
| Income | `-$1,743,597,000.` | `-$1,743,597,000,000.00` |
| Expenses | `$1,202,771,000.` | `$1,202,771,000,000.00` |

Every amount is cut mid-number at the screen edge with no ellipsis, so `$921,983,000.6` reads as about $922 million instead of about $922 billion. Account-name glyph bottoms are also clipped by the row height. At maximum size the amounts stay truncated and the name column collapses to a few pixels. Restoring `large` shows every name and full balance.

**Same cause, worse symptom.** In `account-table.tsx`, the balance `AmountText` has no shrink constraint and scales to `amountMaxFontSizeMultiplier` 1.4. A 19-character amount's intrinsic width exceeds the row, so the `flex: 1` name is squeezed to nothing and the amount overflows the container. The fix contract above still holds. Follow the stacked-layout threshold in `common/theme/dynamic-type.ts`, as `31f1e4ce` did for `w3/181` and `w3/183`.

**Extended acceptance.** Verify at AX1 as well as maximum size, on a ledger with about 19-character balances (`open_ledger/alphabet`), that no balance is clipped and no glyph is cut vertically by the row height. Checking only default and maximum on `airbnb` would pass while this still fails.

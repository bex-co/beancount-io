# `bea add document` JSON returns the relative `--path`, but `list document` returns an absolute path

**Severity:** minor. **Estimate:** 30–45 minutes. **Owner:** cli. **A1:** an
agent that writes a document with a relative path and then filters or
round-trips via `list document` cannot match on `filename` — add’s
`data.directive.filename` is `receipt.pdf` while list’s row is the resolved
absolute path.

Found 2026-09-15 by continuous CLI QA against `main`, HEAD `f14c9b3a`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only (`touch receipt.pdf` beside `main.bean`).

## Repro

```sh
touch receipt.pdf
bea --json --file main.bean add document \
  --date 2024-03-01 --account Assets:Bank:Checking --path receipt.pdf
# data.directive.filename == "receipt.pdf"
# ledger line: 2024-03-01 document Assets:Bank:Checking "receipt.pdf"

bea --json --file main.bean list document
# data[0].filename == "/abs/…/receipt.pdf"   # not equal to add’s value
```

Working control: `list note` / `add note` keep the same `comment` string.
Absolute `--path` on add both writes and lists the absolute path (portable
relative paths are the documented default).

## Expected

JSON `filename` for the same directive should use one stable form — prefer the
ledger-relative string that was written (and that USAGE documents for
`--filename` / `--path`) — or document and expose both (`filename` +
`resolved_path`). Agents must be able to match add → list without guessing
the ledger directory.

## Actual

Add echoes the path argument / written token. List serializes
Beancount’s loaded `Document.filename`, which the loader has already resolved
to an absolute path (`bea_engine/ledger/reader.py` `DocumentDirective(…,
filename=entry.filename)`).

## Fix

When serializing documents for list (and any other read surface), prefer the
path as stored in the source file (relative when the directive used a relative
token), or always relativize against the destination ledger directory before
emitting JSON. Keep validation of existence against the resolved path.
Regression: relative add → list `filename` equals the written token; absolute
add still round-trips.

## Dedupe

No open `.pm` note covers document `filename` add/list asymmetry. Not w3/228
(`--into` glob messaging) or path-resolution docs-only work.

---

**Resolved 2026-09-16** — `list document` relativizes Beancount's absolute `filename` against the directive source directory so it matches relative `add document --path`. Covered by `cli/tests/test_document_filename_list.py`. Shipped with this board close.

# `bea query -o out.csv` writes an ASCII text table when `--format` is omitted

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** cli. **A1:** an
agent or script that names a `.csv` destination without `-f csv` gets exit 0
and a file that looks like a spreadsheet export but is an ASCII table —
downstream parsers fail silently.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `cd921d3b`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only. Evidence: `cli/tmp/qa-20260915/c680/`, `c692/` (confirm).

## Repro

```sh
bea --file main.bean query 'SELECT date, narration LIMIT 3' -o out.csv
# exit 0 — file is an ASCII table with ---- separators, not CSV

bea --file main.bean query 'SELECT date, narration LIMIT 3' -f csv -o out.csv
# exit 0 — date,narration\n...
```

Same default-text write for `-o out.tsv` / `-o out.txt` unless `-f` is set.

## Expected

Infer `csv` when `-o` ends in `.csv` (optionally `.tsv`), **or** refuse/warn
when the destination suffix implies CSV but `--format text` is in effect
(exit 2: pass `-f csv` or rename). Document the rule in USAGE.

## Actual

`query.py` defaults `output_format` to `"text"` and forwards it unchanged;
no suffix check on `--output`.

## Fix

When `-o` is set and `--format` was not explicitly chosen, map `.csv` → csv
renderer (or UsageError). Regression: `-o out.csv` without `-f` emits
parseable CSV (or exits 2 with guidance); `-f csv -o out.csv` unchanged;
`--json -o out.csv` stays under w3/296.

## Dedupe

Not w3/296 (`--json` silently drops `-f`). Not w3/300 (same-path wipe).
Not w3/250 (directory `-o`). Not w3/242 (`PRINT` + csv). No open note covers
`-o *.csv` without `-f csv`.

---

**Resolved 2026-09-17** — `query -o *.csv` without `--format` infers CSV. Covered by `cli/tests/test_query_csv_suffix_infers_format.py`. Shipped with this board close.

# Browser-default number formatting breaks report hydration

Severity: **minor**. Owning package: **dashboard**. Estimate: **50–60m** for the
shared formatter/hook repair and focused SSR/hydration checks; callers retain
their existing hook interface.

## Reproduction

Production https://beancount.io, 2026-09-10, Chrome 152.0.7977.77, light,
authenticated QA GROWTH reader. Synthetic public example ledger, pull=true,
push=false, admin=false. Local HEAD 27873fc2; fetched main a1c1bac8 has no change
to the implicated formatter/hook. Exact deployed SHA unverified.

1. With browser locale fr-FR, open
   /ledger/open_ledger/example/balance-sheet?lang=en&time=2016.
   Keep the default Monthly / At Cost controls.
2. The server-rendered Assets total reads **80,149.807**. The settled browser
   replaces it with **80 149,807** and emits minified React error 418.
   A marker on the initially parsed account-list element shows it is detached:
   the settled list is a replacement DOM element.
3. Fresh 1440×1000 and 390×844 runs both reproduce the error and replacement.
   The English app language remains en; no filter or amount changes.
4. Fresh en-US browser controls at both widths preserve the initial account-list
   element and produce no page error.
5. In separate fr-FR diagnostic contexts, override only the default locale of
   Number.prototype.toLocaleString to en-US before loading. Both widths now keep
   the original list and produce no page error. The browser preference remains
   French. This is a temporary browser-only diagnostic, not a shipped patch.

The initial server-rendered comparison used JavaScript-disabled fresh contexts
for en-US and fr-FR. Both receive the same English-format amounts. Their ordinary
JavaScript-enabled counterparts preserve the list in English and replace it in
French. Across the four server/settled comparisons and six repeat/control
contexts, all documents return HTTP 200 and mutation guards see zero attempts.
The six repeat/control contexts have zero console-error messages; only the two
unmodified French runs emit the page exception.

Expected: a report's initial render and hydration use the same explicit
formatting locale, allowing React to reuse the server-rendered content. The
selected app language should determine localized report numbers, matching the
existing statement-export convention. The [React error reference](https://react.dev/errors/418)
explains that error 418 regenerates a mismatched tree; retained-element checks
confirm the replacement here. No load-time penalty or lost user input was
measured, and the settled page remains usable.

## Data and source trace

GraphQL QANumberLocale and REST
/api-gateway/v1/ledgers/open_ledger/example/statements/balance-sheet
with time=2016, conversion=at_cost, interval=monthly both return HTTP 200 and the
same Assets balanceChildren: USD="80149.80683", VACHR="25"; no GraphQL errors.
These are the inputs formatted by the live dashboard. A preliminary control
used the unsupported token cost; it was corrected to the page's actual at_cost
constant and excluded from evidence comparisons. No backend amount discrepancy
is claimed; live MCP was not exercised.

- common/lib/format/format-number.ts:9–17 calls value.toLocaleString() without
  a locale when renderCommas is true. The API delegates to Intl.NumberFormat
  and uses the runtime default when no locale is supplied, as documented by
  [MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number/toLocaleString).
- common/hooks/use-format-number.ts:12–18 forwards only value and renderCommas.
  Its callback depends only on that option and has no app-language input.
- features/reports/balance-sheet/hierarchy-list.ts:65–72 and 86–119 use the
  hook for primary/other amount cells; the selected balanceChildren is chosen
  at lines 175–176. Backend ledger-finance-resolver.query.ts:342–350 maps the
  raw balance_children object without locale formatting; its shared service
  passes the requested report filters through.
- A live call trace identifies the very first default-locale number as
  80149.80683, through use-format-number-Bmgp1sxr.js and
  hierarchy-list-NtkMez5B.js. The former asset returns HTTP 200 and contains
  exactly the same no-locale formatter/hook implementation. Its entry module
  is main-z45iacYQ.js. This establishes the deployed implicated code directly.
- Installed react-dom 19.2.3's development implementation at
  cjs/react-dom-client.development.js:5229–5250 queues the mismatch and throws
  HydrationMismatchException. The live error plus DOM checks establish actual
  deployed behavior independently of the local package version.

The pure formatter's only production caller is useFormatNumber, with an
additional barrel export. Sixteen components consume the hook: Balance Sheet
hierarchy list, hierarchy tree map and line chart; Income Statement's single
and stacked date-balance charts; Cash Flow charts; Overview's income/expenses,
net-worth, Sankey, formatted amounts, distribution bar and distribution pie;
Budget chart; Statistics' entry-type counts, account-last-entries and postings
per account. HierarchyList also renders Income Statement, Cash Flow and Trial
Balance. Only Balance Sheet has the isolated live hydration proof above.
Separate inline quota-number formatters exist but are outside this reproduced
report defect; the paid reader's directive-usage indicator renders null.

## Repair and acceptance

Pass the active router/request i18n language through useFormatNumber into an
explicit formatter locale; update the callback when language changes. Reuse
existing locale resolution and keep SSR/client inputs identical.
StatementExportMenu already supplies i18n.language at line 140. Do not mutate
global Intl behavior, disable report SSR, or suppress hydration warnings.
Preserve renderCommas=false, values, commodity labels, signs and current numeric
precision policy; this finding concerns locale-driven DOM replacement.

- [ ] Fresh en/fr-FR and fr/en-US report loads render numbers in the active app
      language consistently before and after hydration, with no number-caused
      error 418 or account-list replacement. English matching-locale controls pass.
- [ ] A live app-language change updates formatted amounts without changing the
      selected period, conversion, filters or underlying amounts.
- [ ] A focused rendered regression checks initial DOM reuse across different
      runtime-default locales; cover both renderCommas settings and representative
      primary/other amounts. Run normal dashboard gates and locale budget.
- [ ] Report loading/error/empty states and normal account navigation still work.

## Objective

Close the same router-pending gap as t001 for the case that needs no injected delay: switching ledgers. Today the URL changes to the destination ledger in ~60 ms while the previous ledger's fully-rendered content — its description, its result count and its transaction rows — stays on screen for the better part of a second, with no pending indication. Make the ledger layout stop presenting one ledger's data under another ledger's URL.

## Context

Read the milestone README first. This is the same DoD bullet from completed `m15` that the milestone already exists to close — *"no stale data is presented as a settled response for a different URL"* — but with two differences that make it worth its own task:

- **No delay injection.** The 129/t001 reproductions hold a request open to force the window. This one reproduces at natural production latency, so every user hits it on every ledger switch.
- **Cross-ledger, not cross-period.** The retained content belongs to a *different ledger*, so the page asserts the destination ledger while showing the source ledger's transactions and counts — including a private ledger's rows under a public ledger's URL.

Measured on production 2026-09-12, isolated headless Chrome, 1440×1000, authenticated QA account, no throttling; polled every ~120 ms after clicking the sidebar's **Select a ledger** combobox:

| direction | URL switches | content switches | stale window |
| --- | --- | --- | --- |
| private `puncsky/example` → public `open_ledger/minimax` | 59 ms | 923 ms | **864 ms** |
| public `open_ledger/minimax` → private `puncsky/example` | 59 ms | 674 ms | **615 ms** |

During the first window, `/ledger/open_ledger/minimax/journal` renders "Browse and filter all transactions in **example**", "Results 1–60 / **1047**" and example's rows (`STRIPE; TRANSFER; TIAN PAN`, `Anthropic • ANTHROPIC* CLAUDE SUB`). The settled values are 1047 transactions for `example` and 67 for `minimax`, so the two are unmistakable. No skeleton, no `aria-busy` on `main`, nothing marking the content as stale.

Evidence: `dashboard/tmp/qa-20260912/ledger-switch-stale.json` (gitignored, local only).

## Steps

1. Reproduce both directions with the timing method above before changing anything.
2. Extend t001's pending indication at the shared ledger layout boundary so a change of `ledgerOwner`/`ledgerName` — not only a change of report scope — enters a truthful pending state instead of retaining the previous ledger's rendered content.
3. Make the retained content unmistakably not-the-destination while pending: either replace it or mark it, but never let it read as settled data for the new URL.
4. Check the journal, accounts and a report route, and both an authenticated private→public and a public→private switch.
5. Confirm `m15`'s shipped behavior still holds: a ledger switch resets the shared `account`/`filter`/`time` filters unless the destination URL supplies new values.

## Acceptance criteria

- [ ] After selecting a different ledger, no rendered value that belongs to the previous ledger — description, result count, or rows — is presented as settled content for the destination URL, in either direction.
- [ ] The pending state is announced accessibly and clears on success; an error does not leave a permanent busy state.
- [ ] Verified at 1440 and 390 on the journal, accounts and one report route, with no injected delay.
- [ ] `m15`'s ledger-switch filter reset still behaves as shipped.
- [ ] A regression test drives a ledger change and asserts the destination route never renders the source ledger's settled content.

## Out of scope

The Apollo conversion-phase export mismatch (t002/t003), backend or API changes, prefetching or otherwise making the switch faster rather than truthful, and the mobile package.

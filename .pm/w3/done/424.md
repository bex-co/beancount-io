# `bea import` debit/credit mapping turns a negative debit cell into money in, and refuses a `0.00` companion cell

**Severity:** major. **Estimate:** 30–45 minutes. **Owner:** cli. **A1/A2:** a
newcomer importing a common "Money Out / Money In" export (header inference
maps `Money Out` to `debit`) gets every outflow written as an inflow, with exit
0 and a clean `bea check`.

Found 2026-09-26 by CLI QA (`qa-find-bugs-cli`) against `main` HEAD
`8cd9732b`, `uv run bea` 0.3.0, Darwin 26.5.1 arm64, isolated
`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, stdin closed. Synthetic ledger only.

## Repro

```sh
cat > main.bean <<'EOF'
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Expenses:Uncategorized USD
EOF
printf 'Date,Description,Money Out,Money In\n2026-02-01,Coffee,-4.50,\n2026-02-02,Salary,,1000.00\n' > export.csv
bea --file main.bean import export.csv --account Assets:Checking --apply
bea --file main.bean balance Assets:Checking
```

Header inference reads `--csv date=Date,debit=Money Out,credit=Money In,narration=Description`;
the preview shows `Coffee  4.50 USD`, the apply writes
`Assets:Checking  4.50 USD` and exits 0, and the balance is `1,004.50 USD`.
Expected `-4.50 USD` and `995.50 USD`: USAGE/IMPORTING say "debits post
negative", and a debit is money leaving the source account whatever sign the
bank prints on it. Many banks print the outflow column with a leading minus.

Second shape at the same site: a row with `Debit=30.00,Credit=0.00` (banks
often zero-fill the unused column) is refused with
`Row 4 (line 5): fill exactly one of 'Debit' or 'Credit'.` and exit 2, so the
whole export cannot be imported without hand-editing.

## Root cause

`cli/src/bea_engine/csv_mapper.py:797-804`: the pair branch tests
`bool(debit) == bool(credit)` on raw strings (so `"0.00"` counts as filled),
then parses the filled cell and applies `_negated` to a debit unconditionally.
A cell that already carries a minus is negated twice into a positive.

## Fix

- A debit posts negative and a credit positive by *magnitude*: parse the cell,
  then take `-abs(n)` for debit and `abs(n)` for credit (keep the exact-negation
  helper from w3/408 so no digits change). If a column mixes signs (some
  debits negative, some positive), refuse naming the column and rows rather
  than guessing.
- Treat a cell that parses to zero as empty for the "exactly one" rule; still
  refuse two non-zero cells, and treat two zeros as a skipped blank row or a
  zero-amount refusal consistently with the amount path.
- `sign=ledger` then flips the result as today.
- Document both in `cli/docs/IMPORTING.md` under the debit/credit pair.

## Acceptance

- The repro writes `-4.50 USD`; a positive-debit control (`Debit=20.00`)
  still writes `-20.00 USD`; credit `1000.00` still writes `1000.00 USD`.
- `Debit=30.00,Credit=0.00` previews `-30.00 USD`.
- A debit column mixing `-5` and `7` is refused with the column named.
- Regression tests in `cli/tests/` cover all three through `bea import`.

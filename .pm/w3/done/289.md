# `bea list` drops directive metadata for commodity / note / event / open / document / custom

**Severity:** minor. **Estimate:** 25–40 minutes. **Owner:** cli. **A1:** an
agent that `list commodity` / `list note` after writing `name:` / `author:`
metadata (or reads existing books that use commodity metadata heavily) gets
JSON/human rows with no `meta` field — while `list transaction --details`
already returns transaction and posting metadata.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `90c82672`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
cat > main.bean <<'EOF'
option "operating_currency" "USD"
2020-01-01 commodity HOOL
  name: "Hollowood"
  asset-class: "stock"
2020-01-01 open Assets:Cash USD
  friendly: "Cash"
2020-01-01 note Assets:Cash "hello"
  author: "qa"
2020-01-01 event "location" "SF"
  source: "manual"
2020-02-01 custom "budget" TRUE 1000
  note: "q1"
EOF

bea --json --file main.bean list commodity
# {"data":[{"date":"2020-01-01","currency":"HOOL"}]}  ← no name / asset-class

bea --json --file main.bean list note
# {"data":[{"date":"…","account":"…","comment":"hello"}]}  ← no author

bea --json --file main.bean list event
# no source meta

bea --json --file main.bean list open
# no friendly meta

bea --json --file main.bean list custom
# values present; note meta missing
```

Working control — transaction metadata is exposed:

```sh
bea --file main.bean add transaction --date 2020-03-01 -n x \
  --meta 'receipt:R1' -p 'Assets:Cash -1 USD' -p 'Expenses:Food 1 USD'
# (open Expenses:Food first)
bea --json --file main.bean list transaction --details --search x
# data[].meta includes receipt
```

## Expected

Every `list <type>` JSON object includes a `meta` map of user keys (excluding
Beancount `filename`/`lineno` source keys, or documenting that choice). Human
tables may keep a compact default view but JSON is the agent contract.

## Actual

`NoteDirective`, `EventDirective`, `CommodityDirective`, `OpenDirective`,
`DocumentDirective`, and `CustomDirective` models have no `meta` field;
`reader.list_*` constructors never copy `entry.meta`.

## Root cause

`cli/src/bea_engine/ledger/models.py` omits `meta` on those directive models;
`cli/src/bea_engine/ledger/reader.py` `list_notes` / `list_commodities` / …
append bare fields only. Transaction listing already maps meta under
`--details`.

## Fix

Add optional `meta: dict` to the affected models, populate from `entry.meta`
(strip or keep filename/lineno consistently with transaction listing), and
include it in JSON output. Regression: the fixture above returns the written
keys for each list type; transaction `--details` unchanged.

## Dedupe

Not w3/284 (`--meta` write validation). Not w3/244 (document comment vs
filename). Not w3/237 (import-id / bank_id write). No open note covers
`list` dropping read-side directive metadata.

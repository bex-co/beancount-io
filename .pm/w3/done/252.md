# `bea add note` / `event` / `custom` keep CR/LF in string fields; payee/narration flatten

**Severity:** minor. **Estimate:** 20–35 minutes. **Owner:** cli. **A1:** an
agent that pastes a multiline bank memo into `--comment` / `--description` /
`text:…` gets a split ledger line (`"SF\nCA"`), while the same paste into
`--narration` or `--payee` becomes one line (`"SF CA"`) per USAGE.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `12285b6c`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
bea --json --file main.bean add note --date 2024-04-01 \
  --account Assets:Cash --comment $'line1\nline2'
# ledger:
#   2024-04-01 note Assets:Cash "line1
#   line2"
# JSON directive.comment retains the newline; bea check still exits 0

bea --json --file main.bean add event --date 2024-04-11 \
  --type location --description $'SF\nCA'
# ledger: event "location" "SF\nCA" across two physical lines

bea --json --file main.bean add custom --date 2024-04-20 \
  --type budget --value $'text:hello\nworld'
# ledger: custom "budget" "hello\nworld" across two lines
```

Working control — same newline through transaction fields:

```sh
bea --json --file main.bean add transaction --date 2024-04-10 \
  --narration $'a\nb' --payee $'Bob\nCorp' \
  --posting 'Assets:Cash -1 USD' --posting 'Expenses:Transport 1 USD'
# writes: 2024-04-10 * "Bob Corp" "a b"
# JSON payee/narration are already flattened
```

`USAGE.md`: “Payees, narrations, and string metadata are written on one line:
runs of CR/LF line breaks become spaces in single adds, bulk JSON, and
imports.”

## Expected

Note `comment`, event `description`, and custom `text` values flatten CR/LF to
spaces the same way as payee/narration/string metadata (via the existing
`single_line` helper), so every agent-written string field stays one ledger
line. Keep intentional Beancount multiline strings out of CLI/add JSON unless
documented as an escape hatch.

## Actual

```text
cli/src/bea_engine/ledger/writer.py  normalize_entry_strings
  — single_line(payee/narration) and string metadata
cli/src/bea_engine/ledger/adding.py  _simple note/event
  — comment/description via _text() with no single_line
cli/src/bea_engine/ledger/writer.py  format_entry Note/Event/Custom
  — escape_string only; does not flatten
```

Beancount accepts the multiline quoted form, so `check` stays green and the
inconsistency is easy to miss.

## Fix

Apply `single_line` to note `comment`, event `description`, custom text
`value`s (and any other CLI-authored string directive fields that are not
paths) before write — ideally in `normalize_entry_strings` / `_simple` so
bulk and single-add share one path. Regression: newline in note/event/custom
text becomes a space in the file and in returned JSON; narration control still
flattens.

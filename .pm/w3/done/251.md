# `bea format -i` on a tree with a non-UTF-8 `.bean` fails with an opaque codec error and no path

**Severity:** minor. **Estimate:** 20–40 minutes. **Owner:** cli. **A1:** an
agent formatting a directory cannot tell which scanned file was binary or
corrupt; `--check` / `--dry-run` name the path, but `-i` does not.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `16bdaa8c`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache.

## Repro

```sh
mkdir fmtdir
printf '2024-01-01 open Assets:X USD\n2024-01-02 * "ok"\n  Assets:X 1 USD\n  Equity:Y -1 USD\n' > fmtdir/good.bean
printf '2024-01-01 open Assets:X USD\n' > fmtdir/bin.bean
printf '\x00\xff\xfe' >> fmtdir/bin.bean

bea --json format -i fmtdir
echo exit=$?
# exit 1
# {"error":{"category":"validation",
#   "message":"'utf-8' codec can't decode byte 0xff in position 30: invalid start byte",
#   "exit_code":1}}
# — no filename

# working control — same tree:
bea --json format --check fmtdir
# message names …/fmtdir/bin.bean (bean-format could not read …)
```

Human `format -i fmtdir` prints the same bare codec string. No file is
rewritten (failure is in the pre-write snapshot).

## Expected

Name the failing path in the error (and keep `--json` as a structured error),
matching the `--check` / `--dry-run` contract that recursive failures identify
the affected file. Example: `could not read …/fmtdir/bin.bean as UTF-8 text`.

## Actual

`format.py` builds `before = {file: _text(file) for file in files}` where
`_text` is bare `Path.read_text()`. A `UnicodeDecodeError` (or other OSError)
propagates without the path. The later `bean-format --in-place` never runs, so
there is also no upstream traceback that would have named the file.

## Fix

Wrap `_text` (or the `before` / post-write re-read) so decode and permission
failures become `BeaError` / `UsageError` with `str(file)` in the message.
Keep successful UTF-8 trees unchanged. Regression: tree with one binary `.bean`
and one good file under `--json format -i` returns a JSON error that includes
the binary path; `--check` still names it.

## Dedupe

Not w5/004 (read-only `-i` → raw bean-format traceback / partial rewrite). Not
w3/249 (empty-dir JSON silence). Not w3/250 (`-o` directory). No open note
covers pre-write `_text` decode without a path.

---

**Resolved 2026-09-16** — `format -i` `_text` failures name the file path (UTF-8 decode / OSError) instead of a bare codec string. Covered by `cli/tests/test_format_binary_path.py`. Shipped with this board close.

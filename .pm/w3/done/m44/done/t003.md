## Objective

`resolveApiKeyIdentity` fires `void stampLastUsed(key.id, database)` on every successful resolve. `lastUsedAt` exists so a person looking at their key list can see which key their cron job is actually using — five-minute resolution, deliberately off the request path. An introspection call is a third party asking *about* a key, not that key being used, and stamping it turns that signal into noise. Give introspection a resolve path that observes without recording.

## Context

- `src/server/api/identity.ts` — `resolveApiKeyIdentity`, `stampLastUsed`, `LAST_USED_THROTTLE_MS`, the process-local `lastUsedThrottle` map.
- The stamp is already throttled and fire-and-forget, so this is about intent, not cost.
- Prefer threading an explicit option through `ResolveIdentityOptions` over a parallel copy of the resolver — two resolution paths that can disagree about who is authenticated is the failure this codebase has already paid for once (ADR 0006 problem 2).

## Steps

1. Add an option to `ResolveIdentityOptions` that suppresses usage recording, defaulting to recording so every existing caller is unchanged.
2. Thread it to `resolveApiKeyIdentity`.
3. Audit the OAuth and session paths for any other write-on-read — the session path's `models.jwt.verify` is a read, confirm nothing else stamps.

## Acceptance criteria

- [ ] Resolving with the option set does not call `touchLastUsedAt`, proven by a test that asserts on the model call rather than on the timestamp.
- [ ] Default behavior is unchanged: a normal API request still stamps, still throttled.
- [ ] There is one resolution path, not two.

## Out of scope

Changing the throttle window or moving `lastUsedAt` off the resolver.

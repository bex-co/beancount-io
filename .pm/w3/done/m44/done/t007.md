## Objective

Check the shipped endpoint is discoverable and usable on every surface it exposes — an integrator who has never read this repo should be able to validate a credential from the documentation alone.

## Context

- `backend-cluster/backend-v2/README.md` already carries the "OAuth deployment contract" section — the canonical worked example of the issuer → resource → well-known chain. The introspection endpoint belongs next to it, with a copy-pasteable request and the full response shape for each of the three credential kinds.
- The README should also say plainly what offline JWKS verification can and cannot do, so a reader does not reach for the wrong one: OAuth access tokens verify offline against `/api-gateway/oauth/jwks`; session tokens and `bcio_` keys cannot, and no credential's live-or-revoked status can.
- Check the root `README.md` and `CLAUDE.md` package tables still describe backend-v2 accurately.
- Verify the `AGENTS.md` symlinks and the `.claude/skills` → `../.agents/skills` link are intact, then run `python3 scripts/check-agent-guidance.py`.

## Acceptance criteria

- [ ] The backend README documents the endpoint with a worked request and the response for all three credential kinds, including the `active: false` case.
- [ ] It states which credentials can be verified offline and which cannot, and why.
- [ ] `python3 scripts/check-agent-guidance.py` passes.
- [ ] Any drift found beyond this milestone's scope is recorded as a new inbox note rather than fixed silently here.

## Out of scope

Dashboard or mobile UI for introspection. A client library.

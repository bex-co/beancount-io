## Objective

Cover the behavior this milestone shipped and, specifically, its failure modes. The valuable tests here are the negative ones — this endpoint is a security surface, and the ways it can be wrong are ways it leaks.

## Context

The matrix that matters:

- **Three kinds live** — OAuth access token, `bcio_` API key, session JWT each resolve with correct `sub`, kind, lifetime, and capability projection.
- **Three kinds revoked** — grant revoked via the revocation endpoint, key revoked, `jwts` row deleted by logout. Each returns exactly `{"active": false}`.
- **Indistinguishability** — expired, malformed, and garbage produce byte-identical responses. Assert on the whole body, not on `active` alone; a test that only checks `active === false` will not catch a leaked `error_description`.
- **The session capability trap** — a session token's response must not read as "no permissions". Assert the projected capabilities directly.
- **No side effect** — introspecting an API key leaves `lastUsedAt` untouched; assert on the model call, since the throttle window would mask a timestamp assertion.
- **Caller policy — the endpoint is never anonymous.** A request with no `Authorization` header, no cookie and no `x-api-key` is refused, and so is a caller holding a credential below the ADR017 bar. Assert the refusal is an authentication failure and **not** `{"active": false}` — the two are easy to confuse in a handler and only one of them keeps the endpoint from being an oracle. This is a regression test for the specific trap that the `REST ALL /api-gateway/oauth/{*path}` always-public entry would cover a mount under that prefix silently, so it must exercise the mounted route rather than the handler in isolation.
- **No OAuth configured** — with `OAUTH_JWKS` unset, API keys and session tokens still introspect.

Tests must assert real behavior and failure modes. Do not snapshot the whole response object as a substitute for asserting what each field means.

## Acceptance criteria

- [ ] Every row of the matrix above has a test.
- [ ] Each test fails when the behavior it covers is broken — verify by breaking it, not by assuming.
- [ ] `yarn test` passes, including the surface-parity and op-class coverage gates.

## Out of scope

Load or timing-attack testing of the digest lookup. End-to-end tests against a deployed environment.

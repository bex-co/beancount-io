## Objective

An endpoint a third party has to be told about by hand is one they will not use. Advertise `introspection_endpoint` in the authorization-server metadata a validator already reads, and record the new path in the `.well-known` index so it does not fall out of sync.

## Context

- `/.well-known/oauth-authorization-server[/{issuer-path}]` is generated by `oidc-provider` inside `setOidcRoutes` (`src/features/oauth/api/oidc-route.ts`). Because the endpoint from t004 is our own handler and not oidc-provider's built-in introspection, the document will not advertise it automatically — this has to be added deliberately.
- If the endpoint is not an OAuth-client-authenticated endpoint per ADR017, advertising it in RFC 8414 metadata may be the wrong claim to make. Check ADR017's decision 1 before adding the field; if it does not belong there, document the endpoint in the backend README instead and say so here.
- `docs/adrs/ADR009-backend-v2-well-known-paths.md` is the single index of every `.well-known` path and the ten places a change to one touches. This task is not adding a path — only a field inside an existing document — so most of the ten do not apply. Confirm that and note it, rather than assuming.
- The no-JWKS branch of `setOidcRoutes` replaces OAuth discovery with a `503 oauth_not_configured` handler. Decide whether introspection should still answer when OAuth is unconfigured: it must, because API keys and session tokens exist on a deployment with no OAuth signing keys at all.

## Acceptance criteria

- [ ] A validator reading the authorization-server metadata can find the introspection endpoint, or ADR009/the README records why it is advertised elsewhere.
- [ ] Introspection still answers on a deployment with `OAUTH_JWKS` unset — OAuth tokens report `active: false` there, API keys and session tokens still resolve.
- [ ] `ADR009`'s table and touchpoint list are accurate after this change.
- [ ] `oidc-route.test.ts` covers the advertised field and the no-JWKS case.

## Out of scope

Adding any new `.well-known` path. Changing the mobile client's discovery mirror (`mobile/src/common/oauth/discovery.ts`) — it builds paths, and no path changed.

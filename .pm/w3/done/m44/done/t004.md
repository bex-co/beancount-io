## Objective

Build the RFC 7662 endpoint over `resolveIdentity`, at the mount and behind the caller-authentication policy ADR017 chose, with its scope-gate census entry and a rate-limit bucket that actually applies to its path.

## Context

- `resolveIdentity` (`src/server/api/identity.ts:294`) already returns `undefined` for absent, malformed, expired and revoked without distinguishing them — that is the `{"active": false}` answer, and preserving the indistinguishability is a requirement, not an accident. Do not add error detail to the response.
- `oidc-provider`'s `features.introspection` is not used: it would answer `active: false` for a live `bcio_` key or session JWT. See the milestone README.
- `rate-limit.ts:200` buckets by path substring — `/oauth` or `/.well-known/` get the `oauth` budget. A mount outside those strings has no bucket until one is added, and this endpoint is a brute-force oracle against the API-key digest lookup.
- `always-public.ts` compares its census against what the composition root actually mounted, in both directions, so a new mount fails the test until it is either gated or justified in writing. Note the existing `REST ALL /api-gateway/oauth/{*path}` catch-all covers anything under that prefix.
- Response projection per ADR017: `active`, `sub`, `exp`/`iat` (from t002), `client_id` and `jti` where the credential has them, the single-ledger ceiling from `ledgerScope`, the credential kind, and the capability projection — **not** the raw `scopes` set, for the reason in the milestone README.

## Steps

1. Register the route and handler; resolve with the no-side-effect option from t003.
2. Enforce the caller policy from ADR017 before resolving anything. The caller's own credential is checked **first**, and a caller who fails that check gets a `401`/`403` without the submitted token being looked at at all — never a `{"active": false}`, which would leak that the endpoint answers anonymously and make it a usable oracle anyway.
3. **Prove the endpoint is not anonymous.** Do not infer this from the code path — exercise the mounted route. Issue the request with no `Authorization` header, no cookie, and no `x-api-key`, and confirm it is refused; then confirm the census does not silently permit it: the endpoint's path must not be covered by the `REST ALL /api-gateway/oauth/{*path}` always-public entry, or must carry a narrower entry that overrides it. A `grep` of `always-public.ts` is not sufficient evidence, because the catch-all makes the absence of an entry look fine. Record the observed refusal in the task notes.
4. Project the identity onto the response; for `active: false` return exactly `{"active": false}` and no other field.
5. Add the `always-public.ts` entry with a written reason, or confirm the mount is under the gate and record which op-class.
6. Add the rate-limit bucket for the chosen path.
7. Regenerate `docs/openapi/v1.json` if the mount falls under the v1 contract (`yarn generate-v1-openapi`).

## Acceptance criteria

- [ ] A live OAuth access token, a live `bcio_` key, and a live session JWT each return `active: true` with a correct `sub` and credential kind.
- [ ] A revoked grant, a revoked key, and a session whose `jwts` row was deleted by logout each return exactly `{"active": false}`.
- [ ] An expired credential, a malformed string, and a garbage string produce byte-identical responses.
- [ ] An unauthenticated caller is refused — verified against the mounted route with no `Authorization` header, no cookie and no `x-api-key`, not inferred from reading the handler.
- [ ] The refusal is an authentication failure, not `{"active": false}`: a caller who cannot authenticate learns nothing about the submitted token.
- [ ] The endpoint's path is provably not covered by the `REST ALL /api-gateway/oauth/{*path}` always-public entry, or carries a narrower entry that overrides it.
- [ ] A session token's response does not read as "no permissions".
- [ ] `always-public.test.ts` passes in both directions; the endpoint has a rate-limit bucket.

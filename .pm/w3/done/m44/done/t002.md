## Objective

`Identity` has no `exp`, `iat`, or `nbf`. All three credential kinds hold that data at resolve time and every one of them throws it away. Widen `Identity` with the credential's lifetime and project it from each resolver, so introspection can report it without re-resolving the token a second way.

## Context

Each source has it and drops it:

- **Session** — `resolveSessionIdentity` calls `database.models.jwt.verify`, which returns a bare `userId` (`src/features/auth/data/jwt-model/postgres-impl.ts`). The `jwts` row has `expireAt`, and the decoded token has `exp`/`iat`. The model's return shape has to widen.
- **API key** — `resolveApiKeyIdentity` calls `isApiKeyLive(key, new Date())`, so the expiry is in hand and is then discarded.
- **OAuth** — `resolveOidcIdentity` keeps `authenticatedAt` from `auth_time` and drops the JWT's own `exp`/`iat`; widen `OidcIdentity` alongside.

Optional fields, so `systemIdentity` and existing in-process fixtures stay valid — a workload identity has no credential and therefore no lifetime.

## Steps

1. Add optional `issuedAt` / `expiresAt` (seconds since epoch, matching the existing `authenticatedAt` convention) to `Identity`.
2. Widen `IJwtModel.verify`'s return so the session path can report expiry; update the Postgres implementation and its tests.
3. Project the lifetime in all three resolvers, plus `OidcIdentity`.
4. Update test fixtures and any exhaustive `Identity` constructions.

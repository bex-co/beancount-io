## Objective

Make the export refuse any destination directory where it would replace a file it
was not given, naming the colliding path, with the same `--force` opt-in the
neighbouring `bea example -o` already offers.

## Context

- Re-verified 2026-09-26 (`w3/436`), signed out and with `--allow-errors` (no
  account needed): `price export --output audit` replaced a pre-existing
  unrelated `audit/main.bean` and printed "Exported 2 files to …" at exit 0, with
  nothing in the JSON answer's `files` list marking an overwrite.
- The rationale is already written into the export's own refusal for the ledger's
  own directory: *"it holds main.bean, which the export would overwrite. Choose
  an empty or dedicated directory."* It is simply not applied to other
  directories.
- The default `<ledger>-export/` destination has the same exposure when it
  already exists.

## Steps

1. Compute the full set of paths the export would write before writing any of
   them.
2. Refuse with exit 2 when any of those paths already exists, naming the first
   collision and reusing the existing wording; keep the ledger's-own-directory
   message as the more specific case.
3. Add a `--force` opt-in that proceeds and marks each overwritten path in the
   JSON answer's `files` list.
4. Apply the same check to the default destination.

## Files

- `cli/src/cli/commands/price.py` (export path) and the export helper it calls

## Acceptance criteria

- [ ] With a pre-existing `DIR/main.bean`, the export exits 2, writes nothing,
      and `DIR` is byte-identical including its file list.
- [ ] `--force` overwrites and the JSON answer marks the overwritten paths.
- [ ] An empty or new directory still exports exactly as before, and the
      ledger's-own-directory refusal is unchanged.
- [ ] Reproducible signed out with `--allow-errors`, so the test needs no
      credentials.

## Out of scope

- Managed-feed fetch behavior and `--allow-errors` semantics themselves.
- `w3/413` (portable export overwriting a local price file), if it is a distinct
  path after this change — re-check and file separately if so.

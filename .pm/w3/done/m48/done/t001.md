## Objective

Refuse a forwarded `-o/--output` that names the ledger under read — root or any
include, any spelling, through links — before the native writer is launched, the
way `query` and `format` already do.

## Context

- `cli/src/cli/commands/ingest.py` `_forward` passes `ctx.args` straight to
  `launch.run_optional_script`; `cli/src/cli/commands/treeify.py` forwards `-o`
  to native treeify. Neither calls `output.refuse_ledger_alias`
  (`cli/src/cli/output.py:235`).
- Re-verified 2026-09-26 (`w3/431`): `ingest extract -e main.bean -o main.bean`
  replaces the whole ledger at exit 0; `-o sub/extra.bean` replaces an included
  file and leaves `bea check` failing; `treeify -o main.bean` replaces the ledger
  with an ASCII tree.
- Working controls to match: `query -o` and `format -o` exit 2; `example -o`
  refuses an existing file without `--force` (exit 4).
- `ingest archive -o DIR` moves source documents into a directory tree and must
  keep working.

## Steps

1. Parse the forwarded arguments for the output option in every spelling
   (`-o X`, `-oX`, `--output X`, `--output=X`) instead of assuming a shape.
2. Resolve the candidate and refuse when it aliases the resolved ledger closure
   or the `-e/--existing` ledger's closure — comparing resolved real paths so
   symlinks and hard links are caught.
3. For `treeify`, refuse on the same basis when a ledger resolves, and otherwise
   refuse an existing `.bean`/`.beancount` destination without `--force`.
4. Leave `ingest archive -o DIR` out of the guard, and say so in a comment so the
   next reader does not "fix" it.

## Files

- `cli/src/cli/commands/ingest.py`
- `cli/src/cli/commands/treeify.py`
- `cli/src/cli/output.py` (only if the helper needs a closure-aware entry point)

## Acceptance criteria

- [ ] Each spelling of the aliasing destination exits 2 with a message naming the
      ledger, and the ledger closure is byte-identical afterwards.
- [ ] A symlink and a hard link to the root ledger are both refused.
- [ ] `ingest extract -o <new file>` still writes, and `ingest archive -o DIR`
      still archives.

## Out of scope

- Beangulp's own truncation semantics (upstream).
- `query -o` file modes and symlinked destinations (`w3/422`).

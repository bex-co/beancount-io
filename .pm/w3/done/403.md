# `doctor region` loses relative include resolution when an option separates its operands

**Minor · 30–45m · cli · A1.** A valid `--conversion cost` option between the
ledger and region operands breaks resolution of an included file from a
foreign working directory. Moving the same option before or after the two
operands works; the failure message also mistakes `cost` for the region.

Found 2026-09-21 at HEAD `358b17ce`, checkout `bea 0.3.0`
(`cli/.venv/bin/bea`), Python 3.13.0, macOS 26.5.1 arm64. Repeated with two
pristine split-ledger fixtures, isolated config/cache, closed stdin and
separate captured stdout/stderr. Every source hash remains unchanged.

## Reproduce

Create `/absolute/books/main.bean`:

```beancount
2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:Food USD
include "txns/jan.bean"
```

Create `/absolute/books/txns/jan.bean`:

```beancount
2026-01-02 * "Lunch"
  Assets:Cash -5.50 USD
  Expenses:Food
```

From a directory outside `books` that has no `txns/jan.bean`:

```sh
bea doctor region /absolute/books/main.bean --conversion cost txns/jan.bean:1:3
# exit 1; stdout: Net Income: ()
# stderr: doctor region matched no entries for 'cost' in /absolute/books/main.bean
bea doctor region --conversion cost /absolute/books/main.bean txns/jan.bean:1:3
# exit 0; Lunch, Cash -5.50 USD, Food 5.50 USD, Net Income (-5.50 USD)
```

Expected: both forms return that same region. Native Click accepts options
between operands, and `cli/docs/USAGE.md` promises included locations are
resolved against the root ledger directory when they do not exist in cwd.

Additional controls: the option after both operands succeeds; using an
absolute region filename succeeds even with the option in the middle; the
original failing command succeeds from inside `books`. The middle
`--conversion=cost` spelling fails too, though its error names the correct
region. `doctor context ... txns/jan.bean:1` succeeds from the foreign cwd.

## Cause and fix

`cli/src/cli/commands/doctor.py:53` `_located_against_ledger` finds the ledger
by checking which argument names a file, then assumes its immediate next
argument is the location. With an interposed option that is `--conversion`,
so the function returns without resolving the real location. Native loading
then looks in cwd and finds no entries. `_positionals` at line 40 only drops
arguments beginning with `-`, leaving the option value `cost`; the empty-scope
diagnostic at line 212 consequently labels it as the region.

Identify actual native operands while honoring option values, `--name=value`
and `--`, then resolve the location independently of option placement. Reuse
that interpretation for the empty-scope diagnostic. Preserve cwd-first
resolution when that file exists, absolute paths, line-only regions and
upstream's native option validation. Regression coverage should execute the
middle-option repro from a foreign cwd and preserve the working placements.

Caller search: the resolver is shared by `context`, `linked` and `region`;
the live failure here is `region` with its supported conversion option.
Other operations/option values, missing/invalid option values and other OSes
remain unverified. No server/API or dependency changes are required.

Dedupe: searched all queues, completed/blocked items and open milestones for
doctor option ordering, relative locations and `_located_against_ledger`.
Completed `w3/355` (`77dde089`) explicitly fixed this resolution for all three
operations, but its full tests only pass adjacent ledger/location operands.
`w3/352` fixes scoped decimal rendering and `w2/020` native help; neither owns
argument interpretation. Targeted helper history shows no later fix.

Evidence: ignored `cli/tmp/qa-20260922T052032Z-loop/doctor-option-{placement,repeat}/`
and `captures/doctor-options-*.json`, plus `doctor-context-relative.json`.
These retain exact argv/cwd, fixture contents/hashes, streams, exit codes and
duration. The public fixture above is sufficient to rerun the failure.

---

**Resolved 2026-09-22** — `doctor` identifies its operands wherever the
options sit, so relative-include resolution no longer depends on argument
order.

`_located_against_ledger` found the ledger by looking for an argument naming an
existing file, then assumed the *next* argument was the location. With
`--conversion` between them that was the option itself, so w3/355's resolution
never ran. `_positionals` had the matching gap — it dropped arguments starting
with `-` but kept the option's value, which is why the empty-scope message
named `cost` as the region.

Both now come from one `_operand_indices` walk that skips an option *and its
value*, handles `--name=value`, and treats everything after `--` as an operand.
Fixing `_positionals` centrally also corrects the four other call sites that
read the ledger operand (`parse`, `print-options`, `roundtrip`, and the second
empty-scope site).

The option grammar is not guessed. Upstream's `context`, `linked` and `region`
each take exactly `FILENAME LOCATION`, and `region` has the single
value-taking option `--conversion` with no boolean flags anywhere — read off
`beancount.scripts.doctor`. The frontend may not import beancount, so that set
is restated there and a test pins it against upstream, asserting both that the
list still matches and that no boolean flag has appeared (which would make an
operand look like a value).

Verified on the note's fixture from a foreign working directory: the middle
option now returns the region, as do `--conversion=cost` in the middle and the
three placements that already worked. The empty-scope message names the region
rather than `cost`.

One thing worth recording for anyone re-running this: my first attempt used a
fixture under `/tmp`, where **nothing** worked. That is unrelated — on macOS
`/tmp` is a symlink to `/private/tmp`, so the location path never string-matches
the `/private/...` filename the loader recorded. The test fixture uses
`tmp_path` and says so, because a future reader hitting that would reasonably
conclude the fix had regressed.

Regression coverage is `cli/tests/test_doctor_option_placement.py`: the five
placements end to end, the diagnostic, the operand walk directly, and w3/355's
rule that a location which already resolves is left untouched. Reverting only
the operand walk fails 7 of its 16. `cd cli && make check-all` passes (1879
tests).

Unverified, as in the note: `context` and `linked` with an interposed option
(they share the resolver and have no options of their own, so there is nothing
to interpose), missing or invalid option values, and other platforms.

# `bea query -o` writes exports as mode 0600, resets an existing file to 0600, and replaces a symlinked destination instead of writing through it

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** cli. **A1:** an
export meant for another tool or user (a CSV for a spreadsheet, a JSON
result for a CI artifact step) comes out owner-only, and a symlinked
report path is silently turned into a regular file while the real target
stays stale. `bea format -o` and `bea example -o` honor the umask and write
through links; ledger writes preserve the file mode.

Found 2026-09-25 by CLI QA (`qa-find-bugs-cli`) against `main` HEAD
`8cd9732b`, `uv run bea` 0.3.0, Darwin 25.5.0 arm64, umask 022.

## Repro

```sh
printf 'option "operating_currency" "USD"\n2026-01-01 open Assets:Cash\n' > main.bean
echo old > b.csv; chmod 644 b.csv
bea --file "$PWD/main.bean" query -f csv -o "$PWD/b.csv" "SELECT account FROM #accounts"
ls -l b.csv                               # -rw-------  (was -rw-r--r--)
bea --json --file "$PWD/main.bean" query -o "$PWD/c.json" "SELECT 1"
ls -l c.json                              # -rw-------
mkdir real; echo old > real/t.csv; ln -s real/t.csv link.csv
bea --file "$PWD/main.bean" query -f csv -o "$PWD/link.csv" "SELECT 1"
ls -l link.csv; cat real/t.csv            # link.csv is now a regular 0600 file; real/t.csv still "old"
# control:
bea --file "$PWD/main.bean" format -o "$PWD/f.bean" main.bean; ls -l f.bean   # -rw-r--r--
```

## Root cause

Both export paths create the file with `tempfile.mkstemp` (always 0600) and
`os.replace` it over the destination, without a `chmod`:
`cli/src/bea_engine/query.py:201–204` (text/csv, via
`bea_engine/ledger/write.py` `candidate_file` ~245) and
`cli/src/cli/utils.py:144–160` `atomic_write` (the `--json -o` path via
`cli/src/cli/output.py:309`). The ledger writer at
`bea_engine/ledger/write.py:805` does `candidate.chmod(...)`; the export
paths never got the equivalent. `os.replace` on a symlink replaces the link.

## Fix

Before the replace, give the candidate the existing destination's mode, or
`0o666 & ~umask` for a new file; resolve a symlinked destination to its
target (as `format -o` effectively does) before creating the sibling temp.
Keep atomicity and the w3/380 "failed query preserves the old export"
behavior.

## Acceptance

- New exports get `0644` under umask 022; an existing `0644` export stays
  `0644`; `-o link.csv` updates `real/t.csv` and leaves the link in place —
  for text, csv and `--json` exports.
- Regression tests for mode and symlink on both paths.

## Dedupe

Searched `.pm/**` and `git log` for 0600, umask, permission, symlink +
query/output: only credential-file 0600 work (a5323178, w2/m24/t007) and the
atomic-export change (w3/380). No open item.

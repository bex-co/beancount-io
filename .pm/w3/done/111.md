# Mobile recurring switch has no accessible name

Severity: minor. Estimate: 20m. Package: mobile. A2 — make merchant preferences identifiable with assistive technology.

Environment: September 10, HEAD a1c1bac8 (merchant screen unchanged since a7c088d2), native build 1.20260906.47, iPhone 17e / iOS 26.5, English/System/light/default large text. Signed-in QA at https://beancount.io, public synthetic open_ledger/crypto-example.

Repro: select the crypto example, then open inspected internal route beancount:///(app)/merchant-detail?payee=Ethereum%202.0. Inspect merchant-recurring-toggle with Expo MCP automation_find_view. It exists, is enabled and hittable, has value "1", but label, title and placeholder are all empty. Terminate/relaunch the app, reopen the route and repeat: the label is still empty. No recurring preference was changed. This proves the destination and native accessibility metadata, not the full merchant-list navigation or VoiceOver speech.

Expected: the switch exposes a localized meaningful name identifying the recurring-merchant preference and its native checked state. Actual: visible adjacent copy says “Mark as not recurring”, but the switch itself has no accessible name. Working control: ledger-drawer-button exposes “Open menu” through the same MCP inspection.

Root cause: mobile/src/screens/merchant-detail-screen/merchant-detail-screen.tsx:491-498 supplies testID, value and callbacks to Switch but no accessibilityLabel. The adjacent title/helper Text components sit in a sibling View without an accessible relationship. The test identifier does not supply a user-facing label. The single merchant-detail route shares this control across all payees.

Fix: give the switch a translated accessible name that identifies the recurring preference, retain its native checked state, and provide the existing device-local override explanation as a hint if useful. Verify enabled and disabled values are understandable without reading neighboring text. Keep the current detection/override behavior. Do not replace the native switch or add dependencies.

Evidence: mobile/tmp/qa-2026-09-10/recurring-ax-first.json, recurring-ax-repeat.json and drawer-ax-control.json contain the native metadata; crypto-merchant.jpg shows the visible control. A later screenshot, crypto-merchant-repeat.jpg, caught the launch splash and is not corroborating screen evidence. The screen's separate “Trailing tokens” list error does not prevent the switch rendering or being exposed; it is under separate investigation. Actual VoiceOver navigation/audio, Android, denied/expired/offline states and other locales were not exercised. No ledger writes, product fixes or shipping.

Dedupe: searched all .pm markdown, including completed accessibility work in w4/done/m7, for recurring controls, switch labels and merchant accessibility. No matching item. w3/103 concerns dashboard loading-button names, a different implementation. Merchant history contains 2b36b2cc (feature) and a7c088d2 (analytics cleanup); current main still omits the label.

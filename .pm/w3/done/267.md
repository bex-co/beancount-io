# `bea format` turns tab-indented postings into 1-space indent and then treats that as already formatted

**Severity:** minor. **Estimate:** 20–40 minutes (may be upstream
`bean-format`). **Owner:** cli. **A1:** a ledger that used tabs for posting
indent is rewritten to a single ASCII space before the account name; later
`format --check` is green, so CI never restores the usual two-space style
agents and docs show.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `922cf45b`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
printf '%s\n' \
  'option "operating_currency" "USD"' \
  '2020-01-01 open Assets:Cash USD' \
  '2020-01-01 open Expenses:Food USD' \
  '' \
  '2020-02-01 * "x"' \
  $'\tAssets:Cash -1 USD' \
  $'\tExpenses:Food' \
  > tabs.bean

bea format -i tabs.bean
python3 -c "print(repr(open('tabs.bean').read()))"
# postings become ' Assets:Cash  -1 USD' / ' Expenses:Food' (one space)

bea format --check tabs.bean
# exit 0 — All 1 file(s) are formatted.
```

Working control — the same ledger with two-space posting indents formats to
two spaces and stays two spaces under `--check`.

## Expected

Formatting normalizes posting indentation to the project’s usual two spaces
(or whatever indent `_destination_indent` / bean-format already uses for
space-indented files), not a single space that then becomes the frozen
canonical form.

## Actual

`bea format` delegates to `bean-format`. Tab indents are expanded/replaced such
that one space remains before the account; `--check` then compares against that
output and reports clean. Space-indented inputs keep two spaces.

## Fix

After upstream align (or in a thin post-pass), rewrite posting lines that begin
with a single space (or leftover tabs) to the standard two-space indent used
elsewhere, or configure/patch bean-format’s tab handling so tabs become two
spaces. Regression: the tab fixture formats to two-space postings; `--check`
stays green; ordinary two-space files unchanged.

## Dedupe

Not w3/249 (empty format directory JSON). Formatting of invalid files as
alignment-only is documented in USAGE. No open note covers tab→one-space
canonicalization.

---

**Resolved 2026-09-16** — after bean-format, posting indents that are tabs or a single space are normalized to two spaces; `--check` compares the same canonical form. Covered by `cli/tests/test_format_tab_indent.py`. Shipped with this board close.

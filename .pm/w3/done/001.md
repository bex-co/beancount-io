# Revive or retire mobile analytics

Every `analytics.track` call in the app no-ops in production: `mobile/src/config.ts` ships
`analytics.mixpanelProjectToken: ""` (a `// TODO` since the monorepo move), and `MyAnalytics`
(`mobile/src/common/analytics.ts`) only constructs the Mixpanel client when the token is
non-empty. Found during `w3/m3/t002` (2026-08-24), where zero funnel data forced a double
"no" — no interval filter on /budget, keep the Home panel CTA.

Two honest paths:

1. Provision a Mixpanel project and feed the token at build time (EAS secret →
   `EXPO_PUBLIC_*` env var read in `config.ts`); never commit it to this public repo.
2. Delete the wrapper and stop wiring events into a dead sink.

Until one happens, no analytics-gated product decision on this board can run — it will hit
the same zero-data wall m3's review did.

## Outcome — retired (2026-08-27)

Path 2. The wrapper, the vendored Mixpanel client, `usePageView`, and every
`analytics.track` call site are gone, along with the `expo-analytics` and
`expo-mixpanel-analytics` dependencies and the dead `analytics` block in
`mobile/src/config.ts` (the `googleTid` beside the token was equally unused).
Provisioning a Mixpanel project (path 1) would have put a per-user event stream
behind a credential this public repo cannot hold, to serve a roadmap that had
not yet spent a decision on it — the honest move was to stop pretending the
instrumentation existed.

Dead plumbing removed with it, since analytics was its only consumer: the
`HomeDashboardCard` wrapper and its `home-card-tap` contract (Home cards now use
the shared `DashboardCard` directly), `TransactionDetailSource`,
`TextInputScreen`'s `analyticsPageName` / `analyticsSaveEventName` props,
`BalanceChartCard`'s `onRangeChange`, `MenuButton`'s `onOpen`, and the
`identify` / `track` / `trackLogout` / `deleteAnalyticsUser` dependencies of the
sign-in and sign-out flows. `mobile/CLAUDE.md` now says the app ships no event
tracking, so no future session adds a call to a sink that isn't there.

A board decision that needs usage data again starts by reviving a sink — that is
its own milestone, with the credential question answered first.

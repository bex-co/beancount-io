# doctor roundtrip exits zero when its actual comparison reports different entries

**Minor · 30–45m · cli · A1.** Automation cannot rely on roundtrip's exit
status: a valid input can print `ERROR : Entries differ!` and still exit 0.
The existing input-syntax guard only covers failures before the comparison.

Found 2026-09-21 at HEAD `d5e8e06d`, checkout `bea 0.3.0`, Python 3.13.0,
macOS 26.5.1 arm64. Two pristine copies of each fixture, fresh real subprocesses,
closed stdin, isolated config/cache and unchanged source hashes. Concurrent
import-identity edits belong to another worker and do not affect this path.

## Reproduce

Save `/absolute/quote.bean` exactly as follows:

```beancount
2026-01-01 open Assets:Cash USD
2026-01-02 note Assets:Cash "a\"b"
```

```sh
bea --json --file /absolute/quote.bean check
# exit 0, valid=true
bea doctor roundtrip /absolute/quote.bean
# exit 0 despite stderr ending: ERROR   : Entries differ!
```

The pinned upstream printer drops the note's quote escaping when writing its
temporary representation. Stdout reports an invalid token in the temporary
`quote.roundtrip1.bean`, then prints the differing entries. This is a real
failed comparison, not a fabricated error stream.

A second valid fixture containing `note Assets:Cash "a\\b"` also exits 0
with `Entries differ!`: upstream prints a single backslash, and rereading
changes the note text to a backspace escape. Both examples reproduce on a
fresh copy. The control `note Assets:Cash "ab"` exits 0 with `Entries are the
same. Congratulations.` in both copies. Original files remain byte-identical;
no existing artifact files were present in these directories.

Expected: a failed roundtrip comparison exits **1** while retaining the native
diagnostic output. Successful comparisons stay 0, and an already nonzero
native status is preserved. Document this case alongside the current doctor
exit table in `cli/docs/USAGE.md`.

## Cause and bounded fix

`cli/src/cli/commands/doctor.py:161` `_forward_roundtrip` asks
`_syntax_errors_of` about the original input. When that passes, it returns
`launch.run_native`'s exit unchanged. The pinned installed
`beancount/scripts/doctor.py:122` `roundtrip` logs `Entries differ!` around
line 178 but never returns a failure status. The bea wrapper therefore fixes
invalid-input false success but misses failure during the operation itself.

Map the real comparison outcome to bea's exit contract, reusing its existing
native capture/replay machinery. Keep diagnostics visible, preserve explicit
native failures and avoid confusing user text printed on stdout with a native
comparison error. Add actual-command tests using these fixtures and the
successful control. Do not fork or replace upstream's printer/comparison;
detecting its mismatch is the purpose of this diagnostic. No dependencies or
API changes are needed.

---

**Resolved 2026-09-22** — a failed roundtrip comparison exits **1**.

w3/371 covered input that does not parse; this covers input that parses and
whose comparison then fails. Upstream logs `Entries differ!` and returns 0
regardless, so a valid ledger that does not survive its own print/parse cycle
was indistinguishable from a clean one to anything automated.

The valid-input branch now captures rather than streams, replays the output
unchanged, and raises when the verdict says the entries differ. Upstream's
printer and comparison are untouched — detecting their mismatch is the point
of the diagnostic, as the note insisted.

On the note's caution about confusing user text with a native error: upstream
**logs** its verdict to stderr but **prints** the differing entries to stdout,
so `_entries_differ` reads stderr alone. Verified directly: a ledger whose
narration is literally `"Entries differ!"` round-trips cleanly and exits 0.
That is pinned as a test.

Verified on both reported fixtures — the escaped quote and the escaped
backslash — each exiting 1 with upstream's `Entries differ!` still visible and
the source byte-identical. Controls hold: a clean comparison still exits 0 with
its congratulations, the native trace is still shown, unparseable input keeps
w3/371's own failure, and **w3/409's collision guard still runs first** (exit 4,
file untouched). Both safeguards share this wrapper and neither displaces the
other, which the note asked for explicitly.

`cli/docs/USAGE.md`'s doctor exit table now covers both roundtrip failures and
the exit-4 collision refusal from w3/409, which was previously undocumented.

Regression coverage is `cli/tests/test_doctor_roundtrip_mismatch_exit.py`.
Reverting the verdict mapping fails its two mismatch cases while all five
controls pass either way. `cd cli && make check-all` passes (1953 tests).

Unverified, as in the note: other platforms, and directive types beyond the
two escaping shapes reported.

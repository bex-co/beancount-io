## Objective

Pin the repair with tests that would have caught the original mismatch: assert the **relationship** between a header and the value beneath it, not just that both strings render somewhere.

## Context

- The original bug is invisible to a test that only checks "the header 'Units' is present" and "a postings toggle is present" — both were true while the column was wrong. Query by column: `getByRole("columnheader", { name })` and the cell in that column for a given row.
- Existing suites: `dashboard/src/features/journal/components/__tests__/journal-table.test.tsx`, plus the account page's tests under `features/reports/account/__tests__/`. Note that several page-level suites mock `journal-table` away, so the real assertions belong in the component's own suite.
- Cover both branches: `isAccountJournal` true and false.
- Use the reproduction data: a commodity purchase row with a posting count, a change and a balance.

## Steps

1. Assert, for the account branch, that each of the six columns' cells hold the expected values for a known row.
2. Assert the same for the plain `/journal` branch's four columns.
3. Assert non-transaction rows leave the value columns empty rather than invented.
4. Assert the postings disclosure is operable by keyboard and has an accessible name inside the table structure.
5. Confirm each test fails when the corresponding fix is reverted — in particular, swapping the body's slot-4 content back to the postings toggle under a "Units" header must fail.

# Scope journal filter persistence per ledger instead of leaking it across ledgers

Source: continuous dashboard QA, 2026-10-04.
Pillar: A2 — switching ledgers must not silently apply another ledger's journal filters and hide entries.

The journal page persists directive-type, subtype, Metadata, and Postings filter state in global `localStorage` keys (`journal.directiveTypes`, `journal.transactionSubtypes`, `journal.documentSubtypes`, `journal.customSubtypes`, `journal.showMetadata`, `journal.showPostings`), so flag/type selections made on one ledger's journal are active when any other ledger's journal opens.

Root cause: `dashboard/src/features/journal/pages/journal-page.tsx:75` claims "persisted per ledger in localStorage" but keys carry no ledger id, and `useLocalStorageState` (`dashboard/src/common/hooks/use-local-storage-state.ts:62`) uses keys verbatim. The page already computes `ledgerId` (line 65) and never uses it for the keys.

Repro: on `/ledger/open_ledger/example/journal` press the Pending (and/or Cleared) flag; open any other ledger's `/journal` — the same flags arrive pressed. Reload preserves them (by design); the cross-ledger carryover is the defect.

Acceptance: each ledger's journal opens with its own persisted filter state (or defaults on first visit); changing filters on one ledger never changes another's; reload still restores the current ledger's state. The account journal already uses mount-local state and is unaffected. Add a regression test for per-ledger keying, run the dashboard checks, and ship.

Scope: dashboard journal page only (BQL history is global by design and out of scope). Estimated under one hour.

---

**Resolved 2026-10-04** — `journal-page.tsx` now keys every persisted filter as `journal.<ledgerId>.<filter>` and remounts `JournalContent` per ledger (`key={ledgerId}`), since `useLocalStorageState` reads its key only on mount; both halves are required (the regression test fails with either removed). `journal-filter-persistence.test.tsx` switches ledgers on a mounted page and checks each keeps its own selections and that a remount restores them. Selections saved under the old global keys are no longer applied, so each ledger starts from defaults once. Dashboard format, lint, 4,953 tests and build passed. Shipped in `3d6af2d7` (`dashboard`).

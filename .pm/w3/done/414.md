# `bea add transaction` with a currency-less cost spec (`{}`, `{2026-03-01}`) writes the entry, then crashes and exits 1

**Severity:** major. **Estimate:** 30–45 minutes. **Owner:** cli. **A1:** an
agent selling a lot with the idiomatic `{}` gets exit 1 and a traceback saying
"engine did not answer", so it retries — and every retry appends another sale.
Regression of the `w3/240` CostSpec serialization fix (`0d47a757`).

Found 2026-09-25 by CLI QA (`qa-find-bugs-cli`) against `main` HEAD `8cd9732b`,
`uv run bea` 0.3.0 (checkout engine), Darwin 25.5.0 arm64, isolated
`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, stdin closed. Synthetic ledger only.

## Repro

```sh
cat > main.bean <<'B'
option "operating_currency" "USD"
2026-01-01 open Assets:Brokerage
2026-01-01 open Assets:Cash USD
2026-01-01 open Equity:Opening USD
2026-01-01 * "Fund"
  Assets:Cash  1000.00 USD
  Equity:Opening
2026-03-01 * "Buy"
  Assets:Brokerage  10 HOOL {100.00 USD}
  Assets:Cash  -1000.00 USD
B
cp main.bean pristine.bean
bea --file "$PWD/main.bean" add transaction --date 2026-03-02 \
  -p 'Assets:Brokerage -5 HOOL {}' -p 'Assets:Cash 500.00 USD' Sell
echo exit=$?     # exit=1
diff pristine.bean main.bean   # the Sell entry WAS appended
```

stderr: `Error: The Beancount engine did not answer 'bea-engine add … --type
transaction --request -' (exit 1).` followed by a Rich traceback ending
`TypeError: Object of type type is not JSON serializable`. `--json` gives
the same as `{"error":{"category":"validation","exit_code":1,…}}` with the
traceback lines in `details`. Running it three times appends three sales;
`bea check` stays green, so nothing flags the duplicates. `{2026-03-01}`
(date-only lot selector) behaves identically. Controls: `{100.00 USD}` and
`{USD}` succeed with exit 0 and the file changes once.

Second symptom, same function: a total cost reports the wrong number.
`-p 'Assets:Brokerage 2 HOOL {{250.00 USD}}' -p 'Assets:Cash -250.00 USD'`
succeeds, but `data.directive.postings[0].cost` is
`{"number":"0","currency":"USD",…}`. Feeding that directive back into
`bea add transactions --from -` (the documented round-trip guarantee in
USAGE.md "Investment postings and metadata") fails with
`Transaction does not balance: (-250.00 USD)`.

## Root cause

`cli/src/bea_engine/protocol.py` `_jsonable` (lines ~175–190): for a
`CostSpec`, `number` falls back to `number_per` and the dict is built as
`{"number": _jsonable(number), "currency": currency}` — `currency` is **not**
passed through `_jsonable`, so a parser `MISSING` sentinel (a class) reaches
`json.dumps`. The encode runs in `answering()` after the `yield`, i.e. after
`write.append` already replaced the file, and outside the `try`, so no error
envelope is produced. For `{{250 USD}}` the parser yields `number_per=0,
number_total=250`; the branch reports `number_per` and drops the total. The
frontend mirror `cli/src/cli/output.py` (~343–348) has the same shape.

## Fix

- Serialize a `CostSpec` explicitly: MISSING → `null` for every field; a
  total-only spec reports the per-unit equivalent (or a `number_total`
  field that `add transactions` accepts) so the round-trip holds.
- Build the answer (or at least prove it serializes) **before**
  `write.append`, so a response failure can never follow a committed write.
- Frontend: an engine that dies without an envelope during a write command
  should be reported as exit 4 ("outcome unknown — inspect the file before
  retrying"), per the exit-code table, not exit 1.

## Acceptance

- The repro exits 0, appends once, and `data.directive` carries `cost` with
  nulls for the unspecified parts; `{2026-03-01}` likewise.
- The `{{250.00 USD}}` response round-trips through `add transactions`.
- Regression tests for both, plus one proving no write happens when the
  answer cannot be built.

**Resolved 2026-09-27** — Fixed. A CostSpec is serialized field by field with `null` for every unspecified part and the total under its own `number_total` key (`_cost_spec_jsonable`, in both `cli/src/bea_engine/protocol.py` and its frontend mirror `cli/src/cli/output.py`), and `bea-engine add --type transaction` encodes its answer *before* `write.append`, so an answer that cannot be built refuses instead of following a committed write. `{}` and `{2026-03-01}` exit 0 and append once; `{{250.00 USD}}` round-trips back through `add transactions`. A write whose engine dies without an envelope is now reported as exit 4, outcome unknown. Shipped through [w3/m49](./done/m49/README.md) (`cli`), in the working tree on top of `8cd9732b` and pending review.

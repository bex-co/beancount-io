# SIGTERM/SIGHUP to a writing `bea` leaves full-size ledger copies behind; only SIGINT cleans up

**Severity:** minor (disk litter in the user's books, no data loss). **Owner:**
cli. **Estimate:** 20–30 minutes. **A1:** the signal-forwarding teardown exists
precisely so a supervisor, container stop or `timeout` cannot orphan a staged
copy of the ledger — but the engine has no SIGTERM/SIGHUP handler, so the
forwarded signal kills it before any `finally` runs and the copies stay.

Found by continuous CLI QA 2026-09-26, `bea` 0.3.0 at HEAD `8cd9732b`, Darwin
26.5.1 arm64, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, closed stdin,
synthetic ledger, no network or account. Run the executable directly (a `uv run`
wrapper is not signal-transparent and hides this).

## Repro

```sh
# a ledger big enough that the write takes seconds (~10 MB, 120k transactions)
python3 - <<'EOF'
import datetime, pathlib
L=['option "operating_currency" "USD"\n','2020-01-01 open Assets:Bank USD\n',
   '2020-01-01 open Expenses:Food USD\n','2020-01-01 open Equity:Opening USD\n',
   '2020-01-01 * "open"\n  Assets:Bank  1000000.00 USD\n  Equity:Opening\n']
d=datetime.date(2020,1,2)
for i in range(120000):
    L.append(f'{d.isoformat()} * "p{i}"\n  Assets:Bank  -1.00 USD\n  Expenses:Food  1.00 USD\n')
    if i%40==39: d+=datetime.timedelta(days=1)
pathlib.Path('books/main.bean').write_text(''.join(L))
EOF

# start the write, send SIGTERM a few seconds in (not from the terminal — to the pid)
bea --file books/main.bean add transaction --date 2024-12-31 -n term \
    -p 'Assets:Bank -2.00 USD' -p 'Expenses:Food 2.00 USD' &
sleep 6; kill -TERM $!; wait

ls -a books/
# .bea-b_3efr6j.tmp  .bea-tofh15_k.tmp  main.bean   <-- two ~10 MB copies left
du -sh books/                                       # ~30 MB for a 10 MB ledger
```

`kill -HUP` behaves the same. `kill -INT` at the same point leaves **no** stray
files. Reproduced at several delays for both `bea add transaction` and
`bea import --apply`; sometimes a `..bea-*.tmp.picklecache` sidecar (~24 MB)
joins them. The ledger itself is never damaged in any of these runs.

## Expected

Any forwarded termination signal unwinds the engine's context managers, so the
`.bea-*.tmp` candidate and its pickle sidecar are gone when the process exits —
the behavior `cli/src/cli/engine/launch.py:337-365` and the design note at
`cli/src/bea_engine/ledger/write.py:181-196` both promise for everything except
SIGKILL.

## Actual

`bea_engine` installs no signal handlers (`grep -rn signal src/bea_engine/` finds
only comments). SIGINT works by accident: CPython turns it into
`KeyboardInterrupt`, so `candidate_file`'s `finally` runs. SIGTERM and SIGHUP keep
their default disposition and terminate the interpreter outright. The leftovers
are only removed by `sweep_abandoned_candidates` on a *later write to the same
directory*, and only once they are an hour old — a ledger that is never written
again keeps them forever.

## Fix

In the engine entry point (`cli/src/bea_engine/__main__.py`), install handlers for
SIGTERM and SIGHUP that raise `SystemExit` (or re-raise `KeyboardInterrupt`) so
`ExitStack`/`finally` blocks unwind, then exit with `128 + signum`. Restore
default disposition before exiting so the reported status stays truthful.
Regression coverage: a test that SIGTERMs a slow write and asserts the target
directory contains no `.bea-*` / `..bea-*` entry afterwards, alongside the
existing SIGINT case.

## Dedupe

Not w3/435 (SIGINT during `format -i` can zero the ledger — a different command,
a different failure, and `format -i` does not use the candidate/`finally` path at
all). Not w3/434 (missing write lock). `git log -S _forwarding_teardown` shows the
forwarding was added for exactly this scenario; the engine half was never built.

---

**Resolved 2026-10-02** — The engine entry point now handles SIGTERM and SIGHUP by raising `SystemExit(128 + signum)`, letting write context managers remove staged candidates and their pickle sidecars before exit. Prior handlers are restored; frontend signal status and SIGINT behavior remain intact. Shipped in `9623bb07` (`cli`). Real add/import regressions synchronize on staged validation: all four TERM/HUP cases failed before the fix and both SIGINT controls passed. Two direct-engine cases also failed before the fix and now report 143/129. The focused signal/cleanup suite passed 54 tests; `make check-all` passed 2,464 tests with one skip. Tests use isolated synthetic ledgers, verify unchanged bytes and helper exit, and require no external account. Public-tree secret scan passed.

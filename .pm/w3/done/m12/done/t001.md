## Objective

Make the registered Monaco shortcut execute the latest editor text through the same submission path as the button.

## Context

- See the major finding: Cmd+Enter sends select * from accounts after editing to select account limit 2 or 3.
- onMount registers a callback closing over the initial handleSubmit/queryText.

## Steps

1. Give keyboard and button actions one submission path that takes current text; for example, read editor.getValue in the registered command and pass it to that path.
2. Preserve trimming, URL synchronization, execution tracking and request deduplication.
3. Add a regression that edits a mounted editor before invoking its registered command; verify the actual submitted variables.

- `dashboard/src/features/bql/pages/index.tsx`

## Acceptance criteria

- [ ] The tested edited query is sent by both the button and shortcut, once per action.
- [ ] Repeated edits continue to use the latest text, rather than merely fixing the first edit.
- [ ] Empty text remains a no-op and the correct platform shortcut is registered.

## Out of scope

- Backend BQL engine changes or changes to unrelated Monaco consumers.

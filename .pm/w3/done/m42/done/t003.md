The only other date input in the app is a native `type="date"` API-key expiry field (browser-rendered, ISO value semantics) — not a US-order typed field, out of scope.
- Docs/skills grep (`skills/`, `docs/`, dashboard README/CLAUDE.md) for date-format guidance: nothing teaches `MM/DD/YYYY` as the app's input format; archived m24 records intentionally untouched.
- No API, schema, or stored-format change: the parser still publishes a plain `Date`, the ledger keeps ISO dates; this is an input-parsing change only.
- Browser: authenticated in-browser verification was not possible in this environment (no QA credentials on disk, no Docker for a local stack, every ledger route redirects signed-out sessions to login).

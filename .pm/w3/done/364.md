# `bea doctor missing-open` exits 0 with no output when postings hit a pre-closed account

**Severity:** minor. **Estimate:** 20–40 minutes. **Owner:** cli. **A1:** an
agent that runs `doctor missing-open` after `check` reports “inactive account”
gets exit **0** and empty stdout — so it assumes opens are complete while
`check` still fails. When both unknown and inactive accounts exist, only the
never-opened account is printed; the inactive one stays silent.

Found 2026-09-16 by continuous CLI QA ([c1070 hunt](894bd956-9e0f-41a0-9d4d-c72df9d14331)),
HEAD `cf6f58a1`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Evidence:
`cli/tmp/qa-20260915/c1070/`.

## Repro

```sh
# Checking opened then closed; late txn posts to it
bea --file closed-only.bean check
# exit 1 — Invalid reference to inactive account

bea doctor missing-open closed-only.bean
# exit 0 — (no output)

# Mixed unknown + inactive: prints only open Equity:Open
```

## Expected

Surface inactive-account cases (or exit nonzero / document never-opened-only)
so agents do not treat empty `missing-open` as “opens fixed.”

## Actual

Upstream `bean-doctor missing-open` only emits opens for accounts with no
`open` at all; pre-closed accounts are omitted. Wrapper keeps exit 0.

## Fix

Report inactive references (or nonzero when they remain). Regression: both
fixtures name `Assets:Bank:Checking`; mixed still prints `Equity:Open`.

## Dedupe

Not w3/345, 276, 243. No open note on `missing-open` silence for pre-closed
accounts.

# `bea add transactions --from` silently drops unknown transaction fields, so a `narration` typo writes a blank payee/narration

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** cli. **A1:** an
agent generating bulk JSON can misspell `narration` as `narrative` (or
`payee` as `payer`) and get a clean exit with a ledger line `2024-03-20 *`
and no text, while the same extra key on a posting is rejected.

Found 2026-09-15 by continuous CLI QA against `main`, HEAD `63a1255c`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated `BEA_CONFIG_DIR` /
`XDG_CACHE_HOME`. Synthetic fixtures only.

## Repro

```sh
cat > rows.json <<'EOF'
[{"date":"2024-03-20","narrative":"Should be narration","postings":[
  {"account":"Expenses:Food:Groceries","units":{"number":"1.00","currency":"USD"}},
  {"account":"Assets:Bank:Checking"}
]}]
EOF
bea --json --file main.bean add transactions --from rows.json
echo exit=$?
# stdout: {"data":{"written":1,"rejected":[]},...}  exit 0
```

Ledger appendix:

```text
2024-03-20 *
  Expenses:Food:Groceries                   1.00 USD
  Assets:Bank:Checking
```

Working control — extra posting field is rejected (exit 1):

```text
Row 1, postings.0.foo: Extra inputs are not permitted
```

`unknown: true` on the transaction object is also accepted and ignored
(`written: 1`).

Evidence: `cli/tmp/qa-20260915/evidence/c3-typo.out`, `c3-extraf2.err`,
fixture `cli/tmp/qa-20260915/fixtures/typo.bean`.

## Expected / actual

`cli/docs/USAGE.md:541-543` rejects unknown **posting** fields and says
schema errors name a row, field path, and example. The documented example
uses `"narration": "Groceries"`. Expected: the same extra-forbid policy on
the transaction object (and other bulk/single-add directive models), so
`narrative` is `Row 1, narrative: Extra inputs are not permitted` and
nothing is written.

Actual: `Posting` sets `extra="forbid"`; `TransactionDirective` does not, so
Pydantic ignores unknown keys. A successful write is indistinguishable from
a correctly empty narration.

## Root cause

`cli/src/bea_engine/ledger/models.py:44` — `Posting.model_config = extra="forbid"`.
`TransactionDirective` at `:73-82` has no `model_config`; Pydantic v2
default is ignore. Other directive models in the same file (`OpenDirective`,
…) share that default.

## Fix

Set `extra="forbid"` on `TransactionDirective` and the other directive
models used as JSON input (keep `source` allowed on list output if that
round-trips through the same class — if list JSON is reused as add input,
either strip `source` in the add path or allow only that extra). Regression:
`narrative` / unknown top-level keys exit 1 with a field path; posting extras
stay rejected; a complete documented example still writes.

## Dedupe

No `.pm` hit for extra-forbid / unknown bulk fields. Not w3/223 (tag parse
messages). USAGE’s posting-only wording is the current contract; this is the
inconsistency, not a docs-only nit.

## Unverified

Single `bea add transaction` has no JSON object body. Other directive add
subcommands’ JSON envelopes. Pydantic `source` on list→add reuse.

---

**Resolved 2026-09-15** — directive models now use extra=forbid, so bulk JSON typos like narrative are rejected with a field path and nothing is written. Covered by cli/tests/test_bulk_transaction_unknown_fields.py. Shipped with this board close.

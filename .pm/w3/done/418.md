# `bea cloud ledger show` on a missing ledger says "Not authorized … Run 'bea cloud login'" while delete says "Ledger not found"

**Severity:** minor. **Estimate:** 30–45 minutes. **Owner:** cli +
backend-v2. **A1:** a signed-in agent that mistypes a ledger name (or checks
one it just deleted) is told to log in again, which cannot help, and gets
exit 3 instead of the not-found exit 1 that delete returns for the same name.

Found 2026-09-25 by CLI QA against `main` HEAD `8cd9732b`, `uv run bea` 0.3.0,
production API `https://api.v3.beancount.io`, QA account signed in through
`bea cloud login` (`cloud status` exit 0). Only a disposable
`qa-20260925-cli1` ledger was created and deleted.

## Repro

```sh
bea --json cloud ledger create qa-20260925-cli1          # exit 0
bea --json --yes cloud ledger delete <owner>/qa-20260925-cli1   # exit 0
bea --json cloud ledger show <owner>/qa-20260925-cli1
# exit 3 {"category":"auth","message":"Not authorized (Authorization denied). Run 'bea cloud login'."}
bea --json --yes cloud ledger delete <owner>/qa-20260925-cli1
# exit 1 {"category":"validation","message":"Ledger not found"}
bea --json cloud ledger show <owner>/never-existed       # same exit 3 as above
bea --json cloud status                                   # exit 0 — the credential is fine
```

## Root cause

- Server: `backend-cluster/backend-v2/src/server/api/authorization/authorization-service.ts`
  conceals denials as `404 Ledger not found` (`LEDGER_NOT_FOUND_CONCEALMENT`)
  for administration/collaborator actions, but the content-read actions
  (`LEDGER_METADATA_READ` etc. via `ledgerContentReadRequirement()`) answer a
  missing ledger with `403 Authorization denied`.
- CLI: `cli/src/cli/errors.py` `error_from_status` maps 401 **and** 403 to the
  same "Run 'bea cloud login'" remedy, although a 403 with a valid credential
  is not fixed by logging in.

## Fix

Apply the same not-found concealment to ledger read actions so show and
delete agree (REST, GraphQL and MCP share the service, so keep parity), and
give 403 its own CLI wording ("this account cannot access '<owner>/<name>',
or it does not exist") while 401 keeps the login remedy.

## Acceptance

`cloud ledger show` of a missing or inaccessible ledger returns the same
status and message as `delete`, and no 403 message suggests re-login while
`cloud status` succeeds; tests on both sides.

## Dedupe

`w5/012` (done) made the 401/403 remedy source-aware for `BEA_TOKEN`;
`w1/006` (done) aligned revoked-token wording. Neither covers a valid
credential receiving 403 for a missing ledger.

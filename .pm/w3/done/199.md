# Keep ledger rows reachable in the drawer at enlarged text sizes

**Severity:** minor. **Estimate:** 45–60 minutes. Package: mobile. A2 — users who need enlarged text must still be able to choose their ledger from the primary navigation.

Environment: 2026-09-13, main `84231f9c`, native development build 1.20260906.47 (47), Metro localhost:8081, iPhone 17e / iOS 26.5, English, light appearance. Signed-in QA account with one existing owned ledger and the public `open_ledger/minimax` selected. No ledger writes.

Repro:
1. Set iOS text size to `accessibility-extra-extra-extra-large`, terminate/relaunch the app, and open the Home drawer using Open menu.
2. Dismiss the development warning banner. The top Ledgers / New controls wrap, and the pinned Browse ledgers / Merchants / Settings controls occupy most of the drawer. Only an owner header is visible in the ledger list; no ledger row is visible.
3. Swipe upward inside the narrow ledger list four times. Its owner header changes to OPEN_LEDGER, but the current minimax row remains hidden beneath the sticky header.
4. Terminate/relaunch and repeat opening the drawer: same result (initial fresh PID 35916; repeat PID 39369).
5. Restore `large`, relaunch (PID 42510), reopen: both ledger rows and the footer fit. The public minimax row is visible and reports `is_hittable: true`.

Expected: the user can scroll to, read, and tap each ledger at every supported text size, while retaining access to the other navigation actions. Actual: the list viewport is only 70.33 points high (y=246), less than its 84.67-point sticky owner header. Rows are 102 points high. Before scrolling, the public minimax row exists at y=524.33 but reports `is_hittable: false`; after four real native swipes the list reaches the last group, whose sticky header still fills the viewport. Default-size minimax is 48 points high and hittable at y=278.67. This is a local layout failure, not an empty response or a loading state.

Root cause: `mobile/src/components/ledger-drawer/ledger-drawer.tsx:280` gives only the SectionList `flex: 1`, while the top section header and bottom `navSection` remain outside that scrolling region. Uncapped section/action text wraps and expands these siblings. The SectionList at line 659 enables sticky headers; at maximum size its owner header exceeds the remaining viewport, covering the rows even as they scroll. The pinned layout was introduced in `e1918c0c`; no later drawer change repairs it.

Fix: adapt the drawer to the available vertical space and font size so a complete ledger row can be exposed and selected. Use a scrollable overall layout or an equivalent large-text arrangement when pinning would consume the list; do not leave a sticky header taller than the usable list. Preserve standard-size pinned actions, stable ledger ordering/selection, owner grouping, conditional search and its reset-on-close, and existing share actions. Do not globally disable font scaling. Add focused coverage for the constrained-height layout and recheck the native swipe/select journey with maximum text.

Blast radius: one LedgerDrawer hosted by LedgerDrawerProvider in `mobile/app/(app)/(tabs)/_layout.tsx:248`, opened by Home, Accounts, Transactions, Reports, and Files headers. Native reproduction used Home. Default text is the working control. Ten-plus ledger search, empty/error/refresh states, keyboard, landscape, other locales, VoiceOver navigation, Android, and physical devices were not exercised in this finding; preserve those states when adjusting layout. No GraphQL/REST/MCP behavior change is required.

Dedupe: searched all open and done queues for drawer/font/text/height/sticky/pinned terms and scanned every open milestone title. Completed 174 concerns Home chart height; 180/181 concern search/merchant rows; open 191 concerns chart touch stranding the drawer. None covers the newly pinned drawer list becoming smaller than its sticky headers. No chart gesture was used during this reproduction.

# `bea report -x` accepts any string: a typo (`at-cost`, `usd`) becomes a fake currency and a units report exits 0 in a terminal

**Severity:** minor. **Estimate:** 15–25 minutes. **Owner:** cli. **A1:** a
typo in `--conversion` does not read as a usage error; in a terminal the user
gets an unconverted report headed `Valuation: at-cost`.

Found 2026-09-26 by CLI QA (`qa-find-bugs-cli`) against `main` HEAD
`8cd9732b`, `uv run bea` 0.3.0, Darwin 26.5.1 arm64. Synthetic ledger with
USD, EUR and a HOOL lot.

## Repro

```sh
bea --file main.bean report balance-sheet -x at-cost      # under a PTY
bea --file main.bean report overview -x usd               # piped
```

PTY: exit 0, `Valuation: at-cost`, stderr-banner lines
`USD has no at-cost price at any date; shown in units`, the tree in units,
and `Net Worth: Unavailable at-cost`. Piped: exit 1 with
`Missing prices for EUR, HOOL, USD → usd … USD has no usd price at any date`.
`bea balance -x …` shares the path.

Expected: USAGE says invalid report inputs exit 2. `-x` should accept
`units`, `at_cost`, `at_value`, or a syntactically valid Beancount currency
(uppercase, e.g. `^[A-Z][A-Z0-9'._-]{0,22}[A-Z0-9]?$`); anything else is a
usage error naming the three keywords (and suggesting `at_cost` for
`at-cost`, `USD` for `usd`). A valid currency the ledger never names is still
allowed, as documented.

## Root cause

`cli/src/cli/commands/report.py:165` only refuses blank values
(`refuse_blank_filter`) and forwards the string at `:183`;
`cli/src/bea_engine/report.py:349` uses it as the conversion target without
validation, so the missing-price path explains a typo as missing prices.

## Acceptance

- `-x at-cost`, `-x usd`, `-x 'US D'` exit 2 in TTY, piped and `--json`
  modes; `-x USD`, `-x EUR`, `-x GBP` (unpriced, documented partial path),
  `units`, `at_cost`, `at_value` unchanged. Regression in `cli/tests/`.

## Dedupe

w3/328 (done) refused empty `-x`; w3/241/357 concern valid keywords. No item
covers malformed conversion values.

**Resolved 2026-10-02** — Reports and balances reject malformed conversion values with usage exit 2 before loading the ledger, including terminal, piped, JSON, and direct-helper calls. The diagnostic lists the three modes and suggests corrected spellings where possible. Currency validation uses the actual Beancount lexer, preserving single-letter, slash-prefixed, and long symbols without a registry or arbitrary length cap; valid unpriced targets retain the existing partial-valuation policy. Shipped in `a6c0231b` (`cli`). Triage reproduced terminal success for `at-cost` and JSON missing-price exit 1 for `usd`. Nine real CLI and twenty helper regression cases failed before the fix; fifteen mode, currency, and pricing-policy controls passed. All 60 focused tests passed after the single-letter lexer distinction was corrected. `make check-all` passed with 2,377 tests and one skip; source review and the public-tree secret scan passed. Help, generated reference, and usage documentation were updated. All fixtures were synthetic local ledgers.

# `bea query` advertises a `balances` table (`.tables` / `.describe`) but `SELECT … FROM balances` is a syntax error

**Severity:** minor. **Estimate:** 45–60 minutes. **Owner:** cli (beanquery
surface / docs). **A1:** an agent that discovers tables via `.tables` then
writes `SELECT account, amount FROM balances` gets a syntax error pointing at
`FROM balances`, while the undocumented bare shell command `balances` works.

Found 2026-09-15 by continuous CLI QA against `main`, HEAD `28c90de8`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
bea --file main.bean query '.tables'
# lists: accounts, balances, commodities, …

# PTY / interactive:
#   .describe balances
#   table balances: meta, date, account, amount, tolerance, discrepancy

bea --file main.bean query "SELECT * FROM balances"
bea --file main.bean query "SELECT account FROM balances"
# exit 2 — syntax error caret under FROM balances

bea --file main.bean query balances
# exit 0 — account / SUM(position) table (shell command, not SELECT)

# Quoting reaches the real table env (balance assertions), which discovery
# already describes — so the table exists; only the unquoted keyword fails:
bea --json --file main.bean query 'SELECT * FROM "balances" LIMIT 3'
# exit 0 — columns date, account, amount, tolerance, discrepancy
```

Working controls: `SELECT * FROM prices|postings|transactions|entries|…`
succeed. See also w3/247: `FROM accounts` runs but binds to **postings**
(separate bug). Reconfirmed 2026-09-16 continuous CLI QA (`2c3381fd`).

## Expected

Either:

1. `SELECT … FROM balances` runs and returns the described columns, or
2. `.tables` / `.describe` do not list `balances` as a SQL table (document it as
   a shell command only), and the syntax-error hint names that fact instead of
   sending agents back to the interactive shell.

## Actual

Discovery APIs treat `balances` like other tables; the SELECT parser rejects
`FROM balances`. Agents following `.tables` hit a dead end.

Likely upstream beanquery (managed engine 0.2.0) with bea owning the discovery
UX and error wrapping. Confirm in engine beanquery sources before choosing
fix vs document.

## Fix

Prefer making `FROM balances` work if the table env exists; otherwise remove or
relabel it in `.tables`/`.describe` output (or bea’s help) and teach the error
path to say “use the `balances` command, not FROM balances”. Regression: the
repro SELECT either returns rows or a non-misleading usage error; bare
`balances` stays green.

## Dedupe

Not w3/234 (`--json` forcing format json on dot-commands). No open note covers
`FROM balances` vs `.tables` mismatch.

---

**Resolved 2026-09-16** — unquoted `FROM balances` is rewritten to `FROM "balances"` so SELECT hits the balance-assertions table. Covered by `cli/tests/test_query_reserved_tables.py`. Shipped with this board close.

# `bea add balance` without `--pad-from` still advises opening the account “to use --pad-from”

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** cli. **A1/A2:**
reconcile flows that assert a balance on an unopened or not-yet-active account
get recovery text that names `--pad-from` even when that flag was never passed,
so agents chase the wrong flag instead of `bea add open` / a later assertion
date.

Found 2026-09-15 by continuous CLI QA against `main`, HEAD `cff26c03`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated `BEA_CONFIG_DIR` /
`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`. Synthetic fixtures only.

## Repro

```sh
# pristine ledger with Assets:Bank:Checking / Assets:Cash only — no Savings
bea --json --file main.bean add balance \
  --date 2024-03-15 --account Assets:Bank:Savings --amount '500 USD'
```

Exit 1 details include the correct unknown-account hint **and**:

```text
Review the assertion date: Assets:Bank:Savings must be open on an earlier day
to use --pad-from. Balance assertions run at the start of the day.
```

Same wording when the account exists but opens later than the assertion day:

```sh
bea --file main.bean add open --date 2024-06-01 --account Assets:Bank:Savings
bea --json --file main.bean add balance \
  --date 2024-03-15 --account Assets:Bank:Savings --amount '500 USD'
# still: "… must be open on an earlier day to use --pad-from."
```

Working control: a wrong amount on an already-active account does **not**
mention `--pad-from` (date / missing-txn hint only). Passing `--pad-from` when
the account is inactive correctly fails with “Pad accounts must be active…”.

## Expected

When `--pad-from` was not on the command line, recovery should say the account
must be open on an earlier day for the balance assertion (and point at
`bea add open` / moving the date). Mention `--pad-from` only on the
`--pad-from` path, or phrase neutrally without implying the user already chose
that flag.

## Actual

```text
cli/src/bea_engine/ledger/write.py — _balance_recovery_hints
  if balance.account not in active:
      return [
          f"… {balance.account} must be open on an earlier day to use --pad-from. …"
      ]
```

The helper never receives whether the write used `--pad-from`, so the inactive-
account branch always names that flag.

## Fix

Thread a `pad_from: bool` (or omit the flag name) into `_balance_recovery_hints`
and branch the inactive-account sentence. Regression: plain `add balance` on an
unknown/inactive account must not say “to use --pad-from”; `add balance
--pad-from` on the same setup may still mention pad requirements.

## Dedupe

Not w3/done/224 (matching amount + `--pad-from` circular unused-pad hint —
already fixed). No other open `.pm` note covers inactive-account wording on the
plain balance path.

---

**Resolved 2026-09-16** — inactive-account balance recovery no longer says “to use --pad-from”; it points at open / later date instead. Covered by `cli/tests/test_balance_inactive_hint.py`. Shipped with this board close.

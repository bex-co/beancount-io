# Budget writes were broken: the ledger service never implemented `custom`

**Fixed 2026-08-27.** Adding a budget failed on every client with
`entry 0: Cannot read properties of undefined (reading 'type')` (HTTP 400 from
the ledger service at `POST /entries/{owner}/{repo}/bulk`). Found while trying
to verify `w3/m1` and `w3/m2` in the app; reproduced from a direct GraphQL
`bulkEntries` call and from the dashboard's own **Add Budget** dialog, so it was
never mobile-specific.

## Root cause

`idl/beancount-ledger.openapi.json` is the authority, and it defines **no
`budget` entry type**. `EntryAddBulkEntriesRequest`'s discriminator maps ten
types — transaction, balance, commodity, price, note, open, close, event,
**custom**, document. A budget travels as `custom` with `type: "budget"` and
account/interval/amount carried as `values`, each tagged by **`kind`**
(`account` / `text` / `number` / `amount`, per `CustomDirectiveCreate`).

- `backend-v2`'s `ledger-entry-service.ts` emitted exactly that. **Conformant.**
- `ledger`'s `entry-build.ts` `toDirective` had **no `case "custom"`**. It had a
  `case "budget"` matching no wire type, expecting `{account, interval, amount}`
  and tagging values by `type` instead of `kind`. **Non-conformant.**

An unhandled discriminant in an exhaustive switch returns `undefined`, so
`directiveToText(undefined)` threw.

## Fix

`backend-cluster/ledger`:

- `foundation/ledger-api-types/ledger-entry-input.ts` — added `CustomInput` and
  `CustomValueInput` (the `kind`-tagged wire vocabulary) and a `custom` variant.
- `foundation/rustledger/entry-build.ts` — added `case "custom"`, plus
  `toTypedValue` mapping the wire's `kind` tags onto the engine's `type` tags
  (`text`→`string`; flat `amount` → nested `value`). The unreachable `budget`
  case is left in place with a note saying the wire cannot produce it.

## Why CI was green

Each side had a unit test pinning its own half and neither crossed the
boundary: the ledger's `entry-build.test.ts` fed the invented
`{ type: "budget" }` shape, while backend-v2's
"should add a budget entry as a custom directive" asserted the `custom` shape it
sends. Both passed while the integrated path was broken.

Three tests now cover the real contract, including one asserting that a
wire-shaped `custom` budget renders byte-identically to the `budget` golden.

## Verified end to end

On `deploy/docker-mac` with the ledger container rebuilt: `bulkEntries` with two
BUDGET entries returned "Added 2 entries successfully"; the file received
`2026-01-01 custom "budget" Expenses:FoodAndDining "monthly" 300.00 USD` and the
quarterly sibling; and the dashboard's Add Budget dialog added a third.

## Follow-up

`w3/m1/t013` and `w3/m2/t009` can now be attempted for real — both were blocked
on this. The ledger's dead `budget` case could be removed once nothing
in-process builds the union directly.

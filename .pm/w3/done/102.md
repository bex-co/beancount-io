# Valid BQL block comments fail in hosted queries

**Minor · backend-cluster/ledger · 50–60m.** A1/A2: a query annotated with
standard BQL block comments should run in the dashboard and agent query surfaces.

## Reproduce and expected result

On https://beancount.io/ledger/open_ledger/example/query?lang=en, execute:

```sql
SELECT account FROM accounts ORDER BY account LIMIT 2
```

It returns Assets:US:BofA and Assets:US:BofA:Checking. Add a leading
`/* qa comment */` line and execute again. The dashboard shows an invalid-input
error; GraphQL returns HTTP 200 with BAD_USER_INPUT and
`Invalid BQL query: syntax error at position 0: found '/' expected identifier`.
An inline comment after SELECT and a trailing comment also fail. Removing the
comment restores the same two rows. A quoted `'/* literal */'` result succeeds.

Repeated on 2026-09-09 in fresh 1440×1000 and 390×844 Chrome 152.0.7977.77
contexts, English/light, authenticated QA reader of public synthetic
open_ledger/example. Both documents return 200. Ten exact-response UI executions:
six comment failures and four successful plain/quoted controls; no page errors
or mutations. REST POST /api-gateway/v1/ledgers/open_ledger/example/query with
JSON {query} independently returns 200 for the plain query and 400 BAD_USER_INPUT
for the leading comment at each width. The submitted text preserves the comment.

Expected: comments outside quoted text act as whitespace. The
[upstream BQL grammar](https://github.com/beancount/beanquery/blob/master/beanquery/parser/bql.ebnf)
declares block comments. Actual Python beanquery 0.2.0 on a three-directive,
synthetic local ledger accepts leading, inline, trailing, multiline, adjacent,
multiple, Unicode and CRLF block comments, with identical rows. This is verified
execution, not an assumption that all SQL syntax belongs to BQL.

Evidence in dashboard/tmp/qa-20260907-w3-loop/:
bql-block-comment-live-evidence.json, bql-comment-local-control.json,
bql-comment-python-control.json, bql-block-comment-{1440,390}.png.
Source/fetched main 7f4b6190; deployed SHA unverified. Both actual WASM 0.21.0
and the current pin 0.24.0 reject the basic block-comment matrix, so the recent
upgrade alone cannot fix it. Temporary browser contexts closed; no ledger changed.

## Root cause and bounded fix

dashboard/src/features/bql/pages/index.tsx:216–220 configures block comments
and :87–93 sends the editor query. Ledger service
src/features/ledger/service/ledger-shell-service.ts:85–105 passes it unchanged
to queryLedgerFilesResult from both queryShell and queryShellText. In
src/foundation/rustledger/engine.ts:626–698 it reaches the WASM Ledger.query.
Upstream rustledger 0.24.0 parser.rs:179–188 skips whitespace only.

Add a small shared compatibility wrapper for both ledger shell modes that treats
valid outside-string block comments as whitespace before the existing engine.
Keep quoted bytes, token separation and line boundaries intact; retain invalid
query rejection through assertQuerySucceeded. Do not copy or fork an upstream
parser. A scratch-only candidate already matches all 13 successful Python
results and preserves all seven invalid outcomes in a 20-case matrix on 0.24.0.
It is research evidence, not a production implementation.

Include single/double quoted comment text, adjacent single quotes and a
backslash immediately before a closing quote. Current BQL treats backslashes
as ordinary bytes; a generic SQL/JavaScript escape scanner would change meaning.
Unterminated comments, comment-only input and malformed queries must remain
errors. Leading --, # and ; controls also fail in the Python oracle; support for
those syntaxes is outside this finding. Preserve UTF-8 error-offset accounting
when substituting whitespace.

Blast radius: search found two production domain calls to
queryLedgerFilesResult, the shell methods above. Both are shared behind
backend-v2 GraphQL queryShell/queryShellText, REST JSON/text and MCP
runBqlQueryStructured/runBqlQuery. Gateway ledger-shell-service.ts:44–128 and
rest/v1/query-handler.ts:48–67 route to these methods; ai-agent/api/mcp-tools.ts:
504–518 binds the MCP tools through ai-agent/tools/bql-query-tool.ts. Keep one
ledger-package implementation and preserve authorization and result envelopes.

Acceptance: the exact browser and REST reproduction returns the plain query's
rows at both widths; meaningful service tests cover both shell modes and the
20-case compatibility/failure matrix. Quoted text must remain byte-for-byte
identical. MCP and REST text rendering are traced in source but not live-probed;
verify their existing shared-service parity tests when implementing.

## Dedupe and limits

Searched all open/done board notes, open milestones across queues and targeted
history for block comments, query parsing and BQL compatibility; no item owns
this omission. m27 upgrades the engine for transaction syntax; its new version
still reproduces this failure. m12 and 098/099 cover editor execution/completion,
not the independent REST parser failure. No product fix was made.

This is a settled syntax failure, not a loading, authentication or transport
error. Empty/denied/expired-session behavior is not changed by the proposed
normalization and was not re-tested in this comment probe. Other browsers,
native query UI and general SQL comment syntax remain unverified.

# Unknown dashboard sub-routes answer 200 with a "Page Not Found" body

**Minor · 40–55m · dashboard.** A3: a link checker, uptime monitor or agent fetching a dead dashboard URL is told the request succeeded.

Production https://beancount.io, 2026-09-12, isolated headless Chrome (Playwright MCP `--headless --isolated`), English/light, 1440×1000, authenticated QA account. Local/fetched main `84231f9c`; deployed SHA unverified. Read-only.

Fetch each URL and read the response status alongside the rendered page:

| route | HTTP | title | robots |
| --- | --- | --- | --- |
| `/settings/account` | **200** | Page Not Found | `noindex, follow` |
| `/ledger/<owner>/example/no-such-page` | **200** | Page Not Found | `noindex, follow` |
| `/ledger/nosuchowner/nosuchledger` | **404** | Page Not Found | `noindex, follow` |

The third row is the working control, and it is in this same app: a missing *ledger* answers a real 404. An unknown route under a known prefix answers 200 while rendering the not-found page.

Search engines are already protected — every one of these carries `noindex, follow`, which is completed [w2/m8](../w2/done/m8/README.md)'s doing. The cost falls on everything else that reads status codes: link checkers report a broken link as healthy, uptime and synthetic monitors see success, and an agent fetching the URL gets `200` plus HTML that says the page does not exist.

Root: the catch-all and the root fallback only *render* the page.

- `dashboard/src/routes/$.tsx` — `component: NotFoundPage` with `noIndex: true` in its `head`, and nothing that signals a 404 to the server.
- `dashboard/src/routes/__root.tsx:38` — `notFoundComponent: NotFoundPage`, likewise render-only.

The mechanism that works already exists one file away: `dashboard/src/routes/ledger.$ledgerOwner.$ledgerName.tsx:61-62` throws `notFound()` from its loader when the ledger resolves to `FORBIDDEN` or `NOT_FOUND`, and that thrown value is what turns into the real 404 in the control row. `grep -rn "setResponseStatus\|notFound()" src` returns exactly that one line — no other route participates.

Fix: make the unmatched-route paths answer 404 the same way the ledger route already does, so the status matches the page being rendered. Keep the existing `noindex` and the rendered `NotFoundPage` exactly as they are — this is a status-code change, not a redesign. Verify under SSR specifically: a client-side navigation into a bad route has no status to set, so the requirement is that a **direct fetch or reload** of the URL answers 404. Owning package: `dashboard` only; no API or schema change.

Blast radius: every route tree the dashboard owns — `/ledger`, `/settings`, `/auth`, `/lgasset`, `/oauth` (the list `dashboard/CLAUDE.md` names for Search Console). Check that legitimate authenticated redirects (the `UNAUTHENTICATED` branch beside the `notFound()` above) keep returning their redirect rather than becoming 404s, and that the FORBIDDEN case keeps its current deliberate mapping to not-found rather than leaking existence.

Adjacent states: a real page must keep answering 200; the login redirect for an unauthenticated visitor must keep working; an error boundary is not a 404 and must not be converted into one.

Not ours, observed in the same pass: `/totally-made-up-path-qa` (a bare root path) answers 404 but from a **different** handler — its title is the raw path (`/totally-made-up-path-qa not found`), it emits no robots meta, and it sets a canonical pointing at the non-existent URL. `dashboard/CLAUDE.md` notes the same host fronts CMS, forum and API services, and root paths are not dashboard routes. Recording it for whoever owns that surface; explicitly **not** part of this note's fix.

Dedupe: searched every queue including `done/` for 404, not found, status code and soft-404 terms. Completed [w2/m8](../w2/done/m8/README.md) forced ledger loader error states to `noindex` — it settled indexability, never the status code, and its work is why the SEO half is already fine. Completed `179` is a mobile missing-file screen; `152` is backend error classification for missing public profiles (a different layer and package). Nothing owns the HTTP status.

Unverified: `/auth`, `/lgasset` and `/oauth` unknown sub-routes were not probed; SSR-versus-client-navigation behavior was not separated; the patched behavior.

Evidence (gitignored, local only): `dashboard/tmp/qa-20260912/soft-404-status.json`.

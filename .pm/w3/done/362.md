# `bea format` directory walk silently omits broken-symlink `.bean` paths from `scanned`

**Severity:** minor. **Estimate:** 25–40 minutes. **Owner:** cli. **A1:** a
pre-commit or agent that runs `bea format -i books/` on a split ledger cannot
tell a broken `include` target is missing from the format scan — `find`/`ls`
show three `.bean` paths, format reports `scanned: 2` and exit **0**, while
`bea check` on the same tree fails on the unreadable include.

Found 2026-09-16 by continuous CLI QA ([c1040 hunt](71549ce0-6925-4441-83c9-e4dc7526623f)),
HEAD `eb41d24e`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Evidence:
`cli/tmp/qa-20260915/c1040/`.

## Repro

```sh
mkdir -p books/txns
cat > books/main.bean <<'EOF'
include "txns/jan.bean"
include "txns/feb.bean"
EOF
printf '2020-01-01 open Assets:Cash USD\n2020-01-02 * "jan"\n  Expenses:Food 1.00 USD\n  Assets:Cash\n' > books/txns/jan.bean
ln -s /missing/feb.bean books/txns/feb.bean

find books -name '*.bean' | wc -l
# 3

bea --json format books --check
# exit 0 — scanned: 2

bea --file books/main.bean check
# exit 1 — feb.bean does not exist
```

## Expected

Directory-scoped format surfaces every `*.bean` entry — name broken symlinks
(or refuse) so `--check` is not green when an include target in the tree is
unreadable.

## Actual

`format.py` `_targets()` uses `rglob` + `f.is_file()`, so broken symlinks
vanish from `scanned`. Explicit `format books/txns/feb.bean -i` errors; the
directory walk hides the same path.

## Fix

Treat non-readable `rglob` matches as failures (`skipped` / nonzero), not
silent drops. Regression: repro reports three paths or exits naming `feb.bean`.

## Dedupe

Not w5/004, w3/249, 251, 273, 329, 332. No open note covers silent omission of
broken-symlink `.bean` entries from recursive `scanned`.

---

**Resolved 2026-09-17** — The directory walk no longer drops a `*.bean` entry it
cannot read. A broken symlink (or any walked non-file that is not a directory)
stops the run with exit **2**, naming the path and where it points, which is
what `bea format <that path>` already did when the same entry was named
explicitly — the walk and the explicit path now agree. This closes the
false-green: `format --check` can no longer report a tree it never looked at
while `bea check` fails on the include that entry stands for. A symlink
resolving outside the requested directory is still skipped, and one resolving
inside is still formatted once under its real path. Documented in
`cli/docs/USAGE.md`; covered by
`cli/tests/test_format_directory_unreadable_entry.py`. Shipped with this board
close.

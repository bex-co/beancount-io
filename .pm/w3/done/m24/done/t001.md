## Objective

Make DatePicker preserve editable text while publishing only complete valid calendar dates; invalid or empty text must invalidate the value without restoring or retaining an old date.

## Context

- The milestone README contains fresh Budget/Balance evidence and the shared cause.
- Live failures were reproduced without accepting any production mutation.

## Steps

1. Separate raw text from the parsed Date and distinguish parent echoes from external resets. Preserve the draft through partial/invalid edits.
2. Parse complete MM/DD/YYYY and YYYY-MM-DD input using the existing date-fns helpers; reject impossible days and incomplete prefixes. Interpret both as local calendar components, so an ISO date-only paste cannot shift to the previous day west of UTC. Keep local calendar-date semantics explicit.
3. Propagate invalid/empty state through the existing Date | undefined boundary. Keep Calendar, Today, keyboard opening and external reset behavior coherent.

## Files

- dashboard/src/common/components/ui/date-picker.tsx
- `dashboard/src/common/components/ui/__tests__/date-picker.test.tsx` (new)

## Acceptance criteria

- [ ] Sequential typing of 06/15/2025 does not expand prefixes or move the cursor into an unrelated date.
- [ ] Empty, partial and impossible dates invalidate the value without erasing the visible draft or silently retaining a prior Date.
- [ ] Valid input, Calendar/Today selection and external resets converge on the intended date.
- [ ] Complete ISO and slash-date inputs denote the same calendar day in America/Los_Angeles and UTC without converting through UTC midnight.

## Objective

Make every DatePicker consumer accept empty/invalid state and prevent required forms from serializing a stale valid Date.

## Context

- The milestone README contains fresh Budget/Balance evidence and the shared cause.
- Live failures were reproduced without accepting any production mutation.

## Steps

1. Remove valid-only callback guards in the six consumers that discard undefined; preserve ReceiptReviewForm's existing forwarding behavior.
2. Keep required schemas honest and show useful localized date validation through the existing form error UI. Block both Enter and pointer submission before format() or mutation when the draft is invalid.
3. Verify Budget and Balance with the live repro inputs, then cover the five source-only integrations using local isolated fixtures. Preserve other field validation, busy states and resets.

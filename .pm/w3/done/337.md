# `bea cloud ledger delete` confirms before auth when signed out

**Severity:** minor. **Estimate:** 15–25 minutes. **Owner:** cli. **A1:** a
signed-out agent gets exit **2** “pass `--yes`” instead of exit **3** “Not
logged in”, so automation chases confirmation instead of credentials.

Found 2026-09-16 by continuous CLI QA ([c790 hunt](9b10a7e8-114b-482f-9853-b3f79984ab5c)),
HEAD `6195b15d`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Confirmed
`cli/tmp/qa-20260915/c791/`. Evidence: `c790/`.

## Repro

```sh
# isolated config; no BEA_TOKEN
bea cloud ledger list
# exit 3 — Not logged in

bea cloud ledger delete user/name
# exit 2 — Permanently delete … pass --yes

bea --yes cloud ledger delete user/name
# exit 3 — Not logged in (only after --yes)
```

## Expected

Auth failure (exit 3) before the destructive confirmation gate, matching
`list` / `show`.

## Actual

`ledger_delete` calls `confirm(...)` before `authenticated_client()`.

## Fix

Resolve credentials before confirm (or skip confirm when auth will fail).
Regression: signed-out delete (with/without `--json`) exits 3; invalid
`full_name` still exits 2 first.

## Dedupe

Not w3/271 (empty `BEA_TOKEN=`). Not w1/done/007 (name validation before
confirm). No open w3 note covers delete confirm-before-auth.

**Resolved 2026-09-17** — Generated destructive cloud commands resolve credentials before the confirmation gate, so signed-out `cloud ledger delete` exits 3. Covered by `cli/tests/test_cloud_ledger_delete_auth_before_confirm.py`. Shipped with this board close.

## Cause and bounded repair

`dashboard/src/common/components/diff-viewer/diff-viewer.tsx:136–176` handles the
request in a layout effect. It checks only that listRef.current exists, invokes
scrollToRow at159, and unconditionally marks the token handled at165. It does
not establish that the underlying scroll element exists or retry on its readiness.

Installed react-window2.2.5's `dist/react-window.js:724–772` initially stores its
container element as null. Its imperative handle can already exist then;
scrollToRow only calls the DOM scroll when `w?.scrollTo` exists. The handle is
updated after the element state changes, while the parent's handled token has
already suppressed the pending request. This source-level mount-readiness race
explains why a later link activation works. The deployed viewer has the same
unconditional token consumption; no library version change is requested.

Use actual list/element readiness to resolve the pending destination, and mark
it consumed only after it can be applied. Arrange a deterministic readiness
retry, not an arbitrary delay or continuous force-scroll. Keep the latest
request tied to ledger/commit, cancel stale requests, and preserve same-fragment
reactivation, small diffs and the large-diff loading gate.

- [ ] Both initial-fragment and select-before-Load journeys reach the staking
      header on the first load at desktop/narrow widths.
- [ ] The already-loaded link control still works; ordinary rerenders do not
      undo a reader's subsequent manual scroll or reuse another commit's target.
- [ ] Coverage exercises real virtual-list mounting and visible destination,
      including the imperative-handle-before-element state. The current
      `diff-viewer.test.tsx:9–54` mock supplies an immediate scrollToRow spy with
      element:null and only asserts its invocation; it cannot catch this race.
      Run normal dashboard checks when implementing.

CommitDetail passes the pending focus after its existing gate at
`features/git/commits/components/commit-detail.tsx:81–82,170`; CommitFileList's
one production caller is CommitDetail. DiffViewer also renders pull-request
reviews; that path has no newly reproduced failure and needs compatibility
coverage. List/detail routes share CommitsSplitView. This repair is confined to
dashboard readiness handling.

# `bea add commodity` has no `--meta`; writer always emits bare commodity lines

**Severity:** minor. **Estimate:** 30–45 minutes. **Owner:** cli. **A1:** agents
cannot register fund/security metadata (`name`, `asset-class`, …) via
`add commodity` — only a bare date/symbol stub — while hand-authored commodity
meta is valid under `check`.

Found 2026-09-16 by continuous CLI QA ([c960 hunt](98af6c28-a7bc-417d-a5b0-b54351cf134f)),
HEAD `2c77a1ab`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Confirmed
`cli/tmp/qa-20260915/c961/`. Evidence: `c960/`.

## Repro

```sh
bea add commodity --help
# no --meta

bea --file main.bean add commodity --date 2020-01-01 --currency VFINX
# writes: 2020-01-01 commodity VFINX
```

Hand-authored `name:` / `asset-class:` under commodity passes `check`;
`list commodity` still drops meta (w3/289).

## Expected

`--meta` on `add commodity` (same parser as transaction add) persists keys on
disk and in the add JSON response.

## Actual

`CommodityDirective` / `write_commodity` omit meta; frontend has no `--meta`.

## Fix

Thread `--meta` through add/writer. Regression: `--meta 'name:…'` writes
indented keys; pair with w3/289 for list round-trip.

## Dedupe

Complement of w3/289 (list-side meta omission). Not w3/347 (txn date meta).
No open note covers missing commodity `--meta` on add.

---

**Resolved 2026-09-17** — `bea add commodity` takes `--meta`, the same option
and the same parser `add transaction` uses, so an agent can register what a
symbol is (`--meta 'name:Vanguard 500 Index' --meta 'asset-class:equity'`)
rather than writing a bare date-and-ticker stub. The keys are written indented
under the directive, keep their native types on disk (`quantum: 3`,
`when: 2020-03-04`, not quoted text), and the add envelope answers with the same
tagged `{"kind": …}` shape transaction metadata already used — a plain model dump
would have flattened a number into a string, so a response could not have been
sent again unchanged. An invalid key is still refused before anything is
written, and a commodity with no `--meta` is byte-identical to before.

This is the write side only; `list commodity` still drops meta on read
(w3/289, still open) — the round trip closes when that lands. Documented in
`cli/docs/USAGE.md` and the generated `cli/docs/REFERENCE.md`; covered by
`cli/tests/test_add_commodity_meta.py`. Shipped with this board close.

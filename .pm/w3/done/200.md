# Reflow the recurring badge with enlarged merchant names

**Severity:** minor. **Estimate:** 35–50 minutes. Package: mobile. A2 — an enlarged merchant directory should remain readable without scrolling through a name one letter at a time.

Environment: main `84231f9c`, 2026-09-13, native build 1.20260906.47 (47), Metro8081, iPhone17e/iOS26.5, English/light, authenticated QA session viewing public `open_ledger/real-estate-example`. Report mode; no recurring override or ledger writes.

Repro:
1. Open the public Real Estate ledger, then drawer → Merchants. At standard `large` text, Bank and Depreciation in the general list each show a horizontal name, RECURRING badge, 21 transactions and last date.
2. Set `accessibility-extra-extra-extra-large`, terminate/relaunch, open the existing Merchants route, dismiss the development banner, and swipe upward three times through the four recurring entries to the general list.
3. Bank is now a vertical B / a / n / k column next to a wide RECURRING badge. Depreciation likewise wraps one character per line. The latter row is 1,021.33 points tall, exceeding the 844-point device window; Green Lawn Care is 1,178.33 points tall. Native hierarchy measures the badge width as 252.67 points. The screenshot shows the name continuing below the viewport while the badge occupies most of its horizontal space.
4. Repeat after another fresh launch (initial PID50889, repeat51790): same one-letter columns. Restore `large` and relaunch (52097): horizontal Bank/Depreciation names and badges fit again.

Expected: the badge and name reflow so enlarged names retain usable reading width. Actual: a full-width scaled badge forces the name into a narrow column; simply removing the name's line limit creates exceptionally tall rows. All letters remain available by scrolling, so this is not a claim of missing data or an inaccessible navigation target.

Working controls: on the same enlarged screen, the recurring-section entries do not render the badge and now correctly show Bank/$1,852.57, Tenant/$2,300.00 and Depreciation/~$969.70 with Monthly and Overdue. Depreciation wraps over two lines there, instead of the general row's one-character column. Standard-size general rows fit. A fresh read-only `getLedgerJournal` query returns 91 transactions / 20 payees; Bank, Tenant and Depreciation each have 21, Green Lawn Care 6. Last dates are Nov30, Nov1, Nov15 and Sep15, 2025 respectively, agreeing with the native directory. This is layout, not aggregation or a failed API response.

Root cause: `mobile/src/screens/merchants-screen/merchant-row.tsx:71` keeps `nameRow` horizontal. The name has `flexShrink: 1`; the badge at line84 has `flexShrink: 0` and uncapped scaled text. At line213, `31f1e4ce` removed the name's line limit in the stacked variant, but line216 still leaves the large badge beside it. The outer row stacks its date/amount correctly; the inner name/badge pair does not adapt. `showBadge` at line169 restricts this failure to recurring merchants in the general section, explaining the passing recurring-section control.

Fix: reflow the badge below/around the name in the enlarged layout, giving the payee usable width and keeping the status associated with its row. Preserve standard-size layout, full name/count/date, recurring-section cadence/amount/Overdue, search/sort grouping, and whole-row navigation/accessibility label. Add focused coverage of the badge-bearing branch at enlarged text, then check the actual native directory with a long payee. Do not hide the badge or globally disable font scaling.

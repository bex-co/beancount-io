# price export can rewrite its source through a nonexistent path component followed by ..

**Major · 30–45m · cli · A1/A2.** The portable-export source guard resolves
only already-existing output paths. A path that reaches the source directory
through a not-yet-created component bypasses it and overwrites source files.

Found 2026-09-21 at HEAD `d5e8e06d`, checkout `bea 0.3.0`, Python 3.13.0,
macOS 26.5.1 arm64. Two fresh synthetic trees, real subprocesses, closed stdin,
isolated config/cache. All export commands used `--offline`; no credentials,
managed feed, HTTP simulation or network fetch was involved.

## Reproduce

In `/absolute/books`, create `main.bean`:

```beancount
include "parts/*.bean"
2026-01-02 * "Opening"
  Assets:Cash 5 USD
  Equity:Opening
```

Create `parts/a.bean` containing `2026-01-01 open Assets:Cash USD`, and
`parts/b.bean` containing `2026-01-01 open Equity:Opening USD`.
Ensure `/absolute/books/not-created` does not exist. The original passes
`bea --json --file /absolute/books/main.bean check`.

```sh
bea --json --offline --file /absolute/books/main.bean price export \
  --output /absolute/books
# exit 2: it holds main.bean, which the export would overwrite

bea --json --offline --file /absolute/books/main.bean price export \
  --output /absolute/books/not-created/..
# exit 0; source main.bean was overwritten
```

Actual source diff in both pristine runs:

```diff
-include "parts/*.bean"
+include "parts/a.bean"
+include "parts/b.bean"
```

The supposedly separate snapshot is the source itself; the command creates
`not-created` and reports output paths containing `not-created/../main.bean`
and the two included files. Stdout is a success JSON envelope, stderr empty.
Original and after hashes/contents prove the mutation. Besides rewriting the
source, replacing the glob changes which future included files it can load.

Expected: refuse this alias just like the direct source-directory target,
before creating directories or changing any file. Completed w1/m29/t005
explicitly requires that exporting never modify the customer's ledger.

Controls: after `not-created` exists, repeating that same alias is correctly
refused with exit 2. A fresh tree exported to a separate `snapshot/` succeeds,
preserves all source hashes and passes a fresh check of the exported root.

## Cause and bounded fix

`cli/src/bea_engine/managed_load.py:539` in `export_portable` computes
`target.resolve() if target.exists() else target.absolute()`. `absolute()`
leaves `..` intact, so comparison with each canonical source parent misses
the alias. Later `dest.parent.mkdir(parents=True, exist_ok=True)` creates
the missing component, and `dest.write_bytes(...)` follows `..` back into
the source tree. The guard and write paths therefore refer to different
effective locations. Targeted history traces this guard to `109fef1d`.

Canonicalize prospective destinations even when their final components do
not exist, and compare them against the source files/directories before
writing. Preserve rejection of existing source aliases and allow legitimate
new export directories. Check symlinked existing ancestors when selecting
the canonicalization helper; do not merely strip `..` text. Add real export
regressions that assert source bytes and directory side effects, with the
direct-target refusal and separate-output controls. No dependencies or API
changes are needed.

Caller path: `cli/src/cli/commands/price.py` `_export` forwards the path to
the engine's `price-export`, which calls `export_portable`. Both local-only
and managed-feed exports use this destination guard; only local-only export
is reproduced here. Managed feed rewriting, symlink variants, other OSes and
concurrent filesystem changes remain unverified.

**Resolved 2026-09-22** — `price export` refuses every alias of the source
directory, not only the ones that already exist.

The guard used `target.resolve() if target.exists() else target.absolute()`,
and `absolute()` leaves `..` in place. So `books/not-created/..` compared
unequal to `books`, slipped past, and then `mkdir(parents=True)` created the
missing component and the writes followed `..` back into the ledger —
rewriting `main.bean` and replacing its `include "parts/*.bean"` glob with two
fixed includes, at exit 0 with empty stderr.

`resolve()` is now used unconditionally. That is the right tool rather than
stripping `..` textually, exactly as the note warned: it normalizes the
non-existent tail **and** resolves symlinks in the ancestors that do exist, so
a destination reached through a symlinked parent is compared as the directory
it truly names. I verified that property directly before relying on it, and it
is covered by a test — a symlink to the books directory plus `nope/..` is
refused.

Verified: the reported bypass, a two-level `x/y/../..`, an alias back into the
included `parts/` directory, and a plain `.` are all refused at exit 2 with the
source byte-identical, the `parts/*.bean` glob intact, and **no** `not-created`
directory left behind — the guard runs before the mkdir, which is the other
half of the report.

Controls hold: the direct source-directory target is still refused, a separate
`snapshot/` still exports (and the exported root passes its own `check`), and a
brand-new subdirectory *inside* the tree is still allowed, since only a
directory holding source files is an alias.

Regression coverage is `cli/tests/test_price_export_destination_aliases.py`.
Reverting the canonicalization fails 6 of its 10; the already-existing-path
refusals and the legitimate exports pass either way. `cd cli && make check-all`
passes (1990 tests).

One note for anyone extending these tests: the source-digest helper names the
three ledger files explicitly rather than globbing, because a legitimate export
into a subdirectory of the tree would otherwise be counted as the source
having changed.

Unverified, as in the note: managed-feed rewriting (only local-only export was
exercised), other platforms, and concurrent filesystem changes between the
check and the write.

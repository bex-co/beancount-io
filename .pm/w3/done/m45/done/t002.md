## Objective

Implement compatibility for existing lossy generated IDs and earlier NFC variants, validating full source content before treating a candidate as already imported. Do not globally relax native-ID conflict checks or rewrite ledger history. Exercise reversed legacy fixtures as well as new identities.

## Context

See [the milestone](./README.md) for exact reproduction, scope and compatibility requirements.

## Acceptance criteria

- [x] Both milestone fixtures replay in reverse as two duplicates against legacy and new ledgers.
- [x] A genuinely changed native bank ID still causes exit 4.
- [x] N identical rows retain multiplicity and repeat-import idempotency.

## Out of scope

Backend/API changes, new dependencies, edits to real ledgers and unrelated import behavior.

## Resolution

Every format a released `bea` actually wrote is offered as a lookup-only key, newest first: pre-exactness (two decimals, no commodity) and pre-exactness-and-pre-NFC. The exact/un-normalized combination is deliberately absent — NFC shipped before exactness, so no ledger was ever written under it. An older *amount* key is content-checked before it counts as a match, because that format was lossy enough to hand two different rows one digest; a mismatch is ignored rather than reported. A reused native bank id with changed data is still a conflict.

## Objective

`ask` is the one command that costs money per call and it inherited the AI SDK's
default of 50 requests, so a model that kept calling tools spent all 50 and then
handed the user a third-party limit name and a link to another project's
documentation. Own the ceiling, and own the words.

## Context

- `cli/src/cli/ask/agent.py` — `translated_failures()` covered `ModelHTTPError`
  only, so every other SDK run failure fell through to the catch-all in
  `cli/src/cli/main.py`.
- Both call sites (`commands/ask.py` for `--print`, `ask/repl.py` for the
  session) must spend the same budget.

## Steps

1. Declare `REQUEST_LIMIT` / `TOOL_CALLS_LIMIT` and a `usage_limits()` builder,
   and pass it at both `run_sync` call sites.
2. Translate `UsageLimitExceeded` and then the whole `AgentRunError` family into
   `BeaError`, each saying what happened, that nothing was written, and what to
   try — and quoting none of the SDK's sentence, which is the defect itself.
3. Keep the `ModelHTTPError` arm first so the existing status table still wins.

## Files

- `cli/src/cli/ask/agent.py`
- `cli/src/cli/commands/ask.py`
- `cli/src/cli/ask/repl.py`

## Acceptance criteria

- [x] A model that only ever calls tools stops well under 50 requests and the
      message names bea's own budget.
- [x] No user-facing message contains `request_limit`, `max retries count`,
      `Consider raising` or an `ai.pydantic.dev` URL.
- [x] Every translated failure states that nothing was written; 401 still exits 3.

## Out of scope

- A per-request `max_tokens` cap — that is `w3/446`, tracked separately.

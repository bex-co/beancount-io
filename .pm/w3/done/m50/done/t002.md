## Objective

`ask` was the only surface outside the sanitizer `w3/392` installed: the approval
panel appended the proposed directive to a Rich `Text` verbatim, and both answer
prints went through `rich.markdown.Markdown` unescaped. Make every
model-controlled byte inert before it is printed.

## Context

- `cli/src/cli/utils.py` holds the frontend twin of the sanitizer.
  `single_line()` collapses newlines, which would destroy a directive or an
  answer — so the same escape mapping is needed with the line structure kept.
- Render paths: `cli/src/cli/ask/repl.py` (panel, session answer) and
  `cli/src/cli/commands/ask.py` (`--print` answer).

## Steps

1. Add `inert_text()` next to `single_line()`, both expressed through one
   `_escape_controls()` helper so the mapping exists once. Normalize CRLF and
   lone CR to LF so a stray CR cannot return the cursor.
2. Apply it to the directive, the destination and the warnings on the panel, and
   to `result.output` on both answer prints.

## Files

- `cli/src/cli/utils.py`
- `cli/src/cli/ask/repl.py`
- `cli/src/cli/commands/ask.py`

## Acceptance criteria

- [x] The panel shows a crafted directive as visible `\xNN` and emits no raw ESC.
- [x] A `--print` answer carrying a cursor-up/erase-line payload emits no CSI on
      a real terminal; the text is still legible as escapes.
- [x] `single_line()` behavior is unchanged (its existing tests still pass).

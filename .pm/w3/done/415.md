# `bea format -i` rewrites text inside multi-line strings, while `--check` and `--dry-run` say nothing would change

**Severity:** major. **Estimate:** 40–60 minutes. **Owner:** cli. **A1/A2:**
formatting is supposed to preserve meaning; here it silently edits note
comments, narrations and metadata values that span lines, and the preview a
cautious user or CI runs first reports the file as already formatted.
Regression from the `w3/267` indent fix (`95f70d36`).

Found 2026-09-25 by CLI QA against `main` HEAD `8cd9732b`, `uv run bea` 0.3.0,
Darwin 25.5.0 arm64, isolated config/cache. Synthetic files only.

## Repro

```sh
printf '%s\n' 'option "operating_currency" "USD"' \
  '2026-01-01 open Assets:Cash USD' '' \
  '2026-01-02 note Assets:Cash "Address:' \
  '    221B Baker Street"' > only.bean
cp only.bean orig.bean
bea format only.bean | diff orig.bean - && echo "stdout: unchanged"
bea format --check only.bean;   echo exit=$?   # exit=0 "All 1 file(s) are formatted."
bea --json format --dry-run only.bean           # "formatted": []
bea format -i only.bean                          # "1/1 file(s) formatted."
diff orig.bean only.bean
# <     221B Baker Street"
# >   221B Baker Street"
bea --json --file "$PWD/only.bean" list note    # comment lost two spaces
```

The same happens to a multi-line narration (`"Multi\n        line"` becomes
`"Multi\n  line"`), a multi-line metadata string, and a continuation line
that starts with a tab. Upstream `bean-format` (what stdout/`-o` run) leaves
all of these alone.

Related divergence in the same helper: posting metadata written at the
conventional four spaces is flattened to two, so it reads like another
posting-level line (`bea list` still attaches it to the posting, but the
file no longer shows that), and a tab-indented file formats to one-space
indents through stdout/`-o` but to two spaces through `-i`. Both `--check`
verdicts are green, so `-i`, stdout and `-o` disagree about the canonical
form.

## Root cause

`cli/src/cli/commands/format.py` `_canonical_posting_indent` (~323–344)
rewrites **every** indented line whose indent is not exactly two spaces to
two spaces, without knowing whether the line is a posting, posting metadata,
or the inside of a string literal. `_format_in_place` (~176) applies it
to the file after `bean-format --in-place`; the `--check`/`--dry-run`
comparison (~320) canonicalizes **both** sides, so the edit it would make is
invisible to the preview.

## Fix

Normalize only what `w3/267` targeted — a posting line's leading tab or
single-space indent — and only outside string literals (track open quotes
across lines, or use the tokenizer's line/column for postings). Leave
metadata indentation and string contents byte-for-byte. Make `--check` /
`--dry-run` compare against exactly what `-i` would write, and apply the
same normalization to stdout/`-o` so all destinations agree.

## Acceptance

- The repro: `-i` leaves `only.bean` unchanged and `list note` returns the
  original comment; `--check` stays green.
- A tab-indented posting file produces identical bytes via stdout, `-o` and `-i`.
- A file where `-i` would change anything is reported by `--check`/`--dry-run`.
- Regression tests: multi-line note/narration/metadata strings, four-space
  posting metadata, tab postings.

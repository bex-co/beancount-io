# `bea import` preview marks rows `ready` and shows a write diff when the counter-account is not open

**Severity:** minor. **Estimate:** 30–45 minutes. **Owner:** cli. **A1:** an
agent that treats preview `STATUS=new` / `N ready` as apply-safe will call
`--apply` and get exit 1 (“Import would leave the ledger invalid”) after
already being shown a green-looking diff — e.g. default
`Expenses:Uncategorized` or a rules target that was never `open`ed.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `561f0206`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
# ledger has Expenses:Food but NOT Expenses:Uncategorized
bea --file main.bean import bank.csv --csv auto --account Assets:Cash
# exit 0
# stderr: … Invalid reference to unknown account 'Expenses:Uncategorized' …
# stdout: csv → Assets:Cash: 1 ready, …
#         ROW … STATUS new …
#         +++ diff proposing Expenses:Uncategorized postings
#         Preview only. …

bea --file main.bean import bank.csv --csv auto --account Assets:Cash --apply
# exit 1 — Import would leave the ledger invalid; nothing was written.
# (same unknown-account diagnostic)
```

Same shape with `--rules` pointing at an account that is not open: preview
still says `1 ready` and paints the diff; apply refuses.

Same shape for currency constraints (2026-09-16 QA extension): a CSV
`currency=Currency` row posting `EUR` into `Assets:Cash` opened as `USD`
only — preview exit 0 with stderr `Invalid currency EUR for account
'Assets:Cash'`, summary `1 ready`, and a write diff; `--apply` exits 1 and
writes nothing.

Under `--json`, the contradiction is explicit in one object: `ready: 1`,
`rows[].status: "new"`, `include: true`, plus a non-empty
`validation_errors` listing the unknown account (or currency constraint) —
exit still 0.

Working control: open `Expenses:Uncategorized` (or the rule account) first —
preview stays `1 ready` and `--apply` writes. For the currency case, open
`Assets:Cash` with `USD,EUR` (or map the row to an EUR account).

## Expected

Preview should not count a row as `ready` (or should use a distinct status /
nonzero exit) when the proposed entries fail the same validation `--apply`
uses. Prefer naming the missing open(s) in the status column / summary so
agents fix opens before apply.

## Actual

Preview builds entries and prints a diff even while loader validation errors
stream on stderr; the row status stays `new` and the summary says `ready`.
Only `--apply` turns that into a hard failure.

## Fix

After building the preview entries, run the same validation gate as apply
(without writing). Rows (or the whole preview) that fail account-reference /
currency-constraint / balance checks should not be labeled `ready` — e.g.
status `would_fail_validation` and summary `0 ready, N invalid`, exit 2 for
unattended use, or keep exit 0 but make `ready` mean apply-safe. Regression:
the Uncategorized-missing, rules-missing-account, and EUR-into-USD-only
fixtures stop reporting `ready` for those rows; apply behavior unchanged.

Not w3/263 (blank CSV rows). No open note covers preview `ready` vs apply

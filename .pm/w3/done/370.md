# `bea format --check` exits 0 when the include graph is broken or invalid

**Severity:** minor. **Estimate:** 25–40 minutes. **Owner:** cli. **A1:** a
pre-commit or agent that runs `bea format --check` on a split-ledger root
expects a nonzero exit when `bea check` fails — instead format reports “All 1
file(s) are formatted” and exit **0** for missing includes **and** for
existing children that fail syntax / balance / assertions.

Found 2026-09-16 by continuous CLI QA ([c1130 hunt](828702af-9b3c-4b99-9a5d-63a5efa2363a)),
HEAD `1d517572`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Evidence:
`cli/tmp/qa-20260915/c1130/`. Extended 2026-09-16 for present-but-invalid
includes ([c1220 hunt](1081c08e-d11a-4d98-9b46-86c973842aa7)), HEAD
`420d5cca`; evidence `c1220/` (`fmt-invalid/`, `fmt-unbal/`, `bal-fail/`).

## Repro

```sh
# missing target
# main.bean: include "missing.bean"
bea --file main.bean check
# exit 1 — File glob "missing.bean" does not match any files
bea format main.bean --check
# exit 0 — All 1 file(s) are formatted.

# existing invalid child (c1220)
# main.bean includes bad.bean with Invalid token / unbalanced / failed balance
bea --file main.bean check
# exit 1 — diagnostics on child
bea format main.bean --check
# exit 0 — All 1 file(s) are formatted.
```

## Expected

`format --check` fails when the include graph is missing or would fail
`bea check`, matching load/`check` semantics.

## Actual

`format.py` only inspects the named file’s text; it never resolves or
validates includes.

## Fix

On `--check` for a ledger file, resolve includes and fail if any target is
missing or fails the same load/validation gate as `bea check`. Regression:
missing and invalid-child repros exit nonzero; valid trees stay green.

## Dedupe

Not w3/332 (existing child unformatted only). Not w3/362 (broken symlink
omitted from directory walk). Not w3/273 (same-file unparseable text). Invalid
existing children are the same include-blind class as this note (not a
separate filing).

# init rejects valid single-letter Beancount currency symbols

**Minor · 15–25m · cli · A2.** `init --currency F` refuses a valid Beancount
commodity symbol, contradicting its documented syntax-based currency policy.

Found 2026-09-21 at HEAD `d5e8e06d`, checkout `bea 0.3.0`, Python 3.13.0,
macOS 26.5.1 arm64. Fresh commands with isolated config/cache and closed stdin;
two fresh F targets and a C target fail identically without creating files.

```sh
bea --json --no-input init /absolute/new.bean --currency F --date 2026-01-01
```

Actual: exit **2**, empty stdout, JSON usage error on stderr:
`Invalid value: Invalid operating currency: 'F'. Use a symbol such as USD or EUR.`
Expected: create a valid ledger, retaining the existing non-three-letter typo
warning. `cli/docs/USAGE.md:238` says symbols follow Beancount syntax,
including custom symbols, and are not restricted to an ISO registry.

Independent accepted control: save this as a different file, then run
`bea --json --file /absolute/control.bean check`:

```beancount
option "operating_currency" "F"
2026-01-01 open Assets:Cash F
2026-01-01 open Equity:Opening F
2026-01-02 * "Single ticker"
  Assets:Cash 1 F
  Equity:Opening
```

It exits 0 with `valid=true`. A C option/open fixture also passes. Init with
`FE` succeeds, emits its existing custom-symbol warning, and passes a fresh
check; the USD opening-balance control succeeds too.

Cause: `cli/src/cli/commands/init.py:44` `_currency` uses
`[A-Z][A-Z0-9'._-]*[A-Z0-9]`, requiring two mandatory characters. It omits
the valid single-uppercase-letter case. The helper validates both explicit
options and prompt answers; only the explicit path was exercised here.
History traces the validator to `ff47e5c6`, with no later single-letter repair.

Allow the valid single-letter form while preserving trimming, uppercasing,
invalid-symbol rejection and non-three-letter warnings. Keep the frontend
independent of Beancount imports. Cover F/C and lowercase normalization with
actual init/check regressions and retain malformed-symbol controls. No new
dependencies, backend/API changes or wider currency-policy changes.

Searched all board queues, including done/blocked, for single-letter currency,
commodity and init validation; no matching open item. Single-letter metadata
key rejection (w3/229) is a different grammar. Evidence is ignored under
`cli/tmp/qa-20260922T052032Z-loop/`: `init-boundaries/`,
`init-symbol-repeat/`, captures `init-boundary-*.json`,
`init-single-symbol-native-control.json`, `init-symbol-*.json`, with argv,
cwd/environment, streams, exits, duration, revision and file hashes/content.
Interactive prompting and other platforms remain unverified.

---

**Resolved 2026-09-22** — `init --currency F` creates a ledger, and so does
every other symbol the loader accepts.

The validator required two characters, so a single-letter ticker was refused
even though Beancount accepts it and `bea check` validates a ledger using it.
Upstream's `CURRENCY_RE` makes the final character optional.

Rather than add a `?` and hope, I compared candidate patterns against
upstream's own regex over every string up to four characters from the symbol
alphabet. That turned up a second, unreported case: upstream ends its pattern
with `\b`, so `X_` **is** a symbol and `A.` is not — a naive `?` would have
accepted `A.` and the old pattern was already refusing `X_`. The shipped
pattern is `[A-Z](?:[A-Z0-9'._-]*[A-Z0-9_])?`, which agrees with upstream on
all 4-character strings with **zero** disagreements, and a test pins that
comparison so the restated copy cannot drift. The frontend still loads no
Beancount.

Deliberately still refused: upstream's leading-`/` commodity-**pair** form
(`/OIL`). It is not an operating currency, and accepting it would be the wider
policy change this item was scoped to avoid. The test asserts it stays refused
and explains why the comparison excludes it.

Verified end to end: `--currency F` and `--currency C` create ledgers that
check clean with `option "operating_currency" "F"` written; lowercase and
padded input still normalize (`f` → `F`, `"  c  "` → `C`); the non-three-letter
typo warning still fires for `F`; and `1F`, `A.`, `US D` and `/OIL` are still
refused at exit 2 without creating a file.

Regression coverage is `cli/tests/test_init_currency_symbols.py`. Reverting the
pattern fails 10 of its 27. `cd cli && make check-all` passes (1980 tests).

Unverified, as in the note: the interactive prompt path (it calls the same
`_currency` validator, so it is fixed by construction, but it was not driven),
and other platforms.

# `bea list custom` human VALUES column drops typed-value kinds

**Severity:** minor. **Estimate:** 15–25 minutes. **Owner:** cli. **A1:** an
agent that `add custom` with `text:` / `bool:` / `date:` / `amount:` values and
then `list custom` in human mode cannot round-trip the kinds — `True True
2020-01-01` is ambiguous (`text:True` vs `bool:TRUE`), while `--json` already
returns `{kind, value}` correctly.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `19128ce1`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
bea --file main.bean add custom --date 2020-05-01 --type budget \
  --value 'text:True' --value 'bool:TRUE' --value 'date:2020-01-01'

bea --file main.bean list custom
# DATE        TYPE    VALUES
# 2020-05-01  budget  True True 2020-01-01

bea --json --file main.bean list custom
# values: [{"kind":"text","value":"True"},{"kind":"bool","value":true},
#          {"kind":"date","value":"2020-01-01"}]
```

Working control: amount values already render as `number currency` via the
`kind == "amount"` branch in `_format_custom_values`.

## Expected

Human VALUES should preserve enough kind information to match the add syntax
(or Beancount custom value printing) — e.g. `TRUE` / `False` for bools,
`YYYY-MM-DD` with a date cue, or `text:…` / `bool:…` prefixes — so text `"True"`
and bool `TRUE` are distinguishable.

## Actual

`cli/commands/list.py` `_format_custom_values` does `str(value["value"])` for
every non-amount kind, collapsing typed customs into bare Python/string forms.

## Fix

Format each kind explicitly (mirror add/`--json` kinds, or Beancount’s custom
printer). Regression: the three-value repro’s human VALUES distinguish
text/bool/date; JSON unchanged.

## Dedupe

Not w3/289 (`list` dropping `meta` on custom and others). No open note covers
human VALUES kind loss on `list custom`.

**Resolved 2026-09-17** — Human `list custom` VALUES use `text:`/`bool:`/`date:`/`amount:` prefixes matching add. Covered by `cli/tests/test_list_custom_value_kinds.py`. Shipped with this board close.

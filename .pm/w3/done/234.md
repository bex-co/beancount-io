# `bea --json query` forces `--format json`, so one-shot shell utilities that work in human mode become BQL syntax errors

**Severity:** minor. **Estimate:** 30–45 minutes. **Owner:** cli. **A1:** an
agent scripting discovery (`.tables`, `.set`, `.errors`, `.describe …`) under
global `--json` gets a usage syntax error pointing at the interactive shell,
even though the same argument succeeds without `--json`.

Found 2026-09-15 by continuous CLI QA against `main`, HEAD `e093cc4b`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
bea --file main.bean query '.tables'
# exit 0 — prints accounts/balances/…

bea --json --file main.bean query '.tables'
echo exit=$?
# exit 2
# {"error":{"category":"usage",
#   "message":"Cannot run this BQL query: syntax error.",
#   "details":["  .tables","  ^",
#     "Run bea query with no argument for the interactive shell,
#      where .tables lists what you can query."]}}

bea --json --file main.bean query '.set'     # same syntax-error shape
bea --json --file main.bean query '.errors'  # same

# same class — stored-query runner (ledger has `query "cash" "SELECT …"`):
bea --file main.bean query '.run cash'       # exit 0, table rows
bea --json --file main.bean query '.run cash'
# exit 2 — identical “syntax error” + interactive-shell hint
```

Working control: `bea --json --file main.bean query 'SELECT account LIMIT 1'`
returns columns/rows. Human one-shot `.tables` / `.set` / `.errors` / `.run`
succeed.

## Expected

Either:

1. One-shot shell utilities under `--json` return a stable JSON shape (for
   example `data.text`, or a documented `data.utility` field) via the shell
   dispatch path used by human mode, or
2. A clear usage error that says `--json` only accepts SELECT/PRINT (or
   `--format json` row queries), without claiming the only place `.tables`
   works is the interactive shell.

## Actual

```text
cli/src/cli/commands/query.py
  args += ["--format", "json" if ctx.json_output else output_format]
  # --json → bea-engine query --format json → rows_answer / bare execute
  # which does not run BQLShell.onecmd, so ".tables" is a BQL syntax error
```

Human mode uses `--format text` → `text_answer` → shell.onecmd, which is why
`.tables` works without `--json`.

## Fix

When the query string is a known shell utility (leading `.` or aliased
`help`/`errors`/…), keep the shell/text dispatch even under `--json` and emit
`text` (or a dedicated field) in the frontend envelope; or reject with an
honest message that does not send agents to the interactive shell for a
command that already works one-shot. Regression: human `.tables` stays green;
`--json query '.tables'` either returns structured text or a non-misleading
usage error (not “syntax error” + interactive-only hint).

## Objective

Use the existing ledger permission contract for the entry editor and its mutation actions.

## Context

- Live reader permissions are admin:false, pull:true, push:false, yet the dialog allows an unsaved edit and enables Save/Delete.
- The journal, overview recent activity, and account report share EntryContextDialog.

## Steps

1. Derive or consistently pass canWrite for the selected ledger; default to read-only while permission is unresolved.
2. Set editor readOnly, gate mutation controls, and guard handlers against a late permission loss.
3. Add a meaningful reader/writer check and define handling for an existing draft when write permission changes.

## Acceptance criteria

- [ ] Guests and signed-in readers can inspect source/balances but cannot edit or invoke mutation actions.
- [ ] Authorized writers retain normal editing behavior, including changed/unchanged and busy states.
- [ ] A permission change while the dialog is open cannot leave a callable write handler or silently discard an existing draft.

## Out of scope

- Weakening backend authorization or proving a production write bypass.
- Writing to pre-existing production entries during verification.

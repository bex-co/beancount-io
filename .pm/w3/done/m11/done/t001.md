## Objective

Attach the source location already resolved by the ledger service to its entry-context response, while preserving user metadata and entry identity.

## Context

- The major finding and live GraphQL/REST controls are recorded in the milestone README.
- getContext resolves an EntrySlice before serializing the directive; its file and startLine are currently discarded from entry metadata.

## Steps

1. Read ledger package guidance and trace source resolution for normal, included-file, and duplicate entries.
2. Merge resolved filename and one-based lineno into context metadata, preserving other metadata and the existing unresolved-entry error.
3. Add a behavioral regression covering real source slices and run the ledger package's relevant checks.

## Files

- `backend-cluster/ledger/src/features/ledger/service/ledger-journal-service.ts`
- `backend-cluster/ledger/src/foundation/rustledger/source-slice.ts`
- `backend-cluster/ledger/src/features/ledger/service/__tests__/`

## Acceptance criteria

- [ ] A resolved context carries meta.filename equal to the resolved file and meta.lineno equal to startLine + 1.
- [ ] Included files, repeated identical directives, and existing user metadata retain the correct identity/location.
- [ ] Source slice, sha256sum, balances and authorization behavior are preserved; unresolved entries remain errors.

## Out of scope

- Changing the general journal serializer or inventing locations for generated/unresolved entries.
- Copying engine bytes or modifying generated clients.

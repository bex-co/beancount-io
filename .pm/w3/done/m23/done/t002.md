## Objective

Restore focus to the actual Budget action used to open AddBudgetDialog, including a sensible fallback when successful creation removes that action.

## Context

- Header Add Budget and empty-state Add Your First Budget both open one controlled dialog and lose focus on dismissal.
- BudgetChartCard separately instantiates AddBudgetDialog for Add Entry; this caller is source-traced.
- One shared Radix triggerRef must not accidentally bind only the last of multiple mounted openers.

## Steps

1. Capture the specific opener or give each independently scoped dialog a registered trigger; reuse the repository's connected-element return pattern.
2. Wire both page-level buttons and the card Add Entry caller while preserving permissions and form defaults.
3. After close, focus the original connected opener; if creation removed the empty-state action, focus persistent Add Budget.
4. Keep focus in an open form on validation or server error; preserve reset, refetch and write behavior.

## Acceptance criteria

- [ ] Header, empty-state and card paths restore the correct opener after dismissal.
- [ ] A removed opener falls back to persistent Add Budget, never BODY or a detached node.
- [ ] Permission gates, defaults, resets, nested input controls and existing mutations are unchanged.

## Out of scope

Real production budget creation/deletion, budget calculations,003 write retry semantics and other dialogs.

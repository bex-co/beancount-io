## Objective

Let a reader who has never opened the source connect an MCP client in a few minutes: which URL, why the credential has to be pinned to one ledger, which tools they get, and what each failure means.

## Context

- The endpoint is `POST {issuer}/api-gateway/mcp` (ADR 0007 D1). The path is not obvious from the outside, and guessing wrongly lands on the dashboard's SSR catch-all, whose error says nothing useful.
- The credential must carry `ledgerScope: "owner/name"` — `mcp-route.ts` refuses an unpinned one, because MCP has no per-call ledger argument to fall back on (ADR 0007 D3). This is the single most likely thing for a first-time integrator to get wrong, so it belongs above the fold.
- Two credential kinds reach it: an OAuth grant and a durable `bcio_` API key.
- A `401` carries an RFC 9728 pointer to the authorization server; if that pointer does not resolve, the client cannot authenticate at all (ADR 0007 D4) — which is what the t002 check diagnoses.

## Steps

1. Add an MCP section to `backend-cluster/backend-v2/README.md`: endpoint, credential requirement, the seven tools, a client config snippet.
2. State the ledger-scope requirement prominently, with the exact refusal a reader will see if they miss it.
3. Point at ADR 0007 for the contract and at `yarn mcp:conformance` for diagnosing a deployment that will not connect.

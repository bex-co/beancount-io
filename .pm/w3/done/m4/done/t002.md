## Objective

Turn ADR 0007's seven-point conformance checklist into a script an operator runs against a base URL, so "is my MCP endpoint actually connectable?" has one answer instead of seven hand-typed curl invocations — and so a failure names the check rather than surfacing as a stack trace.

## Context

- The checklist is `## Conformance checklist` in `backend-cluster/backend-v2/docs/ADR0007-mcp-surface.md`.
- Checks 1, 2, 3, 6 and 7 need no credential. Checks 4 and 5 need a ledger-scoped credential, so take one optionally and **skip with a stated reason** when it is absent — a skip is honest, a failure would not be.
- The failure modes worth naming distinctly: the endpoint answers but the discovery document it points at does not (check 2); a credential is refused with an internal error rather than a clean 401/403 (check 4, 6).
- `deploy/docker/` self-hosters are a real audience for this, not only the hosted deployment.

## Steps

1. Add a script under `backend-cluster/backend-v2/scripts/` and a `yarn mcp:conformance <base-url> [--token …]` entry point.
2. Implement each check as a named unit printing pass / fail / skip plus the reason.
3. Exit non-zero when any check fails; exit zero when the only non-passes are documented skips.
4. Run it against a local `yarn dev` and confirm the credential-dependent checks skip cleanly.

## Files

- `backend-cluster/backend-v2/scripts/` (new script)
- `backend-cluster/backend-v2/package.json` (script entry)

## Acceptance criteria

- [ ] Against a local `yarn dev`, every check that does not require a credential passes and the rest skip with a reason.
- [ ] Against a base URL whose OAuth signing key is unconfigured, check 2 fails **by name** with the reason, and the process exits non-zero.
- [ ] The script changes no endpoint behavior — it only observes.

## Out of scope

- Wiring it into CI: there is no deployment for CI to point at yet. t003 documents running it by hand; automating it is follow-up work.

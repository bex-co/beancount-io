# `bea add transactions` (no `--partial`) omits `--partial` recovery when the batch fails only at ledger validation

**Severity:** minor. **Estimate:** 25–40 minutes. **Owner:** cli. **A1:** an
agent with a mostly-good bulk JSON file that has one unknown-account (or
unbalanced) row gets only “leave the ledger invalid; nothing was written” and
`unwritten_rows: [0,1,2]`, with no hint that `--partial` would append the good
rows — while a schema error in the same command already teaches `pass --partial
to append the N valid row(s)`.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `87119b1d`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only. Evidence: `cli/tmp/qa-20260915/c542/`.

## Repro

```sh
# main.bean opens Assets:Cash, Expenses:Food, …
cat > rows.json <<'EOF'
[
  {"date":"2024-09-01","narration":"ok","postings":[
    {"account":"Expenses:Food","amount":"1 USD"},{"account":"Assets:Cash"}]},
  {"date":"2024-09-02","narration":"badacct","postings":[
    {"account":"Expenses:NoSuch","amount":"1 USD"},{"account":"Assets:Cash"}]},
  {"date":"2024-09-03","narration":"ok2","postings":[
    {"account":"Expenses:Food","amount":"2 USD"},{"account":"Assets:Cash"}]}
]
EOF

bea --json --file main.bean add transactions --from rows.json
# exit 1 — ledger unchanged
# message: "The change would leave the ledger invalid; nothing was written."
# result.unwritten_rows: [0, 1, 2]  — no --partial advice

bea --json --file main.bean add transactions --from rows.json --partial
# exit 1 — writes rows 0 and 2
# "Added 2 of 3 transactions; 1 row was rejected."
# written_rows: [0, 2], rejected_rows: [1]
```

Schema-error control (already hints):

```sh
# one bad date string → "… pass --partial to append the 1 valid row(s)."
```

## Expected

Non-partial failure after schema-valid rows should count per-row ledger-
acceptable rows and say `pass --partial to append the N valid row(s)`, or at
least mention `--partial` and not imply every `unwritten_rows` index is equally
unrecoverable.

## Actual

Batch `validate_append` fails once; `adding._transactions` sets
`unwritten_rows` to every schema-valid index and re-raises with no `--partial`
text. Schema rejects take the early path that does mention `--partial`.

## Fix

Before raising on non-partial batch ledger failure, run the same sequential
`validate_append` trials as `--partial` to compute recoverable indices; if
nonempty, mirror the schema-path recovery sentence. Regression: the repro
without `--partial` mentions appending 2 rows; with `--partial` still writes
`[0,2]`.

## Dedupe

Not w3/231 (overstates `--partial` count when schema and balance failures are
mixed). Complementary branch: zero schema rejects → batch ledger validation →
silent omit. Not w3/261 (empty postings) or w3/264 (wrong path citation).

---

**Resolved 2026-09-17** — Non-partial bulk add that fails only at ledger validation probes recoverable rows and advises `--partial`. Covered by `cli/tests/test_bulk_partial_recovery_hint.py`. Shipped with this board close.

# `bea cloud ledger show` prints Python reprs (`empty: False`, `permissions: {'admin': True, …}`) and promises a field the server never sends

**Severity:** minor. **Owner:** cli (the `cloud` command generator).
**Estimate:** 25–35 minutes. **A3:** this is the command a newcomer runs to
inspect a hosted ledger; `{'admin': True, 'pull': True, 'push': True}` reads as
a debug dump, and its `--help` names a field that is not in the output.

Found 2026-09-26 by CLI QA (`qa-find-bugs-cli`) against `main` HEAD `8cd9732b`,
`uv run bea` 0.3.0, Darwin 26.5.1 arm64, isolated `BEA_CONFIG_DIR`, authorized
QA account, read-only. Compared field by field against the REST operation the
CLI itself calls (`GET /api-gateway/v1/ledgers/{owner}/{name}`).

## Repro

```sh
bea cloud ledger show open_ledger/example
# id: open_ledger/example
# name: example
# full_name: open_ledger/example
# ssh_url: ssh://git@git.beancount.io:2222/open_ledger/example.git
# http_url: https://git.beancount.io/open_ledger/example.git
# empty: False
# private: False
# created_at: 2026-01-03T09:06:49Z
# updated_at: 2026-08-20T07:14:43Z
# size: 144
# description:
# permissions: {'admin': False, 'pull': True, 'push': False}
```

Three problems in that output:

1. `empty: False` / `private: False` are Python booleans. The sibling
   `bea cloud ledger list` renderer prints the same field as `PRIVATE  no`.
2. `permissions:` is a Python dict literal, single quotes and all.
3. `bea cloud ledger show --help` says "Metadata for a single ledger:
   description, visibility, **default branch**, and the caller's permissions on
   it." No default branch appears, and the REST response has no such field.

## Parity check (this part is clean)

`bea --json cloud ledger show <full_name>` matches the REST body exactly —
every field present, only `camelCase` → `snake_case`, values identical —
and so does `bea --json cloud ledger list` against
`GET /api-gateway/v1/ledgers`. `bea cloud status` agrees with
`GET /api-gateway/v1/user-profile` on email, username and tier. Invalid paging
(`--limit 101`, `--limit 0`, `--page 0`) is refused with the server's own
validation sentence. So this item is about the human rendering and the help
text, not about dropped or mangled data.

## Fix

1. In the `cloud ledger show` human branch
   (`cli/src/cli/commands/cloud/generated/ledger.py:67`, currently
   `typer.echo(f"{key}: {value}")` over the raw dict), render values for people:
   booleans as `yes`/`no` like the `list` renderer at `:40-44`, and a nested
   object as indented `key: value` lines (`permissions:` then
   `  admin: no` …). Because the file is generated, the change belongs in
   `cli/scripts/gen_cloud_commands.py` (or the shared formatter it emits calls
   to), then `make codegen`.
2. Correct the operation description so the promised fields are the ones the
   response carries. The text comes from the annotated backend-v2 operation, so
   fix it there, regenerate the spec, `make spec-sync && make codegen`, and
   `make docs`.
3. Regression coverage: a test asserting no `True`/`False`/`{'` appears in the
   human output of a `cloud` show command, over a fixture response with a nested
   object.

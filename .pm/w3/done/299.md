# `bea query 'help select'` crashes with `NoneType` (PreciseShell `on_Select` has no docstring)

**Severity:** minor. **Estimate:** 15–25 minutes. **Owner:** cli (managed
engine query shell). **A1:** an agent that follows the shell’s own
`help` / `.help` banner (“Beancount query commands: select …”) and runs
`help select` gets a raw `TypeError` message instead of the SELECT syntax help
that upstream beanquery ships.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `58e1e599`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
bea --file main.bean query 'help select'
# exit 1
# Error: expected string or bytes-like object, got 'NoneType'

bea --file main.bean query '.help select'
# same

bea --debug --file main.bean query 'help select'
# Traceback ends in launch.helper_json → LedgerError with that message
```

Working controls:

```sh
bea --file main.bean query 'help from'
# exit 0 — long FROM-clause column/function help on stdout

bea --file main.bean query 'help where'
bea --file main.bean query 'help targets'
# exit 0

# Upstream beanquery BQLShell.on_Select has a full SELECT docstring; print /
# journal / balances help still hit w3/233 envelope leakage rather than this crash
```

## Expected

`help select` / `.help select` prints the SELECT syntax help (or a bea-owned
short summary) and exits 0 in one-shot mode, with the text in the engine
envelope / stdout — same class of answer as `help from`.

## Actual

`bea_engine/query.py` `PreciseShell.on_Select` overrides beanquery’s
`BQLShell.on_Select` without a docstring (or without copying
`BQLShell.on_Select.__doc__`). Beanquery’s `add_help` builds
`help_select` as:

```python
lambda _, fun=func: print(textwrap.dedent(fun.__doc__).strip(), file=self.outfile)
```

`textwrap.dedent(None)` raises `TypeError: expected string or bytes-like
object, got 'NoneType'`. The managed engine surfaces that as a ledger error;
`--json` currently mis-reports `.help select` as a BQL syntax error (separate
from the human-path crash).

## Fix

Give `PreciseShell.on_Select` the upstream docstring (assign
`__doc__ = BQLShell.on_Select.__doc__`, or wrap with
`functools.wraps` / explicit copy). Optionally harden `add_help` consumers
against missing docs. Regression: `bea query 'help select'` exits 0 with SELECT
syntax text; `help from` / `SELECT account LIMIT 1` unchanged.

## Dedupe

Not w3/233 (bare `.help` / `help format` leak past the JSON envelope → “engine
did not answer”). That note’s `help <topic>` examples fail differently; only
`select` hits this NoneType because bea replaced `on_Select`. Not w3/234
(`--json` rejects `.tables`). No open note covers the docstring-stripping
`help select` crash.

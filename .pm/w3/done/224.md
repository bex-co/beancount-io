# `bea add balance --pad-from` when the amount already matches fails with a circular hint

**Severity:** minor. **Estimate:** 30–45 minutes. **Owner:** cli. **A1/A2:**
reconcile flows that always pass `--pad-from` (skills/tutorial) hit a dead-end
error that restates the command they just ran, instead of saying the pad is
unnecessary.

Found 2026-09-15 by continuous CLI QA against `main`, HEAD `89e2d9cc`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
ledger whose `Assets:Bank:Checking` inventory is already `3357.83 USD`.

## Repro

```sh
# Checking balance is already 3357.83 USD (verified via bea balance / BQL)
bea --json --file main.bean add balance \
  --date 2024-03-10 --account Assets:Bank:Checking --amount '3357.83 USD' \
  --pad-from Equity:Opening-Balances
```

Exit 1:

```text
Unused Pad entry Add both directives atomically with bea add balance
--pad-from ACCOUNT --date YYYY-MM-DD --amount 'NUMBER CURRENCY' --account ACCOUNT.
```

Nothing written. Same command **without** `--pad-from` succeeds (writes the
balance assertion alone) and `bea check` stays green.

Evidence: `cli/tmp/qa-20260915/evidence/pad-match.err`, `bal-only.out`.

## Working control

`--pad-from` when the asserted amount **differs** from the book balance still
writes pad+balance atomically (earlier pad-from to `3000.00 USD` on this
fixture family succeeded). Bare unused `pad` without a following balance is
the case the hint was written for.

## Expected / actual

Beancount correctly rejects an unused `pad`. Expected from bea when that
rejection comes from an atomic `--pad-from` whose amount already matches:

- Prefer writing only the balance assertion (pad omitted), **or**
- Fail with usage/validation text that says the book balance already matches
  and to omit `--pad-from` (or name the current book amount).

Actual: the generic “Unused Pad” rewriter always appends “Add both directives
atomically with bea add balance --pad-from …”, which is exactly the invocation
that just failed — a circular hint.

## Root cause

`cli/src/bea_engine/ledger/write.py:393-397` — any `"Unused Pad"` in the
engine message gets that suffix, with no check that the candidate write
already included a pad+balance pair from `--pad-from`
(`cli/src/cli/commands/add.py:208-216`).

## Fix

Detect unused-pad failures on a candidate that already contains both a pad and
its balance (the `--pad-from` path): replace the circular suffix with “Book
balance already matches NUMBER CURRENCY; omit --pad-from and add the assertion
alone,” or skip emitting the pad when the residual is zero before validate.
Keep the existing hint for a lone `bea add pad` without a following balance.
Regression: matching amount + `--pad-from` must not tell the user to re-run
`--pad-from`; mismatched amount + `--pad-from` still writes both.

## Dedupe

Prior `--pad-from` work (w1/m17–m19) taught the happy path; no open item covers
the already-matching residual. Not w3/223 (tag/link messages).

## Unverified

Tolerance bands (`~`), multi-commodity pads, `--allow-errors` on this path.

---

**Resolved 2026-09-15** — matching --pad-from now omits the unused pad and writes the balance assertion alone (with a warning); Unused Pad hints no longer tell the user to re-run --pad-from when pad+balance were already paired. Covered by cli/tests/test_pad_from_matching_balance.py. Shipped with this board close.

# `bea --json check` forwards bean-check flags into `bea-engine check`, which rejects them

**Severity:** major. **Estimate:** 45–60 minutes. **Owner:** cli. **A1:** an
agent that follows `bea check --help` (which advertises bean-check's `-v`,
`--auto`, …) and also uses global `--json` gets a false "engine did not
answer" validation failure instead of a check result or a clear usage error.

Found 2026-09-15 by continuous CLI QA against `main`, HEAD `c181f6d2`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated `BEA_CONFIG_DIR` /
`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`. Synthetic fixtures only.

## Repro

```sh
bea --file main.bean check -v          # works: bean-check timings on stderr, exit 0
bea --json --file main.bean check -v   # fails
echo exit=$?
# stderr JSON:
# {"error":{"category":"validation",
#   "message":"The Beancount engine did not answer 'bea-engine check --file … -v' (exit 2).",
#   "details":["… No such option: -v …"]}}

bea --json --file main.bean check --auto     # same shape, "No such option: --auto"
bea --json --file invalid.bean check --allow-errors  # same; --allow-errors is not a check option either
```

Working control: `bea --json --file main.bean check` (no extra args) returns the
envelope with `data.valid` / `data.errors`. Human `bea check -v` and
`bea check --auto` succeed via bean-check.

Evidence: `cli/tmp/qa-20260915/evidence/361-v.err`, `362-auto.err`,
`351-ae-json.err`, `check-help.txt`.

## Expected / actual

`bea check --help` epilog documents the native bean-check interface, including
`-v` / `--verbose` and `-a` / `--auto`. Global `--json` is documented to wrap
check in bea's envelope (`USAGE.md:807`, `check.py` comment at line 16).

Expected under `--json` + a native-only flag: either honour the flag inside the
JSON path, or exit **2** with a usage error that names the unsupported flag and
says to drop `--json` for bean-check's native options — never a validation
"engine did not answer" wrapping Click's help box.

Actual: `check.py:17` always does
`helper_json(["check", "--file", str(file), *ctx.args])`, so bean-check flags
land on `bea-engine check`, which only accepts `--file`. Click's "No such
option" becomes exit 2 from the helper; `launch.helper_json` surfaces that as
category `validation` with the raw rich-traceback details.

## Root cause

```text
cli/src/cli/main.py:210          _CHECK_CTX allow_extra_args + ignore_unknown_options
cli/src/cli/commands/check.py:15-18
  if json: helper_json(["check", "--file", file, *ctx.args])
  else:    run_native("bean-check", [file, *ctx.args])
```

Human and JSON paths intentionally diverge (envelope vs native streams), but
extra args are shared. `src/bea_engine/main.py` `check` has no `-v`/`--auto`.

## Fix

Pick one consistent policy and test it:

1. **Preferred:** under `--json`, if `ctx.args` is non-empty, raise `UsageError`
   listing the forwarded tokens and stating that bean-check options (`-v`,
   `--auto`, …) require running without `--json` (or name the subset you will
   implement in the engine). Empty args keep today's envelope behaviour.
2. **Alternative:** implement the useful native flags on `bea-engine check` and
   map them; still translate unknown options to `usage` exit 2, not
   "engine did not answer" / `validation`.

Do not leave Click help / box-drawing characters inside JSON `details` for a
flag the frontend deliberately forwarded. Add regressions for
`bea --json check -v`, `--auto`, and a nonsense flag; keep human `-v`/`--auto`
green.

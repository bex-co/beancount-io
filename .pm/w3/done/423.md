# The interactive `bea query` shell still truncates column headers (`count(*)` → `co`)

**Severity:** minor. **Estimate:** 15–20 minutes. **Owner:** cli. Follow-up
to w3/253, which fixed one-shot text tables only.

Found 2026-09-25 by CLI QA (`qa-find-bugs-cli`) against `main` HEAD
`8cd9732b`, `uv run bea` 0.3.0, Darwin 25.5.0 arm64, driven through a real
PTY. Synthetic ledger (12 postings).

## Repro

```text
$ bea --file main.bean query
beanquery> SELECT count(*);
co
--
12
```

Controls: the one-shot `bea query 'SELECT count(*)'` and piped stdin
(`printf 'SELECT count(*);\n' | bea query`) both print `count(*)`.

## Root cause

`cli/src/bea_engine/query.py:179–183` sets `shell.settings.narrow = False`
for the one-shot path, but the interactive path at `query.py:302` builds
the shell with upstream's default `narrow=True`, which beanquery's
`render_text` uses as a width of 1 (see w3/253).

## Fix

Set `narrow = False` as the interactive default too; `.set narrow true`
remains available.

## Acceptance

- In a PTY session `SELECT count(*);` prints the full `count(*)` header;
  a test drives the interactive shell and asserts it.

# `bea add custom` with no `--value` writes a directive that crashes Beancount's pad plugin (`values is None`)

**Severity:** major. **Estimate:** 30–45 minutes. **Owner:** cli. **A1:** an
agent exploring `add custom` (or omitting values) can leave the ledger unloadable
under the default pad plugin; `--allow-errors` still writes the poison line.

Found 2026-09-15 by continuous CLI QA against `main`, HEAD `b4e9c1c4`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
bea --json --file main.bean add custom --date 2024-03-01 --type budget
echo exit=$?
# exit 1 — nothing written (good), but the error is a pad-plugin TypeError traceback:
# Error applying plugin "beancount.ops.pad": … TypeError: 'NoneType' object is not iterable
#   for custom_value in entry.values:

bea --json --file main.bean add custom --date 2024-03-01 --type budget --allow-errors
echo exit=$?
# exit 0 — WRITES:
#   2024-03-01 custom "budget"
# and returns the same TypeError in data.warnings
```

After the `--allow-errors` write, `bea check` stays red with the same traceback.
Working control:

```sh
bea --json --file main.bean add custom --date 2024-03-01 --type budget --value 'text:x'
# writes: 2024-03-01 custom "budget" "x"
# bea check → green
```

## Expected

Reject zero-value customs at the CLI with a clear usage error (custom directives
need at least one `--value`, or write `values=[]` in a form Beancount loads as
an empty list — not `None`). Never write a line that makes the default loader
raise `TypeError` inside `beancount.ops.pad`. `--allow-errors` must not persist
directives that break plugin iteration.

## Actual

Empty `values` serializes as `custom "budget"` with no value tokens; Beancount
loads `entry.values is None`; realization/pad crashes. Validation surfaces that
as a plugin traceback instead of a field error.

## Root cause

```text
cli/src/bea_engine/ledger/writer.py:289-306  write_custom → Custom(..., values=values)
# empty list may still print with no value tokens
beancount/core/realization.py:311  for custom_value in entry.values  # None → TypeError
beancount/ops/pad.py:56
```

## Fix

1. Require ≥1 `--value` in `bea add custom` (usage exit 2), matching practical
   Beancount customs, **or** emit a trailing form that parses to `values=[]`
   if that is valid upstream.
2. Do not treat pad `TypeError` on `values is None` as a reason to allow
   `--allow-errors` writes — keep the file unchanged.
3. Regression: no `--value` → usage error, file unchanged; `--value text:x` OK;
   never leave `custom "budget"` alone on disk via `--allow-errors`.

---

**Resolved 2026-09-16** — `bea add custom` now requires at least one `--value` (usage exit 2) in the CLI and engine; empty customs are never written even with `--allow-errors`. Covered by `cli/tests/test_custom_requires_value.py`. Shipped with this board close.

# `bea query` `GROUP BY accounts` crashes with `issubclass() arg 1 must be a class`

**Severity:** minor. **Estimate:** 30–60 minutes. **Owner:** cli. **A1:**
`SELECT accounts, count(*) FROM transactions GROUP BY accounts` exits **1**
with a raw Python TypeError, while `GROUP BY tags` gets a clear non-hashable
compilation error.

Found 2026-09-16 by continuous CLI QA ([c1000 hunt](615ca31f-5363-43fb-973a-c3b72382c343)),
HEAD `98a92d0e`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Confirmed
`cli/tmp/qa-20260915/c1001/`. Evidence: `c1000/`.

## Repro

```sh
bea --file main.bean query \
  'SELECT accounts, count(*) FROM transactions GROUP BY accounts'
# exit 1 — issubclass() arg 1 must be a class

bea --file main.bean query \
  'SELECT tags, count(*) FROM transactions GROUP BY tags'
# exit 2 — GROUP-BY a non-hashable type is not supported
```

## Expected

Same actionable non-hashable message as tags/links (or a supported flatten
recipe) — never a Python TypeError.

## Actual

`accounts` is typed `set[str]`; beanquery’s `issubclass(dtype, Hashable)`
raises TypeError on parameterized generics.

## Fix

Treat parameterized set dtypes like plain sets before `issubclass`. Regression:
repro exits 2 with the non-hashable wording; `DISTINCT accounts` unchanged.

## Dedupe

Related to w3/353 (DISTINCT tags/links). Not w3/247. No open note covers
`GROUP BY accounts` crash.

# Give contentless push activities honest feed titles instead of "Committed to X"

Source: continuous dashboard QA, 2026-10-04.
Pillar: A2 — the dashboard Activity feed must not show mystery entries that look like duplicate or broken commits.

The ledger activity feed can return a `commit_repo` push whose commit list is empty while a head SHA is present (e.g. pushing an existing tip under a new ref). It renders as "Committed to example" with a bare commit hash and no message — directly beside the same commit's real entry — and a sibling contentless activity renders as a header-only "Committed to example" card with no detail at all. Both look like duplicates or loading failures.

Mechanism (verified in code; the exact upstream op that produced the observed pair is unverified from the client side): `transformActivityToFeedItem` (`backend-cluster/backend-v2/src/features/gitea/feed/service/activity-transformer.ts:173`) never drops contentless pushes, `summarizeParsedContent` returns `""` for an empty push commit list (`activity-content-parser.ts:272`), `generateActivityLink` still links the head SHA, and unmapped op types fall back to the `commit_repo` title template (`activity-transformer.ts:140`).

Repro: dashboard `/ledger` Activity on an account whose repo has a ref push of an existing tip; observe a "Committed to <repo>" card with a hash but no message (and/or a header-only card) duplicating an adjacent commit's SHA.

Acceptance: contentless push-like activities either get an honest title/summary from their op type and ref (never a bare "Committed to X" with no message) or are skipped when they carry nothing a reader can act on; the same commit no longer appears as both a messaged and a bare card from one action. Cover the new titling/skip rule with transformer unit tests, run the backend-v2 checks, and ship.

Scope: backend-v2 feed service only; the dashboard renders what the API sends. Estimated under one hour.

---

**Resolved 2026-10-04** — `transformActivityToFeedItem` now skips `commit_repo` / `mirror_sync_push` activities that introduced no commits or carry no content (their head commit already has its own card from the push that introduced it), gives unknown op types a neutral `Activity in <repo>` title instead of `Committed to <repo>`, names refs by their short names, and titles Gitea's branch creation (recorded as `push_tag` with a `refs/heads/` ref) as `Created branch <name>`. Transformer tests cover the skip, kept pushes, ref titles and the fallback (4 fail with the rule disabled); backend-v2 typecheck, lint, 5,013 tests and the OpenAPI drift check passed. The exact upstream op behind the observed pair stays unverified from the client side, as the note said. Shipped in `3608b77c` (`backend-cluster/backend-v2`).

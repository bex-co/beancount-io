# `/register` and `/signup` answer 503 "no available server" instead of a redirect or a 404

**Severity:** minor. These are two guessable sign-up URLs, and a newcomer who types one sees an infrastructure error page, not the sign-up form. **Estimate:** 20–30 minutes once the owner is found. **A2:** a newcomer guessing the sign-up URL should land on sign-up, not on an error.

## Observed (production `https://beancount.io`, 2026-11-16, signed out, read-only)

| Path | Response |
| --- | --- |
| `/register` | HTTP 503, body `no available server` |
| `/signup` | HTTP 503, body `no available server` |
| `/login` (control) | redirects to `/auth/login` |
| `/nonexistent-qa-path-xyz` (control) | the dashboard's normal 404 page |

The body reads like an edge proxy whose route for these paths points at a backend that does not exist. Neither path is a route in `dashboard/src/routes`. Nothing under `deploy/` or in `bex.yaml` mentions them. The rule is most likely in the production edge configuration or the separate website repository. Neither is in this monorepo.

## Fix

1. Find which layer answers these two paths. `/login` already redirects, so start with whatever rule produces that redirect.
2. Make both paths redirect (3xx) to `/auth/sign-up`, the way `/login` redirects to `/auth/login`. If redirecting is not wanted, remove the dead route so the normal 404 page answers.
3. If the rule lives outside this repository, block this note with that owner named as the one who can clear it.

**Acceptance:** `curl -sI https://beancount.io/register` and `curl -sI https://beancount.io/signup` each return either a 3xx to `/auth/sign-up` or the dashboard's 404 page, never a 503.

**Dedupe:** searched `.pm/**` for `no available server`, `/signup`, and `/register`. Only the w4/137 sign-up form hydration note matched, which is unrelated.

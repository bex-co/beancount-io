# Portable price export overwrites a copied local price file with a generated feed file

**Major · 40–55m · cli · A1.** A local file named `prices/BTC-USD.beancount`
collides with the generated export for the managed BTC-USD feed. Export
reports success but loses the local manual price and writes two includes of
the same generated file. Original source files remain intact.

Found 2026-09-21 at HEAD `d5e8e06d`, checkout `bea 0.3.0`, Python 3.13.0,
macOS 26.5.1 arm64. Repeated in two pristine directories with real commands,
closed stdin and isolated config/cache. All commands used `--offline` with
no cached revision and no credentials; no HTTP request or server defect is
claimed. `--allow-errors` intentionally permits the documented marker-only
export for the unavailable feed, not loss of independent local data.

## Reproduce

`/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"
include "prices/BTC-USD.beancount"
include "https://beancount.io/prices/BTC-USD"
2026-01-01 open Assets:Crypto BTC
2026-01-01 open Equity:Opening BTC
2026-01-02 * "Holding"
  Assets:Crypto 1 BTC
  Equity:Opening
```

`/absolute/books/prices/BTC-USD.beancount`:

```beancount
2026-01-02 price BTC 100 USD
```

```sh
bea --json --offline --file /absolute/books/main.bean list price --allow-errors
# exit 0; one local BTC price, 100 USD; expected unavailable-feed warning
bea --json --offline --file /absolute/books/main.bean price export \
  --output /absolute/snapshot --allow-errors
# exit 0; success envelope, plus the expected unavailable-feed warning
bea --json --offline --file /absolute/snapshot/main.bean list price --allow-errors
# exit 0; data=[]; stderr now warns Duplicate filename parsed
```

Both source include lines become `include "prices/BTC-USD.beancount"` in the
snapshot. That destination contains only a `bea-managed-error` comment and a
`custom "bea-managed-source"` marker; the copied 100 USD price is gone.
The JSON `files` array even lists the same destination twice. Both fresh
reproductions agree, and source hashes are unchanged.

Expected: local ledger data and generated feed artifacts have distinct
destinations, with each rewritten include targeting its correct file.
Retain the manual 100 USD price. An accurate pre-write collision refusal is
preferable to a successful corrupted snapshot, but a collision-free naming
policy preserves the intended portable export journey.

Controls: change only the local basename to `prices/manual.beancount` and its
include. With the same offline unavailable feed and `--allow-errors`, export
then retains the 100 USD price; a fresh `list price` and `check` of the exported
ledger both succeed without duplicate-file errors. Without `--allow-errors`,
the unavailable feed is correctly refused before any export file is created.

## Cause and scoped repair

`cli/src/bea_engine/managed_load.py:545` builds copied-file `destinations`
preserving their paths under the root. At line 553 it independently assigns
each managed feed to `target / "prices" / f"{source.alias}.beancount"`, with
no check against those destinations. The first write loop copies the local
file; the second loop overwrites it with `_export_feed_text`. The include
rewriter correctly follows both maps, which now point to the same file.

Allocate the complete destination map before writes, accounting for both
copied files and generated feed files. Choose deterministic distinct names
on collision and rewrite includes using that mapping, or refuse atomically
before writing. Do not discard the local price or merge unrelated files by
basename. Preserve effective-feed content, manual-price precedence and
portable relative includes. Cover both unavailable-marker and cached-feed
cases in implementation tests; only the marker case is reproduced here.
No dependencies or backend/API changes are needed.

The frontend `price._export` and engine `price-export` both use this helper.
Its mapping also allocates `_shared/` paths and supports multiple sources;
those additional collision shapes are source-traced, not separately tested.
Other OSes, live/cached managed prices and a repaired implementation remain
unverified.

---

**Resolved 2026-09-22** — a generated feed no longer overwrites a copied local
file in the snapshot.

`export_portable` built two destination maps independently, so a ledger that
legitimately keeps its own `prices/BTC-USD.beancount` beside a managed
`BTC-USD` feed had the copy written over by the generated file: the manual
price gone, the same file included twice, and `list price` on the snapshot
returning nothing with a `Duplicate filename parsed` warning — all at exit 0.

Feed destinations are now allocated **against** the copied files. The copies
keep their relative paths, because that is what makes the export portable, so
the generated file is the one that moves: `_free_feed_path` takes the plain
`<alias>.beancount` when it is free and otherwise steps to `-managed`, then
numbered. Deterministic, so re-exporting the same tree produces the same
names. Two managed sources sharing an alias are handled by the same set, since
each allocation is recorded as it is made.

I chose the collision-free naming policy over a pre-write refusal. The note
allowed either but said a refusal is only "preferable to a successful corrupted
snapshot", while "a collision-free naming policy preserves the intended
portable export journey" — and this case is a perfectly reasonable ledger that
should simply export.

Verified on the note's fixture: the manual 100 USD price survives and is
readable from the snapshot, the two includes point at two different files, the
reported `files` array has no duplicate, and the exported ledger both loads
without a duplicate-filename warning and passes `check` with `valid: true`.
Controls hold — a non-colliding local name leaves the feed at its plain
`BTC-USD.beancount` with no needless suffix, and without `--allow-errors` the
unavailable feed is still refused before the destination is created.

Regression coverage is `cli/tests/test_price_export_name_collisions.py`,
including unit tests of the allocator's determinism. Reverting the allocation
fails 4 of its 9. `cd cli && make check-all` passes (1999 tests).

Unverified, as in the note: the cached-feed case (only the unavailable-marker
case is reproduced — the collision is in destination allocation, which runs
before any feed content is rendered, so it is content-independent by
construction), `_shared/` collision shapes, and other platforms.

# Add the missing accessible description to the Entry Context dialog

Source: continuous dashboard QA, 2026-10-04.
Pillar: A2 — assistive-technology users opening a journal entry need the dialog announced with its purpose, and the console must stay clean.

Opening Entry Context (overview Recent activity row, or any journal row) logs `Warning: Missing Description or aria-describedby={undefined} for {DialogContent}` — the only console warning across a full production sweep — and leaves screen-reader users without a dialog description.

Root cause: `dashboard/src/features/journal/components/entry-context-dialog.tsx:142` renders `DialogContent` with a `DialogTitle` but no `DialogDescription` (or `aria-describedby`). Sibling dialogs (`new-directive-dialog/index.tsx`, `entry-context-panel.tsx`, `export-journal-button.tsx`) all include one.

Repro: open `/ledger/open_ledger/example`, click any Recent activity row, watch the console.

Acceptance: opening Entry Context logs no Radix warning and exposes an accessible description naming the entry it shows; focus entry/return behavior is unchanged. Cover with the existing dialog test setup, run the dashboard checks, and ship.

Scope: dashboard journal only. Estimated under one hour.

---

**Resolved 2026-10-04** — `entry-context-dialog.tsx` now renders a visually hidden `DialogDescription` naming the entry it shows (`journal.entryContextDescription`, "Source and file location for <date · payee · narration>", in all 15 locales) and opts out explicitly with `aria-describedby={undefined}` when there is no entry. A dialog test asserts the accessible description and the absence of the Radix warning (it fails on the old component); existing focus tests unchanged. Dashboard format, lint, 4,951 tests and build passed. Shipped in `045b95c6` (`dashboard`).

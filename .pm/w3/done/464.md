# Hide custom QueryView loading skeletons from assistive technology

Source: continuous dashboard QA, 2026-10-04.
Pillar: A2 — screen-reader users must hear a loading status, not an empty phantom table, while ledger data loads.

Pages that pass a custom `loadingSlot` to `QueryView` expose their skeleton markup to the accessibility tree: on Accounts, AT observes a 7-column table of empty headers and rows during load. `QueryView` (`dashboard/src/common/components/query-view.tsx:33`) returns `loadingSlot` with no busy/hidden wrapper, while the default `ReportLoadingState` correctly uses `role="status"` with `aria-live` and `aria-busy`.

Blast radius: every custom `loadingSlot` caller — ledger-data `accounts`, `settings`, `commodities`, `documents`, `errors`, `events`, and `budget` pages. Working control: the activity feed wraps its skeletons in an `aria-busy` region with `aria-hidden` cards.

Repro: throttle or cold-load `/ledger/open_ledger/example/accounts`; inspect the accessibility tree before data arrives — empty table headers and cells are exposed.

Acceptance: while loading, AT receives a busy/loading announcement and no phantom tables on any `QueryView` consumer — preferably via one shared wrapper in `QueryView` rather than seven caller edits. Add a test asserting the loading output is hidden-or-busy, run the dashboard checks, and ship.

Scope: dashboard shared component (plus removal of any now-redundant caller attributes). Estimated under one hour.

---

**Resolved 2026-10-04** — `QueryView` now renders any custom `loadingSlot` inside a new shared `SkeletonLoadingState` (`state-components.tsx`): a `role="status"` / `aria-live="polite"` / `aria-busy="true"` region with a screen-reader `common.loadingData` message and the skeleton `aria-hidden`, covering all seven callers with no caller edits (none carried attributes to remove). A `query-view` test asserts the busy status and that a skeleton table and its headers are absent from the accessibility tree (fails on the old component). Dashboard format, lint, 4,954 tests and build passed. Shipped in `8fedfcbe` (`dashboard`).

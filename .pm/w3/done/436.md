# `bea price export --output DIR` silently overwrites whatever already lives in DIR, including another ledger's `main.bean`

**Severity:** major (silent data loss of a file the command was never given).
**Owner:** cli. **Estimate:** 30–45 minutes. **A2:** the export guard already
refuses the one directory it knows about and tells the user to "choose an empty
or dedicated directory" — but any *other* directory is overwritten without a
word, so pointing the snapshot at an existing folder destroys it.

Found by continuous CLI QA 2026-09-26, `uv run bea` 0.3.0 at HEAD `8cd9732b`,
Darwin 25.5.0, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, synthetic ledgers,
closed stdin, authorized QA account for the managed feed.

## Repro

```sh
# books/main.bean — a ledger with one managed price include
cat > books/main.bean <<'EOF'
option "operating_currency" "USD"
include "https://beancount.io/prices/BTC-USD"
2024-01-01 open Assets:Crypto BTC
2024-01-01 open Equity:Opening
2024-01-02 * "buy"
  Assets:Crypto  0.5 BTC {40000 USD}
  Equity:Opening
EOF

# an unrelated ledger of the user's, in the directory they pick for the snapshot
mkdir -p audit
printf 'option "title" "OTHER LEDGER"\n2020-01-01 open Assets:Other USD\n' > audit/main.bean

bea --file books/main.bean price export --output audit
# Exported 2 files to …/audit.      exit 0, no warning
head -1 audit/main.bean             # option "operating_currency" "USD"  — the other ledger is gone
```

The pre-existing `audit/main.bean` is replaced by the exported copy of
`books/main.bean`. Exit 0, no warning on stdout or stderr, nothing in the JSON
answer's `files` list marks a file as overwritten.

Working control in the same session: `price export --output books` (the ledger's
own directory) is correctly refused — *"Cannot export into …/books: it holds
main.bean, which the export would overwrite. Choose an empty or dedicated
directory."* — and writes nothing. The default `<ledger>-export/` destination
has the same exposure when that directory already exists.

## Expected

An export that would replace a file it was not given refuses before writing
anything, naming the colliding path, and offers the same opt-in the neighbouring
command already has (`bea example -o` refuses an existing destination unless
`--force`). The rationale is already written into the existing error message;
it just is not applied to collisions outside the ledger's own directory.

## Root cause

`cli/src/bea_engine/managed_load.py` `export_portable` (~l.549–555) checks only
whether the resolved target *is a directory that holds one of the source
files*:

```python
for path in snapshot.contents:
    if resolved_target == path.parent.resolve():
        raise UsageError(f"Cannot export into {target}: it holds {path.name} …")
```

The later plan check (~l.589–602) compares planned destinations against the
source files with `os.path.samefile` and confirms nothing lands outside the
target — both protect the *source*, neither protects an unrelated pre-existing
file at a planned destination. The write loops then
`dest.write_bytes(...)` / `shutil.copyfile(...)` unconditionally.

## Fix

In `export_portable`, after the plan is assembled (`planned`, i.e. copied ledger
files, feed files and attachments) and before the first write, collect every
planned destination that already exists and refuse with a `UsageError` naming
them and the count, "Nothing was written." Add an explicit opt-in for the
deliberate case — re-exporting into the same snapshot directory is normal — via
a `--force`/`--overwrite` flag threaded through `bea price export`
(`cli/src/cli/commands/price.py` `_export`, which today accepts only `--output`
and `--allow-errors`) and the `price-export` engine command in
`cli/src/bea_engine/main.py`. Document it beside the existing
`bea price export --output audit` example in `cli/docs/USAGE.md` (~l.973–990).

Regression coverage: export into a directory containing an unrelated
`main.bean` refuses and leaves that file byte-identical; the same export with
the new flag succeeds; a fresh directory is unaffected; re-export into the
directory a previous export created still works with the flag.

## Blast radius

`bea price export` with and without `--output`, and the default
`<ledger>-export/` destination. Same class as w3/done/409 (doctor roundtrip
deleting pre-existing sibling files), which was treated as a bug and fixed.
Distinct from w3/done/412 (a `..` component letting the export reach its own
source) and w3/done/413 (a generated feed file overwriting a *copied* local
price file) — both are about the export's own inputs and its internal
collisions; this is a third-party file in the chosen destination. `--output FILE`
commands (`query -o`, `format --output`) overwrite an existing file by ordinary
CLI convention and are not in scope; the difference here is that the user names
a *directory* and the command chooses the filenames inside it.

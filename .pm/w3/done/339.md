# `bea add transaction` inferred-zero balancing posting vanishes from `list` / query

**Severity:** minor. **Estimate:** 20–35 minutes. **Owner:** cli. **A1:** an
agent that books `Expenses:Food 0 USD` + bare `Assets:Cash` gets exit **0** and
both lines on disk, but `list transaction` / BQL show only Expenses:Food.

Found 2026-09-16 by continuous CLI QA ([c810 hunt](99ddfd9b-ac04-4cdf-9492-7e525277afb3)),
HEAD `419d18f9`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Confirmed
`cli/tmp/qa-20260915/c804/`. Evidence: `c810/`.

## Repro

```sh
bea --file main.bean add transaction --date 2020-05-01 --narration z \
  --posting 'Expenses:Food 0 USD' --posting 'Assets:Cash'
# disk has both legs

bea --file main.bean list transaction
# POSTING AMOUNTS: Expenses:Food: 0 USD  (Assets:Cash omitted)

# control: explicit `Assets:Cash 0 USD` lists both accounts
```

## Expected

List/query agree with the written source (include the Cash leg as 0), or
`add` refuses a no-op zero-net write.

## Actual

Beancount realizes the bare leg as inferred 0 and drops it from
`entry.postings`; `reader.py` maps only realized postings.

## Fix

Reject zero-net inferred adds, or serialize source legs including zero
inferred. Regression: repro lists both or errors on add; explicit `0`/`0`
unchanged; nonzero inference unchanged.

## Dedupe

Not w1/done/012 (import fingerprint zeros). Not w3/315/321/323. No open note
covers inferred-zero balancing legs missing from CLI list/query.

## Objective

Attach a `requestId` to every `BulkEntries` and `InsertReceiptTransaction` save, mint a new one whenever the content changes, and handle in-progress and exhausted retries gracefully.

## Context

- Callers: `features/journal/components/new-directive-dialog/*-form.tsx`, `features/importer/hooks/use-import-submit.ts`, `features/ledger-data/accounts/{open,close}-account-dialog.tsx`, `features/ledger-data/budget/add-budget-dialog.tsx`, `features/receipt/hooks/use-receipt-workflow.ts`.

## Acceptance criteria

- [x] A double submit records one entry.
- [x] In-progress → automatic bounded backoff retry with the same id; the user sees saving, then success.
- [x] Exhausted retries → "may already be saved" message and journal refetch; no endless spinner.
- [x] Editing after a failure mints a new id; `yarn format:check`, `yarn lint`, `yarn test`, and `yarn build` pass.

## Out of scope

- Mobile.

## Done 2026-11-03

- `common/lib/entry-write/entry-write.ts`: `useEntryWrite()`.
  - `withRequestId(variables)` names a save `<form nonce>-<FNV-1a fingerprint of the variables>`, so a resend of the same content reuses the id and an edit mints a new one.
  - `send(write)` retries the server's in-progress `CONFLICT` (`extensions.resource: "Entry write"`) after 1, 2, and 4 s with the same id.
  - When retries run out, it throws `EntryWriteMaybeSavedError`, which `getErrorMessageKey` shows as `common.errors.entryMaybeSaved` (all 15 locales), and refetches the active queries, the journal among them.
  - The nonce renews after every save and each time a form is opened, so two identical coffees saved one after the other stay two entries.
- Wired into every entry save:
  - The New Entry transaction, note, balance, and open forms.
  - Smart Import submit.
  - The Accounts open and close dialogs.
  - Add Budget.
  - Receipt insert (`InsertReceiptTransaction`).
- The operations `BulkEntries` and `InsertReceiptTransaction` take `$requestId`, and `definitions.ts` was regenerated from backend-v2's printed schema; only these operations changed.
- Tests:
  - `entry-write.test.ts` (8): backoff, bounded give-up, other errors passed through, fingerprint, id stability, renewal and retention, and the refresh on maybe-saved.
  - `retry-safe-submit.test.tsx` (3): an in-progress retry resends the same id; resend after a refusal keeps the id while an edit changes it; two identical saves get two ids. All three fail on the previous form.
  - 24 suites that mock `@apollo/client/react` gained a `useApolloClient` stub, and two exact-variable assertions now allow `requestId`.
- Gates: `yarn format:check`, `yarn lint` (tsc, ESLint, Knip, i18n), `yarn test` (7688), and `yarn build` pass.
- **Deploy order:** backend-v2 (`fcf984b59`) before the dashboard, because an older GraphQL schema rejects the new `requestId` argument.

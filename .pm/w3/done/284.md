# `bea add … --meta filename:…` / `lineno:…` fails with a misleading “must be key:value” error

**Severity:** minor. **Estimate:** 15–25 minutes. **Owner:** cli. **A1:** an
agent that copies Beancount source-location keys into `--meta` (or uses an
uppercase-leading key like `Filename:x`) is told the pair is not `key:value`
when it already is — the real rule (reserved keys / key pattern) is hidden.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `70a68abd`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
bea --json --file main.bean add transaction --date 2020-05-01 --narration m \
  --meta 'filename:x' \
  --posting 'Assets:Cash -1 USD' --posting 'Expenses:Food 1 USD'
# exit 2
# {"error":{"category":"usage",
#   "message":"Each --meta must be 'key:value', such as 'receipt:IMG_1234.jpg'; use '\"\"' for empty text.",
#   "exit_code":2}}

bea --json --file main.bean add transaction --date 2020-05-01 --narration m \
  --meta 'lineno:1' \
  --posting 'Assets:Cash -1 USD' --posting 'Expenses:Food 1 USD'
# exit 2 — same generic message

bea --json --file main.bean add transaction --date 2020-05-01 --narration m \
  --meta 'Filename:x' \
  --posting 'Assets:Cash -1 USD' --posting 'Expenses:Food 1 USD'
# exit 2 — same generic message (key must start with [a-z])
```

Working controls:

```sh
bea --json --file main.bean add transaction --date 2020-05-01 --narration m \
  --meta 'receipt:IMG_1.jpg' \
  --posting 'Assets:Cash -1 USD' --posting 'Expenses:Food 1 USD'
# exit 0

bea --json --file main.bean add transaction --date 2020-05-01 --narration m \
  --meta 'file-name:x' \
  --posting 'Assets:Cash -1 USD' --posting 'Expenses:Food 1 USD'
# exit 0 — hyphenated non-reserved key works
```

## Expected

Separate usage errors that name the actual rule:

- `filename` / `lineno` are reserved (Beancount source location); choose another
  key.
- Keys must match `[a-z][A-Za-z0-9_-]*` (or whatever the CLI documents).
- Keep the existing “must be key:value” / empty-value message for true shape
  errors (`nocolon`, `key:`, `:value`).

## Actual

`_parse_metadata` in `bea_engine/ledger/adding.py` folds four conditions into
one `UsageError`: missing `:`, bad key pattern, `key in {"filename","lineno"}`,
and empty value. Agents cannot tell reservation from a typo.

## Fix

Split the guard into distinct messages (reserved keys, pattern, empty value,
missing separator). Regression: the three repros above get specific text;
`receipt:…` and `file-name:…` still succeed; `nocolon` still gets the shape
message.

## Dedupe

Not w3/229 (single-letter keys mis-blamed on postings after parse). Not
w3/235 (bool `--meta`). Not w3/255 (empty required fields). No open note
covers reserved `filename`/`lineno` or the collapsed `--meta` validation
message.

**Resolved 2026-09-16** — `--meta` validation splits reserved `filename`/`lineno`, key pattern, and shape errors into distinct usage messages. Covered by `cli/tests/test_meta_reserved_keys.py`. Shipped with this board close.

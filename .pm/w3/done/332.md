# `bea format -i` / `--check` on a split-ledger root leaves includes unformatted but reports green

**Severity:** minor. **Estimate:** 30–45 minutes. **Owner:** cli. **A1:** an
agent or pre-commit that runs `bea format -i main.bean` / `format --check
main.bean` on a root with `include "child.bean"` believes the whole book is
aligned (exit **0**) while `child.bean` still fails its own `--check`.

Found 2026-09-16 by continuous CLI QA ([c740 hunt](63533b51-1d88-40ba-ba0f-bf8a474ff8e4)),
HEAD `b85e2621`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache.
Evidence: `cli/tmp/qa-20260915/c740/`, `c750/` (confirm).

## Repro

```sh
# main.bean includes child.bean; both need amount alignment
bea format --check main.bean   # exit 1
bea format --check child.bean  # exit 1

bea format -i main.bean        # exit 0 — root only
bea format --check main.bean   # exit 0 — “All 1 file(s) are formatted”
bea format --check child.bean  # exit 1 — child still misaligned

# Control — directory walk reaches both:
bea format -i .
```

## Expected

Root format/`--check` either walks `include` edges (like load) or clearly
states that only the named path is scoped and included siblings are unchecked.
A green `--check main.bean` must not imply the split ledger is fully aligned.

## Actual

`_targets()` expands only explicit paths/directories — no include graph. Root
`-i`/`--check` never sees `child.bean`.

## Fix

When formatting a ledger file, optionally follow includes (or warn under
`--check` that N included files were not scanned). Regression: after
`format -i main.bean`, either child is aligned or `--check main.bean` is not
green without disclosing skipped includes.

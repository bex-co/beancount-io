## Objective

Prove the guard holds where it matters: the mutation must not fire without confirmation, from any caller, by pointer or keyboard.

## Context

- The strongest assertion is on the mutation itself — spy on the delete mutation and assert it is **not** called when Delete is clicked and the confirmation is cancelled or dismissed, and called exactly once when confirmed.
- Existing suites: `dashboard/src/features/journal/components/__tests__/`, plus the account and overview callers' own tests. Note that some page-level suites mock the dialog away, so the behavioral assertions belong with the component.
- Cover: cancel, Escape, confirm, double activation, and the read-only case where Delete is absent.

## Steps

1. Add component tests asserting the mutation is not called on cancel/Escape and called once on confirm.
2. Add a double-activation test.
3. Assert focus returns to the Delete button after cancel.
4. Confirm each test fails with the confirmation removed.

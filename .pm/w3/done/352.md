# `bea doctor region` / `linked` balance tree mis-reports fractions when later postings lack decimals

**Severity:** minor. **Estimate:** 30–60 minutes. **Owner:** cli. **A1:**
`doctor region` and `doctor linked` on a `5.50 USD` coffee show `-6 USD` /
`6 USD` in the balance tree when a later posting uses `100 USD` (no decimal),
while `Net Income` stays `-5.50 USD`.

Found 2026-09-16 by continuous CLI QA ([c940 hunt](86942cc6-e772-46a9-a761-22e91c5cff60)),
HEAD `c4675837`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Confirmed
`cli/tmp/qa-20260915/c943/`. Evidence: `c940/`. Extended 2026-09-16 for
`doctor linked` ([c1050 hunt](fb67bbd7-d530-4c61-9ec2-9cd79babebbd)), HEAD
`4136af4b`; evidence `c1050/` (`repro-bad.bean` / `repro-good.bean`).

## Repro

```sh
# Coffee 5.50; later txn "100 USD" without decimals
bea doctor region main.bean 8:10
# tree: Checking -6 USD, Food 6 USD; Net Income: (-5.50 USD)

bea doctor linked main.bean ^coffee-feb
# same poisoned tree vs Net Income

# control: later amounts as 100.00 USD → tree shows -5.50 / 5.50
```

## Expected

Region/linked balance trees match the scoped postings (and Net Income),
independent of later amount literal formatting.

## Actual

Later whole-number amount tokens poison tree formatting precision for earlier
regions and linked transactions; Net Income stays exact. Same upstream
`bean-doctor` display path for both subcommands.

## Fix

Upstream `bean-doctor` (or bea wrappers) format trees from the scoped amounts.
Regression: both `region` and `linked` repros show `-5.50` / `5.50`.

---

**Resolved 2026-09-17** — Took the note's "bea wrapper" branch. Upstream formats
the balance tree with the *whole ledger's* display context, whose precision is
the most common one it saw, so a `5.50 USD` scope rounded to `6 USD` in a book of
whole-dollar amounts while `Net Income` — which does not go through that format —
still read `-5.50 USD`.

`bea doctor region` / `linked` now run upstream's own command inside the engine
(`bea-engine scoped`), where bea substitutes one thing: a display context built
from the entries upstream itself selected. Upstream keeps every decision — which
entries a link, tag, location or region selects, the realization, the
conversion, the rendering, the usage errors and the exit status — so nothing is
re-implemented (`.pm/DO_NOT_DO.md`). The tree and `Net Income` now agree in both
directions: a whole-number scope shows no trailing zeros either. The empty-scope
gate from w3/363 is untouched and still exits 1.

This is `bean-doctor`'s own renderer, not the `report`/`balance` display-context
work in w1/m27 t004 (w3/365), which is a different code path. Documented in
`cli/docs/USAGE.md`; covered by `cli/tests/test_doctor_scoped_precision.py`.
Shipped with this board close.

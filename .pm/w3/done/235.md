# `bea add transaction --meta 'cleared:true'` stores a string `"true"`, while bulk JSON boolean meta stores `TRUE`

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** cli. **A1:** an
agent setting boolean metadata from the human `--meta` form gets quoted
strings in the ledger; the same values via `add transactions` JSON write real
Beancount booleans, so the two write paths disagree.

Found 2026-09-15 by continuous CLI QA against `main`, HEAD `e093cc4b`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
bea --file main.bean add transaction --date 2024-03-26 --narration boolmeta \
  --posting 'Expenses:Food:Groceries 1 USD' --posting 'Assets:Bank:Checking' \
  --meta 'cleared:true' --meta 'flag:false' --meta 'count:3'
# writes:
#   cleared: "true"
#   flag: "false"
#   count: 3
```

Control — bulk JSON with real booleans:

```sh
bea --json --file main.bean add transactions --from rows.json
# rows.json meta: {"cleared": true, "flag": false, "count": {"kind":"number","value":"3"}}
# writes:
#   cleared: TRUE
#   flag: FALSE
#   count: 3
```

## Expected

`--meta 'cleared:true'` / `'flag:false'` should write Beancount boolean
metadata (`TRUE` / `FALSE`), matching the bulk JSON path and Beancount's own
`key: TRUE` syntax. If bare `true`/`false` cannot be parsed safely, reject with
a usage hint (`use true/false` or document only JSON for booleans) instead of
quietly quoting them as strings.

## Actual

CLI `--meta` parsing treats `true`/`false` as ordinary text values and the
printer emits quoted strings. Numbers still work (`count: 3`).

## Root cause

```text
cli/src/bea_engine/ledger/adding.py _parse_metadata
  # fallback / string path does not recognize boolean literals
# contrast: bulk JSON bool → metadata_for_write → TRUE/FALSE
```

## Fix

Teach `_parse_metadata` (or the Beancount meta parse path) to accept bare
`true`/`false`/`TRUE`/`FALSE` as booleans. Regression: `--meta cleared:true
--meta flag:false` writes `cleared: TRUE` / `flag: FALSE`; bulk JSON booleans
unchanged; `--meta note:trueish` still stays a string.

---

**Resolved 2026-09-16** — `--meta key:true`/`false` normalize to Beancount `TRUE`/`FALSE` via the metadata parser; `trueish` stays a string. Covered by `cli/tests/test_meta_boolean_literals.py`. Shipped with this board close.

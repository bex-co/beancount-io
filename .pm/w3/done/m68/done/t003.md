## Objective

A user who copies the HTTPS clone URL knows that the password prompt wants a personal access token, and where to get one. A user whose stored credential is stale knows how to clear it.

## Context

- Dashboard clone dialog: `dashboard/src/features/ledger-editor/directory-browse/components/ledger-clone-url-menu.tsx`. It shows `httpUrl` without saying what credential to use.
- Token page: `/settings/api-keys` (w3/m10).
- Docs that describe Git over HTTPS:
  - the doc comment on `setGitProxyHandler`
  - `backend-cluster/backend-v2/docs/authentication-rate-limits.md`
  - `deploy/docker/README.md`
  - `deploy/bex/README.md`
- A stale credential is a real failure mode. Git keeps retrying the stored value, and the retries spend the account's failed-password budget until it answers 429.

## Steps

1. Under the HTTPS option in the clone dialog, add one line: username anything, password a personal access token, with a link to `/settings/api-keys`. Keep SSH the first option.
2. Update the docs above. Show how to clear a stale credential: `printf 'protocol=https\nhost=<host>\n' | git credential reject`, the macOS Keychain entry for the host, and the line in `~/.git-credentials`.
3. Localize the new dashboard string the way neighboring strings are localized.

# Trial Balance never states whether it balances

**Minor · 45–60m · dashboard.** A1: the one page whose stated job is a balance check should perform the check.

Production https://beancount.io, 2026-09-12, isolated headless Chrome (Playwright MCP `--headless --isolated`), English/light, 1440×1000, authenticated QA account on its own synthetic `example` ledger. Local/fetched main `84231f9c`; deployed SHA unverified. Read-only.

Open `/ledger/<owner>/example/trial-balance?time=2017`. The page's own description reads "View the trial balance for example. **Verify that debits equal credits across all accounts.**" It then renders roughly 60 hierarchy rows across `Account / USD / Other` and stops. There is no total row, no per-unit sum, and no statement of whether the ledger balances. To do the thing the page says it is for, a reader must add ~60 rendered rows by hand, in three separate units.

The root rows are: Equity `-78,380.929` / `-25 VACHR`; Liabilities `-2,704.29`; Income `-93,588.9` / `-18,500 IRAUSD` / `-95 VACHR`; Assets `109,529.339` / `-8 VACHR`; Expenses `65,144.78` / `18,500 IRAUSD` / `128 VACHR`. Summed by hand they reconcile exactly — USD `109529.339 − 2704.29 − 78380.929 − 93588.9 + 65144.78 = 0`, VACHR `−25 − 95 − 8 + 128 = 0`, IRAUSD `−18500 + 18500 = 0`. So the data is correct and no calculation defect is claimed; the page simply withholds the conclusion.

Root: `dashboard/src/features/reports/trial-balance/trial-balance-content.tsx:276-280` renders `<HierarchyList data={hierarchyData} primaryCurrency={...} collapsePatterns={...} />` and passes no `summaryRows`. The mechanism already exists and a sibling report already uses it: `dashboard/src/features/reports/CLAUDE.md` documents `summaryRows` as the way aggregates reach that shared tree table ("plain unlinked rows below the detail rows"), and `features/reports/cash-flow/cash-flow-content.tsx:172` and `:289` pass net-cash totals through it. The concept is also already modelled elsewhere in the codebase: the Balance Sheet **export** builds an accounting-equation control summary with "the exact per-unit reconciliation difference" (`features/reports/CLAUDE.md`). Only the Trial Balance page has neither.

Fix: pass `summaryRows` to the Trial Balance `HierarchyList` with a per-unit total of the rendered roots, and state the outcome plainly — a difference of zero in every unit means it balances; any nonzero difference must be shown as the exact per-unit difference and labelled, never silently absorbed or rounded away. Reuse the Balance Sheet export's existing reconciliation wording and its rule that a nonzero difference is an internal-draft signal rather than inventing new copy. Keep the units separated (`USD` and `Other` are already distinct columns); never add across units. Owning package: `dashboard` only — no API, schema or engine change; the totals come from the hierarchy the page already has.

Blast radius: `HierarchyList` is the shared statement tree table (`balance-sheet/hierarchy-list.tsx`, wrapped by `hierarchy-list-card.tsx`) used by every statement page. Passing `summaryRows` from one more caller must not alter Balance Sheet, Income Statement or Cash Flow output — Cash Flow already passes the prop, so the path is exercised.

Adjacent states: an empty or fully filtered ledger must show an honest zero or empty state rather than a fabricated balanced result; a filtered period that legitimately does not reconcile must show the difference, not hide it; the existing collapse patterns and the shared horizontal scroll area at 390 must be preserved.

Dedupe: searched every queue including `done/` for trial balance, totals, reconciliation and `summaryRows`. Completed `m16` preserved parent-account postings in Cash Flow and completed `m20` exposed Cash Flow filters — both are Cash Flow behavior, not this page. Open [m32](./m32/README.md) owns the *assistive-technology semantics* of these same statement hierarchy tables; if it lands first, add the summary row inside whatever structure it establishes, and coordinate rather than duplicating. Open [m35](./m35/README.md) ties report results and exports to their completed request — a different concern. Nothing owns the missing total.

Not in scope: Trial Balance has no Export action, and that is deliberate — `features/reports/CLAUDE.md` names Balance Sheet, Income Statement and Cash Flow as the supported statement exports. Do not add one here.

Unverified: other locales, narrow viewport, a ledger that genuinely does not reconcile (the synthetic fixture balances), and the patched behavior.

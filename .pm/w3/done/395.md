# Account-filtered reports prune headline totals but keep counterparty amounts in interval series

**Severity:** major. **Owner:** cli. **Estimate:** about 1 hour for the shared
account-scope correction, focused regression coverage, and contract update.
**A1:** an agent receives conflicting financial amounts for the same account
and closing date inside one successful report. The extra series amounts also
make a fully valued selected account fail on an excluded commodity's price.

Found 2026-09-21, `main` HEAD `e213e53b`, checkout `cli/.venv/bin/bea` 0.3.0,
Python 3.13.0, macOS 26.5.1 arm64. Two fresh synthetic fixtures, separate CLI
processes, closed stdin, 35-second timeouts, isolated config/cache/data. All
primary commands exit 0 with empty stderr and unchanged ledger hashes.
Concurrent text-sanitization edits do not change these calculation paths.

## Reproduce

Create `main.bean` in a disposable directory:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Cash USD
2026-01-01 open Assets:Savings USD
2026-01-01 open Equity:Opening USD
2026-01-01 open Expenses:Food USD
2026-01-01 open Expenses:Rent USD
2026-01-02 * "Opening"
  Assets:Cash 1000.00 USD
  Equity:Opening
2026-01-05 * "Split expense"
  Expenses:Food 25.00 USD
  Expenses:Rent 75.00 USD
  Assets:Cash -100.00 USD
2026-01-10 * "Savings transfer"
  Assets:Savings 100.00 USD
  Assets:Cash -100.00 USD
```

```sh
bea --json --file "$PWD/main.bean" check
bea --json --file "$PWD/main.bean" report overview -t 2026-01 -a Assets:Cash
bea --json --file "$PWD/main.bean" report balance-sheet -t 2026-01 -a Assets:Cash
bea --json --file "$PWD/main.bean" report income-statement -t 2026-01 -a Expenses:Food
```

Check is valid. Both pristine repeats produce:

| Command | Correct headline | Incorrect January 31 interval |
| --- | --- | --- |
| Overview, Cash | `totals.assets.USD = "800.00"` | `series.assets[0].balance.USD = "900.00"` |
| Balance sheet, Cash | `net_worth.USD = "800.00"` | `net_worth_series[0].balance.USD = "900.00"` |
| Income statement, Food | `net_profit.USD = "-25.00"` | `periods[0].net_profit.USD = "-100.00"` |

The Cash overview also has empty headline expenses but `100.00 USD` expenses
in its interval. The Food interval includes `75.00 USD` of Rent that its
account tree correctly excludes. Removing `--json` displays the same
contradictions directly, including:

```text
Net Profit: -25.00 USD
Monthly breakdown
PERIOD END  INCOME  EXPENSES    NET PROFIT
2026-01-31  —       100.00 USD  -100.00 USD
```

Independent controls: `query 'SELECT account, sum(position) GROUP BY account'`
returns Cash `800.00 USD`, Savings `100.00 USD`, Food `25.00 USD`, Rent
`75.00 USD`. `balance Cash` and `report trial-balance -a Assets:Cash` both
return 800.00. The unfiltered balance sheet correctly agrees with itself at
900.00 in both headline and series. Thus conversion, timing, and rounding do
not explain the discrepancy.

## Related valuation failure, same cause

In another valid synthetic ledger, open Cash USD, Stock HOOL, and Opening
equity USD on January 1; fund Cash with 1000 USD on January 2, then buy
`1 HOOL {100.00 USD}` with `Assets:Cash -100.00 USD` on January 5. Supply no
price directive. These are the complete transaction bodies:

```beancount
2026-01-02 * "Opening"
  Assets:Cash 1000.00 USD
  Equity:Opening
2026-01-05 * "Buy"
  Assets:Stock 1 HOOL {100.00 USD}
  Assets:Cash -100.00 USD
```

Cash is unambiguously 900.00 USD. `report trial-balance -a Assets:Cash -t
2026-01` returns that value. The same filter on JSON overview/balance-sheet
exits **1**, stdout empty, with `Missing prices for HOOL → USD`, because the
unpruned series includes Stock. Both fail again from a pristine copy.
`--allow-errors` then incorrectly makes Cash net worth `{"USD":null}` even
though its returned asset tree contains only `{"USD":"900.00"}`.

## Root cause and fix

- `cli/src/fava/core/filters.py:450` selects whole entries touching the
  account; this appropriately preserves full transactions at that layer.
- `cli/src/bea_engine/report.py:116`, `:161`, `:203` prune statement trees,
  but `:147`, `:175`, and `:235` still serialize the original unpruned
  `FinancialStatementsModule` series. The valuation inputs at `:127`, `:167`,
  and `:214` likewise retain those series.
- `cli/src/fava/modules/chart.py:178`, `:233`, `:333` aggregate all postings
  under broad account roots for interval totals, account balances, and net
  worth. They do not apply the report's requested account predicate.
- `cli/src/cli/commands/report.py:231`, `:276`, `:331` faithfully render these
  mismatched arrays. Fixing only text output would leave JSON wrong.

Compute flow and balance series from the same matching accounts as the
headline, applying the existing parent/regex semantics before aggregation and
valuation. Reuse the shared chart/inventory machinery; preserve per-date
conversion, cost lots, signs, and interval boundaries. Do not restore the old
counterparty-contaminated headline to make the numbers agree. Account-filtered
current earnings must use a stated scope consistent with the corresponding
income statement; currently balance-sheet earnings also come from the
unpruned report object. Preserve the existing rule that an account-filtered
balance sheet does not claim full equity reconciliation.

Caller search covers all `interval_totals`, `account_balance`, and `net_worth`
callers: the affected public commands are overview, income-statement, and
balance-sheet, in text and JSON. Trial balance and `balance` are working
controls. Scope the repair to the CLI package; no API transport change.
Update `cli/docs/USAGE.md:844`, which still says report account filters retain
all postings even though the completed w3/322 change deliberately prunes them.

---

**Resolved 2026-09-21** — a filtered report's interval series, valuation and
current earnings now describe the same accounts as its headline.

`AccountFilter` keeps whole entries, which is right at that layer, but anything
aggregating *postings* has to narrow again. The trees did (w3/322, w3/379); the
chart series never did. The fix puts the narrowing where the aggregation
happens: `ChartModule.interval_totals`, `account_balance` and `net_worth` now
apply the report's account predicate per posting. No signatures changed — all
three already receive `filtered`, which carries `filtered.account` — so every
caller inherits it, text and JSON alike.

The predicate itself moved to one place. `fava.core.filters.account_predicate`
is now the single definition of what `--account` means, and
`bea_engine.report._report_filter_match` delegates to it instead of restating
it. Three copies of that rule is how a report starts contradicting itself
again — the same drift that caused w3/385 and w3/390.

Current earnings needed a separate fix: `balance_sheet` sums the income and
expenses hierarchies *before* this module prunes anything, so a filtered sheet
reported the whole period's P&L beside a narrowed net worth. `_scoped_earnings`
recomputes it from the pruned trees when a filter is set, and returns the
original object untouched when one is not, so unfiltered output is
byte-identical.

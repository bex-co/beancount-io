# Remembered explicit `--date-format` poisons later same-header CSVs with a different convention

**Severity:** major. **Estimate:** 30–45 minutes. **Owner:** cli. **A1:** after
one `import … --date-format '%m/%d/%Y'` (or any explicit format), a later
flag-free import of another file that shares the same header + `--account` but
uses ISO dates fails with `cannot parse date '2024-04-02' … with format
'%m/%d/%Y'` — even though `IMPORTING.md` already refuses to sticky-remember
*inferred* date formats for exactly this reason (“two exports can share a
header row without sharing a date convention”).

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `f60bbc67`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated `BEA_CONFIG_DIR` /
`XDG_CACHE_HOME`. Synthetic fixtures only. Evidence: `cli/tmp/qa-20260915/c498/`,
probe `c491g`.

## Repro

```sh
# fresh BEA_CONFIG_DIR; ledger with Assets:Cash + Expenses:Food open
printf 'Date,Amount,Description\n04/01/2024,-10.00,Coffee\n' > us.csv
printf 'Date,Amount,Description\n2024-04-02,-11.00,Tea\n' > iso.csv

bea --file main.bean import us.csv \
  --csv 'date=Date,amount=Amount,narration=Description' \
  --date-format '%m/%d/%Y' --account Assets:Cash --default-account Expenses:Food
# exit 0 — remembers mapping + date_format

bea --file main.bean import iso.csv --account Assets:Cash --default-account Expenses:Food
# exit 2
# Using remembered column mapping for iso.csv (--date-format %m/%d/%Y).
# Error: Row 2: cannot parse date '2024-04-02' in column 'Date' with format '%m/%d/%Y'.

# Control — fresh config, same iso.csv with explicit --csv (no sticky):
# exit 0 — Tea on 2024-04-02
```

## Expected

Either (a) do not persist `--date-format` across files (re-infer per file, same
as inferred formats), or (b) on parse failure fall back to re-inference /
clear guidance to pass `--date-format` / `--csv` for this file — never apply a
US format to unambiguous ISO dates silently via sticky memory.

## Actual

`cli/commands/import_.py` stores caller-chosen `date_format` in the remembered
CSV record keyed by header+account; recall restores it before inference, so the
ISO file never gets `infer_date_format`.

## Fix

Stop persisting `date_format` in sticky CSV memory (align with inferred
policy), or persist it but re-infer when `strptime` fails for any row.
Regression: the us→iso sequence above previews Tea; us→us still works without
re-passing `--date-format` only if product keeps sticky format *and* validates
it per file.

## Dedupe

Not w3/279 (`sign=ledger` sticky flip — same memory keyed by headers, different
field). Not w3/238 (JSON drops notes / inferred date-format visibility). This
is the explicit `--date-format` half of the documented “shared headers ≠ shared
date convention” hazard.

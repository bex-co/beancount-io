# Show a missing-file state when the editor query returns null

Severity: minor. Estimate: 30–45m. Package: mobile. A2: an outdated or mistyped source link explains that the file is unavailable instead of leaving a blank editor screen.

Environment: production API, authenticated QA session, public open_ledger/minimax; HEAD f1965988/mobile source7538fb0d, native client1.20260906.47, iPhone17e/iOS26.5, English/default text/light appearance.

Repro:
1. Open the real MiniMax main.bean source. It loads the MiniMax title, MUSD operating currency and account declarations.
2. Open the inspected internal route beancount:///(app)/ledger-file-editor?path=qa-nonexistent-20260911.bean. This is explicitly a nonexistent-file negative test; no such file was created or deleted.
3. Wait for loading to settle. The title changes to the missing path, Save remains disabled and the whole content area stays blank. There is no missing-file explanation or recovery action in the content.
4. Terminate/relaunch the app and reopen that route under the retained MiniMax selection. Fresh PID99354 reproduces the blank state. Reopen the real main.bean link: source loads correctly. Returning to the nonexistent path again leaves the settled content blank, with the development banner dismissed.

API control: the same read-only getLedgerFile query and missing path returns {"getLedgerFile":null}, without a GraphQL error. The generated schema declares a nullable LedgerFileContent result at mobile/src/generated-graphql/schema.graphql:1307. The previous file's contents do not leak into the new session; the missing-result branch is the failure, not stale-document retention. No save was attempted and no production data changed.

Root cause: mobile/src/screens/ledger-file-editor-screen/index.tsx:320 exits initialization when fileData.getLedgerFile is absent. isFirstLoad at556 becomes false when the request finishes, while the render branch at580–608 only handles fileError or initialized=true; a successful null response reaches the final null child. The session key added by7538fb0d correctly resets identity but does not handle this settled result. The rendering branch dates to3026f123.

Fix: represent a completed null result as an explicit localized unavailable/missing-file state, with safe navigation back to Files and an optional retry of the same identity. Keep Save disabled and do not initialize an editable empty document for a missing resource. Distinguish this state from a real zero-length file, initial loading and network/authorization errors; preserve the current identity key, authoritative reads and unsaved-change guard. Focused state/render coverage should cover loading, null, real empty content, query error, successful content and missing→valid identity recovery.

Blast radius: one shared editor screen handles Beancount and ordinary text paths reached from Files, notifications/source locations and app links. The negative test used an internal deep link; no actual broken notification or deleted-file browser row was fabricated as a valid fixture. Those entry points are source-traced only. Android, physical devices, denied/expired/offline states, real empty files and retry after a file reappears remain unverified. Bounded JS error capture empty, consistent with the successful null query.

Dedupe: searched all root open/done queues for getLedgerFile/null/missing/blank editor states and scanned open milestones. Read w3/done/100 in full: its previous-document identity failure is repaired by7538fb0d and stays repaired here. This is the adjacent missing-result state, not a reason to reopen the old stale-buffer finding. No matching open fix or newer repair found. Report only; no product fix or shipping.

# Import preview tallies omit conflict rows — an all-conflict preview reads as empty

Severity: minor. **Estimate:** 30m. **Owner:** cli. The highest-stakes
row status (it alone forces `--apply` to exit 4) is counted nowhere.

A reused stable ID with different data previews as status `conflict`
with a clear per-row explanation, but the tallies in both surfaces
ignore it:

- human: `… 0 ready, 0 exact duplicates, 0 possible duplicates` (no
  conflict count; `blocked` rows, by contrast, ARE appended)
- JSON: `ready/duplicates/possible_duplicates/blocked` all 0; no
  `conflicts` key

A script — or a skimming human — reading only the tallies concludes
"empty file, nothing to do" when the real answer is "review required".

## Repro (synthetic, no login; uses the documented example importer)

```sh
cd cli
T=$(mktemp -d) && cd $T
uv run --project /path/to/cli bea --no-input init books --currency USD --date 2026-08-01
cat > bank.csv <<'EOF'
Date,Payee,Narration,Amount,Currency,Category,BankID
2026-08-02,Cafe,Coffee,-5.25,USD,Expenses:Dining,bank-001
EOF
C=/path/to/cli/docs/examples/csv_importers.py
uv run --project /path/to/cli bea --file books/main.bean import bank.csv --config $C --apply >/dev/null
cat > bank2.csv <<'EOF'
Date,Payee,Narration,Amount,Currency,Category,BankID
2026-08-02,Cafe,Coffee,-99.99,USD,Expenses:Dining,bank-001
EOF
uv run --project /path/to/cli bea --file books/main.bean import bank2.csv --config $C
# 0 ready, 0 exact, 0 possible — plus one unexplained-by-tally conflict row; exit 0
uv run --project /path/to/cli bea --no-input --file books/main.bean import bank2.csv --config $C --apply
# exit 4, nothing written (this half is correct per docs)
```

HEAD `b94d9461`, bea 0.2.0, Darwin arm64, isolated config/cache.

## Root cause

The engine (`cli/src/bea_engine/importing.py:210`) tracks conflicts as
a boolean for the exit-4 gate but never counts them into the preview
dict, and the frontend summary
(`cli/src/cli/commands/import_.py:653-661`) appends `blocked` but has
no conflicts clause. Row detail (`status: conflict` + reason) exists in
both surfaces — only the tallies are blind.

## Fix direction

Count conflict rows in the engine preview (e.g. `conflicts: n`) and
append `, n conflict(s)` to the human summary alongside `blocked`;
keep the per-row table as is. Regression test: the repro above asserts
the human summary names the conflict and the JSON carries the count,
plus a mixed preview (new + duplicate + possible + blocked + conflict)
whose tallies sum to the row count. While here, confirm `written`
accounting on `--apply` results names skipped-conflict rows the same
way in both surfaces.

## Blast radius / dedupe

- Affected: `import` preview tallies (human + `--json`) whenever any
  row has status `conflict`. Per-row reporting, the exit-4 refusal,
  and the no-write guarantee are all correct — tallies only.
- Working controls: `blocked` rows ARE tallied in both surfaces;
  exact/possible counts verified against fixture rows.
- Searched all `.pm/**/*.md` for conflict-tally/count: no match.

---

**Resolved 2026-09-21** — conflict rows are counted in both preview surfaces.

The engine (`cli/src/bea_engine/importing.py`) tracked conflicts only as the
boolean that gates exit 4, so the preview dict never carried a count; the
frontend summary (`cli/src/cli/commands/import_.py`) appended `blocked` but had
no conflicts clause. The preview now computes `conflicts` the same way as its
sibling tallies, and the human summary appends `, N conflict(s)` alongside
`blocked`. Per-row reporting, the exit-4 refusal and the no-write guarantee
were already correct and are untouched.

The note's follow-up on `written` accounting resolves cleanly rather than
needing its own wording: `--apply` with any conflict is an all-or-nothing
refusal — it raises before `ledger_write.append`, so nothing is written and
`written` stays 0, and there is no partial-write case where skipped-conflict
rows would need naming. Because the refusal attaches `result=preview`, the
error envelope now carries the conflict count too (verified: `conflicts: 1,
written: 0` at exit 4).

Verified on the note's repro: human reads `… 0 ready, 0 exact duplicates, 0
possible duplicates, 1 conflict`, and JSON carries `"conflicts": 1`. A mixed
preview (conflict + duplicate + new) tallies 1/1/1 and the tallies sum to the
row count. A clean preview still says nothing about conflicts.

No doc change: the tally keys are not documented in `USAGE.md` or
`REFERENCE.md`, so the new key follows the same shape as its siblings.

Regression coverage is `cli/tests/test_import_conflict_tally.py`. Reverting the
fix fails 4 of its 5 tests; the fifth is the clean-preview control that must
pass either way. `cd cli && make check-all` passes (1562 tests).

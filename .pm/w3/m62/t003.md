## Objective

Add one **Currency** field to today's single creation form, prefilled for the user, and send it for Starter ledgers only.

## Context

- Form: `mobile/src/screens/create-ledger-screen/create-ledger-screen.tsx`. It sends `name`, `description`, `private`, `template` (only when Sample), and `requestId`.
- Starting point from before the revert: `6dc73928d^:mobile/src/screens/create-ledger-screen/currency-suggestion.ts and setup-currencies.json`. Keep only the order below; drop the time-zone candidate, the source label, and the setup flow.
- The current-user query does not read `defaultCurrency` today; the GraphQL `User` type exposes it.

## Steps

1. Read `defaultCurrency` in the current-user query and regenerate types with the mobile GraphQL codegen.
2. Prefill: saved `defaultCurrency` → the supported currency of the device region (`Intl` / the existing localization helper) → `USD`. Offer the supported list for editing.
3. Show the field under the template choice while Starter is selected; hide it for Sample.
4. Send `currency` only for Starter. Keep the submit label "Create ledger".
5. Add the field's label and hint to every shipped locale.

## Files

- `mobile/src/screens/create-ledger-screen/create-ledger-screen.tsx` and its tests
- the package's current-user GraphQL document and generated types, locale files

## Acceptance criteria

- [ ] With `defaultCurrency: "JPY"` the field opens as JPY; with none and a supported region it opens as that region's currency; otherwise USD.
- [ ] Creating a Starter ledger sends the selected currency; a Sample ledger sends no `currency`.
- [ ] The rest of the form (fields, order, validation, requestId retry behavior) is unchanged.
- [ ] `yarn format:check`, `yarn lint`, `yarn typecheck`, `yarn test:unit` pass.

## Out of scope

- Saving the chosen currency back to the profile.
- Any other ADR026 change.

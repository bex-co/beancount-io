## Implementation notes

`/simplify` ran four reviewers (reuse, simplification, efficiency, altitude) over the code t001–t003 changed. Applied, all behavior-preserving:

- backend-v2: the Starter is a function of its currency, `starterLedgerTemplate(currency = "USD")`, instead of a string replace that would silently stop matching if the option line were reworded; `simpleLedgerTemplate` is `starterLedgerTemplate()`, byte-identical to before (compared against the previous module). `isSupportedCurrency` in `features/ledger/setup` replaces four copies of `supportedCurrencies.includes` (create, `updateProfile`, and the setup builder's two checks).
- dashboard: `currencyToSend` (in `lib/ledger-currency.ts`, as on native) is the one rule for which creations send a currency; `CreateLedgerFormValues` is now a union, so the type forbids a currency with a template. `useCreateLedger` lost an extra await, `defaultLedgerCurrency` reads as "first locale with a region", and `isLedgerCurrency` is a type guard on both clients.
- mobile: the saved preference comes from `useSavedDefaultCurrency` beside `useCurrentUser`, which, like the avatar read, remembers per server that an older schema refused the field instead of asking again on every visit; a redundant loading flag is gone.

Skipped: caching the 162 currency labels per language (well under a millisecond per dialog open), and folding the backend's explicit USD default into `starterLedgerTemplate(currency ?? "USD")` (the explicit default keeps "unchanged without a currency" visible). The efficiency reviewer found nothing worth changing.

## Objective

Let a client choose a Starter ledger's operating currency with one optional field, without changing what any existing request creates.

## Context

- `CreateLedgerInput` — `backend-cluster/backend-v2/src/features/ledger/api/resolvers/ledger-resolver.types.ts`; REST schema `src/features/ledger/api/rest/v1/schemas.ts`; MCP `createLedger` in `src/features/ai-agent/api/mcp-tools.ts`.
- `LedgerWorkflow.createLedger` (`src/features/ledger/workflow/ledger-workflow.ts`) picks `setup` → `buildLedgerFiles`, `SAMPLE` → `ledgerWithMultipleFilesTemplate`, otherwise `defaultLedgerTemplate`, whose `main.bean` has `option "operating_currency" "USD"` and no account currencies.
- Supported codes: `setupCurrencies.supportedCurrencies` (`src/features/ledger/setup/currencies.json`), already used by `updateProfile` and the setup builder.
- The idempotency hash is built from `name`, `description`, `private`, `template`, `setup`.

## Steps

1. Add nullable `currency` to the GraphQL input, REST body, and MCP tool schema with the same description.
2. In the workflow: reject `currency` with `setup` or `SAMPLE`; validate it against the supported list; for Starter, replace the operating-currency line of `main.bean` only when `currency` is present and not `USD`.
3. Add `currency` to the idempotency hash only when it is non-null.
4. Regenerate the OpenAPI snapshot (`yarn generate-v1-openapi`) and the parity registry entries; in `cli/`, run `make spec-sync codegen docs`.

## Files

- `backend-cluster/backend-v2/src/features/ledger/{api,workflow}/**`, `src/features/ai-agent/api/mcp-tools.ts`, `docs/openapi/v1.json`, `docs/mcp.md`
- `cli/openapi/v1.json` and its generated client

## Acceptance criteria

- [ ] A request without `currency` yields the same `main.bean` bytes and the same idempotency hash as before the change (test compares against the unchanged template).
- [ ] `currency: "EUR"` creates `option "operating_currency" "EUR"` on every surface; `"usd"`, `"XXX"`, or a non-ISO string fails with a validation error naming `currency`.
- [ ] `currency` with `template: SAMPLE` or with `setup` fails with a validation error on every surface.
- [ ] `yarn typecheck`, `yarn test` (parity gate included), `yarn format:check`, `yarn lint:deadcode` pass; the OpenAPI snapshot has no drift; `make spec-check docs-check` passes in `cli/`.

## Out of scope

- Reading the profile `defaultCurrency` on the server; the sign-up default ledger (`auth-service.ts`) stays `USD`.
- A `bea cloud ledger create --currency` flag (the CLI already sets currency through `--preset` setups).

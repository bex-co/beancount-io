# `bea format --check` exits 0 when an include target does not exist

**Severity:** minor. **Estimate:** 25–40 minutes. **Owner:** cli. **A1:** a
pre-commit or agent that runs `bea format --check` on a split-ledger root
expects a nonzero exit when `bea check` fails because an `include` glob matches
no files — instead format reports “All 1 file(s) are formatted” and exit **0**.

Found 2026-09-16 by continuous CLI QA ([c1130 hunt](828702af-9b3c-4b99-9a5d-63a5efa2363a)),
HEAD `1d517572`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Evidence:
`cli/tmp/qa-20260915/c1130/`.

## Repro

```sh
# main.bean: include "missing.bean"
bea --file main.bean check
# exit 1 — File glob "missing.bean" does not match any files

bea format main.bean --check
# exit 0 — All 1 file(s) are formatted.
```

## Expected

`format --check` fails when the include graph is broken (missing target),
matching load/`check` semantics.

## Actual

`format.py` only inspects the named file’s text; it never resolves includes.

## Fix

On `--check` for a ledger file, resolve includes and fail if any target is
missing. Regression: repro exits nonzero naming the include; valid trees stay
green.

## Dedupe

Not w3/332 (existing child unformatted). Not w3/362 (broken symlink omitted
from directory walk). No open note on `format --check` green for missing
include targets.

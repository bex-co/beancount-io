# Loading buttons lose their accessible names

**Minor · dashboard · 45–60m.** A2: readers using the accessibility tree should
still be able to identify an action while its request is pending.

## Reproduce

1. Open https://beancount.io/ledger/open_ledger/example/query?lang=en.
2. Enter `SELECT account FROM accounts LIMIT 1`, focus **Execute Query**, and
   press Enter. Hold the QueryShell request before transport to inspect loading.
3. The previously named button becomes `button [disabled]` with an empty
   accessible name. The text remains in a child span whose computed
   visibility is hidden; there is no aria-label or aria-labelledby fallback.
4. Release the request: HTTP 200 returns Assets:US:BofA. The enabled button
   regains the name Execute Query.

The same sequence occurs for **Star** on the example Overview and **Unfollow**
on /ledger/open_ledger. Their intercepted writes were aborted before transport:
the original Star/Unfollow state and useful failure notification return. No
star or follow relationship changed.

Fresh 1440×1000 and 390×844 Chrome 152.0.7977.77 contexts on 2026-09-09,
English/light, authenticated QA, public synthetic example: all six initial
documents return 200; six pending buttons have empty names and six settled
buttons recover their names. Two BQL reads succeed; four social writes are
aborted. No page errors. The request holds simulate transport delay and do not
claim production is slow. Ordinary success/error recovery works.

Evidence: dashboard/tmp/qa-20260907-w3-loop/loading-button-evidence.json and
loading-button-query-{1440,390}.png. Captures include actual role snapshots,
computed CSS, missing naming attributes and pending/settled states. A temporary
DOM control changes the query label to visibility:visible with opacity:0:
the spinner remains and the disabled button is named Execute Query again at
both widths. That control also sets aria-busy; all overrides were removed before
settlement. No product source was changed. Source/fetched main 7f4b6190;
exact deployed SHA unverified, shared markup and behavior match.

## Root cause and scoped fix

dashboard/src/common/components/ui/button.tsx:54–76 replaces children during
loading with a span using Tailwind's invisible class and a separate spinner.
Visibility-hidden, unreferenced text does not provide a name. The
[Accessible Name computation](https://www.w3.org/TR/accname-1.2/#computation-steps)
explains this distinction from transparent text; the cited 1.2 text is a working
draft and the browser captures are the direct reproduction.

Keep the translated child label available to name computation while preserving
the spinner, button dimensions and duplicate-submit protection. A transparent
label that still occupies layout, or an equivalent naming arrangement, works.
Preserve explicitly supplied aria-label/aria-labelledby, text with nested icons,
and the existing asChild behavior. Expose pending state without replacing each
feature's name with a generic unnamed spinner. A shared primitive fix avoids
copying labels into sixteen feature call sites.

AST inspection found **16 direct Button loading usages** across: BQL Execute;
two collaborator-row actions and Invite; Journal Export; New Entry Balance,
Note, Open Account and Transaction; Accounts Close/Delete/Open; Add Budget;
receipt review; Overview Star; and profile Follow. Other loading props in
search/table/result components are not this Button contract. Star and Follow
each have one production mounting call site, in Overview and user-profile-page.
No backend or GraphQL/REST/MCP contract change is needed.

Acceptance: all three measured journeys retain a nonempty appropriate button
name throughout pending and settled states at both widths, while still blocking
duplicate requests. Released BQL reads succeed, and failed social actions retain
their original state. Cover text, icon-plus-text and explicit naming overrides
in the shared primitive; verify with rendered CSS/browser accessibility semantics.
The current button.test.tsx:22–31 only asserts the invisible span's textContent
and spinner, which pass even when the accessible name is empty.

## Dedupe and limits

All open/done notes, open milestone summaries and targeted history were checked
for pending/loading button names and invisible labels. No item owns this shared
loading failure. The primitive has not changed since import af5339de.
Existing 013/053/062/066/070/074 cover controls missing names while idle;
m23 covers dialog focus return; w4/m4 covers native discovery and star recovery.
Those fixes do not repair this separate web primitive.

No successful production social mutation, private ledger change, invitation,
or receipt upload was made. Unexercised loading call sites are source-traced,
not counted as independent live bugs. Native apps, other browsers and spoken
VoiceOver/NVDA announcements remain unverified. All temporary contexts closed.

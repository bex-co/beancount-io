# `bea list close` presents `close_tree` plugin closes as if they were on disk

**Severity:** minor. **Estimate:** 25–40 minutes. **Owner:** cli. **A1:** an
agent that enables `beancount.plugins.close_tree`, closes a parent account, then
trusts `list close` / JSON as the source of truth believes every child was
explicitly closed in the ledger — while only the parent `close` line exists on
disk.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `2fa8d92b`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only. Evidence: `cli/tmp/qa-20260915/c643/`.

## Repro

```sh
bea --file main.bean add open --date 2020-01-01 \
  --account Expenses:Food:Groceries --currency USD
printf '\nplugin "beancount.plugins.close_tree"\n' >> main.bean
bea --file main.bean add close --date 2020-06-01 --account Expenses:Food

grep -n 'close ' main.bean
# only: 2020-06-01 close Expenses:Food
# (no close Expenses:Food:Groceries on disk)

bea --file main.bean list close
# DATE / ACCOUNT includes Expenses:Food:Groceries and Expenses:Food

bea --json --file main.bean list close --account Groceries
# data[] includes Expenses:Food:Groceries — no synthetic source marker
```

## Expected

`list close` (human + JSON) either omits plugin-synthesized closes or labels
them with a non-ledger source (e.g. `<close_tree>`), matching w3/301 / w3/319
for opens and w3/318 for prices.

## Actual

`list_closes` walks post-plugin loaded `Close` entries with no on-disk filter.

## Fix

Share the on-disk / labeled-source filter with the other plugin-leak list fixes.
Regression: the repro’s `list close --account Groceries` is empty (or clearly
synthetic); the parent `Expenses:Food` close still lists; control without the
plugin unchanged.

## Dedupe

Not w3/301 (`auto_accounts` → list open). Not w3/319 (`currency_accounts` →
list open). Not w3/318 (`implicit_prices` → list price). No open note covers
`close_tree` closes in `list close`.

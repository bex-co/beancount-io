# Empty `BEA_TOKEN=` is rejected as “contains whitespace or control characters”

**Severity:** minor. **Estimate:** 10–15 minutes. **Owner:** cli. **A1:** a CI
job that exports `BEA_TOKEN=` (empty) or clears the var to `""` gets a
misleading auth error about whitespace/controls instead of the normal “Not
logged in” / empty-credential guidance — agents chase a paste bug that is not
there.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `a3f166e6`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only (no live credentials).

## Repro

```sh
# no BEA_TOKEN
bea cloud status
# exit 3 — Not logged in. Run 'bea cloud login', or set BEA_TOKEN.

BEA_TOKEN= bea cloud status
# exit 3
# Invalid BEA_TOKEN or stored credential (contains whitespace or control
# characters). Fix the environment value or run 'bea cloud login'.

BEA_TOKEN=' ' bea cloud status
# exit 3 — same whitespace message (correct for a space)
```

## Expected

Empty `BEA_TOKEN` behaves like unset: “Not logged in…” (or an explicit “empty
BEA_TOKEN” usage/auth message). Reserve the whitespace/control wording for
tokens that actually contain those characters.

## Actual

`cli/auth/credentials.py` validates with:

```python
if not token or _INVALID_TOKEN.search(token):
    raise AuthError("Invalid BEA_TOKEN … (contains whitespace or control characters)…")
```

So `not token` (empty string) shares the whitespace-oriented message.

## Fix

Split the branches: empty/missing → not-logged-in (or “BEA_TOKEN is empty”);
regex hit → whitespace/control message. Regression: `BEA_TOKEN=` matches unset
wording; `BEA_TOKEN='abc\\n'` still gets the whitespace message.

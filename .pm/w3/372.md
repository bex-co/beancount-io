# `bea query` same-day `OPEN ON D CLOSE ON D` excludes that day's transactions while `list` includes them

**Severity:** minor. **Estimate:** 20–40 minutes. **Owner:** cli. **A1:** an
agent mirroring `list transaction --from-date D --to-date D` with BQL
`OPEN ON D CLOSE ON D` gets exit **0** and `(no rows)` for transactions on D,
while `list` returns them.

Found 2026-09-16 by continuous CLI QA ([c1170 hunt](0b97424e-4333-4eaf-993a-a8ddbc409d23)),
HEAD `08a98331`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Confirmed
`cli/tmp/qa-20260915/c1170/`. Evidence: `c1170/`.

## Repro

```sh
bea --file main.bean list transaction --from-date 2024-03-10 --to-date 2024-03-10
# Lunch present

bea --file main.bean query \
  'SELECT date, narration FROM OPEN ON 2024-03-10 CLOSE ON 2024-03-10 WHERE narration ~ "Lunch"'
# (no rows)

# control: CLOSE ON 2024-03-11 returns Lunch
```

## Expected

Same-day BQL windows include transactions on D (match list inclusive dates),
or document/reject equal OPEN/CLOSE with a `CLOSE ON D+1` hint.

## Actual

Beanquery treats `CLOSE ON D` as exclusive of D when equal to OPEN; `list`
uses inclusive `_in_date_range`.

## Fix

Document semantics and/or hint/normalize same-day windows. Regression: repro
returns Lunch; extended CLOSE unchanged; list unchanged.

## Dedupe

Not w3/334, 327, 360, 358. No open note on BQL same-day OPEN/CLOSE vs list
inclusive filters.

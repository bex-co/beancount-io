# BQL charts replace valid Decimal and Inventory values with invented numbers

Severity: **major**. Owning package: **dashboard**. Estimate: **55–60 minutes**,
bounded to decoding supported chart values and safely omitting unsupported
charts; a full multi-currency chart feature is outside this repair.

Production `https://beancount.io`, 2026-09-08, Chrome152, English, System/light;
authenticated QA reader of public example ledgers. Desktop1440×1000 and fresh
narrow390×844. Deployed SHA unverified; local `a315c273` and fetched
`origin/main cc3f4c2f` contain the same implicated chart helper and serializers.

   `SELECT date, sum(number) WHERE account = 'Assets:US:BofA:Checking' GROUP BY date ORDER BY date LIMIT 3`.
   Alternatively open the same page with this query URL-encoded in `query`.

GraphQL QueryShell and REST POST
`/api-gateway/v1/ledgers/{owner}/{name}/query` return200 and agree with the tables.
Decimal cells are strings (`"4841.12"`, `"-4.00"`, `"-2400.00"`) with dtype
`Decimal`. Inventory cells are currency-to-decimal maps such as
`{"UNIV2ETHUSDC":"0.15"}` with dtype `Inventory`. Integer cells are JSON numbers.
These are valid read-only BQL queries and valid wire representations.

Root cause: `dashboard/src/features/bql/lib/chart-utils.ts:13–34` admits Decimal,
int, Inventory and Amount columns. `parseQueryChart` initializes each value to0
at71 but never handles strings, so Decimal values stay0. Its object fallback
at85 searches `JSON.stringify(value)` for the first number. It therefore reads
the **2 in the currency name** before the actual amount. A local source probe
using the captured production tables returns `[0,0,0]`, `[2,2,2,2]` and the
correct integer control `[2,1,1]`; this is source confirmation, separate from
the browser observations.

`features/bql/components/query-result-card.tsx:132` is the sole production caller
of this decoder; QueryResultChart passes its output to shared ReactECharts.
URL auto-execution, Execute and reopening history all reach this result card.
Text results and ineligible column layouts do not use the chart decoder.

The producer is correct: ledger `features/ledger/service/ledger-shell-mappers.ts`
defines decimal-string CurrencyMap values at9–13, combines units with BigNumber
at40–55, classifies Decimal/Inventory at65–106 and preserves primitives/maps in
`toShellCell` at167–181. `queryResultToShellResult` at190–205 retains these types.
LedgerShellService at85–94 invokes it; backend-v2 LedgerShellService at44–80
copies the types and cells into the shell result. GraphQL QueryShell and REST
query-handler delegate to that service, as does MCP runBqlQuery in source.
Live MCP was not exercised. Do not change the API/serializer or financial
decimal precision to accommodate this dashboard parsing error.

Fix at the chart boundary: accept finite, validated numeric strings for Decimal
alongside the existing numeric integer path. Decode Inventory/Amount through
the actual currency-map contract, never a regex over serialized JSON. For a
supported single-unit result, plot the signed amount and expose its unit in the
series/tooltip. For ambiguous/multiple-unit or unsupported cells, retain the
table and omit the unsupported chart rather than silently choosing a unit,
summing different units, or inventing zero. Preserve a legitimate zero as
distinct from missing/invalid data, and keep category order and table/CSV values.

Acceptance: use real API-shaped regression fixtures for fractional/negative
Decimal strings, numeric currency names, single-unit Inventory maps, legitimate
zero, missing/invalid cells and mixed units. Existing chart tests mainly use
numbers and legacy object shapes and miss this wire contract. Verify the actual
desktop/narrow chart tooltips against table values for both public queries and
the integer control; run dashboard format, lint, tests and build checks. No
dependency, API migration or broader chart redesign is required.

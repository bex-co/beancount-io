# `bea add` rewrites `@@` total prices as `@` unit prices with unbounded repeating decimals

**Severity:** major. **Estimate:** 30–45 minutes. **Owner:** cli. **A1:** an
agent that books `3 HOOL @@ 10 USD` (documented total-price syntax) permanently
writes `3 HOOL @ 3.333333333333333333333333333 USD` into the ledger — losing
the exact total and polluting the file with a non-terminating Decimal — while
the same `@@` line hand-edited into the file survives `check` / `format`.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `5987e0d6`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only. Evidence: `cli/tmp/qa-20260915/c513/`.

## Repro

```sh
bea --file main.bean add open --date 2020-01-01 --account Assets:Broker --currency HOOL
bea --file main.bean add transaction --date 2020-08-02 --narration odd \
  --posting 'Assets:Broker 3 HOOL @@ 10 USD' --posting 'Assets:Cash'
# writes:
#   Assets:Broker  3 HOOL @ 3.333333333333333333333333333 USD

bea --json --file main.bean add transaction --date 2020-08-03 --narration odd2 \
  --posting 'Assets:Broker 3 HOOL @@ 10 USD' --posting 'Assets:Cash'
# data.directive.postings[0].price.number ==
#   "3.333333333333333333333333333"
```

Working control — hand-authored `@@` kept:

```sh
# append manually:  Assets:Broker 3 HOOL @@ 10 USD
bea format main.bean   # still shows @@ 10 USD
bea check --file main.bean  # exit 0
```

## Expected

Preserve `@@ TOTAL` on write (or emit a quantized `@` that still multiplies
back to the exact total, e.g. within display precision), matching Beancount’s
total-price syntax and the hand-authored control.

## Actual

Postings are parsed into a per-unit `price` Amount (`10/3`), then
`format_entry` / writer emits `@` with the full Decimal exponent — no `@@`
round-trip and no quantization.

## Fix

Prefer serializing total prices as `@@` when the input used `@@` (or when
`units * price` was the authored total). If always emitting `@`, quantize to a
sensible precision that preserves `units * price == total`. Regression: the
`3 HOOL @@ 10 USD` repro’s on-disk line contains `@@ 10` (or a short exact
`@`), not a 28-digit repeater.

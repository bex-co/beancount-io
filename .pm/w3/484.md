# Remove production verification probes from the public `open_ledger/example` showcase

**Severity:** minor (public-facing hygiene). **Estimate:** 15–20 minutes, plus a runbook note. **Owner:** operations for the `open_ledger` account (a ledger write only its owner can make), with a note in `deploy/` or the verification runbook. **A3:** `open_ledger/example` is the first ledger visitors and agents open, and the default anonymous control in every QA run. Its Files and Version History currently show internal infrastructure checks, which read as debris in the product's shop window.

## Live observation

Production `https://beancount.io`, 2026-10-15, read-only.

- `/ledger/open_ledger/example/files/tree/main` lists `.ssh-proxy-verify` (156 B, Aug 18 2026) and `.verify-m15` (21 B, Aug 18 2026) beside `main.bean` and `README.md`. Both open to "Unsupported file format" (see w3/483).
- `/ledger/open_ledger/example/commits` shows, above the ledger's real history, commits titled "verify: unaffected ledger still pushes", "verify: directive limit enforcement point", "chore: verify the m15 bridge in production" and four "chore: verify the git control plane over ssh".

No script in this repository writes these files (searched for their names and commit titles), so they came from one-off production probes.

## Fix

As the `open_ledger` owner, delete `.ssh-proxy-verify` and `.verify-m15` in one commit with a clear message. History stays; rewriting the public ledger's history is not worth the risk. Record in the verification runbook (or `deploy/AGENTS.md`) that production write probes target a dedicated non-showcase ledger, never `open_ledger/*`.

Acceptance: the showcase file tree lists only ledger content, and the runbook names the probe ledger. No change to the ledger's financial data.

## Objective

Determine whether the `homeCharts` query's already-returned (and currently unused) `data.data[].budgets: JSONObject` field carries enough per-account budget data to power the Home Budget panel without extra `getLedgerIntervalTotals` calls. Record the decision so t009 builds on it.

## Context

- `mobile/src/generated-graphql/schema.graphql` — `homeCharts` return shape includes `budgets`.
- The panel needs, per budget group: account, current-period budget amount, current-period actual, currency.
- Fallback if the payload is insufficient: one `getLedgerJournal` (budget directives) + up to 3 `getLedgerIntervalTotals` calls scoped by a current-period `time` range.

## Steps

1. Call `homeCharts` against a ledger that has budget directives; inspect the `budgets` payload shape and freshness.
2. Compare against the panel's data needs (current-period budget + actual per group, respecting daily-equivalent proration).
3. Write the decision + payload notes into this file's Acceptance section; adjust t009's plan accordingly.

## Files

- `.pm/w3/m1/t001.md` (decision record)

## Acceptance criteria

- [x] Decision recorded: `homeCharts.budgets` is **insufficient**. Payload shape is `ChartItemV2.budgets: JSONObject` (schema line 136) — a **currency-keyed total** for the chart's account scope per interval, mirroring Fava's `calculate_budget_children` roll-up (`fava-slim/fava/modules/budgets.py:179`). There is no per-account breakdown, so the panel cannot derive per-group rows ("Expenses:Food:Groceries 412 / 500") from it.
- [x] t009 data source confirmed as the fallback: `getLedgerJournal` (budget directives, shared cache with /budget) + one `getLedgerIntervalTotals` per displayed group, capped at 3 by the panel's ranking, `time` = that group's current period. Cost is 1 + ≤3 queries, and the journal read is a cache hit once /budget has loaded.

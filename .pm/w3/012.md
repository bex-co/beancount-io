# Commodity tooltips round distinct fractional prices to the same value

**Severity:** minor — the price-history view cannot reveal the actual quoted
prices. **Estimate:** 30–45m, scoped formatting and regression coverage.
**Pillar:** A2 — readers exploring the public crypto example can inspect the
prices behind its holdings without losing meaningful precision.

Reproduced 2026-09-08 on production, Chrome 152, English/light, authenticated
QA account, synthetic public `open_ledger/crypto-example`. Source `a315c273`;
deployed SHA unverified. Fresh repeats at 1440×1000 and 390×844.

1. Open `/ledger/open_ledger/crypto-example/commodities`.
2. Scroll to the **CUSDC/USD** card, which has three price points.
3. Hover each point: January 1, June 1 and December 31, 2024.
4. All three tooltips show **CUSDC/USD: 0.02**. Most distinct y-axis ticks also
   have the identical label `0.02`; the line visibly rises but the quoted values
   do not explain it. Fresh desktop and narrow repeats agree.

Expected values are respectively **0.0225, 0.0227 and 0.0230 USD per CUSDC**,
as returned by the actual `GetLedgerCommodities` request, HTTP 200,
`ledgerId: "open_ledger/crypto-example"`. GET
`/api-gateway/v1/ledgers/open_ledger/crypto-example/commodities` returns HTTP 200
with the same exact decimal strings. Working control: BTC/USD on August 1,
2024 displays `59000.00`, matching its API value. No console errors.

Root cause: `dashboard/src/features/ledger-data/commodities/index.tsx:38–41`
converts values to numbers for plotting; the tooltip at 58–74 then uses
`price.toFixed(2)`, and the y-axis formatter at 94–99 independently applies
the same fixed two decimals. These are commodity quotes, not cent-rounded
cash amounts. The `CommodityChart` function has one caller in the same page
at 234, used for every returned base/quote pair.

Producer/serializer control: ledger
`src/foundation/rustledger/directives-report.ts:221` builds the price pairs,
called by `src/features/ledger/service/ledger-data-service.ts:248–258`.
Gateway `src/features/ledger/api/resolvers/ledger-data-resolver.query.ts:233–241`
passes each price's date/value through. REST and MCP share `VOCABULARY_READS`;
REST was exercised and MCP only traced. No API or stored-price change is needed.

Fix in **dashboard**: retain each point's source decimal string for tooltip
display, allowing harmless trailing-zero normalization without rounding away
significant fractional digits. Keep numeric conversion for chart coordinates.
Format y-axis ticks with precision appropriate to their step/magnitude so
distinct visible ticks do not all collapse to `0.02`. Scope this to commodity
quotes; the shared cash-oriented `common/lib/format/format-number.ts` also
caps at two decimals and is not a suitable drop-in fix.

Acceptance: the three reproduced tooltips reveal their distinct values and
dates, and the axis meaningfully distinguishes its ticks. Preserve BTC/USD,
zero values, empty/single-point series and readable narrow layout. Exercise
the real chart-option formatters with low-price decimals; do not merely test
a formatter disconnected from the component. Loading/error handling remains
with the existing `QueryView` and must not present synthetic zero prices.

Dedupe: all open/completed board records were searched for commodities,
precision, rounded prices and CUSDC. No overlapping open item was found.
Completed `w2/done/m22` changed chart loading/registration and required working
tooltips, but did not change these formatters; targeted history traces both
to `af5339de`. This is not established as a regression caused by that work.
Completed `w3/done/m6` exposes the vocabulary APIs, which preserve the values.
No newer source fix exists on current main.

Unverified: other browsers/locales, actual touch interaction, arbitrary very
small/exponent quotes, errors/offline and a patched implementation. Narrow
coverage used a desktop browser viewport and mouse. No production data changed.

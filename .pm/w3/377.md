# `csv:sha256` import-ids split across Unicode normalizations (re-import duplicates)

**Severity:** minor. **Estimate:** 60–90 minutes (spec + dual-hash migration). **Owner:** cli. **A2:** a
bank row whose description arrives NFD in one export and NFC in the next gets
two different `import-id` values, so the second import posts a duplicate
instead of exact-matching the first.

Found 2026-09-17 during the w1/m26/t006 skill review against `main`, HEAD
`0b5fa215`, `uv run bea` 0.2.0, Darwin arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
python3 -c "
import unicodedata
nfd = unicodedata.normalize('NFD', 'Café X')
nfc = unicodedata.normalize('NFC', 'Café X')
open('nfd.csv','w').write('Date,Payee,Amount\n2026-08-10,' + nfd + ',-28.40\n')
open('nfc.csv','w').write('Date,Payee,Amount\n2026-08-10,' + nfc + ',-28.40\n')
"
printf '[[rule]]\nmatch = "caf"\naccount = "Expenses:Food"\n' > rules.toml
bea --file main.bean import nfd.csv --csv date=Date,amount=Amount,payee=Payee --account Assets:Checking --rules rules.toml
# import-id: "csv:sha256:fafae216cb2748c5"
bea --file main.bean import nfc.csv --csv date=Date,amount=Amount,payee=Payee --account Assets:Checking --rules rules.toml
# import-id: "csv:sha256:0d2aa9afca7ff6ee"  <- same logical row, different id
```

## Cause

`bea_engine/importing.py::_hash_import_id` uppercases and hashes the raw row
description without NFC-normalizing it first, and
`skills/.claude/skills/beancount-import/references/dedup.md` specifies the
`csv:sha256` form the same way. w1/m26/t004 normalized every other comparison
surface; the hash was left out deliberately: changing it alters ids already
written to ledgers, so the fix needs a spec update plus a migration (dual-hash
lookup or a re-hash pass), not a one-line normalize.

## Fix sketch

1. NFC-normalize the description (and account) before hashing in
   `_hash_import_id`, and the same inputs in `_fingerprint`/`_candidate_key`.
2. Update the `dedup.md` hash normalization spec to match.
3. Migrate existing ids: look up both the legacy and the normalized hash on
   import, or ship a re-hash command; pin with a test that imports one row in
   each normalization and gets one entry.

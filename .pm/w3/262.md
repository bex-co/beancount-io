# `bea query '   '` exits 0 with empty stdout, while `--json` and stdin whitespace reject

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** cli. **A1:** an
agent or CI job that accidentally passes a blank/whitespace BQL argument (env
expansion, heredoc padding) thinks the query succeeded under human/`--format
csv`, while the same string under `--json` is a usage syntax error — and the
same whitespace on stdin is already refused as “query required”.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `a9e86eb3`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
bea --file main.bean query '   '
echo exit=$?
# exit 0 — empty stdout, empty stderr

bea --file main.bean query --format csv '   '
echo exit=$?
# exit 0 — empty stdout

bea --json --file main.bean query '   '
echo exit=$?
# exit 2
# {"error":{"category":"usage",
#   "message":"Cannot run this BQL query: syntax error.", …}}

printf '   \n' | bea --file main.bean query
# exit 2 — "A query is required as an argument or on stdin."
```

Working control: a real `SELECT …` succeeds in both human and `--json`; omitting
the argument with `--no-input` raises the same “query is required” usage error.

## Expected

Whitespace-only argv queries match the stdin empty rule: exit 2 usage (“A
query is required…”) in every mode before the engine runs, so human / CSV /
JSON agree.

## Actual

`cli/src/cli/commands/query.py` only treats missing/empty `query_string` as
absent (`if not query_string:`). A whitespace token is truthy, so it is
forwarded to the engine:

- human / `--format csv` → `text_answer` → `shell.onecmd`, which no-ops on a
  blank line (exit 0, empty text);
- `--json` → `rows_answer` → bare `execute`, which raises Beanquery syntax
  error on the same spaces.

Stdin already calls `.strip()` and rejects.

## Fix

After resolving the query string (argv or stdin), if `not query_string.strip()`
raise the existing “A query is required…” usage error (before helper launch).
Regression: argv `'   '` / `'\n'` / `'\t'` exit 2 in human, csv, and `--json`
with no engine call; nonempty queries unchanged; interactive shell (no argv,
TTY) unchanged.

## Dedupe

Not w3/234 (`--json` breaks `.tables` / shell utilities — nonempty dotted
commands). Not w3/236 (`.run` missing name exits 0 empty). Not w3/249 (empty
stdout on format with no files). No open note covers whitespace-only BQL argv
vs stdin / `--json` asymmetry.

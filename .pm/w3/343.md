# `--file` / `$BEA_FILE` directory error always hints `main.bean` (ignores `main.beancount`)

**Severity:** minor. **Estimate:** 15–25 minutes. **Owner:** cli. **A2:** pointing
`--file` at a directory that only has `main.beancount` suggests
`…/main.bean`; following that hint fails while the sibling `.beancount` works.

Found 2026-09-16 by continuous CLI QA ([c850 hunt](7ea38662-f8ed-4637-80e3-2945818d6321)),
HEAD `dda764a4`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Confirmed
`cli/tmp/qa-20260915/c853/`. Evidence: `c850/`.

## Repro

```sh
# books/ contains only main.beancount
bea --file books check
# exit 2 — … for example --file books/main.bean

bea --file books/main.bean check
# exit 2 — No ledger file …

bea --file books/main.beancount check
# exit 0
```

Same hard-coded `main.bean` hint when `$BEA_FILE` is the directory.

## Expected

Hint an existing root ledger under the directory (`main.bean` else
`main.beancount`), or name both.

## Actual

`context.py` `entry_file()` always appends `candidate / 'main.bean'`.

## Fix

Probe the directory for root ledger names before building the hint.
Regression: `.beancount`-only dirs hint the working path.

Related to w3/307 (cwd skips `main.beancount`) — different surface: directory
target hint. Not w3/340 (stale `$BEA_FILE`). No open note covers this hint.

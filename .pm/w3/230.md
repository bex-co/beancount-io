# `bea add transactions` accepts bare JSON numbers in `meta` then fails with opaque `Unexpected value: '1'`

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** cli. **A1:** an
agent that puts `"meta": {"count": 1}` in bulk JSON (natural JSON) gets a
validation error with no key, row, or schema hint, while booleans and tagged
numbers are the documented path.

Found 2026-09-15 by continuous CLI QA against `main`, HEAD `127b2378`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
cat > rows.json <<'EOF'
[{"date":"2024-03-21","narration":"tm","meta":{"count":1},"postings":[
  {"account":"Expenses:Food:Groceries","amount":"1 USD"},
  {"account":"Assets:Bank:Checking"}
]}]
EOF
bea --json --file main.bean add transactions --from rows.json
echo exit=$?
# stderr: {"error":{"category":"validation","message":"Unexpected value: '1'","exit_code":1}}
```

Same for `"count": 1.5`. Working controls:

```sh
# boolean meta OK
{"meta":{"cleared":true}, ...}

# tagged number OK (with a Beancount-legal key length ≥ 2)
{"meta":{"count":{"kind":"number","value":"1"}}, ...}
```

`USAGE.md` documents tagged objects for numeric metadata; bare JSON numbers
should not pass validation only to die inside Beancount's printer.

## Expected

Either coerce JSON `int`/`float` to `Decimal` before print, or reject at schema
validation with a usage/validation message naming the key and showing
`{"kind":"number","value":"…"}`. Never surface bare `Unexpected value: '1'`
from `beancount.parser.printer`.

## Actual

Pydantic accepts the int; `metadata_for_write` passes it through; upstream
`EntryPrinter.write_metadata` raises `ValueError`; the CLI maps that to a
category `validation` error with only that string.

## Root cause

```text
beancount/parser/printer.py write_metadata — rejects Python int/float
cli/src/bea_engine/ledger/write.py:559-584 metadata_for_write — no int→Decimal
cli/src/bea_engine/ledger/models.py — TransactionDirective.meta is dict[str, Any]
```

## Fix

1. In `metadata_for_write` (or the bulk model), convert `int`/`float` to
   `Decimal`, or reject with `Invalid metadata for 'count': use
   {"kind":"number","value":"1"} (JSON numbers are not Beancount metadata).`
2. Include row index in bulk rejection details when possible.
3. Regression: bare `1` / `1.5` either write correctly as decimals or fail with
   the named guidance; `cleared: true` and tagged numbers stay green.

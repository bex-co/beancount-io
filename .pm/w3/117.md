# Download ZIP fails without user feedback when archive discovery rejects

Severity: **minor**. Package: **dashboard**. Estimate: **30–45m**, including
focused error/retry coverage for the existing Git Clone action.

Production client at https://beancount.io, September 11, 2026, headless Chrome
152.0.7977.83, English/light, fresh 1440×1000 and 768×1024 contexts. Dedicated QA
GROWTH account reading public synthetic `open_ledger/crypto-example`,
pull:true, push/admin:false. Local main f943005d; fetched main f1965988 has the
same implicated dashboard files. Entry module main-z45iacYQ.js; deployed SHA
unverified.

**The failure responses below are controlled browser simulations.** Normal
production archive downloads succeed; this report does not claim a live outage.

## Reproduce and recover

1. Open `/ledger/open_ledger/crypto-example/files/tree/main?lang=en`, then
   **Git Clone**. The Clone Repository popover exposes **Download ZIP**.
2. Intercept only the GraphQL operation `GetLedgerArchiveDownloadUrl`, variables
   `{ledgerId:"open_ledger/crypto-example"}`. Return HTTP503 with JSON
   `{"errors":[{"message":"QA controlled archive service failure","extensions":{"code":"INTERNAL_SERVER_ERROR"}}]}`.
   All other document, ledger, directory and file requests remain live.
3. Click Download ZIP. The lookup completes, no download begins, and the popover
   stays unchanged. The Notifications region is empty. The only error is an
   unhandled browser error: `Response not successful: Received status code 503`.
4. A fresh 1440px context returning HTTP200 with the same GraphQL error and
   `data:null` also gives no feedback; its page error is
   `QA controlled archive service failure`. Each failure used one intercepted
   request and produced zero downloads.
5. In another fresh 768px context, activate Download ZIP with Enter under the
   HTTP503 control. The same unchanged popover, empty Notifications region and
   unhandled error recur. The button remains enabled.
6. Remove the interception and press Enter on the same button. The real lookup
   returns200 and downloads `crypto-example-main.zip` (16,458 bytes) successfully.
   Thus the action is retryable, but the failed attempt gives no explanation.

Expected: a failed lookup produces localized, accessible error feedback and
leaves a usable retry action, without an unhandled rejection or false success.
Ordinary successful downloads should keep working.

## Cause and bounded repair

`dashboard/src/features/ledger-editor/directory-browse/components/ledger-clone-url-menu.tsx:104–118`
creates a skipped query and awaits its `refetch` in `handleDownloadZip`, but
never catches a rejection or renders its error state. The button at176–181
passes that async function directly to onClick. Both transport and GraphQL
failures therefore escape the event handler before window.open is reached.

Installed Apollo Client4.1.3's `core/ObservableQuery.js:366–398` returns the
reobserve promise for refetch; its tracking operator rejects error notifications
at1363–1364. The local client uses default query options. The auth error link
handles UNAUTHENTICATED redirects only (`common/apollo/links/auth-error-link.ts:81–90`);
it does not provide fallback feedback for these service errors.

Catch lookup failures in the Git Clone action and use the existing translated
error formatter/notification pattern already used by CloneUrlInput in this file.
Keep the archive lookup read-only and preserve auth redirects, URL handling,
keyboard activation and normal retry. This does not need a global Apollo policy
change, a new dependency, or a backend/API change.

- [ ] HTTP503 and HTTP200 GraphQL-error repeats show useful error feedback and
      emit no unhandled browser rejection. The failed attempt starts no download.
- [ ] After a failed lookup, a subsequent successful lookup downloads the archive
      exactly once and retains the Download ZIP accessible name and usable focus.
- [ ] Meaningful rendered tests drive the real action through rejection and
      recovery; retain the existing clone-tab/copy-name checks. Run dashboard checks.

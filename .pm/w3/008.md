# Files directory rows cannot be opened with the keyboard

**Severity:** major for keyboard users — the main file-opening journey is
unavailable. **Estimate:** 35–50m including keyboard navigation verification.
**Pillar:** A2 — a newcomer must be able to explore a ledger's source files.

Reproduced 2026-09-07 on production, Chrome 152, English/light, 1440×1000 and
390×844, authenticated reader of `open_ledger/example`. Source/fetched main
`57fc1c27`; deployed SHA unverified.

1. Fresh-load `/ledger/open_ledger/example/files/tree/main` and wait for the
   file list and rendered README.
2. Focus the toolbar's Version History button and press Tab.
3. Focus jumps to the README's external **Beancount** link, skipping every file
   row. The accessibility tree presents `main.bean` as ordinary text, with no
   link/button role. Repeat from fresh desktop and narrow loads: same result.
4. Click the `main.bean` row with the mouse. The app opens
   `/ledger/open_ledger/example/files/blob/main/main.bean`; `GetLedgerFile`
   returns HTTP 200, the expected filename, 318015 bytes and nonempty content.

Expected: each file/directory destination is a named, focusable navigation
control, reachable by Tab and activatable with Enter. Actual: only pointer
clicks work. The directory row is a DIV without role, tabindex or interactive
descendants. The underlying file read succeeds.

Root cause: `dashboard/src/features/ledger-editor/directory-browse/components/ledger-directory-view.tsx:257–266`
maps every item to a DIV with only `onClick`. Use a native TanStack Link for
file/directory navigation, reusing the route/path construction used by
`common/hooks/use-file-navigate.ts`; preserve current sorting, path encoding,
permission gates, hover and visible-focus behavior. A pointer cursor alone
does not make a row keyboard-operable. Do not add nested interactive controls
inside the link or expand this change into branch support.

Blast radius: `LedgerDirectoryView` is used by directory-browse's
`/files/tree/$branch/$` route and the `/files/content?path=...` view. The tree
route is live-verified; the content alias and a directory containing actual
subfolders are traced only. Regression checks should cover both item types and
callers, including empty/loading/error states. The existing commit-history
list is a working native-link control; its selected `main.bean` commit and
file-diff anchor load correctly.

Dedupe: searched all open/completed `.pm` files for directory/file keyboard
navigation and accessibility. No overlap. `w3/006` is the separate shared
journal pagination defect; `w5/done/m2` covers sidebar/gallery, not file rows.
The DIV implementation traces to `af5339de`; the later `aeec496b` localization
change does not fix it, and fetched main has no newer repair.

Acceptance: Tab reaches `main.bean`, Enter opens the correct file, a folder
link enters its directory, and mouse navigation still works at both widths.
Keep focus visible and never require direct DOM focus injection to reach a
file row. Other browsers/screen readers and a patched implementation remain
unverified. No ledger writes occurred.

Local evidence: `dashboard/tmp/qa-20260907-w3-loop/file-navigation-evidence.json`,
`file-tree-keyboard-1440.png`, and `file-tree-keyboard-390.png`. The narrow
toolbar's missing name is tracked separately in `w3/009`.

# `bea query` text tables truncate headers to the value width (`count(*)` → `c`)

**Severity:** minor. **Estimate:** 30–45 minutes. **Owner:** cli (managed
beanquery / query text path). **A1:** an agent that runs
`bea query 'SELECT count(*) …'` in human mode gets a vertical `c` / `-` / `7`
table and cannot read the column name; `--json` and `.set narrow false` work.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `67b7ec5a`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only. Reproduced with both `bea --file … query` and native
`bean-query` from the managed engine.

## Repro

```sh
bea --file main.bean query 'SELECT count(*) FROM "accounts"'
# stdout (exit 0):
# c
# -
# 7

bea --file main.bean query 'SELECT sum(number) WHERE account ~ "Cash"'
# stdout:
# sum(n
# -----
# 97.25

# Same truncation with --numberify multi-currency headers:
bea --file multi.bean query 'SELECT account, sum(position) GROUP BY 1' -m
# account          sum(  sum
# -----------------------  ----  ---
# (JSON columns are "sum(position) (USD)" / "(EUR)" — readable)
```

Working controls:

```sh
bea --json --file main.bean query 'SELECT count(*) FROM "accounts"'
# columns[0].name == "count(*)", rows [[7]]

# interactive:
bea --file main.bean query
#   .set narrow false
#   SELECT count(*) FROM "accounts"
# count(*)
# --------
#        7
```

## Expected

Default text rendering keeps enough column width for the header (or documents
that `narrow` must be off for readable aggregate names). `SELECT count(*)`
should show `count(*)` (or an alias), not a single letter.

## Actual

Managed `beanquery/query_render.py` `render_text(..., narrow=True)` computes:

```python
widths = [max(1, narrow or len(header), len(nullvalue), render.prepare()) ...]
```

When `narrow` is the boolean `True` (shell default in `beanquery/shell.py`),
`narrow or len(header)` evaluates to `True`, and `max(..., True, ...)` treats
it as `1`. Headers are therefore truncated to the data width (`7` → width 1 →
header `c`). Intended narrow behavior was “ignore header length,” but the
boolean was used as a width contribution instead of a branch.

Bea’s one-shot `query` path uses this default; `--json` bypasses text render.

## Fix

Upstream-correct the width expression (e.g. use `0 if narrow else len(header)`),
and/or have `bea query` one-shot text mode pass `narrow=false` (or `.set narrow
false` before rendering) until the engine is fixed. Regression: human
`SELECT count(*) FROM "accounts"` prints a full `count(*)` header; aliased
`AS n` still fits; `--json` unchanged.

## Dedupe

Not w3/234 (`--json` rejects `.tables`). Not w3/242 (`PRINT` ignores `--format
csv`). Not w3/246/247 (FROM table binding). No open note covers default
`narrow` header truncation in query text tables.

# `bea import --rules` treats `match = ""` as a catch-all (first rule wins all rows)

**Severity:** minor. **Estimate:** 15–25 minutes. **Owner:** cli. **A1:** a
`rules.toml` with blank `match` categorizes every CSV row into that rule’s
account; later rules never run.

Found 2026-09-16 by continuous CLI QA ([c840 hunt](9020500b-5d89-466e-9d17-938de2042b3d)),
HEAD `5a5dd9fc`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Confirmed
`cli/tmp/qa-20260915/c841/`. Evidence: `c840/`.

## Repro

```sh
# rules.toml: match="" → Expenses:Food; match="OTHER" → Expenses:Misc
bea --file main.bean import bank.csv --csv auto --account Assets:Checking \
  --rules rules.toml
# BOTH rows → Expenses:Food (OTHER SHOP never hits second rule)
```

## Expected

Reject blank `match` (exit 2) or treat as non-matching — must not swallow all
rows via `re.compile("")`.

## Actual

`CsvRule.compile` accepts `""`; `search("")` matches every string.

## Fix

Reject `not match.strip()` in compile. Regression: repro exits 2; patterned
rules unchanged.

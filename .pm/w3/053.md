# Import's CSV example download has no accessible name

Severity: **minor**. Owner: **dashboard**. Estimate: **15–25 minutes**.
A2: newcomers can identify and download the working CSV template from Smart
Import using its accessible controls.

Production `https://beancount.io`, 2026-09-08, Chrome 152, English,
System/light; authenticated reader of public synthetic `open_ledger/crypto-example`.
Fresh 1440×1000 and 390×844. Local HEAD `a315c273`, fetched main `cc3f4c2f`;
implicated code is unchanged there. Deployed SHA unverified.

1. Open `/ledger/open_ledger/crypto-example/import` in the initial upload state.
2. Focus **Browse files**, then press Tab. Focus reaches the small download
   link beside **CSV format reference**.
3. The accessibility tree identifies only an unnamed link to
   `/lgasset/csv_transactions.csv`. It has no text, aria-label or title, and
   its only SVG is aria-hidden.
4. Press Enter: it correctly downloads `example_transactions.csv`. Fresh
   desktop and narrow repeats have the same empty name and successful download.

Expected: the link's accessible name identifies the CSV-example download.
The adjacent reference caption is not associated with the link as its name.
Browse files is a working named control; this download is keyboard-reachable
but does not identify its action to assistive technology.

Root cause: `dashboard/src/features/importer/components/steps/upload/file-upload.tsx:191–197`
renders an anchor containing only the decorative Download icon. Add the
existing localized `importer.error.downloadCsvExample` value as its accessible
label, preserving the actual anchor, href and download filename. This string
already describes the same resource in the parse-error fallback at
`parse-error-display.tsx:125–132`; that fallback was source-traced only.

FileUpload has one production caller in the upload step at `upload/index.tsx:53`.
Both references point to the same static CSV; there is no API or importer-parser
change to make for this defect.

Working data control: the resource returns HTTP 200, `text/csv; charset=utf-8`,
490 bytes. Both downloaded files have identical content: one four-column header
and ten synthetic transactions. Loading the downloaded file at 390px produces
**10 Valid**, retaining all ten dated payees and amounts. No page/console errors
or API requests occur during that local preview. Upload Different File discards
it; Configure, Import and AI processing were not invoked for the sample.

Acceptance: the initial upload screen exposes a link named **Download CSV
Example** in English and the existing localized equivalent elsewhere, at both
widths. Tab and Enter still download the same valid ten-row file. Verify the
accessible name and the existing download/preview control; no additional
dependency or dedicated implementation-mirroring test is needed.

Dedupe: searched open/completed board records for CSV samples, download labels
and format references, and reviewed open milestone summaries. 009/013 concern
separate Files/copy controls; the importer validation and sign findings concern
data handling. No overlapping repair exists. Targeted history traces the bare
anchor to `af5339de`, with no newer fix on fetched main.

Other locales/browsers, screen readers, the parse-error path and patched behavior
remain unverified. No production data changed and no local draft remains.

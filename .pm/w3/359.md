# Broken ledger `plugin` directives surface full Python tracebacks on load

**Severity:** minor. **Estimate:** 30–45 minutes. **Owner:** cli. **A1:** a
mistyped `plugin` line yields a multi-line Traceback on `check`/`add`/`list`/
`query` instead of a one-line message naming the plugin and root error.

Found 2026-09-16 by continuous CLI QA ([c1010 hunt](8b136e85-a84c-4965-9041-f6a034c410ca)),
HEAD `be6019bb`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Confirmed
`cli/tmp/qa-20260915/c1012/`, `c1013/`. Evidence: `c1010/`.

## Repro

```sh
# bad plugin config
plugin "beancount.plugins.auto_accounts" "["
bea --file main.bean check
# exit 1 — Error applying plugin … Traceback … TypeError …

# missing module
plugin "nonexistent_plugin_xyz"
# exit 1 — Error importing … Traceback … ModuleNotFoundError …
```

Syntax errors stay concise (control).

## Expected

One/two-line plugin failure (name + terminal exception); full traceback only
under `--debug`.

## Actual

Beancount embeds tracebacks in loader errors; bea forwards them into stderr and
JSON `details`.

## Fix

Rewrite traceback-bearing plugin load/apply errors to a short summary; keep
`--debug` verbose. Regression: both repros exit 1 without Traceback body.

## Dedupe

Not w3/232 / 302 / 298. No open note covers traceback-heavy `plugin` directive
load errors.

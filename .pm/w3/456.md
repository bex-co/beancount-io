# A glued short option on a forwarding command silently prints `bea`'s help and exits 0

**Severity:** minor (a command that looks like it ran and did nothing).
**Owner:** cli. **Estimate:** 20–30 minutes. **A1:** an agent that writes
`-o/abs/path` instead of `-o /abs/path` gets exit 0 and no output, which reads
as success.

Found while implementing [w3/m48](./done/m48/README.md) on 2026-09-26, `bea`
0.3.0 at HEAD `8cd9732b`.

## Repro

```sh
bea --file main.bean ingest extract -o/Users/me/books/out.bean in
# exit 0; bea's own `ingest extract` help is printed; nothing is extracted.
```

## Root cause

Click parses a glued short option as a cluster of single-character flags. On a
forwarding command (`allow_extra_args` + `ignore_unknown_options`) the whole
token is preserved only when *every* character is unknown to `bea`; a path
containing `h` (or any other character `bea` binds as a short option, such as
`f`) matches `-h`/`--help`, so the run turns into a help print at exit 0. A path
without such a character (`-omain.bean`) is forwarded intact and is handled
correctly, including by the new output-destination guard.

## Expected

A forwarded token starting with `-o`/`-e` and continuing with a path is either
forwarded whole or refused with exit 2 naming the spelling — never silently
turned into `--help`. The same applies to `treeify`, `example`, `price`, and
every other passthrough command.

## Out of scope

The output-destination guard itself, which is in place and covers every spelling
Click actually forwards (`w3/m48`, tests
`cli/tests/test_output_destination_guard.py`). No data loss is involved here:
the help print writes nothing.

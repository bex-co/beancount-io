# Currency fields clip MUSD, USDT and longer commodity symbols

**Severity:** minor. **Owner:** dashboard. **Estimate:** 35–50 minutes.
**A2:** users can read the complete selected currency when reviewing an entry.

Production `https://beancount.io`, 2026-09-08, Chrome 152, English/light,
1440×1000 and 390×844. QA session, public `open_ledger/minimax`.
Local HEAD `a315c273`, fetched main `afb36a9b`; relevant source unchanged,
deployed SHA unverified. Only local currency drafts were changed; no form
was submitted and no mutation was attempted.

1. Open `/ledger/open_ledger/minimax/journal?lang=en&action=new-entry&directive=transaction`.
   Inspect the first Currency field with its untouched **MUSD** default.
2. Move focus to Close without activating it, and wait for the picker to close.
   The field clips the final part of the symbol even with scrollLeft 0.
3. Type **USDT** into Currency and press Enter to commit the custom value.
   After blurring, its final letter is clipped. **USD** fits and is the
   working short-symbol control. Repeat on the Balance tab and at both widths.
4. **UNIV2ETHUSDC** is also clipped. All raw input values remain complete;
   the defect concerns the visible selected unit, not serialization.
5. On Budget → Add Budget, MUSD and USDT fit its wider Currency field, but
   UNIV2ETHUSDC still clips. Repeat all failures from fresh loads.

Measured text space and actual rendered fonts explain the captured clipping:

| Field                 | Total width | Available text width | Required text width, desktop / narrow |
| --------------------- | ----------- | -------------------- | ------------------------------------- |
| Transaction / Balance | 80px        | 34px                 | MUSD 41.05 / 46.35px                  |
| Transaction / Balance | 80px        | 34px                 | USDT 37.28 / 42.04px                  |
| Transaction / Balance | 80px        | 34px                 | USD 28.96 / 32.68px — fits            |
| Add Budget            | 144px       | 98px                 | UNIV2ETHUSDC 107.58 / 121.26px        |

In isolated diagnostic controls, changing only the owning FormItem's width to
192px provides 146px of text space. Every tested symbol becomes fully visible
with the same value, font and Clear action. This is a temporary DOM control,
not a product patch. Twelve documents and 36 symbol states, each with a width
control, returned HTTP 200 with no page exceptions or mutation attempts.
All isolated contexts closed.

Root, under `dashboard/src/`:

- `features/journal/components/new-directive-dialog/transaction-form.tsx:507`
  and `balance-form.tsx:208` constrain Currency to `w-20`.
- `features/ledger-data/budget/add-budget-dialog.tsx:293` uses `w-36`.
- Shared `common/components/ui/combobox.tsx:210,217–224` reserves 32px right
  padding for its Clear button. `ui/input.tsx:11` adds 12px left padding,
  borders and responsive 14px/16px text. Those necessary spaces leave too
  little room in the caller's fixed width.

Give these currency fields enough responsive space to show their supported
selected symbols, including the actual MUSD default and the longer control.
Keep them within the form at 390px, with usable adjacent Amount fields and
posting controls. The 192px diagnostic establishes the cause; choose sizing
that fits each existing layout. Preserve Clear, fonts, keyboard selection and
the complete stored value. Do not shorten currency identifiers, remove button
padding, or change numeric parsing to hide this display failure.

All five CurrencyCombobox callers were searched. Transaction, Balance and
Add Budget are live-proven above. ReceiptReviewForm and Import Configure use
FormItem without these fixed widths and are source-audited controls only;
their layouts were not separately retested for this finding. No global
Combobox/Input or backend change is required. Verify the visual results at
both widths and run the dashboard gates when implementing; a test that merely
asserts the replacement Tailwind class would not prove the repair.

Dedupe: all open/completed records and targeted history searched for currency
clipping, width and symbol truncation. 065 covers lost labels; 086 covers the
DatePicker's own default width; 089 and m27 concern numeric serialization and
booking. None repairs these three Currency field widths. The fixed-width
wrappers trace to `af5339de`; fetched main has no correction.

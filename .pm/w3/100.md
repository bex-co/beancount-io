# Mobile file editor retains the previous ledger's document after a link switch

Severity: minor (reproduced read-only display mismatch). Estimate: 60 minutes, mobile. A2/A3: following shared ledgers must keep source views associated with the correct ledger.

Environment: 2026-09-09, main `7f4b6190`, rebuilt native `io.beancount.ios` 1.20260906.47 on iPhone 17e/iOS 26.5, Metro 8083, https://beancount.io API. Authenticated reader, public `open_ledger/example` and `open_ledger/airbnb`, both push=false.

Fresh-launch repro:

1. Terminate/relaunch. Select the public example ledger (tested with `beancount:///ledger/open_ledger/example/journal`).
2. Tap Files, then main.bean. Confirm `option "title" "Example Beancount file"` and the generated example header.
3. Open `beancount:///ledger/open_ledger/airbnb/files/blob/main/main.bean` once. Wait for Airbnb main.bean: title Airbnb Inc (ABNB) Financial Statements, followed by includes for accounts.bean and 2023.bean through 2026.bean.
4. Tap Back once. The retained main.bean screen shows the old Example Beancount file again, even though the global selected ledger has changed to Airbnb.
5. Tap Back again. Files lists Airbnb's files (2023.bean, 2024.bean, 2025.bean, 2026.bean, accounts.bean, main.bean, etc.). Reopen main.bean from this list: Airbnb content returns correctly.

Repeated after a fresh launch with the initial file opened through the actual Files tab. First run opened both file views through custom links and showed the same retained document. The document display itself does not identify its ledger; current query and action scope follow the selected ledger. Expected: the document, revision/SHA state and ledger identity stay together. Either restore an explicitly bound original ledger on Back, or reload/remount the retained view for the new selected ledger. Do not show the old ledger's buffer while reads/actions refer to the new ledger.

No runtime exception is required to produce this state.

Root cause: `mobile/src/screens/ledger-file-editor-screen/index.tsx:254,272-277` scopes the network-only query to reactive ledgerId and path. At lines 279-302, initialized is component-local state and the file-data effect exits forever once it is true. No ledger/path identity change resets initialized, documentSpec, shaRef or the revision tracker. `app/(app)/ledger-file-editor.tsx:6-7` renders the editor without an identity key, while `src/components/ledger-guard/ledger-guard.tsx` supplies the current reactive ledger. The app-link handler changes ledgerVar at `open-app-link.ts:75`; retained editor instances receive the new scope but keep the old document.

Fix: isolate the entire editor session by ledgerId plus path (a keyed inner editor is one option), including document epoch, SHA, revision tracker, save-in-flight state and asynchronous callbacks. On identity change, show loading until the matching file arrives and prevent an old response from initializing the new document. Preserve same-document unsaved-change protection and do not reset the document on routine background refresh. For read failures, show the current file's failure state rather than an old ledger's document. Regression: two readable ledgers with the same path but different content, open A → switch to B → Back → verify rendered content and request identity agree; closing and reopening remains a working control. Test delayed A responses and readonly state as adjacent cases.

Blast radius: the single editor route is reached from Files, notifications/error navigation and app-link resolution; both Beancount and ordinary text files share the component. Only same-path public Beancount files were reproduced. Writable edits/saves, dirty buffers, differing permissions, denied/expired sessions, failure injection, and physical-device/Android behavior were not tested. No claim of an actual wrong-ledger write or authorization bypass.

Dedupe: searched all .pm markdown including done for initialized, stale document, cross-ledger file and editor identity/reset. No overlapping mobile document-identity task found. w3/097 covers duplicate app-link navigation and is adjacent: removing duplicate pushes alone does not reset a retained editor's document when ledger scope changes. History search for the initialization guard traces it to `3026f123` (native editor); recent editor history includes `afb36a9b`, `b4e2bd6b`, `221f5a4e`, with the guard still present. Report only; no source fix, production write or shipping.

# `bea report --conversion at_value` leaves `@`-priced inventory in commodity units while `--conversion USD` converts it

**Severity:** minor. **Estimate:** 45–60 minutes. **Owner:** cli (Fava convert path).
**A1:** an agent valuing price-only holdings (`2 HOOL @ 10.5 USD` plus a
`price HOOL`) with `at_value` still sees `2 HOOL` on Assets and a mixed
net-worth; the same ledger under `--conversion USD` shows `21.00 USD`.

Found 2026-09-15 by continuous CLI QA against `main`, HEAD `abe462f2`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
bea --file main.bean add open --date 2024-01-01 --account Assets:Investments:HOOL --currency HOOL
bea --file main.bean add price --date 2024-03-01 --currency HOOL --amount '10.5 USD'
bea --file main.bean add transaction --date 2024-03-03 --narration buy \
  --posting 'Assets:Investments:HOOL 2 HOOL @ 10.5 USD' \
  --posting 'Assets:Bank:Checking'

bea --file main.bean report balance-sheet --conversion at_value
# Assets:Investments:HOOL = 2.00 HOOL
# Net Worth: 2.00 HOOL  3,434.08 USD
# (translation adjustment mentions 21.00 USD under equity)

bea --file main.bean report balance-sheet --conversion USD
# Assets:Investments:HOOL = 21.00 USD
# Net Worth: 3,455.08 USD
```

Working control — lots with cost basis `{10.00 USD}` *do* convert under
`at_value` (HOOL line becomes USD). BQL
`SELECT convert(sum(position),'USD') WHERE account ~ 'HOOL'` returns `21.0 USD`.

`USAGE.md`: "`at_value` uses market values with Fava's cost fallback when no
price exists."

## Expected

With a market `price` present, `at_value` should value `@`-priced (cost-less)
inventory in the conversion currency on the asset lines / net worth, matching
`--conversion USD` for a single operating currency (or document the Fava
exception clearly and surface `missing`/partial valuation).

## Actual

`at_value` keeps uncosted units as commodity amounts; USD conversion path
applies the price. Agents following the docs get mixed-currency net worth.

## Root cause

Likely Fava `convert` / `at_value` only revalues cost-held positions, while the
operating-currency conversion path prices any inventory. Confirm in
`bea_engine/report.py` + Fava conversion helpers before changing behavior.

## Fix

Align `at_value` with documented market valuation for price-only lots (reuse
the USD/operating-currency price application), or refuse/warn when at_value
leaves priced commodities unconverted. Regression: the `@` + `price` fixture
above must show HOOL as 21 USD under `at_value` (same as `--conversion USD`);
cost-basis lots stay green.

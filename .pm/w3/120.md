# Accounts loses search and type selection on browser Back

Severity: **minor**. Package: **dashboard**. Estimate: **45–60m**.
A2: inspecting an account and returning to the list should preserve the reader's
selection, so checking the next matching account does not require rebuilding it.

Environment: production https://beancount.io, 2026-09-11, isolated headless
Chrome152.0.7977.83, English/light, authenticated public reader of synthetic
`open_ledger/crypto-example`. Fresh1440×1000 and390×844 contexts. Local and
fetched origin/main are f1965988; implicated source has no newer fix. The
complete deployed build is not proven identical to this commit.

1. Open `/ledger/open_ledger/crypto-example/accounts?lang=en`.
2. Search **binance**, then select the **Liabilities** type. The table shows
   **1 / 45**, only `Liabilities:Crypto:Binance:Margin`.
3. Open that account: click its full account button on desktop, or its visible
   Open-status cell in the clickable row on narrow screens. The destination
   `/ledger/open_ledger/crypto-example/account/Liabilities%3ACrypto%3ABinance%3AMargin`
   correctly shows the margin purchase and repayment.
4. Use browser **Back**. The URL returns to Accounts, but the search is empty,
   **All Types** is selected and **45 / 45** rows appear. Both fresh contexts
   reproduce. An earlier independent narrow parent-prefix keyboard journey also
   loses the same selection on Back.

Expected: Back restores the prior Accounts list selection and one matching row;
Forward returns to the detail. Preserve selection across a subsequent reload of
that restored list if implementing this through validated route search. Do not
apply these list-local controls as global journal/report account predicates.

Margin account. The data is present; the browser drops its local predicates.

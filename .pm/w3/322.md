# `bea report … -a ACCOUNT` keeps counterparty postings; totals disagree with `bea balance`

**Severity:** major. **Estimate:** 45–60 minutes. **Owner:** cli. **A1:** an
agent that runs `report trial-balance -a Assets:Cash` (or overview /
balance-sheet) believing the statement is scoped to Cash still sees
Income/Expenses/Savings and Assets **975** — the full double-entry of every
transaction that touched Cash — while `bea balance Cash` correctly shows only
**875** on Assets:Cash. The header’s `account: Cash` label is therefore a lie
whenever Cash is a hub account.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `5e8f3039`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only. Evidence: `cli/tmp/qa-20260915/c667/`, `c668/`.

## Repro

```sh
cat > main.bean <<'EOF'
option "operating_currency" "USD"
2020-01-01 open Assets:Cash USD
2020-01-01 open Assets:Savings USD
2020-01-01 open Expenses:Food USD
2020-01-01 open Income:Salary USD
2020-01-15 * "salary"
  Assets:Cash  1000.00 USD
  Income:Salary
2020-06-01 * "food"
  Expenses:Food  25.00 USD
  Assets:Cash
2020-12-01 * "save"
  Assets:Savings  100.00 USD
  Assets:Cash
EOF

bea --file main.bean balance Cash
# Trial Balance … account: Cash
#   Assets  875.00 USD
#     Cash  875.00 USD
# (Savings / Income / Expenses absent)

bea --file main.bean report trial-balance -a Cash
# Trial Balance … account: Cash
#   Assets  975.00 USD
#     Cash  875.00 USD
#     Savings 100.00 USD
#   Income -1,000.00 USD …
#   Expenses 25.00 USD …

bea --file main.bean report trial-balance -a Assets:Cash
# same unscoped tree / 975 Assets

bea --file main.bean report overview -a Cash
# Assets 975 / Income -1000 / Expenses 25 / Net Worth 975

bea --file main.bean report balance-sheet -a Cash
# Assets includes Savings; Net Worth 975
```

Working control — income-statement on a leaf expense can look narrowed because
few counterparties sit on that statement:

```sh
bea --file main.bean report income-statement -t 2020 -a Food
# Expenses:Food 25 only (Income 0)
```

## Expected

`--account` / `-a` on `report` matches the help (“parent account or a regular
expression”) and `bea balance`’s tree prune: show balances **for matching
accounts** (and ancestors as needed), not every posting on every transaction
that merely touched the match. Header `account: …` must describe the tree that
was actually rendered. Hub accounts like Checking/Cash must not silently
reproduce the unfiltered statement.

## Actual

`bea_engine/report.py` `_load(..., account=…)` applies Fava `AccountFilter`,
which keeps whole directives whose `get_entry_accounts` hit the match
(`fava/core/filters.py`). Overview / income-statement / balance-sheet /
trial-balance then build trees from that entry set — counterparties remain.
`_balances` (the `bea balance` command) instead computes a full trial balance
and **prunes** with `_prune_tree` by substring — different semantics, same
“account: Cash” metadata label.

## Fix

After entry filtering (or instead of it for tree reports), prune report trees
the way `_balances` does (or filter inventories to matching accounts before
aggregation). Keep Nomatch → honest empty/zero behavior (see w3/292).
Regression: the Cash fixture’s `report trial-balance -a Cash` Assets total
equals `bea balance Cash` (875); Savings/Income/Expenses are absent (or clearly
marked as counterparts if product wants an optional journal-style mode).

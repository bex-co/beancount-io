# `bea add balance` appends an identical assertion (no price-style idempotency)

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** cli. **A1:** an
agent that re-runs the same `add balance` (retry, script, or recovery after a
uncertain write) silently doubles the assertion — `check` stays green — while
`add price` already no-ops on an exact match.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `047d2be0`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
cat > main.bean <<'EOF'
option "operating_currency" "USD"
2020-01-01 open Assets:Cash USD
2020-01-01 open Equity:Opening USD
2020-01-02 * "Opening"
  Assets:Cash     100 USD
  Equity:Opening -100 USD
2020-04-01 balance Assets:Cash 100 USD
EOF

bea --file main.bean add balance --date 2020-04-01 -a Assets:Cash --amount '100 USD'
# exit 0 — "Added 1 balance …"
# file now has two identical assertions (spacing may differ)

bea --file main.bean check   # exit 0

# Control — price idempotency:
bea --file main.bean add price --date 2020-05-01 -c EUR --amount '1.10 USD'
bea --file main.bean add price --date 2020-05-01 -c EUR --amount '1.10 USD'
# "Price already recorded …; nothing was written."
```

Same missing short-circuit for exact-duplicate `add note` / `add event` (weaker;
USAGE documents the price pattern most clearly for balance recovery hints).

## Expected

Exact same date + account + amount (+ tolerance) → exit 0, nothing written,
human “Balance already recorded …”, JSON `written: 0` / `duplicate: true` with
`source` — matching `add price`.

## Actual

`_balance()` always appends. JSON reports `written: 1`. Beancount accepts the
duplicate lines, so there is no validation safety net.

## Root cause

`cli/src/bea_engine/ledger/adding.py`: only `_price()` scans for an exact match
before append; `_balance()` (~144–160) calls `_appended()` directly. Frontend
`add.py` handles `duplicate` only for price.

## Fix

Before append, if an existing balance matches date/account/amount/tolerance,
return the duplicate short-circuit used by price. Optionally apply the same to
note/event. Regression: second identical `add balance` no-ops; different amount
or date still writes; price behavior unchanged.

## Dedupe

Not w3/291 (same-day price with a *different* amount). Not w3/293 (human
tolerance display). Not w3/243 / done/224 (`--pad-from`). No open note covers
exact-duplicate `add balance` append.

# Failed `bea add` / bulk rejects cite ledger line numbers that do not exist after “nothing was written”

**Severity:** minor. **Estimate:** 30–45 minutes. **Owner:** cli. **A1:** an
agent that follows `main.bean:9` from a validation error opens a file that ends
at line 7 (or never had the rejected entry), wastes a turn, and may “fix” the
wrong existing transaction.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `3293ae7f`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
# main.bean is 3 lines (option + 2 opens)
bea --file main.bean add transaction --date 2020-02-01 --narration bad \
  --posting 'Assets:Cash -1 USD'
# exit 1
# Error: The change would leave the ledger invalid; nothing was written.
#   …/main.bean:5: Transaction does not balance: (-1 USD)
# file still ends at line 3 — line 5 does not exist

bea --file main.bean add transactions --from mixed.json --partial
# mixed.json: row1 balanced, row2 unbalanced
# exit 1 — "Added 1 of 2… Row 2: …/main.bean:9: Transaction does not balance"
# final file has only the accepted txn (lines 1–7); line 9 does not exist
```

Working control: `bea check` on a ledger that already contains an unbalanced
txn cites a real line that `sed -n 'Np'` can show.

## Expected

When the cited entry was never committed (atomic reject, or a `--partial`
rejected row), the detail should not pretend it lives at a stable path:line in
the on-disk ledger. Prefer row-oriented wording (`Row 2: Transaction does not
balance…`) and/or mark the location as proposed (`candidate` / `would be at`),
without a clickable line that is absent after the command.

## Actual

Validation runs on a staged candidate that includes the proposed append.
Beancount’s `meta.lineno` from that candidate is copied into the user-facing
`LedgerError` details even when `write.py` discards the candidate (`nothing was
written`) or omits a rejected `--partial` row. The path is the real ledger
path, so agents treat the line as authoritative.

## Fix

When emitting errors for uncommitted candidate content, either (1) rewrite
details to name the JSON/CLI row and drop path:line, or (2) keep path:line but
prefix clearly (`proposed append`, `not written`). For `--partial`, never cite
a line past the post-write EOF for a rejected row. Regression: the two
reproducers above mention Row / proposed and do not point at a missing line;
`bea check` on an already-invalid file still cites real lines.

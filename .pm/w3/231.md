# `bea add transactions` without `--partial` overstates how many rows `--partial` would accept when schema and balance failures are mixed

**Severity:** minor. **Estimate:** 30–45 minutes. **Owner:** cli. **A1:** an
agent told “pass `--partial` to append the 2 valid row(s)” after a mixed batch
still sees one of those rows rejected for not balancing, so the recovery advice
is wrong.

Found 2026-09-15 by continuous CLI QA against `main`, HEAD `3aaafec0`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
cat > rows.json <<'EOF'
[
  {"date":"2024-03-20","narration":"ok","postings":[
    {"account":"Expenses:Food:Groceries","amount":"1 USD"},
    {"account":"Assets:Bank:Checking"}
  ]},
  {"date":"nope","narration":"bad date","postings":[
    {"account":"Expenses:Food:Groceries","amount":"1 USD"},
    {"account":"Assets:Bank:Checking"}
  ]},
  {"date":"2024-03-22","narration":"unbal","postings":[
    {"account":"Expenses:Food:Groceries","amount":"1 USD"}
  ]}
]
EOF

bea --json --file main.bean add transactions --from rows.json
# exit 1 — nothing written
# message: "1 of 3 row(s) are invalid; nothing was written.
#   Fix them, or pass --partial to append the 2 valid row(s)."
# result.rejected_rows: [1]   # only the schema failure
```

Control — same file with `--partial`:

```sh
bea --json --file main.bean add transactions --from rows.json --partial
# exit 1 — writes only row 0
# "Added 1 of 3 transactions; 2 rows were rejected."
# rejected_rows: [1, 2]  # bad date + unbalanced
```

So without `--partial`, the CLI stops after schema validation and claims two
rows are valid; with `--partial`, only one row is actually appendable.

## Expected

The non-partial error should not promise a `--partial` write count higher than
what ledger validation would accept. Options:

1. Run the same per-row ledger validation used by `--partial` before composing
   the message (count only rows that would write), or
2. Soften the text to “pass `--partial` to append schema-valid rows (ledger
   validation may still reject some)”, and list only schema `rejected_rows`
   explicitly as schema failures.

## Actual

On any schema rejection, `adding._transactions` returns early with
`len(valid)` as the promised `--partial` count, without checking balance /
account errors on those rows.

## Root cause

```text
cli/src/bea_engine/ledger/adding.py:422-433
  if rejected and not partial:
      raise … append the {len(valid)} valid row(s) …
# ledger validation for valid rows happens only later (:437+)
```

## Fix

Before the non-partial schema short-circuit message, either validate each
schema-valid row against the ledger the way the partial path does, or change
the copy so it does not assert a write count. Add a regression with the three
row fixture above: non-partial must not say “2 valid”; `--partial` still writes
exactly one.

# `bea query -o` truncates or corrupts the ledger when `--output` is the same path as `--file`

**Severity:** critical. **Estimate:** 30–45 minutes. **Owner:** cli. **A1:** an
agent that redirects a query onto the ledger path (typo, script variable reuse,
or `PRINT -o main.bean` to “pretty-print in place”) silently **wipes** the books
(human mode: 0-byte file) or **replaces** them with a JSON envelope (`--json`),
then exits 0 — recoverable only from backups.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `6e10272e`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
cat > main.bean <<'EOF'
option "operating_currency" "USD"
2020-01-01 open Assets:Cash USD
2020-01-01 open Equity:Opening-Balances

2020-01-01 * "seed"
  Assets:Cash               100 USD
  Equity:Opening-Balances  -100 USD
EOF

bea --file main.bean query 'PRINT' -o main.bean
echo exit=$?
wc -c main.bean
# exit 0
# stderr: (no rows)
# main.bean is 0 bytes

# restore, then JSON mode:
bea --json --file main.bean query 'PRINT' -o main.bean
# exit 0; stdout empty; main.bean begins with {"bea": "0.2.0", ...}
bea --file main.bean check
# syntax error, unexpected LCURL
```

Also reproduces with `SELECT account` (not only `PRINT`), with relative
`./main.bean` for both flags, and when `--file` and `-o` are **different
paths that share an inode** (hard link): both names become 0 bytes.

Interactive shell vector (same class — destination is the ledger):

```sh
bea --file main.bean query
# at beanquery> prompt:
.output main.bean
SELECT account LIMIT 1
.quit
# main.bean is now the text table (~tens of bytes), not a ledger
```

Working control — different output path:

```sh
bea --file main.bean query 'PRINT' -o /tmp/out.bean
# exit 0; main.bean unchanged; /tmp/out.bean has formatted directives
```

## Expected

Refuse with exit **2** (usage) when `--output` / `.output` resolves to the same
file as the ledger being queried (after `realpath` / same-file check), with a
message that names both paths. Do not open the ledger for write before it has
been loaded. `--json` must not write the envelope into the ledger file either.

## Actual

Human mode: managed engine opens `-o` with `"w"` **before** loading the ledger
(`bea_engine/query.py` `destination = output.open("w")`), truncating the file;
the subsequent load sees an empty ledger, `PRINT`/`SELECT` yield no rows,
stderr prints `(no rows)`, exit 0 — ledger gone.

JSON mode: frontend honors `-o` via `output.emit(..., destination=Path(...))`
and atomically writes the JSON envelope **into** the ledger path; `bea check`
then fails on `{`.

Interactive: `PreciseShell.do_output` opens the path with `"w"`
(`bea_engine/query.py`); a following `SELECT` writes the table over the books.

## Fix

1. In `cli/src/cli/commands/query.py` (and any path that forwards `--output`),
   resolve both `--file` and `-o` and raise `UsageError` when they are the same
   inode/path.
2. In `bea_engine/query.py`, do not open the output file until after a successful
   load (or open with exclusive create / write to a temp then rename only when
   destination ≠ source). Guard `do_output` the same way against the loaded
   ledger path. Prefer failing closed over truncating.
3. Regression: the one-shot and interactive repros exit/refuse with an intact
   ledger; distinct `-o` / `.output` paths and stdout still work for `PRINT`
   and `SELECT`.

## Dedupe

Not w3/277 (one-shot `.output PATH` creates an empty **external** file; no
ledger wipe). Not w3/270 / w3/250 (`--output` directory / missing parent → raw
errno). Not w2/done/021 (fixed: `--json query` ignoring `-o`). No open note
covers `-o` / `.output` == `--file` destroying the ledger.

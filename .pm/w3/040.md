# File edit shortcuts and URLs expose an editable draft to public readers

Severity: **minor**. Owner: **dashboard**. Estimate: **45–60 minutes**.
A2: public-ledger readers should receive controls that match their permission
and avoid preparing changes they cannot save.

Production `https://beancount.io`, 2026-09-08, Chrome 152, English, System/light;
1440×1000 and fresh narrow 390×844. Authenticated QA reader of public
`open_ledger/budgeting-envelopes`: a fresh GraphQL read returned HTTP200 with
`admin:false, pull:true, push:false`. Local `a315c273`; fetched main `cc3f4c2f`
has unchanged implicated file-editor code. Deployed SHA unverified.

1. Open `/ledger/open_ledger/budgeting-envelopes/files/blob/main/accounts.bean`.
   Ordinary view hides Edit and shows only More actions; typing is rejected.
2. Press **Cmd+E** in the desktop browser. The route gains `?editMode=true`,
   and Edit, Save and Cancel controls appear.
3. Focus the editor and type an unsaved comment such as
   `; qa-local-unsaved-shortcut-probe`. The buffer accepts it and Save is enabled.
4. Reload from the ordinary route at 390×844 and repeat the shortcut; the
   read-only typing control is rejected, but shortcut-triggered editing accepts
   the local comment. A fresh desktop load with `?editMode=true` also enters
   edit mode immediately; the actual Monaco model reports `readOnly:false`.

Expected: effective edit mode requires current ledger write permission,
regardless of a URL parameter or keyboard shortcut. Readers retain file
selection, search, copy and download, with an immutable editor. Writer access
must still use the existing permission contract.

This is a misleading UI and draft-editing defect. No Save or Delete was
invoked, no write request was sent, and no server authorization bypass is
claimed. Source-side authorization remains in backend-v2
`ledger-workflow.ts:591–595`, which checks `LEDGER_FILES_WRITE` before updating
a file. The ordinary view is a working browser control; the server check was
traced in source and must be preserved.

Root cause: `dashboard/src/features/ledger-editor/file-editor/components/ledger-file-view/text-file-view.tsx:96–112`
registers Cmd/Ctrl+E whenever `isEditMode` is false without checking permission.
`ledger-file-view/index.tsx:94–101` sets the URL flag unconditionally. The blob
route parses that boolean, and `file-content-view.tsx:79–88` passes it through.
`text-file-view.tsx:141–169` renders the edit toolbar and sets editor readOnly
solely from that flag. The ordinary button's `LedgerWritePermission` wrapper
in `non-text-file-views.tsx:121–136` guards only its own rendered control.

Use `useLedgerPermission` to derive effective edit state and gate shortcut,
toolbar, and save handlers, defaulting to read-only while access is unresolved.
Reject or normalize an unauthorized `editMode` URL without creating a navigation
loop. If permission is lost during a legitimate draft, block further mutation
and preserve the draft for explicit recovery rather than silently discarding it.
Keep writer editing, existing dirty-state protection and source-line navigation.

Blast radius: FileContentView is the sole TextFileView caller; EditModeToolbar
is also used only there. This covers the blob route for Beancount, Markdown,
plain text and supported extensionless text. Non-text previews have separate
renderers. Direct URL and Cmd+E were exercised; Ctrl+E is the same source branch
but was not run on another OS. Guest and authorized-writer journeys remain
unverified in this pass.

Acceptance: real routed file-view tests cover reader/guest/loading permissions,
direct edit URLs, shortcuts, and permission loss, with no save callback possible
without write permission. Include an authorized writer control. Assert actual
editor behavior and toolbar state, not only absence of the ordinary Edit button.
Run dashboard format, lint, tests and build.

Dedupe: searched all open/completed board records for file shortcuts, editMode,
read-only editors and mutation controls; scanned open milestone summaries.
`w3/m11/t003` concerns **EntryContextDialog**, whose callers and full DoD were
reviewed. Fetched main has completed m11 and guards that dialog, while these
separate file-view files remain unchanged; this is not deployment lag or a
reopened dialog task. `w2/m7` added extensionless file previews, not permission
gating. History traces the shortcut and URL setter to `af5339de`; subsequent
localization/language fixes do not repair access handling.

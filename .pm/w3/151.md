# Keep native navigation action labels inside the bar

**Minor · 45–60m · mobile.** A2: users needing larger text must still be able to read the actions that finish an entry step.

Environment: September11,2026; production https://beancount.io; local HEADf1965988/mobile7538fb0d; native bundle io.beancount.ios, version1.20260906.47; iPhone17e/iOS26.5; English/System-light; public open_ledger/minimax with authenticated QA pull/push permission. No transaction submitted, and no production write. Dynamic Type restored to default large after the pass.

1. Set iOS text size to the maximum accessibility category (simctl content_size accessibility-extra-extra-extra-large), then terminate/relaunch the native app and wait for Home.
2. Use the actual Transactions tab, then plus. New Transaction displays its native title and Back button normally, but the custom **Done** label grows beyond the navigation-bar action container and its lower portion is cut off. This persists while scrolling the form to the last posting and remainder.
3. A fresh maximum-size relaunch repeats the same result: initial PID48339, repeat PID49363.
4. In the fresh repeat, tap the actual Payee row. Its enabled **Save** label has the same vertical clipping. Nothing is saved; this Payee Save would only return text to the draft, but was not invoked during this check.
5. Working control: relaunch at **accessibility-large** (PID48958), open the same form, and Done fits completely. Default-large screenshots from the same session also show complete Done and Payee Save labels.

Expected: header actions stay fully readable, inside the native navigation bar, at supported accessibility text sizes. Actual: the native bar retains its action height while custom React Native Text grows beyond it. The form body itself scrolls, and capped amount values remain readable; this report does not claim the whole form is inaccessible or that the buttons stop receiving taps. Save/Done invocation under the failing setting, VoiceOver speech, Android and physical devices remain unverified.

Root: `mobile/src/common/theme/typography.ts:97–101` supplies headerActionStyle with fontSize18 and no scaling policy. `multi-postings-transaction-screen.tsx:465–483` puts an unrestricted Text using that style into Stack.headerRight; `components/text-input-screen/index.tsx:171–180` does the same for Save. The native header clips the oversized text, visible in the screenshots. Existing amountMaxFontSizeMultiplier at typography.ts:94 deliberately limits constrained amount text, which is a working approach to sizing policy; it is not currently applied to these action labels. Do not claim an iOS gesture or network cause.

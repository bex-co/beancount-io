# `bea doctor directories` prints ERROR lines but exits 0 on invalid document trees

**Severity:** minor. **Estimate:** 15–25 minutes. **Owner:** cli. **A1:** an
agent or CI gate that runs `bea doctor directories LEDGER DOCS/` expects a
nonzero exit when the hierarchy disagrees with open accounts — instead it gets
`ERROR: Invalid directory …` on stdout and exit **0**.

Found 2026-09-16 by continuous CLI QA ([c1120 hunt](0129c139-d6cd-4db9-b6dd-93d44d490212)),
HEAD `22334bf1`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Evidence:
`cli/tmp/qa-20260915/c1120/`.

## Repro

```sh
mkdir -p docs_bad/Wrong/Account
bea doctor directories main.bean docs_bad/
# ERROR: Invalid directory … no corresponding account 'Wrong:Account'
# exit 0

# control matching tree: quiet, exit 0
```

## Expected

Mismatches exit nonzero (map ERROR output to exit **1**), so automation can
gate on the command.

## Actual

Wrapper forwards bean-doctor’s exit **0** while ERROR lines print to stdout.

## Fix

Treat `ERROR:` output (or upstream status) as failure. Regression: mismatch
exits **1**; valid tree stays **0**.

## Dedupe

Same family as w3/345 / 363 false-greens but exclusive to `doctor directories`.
No open note covers it.

# `bea add price` silently appends a second same-day quote when the amount differs

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** cli. **A1:** an
agent that corrects a wrong FX quote with another `add price` on the same
date/commodity gets a second directive instead of a conflict — `check` stays
green, conversion silently switches to the later line, and only an *exact*
amount match is reported as “already recorded”.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `f0783e97`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
# Ledger already has: 2020-04-01 price EUR 1.10 USD

bea --file main.bean add price --date 2020-04-01 -c EUR --amount '1.10 USD'
# exit 0 — "Price already recorded …; nothing was written."

bea --file main.bean add price --date 2020-04-01 -c EUR --amount '1.20 USD'
# exit 0 — "Added 1 price …"
# file now contains BOTH:
#   2020-04-01 price EUR 1.10 USD
#   2020-04-01 price EUR 1.20 USD

bea --file main.bean check   # exit 0
bea --file main.bean report balance-sheet -x EUR --allow-errors
# Cash valued with 1/1.20 (later quote wins), not 1/1.10
```

## Expected

Same date + commodity with a **different** amount is either rejected (exit 1/2
naming the existing quote) or requires an explicit flag (e.g. `--replace` /
`--allow-duplicate-date`) before writing. Exact-match short-circuit can stay.

## Actual

Only exact date/commodity/amount matches short-circuit. A different amount
appends another price directive; Beancount accepts it and later quotes win in
conversion with no CLI warning.

## Root cause

`add price` idempotency checks for an exact amount match (help text:
“report an exact existing date/commodity/amount match”) and otherwise appends.
No same-day/commodity conflict path.

## Fix

Before append, if any price exists for the same date+commodity with a different
amount, raise a validation/usage error that shows the existing quote and how to
replace it (edit the file, or a documented replace flag). Regression: exact
`1.10` still no-ops; `1.20` on the same day errors unless opted in; distinct
dates still append.

## Objective

Add ADR026's nullable account field `defaultCurrency`: stored with the user, readable wherever the profile is, and written only through `updateProfile`.

## Context

- User model: `backend-cluster/backend-v2/src/features/auth/data/user-model/` (Drizzle schema, Postgres impl); migrations in `src/drizzle/migrations/` (last `0027`).
- Profile reads: GraphQL `getUserProfile` (`features/auth/api/account-resolver.ts`), REST `GET /api-gateway/v1/user-profile` (`account-routes.ts`), MCP `userProfile` resource (`features/ai-agent/api/mcp-resources.ts`).
- `Mutation.updateProfile` keeps its documented REST/MCP exclusion (`src/server/api/op-class.ts`).
- Values are validated against ADR021's supported currencies (`features/ledger/setup/currencies.json`).

## Steps

1. Add the nullable column and migration `0028`.
2. Return `defaultCurrency` from all three profile reads.
3. Accept an optional `defaultCurrency` on `updateProfile` (null clears), refusing unsupported codes.
4. Regenerate the OpenAPI snapshot; keep the parity gate at zero.

## Files

- `backend-cluster/backend-v2/src/features/auth/`
- `backend-cluster/backend-v2/src/drizzle/migrations/`
- `backend-cluster/backend-v2/docs/openapi/v1.json`

## Acceptance criteria

- [ ] REST, GraphQL, and MCP profile reads return the same `defaultCurrency` (null when unset).
- [ ] `updateProfile` stores a supported code, clears on null, refuses an unsupported one, and leaves names unchanged when only the currency is sent.
- [ ] `previewLedgerSetup`/`createLedger` never read it: an omitted `operatingCurrency` stays ADR021's default.
- [ ] `yarn typecheck` and `yarn test` pass.

## Out of scope

- Client reads and writes (t002, t004); a settings screen control.

# Keyboard filter selection is replaced by the partial search text

Severity: **major**. Owner: **dashboard**. Estimate: **45–60 minutes** for
the shared commit handler and meaningful interaction coverage. A2: selecting a
suggested account, year or payee applies that selection and its expected scope.

Production `https://beancount.io`, 2026-09-08, Chrome 152, English,
System/light; authenticated reader of public synthetic `open_ledger/crypto-example`.
Fresh desktop 1440×1000 and tablet-width 1024×844 repeats. Local HEAD `a315c273`,
fetched main `cc3f4c2f`; implicated code is unchanged there. Deployed SHA
unverified. At fresh 390×844 the controls are hidden by the separate m20 defect,
so selection at that width remains unverified.

1. Load `/ledger/open_ledger/crypto-example/journal` with no global filters and
   Transaction selected. Wait for the header's Account combobox.
2. Type **BTC**. Four suggestions appear: Binance, Coinbase, Mining and Ledger
   wallet BTC accounts, in that order.
3. Press ArrowDown twice. **Assets:Crypto:Coinbase:BTC** is visibly highlighted.
4. Press Enter. The input and URL retain **BTC** instead of the selected full
   account. Journal returns **15 transactions**, including other BTC accounts.
5. Clear all, type BTC again and click the Coinbase suggestion with the mouse.
   The full account is retained and the journal correctly returns **7**.
6. Typing the complete account string and pressing Enter also returns 7.

Both fresh widths reproduce the same keyboard/pointer/exact-text results.
Actual GetLedgerJournal requests contain `account: "BTC"` with total 15 after
keyboard selection, versus the full account with total 7 for both controls.
All return HTTP 200 with no GraphQL, page or console errors. REST reads with
the same account, Transaction type and pagination independently return 15/7.
The API correctly serves the filter it receives.

Other instances reproduce the same cause on fresh desktop loads:

- Type **Coin** in the payee/tag filter, highlight `payee:"Coinbase"`, then
  Enter. It commits Coin and returns 12 entries; exact `payee:"Coinbase"`
  returns 11.
- Type **202** in Time and highlight **2024**, then Enter. It commits 202 and
  shows the journal's generic server-error message. A fresh 1024px repeat
  matches; exact **2024** returns 67 transactions. The invalid request reaches
  GraphQL as `INTERNAL_SERVER_ERROR`, the already tracked category bug in 024.

Root cause: `dashboard/src/common/components/ui/combobox.tsx:75–79`
handles explicit selection by scheduling `setInputValue(selectedValue)`,
calling `onValueChange(selectedValue)`, then immediately blurring the input.
Its blur handler at 108–112 commits the old render's `inputValue` whenever
`allowCustom` and `triggerOn="blur"`. Keyboard Enter calls that path at
120–124 while the input still has focus, so the blur overwrites the explicit
choice with the draft query. Exact-text Enter has no different draft to
overwrite it with. Pointer selection happens after the earlier input blur and
therefore leaves the selected canonical value last.

`common/components/ledger-search-controls/index.tsx:159–191` sets all three
global controls to custom/blur mode. Its change handler at 84–92 passes the
value straight into the shared filter provider, and Journal consumes that
committed value. The wrong input is present before URL serialization; m15's
encoding/history repair cannot fix this event-order problem.

Fix the common Combobox's commit handling: an explicit highlighted selection
must remain the committed value through any resulting blur and be committed
once. Distinguish that programmatic blur from an ordinary user blur that should
commit a custom draft. Keep pointer selection, complete/custom Enter, ordinary
blur, clearing and externally controlled value updates coherent. Do not defer
the race with a timeout, disable custom filters, or make backend matching guess
which suggestion the user intended.

Caller search: seven production wrappers use Combobox. SearchControlCombobox
is the only wrapper opting into blur mode, in these three global instances.
Account, currency, operating-currency, payee, narration and source-file wrappers
retain default change mode; source-file also disallows custom values. Preserve
those modes with focused regression cases instead of changing their semantics.
A real 390px Import control confirms default-mode keyboard selection works:
Coinbase:USD → ArrowDown → Enter retains Assets:Crypto:Coinbase:USD. Assigning
both target accounts and toggling selections preserves those values. No import
was submitted; all local configuration was discarded. This additional control
is saved in `extra-filter-import-controls.json` beside the primary evidence.
The affected header is currently shared by Overview, Journal, Income Statement,
Balance Sheet, Trial Balance, account detail, Events and Statistics; Cash Flow
and narrow exposure are queued in m20. Only Journal's resulting data was
exercised for this finding.

Acceptance: the exact Coinbase keyboard journey commits the full account and
returns 7, matching pointer selection. Coin→Coinbase commits the full expression
and returns 11; 202→2024 commits 2024 and returns 67. In a controlled component
test using real focus/keyboard events, assert the final committed value and
absence of a later stale-draft callback. The existing click-only default-mode
test merely checks that the desired value appears among calls and does not
cover this failure. Preserve ordinary custom blur, clearing and the six default
mode wrappers. Run dashboard gates when implementing; no API change is needed.

Dedupe: searched open/completed board records for combobox blur, partial filter
selection and keyboard commits, and reviewed open milestone summaries. 010 is
the separately implemented Gallery search. m15 owns provider/URL state; m20 owns
filter visibility and future panel integration. Coordinate this existing
primitive repair with m20/t003 rather than introducing another panel-specific
workaround. 024 retains the invalid-input category repair. Targeted history
traces the immediate blur to `af5339de`, with no newer fix on main.

Other routes' data, native touch, screen readers, other locales/browsers,

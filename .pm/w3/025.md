# Narrow statement tables split digits across lines

Severity: minor. Owner: dashboard. Estimate: 30–45 minutes. A2: a reader can
read a complete decimal amount on a phone-width statement without reconstructing
digits from separate lines.

Environment: production https://beancount.io, Chrome 152, authenticated QA public
reader on synthetic `open_ledger/example`, English/System light, 390×844 and
1440×1000. Fresh narrow repeat on 2026-09-08. Source HEAD a315c273; fetched
origin/main cc3f4c2f has no matching layout correction. Deployed build identity
is not proven equal to local HEAD.

Reproduce:

1. At 390×844 open `/ledger/open_ledger/example/balance-sheet?time=2016` and
   wait for Assets List values to settle, with Monthly/At Cost selected.
2. Assets and US each display `80,149.80` on one line and the final `7` on the
   next line. DOM text is still `80,149.807`; character Range measurements place
   the first nine characters at y=653 and the final digit at y=673. The amount
   cell is 78.5px wide and 40px high. Fresh navigation repeats it.
3. `6,377.23` in the same layout occupies one line/20px. At 1440px all characters
   of `80,149.807` occupy the same line, so this is width-dependent rendering.
4. Fresh `/trial-balance?time=2016` also wraps `-42,588.767`, `-39,098.25` and
   `-3,490.533` into 40px cells while shorter amounts remain 20px high.

Expected: preserve each displayed signed decimal as one readable unit. Do not
round away digits, clip, overlap adjacent commodities or hide amounts to make
the layout fit. A locally scrollable table is acceptable when the columns need
more space than the viewport.

Root cause: `dashboard/src/features/reports/balance-sheet/hierarchy-list.tsx:39`
uses a fixed 12-column grid; amount cells at `:137`/`:144` each get three
columns. The numeric element at `:70` has no wrapping override and inherits
`overflow-wrap:anywhere` from `common/root-route/shell-component.tsx:20`.
The inherited rule allows a break within a number once the narrow column fills.
The shared PrimaryCurrencyColumn and OtherBalancesColumn also render summary
amounts; keep signs, precision and commodity labels intact across both.

Fix numeric wrapping locally in HierarchyList and give the amount columns
enough minimum space, with horizontal scrolling or another deliberate narrow
layout when needed. Keep headers aligned with all tree/summary rows and retain
account expansion/navigation. Do not remove the root long-text wrapping policy.
No GraphQL/REST/MCP or report arithmetic changes are needed: GraphQL at-cost
assets are 80149.80683 USD plus 25 VACHR, consistent with the displayed rounded
string; the DOM retains that string and only its layout is broken.

Blast radius: shared HierarchyList/Card is used by Balance Sheet, Income
Statement, Cash Flow and Trial Balance. Balance Sheet and Trial Balance are
observed; the other two are source-traced shared callers. Short values and
desktop width are working controls.

Acceptance: fresh 390px Balance Sheet/Trial Balance render each signed decimal
on one line without clipping/overlap; headers, other units and long account
labels remain readable and reachable. Check larger totals and multi-commodity
rows in the same component, plus 1440px and statement print/export controls.
A browser layout check is sufficient for this CSS fix; do not add mock-only
tests of class names.

Dedupe: searched all open/done board records for amount/decimal wrapping and
narrow columns; no overlap found. `w3/012` concerns tooltip rounding, not line
breaks, and `w3/020`/`022` concern print isolation/data snapshots. Targeted
history traces both the grid and root wrapping policy to af5339de; the later
cash-flow hierarchy reuse did not introduce the initial behavior.

Unverified: native app, other locales, browser zoom, every currency/amount
length and print behavior after the proposed CSS change. No product fix or
shipping included.

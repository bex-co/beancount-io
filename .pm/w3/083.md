# A background quota read turns the public Ask landing page into a login redirect

**Severity:** minor. **Owner:** dashboard. **Estimate:** 35–50 minutes.
**A2/A3:** a new visitor can inspect the public Ask introduction before choosing
to sign in and submit a protected request.

Production `https://beancount.io`, 2026-09-08, Chrome 152, English/light.
Public `open_ledger/example`; 1440×1000 and 390×844 isolated guest contexts.
Local HEAD `a315c273`, fetched main `afb36a9b`; implicated dashboard files
unchanged. Deployed SHA unverified.

1. With no site cookies, open `/ledger/open_ledger/example/agent?lang=en`.
   Do not supply `q`, enter text, attach a file or submit anything.
2. The HTTP200 page automatically navigates to login. `next` retains the
   Ask path; the separate incorrect `reason=expired` wording is already060.
3. Repeat on `/ledger/open_ledger/example/ask?mode=sandbox&lang=en` and both
   widths. Four ordinary cases and four fresh repeats reproduce the redirect.
4. In four isolated causal controls, hold only `GetAiCfoUsage` before sending
   it. The public greeting, empty enabled composer and Log In / Sign Up action
   remain visible. Release the read and forward its actual HTTP200 GraphQL
   `UNAUTHENTICATED` response unchanged: the page then navigates to login.
5. In four authenticated controls the same quota query returns data without
   errors, and both empty Ask surfaces remain open. Personal quota amounts
   and private response data were not retained.

Expected: mounting this public introduction does not require a private usage
read. Completed `w2/m8` explicitly classifies base Ask/Agent as an indexable
public acquisition surface, separately from protected shells and prefilled
questions. The current Agent route also has no auth guard, and its greeting
and composer render for guests. This report concerns viewing that introduction;
submitting a question still requires authentication and available quota.

Root cause: `features/ai-agent/pages/agent/page.tsx:333` always mounts
`AiCfoUpgradePanel`, including when its existing `isAuthenticated` value is
false. `common/components/ai-cfo-upgrade-panel.tsx:15–24` invokes usage before
its hide/loading conditions. `common/hooks/use-ai-cfo-usage.ts:7–11` always
starts `GetAiCfoUsage` with cache-and-network. The query in
`graphql/query/auth.graphql:49` reads private current-user usage. Backend
`feature-usage/service/ai-cfo-usage-service.ts:115–120` correctly authorizes
`USER_AI_USAGE_READ`; its guest denial is not a backend bug.

`common/apollo/links/auth-error-link.ts:73–83` correctly redirects a protected
operation's denial. It exempts optional identity probes, not private usage.
Other observed reads (`GetCurrentUser`, public tier quotas, ledger accounts,
errors and events) return HTTP200 without GraphQL errors in these guest cases.
No chat request or mutation is attempted, and there are no page exceptions.

Use the existing authenticated state to mount the quota panel only for signed-in
visitors on the shared Agent page. `common/hooks/use-is-authenticated.ts:3–5`
already reads the root identity; no additional identity request or state layer
is needed. Keep hook calls valid and preserve authenticated usage/upgrade
behavior. Both ordinary Agent and sandbox Ask use this component. The other
panel caller is Import; the other usage-hook caller is authenticated Settings.
Those are source-audited controls, not reasons to expand this fix into access
policy for Import or other protected features.

Do not whitelist private quota queries globally, make usage publicly readable,
relax chat authentication/quota checks, or change the page's indexability to
conceal the navigation bug. The real guest chat denials in082 confirm that the
protected submission boundary remains separate from viewing the introduction.

Acceptance: without a question, fresh guests can remain on either Ask surface
at both widths and no private quota request fires. Signed-in visitors still
fetch usage and can see the existing limit/upgrade panel when applicable.
A meaningful regression exercises guest versus authenticated mounting and
request behavior; retain protected-query redirects and optional-identity
exclusions. Expired signed-in sessions and actual model output remain separate
unverified cases.

Dedupe: all local open/completed boards and fetched main searched for public
Ask, guest quota and usage-query redirects.060 owns misleading expiry copy;
082 owns query/mode loss after a chat401. Neither prevents this unsolicited
private read. Completed `w2/m8` supplies the public-surface policy but did not
test hydrated guest navigation. `2f982c52` deliberately protected anonymous
public browsing by exempting nullable identity probes; keep that behavior.
The unconditional panel/query dates to `af5339de`; fetched main has no repair.

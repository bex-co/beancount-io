# Journal export loses keyboard focus when its dialog closes

Promoted to [m23](./m23/README.md) after independent Budget-dialog reproduction.
The original Journal evidence below is retained; implement and close the shared
focus-return work through that milestone. Count this historical note only once.

Severity: **minor**. Owner: **dashboard**. Estimate: **25–40 minutes**.
A2: keyboard users can inspect and dismiss a journal download without losing
their place in the page.

Production `https://beancount.io`, 2026-09-08, Chrome 152, English,
System/light; authenticated reader of public synthetic `open_ledger/crypto-example`.
Desktop 1440×1000 and fresh 390×844. Local HEAD `a315c273`, fetched main
`cc3f4c2f`; implicated code is unchanged there. Deployed SHA unverified.

1. Load `/ledger/open_ledger/crypto-example/journal?time=2025` and focus Export.
2. Press Enter. The correctly named **Export Journal** dialog opens.
3. Press Escape and wait for the dialog to disappear and its close animation
   and deferred focus handling to settle. Focus is now on `BODY`, not Export.
4. Press Enter again. The dialog does not reopen. Manually refocusing Export
   allows it to open again.
5. Repeat by focusing Cancel inside the dialog and pressing Enter, then by
   using its Close button. Both closures lose focus in the same way.

Complete fresh desktop/narrow repeats agree, measured 350ms after the dialog
becomes hidden. These dismissal journeys generate no plaintext-export request
or page error. A further unfiltered Escape repeat also records no console error.
The toolbar Export button has no dialog relationship/expanded attributes.

Working control: Overview's **Customize** panel returns focus to Customize
after Escape at both widths, and immediate Enter reopens it. No customization
values were changed. It uses the same Radix dialog package through Sheet and
registers its button with SheetTrigger.

Root cause: `dashboard/src/features/journal/components/export-journal-button.tsx:96–112`
renders a plain Button outside the controlled Dialog and manually sets its
open state. It never registers a DialogTrigger or supplies an explicit focus
return target. The shared wrapper in `common/components/ui/dialog.tsx:10–18`
and 63–81 delegates those behaviors to Radix.

Verified published artifacts for the lockfile's Radix Dialog **1.1.15** and
Focus Scope **1.1.7**, including registry integrity. Dialog starts with a null
triggerRef, attaches it in DialogTrigger, then its modal close handler prevents
Focus Scope's default restoration and focuses that triggerRef. Here it remains
null. Focus Scope dispatches this close event asynchronously; the measurements
above wait beyond it. Radix's documented Escape behavior also returns focus to
the registered trigger. See [Dialog keyboard interactions](https://www.radix-ui.com/primitives/docs/components/dialog#keyboard-interactions).

Fix the export caller: put its existing button inside the same Dialog root
using **DialogTrigger asChild**, preserving the controlled open state needed
after asynchronous export. Preserve its accessible Export name, icon layout,
busy state, cancel behavior, request scope and feedback. The registered trigger
should restore focus after Escape, Cancel, Close and successful completion;
do not add a timeout or global focus override to the shared primitive.

The only production ExportJournalButton caller is
`features/journal/pages/journal-page.tsx:207`, exposed by the main Journal route.
Other manually controlled dialogs require their own evidence; this note does
not establish a shared-wrapper defect or widen the entry-context work in m11.

Download controls succeed: time=2025 returns HTTP 200 with one transaction and
seven balance assertions. Time=2020 displays **Results 0–0 / 0** and exports
only setup/options, also HTTP 200. The empty-period download closes the dialog
and again leaves focus on BODY. No empty-result export failure was retained.
Both files were saved locally; no production ledger data changed.

Acceptance: the exact keyboard closures retain focus on Export at desktop and
narrow widths, immediate Enter reopens it, and the dialog exposes its trigger
relationship. Successful populated and empty-period downloads retain their
current content and feedback while restoring focus. Add an actual component
interaction check with the real dialog primitive, including asynchronous
completion; preserve busy/error behavior and run dashboard gates when fixing.

Dedupe: searched all open/completed board records for export/modal focus and
missing triggers, and scanned open milestone summaries. 023 fixes misleading
export scope copy; this independent trigger wiring does not change scope.
Completed w5/m2 delete-ledger focus work targets a separate dialog with an
explicit return target. Targeted history traces this caller to `af5339de`,
with no newer repair on fetched main.

Pending-request dismissal, network failure, expiry, screen readers, other
browsers/locales and a patched implementation remain unverified. An exploratory
locator assumed **Close dialog**; the actual accessible name is **Close**, and
the corrected complete repeats above pass that locator. All dialogs are closed
and global filters cleared.

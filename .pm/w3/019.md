# System appearance does not follow a running browser's color-scheme changes

**Severity:** minor — System appearance stays in the previous mode until reload.
**Estimate:** 35–50m, reactive theme resolution and focused lifecycle coverage.
**Pillar:** A2 — the dashboard follows a newcomer's chosen system appearance.

Reproduced 2026-09-08 on production, Chrome 152, English, authenticated reader
of synthetic `open_ledger/example`, source `a315c273`; deployed SHA unverified.
Desktop 1440×1000 and fresh narrow 390×844 repeats. Browser color-scheme
emulation changed the real `prefers-color-scheme` media query; the OS itself
and application theme state were not modified by the test harness.

1. Open `/ledger/open_ledger/example/income-statement?time=2017-09` and select
   avatar → Theme → System on desktop with a light browser color scheme.
2. Change the browser color scheme to dark while the page remains open.
   `matchMedia('(prefers-color-scheme: dark)').matches` becomes true, but
   `<html>` remains `light` and the white background stays visible after 700ms.
3. Reload: the same stored `system` preference now correctly renders dark.
4. Change back to light without reloading. The media query becomes false,
   but the HTML class remains `dark`.
5. Fresh narrow reload under light, followed by dark media, repeats the stale
   light page after 1300ms. Explicit Light/Dark selection works immediately.

Expected: while System is selected, the rendered theme updates when the
browser's color-scheme preference changes, without navigation/reload. Keep the
stored preference as `system`. Explicit Light or Dark must remain fixed.

Root cause in **dashboard**: `common/providers/theme-provider/utils.ts:4–10`
reads `matchMedia(...).matches` only on demand.
`common/providers/theme-provider/index.tsx:90–110` resolves it in an effect
depending only on `theme` and hydration; neither changes on a media-query
event. `hooks.ts:15–21` likewise reads a nonreactive snapshot for
`useIsDarkTheme`. No media-query change subscription exists. The one-time
document theme script resolves the preference on reload, explaining that
working recovery control.

Fix: subscribe to color-scheme changes and expose one reactive resolved
appearance through the existing provider/hooks. Apply it to the root class
and dependent consumers while the stored preference remains System. Preserve
explicit overrides, URL/native appearance overrides, SSR/hydration first paint,
and cookie/storage semantics; dispose the listener on unmount. Do not replace
the user's System preference with whichever mode was most recently resolved.

Blast radius: the provider wraps dashboard routes; consumers include the two
appearance selectors, Monaco editors/dialogs, Overview Sankey/distribution,
toast styling and native bridge initialization. The live reproducer covers
the report's entire page surface. Other consumers require focused regression
checks; their individual stale states were not independently retained.
This is separate from `w3/018`: that finding concerns chart text defaults even
when the root HTML class has already changed correctly.

Acceptance: a real media-query change event while System is selected updates
the root class and a hook consumer in both directions without reload; explicit
modes ignore those events. Returning to System immediately resolves the current
media value. Unmount removes listeners, hydration remains stable, and the
preference stays `system`. No API/schema or financial-data change is required.

Dedupe: searched all open/completed records for System appearance, OS theme,
matchMedia and prefers-color-scheme; no overlap. `w2/done/m22` checks explicit
chart-theme changes, a different layer. Targeted history traces the one-time
resolution to `af5339de`; no earlier working live subscription or later fix
was found. This is not attributed to the chart performance refactor.

Unverified: actual host OS scheduling/toggle, other browsers, native embedded
views, expired sessions and network failure. The report's authenticated
financial read succeeds in the adjacent appearance pass; no data response
or DOM class was mocked. No product fixes, ledger writes or shipping included.

Verified evidence under `dashboard/tmp/qa-20260907-w3-loop/`:
`system-theme-evidence.json`, `system-theme-stale-1440.png`, and
`system-theme-stale-390.png`. The run restored the System preference and
initial light appearance; browser media emulation cleanup is tracked in the
local running report.

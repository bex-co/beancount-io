## Objective

Give both journals real table semantics so every value is announced with its column. Today the accessibility tree has no `table`, `rowgroup`, `row`, `cell` or `columnheader` anywhere in the list: the headers are plain generics and each entry is one flat button whose name concatenates every column (`"2017-08-27 * Buy shares of GLD Toggle postings 2433.36 USD 4559.80 USD"`). Also give the flag column an accessible name instead of the bare letter `F`.

## Context

- `dashboard/src/features/journal/components/journal-table.tsx` — `JournalTableHeader` at `:82-121` and the row body at `:225-296` are plain `div`/`span` markup.
- Completed [m25](../../done/m25/README.md) is the precedent: it gave Accounts and Holdings real table structure **while keeping row actions usable by keyboard**. Reuse that approach rather than inventing another.
- Completed [m28](../../done/m28/README.md) solved the same "values disconnected from columns" problem for the BQL result table; check whether its layout technique applies.
- The whole row is currently a click target that opens the entry dialog, and it contains a nested postings-toggle button. Preserve both interactions — a table conversion must not nest interactive controls illegally or lose the row click.
- The narrow layout hides several columns (`sm:hidden` / `sm:block`); the exposed structure must stay honest at 390 rather than announcing columns that are not rendered.
- The flag header `"F"` is a hardcoded literal at `:92-95`, unlike every neighbouring header which uses `t(...)`; a new label needs keys in all 15 locale files.

## Steps

1. Convert the header and rows to a table structure with column headers and per-row cells, following m25's approach.
2. Keep the row click and the nested postings disclosure both operable by keyboard.
3. Give the flag column an accessible name; add the key to all 15 locales.
4. Verify the exposed structure matches the rendered columns at 1440 and 390, on `/journal` and on an account page.

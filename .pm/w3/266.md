# `bea add` / append fails on ledgers that lack a final newline (while `check` stays green)

**Severity:** minor. **Estimate:** 15–25 minutes. **Owner:** cli. **A1:** files
saved without a trailing newline (common from some editors and `printf` without
`\n`) pass `bea check` but every append refuses with a cryptic syntax error on
the last existing line, so agents cannot continue the ledger without a manual
`echo >>` or `bea format -i` first.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `1e3a4a5f`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
printf 'option "operating_currency" "USD"\n2020-01-01 open Assets:Cash USD\n2020-01-01 open Expenses:Food USD' \
  > main.bean
# file does NOT end with \n

bea --file main.bean check
# exit 0

bea --file main.bean add transaction --date 2020-02-01 --narration x \
  --posting 'Assets:Cash -1 USD' --posting 'Expenses:Food'
# exit 1 — nothing written
# …/main.bean:3: syntax error, unexpected ASTERISK, expecting end of file or EOL

bea --file main.bean add note --date 2020-02-01 --account Assets:Cash --comment hi
# exit 1 — unexpected NOTE … same class

printf 'date,amount,description\n2020-08-01,-2.00,x\n' > bank.csv
bea --file main.bean import bank.csv --csv auto --account Assets:Cash \
  --apply --duplicates include
# exit 1 — unexpected FLAG … same missing-newline glue

# --into an included file that lacks a final newline fails the same way
```

Working control — same bytes plus a final `\n` appends successfully. `bea format
-i` on the no-newline file rewrites a trailing newline and then add works.

## Expected

Append inserts a separating newline when the destination does not already end
with one, so add/import succeed and `check` remains green. Optionally normalize
on write so the file gains a final newline.

## Actual

`bea_engine/ledger/write.py` `appended_content` builds a draft with a leading
`\n` before new blocks, then returns `text + "\n".join(tail) + "\n"`. When
`text` has no trailing newline, the last original character is concatenated
onto the first character of the new directive (`USD2020-02-01` / `USD2020-02-01
note…`), which the loader reports as a syntax error on the old last line.

## Fix

If `text` is nonempty and does not end with `\n` (honor CRLF if that is the
file’s convention — see w3/258), insert the missing terminator before joining
the aligned tail. Regression: the printf fixture above accepts add transaction
and add note; files that already end in `\n` / `\r\n` unchanged in hash aside
from the new directive.

## Dedupe

Not w3/258 (CRLF files get LF-only appends). Not w3/264 (phantom line numbers
on rejects). No open note covers missing final newline blocking append while
check stays clean.

# Budget account and currency selectors discard their form labels

Severity: **minor**. Owner: **dashboard**. Estimate: **40–60 minutes**.
A2: users can identify budget fields by their real labels and focus them by
activating those labels; account guidance remains associated with its input.

Production `https://beancount.io`, 2026-09-08, Chrome 152, English, light.
Fresh QA contexts at 1440×1000 and 390×844, public `open_ledger/minimax`.
GetLedger returns HTTP 200, no errors, pull/push true and admin false. No form
values were changed or submitted. Local HEAD `a315c273`, fetched main
`853a4942`; implicated source unchanged, deployed SHA unverified.

1. Open `/ledger/open_ledger/minimax/budget`, then **Add Budget**. Wait for
   the Account and Currency queries to finish and the actual inputs to render.
2. Focus Cancel, then click the **Account** label. Focus moves to the dialog
   container instead of the account input. Repeat for **Currency**: same result.
3. Inspect the accessibility tree: the account selector is named
   **Expenses:Groceries**, from its placeholder. The currency selector is named
   **USD**, from its placeholder, although its current value is **MUSD**.
4. Repeat from a fresh load at each width. Date and Amount labels correctly
   focus their inputs; Interval also has a real label association.

Both failing labels have a nonempty htmlFor but zero matching DOM IDs and
`label.control === null`. Both native combobox inputs have an empty id and no
aria-describedby, aria-invalid or aria-labelledby. The visible account help
paragraph has its expected description ID, but nothing connects it to the input.
These controls remain keyboard reachable and have placeholder-derived names;
this is not a claim that they are completely unnamed or inaccessible by Tab.

Root cause:

- `common/components/ui/form.tsx:96–124` correctly gives FormLabel the field
  ID and uses Radix Slot to pass id, aria-describedby and aria-invalid to its child.
- `common/components/ledger-comboboxes/account-combobox.tsx:14–36,76` and
  `currency-combobox.tsx:14–34,69` destructure only their own props, discarding
  those attributes instead of forwarding them.
- `common/components/ui/combobox.tsx:25–48,201–215` also has no input identity/
  description passthrough. Forwarding only through the outer wrapper would
  still lose the attributes before the native Input.
- Budget callers at `features/ledger-data/budget/add-budget-dialog.tsx:212–233`
  and `289–303` already supply the real FormLabel/FormControl structure.

All source paths above are relative to `dashboard/src/`. The lockfile resolves
the direct Radix Slot dependency to 1.2.4. Its integrity-verified implementation
merges props and clones the immediate child (`dist/index.mjs:43–54,75–97`),
consistent with the [official Slot contract](https://www.radix-ui.com/primitives/docs/utilities/slot).
The library supplies these attributes; the application wrappers drop them.

Fix: expose a small typed native-input identity/ARIA contract on Combobox and
forward it through the ledger selectors to the actual Input. Do not place the
field ID on a surrounding div or overwrite internal refs, selection/blur
handlers, role, expanded state or autocomplete behavior. Keep the six wrappers'
passthrough contract consistent: Account, Currency, OperatingCurrency, Payees,
Narrations and SourceFile. No global FormControl rewrite or dependency upgrade
is needed. Existing labels and translations provide the intended names.

Working counterfactual: in isolated page contexts, assigning each input its
existing label's target ID and the account's existing description ID makes
label activation focus the correct native input. Snapshots then name them
Account and Currency. These runtime DOM changes were discarded; no source or
deployed fix is claimed. Both original and counterfactual loads have HTTP 200
documents and zero console errors/page exceptions.

Blast radius searched: Account/Currency selectors also occur in Journal Balance,
Transaction and Note, Import configuration, receipt review and bank review.
Transaction's Payees/Narrations also sit under FormControl. OperatingCurrency
is used by bank mapping and SourceFile by bank review. These callers are
source-traced, not additional live-proven failures. Bank mapping's plain labels
also omit matching caller-supplied IDs; forwarding alone does not establish
those associations, so that caller repair needs its own reproduction. The
sidebar's same-named AccountCombobox comes from `go-to-account.tsx` and is a
different component. Global ledger search uses the underlying Combobox directly.

Acceptance: the two Budget labels identify and focus their settled native
inputs at both widths, and Account's description is associated with that input.
Use real FormControl/wrapper rendering and behavior checks for label activation,
accessible name/description and invalid-state propagation. Preserve loading,
disabled, query-error, selection and clearing behavior; these adjacent states
and native screen readers remain unverified live. Coordinate with 052's
independent blur/keyboard selection repair, 064's amount step change and m23's
dialog focus return work. Ref-based invalid-field focus is outside this note.

Dedupe: searched open and completed board records for combobox labels, field
association, descriptions and aria-describedby. 057 is Signup's separate
missing RHF registration/ref; completed w5/m2 covers Gallery semantics and a
delete-dialog description. No existing item covers this prop-loss mechanism.
Targeted history shows `af5339de` and localization `aeec496b`; fetched main
contains no repair to these shared components. No new milestone is warranted

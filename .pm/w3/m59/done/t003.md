## Objective

Give the CLI's engine-side builder the same module behavior, and expose a repeatable `--module` (with `--property-name`) on `bea init` and `bea cloud ledger create`.

## Context

- `bea init --preset` reads `cli/src/bea_engine/setup_catalog.json` through `cli/src/cli/commands/init.py`; the engine builds the files (`cli/src/bea_engine/initiating.py`).
- `bea cloud ledger create` (`cli/src/cli/commands/cloud/ledger/app.py`) sends `setup` through the generated REST client; regenerate it after t002's OpenAPI change (`make spec-sync && make codegen`).
- CLI conventions: frontend never imports Beancount; generated files and `docs/REFERENCE.md` are regenerated, never hand-edited.

## Steps

1. Implement module account generation in the engine builder from the catalog.
2. Add repeatable `--module` and `--property-name` to both commands; refuse modules without `--preset personal@1` with a usage error and nothing written.
3. Regenerate the REST client and `docs/REFERENCE.md`.

## Files

- `cli/src/bea_engine/`
- `cli/src/cli/commands/init.py`
- `cli/src/cli/commands/cloud/ledger/`
- `cli/docs/REFERENCE.md`

## Acceptance criteria

- [ ] `bea init --preset personal@1 --module investments@1 --module rental-property@1` writes the A.9 accounts once, in either flag order.
- [ ] A module without `--preset personal@1` exits 2 and writes nothing; invocations without `--module` are unchanged.
- [ ] `make check-all` passes.

## Out of scope

- Interactive prompts for modules (explicit flags only in this milestone).

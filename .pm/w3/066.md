# New Transaction leaves status and posting actions unnamed

Severity: **minor**. Owner: **dashboard**. Estimate: **35–55 minutes**.
A2: users can identify transaction status and posting-row actions through their
accessible names instead of guessing from punctuation or decorative icons.

Production `https://beancount.io`, 2026-09-08, Chrome 152, English, light.
Fresh QA contexts at 1440×1000 and 390×844, public `open_ledger/minimax`.
Authenticated public-ledger permission control: pull/push true, admin false.
Local HEAD `a315c273`, fetched main `853a4942`; implicated source unchanged,
deployed SHA unverified. All contexts were closed; no entry was submitted.

1. Open `/ledger/open_ledger/minimax/journal?action=new-entry&directive=transaction`.
   Wait for the Transaction tabpanel and both Currency inputs to settle.
2. Inspect the status control beside Date: the accessibility tree exposes
   **combobox: "\*"**, with no accessible name. Open it by Space and focus/
   activate the **! Pending** option by Enter. It becomes **combobox: "!"**,
   still unnamed. The popup options themselves have meaningful names.
3. Focus the plus button in the second posting row. It is exposed simply as
   **button**, with no name. Enter adds a third empty row.
4. All three rows now have unnamed trash buttons. Focus the third and press
   Enter: the row count returns from three to two. The controls work, but their
   purpose and row context are absent from their accessible names.

Fresh repeats pass these exact interactions at both widths. The posting buttons
have no text, title, aria-label or aria-labelledby, and their SVGs are aria-hidden.
The status trigger has only its punctuation value, no label/title association.
Calendar **Select date**, currency **Clear**, and **Create Transaction Entry**
are named working controls in the same form. This finding does not claim that
the unnamed actions cannot receive keyboard focus or that status selection fails.

Root cause is confined to `dashboard/src/features/journal/components/new-directive-dialog/transaction-form.tsx`:
status SelectTrigger at372–379 lacks a label and supplies only the raw flag
symbol; remove/add Buttons at521–541 contain only Trash2/Plus icons.
`common/components/ui/select.tsx:25–45` and `ui/button.tsx:39–65` forward
attributes normally. FormControl cannot invent an accessible name when no
FormLabel or explicit label is supplied. This differs from065's lost input props.

Fix these three caller controls: give status the existing localized
`common.status` name and preserve a meaningful selected status using the
existing Cleared/Pending/blank translations; give the plus action a localized
**Add posting** name and trash actions **Remove posting {{number}}** or equivalent
row context. Add missing journal keys across all 15 locale modules. Preserve
the existing native controls, handlers, minimum-row rule and automatic blank-row
behavior. No global Button/Select rewrite or new dependency is needed.

The [WAI combobox pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)
distinguishes a widget's name from its selected value, and the
[button pattern](https://www.w3.org/WAI/ARIA/apg/patterns/button/) requires a name
that identifies the action. Tooltip-only mouse hints do not address these
observed empty accessibility names.

Blast radius: TransactionForm has one actual component caller,
`new-directive-dialog/index.tsx:86`, reached through Journal's toolbar/sidebar
entry actions and deep-link variants. Import's same-named TransactionFormData
type is unrelated. These status/row controls do not appear in the other Journal
directive panels. Other controls and native mobile are outside this repair.

Acceptance: accessibility-tree queries find Status, Add posting and each
uniquely identified Remove posting action; Pending selection still works and
keyboard activation still changes two rows to three and back. Preserve named
Calendar/Clear/Create controls and repeat at desktop/narrow widths. Use actual
form controls for focused interaction/name assertions; do not merely snapshot
the icon markup. Loading/error/disabled states, filled-row deletion, actual
write success, other locales and native screen readers remain unverified live.

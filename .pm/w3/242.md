# `bea query 'PRINT …' --format csv` silently prints Beancount directives, not CSV

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** cli. **A1:** an
agent that asks for CSV export of `PRINT` gets directive text that is not CSV,
with exit 0 — no warning that `--format csv` was ignored.

Found 2026-09-15 by continuous CLI QA against `main`, HEAD `63aa356b`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
bea --file main.bean query 'PRINT FROM has_account("Cash")' --format csv
echo exit=$?
# exit 0 — stdout is Beancount directive text (same as --format text/beancount),
# not comma-separated columns
```

Controls:

```sh
bea --file main.bean query 'SELECT account LIMIT 2' --format csv
# real CSV header/rows

bea --file main.bean query 'SELECT account LIMIT 1' --format beancount
# exit 2 — clear usage: beancount format needs entries / use PRINT
```

## Expected

Either:

1. Refuse `PRINT` (or any directive render) with `--format csv` via usage error,
   or
2. Emit a real CSV representation of the printed entries.

Do not exit 0 with non-CSV text when the user asked for csv.

## Actual

Shell `PRINT` always renders directives through the beancount/text printer;
`--format csv` does not change the output and is not validated for PRINT.

## Root cause

```text
bea_engine.query.text_answer → BQLShell.onecmd(PRINT…)
# format setting unused for Print dispatch; csv renderer never runs
```

## Fix

When the statement is `PRINT` (or returns entries) and `--format csv`, raise
`UsageError` naming `--format text`/`beancount`, or implement CSV. Regression:
the repro exits 2 (or emits parseable CSV); `SELECT … --format csv` and
`PRINT … --format beancount` stay green.

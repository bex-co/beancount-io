## Objective

Pin the real filter/count behavior across domain, adapters and dashboard state transitions.

## Context

- Service-call-only mocks do not prove API parity.
- Use balanced synthetic ledger fixtures with controlled external dependencies; no production mutations.

## Steps

1. Cover counterpart postings, multiple postings to the same account, child accounts, empty/default fields, fiscal boundaries and clamped opening/transfer entries.
2. Exercise GraphQL execution, HTTP REST and an MCP client against the shared implementation for results, malformed filters and relevant relationship/scope/pin/audience refusals.
3. Exercise actual dashboard filter changes, clearing, zero matches, failures, rapid changes and ledger switches; assert displayed rows/counts, not only query invocation.
4. Run owning-package normal gates; refresh generated contracts and resolve failures caused by this milestone.

## Files

- Ledger report service/domain tests
- Gateway analysis behavioral contract tests
- Dashboard Statistics component tests
- Owning-package check commands in CLAUDE.md

## Acceptance criteria

- [ ] Tests fail with the original constant-query UI and with an adapter that drops a filter.
- [ ] All eligible adapter gaps remain zero, frozen API baseline intact and generated schemas current.
- [ ] Required dashboard, ledger, IDL and gateway checks pass; any unverified live behavior is stated explicitly.

## Out of scope

Snapshot-only coverage, broad performance work and sending data to paid providers.

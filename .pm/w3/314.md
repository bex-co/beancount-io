# `bea --json --version` prints plain text instead of a JSON envelope (or a refuse)

**Severity:** minor. **Estimate:** 15–25 minutes. **Owner:** cli. **A1:** an
agent that runs every invocation under `--json` and parses stdout as the
envelope gets raw `bea 0.2.0` from `--version` — `json.loads` fails — while
USAGE’s JSON exceptions list `ask` / `doctor` / `example` / `treeify` / cloud
login but not `--version`.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `6c53f166`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache.

## Repro

```sh
bea --json --version
# exit 0
# stdout: bea 0.2.0
# stderr: empty
# not a JSON object

bea --version --json
# same plain-text stdout
```

Working control — other globals under `--json` already use the error envelope:

```sh
bea --json -V
# exit 2; stderr: {"error":{"category":"usage","message":"No such option: -V",…}}
```

## Expected

Either emit a small envelope (e.g. `{"bea":"0.2.0","data":{"version":"0.2.0"}}`)
or reject like doctor (`refuse_json` / usage error). Document the choice in
USAGE’s JSON exceptions list.

## Actual

`cli/main.py` `_version_callback` is an eager Typer callback that
`typer.echo(f"bea {version}")` and exits before `json_output` shapes the run.

## Fix

If `json_output` is set, emit the envelope (or refuse) instead of plain text;
keep human `--version` unchanged. Regression: `bea --json --version` is
parseable JSON or a documented refuse; `bea --version` still prints `bea X.Y.Z`.

## Dedupe

Not w3/312 / done/221 (command-level native forwards). Not w3/295 (engine
enable messaging). No open note covers global `--version` under `--json`.

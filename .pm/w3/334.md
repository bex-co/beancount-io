# `bea list transaction` repeatable `--search` AND-combines without documenting it

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** cli. **A1:** an
agent that appends `--search $term` per candidate (expecting union) gets exit
**0** and zero rows when each term alone matches a different transaction.

Found 2026-09-16 by continuous CLI QA ([c770 hunt](94ca2918-fe2d-4106-98ca-dcd9f0054048)),
HEAD `468b348d`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Evidence:
`cli/tmp/qa-20260915/c770/`.

## Repro

```sh
# Coffee and Salary each match one row alone
bea --file main.bean list transaction --search Coffee --search Salary
# exit 0 — No transactions found. (AND; no row has both substrings)
```

## Expected

Document AND in `--help` / USAGE, or OR-union repeatable `--search` (and keep
AND via another flag). Silent empty vs single-term hits must not surprise agents.

## Actual

`reader.py` `list_transactions` requires `all(term in payee or narration)`.
USAGE only says “repeatable”; help has no AND/OR note.

## Fix

Pick OR union or document AND; align help, USAGE, and a regression. Keep
`--search Netflix --search Sub` finding the combined payee+narration row under
AND if that policy stays.

## Dedupe

Not w3/286 (empty `--search ''`). Not w3/333 (empty `--tag`/`--link` poison).
No open note covers multi-`--search` AND on disjoint rows.

# `bea --json query -f csv` silently ignores `--format` (always forces JSON)

**Severity:** minor. **Estimate:** 10–15 minutes. **Owner:** cli. **A1:** an
agent that asks for CSV under global `--json` (e.g. `--json query … -f csv -o
out.csv`) gets a JSON envelope in the file with no warning that `-f` was
dropped — easy to think the export failed or that CSV padding bugs apply.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `eecf0936`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
bea --json --file main.bean query 'SELECT account LIMIT 2' -f csv -o out.txt
# exit 0 — out.txt is the JSON envelope, not CSV
# no stderr warning about --format

bea --json --file main.bean query 'SELECT account LIMIT 2' -f csv
# stdout JSON envelope; -f unused
```

Working control without `--json`:

```sh
bea --file main.bean query 'SELECT account LIMIT 2' -f csv
# CSV text on stdout
```

## Expected

Either refuse the combination (exit 2: `--json` already selects JSON; drop `-f`
or drop `--json`) or document and warn that `--format` is ignored under
`--json`. Prefer a hard usage error so agents cannot mis-read the file.

## Actual

`query.py` always passes `--format json` to the engine when
`ctx.json_output` is set, discarding the user’s `-f` / `--format` value with
no message.

## Root cause

`cli/src/cli/commands/query.py` (~92):

```python
args += ["--format", "json" if ctx.json_output else output_format]
```

No conflict check when `ctx.json_output and output_format != "text"` (default)
or when `output_format` is explicitly `csv` / `beancount`.

## Fix

If `--json` is set and `--format` is not the default `text`, raise UsageError
naming the conflict (or accept only `text` as “unused default”). Regression:
`--json … -f csv` exits 2; `--json` alone and human `-f csv` unchanged.

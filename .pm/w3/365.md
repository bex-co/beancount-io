# `bea balance` / `report` human tables force `.00` when `doctor display-context` infers zero fractional digits

**Severity:** minor. **Estimate:** 15–25 minutes. **Owner:** cli. **A1:** an agent
that sees `fractional_max=0` from `doctor display-context` then reads
`bea balance` gets misleading `100.00 USD` / `12.00 HOOL` while
`list transaction` shows `100 USD` and JSON keeps `"100"`.

Found 2026-09-16 by continuous CLI QA ([c1080 hunt](97db6c1b-a535-4536-89ce-deb436a15d42)),
HEAD `f32966fe`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Evidence:
`cli/tmp/qa-20260915/c1080/`.

## Repro

```sh
bea doctor display-context integer-only.bean
# USD … fractional_max=0

bea --file integer-only.bean balance
# Cash → 100.00 USD

bea --file integer-only.bean list transaction
# Assets:Cash: 100 USD

# also: option "display_precision" "USD:0" still prints 100.00 USD
# also: HOOL units balance → 12.00 HOOL when fractional_max=0
```

## Expected

Human balance/report honor inferred/explicit precision (zero → `100 USD`).

## Actual

`_quantize` uses precision `0`, but `_amounts` formats with `max(2, -exponent)`,
forcing two fractional digits.

## Fix

Honor precision map fractional count (allow `0`); keep `max(2, …)` only when
precision is unknown (w3/304). Regression: integer-only / `USD:0` print
`100 USD`; cent ledgers still show `101.50 USD`.

## Dedupe

Related to w3/304 (missing conversion currency → unbounded decimals) — distinct
symptom: precision **is** present and zero. Not w3/313. No open note on forced
`.00` when `fractional_max=0`.

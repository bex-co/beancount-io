# Human reports print empty sections as `0.00 <conversion>` while unconverted rows stay in source units

**Severity:** minor. **Estimate:** 15–25 minutes. **Owner:** cli. **A1:** under
`-x GBP --allow-errors` (no GBP prices), Assets still read `2,950.00 USD` but
empty Liabilities print `0.00 GBP` — agents can think liabilities were
successfully valued in GBP while the rest of the statement is still in USD.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `95537494`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only (`pristine` USD ledger, EUR price only).

## Repro

```sh
bea --file main.bean report trial-balance -x GBP --allow-errors
# Partial valuation: some prices are missing…
#   Assets          2,950.00 USD
#   Liabilities     0.00 GBP      ← empty tree, labeled GBP
#   Equity         -1,000.00 USD
#   Income         -2,000.00 USD
#   Expenses           50.00 USD

bea --json --file main.bean report trial-balance -x GBP --allow-errors
# data.liabilities.balance_children == {}  (no GBP amount)
```

Same pattern on `balance-sheet` / `balance` when a section has no postings.

## Expected

Empty sections under a failed/partial conversion should match the statement’s
unit story: `—`, `0.00 USD` (operating currency), or omit a fake conversion
label — not `0.00 GBP` beside USD rows that never converted.

## Actual

`cli/commands/report.py` `_amounts` falls back to `f"0.00 {conversion}"` whenever
the balance map is empty and `-x` is a currency, with no check that conversion
actually produced amounts in that currency.

## Fix

When `balance` is empty under conversion, render `—` / operating-currency zero /
`0.00` without the target code unless the conversion succeeded for the report.
Regression: the GBP `--allow-errors` trial balance does not show `0.00 GBP` on
empty Liabilities while Assets remain USD.

## Dedupe

Not w3/304 (repeating decimals when EUR conversion *succeeds* without display
precision). Not missing-price messaging itself (documented). No open note covers
empty-section `0.00 <target>` under partial conversion.

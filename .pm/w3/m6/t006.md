## Objective

Cover the property that makes porting-by-family worth doing: the two surfaces cannot drift, because they resolve through one service.

## Context

- The interesting test is not "the REST route returns data" — it is that the REST route and the resource template return *the same* data for the same ledger. That is the guarantee ADR 0006 D1 asserts and the one a two-surface port could quietly break.
- Revocation: both a REST read and a resource read must be refused on the call after access is removed. `mcp-revocation.test.ts` is the model.

## Steps

1. Assert REST and MCP agree for the same ledger, per verb.
2. Assert both are refused after revocation.
3. Assert the tool list is unchanged.

## Files

- `src/features/ledger/api/rest/v1/__tests__/`, `src/features/ai-agent/api/__tests__/`

## Acceptance criteria

- [ ] A per-verb equivalence test covers all eleven.
- [ ] Each new test fails against the code before its change.

## Out of scope

- Load or pagination behaviour on very large ledgers.

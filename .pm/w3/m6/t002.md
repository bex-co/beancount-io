## Objective

Expose the same eleven reads as MCP resource templates, over the same service calls t001 uses. Resources rather than tools, so the tool list does not grow (ADR 0008 D2).

## Context

- Needs m5/t004's resource layer: the `resources` capability, template registration, and the per-call `authorizeLedger` path.
- The eleven: getLedgerCommodities, getLedgerCurrencies, getLedgerTags, getLedgerLinks, getLedgerPayees, getLedgerNarrations, getLedgerYears, getLedgerEvents, getLedgerErrors, getLedgerAttributes, ledgerMeta.
- URI shape follows m5/t004's scheme decision, e.g. `…/{owner}/{name}/payees`.
- **The same service call as t001.** If the REST route and the resource template reach the ledger by different paths, they will drift, and the drift will be invisible because each has its own tests. One service, two adapters.
- These are enumerations, so several return unbounded lists. Decide per template whether the payload needs a cap, and say so rather than discovering it on a large ledger.

## Steps

1. Register the eleven templates against the existing services.
2. Authorize each read per call; refuse a revoked grant.
3. Drive `resources/templates/list` and `resources/read` with a real client over `InMemoryTransport`.

## Files

- `src/features/ai-agent/api/` (the resources fragment), `src/server/api/op-class.ts`

## Acceptance criteria

- [ ] All eleven appear in `resources/templates/list`; each `resources/read` returns real data.
- [ ] Each resolves through the same service function as its REST twin.
- [ ] `tools/list` is unchanged — still seven tools.
- [ ] A read after revocation is refused.

## Out of scope

- `subscribe` / `listChanged`; the remaining reads.

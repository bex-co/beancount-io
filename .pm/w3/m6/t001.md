## Objective

Put the eleven ledger-vocabulary reads on the v1 REST surface. No new services and no new primitive — `v1Route` already mounts, validates, and documents an endpoint from one declaration, and 24 routes prove it.

## Context

- The eleven: getLedgerCommodities, getLedgerCurrencies, getLedgerTags, getLedgerLinks, getLedgerPayees, getLedgerNarrations, getLedgerYears, getLedgerEvents, getLedgerErrors, getLedgerAttributes, ledgerMeta.
- `src/features/ledger/api/rest/v1/` — add each as a `v1Route({...})` and list it in `v1/index.ts`.
- Paths address a ledger as `{owner}/{name}`, two segments, never one `{ledgerId}` — a single segment needs `%2F` to survive Cloudflare and Caddy (ADR 0006 D7).
- Each op is already classified `read` in `op-class.ts`; adding the REST identifier to the existing row is the change, not a new row.
- `yarn generate-v1-openapi` regenerates `docs/openapi/v1.json`; `openapi-completeness.test.ts` fails if the snapshot and the live document disagree, so the contract change shows up as a reviewable diff.

## Steps

1. Declare the eleven routes; list them in `v1/index.ts`.
2. Fill each row's `rest` identifier in `VERB_TABLE` and drop its `deferred:` `restExempt`.
3. `yarn generate-v1-openapi`; review the snapshot diff.

## Files

- `src/features/ledger/api/rest/v1/`, `src/server/api/op-class.ts`, `docs/openapi/v1.json`

## Objective

Make account/filter/time follow the current router location on initial load,
filter edits and browser history, without a second persistent state snapshot.

## Steps

1. Define shared ledger search validation at the owning route scope. Preserve
   numeric-looking years and existing generated filter URLs through a tested
   compatibility policy; treat malformed encodings safely.
2. Bind the existing consumer API to reactive router search and route navigation
   rather than mount-only useState and raw history.replaceState.
3. Keep edits as replace navigation, preserve valid route-specific parameters,
   and implement explicit clear without middleware restoring removed values.
4. Keep SSR/hydration stable and avoid introducing dependencies or route import
   cycles into common infrastructure.

- `dashboard/src/common/providers/ledger-search-params-provider/`

## Acceptance criteria

- [ ] URL, provider consumers and controls reflect the same selection after Back
      and Forward; the reported six-versus-393 journal mismatch cannot persist.
- [ ] Filter edits and Clear all update the router once without resetting
      unrelated valid route state or overwriting history metadata.
- [ ] Existing direct URLs, quoted expressions and numeric year input remain usable.

## Out of scope

Backend filtering, new global state libraries, and expanding supported filters.

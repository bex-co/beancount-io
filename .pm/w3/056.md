# Statistics account destinations cannot be reached with the keyboard

Severity: **major for keyboard users**. Owner: **dashboard**.
Estimate: **25–40 minutes**. A2: a newcomer can open the account behind a
Statistics count or balance using the same visible destination as a mouse user.

Production `https://beancount.io`, 2026-09-08, Chrome 152, English,
System/light; authenticated reader of public synthetic `open_ledger/example`.
Fresh 1440×1000 and 390×844, no global filters. Local HEAD `a315c273`, fetched
main `cc3f4c2f`; implicated code unchanged there. Deployed SHA unverified.

1. Open `/ledger/open_ledger/example/statistics` and wait for its tables to
   finish loading. Postings per Account has **58 account rows**; Account Last
   Entries has **15 account rows**.
2. Focus the final header avatar button, **P**, and press Tab. Focus jumps
   directly to the **Overview** link under Related Pages, skipping every
   account in both tables. Fresh desktop/narrow repeats agree.
3. The blue account destinations are plain table cells. Each affected table
   has **zero links and zero focusable descendants**; the cells have no role,
   tabindex or keyboard handler.
4. Mouse-click `Assets:US:BofA:Checking` in Postings per Account, or
   `Liabilities:US:Chase:Slate` in Account Last Entries. Both correctly open
   their corresponding account routes at both widths. Each account journal
   read returns HTTP 200, the requested account name and twenty items.

Expected: every displayed account destination is a named link that Tab can
reach and Enter can open. The count/date/balance cells remain ordinary data.
The current pointer cursor and click handler do not expose account navigation
to keyboard or accessibility-tree users.

Root cause: `dashboard/src/features/ledger-data/statistics/postings-per-account.tsx:169–190`
and `account-last-entries.tsx:171–185` navigate from a TableCell `onClick`.
Neither renders an interactive account element. Their only production callers
are the Statistics page at `statistics/index.tsx:35` and `:38`; both rendering
branches should be repaired together. The shared TableCell is correctly a
generic cell and should not receive a global keyboard workaround.

Render the account text as a native TanStack Link inside each account cell,
using the existing owner/name/account route parameters. Keep its readable
account name, current visual layout and visible focus. Remove the cells'
imperative navigation rather than nesting duplicate interactive targets.
No API, count/balance calculation or permission change is needed.

Controls/evidence: actual QueryShell and GetLedgerAccountLastEntries responses
return HTTP 200 and match the 58/15 rendered rows. The fresh page/keyboard
repeats have no console or page errors. The reached Related Overview link is
a working native control: Enter opens the correct ledger Overview and returns
HTTP 200 at both widths. The initial pointer recorder assumed a nonexistent
Journal button on account detail; that locator failure was discarded and the
clean repeats instead verified the actual account-journal response and rendered
Transaction control.

Acceptance: Tab reaches Checking in the postings table and Slate in the last
entries table; Enter opens exactly their existing encoded account URLs.
Mouse navigation and the observed data remain unchanged at both widths.
Verify accessible link names and actual navigation, preserving loading, empty
and error branches. A focused behavioral regression should fail if these
destinations become click-only cells again; run dashboard gates when fixing.

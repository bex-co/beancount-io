# `bea report --account` regex filters return empty totals (substring prune disagrees with regex entry filter)

Severity: major. **Estimate:** ~1h. **Owner:** cli. A documented capability
returns silently-empty financial numbers with exit 0.

`report --account` promises "a parent account or a regular expression", and
the invalid-filter error even suggests `'Expenses:(Food|Rent)'`. Parent
accounts work; every true regex returns empty totals with
`account_filter_empty: false` — and `trial-balance` prints a bare header
with no "no match" note, since entries *did* match.

## Repro (synthetic, no login)

```sh
cd cli
cat > /tmp/r.bean <<'EOF'
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Expenses:Dining USD
2026-01-01 open Expenses:Groceries USD
2026-01-01 open Income:Salary USD
2026-01-10 txn "Employer" "Pay"
  Income:Salary -3000.00 USD
  Assets:Checking 3000.00 USD
2026-01-12 txn "Store" "Food"
  Expenses:Groceries 85.50 USD
  Assets:Checking -85.50 USD
EOF
uv run bea --json --file /tmp/r.bean report overview --account 'Expenses:(Dining|Groceries)'
# totals.expenses == {} — expected 127.50 USD; account_filter_empty == false
uv run bea --json --file /tmp/r.bean report overview --account '.*'
# ALL totals empty — a match-everything regex matches nothing
uv run bea --file /tmp/r.bean report trial-balance --account 'Expenses:.*'
# bare 3-line header, exit 0, no "no match" note
uv run bea --json --file /tmp/r.bean report overview --account Expenses
# expenses == {'USD': '127.50'} — parent form is the working control
```

HEAD `b94d9461`, bea 0.2.0, Darwin arm64, isolated config/cache.

## Root cause

Two filter stages disagree. Fava's `AccountFilter`
(`cli/src/fava/core/filters.py:438`) matches entries by
(`has_component` OR regex `search`), so `Expenses:.*` keeps the right
entries. Then `_prune_sections` → `_prune_tree`
(`cli/src/bea_engine/report.py:503-531`) prunes the statement trees by
**substring** (`term in fold_account(node.account)`) — "the way `bea
balance` does". `"expenses:.*"` is a substring of nothing, so every node
is pruned and totals come back empty. `account_filter_empty` is computed
from `filtered.entries` (non-empty), so the metadata and the missing
"no match" note both claim success.

Introduced by `1de86f11` (w3/322): pruning report trees like balance
correctly removed counterparty postings for parent filters, but `balance`
documents *substrings* while `report` documents *regex* — the shared
prune honors only the former.

## Fix direction

Give the report prune the same matcher the entry filter uses:
(`has_component` OR case-insensitive regex `search`) instead of
substring. Parent-account behavior must not change (a parent is both a
component-prefix and a matching regex), and w3/322's DoD (no
counterparty postings; totals agree with `balance` for parent filters)
must keep holding — keep its regression test green. Do NOT change
`balance`'s substring semantics (documented); if the prune stays shared,
it needs a per-caller matcher. Regression tests: the documented
`'Expenses:(Food|Rent)'` shape, a match-nothing regex (expect the "no
match" note + `account_filter_empty: true`, not a bare header), and
parent-filter parity with `balance`. All four `report` subcommands share
the prune (report.py:116,161,203,246).

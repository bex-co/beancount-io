# Gallery's Back logo cannot be reached with the keyboard

**Severity:** minor. **Owner:** dashboard. **Estimate:** 20–30 minutes.
**A2:** a person exploring ledgers can return through the same visible action
with keyboard or assistive technology.

Production `https://beancount.io`, 2026-09-08, Chrome 152, English,
System/light; authenticated QA session. Fresh 1440×1000 and 390×844 contexts.
Local HEAD `a315c273`, fetched main `5b70f569`; implicated source unchanged,
deployed SHA unverified. Only the public example was used as the prior page.

1. Visit `/ledger/open_ledger/example/journal?lang=en), then
`/ledger-gallery?lang=en`. Wait for the Gallery page to finish loading.
2. Start Tab navigation from the page. Focus goes directly to the ledger-search
   combobox, skipping the large logo that has a pointer cursor.
3. The header exposes an image named **Beancount Logo**, the heading and
   description. It has zero links, buttons or focusable elements. The image
   has neither a tabindex nor an interactive ancestor.
4. Click that same logo with a mouse. It returns to the seeded Journal route
   at both widths. Fresh repetitions reproduce the missing keyboard action
   and the passing pointer control.

Expected: the action is a named, focusable Back button with a visible focus
indicator; Enter and Space perform one history-back operation. Actual: only
pointer activation is wired, and the accessible image name describes the brand
without exposing its Back action. Browser-level navigation remains an available
workaround, so this is not a claim that the user is trapped.

Root cause: `dashboard/src/features/ledger-list/pages/gallery-page/index.tsx:174`
renders a bare IMG; line177 attaches `window.history.back()` to its click.
No DOM, event or API adapter converts it into a keyboard control.
`routes/ledger-gallery.tsx:6` is the sole Gallery component route.
The source `routes/gallery.tsx` contains an alias redirect, but live direct
`/gallery` currently returns HTTP404; that separate deployment observation
has an unverified routing cause and is outside this fix.

Use a native `button type="button"` around the logo, move the existing history
action to it, and give it a translated Back name using the existing
`common.back` (or `common.goBack`) message. Treat the nested logo as decorative
when the button supplies its action name. Preserve appearance, visible focus
and the existing history destination; adding a role or tabindex to IMG alone
does not provide native keyboard activation.
The [W3C button pattern](https://www.w3.org/WAI/ARIA/apg/patterns/button/)
requires an action name and supports Enter/Space activation.

Cover the real Gallery component in
`features/ledger-list/pages/gallery-page/__tests__/gallery-page.test.tsx`:
Tab reaches Back before search, Enter and Space each invoke Back once,
the existing search combobox and Clear action retain their behavior.
Other direct browser-history callers are the root NotFound/Error pages,
which already render native buttons; Settings uses its router history from a
button. Do not change those callers or the shared button primitive.

All four retained documents return HTTP200, with no console errors, page
exceptions or attempted mutations. No search was sent, ledger written or
private result retained; isolated contexts closed.
Evidence in `dashboard/tmp/qa-20260907-w3-loop/`:
`gallery-back-logo-evidence.json`, `gallery-back-logo-1440.png` and
`gallery-back-logo-390.png`. Crops show the 80px/64px image; JSON retains
keyboard focus, header semantics and the completed pointer navigation.

# `bea … --into` with a literal include still says “add an include directive” when only the file is missing

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** cli. **A1:** after
`include "txns/may.bean"` is already in the root, `--into txns/may.bean` exits
**2** telling the agent to add an include — until an empty file is created.

Found 2026-09-16 by continuous CLI QA ([c860 hunt](0617025e-9c85-4afd-90b7-4ab9b9449a87)),
HEAD `96c2fec6`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Confirmed
`cli/tmp/qa-20260915/c861/`. Evidence: `c860/`.

## Repro

```sh
# main.bean has: include "txns/may.bean"  (file absent)
bea --file main.bean add transactions --from rows.json --into txns/may.bean
# exit 2 — … is not included … Create it and add an include directive …

: > txns/may.bean
bea --file main.bean add transactions --from rows.json --into txns/may.bean
# exit 0
```

## Expected

Say the destination **file** must be created (include already present), or
auto-create it. Do not claim the include is missing.

## Actual

`require_target` only sees expanded/existing include paths; message always
mentions adding an include.

## Fix

Detect literal include strings for the `--into` path; emit file-create guidance
(or create empty file). Regression: repro message (or success) without “add an
include”; w3/228 glob case aligned.

## Dedupe

Sibling of w3/228 (glob include messaging) — this is the **literal**
`include "path"` case with the same wrong recovery text. Not w3/332.

# Shared mobile commit links stack the destination twice

Severity: minor. Estimate: 50–60 minutes. Package: mobile. A2/A3: a reader following a shared ledger link should be able to return with one Back action.

Environment: 2026-09-09, main at `7f4b6190`, native development build `io.beancount.ios` version 1.20260906.47 rebuilt that day, iPhone 17e/iOS 26.5, Metro 8083, production API https://beancount.io. Authenticated reader of public synthetic `open_ledger/example`; push permission false.

Repro:

1. Terminate and launch the app normally; verify Home on `open_ledger/example`.
2. Open exactly once with `xcrun simctl openurl <iPhone-17e-UDID> 'beancount:///ledger/open_ledger/example/commit/5513babce495313fbfbb5b16131b8b27a6021801'`.
3. Wait for populated commit detail: title Update file main.bean, author open_ledger, +4/−4, main.bean diff.
4. Tap the visible Back control once. The identical commit screen remains.
5. Tap Back a second time. Home returns.

Repeated after fresh launch. Earlier independent run from Budget likewise needed two Back taps to return to Budget. Expected one link activation to add one destination and one Back to restore the preceding screen.

Evidence under `mobile/tmp/qa-2026-09-09/`: `link-repeat-start.jpg`, `commit-repeat-open.jpg`, `commit-repeat-back-once.jpg`, `commit-repeat-back-twice.jpg`; first run `commit-back-once.jpg` and `commit-back-twice.jpg`. API control `changed-commit.json` returns the same SHA and populated main.bean diff (+4/−4); correct content loading distinguishes this from a failed request. `link-logs.json` has an empty capture, so no claim of error-free logging. Screenshots are 946×2048; Back tap is native logical point (40,68).

Root cause: `app/+native-intent.tsx:31` calls `rewriteSystemPath`; `src/common/app-links/rewrite-system-path.ts:32` returns the destination path. Installed Expo Router `node_modules/expo-router/build/link/linking.js:117-123` forwards that rewritten URL to its navigation listener. Separately `use-app-link-handler.ts` subscribes to the same URL and calls `openAppLinkTarget`, whose non-tab branch at `open-app-link.ts:86` unconditionally pushes the destination after its readability probe. The handling ref deduplicates only calls inside that hook; it does not coordinate with Router's listener.

Fix: give link destination navigation one owner, or recognize that Router already navigated to this exact destination before issuing another push. Preserve the prior route, perform the ledger readability check and session guard, and apply the target ledger before displaying settled content. Avoid blindly replacing all destinations if that drops the genuine prior screen. Clear/consume pending links consistently so sign-in replay does not resurrect a processed link.

Blast radius: searched both callers of `openAppLinkTarget`: the app-link hook and `oauth-sign-in-finalizer.ts`. Resolver non-tab routes include account detail, commit detail, file editor, transaction detail, and Budget; only commit duplication was reproduced. Tab routes use replace and have a separate navigation path. Correct commit data and successful second Back are working controls. Add a focused navigation integration regression for a warm link: prior Home → one commit route → one Back restores Home. Cover cold launch and signed-out replay as adjacent states, with denied/network-failed readability probes leaving the original selection intact; these cases were not reproduced in this run.

Dedupe: searched all `.pm/**/*.md`, including done, for duplicate screen/navigation, Back twice, and app-link terms; no overlapping navigation defect found. `git log -S 'router.push(href as Href)'` traces introduction to `2a464bbc` (w4/m5); no later fix in the app-link history. Rechecked completed `w4/done/m5` DoD: prior closeout verified tab destinations, not non-tab Back behavior. Its known hosted AASA 404 is tracked separately in w4/001 and is not this bug.

Unverified: HTTPS OS association delivery, physical device, Android, cold-link/sign-in/denied recovery, other non-tab destinations. This custom-scheme test proves native destination navigation, not universal-link deployment. Report only; no product fix, production ledger write, or shipping.

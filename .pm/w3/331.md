# `bea format --currency-column` unbounded values bloat ledgers on `-i`

**Severity:** major. **Estimate:** 20–30 minutes. **Owner:** cli. **A1:** an
agent that passes a large `-c` / `--currency-column` (typo `99999`, copied
context) runs `bea format -i` and exits **0** while each posting line gains
~(column − account − amount − 4) spaces — a two-posting ledger grows from
**171 B to ~200 KiB**; `bea check` still passes.

Found 2026-09-16 by continuous CLI QA ([c720 hunt](f04ea07c-3930-465b-bfe4-a0238a77a716)),
HEAD `b85e2621`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache.
Evidence: `cli/tmp/qa-20260915/c720/`, `c750/` (confirm: 171 → 200121 bytes).

## Repro

```sh
# 171-byte minimal two-posting ledger
bea format -i --currency-column 99999 main.bean
# exit 0 — 1/1 file(s) formatted
wc -c main.bean
# ~200121
bea --file main.bean check
# exit 0
```

## Expected

Reject absurd column widths (hard upper bound and/or refuse growth beyond a
sane multiple of natural width), or cap padding. Never exit 0 after writing
100 KB+ space runs per line.

## Actual

Only negatives are rejected; vendored `align()` pads to the requested column
with no ceiling. `-i` / stdout / `--json` all accept it.

## Fix

Clamp or UsageError when `--currency-column` exceeds a documented max (e.g.
200) or when formatted size would inflate beyond N× input. Regression: `-c
99999` exits 2 (or caps); `-c 50` still widens usefully; file size stays sane.

# `bea --json import` drops engine `notes` (e.g. non-account category labels), so agents miss human-mode guidance

**Severity:** minor. **Estimate:** 15–25 minutes. **Owner:** cli. **A1:** an
agent previewing CSV import under `--json` never sees “category is not an
account name” (or other engine notes); human mode prints them and the engine
already returns them in `data.notes`.

Found 2026-09-15 by continuous CLI QA against `main`, HEAD `c2bedfb0`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
printf 'Date,Description,Amount,Category\n2024-03-10,X,-4.50,Groceries\n' > cat.csv

bea --no-input --file main.bean import cat.csv \
  --csv date=Date,amount=Amount,narration=Description,category=Category \
  --account Assets:Bank:Checking
# human stdout includes:
#   1 row(s) carry a category that is not an account name ('Groceries');
#   they post to Expenses:Uncategorized with flag '!'. …

bea --no-input --json --file main.bean import cat.csv \
  --csv date=Date,amount=Amount,narration=Description,category=Category \
  --account Assets:Bank:Checking
# data.notes is absent/null; stderr empty; row rule=unmatched only
```

`IMPORTING.md` promises the preview “says so once, naming the labels it saw.”

Extended 2026-09-16 continuous CLI QA (`c9716b25`): frontend-only notes are
also missing under `--json`, and the inferred date format never appears in the
envelope at all.

```sh
# ambiguous US/EU dates (no day > 12)
printf 'date,amount,description\n01/02/2024,-1.00,A\n03/04/2024,-2.00,B\n' > amb.csv

bea --file main.bean import amb.csv --csv auto --account Assets:Cash \
  --default-account Expenses:Food:Groceries
# human includes:
#   Read the column mapping … --date-format %m/%d/%Y …
#   Dates parse as %m/%d/%Y but the column has no day past the twelfth …

bea --json --file main.bean import amb.csv --csv auto --account Assets:Cash \
  --default-account Expenses:Food:Groceries
# data.notes absent; data.config is only the column map (no date-format);
# dates quietly become 2024-01-02 / 2024-03-04
```

## Expected

JSON envelope retains `data.notes` (list of strings) with the same advisories
human mode prints — engine notes **and** frontend notes (mapping discovery,
ambiguous date-format). Also expose the effective `date_format` (e.g.
`data.date_format` or inside `config`) so agents can reproduce the preview.

## Actual

```text
cli/src/cli/commands/import_.py:310-321
  output.note(mapping / date-format / ambiguity)   # humans only
cli/src/cli/commands/import_.py:355-361
  for note in preview.pop("notes", []) or []:
      output.note(str(note))
  if json_output:
      output.emit(preview, …)   # notes already removed; no date_format field
```

Under `--json`, `output.note` does not re-attach the strings, so the only copy
is discarded. Inferred `--date-format` is passed to the engine but never copied
into the emitted preview object.

## Fix

Do not `pop` notes before `output.emit` in JSON mode (print for humans, keep
in the payload for JSON). Append the same frontend `inferred_notes` /
mapping-discovery lines into `data.notes`. Include the effective
`date_format` in the JSON result. Regression: category-label CSV and ambiguous
`01/02/2024` CSV under `--json` both return non-empty `data.notes`; the latter
also names `%m/%d/%Y` (or equivalent); human mode still prints the same lines.

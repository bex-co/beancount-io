# `bea --json import` drops engine `notes` (e.g. non-account category labels), so agents miss human-mode guidance

**Severity:** minor. **Estimate:** 15–25 minutes. **Owner:** cli. **A1:** an
agent previewing CSV import under `--json` never sees “category is not an
account name” (or other engine notes); human mode prints them and the engine
already returns them in `data.notes`.

Found 2026-09-15 by continuous CLI QA against `main`, HEAD `c2bedfb0`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
printf 'Date,Description,Amount,Category\n2024-03-10,X,-4.50,Groceries\n' > cat.csv

bea --no-input --file main.bean import cat.csv \
  --csv date=Date,amount=Amount,narration=Description,category=Category \
  --account Assets:Bank:Checking
# human stdout includes:
#   1 row(s) carry a category that is not an account name ('Groceries');
#   they post to Expenses:Uncategorized with flag '!'. …

bea --no-input --json --file main.bean import cat.csv \
  --csv date=Date,amount=Amount,narration=Description,category=Category \
  --account Assets:Bank:Checking
# data.notes is absent/null; stderr empty; row rule=unmatched only
```

`IMPORTING.md` promises the preview “says so once, naming the labels it saw.”

## Expected

JSON envelope retains `data.notes` (list of strings) with the same advisories
human mode prints. Optionally also mirror them under a documented field if
`output.note` remains for humans.

## Actual

```text
cli/src/cli/commands/import_.py:355-361
  for note in preview.pop("notes", []) or []:
      output.note(str(note))
  if json_output:
      output.emit(preview, …)   # notes already removed
```

Under `--json`, `output.note` does not re-attach the strings, so the only copy
is discarded.

## Fix

Do not `pop` notes before `output.emit` in JSON mode (print for humans, keep
in the payload for JSON). Regression: the category-label CSV under `--json`
returns a non-empty `data.notes` containing `Groceries`; human mode still
prints the same line.

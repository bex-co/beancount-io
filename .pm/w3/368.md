# `bea import --rules` ignores category-column labels the preview tells agents to rules-categorize

**Severity:** minor. **Estimate:** 30–45 minutes. **Owner:** cli. **A1:** an
agent mapping `category=Category` and passing `--rules` whose patterns match
values like `STARBUCKS` in that column still sees every row `unmatched` with
flag `!`, while the preview advises “Categorize them with --rules”.

Found 2026-09-16 by continuous CLI QA ([c1110 hunt](50eee512-f534-4b3f-aeda-58a385540dc9)),
HEAD `2dfedc62`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Evidence:
`cli/tmp/qa-20260915/c1110/`.

## Repro

```sh
# CSV Category=STARBUCKS; rules match = "STARBUCKS" → Expenses:Food
bea --file main.bean import bank-category.csv \
  --csv date=Date,category=Category,narration=Description,amount=Amount \
  --account Assets:Checking --rules rules-category.toml
# advisory still says use --rules; RULE = unmatched
```

Control: same rules match when `STARBUCKS` is in narration instead.

## Expected

Rules also try the category cell when it is not a full account name (or the
advisory must not suggest `--rules` for that case).

## Actual

`_categorize()` only searches `payee`/`narration`; non-account category labels
become `rejected_categories` and the advisory always mentions `--rules`.

## Fix

Run rule regexes against category before rejecting, or narrow the advisory.
Regression: `STARBUCKS` in Category categorizes; payee/narration matching
unchanged.

Not w3/342, 238. No open note on `--rules` failing on category-column labels
while the preview recommends `--rules`.

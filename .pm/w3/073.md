# Narrow account search clips the start of account names

Severity: **minor**. Package: **dashboard**. Estimate: **25–40m**.
A2: users can read the full account names and search text when navigating on a
narrow screen.

Production `https://beancount.io`, 2026-09-08, Chrome 152, English/light,
QA reader of public `open_ledger/example` (pull true, push/admin false).
Local `a315c273`, fetched main `790791ac`, implicated sources unchanged;
deployed SHA unverified. These are successful production reads, not injected
failures or synthetic response data.

1. At 390×844, load `/ledger/open_ledger/example/journal?lang=en`. Open the
   sidebar, then **Search accounts...** beside Accounts.
2. Wait for the account options to load and the opening animation to settle.
   The popup flips to the left of its trigger and starts at **x = −37px**.
   Its search field and the text of the first option start at **x = −24px**.
   The visible first account reads **ets** instead of **Assets**; other account
   prefixes and the beginning of the search placeholder are also cut off.
3. Repeat from fresh contexts at 390px and 320px: identical negative bounds.
   The document width equals the viewport, so there is no horizontal page
   scrollbar to reveal the clipped text.
4. Working controls: desktop 1440×1000 places the popup at x247–535, and a
   600×844 sidebar places it at x279–567. Both show the full 288px popup.
   Escape returns focus at all four widths. Existing keyboard selection still
   opens the correct account and closes the narrow sidebar.

All lists contain 91 options from 60 real account names plus generated parents.
The matching GraphQL and REST reads return HTTP 200 without errors. All page
documents return 200, with no console/page errors. No mutations were attempted,
and every temporary context closed. This is horizontal placement, not missing
account data, an animation capture, or a zoom/device-scale mismatch.

Root: `dashboard/src/common/components/ledger-layout/go-to-account.tsx:56`
forces side="right" and align="start" for every viewport. The common Popover
at `common/components/ui/popover.tsx:18–34` supplies a 4px gap and 288px width.
On the narrow sidebar the trigger occupies x255–275, so neither side has space
for that fixed width. The observed Radix wrapper uses
`translate(-37px, 150px)` with data-side="left"; option text is genuinely
outside the viewport after layout has settled.

The pinned Radix Popper **1.2.8** source at `dist/index.mjs:104–112` applies
offset, shift with crossAxis false, and default flip. Pinned Floating UI core
**1.7.3** defaults fallbackAxisSideDirection to none at line564, so this
horizontal preference does not try top/bottom. Registry integrity was verified
for both artifacts. The documented [flip behavior](https://floating-ui.com/docs/flip#fallbackaxissidedirection)
explains why both horizontal placements can overflow on a narrow viewport;
this is a caller configuration problem, not an upstream regression.

A local control executed the pinned positioning algorithm with the measured
production rectangles. The current configuration reproduces x−37 at 390/320;
bottom-end with 8px collision padding gives **x8, y174**, fully within both
viewports. This is an algorithm control, not patched browser rendering.

Fix this caller to use a vertical placement on mobile, such as bottom/end,
with viewport padding and a width cap that fits the viewport. Reuse its existing
isMobile state. Keep the desktop side placement, native popup focus/keyboard
behavior and scrollable list. Use the
[Popover positioning props](https://www.radix-ui.com/primitives/docs/components/popover)
instead of hardcoded negative-position corrections or a global wrapper rewrite.

Acceptance: at 320px and 390px, the whole input, option text and popup stay
inside the viewport during empty/loaded/filtered states, and remain usable
after resize. Recheck desktop/600px, Escape focus return, account selection and
sidebar dismissal. Use actual browser bounds and visual text checks; an
accessibility snapshot alone sees the complete hidden prefix and misses this
failure. Run the dashboard gates when implementing.

shared by ledger routes. Other right-side common callers are the collapsed
desktop group flyout and a tooltip explicitly hidden on mobile; neither needs
this mobile placement change. The same-named form AccountCombobox is separate.

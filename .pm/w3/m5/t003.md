## Objective

Turn the parity numbers into something CI defends. The existing guard checks that an exemption *exists* and is not obviously boilerplate; it cannot check that the reason is true, which is how all three of t001's defects survived it.

## Context

- `src/server/api/__tests__/surface-parity.test.ts` — keeps its current checks and gains three.
- **Ratchet (ADR 0008 D6):** a checked-in per-surface ceiling on `deferred:` count. Adding a verb without its twins fails until the number is raised *in the same diff* — raising it is then a visible, arguable act. Set the ceilings from t002's actual counts, not from ADR 0008's prose, which was computed before t001 changed a row.
- **Escape-hatch class compatibility (D7.1):** an exemption citing a read-only alternative must not sit on a `write` or `admin` verb. Catches t001's `bulkEntries` shape.
- **Dependency citation (D7.2):** an exemption citing another ADR decision must cite it parseably, so changing that decision can enumerate what it re-opens. Catches t001's `listLedgers` shape.
- `structural:` entries are counted separately and are not expected to move.

## Steps

1. Add the three checks.
2. Set ceilings from t002's counts.
3. Confirm each new check fails against the pre-t001 table — a guard that never fails on the bug it was written for is not evidence.

## Acceptance criteria

- [ ] Adding a verb with no REST/MCP twin and no ceiling bump fails CI, naming the surface.
- [ ] Each of the three checks was verified to fail against the defect it targets.
- [ ] `structural:` count is reported separately and excluded from the ceiling.

## Out of scope

- Judging whether a reason is *wise*. These check internal consistency with the row.

## Objective

Make the Git smart-HTTP proxy accept a `bcio_` personal access token as the Basic Auth password. It should authorize the request the same way REST authorizes that key, then forward to Gitea with the key owner's generated Gitea credential, as the email + password path already does.

## Context

- `backend-cluster/backend-v2/src/features/gitea/api/git-proxy-handler.ts`:
  - `parseBasicAuth`.
  - `handleGitProxy`: the `@` branch chooses between app login and Gitea passthrough.
  - `isGitSmartHttpRequest`.
- `backend-cluster/backend-v2/src/features/apikeys/service/api-key-service.ts`:
  - `verify(plaintext)` returns the live key or `null`. Revoked, expired, and unknown keys all return `null`.
  - `stampLastUsed`.
- Scope and ledger restriction as REST applies them: `src/server/rest/scope-middleware.ts` and the `ledgerScope` columns in `features/apikeys/data/api-key-model/schema.ts`.
- Per-account password budget from w0/m7. A token is not a password and must not be charged against it.

## Steps

1. Detect a token by its `bcio_` prefix on the password, before the `@` branch. Accept any non-empty username.
2. Map the request to a scope:
   - `info/refs?service=git-upload-pack` and `git-upload-pack` need `ledger.read`.
   - `info/refs?service=git-receive-pack` and `git-receive-pack` need `ledger.write`.
   - `ledger.admin` implies both, as it does elsewhere.
3. Refuse a key restricted to another `owner/name`. Then load the key owner and forward with their Gitea credential.
4. Answer a rejected key with 401 and `WWW-Authenticate: Basic realm="Git"`. Answer a missing scope or a ledger outside the key's restriction as REST does, with a message git prints.

## Acceptance criteria

- [ ] A `ledger.read` key clones and fetches. It is refused on push.
- [ ] A `ledger.write` key pushes.
- [ ] A key restricted to `a/x` is refused on `a/y`.
- [ ] Revoked, expired, and unknown keys all get the same 401.
- [ ] A token request leaves the account's failed-password budget unchanged.
- [ ] Email + password and Gitea-username sign-in behave exactly as before.

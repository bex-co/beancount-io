## Objective

Add one setting that controls whether the Git HTTPS endpoint still accepts passwords. It lets the owner phase out password sign-in in stages, as GitHub did: announce, warn, then refuse.

## Context

- The setting lives in code: a typed field such as `gitHttp: { passwordAuth: "warn" }` on `AppConfig` in `backend-cluster/backend-v2/src/config/config.ts`, or a sibling module that it re-exports. It is **not** read from `process.env`. The owner's rule is that environment variables are for credentials, and a policy change should go through a commit and a deploy.
- Do not put it in `readFeatureFlags` (`src/features/healthz/utils/public-configuration.ts`). That map is boolean only and is served publicly, while this setting is server-side authentication policy.
- It covers both password paths in `git-proxy-handler.ts`: app email + password, and the Gitea-username passthrough.

## Steps

1. Add the typed setting with the union `"allow" | "warn" | "deny"` and set the shipped value to `warn`.
2. `warn`: accept the password. Log the path (`email` or `gitea`) without the credential, and count it in the existing metrics registry. Where the protocol carries a message, tell the user to switch to a token and name `/settings/api-keys`. For example, use a sideband `remote:` line in an upload-pack or receive-pack response, the way the push-rejection path in this handler already speaks the protocol. Do not break `info/refs`.
3. `deny`: refuse both password paths with a 401 and `WWW-Authenticate`. The body names the token page. Tokens (t001) are unaffected.
4. Tests take the setting as an injected value, not a mutated global.

## Files

- `backend-cluster/backend-v2/src/config/config.ts` (or a new `src/config/git-http.ts`)
- `backend-cluster/backend-v2/src/features/gitea/api/git-proxy-handler.ts` and its tests

## Acceptance criteria

- [ ] `grep -n "passwordAuth" src/config` shows a typed constant, and no `process.env` read for it exists.
- [ ] `allow` behaves exactly as today.
- [ ] Under `warn`, each password path still authenticates, emits one log line and one counter increment labeled by path, and a clone shows the switch-to-token hint.
- [ ] Under `deny`, both password paths get a 401 that names the token page, and a token still clones and pushes.

## Out of scope

- Switching the shipped value to `deny`, which is the owner's decision after `warn` counts are in.

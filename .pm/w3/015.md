# Smart Import splits a quoted multiline CSV field into invalid transactions

**Severity:** major — valid transaction data becomes two erroneous preview
rows, requiring manual repair or exclusion from import.
**Estimate:** 45–60m, browser CSV record parsing and focused regression.
**Pillar:** A2 — a newcomer can preview an ordinary bank CSV without losing a
transaction because its description contains a quoted line break.

Reproduced 2026-09-08 on production, Chrome 152, English/light, authenticated
QA reader, synthetic public `open_ledger/example`. Source `a315c273`, fetched
main `cc3f4c2f` has no importer changes; deployed SHA unverified. Fresh desktop
1440×1000 and narrow 390×844 repeats. All fixture parsing stayed in the browser.

1. Open `/ledger/open_ledger/example/import` and choose this two-record CSV:

   ```csv
   Date,Payee,Description,Amount
   2025-12-01,QA Parser Control,"Lunch, ""tea""",-1.25
   2025-12-02,QA Parser Multiline,"First line
   Second line",-2.50
   ```

2. The preview reports **1 Valid / 2 Errors** and renders three transaction rows.
3. Row 1 correctly retains `Lunch, "tea"` and `-1.25`.
4. Row 2 contains only `First line` and amount `0`. Row 3 puts
   `Second line,-2.50` in the date field and also has amount `0`.
5. The preview warns that errored rows need fixing or will be skipped. Continue
   to Configure is enabled because the unrelated first record is valid.
6. Fresh-load and repeat with a CRLF fixture, including CRLF inside the quoted
   description: the same three rows and error counts appear at narrow width.
7. Use Upload Different File to discard the preview. Configuration and actual
   submission were not invoked.

Expected: **2 Valid / 0 Errors**, preserving the second record's complete
description and `-2.50` amount. Quoted line breaks are part of the documented
CSV format. [RFC 4180, section 2](https://www.rfc-editor.org/rfc/rfc4180#section-2)
describes them alongside quoted commas and escaped quotes. An independent
Python `csv.reader(strict=True)` control reads both LF and CRLF fixtures as
two data records with four fields each.

Root cause: `dashboard/src/features/importer/hooks/use-csv-parser.ts:68–71`
splits the entire content on every newline and removes blank physical lines
before quote-aware parsing. `parseCSVLine` is then restarted for each physical
line at 86–87, losing the quoted field's state. The format-error return at
93–103 invents the two partial rows with zero amounts. Its comma/escaped-quote
state machine already handles the first control record correctly.

The producer is the browser `FileReader` at 161–172, not an API response.
`use-multi-stage-parser.ts:26–35` returns this client result when at least one
row is valid; the workflow then renders the preview. No GraphQL operations
occurred during either observed parse and there were no console errors. No
file was uploaded to storage, no AI parse ran, and no ledger entry was written.

Fix in **dashboard**: parse logical CSV records from the complete input while
carrying quote state across physical line endings. Treat a newline as a record
separator only outside quotes; retain embedded line breaks and escaped quotes
inside a field. Apply existing four-column/header/date/payee/amount validation
after record assembly and keep error row locations coherent. Do not replace
embedded line breaks with invented transactions or silently erase description
content. Reuse/extend the existing parser; adding a dependency requires the
repository's normal user approval.

Acceptance: LF and CRLF fixtures both preview exactly two valid records with
the expected text and signed amounts; ordinary quoted commas and doubled quotes
still work. Cover quoted empty lines, optional trailing record separators and
an unterminated quote with a meaningful error. Verify the real hook/FileReader
to preview path, and that a valid multiline CSV does not fall back to AI.

Dedupe: searched all open/completed board files for CSV quoting, multiline,
newline and parser splitting. No overlapping open item was found. Completed
`w4/done/m1` tests newlines in report CSV exports, a different direction and
implementation; CLI import work also uses a separate parser. Existing dashboard
CSV tests cover quoted commas/quotes but not quoted multiline records. Targeted
history traces this split to `af5339de`; fetched main has no repair.

Two hook callers were found: the active multi-stage parser and FileUpload's
fallback parser branch. The active upload → preview path was exercised; the
fallback callback branch, all-invalid-file AI fallback, actual import writes,
other browsers/locales and a patched implementation remain unverified. Both
test previews were cleared; only ignored local evidence files remain.

# `bea report * -i daily` series stops at last transaction while `as_of` follows notes

**Severity:** minor. **Estimate:** 30–60 minutes. **Owner:** cli. **A1:** JSON
`income-statement -i daily` shows `as_of: 2020-06-01` but `periods` end on the
last transaction date (2020-02-01), omitting zero-filled days USAGE says the
interval covers.

Found 2026-09-16 by continuous CLI QA ([c910 hunt](bc43522f-cf76-4304-b072-90ddfda5daa1)),
HEAD `eab23fea`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Confirmed
`cli/tmp/qa-20260915/c911/`. Evidence: `c910/`.

## Repro

```sh
# ledger: txns in Jan/Feb, note on 2020-06-01
bea --json --file main.bean report income-statement -i daily
# as_of / period.end_exclusive → June; periods last date → 2020-02-01
```

Same class on overview / balance-sheet series.

## Expected

Interval buckets span `period.start` through `as_of` (zero-filled), per USAGE.

## Actual

`_metadata()` uses all dated entries for `as_of`; Fava interval series stop at
last transaction.

## Fix

Pad/regenerate series through `as_of`. Regression: note-after-txn fixture
returns daily periods ending on the note date.

## Dedupe

Not w3/292 / 288. No open note covers interval series shorter than report
`as_of` when notes/events post-date the last transaction.

# `bea` rejects UTF-8 BOM ledger files (`Invalid token: '\ufeffoption'`) while import strips BOM CSV

**Severity:** minor. **Estimate:** 20–35 minutes. **Owner:** cli. **A1/A2:** an
agent or editor that saves `main.bean` as UTF-8 with BOM (common on Windows)
cannot `check`, `list`, `query`, or `add` — Beancount sees `\ufeffoption` —
even though `bea import` already strips BOM on CSV.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `ae4abedc`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
# pristine ledger with a leading UTF-8 BOM
printf '\xef\xbb\xbf' | cat - main.bean.pristine > bom-main.bean

bea --json --file bom-main.bean check
# exit 1
# details: …/bom-main.bean:1: Invalid token: '\ufeffoption'

bea --json --file bom-main.bean list open --limit 1
# exit 1 — Ledger has 1 error(s)… same \ufeffoption token
```

Working controls:

```sh
bea --json --file main.bean.pristine check
# valid: true

# CSV BOM already stripped (IMPORTING.md / w3/248 control):
printf '\xef\xbb\xbfDate,Description,Amount\n2024-03-01,Coffee,-4.50\n' > bom.csv
bea --json --file main.bean import bom.csv --csv auto --account Assets:Bank:Checking
# exit 0 preview (after Expenses:Uncategorized is open)
```

## Expected

Ledger load paths accept a leading UTF-8 BOM the same way CSV import does
(`utf-8-sig` / strip once), so BOM-only difference does not make a valid ledger
unloadable. Optionally warn once; do not require agents to re-save the file.

## Actual

Loader/parser reads the file as strict UTF-8 text; U+FEFF remains on the first
token. Bea surfaces Beancount’s `Invalid token: '\ufeffoption'`. CSV open uses
`encoding="utf-8-sig"`; ledger open does not.

## Fix

Strip a single leading UTF-8 BOM when reading ledger bytes (or open with
`utf-8-sig`) on the engine load path used by check/list/query/add/report, before
Beancount tokenizes. Keep non-BOM content byte-identical. Regression: BOM copy
of a valid ledger `check`s clean and `list open` returns rows; BOM-less control
unchanged; CSV BOM behavior unchanged.

## Dedupe

Not w3/248 (`add transactions --from` JSON BOM). Not w3/227 (Latin-1 CSV).
No open note covers BOM on `.bean` ledger files.

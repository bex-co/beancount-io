# `bea format --check` is green for files `bea check` rejects (garbage / truncated directives)

**Severity:** minor. **Estimate:** 25–40 minutes. **Owner:** cli. **A1/A2:** a
pre-commit or agent gate that only runs `bea format --check` on a tree will
pass over `.bean` files that are not valid Beancount at all — bean-format
echoes them unchanged, and bea treats “no rewrite” as “already formatted”.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `7c578ef8`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
printf 'not beancount\n' > garbage.bean
printf '2020-01-01 open\n' > half.bean   # truncated open

bea format --check garbage.bean
# exit 0 — All 1 file(s) are formatted.

bea --json format --check garbage.bean
# {"data":{"scanned":1,"formatted":[],"check":true,...}}

bea --file garbage.bean check
# exit 1 — Invalid token: 'not' / 'beancount'

bea format --check half.bean
# exit 0 — All 1 file(s) are formatted.

bea --file half.bean check
# exit 1 — syntax error, unexpected EOL, expecting ACCOUNT
```

Directory mix: one valid misaligned ledger + one garbage file under
`bea format -i dir/` reports `2/3 file(s) formatted` (or similar) with **exit 0**
and never names the garbage path as a failure; `--check` on that tree is green
after the good files are aligned.

Trailing-newline footgun (same root cause): garbage **without** a final `\n`
fails `format --check` (`would format`), then `format -i` “formats” it by
appending only `\n`, reports `1/1 file(s) formatted`, and subsequent
`format --check` is green — while `bea check` still rejects every token.
`printf 'not beancount at all' > g.bean` then `bea format -i g.bean` is enough.

Working control: a deliberately misaligned valid ledger fails `--check` and
lists `would format: …`.

## Expected

`format --check` / recursive `-i` should not report success for paths that are
not parseable ledgers. Prefer exit ≠ 0 (or a structured `failed` list under
`--json`) naming each path bean-format left untouched for lack of structure,
or document that `--check` is alignment-only and must be paired with
`bea check`. Today’s success copy (“All N file(s) are formatted”) implies
ledger health.

## Actual

`_would_change` compares bean-format stdout to disk. Upstream `bean-format`
exits 0 and reprints non-ledger / truncated text unchanged, so
`changed == []` and `_report` prints success. Comment in
`cli/commands/format.py` already wants formatter *failures* not to look like
“already formatted”, but passthrough success never raises.

## Fix

After a successful bean-format capture, if the file does not parse as
Beancount (reuse the same loader/`bea check` syntax path, or detect empty
parse with residual text), treat it as a format/check failure with the path
named. Keep true no-op on valid already-aligned files. Regression: the
garbage and truncated-open fixtures fail `format --check` with a path; a
valid aligned fixture still exits 0.

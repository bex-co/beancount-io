# Money movement month labels ignore the selected language

Severity: **minor**. Owning package: **dashboard**. Estimate: **35–50m** for the
local formatter, its two call sites and focused rendered checks.

## Reproduction and evidence

Production https://beancount.io, 2026-09-10, Chrome 152.0.7977.77, light.
Authenticated QA GROWTH reader; synthetic public example ledger has pull=true,
push=false, admin=false. Local main/origin main: 27873fc2; exact deployed SHA
unverified. The implicated formatter is unchanged since af5339de.

1. In an en-US browser, open
   /ledger/open_ledger/example?lang=fr&time=2016.
2. Wait for the Overview to settle and inspect **Mouvements d'argent**.
   Its selected month and both card subtitles read **December 2016**, while the
   heading, **Entrées d'argent**, **Sorties d'argent** and controls are French.
   Expected: **décembre 2016** in all three positions.
3. Repeat from a fresh context at 1440×1000 and 390×844: same result;
   document lang=fr, navigator.language=en-US, no page exceptions.
4. In fresh fr-FR browser contexts, open the same route with lang=en.
   All three labels instead read **décembre 2016** amid English UI.
   Expected: **December 2016**. Both widths reproduce.
5. Matching fr app/fr-FR browser controls correctly show **décembre 2016**.

Six fresh contexts: six document responses HTTP 200, four mismatches and two
matching controls, zero attempted mutations. The month-scoped View all links
remain time=2016-12, with the correct app language. The underlying selected
period is correct; this is generated UI text, not a ledger-authored description.

## Root cause and repair

dashboard/src/features/reports/overview/components/money-movement-section.tsx:

- Lines 33–40: formatMonth parses the period locally, then constructs
  Intl.DateTimeFormat(undefined, { month: "long", year: "numeric" }).
  The runtime default chooses the month language. This is also the documented
  [Intl.DateTimeFormat locale behavior](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/DateTimeFormat/DateTimeFormat).
- Line 85: MovementCard uses that helper for its subtitle; this component
  renders once each for income and expenses.
- Line 259: the section's selected-month label uses the same helper.
  Both components already use useTranslations, whose return value includes
  the request/router-specific i18n instance.

Supply the resolved active application language to this formatter and both
call sites, using the existing localization contract. It must react to language
changes and use the same explicit language during SSR and hydration. Preserve
the existing date parsing, invalid-date fallback, selected month, partial-period
marker, amounts and drill-down time filters. No new dependency or global
Intl/date-fns setting is needed.

Caller search finds one production MoneyMovementSection consumer:
features/reports/overview/index.tsx:178, on the ledger Overview route.
The local helper has exactly the two calls above. This repair is dashboard
presentation only; no GraphQL, REST or MCP schema/producer change is indicated.

locale. Do not promise this narrow repair removes every hydration error.

the visible month-language failure independently.

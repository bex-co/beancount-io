# Transaction auto-balance counts rows that submission discards

**Promoted to [m26](./m26/README.md).** That milestone is the sole implementation
queue and estimate after fresh reproduction of multiple eligible missing
amounts. This note retains the original evidence; count the group only once.

Severity: **major**. Owner: **dashboard**. Estimate: **35–55 minutes**.
A2: a person entering a transaction can leave an unused posting row without
the automatic amount producing an unbalanced transaction or a NaN amount.

Production `https://beancount.io`, 2026-09-08, Chrome 152, English, light.
Fresh QA contexts at 1440×1000 and 390×844, public `open_ledger/minimax` with
pull/push true and admin false. Local HEAD `a315c273`, fetched main `853a4942`;
implicated source unchanged, deployed SHA unverified. All mutation requests
were aborted before transmission; these are prepared payloads, not accepted writes.

1. Open `/ledger/open_ledger/minimax/journal?action=new-entry&directive=transaction`.
   Wait for the Transaction tabpanel and Currency inputs. Keep MUSD throughout.
2. Leave the first row's Account empty. In the second row, choose
   **Expenses:CostOfRevenue** and enter Amount **10**.
3. Click the plus button to add a third row. Choose **Assets:Current:Cash**
   in that row and leave its Amount empty for automatic balancing.
4. With the first row entirely blank, the UI puts the **-10.00** automatic
   placeholder on that unused first row. The real Cash row has no inferred
   amount. Create Transaction Entry is enabled and prepares only these rows:
   Expenses:CostOfRevenue **10 MUSD**, Assets:Current:Cash **NaN MUSD**.
5. Repeat fresh, but enter **100** as Amount in the first row while keeping
   its Account empty. Now Cash shows **-110.00**. Submission drops the first
   row but prepares **10 MUSD** and **-110 MUSD**, a residual of **-100 MUSD**.

Both cases repeat at desktop and narrow widths. The first case loses the
inferred amount to a row omitted from output; the second counts an amount
omitted from output. No extra commodity conversion or precision is involved.

Expected: the existing intentional rule that skips blank-account rows must
also govern auto-balance. With only the Expense10 and Cash rows eligible,
Cash's inferred amount is **-10 MUSD** in both cases. A row excluded from the
transaction cannot contribute to its sum or receive its inferred amount.

Working controls: a fresh normal Expense10/Cash-auto pair produces **10/-10**.
Removing the unused first row from the failing draft also restores **10/-10**;
the ordinary automatic trailing blank row remains harmless. Both controls pass
at both widths and prepare exactly two postings. They were also intercepted.

Root cause in
`dashboard/src/features/journal/components/new-directive-dialog/transaction-form.tsx`:

- `autoBalanceInfo` at173–214 iterates every watched row. It chooses the first
  empty amount and sums filled amounts by currency without checking Account.
- `onSubmit` at221–239 applies those inferred amounts by original row index,
  then removes blank-account rows at235. It serializes remaining empty amounts
  through parseFloat(...).toString(), producing the literal string **NaN**.
- The schema at78–103 intentionally allows blank draft accounts/amounts and
  validates before this derived output, so it does not catch this mismatch.

Fix: apply the same nonblank trimmed-account eligibility rule before creating
currency groups, summing amounts or choosing an inference target. Preserve
original row indexes in the result Map so an early skipped row does not shift
the inferred amount onto another posting. Keep per-currency grouping and the
existing output/unused-row policy. Do not include every draft row in output,
silently default NaN to zero, or alter financial signs to hide the residual.

A local Beancount3.2.3 fixture independently accepts **10/-10** without errors,
rejects **10/-110** with **Transaction does not balance: (-100 MUSD)**, and
rejects **NaN** as an invalid token. This is a local parser control, not a claim
about the uncalled production gateway's error or persistence behavior.

Blast radius: the calculation and serializer are private to TransactionForm,
whose only component caller is `new-directive-dialog/index.tsx:86`. Journal's
toolbar/sidebar entry actions and transaction deep link share this flow.
Other directive forms, import conversion and native mobile use different paths.

Acceptance: both original cases show Cash auto **-10.00** and prepare only
Expense10/Cash-10, with no NaN or extra -100 residual. Preserve normal entry,
deleting the unused row, automatic trailing rows and separate currency groups.
Use meaningful inference/submission checks with ignored rows at the beginning,
middle and end and whitespace-only accounts. Preserve original index mapping;
a test that filters rows and then compares only a sum would miss misassignment.
The original pass did not exercise multiple eligible missing amounts or other
currencies. Those states are now covered by m26's fresh failures and valid
controls. A patched production flow remains unverified.

Dedupe: searched open/completed records for auto-balance, unused/empty-account
rows and NaN postings. 039 is import sign reversal; 064 is native precision

# `bea list document` human table omits tags/links (JSON includes them; no `--details`)

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** cli. **A1:** an
agent that `add document … --tag trip --link inv-001` then `list document` in
human mode cannot see `#trip` / `^inv-001` — only DATE/ACCOUNT/FILENAME — while
JSON already returns `tags` and `links`, and there is no `--details` escape
hatch (unlike transactions).

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `5b1b3cde`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only. Evidence: `cli/tmp/qa-20260915/c552/`.

## Repro

```sh
mkdir -p receipts && echo '%PDF' > receipts/a.pdf
bea --file main.bean add document --date 2024-06-01 \
  --account Assets:Cash --path 'receipts/a.pdf' --tag trip --link inv-001
# ledger: document … "receipts/a.pdf" #trip ^inv-001

bea --file main.bean list document
# DATE / ACCOUNT / FILENAME only — no tags/links

bea --json --file main.bean list document
# "tags":["trip"], "links":["inv-001"]
```

## Expected

Human list shows tags/links (columns or inline), matching `add document
--tag/--link` and JSON — or offer `--details` that includes them.

## Actual

`cli/commands/list.py` `_SPECS["document"]` only emits
`[date, account, filename]`. Help has no `--tag`/`--link` filters or
`--details`.

## Fix

Add TAGS/LINKS columns (empty when absent), optionally `--tag`/`--link`
filters like transactions. Regression: the repro’s human row includes `trip`
and `inv-001`; JSON unchanged.

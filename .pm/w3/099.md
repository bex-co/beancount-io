# BQL suggestions accumulate duplicates after returning to Query

**Minor · dashboard · 40–55m.** A2: navigating between ledger pages should not
fill the query editor's suggestions with repeated copies of the same examples.

## Live reproduction

On https://beancount.io/ledger/open_ledger/example/query?lang=en:

1. Clear the editor and press Ctrl+Space. Four suggestions appear, one each for
   accounts, balances, entries and transactions.
2. Dismiss suggestions, use the page's **Related Pages → Journal** link, wait for
   Journal to finish loading, then use browser Back.
3. Clear the editor and reopen suggestions: **12 items**, three of each example.
4. Repeat the Journal/Back journey: **20 items**, five of each example.
5. Reload Query and reopen suggestions: exactly **4 items** again.

Repeated on 2026-09-09 in fresh 1440×1000 and 390×844 Chrome 152.0.7977.77
contexts, English/light, authenticated QA reader of public synthetic
open_ledger/example. Eight measured phases in the retained two-context repeat
show the same **4 → 12 → 20 → 4** sequence. The list virtualizes: the 20 total is
confirmed by each option's aria-setsize, while only the first 12 options are
mounted. It is not a count inferred from a truncated DOM.

Fresh initial documents return 200; the paced repeat has no page errors or
mutations, and no BQL query was executed. An earlier faster navigation probe
also showed duplicates but emitted Canceled errors; those errors did not survive
the fresh repeat and are not attributed to this defect.

Evidence in dashboard/tmp/qa-20260907-w3-loop/:
bql-completion-navigation-evidence.json and
bql-completion-duplicates-{1440,390}.png. The record includes option text,
aria-posinset and aria-setsize for each phase. Source/fetched main 7f4b6190;
deployed SHA unverified, live behavior matches the source lifetime issue.
All temporary contexts closed. No persistent user data was created.

## Root cause and scoped fix

dashboard/src/features/bql/pages/index.tsx:243–308 calls
monaco.languages.registerCompletionItemProvider("sql", ...) from editor onMount,
discarding the returned disposable. Each editor mount contributes another
four-item provider to Monaco's shared SQL registry. The adjacent SQL
setLanguageConfiguration at216–240 also discards its disposable.

Pinned Monaco 0.55.1 confirms the ownership: standaloneLanguages.js:448–450
registers in the language-features service; languageFeatureRegistry.js:45–66
retains entries until their returned disposable is called. Its orderedGroups
at89–104 groups equal-scoring SQL providers together, and
contrib/suggest/browser/suggest.js:184–216 requests and combines their items.
The observed navigation can mount more than one editor instance; this finding
does not assume one mount per Back action.

The common/components/monaco-editor/index.tsx wrapper only adds ClientOnly.
Installed @monaco-editor/react cleans up the editor/model on unmount, but knows
nothing about providers manually registered by this page. Disposing a model
does not remove a separate language-registry entry.

Give the page's provider and language-configuration registrations explicit
ownership. Retain their disposables and clean them up with the owning editor
lifecycle (Monaco exposes onDidDispose), or register one deliberately shared
BQL provider with equivalent bounded lifetime. Preserve four distinct examples
while Query is active and remove obsolete registrations when it leaves.
Do not globally reset Monaco, reload the page on navigation, or clear query
history to hide the duplicate list.

Search found one production completion-provider call site, this BQL page.
Its four snippets and SQL configuration are the bounded scope. Existing
Beancount language registrations have separate initialization and should retain
their current lifecycle. No backend, REST/GraphQL/MCP, or native change is needed.

Acceptance: after the exact initial/Journal/Back/repeat/reload journey at both
widths, the suggestion list contains four distinct examples at every Query
visit, each usable. Check keyboard selection through the list and repeated
mount/unmount cleanup without disabling suggestions. Preserve m12's URL and
Cmd+Enter behavior. Use meaningful editor lifecycle/browser coverage; the page
test currently stubs registration as a void function and never exercises its
disposable contract. A global registry count alone is not the user-facing check.

providers, Monaco cleanup and disposal; scanned open milestones across queues
and DO_NOT_DO. No existing item owns this lifetime issue. [098](./098.md) covers

SQL editors and native keyboards remain unverified.

# Smart Import accepts reordered CSV headers but swaps monetary values

Severity: **major**. Package: **dashboard**. Estimate: **45–60m** for bounded
header-layout validation or recognized-column mapping and regression coverage.

Production https://beancount.io, September 11, 2026, QA-owned headless Chrome
152.0.7977.83, English/light, 1440×1000 and fresh 390×844. Dedicated QA GROWTH
account, public synthetic `open_ledger/crypto-example`, pull:true, push/admin:false.
Local main f943005d; fetched main f1965988 has identical importer files. Live
entry module main-z45iacYQ.js; exact deployed SHA is unverified.

## Reproduce

1. Open `/ledger/open_ledger/crypto-example/import?lang=en` and select this local
   CSV. The amount and description columns are explicitly named:

   ```csv
   Date,Payee,Amount,Description
   2026-09-10,QA Supplies,-4.50,4102
   2026-09-11,QA Books,-12.75,4203
   ```

2. Preview says **2 Valid** with no layout warning. Its first row has
   Description **-4.50**, Amount **4102**; its second has Description **-12.75**,
   Amount **4203**. Both expenses have become positive values from the numeric
   descriptions. **Continue to Configure** is available.
3. Continue. Both rows remain selected with those same incorrect amounts and
   descriptions. The action says **Import 2 Transactions**. After account and
   currency reads finish, the values remain wrong; only the ordinary missing
   target-account warning is present. Do not submit.
4. A fresh narrow context repeats the two valid preview rows and both wrong
   configuration amounts. The table is horizontally scrollable; the accessible
   snapshot exposes the amount cells even when they are outside the viewport.
5. In another fresh desktop context, use the documented column order:

   ```csv
   Date,Payee,Description,Amount
   2026-09-10,QA Supplies,4102,-4.50
   2026-09-11,QA Books,4203,-12.75
   ```

   Preview again says **2 Valid**, now preserving the intended descriptions and
   negative amounts. Configuration contains **-4.5** and **-12.75**. Removing
   the trailing zero from -4.50 preserves its value and is not this defect.

Expected: a header-bearing file must either map the recognized columns correctly
or explain that its layout is unsupported before declaring the rows valid.
Silently accepting a header that contradicts the positional parser corrupts
the monetary meaning. The upload reference documents Date, Payee, Description,
Amount and says negative values represent expenses; arbitrary-order support is
not promised or required by this report. Rejecting unsupported layouts is a
valid bounded repair; a generic mapping interface is unnecessary.

## Cause and repair boundary

`dashboard/src/features/importer/utils/csv-validator.ts:154–173` recognizes
`date` plus any companion header anywhere in the first record, without checking
their positions. `hooks/use-csv-parser.ts:142–143` then discards that header.
At166–173 it always destructures the data as date, payee, description, amount.
The final fields 4102 and 4203 satisfy the complete decimal grammar, so
buildParsedRow reports no error despite reading the wrong column.

FileUpload passes the selected local File to UploadStep; FileReader at
use-csv-parser.ts:195–200 supplies its complete text. The active multi-stage
parser returns immediately when validCount > 0 (use-multi-stage-parser.ts:35–37).
No server parser gets a chance to correct the interpretation. The workflow
stores these rows and passes them to ConfigureStep. TransactionConfigForm's
date/amount checks at51–55 and conversion at117–125 only revalidate the already
misassigned amountInput, so they cannot recover the discarded header meaning.

Check the recognized header schema before discarding it or interpreting data
positionally. Preserve the canonical optional-header path, headerless rows,
whole-field case handling, quoted logical records, raw diagnostics and valid
zero. Keep an unsupported layout actionable through the current upload/preview
or parser-fallback error flow; do not label misassigned numeric fields valid.

- [ ] The exact reordered fixture cannot reach configuration as amounts 4102
      and 4203. It either retains -4.50/-12.75 under recognized mapping or shows
      a clear unsupported-layout outcome without corrupted valid rows.
- [ ] The canonical control still previews/configures both intended signed
      values at desktop and narrow widths; Back/Upload Different File recovers.
- [ ] Meaningful coverage drives the real CSV parser and upload-to-preview
      handoff, with canonical/headerless controls and contradictory header
      positions. Preserve the completed headerless-row and validation fixes;
      run dashboard checks when implementing.

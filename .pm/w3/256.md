# `bea import --csv` rejects common bank amount spellings (`$4.50`, `1,000.00`, `(4.50)`)

**Severity:** minor. **Estimate:** 30–45 minutes. **Owner:** cli. **A2/A1:** a
newcomer whose US-style bank export uses currency symbols, thousands separators,
or accounting parentheses cannot use the documented no-code CSV path; the error
only says `cannot parse amount` with no recovery hint.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `b2aa5e83`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
bea --no-input init books --currency USD --date 2024-01-01
bea --file books/main.bean add open --date 2024-01-01 \
  --account Expenses:Uncategorized

printf 'Date,Description,Amount\n2024-03-01,Coffee,$4.50\n' > dollar.csv
bea --json --file books/main.bean import dollar.csv \
  --csv date=Date,payee=Description,amount=Amount \
  --account Assets:Bank:Checking
# exit 2 — cannot parse amount '$4.50'

printf 'Date,Description,Amount\n2024-03-02,Paycheck,"1,000.00"\n' > comma.csv
bea --json --file books/main.bean import comma.csv \
  --csv date=Date,payee=Description,amount=Amount \
  --account Assets:Bank:Checking
# exit 2 — cannot parse amount '1,000.00'

printf 'Date,Description,Amount\n2024-03-01,Coffee,($4.50)\n' > paren.csv
bea --json --file books/main.bean import paren.csv \
  --csv date=Date,payee=Description,amount=Amount \
  --account Assets:Bank:Checking
# exit 2 — cannot parse amount '($4.50)'

# Unicode minus (U+2212) and trailing zero-width space (U+200B) also fail:
printf 'Date,Description,Amount\n2024-03-01,Uminus,\u22124.50\n' > uminus.csv
bea --json --file books/main.bean import uminus.csv \
  --csv date=Date,payee=Description,amount=Amount \
  --account Assets:Bank:Checking
# exit 2 — cannot parse amount '\u22124.50'
```

Working control (plain signed decimal):

```sh
printf 'Date,Description,Amount\n2024-03-01,Coffee,-4.50\n' > plain.csv
bea --json --file books/main.bean import plain.csv \
  --csv date=Date,payee=Description,amount=Amount \
  --account Assets:Bank:Checking
# exit 0 — ready row with -4.50 USD
```

Whitespace around a plain decimal is stripped and works (`" -4.50 "`).

## Expected

No-code CSV amounts accept common export spellings: optional leading currency
symbol (`$`, `€`, …), optional thousands separators (`,` or thin space), and
accounting parentheses for negatives — then parse as `Decimal`. Or document
that only bare decimals are supported and name a preprocess step in the error.

## Actual

`bea_engine/csv_mapper.py` `_parse_decimal` is `Decimal(value.strip())` only.
Any `$`, grouping comma, or `(…)` raises `InvalidOperation` → usage error.
`IMPORTING.md` says “bad amounts fail with the row number and column name”
but does not state the accepted grammar.

## Fix

Normalize amount cells before `Decimal` (strip currency letters/symbols that
are not part of the number, remove thousands separators when a decimal point
is present, map `(n)` → `-n`, map U+2212 minus to ASCII `-`, strip ZWSP/NBSP
padding), or share a small amount tokenizer with a clear grammar. Keep
European decimal-comma (`-4,50`) coordinated with w3/226’s related note.
Regression: each failing CSV above imports; plain `-4.50` and debit/credit
controls unchanged.

## Dedupe

Not w3/226 (semicolon/tab delimiter; mentions EU `-4,50` as related follow-up
only). Not w3/227 (non-UTF-8 encoding). No open note covers `$` / thousands /
parentheses amount normalization on the comma-CSV path.

# Public file titles lose the file path after rendering

Severity: **minor**. Owner: **dashboard**. Estimate: **40–60 minutes**.
A3: readers can distinguish public ledger files in browser tabs, bookmarks and
shared links, preserving the path-aware titles promised by completed w2/m8.

Production `https://beancount.io`, 2026-09-08, Chrome 152, English, light.
Fresh anonymous public-reader contexts at 1440×1000 and 390×844. Local HEAD
`a315c273`, fetched main `cc3f4c2f`; implicated source unchanged. Deployed SHA
unverified. No file edits or production writes.

1. Open `/ledger/open_ledger/budgeting-envelopes/files/blob/main/accounts.bean`
   and wait for the Monaco editor to render.
2. The browser title, `og:title` and `twitter:title` all read
   **Files - budgeting-envelopes**, without `accounts.bean`.
3. Fresh-load the sibling `main.bean` URL. All three titles are identical to
   the first file. Repeat at the narrow width with the same result.
4. Open `/files/tree/main` in the same ledger and click the actual `main.bean`
   file row. Client navigation also reaches the correct file with the generic
   browser title. Both widths reproduce it without page or console errors.

Expected: the title identifies the file path as well as the ledger, for
example **accounts.bean · Files - budgeting-envelopes**, before and after
hydration and navigation; sharing metadata identifies the same file.

The initial HTML has both the path-aware title and the generic title. The
settled head contains three title elements: generic, path-aware, generic;
Chrome's document title is the generic one. This is conflicting metadata,
not a missing file or a loader that has not finished. The editor and visible
filename are correct. Independent GetLedgerFile controls return HTTP200,
no GraphQL errors, distinct matching names/paths, and blobs `b24f2107…` and
`1b4d41f7…` (1663 and 1421 bytes). QA-authenticated REST file reads also return
HTTP200 and those exact paths/blob IDs; the anonymous REST controls require
authentication (401), which was not classified as this metadata bug.
The canonical URLs correctly distinguish
both files and the read pages have no robots noindex directive.

Root cause: the blob route's `head()` at
`dashboard/src/routes/ledger.$ledgerOwner.$ledgerName.files.blob.$branch.$.tsx:16–35`
prefixes the file path, but `features/ledger-editor/file-editor/index.tsx:47–56`
renders `LedgerPageSEO` with only `seoKey="ledgerFiles"`. Its file path is
passed to the canonical builder, not to the title. `common/components/seo/ledger-page-seo.tsx`
forwards the generic translated key; `common/components/seo/ledger-seo.tsx:83–114`
independently emits its generic title and OG/Twitter titles. The English key
in `i18n/locales/seo/en.ts:126` contains only the ledger name.

The pinned TanStack Router 1.167.0 implementation was inspected from its
integrity-verified package: `headContentUtils.tsx` deduplicates route metadata,
then HeadContent/Asset render the chosen title. It does not reconcile a
separate component's React-hoisted title. React's [title documentation](https://react.dev/reference/react-dom/components/title)
also describes multiple simultaneous titles as undefined browser/search-engine
behavior. Do not rely on title ordering as the fix.

Use one consistent path-aware title value for the blob's route metadata and
its sharing metadata, with a single authoritative document-title producer on
this route. Keep the filename available before file-content loading finishes.
Preserve existing localized ledger titles/descriptions, stable branch/path
canonicals, read-page indexability, and edit-mode noindex. Scope shared SEO
changes so other pages keep their current titles and metadata; this does not
require a general metadata-system rewrite or new dependencies.

Working controls: tree pages retain the generic Files title and noindex at
both widths. A QA-authenticated public commit detail retains **Commit 7442e53 -
budgeting-envelopes** in its browser and OG title: both its route and page
component pass `shortSha`. That control also has duplicate equal titles; it
proves parameter preservation, not a globally deduplicated head.

Blast radius: every blob path/branch uses this file page. Directory and legacy
Files content pages also use `ledgerFiles` but should keep their generic
title/noindex; create/upload use separate keys. Commit titles must retain
their working SHA behavior. Other locales, nested/non-ASCII paths, slow/error
file loads, edit mode and back/forward are proposed regression cases, not
additional live reproductions. API/REST/MCP file content contracts are not
changed by this dashboard metadata repair. Search ranking or third-party card
caches were not measured.

Acceptance: fresh accounts.bean/main.bean pages and tree-to-blob navigation
produce distinct path-aware browser/OG/Twitter titles at both tested widths;
the settled blob has no competing generic title. SSR output and hydration
agree. Canonical/indexability controls and the commit title still pass.
Add a focused route-plus-page rendering regression that catches this conflict,
rather than only asserting the route head function's already-correct string.

Dedupe: searched all open/completed board records for file titles, metadata
conflicts and path-aware titles, and scanned other queues. Completed w2/m8's
verification explicitly promises path-aware blob titles; its remaining DoD
still requires read blobs indexable, tree/write routes noindex and canonical
query stripping. `42ee1dec` added the route-only file prefix while preserving
the generic page SEO. `2d1baa41` changes canonicals, not this title mismatch.
No repair exists on fetched main. 009/040–042/046 concern file controls, drafts
or missing-file states; m17 and completed w2/m9 concern different commit work.

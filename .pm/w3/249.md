# `bea --json format -i` on a directory with no ledger files exits 0 with empty stdout

**Severity:** minor. **Estimate:** 15–30 minutes. **Owner:** cli. **A1:** a
script that formats a tree under `--json` and treats empty stdout as failure
cannot tell “nothing to do” from a broken pipe; human mode prints “No .bean or
.beancount files found.” while JSON is silent.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `22663317`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache.

## Repro

```sh
mkdir emptydir
bea format -i emptydir
# stdout: No .bean or .beancount files found.
# exit 0

bea --json format -i emptydir
echo exit=$?
# exit 0 — stdout empty, stderr empty (no envelope)

# working controls — same empty dir:
bea --json format --check emptydir
# {"data":{"scanned":0,"formatted":[],"check":true,...},...}
bea --json format --dry-run emptydir
# {"data":{"scanned":0,"formatted":[],"dry_run":true,...},...}
```

Also: a directory that only contains non-ledger files (e.g. `readme.txt`)
behaves the same under `--json format -i` (empty stdout) while
`--json format --check` reports `scanned: 0`.

## Expected

`--json format -i` on zero targets should emit the usual envelope, e.g.
`data: {scanned: 0, formatted: [], in_place: true}`, matching `--check` /
`--dry-run`.

## Actual

```text
cli/src/cli/commands/format.py
  if not files:
      output.success("No .bean or .beancount files found.")
      return
  # never reaches output.emit under --json
```

## Fix

When `ctx.json_output` and `files` is empty, `output.emit(_result([], []) |
{"in_place": True}, target=…)` (or shared empty-scan payload) instead of
`output.success` alone. Keep the human one-liner. Regression: empty dir /
no-matching-suffixes dir under `--json format -i` returns a parseable
envelope with `scanned: 0`.

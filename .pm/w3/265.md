# `bea import --csv` treats `NaN` / `Infinity` amounts as ready; apply then fails with “Invalid token”

**Severity:** minor. **Estimate:** 15–25 minutes. **Owner:** cli. **A1:** an
agent that trusts the preview’s `ready` count and diff will attempt `--apply`
on rows that can never write, getting a staged-candidate lexer error instead
of a row-level amount parse failure.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `02516c0a`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
# Assets:Cash + Expenses:Uncategorized open in main.bean
printf 'date,amount,description\n2020-06-03,NaN,nan\n' > nan.csv
bea --file main.bean import nan.csv --csv auto --account Assets:Cash
# exit 0 — "1 ready"; preview diff shows `Assets:Cash … NaN USD`

bea --file main.bean import nan.csv --csv auto --account Assets:Cash \
  --apply --duplicates include
# exit 1 — nothing written
# Invalid token: 'NaN'

printf 'date,amount,description\n2020-06-04,Infinity,inf\n' > inf.csv
bea --file main.bean import inf.csv --csv auto --account Assets:Cash
# exit 0 — "1 ready"; SOURCE AMOUNT `Infinity USD`
```

Working control: empty amount fails at parse (`cannot parse amount ''`);
`bea add … --posting 'Assets:Cash NaN USD'` exits 2 with `Invalid token: 'NaN'`
before claiming success.

## Expected

Non-finite amounts (`NaN`, `±Infinity`, case variants `inf`/`nan`) fail in
`_parse_decimal` with a clear row/column usage error during preview, same as
other bad amounts — never listed as `ready`.

## Actual

`csv_mapper._parse_decimal` uses bare `Decimal(value.strip())`. Python accepts
`NaN`/`Infinity` as non-finite Decimals, so extract builds entries; preview
marks them ready. Beancount’s lexer rejects the tokens only when apply
validates the candidate ledger.

## Fix

After `Decimal(...)`, require `number.is_finite()` (and reject otherwise with
`cannot parse amount …` or an explicit non-finite message). Regression: the
three CSVs above exit 2 on preview with no ready rows; ordinary `-4.50`
unchanged.

## Dedupe

Not w3/256 (rejects common bank spellings that should work). Not w3/259
(scientific notation path split). Not w3/263 (blank rows). No open note covers
non-finite CSV amounts shown as ready.

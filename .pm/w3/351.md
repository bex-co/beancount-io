# `bea check` stays green on a copied ledger with absolute document paths outside the copy

**Severity:** minor. **Estimate:** 25–40 minutes. **Owner:** cli. **A1:** after
`cp main.bean` without attachments, absolute document paths still resolve to
the original tree so `check` exits **0** — while relative paths correctly fail.

Found 2026-09-16 by continuous CLI QA ([c930 hunt](62e4a1d6-76c6-4d48-9c7e-c406f33cf01a)),
HEAD `e1602b7d`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Confirmed
`cli/tmp/qa-20260915/c931/`. Evidence: `c930/`.

## Repro

```sh
# orig/main.bean has absolute document path to orig/docs/invoice.pdf
cp orig/main.bean copy-only/main.bean
bea --file copy-only/main.bean check
# exit 0 — attachments still live under orig/

# same copy with relative "docs/invoice.pdf" → exit 1 File does not exist
```

## Expected

Check fails (or warns) when document paths fall outside the loaded ledger’s
directory; `add document` should prefer/require relative paths for portability.

## Actual

Absolute paths validate by global existence; copies appear valid while bound to
another tree.

## Fix

Reject/warn absolute `--path` outside the ledger root on add, and/or emit a
check diagnostic for out-of-tree documents. Regression: abs-path copy exits
nonzero (or warns); relative missing path still exits 1; in-place orig OK.

## Dedupe

Related to w3/244 (add relative vs list absolute) — different surface: copy
portability under `check`. No open note covers falsely green copied ledgers
with absolute document paths.

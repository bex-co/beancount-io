# Account and ledger search inputs have empty accessible names

Severity: **minor**. Package: **dashboard**. Estimate: **20–35m**.
A2: assistive-technology users can identify the search field after opening
account navigation or the ledger switcher.

Production `https://beancount.io`, 2026-09-08, Chrome 152, English/light.
QA reader of public `open_ledger/example`, fresh 1440×1000 and 390×844 contexts.
Local `a315c273`, fetched main `790791ac`, implicated sources unchanged;
deployed SHA unverified.

1. Load `/ledger/open_ledger/example/journal?lang=en`. Open the sidebar at
   narrow width, then **Search accounts...** beside Accounts.
2. The visible input says **Search accounts...**, but its accessibility-tree
   entry is just **combobox [expanded]**, with no name. aria-labelledby points
   to a real hidden label whose text is empty; the associated native label is
   also empty. The input's placeholder does not supply its accessible name.
3. In a separate fresh context, open **Select a ledger**. Its input shows
   **Search ledgers...** and has the same unnamed combobox/empty-label state.
4. Repeat both journeys from fresh pages at 390px: identical result. The
   trigger buttons themselves retain their existing accessible names.

Expected: the two inputs have localized names identifying account or ledger
search. In isolated runtime controls at both widths, setting only the existing
hidden label's text to the existing placeholder produces named comboboxes
**Search accounts...** and **Search ledgers...**. Filtering still finds the
known public account/ledger, and Escape returns focus to the right trigger.
No item selection or write action is needed. These are label controls, not a
patched-production claim.

Root: `dashboard/src/common/components/ledger-layout/go-to-account.tsx:57–60`
and `ledger-switcher.tsx:229–230` supply CommandInput placeholders but omit
the parent Command's label prop. The wrapper at
`common/components/ui/command.tsx:9–22` already forwards that prop. Pinned,
registry-integrity-verified **cmdk 1.1.1** renders a hidden label from the root
label prop and points its input's aria-labelledby to that label. The package
README demonstrates the supported Command label API. This association to an
empty label explains why the visible placeholder does not rescue the name.

Fix the two callers by passing their existing translated search strings to
Command's label prop: component.accountCombobox.placeholder for account search
and page.dashboard.searchLedgers for ledger search. Keep their existing
placeholders, input IDs, native label association, filtering and focus behavior.
No new translations, generic hardcoded label, dependency, API change or shared
wrapper rewrite is needed. The
[combobox pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)
requires an accessible name for the field.

Verify actual browser names at desktop/narrow widths, including active Chinese
using the existing translated strings. Keep public-target filtering and Escape
controls, then run the owning package gates when implementing. Avoid a test
that only checks placeholder text: that is already present in the broken UI.

Blast radius: these are the only two production CommandInput callers. Both
live in the shared ledger sidebar across ledger routes. CommandDialog has no
production caller; the shared form Combobox uses its own input outside Command
and is not part of this repair. API data and query state do not determine the
missing label. All documents return HTTP 200, with no console/page errors.
Temporary contexts closed; no credentials or private ledger result lists were
retained. Native assistive technology, other browsers and patched language
transitions remain unverified production scenarios.

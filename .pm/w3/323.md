# `bea add transaction --allow-errors` writes newly introduced semantic errors and exits 0

**Severity:** major. **Estimate:** 30–45 minutes. **Owner:** cli. **A1:** an
agent that passes `--allow-errors` (copying the flag from a failing balance
assertion workflow) can append a transaction with an unknown account or
currency mismatch; bea prints **Added 1 transaction**, exits **0**, and leaves
a ledger that **`bea check` rejects** — while the same add without the flag
correctly refuses.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `47a96ffb`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only. Evidence: `cli/tmp/qa-20260915/c670/`, `c665/` (confirm).

## Repro

```sh
cat > main.bean <<'EOF'
option "operating_currency" "USD"
2020-01-01 open Assets:Cash USD
2020-01-01 open Expenses:Food USD
EOF

# Control — refused:
bea --file main.bean add transaction --date 2020-02-01 --narration ctrl \
  --posting 'Assets:Cash -1 USD' --posting 'Expenses:Missing'
# exit 1 — nothing written

# Bug — written:
bea --file main.bean add transaction --date 2020-02-01 --narration bad \
  --posting 'Assets:Cash -1 USD' --posting 'Expenses:Missing' --allow-errors
# exit 0 — Added 1 transaction …
# stderr still: unknown account Expenses:Missing

bea --file main.bean check
# exit 1 — Invalid reference to unknown account 'Expenses:Missing'
```

Currency mismatch variant:

```sh
bea --file main.bean add transaction --date 2020-02-01 --narration eur \
  --posting 'Assets:Cash -1 EUR' --posting 'Expenses:Food' --allow-errors
# exit 0; check exit 1 (Invalid currency EUR …)
```

JSON: `"written": 1` with the validation text only in `warnings`, exit 0.

## Expected

USAGE: `--allow-errors` is for a semantic error that is **intentional or
already in the books** (e.g. a failing balance assertion), not for introducing
new unknown-account / currency violations. Either block those newly introduced
failures even with the flag, or exit non-zero / `written: 0` when post-write
`check` would fail for reasons absent before the append.

## Actual

`validate_candidate(..., allow_errors=True)` returns unknown-account / currency
messages as warnings; `append` persists the directive; the frontend reports
success. Same helper as import apply (w3/321).

## Fix

Shared with w3/321: distinguish pre-existing ledger errors from errors
introduced solely by the candidate. Regression: the repro exits ≠ 0 and leaves
the pristine file; `--allow-errors` still allows a **clean** transaction over a
ledger that already has a failing balance assertion.

## Dedupe

Not w3/321 (import `--apply --allow-errors` only). Not w3/232 (`add custom`
pad poison). Not w3/276 (import without the flag). No open note covers
**`add transaction --allow-errors`** persisting check-invalid rows.

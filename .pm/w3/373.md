# `report income-statement -x units` monthly breakdown drops explicit zero P&L months that default conversion keeps

**Severity:** minor. **Estimate:** 20–35 minutes. **Owner:** cli. **A1:** an
agent comparing default and `-x units` income statements sees inactive months
flip from `0.00 USD` / `{"USD":"0"}` to `—` / `{}` — silent loss of “zero
activity” vs “no row”.

Found 2026-09-16 by continuous CLI QA ([c1180 hunt](f8f82612-407e-4749-add5-5ba4eb6bc4d8)),
HEAD `de21ec33`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Evidence:
`cli/tmp/qa-20260915/c1180/`.

## Repro

```sh
bea --file main.bean report income-statement
# 2020-01-31 / 2020-04-30 → 0.00 USD columns

bea --file main.bean report income-statement -x units --allow-errors
# same months → —

bea --json … report income-statement
# net_profit {"USD":"0"}

bea --json … report income-statement -x units --allow-errors
# net_profit {}
```

## Expected

`-x units` should not change zero-month semantics for USD-only P&L buckets, or
document that units mode treats quiet months as absent.

## Actual

Units conversion renders empty buckets as `—` / `{}` while default keeps
explicit operating-currency zeros for the same months.

## Fix

Preserve explicit zeros under `-x units` when amounts are operating-currency
only, or document the difference. Regression: quiet months match across modes;
active multi-currency months unchanged.

Not w3/313, 304, 327, 292. No open note on units conversion changing

# `bea report … -x ''` silently uses the default conversion (same as omitting `-x`)

**Severity:** minor. **Estimate:** 10–15 minutes. **Owner:** cli. **A1:** an
agent that passes `-x ""` from a template hole believes conversion was
requested but gets the default (`USD` for a single operating currency, or
`units` when several) with no usage error — while `-x '   '` attempts a
nonsense target and fails on missing prices.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `cae6cfc1`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only. Evidence: `cli/tmp/qa-20260915/c730/`, `c731/`.

## Repro

```sh
# single operating_currency USD
bea --json --file main.bean report trial-balance -x ''
# conversion: "USD" — identical to omitting -x

bea --file main.bean report trial-balance -x '   '
# exit 1 — Missing prices for USD →    …
```

Multi-OC ledger: `-x ''` and omitting `-x` both yield `conversion: "units"`.

## Expected

Empty `-x` / `--conversion` is a usage error (exit 2), same empty-filter
policy as w3/327 (`-t ''`) and w3/286–287 / w3/294.

## Actual

`_load` does `conversion or (currencies[0] if … else "units")`, so `""` is
falsy and falls through to the default.

## Fix

Treat empty/whitespace-only conversion like an invalid `-x` (UsageError)
before the defaulting expression. Regression: `-x ''` / `-x '  '` exit 2;
omitting `-x` and `-x USD` unchanged.

## Dedupe

Not w3/327 (empty **time**). Not w3/313 (empty section `0.00 <conversion>`
label under partial FX). No open note covers empty `--conversion` / `-x ''`.

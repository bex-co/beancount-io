# Import row selection removes the focused checkbox

Severity: **minor**. Owner: **dashboard**. Estimate: **35–50 minutes**.
A2: a keyboard user should be able to select and deselect import transactions
without losing their position in the configuration table.

Production `https://beancount.io`, 2026-09-08, Chrome 152, English,
System/light; authenticated QA reader of public synthetic `open_ledger/crypto-example`.
Desktop 1440×1000 and fresh 390×844, after account/currency controls finish
loading. Local HEAD `a315c273`, fetched main `cc3f4c2f`; implicated selection
code is unchanged there. Deployed SHA unverified.

1. Open `/ledger/open_ledger/crypto-example/import` and preview this local CSV:

   ```csv
   2025-12-01,QA Coffee,Regular purchase,-4.50
   2025-12-02,QA Grocery,Regular purchase,-45.67
   ```

2. Continue to Configure. Wait for Select source account and Select currency
   controls; leave source account blank and currency USD. Both row checkboxes
   are initially checked, and the action says **Import 2 Transactions**.
3. Focus **Select transaction 1** and press Space. It correctly unchecks and
   the action becomes **Import 1 Transaction**, but focus moves to `BODY`.
4. The originally focused checkbox is now disconnected from the DOM. A new
   checkbox has replaced it. Pressing Space again does not select it again.
5. As a control, focus **Select all visible rows** and press Space. It selects
   both transactions and retains focus. The action returns to Import 2.

Fresh desktop and narrow repeats agree, with the account/currency controls
fully loaded. No page errors or API requests occurred during the monitored
selection interactions. No Import or AI Fill action was activated. All local
configuration and preview state was discarded afterward.

Expected: toggling a row's selected boolean changes its checked state and
counts while preserving focus on that same control. Repeated Space must
select/deselect it without refocusing. Keep transaction values, assigned
accounts and unrelated validation state intact.

Root cause: `dashboard/src/features/importer/components/steps/configure/account-mapping-table.tsx:156–159`
uses `useFieldArray.update(index, { ...txn, selected: !txn.selected })` for a
single boolean. Its rendered TableRow at 288–297 is keyed by `field.id`.
The pinned React Hook Form 7.71.0 implementation regenerates the updated
row's ID in `useFieldArray.update`, so React remounts the entire row and removes
the focused checkbox. This matches the observed disconnected DOM node; it is
not a missing accessible name or a failure to change the selection.

Use a normal controlled field update for `transactions.<index>.selected`
through the existing form/control API. Keep stable field-array keys. Apply the
same scalar-update approach to the visible-row bulk handler at 141–152 so it
does not unnecessarily replace every row. Do not change keys to array indices
or add a blanket refocus effect to hide the remount.

The bulk control works because it lives outside the rows being replaced.
Additional working control: with both selected, search **QA Coffee**, then
deselect all visible rows. Only Coffee is unchecked; the hidden Grocery row
stays selected and Import 1 remains accurate after clearing search. Preserve
that visible-only behavior, the existing accessible names, and missing-account
warnings for selected rows.

AccountMappingTable has one production caller, `transaction-config-form.tsx:254`,
in Smart Import configuration. Its two selection handlers are the only
field-array update calls in the importer. Keep the existing field-array
management for actual structural operations and normal target-account fields.

Acceptance: the exact desktop/narrow Space journey retains focus and supports
immediate repeated toggles. Bulk selection retains focus, search-hidden rows
keep their state, Import counts and missing-account warnings stay correct,
and assigned accounts/transaction values survive selection changes. Use a
component interaction test through the actual form and checkbox, checking
focus and user-visible selection behavior; run normal dashboard checks when
implementing. No dependency upgrade or backend work is needed.

Dedupe: searched all open/completed board records for checkbox focus, row
remounts and field-array selection updates, and reviewed open milestone
summaries. 047 concerns replacing an inline Preview input on Enter/Escape;
this Configure checkbox should never need replacement for a boolean change.
037 concerns Preview row identity after deletion, and m19 owns input
validation. Do not merge these causes into an index-key workaround. Targeted
history traces this selection handler to `af5339de`, with no newer repair.

# Six legacy dashboard alias paths 404 on the website instead of redirecting

`dashboard/src/routes/{dashboard,gallery,welcome,logout,forgot-password,reset-password}.tsx` redirect `/dashboard`, `/gallery`, `/welcome`, `/logout`, `/forgot-password` and `/reset-password` to `/ledger`, `/ledger-gallery` and `/auth/*`. On 2026-11-21, signed out and signed in, production sent each of the six to the website instead. The website answered HTTP 404 with its own page rather than the dashboard (`main-CIyNN76T.js`), so these redirects never run in production.

- `/nonexistent-qa-path-xyz` now gets the website's page too; w3/652 recorded it as the dashboard's 404 on 2026-11-16.
- `/login` and `/sign-up` still answer 307 to `/auth/*`, and `/settings` and `/ledger-gallery` still reach the dashboard.
- Nothing in this repo links to the six paths today (live emails use `/auth/reset-password/?token=`), so only old bookmarks and links are hurt.

The fix lives in the production edge or website routing, not in this repo. Alternatively, the owner retires the aliases and the route files are deleted.

**Done when:** `curl -sI https://beancount.io/dashboard` and the other five return a 3xx to their dashboard target, or the owner decides to retire the aliases and the six route files are removed.

Source: routine `dashboard-qa` follow-up, 2026-11-21. (≤1h)

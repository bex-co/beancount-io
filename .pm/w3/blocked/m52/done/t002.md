## Objective

Translate recognized shared-provider quota refusals into the product's 429 rate-limit contract. Name shared service capacity separately from the user's monthly allowance, carry validated reset/retry metadata when present, and keep provider documents, pricing links, and credentials out of customer errors.

## Files

- `backend-cluster/backend-v2/src/features/llm/service/llm-service.ts`
- Shared domain error types if required
- Actual proxy adapter/service regression tests and backend documentation

## Acceptance criteria

- Simulated provider 402/429 quota responses produce product-owned 429 errors through the actual route.
- Plain and nested provider envelopes are handled with bounded parsing; unsupported data never becomes raw customer-visible JSON.
- Only valid reset metadata is exposed; local monthly quota enforcement and failed-request usage accounting are preserved.
- Regressions fail before the fix; backend checks pass.

## Resolution

Shipped in `cff30747` (backend-v2). Recognized 402/429 provider quota errors now return the product's `RATE_LIMITED` 429 contract with `quotaScope: shared_service`. The bounded parser recognizes exact codes through error/message envelopes, normalizes valid future reset timestamps, and validates retry seconds. Product-owned messages include safe reset guidance without copying provider documents, links, or credentials. Other provider errors retain their HTTP status with safe generic messages. Local monthly checks still precede the upstream call; failed calls never record usage. Public backend documentation distinguishes shared capacity from account allowance.

All 26 new HTTP cases failed before the fix, while 17 existing cap/auth/quota controls passed. The full backend suite passed 294 suites / 4,835 tests. Review then added a non-ASCII byte-limit regression: it failed first and passed after the parser switched to UTF-8 byte counting; all 47 final focused tests pass. Typecheck, lint/dead-code detection, build, unchanged regenerated v1 OpenAPI, and the final public-tree secret scan pass; typecheck/lint and the focused suite were rerun after the byte-limit refinement. Controlled upstream responses only; no real provider or customer ledger was called.

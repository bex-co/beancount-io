# BQL horizontal scrolling separates cells from their column headers

**Promoted to [m28](./m28/README.md).** That milestone is the sole implementation
queue and estimate after fresh reproduction of missing table semantics in the
same renderer. This note retains the original scroll evidence; count it once.

Severity: major. Owner: dashboard. Estimate: 45–60 minutes for a shared scroll
layout and focused browser regression. A2: readers can interpret wide query
results without assigning values to the wrong columns.

Environment: production https://beancount.io, Chrome 152, authenticated QA public
reader on synthetic `open_ledger/example`, English/System light, 390×844 with a
1440×1000 control. Initial and fresh narrow reproductions on 2026-09-08. Source
HEAD a315c273; fetched origin/main cc3f4c2f has no matching result-layout fix.
The deployed build is not proven identical to this checkout.

Reproduce:

1. Open `/ledger/open_ledger/example/query` with the URL query parameter set to
   `SELECT account, date, flag, payee, narration, position LIMIT 3`, or execute
   that query using the button. Wait for the three-row result to settle.
2. At 390px, hover the result rows and horizontally scroll 300px. The body
   scrollLeft becomes 300 while the outer/header scroller remains zero.
3. Header positions stay account x26, date x146, flag x266, payee x386,
   narration x506 and position x626. First-row cells move to x-274, -154, -34,
   86, 206 and 326 respectively. The screenshot shows Hoogle under account,
   Payroll under date and the position amount under flag.
4. Fresh navigation repeats the same mismatch. At 1440px the six columns fit,
   neither container overflows and every header/cell position aligns.

Expected: horizontal scrolling moves header and corresponding cells together,
regardless of whether the gesture starts over the header or rows. Every column
must remain reachable without independent scroll positions or blank body areas.

Working data control: the actual QueryShell GraphQL response is HTTP 200, with
six matching type descriptors and three six-cell rows. The last row's payee is
Hoogle, narration Payroll and position 1350.60 USD. The response is correct;
the display separates these values from their labels. Fresh console has zero
errors/warnings. A 60-account single-column query can vertically scroll to
Liabilities:US:Chase:Slate and exports all 60 rows plus its header, so the body
is not generally truncating query data.

Root cause: `dashboard/src/features/bql/components/query-result-card.tsx:73`
places the header inside an outer `overflow-x-auto` wrapper. The sibling
react-window List at `:85` is constrained to width 100%, while each header and
body cell has min-width 120px. It creates another horizontal scroller when
columns exceed that width. The locked react-window 2.2.5 List source sets
overflowY:auto; the browser computes horizontal overflow as auto as well.
Runtime geometry confirms two separate 338px viewports with scrollWidth720.

Fix QueryResultCard so header and virtualized body share the same content width
and horizontal scroll owner. Keep vertical virtualization and its 600px cap,
consistent column widths and scrollbar alignment, readable cell content and
CSV export. Do not synchronize two independent x-scroll positions with ad hoc
event handlers if one shared scroll layout suffices, or fix the issue by hiding
later columns/removing virtualization. No server/schema/data changes required.

Blast radius: QueryResultCard renders every BQL history result table, including
reopened results and auto-executed query URLs. Its chart/text/empty/error paths
must remain intact. The stale editor behavior in `w3/m12` is separately tracked;
this reproducer intentionally identifies the executed query in its history card.

Acceptance: for the six-column reproducer, scroll from either header or body
at 390px and verify each column's header/cells retain the same x-position. Repeat
after resizing to 1440px and back and on a longer vertically virtualized result;
last row/column and CSV remain complete. Use a real browser geometry check,
not a class-name assertion or mocked react-window rendering.

Dedupe: searched all open/done board records for query/BQL column alignment,
horizontal scrolling and headers. `w3/m12` changes query execution/editor state;
`w3/025` changes statement hierarchy numeric wrapping in another component.
Neither covers this two-scroller result table. Targeted history traces the
wrapper/List arrangement to af5339de, without a later source correction.

Unverified: touch hardware, native app, browser zoom, every column count and
non-overlay OS scrollbar. No product implementation or shipping included.

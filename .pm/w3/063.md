# Confirming composed text submits an unfinished AI question

Severity: **major**. Owner: **dashboard**. Estimate: **45–60 minutes**.
A2: people using an input method editor can finish writing a question without
the Enter key used to confirm a word prematurely sending their draft.

Production `https://beancount.io`, 2026-09-08, Chrome 152, English, light.
Fresh QA-authenticated public-reader contexts at 1440×1000 and 390×844 on
`open_ledger/example`. Local HEAD `a315c273`; main refreshed during this sweep is
`cc3f4c2f`, with no change to either implicated input. Deployed SHA unverified.

1. Open `/ledger/open_ledger/example/agent` and enter **How do I record **.
2. Start composing **记账** and press Enter while the composition session is
   active, as when confirming an input-method candidate.
3. The draft is cleared, **How do I record 记账** appears as a user message,
   and the client attempts POST `/api-gateway/agent` before composition ends.
4. Repeat on `/ask?mode=sandbox`: the same draft is submitted to `ask-agent`.
5. In Overview's **Ask me anything about this ledger...** input, the same
   composition confirmation navigates away to `/agent?q=...` and auto-submits
   the unfinished text. All three surfaces reproduce at both widths.

The retained browser reproduction uses Chromium's
[Input.imeSetComposition](https://chromedevtools.github.io/devtools-protocol/tot/Input/#method-imeSetComposition)
to establish real browser composition state, then Playwright Enter. It does
not dispatch a fabricated KeyboardEvent from page JavaScript. Each failing
sequence records trusted compositionstart/compositionupdate/input events and
a trusted Enter keydown with `isComposing=true`, before any compositionend.
The browser input holds the exact draft immediately before that Enter.

Expected: composition-confirming Enter is left to the input method. It must
not submit, navigate, clear the draft or append a chat message. After text is
committed, a separate ordinary Enter may submit normally. This follows the
[UI Events composition flag](https://w3c.github.io/uievents/#dom-keyboardevent-iscomposing),
which identifies keyboard events occurring within a composition session.

Root cause: `dashboard/src/features/ai-agent/pages/agent/agent-chat-input.tsx:173–184`
checks only Enter and Shift, immediately calls preventDefault/onSubmit, and
never checks the native event's composition flag. The global type-to-focus
listener in the same file correctly excludes composing events at line143,
but that does not protect the textarea's own submit handler. AgentPageImpl
at `pages/agent/page.tsx:305–306` sends the message and clears input.

`features/ai-agent/components/quick-ask-input.tsx:26–30` independently has the
same omission. Its handler navigates with `q`; the mode-less Ask alias redirects
to Agent, whose `page.tsx:176–187` submits that initial question. Therefore
fixing only the textarea leaves the Overview entrypoint broken.

In both React key handlers, return while `e.nativeEvent.isComposing` is true,
before preventDefault or submission/navigation. Preserve Shift+Enter multiline
input, ordinary Enter submission, whitespace/disabled/upload guards, and the
existing global type-to-focus exclusions. Use the native KeyboardEvent flag:
the pinned React DOM19.2.3 package was integrity-verified and its SyntheticEvent
constructor at `react-dom-client.development.js:3364` retains `nativeEvent`.
No new dependency, input-method implementation or AI transport change is needed.
Add browser-specific fallback logic only if a separate real browser reproduction
shows that it is required; Safari key-code behavior is not proven here.

Working controls at both widths: committing the same composed text through
CDP Input.insertText preserves the draft with zero requests; Shift+Enter adds
a newline with zero requests; a subsequent ordinary Enter has
`isComposing=false` and makes exactly one guarded request containing the
completed text. The commit control emits compositionend with isTrusted=false;
the failing Enter sequences above have trusted composing keydowns. No claim
of a manually operated macOS/Windows IME or native mobile keyboard is made.

Blast radius: AgentChatInput serves `/agent`, `/ask?mode=sandbox` and the
source-traced `/ask?mode=agent` variant. QuickAskInput's sole production caller
is Overview. The whole AI feature was searched for Enter handlers; these two
are the relevant producers. 062 changes this composer's accessible send name;
preserve that independent repair when these tasks land together.

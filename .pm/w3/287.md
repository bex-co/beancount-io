# `bea list … --account ''` matches every row (empty substring is always true)

**Severity:** minor. **Estimate:** 10–20 minutes. **Owner:** cli. **A1:** same
class as w3/286 for `--search`: an empty `--account` filter (template hole,
shell `""`, JSON→CLI bridge) silently returns the full unfiltered list for
every account-filtered `list` subcommand instead of zero hits or a usage
error.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `6cbb6a92`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
# Any ledger with several opens / transactions

bea --json --file main.bean list open
# data length N (e.g. 4)

bea --json --file main.bean list open --account ''
# exit 0 — data length N (same as unfiltered)

bea --json --file main.bean list open --account Cash
# exit 0 — only opens whose account contains “Cash”

bea --json --file main.bean list transaction --account ''
# exit 0 — every transaction (same as omitting --account)

bea --json --file main.bean list price --currency ''
# exit 0 — every price (same as omitting --currency)
```

Same empty-string match-all on `list transaction|note|balance|close|document|pad`
and on `list price|commodity --currency ''`.

## Expected

Empty `--account` / `--currency` is a usage error (exit 2: filter required) or
matches nothing. It must not disable filtering. Align with the fix chosen for
w3/286 (`--search ''`) even though the mechanism differs (see below).

## Actual

Passing `--account ''` or `--currency ''` returns the same rows as omitting the
option.

## Root cause

Filters are gated with truthiness, e.g.
`if account and account.casefold() not in entry.account.casefold()` and
`if currency and entry.currency.casefold() != currency.casefold()`
(`cli/src/bea_engine/ledger/reader.py`). An empty string is falsy, so the
`if account` / `if currency` guard fails and the filter is skipped entirely.
(Contrast w3/286: `--search ''` builds `terms=['']`, which is truthy, and
`'' in text` is always true.)

## Fix

Reject blank `--account` / `--currency` (after strip) with a usage error, or
treat blank as “match nothing”. Share validation with w3/286. Regression:
`--account ''` and `--currency ''` exit 2 (or `[]`); non-empty filters
unchanged.

## Dedupe

Twin of w3/286 (empty `--search`; different mechanism). Not w3/285 (`list pad`
SOURCE column). Not w3/275 (Unicode). No open note covers empty-string
`--account` / `--currency` disabling the filter.

# `bea add open` cannot set a booking method (`FIFO` / `STRICT` / …)

**Severity:** minor. **Estimate:** 25–40 minutes. **Owner:** cli. **A1:** an
agent opening a brokerage account for lot matching has no CLI/API way to emit
`open … "FIFO"` — `write_open` hardcodes `booking=None`, and `add open` has no
`--booking` flag — so FIFO/STRICT policy must be hand-edited into the ledger
(and even then `list open` drops it; see w3/290).

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `0ef1931e`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
bea --file main.bean add open --help
# Options: --date, --account, --currency, --allow-errors, --into
# (no --booking)

bea --file main.bean add open --date 2020-01-01 \
  --account Assets:Broker --currency HOOL --booking FIFO
# Error: No such option: --booking

bea --file main.bean add open --date 2020-01-01 \
  --account Assets:Broker --currency HOOL
# writes: 2020-01-01 open Assets:Broker HOOL
# (never: … HOOL "FIFO")
```

## Expected

`bea add open` accepts an optional booking method (Beancount’s
`FIFO`/`STRICT`/`NONE`/`AVERAGE`/…) and writes it on the open line, matching
hand-authored `open Assets:Broker HOOL "FIFO"`.

## Actual

`bea_engine/ledger/writer.py` `write_open` always passes `booking=None` to
`Open(...)`. `OpenDirective` has no booking field; the Typer command exposes
none.

## Fix

Thread optional `booking: str | None` through `OpenDirective`, the `add open`
CLI (`--booking`), and `write_open` (map to `beancount.core.data.Booking`).
Reject unknown names with a usage error. Pair with w3/290 so list/JSON round-
trip the value. Regression: `--booking FIFO` writes `"FIFO"` on the open line;
omit → unchanged bare open.

## Dedupe

Not w3/290 (`list open` drops booking on opens already in the file). Complementary
write-path gap: agents cannot create the booking in the first place via `bea`.

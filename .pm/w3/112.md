# Mobile merchant detail fails for punctuated payee names

Severity: major. Estimate: 45m. Package: mobile. A2 — a valid public-example merchant should open its recorded transactions.

Environment: September 10, HEAD a1c1bac8, native build 1.20260906.47 loading local JS, iPhone 17e / iOS 26.5, English/System/light/default large text; signed-in QA at https://beancount.io, public read-only open_ledger/crypto-example.

Repro:
1. Select the public crypto example, then open inspected internal route beancount:///(app)/merchant-detail?payee=Ethereum%202.0.
2. After loading, the header shows Ethereum 2.0, 11 transactions, $117.50 and Feb 20–Dec 31, 2024. The transaction list is replaced by “Failed to load merchant: Trailing tokens” and Try again.
3. Terminate/relaunch, reopen the same route and let it settle: same failure. This tests the destination, not the merchant-list tap journey.

Expected: show all 11 exact-payee transactions, newest first. Actual: metadata queries succeed but journal loading fails. A read-only getLedgerJournal request with directiveTypes:[Transaction], limit:20 and filter:"Ethereum 2 0" returns HTTP 200 with GraphQL errors [{message:"Trailing tokens"}]. Raw "Ethereum 2.0" also fails. The valid filter payee:"Ethereum 2.0" returns total:11 and 11 entries, including December 31 hash a2880e3ebb69187903bf71fda168e234. Native Lido detail is a working control: four transactions and four visible rows, no error.

Root cause: mobile/src/screens/merchant-detail-screen/selectors/filter-exact-payee.ts:19-20 treats the API filter as free text and replaces periods with spaces. merchant-detail-screen.tsx:274,286-290 passes that bare string to getLedgerJournal and repeats it for pagination at 347-351. The advanced-filter grammar tokenizes the numeric suffix, leaving trailing tokens. The quoted BQL metadata/total queries use a different builder and succeed, explaining the populated header. The server is correctly rejecting invalid filter syntax; this is a mobile serializer mismatch.

Fix: serialize a valid quoted, regex-escaped literal for the journal query while preserving the original exact-payee comparison, or use an equally safe explicit payee predicate. Consolidate with the already-shipped Transactions plain-search serializer where semantics fit; remove the obsolete punctuation-stripping workaround. Preserve pagination and retry behavior, and ensure quotes/regex characters cannot alter the intended search. Add focused tests for Ethereum 2.0, MiniMax Group Inc., ordinary Lido and quoted payee names. Native acceptance: Ethereum detail loads its 11 transactions after fresh launch and Lido remains correct.

Blast radius: journalSearchFilter has one production caller, the merchant-detail screen, used for both initial and subsequent pages for all merchants. Main Transactions uses toPlainSearchFilter separately and its Mr. Marcel journey passed earlier in this run. The metadata/count and recurring preference controls remain available even when the journal fails. Empty, denied, expired-session, network-failure, long pagination, Android and physical-device states are not newly verified. The related suggestions hook is not a caller and is not claimed affected without its own repro.

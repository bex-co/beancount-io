# Dark-mode report chart labels retain light-theme colors

**Severity:** minor — dates, values and the active legend become difficult to read
in dark mode. **Estimate:** 45–60m, shared chart theme wiring and focused coverage.
**Pillar:** A2 — newcomers can read the public example's reports in their chosen appearance.

Reproduced 2026-09-08 on production, Chrome 152, English, authenticated reader
of synthetic `open_ledger/example`, source `a315c273`; deployed SHA unverified.
Desktop 1440×1000 and fresh narrow 390×844 repeats, Monthly / At Cost,
Time `2017-09`, no account or expression filter.

1. Open `/ledger/open_ledger/example/income-statement?time=2017-09`.
2. On desktop choose avatar → Theme → Dark, then reload the report.
3. Inspect the Net Profit chart: axis values, `2017-09` and the active `USD`
   legend remain dark gray against the dark page.
4. Repeat at narrow width after reload. The same colors and contrast remain.
5. Select Light and reload as the working control: the same text color is now
   readable against the white page.

During an actual canvas repaint, the affected text uses `12px sans-serif`,
fill `#54555a` (84,85,90). The transparent chart overlays the computed body
background `oklch(0.16 0.008 145)`, converted by the browser to sRGB (11,14,11).
Their contrast is **2.6102785341:1**, versus **7.4362594324:1** on the light
background (255,255,255). These are drawing/CSS colors, not anti-aliased edge
samples. W3C's normal-text readability threshold is 4.5:1; the finding is
specific to the selected dark appearance. [W3C contrast guidance](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

The financial read succeeds: authenticated GraphQL `getLedgerIncomeStatement`
with the same period/interval/conversion returns HTTP 200 and September 30
`netProfitData.balance` `{USD:"-2354.89",VACHR:"-5"}`. No browser errors in the
fresh repeat. CSV and Markdown exports preserve correct values, periods and
their documented sign conventions. The report's on-screen accounting signs
follow its existing inversion option and are not part of this finding.

Root cause in **dashboard**: `common/components/react-echarts/client.tsx:14,32,42`
receives an optional `theme` and calls `init(chartRef.current, theme)`; neither
the shared wrapper (`index.tsx:70–89`) nor production callers supply the app's
resolved theme. `income-statement/date-balance-chart/single-date-balance-chart.tsx:140–144`
passes only option/style/class, and `utils.ts:38–72` supplies axis formatters
without label colors. The provider changes the HTML class at
`common/providers/theme-provider/index.tsx:88–110`; that does not change canvas
text defaults. ECharts 6.0.0 is pinned in `dashboard/yarn.lock`; its dark theme
explicitly supplies axis and legend text colors. [ECharts 6.0.0 dark theme](https://github.com/apache/echarts/blob/6.0.0/src/theme/dark.ts)

Fix: default the shared chart rendering to the resolved application appearance,
while preserving an explicit caller theme. Make axis labels and active legend
text readable on the real surface in both modes, including initial hydration
and an in-page theme change. Preserve transparent/card backgrounds, existing
series meanings, lazy runtime loading, chart disposal, resize and ref behavior.
Audit explicit text-color overrides before assuming a default theme covers
every chart; do not alter financial data, APIs or generic number formatting.

Blast radius: 14 ReactECharts instances across 13 production component files:
report line/treemap/single/stacked charts; Overview income-expenses, net-worth,
Sankey and two distribution charts; two Cash Flow charts; Budget, Commodities
and BQL result charts. All omit `theme`. The account GLD chart independently
showed dim labels in dark mode, but exact contrast was measured on Income
Statement only. Audit shared callers without claiming every chart was measured.

Acceptance: the exercised axis/date/active-legend text reaches at least 4.5:1
in dark and light appearances on desktop/narrow; changing theme and reloading
both retain readable labels. Test real app-theme-to-chart wiring, not only
passing `theme="dark"` directly to a mocked renderer. Preserve empty/error
placeholders, explicit theme overrides and the existing chart lifecycle checks.

Dedupe: searched all open/completed board records for chart theme, dark mode
and contrast. `w2/done/m22` preserves theme switching in its DoD, but its
performance change `76b61b35` inherited the same optional-theme-only wiring
from `af5339de`; this is an uncovered pre-existing state, not a proven
performance regression. No overlapping open item or later source fix found.

Unverified: OS appearance transitions, all remaining chart types' contrast,
expired sessions, network failure and a patched build. Canvas instrumentation
was limited to one repaint and restored in `finally`; no API response or chart
data was replaced. No product fixes, production writes or shipping included.

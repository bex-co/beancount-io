**Minor · dashboard · 45–60m.** Regression in the download branch introduced by
completed [w2/m7](../w2/done/m7/README.md). A2: downloading a repository's
Makefile should produce a file that build tools recognize without renaming it.

## Root cause and bounded fix

dashboard/src/features/ledger-editor/shared/lib/utils.ts:198–199 assigns
text/plain to recognized basenames. downloadFile at 264–276 makes a Blob with
that MIME and sets the suggested filename. Chrome supplies a preferred extension
when a suggested name has no extension. The source for the actual browser version
was read: [Chromium 152 filename handling](https://chromium.googlesource.com/chromium/src/+/152.0.7977.77/net/base/filename_util_internal.cc),
GetCorrectedExtensionUnsafe and EnsureSafeExtension; its separate
SanitizeGeneratedFileName trims leading dots. The [HTML download algorithm](https://html.spec.whatwg.org/multipage/links.html#downloading-resources)
allows MIME-based filename adjustment. This is the dashboard choosing a download
representation that changes a meaningful repository filename.

Choose a download-specific MIME for recognized extensionless text basenames
that preserves Makefile, LICENSE and Dockerfile names while retaining their
original bytes. The measured application/octet-stream Blob control is a working
candidate. Keep text classification, Monaco language and preview MIME behavior
from w2/m7; do not globally change getMimeTypeFromExtension or remove the text
allowlist. No browser-sanitization bypass, ZIP redesign, or API change is needed.

Exactly four production callers use downloadFile: file-view-mode.tsx:25 for
text, and non-text-file-views.tsx:214,291,347 for image/PDF/unknown files.
FileContentView selects those paths. Limit the behavioral change to the affected
text downloads, and retain ordinary .bean/.beancount/.md/.txt names, non-ASCII
bytes, and the existing image/PDF/unknown-file paths. Empty content, denied
reads and failed reads must not create a misleading successful download.

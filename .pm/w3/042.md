# Escape in file Find cancels edit mode instead of closing Find

Severity: **minor**. Owner: **dashboard**. Estimate: **35–50 minutes**.
A2: standard editor search shortcuts should let a user find a location and
continue editing without unexpectedly leaving the editor.

Production `https://beancount.io`, 2026-09-08, Chrome152, English, System/light;
desktop1440×1000 and fresh390×844. Public synthetic
`open_ledger/budgeting-envelopes/accounts.bean`; authenticated QA reader.
Local `a315c273`, fetched main `cc3f4c2f`, deployed SHA unverified. The implicated
file editor is unchanged on fetched main. Edit mode was entered through the
separate040 UI defect; the same handler has no role branch. Authorized-writer
coverage is required during implementation and was not live-tested here.

1. Open `/ledger/open_ledger/budgeting-envelopes/files/blob/main/accounts.bean?editMode=true`.
   Leave the file contents unchanged.
2. Focus the editor, press **Cmd+F**, and search **Expenses**. The Find / Replace
   widget has a **Close (Escape)** button and finds eight matches.
3. With the Find input focused, press **Escape**.
4. Wait for navigation and the normal More actions toolbar to settle.
   The URL loses `editMode=true`, the actual editor switches to read-only,
   and **Find remains open**. A fresh narrow journey reproduces this exactly.

Expected: Escape closes Find, returns focus to the editor and preserves edit
mode, contents and selection. The widget explicitly advertises that shortcut.

Working controls: clicking Find's Close button hides it while preserving
`editMode=true` and `readOnly:false`. In ordinary read-only mode, Escape also
closes Find correctly without changing the route. The reproduced failure needs
no dirty draft: the buffer remains1659 UTF-16 code units throughout. This is
independent of041's premature discard after a deliberate Cancel.

Root cause: `dashboard/src/features/ledger-editor/file-editor/components/ledger-file-view/text-editor.tsx:76–112`
installs a document listener in the capture phase. When editing, **every Escape**
calls `preventDefault`, `stopPropagation`, and `onCancel`, without checking
editor/widget focus or allowing Find to handle the event. TextFileView passes
its file-level cancel callback at162–169; that callback exits the edit URL.
Read-only mode returns before this interception, explaining its working control.

The locked Monaco **0.55.1** implementation confirms the intended inner action:
`esm/vs/editor/contrib/find/browser/findController.js:841–849` binds Escape to
CloseFindWidget while the Find widget is visible. `closeFindWidget` hides it
and focuses the editor at163–168. The widget's Close button uses the same action
label at `findWidget.js:889–897`. Its published package was inspected under
ignored scratch space; no dependency was installed or changed.

Fix the file-level shortcut's scope so editor widgets receive their own Escape
first. Prefer Monaco's existing context-aware command handling, or an equivalent
guard that only cancels the file when the intended editor context owns the key;
do not duplicate Monaco's Find implementation. Preserve deliberate Cancel and
Escape from the plain editor body, with041's draft-preservation contract. Do
not allow a document-level handler to swallow Escape from an open dialog/menu.

Blast radius: TextEditor has one product caller, TextFileView, shared by text
blob previews. Other Monaco users such as BQL and EntryContextDialog do not
import this handler. Only Find was reproduced; other editor widgets must not be
claimed affected without their own checks.

Acceptance: mount the actual editor/route interaction or run a browser test.
With Find focused, Escape closes only Find and leaves the same edit route and
buffer; the Close button and read-only search still work. Include a plain-editor
cancel control and a dirty-buffer Find control to ensure searching never
discards a draft. Run dashboard format, lint, tests and build.

Dedupe: searched all open/completed `.pm` for Find widgets, Escape, editor
shortcuts and edit cancellation, and checked open milestone summaries.040 gates
permissions;041 fixes the discard transition after Cancel has actually been
chosen. Fixing either alone leaves this incorrect event interception intact.
m12 is BQL execution, and w2/m7 is file-type support. Targeted `git log -S`
traces this Escape listener to `af5339de`; fetched main has no repair.

No file edits or writes occurred in this comparison, and no application page
errors occurred in the monitored fresh repeat; the only background request was
GetCurrentUser. Both Find widgets were closed using their working button and
the ordinary read-only page restored. Other OS shortcuts, locales and actual
writer persistence remain unverified.

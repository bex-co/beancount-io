# `bea doctor parse` exits 0 on syntax-invalid ledgers that `bea check` rejects

**Severity:** minor. **Estimate:** 25–40 minutes. **Owner:** cli. **A1:** a CI
or agent gate using `bea doctor parse` gets exit **0** on truncated/invalid
syntax while `bea check` exits **1**.

Found 2026-09-16 by continuous CLI QA ([c870 hunt](bbf53c50-27f4-48bc-b334-cece81e345f8)),
HEAD `7138997c`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Confirmed
`cli/tmp/qa-20260915/c871/`. Evidence: `c870/`.

## Repro

```sh
printf '2020-01-01 open\n' > half.bean
bea --file half.bean check
# exit 1 — syntax error, unexpected EOL, expecting ACCOUNT

bea doctor parse half.bean
# exit 0 — yacc recovery noise on stderr, no failure status
```

## Expected

`doctor parse` exits nonzero on unparseable input, or USAGE documents it as a
debug trace only (not a validity gate). Prefer exit **1** when recovery ran.

## Actual

`doctor.py` forwards bean-doctor’s exit unchanged; upstream parse recovers and
returns 0. `bea check` / bean-check exits 1 on the same file.

## Fix

Map parse/syntax failure to exit 1 after `doctor parse` (or document + warn).
Regression: `half.bean` exits 1; valid ledger stays 0; `check` unchanged.

## Dedupe

Not w3/312 (JSON refusal). Not w3/273 (format `--check` on invalid text). No
open note covers doctor parse/lex false-green vs check.

## Objective

Make configuration consume only validated transaction values, with no silent substitution of today's date or fallback zero.

## Context

Read the parent milestone for exact production evidence, source trace, working
controls and limits. Follow dashboard and importer guidance. This is the sole
implementation queue for promoted038 and its reproduced error-loss extension.

## Steps

1. Remove dateResult.date || new Date() as a recovery for invalid imported dates. Validate the selected row boundary and retain actionable diagnostics for excluded input.

2. Keep the existing mixed-validity behavior: valid rows may proceed with an accurate skip warning, while rejected rows remain repairable in Preview. Never treat a missing parse result as a valid zero; preserve literal zero.

3. Verify unchanged valid dates and amounts through configuration and Back. Preserve account/currency mapping and039's separately owned sign contract; do not add a second parser or make a production import.

## Acceptance criteria

- [ ] Untouched or unrelated-edited invalid rows never acquire today's date or a valid fallback amount.
- [ ] Only the valid control row configures until the real date/amount are repaired; repaired values pass unchanged.
- [ ] Back and re-entry preserve accurate validity and the existing valid-row selection semantics.

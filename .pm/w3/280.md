# `bea import --csv auto` ignores a bare `id` / `ID` column (FitId works; content-hash IDs used instead)

**Severity:** minor. **Estimate:** 15–25 minutes. **Owner:** cli. **A1:** bank
CSVs whose stable identifier column is literally `id` or `ID` (very common)
never get `bank_id` / `bank:…` dedupe under header inference; rows fall back to
`csv:sha256:…` hashes, so same-ID duplicates across exports are weaker
possible-duplicates instead of exact skips — while `FitId` and
`transaction_id` infer correctly, and `id=ID` works when typed by hand.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `d5ff10f7`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
printf '%s\n' 'Date,Description,Amount,ID' \
  '2024-03-10,Cafe,-4.50,txn-1' \
  '2024-03-11,Cafe2,-5.00,txn-2' > id.csv

bea --json --file main.bean import id.csv --csv auto --account Assets:Bank:Checking
# config: date=Date,amount=Amount,narration=Description   ← no id=
# entries use import-id: "csv:sha256:…" only — no bank_id

printf '%s\n' 'Date,Description,Amount,id' \
  '2024-03-10,Cafe,-4.50,txn-1' > idlower.csv
bea --json --file main.bean import idlower.csv --csv auto --account Assets:Bank:Checking
# same — bare "id" still omitted

# Control — FitId synonym and explicit map both work:
printf '%s\n' 'Date,Description,Amount,FitId' '2024-03-10,Cafe,-4.50,txn-1' > fit.csv
bea --json --file main.bean import fit.csv --csv auto --account Assets:Bank:Checking
# config includes id=FitId; entry has bank_id + import-id: "bank:txn-1"

bea --json --file main.bean import id.csv \
  --csv date=Date,amount=Amount,narration=Description,id=ID \
  --account Assets:Bank:Checking
# bank_id / bank:txn-* as expected
```

## Expected

Header inference treats `id` / `ID` (case-insensitive) as the `id` role, matching
`IMPORTING.md` (“An `id` column becomes `bank_id` metadata”) and the other
id synonyms already listed (`fitid`, `transaction_id`, …).

## Actual

`_HEADER_SYNONYMS["id"]` is only
`("transaction id", "transaction_id", "reference number", "fitid")` — it does
not include the role name `id` itself, so a column named `id`/`ID` is skipped.

## Fix

Add `"id"` (and optionally `"txn id"`, `"txnid"`, `"bank id"`) to the `id`
synonym tuple in `csv_mapper.py`. Regression: the `ID` / `id` fixtures above
infer `id=…` and write `bank_id` + `bank:` import-ids; FitId and explicit
`id=` controls stay green.

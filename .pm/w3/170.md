# Auth next guard accepts a tab-obfuscated external redirect

**Major · dashboard · 40–55m.** A2/A3: authentication continuation links must remain on the application origin.

In an existing QA session, open `/auth/login?next=%2F%09%2Fqa-redirect.invalid%2Fprobe`. Production returns HTTP307 with Location containing slash, a literal horizontal tab, slash, then `qa-redirect.invalid/probe`. Chrome resolves this as `https://qa-redirect.invalid/probe`, leaving the application. Repeat with `/auth/sign-up` yields the same result. No password or OTP submission is required for an existing session. An attacker-controlled continuation link can redirect an authenticated visitor to an unrelated site; this proves an open redirect, not credential theft or token leakage.

Reproduced September11,2026 on https://beancount.io in fresh isolated headless Chrome152.0.7977.83 contexts, desktop1440×1000 and narrow390×844, English/light, QA GROWTH session. The reserved .invalid destination was intercepted with a local HTML response. Browser navigation initially reports ERR_NAME_NOT_RESOLVED for the HTTP redirect chain, then the intercepted navigation settles at the external origin with “QA intercepted destination”; do not claim a real remote website loaded. Independent read-only requests with redirect following disabled confirm the actual production307 and exact Location for both routes. Signed-out controls return200/noLocation. Safe public-ledger next works; plain protocol-relative `//qa-redirect.invalid/probe` is rejected. The newline variant returns the application's Invalid URL Parameters500 instead of navigating; it is not evidence of an external redirect.

# `bea doctor region` balance tree mis-reports fractions when later postings lack decimals

**Severity:** minor. **Estimate:** 30–60 minutes. **Owner:** cli. **A1:**
`doctor region` on a `5.50 USD` coffee shows `-6 USD` / `6 USD` in the balance
tree when a later posting uses `100 USD` (no decimal), while `Net Income`
stays `-5.50 USD`.

Found 2026-09-16 by continuous CLI QA ([c940 hunt](86942cc6-e772-46a9-a761-22e91c5cff60)),
HEAD `c4675837`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Confirmed
`cli/tmp/qa-20260915/c943/`. Evidence: `c940/`.

## Repro

```sh
# Coffee 5.50; later txn "100 USD" without decimals
bea doctor region main.bean 8:10
# tree: Checking -6 USD, Food 6 USD; Net Income: (-5.50 USD)

# control: later amounts as 100.00 USD → tree shows -5.50 / 5.50
```

## Expected

Region balance tree matches the region’s postings (and Net Income), independent
of later amount literal formatting.

## Actual

Later whole-number amount tokens poison tree formatting precision for earlier
regions; Net Income stays exact.

## Fix

Upstream `bean-doctor region` (or bea wrapper) format tree from the region’s
own amounts. Regression: repro shows `-5.50` / `5.50`.

## Dedupe

No open w3 note on `doctor region` balance display. Not w3/312 (JSON refusal).

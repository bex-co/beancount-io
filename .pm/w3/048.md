# An empty Overview filter result claims the whole ledger has no activity

Severity: **minor**. Owner: **dashboard**. Estimate: **25–40 minutes**.
A2: a reader exploring an example's dates should understand an empty selection
and be able to recover without mistaking a populated ledger for an unused one.

Production `https://beancount.io`, 2026-09-08, Chrome 152, English,
System/light; authenticated QA reader of public synthetic `open_ledger/crypto-example`.
Desktop 1440×1000 and fresh 390×844. Local HEAD `a315c273`, fetched main
`cc3f4c2f`; implicated Overview code unchanged there. Deployed SHA unverified.

1. Fresh-open `/ledger/open_ledger/crypto-example?time=2020`.
2. After loading, Overview says **Empty ledger** and **This ledger has no
   activity yet. You can view its accounts, journal, or source file.**
   It offers Accounts, Journal and Files links, with no selection-specific
   explanation. Once its separate header attributes finish loading, desktop
   correctly shows Time 2020 and Clear all above the misleading message.
3. Reload at 1440×1000, then fresh-load at 390×844. Both show the same message.
4. Open `/ledger/open_ledger/crypto-example` as a fresh document without the
   filter. Financial position and the other modules appear; Net Worth shows
   **114,581.88 USD**. Fresh unfiltered Journal has **68 transactions**.
   The settled desktop header's Clear all also restores populated Overview
   in place and removes time from its URL.

Separate authenticated GraphQL reads with `conversion:"at_cost"` and
`interval:"monthly"` both return HTTP 200 without GraphQL errors. With
`time:"2020"`, the response contains twelve 2020 monthly net-worth points
with empty balances and no matching activity. Without time, it has fourteen
points from January 2024 through February 2025; the final balance is
`{USD:"114581.879925"}`. REST
`/api-gateway/v1/ledgers/open_ledger/crypto-example/overview?time=2020&conversion=at_cost&interval=monthly`
also returns 200 and the same empty selected-period data. The service is
correctly filtering this populated ledger.

No page errors occurred in the monitored fresh desktop run. Its browser
response monitor saw no GetLedgerOverview response: the Overview route loader
prefetches the query and the component uses that cached result. The reads
above are explicit API controls, not mislabeled captures of UI requests.

Expected: when account/filter/time is active and the settled result has no
activity, describe **no activity for the current filters**. Retain the working
desktop Clear all behavior and the existing empty-ledger setup for a truly
unfiltered empty ledger, including the separate reader/writer permission
behavior. Responsive access to the shared header controls belongs to promoted
004/m20; do not duplicate that implementation here.

Root cause: `dashboard/src/features/reports/overview/index.tsx:80–87` requests
the selected account/filter/time; at 136 it calls `hasOverviewActivity` on
that filtered result. At 409–421, every false result renders EmptyLedgerSetup
without considering filter context. `lib/overview-utils.ts:91–125` intentionally
detects whether the supplied series/hierarchies have activity; it cannot prove
the entire ledger is empty. Running that unchanged helper against both real
API controls returns false for 2020 and true unfiltered. Its zero-filled
response and nested-activity tests describe valid behavior and should remain.
`components/empty-ledger-setup.tsx:31–62` supplies the misleading reader copy;
the writer branch also assumes a first-time setup but was not exercised live.

Fix the Overview branch and localized empty-result presentation. Do not change
financial aggregation or issue an unfiltered report request merely to relabel
an active filter result. Keep pending and failed requests distinct from
successful empty results. Preserve existing filter actions and coordinate with
m15's router/filter work and m20's responsive controls.

Producer trace: gateway finance resolver at 171–220 forwards selectors to
LedgerFinanceService and maps the report data. Ledger `src/api/reports.ts:287–297`
passes those selectors to `features/ledger/service/ledger-finance-service.ts:68–127`,
which derives the selected series and account hierarchies. No API change is
needed. `hasOverviewActivity` and EmptyLedgerSetup each have one production
caller in Overview, reached through the ledger index route.

Cover account/filter/time contexts, genuinely unfiltered

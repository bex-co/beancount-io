# Open Account validation remains English in localized forms

**Severity:** minor. **Owner:** dashboard. **Estimate:** 35–50 minutes.
**A2:** users can understand and correct an account-name error in their
selected interface language.

Production `https://beancount.io`, 2026-09-08, Chrome 152, light theme.
Existing QA session, public `open_ledger/minimax`, English/Chinese/French,
1440×1000 and390×844. Local HEAD `a315c273`, fetched main `afb36a9b`, relevant
sources unchanged. Deployed SHA unverified. All inputs are synthetic local
drafts; no account creation or other mutation was attempted.

1. Open Journal's New Entry → Account form, for example
   `/ledger/open_ledger/minimax/journal?lang=zh&action=new-entry&directive=account`.
2. Enter **Checking** and move focus out. Despite the Chinese interface,
   validation says **Account must start with one of: Assets, Liabilities,
   Equity, Income, Expenses**.
3. Clear the field. Validation says **Account name is required**, also in
   English. The corresponding French form has the same two English errors.
4. Fresh repeats confirm both messages at both widths. Invalid inputs disable
   submission correctly; **Assets:QaLocaleDraft** clears the errors and enables
   the button. Do not submit it. English is the baseline control.
5. Accounts → Open Account provides a useful comparison: both messages are
   translated in Chinese. In French its required-name message is translated,
   but the prefix warning is also English. This is a second missing step in
   the same validation-localization repair, not a fully passing French control.

Expected: the explanatory sentence follows the interface language. The ledger's
actual account prefixes remain literal values; translating those identifiers
would instruct the user to enter the wrong account name.

Root: `features/journal/components/new-directive-dialog/open-account-form.tsx:55–72`
hardcodes both sentences in its Zod schema, including the no-options fallback.
It already has `useTranslations`, but the schema does not use it. The prefix
list comes from `GetLedger.options` at40–52; the query explicitly requests all
five configured account-type names in `graphql/query/ledger.graphql:111–115`.
There is no missing server field or malformed prefix data in these cases.

Reuse `page.accounts.accountNameRequired` and
`page.accounts.accountMustStartWith`, passing the existing prefix list through
the established translation interpolation. Include the active translator in
the schema's dependencies without resetting the user's form. The working
Accounts implementation is at `ledger-data/accounts/open-account-dialog.tsx:90–98`.
Keep the same required/prefix rules, validation timing, date handling, write
permission and serialized account name; no API/schema/SDK change is needed.

Also finish three existing locale values found by auditing these two keys
across all15 supported catalogs: `accountMustStartWith` is still copied English
in `accounts/locales/fr.ts:12` and `ca.ts:12`; `accountNameRequired` is still
copied English in `uk.ts:20`. Translate those values and preserve their existing
interpolation tokens. The other values already contain localized messages.
The Catalog→`extractMessages`→`useTranslations` path preserves these literal
messages, so changing only Journal's call site would leave the French warning
reproduced here unchanged. Catalan/Ukrainian are source-traced, not live-tested.

Blast radius: Journal's `NewDirectiveDialog` has one `OpenAccountForm` placement
at `new-directive-dialog/index.tsx:100–105`, selected by the Account tab or
supported action link. Both account-entry forms consume the shared validation
keys after this repair. Other untranslated labels noticed in the French form,
such as Open Date, are outside this two-message finding; do not turn this into
a blanket translation rewrite or introduce duplicate validation keys.

Acceptance: Chinese and French Journal forms render localized required/prefix
errors, and the French Accounts prefix warning is localized. English still
works; valid configured-prefix input still clears errors and invalid input
still blocks submission. A meaningful form regression exercises these states
and interpolation; keep locale-key parity and the existing translation gates.
The current completeness detector rejects `[TODO]` markers, so merely passing
that gate does not verify the three copied-English values. Run dashboard gates
when implementing. Actual creation and locale changes during an open draft
were not exercised in this QA pass.

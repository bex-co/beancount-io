# `bea query --source` with a bad URI scheme dumps a raw bean-query traceback

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** cli. **A1:** an
agent that guesses a source URI (`bean:…`, `file:…`) from the `--source`
help (“Native Beanquery source URI”) gets an uncaught `ModuleNotFoundError`
traceback from the managed `bean-query` binary instead of a usage error that
names the valid scheme(s).

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `720b006e`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
bea query --source "bean:$PWD/main.bean" 'SELECT count(*) FROM accounts'
# exit 1
# Traceback (most recent call last):
#   … bean-query …
# ModuleNotFoundError: No module named 'beanquery.sources.bean'

bea query --source "file:$PWD/main.bean" 'SELECT count(*) FROM accounts'
# exit 1 — same class of traceback for beanquery.sources.file
```

Working controls:

```sh
bea query --source "beancount:$PWD/main.bean" 'SELECT count(*) FROM accounts'
# exit 0 (text table)

bea query --source "$PWD/main.bean" 'SELECT count(*) FROM accounts'
# exit 0 — path without scheme also works

bea --json query --source 'bean:x' 'SELECT 1'
# exit 2 — refuses --json with --source (separate, clearer usage path)
```

## Expected

Exit 2 (usage/validation) with a short message that `--source` must be a
Beanquery URI using a supported scheme (at least `beancount:…` / bare path),
without leaking engine site-packages frames. Optionally list schemes from
`beanquery.sources` discovery.

## Actual

`--source` is forwarded to `bean-query`; an unknown scheme triggers
`importlib.import_module(f'beanquery.sources.{scheme}')` and the exception
propagates as a raw traceback on stderr with exit 1. Help text does not name
the working `beancount:` scheme.

## Fix

Validate the URI before/after the native call: on `ModuleNotFoundError` /
nonzero native status with traceback, map to `UsageError` naming
`beancount:<path>` (and bare path). Keep successful `beancount:` and bare-path
controls unchanged. Regression: `bean:` and `file:` repros exit 2 with no
traceback; `beancount:` still exits 0.

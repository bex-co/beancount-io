# Narrow account reports hide interval and valuation selectors

Severity: **minor**. Owner: **dashboard**. Estimate: **30–45 minutes**.
A2: readers exploring an account on a phone should be able to choose its
reporting interval and inspect commodity units using the existing controls.

Production `https://beancount.io`, 2026-09-08, Chrome 152, English,
System/light; authenticated QA reader of public synthetic
`open_ledger/crypto-example`. Desktop 1440×1000 and fresh 390×844.
Local HEAD `a315c273`, fetched main `cc3f4c2f`, deployed SHA unverified.
The account page has no newer source correction on fetched main.

1. Open `/ledger/open_ledger/crypto-example/account/Assets%3ACrypto%3ACoinbase%3ABTC`
   on desktop, with no Time, Account or expression filters.
2. The chart toolbar provides Monthly and At Cost selectors. Change At Cost
   to **Units**, then Monthly to **Quarterly**. Both work: account-report reads
   return HTTP200 with the chosen conversion/interval; the latest balance is
   **0.18 BTC**, and the quarterly chart has five period-end values.
3. Resize to390×844. Both selectors disappear, leaving only **View**.
4. Fresh-load the same URL at390×844. The page returns to its Monthly / At Cost
   defaults but exposes neither value nor control. View offers only
   **Account Balance** and **Changes Over Time**. Switching between those views
   and opening the mobile sidebar reveals no interval/valuation alternative.
5. Another fresh narrow load reproduces it, with HTTP200 account report/journal
   responses, `interval:"monthly"`, `conversion:"at_cost"`, and no page errors.

Expected: both report choices remain visible and operable on narrow screens,
using a wrapping/stacked toolbar or an accessible compact control. The current
values must be inspectable. Users should not need to widen the browser to view
BTC units or change from monthly grouping. This is a populated report; default
rendering and data retrieval work.

Root cause: `dashboard/src/features/reports/account/index.tsx:388–398` wraps
the only IntervalSelect and ConversionSelect in `hidden sm:flex`. The parent
at382 does not provide a narrow replacement. The separate View selector only
renders the two `tabOptions` at292–298, through
`common/components/responsive-tab-trigger-list/index.tsx:37–51`.
The initial state is Monthly / At Cost (`account/constants.ts:7–8`);
the selected values feed GetLedgerAccountReport at315–316 and conversion also
feeds AccountJournalTable at460. This is CSS visibility, not a missing API.

Fix the account toolbar's responsive layout using the existing selectors and
local state; keep both choices available with meaningful accessible names and
without horizontal page overflow. Do not create a second query path, duplicate
selection state or modify conversion arithmetic. Preserve View selection and
the current values while resizing. A deliberate fresh-load default is not
reported as a persistence defect.

Working controls: at the same390px width, the public crypto Balance Sheet
provides View, Monthly and At Cost; its Units option is selectable and was
restored to At Cost. Its toolbar keeps the shared selectors in a wrapping flex
container at `reports/balance-sheet/balance-sheet-content.tsx:196–207`.
Source searches also found these shared primitives in Income Statement, Cash
Flow and Trial Balance, whose callers do not use this account-only hidden
wrapper. Only the account route and its two chart views are implicated here;
do not change the shared selector to repair its caller's visibility.

Acceptance: at390px, choose Units and Quarterly on the actual account page,
verify matching report requests and the0.18BTC ending balance, then return to
At Cost / Monthly. Both chart views retain usable controls, and resizing to
desktop and back keeps their selected values. Use a browser/layout check that
evaluates actual visibility and keyboard activation; jsdom class snapshots
cannot prove responsive reachability. Check a narrower layout and normal
loading/error behavior during implementation, and run dashboard checks.

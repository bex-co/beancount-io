# Mobile transaction search rejects punctuation in existing merchant names

**Severity:** minor. **Owner:** mobile. **Estimate:** 50–60 minutes.
**A2:** newcomers can find a transaction by typing the merchant name shown in the app.

Environment: 2026-09-08, production https://beancount.io API, local mobile HEAD
`a623f745`, native `io.beancount.ios` 1.20260906.47 on iPhone 17e / iOS 26.5,
390×844 logical points, English/light. Authenticated reader of public synthetic
`open_ledger/example`; no ledger writes. Native OAuth session survives relaunch.

Repro (actual tab navigation, no deep link):
1. Select the public example ledger and open Transactions. Reset and Apply any
   filters, clear Search, and type `Mr. Marcel` using the native search field.
2. Wait for the debounced request. The list disappears and reads
   `Failed to load transactions: Illegal character "."`.
3. Terminate and relaunch the app, return to Transactions, clear the field and
   repeat the exact name. The same settled error appears.
4. Clear and type `Marcel`: all six matching transactions appear, followed by
   No more entries. The latest is April 19, 2016, $32.01.

Expected: typing the displayed merchant name finds its transactions without
requiring knowledge of the advanced filter language. Actual: an ordinary period
is interpreted as unsupported syntax. This is an error response, not empty data.

Read-only GraphQL control: GetLedgerJournal with ledgerId `open_ledger/example`,
query `{offset:0,limit:20,directiveTypes:["Transaction"],filter:"Mr. Marcel"}`
returns HTTP200 with GraphQL error `Illegal character "."`. Using `Marcel`, or
surrounding the full name with double quotes inside the filter string, returns
`total:6` and six `Mr. Marcel` entries dated 2016-04-19, 2016-04-15,
2015-09-13, 2015-09-12, 2015-09-10 and 2015-09-08.

Root cause: `mobile/src/screens/transactions-screen/transactions-screen.tsx:103`
trims/debounces Search and at104 assigns it directly to `filter`; initial and
pagination requests reuse it at123/158. `TransactionsHeader` labels this field
Search. The GraphQL resolver delegates at
`backend-cluster/backend-v2/src/features/ledger/api/resolvers/ledger-journal-resolver.query.ts:158`;
`service/ledger-journal-service.ts:162` forwards query.filter unchanged.
`backend-cluster/ledger/src/foundation/rustledger/directive-filter.ts:95` invokes
advanced filtering; the bare STRING lexer rule at296 excludes periods and lex
throws at336. The quoted STRING rule accepts the name. Journal service at473
maps that parser failure to BadUserInputError. This is the documented advanced
filter contract; the mobile consumer treats it as plain search.

Fix: serialize ordinary mobile search text into a safe literal search expression
before both initial and fetchMore requests, preserving punctuation and escaping
regex metacharacters and quote delimiters according to the existing parser.
Keep the original text visible, omit the filter for empty/whitespace input, and
retain account/status/date composition and server-side pagination. Do not strip
periods and broaden results, or relax the shared advanced-filter API used by
other clients. Cover names containing periods, apostrophes and both quote kinds
at the serializer boundary; those additional native cases are not claimed here.

Blast radius: the sole TransactionsScreen route is
`mobile/app/(app)/(tabs)/transactions.tsx`. Both its initial page and fetchMore
use the same filter variable. Caller search also found merchant detail's separate
`journalSearchFilter` workaround (`selectors/filter-exact-payee.ts:19`) and raw
payee forwarding in `use-two-posting-suggestions.ts:36`; their live behavior is
not established by this finding and they should not be silently swept into it.
Hoogle and Chichipotle searches work. Hoogle + checking account gives71 results;
adding the current 1M date range gives zero in UI/API. Reset+Cancel preserves
applied filters; Reset+Apply removes them. These are working composition controls.

Acceptance: exact native `Mr. Marcel` search returns those six rows after relaunch;
clear restores the list; initial and subsequent pages use the same encoded needle.
Use meaningful serializer/request-variable tests for punctuation, empty input and
filter composition. Preserve skeletons during first load, honest settled empty
results and genuine network-error handling. Offline, expired-session, Android,
physical-device input and paging to the last page were not exercised here.

Dedupe: searched all open/completed .pm records for punctuation, Mr. Marcel,
Illegal character, FilterParse, merchant/search and plain-text search, and scanned
open milestone headings across queues. No overlapping item. w3/017 concerns
merchant posting counts. Targeted git log -S traces raw Transactions search to
`69001418` and the independent merchant workaround to `2b36b2cc`; latest local
source retains the defect. No known prior working state establishes a regression.

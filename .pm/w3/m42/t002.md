## Objective

Make every date input tell the user the ordering actually in force, in their language, and remove the hardcoded literals.

## Context

- Hardcoded today: `features/journal/components/new-directive-dialog/transaction-form.tsx:331` and `features/receipt/components/receipt-review-form.tsx:161`. Grep for other `DatePicker` call sites — those two are only the ones that pass a literal placeholder.
- `MM/DD/YYYY` is currently exempted in `src/test/no-untranslated-user-facing-strings.test.ts:57` under `INTENTIONAL_LITERALS`. Remove that entry as part of this task; the remaining members of that set (`BQL`, `HTTP`, `KB`, `SSH`, `USD`, `Esc`) genuinely are invariant and stay.
- Prefer deriving the hint from the t001 pattern over adding 15 translated literals — a derived hint cannot drift from the parser, which is what caused this defect in the first place.
- Mention the ISO form somewhere discoverable, since it is always accepted.

## Steps

1. Derive the hint from the active pattern and pass it from the shared picker rather than each call site.
2. Remove both hardcoded placeholders.
3. Remove `MM/DD/YYYY` from `INTENTIONAL_LITERALS` and run that test.
4. Add locale keys only for text that is genuinely prose, not for the pattern itself.

# `bea ingest` with a `CONFIG = […]` import file exits 0 and prints nothing

**Severity:** minor. **Estimate:** 25–40 minutes. **Owner:** cli. **A1:** an
agent that points `bea ingest identify|extract|archive --config` at the same
`CONFIG = [importer, …]` module that `bea import --config` accepts (including
`docs/examples/csv_importers.py`) gets exit 0 and empty stdout/stderr — looks
like “no matches” / success — instead of a usage error that the script must
call `beangulp.Ingest(...)()` (or that they meant `bea import`).

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `6fd96161`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only. Evidence: `cli/tmp/qa-20260915/c598/`. Extended 2026-09-16 for
`ingest archive` ([c1140 hunt](9be84ee7-e73e-48d9-b493-117cd6fb4680)), HEAD
`6be1ba9b`; evidence `c1140/`.

## Repro

```sh
# docs/examples/csv_importers.py exports CONFIG = [CategorizedCSV()] — the
# bea import --config shape; it never calls beangulp.Ingest(...)().

cat > bank.csv <<'EOF'
Date,Payee,Narration,Amount,Currency,Category,BankID
2020-01-15,Coffee Shop,Latte,-12.50,USD,Expenses:Food,id-1
EOF

bea ingest identify --config docs/examples/csv_importers.py bank.csv
echo exit=$?
# exit 0; stdout empty; stderr empty

bea ingest extract --config docs/examples/csv_importers.py bank.csv
echo exit=$?
# exit 0; stdout empty; stderr empty

bea ingest archive --config docs/examples/csv_importers.py
# exit 0; empty (also empty when SRC is /nonexistent.csv)

# Same module works for import:
bea --file main.bean import bank.csv --config docs/examples/csv_importers.py
# preview rows; exit 0
```

Working control (Ingest entrypoint):

```sh
# ingest.py ends with: beangulp.Ingest([Dummy()])()
bea ingest identify --config ingest.py bank.csv
# "* …/bank.csv ... OK" / importer name; exit 0
# archive with missing SRC → exit 2 (path does not exist)
```

## Expected

Refuse a script that does not run the Beangulp CLI entrypoint: exit **2**
(usage), name that `bea ingest` needs `beangulp.Ingest(...)()` (as the missing-
script hint already says), and point agents at `bea import --config` for
`CONFIG = […]` modules. Do not report success with blank output — including
`archive`.

## Actual

`cli/commands/ingest.py` `_forward` → `launch.run_optional_script` spawns
`engine_python script.py identify|extract|archive …`. A CONFIG-only module
loads, defines `CONFIG`, ignores argv, and exits 0. No check that Ingest
handled the subcommand.

## Fix

After the child exits 0 with empty output (or via a lightweight preflight that
the script’s `__main__` invokes Ingest), raise a bea usage error distinguishing
CONFIG-style import files from ingest scripts. Regression: identify/extract/
archive repros exit 2 with that hint; a real `Ingest(...)()` script still
works; `bea import --config` on the same file unchanged.

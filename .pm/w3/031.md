# Budget cards hide actual and variance when the latest interval has zero activity

Severity: minor. Owner: dashboard. Estimate: 25–40 minutes. A1/A2: a reader
checking a spending target can distinguish zero activity from unavailable data
and see how far below the target that period is.

Environment: production https://beancount.io, Chrome 152, English, System/light,
1440×1000 and fresh 390×844 repeat, 2026-09-08. Authenticated QA reader of public
synthetic `open_ledger/budgeting-envelopes`; pull true, admin/push false. Source
HEAD a315c273; fetched origin/main cc3f4c2f has no matching correction. The
deployed build is not proven identical to local HEAD.

Reproduce:

1. Open `/ledger/open_ledger/budgeting-envelopes/budget?lang=en`, leave All time
   selected, and search Rent. One of seven budget groups remains.
2. Its card shows Current budget 1,650 USD, but no Latest actual, Variance,
   target-status badge or progress track. The chart contains January, February
   and March 2026. Hover March: the tooltip says Budget 1,650 USD, Actual 0 USD.
3. Reload at narrow width and search Rent again; the same summaries are absent.
4. Working control: search Insurance. Its March card shows Latest actual
   600 USD and Above target / +500 USD against the 100 USD budget.

Expected: a returned interval with zero units of the budget currency displays
0 USD actual and the corresponding -1,650 USD / Below target comparison for
Rent. An absent result, failed request or malformed amount remains distinct
from a valid sparse zero balance.

The actual browser GetLedgerIntervalTotals response is HTTP 200 with three
Rent intervals: January and February each have `balance: {USD: "1650"}`;
March 31 has `balance: {}` and `accountBalances: {}`. An independent read
returns the same data. The public journal has no March Rent posting. No page
errors occurred during the fresh repeat, and all seven budget directives load.

Root cause: `dashboard/src/features/ledger-data/budget/budget-chart-card.tsx`
lines 110–119 treats a missing currency in the last interval as null. That
suppresses variance at 132–135 and the summary block at 305. The same component's
chart conversion at 169–175 correctly treats an absent currency as zero.
Upstream, ledger `foundation/rustledger/interval-series.ts:214–228` deliberately
drops zero currencies when serializing inventories; `intervalTotals` still
returns every interval. Gateway `ledger-data-service.ts:367–386` delegates the
read and its resolver at 562–587 forwards balance without changing that shape.
The API's sparse inventory representation is expected and need not change.

Fix the dashboard's latest-period amount interpretation to agree with its chart
for a valid returned interval. Preserve the separate no-series/error/invalid
amount states, the chosen currency, income-budget sign handling and the
historically active target. This component is the sole dashboard budget-card
consumer; mobile uses its own implementation and is not part of this filing.

Acceptance: a realistic multi-period response ending with an empty balance map
renders zero actual, negative expense variance and Below target; explicit zero
and a missing selected currency behave consistently with the chart. A populated
latest period still displays 600 / +500 in the control above. Empty series and
failed reads remain honest. Verify the rendered card at desktop/narrow widths,
including a negative income target, without changing the shared API contract.

Dedupe: searched all open/done .pm records for zero budgets, missing actuals and
empty balances. The mobile m1 card spec requires these summaries but does not
track this dashboard defect. Its t008 known 20-directive pagination issue is
separate and is not reproduced by this seven-directive fixture. History for
this dashboard component contains only its af5339de import; no later fix found.

Unverified: live income budgets, multi-currency groups, malformed server values
and write flows. No ledger mutations, product fixes or shipping included.

# Journal export dialog overstates which filters apply

**Severity:** minor — the dialog promises the visible filtered entries but
exports a broader, intentionally different scope. **Estimate:** 20–35m,
accurate localized scope text and a focused dialog check. **Pillar:** A3 — users
understand what a portable journal contains before downloading it.

Reproduced 2026-09-08 on production, Chrome 152, English/System-light,
authenticated reader of synthetic `open_ledger/example`, source `a315c273`;
deployed SHA unverified. Desktop 1440×1000 and fresh narrow 390×844 repeat.
No global date/account/expression filter for the failure case.

1. Open `/ledger/open_ledger/example/journal`; leave Transaction selected and
   select **Pending transactions**. The list correctly shows **0–0 / 0** and
   no matching entries.
2. Open Export. Its dialog promises **Download currently filtered entries as
   a Beancount file**, without identifying excluded controls.
3. Confirm Export. The 266,580-byte file contains **1,044 cleared (`*`)
   transactions and 82 balance assertions**, despite the empty pending list.
4. A fresh load and narrow repeat produce the same counts.
5. Working scope control: enter `flag:"!"` in the global expression field,
   then export. The file is 339 bytes of setup/options and has zero transactions
   or balance assertions. A `payee:"Hoogle"` API control returns 71 transactions.

The API is behaving according to its narrower contract. Authenticated GraphQL
`getLedgerPlaintextJournal` and REST `.../plaintext-journal?filter=flag%3A%22!%22`
both return HTTP 200 with the same 339-byte empty-transaction result. This note
does not propose changing the intentional export eligibility or API defaults.

Root cause in **dashboard**:
`features/journal/pages/journal-page.tsx:207–212` gives ExportJournalButton only
the global account/filter/time values. Its request at
`components/export-journal-button.tsx:50–60` passes precisely those fields,
while the dialog at 115–120 uses the overbroad `journal.downloadFilteredEntries`
description. The visible directive-type/status controls are a separate state.

Contract trace: gateway `ledger-journal-resolver.query.ts:115–125` defines only
account/filter/time for plaintext export. `api/rest/v1/journal-reads.ts:90–96`
explicitly describes that scope and shares it with `ledgerPlaintextJournal`
MCP. Ledger `ledger-journal-service.ts:589–635` applies those global filters,
then emits transactions and balance assertions while omitting generated flags
per the existing Fava-compatible export policy. The UI should describe this
contract rather than implying every journal toggle participates.

Fix in **dashboard**: describe the export as source transactions and balance
assertions narrowed by the selected date, account and search expression.
Explicitly state before confirmation that entry-type and transaction-status
buttons do not limit it. Keep Cancel available and preserve the current
request, download and failure feedback. Use the existing localized copy
conventions; do not expose GraphQL field names as product text. Matching every
local journal selector would be a separate product/API change, not required
to make this existing export honest.

Blast radius: one ExportJournalButton production caller, the main Journal
page. Account Journal has a different filtering problem in `w3/m13`; this note
does not duplicate or widen that milestone. Current global expression filtering
is the working control and must remain effective.

Acceptance: with Pending selected and zero visible entries, the export dialog
clearly explains its broader scope before confirmation. With the quoted global
flag expression, export still yields zero transactions. Verify localized
description and confirmation/cancel flow at desktop/narrow; no backend or
financial-data changes are needed.

Dedupe: searched all open/completed board records for plaintext/journal export
and ignored filters. The parity work in `w1/done/m10` and `w3/done/m7` preserves
the narrower API contract. No overlapping open copy correction found. Targeted
history shows the description/wiring in `af5339de`; no prior working broader
export establishes a regression.

Unverified: every directive/subtype combination, writer imports, other locales,
session expiry and network failure. One exploratory unquoted `flag:!` request
failed and was discarded; the valid quoted expression above succeeds. No
production import/write, product fix or shipping included.

# `bea --json` on `doctor` / `example` / `treeify` breaks the JSON contract that `ask` already enforces

**Severity:** minor. **Estimate:** 30–45 minutes. **Owner:** cli. **A1:** a
coding agent that wraps every `bea` invocation in `--json` cannot parse
success or failure for the three native-forward commands, while neighbouring
commands already reject or emit the envelope.

Found 2026-09-15 by continuous CLI QA (`qa-find-bugs-cli`) against `main`,
HEAD `2e72e7fc`, using `uv run bea` 0.2.0 on Darwin 25.5.0 arm64 with isolated
`BEA_CONFIG_DIR` / `XDG_CACHE_HOME` and `BEA_NO_UPDATE_NOTIFIER=1`. Synthetic
local fixtures only; no credentials.

## Repro

```sh
# Failure path — stderr is upstream Click text, not a JSON error object
bea --json doctor context
echo exit=$?
# stderr:
#   Usage: bean-doctor context [OPTIONS] FILENAME LOCATION
#   ...
#   Error: Missing argument 'FILENAME'.
# json.loads(stderr) → JSONDecodeError

# Success path — stdout is raw upstream text, not the bea envelope
bea --json example 2>/dev/null | head -1
# → ;; -*- mode: org; mode: beancount; -*-
# exit 0, ~300KB of bean-example text on stdout

printf '%-30s %s\n' 'Assets:Bank:Checking' '100' 'Assets:Cash' '25' \
  | bea --json treeify | head -1
# → `-- Assets   (ASCII tree, not JSON)
```

Evidence under `cli/tmp/qa-20260915/evidence/`: `272-doc.err`,
`120-example-json.out`, `292-tree-json.out`, `env.json`.

## Working controls

- `bea --json ask "x"` exits 2 with
  `{"error":{"category":"usage","message":"bea ask has no JSON output. ..."}}`
  (`cli/src/cli/commands/ask.py:44-45`).
- `bea --json price fetch` (feature disabled) and `bea --json ingest identify`
  (no script) also return the JSON error object.
- `bea --json check` / `query` / `list` / `report` / `init` emit the documented
  envelope on stdout.

So the frontend already knows how to refuse JSON mode; only the three
`run_native` pass-throughs skip that gate.

## Expected / actual

`cli/docs/USAGE.md:807` lists the commands that accept `--json`.
`USAGE.md:853-856` names the commands that cannot produce JSON and says
`ask` rejects JSON mode. `doctor`, `example`, and `treeify` are absent from
both lists, yet they accept the global flag and then violate
`USAGE.md:84` / `148` (JSON on stdout, JSON errors on stderr).

Expected (match `ask`): under `--json`, each command exits **2** with a usage
error naming itself and pointing at the non-JSON interface (or, for failures
only, wrap upstream's message in the standard error object — but rejection is
the smaller, consistent fix).

Actual: success writes upstream text to stdout; usage failures from
bean-doctor write Click help to stderr; `json.loads` fails on both streams.

## Root cause

```text
cli/src/cli/commands/doctor.py:37-38   launch.run_native(...); raise typer.Exit(code)
cli/src/cli/commands/example.py:12-13  launch.run_native("bean-example", ...)
cli/src/cli/commands/treeify.py:12-13  launch.run_native("treeify", ...)
```

None reads `context.current().json_output`. `ask.py:44-45` is the precedent.

## Fix

In each of the three commands (or one shared helper used by all native
pass-throughs), if `ctx.json_output`: raise `UsageError` analogous to ask,
e.g. "`bea doctor` has no JSON output; run without `--json` and pass the
ledger path as a positional argument." Do not change human-mode behaviour.
Document the three commands beside `ask` in `USAGE.md`'s JSON exceptions.
Add regression tests that `bea --json doctor context`, `bea --json example`,
and `printf … | bea --json treeify` each exit 2 with a parseable JSON error
and empty stdout.

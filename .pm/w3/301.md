# `bea list open` presents `auto_accounts` plugin opens as if they were on disk

**Severity:** major. **Estimate:** 30–45 minutes. **Owner:** cli. **A1:** an
agent that enables `beancount.plugins.auto_accounts`, posts to a new account,
then trusts `list open` / JSON as the source of truth believes
`Expenses:AutoNew` was written — it was not. Removing the plugin (or sharing
the file) makes `bea check` fail; `grep` / editors never see the open.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `dd386d41`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
cat > main.bean <<'EOF'
option "operating_currency" "USD"
2020-01-01 open Assets:Cash USD
2020-01-01 open Equity:Opening-Balances
plugin "beancount.plugins.auto_accounts"
EOF

bea --file main.bean add transaction --date 2020-07-01 --narration auto \
  --posting 'Expenses:AutoNew 5 USD' --posting 'Assets:Cash'
# exit 0 — only the transaction is appended (no open line)

grep AutoNew main.bean
#   Expenses:AutoNew                5 USD
# ← no "open Expenses:AutoNew"

bea --file main.bean list open --account AutoNew
# DATE        ACCOUNT           CURRENCIES
# 2020-07-01  Expenses:AutoNew

bea --json --file main.bean list open --account AutoNew
# [{"date":"2020-07-01","account":"Expenses:AutoNew","currencies":[]}]
# ← no source / plugin marker

# Working control — strip the plugin line:
# bea check → Invalid reference to unknown account 'Expenses:AutoNew'
# list open --account AutoNew → none
```

Loader evidence: the synthetic open’s meta is
`filename='<auto_accounts>', lineno=2` (not the ledger path).

## Expected

`list open` (human + JSON) either:

1. omits plugin-synthesized opens whose `meta.filename` is not a real ledger
   path (e.g. `<auto_accounts>`), matching what is actually on disk, or
2. includes them only with an explicit marker (`source.filename`,
   `synthetic: true`, etc.) so agents do not treat them as written opens.

`add` may keep accepting postings under the plugin; this note is about the
read path lying about file contents.

## Actual

`bea_engine/ledger/reader.py` `list_opens` walks every post-plugin `Open` from
`beancount.loader.load_file` and builds `OpenDirective(date, account,
currencies)` with no filter on `entry.meta["filename"]` and no source field.
Plugin-only opens are indistinguishable from real ones.

## Fix

Skip opens whose filename is a plugin sentinel (or not among the ledger’s
parsed files), **or** serialize `source` / `synthetic` on every open row.
Regression: the repro’s `list open --account AutoNew` is empty (or clearly
marked); a handwritten `open Expenses:AutoNew` still lists; `bea check` with
the plugin still green.

## Dedupe

Not w3/290 (`list open` drops booking method on real opens). Not w3/289
(transaction metadata drop). Not upstream-only: CLI list claims to list
directives “from a .bean file”. No open note covers plugin-synthesized opens
appearing as file opens.

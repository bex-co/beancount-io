# Expose selected budget form values to native accessibility

Minor · 30–45m · mobile · A2: a newcomer using a screen reader can review a budget draft before submitting it.

Environment: https://beancount.io, HEAD84231f9c, native io.beancount.ios 1.20260906.47(47), iPhone 17e/iOS26.5, authenticated QA session, public MiniMax fixture, English/System/light/default text size. Report-only; no budget submitted.

Repro: with MiniMax selected, open inspected internal route `beancount:///(app)/add-budget`. This proves the destination, not the Budget plus-button journey. The form visibly shows Date2026-09-13, IntervalMonthly and CurrencyMUSD. Native XCTest accessibility hierarchy exposes three leaf Buttons labeled only `Date`, `Interval`, `Currency`, with no value or descendant text. Open Interval, use a real native scroll to Yearly and tap the picker Done: visible Interval becomes Yearly, while accessibility remains only `Interval`. Terminate/relaunch (PID57625), wait for Home, reopen Add Budget: Monthly defaults correctly, but the same three values remain absent. Account is empty; visible Expenses:Groceries is a placeholder, not an actual selected account. Form Done remains disabled.

Expected: the row's accessible name identifies the field and its accessible value conveys the current displayed selection. Actual: a reader cannot obtain the selected date, interval or currency from these form rows. This is native metadata verification, not a claim of recorded VoiceOver speech. Control: the open interval picker exposes StaticText `Monthly` in the same XCTest hierarchy; the visible Monthly→Yearly change also proves the selection itself works.

Root: `mobile/src/screens/add-budget-screen/add-budget-screen.tsx:127–159` groups label and value Text children in TouchableOpacity but explicitly assigns `accessibilityLabel={label}` at142 without accessibilityValue. That suppresses automatic descendant text. All four local FormRow callers at284–325 (Date, Account, Interval, Currency) share it; add and update modes use the same screen. Account's populated/locked state is source-traced, not natively exercised in this pass.

Fix: expose the displayed localized value through accessibilityValue or an equivalent combined localized description, without duplicate announcements. Keep a blank account distinguishable from an actual selection, preserve fixed-account semantics in update mode, and update accessible values when picker selections change. Keep loading currency honest and retain disabled/busy submit state. Add meaningful coverage for changing Monthly→Yearly, date/currency values, blank account and locked selected account. No backend/API behavior change or new dependency is needed.

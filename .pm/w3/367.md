# `bea add balance` silently drops all but the last repeated `--amount` (exit 0)

**Severity:** minor. **Estimate:** 25–40 minutes. **Owner:** cli. **A1:** an agent
reconciling a multi-currency account passes two `--amount` values and gets
exit **0** / “Added 1 balance” while only the **last** currency is written —
the first assertion is discarded with no warning.

Found 2026-09-16 by continuous CLI QA ([c1100 hunt](861f74e9-46e2-42ac-8bbb-c2c57986e361)),
HEAD `297302ee`, `uv run bea` 0.2.0, Darwin 25.5.0 arm64. Confirmed
`cli/tmp/qa-20260915/c1100/confirm/`. Evidence: `c1100/`.

## Repro

```sh
bea --file multi.bean add balance --date 2020-01-16 \
  --account Assets:Wallet --amount "100 USD" --amount "50 EUR"
# exit 0 — Added 1 balance
# ledger: only 50 EUR; 100 USD dropped
```

## Expected

Write **two** balance directives, or exit **2** with a clear usage error. No
silent drop.

## Actual

`--amount` is a single `str` in `add.py`; Typer keeps only the last value.

## Fix

Accept repeated `--amount` (list) and write one line per value, or reject
duplicates. Regression: both USD and EUR written (or exit 2); single `--amount`
unchanged.

## Dedupe

Not w3/297, 293, 243. No open note on silent loss of the first `--amount` on
multi-currency `add balance`.

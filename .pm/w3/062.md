# The AI composer's send button has no accessible name

Severity: **minor**. Owner: **dashboard**. Estimate: **20–35 minutes**.
A2: keyboard and screen-reader users can identify the primary action for their
first question without recognizing an unlabeled return-arrow icon.

Production `https://beancount.io`, 2026-09-08, Chrome 152, English, light.
Fresh QA-authenticated contexts at 1440×1000 and 390×844, public
`open_ledger/example`, read-only permissions. Local HEAD `a315c273`, fetched
main `cc3f4c2f`; implicated source unchanged. Deployed SHA unverified.

1. Open `/ledger/open_ledger/example/agent`.
2. Type the local draft **What is double-entry bookkeeping?** in the composer.
3. Press Tab: focus moves to **Attach file**. Press Tab again: focus reaches
   an enabled button whose accessible name is empty.
4. Repeat from fresh loads at both widths and on
   `/ledger/open_ledger/example/ask?mode=sandbox`; the result is identical.

The accessibility tree lists the textarea, **button Attach file**, then only
**button**. The send button has no text, title, aria-label or labelled-by
reference; its only SVG is aria-hidden. The empty composer exposes the same
unnamed action in its disabled state. Expected: a localized action name such
as the existing **Ask**, in both enabled and disabled states.

Working control: the neighboring Attach file button has a meaningful label
and correct keyboard focus. No native screen-reader session was run; the
finding is proven through the browser accessibility tree and focused DOM.
Keyboard activation, actual answer delivery and Enter submission were not
tested, so this is not a claim that submitting is impossible.

Root cause: `dashboard/src/features/ai-agent/pages/agent/agent-chat-input.tsx:251–268`
renders an icon-only submit Button without a label. Its Attach file sibling
at 240–249 explicitly sets `aria-label`. The common Button primitive forwards
provided props; it cannot infer a meaningful action from a decorative icon.
`AgentPageImpl` at `pages/agent/page.tsx:384–394` uses this shared composer for
both the in-process agent and AskAgentPage's sandbox/agent modes.

Give this submit button `aria-label={t("aiAgent.ask")}`, reusing the existing
localized action already displayed by QuickAskInput. Preserve its actual
disabled/uploading state, focus order, submission handlers and icon. Do not
rename decorative SVGs as a substitute for naming the button or change the
common primitive to invent names. This label-only change needs no backend,
REST/MCP, AI transport or dependency change.

Blast radius: `/agent` and `/ask?mode=sandbox` were exercised at both widths.
`/ask?mode=agent` uses the same component and is source-traced only; mode-less
`/ask` redirects to `/agent`. Overview's separate QuickAskInput already has
visible localized Ask text and should retain it. Attachment removal and upload
progress are separate states; their actual uploads were not exercised.

Acceptance: after entering a draft, the focused action is exposed as **Ask**
at both widths and on both tested routes; empty/disabled and uploading states
retain that name. Attach file remains separately named. Verify the existing
composer test can locate the intended action by role/name and preserve its
disabled conditions; no live model request is needed for this check. Other
locales and native screen-reader/browser combinations remain unverified.

All four page documents returned HTTP200, with no console/page errors. Minimal
GetLedger controls returned HTTP200, no GraphQL errors, public visibility and
`pull=true`, `push=false`, `admin=false`. The composer and label are generated
locally. Chat endpoints were guarded before navigation; guards recorded zero
attempts. No submit click/Enter, model call, sandbox, attachment upload or
ledger mutation occurred. Drafts were cleared and all contexts closed.

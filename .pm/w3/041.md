# File Cancel erases the draft before the unsaved-changes choice

**Promoted to [m29](./m29/README.md).** That milestone owns the implementation
and estimate, including the fresh writer repeat and new-file navigation guard.
This note retains the original evidence; count the group only once.

Severity: **major**. Owner: **dashboard**. Estimate: **45–60 minutes** for the
cancel/navigation transition and integrated regression coverage. A2: a person
who chooses Stay must retain the unsaved work the dialog promises to protect.

Production `https://beancount.io`, 2026-09-08, Chrome152, English, System/light;
desktop1440×1000 and a fresh390×844 repeat. Public synthetic
`open_ledger/budgeting-envelopes/accounts.bean`. Local `a315c273`; fetched
`origin/main cc3f4c2f` has unchanged implicated file-view code. Deployed SHA
unverified. Only local unsaved comments were edited; no Save/Delete or write
request occurred. Reader access to edit mode is separately tracked in040;
authorized-writer behavior is inferred from the same unbranched component,
and must receive a proper writer regression fixture during implementation.

1. Open `/ledger/open_ledger/budgeting-envelopes/files/blob/main/accounts.bean?editMode=true`.
   The initial editor model has **1659 UTF-16 code units**.
2. Type a local comment, `; qa-local-unsaved-cancel-probe`. The desktop model
   grows to **1691** and contains the marker.
3. Working control: click the Files breadcrumb. The Unsaved Changes dialog
   appears with **Stay / Leave Without Saving**; the draft remains1691.
   Choose Stay: the full draft remains1691 and the editor stays open.
4. Now click **Cancel**. The same dialog asks “Are you sure you want to leave?
   Your changes will be lost.” Before answering, the model has already reverted
   to **1659**, and the marker is gone.
5. Choose **Stay**. The URL remains `?editMode=true`, but the draft is still
   replaced with the original file. Repeat from a fresh narrow load, using
   **Escape** to invoke Cancel: **1692 →1659** before the prompt is answered,
   and Stay again leaves the original contents.

Expected: while offering a Stay choice, keep the complete draft until the user
confirms leaving. Stay or dismissing that prompt must preserve the draft,
selection and editing session. A clean-buffer Cancel should leave edit mode
without a false unsaved prompt. Confirmed discard must return to the saved
contents and ordinary view exactly once.

Root cause: `dashboard/src/features/ledger-editor/file-editor/components/ledger-file-view/text-file-view.tsx:127–132`
calls **setEditedContent(plainContent)** before `onExitEditMode`. The latter
navigates away from the edit query flag in `ledger-file-view/index.tsx:103–110`.
`file-edit-mode.tsx:64–71` has already registered a dirty-state `useBlocker`;
it blocks that navigation and displays the resolver dialog at166–195. The
buffer reset still commits while navigation waits. Stay merely resets the
navigation resolver; it cannot restore the discarded buffer.

Framework control: the exact locked `@tanstack/react-router` **1.167.0** source
was inspected from its published package, without installing dependencies.
`src/useBlocker.tsx:210–244` awaits the registered predicate, creates the
blocked resolver, and implements `reset` as resolving the navigation decision
true. It does not roll back application state. This matches the live
Files→Stay control and the independent Cancel failure; the router should not
be replaced or patched for the caller's early reset.

Fix the cancel transition so discarding the buffer follows the user's actual
decision. Retain one consistent confirmation flow: a dirty Cancel/Escape opens
the existing choice without first resetting content; Stay/Close preserves it;
Leave Without Saving discards and exits. Avoid simply delaying the reset by a
timer or suppressing all navigation protection. Preserve ordinary link/back
protection, clean Cancel, save success/failure handling, and writer permission
checks. No API or dependency change is needed.

Blast radius: TextFileView is the sole consumer of EditModeToolbar, and
FileContentView is the sole TextFileView caller. All supported text blob views
share this path. The Cancel button and document-level Escape handler
(`text-editor.tsx:104–108`) invoke the same callback. The entry-context dialog,
import wizard and non-text previews have separate flows.

Acceptance: use the real file-view state with a routed blocker, asserting the
full editor buffer before the prompt, after Stay/Close, and after confirmed
discard. Cover button Cancel, Escape, ordinary Files/back navigation, clean
buffers and failed saves. Existing `ledger-file-view-editmode-sync.test.tsx`
tests at125–139 and346–378 simulate replacement callbacks/variables instead of
mounting this interaction, so they cannot detect the failure. Add meaningful
coverage rather than another callback-call-count assertion. Run dashboard
format, lint, tests and build.

No application page errors occurred in the monitored desktop comparison; its

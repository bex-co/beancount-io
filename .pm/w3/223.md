# `bea add transaction` header errors (`--tag` / `--link` / `--flag`) blame postings

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** cli. **A1/A2:** an
agent or newcomer who mistypes a tag, link, or flag is told to fix postings, so
they edit the wrong option.

Found 2026-09-15 by continuous CLI QA against `main`, HEAD `89e2d9cc`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated `BEA_CONFIG_DIR` /
`XDG_CACHE_HOME`. Synthetic fixtures only.

## Repro

```sh
bea --json --file main.bean add transaction --date 2024-03-01 --narration x \
  --posting 'Expenses:Food:Groceries 1 USD' --posting 'Assets:Bank:Checking' \
  --tag 'has space'
```

Exit 2, stderr:

```json
{"error":{"category":"usage",
  "message":"Invalid transaction options; use postings such as 'Assets:Checking -30 USD'. Nothing was written.",
  "details":["Transaction options: Invalid token: 'space'"]}}
```

Same primary message for `--link 'bad link'` (`Invalid token: 'link'`) and for
`--flag '??'` (`syntax error, unexpected FLAG, expecting end of file or EOL or
TAG or LINK`). Postings in all cases are valid.

Re-checked 2026-09-15 (HEAD `b50710b3`): `--flag '??'` still hits the same
canned posting-example headline.

## Working controls

- Bad account on a posting names the account rule, not postings-as-examples:
  `Invalid account 'NOT_AN_ACCOUNT'. Account names use colon-separated…`
- Bad `--meta nocolon` says: `Each --meta must be 'key:value'…`
- Valid `--tag alreadyhashed` / `--link ok-link` write successfully.

## Expected / actual

Expected: primary message names tags/links (or “transaction header”), e.g.
“Invalid tag 'has space'; tags are one token without spaces” / “Invalid link
…”, with details pointing at `--tag` / `--link`. Do not recommend posting
syntax when every `--posting` parsed cleanly.

Actual: one canned UsageError always recommends posting examples whenever the
parsed header+postings string fails, including pure tag/link failures.
Details say `Transaction options:` (correct bucket) but the token fragment
(`'space'`, `'link'`) is easy to miss under the posting-focused headline.

## Root cause

`cli/src/bea_engine/ledger/adding.py:314-322` — on any parse failure of the
synthetic transaction text, raise:

```text
"Invalid transaction options; use postings such as 'Assets:Checking -30 USD'…"
```

`details` distinguish `Transaction options` vs `--posting N` via lineno
(`:317-319`), but the headline never branches on that.

## Fix

When every detail is prefixed `Transaction options:` (no `--posting N`), use a
header-focused message that mentions `--tag` / `--link` / flag / payee /
narration. Keep the posting example only when a detail names `--posting N`.
Optionally validate tag/link tokens in the frontend before building the parse
string (Beancount tags/links are single tokens). Regression: `--tag 'has space'`
and `--link 'bad link'` with valid postings must not mention posting examples;
a truly bad `--posting` still should.

## Dedupe

No prior `.pm` hit for this message or tag/link UX when first filed. Unrelated
to w3/221–222. Related follow-ups that share the same canned headline but are
separate triggers: w3/229 (single-letter `--meta` keys) and the `--posting`
detail path for lowercase currencies (detail correctly says `--posting N`).

## Unverified

Interactive prompts; bulk `add transactions --from` tag fields; non-UTF-8 tags.

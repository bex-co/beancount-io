# BQL completion keeps the typed prefix before the suggested query

**Minor · dashboard · 45–60m.** A2: a newcomer accepting the editor's own BQL
example should get an executable query.

## Reproduce

1. Open https://beancount.io/ledger/open_ledger/example/query?lang=en.
2. Replace the editor contents with **sel** and invoke suggestions with Ctrl+Space.
3. Choose **select \* from accounts**, then click **Execute Query**.

Actual editor, history and QueryShell input are **selselect \* from accounts**.
The server correctly returns HTTP 200 with GraphQL BAD_USER_INPUT:
"Invalid BQL query: syntax error at position 0: unexpected token 'selselect'".
The UI shows its generic invalid-input alert. Expected editor/request:
**select \* from accounts**, without the already typed prefix.

Repeated from fresh desktop (1440×1000) and narrow (390×844) contexts on
2026-09-09. All four offered snippets — accounts, balances, entries and
transactions — retain **sel**. Keyboard acceptance after typing the full word
**select** also produces **selectselect \* from accounts**.

The empty-editor control works for every snippet at both widths:

| Accepted complete query     | Actual result rows |
| --------------------------- | ------------------ |
| select \* from accounts     | 60                 |
| select \* from balances     | 82                 |
| select \* from entries      | 2051               |
| select \* from transactions | 1044               |

Four retained prefix-check contexts cover 18 executions, all HTTP 200:
ten invalid prefixed queries and eight successful empty-editor controls.
No page errors or mutations in those contexts. Initial timed sampling of the
larger control queries was replaced by a run that awaits each exact response;
it is not used to claim a missing result or another query failure.

Environment: production UI/API https://beancount.io, Chrome 152.0.7977.77,
English/light, QA session from dashboard/.env, reader of public synthetic
open_ledger/example. Source/fetched main 7f4b6190; deployed SHA unverified.
Evidence: dashboard/tmp/qa-20260907-w3-loop/bql-completion-evidence.json and
bql-completion-prefix-{1440,390}.png. These contain public query text, sanitized
responses and the actual rendered malformed editor/history. All temporary
contexts and their local query histories were discarded.

## Root cause and fix

dashboard/src/features/bql/pages/index.tsx:243–308 registers one SQL completion
provider with four snippet records. Each range sets both startColumn and
endColumn to position.column, ignoring the model's existing word. Monaco thus
inserts at the cursor rather than replacing **sel**.

Pinned Monaco 0.55.1 confirms the mechanism: monaco.d.ts:7361–7367 defines the
completion replacement range; esm/vs/editor/contrib/suggest/browser/suggest.js:
57–60 takes the supplied start/end; suggestController.js:467–480 derives
overwriteBefore as cursor column minus that start. The current zero-width range
overwrites zero characters. Empty input is the valid control because there is
then no prefix to remove. The QueryShell caller at index.tsx:87–93 accurately
sends the resulting editor text; no backend parser or API parity change is needed.

Build the replacement range from the current model's word/prefix for these
whole-query snippets, preserving surrounding user text. Use one consistent
range for the four records rather than four cursor-only copies. Verify
statement-start indentation and cursor-in-word cases; if a whole-query snippet
cannot be inserted meaningfully within an existing statement, suppress it there
instead of appending another SELECT or replacing unrelated text. Those additional
contexts are implementation checks, not observed failures from this run.

Acceptance: choosing each existing snippet after **sel** yields exactly its
complete query and runs with the same result as the empty-editor control.
Pointer and Enter acceptance agree. Empty-editor insertion, unrelated text,
ordinary typing, URL restoration and Cmd+Enter submission still work. Test the
actual provider with Monaco's replacement semantics and retain a real browser
acceptance check; the current page test only stubs provider registration at
pages/**tests**/index.test.tsx:128 and cannot detect this defect.

Search found exactly one production BQL provider registration with four
suggestions. The shared common/components/monaco-editor/index.tsx only wraps the
editor in ClientOnly; do not change every editor's insertion behavior.

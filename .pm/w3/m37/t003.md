## Objective

Make **Download CSV** on the Query page write the same amounts the table shows, using the shared text formatter from t001, so a spreadsheet receives `-3623.17 USD` instead of `{"USD":"-3623.17"}`. Decide the shared `common/lib/export/csv.ts` behavior deliberately: either teach the BQL export path to pre-format its inventory cells before handing rows to the generic writer, or give the writer an opt-in cell formatter. Do not silently change how other callers of that writer serialize their objects.

## Context

- Defect site: `dashboard/src/common/lib/export/csv.ts:32` — `typeof value === "object" ? JSON.stringify(value) : String(value)`.
- BQL export entry point: `dashboard/src/features/bql/lib/export-utils.ts` and `dashboard/src/features/bql/components/` (the Download CSV control on the result card).
- Working control: Holdings' Export CSV already writes `5317.06 USD` through `csvObjectToString`.
- Existing callers of the generic writer must keep working; check every one before changing its default.

## Steps

1. Enumerate the callers of the shared CSV writer and pick between pre-formatting at the BQL call site and an opt-in formatter hook.
2. Route BQL inventory cells through the shared t001 text formatter.
3. Verify quoting and row structure for a multi-unit cell.

## Files

- `dashboard/src/common/lib/export/csv.ts`
- `dashboard/src/features/bql/lib/export-utils.ts`
- `dashboard/src/features/bql/components/query-result-card.tsx` (export wiring only)

## Acceptance criteria

- [ ] The reproduced query's CSV contains `-3623.17 USD`, `469.61 USD` and `9 ITOT`, with empty cells for the two zero-net rows.
- [ ] A multi-unit cell keeps every unit inside one quoted field and does not break the row structure or the header/column count.
- [ ] Every other caller of the shared CSV writer produces unchanged output.
- [ ] The BOM, delimiter, quoting and filename behavior of the existing export are unchanged.

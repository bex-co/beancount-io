# Compact date fields clip the year before the user edits anything

**Severity:** minor. **Owner:** dashboard. **Estimate:** 25–40 minutes.
**A2:** the entire selected calendar date is visible when reviewing a new
directive, without focusing and horizontally scrolling its input.

Production `https://beancount.io`, 2026-09-08, Chrome 152, English/light,
1440×1000 and390×844. Existing QA session, public `open_ledger/minimax`.
Local HEAD `a315c273`, fetched main `afb36a9b`; relevant files unchanged.
Deployed SHA unverified. No form values are changed or submitted.

1. Open Journal → New Entry with Transaction, Balance, Note or Account selected.
2. Move focus to the dialog's Close button without activating it. The untouched
   date is **09/08/2026**, but its field cuts off the end of the year. The
   screenshot at390px visibly ends partway through the year before the calendar
   icon. The input has its complete value and scrollLeft0; this is not a partial
   edit, selected-text artifact or parsing change.
3. All four Journal forms use the same128px field. After borders and padding,
   only74px remains for date text. Using its actual rendered font, the complete
   string measures77.15px at desktop14px and86.77px at narrow16px. The narrow
   clipping is larger; screenshots, not just the text measurement, show it.
4. Accounts → Open Account is a working production control: its full-width
   date field is430px/308px and shows the full same value at both viewports.
5. Fresh Account-tab and Accounts controls reproduce those results. In isolated
   DOM controls change only the compact field wrapper to160px: text space
   becomes106px and the full date is visible, with the same value and font.

Expected: the default compact field accommodates its own normal ten-character
date plus calendar action at both supported input font sizes. Actual: the
default width and reserved icon space consume too much of the field. The year
is still in the input value; no data loss, incorrect serialization or backend
failure is claimed by this display-only finding.

Root: `common/components/ui/date-picker.tsx:115–120` fixes the wrapper to128px
and reserves40px on the right with `pr-10`. Shared `ui/input.tsx:11` adds12px
left padding, borders, full width, base16px text and desktop14px text. The
popover's absolutely positioned calendar action at130–138 requires its own
space. Merely removing its padding would let text collide with that button.

Give the shared DatePicker default enough usable text width for its formatted
date and calendar button, while retaining responsive fit and explicit full-width
overrides. The160px control proves the sizing cause; choose the local sizing
rule that fits the existing form layout. Preserve the input font, complete
date format, keyboard/pointer access, calendar positioning and parent reset
behavior. Do not abbreviate the year, shrink the global Input font or change
date parsing to conceal clipping.

# `bea add … --into` under an include glob says to add an include directive, but only creating the file is required

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** cli. **A1:** an
agent maintaining `include "txns/*.bean"` cannot `--into txns/new.bean` until the
file exists; the error tells them to edit the root include list, which is the
wrong fix for a glob.

Found 2026-09-15 by continuous CLI QA against `main`, HEAD `07547c5e`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
mkdir -p books/txns
cat > books/main.bean <<'EOF'
option "operating_currency" "USD"
include "accounts.bean"
include "txns/*.bean"
EOF
cat > books/accounts.bean <<'EOF'
2024-01-01 open Assets:Bank:Checking USD
2024-01-01 open Expenses:Food
2024-01-01 open Equity:Opening-Balances
2024-01-01 * "Opening"
  Assets:Bank:Checking  100 USD
  Equity:Opening-Balances
EOF
printf '%s\n' '2024-02-01 * "A"' '  Expenses:Food  1 USD' '  Assets:Bank:Checking' \
  > books/txns/a.bean

bea --json --file books/main.bean add transaction --date 2024-02-02 --narration B \
  --posting 'Expenses:Food 2 USD' --posting 'Assets:Bank:Checking' \
  --into txns/b.bean
# exit 2
# Write destination …/txns/b.bean is not included by …/main.bean.
# Create it and add an include directive to the root first.
```

Working control:

```sh
: > books/txns/b.bean   # create empty file matching the glob; no root edit
bea --json --file books/main.bean add transaction --date 2024-02-02 --narration B \
  --posting 'Expenses:Food 2 USD' --posting 'Assets:Bank:Checking' \
  --into txns/b.bean
# exit 0 — writes into txns/b.bean
```

`USAGE.md` already says the destination must exist; the bug is the recovery
text for glob includes.

## Expected

When the path would match an existing include glob (`txns/*.bean`), say that the
file must be created first (and optionally offer to create an empty file), not
that a new `include` line is required. Prefer allowing `--into` to create a new
path that matches a captured glob pattern in one step.

## Actual

`LedgerSnapshot.require_target` only accepts paths already present in
`contents` (glob expansion at capture time). Missing targets always get the
same "add an include directive" UsageError.

## Root cause

```text
cli/src/bea_engine/ledger/write.py:82-87  require_target
cli/src/bea_engine/ledger/write.py:75-78  patterns recorded from include globs
```

## Fix

1. If `target` matches any recorded include `pattern` via `glob`/`fnmatch` but
   is absent, emit: create the file (it is covered by `include "…"`); do not
   mention a new include directive.
2. Optional: create an empty file then write when the path matches a pattern
   and the parent directory exists — still refuse paths outside every pattern.
3. Regression: glob ledger, `--into` missing member fails with glob-specific
   text; after `touch`, write succeeds without editing the root.

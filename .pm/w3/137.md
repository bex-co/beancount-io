# Transaction Share link closes its menu without opening the iOS share sheet

**Minor · 40–55m · mobile.** A3: readers should be able to share a public example entry through the app's advertised action.

Environment: September 11, HEAD f1965988, native build 1.20260906.47 with current JS, iPhone 17e / iOS 26.5, English/System/light/default large text. Signed-in QA at https://beancount.io, public read-only open_ledger/crypto-example. No production writes or outbound sharing.

Repro: open Crypto Home, choose Liabilities, tap See all, then the Liabilities root in Accounts. Tap Aave dated November 1, 2024 (entry hash 4dc6c56d288b62c2c7f5c80cbd308e81), open the top-right action menu and tap Share link. The menu closes; no share sheet remains visible. A subsequent native accessibility hierarchy contains the transaction screen and no activity sheet. Relaunch the app (PID 70579), verify Home, open the same valid entry through its shared deep link, and repeat: the same failure occurs. The first run used actual account/entry navigation; the fresh repeat proves the shared-link destination.

Expected: the iOS activity sheet stays open with the entry's canonical HTTPS link until the reader selects an activity or cancels. Actual: the action returns silently to the detail screen. Copy link is also advertised, but clipboard behavior was not exercised in this run.

Working control: from the same fresh process, open the drawer and tap drawer-share-link-row. A native activity sheet appears with beancount.io and its available activities. Dismissed by tapping outside; nothing sent. The drawer uses the same shareLedgerUrl helper and has no native Modal, ruling out a blanket simulator/share-service failure. This control verifies sheet presentation, not every activity's payload behavior.

Root: mobile/src/components/menu-button/index.tsx:143–145 sets visible=false and immediately invokes item.onPress in the same handler. Transaction detail's callback at src/screens/transaction-detail-screen/transaction-detail-screen.tsx:358–360 calls src/common/app-links/ledger-url-actions.ts:4–5, which immediately invokes Share.share. The menu is a React Native Modal (line124), and no onDismiss completion orders the share presentation after dismissal. The likely mechanism is presentation on the outgoing modal during its dismissal; the exact UIKit interleaving was not instrumented. Installed React Native RCTActionSheetManager.mm:288–308 chooses RCTPresentedViewController and presents the activity controller; Fabric RCTModalHostViewComponentView.mm:194–202 emits onDismiss only after native dismissal completes. Bounded JS error capture was empty; that is not proof of no native presentation race.

Fix: defer actions that present another native controller until the menu's native dismissal completes. Preserve the selected callback exactly once, do not execute it on backdrop/cancel, clear pending actions safely, and avoid an arbitrary timeout. Provide equivalent Android behavior without waiting for an iOS-only completion event there. Keep the menu usable for ordinary navigation and clipboard actions. Do not modify URL construction or ledger permissions to fix presentation.

Blast radius: MenuButton has two callers, transaction detail and Home's authorized quick-add menu. Only entry sharing is natively reproduced here; preserve quick-add navigation in regression coverage. shareLedgerUrl has two callers, entry detail and drawer; drawer presentation is the working control. Entry destinations reached from lists and shared links use the same detail screen. Loading/missing hash cannot provide a share URL and is separate from this fully loaded case; empty/error/offline entry states and Android are unverified.

Completed w4/m5/t005 explicitly requires the entry and ledger share sheets to open; this is an unmet native acceptance criterion, not a new sharing feature. Menu's immediate callback dates to 9c240d2e; sharing was added in 2a464bbc. No newer fix in current mobile history. Existing w3/115 concerns cross-ledger filters; w3/126 and132 are dashboard findings. No overlapping open native sharing item found.

Acceptance: entry Share opens a stable native sheet after menu dismissal; cancel returns to the same entry; repeated taps do not create duplicate sheets; drawer sharing still opens. Add a meaningful dismissal-order regression covering no callback before native dismissal and exactly one callback afterward, plus dismissal without selection. Verify native presentation on iPhone 17e; run the normal mobile checks when implementing.

# `bea list transaction --search ''` matches every row (`'' in text` is always true)

**Severity:** minor. **Estimate:** 10–20 minutes. **Owner:** cli. **A1:** an
agent that passes an empty `--search` (shell expansion, template hole, or
JSON→CLI bridge) gets the full unfiltered transaction list instead of zero
hits or a usage error — while whitespace-only `--search '   '` correctly
returns nothing.

Found 2026-09-16 by continuous CLI QA against `main`, HEAD `11e8dd62`,
`uv run bea` 0.2.0, Darwin 25.5.0 arm64, isolated config/cache. Synthetic
fixtures only.

## Repro

```sh
# Fixture with three transactions (any valid ledger with ≥1 txn works)

bea --json --file main.bean list transaction --search ''
# exit 0 — data length == unfiltered list (every narration “matches”)

bea --json --file main.bean list transaction --search '   '
# exit 0 — data: []  (spaces are not a substring of payee/narration)

bea --json --file main.bean list transaction --search food
# exit 0 — only narrations containing “food”
```

## Expected

An empty `--search` term is either a usage error (exit 2: search text required)
or treated as “match nothing” / ignored. It must not silently disable filtering.
Repeatable `--search food --search ''` should not keep the food filter while
pretending the empty term also matched (today the empty term is a no-op in
`all(...)` because `'' in s` is always true).

## Actual

`list_transactions` builds `terms = [(term or "").casefold() for term in search]`
and requires `all(term in payee or term in narration for term in terms)`.
In Python, `'' in any_string` is always `True`, so a lone empty term matches
every transaction.

## Root cause

`cli/src/bea_engine/ledger/reader.py` `list_transactions` (~142–156): empty
strings are kept in `terms` and then substring-tested without a non-empty
guard. Typer correctly rejects a bare `--search` with no argument, but
`--search ''` / `--search ""` reaches the filter.

## Fix

Reject empty (after strip) `--search` values with a usage error, or drop
blank terms and error if none remain. Regression: `--search ''` exits 2 (or
returns `[]` if “match nothing” is chosen); `--search food` and
`--search '   '` behavior stay as today (or whitespace also rejected if
stripped). Document the choice in `USAGE.md`.

# Ask sign-in can discard the question and selected mode

**Severity:** minor. **Owner:** dashboard. **Estimate:** 35–50 minutes.
**A2:** a prefilled Ask link retains the user's question and chosen surface
through authentication.

Production `https://beancount.io`, 2026-09-08, Chrome 152, English/light,
fresh 1440×1000 and 390×844 guest contexts with zero site cookies initially.
Public `open_ledger/example`; local HEAD `a315c273`, fetched main
`afb36a9b`, implicated dashboard files unchanged. Deployed SHA unverified.

1. Open `/ledger/open_ledger/example/agent` with `q` set to
   **qa-20260908-login-context + 零 & savings** and `lang=en`.
   URL-encode the complete question; the emitted user text correctly retains
   spaces, plus, ampersand and Unicode.
2. Its automatic chat request receives a real HTTP401:
   `{"ok":false,"error":{"code":"UNAUTHENTICATED","message":"Authentication required"}}`.
   The client reaches login with `next=/ledger/open_ledger/example/agent`,
   discarding the question/search.
3. Repeat using `/ledger/open_ledger/example/ask?mode=sandbox&q=...&lang=en`.
   The analogous `ask-agent` 401 can produce
   `next=/ledger/open_ledger/example/ask`, losing both question and mode.
4. This is intermittent without timing control: concurrent
   `GetAiCfoUsage` returns GraphQL `UNAUTHENTICATED` and its global auth
   handler sometimes wins with the full path/search intact (and the separate
   incorrect expiry explanation tracked in060).
5. For a deterministic fresh repeat, hold only the `GetAiCfoUsage` read
   before transmission while forwarding the actual chat 401 unchanged.
   Both widths and both surfaces then retain only the bare path.
   Abort the held read after recording the login destination.
6. In separate already-authenticated destination controls, the complete
   original URLs prepare one request with the same question. Sandbox keeps
   `/ask?mode=sandbox`, endpoint `ask-agent` and request mode `ask`.
   The stripped destinations prepare no question; bare `/ask` redirects to
   `/agent`. All authenticated chat requests were aborted before transmission.

Expected: the complete safe relative route, including `q`, `mode` and
language search, survives the 401-to-login transition regardless of which
auth response completes first. Actual: the custom chat redirect constructs
a path-only destination. Login's successful return consumes this `next`,
so the lost question cannot auto-submit and sandbox can become the ordinary
Agent surface. The destination behavior was tested using existing QA cookies;
no full interactive credential submission is claimed.

Root cause: `dashboard/src/features/ai-agent/pages/agent/page.tsx:95–104`
handles 401 by rebuilding a path from owner/name/`routeSuffix`, dropping
the current search string. `:60–61` and `:176–187` consume `q` only on
mount. `pages/ask-agent/index.tsx:13–27` selects sandbox/agent behavior from
`mode`, and `routes/ledger.$ledgerOwner.$ledgerName.ask.tsx:16–25`
redirects a mode-less Ask URL to Agent.

The correctly preserving control is already implemented by
`common/apollo/links/auth-error-link.ts:80–83`, which captures pathname plus
search and URL-encodes that complete relative destination. The distinct
`reason=expired` copy defect remains060.
`features/auth/pages/login-page/index.tsx:24–31` correctly prioritizes
`getSafeRedirectPath(next)` and performs document navigation; do not change
that consumption or weaken its rejection of external/protocol-relative paths.

Repair the custom chat 401 redirect to retain the active route and search using
the existing safe auth-navigation convention, with coherent duplicate-redirect
handling. Preserve encoded question characters exactly once, current ledger and
mode; do not rebuild a bare route or stash the question in durable browser
storage. Remove a now-unused routeSuffix-only abstraction if appropriate after
checking its sole Ask wrapper caller. This changes only dashboard navigation;
authentication, quota rules, provider routing and server APIs stay as defined.

Backend `ai-agent/api/agent-route.ts:51` and
`api/ask-agent-route.ts:92` resolve authentication before invoking their
handler/workflow. `utils/route-guards.ts:22` rejects missing identity.
Real guest requests were rejected at this boundary; no model/sandbox work was
accepted. The quota-read race is an observed competing redirect, not evidence
that a 401 may be treated as a successful chat response.

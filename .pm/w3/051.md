# Commodity price history cannot be read with the keyboard

Severity: **major for keyboard users**. Owner: **dashboard**.
Estimate: **45–60 minutes**, a scoped price-history disclosure and interaction
coverage. A2: readers can inspect the dated prices behind the public crypto
example without needing a pointing device.

Production `https://beancount.io`, 2026-09-08, Chrome 152, English,
System/light; authenticated reader of public synthetic `open_ledger/crypto-example`.
Desktop 1440×1000 and fresh 390×844. Local HEAD `a315c273`, freshly fetched main
`cc3f4c2f`; implicated commodity/chart code is unchanged there. Deployed SHA
unverified.

1. Load `/ledger/open_ledger/crypto-example/commodities`. Wait for prices and
   chart rendering to settle. The page contains 14 commodity-pair cards.
2. Focus the last header control, the account/avatar button, and press Tab.
3. Focus jumps directly to the **Holdings** related-page link after all cards.
   No chart, price-history control or alternate data view is reachable.
4. Inspect the BTC/USD card's accessibility tree. It contains only **BTC/USD**
   and **Price history with 14 data points**. No dates or quote values appear.
5. Pointer control: hover its December 31, 2024 point. A tooltip now reveals
   **2024-12-31 / BTC/USD: 93500.00**. Keyboard users have no equivalent action.

Complete fresh desktop/narrow repeats agree. The BTC card has one canvas,
zero focusable controls, no accessible image description and no table. The
page's accessibility snapshot exposes only pair names and point counts before
pointer interaction. Both actual GetLedgerCommodities reads return HTTP 200,
14 pairs, and all 14 BTC/USD date/value points; no console/page errors occur.
Screenshots were recaptured after the chart animation finished.

Expected: keyboard and assistive-technology users can inspect each pair's dated
price values through the page. A pair name and count alone do not expose the
price history. The pointer path and source data already work.

Root cause: `dashboard/src/features/ledger-data/commodities/index.tsx:218–237`
renders each card with a pair label, count and CommodityChart only. That
function at 33–153 provides an axis-hover tooltip and a ReactECharts canvas;
it supplies no keyboard interaction or text data alternative. The client chart
wrapper at `common/components/react-echarts/client.tsx:96` returns a div with
no semantic data or focus handling. This is a missing commodity-page read path,
not an API failure or a chart that failed to load.

Fix in **dashboard**: add a keyboard-operable price-history disclosure for
each pair, with a semantic table of date and price in that pair's quote units.
Give the disclosure a localized name identifying the pair and expose its open
state. Use the existing common UI primitives, retaining source decimal strings
for display and chronological dates. Keep the chart and pointer tooltip.
The table should use the already loaded prices, require no additional request,
and remain available independently of the lazy chart module. Do not add an
empty focus stop to the canvas or treat an image label containing only the pair
name as access to the actual data.

CommodityChart has one production caller, the map in this page, covering every
returned pair. Keep this change scoped to Commodities; other chart-only
surfaces need independent journeys before expanding the work. Working product
control: Overview's Net Worth **Show table** button responds to Enter and exposes
its dated values as text; **Show chart** responds to Space and restores the
chart. It demonstrates an existing keyboard-accessible alternative pattern.

API trace: `GetLedgerCommodities` selects base/quote and string date/value.
Gateway `ledger-data-resolver.query.ts:25–42,233–241` preserves those strings.
Ledger `ledger-data-service.ts:248–258` delegates to
`foundation/rustledger/directives-report.ts:221`, which builds the price pairs.
The actual REST commodities control also returns 200 and the same 14 BTC dates
and prices, including 93500.00 on December 31. REST/MCP share vocabulary reads;
MCP was traced only. No backend or stored-price change is needed.

## Objective

The current CLI sends `max_completion_tokens`, but the route's Zod schema strips that field. Preserve modern and legacy output caps end to end, reject an ambiguous request containing both, and give an uncapped request a modest explicit default rather than the provider's model maximum.

## Files

- `backend-cluster/backend-v2/src/features/ai-agent/api/openai-chat-completions-route.ts`
- `backend-cluster/backend-v2/src/features/llm/service/llm-service.ts`
- Backend route/service regression tests and public backend documentation

## Acceptance criteria

- The actual HTTP adapter and real service forward either cap spelling and default an omitted cap.
- Invalid or conflicting caps fail before a model call.
- Authorization, per-user quota checks, usage recording, and the documented wire-compatibility parity exceptions remain intact.
- Regressions fail before the fix; backend checks pass.

# A save that times out on the server's internal hop says "Failed to save" though it may have committed, inviting a duplicate entry

**Severity:** moderate (the duplicate-write risk of w21/351). **Estimate:** 15 minutes. Owner: mobile. A3: `mobile/src/common/ledger-refusal.ts:299-332` (`ledgerWriteFailureMessage`) treats only a non-2xx HTTP status or transport text as "unconfirmed". backend-v2 maps a 502/503/504 or no-status reply from the ledger service, including its 90 s write timeout (`api-client.ts:79`), to `SERVICE_UNAVAILABLE` (`error-to-domain.ts:174-178`). GraphQL sends that with HTTP 200, so the function returns null, and New Transaction, Edit, Budget and Open Account show the generic "Failed to save".

Not run natively. Under `tsx` (the agent's proof): `HTTP 502 → ledgerWriteUnconfirmed`, `GraphQL SERVICE_UNAVAILABLE → null`, `INTERNAL_SERVER_ERROR → null`.

## Fix

On writes, treat `SERVICE_UNAVAILABLE` and `INTERNAL_SERVER_ERROR` as `ledgerWriteUnconfirmed` ("The server didn't confirm the save. Check before trying again.").

**Acceptance:** these codes on a write show the unconfirmed message. A unit case is added.

# A trailing decimal point ("123.", "5.") is refused with a red error, including in the middle of typing "123.50"

**Severity:** minor. **Estimate:** 15 minutes. Owner: mobile.

**Root cause (A3).** `parseExactAmount` (`mobile/src/screens/multi-postings-transaction/postings-utils.ts`) returns `null` for a number that ends in a decimal point, although Beancount accepts `123.` and `5.`. The form treats `null` as invalid: the amount turns red, the Remainder shows "—", the message "Use digits and one decimal point, like 1234.56" appears and Done is disabled. w21/075 and w21/792 made `.5` and `,5` work; the trailing-point case wasn't covered.

**Native (iPhone 17e, 2026-10-24).** New Transaction → first amount, using the decimal-pad keys: typing `1`, `2`, `3`, `.` shows "123." in red with the error line and Remainder "—". Typing `5`, `0`, `5` after it gives "123.505", which is green and accepted, so the red state is only the step in between. I discarded the draft.

**`tsx` proof (the real `parseExactAmount`):** `"123."` → `null`, `"5."` → `null`, while `"123"` → `"123"`, `"123.5"` → `"123.5"` and `".5"` → `"0.5"`. A pasted `5.` is refused the same way.

## Fix

Read a trailing decimal point as complete (`"123."` → `"123"`, `"5."` → `"5"`), or at least don't show the error while the field is focused and the text ends in a point.

**Acceptance:** `parseExactAmount("123.")` is `"123"`; typing `1`, `2`, `3`, `.` leaves the field neutral (no red, no error line); `"."` alone is still refused.

## Dedupe

w21/075 (leading ".5") and w21/792 (",5") are the neighbouring cases. Searched `.pm/w21/**` for "trailing decimal", "mid-typing" and "123.".

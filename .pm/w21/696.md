# Reports' Recent Transactions says "No transactions yet" when the only income or expense is next month's (w21/669 vs w21/266)

**Severity:** trivial (empty-state wording). **Estimate:** 10 minutes. Owner: mobile. A3: w21/669 bounded the card's fetch at month-end (`select-account-transactions.ts:154`). `hasAnyAccountTransaction` (`account-transactions-card.tsx:138-140`) now looks only inside that window. A ledger whose only income or expense is dated next month therefore reads "No transactions yet" on 1M–1Y, instead of w21/266's "No transactions in this range". ALL lists the row.

Proven under `tsx` (the agent ran it): with opens plus `2026-11-01 * "QA Landlord" "nov rent"` (Expenses:Rent 1500.00 USD / Assets:Bank), the 1M window is `0001-01-01 - 2026-10-31`. 0 rows come back, so `hasAny` is false and the card says "No transactions yet". With the old unbounded fetch, `hasAny` was true. Not run natively, because the QA ledger always has past expenses, so this needs an empty ledger.

## Fix

Decide "any transaction at all" from an unbounded count (or the ALL fetch), not from the bounded page.

**Acceptance:** with this fixture, 1M reads "No transactions in this range" and ALL lists the November rent. A unit case is added.

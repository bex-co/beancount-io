# The Ask-AI screen hard-codes `keyboardVerticalOffset={96}` instead of using the shared stack offset

**Severity:** low. **Estimate:** 10 minutes. Owner: mobile.

**Root cause (A3).** `mobile/src/screens/agent-screen/agent-screen.tsx:284` has `keyboardVerticalOffset={Platform.OS === "ios" ? 96 : 0}`. The rest of the app uses `useStackKeyboardOffset()` (`insets.top + 44`, `src/common/hooks/use-stack-keyboard-offset.ts`), which w3/215 introduced for Server settings and Profile; the Ask-AI screen was missed. The literal matches the real value only on one inset size: an iPad's top inset is about 24 pt against about 59 pt on a notched iPhone, so the correct offset is about 68–74 and the composer would float roughly 22–28 pt too high above the keyboard. I did not measure this; the numbers come from the insets.

The Ask-AI feature is disabled on purpose (`config.features.agentChat: false`), so this only matters once it ships. Not run natively for that reason.

## Fix

Use `useStackKeyboardOffset()`.

**Acceptance:** a source test that `agent-screen.tsx` contains no numeric `keyboardVerticalOffset` literal.

## Dedupe

Searched for "keyboardVerticalOffset", "useStackKeyboardOffset" and "agent-screen". w3/215 and w3/211 cover only the other two screens.

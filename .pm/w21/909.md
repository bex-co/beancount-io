# Update Budget on a budget that hasn't started yet can't be dated earlier than its start

**Severity:** minor. **Estimate:** 20 minutes. Owner: mobile.

**Root cause (A3).**
- When every entry is in the future, `groupBudgetEntries` uses the earliest one as a preview.
- `budgetInEffectDate` (`mobile/src/screens/budget-screen/selectors/budget-selectors.ts:800-803`) returns that future date.
- `budget-screen.tsx:148` passes it as `currentDate`.
- `updateBudgetDates` makes that date both the picker's floor and its starting date (`add-budget-screen.tsx:228, 462`).

The floor exists because, per w21/623, an earlier date would never take effect. That reason doesn't apply here: an entry dated today takes effect today.

Not run natively in this pass. Proven with `tsx`: for a single 2026-11-01 entry with today 2026-10-23, the picker's minimum and initial date are both Sun Nov 01 2026. An extra entry dated today would become current, and October would budget 222.58.

**Native steps:**
1. Add `2026-11-01 custom "budget" Expenses:Food "monthly" 300 USD`.
2. Go to Budget, tap Update, then open the date picker.

No day before Nov 1 can be chosen.

## Fix

When no history entry is dated on or before today, set no floor and start the picker on today.

**Acceptance:**
- For a budget that hasn't started, Update starts on today and accepts it.
- For a budget already in effect, w21/623 and w21/661 behave as before.

w21/661 named the earliest future entry as its fallback without weighing this case, so an owner's yes may be needed. Searched for "budgetInEffectDate" and "updateBudgetDates", and checked w21/623, w21/661 and w21/765.

# Pasting " 20" (with a leading space) into a negative row turns it unreadable, and Done is refused (left open by w21/791)

**Severity:** minor. **Estimate:** 5 minutes. Owner: mobile. A3: `postings-utils.ts:82-89` (`typedAmountInput`) passes the untrimmed input to `signedAmountInput(input, …)`, giving `"- 20"`, which `parseExactAmount` rejects. w21/791's resolution says unsigned digits keep the row's sign, and w21/232 says pasted spaces are tolerated.

Reproduced natively with w21/853's build; the draft was discarded. New Transaction ▸ row 1: type 12.50, then make it negative with the sign badge. Select its "12.50" ▸ Paste **" 20"**. The row shows a red **"20"** with no sign badge, Remainder shows "—", and **"Use digits and one decimal point, like 1234.56"** appears. Done is disabled.

## Fix

Pass the trimmed, mark-free `absolute` to `signedAmountInput(absolute, rowNegative)` instead of `input`.

**Acceptance:** " 20" pasted into a negative row reads −20. A unit case is added.

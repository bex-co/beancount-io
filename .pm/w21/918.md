# Opened offline the day after it was last viewed, Merchant detail shows its load-error header instead of the cached count and totals

**Severity:** minor. It is the same failure class as w21/184 and w21/513, which were fixed on Home. **Estimate:** 45 minutes. Owner: mobile.

This is a regression from w21/796.

**Root cause (A3).**
- `merchant-detail-screen.tsx:283-315` builds the meta, totals, weights and scheduled statements with `{ through: today }` or `{ after: today }`. Since w21/796, the BQL text, and so the Apollo cache key, changes every day.
- Offline, the next day's statements miss the persisted cache and fail. `composeMerchantStats(null, …)` then returns null.
- `fatalError = !stats && (metaError || totalsError)` (`mobile/src/screens/merchant-detail-screen/merchant-detail-screen.tsx:590`) replaces the header with "Couldn't load" and Retry. The cached rows still list below it.
- The directory has the same date-keyed reads: `payeeCountsThroughBql(today)` and `payeeSeriesCutoff(today)`. These fall back quietly: the counts include scheduled entries, and the Recurring section is lost.

Not run natively; this needs a day change while offline. `tsx` proof: on Oct 23 the statement is `…WHERE payee = "Blue Bottle" AND date <= 2026-10-23`, and on Oct 24 it is `…AND date <= 2026-10-24`. `composeMerchantStats(mapMerchantMeta(null), [])` returns `null`.

**Native steps:**
1. Open any merchant online.
2. On a later day, launch in airplane mode and open the same merchant.

The header shows the error with Retry, while its rows still list.

## Fix

Use one date-free statement per payee, such as `SELECT date, currency, sum(number) … GROUP BY date, currency` (and the same for weights), and split it at `today` on the client. This also cuts the reads from five to two. Alternatively, keep a stable month-end window, as w21/513 did.

**Acceptance:**
- After a day change offline, the header shows the cached count, totals and scheduled line.
- Online figures are unchanged.
- A unit test asserts that the statements don't depend on `today`.

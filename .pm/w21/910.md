# Two identical budget entries share one entry_hash, so both history rows are highlighted as current and share a React key

**Severity:** low. **Estimate:** 20 minutes. Owner: mobile.

**Root cause (A3).** The ledger's hash leaves out source position (w21/419), so entries with the same date, account, interval and amount get the same hash. Two places then treat the twins as one entry:
- `selectHistoryRows` marks every row whose hash matches the current entry as current (`budget-selectors.ts:791`).
- `mobile/src/screens/budget-screen/components/budget-history-rows.tsx:184` uses `key={row.entry_hash}`.

w21/524 fixed twin keys only for the Recent transactions cards.

**How twins get written:** open Update on a budget set today and save the same amount. The date floor is today, and nothing refuses an entry that changes nothing.

Not run natively in this pass. Proven with `tsx`: two identical 2026-10-23 300 USD entries give two rows with the same key, both `current=true`.

## Fix

- Key rows by hash plus position, as `journalRowKeys` does.
- Mark only the last same-date twin as current.
- Optionally, refuse an Update that changes nothing.

**Acceptance:** two identical entries give two rows, one highlighted, and no key warning.

# Mobile never attaches the scanned receipt image to the transaction it saves; the dashboard does

**Severity:** moderate (parity gap). **Estimate:** 30 minutes. Owner: mobile. A3: `use-receipt-workflow.ts:172-174` uses the upload only as model input. The form saves through `addEntries` with no `document` directive or link, and `receipt-capture-screen.tsx:64-67` deletes the photo on unmount. The dashboard saves through `insertReceiptTransaction` (`dashboard/src/features/receipt/hooks/use-receipt-workflow.ts`), which stores the receipt. Mobile's `InsertReceiptTransaction` operation was removed as dead code in w4/m12.

Not run natively (the save follows a parse, which spends AI quota). This is a code-level trace (the agent's).

## Fix

Carry the upload's `objectKey` into the form and save through `insertReceiptTransaction`, which already orders the document safely since w23/058.

**Acceptance:** a scanned receipt saved from mobile has its document attached, as on the dashboard. A source case is added.

## Dedupe

Not w23/058 (server orphan copies), w2/m47 (skills) or w21/585 (cache deletion). Searched `.pm/**` for insertReceiptTransaction together with mobile.

---

**Blocked 2026-10-24** — needs an owner design decision on what the receipt-saved transaction is. `insertReceiptTransaction` (what the dashboard uses, ordered safely since w23/058) takes one payee, one description, one amount and currency, an expense account, a payment account and a document account: exactly two postings. Mobile's form after a scan is the full multi-posting New Transaction (it can be edited into a split, given a tag, link or metadata, or have its accounts and date changed), and it saves through `addEntries`. Attaching the receipt therefore means either (a) saving the form through `insertReceiptTransaction` only while it is still a plain two-posting receipt entry and falling back to `addEntries` (no document) otherwise, or (b) extending `insertReceiptTransaction` (REST, GraphQL and MCP, with a backend-v2 deploy) to take the full entry, or (c) a separate `addEntries` plus a document directive written in the same commit. Each changes what a scan saves and which surface owns it. The upload's `objectKey` also has to survive the route hop and the unmount cleanup (w21/585), and the temp object expires on its own.

**Unblock:** the owner chooses (a), (b) or (c); then this note is workable in `mobile` (and `backend-cluster/backend-v2` for (b)/(c)). Clearable by the owner only.

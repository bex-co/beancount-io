# Delete Account: if local sign-out throws after the server deleted the account, the user gets no feedback

**Severity:** minor. **Estimate:** 15 minutes. Owner: mobile.

**Root cause (A3).** `runAccountDeletion` (`mobile/src/screens/setting/delete-account.ts`) runs `await signOut()` outside any try, after `deleteAccount()` returned true (`:18-23`). In `setting/main-content.tsx`, `handleDeleteAccountConfirm` calls `handleDeleteAccount()` (`:120-130`) with no await and no catch. If `actionLogout` rejects (the same cause as w21/967), there is no success toast, no failure alert and no redirect. The account is already gone, and the user sits on Settings with an invalid session.

Not run natively: deletion is out of bounds for this session, and the failure can't be forced. `tsx` proof: with `deleteAccount` returning true and `signOut` throwing, `runAccountDeletion` rejects instead of returning "deleted".

## Fix

- Treat a `signOut` failure as `"deleted"`.
- Force the session clear and navigate to Welcome regardless.
- Catch in `handleDeleteAccountConfirm`.

**Acceptance:** `runAccountDeletion` with a throwing `signOut` resolves "deleted".

# A ledger renamed on the web appears twice in the drawer, and the "current" row keeps the old name; per-ledger state stays under the old id

**Severity:** minor. **Estimate:** 30 minutes. Owner: mobile. A3: the server answers the old name through the host's redirect (w23/061) and returns the new canonical id. Neither the splash check (`splash-provider.tsx:124-131`) nor the drawer (`account-ledger-drawer.tsx:14-28`, `drawer-ledgers.ts:33-58`) moves the saved selection to that id. The drawer's match fails, so it synthesizes a "Current ledger" row from the old id.

Not run natively: it needs a ledger rename on the web. Under `tsx` (the agent's proof), a saved selection `qa/personal`, a directory `[qa/budget, qa/personal-2025]` and a server reply of `qa/personal-2025` make the drawer render `[Current ledger · qa] personal (selected)` above `[qa] budget, personal-2025`, with the real row not marked current. Browse ledgers marks no row "Current". Tapping `personal-2025` drops Recent accounts, recurring marks and filters, which are keyed under `qa/personal`.

## Fix

When `GetLedger` returns a different id, move the selection to it and re-key the per-ledger state (`renameLedgerKeys`), as Profile's username rename already does. Do this in the splash check and the drawer.

**Acceptance:** after a web rename, the drawer shows one row, under the new name and marked current, and per-ledger state follows it. A unit case is added.

# A failed shutter tap gives no feedback on iPad or with System Haptics off, and a camera that never starts gives no message

**Severity:** minor. This is an acceptance gap left by w21/873. **Estimate:** 20 minutes. Owner: mobile.

**Root cause (A3).** The only feedback for a failed `takePictureAsync` is `haptics.error()` (`mobile/src/screens/receipt-capture-screen/camera-view.tsx:151-156`). Haptics can silently do nothing (`common/haptics.ts`): iPads have no Taptic Engine (`app.json` sets `supportsTablet: true`), and users can turn System Haptics off.

`ExpoCameraView` (`:230`) has no `onMountError`. When the camera can't start, for example on iPad in Split View or Slide Over, the preview stays black and every tap fails silently. "Choose from photos" is the only way forward, and nothing points to it.

Not run natively: on the simulator, capture returns a generated photo, so the failure can't be triggered (as w21/873 noted). Proven from the code path.

## Fix

On a capture failure and on `onMountError`, show an announced inline message alongside the haptic, for example "Camera isn't ready. Try again or choose from photos."

**Acceptance:** a failed capture and a mount error both render visible text that VoiceOver announces.

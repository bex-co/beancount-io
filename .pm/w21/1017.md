# In Persian, the period pills use Latin digits inside Persian labels ("1م", "3م", "6م", "1س") while every other number on the same screen is written in Persian digits

**Severity:** minor (fa; consistency). **Estimate:** ~20 minutes. Owner: mobile. A3: `mobile/src/translations/fa.ts` lines 491–502 write the digits of `range1M`, `range3M`, `range6M`, `range1Y` and the four `rangeSpoken*` strings as Latin text, so they bypass `localizeDigits`, which the formatted numbers go through (`mobile/src/common/number-utils.ts`, `date-format.ts`; w21/882, w21/884, w21/933).

iPhone 17e, iOS 27.0, dev build `io.beancount.ios`, `main` at `2fd7c126d`, a synthetic example ledger, default text size, light mode.

1. Settings, Language, choose **فارسی**, confirm, and accept "restart now" (or relaunch the app to apply right-to-left).
2. Open Home or Reports and read the period pills under the chart. (A screenshot is kept locally and is not committed.)

The pills read `1م`, `3م`, `6م`, `از آغاز سال`, `1س`, `همه` with Latin digits 1, 3 and 6. The card above them shows `$۱۱۸,۳۹۰,۵۱`, `+$۷۴۲,۰۲ (+۰,۶۳%)` and `۲ اکتبر ۲۰۲۶` in Persian digits, so the pill row reads as a different numeral system from the card around it.

**Expected:** the pills follow the rule w21/884 recorded ("a language renders its own digits"): `۱م`, `۳م`, `۶م`, `۱س`, and the spoken labels `۱ ماه`, `۳ ماه`, `۶ ماه`, `۱ سال`.

## Fix

Write those eight Persian strings with Persian digits, or compose them from a count through the same `localizeDigits` path. Add a unit case that no `fa` range label contains a Latin digit.

**Acceptance:** in Persian, the pills on Home, Reports, the account detail chart and the Budget screen read with Persian digits, the spoken labels match, and the pill row still fits at AX2.

**Out of scope on purpose:** the input examples at `fa.ts` lines 727, 890 and 894 (`500 یا 49.99`, `100 یا -30.50`, `2026-01-01`) show the syntax the fields accept (w4/1057), so they stay Latin.

## Blast radius

The same keys feed Home, Reports, the account detail chart and the Budget screen, so one change covers all of them. Adjacent states: Chinese renders `近6月` with Latin digits, which is the normal Chinese convention and is unaffected. Unverified: Android, and how VoiceOver reads the spoken labels.

## Dedupe

Searched `.pm/**` and `mobile/.pm/**` for `range1M`, `rangeSpoken`, `1م`, pill and Persian digits. `w21/884` (chart labels) and `w21/933` (chart ticks) fixed other places and do not mention the pills; `w4/066` and `w4/1005` are right-to-left layout problems.

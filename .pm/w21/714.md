# Delete Account's phrase field shows "Type the phrase exactly as shown." from the first correct letter (w21/158 regression)

**Severity:** trivial (a red error, also read aloud by VoiceOver, while the user is typing correctly). **Estimate:** 10 minutes. Owner: mobile. A3: `setting/delete-confirmation.ts:14` returns the mismatch message for any non-empty text that isn't the full phrase, including a correct prefix. `TextInputModal` (`components/text-input-modal/index.tsx:199-202, 254`) renders it immediately, and `InlineError` announces it (`inline-error/index.tsx:27`). w21/158's acceptance said "a wrong phrase shows the reason"; a correct prefix isn't a wrong phrase.

Native (iPhone 17e, Metro `--clear` at `73ba21123`; nothing submitted): drawer ▸ account row ▸ Settings ▸ Delete Account ▸ **Delete Account** in the alert, which only opens the phrase field (`main-content.tsx:224`). Typing "s" shows "**Type the phrase exactly as shown.**" in red under the field. Cancelled. Under `tsx` (the agent's proof), "s", "sudo" and "sudo delete my" all return the mismatch message.

## Fix

Show the error only when the text is not a prefix of the phrase (case-insensitive, as the check is), or only after a blur or submit attempt. Keep the confirm button disabled until the phrase matches.

**Acceptance:** typing the phrase letter by letter shows no error. A wrong letter ("sx") shows it. A unit case is added.

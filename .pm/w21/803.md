# One transient server error turns off profile photos until the app restarts

**Severity:** trivial. **Estimate:** 10 minutes. Owner: mobile. A3: `mobile/src/common/hooks/use-current-user.ts` adds the server to `serversWithoutAvatars` on any GraphQL error (`graphQLErrors.length > 0`). The backend returns transient failures (`SERVICE_UNAVAILABLE`, `RATE_LIMITED`, `INTERNAL_SERVER_ERROR`) as GraphQL errors with HTTP 200 (see w21/182). After one such failure, the avatar query is skipped for the rest of the process: the drawer, Settings and Profile show initials, and Profile's "Photo from Gravatar" caption disappears.

Not run natively: it needs a server error. This is the agent's code-path trace.

## Fix

Mark a server as having no avatar field only when `isUnsupportedDocumentError(error)` matches, the unknown-field check already used in `ledger-errors-read.ts`.

**Acceptance:** a transient error doesn't disable avatars, and an unknown-field error still does. A unit case is added.

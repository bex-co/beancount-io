# The new clash refusals for a folder used as a file name use "file" wording, and the file branch for a case twin is unreachable (w21/988 regression)

**Severity:** low. **Estimate:** 15 minutes. Owner: mobile. This is a regression of w21/988 (`504791d12`).

**Root cause (A3).** In `checkLedgerFileName` (`mobile/src/screens/ledger-file-browser-screen/utils.ts`, about `:130-148`), a name that equals a *folder* returns `issue: "exists"`, which the dialog (`index.tsx`, about `:522`) renders as `ledgerFileNameExists` ("A file named … already exists"). The earlier case-twin check (about `:130`) uses `existingNames`, which already includes files, so the new `kinds.files` branch is never reached for case twins.

Not run natively in this pass. `tsx` proof (the agent's, real helper):
- `checkLedgerFileName("x", ["main.bean","x.bean"], {files:["main.bean"], folders:["x.bean"]})` gives `{issue:'exists', existing:'x.bean'}`, so the dialog says "file" for a folder.
- `checkLedgerFileName("Main.bean/x", ["main.bean"], {files:["main.bean"]})` gives `folderExists` ("A folder named main.bean…") for what is a file.

## Fix

Add a `folderExists`-style issue for the folder-used-as-file case, and make the case-twin check word its message by kind (folders only for `folderExists`).

**Acceptance:** a folder `x.bean` with input `x` returns the folder wording, and a file `main.bean` with input `Main.bean/x` is reported as a file.

Searched for `ledgerFileNameExists`, `folderExists` and `kinds.folders`; the original fix is done w21/988.

## Objective

Find the transactions the engine reports a `BOOK` error for (for example "No matching lot") and give each a not-booked mark in the snapshot, so every consumer can tell them from booked entries.

## Context

- `backend-cluster/ledger/src/foundation/rustledger/engine.ts` keeps rustledger's `raw.directives` unchanged, failed-booking entries included
- `book-errors.ts` (`locateBookErrors`) already pairs `BOOK` errors with a transaction by date and narration; twins are told apart by order
- Fixture: the QA Buy / QA Sell example in the milestone README

## Steps

1. Pair each `BOOK` error with its directive (reuse the date + narration + order rule); leave unpaired errors as they are.
2. Record the marked directives on the frozen snapshot (a parallel index, like `generated`), not in the directive's own fields.
3. Unit case: the fixture marks QA Sell and nothing else; two same-day twins mark the right one.

## Files

- `backend-cluster/ledger/src/foundation/rustledger/engine.ts`
- `backend-cluster/ledger/src/foundation/rustledger/book-errors.ts`

## Acceptance criteria

- [ ] With the fixture the snapshot marks exactly the QA Sell transaction.
- [ ] A ledger with no booking errors is unchanged.

## Out of scope

- Unrelated booking behavior of the engine.

## Shipped

The engine marks a transaction the engine reports a `BOOK` error for (`unbookedTransactions` in `book-errors.ts`; a `WeakSet` mark in `plugins/provenance.ts`, carried across the worker as `snapshot.unbooked`); twins are marked only when the error count matches. Checked against the real engine on the fixture: only QA Sell is marked.

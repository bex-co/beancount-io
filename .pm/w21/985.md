# A push whose only commit has an empty message now produces a bare "+1 more commit(s)" line (w21/963 regression)

**Severity:** low. **Estimate:** 10 minutes. Owner: backend-v2. This is a regression of w21/963 (`2aca9a493`).

**Root cause (A3).** In `backend-cluster/backend-v2/src/features/gitea/feed/service/activity-content-parser.ts` (the `push` case, about `:306`), `remainder = parsed.totalCount - lines.length` is positive even when `lines` is empty, so the suffix `\n+N more commit(s)` is emitted with nothing above it.

Not run natively in this pass (backend-v2 has no installed packages here and isn't redeployed). `tsx` proof (the agent's): `summarizeParsedContent` gives `"\n+1 more commit(s)"` for one empty-message commit and `"\n+3 more commit(s)"` for three; before the change both gave `""`. The mobile `pushSummary` (`feed-logic.ts:198`) returns null when no commit line is listed, so the row shows the English `+1 more commit(s)` text raw, in every language.

## Fix

Return `""` when `lines.length === 0`, or emit the suffix only when `lines.length > 0`.

**Acceptance:** a test with `commits=[""]` and `totalCount=1` expects `""`.

Searched for "more commit(s)" and "empty message". w21/716 and w21/731 are related.

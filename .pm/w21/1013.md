# The Accounts tab breaks a long account name mid-word at the largest supported text size ("Bank:Mercury:Checkin" / "g")

**Severity:** minor (cosmetic; the whole name is still there, but a word is split). **Estimate:** ~30 minutes. Owner: mobile. A2: at AX2 (`accessibility-large`) the Accounts tab renders each row in its stacked layout. `mobile/src/components/account-table/account-table.tsx` (the `stacked ? …` branch, around lines 366–382) renders `<Text style={[styles.stackedName, …]}>{label}</Text>` with no line limit and no break opportunities, so a colon-joined name is one unbroken token and wraps wherever the line ends. The wide branch (around line 404) uses `numberOfLines={1}` with `ellipsizeMode="middle"` and is fine.

iPhone 17e, iOS 27.0, dev build `io.beancount.ios`, `main` at `434d05dc6`, a synthetic example ledger. Judged on a **cold launch**: a live text-size change leaves stale native measurements (`mobile/AGENTS.md`), which clipped other labels that then rendered correctly after a relaunch.

1. `xcrun simctl ui <udid> content_size accessibility-large`.
2. Terminate and relaunch the app, then dismiss the development warning banner.
3. Open the Accounts tab with the Assets group expanded.
4. The leaf `Assets:Bank:Mercury:Checking` reads "Bank:Mercury:Checkin" on one line and "g" on the next. (A screenshot is kept locally and is not committed.)

Not an AX3–AX5-only finding (`.pm/DO_NOT_DO.md`): it reproduces at AX2.

## Fix

In the stacked branch, give the displayed label break opportunities after each `:` (a zero-width space, `​`, inserted into the displayed string only; keep the real name for accessibility labels, search and navigation), so lines break at account-segment boundaries. Alternatively cap the name at two lines with a head or middle ellipsis that keeps the leaf. Either way a word is never split.

**Acceptance:** at AX2 on a cold launch, `Assets:Bank:Mercury:Checking` and `Expenses:Food:Groceries` wrap only at a `:` (or end in a head/middle ellipsis that keeps the leaf); the wide layout at default size is unchanged; a unit case covers the label transform, including a name with no colon.

## Blast radius

The same unbroken-token mechanism was noted in w21/029's 2026-10-21 native recheck for New Transaction ("Assets:Bank:Checkin / g", "Expenses:Food:Groc / eries"), which suggested the same `​` follow-up and was never filed. Check the other consumers of `stackedName` and `prefersStackedLayout`: the account picker, the account detail header and the posting rows. A shared helper that returns a break-friendly label would fix them together. Adjacent states: the wide layout at default size renders the middle ellipsis correctly. Unverified: Android, other locales, right-to-left (Persian).

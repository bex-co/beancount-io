# The new AVERAGE error has no file or line when a same-day transaction shares the sale's narration, or the sale has no strings, so it can't be tapped (w21/708 gap)

**Severity:** minor. **Estimate:** 20 minutes. Owner: ledger. A3: `average-booking.ts:58-59` raises the error without a location and relies on w21/534's locator. That locator gives up when the counts of errors and matching transactions differ (`book-errors.ts:80`), and it skips transaction lines with no quoted string (`:45`). Notifications then shows the row with no location, and it can't be tapped (`notifications-screen.tsx:192`, `canFix = !!err.filename`).

Proven with the real engine under ts-node at `HEAD` and at the parent of the fix commit (as `yarn verify:rustledger` runs it), against Beancount 3.2.3 `bean-check`. Not on production: the ledger service hasn't been redeployed since before w21/675.

A sale `2024-06-01 * "Vanguard" "Rebalance"` of `-5 VTI {} @ 120 USD` on an AVERAGE account, plus a second `2024-06-01 * "Vanguard" "Rebalance"` buying BND. The engine gives `BOOK null:null`, while bean-check reports main.beancount:8 "AVERAGE method is not supported". A sale written as `2024-06-01 *` with no strings also gives null:null (bean-check: line 7).

## Fix

Raise the AVERAGE error with the posting's own location (the engine knows which directive it is checking), instead of locating it afterwards by text.

**Acceptance:** both variants report the sale's file and line, and the notification row opens it. A unit case is added.

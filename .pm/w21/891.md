# Reports' range chips scroll the selected chip into view only on first paint: tapping the cut-off "AL" chip at AX2, or a range set from Home's See all, leaves the selection off-screen

**Severity:** minor (accessibility text sizes). **Estimate:** 15 minutes. Owner: mobile. A3: `components/time-range-pills/index.tsx:237-240, 279-287`. `revealSelected` runs once on first layout and is then locked by `revealedRef`; a chip's `onPress` only moves the highlight. A range set from outside (`requestedReportsRange`, from Home Spending's See all) and a live text-size change don't re-reveal either. (w21/886 said the range chips "already do this"; they do only on first paint.)

Not run natively in this pass. At AX2, the Reports strip draws "AL" cut off at the right edge (seen in the AX2 sweep earlier today); per the agent's trace, tapping it selects ALL while the highlight stays clipped. At the default size, the English chips fit (w2/039).

## Fix

Call `selectedPillRevealOffset` and `scrollTo` from `onPress` and from an effect on `value`, covering overflow on the right as well as the left.

**Acceptance:** at AX2, tapping "AL" scrolls the ALL chip fully into view, and an externally set range is scrolled into view. A source case is added.

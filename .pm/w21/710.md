# The balance sheet without a time filter has no Equity:Conversions, so assets, liabilities and equity don't net to zero in a multi-currency ledger

**Severity:** minor (API, MCP and dashboard consumers; the mobile query doesn't select equity). **Estimate:** 45 minutes. Owner: ledger. A3: `ledger-finance-service.ts:228` and `:258` handle the unfiltered path (`:417` returns no clamp). `closeCurrentEarnings` moves earnings only. It lacks the conversions step Fava's `Tree.cap` performs (the repo's port is `cli/src/fava/core/tree.py:282-296`), and the at-value Unrealized line too. With `time` set, the clamped path adds Conversions and balances.

Production, through GraphQL on the disposable ledger (restored byte-for-byte afterwards), and the agent's run of the real `main` service code against Beancount 3.2.3 `bean-check`/`bean-query`.

The QA ledger plus

```
2024-01-01 open Assets:Qa20261020Usd
2024-01-01 open Assets:Qa20261020Eur
2024-01-01 open Expenses:Qa20261020Travel
2024-01-01 open Equity:Qa20261020Open
2024-01-02 * "QA fund"      ; Usd +1000 USD, Open -1000 USD
2024-01-03 * "QA Exchange"
  Assets:Qa20261020Eur  100 EUR @@ 110 USD
  Assets:Qa20261020Usd  -110 USD
2024-01-04 * "QA Hotel"     ; Travel 50 EUR, Eur -50 EUR
```

`getLedgerBalanceSheet(conversion:"at_cost")`:

- **No `time`:** Assets + Liabilities + Equity = **USD −110.00, EUR +100**. The equity tree has no Conversions account.
- **`time: "2024"`:** the same sum is **0 / 0**, with Conversions present.

The agent's at-value run also misses Unrealized gains (a NONE-booking broker worth 3000 against a cost of 1500 leaves assets 8000 against equity −6500, with or without `time`).

## Fix

Apply the same cap (Conversions:Current, and Unrealized at value) on the unfiltered path as on the clamped one, mirroring Fava's `Tree.cap`.

**Acceptance:** with this fixture, the unfiltered balance sheet nets to zero per currency and lists Conversions. The at-value case includes Unrealized. Parity holds across GraphQL, REST and MCP. A unit case is added.

The w6/m5 README left conversions and unrealized gains unverified. Searched `.pm/**` for "Conversions", closeCurrentEarnings and Tree.cap.

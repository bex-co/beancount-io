# A successful save can still land on "This transaction was changed or removed"

**Severity:** moderate. The save is written, but the screen says the entry is gone. **Estimate:** 20 minutes. Owner: mobile. A3: `mobile/src/screens/edit-transaction-screen/edit-transaction-screen.tsx:511` decides the exit with `resolveSaveExit(targetEntryHash, saved.entryHash)`, where `targetEntryHash` comes from `entryHashRef.current`.

**How the IDs get out of step.**
- `entryHashRef` moves to a new ID in two cases: a save that stays on screen because the user kept typing (`applySavedIdentity`, about `:437`), or Reload finding the entry under a new ID (`:292`).
- The detail screen behind still holds the route's original ID, H1.
- A next save that keeps the ID (a comment, metadata or posting order) returns H2, equal to the target, so the exit is "unchanged".
- The screen then clears the draft, re-reads H2 (`:546`), and goes `router.back()` (`:553`) to the detail screen still keyed on H1.
- That screen's focus refetch gets NOT_FOUND for H1 and shows the removed state.

Not run natively; steps 2–3 need an outside change made at the right moment. `tsx` proof: after `applySavedIdentity({entryHash:"H1"}, {entryHash:"H2"})`, `resolveSaveExit("H2","H2")` returns `{kind:"unchanged"}`, while the screen behind holds H1. Compared with the route's ID instead, `resolveSaveExit("H1","H2")` returns `{kind:"detail", entryHash:"H2"}`, which is correct.

**Native steps** (w21/823's setup):
1. Open a disposable entry ▸ Edit ▸ paste a changed version.
2. Change the entry through the API.
3. Save ▸ Copy & Reload.
4. Paste `  ; checked` under the postings ▸ Save.

**Expected:** the detail screen shows the entry. **Actual:** "This transaction was changed or removed."

## Fix

Decide the exit against the route's `entryHash`, which the detail screen holds. Any saved ID that differs from it takes the `dismissTo` "detail" path.

**Acceptance:**
- Route H1, target H2 and saved H2 resolve to `detail`/H2.
- A stay-on-screen save followed by a comment-only save returns to a detail screen keyed on H2.

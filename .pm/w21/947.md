# Adding a budget for an account that already has one skips Update's safeguards

**Severity:** minor. **Estimate:** 20 minutes. Owner: mobile.

**Root cause (A3).** `mobile/src/screens/add-budget-screen/add-budget-screen.tsx:213-214` treats a request as an Update only when the `account` route parameter is present. Reaching the same account and currency through + and the picker gives:
- no minimum date (w21/623);
- the stock "500" placeholder instead of the current amount;
- no note that a budget already exists.

Not run natively in this pass. `tsx` proof: the current entry is `2026-10-01` monthly 600 USD. An Add for the same account, dated 2026-09-15 at 300, writes that directive. On 2026-10-23 the 600 USD budget is still in effect, with history `[09-15 300, 10-01 600]`. That is w21/623's "saves but changes nothing" result, reached through Add.

## Fix

When the picked account and currency match an existing budget:
- apply `updateBudgetDates(budgetInEffectDate(group))`;
- show the current amount as the placeholder;
- add a "Replaces the current budget" note.

Alternatively, switch the form into Update mode.

**Acceptance:**
- Picking an account and currency that already have a budget limits the date to its in-effect date or later, and shows its amount.
- A new pair behaves as it does today.

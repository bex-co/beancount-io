# Log out can fail halfway and leave the user signed in with a revoked token, with no message

**Severity:** minor. **Estimate:** 20 minutes. Owner: mobile.

**Root cause (A3).** `clearServerScopedState` (`mobile/src/common/server-url-actions.ts:44`) awaits `clearPendingAuthorization()` (a SecureStore delete) before `sessionVar(null)`. `performLogout` (`src/screens/setting/logout-action.ts`, the `clearLocalState` call) doesn't catch a failure there, although its comment says local isolation "always completes".

If that delete rejects (Keychain unavailable or locked), nothing is cleared, `markSignedOut` never runs and the session stays in place. The server-side revoke has already happened. The Log out `onPress` in `setting/main-content.tsx` has `try { await actionLogout…; router.replace } finally {…}` and no catch, so the spinner stops, there is no navigation and no message, and an unhandled rejection is raised. The user stays "signed in" on a dead token until the next 401 triggers teardown.

Not run natively: a Keychain failure can't be forced on the simulator. `tsx` proof: the real `performLogout` with `clearLocalState` throwing rejects with `markSignedOut ran: false`.

## Fix

- Wrap each step of `clearServerScopedState` so a failing step can't skip `sessionVar(null)`, for example `clearPendingAuthorization().catch(() => {})`, or move it after the session clear.
- Catch in the Log out handler, and still route to Welcome.

**Acceptance:** `performLogout` with a throwing `clearPendingAuthorization` still ends with `sessionVar() === null`, `markSignedOut` called and no rejection.

**Resolved 2026-10-24** — Log out always completes locally: `clearServerScopedState` treats the pending-authorization delete as best effort, so a Keychain that will not delete it no longer skips `sessionVar(null)`; `performLogout` goes on to `markSignedOut` when `clearLocalState` throws, instead of rejecting; and the Log out handler catches whatever is left and still routes to Welcome. Cases in `logout.test.ts` (the throwing wipe, the best-effort delete and the handler order pinned in source; they fail without the change) and `error-handling.test.ts` follows the new line (`mobile`).

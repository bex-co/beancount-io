# The New Ledger name limit is checked on the typed text, but the server checks the slug, so some valid names are refused

**Severity:** low. **Estimate:** 10 minutes. Owner: mobile.

**Root cause (A3).** `mobile/src/screens/create-ledger-screen/create-ledger-screen.tsx:234` uses `.max(100, t("createLedgerNameMaxLength"))` on the raw name. The server's limit is 100 characters after slugifying (`backend-cluster/ledger/src/shared/ledger-name.ts`, `validateLedgerName`: "Maximum is 100 characters after transformation"). Slugify trims leading and trailing hyphens and spaces and drops characters outside `[a-z0-9_-]`, so a long typed name can slugify to 100 characters or fewer.

Not run natively in this pass; creating a ledger is off limits here, and the check is refused before anything is sent. `tsx` proof (the agent's, with the real `slugifyLedgerName` and `isNewLedgerName`): `"a".repeat(100) + "  "` has raw length 102 and slug length 100, and `isNewLedgerName` is true. The form's `.max(100)` rejects it with the "name too long" message, while the server would accept the 100-character slug. A name over 100 characters with punctuation or emoji that slugifies to 100 or fewer behaves the same.

**Native steps:** drawer → New → paste exactly 100 `a` characters followed by two spaces. The field shows the max-length error and Next is refused. Do not submit.

## Fix

Validate the length on `slugifyLedgerName(value)`, and keep the minimum check as it is.

**Acceptance:** a unit test where `"a".repeat(100) + "  "` passes the schema and `"a".repeat(101)` fails.

# Symlinks in a ledger repo show as plain files and open as "too large to open on your phone"

**Severity:** minor. The message is wrong, and a symlinked folder can't be browsed. **Estimate:** 30 minutes. Owner: mobile, plus the ledger service.

**Root cause (A3).**
- **Ledger service:** it passes Gitea's `type` through unchanged (`backend-cluster/ledger/src/api/files.ts:42`, `toFileContentPublic`); Gitea returns `file`, `dir`, `symlink` or `submodule`. For a symlink, Gitea fills `target` and leaves `content` null, and `size` is the length of the target path (`gitea-api.ts:531-553`). `withLargeContent` (`files.ts:73`) fetches raw bytes only for `type === "file"`.
- **Mobile file list:** it only tells `"dir"` apart from everything else (`mobile/src/screens/ledger-file-browser-screen/index.tsx:257` and `:738`). A symlink named `prices.bean` or `2024` therefore passes `isEditableTextFile` and opens the editor.
- **Editor:** `isUnreadableLargeFile(null, 22)` (`src/common/ledger-file-content.ts:39`) is true, so the editor (`ledger-file-editor-screen/index.tsx:480`) shows "This file is too large to open on your phone…".

Not run natively. A symlink needs a git push to a disposable ledger. `tsx` proof: for `{type:"symlink", name:"2024"}` and `{type:"symlink", name:"prices.bean"}`, `isDir` is false and the row is tappable as a file, and `isUnreadableLargeFile(null, 22)` returns `true`.

**Native steps** once a symlink exists:
1. In a disposable ledger, push `ln -s archive/2024 2024` and `ln -s shared/prices.bean prices.bean`.
2. Open Files: both appear as file rows with a chevron.
3. Tap `2024`: the editor opens with the "too large" read-only notice.

## Fix

- Give `symlink` and `submodule` rows their own icon and a note, such as "Link to archive/2024".
- Either make them not tappable, or resolve a target that stays inside the repo and browse or open it.
- In the editor, key the notice on the type rather than reusing "too large".
- Consider having `getLedgerFile` return `type` and `target`.

**Acceptance:**
- A `symlink` entry isn't opened as an editable file.
- The editor never shows `ledgerEditorTooLarge` for `{content:null, size:22, type:"symlink"}`.

## Dedupe

The only hits are CLI items: w3/329, w3/362 and w3/422. Searched for "symlink", "submodule", "too large to open", "ledgerEditorTooLarge" and "ln -s".

---

**Resolved 2026-10-24** — a `symlink` or `submodule` row in Files is no longer opened as an editable file: `isOpenableTextEntry` (`common/ledger-file-types.ts`) keys on the entry type as well as the name, the row gets a link icon and the existing dimmed "Can't be opened in the app" note, and the tap does nothing. Cases in `ledger-file-links.test.ts` (`mobile`). Deviations: links are not resolved or browsed, and the editor and `getLedgerFile` were not changed (a link no longer reaches the editor from the browser). Not run natively.

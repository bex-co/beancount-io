# A failing balance gets no "Off by" when another assertion on the account has the same amount (monthly "0.00" card checks)

**Severity:** minor (the common pay-in-full credit-card pattern). **Estimate:** 30 minutes. Owner: ledger. A3: `journal-serialize.ts:310` pairs E2001 errors with assertions by account, amount, currency and tolerance only. When more assertions than errors share that key, every one keeps `diff_amount: null`. The error carries a file and line, which would tell them apart. w21/087's resolution mentions this limit, but no item tracks it.

Production, through GraphQL on the disposable ledger (restored byte-for-byte; ledger service as deployed 2026-10-22), and the agent's run of the real `main` service code (`e911af9c8`) against an in-memory store, with `bean-check`/`bean-query` 3.2 as the reference.

A Liabilities:Qa20261020Card with `balance … 0.00 USD` on 02-01, 03-01 and 04-01. February is underpaid by 5.00 (−55 spent, +50 paid), and that is fixed on 03-25. `getLedgerErrors` reports "Balance failed for Liabilities:Qa20261020Card: expected 0.00 USD, got -5.00 USD", but all three Balance rows from `getLedgerAccountJournal` have `diff_amount: null`. The 03-01 row shows running balance −5.00 with no Off-by line.

## Fix

Match an error to its assertion by the error's source location (file and line, or entry hash), falling back to the current key.

**Acceptance:** the 03-01 row gets `diff_amount −5.00 USD` and shows "Off by". The 02-01 and 04-01 rows stay null. A unit case is added.

Limit noted in w21/087's resolution (done). Not the text-prefix matching parked as w21/180. Searched `.pm/**` for diff_amount, "Off by" together with "same amount", and journal-serialize.

# Home's Spending card says "No spending yet" on a ledger with months of spending, whenever this month and last month are empty

**Severity:** trivial. The copy claims the ledger has never spent, while Recent Transactions above it lists August purchases. **Estimate:** 10 minutes. Owner: mobile. A3: `home-screen/selectors/select-spending-compare.ts:155-169` (`noSpending`) looks only at this month and last month, and `components/spending-card.tsx:217-230` then shows `spendingEmpty` ("No spending yet", `translations/en.ts:502`). w21/418 wrote that copy for an empty ledger. The same text shows when a month's spending and refunds net to zero.

Not run natively: the card is below the fold. Under `tsx` (the agent's proof), with reference date 2026-10-23, `spendingWindow` gives 2026-09-01 – 2026-10-31. With Sep and Oct both empty, `selectSpendingCompare` gives 0 / 0 and `noSpending` is true. The disposable QA ledger itself has spending Jan–Aug and none in Sep–Oct, so it is in exactly this state. w21/418's native recheck saw "No spending yet" on it and accepted it, but that item's acceptance covered only an empty ledger.

## Fix

Scope the copy to the two months, for example "No spending this month or last month". Keep "No spending yet" for a ledger with no Expenses activity at all.

**Acceptance:** a ledger whose last spending was in August says the scoped text, and an empty ledger still says "No spending yet". A unit case is added.

## Dedupe

Follows w21/418 (done) and differs from w21/493 (other-currency spending). Searched `.pm/**` for noSpending, spendingEmpty, "No spending", dormant and "stale ledger".

**Resolved 2026-10-23** — When this month and last month show no spending, Home's Spending card now says "No spending this month or last month", a new `spendingEmptyRecent` in all 13 locales. It keeps "No spending yet" for a ledger that never spent. To tell them apart, the card reads the Expenses root's monthly totals over the whole span, but only in that empty state. The new `everSpent` (`home-screen/selectors/select-spending-compare.ts`) is false only when no month holds an amount in any currency. Until that read lands the card shows the scoped text, which is true either way.

A ledger whose last spending was in August now gets the scoped text, and an empty ledger still says "No spending yet". So does a month whose spending and refunds net to zero, since the scoped text says only what is known about the two months.

Unit and source cases are in `selectors/__tests__/select-spending-compare.test.ts` and `spending-conversion.test.ts` (the whole-span read uses the same conversion); four fail at the previous HEAD. Not checked natively (the card is below the fold). Shipped in the commit that moves this note.

# Same-day entries from different include files come back in the wrong order, so running balances are wrong ("+10 → 10" where Beancount gives 7)

**Severity:** moderate. **Estimate:** 30 minutes. Owner: ledger (affects REST, GraphQL and MCP). A3: `backend-cluster/ledger/src/foundation/rustledger/entry-sort-order.ts:39-50, 95`. `sourceLines` pools every file's line numbers under each `date|type` key, sorts them, and hands them out in the engine's order, so a main-file entry can take an included file's line number.

Proven on `main` (`053f4eb84`) against Beancount 3.2.3 `bean-query` (the agent's run; not deployed). `main.bean` includes `b.bean`. In `b.bean`, line 1 is `2024-01-05 * "inc-early-line"` (Cash −3) and line 4 is a note. In `main.bean`, line 9 is `2024-01-05 * "main-late-line"` (Cash +10). Beancount gives inc −3 → **−3**, then main +10 → **7**. The service gives main +10 → **10**, then the note, then inc −3 → 7. In the app, account detail would show "+10 → 10" for a row whose correct running balance is 7, and the journal and Entry Context order differ.

## Fix

Record each directive's real file and line (from `captureDirectiveSourceIds` or the block index) and sort by Beancount's `entry_sortkey` (date, type order, file, line).

**Acceptance:** this fixture orders as bean-query does. A unit case is added.

## Dedupe

The multi-file variant of w21/134 and w21/324 (done; single-file and plugin cases). Searched `.pm/**` for entry_sortkey, restoreEntrySortOrder and entry-sort-order.

---

**Resolved 2026-10-24** — `restoreEntrySortOrder` takes the entry point and collects each directive's source line only from the files the entry point loads, in the order the engine emits them (entry point, then its includes depth first, each file ascending) instead of pooling and sorting every file's lines, so a main-file entry no longer takes an included file's line number. Checked live against the engine on this note's fixture: inc-early-line, the note, then main-late-line, as bean-query orders them. Tests in `entry-sort-order.test.ts` (cross-file order; fail on the old pooling), shipped in the commit that closes this note (`backend-cluster/ledger`). Needs a ledger deploy to reach production. Also covers w21/844.

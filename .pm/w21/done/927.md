# Persian or Arabic account paths still read child before parent on New Transaction, Add Budget, Transaction Filters and the Open Account preview

**Severity:** minor. Right-to-left users see their account hierarchy backwards, including the name Open Account is about to write. **Estimate:** 20 minutes. Owner: mobile.

This is a third gap after w21/743 and w21/766.

**Root cause (A3).** These four places render the raw path without `isolateAccountPath`:
- The New Transaction posting row (`mobile/src/screens/multi-postings-transaction/multi-postings-transaction-screen.tsx:399-403`).
- Add Budget's Account row (`add-budget-screen.tsx:390`).
- Transaction Filters' account row (`transaction-filters-screen.tsx:399`).
- Open Account's "Will be created as {{account}}" preview (`open-account-screen.tsx:437, 541`). That screen pins its own input to left-to-right so the name reads root first (`:148-151`), and the preview just below it contradicts that.

The source check in `common/__tests__/bidi.test.ts` doesn't list any of these files.

Not run natively in this pass. Proof with CoreText through `swift`:
- `Expenses:خوراک:رستوران` lays out as `[Expenses:] [رستوران] [:] [خوراک]`, child first.
- In a right-to-left paragraph it is fully mirrored.
- Wrapped in `isolateAccountPath`, it reads root first in both directions.

**Native steps:**
1. On a throwaway ledger, open `Expenses:Qa20261024:خوراک:رستوران`.
2. Pick that account as a New Transaction posting, as a budget account, and as the Transactions account filter.

## Fix

At all four places, wrap the visible text in `isolateAccountPath`; for Open Account, wrap the `{{account}}` value. Keep plain paths in accessibility labels, as w21/766 did.

**Acceptance:** extend `bidi.test.ts`'s source check to these four files. Each case fails at the current HEAD.

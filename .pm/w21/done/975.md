# `queryDeduplication: false` is global, so screens that mount several hooks for the same query now send duplicate requests

**Severity:** moderate for performance and battery; latency worsens on slow networks. **Estimate:** 30 minutes. Owner: mobile. This is a side effect of w21/904 (`da6a7ef6e`).

**Root cause (A3).** `mobile/src/common/apollo/client.ts:37` turns deduplication off for every query. The default fetch policy is `cache-and-network` (`default-options.ts`), so each mounted `useQuery` asks the network once. Several hooks wrap the same query and mount together: `use-ledger-access`, `use-operating-currency`, `use-ledger-root-names`, `ledger-guard`, `account-ledger-drawer` and `spending-card` (`useLedgerReadContextQuery` and `useGetLedgerQuery`, 7 and 5 call sites). Deduplication used to collapse each group into one request.

Not run natively in this pass. `tsx` proof (the agent's): Apollo with a counting link and 5 identical `watchQuery` calls made 1 request with deduplication on and 5 with it off, using the app's defaults. The exact call counts on one screen were not traced.

## Fix

Remove the global flag, and set `context: { queryDeduplication: false }` only on the post-write read-backs (`invalidateLedgerData` and refetch). `use-discovery.ts:32` and `ledger-directory.ts:135` already use that per-operation pattern.

**Acceptance:**
- 5 co-mounted identical watchers send 1 request.
- A write followed by a refetch while a read is in flight still re-reads, which is w21/904's existing test.

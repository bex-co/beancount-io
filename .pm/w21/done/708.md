# The ledger service books AVERAGE sales silently, while Beancount 3.2 refuses them: hosted reports show gains Beancount wouldn't compute

**Severity:** minor (hosted numbers diverge from Beancount for ledgers that use AVERAGE booking; no error explains why). **Estimate:** 30 minutes, plus a decision. Owner: ledger. A3: `@rustledger/wasm` 0.24 implements AVERAGE booking; Beancount 3.2 doesn't, and reports "AVERAGE method is not supported". `engine.ts:713-717` passes rustledger's result through, and nothing in the error pipeline flags it. A ledger that bean-checks with errors locally reads as clean on the hosted service, with different balances.

Production, through GraphQL on the disposable ledger (restored byte-for-byte afterwards), and the agent's run of the real `main` service code against Beancount 3.2.3 `bean-check`/`bean-query`.

```
2024-01-01 open Assets:Qa20261020AvgCash USD
2024-01-01 open Assets:Qa20261020Broker VTI "AVERAGE"
2024-01-01 open Income:Qa20261020Gains USD
2024-01-01 open Equity:Qa20261020Open USD
2024-01-01 * "QA Opening"   ; AvgCash +5000 USD
2024-01-02 * "QA Buy"       ; Broker 10 VTI {100 USD}, AvgCash -1000 USD
2024-02-02 * "QA Buy"       ; Broker 10 VTI {200 USD}, AvgCash -2000 USD
2024-06-01 * "QA Sell"
  Assets:Qa20261020Broker  -10 VTI {} @ 300 USD
  Assets:Qa20261020AvgCash  3000 USD
  Income:Qa20261020Gains
```

`getLedgerErrors` returns nothing for these accounts. `getLedgerTrialBalance(conversion:"at_cost")` gives Broker **1500 USD** (10 VTI at the average 150) and Gains **−1500 USD**, so Reports shows a $1,500 gain in June 2024. bean-check exits 1 with "AVERAGE method is not supported" on the Sell, and doesn't book it. `option "booking_method" "AVERAGE"` behaves the same way.

## Fix

Decide the contract. Either match Beancount (report an error for AVERAGE, the same as the CLI) or keep rustledger's AVERAGE booking and document it as a deliberate extension with a visible note. Whichever is chosen, hosted, CLI and dashboard should agree.

**Acceptance:** this fixture reports the same error Beancount does, or the hosted UI clearly labels AVERAGE as supported, and the docs say so. A unit case is added.

**Resolved 2026-10-23** — contract chosen to match Beancount, as the CLI already does (w5/162 refuses to open an AVERAGE account, w5/764 warns under the option, and the `beancount-trade` skill tells users average cost is not supported): the ledger service now reports Beancount's "AVERAGE method is not supported" on each transaction that reduces a position booked AVERAGE, whether the account's open line names it or `option "booking_method" "AVERAGE"` sets it (`average-booking.ts`), in the engine's booking-error form, so it lands on the sale's line (line 14 of the note's fixture, as bean-check 3.2.3 reports). Purchases, other methods and other accounts are untouched; covering a short position counts as a sale. The refused sale is still counted in balances as rustledger booked it (at the average): whether an entry that failed booking leaves the reports, as Beancount drops it, is w21/678's open owner decision. Tests: `average-booking.test.ts` and two `verify:rustledger` checks (the AVERAGE sale is refused on its line; the FIFO control books cleanly). Shipped in the commit that closes this note (`backend-cluster/ledger`). Needs a ledger deploy to reach production.

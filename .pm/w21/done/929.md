# Account picker search ignores accents: "cafe" finds nothing beside Expenses:Café, then offers to create a look-alike Expenses:Cafe

**Severity:** moderate. It invites a near-twin account and split balances. This is the Latin-accent counterpart of w21/836 (Arabic letters). **Estimate:** 30 minutes. Owner: mobile.

**Root cause (A3).** In `mobile/src/common/account-search.ts`, `toNfc` (`:49`) and `fuzzyMatch` (`:117`) apply NFC and the Arabic fold to both sides, but no accent fold. `nameKey` (`account-close-dates.ts:179`) and `exactness` (`account-search.ts:157`) don't fold accents either.

Not run natively in this pass. `tsx` proof:
- `cafe` and `Cafe`, against a chart that has `Expenses:Café`, give `results:[]`, `createEmpty:true` and `created:"Expenses:Cafe"`.
- Open Account's duplicate check (`ledgerSpelling`) also accepts the twin, so Done is enabled.
- The same happens for `epargne` vs `Assets:Épargne`, and `isbank` vs `İşBank`.

**Native steps:**
1. With `Expenses:Café` opened, go to New Transaction ▸ account picker.
2. Paste `cafe`.

The picker reads "No matching accounts" and offers Create "cafe".

## Fix

- In `toNfc`, add an accent fold that keeps one unit per original character, as `lowerAligned` does.
- Apply the same fold in `nameKey`.
- Optionally, have Open Account warn when a typed name folds to an existing account.

**Acceptance:**
- `cafe` finds `Expenses:Café`, and no Create is offered.
- `café` still ranks the exact hit first.
- ASCII scoring is unchanged.

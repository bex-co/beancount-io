# A refused add leaves an empty routed file and a "chore: create file" commit behind

**Severity:** minor (stray empty file in Files, noise in Recent changes; worse with several routed targets). **Estimate:** 30 minutes. Owner: backend-v2. A3: `backend-cluster/backend-v2/src/features/ledger/service/ledger-entry-service.ts` `writeBulkEntries` (lines 354–370) calls `ensureFileExists` (lines 543–574) for each routed target. That commits the missing file as `content: ""` with message "chore: create file", as its own commit. Only afterwards does `addEntries` (line 372) send the entries to the ledger service, which may still refuse them: unbalanced entries (`backend-cluster/ledger/src/api/entries.ts:230`), new bean-check errors (`:343`), or the directive limit (`:349`). Since w23/058 the bulk route has a `dryRun` mode that treats a missing routed file as empty (`entries.ts:192`), so the create is unnecessary before the check.

Production, through GraphQL on the disposable ledger (2026-10-23 06:48 UTC; afterwards the stray file was deleted and `main.bean` restored byte-for-byte; verified identical to the snapshot). Fixture: the QA ledger plus

```
2000-01-01 custom "beancountio-option" "transaction_file" "qa-w21-route/{year}.bean"
include "qa-w21-route/*.bean"
```

`bulkEntries` (as Open Account and Budget send it; New Transaction's `addEntries` goes through the same `addBulkEntries`) with one 2026-09-01 transaction to the never-opened `Expenses:QaW21NotOpen`. It returned `VALIDATION_FAILED` "…Account Expenses:QaW21NotOpen was never opened (qa-w21-route/2026.bean:2)", so the app says nothing was saved. Yet `getLedgerDirContent(dirPath:"qa-w21-route")` then listed `2026.bean`, size 0 (blob `e69de29…`), and `listCommits` had a new head "chore: create file". When an entry is routed to two new files and the second create fails, the first is left behind. Even a successful routed write lands as two commits.

## Fix

Don't create the file up front. Let the ledger service's write create it, or run the `dryRun` check before `ensureFileExists`. Ideally write the routed files and the entries in one commit.

**Acceptance:** with this fixture, the refused write leaves the ledger's files and commits unchanged, and a successful routed write is a single commit. A unit case is added.

## Dedupe

Not w23/058 (a refused receipt write leaves a stored document behind), w23/062 (a routed year file nothing includes) or w21/453 (blocked; retry duplicates). Searched `.pm/**` for ensureFileExists, "chore: create file" and "empty file".

Side observation, not filed here: the same probe without the glob include got `success: true` and committed to an unincluded `qa-w21-route/2026.bean`, w23/062's symptom. That fix looks undeployed as of this probe.

---

**Resolved 2026-10-23** — `writeBulkEntries` no longer creates a missing routed file up front: when a target is missing it first asks the ledger with a dry run (which checks a missing file as empty), and only creates the files and writes once that accepts, so a refused write leaves no empty file and no "chore: create file" commit. When every target exists it still makes one call. Tests in `ledger-entry-service.test.ts` (the old "keeps the created routing file" boundary of w1/m10/t016 is replaced by "creates nothing when the ledger refuses"), shipped in the commit that closes this note (`backend-cluster/backend-v2`). Not done: the created files and the entries are still separate commits on success. Needs a backend-v2 deploy to reach production.

# New File's case-clash error names the typed name, not the existing file: "A file named Main.bean already exists" beside main.bean

**Severity:** trivial. The message describes a file that doesn't exist. **Estimate:** 10 minutes. Owner: mobile. A3: w21/770 compares names by a portable key, but `ledger-file-browser-screen/index.tsx:485` (and `:592` for the server conflict) still formats `ledgerFileNameExists` with the typed `check.filename`, not the clashing file's real name.

Native (iPhone 17e, Metro `--clear` at `5ce8e8c8f`, English UI): Files ▸ + ▸ paste `Main` beside `main.bean`. The dialog shows **"A file named Main.bean already exists"**, and Create file is disabled, which is correct. Nothing was written.

## Fix

Have `checkLedgerFileName` return the existing file's path for a clash, and name it in the message: "A file named main.bean already exists".

**Acceptance:** typing `Main` names `main.bean`. An exact duplicate is unchanged. A unit case is added.

# Offline, Home's budget panel claims "$0.00 · Below target" when the cache holds no totals for the window it reads

**Severity:** moderate. The panel makes a false, favorable claim about spending, which is the symptom w21/080 was meant to stop. **Estimate:** 30 minutes. Owner: mobile.

**Root cause (A3).** In `mobile/src/screens/home-screen/hooks/use-budget-panel.ts:175-180`, the fallback `.catch(() => totals("cache-only")).catch(() => null)` assumes a cache miss rejects. It doesn't: Apollo resolves `{data:{}, partial:true}`.
- `:163` turns that into `[]`.
- So `failed: items === null` (`:200`) is false.
- `select-budget-panel.ts:88,102` then treat the missing actual as 0.

**Where the cache misses come from:**
- After an online session that found an entry later this month, only the "to today" window is cached. Offline, the scheduled check fails and counts as "none", so the panel reads the month-long window, which was never cached.
- On a new month or year, `budgetPanelWindow` changes, so the cache misses too.

Not run natively; the simulator shares the host's network. `tsx` proof, using the hook's exact read chain against a link that answers online and then fails:

| Run | scheduled | failed | actual | budget | status |
|---|---|---|---|---|---|
| Online | true | false | 312.4 | 370.97 | (correct) |
| Offline | false | false | 0 | 370.97 | below (favorable) |
| Nov 1, empty cache | – | false | 0 | 16.67 | below |

**Native steps:**
1. Add an entry dated a few days ahead.
2. Open Home online.
3. Relaunch in airplane mode.

## Fix

- Read with `.then(({data}) => data?.getLedgerIntervalTotals ?? null)`, and treat `null` from cache-only as failed.
- Or, when the network fails, try the cached "to today" window before the month window.

**Acceptance:**
- A unit case where cache-only resolves `{}` ends with `failed:true` and no $0 rows.
- Offline, after an online session that had scheduled entries, the panel shows the cached actuals.

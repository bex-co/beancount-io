# A ledger whose main.bean is missing is reported as "deleted, renamed or unshared", and every tab is blocked, Files included

**Severity:** moderate. The user has no way out inside the app, while the drawer still lists the ledger. **Estimate:** 20 minutes. Owner: mobile. A3: `mobile/src/common/graphql-error-codes.ts:29` (`isLedgerGone` is true for any `NOT_FOUND`), used by `components/ledger-guard/ledger-guard.tsx:132,262` on the read-context query. The ledger service's missing-entry-point check (`file-map-loader.ts:651`, "Ledger entry point with ID '…:main.bean' not found") reaches the app as `NOT_FOUND`.

Not run natively: the API refuses deleting or renaming main.bean (w23/031). It needs a git push removing it, or a repo imported with another entry file. Under `tsx` (the agent's proof), `isLedgerGone(entry-point missing)` gives `true`, so the screen reads "This ledger is no longer available. It was deleted, renamed or unshared."

## Fix

Treat it as gone only when the repository itself is missing (not the "Ledger entry point" resource). Otherwise show a "ledger can't load — open Files" state that keeps the Files tab reachable.

**Acceptance:** a missing entry point shows a recoverable state with Files available. A unit case is added.

## Dedupe

Not w21/054, 074, 182 or 226, nor w23/031 or 047. Searched `.pm/**` for isLedgerGone and "entry point".

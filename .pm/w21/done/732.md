# In a ledger without `operating_currency`, a USD merchant's header reads "120.00 USD" while its rows read "−$60.00" (w21/719 vs w21/699 and w21/415)

**Severity:** trivial. **Estimate:** 15 minutes. Owner: mobile. A3: the merchant header and the Merchants list's recurring amount (`merchant-detail-screen/selectors/format-merchant-total.ts:42-49`) use `ledgerPrimaryCurrency`, which falls back to the most-used currency when no option is set (w21/415). The transaction rows use `common/hooks/use-operating-currency.ts:15`, which returns only `operating_currency[0]`, so it's undefined there, and `labelRowAmount` prints USD as "$". w21/719's fix brought the header in line with one source and not the other.

Not run natively: it needs the disposable ledger's `operating_currency` line removed and a ledger dominated by CAD. Proven under `tsx` (the agent's proof): `ledgerPrimaryCurrency([], ["CAD","USD"])` gives "CAD". The header at HEAD is "-120.00 USD" (before w21/719 it was "-$120.00"), and the row formatter gives "$60.00".

## Fix

Use one source for "the ledger's primary currency" everywhere: rows, detail and merchant header.

**Acceptance:** with no `operating_currency` and mostly CAD, a USD merchant's header and rows use the same label. A unit case is added.

## Dedupe

Conflict between w21/719 (done), w21/699 (done) and w21/415 (done). Searched `.pm/**` for ledgerPrimaryCurrency and use-operating-currency.

**Resolved 2026-10-23** — `useOperatingCurrency` (the rows', the transaction detail's and the row icon's source) now returns `ledgerPrimaryCurrency(operating_currency, the ledger's currencies)`, the same reading as the merchant header and Merchants list, so with no option and a CAD ledger a USD row reads "60.00 USD" under a "-120.00 USD" header. Unit and source cases in `mobile/src/__tests__/primary-currency-everywhere.test.ts`. Shipped in the commit that moves this note.

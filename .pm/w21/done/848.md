# Decorative icon glyphs are still separate VoiceOver stops on several screens, and two intended labels (stale-data banner, Browse ledgers loading) are never read

**Severity:** low to moderate (it shows up on many screens). **Estimate:** 30 minutes. Owner: mobile. A3: each vector icon renders as a `<Text>` holding a private-use character, and Text is accessible by default, so VoiceOver stops on it (w2/069 heard these as "U+F…"). These sites have no hiding wrapper:
- `merchant-detail-screen.tsx:602`: the header icon when there's no brand logo.
- `components/search-bar/index.tsx:116`: the leading search icon in every search field.
- `ledger-selection/index.tsx:248`: the search icon on Browse ledgers.
- `notifications-screen.tsx:393`: the "Ledger healthy" check icon.
- Empty and error states: `budget-screen.tsx:245`, `merchants-screen.tsx:328,348`, `no-results-state.tsx:65`, `transactions-empty-state.tsx:103`, `ledger-file-browser-screen/index.tsx:810` and `ledger-guard.tsx:153`.

Two labels are silently ignored because the `View` lacks `accessible` (on Fabric, reachability comes only from `accessible`):
- `stale-data-banner/index.tsx:39-48`, used on 7 screens.
- `ledger-selection/index.tsx:204`, the loading skeleton's "Loading…".

Not run natively (VoiceOver). This is a code-level trace (the agent's).

## Fix

Mark each glyph `accessibilityElementsHidden` with `importantForAccessibility="no"`, add `accessible` to the banner and the skeleton, and extend the guardrail test to cover icons outside pressables.

**Acceptance:** none of these glyphs is a VoiceOver stop, and the banner and loading labels are read. Source cases are added.

## Dedupe

Same class as w21/141, 605 and 639 (other sites). Searched `.pm/**` for decorative, glyph, "U+F", StaleDataBanner and SearchBar.

# The Account Picker lists an account's children apart from their parent: the Vanguard accounts are split across the list, so scanning for one institution means reading the whole Assets section

**Severity:** minor (scan-ability; every account is present and selectable). **Estimate:** ~30 minutes. Owner: mobile. A2: `groupAccountsByRoot` in `mobile/src/common/ledger-meta-utils.ts` documents "preserving the caller's ordering both across roots (first seen wins) and within each root", and `mobile/src/screens/account-picker-screen/picker-sections.ts` passes the account list through unchanged, so the browse order is whatever order the ledger metadata query returns.

iPhone 17e, iOS 27.0, dev build `io.beancount.ios`, `main` at `434d05dc6`, a synthetic example ledger, light mode, default text size, the All chip.

1. Transactions tab, open the filter sheet (the sliders icon), and tap the **Account** row.
2. Read the Assets section from the top. (A screenshot is kept locally and is not committed.)

The rows read: `Assets:Bank`, `Assets:Bank:Mercury`, `Assets:Bank:Mercury:Checking`, `Assets:US`, `Assets:US:Vanguard`, `Assets:US:Vanguard:Cash`, `Assets:US:BofA`, `Assets:US:BofA:Checking`, `Assets:US:Vanguard:RGAGX`, `Assets:US:Vanguard:VBMPX`, `Assets:US:Hoogle`, `Assets:US:Hoogle:Vacation`. Vanguard's children are not contiguous: `BofA` and `BofA:Checking` sit between `Vanguard:Cash` and `Vanguard:RGAGX`. The order looks like declaration order (a child opened later lands after unrelated accounts opened earlier), which is **not verified**: whether the query returns declaration order, and whether a flat declaration-order list is intended, are open.

**Expected:** an account's descendants follow it, so the list reads as the hierarchy the Accounts tab shows: `Vanguard`, `Vanguard:Cash`, `Vanguard:RGAGX`, `Vanguard:VBMPX`, then `BofA`, `BofA:Checking`.

## Fix

In the picker's browse list, sort each root section by full account name (a stable comparison on the segments, case and accent insensitive in the way `foldAccents` already treats search), leaving the pinned Recent block, search results and the scroll-to-selected behaviour alone. Add a unit case in `picker-sections` for interleaved parents and children.

**Acceptance:** with the ledger above, every account's descendants are contiguous and directly follow it in the browse list; the Recent block, search ordering and the selected-row scroll are unchanged.

## Blast radius

`groupAccountsByRoot` is used wherever the app shows accounts by root, so prefer sorting at the picker rather than in the shared helper, and check the posting picker in New Transaction and Open Account before touching the helper. With a search query or a root chip the same order applies. Unverified: Android, other locales' collation.

## Dedupe

Searched `.pm/**` and `mobile/.pm/**` for declaration order, alphabetical, `groupAccountsByRoot`, picker order and sort. Nothing covers this; `w21/021` (the Recent block ignoring the root chip), `w21/045` (closed accounts offered) and `w21/229` (accounts not yet open offered on a back-dated entry) are different picker problems.

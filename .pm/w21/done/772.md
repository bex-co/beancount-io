# A missing file included from two places is listed twice at the first include's line; the second include is never pointed to (w21/189 gap)

**Severity:** minor (the user can't find the second include; with an unincluded archive file, the only row points into a file the ledger doesn't read). **Estimate:** 20 minutes. Owner: ledger. A3: w21/189's relocation (`backend-cluster/ledger/src/foundation/rustledger/url-include-errors.ts:52-59`) keeps only the *first* file in the repository that includes a given target, and moves every matching LOAD error there (`:64-79`). It also scans files `main.bean` never includes.

Production, through `getLedgerErrors` on the disposable ledger (restored byte-for-byte afterwards). `include "qa20261020-missing.bean"` twice at the top of `main.bean` gives two errors, both "**Included file not found: qa20261020-missing.bean · main.bean:1**" (the second include is on line 2). In the agent's run with a sub-file include, both rows point at `main.bean`, and the sub-file's editor banner is empty. With an unincluded `archive/qa20261020-old.bean` that sorts first, the only row points into that unread file.

## Fix

Relocate each LOAD error to its own include directive, only within files actually loaded from `main.bean`.

**Acceptance:** the two-include fixture gives errors at lines 1 and 2, and the sub-file case points into the sub-file. Unincluded files are never blamed. A unit case is added.

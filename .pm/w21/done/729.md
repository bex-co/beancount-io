# Typing an amount before choosing the first payee stops that payee's usual accounts from filling in (w21/411 covered only a second payee)

**Severity:** minor (a common order of entry silently books to the default accounts). **Estimate:** 15 minutes. Owner: mobile. A3: `multi-postings-transaction/payee-seed.ts:11-21` and `:60` fill in the payee's last accounts for the *first* payee only while the amounts are also untouched. w21/411 made typed amounts not block the fill for a *second* payee. So the outcome depends only on whether the amount came before the first payee.

Native (iPhone 17e, Metro `--clear` at `47afd172e`; nothing saved, forms discarded; today 2026-10-23):

- **Amount first:** Home ▸ + ▸ Enter new transaction, type **4**, then Payee ▸ the **FARMERS MARKET** suggestion. The postings stay on the defaults "**Assets:Bank:Checking** 4 / Expenses:Food:Groceries".
- **Control, payee first:** a fresh form ▸ Payee ▸ FARMERS MARKET fills in "**Assets:Cash** / Expenses:Food:Groceries", that payee's usual accounts.

Under `tsx` (the agent's proof), `seedPostingsFromPayee` returns the accounts for payee-first and for amount-then-second-payee, but null for amount-then-first-payee.

## Fix

Apply w21/411's rule to the first payee too: typed amounts don't count as editing the postings; only changed accounts do. Keep the typed amounts.

**Acceptance:** amount-then-payee fills in Assets:Cash and keeps the 4. Changed accounts still block the fill. A unit case is added.

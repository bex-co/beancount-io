# A transaction you wrote with flag R, T, U, M or P opens read-only as if plugin-generated, and one flagged S or C is missing from Transactions

**Severity:** minor (since w21/652 the API accepts any capital-letter flag, so these are ordinary user entries). **Estimate:** 30 minutes. Owner: mobile and ledger. A3: `transaction-detail-screen/selectors/select-transaction-detail.ts:21-33` (`hasEditableSource`) treats every `P`/`S`/`T`/`C`/`U`/`R`/`M` flag as generated, and `transaction-detail-screen.tsx:379` and `:590` hide Edit, the menu and the source for those entries. Separately, `backend-cluster/ledger/src/features/ledger/service/ledger-journal-service.ts:697-703` drops every `C`/`S` transaction from the journal, not only the summarization entries a time filter generates. `plaintextExportDirectives` (`:237`) leaves them out of the Journal export too.

Native (iPhone 17e, Metro `--clear` at `3263cb449`; disposable ledger restored byte-for-byte; today 2026-10-23): the QA ledger plus `2026-10-20 R "Qa20261020 Refund flag R"` (Misc −7.00 / Card +7.00) and `2026-10-20 S "Qa20261020 Settled flag S"` (Misc +9.00 / Checking −9.00).

- **Missing S entry:** Transactions lists "Qa20261020 Refund flag R +$7.00" on October 20, but **no "Settled flag S" row**.
- **Read-only R entry:** opening the R row shows the hero and Money flow with **no pencil, no ⋯ menu and no Entry Context**.

Under `tsx` (the agent's proof), the server finds the R entry's source text, while mobile gives `{isGenerated: true, showWriteActions: false, menu: []}`. The S entry is in the parsed data but not in the journal output.

## Fix

Decide "generated" from the server's provenance (`generated_from`, or the engine's synthetic marker), not from the flag letter. Drop only the summarization entries the engine inserts, not every `S`/`C` transaction.

**Acceptance:** an R-flagged entry has Edit, the menu and its source, and an S-flagged entry is listed on Transactions and exported. Plugin copies and padding stay read-only. Unit cases are added.

## Dedupe

Consequence of w21/652 (done; flags accepted). Not w21/443, w21/504, w21/508 or w21/660 (plugin copies). Searched `.pm/**` for hasEditableSource and flag together with S, C or R.

---

**Resolved 2026-10-23**. "Generated" is now decided by provenance, not the flag letter.

- **Ledger:** `getJournal` drops only the time clamp's own `C`/`S` entries, which are absent from the ledger's id map. A transaction written with flag S or C is listed.
- **Ledger:** the plaintext export (`plaintextExportDirectives`, now given the snapshot's own directives) writes every transaction of the ledger, R/S/C/T/U/M/P-flagged ones included. It leaves out padding the pad pass generated and the clamp's entries (except a window's `S` opening summaries, as before).
- **Ledger:** the engine now sends its generated marks across the worker whenever anything is generated, padding included. Before, they crossed only with source details. Unmatched padding in the fallback path is marked too.
- **Mobile:** `mayBeGenerated` (a reserved flag) only means an entry might be synthetic. The context is read for every entry, and the new `selectEntrySource` holds such an entry read-only until the read finds its source. Then Edit, the menu and its source appear.
- **Mobile:** a NOT_FOUND for an entry whose source was never found is read as generated, not removed (w21/444). One after the source was found still reads as removed. Plugin copies stay read-only through `generated_from`, and padding stays read-only.

The live case in `scripts/verify-rustledger.ts` checks the journal (plain and time-windowed), the export and its reload; at the previous HEAD the S entry is missing. Unit cases are in `plaintext-export-directives.test.ts` and `select-transaction-detail.test.ts`, and the mobile source tests are updated. Not run natively.

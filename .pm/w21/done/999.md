# In the Transactions search row, the clear ✕ and the Filters button have 32–34 pt targets whose slop overlaps in the 8 pt gap between them

**Severity:** low to moderate. A tap just right of the ✕ opens Filters instead of clearing the search. **Estimate:** 15 minutes. Owner: mobile.

**Root cause (A3).**
- `mobile/src/components/search-bar/index.tsx:146`: the clear button is an 18 pt icon with `hitSlop={8}`, about 34 pt.
- `mobile/src/screens/transactions-screen/transactions-header.tsx:65`: the Filters button is a 16 pt icon with `hitSlop={8}`, about 32 pt.
- The row's gap is 8 pt, so each button's slop covers the whole gap, and the later sibling wins there.

Not run natively in this pass (code level only).

**Native steps:** Transactions → paste "coffee" into search → tap the gap just right of the ✕. The Filters sheet opens and the text is not cleared.

## Fix

Give each button its own 44 pt box (`minWidth` and `minHeight: iconActionSize`) and drop the colliding slop, for example a `marginStart` and a non-overlapping `hitSlop`.

**Acceptance:** with text in the field, a tap within 12 pt of the ✕ centre clears it, and a tap within 12 pt of the Filters centre opens Filters; neither target is under 44×44 or overlaps the other.

**Resolved 2026-10-24** — the search ✕ and the Transactions Filters button each get a 44 pt wide layout box (`minWidth: iconActionSize`) and a vertical-only slop that makes them 44 pt tall (the `hitSlop={8}` on both, which covered the 8 pt gap between them, is gone). Width is layout, so the two cannot overlap; height is slop, so the field stays 36 pt. The Filters button takes back the field's trailing padding (`marginEnd: -space.md`) so the funnel sits where it did, and its active dot moves with the funnel inside the wider box. Deviation: the search input is about 54 pt narrower with text present. Source tests pin both targets and fail without the change.

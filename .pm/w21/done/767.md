# After a metadata-only edit, an entry flagged R (or another reserved flag) keeps showing its pre-edit copy, so the save looks lost (w21/745 made these editable; w21/388/472 symptom)

**Severity:** minor. **Estimate:** 15 minutes. Owner: mobile. A3: `transaction-detail-screen/selectors/select-own-entry.ts:14-19` (`holdGeneratedEntry`) keeps any reserved-flag entry it was shown, even after its source has been found. `selectOwnEntry` (`:22-28`) returns that held copy while the hash still matches, and `transaction-detail-screen.tsx:505-514` prefers it over the fresh context entry. A metadata-only edit keeps the hash (the save takes the "unchanged" exit, `edit-transaction-screen.tsx:424`, which clears the stash but not the held copy), so the detail repaints the old copy.

Not run natively (the Metadata section sits below the fold, and the edit needs typing in the code editor). Proven by the agent: ts-node shows that adding `receipt: "Qa20261020-r"` to an `R` entry keeps hash `3767729a…`. Mobile selectors run in the screen's order give, for R, `{"editable":true,"shownMeta":{"filename":"main.bean","lineno":93}}` (no receipt). For `*`, `shownMeta` includes `receipt`.

## Fix

Stop holding a reserved-flag entry once its source is known (provenance says it's user-written), or drop the held copy on any save.

**Acceptance:** after the metadata edit, an R entry's detail shows `receipt: Qa20261020-r`, as `*` does. A unit case is added.

## Dedupe

Consequence of w21/745 (done); same symptom as w21/388 and w21/472 (done) for these flags. Searched `.pm/**` for holdGeneratedEntry.

**Resolved 2026-10-23** — `selectOwnEntry` (`transaction-detail-screen/selectors/select-own-entry.ts`) takes whether the context read has found the entry's source, and once it has, the held copy no longer stands in for the read. The detail screen now asks it after the read. A reserved-flag entry the user wrote is still held, read-only, until its source is found (w21/444, w21/745). From then on the fresh context entry is shown, so after a metadata-only edit (same hash, stash cleared) an R entry shows `receipt: Qa20261020-r`, as a `*` entry does. A fresh stash still wins. Unit and source cases are in `select-own-entry.test.ts` and fail at the previous HEAD. Not run natively. Shipped in the commit that moves this note.

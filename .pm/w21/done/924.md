# A deferred foreground refresh fires after Log out, shows "Your session ended", and can break the next sign-in

**Severity:** moderate. **Estimate:** 30 minutes. Owner: mobile.

This is a regression from w21/838, which deferred a return to the app instead of dropping it.

**Root cause (A3).**
- `mobile/src/common/apollo/foreground-refresh.ts:40` schedules a timer that nothing can cancel.
- The directory provider's cleanup (`ledger-directory-provider.tsx:31-35`) only removes the AppState listener, and `dispose` (`ledger-directory.ts:80`) only aborts the request already in progress.
- After sign-out, the orphaned timer runs `directory.revalidate()`. That sends `LedgerDirectory` with no token, and the server answers UNAUTHENTICATED.
- `auth-error-link.ts:22` treats a missing session as a session that ended and calls `teardownAndRoute` (`error-handling.ts:13,22`). That sets `signOutReason = "sessionEnded"`, then reruns `clearServerScopedState()`, which also clears any pending authorization (`server-url-actions.ts:36,44`).

Not run natively in this pass. `tsx` proof with the real modules:
- On a fake clock, a return at 40 s followed by another at 45 s schedules a run for 70 s. Firing that timer after logout still refreshes (the count goes from 1 to 2).
- `createAuthErrorLink`, with `getSession: () => null` and an UNAUTHENTICATED answer, calls teardown once.
- With the stored verifier cleared, `runNativeSignIn` ends as `"rejected"`, which Welcome shows as "Could not complete sign-in".

**Native steps:**
1. While signed in, background the app and reopen it.
2. Within 30 s, do it again.
3. Right away, go to Settings → Log out → confirm.

**Expected:** a plain Welcome screen.

**Actual:** up to about 30 s later, Welcome shows "Your session ended. Sign in again to continue." If a browser sign-in is open at that moment, approving it fails with "Could not complete sign-in".

## Fix

- Have `createForegroundRefresher` return a disposer that clears its pending timer. Call it in every effect cleanup: the directory provider, `use-foreground-refresh.ts`, and the guest session.
- Have the auth-error link ignore UNAUTHENTICATED when there is no session.

**Acceptance:**
- Disposing the refresher while a run is pending means the run never fires.
- UNAUTHENTICATED with `getSession() === null` doesn't call teardown.

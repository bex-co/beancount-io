# New Transaction's Done is drawn dimmed on an invalid draft, but VoiceOver never says "dimmed"

**Severity:** low. **Estimate:** 10 minutes. Owner: mobile. A3: `multi-postings-transaction-screen.tsx:750-760` passes `disabled={saving || saved}` and `accessibilityState={{ disabled: !canSave || saving }}`. React Native's `Pressable` overwrites `accessibilityState.disabled` with the `disabled` prop, which is false here. So a draft with a validation error draws Done grey (`doneButtonDisabled`), while VoiceOver reads "Done, button" with no "dimmed".

Not run natively (VoiceOver). Natively, a refused draft shows a grey Done (seen during w21/791's and w21/793's rechecks). This is a code-level proof (the agent's).

## Fix

Choose one meaning. If Done stays pressable so it can show the error, drop the dimmed style or add a hint naming the error. If it should read "dimmed", drop the `disabled` prop and rely on the existing single-flight guard.

**Acceptance:** the drawn state and the spoken state agree for an invalid draft. A source case is added.

w21/044 fixed only the in-flight window. Searched `.pm/**` for Done together with dimmed, and accessibilityState disabled.

**Resolved 2026-10-24** — chose "read dimmed": Done keeps its grey look and stays pressable on an invalid draft (which is how it shows what is wrong), and now its `disabled` prop is `true` only while saving or after, otherwise `undefined`, so Pressable no longer overwrites `accessibilityState.disabled` and VoiceOver says "dimmed" over the grey Done.

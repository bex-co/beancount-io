# A budget saved from the app gets the commit subject `Add 2026-10-01 "budget"`, whatever the account or amount

**Severity:** minor. It leaves the w21/903 fix incomplete. **Estimate:** 20 minutes. Owner: ledger (all surfaces get it).

**Root cause (A3).** `entryLabel` (`backend-cluster/ledger/src/features/ledger/utils/commit-message.ts:36-44`) takes the first quoted string on the line as the entry's name. That is right for a transaction. For `custom "budget" Expenses:Food "monthly" 300 USD`, the first quoted string is the directive type.

Not run natively in this pass; it needs the ledger deploy that carries w21/903, and production still lags `main`. `tsx` proof with the real `commit-message.ts`:
- `2026-10-01 custom "budget" Expenses:Food "monthly" 300.00 USD` and `2026-10-01 custom "budget" Expenses:Rent "monthly" 1500.00 USD` both give `Add 2026-10-01 "budget"`.
- Other directives misname the same way: `open Assets:Cash USD "STRICT"` gives `"STRICT"`, `event "location" "Paris"` gives `"location"`, and `open Assets:Cash ; "main" account` gives `"main"` from the comment.
- A transaction with an empty payee and narration gives `Add 2026-10-22 "" ""`.

**Native steps** (after the deploy): save a budget for Expenses:Food and another for Expenses:Rent, then open Recent changes. Both rows read `Add 2026-10-01 "budget"`.

## Fix

Use the quoted-string rule only when the line is a transaction (`txn`, `*` or `!`). Label any other directive by its type plus its first token, for example `Add 2026-10-01 custom budget Expenses:Food`. Strip a trailing `;` comment before parsing, and treat all-empty strings as having no name.

**Acceptance:** cases in `commit-message.test.ts`:
- the two budget lines give different subjects that name the account;
- `open … "STRICT"`, `event` and `; "main"` don't take a quoted string as the name;
- an empty-narration transaction doesn't produce `"" ""`.

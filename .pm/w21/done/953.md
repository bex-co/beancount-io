# "Back to Files" stacks a second copy of the whole tab bar instead of returning to the existing one

**Severity:** minor to moderate. This is the w21/242 class, at a call site that fix missed. **Estimate:** 15 minutes. Owner: mobile.

**Root cause (A3).** The missing-file screen's Back to Files button (from w3/201) calls `router.replace("/(app)/(tabs)/ledger")`, or `"/examples/(tabs)/ledger"` for a guest (`mobile/src/screens/ledger-file-editor-screen/index.tsx:1232`). In expo-router 57 this replaces the editor with a brand-new `(tabs)` route on the `(app)` stack, rather than returning to the tab bar underneath.

Not run natively in this pass; the file has to be deleted outside the app while the editor is open.

**Proof:** expo-router's own routing functions (`findDivergentState`, `getPayloadFromStateRoute`, `StackRouter.getStateForAction`), run on the stack tab bar → Transaction detail → editor:

| | Resulting stack |
|---|---|
| Now | `(tabs)#tabs-1 \| transaction-detail#td-1 \| (tabs)#<new>`, a second tab bar with every tab's live queries |
| With `dismissTo` | `(tabs)#tabs-1{"screen":"ledger"}` |

**What the user sees:**
- The Files folder and each tab's scroll position are lost.
- Back (Android) or an edge swipe returns to the stale screens underneath.
- Each repeat stacks another full tab bar.

**Native steps:**
1. Files → a subfolder → open a file.
2. Delete that file outside the app.
3. Tap Reload, then Back to Files.

Files opens at its root, not the subfolder. If you entered the editor from Home → bell → an error row instead, Back after this lands on Notifications.

## Fix

Use `router.dismissTo(guest ? "/examples/(tabs)/ledger" : "/(app)/(tabs)/ledger")`, as w21/242 did for Browse ledgers and Create Ledger.

**Acceptance:**
- Extend `tab-bar-stacking.test.ts` to cover this call site, signed in and as a guest. It should fail on the current file.
- After the steps above, the stack holds exactly one `(tabs)`.

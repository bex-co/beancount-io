# Saving Edit Transaction with a trailing indent-only line (what Return after the last posting leaves) writes a stray "  " line into the file and lands on "This transaction was changed or removed"

**Severity:** major. The save succeeds but reads as a failure, a later save from the editor gets a false "modified elsewhere", and each such save leaves another whitespace-only line between entries. **Estimate:** 30 minutes. Owner: ledger, plus mobile. A3: `normalizeSliceReplacement` (`backend-cluster/ledger/src/foundation/rustledger/source-slice.ts:790`) trims only trailing `\r\n`, so a final `"  "` line is stored. `ledger-journal-service.ts:1127` returns the sha of that stored text, not of the block a fresh read serves without it. The detail screen won't adopt a read whose checksum isn't the saved one (`transaction-detail-screen.tsx:426-439`, `isSavedChecksum`), so it shows the removed state. The agent's `tsx` proof shows the same mismatch for a column-0 `;` comment added above or below the entry, a leading blank line, and a one-line entry in a CRLF file.

Reproduced natively on the iPhone 17e simulator, English UI, Metro `--clear` at `2cd441283`, on the disposable QA ledger, which was restored byte-for-byte to `f1a0b83c`. Fixture: `2026-10-20 * "Qa20261020 Cafe" "Lunch"` with `Expenses:Qa20261020:Food 12.00 USD` / `Assets:Qa20261020:Cash`.
1. Transactions ▸ the entry ▸ pencil ▸ tap the end of the last posting ▸ Return (an auto-indented line 4) ▸ Save. The detail reopens, but the file now holds `…Cash\n  \n`.
2. Pencil again ▸ Select All ▸ paste the entry with `13.00` and a final `"  "` line ▸ Save. The screen reads **"This transaction was changed or removed. Go back to see the current list."** The file holds `…13.00 USD\n  Assets:Qa20261020:Cash\n  \n  \n`, two stray whitespace lines.

## Fix

Strip blank and whitespace-only lines from both ends of the replacement before storing it. Then either refuse column-0 comments in `assertSingleEntryText`, or return the sha of the block `splitIntoBlocks` finds at `startLine` after the write.

**Acceptance:** both steps save, and the detail shows the edited entry. The file gains no whitespace-only lines. Unit cases cover a trailing indent line, a leading blank line and column-0 comments.

## Dedupe

Not w21/692 (an indented comment) or w21/252 (multi-line CRLF). Searched `.pm/**` for newSha256sum, servedSliceText and normalizeSliceReplacement.

---

**Resolved 2026-10-23** — Two changes in the ledger service:
- **Stored text:** `normalizeSliceReplacement` (`backend-cluster/ledger/src/foundation/rustledger/source-slice.ts`) now trims blank and whitespace-only lines from both ends of a replacement before storing it. It used to trim only trailing newlines. The indent-only line Return leaves after the last posting, and a leading blank line, no longer land in the file. Spaces closing the last posting are kept.
- **Returned checksum:** the update's `newSha256sum` (`ledger-journal-service.ts`) is now the checksum of the block a fresh read serves: the dated block among the stored lines, found with `splitIntoBlocks` by the new `servedReplacementSlice`. Previously it was the stored text, which a column-0 `;` comment above or below the entry, or a one-line entry in a CRLF file, made differ from any read.

Both of the note's steps now save, the detail adopts the read, and the file gains no whitespace-only lines.

Unit cases in `source-slice.test.ts` cover a trailing indent line, several trailing ones, a leading blank line, comments above and below, and a one-line CRLF entry. Each half fails with the previous behaviour restored. Ledger lint, typecheck, build and the live engine checks are green. The test run had one failure, the known intermittent `file-request-limit` ECONNRESET, which passed on rerun. Needs a ledger-service deploy. Not checked natively.

# Leaving the account picker while Open Account is still saving lets the picker's callback close whichever screen is now on top

**Severity:** minor to moderate. New Transaction is closed under the user, or an unprompted "Discard changes?" appears over their draft. **Estimate:** 20 minutes. Owner: mobile. A3: `confirmSelection` at `mobile/src/screens/account-picker-screen/account-picker-screen.tsx:491-497` calls the global `router.back()` with no `isHere` check.

Not run natively. Two Backs during "Saving…" are faster than the simulator driver can tap, the same limit w21/581 noted. Code path:

1. w21/581 made Open Account capture the picker's callback before saving (`open-account-screen.tsx:392`) and call it after the save even when the user has left (`:424`).
2. New Transaction → posting picker → type "Qa Foo" → Create → Done. "Saving…" lasts through the awaited full invalidation.
3. Swipe back to the picker (the Open Account form is clean, so there is no prompt), then swipe back again to New Transaction.
4. The save lands. `onSelectedRef` still holds the form's setter, so the posting is filled, and then `router.back()` runs against New Transaction.

**Expected:** the user stays on the form with the posting filled. **Actual:** New Transaction gets a GO_BACK. A dirty draft shows "Discard changes?"; a clean one closes.

## Fix

Give the picker `useIsHere()` (as `edit-transaction-screen.tsx` and `profile-screen.tsx` use) and pop only `if (isHere())`. Keep delivering the account either way.

**Acceptance:** a unit case calls the stored callback after the picker is popped and asserts no `router.back()`.

## Dedupe

A regression of done w21/194 ("post-write navigation … closed whatever screen was now on top"), exposed by done w21/581's fix. Searched for "runAccountCreatedCallback", "confirmSelection" and "AccountCreated".

---

**Resolved 2026-10-24** — the picker's one exit (`confirmSelection`) delivers the account either way but calls `router.back()` only while the picker is the screen shown (`useIsHere`), so a save that lands after the user left no longer pops New Transaction or raises "Discard changes?". Source case in `account-picker-leaves-only-when-here.test.ts` (`mobile`). Not run natively (the callback path is pinned in source, not rendered).

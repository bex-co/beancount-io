# A ledger description over 2048 characters fails Create with "Couldn't create the ledger. Please try again.", and retrying never helps

**Severity:** minor. The user is stuck on Review with advice to retry, while the field that is actually wrong is on the previous step. **Estimate:** 20 minutes. Owner: mobile.

**Root cause (A3).**
- The form accepts any length: `mobile/src/screens/create-ledger-screen/create-ledger-screen.tsx:236` (`description: z.string()`), and the input (`:745-755`) has no `maxLength`.
- Since w23/037, the server refuses descriptions over 2048 characters ("A ledger description can be at most 2048 characters").
- `classifyCreateLedgerError` (`ledger-name.ts:79-137`) maps that refusal to `"other"`, so Review shows `createLedgerGenericError` as a general error instead of an error on the description field.

Not run natively: showing it means sending a create, which this session doesn't do. `tsx` proof: an error built like the server's refusal, with that message, comes back from `classifyCreateLedgerError` as `other`.

## Fix

- Add `.max(2048, t("createLedgerDescriptionMaxLength"))`, counting code points as Gitea does.
- Add `maxLength={2048}` to the input.
- Add a `"description"` kind to `classifyCreateLedgerError` that sets the field error and returns to the form step, as `conflict` already does.

**Acceptance:**
- 2049 characters fails Next with a field error, and exactly 2048 passes.
- A server refusal with that message lands on the field, not as a general error.

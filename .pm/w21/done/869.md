# Scan Receipt says "Please try again" and offers a Try Again that can never work for permanent server refusals (e.g. a self-hosted server with no S3 or LLM keys)

**Severity:** moderate. **Estimate:** 20 minutes. Owner: mobile. A3: `receipt-capture-screen/receipt-utils.ts:66-86`. `parseErrorCode` maps every code except `RESOURCE_LIMIT_REACHED` to `parse_failed`, and `receiptCanRetry` refuses retry only for `quota_exhausted`. On the upload leg, `use-receipt-workflow.ts:184-193` maps any error to `receiptUploadFailed`.

Not run natively. Under `tsx` (the agent's proof), `CONFIGURATION_ERROR`, `INTERNAL_SERVER_ERROR`, `FORBIDDEN` and `BAD_USER_INPUT` on the parse leg all give "Could not read receipt. Please try again." with retry allowed. A `CONFIGURATION_ERROR` on upload gives "Upload failed. Please try again." with retry allowed. A default `deploy/docker` install leaves `TEMP_ASSETS_AWS_S3_*` and the LLM keys empty (`.env.example:70-95`), so every scan fails and each Try Again re-uploads the same photo.

## Fix

Classify permanent codes (`CONFIGURATION_ERROR`, `FORBIDDEN`, `BAD_USER_INPUT`, LLM not configured) separately from transient ones. Give permanent codes their own copy ("Receipt scanning isn't set up on this server") and no retry.

**Acceptance:** these codes show a non-retryable message. Unit cases are added.

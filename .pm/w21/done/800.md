# Profile throws away edits on Back without asking, unlike every other edit form

**Severity:** minor. **Estimate:** 15 minutes. Owner: mobile. A3: `mobile/src/screens/profile/profile-screen.tsx` is the only edit form that never calls `useUnsavedChangesGuard`. The file editor, Edit Transaction, Add Budget, New Transaction and Open Account all use it. A changed first name is plain form state, and the route (`app/(app)/profile.tsx`) adds no guard.

Reproduced natively on the iPhone 17e simulator, English UI, Metro `--clear` at `4c314cfc7`; nothing was saved. ☰ ▸ the account row ▸ Settings ▸ the account row ▸ Profile ▸ paste "Qa" into **First name**. Save turns active. Tap Back: Settings appears at once, with no "Discard changes?" alert, and the edit is gone.

## Fix

`useUnsavedChangesGuard(hasChanges && !saved, leavingSavedRef)`, with the ref set before the `router.back()` that follows a successful save.

**Acceptance:** Back or swipe-back after an edit asks to discard, and Back after a save doesn't. A source case is added, like the other forms'.

---

**Resolved 2026-10-23** — Profile (`screens/profile/profile-screen.tsx`) now calls `useUnsavedChangesGuard(hasChanges && !saved, leavingSavedRef)`, as the other edit forms do. `hasChanges` is the same `profileChanges` comparison its Save button uses. Back or swipe-back after an edit asks "Discard changes?". A successful save sets `leavingSavedRef` before its `router.back()` (or the Settings replace), so the Back after a save doesn't ask. Source and unit cases are in `profile/__tests__/unsaved-guard.test.ts`; the two wiring cases fail at the previous HEAD. Not checked natively. Shipped in the commit that moves this note.

Native recheck (iPhone 17e, fresh Metro `--clear` at `2cd441283`, second launch, English UI; nothing was saved): ☰ ▸ the account row ▸ Settings ▸ the account row ▸ Profile ▸ paste "Qa" into First name ▸ Back. It now shows "**Unsaved Changes — Discard your changes?**" with Cancel and Discard. Discard returns to Settings, and the name stays unset. Fixed. Swipe-back and Back after a save were not exercised.

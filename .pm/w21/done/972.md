# Accent folding (w21/929) stops two distinct accented account names being told apart: Create is hidden and the wrong account is called closed

**Severity:** moderate. A legitimate new account can't be created from the picker, and the picker names a different account as closed. **Estimate:** 20 minutes. Owner: mobile. This is a regression of w21/929 (`7f7e80a21`).

**Root cause (A3).** `nameKey` (`mobile/src/common/account-close-dates.ts:205`) now folds accents. `nameKey` is the identity key for exact-name decisions, not only for fuzzy search: `showCreateBelowResults` (`picker-sections.ts:189-215`), `closedAccountNamed` (`:216-219`) and `notYetOpenAccountNamed` (`:237-240`) all use it. `Expenses:Cafe` and `Expenses:Café` are different Beancount accounts.

`foldAccents` also folds non-Latin letters, though its doc comment promises Latin only: `Расходы:Мой` becomes `Расходы:Мои` (й to и) and `Ёлка` becomes `Елка`.

Not run natively in this pass. `tsx` proof (the agent's, with the real functions):
- `showCreateBelowResults("Expenses:Cafe", ["Expenses:Café"], …)` returns `false`; with `["Expenses:Cafe2"]` it returns `true`. So Create is not offered for `Expenses:Cafe`.
- `closedAccountNamed("Expenses:Cafe", …, {Expenses:Café closed})` returns the `Café` account, so the user is told a different account is closed.
- `fuzzyMatch("мои", "Expenses:Мой")` scores 37.

## Fix

Keep `nameKey` accent-exact, and apply `foldAccents` only inside `fuzzyMatch` and the search ranking. In `foldAccents`, fold only when the base letter is Latin (`/\p{Script=Latin}/u`).

**Acceptance:**
- `showCreateBelowResults("Expenses:Cafe", ["Expenses:Café"])` is `true`.
- `closedAccountNamed("Expenses:Cafe", …)` is `null` when only `Café` is closed.
- `fuzzyMatch("cafe", "Expenses:Café")` still matches.
- `foldAccents("Мой")` is `"Мой"`.

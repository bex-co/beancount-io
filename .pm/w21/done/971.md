# A transaction the ledger couldn't interpolate shows blank posting amounts and an unsigned, misleading headline

**Severity:** minor. It affects only ledgers that already have bean-check errors. **Estimate:** 30 minutes. Owner: mobile.

**Root cause (A3).**
- When booking fails, the engine still returns the transaction with `units: null`; this was confirmed against the real `@rustledger/wasm` for a single posting, two elided postings and `1e3 USD`. The ledger's own error list has the matching "interpolation failed" messages.
- `serializePosting` in the ledger's `journal-serialize.ts` (about `:176-180`) then sends `units: { number: "", currency: "" }`.
- `selectPostingRows` (`mobile/src/screens/transaction-detail-screen/selectors/select-transaction-detail.ts:265`) passes the empty string to `formatPostingUnits`, so the amount is `" "`.
- `selectTransactionAmount`, fed `{ "": "" }`: with both postings elided there is no headline, and with `Expenses:Food 12.50 USD` plus an elided `Assets:Cash`, the row reads `$12.50` with no sign, where a normal spend reads `-$12.50`.

Not run natively in this pass. Proof with `tsx` against the real helpers.

**Native steps:** append a one-posting transaction to a QA file, then compare Transactions and the detail screen with the Ledger errors list.

## Fix

Treat an empty `units.number` as "no amount". The detail posting row shows a dash or "No amount", and the headline skips that leg or shows the `mixedLabel`.

**Acceptance:** a unit case for `selectPostingRows` with `{ number: "", currency: "" }` expects a non-blank `amount`.

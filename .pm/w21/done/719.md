# In a CAD ledger, a USD merchant's header still reads "$120.00" over rows reading "−60.00 USD" (w21/699 vs w21/535)

**Severity:** minor (the same ambiguous "$" w21/699 removed from rows, now only in Merchants). **Estimate:** 15 minutes. Owner: mobile. A3: when a merchant has a single currency, `merchant-detail-screen/selectors/format-merchant-total.ts:52-53` keeps the symbol formatter, so USD reads "$". The Merchants list's recurring amount does the same (`merchants-screen/merchant-row-text.ts:64`). w21/699 switched the transaction rows to codes for non-operating dollars, so the header and its own rows now disagree.

Native (iPhone 17e, Metro `--clear` at `370711d32`; disposable ledger with `operating_currency` swapped to CAD, restored byte-for-byte): drawer ▸ Merchants ▸ CITY BUS (the QA ledger's USD transit payee). The header reads **"$120.00"** and both rows read **"−60.00 USD"**, while Home's "$" means CAD. Under `tsx` (the agent's proof), `formatMerchantTotals([{total:-42.5,currency:"USD"}],"CAD")` returns `['-$42.50']` and `merchantRowText` gives "-$15.99" for a USD recurring row.

## Fix

Use the same rule as w21/699 in the merchant header and the list's recurring amount: a dollar currency that isn't the operating currency reads by code.

**Acceptance:** in a CAD ledger, a USD merchant's header and recurring row read "USD". A USD ledger is unchanged. Unit cases are added.

## Dedupe

Conflict between w21/699 and w21/535 (both done). Searched `.pm/**` for formatMerchantTotals and merchantRowText together with CAD.

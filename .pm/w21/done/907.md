# A stock buy dated after today turns a cash account into "0 VOO" on account detail

**Severity:** minor. The header, the chart and every journal row read in the wrong unit. **Estimate:** 30 minutes. Owner: mobile. A3: `mobile/src/screens/account-detail-screen/selectors/select-account-balance-series.ts:46` picks the display unit from the units report's last point through `latestBalance(...)`, with no `today` cap. The units series beside it (`:95`, `point.date <= today`, from w21/517) does drop future points.

Not run natively in this pass. Proven with `tsx` against the real selectors.

**Fixture.** Today is 2026-10-23. `Assets:QaBroker` has:
- a $4,800.00 deposit on 2026-10-05;
- "QA Buy VOO" on 2026-11-02: 10 VOO {480.00 USD}, paid from the account's own USD.

**Results:**
- `selectAccountBalanceDisplay(...)` returns units `{"currency":"VOO","number":10}`.
- `selectAccountUnitsSeries("VOO", units, today)` returns `[{"date":"2026-10-05","value":0}]`.
- With VOO units, `selectAccountJournalRows` gives the deposit row a change of 0, otherChanges `+4800 USD`, and a balance of 0.
- A buy dated 2026-10-28 gives the same result. Even `latestBalance(points, today)` still returns `{"VOO":"10"}`, because it caps by month, not by day, so copying the w21/665 fix would not be enough.

**Native steps** (disposable ledger):
1. Add `price VOO 500.00 USD` dated 2026-10-01, the deposit and the future buy.
2. Open Accounts and tap the QaBroker row.

**Expected:** the screen reads in money, with the deposit row at "+$4,800.00".

**Actual:**
- The header reads "0 VOO", with "Balance · $5,000.00 at market" over "Not enough data to chart yet".
- The deposit row reads "+4,800.00 USD · not in total" and "Balance: 0 VOO".

## Fix

Choose the units balance from the last units point dated on or before `today`, comparing by day as `selectAccountUnitsSeries` does. Use the same rule for the `latest` fallback.

**Acceptance:** add unit cases to `select-account-balance-series.test.ts`. With the buy dated 2026-11-02, and again 2026-10-28, the display is money. Once today passes the buy date, it reads "10 VOO".

## Dedupe

This is the account-detail version of done w21/665, which fixed Home only (`select-balance-sheet-series.ts:39-41`). Done w21/517 capped only the units series. The Accounts row's future-entry scope is blocked w21/674. Searched for "latestBalance", "selectAccountBalanceDisplay", "reads in units" and "0 VOO".

---

**Resolved 2026-10-24** — `selectAccountBalanceDisplay` picks the display unit, and the market fallback, from the last report point dated on or before today (by day, since the account report is change-only), so a buy dated 2026-10-28 or 2026-11-02 leaves the account reading in money until the day arrives, then in "10 VOO". `latestBalance` is untouched: Home's month-end points need its month cap. Cases in `select-account-balance-series.test.ts` (`mobile`). Not run natively.

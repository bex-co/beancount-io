# The AVERAGE check reads the first `booking_method` option, though the last value wins: a false error, or a missed one (w21/708 regression)

**Severity:** minor. **Estimate:** 10 minutes. Owner: ledger. A3: `average-booking.ts:4` and `:26` use `OPTION.exec`, which returns the first match. The engine itself reports E7003 "…set more than once; the last value wins".

Proven with the real engine under ts-node at `HEAD` and at the parent of the fix commit (as `yarn verify:rustledger` runs it), against Beancount 3.2.3 `bean-check`. Not on production: the ledger service hasn't been redeployed since before w21/675.

`option "booking_method" "AVERAGE"` followed by `option "booking_method" "FIFO"`, then an account opened without a method, a buy of 10 VTI {100 USD}, and a sale of `-5 VTI {} @ 300 USD`. bean-check is clean. The engine reports E7003 (as before) **plus a false "AVERAGE method is not supported"** on the sale. With the two options reversed (FIFO, then AVERAGE), bean-check refuses the sale and the engine misses it.

## Fix

Read the last `booking_method` option, the same as the engine and Beancount.

**Acceptance:** both orders match bean-check. A unit case is added.

## Dedupe

Regression from w21/708 (done). Searched `.pm/**` for booking_method together with "last value".

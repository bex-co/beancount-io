# A CRLF main.bean still gets a bare-LF line when an add creates a routed year file and its include (w21/673 gap)

**Severity:** minor (mixed line endings in Windows-authored ledgers). **Estimate:** 10 minutes. Owner: ledger. A3: w21/673 made the entry write keep the target file's line ending. When the add routes to a new year file, though, `addIncludes` (`backend-cluster/ledger/src/features/ledger/utils/routed-includes.ts:10-23`, called from `src/api/entries.ts:291`) splits and joins `main.bean` on `"\n"` and appends `include "…"` with a bare LF. w21/673 asked to cover the other add paths too.

Proven with the real code under ts-node (as `yarn verify:rustledger` runs it): a CRLF `main.bean` with `2000-01-01 custom "beancountio-option" "transaction_file" "txns/{year}.bean"`, `include "txns/2025.bean"` and the opens, and no `txns/2026.bean`. An `addEntries` for today leaves `main.bean` with 3 CRLF and 1 bare LF (`include "txns/2026.bean"\n`). With no existing include line, the appended include also ends in a bare LF. Not run on production: the ledger service hasn't been redeployed since w21/673.

## Fix

Use the same `lineEndingOf` / `appendBlock` helpers in `addIncludes`.

**Acceptance:** with this fixture, every line of `main.bean` ends in CRLF after the add, and LF files are unchanged. A unit case is added.

Gap in w21/673 (done). Related: w23/062 (routed includes). Searched `.pm/**` for addIncludes and routed-includes together with CRLF.

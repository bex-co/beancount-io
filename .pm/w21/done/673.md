# New Transaction appends LF lines to a CRLF ledger file (add-path sibling of w21/252 and w21/062)

**Severity:** minor (mixed line endings; the ledger still parses, but every add makes a noisy diff in a Windows-authored file). **Estimate:** 20 minutes. Owner: ledger. A3: the add path builds the new content as `cached.current + "\n"` plus `entryInputToText`'s LF text (`backend-cluster/ledger/src/api/entries.ts:303`). Edit Transaction keeps CRLF (w21/252) and the file editor keeps it (w21/062), but adding an entry doesn't.

Production, through GraphQL on the disposable ledger (restored byte-for-byte): `main.bean` rewritten with CRLF endings (87 CRLF, 0 bare LF), then `addEntries` with one transaction (`QA CrlfCafe`, Assets:Cash −3.00 USD → Expenses:Food:Groceries) — the same mutation New Transaction's Done sends. The file afterwards holds 87 CRLF and 5 bare LF:

```
… Assets:Cash  49.75 USD\r\n\n2026-10-22 * "QA CrlfCafe" "Coffee"\n  Assets:Cash   -3.00 USD\n  …
```

## Fix

Detect the file's line ending, as the edit path does (w21/252), and write the separator and the new entry with it. Cover `bulkEntries` and the other add paths too.

**Acceptance:** adding to a CRLF file leaves every line ending CRLF. LF files are unchanged. A unit case is added.

## Dedupe

Add-path sibling of w21/252 (done; edit) and w21/062 (done; file editor). w21/272 is the Entry Context display. Searched `.pm/**` for CRLF together with add, addEntries and "line ending".

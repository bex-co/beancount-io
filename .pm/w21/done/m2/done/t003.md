## Objective

Confirm each screen without its own scroll container needs no readable-width
cap — because it inherits one (scaffold, multi-postings form), is not a
scrolling content screen (camera, code editor), or is already width-bounded —
and cap any that do.

## Context

- w21/1005 capped the Add Budget, Open Account, and multi-postings forms; Add Transaction and Edit Transaction render through multi-postings.
- `contentColumn` exists at `mobile/src/common/content-column.ts`.

## Steps

1. Open each screen below and establish how its content is laid out.
2. Cap with `...contentColumn` (plus a `content-column.test.ts` consumer check) any screen whose content runs edge to edge on iPad.
3. Record per screen, in the ship summary, why it needed no change or what changed.
4. Run the mobile gates if anything changed: `yarn format:check`, `yarn lint`, `yarn typecheck`, `yarn test:unit` (from `mobile/`).

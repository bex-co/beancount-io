# "Try again" on the shared "Failed to load" tile shows no progress, and offline nothing changes at all

**Severity:** minor. It affects about a dozen screens. **Estimate:** 30 minutes. Owner: mobile.

**Root cause (A3).**
- `mobile/src/components/card-load-failure/index.tsx:43` calls a bare `refetch()`. None of these queries set `notifyOnNetworkStatusChange`, so `useQuery` never reports loading while the refetch runs.
- When the refetch fails again, Apollo's `onError` (`@apollo/client/react/hooks/useQuery.js:243-246`) skips the update, because the new error is deep-equal to the one already shown.

**Affected:** Home chart, Recent Transactions, Spending, Budget groups, Latest Updates, Notifications, commit detail, Profile, Settings profile, Reports and Entry Context.

Not run natively; the simulator can't fail one app's network. `tsx` proof, using a copy of `useQuery`'s update logic:
- Offline tap: "error equal to the one on screen: no render".
- Online tap with an 800 ms response: at 400 ms the screen still shows `loading=false error=true`.

## Fix

Let `CardLoadFailure` own a busy state:
- take `onRetry: () => Promise<unknown>`;
- show a spinner and disable the button until the retry settles;
- announce the result.

Or pass `notifyOnNetworkStatusChange: true` on the affected queries.

**Acceptance:**
- While `onRetry` is still pending, the busy state shows.
- A second identical failure announces "Failed to load" again.

---

**Resolved 2026-10-24** — `CardLoadFailure` owns a busy state: "Try again" disables itself and shows a spinner until the retry settles and for at least 600 ms, so a refetch whose new error equals the one on screen no longer looks like a dead tap; if the card is still there afterwards it announces "Failed to load" again. `onRetry` may return the retry's promise, and the nine call sites that discarded it with `void` now return it. Source cases in `card-load-failure-busy.test.ts`; four existing pins updated (`mobile`). Deviation: the sites with named retry handlers (`retry`, `retryRows`, `onRetry`) keep the 600 ms minimum only unless their handlers return a promise. Not run natively.

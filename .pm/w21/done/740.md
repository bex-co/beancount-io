# Errors from built-in plugins (`leafonly`, `noduplicates`, `coherent_cost`, `onecommodity`, `unique_prices`) carry no file or line, so their Notifications rows can't be tapped

**Severity:** minor. **Estimate:** 30 minutes. Owner: ledger. A3: `backend-cluster/ledger/src/features/ledger/service/ledger-data-mappers.ts:44-56` maps plugin errors with `source: null`. Unlike option errors (w21/309) and booking errors (w21/534), there's no relocation step for them in `engine.ts:714-720`. `leafonly` is also reported once per posting (7 rows instead of 1).

Production, through `getLedgerErrors` on the disposable ledger (restored byte-for-byte): the `unique_prices` error in w21/735 came back with filename and line null. Proven with the real engine under ts-node (in-process snapshot, `LedgerDataService.getErrors`/`getTrialBalance`/`getAccountJournal`) against Beancount 3.2.3 `bean-check`/`bean-query` (the agent's run). bean-check gives each of these a location ("main.bean:10: Non-leaf account …", "main.bean:21: Duplicate entry", "main.bean:13: Currency 'VTI' is used both with and without cost"), while the service gives `source: null`, `code: "PLUGIN"` for all of them. Mobile's Notifications rows can't open the editor (`canFix = !!err.filename`), and the file editor's error banner never lists them. w21/189 mentioned plugin errors in passing; never filed.

## Fix

Carry the offending directive's location through the plugin error mapping (the engine has the entry), and dedupe `leafonly` per account.

**Acceptance:** each plugin's error lands at bean-check's file and line, and `leafonly` reports once per account. Unit cases are added.

**Resolved 2026-10-23**. Each plugin now places its errors where bean-check 3.2.3 does:

- `onecommodity` and `unique_prices` were already placed by w21/736 and w21/735.
- `leafonly` (new `leafonly.ts`): when declared directly or through pedantic, the engine's per-posting errors are replaced by Beancount's. That is "Non-leaf account 'X' has postings on it", once per account, on its open line. A parent holding anything but its open and balances counts, notes included.
- `noduplicates` (`noduplicates.ts`): each engine error is placed on the later copy it is about. The copies are the day's same-narration transactions that repeat an earlier one, compared without metadata, comments or spacing. The engine's wording is kept, since Beancount's prints both entries' internals.
- `coherent_cost` (`coherent-cost.ts`): the engine does not run it at all, so a ledger bean-check refused read as healthy. It now raises Beancount's "Currency 'X' is used both with and without cost" on the first transaction using it without cost.

Two shared source locators move into `block-index.ts` (`openLocations`, `entryLocator`); the AVERAGE, generated-close and nounused checks now use them. Unit cases are in `plugin-locations.test.ts`. A live engine case in `scripts/verify-rustledger.ts` gives bean-check's lines 4, 16 and 22; at the previous HEAD it gives three unlocated errors and no coherent_cost one. A ledger-service deploy is needed to reach production. Shipped in the commit that moves this note.

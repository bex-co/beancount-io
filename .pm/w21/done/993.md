# The dashboard rounds some currencies to whole units (HUF, COP, IDR, PKR, …), while mobile follows ISO 4217 and shows two decimals

**Severity:** moderate. It is a loss of precision for a currency someone may use for everything, and the two apps show different amounts. **Estimate:** 30 minutes. **Owner: dashboard** (filed here from a mobile-versus-dashboard comparison; the dashboard board is w4). The mobile side is right.

**Root cause (A3).**
- Dashboard: `dashboard/src/common/lib/format/format-number.ts`, `currencyMinorDigits` (`:84`, reading `resolvedOptions().maximumFractionDigits` at `:93`) and `formatNumber`. It takes the digit count from `Intl.NumberFormat`, which follows CLDR's cash digits.
- Mobile: `mobile/src/common/currency-util.ts:69-103`, the `MINOR_UNITS` table with a default of 2, which is the ISO 4217 scale (w21/070).

Not reproduced in the browser. `tsx` proof (the agent ran both sides), for the amount 1234.56 with the same locale:

| Currency | Dashboard `formatNumber(1234.56, true, "en", c)` | Mobile `currencyMinorUnits(c)` |
|---|---|---|
| HUF | `1,235` | 2 |
| COP | `1,235` | 2 |
| IDR | `1,235` | 2 |
| IQD | `1,235` | 3 |
| USD | `1,234.56` | 2 |

Across all `Intl.supportedValuesOf("currency")` codes, 17 differ: AFN, ALL, COP, HUF, IDR, IQD, IRR, KPW, LAK, LBP, MGA, MMK, PKR, SLL, SOS, SYP, YER. The dashboard shows 0 digits for all of them; mobile shows 2, except IQD at 3. A small residue also collapses on the dashboard: -0.40 HUF renders as `0`.

## Fix

In the dashboard, take the digit count from an ISO 4217 table instead of `Intl`. Don't import across packages; a shared fixture of expected digits would keep the two copies in step.

**Acceptance:** `formatNumber("1234.56", true, "en", "HUF")` gives `1,234.56`; the same call with IQD and `"1234.567"` gives `1,234.567`; JPY and KRW stay at 0.

## Dedupe

Searched `.pm/**` for "minor unit", "ISO 4217", "CLDR", "HUF", "IDR", "COP" and "PKR": nothing for these codes. w21/070 and w4/m45 and m55 cover other cases.

---

**Resolved 2026-10-24** — the dashboard's `currencyMinorDigits` takes the ISO 4217 digits for the 17 codes where `Intl` follows CLDR's cash digits (AFN, ALL, COP, HUF, IDR, IRR, KPW, LAK, LBP, MGA, MMK, PKR, SLL, SOS, SYP, YER at two, IQD at three), through a small table, and leaves every other code on what `Intl` reports, so `formatNumber("1234.56", true, "en", "HUF")` is `1,234.56` and JPY and KRW stay at 0. Commodities that are not ISO currencies are untouched. Cases in `format-number.test.ts` (`dashboard`; format, lint and the full suite green). Not run in a browser.

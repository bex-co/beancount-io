# A NUL character in the payee or narration is committed, and then none of the file's entries load

**Severity:** major (one pasted character takes a ledger file offline; Beancount 3.2 reads the same file fine). **Estimate:** 20 minutes. Owner: ledger (and mobile input). A3: nothing checks text fields for control characters, neither `entries.ts` nor Edit's `assertSingleEntryText`. The precheck runs on the projected text without the loader's strict decoding (`ledger-data-service.ts:481-506`). The real loader then refuses any file that contains NUL (`src/features/gitea/utils/gitea-file-content.ts:59-63`). Edit Transaction is affected too: in the agent's run, `newContent` with "lun\u0000ch" returned "Entry updated successfully".

Production, through the `addEntries` mutation New Transaction sends (`multi-postings-transaction-screen.tsx:687`), on the disposable ledger (restored byte-for-byte after each probe). The agent also ran the real `main` service code (`08cbe6191`) in memory and checked it against Beancount 3.2.

`addEntries` with narration "qa nul a\u0000b" returned `success: true`. Afterwards `getLedgerErrors` is just "main.bean is not UTF-8 text (invalid UTF-8 or binary data), so none of its entries were read". Every account and transaction in main.bean disappears from the app until the file is repaired. A NUL can't be typed on a phone, but it can arrive by paste (and through the API and MCP).

## Fix

Reject (or strip) C0 control characters other than tab in payee, narration, metadata values and edited slices, before the precheck, with a clear validation message. Also make the precheck use the loader's strict decoding, so a write that would make the file unreadable counts as a new error. Mobile can strip them when text is pasted.

**Acceptance:** this add is refused with a field error and the file is unchanged. Edit Transaction is covered too. Unit cases are added.

## Dedupe

Not w21/679 (an existing non-UTF-8 file). Searched `.pm/**` for NUL, "control character" and "\\u0000".

---

**Resolved 2026-10-23** — the bulk/`addEntries` route refuses a control character (`\p{Cc}` other than tab, LF and CR) in any text field, key or value of a row with a field error, before any file is read (`assertNoControlCharacters`), and an edited slice is refused the same way (`assertSingleEntryText`), so the NUL add is refused and the file is unchanged. Tests: `entry-tokens.test.ts` and a route test in `entries-amount-syntax.test.ts` (fails without the change), shipped in the commit that closes this note (`backend-cluster/ledger`). Not done: the precheck still decodes leniently (the refusal above removes the way in) and mobile does not strip pasted control characters. Needs a ledger deploy to reach production.

# A merchant's header total still rounds BTC to 2 decimals: "0.00 BTC" above a "−0.004 BTC" row (w21/595 incomplete)

**Severity:** minor (crypto ledgers). **Estimate:** 15 minutes. Owner: mobile. A3: w21/595's title names merchant totals, but `merchant-detail-screen/selectors/format-merchant-total.ts:26` and `:53` still zero any total under 0.005 before formatting, whatever the currency. The formatter on its own gives "0.004 BTC".

Native (iPhone 17e at `d731eb32a`; disposable ledger restored byte-for-byte):

```
2026-01-01 commodity BTC
2026-01-01 open Assets:Qa20261020Wallet BTC
2026-01-01 open Expenses:Qa20261020Food
2026-10-01 * "QA Lightning Cafe" "sats"
```

Merchants ▸ QA Lightning Cafe: the header reads "0.00 BTC", while its only row reads "−0.004 BTC". Home's Recent Transactions also shows "−0.004 BTC".

## Fix

Drop the clamp, or clamp only below the currency's own display precision, as w21/595 did for the other surfaces. Use the same rule in both branches.

**Acceptance:** the header reads "0.004 BTC" (sign as elsewhere). USD dust under half a cent still reads $0.00. Unit cases are added.

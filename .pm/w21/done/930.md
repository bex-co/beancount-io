# A closed or not-yet-open exact account name is explained only when the picker search has no other hits

**Severity:** low. The user sees an unrelated row, no Create row, and no reason why. **Estimate:** 15 minutes. Owner: mobile.

**Root cause (A3).** `mobile/src/screens/account-picker-screen/account-picker-screen.tsx:551-560` computes `closedMatch` and `futureMatch`. Both suppress the Create rows (`:569`, `:590`). The "closed on…" and "opens on…" notes, though, render only inside `ListEmptyComponent` (`:731`), which never shows when loose matches exist.

Not run natively in this pass. `tsx` proof with `Expenses:Phone` closed on 2026-09-01:
- `phone` lists `["Expenses:Housing:Rent"]`, `closedMatch` is set, the note isn't visible, and there is no Create row.
- Without the Rent account, the note shows.

**Native steps:**
1. On a disposable ledger, close `Expenses:Phone` and keep `Expenses:Housing:Rent`.
2. Go to New Transaction ▸ expense account and paste `phone`.

Only Rent is listed, with no note.

## Fix

Also render the closed and opens-later notes as the list footer when `closedMatch` or `futureMatch` is set and results exist.

**Acceptance:** `phone` shows Rent plus "Expenses:Phone was closed on September 1, 2026", and still no Create.

## Dedupe

w21/122, w21/374 and w21/531 fixed only the empty-results path. Searched for "closedAccountNamed", "notYetOpenAccountNamed", "ListEmptyComponent" and "accountPickerClosedOn".

---

**Resolved 2026-10-24** — the "closed on…" and "opens on…" notes are one `matchNotes` element, rendered in the empty state as before and now as the list footer when loose matches exist (Create still hidden). Source case in `picker-sections.test.ts` (`mobile`). Deviation: pinned in source, not rendered. Not run natively.

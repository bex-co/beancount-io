# A plugin copy's "Open the source entry" opens a blank "No entry context data available": the amortize source has no entry of its own (w21/508 follow-up)

**Severity:** minor (the new link is a dead end for every amortize copy). **Estimate:** 30 minutes. Owner: mobile (and possibly ledger). A3: w21/508 added "Open the source entry", which navigates to transaction detail with the copy's `generated_from` hash. For an `amortize_over` source, the plugin replaces the original entry with its copies. `getLedgerEntryContext(<source hash>)` returns the source's `slice` and `sha256sum`, but `entry` holds only `{meta: {filename, lineno}}`, with no date or postings. `transaction-detail-screen.tsx:600` then shows `journalNoData`.

Native (iPhone 17e at `d731eb32a`, fresh Metro `--clear` with `d731eb32a`; disposable ledger restored byte-for-byte): w21/443's amortize fixture (600.00 USD over 12 months from 2026-06-01). The (5/12) copy's detail correctly shows "A plugin generated this entry from another one, so it can't be edited or deleted here." with no Edit pencil. Tapping **Open the source entry** opens a "Transaction" screen that reads only "No entry context data available". Production, read-only: the source hash `c0f2e35cbb…` returns slice `2026-06-01 * "QA Insurer" "qa-20261020 car insurance"` with `amortize_months: 12` and the 600.00 postings, and `entry: {meta: {filename: "main.bean", lineno: 92}}`.

## Fix

When the source has no live entry, render it from its slice: show the written text read-only with Edit (it's the real, editable source), or open the file editor at `main.bean:92`. Alternatively, have the ledger service return the pre-plugin entry for a `generated_from` source.

**Acceptance:** Open the source entry shows the amortize source (its text, date and amount) and lets the user edit it there. A test covers a source whose context has a slice but no entry.

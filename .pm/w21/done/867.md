# Guests can't load a transaction's Entry Context: w21/508's new GetLedgerTransactionContext query is missing from the guest allowlist (w21/635 class, regressed)

**Severity:** major for guests (every example transaction). **Estimate:** 10 minutes. Owner: mobile. A3: w21/508 (`d731eb32a`) made transaction detail read through `GetLedgerTransactionContext` (`transaction-detail-screen/use-transaction-context.ts:20`). That query isn't in the guest client's `PUBLIC_OPERATIONS` (`mobile/src/common/guest/guest-client.ts:31-54`), whose gate refuses it with "Guest operation is not a public example read". `isUnsupportedDocumentError` doesn't match that message, so the screen never falls back to `GetLedgerEntryContext`.

Not run natively (it needs signing out). Under `tsx` with the real `createGuestClient` and a stubbed fetch (the agent's proof): `GetLedgerTransactionContext -> REJECTED: Guest operation is not a public example read`, while `GetLedgerEntryContext -> reached network`. A guest opening a row sees Entry Context stuck on "Showing cached numbers — they may be out of date", and loses the entry's error rows and plugin-copy check. Opening a guest entry link with nothing cached shows a failure card whose Retry can never succeed.

## Fix

Add `GetLedgerTransactionContext` to `PUBLIC_OPERATIONS`, with a row in `guest-access.test.ts`. Better still, add a test that every document used by a guest-reachable screen is allowlisted.

**Acceptance:** a guest's transaction detail loads its context without a stale banner. Tests are added.

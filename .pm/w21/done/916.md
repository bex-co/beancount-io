# On a self-hosted server, Settings still offers Invite Friends, which shares a beancount.io sign-up link carrying the self-hosted user's id

**Severity:** minor (privacy, and self-hosted users get hosted-service UI, the same class as w21/155). **Estimate:** 15 minutes. Owner: mobile.

**Root cause (A3).**
- `mobile/src/screens/setting/about.tsx:11` always renders `InviteSection`, with no server check.
- `ReferralScreen` builds `buildReferralUrl(Platform.OS, userId)` (`referral-screen.tsx:87`) from the session's `userId` on whatever server the user signed in to.
- The destination is deliberately hard-coded to the hosted sign-up page (`src/common/referral-url.ts:4`).

So a self-hosted user shares `https://beancount.io/auth/sign-up?src=ios&by=<their-self-hosted-id>`. That sends friends to the hosted service and publishes an id from another server. It gains nothing either: backend-v2 ignores `inviteBy` (`backend-cluster/backend-v2/src/features/auth/api/auth-resolver.ts:368`, "accepted for backward compatibility but no longer used").

Not run natively; it needs a self-hosted server. `tsx` proof: `buildReferralUrl("ios","42")` returns `https://beancount.io/auth/sign-up?src=ios&by=42` whatever the server is. No `isOfficialServerUrl` check exists on the Settings or referral path; that check is used only in the welcome, examples and guest links.

**Native steps:**
1. Point the app at a self-hosted server URL and sign in.
2. Open Settings: the Invite Friends card is shown.
3. Open Referral: the shared link points to beancount.io and carries the local id.

## Fix

- Render `InviteSection`, and allow the `/referral` route, only when `isOfficialServerUrl(getServerUrl())`.
- Optionally drop `by`, since nothing reads it.

**Acceptance:**
- With a non-official server URL, Settings shows no Invite Friends card, and `/(app)/referral` redirects.
- With the official URL, nothing changes.

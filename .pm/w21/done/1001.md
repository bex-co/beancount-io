# Merchants, Merchant detail and the account picker don't inset their lists for the home indicator, so the last row ends under it

**Severity:** minor to moderate. The last row or footer on the bottom-most lists of those screens can never scroll clear of the home-indicator zone (about 34 pt on the iPhone 17e). **Estimate:** 20 minutes. Owner: mobile.

**Root cause (A3).** These are pushed Stack screens (no tab bar), and React Native's default `contentInsetAdjustmentBehavior` is "never", so nothing adds the bottom safe area:
- `mobile/src/screens/merchants-screen/merchants-screen.tsx`: the root is a plain `View`, and the list's `listContent` is `{ flexGrow: 1 }` (`:90-92`). `useSafeAreaInsets` is used only for the keyboard overlap (`:166`).
- `mobile/src/screens/merchant-detail-screen/merchant-detail-screen.tsx`: the same shape (`:108-110`), and the only footer is the loading indicator.
- `mobile/src/screens/account-picker-screen/account-picker-screen.tsx` (about `:164-168`, `:666-733`): `listContent` is `paddingBottom: gutter` (16), described in a comment as only the keyboard inset; there is no `insets.bottom`.

Sibling pushed screens do handle it: account detail, Budget, Notifications, commit detail, transaction detail, Add Budget, Open Account, Transaction Filters, multi-postings and the agent screen wrap in `SafeAreaView edges={["bottom"]}`, and `edit-transaction` and `valuation-sheet` use `insets.bottom`.

Not run natively in this pass: the simulator driver can't scroll, and on a short list the last row isn't near the edge. I confirmed in the code that Merchants and Merchant detail have no bottom padding or inset at all. On Merchants, the screenshot of the 11-row list shows the list frame running to the physical screen edge, with a row cut off there. A manual flick to the end shows the last row sitting on the home indicator.

## Fix

On the three lists, either add `paddingBottom: insets.bottom` to the content container, set `contentInsetAdjustmentBehavior="automatic"`, or wrap the screens in `SafeAreaView edges={["bottom"]}` like their siblings. The picker's `automaticallyAdjustKeyboardInsets` should keep working with the first two.

**Acceptance:** a source guard fails any pushed-route screen whose list has none of the three; at full scroll, the last merchant row's bottom edge ends at or above the home-indicator zone.

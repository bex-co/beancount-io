# A pad that isn't needed at its first balance silently hides a later failing balance: no error, no Off-by, bell at 0

**Severity:** major (a failed reconciliation looks like a pass). **Estimate:** 1–2 hours. Owner: ledger. A3: rustledger 0.24 returns no error and no padding for this ledger, and `engine.ts:166-176` (`snapshotOf`) passes `getErrors()` and `expandPads()` through unchanged. When the pad's first balance already passes, Beancount reports "Unused Pad entry", and a later failing balance on the same account is still reported. Here both are lost.

Production, through GraphQL on the disposable ledger (restored byte-for-byte; ledger service as deployed 2026-10-22), and the agent's run of the real `main` service code (`e911af9c8`) against an in-memory store, with `bean-check`/`bean-query` 3.2 as the reference.

```
2026-01-01 open Assets:Qa20261020PadCash
2026-01-01 open Equity:Qa20261020Open
2026-01-01 open Expenses:Qa20261020Food
2026-01-02 * "QA Deposit"
  Assets:Qa20261020PadCash  100.00 USD
  Equity:Qa20261020Open  -100.00 USD
2026-02-01 pad Assets:Qa20261020PadCash Equity:Qa20261020Open
2026-02-02 balance Assets:Qa20261020PadCash  100.00 USD
2026-02-03 * "QA spend"
  Assets:Qa20261020PadCash  -10.00 USD
  Expenses:Qa20261020Food  10.00 USD
2026-02-04 balance Assets:Qa20261020PadCash  100.00 USD
```

`getLedgerErrors` lists nothing for this account; bean-check reports "Unused Pad entry" and "Balance failed … expected 100.00 USD != accumulated 90.00 USD". `getLedgerAccountJournal` gives the 02-04 Balance row a running balance of 90.00 with `diff_amount: null`, so account detail shows a passing assertion and the bell stays at 0. If the first balance does need padding, the later failure is reported. Without the later balance, "Unused Pad entry" is reported.

## Fix

After rustledger's pass, re-check balance assertions against the padded running balances, or apply Beancount's rule that a pad applies only to its next balance on that account. Emit "Unused Pad entry" when the pad adds nothing. Pin this as an engine regression case and report it upstream.

**Acceptance:** this fixture yields both bean-check errors, and the 02-04 row shows "Off by −10.00 USD". A unit case is added.

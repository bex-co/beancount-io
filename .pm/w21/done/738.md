# `option "documents"` discovery never runs, so statements in the documents folder never appear in account detail

**Severity:** minor (a documented Beancount/Fava feature silently does nothing). **Estimate:** 1 hour. Owner: ledger. A3: `backend-cluster/ledger/src/foundation/rustledger/document-validation.ts:31-33` says discovery "is still a no-op". `engine.ts:711-714` only filters errors, although `repoPaths` (the repo's file list) is available there. Fava's `tag_discovered_documents` therefore has nothing to tag.

Proven with the real engine under ts-node (in-process snapshot, `LedgerDataService.getErrors`/`getTrialBalance`/`getAccountJournal`) against Beancount 3.2.3 `bean-check`/`bean-query` (the agent's run). `option "documents" "documents"`, an opened `Assets:Qa20261020:Checking`, and a file `documents/Assets/Qa20261020/Checking/2024-02-01.statement.pdf`. bean-query `PRINT FROM has_account(...)` lists a `2024-02-01 document Assets:Qa20261020:Checking ".../2024-02-01.statement.pdf"` entry. `getAccountJournal` returns only the Open and the Transaction. Mobile's account detail renders Document rows (`select-account-journal.ts:84/285`) but never receives any.

## Fix

Implement discovery from `repoPaths`: `<root>/<Account/Path>/<YYYY-MM-DD>.<name>` becomes a `document` directive for an opened account, as Beancount does.

**Acceptance:** this fixture's account journal includes the discovered document, and explicit `document` directives are unchanged. A unit case is added.

**Resolved 2026-10-23** — new `backend-cluster/ledger/src/foundation/rustledger/document-discovery.ts`, run by the engine before any plugin, as `beancount.ops.documents` is. Each `option "documents"` root is resolved against the entry point's directory and read from the repository's file list (`repoPaths`). Under it, a file in an account's folder named `YYYY-MM-DD.<anything>` becomes a `document` of that account, when some entry names the account. The document carries its repository path, is marked generated (it has no source text to edit), and is placed where Beancount sorts it (after the day's entries, before its written documents and closes). A nonexistent date raises bean-check's own "Invalid date on document file …" error. Written `document` directives are unchanged. Fava's `tag_discovered_documents` port now tags only the discovered ones `#discovered`; it was a no-op for lack of discovery. Checked against bean-check/bean-query 3.2.3 on a real folder. Unit cases in `document-discovery.test.ts` and `plugins/__tests__/tag-discovered-documents.test.ts`. The live case in `scripts/verify-rustledger.ts` goes through `getAccountJournal`, parsed and cached; at the previous HEAD it lists only the written document. A known flake, `file-request-limit.test.ts`, failed once in the full run and passed on rerun. Needs a ledger-service deploy to reach production. Shipped in the commit that moves this note.

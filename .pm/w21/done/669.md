# Reports' Recent Transactions fetches the newest 200 entries with no end date, so pre-entered entries empty every range

**Severity:** minor (Reports; ledgers with scheduled or forecast entries). **Estimate:** 20 minutes. Owner: mobile. A3: `reports-screen/components/account-transactions-card.tsx:34` asks for the newest `FETCH_WINDOW` (200) Income/Expenses transactions with no time bound, and `selectors/select-account-transactions.ts:98` then keeps only rows from the range's start month through the anchor month. With 200 or more entries dated after today, the page holds only future rows, and every range except ALL shows "No transactions in this range". With fewer future rows, "Upcoming" rows for later this month crowd the card's 10 rows before today's entries do. Home's card got an end date in w21/471. This one never did.

Native (iPhone 17e at `d731eb32a`; disposable ledger restored byte-for-byte; today 2026-10-22): the QA ledger's history (expenses through Aug 28, 2026) plus 210 daily "QA Cafe" 4.50 USD entries from 2027-01-01. On Reports at the default 6M, the chart still shows May–Oct, but `account-transactions-card` measures 358×91 pt, which is the single "empty" line (the loading tile alone is 160 pt). Without the fixture, the card lists the August rows. Under `tsx` (the agent's proof), the 200-row page spans 2027-01-31 to 2027-08-18, so 1M, 3M and YTD give 0 rows and ALL gives 10 rows starting 2027-08-18. A `fava.plugins.forecast` `[DAILY]` entry produces the crowding variant.

## Fix

Bound the query at the range's end: today, or the anchor month's end per w21/523's rule. Alternatively, page until the window's start is reached.

**Acceptance:** with this fixture, 6M and 1M list the August entries, and ALL lists the newest entries. A unit case is added.

# A Persian or Arabic account path shows its segments child-before-parent ("Qa20261020Bank:ملی:بانک") on Accounts and in the detail header

**Severity:** minor (RTL users read their own account hierarchy backwards). **Estimate:** 20 minutes. Owner: mobile. A3: the Accounts label (`components/account-table/account-table.tsx:383-385`, joined by `compressChain` in `select-account-list.ts:250-252`) and the detail header (`account-detail-screen.tsx:481-487`) render the joined path with no bidi isolation. Two RTL segments around ":" form one RTL run, so they flip. This contradicts the rule stated in `open-account-screen.tsx:146-148` ("the root comes first and the sub-path follows it, in every app direction").

Native (iPhone 17e, Metro `--clear` at `b2ec6ca23`; disposable ledger restored byte-for-byte; today 2026-10-23), with the app in English: `2026-01-01 open Assets:Qa20261020Bank:بانک:ملی` holding 100.00 USD. The Accounts tab row reads "**Qa20261020Bank:ملی:بانک**". The sub-account ملی is drawn before its parent بانک. Under the agent's CoreText check, the runs lay out as `[LTR Qa20261020Bank:] [RTL ملی] [RTL :] [RTL بانک]`.

## Fix

Isolate each segment (U+2068…U+2069 FSI/PDI) or render the path as separate inline segments with LTR separators, in the Accounts rows, the detail header and the picker.

**Acceptance:** the path reads root-first (Qa20261020Bank, then بانک, then ملی) in both LTR and RTL app languages. A unit case is added.

## Dedupe

Related to w21/095, w21/249 and w21/536 (Persian UI) and w21/698 (RTL currency symbols). Searched `.pm/**` for compressChain and RTL together with account path.

**Resolved 2026-10-23** — new `isolateAccountPath` in `mobile/src/common/bidi.ts`. When a path holds right-to-left letters, each segment goes in a first-strong isolate (U+2068…U+2069) and the whole path in a left-to-right isolate, so it reads root-first in every app direction, as Open Account writes a name (w0/049). A Latin path is returned as it is. It is used by the Accounts rows (including an "own postings" row's name), the account detail header and the account picker's parent path; accessibility labels keep the plain path. Checked with CoreText, natural and right-to-left base direction: `Assets:Qa20261020Bank:بانک:ملی` now lays out root first in both. Before, it drew ملی before بانک, and fully mirrored in a right-to-left paragraph. The picker's trailing-separator parent path also reads root first. Unit and source cases are in `common/__tests__/bidi.test.ts` and fail at the previous HEAD. The picker's render harness (`live-font-scale-remeasure.test.ts`) now gets the real `bidi` module. Not run natively. Shipped in the commit that moves this note.

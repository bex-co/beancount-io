# w21/544's fix doesn't work: "View errors" still stacks a second Notifications screen

**Severity:** minor to moderate. This reopens done w21/544. **Estimate:** 20 minutes. Owner: mobile.

**Root cause (A3).** `mobile/src/screens/ledger-file-editor-screen/index.tsx:535` calls `router.navigate("/(app)/notifications")`. w21/544 was closed on the claim that `navigate` returns to an existing Notifications screen. In expo-router 57's stack router (`expo-router/build/layouts/StackClient.js:83-216`), `NAVIGATE` reuses a route only when it is the current top screen or `pop` is set. Neither holds here, so a new Notifications screen is pushed.

The test that closed 544 (`refresh-on-return.test.ts:44-47`) only checks that the source contains `router.navigate(`, so it can't catch this.

Not run natively in this pass; it needs a broken save on the ledger.

**Proof:** the real router code, with its React imports stubbed, starting from tab bar → Notifications → editor:

| Call | Resulting stack |
|---|---|
| `navigate` (current) | `(tabs) \| notifications#notif-1 \| ledger-file-editor \| notifications#<new>` |
| `dismissTo` | `(tabs) \| notifications#notif-1` |

**Native steps** (on a disposable ledger that already has one error):
1. Home → bell → tap the error row; the editor opens.
2. Paste a broken line, Save, then tap View errors in the "Save left errors" alert.
3. Tap Back.

You land on the editor instead of Home. It takes three Backs to get home.

## Fix

If a `notifications` route already sits below the editor, use `router.dismissTo("/(app)/notifications")`; otherwise push. Don't use `dismissTo` unconditionally: with no Notifications screen in the stack, it replaces the editor itself.

**Acceptance:**
- A router-state test: after View errors, the stack is `(tabs) | notifications` when entered from Notifications, and `(tabs) | editor | notifications` when entered from Files.
- Replace the source-text assertion in `refresh-on-return.test.ts`.

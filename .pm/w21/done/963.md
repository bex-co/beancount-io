# Latest Updates undercounts a push when one of its listed commits has an empty first line

**Severity:** trivial. **Estimate:** 10 minutes. Owner: backend-v2.

**Root cause (A3).** `activity-content-parser.ts:302-304` drops blank subjects with `.filter(Boolean)`, but computes `remainder` from the unfiltered `shown.length`. `feed-logic.ts`' `pushSummary` then works out `total = listed.length + more`, which comes out one short for each dropped subject.

Not run: this is read from the code only. For example, 5 commits where one of the first three has a blank first line (a message starting with a newline) gives "+2 more", and the row reads "4 Commits".

**Native steps:** a multi-commit `git push` is needed, and the card is below the fold, so it can't be driven here.

## Fix

Compute `remainder` from `lines.length`, or emit the total count in the summary, as w21/716 suggested.

**Acceptance:** a push with 5 commits, one of them with a blank subject, reports a total of 5.

## Dedupe

Related: w21/716 and w21/731. Searched for "pushSummary" and "fitLines".

---

**Resolved 2026-10-24** — the push summary measures its "+N more commit(s)" from the lines it lists (`parsed.totalCount - lines.length`), not from the commits it looked at, so a commit with an empty message, dropped from the list, is counted among the rest and the total reads as the push's (two listed and "+3 more" for five). One feed formatter feeds REST, GraphQL and MCP alike. Case in `activity-content-parser.test.ts` (fails without the change; `backend-cluster/backend-v2`, typecheck and the full suite green). Not run natively.

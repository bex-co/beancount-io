# An entry added after an unclosed quote is reported as saved, but the ledger never reads it

**Severity:** major (silent data loss: "Transaction saved", yet the entry is nowhere in the app). **Estimate:** 30 minutes. Owner: ledger. A3: `new-ledger-errors.ts:33-47` matches errors by message and file, ignoring the line. rustledger's parse error always reads "parse error: unexpected input", so an entry swallowed by an earlier unclosed string looks like no change. `entries.ts:58` and `:376` get no hash back for the new entry (`entry_hashes: []`) and report success anyway.

Production, through the `addEntries` mutation New Transaction sends (`multi-postings-transaction-screen.tsx:687`), on the disposable ledger (restored byte-for-byte after each probe). The agent also ran the real `main` service code (`08cbe6191`) in memory and checked it against Beancount 3.2.

The QA ledger plus `2026-02-01 note Assets:Cash "call bank about` (an unclosed quote, as a half-typed note saved from the file editor would leave). Before: two "parse error: unexpected input" errors. `addEntries` (narration "QA NEWUNCLOSED") returned `success: true`, and the text is in main.bean. Yet `getLedgerJournal` filtered on it returns 0 rows, and the error list still reads "parse error: unexpected input". Under Beancount 3.2 the error set changes visibly (`Invalid token: 'Shop"'` at the new line).

## Fix

Treat an add whose written entries can't be found in the reparsed ledger (no hash) as a failure, and report it. Match parse errors by location too, so a new swallowed region counts as new.

**Acceptance:** this add is refused (or reported as not saved) and the app doesn't say "Transaction saved". Adds to a ledger with an unrelated parse error elsewhere still work. A unit case is added.

# Saving a file with `\r\r\n` line endings drops one CR on every line, so the commit touches the whole file

**Severity:** minor. It changes bytes on lines the user never touched, the same symptom as w21/062. **Estimate:** 20 minutes. Owner: mobile.

**Root cause (A3).** The open and save steps disagree about the extra CR:
- On open, `mobile/src/components/code-editor/editor-text.ts:12` turns `\r\r\n` into `\r` plus a line break, keeping the extra `\r` as a character, as w21/815 intended.
- On save, `mobile/src/common/ledger-file-content.ts:70` (`content.replace(/\r?\n/g, ending)`) treats that `\r` as part of the line ending and drops it.

Not run natively; the file has to be seeded through git or the API. `tsx` proof with real CodeMirror and the app's helpers: `'a\r\nb\r\nc\r\r\n'` saves as `'a\r\nb\r\nc\r\n'`. A 4-line ledger with `\r\r\n` throughout saves as plain CRLF.

**Native steps:** seed a `\r\r\n` file, open it, add one line and Save. The commit stats cover every line instead of +1.

## Fix

Save with `content.replace(/\n/g, ending)`. To keep pasted CRLF text normalized, strip the CR before each line break of pasted text when it's inserted, with a CodeMirror input filter.

**Acceptance:**
- Decode → editor → save round-trips `\r\r\n` and the lone-CR fixtures byte for byte.
- A pasted `"x\r\ny"` saves with the file's own line ending.

## Dedupe

Only the CLI's w5/380 matches, which is a different package. w21/062, w21/252 and w21/815 are related. Searched for "\r\r", "CRCRLF", "double CR" and "withLineEnding".

---

**Resolved 2026-10-24** — `withLineEnding` writes every `\n` as the file's ending and keeps a `\r` before it, as the editor opened it, so a `\r\r\n` file saves byte for byte; pasted CRLF text is normalized at the door by CodeMirror's `clipboardInputFilter` (`pastedText`), so it saves with the file's own ending. Cases in `editor-text.test.ts` (the round trips; the filter pinned in source; `mobile`). Not run natively.

# In a non-dollar ledger, a CAD (or AUD, MXN) merchant's header total reads "$150.00" while its own row reads "−150.00 CAD" (gap in w21/719)

**Severity:** minor. The header shows a different currency from the rows, and "$" reads as USD. **Estimate:** 10 minutes. Owner: mobile. A3: `merchant-detail-screen/selectors/format-merchant-total.ts:46-53` treats a symbol as taken only when the ledger's primary currency or another total shares it. The rows follow `common/currency-util.ts:39` (`labelRowAmount`): only USD gets "$", and every other currency reads by code.

Reproduced natively on the iPhone 17e simulator, English UI, Metro `--clear` at `51bc7dccd`. The disposable QA ledger's `operating_currency` was switched to EUR for the probe, then restored byte-for-byte to `f1a0b83c`. Fixture: `2026-10-05 * "Qa20261020 Maple Diner" "lunch"` posting 150.00 CAD. Drawer ▸ Merchants ▸ search "Maple" ▸ tap the row. The header reads "**$150.00**" above a row reading "**−150.00 CAD**". Under `tsx` (the agent's proof), AUD in a GBP ledger gives "$80.00" against "80.00 AUD".

## Fix

In `formatMerchantAmount`, read any non-USD dollar currency by code when the primary currency isn't a dollar, matching `labelRowAmount`.

**Acceptance:** this header reads "150.00 CAD". A unit case is added.

# In a CAD (or AUD, NZD, MXN, SGD, HKD) ledger, "$" means CAD on Home but USD in transaction rows and detail

**Severity:** minor (an ambiguous money symbol for every non-US dollar ledger). **Estimate:** 15 minutes. Owner: mobile. A3: the transaction row formatter (`transactions-screen/utils/transaction-display-utils.ts:59`) and the detail postings (`transaction-detail-screen/selectors/select-transaction-detail.ts:131`) hardcode `currency === "USD" ? "$…" : "… CODE"`. Meanwhile `formatMoneyWithCurrency` labels CAD, AUD and the others "$" on Home, Accounts, Budget and Reports. w21/535 fixed the collision only in the merchant header; its resolution leaves `getCurrencySymbol` unchanged elsewhere.

Native (iPhone 17e, fresh Metro `--clear` at `4d9abc812`; disposable ledger with its `operating_currency` line swapped for the probe, then restored byte-for-byte; today 2026-10-23): `option "operating_currency" "CAD"` plus a 1,000.00 CAD seed, `2026-10-20 * "QA US Store"` −42.50 **USD**, and `2026-10-21 * "QA Canadian Store"` −42.50 **CAD**. Home ▸ Net Worth reads **"$957.50"** (CAD). Recent Transactions shows "QA Canadian Store −42.50 CAD" and **"QA US Store −$42.50"** (USD). The same "$" means two currencies one card apart. (The fixture also raised an unrelated "Invalid currency CAD … Equity:Opening-Balances" error, because the base ledger restricts that account to USD.)

## Fix

Use one rule. Rows and detail should use the same `formatMoneyWithCurrency` as the headline, and the symbol must not be shared with the operating currency: show "US$" or "USD" for USD in a CAD ledger, and "CA$"/"$" for the operating dollar.

**Acceptance:** in a CAD ledger, a USD row never reads plain "$" while the headline's "$" means CAD. USD ledgers are unchanged. Unit cases are added.

## Dedupe

Extends w21/535 (done; merchant header) and is the converse of w21/058 (done). Searched `.pm/**` for 'currency === "USD"', CAD and "US$".

**Resolved 2026-10-23** — one labelling rule, `labelRowAmount` (`common/currency-util.ts`), now serves the transaction row (`formatAmount`, every branch of `selectTransactionAmount`), the detail hero, each posting and its per-unit cost and price: USD reads "$42.50" unless the ledger's first operating currency is another currency whose symbol is "$" (CAD, AUD, NZD, MXN, SGD, HKD, …), where it reads "42.50 USD". USD ledgers, and ledgers in EUR, JPY or any non-dollar currency, keep "$" for USD; every other currency still reads by code ("42.50 CAD"). The account journal already formats only in the ledger's own currency, so it had no collision. Rows did not switch to the headline's symbol formatter for every currency (EUR rows still read "42.50 EUR"); that wider change was not needed for the acceptance. Tests in `transaction-display-utils.test.ts` and `select-transaction-detail.test.ts` fail without the change; shipped in the commit that closes this note (`mobile`). Not re-run natively.

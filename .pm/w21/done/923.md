# A dirty New Transaction loses its link guard after Open Account is pushed over it

**Severity:** minor to moderate. An external link switches ledgers under the draft without asking, which is the w21/580 symptom again. Done can then write ledger A's draft into ledger B. **Estimate:** 20 minutes. Owner: mobile.

**Root cause (A3).** `mobile/src/common/unsaved-edits-guard.ts:18-25` keeps a single active check:
- `active = check` replaces the earlier screen's check.
- That screen's cleanup then sets `active = null`.

`use-unsaved-changes-guard.ts:31-57` registers again only when `[hasUnsavedChanges, leavingSaved, t]` changes. So after Open Account goes away, the dirty New Transaction underneath has nothing registered. `open-app-link.ts:94`'s `confirmDiscardUnsavedEdits()` then resolves `true` at once and switches `ledgerVar`. Add Budget, which also pushes the account picker, has the same gap.

Not run natively: the trigger is a beancount.io link opened from outside the app, and deep links can't be accepted on this simulator. `tsx` proof: register New Transaction's check (it answers Cancel), register Open Account's check, run Open Account's cleanup, then call `confirmDiscardUnsavedEdits()`. The output is `{ linkProceeds: true, newTransactionAsked: 0 }`.

**Native steps:**
1. Open New Transaction and type an amount.
2. Tap a posting's account, type "Qa Pets", and tap Create.
3. In Open Account, edit the name, then go Back and choose Discard.
4. Open a beancount.io link to another ledger from Notes.

**Expected:** "Discard your changes?" before anything switches. **Actual:** the ledger switches with no prompt.

## Fix

Make the slot a stack:
- Registering pushes a check.
- Cleanup removes that one entry.
- Confirming asks the top entry, or every entry in order.

**Acceptance:** in `use-unsaved-changes-guard.test.ts`, register A, register B, unregister B. Then `confirmDiscardUnsavedEdits` must call A, and A's Cancel must make it resolve false.

## Dedupe

Different from w21/090, w21/580 and w21/905. Searched for "confirmDiscardUnsavedEdits", "registerUnsavedEditsGuard", "single slot", and "unsaved" with "Open Account".

---

**Resolved 2026-10-24** — the unsaved-edits guard is a stack (`common/unsaved-edits-guard.ts`): registering pushes a check, cleanup removes that one entry, and confirming asks every dirty screen, newest first, stopping at the first that says stay. After Open Account is gone, the New Transaction under it is asked before a link switches ledgers; Add Budget with its picker gets the same. Cases in `unsaved-edits-stack.test.ts` (`mobile`). Note: with two dirty screens stacked, the user can see two "Discard changes?" prompts in a row. Not run natively.

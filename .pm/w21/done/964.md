# Account detail still applies a late "load more" page to a different list (w21/116's third screen)

**Severity:** minor. The trigger is rare. **Estimate:** 15 minutes. Owner: mobile.

**Root cause (A3).** `loadMore` in `mobile/src/screens/account-detail-screen/account-detail-screen.tsx` (about `:371-410`) calls `fetchMore` with `offset: items.length`, `account` and `conversion: journalConversion`. Its `updateQuery` has no check that the list is still the one requested, and it calls `setLastJournalPage(page)` from inside `updateQuery`, so a late page leaks the "last page" state as well as the rows. Apollo applies `updateQuery` to the query's current variables when the response arrives (`ObservableQuery.js:411-424`, as w21/116 documents).

w21/116 fixed this on Transactions and Merchant detail by comparing a `listKeyRef` against the key captured at request time. Account detail already builds the equivalent key (`listKey = ledgerId|account|journalConversion`, `:356`) but has no `listKeyRef` and never reads it in `updateQuery`.

Not run natively; only read from the code, so this is a code-path finding, not a reproduction. The interleaving:
1. The user scrolls to the end, so `loadMore` sends the page request with `conversion: "units"`.
2. Before it returns, the account's display flips from one commodity to several (a foreground or pull-to-refresh after the ledger changed elsewhere), so `journalConversion` changes and `useAccountJournal` re-queries.
3. The old page resolves and is merged into the new conversion's list, with its `total` and `lastJournalPage`, so paging can end wrongly.

Native steps are not feasible: they need a slow network plus a unit-mix change mid-request.

## Fix

At the top of `loadMore`, capture `requestedFor` from a `listKeyRef` kept current as on Transactions. In `updateQuery`, `if (listKeyRef.current !== requestedFor) return prev;` before any merge or `setLastJournalPage`.

**Acceptance:** drive `updateQuery` with a changed key and expect `prev` back and no `setLastJournalPage` call, plus a control that appends the page for its own key. Mirror w21/116's harness test in `empty-ledger-actions.test.ts`.

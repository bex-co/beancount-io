# Notifications keeps saying "Ledger is healthy — no errors" after a failed refresh, and Merchants keeps cached rows, neither with a stale-data banner

**Severity:** minor to moderate (a false health claim on the health screen). **Estimate:** 15 minutes. Owner: mobile. A3:
- `notifications-screen.tsx:271-276,389-402` treats cached data plus an error as ready, and has no `StaleDataBanner`.
- `merchants-screen.tsx:230` drops the error whenever cached data exists, also with no banner.

Home, Transactions, Accounts, Reports, account detail and merchant detail all show one.

Not run natively (it needs the device offline). Under `tsx` with the real ApolloClient and a link that fails the second call (the agent's proof): `data={"getLedgerErrors":[]}`, `error="Network request failed"`, state `ready`, so the healthy text renders with no banner.

## Fix

Run `isShowingStaleDataFromQueries` over Notifications' errors and commits queries and Merchants' rollup, and render `StaleDataBanner`. Don't claim "healthy" from stale data.

**Acceptance:** after a failed refresh, both screens show the stale banner, and Notifications doesn't assert health. A unit or source case is added.

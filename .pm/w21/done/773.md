# Include errors other than "file not found" (a glob matching nothing, the same file included twice, an unknown plugin) have no file or line, so they can't be tapped or shown in the editor

**Severity:** minor. **Estimate:** 20 minutes. Owner: ledger (and mobile). A3: `backend-cluster/ledger/src/features/ledger/service/ledger-data-mappers.ts:49-52` sets `source: null`, and only "file not found" is relocated (`url-include-errors.ts:65`). Mobile's editor fallback (`mobile/src/screens/ledger-file-editor-screen/utils.ts:20-37`) matches file names in the message, but a quoted name keeps its quote and never matches.

Production, through `getLedgerErrors` on the disposable ledger (restored byte-for-byte afterwards). `include "qa20261020/*.bean"` at the top of `main.bean` gives "include pattern "qa20261020/*.bean" does not match any files" with **filename null, line null**. In the agent's run, Notifications shows it with no location and no open icon, tapping does nothing (`canFix = !!err.filename`), and `main.bean`'s banner is empty. "Duplicate filename parsed" and the E8005 unknown-plugin error ("Python plugin … requires the python-plugins feature") behave the same way.

## Fix

Locate these errors at their `include` / `plugin` directive (the engine knows the file and line it parsed), and strip quotes in the editor's name-matching fallback.

**Acceptance:** each fixture's row shows `main.bean:1` and opens the editor there, and `main.bean`'s banner lists it. Unit cases are added.

## Dedupe

Not addressed by w21/189 (done; it named E8005 as out of scope). Siblings of w21/309, w21/534 and w21/740 (other unlocated errors). Searched `.pm/**` for "does not match any files", "Duplicate filename" and E8005.

---

**Resolved 2026-10-23**. The ledger now places these errors itself, through a new `locateIncludeAndPluginErrors` in `backend-cluster/ledger/src/foundation/rustledger/url-include-errors.ts`, run by the engine after w21/772's include relocation:
- A glob include matching nothing goes to its `include` line.
- "Duplicate filename parsed" goes to the second `include` of that file, with include lines read only in the files the entry point loads.
- E8005's unknown Python plugin goes to its `plugin` line in the entry point.

Each fixture now reads `main.beancount:1`, or `:2` for the duplicate, so its row opens the editor there and the file's banner lists it.

On mobile, the editor's name-matching fallback (`ledger-file-editor-screen/utils.ts`) strips a leading quote or bracket, so an unlocated message that quotes its file ("parsed: \"sub.beancount\"") now matches that file.

Unit cases are in the ledger's `url-include-errors.test.ts` and mobile's `file-errors-name-end.test.ts`, and the live engine cases are in `scripts/verify-rustledger.ts`; at the previous HEAD the live cases get `null:null`. Needs a ledger-service deploy for the server half. Not run natively. Shipped in the commit that moves this note.

# Edit Transaction calls an indented date line "an empty entry" and points the user at Delete

**Severity:** minor. The message is false, and its advice would delete the transaction. **Estimate:** 15 minutes. Owner: ledger, plus mobile. A3: `entry-tokens.ts:201-256` (`topLevelLines`) skips a header that starts with whitespace, so the draft "holds no entry", and `mobile/src/common/ledger-refusal.ts:202` maps that to `editTransactionEmpty`.

Reproduced natively with w21/813's build and fixture; the save was refused, so nothing was written. Pencil ▸ tap before `2026` on line 1 ▸ paste a single space ▸ Save. The banner reads **"An empty entry can't be saved. To remove the transaction, use Delete on its detail screen."** while the editor still shows the whole entry. Per the agent's proof, a leading tab or 4-space-indented pasted text gives the same banner.

## Fix

When an indented dated line exists, have the ledger say that the date must start the line, and map that to `ledgerEntryIndent`. Keep `editTransactionEmpty` for a draft that is truly empty or all comments.

**Acceptance:** this edit reads an indentation message, and an emptied draft keeps the current one. Unit cases are added.

**Resolved 2026-10-23** — The ledger now names an indented date line. `assertSingleEntryText` (`backend-cluster/ledger/src/features/ledger/utils/entry-tokens.ts`) finds no top-level directive in that draft. When an indented line starts with a date, it now refuses with "newContent's date line is indented; a dated directive starts at column zero: …" instead of "holds no entry". REST, GraphQL and MCP share that check. On the app, `ledger-refusal.ts` maps the new wording to `ledgerEntryDateIndented`, a new string in all 13 locales: "The date must start its line: remove the space before it." A draft that is empty or only comments keeps `editTransactionEmpty`.

I added `ledgerEntryDateIndented` instead of reusing `ledgerEntryIndent` ("Indent postings under the date line."), whose words describe the opposite mistake.

Unit cases cover a leading space, a tab, and 4-space-indented pasted text in the ledger's `entry-tokens.test.ts` (which fail at the previous HEAD), plus the mapping in mobile's `ledger-refusal.test.ts`. Ledger lint, typecheck and build are green, as are the mobile gates. The ledger test run had one failure, the known intermittent `file-request-limit` ECONNRESET, which passed on rerun. Needs a ledger-service deploy. Not checked natively. Shipped in the commit that moves this note.

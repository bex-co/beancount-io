# On a ledger with no plugins, a padding entry opens to "This transaction was changed or removed"; the same entry opens fine once any plugin is declared

**Severity:** moderate. Every padding row on a plugin-free ledger is a dead end. **Estimate:** 20 minutes. Owner: ledger. A3, traced on `main` (not a stale deploy):
- `backend-cluster/ledger/src/foundation/rustledger/engine.ts:697-699` records each directive's source ID only `if (applyTs || sourceDetails !== undefined)`, which is true only when a `fava.plugins.*` plugin (or another trigger such as a `document` line) is present.
- Without that, `mergePaddingTransactions` (`:269-273`) has no pad source ID to copy onto the padding entry.
- `ledger-journal-service.ts:762-768` then falls back to the padding entry's own hash, finds no source text, and returns NOT_FOUND (`entryNotResolvableError`, line 122).
- The mobile detail shows "changed or removed" when a cached successful read set `sourced` (w21/745's rule).

In-process proof on `main` (`getContext` for the padding ID `f1d845386df9ac78ca4e50f1a891a0db`): with no plugin, NotFoundError. With no plugin but a `document` line, ok, `generated_from 35552d0e…` and the pad slice. With the plugin, the same.

Reproduced natively on the iPhone 17e simulator, English UI, Metro `--clear` at `1d3fd1a10`, on the disposable QA ledger, which has no `plugin` lines and was restored byte-for-byte to `f1a0b83c`. Fixture: `2026-10-20 open Assets:Qa20261020Cash USD`, `… open Equity:Qa20261020Opening USD`, `2026-10-21 pad Assets:Qa20261020Cash Equity:Qa20261020Opening` and `2026-10-22 balance Assets:Qa20261020Cash 500.00 USD`. Transactions lists "(Padding inserted for B… · Pad · +$500.00)". Tapping it, three times, shows **"This transaction was changed or removed. Go back to see the current list."** FARMERS MARKET on the same list opens normally. Adding only `plugin "fava.plugins.amortize_over"` and relaunching makes the same padding row open, showing its +$500.00 detail and the padding notice.

## Fix

Record source IDs whenever padding is merged (always run `seedDirectiveSourceIds`, a cheap pass). Alternatively, in `mergePaddingTransactions`, give the padding entry the pad's own ID from `buildEntryIdMap` when none is recorded. Optionally, on mobile, don't treat a NOT_FOUND that follows only a cached read of a flag-P entry as "gone".

**Acceptance:** with this fixture and no plugins, the padding row opens its detail. A unit or engine case is added.

## Dedupe

Not w21/841 (wording, done) or w21/508 and 660 (plugin copies). Searched `.pm/**` for padding together with "changed or removed".

**Resolved 2026-10-24** — source IDs are now recorded whenever the ledger has padding (`tracksSourceIds`: a plugin, a document line, or padding), so a padding entry takes its pad's ID on a ledger with no plugins too and its detail resolves (`generated_from` set) instead of NOT_FOUND. Tests in `engine-padding-source.test.ts` (stubbed engine; the first fails without the change), shipped in the commit that closes this note (`backend-cluster/ledger`). Needs a ledger deploy to reach production.

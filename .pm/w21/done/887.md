# In right-to-left layouts (Persian), Home's tab-strip fade is inverted once the strip has scrolled

**Severity:** minor (RTL only). **Estimate:** 15 minutes. Owner: mobile. A3: `segmented-pages/index.tsx:226` and `tab-strip-overflow.ts:17` treat `contentOffset.x` as the distance from the strip's start. In React Native 0.86 on iOS, an RTL ScrollView reports `x = contentWidth − containerWidth − nativeX` (`RCTScrollViewComponentView.mm` ≈594), which is largest at the visual start.

Not run natively (it needs Persian, an RTL restart, and an overflowing strip). Under `tsx` (the agent's proof): in RTL at the start after a scroll event, with Liabilities hidden, the fade is false; scrolled fully to the end, with Liabilities shown, the fade is true.

## Fix

When `I18nManager.isRTL`, compute the remaining scroll as `contentWidth − viewportWidth − x`. Add a unit case.

**Acceptance:** in RTL, the fade shows only while the last tab is off-screen.

## Dedupe

Not w4/064, 029 or 062, nor w2/039. Searched `.pm/**` for fade together with rtl and Persian.

---

**Resolved 2026-10-24** — closed by triage, fixed in `69165438a` (shipped with w21/886): `tabStripHasMoreAfter` takes `rtl` and, for an RTL strip, reads the offset as the distance still to scroll (largest at the visual start), so the fade shows while a tab is hidden and goes once the end is reached; the strip passes `I18nManager.isRTL`. Tests: `tab-strip-overflow.test.ts` ("in a right-to-left strip") (`mobile`). Not run natively (needs Persian and an RTL restart).

# Add Budget keeps the operating currency after you pick an account that spends only in another currency, so a yen budget is saved as USD

**Severity:** moderate. The wrong currency is written silently, and the budget can never measure anything. **Estimate:** 30 minutes. Owner: mobile.

**Root cause (A3).** The default currency ignores the picked account: `add-budget-screen.tsx:250` with `defaultBudgetCurrency` (`currency-options.ts:29`). w21/395's resolution names this as a deviation, but it was never filed.

Not run natively in this pass. `tsx` proof, on a USD ledger that also knows JPY:
- The default currency is `USD`.
- `buildBudgetEntry` for `Expenses:Travel:Japan` with "150000" writes `{"number":"150000","currency":"USD"}`.
- With ¥120,000 spent, the card reads "Budget $111,290.32 · Actual $0.00 · Not in total ¥120,000", with no status.

**Native steps:**
1. Use a disposable ledger with `open Expenses:QaJapan JPY` and one JPY expense.
2. Budget → + → pick QaJapan → type 150000.

The Currency row still shows USD.

## Fix

When an account is picked and the currency hasn't been chosen by hand, default to the account's only currency. `getLedgerAccountDirectives` already returns `balance`: add it to `ledgerAccountCloseDates.graphql` and use its single currency. No backend change is needed.

**Acceptance:**
- Picking an account that holds only JPY sets the currency to JPY.
- A currency chosen by hand isn't overwritten.
- Multi-currency and empty accounts keep the current default.

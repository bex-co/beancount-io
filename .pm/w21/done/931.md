# The Cash flow chart's VoiceOver label reads float leftovers ("Income -$0.0000000000000018") while the card shows $0

**Severity:** low. It affects VoiceOver only, but the number is plainly wrong. **Estimate:** 15 minutes. Owner: mobile.

This is the third copy of the bug fixed in w21/597 (Reports bar chart) and w21/821 (Budget). The Cash flow (Sankey) chart was missed.

**Root cause (A3).**
- `treeTotal` (`mobile/src/screens/reports-screen/selectors/sankey-data.ts:350`) adds up the top-level nodes as raw floats.
- `:468` stores that sum as `totalIncome` and `totalExpenses`.
- `cashFlowChartSummary` (`:665-668`) formats it with no `roundMoney`.

The card's own total cleans the same sum with `withoutResidue` (`select-ranged-account-tree.ts:245`).

Not run natively in this pass. `tsx` proof (the real selector feeding the real transform), with one 1M point holding `Income:Salary -10.10`, `Income:Bonus -20.20`, `Income:Clawback 30.30` and `Expenses:Food 50.00`:
- The card total is `0`.
- The label reads `"Cash flow from income to expenses. Income -$0.0000000000000018, expenses $50, from savings $50."`
- Expenses that net to zero the same way read `"expenses -$0.0000000000000036"`.

**Native steps:** add that fixture to a disposable ledger, open Reports ▸ 1M, and read the Cash flow card's `accessibilityLabel`.

## Fix

Build `totalIncome` and `totalExpenses` with `withoutResidue` or `roundMoney(…, currency)`, or pass in the selector's existing `total`. Round `savings` the same way.

**Acceptance:** the fixture reads "Income $0". A unit case is added to the sankey-data tests.

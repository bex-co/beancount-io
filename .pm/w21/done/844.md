# A non-included .bean file elsewhere in the repo brings back w21/134's "+100 → 500" running balance

**Severity:** moderate. **Estimate:** 15 minutes. Owner: ledger. A3: the same `sourceLines` (`entry-sort-order.ts:39`) scans every `.bean` file in the FileMap, not only files the entry point loads. A stray `old/backup.bean` with a same-date transaction breaks the line count for that key, so the engine's grouped order comes back.

Proven on `main` (`053f4eb84`) against Beancount 3.2.3 (the agent's run). w21/134's fixture (Salary +100, pad, `balance 500`) reads correctly on its own. Adding a non-included `old/backup.bean` with `2024-08-05 * "old copy"` gives: Pad → {}, Padding +400 → 400, **Salary +100 → 500**. Beancount gives Salary → 100, then Padding → 500. In the app, account detail would show impossible running balances again.

## Fix

Collect source lines only from files the entry point reaches (`includeTraversalOrder` / `loadedFiles`).

**Acceptance:** this fixture with the stray file orders as Beancount does. A unit case is added.

## Dedupe

Variant of w21/134 and w21/324 (done). Related to w21/843 (same function). Searched `.pm/**` for entry-sort-order and "not included".

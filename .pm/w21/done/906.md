# After an Edit that changes the entry's ID, the detail screen paints "changed or removed" for a frame and reloads the whole ledger a second time

**Severity:** minor. The flash is about one painted frame, but every such edit costs a redundant full ledger refetch. **Estimate:** 30 minutes. Owner: mobile. A3: `mobile/src/screens/transaction-detail-screen/transaction-detail-screen.tsx:439` computes `entryReplaced` during render, before the `:429` effect (w21/692) adopts the saved checksum.

Not run natively; the frame may be too short to capture. Code path:

1. Edit's `dismissTo` hands the detail the new entry ID without remounting it.
2. When the new read arrives, `isShownEntryReplaced(pinnedSha, readSha, loading)` compares the old pinned checksum with the new read checksum and returns true.
3. That frame paints the "removed" screen (`:640`), and `:581-582` fires an extra `invalidateLedgerData(client, "entries")`.
4. Only after the paint does the effect adopt the new checksum.

The "unchanged" exit (its network-only context read at `edit-transaction-screen.tsx:546`) takes the same path off-screen, so it gets only the extra refetch.

## Fix

Work out the shown checksum during render, with `nextShownChecksum(pinned, read, { adoptNext: isSavedChecksum(read) })`, before calling `isShownEntryReplaced`. Keep the effect only to store it.

**Acceptance:** a unit case renders the detail with a saved checksum that differs from the pinned one and asserts no "removed" frame and no extra invalidation.

## Dedupe

A residue of w21/692, w21/672 and w21/694, which cover the pinning logic but not this render-order gap. Searched for "isShownEntryReplaced" and "transactionDetailRemoved".

---

**Resolved 2026-10-24** — the detail screen works out the shown checksum while rendering (`shownSha`, adopting the saved one) and compares that with the read, so an Edit that changes the entry ID no longer paints "changed or removed" for a frame or fires the extra `invalidateLedgerData`; the effect only stores the pin, and writes carry `shownSha`. Cases in `select-shown-checksum.test.ts` (the composition and a source pin; `mobile`). Deviation: no rendered test of the screen. Not run natively.

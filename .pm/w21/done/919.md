# Recent Transactions flashes the first-run "No transactions yet" and Add Transaction while it checks for upcoming entries, and keeps that text if the check fails

**Severity:** low. **Estimate:** 20 minutes. Owner: mobile.

This is a gap in w21/573.

**Root cause (A3).** In `recent-transactions-card.tsx:137-159`, `upcomingOnly` needs `newestData`. `selectRecentCardState` (`mobile/src/screens/home-screen/selectors/recent-window.ts:74-91`) never sees that newest-entry read. So when there are no rows up to today, the card counts as "ready" and renders `recentTransactionsEmpty` plus the call to action until the read lands. If the read fails, that text stays.

Not run natively in this pass. `tsx` proof: a page holding only an Oct 30 entry, with today Oct 23, gives `shown: 0, state: 'ready', upcomingOnly: false`.

**Native steps:** on a ledger whose transactions are all after today, watch Home on a cold load. The first-run text and button flash, then the upcoming message replaces them. This is easiest to see on a slow network.

## Fix

Pass the newest read into `selectRecentCardState`. Keep the skeleton while it is pending, and show the failure tile if it fails.

**Acceptance:**
- A ledger with only future transactions never shows the first-run text or button.
- A ledger with no transactions at all still does.

# Add Budget's one-currency default (w21/946) does nothing for Expenses accounts, which are the accounts people budget

**Severity:** moderate. The fix fails its own scenario: the original yen example was an Expenses account. **Estimate:** 45 minutes. Owner: mobile and ledger. This is a regression of w21/946 (`1cf007334`).

**Root cause (A3).**
- `closeDatesOf` and `accountOnlyCurrency` (`mobile/src/common/account-close-dates.ts`) read each account's currencies from the `balance` field of `getLedgerAccountDirectives`.
- The ledger service fills that field only for Assets and Liabilities: `DEFAULT_BALANCE_ROOTS = ["Assets", "Liabilities"]` (`backend-cluster/ledger/src/features/ledger/utils/account-entries.ts:50`), applied in `accountBalances` (`:101-110`).
- backend-v2 (`ledger-account-service.ts`, about `:149`) builds `balance` from that same read.

Not run natively in this pass. `tsx` proof (the agent's, with the real `closeDatesOf` and `accountOnlyCurrency`): an Expenses account comes back with no balance, `Expenses:Travel:Japan` gives `undefined`, and the budget currency stays on USD. An Assets yen account does give `JPY`, but nobody budgets an asset account.

Side effect: an Assets account holding one commodity (for example `10 AAPL`) now pre-selects `AAPL` as the budget currency.

## Fix

Read each account's currencies another way: a BQL or trial-balance read for Expenses and Income, or the `open` directive's currency list. Alternatively, expose balances for those roots on the server, with the matching REST and MCP change under the parity rule.

**Acceptance:**
- A fixture shaped like the real server response, where Expenses accounts have `balance: null`, still returns `JPY` for `open Expenses:QaJapan JPY` with one yen posting. The current unit tests feed `balance` for every account.
- An Assets commodity account does not pre-select a stock ticker as the budget currency.

## Dedupe

Only the original item, done w21/946, matches. Searched for "accountOnlyCurrency", "account's only currency" and "Assets and Liabilities".

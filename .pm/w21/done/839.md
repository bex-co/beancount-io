# Pull-to-refresh on Accounts, Transactions, Reports and Files skips the ledger errors behind the bell badge, and Accounts skips close dates (w21/138 fixed Home only)

**Severity:** minor. **Estimate:** 15 minutes. Owner: mobile. A3: the pull handlers on Accounts (`accounts-screen.tsx:149-163`), Transactions (`transactions-screen.tsx:274-277`), Reports (`reports-screen.tsx:145-158`) and Files (`ledger-file-browser-screen/index.tsx:463`) never refetch ledger errors, which the bell in every tab header counts. Accounts' pull also skips the close-date query (`useAccountCloseDatesState`, line 112). An account closed and emptied elsewhere stays in the tree after a pull, because `account-close-dates.ts:158-168` filters with the old dates.

Not run natively (a pull needs a drag). This is the agent's code-path trace: add an unbalanced entry through the API and pull Accounts, and the bell shows no badge. Add a `close` for an emptied account and pull, and the account stays listed. Backgrounding the app does fix both.

## Fix

Add the errors refetch to each tab's pull handler, or have the bell follow one shared refresh signal. Add the close-date refetch to Accounts.

**Acceptance:** after a pull on any of these tabs, the bell reflects new errors, and Accounts hides a newly closed, empty account. Source cases are added.

# A discovered statement dated before its account opened raises no error (w21/738 variant)

**Severity:** trivial. **Estimate:** 15 minutes. Owner: ledger. A3: `engine.ts:692` merges discovered documents after validation has already run. With a TS-ported fava plugin declared instead, the result is an unlocated E1001 "unknown account".

Proven with the real engine under ts-node (as `yarn verify:rustledger` runs it) against Beancount 3.2.3 `bean-check`, also at the commit before the fix (the agent's run). Not on production: the ledger service hasn't been redeployed with the fix. `option "documents" "documents"`; `2026-03-01 open Assets:Qa20261020Docs`; file `documents/Assets/Qa20261020Docs/2026-02-01.statement.pdf`. bean-check reports "Invalid reference to inactive account 'Assets:Qa20261020Docs'"; the engine reports 0 errors, and `getLedgerAccountJournal` still lists the document.

## Fix

Merge discovered documents before validation (or validate them separately with the same rules), and give the error the document's file path.

**Acceptance:** this fixture matches bean-check with a usable location. A unit case is added.

# New Transaction and its account picker treat a failed first metadata read as an empty ledger: no accounts, "$" on a EUR ledger, "This ledger has no accounts yet" with an Open Account row

**Severity:** minor. **Estimate:** 20 minutes. Owner: mobile. A3:
- `multi-postings-transaction-screen.tsx:489-523` never reads `error` from `useLedgerMeta`. On failure the skeleton ends (`:825`), both posting rows stay without accounts, and the currency falls back to `ledgerPrimaryCurrency([], [])` = "USD". There is no error and no Retry.
- `account-picker-screen.tsx:291,723` ignores the read-context error. It shows "This ledger has no accounts yet." and, when write access was read fine, an "Open Account" row.

Not run natively. Under `tsx` (the agent's proof): assets `[]`, empty-text key `accountPickerNoAccounts`, `showCreateAccountRow(...) = true`, currency `USD`.

## Fix

Add a failure state with Retry to both, and keep Done disabled until metadata has loaded, as Add Budget does.

**Acceptance:** a failed metadata read shows an error with Retry, not an empty ledger. Unit cases are added.

## Dedupe

Not w21/630 (Open Account), 262, 406, 110 or 643, nor 228 (blocked). Searched `.pm/**` for useLedgerMeta together with error.

# Cmd-S on a hardware keyboard saves an unchanged file, sending a write the disabled Save button never would

**Severity:** low. It needs a hardware keyboard: iPad (`supportsTablet: true`) or Bluetooth. **Estimate:** 15 minutes. Owner: mobile.

**Root cause (A3).**
- The `Mod-s` keybinding (`mobile/src/components/code-editor/code-editor.tsx:250`) calls `requestSaveRef`, which only checks read-only (`:371-373`).
- `handleSave` (`ledger-file-editor-screen/index.tsx:881-887`) has no unsaved-changes check either, so a clean buffer goes to `updateLedgerFile` with the message `` `edit ${path}` `` (`:911`).
- On the server, the file path goes straight to Gitea's contents PUT (`backend-cluster/ledger/src/api/files.ts:160-179`). Unlike the entry path (`commit-ledger-files.ts:210`), it never skips identical content.
- Edit Transaction shares this editor, and its `handleSave` (`edit-transaction-screen.tsx:385`) has no such check either.

Not confirmed whether Gitea writes an empty commit or refuses. Either result is unasked for: a noise row in Recent changes, or a save error for something that changed nothing.

Not run natively: in the simulator, Cmd-S is the simulator's own screenshot-save shortcut. **Native steps** on an iPad with a keyboard: open `main.bean` and press Cmd-S without editing.

## Fix

- In `Mod-s`, do nothing when `view.state.doc.eq(savedDocumentRef.current)`.
- Make `handleSave` do nothing when there are no unsaved changes, except for an Overwrite.

**Acceptance:**
- Mod-s on a clean buffer sends no mutation.
- Mod-s after an edit saves once.

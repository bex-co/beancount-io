# Switching Browse-ledgers tabs briefly shows the previous tab's rows

**Severity:** low. **Estimate:** 20 minutes. Owner: mobile.

**Root cause (A3).** `mobile/src/screens/ledger-selection/index.tsx` (about `:157-168`): `store.load(tab, …)` runs in an effect after paint, so for one frame the new tab renders the old tab's `state.items` (filtered by `filterLedgers` on the Your/Starred tabs). Code-read finding, not run natively.

## Fix

Clear or key the items by tab at switch time (or load in the tab-press handler) so the skeleton shows immediately.

**Acceptance:** a render test that the first render after a tab change contains no rows from the previous tab.

## Dedupe

Searched `.pm/**` for "tab" with "ledger-selection": nothing found.

**Resolved 2026-10-24** — The store exposes `loadedTab`, declared synchronously when a load starts; the screen blanks rows while it mismatches the selected tab and shows the skeleton until the new rows land.

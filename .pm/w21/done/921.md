# A payee's usual accounts don't fill in when 50 newer entries merely contain its name ("Uber" hidden behind "Uber Eats")

**Severity:** minor to moderate. The fill silently does nothing for short payee names that appear inside other payees or narrations (Uber, Apple, Shell, Amazon). **Estimate:** 30 minutes. Owner: mobile.

**Root cause (A3).**
- `mobile/src/screens/add-transaction-screen/hooks/two-posting-query.ts:10` sends `{ filter: toPlainSearchFilter(payee), limit: 50 }`.
- The engine's quoted-string filter is a case-insensitive substring match over narration and payee (`backend-cluster/ledger/src/foundation/rustledger/directive-filter.ts:651-663`). It returns the newest 50 matches and isn't limited to transactions.
- The client then keeps only exact `merchantKey` matches (`deriveTwoPostingSuggestions`). If the 50 newest matches belong to other payees, the right payee's entries never arrive.

Not run natively; it needs 50 or more fixture entries. `tsx` proof, using a simulated journal filtered the way the engine filters (newest first: 50 "Uber Eats" entries, Card → Delivery, then 10 "Uber" entries, Checking → Rideshare):
- With `limit 50`, from/to are `null`, so nothing fills.
- With `limit 1000`, it fills `Assets:Checking` / `Expenses:Transport:Rideshare`.

**Native steps:**
1. On a disposable ledger, add 50 newer "Uber Eats" entries and some older "Uber" ones.
2. New Transaction → Payee → "Uber".

The postings stay on the defaults.

## Fix

- Match the payee field only, e.g. `payee:"<escaped>"`; the attribute exists around `directive-filter.ts:700`.
- Add `directiveTypes: ["Transaction"]`.
- Either page until enough exact matches arrive, or raise the limit.
- Keep the client-side `merchantKey` re-filter.

**Acceptance:** with the fixture above, picking "Uber" fills Checking → Rideshare. A unit test covers the query variables.

**Resolved 2026-10-24** — the usual-accounts query matches the payee field whole, over transactions only (`toExactPayeeFilter` in `plain-search-filter.ts`: `payee:"^\\s*Uber\\s*$"` spelled with the search's own quote and whitespace tolerance, plus `directiveTypes: [Transaction]`), so 50 newer "Uber Eats" entries no longer hide "Uber"; a pattern too long to send falls back to the plain filter, and the client-side `merchantKey` re-filter stays. Cases in `two-posting-query.test.ts` (`mobile`). Deviation: the limit stays 50 and the read does not page. Not run natively.

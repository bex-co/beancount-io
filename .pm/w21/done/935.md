# Every offline delete says "The server didn't confirm the save", even when, as with Budget, no delete was sent

**Severity:** minor to moderate. The wording is wrong in every locale: it says "save" for a delete. For a budget entry it is also false, because it suggests the entry might already be gone. **Estimate:** 30 minutes. Owner: mobile.

**Root cause (A3).**
- `mobile/src/common/ledger-refusal.ts:333-339` maps every transport failure except `OAuth refresh failed` (`PRE_SEND_FAILURE`, `:271`) to `ledgerWriteUnconfirmed`.
- `use-delete-budget-entry.ts:39-47` first does a `network-only` entry-context read to get the checksum. When that read fails offline, `:74` reports it as a write failure.
- File delete takes the same path. Transaction delete shows the message twice, as a toast and as an alert.

Not run natively; the simulator can't take one app offline. `tsx` proof, with an offline link: the budget path sent only `['GetLedgerEntryContext']`, and the message came back "The server didn't confirm the save…". File delete gave the same message.

**Native steps:** in airplane mode, go to Budget → open a history row → Delete → Delete.

## Fix

- A failed pre-read means nothing was deleted, so show offline wording, or a delete-specific "Couldn't delete. Nothing changed."
- Add a delete variant of the unconfirmed message ("The server didn't confirm the delete…").

**Acceptance:**
- A failed pre-read shows the not-sent wording.
- A failed delete never says "save", in any locale.

## Dedupe

w21/327, w21/351, w21/584, w21/858 and blocked w21/453 cover writes, not deletes or the pre-read. Searched for "ledgerWriteUnconfirmed" and "confirm the save".

# New Transaction shows a green "✓ $0.00" and no format error while a later row holds an unreadable amount, whenever an earlier row has no account (gap in w21/031)

**Severity:** minor. The form looks balanced while it holds an amount it can't read; the error only appears after the account is fixed. **Estimate:** 15 minutes. Owner: mobile. A3: `multi-postings-transaction-screen.tsx:653` sets `amountUnreadable` only when `validationError === "invalidAmount"`. `validatePostings` (`postings-utils.ts:458-466`) stops at the first problem, so a `missingAccount` (`:460`) or `zeroAmount` on an earlier row hides it.

Not run natively (it needs a third row with no account plus multi-dot typing). Under `tsx` (the agent's proof): row 1 "10", Add posting, and row 3 with no account and "1.2.3" give `validation missingAccount`, `remainder 0.00`, `balanced true`, `amountUnreadable false`, while row 3 is unparsed (drawn red). Expected native result: Remainder "✓ $0.00" in green, no "Use digits…" line, and Done says "All postings need an account".

## Fix

Derive `amountUnreadable` from `postings.some(hasUnparsedAmount)`, independently of which validation error comes first, and show the neutral "—" and the inline error from that.

**Acceptance:** with this state, Remainder shows "—" and the format error shows. A unit case is added.

# Saved narration and payee lose left-to-right and right-to-left marks and soft hyphens (w21/965), which may change right-to-left text a user typed on purpose

**Severity:** low, and a judgment call for the owner. **Estimate:** 15 minutes. Owner: mobile. This is a side effect of w21/965 (`1544f7be8`).

**Root cause (A3).** `mobile/src/common/clean-free-text.ts:8` strips U+200E/200F (LRM/RLM) and U+00AD (soft hyphen) from everything saved through `TextInputScreen.commit` (`components/text-input-screen/index.tsx:172`), which only the narration and payee input screens use. A user who typed an RLM so trailing punctuation sits in the right place in Arabic or Hebrew text loses it silently.

Not run natively in this pass. `tsx` proof (the agent's): `cleanFreeText("فاتورة ‏(INV-12)‏")` gives `فاتورة (INV-12)`, 17 code points down to 15. ZWNJ and ZWJ, emoji ZWJ sequences and U+FE0F are intact (`👨‍👩‍👧 ❤️` and `می‌خواهم` survive).

## Fix

Strip only U+200B, U+2060 to U+2064, U+FEFF and the bidi embeddings from the **saved** text, and keep LRM, RLM and ALM (U+200E, U+200F, U+061C) there. Keep removing all of them in `merchantKey` and the search fold, so merchants still merge.

**Acceptance:** `cleanFreeText` on text with deliberate RLM marks keeps them for saving, while `merchantKey` is the same with or without them.

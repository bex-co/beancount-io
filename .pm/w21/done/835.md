# New Transaction's payee suggestions miss Persian/Arabic letter variants, list both spellings, and the other spelling fills no accounts (mobile half of w21/785)

**Severity:** moderate for Persian and Arabic users. **Estimate:** 20 minutes. Owner: mobile. A3: `mobile/src/components/text-input-screen/match-suggestions.ts:9` (`fold`) and the dedupe key in `matchSuggestions` handle only NFC, case, the Turkish İ and spaces. `mobile/src/common/merchant-key.ts:13` (`merchantKey`) has the same gap, so `deriveTwoPostingSuggestions` drops the other spelling's history. w21/785 added `foldArabicScript` on the server only.

Not run natively. Under `tsx` (the agent's proof):
- `matchSuggestions(["Qa20261020 كافي شاپ"], "کافی", 30)` → `[]`.
- An empty query lists both spellings as two rows.
- Payee `Qa20261020 کافی شاپ` against a `Qa20261020 كافي شاپ` Visa→Coffee entry gives `autoFill: null` on both sides.

## Fix

Move `foldArabicScript`'s folds into one import-free helper: ي/ى→ی, ك→ک, ة→ه, أإآ→ا, digits, harakat, and ZWNJ→space. Apply it in `fold`, the dedupe key and `merchantKey`.

**Acceptance:** `کافی` suggests the `كافي` payee, the two spellings show as one row, and picking either fills Visa/Coffee. Unit cases are added.

# The Accounts tab breaks a long account name mid-word at the largest supported text size ("Bank:Mercury:Checkin" / "g")

**Severity:** minor (cosmetic; the whole name is still there, but a word is split). **Estimate:** ~45 minutes (two surfaces, one shared helper). Owner: mobile. A2: at AX2 (`accessibility-large`) the Accounts tab renders each row in its stacked layout. `mobile/src/components/account-table/account-table.tsx` (the `stacked ? …` branch, around lines 366–382) renders `<Text style={[styles.stackedName, …]}>{label}</Text>` with no line limit and no break opportunities, so a colon-joined name is one unbroken token and wraps wherever the line ends. The wide branch (around line 404) uses `numberOfLines={1}` with `ellipsizeMode="middle"` and is fine.

iPhone 17e, iOS 27.0, dev build `io.beancount.ios`, `main` at `434d05dc6`, a synthetic example ledger. Judged on a **cold launch**: a live text-size change leaves stale native measurements (`mobile/AGENTS.md`), which clipped other labels that then rendered correctly after a relaunch.

1. `xcrun simctl ui <udid> content_size accessibility-large`.
2. Terminate and relaunch the app, then dismiss the development warning banner.
3. Open the Accounts tab with the Assets group expanded.
4. The leaf `Assets:Bank:Mercury:Checking` reads "Bank:Mercury:Checkin" on one line and "g" on the next. (A screenshot is kept locally and is not committed.)

Not an AX3–AX5-only finding (`.pm/DO_NOT_DO.md`): it reproduces at AX2.

**Second surface, confirmed 2026-10-30 (same cold-launch AX2 setup):** the account detail header breaks the same way. Opening the Checking account from the Accounts tab shows "Assets:Bank:Mercury:Che" on one line and "cking" on the next. `mobile/src/screens/account-detail-screen/account-detail-screen.tsx` (around line 541) renders `<Text style={styles.accountPath}>{isolateAccountPath(account)}</Text>` with no line limit and no break opportunities. A shorter name (`Liabilities:US:Chase:Slate`) fits on one line, so it only shows for names wider than the row. The Notifications screen wraps at word boundaries and is unaffected.

## Fix

In the stacked branch, give the displayed label break opportunities after each `:` (a zero-width space, `​`, inserted into the displayed string only; keep the real name for accessibility labels, search and navigation), so lines break at account-segment boundaries. Alternatively cap the name at two lines with a head or middle ellipsis that keeps the leaf. Either way a word is never split. Do it once, in a shared helper that returns the break-friendly display label, and use it for the Accounts stacked row and the account detail header (`isolateAccountPath` is the natural place to compose it, keeping its bidi isolation).

**Acceptance:** at AX2 on a cold launch, `Assets:Bank:Mercury:Checking` and `Expenses:Food:Groceries` wrap only at a `:` (or end in a head/middle ellipsis that keeps the leaf) in both the Accounts stacked row and the account detail header; the wide layout at default size is unchanged; a unit case covers the helper, including a name with no colon and a name that `isolateAccountPath` already isolates.

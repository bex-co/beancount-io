# The Accounts tab tree builder is quadratic in the number of accounts

**Severity:** moderate, and only for ledgers with thousands of accounts. **Estimate:** 30 minutes. Owner: mobile.

**Root cause (A3).** In `graftZeroAccounts` (`mobile/src/components/account-list/select-account-list.ts`):
- `:491` runs `wanted.includes(node.account)` for every raw node (nodes × accounts).
- `:513` runs `rendered.some((node) => node.account.startsWith(...))` for every wanted account (accounts × nodes).
- `selectTrialBalanceCategories` (`select-trial-balance.ts:95`) passes the full account list to all five categories, and the Accounts screen re-runs it in a `useMemo` (`accounts-screen.tsx:123`) on every refetch, pull-to-refresh and `today` change.

Not run natively; it needs about 5,000 `open` directives. `tsx` proof (Node/V8, the agent's; Hermes is not measured and is typically several times slower), using the real `selectTrialBalanceCategories` with 40 leaves per parent:

| Accounts | With account names | Without |
|---|---|---|
| 520 | 6 ms | 0 ms |
| 1,000 | 19 ms | 0 ms |
| 2,000 | 70 ms | 1 ms |
| 5,000 | 375 ms | 5 ms |
| 10,000 | about 1.7 s | not run |

At 300 accounts it costs about 3 ms, so only very large charts feel it.

## Fix

Build a `Set` of `wanted` once for `survives`, and a `Set` of every ancestor prefix of the rendered nodes once, so the descendant check is a lookup instead of `some(startsWith)`.

**Acceptance:** `selectTrialBalanceCategories` with 5,000 account names finishes in under 50 ms, with output identical to today on the existing `select-account-list` fixtures.

---

**Resolved 2026-10-24** — `graftZeroAccounts` builds its lookups once: a `Set` of the wanted accounts for `survives`, a `Set` of every proper ancestor of a rendered account for the "stands in for it" check, and a path map of the cloned nodes for the graft, replacing `includes`, `some(startsWith)` and a `find` per sibling. Output is unchanged on all existing `select-account-list` and `select-trial-balance` fixtures; with 5,000 accounts it builds in well under 150 ms in the test (it failed that bound on the old code). Cases in `select-trial-balance.test.ts` (`mobile`). Hermes was not measured. Not run natively.

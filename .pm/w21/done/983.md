# A dashboard journal link with a regex account filter now matches nothing (w21/959 regression)

**Severity:** medium. **Estimate:** 20 minutes. Owner: mobile. This is a regression of w21/959 (`09b0ef0b4`).

**Root cause (A3).** `toFilterQuery` (`mobile/src/screens/transactions-screen/filters/select-filter-query.ts:156-166`) escapes and anchors any `filters.account` that contains `:` and starts with a root. `journalLinkFilters` (`mobile/src/common/app-links/journal-link-filters.ts:74-88`) puts the link's `account` parameter into `filters.account` as written. The ledger service's matcher (`makeAccountNameMatcher`, `backend-cluster/ledger/src/foundation/rustledger/directive-filter.ts:316-323`) deliberately reads regex syntax in that value as a Fava regex, for example `^Expenses:(Food|Rent)`.

Not run natively in this pass: links can't be accepted on this simulator. `tsx` proof (the agent's, `toFilterQuery` on `journalLinkFilters` output):
- `Expenses:Food.*` becomes `^Expenses:Food\.\*(:|$)`, which matches no account.
- `Expenses:Food|Expenses:Rent` becomes `^Expenses:Food\|Expenses:Rent(:|$)`, which matches no account.
- `^Expenses:(Food|Rent)` is unchanged, only because the leading `^` fails the root test.

I confirmed the escape-and-anchor branch in the code.

## Fix

Anchor and escape only when the value has no regex syntax (`/[.*+?^${}()|[\]\\]/`), the same split the server uses. Better still, anchor in the filter sheet's picker path rather than inside `toFilterQuery`, so link values pass through untouched.

**Acceptance:** `toFilterQuery` leaves `Expenses:Food.*` and `Expenses:Food|Expenses:Rent` untouched, and still anchors `Expenses:Travel`.

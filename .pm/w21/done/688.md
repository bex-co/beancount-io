# File editor: Enter after a one-line directive (`price`, `open`, `balance`…) indents the next line, so the next directive typed there is a syntax error (w21/338 regression)

**Severity:** minor (the editor produces invalid beancount on ordinary typing). **Estimate:** 15 minutes. Owner: mobile. A3: `mobile/src/components/code-editor/beancount-language.ts:168` returns `unit` whenever the previous line matches `DATED_LINE`, treating every dated line as a transaction header. Before w21/338, CodeMirror copied the line's indentation (0 for a directive). The line-161 check only helps when the dated text is already *after* the cursor, which isn't true while typing.

Not run natively: on iPhone 17e the end of the QA `main.bean` is below the fold and the automation can't scroll. Proven under `tsx` with the real CodeMirror `insertNewlineAndIndent`, the app's indent rule and `detectIndentUnit`:

- After `2026-10-01 price BTC 60000.00 USD`, Enter and the date chip give `"…USD\n  2026-10-23 price BTC 61000.00 USD"`.
- `open` and `balance` lines behave the same way. Control: after an `option` line, the result starts at column 0.
- `bean-check` 3.2.3 on the price result: `syntax error, unexpected DATE, expecting end of file or EOL or KEY`.

On device, saving that gives "Saved, with a new ledger error".

## Fix

Indent after a dated line only when it is a transaction header (a flag or `txn` after the date), not after a one-line directive.

**Acceptance:** Enter after `price`, `open`, `close`, `balance`, `pad`, `note`, `event`, `commodity` and `document` lines lands at column 0. After a transaction header it is still indented (w21/338). Unit cases are added.

## Dedupe

Regression from w21/338 (done). Searched `.pm/**` for beancountIndent, DATED_LINE and "indents the next".

---

**Resolved 2026-10-23** — `beancountIndent` indents the line after a dated line only when it is a transaction header (a flag or `txn` after the date); after `price`, `open`, `close`, `balance`, `pad`, `note`, `event`, `commodity`, `document` or `custom` the next line starts at column 0, so the next typed directive is not a syntax error. Cases in `beancount-language.test.ts` (fail without the change), shipped in the commit that closes this note (`mobile`). Not run natively.

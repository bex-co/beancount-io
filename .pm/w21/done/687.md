# Create Ledger presets open every account restricted to the operating currency, so Portfolio refuses its own first share purchase (hosted sibling of w5/957)

**Severity:** major (a new user's first trade or foreign-currency purchase in a fresh preset ledger is refused). **Estimate:** 30 minutes. Owner: backend-v2. A3: `backend-cluster/backend-v2/src/features/ledger/setup/build-ledger.ts:277-280` (`openLine`) writes `open <account> <operatingCurrency>` for every preset account except the opening-balances equity. That includes `Assets:Holdings`, the account the Portfolio preset exists to hold securities in. The mobile Create Ledger screen sends its preset setup to this hosted builder. w5/957 fixed the same bug only in the CLI builder. It also contradicts ADR021's rule that the operating currency "neither converts amounts nor prohibits other currencies".

Production, read-only: `previewLedgerSetup(setup: {preset: PORTFOLIO, operatingCurrency: "USD"})` (the query Create Ledger's preview sends) returns `open Assets:BrokerCash USD`, `open Assets:Holdings USD`, `open Expenses:Fees USD`, `open Income:Dividends USD`, `open Income:Interest USD`. PERSONAL returns `open Expenses:Food USD`, `open Assets:Cash USD` and so on. In the agent's run, `bean-check` 3.2 on the Portfolio file plus `Assets:Holdings 10 VTI {20.00 USD}` gives "Invalid currency VTI for account 'Assets:Holdings'". On the Personal file, a 12.00 EUR lunch gives "Invalid currency EUR for account 'Expenses:Food'" (and for 'Liabilities:CreditCard'). Not created natively, because the QA rules forbid creating ledgers.

## Fix

Port w5/957: open preset accounts without a currency constraint (or constrain only the accounts whose catalog says so), keeping w23/048's equity rule.

**Acceptance:** previewing Portfolio shows `open Assets:Holdings` with no currency, and the preset's own acceptance scenario (buying shares) passes bean-check. Personal accepts a EUR expense. A unit case covers each preset.

## Dedupe

Hosted sibling of w5/957 (done; CLI). Related to w23/048 (the equity currency). Searched `.pm/**` for "Invalid currency", openLine, Assets:Holdings and previewLedgerSetup.

---

**Resolved 2026-10-23** — the hosted builder opens preset accounts with no currency constraint (`openLine` in `build-ledger.ts`); only an account set up with its own currency is restricted, and the opening-balances equity rule of w23/048 is unchanged. Previewing Portfolio shows `open Assets:Holdings` bare, so the first share purchase no longer fails bean-check, and a euro lunch is accepted in a dollar Personal ledger. Cases in `build-ledger.test.ts` (every Personal and Portfolio account opens bare; an account with its own currency stays restricted), shipped in the commit that closes this note (`backend-cluster/backend-v2`). Needs a backend-v2 deploy to reach production.

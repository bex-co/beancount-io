# File editor: text typed while "Saving…" is up is dropped by a later web-view restart, Overwrite or Recreate

**Severity:** minor (silent loss of keystrokes typed during a save). **Estimate:** 30 minutes. Owner: mobile. A3: when a save succeeds, `ledger-file-editor-screen/index.tsx:909` calls `recoveryRef.current.saved(content)` with the text as it was when Save was tapped. That overwrites the recovery draft, which by then holds newer typing. A web-view restart (`ready()`, `:660`) and Overwrite or Recreate (`rebaseOnSaved`, `:746`/`:815`) then restore the older text. "Copy & Reload" in the File Changed alert copies the save-time `content` too (`:786`). The w21/342 and w21/522 fixes don't cover a save in flight.

Not run natively, because the window is a single network round-trip and the automation's taps take about 4 s each. Proven under `tsx` with the real `createEditorRecovery`, in the screen's call order:

- Draft `"L1\nAAA\nBBB\n"`, where BBB was typed during the save of `"L1\nAAA\n"`.
- `latest()` after the save returns `"L1\nAAA\n"`.
- The web-view restart restores `{"value":"L1\nAAA\n","savedValue":"L1\nAAA\n"}`, so BBB is gone and Save stays enabled over text that is already saved.

After Overwrite, BBB is saved on the server but disappears from the screen, and the next Save deletes it there.

## Fix

On a successful save, record the saved text as the baseline without replacing the latest draft. Rebase operations should use the current draft, and Copy & Reload should copy the current text.

**Acceptance:** text typed during a save survives a web-view restart, Overwrite, Recreate and Copy & Reload. A unit case covers the in-flight order.

## Dedupe

Not covered by w21/342 (a web-view kill with no save in flight) or w21/522 (the baseline after Overwrite). Searched `.pm/**` for recoveryRef, "Saving…" and "typed while".

---

**Resolved 2026-10-23** — a successful save now records only the saved text as the baseline (`saved`), after `saving` marks the sent text as the latest at its start, so keystrokes typed during "Saving…" stay the latest through a web-view restart, Overwrite and Recreate; Overwrite and Recreate rebase on the editor's text read after their save, and Copy & Reload copies the current text. Cases in `editor-recovery.test.ts` (the in-flight order, fails without the change) and the updated source pins in `rebase-after-overwrite.test.ts` and `conflict-options.test.ts`, shipped in the commit that closes this note (`mobile`).

# The code editor treats a lone carriage return as a line break: any save rewrites "Order 12\r34" to two lines, and error "line N" taps land early

**Severity:** major (a silent data change on an unrelated save). **Estimate:** 20 minutes. Owner: mobile. A3: `mobile/src/components/code-editor/code-editor.tsx:417,461`. `EditorState.create` sets no `lineSeparator`, so CodeMirror splits on `\r\n?|\n` and saves with `\n`. Beancount and rustledger keep a lone CR as text. Edit Transaction uses the same editor.

Not run natively: a lone CR has to be seeded through git or the CLI. Under `tsx` (the agent's proof), the engine reads the narration as `"Order 12\r34"` and reports a later error at `main.bean:6`. In the editor, line 6 is the previous entry's posting, and a round trip saves `"Order 12\n34"`. Fixture: `2026-10-20 * "Qa20261020 Shop" "Order 12<CR>34"`, then a 2026-10-22 entry posting to an unopened account.

## Fix

Set `EditorState.lineSeparator` to the file's dominant line ending, so a lone `\r` stays a character, or open files that contain a lone CR read-only with a notice.

**Acceptance:** opening and saving this file with an unrelated edit keeps `\r` in the narration, and the error tap lands on the right line. A unit case is added.

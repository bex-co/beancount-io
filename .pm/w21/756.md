# A `pad` into a child account closed by `close_tree` still raises no error (w21/737 variant)

**Severity:** minor. **Estimate:** 10 minutes. Owner: ledger. A3: `generated-closes.ts:45` checks transactions only. After a close, Beancount allows only balance, document and note entries, so a pad is an error.

Proven with the real engine under ts-node (as `yarn verify:rustledger` runs it) against Beancount 3.2.3 `bean-check`, also at the commit before the fix (the agent's run). Not on production: the ledger service hasn't been redeployed with the fix. w21/737's opens and close, plus `Equity:Qa20261020Opening`, `2024-05-01 pad Assets:Qa20261020Broker:VTI Equity:Qa20261020Opening` and `2024-05-02 balance … 5 USD`. bean-check reports "Invalid reference to inactive account" at the pad's line (twice); the engine reports 0 errors.

## Fix

Apply the generated-close check to pad directives too (all directive types except balance, document and note).

# Edit's refusal line number is off when the draft starts with blank lines

**Severity:** low. The error cites the wrong line. **Estimate:** 15 minutes. Owner: mobile.

**Root cause (A3).** The server drops leading blank lines before validating (`normalizeSliceReplacement`, `backend-cluster/ledger/.../source-slice.ts:792-799`, since w21/813). The client maps the cited line against the raw draft (`mobile/src/common/ledger-refusal.ts:75`, with `lineCount` from `edit-transaction-screen.tsx:470`).
- `headerQuotesUnbalanced` (`ledger-refusal.ts:104`) also reads the draft's first line. That line is blank, so the quote hint never shows either.

Not run natively in this pass. Proof with the real engine on `replaceSliceInFile` output: for an unbalanced draft that starts with `\n\n`, the error cites `main.bean:4`, and `describeLedgerRefusal` says "(line 1)". In the editor, line 1 is blank; the header is on line 3.

**Native steps:**
1. Open a disposable entry ▸ Edit.
2. Paste a draft that starts with two blank lines and has a 6.00 posting against −5.00.
3. Save.

The banner reads "…does not balance… (line 1)".

## Fix

Before building the refusal context, offset the line by the number of leading blank lines, or strip them from the draft as the server does.

**Acceptance:**
- With two leading blank lines, a citation of the entry's first line maps to "line 3".
- The quote hint still fires for an unbalanced header after blank lines.

w21/813 fixed only what is stored, not the line mapping. w21/369 and w21/507 are different. Searched for "leading blank", "tidyRefusalDetail" and "lineCount".

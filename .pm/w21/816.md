# An entry containing a control character (such as ESC from a CSV import) can never be edited: Save shows raw English API text that also blames the user's edit

**Severity:** minor. **Estimate:** 20 minutes. Owner: ledger, plus mobile. A3: `entry-tokens.ts:245` (`CONTROL_CHARACTER`) refuses `\p{Cc}` in `newContent`, even when the character came from the slice the server itself served. The mobile mapping passes the raw text through: "newContent contains the control character U+001B, which the ledger cannot store as text". The character is invisible in the editor, so the user can't remove it there.

Not run natively: it needs a seeded ESC (w3/271 shows CSV imports keep them). Under `tsx` (the agent's proof), the engine parses `"CARD 1234\u001b[0m"` with 0 errors, yet a metadata-only edit of that entry is refused with the text above.

## Fix

Allow control characters already present in the loaded slice, or map the refusal to localized copy that names the location and offers the file-editor workaround.

**Acceptance:** a metadata-only edit of such an entry saves, or the refusal is localized and actionable. A unit case is added.

## Dedupe

Only CLI, dashboard and auth items mention control characters. Searched `.pm/**` for "control character" and CONTROL_CHARACTER.

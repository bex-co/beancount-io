# Opening an account (or posting to a parent) collapses a branch the user had expanded on the Accounts tab, because the folded row's key changes

**Severity:** minor. **Estimate:** 25 minutes. Owner: mobile. A3: expand state is keyed by each row's account (`account-table.tsx:489,533`, `flatten-rows.ts:120-121`). A folded chain is keyed by its deepest account (`select-account-list.ts:245-262`), and a lone top-level level is skipped (`:292-307`). When a write reshapes the tree, a new parent row appears under a key with no saved state and defaults to collapsed. w21/175's reveal opens only the new account's ancestors.

Not run natively: it needs typing a new account name and a pre-expanded branch, which these taps don't drive reliably. Under `tsx` with the real selectors (the agent's proof):
- With `US:Bank` expanded (Checking 1,200, Savings 800) beside `US:Broker` 500, opening `Assets:Qa20261020Cash` leaves only "> Qa20261020US 2500" (collapsed) and "Qa20261020Cash 0".
- With `Broker:Fidelity` expanded, a −5 posting to `Assets:Qa20261020Broker` leaves only "> Qa20261020Broker 495".

## Fix

Have `compressChain` and `skipPassThroughLevels` record the accounts each row absorbed. A row should then read the saved state of any absorbed account, or default to open when its rows were visible before the write.

**Acceptance:** both sequences keep the previously expanded children visible. Unit cases are added.

# A dirty file editor now asks "Discard changes?" twice on a cross-ledger link

**Severity:** moderate. It is a direct side effect of w21/923 making the guard a stack (`2bc31b9b4`). **Estimate:** 10 minutes. Owner: mobile.

**Root cause (A3).** `mobile/src/screens/ledger-file-editor-screen/index.tsx:1007` calls `useUnsavedChangesGuard(hasUnsavedChanges)`, which registers a guard. The same screen registers a second, identical guard with `registerUnsavedEditsGuard` in an effect at `:1013`. The old single slot let the second overwrite the first. Now both stay registered, and `confirmDiscardUnsavedEdits` (`open-app-link.ts:96`) asks each in turn.

Not run natively in this pass: the trigger is an external link opened over a dirty editor. `tsx` proof (the agent's): registering the same ask twice and calling `confirmDiscardUnsavedEdits()` ran it twice (`alerts shown: 2`).

## Fix

Delete the redundant effect at `:1013-1035`, since the hook already registers. Alternatively, have `registerUnsavedEditsGuard` de-duplicate per screen with an owner key.

**Acceptance:** one dirty file editor and a cross-ledger link produce exactly one prompt. A test mounts both registrations and counts the prompts.

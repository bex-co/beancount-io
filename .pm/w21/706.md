# An unused pad makes the account's next pad raise a false "Multiple pad directives" error, and the pad and balance error paths are quadratic

**Severity:** minor (a false error in the common monthly pad-and-balance pattern, plus multi-second loads on large ledgers). **Estimate:** 45 minutes. Owner: ledger. A3: rustledger reports E2004 "Multiple pad directives" for the next pad after an unused one. w21/675's recheck blanks the unused pads and re-validates (`engine.ts:726-737`), but never drops errors that disappear once the unused pads are gone. Separately, `padLocation`/`withoutBlock` re-split every file for each pad (`pad-tolerance.ts:70-77`, `pad-recheck.ts:45`), and `balance-error-dates.ts:29` re-splits the source for each failing balance.

Proven with the real engine under ts-node, with `bean-check` 3.2 as the reference: a 100 USD deposit, then

```
2026-02-01 pad Assets:A Equity:Open
2026-02-02 balance Assets:A  100.00 USD
2026-03-01 pad Assets:A Equity:Open
2026-03-02 balance Assets:A  120.00 USD
```

bean-check reports only "Unused Pad entry" (the first pad). The engine adds E2004 on the second pad. Timing: 2000 unused pads take 6.8 s against 84 ms with no pads, and 4000 take 20 s (with 3999 false E2004s). 4000 failing balances take 6.5 s. Not on production yet (the ledger service hasn't been redeployed).

## Fix

After the recheck, drop E2004 errors that don't recur without the unused pads. Index line offsets once per file for the pad and balance lookups.

**Acceptance:** this fixture reports only "Unused Pad entry". 4000 pads or failing balances load in well under a second. Unit and perf cases are added.

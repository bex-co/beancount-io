# Edit Transaction calls an indented date line "an empty entry" and points the user at Delete

**Severity:** minor. The message is false, and its advice would delete the transaction. **Estimate:** 15 minutes. Owner: ledger, plus mobile. A3: `entry-tokens.ts:201-256` (`topLevelLines`) skips a header that starts with whitespace, so the draft "holds no entry", and `mobile/src/common/ledger-refusal.ts:202` maps that to `editTransactionEmpty`.

Reproduced natively with w21/813's build and fixture; the save was refused, so nothing was written. Pencil ▸ tap before `2026` on line 1 ▸ paste a single space ▸ Save. The banner reads **"An empty entry can't be saved. To remove the transaction, use Delete on its detail screen."** while the editor still shows the whole entry. Per the agent's proof, a leading tab or 4-space-indented pasted text gives the same banner.

## Fix

When an indented dated line exists, have the ledger say that the date must start the line, and map that to `ledgerEntryIndent`. Keep `editTransactionEmpty` for a draft that is truly empty or all comments.

**Acceptance:** this edit reads an indentation message, and an emptied draft keeps the current one. Unit cases are added.

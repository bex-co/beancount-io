# A journal link with `?time=0000` makes Transactions fail to load

**Severity:** low (an opened link only). **Estimate:** 10 minutes. Owner: mobile.

**Root cause (A3).** `periodDays` in `mobile/src/common/app-links/journal-link-filters.ts` (`:15`, the year branch) accepts `0000`. `resolveDateRange` then sends `time: "0000-01-01 - 0000-12-31"`. The server's `parseDateRange` returns `undefined` for it, which becomes a `BadUserInputError`; years `0001` and later parse. The list then shows `transactionsLoadError`, and the filter sheet's date picker would read the year as 1900.

Not run natively: deep links can't be accepted on this simulator. `tsx` proof: `journalLinkFilters` returns `custom 0000-01-01..0000-12-31`, and `toFilterQuery` sends that `time` string.

## Fix

Reject years below 0001 in `periodDays`, so the link opens unfiltered, like other unreadable times.

**Acceptance:** `journalLinkFilters(new URLSearchParams("time=0000")).range` equals `"all"`.

# Browse ledgers: Load more re-sorts the whole list, so featured open_ledger rows from page 2 jump above rows already on screen

**Severity:** low. **Estimate:** 20 minutes. Owner: mobile.

**Root cause (A3).** `mobile/src/screens/ledger-selection/discovery-store.ts` `merge()` (about `:63-70`) sorts the whole merged list so `open_ledger/*` rows rank first. After Load more, a page-2 `open_ledger/*` row is inserted above rows the user is already reading and the list shifts under their thumb.

Proven by running the store with fake pages: page 1 `[a/x, b/y]`, page 2 `[open_ledger/z]` gives `[open_ledger/z, a/x, b/y]`. Not seen natively (the driver cannot scroll to Load more).

## Fix

Rank on the server (priority owner) or sort only within the appended page and keep earlier rows in place.

**Acceptance:** a store test where a page-2 featured row lands after the rows already shown.

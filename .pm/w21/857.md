# The ledger service runs date-dependent plugins (amortize_over, forecast) on the server's UTC date: in NZ, November's amortized $100 is missing until 13:00 local on Nov 1

**Severity:** minor to moderate. **Estimate:** 45 minutes. Owner: ledger (with parity across REST, GraphQL and MCP). A3: `backend-cluster/ledger/src/foundation/rustledger/plugins/index.ts:87` (`localTodayStr`) reads the server clock (the `node:22-alpine` image sets no time zone, so UTC), and `engine.ts:514` and `:581` use it. `amortize-over.ts:152` drops copies dated after that "today", and `forecast.ts:157-166` stops repeating at the end of that "today's" year. Clients can't pass their own date.

Not run natively: the simulator's time zone can't be changed here. Under `TZ=UTC npx tsx` with the real plugins (the agent's proof):
- **Auckland, Nov 1 09:30** (server date Oct 31): a 3-month amortized entry keeps only the 09-01 and 10-01 copies, so November's $100 is missing until 13:00 local.
- **Auckland, Jan 1 2027 09:30** (server date Dec 31 2026): a `#` "Rent [MONTHLY]" forecast ends at 2026-12-01, so no 2027 forecasts show as Upcoming until 13:00.
- **Los Angeles, Oct 31 18:30** (server date Nov 1): the 11-01 copy appears a day early.

## Fix

Add an optional client date to the reads that run plugins, and thread it through to the plugins and `parseDateRange`. Without one, keep today's behaviour. The cache key already includes the date. Apply it on every surface.

**Acceptance:** with the client date supplied, these three cases match the client's local calendar. Unit cases are added.

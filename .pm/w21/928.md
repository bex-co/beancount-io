# The account picker hides its Create row when the search text appears inside an unrelated account name ("car" in CreditCard)

**Severity:** minor to moderate. The user can't create the new category from the picker and has to leave for Accounts ▸ +. **Estimate:** 20 minutes. Owner: mobile.

**Root cause (A3).** `mobile/src/screens/account-picker-screen/picker-sections.ts:201-204` (`showCreateBelowResults`) counts any result whose name contains the word anywhere (`name.includes(word)`) as a real hit. w21/258 asked for a match on a whole name segment.

**Native (iPhone 17e, 2026-10-23).**
1. New Transaction → expense posting's account → paste `car` into Search accounts.
2. The picker lists "Liabilities:CreditCard:Visa" and "Income:Salary", with no Create row.

`Expenses:Car` doesn't exist, so Create should be offered. Nothing was saved.

**`tsx` proof (the agent's).** With `Expenses:Healthcare`, `Expenses:Childcare` and `Expenses:Home:Carpet` in the chart:
- `car` gives `createEmpty:false` and `createFooter:false`.
- `pet` gives the same.

## Fix

Count a word as a hit only when it starts a segment of the result, or when `createdAccountName(query, root, roots)` equals an existing account by `nameKey`. Otherwise, show the footer.

**Acceptance:**
- `car` and `pet` show Create below the matches.
- `food`, `rent`, `credit card` and `FOOD:groc` still hide it, as the existing tests require.

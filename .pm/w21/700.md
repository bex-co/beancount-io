# Home's Recent Transactions flashes "No transactions yet" with an Add Transaction button while its up-to-today read loads, and stays that way if the read fails (w21/664 regression)

**Severity:** minor (a misleading first-run empty state on Home; stuck there when offline on a later day). **Estimate:** 30 minutes. Owner: mobile. A3: w21/664 added a second, up-to-today read when the month-end page holds only future rows. `recent-transactions-card.tsx` reads only that query's `data` (`:99`), never its `loading` or `error`. While `pastData` is undefined, `entries` come from the month-end page with its future rows removed, so the card is empty (`:112-118`). The skeleton keys off the first query only (`:164`), so the card renders the first-run "No transactions yet" text and the Add button (`:168-189`). Pull to refresh refetches only the first query (`:83`). The second query's window, `recentTransactionsWindowToToday` (`selectors/recent-window.ts:53`), changes daily, so offline on a later day the read fails and the false empty state stays (the failure w21/513 fixed for the first query).

Native (iPhone 17e, Metro `--clear` at `4d9abc812`; disposable ledger with w21/664's fixture of 32 × 1.00 USD entries on 2026-10-24…31, restored byte-for-byte afterwards): a cold launch with a 14-frame `simctl io screenshot` burst. Frames 8–9 show cached rows (Farmers Market…). Frame 10 shows **"No transactions yet" and a green "Add Transaction" button**. Frames 11–14 and the settled screen show the rows again. Under `tsx` (the agent's proof), with `needsPast` true and `pastData` loading or failed, the card is not failed, shows no skeleton, and shows `recentTransactionsEmpty` with the Add button.

## Fix

Treat the second read as part of the card's state: show the skeleton while it loads, the failure tile with Retry when it fails, and refetch it on pull to refresh. Give it a cache key that survives a day offline (as w21/513 did).

**Acceptance:** a cold launch with this fixture never shows "No transactions yet". With the second read failing, the card shows "Couldn't load" and Retry. A unit case covers both.

Searched `.pm/**` for pastData, "No transactions yet" together with loading, and recentTransactionsWindowToToday.

# Charts and the referral screen are sized from a screen width read once at app start, so on iPad they keep the old width after rotation or a Split View resize

**Severity:** medium (iPad only; the app declares iPad support). **Estimate:** 30 minutes. Owner: mobile.

**Root cause (A3).** `mobile/src/common/screen-util.ts:3-4` does `export const ScreenWidth = Dimensions.get("window").width` (and `ScreenHeight`), evaluated once when the module loads. Window resizes (iPad rotation, Split View, Slide Over) never re-run it. These use it for sizes:
- `mobile/src/common/d3/interactive-line-chart.tsx:532`: `chartWidth = ScreenWidth - contentPadding * 2` (the account-detail and net-worth chart; the SVG and `geometry` memo are built from it).
- `mobile/src/common/d3/bar-chart-d3.tsx`: the same (the Home spending card).
- `mobile/src/common/d3/income-expense-bar-chart.tsx:127`: `availableWidth = ScreenWidth - contentPadding * 2 - axisWidth`, which drives the bar and plot widths.
- `mobile/src/screens/referral-screen/referral-screen.tsx`, about `:47` and `:74`: a fixed width on the share-link box and the share button.

The Sankey (`cash-flow-sankey.tsx:257`) uses it only as an initial value and re-measures through `onLayout`, so it is fine. w21/220 fixed only the budget chart and told the next person to check `bar-chart-d3`, `income-expense-bar-chart` and `interactive-line-chart`; none of those was changed.

Not run: this is a code-level finding, because the only simulator available is an iPhone in portrait (the app is portrait-only on iPhone, so landscape and Split View exist on iPad only). Effect, from the code: on an 820 pt iPad opened in portrait the chart is 788 pt wide; after rotating to landscape (1180 pt) it stays 788 pt in a 1148 pt container, flush left. Opened in landscape and rotated to portrait, it is 1148 pt in a 788 pt container and overflows. Dragging a Split View divider down to a Slide Over width has the same effect.

**To confirm:** boot an iPad simulator, open Home, Accounts, then an account, and rotate; the spending bars and the balance line stay at the old width.

## Fix

Measure the container with `onLayout`, or use `useWindowDimensions().width`, as `budget-bar-chart-d3.tsx` and the Sankey already do. Delete `ScreenWidth` and `ScreenHeight` from `screen-util.ts`, and the dead `isIphoneX`, `statusBarHeight` and `navigationBarHeight` that are computed from the same stale values.

**Acceptance:** render each chart with a width of 820 and then 1180 and assert the SVG width follows the container; add a source check that no `src/` file imports `ScreenWidth` or `ScreenHeight`.

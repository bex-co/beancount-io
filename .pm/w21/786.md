# A journal app link replaces the Transactions filters but keeps the old search text, so the linked account/month can show "No transactions match"

**Severity:** low. **Estimate:** 20 minutes. Owner: mobile. A3: `mobile/src/common/app-links/open-app-link.ts:105-108` writes only `transactionFiltersVar`. The search text lives in the tab's local state (`transactions-screen/transactions-screen.tsx:117`), so for the same ledger it survives the link while the tab stays mounted. w21/344's resolution says a link "replaces whatever filter was left in the app"; the search isn't replaced.

Not run natively: `simctl openurl` deep links are blocked by the system confirmation on this simulator (w4/blocked/001). Code path (the agent's trace): type "cafe" in Transactions on ledger A, go Home, then open `…/ledger/A/journal?account=Assets:Qa20261020:Bank&time=2026-10`. The list shows that account and month, still narrowed by "cafe".

## Fix

Keep the search in a ledger-scoped reactive variable (or bump a reset token), and have `openAppLinkTarget` clear it along with the filters.

**Acceptance:** after the link, the search box is empty and the list shows every entry for the linked account and month. A unit case is added.

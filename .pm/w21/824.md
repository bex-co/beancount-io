# A folder path with Persian or Arabic segments draws child first in the Files breadcrumb ("qa20261020/ملی/بانک"), as account paths did before w21/743

**Severity:** minor. The breadcrumb, commit file rows and diff headers show the wrong place for a file. A `documents/` tree mirrors account names, so Persian or Arabic accounts produce these paths. **Estimate:** 20 minutes. Owner: mobile. A3: paths are rendered raw in three places:
- the breadcrumb, `ledger-file-browser-screen/index.tsx:775`
- commit detail's file rows and "Renamed from", `commit-detail-screen.tsx:354` and `:52`
- diff header lines, where `isolateSourceLine` (`common/bidi.ts`, w21/780) isolates the whole `a/…` token but not each path segment

Per the agent's CoreText check, `documents/Assets/بانک/ملی/2026-10-01.pdf` even draws its date backwards and moves the file name into the folder path.

Reproduced natively on the iPhone 17e simulator, English UI, Metro `--clear` at `dca83bb03`. In the disposable ledger, `qa20261020/بانک/ملی/notes.bean` was created through the API and deleted afterwards; main.bean was untouched. Files ▸ qa20261020 ▸ بانک ▸ ملی: in a device-resolution crop, the breadcrumb draws "qa20261020/", then **ملی** (the child), then "/بانک" (the parent). That is the child-first order w21/743 fixed for account paths.

## Fix

Add `isolatePath` to `common/bidi.ts`, modelled on `isolateAccountPath` but splitting on `/`: a first-strong isolate per segment, inside a left-to-right isolate. Apply it to the breadcrumb, file rows, "Renamed from", `formatErrorLocation`, and path tokens inside `isolateSourceLine`.

**Acceptance:** this breadcrumb draws parent first, and a dated file name stays at the end. Unit cases are added.

## Dedupe

Not w21/743, 766 or 780 (account paths and source lines). Searched `.pm/**` for breadcrumb together with bidi, RTL and isolateAccountPath.

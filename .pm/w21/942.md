# In the file editor, tapping the same error row again within 3 s doesn't jump

**Severity:** low. The control appears not to respond. **Estimate:** 15 minutes. Owner: mobile.

**Root cause (A3).** `onJump={(line) => setJumpToLine(line)}` (`mobile/src/screens/ledger-file-editor-screen/index.tsx:1181`) sets a value equal to the current state, so React skips the render. The editor's jump effect depends only on `jumpToLine` (`code-editor.tsx:594`), so it doesn't run again. The state resets to null only after a 3 s timer (`index.tsx:1089-1095`).

It bites in two cases:
- Tap "line 42", scroll away, then tap "line 42" again.
- Open the editor from a Notifications error row, then tap that same row in the banner.

Not run natively: the driver takes about 4 s per tap, which is longer than the window. A person can reproduce it.

## Fix

Make the jump carry a sequence number (`{line, seq}`), as `insertSpec` already does, and key the editor's effect on `seq`.

**Acceptance:** two taps on the same row both move the cursor to that line.

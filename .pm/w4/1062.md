## Cause and bounded repair

The installed Radix react-dialog1.1.15 uses react-dismissable-layer1.1.11 and react-use-escape-keydown1.1.1. `react-use-escape-keydown/dist/index.js:40–50` listens on the document with **capture:true**. `react-dismissable-layer/dist/index.js:97–106` invokes onEscapeKeyDown and dismisses the highest layer when it was not prevented.

`dashboard/src/common/components/ui/dialog.tsx:84–89` protects active composition/busy dialogs and delegates the caller hook. `features/journal/components/entry-context-dialog.tsx:184–204` supplies no editor-widget Escape ownership override. Its onOpenChange reaches requestLeave, which closes this clean/read-only source before Monaco can consume the key. The installed Monaco0.55.1 Find controller already binds Escape to closing its visible widget (`esm/vs/editor/contrib/find/browser/findController.js:838–849`); the native controls above establish both widgets otherwise function normally.

Coordinate this dialog's capture-phase dismissal with the embedded editor's active-widget ownership using the existing dialog/editor event hooks. Let Monaco consume Escape for its actual Find/Go to Line widgets, retain the source dialog and editor focus, then let a later unclaimed Escape run the existing outer leave behavior. Preserve composition handling, ordinary close/return focus, dirty-discard protection, pending-write ownership, source identity, readonly semantics, Find acceptance and Go to Line acceptance. Do not suppress all editor Escape keys, add delays, copy widget controllers, patch dependencies or introduce a global focus/key manager. Keep the repair scoped to this integration; no API, dependency or cross-package change is needed.

Acceptance: real loaded-editor keyboard checks reproduce Find and :2 Go to Line at narrow/desktop widths; first Escape closes only the widget, second Escape performs the normal outer dismissal, and the existing Close/Enter controls still work. Include meaningful nested editor/dialog key-order regression coverage, retain existing composition/dirty/pending protections, and run dashboard gates when implementing. QA authored no product fix or formal tests.

# Let configured transaction tolerances reach ledger validation

**Minor · 40–55m · dashboard · A2.** Residual of [W3/499](../w3/done/499.md), whose closeout explicitly left higher configured tolerances unexercised. New Entry treats Beancount's default inferred tolerance as the ledger's effective policy and refuses otherwise valid entries before submitting them.

## Reproducer and accounting control

Use a synthetic ledger with:

```beancount
option "operating_currency" "USD"
option "inferred_tolerance_default" "USD:0.01"
2026-01-01 open Assets:Bank:Checking USD
2026-01-01 open Expenses:Food:Coffee USD
```

In Journal → New Entry → Transaction, select those two accounts, explicitly choose USD, and enter **−10.00 / 9.99**, leaving the automatically added unnamed row unused. Click Create Transaction Entry.

Expected: the unchanged postings reach the ledger's authoritative validation. The −0.01 USD residual is within this ledger's explicit 0.01 tolerance. Actual client branch: **“Postings don't balance: -0.01 USD left over. Adjust an amount, or clear one to balance it automatically.”** No mutation is prepared. Clearing or changing an intended amount is unnecessary for this valid entry.

Independent local Python Beancount 3.2.3 and the current bundled rustledger-WASM both load the complete fixture including that transaction with **zero errors**. The current ledger-service `checkTransactionBalance` with `scanInferredToleranceDefaults` also accepts it. Controls: removing the option refuses the −0.01 residual; −10.00 / 9.98 exceeds the configured tolerance and is refused; −10.00 / 9.996 passes the default implied tolerance. A separate `*:1` whole-number fixture passes both engines and the precheck; its native form variant was not exercised.

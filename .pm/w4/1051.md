**Minor · dashboard · 35–50 minutes · A2.** A reader should be able to read configuration values as ordinary text on a supported narrow viewport.

## Cause and bounded repair

`dashboard/src/features/ledger-data/settings/options-table-section.tsx:72–73` gives the first header an unconditional `w-75` (300px). The auto-layout table has no responsive allocation or readable minimum for its second column. The app body inherits `[overflow-wrap:anywhere]` from `common/root-route/shell-component.tsx:24`; with only about9px of usable value width after cell padding, the browser can satisfy the first-column width by breaking every value character. The shared Table's horizontal wrapper does not help because the table itself fits322px.

Make this options-table layout responsive so both option names and full values have usable reading width at390px. Suitable bounded choices include allowing the first column to share the available width and wrap long identifiers, or preserving readable columns in an accessible local scroll region. Keep every exact value, Option/Value relationships, both table names, formatting of arrays/objects/null/booleans and desktop readability. Do not truncate values, shrink the font to fit, change ledger configuration, remove the global wrapping rule or alter every shared Table consumer. Both BeancountOptionsSection and FavaOptionsSection use this single owner.

Acceptance: actual browser geometry at390px and1440px shows readable headings and short values; include long option identifiers and scalar/array values, preserve the complete text and named table semantics, and keep any necessary overflow within an operable named region. Verify both cards and repeat at narrow width. Add a meaningful layout regression and run dashboard format:check, lint, test and build when implementing. Other engines/locales, zoom and actual screen-reader speech remain unverified here.

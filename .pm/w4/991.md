# Return focus to visible report filters after the header changes layout

**Severity:** minor. **Estimate:** 35–50 minutes. **Owner:** dashboard. **A2:** closing Report filters should leave a usable filter control focused even if the header changed layout. Residual follow-up to completed [W3/m20's focus-return acceptance](../w3/done/m20/done/t002.md); ordinary narrow close still works, so no additional historical finding group is counted.

## Reproduction and controls

Production `https://beancount.io`,2026-10-22; isolated owned headless Chromium155.0.8059.85, anonymous public `open_ledger/example`, English/light. Two fresh390×844 contexts, each resized only within its owned browser page to1440×1000. No response, clock, CPU or state fixtures.

1. Open `/ledger/open_ledger/example/journal?time=2016` and wait for the genuine Journal read. The retained independent response is HTTP200 with393 transactions, Transaction type, offset0, limit60 and no GraphQL errors.
2. Activate **Filters** by native Enter and wait for the named **Report filters** dialog. Widen to1440×1000. The dialog correctly stays open and usable, while the header switches to inline filters.
3. In the first context, activate the dialog's **Close** button by native Enter. In the independent context, press Escape with no nested suggestion popup open. Wait until the dialog detaches and rendering settles.
4. Both paths leave activeElement on **BODY**. The inline Time field is visible, but no filter control receives focus. Native Tab reaches **Skip to main content**, outside the filter workspace. The original Filters button remains connected and enabled but is `display:none` with zero client rects.

Working controls: after returning the second context to390px, opening and closing the same dialog without widening returns focus to the visible Filters button. Clicking the visible desktop Time field in the first context recovers normal editing; ArrowLeft/Escape keep exact2016 and its URL, with no extra Journal read. Body pointer/scroll locks clear and no dialog remains after recovery settles. The applied Time,393-row result and query counts remain intact; the defect is the missing close-focus handoff, not a stuck modal or changed filter.

A further fresh **1040×1000** control reproduces without resizing the viewport. The expanded sidebar leaves a784px header and visible Filters opener. With the sheet open, the native app shortcut **Cmd+B** collapses the sidebar; after its transition finishes, the same1040px viewport has a992px header and a hidden opener. Escape again leaves BODY, followed by Skip to main content on Tab. Expanding the sidebar back to the784px-header layout and repeating an ordinary open/Close returns focus to Filters. The Journal remains2016 and its read count stays1. This confirms that actual container/control visibility, rather than window width alone, must govern the handoff.

## Cause and bounded repair

`dashboard/src/common/components/ledger-layout/layout-header.tsx:94–137` keeps the Sheet mounted independently of its CSS-responsive opener. The inline controls appear and the opener hides at `@min-[52rem]/ledger-header`; the tested wide header is1184px. SheetContent receives no onCloseAutoFocus override or alternate visible target. `common/components/ui/sheet.tsx` forwards that callback to Radix when supplied, but supplies no application-specific fallback itself.

Installed `@radix-ui/react-dialog/dist/index.mjs:146–149` prevents its default unmount focus handling and calls the trigger ref's focus method. The ref still points to this hidden button, so it cannot receive focus. The exact browser state corroborates that ownership gap. The existing restoreFocusOnDialogClose helper checks document.contains, not visibility; a connected hidden preferred opener would also defeat its supplied fallback unless the caller filters that preference appropriately.

Keep the close handoff in the header that owns these equivalent responsive controls. Return to the opener while it is visible; otherwise choose an appropriate visible inline filter control. Determine actual availability within the header's container layout rather than substituting a viewport-only breakpoint. Preserve the open sheet and its draft through resizing, ordinary narrow focus return, filter values/history, deliberate focus movement and modal lock cleanup. A resize alone should not steal focus from the active dialog. No API, dependency or backend change is needed.

Acceptance: real rendered close-focus regressions cover a connected but hidden opener and a visible equivalent fallback. Repeat390→1440 with both native Close and Escape: focus lands on a connected visible filter control and Tab continues there. Same-width close returns to Filters, values/query counts stay correct, and manual continuation remains usable. Run dashboard gates when implementing; other routes, locales, physical window managers/screen readers and repaired behavior remain unverified.

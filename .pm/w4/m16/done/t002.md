## Objective

Apply the same bounded state-ownership approach to Income Statement, Balance Sheet and Trial Balance, preserving their valid tab options.

## Context

See [FINDINGS.md](./FINDINGS.md) and the milestone definition of done. Preserve the settled-data/export requirements in reports/CLAUDE.md.

## Files

income-statement/index.tsx and income-statement-content.tsx; balance-sheet/index.tsx and balance-sheet-content.tsx; trial-balance/index.tsx and trial-balance-content.tsx

## Acceptance criteria

- [x] Income survives uncached Yearly and Assets survives uncached Weekly; Trial Balance Equity survives uncached conversion reads; all current selectors remain controlled.

## Out of scope

API/schema changes, financial calculations, new dependencies and unrelated navigation preferences.

## Implementation and verification

Completed 2026-09-19. Income Statement, Balance Sheet and Trial Balance now own their chart selection in the page rather than the content component, exactly as t001 did for Cash Flow: `selectedTab` moves to `index.tsx`, which outlives the pending read, and the content takes `selectedTab` / `onSelectedTabChange`. Each keeps its own default — `netProfit`, `netWorth` and `assets` — so no report's valid tab options changed. All four selectors are now controlled by the page.

The repair is identical across the four because the defect was: each content component owned the selection with `useState`, and each page returns `ReportLoadingState` while `selectSettledReportData` reports pending, destroying the owner. Trial Balance reaches the same boundary through a conversion change rather than an interval, which is why it belongs in the same repair.

The stale-data contract is untouched. Every page still withholds its content — statement, amounts and export — until data settles; only the reader's choice of chart survives the gap. The ledger-specific conversion cookie is unchanged, and the selection stays report-scoped because it is per-page React state under a layout that keys its subtree by ledger id.

Verified live rather than inferred, against a local production build reading the public `open_ledger/public-company-template` ledger anonymously: 16 checks in fresh isolated headless Chromium contexts at 1440x1000 and 390x844, all passing. Cash Flow keeps By Activity through an uncached Quarterly, Income Statement keeps Income through an uncached Yearly, Balance Sheet keeps Assets through an uncached Weekly, and Trial Balance keeps Equity through an uncached Units conversion — each confirmed at both widths, so the desktop tab strip and the narrow View selector agree.

Two test harnesses that render content directly were updated to own the selection the way the page does, so their tabs behave as in production; the inline Trial Balance render that only checks a summary row passes a fixed selection. `yarn vitest run src/features/reports` passes 61 files and 533 tests.

Gates from `dashboard/`: `yarn format:check`, `yarn lint`, `yarn build` and `yarn test` pass at 376 files and 4,238 tests. The first lint run caught two now-unused `useState` imports left behind in the balance-sheet and trial-balance content components; both were removed, and `income-statement-content` keeps its import because it still owns `chartMode`. gitleaks reports no leaks in the changed tree.

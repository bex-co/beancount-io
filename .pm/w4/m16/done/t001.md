## Implementation and verification

Completed 2026-09-19. The selection now lives in `cash-flow/index.tsx`, which outlives the pending read, and `CashFlowContent` takes it as `selectedTab` / `onSelectedTabChange`. Nothing else moved: the page already owned `timeInterval` and `conversion` this way, so the chart selection simply joins the state the page was already holding for the same reason.

This keeps both contracts the milestone has to satisfy at once. `selectSettledReportData` still classifies every loading response as pending, `index.tsx` still returns `ReportLoadingState` in that branch, and the content component — with its statement, amounts and export menu — is still withheld until data settles. Only the reader's choice of chart survives the gap. The state stays report-scoped rather than global: it is per-page React state, and the ledger layout keys its subtree by ledger id, so a ledger switch discards it.

Covered by two cases in `cash-flow/__tests__/index.test.tsx`. The first walks the real reproduction through the page: settled data, the reader picks By Activity, an uncached interval leaves the read pending so the content is replaced, then the read settles and By Activity is still selected. The second asserts the content and its export stay withheld while pending, so the repair cannot be mistaken for weakening the stale-data safeguard. The content harness in `cash-flow-content.test.tsx` now owns the selection the way the page does, so its tabs behave as they do in production.

Proved real rather than assumed: pinning the page's props back to the old behaviour — a constant `netCashFlow` with a no-op setter, which is what an unmounted owner produces — fails the selection case while the other five still pass. Restoring the fix passes all six.

Gates from `dashboard/`: `yarn format:check`, `yarn lint` and `yarn build` pass. `yarn test` needed care: the first full run reported one failure in `journal/components/new-directive-dialog/__tests__/amount-step-precision.test.tsx`, a focus-timing assertion in an unrelated feature that shares no module with these files. It passes in isolation, the clean tree passed 376/376, and a second full run of this identical tree also passed 376 files and 4,236 tests. Same code passing and failing across runs is nondeterminism, not a consequence of this change, so it is recorded as a flake in [141](../../141.md) rather than dismissed or silently re-run.

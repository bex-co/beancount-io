## Adoption verification

Completed 2026-09-19. The comparison journey was exercised live against a local production build reading the public `open_ledger/public-company-template` ledger anonymously, in fresh isolated headless Chromium contexts at 1440x1000 and 390x844.

Twenty checks passed in total. Sixteen from t002 cover the four reports: Cash Flow keeps By Activity through an uncached Quarterly, Income Statement keeps Income through an uncached Yearly, Balance Sheet keeps Assets through an uncached Weekly, and Trial Balance keeps Equity through an uncached Units conversion — each at both widths, so the desktop tab strip and the narrow View selector agree on what the reader is looking at. Four more confirm the behaviour the milestone says must not change: returning from Quarterly to the now-cached Monthly still retains By Activity, so the repair did not simply mask the cached path; and collapsing and re-expanding the charts section leaves the selection intact.

One worked example of the point of the milestone: on Cash Flow the reader picks By Activity, changes Monthly to Quarterly, and the same By Activity chart comes back regrouped by quarter. Before this milestone that interaction returned Net Cash Flow, so the reader had to reselect their chart after every interval change.

Documentation decision, recorded as t003 asks. `src/features/reports/AGENTS.md` already described the settled-data contract accurately — statement pages use `selectSettledReportData` so export and print only see a coherent completed result — and that claim needed no correction. It was, however, silent on the consequence that produced this defect: the pending branch replaces the report content component, so any view state the reader chose cannot live inside it. One sentence was added next to that contract saying chart selection belongs to the page and is passed down as `selectedTab`/`onSelectedTabChange` alongside `conversion` and `timeInterval`. That is the guidance that would have prevented the bug, and it is the only documentation change made — no unrelated churn, no new feature documentation, and `python3 scripts/check-agent-guidance.py` still reports all 17 scopes canonical.

A caution worth recording for the next browser run in this repo: the harness serves `dashboard/.output`, so it must be built with `VITE_API_URL=/api-gateway/`. A later plain `yarn build` overwrites that output with the bundle pointing at the deployed API host, and the reports then render without their interval and conversion controls. That was observed and corrected during this task; it affected only the harness, never a product claim, and the sixteen t002 results were produced on a correctly built harness.

Not claimed: error and retry states were not exercised live, since triggering them safely needs a failure this read-only public journey cannot produce. They are unchanged by this milestone, which only moved where the selection is owned.

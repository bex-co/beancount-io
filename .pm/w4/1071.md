# Pluralize CSV preview row counts

**Minor · dashboard · 45–60m · A2.** Follow up on [m28](./done/m28/README.md)'s existing count-message convention at the Import Preview consumer. This is a wording defect: the numeric row counts and validation decisions remain correct.

## Reproduce and controls

Production `https://beancount.io`,2026-10-24 UTC; owned isolated headless Chromium156.0.8078.47, light/UTC, synthetic-ledger owner. Fresh390×844 and1440×1000 loads repeat in English and Russian.

1. Open Smart Import with `?lang=en` and upload this local synthetic CSV. Stop at Preview; no AI or import is needed.

```csv
Date,Payee,Description,Amount
2026-10-01,qa-20261024-count-good,Valid row,0
2026-10-01,qa-20261024-count-bad-1,Invalid amount,oops
```

2. The badges show **1 Valid / 1 Errors**. Adding another invalid-amount row correctly changes the second number to **2 Errors**.
3. Repeat fresh uploads with `?lang=ru`, keeping one valid row and respectively1,2,5 invalid rows. Both widths show **1 Действительные** and **1 Ошибки / 2 Ошибки / 5 Ошибки**. The error noun never changes. Natural Russian error counts require **1 ошибка / 2 ошибки / 5 ошибок**; English requires **1 Error / 2 Errors**.
4. English working controls at both widths: edit the invalid amount to **12.50** and press Enter. The badges correctly become **2 Valid**, with no error badge. Delete the zero-valued companion: **1 Valid** remains, and the repaired row is retained.

Independent CSV parsing confirms every displayed numeric count: one valid row plus the requested number of invalid rows. The existing count is the number of **rows with errors**, not the number of individual field errors. Preserve that meaning. The Russian2 case and English2 case demonstrate why a fixed plural can look correct for some counts while failing others.

## Cause and bounded repair

`dashboard/src/features/importer/components/steps/preview/import-preview-table.tsx:53–58` derives correct counts from editable rows. At:118/:123 it renders the number separately from `t("importer.preview.validCount")` or `t("importer.preview.errorsCount")`, passing no count.

All15 importer catalogs define these as static messages. English:204–211 supplies **Valid / Errors**; Russian:201–208 supplies **Действительные / Ошибки**. The translation hook therefore has no plural category to select. This is a missed consumer of the existing infrastructure, not a new framework requirement.

Convert these two badge messages to natural count messages using the repository's existing plural families and `t(key,{count})`. Provide each locale's required categories, including Russian one/few/many/other and the single other form for Chinese/Japanese/Korean. Let the message place its count; avoid concatenating a number with an invariant plural label. Keep row validation, raw amounts, stable row IDs, deletion, selection and Continue eligibility unchanged. The valid badge also needs natural localized singular wording; English “Valid” itself is invariant.

The only production consumer is `PreviewStep`, reached through Smart Import's shared workflow. Its empty-file branch uses `EmptyRowsState` instead, and the error badge is intentionally absent at zero. No loading, parsing, API, backend, dependency or other-package change is needed.

Acceptance: render the real Preview with real translations for English1/2 and Russian1/2/5; assert natural full count labels and correct numbers. Repair/delete rows and verify the translated badges update, including disappearance of the zero-error badge. Keep the empty-file path and correct row classification. Check all15 catalog categories and dashboard gates when implementing. Existing row-identity/structural-repair tests replace translation with key echoes and cannot catch this wording defect. QA added no product fix or formal test.

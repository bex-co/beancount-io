# Return Budget search focus after keyboard Clear

Severity: **minor**. Estimate: **25–40 minutes**, dashboard only. A2 — a keyboard reader should be able to clear an account search and immediately type the next one.

## Live reproduction

Production `https://beancount.io`, public synthetic `open_ledger/budgeting-envelopes`, authenticated read-only QA, English/System, owned headless Chromium **149.0.7827.55**. Fresh **1440×1000 and 390×1000** loads reproduce. Current main **7737688d** retains the cause; deployed full SHA is unverified. No request substitution or production writes.

1. Open `/ledger/open_ledger/budgeting-envelopes/budget`. In **Search budgets by account...**, type **Dining** and wait for the one matching account/history table.
2. Press **Tab** from that input. The adjacent icon button named **Clear** receives focus. Press **Enter**.
3. The search correctly becomes empty and all seven budgets return, but the focused button is removed and `document.activeElement` becomes **BODY**. The search input has no focus.
4. Type **Rent** through actual keyboard character events (`page.keyboard.type`). The search stays empty: none of those characters reach it. Explicitly refocus the search and type Rent; the value becomes **Rent** and its matching history table appears normally.

Both widths repeat the exact focused Clear → BODY → ignored typing → successful refocused typing sequence, without browser exceptions. The separate no-match journey also reproduces the focus loss. Filter values themselves work: whitespace/case-insensitive `  DINING  ` finds one of seven accounts, unmatched text finds zero, clearing only search preserves Monthly and Last year, and the no-match list-reset button clears search/interval while preserving Last year. Keep those semantics.

## Cause and bounded repair

`dashboard/src/features/ledger-data/budget/index.tsx:247–254` conditionally renders the search's Clear button only while `search` is nonempty; its handler only calls `setSearch("")`. The always-mounted Input at **lines 240–246** has no ref/focus handoff. Thus clearing unmounts the focused element without choosing the appropriate replacement.

Return focus to this search input when its adjacent Clear action runs, keeping the emptied value and current interval/time filters. Preserve the existing button's accessible name, keyboard and pointer activation, matching/counts, and read-only permissions. Keep the change local to this search control; do not alter global Button behavior or redesign the no-match reset button/dialog focus helpers.

Acceptance: a rendered owning-page test types Dining, tabs to the adjacent Clear button, presses Enter, asserts the empty search is the active element, then types Rent without a refocus and sees the matching result. Verify pointer clearing and fresh desktop/narrow keyboard journeys, including the no-match case. The test must assert continued typing/focus, not just the cleared value or restored result count. Run dashboard format/lint, tests and build when implementing.

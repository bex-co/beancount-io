# Keep early Find validation errors inside the source viewer viewport

Severity: **minor**, dashboard. Estimate: **45–60 minutes**. A2 — readers should be able to read source-search validation messages on narrow screens, including immediately after the editor becomes available.

## Reproduce

Production `https://beancount.io`, 2026-10-09, dedicated QA login, public synthetic `open_ledger/example`, English, isolated headless Chromium 149.0.7827.55. Source rechecked on main **aeb59561**; intervening pulls changed board files, not the editor wrapper. Exact deployed SHA is unverified.

1. In a fresh 390×1000 or 320×1000 context, open `/ledger/open_ledger/example/files/blob/main/README.md?editMode=false&lang=en`. Leave assets and API responses untouched.
2. As soon as the actual Editor content textbox appears, focus it and press Cmd+F. Enable Use Regular Expression through its visible checkbox or the actual Option+Cmd+R shortcut when the responsive toolbar hides the checkbox. Type `[` into Find.
3. On affected cold loads, the invalid-expression message retains a **419px** inline container width. At 390px it starts at **x=-66**; at 320px it starts at **x=-136**. Its opening text is clipped off the left edge. Screenshots at both widths were visually inspected. The reason remains partly readable; this is not a claim that the entire message disappears.
4. In an independent fresh 390×1000 reproduction, the Find input had already narrowed to **145px**, but the popup still had width 419px and x=-66 both approximately 800ms and four seconds after typing. Waiting for the input layout to settle did not repair the existing popup.

This is timing-dependent, not every narrow search. In that three-context observation, two cold loads sized the message correctly; the third reproduced the stale width. In the affected run, Editor content appeared at 6530ms and the real `editor.main.css` response headers arrived at 6548ms with HTTP 200. Those timestamps identify response headers, not completed stylesheet application. Earlier independent fresh narrow runs also reproduced clipping without fault injection.

## Controls and scope

Waiting 2.5 seconds after editor readiness and another second after opening Find before entering the expression produced fitting messages at all three widths: 145px at 390, 58px at 320, and 235px at 1440. The narrow messages wrap rather than clip. Invalid regex correctly sets `aria-invalid=true`; replacing it with `Beancount` clears validation and reports **1 of 13**; a synthetic unmatched search reports No results; Escape closes Find and returns focus to the read-only editor. These logical controls pass at 1440, 390 and 320px. Preserve them.

Only public read-only source search was exercised. No source edits, Replace, Save, clipboard operations or ledger/account mutations were performed. All fresh contexts were closed; the original QA page was untouched.

## Cause and bounded repair

`dashboard/src/common/components/monaco-editor/index.tsx` directly mounts `@monaco-editor/react` inside ClientOnly and delegates readiness through onMount. The installed Monaco 0.55.1 input-box implementation snapshots the input width when showing a validation message. Runtime evidence shows a retained 419px message width after the actual input becomes 145px. Initial stylesheet/layout timing is the supported integration-level explanation; the precise upstream positioning sequence is not proven.

Make the existing integration use settled geometry for an early Find validation message, or refresh the existing message geometry when styles/container size settle. Use a supported lifecycle/layout mechanism. Do not replace this with a fixed delay, editor remount, lost search state, upstream fork or new dependency. Preserve read-only semantics, source content, selection, Find focus/query, ordinary validation recovery and the persistent editor lifecycle. Coordinate shared-wrapper work with **w4/210**, whose separate defect concerns terminal initialization failure.

Acceptance: a real browser check opens Find immediately during controlled late-style initialization and proves the invalid-expression message remains within the narrow viewport after layout settles, while a settled-first and desktop control pass. Assert actual rectangles rather than mocked zero-width geometry. Keep the logical search/recovery and read-only controls above; run dashboard gates when implementing. No API change is required.

# The account picker truncates the leaf and keeps the prefix — the opposite of what its own comment says matters

**Severity:** minor. **Estimate:** 15–25 minutes. Owner: mobile. A2: this picker is how a user chooses an account for a filter, a posting or a budget. Three of four search results for `market` end in `…`, and every one of them keeps a shared prefix the user did not need in full.

Environment: branch `main`, HEAD `038faeeb`, native development build `io.beancount.ios` on iPhone 17e / iOS 26.5, English / System / **default** text size, light, authenticated production session at `https://beancount.io`, public `open_ledger/alphabet`. Report-only QA; no filter was applied and no account was selected — the picker was opened and backed out of.

## Repro

1. On `open_ledger/alphabet`, Transactions → filter icon → **All accounts**.
2. The list renders each account as a grey parent path plus a bold leaf. Four of the eleven visible rows are cut:

   | rendered | the part that was lost |
   | --- | --- |
   | `Assets:NonCurrent:Deferred-Income-T…` | `axes` |
   | `Assets:NonCurrent:Non-Marketable-S…` | `ecurities` |
   | `Assets:NonCurrent:Operating-Lease-A…` | `ssets` |
   | `Assets:NonCurrent:Property-Plant-Equ…` | `ipment` |

   In every case `Assets:NonCurrent:` — identical on five consecutive rows — is rendered in full.

3. Search `market`. Three of the four results are cut:

   ```
   Assets:Current:Marketable-Securities
   Assets:NonCurrent:Marketable-Securit…
   Expenses:Operating:Sales-And-Market…
   Assets:NonCurrent:Non-Marketable-S…
   ```

   The searched-for word survives here only by luck of position; the leaf that distinguishes each account does not.

## Root cause

`account-picker-screen.tsx:206-209` puts both halves inside **one** `Text` with `numberOfLines={1}`:

```tsx
<Text style={styles.listItemText} numberOfLines={1}>
  <Text style={styles.parentPath}>{parent}</Text>
  <Text style={styles.leaf}>{leaf}</Text>
</Text>
```

React Native truncates a single-line `Text` at the **tail**, so overflow always eats the last child — the leaf.

The file already states the principle this defeats, twenty lines up (`:120-121`):

> *"The parent path is context; the leaf is what identifies the account, so it carries weight as well as colour — hierarchy shouldn't be colour-only."*

That reasoning is right, and the styling follows it: `parentPath` is `black80`, `leaf` is `fontWeights.medium`. Only the truncation disagrees.

## Fix

**Try one prop first — the app already solves this correctly elsewhere.** The New Transaction form renders account names with `ellipsizeMode="middle"` (`multi-postings-transaction-screen.tsx:315` and `list-item.tsx:95`), which keeps both ends: on device it shows `Assets:Ban…ry:Checking` and `Expense…:Internet` — root *and* leaf legible. The picker's row is the same shape minus that one prop, so:

```tsx
<Text style={styles.listItemText} numberOfLines={1} ellipsizeMode="middle">
```

is the smallest change that fixes it, and it matches an existing in-repo pattern rather than introducing a new one. **Verify it with the nested children**: the picker's row nests two styled `<Text>` elements inside the truncating one, which the transaction form does not, and middle-ellipsis over nested children should be confirmed on device before settling on it.

If that does not hold, fall back to making the two halves siblings in a row so the *parent* absorbs the overflow:

```tsx
<View style={styles.listItemText}>
  <Text style={styles.parentPath} numberOfLines={1} ellipsizeMode="head">{parent}</Text>
  <Text style={styles.leaf} numberOfLines={1}>{leaf}</Text>
</View>
```

with `parentPath: { flexShrink: 1 }` and `leaf: { flexShrink: 0 }`. The leaf then renders whole and the context degrades — `…NonCurrent:Property-Plant-Equipment` — which is the right trade, because the prefix is recoverable from the section header and the leaf is not recoverable from anything.

`ellipsizeMode="head"` on the parent keeps the segment nearest the leaf, which is the most informative part of the context. Note that head-ellipsizing is the one RN mode that historically misbehaves on Android; since this is a two-`Text` row rather than nested children, `"tail"` on the parent is an acceptable fallback and should be checked there.

**Do not** solve it by dropping the parent path. Two accounts can share a leaf (`Assets:Current:Other` and `Assets:NonCurrent:Other` are both present in this ledger and would become identical rows), so the context is load-bearing — it just is not the part to protect first.

**Acceptance:** on `open_ledger/alphabet`, `Assets:NonCurrent:Property-Plant-Equipment` shows its leaf in full; the `market` search shows all four leaves in full; `Assets:Current:Other` and `Assets:NonCurrent:Other` remain distinguishable; the selected-row checkmark and the chevron keep their positions; and a short account renders exactly as it does today with no gap. Add a unit test that the row renders parent and leaf as separate nodes with the shrink applied to the parent — `splitAccountLeaf` has tests, but nothing covers how the two halves are laid out.

## Blast radius

One row component. `splitAccountLeaf` has exactly **one** consumer in the app — this screen — so the change cannot reach anywhere else. No effect on search, ranking, sectioning, or selection.

**The convention this note argues for already exists, and three rows are missing it.** `grep -rn 'ellipsizeMode' src/ --include='*.tsx'` returns five deliberate uses — `"middle"` on the transaction-detail posting rows (`posting-row.tsx:77`), the budget group card's account (`budget-group-card.tsx:196`), and both transaction-form sites (`multi-postings-transaction-screen.tsx:315`, `list-item.tsx:95`), plus `"head"` on `add-budget-screen.tsx:148`. Against that, three rows render a path-like string with `numberOfLines={1}` and **no** mode, so they tail-truncate:

| site | truncates | bites today? |
| --- | --- | --- |
| account picker row (`account-picker-screen.tsx:206`) | the account leaf | **yes** — this note |
| Entry Context balance row (`balance-section.tsx:78`) | nothing; it wraps instead, no `numberOfLines` at all | **yes** — `w4/058` |
| commit detail file row (`commit-detail-screen.tsx:235`) | the **filename**, keeping the directory | not on current data — `open_ledger/alphabet`'s paths (`2026/Q2.bean`, `main.bean`) are short enough to fit |

The commit-detail row is listed for completeness rather than as a separate defect: it is the same omission and the same one-prop fix, it just has no ledger in reach with a path long enough to show it, and its row already carries an `accessibilityLabel` with the full filename so assistive tech is unaffected. Fix all three in the sitting that fixes this one.

Not exercised: enlarged Dynamic Type (which makes this strictly worse and is worth measuring after the fix), dark mode, Android's `ellipsizeMode="head"` behaviour, RTL layout (`LEADING_TEXT_ALIGN` is already applied, but head-ellipsis in RTL was not checked), and a ledger with deeper accounts than five segments.

## Adjacent states

The rest of the picker is **good** and several parts of it are better than average:

- **Search ranks sensibly.** `market` returned leaf-initial matches first (`Marketable-Securities` ×2), then `Sales-And-Market…`, then `Non-Marketable-S…` where the match is not at a segment start. Case-insensitive.
- The category pills (`All` / `Assets` / `Liabilities` / `Income` / `Expenses` / `E…`) **disappear while a search is active**, which is right — a global search should not be silently scoped by a leftover pill.
- Sections are headed by root (`Assets`), and rows carry `accessibilityRole="button"` with `accessibilityState={{ selected }}`; the selected row swaps its chevron for a `checkmark` in the primary colour, so selection is not colour-only.
- `listContent` reserves `paddingBottom: 150`, so the last rows are not trapped under the sheet's bottom edge.

The rightmost category pill renders as `E…` (Equity) at the screen edge. **Not filed:** the pill row scrolls horizontally, so a partially visible last item is ordinary for that control rather than a defect — the same reasoning recorded for the budget chart's clipped axis label in `w4/038`.

No "Recent" / frecency section appeared above `Assets`. That is expected rather than wrong on this ledger — `open_ledger/alphabet` is read-only and has never been used for entry from this device, so `account-frecency` has nothing to rank. It does mean the frecency path is **still unexercised live**, and needs an owned ledger with entry history to test.

## Dedupe

Searched all `.pm/**/*.md` including `done/` for account picker, truncation, ellipsis, leaf and prefix terms. **`w4/012`** ("on a billion-scale ledger the Accounts balance itself is truncated, not just the name") and **`w3/217`** are the Accounts *tab*, where the name loses a width contest with the balance column — a different screen, a different competing element, and there is no balance in this picker at all. **`w4/048`** (filed this run) is the same *shape* on the transactions row — the identifying field losing to the contextual one — and the two are worth reading together as a pattern, but they share no code. **`w4/010`** is this screen's "Create" prefill capitalization. `w4/013` is Dynamic Type on the transaction row. No item covers the picker's row truncation.

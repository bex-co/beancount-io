# Indent statement account hierarchies from the leading edge in Persian

Severity: **minor**. Package: **dashboard**. Estimate: **35–45m**. Source:
continuous dashboard QA for w4. **A2/A3**: Persian readers should see which
accounts are children when report rows use relative account names.

Production `https://beancount.io`, anonymous synthetic `open_ledger/example`,
isolated headless Chromium149.0.7827.55. Local main `390568c2`, served
`main-d5j4FX-V.js`; exact deployed revision unverified.

1. Open `/ledger/open_ledger/example/income-statement?lang=fa&time=2016` at
   390×844/dark. The document correctly has `lang=fa`, `dir=rtl`.
2. In Income List, read **Income → US → ETrade → Dividends**. These four rows
   represent four depths, but every account link ends at the same right edge,
   x338. Parent expanders likewise remain at x346 through370 at every depth.
3. Fresh-load the same Persian route at1440×1000/light: all four links again
   end at one x coordinate,1116. The visual tree is flat.
4. Fresh English control at1440×1000: those links start at x320,340,360,380,
   correctly indenting20px per depth. The source data and row order are equal.
5. Persian ETrade collapse still removes Dividends/Gains and re-expansion
   restores them. The defect is their visible depth, not broken disclosure.

Real GraphQL `getLedgerIncomeStatement` returns HTTP200 with no errors and the
nested child chain `Income` → `Income:US` → `Income:US:ETrade` →
`Income:US:ETrade:Dividends`. No API or financial-calculation change is needed.

Cause: `dashboard/src/features/reports/balance-sheet/hierarchy-list.tsx:44`
sets `paddingLeft: level * 20 + 8`, applied to the account row header at
`:216–220`. In RTL that pads the trailing edge, while the flex row's leading
edge stays fixed. Measured computed left padding grows8/28/48/68px; right
padding stays12px, and every link retains the same right edge. The component
already strips the parent prefix from each child label, so the missing
indentation removes a useful parent/child cue.

Use logical leading-edge padding for the existing depth calculation, retaining
the same20px step and LTR geometry. Preserve relative labels, full destination
account paths, named table/row/column semantics, expand/collapse, summary rows,
amounts and the existing horizontal table scroll. Do not compress the monetary
columns or change the table's minimum width to repair this indentation issue.

Acceptance: fresh Persian desktop/narrow trees indent descendants inward from
the right by20px per level; English still indents from the left. Keyboard
collapse/expand preserves the correct children and indentation. Check the
shared table in Income Statement and direct Trial Balance, with a Balance
Sheet/Cash Flow smoke check. Use rendered geometry to verify direction; merely
asserting a style-property literal is insufficient. Run dashboard gates.

Statement, Balance Sheet and Cash Flow) and `trial-balance-content.tsx:301`.

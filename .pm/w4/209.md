# Gate Net Worth view controls until client navigation can handle input

Severity: **minor**, dashboard. Estimate: **35–50 minutes**. A2 — a reader should not receive an enabled view control that silently drops its first activation.

## Reproduce

Production `https://beancount.io`, 2026-10-09, authenticated read-only QA of public synthetic `open_ledger/crypto-example`, English/System, owned isolated headless Chromium **149.0.7827.55**. Current main **6783733b** retains the cause; exact deployed SHA is unverified. The latest pull changed only unrelated w2 board records.

1. Open `/ledger/open_ledger/crypto-example?lang=en` in a fresh context. Wait until **Show table** is visible, then focus it and press **Enter**, or activate it with an ordinary pointer click. No script/API request is delayed or intercepted, and no forced click is used.
2. The enabled control receives a trusted native click, but stays `aria-pressed="false"`, the URL has no `view` parameter, and no twelve-period table appears.
3. Observe when the rendered button acquires its React `onClick` property. Wait another **600 ms** without activating anything. The original action still has not taken effect: chart remains selected and `view` is absent.
4. Activate the same control again. It immediately changes to `?view=table`, pressed true, and the table appears. The settled table's dates, amounts, keyboard scrolling and reload behavior passed the preceding independent QA sweep.

Two rounds of four fresh contexts cover **1440×1000 and 390×844**, keyboard and pointer independently. All eight early actions arrived before the client handler existed; the repeat round explicitly checks the unchanged state after attachment and before retry. Its trusted clicks occurred at **9,730 / 3,708 / 10,273 / 5,897 ms** after navigation start, with handlers observed at **12,611 / 8,683 / 14,164 / 9,752 ms**, respectively. These are observed runs, not promised latency or a performance benchmark. The DOM-presence-to-handler interval is not a paint timestamp; actions were issued only after Playwright's visible-control check.

A further fresh narrow keyboard control records the same lost action, no browser console/page errors, an unchanged view after handler attachment, and successful retry. Its screenshot shows the focused table control while chart remains selected. The cached/server-rendered primary overview supplies no browser `GetLedgerOverview` response in that control, so this does not claim a captured API failure or operation status. No transaction, credential or server data was changed.

## Cause and bounded repair

`dashboard/src/features/reports/overview/components/net-worth-card.tsx:361–383` server-renders both view buttons as enabled, with no readiness gate. Show table relies solely on `onClick={() => setView("table")}`. `common/hooks/use-url-view.ts:25–38` then invokes client router navigation; the button has no native navigation fallback before JavaScript binds. The live trusted-event and attached-handler observations distinguish this from a missing key event or a permanently broken table.

Make this small view-control group honestly unavailable until its client handler is ready, using the existing hydration mechanism, and enable it after hydration. Keep the existing SSR-selected view and readable balances/table content; do not replace the entire card with a spinner or add a timer. Preserve both controls' names, pressed states, keyboard/pointer behavior, URL replacement, supported direct bookmarks and reload state. The chart control has the same source omission, but its early activation was not separately exercised. Do not change global Button behavior or redesign every SSR interaction.

Acceptance: a real server-rendered card with deferred client initialization exposes disabled view controls; early keyboard/pointer input cannot be advertised as accepted and then lost. After hydration, normal Enter, Space and pointer activation changes the view and URL; table/chart bookmarks still server-render their selected content, and reload remains correct. Add a meaningful hydration/component regression plus a browser check of the enabled transition and actual activation, not a class-name assertion. Run dashboard format/lint, tests and build when implementing. No API, dependency, translation or cross-package change is needed.

NetWorthCard has one application caller, `features/reports/overview/index.tsx`; index overview and the `/overview` redirect reuse it. Other controls' readiness and other browser engines remain unverified. The view buttons date to **af5339de**; **a0940b82** moved their state into the URL, and **be8e9eba / 658110f7** retain the enabled initial render.

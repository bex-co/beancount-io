# Preserve typed filters while suggestions refresh

**Minor · dashboard · 45–60m · A2.** A successful background entry completion refreshes header suggestions and erases an already-focused, uncommitted Time filter. The header and narrow filter panel remain open, but the input is replaced with an empty one and subsequent typing misses it.

## Reproduction and controls

Production dashboard,2026-10-25 UTC; owned isolated headless Chromium156.0.8078.47, English/light/UTC, synthetic-ledger owner. Fresh390×844 and1440×1000 journeys repeat. Metadata, suggestion reads, navigation and controls are genuine. One Note submission is held before transport and given a **browser-local success acknowledgement**; nothing is booked on the server.

1. Journal → New Entry → Note. Choose existing Assets:Cash, enter prefixed text A and activate Create Note Entry. Hold the one BulkEntries request before transport. The Note field correctly becomes disabled.
2. Use browser Back and wait for the actual dialog exit. This deliberately closes the old draft; no loss on that departure is claimed.
3. Focus the header Time input, or open Filters at390 and use Time there. Enter `2026-10` without Enter or blur. Its actual value is complete and focused; the applied URL intentionally has no Time filter.
4. Release the held operation with the local success acknowledgement. The real GetLedgerAttributes count goes1→2. Three filter skeletons appear, the original Time input disconnects, then a new Time input appears empty. The header remains the same connected node; the narrow sheet also remains the same connected, visible node.
5. After2.5s, the field is still empty and unfocused. A native `1` key without refocusing reaches BODY at desktop or the enclosing dialog at390 and does not reach Time. No explicit filter reset, scope change or replacement text was requested.
6. Explicitly refocusing Time, re-entering the same month and using native Tab works: the field retains `2026-10` and the URL receives exact `time=2026-10` at both widths.

Two fresh failure controls follow the identical pending-Note/Back/filter-draft journey but abort the old request before transport. GetLedgerAttributes stays at one read; the same Time node, exact text and focus remain throughout the2.5s observation at both widths. The earlier completion's cache refresh, rather than Back or ordinary typing, distinguishes the failure.

Separate working controls preserve a newer New Entry draft through the same old acknowledgement. This finding concerns the header's own fields. The before/after narrow screenshots were inspected; their success toast is the modeled acknowledgement, not evidence of a hosted booking.

## Cause and bounded repair

NewDirectiveDialog's success handler in `dashboard/src/features/journal/components/new-directive-dialog/index.tsx` refreshes the cache. `common/hooks/use-apollo-cache.ts` evicts ROOT_QUERY. The observed genuine suggestion reread makes LedgerSearchControls loading again.

`common/components/ledger-search-controls/index.tsx:117–130` returns three Skeletons for every `loading` state, replacing its controls even after they have accepted input. `common/components/ui/combobox.tsx:65` owns the uncommitted text in component state. Removing that instance removes its draft and caret; the later instance starts from the unchanged applied router value, which is empty. The retained header/sheet nodes and observed skeletons isolate this local replacement from a whole-layout remount or delayed prop echo.

Keep already-rendered manual controls and their input identities/drafts through a same-ledger suggestions refresh. Preserve truthful loading feedback, fresh healthy options and the existing empty-options/manual-entry fallback on a failed read. Keep legitimate cache invalidation after writes. Do not work around it by suppressing refresh, committing the draft automatically, retaining failed/stale suggestions, or adding a global/persistent draft store. Initial loading/no-data handling, deliberate Clear all/Back/Forward resets and ledger isolation must remain correct. No API or dependency change is needed.

Acceptance: use the real filter owner/provider and Apollo cache boundary. With a focused uncommitted Time draft, evict/refetch its attributes and resolve healthy metadata; the same input retains exact text/caret/focus, the URL stays uncommitted, and an explicit Enter/blur applies it once. Cover inline and actual Sheet layouts, failed refresh, option recovery, ordinary commits, deliberate reset/history and ledger switch. Run dashboard gates when implementing. QA authored no product fix or formal regression test.

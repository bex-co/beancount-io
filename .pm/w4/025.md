# Seven dead GraphQL operations and a 19-case test for a hook that doesn't exist, all invisible to `lint:deadcode`

**Severity:** minor — no user-facing defect. **Estimate:** likely **over an hour across several independent pieces**; consider `/pm promote` to a milestone rather than treating this as one sitting. Owner: mobile. A2: root `CLAUDE.md` advertises `lint:deadcode` as detecting "unused files, exports, and exported types", and an agent trusting that gate is told this tree is clean when it is not.

Environment: branch `main`, HEAD `038faeeb`. Verified by static analysis over the repository plus `yarn lint:deadcode` (**passes clean, 1.06s, zero findings**) and `yarn test:unit` (**1769 passed**).

## 1 — Seven GraphQL operations with no consumer

Every `.graphql` document under `src/common/graphql/queries/` was matched against every reference to its generated hooks (`use<Name>Query` / `LazyQuery` / `SuspenseQuery` / `Mutation`) and its `<Name>Document`, outside `src/generated-graphql/`. Seven have **zero** references anywhere in `src/` or `app/`:

| operation | file | corroborating evidence |
| --- | --- | --- |
| `SubscriptionStatus` | `subscriptionStatus.graphql` | no screen in `src/screens/` mentions subscription or billing |
| `CreateSubscriptionSession` | `createSubscriptionSession.graphql` | ditto |
| `CancelSubscription` | `cancelSubscription.graphql` | ditto |
| `GetAiCfoUsage` | `getAiCfoUsage.graphql` | — |
| `InsertReceiptTransaction` | `insertReceiptTransaction.graphql` | `src/screens/receipt-capture-screen/` never references it |
| `JournalEntries` | `journalEntries.graphql` | takes no `$ledgerId` — pre-multi-ledger, superseded by `getLedgerJournal` |
| `UserProfile` | `userProfile.graphql` | `emailReportStatus` has **zero** non-test references; Settings shows no Email Report control |

`JournalEntries` alone generates ~20 exported symbols in `graphql.tsx` (the document, five hooks, and the query/variables types).

**Check intent before deleting.** No open `.pm` item covers billing, subscriptions, receipt insertion or AI-CFO usage on mobile, so nothing on the board is staged behind these — but absence from the board is not proof that nobody is holding them. Confirm with the owner, then delete the `.graphql` sources and re-run `yarn codegen`; **never hand-edit `src/generated-graphql/`** (root `CLAUDE.md`).

## 2 — A 253-line test file for a hook that was deleted

`src/screens/setting/hooks/` contains **only** `__tests__/`. The hook the directory existed for — `use-user-profile.ts` — is gone, and `use-user-profile.test.ts` outlived it.

The file imports nothing. It declares its own `UserProfileQueryData` interface and its own `extractUserProfileData` helper, commented "mirrors hook implementation", then asserts against them. **19 `it` cases**, several of which test the language rather than the app:

```ts
it("should accept valid userId", () => {
  const userId = "user-123";
  const variables = { userId };
  expect(variables.userId).toBe("user-123");
});
```

These cases are part of the 1769 the suite reports as passing. They cannot fail and never have. `.agents/skills/pm/SKILL.md` already names this shape as the thing to avoid — "never game coverage with trivial, tautological, or snapshot-everything tests" — so removing the directory needs no new policy.

Related: `src/translations/__tests__/index.test.ts:261-266` pins `en.subscribe === "Email Report"`, `en.off`, `en.weekly`, `en.monthly` for that same removed feature, so the test now actively **prevents** the dead strings from being cleaned up. Remove the keys and that case together.

## 2b — A live module kept alive only by its own test, holding a second answer to a question already answered (added September 14)

§2 is a test that outlived its subject. This is the mirror image: a **subject that outlived its callers**, propped up by its test. Same blind spot, and it needs saying separately because deleting it is a judgement call rather than housekeeping.

`src/screens/home-screen/selectors/select-transaction-amount.ts` exports two functions. Neither has a single production reference:

| export | referenced by |
| --- | --- |
| `getSignedTransactionAmount` | `__tests__/select-transaction-amount.test.ts` only — 8 assertions |
| `formatSignedAmount` | the same file only — 3 assertions |

`grep -rn "getSignedTransactionAmount\|formatSignedAmount\|select-transaction-amount" src/ app/` returns nothing outside that test. 11 of the suite's 1769 are inert.

**Why it is not merely dead.** The module is a *second, divergent implementation* of the app's most load-bearing display decision — which single number to show for a transaction — and the live one sits two directories away at `src/screens/transactions-screen/utils/transaction-display-utils.ts:86` (`selectTransactionAmount`, consumed by `entry-row/index.tsx:103` on four surfaces and by `transaction-detail-screen`). The two disagree on the hard part:

| | dead `getSignedTransactionAmount` | live `selectTransactionAmount` |
| --- | --- | --- |
| multi-currency postings | filters to one currency and sums | buckets **by** currency and never sums across, with the reasoning written out: *"a fund purchase pairs `-3,177.39 USD` with `+355.63 RGAGX`, and adding those produces a number that means nothing"* |
| which bucket wins | n/a | prefers the currency a posting quotes cost/price in, else the largest magnitude |
| decimal scale | none | tracks the widest scale any leg recorded |

So the dead one is the naive one. It is a live hazard precisely because it looks finished and is green: someone wiring up a Home-screen amount would reasonably reach for the file named `home-screen/selectors/select-transaction-amount.ts`.

**Its test also pins a formatting convention the app rejects.** `select-transaction-amount.test.ts:95` asserts `formatSignedAmount(1000, "$") === "+$1000.00"` — no thousands separator — while `formatSignedMoneyWithCurrency` gives `+$1,000.00`, and `formatSignedAmount` takes a *symbol* rather than a currency code, so a symbol-less commodity (MUSD, VACHR, STETH) would render as a bare unlabelled number. That is the same defect `w4/060` files against the chart axes, frozen here by an assertion instead. Same shape as `w4/024`'s wrong-expectation problem.

**Do not revive it as a fix for `w4/004`.** It buckets Assets and Liabilities into one total exactly as the live selector does, so a cash→cash transfer nets to zero there too. It shares the bug and lacks the currency handling.

**The inventory is complete: this is the only instance.** Every non-test module under `src/` and `app/` was matched against every reference to its basename across the tree; exactly two modules have importers that are *all* test files. The other, `src/scripts/play-release.ts`, is a **false positive** — `scripts/play-release.sh:5` invokes it with `npx tsx`, which is a real entry point that no import graph can see. So there is one genuine case, and the cleanup is bounded.

## 3 — Why no gate catches any of this

Two independent blind spots, both currently justified by their own comments:

- `knip.jsonc:13-16` sets `"ignoreIssues": { "src/generated-graphql/**": ["exports", "types"] }` because "GraphQL Code Generator owns this public generated API." Correct in itself — you must not chase knip findings by editing generated output. The consequence is that the generated hooks of an unused operation are exempt, and knip does not parse `.graphql` files at all, so the *source* document is invisible too.
- `knip.jsonc:7` lists `src/**/*.test.{ts,tsx}` as an **entry point**, so a test file is never reported as unused — which is what a test runner needs, and what lets an orphaned test directory survive its subject.

## Fix

1. Confirm intent on the seven operations, delete the unneeded `.graphql` sources, re-run `yarn codegen`, and verify `yarn test` still passes.
2. Delete `src/screens/setting/hooks/` entirely, plus the Email Report translation keys and the test case pinning them.
3. Close the gate so this cannot silently recur: add a check that every `.graphql` operation document has at least one reference to its generated hook or `Document` export outside `src/generated-graphql/`. The detection script in this note is ~10 lines of shell and could live beside the existing checks; wire it into `yarn lint:deadcode` so the advertised gate means what root `CLAUDE.md` says it means.

4. Delete `src/screens/home-screen/selectors/select-transaction-amount.ts` and its test (§2b), after confirming with the owner that no Home-screen amount work is staged behind it. If something *is* staged, the right move is to delete it anyway and use the live `selectTransactionAmount` — keeping a naive duplicate of the app's central display decision is the hazard, not the deletion.
5. Close the *second* gate too. Step 3's check is GraphQL-specific and would not have caught §2b: a `.ts` module whose only importers are test files is invisible to knip for the same reason an orphan test is — `knip.jsonc:7` makes tests entry points. Add a companion check that reports any non-test module under `src/` whose importers are all tests, with an allowlist for CLI-invoked scripts (`src/scripts/play-release.ts` is the one legitimate case today, reached through `scripts/play-release.sh`). It is the same ~10 lines of analysis.

Do **not** address this by removing the `ignoreIssues` entry or the test-entry glob — both are correct, and dropping either would flood the gate with findings you must not act on. The two added checks sit beside knip rather than reconfiguring it.

**Acceptance:** no `.graphql` operation document lacks a consumer; `src/screens/setting/hooks/` and `src/screens/home-screen/selectors/select-transaction-amount.ts` no longer exist; `yarn lint:deadcode` fails when an unused operation document is added **and** when a module importable only from tests is added, and passes once each is removed, with `src/scripts/play-release.ts` still passing; `yarn test` and the unit count stay green with the tautological cases gone (the count will drop by 19 plus one from §2, and by 11 more from §2b — which is the point).

## Objective

Route the initial URL and runtime `Linking` events through the resolver, select the target ledger with the safe-open path from w4/m4, and keep the target across the welcome and sign-in flow for a signed-out user.

## Context

- `app/_layout.tsx` and `app/(app)/_layout.tsx` own providers and the signed-out redirect; `app/oauth/callback.tsx` must keep receiving its own URLs untouched.
- w4/m4 shipped the safe-open path for discovered ledgers (`src/screens/ledger-selection/use-discovery.ts` and the permission handling); reuse it so a public ledger opens read-only and a ledger the account cannot read falls back to opening the URL in the browser.
- A pending link target must survive the OAuth round trip: store it in memory or `expo-secure-store`-free storage, consume it once after sign-in.

## Steps

1. Add an app-link handler hook mounted in the root layout that ignores OAuth callback URLs and feeds everything else to the resolver.
2. On a resolvable link: select the ledger via the safe-open path, then `router.push` the href; on failure open the URL with `Linking.openURL` and keep the current ledger.
3. Persist a pending target while signed out and replay it once after the session exists.
4. Verify with `xcrun simctl openurl <udid> "https://beancount.io/ledger/open_ledger/example/balance-sheet"` on the rebuilt development client, signed in and signed out.

## Files

- mobile/app/_layout.tsx
- mobile/app/(app)/_layout.tsx

## Acceptance criteria

- [ ] An https ledger link opens the matching native screen while signed in.
- [ ] The same link tapped while signed out lands on that screen after sign-in.
- [ ] A private ledger the account cannot read opens in the browser and the current selection is unchanged.
- [ ] OAuth callbacks are unaffected; light and dark screenshots recorded.

## Out of scope

- Universal-link verification on a physical device (recorded after the next store build in Closeout).

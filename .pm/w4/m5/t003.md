## Objective

Write a pure function that maps a dashboard ledger URL to an Expo Router href plus the ledger it targets, so link handling has one testable core.

## Context

- Dashboard routes to cover: `/ledger/$owner/$name` (and `/overview`), `/account/$accountName`, `/journal`, `/commit/$sha`, `/files/blob/$branch/$path`, `/income-statement`, `/balance-sheet`, `/budget`.
- Mobile targets: Home, `account-detail`, `transactions`, `commit-detail`, `ledger-file-editor`, `reports`, `budget`; unknown ledger sub-paths fall back to Home.
- Ledger identity is `owner/name`; the resolver returns the ledger full name and the href, never touching state itself.
- Non-ledger URLs (gallery, settings, auth) are not claimed by the resolver and open in the browser.

## Steps

1. Create `src/common/app-links/resolve-app-link.ts` with a path table and a `resolveAppLink(url): { ledgerFullName, href } | null` function.
2. Reject hosts other than the selected server's host and the hosted domain.
3. Unit-test every table row, trailing slashes, query strings, encoded account names, and unknown paths.

## Files

- mobile/src/common/app-links/resolve-app-link.ts
- mobile/src/common/app-links/__tests__/resolve-app-link.test.ts

## Acceptance criteria

- [ ] Each documented path resolves to the intended href with the correct params.
- [ ] Unknown sub-paths resolve to the ledger Home; non-ledger and foreign-host URLs return `null`.
- [ ] `yarn typecheck` and `yarn test:unit` pass.

## Out of scope

- Navigation side effects; ledger selection; permission checks.

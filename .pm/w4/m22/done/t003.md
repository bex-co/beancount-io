## Objective

Verify anonymous source/entry reading and existing editor affordances; inspect relevant package guidance for drift.

See [FINDINGS.md](./FINDINGS.md) for evidence, source and limits.

## Acceptance criteria

- [x] Readers can identify read-only content and still select, find, copy and navigate back.
- [x] No unrelated guidance changes, new dependencies or permissions changes; preserve source line and Journalpage2 Back controls.

## Outcome

**Readers can identify read-only content.** 20/20 state checks across the two
public reader journeys — file source and journal Entry Context — in both
supported input modes at 1440x1000 and 390x844, all reporting native AX
`readonly=true` where they previously reported `false`, with every Monaco model
byte-identical after a typed key.

**And they can still work with it.** 9/9 affordance checks, all of which
FINDINGS asked to preserve:

- **Selection** — `Cmd+A` selects the whole 318,015-character model.
- **Find** — `Cmd+F` opens the widget and `2017-09-07` reports **1 of 1**, the
  exact match FINDINGS recorded.
- **Escape** — closes Find and returns focus to `Editor content`.
- **Read-only state survives the interaction** — `aria-readonly` is still
  `true` after clicking, selecting, finding and escaping, which is the check
  that would catch Monaco re-rendering its input surface and dropping the
  attribute.
- **The Journal round trip** — from journal `offset=60`, the Entry Context
  panel's `main.bean:595` location opens
  `files/blob/main/main.bean?lineNumber=595`, and Back returns to
  `offset=60`. (My pagination-text capture came back empty on both sides, so
  the URL is what this assertion rests on; the offset is the thing FINDINGS
  named.)

**No guidance drifted and none was added.** There is no `AGENTS.md` owning
`common/` or `ledger-editor/` — only `importer/`, `ledger-data/` and
`reports/` have one — and inventing a file for this would be the unrelated
guidance change this task rules out. The contract is documented where a reader
of the code meets it: the doc comments on `syncReadOnlyState` and
`withDomReadOnly` in the shared wrapper. `dashboard/README.md`'s "Readers stay
read-only; writers keep the same edit/delete" remains accurate, and more so.

No dependency was added and no permission changed: the repair sets one ARIA
attribute and defaults one Monaco option. The public BQL editor still reports
`readonly=false` and accepts typing, so nothing writable was frozen.

Not claimed: no screen reader was exercised; Chromium only, with emulated
viewports; authenticated editing was not tested.

# `docs/mcp.md` still advertises removed `beancount://legacy/...` resources and stale inventory counts

**Severity:** minor. **Estimate:** 20–30 minutes. **Owner:** backend-v2 docs.
**A1/A2:** this is the customer contract for the MCP surface; an agent or
integrator that reads it is sent to three resource URIs that no longer exist
and told the server has 24 tools and 66 templates when HEAD serves 26 and 64.

Found 2026-09-15 by MCP QA against `main`, HEAD `fbdffde8`, comparing the
document with `resources/templates/list` and `tools/list` from the real
registry over the SDK's in-memory transport, and with `git` history.

## Repro

```sh
cd backend-cluster/backend-v2
grep -n "beancount://legacy\|24 tools and 66" docs/mcp.md
#  10: It covers 24 tools and 66 resource templates.
# 330: `beancount://legacy/ledgers/{ledgerId}/archive/{archive}`
# 511: `beancount://legacy/ledger-meta{?userId,ledgerId}` and
# 519: Legacy `journalEntries` is available at `beancount://legacy/journal-entries`
grep -c "beancount://legacy" src/features/ai-agent/api/mcp-resources.ts   # 0
grep -c '^    name: "' src/features/ai-agent/api/mcp-tools.ts               # 26
```

`resources/templates/list` at HEAD returns 64 templates, none under
`beancount://legacy/`; `tools/list` returns 26 tools.

## Expected

The document describes the implementation in this repository (its own
opening paragraph). Removed resources are not described as "available", the
archive resource is `beancount://{owner}/{name}/archive/{archive}`, and the
inventory line matches HEAD or is dropped in favour of "use `tools/list`".

## Actual

The three legacy URIs were removed in `b6bbd37e` (w2/m27, 2026-09-09) together
with `addLegacyEntries`, and `checkLedger` / `getLedgerContext` were added
the same day. The document was edited twice afterwards (`489a2947` on
2026-09-11, `18413b29` on 2026-09-15) without refreshing lines 10, 330, 511
and 519; the "Legacy transaction insertion" section correctly says the tool
left MCP but then points readers at the removed resources.

## Also stale: the `resources/list` paragraph (added 2026-09-15, same sweep)

Lines 433–434 say "This server does not enumerate instances with
`resources/list`; an empty result there does not mean resources are
unavailable." Since `b6bbd37e` (w2/m27) `assembleMcpRegistry` registers a list
callback for every template with a `listSegment` and for the file template,
backed by `listLedgerResources` in `mcp-resources.ts`. Driving the real
registry in-process with a pinned credential and two source files,
`resources/list` returns 9 instances: `source-files`,
`statements/income-statement`, `statements/balance-sheet`, `accounts`,
`metadata`, `payees`, `errors`, and `files/main.bean`,
`files/2026/september.bean`. Rewrite the paragraph to say listing returns the
credential's ledgers' static reads plus up to the capped number of source
files, and that templates remain the complete inventory.

## Fix

Rewrite the legacy paragraphs to name only the REST twins
(`GET /api-gateway/v1/legacy/ledger-meta`, `.../legacy/journal-entries`) and
the current archive URI; replace the hard-coded counts with the review date
plus the discovery instruction, or refresh them to 26 and 64. Optionally add
a small test beside `mcp-prompt-list.test.ts` that fails when `docs/mcp.md`
cites a `beancount://` template that is not registered, mirroring the check
prompts already get.

# CSV decimal-comma amounts with one or four fractional digits are multiplied silently

Severity: **major**. Package: **cli**. Estimate: **45–60m**. Source: continuous
CLI QA for w4. **A1/A2:** the documented CSV import must preserve an amount's
value regardless of the number of decimal places in an export.

Environment: 2026-09-21, main `390568c220bfbdb0df1c9decb8436c64dfa3c9ca`,
checkout `cli/.venv/bin/bea` 0.3.0, Python 3.13.3, Darwin arm64.
All commands ran as fresh subprocesses under isolated
`cli/tmp/qa-20260921-cli-loop/`, with absolute ledger paths, closed stdin
(except the explicitly piped JSON), captured stdout/stderr, and 25-second
limits. Child-only `BEA_CONFIG_DIR`, `XDG_CACHE_HOME`, and `XDG_DATA_HOME`
pointed inside that directory; `BEA_NO_UPDATE_NOTIFIER=1`; inherited
`BEA_FILE` and `BEA_TOKEN` were removed. No hosted account was used.

## Reproducer and observed result

Use this disposable `main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Food USD
```

`bank.csv`:

```csv
Date;Description;Amount
2024-03-01;Purchase;-0,5
```

With absolute paths substituted:

```sh
bea --json --file main.bean import bank.csv --csv auto   --account Assets:Cash --default-account Expenses:Food
bea --json --file main.bean import bank.csv --csv auto   --account Assets:Cash --default-account Expenses:Food --apply
bea --json --file main.bean query "SELECT number WHERE account = 'Assets:Cash'"
bea --json --file main.bean check
```

All exit 0. Preview reports `-5 USD`, apply writes it, and fresh query returns
`rows: [["-5"]]`; the ledger checks valid. JSON stderr is empty. Human preview
also shows `-5 USD` without a decimal-convention warning. Resetting the fixture
and using `-0,1234` writes `-1234 USD`, a 10,000-fold change from `-0.1234`.
Controls: `-0,50` correctly writes `-0.50`; the correctly quoted US grouped
amount `"-1,234.56"` correctly writes `-1234.56`. Each candidate and control
was exercised twice from pristine ledgers, with a third minimal one-digit repro.
Preview preserves bytes; apply appends balanced postings with the wrong magnitude.
A repeat apply then deduplicates those incorrect postings.

Expected: preserve `-0.5` and `-0.1234` exactly under the documented comma-decimal
support (`cli/docs/IMPORTING.md`, amount grammar), or refuse an unresolved
convention with a corrective message. A comma followed by one/four digits is
not a valid three-digit thousands group; deleting it cannot be a safe fallback.

## Cause, scope, and repair

`cli/src/bea_engine/csv_mapper.py:33,79–85` recognizes a comma-only decimal vote
only when exactly two digits follow it. `_resolve_decimal_comma:88–122` then
falls back to point-decimal mode, and `_parse_amount_cell:169–172` removes every
comma without validating grouping. No quote, delimiter, or precision is lost
in the CSV reader; the error is the amount parser.

Resolve the column convention without assuming currency precision is two,
validate grouping before stripping separators, and reject genuinely ambiguous
or conflicting conventions explicitly. Preserve Decimal precision. Reuse the
existing importer; do not add a parallel parser or dependency.

Caller search: `_parse_amount_cell` is reached through `CsvImporter._parse_decimal`,
used by amount and debit/credit extraction. Preview and apply share it, as do
automatic/explicit/remembered mappings. No frontend amount parser or backend
surface needs to change for this bounded repair.

- [ ] These one- and four-digit comma-decimal fixtures retain their exact
      value through preview, apply, fresh BQL and check; rejected inputs never write.
- [ ] Two-digit comma decimals and properly grouped US/EU controls remain
      correct; malformed grouping and mixed conventions cannot change magnitude silently.
- [ ] Exercise amount and debit/credit entry paths in meaningful parser/CLI
      regressions, then run CLI gates when fixing.

Dedupe: all queues/open milestones and done/blocked history searched for comma
precision, separator voting and decimal-comma parsing. This is a residual
correctness gap in completed w1/m24/t003 and w3/256, whose full DoD and existing
amount-spelling controls were reviewed. The original two-decimal fixtures still
work. `git log -S _COMMA_DECIMAL_TAIL` traces the current implementation to
`7a42704a` and its engine copy in `a90b1706`; no later fix or open duplicate.

Evidence: verified `cli/tmp/qa-20260921-cli-loop/captures/cycle2-*decimal-*.json`,
`minimal-decimal-*.json`, and corresponding fixtures. Separate stderr/stdout,
exact arguments and before/after hashes are retained; public repro is complete above.
Unverified: other OSes, other locales and arbitrary ambiguous three-digit inputs.
No product fix or shipping; no credentials or hosted resources were created.

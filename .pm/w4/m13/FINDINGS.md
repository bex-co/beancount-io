# Journal shared-filter changes retain the previous page after pending-layout unmount

Severity: minor. Package: dashboard. Estimate: 50m including a real layout/router regression. Source: repeated dashboard QA requested for w4, 2026-09-17. A2: newcomers filtering the example journal should see the start of the matching transactions.

Environment: production https://beancount.io, anonymous public synthetic ledger `open_ledger/example`, QA-owned headless isolated Chromium 131, English/light, 1440×1000 and 390×844. Local clean main at `26d54a9db7d33c31a549bd12a0454a1c01f3f038`. Deployed main asset is `main-BIr0jJni.js`; exact deployed commit is unverified and local build asset differs. The deployed `ledger._ledgerOwner._ledgerName.journal-yO7XnS4z.js` contains the same filter-key/useState/reset-effect implementation described below.

Reproduction:
1. Open `/ledger/open_ledger/example/journal`, click Next. URL becomes `?offset=60`, Results 61–120 / 1044.
2. Select 2016 in Time. At narrow width first open Filters, then select 2016 and close Report filters.
3. Settled URL is `?offset=60&time=2016`; Results remains 61–120 / 393, first transaction 2016-11-03 RiverBank Properties. Reload retains that incorrect starting page. Repeated from a fresh load with `?offset=60` by typing 2016 + Enter, and again through the narrow sheet.

API returns total 393 and the November first row. Browser fetch control with the same query and offset 0 returns HTTP 200, total 393, first date 2016-12-31, hash `4b604180cd10559b772ca7af10b98ffa`. No page errors. Verified local artifacts: `dashboard/tmp/qa-20260917/journal-time-offset.json`, `journal-time-offset.png`, `journal-time-offset-narrow.png`. Public text reproduction and response summaries above stand independently of ignored artifacts.

Root mechanism: `dashboard/src/common/components/ledger-layout/index.tsx:40,113` replaces Outlet while router `isLoading`; journal-page.tsx:140 initializes `appliedFilterKey` from the newly mounted filter. Its reset effect at 158 therefore sees equality and retains URL offset. Shared filter updater `common/lib/ledger-search-params/parse.ts:83` deliberately spreads the previous search, including offset. Installed TanStack router-core/src/router.ts:2370 sets isLoading when ingesting navigation matches. The source mechanism is consistent with the observed missing offset-0 request; component lifetime was not instrumented in production.

Fix: reset journal pagination atomically with a genuine change to shared time/account/expression filters, in state that survives the pending outlet replacement. Preserve direct-link/reload/drill-down page restoration and the honest pending UI introduced for stale-report protection. Do not reset pagination on every mount or remove the pending safeguard. Dashboard-only; API already honors the submitted offset.

Blast radius: shared updater is used through LedgerSearchParamsProvider for time/account/filter and clearing filters; journal consumes all three in its filter identity. This report verifies time changes only. Journal route `routes/ledger.$ledgerOwner.$ledgerName.journal.tsx` renders the page; other report/account pages share the layout but their pagination behavior is not claimed reproduced. Working controls: Next changes rows and URL; explicit page reload preserves offset; offset-0 API returns the correct first page. Directive-filter reset is covered by the existing unit test, which does not mount the real pending layout.

Acceptance: desktop and narrow steps above start at result 1 after the year change; integration coverage mounts the actual layout/router and verifies the requested offset, including a shared account/expression change and Clear all. Preserve explicit offset reload and journal→account→Back behavior from w3/done/131. Keep pending results inaccessible until coherent data settles. Empty, denied, expired-session and network-failure behavior must remain truthful; these states were not exercised in this finding. Run dashboard's native gates when implementing.

## Accounts search loses focus after the first typed character

1. Open `https://beancount.io/ledger/open_ledger/example/accounts` and wait for the populated list.
2. Click Search accounts and type `Checking` normally (browser keyboard events, 180–200ms between keys).
3. The settled URL is `?search=C`, input value is `C`, document.activeElement is BODY, and 33 / 60 accounts remain. The remaining letters do not reach the input. No pointer movement or deliberate blur occurred.

Expected: the input retains focus/caret, accepts all eight characters, and shows the single Checking account. Actual: the first URL update interrupts ordinary typing. Pasting/filling the entire word at once does find the correct account, which masked this in the initial sweep. The full-field control yields 1 / 60 and navigates to the matching account; Back restores `?search=Checking`.

The source still contains both pieces, and the existing Accounts history regression tests do not include this real layout lifecycle. `4d701a91` added URL-backed local search; `05c78c69` added the unconditional pending outlet replacement later. No later source repair found.

Fix: keep the focused local-list controls mounted across local search/type URL updates, and preserve focus/caret and successive input events. Preserve honest pending/export protection for report scope changes and ledger switches; do not simply delete the stale-data guard or focus every search box after every navigation.

# The same Catalan key-to-meaning shift is still live on five more report catalogs

Severity: major localized interface defect. Package: dashboard. Estimate: ~90m — five catalogs plus a guard, so this is a milestone candidate rather than a note if the audit confirms the full count.

w4/m14 repaired the Catalan shift where it was reproduced in the browser: the shared common catalog and the Journal catalog. The identical defect class — a key carrying the Catalan written for a neighbouring concept while its `description` stays correct — is still shipping on five other feature catalogs, all user-facing report pages that m14's live walk never visited.

Verified on `main` at `8850efc8` by comparing each Catalan entry against the English message for the same key:

- `dashboard/src/features/reports/trial-balance/locales/ca.ts` — `page.trialBalance.equityHierarchy` reads "Diari" (Journal). `assetsHierarchy`, `expensesHierarchy`, `incomeHierarchy` and `liabilitiesHierarchy` all hold their own `*Description` sentence or a net-worth-tracking sentence instead of a title. `noData` reads "No s'han trobat coincidències" (No matches found). `overviewDescription` is byte-identical to `overviewTitle`.
- `dashboard/src/features/reports/account/locales/ca.ts` — `changesOverTime` reads "Balanç de situació" (Balance sheet). `title` reads "Compte" (Account) rather than Account Report. `errorLoading` and `loading` hold composition sentences. `noData` holds a net-worth-tracking sentence. `noJournalEntries` and `noJournalEntriesForAccount` are swapped.
- `dashboard/src/features/reports/overview/locales/ca.ts` — `assetsDistribution` and `liabilitiesDistribution` hold currency-tracking sentences instead of titles. `failedToLoad` reads "Error en carregar les opcions de filtre" (Failed to load filter options). `loading` reads "Carregant comptes..." (Loading accounts).
- `dashboard/src/features/reports/locales/ca.ts` — `incomeVsExpenses` reads "Compte de resultats" (Income Statement); its `Description` holds the title text.
- `dashboard/src/features/reports/income-statement/locales/ca.ts` — `noData` reads "Dades no disponibles" (No Data Available) rather than the income-statement-specific message.
- `dashboard/src/features/ledger-editor/file-editor/locales/ca.ts` — `unsavedChanges` reads "Desplegar tot" (Unfold all); `unfoldAll` reads "Plegar tot" (Fold all), duplicating `foldAll`; the unsaved-changes title and message are shifted onto each other and onto `unsupportedFileFormat`.

Root cause is the same bulk localization pass that produced the m14 values; `git log -S` traces the wrong strings to `aeec496b`. The two locale scripts did not cause it and cannot detect it: `dashboard/scripts/prepare-translations.ts` copies by key, and both it and `flatten-translation-keys.ts` point at directories that do not exist (`src/common`, `src/common/locales`, `ledger-settings`) while omitting real ones, so they reach at most 14 of the 45 locale directories — none of which contain the entries above. Fixing or deleting those scripts is separate work; the guard belongs in the test, which already globs `features/**/locales/*.ts` recursively.

Cheapest available guard, measured: `dashboard/src/test/translations.test.ts:416` short-circuits with `if (enVars.length === 0) continue;`, so the cross-language interpolation check never notices a locale value carrying a placeholder the English lacks — exactly how a `{ledgerName}` description sentence lands on a title key. Removing that early exit and comparing placeholder sets over the union of keys flags 9 of these residuals with zero false positives across all 14 locales. That one line plus the repair is the whole fix; a length-ratio or neighbour-fit heuristic is only needed for the residuals with no placeholder on either side.

Scope note: m14 is closed correctly — its definition of done covers the navigation and Journal journeys, which were verified live at both widths. This is the same defect on different pages, recorded rather than folded into that milestone. `w4/083` owns other locales' partly untranslated strings and is not this. Catalan is still the only locale showing the misassignment; a sweep of all 14 non-English locales across all 15 catalog groups found no other.

Also worth one line while in here: `zh` renders `journal.pending` as "待处理" instead of the literal "!" flag, which the m14 regression test excludes by name as a pre-existing deviation.

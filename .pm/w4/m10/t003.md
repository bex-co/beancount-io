## Objective

Add the two community files GitHub's profile checker and most developers look for, with a private reporting channel for security issues so vulnerabilities never land in the public tracker or chat.

## Context

- No `SECURITY.md` or `CODE_OF_CONDUCT.md` exists at the root.
- GitHub's private vulnerability reporting is the cleanest channel; it is a repository setting the user must enable (`gh api -X PUT repos/bex-co/beancount-io/private-vulnerability-reporting` or the Settings page). Ask before flipping it; if not enabled, name a maintainer contact the user supplies, never a placeholder address.
- `CONTRIBUTING.md` "Never commit secrets" already describes the gitleaks gate; SECURITY.md should link it and add supported versions (hosted service, latest `cli-v*` release, latest `mobile-v*` release) and the disclosure timeline.
- Use Contributor Covenant 2.1 for the code of conduct with the same reporting contact.

## Steps

1. Confirm the reporting channel with the user and enable private vulnerability reporting if approved.
2. Write `SECURITY.md`: how to report, what to include, response timeline, supported versions, the gitleaks policy link.
3. Write `CODE_OF_CONDUCT.md` from Contributor Covenant 2.1 with the enforcement contact.
4. Link both from `CONTRIBUTING.md` and the root `README.md` "Contributing" section.

## Files

- `SECURITY.md` (new), `CODE_OF_CONDUCT.md` (new), `CONTRIBUTING.md`, `README.md`

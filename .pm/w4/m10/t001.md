## Objective

Add GitHub issue forms so every new issue arrives with the package, version, reproduction, and expected result the maintainers need, and route questions to the community chat instead of the tracker.

## Context

- `.github/` currently has no `ISSUE_TEMPLATE/` directory.
- Packages to offer in a dropdown: `dashboard`, `mobile`, `cli`, `skills`, `backend-cluster`, `deploy`, `docs`, `other`.
- Version fields differ per package: `bea --version` for the CLI, the app version from Settings for mobile, the commit for the dashboard and backend; say so in the field description.
- Root `README.md` "Quality bar" table is the canonical list of package checks; link it.
- `config.yml` should disable blank issues and offer contact links to the Telegram chat and, once t003 lands, the security policy.

## Steps

1. Create `.github/ISSUE_TEMPLATE/bug.yml`, `feature.yml`, `skill-request.yml`, `self-host.yml` with `labels:` auto-applied (`bug`, `enhancement`, `skills`, `self-host`; create the two missing labels through `gh label create`).
2. Create `.github/ISSUE_TEMPLATE/config.yml` with `blank_issues_enabled: false` and the contact links.
3. Open a draft issue on a fork or with `gh issue create --web` to confirm the forms render; do not file test issues on the public tracker.

## Files

- `.github/ISSUE_TEMPLATE/bug.yml`, `feature.yml`, `skill-request.yml`, `self-host.yml`, `config.yml`

## Acceptance criteria

- [ ] "New issue" shows the four forms and the contact links; blank issues are disabled.
- [ ] Each form has package, version or commit, and a required description; bug has reproduction, expected, and logs.
- [ ] Forms pass GitHub's YAML schema (rendering without an error banner).

## Out of scope

- Discussions categories (a repository setting for the user).

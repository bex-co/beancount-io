# Preserve early Gallery input or keep search disabled until it can handle typing

Severity: **minor**, dashboard. Estimate: **35–50 minutes**. A2 — a newcomer’s first ledger lookup should run, rather than leave an apparently filled search field doing nothing.

Production `https://beancount.io/ledger-gallery?lang=en`, 2026-10-09, dedicated QA session, owned isolated headless Chromium 149.0.7827.55. Fresh 1440×1000 and 390×844 contexts, repeated once at each width. Main **dd709484** retains the cause; the latest pull changed board records only. Exact deployed SHA is unverified.

## Reproduce

1. On a fresh page, wait for the actual visible combobox, focus it and type `adyen` through the browser keyboard at 20ms per character. Do not delay application scripts or API requests, force events, invoke handlers, or change the DOM’s disabled state.
2. At typing time, an observational DOM check finds no attached React `onChange` handler. In both retained fresh repeats, all five native input events are trusted and their values progress from `a` to `adyen`.
3. Five seconds later, the input remains enabled and visibly contains `adyen`, but its attached React props still hold an empty value. There have been **zero SearchLedgers requests** and there are **zero options**. The narrow screenshot was visually inspected. This is not an empty search result or an API failure: no lookup was sent.
4. Wait for the real change handler to attach, select all and type the same `adyen` again with the same keyboard method. One SearchLedgers request runs and one result appears, in the same context without reloading or changing credentials. Both widths and both fresh rounds agree.

## Cause and bounded repair

`dashboard/src/features/ledger-list/pages/gallery-page/index.tsx` initializes `searchQuery` to an empty string. The enabled server-rendered Input only transfers text into that state through `handleInputChange`. The debounce and eligibility checks read that state, so text entered before the handler attaches remains in the browser field but never reaches the lookup. The Input has no readiness gate or mechanism to adopt those early edits.

Either preserve and submit the actual early input once initialization completes, or keep this local field disabled until it can accept input. Use actual readiness rather than a timer. Preserve the accessible name, ordinary editing, 300ms debounce, minimum-length rule, current-query result ownership, Escape/focus behavior and keyboard selection. Do not rewrite the global Input primitive, change API policy, add dependencies or delay the whole page to repair one control.

Acceptance: a real cold browser load with early native typing cannot leave enabled visible text without a lookup; a gated implementation must become usable and search normally when ready. Retyping must not be necessary, and no duplicate lookup or stale selection may result. Repeat desktop/narrow and add meaningful owning-component coverage around pre-readiness input and the transition to ready, then run dashboard gates when implementing.

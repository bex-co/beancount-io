## Objective

Add meaningful SSR/browser regressions that delay or disable hydration, intercept submissions before transmission, and assert password fields never enter a GET URL. Cover keyboard and button submission, hydrated validation, and shared hidden-username consumers. Use synthetic fixtures only.

## Outcome

11 committed cases in `native-submission.test.tsx`, asserting the **server**
output through `renderToString` — because the markup a reader holds while
scripts load or after they fail is exactly what the defect lived in. A hydrated
test could never have caught it.

Per form (login and registration):

- **never declares a GET form** — `method="post"` present, `method="get"`
  absent. React omits the attribute entirely when unset, and the native default
  is then GET, which is the defect.
- **renders its submit button disabled** — the attribute, in server output.
- **says why it cannot be used without scripts** — `<noscript>` with the
  notice.
- **still carries its password field** — so the other three are not vacuous if
  the form is ever restructured.

Plus three hydrated cases: the submit button enables, a filled submit reaches
the client handler with its values (so nothing is left to the browser), and an
empty submit stays on the page with validation errors.

Each guard proved load-bearing independently, which is what "tests fail against
the original native GET behavior" asks for:

| Reverted | Cases that fail |
| --- | --- |
| `method="post"` | 2 |
| the `<noscript>` notice | 2 |
| the hydration gate on the submit button | 2 |

**One of my own assertions was vacuous and is worth recording.** The disabled
check was `expect(submit).toContain("disabled")`, which passed even with the
hydration gate removed — the button's Tailwind classes include
`disabled:pointer-events-none` and `disabled:opacity-50`, so the substring was
always there. I only found it because the revert failed to fail. It now matches
the attribute (`/\sdisabled=""/`), and the revert fails as it should.

All fixtures are synthetic (`qa-fixture@example.invalid`,
`NotARealSecret-000`); nothing resembling a credential appears anywhere, and no
network call is made — the hydrated cases assert against a spy.

Gates from `dashboard/`: `yarn format:check`, `yarn lint`, `yarn test` (385
files, 4342 passed, 1 pre-existing skip) and `yarn build` all pass. `gitleaks`
reports no leaks in `dashboard/src`.

The browser-level evidence — JavaScript disabled, navigation intercepted before
transmission, click and Enter, both widths, login and sign-up — is recorded in
t001 and t002 and re-run in t006. The shared hidden-username consumers stay
source-verified, since those routes need a valid OAuth `uid`.

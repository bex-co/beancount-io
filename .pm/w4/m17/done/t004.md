## Simplify review

Completed 2026-09-19. Ran `/simplify` over the repair. The efficiency angle was verified directly — the diff adds no timer, effect, subscription or dependency, reusing the existing debounce — and the reuse and altitude angles were reviewed in depth. The altitude review confirmed the mechanism against the installed router rather than inferring it: `router-core` builds a navigation's `fromParams` and `fromSearch` from `pendingBuiltLocation ?? latestLocation`, so any navigation relying on implicit inheritance resolves against the in-flight destination, and explicit `params` win because they are assigned over the inherited ones.

**Fixed — the sibling with the identical defect.** `user-profile-tabs.tsx` still wrote its tab with `to: "."` from the same profile route. The profile stays interactive while a card's route is pending, so a tab click in that window produced the same `/ledger/undefined`. It is now addressed explicitly, and the five assertions in its suite that pinned the old relative target were updated to the new one.

**Fixed — the guard sat one level too low.** It only gated the debounced write, but `updateSearch` is also called by the sort select, "Show more" and the show-reset inside `editQuery`, all reachable while a card's route is pending. The check now gates every write. That also closes a subtler hole the altitude review surfaced: `search: (previous) => ...` reads `previous` from the pending destination too, so pinning `to` and `params` alone would still have merged the wrong route's search.

**Fixed — one owner for the pending draft**, which is what this task's acceptance asks for. The debounce and the departure flush each carried the skip-if-unchanged rule and the empty-means-absent encoding; that is the whole definition of committing the draft, not a stray ternary, and two copies could silently diverge. `commitQuery()` now holds the guard, the encoding and the timer, which it clears through a ref so a flushed write cannot be followed by a redundant duplicate navigation.

**Fixed — smaller correctness-adjacent cleanups.** The route id appeared four times, once as an untyped string inside the guard, where a rename would have compiled cleanly and left `hasLeftProfile()` permanently true — silently stopping every debounced write. It is now one `PROFILE_ROUTE` constant used at all four sites. The activation handler also matched Space, but the cards are anchors, which the browser activates on Enter only, so Space wrote to the URL on a keypress that never navigates; that branch is gone.

**Test hygiene.** The race suite had re-declared the whole route tree to add a held loader; `buildRouter` now takes that loader as an option. A near-duplicate case that repeated an existing test's setup for one extra assertion was folded into it.

**Not adopted, with reasoning.** A lint rule banning `to: "."` was considered and rejected: it would flag nine call sites to catch two, and it targets the wrong invariant — the hazard is implicit param inheritance during a pending navigation, not the literal. Every absolute navigation in the repo already passes explicit params, so the convention is de facto enforced. `useBlocker` and `router.subscribe("onBeforeNavigate")` were both checked as alternative seams for the departure flush and are available, but both fire after the history-entry decision, which is too late to write into the entry being left; pointerdown-capture is correct precisely because it runs before any navigation exists. `useRouter` was confirmed the right hook here — the repo uses `useRouterState` with a selector for render-time reads and `useRouter` for imperative access, and this is an imperative call-time read that must not be a render snapshot.

**Recorded rather than fixed**, in [143](../../143.md): `journal-page.tsx` has the only other genuinely delayed relative write, firing after an awaited mutation, where it could produce `/ledger/undefined/undefined/journal`. It is a different feature and outside this milestone. The note also records that the departure flush is bound to the results grid, so leaving via the tabs or the profile header still drops an uncommitted query.

Both regressions were re-verified after the restructuring: reverting the explicit target and guard fails only the race case, and removing the flush fails only the Back case. Gates from `dashboard/`: `yarn format:check`, `yarn lint`, `yarn build` and `yarn test` pass at 376 files and 4,244 tests.

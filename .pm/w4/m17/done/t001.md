## Objective

Prevent the outstanding search timer from starting relative profile navigation after a card/tab/profile departure begins. Handle the real pending-route lifetime and explicit identity without redirecting to the old profile.

## Context

See [FINDINGS.md](./FINDINGS.md) and the milestone definition of done. Preserve completed w3/164's profile history contract.

## Files

LedgerCollection and its navigation boundary

## Acceptance criteria

- [x] A pending ledger read survives the debounce deadline and no undefined or old-profile navigation occurs.

## Out of scope

Backend/API changes, collection server-cap changes, global router behavior, new dependencies and unrelated ledger-list fixes.

## Implementation and verification

Completed 2026-09-19. Two changes in `user-profile/components/ledger-collection.tsx`, matching FINDINGS' instruction that supplying a username alone or cancelling the timer alone would each leave half the defect.

The profile-scoped write is now addressed explicitly — `to: "/ledger/$username"` with `params: { username }` instead of `to: "."`. That is the direct cause of the reported `/ledger/undefined`: once a ledger card has started its route, the router resolves a relative navigation against the pending destination, whose params carry `ledgerOwner` and `ledgerName` rather than `username`, so `$username` interpolated as undefined.

Explicit addressing alone would still let a stale timer drag the reader back to the profile they just left, so the debounced update now checks at fire time whether the reader has started going elsewhere, reading the router's pending or current match and returning early when it is no longer the profile route. Checking at fire time rather than scheduling time is what makes it correct: the component stays mounted while the ledger read is in flight, which is exactly the window the defect lives in.

Covered by a router integration case that reproduces the real race rather than a pre-seeded search URL: the ledger route holds an unresolved loader, the reader types and clicks the actual card, the route goes pending with the profile still mounted, and the outstanding debounce is allowed to fire against that pending destination. A second case asserts a settled write still lands on the profile.

Worth recording honestly: the first version of this test passed against the unfixed code, so it was not reproducing anything. It navigated with `router.navigate` to a loaderless route, which completes immediately and never leaves the route pending. Rebuilt with a held loader and a real card click, it fails against the unfixed code with the exact reported symptom — `expected '/ledger/undefined' not to contain 'undefined'` — and passes with the repair.

Two existing tests needed updating for the new contract, both deliberate. `user-profile-tabs.test.tsx` mocks `@tanstack/react-router` and had to expose `useRouter`, and its "Show more" case asserted the old `to: "."`; it now asserts the explicit profile target with its params, which is the behaviour being fixed.

Validated search, sort and show handling, the bounded counts, typing focus and the no-history-churn contract are untouched — the write is still `replace: true` and still debounced at 250ms. Gates from `dashboard/`: `yarn format:check`, `yarn lint`, `yarn build` and `yarn test` pass at 376 files and 4,243 tests. The departure snapshot that preserves an unpersisted search for Back is t002's work and is not claimed here.

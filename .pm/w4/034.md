# Two routes crash on render when opened without their params — `useLocalSearchParams` types lie about what arrives

**Severity:** minor — hard render crashes, but both need a URL to reach. **Estimate:** 25–35 minutes for both. Owner: mobile. A2: these routes are registered and reachable by the custom scheme, so anything that can fire a URL — another app, a web page, a stale link — crashes them. One of the two is the **live file editor**, reached normally from the Files tab, not a parked screen.

**Two confirmed instances, same cause, same fix shape** — filed together because splitting them would fragment one cleanup:

| route | crash site | in the UI? |
| --- | --- | --- |
| `/(app)/add-transaction-next` | `add-transaction-next-screen.tsx:255` — `currentMoney.split(".")` | no (`w4/033`) |
| `/(app)/ledger-file-editor` | `ledger-file-editor-screen/index.tsx:539` — `path.split("/")` | **yes** — Files tab → tap a file |

Environment: branch `main`, HEAD `038faeeb`, native development build `io.beancount.ios` on iPhone 17e / iOS 26.5, authenticated production session at `https://beancount.io`, own ledger `puncsky/example`. Report-only QA; **nothing was saved** — the screen never rendered far enough to offer a save.

## Repro

1. Select an **owned** ledger (`puncsky/example`); the route sits behind `LedgerWriteGuard`, so a read-only ledger redirects instead.
2. Fire `xcrun simctl openurl <udid> 'beancount:///(app)/add-transaction-next'`.
3. A full-screen **Render Error** appears immediately:

   ```
   Cannot read property 'split' of undefined
   add-transaction-next-screen.tsx (255:54)

   Component Stack:
     <AddTransactionNextScreenComponent />  add-transaction-next-screen.tsx:97
     <LedgerGuardProviderComponent />       ledger-guard.tsx:96
   ```

4. Dismissing the error returns to Home with the session and ledger intact, so the app is not wedged in development.

**Working control — the intended path is fine.** `add-transaction-screen.tsx:212-223` always passes all five params and refuses to navigate when the amount is still `"0.00"`, so arriving from the quick-add keypad renders correctly. The crash is specific to entering the route cold.

## Repro — second instance, on a live screen

1. With any ledger selected (`open_ledger/alphabet` used here — read-only is fine, this one is not behind `LedgerWriteGuard`).
2. Fire `xcrun simctl openurl <udid> 'beancount:///(app)/ledger-file-editor'` with **no `path`**.
3. Same render error:

   ```
   Cannot read property 'split' of undefined
   index.tsx (539:30)

   Component Stack:
     <LedgerFileEditorSession />  ledger-file-editor-screen/index.tsx:287
     <LedgerFileEditorScreen />   ledger-file-editor-screen/index.tsx:271
   ```

`index.tsx:272` declares `useLocalSearchParams<{ path: string; initialLine?: string }>()` — again one param optional and one asserted — passes `path` into `LedgerFileEditorSession({ path }: { path: string })`, which does `const fileName = path.split("/").pop() ?? path;` at line 539. The `?? path` fallback guards the *result* of `.pop()`, not the dereference before it.

**Working control:** the same screen entered normally (Files tab → tap `main.bean`) supplies `path` and renders correctly, as verified earlier in this run.

**This instance does not self-recover, and the other one does.** Dismissing the `add-transaction-next` error returns to Home. Dismissing this one does not: the crashed route stays mounted and re-throws, and navigating away with `beancount:///(app)/(tabs)` does not clear it either — only terminating and relaunching does. So the file editor is both the more reachable of the two routes and the harder one to escape.

## Root cause

`add-transaction-next-screen.tsx:100-111`:

```ts
const {
  currentMoney, currentAsset, currentExpense, currentCurrency, currentPayee,
} = useLocalSearchParams<{
  currentMoney: string;      // ← declared non-optional
  currentAsset: string;
  currentExpense: string;
  currentCurrency: string;
  currentPayee?: string;     // ← the one that is marked optional
}>();
```

then at lines 255 and 258:

```tsx
{`${currencySymbol}${currentMoney.split(".")[0]}`}
{`${currentMoney.split(".")[1]}`}
```

`useLocalSearchParams`'s type argument is an **assertion, not a guarantee** — Expo Router returns whatever the URL actually carried. Entered without params, `currentMoney` is `undefined`, and `.split` throws. Because the generic declares it as `string`, TypeScript cannot flag the dereference, so `yarn typecheck` passes.

The author clearly understood the distinction — `currentPayee` *is* marked `?` — and applied it to one param out of five.

## There is a correct example of the same pattern in the repo

`commit-detail-screen.tsx:161-172` declares the identical non-optional shape and then defends against the value being missing anyway:

```ts
const { sha } = useLocalSearchParams<{ sha: string }>();
...
variables: { ledgerId, sha: sha ?? "" },
skip: !ledgerId || !sha,
const shortSha = sha ? sha.slice(0, 7) : "";
```

Same lying annotation, guarded every time the value is used, plus an empty state when the query returns nothing. That is the shape to copy — **no device check was needed to establish this; the source is decisive.**

## Fix

1. Type the params honestly: every param that is not guaranteed by *every* route into the screen should be `?: string`. For this screen that is all five, since the route is reachable by URL.
2. Guard the render. A screen entered without its subject has nothing to show, so the honest response is to send the user somewhere useful rather than render a broken view — `Redirect` to `/add-transaction` when `currentMoney` is absent, and to the file browser (`/(app)/(tabs)/ledger`) when `path` is absent, mirroring how `app/(app)/agent.tsx` redirects rather than rendering a route it should not show.
3. Do not fix it with `currentMoney ?? "0.00"`. That renders a form seeded with a zero the user never entered, on a screen whose own predecessor refuses to proceed at `"0.00"`.

**Acceptance:** `beancount:///(app)/add-transaction-next` and `beancount:///(app)/ledger-file-editor`, each with no params, land on a usable screen instead of a render error; both normal entry paths (quick-add keypad with all five params; Files tab → tap a file) are unchanged; and neither `currentMoney` nor `path` is dereferenced without a guard. Add a test that renders each screen with empty params — neither screen has one today.

## Blast radius

Two screens confirmed. The pattern appears on 15 `useLocalSearchParams` sites; I audited every one that declares a param **non-optional**, which is the only shape that can hide this:

| screen | required param | dereferenced unguarded? |
| --- | --- | --- |
| `add-transaction-next-screen` | `currentMoney` +3 | **yes — crashes** |
| `ledger-file-editor-screen` | `path` | **yes — crashes** |
| `edit-transaction-screen` | `entryHash`, `ledgerId` | no — `entryHash ?? ""`, `skip: !entryHash \|\| !ledgerId`, `useRef(entryHash ?? "")` |
| `commit-detail-screen` | `sha` | no — `sha ?? ""`, `skip: !sha`, `sha ? sha.slice(0,7) : ""` |
| `narration-input-screen` | `narration` | no — `initialValue={narration \|\| ""}` |
| `account-picker-screen` | `type` | no — `accountOrderFor(type?: string)` takes it optional and falls back (`push-account-picker.ts:21-23`) |

Every other site already declares its params optional (`q?`, `account?`, `ledger?`, `payee?`, `testMode?`, `prefill?`/`prefillRoot?`), and `open-account-screen` additionally does `prefill ?? ""`. **Every non-optional site is now traced**: four of six defend the value, two do not. So the codebase mostly gets this right, and the audit is complete rather than a sample.

**Three of the four "defends the value" rows are now observed on device, not only traced** (September 13, HEAD `038faeeb`, paramless deep links):

- `edit-transaction-screen` — on writable `puncsky/example`, `beancount:///(app)/edit-transaction` renders **"Failed to load transaction"** in red under the screen's help text, with a working `Cancel`. (On a read-only ledger it never reaches the param code at all: `LedgerWriteGuard` shows *"This ledger is read-only. Choose a ledger you can edit to make changes."* with a `Browse ledgers` link.)
- `narration-input-screen` — `beancount:///(app)/narration-input` renders an empty field with the ledger's narration suggestions listed normally.
- `payee-input-screen` — same shape, verified earlier in this run.

So the guarded majority genuinely degrades well, which sharpens the contrast with the two that crash: this is not a codebase that lacks the pattern, it is two screens that skipped it.

Not exercised: **release-build behaviour.** In development LogBox shows the red screen and dismissal recovers to Home; without LogBox the same render throw hits whatever error boundary exists above it, which I did not trace, so "white-screens it" is the expected outcome rather than an observed one. Android is also unexercised.

## Adjacent states

This answers the question `w4/033` left open — it filed the route as unreachable-and-undocumented and recorded that whether it *works* when deep-linked was unverified. It does not. Read the two together: if the decision there is to remove the screen this is moot, and if the decision is to promote it this must be fixed first.

Noted in passing, and corroborating `w4/029`: the `"0.00"` guard on the quick-add keypad reports itself with `toast.showToast` (`add-transaction-screen.tsx:206-209`). Since no toast renders, a user on that flow who taps through with an empty amount gets **no feedback at all** — the navigation simply does not happen. That is a non-write toast path, which `w4/029`'s blast radius listed as unexercised; it is on the parked screen, so it changes nothing today, but it is one more surface that depends on toasts working.

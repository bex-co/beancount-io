# Half-translated messages are caught hours late in CI; the translator workflow could say so at edit time

Severity: minor tooling gap. Estimate: ~30m, dashboard. A2: shortens the loop
between creating this defect and seeing it.

`dashboard/scripts/prepare-translations.ts` is the documented translator entry
point (`yarn i18n:prepare`). It walks every catalog, prints a per-locale status
table, and tells the reader to grep `[TODO]` and edit in place.

The half-translated shape is created in exactly that edit: `[TODO] Account
Journal` becomes `Счёт Journal` when only the leading token gets replaced. The
script counts `[TODO]` markers and nothing else, so it reports that file as
progressing while the edit has left a word in neither language behind. The
guard shipped in `w4/m24/t010`
(`dashboard/src/test/locale-stray-english.test.ts`) catches it, but only on a
later `yarn test` run — and the `yarn test:translations` alias a translator
would reach for does not include that suite.

Shape: import `strayEnglishWords` from `dashboard/src/test/locale-scan.ts` into
`prepare-translations.ts` and add a "half-translated" column beside the TODO
count, listing the offending keys for the locale being worked on. Optionally
add the guard to whatever `test:translations` runs, so the translator's own
command covers it.

Not the right shape: a custom ESLint rule. `dashboard/eslint.config.js` has no
local plugin infrastructure, so that would be net-new machinery for a check
that already has two good homes — the prepare script and the test suite.

Acceptance: `yarn i18n:prepare` reports half-translated messages per locale
alongside the TODO count, using the shared predicate rather than a second copy
of it; the numbers agree with what the guard reports. Dashboard gates pass.

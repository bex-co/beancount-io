# Keep commodity-price tooltips inside narrow chart viewports

Severity: **minor**. Package: **dashboard**. Estimate: **35–45m**. Source:
continuous dashboard QA for w4. **A2**: readers exploring commodity prices must
be able to read the date and pair name beside the quoted value.

## Reproduce

Production `https://beancount.io`, anonymous public synthetic `crypto-example`,
isolated headless Chromium 149.0.7827.55. English; 320×800/light and fresh-load
390×844/dark. Local main `390568c2`, deployed `main-d5j4FX-V.js`; exact deployed
revision unverified. These are narrow browser pointer checks, not physical
phone/touch tests.

1. Open `/ledger/open_ledger/crypto-example/commodities?lang=en`.
2. Scroll vertically to the **UNIV2ETHUSDC/USD** card without horizontal
   scrolling. Hover the October 2025 point (2025-10-05).
3. At 320px, the settled tooltip has x **−38**, width **203.28125**, right
   **165.28125**. Its full DOM text is `2025-10-05` and
   `UNIV2ETHUSDC/USD: 1002`, but the screenshot clips the leading year and
   commodity characters off the left edge.
4. Reload at 390px/dark, hover the same point: x **−28**, same width, right
   **175.28125**. The canvas is correctly 324px wide, and main client/scroll
   widths are both 390, so this is neither an oversized canvas nor a page
   that can scroll sideways to reveal the tooltip.
5. Desktop control at 1440×1000/light: same point, same complete text, x580
   through783.28125; it fits. Keyboard **Show price history for
   UNIV2ETHUSDC/USD** opens the correctly named table, whose 2025-10-05 row
   shows `1002.00`.

Real `GetLedgerCommodities`, variables
`{ledgerId:"open_ledger/crypto-example"}`, returns HTTP200, no GraphQL errors,
and the selected pair's price `{date:"2025-10-05",value:"1002.00"}`. Six price
points render for this pair. No application exception accompanies the failure.
The existing quote precision is correct; only popup placement is defective.

## Cause and bounded repair

`dashboard/src/features/ledger-data/commodities/index.tsx:46–64` constructs
`CommodityChart`'s HTML axis tooltip without confinement. Its sole render site
is the pair-card loop at `:223`, so the same option owns every commodity pair
on this route. `build-commodity-chart-labels.ts:21–35` retains source strings
and supplies the correct date/pair/price text. The GraphQL resolver at
`backend-cluster/backend-v2/src/features/ledger/api/resolvers/ledger-data-resolver.query.ts:234–250`
passes those fields through; no API repair is indicated.

Installed ECharts `lib/component/tooltip/TooltipView.js:749–782` flips a popup
that overflows right to `x - width - gap`; `:646–650` clamps the resulting
negative position only when confinement is enabled. The recorded final
transforms are `translate3d(-71px,145px,0px)` and
`translate3d(-61px,145px,0px)` relative to the charts, not mid-animation guesses.

Reuse `CONFINED_TOOLTIP` from `dashboard/src/common/lib/chart/tooltip.ts:15`
in this option producer, retaining its formatter and axis trigger. Verify
full date, pair and price visibility at 320/390px and desktop in both themes,
including resizing and the existing keyboard history disclosure. Keep exact
quote strings, line-series data and axis labels unchanged. Do not alter
ECharts itself, global chart defaults, APIs, or ledger data. A live geometry
check is required; a configuration-literal assertion alone cannot prove the
popup is visible. Run normal dashboard gates for the eventual repair.

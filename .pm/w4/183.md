# Keep BQL End navigation on the final row after dynamic measurements settle

Severity: **minor** keyboard-navigation defect. Package: **dashboard**.
Estimate: **45–60m** for the bounded result-table repair and checks. Source:
continuous dashboard QA for w4; **A2/A3** — readers should reach the final query
result with one End press even when preceding inventory cells have several lines.

Production `https://beancount.io`, anonymous synthetic `open_ledger/example`,
owned isolated headless Chromium149.0.7827.55. Local main `390568c2`, served
`main-d5j4FX-V.js`; exact deployed revision unverified.

1. Fresh-load `/ledger/open_ledger/example/query?lang=en&query=SELECT%20date%2C%20sum(position)%20GROUP%20BY%20date%20LIMIT%20100`
   at390×844/dark. Wait for the100-row result and initial layout to settle.
2. From Execute Query, Tab through the result summary, Download CSV and Delete
   query into the scrollable result rowgroup. This native Tab path was verified;
   it does not require adding a tabindex or modifying the DOM.
3. Press End once and wait one second. The last API row is2015-05-31, but it
   remains entirely below the visible result viewport. The preceding2015-05-30
   row is at the bottom of the screen.
4. Geometry: initial scrollHeight3635; End reaches scrollTop3035 for the600px
   viewport. Measurement of newly rendered inventory rows increases scrollHeight
   to3669, leaving a34px gap. Row101 (header-inclusive index) spans y844.5–877.5,
   while the scroll viewport ends at844. A later settled observation is unchanged.
5. Fresh1440×1000/light independently repeats the34px shortfall: initial
   scrollHeight4035, final4069, scrollTop3435, clientHeight600. Only the first
   few pixels of the37px final row reach the viewport; its date is not readable.

Working controls: a second End press exposes the final row (narrow gap0;
desktop gap1 from fractional geometry). A fresh narrow `SELECT date LIMIT 100`
control has uniform rows and reaches row101 on the first End: height3300,
scrollTop2700, viewport600, gap0. This is not missing data or permanently
unreachable content; it is a failed first jump to the end.

The actual QueryShell HTTP200 response has100 rows, including2015-05-31 last,
with11 multi-unit rows and up to3 inventory lines per cell. API values and row
indexes are correct. Row101 exists as overscan below the clipping boundary, so
checking DOM presence or a generic visibility assertion would miss the defect.

Cause: `dashboard/src/features/bql/components/query-result-card.tsx:143–146`
uses useDynamicRowHeight, and its List at189–208 relies on native scrolling
without preserving an End target while measurements change. Installed
react-window2.2.5 (`dist/react-window.js:725–742,878–937`) estimates unmeasured
row heights, then ResizeObserver updates measured heights and total extent.
The browser's completed native End scroll remains at the earlier bottom.
The observed34px growth and unchanged scrollTop establish that mechanism.

Keep the explicit End destination anchored to the actual final row until its
new measurements settle, using the existing List/ref/measurement facilities.
Scope this to the result scroll area and preserve ordinary scrolling, focus,
Home/Page navigation, dynamic cell heights, the600px cap, virtualization,
semantic indexes, exact values and exports. Do not force readers to the bottom
on every render or restore fixed-height rows that clip inventory/PRINT cells.
No backend, dependency upgrade or shared virtualizer rewrite is required.

Acceptance: one End from a fresh result fully exposes2015-05-31 after layout
settles at both widths, within fractional-pixel tolerance. The uniform-row
control still works, and scrolling away stays under the reader's control.
Verify rendered clipping geometry and actual keyboard input; preserve the
existing multi-unit/PRINT and large-result cases. Run dashboard gates.

Blast radius: QueryResultTable is private to QueryResultCard, whose sole
production owner is `features/bql/pages/index.tsx:374`; every table-shaped BQL
history result shares it. Other virtual lists, other engines and Ctrl+End were
not reproduced. `common/components/diff-viewer` already demonstrates List's
imperative scrollToRow API, but has a separate navigation contract.

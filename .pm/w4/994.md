# Keep collapsed BQL history cards closed when another card is deleted

**Severity:** minor residual of [253](./done/253.md). **Estimate:** 25–40 minutes. **Owner:** dashboard. **A2:** deleting a saved query must preserve the disclosure choices on the remaining queries.

## Reproduction and controls

Production `https://beancount.io`, 2026-10-22; owned isolated headless Chromium 155.0.8059.85, anonymous public `open_ledger/example`, English/light, fresh 1440×1000 and 390×844 contexts. All results come from genuine HTTP 200 QueryShell reads. Only disposable browser history changes; no response fixtures or hosted writes.

1. Execute A, B and C through the actual editor using Cmd+Enter, waiting for each exact one-row result. Use `SELECT 'qa-20261022-collapse-A' AS label LIMIT 1` and B/C variants. History is [C, B, A]; new queries open normally.
2. Use each native summary with Enter to collapse A and B. The settled states are C open, B closed, A closed.
3. Focus B's **Delete query** and press Enter. History becomes [C, A], with C still open and A still closed. This is the passing middle-deletion control.
4. Delete C in the same way. A becomes first and **reopens automatically**, displaying its cached result even though A was explicitly collapsed and was neither selected nor executed. Both fresh widths repeat.

The original A summary and details DOM nodes remain identical and connected. QueryShell counts stay exactly **3 → 3 → 3** through deletion and the later native close/reopen control. History storage correctly contains only A; the editor and query bookmark still contain the exact C query. Cached manual close/reopen keeps A's summary focused and starts no read. Thus no result, model or storage corruption is claimed; the defect is the unwanted change to an unrelated disclosure. BODY focus after removing the Delete button is the already-filed [988](./done/988.md), not another finding here.

## Cause and bounded repair

`dashboard/src/features/bql/pages/index.tsx:358–369` correctly keys cards by their unique query, but passes `isInitiallyOpen={index === 0}` on every render. In `components/query-result-card.tsx:289–293`, the effect sets `details.open = true` whenever that prop becomes true. Removing the first card changes the next card's index, so a positional change is treated as an opening instruction. Stable keys preserve the node but cannot prevent this effect from overriding its native closed state.

Keep explicit disclosure state on cards that survive deletion. Separate initial/new execution opening intent from merely occupying index zero; retain the existing useful opening of a newly submitted query and keyboard opening of an uncached history item. Preserve unique card identities, cached results, ordering, export controls, exact editor/URL state and cross-ledger isolation. Coordinate with 988's independent focus handoff in these same owners; moving focus alone does not stop this effect. Do not remove all useful automatic opening or introduce a global history-change focus/open effect. No API, dependency or backend behavior change is needed.

Acceptance: through the real history hook/page/cards, load [C, B, A], collapse A/B, delete B and then C, and assert the same A node stays closed with its cache intact and no additional read. Include a remaining-open control, native cached toggles, initial/new query opening and normal history execution/reordering. Preserve the completed 253 behavior and 988's focus target. Repeat desktop/narrow and run dashboard gates when implementing. Pending reads, other locales/engines and repaired behavior remain unverified.

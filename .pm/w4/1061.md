**Minor · dashboard · 35–50 minutes · A2.** The source-location action and balance disclosure receive keyboard focus without any painted focus cue in high-contrast browser mode.

## Cause and bounded repair

`dashboard/src/features/journal/components/entry-context-panel.tsx:320–350` renders both as custom HTML buttons with **outline-none**, shadow-based focus-visible rings, and zero-width borders. Forced colors removes box-shadow, while the outline style remains none. Text/background/underline and disclosure state stay unchanged between the focused/unfocused captures. The global baseline outline therefore does not rescue these overrides.

The [CSS Color Adjustment specification](https://drafts.csswg.org/css-color-adjust-1/#forced-colors-properties) describes the forced-color shadow behavior. [W3C's Focus Visible guidance](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html) explains why keyboard readers need a visible indication of the active control. This QA checks the actual rendered controls; physical Windows palettes and a complete accessibility-conformance assessment were not performed.

Give both controls a visible system-color focus outline in forced colors, reusing the app's established treatment. Preserve normal source typography/underline and rings, names, Tab order, expanded state/aria-controls, source destination, read-only/writing guards and focus return. The disclosure sits inside an **overflow-hidden** rounded wrapper: use an inset-compatible outline/offset so the new cue is not clipped. Keep this local to the existing entry controls; no new focus framework, global styling exception, dependency or API change is needed.

Acceptance: native Tab/Shift+Tab paints a distinguishable indicator for both real controls at390/1440 under forced colors, while ordinary rings, Enter activation, disclosure expansion/collapse and dialog Close/return focus remain correct. Verify the actual padded before/after paint and the standalone consumer; class presence alone cannot establish visibility. Add meaningful rendered/style coverage when implementing and run dashboard gates. QA authored no product fix or formal tests. Disclosure activation after these focus captures and source-file navigation were not independently exercised by this specific check.

# Keep the desktop sidebar gap beside its pane in Persian layouts

Severity: **minor** layout/navigation defect. Package: **dashboard**. Estimate:
**45–60m** for the bounded composition repair and geometry checks. Source:
continuous dashboard QA for w4. **A2/A3**: choosing Persian must not put report
content and sign-in controls underneath the sidebar.

## Reproduce

owned isolated headless Chromium149.0.7827.55. Local main `390568c2`, served
`main-d5j4FX-V.js`; exact deployed revision unverified.

## Cause and bounded repair

`dashboard/src/common/components/ledger-layout/index.tsx:112` composes the
sidebar and main in a flex row that inherits `dir=rtl`. Its first in-flow child
(the sidebar gap) consequently moves to the right. The shared
`common/components/ui/sidebar.tsx:255–266,347–366` still defaults to the
physical `side="left"` and positions the actual fixed pane with `left-0`.
The independently located gap and pane now disagree.

Keep the desktop composition's gap on the same physical side as the fixed
pane, while preserving RTL inside navigation and content. The current
`SidebarRail` explicitly assumes a left-anchored pane (`sidebar.tsx:417–418`)
and computes pointer width from the wrapper's left edge; a bounded repair can
keep that established physical layout and correct the RTL row ordering. Do not
merely move the fixed pane to the right while leaving its rail math unchanged,
or set all Persian content back to LTR.

Apply the same composition rule to its three production owners: ledger layout,
`common/components/ledger-layout/ledger-layout-loading.tsx:86–107`, and
`features/ledger-list/pages/dashboard-page/components/dashboard-layout.tsx:41–54`.
The authenticated dashboard and loading scaffold are source-traced consumers;
only the public ledger layout is live-reproduced. No API, data, locale-catalog,
dependency or new sidebar abstraction is required.

Acceptance: at1024/1440, Persian and English main/pane rectangles do not overlap
in expanded,48px-collapsed and nondefault-width states. The main area uses the
remaining space with no opposite-edge gap, and sign-in/report controls receive
pointer input. Preserve rail keyboard/drag direction, persisted width/open
state, RTL text and the narrow sheet's dismissal/focus behavior. Verify geometry
and actual activation, not just the presence of a CSS class. Run dashboard gates.

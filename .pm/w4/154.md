# The profile tab triggers replace the whole search object, discarding q, sort, show and lang

Severity: minor state-loss defect. Estimate: ~30m, dashboard. A2: a reader who
has searched or sorted a profile's ledgers loses that state by glancing at
another tab.

Found while closing `w4/151`, which fixed the neighbouring seam — the search
draft now flushes to the URL on the field's own blur, so it reaches the entry
being left. Departing by a tab still loses it, but for an unrelated reason.

`features/user-profile/components/user-profile-tabs.tsx:125` navigates with a
literal search object:

```
void navigate({
  to: "/ledger/$username",
  params: { username },
  search: { tab: newTab as ... },
  replace: true,
});
```

`search` given as a value replaces the entry's search params outright rather
than merging, so every sibling param is dropped.

Repro on the public `open_ledger` profile, English, 1440x900. Open
`/ledger/open_ledger?lang=en`, type `gov` into **Search ledgers**, then click
the **Starred** tab. The URL becomes `?tab=starred` — `q` is gone, and so is
`lang`, which is the giveaway that this is wholesale replacement rather than
anything to do with the search flush. Returning to **Ledgers** shows the
unfiltered list. The same gesture loses `sort` and `show`.

Fix: pass the updater form so the tab merges into what is already there —
`search: (prev) => ({ ...prev, tab: newTab })` — keeping `replace: true` and
the explicit `to`/`params`, which are load-bearing for a separate reason
recorded in the comment above that call: `to: "."` would resolve against a
pending ledger destination and land on `/ledger/undefined`.

Acceptance: typing a query, changing sort, or revealing more ledgers and then
switching tabs preserves `q`, `sort`, `show` and `lang`; switching back shows
the same filtered list; the destination is still the profile route and never
contains `undefined`; Back/Forward still work. Cover it in
`features/user-profile/components/__tests__/` — the existing
`ledger-collection.test.tsx` already builds a memory router with the profile
search schema and is the closest model, though the tabs have their own suite.
Run the dashboard gates.

Blast radius: the profile tab strip only. Worth checking whether other tab
strips in the dashboard pass `search` as a literal in the same way; that check
is in scope for this note, fixing any found elsewhere is not.

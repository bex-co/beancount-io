# The Budget screen's "YTD" pill spans the whole calendar year, so the card reports a future month

**Severity:** minor. **Estimate:** 25–40 minutes. Owner: mobile. A2: `YTD` is the Budget screen's **default** range, so this is what a user sees on arrival — a headline `Budget / Actual / Variance` describing a month that has not started, and a "Below target" badge earned by having no data yet.

Environment: branch `main`, HEAD `038faeeb`, native development build `io.beancount.ios` on iPhone 17e / iOS 26.5, English / System / light, authenticated production session at `https://beancount.io`, own ledger `puncsky/example`, "today" = **2026-09-13**. Report-only QA; no budget was created, updated or deleted — `Update Budget` was never tapped.

## Repro

1. Select `puncsky/example` and open `beancount:///(app)/budget`. The default pill is **YTD**.
2. The first card (`Expenses:He…roupTermLife`, chip **Monthly**, USD) reads:

   > **Budget $122.00** · **Actual $0.00** · **Variance −$122.00** · *Below target*

   and its axis runs `… JUL AUG SEP OCT NOV DEC`.
3. Tap **1Y**. The same card now reads:

   > **Budget $52.87** · **Actual $0.00** · **Variance −$52.87**

   and its axis runs `… APR MAY JUN JUL AUG SEP`.

The 1Y figure is **correct**: `$122.00 × 13/30 = $52.87`, September's budget prorated to the 13th. The YTD figure is December 2026's full-month budget — three months in the future.

## Root cause

Two pieces combine.

**1. "YTD" is not year-to-date.** `budget-labels.ts:100-103` maps the pill to fava's `time` filter:

```ts
case "this-year":
  return "year";        // the whole calendar year
case "last-12m": {
  …                     // explicit inclusive range ending at `today`
}
```

`year` means January–December. So the charted series runs past today into `OCT`, `NOV`, `DEC` 2026, each with a budget line and a zero actual. The pill's label key is literally `rangeYTD` (`budget-labels.ts:85`), so the label says "to date" and the filter does not.

**2. The card headline reads the *last* charted period.** `select-budget-card-stats.ts:57,63`:

```ts
const latest = series.length > 0 ? series[series.length - 1] : null;
const budget = latest ? Math.abs(latest.budget) : Math.abs(group.value);
```

That is a deliberate and well-reasoned choice — its comment explains the series "carries the budget that was in effect for each charted period … so a mid-year raise doesn't retroactively rewrite history". It is only wrong because piece 1 puts unstarted months at the end of the series.

So `Actual $0.00` and `Variance −$122.00` are arithmetically right *for December*, and the `Below target` badge is earned by a month that has not begun. Under 1Y — whose window ends today — the same code produces the right answer, which is the clearest evidence that the range mapping is the defect and the card stats are not.

## All four ranges, now exercised

| pill | filter | last charted period | headline Budget | verdict |
| --- | --- | --- | --- | --- |
| **YTD** | `year` (Jan–Dec) | **DEC 2026** — future | `$122.00` | **wrong** — a month that has not started |
| **LY** | `year-1` | DEC 2025 | `$0.00` (`$0.00` actual, *On target*) | correct — complete past year, and the budget did not exist then |
| **1Y** | explicit range ending **today** | SEP 2026 | `$52.87` | **correct** — September prorated to the 13th |
| **ALL** | no filter | SEP 2026 | `$122.00` | **inconsistent** — right month, full-month budget against a partial-month actual |

`1Y` and `ALL` end on the *same* period and disagree about its budget (`$52.87` vs `$122.00`), which is the clearest single symptom. The difference tracks the window end: `1Y` truncates September at the 13th and the prorated budget follows; `ALL` has no end bound, so the period is treated as whole while its actual is necessarily partial.

**So the defect generalises**: the headline compares a budget and an actual measured over **different spans** whenever the window does not end today. `YTD` is the loud case (a future month); `ALL` is the quiet one (a full-month target against 13 days of spending). `1Y` and `LY` are right precisely because their windows end where the actuals do.

*Inference, flagged:* that the proration follows the filter's end date is deduced from the figures (`$122.00 × 13/30 = $52.87` exactly, today being the 13th) rather than read from the server. The series field is documented as a "**Prorated** budget for the same period" (`select-budget-card-stats.ts:19`), which is consistent, but the proration itself happens outside this repository and was not traced.

## Fix

Change `"this-year"` to a genuine year-to-date window rather than changing the card:

```ts
case "this-year":
  return formatTimeFilter({ start: `${year}-01-01`, end: today });
```

`timeSpanToFilter` already takes `today` and already builds an explicit inclusive range for `last-12m`, so this is the same shape one case up.

Do **not** fix it by making the card pick the last *elapsed* period instead of the last charted one — that would paper over a chart which still draws empty future months, and it would break the documented mid-year-raise behaviour that currently works. If charting the remainder of the year is wanted (a forward-looking budget view is a reasonable product idea), then the pill needs a different label and the headline needs to name the period it describes.

**Acceptance:** on 2026-09-13, the YTD card shows September's prorated budget (`$52.87`) with September's actual, matching what 1Y shows; the chart's last plotted month is the current one; **`ALL` agrees with `1Y` on September rather than showing `$122.00`**; `LY` is unchanged (verified correct — a complete past year); and `1Y` is unchanged. Add a test that `timeSpanToFilter("this-year", "2026-09-13")` produces a window ending `2026-09-13` — the existing tests cover `last-12m`'s arithmetic but nothing pins `this-year`.

## Blast radius

The Budget screen's default view, and **Home's budget panel, which is confirmed to share both halves of the defect**:

- `use-budget-panel.ts:90` builds its window with `timeSpanToFilter(DEFAULT_BUDGET_SPAN)`, and `DEFAULT_BUDGET_SPAN` is `"this-year"` (`budget-labels.ts:82`) — so Home issues the same whole-calendar-year `"year"` filter.
- `select-budget-panel.ts:13` imports `selectBudgetCardStats` from the budget screen, so the rows are derived by the same "last charted period" rule.

Home therefore ranks "the budgets closest to their limit" using a budget/actual pair taken from a month that has not started, and — unlike the Budget screen — it has **no range pills**, so there is no way for a user to land on a correct view. *Established from source*: the panel sits below the fold and could not be read on screen (`w4/020`), so this arm is a code trace rather than an observation.

Every budget card on the Budget screen is affected identically: the second card, `Liabilities:AccountsPayable`, shows the same `$122.00 / $0.00 / −$122.00 / Below target` shape at YTD.

Requires an **owned** ledger, so a read-only public ledger cannot reach it. **All four ranges are now exercised** (see the table above). Not exercised: the per-point favorability colouring across future months, dark mode, enlarged Dynamic Type, and Android.

## Adjacent states

The rest of the screen behaves correctly and is worth recording. The `1Y` proration is exact to the cent. The variance colouring is right for an expense budget — under-spending shows green with "Below target", which is the favourable direction, and `select-budget-card-stats.ts` documents income inversion as the case most easily got wrong. The `Monthly` / `USD` chips, the `2 entries` disclosure and the `Update Budget` action all render.

`LY` rendering `Budget $0.00 · Actual $0.00 · Variance +$0.00 · On target` for a year in which the budget did not exist is self-consistent and **not** filed — `$0` against `$0` genuinely is on target, and `select-budget-card-stats.ts` already returns a `null` progress percentage when `budget <= 0`. Whether a non-existent budget should say "On target" at all is a copy question, not an arithmetic one.

Two things I checked and **did not** file. The leftmost axis label is clipped to a fragment (`I` at YTD, `ᴙ` at 1Y) — that is `ScrollableAxisChart` auto-scrolling to the most recent periods, so a partial label at the left edge is ordinary for a horizontally scrolled plot, not a defect. And `Liabilities:AccountsPayable` having a budget at all is unusual, but that is the subject of the open `w1/023` ("Add Budget offers every account type while its own help text says expense or income only") rather than something new here — it does corroborate that note from the mobile side.

## Dedupe

Searched all `.pm/**/*.md` including `done/` for budget, proration, `this-year`, YTD and future-period terms. **`w4/037`** (open, filed this run) is also about a "YTD" pill meaning the wrong thing, but on the balance/report charts and for a different reason — there `rangeStartMonth` anchors YTD to the *latest data point's* year; here `timeSpanToFilter` maps YTD to the *whole current* year. Different functions, different failures, both worth fixing. `w3/206` is budget-form accessibility; `w1/023` is the account-type question noted above. No item covers the budget range mapping.

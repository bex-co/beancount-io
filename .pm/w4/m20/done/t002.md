## Objective

Name all three Statistics tables and both read-only Settings tables from their existing localized headings, including consistent loading-to-settled associations without duplicate IDs.

## Context

See [FINDINGS.md](./FINDINGS.md) for reproductions, source, controls and evidence limits.

## Acceptance criteria

- [x] Postings per Account, Account Last Entries and Entries Count by Type expose their distinct visible names.
- [ ] Beancount Options and Fava Options expose their distinct localized names while public read-only permissions remain intact.
- [ ] Preserve filtered counts, account links, zero-percentage handling and independent loading/error/empty states.

## Out of scope

API/data changes, global Table defaults, new dependencies, unrelated control labels and a broad accessibility redesign.

## Outcome

All five remaining tables now take their name from the visible heading that
already identifies them, using the same `aria-labelledby` association as t001
and w3/m32 — no new translation phrase, no global `Table` default, no change to
values, links, sorting or permissions.

- **Statistics** — `postings-per-account.tsx`, `account-last-entries.tsx` and
  `entries-count-by-type.tsx` each mint a `headingId` with `useId` and put it on
  the `h3` beside the table. Each file does this **twice**, because the skeleton
  state renders its own heading-and-table pair and FINDINGS recorded that the
  loading branches repeat the omission; the error and empty branches render no
  table, so they are left alone.
- **Settings** — `beancount-options-section` and `fava-options-section` put a
  `titleId` on their existing localized `CardTitle`.

One mistake worth recording, because the live check is what caught it: in
`postings-per-account.tsx` the id first landed on the empty state's heading
rather than the one beside the table, since that component renders two headings
in different branches. The accessibility tree then showed the table still
unnamed with a dangling `aria-labelledby`, so the idref check failed. Moved to
the correct heading and the empty state left without an id, which it does not
need.

32/32 live checks over CDP at 1440x1000 and 390x844, on a production build:

- Statistics — `Postings per Account`, `Account Last Entries`,
  `Entries Count by Type`, all distinct, rows still 26 / 15 / 12;
- Settings — `Beancount Options` and `Fava Options`, distinct, rows still
  10 / 19;
- Budget and Commodities from t001 still named and distinct;
- every `aria-labelledby` idref resolves to exactly one element, and no page in
  the set has a duplicate id.

Gates from `dashboard/`: `yarn format:check`, `yarn lint`, `yarn test` (378
files, 4264 passed, 1 pre-existing skip) and `yarn build` all pass.

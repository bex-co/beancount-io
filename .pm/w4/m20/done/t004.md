## Outcome

Reviewed the m20 diff for reuse and simplification. The review's verification
pass found no id-placement mismatches — in all three Statistics files the
`id={headingId}` sits on the heading rendered in the same return branch as its
table, every `useId` is at component top level (including the one in
`postings-per-account.tsx`, called before its `totalRows === 0` early return),
and no unused imports were left behind.

Applied:

- **Cut seven duplicated comments.** The same two lines had been pasted six
  times across the Statistics files and twice more in the Settings sections,
  all restating what `ledger-data/AGENTS.md` now says once. The nine-line JSDoc
  on `ariaLabelledBy` came down to two. Net −28 lines of prose, +5 of code.
- **`ariaLabelledBy` is now required**, not optional. The reports precedent
  degrades safely (`ariaLabel ?? (ariaLabelledBy ? undefined : …)`); budget had
  no fallback, so an optional prop meant a second call site could compile clean
  and silently reproduce the unnamed table this milestone exists to fix. The
  contract now lives in the compiler rather than only in prose.
- **One definition of the commodity pair label.** `${base}/${quote}` was built
  independently three times — the chart, the visible `CardTitle`, and the
  history component whose `aria-label` it becomes. The table's accessible name
  matching its visible title was therefore a coincidence; `commodityPairLabel`
  makes it structural.

Not applied, and filed instead as [w4/145](../../145.md): the three Statistics
files repeat a whole section shell (heading + icon + description + the
overflow wrapper pair) six times, and the two Settings option sections are
near-clones. Collapsing either would mint the id once as a by-product, but both
are pre-existing duplication this diff only adds one line to, and the milestone
explicitly forbids a generic naming framework — so they are follow-up work, not
a blocker.

Rejected: extracting the association itself into a `useTableHeadingId()` hook or
a `<NamedTable>`. Three lines of `useId` / `id=` / `aria-labelledby=` wrapped in
a helper is exactly the generic naming framework this task's own out-of-scope
list rules out, and it would rename `useId` for no gain. The shared
`ui/table.tsx` `Table` is untouched, and no new translation key was added.

Also confirmed justified rather than inconsistent: commodities use `aria-label`
where the other six use `aria-labelledby`, because the `CardTitle` carrying the
pair is rendered inline inside a `.map()`, so there is no component boundary
where `useId` could legally be called. `AGENTS.md` already records that rule.

Gates from `dashboard/`: `yarn format:check`, `yarn lint`, `yarn test` (378
files, 4264 passed, 1 pre-existing skip) and `yarn build` all pass, and the live
checks are unchanged at 32/32 naming and 14/14 journey controls.

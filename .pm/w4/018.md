# m5 follow-up: ledger links do not open the app in production — the well-known files are 404

Severity: **major** residual in completed **w4/m5** ("Ledger links open in the app"); retain that existing finding group rather than counting this as unrelated discovery. **Estimate:** 20–30 minutes to set and verify, plus a store build for the device check. Owner: `deploy` / hosted configuration (not mobile, not a code change). A3: m5's stated outcome — "every README, gallery, and Telegram link becomes an entry point into the native app" — is inoperative today, while the board shows the milestone done.

**This is m5's own deferred check, now performed and failed.** Its closeout records: *"Production `https://beancount.io/.well-known/apple-app-site-association` still 404 until hosted `APP_LINKS_APPLE_TEAM_ID` is set; https Universal Links cannot verify before that. Physical-device UL check remains after the next store build (DoD)."* The milestone was closed with that check outstanding. It is still outstanding, and the capability does not work.

Environment: branch `main`, HEAD `038faeeb`, native development build `io.beancount.ios` on iPhone 17e / iOS 26.5, authenticated production session at `https://beancount.io`. Report-only QA; no ledger mutation.

## Repro

**A — warm app (decisive).** With the app running on `open_ledger/alphabet`:

```
xcrun simctl openurl <udid> 'https://beancount.io/ledger/open_ledger/minimax'
```

**Safari opens the web dashboard**, not the app — the minimax ledger page with `Log In / Sign Up`, `Star`, `Income Statement`, `Journal`, and net worth `1,346.683 MUSD`. The app's selection is untouched.

**B — cold app.** Terminate, fire the same URL, wait 30s, open the ledger drawer: the app is in the foreground on **`alphabet`** — the previously selected ledger — with `minimax` unselected. The ledger named in the URL was not opened.

**Working control:** the custom-scheme link `beancount:///ledger/open_ledger/minimax` switches ledgers correctly and has done so repeatedly throughout this session. So the in-app routing works; it is the https association that does not.

## Cause — deployment configuration, not code

Both well-known files are missing in production, verified directly:

```
https://beancount.io/.well-known/apple-app-site-association  → 404 (text/plain)
https://beancount.io/.well-known/assetlinks.json             → 404
```

Without a verifiable `apple-app-site-association`, iOS never associates `beancount.io` with the app, so an https ledger URL is just a web link. The Android side is equally blocked by the missing `assetlinks.json`.

The route is correct and the 404 is deliberate. `backend-cluster/backend-v2/src/features/well-known/api/well-known-route.ts:106-111` comments *"Unset env → 404 so a self-host without a native build does not advertise"*, and `src/config/config.ts:346` reads `process.env.APP_LINKS_APPLE_TEAM_ID`. The hosted deployment simply has not set it — m5's closeout names the exact value.

**The mobile code appears complete and correct** and is not implicated: `src/common/app-links/resolve-app-link.ts` accepts only `http:`/`https:` and maps ledger paths to hrefs; `use-app-link-handler.ts` covers cold start (`ExpoLinking.getLinkingURL`), the `getInitialURL` fallback, the warm `url` event, and stashes a pending target to replay after sign-in. None of it can run if iOS never hands the app the URL.

## Fix

1. Set `APP_LINKS_APPLE_TEAM_ID` on the hosted deployment so the well-known route serves both files, and confirm `application/json` content-type — m5's DoD requires that, and the current 404 returns `text/plain`.
2. Re-run m5's DoD bullet 1 end to end: `xcrun simctl openurl` with an https ledger URL should open the native ledger view, every resolver path should land on its screen, and a private ledger the account cannot read should fall back to the browser with the current selection intact.
3. Complete the physical-device Universal Link check m5 deferred, after the next store build — the entitlement needs a native rebuild, so a simulator pass alone does not close this.
4. Validate with Apple's and Google's checkers, as m5's DoD states.

Do not change the route's unset-env 404: it deliberately stops a self-host without a native build from advertising an association it cannot honour (and root `CLAUDE.md` forbids half-self-hosted seams). Do not weaken the mobile resolver to accept custom-scheme links as a substitute — the shared links that matter are https.

**Acceptance:** both well-known URLs return 200 with `application/json` on the hosted deployment; `xcrun simctl openurl` with `https://beancount.io/ledger/open_ledger/minimax` opens the app on minimax rather than Safari; the drawer shows minimax selected; and the deferred device check is recorded.

## Blast radius

Every https entry point m5 shipped: README, gallery and Telegram links, the Smart App Banner path on public ledger pages, and the **Share link / Copy link** actions in the app — which produce canonical https URLs (verified this session: `https://beancount.io/ledger/open_ledger/alphabet` and `…/entry/63e37c79d4a02c7cfaa844f0a27cd4e8`) that currently round-trip to the browser rather than the app. Android app links are blocked by the same missing file but were not exercised. Not exercised: signed-out link handling, the private-ledger browser fallback, and the resolver's other path shapes — all of which are untestable until the association verifies.

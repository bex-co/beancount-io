# Home's third chart tab has no nudge in Russian — the scrolling tab strip's own mitigation doesn't hold in every long locale

**Severity:** trivial. **Estimate:** 10–15 minutes. Owner: mobile. A3: in Russian the Home balance card shows `Чистые активы | Активы` and then the green `Показать все` link. `Обязательства` (Liabilities) is off-viewport with **nothing on screen suggesting it exists** — no clipped word, no scroll indicator, and the pager below cannot be swiped.

**This is not a request to stop the tab strip scrolling.** That is a deliberate, documented decision and it should stand — see "What is already settled" below. The narrow claim is that its stated mitigation — a partially visible next tab acting as a nudge — is absent in one class of locale, which the decision did not account for.

Environment: branch `main`, HEAD `038faeeb`, native development build `io.beancount.ios` on iPhone 17e / iOS 26.5, light, **default text size**, authenticated production session at `https://beancount.io`, `open_ledger/alphabet`. App locale forced via the persisted `locale` key (method in `w4/063`); restored afterwards. Report-only QA; no ledger mutation.

## Repro

| locale | Home balance card header | nudge? |
| --- | --- | --- |
| `en` | `Net Worth` · `Assets` · `Liabilities` · `See all ›` | n/a — all three fit |
| `de` | `Nettovermögen` · `Vermöge` · `Alle ansehen ›` | **weak** — `Vermögen` is cut mid-word with no ellipsis, directly against a green link, so it reads as breakage rather than as "scroll me" |
| `ru` | `Чистые активы` · `Активы` · `Показать все ›` | **none** — `Активы` renders complete, the row simply ends, and nothing hints at a third tab |

Russian is the sharper case precisely *because* nothing is clipped.

## Why it happens, and why it is locale-shaped

`src/components/segmented-pages/index.tsx:29-34` states the trade-off and names the exact language:

> *"The tab strip scrolls horizontally: at 16px three labels can outrun the screen in longer locales (de: "Net Worth" + "Vermögen" + "Verbindlichkeiten"), and truncating a tab name reads worse than a nudge."*

The strip is a horizontal `ScrollView` with **`showsHorizontalScrollIndicator={false}`** (`:138`), so the only cue is whatever of the next label happens to fall inside the viewport. Whether there *is* such a cue depends on where the label boundaries land, which is a property of the translation, not of the design:

| locale | net worth + assets + liabilities, in character widths (CJK counted double) |
| --- | --- |
| `de` | **38** |
| `pt` | 32 |
| `ru` | 32 |
| `uk` | 30 |
| `es` | 29 |
| `fr` | 27 |
| `en`, `bg`, `ca`, `nl` | 26 |
| `sk`, `fa` | 25 |
| `zh` | 14 |

`de` overflows hardest and lands mid-word, which produces a nudge by luck. `ru` overflows by less and lands on a word boundary, which produces none. Five locales sit above English; `en`, `zh` and the short ones are unaffected.

**And the tab strip is the only route.** `PagerView` is mounted with `scrollEnabled={false}` (`:175`) — sensibly, since `InteractiveLineChartD3` owns horizontal drags for scrubbing — so the chart area cannot be swiped between pages. A Russian user who never drags the label row never learns that Home has a Liabilities chart.

The tab itself is rendered, not dropped: `account-charts-card.tsx:151-155` always builds three `charts` entries and `tabs={charts.map(({ key }) => t(key))}` maps all three into the `ScrollView`. It is off-viewport, not absent.

## What is already settled, and should not be re-opened

**`w3/done/171`** (closed) covers Home → Liabilities at **maximum text size** in English and records: *"the **deliberate** horizontal tab strip can be scrolled to reveal the tab; actual tap succeeds."* That is the same mechanism, the same conclusion, and it is closed. Nothing here disputes it: the strip should keep scrolling, the tab should stay reachable by dragging, and truncating a tab name is still worse than a nudge.

The gap this note adds is only that `w3/done/171` observed the enlarged-text case (where the overflow is large and a partial label is guaranteed) and the source comment reasoned about `de` (likewise). Neither considered a locale that overflows *just enough* to hide a tab cleanly.

**At enlarged text the German case degrades from "one tab hidden" to "two"** (September 14, `content_size accessibility-medium`): the row reads `Nettovermö` — the *selected* tab now clipped mid-word — followed immediately by `Alle ansehen ›`. Both `Vermögenswerte` and `Verbindlichkeiten` are off-viewport, so two of the three charts have no visible presence at all. This does not change the fix; it raises how much the missing affordance costs, and it is the configuration `w3/done/171` was looking at when it recorded the strip as scrollable-and-therefore-fine in English.

## Fix

Make the affordance independent of where the translation happens to break. Cheapest first:

1. **Turn the scroll indicator back on for this strip** — `showsHorizontalScrollIndicator={true}`. One prop, no layout change, and it is honest: there *is* more content. The reason it is off is presumably aesthetic, and that is a fair trade to revisit given it is the only cue.
2. Or add a short **edge fade** on the trailing side of `tabsScroll` when the content overflows, which is the more polished version of the same signal and does not depend on iOS's transient indicator behaviour.

Either is preferable to shortening the translations: `Обязательства` and `Verbindlichkeiten` are the correct words, and the app should not compress its own vocabulary to fit a row.

**Do not** fix it by enabling `PagerView`'s `scrollEnabled` — that would contest horizontal drags with the chart's scrub gesture, which is what `useHorizontalSwipeOwnerGesture` exists to arbitrate (and see `w3/191`, which is an open crash in exactly that machinery).

**Acceptance:** on `ru`, `de`, `pt`, `uk` and `es`, the Home balance card shows some visible signal that the tab row continues; `en` and `zh`, where all three tabs fit, gain no stray indicator or fade; the tab strip still scrolls and the tab still taps; and `PagerView` stays `scrollEnabled={false}`. A snapshot test at a fixed width for `en` and `ru` would pin both sides of that.

## Blast radius

One component, one prop. `SegmentedPages` has exactly **one** consumer — `home-screen/components/account-charts-card.tsx:182` — so the change cannot reach any other screen.

Not exercised: **whether the strip can actually be dragged here**, because the pinned Expo MCP has no scroll or drag tool (**`w4/020`**); `w3/done/171` establishes that it can at maximum text size, and I am relying on that rather than re-demonstrating it. Also not exercised: dark mode (irrelevant to layout, but unchecked), enlarged Dynamic Type in these locales — which makes the overflow larger and therefore probably *restores* the nudge — RTL (`fa` is the shortest locale here, so it likely never overflows), and Android.

**A small verification gap worth recording:** `automation_find_view` requires a `testID`, and the tabs carry only `accessibilityRole="tab"`, so the off-screen tab could not be confirmed through the tool — its presence is established from source instead. This is another instance of **`w4/020`**'s missing-`testID` list and belongs on it.

## Adjacent states

The rest of the localized Home is **good** and is worth recording as verified in both languages at default text size: the header (`Startseite` / `Главная`), the card title (`Letzte Transaktionen` / `Последние транзакции`), the tab bar (`Startseite·Konten·Transaktionen·Berichte·Dateien`, `Главная·Счета·Транзакции·Отчеты·Файлы`) and the `See all` links all render fully without clipping. The range pills also fit in both, including Russian's notably long `С нач. года` for YTD — that row is the non-scrollable `TimeRangePills` variant and it still had room, which is a useful negative result for `w4/062`'s neighbourhood.

## Cause and bounded repair

`dashboard/src/features/reports/overview/lib/account-categorizer.ts:44–58` recognizes literal English Income/Equity and the literal-root `ROOT_CATEGORIES`; an unrecognized prefix returns `exclude` before `resolveCashFlowRole`. `sankey-data-transformer.ts:43–47,71` uses that result while descending the hierarchy, so every renamed branch disappears, including leaves with valid explicit roles. `cash-flow-sankey.tsx:57–66` and `overview/index.tsx:409` pass typed hierarchy trees and metadata but no configured-root mapping. `sankey-colors.ts:61` shares the categorizer.

Resolve the account's accounting type using the ledger's configured roots (or the already typed hierarchy root identities), and carry it through the existing Sankey categorization, descendant aggregation and colors. Preserve original labels; configured Income remains the source, configured Equity remains excluded, cash leaves remain excluded, and declared activities keep precedence for eligible roots. Do not change the separate Cash Flow statement's documented fallback heuristics to repair this Overview consumer.

Acceptance: native desktop/narrow Overview renders the fixture's three flows and matching readable table after metadata settles; English-root output remains the control above. Meaningful regression coverage must exercise the complete transformer with configured roots, nested cash and declared activity leaves, and preserve existing units, ancestor postings, Income/Equity policy and honest pending/empty states. Run dashboard gates when implementing. This is dashboard interpretation of existing fields; no API capability or protocol change is needed.

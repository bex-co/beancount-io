# Keep keyboard focus after deleting a BQL history card

**Severity:** minor. **Estimate:** 35–50 minutes. **Owner:** dashboard. **A2:** removing a saved query should leave a visible query control focused so keyboard use can continue in the same workspace.

## Reproduction and controls

Production `https://beancount.io`,2026-10-22; owned isolated headless Chromium155.0.8059.85, anonymous public `/ledger/open_ledger/example/query`, English/light, fresh390×844 and1440×1000. Real read-only QueryShell results; no response substitution. History changes only in these disposable browser contexts.

1. Execute three harmless one-row queries through the actual editor and Execute Query button, waiting for each result and Monaco readiness. Use A/B/C variants of `SELECT 'qa-20261022-history-A' AS label LIMIT 1`; history becomes [C,B,A]. All three cards are loaded before the retained focus checks.
2. Focus B's **Delete query** and press Enter. B correctly disappears, its button disconnects, and history becomes [C,A]. After rendering settles, activeElement is **BODY**, with no query control focused. Both widths reproduce.
3. Native Tab then reaches A's summary. This next-tab continuation works; the demonstrated gap is the missing immediate visible focus handoff after deletion, rather than an assertion that Tab restarts at the page top.
4. Delete C and then the last remaining A. History becomes empty and the editor retains the exact C query, but focus again rests on BODY at both widths. The next Tab goes to **Journal** in Related Pages, outside the query controls.

Working controls: toggling A's cached disclosure keeps the same summary node focused and performs no new query. Explicitly refocusing the editor after the final deletion recovers keyboard editing with its exact text retained. QueryShell counts stay unchanged during deletion/recovery:3 at narrow width and4 at desktop, whose setup included one extra explicit run before measurement. No query is executed by Delete, and remaining data is removed/preserved as intended. Initial rapid desktop setup timing was corrected before the retained deletion cases and is not part of this finding.

## Cause and bounded repair

`dashboard/src/features/bql/components/query-result-card.tsx:392–399` calls onDelete(query) from the focused button. Page `pages/index.tsx:221–228` removes that history item and its results-cache entry; the card and focused button unmount, with no focus destination. The pure history hook correctly filters its stored array but has no UI ownership.

Keep the focus handoff in the originating query action/page. Choose a logical remaining query summary when a card is removed, using the existing unique query identity/order; after the last deletion, return to the mounted editor or another appropriate query control without changing the draft or executing it. Preserve remaining cards' identities, open states and caches, history ordering/storage, URL/bookmarks, query execution and Delete semantics. Do not add a global effect that focuses whenever history changes, which would interfere with ordinary execution/reordering. No API, dependency or backend change is needed.

Acceptance: with the real history hook/page/cards and loaded [C,B,A], native Delete of B focuses the selected remaining summary and retains [C,A] and their state. Deleting first/last/only items has a connected visible fallback; the final case retains exact editor text and starts no query. Cached toggles and the completed253 reorder behavior remain correct. Include a meaningful rendered lifecycle regression, repeat both widths and run dashboard gates when implementing. Pending deletions, other engines/locales and actual screen-reader speech remain unverified.

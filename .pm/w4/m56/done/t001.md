## Objective

Resolve supported CCE membership from complete unfiltered account definitions using the existing root, explicit-role, ancestor and fallback semantics. Build the bounded transaction cash-leg selection before activity intervals are requested.

## Files

- `dashboard/src/features/reports/cash-flow/lib/` and existing query definitions used for account metadata.
- Owning pure helpers only; reuse existing shared infrastructure.

## Acceptance criteria

- [x] The public trip example resolves its three CCE accounts even though the filtered closing hierarchy contains none.
- [x] Compose an exact-member existing FQL predicate; preserve literal account names, quote/regex escaping and parentheses around user OR filters. Keep the user's visible filter unchanged.
- [x] Support the existing eligible declared/ancestor cash and noncash overrides, renamed roots and historical accounts; reuse the existing resolver rather than parallel classification rules.
- [x] Distinguish resolved-empty membership from pending/failed membership. No all-transaction fallback or new dependency/API is introduced.

## Verification

- `cash-flow/lib/model.ts` gains `cashAccountMembership`, which resolves the cash set from the ledger's complete account list (including closed accounts). It walks each asset account's ancestor prefixes through `cashSourceOf`, the declared-role / ancestor / name rule now shared with `collectCashAccounts`, so there is no second classifier. Renamed roots are read as their type.
- `cash-flow/lib/cash-eligibility.ts` adds `cashActivityFilter(filter, accounts)` → `(filter) any(account:"^A$", account:"^B$", …)`:
  - one regex-escaped exact pattern per account keeps each under the engine's 256-character pattern limit (FQL quoted strings have no escapes, so regex escaping is the only escaping);
  - the reader's filter is parenthesized, so its `,` OR stays inside;
  - an empty cash set gives `any(account:"^$")`, which matches nothing;
  - the visible filter is unchanged.
- `cash-eligibility.test.ts` covers the public example's three cash accounts (which the filtered closing hierarchy lacks), declared/ancestor overrides, renamed roots, the empty set, OR precedence and escaping.
- Pending or failed membership is handled by the page and loader (t002). No dependency or API change.

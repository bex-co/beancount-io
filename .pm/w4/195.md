# Give the avatar action a meaningful name at each viewport

Severity: **minor**, dashboard accessibility. Estimate: **30–45 minutes**. A2 — readers should be able to find account settings and appearance controls by their accessible action names.

## Reproduce

Production `https://beancount.io`, 2026-10-08 America/Los_Angeles; QA-owned isolated headless Chromium, English, System theme. Source inspected at main `b5258053`; deployed module `main-GcCTaQbi.js`, deployed commit unknown. Authenticated public-ledger reader; no account or ledger changes.

1. Fresh-load `/ledger/open_ledger/example/journal` at 1440×1000 after the user-profile read settles.
2. Inspect the header avatar button in Chromium's native accessibility tree. Its name is only the account's single initial. DOM `aria-label`, `aria-labelledby` and `title` are all absent; `aria-haspopup="menu"` is present.
3. Focus the button and press Enter. It opens the menu containing Settings, Stars, Theme, Language and Logout. Escape closes it and returns focus correctly.
4. Fresh-load the same public route at 390×1000. The avatar is again named only by the initial, now with no `aria-haspopup`. Focus it and press Enter: it navigates directly to `/settings`.

Expected: the desktop trigger has a localized action name such as **User menu**; the narrow direct-navigation button names **Settings**. An account initial is visual identity, not a description of either action. Preserve the distinct desktop/narrow behavior and keyboard focus contract.

Actual: both different actions expose the same single-letter accessible name. The narrow button gives no indication that it leads to Settings; the desktop name does not identify the account menu or its controls.

# Identify the invalid BQL column instead of showing only generic input guidance

Severity: **minor**. Package: **dashboard**. Estimate: **50–60m** for the
reproduced unknown-column case, localized guidance, and regression coverage.
Source: continuous dashboard QA requested for w4. **A2**: a newcomer should be
able to correct a query from the feedback in the query editor.

## Reproduction and evidence

Production `https://beancount.io`, public synthetic `open_ledger/example`,
anonymous reader, English/light, owned isolated headless Chromium
149.0.7827.55. Reproduced at 1440×1000 and 390×844. Local main
`390568c220bfbdb0df1c9decb8436c64dfa3c9ca`; deployed entry asset
`main-d5j4FX-V.js`. Exact deployed SHA is unverified; the implicated mapper and
consumer remain unchanged in local HEAD, so no local correction was found.

1. Open `/ledger/open_ledger/example/query`.
2. Enter `SELECT nonexistent_column LIMIT 1` and click **Execute Query**.
3. The query card displays only: “Some of the information provided is invalid.
   Please check and try again.” It never identifies the invalid column.
4. Reload the resulting `?query=SELECT+nonexistent_column+LIMIT+1` URL. The same
   result recurs. Resize to 390px: the same alert remains the sole explanation.
5. Working control: execute `SELECT account LIMIT 1`. The table contains
   `Assets:US:BofA:Checking`; its downloaded CSV contains the same header and row.

The real `QueryShell` request returns HTTP 200 with `data.queryShell: null` and
`extensions.code: BAD_USER_INPUT`. Its message is:

```text
Invalid BQL query: Query execution error: column 'nonexistent_column' not found
```

No application console/page errors accompanied the failure. This is neither a
network outage nor an empty successful result. No synthetic response was used.

Verified local evidence under `dashboard/tmp/qa-20260921-loop/`:

`bql-error-reproduction.json`, `bql-invalid-reload.png`,

## Cause and bounded repair

`dashboard/src/features/bql/components/query-result-card.tsx:311–314` routes
every query error through `getErrorMessageKey`. The shared mapper at
`common/lib/errors/error-message.ts:19,39–45` intentionally reduces all
`BAD_USER_INPUT` errors to one generic localized sentence. That safe default is
appropriate for unknown server failures but loses the editor's correction
information in this known query-validation case.

Producer: `backend-cluster/ledger/src/features/ledger/service/ledger-shell-service.ts:127–133`
classifies the engine's query errors as bad input. Backend-v2
`features/ledger/service/ledger-shell-service.ts:62–65` unwraps that result;
`features/ledger/api/resolvers/ledger-shell-resolver.query.ts:86–94` delegates
to the service. `server/graphql/format-error.ts:65–76` preserves domain error
messages and categories. The live response proves that the column diagnostic
reaches the browser.

Add narrowly classified, localized unknown-column feedback in the BQL feature,
identifying the offending query identifier and telling the user to check its
spelling/available columns. Preserve the shared mapper's safe fallback. Do not
render arbitrary server messages, stack traces, HTML, or service errors, and do
not loosen the global error policy. Keep the repair scoped to the demonstrated
unknown-column diagnostic; a general structured diagnostic API is separate work.
No API contract or engine behavior change is required for this bounded case.

One production `QueryResultCard` caller exists, in `features/bql/pages/index.tsx`;
the current query, bookmarked query, and reopened history cards share it.
Other shared-mapper callers are outside this fix.

- [ ] The exact failing query identifies `nonexistent_column` in useful,
      localized editor feedback on initial execution and a fresh URL load.
- [ ] The corrected query still renders/downloads the matching row; failed
      queries never look like zero-row successes or reuse a successful table.
- [ ] A rendered regression check covers the known bad-column response and
      verifies that unknown bad-input, service, and internal errors retain safe
      generic feedback, including HTML-like diagnostic input.
- [ ] Pending and subsequent successful execution stay usable at desktop and
      narrow widths. Run the dashboard gates when implementing.

## Objective

Translate the half-translated Ukrainian messages in `ledger-data`: `statistics` (6), `documents` (2), `events` (1), `settings/visibility-section` (2), `settings/danger-zone-section` (1), `errors` (1) so the shipped
strings read as Ukrainian rather than as a word in neither language.

## Context

- The damage is a translation pass that replaced a leading token and left the
  rest: sometimes the first word, sometimes only the first *letter*.
- Examples in this cluster: `page.documents.documents` = `Вocuments`, `page.documents.filename` = `Файлname`, `page.statistics.lastEntryDate` = `Пast Entry Date`, `page.settings.publicLedger` = `Публічний Ledger`, `page.errors.errors` = `Помилкаs`. The `beancount`/`fava-option` hits in the options descriptions are false positives.
- Bulgarian (`bg.ts`) is the cleanest reference catalog for the same keys; `en.ts` is the source of truth for meaning.
- Keep as notation: brand names, Beancount directive and metadata keywords,
  currency codes, and literal account names used as placeholder examples. The
  allowlist in `dashboard/src/features/journal/components/__tests__/russian-journal-labels.test.tsx` is the current list.

## Steps

1. Diff the cluster's `uk.ts` against `en.ts` and list the messages that mix Cyrillic with a stray English word.
2. Translate each one, checking `bg.ts` for the same key where the phrasing is not obvious.
3. Confirm no key was added, removed or renamed, and that `{placeholder}` interpolations survive.
4. Run `yarn format:check`, `yarn lint`, `yarn test` from `dashboard/`.

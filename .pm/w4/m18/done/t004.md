## Objective

Remove duplicated height/visibility state or formatter logic introduced by the repair. Preserve one shared amount formatter and one clear local owner for cell presentation.

## Context

See [FINDINGS.md](./FINDINGS.md) and the milestone definition of done; preserve w3/m28/m37 behavior.

## Files

Changed BQL renderer/presentation code

## Acceptance criteria

- [x] No overlapping fixed-height workaround, global style override, duplicate formatter, unnecessary abstraction or new dependency remains.

## Out of scope

Backend/API changes, Holdings layout changes, financial rounding policy, new dependencies and unrelated BQL copy fixes.

## Outcome

Ran `/simplify` over the m18 diff with four independent review angles (reuse,
simplification, efficiency, altitude). Reuse found nothing to report: the
component already delegates all amount formatting to the shared
`common/lib/format/inventory-cell.ts`, the only other react-window consumer
(`diff-viewer`) sizes rows from two constants and has nothing to share, and
`ui/table.tsx` is a semantic `<table>` primitive that cannot host a virtualized
rowgroup.

Applied:

- **The table moved into its own `QueryResultTable` component.** It owns the
  height measurement, so a card showing an error, a text result or nothing at
  all no longer allocates a ResizeObserver and a height map, and a row
  measurement re-renders the table rather than the whole card — its summary,
  export button and chart included. This was the one clear owner for cell
  presentation the task asked for.
- **`headers`, `dtypes` and `rows` are memoized, and `rowProps` with them.**
  react-window memoizes `rowProps` by value and rebuilds its cached row bounds
  when that changes; rebuilding those arrays every render discarded the cache
  on every measurement pass, which the fixed-height version never triggered.
- **The row component moved to module scope.** An inline `rowComponent` is a
  new element type each render, so react-window's `memo` wrapper remounted
  every rendered row on each measurement pass instead of updating it.
- **One `COLUMN_CLASS` constant** now defines a result column for the header and
  the body together, so a presentation rule cannot apply to only one of them —
  which is exactly how the whitespace rule had landed in t002.
- **The height-cache key dropped to the row count.** The parent already keys
  each card by its query, so `query` never changes within a mounted card and
  the interpolated string promised an identity it did not track.
- **Comment and mock trims.** Roughly sixteen lines of commit-message narrative
  came out, and the react-window test double no longer stubs `getRowHeight`
  and `setRowHeight`, which nothing calls.

Rejected, with reasons rather than argument:

- **Sizing the list by `maxHeight` alone** and letting react-window's own sizer
  own the box. `List` skips observing its root whenever `style.height` is set,
  so dropping the height makes the viewport depend on a measurement JSDOM
  always reports as 0 — the mechanism would become unverifiable in tests, and
  self-referential in the browser. The existing form is also exact where it is
  used: every row of a result short enough to fit under the cap is rendered and
  measured, so their average times their count is the true total, and any
  taller result has the value discarded by the cap.
- **Removing `overflowX: "hidden"` from the list** as a `truncate`-era leftover.
  It is the column-alignment contract from w3/m28/m37 — a second horizontal
  scroll owner would slide the body out from under the header — and the
  existing test at `query-result-card.test.tsx` asserts it. Restored, with a
  comment saying why it is there.
- **Collapsing the multi-unit inventory stack into the formatter's text.** The
  formatter's CRLF join exists for CSV, and Holdings renders the same data as
  one element per unit from the same shared helper. Reusing the CSV shape for
  the screen would have put `\r` into the DOM and diverged from Holdings; the
  m37 test caught it. The formatter was never duplicated — both paths call the
  shared module — so the acceptance criterion holds without this change.

No new dependency, no global style override, no fixed-height workaround and no
new abstraction beyond the one component the task called for.

## Objective

Implement consistent variable sizing or an explicit accessible full-cell presentation so content never silently disappears. Keep row and viewport calculations aligned and ordinary cells compact.

## Context

See [FINDINGS.md](./FINDINGS.md) and the milestone definition of done; preserve w3/m28/m37 behavior.

## Files

query-result-card.tsx and minimal local presentation helpers

## Acceptance criteria

- [x] The eight-unit inventory is fully inspectable at390 and1440 without overlap or broken scrolling.

## Out of scope

Backend/API changes, Holdings layout changes, financial rounding policy, new dependencies and unrelated BQL copy fixes.

## Outcome

`query-result-card.tsx` no longer fixes rows at `ROW_HEIGHT`. It uses
react-window 2.2.5's own `useDynamicRowHeight` cache (already installed, so no
new dependency): rows render at their natural height, the list measures them,
and the viewport is sized from the same measurements
(`rows.length * getAverageRowHeight()`, still capped at `CONTAINER_HEIGHT`)
instead of `rows.length * 36`. The cache is keyed by query + row count so
heights measured for one execution never size the next one's table.
`ROW_HEIGHT` survives as the compact default and the pre-measurement guess.

Reproduced first, on the built unfixed code: the eight-unit
`SELECT sum(position) WHERE account ~ '^Assets'` cell measured
clientHeight 35 / scrollHeight 157 at 1440x1000 and 35 / 153 at 390x844 — only
`3609.87 USD` visible, seven units clipped. After the change the same cell
measures 157/157 and 153/153: every unit readable at both widths.

Live geometry checks against a production build, 30/30 at both widths:

- the reproduced single-row inventory — no clipped cell, no overlapping rows,
  body columns aligned to the header within 1px, and the viewport fits the
  content exactly (158/158 desktop, 154/154 narrow);
- eleven multi-unit inventory rows in one table
  (`SELECT account, sum(position) ... GROUP BY account`) — nothing clipped or
  overlapping before or after scrolling to the last row, so the fix is not
  limited to the one-row container;
- the FINDINGS large-result control `SELECT date, account LIMIT 1001` —
  `aria-rowcount` 1002, ordinary rows still compact (37px desktop, 33px
  narrow), only 20–25 rows rendered so virtualization is intact, the viewport
  still capped at 600px, and later rows reachable without overlap.

Gates from `dashboard/`: `yarn format:check`, `yarn lint`, `yarn test` (376
files, 4247 passed, 1 pre-existing skip) and `yarn build` all pass. The
component's unit test mocks `react-window`, so the mock gained a
`useDynamicRowHeight` stub — JSDOM reports every box as 0, so real geometry is
covered by the browser checks above and by t005 rather than there.

Horizontal flattening of newline-bearing PRINT strings is untouched here and
belongs to t002.

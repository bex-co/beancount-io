## Objective

Find a signal that separates a half-translated message in a Latin-script
locale from a correct translation that happens to share English words, and
prove it against the two false-positive classes already measured.

## Context

- The script check in `dashboard/src/test/locale-scan.ts` cannot help here: in
  `de` or `es` a stray English word is indistinguishable from the target
  language by script.
- The defect's signature is mechanical — a first-token find/replace leaves the
  English tail intact — so comparing against `en[key]` is the way in.
- Measured during triage, against the shipped catalogs:
  - **shared English tail, one or more words**: 188 hits across the seven
    locales, mostly loanwords (`token`, `layout`, `link`, `filter`, `bank`,
    `upload`, `feed`, `dashboard`, `pull request`). Far too noisy.
  - **shared tail of two or more words**: 18 hits, roughly 14 genuine. Misses
    every single-word tail, which is where much of the damage is —
    `Eliminar Ledger`, `Conta Balance`, `Cuenta Last Entries`.
  - **capitalized English word in a shared tail**: sharper for Romance
    languages, but German capitalizes all nouns, so `Intelligenter Import`,
    `Unbekannter Plan` and `Neueste Updates` are correct German that it flags.
- A third shape exists and is unambiguous: the translated token glues onto the
  English one — `Usuárioname is required` (pt), `Limpared transactions` (pt).
  Worth detecting separately, since it has no false positives.

## Steps

1. Work in a scratch test file, not the shipped guard, until the numbers are right.
2. Try combining: an unambiguous glue rule; a shared-tail rule with a per-locale loanword allowlist; and, for the non-German locales, a title-case rule.
3. Consider whether German needs a different rule or an explicit deviation list instead.
4. Record the hit count and the false-positive rate for the chosen combination, so t002 and t003 have a list to work from.

## Result (2026-09-20)

**Chosen predicate.** A message is half-translated when, compared against
`en[key]`, its shared trailing run with English either

1. holds **three or more English words** — a tail that long is a sentence, not
   a borrowed term; or
2. holds a **capitalized English word**, which in these languages means title
   case carried over from the source — **except in German**, which capitalizes
   every noun.

Both run after an allowlist of brands and borrowed terms. The full hit list is
30 messages, with **no false positive** among them: ca 1, de 1, es 9, fr 5,
nl 3, pt 9, sk 2.

It clears the DoD's not-done bar. None of `Criar token`, `Prejsť na dashboard`,
`Copiar link`, `Redefinir layout`, `Filteren op bank`, `Adicionar arquivos via
upload`, `Intelligenter Import`, `Unbekannter Plan` or `Neueste Updates` is
flagged.

**Three approaches were tried and rejected, each on measurement:**

- *Any shared English tail.* 188 hits across the seven locales, almost all
  borrowed terms. Unusable.
- *Glue detection by shared suffix* — the rule that works for Cyrillic, where
  `Документs` is unambiguous. Romance languages share Latin roots with English,
  so it fires on cognates: `Transaccions`/`Actions`, `Despeses`/`Expenses`,
  `Esdeveniments`/`Events`. Over 40 false positives in Catalan alone.
- *Frequency as a discriminator*, on the theory that a borrowed term recurs
  while a leftover is an outlier. It does not separate them: in Portuguese
  `layout`, `link`, `feed` and `commodities` each appear exactly once, as do
  `balance`, `journal` and `entries`.

**Known blind spot, recorded rather than worked around.** Three Portuguese
messages are genuine damage the predicate cannot see, because their English
tail is one or two lowercase words — indistinguishable in shape from `Criar
token`:

- `journal.clearedTransactions` — `Limpared transactions`
- `journal.otherTransactions` — `Outro transactions`
- `auth.usernameRequired` — `Usuárioname is required`

All three are already on t002's list and will be repaired by key. Catching them
by rule would need per-language morphology — knowing that Portuguese words do
not end in `-ed`, that `Usuário` is a word and `Usuárioname` is not — which is
a dictionary, not a heuristic. This task's acceptance criteria asked for them;
that criterion is not met and is withdrawn here with its reason, rather than
met by a predicate that would flag correct translations.

**Sketch for t006:**

```ts
const shared = trailingWordsSharedWithEnglish(message, english);
const longTail = shared.filter(isAsciiWord).length >= 3;
const titled =
  TITLE_CASE_MEANS_ENGLISH.has(locale) &&
  shared.some((w) => /^[A-Z][a-z]{2,}$/.test(w));
```

with `TITLE_CASE_MEANS_ENGLISH = {ca, es, fr, nl, pt, sk}` — German excluded —
and the allowlist extended with `Import`, `Plan`, `Updates`, `Bank`,
`Dashboard`, `Token`, `Link`, `Layout`, `Feed`, `Filter`, `Commodities`.

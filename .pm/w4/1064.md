**Severity:** minor financial display/export. **Estimate:** 35–50 minutes, dashboard. **A2:** changing a Holdings grouping must not make held units disappear just because both their cost and current quote are zero. Remaining zero-quote coverage from former W3/036.

## Reproduce

The minimal valid fixture declares USD as operating currency, opens a QAFREE asset account and USD equity account, then records:

```beancount
2026-01-02 * "qa-20261024 free holding"
  Assets:QaFree 10 QAFREE {0 USD}
  Equity:QaFreeOpening 0 USD
2026-10-01 price QAFREE 0 USD
```

1. Open `/ledger/open_ledger/example/holdings?lang=en&view=holdings` with only the matching QueryShell replies replaced by that fixture's producer results. Default Holdings displays **10 QAFREE**, cost0, price0. Its real CSV retains those ten units. Select **Holdings by Account**: the position also remains.
2. Select **Holdings by Currency** with the desktop tab or narrow **View** combobox. The response contains exactly `[{"QAFREE":"10"},"0","0",{},{},"0"]`, but the settled page says **No data returned from query**, with no table or Export CSV action.
3. Select **Holdings by Cost Currency**. The response contains `[{"QAFREE":"10"},{},{},"0"]`; the page again shows the false empty result.

Both fresh widths reproduce the same four-view transition. This is loss of displayed/exportable positions, not a changed valuation or stored ledger loss.

The mixed fixture adds one QACONTROL unit at cost10 USD and quote20 USD. By Currency returns two nonempty inventories, but the page counts and displays only QACONTROL. Its actual downloaded CSV has only that row and omits QAFREE at both widths. Default/by-account tables and CSVs retain both positions. By Cost Currency aggregates both into one USD-cost group with nonzero book/market values, and correctly retains both commodities there; that differential follows the predicate below.

Working controls at both widths: cost0 with quote1, and cost10 with quote0, retain their position in every grouping and downloaded CSV. A fully closed position has an empty units inventory and correctly disappears from all four views. Its source fixture includes a price, but the engine's returned closed-group price is0; no known-positive-price-only closed-row native claim is made. Ten retained contexts cover forty modeled reads and twenty-eight actual CSV downloads, independently parsed to match the displayed rows.

## Cause and bounded repair

`dashboard/src/features/ledger-data/holdings/utils.ts:212–220` defines `unitsFirstRowsFilter` as `!isEmpty(row[0]) && !row.slice(1).every(isEmpty)`. The units inventory in column0 is correctly nonempty, but all subsequent cells are zero or empty, so the second condition drops a real position. `holdings/index.tsx:86,95` supplies this predicate to By Currency and By Cost Currency. Account-first filtering includes its units column among the later cells, explaining the passing by-account control; the default lot view also retains its nonempty units.

`holdings-table.tsx:77–79,104–106` applies the same supplied filter to export and rendering, so the mixed CSV omission follows the same cause. The engine serializer intentionally removes zero-net currency keys (`backend-cluster/ledger/src/features/ledger/service/ledger-shell-mappers.ts:44–58`); the nonempty QAFREE inventory is still present. No query, backend, serializer or eligible REST/GraphQL/MCP behavior needs changing.

Make the units-first predicate retain legitimate nonempty unit inventories independently of other cells' valuation. Keep truly empty/sold groups excluded, including remembered-price-only groups, without treating an explicit zero quote as absence of units. Preserve exact positive/negative/small quantities, all four column layouts, row navigation, selected view/count, financial formatting and the shared screen/export filter. No dependency, cross-feature abstraction or API change is needed.

Acceptance: the real DatasetTable and owning grouping controls retain the supplied free/zero-quoted position in both grouped views, counts and parsed CSV; the mixed By Currency export contains both positions. Cover empty units with a surviving price, true closed units, zero versus positive cost/quote, and the unchanged default/account-first views through the real caller. Repeat native controls at both widths and run dashboard gates on implementation. No product fix or formal regression test was authored during QA.

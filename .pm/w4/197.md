# Name the Net Worth valuation details popover

Severity: **minor**, dashboard accessibility. Estimate: **20–30 minutes**. A2 — readers should be able to identify the price-details window behind the Net Worth figure.

## Reproduce

Production `https://beancount.io`, 2026-10-08 America/Los_Angeles; QA-owned isolated headless Chromium, English, System theme. Authenticated reader of the public stock example; no ledger/account writes. Source rechecked after pulling main `408b2690`; production module `main-GcCTaQbi.js`, deployed commit unknown.

1. Fresh-load `/ledger/open_ledger/stock-example?time=2026-05` at 1440×1000 and wait for the financial-position card to settle.
2. Focus **At market value. Valuation details** and press Enter. Wait for the popover's opening animation to finish.
3. Chromium's native accessibility tree exposes an unignored `dialog` with `name: ""`. The content has `role="dialog"`, with neither `aria-label` nor `aria-labelledby`, despite its visible **Valuation details** title.
4. Escape closes it and returns focus to the correctly named trigger. Repeat from a fresh load at 390×1000: the same unnamed dialog appears; close/focus return still work, with no horizontal page overflow.

Expected: the dialog itself has the localized **Valuation details** name. [WAI-ARIA's dialog role](https://www.w3.org/TR/wai-aria-1.2/#dialog) requires an accessible name for nonmodal as well as modal dialogs. Naming the trigger does not name its dialog.

Actual: the title remains plain content, so assistive technology receives no programmatic window identity. The listed holdings and **Update prices** link are readable; this finding does not claim that price data is missing or keyboard access is broken.

## Evidence and repair scope

Ignored `dashboard/tmp/qa-20261008-loop/valuation-dialog-name.json` records native role/name, missing naming attributes, settled content, close/focus controls and both widths. Screenshots `valuation-name-1440.png` and `valuation-name-390.png` show the visible title; the narrow screenshot was inspected. No new browser exception occurred. The nearby **Report filters** sheet was independently opened and correctly exposes `dialog "Report filters"`.

`dashboard/src/features/reports/overview/components/net-worth-card.tsx:144–151` renders NetWorthValuationNote's PopoverContent without a name, followed by an unassociated paragraph containing the existing translated `page.overview.valuationDetails`. `common/components/ui/popover.tsx:20–41` forwards supported attributes to Radix content. This is a caller omission, independent of API results.

Associate that visible title with the PopoverContent using a stable unique ID and `aria-labelledby`, or use the existing localized title as its explicit name. Keep the trigger's separate label, per-holding prices/statuses, selected time/account filters, Update prices destination, responsive placement and Escape/focus return. Do not assign a global default name to every Popover or alter valuation calculations. NetWorthCard has one application caller, `features/reports/overview/index.tsx:274`; other ledgers reuse it but were not independently exercised for this defect.

Acceptance: settled valuation details is discoverable as a named dialog at both widths; a real-component role-and-name assertion fails when the association is removed. Preserve opening/closing/focus controls and existing price-state tests. No new translation, API, dependency or cross-package change is needed; run normal dashboard gates when implementing.

# Name the active Holdings table for its selected grouping

Severity: **minor**, dashboard accessibility. Estimate: **30–45 minutes**. A2 — public-ledger readers navigating by table should be able to identify whether a holdings result is grouped by lot, account, currency, or cost currency.

## Reproduce

Production `https://beancount.io`, 2026-10-08 America/Los_Angeles, QA-owned isolated headless Chromium, English/light. Source inspected at main `4c88ed15`; deployed client module `main-GcCTaQbi.js`, deployed commit unknown. Reads use the same-origin `/api-gateway/`. A signed-in reader of the public `open_ledger/example` ledger was used; no writes.

1. Open `/ledger/open_ledger/example/holdings?view=holdings` and wait for the result table, not the loading state.
2. Inspect the native Chromium accessibility tree. The visible table has role `table`, `ignored: false`, and accessible name `""`.
3. Repeat from fresh loads with `view=by-account`, `view=by-currency` and `view=by-cost-currency`.
4. Repeat all four at 390×1000 after the 1440×1000 checks. The same empty table name occurs in every case.

Expected: the table's accessible name identifies its selected grouping using the existing localized Holdings labels. `dashboard/src/features/ledger-data/AGENTS.md` explicitly requires every table in this feature to have a meaningful accessible name.

Actual: the grouping is named on the desktop tab panel or narrow View control, but the table itself has no accessible name, caption, `aria-label`, or `aria-labelledby`. Readers navigating directly between tables lose that identity.

## Evidence and controls

Settled header-inclusive row counts agree at both widths: Holdings 116, by Account 12, by Currency 9, by Cost Currency 3. CSV export remains enabled, native rows/cells are present, and there were no browser errors or failed HTTP requests. This finding does not claim a calculation, result-count, export, or row-semantics bug.

Working control: expand GLD/USD history at `/ledger/open_ledger/example/commodities`. Chromium exposes the populated table as `{"name":"GLD/USD","ignored":false}` with 142 header-inclusive rows. The same naming pattern can be applied without changing the data model.

Verified ignored evidence: `dashboard/tmp/qa-20261008-loop/holdings-names.json` records all eight fresh loaded views and native table names; `holdings-unnamed-390.png` is the visually inspected 390×1000 cost-currency grouping. The earlier `holdings-deep.json` contains some intermediate, unsettled row counts and is not the count evidence for this finding.

## Cause and repair

`dashboard/src/features/ledger-data/holdings/holdings-table.tsx:121` renders a bare `<Table>`. `DatasetTableProps` at line 26 has no name/heading association, and the four application callers in `holdings/index.tsx:77,85,93,101` pass only query, ledger ID and row filtering. The shared Table primitive forwards attributes correctly; the omission belongs to Holdings.

Pass the existing localized grouping label to each DatasetTable and name its populated table with it, or associate the table with a stable visible heading for that grouping. Use valid stable IDs if choosing `aria-labelledby`; do not point it at a hidden/unmounted desktop tab after a narrow resize. Preserve query strings, ordered columns, row navigation, precision and CSV contents. Empty/loading/error states should remain honest states rather than inventing an empty named data table.

Acceptance: meaningful rendered tests find each populated grouping by its accessible table name; browser checks confirm those names on fresh desktop/narrow loads and after grouping changes. Native table/row/cell semantics and account activation remain intact. Run the dashboard's normal gates when implementing. No API, schema, financial model, dependency or cross-package change is needed.

Dedupe: searched every `.pm` state for Holdings/DatasetTable combined with unnamed, table name, accessible name and aria-label. Read completed `w3/done/m25`'s full DoD: it preserves rows/cells and cell activation, not table names. `w3/done/m32` explicitly excludes Holdings. `w4/done/m20` names Budget, Commodities, Statistics and Settings tables, not Holdings. Grouping persistence (`w3/done/160`) and narrow export (`w3/done/150`) are working controls, not this defect. Targeted `git log -S aria-labelledby` for Holdings finds no implemented naming fix; recent table history preserves the bare Table. No overlapping open repair or deployment-only disposition was found.

Unverified: actual screen-reader speech, other browsers, additional locales, empty/error transitions and authenticated owner holdings. Those limits do not change the native empty-name evidence. No product code or server resources changed.

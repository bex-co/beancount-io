## Objective

Close the first blind spot: knip does not parse `.graphql` files, and `knip.jsonc` correctly exempts generated exports, so an unused operation passes the gate today. Add a small check beside knip that fails when an operation document has no consumer.

## Context

- `mobile/knip.jsonc` ignores `exports` and `types` under `src/generated-graphql/**`. That setting is correct and must stay.
- `mobile/package.json`: `"lint:deadcode": "knip --include files,exports,types"`; `yarn lint` runs it, and the repository-root `scripts/lint-deadcode.sh` runs each package's detector.
- A consumer is any reference to `use<Name>Query`, `use<Name>LazyQuery`, `use<Name>SuspenseQuery`, `use<Name>Mutation`, or `<Name>Document` under `src/` or `app/`, outside `src/generated-graphql/`.

## Steps

1. Write the check as a package script (for example under `mobile/scripts/`, which knip already treats as an entry point), reading the allowlist from t001.
2. Chain it into `lint:deadcode` so both the package lint and the root script run it.
3. Make its failure message name the document and the two ways to resolve it: delete it and run codegen, or allowlist it with a reason.

## Files

- `mobile/scripts/` (new check)
- `mobile/package.json` (`lint:deadcode`)

## Acceptance criteria

- [ ] Adding an unused `.graphql` operation makes `yarn lint:deadcode` fail with the document named; removing it makes it pass.
- [ ] Allowlisted operations pass.
- [ ] `knip.jsonc` is unchanged.

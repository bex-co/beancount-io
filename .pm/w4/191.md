# Make Starter ledgers start without sample money

**Source:** `/pm-brainstorm for w4`, candidate 1, explicitly selected with `$pm 1 for w4` on 2026-09-28. **Scope:** `backend-cluster/backend-v2/`. **Estimate:** 45–60m. **Worker:** worker1. **Goal:** A2 — newcomers can start personal books without first deleting invented transactions.

The default `simpleLedgerTemplate` in `src/features/ledger/utils/ledger-template.ts` contains an “Example Payee” transaction dated 2021-10-11, posting 14.99 USD to `Assets:Cash` against `Equity:Initial`. Mobile's Starter choice omits the template argument and uses this default; Sample explicitly selects the populated sample template. Ledger creation already shipped in w4/m6; this corrects the starting contents rather than rebuilding that flow.

Remove the sample transaction from newly created Starter ledgers while retaining valid account scaffolding and options. Keep Sample populated and leave all existing ledgers untouched. Check the owning package's documentation for claims about starting contents and update any affected guidance. This gives future onboarding a truthful baseline; the observable outcome is a new personal ledger with no demonstration money to clean up before the first real entry.

Acceptance:

- A newly created Starter ledger validates, contains zero transactions, and has zero balances; default/omitted-template creation has the same result.
- Explicit Sample creation still produces its populated demonstration ledger.
- Verify creation and subsequent reads through every eligible REST, GraphQL, and MCP surface under the existing credential policy, following the backend API parity workflow. Preserve documented protocol exceptions and authorization behavior; do not expand credential eligibility to satisfy the check.
- Regression coverage exercises resulting ledger contents and behavior, not merely adapter delegation. Run the owning package's required checks and parity gate; record any live verification separately from controlled tests.
- No migration, rewrite, or deletion affects an existing ledger. No new dependency, API operation, or client onboarding feature is included.

No dependencies. This is a sub-hour inbox correction, not a milestone. The separately proposed mobile first-transaction guide is not part of this approval.

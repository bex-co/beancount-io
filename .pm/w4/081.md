# Statement tables cannot reveal the amounts behind “+N more”

Severity: minor (incomplete on-screen aggregate; CSV is a workaround). Estimate: 50m, dashboard. A2: a reader should be able to inspect every commodity in a statement account total. Source: repeated dashboard QA, 2026-09-17.

Environment: production https://beancount.io; anonymous public synthetic `open_ledger/example`; QA-owned isolated headless Chromium 149.0.7827.55, English, browser-emulated dark appearance. First 390×844 and fresh 1440×1000 reload. Local main `26d54a9db7d33c31a549bd12a0454a1c01f3f038`; deployed main-BIr0jJni.js, exact deployed commit unverified.

Repro:
1. Open `/ledger/open_ledger/example/balance-sheet?time=2016`, show charts, and select conversion **Units**. This preference persists through the fresh reload used below.
2. Scroll the Assets table horizontally to Other. Its Assets row shows USD 6,763.51 separately, then `17 GLD`, `95 ITOT`, `36 VEA`, and `+4 more`.
3. Click “+4 more”: nothing opens or changes. It is a plain DIV, has no title/handler/tab stop, and the row's accessibility subtree contains only those three amounts and the count. The four omitted unit names and values are absent from this row's DOM.
4. Reload at 1440×1000 and repeat: identical. Assets:US has the same omission; Assets:US:ETrade shows three values and an inert “+1 more”. Horizontal scrolling exposes the Other column but cannot expose its omitted contents.

Expected: preserve a compact initial cell if useful, but provide a named keyboard/pointer/touch disclosure that reveals every omitted amount with its unit and sign. Actual: the count advertises additional data without a way to inspect that aggregate in the row. Account children or an export require leaving/reconstructing the aggregate; they are not a disclosure for it.

Independent control: browser GraphQL `getLedgerBalanceSheet(ledgerId:"open_ledger/example",conversion:"units",time:"2016",interval:"monthly")` returns HTTP 200 with Assets `balanceChildren:{USD:"6763.51",GLD:"17",ITOT:"95",VEA:"36",VHT:"39",VACHR:"25",RGAGX:"394.75",VBMPX:"136.632"}`. The actual downloaded Spreadsheet CSV has all eight Assets total rows, including the omitted **39 VHT, 25 VACHR, 394.75 RGAGX and 136.632 VBMPX**. Ordinary one-unit child rows remain readable; table semantics and the account hierarchy expander work. No server, serialization, arithmetic or export loss is claimed.

Root: `dashboard/src/features/reports/balance-sheet/hierarchy-list.tsx:111` renders `otherBalances.slice(0, 3)` and lines 123–126 render only the remaining count in a DIV. This is structural omission, not CSS clipping. The component's existing test at `__tests__/hierarchy-list.test.tsx:229` asserts that “+1 more” exists but does not require access to the fourth value. The compact threshold is explicit; retain it if desired and complete its disclosure rather than merely changing the number of hidden units.

Fix: add the disclosure within OtherBalancesColumn using existing accessible UI primitives, or show all values if that remains readable. Give any trigger an account-appropriate accessible name, preserve focus on close, and make the complete amounts available at 390px without overlap or lost table relationships. Cover tree and summary rows, 0–3 and >3 non-primary balances, signed/inverted amounts, and a change of account/data while disclosure is open. Keep primary-currency and zero-omission rules, account expansion/navigation, horizontal table scrolling and CSV output unchanged. Add meaningful interaction tests with the formerly omitted amount; run dashboard's normal gates. No API or dependency changes are needed.

Blast radius: AmountCells uses OtherBalancesColumn for both hierarchy rows (`hierarchy-list.tsx:248`) and summary rows (`:300`). Production HierarchyList consumers are Balance Sheet, Income Statement, Cash Flow through HierarchyListCard, and direct Trial Balance. Those sibling routes are source-traced for this threshold, not individually reproduced here. Other themes/locales, authenticated roles, actual screen-reader speech and patched behavior remain unverified. Loading/error/denied states were not injected for this candidate.

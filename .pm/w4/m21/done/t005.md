## Objective

Run /simplify over this milestone's implementation without changing behavior.

See [FINDINGS.md](./FINDINGS.md) for evidence, source and limits.

## Acceptance criteria

- [x] Avoid duplicate scalar/unit conversion paths or unnecessary chart abstractions.
- [x] Preserve grouping, filters, metadata loading, declared roles and existing negative/empty-flow handling.

## Outcome

Reviewed the m21 diff across reuse, simplification, efficiency and altitude. The
review confirmed nothing in it breaks grouping, filters, metadata loading,
declared roles or negative/empty-flow handling: `groupDistributionData` still
takes a plain item array and its <1% Other bucket is untouched, `hasNegatives`
still drives the bar fallback, `accountMetaPending` still short-circuits before
any transform so declared roles are never pre-empted, and the `value <= 0` and
`totalSavings > 0` guards are unchanged.

It also found a genuine regression the tests could not: see below.

Applied:

- **No second unit path.** `pickNumericAmount` — the original
  `balance["USD"] ?? Object.values(balance)[0]` — is **deleted**. Its last
  caller, the Income vs Expenses bar chart, now uses the shared unit model. That
  chart compares bars down one axis, so it is in the same position as the
  others: one unit, and say what is left out. Leaving the old picker exported
  from the same module as `buildDistributionData` would have left the contract
  documented but not enforced, with the old helper one autocomplete away.
- **One `ChartUnitScope` component** renders the disclosure for all three charts,
  replacing two copies of the same guard, key, join and styling — and retiring an
  inline helper in `cash-flow-sankey.tsx` that shadowed the exported
  `omittedUnits` under the same name.
- **One numeric coercion.** `readBalance` used `parseFloat` while
  `overview-utils` used `Number`; they disagreed on `"12abc"`. `toFiniteAmount`
  is now the single rule, and `Number` is the deliberate choice: a malformed
  amount becomes NaN and is skipped rather than silently truncated.
- **`addToGroup`** replaces the merge-or-set block that appeared twice in the
  transformer, so the aliasing subtlety is reasoned about once.
- **Trims:** `addAmount` un-exported (no caller outside its module), and ~30
  lines of comment prose removed. The argument for the unit model now lives in
  `reports/AGENTS.md` and once in `unit-amounts.ts`; the load-bearing facts stay
  next to the code that needs them.

Kept deliberately: `chooseDisplayUnit`'s three tie-break tiers all earn their
place. Account count is the primary signal, magnitude settles a real case from
this milestone's own data (one USD account at 27,635.92 against one IRAUSD
account at 18,000 ties on count, and without magnitude the chart would be drawn
in the smaller incidental unit), and alphabetical is what makes the result
independent of `Object.keys` order — the stability the contract promises. And
`projectToUnit` was left alone: it and the projection in `buildDistributionData`
share only `amounts.get(unit)` plus a filter, over different input and output
shapes.

**The regression.** The review caught that t003 returned the scope note from
`DistributionChart` in a bare fragment, while both call sites are cells of
`grid grid-cols-1 lg:grid-cols-2`. The note therefore became a third grid cell —
it sat where the Liabilities card belongs and pushed Liabilities onto the next
row. Measured at 1440 before the fix: three cells, Liabilities 382px below
Assets; after: two cells at the same top. Shipped separately as `af3f009a`
rather than folded in here, so the fix has its own history.

Verified live after all of it: the example overview renders five charts with no
page errors and **three** scope notes — Sankey (IRAUSD, VACHR), assets pie
(VACHR) and now the bar chart (IRAUSD, VACHR), which previously reduced each
bucket to one unit without saying so. The single-currency crypto ledger renders
four charts and no note at all.

Gates from `dashboard/`: `yarn format:check`, `yarn lint`, `yarn test` (379
files, 4282 passed, 1 pre-existing skip) and `yarn build` all pass. `gitleaks`
reports no leaks in `dashboard/src`.

The review's remaining observation — that `unit-amounts.ts` has no test file of
its own, so the tie-break tiers are exercised only incidentally — is t006's
work.

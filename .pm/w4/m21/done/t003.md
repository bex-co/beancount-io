## Objective

Apply the milestone's truthful unit presentation to overview asset/liability distribution data, including pie/bar renderers, percentages and the Other bucket. See FINDINGS.md's additional distribution reproduction.

## Acceptance criteria

- [x] Example2016 retains386.28 USD separately from25 VACHR; it never presents411.28 as one amount or uses80174.80683 as their combined composition denominator.
- [x] Percentages and the existing small-item grouping operate within the displayed unit; unavailable/unpriced units are disclosed, separated or selectable rather than silently added or discarded.
- [x] Preserve actual single-unit values, account identities, signs and ordinary USD/MUSD behavior. Reuse the milestone's unit model where appropriate; do not duplicate arbitrary first-currency selection.

## Outcome

The distribution charts had their own copy of the same defect:
`buildDistributionData` called `pickNumericAmount`, which is
`balance["USD"] ?? Object.values(balance)[0]`, and the pie then summed those
scalars into both its slices and the denominator behind every percentage.

Rather than fix it twice, the unit model moved into
`overview/lib/unit-amounts.ts` — `UnitAmounts`, `readBalance`,
`chooseDisplayUnit`, `collectUnits`, `omittedUnits` — and both the Sankey
transformer and the distribution builder now use it. That is this task's own
instruction not to duplicate arbitrary first-currency selection, and it leaves
one definition of "which unit does this chart speak in".

`buildDistributionData` returns `{ items, unit, units }`: slices for the chosen
unit only, plus every unit the accounts hold. `groupDistributionData` stays
unit-agnostic, because it now receives items that are already in one unit, so
the 1% Other threshold and the grouping behave exactly as before — within that
unit. The chart renders the same scope note the Sankey does, and each chart
names only what **it** omits.

Verified live on the public example ledger at 2016:

| | Before | After |
| --- | --- | --- |
| `Other` slice | 411.28 (0.51%) | **386.28 (0.48%)** |
| Slice denominator | 80,174.80683 | **80,149.807** |
| Liabilities `Slate` | 1,768.88 (100%) | 1,768.88 (100%) |

386.22 USD and 0.06 USD are still grouped into Other, which is right — they are
genuinely below one percent — while the 25 VACHR no longer joins them. The new
denominator is exactly the API's USD asset rollup of 80,149.80683, where the
old one was that plus 25 vacation hours. The single-unit liabilities pie is
unchanged, as the control.

The disclosures land independently and correctly: the assets pie says
*"Amounts are shown in USD. Balances in VACHR are not included."* while the
Sankey on the same page says *"…Balances in IRAUSD, VACHR are not included."* —
each naming what it actually leaves out. Single-unit ledgers show no note.

Since one key now serves both chart families, `page.overview.cashFlowUnitScope`
was renamed `page.overview.chartUnitScope` across all fifteen locales, with its
description updated. It was added minutes earlier in t002, so nothing external
depended on the old name.

Gates from `dashboard/`: `yarn format:check`, `yarn lint`, `yarn test` (379
files, 4282 passed, 1 pre-existing skip) and `yarn build` all pass.

## Cause and bounded repair

`dashboard/src/features/journal/components/export-journal-button.tsx:48–101` manages `isExporting` and catches the query error, but its failure/finally path restores only the enabled state. It remembers neither the submitting control nor whether focus moved deliberately. At:146 the loading Button disables the focused action; there is no failed-action focus handback. The retained Radix dialog subsequently owns focus. Its registered page trigger correctly handles successful closure, so replacing that existing trigger is unnecessary.

The existing `usePendingAction` pattern already captures the starting control, parks focus during a lock, returns it after a failed action only when the user has not chosen another target, and suppresses handback on success. Apply an appropriately scoped version of that existing pattern to this export action, preserving successful download/close ownership and deliberate Close/Cancel choices. Do not add a global Button/Dialog autofocus policy, automatic retries or a timer. Preserve the query's date/account/filter scope, duplicate-download refusal, truthful failure toast, exact content and ordinary dialog dismissal. No API, dependency or other package change is needed.

Acceptance: a real keyboard Export→held read→failure sequence returns focus to the connected Export action, so the next Enter requests exactly one retry. A second failure remains usable; success closes with page-opener focus and the same downloaded bytes. Deliberate movement to Close/Cancel during the wait is respected, and unmounted/changed owners receive no late focus. Repeat both widths and run dashboard gates when implementing. Actual network outages, other engines, screen-reader speech and repaired code remain unverified.

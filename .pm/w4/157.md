# The half-translated guard covers 7 locales of 15; comparing against English would cover all of them

Severity: moderate. Estimate: ~2h, dashboard — likely a milestone, since it
needs a second predicate plus the repairs it finds. A2/A3.

`w4/m24/t010` shipped `dashboard/src/test/locale-stray-english.test.ts`, which
finds a message written in a locale's own script that still carries an English
word. That works for the seven non-Latin locales (bg fa ja ko ru uk zh) and by
construction cannot work for the seven Latin-script ones (ca de es fr nl pt sk):
there, a stray English word is indistinguishable from the target language by
script. The module says so, and treats it as intrinsic.

It is not intrinsic. The defect is mechanical — a find/replace swapped the
leading token and left the English tail — and that signature is visible without
knowing any script, by comparing the message against `en[key]` and looking for
a shared trailing run that still holds real English words.

Sampling that check over the source catalogs turns up ca 22 hits across the
seven Latin-script locales, of which roughly 16 look genuine:

- `seo.welcome.description` is half-translated in ca, de, fr, nl, pt and sk —
  for example `Willkommen to Beancount! Get started with plain-text accounting
  and financial management.` With bg, fa and ru, that is **one key damaged in
  nine of fourteen locales**.
- `page.statistics.accountLastEntries` — `Cuenta Last Entries` (es),
  `Compte Last Entries` (fr), `Conta Last Entries` (pt)
- `page.dashboard.editLedgerSettings` — `Editar Ledger Settings` (es, pt),
  `Bearbeiten Ledger Settings` (de)
- `ledgerEditor.nameYourFile` — `Nombre your file...` (es), `Naam your file...` (nl)
- `page.dashboard.nameMaxLength` — `Nombre must be less than 100 characters`
  (es), `Naam must be less than 100 characters` (nl)

Shape: add `strayEnglishTail(message, englishMessage)` to
`dashboard/src/test/locale-scan.ts` and run it over all fourteen non-English
locales. The existing script check then becomes a second signal for the
non-Latin ones rather than the whole guard. Group failures by key first and
locale second — several of these are one bulk edit damaging one key everywhere,
so a per-key view turns dozens of line items into about a dozen fixes.

Acceptance: the guard covers all fourteen non-English locales; the Latin-script
hits above are either repaired or listed as known deviations against a filed
note; reverting a repair fails it. English unchanged. Dashboard gates pass.

Related: `w4/153` (30 Russian), `w4/156` (13 in bg/fa/ko/zh). Those are the
same class found by the script check; this note is about the locales that check
cannot see at all. Worth doing after them, or folding all three together —
`seo.welcome.description` alone appears in all three.

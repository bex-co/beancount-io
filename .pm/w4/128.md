# Gate file creation and upload forms on ledger write permission

Severity: minor permission-UI defect. Estimate: 60m, dashboard. A2: public readers should not be invited to prepare repository changes they cannot save. Repeated dashboard QA, 2026-09-18.

Environment: production https://beancount.io, anonymous public `open_ledger/freelancer-invoicing`, English/light, QA-owned isolated headless Chromium149.0.7827.55,1440×1000 and fresh390×844. Local main26d54a9db7d33c31a549bd12a0454a1c01f3f038; fetched origin/mainbd5d1d31503f39f73a3201ca9cd36513cac37169; deployed main-BIr0jJni.js, exact deployed commit unverified.

Reproduction:

1. Open `/ledger/open_ledger/freelancer-invoicing/files/new/main/transactions`. The anonymous header offers Log In / Sign Up, but the page renders an editable filename field and Monaco editor. Enter `qa-local-draft-only.bean` and a harmless comment in the local buffer: **Save becomes enabled**. A fresh390 reload repeats this behavior and accepts the comment. Clear both fields afterward; Save becomes disabled again.
2. Open `/ledger/open_ledger/freelancer-invoicing/files/upload/main/transactions`. Stage a small synthetic text file through the file-input API. The page lists the local file, accepts an upload comment and enables **Upload Files**. A fresh390 load through the supported `/files/upload?dirPath=transactions` alias resolves to the canonical route and repeats it. Cancel discards the staged selection and returns to the directory.
3. Working control: the ordinary public directory hides Create File and Upload Files. Its writer-only buttons are already wrapped by LedgerWritePermission. Existing public blob readers also gate effective edit mode on the same permission contract.

Only browser-local drafts were prepared. Neither Save nor Upload was activated, no create/update request was sent, and no repository resource was created. The request observer recorded zero GraphQL mutations during these controls. This is misleading editing UI, not a server authorization bypass. Authenticated reader/writer sessions and actual submissions remain unverified.

Permission evidence: real anonymous GetLedger returns200 with permissions:null; it does not return a false push flag. `common/hooks/use-ledger-permission.ts:5–14` explicitly derives canWrite=false for an unauthenticated visitor. Backend `ledger-resolver.mutation.ts:68–80` requires authentication for createLedgerFile, and `features/ledger/workflow/ledger-workflow.ts:570–574` independently checks LEDGER_FILES_WRITE. Those checks were traced, not exercised by attempting a mutation, and must remain unchanged.

Root: `dashboard/src/features/ledger-editor/create-file/index.tsx:89` disables Save only for filename validation or saving; handleSave invokes CreateLedgerFile without a canWrite guard. `upload-files/index.tsx:60–61` disables Upload only when no files are staged or an upload is in progress; handleUpload likewise invokes CreateLedgerFile without a permission check. Neither page reads useLedgerPermission or gates its editor/file picker. The canonical route wrappers mount these pages directly; compatibility aliases redirect into them. The directory's guarded buttons do not protect these entrypoints.

Use the existing ledger permission contract for both pages and their action handlers, failing closed for anonymous, non-writer and unresolved access. Show a useful sign-in/read-only state with a route back to readable files before inviting a draft or file selection. Cover canonical and existing alias entrypoints without changing alias paths or creating redirect loops. Preserve authenticated writer behavior, valid empty-file creation, filename checks, dirty-state protection, file re-selection and source viewing. If access changes during a legitimate draft, stop further writes without silently discarding that draft. Keep the repair in dashboard; no API/parity or dependency change is needed.

# Entry Context wraps an account name mid-word, five rows below the same name correctly truncated

**Severity:** trivial. **Estimate:** 5–10 minutes. Owner: mobile. A2: an orphaned `g` on its own line reads as corrupted output, in the one panel a user opens specifically to check the ledger's raw state — and the correct treatment is already on screen a few rows above.

Environment: branch `main`, HEAD `038faeeb`, native development build `io.beancount.ios` on iPhone 17e / iOS 26.5, English / System / light / **default text size**, authenticated production session at `https://beancount.io`, own ledger `puncsky/example`. Report-only QA; no ledger mutation — the panel is read-only and nothing was edited or deleted.

## Repro

1. Select `puncsky/example`, Transactions → the `STRIPE; TRANSFER; TIAN PAN…` entry (2026-09-01).
2. Tap the **Entry Context** header (`main.bean:6540`) to expand it.
3. Under **Balances Before Entry**:

   ```
   Liabilities:US:Chase:Slate      -1191.87 USD
   Assets:Bank:Mercury:Checkin     -1614.42 USD
   g
   ```

   The final `g` of `Checking` is alone on the next line.

**The same account, rendered correctly, is five rows up.** The Money flow card on this very screen shows `Assets:Bank:…ury:Checking` — middle-truncated with an ellipsis, root and leaf both legible, one line. Two treatments of one string, one screen.

## Root cause

`transactions-screen/entry-context/balance-section.tsx:36-42, 78`:

```ts
balanceAccount: {
  fontSize: fontSizes.sm,
  fontFamily: fonts.mono,
  color: theme.text01,
  flex: 1,
  textAlign: LEADING_TEXT_ALIGN,
},
```

```tsx
<Text style={styles.balanceAccount}>{balance.account}</Text>
```

`flex: 1` with **no `numberOfLines`**, so the text is free to wrap. A beancount account name contains no spaces, so there is no legal break opportunity and React Native breaks mid-token. The amount beside it has no `flex`, so it keeps its natural width and the account column absorbs the shortfall.

## Fix

```tsx
<Text style={styles.balanceAccount} numberOfLines={1} ellipsizeMode="middle">
```

`middle` rather than the default `tail`, for the reason **`w4/050`** sets out: the leaf is what identifies an account and the parent path is context, so tail-truncation eats the wrong end. It is also the pattern the app already uses for account names elsewhere — `multi-postings-transaction-screen.tsx:315` and `list-item.tsx:95` — and the Money flow card above is the on-screen proof that it reads well here.

Do **not** fix this by shrinking the font or letting the amount shrink instead: this is a monospace column whose alignment is the point, and the amount is the value the user came to check.

**Acceptance:** `Assets:Bank:Mercury:Checking` renders on one line in both balance sections with a middle ellipsis; `Liabilities:US:Chase:Slate`, which fits today, is unchanged and gains no ellipsis; the amount column stays right-aligned and unwrapped; both **Balances Before Entry** and **Balances After Entry** behave the same, since they are the same component. Add a test only if one is cheap — this is a two-prop change on a presentational component with no logic.

## Blast radius

One `<Text>` in `BalanceSection`, used twice on this screen (before/after balances) and nowhere else. No effect on the values, the disclosure, or the source view below it.

**Enlarged Dynamic Type was attempted and is blocked, not skipped.** At `content_size accessibility-medium` (AX1, set with `xcrun simctl ui`, app relaunched, restored to `large` afterwards), the hero and Money flow card consume the whole viewport on this screen: expanding Entry Context shows only its `Balances Before Entry` header at the bottom edge, with every balance row below the fold. Dismissing the development LogBox banner to reclaim its height was not enough. The pinned Expo MCP has no scroll tool (**`w4/020`**), so the rows cannot be brought into view. What the wrap does at AX1 is therefore **unknown** — `flex: 1` with no `numberOfLines` implies it wraps onto more lines rather than truncating, but that was not observed and should not be assumed.

What the same attempt *did* establish, on the way past: at AX1 the Money flow accounts on this screen collapse to `Asset…cking` and `Liabi…Slate` — both ends gone, the account unidentifiable — which is **`w4/014`**'s subject, reproduced. That note's fix and this one touch adjacent rows on one screen and should be checked together.

**Dark mode reproduces it identically** (`xcrun simctl ui … appearance dark`, same entry): `Assets:Bank:Mercury:Checkin` / `g`, with the panel otherwise rendering correctly — section headers legible against the card, mono text at full contrast. Expected, since this is layout rather than colour, but now checked rather than assumed.

Not exercised: Android, and RTL, where `LEADING_TEXT_ALIGN` plus a middle ellipsis is worth a second look.

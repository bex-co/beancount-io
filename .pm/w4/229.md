# Format Statistics percentages in the active app language

Severity: **minor**, dashboard. Estimate: **25–40 minutes**. A2 — generated numerical report text should follow the language the reader selected.

Production `https://beancount.io`, 2026-10-09, dedicated QA login, public synthetic `open_ledger/crypto-example`, isolated headless Chromium 149.0.7827.55, browser locale en-US. Source rechecked on main **850e7765**, unchanged after pulling; exact deployed SHA is unverified.

## Reproduce

1. In fresh 1440×1000 or 1024×1000 contexts, open `/ledger/open_ledger/crypto-example/statistics?time=2026&lang=en`. Wait for actual Transaction cells and account links rather than skeleton rows.
2. Open the real header account menu, hover Language, and choose Deutsch. This is a browser-local language change; no account preference is saved. Document/URL language becomes `de`, year remains 2026, and the table's accessible name becomes **Anzahl der Einträge nach Typ** with German column headers.
3. Percentage cells remain **20.6%**, **23.9%**, **16.7%**, **38.9%**, and **0.0%**. All twelve percentages are unchanged by the language switch. German one-decimal number formatting uses **20,6**, **23,9**, **16,7**, **38,9**, and **0,0** instead. The comparison holds the current percent suffix constant to isolate the decimal-separator defect; a proper locale percent formatter may also supply localized spacing.
4. Fresh direct German loads at 1440×1000 and 390×1000 reproduce Transaction **38.9%** under the German Prozentsatz header. Genuine public ledger options confirm `renderCommas=true`, so this is not an exercised opt-out from locale-aware formatting.

A separate real `getLedgerEntriesCountPerType` read succeeds HTTP 200 and gives **180** total directives: Balance 37, Open 43, Price 30 and Transaction 70, with the other eight types zero. The ratios correctly round to 20.6, 23.9, 16.7 and 38.9 at the current one-decimal precision. Counts match the active-language formatter. This note does not claim incorrect arithmetic, changed denominators or a need for percentages to sum to exactly 100 after rounding.

The actual language transition leaves all Account Last Entries rows unchanged and each of the three Statistics reads at one request; menus close normally. Preserve these controls. No source edit, clipboard operation or ledger/account mutation occurred. All fresh contexts were closed and the original QA page was untouched. The language menu's private profile contents were neither logged nor captured.

## Cause and bounded repair

`dashboard/src/features/ledger-data/statistics/entries-count-by-type.tsx` computes the ratio with `toFixed(1)` and appends `%` directly. That produces a dot-decimal string without consulting the active language. Counts use the existing active-language `useFormatNumber` hook, so the two neighboring number paths have different locale behavior.

Format the derived percentage with the active application language while retaining one fractional digit and the current total/count calculation. Use existing language resolution and a real locale formatter; do not route this through a formatter that silently removes trailing zeros or changes the percentage scale. Preserve the total-zero branch's localized not-applicable dash, positive-total zero rows, native table naming, lossless account-balance quantities, filters, request behavior and English controls. No API/dependency change is needed.

Acceptance: direct German loads and a live English→German transition render comma-decimal percentages at the current one-digit precision; returning to English restores dot decimals without changing the counts or dates. Cover nonzero ratios, positive-denominator zero rows and the zero-denominator not-applicable state through the actual owning component with real locale formatting. Keep the existing empty-period regression and run dashboard gates when implementing.

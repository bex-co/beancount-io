# Refuse CSV records whose extra fields are silently discarded before import

Severity: **major**. Package: **cli**. Estimate: **40–55m**, including both
reader copies and regression coverage. Source: continuous CLI QA for w4.
**A1/A2:** a malformed bank export must not become a successful, numerically
incorrect ledger write.

Environment: 2026-09-21, main `390568c220bfbdb0df1c9decb8436c64dfa3c9ca`,
checkout `cli/.venv/bin/bea` 0.3.0, Python 3.13.3, Darwin arm64.
All commands ran as fresh subprocesses under isolated
`cli/tmp/qa-20260921-cli-loop/`, with absolute ledger paths, closed stdin
(except the explicitly piped JSON), captured stdout/stderr, and 25-second
limits. Child-only `BEA_CONFIG_DIR`, `XDG_CACHE_HOME`, and `XDG_DATA_HOME`
pointed inside that directory; `BEA_NO_UPDATE_NOTIFIER=1`; inherited
`BEA_FILE` and `BEA_TOKEN` were removed. No hosted account was used.

## Reproducer and observed result

Create these two files in a disposable directory. `main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Food USD
```

`bank.csv` (the data record has four fields, against three headers):

```csv
Date,Description,Amount
2024-03-01,Purchase,-1,234.56
```

Run with absolute paths substituted for `main.bean` and `bank.csv`:

```sh
bea --json --file main.bean import bank.csv --csv auto   --account Assets:Cash --default-account Expenses:Food
bea --json --file main.bean import bank.csv --csv auto   --account Assets:Cash --default-account Expenses:Food --apply
bea --json --file main.bean query "SELECT number WHERE account = 'Assets:Cash'"
bea --json --file main.bean check
```

Preview exits 0 with `ready: 1`, amount `-1 USD`, and no validation errors.
Apply exits 0 with `written: 1`; the last field `234.56` is silently lost.
The query returns `rows: [["-1"]]`; check reports valid. JSON stderr is empty.
Human preview also shows one ready row with `-1 USD` and no row-width warning.
The resulting append is a balanced `Assets:Cash -1 USD` / `Expenses:Food 1 USD`
transaction. Preview file hashes remain unchanged; apply changes only the
intended ledger. Two fresh fixtures reproduced the same result, followed by a
third minimal fixture. Repeating apply treats the wrong amount as an exact duplicate.

Expected: reject the malformed record before preview/apply, with its source
line, actual/expected field counts, and a quoting hint; preserve ledger bytes.
Do not guess or concatenate the overflow into an amount. Working control:
change the record to `2024-03-01,Purchase,"-1,234.56"`; preview, apply, and
fresh query all preserve `-1234.56`. Properly declared unused columns may be ignored.

## Cause, scope, and repair

`cli/src/bea_engine/csv_mapper.py:542–545` iterates only the headers when
building each record dictionary, discarding surplus cells. The frontend twin
at `cli/src/cli/csv_mapper.py:444–447` does the same. `csv.reader(strict=True)`
checks quoting, not record width. The engine's `CsvImporter.extract:687–710`
therefore never sees the omitted cells; the balanced candidate passes validation.

Check record width before constructing the mapping, in both readers. Keep
legitimate blank records and mapped/unmapped header behavior explicit. Search
of all `open_records` callers finds header reading and date inference in both
copies, plus engine extraction. `bea import` preview and apply, inferred,
explicit and remembered CSV mappings share this path. Python importer behavior
is not implicated. No backend/API change is required.

- [ ] Overflow records fail preview and apply without writes, naming the file,
      physical line and field-count mismatch rather than reporting a ready row.
- [ ] Quoted grouped amounts, multiline quoted text, blank rows and declared
      unused columns still import correctly; automatic and explicit delimiters agree.
- [ ] A real CLI regression verifies the refusal and the correctly quoted
      control through preview, apply, fresh query and check. Run CLI gates when fixing.

Dedupe: searched all board markdown, including done/blocked and every open
milestone, for CSV overflow/extra fields, row width, truncation and strict CSV.
No open overlap. `5bb12d40` introduced the header-normalizing reader, and
`a90b1706` copied it into the engine. Completed w1/m24 and w3/256 cover amount
spellings, not malformed-record truncation; their quoted grouped-amount control
still passes. No later repair in HEAD.

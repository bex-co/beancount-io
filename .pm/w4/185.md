# Keep Overview customization open when restoring the first hidden module

Severity: **minor** interaction/accessibility defect. Package: **dashboard**.
Estimate: **45–60m**. Source: continuous dashboard QA for w4; **A2/A3** —
readers should be able to restore and arrange dashboard modules in one session.

Production `https://beancount.io`, anonymous synthetic
`open_ledger/real-estate-example`, isolated headless Chromium149.0.7827.55.
Local main `390568c2`, served `main-d5j4FX-V.js`; exact deployed revision
unverified. Only this owned browser's local layout preferences were changed.

1. Open `/ledger/open_ledger/real-estate-example?lang=en`, then the header's
   **Customize** panel. Turn off all seven module switches and close the panel.
2. Reload. The empty state correctly says all dashboard modules are hidden.
   Open **Customize from that empty-state prompt**, below the header.
3. At320×800/dark, turn on **Show module: Financial position** by pointer.
4. The module appears, but the entire Customize dialog immediately disappears.
   Focus is now BODY. The reader must reopen the header's Customize panel to
   restore or arrange another module.
5. Fresh1440×1000/light repeat: start with all seven hidden, open the empty-state
   panel, focus **Show module: Recent activity** and press Space. Same result:
   zero dialogs, focus BODY, Recent activity visible and the other six hidden.

Control: the header's Customize panel stays open when enabling another module;
focus remains on that switch. Its Reset layout action also keeps the panel open
and checks all seven switches. Reset plus reload restored all default modules
and ordering after verification. This is an entry-point-specific interruption,
not intended close-on-change behavior or a production ledger write.

Cause: `dashboard/src/features/reports/overview/index.tsx:432–445` owns a second
DashboardCustomizer inside the `visibleWidgetIds.length === 0` conditional.
Enabling the first module removes that entire branch, including its open Sheet.
The persistent header instance is at399–404. In
`components/dashboard-customizer.tsx:48–55`, each instance owns an uncontrolled
Sheet; switches at71–75 immediately update layout. The hook's localStorage
subscription correctly applies the new visibility, which triggers the unmount.
These are the only two production callers of DashboardCustomizer.

Keep the dialog owner/open state mounted across the empty-to-populated
transition and let both entry points open that stable customization surface.
Preserve local per-ledger persistence, visibility, ordering and Reset layout.
Maintain focus inside the open dialog after changing visibility. On explicit
close, return focus to an available Customize trigger; if the empty-state trigger
has disappeared, use the persistent header trigger. No API or dependency change
is needed; avoid a DOM-click proxy or unrelated global state.

Acceptance: from the all-hidden empty-state prompt, enable a module and then a
second one without reopening Customize, using pointer and keyboard. Reordering
and Reset remain available in the same panel; Escape closes it and restores
focus to a visible trigger. Cover this actual conditional-render transition in
a rendered test, verify default-layout reload and both themes/narrow widths,
and run dashboard gates. The existing empty-state test mocks the customizer out
and therefore does not exercise this interaction.

Dedupe/history: searched every board state for the customizer, storage key,
all-hidden state and dismissal/focus failures; no overlapping repair found.
The conditional owner dates to `af5339de` and remains in current main. Existing
Journal/Budget/Account focus work does not own this Overview conditional panel.
Only anonymous local customization was tested; authenticated settings writes
remain outside this evidence.

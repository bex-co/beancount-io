# Show initial social-list failures instead of claiming an empty profile

Severity: minor. Estimate: 60 minutes, dashboard. A2/A3: public visitors should distinguish unavailable community data from an empty community and recover without reloading the whole profile.

Environment: production https://beancount.io, September17 local / September18 UTC2026; isolated headless Chromium149.0.7827.55, English/light, signed out, public synthetic open_ledger profile. Fresh390×844 and1440×1000 contexts. LocalHEAD26d54a9d; fetchedorigin358ba4dc has no dashboard differences. Deployed main-BIr0jJni.js; exact deployment SHA unverified.

Reproduce:
1. Open `/ledger/open_ledger?lang=en` in a fresh context. Intercept only the browser POST `/api-gateway/` whose GraphQL operation is GetUserFollowers, and abort it with a network failure. Keep GetUserProfile and all other reads live.
2. Choose Followers. The request variables are username=open_ledger, page=1, limit=20.
3. After loading settles, the panel says **No followers yet**, with zero retry buttons; the separate successful profile read still gives **Followers (142)**. Reproduced from fresh desktop and narrow sessions.
4. In the desktop context, independently abort the first GetUserFollowing and GetUserStarredRepos reads and select each tab. They settle to **Not following anyone yet** and **No starred repositories**, respectively, with no failure state.

These are deliberately induced client transport failures, not a claim that production had an outage. No payload was replaced with a synthetic empty success.

# Respect early field focus in New Entry

**Minor · dashboard · 35–50m · A2.** Transaction's delayed Payee autofocus can interrupt a reader who has already reached Date and started typing. The date becomes invalid while the remaining date characters are entered into Payee. This requires rapid interaction during the approximately150ms mount window; settled editing works.

## Reproduction and controls

Production `https://beancount.io`, 2026-10-24 UTC; owned isolated headless Chromium156.0.8078.47, English/light/UTC, synthetic-ledger owner. Fresh390×844 and1440×1000 contexts independently reproduce using real metadata and native keyboard events. No network responses, clocks, application state or handlers are modeled.

1. On Journal, open New Entry once, let its genuine suggestion reads finish, then Close the unsaved dialog. This warms ordinary metadata and isolates the second opening from initial loading.
2. Focus the persistent New Entry link and press Enter. As soon as Transaction appears, press Tab twice: the selected Transaction tab → its tabpanel → Date. Read-only focus telemetry confirms Date owns focus before typing.
3. Press Cmd+A, then type `10/01/2026` with80ms between characters, beginning within the existing mount-focus window. At390, Date receives `1`, then Payee receives `0/01/2026`. At1440, Date receives `10`, then Payee receives `/01/2026`. Date is visibly invalid in both cases.
4. The native key/focus trace places the unsolicited Date→Payee change between the typed characters,139.6/143.0ms after the form's observed mount. There is no intervening click, Tab or navigation. No submission is attempted.
5. Clear Payee, explicitly refocus Date after the timer has settled and repeat the identical native typing: the complete date stays in Date and Payee stays empty at both widths.

Separate cache-warmed, no-early-interaction controls at both widths preserve intended default behavior: Payee receives focus and the complete `qa-20261024-default-focus` text. Keep that default when the reader has not chosen another field. The narrow failure screenshot was visually inspected: invalid Date `1`, focused Payee `0/01/2026` and the unchanged unsaved transaction form.

This establishes misdirected draft typing during startup. Ordinary typing after settlement, submission corruption, lost hosted entries, pointer interaction, prevalence and other directive forms are not claimed.

## Cause and bounded repair

`dashboard/src/features/journal/components/new-directive-dialog/transaction-form.tsx:163–175` schedules a150ms timeout on mount. Its callback unconditionally queries the Payee wrapper and calls `.focus()`. Cleanup cancels it on unmount, but nothing checks whether the reader has already focused or interacted with another usable control. Scoping the selector to Payee prevents selecting Status; it does not protect a deliberate later focus owner.

Keep the initial focus handoff local to Transaction's mount lifecycle. Respect an existing user-chosen field when delayed initialization completes, while preserving ordinary default Payee focus, tab navigation, suggestion loading/recovery, custom Payee entry, close/reopen behavior and existing amount/date validation. Moving the timeout later merely moves the race. No shared global focus override, new dependency or API change is needed.

Acceptance: exercise the real form with its mount handoff pending; native Tab to Date followed by typing must stay entirely in Date. The no-interaction default must still focus Payee, and an explicitly chosen Payee/other usable field must retain its input and caret. Verify close/unmount cancels obsolete work and repeat native checks at both widths, then run dashboard gates when implementing. QA authored no product fix or formal regression test.

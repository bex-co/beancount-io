# Preserve the Account chart view when a shared report filter changes

Severity: **minor**. Package: **dashboard**. Estimate: **45–60m**, reusing the
existing URL-view helper. Source: continuous dashboard QA for w4. **A2**:
a reader comparing period changes should keep that chart when narrowing dates.

## Reproduce

Production `https://beancount.io`, anonymous synthetic `open_ledger/example`,
English/light, isolated headless Chromium149.0.7827.55. Local main `390568c2`,
deployed `main-d5j4FX-V.js`; exact deployed revision unverified.

1. Open `/ledger/open_ledger/example/account/Expenses?lang=en&time=2016-11`.
2. Choose **Changes Over Time**. At1440×1000 this is a tab; at390×844 it is an
   option in the **View** combobox.
3. Change the shared **Time** filter to `2016-10` and press Enter. At390px,
   open **Filters**, edit **Time**, then close **Report filters**.
4. After the new journal/chart read settles, the page has silently selected
   **Account Balance** instead. The URL carries the new time but no view.
5. Fresh desktop navigation repeats November→October. A fresh390px reload
   repeats October→September, and another September→August edit repeats again.

Expected: keep Changes Over Time selected while querying the new time scope,
using the same view-preference policy already chosen for the statement pages
and Overview in completed w4/142. The scope's data should update without
changing which chart the reader chose.

Working control: on the same desktop Account page, selecting Quarterly and
then Monthly leaves Changes Over Time selected. Those are local report reads;
the failure occurs at the shared-route filter transition. The real
`GetLedgerAccountReport` reads return HTTP200 with no GraphQL errors. The
October request has `accountName:"Expenses"`, `interval:"monthly"`,
`conversion:"at_cost"`, `time:"2016-10"`; its period is2016-10-31. The browser
recorded no console/page/request errors during the final narrow repeat.

## Cause and repair

`dashboard/src/features/reports/account/index.tsx:378` still initializes
`selectedTab` in page-local state to `accountBalance`. Both responsive view
controls consume that state. `common/components/ledger-layout/index.tsx:43–64`
correctly treats a shared time/account/expression change as a scope change,
and `:136–143` replaces the whole Outlet with its pending state. When the
Account page remounts, it discards the prior choice. Its route's
`features/reports/account/search.ts` currently validates only journal `offset`.

Add a validated Account-specific view to that existing search contract and
use `common/hooks/use-url-view.ts` with the two supported values, defaulting
to Account Balance. Preserve offset normalization and all shared filter keys.
The existing helper uses replace navigation and omits the default value, so
reuse that behavior instead of introducing another preference store. Keep the
outer pending safeguard and the Account chart's settled-data guard; preserving
stale visuals is not a repair. No API, ledger data or dependency change needed.

- [ ] Changes Over Time survives a real shared time/account/expression edit at
      desktop/narrow widths, through loading and settlement.
- [ ] Reload/shared links retain a valid explicit view; an absent or malformed
      value safely selects the default. The local interval/conversion controls
      continue to preserve the selection.
- [ ] Account journal page restoration and genuine-filter offset reset remain
      correct. This QA run separately verified page2→Time2016-11 sends offset0.
- [ ] A meaningful router/unmount regression fails with page-local selectedTab
      and passes with the persisted choice. Run normal dashboard gates.

Scope is Account chart selection. Other local journal filter/disclosure state
and interval preference policies were not established by this reproducer and
should not be silently bundled into the repair.

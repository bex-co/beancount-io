## Cause and bounded repair

`dashboard/src/features/ledger-data/events/index.tsx:117` defines `typeLabel = type => type || t("page.events.emptyType")`. A nonempty whitespace string is truthy, so it bypasses the empty-type label and renders only whitespace in the trigger and menu item. Those are its two callers; neither supplies another accessible name. CSS whitespace handling and accessible-name normalization leave the controls unnamed.

Provide a visible and accessible representation for whitespace-only authored types in both places, preserving the original string for keys and exact filtering. Keep empty, one-space and other whitespace identities distinguishable if they coexist; an escaped/code-point representation with an appropriate localized label is one bounded option. Do not trim/rename stored event types, merge options, reject valid ledger data or replace null with another authored-string sentinel. Preserve 271's working `all`, empty-string and ordinary-type behavior, search composition, sorting/counts, shared-filter reset and current read retry. No API, dependency, cross-package import or global menu change is needed. Add any new user-facing message in all supported locales.

Acceptance: real Events/menu regressions with ordinary, empty, single-space and tab types expose meaningful distinct option/selected-button names and retain exact row filtering.

# Name the Events table for accessibility navigation

Severity: **minor**, dashboard. Estimate: **20–35 minutes**. A2 — readers navigating by table should be able to identify the event report in the active language.

Production `https://beancount.io`, 2026-10-09, dedicated QA login, public synthetic `open_ledger/example`, isolated headless Chromium 149.0.7827.55. Fresh 1440×1000 and 390×1000 contexts, English and Persian. Source rechecked on main **e9842e26**, unchanged after pulling; exact deployed SHA is unverified.

## Reproduce

1. Open `/ledger/open_ledger/example/events?time=2016&lang=en` and wait for populated rows. The four date/type/description rows exactly match a separate genuine `getLedgerEvents` HTTP 200 read for this ledger and year.
2. Inspect the native table with Chromium `Accessibility.getFullAXTree`: it has role **table**, `ignored:false`, and **name:""**. The actual table has no caption, `aria-label` or `aria-labelledby`.
3. Repeat with `lang=fa`: the document is Persian, but the table still has no name. Both widths reproduce in both languages; independent fresh English contexts at both widths repeat the native empty name and exact four-row control.
4. At desktop the Events / رویدادها page heading is visible but unassociated with the table. At narrow width PageHeader is deliberately hidden by the existing responsive design. Keep that design; it makes a table's independent localized name especially useful.

This is a missing report identity, not missing or inaccessible row data. No actual screen-reader speech was exercised. All fresh contexts were closed, the original QA page was untouched, and no ledger/account mutations or clipboard operations occurred.

## Cause and bounded repair

`dashboard/src/features/ledger-data/events/index.tsx` renders a bare `<Table>` in its populated local-filter branch. Its PageHeader uses the existing localized `page.events.events` identity but does not label that table. The shared Table primitive forwards native table props and is not the missing-label source.

The owning `dashboard/src/features/ledger-data/AGENTS.md`, under **Table Names**, explicitly requires every table in this feature to have an accessible name derived from its identifying heading. Give this table the existing localized Events identity, either through a valid heading association at both widths or a direct localized table label. Do not add a second visible narrow heading merely to supply the name.

Preserve dates, event descriptions, order, type/search filtering, shared-period reset, translated column headers, honest filtered-empty behavior, native table semantics and public read-only access. No API, dependency or shared Table change is needed.

Acceptance: the populated Events table is exposed by its English and Persian name at desktop and narrow widths, including after local filtering still leaves rows. Switching the app language updates the name. Genuine no-result states remain table-free. Add a rendered owning-page regression that queries the actual table by its localized accessible name, plus native browser verification; asserting that an unrelated heading exists does not label the table. Run dashboard gates when implementing.

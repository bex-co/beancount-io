# Half-translated messages are caught hours late in CI; the translator workflow could say so at edit time

Severity: minor tooling gap. Estimate: ~30m, dashboard. A2: shortens the loop
between creating this defect and seeing it.

`dashboard/scripts/prepare-translations.ts` is the documented translator entry
point (`yarn i18n:prepare`). It walks every catalog, prints a per-locale status
table, and tells the reader to grep `[TODO]` and edit in place.

The half-translated shape is created in exactly that edit: `[TODO] Account
Journal` becomes `Счёт Journal` when only the leading token gets replaced. The
script counts `[TODO]` markers and nothing else, so it reports that file as
progressing while the edit has left a word in neither language behind. The
guard shipped in `w4/m24/t010`
(`dashboard/src/test/locale-stray-english.test.ts`) catches it, but only on a
later `yarn test` run — and the `yarn test:translations` alias a translator
would reach for does not include that suite.

Shape: import `strayEnglishWords` from `dashboard/src/test/locale-scan.ts` into
`prepare-translations.ts` and add a "half-translated" column beside the TODO
count, listing the offending keys for the locale being worked on. Optionally
add the guard to whatever `test:translations` runs, so the translator's own
command covers it.

Not the right shape: a custom ESLint rule. `dashboard/eslint.config.js` has no
local plugin infrastructure, so that would be net-new machinery for a check
that already has two good homes — the prepare script and the test suite.

Acceptance: `yarn i18n:prepare` reports half-translated messages per locale
alongside the TODO count, using the shared predicate rather than a second copy
of it; the numbers agree with what the guard reports. Dashboard gates pass.

---

**Resolved 2026-09-20** — `yarn i18n:prepare` now reports a half-translated
count per feature and locale, and lists the offending keys, using
`untranslatedEnglishTail` from `src/test/locale-scan.ts` rather than a second
copy of the rule. Shipped in `4b7533bf` (`dashboard`).

Two pre-existing defects stood in the way, and both are worth recording because
this note assumed the script worked:

- **It did not run at all.** `COMMON_DIR` pointed at `src/common/locales`,
  which does not exist — the shared catalogs are under `src/i18n/locales/`. The
  script crashed on startup at step 2, so nobody had been running it, and
  `common` and `seo` had never appeared in its status report. Both do now, at
  213 and 90 keys. This is the same "the tooling cannot see the shared
  catalogs" defect that `w4/m24/t012` found in the milestone's own survey glob.
- **Fixing that path alone would have shipped a regression.** With it repaired,
  the sync step wrote every unattributed key in the codebase into the shared
  catalog — 40,070 lines across thirteen files. The crash had been hiding it.
  The shared catalogs are therefore read-only for this script, and the write
  path is guarded with the reason. Filed as `w4/159`.

Verified by reverting the Spanish account report: `reports` prints
`205/205 | 100% ⚠️ 3 half-translated` while every other locale stays ✅, and the
summary names the three keys. That is exactly the gap this note described — the
TODO count calls the file finished while three messages read as neither
language. On `main` it reports none, and the run writes nothing under `src/`.

Not done: adding the guard suite to `yarn test:translations`. That alias runs
`src/test/translations.test.ts` only, and widening it is a change to what a
named script means, which is worth its own note if anyone wants it. The report
covers the workflow this note actually named.

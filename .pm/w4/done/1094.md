# Hydrate legacy file links before handing off to the file route

**Severity:** minor. **Estimate:** 35–50 minutes. **Owner:** dashboard. **A2/A3:** accepted compatibility links should open source without a recoverable startup failure.

## Fresh reproduction — 2026-10-25

Production `https://beancount.io`, owned isolated headless Chromium156.0.8078.47, signed out, public synthetic `open_ledger/example`, English/light/UTC. Fresh1440×1000 and390×844 documents reproduce, with independent repeats.

1. Hard-load `/ledger/open_ledger/example/files/content?type=file&path=main.bean&editMode=false&lineNumber=42&lang=en`.

React's [418 explanation](https://react.dev/errors/418) identifies mismatched initial server/client output and regeneration of the affected tree. This is a recovered hydration failure; permanent reader failure, lost drafts/focus and a measured delay are not established.

The healthy controls retain the first main element. A JavaScript-disabled control remains at the alias with the Files title and shell; the canonical control remains at its own URL with the file title. ## Cause and bounded repair

`dashboard/src/routes/ledger.$ledgerOwner.$ledgerName.files.content.tsx:35–49` throws a canonical-file redirect from beforeLoad, while:52 deliberately sets `ssr:false` for the webview/client-auth compatibility route. Its component otherwise renders the directory page. The installed and actually served TanStack hydration implementation, `@tanstack/router-core/src/ssr/ssr-client.ts:242–255`, schedules router.load for SSR-disabled matches during hydration. StartClient hydrates that initial route before rendering RouterProvider. Thus the file-only beforeLoad handoff changes the initial route during hydration; the directory alias and direct destination avoid that transition. The exact React mismatch node was not instrumented.

Move the file handoff into the supported post-mount navigation lifecycle so the alias's initial tree can hydrate first. The installed Navigate component (`@tanstack/react-router/src/useNavigate.tsx:54–77`) already navigates in a layout effect and is a bounded option. Preserve this route's client-only behavior, path/leading-slash normalization, main branch, lineNumber, permission-controlled editMode and replacement history. Preserve directory/default/empty-path behavior, and avoid mounting a directory request for a file target. Keep the canonical viewer unchanged. No API, dependency or global hydration override is needed.

Acceptance: real SSR-to-hydrated browser loads of the file alias reach the right file/line/mode with zero418 at both widths. Direct-file and directory controls stay healthy. Retain the completed repair's Back replacement, missing-file recovery and read-only permission behavior. Cover actual initial hydration, rather than only asserting beforeLoad's redirect destination; run dashboard gates when implementing. Authenticated editing, native webviews, other engines/locales and repaired behavior remain unverified.

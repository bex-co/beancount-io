## Objective

Add a GraphQL query that returns per-account detail including the `open`-directive metadata map, so the dashboard can read `cash-flow-role` declarations. The plumbing already exists end-to-end: the ledger service returns account metadata and `ledger-account-service.ts` in backend-v2 already maps it via `getAccountsDetail` — only the resolver layer lacks exposure.

## Context

- `backend-cluster/backend-v2/src/features/ledger/service/ledger-account-service.ts` — `getAccountsDetail` already returns `{ account, closeDate, meta, ... }`.
- `backend-cluster/backend-v2/src/features/ledger/api/resolvers/ledger-account-resolver.query.ts` — today exposes only `getLedgerAccounts` (`[String]`) and `getLedgerAccountDirectives` (no meta).
- Dashboard consumes the schema via codegen (`dashboard/codegen.ts`, `dashboard/src/graphql/definitions.ts`).

## Steps

1. Add a `getLedgerAccountDetails` query (account + meta + closeDate) to the account query resolver, backed by the existing `getAccountsDetail` service method.
2. Cover it with a resolver/service unit test in backend-v2 (meta map round-trips; missing meta → null).
3. Regenerate the dashboard GraphQL artifacts so the new query is available client-side.

## Files

- `backend-cluster/backend-v2/src/features/ledger/api/resolvers/ledger-account-resolver.query.ts` (+ types file)
- backend-v2 resolver/service tests
- `dashboard/src/graphql/` query document + regenerated definitions

## Acceptance criteria

- [ ] `getLedgerAccountDetails` returns the metadata map for an annotated account and null/empty for unannotated ones
- [ ] backend-v2 unit test green; dashboard codegen runs clean

## Out of scope

- Any ledger-service (rustledger) changes — metadata is already returned
- Mutations or editing of metadata

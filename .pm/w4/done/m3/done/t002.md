## Objective

Implement the single shared resolver that turns an account name plus its `open`-directive metadata into a final cash-flow role, per the spec appendix in the PRFAQ: one key, four values (`"cash" | "operating" | "investing" | "financing"`), declared-beats-heuristic precedence, invalid values fall through and are reported.

## Context

- Spec: `dashboard/docs/PRFAQ-cash-flow-ledger-classification.md` → Appendix ("Specification").
- Current heuristics live in `dashboard/src/features/reports/cash-flow/config.ts` (`CASH_FLOW_ACTIVITY_BY_ROOT`, `CASH_EQUIVALENT_PATTERNS`); consumers are `cash-flow/lib/model.ts` and `overview/lib/account-categorizer.ts`.
- Pure function, no GraphQL dependency: input = account name + meta record (or undefined); output = `{ role, source: "declared" | "heuristic", invalidValue?: string }`.

## Steps

1. Add `lib/role-resolver.ts` under the cash-flow feature implementing the spec (case-sensitive exact match; non-cash roles also mean "not CCE").
2. Document the `cash-flow-role` key in `config.ts` next to the heuristic tables it overrides.
3. Unit-test the matrix: all four values, typo/case/non-string invalids, heuristic fallback, CD-exclusion case (`"investing"` on a `Bank`-named asset).

# New ledger shows "Will be created as" with nothing after it when the name slugifies away

**Severity:** trivial. **Estimate:** 5–10 minutes. Owner: mobile. A2: the one hint on the screen that tells a newcomer what their ledger will actually be called renders as a dangling half-sentence exactly when the name is unusable — the moment it most needs to say something.

Environment: branch `main`, HEAD `038faeeb`, native development build `io.beancount.ios` on iPhone 17e / iOS 26.5, English / System / light, authenticated production session at `https://beancount.io`. Report-only QA; **no ledger was created** — `Create` was never tapped.

## Repro

1. Open `beancount:///(app)/create-ledger`. It seeds `Name` with `my-book` (correct — `generateDefaultLedgerName` avoids collisions), `Private` on, template `Starter`.
2. Select the name and replace it with `!!!` (any string of characters that the slugifier strips entirely — `---`, `...`, `@@@` all do it).
3. Under the field, the hint reads:

   > **Will be created as**

   …and stops. The interpolated slug is the empty string.

Typing a name that slugifies to something *different but non-empty* — e.g. `My Book!` → `my-book` — renders the hint correctly, which is the feature working as intended.

## Root cause

`create-ledger-screen.tsx:193-195`:

```ts
const slug = slugifyLedgerName(nameValue ?? "");
const showSlug =
  Boolean(nameValue) && slug !== nameValue.trim().toLowerCase();
```

and at `:287-291`:

```tsx
{showSlug ? (
  <Text style={styles.hint}>{t("createLedgerSlugPreview", { slug })}</Text>
) : null}
```

The guard asks *"did slugification change anything?"* — which is the right question for deciding whether a preview is worth showing — but never asks *"is the result non-empty?"*. For `!!!`: `slug` is `""`, `Boolean("!!!")` is true, and `"" !== "!!!"` is true, so the preview renders with `{{slug}}` interpolating to nothing. The string is `createLedgerSlugPreview: "Will be created as {{slug}}"` (`translations/en.ts:540`).

## Fix

```ts
const showSlug =
  slug.length > 0 && slug !== nameValue.trim().toLowerCase();
```

`slug.length > 0` subsumes the `Boolean(nameValue)` check — an empty input slugifies to an empty slug — so the expression gets shorter as well as correct.

Consider also surfacing `createLedgerNameInvalid` ("Name must include at least one letter or number.") while the name is in this state rather than only after submit; the string already exists and is exactly the guidance the dangling hint is failing to give. That is a behaviour change (react-hook-form's default validation mode is on submit), so treat it as a separate decision, not part of the one-line fix.

**Acceptance:** with `!!!` in the field no slug hint renders; `My Book!` still shows "Will be created as my-book"; a name that needs no slugification (`my-book`) still shows no hint; and creating a ledger from a valid name is unchanged.

## Blast radius

One conditional on one screen. **No bad data can result** — the Zod schema (`create-ledger-screen.tsx:147-155`) pairs `.min(1)` and `.max(100)` with `.refine((val) => slugifyLedgerName(val).length > 0, …)`, so a name that slugifies away is rejected before the mutation runs. This is a display defect only, which is why it is trivial.

**Not verified:** that tapping `Create` with `!!!` surfaces `createLedgerNameInvalid` inline. `errors.name?.message` is rendered at `:293`, and react-hook-form should block the submit, but confirming it means tapping a button that creates a real ledger on a production account — outside this run's authorization. The header `Pressable` is `disabled={busy}` only, so the control is tappable regardless of validity; whether that is the intended "validate on submit" pattern or an oversight was not established.

Also not exercised: enlarged Dynamic Type, dark mode, and Android.

## Adjacent states

The rest of the screen is **correct** and worth recording. `generateDefaultLedgerName` seeded `my-book` with no collision against the account's existing ledgers. `Private` defaults **on**, which is the right default for a new book. The template rows (`Starter` / `Sample`) render with their hints and a clear selection. And the validation this note does *not* fault is genuinely thorough — `.min(1)` / `.max(100)` / the non-empty-slug refine together reject the whole class of names the server would refuse, which is the same class the open **`w3/196`** reports the *dashboard's* Create File dialog accepting. Mobile gets this right; I left a pointer to both mobile implementations on that note.

**Resolved 2026-09-14** in `fix(mobile): hide the ledger slug preview when the name slugifies away`. A new `ledgerSlugPreview` in `ledger-name.ts` returns the slug only when it is non-empty and differs from the typed name. The Create Ledger screen renders the hint only for a non-null preview.

**Behaviour.**
- `!!!`, `---` and `@@@` show no hint.
- `My Book!` still shows `my-book`.
- `my-book` and an empty field show none.

**Tests.** `ledger-name.test.ts` covers the three cases above. With the empty-slug check removed, the slugifies-away test fails. The mobile gate passes, with 1850 unit tests.

**Not done.** Showing `createLedgerNameInvalid` before submit, which the note leaves as a separate decision.

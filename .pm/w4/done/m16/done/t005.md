## Implementation and verification

Completed 2026-09-19. All four statement pages now carry a chart-selection lifetime regression driven through the real page under its own pending and success branches. t001 added Cash Flow's; this task extended the same coverage to Income Statement, Balance Sheet and Trial Balance, whose page suites previously mocked their content as a bare element and captured nothing.

Each case walks the reproduction: settle the read and assert the report's own default is selected, have the reader pick a different chart through the real `onSelectedTabChange` prop, put the query into the pending state an uncached interval or conversion produces and assert the content is replaced — so a selection living inside it would be lost — then settle again and assert the reader's chart is still selected. Cash Flow additionally pins the stale-data contract directly: while pending, the loading state is what renders, so no stale amounts and no export exist under the new interval's metadata.

Proved real rather than assumed, across all four at once: pinning each page's props back to a constant with a no-op setter — what an unmounted owner produces on every settled render — fails exactly four cases, one per report, while the other eleven in those files still pass. Restoring the repair passes all fifteen.

The reports suite goes from 533 to 536 tests across 61 files. Gates from `dashboard/`: `yarn format:check`, `yarn lint`, `yarn build` and `yarn test` all pass at 376 files and 4,241 tests with the one pre-existing skip. gitleaks reports no leaks in the changed tree.

Treated honestly about what is not covered here. The narrow View selector and the cached-transition control were exercised live in t002 and t003 — 16 and 4 browser checks at both widths — rather than in this suite, which makes no browser claim. Error and retry states are unchanged by this milestone and were not exercised: triggering them needs a failure the read-only public journey cannot produce, and the existing per-page error tests already cover the classified-message behaviour. `chartMode`, lifted in t004, is pinned by the same page-level mechanism only insofar as it is passed as a prop; its own lifetime case was not added, and that gap is recorded with the rest of the follow-ups in [142](../../142.md).

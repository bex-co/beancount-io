# Payee and Narration are the only text fields in the app with iOS autocorrect left on — and they are the two whose values become ledger data

**Severity:** minor. **Estimate:** 10–15 minutes. Owner: mobile. A2: a payee is usually a brand, a proper noun, or a bank's import string (`AMEX EPAYMENT; ACH PMT; TIAN PAN`). Autocorrect exists to rewrite text that is not a dictionary word, which is exactly what these two fields are for. Six other inputs in this app already turn it off; these two, which are the ones that write to the ledger, do not.

Environment: branch `main`, HEAD `038faeeb`, native development build `io.beancount.ios` on iPhone 17e / iOS 26.5, English / System / light, authenticated production session at `https://beancount.io`, own ledger `puncsky/example`. Report-only QA; **nothing was saved** — `Save` was never tapped, and the screen was reached by deep link where `SelectedPayee.getFn()` is unregistered, so `onSave?.(…)` is a no-op anyway.

Ledger search, the server URL, a new ledger's name, an account name, the shared `SearchBar`, and the confirm-phrase modal all opt out. **`src/components/text-input-screen/index.tsx:188-199` does not** — and that component is the whole of both the **Payee** and **Narration** screens (`payee-input-screen.tsx:48`, `narration-input-screen.tsx`):

```tsx
<TextInput
  style={styles.input}
  value={value}
  placeholder={placeholder ?? i18n.t("pleaseInput")}
  placeholderTextColor={theme.controlPlaceholder}
  underlineColorAndroid="transparent"
  clearButtonMode="while-editing"
  autoFocus
  onChangeText={setValue}
  multiline={multiline}
/>
```

No `autoCorrect`, and no `autoCapitalize` either — so the latter defaults to `"sentences"` and silently capitalises the first letter of whatever is typed. (`open-account-screen.tsx:358` faced the same choice and made it explicitly: `autoCapitalize="words"` **with** `autoCorrect={false}`.)

The other four `<TextInput` sites without the prop are not affected and were checked: `add-budget-screen:306` and `multi-postings-transaction-screen:338` are `decimal-pad` amount fields, `agent-screen:384` is the Ask-AI prose composer (where autocorrect is wanted, and the feature is disabled anyway), and `ledger-file-browser-screen` / `setting/main-content` matched only because they mount `TextInputModal`, which sets the prop.

## What it does

On `puncsky/example`, `beancount:///(app)/payee-input?payee=`, typing `anthropic` and then a space: the field became **`Anthropic fix`**. The capitalisation is `autoCapitalize`'s default; the appended word is autocorrect substituting for an unrecognised token. `Anthropic` is a real payee on this ledger (BQL: 2 postings).

**How much to trust that.** The missing prop is certain — it is read from source. The specific mangling is less so: these were synthetic keystrokes through `osascript`, with no on-screen keyboard and therefore no suggestion bar to accept or dismiss, so iOS's correction behaviour here is not identical to a person typing. What the capture establishes is that **corrections are being applied to this field at all**, which is the point; the exact string a real user would get will differ. A second capture in the same session shows the related `.` substitution (`anthropic. `) and, with it, the suggestion card disappearing entirely — see below.

## Why it matters more here than anywhere else

These two fields are the only free-text inputs whose values are **written into the beancount file**. A mangled payee is not a transient annoyance:

- it creates a **new merchant**, permanently, in a plain-text ledger;
- the Merchants screen groups by exact payee, so the mangled one becomes its own row with its own totals, splitting a real merchant's history;
- nothing on the transaction row or the detail screen shows that two near-identical payees exist;
- fixing it means editing raw source (`w4/022`'s screen) or the file.

The suggestion list is the affordance that should prevent this, and it fails in the same moment. `text-input-screen/index.tsx:150` matches with a plain `item.toLowerCase().includes(query)`, so once autocorrect has appended anything the query stops matching and **the entire suggestions card is hidden** — verified on device with `anthropic. ` in the field while `Anthropic` existed in the ledger. The user is offered no correction precisely when they have just been given a wrong one.

## Fix

```tsx
autoCorrect={false}
autoCapitalize="words"   // or "none"; decide, don't inherit "sentences"
```

`autoCapitalize` deserves an explicit choice rather than a default: `"words"` matches `open-account-screen`'s reasoning and suits merchant names, while `"none"` is safer for import strings. Either is defensible; inheriting `"sentences"` is not, because it rewrites the first character of every payee without anyone having decided that.

Consider also trimming on commit. `commit(value)` at `:163` saves the **raw** string while the matcher compares `value.trim()` — so a trailing space (which iOS inserts routinely after accepting a completion) yields a payee that looks identical on screen and is a distinct string in the file. `commit(value.trim())` closes that, and is worth doing in the same edit even though `autoCorrect={false}` removes the commonest way to acquire the space.

**Acceptance:** typing `anthropic` in the Payee field leaves `anthropic` (no substitution and no appended word), with `Anthropic` offered in Suggestions; typing a trailing space and saving commits the trimmed value; the Narration screen behaves the same way, since both mount `TextInputScreen`; and the six fields that already set `autoCorrect={false}` are unchanged. Add a test asserting `TextInputScreen` passes `autoCorrect={false}` and an explicit `autoCapitalize` — the component has no test today.

## Blast radius

One component, two props; it reaches both screens that use it (Payee, Narration) and nothing else. No change to the suggestion query, the commit path, or any caller. Purely additive from the user's point of view: it removes silent rewriting.

Not exercised: a **physical device with a real keyboard**, which is where this should be confirmed before and after — the synthetic-keystroke limitation above means the simulator cannot settle how bad it is, only that it happens. Also not exercised: Android (where `autoCorrect` maps to a different platform behaviour), non-English keyboards, and whether a mangled payee actually lands in the file, which needs write authorization.

## Adjacent states

The rest of the payee picker is **good**: suggestions are recency-ordered with a clock affordance, deduplicated by trimmed value, capped at `MAX_SUGGESTIONS = 30` with the cap applied *after* filtering (so typing recovers any of the ledger's 37 payees — checked by BQL), a skeleton shows only while the query is in flight and no matches exist, `clearButtonMode="while-editing"` gives a one-tap reset, and `onSave?.(…)` is optional-called so a deep-linked visit with no registered callback cannot crash — the failure mode `w4/034` reports on two other routes, handled correctly here.

`payee-input-screen.tsx` also documents why quick-add passes `simpleOnly` (list only payees with a two-posting transaction, matching quick-add's FROM→TO model) and pins the journal query to `network-only` so suggestions cannot come from a cold-start cache that omits today's entries. Both are deliberate and correct.

---

**Resolved 2026-09-14** in `fix(mobile): stop iOS rewriting payees and narrations`. `TextInputScreen` backs both the Payee and Narration screens.

**The change.**
- Its field now sets `autoCorrect={false}` and an explicit `autoCapitalize="none"`.
- It commits the trimmed value, whether saved from the header or a suggestion tap.

**The capitalization choice.** The note asked for a deliberate decision. `"none"` fits both screens, where `"words"` would title-case every narration, and it matches the conservative option the note offered for import strings. No field inherits `"sentences"` any more.

**Tests.** `components/text-input-screen/__tests__/text-input-props.test.ts` checks the source for both props and the trimmed commit. With the component reverted, both tests fail. The mobile gate passes, with 1935 unit tests.

**Not exercised.** A physical keyboard, Android's autocorrect mapping, and a saved payee (a production write).

**Severity:** minor. **Estimate:** 45 minutes. **Owner:** dashboard. **A2/A3:** readers should be able to reconcile an account quantity across Statistics and Holdings without unexplained rounding.

**Resolved 2026-09-19** — Reproduced against a local build at 390px and 1440px:
Statistics' Account Last Entries showed `4.01 ETH` for
`Assets:Crypto:Wallet:MetaMask:ETH` while the Holdings-by-account control
showed `4.00995 ETH` for the same account, and the simpler `0.072 BTC` mining
balance survived unchanged — precision-dependent, exactly as recorded.

`account-last-entries.tsx` converted each decimal string with `Number(amount)`
and passed it to `useFormatNumber`, whose `renderCommas` branch calls
`toLocaleString` with no fraction options, keeping three fractional digits.
These cells are unit quantities, so they now use `formatDecimalCell` from
`common/lib/format/inventory-cell.ts` — the shared lossless contract Holdings
and BQL already use — rather than a private Holdings helper or a global change
to the number hook that also serves report charts, hierarchies, Overview,
Budget and the Statistics counts. The computed-zero (`0`) and absent (`N/A`)
cases, multi-currency lines, the deliberate full-ledger last-entry dates from
`w3/m14` and `w3/138`, the filter scope and the keyboard account destinations
from `49562f6e` are all unchanged, and no API or dependency changed.

After the fix Statistics reads `4.00995 ETH` at both widths, matching Holdings,
with the `2026-09-16` date and `0.072 BTC` untouched.

The existing suite mocked `useFormatNumber` to `String`, so it could not catch
the production rounding; that mock is gone and the cell no longer uses the hook.
Seven new cases run the real formatting path over the reproduced quantity, a
satoshi-scale `0.00000001`, a long `1234567.891234`, a negative `-2.000005`, a
multi-unit balance and the zero/absent distinction; five fail against the
rounding formatter. Gates from `dashboard/`: `yarn format:check`, `yarn lint`,
`yarn test` (403 files, 4543 passed, 1 pre-existing skip) and `yarn build` all
pass. Other engines and locales, failure-state transitions and
`render_commas=false` in production remain unverified. Shipped in `b6d1c9ed`
(`dashboard`).

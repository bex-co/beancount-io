# Preserve exact amounts in Money movement averages

**Minor · 45–60m · dashboard · A2.** Residual of [1015](./done/1015.md): its source-aware formatter cannot recover a nonzero preceding-period average that `averageBalances` already rounded to zero. Monthly income **0.003 BTC** and spending **0.001 BTC** both have zero averages, beside correct totals and USD comparisons. The same numeric calculation also changes **9007199254740993 USD** into **9007199254740992.00 USD** before formatting.

## Reproducer and expected result

Use a synthetic ledger with operating currency USD, commodity BTC and these six transactions: in each of January, February and March2026, transfer **0.003 BTC** from `Income:Mining` to `Assets:Crypto`, **3.00 USD** from `Income:Salary` to `Assets:Bank`, **0.001 BTC** from that asset to `Expenses:Fees`, and **1.00 USD** to `Expenses:Food`. Each month's two transactions balance independently in both units. The complete valid fixture is retained with the evidence below.

1. Open Overview and set Time **2026-Q1**. Money movement initially selects March2026.
2. Read Money in and Money out, then their “Average of up to 3 preceding periods” footers.
3. Previous → February, Next → March; then Previous twice → January and Next → February.

| Readout | Expected | Actual |
| --- | --- | --- |
| Monthly income / category | +0.003 BTC | +0.003 BTC, correct |
| Monthly spending / category | −0.001 BTC | −0.001 BTC, correct |
| February and March income average | +0.003 BTC | **0 BTC** |
| February and March spending average | −0.001 BTC | **−0 BTC** |
| USD averages | +3.00 / −1.00 USD | correct |
| January, no preceding point | — on both cards | correct |

February averages one preceding point and March averages two identical points, so both expected BTC averages follow directly without a repeating quotient. Back/forward month selection repeats the failure. Time and both View all links retain their selected month scopes.

## Cause and bounded repair

`dashboard/src/features/reports/overview/lib/overview-utils.ts:324–345` sums numeric amounts, then sets every unit's average to `Number((value / points.length).toFixed(2))`. `getMovementSnapshot` passes this already-rounded result to the two Money movement cards (`money-movement-section.tsx:228–240,141–147`). This is the only production caller of the snapshot helper; the average has no source decimal left for `FormattedAmounts` to preserve.

The complete served `averageBalances` block in `ledger._ledgerOwner._ledgerName.index-Dt5Wt5tH.js` equals current main `a7c963be1` and working source (SHA-256 `9caac4ef648322d763e5fd7b60bde87871ead9f9f1be840f7e9240349121cb2e`). Whole utility/component modules differ due to other fixes. Direct execution of the complete current utility and current formatter modules produces the same zero averages, including after1015's formatter repair. Targeted history dates this calculation to `af5339de0`; fetched main retains it. No whole-build match is claimed.

Repair the average calculation/model with decimal summation and bounded decimal division, retaining an exact decimal alongside any approximate numeric value until display. Preserve whole-unit digits as well as a commodity's meaningful fractional precision. Keep ISO currency minor-unit formatting at the existing shared formatter boundary, and give derived commodity averages suitable bounded precision, including repeating means, without exposing floating-point residue. Reuse the existing decimal/formatting utilities; do not import another feature's private Holdings helper or add a dependency. Preserve per-unit separation, signs, available preceding-point denominator, three-point cap, filters, totals/categories and the empty-history dash. This needs no API, backend, translation or product-flow change.

Acceptance: the native sequence above shows +0.003/−0.001 BTC averages at both widths while USD and January controls remain correct. Add meaningful helper/rendered regressions for these nonzero commodity means, a genuine zero, a repeating mean and ordinary ISO currencies. Run dashboard gates and distinguish locally repaired behavior from deployed behavior.

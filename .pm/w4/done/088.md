Severity: minor accessibility defect. Estimate: 50m, dashboard. A2: public-ledger readers should receive an accurate current-page indication when navigating with assistive technology.

Environment: production https://beancount.io, anonymous open_ledger/example, isolated headless Chromium149.0.7827.55, English/light320×800 and fresh1440×1000. Local main26d54a9db7d33c31a549bd12a0454a1c01f3f038; deployed main-BIr0jJni.js, exact deployed commit unverified.

**Resolved 2026-09-19** — Reproduced against a local build of the public
example ledger: on `/ledger/open_ledger/example/journal` four links declared
`aria-current="page"` at once — the owner link, the sidebar Overview (with
`data-active="false"`, disagreeing with its own visual selection), the sidebar
Journal, and the Related Pages Overview. A filtered journal URL repeated all
four, and the owner link kept claiming it on the owner page itself.

The cause is `Link`'s default prefix matching: `activeOptions.exact` defaults to
false, so every ancestor destination matches, and an active link automatically
receives `aria-current="page"`. The fix sets destination-appropriate matching at
the application's navigation consumers, in a single shared constant
(`dashboard/src/common/lib/navigation/active-options.ts`) because the reasoning
is the same everywhere: exact pathname matching, with `includeSearch` off
because the sidebar propagates filters such as `time` into its hrefs and the
journal is still the current page on a filtered journal URL — under `exact` the
router would otherwise require a deep-equal search object.

Applied to the sidebar menu and submenu links, the ledger switcher's owner and
dashboard links, Related Pages, and — found while verifying — the remaining
"go to dashboard" links on the profile header and the two error states, which
made the same false claim on every `/ledger/<user>` URL. The router-wide
defaults and the dependency are untouched.

After the fix exactly one link declares the current page on Documents at 320px
and on Journal, filtered Journal and Overview at 1440px, and it is always the
one with `data-active="true"`. Navigation still works from the narrow sheet
(which still dismisses on navigate), the expanded sidebar and the collapsed
rail: 7/7 live checks. Four regression cases in
`ledger-layout/__tests__/current-page-links.test.tsx` drive a real router over a
real history rather than a mocked `Link`; three fail before the change and the
fourth is the control that must keep passing. Gates from `dashboard/`:
`yarn format:check`, `yarn lint`, `yarn test` (388 files, 4386 passed, 1
pre-existing skip) and `yarn build` all pass. Shipped in `c92d8e71`
(`dashboard`).

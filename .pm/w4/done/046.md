# 35 translation keys are dead — 455 translated strings across 13 locales that nothing can render

**Severity:** trivial. **Estimate:** 20–30 minutes to delete, longer if a detector is added. Owner: mobile. A3: every locale file carries them, so each is a line a translator has to read, decide about, and keep in sync forever, for a string the app can never show. Two of the 35 are more than clutter and are called out below.

Environment: branch `main`, HEAD `038faeeb`; static analysis of the repository at that commit. No device interaction, no runtime state touched.

## The finding

`src/translations/en.ts` defines **464 keys**. **35** of them are referenced nowhere in `src/` or `app/` — not as a literal, and not reachable from any dynamic `t()` call site. All thirteen locale files define most of them, for **455 dead key definitions in total**.

## Two that are not just clutter

- **`editConflict`** — the message for a rejected stale-checksum save on Edit Transaction, translated 13 times for a branch that was never written. That is **`w4/045`**, filed separately, and it should be fixed rather than deleted.
- **`ledgerEditorSaveSuccess: "File saved"`** — unused **deliberately**. `ledger-file-editor-screen/index.tsx:431-433` says so: *"This save stays on the screen and shows no toast, so the haptic is the only confirmation the user gets."* Worth pausing over before deleting: a simulator has no Taptic Engine, so that confirmation has never been verified by this QA tooling and cannot be (`mobile/CLAUDE.md` says as much), and `w4/029` establishes that the toast it was rejected in favour of does not render anywhere anyway. Whether a save with no visual confirmation is the right call is a product question, not a cleanup one — **do not delete this key as part of a sweep**; resolve the question first.

## How the list was verified

Naive "key not found as a literal" over-reports, because keys are also built dynamically. The list above survives that objection:

1. Every `t(...)` call site whose argument is **not** a plain string literal was enumerated — 41 of them.
2. Each was resolved to its key space. All but one resolve to literal key strings that appear in code (`RANGE_LABEL_KEYS`, `TIME_SPAN_LABEL_KEYS`, `STATUS_LABEL_KEYS`, `DATE_RANGE_LABEL_KEYS`, `VALIDATION_KEYS`, `CATEGORY_KEYS`, `intervalLabelKey`, `directiveTypeLabelKey`, `failureMessageKey`, `receiptErrorKey`, the merchants `titleKey`, the reports card's `titleKey`/`emptyKey`, the agent presets, the `discoveryTab_${value}` and `discoveryEmpty_${tab}` templates), so those keys were already counted as used.
3. The one exception is `t(month.slice(5, 7))` — documented at `series-util.ts:164` and `income-expense-bar-chart.tsx:31` — whose key space is the numeric month keys `"01"`–`"12"`. None of the 35 is a numeric key.

**An earlier pass in this run got this wrong** and did not file: a prefix heuristic flagged `discoveryEmpty_*` and `budgetInterval*` as dead when both are built dynamically, so the list was untrustworthy. Enumerating the call sites instead of guessing at prefixes is what made it publishable.

## Fix

Delete the 33 keys from `en.ts` and from every locale file — all except `editConflict` (wire it up, per `w4/045`) and `ledgerEditorSaveSuccess` (decide the product question first).

Then add a detector so this cannot re-accumulate, and run it in the unit suite. It must handle dynamic construction, which is why `lint:deadcode` cannot do this — Knip analyses modules and exports, and a locale file is one object export whose keys it has no reason to trace. The rule needs to be i18n-specific:

- collect keys from `en.ts`;
- collect every string literal in `src/` and `app/` and treat a match as a use (deliberately generous — it is better to miss a dead key than to delete a live one);
- **fail on any non-literal `t()` argument that is not on an allowlist**, so a new dynamic call site forces someone to declare its key space rather than silently widening the blind spot.

Also worth checking in the same pass: keys present in a non-English locale but absent from `en.ts`. That direction was not swept here.

**Acceptance:** `en.ts` has 429 keys; every locale file defines a subset of them; the detector reports zero dead keys and fails when a key is added and left unused, and when a dynamic `t()` call site is added without an allowlist entry; the app renders identically (no key rendered as its own name).

## Blast radius

Translation files only, plus one new check. **No runtime behaviour changes** — deleting a key nothing reads cannot change what renders, which is why this is trivial and also why it is safe to do in one commit. The one risk is deleting a key that *is* reachable; step 2 above is the guard against that, and the generous literal match biases toward keeping.

Not verified: the Bulgarian and Persian files beyond key presence, and whether any locale carries keys `en.ts` lacks (see above).

## Adjacent states

The i18n setup itself is in **good shape**, which is the context this finding belongs in: every key used in code exists in `en.ts` (the reverse sweep returned **zero** missing keys, so nothing in the app can render a raw key name), other locales extend `en` so an untranslated key falls back rather than blanking, and `useTranslations()` subscribes to `localeVar` so a locale change re-renders. The one place the app bypasses `t()` entirely is the three delete-account messages — that is `w4/043`.

## Dedupe

Searched all `.pm/**/*.md` including `done/` for translation, i18n, locale, dead-code and unused-key terms. `w4/025` (seven dead GraphQL operations) and `w4/026` (178 tests that never import their subject) are the same family — real dead weight that `lint:deadcode` structurally cannot see — and a fix for this one should be cross-referenced there. `w4/045` and `w4/043` are cited above. `w3/001` retired the Mixpanel wrapper, which is plausibly where some of these strings were orphaned, but it does not cover them. No item covers translation keys.

**The detector.** A new `translations/__tests__/unused-keys.test.ts` fails when an English key is not reachable. A key counts as used when it appears as a quoted literal anywhere in `src/` or `app/` outside the translation files: generous on purpose, so a live key is never reported dead. Two kinds of exception are declared in the test:
- template-built families: `discoveryTab_*`, `discoveryEmpty_*`, and the month keys `01`–`12`
- keys deliberately unused, each with its reason

**Proof.** Adding an unused key fails the detector, and locale integrity in every other locale. The mobile gate passes: `format:check`, `lint`, `typecheck`, and `test:unit` (1935 passed).

- A separate reverse sweep (keys in a locale but not English): locale integrity's "no extra keys" check already enforces it.

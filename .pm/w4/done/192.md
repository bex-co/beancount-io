# Give empty ledgers a direct Add transaction action

**Source:** `/pm-brainstorm for w4`, candidate 1, approved with `$pm both to w4` on 2026-09-28. The user explicitly requested a step to show the final screenshot after the work is done. **Scope:** `mobile/`. **Estimate:** 45–60m. **Worker:** worker1. **Goal:** A2 — a newcomer can open the first-entry form directly from empty ledger content.

Home's recent-transactions card currently displays an empty-state sentence; Transactions tells the user to find the header's plus button. Add a visible, labeled Add transaction action to both empty states, reusing the existing transaction form, navigation, permission checks, and translated labels. Preserve distinct loading, failed-read, filtered-empty, and read-only states.

Source files: `mobile/src/screens/home-screen/components/recent-transactions-card.tsx`, `mobile/src/screens/home-screen/home-screen.tsx`, `mobile/src/screens/transactions-screen/transactions-empty-state.tsx`, and `mobile/src/screens/transactions-screen/transactions-screen.tsx`.

Why now: [w4/191](./191.md) shipped empty Starter templates in `2d754ae2`; [m29](./m29/README.md) also makes guest/read-only behavior part of ordinary navigation. The expected outcome is an obvious first-entry action for a writer, with fewer taps to the existing form. Record the before/after tap count in a repeatable native walkthrough; no analytics is needed.

Steps:

1. Add the action to the two genuine empty states, wired to the existing add flow and the currently selected ledger. Preserve the shared header geometry and refresh behavior.
2. Verify writer navigation and absence of write actions for guests/readers. Check loading, errors, filtered-empty results, light/dark themes, and enlarged text. Review the mobile README for any affected walkthrough wording and run the mobile package's required checks.
3. **After the implementation and checks are complete, capture and inspect final screenshots from the running app, then show them to the user in the completion response.** Include Home and Transactions with the new action visible in light and dark themes. Capture the final UI after the last relevant change; use synthetic data and keep artifacts in `mobile/tmp/w4-192/`. Display the actual images in the handoff, rather than only claiming verification or listing file paths. Do not mark this item complete until this screenshot handoff is ready and included with the completion report.

Acceptance:

- Each empty-state action opens the existing form for the selected writable ledger in one tap; no duplicate form or new backend operation is introduced.
- Guests/readers have no write action. Query failures and filtered-empty results retain their own truthful states.
- Labels, focus targets, layout, and contrast work in both themes and with enlarged text.
- The completion response shows the final Home and Transactions screenshots; the resolution record identifies the verification context and screenshot artifacts.
- Verification can open and discard the form without saving a transaction. Use isolated synthetic fixtures for any setup requiring writes and follow `mobile/AGENTS.md` for live verification.

# Keep zero-value Cash Flow summary lines in Markdown and print

Severity: **minor**. Estimate: **40–60 minutes**, dashboard only. A2 — exporting a valid zero-movement statement should preserve its net-change line and complete cash reconciliation.

## Fresh live reproduction

Production `https://beancount.io`, public synthetic `open_ledger/stock-example`, authenticated read-only QA, English/System, owned headless Chromium **149.0.7827.55**. Fresh **1440×1000 and 390×1000** loads reproduce. Current main retains the renderer cause; deployed full SHA is unverified. No response substitution or production writes.

1. Open `/ledger/open_ledger/stock-example/cash-flow?time=2024-01-08`. Choose **Units**, wait for the settled cash table and export controls.
2. The page shows Brokerage Cash **50,000 USD**, Bank Checking **10,000 USD**, opening cash **60,000 USD**, closing cash **60,000 USD**, and a present Net Change row displayed as a dash for zero.
3. Download **Markdown report**. Its Statement summary contains only opening **60,000.00 USD** and closing **60,000.00 USD**. The zero Net Change line and all three zero net operating/investing/financing totals are missing.
4. Inspect the actual statement portal under headless print media. It likewise has exactly **two summary rows**, opening and closing. Both widths produce the identical omissions and successful downloads; no print-dialog or printer verification is claimed.

Independent read-only Account Journal controls return HTTP 200: Bank Checking has a January 7 generated opening **60,000 USD**, then a January 8 change **−50,000 USD** and closing **10,000 USD**; Brokerage Cash changes **+50,000 USD** and closes **50,000 USD**. This is a real transfer between recognized cash accounts, with zero net cash movement, not a missing-cash classification case or an empty report. Existing **w4/198** already records this transfer as a valid cash-only conversion control; preserve it.

Additional renderer boundary: `/ledger/open_ledger/adyen/cash-flow?time=2025`, Units, has an empty model closing-balance map. Its page retains the closing-cash row and CSV retains the closing `net_change` total row with blank amount/unit, but Markdown and print drop that closing line. Do not infer Adyen's cash-account classification is wrong: its unannotated `CashAndCashEquivalents` name falls outside the documented heuristics. The primary reproduction above has recognized cash accounts and needs no classification judgment.

## Cause and bounded repair

`dashboard/src/features/reports/export/model.ts` builds the activity-total and opening/net-change/closing rows even when a sparse balance map produces `amounts: []`. `presentation.ts:232–263` returns all six Cash Flow summary items; it does **not** discard the empty row. But `markdown.ts:184–192` flatMaps only `item.row.amounts`, and `printable-statement.tsx:348–363` does the same. An empty map therefore produces no rendered line at all. Nonempty balances, including the two 60,000 USD rows, render correctly.

Preserve every required summary line in both renderers. Represent a genuine sparse zero with its known statement unit; retain a truthful placeholder if a value/unit is unavailable, rather than erasing the row or inventing a balance. Prefer one shared presentation rule for these two consumers. Keep raw CSV rows, exact nonzero decimals, dates, statement signs, supporting-detail behavior, no-data/pending export gating and declarations unchanged. Do not change cash-account heuristics, recalculate flows, add balancing amounts or alter APIs/dependencies to fix this serialization defect.

Acceptance: the real transfer document renders all six summary labels in Markdown and print, with 60,000 USD opening/closing, zero net change and zero activity totals. A sparse closing row remains present, and genuinely unavailable units are handled honestly. Existing populated and multi-unit summaries retain their exact values and scope. Add a meaningful rendered regression using empty maps, checking actual Markdown lines and print rows, not just the six item keys returned by the helper. Run dashboard format/lint, tests and build when implementing.

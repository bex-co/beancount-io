## Objective

Apply the same serialization contract to requireAuth and the ledger UNAUTHENTICATED guard, without changing credential policy or native-window hash handling.

## Context

See [FINDINGS.md](./FINDINGS.md) for reproduction, source and evidence limits.

## Acceptance criteria

- [x] Both guards preserve nonempty router fragments when available and retain safe fallbacks for rejected destinations.

## Out of scope

Backend/API changes, authentication policy changes, new dependencies and unrelated login defects.

## Outcome

`requireAuth` in `common/lib/auth/auth.ts` and the ledger route's
UNAUTHENTICATED branch now both call `toRelativeLocation` instead of building
the string by hand, so all three continuation producers share one definition.
The only remaining concatenation in `src/` is inside the helper itself.

Nothing else changed: `getSafeRedirectPath` still validates and encodes, so the
unsafe-next rejection from w3/170 and the `fallbackPath` behaviour for a
rejected destination are as they were. The native-window hash consumers
FINDINGS asked to leave alone — `features/git/commits/components/commit-detail.tsx`,
which reads `window.location.hash` where the `#` is present — were not touched.

Verified live, signed out, 6/6 at 1440 and 390:

- navigating in-app to a guarded route at `/settings?lang=en#profile-section`
  sends login `next=/settings?lang=en#profile-section`, fragment intact;
- loading that same URL as a fresh page sends `next=/settings?lang=en`, because
  the browser never transmits the fragment — the server limitation FINDINGS
  records, not a regression;
- a plain guarded path still yields `/settings`.

Scope limit, stated rather than glossed: the ledger UNAUTHENTICATED guard fires
only for a ledger that exists but is not readable by the caller, which an
anonymous session cannot reach on the public instance without naming a private
ledger. It is verified here by source and by the shared helper's unit coverage,
not by a browser reproduction — the same limit FINDINGS placed on it.

Gates from `dashboard/`: `yarn format:check`, `yarn lint`, `yarn test` (377
files, 4253 passed, 1 pre-existing skip) and `yarn build` all pass.

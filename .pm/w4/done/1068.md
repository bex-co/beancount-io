## Cause and bounded repair

`dashboard/src/features/importer/utils/csv-validator.ts:232–243` votes from separator positions or a comma-tail match without checking the complete monetary spelling. `oops.1,00` gets a strong EU vote solely because its last comma follows its dot; `oops,12` gets a weak EU vote despite the alphabetic prefix. Both tokens are invalid under **either** convention, confirmed with the unmodified current parser.

`resolveDecimalConvention` at:255–267 accepts those votes. Its sole production caller, `hooks/use-csv-parser.ts:265–295`, filters record width but decides the convention before validating amount syntax. `buildParsedRow` later rejects the bad cell while storing `decimalComma:true` on the accepted row. Preview, inline validation (`utils/row-edit-schema.ts`) and `lib/import-config-draft.ts:44–83` consistently reuse that contaminated decision. The actual current configuration builder yields a selected transaction with raw `amountInput:"-1,250"` and exact **`amountDecimal:"-1.250"`**; this is not merely trimmed display zeros.

Require a complete supported monetary spelling before using its separators as column evidence. Keep one convention for the whole file, raw tokens and useful errors. Preserve valid currency/sign/grouping wrappers, [1054](./done/1054.md)'s supported grouping evidence, genuine mixed-column refusal, exact-decimal/unsupported-precision handling and per-row propagation. Distinguish malformed syntax from a syntactically valid decimal refused only for numeric precision. Do not guess each row independently or change backend/API behavior or dependencies.

Acceptance: both malformed companions are refused without changing the first row's **-1250** in Preview or Configure; the baseline and genuine comma-decimal control stay correct. Meaningful regressions must drive the actual CSV parser through valid-row/configuration construction, including strong/weak malformed votes and existing grouping/mixed/precision controls. Repeat native narrow/desktop upload/reset and run dashboard gates when implementing. QA authored no product code or formal tests.

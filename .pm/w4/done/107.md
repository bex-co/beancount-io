# Make historical Budget actuals readable without hovering the chart

Severity: minor. Estimate: 60 minutes, dashboard. A2/A3: a keyboard or assistive-technology user should be able to compare past actual spending with its budget without estimating canvas bars.

Environment: production https://beancount.io, September17 local / September18 UTC2026, isolated headless Chromium149.0.7827.55, signed out, English/light. Public synthetic budgeting-envelopes ledger, All intervals / All time, units conversion. Fresh390×844 and1440×1000. LocalHEAD26d54a9d; origin358ba4dc has no dashboard changes. Deployed main-BIr0jJni.js; exact deployed SHA unverified.

Reproduce:

1. Open `/ledger/open_ledger/budgeting-envelopes/budget?lang=en` and inspect Expenses:Dining.
2. Its chart plots January actual160.5USD, February0, March0 against a200USD budget for each month. Real pointer hover over January shows `2026-01-31 / Budget: 200 USD / Actual: 160.5 USD`.
3. Neither exposes historical actual160.5. Fresh desktop repeats the missing value; no chart button/link/input/tabindex exists. Tab from Last12months passes the chart and remaining static cards, ending at BODY in that desktop context.
4. The target-history table is not an actual-spending history: it contains the dated budget directive only. The page has no month stepper or equivalent actual-value table. Pointer-created tooltip text briefly enters AX, then disappears after pointer leave; this does not supply keyboard access.

January31 balance is USD160.5 and accountBalances matches; February28/March31 sparse balances are empty. Mounted chart options in both widths contain Budget[200,200,200], Actual[160.5,0,0]. Sparse-zero interpretation is correct; no numeric or backend bug claimed.

Root: `dashboard/src/features/ledger-data/budget/budget-chart-card.tsx:108` reads all periods, :114 exposes only the last actual, and :159–258 builds the historical values solely for ECharts. At401 the canvas has no data alternative; at409 BudgetHistoryTable reads group.budgetHistory rather than chartData. `common/components/react-echarts/client.tsx` renders an unnamed div/canvas; changing generic chart defaults cannot supply meaningful Budget-specific dates/units. The chart dates to af5339de;74fe6cbb correctly added sparse latest-zero handling, not historical access. BudgetChartCard's sole production owner is the Budget page; all account/currency cards share it. Actual live proof is the Dining monthly USD card.

Fix: provide a discoverable, keyboard-accessible, semantically named period-data table or equivalent structured text beside each Budget chart, with period, effective target, actual and unit. Reuse the existing calculated chart values and direction/currency/proration rules; do not recompute different financial semantics or add requests/dependencies. A concise named disclosure is acceptable for long histories; its expanded state, focus and hidden contents must work correctly. Keep the existing dated target-history table distinct. Coordinate names with w4/m20 without replacing that milestone's separate target-history labeling work. Preserve loading/error/empty states and permissions; never show a successful-looking zero table for a failed read.

Acceptance: January160.5USD and its200USD target, plus February/March zero actuals, are available without pointer hover at both widths. A real rendered test should assert the values after keyboard disclosure (if used), not just that an aria string exists. Exercise time-filter changes, sparse zero and failure transitions with the same model; preserve current sign behavior for income targets. Other interval/currency histories are source-scoped regression cases, not claimed live reproductions.

Working controls/dedupe: Overview Net Worth has Show table, and Overview Money movement exposes matching monthly income/expense values with keyboard Previous/Next; no blanket inaccessible-chart finding is being filed. Full board search including done/blocked found w3/done/124, the analogous native-mobile chart repaired in a different package; w4/m20 only names already-existing history tables. Neither repairs this dashboard's missing historical actuals. No newer main repair found.

The repair follows [W3C guidance for complex charts](https://www.w3.org/WAI/tutorials/images/complex/): provide textual access to essential chart information, with structured data where useful. This browser inspection is not a full WCAG audit or an actual screen-reader speech test.

**Resolved 2026-09-19** — Reproduced against a local build of the public
budgeting-envelopes ledger: the `Expenses:Dining` card's text contained
`Current budget 200 USD`, `Latest actual 0 USD`, `Variance -200 USD` and the
dated target history, and `160.5` appeared nowhere at 1440px or 390px. The card
had no focusable chart element.

`budget-chart-card.tsx` built the historical values solely for ECharts. They
now come from one `periodRows` model that both the chart series and a new table
read, so the readable values cannot drift from the canvas. The table sits
behind a named, keyboard-reachable disclosure, closed by default so long
histories stay out of the way, and lists each period with its effective target,
its actual and the currency. It reuses the existing calculation, direction and
proration rules — including the sign convention for income targets — and adds
no request or dependency.

It renders only for a settled, non-empty read, so a failed read shows the
card's own error instead of a table of zeros. It carries its own accessible
name (`… Period data`), because the card already stacks the dated target
history and two identically named tables would be indistinguishable to anyone
navigating by table; that existing history table is untouched, so `w4/m20`'s
labeling work is unaffected.

Verified in a real browser, 10/10 at 1440px and 390px: the disclosure is closed
on load, Enter opens it, and January reads `2026-01-31 / 200 USD / 160.5 USD`
with February and March at `0 USD`; the target history remains a second table;
an aborted `GetLedgerIntervalTotals` read shows the connection message and no
table; and switching the page's time span takes the table from 3 periods to 12
in step with the chart.

Seven rendered cases in `budget/__tests__/period-data-table.test.tsx` assert the
table against the chart's own captured series rather than numbers typed into
the test, and cover the loading, error and empty reads, the column names, the
separate target history and an income target's signs; four fail without this
change. Gates from `dashboard/`: `yarn format:check`, `yarn lint`, `yarn test`
(398 files, 4462 passed, 1 pre-existing skip) and `yarn build` all pass.

Noted while testing: the raw interval budget value carries floating-point noise
(`199.99999999999986`), which the shipped formatter rounds away — pre-existing
and equally true of the chart, so not changed here. Authenticated edit
controls, physical screen readers and other engines remain unverified. Shipped
in `4673ee9f` (`dashboard`).

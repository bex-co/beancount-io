**Resolved 2026-09-19** — Reproduced against a local build of the public
example ledger: at page 2 of `Assets:US:BofA:Checking` the URL was still
`?lang=en`, so nothing about the position reached history. Opening the entry's
source at `main.bean:773` unmounted the table and Back rebuilt it at offset 0 —
first entry `2017-09-07` instead of `2017-06-21` — at both 1440px and 390px.

The position now lives in the route's validated search params, the way the main
Journal has since `4d701a91`. A new `features/reports/account/search.ts`
declares only the account journal's own `offset`; the shared account/filter/time
params stay on the parent ledger route, so this is not turned into a shared
report filter. Page moves replace the history entry, so Back still leaves the
account rather than walking back through every page visited, and an explicit
link can carry a page. The value is untrusted and re-coerced on read.

A genuine filter change still starts again at the first page, and that reset had
to move into `LedgerSearchParamsProvider`'s own navigation: the pending layout
can unmount the page, so a reset owned by it would never run. That is exactly
why the Journal's reset already lives there; the gate now covers both paginated
lists instead of only the Journal.

Verified in a real browser, 9/9: page 2 → `main.bean:773` → Back returns to
`2017-06-21` with the query asking offset 20 again, at 1440px and 390px; a
second account (`Expenses:Food:Groceries`) round-trips its own page; applying a
shared filter drops the offset and re-queries at 0; `?offset=-5`, `?offset=abc`
and `?offset=2.7` render the first, first and third rows; `?offset=999999999`
settles on the last page at offset 260 with 30 rows; and the main Journal still
records `offset=60` on its own Next. Seven regression cases in
`features/reports/account/__tests__/account-pagination-url.test.tsx` drive a
real router over a real history and assert the offsets the GraphQL query
actually asked for — including the unmount and Back — and five of them fail
without this change. Three existing account suites that render the table
without a router gained stubs for the two router hooks it now uses.

Gates from `dashboard/`: `yarn format:check`, `yarn lint`, `yarn test` (389
files, 4407 passed, 1 pre-existing skip) and `yarn build` all pass. Other
browsers and authenticated editing remain unverified. Shipped in `e0bd19de`
(`dashboard`).

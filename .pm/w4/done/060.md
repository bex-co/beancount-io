# Chart axes glue the currency symbol on by hand — "$-50.0" on a USD ledger, a bare "400.0" on a commodity one

**Severity:** minor, with an arm that is arguably major (see below). **Estimate:** 20–30 minutes. Owner: mobile. A2/A3: on the public `open_ledger/minimax` the Reports chart's Y axis reads `400.0` / `-200.0` with **no currency at all**, while the hero card three inches above it on the same screen correctly reads `1,346.68 MUSD`. The file that formats money already forbids exactly this, in a comment, and implements the rule correctly for every non-chart figure.

Environment: branch `main`, HEAD `038faeeb`, native development build `io.beancount.ios` on iPhone 17e / iOS 26.5, English / System / light / default text size, authenticated production session at `https://beancount.io`. Two ledgers: own `puncsky/example` (USD) and public `open_ledger/minimax` (MUSD). Report-only QA; no ledger mutation — only the selected ledger and the Reports/Home tabs were touched.

## Repro — arm 1: the sign lands on the wrong side of the symbol (USD)

1. Select `puncsky/example`, Reports tab, **6M**.
2. The income/expense chart's Y axis reads, top to bottom:

   ```
   $100.0   $50.0   $0.0   $-50.0   $-100.0
   ```

   `$-50.0` and `$-100.0` put the minus **after** the dollar sign. Every other money string in the app puts it before.

## Repro — arm 2: no currency at all (MUSD)

3. Switch to `open_ledger/minimax` (Browse ledgers → `open_ledger/minimax`), Reports, **6M**.
4. The same axis now reads:

   ```
   400.0   200.0   0.0   -200.0   -400.0
   ```

   Bare numbers. 400.0 of what is not answerable from the chart.

5. **The control is on the adjacent screen, same ledger, same session.** Home on `open_ledger/minimax` renders the hero as **`1,346.68 MUSD`**, its delta as `+3,994.87 MUSD`, and every Recent Transactions row as `357.997 MUSD` / `3,994.853 MUSD`. So the app does know how to label this commodity; the chart axis is the one place that doesn't.

Note the two arms are mutually masking: on MUSD the sign reads correctly (`-200.0`) *because* the symbol is empty, and on USD the currency is present *because* USD has a symbol. Neither ledger shows both faults at once, which is probably why this survived.

## Root cause

Five call sites build the string by hand with the same idiom:

| site | what it labels |
| --- | --- |
| `src/common/d3/scrollable-axis-chart.tsx:78` | Y-axis ticks — Reports income/expense **and** the Budget screen's per-group chart |
| `src/common/d3/bar-chart-d3.tsx:89` | Y-axis ticks — Home's Spending card |
| `src/common/d3/income-expense-bar-chart.tsx:158, 161, 164` | the chart's `accessibilityLabel` (income, expense, net totals) |

all of the form:

```tsx
{`${currencySymbol}${shortNumber(tick)}`}
```

`shortNumber` (`number-utils.ts:13-42`) returns its own sign as a leading `-`, so prefixing a symbol yields `$` + `-50.0`. And `getCurrencySymbol` (`currency-util.ts:12-17`) returns **`""`** for any code `currency-icons` doesn't know — `MUSD`, `VACHR`, `IRAUSD`, `STETH`, `CUSDC` — so the interpolation contributes nothing and the number ships unlabelled.

**The correct rule is written down, in the same file, twenty lines below `shortNumber`.** `number-utils.ts:56-57`:

> *"Sign prefix + grouped absolute amount, shared by the money formatters. **The sign is always a prefix**; only the currency's placement differs between them."*

and `:83-86`:

> *"a known symbol prefixes (right after the sign, e.g. `-$1,234.50`); an unknown/symbol-less currency's code is appended after the amount (e.g. `1,234.50 MUSD`), **so a custom commodity is never shown as a bare, unlabeled number**."*

`annotateCurrency` implements both rules, and `formatMoneyWithCurrency` / `formatSignedMoneyWithCurrency` route everything else in the app through it. The charts bypass it — they take a `currencySymbol` prop rather than a `currency` code, so `annotateCurrency`'s fallback branch is unreachable from where they stand.

## Fix

Give the charts the **currency code** instead of the symbol, and format through the existing helper rather than by hand. A short-form sibling of `annotateCurrency` is the smallest honest version:

```ts
/** `shortNumber` with its currency, following the same rules as the long form. */
export const formatShortMoneyWithCurrency = (
  value: number,
  currency: string,
): string => {
  const sign = value < 0 ? "-" : "";
  return annotateCurrency(sign, shortNumber(Math.abs(value)), currency);
};
```

giving `-$50.0` and `400.0 MUSD`. Then replace all five call sites and thread `currency` down in place of `currencySymbol` through `ScrollableAxisChart`, `BarChartD3`, `IncomeExpenseBarChartD3` and `BudgetBarChartD3`.

**Do not** fix it by moving the `-` at each call site: that leaves the symbol-less arm — the worse one — untouched, and adds a sixth hand-rolled formatter to a file whose entire point is that there is one.

Check the axis width after the change. `LEFT_PADDING` in `scrollable-axis-chart.tsx` and `leftPadding` in `bar-chart-d3.tsx` are sized for `$400.0`; `400.0 MUSD` is meaningfully wider and the ticks are `textAnchor="end"`, so an appended code may collide with the plot. If it does, the honest options are a narrower code position or a single currency caption on the chart — not dropping the label again.

**Acceptance:** on `puncsky/example` the Reports axis reads `-$50.0`, not `$-50.0`; on `open_ledger/minimax` it reads `400.0 MUSD` (or another unambiguous placement), not `400.0`; Home's Spending card and the Budget screen's group chart get the same treatment, since they share the two tick sites; the `incomeExpenseChartSummary` and `budgetChartSummary` accessibility strings carry the same currency; and a USD ledger's positive ticks are unchanged (`$50.0` stays `$50.0`). Add unit tests for the new helper covering negative + known symbol, negative + unknown code, zero, and a value large enough to take a suffix — `shortNumber` has tests but nothing covers its composition with a currency.

## Blast radius

Four chart components and one new formatter. No change to `shortNumber`'s numeric output, to `annotateCurrency`, or to any of the long-form money formatters, so every non-chart figure in the app is untouched.

Surfaces affected, all three observed or shared-by-code:

| surface | observed |
| --- | --- |
| Reports → income/expense chart axis | **yes**, both ledgers |
| Budget screen → per-group chart axis | shares `ScrollableAxisChart:78` — not observed (needs a ledger with budgets) |
| Home → Spending card axis | shares `bar-chart-d3.tsx:89` — not observed (`puncsky/example` has one month of expenses in range) |
| chart accessibility labels | source only; VoiceOver is unavailable on Simulator (`w4/002`) |

Not exercised: dark mode (this is string composition, so it should be identical, but it was not checked), enlarged Dynamic Type against the axis width concern above, RTL (where a prefixed sign and an appended code both want re-examining), and Android.

## Adjacent states

The rest of the Reports screen behaved correctly across the ledger switch: the 6M pill stayed selected, the income/expense series and the Sankey both re-fetched for the new ledger with no stale bars, and the month labels moved from APR–SEP to JAN–JUN, matching minimax's last activity. The `puncsky/example` axis range (`$100.0` max) reconciles with BQL: `SELECT year, month, sum(position) WHERE account ~ '^Expenses:' AND year = 2026` returns exactly one row, `2026-09 → $102.00`.

## Dedupe

`grep -rln 'shortNumber\|annotateCurrency\|getCurrencySymbol\|axis tick\|MUSD' .pm --include='*.md'` over the whole board including `done/`, then read every open hit.

- **`w4/024`** (open) is the closest and is **the same function, a different defect**: it covers `shortNumber`'s *numeric* output — the zero tick rendering `$0.0`, and rounding past its own suffix (`1000.0K`). It says nothing about the sign's position or the currency label, and its fix (round-then-suffix, drop the decimal when whole) does not touch either arm here. The two land in the same file and should be done in one sitting. **One amendment is owed to `w4/024` regardless of this note:** it frames the `.0` as *"the zero tick alone carries a `.0`"*, which is true only when the axis spans thousands. On `puncsky/example` at 6M every tick is under 1000, so the axis reads `$100.0 $50.0 $0.0 $-50.0 $-100.0` — **every** tick carries the stray decimal, not just zero.
- **`w4/016`** (open) is commodity accounts on the **Accounts** tab showing an unlabelled USD *cost basis*, and a cost-less commodity collapsing to `$0.00`. Different surface, different cause (cost conversion, not string composition), and different symptom — there the number is labelled with the *wrong* currency; here it is labelled with *none*. Its "not exercised" list explicitly parks *"Reports … and a ledger whose operating currency is itself non-USD (`open_ledger/minimax` is MUSD throughout)"* — which is precisely arm 2 above, so this note closes that gap rather than repeating it.
- **`w4/054`** (open) is the Sankey's accessibility label emitting bare 12-digit integers, and it already cites `bar-chart-d3.tsx:158` and `budget-labels.ts:145-146` as the *correct* precedent to copy. That remains the right call — `shortNumber` is still the right helper — but this note shows both precedents are themselves missing the currency rule, so `w4/054`'s fix should adopt the new helper rather than the raw idiom.
- **`w3/216`** (open), **`w4/005`**, **`w4/006`** are all "the sign is *lost*" — `formatMoneyWithCurrency` dropping it, or a layout detaching it. Here the sign is present, correct, and merely on the wrong side of the symbol. Related theme, no shared code.

No item covers the chart axis's currency composition.

**A sixth instance of the idiom exists and is already dead** (added September 14): `home-screen/selectors/select-transaction-amount.ts:61-67`'s `formatSignedAmount` builds `` `${sign}${currencySymbol}${Math.abs(amount).toFixed(2)}` `` — sign in the right place, but symbol-only (so no fallback for a symbol-less commodity) and without thousands grouping. It has **no production callers**, and its test pins `"+$1000.00"`. Filed as `w4/025` §2b, where the deletion belongs; noted here only so the call-site count is not later found to be seven.

**Resolved 2026-09-14** in `fix(mobile): label chart axes and summaries with the currency, sign first`.

**The helper.** `number-utils.ts` gains `formatShortMoneyWithCurrency(value, currency)`, the short-form sibling of the long money formatters. It routes through `annotateCurrency`, so:
- the sign leads (`-$50`)
- a currency with no symbol is labelled by its code (`400 MUSD`)

**Where it is used.**
- **Charts:** `BarChartD3`, `ScrollableAxisChart`, `BudgetBarChartD3` and `IncomeExpenseBarChartD3` take a `currency` code instead of `currencySymbol`.
- **Summaries:** the income/expense summary and `budgetChartSummary` use the helper.
- **Callers:** Home's spending card, Reports and the budget group card now pass the code instead of computing a symbol. No `currencySymbol` remains in chart code.

A USD ledger's positive ticks keep their form (`$50`).

**Tests.**
- `number-utils.test.ts` covers negative with a known symbol, positive and negative with an unknown code, zero, and a suffixed value.
- `budget-labels.test.ts` moves to currency codes and adds an MUSD summary.
- `d3/__tests__/chart-currency-labels.test.ts` is a source guardrail over the four chart files and the callers.
- With the charts and labels reverted, 7 tests fail. With the helper putting the sign after the symbol, its tests fail. The mobile gate passes, with 1935 unit tests.

**Not verified.** The y-axis gutter (`LEFT_PADDING`, and 50 on the bar chart) is unchanged. Whether `400 MUSD`-style ticks fit it was not checked on device, and neither was Reports on `open_ledger/minimax`.

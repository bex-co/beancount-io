## Objective

Add meaningful aggregation and rendered integration regressions, then run dashboard gates.

See [FINDINGS.md](./FINDINGS.md) for evidence, source and limits.

## Acceptance criteria

- [x] Tests cover parent plus child, empty child, multiple depths, unit identity, mixed units, MUSD and Savings without cross-unit arithmetic.
- [x] Distribution percentages and Other grouping remain unit-specific; a regression to dropped parent balances, mixed-unit slices or literal USD fails; verify actual desktop/narrow chart values and tooltips.

- [x] Realistic intermediate tree nodes prove heuristic and declared role exclusions at all supported depths; flattened fixtures alone are insufficient.

## Outcome

37 new cases across four files, all against realistic account trees with real
intermediate nodes — every defect in this milestone was invisible to a
flattened fixture.

**`unit-amounts.test.ts` (14)** — the model that decides which number a reader
sees: every unit kept rather than USD-or-first, the API's decimal strings
parsed, *all* units negated on inverse, a malformed amount skipped rather than
truncated (`"12abc"` — the `parseFloat` trap t005 removed), zero and missing
amounts producing nothing, merging unit by unit, and each of
`chooseDisplayUnit`'s three tiers including independence from key order.

**`overview-chart-units.test.ts` (13)** — aggregation over the reported trees:
the two tax parents' postings surviving an empty child and an IRAUSD sibling
(27,931.15 USD kept apart from 18,000 IRAUSD, explicitly *not* 42,116.2), the
same total holding **at depths 1, 2 and 3**, nested Cash and Checking staying
out of an investing ancestor, a declared `investing` role keeping a cash-named
account, a declared `cash` role excluding one, Savings computed inside the
display unit while 999 vacation hours contribute nothing, an empty diagram
yielding no unit at all, and the distribution builder keeping VACHR out of both
the dollar slices and their denominator.

**`chart-unit-scope.test.tsx` (5)** — the disclosure, and the regression no test
had caught: `DistributionChart` must occupy **exactly one element**, note
included, because its call sites are cells of a two-column grid.

**`cash-flow-sankey-units.test.tsx` (5)** — the tooltip formatter, captured out
of the ECharts option and called directly: MUSD named rather than relabelled
USD, EUR named, USD still USD, and the omitted units disclosed.

Every defect class was proved load-bearing by reverting it:

| Reverted | Cases that fail |
| --- | --- |
| sum only children (drop a parent's postings) | 3 |
| read one unit per balance (USD-or-first) | 7 |
| let descendants inherit their ancestor's role | 3 |
| return the note in a bare fragment | 1 |
| append a literal ` USD` to every edge | 2 |

Restoring each passes 225/225 in `features/reports/overview`.

One test failed in a way worth keeping: the disclosure case was written with one
USD account against one IRAUSD account, and the diagram came out in **IRAUSD** —
the count tier ties, so magnitude decides and the larger retirement balance
wins. Nothing is misstated (the note correctly says USD is omitted), but the
choice is poor. The case was rewritten to the realistic shape and a second case
now documents the behaviour explicitly; the underlying improvement — prefer the
ledger's declared operating currency, which the net-worth cards already read —
is filed as [w4/146](../../146.md) rather than smuggled into a test task.

Gates from `dashboard/`: `yarn format:check`, `yarn lint`, `yarn test` (383
files, 4319 passed, 1 pre-existing skip) and `yarn build` all pass.

Desktop and narrow chart values and tooltips were verified in t004 by real
pointer hovers and are re-confirmed in t007.

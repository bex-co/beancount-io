## Objective

Check public example and Synopsys overview journeys and any new unit-selection or explanatory copy in all supported locales.

See [FINDINGS.md](./FINDINGS.md) for evidence, source and limits.

## Acceptance criteria

- [x] Readers can discover the displayed unit and any incomplete/unavailable combined view.
- [x] Check owning README and root adoption guidance for drift; do not add unrelated documentation or alter role policy.

## Outcome

**Readers can see the displayed unit.** Every Sankey edge tooltip now ends in
the unit the chart is actually drawn in, verified by real pointer hovers at
1440x1000 and 390x844 on four public ledgers:

| Ledger | Edge | Reads |
| --- | --- | --- |
| example | `Cash Flow → Expenses:Taxes` | 52,047.35 USD |
| example | `Cash Flow → Assets:US` | 73,386.297 USD |
| Synopsys | `Income:Revenue → Cash Flow` | 7,054 MUSD |
| Adyen | `Income:NetRevenue → Cash Flow` | 26,328,539,000 EUR |
| crypto-example | every edge | USD (single-unit control) |

**And the incomplete view is disclosed.** On the mixed example ledger the
assets pie says *"Amounts are shown in USD. Balances in VACHR are not
included."* and the Sankey says *"…Balances in IRAUSD, VACHR are not
included."* — each naming only what it omits. Single-unit Synopsys and
crypto-example render no note, because nothing is left out. The assets pie's
`Other` slice reads 386.28 (0.48%) at both widths.

All **15/15 locales** render both notes as real translations —
en, de, es, fr, pt, nl, ca, sk, ru, uk, bg, ja, ko, zh, fa — checked by
querying the note element itself. A first version of that check matched page
text with a regex and was passing on unrelated net-worth content; it was
rewritten to select the element, which is when it became evidence.

**Documentation.** The root `README.md` package table, `dashboard/README.md`
and the skill catalogs carry nothing about overview chart amounts, so nothing
drifted. Two owning documents did need work and got it:

- `features/reports/AGENTS.md` gained an **Overview chart units** section: why a
  chart that sums its parts can hold only one unit, that `unit-amounts.ts` is
  the single model, and the two aggregation rules (an account's own `balance`
  counts at every level; every descendant resolves its own role). It sits beside
  the existing multi-unit rules for statements and exports.
- `docs/PRFAQ-cash-flow-ledger-classification.md` claimed only that a `"cash"`
  role "excludes the account from flow nodes". Since t001 that exclusion also
  reaches ancestors' totals, so the sentence was understated and is now
  corrected. No role policy changed.

`python3 scripts/check-agent-guidance.py` passes (17 canonical scopes).

**A regression this task surfaced.** Walking the journeys is also what put the
overview grid under a microscope, and the simplify review then confirmed it: the
scope note added in t003 was returned from `DistributionChart` in a bare
fragment, so it became a third cell of the two-column Balance Sheet grid — the
note sat where the Liabilities card belongs and Liabilities dropped to the next
row. Measured at 1440: three cells, Liabilities 382px lower than Assets. Fixed
and shipped separately in `af3f009a`; the grid is back to two cells at the same
top, and no board task claimed to be complete while it was live.

Gates from `dashboard/`: `yarn format:check`, `yarn lint`, `yarn test` (379
files, 4282 passed, 1 pre-existing skip) and `yarn build` all pass.

Honest note on tooling: the consolidated browser suite proved unreliable at
sweeping canvas tooltips — small Sankey edges and a 0.48% pie slice are easy for
a hover grid to miss, and a run whose bundle was rebuilt mid-flight reported
empty results. Every figure above comes from targeted per-chart probes that
reproduce, and the suite now fails loudly when a page renders no charts instead
of reporting empty tooltips as passes.

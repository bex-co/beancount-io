## Cause and bounded repair

`components/steps/configure/account-mapping-table.tsx:172–183`, under `dashboard/src/features/importer/`, loops over every filtered index and calls `setValue("transactions.<index>.selected",…)` separately. Installed react-hook-form7.71.0's `dist/index.esm.mjs:1768–1806` clones the **whole form value** on every such call before notifying observers.

`transaction-config-form.tsx:140–170` also subscribes with `form.watch`; every notification maps the complete transactions array and passes it to `lib/import-config-draft.ts:111`'s `toImportConfigDraft`. Thus a single N-row action performs N full-form updates and N full-draft publications: quadratic work.

A control executes the **actual current AST-extracted toggle and watch callbacks**, actual draft helper and real installed `createFormControl`, without a React renderer. At2,000 rows it observes2,000 publications and **4,000,000 row choices copied**, taking3.336seconds. Removing only the draft watcher still takes3.170seconds: throttling that subscriber alone leaves the per-field full-form clones. A single aggregate update has one publication in the complexity control; rendered field-array identity/focus is unverified for that alternative, so it is not a verified repair.

Apply a bulk selection as a bounded form/draft update instead of N full-form copies. Build the final filtered selection once, publish its coherent final draft with bounded work, and keep the stable parsed-row identities and mounted-field/focus behavior. Preserve individual-row edits, mixed/empty/disabled states, search/amount-filter scoping, hidden selections, targets, exact amounts, pending locks and immediate Configure↔Preview draft retention. Keep the excluded-row repair from [309](./done/309.md). This is a dashboard selection/form boundary; no dependency, upstream fork or API change is needed.

Acceptance: drive the real Configure form and actual form engine through whole-list and filtered bulk toggles. The amount of full-draft copying must grow linearly, with a bounded number of publications per action, while IDs, targets, focus and selected counts remain correct. Include immediate Back/Continue, temporarily invalid/excluded rows and the current one-row controls. Recheck the2,000-row native journey at both widths and run dashboard gates when implementing. Avoid a flaky CI wall-clock threshold or a mocked setter that omits the actual form work. QA authored no product fix or formal tests.

## Objective

Create one typed, presentation-neutral statement model that both Balance Sheet and Profit & Loss can populate and that CSV and print renderers can consume without duplicating accounting-sign or hierarchy logic.

## Context

- Report-specific export code belongs under `dashboard/src/features/reports/export/`.
- The existing GraphQL responses provide `SerializableTreeNode` hierarchies and string-compatible amount maps.
- The current pages already know the ledger display name, primary currency, time/account/advanced filters, conversion, zero/closed-account preferences, and liability/income/equity display-sign preference.
- Amounts must remain strings through the export model; do not introduce JavaScript floating-point aggregation.

## Steps

1. Define `StatementExportDocument`, section, row, amount, and context types for both statement kinds.
2. Implement a pure recursive hierarchy flattener with deterministic order, depth, row kind, account path, currency, raw amount, and display-sign handling.
3. Add Balance Sheet and Profit & Loss adapters that populate titles, sections, totals, and the active report context from data already loaded by each page.
4. Document how parent rollups, leaf rows, zero/closed accounts, multi-currency values, and collapsed display groups map into exports.

## Acceptance criteria

- [x] One shared typed model represents both statements without renderer-specific fields.
- [x] Pure adapters preserve amount strings, hierarchy order, depth, currency, and intended display signs.
- [x] Tests cover nested parents, leaf accounts, zero amounts, missing primary currency, multi-currency amounts, and inverted signs.

## Out of scope

- New GraphQL fields, source-revision provenance, comparison periods, cash/accrual switching, or server-side aggregation.

## Completion

- Added a renderer-neutral `StatementExportDocument` model and adapters under `dashboard/src/features/reports/export/` for both statement kinds.
- Hierarchies flatten in server preorder with explicit depth and total/subtotal/account row kinds. Parent rows use the same `balanceChildren` rollups as the interactive list; collapsed groups remain complete in export because collapse is a disclosure preference, while zero/closed filtering is applied before adaptation.
- Exact amounts stay as strings. Profit-and-loss period totals use decimal-string/`BigInt` arithmetic instead of IEEE-754 aggregation.
- Focused tests cover nested and leaf rows, zero and missing-primary values, multiple currencies, closed-account visibility, stable ordering, and inverted display signs.

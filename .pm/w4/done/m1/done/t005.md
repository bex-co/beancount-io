## Objective

Make the export flow understandable in every dashboard locale, operable by keyboard and assistive technology, and measurable without collecting ledger or financial data.

## Context

- Report translations are feature-scoped under `dashboard/src/features/reports/**/locales/` and aggregated by the dashboard i18n layer.
- Analytics events are typed in `dashboard/src/common/analytics/events.ts`.
- Safe event dimensions are report kind, requested format, and success/failure category; ledger names, account names, filters, amounts, currencies tied to a user, and filenames are not safe payloads.

## Steps

1. Add concise export labels, descriptions, success messages, and failure messages to every supported dashboard locale.
2. Verify the trigger, menu items, printable document, and feedback states have descriptive accessible names, correct focus behavior, and no icon-only ambiguity.
3. Add typed started/completed/failed events with only report kind, format, and a bounded failure category.
4. Confirm each user action emits at most one completion or failure event.

## Files

- `dashboard/src/features/reports/export/locales/**`
- `dashboard/src/locales/index.ts`
- `dashboard/src/common/analytics/events.ts`

## Acceptance criteria

- [x] Translation-key parity passes for every supported dashboard locale.
- [x] The full menu and print flow are keyboard-operable with descriptive labels and sensible focus return.
- [x] Analytics distinguish statement kind, CSV versus print, success, and bounded failure category.
- [x] No event contains ledger identifiers, filenames, filters, account names, amounts, or other financial content.

## Out of scope

- Funnel dashboards, experimentation infrastructure, translated account names, or changing global number-format preferences.

## Completion

- Added complete export copy for all 15 dashboard locales and composed it through the existing report locale bundles; translation parity and interpolation tests pass.
- The trigger is labeled, Radix menu items retain keyboard/focus behavior, print markup uses semantic headings and table associations, and empty/busy actions are disabled.
- Added typed started/completed/failed analytics. Payloads contain only `report_type`, `format`, and the bounded failure category; analytics failures cannot interrupt exporting.
- Tests prove keyboard opening, exactly one terminal event, bounded failures, duplicate suppression, and absence of the fixture ledger name from event payloads.

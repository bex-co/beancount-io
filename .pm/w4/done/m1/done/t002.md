## Objective

Export the shared statement model as a stable, spreadsheet-safe CSV that opens correctly in Excel and remains useful for downstream analysis.

## Context

- `dashboard/src/features/bql/lib/export-utils.ts` already neutralizes formula prefixes and prepends a UTF-8 BOM.
- `dashboard/src/common/lib/utils/csv-export.ts` is less defensive; do not create a third divergent CSV implementation.
- Account names and filter labels are user-controlled text and must never be interpreted as spreadsheet formulas.
- No new spreadsheet or download dependency is needed.

## Steps

1. Extract or generalize the existing secure CSV field escaping and Blob-download behavior into a common format helper without regressing BQL exports.
2. Serialize statement rows with an explicit stable schema including statement, section, account path, depth, row kind, filter context, currency, amount, and conversion.
3. Generate sanitized deterministic filenames from ledger name, statement kind, time context, conversion, and export date.
4. Wire cleanup for temporary object URLs and define behavior for empty statements and download failures.

## Acceptance criteria

- [x] CSV output includes a UTF-8 BOM, stable headers, preserved amount strings, and one unambiguous currency per amount.
- [x] Values beginning with spreadsheet formula characters are neutralized while ordinary negative numbers remain numeric.
- [x] Quotes, commas, CR/LF, Unicode, nulls, long names, and unsafe filename characters have regression coverage.
- [x] BQL CSV export retains its existing behavior after helper consolidation.

## Out of scope

- Native XLSX/ODS files, formulas inside exported workbooks, ZIP packs, scheduled delivery, or server-side files.

## Completion

- Consolidated formula neutralization, quoting, UTF-8 BOM Blob creation, and object-URL cleanup in `dashboard/src/common/lib/export/csv.ts`; BQL and the legacy table helper now delegate to it.
- Added a stable statement schema with report context, primary and row currency, exact amount strings, and totals represented by explicit row kinds.
- Filenames are deterministic and sanitize control/path characters, dot traversal, repeated separators, length, and Windows device names.
- Regression tests cover formula prefixes versus signed numbers, BOM bytes, quote/comma/CR/LF/Unicode/null/object values, empty rows, unsafe filenames, cleanup on browser-click failure, and unchanged BQL output.

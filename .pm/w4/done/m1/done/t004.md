## Objective

Expose CSV and Print / Save as PDF from both core financial-statement pages and ensure each action uses the exact data and report context currently on screen.

## Context

- Integrate in `dashboard/src/features/reports/balance-sheet/` and `income-statement/`; do not create a top-level generic export feature.
- The pages already receive current GraphQL data, ledger identity, filters, conversion, interval, and visibility preferences.
- Export controls belong beside the existing report header actions and must work at mobile browser widths.
- Public and private ledgers should inherit existing report-read access; client-side export must not add a new permission path.

## Steps

1. Add a shared labeled Download menu with `Spreadsheet CSV` and `Print / Save as PDF` actions.
2. Build the appropriate statement model from each page's current filtered data and preferences.
3. Disable actions while usable data is unavailable, prevent duplicate activation, and surface success/failure feedback.
4. Verify the menu layout and action labels at narrow and wide dashboard widths.

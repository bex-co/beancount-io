## Cause and repair

`dashboard/src/features/importer/utils/csv-validator.ts:153–160` scans the cell but returns inside the first recognized-character iteration of `amountCurrencySymbol`. `lib/import-currency-conflicts.ts:28–29` checks only that result and skips the row if its currency set includes the selected currency. Separately, `splitAmountSign` at:183–198 strips both edge symbols, so normalizing the numeric amount loses the unchecked contradiction. `transaction-config-form.tsx:212–239` then prepares the single selected currency because the computed conflict list is empty. The original amount token is still available; this is not a failure to retain source evidence.

Check every recognized symbol's existing association against the chosen currency, and report every conflicting association using the existing selected-row alert/refusal path. Deduplicate repeated identical symbols/row numbers. Preserve `$`/`¥` ambiguity, shared `£`/`₩` association sets, matching repeats, excluded-row behavior, exact signs/normalization, inline edits and draft/pending locks. Do not guess between contradictory symbols, perform FX, add a dependency or introduce cross-package imports. No backend/API/parity change is required.

Acceptance: the EUR/GBP contradictory cases cannot prepare an import under either symbol order; the existing alert names the conflicting rows/symbols and native submission prepares zero requests. Single mismatches, matching repeats, ambiguous-dollar and shared-association controls remain compatible. Include meaningful parser/guard and rendered Configure regressions covering both orders and selected/excluded rows, repeat desktop/narrow, then run dashboard gates on implementation. No product change or formal test was authored during QA.

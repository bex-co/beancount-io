# Keep Account Journal selections when Time changes

**Severity:** minor follow-up to [142](./142.md)'s Account-state audit. **Estimate:** 45–60 minutes. **Owner:** dashboard. **A2:** entry-type filters must compose with the shared period instead of disappearing when that period changes.

## Reproduction and controls

Production `https://beancount.io`, 2026-10-22; owned isolated headless Chromium 155.0.8059.85, anonymous public `open_ledger/example`, English/light, fresh 1440×1000 and 390×844 Account contexts. Genuine successful reads; no response fixtures, artificial delay or hosted writes.

1. Open `/ledger/open_ledger/example/account/Assets%3AUS%3ABofA%3AChecking?time=2016`. In Account Journal turn **Metadata off**, **Postings on**, then select **Balance only** by enabling Balance and disabling Transaction.
2. The actual GetLedgerAccountJournal sends `directiveTypes:["Balance"]`, time 2016, this exact account, limit 20 and offset 0. HTTP 200 returns **15 balance entries**. Both display choices survive this ordinary inner query replacement: Metadata remains off and Postings on.
3. Change shared **Time** to **2016-11** and press Enter. At narrow width use Report filters → Time and close the sheet normally after the read. The successful new request now sends **directiveTypes:["Transaction"]** and returns **10 transactions**. Balance is off, Transaction on, Metadata on and Postings off: all three choices have reverted to defaults. Both fresh widths reproduce.
4. Independent control with the same account, November scope, conversion, child-account setting, limit and offset, retaining `directiveTypes:["Balance"]`, returns HTTP 200 with **one balance entry dated 2016-11-07**. The backend accepts the intended combination; the client discarded it.
5. Reselect Balance only. The real UI read returns that one balance. Restore Metadata off/Postings on: they work without another Account Journal request. A separate ordinary Journal desktop control retains both display choices through the same Time edit and a reload.

No accounting corruption is claimed. The reader selected balance assertions for the new period, but the client instead requests transactions because the selected type was reset. Metadata/Postings loss independently confirms the same owner was reinitialized. Default pagination was used throughout; nonzero-page behavior is not verified by these cases.

## Cause and bounded repair

`dashboard/src/features/reports/account/index.tsx:90–105` owns four filter sets and two display flags as local useState inside AccountJournalTable: directive types, transaction/document/custom subtypes, showMetadata and showPostings. At :187–208 those selected sets supply GetLedgerAccountJournal inputs, and :290–309 binds the same state to JournalFilters. The account page is the table's sole production owner.

The outer ledger layout replaces Outlet for a shared account/filter/time change, unmounting this owner. It therefore initializes Transaction, empty subtype sets, Metadata true and Postings false. Its own journal read only swaps the body below the controls, so ordinary local-filter reads correctly preserve display choices. [142](./142.md)'s audit declared Account Journal state clean by checking that inner boundary; the native shared-Time case demonstrates the remaining outer-boundary gap.

Keep those filter/display choices in an account/report-scoped home that survives a shared-scope pending replacement, using the repository's existing validated URL-state pattern where appropriate. Preserve the current initial defaults and account/ledger isolation; do not create global preferences, change the ordinary Journal's scoped storage, retain stale rows under a new period, or persist ephemeral dialogs/entry references. The subtype sets share the same traced lifetime and need regression coverage; only directive type and both display flags are independently failed here.

Retain the pagination contract: meaningful filters start at the first page, while explicit valid reload/Back positions remain supported. Preserve the selected chart view, with_children, account/filter intersection, exact read results, source actions, loading/error/retry states and JournalFilters' existing callbacks. No API, dependency or backend behavior change is needed.

Acceptance: with the real owner/router/query integration, select Balance-only and custom Metadata/Postings choices, edit Time, and assert the first new query retains Balance and the chosen flags survive. Cover each subtype set, empty matches, pending/rejected/successful reads, ordinary inner-filter changes, valid defaults/isolation and pagination requirements. Repeat desktop/narrow and preserve the working ordinary Journal control; run dashboard gates when implementing.

**Resolved 2026-10-22** — Account Journal's entry-type filters, subtype filters and Metadata/Postings toggles now live where the ordinary Journal keeps its own: in localStorage, through one shared `useJournalFilterState` hook with the Journal's validated deserializers. The Journal keeps its existing `journal.<ledger>` keys. Account Journal is scoped per ledger and account (`accountJournal.<ledger>.<account>`), and its table remounts per account. A shared Time, account or filter edit, which remounts the page, keeps them. Defaults, pagination, the account filter intersection and the Journal's behavior are unchanged. Regression `account-journal-choices.test.tsx`: Balance-only, every subtype set and both toggles survive a full page remount, and the first read after it asks for the chosen entries; a fresh account starts from the defaults. The remount case fails against the old code.

Local browser check at 1440×1000 and 390×844 (Filters sheet), on `Assets:US:BofA:Checking`, time 2016-08 → 2016-11: Balance only, Metadata off and Postings on all survived, and the first new GetLedgerAccountJournal sent `directiveTypes: ["Balance"]` with `time: "2016-11"`. The reads were answered from the store's real 2016-08 responses, since only the choices were under test. No mutations. Shipped in `7f454ac60` (`dashboard`).

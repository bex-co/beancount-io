# Retry a failed account-deletion source preview in place

**Severity:** minor error recovery. **Estimate:** 30–45 minutes, dashboard. **A2:** a transient source-preview failure should offer a retry in the selected confirmation, rather than require closing and finding the account again. Additional observer consumer of completed [m50](./done/m50/README.md)'s read-recovery pattern; count one residual, no new historical finding group.

Production `https://beancount.io`, 2026-10-24, owned isolated headless Chromium156.0.8078.47, English/light/UTC, QA owner on its designated disposable ledger. Fresh390×844 and1440×1000 contexts. Actual native account creation, persisted account/source reads and modal actions; no data responses are modeled. Only each first source-preview read is aborted before transport.

## Reproduce and controls

1. Snapshot the disposable ledger and check it has zero errors. Through Accounts → **Open Account**, create `Assets:Qa-20261025-ReadRecovery`. The real write succeeds once; a fresh account-directives read confirms it is open, has no balance and has **entryCount0**, so its Delete action is available.
2. Activate that row's **Actions** → **Delete**. Abort its automatic `GetLedgerEntryContext` read before transport.
3. The **Delete Account** dialog shows the correct account and the inline connection error. **Delete** is disabled. Its only buttons are **Cancel**, disabled **Delete**, and **Close**; there is no Try Again/Retry/Reload action. The narrow screenshot was visually inspected.
4. Restore normal transport while keeping the dialog open, then wait1.5seconds. The same error and disabled Delete remain; no new read occurs. This is not a demand for automatic retry: there is no explicit in-place recovery action either.
5. Cancel and open Delete on the same account again. A genuine HTTP200 source read succeeds, shows the correct own OPEN directive in the read-only editor, clears the error and enables Delete. Cancel without confirming deletion. Both widths repeat from fresh page loads.

Working controls: closing either the failed or healthy dialog correctly returns focus to that account's row action; the recovered editor exposes `aria-readonly=true`. The account creation persists and its zero-entry count is correct. No deletion is confirmed or attempted. Each retained context has one controlled failed read, one genuine healthy source read, zero mutations and zero unhandled page exceptions; the only console errors are the two expected aborted-resource messages.

## Cause and bounded repair

`dashboard/src/features/ledger-data/accounts/delete-account-dialog.tsx:54–79` owns separate network-only `GetLedgerEntryContext` queries for the opening and optional closing directives, but destructures neither `refetch`. At:85–88 `contextError` combines their errors; at:90–95 `canSubmit` correctly requires their checksums. The rendered failure at:174–178 is only Alert text, while the footer has Cancel/Delete. There is no retry callback or control. The page at `accounts/index.tsx` is this dialog's only production caller.

Use the existing scoped read-recovery pattern to retry the failed eligible context query without dismissing or changing the selected account. Keep the error until recovery settles, provide a busy action that refuses duplicate retries, retain useful retry focus after another failure, and enable deletion only when the current target's required checksums are available. For a closed account, preserve a healthy sibling preview and handle either opening- or closing-source failure correctly; that two-preview branch is source-derived scope, not a native reproduction here. Do not automatically delete after recovery or alter account eligibility, source checksums, permissions or backend behavior.

Acceptance: real DeleteAccountDialog/Apollo interactions cover cold failure → explicit retry → another failure → successful current-target preview, including each failed observer for a closed account. The selected account and read-only source stay correct, Delete remains disabled until the necessary fresh context is ready, and no deletion is sent by retry. Preserve Cancel/Close's passing row-focus controls and test another target opened during recovery. Repeat the native open-account case at both widths and run dashboard gates on implementation. Actual outages, closed-account native behavior, other engines and repaired code remain unverified.

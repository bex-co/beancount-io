# Describe the Commodities empty state as missing price history

Severity: minor misleading copy. Estimate: 35m, dashboard. A2: a public reader should understand why a ledger with currency holdings has an empty price-history page.

Production https://beancount.io, signed out, isolated headless Chromium149.0.7827.55, English/light. Repeated320×844 and1440×1000 reloads of `/ledger/open_ledger/synopsys/commodities?lang=en` show “No Commodities Found” and “No commodities are available in this ledger.” Desktop also promises to view and manage currencies/stocks/assets used in the ledger. Local/fetched main26d54a9db7d33c31a549bd12a0454a1c01f3f038; deployed main-BIr0jJni.js, exact deployed SHA unverified.

Control: the same public ledger's Holdings page has15 rows denominated in MUSD. A read-only combined GraphQL request returns HTTP200 with `getLedgerAttributes.currencies=["MUSD"]` and `getLedgerCommodities=[]`. Statistics reports zero Price directives. Thus the ledger contains currency-denominated holdings; it has no price pairs for this page to display. This is a wording defect, not a missing holding, failed request or empty-ledger condition.

Producer trace: backend-v2's `ledger-data-resolver.query.ts:234` delegates to ledger-data-service.getCommodities. The ledger service at `src/features/ledger/service/ledger-data-service.ts:285` calls `commodityPairsWithPrices`; `src/foundation/rustledger/directives-report.ts:213` documents the Fava-compatible price-pair contract and its loop accepts only Price directives. The dashboard intentionally renders charts/history for those pairs. Preserve this contract; do not expand the API into a commodity-declaration or holdings list.

Root: `dashboard/src/features/ledger-data/commodities/index.tsx:198–199` uses `page.commodities.noCommoditiesFound` and `page.commodities.noCommoditiesFoundDescription`, whose English values at locales/en.ts:15–21 wrongly describe the absence of all commodities. `dashboard/src/i18n/locales/common/en.ts:375–378` broadens the page description to viewing/managing all commodities used. These strings trace unchanged to af5339de. Both catalog families have15 locales; the repeated live reproduction is English only.

Repair the empty title/description to explain that no commodity/currency price history is available. Align the page description with viewing recorded price pairs and histories; do not promise management actions the page does not implement. Update the same keys and translator descriptions consistently across the15 locale catalogs. Keep the Commodities navigation name, existing results, read-only behavior, related links and error state. Do not tell users they must add a price merely to make an otherwise valid single-unit ledger work. No API, ledger-engine, dependency or calculation change is needed.

Acceptance: synopsys still returns an empty price list, but the page explains missing price history while its MUSD holdings remain available. A populated stock-example or crypto-example still shows its original pairs, chart points and disclosed tables; genuine read failures remain errors rather than empty states. Check localized wording and native dashboard gates. No assertion-only copy tests are needed solely to mirror the chosen sentence. Other locales' runtime, physical devices and patched behavior remain unverified.

**Resolved 2026-09-19** — Reproduced against a local build: the public synopsys
ledger's Commodities page showed "No Commodities Found" and "No commodities are
available in this ledger." at 1440px and 320px, above a page description
promising to "view and manage commodities (currencies, stocks, and assets)",
while its Holdings page lists fifteen MUSD rows. The ledger has
currency-denominated holdings; what it has none of is Price directives.

Three keys were rewritten across all fifteen catalogs, keeping their names and
updating their translator descriptions:
`page.commodities.noCommoditiesFound` now reads "No Price History Found",
`page.commodities.noCommoditiesFoundDescription` explains that the ledger
records no commodity prices so there is no exchange-rate history to show, and
`common.pageDescription.commodities` describes the recorded price pairs and
each one's exchange-rate history without promising management. The copy states
the fact rather than demanding a Price directive, because a single-unit ledger
with no prices is valid.

The price-pair contract is untouched — the backend resolver, the ledger
service's `commodityPairsWithPrices` and the rustledger Price-only loop are
unchanged, as are the navigation name, existing results, read-only behaviour,
related links and the error state.

Verified in a real browser, 8/8: synopsys explains the missing price history at
1440px and 320px while its Holdings still lists fifteen rows; crypto-example
still renders its six pairs, six charts and six history disclosures; French,
Japanese and Russian render their own wording; and an aborted
`GetLedgerCommodities` read still shows "Failed to Load Commodities" rather
than the empty state. Gates from `dashboard/`: `yarn format:check`,
`yarn lint`, `yarn test` (395 files, 4436 passed, 1 pre-existing skip) and
`yarn build` all pass. Per this note, no copy-mirroring test was added.

("Loading events..."), one of the corruptions `w4/m14` is auditing. It now
carries a correct Catalan sentence for this key; the wider Catalan audit is
unaffected. Other locales' runtime and physical devices remain unverified.

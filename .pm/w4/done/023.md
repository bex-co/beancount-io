# Deleting a `---` line renders as unchanged in the native commit diff

**Severity:** minor. **Estimate:** 20–30 minutes. Owner: mobile. A3: the commit diff is how someone judges what actually changed in a public ledger, and here it silently shows a deletion as an untouched line.

Environment: branch `main`, HEAD `038faeeb`, native development build `io.beancount.ios` on iPhone 17e / iOS 26.5, authenticated production session at `https://beancount.io`, ledger `open_ledger/alphabet`. Report-only QA; no ledger mutation. The misclassification below is demonstrated against real `git diff` output in a throwaway local repo, not by writing to any ledger.

## Repro

The classifier is a pure exported function, so it reproduces exactly without a ledger write. In a scratch git repo, delete a Markdown horizontal rule / front-matter delimiter:

```
NOTES.md:  "title\n---\nbody\n"  →  "title\nbody\n"
```

`git diff` emits the deletion line `----` (the `-` prefix plus the `---` content). Feeding the real diff through `classifyDiffLine` from `src/screens/commit-detail-screen/diff-utils.ts`:

```
context  "@@ -1,3 +1,2 @@"
context  " title"
context  "----"        ← the deleted line, classified as unchanged
context  " body"
```

The symmetric case fails too: adding a line whose text begins with `++` emits `+++note`, which classifies as `context` rather than `added`.

**Expected:** `----` is a removal (red) and `+++note` is an addition (green).
**Actual:** both render with the neutral context background, indistinguishable from a line that did not change.

**Working control:** ordinary lines classify correctly — `+added line` → added, `-removed line` → removed, `--- a/NOTES.md` and `+++ b/NOTES.md` headers → context. Verified natively on commit `7c6545b` (`Add README.md`) on `open_ledger/alphabet`, whose additions render green and whose `+++ b/README.md` header correctly does not.

## Root cause

`src/screens/commit-detail-screen/diff-utils.ts:8-16` distinguishes a content line from a file header by prefix alone:

```ts
if (line.startsWith("+") && !line.startsWith("+++")) return { type: "added", content: line };
if (line.startsWith("-") && !line.startsWith("---")) return { type: "removed", content: line };
return { type: "context", content: line };
```

In a unified diff the prefix character is stripped from the payload, so a removed line whose content is `---` *is* `----`, and an added line whose content is `++note` *is* `+++note`. The `!startsWith("+++")` / `!startsWith("---")` guards cannot tell those apart from the `--- a/file` / `+++ b/file` headers, because by prefix they are identical. The guards are a heuristic standing in for position.

`parseDiff` (line 18) maps the classifier over the lines with no state, so nothing else can recover the distinction.

## Fix

Classify by position instead of by prefix. Header lines only ever appear before a hunk opens, so tracking whether the parser is inside a hunk removes the ambiguity entirely and lets the `+++`/`---` special cases go away:

```ts
export function parseDiff(diff: string): DiffLine[] {
  let inHunk = false;
  return diff.split("\n").map((line) => {
    if (line.startsWith("diff --git")) inHunk = false;
    else if (line.startsWith("@@")) inHunk = true;
    else if (inHunk) {
      if (line.startsWith("+")) return { type: "added" as const, content: line };
      if (line.startsWith("-")) return { type: "removed" as const, content: line };
    }
    return { type: "context" as const, content: line };
  });
}
```

Resetting on `diff --git` keeps a multi-file diff correct, so the `--- a/…` / `+++ b/…` pair of the *second* file is not read as content of the first file's last hunk. Keep `\ No newline at end of file` as context — it already falls through.

`classifyDiffLine` is exported and unit-tested, so decide deliberately whether it stays: a single line cannot be classified correctly without hunk context, so either keep it for the header cases and mark the limitation, or fold it into `parseDiff` and move its tests across. Do not leave a correct `parseDiff` beside a stateless `classifyDiffLine` that still gets these wrong.

**Acceptance:** a diff that deletes a `---` line renders that line with the removed (red) styling, and one that adds a `++`-prefixed line renders it added (green), while `--- a/file` and `+++ b/file` headers stay neutral in both single-file and multi-file diffs.

Extend `src/__tests__/notifications-m14.test.ts`, which already pins the header behaviour with `classifyDiffLine: +++ header line is context (not added)` and its `---` twin but has **no case where a content line collides with a header prefix** — that gap is why this survived. Add the two collision cases and a two-file diff.

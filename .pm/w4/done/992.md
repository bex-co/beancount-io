# Keep keyboard focus on Refresh prices while it refreshes

**Severity:** minor accessibility. **Estimate:** 30–40 minutes. **Owner:** dashboard. **A2:** a keyboard reader who refreshes managed prices should stay on the card's action and hear the outcome, not be sent back to the top of the page.

## Reproduction

Found during the native check for [332](./332.md), 2026-10-22: built dashboard against the local fixture API with a synthetic owner, Commodities reached by client-side navigation, one managed source answered in the browser, every `RefreshLedgerManagedPrices` answered or aborted before transport. No hosted reads or writes.

1. Focus **Refresh prices** and press Enter, at both 1440×1000 and 390×844.
2. While the refresh is in flight the button is `disabled` and the browser drops its focus: `document.activeElement` is `<body>` when the refresh settles.
3. This holds on every outcome: an acknowledged refresh, an acknowledged refresh whose chart read fails (the card's new alert does get announced), and a refresh that fails before acknowledgement (the "Could not refresh prices" toast). The next Tab starts from the top of the document.

Controls: the card's **Reload charts** (332) already keeps focus. It holds one read through `usePendingAction`, hands focus back when the read fails, and moves it to Refresh prices when the read lands.

## Cause and bounded repair

`dashboard/src/features/ledger-data/commodities/managed-price-sources.tsx` disables the focused button on `refreshing` and never restores focus. This predates 332: the same `disabled={refreshing}` was in `4678079a1`.

Keep focus on the action across the refresh, with one refresh at a time. One way is to start it through `usePendingAction` and return focus to Refresh prices once it settles, whatever the outcome; the button stays mounted, so unlike a dialog, a landed refresh has nowhere else to put focus. Preserve 332's separate acknowledgement and chart-read handling, the pre-acknowledgement toast, reader permissions and the busy label. No dependency, API or translation change.

Acceptance: a real-Apollo component test shows focus on Refresh prices after a keyboard refresh lands, after one that fails before acknowledgement, and after one whose chart read fails. A second Enter during the refresh sends nothing. Repeat the desktop and narrow native checks and run the dashboard gates.

---

**Resolved 2026-10-22** — Refresh prices now runs through `usePendingAction`: one refresh at a time, busy for its whole length including the chart read, with focus parked on the page region meanwhile. Because the button stays on the card, focus returns to it however the refresh ends. 332's separate acknowledgement and chart read, the pre-acknowledgement toast, the busy label and reader permissions are unchanged. A new real-Apollo test in `commodities-managed-refresh.test.tsx` holds each outcome: landed, failed before acknowledgement, and landed with a failed chart read. Each returns focus to Refresh prices and ignores a second Enter, and each fails against the old code.

Local browser check of all three outcomes at 1440×1000 and 390×844, with each refresh delayed 800 ms: a second Enter mid-refresh sent nothing (one refresh per case), and focus ended on Refresh prices. The alert and toast appeared as before. Shipped in `95dd7e744` (`dashboard`).

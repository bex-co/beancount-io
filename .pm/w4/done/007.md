# Collapse the empty description line in Browse ledgers rows

**Severity:** minor. **Estimate:** 20–30 minutes. Owner: mobile. A3: Explore is the app's public catalog of open ledgers, and almost every row in it currently renders with a blank gap in the middle.

Environment: branch `main`, HEAD `038faeeb`, native development build `io.beancount.ios` on iPhone 17e / iOS 26.5, English / System / light / default text size, authenticated production session at `https://beancount.io`, selected ledger `open_ledger/alphabet`. Report-only QA; no ledger mutation, and no star was added or removed.

## Repro

1. Terminate and relaunch the app. Ledger drawer (hamburger) → **Browse ledgers** → **Explore** tab.
2. `open_ledger/adobe`, `open_ledger/adyen`, `open_ledger/airbnb`, `open_ledger/amazon` and `open_ledger/amd` each render their name, then an **empty line**, then `Public`. The star sits alone in the gap.
3. `open_ledger/alphabet`, the one row in view that has a description, renders name → `Alphabet Inc. Financial Statements` → `Public · Current` with no gap.
4. **Your ledgers** tab: `puncsky/example` has the same gap between its name and `Private`; `open_ledger/minimax` has a description and does not.
5. Relaunch and repeat. The gap reproduces.

**Expected:** a row with no description is as tall as its content — name directly above the visibility line, like the described rows.
**Actual:** every description-less row reserves a full line of empty text, so the visibility label is pushed down and the row reads as if something failed to load.

## Root cause

`mobile/src/screens/ledger-selection/index.tsx` renders the description `<Text numberOfLines={1} style={styles.muted}>{item.description ?? ""}</Text>` unconditionally inside the row's content `Pressable`. React Native still lays out a `Text` whose content is the empty string, so it claims a full `styles.muted` line box plus its spacing. Introduced with the screen in `221f5a4e` ("feat(mobile): add ledger discovery and synced stars"); nothing since has touched it.

## Fix

Render the description element only when `item.description` is a non-empty string after trimming — `{item.description?.trim() ? <Text …>{item.description}</Text> : null}` — so the row height follows its content. Keep `numberOfLines={1}`, the `muted` style, and the visibility/current line exactly as they are. If a uniform row height is wanted for list stability, that is a deliberate different fix: set an explicit `minHeight` on `styles.content` and say so in a comment, because today's behavior is neither — it is a stable height only by accident of an empty `Text`.

**Acceptance:** on a fresh iPhone 17e launch, Explore shows `open_ledger/adobe` with `Public` directly under its name, while `open_ledger/alphabet` still shows its description and `Public · Current`; the same holds on Your ledgers for `puncsky/example` and `open_ledger/minimax`. Add regression coverage that a row without a description renders no description node and one with a description renders it, including a whitespace-only description.

## Blast radius

`styles.muted` is used by both the description line and the visibility line in this same row; scoping the change to the conditional render leaves the visibility line untouched. The row is shared by all three tabs — Your ledgers, Starred, Explore — and the gap was observed on Your ledgers and Explore. Not independently reproduced: the Starred tab (empty for this account), search-filtered results, dark mode, and enlarged Dynamic Type, where the reserved line costs proportionally more height.

## Adjacent states

The empty `Text` contributes nothing to VoiceOver, and the row's own `accessibilityLabel` (`discoveryOpen`) already names the ledger, so this is visual only. Loading, refreshing and the star's pending/dim state are unaffected.

## Dedupe

Searched all `.pm/**/*.md` including `done/` for discovery/explore rows, blank or empty description, and row layout. `w4/done/m4` ("Mobile ledger discovery and starred ledgers") shipped this screen but no task covers row height or the description slot. `w3/214.md` is the code editor's keyboard offset — unrelated. `git log -S 'item.description ?? ""' -- mobile/` returns only the screen's introducing commit, so there is no fix on `main` and this is not deployment lag.

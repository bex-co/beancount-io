# Protect Entry Context drafts during history navigation

**Severity:** minor, remaining caller-exit gap from [w3/565](../w3/done/565.md). **Estimate:** 45–60 minutes, dashboard. **A2:** correcting an entry should offer the same Keep editing / Discard decision when browser history leaves its page as when Close leaves its dialog.

Production `https://beancount.io`, 2026-10-24, owned isolated headless Chromium 156.0.8078.47, English/light/UTC, independent authenticated QA-owner contexts at 1440×1000 and 390×844. Ordinary source-backed transaction in the designated disposable ledger; genuine reads, unsaved local typing only. No Save/Delete, hosted writes, mutation attempts, modeled responses, page exceptions or route errors.

## Reproduce and working controls

1. Open `/ledger/<owner>/<ledger>/accounts?lang=en`, then activate the actual **Journal** navigation link. At 390px, first open **Toggle Sidebar**. This is one same-document SPA history transition; `performance.timeOrigin` is unchanged.
2. Activate the first transaction's named **Open entry …** date button. Wait for **Editor content**, `aria-readonly=false`, and the genuine entry-context read. Append a local comment such as `; qa-20261024-entry-history-local-draft` at the end using the editor's native keyboard input.
3. The exact marker is rendered, **Source has been modified** appears, and Save is enabled. Click Close: **Discard your edit?** correctly appears. Choose **Keep editing**: the exact rendered draft is retained and Save remains enabled.
4. Traverse history Back with Playwright `page.goBack()`. Accounts opens immediately in the same document, with no discard decision or native dialog. Entry Context and its draft disappear.
5. Forward returns to Journal. Reopen the same entry: the marker is gone and Save is disabled. A separate read-only entry-context request returns HTTP200 with the byte-identical original source and checksum. Stored ledger data was never changed.

Both widths independently reproduce the complete sequence. A clean dialog can close and Back reaches Accounts normally. This proves automated browser-history traversal; physical browser-toolbar activation and unload/reload behavior remain unverified.

Separate fresh standalone-entry controls at both widths pass: type a local source comment, activate **Back to journal**, receive the discard decision, choose Keep editing and retain the exact draft with enabled Save, then explicitly Discard to reach Journal. Independent stored-source/checksum readbacks remain unchanged there too.

## Cause and bounded repair

`dashboard/src/features/journal/components/entry-context-dialog.tsx:167–190` owns `dirty`, `writing` and `requestLeave`, but the gate only receives Radix `onOpenChange` and the panel's source-file action. It has no router/history blocker. Journal owns the dialog's open/entry state (`pages/journal-page.tsx:153,396–406`); leaving the route unmounts that owner without invoking the dialog's gate. The other source-traced callers are `features/reports/account/index.tsx` and `features/reports/overview/components/recent-activity-card.tsx`; those journeys were not reproduced live here.

The standalone `features/journal/pages/entry-page.tsx:40–56` already consumes panel dirtiness with `useBlocker`, a resolver, and the existing unload policy. Extend the dialog's active draft protection to router exits through the existing local discard choices. Keep editing must cancel the pending navigation and retain the actual editor text; Discard must complete exactly the requested history transition. Coordinate this with Close/source exits so only one decision opens and navigation does not restore focus to an obsolete route opener. Preserve clean/read-only exits, permissions, source destinations, the existing pending-write lock and successful-write ownership. Reuse the repository's blocker pattern; no persistent draft storage, global navigation manager, dependency or API change is needed.

Acceptance: real router + dialog integration covers Accounts → Journal → dirty Entry Context → Back, Keep editing preserving text/history, and Discard reaching Accounts. Include clean/read-only controls, local Close/source decisions and the standalone page control; cover Account/Overview owners through the shared dialog. Repeat native keyboard/history checks at both widths and run dashboard gates on implementation. Pending save/delete and physical-toolbar/unload behavior were not exercised in this report.

Two separate fresh shortcut contexts perform three successive immediate edits/runs each: all **six** submit the current model. Two separate native-pointer contexts perform the same three edits/runs each: all **six** submit the current model. The first two button trials in each failing context also pass. ## Cause and bounded repair

`dashboard/src/features/bql/pages/index.tsx:213–215` makes the toolbar call `submitQuery(queryText)`, using React state. The editor at:245–246 updates that state through onChange, but at this handoff its live model is already newer than the submitted value. The registered shortcut at:251–257 already calls **editor.getValue()**, updates state and passes that current text to the same submission path. The retained controls demonstrate that path works.

Have toolbar activation read the current mounted BQL editor model through a page-owned reference, using the existing shared submit path as the shortcut does. Handle editor readiness/teardown and ledger changes coherently, without retaining a disposed editor. Preserve trimming, empty-query handling, current-model history/URL ownership, request deduplication, real fresh reruns, errors, exports, and deliberate bookmark restoration. No timer, debounce, delayed-button workaround, dependency or global Monaco-wrapper rewrite is needed.

Acceptance: a meaningful mounted-editor/real-request regression makes the live model newer than its last React value and invokes the actual toolbar handler; it must send the live text, update the bookmark/history correctly and fail against the old state-only handler. Repeat successive committed edits and keyboard toolbar activation at both widths, plus the recorded shortcut/pointer controls, ordinary readiness, empty/invalid queries and unmount/ledger compatibility. Preserve [989](./989.md)'s separate draft-restoration requirements. Run dashboard gates when implementing. No product implementation or formal test was authored during QA; preedit/IME behavior is unverified.

## Objective

Associate each budget history with its account and currency identity and each commodity history with its base/quote pair, using the owning components and existing Table props.

## Context

See [FINDINGS.md](./FINDINGS.md) for reproductions, source, controls and evidence limits.

## Acceptance criteria

- [x] Two currencies for one budget account and two same-quote commodity pairs have distinct meaningful table names.
- [ ] Preserve grouping by account plus currency, interval history, row precision, disclosure state, keyboard operation and read-only action gates.

## Out of scope

API/data changes, global Table defaults, new dependencies, unrelated control labels and a broad accessibility redesign.

## Outcome

Reproduced first on the built code, at 1440x1000 and 390x844, by reading
Chromium's own accessibility tree over CDP rather than inferring from the DOM:
seven budget history tables and three commodity price-history tables, **every
one with an empty accessible name**, no caption, no `aria-label`, no
`aria-labelledby`.

Both now follow the naming idiom w3/m32 already established for the statement
hierarchy tables (`ariaLabelledBy` passed from the card that owns the visible
title), rather than inventing a second convention:

- **Budget** — `budget-chart-card.tsx` mints two ids with `useId` and puts them
  on the nodes that already carry the identity: the account `CardTitle` and the
  currency `Badge`. `BudgetHistoryTable` takes them as `ariaLabelledBy`. The
  currency is part of the name deliberately, because `groupBudgetEntries` keys a
  group by account *and* currency, so one account can appear more than once; the
  interval is deliberately left out, because interval changes are entries
  *within* one history, not separate ones.
- **Commodities** — the table takes `aria-label={pairLabel}`, the same
  `${base}/${quote}` string the card title renders. The pair label already
  existed in the component, and the existing `tableId` could not be reused: it
  names the disclosure's target region, not the table. The named disclosure
  button and its `aria-controls` are untouched.

After the change, 14/14 live checks at both widths:

- all seven budget tables named, all distinct — `Expenses:Dining USD`,
  `Expenses:Groceries USD`, `Expenses:Insurance:Car USD`, `Expenses:Rent USD`,
  `Expenses:Transport USD`, `Expenses:Travel USD`, `Expenses:Utilities USD`;
- all three commodity tables named and distinct — `ACME/USD`, `BMKT/USD`,
  `NWRB/USD`, so the base commodity is now part of the identity;
- every `aria-labelledby` idref resolves to exactly one element and the page
  has no duplicate ids at all;
- rows are unchanged — 1 per budget history on this fixture, 13/13/15 for the
  commodities, matching what FINDINGS recorded.

Gates from `dashboard/`: `yarn format:check`, `yarn lint`, `yarn test` (378
files, 4264 passed, 1 pre-existing skip) and `yarn build` all pass.

No screen-reader speech is claimed: this is native accessibility-tree metadata
and DOM association, the same boundary FINDINGS drew.

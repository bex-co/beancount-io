## Objective

Add rendered regression coverage for the seven table authoring sites and interactions that change their data identity; run the dashboard native gates.

## Context

See [FINDINGS.md](./FINDINGS.md) for reproductions, source, controls and evidence limits.

## Acceptance criteria

- [x] Tests query tables by meaningful accessible names and fail against the current unnamed markup.
- [x] Cover budget account/currency collisions and filters, commodity close/reopen and precise values, and Statistics state changes without losing names or duplicating IDs.
- [x] Cover distinct Settings option-table names and preserve public read-only permission gates.
- [x] Dashboard format:check, lint, test and build pass; public replay evidence is recorded.

## Out of scope

API/data changes, global Table defaults, new dependencies, unrelated control labels and a broad accessibility redesign.

## Outcome

Before this task nothing in `features/ledger-data/` asserted an accessible table
name — the contract lived in comments and `AGENTS.md` and was enforced nowhere.
Added 14 rendered cases that query through
`getByRole("table", { name })`, which resolves the real accessible name
(caption, `aria-label`, `aria-labelledby`) rather than looking for text on the
page, so they fail against the bare `<table>` markup rather than passing on a
heading that merely sits nearby.

New `ledger-data/__tests__/table-accessible-names.test.tsx` (8 cases):

- **the account/currency collision** — `groupBudgetEntries` splits one account
  billed in USD and EUR into two groups, and the two tables come back as
  `Expenses:Travel USD` and `Expenses:Travel EUR`; the account alone would name
  them identically;
- **id uniqueness** — with both cards mounted, every `id` in the tree is unique
  and each table's `aria-labelledby` idref resolves to exactly one element;
- **interval changes stay inside one history** — a monthly entry followed by a
  quarterly one is still a single group, and its named table holds both rows;
- **two same-quote commodity histories** name themselves `ACME/USD` and
  `BMKT/USD` by their own base;
- **close and reopen** restores both the name and `0.0225` intact, keeping the
  existing small-value precision control;
- **keyboard** — tab to the disclosure, press Enter, same name;
- **Settings** — `Beancount Options` and `Fava Options` are distinct, and
  neither section renders an input, textarea or select, so the public read-only
  gate is asserted alongside the name.

Extended the three existing Statistics suites (6 cases) rather than duplicating
their Apollo and router mocks: each asserts its name **in both states**, since
the settled branch and the skeleton branch render their own heading-and-table
pair, plus the idref check on the settled one.

Proved load-bearing by stripping every association back to a bare `<Table>`:
**12 tests across 4 files fail**, and restoring them passes 279/279 in
`features/ledger-data`.

Gates from `dashboard/`: `yarn format:check`, `yarn lint`, `yarn test` (379
files, 4278 passed, 1 pre-existing skip) and `yarn build` all pass. `gitleaks`
reports no leaks in `dashboard/src`. Public replay evidence is recorded in t003
and re-run in t006.

One process note worth keeping: the revert check was run with
`git checkout -- src/features/ledger-data/statistics/`, which also reverted the
new tests inside that directory, since `__tests__` lives under it. They were
re-applied and re-verified; nothing was lost, but the shortcut is worth not
repeating.

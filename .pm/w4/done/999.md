# Strengthen the read-retry regressions shipped with M50

**Severity:** minor test quality. **Estimate:** 40–50 minutes. **Owner:** dashboard. **A2:** the in-place retry contract from [M50](./m50/README.md), since reused by [337](./337.md) and [338](./338.md), should be pinned by tests that fail when it breaks.

## Findings

These come from the M50 Simplify review. The review ran on the pre-ship diff and reported after the milestone closed; each point below was re-checked against current `main`. The review's crash blocker was already fixed before shipping: `report-read-retry.test.tsx` supplies minimal page shapes, and both suites exit 0 with no unhandled errors.

- `dashboard/src/features/reports/__tests__/report-read-retry.test.tsx` ends each page's case by asserting that Try Again is gone. Asserting each page's own success content (a row, total or heading) would show that the retried read actually rendered, rather than relying on the run failing on a crash.
- In the same test, the second Enter after `toBeDisabled()` followed by `expect(reads).toHaveLength(2)` cannot fail on its own: user-event never activates a disabled button. `toBeDisabled()` is the assertion; drop the pair. The focus-handback wait only exercises Account, the only page with a `[tabindex]` ancestor that parks focus. Keep it as Account's handback check and say so.
- No test checks that the classified error message stays visible while a retry is pending. That is the only reason `useQueryRetry` keeps `retried`, and replacing it with a bare `new Error()` passes every suite. Assert the message text during the held retry, as the Holdings and Statistics regressions do for their own guidance.
- `commodities-read-retry.test.tsx` has a focus wait that cannot fail (jsdom keeps focus on a disabled button with no parking region), a Try Again absence check implied by the line above it, and `expect(await findBy…).toBeInTheDocument()` wrappers around queries that already throw.

## Optional simplifications

These are behavior-preserving and can be skipped.

- `common/hooks/use-query-retry.ts` syncs `retried` during render. Setting it in `retry()` would behave the same, because Try Again only exists while `failure === error`, and it removes a re-render per new error.
- The hook could return `ReportErrorState`-shaped props (`{ error, onRetry, retrying }`) so callers spread one object. If done, update the example in `features/reports/AGENTS.md`.
- `state-components.tsx`: the `retrying = false` default is redundant with Button's own default.

Acceptance: each strengthened assertion fails against a deliberately broken copy of the hook or page, for example a missing `retried`, success content not rendered, or focus handback removed. Gates stay green. No product behavior change.

---

**Resolved 2026-10-22** — `report-read-retry.test.tsx` and `commodities-read-retry.test.tsx` now assert the retry contract directly:
- **Success content.** Each page shows its own success content after the retry ("No … data found", "No journal entries found", "No Price History Found"), not just Try Again gone.
- **Reason while pending.** The failure's reason stays visible during a held retry: the classified "Connection problem", or Account Journal's own message.
- **Focus handback.** Focus is dropped for real (jsdom keeps it on a disabled button), so the handback check can now fail on every page, not just Account.

The second-Enter-on-a-disabled-button checks and the redundant `findBy…toBeInTheDocument()` wrappers are gone.

Mutation-checked: dropping `retried` from `useQueryRetry`, or making every retry count as landed (no handback), fails all six cases.

The optional hook simplifications (setting `retried` in `retry()`, spreadable props, the redundant `retrying` default) were skipped as the note allows. Test-only change, no product behavior change; format, lint and tests pass. Shipped in `387864139` (`dashboard`).

# Use one current valuation date throughout Holdings queries

**Severity:** major. **Estimate:** 60 minutes, confined to four generated query templates and verification. **Owner:** dashboard. **A2/A3:** displayed prices, market values and gains must reconcile before a reader exports a portfolio.

Production `https://beancount.io`, signed out, English/light, isolated headless Chromium149.0.7827.55. Local HEAD26d54a9d, fetched main bd5d1d31, main-BIr0jJni.js; exact deployed SHA unknown. Observed September17 local / September18 UTC2026.

Open `/ledger/open_ledger/stock-example/holdings?view=by-currency&lang=en` at390×844. Reload, then fresh-load at1440×1000. Holdings by Currency and its actual Export CSV contain:

These are fictional securities in the public example. The GraphQL QueryShell HTTP200 returns these exact decimal strings; CSV faithfully exports them. This is not a renderer or floating-point arithmetic error. NWRB even shows a5.74% gain where the displayed current quote implies a13.40% loss against3971 USD book value.

GetLedgerCommodities shows the displayed prices dated2026-07-01. Market values instead use future2027-01-01 quotes97.10/110.75/11.05. A separate real read `SELECT getprice('ACME','USD'), getprice('ACME','USD',2026-09-17), getprice('ACME','USD',2027-01-01) LIMIT 1` returns90.80/90.80/97.10. Both functions individually have supported semantics, but the generated dashboard query combines their different defaults in one current portfolio row.

Root: `dashboard/src/features/ledger-data/holdings/holdings-statement.ts:1–46` uses undated GETPRICE for the price column and undated VALUE for market_value and the percentage numerator. The pinned upstream0.24.0 executor initializes query_date from today and GETPRICE uses it when no date is supplied; VALUE instead passes an absent date through to latest-price conversion. See [pinned executor](https://github.com/rustledger/rustledger/blob/v0.24.0/crates/rustledger-query/src/executor/mod.rs#L1195), especially1195–1230 and1411–1447. Installed-WASM behavior independently confirms this distinction.

Offline original fixture: two TEST shares bought at10 USD, a2020 price20 USD and a2099 price30 USD, with **no sale or reduction**. Installed0.24.0 returns price20 alongside undated market value60 USD. Explicit VALUE(..., today()) returns40 USD, with price20. This separates the cause from blocked w3/113's lot-reduction price inference. No upstream source or WASM bytes were copied into the repo; the ignored probe uses the existing installed package.

Verified repair direction: in the application's own four Holdings templates, explicitly use the engine's today() valuation date for GETPRICE and **every** VALUE call, including both aggregate market_value and per-position gain calculations. This retains the existing current-price column's cutoff and makes values/gains use that same cutoff. It changes neither source holdings/quantities nor historical cost, and does not impose a new date parser, filter, valuation engine or user-facing control. Do not rewrite arbitrary BQL, compensate returned totals in the browser, alter generic API function defaults, fabricate Price directives, or change the independently blocked price-inference policy.

The defect reproduced live at 390px on the by-currency view before any change (150 ACME units×price 13620.0000 against market 14565; 201.25 BMKT 21423.0625 against 22288.4375; 380 NWRB 3439.0000 against 4199), and all three reconcile exactly afterwards. Acceptance ran all four queries against the real engine, 11/11: every view conserves the same dated total (66777.4125 USD for holdings, by-account, by-currency and by-cost-currency), matching this note's predicted figure; the CSV download agrees with the rendered table; and the crypto-example control, which has no future-price conflict, returns byte-identical data before and after. Quantities, cost, acquisition dates, ordering and keyboard links are untouched, and no date parser, filter, valuation engine, user-facing control or new dependency was added — the engine is still not a dashboard dependency. `__tests__/holdings-statement.test.ts` updates the four existing template assertions to the dated strings and adds a guard that scans each statement with balanced-parenthesis matching, failing on any undated `value()` or `getprice()` call, plus an explicit check that both the aggregate market value and the gain numerator carry `today()`. That guard is a rule pin, not a proof of valuation — the numbers were verified against the engine; what the test prevents is a future edit reintroducing an undated call in one template.

## Objective

Wire correct DOM/read-only behavior for Entry Context and the source-derived account-deletion previews; review all existing Monaco consumers.

See [FINDINGS.md](./FINDINGS.md) for evidence, source and limits.

## Acceptance criteria

- [x] Entry Context readOnly=!canWrite is reflected in native AX in both input modes; ordinary typed text remains rejected for readers.
- [x] BQL, create-file and authorized entry/source editing stay editable; preview verification uses local fixtures without deleting production data.

## Outcome

Reviewed all five Monaco consumers. Three passed `readOnly` without
`domReadOnly` — `journal/components/entry-context-panel.tsx` and both deletion
previews in `ledger-data/accounts/delete-account-dialog.tsx` — so Monaco never
put the native `readonly` attribute on their textarea. `text-editor.tsx` had
always set both; BQL and create-file are editable and set neither.

Rather than add the option at three call sites, the shared wrapper now defaults
`domReadOnly` to `readOnly` whenever a consumer sets one and not the other. The
next Monaco consumer cannot forget it, and a caller that genuinely wants one
without the other can still say so explicitly. That is the same altitude as
t001's `aria-readonly` fix, and it is what FINDINGS asked for — it warned that
repairing only the file-viewer call site "would leave this Entry Context case
broken".

Entry Context verified live on the public example journal (2016, offset 60,
the RiverBank Properties entry at `main.bean:595`), in both supported input
modes at 1440x1000 and 390x844 — **8/8**:

| Mode | Before | After |
| --- | --- | --- |
| native EditContext | AX `readonly=false`, no `aria-readonly` | **`readonly=true`** |
| textarea fallback | AX `readonly=false`, no native `readonly` | **`readonly=true`**, native `readonly` present |

The fallback case is the one the previous state got wrong even before this
milestone: the source viewer's fallback was already correct, Entry Context's
was not, and FINDINGS traced that to exactly this missing option.

Typing stays rejected everywhere: every Monaco model on the page is compared in
full before and after pressing `x`, and all are byte-identical.

Editable surfaces are unaffected — 20/20 across the whole suite. The public BQL
editor still reports `readonly=false`, carries `aria-readonly="false"` and
accepts a typed character at both widths.

The two deletion previews are covered by the same wrapper default. They sit
behind a writer-only dialog, so they are verified by source and by the shared
behaviour rather than by a production reproduction — no account was deleted and
no fixture data was mutated, which is what this task's own criterion asks.

Gates from `dashboard/`: `yarn format:check`, `yarn lint`, `yarn test` (383
files, 4319 passed, 1 pre-existing skip) and `yarn build` all pass.

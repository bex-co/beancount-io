## Outcome

Re-ran every check against a fresh production build of the shipped code:
**29/29** — 20 read-only state checks and 9 reader-affordance checks.

Definition of done, clause by clause:

- **Native accessibility reports `readonly=true`** for anonymous file source
  *and* journal Entry Context, in **both** the native EditContext and textarea
  fallback modes, at 1440x1000 and 390x844. Before this milestone the
  EditContext surface reported `false` for both consumers, and Entry Context's
  textarea fallback reported `false` as well.
- **Editing remains rejected.** The complete Monaco model is byte-identical
  after a typed `x` in every mode and width — 318,015 characters for the source
  viewer, and every model on the Entry Context page.
- **Writer and view-mode behaviour preserved.** The public BQL editor still
  reports `readonly=false`, carries `aria-readonly="false"` and accepts typing;
  a reader→writer→reader transition is covered by the committed cases.
  Selection, Find (`2017-09-07` → "1 of 1"), Escape returning focus to
  `Editor content`, line navigation to `main.bean:595` and Back retaining
  `offset=60` all pass, and `aria-readonly` is still correct after all that
  interaction.
- **No browser API is globally removed.** The textarea fallback is reached only
  by deleting `window.EditContext` inside a separately labelled diagnostic
  browser context. Product code disables nothing, adds no dependency, and
  changes no permission — the repair is one ARIA attribute and one defaulted
  Monaco option, in the shared wrapper all five consumers already used.
- **Meaningful checks and gates pass.** 12 committed cases against a
  Monaco-shaped double, both halves proved load-bearing by removal (7 and 2
  failures), plus `yarn format:check`, `yarn lint`, `yarn test` (384 files,
  4331 passed, 1 pre-existing skip) and `yarn build`.

Unexercised assistive technologies, recorded as the definition of done
requires:

- **No screen reader was run.** Every result is Chromium's native accessibility
  tree and DOM attributes. No speech, no shortcut behaviour, no NVDA/JAWS/
  VoiceOver claim.
- **Chromium only.** Firefox and WebKit were not tested against the repair.
  FINDINGS' WebKit 18.2 observation was a pre-repair corroboration of the
  missing `domReadOnly`, not a check of this fix.
- **Anonymous public ledgers only.** Authenticated production editing was not
  exercised; the two account-deletion previews sit behind a writer-only dialog
  and are covered by the shared policy and its tests rather than by deleting
  real data.
- Viewports are emulated, not physical devices.

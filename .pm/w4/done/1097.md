**Severity:** minor. **Owner:** dashboard. **Estimate:** 45–60 minutes. **A2:** a reader reviewing exact commodity prices should keep the histories they opened when refreshing the same ledger. One remaining consumer of [m16](./done/m16/README.md)'s state-ownership pattern; do not count another historical finding group.

1. Open `/ledger/open_ledger/stock-example/commodities?lang=en`. By keyboard Enter, open **Show price history for ACME/USD** and **…BMKT/USD**. Both controls report `aria-expanded=true`; their named tables contain13 exact dated prices each. Leave NWRB/USD collapsed.
2. When the genuine current-head poll exposes **Out of date — click to refresh**, activate that actual button. In the first two cases, hold only GetLedgerCommodities before transport to inspect pending rendering.
3. Both old history controls/tables disconnect, accessible table count becomes0, and Loading data appears. Release the read unchanged: HTTP200 returns the same three pairs and all **41 unchanged source prices** (13 ACME,13 BMKT,15 NWRB), with no GraphQL errors.
4. All three controls now read **Show price history…**, with `aria-expanded=false`. Both deliberately opened tables have been forgotten despite identical ledger, URL, pair identities and prices.
5. Manually reopen ACME by Enter: its13 rows exactly match the original response/table. In the third fresh narrow case, apply **no price-read hold**; the ordinary successful refresh still collapses both histories. No outage is required.

Three retained contexts show six unwanted disclosure resets over six genuine commodity reads. All reader mutations, hosted writes, page exceptions and console errors are0. Python independently compares complete before/after response arrays, every originally displayed history row and the recovered table. The initial plain stock journey also verifies independent collapse/reopen: collapsing BMKT leaves ACME/NWRB tables and focus intact at both widths. This is refresh state loss, not an inaccessible disclosure, missing price, count, precision or calculation defect.

## Cause and bounded repair

`dashboard/src/features/ledger-data/commodities/commodity-price-history.tsx:22` keeps `open` in local `useState(false)`. Its sole production caller is the Commodities page at `commodities/index.tsx:230`, below that page's QueryView at:180. `common/components/query-view.tsx:54–59` replaces its children on loading, so a same-ledger revalidation removes the owners of all opened histories; successful data recreates each closed by default. The native action calls ROOT_QUERY eviction through `common/hooks/use-apollo-cache.ts:19`. The outer LedgerLayout already retains its shown same-ledger outlet on this cache refresh; changing that boundary alone cannot repair the inner branch.

Keep disclosure choices in a stable owner scoped to this ledger and **base/quote pair**, above the pending/error child replacement, and make histories reflect that retained choice. After a successful same-pair refresh, ACME/BMKT remain open and NWRB remains closed, showing the newly accepted response. New pairs start closed; disappearing pairs must not display stale tables. Preserve independent toggles, names/aria relationships, exact decimal strings, keyboard focus behavior, RTL amount isolation and narrow wrapping. Do not make transient disclosure state a global preference or add URL/storage persistence, requests, dependencies or API changes. Do not weaken pending-data guards or globally change QueryView's loading policy to solve this one consumer.

Acceptance: real Commodities/Apollo interactions open two histories, evict/refetch the same ledger through pending→success and retain those choices with exact returned rows; keep a third collapsed. Cover failure→in-place retry, changed/new/removed pairs and ledger isolation as compatibility cases, retaining m50's existing query-scoped retry. Exercise the actual parent boundary, rather than only rerendering CommodityPriceHistory with a new prop. Repeat desktop/narrow and run dashboard format:check, lint, test and build when implementing. **Resolved 2026-10-26** — `CommodityPriceHistory` is now a controlled disclosure. The Commodities page holds which `base/quote` histories are open, scoped to the current ledger, above the QueryView loading branch that replaces the cards while a refresh reads. A same-ledger refresh keeps opened histories open, showing the newly returned rows, and keeps closed ones closed. A new pair starts closed, a removed pair renders nothing, and another ledger starts with everything closed. Nothing is persisted to the URL or storage, and QueryView's loading policy is unchanged. A real Apollo page test (`commodities-history-refresh.test.tsx`) opens two of three histories, evicts the root query as Refresh does, holds the read, checks that no table is shown while it is pending, then releases a changed response and checks the exact rows, the expanded states, the new pair and ledger isolation; it fails on the old local state. The existing toggle, naming and RTL tests use a local owner. Dashboard format/lint/test/build pass. Native verification was not repeated, because it needs a simulated stale head; the deployed site and the repaired build in a browser are unverified.

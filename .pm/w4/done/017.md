# A URL `include` is reported against a path the user never wrote (`https://` → `https:/`)

**Severity:** minor. **Estimate:** 30–45 minutes. **Owner: `backend-cluster/ledger`** — surfaced through mobile QA, but the mobile app faithfully renders what it is given. A2: a permanent, unclearable error in a newcomer's Notifications that names a path absent from their ledger sends them hunting a typo that isn't there.

Environment: branch `main`, HEAD `038faeeb`, native development build `io.beancount.ios` on iPhone 17e / iOS 26.5, English / System / light, authenticated production session at `https://beancount.io`, own ledger `puncsky/example`. Report-only QA; no ledger mutation. BQL and file reads below are read-only through the MCP credential pinned to that ledger.

## Repro

1. Select `puncsky/example`. The header bell carries a red **1** badge.
2. Tap the bell. Under **LEDGER ERRORS**:

   > `failed to read file https:/beancount.io/prices/BTCUSD: file not found in virtual filesystem: https:/beancount.io/prices/BTCUSD`

   Note **`https:/`** — one slash — in both halves of the message.
3. Read the ledger source. `main.bean` line 10 is:

   ```
   include "https://beancount.io/prices/BTCUSD"
   ```

   **Two slashes.** The path in the error does not exist anywhere in the ledger.

## Cause

`backend-cluster/ledger/src/foundation/rustledger/file-map-loader.ts:68-76`:

```ts
export function resolveIncludeTarget(includingPath: string, target: string): string {
  const joined = target.startsWith("/")
    ? target
    : posix.join(posix.dirname(includingPath), target);
  return posix.normalize(joined).replace(/^\/+/u, "");
}
```

The target is not absolute, so it goes through `posix.join(posix.dirname("main.bean"), target)` → `posix.join(".", "https://beancount.io/prices/BTCUSD")`, and POSIX path semantics collapse the `//`. Verified in Node against the ledger's exact string:

```
normalizePath(raw)      = "https:/beancount.io/prices/BTCUSD"
join(dirname(main),raw) = "https:/beancount.io/prices/BTCUSD"
```

— byte-identical to what the app shows.

**This is not cosmetic.** The function's own doc comment states the resolved path "is both the Gitea blob key we fetch and the key the WASM engine looks the include up under, so the two agree." So the mangled string is the lookup key, not just a display string: the loader searches the repo for a blob literally named `https:/beancount.io/prices/BTCUSD`, doesn't find it, and the WASM engine reports it missing from the virtual filesystem.

**Remote includes appear to be unsupported by design**, and that looks deliberate rather than broken: includes resolve to repository blobs, and there is no HTTP fetch path anywhere in this loader (`grep http` in the file returns nothing). So the ledger line is asking for something the platform does not do.

## Fix

The defect is the **diagnostic**, not the missing feature. Detect a target with a URI scheme (`^[a-z][a-z0-9+.-]*://`) before path resolution and fail with a message that names what the user actually wrote and why it cannot work — for example: `include "https://beancount.io/prices/BTCUSD": include targets must be paths inside the ledger repository; remote URLs are not supported.` Never run a URL through `posix.join`/`posix.normalize` and then report the mangled result.

Leave the repo-relative behaviour exactly as it is: `.`/`..` resolution, duplicate-slash collapsing, leading-slash stripping, and glob metacharacters surviving normalization are all deliberate and depended upon.

**Whether remote includes should be supported at all is a separate product question**, not part of this fix — note that `w4/m9` (`bea price fetch`) is the adjacent live topic for keeping prices current, and a price-include mechanism would belong there, not here.

**Acceptance:** a ledger containing `include "https://…"` reports an error quoting the original URL and stating that includes must be repo-relative; no error message anywhere contains `https:/` with a single slash. Repo-relative includes, `..` traversal, absolute-path includes and glob includes behave exactly as before. Add coverage to `src/foundation/rustledger/__tests__/file-map-loader.test.ts` for a URL target and for a target containing an incidental `//` — **the suite currently has no test for either**, which is why the collapse went unnoticed.

## Blast radius

`resolveIncludeTarget` is the single resolution point for every `include` in a ledger, so any target containing `//` is affected, not just URLs. Reproduced on `puncsky/example` via the mobile Notifications screen. Not exercised: the dashboard's and CLI's rendering of the same error, the MCP `beancount://{owner}/{name}/errors` resource, whether a glob target containing `//` is similarly mangled, and behaviour when the URL-like target is the ledger's entry point rather than an include.

## Adjacent states

The mobile Notifications screen itself behaves correctly: the error has no filename, and `formatErrorLocation` (`mobile/src/screens/notifications-screen/formatting.ts`) correctly falls back to rendering the whole message. The healthy state (`Ledger is healthy — no errors.` on `open_ledger/alphabet`) and the RECENT CHANGES list both render fine. Note the error is **permanent and unclearable** from the app — the badge stays until the ledger line is edited.

---

**Resolved 2026-09-14** in `fix(ledger): report a URL include as written instead of a collapsed path`.

**What the engine does.** rustledger resolves includes itself through `Ledger.fromFiles`, so fixing `resolveIncludeTarget` alone would not change the message. A live parse on `@rustledger/wasm` 0.21.0 returned `code: "LOAD"`, `phase: "parse"`, no file or line, and `failed to read file https:/beancount.io/prices/BTCUSD: file not found in virtual filesystem: https:/beancount.io/prices/BTCUSD`. A URL included from `sub/nested.bean` was reported as `sub/https:/example.com/p.bean`. An incidental `include "sub//a.bean"` loaded normally.

**Fix.**
- **The error.** At the engine error seam, after `reconcileDocumentErrors`, `reportUrlIncludes` (`src/foundation/rustledger/url-include-errors.ts`) replaces that report with `include "https://beancount.io/prices/BTCUSD": include targets must be paths inside the ledger repository; remote URLs are not supported`, located at the file and line of the `include`. Other load errors, including a missing repository include, are left alone.
- **The loader.** A target with a URI scheme (`isUrlIncludeTarget`) is now skipped by `loadLedgerFileMap`, `collectSourceFiles`, and the source-slice include walk. A URL is no longer normalized, matched as a glob (a query string's `?`), or fetched as a repository blob.
- **Unchanged.** `resolveIncludeTarget` still resolves `.` and `..`, collapses duplicate slashes, strips leading slashes, and keeps globs.

**Tests.**
- `url-include-errors.test.ts` feeds in errors shaped like the engine's live output: a top-level URL, a nested URL, errors that must stay untouched, and a ledger with no URL include.
- `engine-url-include.test.ts` covers the wiring through `parseLedgerFilesInProcess`, with the WASM loader stubbed.
- `file-map-loader.test.ts` covers URL recognition, an incidental `//` that still collapses, include line numbers, and a URL never resolved against or fetched from the repository.
- Mutation proof: remove the engine call or either loader skip, and its test fails.
- `yarn test` passes (918), as do `yarn lint`, `yarn typecheck` and `yarn build`.

**Not exercised.** The deployed service. The new message as rendered on mobile Notifications, the dashboard, the CLI, and the MCP errors resource. Whether remote includes should be supported at all remains a separate product question; `w4/m9` is the adjacent prices topic.

# Keep transaction rows identifiable at enlarged text sizes

**Severity:** minor — rated to match `w3/done/181`, the same defect in the merchant row, though the blast radius here is larger: this is the app's primary browse list and *every* row becomes indistinguishable. **Estimate:** 45–60 minutes. Owner: mobile. A2: users who enlarge text must be able to tell one transaction from another before opening it.

Environment: branch `main`, HEAD `038faeeb`, native development build `io.beancount.ios` on iPhone 17e / iOS 26.5, English / System / light, authenticated production session at `https://beancount.io`, public `open_ledger/alphabet`. Report-only QA; no ledger mutation. Content size restored to `large` afterwards and verified.

## Repro

1. `xcrun simctl ui <udid> content_size accessibility-medium` (AX1 — the first size past the 1.3 threshold in `common/theme/dynamic-type.ts`). Terminate and relaunch the app.
2. Tab bar → **Transactions**.
3. Every visible row's payee is cut to two or three characters while its amount keeps full width:

   | Name shown | Amount shown |
   | --- | --- |
   | `Q2 2…` | `$26,560,000,000.00` |
   | `Q2…` | `+$97,983,000,000.00` |
   | `Q2 20…` | `$6,461,000,000.00` |
   | `Q2 2…` | `$18,219,000,000.00` |
   | `Q2 20…` | `+$106,000,000.00` |

   All eight rows read `Q2…`/`Q2 2…`/`Q2 20…`. Nothing distinguishes an expense from revenue, or one entry from another, except the amount and the leading icon.
4. Home → Recent Transactions shows the same collapse, down to a single character: `Q…` beside `$26,560,000,000.00`.
5. Relaunch at AX1 and repeat — identical.

**Working control:** restore `content_size large`. Every row shows its full payee (`Q2 2026 Expenses`, `Q2 2026 Other I…`, `Q2 2026 Revenue`) beside the same amounts.

**Expected:** at enlarged sizes the row stays identifiable — the name gets the space it needs, restacking above the threshold if necessary, as the merchant row and Reports categories already do.
**Actual:** the amount takes whatever width it wants and the name absorbs the entire shortfall.

## Root cause

`mobile/src/screens/transactions-screen/entry-row/index.tsx` styles: `middle: { flex: 1 }` holding `name: { flexShrink: 1 }`, beside `amount: { fontSize: fontSizes.md, marginStart: space.sm, flexShrink: 0 }`. The amount is explicitly unshrinkable, so in a `flexDirection: "row"` it claims its full intrinsic width first and the name is the only thing that can give. At AX1 with a 19-character amount, what is left is a few characters.

This is the same shape `31f1e4ce` ("make nine surfaces survive Dynamic Type and the keyboard") repaired elsewhere — `w3/181` for merchant rows ("gave the scaled date fixed width, squeezing the name"), `w3/183` for Reports categories ("names ellipsized while the amount kept a 1.4x cap"). `EntryRow` was not among the nine.

## Fix

Follow the established pattern rather than inventing one: above `common/theme/dynamic-type.ts`'s 1.3 threshold, drop the amount to its own line and let the name wrap; below it, keep today's single-row geometry byte-for-byte. `w3/183` and `w3/181` both did exactly this and share that helper.

Do not fix this by letting the amount shrink or ellipsize — `AmountText`'s own contract is that amounts "can't ellipsize without lying". Do not cap the name to a fixed width, and do not drop the pending badge or the type label; both live in `middle` and must survive the restack. Preserve the icon, the tap target and the row's `minHeight` rhythm.

**Acceptance:** on a fresh iPhone 17e launch at AX1 and at maximum size, Transactions rows show their full payee and their full amount, on `open_ledger/alphabet` (19-character amounts) and on a short-amount ledger; at `large` the rows are pixel-identical to today. Home → Recent Transactions and the Reports account-transactions card get the same treatment. Add constrained-layout regression coverage for a long name with a large amount, a short name, a pending row (badge present), and a non-transaction row that renders `directive_type` in the amount slot.

## Blast radius

`EntryRow` has four production callers: `transactions-screen.tsx:238` (reproduced), `home-screen/components/recent-transactions-card.tsx:80` (reproduced), `reports-screen/components/account-transactions-card.tsx:118` and `merchant-detail-screen.tsx:575` (both not independently exercised at AX1). `account-detail-screen/components/account-entry-row.tsx` is a different component with its own layout and is **not** covered by this note. Not exercised: RTL, dark mode, VoiceOver, Android.

## Adjacent states

The amounts themselves are correct and complete here — unlike `w4/012`/`w3/217`, where the Accounts row clips the *balance*. The two are opposite outcomes of the same "unshrinkable trailing block" mistake and should be fixed with the same restack technique, but they are different components and different notes. Loading skeletons (`transactions-list-skeleton.tsx`, which mirrors EntryRow's 40px icon and 12px padding) will need the same treatment or the list will shift when data lands.

---

**Resolved 2026-09-14** — fixed in `mobile` by `fix(mobile): keep transaction rows identifiable at enlarged text sizes`. Triage confirmed the root cause at HEAD before the fix: `EntryRow`'s amount had `flexShrink: 0` beside a single-line name, so at AX1 the payee absorbed the whole shortfall and read `Q2…`. The note was not stale.

Following `31f1e4ce` (`w3/181`, `w3/183`), `EntryRow` reads `useWindowDimensions().fontScale`. At or above `prefersStackedLayout`'s 1.3 threshold it becomes a column: the icon and name, with the pending badge, sit in an inner row, the name can wrap, and the amount — or the directive type for a non-transaction — moves to its own line at the leading edge. Below the threshold the row is unchanged. The amount is never truncated or ellipsized. `TransactionsListSkeleton` restacks the same way, so the list does not shift when rows replace it. The four `EntryRow` callers — Transactions, Home recent transactions, the Reports account card, and merchant detail — all inherit the change.

Regression test: `mobile/src/__tests__/entry-row-dynamic-type.test.ts`. It is a source guardrail, because the unit runner cannot lay out text. It checks the threshold wiring, the wrapping name, the unbounded amount, and the skeleton, and all four tests fail with the restack reverted. The device acceptance at AX1 and at maximum size on `open_ledger/alphabet` was not repeated in this run.

## Objective

Derive `metadata/play/<locale>.json` from the canonical `app-info` and `version` copy with Play's limits, mapping locales through `store-locales.json` and adding Bulgarian and Persian, which Play accepts and Apple does not.

## Context

- Play limits: title 30, short description 80, full description 4000 characters; Play locale codes differ from Apple's (`zh-CN`, `pt-BR`, `es-419`, and so on).
- `metadata/app-info/<locale>.json` holds name and subtitle; `metadata/version/<version>/<locale>.json` holds description and promotional text; `metadata/store-locales.json` maps runtime to store locales.
- `yarn metadata:validate` is the existing project check; extend it rather than adding a second validator.

## Steps

1. Write the generator (Node, beside the existing metadata scripts) that emits one Play JSON per locale, deriving the short description from the subtitle plus promotional text and trimming at word boundaries.
2. Add bg and fa entries with translated copy consistent with the app's locale files.
3. Extend `metadata:validate` with the Play limits and run it in CI.

## Files

- mobile/metadata/play/
- mobile/metadata/store-locales.json
- mobile/scripts/
- mobile/package.json

## Acceptance criteria

- [x] Fourteen-plus Play locale files exist, including bg and fa, and each respects the three limits.
- [x] `yarn metadata:validate` fails when a limit is exceeded and passes on the generated set.

## Out of scope

- Release notes; those already flow from `yarn bump`.

## Validation evidence

Generated 16 metadata/play locale files from the current canonical App Store copy plus native Bulgarian and Persian sources. yarn metadata:validate passes on the generated set and rejects a deliberately over-limit title in an isolated fixture. Tests cover Unicode limits, locale mapping, and complete-word/clause trimming. CI now invokes metadata validation without regenerating files, so drift fails the gate.

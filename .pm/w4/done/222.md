# Reveal the focused account prefix inside the narrow Accounts row

Severity: **minor**. Package: **dashboard**. Estimate: **25–40m**. Source:
continuous dashboard QA. **A2**: a keyboard reader should see which parent
account will open before pressing Enter.

Production `https://beancount.io`, public synthetic `open_ledger/example`,
owned isolated headless Chromium149.0.7827.55, local main `42de5a66`; exact
served revision unverified. Read-only navigation, no account writes.

1. At390×900, open `/ledger/open_ledger/example/accounts?time=2016&lang=en`
   and search `Expenses:Taxes:Y2017:US:Federal:PreTax401k`.
2. Focus that row's Expenses prefix button. Press Tab four times, through
   Taxes, Y2017 and US to Federal. These are actual native key presses.
3. The active button's label is `:Federal`, width67.4375px, but only10.703125px
   survives the account-name span's clipping. Its span retains `scrollLeft=0`.
   The row visibly ends `Expenses:Taxes:Y2017:US…`; the focused Federal segment
   is not readable. The highlighted parent prefix also stops at that ellipsis.
4. Wait800ms after focus, then another500ms: identical geometry and focus.
   Two independent fresh390px contexts reproduce this. Enter opens the parent
   `Expenses:Taxes:Y2017:US:Federal`, as its accessible name promises.
5. Fresh1440px control: the same focused button is fully visible, all67.4375px.
   On narrow, tabbing one further to PreTax401k causes the browser to scroll
   the span149px and reveal that leaf; the partially clipped Federal focus
   specifically receives no equivalent reveal.

This is a visible keyboard-focus/readability defect. The buttons' full prefix
accessible names and destination navigation work; no screen-reader speech or
missing-data defect is claimed. The real public account-directory API includes
this account. A cropped row screenshot was visually inspected, alongside the
settled rectangles and actual activeElement.

`dashboard/src/features/ledger-data/accounts/account-prefix-navigation.tsx:35`
puts all segment buttons inside a `truncate` span capped at55cqw on narrow
screens. Its `onFocus` at62 only updates the highlighted prefix. It does not
ensure that a partially clipped focused segment becomes visible. The browser
reveals the later entirely-outside leaf, but leaves this intermediate prefix
mostly outside the clipping area. Changing the account table's data, widths
or global overflow is unnecessary.

Reveal each focused prefix within the existing account-name viewport, retaining
ellipsis for the unfocused row and the established narrow layout. Preserve
full accessible names, native Tab order, prefix hover/focus highlighting,
parent/full-account navigation, table semantics and permission gates. Check
actual clipped geometry and visible text for partially clipped intermediate
segments and the leaf, including reverse Tab and a Persian smoke check; avoid
scrolling the whole page or changing which button receives focus. Run relevant
dashboard checks when implementing.

Dedupe across open/done/blocked board notes found no Accounts-directory prefix
focus-reveal repair. Done `w4/050` concerns the native mobile account picker,
not this dashboard component. `w4/204` is search-Clear focus restoration and
`w4/221` is the directory table's accessible name; both have different causes.

Ignored evidence under `dashboard/tmp/qa-20261008-loop/`:
`accounts-long-prefix-keyboard-control-result.json` contains every prefix's

`accounts-partially-clipped-prefix-focus-repro-result.json` contains the two
settled narrow repeats and desktop control. Screenshots

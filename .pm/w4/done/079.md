# Report interval and conversion selectors have no accessible names

Severity: minor. Estimate: 45m, dashboard. A2: readers using assistive technology should be able to identify which report control changes the interval and which changes valuation. Source: repeated dashboard QA, 2026-09-17.

Environment: production https://beancount.io, anonymous reader of public synthetic `open_ledger/example`; QA-owned isolated headless Chromium 149.0.7827.55, English/light, 1440×1000 and fresh 390×844 reload. Local main `26d54a9db7d33c31a549bd12a0454a1c01f3f038`; deployed asset main-BIr0jJni.js, exact deployed commit unverified.

Repro:
1. Open `/ledger/open_ledger/example/account/Assets%3AUS%3ABofA%3AChecking`, wait for the account chart, and inspect Chromium's accessibility tree through `Accessibility.getFullAXTree`.
2. The interval and conversion controls are focusable comboboxes with `name.value: ""`, while their separate values are `Monthly` and `At Cost`. Select Changes Over Time, then Yearly: the interval value updates to `Yearly` but its name remains empty.
3. Reload at 390×844. Both controls again have empty names; the adjacent responsive View combobox has `name: "View", value: "Account Balance"`.
4. Open `/ledger/open_ledger/example/trial-balance?time=2016` at 390px with charts shown. View is named; At Cost is unnamed. Focus conversion, press Space, ArrowDown twice, then Enter: Units is selected, but the control still has no name.

Expected: stable, localized names describing interval and conversion independently of their selected values. Actual: the browser exposes the selected values and options but no names identifying the controls' purposes. This records accessibility metadata, not an actual screen-reader speech session. Pointer and keyboard selection work; no arithmetic failure is claimed.

Working controls: the neighboring View combobox and desktop global Time/Account filters have nonempty names in the same browser tree. Trial Balance's Units selection sends `GetLedgerTrialBalance` with `{ledgerId:"open_ledger/example", conversion:"units", account:"", filter:"", time:"2016"}` and receives HTTP 200 without GraphQL errors. The menus expose their option names correctly.

Root cause: `dashboard/src/common/components/interval-select.tsx:37` and `conversion-select.tsx:37` render SelectTrigger without an associated label, aria-label or aria-labelledby. Their localized placeholders are passed to SelectValue and do not name a populated trigger. The shared `ui/select.tsx:34` wrapper forwards supplied props; installed `@radix-ui/react-select/dist/index.js:240` sets role combobox and forwards triggerProps without inventing a name. This is an omission in the two owning wrappers, not a reason to fork the primitive.

Fix: supply a stable translated accessible name on each shared trigger, using an appropriate existing translation or adding purpose-specific keys in the normal locale catalogs. Preserve the independent selected value, keyboard behavior, size/class overrides, and conversion/interval callbacks. Add meaningful role-and-name checks against the real rendered wrappers for multiple selected values, including a non-English locale; verify the browser tree on Account and Trial Balance after implementation. Run dashboard's normal format/lint/test/build gates. No API/schema or dependency change is needed.

Blast radius from all production callers: IntervalSelect appears on Account, Balance Sheet, Income Statement and Cash Flow; ConversionSelect appears on those four plus Trial Balance. The latter three sibling report journeys are source-traced for this omission, not separately reproduced here. Preserve completed chart-collapse behavior: hidden chart controls must remain excluded from focus/accessibility, and reopening must restore named controls. Empty/error/authenticated states, actual screen-reader output and non-Chromium engines remain unverified.

Dedupe: searched all `.pm/**/*.md`, including done/blocked, for both component names, combobox, unnamed/unlabelled selectors, and chart-control labels; scanned open milestone titles. Completed `w3/done/148.md` fixed narrow Trial Balance selector availability, and `w3/done/127.md` fixed hidden chart focus; neither supplies the missing names. Current history for both wrappers is the original `af5339de` import, and targeted aria-label history contains no repair. No overlapping open finding or newer source fix found.

Verified ignored evidence: `dashboard/tmp/qa-20260917/unnamed-report-selectors.json` records native Chromium name/value pairs for desktop, fresh narrow Account, and Trial Balance before/after Units. `unnamed-report-selectors.png` is the visually inspected 390×844 Account control screenshot. Report-only work; no product fix, production mutation, commit or push.

**Resolved 2026-09-19** — both shared triggers now carry `aria-label` with the
same localized string they already used as a placeholder ("Select time period",
"Select conversion"), which exists in all fifteen locales, so no new keys were
needed; a caller passing its own placeholder names the control with that
instead. Verified in Chromium's accessibility tree at 1440×1000 and 390×844 on
the account and trial-balance pages: the two controls went from `name: ""` to
their names, and every combobox on both pages now has a distinct non-empty name
beside its own value — 8/8. Ten regressions assert role and name against the
real wrappers across three selected values each, a non-English locale, a
caller-supplied override, and the two controls being named differently; all ten
fail without the attribute. Keyboard behaviour, size/class overrides and the
value callbacks are untouched. No screen reader was exercised — this is
accessibility-tree metadata, the same boundary the note drew. Shipped in
`95be96cc` (`dashboard`).

---

**Resolved 2026-09-19** — `code-block.tsx` hid the copy affordance with
`opacity-0` and revealed it only through `group-hover:opacity-100`, with no
rule for keyboard focus, so Tab landed on a correctly named and correctly
focusable button that computed `opacity: 0` — hiding both its icon and the
shared Button's focus ring. `focus-visible:opacity-100` now reveals it while
focused.

Nothing else changed: hover still reveals it, blurring with the pointer away
hides it again, and the focus order, the localized accessible label from
`64b477da`, the copied text, the success and failure feedback, the timer
cleanup and inline code are untouched. The button stays in the tab order and
the shared Button is not modified.

Verified in a real browser at 390px and 1440px against the component's own
class list, read out of the source file rather than retyped, so the check
measures the shipped rule: with the previous classes a keyboard-focused button
matched `:focus-visible` and computed `opacity: 0`; with this change it
computes `1`, hover still computes `1`, and an idle button with the pointer
away computes `0`. Because `:focus-visible` is direction-independent, Shift+Tab
was not separately measured.

The production repro path was not reachable locally: the README card renders
for these public ledgers but its file content comes back empty through the QA
proxy, so no fenced code block exists to Tab into. The check above exercises
the same component and the same compiled CSS instead, and the existing
code-block, markdown-renderer and readme-card suites (29 cases) still pass
unchanged; per this note no class-string assertion was added. Gates from
`dashboard/`: `yarn format:check`, `yarn lint`, `yarn test` (395 files, 4436
passed, 1 pre-existing skip) and `yarn build` all pass. Other browsers,
physical touch and actual screen-reader speech remain unverified. Shipped in
`be58a47e` (`dashboard`).

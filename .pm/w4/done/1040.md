# Keep focus on the What's new disclosure when its layout changes

**Severity:** minor. **Estimate:** 40–55 minutes, dashboard. **A2:** keyboard readers should be able to expand and collapse release notes without losing the disclosure control.

## Reproduction and controls

Production `https://beancount.io/ledger?lang=en`, 2026-10-23; dedicated QA sign-in, owned isolated headless Chromium156.0.8078.47, English/UTC/light, fresh1440×1000 and390×844 contexts. The genuine GetChangelog read (`limit:5,locale:en`) returns five releases with HTTP200 and no GraphQL errors. All five predate the fresh device's unread cutoff, so What's new initially has its compact layout. No stored preference or response fixture was injected.

1. Focus **Show recent releases** and press Enter. Five release rows and **Hide recent releases** appear. After the new layout is visible and its animation has settled, the original button is gone and `document.activeElement.tagName` is **BODY**.
2. Press Enter again without moving focus. The section remains expanded; the corresponding Hide button did not receive focus.
3. Focus **Hide recent releases** and press Enter. The compact layout and Show button return. After settlement, the focused Hide button is gone and focus is again **BODY**. A second Enter leaves the section collapsed.
4. Native Tab after that collapse reaches the compact latest-release **link**, not the equivalent Show button. This is not a claim that Tab restarts at the beginning of the document: the observed next stop remains nearby. The failure is losing the active disclosure and the ability to toggle it again with Enter.
5. Working control in each same context: focus Activity's **Show More** and press Enter. Genuine GetFeed reads use source LEDGER_RSS, limit10, offsets0/10 and locale en. Cards increase10→20, and the settled Show More button retains native focus.

Both fresh widths reproduce both disclosure transitions. No release link, Mark all as read action, outgoing message, hosted mutation or AI action was activated. Zero attempted GraphQL mutations, route errors or page exceptions. This report does not claim financial-data loss or an inaccessible release list.

## Cause and bounded repair

`dashboard/src/features/ledger-list/components/whats-new.tsx:54–55` computes `expanded` from unreadCount/manuallyExpanded. Its compact early-return layout starts at:63; the Show button at:100–113 sets manuallyExpanded true. The expanded return puts a different Hide button under another parent at:160–171 and sets it false. Each manual transition removes the focused control and mounts its replacement without a focus handoff. The generic Button primitive cannot retain a DOM node that this owner removes.

Keep the disclosure's focused control through both user-initiated transitions, either by retaining the same button or by handing focus to its equivalent after the new layout mounts. Preserve the localized Show/Hide names, aria-expanded/controls association, responsive compact/expanded presentation, release ordering, links, unread flags and watermark policy. Do not pull focus into the section when a background read or cross-tab watermark update changes its state. Preserve the deliberate absence of a section when changelog loading fails or returns no releases. No API, dependency or shared dialog/paging change is required.

Acceptance: with the real WhatsNew owner/hook and an all-read release list, focus the disclosure, press Enter to expand, and verify the active control now has the Hide name and expanded state. A second Enter collapses it and leaves the Show control focused; repeat the cycle with Space and at desktop/narrow widths. Verify link navigation/tab order and the existing unread-driven presentation still work without unsolicited focus moves. Keep the working Activity paging control and run dashboard gates when implementing. Mark all as read and last-unread-link transitions need adjacent regression coverage; they were not independently exercised live because these real releases are older than the initial cutoff.

**Resolved 2026-10-23** — In What's new (`ledger-list/components/whats-new.tsx`), four actions swap the layout and remove the control just pressed: Show, Hide, Mark all as read, and opening the last unread release. Each now sets a one-render handoff. A layout effect then focuses the disclosure toggle, now one ref shared by the Show and Hide buttons, but only when focus was actually dropped. An earlier unread release's link keeps its focus, and a background read or another tab's watermark never moves focus. Names, `aria-expanded`/`aria-controls`, both layouts, ordering, links, unread flags, the watermark policy and the absent section on failure or empty are unchanged.

`whats-new-focus.test.tsx` runs the real WhatsNew over the real watermark hook (only the changelog read stubbed). It covers:
- all-read Enter and Space cycles: Hide focused and expanded, then Show focused and collapsed, then Hide again;
- Mark all as read handing focus to Show;
- the last unread link handing focus to Show;
- an earlier unread link keeping focus;
- another tab reading everything without moving focus from a control after the section.

The four defect cases fail on the old component; the two preservation controls pass on both.

Native check on the built repaired client (local fixture SSR, synthetic signed-in owner; `GetChangelog` answered in the browser with synthetic releases, either all older than the first-visit cutoff or two recent unread), at 1440×1000 and 390×844:
- Enter, Enter, Space, Space on the disclosure focuses Hide (expanded), Show (collapsed), Hide, Show;
- Tab then moves on to the next control after the section;
- in the unread case, Mark all as read leaves focus on Show recent releases, and Enter re-expands with Hide focused.

Zero mutations or page errors, and no horizontal scroll. Release links were not opened natively. The local fixture had no Activity feed data, so Activity's own paging control was not re-checked here; it is unchanged by this diff. Dashboard gates pass. Not verified: other engines and locales, screen-reader speech, and the deployed client. Shipped in the commit that moved this note (`dashboard`).

# Keep IME composition keys from applying Combobox values

**Minor · dashboard · 55 minutes.** A2: Japanese and other input-method users must be able to confirm composed text without accidentally applying a filter or suggestion. Production beancount.io, 2026-10-20, owned isolated headless Chromium 155, Japanese application/browser locale, fresh 1440×1000 and 390×844 contexts. Signed-out public example, read-only. Local main `8c5f352c6`; full deployment revision unverified.

## Browser reproduction and controls

1. Open `/ledger/open_ledger/example/income-statement?time=2016-08&lang=ja` and wait for the actual filter input to hydrate. At narrow width open **フィルタ** → **レポートフィルタ**. Focus the Time field, named **期間**.
2. Start Chromium's browser-engine IME composition through a page-scoped CDP session: Input.imeSetComposition with text `2016-09`, selectionStart/End 7. The real field contains that preedit value while the URL still selects 2016-08. Captured compositionstart/compositionupdate/input events are trusted; input.isComposing is true.
3. Dispatch Enter through Input.dispatchKeyEvent. The browser-generated keydown has **isTrusted=true, isComposing=true, keyCode=13**.
4. At both widths the app immediately changes the URL to `time=2016-09` and blurs the field. Its pending composition is terminated. This key should confirm the input method's composition, leaving an ordinary later Enter to apply the filter.

An independent controlled DOM compositionstart/keydown case also reproduces at both widths with isComposing=true/keyCode229; those events are explicitly untrusted and are supplementary evidence. A separate ordinary Playwright Enter control at 390px correctly applies 2016-09. No ledger writes, mail, clipboard or OS input-method changes occurred. Physical Japanese/Chinese/Korean IME sessions remain unverified; this is a browser-engine composition reproduction, not a physical-keyboard claim.

The [W3C UI Events composition-key contract](https://www.w3.org/TR/uievents/#events-composition-key-events) describes key events delivered during a composition session with isComposing set. The app currently treats such an event as its ordinary application shortcut. No claim about every platform's legacy keycode sequence is needed for the trusted keyCode13 case.

## Cause and bounded repair

`dashboard/src/common/components/ui/combobox.tsx:137–179` handles Enter/Escape/arrows without inspecting the native event's composition state. Its custom-value Enter branch prevents default, calls onValueChange, closes the popup and blurs the input. Ledger search controls configure Time, Account and the payee/tag filter with allowCustom=true/triggerOn=blur, so composing Enter prematurely applies their draft. This is distinct from [255](./255.md)'s focus loss after an intentional ordinary selection.

Keep the component's own keyboard selection/commit/dismiss/navigation actions out of active composition. Read React's underlying native KeyboardEvent state; do not solve this by disabling non-ASCII text, swallowing the input method's default action, auto-submitting at compositionend or moving focus. After composition ends, normal Enter, arrows, Escape, blur and pointer selection must retain their established behavior. Keep any required compatibility handling bounded to observed event sequences.

Search results identify shared consumers in ledger filters; account, source-file, payee, narration and currency wrappers; importer account mapping; and Journal Note metadata. Only the Time alias was live exercised. Audit these callers for the shared fix without claiming that any wrong account was booked or that a form submitted. [287](./287.md) and [288](./288.md) record independent Gallery and DatePicker handlers; neither uses this Combobox implementation.

Acceptance: meaningful real-Combobox tests send composing Enter with isComposing=true/keyCode13 and verify no selection callback, blur or popup/application commit. Cover a highlighted suggestion and allowCustom/triggerOn=blur, composition-end followed by ordinary Enter, and retained arrow/Escape behavior outside composition. A real filter harness must leave the URL unchanged during composition and apply it on the subsequent ordinary command. Repeat browser-engine composition at desktop/narrow widths and run dashboard format/lint/test/build. No API, dependency or persistent draft mechanism is needed.

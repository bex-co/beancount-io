## Objective

Add the `createLedger` GraphQL operation to mobile and a create-ledger screen mirroring the dashboard's form rules: name with slug preview, description, private toggle, and a Starter or Sample template choice.

## Context

- The schema exposes `createLedger(name, description, private, template: LedgerTemplate)` with `STARTER` and `SAMPLE`; mobile never calls it (`src/common/graphql/queries/` has no such operation).
- The dashboard's rules live in `dashboard/src/features/ledger-list/components/ledger-form.tsx`: name 1–100 chars, GitHub-style slug, default name generated from existing ledgers, private defaults to true, template defaults to Starter and is only sent when Sample.
- Forms use React Hook Form + Zod; screens live in `src/screens/<name>/` and mount from `app/(app)/`; loading states use `LoadingTile`.

## Steps

1. Add `createLedger.graphql` and run `yarn codegen`.
2. Build `src/screens/create-ledger-screen/` and `app/(app)/create-ledger.tsx` with the four fields, slug preview, and a template picker with short descriptions.
3. Port the slug rules as a pure helper with unit tests.
4. Verify in the simulator in light and dark.

## Files

- mobile/src/common/graphql/queries/createLedger.graphql
- mobile/src/generated-graphql/
- mobile/src/screens/create-ledger-screen/
- mobile/app/(app)/create-ledger.tsx

## Acceptance criteria

- [ ] The form rejects empty and over-long names and shows the slug when it differs from the input.
- [ ] Submitting sends `template` only for Sample, matching the dashboard payload.
- [ ] `yarn typecheck` and `yarn test:unit` pass; light and dark screenshots recorded.

# Search payee suggestions by their literal names while retaining safe filter values

Severity: minor search regression. Estimate: 45m, dashboard. A2: readers should find a payee by typing the name printed in their journal, including punctuation.

Environment: production https://beancount.io, anonymous synthetic open_ledger/example, isolated headless Chromium149.0.7827.55, English/light1440×1000 and fresh390×844. Local main26d54a9db7d33c31a549bd12a0454a1c01f3f038; deployed main-BIr0jJni.js, exact deployed commit unverified.

Repro: open Journal and type `E.B.` into “Filter by tag, payee, ...”. The input retains the complete text but offers no matches. Fresh desktop character-by-character typing at120ms/key repeats this; fresh390 through Filters repeats it too. GetLedgerAttributes successfully includes the literal payee `E.B.'s Beer and Wine`. Replace the draft with `Beer`: the payee suggestion appears, with backslashes before its periods. Select it: Journal correctly returns four entries for that exact payee, HTTP200, dated April13/15/16/18,2016. The payee exists and filtering works after selection; discovery by its punctuated prefix is what fails.

Expected: raw payee-name searches match their suggestions while selection still emits the safe, regex-escaped FQL value. Actual: serialization changes the only searchable text, so a period in the typed name is no longer adjacent to the preceding letter in the suggestion's escaped representation.

Root: `dashboard/src/common/components/ledger-search-controls/index.tsx:149` builds payee items with serializePayeeFilter. SearchControlCombobox at49–55 assigns that same serialized string to both label and value. Shared `ui/combobox.tsx:75–84` searches only label/value by literal substring, so the raw `E.B.` cannot match the escaped text. Preserve the raw payee as searchable/display metadata alongside its separately serialized value. Combobox already supports separate label and value; avoid weakening the serializer or treating every user-authored advanced expression as plain text. Time/account hierarchy, tag/link suggestions and custom-expression editing must retain their existing behavior.

Dedupe/history: searched all .pm including done/blocked for payee autocomplete/search, suggestion labels and punctuation escaping. Completed w3/155 repaired generated payee values that accidentally acted as regex syntax. Commit254cfea0 correctly added serializePayeeFilter but passed its escaped output through the string-only item path; this is its autocomplete consequence. Retain that completed literal-matching repair and its mixed-quote/backslash tests. Native w3/112 concerns another package's merchant filtering. Open w4/m13 interrupts Accounts typing at a route remount; here the full text and focus remain, and local suggestion matching alone fails. No matching active item or later repair found.

Acceptance: typing the literal punctuated name offers the right suggestion; keyboard/pointer selection emits the unchanged safe serialized value and still returns the four matching entries. Cover periods, parentheses, quotes/backslashes and ordinary payees in a meaningful rendered combobox test, plus tag/link and custom-expression controls. Do not strip punctuation, search against a lossy name, double-escape values or change backend regex semantics. Verify fresh desktop/narrow and run dashboard gates. Other engines, locales, live mixed-quote payees and patched behavior remain unverified.

**Resolved 2026-09-19** — Reproduced against a local build of the public
example ledger: typing `E.B.` in the journal filter returned "No matches found"
while `Beer` produced `payee:"E\.B\.'s Beer and Wine"`. The same held for the
ledger's other punctuated payees. (`Amazon.com` named in the original write-up
is not a payee in this ledger; `Mr. Marcel`, `Giacomo's Restaurant` and
`Dupar's` are, and each reproduced the same way.)

The suggestion's only searchable text was the escaped FQL expression:
`ledger-search-controls/index.tsx` built payee items with
`serializePayeeFilter`, `SearchControlCombobox` assigned that one string to
both `label` and `value`, and `ui/combobox.tsx` searched only those two by
literal substring.

An option can now carry the text a reader would type when it differs from what
the option says: `ComboboxOption` gained an optional `searchText` that the
filter also matches, and payee suggestions carry the raw name beside their
separately serialized value. The serializer, the displayed expression, the
committed value and the backend regex semantics are unchanged, as are time,
account hierarchy, tag and link suggestions and custom-expression editing — the
`w3/155` literal-matching repair and its mixed-quote and backslash tests are
untouched.

Verified in a real browser, 11/11: drafts `E.B.`, `Mr. Marcel`, `Giacomo's` and
`Dupar's` each offer their own suggestion, an ordinary `Beer` substring still
works, `#trip` still matches tags, keyboard selection commits
`payee:"E\.B\.'s Beer and Wine"` unchanged and returns exactly the four entries
dated 2016-04-13, 04-15, 04-16 and 04-18 at both 1440px and 390px, and a
hand-written expression is still committed verbatim. Ten component cases cover
periods, parentheses, quotes, backslashes and an ordinary payee, plus tag/link
and custom-expression behaviour; six fail without the change while the control
cases keep passing. Gates from `dashboard/`: `yarn format:check`, `yarn lint`,
`yarn test` (388 files, 4400 passed, 1 pre-existing skip) and `yarn build` all
pass. Other engines and locales remain unverified. Shipped in `46f7d97e`
(`dashboard`).

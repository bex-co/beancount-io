# Appearance and breakpoint changes discard chart legend selections

Severity: **minor**. Estimate: **45–60 minutes**, dashboard only. A2 — readers comparing commodity series should keep their chosen series when System appearance changes.

Production `https://beancount.io`, 2026-10-09; dedicated QA GROWTH session from the user-selected root `.env`, English/System, owned isolated headless Chromium149. Fresh1440×1000 and390×844 reproductions and explicit-Light controls. Source/main `be4cb3b6` after pull (only unrelated board files changed); exact deployed SHA unverified. No ledger writes or fabricated responses.

1. Open `/ledger/open_ledger/example/income-statement?time=2016-02&lang=en&theme=system` with system appearance Light. The initial monthly chart exposes USD, IRAUSD and VACHR legend entries.
2. Click the **IRAUSD** canvas legend label with the browser pointer. The actual legend map becomes `{USD:true, IRAUSD:true, VACHR:false}`. Hover the chart: the tooltip contains `USD: -3,055.88` and `IRAUSD: +2,400`.
3. Change the browser’s system color scheme to Dark. After1200ms, the page is dark, but IRAUSD becomes unselected and its bar/tooltip value disappear. The map is `{USD:true, IRAUSD:false, VACHR:false}`.
4. Click IRAUSD again in Dark: its series/value returns. Change system appearance back to Light: IRAUSD becomes unselected again.

Both fresh widths repeat all four steps. Each appearance change creates a new ECharts instance. The report URI remains scoped to February2016, with exactly one observed `GetLedgerIncomeStatement` request and HTTP200 throughout; no new read or report-data change explains the lost choice. Actual pointer hovering and cropped screenshots show the disappearing series, rather than relying only on configuration inspection.

Working control: fresh explicit `theme=light` contexts at both widths keep the same chart instance, selected IRAUSD, and both tooltip values through system Dark/Light changes. Reselecting IRAUSD in the failing System context also works until the next appearance change. A separate account-chart visual control preserves250ACME and readable theme-specific tooltip colors across Light/Dark/Light; the theme repaint itself is functional. This is selection loss, not a financial-sign, missing-data or general chart-color claim.

Root: `dashboard/src/common/components/react-echarts/client.tsx:30–46` disposes/reinitializes the chart whenever `resolvedTheme` changes. Its option effect at48–55 replays the caller’s original defaults. Income Statement’s `single-date-balance-chart.tsx:119–128` initially selects only the primary series; pointer changes live inside the ECharts model and are not retained by the wrapper. Existing lifecycle tests explicitly expect recreation and replay but have no user-selected legend assertion.

Preserve the actual selected legend map across an appearance-only refresh of the same report/options, then apply it to currently eligible legend names through supported ECharts behavior. Preserve genuine option/data-scope updates, explicit theme precedence, the current palette/contrast, loading state, resize observers and disposal on unmount. Do not replay an old full option payload over newer report data or force all currencies selected. Installed ECharts6.0.0 also exposes `setTheme`, but an isolated real-runtime SVG control proves that calling it alone resets `{IRAUSD:true}` to false; merely replacing recreation with `setTheme` does not fix this bug. Resolved 2026-10-10. The shared chart client captures only selected legend maps before appearance recreation, tagged with the option object actually applied. After applying the same options to the refreshed chart, supported silent legend actions restore choices for current eligible names and selectable legends. Genuine new options keep their own defaults; no old full option payload is replayed. The unused mobile-key remount is removed, so existing window/container resize handling keeps the instance and its choice across breakpoint crossings. Explicit themes, palettes, loading, resize observers, refs and unmount disposal remain covered. Implementation ships with this resolution (`dashboard`).

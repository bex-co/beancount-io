# Retry a failed Collaborators settings read in place

**Minor · dashboard · 35–50 minutes · A2.** Residual of [M50](./done/m50/README.md): an administrator should be able to recover the failed member-list read where its error appears.

## Reproduction and control

Production `https://beancount.io`, 2026-10-23 Los Angeles / Oct24 UTC, owned isolated headless Chromium156.0.8078.47, English/light/UTC. Four fresh authenticated cases, two each at1440×1000 and390×844, use only the designated disposable QA ledger. **Abort only the initial ListLedgerCollaborators browser request before transport. This is an injected read failure, not a production outage.** Other requests and all response bodies remain genuine.

1. Open `/ledger/<qa-owner>/<synthetic-ledger>/settings?lang=en` as its owner. The Collaborators card settles at **Error Loading Collaborators / Failed to fetch**, with zero Try Again/Retry actions. Invite Collaborator is absent while the list is unavailable.
2. General Settings still has its Save control; Beancount Options and Fava Options render11 and20 table rows including headers. The collaborator failure does not take down those sections. Do not activate Save, visibility, deletion or membership controls.
3. Remove the selected fault and reload the same URL. ListLedgerCollaborators returns genuine HTTP200, no GraphQL errors and an empty list. The same card now says **No Collaborators** and offers Invite Collaborator; the two options tables are unchanged. This verifies a reload workaround and distinguishes an unknown list from a genuinely empty one. No invitation was opened or sent.

## Cause and bounded repair

`dashboard/src/features/ledger-data/settings/collaborators-section/index.tsx:50–62` obtains data/loading/error from ListLedgerCollaborators but drops its refetch callback. Its error branch at199–209 renders only an icon, heading and error text. The Settings page's GetLedger QueryView retry belongs to another observer and cannot recover this independently mounted list.

Wire the card to its own existing Apollo observer and reuse the established in-place retry lifecycle: native keyboard activation, a retained busy error with one pending attempt, handled rejection with focus returned to the retry action, and truthful empty/populated content after success. Keep the current ledger scope, admin gate, healthy sibling sections, member table naming, plan-limit handling and mutation controls. Leaving Settings during a retry must not steal focus or restore old content. Avoid reloads, a global retry loop, new dependencies or backend/API changes. Do not invite, remove or leave membership as a recovery workaround.

Acceptance: meaningful real-Apollo coverage of failure → pending → rejected → successful retry with unchanged ledger variables, a single active read, failure focus and no mutations. Verify both widths and the real empty/member branches; run dashboard format:check, lint, test and build. A populated live membership fixture, GraphQL error envelope, other locales/engines, actual screen-reader speech and repaired behavior remain unverified here.

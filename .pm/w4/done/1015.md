# Keep source digits and exact text in the rest of Overview's amounts

**Severity:** minor financial display. **Estimate:** 45–60 minutes. **Owner:** dashboard. **A2:** Overview amounts should read as the ledger records them, as the Net Worth headline, table and change now do.

Follow-up from the [m52](./m52/README.md) `/simplify` review (reuse, simplification and altitude reviews, 2026-10-22). m52 made `formatNumber` format decimal strings exactly and gave Overview's `CurrencyAmount` the ledger's decimal (`exact`). Source-only findings, not yet reproduced in a browser:

- **Commodity source digits.** `FormattedAmounts` (`features/reports/overview/components/formatted-amounts.tsx`) and the Net Worth change call `formatNumber(value, currency)` without `fractionDigitsOf(source)`, contrary to the dashboard AGENTS.md rule. A non-ISO commodity therefore keeps at most three digits: `4.00995` ETH shows as `4.01`, and `0.0001` BTC shows as `0`. The source decimal is now at hand (`amount.exact`), so the fix is one argument per site. It changes commodity output in four Overview cards (Net Worth, Account balances, Money movement, Recent activity), so verify each.
- **Other Net Worth card text still built from doubles:**
  - the chart tooltip, `formatNumber(Number(value))`;
  - the valuation note's cost basis and unrealized gain (from `net-worth-valuation.ts`). A +1 unrealized gain on a 2^53 cost basis also hides that line through `showCostBasis`;
  - holdings units, whose digits come from `fractionDigitsOf(String(number))`.

Coordinate with [1001](./1001.md) (LineChart text values), which can use the same string-capable formatter. String inputs are capped at 20 fraction digits there.

Acceptance:
- Overview amounts with a source decimal keep its digits (non-ISO commodities) and its exact value.
- ISO currencies keep their minor units.
- Rendered regressions per changed card fail on the old code.
- Native 1440/390 checks and dashboard gates pass.

---

**Resolved 2026-10-22** — Every site this note names now formats the ledger's decimal. `FormattedAmounts` (Net Worth, Account balances, Money movement, Recent activity) and the Net Worth change pass `fractionDigitsOf(source)`. The Net Worth chart tooltip moved to a per-series `valueFormatter` that formats each point's own decimal in its currency. `describeNetWorthValuation` also returns optional `unitsExact`, `costBasisExact` and `unrealizedExact` (exact `sumDecimalNumbers`); the card displays them and decides `showCostBasis` from the exact difference. ISO currencies keep their minor units. The native check used a local fixture app whose SSR and client reads served a modeled Overview: the last two market points became 9007199254740992 → 9007199254740993 USD, ETH 1.5 → 4.00995 and BTC 0.0001, with matching units and at-cost figures. The valuation line read **Cost basis 9,007,199,254,740,992.00 USD · Unrealized +1.00 USD** (hidden before as a 0 double gain). The holdings popover showed **0.00000001234567890123 BTC**, and native hover on the point plotted at 9007199254740992 read **USD 9,007,199,254,740,993.00**. No mutations, no page errors.

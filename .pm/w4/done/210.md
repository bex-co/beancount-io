# Show a recoverable error when Monaco initialization fails

Severity: **minor**, dashboard. Estimate: **45–60 minutes**. A2/A3 — readers should see a failed editor initialization and a usable recovery action instead of waiting on a terminal failure.

## Reproduce

Production `https://beancount.io`, 2026-10-09, dedicated QA login, public synthetic `open_ledger/example`, English, QA-owned isolated headless Chromium 149.0.7827.55. Fresh 1440×1000 and 390×844 contexts. Source rechecked on main **445bc0c7**; the pull introduced no dashboard changes. Exact deployed SHA is unverified.

1. Open `/ledger/open_ledger/example/files/blob/main/README.md?editMode=false&lang=en` in a fresh context. Intercept only the Monaco bootstrap script, currently `https://cdn.jsdelivr.net/npm/monaco-editor@0.55.1/min/vs/loader.js`, and fulfill that request with HTTP 503. Leave document, application assets and API responses untouched. This is a controlled asset-failure simulation, not a claim of a production CDN outage.
2. The real `GetLedgerFile` succeeds HTTP 200 with file data. The viewer shows the README filename and 1.91 KB metadata. Console records the 503 and **“Monaco initialization: error: Event”**, establishing a rejected initialization rather than a still-pending file read.
3. At two seconds and again eight seconds later, the viewer still says **Loading...**, with zero editor textboxes, zero visible alert elements and no Retry / Try again / Reload button. Both fresh widths reproduce. The narrow screenshot was visually inspected.
4. Remove the interception and reload the same URL. Both widths recover a visible editor with `aria-readonly=true` and no Loading placeholder; the genuine file read again succeeds HTTP 200.

An additional fresh 390px BQL context at `/ledger/open_ledger/example/query?query=SELECT%20date%20LIMIT%202&lang=en` reproduces the same terminal placeholder under the same asset-only failure. Its real `QueryShell` succeeds HTTP 200 and shows both returned date rows while the editor is unavailable. Removing the guard and reloading restores the editable textbox (`aria-readonly=false`) and removes the placeholder. No query result, file content, credential or ledger mutation was fabricated or changed.

## Cause and bounded repair

`dashboard/src/common/components/monaco-editor/index.tsx` wraps `@monaco-editor/react` in `ClientOnly` and delegates editor initialization without a failure state or recovery action. The installed upstream editor's initialization catch only logs the error; its ready state remains false, so its loading UI stays mounted. The installed loader assigns the script's `onerror` to promise rejection and keeps its initialized flag and shared promise. Remounting an editor alone is therefore not a demonstrated recovery mechanism.

Handle terminal initialization failure in the existing shared wrapper, replace the pending placeholder with a localized accessible error, and provide an explicit recovery action that actually works. A supported reinitialization or deliberate user-triggered document reload is suitable; verify the loader's cached rejection rather than presenting a Retry button that repeats it. Ignore ordinary disposal cancellation. Preserve the current URL, supplied content, read-only DOM semantics, normal mount callbacks, and healthy independent file/query results. Do not automatically reload, change dependencies, vendor the editor, change APIs or rewrite callers into separate editor implementations. New-file authoring and writable drafts were not exercised.

Acceptance: a terminal bootstrap failure with a healthy file read shows an editor error rather than ongoing loading at desktop and narrow widths; its actual recovery action restores the same read-only file. The BQL consumer retains successful result rows and recovers its editor. Healthy initialization and normal unmount cancellation remain passing controls. Add meaningful wrapper/consumer coverage driving a rejected initialization promise and the recovery action, then repeat the browser asset-failure check and run dashboard gates when implementing.

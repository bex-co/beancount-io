# Statistics and Settings sections are copy-pasted shells

Found while reviewing w4/m20 and verified by reading the code at `216351bd`.
Pre-existing duplication that m20 only added one line to, so it was filed
rather than folded into that milestone.

## Statistics — the same section shell six times

`dashboard/src/features/ledger-data/statistics/{postings-per-account,
account-last-entries,entries-count-by-type}.tsx` each render the shell twice,
once in their loading state and once with data:

- `<h3 className="flex items-center gap-2 text-lg font-semibold mb-2">` plus an
  icon and the localized title,
- a `<p className="text-sm text-muted-foreground mb-4">` description,
- the `overflow-hidden w-full` / `overflow-x-auto` wrapper pair around the
  table.

Compare `postings-per-account.tsx:34-48` with `:147-162`.

A feature-level `StatisticsSection({ icon, title, description, children })` in
`statistics/` would collapse all six and mint the heading id once, so the
naming contract m20 added would hold by construction rather than by six
correct copies. Keep it inside `statistics/` — m20 deliberately ruled out a
generic table-naming framework, and this is a layout shell, not that.

## Settings — two near-clone option sections

`dashboard/src/features/ledger-data/settings/beancount-options-section/index.tsx`
and `fava-options-section/index.tsx` are near-identical: same imports, same
JSX apart from title, description, documentation URL and the entries they map.
Their `formatValue` helpers differ by a single `typeof value === "object"`
branch. Every change to either card has to be made twice, and m20's naming
association is now the fourth such thing.

An `OptionsTableSection({ title, description, docUrl, entries })` in
`settings/` would own the `useId` once as a by-product. Check first whether the
`formatValue` difference is deliberate — if it is, it should be a prop, not a
reason to keep two files.

## Why it matters beyond tidiness

m20 gave seven tables accessible names, and `ledger-data/AGENTS.md` records the
rule. Collapsing these shells would make the rule structural instead of
something the next author has to read and remember.

**Resolved 2026-09-20** — Both halves done, and both kept inside their own feature as the note asks. `statistics/statistics-section.tsx` owns the heading, the description and the scroll wrappers, and goes one step further than the note proposed: it renders the `Table` itself and puts the heading id on it, so a section cannot put a table on the page without naming it — the m20 rule is now structural rather than six correct copies. All six shells across `postings-per-account`, `account-last-entries` and `entries-count-by-type` are gone; `useId` and the `Table` import went with them. `settings/options-table-section.tsx` owns the card, the documentation link and the option rows, minting the title id once; the two callers are reduced to an entry list each, from 231 lines to 112. The `formatValue` question was checked rather than assumed: the only difference was fava's `typeof value === "object"` branch, and it is not deliberate protection — without it an object renders as `[object Object]`, so the shared helper keeps the branch as a superset of what a scalar-only list needs, and no caller loses anything. Verified in the browser on the Statistics page: all three tables render with their accessible names ("Postings per Account", "Account Last Entries", "Entries Count by Type") and their real row counts (48, 15, 12), so the naming survived the move intact. The settings cards need an authenticated ledger and were not exercised live; they are covered by the existing suite, which passes unchanged. One process note: a first mechanical rewrite of the statistics shells re-indented the captured table bodies and corrupted a nested `params={{…}}`, so it was reverted in full and redone leaving the bodies verbatim for prettier to format — worth knowing for anyone doing the same kind of sweep. Dashboard gates all pass (`yarn format:check`, `yarn lint`, `yarn test` — 424 files, 4768 passed, 1 pre-existing skip — and `yarn build`). Shipped in `5f909d39` (`dashboard`).

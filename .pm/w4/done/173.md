# One-shot BQL tables still execute control sequences from existing ledger text

Severity: **minor**. Package: **cli**. Estimate: **40–55m** for the reproduced
one-shot text-rendering path and PTY regression. Source: continuous CLI QA for
w4. **A1/A2:** query results from existing books should be readable literal text,
consistent with the now-sanitized directive list. No code execution is claimed.

Environment: 2026-09-21, main `390568c220bfbdb0df1c9decb8436c64dfa3c9ca`,
checkout `cli/.venv/bin/bea` 0.3.0, Python 3.13.3, Darwin arm64. Synthetic
fixtures and all outputs stayed beneath `cli/tmp/qa-20260921-cli-loop/`.
Fresh processes used child-only config/cache/data directories there,
`BEA_NO_UPDATE_NOTIFIER=1`, no inherited BEA_FILE/BEA_TOKEN, and bounded
25-second captures. No hosted account, live price fetch, or real ledger.

## Reproducer and observed result

Create this minimal synthetic ledger with Python so the controls are actual bytes:

```python
from pathlib import Path
Path("main.bean").write_text(
    '2024-01-01 open Assets:Cash USD\n'
    '2024-01-01 open Expenses:Food USD\n'
    '2024-03-01 * "FAKE\x1b[2J\x1b[HCONTROL"\n'
    '  Expenses:Food 1 USD\n'
    '  Assets:Cash\n'
)
```

`bea --json --file /absolute/main.bean check` passes. With stdout connected
to a real PTY, run:

```sh
bea --file /absolute/main.bean query 'SELECT narration'
```

Exit 0 and empty stderr. Captured stdout contains this byte sequence twice
(one result per posting): `FAKE\x1b[2J\x1b[HCONTROL`. There are four raw ESC
bytes. The sequences are terminal clear-screen and cursor-home controls, not
visible literal text. Repeated with two pristine larger fixtures and the exact
minimal fixture above. Stdin was DEVNULL and the query was supplied explicitly,
so no interactive shell/history was opened. Source hashes remain unchanged.

Working controls under the same PTY: `list transaction` and `list transaction
--details` emit zero raw ESC bytes and show visible escaped text. JSON query
output contains JSON-escaped controls, parses correctly and preserves the value.
Piping human query stdout instead of using a PTY hides the problem: Click strips
these CSI sequences and prints `FAKECONTROL`; this is why a pipe-only regression
would be insufficient.

Expected: unsafe controls in displayed BQL string cells are rendered visibly,
without executing terminal commands. Preserve table structure, the underlying
ledger value, and JSON/machine-export fidelity. This is a display-boundary fix,
not an instruction to rewrite existing ledger data or flatten every table newline.

## Cause and repair

`cli/src/bea_engine/query.py:343–357` renders SELECT rows through upstream
`FORMATS`, preserving the string controls. `cli/src/cli/commands/query.py:246–249`
then sends the rendered text directly to `typer.echo`; it bypasses
`cli.output.table` and its `single_line` cell sanitizer. Click strips CSI for a
pipe but preserves it for a terminal. The recent write/list sanitization therefore
does not cover BQL reads of pre-existing files.

Apply safe literal string rendering on the reproduced terminal text path while
preserving numeric precision and table structure. Keep JSON/raw export data
separate from display escaping. Caller search traces `query` to the engine's
shared precise SELECT renderer; the interactive shell and Ask share parts of
that renderer but were not exercised and are not claimed as reproduced here.
If the shared renderer is changed, verify those consumers' formatting contracts.

- [ ] The exact one-shot PTY query emits no raw controls from its narration;
      the anomalous bytes remain visibly represented and the table stays readable.
- [ ] Ordinary text, decimal precision and list/detail controls remain correct;
      JSON still preserves the original value, and the source is byte-identical.
- [ ] Add a real PTY regression and a machine-output control; run CLI gates.

Dedupe: searched all .pm markdown and open milestones for BQL/query terminal
controls and escapes. Completed w3/392 (`ada8bb97`) fixes import/add persistence
and `output.table`; its full chain and acceptance were reviewed and its list
controls pass here. This is the uncovered BQL consumer of existing ledger text,
not a claim that the repaired import still writes escapes. Current query history
(`2860c09b`, `0e04c47b`) retains direct echo; no open duplicate.

Verified captures: `captures/cycle6-pty-*-query-*.json`, matching list/detail
controls, `cycle6-terminal-minimal-*.json`, and pipe controls from cycle5 under
the run directory. Exact PTY setup is in `pty_stdout.py`. Unverified: interactive
shell (hardcoded upstream history cannot be isolated through BEA_CONFIG_DIR),
Windows, OSC variants and hosted clients. No live data, product fixes or shipping.

**Resolved 2026-09-23** — Text-format BQL SELECT results (one-shot and the shell's shared renderer) now escape control characters in string cells, and in set/tuple cells, to a visible `\xNN` before beanquery renders them. A real-PTY regression in `cli/tests/test_control_character_sanitization.py` runs the note's narration and asserts no raw ESC, the visible escape, `1.2345` precision, and unchanged source bytes; it fails without the fix.

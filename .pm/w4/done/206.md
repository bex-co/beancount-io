# Pull-request review offers merge and close to a read-only reader

**Severity:** minor. **Owner:** dashboard. **Estimate:** 30–45m. **Evidence scope:** browser-only simulated open request on the running dashboard; no existing open production request was available and no review mutation was attempted.

2026-10-08, production `https://beancount.io`, QA-owned isolated headless Chromium 149, English/System, fresh 1440×1000 and 390×844 repeats. Source HEAD `c4b401fd`; production module `main-GcCTaQbi.js`, deployed SHA unverified. Root `.env` supplied the dedicated QA login; no credential values are recorded. The real public `open_ledger/crypto-example` metadata returns HTTP200 with `permissions: {admin:false,pull:true,push:false}`.

1. In the authenticated reader context, intercept only the browser's `GetPullRequestDetails` response for `/ledger/open_ledger/crypto-example/pull/1`. Return a schema-shaped **simulation**: number 1, state `open`, title `QA simulated open request`, author `qa-synthetic-contributor`, head `qa-browser-only`, base `main`, and one synthetic file/diff. 2. Wait for the review page to settle. Observe **Approve & Merge** and **Reject & Close**; focus each with the keyboard without activating either.
3. Repeat from fresh navigation at both widths. Each response is intercepted once. Both buttons are enabled and focusable at both widths, with no new console errors. A second fresh run repeats this result.
4. Working control: repeat with the same simulated response's state changed to `closed`. Both action buttons disappear at both widths while the review metadata remains readable.

Expected: readers can inspect the metadata, changed files and diff, but cannot activate write-only review actions. Actual: an open request exposes both write actions solely because it is open. This is a misleading permission affordance, not a demonstrated backend authorization bypass.

Fixture limit: real `getPullRequestDetails(...,prNumber:1)` reads on example, crypto-example, stock-example, freelancer-invoicing and real-estate-example all return HTTP200/`NOT_FOUND`. No live open-request or successful writer-review behavior is claimed. No approve/reject, request creation, clipboard operation or ledger write occurred.

## Cause and bounded repair

`dashboard/src/features/git/pull-requests/pages/pr-review-page.tsx:123` mounts PRActions unconditionally after a successful read. `components/pr-actions.tsx:22` checks only `state !== "open"`; its disabled conditions at31/36 cover pending mutations, not permissions. PRActions has one production caller, this review page. The existing `common/components/ledger-permission/write.tsx` already hides children unless `useLedgerPermission().canWrite` is true (`push === true || admin`).

Wrap the review actions with that existing write-permission gate, retaining reader access to PRMetadata, PRFileList and DiffViewer. Preserve open-writer pending states and the closed/merged action omission. Do not use an admin-only gate: ordinary writers are eligible. Add a meaningful rendered review-page regression using the real action component and permission wrapper: open reader has no review buttons, open writer retains both, closed/merged omit both. Current page tests mock PRActions, so they do not establish its permission boundary. Run dashboard gates when implementing.

The policy is explicit in `backend-cluster/backend-v2/src/server/api/authorization/authorization-service.ts:382–395`: both pull-request approve and reject require `WRITE_CONTENTS`; read uses a content-read requirement at359. The service authorizes before merge/close at `features/gitea/pull-request/service/pull-request-service.ts:430/455`. Preserve these REST/GraphQL/MCP checks; this repair changes only dashboard rendering and requires no API, dependency or cross-package import.

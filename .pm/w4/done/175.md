# CSV diagnostics count records as physical lines after a quoted multiline field

Severity: **minor**. Package: **cli**. Estimate: **30–45m**. Source: continuous
CLI QA for w4. **A1/A2:** the line number offered for correcting a bad bank cell
must identify that line in the source file.

Environment: 2026-09-21, main `390568c220bfbdb0df1c9decb8436c64dfa3c9ca`,
checkout `cli/.venv/bin/bea` 0.3.0, Python 3.13.3, Darwin arm64. Fresh
subprocesses ran with closed stdin and 25-second limits under
`cli/tmp/qa-20260921-cli-loop/`; child-only config/cache/data paths were isolated,
update notices disabled, BEA_FILE/BEA_TOKEN removed. All inputs were synthetic.

## Reproducer and result

`main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Food USD
```

`bank.csv` has four physical lines:

```csv
Date,Description,Amount
2024-03-01,"Multi
line",-1
2024-03-02,Second,oops
```

Substitute absolute paths and run:

```sh
bea --json --file main.bean import bank.csv --csv auto   --account Assets:Cash --default-account Expenses:Food
```

Exit 2; stdout empty. The error says `Row 2 (line 3): cannot parse amount 'oops'
in column 'Amount'`. The bad cell is on **line 4**, not line 3; the data-row
ordinal 2 is correct. Human mode gives the same incorrect locator. No ledger
bytes change. Repeated on two fresh fixtures and the exact minimal fixture above.

Working control: replace the first description with the one-line `One line`.
The bad row then actually occupies line 3 and the same diagnostic is correct.
Expected: retain row 2 but report physical line 4 for the multiline case, as
`docs/IMPORTING.md` explicitly defines the parenthesized line for hand-editing.

## Cause and repair

`cli/src/bea_engine/csv_mapper.py:542–545` converts `csv.reader` records to
plain dictionaries and drops `reader.line_num`. `CsvImporter.extract:705–707`
later reconstructs a purported physical line as `index + 2`, which counts
records and fails after a record spans multiple lines. `_at:125–140` labels it
as a physical line. The resulting line also supplies imported entry metadata.

Carry actual physical record positions from the CSV reader into extraction,
separately from the nonblank preview row ordinal. Preserve skipped-row behavior
and report the start line of the offending record consistently. All amount,
date and currency cell diagnostics using `_at` share this path; preview/apply
and CSV mapping modes share `CsvImporter`. The frontend reader twin also has
consumers for inference/header reads, so preserve their interface deliberately.

- [ ] The exact fixture reports Row 2, line 4, and writes nothing.
- [ ] One-line, quoted multiline, blank-row and multiline-header controls retain
      correct independent row ordinals and physical positions.
- [ ] Add a regression using actual CSV source lines as the oracle, and run CLI gates.

Dedupe: searched all queues, done/blocked records and open milestones for
multiline CSV line diagnostics. Completed w3/385 (`ca081da7`) fixes row ordinals
and explicitly leaves multiline physical lines unverified; its full resolution
and DoD were read. Its one-line/blank-row controls still pass. This filing turns
that carried-forward uncertainty into a reproduced residual bug; no open overlap.

Verified evidence: `captures/cycle8-*-physical-line-*.json`,
`cycle8-minimal-line-*.json`, and corresponding CSV/ledger fixtures under the
run directory, with exact argv, streams and before/after hashes. Unverified:
other encodings and operating systems. No product changes, credentials or shipping.

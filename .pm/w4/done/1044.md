# Retry the first Entry Context read without dismissing its dialog

**Severity:** minor follow-up to [M50](./done/m50/README.md)'s read-recovery contract. **Estimate:** 35–50 minutes, dashboard. **A2:** a reader should be able to recover an entry's source/context from its displayed error while keeping the selected entry open.

## Reproduction and controls

Production `https://beancount.io`, October23 local / October24 UTC2026; anonymous public `open_ledger/example`, isolated headless Chromium156.0.8078.47, English/UTC/light, fresh1440×1000 and390×844 contexts. Only the first browser GetLedgerEntryContext is aborted; no actual service outage or response fixture is claimed.

1. Open `/ledger/open_ledger/example/journal?lang=en&time=2016-04-19`. There are five transaction rows. Focus **Open entry 2016-04-19 Starbucks (row 2)** and press Enter.
2. Abort that entry's first GetLedgerEntryContext (`ledgerId:open_ledger/example,entryHash:<the-selected-hash>`). The dialog settles to **Connection problem. Please check your internet connection and try again.** with **zero Try Again/Retry buttons**. Both widths reproduce. Retained screenshots wait for opening animations to finish and record dialog opacity1.
3. Remove the fault and press Escape. The original Starbucks row regains focus; the same date scope and five journal rows remain.
4. Press Enter on that same row. A genuine HTTP200 context read with the **same variables/hash**, no GraphQL errors, returns the selected2016-04-19 Starbucks entry. The context displays **Open source at main.bean:1913**, with no error. No full-document reload or source navigation was used.
5. Escape again returns focus to the same row and preserves all five entries and the unchanged Journal URL at both widths.

Independent Beancount control identifies that authored Starbucks directive at line1913. The recovered backend context's after−before balances equal its exact source postings: **+5.23USD** in Expenses:Food:Coffee and **−5.23USD** in Liabilities:US:Chase:Slate. The service can return the correct entry; the missing piece is an in-place recovery action. No accounting error is claimed.

Close/reopen is a verified workaround. No Save, Delete, Copy, AI action or hosted write was activated. Each retained case has one local aborted context request followed by one successful genuine context read, zero attempted mutations, route errors or page exceptions.

## Cause and bounded repair

`dashboard/src/features/journal/components/entry-context-panel.tsx:113–120` implements EntryContextError as only Alert/AlertDescription. The panel already owns GetLedgerEntryContext's **refetch** at:549–558 with entryHash/ledgerId and its existing skip conditions. At:644–648 a first read replaces the body with loading/error content; the error receives no retry callback.

Use the existing scoped query-retry lifecycle for this initial no-data failure. Retain the error view with a focusable busy Try Again during a retry, send one request for the current entryHash/ledgerId, and return focus to that action after another rejection. Render the retained first-read failure before the ordinary no-data loading branch, since Apollo clears error while refetching. Success restores the selected source/context without dismissing and reopening its owner or reloading the Journal.

Preserve [979](./done/979.md)'s cached-data/draft path: an already shown context/editor stays mounted during refresh, and its existing refresh-failure toast/refetch remains usable. Keep dirty source text/edit-base identity, stale-source handling, read-only/managed/generated-source behavior, generated opening/conversion presentation and Save/Delete's pending-write lifetime from [M49](./done/m49/README.md). Keep Close/Escape available during a **read** retry; the existing write lock must remain confined to the write lifecycle. Dismissing or moving to another entry while a retry is pending must not reopen the old dialog or steal focus after completion. No API, backend, dependency or permission-policy change is needed.

Acceptance: real panel/query integration covers cold read failure → held keyboard retry with error/action retained busy → repeated rejection and focus handback → successful context, with exact query variables and repeat-activation protection. Exercise dismissal/another entry while pending and preserve generated/no-read and already-loaded dirty-editor controls. Repeat the native close/reopen/focus control at both widths and run dashboard gates. These pending-retry cases are implementation regression scope: there is currently no initial action to activate live.

**Resolved 2026-10-23** — `EntryContextPanel` (`journal/components/entry-context-panel.tsx`) now passes its first-read `GetLedgerEntryContext` error and `refetch` to `useQueryRetry` and renders the retained failure before the no-data loading view. `EntryContextError` shows the localized error with a Try Again, busy while the retry runs, so a second press sends nothing. Another failure returns focus to Try Again. Success shows the selected entry inside the same open dialog.

A refresh over shown data keeps 979's toast path, and the editor, drafts and write lifecycle (M49) are untouched. Close/Escape stays available during a read retry. A dialog dismissed, or switched to another entry, during a retry never shows the old failure or takes focus; the panel remounts per entry.

`entry-context-first-read-retry.test.tsx` runs the real dialog, panel and Apollo observer. It covers:
- a cold failure, then a keyboard retry with a busy error and action, where a second Enter sends nothing;
- another failure that keeps focus;
- the source shown, with every read `{entryHash, ledgerId}` unchanged;
- Escape during a retry: the dialog stays closed with focus on the entry opener;
- another entry during a retry: entry-b is read and shown, not the old failure.

All three fail on the old panel.

Native check on the built repaired client (local fixture SSR, public example ledger, genuine recorded reads), at 1440×1000 and 390×844, on `/journal?time=2016-04-19` with keyboard Enter on "Open entry 2016-04-19 Starbucks (row 2)" and the first context read aborted:

Zero mutations or page errors, and no horizontal scroll. Dashboard gates pass.

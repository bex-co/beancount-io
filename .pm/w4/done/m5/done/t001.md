## Objective

Make backend-v2 serve `/.well-known/apple-app-site-association` and `/.well-known/assetlinks.json` so `beancount.io` (and any self-hosted domain) can vouch for the native app. Values come from environment variables with documented Beancount.io defaults so the repo stays deployment-neutral.

## Context

- `backend-cluster/backend-v2/src/features/well-known/api/well-known-route.ts` already serves `security.txt`; add the two files beside it.
- AASA needs `Content-Type: application/json`, the `applinks` details for `<TEAMID>.io.beancount.ios` and the `/ledger/*` path pattern; assetlinks needs `io.beancount.android` and the Play App Signing SHA-256 fingerprint.
- The Team ID and fingerprint are public by definition (this URL publishes them) but still come from env: `APP_LINKS_APPLE_TEAM_ID`, `APP_LINKS_ANDROID_SHA256` (comma-separated). Unset → 404 so a self-host without a native build serves nothing misleading.
- The docker deploy proxies `/.well-known/*` to backend-v2 (see `deploy/docker/docker-compose.yml`).

## Steps

1. Add the two GET handlers to the well-known route with the env-driven config.
2. Add REST tests for the JSON shape, content type, and the unset-env 404.
3. Document the variables in `backend-cluster/backend-v2/README.md` and the deploy `.env.example` files.
4. Verify on `deploy/docker-mac` that both URLs answer through the dashboard host.

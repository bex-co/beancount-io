## Objective

Give the native app the entitlement and intent filters it needs to claim `https://beancount.io/ledger/*` links.

## Context

- `mobile/app.json` currently has no `ios.associatedDomains` and no `android.intentFilters`; the schemes `beancount`, `io.beancount.ios`, and `io.beancount.android` stay for the OAuth callback and deep links.
- The entitlement only takes effect in a native build, so it ships with the next store release; the development client must be rebuilt for simulator verification.

## Steps

1. Add `ios.associatedDomains: ["applinks:beancount.io"]` and an `android.intentFilters` entry with `autoVerify: true` for `https` `beancount.io` path prefix `/ledger`.
2. Run `npx expo prebuild --no-install --platform ios` into a scratch directory and confirm the entitlement and manifest output, then discard it.
3. Rebuild the development client (`SENTRY_DISABLE_AUTO_UPLOAD=true npx expo run:ios`).

## Files

- mobile/app.json

## Acceptance criteria

- [ ] Prebuild output contains the associated-domains entitlement and the auto-verified intent filter.
- [ ] `yarn format:check` passes; the OAuth callback still completes on the rebuilt client.

## Out of scope

- Self-hosted domains: the app can only claim domains listed at build time; document that custom-scheme links still work everywhere.

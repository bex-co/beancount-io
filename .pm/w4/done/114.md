# Do not date a filtered statement as though its relative time filter were absent

Severity: major. Estimate: 60 minutes for the truthful unresolved-period fallback described below. Package: dashboard. A3: exported financial statements must not claim a period their numbers do not cover.

Environment: production beancount.io, public `open_ledger/apple`, signed out, English/light, isolated headless Chromium149.0.7827.55, fresh390×844 and1440×1000. Root: `dashboard/src/features/reports/export/reporting-period.ts:239–271` treats a null parseConcreteTimeFilter result as an absent selection. The concrete parser intentionally does not resolve relative tokens. Consequently a nonempty, backend-accepted year-1 falls through to implicitThroughDate and the generation day, with inferredStartDate from the chart buckets. Backend `ledger/src/foundation/rustledger/directive-filter.ts:1050–1068` substitutes year-1 before parsing; the producer returns correctly filtered2025 data. Export model.ts278 forwards the raw time filter but has no authoritative resolved-bound fields in this report response. Markdown, CSV, print and filenames all consume the wrong common reportingPeriod.

Scoped fix: distinguish an empty time filter from a nonempty selection whose exact bounds the export cannot resolve. Apply the existing generation-day/future-bucket policy only to genuinely unfiltered statements. For an unresolved selected filter, leave start/end/as-of dates unknown, retain the exact raw selection, use the existing unavailable-date/internal-draft notices and period-unresolved filename fallback, and expose that raw time selection in Markdown/print scope as CSV already does. Reuse an appropriate existing localized Time label where possible. Do not claim all available activity or manufacture bounds from partial chart buckets. If a later implementation supplies authoritative resolved bounds, year-1 here must resolve toJanuary1–December31,2025; this note does not require a second relative-date parser or backend/schema expansion. Preserve report numbers, units and filters.

**Resolved 2026-09-19** — Reproduced against a local build: exporting the
public Apple income statement at `?time=year-1` produced "For the period
January 1, 2025 – September 17, 2026" above numbers covering 2025, with the
CSV carrying the same invented bounds and the filename repeating them. The
Balance Sheet said "As of September 17, 2026". Only the labelling was wrong —
the explicit `?time=2025` export returns byte-identical numbers.

`reporting-period.ts` treated a null `parseConcreteTimeFilter` result as an
absent selection, so a non-empty relative token the backend had already
resolved fell through to `implicitThroughDate` and the generation day. A
non-empty selection whose bounds the export cannot resolve is now distinguished
from no selection at all: its start, end and as-of dates stay unknown and the
raw selection is kept. The existing machinery then tells the truth without new
wording — the heading reads "Reporting date unavailable", the statement is
marked an internal draft, the CSV's `period_start`/`period_end` are empty while
`time_selection` still reads `year-1`, and the filename falls back to
`period-unresolved`. Markdown and print now also list the raw selection in the
scope block under the existing localized Time label, which the CSV has always
carried.

The genuinely unfiltered path is untouched, so `w1/022`'s guarantees hold, and
no second relative-date parser, backend or schema change was introduced. If
authoritative resolved bounds ever arrive, `year-1` would resolve to
2025-01-01 – 2025-12-31 through the same code.

Verified in a real browser, 7/7: the Apple income statement, balance sheet and
cash flow all export unresolved dates with `**Time:** year-1` stated, at 1440px
and 390px, with `period-unresolved` filenames and empty CSV bounds; an explicit
`?time=2025` still exports January 1 – December 31, 2025 with a
`2025-01-01-to-2025-12-31` filename; and an unfiltered export still runs
through today.

Nine regression cases cover four unresolved forms (`year-1`, `quarter-1`,
`month-2` and an open-ended range), all three statement kinds through the
shared resolver, the Markdown heading, notice and scope line, the CSV columns,
the explicit control and the empty-filter control; five fail without this
change. Gates from `dashboard/`: `yarn format:check`, `yarn lint`, `yarn test`
(400 files, 4493 passed, 1 pre-existing skip) and `yarn build` all pass. Native
print/PDF tagging, other relative tokens, cross-year timezone boundaries and
custom fiscal calendars remain unverified. Shipped in `b25aee1b` (`dashboard`).

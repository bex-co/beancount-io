# Gallery scrolling rolls keyboard selection back under a stationary pointer

**Severity:** minor. **Owner:** dashboard. **Estimate:** 35–50m. A2/A3: exploring searchable shared ledgers should not discard keyboard navigation steps when the pointer happens to rest over the results.

Production `https://beancount.io/ledger-gallery`, 2026-10-08, dedicated QA login from the root `.env`, English/System, QA-owned isolated headless Chromium 149. Fresh 1440×1000 and 390×844 reproductions. Source `05f8c2d8`, rechecked after pulling `b4ed6bfa` (only an unrelated w2 board note changed); deployed SHA unverified. No ledger writes occurred. Search result identifiers belonging to other accounts are excluded from this record.

## Reproduce

1. Search **in**, wait for the results to settle, and keep keyboard focus in the search combobox. QA observed 15 results, enough to scroll inside the 300px-high listbox.
2. Move the pointer over the fourth option (`ledger-search-option-3`). Do not move it again. The active descendant is option3.
3. Press ArrowDown, wait 600ms: active descendant becomes option4.
4. Press ArrowDown again, wait 600ms: active descendant is **option4 again**, rather than option5. Input focus remains in the combobox.
5. Continue to six total ArrowDown presses, waiting 600ms after each. At both widths the settled active indices are **3 → 4 → 4 → 5 → 5 → 6 → 6**, instead of 3 → 4 → 5 → 6 → 7 → 8 → 9.

Expected: each ArrowDown advances one option until the final boundary; the selected option scrolls into view without another input changing selection. Actual: scrolling beneath an unmoving pointer fires option-entry events that overwrite keyboard selection. This is lost navigation steps, not a permanently unreachable option or an incorrect Enter handler.

A separate fresh desktop repeat recorded native event ordering after the initial hover: mouseover/mousemove on option3 at **(720,629)**, followed by mouseover on option3 and then option4 at the **same coordinates**, with **no subsequent mousemove**. Two ArrowDown presses leave option4 selected, focus still in the input, with zero new console errors. This directly corroborates scrolling-induced hover rather than an extra pointer action.

Working controls: moving the pointer outside the popup makes the next ArrowDown advance normally (6 → 7). Fresh keyboard navigation with the pointer outside the popup reaches option14, which is selected and fully inside the listbox after the animation settles at both widths. Enter opens the public `open_ledger/thor-industries` ledger. Back returns to the intentionally cleared gallery input with no stale options.

An earlier 150ms scroll measurement found the final option outside the popup during its smooth animation; the later settled control disproves that as a separate visibility bug. Initial automation timing/index assumptions were corrected before retaining the stationary-pointer reproduction. No pagination defect or 50-result coverage is claimed.

## Cause and bounded repair

`dashboard/src/features/ledger-list/pages/gallery-page/index.tsx:137–144` advances the highlight for arrow keys. Its effect at174–180 scrolls the selected option into view. The option handler at318 unconditionally calls `setHighlightedIndex(index)` on **onMouseEnter**, including browser entry events caused by that scroll moving a different option beneath the stationary pointer. Keyboard and incidental hover race over the same state.

Update pointer-based selection from genuine pointer movement, rather than every entry event caused by programmatic scrolling. Keep this local to the existing Gallery options; preserve intentional pointer hover, click selection, arrow boundaries, aria-activedescendant/aria-selected, scrolling, Escape/Clear, current-query result eligibility and navigation. Do not merely lengthen a timeout, remove hover support, or change global menu behavior. A real browser regression should park the pointer on an option, scroll with two or more arrow presses and wait for settlement, then assert the expected active index; a mocked mouseEnter callback alone misses the cause. Include the pointer-away and actual pointer-movement controls. Run dashboard gates when implementing; no API, dependency or cross-package change is needed.

This handler has one production page, `/ledger-gallery`; no other picker or touch behavior was independently reproduced. All board states were searched for Gallery hover/pointer, keyboard selection rollback and scroll/mouse-enter interaction; no overlapping repair. Completed w3/163 concerns Escape focus, w4/113 concerns another combobox's highlight/selection semantics, and w4/097 concerns sidebar touch hover. Recent Gallery changes `86ca4531`, `620c7b0a`, `e4ba513d` retain the handler; targeted history has no newer movement guard. This is not an already-fixed deployment lag.

Ignored evidence under `dashboard/tmp/qa-20261008-loop/`: `gallery-hover-keyboard-scroll-repro.js` (fresh desktop/narrow traces), `gallery-hover-scroll-events-repro.js` (fresh native event ordering), `gallery-last-option-settled-scroll-control.js`, and verified `gallery-hover-rollback-option4.png`. The screenshot is cropped to a verified public result and was visually inspected. Event listeners were removed and the owned headless pointer moved outside the popup. Other engines, assistive-technology speech, physical touch and patched behavior remain unverified.

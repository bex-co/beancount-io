# Give the Settings language picker a localized accessible name

**Minor · 25–40m · dashboard · A2.** Users navigating controls through accessibility metadata should be able to identify the language setting independently of its selected value.

Reproduced on production `https://beancount.io/settings/general?lang=en`, October 9, 2026, authenticated QA reader, isolated headless Chromium 149 at 390×1000 and 1440×1000. Research HEAD `722792f8`; exact deployed revision unverified. No ledger is involved and no account or ledger mutation was submitted.

1. Open the direct General Settings route and wait for the visible language combobox.
2. Inspect its native Chromium accessibility node: both fresh widths expose `role: combobox`, `name: ""`, `value: "English"`, `focusable: true`, `hasPopup: dialog`, and `expanded: false`.
3. The rendered button has neither `aria-label` nor `aria-labelledby`. Its current-language text is present, but does not name this combobox. Fresh German controls likewise have the snapshot `combobox: Deutsch`; after selecting Japanese it is `combobox: 日本語`, without a quoted accessible name.

Expected: a stable, translated name identifying the language setting, separate from the current native-language value. The [WAI-ARIA combobox guidance](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/) distinguishes these two properties. Actual: the value is discoverable, but the control's purpose has no accessible name. This records browser metadata; physical screen-reader speech was not tested.

Working control: fresh `/settings/general?lang=de` at 390×844 and 1440×1000, wait for the trigger's bound handler, focus the trigger and press Enter, focus the actual Japanese option and press Enter. The picker closes, returns focus to its trigger, clears its busy state, updates URL/document language to Japanese, and retains Japanese after reload at both widths. There is no horizontal page overflow. Option focus was set explicitly before native Enter; full sequential Tab navigation is not claimed. Initial name-based locator timeouts are automation consequences of the empty name, not separate loading or authentication findings; the authorized session recheck returned HTTP 200 and an authenticated profile.

Root: `dashboard/src/features/user-settings/pages/general/appearance-section/language-selector.tsx:34–45` assigns `role="combobox"` to the Button but supplies no name. Its neighboring translated label in `appearance-section/index.tsx:50–57` is an unassociated paragraph. The shared Button forwards supplied attributes; installed Radix PopoverTrigger (`@radix-ui/react-popover/dist/index.js:129–143`) supplies popup relationships and forwards props, without associating that neighboring paragraph. Existing selector tests query by role and text content, so they do not establish a name.

Fix: associate the existing translated Current language label with this trigger, or supply its existing translated text as a stable accessible name. Preserve the independent native-language value, current-option marker, popup keyboard behavior, focus return, pending state and language persistence. Add meaningful rendered role-and-name assertions across English and a non-English locale and after a language change. Recheck the native browser name/value pairs at both widths, then run the dashboard's normal checks. No primitive fork, dependency, API or schema change is needed.

**Resolved 2026-10-10** — The Settings language combobox uses the existing translated `userSettings.currentLanguage` label as its accessible name, while its separate native-language value stays visible. Implementation ships with this resolution (`dashboard`).

Reproduced an empty native Chromium name with value English at 1440px and 390px against the local dashboard and synthetic read-only authentication fixture. Four final fresh English/German journeys at both widths expose Language/English and Sprache/Deutsch, then 言語/日本語 after keyboard selection. The current-option marker, popup closure, restored trigger focus, settled Escape focus return, cleared busy state, Japanese URL/document language/preferences and name/value after reload all pass, with no horizontal overflow. The actual Japanese option was focused explicitly before Enter; a full native sequential Tab journey or physical screen-reader speech is not claimed. Initial focus snapshots preceded popover restoration; the final checks awaited the actual focused trigger and settled close.

The four existing real-localization selector tests now require exact English, French and Chinese setting names independently of selected-language text. They also cover the live English-to-French name change, sequential Tab/Enter selection, current markers, focus return, resource loading, persistence and authoritative URL replacement. Removing only the two naming edits makes all four cases fail on missing localized names without unhandled errors; byte-exact restoration returns all four to green. Full formatting, lint, test and build gates pass: 473 suites, 5,177 passing tests and one existing skip. No API, locale catalog, dependency or primitive change was needed.

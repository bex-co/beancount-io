## Cause and verified source

`dashboard/src/features/ledger-data/holdings/utils.ts:114–121` trims the decimal string, converts it with `Number(trimmed)`, then calls `toFixed(2)`. The closest binary value to2.675 is slightly below the decimal half, so both signs round toward2.67. The exact input was available before that conversion.

`formatHoldingsCell:141–142` dispatches this column to that helper. `holdings-table.tsx:209–211` uses it for visible cells; `tableToCSV` at`utils.ts:94` uses the same dispatcher. All four groupings share DatasetTable. The complete current utility reproduces2.67/−2.67; its existing exact `roundDecimalString(source,2)` gives2.68/−2.68, while1.25 and0.42 controls are unchanged. This does not require a new decimal dependency or changes to BQL, API, valuations, holdings rows or lossless source-quantity formatting.

The served asset is `ledger._ledgerOwner._ledgerName.holdings-CNMgrswv.js`. Its complete `formatPercentageCell` matches researched local HEAD`0f68e9b03` and fetched main`16fd44d63` byte-for-byte, SHA256`f4eb21b7aa91d7498f445804271025c009e731f017187e079ea10e0e5d2da175`. Whole utility/table/query modules differ from current source for other work; no whole-build match is claimed. In particular the deployed BQL templates predate1019's signed-gain fix. Running all four actual captured templates and all four current templates against this positive-price fixture gives identical complete raw tables, so that deployment difference does not explain the rounding. Targeted history traces the formatter to`b9bdc71b3`; it is still present on fetched main.

**Resolved 2026-10-23** — `formatPercentageCell` (`ledger-data/holdings/utils.ts`) now rounds a plain decimal string with the file's existing exact half-up `roundDecimalString(value, 2)`, padded to two fixed places, instead of `Number(...).toFixed(2)`. A returned `2.67500` is 2.68 and `-2.67500` is −2.68. Screen and CSV share the dispatcher, so both changed together. Genuine zero (`0`), null, empty, non-numeric and number inputs behave as before; units, prices, cost and book/market values are untouched. One incidental difference: a tiny negative such as `-0.004` now reads `0.00`, not `-0.00`.

`utils.test.ts` covers the half and carry boundaries (2.675, −2.675, 1.005, 9.995 → 10.00, 2.674999), the 1.25 and 0.42 controls, fixed places and fallbacks. A `tableToCSV` export case shows 2.68 and −2.68 beside a lossless 102.675 market value. The boundary and export cases fail on the old branch.

# Persist the dashboard report conversion choice per ledger across report pages

From `/pm-brainstorm for w4` 2026-09-10 (item 7), prompted by issue 176's ask for one display currency across the app. The dashboard exposes a conversion selector per report page (`ConversionOption`, seeded from the Fava `conversion_currencies` option). Verify first whether the selection already persists when moving between Balance Sheet, Income Statement, Cash Flow, and Budget for the same ledger; if it does, drop this note. If not, store the choice per ledger (local storage keyed by ledger id, same pattern as other per-ledger UI state) and apply it on every report page. Sub-hour, dashboard only. A2/A3.

---

**Resolved 2026-09-14** — fixed in `dashboard` by `feat(dashboard): keep each ledger's report conversion across report pages`. Triage confirmed the gap at HEAD before the fix: Balance Sheet, Income Statement, Cash Flow, Trial Balance, and the account report each held `conversion` in page-local `useState` seeded from `at_cost`, so a choice made on one page reset on the next and on reload. The Overview has no conversion selector and Budget has no conversion, so neither changed.

The five pages now share `features/reports/components/use-report-conversion.ts`, which keeps one conversion per ledger. It is stored in a cookie rather than local storage, because a cookie is readable during server rendering — the same reason report chart visibility uses a cookie — so server and client render the same choice. A stored value is used only while the page still offers it (cost, market value, units, or the ledger's primary currency); anything else falls back to cost. The cookie is read for the current ledger on each render, so a mounted report page follows a ledger switch. The four report loaders that prefetch data (Balance Sheet, Income Statement, Cash Flow, Trial Balance) prefetch with the stored choice so a server render still has its data. The now-unused `trial-balance/constants.ts` was removed.

Regression tests: `features/reports/components/__tests__/use-report-conversion.test.ts` covers the default, a choice carrying to the next page for the same ledger, per-ledger isolation, a ledger switch on a mounted page, primary currency accepted versus an unoffered currency, and malformed cookies. `features/reports/cash-flow/__tests__/loader.test.ts` checks that the prefetch uses the stored choice.

# Refuse a portable export that silently loses local document attachments

Severity: **minor**. Package: **cli**. Estimate: **40–55m** for a bounded refusal/diagnostic and regression coverage. Source: continuous CLI QA. **A1/A2**: an agent must not receive success for a portable copy that fails stock Beancount validation despite a valid source.

Reproduced twice from pristine synthetic fixtures on main `390568c2`, checkout `cli/.venv/bin/bea` 0.3.0, Python 3.13.3, macOS arm64. Commands ran with closed stdin, piped stdout/stderr, isolated `BEA_CONFIG_DIR` and `XDG_CACHE_HOME`, notifier disabled, and inherited `BEA_FILE`/`BEA_TOKEN` removed.

Create `source/receipt.pdf` containing any synthetic bytes and `source/main.bean`:

```beancount
2024-01-01 open Assets:Cash USD
2024-03-01 document Assets:Cash "receipt.pdf"
```

Run with absolute paths:

```sh
bea --json --file /scratch/source/main.bean check
bea --json --file /scratch/source/main.bean price export --output /scratch/export
bea --json --file /scratch/export/main.bean check
bean-check /scratch/export/main.bean
```

Source check exits 0. Export exits 0 with empty stderr, lists only `export/main.bean`, and leaves its relative document directive unchanged. Both exported checks exit 1: `main.bean:2: File does not exist: "/scratch/export/receipt.pdf"`. The attachment is absent. Manually copying the synthetic receipt into export makes check pass (exit 0), independently isolating the failure. Source ledger and receipt remain unchanged. No managed network feed or credentials are needed.

Expected basis: ADR018 section 10 and CLI USAGE promise a self-contained export checkable by unmodified upstream Beancount. Source validity does not survive this successful export. The original completed w1/m29/t005 excluded whole-ledger snapshots, but the shipped implementation and later accepted ADR explicitly specify closure copies and stock validation. This note does not propose a general attachment archiver.

Root: `cli/src/bea_engine/managed_load.py:502–573`, `export_portable`, copies only `LedgerSnapshot.contents` (root and included ledger text) plus managed feeds. `_rewrite_export_includes` rewrites includes only; document paths neither move nor trigger a limitation diagnostic. No destination validation checks the claimed portable result. Frontend `src/cli/commands/price.py` calls the engine dispatch at `bea_engine/main.py`; this is the export command's sole production path.

Bounded repair: detect local document dependencies that the current exporter cannot preserve and refuse before writing with a path-specific, actionable diagnostic. Alternatively preserve the narrowly supported local attachment case if it fits this scope. Do not silently drop the directive, advertise a self-contained success, or merely retain an absolute dependency on the original machine. Broader attachment/plugin packaging can be separately sized if desired.

Acceptance: this valid source either produces an export that passes stock `bean-check` after relocation without its source directory, or returns a clear nonzero unsupported-dependency error before writing. Cover a document in a nested include, source immutability, and the existing document-free export control. Preserve managed feed provenance and unavailable-source policy. Run CLI checks for the repair.

Dedupe: searched open/done/blocked board and export history; no matching attachment report found. w4/171 concerns parent-relative include mapping; w4/172 concerns destination aliases overwriting source. This case uses neither. Export originates in `109fef1d`, simplified by `de97db58`; current `3c86426b` provenance/auth changes do not add document handling. Existing `TestPriceExport` covers feeds/includes and stock validation but not document directives.

Evidence: ignored `cli/tmp/qa-20260921-cli-loop/captures/cycle9-*-document-*.json`, `cycle9.py`, and `document-upstream.json`. Two complete CLI repetitions, stock `bean-check` failure, and two successful manual-copy controls. Synthetic attachment contents need not be a real PDF because Beancount validates existence. Absolute/outside-tree documents and plugin resources remain unverified; no broader claim is made.

---

**Resolved 2026-09-23** — Took the note's narrower preservation option rather than a blanket refusal. `export_portable` now copies every `document` the loaded ledger names (directly, from a nested include, or found through a relative `documents` option) when it lives under the root's directory, to the same relative place, so relative paths keep resolving after relocation. A document outside that tree, named by an absolute path, in an include the export relocates, or under an absolute `documents` option refuses the export before anything is written, naming it. Source documents also join the pre-write identity guard. The note's fixture now exports `receipt.pdf`, and the relocated copy passes upstream `bean-check` with the source deleted. `cli/tests/test_price_export_documents.py` covers the nested-include document, source immutability, and both refusals (all three fail without the fix); the document-free export tests stay green. `cli/docs/USAGE.md` documents the rule. `make spec-check` was red from unrelated w2/m32 work. Plugin resources remain out of scope. Shipped in `d6d801e9` (`cli`).

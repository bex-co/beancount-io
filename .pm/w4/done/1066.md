## Cause and bounded repair

`dashboard/src/features/ledger-data/commodities/format-commodity-price.ts:27–35` handles zero source range by deriving decimals only from the constant quote's magnitude. For±1e-9 it returns10. `formatCommodityAxisTick` at:48–58 then derives only two significant digits, so adjacent padded ticks1.05e-9 and1.1e-9 collapse to the same string. The chart's real y-axis in `commodities/index.tsx:81–92` pads a constant positive series to80–110% and a negative series to110–90%; those distinct intermediate ticks are legitimate. `build-commodity-chart-labels.ts:33–34` supplies the source values, rather than the padded tick spacing, to the formatter.

Choose sufficient bounded precision for the actual constant-series scale so adjacent rendered ticks stay distinguishable, including the power-of-ten rounding boundary and negative prices. Keep ordinary-price readability, true zero, varying tiny/exponent labels, exact source history/tooltip text, dates and numeric plotting. Do not change source prices, pad the data with invented values, revert to fixed six-place zeros, add dependencies or introduce a global chart abstraction. The formatter is called through this commodity chart-label builder only; shared report/BQL axes have separate policies.

Acceptance: the real CommodityChart for the supplied positive and negative constant series renders distinct neighboring tick labels at both widths; its history/source values remain exact. Include varying tiny, exponent, ordinary constant and zero controls through the real chart wiring, with a half-step near a power of ten rather than only the source quote itself. Repeat native screenshots and run dashboard gates on implementation. No product fix or formal regression test was authored during QA.

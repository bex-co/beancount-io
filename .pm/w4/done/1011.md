# Name the date-picker calendar popup

**Severity:** minor accessibility. **Estimate:** 30–45 minutes. **Owner:** dashboard, `common/components/ui/date-picker.tsx`. **A2:** a reader navigating the date chooser should encounter a named calendar dialog, alongside its separately named field, trigger and month grid.

## Reproduction and passing controls

Production `https://beancount.io`,2026-10-22 America/Los_Angeles; owned isolated headless Chromium155.0.8059.85, English/light, UTC clock, designated disposable QA ledger owner. Independent390×844 and1440×1000 New Entry → Note dialogs reproduce. No response substitution, mutation attempt or hosted write.

1. Set Date to **2000-02-28**, commit the field, focus **Select date** and press Enter.
2. Chromium's actual Accessibility.getFullAXTree exposes two unignored dialogs: **New Entry** and **name:""**. The calendar popup has role=dialog with neither aria-label nor aria-labelledby. The inner grid is correctly named **February2000**; that name does not label its containing dialog. Both fresh widths reproduce, also with1900 selected.
3. Passing date control: focus the selected February28 day, press ArrowRight, then Enter. In2000 the named focused day is **Tuesday, February29th,2000**, and the field becomes **02/29/2000**. In1900 it is **Thursday, March1st,1900**, and the field becomes **03/01/1900**. Independent Python civil-date arithmetic agrees with both. The parent New Entry stays open and no submission occurs.
4. Reopen the calendar and press Escape. Only the calendar closes, New Entry remains, and focus returns to **Select date**, at both widths. Preserve these working controls.

## Cause and bounded repair

`date-picker.tsx:231` renders PopoverContent without a name. The trigger above it uses the existing translated `common.selectDate`, but that names the button only. The shared Popover wrapper forwards accessibility props. Give this DatePicker popup an appropriate localized accessible name, reusing the existing chooser label or a valid associated label. Keep field/trigger names independent and do not impose one generic name on every Popover.

Seven production DatePicker callers were searched: Transaction, Balance, Note and Open Account tabs in New Entry; Accounts' separate Open Account; Add Budget; Receipt Review. One shared repair covers their popup. Only Note was exercised live here; the other six are source-traced compatibility scope. Preserve civil-day values/timezones, validation/drafts, year bounds, composition guards, selected month, native day keyboard actions, Escape/focus return and short-window scrolling. No API, dependency, financial calculation or receipt/AI action is involved.

Acceptance: a real DatePicker with actual localization exposes a named dialog on keyboard/pointer opening in English and a second locale, for empty and selected values; names follow the app language. Test the popup's role/name rather than only its trigger or inner grid. Retain native day selection, field update and Escape/focus behavior, repeat desktop/narrow, and run dashboard gates when implementing. QA authored no product fix or tests.

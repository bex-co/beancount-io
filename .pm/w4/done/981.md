# Escape receipt text in the Beancount preview

**Severity:** minor. **Estimate:** 30–45 minutes. **Owner:** dashboard. **A2:** the receipt review's Preview should represent the payee and description the reader entered as valid Beancount text.

Production `https://beancount.io`,2026-10-22, owned isolated headless Chromium155.0.8059.85, English/light, authenticated designated synthetic ledger. Fresh390×844 and1440×1000 independently reproduce. Temporary-upload URL, PUT and ParseReceipt responses are explicitly modeled locally; no actual upload, AI call or quota use. Record requests are aborted before transport.

1. Open `/ledger/<qa-owner>/<synthetic-ledger>/receipt`. Supply a tiny synthetic image and locally modeled parsed receipt with date2026-08-01, amount12.50, existing expense/payment accounts and plain initial text.
2. Enter payee `qa-20261022 Bob "Cafe"` and description `qa-20261022 folder C:\Receipts`.
3. Preview renders the header `2026-08-01 * "qa-20261022 Bob "Cafe"" "qa-20261022 folder C:\Receipts"`. Quotes and backslashes are interpolated verbatim inside quoted Beancount strings.
4. Actual Beancount3.2.3 `parser.parse_string` on that captured preview returns zero entries and **Invalid token: 'Cafe""'** at both widths. Properly escaping the same two strings parses one entry whose payee/narration round-trip exactly.
5. Isolate backslashes with plain payee and description `qa-20261022 folder C:\temp\receipt`: the captured preview parses, but its narration contains a tab/carriage return in place of the literal backslashes. The original description does not round-trip. Ordinary plain payee/description previews parse and round-trip correctly at both widths.

Native Record in each original quote case prepares exactly one structured InsertReceiptTransaction input containing the exact typed payee and description and12.50/-12.50USD. Both attempts are intercepted and aborted; the preview is the demonstrated defect. No claim that these malformed preview strings are submitted, stored, executed, or injected into another surface. A third fresh desktop visual repeat with shorter `qa "Cafe"` / `qa C:\temp\receipt` shows the same unescaped header and makes no Record attempt.

## Cause and repair

`dashboard/src/features/receipt/components/receipt-review-form.tsx:128–135` builds previewText by placing watched payee and description directly between quote characters. At:337–338, pre renders that text correctly as text; HTML escaping cannot repair its Beancount string syntax.

Serialize each preview string using the Beancount quoted-string rules, preserving quotes, backslashes and supported control characters exactly on a parse round-trip. Keep ordinary text and Unicode readable, exact amount strings, dates, account selections, empty-draft placeholders and structured submission values intact. Do not alter the reader's actual fields or add a second receipt submission serializer. Check existing suitable shared utilities before introducing a small helper. No API, dependency or backend change is needed.

Acceptance: rendered real review edits produce previews that parse and round-trip the typed quoted merchant and backslash-only description, alongside plain/Unicode controls. Keep structured mutation input exact. Verify both widths and run dashboard gates when implementing. Actual backend persistence, real OCR output, other engines/locales and the repaired deployment remain unverified.

**Resolved 2026-10-22** — the receipt review's Preview now writes the payee and description through a new shared helper, `beancountString` (`common/lib/beancount/quoted-string.ts`). It escapes backslashes and then quotes, so the preview header parses and round-trips the reader's exact text. Plain and Unicode text, amounts, dates, accounts, placeholders and the structured Record input are unchanged; no existing quoter was found to reuse. `quoted-string.test.ts` covers plain text, quotes, backslashes, a mixed backslash-quote, Unicode and empty text. `receipt-review-preview.test.tsx` edits the real form to `qa Bob "Cafe"` and `qa folder C:\temp\receipt`, asserts the escaped header and checks that Record submits the text exactly as typed; that case fails with the change reverted, and the Unicode control passes. Native checks at 1440 and 390 px against the local fixture API modeled the upload URL, PUT and ParseReceipt in the browser and aborted Record before transport. They showed the header `2026-08-01 * "qa-981 Bob \"Cafe\"" "qa-981 folder C:\\temp\\receipt"`, and the Record input carried the exact typed strings and 12.50/-12.50 USD. Beancount 3.2.3's `parser.parse_string`, from the CLI package's environment, parsed that captured preview as one entry with no errors, and the payee and narration equalled the typed text. No uploads, AI calls, writes or page errors. Shipped in `c2d48b003` (`dashboard`).

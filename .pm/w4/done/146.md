# Overview charts could pick their unit from the ledger's operating currency

Found while writing w4/m21/t006's tests, against the code at `73829285`.

`overview/lib/unit-amounts.ts`'s `chooseDisplayUnit` decides which unit an
overview chart is drawn in by reading the accounts: most accounts wins, ties
break on total magnitude, then alphabetically. That is truthful and stable, and
it gets every public fixture right — USD for the example ledger, MUSD for
Synopsys, EUR for Adyen.

It can still pick an odd unit on a thin ledger. With exactly one account on
each side, the count tier ties and magnitude decides, so a single large
retirement account denominated in `IRAUSD` beats a single smaller `USD`
account and the whole diagram is drawn in IRAUSD — with a correct note saying
USD is not included. Nothing is misstated, but the chart is less useful than it
could be. `overview/lib/__tests__/../cash-flow-sankey-units.test.tsx` documents
this in "follows the units the accounts use, not the largest number".

The ledger already declares a stronger signal. The net-worth and account cards
read the operating currency (that is how Adyen's cards show EUR), and
`buildAccountBalanceRows` takes a `preferredCurrency` for exactly this purpose.
Threading the same value into `chooseDisplayUnit` as a first tier — prefer the
declared operating currency when the accounts actually hold it, otherwise fall
back to today's account-count heuristic — would make the choice match what the
rest of the page already shows.

Scope: `chooseDisplayUnit`'s signature plus its three callers (the Sankey
transformer, `buildDistributionData`, the income/expenses bar chart), and the
`preferredCurrency`/`primaryCurrency` the overview page already has in hand.
Keep the existing tie-breaks as the fallback, and keep the disclosure note —
the point is a better first choice, not a different contract.

Not a correctness defect: no amount is misreported today, and every omitted
unit is disclosed. This is a quality-of-choice improvement.

---

**Resolved 2026-09-20** — `chooseDisplayUnit` takes an optional `preferred` unit and returns it when the accounts actually hold it, ahead of the account-count tier. Everything else is untouched: the count, magnitude and alphabetical tie-breaks remain as the fallback and are still exercised whenever nothing is declared or the declared unit is absent from the accounts, and the disclosure note is unchanged — the point was a better first choice, not a different contract. Threaded through all three consumers the note scoped, from the `primaryCurrency` the overview page already holds: `transformToSankeyData` (a new `preferredCurrency` option), `buildDistributionData` (a third argument), and `IncomeExpensesChart` (a prop), with the two chart components gaining a `primaryCurrency` prop to carry it. The thin-ledger case the note describes is covered directly: one `IRAUSD` account against one smaller `USD` account still resolves to IRAUSD with no preference, and to USD once the operating currency is declared. Four more cases pin the rest of the contract — a declared currency winning over a unit with more accounts, a declared currency the accounts do not hold being ignored rather than drawing an empty chart, the existing tie-breaks surviving `null`, `undefined` and `""`, and an empty ledger still answering nothing. The existing `cash-flow-sankey-units` case the note cites, "follows the units the accounts use, not the largest number", passes unchanged, because it calls the chooser without a preference. Both public fixtures were re-checked live and choose exactly as before: the example ledger's Sankey reads `Income:US → Cash Flow 357,944.58 USD` and Adyen's reads `Income:NetRevenue → Cash Flow 26,328,539,000 EUR`. Not verified: a real ledger that actually exhibits the thin-ledger shape — the public fixtures do not, which is why the note filed this as a quality-of-choice improvement rather than a defect, and why that case is covered by unit tests rather than in a browser. Dashboard gates all pass (`yarn format:check`, `yarn lint`, `yarn test` — 424 files, 4773 passed, 1 pre-existing skip — and `yarn build`). Shipped in `74d87ea5` (`dashboard`).

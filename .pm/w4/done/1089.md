# Preserve empty single-column records in query CSV

**Severity:** minor. **Estimate:** 25–40 minutes. **Owner:** dashboard. **A2:** a downloaded query result must preserve its rows and column count when a valid result cell is empty.

## Fresh reproduction — 2026-10-25

Production `https://beancount.io`, owned isolated headless Chromium156.0.8078.47, anonymous public synthetic `open_ledger/example`, English/light/UTC. Fresh retained390×844 and1440×1000 contexts plus an independent desktop repeat with positive controls.

1. Open `/ledger/open_ledger/example/query?lang=en`.
2. Execute `SELECT '' AS blank_text LIMIT 1`. Genuine QueryShell returns HTTP200, no errors, one str column and `rows: [[""]]`. The table correctly shows **Rows: 1**, one column header and one empty data cell.
3. Activate **Download CSV**. It succeeds, but its14 bytes are the UTF-8 BOM followed by `blank_text\n`. Reading the actual file with Python's standard `csv.reader` returns only `[["blank_text"]]`: the data record is absent.
4. Execute `SELECT '' AS blank_text LIMIT 3` and download. The UI/API correctly retain three one-field rows. The16-byte file contains BOM + `blank_text\n\n\n`; the reader produces `[["blank_text"], [], []]`, losing one record and the remaining records' one-column shape.
5. The ordinary empty aggregate `SELECT sum(position) AS total WHERE year = 1900` also returns one empty str value. Its9-byte CSV is BOM + `total\n`, again read as header only. No Inventory object or zero-amount interpretation is assumed.

Both widths repeat all three failures. The independent desktop run repeats the one-row loss. Seven failing downloads in total; no transport or download exception is involved. The result screenshot was visually inspected.

Working controls: a query matching zero rows truthfully shows **No data returned from query** and downloads its two headers with zero data rows at both widths. `SELECT 'ordinary' AS blank_text LIMIT 1` retains its single value. `SELECT '' AS left_blank, '' AS right_blank LIMIT 1` emits a comma for the empty two-field record and round-trips correctly. These four downloads pass. Export makes no extra QueryShell read.

Python's independent csv.writer serializes the one-column case as `blank_text\n""\n`, which csv.reader round-trips to the header plus one empty-string cell. It also preserves all three blank records. This evidence establishes the observed reader/shape mismatch; other spreadsheet applications were not tested.

## Cause and bounded repair

`dashboard/src/features/bql/lib/export-utils.ts:27–37` keeps the ordered table rows and maps them through the shared writer. `common/lib/export/csv.ts:32–40` leaves an empty string unquoted, since it has no comma, quote or newline. `rowsToCSV` at:49–50 joins each one-field empty record into an empty line, with no way to distinguish the final record from a terminal line ending. BOM creation at:57–60 is correct.

Make a one-field record whose serialized field is empty explicit, using a quoted empty field. Preserve the intended row width and count without inventing a row for a genuinely empty result. Keep ordinary empty fields in wider rows, exact numbers, existing escaping, Unicode/BOM, download names and existing serialization protections. No API, query-engine, dependency or translation change is needed.

All shared-writer callers were traced. BQL accepts arbitrary column counts and exposes this case. The legacy object exporter already requests quoteAll, while statement exports use23 named columns: do not claim those surfaces reproduce this defect or change their established formats unnecessarily. Existing query table/virtualization behavior is correct.

Acceptance: export the actual one-row, three-row and empty-aggregate result shapes and parse the produced CSV with an independent reader; records and widths must equal the formatted API table. Retain the genuine zero-result, nonempty single-column and two-empty-column controls, plus existing CSV escaping/BOM cases. Repeat native downloads at both widths and run dashboard gates when implementing.

# Keep a current budget from masquerading as the selected historical target

Severity: **minor** financial loading/error-state defect. Package: **dashboard**.
Estimate: **35–45m**. Source: continuous dashboard QA for w4; **A2/A3** — a dated
budget comparison should not show a later target as though it belongs to the
selected historical period.

Production `https://beancount.io`, anonymous synthetic
`open_ledger/budgeting-envelopes`, isolated headless Chromium149.0.7827.55.
Local main `390568c2`, served `main-d5j4FX-V.js`; exact deployed revision
unverified. Browser date is real, September2026. The delay below is explicitly
browser-controlled; the held server response is real and unmodified.

1. Fresh-load `/ledger/open_ledger/budgeting-envelopes/budget?lang=en` at
   1440×1000/light. Wait for Expenses:Dining: Current budget200USD.
2. Select **Last year**, holding only Dining's actual GetLedgerIntervalTotals
   response for `time:"year-1"` before delivery to the browser.
3. Last year is pressed, and the card immediately relabels its metric to
   **Budget200USD**. The chart area shows a loading spinner; historical actual,
   variance and period table are correctly withheld. The header target alone
   looks ready and uses the wrong period's value.
4. Release the response. The same selected Last year card changes to
   **Budget0USD / Latest actual0USD / On target / variance0USD**.
5. Fresh390×844/dark repeats the exact pending200→settled0 transition.

The real budget directive is dated2026-01-01 with values
`["Expenses:Dining","monthly",{"number":"200.00","currency":"USD"}]`.
The actual HTTP200 period read returns twelve2025 month-end buckets with empty
balances. There is no effective2025 target; the settled zero is correct. The
2026 target-history row remains correctly dated and is not itself a defect.

Adjacent failure check: a separately labeled browser-only SERVICE_UNAVAILABLE
response leaves **Budget200USD** above the proper unavailable-service message
while Last year remains selected. Removing the override and selecting All time
then Last year restores the real0USD comparison. This does not claim a real
production outage, nor measure how long the normal loading mismatch lasts.

Cause: `dashboard/src/features/ledger-data/budget/budget-chart-card.tsx:167–168`
returns displayBudgetValue whenever chartData is empty, including when the
new period read is pending or has failed. That fallback is the latest configured
budget, not the selected period's target. Lines339–348 render it unconditionally
and change its label to Budget for year-1. Loading/error guards at418–446 cover
the chart and period table, leaving the misleading header outside them.

Make the read-dependent comparison target unavailable/pending until that
period's successful data is ready; keep the header honest on read failure too.
Reuse the existing loading/error presentation. Do not substitute a numeric zero
for unknown data, reimplement relative-period parsing, or add a request just to
avoid the fallback. If a latest configured target is shown separately, label
that fact and its date explicitly. Preserve the valid dated history, settled
zero target/actual behavior, proration, exact-match tolerance, income direction,
permissions and accessible period table. No API or dependency change is needed.

Acceptance: with Last year selected and the real Dining response held, no ready
metric asserts200USD as that year's target. A failed read cannot restore that
fallback; releasing/retrying reveals the correct0USD comparison. All time's
known200USD target and January's160.5USD actual remain valid. Exercise the real
loading→success/error paths at desktop/narrow widths and run dashboard gates.

Blast radius: BudgetChartCard's sole production owner is
`features/ledger-data/budget/index.tsx:309`, shared by all account/currency cards.
Only Dining's historical transition and simulated error were live-reproduced;
other intervals, currencies and authenticated writes remain unverified.

Dedupe/history: all board states searched for BudgetChartCard, the fallback
identifiers, historical budgets and pending/stale budget metrics. Completed

Completed w4/130 fixes floating-point variance and explicitly preserves this

**Resolved 2026-09-23** — When `BudgetChartCard`'s header claims the selected dated period's target (`time=year-1`, labelled "Budget"), the value now comes only from that period's own settled read. While the read is pending, after it fails, or when it is settled but empty, the header shows an em dash instead of the latest configured budget; variance and progress stay withheld. "Current budget" (all time) still shows the latest configured budget while in flight, as its label says. The settled 0 USD comparison, dated history, and period table are unchanged. `budget/__tests__/period-data-table.test.tsx` covers pending, failed, and settled Last year and the pending all-time control against the real English catalog; the pending and failed cases fail without the fix. Not re-verified on production or in a live browser with a held response. Shipped in `57a762e5` (`dashboard`).

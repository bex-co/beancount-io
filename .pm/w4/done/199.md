# Omit non-public avatar URLs from public profiles and social lists

Severity: **minor**. Owner: **backend-cluster/backend-v2**. Estimate: **45–60 minutes**. A2 — public-profile discovery should not send the browser to a server's loopback origin for every avatar.

## Reproduce

Production `https://beancount.io`, 2026-10-08 America/Los_Angeles; QA-owned isolated headless Chromium, English, fresh anonymous contexts at 1440×1000 and 390×1000. Source rechecked after pulling main `1ceeb845`; deployed module previously observed `main-GcCTaQbi.js`, exact deployment commit unknown. No follow/unfollow, profile, credential or ledger changes.

1. Open `/ledger/open_ledger?tab=followers` and wait for the first 20 follower links.
2. Browser image requests target **`http://localhost:3000/avatars/...`** and fail with **`net::ERR_CONNECTION_REFUSED`**. Each fresh viewport produces **21** such failures: the profile avatar plus the first 20 follower avatars.
3. Choose **Show more**. The list correctly grows to 40 links, but produces 20 more failed loopback image requests, for **41** total. The avatar components fall back to initials; names and profile navigation remain usable.

Expected: an API avatar URL is a publicly usable absolute HTTP(S) URL, or absent when the upstream URL is non-public. Missing avatars should use the existing initials fallback without asking the visitor's own localhost for an image. Do not rewrite the URL to an unverified public Git origin: completed w3/459 records that the hosted `/avatars/` origin requires basic authentication.

## API control and source

REST `GET /api-gateway/v1/social/followers?username=open_ledger&page=1&limit=20` independently returns HTTP 200 and the same 20 loopback avatar origins. No avatar hashes or follower identities are needed to reproduce or are included here.

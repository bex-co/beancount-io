# Fix: export print tree leaks as visible text at the bottom of Income Statement / Balance Sheet pages

Production regression from w4/m1 (`feat(dashboard): export professional financial statements`).

## Diagnosis

- `PrintableStatement` (`dashboard/src/features/reports/export/printable-statement.tsx`) portals the full export statement (entity header, notices, summary tables, supporting account detail, "Generated by…" footer) into `document.body`; `StatementExportMenu` mounts it permanently on the income-statement and balance-sheet pages.
- It is meant to be hidden on screen by `@media screen { .statement-print-root { display: none } }` in `statement-print.css`.
- That CSS never reaches production: the app ships all CSS as one inline `<style>` (`src/routes/__root.tsx` imports `src/style.css?inline`) and `dashboard/vite.config.ts` sets `cssCodeSplit: false`. The plain `import "./statement-print.css"` in `printable-statement.tsx` is extracted into an orphaned `lgassets/style-*.css` asset that no chunk references and nothing links (verified in the local `.output` Vite manifest — zero `css` associations — and on the live site, where the deployed `statement-export-menu-*.js` references no CSS).
- Dev mode cannot reproduce this: Vite dev serves plain CSS imports through the module graph.

## Fix

1. Add `@import "./features/reports/export/statement-print.css";` to `dashboard/src/style.css` (same pattern as the existing `chat-markdown.css` / `diff-viewer.css` imports) so the print rules ride the inline bundle.
2. Delete the side-effect `import "./statement-print.css";` from `printable-statement.tsx`.
3. Rebuild (`yarn build`) and verify the `@media screen` hiding rule and `@media print` rules appear in the served inline `<style>`, and that the pages no longer render export text on screen while Print / Save as PDF still works.
4. Regression test: extend `dashboard/src/features/reports/export/__tests__/statement-print-css.test.ts` to assert `src/style.css` includes the statement-print import, and scan `src/` for bare (non-`?inline`) `.css` side-effect imports so this cannot regress.

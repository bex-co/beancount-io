# Keep Budget's round-off tolerance from erasing visible USD differences

**Severity:** minor. **Estimate:** 45–60 minutes. **Owner:** dashboard. **A2:** a Budget card whose actual is visibly above or below its target must show that difference instead of an apparently exact match.

## Reproduction and controls

Production `https://beancount.io`,2026-10-22 UTC; owned isolated headless Chromium155.0.8059.85, anonymous public budgeting-envelopes page, English/light. Fresh390×844 and1440×1000 reproduce the positive difference; another fresh1440 case reproduces the negative difference. **Budget and interval-total responses are modeled locally against the deployed client**, using complete shapes cloned from the actual public response. Other reads remain real; no hosted budget or posting is created or changed.

1. Open `/ledger/open_ledger/budgeting-envelopes/budget` with October2026 as the current month. Fulfill its budget journal with one Jan1 monthly Expenses:Dining directive, amount **34084860461056.00 USD**. Supply one October31 interval with actual **34084860461057.00 USD**, including the matching account inventory.
2. At both widths the card and Period data show the exact target **34,084,860,461,056.00 USD** and actual **34,084,860,461,057.00 USD**, but **Variance / On target / 0.00 USD**. Expected: **Above target / +1.00 USD**.
3. Independently set actual to **34084860461055.00 USD**: the card again says On target/0.00. Expected: **Below target / -1.00 USD**.

The target is **31 × 2^40**. Its daily monthly equivalent is exactly2^40, so summing the31 October days introduces no proration residue. Both target and actual are exact integers below2^53. Independent Python Decimal and integer calculations verify the displayed target/actual against the modeled inputs and the ±1.00 deltas; this is a visible whole-dollar difference, rather than an unrepresentable or sub-cent remainder.

Working controls:

- Same large target, actual **34084860461060.00**: Above target/+4.00 USD, correctly.
- Smaller target **133143986176.00** (=31 × 2^32), actual **133143986177.00**: Above target/+1.00 USD, correctly.
- Ordinary exactly met **1650.00/1650.00 USD**: On target/unsigned0.00 remains correct after actual daily proration.
- A refund actual **-50.00** against **200.00 USD** retains its minus sign and reports Below target/-250.00, correctly.

## Cause and bounded repair

`features/ledger-data/budget/budget-utils.ts:280–286` normalizes any difference within **max(abs(actual),abs(budget),1) × Number.EPSILON × 512** to zero. For this +1 fixture, that bound is **3.8750000000001136868 USD**, so a representable visible dollar is deliberately zeroed. +4 exceeds the bound and survives; the smaller target's bound is about0.01514, explaining its working +1 control. BudgetChartCard's sole production call at:233 then derives variance, badge and favorability from that zero.

Bound numerical normalization so it cannot erase a difference that renders as nonzero at the card's supported monetary/quantity precision. Keep signed variance, badge and favorability coherent. Preserve the original28/29/31-day exactly met targets and real fractional-commodity differences; do not remove round-off handling blindly, impose a universal cent threshold, alter incoming amounts or globally round commodities to USD precision. Retain daily-equivalent dated-target proration, sparse balances and income direction. No API, dependency or ledger change is needed.

Acceptance: the actual proration→comparison→card path renders the reproduced ±1 USD differences at both widths, while +4, smaller-target +1, exact1650 and refund controls remain correct. Include meaningful scale-boundary and original round-off regressions, plus fractional-unit compatibility, then run dashboard gates when implementing. Yearly/mid-period large-value cases, income reversal, arbitrary non-ISO scales and the repaired deployment remain unverified.

**Resolved 2026-10-22** — `budgetVariance` now takes the card's display precision: an ISO currency's minor units, else the commodity's shown digits (`max(quantityDigits, 3)`). A difference of half a unit or more at that precision is never flattened. Below it, only the existing ulp-per-day round-off allowance zeroes a difference, so the proration's last-place residue is still absorbed. Daily-equivalent proration, sparse balances, income direction and fractional commodities are unchanged. `budget-variance.test.ts` runs the real proration at the note's 31 × 2^40 USD target: ±1 USD now survives, and the +4 and smaller-target +1 controls hold.

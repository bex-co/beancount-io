# MCP: a mistyped resource URI or a malformed prompt argument returns a double-prefixed `-32602` with no `data.code` or hint

**Severity:** minor. **Estimate:** 30–45 minutes. **Owner:** backend-v2 (MCP
adapter). **A1:** `docs/mcp.md` and w2/m28's definition of done promise that
every MCP failure carries `{code, hint}` and that no message is
double-prefixed; two of the most common agent mistakes still get neither.

Found 2026-09-15 by MCP QA against `main`, HEAD `fbdffde8`, driving the real
registry through the MCP SDK's in-memory transport (`@modelcontextprotocol/sdk`
1.30.0) with stubbed services. Both failures happen before any service runs.

## Repro

With the client from the same in-memory setup as w4/069, pinned to
`alice/main`:

```ts
await client.readResource({ uri: "beancount://alice/main/nosuch" });
// McpError code -32602, data undefined
// message: "MCP error -32602: MCP error -32602: Resource beancount://alice/main/nosuch not found"

await client.getPrompt({ name: "close-month", arguments: { month: "2026-1" } });
// McpError code -32602, data undefined
// message: "MCP error -32602: MCP error -32602: Invalid arguments for prompt close-month: month must be YYYY-MM at month"
```

Controls from the same session:

```ts
await client.readResource({ uri: "beancount://bob/other/errors" });
// -32003, data.code FORBIDDEN, data.hint present, single prefix (our mcp-errors path)

await client.callTool({ name: "runBqlQuery", arguments: { query: "BALANCES", ledger: "nope" } });
// isError, {code: BAD_USER_INPUT, hint: "Call `listLedgers`, then pass ledger: ..."}
```

## Expected

Per `docs/mcp.md` ("The same codes reach resource reads, as the JSON-RPC
error's `data`, with the message unprefixed so a client's SDK adds exactly one
`MCP error <n>:` prefix") and w2/m28 t003's acceptance ("no message is
double-prefixed"): an unmatched `beancount://` URI answers `NOT_FOUND`
(`-32002`) with a `data.hint` naming `resources/templates/list`; a malformed
prompt argument answers `BAD_USER_INPUT` (`-32602`) with `data.code` and a
hint, each with one prefix.

## Actual

Both errors are raised by the SDK itself as `McpError` (server `mcp.js`
`Resource template … not found` / `Invalid arguments for prompt …`). The
SDK's `McpError` constructor already prepends `MCP error <code>: `, the
server's protocol layer forwards `error.message` verbatim
(`shared/protocol.js`), and the client wraps it once more. Because the error
never passes through `mcp-errors.ts`, there is no `data.code` and no hint,
and the code is `-32602` rather than the documented `-32002` for a missing
resource.

## Root cause

- `src/features/ai-agent/api/mcp-prompts.ts` delegates argument validation to
  the SDK via `argsSchema` (added in `18413b29`, w5/m5), so the refusal is the
  SDK's, not ours.
- `assembleMcpRegistry` (`src/server/api/composition-root.ts`) registers only
  concrete templates; a URI that matches none is refused by the SDK before any
  of our handlers run. `mcp-errors.ts` only shapes errors thrown inside a
  handler.

## Fix

1. Prompts: keep `argsSchema` permissive (strings) and validate `month` /
   `ledger` inside the prompt callback, throwing the project's coded error so
   `mcp-errors.ts` emits `-32602` + `data: {code: "BAD_USER_INPUT", hint}` with
   one prefix. Keep the existing `mcp-prompt-list.test.ts` cases and assert
   the error shape instead of the SDK prose.
2. Resources: register a last, non-listable catch-all template
   (`beancount://{+rest}`) whose read throws `NotFoundError` with a hint
   pointing at `resources/templates/list` and the ledger-scoped grammar, so
   an unmatched URI gets `-32002` + `data.code`/`hint` like a missing file.
3. Add regression tests beside `mcp-errors.test.ts` for both paths; run
   `yarn typecheck` and `yarn test`.

---

**Resolved 2026-09-16** in `fix(backend-v2): answer unmatched resource URIs and malformed prompt arguments in the MCP envelope`. Both refusals were the SDK's, raised before any handler of ours ran, so `mcp-errors.ts` never saw them.

**Resources.** `assembleMcpRegistry` now registers a last catch-all template, `beancount://{+rest}`, with no list callback. Every concrete template above it still wins — the SDK reads through the first template whose URI matches — so an unmatched `beancount://` URI reaches a handler that throws `NotFoundError` with a hint naming `resources/templates/list` and the ledger-scoped grammar. It answers `-32002` with `data.code: "NOT_FOUND"`, `data.hint`, and one prefix. It is not gated: it reaches no service and always refuses, and the transport limiter has already charged the request.

**Prompts.** The `ledger` and `month` patterns move out of `argsSchema` into `validatePromptArgs`, which the prompt callback runs before `build`. `prompts/list` publishes an argument's name, description and requiredness and never its schema, so nothing an agent can read changed; the refusal is now `-32602` with `data.code: "BAD_USER_INPUT"`, the argument named, a hint, and one prefix. `backend-v2/CLAUDE.md` said to validate these in `argsSchema` and now says where they actually live and why.

**`McpResourceFailure` is now `McpRequestFailure`** — it carries prompt failures too — and the envelope-and-throw that both paths share is one `refuseMcpRequest` helper.

**Not fixed: a URI under another scheme.** `https://example.com/x` still returns the SDK's double-prefixed `-32602` with no `data`. The catch-all is deliberately scoped to `beancount://`: this server reserves `https://` for resources a client fetches on its own, and claiming every scheme would advertise a template that matches anything.

**The catch-all is listed.** `resources/templates/list` has no way to hide a registered template, so it now returns 65 rather than 64, the last entry being `unknownResource` / `beancount://{+rest}`, titled and described as not a resource. The prompt-list guard is unaffected: it matches cited URIs against the `MCP_RESOURCES` descriptors, not the live registry, so a cited-but-unregistered URI still fails it.

**Tests.** `features/ai-agent/api/__tests__/mcp-resources.test.ts` asserts the code, `data.code`, hint and single prefix for two unmatched URIs — including `beancount://alice/main/bank/list`, the one the prompt-list guard was written for — plus a guard that a matching template is not shadowed. `server/api/__tests__/mcp-prompt-list.test.ts` asserts the same three properties for the malformed `month` and the two malformed `ledger` cases it previously checked as prose. With the fix reverted, five of them fail. `yarn typecheck` and `yarn test` pass, with 4526 unit tests; `yarn generate-v1-openapi` reports no drift.

**Not exercised.** The hosted endpoint; this was verified in-process through the SDK's in-memory transport, as the note's repro was.

# Slim down the health-check failure log

**Source:** user request, 2026-09-27. **Package:** backend-cluster/backend-v2. **Estimate:** 45m. **Goal:** A2 — self-hosters and contributors can identify an unhealthy dependency quickly while bringing up the full stack.

`src/features/healthz/api/healthz-handler.ts` logs `Health check failed for ${name}` with an `error` metadata field. It already extracts the error message rather than logging the whole exception, but the message is unbounded; the development formatter in `src/shared/logger/index.ts` expands metadata into indented JSON. This is source review, not a captured production failure.

Make the routine health-check warning compact: retain the failed service and a short, single-line reason, with a useful error code or HTTP status when available. Bound long or multiline messages, preserve the existing module and request correlation, and avoid full error objects, stacks, request/response dumps, credentials, or payloads. Review the adjacent AI-health-cache read warning for the same presentation. Keep the change local to health logging; no shared-logger redesign or new dependency.

Acceptance:

- Timeout, upstream HTTP failure, and cache-read failure produce concise warnings that still identify what failed and why; long or multiline reasons remain bounded.
- Exercise the registered handler with controlled failing dependencies and assert the emitted warnings. The existing route-registration-only test does not cover this behavior.
- Health-check timing, checks, severity, HTTP status/body, strict-mode behavior, and cached AI-health behavior stay unchanged; successful probes gain no new warnings.
- Run the package's relevant tests and required checks. Record a sanitized before/after log example so the reduction is reviewable.

No matching health-check log reduction was found in the open, blocked, or completed board. This is a sub-hour inbox item, not a milestone.

---

**Resolved 2026-09-28** — `healthz-handler.ts` now logs each failed probe as `service` plus a single-line `reason` bounded to 200 characters, with the upstream HTTP `status` or the network error `code` (read from the error or its fetch `cause`) when known; the AI-health cache-read warning uses the same shape without `service`. Module and request correlation are unchanged, and response bodies, the 5 s timeout, status codes, strict mode, and cached AI health are untouched. `healthz-handler.test.ts` now drives the registered handler through a successful run (no warnings), ledger HTTP 503, gitea `ECONNREFUSED` via fetch cause, a postgres timeout at exactly 5 s, a long multiline redis error, a cache-read failure, and strict-mode unhealthy AI. Five of those tests fail against the previous handler. `yarn typecheck`, eslint, prettier, `lint:deadcode`, and `yarn test` (290 suites, 4592 tests) pass. Shipped in `0b311baf` (`backend-cluster/backend-v2`).

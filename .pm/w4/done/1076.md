# Keep large BQL charts from crashing the query workspace

**Minor · dashboard · 40–55m · A2.** A successful150,000-row date/Decimal result throws **RangeError: Maximum call stack size exceeded** while building its chart. The Query workspace becomes a section-error panel: editor, result table and Download CSV all disappear. This is a chart-range calculation failure, not an invalid query or failed ledger read.

## Cause and bounded repair

`dashboard/src/features/bql/lib/chart-utils.ts:115–120`, `displayExponent`, evaluates `Math.max(0, ...values.map(Math.abs))`. A large supported result expands every point into a function argument, exceeding this runtime's argument capacity even though every amount is only1 or-1. It fails before ECharts receives an option.

`components/query-result-card.tsx:341` calls parseQueryChart synchronously during render, before returning its table/export UI. The exception therefore reaches the section boundary and removes the complete Query workspace. QueryResultCard is the helper's sole production caller.

The actual current module, evaluated unchanged with only its unrelated tooltip constant stubbed, repeats the150,000-row RangeError. Its1,000-row case succeeds and three-column case returns no chart. The actual parent revision of **13dfb17c0** builds a150,000-point option for the same input without throwing: that1049 tiny-range repair introduced displayExponent and this spread.

Compute the maximum with bounded argument usage, preserving the current numeric range/scaling contract and exact source-text tooltips. Keep valid large results, their virtualized table, editor and complete CSV available. Preserve1049's tiny nonzero range and ordinary/zero/negative/mixed-unit behavior. Do not truncate queries/results or remove the tiny-value repair. No dependency, API or backend change is needed. ECharts throughput after that calculation is corrected remains unverified; this report proves the earlier exception.

Acceptance: exercise the real chart parser and result-card path with the producer-backed150,000-row scalar input. It must not throw or replace the workspace; table and full export remain usable. Retain the small two-column chart, large three-column control and tiny-range regressions, then repeat both native widths and dashboard gates when implementing. QA authored no product fix or formal regression test.

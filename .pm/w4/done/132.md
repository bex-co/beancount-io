# Name the Git Clone dialog and protocol URL fields

Severity: minor. Estimate: 35m, dashboard. A2/A3: newcomers using assistive technology can identify the public example's clone popup and URL field. Repeated dashboard QA, 2026-09-18.

Environment: production beancount.io, anonymous public open_ledger/freelancer-invoicing, English/light, isolated headless Chromium149.0.7827.55;1440×1000 and fresh768×1024. HEAD26d54a9d, fetched origin/mainbd5d1d31, deployed main-BIr0jJni.js; exact deploy SHA unverified.

Do not label a textbox with the copy action or put a generic name on every Popover.

**Resolved 2026-09-19** — The popup's `PopoverContent` now carries `aria-labelledby` pointing at the `Clone Repository` heading it already renders, and each read-only URL input is labelled by its own protocol tab plus that same heading, so the two fields resolve to distinct names without borrowing the copy button's action label and without a generic name on every Popover. The associations use React `useId` values on the heading and on a span inside each tab trigger, so no new translation keys were added and nothing depends on Radix's internal ids. Both omissions were reproduced first at HEAD against the public read-only API: opening Git Clone gave a `role="dialog"` with neither `aria-label` nor `aria-labelledby` while the heading rendered visibly, and the SSH input had no name. After the change, measured in the browser at 1440×1000, the dialog's label resolves to "Clone Repository" and the SSH textbox to "SSH Clone Repository" holding `ssh://git@git.beancount.io:2222/open_ledger/freelancer-invoicing.git`; switching to the HTTP tab gives "HTTP Clone Repository" with the HTTPS URL, while its copy button keeps its own "Copy HTTP clone URL" label. Both inputs remain read-only, Escape still closes the popup and returns focus to the Git Clone trigger, and a fresh load at 768×1024 reports the same dialog and field names. `__tests__/clone-dialog-names.test.tsx` adds five cases that query by role _and_ name — a value assertion would have passed before the fix — covering the dialog name, each protocol's field name and URL, the fact that only one field is present per tab, that no textbox is named after a copy action while the copy button keeps its own name, and that the fields stay read-only; four of the five fail when the associations are removed. `CloneUrlInput` gained a required `labelledBy` prop, and the existing `clone-url-input.test.tsx` was updated to pass it (tests are excluded from the typecheck, so this was a correctness fix rather than a gate failure). Not verified: actual screen-reader speech, other engines and locales, and authenticated key management. Below 640px the trigger is deliberately hidden, so no narrow case is claimed. Dashboard gates all pass (`yarn format:check`, `yarn lint`, `yarn test` — 415 files, 4652 passed, 1 pre-existing skip — and `yarn build`). Shipped in `6436fbea` (`dashboard`).

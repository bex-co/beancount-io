# Calculate Budget's rolling range when the reader selects it

**Severity:** minor. **Estimate:** 30–45 minutes. **Owner:** dashboard. **A2:** returning to a Budget tab the next day and explicitly choosing Last 12 months should include the selection day.

## Reproduction and controls

Production `https://beancount.io`,2026-10-22; isolated owned headless Chromium155.0.8059.85, anonymous `/ledger/open_ledger/budgeting-envelopes/budget`, English/light, UTC. Fresh390×844 and1440×1000 reproduce independently. Only the owned page's Date is controlled using Playwright `Page.clock.setFixedTime`; the computer clock and timers are untouched. All API responses are real, with no modeled ledger data or hosted writes.

1. Before opening Budget, set the page Date to `2026-10-21T12:00:00Z`. Leave All time selected and wait for the actual Dining card.
2. Change only the page Date to `2026-10-22T12:00:00Z`, representing returning the next day. Use native Enter on Time span → Last 12 months.
3. The selected button has `aria-pressed=true`, but the real GetLedgerIntervalTotals request for Expenses:Dining sends `time:"2025-10-21 - 2026-10-21"`, with monthly/units unchanged. HTTP200 returns13 periods ending October21. Expanded Period data ends **2026-10-21 /135.48 USD budget /0.00 USD actual**.
4. A fresh page mounted on October22 at each width sends **`2025-10-22 - 2026-10-22`**, ending **2026-10-22 /141.94 USD budget /0.00 USD actual**. These prorated targets independently agree with the actual200USD monthly target ×21/31 and22/31.

In the original narrow tab, choosing All time and then Last 12 months again still ends October21. Reloading that same tab with its Date still October22, then selecting Last 12 months, recovers the October22 request and141.94USD final-period target. Real responses in all retained cases are200 without GraphQL errors; no route errors or page exceptions occurred. Current public data has zero actual in the final month; the concrete demonstrated discrepancy is the requested range, rendered period date and prorated target, rather than an invented missing transaction.

## Cause and bounded repair

`dashboard/src/features/ledger-data/budget/index.tsx:25–29` computes the explicit rolling range from `new Date()` and `subYears`. At:149, `useMemo(() => getLast12MonthsRange(), [])` freezes it at mount, including while All time is selected. The timeFilter memo at:151–162 returns that same frozen string on later selections;:301 passes it to every BudgetChartCard. The card sends it to the interval-total observer and uses the returned period dates for target proration. The server correctly answers the stale explicit range.

Derive this rolling range from the current browser civil day when the reader selects it, including after selecting another span and returning. Do not retain a mount-time Date. Keep query variables, period labels, target calculations and cache identity aligned. Preserve existing local-date formatting, subYears/leap-day behavior, other spans, budget history, interval controls and sparse actuals. This reproduced case requires no global clock framework, dependency, API or backend change. Continuous unattended refresh exactly at midnight is unverified and is not required to fix this explicit-selection failure.

Acceptance: mount on day21 with All time; advance the owned Date to22 without advancing timers; select Last 12 months and obtain the same22-ended query and rendered final period as a fresh22 page. Repeat after switching away/back and at both widths. Retain same-day and current span/interval controls. Use a meaningful component/observer regression for the selection path and run dashboard gates when implementing. Other time zones, year boundaries, leap-day live behavior and the repaired deployment remain unverified.

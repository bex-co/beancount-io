# Keep AI Fill cancellation quiet when going Back

**Minor · dashboard · 35–50m · A2.** Going Back during categorization cancels the request and then displays **AI categorization failed / Something went wrong. Please try again.** The cancellation is caused by the user's ordinary navigation, before any service response. The next CSV remains unmodified.

## Reproduction and controls

Production `https://beancount.io`, 2026-10-24 UTC; owned isolated headless Chromium156.0.8078.47, English/light/UTC, synthetic-ledger owner. Fresh 390×844 and 1440×1000 replacement-file journeys repeat; another desktop same-file journey confirms Back alone is sufficient.

Only SuggestTransactionCategories is held before transport. Its eventual response is browser-local; no AI request reaches the server or spends quota. Metadata and the workflow are genuine.

1. Upload a valid local CSV with two prefixed synthetic rows, Continue to Configure, and leave their targets empty.
2. Activate **AI Fill**. Hold its actual two-row SuggestTransactionCategories query. **Back remains enabled**.
3. Press Back to Preview while the query is still held. Before releasing any response, the global toast appears: **AI categorization failed / Something went wrong. Please try again.**
4. Native request-failure observers in the fresh desktop cases record **net::ERR_ABORTED** at this transition. The helper has fulfilled zero responses when the toast appears. No backend error was supplied.
5. Choose Upload Different File, upload a different one-row CSV and Continue. The same failure toast remains beside that new configuration. Its target correctly stays blank. Attempting to release the old modeled response leaves the new row and target unchanged.
6. The separate desktop Back → Continue control, without replacing the file, produces the same error and retains its two blank targets.

Two passing controls isolate the defect: Back without starting AI Fill is quiet; staying on Configure and releasing the same schema-complete local success fills both targets and truthfully reports **2 transactions** categorized. The genuine-error handling control is also covered: browser-local GraphQL errors while Configure remains mounted show useful failure feedback at both widths in the1073 evidence. Preserve that behavior.

The three departure cases establish a misleading cancellation notice. No stale result applied to a new CSV, target overwrite, server failure, lost hosted data or wrong booking was observed.

## Cause and bounded repair

`dashboard/src/features/importer/hooks/use-import-workflow.ts:handleBack` changes Configure to Preview. `components/import-workflow-container.tsx:67–78` conditionally renders Configure, so its TransactionConfigForm, lazy query and AccountMappingTable unmount.

Served/installed Apollo Client4.1.3's `react/hooks/useLazyQuery.js:54–61` unsubscribes on unmount. `core/ObservableQuery.js:1041–1059` tears down the observer and aborts active operations; its tracking promise at:1355–1388 rejects an unfinished operation as **AbortError**. The actual native ERR_ABORTED event and pre-response timing agree.

The rejection propagates from `use-ai-categorization.ts:28–33` through TransactionConfigForm's awaited categorizer. The old `account-mapping-table.tsx:handleAICategorize` catch unconditionally calls the global `toast.error(aiFailed,…)` after its component has unmounted. It has no live-owner/cancellation guard; formatting that expected abort gives the observed generic error.

Keep async feedback owned by the active configuration/attempt and treat its deliberate unmount cancellation quietly. Preserve the current cancellation, available Back/reset navigation and isolation of the replacement CSV. Keep useful service/network failures and explicit retry for an active configuration, plus current successful application/count messages. This is a local action-lifetime boundary; no global error-message suppression, retained obsolete AI request, new dependency, quota or API change is needed.

Acceptance: drive the real workflow and Apollo lazy query with a deferred response. Back before completion produces no failure toast; Back/Continue and replacement-file controls preserve their own rows/targets and ignore obsolete outcomes. Staying mounted still applies valid suggestions, and a real query-error control still reports failure and re-enables AI Fill. Repeat both native widths and run dashboard gates when implementing. QA authored no product fix or formal test.

# Resize charts when their containers become visible or change width

Severity: minor chart-layout defect. Estimate: 60m, dashboard. A2: a reader who restores a saved-hidden report chart should see its full plot and currency legend without having to resize the browser.

Environment: production https://beancount.io, anonymous synthetic open_ledger/example, isolated headless Chromium149.0.7827.55,320×800 dark and light,1440×1000 light. **Resolved 2026-09-19** — The repair this note asks for — a properly
cleaned-up `ResizeObserver` on the shared chart client — shipped in `c59830af`
while fixing `w4/087`, whose 1024px wide-sidebar case is the same missing
container observation this note records for the sidebar. `95ea4d61` then added
the theme-recreation coverage this note's acceptance also asks for.

`dashboard/src/common/components/react-echarts/client.tsx` now observes the
chart's own container alongside the existing `window` listener, so a container
that changes size without a window resize — a reveal, a sidebar width change, a
grid reflow — resizes the current instance. The observer is created once,
survives the dispose/init cycle of a theme change because the handler reads the
instance ref at call time, and is disconnected on unmount. `window` resize
behaviour, instance refs, options, loading state, lazy loading and the SSR
placeholder are unchanged, and nothing in zrender or the hidden/inert wrapper
from `w3/127` was touched.

Verified in a real browser at HEAD, on the exact mechanism this note traced:
collapse the charts until the section really is `display:none`, change the
viewport from 320 to 900 while it cannot measure itself — the canvas attribute
falls back to `100`, which is the zrender `parseInt(root.style.width)` fallback
named here — then reveal it with nothing dispatching a window resize. The
canvas comes back at 596px matching its 596px host. 6/6 checks across Cash Flow
in light and dark and Balance Sheet, the sibling report this note asked to
confirm. A normal visible-mount control stays correct, and the
container-width-only case was separately confirmed on Commodities at 1024px
with a 384px sidebar.

Two regression cases in
`react-echarts/__tests__/client-lifecycle.test.tsx` drive container-size
notifications with no window resize and assert cleanup and theme recreation;
both fail when the observation is removed. Gates from `dashboard/`:
`yarn format:check`, `yarn lint`, `yarn test` (388 files, 4390 passed, 1
pre-existing skip) and `yarn build` all pass.

Not reproducible as written, and filed separately: this note's own repro —
saving the hidden preference and reloading — no longer reaches a hidden chart
at mount, because a report loaded with charts saved-hidden now renders the
section expanded while its toggle reports collapsed. That is a different defect

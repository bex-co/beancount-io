**Resolved 2026-09-19** — Reproduced against a local build: on the public
stock-example ACME account at Monthly / At Cost, neither `14,598` nor `4,092`
appeared anywhere on the page at 390px or 1440px before hovering the canvas.

`features/reports/account/index.tsx` rendered `accountBalanceData` and
`intervalTotalsData` through their charts with no data alternative. Both series
share the date/balance shape, so one small presentation now serves both views:
`chart-period-table.tsx` offers a named, keyboard-reachable disclosure listing
the periods the chart plots with every unit each holds. It never sums across
commodities and never invents a value — a period returned with no balances, or
with a null unit, shows a dash, which is not the same as an explicit zero. It
reads the settled series introduced for `w4/099`, so it cannot present a
previous selection as a new one, and it renders nothing for an empty, loading
or failed read. Each table is named by its own card, since both sit on one
page. No request, dependency or backend change, and the responsive journal
columns and `m40` semantics are untouched.

Verified in a real browser, 5/6: after Enter on the disclosure the balance
reads `2026-02-28 / 14598 USD` at 390px and 1440px, the change reads
`2026-02-28 / -4092 USD`, switching Monthly to Yearly takes the table from 12
rows to 1 in step with the chart, and an aborted `GetLedgerAccountReport` leaves
no table at all.

Reported honestly: the sixth live check looked for a multi-unit period and
found none — the sampled accounts are single-unit under At Cost — so multi-unit
data is covered by the rendered cases rather than live. Seven rendered cases in
`account/__tests__/chart-period-table.test.tsx` cover the named disclosure, a
negative change, a multi-commodity period listing each unit with no combined
total, the sparse/zero/null distinction, an empty series, the per-card table
name, and a changed series; removing the null filter fails the sparse case.
jsdom does not implement `<summary>` activation, so the open/close behaviour is
covered by the browser run rather than there. Gates from `dashboard/`:
`yarn format:check`, `yarn lint`, `yarn test` (399 files, 4474 passed, 1
pre-existing skip) and `yarn build` all pass. Actual screen-reader speech,
touch assistive technology and other engines remain unverified. Shipped in
`c0bfd00a` (`dashboard`).

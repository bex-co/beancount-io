# Show the required Source Account error during import configuration

**Severity:** minor validation/accessibility. **Estimate:** 15–30 minutes, dashboard. **A2:** a customer finishing account mapping should receive a readable explanation when the required source account is empty, including an error association usable without color.

Production https://beancount.io, 2026-10-21, English/UTC, dedicated synthetic-ledger QA account, owned isolated headless Chromium155.0.8059.85. Independent fresh1440×1000 pointer and390×844 native-keyboard submission cases. Real CSV/configuration UI and healthy reads; no response/transport faults. Validation rejects every attempted submit before an import callback or mutation; no transaction is booked.

## Reproduction and controls

1. At `/ledger/<qa-owner>/<synthetic-ledger>/import`, choose a two-row UTF-8 Date,Payee,Description,Amount CSV with synthetic-1.25/2.50 entries. Continue to Configure and wait for named Source Account/Currency controls. Keep USD, assign both selected rows a legal nonempty target such as Expenses:Food, and leave Source Account empty. The missing-target warning is gone.
2. Activate Import2Transactions by pointer at1440 or focused-button Enter at390. Source Account changes aria-invalid=false→true and gains invalid styling, but **Source account is required** is absent. No alert/error text explains the rejected submit. Focus remains on Import.
3. Its aria-describedby now names a form-item-message ID whose element does not exist. Both fresh widths reproduce. The validation itself works:0 import/mutation attempts and the configuration stays mounted. This is missing textual/associated feedback, not accepted invalid accounting data.
4. Passing control in each context: set Source Account to Assets:Cash; its invalid state clears. Clear Currency and submit while it is empty. **Currency is required** appears, Currency is invalid, and its message reference resolves to that exact text. Restore USD: the error clears and both fields are valid. Do not activate a fully valid Import.

## Cause and bounded repair

`dashboard/src/features/importer/components/steps/configure/transaction-config-form.tsx:65–70` correctly defines the localized sourceAccountRequired constraint. The Source Account FormItem at:213–239 renders its label, AccountCombobox and hint but omits FormMessage. The same component already imports FormMessage and renders it for Currency at:259. Shared FormControl therefore supplies the normal error ID when source validation fails, but this caller supplies no message node to resolve it.

Render the existing field error in the Source Account item and keep its programmatic association intact, following the working Currency pattern. Reuse importer.configure.sourceAccountRequired; no new translation key, dependency, API or validator is needed. Preserve invalid-submit refusal, values, targets/selection, existing currency feedback and valid import behavior. The observed focus state is context; this bounded repair need not redesign generic combobox focus.

Acceptance: with valid row targets/currency and an empty source, native submission shows the localized required message, resolves the field's error reference and attempts0 writes. Correcting the source removes the error; missing Currency still gives its own working message. Repeat both widths, use appropriate existing form/accessibility checks, and run dashboard format:check, lint, test and build on implementation. No string-mirroring test or hosted booking is necessary for this missing markup.

## Outcome

Re-ran every check against a fresh production build of the shipped code:
**9/9** credential checks and the full noscript matrix.

Definition of done, clause by clause:

- **Delaying or failing the client entry script cannot produce a
  credential-bearing GET.** With JavaScript disabled, login (by click *and* by
  Enter, at 1440x1000 and 390x844) and sign-up now record **one navigation —
  the page load itself**. Before, a second navigation carried the fields; now
  there is no submission at all, and the form declares `method="post"` so even
  one could not serialize to a URL. No `password` key appears anywhere.
- **Hydrated authentication, validation and `next` routing still work.** The
  submit button enables after hydration at both widths, and an empty submit
  shows "Email is required" / "Password is required" with the `next`-bearing
  route unchanged — the healthy control FINDINGS recorded. The shared consent
  form contracts are untouched: `consent` and `mobile-consent` already declared
  `method="POST"` with explicit actions, and `identity-consent` inherits the
  guard through the same two components.
- **Browser regressions intercept before transmission and cover both states.**
  Every attempted navigation was aborted in the browser. The vulnerable window
  is covered with JavaScript disabled; the healthy controls are covered
  hydrated. 11 committed cases assert the server output directly, each guard
  load-bearing on its own (2 failures apiece when reverted).

Beyond the stated criteria, the reader is no longer left in a **misleading
usable state**: without scripts both forms now explain themselves — *"Sign-in
needs JavaScript. Please enable it and reload this page."* — in all fifteen
locales, and that notice disappears once the button works.

Not exercised, deliberately and by this milestone's own rules:

- **No real credential, account, email, OTP, password reset or authentication
  mutation.** Fixtures are synthetic throughout
  (`qa-fixture@example.invalid`, `NotARealSecret-000`), and no attempted
  submission ever reached a server.
- **The forgot-password form was not submitted** — that would send a real reset
  email.
- **The OAuth consent routes stay source-verified.** They require a valid
  `uid`; no authenticated consent was performed.
- **Chromium only**, with emulated viewports. This is a controlled
  script-delay reproduction, not a measurement of how often it happens in the
  wild.

Related and deliberately untouched: [w4/137](../../137.md), the signup default
overwriting early input, is independent of this issue and stays open.

Gates from `dashboard/`: `yarn format:check`, `yarn lint`, `yarn test` (385

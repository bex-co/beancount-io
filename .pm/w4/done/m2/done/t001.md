## Objective

Build the renderer-neutral cash-flow data model: extend the existing activity categorizer into a shared operating/investing/financing classification, define the cash-and-cash-equivalents (CCE) account set heuristic, and net out transfers between cash accounts so inflows/outflows are never double-counted.

## Context

- `dashboard/src/features/reports/overview/lib/account-categorizer.ts` — existing heuristic (`source/operating/investing/financing/exclude`) used by the Sankey; extend it, don't fork it.
- `dashboard/src/features/reports/export/model.ts` — exact-decimal string amount conventions to follow.
- ADR002 "Decision" part 1 and "Classification strategy" — transfers between cash accounts net to zero (data-pipeline rule).
- Client-side only: compose from `GetLedgerOverview` hierarchies + interval series; no new backend queries.

## Steps

1. Extract/extend the categorizer into a shared module the Sankey and the statement both use.
2. Implement the documented CCE heuristic (checking/savings/cash-style asset accounts).
3. Implement transfer netting between CCE accounts.
4. Unit-test classification, CCE set, and netting on realistic hierarchies (incl. brokerage, credit-card payment, mortgage principal cases from ADR002).

## Files

- `dashboard/src/features/reports/overview/lib/account-categorizer.ts` (extend/move)
- new `dashboard/src/features/reports/cash-flow/lib/` (model + tests)

## Acceptance criteria

- [ ] Given a hierarchy with inter-cash transfers, statement inflow/outflow totals exclude them (net to zero).
- [ ] The Sankey renders unchanged output after the refactor (shared categorizer, no behavior change).
- [ ] Unit tests cover the ADR002 misclassification-prone cases.

## Out of scope

- Account-metadata classification overrides (`cashflow: operating|investing|financing`) — deferred follow-up per ADR002.

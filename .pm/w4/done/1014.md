## Cause and bounded repair

`dashboard/src/features/journal/components/new-directive-dialog/transaction-form.tsx:335–343` prevents default for Ctrl/Meta+Enter and calls `submit()` directly. The button's normal form submission receives browser constraint validation; this application shortcut does not. `common/hooks/use-pending-submit.ts` calls react-hook-form's `handleSubmit`, which runs the Zod resolver without checking native validity.

The controlled `type="number"` amount at `transaction-form.tsx:554` exposes an empty value for these bad-input states. Installed react-hook-form's Controller reads `event.target.value` (`dist/index.esm.mjs:15–19,429–436`); its resolver path at 2164–2198 validates that stored string. The amount schema explicitly allows empty strings for auto-balance. `transaction-auto-balance.ts` then infers/applies `12.50` to what it receives as empty. Zod cannot recover the unfinished browser token from that value.

Make the shortcut use the form's native validation/submission path, or explicitly honor native validity before entering the existing submit guard. `requestSubmit()` is an available native route; `form.submit()` also bypasses validation. Preserve pending protection, the composing-key exclusion, exact decimals, account checks, genuine blank inference and failed-write draft/focus recovery. Keep this within TransactionForm unless a demonstrated shared caller needs a change; no global Input rewrite, API/parity work, dependency or loss of supported exponent input is needed. NewDirectiveDialog is its only production owner. Balance, Note and Account do not share this form's modifier handler.

Acceptance: native browser-keyboard `1e` and `-` cases at both widths emit zero requests for either modifier and retain a repairable draft with useful feedback. Blank and complete-exponent controls submit exact postings once; button/ordinary Enter, composition and a held pending write retain their existing behavior. Include a meaningful regression at the actual form/native-validity boundary: assigning a string to a jsdom number input alone does not reproduce the browser's editable bad-input state. Run dashboard gates when implementing. QA authored no product fix or formal tests.

# Settings sends iOS users to the "Apple Store" — which is a different Apple product

**Severity:** trivial. **Estimate:** 5 minutes. Owner: mobile. A3: the review prompt is a distribution surface, and it names the wrong store. "Apple Store" is Apple's retail/hardware app; the place you rate an iPhone app is the **App Store**. The Android arm says "Google Play", which is correct — so the row reads as carefully written and is wrong on exactly one platform.

Environment: branch `main`, HEAD `038faeeb`, native development build `io.beancount.ios` on iPhone 17e / iOS 26.5, English / System / light. Report-only QA.

## Repro

Open `beancount:///(app)/settings`. Under **Support**:

> **Like it? Give it a review :)**
> Apple Store

## Root cause

`src/screens/setting/main-content.tsx:141`:

```tsx
content={Platform.OS === "ios" ? "Apple Store" : "Google Play"}
```

The destination itself is right — `:145` opens `https://apps.apple.com/us/app/id1527950512`, which is the App Store listing. Only the label is wrong.

## Fix

```tsx
content={Platform.OS === "ios" ? "App Store" : "Google Play"}
```

Both are proper nouns and both should stay untranslated, so leaving them as literals rather than moving them into `t()` is correct — Apple and Google use the same names across locales. (The neighbouring hardcoded strings in this file that *should* be translated are the separate `w4/043`.)

**Acceptance:** the Support row's subtitle reads `App Store` on iOS and `Google Play` on Android; tapping it still opens `apps.apple.com/us/app/id1527950512` in the in-app browser.

## Blast radius

One string on one row. No behaviour change. The same sweep found no other occurrence of "Apple Store" anywhere in `src/`, `metadata/`, or the store listing copy — `metadata/` uses "App Store" correctly throughout, so this is an isolated slip rather than a pattern.

Not exercised: Android (the `Google Play` arm was read, not run), dark mode, enlarged Dynamic Type, and whether `WebBrowser.openBrowserAsync` on a real device offers the native review sheet instead (a separate product question — `expo-store-review` exists and would be the better affordance, but changing the mechanism is not part of fixing the label).

## Adjacent states

The `/us/` segment hardcoded into the App Store URL is worth a second look but is **not** filed: Apple redirects a storefront-less or mismatched-storefront link to the user's own region, so it works, and asserting it should be region-derived without testing from another storefront would be a guess. Noting it here so the next person does not have to re-derive that.

The rest of the Support section is correct: the Help Center row opens `https://beancount.io/docs/help-center`, both rows use `WebBrowser.openBrowserAsync` (in-app browser, so the user returns to the app rather than being handed to Safari), and both carry translated titles.

## Dedupe

Searched all `.pm/**/*.md` including `done/` for App Store, Apple Store, review-prompt and settings-copy terms. The App Store items on the board (`w2` metadata milestones, `mobile/metadata/`) are about the store *listing*, not this in-app label. `w4/043` is the same file's untranslated-strings defect and should be fixed in the same sitting. No item covers this.

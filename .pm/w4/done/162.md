# Make the BQL editor's Comment shortcut produce supported comment syntax

Severity: **minor**. Package: **dashboard**. Estimate: **45–60m** including a
real editor regression check. Source: continuous dashboard QA for w4. **A2**:
annotating a query with the editor's built-in action must not make it invalid.

## Reproduce

Production `https://beancount.io`, anonymous public synthetic
`open_ledger/example`, English/light, owned isolated headless Chromium
149.0.7827.55. Desktop 1440×1000 and fresh-load repeat at 390×844. Local main
`390568c2`, deployed entry `main-d5j4FX-V.js`; exact deployed revision unverified.

1. Open `/ledger/open_ledger/example/query`.
2. Enter two lines: `QA query note`, then `SELECT account LIMIT 1`.
3. Put the caret on the first line and use Monaco's **Toggle Line Comment**
   shortcut, Cmd+/ on the tested Mac. The editor generates:

   ```sql
   -- QA query note
   SELECT account LIMIT 1
   ```

4. Click **Execute Query**. The card reports invalid input. Its real GraphQL
   `QueryShell` response is HTTP 200, `data.queryShell: null`,
   `extensions.code: BAD_USER_INPUT`, and:

   ```text
   Invalid BQL query: syntax error at position 0: found '-' expected identifier
   ```

5. Fresh-load the Query page, repeat the actual keyboard action at 390px, and
   execute: same generated text and failure. Reloading that query URL also
   fails after execution settles.
6. Working control: replace the first line with `/* QA query note */`, leaving
   the SELECT unchanged. The real UI and an independent GraphQL read return
   the one-row `Assets:US:BofA:Checking` table, matching the plain SELECT.

The backend correctly rejects unsupported syntax. This finding concerns the
editor generating it, not a request to expand BQL or repair the generic error
message (tracked separately by w4/160).

## Cause and repair

`dashboard/src/features/bql/pages/index.tsx:257–260` explicitly registers
`lineComment: "--"` for its SQL-based BQL editor, while also registering the
supported block delimiters. Installed Monaco 0.55.1's
`esm/vs/editor/contrib/comment/browser/lineCommentCommand.js:29–36` reads that
token; `:194–208,244` supports falling back to block comments when no line
comment token is available. The keyboard reproduction confirms the production
configuration emits the declared token.

Configure the BQL editor's comment command to emit and toggle supported
`/* ... */` comments while preserving the selection and query. Verify the
effective merged Monaco language configuration, not just the source object:
the built-in SQL language also has defaults. Keep the existing registration
disposal and remount behavior. Do not add `--` preprocessing to the dashboard
or engine, alter quoted query strings, or change arbitrary SQL editors.

The server's existing `stripBqlBlockComments` calls in
`backend-cluster/ledger/src/features/ledger/service/ledger-shell-service.ts:96,112`
explain the working block-comment control. Error classification is performed
at `:127–133`; backend-v2's shell service/resolver forwards it to the browser.
No API/engine change is needed.

- [ ] Commenting the note through the real editor command yields a runnable
      query with the same one-row result as its uncommented SELECT.
- [ ] Toggling the comment off/on restores the note and then the valid comment;
      selection/multiline behavior stays coherent.
- [ ] Regression coverage invokes the actual Monaco comment action, or a
      browser check verifies the effective language registration and resulting
      executable text. Do not merely assert a configuration literal.
- [ ] Reopening the Query page does not duplicate registrations or restore the
      incompatible token. Run the dashboard gates when implementing.

Blast radius: this is the sole production `defaultLanguage="sql"` and
`setLanguageConfiguration("sql", ...)` site found in dashboard. Its button,
keyboard execution, URL reopening, and history feed the same BQL execution
path. No unrelated editor repair is implied.

Dedupe: searched all board files, including done/blocked work and open
milestones, for BQL comments, line comments, Toggle Comment, and editor comment
configuration. Completed w3/102 fixed *supported block comments* at the engine
boundary and explicitly excluded `--`; w1/026 covers the CLI's leading-comment
dispatch and likewise records `--` as unsupported. The new failure is the
dashboard's own generated syntax. `git log -S 'lineComment: "--"'` traces the
unchanged setting to `af5339de`; no pending or already-landed repair was found.

Evidence under `dashboard/tmp/qa-20260921-loop/`:
`bql-line-comment.json` (desktop generated text and real response),
`bql-line-comment-repeat-390.png` (keyboard action, transient pending frame),
`bql-line-comment-settled-390.png` (fresh URL after settlement), and
`bql-comment-graphql-control.json` (failing line/successful block pair).
`bql-comment-repeat-control.json` records the successful UI control and the
REST check's limitation: both anonymous REST query requests were refused with
401, so no REST syntax-behavior claim is made. MCP was not exercised.

Unverified: Windows/Linux Ctrl+/, other browsers/locales, actual screen-reader
speech, authenticated queries, and multi-selection editing. No production
writes, product fixes, dependency changes, or shipping occurred.

---

**Resolved 2026-09-23** — The query editor now uses its own `bql` Monaco language instead of borrowing `sql`: a block-comment-only configuration, so Toggle Line Comment emits and removes `/* … */`, plus a small Monarch tokenizer and the snippet completion provider, all disposed on remount. The fix goes beyond the note's proposed config edit: Monaco's built-in SQL configuration (also `--`) loads lazily and could register after the page's on a first visit, so editing the `sql` configuration alone would not have held. `features/bql/lib/__tests__/bql-language.test.ts` drives the real Monaco comment action (single line, toggle off, multi-line, remount) with a later-registered SQL `--` configuration present, and fails if `lineComment: "--"` is restored. Not re-verified on production or with a real keyboard in a browser. Shipped in `4c3668d1` (`dashboard`).

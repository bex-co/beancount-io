# MCP `manageApiKeys` advertises an empty input schema, so agents cannot discover its arguments

**Severity:** major. **Estimate:** 45–60 minutes. **Owner:** backend-v2 (MCP
adapter only; REST and GraphQL are unaffected). **A1:** the one destructive
key-management tool on the agent surface publishes no `operation`, no field
names, and no `format: date-time`, so an agent has to guess `id`, `scopes`,
`ledgerScope` and `expiresAt` from prose — the exact discoverability w2/m27
set out to fix.

Found 2026-09-15 by MCP QA against `main`, HEAD `fbdffde8`, driving the real
registry (`assembleMcpRegistry`) through the MCP SDK's in-memory transport
with stubbed services (`@modelcontextprotocol/sdk` 1.30.0). No credential or
hosted call was needed; the schema is computed from the descriptor.

## Repro

```ts
// backend-cluster/backend-v2, ts-node -r tsconfig-paths/register --transpile-only
import { Client } from "@modelcontextprotocol/sdk/client/index.js";
import { InMemoryTransport } from "@modelcontextprotocol/sdk/inMemory.js";
import { assembleMcpRegistry } from "@/server/api/composition-root";
import { config } from "@/config/config";
const identity = { userId: "u", method: "oauth", scopes: new Set(["ledger.admin"]), ledgerScope: "a/b" };
const server = assembleMcpRegistry({ identity, ledgerId: "a/b" } as never, config);
const client = new Client({ name: "qa", version: "1" });
const [a, b] = InMemoryTransport.createLinkedPair();
await Promise.all([client.connect(a), server.connect(b)]);
const { tools } = await client.listTools();
console.log(JSON.stringify(tools.find((t) => t.name === "manageApiKeys")!.inputSchema));
// {"type":"object","properties":{}}
console.log(JSON.stringify(tools.find((t) => t.name === "manageLedgers")!.inputSchema.required));
// ["operation"]   <- control: every other grouped tool advertises its fields
```

Calling `manageApiKeys` with `{}` is still refused by the SDK's input
validation ("Invalid option: expected one of list|create|revoke"), so the
runtime contract and the advertised contract disagree.

## Expected

`tools/list` publishes the same object schema the other grouped tools do:
`operation` as a required enum of `list | create | revoke`, plus `name`,
`scopes`, `ledgerScope`, `expiresAt` (`format: date-time`) and `id` with
their descriptions. `docs/mcp.md` promises exactly this ("MCP key creation
advertises camelCase `ledgerScope` and ISO 8601 `expiresAt`
(`format: date-time`)").

## Actual

`{"type":"object","properties":{}}` — no properties, no `required`, not even
the `$schema`/`additionalProperties` keys every other tool's schema carries.

## Root cause

`src/features/ai-agent/tools/api-key-tools.ts:117` wraps the strict object
schema in `z.preprocess(...)` to fold the deprecated `ledger_scope` /
`expires_at` spellings. The SDK converts a tool's `inputSchema` to JSON Schema
by introspecting a Zod object; a `ZodEffects`/preprocess wrapper is opaque to
it, so it publishes an empty object. Introduced by `b6bbd37e` (w2/m27,
2026-09-09), whose own task text says the advertised input should carry one
`expiresAt` with `format: date-time` — the alias cleanup shipped, the
advertisement regressed to nothing. `mcp-tool-list.test.ts` asserts names
and descriptions but never inspects a published `inputSchema`, which is why
this passed.

## Fix

Publish a plain `z.object` (declare `ledger_scope` / `expires_at` as optional
deprecated fields with a one-line description, or drop them now that the
"one release" grace period has passed) and normalize aliases inside
`executeManageApiKeys` before the strict parse. Add a `mcp-tool-list` test
that fails when any tool's published `inputSchema.properties` is empty, and
one asserting `manageApiKeys` advertises the `operation` enum and
`expiresAt.format === "date-time"`. Refresh the note in `docs/mcp.md` if the
snake_case spellings are removed. Run `yarn typecheck` and `yarn test`.

---

**Resolved 2026-09-16** in `fix(backend-v2): publish manageApiKeys's input schema in tools/list`. The `z.preprocess` wrapper is gone: `manageApiKeysInputSchema` is now a plain `z.object` the SDK can convert, so `tools/list` publishes `operation` as a required `list | create | revoke` enum plus `name`, `scopes`, `ledgerScope`, `expiresAt` (`format: date-time`) and `id` with their descriptions. The advertised object is loose rather than strict so the deprecated `ledger_scope` / `expires_at` spellings still survive the SDK's parse; `executeManageApiKeys` folds them — the documented spelling still wins a conflict — and then re-parses against the strict schema, so an unknown field is still refused, now as the tool's own `{ ok: false }` rather than a transport error.

**Deviation.** `docs/mcp.md` is unchanged: the snake_case spellings stay accepted, so what it says is still true. Removing them is a contract change the note listed as optional and the code comment gates on "one release"; it is not folded in here.

**The `tools/list` size gate moved from 61 KB to 63 KB.** Publishing the schema costs 1.4 KB, 0.4 KB of it the ISO 8601 pattern for `expiresAt`. w2/m27:t005 recorded that it had deleted that regex; what it had actually done was publish the whole schema as `properties: {}`, so the saving it measured was this bug. The gate's comment now says so.

**Tests.** `server/api/__tests__/mcp-tool-list.test.ts` gains two cases: one that fails when any tool but `deleteAccount` (which takes no arguments) advertises empty `properties`, and one pinning `manageApiKeys`'s `required`, its `operation` enum, `expiresAt.format === "date-time"`, and that only the six camelCase spellings are advertised. Both fail against the old schema. The existing alias-acceptance cases in `features/apikeys/__tests__/api-key-authorization-parity.test.ts` — the snake_case create and "prefers the documented spelling when both key spellings are sent" — still pass unchanged. `yarn typecheck` and `yarn test` pass, with 4520 unit tests; `yarn generate-v1-openapi` reports no drift.

**Not exercised.** The hosted endpoint — this was verified in-process through the SDK's in-memory transport, as the note's repro was.

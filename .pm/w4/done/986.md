# Default a newly opened Budget or Open Account form to the opening day

**Severity:** minor. **Estimate:** 45–60 minutes. **Owner:** dashboard. **A2:** a reader returning to a tab the next day should not begin a new dated directive with yesterday silently selected.

## Reproduction and controls

Production `https://beancount.io`,2026-10-22; isolated owned headless Chromium155.0.8059.85, English/light, authenticated designated synthetic ledger, UTC. Add Budget and Accounts → Open Account each reproduce independently at390×844 and1440×1000. Control only the owned page's Date with `Page.clock.setFixedTime`; do not advance timers or change the computer clock. All reads are real; no form is submitted or mutation attempted.

1. Set the page Date to **2026-10-21T12:00:00Z**, then open `/ledger/<qa-owner>/<synthetic-ledger>/budget` with its dialog closed. Wait for hydration and the existing native Add Budget handler before continuing.
2. Set Date to **2026-10-22T12:00:00Z** and use native Enter on **Add Budget**. This first new form opens with **10/21/2026**, despite the browser now being on October22. Both fresh widths reproduce.
3. Independently repeat on `/accounts`, leaving its Open Account dialog closed while changing day21→22. Activate **New** at390 or **Open Account** at1440. Open Date again defaults to **10/21/2026** at both widths.
4. Same-day controls mounted and opened on October22 correctly show **10/22/2026**: fresh narrow Budget and fresh desktop Accounts. The date utility itself resolves the controlled current day correctly.

Two further controls must remain correct: explicitly type October23 while Budget390 or Open Account1440 is open, then change the owned Date to October24 and edit another field. The explicitly chosen date stays **10/23/2026**. Cancel and reopen on October24: the current close/reset path then correctly starts **10/24/2026**. The failure is a new opening after the form spent the day boundary closed, rather than an expectation to overwrite an existing draft at midnight.

## Cause and bounded repair

Both dialog components stay mounted while closed. `budget/add-budget-dialog.tsx:117–145` and `accounts/open-account-dialog.tsx:62–81` initialize useForm with `date:todayIsoDate()`, and their resetForm refreshes that default. Their open-state effects explicitly **return when open is true** and reset only on mount/close. Opening the following day therefore keeps the old closed-state reset value. The installed react-hook-form implementation retains the initialized default state until reset; re-evaluating the useForm options during render does not refresh the stored field. Both onSubmit paths use the selected data.date directly; this run did not submit or assert a persisted backdated directive.

Initialize the default date from the current local civil day when a genuinely new form opens. Keep an already open draft's explicit date intact, including across a day change, and retain existing Cancel/reopen behavior. Preserve other default/locked fields, amount precision, validation, pending write locking, opening/session counters and stale completion guards from284/295. Do not reset every render, add a global clock system, change the user's date automatically while editing, or repair this only by changing DatePicker's display. No API, dependency or backend change is needed.

Acceptance: mount each real page with its form closed on day21; after the owned Date becomes22, first-open defaults to22 at both widths. Retain same-day controls, explicit23 across day24, Cancel/reopen24 and pending/draft isolation regressions. Add a meaningful actual-form lifecycle regression and run dashboard gates when implementing. BudgetChartCard's Update entrypoint shares AddBudgetDialog but was not live exercised here; the page's Add and Accounts' Open were. Journal's separate New Entry forms, non-UTC zones, month/year boundaries, actual booking and the repaired deployment remain unverified.

**Resolved 2026-10-22** — AddBudgetDialog and OpenAccountDialog now reset their draft when they open as well as when they close, so a new draft's date defaults to the day it opens.

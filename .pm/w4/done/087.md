**Resolved 2026-09-19** — Reproduced at 320px against a local build of the
public crypto example: the card measured 367.47px (x8–375.47) inside a 304px
grid, the history button ended at x350.47 outside the viewport, and the content
scroller reported clientWidth 320 / scrollWidth 375 while the document stayed
320 wide.

Three causes, all fixed in
`dashboard/src/features/ledger-data/commodities/index.tsx`,
`commodity-price-history.tsx` and
`dashboard/src/common/components/react-echarts/client.tsx`:

1. The grid had no column template below `md`, so its implicit `auto` track
   sized to the widest card's max-content. Both the data grid and the loading
   grid now declare `grid-cols-1`, which resolves to `minmax(0, 1fr)` at every
   breakpoint, and the cards and chart box carry `min-w-0`.
2. The history button inherited `whitespace-nowrap` from the shared Button, so
   the 317.47px label set the card's minimum width. It now wraps, scoped to
   this button — the shared Button is untouched, the full accessible name is
   preserved, and the keyboard disclosure added in `a4194ff3` still works.
3. Charts resized only on `window resize`, so widening the sidebar from 256 to
   384px at 1024px left a 302px canvas inside a 288px card — child overflow
   with no page overflow. The shared chart client now observes its own
   container.

After the fix, at 320px the card is 304px flush with the grid and the button
254px ending at x287, with no overflowing scroller. Verified in a real browser
at 320, 390, 1024, 1024 with the 384px sidebar, and 1440: 40/40 checks pass —
Show and Hide both fit their card and the viewport, Enter expands with focus
retained, and all seven history rows keep their date and price strings. The
Overview and balance-sheet charts were re-checked at 320 and 1440 because the
resize fix is in the shared client. Two regression tests were added and proven
load-bearing by reverting each fix. Shipped in `c59830af` (`dashboard`).

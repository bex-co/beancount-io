# Keep a calendar-cleared date visibly empty

**Minor · dashboard · 40–55m · A2.** Residual of [239](./done/239.md): clearing through the calendar bypasses the working typed-clear/default-echo guard. The field displays today's valid-looking date beside **Invalid input** and a disabled submit button. No submit or incorrect booking was observed.

## Reproduce and working controls

Expected: when the calendar clears the selected date, keep its empty display aligned with the form value and error until the reader chooses/types a valid date or deliberately resets. Preserve the widget's existing ability to clear; this does not require banning deselection, inventing today's date, or changing date/schema contracts.

## Cause and bounded repair

`dashboard/src/common/components/ui/date-picker.tsx:143–150` handles typed clearing by publishing undefined and setting `heldDraft:true`, so the sync effect refuses react-hook-form's initial default echo. But `commitDate` at:153–160 unconditionally clears that hold, even for undefined. `handleCalendarSelect` at:162–164 calls it when the single-selection calendar deselects its current day.

`open-account-form.tsx:51` initializes the Controller with `todayIsoDate()`. RHF's default fallback returns that original day when the field value becomes undefined. DatePicker's unheld sync effect at:99–134 treats the echo as a deliberate value change and formats today into the input. The schema-backed form remains invalid, and FormControl correctly forwards that invalid state; the error/disabled state is not the defect. The visible date is.

DatePicker also computes `selected` directly from the echoed value at:172, without considering its held empty/invalid draft. That explains the selected default inside the blank-field calendar and why clicking its day toggles back to undefined. Fixing only the input's empty hold would leave that selection inconsistency.

Give calendar-originated undefined the same held-empty/default-echo treatment as typed clearing, and keep the calendar selection consistent with the held draft instead of its echoed default. Preserve actual date selection, Today recovery, genuinely optional blank dates, strict Gregorian/canonical-string handling, locale reformatting and deliberate external resets. Coordinate the shared component with [1069](./1069.md)'s separate pending-calendar lock; do not merge their distinct causes or weaken either contract. No API/backend, dependency, new draft store or other package change is needed.

Seven DatePicker consumers share the primitive: all four New Entry forms, Accounts Open Account, Add Budget and Receipt Review. Only New Entry Account and Accounts Open Account were natively exercised here; other callers need compatible coverage without an AI/receipt operation.

Acceptance: real DatePicker + useForm/Controller regressions activate the already-selected calendar day by pointer and keyboard after a valid edit, then assert an **empty** invalid display and disabled schema-required submit. Also clear by typing, reopen the calendar, and choose the current day: it must become a valid date, with no phantom prior selection preventing it. Keep the passing typed-clear control, different-day/Today recovery, optional blanks and explicit resets. Existing239 tests only clear the text with `user.clear`; valid-calendar and year-range tests never exercise calendar deselection. Repeat narrow/desktop and run dashboard gates when implementing. QA authored no product fix or formal tests.

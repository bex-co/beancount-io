# Show when each change happened in native Recent Changes

**Severity:** minor. **Estimate:** 30–45 minutes. Owner: mobile. A2/A3: a section titled "Recent changes" is the app's answer to "is this public ledger maintained?", and today it cannot answer it.

Environment: branch `main`, HEAD `038faeeb`, native development build `io.beancount.ios` on iPhone 17e / iOS 26.5, English / System / light / default text size, authenticated production session at `https://beancount.io`, public `open_ledger/alphabet`. Report-only QA; no ledger mutation.

## Repro

1. Terminate and relaunch the app. Tap the **bell** in the header.
2. Under **RECENT CHANGES**, each row shows only a message, an author name, and a short SHA — `Add Q2 2026 quarterly report data / Dora Noda 6c15574`, `Add README.md / Tian Pan 7c6545b`, `Rebuild FY2022–FY2025 balance sheets from primary filings, add Q1 2026 / Tian Pan c3372c3`, `update / Dora Noda e0944d1`, `update / Tian Pan c3b0d1d`. **No dates.**
3. Tap the first row. Commit detail `6c15574` shows the message, `Author: Dora Noda`, `STATS +137 −0`, a `FILES` list (`2026/Q2.bean +135 −0`, `2026/year.bean +1 −0`, `main.bean +1 −0`) and the unified diff. **Still no date.**
4. Relaunch and repeat. Both screens reproduce with no timestamp anywhere.

**Expected:** each change is dated, so "recent" is verifiable and two commits both titled `update` are distinguishable.
**Actual:** nothing in the list or the detail says when any change happened; the two `update` rows are separable only by their SHAs.

## Root cause

Not a data gap — the field is already in the schema and is non-nullable. `src/generated-graphql/types.ts:220-225` defines `CommitAuthor` with `date: Scalars['String']['output']` (required), and both `CommitListItem.author` (line 248) and `CommitDetails.author` (line 229) carry it. The mobile query simply never asks for it: `ListCommitsDocument` (`src/generated-graphql/graphql.tsx:2160-2170`) selects `sha shortSha message author { name }`. `notifications-screen.tsx` renders only those, and `notifications-screen/formatting.ts` has helpers for the error location and the short SHA but none for a date. `commit-detail-screen.tsx` does the same for `getCommitDetails`. No comment or test records this as a deliberate omission.

## Fix

1. Add `date` to the `author` selection in both the `listCommits` and `getCommitDetails` operation documents, then re-run `yarn codegen` (`src/generated-graphql/` is generated — do not hand-edit it).
2. Render the date on the commit row next to the author/SHA line, and on the commit detail beside `Author:`.
3. Reuse the existing `formatFeedDate` (`src/common/date-format.ts:96`) rather than adding a formatter: a commit carries a real instant, not a ledger day, so it belongs in the device's zone, and that helper already returns `""` for an unparseable or missing value instead of dating it to 1 Jan 1970. Pass the locale from `useTranslations`/`localeVar` so it re-renders on a locale change.

Keep the row layout's existing two-line shape; the date joins the muted author/SHA line rather than adding a third line. No backend, API, or cross-package change is needed — the field already exists and this costs nothing extra on the wire.

**Acceptance:** on a fresh iPhone 17e launch, `open_ledger/alphabet` → bell → RECENT CHANGES shows a date on every row, and the two `update` rows are distinguishable by date; the commit detail for `6c15574` shows the same date next to its author. Switching the app language re-renders the dates in that locale. Add regression coverage for the formatting path with a valid ISO timestamp, a missing/empty value (renders nothing, not "Invalid Date" and not 1970), and a non-`en` locale.

## Blast radius

Two screens: `src/screens/notifications-screen/notifications-screen.tsx` and `src/screens/commit-detail-screen/commit-detail-screen.tsx`. `formatFeedDate` is shared with the feed; adding callers does not change its behavior. Both screens reproduced natively. Not exercised: dark mode, enlarged Dynamic Type (where a third element on the muted line may wrap), VoiceOver, Android, a ledger with no commits at all, and the branch/commit-history surfaces outside the bell.

**Resolved 2026-09-14** — fixed in `mobile` by `fix(mobile): show when each change happened in Recent Changes`. Triage confirmed the root cause at HEAD before the fix: `CommitAuthor.date` was already a required schema field, but `listCommits` and `getCommitDetails` selected only `author { name }`. The note was not stale.

Both operation documents now select `author { name date }`, and `yarn codegen` regenerated `src/generated-graphql/`. `notifications-screen/formatting.ts` adds `formatCommitAuthorLine`, which appends the day through the existing `formatFeedDate` in the app language. A missing or unparseable date shows the author alone, never "Invalid Date" or 1970. The Recent Changes row and the commit detail's `Author:` line use it, with `locale` from `useTranslations()`, so a language change re-renders the dates; the row keeps its two-line shape.

**Codegen note:** introspecting the live schema also regenerated `graphql.schema.json`, `schema.graphql`, and `types.ts` with backend schema changes made since the last mobile regeneration. Examples: optional posting `units`, `userId` arguments dropped from `featureFlags` and `ledgerMeta`, and new append-directive types. The output was committed exactly as generated. `graphql.tsx` changed only in the two commit queries, so the requests the app sends change only by adding `date`, and the typecheck passes against the new types.

Regression tests in `mobile/src/screens/notifications-screen/__tests__/format-commit-author-line.test.ts` cover a valid timestamp, missing, empty, and unparseable dates, two same-author commits told apart by date, and a German locale; three fail when the date is ignored. A device re-check was not repeated in this run.

# prepare-translations auto-generates English for every unattributed key, into the shared catalog

Severity: moderate. Package: dashboard. Estimate: ~1h — needs a decision about
what the script should do, not just a patch.

Found while doing `w4/158`, which added half-translated reporting to
`dashboard/scripts/prepare-translations.ts`. That work had to repair the
script's startup crash first, and the crash turned out to be hiding this.

`determineFeatureFromKey` returns `common` for any key it cannot attribute to a
directory under `src/features/`. `addMissingKeysToEnglish` then writes those
keys into that feature's `en.ts` with a message invented by
`generateMessageFromKey`. Pointed at the real shared catalog, that rewrites
`src/i18n/locales/common/en.ts` with **every key in the codebase** — a measured
40,070 inserted lines across the thirteen `common/*.ts` files, each entry
marked `description: "Auto-generated from code usage"`.

Two distinct problems:

1. **Attribution.** Falling back to `common` is wrong for a key like
   `aiAgent.attachFile`, which belongs to the `ai-agent` feature. The fallback
   should be "skip and report", not "write it somewhere".
2. **A template bug.** One generated entry is the literal key `"${key}"`,
   which means a `${key}` inside a normal quoted string rather than a template
   literal. Worth finding on its own — it suggests the generator produced at
   least one message by string concatenation that was never exercised.

`w4/158` contained the blast radius rather than fixing it: the shared catalogs
are now read-only for this script, so the report reads them while the write
steps skip them, and both places say why. The bug is still live for any key
misattributed to a real feature.

Repro: in `dashboard/scripts/prepare-translations.ts`, remove the
`if (feature in SHARED_LOCALE_DIRS) continue;` guard in
`addMissingKeysToEnglish`, run `yarn i18n:prepare`, and inspect
`git diff src/i18n/locales/common/`. Restore the guard and `git checkout --`
the catalogs afterwards.

Acceptance: an unattributed key is reported rather than written; no generated
entry is a literal `${key}`; running `yarn i18n:prepare` on a clean tree still
writes nothing it should not; and the shared catalogs can be un-gated again, or
the gate is kept deliberately with that reason recorded. Dashboard gates pass.

Worth deciding at the same time: whether this script should write at all, or
whether generating English from key names is a step that ought to be removed.
An auto-generated `message` is indistinguishable in the catalog from a written
one except for its `description`, and `w4/155` found seven keys that had been
added to `en.ts` and never translated anywhere — which is what this generator
produces at scale.

---

**Resolved 2026-09-20** — fixed in `dashboard/scripts/prepare-translations.ts`,
shipped in `45962e1a`.

The note named two problems; there were three, and the first was hiding the
others.

1. **The feature scan looked one level deep**, so nested catalogs —
   `git/commits/locales`, `ledger-data/statistics/locales`, and most of
   `reports/` and `ledger-editor/` — were invisible. It found 13 of 44. This is
   the third instance of the same shape in two days, after the
   `rglob("locales/uk.ts")` survey in `w4/m24/t012` and the
   `src/common/locales` path in `w4/158`. Worth noticing as a pattern: tooling
   in this repo keeps assuming the catalog layout is flatter than it is.
2. **Namespace did not name the directory.** `aiAgent.*` never matched
   `ai-agent/`, `userSettings.*` never matched `user-settings/`, and `page.*`
   and `component.*` span most features. Keys are now placed by reading which
   catalog already contains them — exact, and needing no convention. Unplaced
   keys went 823 → 1.
3. **The fallback wrote rather than declined.** Removed; an unplaceable key is
   reported by name and written nowhere.

On the `${key}` entry this note called a template bug: the generator is fine.
The *extractor* reads source as text with a regex, so it matched the string
`t("${key}")` inside the error message that
`common/hooks/use-translations.ts` formats — text describing a call rather than
a call. Captures containing `${` are now dropped, since a template placeholder
cannot be a literal key.

One key is still reported: `namespace.keyName`, from the format hint in the
same file. It is left visible rather than special-cased — reporting it writes
nothing, and a hardcoded exclusion for one documentation string would be worse
than a line of honest noise.

The shared catalogs could now be un-gated, since the script no longer writes
where it cannot place. They are left read-only deliberately: nothing needs to
write to them, and the gate costs nothing.

Verified: 44 catalogs found, 1420 of 1421 keys placed, no file under `src/`
written, and the half-translated report still fires — reverting the Spanish
account report flags both `reports` and the nested `reports/account`, which
only became visible once the scan recursed.

# Let Enter activate account search's retry button

Severity: minor. Estimate: 35m, dashboard. A2: keyboard users should be able to recover an account search read using either standard button activation key. Repeated dashboard QA, 2026-09-18.

Production beancount.io, anonymous public open_ledger/crypto-example, English/light, isolated headless Chromium149.0.7827.55. Reproduced at390×844 and in a fresh1440×1000 context. HEAD26d54a9d, fetched origin/mainbd5d1d31, deployed main-BIr0jJni.js; exact deployed SHA unknown. This is a controlled browser network failure, not a claimed production outage.

1. In a fresh context open `/ledger/open_ledger`. Abort only GetLedgerAccounts reads to `/api-gateway/`, then follow the crypto-example ledger link through client navigation. Direct SSR loads may already have cached this optional read and are not a reliable failure setup.
2. Open Search accounts... beside Accounts (open Sidebar first at390). Wait for Failed to Load Data / Try Again.
3. Remove the abort so the real network works. Focus the named search combobox and Tab to Try Again. Press Enter.
4. The button keeps focus, the error stays visible and no GetLedgerAccounts request occurs. The desktop key observer records `key:Enter, defaultPrevented:true, target:Try Again`.
5. Press Space on the same button: a real HTTP200 GetLedgerAccounts response contains43 accounts and the options populate. At narrow width, searching MetaMask then shows the matching account paths. No ledger data changed.

Root: `dashboard/src/common/components/ledger-layout/go-to-account.tsx:81–96` nests a native Button inside CommandList/Command. Its onClick calls refetch correctly. The installed cmdk1.1.1 `dist/index.mjs` Command root handles bubbled Enter with unconditional preventDefault and dispatches selection only to a selected command item; the failure branch has no such item. This cancels the focused button's native Enter activation. `common/components/ui/command.tsx:9–21` delegates to that primitive unchanged. Space is not consumed.

Fix locally at the account picker: keep the real retry button outside the command keyboard boundary, or narrowly stop its Enter propagation while preserving native activation. Do not manually invoke refetch twice, prevent native button activation, globally disable command Enter, or fork/update cmdk. Preserve typing, normal account option Enter selection, loading/empty distinctions, cached data, Escape focus return and narrow-sidebar dismissal. No API, schema, dependency or translation addition is needed.

Blast radius: LedgerSidebar is the sole production importer of this go-to-account component, shared across ledger routes. The similarly named form AccountCombobox in ledger-comboboxes is a different implementation and is not included. Other command consumers and authenticated ledger switchers remain unverified.

Dedupe/history: all current/done/blocked board records searched for account search, retry, Enter and cmdk. Historical w3/072 was removed by dd6f2f71 after adding loading/error/retry; its original acceptance explicitly required keyboard-operable retry. This is a bounded residual failure of that repair. The current test at `common/components/ledger-layout/__tests__/go-to-account.test.tsx:92–126` checks pointer click only. Later d7c0c449 and 4cad3dda fix placement/input names; fetched main has no later retry repair. w4/123 owns the popup's missing accessible name; w4/113 concerns active options in the separate shared Time combobox. Neither fixes this button activation.

Acceptance: with the real Command wrapper and a rejected account read, Tab reaches Try Again and Enter triggers exactly one retry which can restore options. Space and pointer click still work; repeated failure stays actionable, successful empty reads remain honest, and Enter on a normal account option still navigates correctly. Exercise desktop/narrow and run dashboard gates when implementing. No actual screen-reader speech, other engine, authenticated state or patched behavior was tested.

Evidence: verified `dashboard/tmp/qa-20260917/account-picker-retry-keyboard.json` (narrow failure/recovery), `account-picker-retry-desktop.json` (fresh desktop key cancellation and request counts), and visually inspected `account-picker-retry-enter-1440.png`. Only expected aborted read failures were injected; no response bodies were fabricated. No product fixes, commits or pushes.

**Resolved 2026-09-19** — The retry button now stops the Enter bubble at itself rather than preventing anything, so the key never reaches cmdk's Command root and the browser performs the button's own activation. That keeps the repair local to the account picker: cmdk is not forked or updated, Enter is not disabled globally, native activation is not blocked, and `refetch` is not invoked by hand — the single `onClick` still runs exactly once. The defect was reproduced first at HEAD by aborting only `GetLedgerAccounts` reads and then restoring the network before retrying: at both 1440×1000 and 390×844, Tab focused "Try Again", Enter produced **0** reads and left the failure on screen, and Space produced **1** read that populated 77 accounts. After the change, Enter at both widths produces exactly **1** read and the 77 accounts appear. Everything the note asked to preserve was re-checked in the same harness: Space still retries once and restores the options, a pointer click does the same, a retry that fails again still offers the button, typing `MetaMask` and pressing Enter on a normal account option still navigates to `/account/Assets%3ACrypto%3AWallet%3AMetaMask` from 7 matches, and Escape closes the popup and returns focus to the Search accounts... trigger. `__tests__/go-to-account.test.tsx` gains three cases alongside the existing pointer-click one, rendering the real Command wrapper so a regression in that boundary fails here: Enter on the focused button calls `refetch` exactly once, Space still does too, and a repeated failure keeps the retry offered. The Enter case fails when the handler is removed; the Space and repeated-failure cases pass either way and stand as controls. Not verified: actual screen-reader speech, other engines, authenticated ledger switchers, and other cmdk consumers — the separately named form `AccountCombobox` in `ledger-comboboxes` is a different implementation and was left alone, as the note directs. Dashboard gates all pass (`yarn format:check`, `yarn lint`, `yarn test` — 418 files, 4672 passed, 1 pre-existing skip — and `yarn build`). Shipped in `735913cc` (`dashboard`).

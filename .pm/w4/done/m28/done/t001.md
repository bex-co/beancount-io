## Objective

Let `useTranslations` accept base keys of `_one`/`_few`/`_many`/`_other` variants with a required `count`, let module catalogs such as `overview/dashboard-translations.ts` declare per-language category sets, and make the locale parity tests require exactly each language's `Intl.PluralRules` categories for plural keys.

## Acceptance criteria

- [ ] Meets the parts of the [definition of done](../README.md#definition-of-done) this task covers.

## Result

- **Plural messages:** `dashboard/src/i18n/plural.ts` expands per-category forms into i18next's suffixed keys, so i18next resolves the form from `{ count }` through `Intl.PluralRules`. The overview catalog types the three m27 count keys as plural forms.
- **Checks:** `src/i18n/__tests__/plural.test.ts` requires exactly each language's categories, and rejects a Russian message missing `few` and a Chinese message with `one`. `src/test/translations.test.ts` now treats a plural family as one key.
- **Deviation:** translation keys are plain `string` in this codebase, so a plural key without `count` is caught by `useTranslations`' dev-mode check rather than by the type-check.
- **Fixed along the way:** the check found 5 importer plural messages with only one/other forms. Russian, Ukrainian and Slovak gained few/many; ca, es, fr and pt gained `many`; ja, ko and zh dropped `one`.

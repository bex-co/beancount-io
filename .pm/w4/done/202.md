# Read the saved report conversion consistently during server rendering

Severity: **minor**. Estimate: **45–60 minutes**, dashboard only. A2 — a reader reloading a public example should receive a server-rendered report in the conversion they selected.

## Live reproduction

Production `https://beancount.io`, public synthetic `open_ledger/example`, fresh anonymous headless Chromium **149.0.7827.55**, English/light, at **1440×1000 and 390×1000**. Local main **245e949c** retains the cause; deployed full SHA/bundle identity is unverified. Only browser-local preferences and read-only report requests were used.

1. In a fresh context, open `/ledger/open_ledger/example/balance-sheet?time=2017-09` and wait for the report. Default At Cost loads without a hydration error.
2. Choose **Units** through Select conversion and wait for the report to settle. Reload the same URL.
3. Each width produces one React **418** hydration error. The settled client correctly restores Units, but the server rendered At Cost first.

An independent JavaScript-disabled context carrying only the report-preference cookie shows server-rendered Assets **109,529.339 USD and −13 VACHR**, including GLD valued at **4,559.8 USD**. Read-only API controls confirm the At Cost root is `{USD: "109529.33944", VACHR: "-13"}`. Units instead returns `{USD: "3609.87", GLD: "17", ITOT: "104", VEA: "36", VHT: "64", VACHR: "-13", RGAGX: "597.748", VBMPX: "193.442"}`, matching the settled client report.

An early read-only MutationObserver captures the initial main table: it remains connected on a fresh default load, but is disconnected after reloading with saved Units as React replaces the server-rendered table. This independently establishes different server/client report bases and DOM replacement. No settled amount error, lost input or regeneration duration was measured; do not inflate this into a calculation defect.

## Cause and bounded repair

`dashboard/src/features/reports/components/use-report-conversion.ts:19` builds the logical key `beancount.reportConversion.open_ledger%2Fexample`. The client cookie setter in `common/hooks/use-cookie-storage-state/cookie.ts` delegates to js-cookie, whose name serialization encodes that percent again: the actual header name contains **`open_ledger%252Fexample`**. js-cookie decodes names on client reads, so the logical lookup succeeds there. The server delegates the same logical key to TanStack/H3; cookie-es keeps header names encoded, so that lookup misses and both the report hook and loader fall back to At Cost.

The installed parser independently reproduces the boundary using a synthetic header, without network access or credentials:

```js
import { H3Event, getCookie } from "h3-v2";
const event = new H3Event(new Request("https://example.invalid", {
  headers: { cookie: "beancount.reportConversion.open_ledger%252Fexample=units" },
}));
getCookie(event, "beancount.reportConversion.open_ledger%2Fexample"); // undefined
getCookie(event, "beancount.reportConversion.open_ledger%252Fexample"); // "units"
```

Trace: installed `js-cookie/dist/js.cookie.js:59–60` serializes names and `:89–106` decodes them when reading; `@tanstack/start-server-core/dist/esm/request-response.js:145–150` looks up the raw parsed name; `cookie-es/dist/index.mjs:21` preserves the name while decoding values. The Balance Sheet loader calls `storedReportConversion` at `features/reports/balance-sheet/loader.ts:22`. Income Statement, Cash Flow and Trial Balance loaders plus the account report share the conversion helper; those are source-traced scope, not additional live reproductions.

Make the server read the browser-serialized preference consistently, preserving existing saved choices, per-ledger isolation, choice validation, expiration/path/SameSite and matching loader prefetch variables. Keep the repair at the report preference or demonstrated cookie boundary. Do not disable SSR, suppress hydration errors, force the client to At Cost, remove prefetching or add a parser dependency.

Acceptance: a real browser-written Units preference for a slash-containing ledger produces Units in both server markup and the settled client after reload, keeps the initial report table connected and emits no hydration error at both widths. Default/no-cookie behavior still uses At Cost; other ledgers retain independent preferences and invalid stored choices retain their documented fallback. Add a meaningful test using actual js-cookie name serialization and the real server header parser: current `use-report-conversion.test.ts` replaces both cookie operations with a Map, bypassing this failure. Run dashboard format/lint, tests and build when implementing.

**Resolved 2026-09-19** — Reproduced against a local build: the description
"View important events and milestones in {ledgerName}. Track account openings,
closings, and lifecycle events." appeared on the empty
`real-estate-example` Events page and, unchanged, above the nine real
employer/location records on `example`. A filtered-empty read
(`?time=2010`) showed "No events found for this ledger." although Clear all
brings back all nine.

Both are bounded copy/scope repairs:

1. `common.pageDescription.events` now describes what an event directive is —
   a dated entry with a type and a description, such as a change of location or
   employer — in all fifteen catalogs, with the `{ledgerName}` placeholder
   intact. French and Chinese repeated the openings/closings claim in their own
   words and were corrected too.
2. The page's `QueryView` `emptySlot` chooses the existing localized
   `page.events.noEventsMatchFilters` when any shared topbar time/account/filter
   is active, and keeps `noEventsFoundForLedger` only when none is. The nested
   local-search branch already drew that line and is unchanged.

The Event-directive contract is untouched: the backend's filtered Event
selection, the REST/GraphQL/MCP shape, the type/search/date filtering, the read
error state and Clear all all behave as before, and nothing clears the reader's
selection automatically.

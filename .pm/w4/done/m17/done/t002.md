## Implementation and verification

Completed 2026-09-19. t001 stopped a late write from hijacking navigation, which by itself would have left the reader's visible search unrecorded when they departed inside the 250ms window. `LedgerCollection` now flushes the pending query into this profile's history entry on the same gesture that opens a ledger, so Back returns to the search they could still see.

The flush runs in the capture phase on the results grid — `onPointerDownCapture`, plus `onKeyDownCapture` for Enter and Space so keyboard activation behaves the same. Capture phase is what makes it correct: the profile write lands before the card's own navigation pushes the ledger entry on top of it. It is a no-op when the query already matches the URL, so an ordinary click after the debounce has settled writes nothing.

Covered by a case that types, opens the card well inside the debounce window while asserting the URL has not yet been written, then goes Back and requires both the restored `q` and the restored input value.

An interaction between the two tasks is worth recording, because it changed a test rather than the product. Once t002 flushes on the card gesture, the card path no longer leaves an outstanding debounce at all — which is the desired outcome, but it neutralized the premise of t001's race test, whose synchronization then failed. The race test now departs via `router.navigate` rather than a card click, so a debounced write genuinely is still pending when the route goes in flight; that is the case t001's guard actually owns. Each test was re-verified in isolation: reverting only t001's explicit target and departure guard fails only the race case, and removing only t002's flush fails only the Back case.

The write remains `replace: true` and still addresses the profile explicitly, so the no-history-churn contract from w3/164 holds — the flush replaces the profile entry rather than adding one — and validated search, sort and show handling, bounded counts and typing focus are untouched. No change was needed in `RepositoryListItem`, and the collection's server cap is unchanged.

Gates from `dashboard/`: `yarn format:check`, `yarn lint`, `yarn build` and `yarn test` pass at 376 files and 4,244 tests; the user-profile suite is 161 tests across 11 files. The fast-cached-destination variant FINDINGS mentions but does not claim reproduced is exercised here only insofar as the harness resolves instantly; the live desktop and narrow journeys belong to t003.

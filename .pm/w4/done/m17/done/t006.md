## Outcome

Re-ran the recorded journeys against a fresh production build of the repaired
code (the app rebuilt and restarted before the run, so the bundle under test is
the shipped one). Three viewports — 1440x1000, 390x844 and 320x568 — each at two
typing cadences (no delay between keystrokes, and 120ms per key), plus a settled
control that lets the URL catch up before opening a card. 33/33 checks passed:

- **opens-selected-ledger** — typing `budget` and opening the match with no
  pause lands on `/ledger/open_ledger/budgeting-envelopes` and never contains
  `undefined`, at every width and cadence.
- **no-user-not-found** — the destination renders the ledger, not a
  "User not found" page.
- **back-restores-search** — Back returns to `/ledger/open_ledger?lang=en&q=budget`
  with the search box still reading `budget` and the collection filtered to the
  single match, even though departure beat the debounced write.
- **forward-reopens-ledger** — Forward reopens the intended ledger.
- **no-page-errors** — no uncaught page errors during any journey.
- **settled-control** — the previously working path still works.

The remaining definition-of-done clauses are covered by the integration tests
from t005: a delayed read and an already cached destination
("never rewrites the destination while a ledger read is in flight"), another
profile ("never writes to another profile after the reader moves on"), tab
changes and unmount (the departure guard plus the effect's timer cleanup), the
no-history-churn contract ("debounces typing into a single replaced history
entry") and bounded search/sort/show preservation ("keeps sort and show while
committing a fast-typed query"). The collection's server cap is unchanged.

Limitations worth recording: the journeys run against the public read-only
profile of one open ledger over an anonymous session, so they exercise the
public discovery path only — signed-in profiles and private ledgers are not
covered here. The narrow widths are emulated viewports, not physical devices.

# Keep manual report filters usable when the suggestions read fails

Severity: **minor**. Estimate: **45–60 minutes**, dashboard only. A2 — an optional suggestions failure should not prevent a reader from changing or clearing a report's already-applied scope.

## Reproduction with an injected read failure

Production `https://beancount.io`, public synthetic `open_ledger/example`, authenticated read-only QA, English/System, owned headless Chromium **149.0.7827.55**. Fresh **1440×1000 and 390×1000** loads reproduce. This is a QA-injected network failure, not an observed production outage. Deployed full SHA is unverified; current source retains the behavior.

1. Intercept only the browser's read-only GraphQL **GetLedgerAttributes** operation and abort it. Let all other requests proceed normally. Open `/ledger/open_ledger/example/income-statement?time=2017-09&account=Expenses`, with Units selected for that ledger, and wait for the report to settle.
2. Desktop replaces the entire filter toolbar with **Failed to load filter options**. At narrow width, open **Filters**: the named Report filters sheet contains its heading/description, that alert and Close, with no Time, Account or payee/tag field and no Clear all.
3. The active scope remains `time=2017-09&account=Expenses`. The Income Statement remains readable, including Net Profit **−2,354.89 USD and −5 VACHR**, and Export remains enabled before opening the modal sheet. A reader can neither correct the scope nor clear it through these controls while the suggestions request is failed.
4. Remove the interception and reload. Both widths restore Time **2017-09**, Account **Expenses** and **Clear all**. The narrow sheet closes normally.

One attributes request is intercepted at desktop; narrow catches two because the header and opened sheet mount separate control instances. Neither test aborts the primary statement request or changes production data. The normal custom-range/clear journey independently works, and real API controls agree with the statement's amounts. This defect concerns loss of filter actions, not a failed or falsely empty financial report.

## Cause and bounded repair

`dashboard/src/common/components/ledger-search-controls/index.tsx:136–147` returns only an Alert on `error`, before rendering Clear all or any manual field. The attributes supply suggestions (`accounts`, `tags`, `years`, `links`, `payees`); the applied values and callbacks already come from LedgerSearchParamsContext, and all three fields support custom text. Clearing filters likewise needs no attributes. Loading also returns before the controls, but the retained finding is the settled failed-read state, not ordinary loading skeletons.

Keep the current applied values, manual editing and clearing available on a suggestions failure, with the honest translated warning and empty/unavailable suggestions as appropriate. Preserve normal suggestion lists once the read succeeds, per-ledger scoping, intentional Enter/blur commits, Escape dismissal/focus, keyboard selection protection, narrow-sheet layout and the primary report's pending/error rules. Do not invent suggestions, silently clear the active scope, fail the primary report, or change backend/API eligibility to work around this UI dependency.

Acceptance: a real controllable attributes read rejects while the primary report succeeds; desktop and narrow still expose the applied Time/Account/filter values and Clear all. Typing a supported custom period changes the actual URL/report, and Clear all removes the actual shared scope despite the attributes failure. Successful recovery restores genuine suggestions and removes the warning without leaking another ledger's options. Add meaningful owning-component/provider tests that reject the query and exercise manual commit/clear callbacks; a snapshot asserting the alert alone would preserve the defect. Run dashboard format/lint, tests and build when implementing.

## Dedupe and scope

Both production callers are `common/components/ledger-layout/layout-header.tsx:95` (desktop) and `:132` (stacked sheet); eligible report/journal routes inherit the shared control. Only Income Statement is live-reproduced here. Search across open, done and blocked board items found no repair for failed suggestions removing manual filtering. **w3/done/134** explicitly excluded permanent filter loss when its attributes read was merely loading; its Cash Flow boundary reset is a different failure. **w3/done/m20** exposes and sizes the narrow controls; **w4/done/095** repairs Escape dismissal; **w4/done/113** repairs suggestion selection semantics. Preserve those behaviors.

The error-return branch dates to **af5339de**; later **e0e5cc8b**, **254cfea0** and **46f7d97e** retain it. Ignored reproduction `dashboard/tmp/qa-20261008-loop/filter-attributes-failure.js` records the injected operation counts, native role snapshots, retained report/export and restored filter values at both widths. An initial diagnostic tried to locate the background Net Profit table by accessible role while the modal sheet was open; that timeout is excluded. Temporary interceptors are removed in finally blocks; no ledger writes or product changes were performed.

## Objective

Observe real native legend changes through the existing ECharts integration and define a small scoped selection contract for LineChart. Apply primary-unit defaults only for initialization or a deliberate new context, preserving the current choice on data/interval option updates. Keep explicit all-off distinct from uninitialized selection and reconcile available-unit changes. Avoid a generic event manager, preference store or dependency.

## Context

See [the milestone](../README.md) and [verified findings](../FINDINGS.md). Owning package: dashboard only.

## Verification

**Contract.**
- `ReactECharts` takes `onLegendSelectChanged`. The client subscribes to ECharts' own `legendselectchanged` on each chart it creates, so the native legend click path is unchanged, and reports every item's visibility.
- `LineChart` keeps that choice, in its own state or in a caller's (`legendSelection`/`onLegendSelectionChange`), and builds `legend.selected` from it through `legendSelectionFor` (`balance-sheet/legend-selection.ts`), which:
  - uses the primary unit (or the first) for a new context, and for a choice that names none of the current units;
  - keeps chosen units, with a newly present unit hidden;
  - uses the default when every chosen visible unit is absent (Units → Market value leaves USD);
  - keeps a deliberate all-off.
- No generic event manager, preference store or dependency. Exact values, tooltips and the period table are unchanged; the client's theme-recreation restore still runs.

**Regression:** `balance-sheet/__tests__/line-chart-unit-selection.test.tsx` uses the real ECharts model in jsdom (SVG renderer). A native legend toggle survives a cached regrouping on the same chart instance, and five `legendSelectionFor` cases pass. The lifecycle case fails against the old `line-chart.tsx`.

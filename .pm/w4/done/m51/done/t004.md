## Verification

`/simplify` ran four parallel reviews (reuse, simplification, efficiency, altitude) over the m51 diff.

**Applied:**
- The client's latest-callback ref became React 19's `useEffectEvent`, as `cli-auth-code-entry-view.tsx` already does.
- `legendSelectionFor` moved from `balance-sheet/` to `features/reports/lib/`; Account depends on it, and it is not Balance Sheet specific.
- LineChart has one ownership test (the callback decides), with no `| null` placeholder.
- `unitSelections`/`onUnitSelectionChange` are required on `BalanceSheetContent`, like `selectedTab`.
- The defensive copy and guard on the ECharts event are gone; ECharts builds a fresh `selected` map per action.
- A legend click no longer rebuilds the option and calls `setOption` a second time (about 10 ms per click, and it restarted the shown series' reveal). The option is built once per data change, and the choice folds in only then or on mount.

**Skipped:**
- Making the primary unit implicit: it would couple the helper to the caller's sort.
- A shared SVG-runtime test mock: there are only two copies.
- Renaming unit/legend naming: churn.
- Reporting the choice upward only on unmount: fragile. The per-click page re-render costs the same as a tab switch.
- The cash-flow and income-statement charts' copies of the default rule: outside this milestone.

The altitude review confirmed that page owners plus a generic client event are the right depth. The client's same-option restore is deliberate (w4/213) and tested, and it cannot know the primary unit or survive a remount.

Gates, the revert check (four lifecycle and owner tests fail on old code) and every browser check were re-run after the changes.

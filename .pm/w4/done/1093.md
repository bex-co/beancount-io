## Cause and bounded repair

`dashboard/src/common/lib/ledger-search-params/parse.ts:11–24` passes every string through **maybeUndoExtraEncoding**. At:32–38, any valid-looking percent triplet triggers decodeURIComponent on the entire value. A literal `%2E` inside the quoted payee pattern becomes a regex dot. A bare trailing percent throws and falls back unchanged, explaining why the existing100% control passes.

The parent search schema normalizes filter at `schema.ts:16`; provider parsing repeats normalization through `parse.ts:50`. Native patches and already URL-decoded links therefore encounter this legacy-recovery heuristic. Journal consumes the resulting string at `journal-page.tsx:184`. The API itself accepts the original literal and correctly returns zero matches.

Confine extra decoding to recognized legacy whole-value encodings at the URL boundary. Preserve canonical typed expressions and embedded quoted text exactly through schema/provider processing, serialization, reload and history. Keep existing fully encoded legacy links working, as well as clear/reset, unrelated route state and malformed-percent recovery. No API, dependency or translation change is needed.

The normalizer is shared by account/filter/time schema validation, provider reads and ledger-action search; report loaders and same-ledger links consume those values. The independently exercised defect is Journal's quoted payee pattern. Other filter fields/routes are source-traced compatibility scope, not additional live findings.

Acceptance: enter the literal expression and open its canonical URL through the real router/provider. The field, URL and API keep `%2E`; the journal shows zero entries and remains so through reload/Back. Retain the passing bare-percent, bracketed-dot, clear and legacy-link controls. Use meaningful shared-schema/provider/query regression coverage, repeat both widths and run dashboard gates when implementing.

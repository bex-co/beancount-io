# Translate the German Events headings and shared account-type label

Severity: **minor**. Package: **dashboard**. Estimate: **25–35m**. Source:
continuous dashboard QA for w4. **A2**: German readers should receive German
navigation and column labels when exploring the public example.

Reproduced on production `https://beancount.io`, anonymous public synthetic
`open_ledger/example`, isolated headless Chromium 149.0.7827.55. Local main
`390568c2`, deployed entry `main-d5j4FX-V.js`; exact deployed revision unverified.

1. Open `/ledger/open_ledger/example/events?lang=de` and wait for the nine events.
2. The document language is `de`, search is `Ereignisse suchen...`, count is
   `Ereignisse: 9 / 9`, and the description already uses the German words
   `Typ` and `Beschreibung`. The table nevertheless has the accessible column
   names `Datum`, **`Type`**, **`Description`**.
3. Reload: same result at 1440×1000/light. An independent fresh-load sweep at
   320×800/dark shows the same English headings.
4. Open `/ledger/open_ledger/example/accounts?lang=de`: the account-type filter
   group also has the accessible name **`Type`**.
5. English control `/events?lang=en` correctly renders `Date`, `Type`,
   `Description` with the same nine records.

The real reload's `GetLedgerEvents` requests return HTTP 200. No application
exception was observed; aborted analytics requests during navigation are
unrelated. This is settled UI copy, not missing or incorrectly translated
ledger-authored data.

Cause: `dashboard/src/features/ledger-data/events/locales/de.ts:7–9` explicitly
sets `page.events.description` to `Description`, and
`dashboard/src/features/ledger-data/accounts/locales/de.ts:134–136` explicitly
sets `page.accounts.type` to `Type`. The table consumes both at
`events/index.tsx:235–238`; the only additional production consumer found is the
Accounts filter group's `aria-label` at `accounts/index.tsx:459`.

Repair these two German catalog messages to `Beschreibung` and `Typ`. Keep the
English catalog and user-authored event types/descriptions unchanged. No API,
ledger parser, shared translation fallback, or dependency change is needed.

Acceptance: German Events displays and exposes `Datum`, `Typ`, `Beschreibung`
at desktop/light and narrow/dark; the Accounts group is named `Typ`. English
keeps its existing names. Search, type selection and counts keep working. Run
the existing translation and dashboard gates when implementing; do not add a
test that merely repeats the two literal strings.

Dedupe: searched all board files including done/blocked work for these keys,
German Events headings and untranslated labels. Completed w4/m25 guards
*half-translated phrases* and does not promise detection of entirely English
messages; these labels are outside its detector's documented scope. Completed
w4/094 fixed the page description and filtered-empty wording, and w4/077 the
count grammar. Their repaired behavior is present. Both unchanged values date
to `af5339de` (`git log -S`); no landed repair or overlapping open task found.

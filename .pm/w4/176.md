# Automatic CSV dates ignore decisive day-first evidence after the first 200 records

Severity: **minor**. Package: **cli**. Estimate: **30–45m**. Source: continuous
CLI QA for w4. **A1/A2:** a longer bank export should use the same unambiguous
date convention as its shorter equivalent, without requiring a corrective flag.

Environment: 2026-09-21, main `390568c220bfbdb0df1c9decb8436c64dfa3c9ca`,
checkout `cli/.venv/bin/bea` 0.3.0, Python 3.13.3, Darwin arm64. Fresh
subprocesses ran with closed stdin and 25-second limits under
`cli/tmp/qa-20260921-cli-loop/`; child-only config/cache/data paths were isolated,
update notices disabled, BEA_FILE/BEA_TOKEN removed. All inputs were synthetic.

## Reproducer and result

Use a ledger with operating currency USD and these two opens dated 2024-01-01:
`Assets:Cash USD`, `Expenses:Food USD`. Generate the CSV in its disposable directory:

```python
from pathlib import Path
Path("bank.csv").write_text(
    "Date,Description,Amount\n"
    + "".join(f"03/04/2024,Purchase {i},-{i+1}\n" for i in range(200))
    + "13/04/2024,Last,-999\n"
)
```

With absolute paths, run:

```sh
bea --json --file main.bean import bank.csv --csv auto   --account Assets:Cash --default-account Expenses:Food
```

Exit 2, stdout empty, error:
`Row 201 (line 202): cannot parse date '13/04/2024' in column 'Date' with format
'%m/%d/%Y'.` The column is unambiguously day-first; `%d/%m/%Y` parses every row.
No bytes are written. Repeated with two pristine ledgers and isolated mapping state.

Working controls: generate only 199 ambiguous rows before the same decisive
last row; automatic preview succeeds with `%d/%m/%Y` and 200 ready rows. Keep
all 201 rows but add `--date-format '%d/%m/%Y'`; preview succeeds with 201 ready
rows. Unique source amounts prevent possible-duplicate review from confusing
the ready counts in these controls.

Expected: consider the full date column before deciding its convention, as
`docs/IMPORTING.md` promises a format parsing every date in the column. Do not
report a valid date as malformed because disambiguating evidence came later.
Truly ambiguous columns should retain the existing explicit ambiguity guidance.

## Cause and bounded repair

`cli/src/cli/csv_mapper.py:456–481` gives `infer_date_format` a default limit of
200 nonempty values and breaks at that count. `commands/import_.py:486–497`
uses the sampled result for the entire import; the ambiguous sample picks
`%m/%d/%Y`, and engine extraction then rejects the first decisive day-first date.
The engine-side twin at `bea_engine/csv_mapper.py:554` has the same sampling
implementation, though the exercised selection is the frontend call.

Evaluate the candidate formats across the whole column, preferably by narrowing
candidates while streaming rather than retaining every value. Preserve encoding,
delimiter, blank-row and explicit-format behavior. Caller search finds automatic
inference plus remembered-explicit-format validation at `import_.py:502`; keep
that second caller's unambiguous-mismatch safety contract intact.

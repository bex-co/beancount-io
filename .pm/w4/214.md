# Global chunk recovery bypasses language failure feedback and reloads the old locale

Severity: **minor**. Estimate: **45–60 minutes**, dashboard only. A2 — a failed language download should keep the current page usable and offer a retry for the language the reader selected.

Production `https://beancount.io`, 2026-10-09; dedicated QA GROWTH session from the root `.env`, German initial language, owned isolated headless Chromium149. Fresh1440×1000 and1024×1000 desktop-menu reproductions. Source/main `bf1e6309` after pull; only unrelated board records changed, deployed SHA unverified. No ledger writes or fabricated locale responses. Narrow screens route the avatar to Settings and were not claimed as this menu reproduction.

1. Open `/ledger/open_ledger/crypto-example/commodities?lang=de`. Open the DAI/USD price history with the native translated disclosure:131 rows.
2. Open the avatar menu, hover **Sprache**, choose **日本語**. Abort only the actual Japanese translation/date-locale script requests (`ja-CsAFnLiX.js`, `ja-D825iNZ_.js` in the observed build).
3. The browser performs a second main-document navigation, reloads the original `lang=de` URL and refetches the commodity data. The DAI history is closed; document language remains de. There is no translated error toast or retry action. Both fresh widths repeat this first-failure behavior.

Expected: the current German page and open history stay usable, with localized failure feedback and **Erneut versuchen**. Retry should reload the selected Japanese URL. `dashboard/docs/performance-locales.md:12–17` explicitly documents that failure/retry contract, also covered by completed w2/m21. Actual: generic recovery silently supersedes the locale handler, reloads the old locale and drops the open disclosure.

Working control: within the same fresh context, reopen the history and choose Japanese again while the two faults remain active. The existing one-minute automatic-reload guard now declines a second reload. After menu dismissal settles, the German131-row history remains open, a translated “Ein Fehler ist aufgetreten” and **Erneut versuchen** appear, and the main-document count remains two. Remove the faults and activate that retry with the keyboard: document count becomes three, URL/document language become ja and the Japanese history control appears. This verifies that the intended local failure/retry path is functional when global recovery does not intercept it. Initial immediate post-toast role snapshots briefly excluded the outside table during menu animation; settled131-row snapshots are authoritative, not a second table-loss claim.

Cause: `dashboard/src/common/root-route/root-component.tsx:11–17` handles every `vite:preloadError` by calling `reloadOnceForStaleChunk` and preventing default when it starts a reload. `dashboard/src/common/lib/errors/chunk-load-error.ts` reloads the current URL without the pending target language. This precedes `useChangeLanguage`’s caught-error toast/retry. `dashboard/src/i18n/init.ts` loads both optional translation and date-locale imports; failure can emit more than one preload event. The first event initiates reload while the old `lang=de` is still correctly uncommitted.

Coordinate global stale-build recovery with the locally handled locale imports so optional language failures retain current UI and reach the existing translated retry. Preserve automatic recovery and its loop guard for genuinely unhandled route chunks, current SSR/lazy-loading behavior, superseded language choices and explicit retry loading the chosen locale. Do not globally disable stale-chunk recovery, persist a language before it succeeds, hardcode observed asset hashes, or add dependencies. Cover both translation and date-locale failures, including concurrent failures; ensure local handling cannot suppress an unrelated route-chunk failure.

Acceptance: the first failed language selection leaves the open German history and old preferences intact, shows the translated retry, and does not automatically reload the old locale. Keyboard retry reaches Japanese after fault removal. Retain a genuine unhandled route-chunk automatic-reload/loop-guard control and a superseded-language control. Test the root event listener together with asynchronous locale rejection; isolated locale-hook tests cannot catch this interception. Run dashboard native gates when implementing.

Dedupe/history: all board states searched for preloadError, stale chunks, language failure/reload. Completed w2/m21 owns the intended lazy-language failure feedback; completed w3/m22 extends localized date loading. The generic root listener was introduced by7a2a6308 and remains unchanged; no newer repair or overlapping open item found. Other lazy-feature failures, unsaved edit loss, physical devices and other engines were not reproduced and are not claims here.

Fault routes were removed and fresh contexts closed in finally blocks. No product fix applied.

Four targeted request failures report `net::ERR_FAILED` across the two attempts, with four matching resource/module console errors; no HTTP error status or real outage is claimed. While they are held, choose **English** through the native menu; URL/document language and table headers become English while the131-row history stays open. Abort the held obsolete Japanese imports. The root still reloads the page: main-document count becomes two, the history closes, and commodity-read count becomes two. English remains selected and there is no toast. Preserve that quiet local behavior and the unrelated critical-route recovery.

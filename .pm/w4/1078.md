# Keep late entry completion from discarding a query draft

**Major · dashboard · 45–60m · A2.** After someone leaves a pending New Entry and starts a query, the earlier entry's completion navigates them back to Journal. The focused, unsubmitted query is discarded. Reopening Query shows its default text rather than that draft.

## Reproduction and controls

Production dashboard,2026-10-25 UTC; owned isolated headless Chromium156.0.8078.47, English/light/UTC, synthetic-ledger owner. Fresh1440×1000 and390×844 contexts repeat. Only the one BulkEntries operation is held before transport and given a **browser-local success acknowledgement**. Navigation, editor, metadata and ledger-error reads are genuine; no entry is booked on the server.

1. Journal → New Entry → Note. Select existing Assets:Cash, enter prefixed text A and activate Create Note Entry. Hold the one request before transport. The field correctly locks.
2. Use browser Back and wait for the dialog to leave the DOM. This is a deliberate departure from A, not the draft-loss claim.
3. Follow **Related Pages → Query**, wait for the usable editor, and enter `SELECT 'qa-20261025-draft-after-note' AS marker LIMIT 1`. Its complete text is visible and the editor is focused. Do not execute it: there are zero QueryShell requests and the query is absent from the URL/history of executed queries.
4. Release the old Note operation with the local success acknowledgement. Without another navigation gesture, the URL changes from the ledger's `/query` route to `/journal`. The original editor disconnects and no editor remains. The native polling samples observe the route change500ms/400ms after release; these are sample intervals, not a general latency claim.
5. Follow Journal's Related Pages → Query again. Both widths show **`select * from accounts`**, with none of the draft marker. The narrow before/after screenshots were inspected.

Two fresh controls repeat the same Note/Back/Query-draft journey but abort the old Note before transport. After four seconds, both remain on Query with the same connected editor and complete draft. The narrow control also confirms its editing focus remains. Thus leaving the old form and ordinary query editing work; the late successful completion introduces the unwanted departure.

This is browser-local loss of accepted, unsubmitted work. No wrong hosted booking, actual server-success timing or saved-query loss is claimed.

## Cause and bounded repair

`dashboard/src/features/journal/components/new-directive-dialog/note-form.tsx` invokes its retained success callback after the mutation resolves. `new-directive-dialog/index.tsx:84–89` limits its direct close to the matching dialog session, but still clears the cache and calls the parent onSuccess after awaiting writeOutcome.report. That parent call has no current-page ownership guard.

`features/journal/pages/journal-page.tsx:387–390` unconditionally calls `setOffset(0)` in that completion. `replaceOffset` at:121–135 explicitly navigates to the captured ledger's Journal route with `replace:true`. The old callback can therefore navigate after Journal has unmounted. The resulting route change unmounts the BQL page, whose unsubmitted query is local queryText state (`features/bql/pages/index.tsx:51`); reopening creates the default observed above.

Scope Journal-specific completion navigation to its still-current page/workflow lifetime and navigation intent. A completion must not replace a destination the reader has already entered or is entering, including departure during the later ledger-error check. Preserve correct explicit route parameters, ordinary foreground close/offset reset, successful write refresh and outcome warnings, duplicate-submit protection, failure retry and newer-dialog ownership. Keep the real operation's outcome coherent when its originating page is gone. No API, dependency or query-persistence feature is needed.

Acceptance: use the real Journal/dialog/router lifecycle with a deferred Note completion. Leave through browser Back, fully enter Query and type an unexecuted draft; resolve the old operation and keep the destination, same editor and exact draft. Cover departure while a destination loader or post-ack ledger-error read is pending, leave/return/new-draft cases, the abort control and ordinary foreground pagination reset. Repeat both native widths and dashboard gates when implementing. QA authored no product fix or formal regression test.

## Cause and bounded repair

`dashboard/src/features/ledger-data/commodities/index.tsx:81–92` fixes the y-axis min/max from the prices, which protects the nonzero plotting range. `build-commodity-chart-labels.ts:18–25` still supplies unscaled1e-24 numeric coordinates. The series' ordinary nice-tick generation remains subject to the served/installed **ECharts6.0.0** precision limit.

`echarts/lib/scale/helper.js:69–72` rounds the nice tick endpoints using interval precision. `lib/util/number.js:56,151–160` caps that rounding at20 fractional places. `lib/scale/Interval.js:108–170` advances each tick through the same rounding. For the actual roughly5e-25 interval, a positive next tick rounds back to0; the loop includes it, then its repeated-tick guard stops. The fixed positive endpoints survive, leaving the invalid middle zero in the returned list. The commodity label formatter correctly writes that supplied0 as `0`; changing its string formatting cannot repair the numeric tick.

An independent local control runs the real installed ECharts interval scale with the unchanged commodity formatter and the same explicit bounds. It returns the identical positive extent and `[min,0,max]` ticks; rounding the positive first increment to20 places produces0. The1e-18 and1e-9 controls return only in-range ticks. Read-only browser renderer observations are corroborated by the actual canvas screenshot and native pointer/history actions; no chart dispatch, formatter invocation or state alteration manufactures the UI result.

# Show keyboard focus on the read-only file editor

**Minor · dashboard · 35–50 minutes · A2.** A keyboard reader needs to see when the source editor owns the keys used for scrolling and Find.

## Reproduction and working control

Production `https://beancount.io/ledger/open_ledger/example/files/blob/main/main.bean?editMode=false&lang=en`, 2026-10-23 Los Angeles / Oct24 UTC, anonymous English/UTC, owned isolated headless Chromium156.0.8078.47. Four fresh cases independently cover390×844 and1440×1000 in ordinary light and dark modes. Native keyboard actions, genuine reads, no response replacement or hosted write.

1. Let the read-only ledger open at its documented end-of-file position, with the sticky Prices heading. Focus the editor and Shift+Tab to **More actions**, then capture the unchanged source frame. No menu is opened.
2. Press Tab. The actual **Editor content** node becomes active and matches `:focus-visible`, but the source frame gives **no discernible focus cue**. Its read-only cursor is hidden. After650ms and two animation frames, all four before/after editor pairs differ by at most **one RGB level per channel**, with zero pixels exceeding a delta of3. These are negligible rendering differences, not byte-identical screenshots; no visible outline is present in the inspected narrow light/dark captures or the full narrow page.
3. Press Tab again. The sticky Prices heading receives native keyboard focus and paints a clear blue outline in the same frame. The comparison changes **658 pixels at390px /2,182 at1440px**, with large RGB deltas in both themes. This working control establishes that the capture can see a painted focus cue.

The input's computed focus outline is solid1px blue, but its rectangle is only **327×1px at390px /1089×1px at1440px**, at the editor's top under the sticky heading area. The visible editor/frame ancestors have no outline or shadow. The computed input style therefore does not establish visible focus on the reading surface.

Functional controls remain good: the editor reports readonly=true; Tab leaves it, reverse Tab reaches More actions, and Tab returns. Native Find has exact source-backed match counts and Escape returns focus without changing bytes. Those separate controls are retained in the evidence below. This report concerns visible keyboard ownership, not lost focus, an editable source buffer or a failed search.

## Cause and bounded repair

`dashboard/src/features/ledger-editor/file-editor/components/ledger-file-view/text-editor.tsx:231–270` disables the read-only cursor/line highlights and renders the read-only wrapper with `[&_.monaco-editor_.cursor]:hidden!`, without a visible editor focus style. The owning frame in `text-file-view.tsx:236` is `border overflow-hidden flex-1 flex flex-col`, also without a focus cue. The ordinary baseline `:focus-visible` rule reaches the small native input, not the visible reading frame; actual images and ancestor styles show the gap.

Draw keyboard focus on the visible owning editor/frame through a suitable supported wrapper or editor-focus integration. Preserve the intentional read-only cursor policy, actual readonly semantics and existing editable-editor behavior. Keep the indicator visible without being clipped by the frame or sticky headings in light/dark and forced-color compatibility controls. Retain source bytes, scrolling/wrapping, line targeting, Find, tab traversal, Escape and persistent editor/draft behavior. Do not make the source writable, move focus to another control, change every app input or add dependencies/API changes. Other languages, README/unknown-text readers, entry-context Monaco instances and writable modes are compatibility audit scope; only this read-only Beancount viewer is a demonstrated visual failure.

Acceptance: with the real editor mounted, native More actions → Tab visibly marks the source frame at both widths/themes; its next sticky-heading Tab stop retains its own cue. A meaningful real-editor/native regression must verify actual painted focus, not only a computed outline or mocked prop. Repeat existing Find, line-link and reverse-Tab controls; run dashboard format:check, lint, test and build when implementing. Other engines, physical forced-color palettes, actual screen-reader speech and repaired behavior remain unverified.

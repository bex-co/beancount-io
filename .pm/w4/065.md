# German is the only locale that leaves "YTD" untranslated — on five surfaces, and it is the single real gap in 456 keys × 12 languages

**Severity:** trivial. **Estimate:** 5 minutes for the string; ~20 if the guardrail below is added too. Owner: mobile. A3: `YTD` is an English finance acronym with no currency in German, sitting in a row where its two neighbours — `1J` and `ALLE` — *were* translated. Dutch, a locale that deliberately keeps `Home`, `Filters` and `Account` in English, still coined `JTD` for it.

Environment: branch `main`, HEAD `038faeeb`, native development build `io.beancount.ios` on iPhone 17e / iOS 26.5, light, default text size, `open_ledger/alphabet`. App locale forced to `de` via the persisted `locale` key (method in `w4/063`) and restored afterwards. Report-only QA; no ledger mutation.

## Repro

Set the app to Deutsch. Home and Reports both show the range row as:

```
1M   3M   6M   YTD   1J   ALLE
```

`1J` (Jahr) and `ALLE` are German; `YTD` is not. Observed on Reports (`Berichte`) and on the Home balance card.

**11 of 12 non-English locales translate it. German is the only one that does not.** `1M`/`3M`/`6M` matching English in several locales is *correct* — Monat, mes, mois, maand, mês, mesiac all begin with M — so those are not gaps. What makes this a miss rather than a choice is that the German file translated `1Y → 1J` and `ALL → ALLE` in the same group and stopped at the middle one.

A German rendering along the lines of `SJB` (seit Jahresbeginn) or `JTD` — Dutch's own coinage for the same phrase — would fit the row's width budget.

## Where it shows

`rangeYTD` is referenced from two key maps and reaches **five** surfaces:

| map | surface |
| --- | --- |
| `RANGE_LABEL_KEYS` (`series-util.ts:20-27`) | Home balance card (`account-charts-card.tsx`) — **observed** |
| | Reports (`reports-screen.tsx:90`) — **observed** |
| | Budget screen (`budget-screen.tsx:182`) |
| | Account drill-down balance card (`balance-chart-card/index.tsx:72`) |
| `DATE_RANGE_LABEL_KEYS` (`transactions-screen/filters/types.ts:33`) | Transactions → Filters date chips (`transaction-filters-screen.tsx:306`) |

Both maps point at the same key, so one string fixes all five.

## Fix

Set `rangeYTD` in `src/translations/de.ts` to a German abbreviation, and have a native speaker pick between `SJB` and `JTD` — the row is width-constrained (see `w4/064`, where German already overflows this card's tab row), so a 3–4 character form is the target rather than a spelled-out phrase.

**Acceptance:** with the app in Deutsch, the range rows on Home, Reports, Budget, the account drill-down and the Transactions filter sheet all show the German label; no other locale changes; and the label still fits the non-scrolling pill row at default text size (check `fa`, which is RTL, and `ru`, whose `С нач. года` is the longest, are both unaffected).

**Worth adding while here:** a test asserting that no non-English locale leaves a *non-universal* key identical to English. The detector below is the whole implementation, and the allowlist it needs is small and explicit — which is what makes the check cheap rather than noisy.

## How this was found, and why the result is reassuring

Every `"key": "value"` pair was parsed out of all 13 files and each non-English value compared with English. **456 keys in `en`; every other locale defines 450–459.** Counting keys whose value is byte-identical to English:

```
bg  6    ca 15    de 21    es 14    fa  6    fr 25
nl 26    pt 16    ru  6    sk 11    uk  6    zh  6
```

Filtering to keys identical to English in **exactly one** locale — the shape a genuine oversight takes, as opposed to a word that is simply the same in several languages — leaves **20 candidates**, and triaging them by hand leaves essentially one:

- **Correct, not gaps (18):** Dutch `account`, `accounts`, `accountsPlural`, `accountSettings`, `filterAccount`, `filters`, `home`, `metadata`, `accountPickerRecent`; French `date`, `note`, `notifications*`, `suggestions`, `transaction`, `transactions`, `discoveryPublic`; German `themeSystem` ("System"). These are the same words in those languages.
- **Arguable:** German `commitDetailDiff` = `"Diff"`. Accepted jargon in German developer usage; **not filed**.
- **A real miss (1):** `de rangeYTD`.

So the translation set is in very good shape — one genuine gap out of roughly 5,400 translated strings — and this note is narrow on purpose. The 6 keys identical to English in ≥10 locales are universal tokens and were excluded.

## Blast radius

One string in one locale file. No code change, no layout change outside the five pill rows listed above, no effect on any other language.

Not exercised: the Budget screen, the account drill-down and the filter sheet **in German** — those three are source-traced through the shared key rather than captured, since they use the same `t("rangeYTD")`. Also not exercised: Android, and whether a longer German form would overflow the row (which is why the fix specifies an abbreviation).

## Adjacent states

The German localization is otherwise thorough and was swept on device in the same pass — Home (`Startseite`, `Nettovermögen`, `Letzte Transaktionen`), Accounts (`Konten`, `Konto`/`Saldo`, and the five root categories `Vermögen` / `Verbindlichkeiten` / `Eigenkapital` / `Einnahmen` / `Ausgaben`), Transactions (`Transaktionen`, `Suchen`), Reports (`Berichte`, legend `Einnahmen` / `Ausgaben` / `Gewinn`) and the tab bar all render fully translated with no clipping.

**Two things are worth recording as working, because they are easy to assume broken:**

- **Dates in list content are properly localized.** The Transactions date header reads `30. Juni 2026` in German, and the Reports month axis reads `JAN FEB MÄR APR MAI JUN`. That sharpens **`w4/056`**: the app clearly *can* localize month names, and the date **picker** is the one place that opts out via its `locale="en_US"` pin — it is not a missing capability.
- **The Accounts tree's root translation is deliberate**, not a leak: `account-table/flatten-rows.ts:17-18` documents "an i18n key on category rows, a ready display name below them", so depth-0 rows translate (`Vermögen`) and everything below keeps the raw ledger name (`NonCurrent`, `Current`). Consistent with the tree's own comment; not filed.

## Dedupe

`grep -rn 'rangeYTD\|YTD' .pm --include='*.md'` over the whole board including `done/` → hits in `w4/037`, `w4/054`, `w4/064`, all read.

- **`w4/037`** ("`YTD` on a stale account reports a year that ended nine years ago") is the same pill and an entirely different defect: its subject is `rangeStartMonth`'s *anchoring*, i.e. what YTD computes. This is what the pill is called in one language. No shared code, no shared fix; they merely share a label.
- **`w4/064`** (filed this run) is the same card's tab row overflowing in long locales, and is cited above for the width constraint on the fix.
- **`w4/043`** is three Settings strings that never reach `t()` at all — a different failure mode (no key) from a key whose German value was left English. **`w4/046`** is dead keys, the inverse problem.

No item covers an untranslated locale value.

## Cause and bounded repair

`AVERAGE_COST_MAX_FRACTION_DIGITS = 8` is passed unconditionally to `roundDecimalString` for average_cost. For `0.00000000150`, the first eight fraction digits and rounding digit are zero, so the BigInt/string routine returns `0`. Both scalar cells and tableToCSV delegate to this same helper. This is deterministic decimal rounding, not floating-point error, a wrong BQL quotient, a source-price defect or deployment lag.

Retain bounded readable derived quotients while preserving a meaningful nonzero result below the fixed eight-place boundary, using the existing string arithmetic and a deliberate small-value precision/significant-digit fallback. Use the same result for screen and CSV. Keep genuine zero, ordinary eight-place/repeating quotients, exact quotients, half-up carry behavior and null/empty handling. Preserve source units, price, book/market values and the separate percentage-column policy. Do not restore unbounded 28-digit quotients or convert decimal strings through Number; no new formatter dependency, API or engine change is needed.

Acceptance: this actual producer's nonzero average stays numerically nonzero and recognizably 0.0000000015 in both native table and downloaded CSV at both widths, while the threshold and true-zero controls remain correct. Cover meaningful digits below/around the cap and ordinary repeating/exact/carry cases with the real formatter path, then run dashboard gates when implementing. No product implementation or formal test was authored during QA.

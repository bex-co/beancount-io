# Return Update Budget to its refreshed card after saving

**Severity:** minor. **Owner:** dashboard. **Estimate:** 45–60 minutes. **A2:** a keyboard user should retain a useful position after successfully updating a target. Residual of completed W4/238 and W3/m23's successful-dialog focus contract; no new historical finding group.

## Reproduction and controls

Production `https://beancount.io`, 2026-10-26 UTC; owned isolated headless Chromium156.0.8078.47, English/light, authenticated writer on the designated disposable synthetic ledger. Four fresh native journeys: twice at1440×1000 and twice at390×1000. No modeled responses, delayed requests, faults, focus intervention during the failing handoff or product/CSS alterations.

1. Through Accounts, open synthetic `Expenses:Qa-20261026` on2026-01-01. Through the Budget header's Add Budget, add a100.00USD monthly target dated2026-10-01. The successful header dialog returns to its persistent Add Budget button.

4. After that settled two-row history plus600ms, the old card and old Update button are disconnected. A new matching Update button exists, but **document.activeElement is BODY**. Native Enter from this position opens zero dialogs and sends zero extra writes. All four journeys reproduce.

## Cause and bounded repair

`dashboard/src/features/ledger-data/budget/add-budget-dialog.tsx:176–187` acknowledges the successful write, closes the dialog and separately starts GetLedgerJournal refetch, correctly preserving [M41](./done/m41/README.md)'s distinction between a saved write and a failed read. `use-budget-entries.ts:31–36,90–95` reports first-page refetch loading. Budget's `index.tsx:223–322` places its card list inside QueryView; `common/components/query-view.tsx:54–59` replaces those children with the loading skeleton. The card's own AddBudgetDialog and registered DialogTrigger at `budget-chart-card.tsx:402–425` therefore leave with the card, and no stable owner restores focus to the logical replacement after loading. The page-level Add dialog at `index.tsx:324–335` has a persistent header return ref outside that replaced list, explaining its passing control.

Coordinate successful Update focus from a stable Budget owner: after the relevant same-ledger list refresh, return to the connected replacement action for the submitted account/interval/currency, or a useful persistent Budget fallback if that action is absent. Respect a later opening, route/ledger change or focus deliberately chosen by the user; never steal focus after such changes. Preserve ordinary Cancel/Escape, pending dismissal, the failed-submit retry target from [M42](./done/m42/README.md), and truthful acknowledged-write versus failed-refresh behavior. Do not turn a failed refresh into a failed write, repeat a write, restore a detached trigger or globally alter QueryView/Dialog loading policy. No API/dependency change or other package work is indicated; do not import another feature's private focus helper.

Acceptance: exercise the real Budget page/card/dialog with its watched Apollo query through successful native Update and real cache/refetch transitions. After settlement, the logical Update or connected fallback is focused, and immediate Enter opens the intended form exactly once. Verify desktop/narrow and preserve the passing header Add/Cancel controls, exact two target rows and amounts, failed/pending refresh handling and stale-opening/ledger/focus safeguards. A dialog-only test with a permanently mounted trigger or no-op refetch misses this cause. Run dashboard format:check, lint, test and build when implementing.

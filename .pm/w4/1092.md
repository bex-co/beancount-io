# Preserve leading zeros in bare-year Time filters

**Severity:** minor. **Estimate:** 25–40 minutes. **Owner:** dashboard. **A2:** entering a supported four-digit year must preserve that period through the URL and API request.

## Fresh native reproduction — 2026-10-25

Production `https://beancount.io`, owned isolated headless Chromium156.0.8078.47, anonymous public synthetic `open_ledger/example`, English/light/UTC. Independent fully settled1440×1000 and390×844 runs; the narrow run uses the actual **Filters** sheet and its visible Time field.

1. Open `/ledger/open_ledger/example/balance-sheet?time=2016&lang=en`. The report loads normally and Time shows2016.

## Cause and bounded repair

`dashboard/src/common/lib/ledger-search-params/parse.ts:87–95`, **toLedgerFilterSearchParam**, converts every string matching four digits with `Number(normalized)`. Thus0100 becomes100 and0001 becomes1. normalizeLedgerSearchValue later stringifies that number without its original padding. The parent ledger search schema calls this helper at `schema.ts:25`; applyLedgerFilterSearch also calls it at `parse.ts:78`. Both link validation and native edits therefore lose the valid year.

LedgerSearchControls commits the custom Time text through setSearchParams. The provider applies that patch through the same shared helper, and report loader/query consumers receive the corrupted string. Installed TanStack qss/search serialization was inspected: its decoder retains non-round-tripping numeric strings such as0001, so a router fork or global parser change is unnecessary. The application explicitly performs the lossy conversion.

Keep a four-digit year as a string whenever number conversion would lose its representation. Retain the existing numeric encoding for ordinary bare years such as2015/2016, preserving their clean URLs. Do not guess padding for genuinely invalid one-/three-digit input, weaken backend validation or change API date support. Keep clearing, legacy double-encoding recovery, unrelated route parameters and pending filter-patch composition intact.

The helper is shared by parent-ledger validation, native filter updates, ledger-action search and Money Movement drill-down links. Five report loader wrappers and the ledger layout consume the normalized filters. Balance Sheet is independently live-tested; Journal/account/action links and other reports are shared-code regression scope, not separate live failures.

Acceptance: exercise the real schema/provider/router with native0100/0001 entry and direct/reloaded links; the field, URL, loader dependencies and API retain the four-digit year and the report succeeds. Keep the passing early-month and modern-year controls, invalid-date classification, Clear all, unrelated filters/offset handling and legacy links. Add meaningful shared-helper/router coverage, repeat both widths and run dashboard gates when implementing. No API, translation or dependency change is required.

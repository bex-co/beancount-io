# Restore report-view focus when the selector hides

**Severity:** minor keyboard continuation. **Estimate:** 35–50 minutes. **Owner:** dashboard (`common/components/responsive-tab-trigger-list/index.tsx`). **A2:** a reader choosing a report view should continue in that report when its narrow selector gives way to desktop tabs.

## Genuine live reproduction

Production `https://beancount.io`, 2026-10-22, owned isolated headless Chromium 155.0.8059.85, anonymous public ledgers, English/light/UTC. Two fresh Holdings contexts and one independent Income Statement context, each starting at 390×844 and resized only within the owned page. Genuine reads, no response/state fixtures or writes.

1. Open `/ledger/open_ledger/stock-example/holdings?lang=en`. Use the native **View** selector to choose **Holdings by Currency**. Its four rows and `view=by-currency` URL settle, with focus correctly returned to View.
2. Focus View and press Space to open its listbox. Widen to 1440×1000 while the list is open. Radix correctly closes the list on the resize, and the desktop **Holdings by Currency** tab appears selected.
3. After the list detaches, body locks clear and two animation frames settle, focus is **BODY**. The old selector remains connected but has `display:none` and zero client rects. Native Tab reaches **Skip to main content** at the top of the page, abandoning the report controls.
4. A second fresh Holdings context repeats. On `/ledger/open_ledger/example/income-statement?time=2016&lang=en`, selecting **Expenses** and repeating the same open-selector resize yields the same BODY → Skip-link handoff, with Expenses still selected.

Working controls in all three retained contexts: ordinary Escape at 390 returns focus to the visible View selector. Resizing an open selector from 390 to 768, where it remains visible, also closes it and correctly restores that focus. Each context then returns to 390 and waits for layout before the failing desktop transition. Manually focusing and activating the selected desktop tab recovers normally. Holdings retains its four exact grouped rows; Income Statement retains Expenses and Time 2016. No selection, query-result or valuation defect is claimed. Pointer and scroll locks clear, and no orphan listbox remains.

## Cause and bounded repair

The shared ResponsiveTabTriggerList renders both controls: SelectTrigger uses `lg:hidden`, while TabsList uses `hidden lg:flex`. Its SelectContent has no `onCloseAutoFocus` handoff. The installed Radix Select closes on the window resize (`dist/index.mjs:370–377`), then its unmount callback calls the original trigger's focus method (`:446–449`). That connected but hidden trigger cannot receive focus. The shared Select wrapper already forwards the supported callback.

Own the fallback in ResponsiveTabTriggerList, which knows the equivalent selected desktop tab. Keep normal close focus on the available narrow trigger; when that trigger is hidden, return to the visible selected tab within this same component. Check actual availability, preserve deliberate focus movement, and avoid a global focus policy for unrelated Select consumers. Keep the controlled selected value, native tab/Select behavior, RTL/forced-color styling, report URL/history and resize lock cleanup. No fixed delay, remount, extra query, dependency or API change is needed.

Acceptance: rendered browser coverage repeats open-selector 390→1440 closure with focus on the visible selected tab and native Tab continuing from that workspace. Preserve 390 Escape, 390→768 close-focus return, subsequent native view changes and selected content through resize. Cover Holdings and a statement consumer, and retain existing controlled-view/forced-color regressions. Run dashboard gates when implementing. No product code or formal test was authored during this QA.

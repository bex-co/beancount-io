# Price export follows destination symlinks and hard links back into the source ledger

Severity: **major**. Package: **cli**. Estimate: **40–55m** for destination
preflight, source-alias protection and regression coverage. Source: continuous
CLI QA for w4. **A1/A2:** creating an export must not rewrite the original books.

Environment: 2026-09-21, main `390568c220bfbdb0df1c9decb8436c64dfa3c9ca`,
checkout `cli/.venv/bin/bea` 0.3.0, Python 3.13.3, Darwin arm64. Synthetic
fixtures and all outputs stayed beneath `cli/tmp/qa-20260921-cli-loop/`.
Fresh processes used child-only config/cache/data directories there,
`BEA_NO_UPDATE_NOTIFIER=1`, no inherited BEA_FILE/BEA_TOKEN, and bounded
25-second captures. No hosted account, live price fetch, or real ledger.

## Reproducer and observed result

Create a disposable valid source:

```text
input/main.bean             include "parts/*.bean"
input/parts/accounts.bean   2024-01-01 open Assets:Cash USD
```

Create `output/`, then make `output/main.bean` a symlink to the absolute
`input/main.bean`. Run:

```sh
bea --json --file /absolute/input/main.bean price export --output /absolute/output
```

Exit 0, empty stderr, manifest lists `output/main.bean` and
`output/parts/accounts.bean`. **The original `input/main.bean` changes** from
`include "parts/*.bean"` to `include "parts/accounts.bean"`, because the
export follows the destination symlink. This changes which future files the
source ledger includes. Repeat from pristine fixtures with a hard link
(`os.link(input_main, output_main)`) instead: exactly the same original-file
rewrite occurs. Symlink and hard-link cases each reproduced twice.

Expected: reject an export destination aliasing any source ledger file before
writing any export files, preserve source bytes, and identify the conflicting
path. This is explicit in completed w1/m29/t005: exporting never modifies the
customer's ledger. It should not depend on the spelling of the destination.

Working controls: a clean dedicated destination exports without changing the
source; exporting directly into the source directory already exits 2 with
`it holds main.bean, which the export would overwrite`. Query/format output
aliases also correctly refuse the same class of overwrite in separate live checks.

## Cause, scope, and repair

`cli/src/bea_engine/managed_load.py:537–544` protects only when the export
**directory** equals a source file's parent. It never compares the individual
mapped destinations with source files. `:560–563` calls `dest.write_bytes(...)`,
which follows symlinks and overwrites the inode shared by hard links.
`_rewrite_export_includes:602–607` expands the glob, making the source mutation
observable even without a managed feed.

Preflight the entire destination plan against source identities before the
first mkdir/write. Resolve path aliases and use inode/samefile checks for
existing destinations; a lexical or resolved-path-only comparison cannot catch
hard links. Refuse conflicting sources with a useful usage error, preserving
all source and existing output bytes. Keep the exporter local-only; no backend
or dependency change is needed. `export_portable` has one production caller,
engine `main.py:597`, reached by frontend `_export` and its `-o`/`--output` aliases.

- [ ] Both exact alias fixtures fail before mutation with the conflicting
      destination/source identified; no source or output file changes.
- [ ] Check all planned outputs, not only the root copy; preserve the existing
      direct-source-directory guard and clean-destination success.
- [ ] Add real filesystem symlink and hard-link CLI regressions around source
      bytes and export effects; run CLI gates when fixing.

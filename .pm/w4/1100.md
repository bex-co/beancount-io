## Cause and bounded repair

`dashboard/src/features/ledger-editor/create-file/index.tsx` initializes `filename` to an empty useState value. Its Input at:231–252 relies on onChange to call setFilename, while readOnly covers **isSaving only**. Before that handler exists, native typing changes the DOM without changing filename state. Hydration's controlled empty value removes the accepted name. The shared Input correctly forwards native props; it is not the owner of this missing readiness condition.

Use the existing hydration-readiness mechanism at this local filename field. Before binding, it must honestly refuse editing; afterward, the first accepted complete name must remain. Extending the current readOnly condition is an option that can preserve its existing autofocus; a disabled gate must also preserve the intended ready-focus behavior without stealing a reader's later chosen focus. Keep pending-save readonly, permissions, filename/path/clash validation, the exact file content, Save eligibility, dirty Cancel/Stay/Leave behavior and late-completion ownership. Do not delay the whole page or Monaco, add a timer/dependency/API, change every shared Input, or remove autofocus without preserving its purpose.

Acceptance: actual CreateFilePage SSR→hydrate coverage exposes the local field unavailable for early editing, enables it naturally, and accepts one exact valid name without requiring a second entry. Verify the filename focus handoff and a deliberate move to Cancel/editor, plus ordinary validation and the fully exercised Cancel→Stay→Leave controls. Preserve pending-save and folder-read-failure safeguards. Repeat desktop/narrow and run dashboard format:check, lint, test and build on implementation.

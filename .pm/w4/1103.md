# Keep profile search unavailable until typing can be retained

**Severity:** minor. **Owner:** dashboard. **Estimate:** 35–50 minutes. **A2/A3:** a visitor searching the public example collection should not lose a completed search on the initial load. One additional W4/211 search-readiness consumer residual, alongside1099's separate Accounts owner; no new historical finding group.

## Reproduction and controls

Production `https://beancount.io`,2026-10-25 America/Los_Angeles; owned isolated headless Chromium156.0.8078.47, anonymous public synthetic `open_ledger` profile, English/light/UTC. Three retained fresh natural loads: two at **390×1000**, typing at50ms/character, and one at **1440×1000**,20ms/character. No script delay, read fault, substituted response, storage seed or hosted write.

1. Fresh-open `/ledger/open_ledger?lang=en`. Focus the visible, enabled **Search ledgers…** field and type **example** before its client handler attaches.
2. All seven native characters are visible in the input. A passive observer records21 trusted input events across the three cases, all with no attached React onChange; the complete term exists before handler attachment in each case.
3. Let the ordinary hydration finish without another edit, then wait700ms after observing the handler. The focused input becomes **empty**, its controlled value is empty, URL has no `q`, and the collection again displays **Showing 12 of 50 loaded ledgers**. All three cases reproduce the completed-term loss.
4. Retype `example` into the now-ready same field. It persists and the URL gets `q=example`; the actual collection displays **Showing 3 of 3 loaded ledgers**: crypto-example, example and real-estate-example. Activate **Clear search**: the field empties, the initial12-card view returns and focus stays in search.

The failed native typing windows were761–1074ms,1014–1329ms and991–1120ms after navigation start; handler first observed1293ms,1479ms and2066ms respectively. These are individual observations, not performance thresholds.

Timing control: a fresh1440px run at70ms/character continues typing after its handler attaches. The first two characters were unbound, later events adopt the current complete native value, and `example` survives correctly. Therefore this finding specifically covers **finishing the term before attachment**, not every keystroke that starts early. A JavaScript-disabled HTTP200 profile document exposes the search field enabled and writable; the actual repaired Gallery document in the same control exposes its distinct search field disabled.

An independent anonymous GetUserProfile control returns HTTP200, no errors and50 loaded public repositories; case-insensitive name/description matching independently gives those exact three examples. The50-item profile preview cap and its honest “loaded” labels are deliberate and working. This is not a missing repository or failed search producer.

## Cause and bounded repair

`dashboard/src/features/user-profile/components/ledger-collection.tsx:93` initializes the controlled `query` from the profile URL, empty here. Its Input at:213–236 is enabled throughout SSR, accepts native text, but only the later onChange can call `editQuery`. On hydration/re-render, its empty controlled state overwrites a completed native edit. No recoverable hydration or page error is involved. Its sole production owner is UserProfileTabs' Ledgers panel, shared by profile routes.

Gate this local search field with the existing TanStack hydration-readiness mechanism, following211's Gallery implementation. Keep its persistent localized name and initial URL value visible, but render the actual input unavailable until it can retain changes; enable it without a timer or forced focus afterward. Preserve the debounced250ms q update, replace-history behavior, blur flushing, pending-destination guards, q/sort/show restoration, preview cap, clear focus and browser search semantics. Do not wait for all page requests, replace the collection, alter the shared Input globally or add persisted draft state. No API, backend, dependency or native-mobile change is needed.

Acceptance: real SSR→hydrate coverage exposes an unavailable profile search before binding and a usable field afterward; the first permitted full term remains visible and filters to the correct records. Retain direct prefilled q links, the successful typing-through-attachment case, Clear focus, sorting/show reset and opening a ledger/Back with current query intact.

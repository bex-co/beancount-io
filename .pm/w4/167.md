# Formatting an empty directory with --output reports a file write that never happened

Severity: **minor**. Package: **cli**. Estimate: **25–40m**. Source: continuous
CLI QA for w4. **A1:** automation must distinguish a produced export from a
missing or stale destination.

Environment: 2026-09-21, main `390568c220bfbdb0df1c9decb8436c64dfa3c9ca`,
checkout `cli/.venv/bin/bea` 0.3.0, Python 3.13.3, Darwin arm64. Fresh subprocesses
with closed stdin, 25-second bounds, isolated child config/cache/data paths and
update notices disabled; inherited BEA_FILE/BEA_TOKEN removed. Cwd and all files
were beneath `cli/tmp/qa-20260921-cli-loop/`. No hosted account or real ledger.

## Reproducer and evidence

Create an empty disposable directory `empty`, then use absolute paths:

```sh
bea --json format /absolute/empty --output /absolute/out.bean
```

Exit 0, empty stderr, and stdout:

```json
{"bea":"0.3.0","target":{"directory":"/absolute/empty"},"data":{"scanned":0,"output":"/absolute/out.bean"},"truncated":false}
```

`out.bean` does not exist. Repeating from a second fresh destination gives the
same result. If the destination already contains `SENTINEL\n`, it remains
byte-identical while the command returns the same success envelope. Human
mode exits 0 with `No .bean or .beancount files found.` and likewise creates nothing.

Expected: refuse an explicit output operation with no input files, with a
nonzero usage error and the zero-file scan result, preserving any existing
export. This follows `cli/docs/USAGE.md`'s exit-0 effect promise and its statement
that successful `-o FILE` identifies what was written. Do not silently publish
an output path that still contains an older export.

Working controls: a directory containing one valid ledger writes the named
output and reports `scanned: 1`; empty-directory `--in-place` already exits 2.
An explicitly empty stdin stream is different: it is a supplied stream and
successfully creates an empty output file. Preserve that supported filter case.

## Cause and bounded repair

`cli/src/cli/commands/format.py:102–116` handles an empty discovered file list
before reaching the formatter. Its JSON `output_file is not None` arm calls
`output.emit(_wrote(0, output_file))` and returns without opening/writing the
file. The human arm prints the no-files sentence and also returns success.
The sibling in-place arm already raises a usage error. `_wrote:547` simply
constructs the optimistic result. Registration is `cli/main.py:301`.

Make explicit file-output handling for zero discovered inputs reject consistently
in human and JSON mode, without changing intentional scan-only checks or
stdin formatting. Caller search finds this handler as the single top-level
format command, with `-o` and `--output` sharing the same branch. No engine,
backend, dependency or protocol surface needs changing.

- [ ] Empty-directory output with a nonexistent destination exits 2, creates
      nothing, and emits one JSON error instead of a success result.
- [ ] An existing destination remains unchanged and is not reported written;
      human mode gives the same failure category.
- [ ] One-file output and empty-stdin output continue creating the promised
      file; scan-only and in-place controls retain their documented behavior.
- [ ] Add focused CLI coverage of observable file effects and run CLI gates.

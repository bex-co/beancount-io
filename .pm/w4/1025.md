# Preserve Income Statement chart units when regrouping periods

**Minor · 45m · dashboard · A2.** Found while fixing [1024](./done/1024.md): the Income Statement's date-balance charts drop the reader's legend choice when the interval changes, as Cash Flow's did. The amounts are correct; only the chosen view is lost.

## Reproducer

Local build from main `c6cd0427b`, public example ledger, fresh 1440×1000 Chromium context, real legend clicks at the rendered item coordinates and the real interval select. The chart instance was read only to observe its selection.

1. Open `/ledger/open_ledger/example/income-statement?time=2016`, Monthly.
2. Click VACHR, then USD, in the legend: `USD:false, VACHR:true`.
3. Choose Quarterly. This is a new read, and the chart remounts as a new instance. The legend comes back as **`USD:true, VACHR:false`**.
4. After choosing VACHR alone again, cached Monthly resets the same way, because each new option carries the primary-unit default.

Expected: the chosen units survive both paths while they remain available, as Balance Sheet (m51) and Cash Flow (1024) now do.

## Cause and repair

`income-statement/date-balance-chart/single-date-balance-chart.tsx:128` and `stack-date-balance-chart.tsx:182` call `legendSelectionFor` without a chosen map, and neither renderer passes `onLegendSelectChanged`. The page's pending branch (`income-statement/index.tsx:119`) unmounts the content, and with it any chart-local choice.

Use the shared `useLegendSelection` hook in `reports/lib/legend-selection.ts` in both charts, and hold each chart's choice on the page through the content, keyed by chart, as Cash Flow's `unitSelections` does. Memoize each option on translated strings, never `t`. Keep the initial primary-unit default, 997's missing-primary fallback, deliberate all-off choices, and the pending/settled guards.

Acceptance:
- Real ECharts legend-event regressions for both charts cover the cached regroup and the pending remount.
- A page test covers the held selection.
- A native check at desktop and narrow widths passes.
- Dashboard gates pass.

## Hosted native confirmation — 2026-10-23

Repeated anonymously against `https://beancount.io` in four fresh, isolated headless Chromium `156.0.8078.47` contexts, English/light/UTC: Net Profit (single bars) and Income (stacked bars), each at 1440×1000 and 390×844. Routes use `/ledger/open_ledger/example/income-statement?time=2016-12&view=netProfit&lang=en`, or `view=income&mode=stacked`.

In every case, native canvas legend clicks chose `USD:false,VACHR:true`. Native Monthly → Quarterly sent one genuine `GetLedgerIncomeStatement` read (`time:"2016-12"`, `conversion:"at_cost"`, `interval:"quarterly"`), HTTP 200 with data and no GraphQL errors. The chart became a new instance and reset to `USD:true,VACHR:false`. After reselecting VACHR alone, cached Monthly made **zero further financial reads**, retained that Quarterly chart instance, and reset the choice again.

Controls: reselecting VACHR works; opening the interval menu preserves it; choosing the already-selected Monthly preserves it. All underlying series values remain identical through regrouping. The single Net Profit plot carries raw ledger values USD −4802.68 and VACHR −15; this confirms selection loss and makes no sign-convention defect claim. No hosted writes, mutation attempts, route errors or page errors; all four contexts closed.

Served assets: `ledger._ledgerOwner._ledgerName.income-statement-B9byEnS4.js` and renderer chunk `index-CqfcWzCA.js`. Their source maps confirm both renderers lack a legend-change callback. The complete served renderer files differ from main `aa9c0fb6b` (including 997's fallback and formatting changes), so this is not a whole-build match. The working tree already contains the 1025 repair in progress; these observations describe the older hosted client and do not verify that repair. Other Income Statement tabs, all-off choices and unit-removal behavior remain regression scope rather than additional native confirmations.

# Preserve source-code direction in Persian commit diffs

Severity: **minor**, dashboard. Estimate: **35–50 minutes**. A2 — readers reviewing bookkeeping changes should see source tokens in source order even when the surrounding interface is right-to-left.

Production `https://beancount.io`, 2026-10-09, dedicated QA login, public synthetic `open_ledger/crypto-example`, isolated headless Chromium 149.0.7827.55. Fresh 1440×1000 and 390×1000 contexts, Persian and English. Source rechecked on main **567943aa**, unchanged after pulling; exact deployed SHA is unverified.

## Reproduce

1. Open `/ledger/open_ledger/crypto-example/commit/0d023f5e1c7029c4977fe11004fee0551caa147c?lang=fa`. Open the translated changed-files disclosure using Enter, activate `transactions/transfers.bean` using Enter, then activate the translated Load Large Diff button using Enter.
2. The virtualized target header is correctly revealed. In source line 14, the date `2024-01-25` appears to the **right** of the quoted Coinbase payee/narration; source comments' initial semicolons also move to the right. Screenshots at both widths were visually inspected.
3. The actual source-content span computes `direction:rtl` and `unicode-bidi:normal`. Its DOM still puts the date before Coinbase. Native text Range rectangles at 1440px put the date at x=941.75 and Coinbase at x=573.28125; at 390px, x=227.75 and x=-140.71875 respectively. These are text-token rectangles, not whole-row bounds.
4. Fresh English controls on the same commit/file render `direction:ltr`: date x=682 before Coinbase x=783.140625 at desktop, and x=90 before x=191.140625 at narrow width. Their screenshots preserve the source date/flag/payee order. Independent initial Persian contexts at both widths showed the same reordered display before this four-context comparison.
5. A separate genuine `getCommitDetails` read succeeds HTTP 200 and confirms the added source line starts with `2024-01-25` before Coinbase. The date was not moved by the API. This is browser bidirectional rendering, not corrupted ledger contents or a persisted edit.

Long source lines also extend beyond the narrow pane in both languages. Their general overflow behavior is outside this note; it is not evidence that every clipped character is a Persian-specific failure.

## Cause and bounded repair

`dashboard/src/common/components/diff-viewer/diff-viewer.tsx` renders virtualized source rows as flex elements with line-number, change-marker and `whitespace-pre` content spans, without isolating the source direction. Its containing document supplies RTL direction. The small-diff branch likewise delegates to Diff/Hunk inside an unisolated `.diff-viewer-container`; that branch is a source-derived regression scope, not an independently reproduced small-diff claim. The owning stylesheet does not provide a source-direction boundary.

Set an explicit left-to-right direction for the code/gutter rendering in both existing diff paths, with appropriate bidi isolation. Keep localized headings, warnings and navigation in their actual interface direction. Preserve source text, whitespace, line numbers, insertion/deletion markers, virtual scrolling, token highlighting, file focus and the deferred large-diff gate. Use the existing integration; do not fork upstream, change APIs/dependencies or rewrite source strings to work around visual ordering.

Acceptance: the real Persian journey renders the date/flag/payee and initial comment marker in source order at both widths while the shell stays RTL and target navigation stays correct. Cover both small and virtualized source paths, including quoted Persian text inside a source string, without changing its underlying text. Keep English controls passing. Verify emitted direction/isolation CSS and actual browser token rectangles; a DOM-text-only assertion misses this bug. Run dashboard gates when implementing.

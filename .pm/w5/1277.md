# Smart Import's Configure step accepts any account for any row, with no notice: a typo, an account opened after the row's date, or a partly typed name such as "Assets:Bank:Ch" all pass until the ledger refuses the whole batch (gap in w3/560)

**Severity:** minor (the ledger refuses the write, so nothing bad is committed). **Owner:** `dashboard`. **Estimate:** 45–60 minutes including moving the availability hook to `src/common/` and a rendered test. **A2:** a newcomer importing last month's statement into a ledger that opens its accounts on the first of this year sees every field accepted and **Import N Transactions** enabled, and learns only from the refusal that the accounts did not exist on those dates. New Entry already warns under the field ("{account} isn't open in this ledger.", "… is closed before …", "… opens after …") and offers to open a new account in the same write (w3/560). Smart Import writes the same transactions through the same `BulkEntries` mutation with none of that. With w5/1276 unfixed, the refusal also throws the whole draft away. **Found by:** `/qa-find-bugs-dashboard` (`dashboard-qa` routine) on 2026-11-28 against `https://beancount.io`, production entry chunk `main-BBmi61Hs.js`, local HEAD `8f66924bb`. Isolated headless Chromium 158 at 1440×1000, English, signed in as the QA owner on its designated disposable ledger `<qa-owner>/mcp-agent-eval` (synthetic fixture `backend-cluster/backend-v2/evals/mcp-agent/fixtures/main.bean`, every account opened 2026-01-01). Every import was refused by the server, so nothing was written (`main.bean` stayed at blob `f1a0b83c`).

## Repro

1. Open `/ledger/<owner>/<ledger>/import`, choose a CSV with the rows `2026-09-01,qa-20261128-r2 Cafe,Coffee,-4.50`, `2026-09-02,qa-20261128-r2 Market,Groceries,-45.67` and `2026-09-03,qa-20261128-r2 Employer,Salary,2500.00`, and press **Continue to Configure**.
2. In **Source Account** type `Assets:Bank:Ch`. The list shows the one match, **Assets:Bank:Checking**. Press Enter. The field keeps `Assets:Bank:Ch`, not the match (the combobox commits typed text unless an option is highlighted). In row 1's target type `Expenses:Fo` and press Escape: the field keeps `Expenses:Fo`, and the "missing target accounts" count drops by one.
3. No field is marked invalid (`aria-invalid="false"`), no notice appears, and **Import 3 Transactions** is enabled.
4. Press it. `BulkEntries` is refused: "adding these entries would introduce 4 new bean-check errors: Account Assets:Bank:Ch was never opened (main.bean:89); Account Expenses:Fo was never opened (main.bean:89); …".

Same from a fresh load with every account picked from its list, but one row dated `2025-12-15`: no notice in Configure, then "Account Assets:Bank:Checking used on 2025-12-15 but not opened until 2026-01-01". And with one target typed as `Expenses:Food:Grocery` and Tab: no notice, then "Account Expenses:Food:Grocery was never opened".

Control: New Entry on the same ledger, with `Expenses:Food:Grocery` typed in Posting 1 and Tab, shows "Expenses:Food:Grocery isn't open in this ledger." under the field, with a checkbox "Also open Expenses:Food:Grocery on 2026-11-28". The dialog was closed without saving.

## Cause

- `dashboard/src/features/importer/components/steps/configure/transaction-config-form.tsx:75-125`: the schema requires only a non-empty `sourceAccount` and, for selected rows, a non-empty `targetAccount`. It never asks whether the ledger can post to that account on the row's date.
- `common/components/ledger-comboboxes/account-combobox.tsx:93` passes `allowCustom={true}`, so a typed partial name is a value. That is deliberate (New Entry relies on it to name new accounts) and is not the bug. New Entry pairs it with `useAccountAvailability` and `AccountAvailabilityNotice` (`features/journal/components/new-directive-dialog/use-account-availability.ts`, `account-availability-notice.tsx`, added in `d695a871f` for w3/560). The importer has neither.

## Fix

- Move `useAccountAvailability` and the notice from `features/journal/components/new-directive-dialog/` to `src/common/` (`dashboard/AGENTS.md` forbids one feature importing another's private hook), and keep New Entry on the moved copy unchanged.
- In Configure, check the source account against every selected row's date, and each row's target against its own date. Show the notice under Source Account (naming the first offending date) and mark each offending row's target with the same message. Keep **Import** disabled while any selected row would be refused, with the count in the existing alert ("2 rows use accounts the ledger can't post to on their dates"). A never-opened name with a valid shape may offer "Also open … on <earliest row date>" the way New Entry does, sent in the same `BulkEntries` batch. Without that, the user deselects or re-targets the rows.
- No backend change. The server's refusal stays the final guard.

## Definition of done

On `/import` with the fixture above: a typed `Assets:Bank:Ch`, a typed `Expenses:Food:Grocery`, or a picked account on a row dated before its `open` each shows a notice before Import is pressed, and Import stays disabled until the row is fixed, deselected, or (for a new name) set to be opened. A file whose rows all fall on dates where their accounts are open imports exactly as today. New Entry's notices behave as before. A rendered Configure test with mocked account directives covers never-opened, opened-later and closed-before cases. It fails on current code. Dashboard gates pass.

## Blast radius

Add Budget already gets a server refusal "for the first budget on an unopened account" (`backend-v2` `ledger-entry-service.ts`). It was not exercised here. Bank Sync's review table was not exercised either (it needs a linked bank).

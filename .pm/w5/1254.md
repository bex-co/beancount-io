# Entry Context calls a transaction you wrote with flag `S`, `P` or `C` "generated" and hides its source, Edit and Delete: "This opening balance was generated when the account journal was limited to a time range" (dashboard half of w21/745)

**Severity:** minor. Nothing is written wrongly, but an ordinary entry cannot be edited or deleted from the Journal, the account page or Overview. The dialog also tells the reader something false about where the entry came from. Since w21/652 the API accepts any capital-letter flag, so these are ordinary user entries. **Owner:** `dashboard` (`features/journal`). **Estimate:** 30–45 minutes including tests. **A1/A2:** a ledger migrated from another tool, or written by an agent, may use any Beancount flag letter. Entry Context is the dashboard's edit path for one entry. w21/745 fixed the same mistake in the mobile app and the ledger service, and its resolution covers no dashboard change. **Found by:** `/qa-find-bugs-dashboard` (`dashboard-qa` routine) on 2026-11-27 against `https://beancount.io`, entry chunk `main-BBmi61Hs.js`, isolated headless Chromium 158 at 1440×1000, English. The run was signed in as the QA account and used a disposable synthetic QA ledger, which was restored byte-for-byte afterwards. Local HEAD `219e7833f`.

## Repro

1. On a ledger that opens `Assets:Cash` and `Income:Dividends`, append:

   ```beancount
   2026-11-20 S "qa-20261127-r14 settled flag S"
     Assets:Cash        -9.00 EUR
     Income:Dividends    9.00 EUR

   2026-11-21 P "qa-20261127-r14 posted flag P"
     Assets:Cash        -7.00 EUR
     Income:Dividends    7.00 EUR

   2026-11-22 C "qa-20261127-r14 cleared flag C"
     Assets:Cash        -3.00 EUR
     Income:Dividends    3.00 EUR

   2026-11-23 R "qa-20261127-r14 refund flag R"
     Assets:Cash         5.00 EUR
     Income:Dividends   -5.00 EUR
   ```

   The ledger checks clean: `getLedgerErrors` returns `[]`.
2. Open `/ledger/<owner>/<ledger>/journal?filter=qa-20261127-r14`. All four entries are listed, flagged `S`, `P`, `C` and `R` under **Other**.
3. Open the `S` row. The dialog says **"This opening balance was generated when the account journal was limited to a time range, so it has no source line to view, edit, or delete."** Below that is a "Generated entry" table. The only button is **Close**.
4. Open the `P` row: **"Beancount generated this entry from a pad directive, …"**. Open the `C` row: **"This conversion was generated to clear the residual cost balance of a time-limited account journal, …"**. Each has only **Close**.
5. Open the `R` row (control). It shows `Location: main.bean:107`, the source editor, **Delete** and **Save**.
6. Open `/ledger/<owner>/<ledger>/entry/<hash>` for the `S` entry and for the `P` entry (working control). Each shows `Location: main.bean:95` (`:99` for `P`), its source, **Delete** and **Save**.

Steps 3–5 were repeated from a fresh load.

**API control:** `getLedgerEntryContext(entryHash, ledgerId)` returns each `S`, `P` and `C` entry's source `slice`, with `generated_from: null`. For a real time-window summary it answers `NOT_FOUND` ("Entry with ID '…' not found"). That summary is the 2015-07-31 "Opening balance for 'Liabilities:US:Chase:Slate' (Summarization)" row on `/ledger/open_ledger/example/account/Liabilities:US:Chase:Slate?time=2015-08`. The server can tell the two apart. The dialog decides before it asks.

## Cause

`dashboard/src/features/journal/components/entry-context-dialog.tsx:60-77` (`GENERATED_FLAGS`, `isGeneratedEntry`) decides "generated" from the flag letter alone. `:190` and `:270-271` then render `GeneratedEntryPanel` instead of `EntryContextPanel`, so no context read is made. The check came in with `8c7185f85` (w4/110, 2026-09-19), when only generated rows carried these letters. `EntryContextPanel` already reads `generated_from` for plugin copies (`entry-context-panel.tsx:217-218`, `:299`). The standalone entry page works because it always renders that panel.

## Fix

Dashboard only, and the same as the mobile half of w21/745: decide by provenance, not by the letter. For a `P`, `S` or `C` entry, read the context as for any other entry. Show `GeneratedEntryPanel`, with its current w4/110 explanation and no "could not be found" error, only when the read answers `NOT_FOUND`. That covers padding and a time window's opening and conversion rows. Otherwise show the ordinary panel with its source, Edit and Delete. While the read is pending, show the panel's usual loading state rather than a generated verdict. Three places use the dialog: `features/journal/pages/journal-page.tsx`, `features/reports/account/index.tsx` and `features/reports/overview/components/recent-activity-card.tsx`.

## Definition of done

- With the repro, the `S`, `P` and `C` rows open from the Journal with their source line (`main.bean:<n>`), **Save** and **Delete**. The `R` row is unchanged.
- On `open_ledger/example` with `?time=2015-08`, the account page's "Opening balance … (Summarization)" row still opens the generated explanation, with no error.
- Rendered dialog tests fail on the current code: an `S`-flagged entry whose context read succeeds shows the source panel; one whose read answers `NOT_FOUND` shows the generated panel; the same holds for `P` and `C`. Dashboard gates pass.

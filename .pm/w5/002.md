# `bea format` cannot read its documented stdin input

**Severity:** minor. **Estimate:** 25–40 minutes. **Owner:** cli. **A1/A2:**
shell pipelines and coding agents cannot format text without first creating a
temporary ledger file, even though the documented safe default is stdout from
stdin.

Found 2026-09-13 by a report-only CLI QA sweep against `main`, HEAD
`038faeeb`, using `uv run bea` 0.2.0 on Darwin 25.5.0 arm64 with isolated
config/cache directories. The fixture was a valid synthetic ledger containing
only local data.

## Repro

```sh
printf '2026-01-01 open Assets:Cash USD\n' | bea format
```

In a fresh non-TTY process, the command exits `2`, writes no stdout, and
forwards this native usage error to stderr:

```text
Usage: bean-format [OPTIONS] [FILENAMES]...
Try bean-format --help for help.

Error: At least one FILENAME is required.
```

`bea format --output clean.bean` with the same stdin fails identically, and
`bea format -` treats `-` as a filesystem path and reports
`Formatting target does not exist`. The nearby upstream control works:

```sh
printf '2026-01-01 open Assets:Cash USD\n' | uv run bean-format -
```

It exits `0` and prints the formatted source. An explicit ledger path also
works through `bea format main.bean`.

## Expected / actual

The quick-start contract at `cli/docs/USAGE.md:199-200` says `bea format`
prints formatted text to stdout and leaves the file alone. The implementation
comment at `cli/src/cli/commands/format.py:158-164` likewise says a bare
command formats stdin. The command should consume the pipe, print formatted
source, and exit `0`.

Instead, the wrapper invokes upstream without a filename, so upstream rejects
the call before reading stdin. JSON mode has the same underlying failure and
also exposes the native plain-text error rather than the normal JSON usage
envelope. The existing JSON destination rule should apply here too: bare JSON
stdin with no explicit destination should be a JSON usage error, while
stdin-to-file should use the successful envelope behavior recorded in
`w5/001.md`.

## Root cause

When `_targets()` returns `None`,
`cli/src/cli/commands/format.py:62-68` calls
`launch.run_native("bean-format", [*alignment, *_destination(output_file)])`
without the stdin sentinel. The pinned `bean-format` interface requires a
filename when no `-` argument is supplied; passing `-` directly to that native
interface is the working stdin path. `_targets()` currently resolves an
explicit `-` as a local path at `:170-174` instead of recognizing it as stdin.

## Fix

Make the documented non-JSON stdin mode pass `-` to `bean-format`, and
recognize an explicit `bea format -` as the same mode. Preserve the existing
usage errors for stdin combined with `--check` or `--in-place`. In JSON mode,
return the normal JSON usage error when no explicit destination is available,
and route `--output FILE` through the successful write envelope. Add pipeline
regressions for stdout and stdin-to-file; keep explicit-file and directory
formatting controls.

## Blast radius and adjacent states

All bare stdin formatting, including stdin-to-file output, is affected. Named
files, recursive directories, in-place formatting, dry-run, and check flows
were exercised and work according to their contracts. TTY input, Windows, and
other installed `bean-format` versions were not exercised.

## Dedupe

Searched all `.pm/**/*.md`, including `done/`, for formatter stdin, piping,
and `bean-format` terms. `.pm/w1/done/m15/done/t005.md` records older format
targeting work, while `.pm/w2/019.md` covers syntax-error behavior and
`.pm/w2/023.md` covers check hints and alignment validation; none covers the
missing stdin sentinel. The current source and docs both still promise stdin.
`git log --oneline -- cli/src/cli/commands/format.py` shows the stdin branch
originated in the independent-engine implementation (`a90b1706`) and has no
follow-up repair on `main`.

# Accounts offers Delete for an account a balance assertion still names, then refuses with "was never opened (main.bean:27)", pointing at the very `open` line being deleted

**Severity:** minor (a dead-end action with a misleading message). **Owner:** dashboard, with a small field in backend-v2/ledger. **Estimate:** 45–60 minutes including tests. **A2:** a newcomer tidying a chart of accounts after a first import opens an unused account's menu. The menu offers **Delete**, since the account has no postings, and the reason under the disabled items says that is the rule. The confirmation then fails with an error that names the line the dialog itself labels "Open", so the user cannot tell that a `balance` assertion two lines down is what keeps the account in use. **Found by:** `/qa-find-bugs-dashboard` (`dashboard-qa` routine) on 2026-11-21 against `https://beancount.io`, entry chunk `main-CIyNN76T.js`, isolated headless Chromium at 1440×1000, English, signed in as the QA owner on the designated synthetic ledger (probe entries removed afterwards, ledger restored byte-for-byte). Local HEAD `8724f3464`.

## Repro

1. Add to the ledger's `main.bean` (lines 27–29 here):

   ```beancount
   2026-01-01 open Assets:Qa-20261121-Probe USD

   2026-01-02 balance Assets:Qa-20261121-Probe 0.00 USD
   ```

2. `/ledger/<owner>/<ledger>/accounts` → **Actions for Assets:Qa-20261121-Probe**. The menu offers **Open register**, **Close Account** and **Delete**, all enabled. For an account with postings, Delete is disabled with "Only an account with no postings can be deleted."
3. **Delete**. The dialog says "This will permanently delete the open directive for Assets:Qa-20261121-Probe." and shows the source labelled **Open** `main.bean:27`.
4. **Delete**. `DeleteMultipleLedgerEntrySourceSlices` answers 200 with a refusal, and the dialog shows: "This would add an error to your ledger: Account Assets:Qa-20261121-Probe was never opened (main.bean:27)". Nothing is deleted.

`main.bean:27` is the `open` line in the file as it stands. The error's line is from the file as it would be after the delete, where the `balance` moved up to line 27. By the same count, an account named only by a `note`, `document`, `pad` or budget `custom` entry is offered Delete too (read from source, not exercised).

## Cause

- `accountEntryCounts` (`backend-cluster/ledger/src/features/ledger/utils/account-entries.ts:130-141`) counts transaction postings only, and `getLedgerAccountDirectives` returns that as `entryCount` (documented on REST as "counts the account's postings, not its directives", `backend-cluster/backend-v2/src/features/ledger/api/rest/v1/analysis-handler.ts:443`).
- The Accounts page enables Delete on `account.entryCount === 0` (`dashboard/src/features/ledger-data/accounts/index.tsx:283`), so an account other directives still name passes.
- The write gate's refusal reports the new error at its location in the projected file, and the dialog shows it next to the current file's location.

## Fix

- The menu offers Delete only for an account that no directive other than its own `open`/`close` names (postings, `balance`, `pad`, `note`, `document`, and `custom` account values). Otherwise Delete is disabled with a reason that says so, for example "Only an account no entry refers to can be deleted." That needs a count of those directives in the account-directive read: add a field (for example `referenceCount`) beside `entryCount` on GraphQL, and on REST in the same change per the parity rule. Do not change what `entryCount` means.
- When a delete is still refused (a race, or a reference the count misses), the message names the entry that still uses the account at its current location (here `main.bean:29`, the `balance`), not a line of the projected file.

## Definition of done

- In the repro, Delete is disabled with the new reason. After the `balance` line is removed, Delete is enabled and succeeds.
- An account with only a `note` (or only a budget `custom` entry) behaves the same way.
- Tests: the ledger count covers each directive type; a rendered Accounts test shows Delete disabled for a referenced account with no postings. They fail on the current code. The owning packages' gates and the backend parity suite pass.

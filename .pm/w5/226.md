# `--importer NAME` cannot choose between two instances of one importer class; the error lists the same name twice

## Reopened: generated selectors collide with declared importer names

**Minor · cli · 30–45m · A1 · worker1. Reproduced 2026-10-24 at
`ee4b7702516da4535bb3b478e2efe9913b09481b`.** The normal two-instance
repair in `510d77118` still passes. Its generated aliases can, however,
collide with another importer's declared name. Following the diagnostic's
selector then chooses another account or refuses a file the listed
importer recognizes. This is remaining acceptance in the same selector
generator; the original report and resolution are preserved below.

With two importers named `bank` and another named `bank#1`, passing
`--importer bank` exits 2 and lists:

```text
bank#1 (Assets:Cash)
bank#2 (Assets:Savings)
```

Following the Cash choice with `--importer bank#1 --apply` exits **0**
and posts the 10 USD payment to **Assets:Broker**, the third importer's
account. Cash remains **100 instead of 90 USD**; Broker becomes **90
instead of 100 USD**. Food is 10 USD, the whole ledger still balances,
and both native validation and fresh `bea check` pass. The preview
does report Broker, so callers comparing that field can catch the mismatch;
the defect is the selector advertised for Cash. Its exact repeat writes zero,
leaving the misrouted posting in place.

Exact declared names winning over generated aliases was a deliberate part
of `510d77118`; **keep that priority**. The generator must reserve those
names instead of advertising an occupied name for another importer.

Environment: bea 0.3.1, macOS 26.5.1 arm64, frontend Python 3.13.3,
managed Python 3.12.10 / Beancount 3.2.3. Use a fresh absolute directory
with this complete standalone recipe. The inspected importer uses only
the standard library and the already available Beancount core; it needs
no Beangulp installation, service, credentials or real ledger.

## Original report and shipped resolution

**Minor · cli · 20–30m · A1.** Real CLI QA, 2026-10-11, HEAD `a8b75aed` (CLI unchanged since `97600b74`), checkout `bea 0.3.1`, macOS.
A config with `[Bank("Assets:Checking"), Bank("Assets:Savings")]`, the
ordinary way to reuse one importer for two accounts, cannot be used: both
instances have Beangulp's default name, shown as `<run_path>.Bank`, and
passing that name to `--importer` returns the same error. No product fix
implemented.

Create disposable `/absolute/books/main.bean`:

```beancount
option "operating_currency" "USD"

2026-01-01 open Assets:Savings USD
2026-01-01 open Expenses:Food
2026-01-01 open Equity:Opening

2026-01-02 * "Opening balance"
  Assets:Checking  1000.00 USD
  Equity:Opening
```

`/absolute/books/imp.py`:

```python
import datetime
from decimal import Decimal as D
import beangulp
from beancount.core import data
from beancount.core.amount import Amount

class Bank(beangulp.Importer):
    def __init__(self, acct): self.acct = acct
    def identify(self, filepath): return filepath.endswith(".txt")
    def account(self, filepath): return self.acct
    def extract(self, filepath, existing):
        return [data.Transaction(data.new_metadata(filepath, 1), datetime.date(2026, 1, 5), "*", "Cafe", "Coffee", frozenset(), frozenset(), [
            data.Posting(self.acct, Amount(D("-5.25"), "USD"), None, None, None, None),
            data.Posting("Expenses:Food", Amount(D("5.25"), "USD"), None, None, None, None)])]

CONFIG = [Bank("Assets:Checking"), Bank("Assets:Savings")]
```

**Resolved 2026-10-13** — Importers that share a name now also answer to `NAME#N`, their position in `CONFIG` among the importers of that name, in `cli/src/bea_engine/importing.py`. When several same-named importers recognize a file, the error says the names collide, lists each one as `NAME#N (account)`, and advises either passing that selector to `--importer` or giving each importer a distinct `name`; the unknown-name error lists the same selectors, and `cli/docs/IMPORTING.md` describes the selector. Configurations whose importers have distinct names keep the previous message and behaviour, and an exact name always wins over a selector. The regression test `cli/tests/test_import_same_named_importers.py` covers the refusal with and without `--importer NAME`, applying with `NAME#2` to the second account, the JSON error details and preview, an out-of-range selector, and the distinct-name control; three of its four cases fail with the fix reverted. The test uses plain importer classes whose default name is the class name rather than Beangulp's `<run_path>.Bank`, since Beangulp is not in the development environment; the code path is the same. Only macOS was exercised. `make check-all` passed. Shipped in `510d7711` (`cli`).

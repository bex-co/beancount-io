# Query page charts of a date column put dates at even steps in row order and draw a smooth curve between them: `ORDER BY date DESC` runs time right to left, and 5 days take the same width as 169

**Severity:** minor. The chart above a `SELECT date, <amount>` result is the Query page's picture of how a balance moved over time, and it misstates that movement. Gaps between dates are not to scale. A descending query flips time without saying so. Two rows on one day get two x positions. A balance that held flat until its next posting is drawn as a curve through values it never had. **Owner:** `dashboard`. **Estimate:** 30–45 minutes. **A2:** a newcomer who charts an account's balance to understand it gets a false shape. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-18 against `https://beancount.io` (entry chunk `main-LGv2TZLj.js`), headless Chromium 1440×1000, English, isolated profile. Reproduced signed in and from a fresh signed-out context on the public ledger. Local HEAD `b6efcfbdf`. Read-only: no ledger writes.

## Repro

Public ledger, no sign-in needed.

1. Open `/ledger/open_ledger/example/query` and run `SELECT date, balance WHERE account = 'Assets:US:ETrade:GLD' ORDER BY date`. The table has 8 rows: 2015-09-15 5 GLD, 2015-11-13 15, 2015-11-18 10, 2016-05-05 12, 2016-09-23 17, 2017-02-15 7, 2017-03-19 9, 2017-08-27 17.
2. In the chart, all eight points are evenly spaced: 2015-11-13→2015-11-18 (5 days) is the same width as 2015-11-18→2016-05-05 (169 days). The smoothed line runs from 10 up to 12 across that half year, though the balance stayed at 10 until 2016-05-05.
3. Run `SELECT date, balance WHERE account = 'Assets:US:BofA:Checking' AND year = 2016 AND month <= 2 ORDER BY date DESC` (16 rows). The x-axis reads 2016-02-25, 2016-02-20, 2016-02-09, 2016-02-04, 2016-01-28, 2016-01-20, 2016-01-08, 2016-01-06 from left to right, so time runs backwards. The two 2016-01-08 rows (-2469.00 USD and -3164.03 USD) are two separate x positions with the same label.

## Expected / Actual

Expected: the x-axis is time. Dates run left to right in chronological order whatever the row order, and spacing is proportional to elapsed time. A balance holds its value until the next point. This is what Fava, the reference the code cites, draws: `get_query_chart` sends a `date` + `Inventory` result to `LineChart.svelte`, which uses `scaleUtc` for x and `curveStepAfter` for the line and area. Actual: a category axis in row order with even steps and a `smooth` spline.

## Root cause

`dashboard/src/features/bql/lib/chart-utils.ts:148-149` picks a line chart for a `date` first column. `:212` still gives it `xAxis.type: "category"`, with one category per row in result order (`:177`, `:213`), and `:235` sets `smooth: true` on the line. The header comment at `:12` says the chart follows Fava's logic, but Fava plots dates on a UTC time scale with step-after interpolation.

## Fix

- For a `date` first column, use an ECharts `time` x-axis and plot `[date, value]` pairs, so points sit at their dates and run chronologically for any `ORDER BY`. Parse the ledger's `yyyy-MM-dd` as a UTC calendar date (see `dashboard/AGENTS.md` on ledger dates), not a local instant.
- Draw the line and area stepped (`step: "end"`, the ECharts equivalent of `curveStepAfter`), not smoothed.
- Keep the tooltip on each row's exact source decimal and unit (`texts[dataIndex]`, w4/254). With a time axis, the hovered point must still map to its own row, including two rows on one date.
- Keep the w4/1049 tiny-value scaling, the w4/1076 large-result guard, the multi-unit refusal, and the bar chart for `str` first columns.
- Tests in `lib/__tests__/chart-utils.test.ts`: ascending and descending results build the same chronological series. A 5-day gap and a 169-day gap differ in x distance (the option carries real dates, not categories). Same-day rows keep their own tooltip text. The series is stepped.

## Blast radius

`parseQueryChart` has one production caller, `QueryResultCard` (`features/bql/components/query-result-card.tsx`). The report pages' own line charts use other builders and are out of scope. `str`-keyed bar charts are unchanged.

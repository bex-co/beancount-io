# Expand a register's resolved parent before filtering its postings

**Minor · cli · 25–40m · A1 · worker1.** Selecting the parent of a
register with an anchored regular expression silently drops its children's
transactions. Literal `Assets:Bank` returns the full **320 USD** subtree;
`^Assets:Bank$` resolves the same parent but returns only its own **100 USD**.
When the parent has only child postings, the anchored selector returns
`account: null, rows: []` and human **`No entries.`**, although its literal
register has **220 USD**. Each read exits **0**. Source files remain unchanged;
no product fix implemented.

Expected: the register's selector resolves one subtree root, then lists
that subtree's postings. Selecting the same parent via an exact regex
should not lose its descendants or return a false empty result. This is
the explicit register policy in `cli/docs/USAGE.md` (the register lists
one subtree) and `report.py:634–635` (a regex matching the parent but not
the children still shows the whole subtree). Ordinary tree-report regex
filtering is a different policy and should remain unchanged.

Root: `report.answer` first calls `_load(file, account, ...)`; the
`FilteredLedger` constructor applies `AccountFilter` to whole transactions
(`cli/src/fava/ledger.py:183–195`). Child-only transactions match neither
`^Assets:Bank$` nor any of its counterparties, so they are already absent
when `_register` builds `group_entries_by_account(filtered.entries)` at
`cli/src/bea_engine/report.py:616`. It resolves the parent from only active
matched posting/balance rows (:617–627), ignoring a declared parent with
no postings. Its intended subtree expansion (:634–637) can therefore see
only the surviving direct-parent transactions, or no parent at all.

`_register_root:695` has one caller, this `_register` path. Frontend
`commands/report.py::register:485` passes its positional selector to the
same engine account option; JSON and human render the incomplete result.
The documented parent-active/source-layout variants exercise that one
producer, not two different renderers losing their own data.

Fix in `cli/`: resolve the uniquely selected register root from the relevant
account set before discarding child-only transactions, then collect its
whole subtree from the correctly time-filtered ledger. Include declared
parents with only child postings. Preserve period opening balances,
posting/date order, lot costs, balance assertions, exact root boundaries
and the refusal of selectors spanning independent trees. Keep the general
`AccountFilter` behavior for ordinary reports; broadening it globally would
change those commands' documented matched-posting semantics. No dependency
or server API change is required.

Control clarification: `bea balance` positional arguments are documented
substrings, so its overall Assets total here legitimately includes BankTwo:
**820 / 720 USD**. Its specific Bank tree node is **320 / 220**, matching
native inventory and `report trial-balance --account Assets:Bank`. An
initial verifier mistook that alias's substring total for a parent-only
total; it was corrected to compare the actual Bank node and the trial

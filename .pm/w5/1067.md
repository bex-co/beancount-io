# Deduplicate signed-zero Amount metadata in native statement notes

**Minor · cli · 25–40m · A1 · worker1.** A native importer returning an
unchanged Note with `rate: Amount(Decimal('-0.00'), 'USD')` appends another
annotation on every apply. Native reload correctly holds `0.00 USD`, but the
comparison key still holds the incoming minus sign. Positive-zero Amounts,
nonzero Amounts and the recently fixed scalar Decimal zero deduplicate.
Default policy and explicit duplicate skip reproduce. Cash and refund counts
remain correct; no monetary loss or product fix is claimed.

## Cause and scoped repair

[`_directive_key`](../../cli/src/bea_engine/importing.py#L1910) canonicalizes
metadata by calling nested `unsigned` on each value (:1924–1932).
`unsigned` recognizes a scalar Decimal only. An Amount is a distinct native
object, so its negative-zero `number` passes through unchanged. The Balance
amount branch below explicitly unwraps an Amount, but metadata does not.

[`_directive_text`](../../cli/src/bea_engine/importing.py#L1897) returns the
printed entry. Writer [`_fixed_point_metadata`](../../cli/src/bea_engine/ledger/writer.py#L279)
handles scalar decimal spelling, while an Amount prints its numeric member.
The incoming comparison text therefore contains `rate: -0.00 USD`; native
parsing returns an Amount with unsigned `0.00` at the same exponent. The
[`_authored_directive_keys`](../../cli/src/bea_engine/importing.py#L2373)
set derives the positive-zero key from the ledger. The generic membership
check (:774–777) misses, and a Note remains `new`; apply appends it again.

Four current-runtime helper proofs use the actual controlled importer and
native-loaded Note. Both affected Amount pairs have equal native values,
equal currency/type and identical Decimal exponents, but unequal keys.
Positive-zero Amount and negative-zero scalar pairs have equal keys.
Actual importing/writer module hashes match the immutable current source.

Extend comparison-only zero canonicalization into an Amount metadata value's
number, retaining the Amount type, currency and precision. Preserve nonzero
numbers and literal strings, keep the existing scalar/Balance behavior, and
do not rewrite the incoming object, source bytes or appended text. Reuse the
existing Amount class/helper; no new dependency, flag, parser or API surface.
This is a local CLI import-key repair, not a change to native zero semantics.

Caller search: generic incoming directives use `_directive_key(entry,
target.parent)` in import classification (:774); `_authored_directive_keys`
uses the same helper for native-parsed written directives (:2392), excluding
transactions and prices. The public failure is verified for Note metadata;
other non-transaction kinds may share the key but are unverified here.
Price uses its separate quote index, and transaction units/costs/prices use
their own numeric identity path. Interactive sessions, other metadata object
types, plugins and other operating systems are unverified.

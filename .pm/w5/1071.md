# Accept native cost-rounding residuals in Cash Flow

**Major · cli · 40–60m · A1 · worker1.** The new priced-FX reconciliation
guard also refuses ordinary native-valid costed purchases with no posting
price. Buying three HOOL for `{{1000.00 USD}}`, paid by an explicit
`-1000.00 USD` cash leg, succeeds through `bea add transaction` and `bea check`.
Cash opens January at 2000 USD and closes at 1000 USD. Nevertheless,
`bea report cash-flow --time 2024-01` exits **2**, with no report, saying
“some transactions move cash in USD by a price, not by cost”. There is no
`@`/`@@` price on any posting. Native booking divides the total by three;
its accepted at-cost residual is **−0.0000000000000000000000001 USD**,
against an inferred **0.005 USD** tolerance. An exactly divisible cost works.
Source bytes and money are preserved; the regression prevents reporting.

## Standalone reproduction and controls

Put checkout `bea` on PATH, save the following as `recipe.py`, and run:

```sh
python3 recipe.py /absolute/unused/cost-book total standard root /absolute/managed-engine/bin/python
```

`renamed included` exercises EUR and renamed account roots in a split file.
The recipe creates the trade with the real CLI, compares it with a separately
handwritten native reference, checks the book, queries its costs and exports
and reloads a full PRINT copy. It captures 13 CLI calls and four uncached
native loads. All read-only calls preserve both authored files, including
refusals; only the selected file receives the add. Each native source and
export contains the same dates, postings, units, booked costs and cash facts.
PRINT legitimately makes inferred cash explicit and changes its inferred
validation tolerance; that derived tolerance is not a changed holding.

## Cause, repair and scope

The new [`_cash_flow`](../../cli/src/bea_engine/report.py#L1120) compares
cash movement with the activity subtotal using exact Decimal inequality
(:1121–1124), then refuses every unequal value (:1126–1137). It does not
consult native transaction tolerances or distinguish accepted booking-rounding
residuals from a real cross-currency basis mismatch. Decimal arithmetic is
appropriate; exact zero as the validity criterion is not. The fallback error
still says “by a price” even when no priced posting exists.

The guard was introduced in `dba24e754` for completed
[1068](./done/1068.md). Fresh pre-guard `61fa32c6c8b7b8151fad266e5276e2476f8446c8`
controls accept the total-cost and tolerated-expense books at exit 0, while
keeping the same native graphs. Preserve upstream's actual rounded costs and
amounts; [1010](./done/1010.md) explicitly requires native booked arithmetic.
One engine dispatch calls `_cash_flow` (:137); frontend
[`cash_flow`](../../cli/src/cli/commands/report.py#L620) carries this failure
to both JSON and human output. No sibling conversion, importer or API adapter
needs changing for this CLI-local report.

Bounded repair: derive an exact per-currency bound from the native accepted
transactions/options in this window, allowing their genuine rounding residue
while retaining 1068's refusal for unsupported priced-FX differences.
Compare native at-cost conservation against that bound, with no float or
blanket global epsilon. Keep actual opening/closing cash grounded in the
cash postings; if an accepted residual needs disclosure or a native rounding
adjustment to explain the rows, identify it explicitly instead of silently
back-solving historical opening cash. Error guidance must name a true basis
mismatch rather than claim that a costed purchase used a posting price.
Keep tiny legitimate amounts and native lot precision. No conversion of the
ledger, artificial price/cost annotation, dependency or backend change.
Run the owning CLI checks when implementing.

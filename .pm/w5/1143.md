# Overview month stepper and Customize reorder buttons drop keyboard focus when they disable themselves

**Severity:** minor (keyboard/assistive-technology focus). **Owner:** dashboard. **Estimate:** 30–45 minutes. **A2:** a keyboard user who steps to the newest month, or moves a module to the end of the list, should keep their place on the page. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-16 against `https://beancount.io`, using headless Chromium at 1440×1000 in English/light. The account was the QA owner, on its designated disposable synthetic ledger. Local HEAD `85c2548ba`. Nothing was saved: the module order was put back with Reset layout.

## Repro

1. Open the ledger Overview (`/ledger/<owner>/<ledger>`). On the QA ledger it opens on July 2026, and the last entry is Aug 28, 2026.
2. Tab to **Month shown → Next** and press Enter. The month becomes August 2026, and Next becomes `disabled` because no later month exists. `document.activeElement` is now `BODY`. Pressing Enter again does nothing, and a screen reader loses its position. The same happens with **Previous** at the earliest month.
3. Open **Customize**. Focus **Move down: Financial position** and press Enter three times. The first two presses move the module and focus stays on its button. The third press makes it the last module, so the button becomes `disabled`, and focus falls to the sheet's content `DIV`. The next Tab goes to the **first** control in the sheet (`Show module: Money movement`), not the next one. The same happens with **Move up** at the first position.

Repeated twice from fresh loads with the same result.

## Cause

The control the user just activated becomes natively `disabled` while it has focus, and the browser then drops focus.

- `dashboard/src/features/reports/overview/components/month-summary.tsx:111` (`disabled={index <= 0}`) and `:128` (`disabled={index < 0 || index >= dates.length - 1}`).
- `dashboard/src/features/reports/overview/components/dashboard-customizer.tsx:156` (`disabled={index === 0}`) and `:167` (`disabled={index === layout.order.length - 1}`).

Nothing hands focus back afterwards. The existing focus fixes in this sheet (w4/299) cover only closing it.

## Fix

When an activation leaves its own button disabled, move focus to the control that can still act. On the month stepper that is the opposite arrow (reaching the newest month puts focus on Previous). In the customizer it is the row's other arrow (Move up after reaching the bottom). Alternatively, use `aria-disabled` with a no-op click so the focused button keeps focus. This is what `features/journal/components/journal-pagination.tsx` already does for its loading state. Use one approach for both components. Keep the existing disabled visuals, labels, and the month live-region announcement.

## Definition of done

- In the repro above, after the press that reaches August 2026, `document.activeElement` is a button inside **Month shown**, not `BODY`. This also holds at the earliest month.
- After moving a module to the last position, focus is on that module's **Move up** button, or on a focusable equivalent in the same row. The next Tab goes to the next control in the sheet, not back to the top. The first position behaves the same way.
- A rendered test (Testing Library with `userEvent`) presses the boundary button and asserts where focus lands, for each component. It fails on current `main`.

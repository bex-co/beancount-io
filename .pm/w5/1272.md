# In Persian the Journal writes "+14 … 16" in Latin digits beside "+۴٬۶۳۹٫۷۰ USD", and Files writes "310.7 KB" in every language, German included (gap in w2/125)

**Severity:** minor (localization). **Owner:** `dashboard`. **Estimate:** 45–60 minutes including tests (eight call sites, one helper). **A2:** Persian is one of the 15 UI languages. w2/125 moved every count on the ledger pages to the language's own digits, so a Latin number in the middle of a Persian row reads like a rendering glitch. In German or French a file size with an English decimal point reads as the wrong magnitude ("310.7 KB" is "310 thousand 7" to a German reader). **Found by:** `/qa-find-bugs-dashboard` (`dashboard-qa` routine) on 2026-11-28 against `https://beancount.io`, production entry chunk `main-BBmi61Hs.js`. QA-owned headless Chromium 158, isolated profile, 1440×1000, language set through the app's preference (`i18nextLng`). Read-only on the public `open_ledger/example`; the Upload Files check selected a file and cancelled without uploading. Local HEAD `ffcebb96f`.

## Repro

Public ledger, no sign-in needed. Pick the language with `?lang=fa` or `?lang=de`.

1. Open `/ledger/open_ledger/example/journal?lang=fa`. The Payroll row of 2017-09-07 reads `Income:US:Hoogle:Salary → Assets:US:BofA:Checking +14 +۴٬۶۳۹٫۷۰ USD 16`. The amount and the pager (`۱ ۲ ۳ … ۱۹`) use Persian digits. The `+14` (more accounts) and the posting-count button `16` use Latin digits.
2. Read that button's accessible name: `نمایش ۱۶ ردیف حسابداری برای 2017-09-07 Hoogle Payroll (ردیف 2)`. The posting count is Persian (`۱۶`), but the row position is Latin (`2`). The same holds for the "Open entry" button on every row (`… (ردیف 59)`), and on account journals and Overview, which use the same rows.
3. Open `/ledger/open_ledger/example/files/tree/main?lang=fa`. The sizes read `310.7 KB` and `1.91 KB`, next to dates in Persian digits (`۸ آبان ۱۴۰۵، ۱۵:۴۹`).
4. Open the same page with `?lang=de`. The sizes still read `310.7 KB` and `1.91 KB`, next to `30. Okt. 2026, 15:49`. Statistics on the same build writes German decimals (`2.754,06 USD`).
5. Signed in with write access, open Upload Files (`/files/upload/main?lang=de`) and choose a 2.5 KB file. The list reads `(2.5 KB)`. Cancel.
6. Open `/ledger/open_ledger/example/commit/deb272d?lang=fa`. The commit header reads `1 فایل +۳ -۰`, but the "files changed" list under it gives the same file as `+3 -0`.

## Cause

- `features/journal/components/journal-posting-toggle.tsx:52,88` render `{amount}` (the posting count) as a raw number. `features/journal/components/journal-lines.tsx:453,477` and `journal-days.tsx:488` render `+{flow.more}` the same way. Both arrived with the compact Journal in `91daf9b46` (2026-11-18), a week after w2/125's sweep.
- The accessible names `journal.openEntry`, `journal.showEntryPostings` and `journal.hideEntryPostings` take `{position}` as well as `{count}`. w2/125 taught the `t` wrapper to localize `count` only, so `position` stays Latin.
- `features/ledger-editor/shared/lib/utils.ts` `formatFileSize` builds `parseFloat(x.toFixed(d)) + " " + unit` with no locale. Its callers are the Files list (`directory-browse/components/ledger-directory-view.tsx:340`), the image, PDF and other non-text file views (`file-editor/components/non-text-file-views.tsx:76`) and Upload Files (`upload-files/index.tsx:453`). The receipt page has its own copy, `(selectedFile.size / 1024).toFixed(1) KB` (`features/receipt/components/receipt-upload-zone.tsx:122`).
- `features/git/commits/components/commit-file-list.tsx:56,59` render `+{file.additions}` and `-{file.deletions}` raw. `features/git/pull-requests/components/pr-file-list.tsx:43-44` does the same for pull requests. The commit header's totals beside them already use the language's digits.
- Read from source and not reproduced live: the Errors page writes `` `${t("page.errors.line")} ${err.lineno}` `` (`features/ledger-data/errors/index.tsx:168-169`), and the AI quota panel uses `toLocaleString()` with no locale, which follows the browser rather than the app (`common/components/ai-cfo-upgrade-panel.tsx:70-82,174`). `useFormatCount` names that as the mistake it exists to prevent.

## Fix

Owned by `dashboard`. No API change.

- Format the Journal's posting count and `+N` with `useFormatCount()`, and pass `position` to the three journal messages already formatted (or extend the `t` wrapper's numeric `replace` from `count` to `position`), so `۱۶`, `+۱۴` and `(ردیف ۲)` read in Persian digits. English stays `16`, `+14` and `(row 2)`.
- Give `formatFileSize` the app language and format the number with `Intl.NumberFormat(language, { maximumFractionDigits })`. Results: German `310,7 KB`, Persian `۳۱۰٫۷ KB`, English unchanged `310.7 KB`. Point the receipt upload zone at the same helper. Keep the unit labels as they are.
- Format the per-file `+N`/`-N` of the commit and pull-request file lists, the Errors line number and the AI quota numbers with `useFormatCount()`.
- Tests: a Persian Journal row renders `۱۶` and `+۱۴`, and its button names carry Persian row positions. `formatFileSize` gives `310,7 KB` for `de` and `۳۱۰٫۷ KB` for `fa`. Both fail on the current code.

## Definition of done

- On production, `/ledger/open_ledger/example/journal?lang=fa` shows the Payroll row as `+۱۴ … ۱۶`, and its button names end `(ردیف ۲)`. `/files/tree/main?lang=de` lists `310,7 KB` and `1,91 KB`, and `?lang=fa` lists `۳۱۰٫۷ KB` and `۱٫۹۱ KB`. The `deb272d` commit's file list reads `+۳ -۰` in Persian. English pages read exactly as today. Dashboard gates pass.

## Blast radius

Searched `features/` and `common/` for raw counts in JSX (`{amount}`, `+{`, `.length}`), `toFixed(` near a unit, and `toLocaleString()` / `Intl.NumberFormat()` without a locale. The sites above are the ones found. Controls that already use the language's digits: the Journal pager and its `first–last / total` (w2/125), Accounts' postings and group counts, Events' `filtered / total`, the commit header's `+N -N` totals, and every amount. ISO dates, account names, commit SHAs, diff line numbers and raw BQL/Holdings cells stay as they are by design (w2/119, w2/125).

## Dedupe

Searched `.pm/**`, including `done/` and `blocked/`, for `formatFileSize`, ` KB`, Persian digits, `useFormatCount`, `+{flow.more}`, posting count and row position. w2/125 (done) is the digit sweep these sites missed. Two of them (the Journal chips) postdate it, and file sizes were not counts, so it never looked at them. w5/1219 covers the hand-built Holdings and commit file counts, and w5/1220 covers Accounts' zero balance. Neither names these surfaces. Local `main` still has every site, so this is not deployment lag.

**Unverified:** the image/PDF file view and the receipt chip live (read from source). Errors page line numbers live (no errors on a public ledger). Other non-Latin numbering systems: only `fa` uses one among the 15 languages.

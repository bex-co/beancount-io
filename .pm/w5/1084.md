## Reproduce

Save the following as `reproduce.py` and run `python3 reproduce.py /absolute/fresh-qa-opening-case` with this checkout's `bea` on PATH. The directory must not already exist. It declares the native summarizer's opening account so missing-account prerequisites cannot explain the failure.

```python
import os, subprocess, sys
from pathlib import Path
case = Path(sys.argv[1]).resolve()
case.mkdir(parents=True, exist_ok=False)
book, out = case / 'main.bean', case / 'export.bean'
book.write_text(r"""option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Assets:Broker HOOL
2024-01-01 open Equity:Opening USD
2024-01-01 open Equity:Opening-Balances
2024-01-01 open Income:Gains USD
2024-01-01 * "Capital"
  Assets:Cash 1000.00 USD
  Equity:Opening -1000.00 USD
2024-01-02 * "Purchase"
  Assets:Broker HOOL {5 USD}
  Assets:Cash -25.00 USD
2024-01-03 * "Purchase"
  Assets:Broker HOOL {5 USD}
  Assets:Cash -15.00 USD
2026-01-02 * "Purchase"
  Assets:Broker HOOL {5 USD}
  Assets:Cash -10.00 USD
2026-01-03 * "Partial sale"
  Assets:Broker -2 HOOL {5 USD} @ 7 USD
  Assets:Cash 14.00 USD
  Income:Gains -4.00 USD
2027-01-01 query "opening" "PRINT FROM OPEN ON 2026-01-01 CLOSE ON 2027-01-01"
""")
env = os.environ.copy()
for key in ('BEA_FILE', 'BEA_TOKEN', 'BEA_ENGINE_PYTHON', 'BEA_ENGINE_DIR'):
    env.pop(key, None)
env.update(BEA_CONFIG_DIR=str(case/'config'), XDG_CACHE_HOME=str(case/'cache'),
           BEA_NO_UPDATE_NOTIFIER='1')
steps = [
    ('source-check', book, ['check']),
    ('full-export', book, ['query', 'PRINT', '-f', 'beancount', '-o', str(out)]),
    ('full-check', out, ['check']),
    ('opening-export', book, ['query',
        'PRINT FROM OPEN ON 2026-01-01 CLOSE ON 2027-01-01',
        '-f', 'beancount', '-o', str(out)]),
    ('opening-check', out, ['check']),
]
for tag, file, args in steps:
    argv = ['bea', '--no-input', '--offline', '--file', str(file), *args]
    r = subprocess.run(argv, cwd=case, env=env, stdin=subprocess.DEVNULL,
                       capture_output=True, text=True, timeout=25)
    print(tag, 'exit', r.returncode)
    print('stdout:', r.stdout)
    print('stderr:', r.stderr)
print(out.read_text())

```

Actual exits are **0, 0, 0, 0, 1**. The successful opening export has empty stdout/stderr and replaces the preceding valid full export. The final check reports:

```text
Ambiguous matches for "-2 HOOL {5 USD}": 8.00 HOOL {5 USD, 2025-12-31}, 2.00 HOOL {5 USD}
```

The generated opening transaction is dated December 31 and contains `Assets:Broker 8.00 HOOL {5 USD}`. On reload, that explicit quantity acquires the transaction's date. The later source-inferred `HOOL {5 USD}` purchase stays undated, so the sale now sees two lots. The valid source ends with one eight-share lot at 5 USD whose cost date is absent; an independent native load confirms the unfiltered full export retains that exact lot.

The authored sources remain byte-for-byte unchanged. This is damage to the published copy, not deletion or mutation of the source ledger.

Expected: preserve the original unknown acquisition date and valid sale, or clearly refuse before publishing and leave the previous valid export intact. Do not invent an acquisition date, switch booking methods, drop the sale or relax validation.

## Controls and mechanism

The six affected public cases are strict, FIFO and a single opening lot without a subsequent purchase, each root/direct and split/stored. Strict fails with the ambiguity above. FIFO's published file also fails native loading: sorting the newly dated and still-undated matching lots raises `TypeError: '<' not supported between instances of 'NoneType' and 'datetime.date'`. With no post-cutoff purchase, loading succeeds but the remaining six-share lot silently gains cost date `2025-12-31`. These are consequences of the same generated-lot date change, not separate tasks.

Six nearby controls — shared explicit cost date, ordinary explicit quantities with natural acquisition dates, and costless priced units, each in both layouts/forms — preserve the native stock positions and reload valid. All full exports pass before the opening export replaces them. The priced controls declare native `Equity:Conversions:Previous` / `Equity:Conversions:Current` accounts; earlier missing-account fixture attempts are excluded from these results.

An independent native, in-memory Beanquery `PRINT FROM OPEN ...` producer trace retains absent cost dates for all three Broker postings: opening 8.00, purchase 2.00, sale -2. The opening transaction has `filename='<summarize>'`, `lineno=0`; its posting metadata is None. Thus the date change happens when serializing and reloading, not in the native query's accounting result.

`cli/src/bea_engine/query.py:1588` dispatches Beancount results to `_render_beancount` (:1823), which applies `_with_inferred_units` (:1887–1907). That helper restores missing quantities only when `reader._number_left_open` (`ledger/reader.py:532–548`) can verify an authored source line. A generated opening posting has no such location, so its booked quantity remains explicit and `DirectivePrinter` (`ledger/writer.py:82`) prints it that way. Native `beancount/ops/summarize.py:500,601–666` creates these transactions and copies the original units/cost into postings with no metadata. Native `parser/booking_full.py:622–624` skips date augmentation when units are missing; :702–704 assigns the transaction date to an explicit augmentation. This native behavior is the control, not a request to fork booking.

The query and reader source are identical to the completed 1066 fix `5dc925747`; the printer class AST is identical too. Later writer changes concern append/close validation and inferred import comparisons. Targeted history contains no later generated-opening repair. Caller search covers the shared Beancount renderer, its source-inference helper, CSV directive cells and writer formatting. Confirmed here: one-shot direct and stored `PRINT` with a native opening window. Interactive output, explicit native `--source`, arbitrary plugin-derived lots, other generated transaction types and other platforms are unverified.

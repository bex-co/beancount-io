# Keep token boundaries after a single-letter cost currency

**Minor · cli · 35–50m · A1 · worker1.** A valid cost in currency `X` or
`Q` needs whitespace before its following comma or brace in Beancount's
native syntax. The shared directive formatter removes that boundary:
`{5 X , 2024-01-02, "A"}` becomes `{5 X, 2024-01-02, "A"}` and
`{5 X }` becomes `{5 X}`. Valid single adds, native imports and listed-JSON
bulk replay are refused. `query PRINT` and transaction `--details` instead
succeed but emit text that fails both native and CLI checks. Original
source ledgers remain valid and unchanged. No product fix implemented.

## Standalone reproduction

Put checkout `bea` on PATH and replace the two `/abs/…` paths with a fresh
disposable directory and the existing managed engine Python. `symbol='Q'`
repeats the defect independently. `simple=True` tests the closing-brace
boundary without an explicit date/label. `two-letter` uses XX/QQ;
`price` keeps the one-letter currency but uses a posting price. Both are
working controls. The initial native reference and `bea check` establish
that each exact input fixture is valid before writes are attempted.

```python

case = Path('/abs/single-letter-cost-case')
engine = Path('/abs/managed-engine/bin/python')
symbol = 'X'  # Q is another single-letter currency

simple = False  # True: omit explicit cost date/label, keeping whitespace before the brace
human_add = False

2024-01-01 * "Capital"
  Assets:Cash 1000.00 CUR
  Equity:Opening -1000.00 CUR
2024-01-05 price HOOL 8 CUR
'''.replace('CUR',currency)
annotation='@ 5 '+currency if mode=='price' else ('{5 '+currency+' }' if simple else '{5 '+currency+' , 2024-01-02, "A"}')

NATIVE='''import json,sys

'''

    env.pop(key,None)

    return {str(p.relative_to(case)):hashlib.sha256(p.read_bytes()).hexdigest()
        for p in case.rglob('*') if p.is_file() and '__pycache__' not in p.parts}

        '--no-input','--offline','--file',str(file),*map(str,args)];started=time.monotonic()
    r=subprocess.run(argv,cwd=case,env=env,stdin=subprocess.DEVNULL,capture_output=True,text=True,timeout=25)
```

## Cause and scoped repair

`cli/src/bea_engine/ledger/writer.py:120–144` delegates posting text to
upstream `EntryPrinter`, then selectively repairs cost syntax.
`_cost_spec_text:205–241` appends the cost currency without a trailing token
separator and joins fields with `", "`; the containing cost formatter closes
the brace directly after the result. That leaves one-letter currencies
adjacent to punctuation that the native lexer does not accept. For a normal
booked `Cost`, the existing correction only handles an empty label, so its
single-letter currency follows the same invalid upstream rendering.

Keep a token boundary after a one-letter cost currency before a comma or
closing brace, for both `CostSpec` and booked `Cost`, through the existing
shared `DirectivePrinter`. Preserve exact numbers, total/compound costs,
constraints, date and escaped labels. Keep ordinary multi-letter symbols
and posting prices unchanged. Do not reject all one-letter commodities or
remove their cost constraints. This is a small syntax adaptation in the
existing printer; do not duplicate native booking or parsing. CLI-only,
no new dependencies or API surfaces.

Caller search confirms the shared formatter reaches single add
(`adding.py:1368`), import writability/entry rendering
(`importing.py:1310,1327`), bulk validation (`adding.py:1915`),
`listing.answer` details (`listing.py:130` → `writer.py:535`), and
`query._render_beancount` (`query.py:1809–1813`). All five paths are
exercised. The direct upstream printer also supplies the bad punctuation;
the native parser accepts the original spaced spelling. No change to the
allowed commodity grammar (`ledger/text.py:156–163`) is needed.
A separate actual-printer proof checks raw `CostSpec` and booked `Cost`
with both the native and CLI printers, for simple and dated costs. All
eight rendered forms reproduce the invalid token; the loaded writer hash
matches the pinned source.

# Files renders each file's last-commit time in the server's UTC zone, so every visitor outside UTC gets React error #418 and a re-rendered page: "Aug 19, 2026, 05:59 AM" becomes "Aug 18, 2026, 11:59 PM" (gap in w4/m36)

**Severity:** minor. The times settle on the reader's zone, but until the scripts run they show UTC with no zone named, and on every load React throws away the server-rendered folder view and renders it again, which costs the first paint and anything a keyboard reader focused meanwhile. **Owner:** `dashboard`. **Estimate:** 30–45 minutes including tests. **A2:** Files is where a newcomer first looks at what their ledger is made of; it should not rebuild itself under them. **Found by:** `/qa-find-bugs-dashboard` (`dashboard-qa` routine) on 2026-11-26 against `https://beancount.io`, production entry chunk `main-BBmi61Hs.js`. QA-owned headless Chromium 158, fresh isolated contexts with Playwright `timezoneId`, 1440×1000, English. Reproduced signed out on the public ledger and signed in on a QA-owned ledger. Read-only: no ledger writes. Local HEAD `78eb9e1da`.

## Repro

Public ledger, no sign-in needed.

1. With the browser zone set to `America/Mexico_City`, open `/ledger/open_ledger/example/files/tree/main`.
2. With scripts disabled (the server's HTML), the file rows read `Aug 19, 2026, 05:59 AM`, `Aug 18, 2026, 07:57 PM`, `Oct 30, 2026, 09:49 PM`, `Jul 14, 2026, 01:18 AM`: UTC. With scripts on, the same rows read `Aug 18, 2026, 11:59 PM`, `Aug 18, 2026, 01:57 PM`, `Oct 30, 2026, 03:49 PM`, `Jul 13, 2026, 07:18 PM`.
3. The console shows `Minified React error #418` (hydration text mismatch), and a `data-` attribute set on `<main>` at `DOMContentLoaded` is gone afterwards: React replaced the server-rendered tree.
4. The same #418 appears in `Asia/Tokyo` (`02:59 PM`), `Europe/Berlin` (`07:59 AM`) and `Europe/London` (`06:59 AM`, British Summer Time on the commit date), at any hour, because only the hour has to differ.

Controls: with the browser in `UTC` the folder view keeps its server-rendered `<main>` and logs nothing. The text view of `main.bean` (`/files/blob/main/main.bean`) shows no #418 in `America/Mexico_City`.

## Cause

- `dashboard/src/features/ledger-editor/directory-browse/components/ledger-directory-view.tsx:344-348` prints `formatDateTime(item.lastCommitterDate)` for each row, and the route loader (`directory-browse/loader.ts`) fetches the folder during the server render.
- `formatDateTime` (`dashboard/src/common/lib/format/format-datetime.ts:8-31`) calls `toLocaleDateString` with an hour and minute and no `timeZone`, so it formats in whichever zone the code runs in: UTC on the server, the reader's zone in the browser.
- w4/m36 gave commit, profile-activity and repository-card timestamps `useHydratedTime()` (`common/hooks/use-date-locale.ts`): UTC until hydration, then the browser's zone in place. It explicitly left other consumers out of scope, and Files was one of them.

## Fix

- Render Files' last-commit times through the w4/m36 helper (`useHydratedTime().exactTime`, or an equivalent hook built on `useHydrated()`): the server and hydration renders show the same UTC text, and the browser's zone follows in place once hydrated. Keep the existing date-and-time style and the active app language.
- Apply the same to the other server-rendered `formatDateTime` caller, the binary-file metadata bar (`features/ledger-editor/file-editor/components/non-text-file-views.tsx:78-82`). Its client-only callers (API key card, managed price sources) may move to the same helper for consistency but do not hydrate today.
- Tests: a real server render of the folder view in UTC hydrated in another zone raises no hydration error, keeps its row nodes, and then shows the browser-zone time; a UTC control is unchanged. The first fails on the current code.

## Definition of done

- In `America/Mexico_City`, `Asia/Tokyo` and `Europe/Berlin`, `/ledger/open_ledger/example/files/tree/main` logs no #418, keeps the server-rendered `<main>`, and after hydration shows each row's time in the browser's zone (`Aug 18, 2026, 11:59 PM` in Mexico City for the first row above).
- A UTC browser is unchanged. Dashboard gates pass.

## Blast radius

`formatDateTime` callers: the folder view and the binary-file metadata bar (both server-rendered), and the API key card and managed price sources (client-fetched: `/settings/api-keys` and Commodities showed no #418 in `America/Mexico_City`). Overview's separate #418 has a different cause, the server's date, and is filed as w5/1217. A Mexico City sweep of the public ledger's other pages found no #418 apart from those two.

## Dedupe

Searched `.pm/**`, including `done/` and `blocked/`, for hydration, `#418`, `formatDateTime`, `lastCommitterDate`, Files and directory timestamps, and time zone. w4/m36 (done) fixed three other timestamp consumers and scoped the rest out; w4/done/227 localized commit timestamps; w5/done/1152 and 1160 concern Files navigation and Version History focus. `main` still formats these times with no hydration guard, so this is not deployment lag.

**Unverified:** a binary file's view (the public ledger has none at its root); the 390px layout, where the time column is hidden by CSS (`hidden md:flex`) but still rendered, so the same mismatch is expected there; right-to-left locales.

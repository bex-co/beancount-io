# A note or account made with New Entry is missing from the Journal it returns to ("Entry created successfully", still "17 entries"), and once Note is turned on its row never says which account the note is for

**Severity:** minor. Nothing is lost, but the reader is told the write worked and cannot see it, and the note they find later doesn't name its account. **Owner:** `dashboard` (`features/journal`). **Estimate:** 30–45 minutes including tests. **A2:** New Entry offers four tabs: Transaction, Balance, Note and Account. Since the compact Journal (`91daf9b46`), the Journal lists only Transaction and Balance by default. So two of the four tabs write an entry the reader is sent back to a Journal that hides. A newcomer who adds a note ("Called the bank about the duplicate charge") sees the success toast, an unchanged count and no new row, and is likely to add it again. When they find **Entry types → Note**, the row reads only the comment. Every other directive that belongs to an account (Balance, Open, Close, Pad, Document, a budget Custom) shows that account. **Found by:** `/qa-find-bugs-dashboard` (`dashboard-qa` routine) on 2026-11-27 against `https://beancount.io`, entry chunk `main-BBmi61Hs.js`, isolated headless Chromium 158 at 1440×1000, English. QA owner on its designated disposable synthetic ledger; both writes were restored byte-for-byte afterwards. Local HEAD `85d08ba30`.

## Repro

Any ledger you can write to, with the Journal's Entry types left at the default (**Transaction, Balance**):

1. Open `/ledger/<owner>/<ledger>/journal`. The header reads `<ledger> · 17 entries`.
2. **New Entry → Note**: date today, account `Assets:Cash`, content `qa-20261127-note "quoted" back\slash` plus a second line. **Create Note Entry**. The dialog closes, the toast says **Entry created successfully**, and the file gains `2026-11-27 note Assets:Cash "qa-20261127-note \"quoted\" back\\slash` and the second line, correctly escaped, with no ledger errors. The Journal still reads `17 entries`, and its first row is still the 2026-08-29 balance.
3. **New Entry → Account**: `Assets:Qa-20261127-Probe`, **Create Account Entry**. Same toast; the file gains `2026-11-27 open Assets:Qa-20261127-Probe`; the Journal still reads `17 entries` with no new row.
4. Reload: still `17 entries`. Open **Entry types** and turn on **Note**: `18 entries`, and the first row is `2026-11-27  Note  qa-20261127-note "quoted" back\slash second line`. The Account column of that row is empty. The Balance row under it shows `Assets:Cash` there.
5. The account's own page, `/ledger/<owner>/<ledger>/account/Assets:Cash`, defaults to the same two types, so the note is hidden there too.

## Cause

- `DEFAULT_DIRECTIVE_TYPES` (`dashboard/src/features/journal/hooks/use-journal-filter-state.ts:8–11`) is Transaction and Balance, a deliberate choice for reconciling. The Journal's New Entry `onSuccess` (`features/journal/pages/journal-page.tsx:470–480`) shows the toast and refetches, but never checks whether the saved type is listed. The dialog knows which tab saved (`activeTab`), so the page can.
- `NoteDescription` (`features/journal/components/journal-description/note-description.tsx:9–16`) renders only `directive.comment`, though `JournalNote` carries `account` (`common/types/journal.ts:98–101`). `OpenDescription`, `CloseDescription`, `PadDescription`, `DocumentDescription` and `CustomDescription` all render the account. The compact row's Account cell (`journal-lines.tsx:420–430`) is filled only for balances and transactions, so a note's account appears nowhere in the compact layout. The Comfortable layout uses the same description (`journal-days.tsx:450`).

## Fix

Dashboard only. No API change.

- After New Entry saves an entry whose type the Journal is not listing, add that type to the Journal's Entry types, the same persisted selection the picker writes, so the new entry is listed on return. Leave the reader's other choices and the defaults for other ledgers alone. A transaction or balance needs no change.
- A note row names its account, as the other account directives do: in the compact Account cell (as for a balance) and in the Comfortable description (`Assets:Cash · <comment>`), with `dir="auto"` on the comment.

## Definition of done

- On production, steps 2 and 3 end with the new note and the new Open listed first and the count raised by one each, with no Entry types change by hand. The Entry types button then reads **Transaction, Balance +1** (then +2), and turning those types off again keeps them off after a reload.
- Step 4's row shows `Assets:Cash` in the Account column at 1440px, and on its second line at 390px.
- Rendered tests: the Journal page saving a Note and an Open through New Entry lists the created type afterwards. A compact and a Comfortable note row show the account. The tests fail on the current code. Dashboard format, lint, test and build pass.

## Blast radius

The ledger Journal is the only page that opens New Entry. The account page shares `useJournalFilterState` and the row components, so the note-account change reaches it too (there it repeats the page's account, as Balance rows already do). Overview's Recent activity uses the days layout, which gets the account through the same description. Working controls: Transaction and Balance entries made with New Entry appear at once. The Accounts page lists a newly opened account.

## Dedupe

Searched every board state for `entryCreatedSuccess`, "Entry created successfully", `DEFAULT_DIRECTIVE_TYPES`, `Entry types` together with note/new entry, `NoteDescription` and "note" rows. w5/1190 (done) fixed the compact layout of Event/Custom/Pad/Document rows and called Note rows "unaffected": it covered spacing, not the missing account. w3/640 (done) is the toast after a write that breaks the ledger. w4/238 (done) is focus after account writes on the Accounts page. None covers a created entry hidden by the default types, or a note without its account. The default dates from `91daf9b46` and the note description from `af5339de0`, so this is not deployment lag.

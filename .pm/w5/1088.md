# Preserve inferred lot quantities in transaction details

**Minor · cli · 30–45m · A1 · worker1.** Redirecting `list transaction
--details` can change a valid ledger's lot identity. Two inferred purchases
that form one undated lot become two dated lots, so a later partial sale
fails strict booking. FIFO and a single-purchase case reload successfully
but acquire dates absent from the source. No product fix made.

existing managed Python 3.12.10 / Beancount 3.2.3 / Beanquery 0.2.0,

checked before/after; reviewed main `a9833883c` has the same local renderer.
Fresh offline subprocesses, isolated child config/cache, HOME unchanged,
closed stdin/no TTY, synthetic ledgers only. Source bytes stay unchanged.

## Standalone reproduction

Put checkout `bea` on PATH, save this as `recipe.py`, and run in two unused
directories. The second case uses renamed roots and an included journal:

```sh
python3 recipe.py /absolute/unused/qa-details-one
python3 recipe.py /absolute/unused/qa-details-two strict included
```

The script records argument arrays, streams, exits, duration and source hashes
in `results.json`. Its checks describe the current failure. Optional modes
`fifo` and `single` show silent date changes; `explicit`, `dated` and
`costless` are working controls.

The source buys two and three HOOL at 5 USD while leaving the quantities to
interpolation. Native booking merges these into one undated lot. After selling
one at 7 USD, the source holds **four HOOL at 5 USD, date None**, cash **82
USD**, and gain **2 USD**. Source check exits 0 and JSON listing correctly
marks both purchases `units.inferred: true`.

Details exits **0**, with its ordinary separate notice on stderr, but writes:

```beancount
2024-01-02 * "Buy 2"
  Assets:Stock 2 HOOL {5 USD}
  Assets:Cash -10 USD
2024-01-03 * "Buy 3"
  Assets:Stock 3 HOOL {5 USD}
  Assets:Cash -15 USD
```

Those stated quantities make native booking assign January 2 and January 3
as acquisition dates. Reloading the complete details stream, with the same
account opens, exits **1**; stdout is empty and JSON stderr reports:

```text
Ambiguous matches for "-1 HOOL {5 USD}":
2 HOOL {5 USD, 2024-01-02}, 3 HOOL {5 USD, 2024-01-03}
```

`query PRINT --format beancount --output PRINT.bean` and its fresh check both
exit 0 and preserve the original native inventory, providing a workaround.
The source-heading comments are already parseable; none are removed in these
exports. Under FIFO, details checks clean but leaves **one HOOL dated January
2 and three dated January 3**, replacing the source's four undated units.
With one inferred purchase, details silently dates the remaining four units
January 2. Cash and immediate gain stay the same in those two cases; the
changed acquisition dates are the observed defect, without a tax-rule claim.

## Cause and repair

`cli/src/bea_engine/ledger/reader.py:613–614` correctly marks the source-backed
omitted quantities. The details path in `ledger/listing.py:132–137` calls
`writer.format_transaction(item, loaded=True)`. Its posting reconstruction
(`ledger/writer.py:565–572`) restores `MISSING` only for
`p.units.inferred and not loaded`, so this caller deliberately bypasses the
marker. A direct producer trace confirms two true reader markers, invalid
numeric loaded rendering, and valid number-less write-form rendering.

Honor the known inference marker in details while retaining the loaded
renderer’s string-preservation behavior. Keep `loaded=True` and its bypass of
the write sanitizer; changing that flag wholesale would regress 834. Omit a
quantity only when the existing reader marks it inferred. Preserve explicit
quantities, explicit cost dates, costless positions, metadata, original
strings and commented source headings. Do not guess dates or globally change
Cost/CostSpec printing to repair this one consumer.

Caller search finds the only production `loaded=True` call in listing's
details branch. Single/bulk add and its validation/planning callers use the
write form, which already honors the marker. Filters, sort order, `--on-disk`
and limits converge on the same details branch. JSON and ordinary table
output keep their booked quantities; query PRINT has its own working
restoration path. This is local CLI work, with no new dependency or eligible
REST/GraphQL/MCP surface to change.

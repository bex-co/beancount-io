# In Persian, Accounts writes a zero balance as a Latin "0" among Persian-digit balances (regression of w2/119)

**Severity:** minor (localization). **Owner:** `dashboard`. **Estimate:** 15–20 minutes including a test. **A2:** w2/119 made Accounts write every balance in the reader's locale; an empty account is the one balance that still is not. **Found by:** `/qa-find-bugs-dashboard` (`dashboard-qa` routine) on 2026-11-26 against `https://beancount.io`, production entry chunk `main-BBmi61Hs.js`. QA-owned headless Chromium 158, isolated context, 1440×1000, signed out. Read-only. Local HEAD `ebed3ee95`.

## Repro

1. Open `/ledger/open_ledger/example/accounts?lang=fa`.
2. `Assets:US:BofA:Checking` reads `۲٬۷۵۴٫۰۶ USD` and its Postings cell `۲۷۵`. `Assets:US:Federal:PreTax401k` and `Liabilities:AccountsPayable`, whose balances are empty, read a Latin `0` in the Balance column, beside Persian-digit posting counts (`۷۴`, `۶`) on the same row.

Expected: `۰`, in the reader's digits like every other balance and count on the page.

## Cause

`dashboard/src/features/ledger-data/accounts/index.tsx:238-240` (`BalanceCell`) returns the literal `<span …>0</span>` for a computed balance with no units. `97c05f2bb` (chart-of-accounts redesign, 2026-11-18) replaced the earlier `-` with this literal, after w2/119 (2026-11-10) had moved the cell's amounts to `<LedgerAmount>`.

## Fix

Write the zero through the page's locale-aware formatter (for example `useFormatCount()(0)` or the ledger-number formatter `LedgerAmount` uses), so Persian reads `۰` and every other language still reads `0`. Test: `BalanceCell` for an empty balance renders `۰` under `fa` and `0` under `en`; the `fa` case fails on the current code.

## Definition of done

`/ledger/open_ledger/example/accounts?lang=fa` shows `۰` for the two empty accounts at 1440×1000 and 390×844; English is unchanged. Dashboard gates pass.

## Dedupe

Searched `.pm/**`, including `done/` and `blocked/`, for Persian with Accounts and zero, `BalanceCell`, and Latin digits. w2/119 (done) localized balances, w2/125 (done) localized counts, w21/1020 is the mobile app. No open item covers it and `main` still has the literal, so this is not deployment lag. Holdings and Query also print `0`, but they print raw query values by design (w2/119).

**Update 2026-11-27 (`dashboard-qa` routine, production `main-BBmi61Hs.js`, local HEAD `2cbf9a141`)** — Statistics has the same literal. On `/ledger/open_ledger/example/statistics?lang=fa`, the **Account Last Entries** table writes `Assets:US:Federal:PreTax401k`, `Liabilities:AccountsPayable`, `Assets:US:BofA` and `Assets:US:Vanguard` (empty balances, `{}` from `getLedgerAccountLastEntries`) as a Latin `0`. The rows around them read `‎−۲٬۷۰۳٫۲۹ USD` and `۸۵۵٫۸۳ USD`, and the Postings table above counts in Persian digits. Cause: `formatBalance` in `dashboard/src/features/ledger-data/statistics/account-last-entries.tsx:39` returns the string `"0"` for an empty balance, and `:36` returns an untranslated `"N/A"` for a null one. Fix both the same way as `BalanceCell`: the locale's zero, and a translated or `—` placeholder for null. Add to the definition of done: `/statistics?lang=fa` shows `۰` for those four rows, and English is unchanged.

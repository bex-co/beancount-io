# Browser Back or reload throws away a typed New Entry or Add Budget draft without the "Discard what you typed?" question that Close and Escape ask

**Severity:** minor (lost input). **Owner:** dashboard. **Estimate:** 45–60 minutes including rendered tests. **A2:** a reader halfway through a first transaction who presses Back (a mouse back button, a trackpad swipe or Cmd+[) or reloads loses everything typed, with no question. The same reader pressing Escape is asked first. Entry Context already asks in both cases. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-18 against `https://beancount.io` (entry chunk `main-LGv2TZLj.js`), headless Chromium 153 at 1440×1000, English/light, signed in as the QA owner on the synthetic ledger `mcp-agent-eval`. Drafts only, nothing was saved. Local HEAD `dc3a1d108`.

## Repro

1. **New Entry, Back.** On `/ledger/<owner>/<ledger>/journal?lang=en`, activate **New Entry**. The URL gains `action=new-entry&directive=transaction` as a new history entry. Type `qa-20261118-back-draft` into Narration with the keyboard and `12.34` into the first Amount. Press browser Back. The URL drops `action=new-entry`, the dialog closes, and no question appears. Forward reopens New Entry with Narration empty.
2. **New Entry, reload.** Same draft, then reload. No `beforeunload` prompt is raised, and the reloaded dialog is empty.
3. **Add Budget, Back.** Go from Journal to **Budget** through the sidebar, open **Add Budget**, and type `250` into Amount. Escape asks **Discard what you typed?** (the control). Choose **Keep editing**, which keeps `250`, then press browser Back. Journal opens and the draft is gone, with no question.

Control: with an Entry Context edit typed into the editor, a reload raises the browser's `beforeunload` prompt in the same session. Per w4/1063, Back asks **Keep editing / Discard**.

## Cause

- `dashboard/src/common/components/discard-draft-guard.tsx:21-82` (`useDiscardDraftGuard`) only gates the leave actions a dialog passes to `requestLeave`: Close, Escape, an outside click and Cancel. It installs no router blocker and no `beforeunload`.
- New Entry's open state is the URL search: `features/journal/pages/journal-page.tsx:298-306` pushes `action=new-entry` through a `<Link>`, and `:370-372` opens the dialog only while that parameter is present. Back therefore removes the parameter and unmounts the form without passing through `requestLeave` (`new-directive-dialog/index.tsx:139-141`).
- Add Budget (`features/ledger-data/budget/add-budget-dialog.tsx:227-238`) is local state, so Back leaves the Budget route and unmounts it.
- The working control is `features/journal/components/entry-context-dialog.tsx:300-345` (`EntryHistoryGuard`, w4/1063): `useBlocker` with `withResolver` for a dirty draft, `enableBeforeUnload`, and a silent block while a write is in flight.

The same guard serves Open Account (`ledger-data/accounts/open-account-dialog.tsx:133`), Create Ledger (`ledger-list/hooks/use-ledger-form-dialog.ts:17`) and the SSH and API key dialogs (`user-settings/pages/ssh-keys/key-create-dialog.tsx:123`, `api-keys/api-key-create-dialog.tsx:205`). They have the same gap by source; only New Entry and Add Budget were exercised.

## Fix

While its dialog holds a dirty draft and no write is pending, have `useDiscardDraftGuard` (or a companion its callers mount) block router navigation with `useBlocker({ withResolver: true })` and ask the existing **Discard what you typed?** question. **Discard** completes exactly the blocked navigation; **Keep editing** cancels it and keeps the draft and focus. Also enable `beforeunload` for the same condition. For New Entry, a Back that only removes `action=new-entry` is the navigation to block. Keep Entry Context's in-flight rule: block silently while a write is pending. An untouched form, and a successful write's own close (which removes `action=new-entry` with `replace`), must not ask.

## Definition of done

- With a typed New Entry or Add Budget draft, browser Back asks **Discard what you typed?**. **Keep editing** leaves the URL, the dialog and every typed value as they were. **Discard** completes the Back.
- Reloading with that draft raises `beforeunload`. A clean form and a just-saved entry leave without asking.
- Rendered tests cover Back with a dirty draft (both answers), a clean form, and a successful write, and fail on the current code. Dashboard gates pass.

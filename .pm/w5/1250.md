# Statistics says every ledger uses "Types: 12": a ledger with only Open, Balance and Transaction entries reads "Entries: 29 · Types: 12", because the count includes the nine types it has none of

**Severity:** minor. **Owner:** `dashboard` (`features/ledger-data/statistics`). **Estimate:** 15–20 minutes including a test. **A2:** the summary line above **Entries Count by Type** is how a newcomer takes in what a ledger is made of. "Types: 12" is the same on every ledger and for every time filter, so it says nothing and wrongly suggests the ledger uses every kind of directive. The table under it lists nine `0` / `0.0%` rows on the same small ledger. **Found by:** `/qa-find-bugs-dashboard` (`dashboard-qa` routine) on 2026-11-27 against `https://beancount.io`, entry chunk `main-BBmi61Hs.js`, isolated headless Chromium 158 at 1440×1000, English, signed in as the QA account. Read-only. Local HEAD `394abaf85`.

## Repro

1. Open `/ledger/<owner>/<ledger>/statistics` on a small synthetic ledger with 12 `open`, 16 transactions and 1 `balance`. The section reads **Entries: 29 · Types: 12**. The table lists Balance 1, Open 12 and Transaction 16, and nine rows of `0` / `0.0%`: Close, Commodity, Custom, Document, Event, Note, Pad, Price and Query. The GraphQL `getLedgerEntriesCountPerType` response has the same twelve rows, nine with `number: 0`.
2. Public control, no sign-in needed: `/ledger/open_ledger/example/statistics` reads **Entries: 2,053 · Types: 12**, though Close, Document, Note, Pad and Query are all `0`. That ledger uses 7 types.

Repeated from a fresh load.

## Cause

- The ledger service returns all twelve directive types, zero-filled and in a fixed order. This is a deliberate contract: `backend-cluster/ledger/src/features/ledger/service/ledger-data-mappers.ts:87-111`.
- `EntriesCountTable` (`dashboard/src/features/ledger-data/statistics/entries-count-by-type.tsx:76-94`) passes `types: formatNum(entries.length)` to `page.statistics.entriesByTypeSummary`. `entries` is every row the API returned, so `types` is always 12. The locale description says `{types}` is "the number of entry types", and the reader takes that to mean the types this ledger has.

## Fix

Dashboard only. No API change. Count only the types with `number > 0` in the summary, so the line above reads `Types: 3` and the public example reads `Types: 7`. In the table, list only the types present, or keep the zero rows after the non-zero ones. Fava lists only the types a ledger has. A period with no entries at all keeps today's empty state, with no `NaN` (w3/138).

## Definition of done

- On production, the repro ledger reads **Entries: 29 · Types: 3**, and `open_ledger/example` reads **Entries: 2,053 · Types: 7**. With a time filter, the count follows the filtered rows.
- A rendered test feeds the twelve zero-filled rows with three non-zero ones and asserts `Types: 3`. It fails on the current code. Dashboard gates pass. The Persian digits from w2/125 are unchanged.

# During a brief API outage, Smart Import, Upload Receipt, Create File and Bank Sync tell a signed-in owner to sign in or that only an owner may connect banks

**Severity:** minor (failure honesty). **Owner:** dashboard. **Estimate:** 30–45 minutes including tests. **A2:** w3/646 stopped an outage from signing people out in the header and on protected routes. On a ledger page the write-gated screens still read the outage as "signed out". The owner of the ledger is told to sign in, or told they are not its owner, and is offered no retry. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-18 against `https://beancount.io` (entry chunk `main-LGv2TZLj.js`), headless Chromium 153 at 1440×1000, English/light. QA owner account on its synthetic `<qa-owner>/mcp-agent-eval` ledger. Local HEAD `a858bdff9`.

## Repro

The browser answered only `GetCurrentUser` with `502 Bad gateway`, a synthetic response repeating the live state w3/646 recorded. Every other request went to production.

1. Signed in as the ledger's owner, open `/ledger/<owner>/<ledger>/journal`.
2. With `GetCurrentUser` failing, navigate in the app (sidebar or router) to **Import → Smart Import**. The header correctly shows neither the user menu nor **Log In** (w3/646). The page body says **Import unavailable — Sign in to import transactions into this ledger.** with a **Sign in** link to `/auth/login?next=…/import`. There is no Try Again.
3. Same on **Upload Receipt** ("Receipt upload unavailable — Sign in to upload receipts to this ledger."), on `files/new/main` ("Please sign in to continue.") and on **Bank Sync** and `plaid-connections` ("Only the ledger's owner or an administrator can connect and manage banks.").
4. Let the API recover and wait. The page keeps the wrong message until the next navigation or a reload. A reload shows the importer.

Control in the same run: navigating to `/settings/general` under the same stub shows "Something went wrong — The service is temporarily unavailable" with **Try Again**, which is w3/646's fix working.

## Cause

The root `beforeLoad` already records the three states (`common/server-fn/user.ts` `fetchUserProfile`, `authStatus: "unavailable"`), and `Authenticated` and `requireAuth` read them. These consumers still read only `userProfile != null` through `useIsAuthenticated` (`common/hooks/use-is-authenticated.ts:3-6`), so "unavailable" is treated as "signed out":

- `common/components/ledger-write-access-notice.tsx:35-55`, which renders the signed-out "Sign in" branch (Smart Import `features/importer/pages/import-page.tsx:47`, Upload Receipt `features/receipt/pages/receipt-page.tsx`).
- `features/ledger-editor/shared/components/write-access-required.tsx:29-37` (Create File, Upload Files).
- `common/hooks/use-ledger-permission.ts:4-12`, which returns `isAdmin: false` and `canWrite: false`, so `features/plaid/components/plaid-states.tsx:19-42` shows the admin-only message, and the journal and sidebar hide their write controls.

## Fix

When `useAuthStatus()` is `"unavailable"`, these notices say that Beancount.io could not confirm the sign-in right now, using the service-unavailable copy already used by the root error page, with a **Try Again** that re-runs the current route in place (`router.invalidate()`). They must not show a sign-in link, the read-only wording or the admin-only wording. `useLedgerPermission` should expose the unknown state so callers can tell "not allowed" apart from "not known yet". Signed-out visitors and read-only signed-in viewers keep exactly today's messages.

## Definition of done

- With `GetCurrentUser` failing on client navigation, Smart Import, Upload Receipt, Create File, Upload Files and Bank Sync show a service-unavailable state with Try Again. None of them shows **Sign in**, "read-only" or "owner or an administrator".
- Try Again after recovery shows the working page without a reload or re-entering credentials.
- A signed-out visitor on a public ledger still sees "Sign in to import…" with the same safe `next`. A signed-in reader without push still sees the read-only copy.
- Rendered tests cover the three auth states for `LedgerWriteAccessNotice`, `WriteAccessRequired` and the Plaid access state, and fail on the current code. Dashboard gates pass.

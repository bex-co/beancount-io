# Choosing another ledger in the switcher from an account, commit, entry or folder page lands on "404 Page not found" or "No account named … in this ledger"

**Severity:** minor (nothing is lost, but the reader picks a ledger they own and is told it has no such page; on a commit or entry page the ledger layout and its switcher disappear too). **Owner:** dashboard. **Estimate:** 30–45 minutes including tests. **A2:** the ledger switcher is how a reader with several ledgers moves between them, and it keeps the page they are on (Journal stays Journal, Balance Sheet stays Balance Sheet). On a page about one thing in the current ledger (an account, a commit, an entry, a file or folder), it also keeps that thing's name or id, which the other ledger rarely has. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-21 against `https://beancount.io` (dashboard entry chunk `main-CIyNN76T.js`), QA-owned headless Chromium at 1440×1000, English/light, no filters, signed in as the QA owner. Read-only. Local HEAD `4b7f2e057`.

## Repro

The QA account owns several synthetic ledgers. Ledger A has `Assets:Bank:Checking` and the commit and entry below; ledger B does not.

1. Open `/ledger/<owner>/<A>/account/Assets:Bank:Checking`. Open the sidebar's "<A> — switch ledger" combobox and choose B. The URL becomes `/ledger/<owner>/<B>/account/Assets:Bank:Checking`, the tab title is "Page Not Found — /ledger/…", and the page says "No account named Assets:Bank:Checking in this ledger." with an "Accounts" button.
2. Open one of A's commits from its commit list (`/ledger/<owner>/<A>/commits` → `/commit/<sha>`), then choose B in the switcher. The URL becomes `/ledger/<owner>/<B>/commit/<sha>` and the whole window is the root "404 / Page not found / The page you're looking for doesn't exist or has been moved to a different location." with "Go Home" and "Go Back". There is no sidebar and no switcher. Loading that URL directly answers HTTP 404. Repeated with a second commit and a third ledger.
3. Open an entry permalink (`/ledger/<owner>/<A>/entry/<hash>`, from an entry's context panel), then choose B: the same full-window 404.
4. Open a folder on a public ledger, `/ledger/open_ledger/alphabet/files/tree/main/2026`, then choose one of your own ledgers. The URL becomes `/ledger/<owner>/<B>/files/tree/main/2026`, and Files shows "Failed to load directory contents" with a Try Again that cannot succeed (the w5/1152 state).
5. Controls on the same build: from Journal (`?offset=20`), Accounts, Overview and the reports, the same switch lands on B's page as expected. `files/blob/main/main.bean` lands on B's `main.bean` only because every one of these ledgers happens to have one.

Repeated from fresh loads.

## Cause

`dashboard/src/common/components/ledger-layout/ledger-switcher.tsx:151-177` (`handleSelectLedger`) takes everything after `/ledger/<owner>/<name>` (`:155-156`) and appends it to the chosen ledger (`:162`). Its search reducer (`:170-175`) already drops `account`, `filter` and `time` so that "the previous ledger's selection" does not leak, but the path still carries the selection when the page is about one thing: `account/$accountName`, `commit/$commitSha`, `pull/$prNumber`, `entry/$entryHash`, `files/{blob,tree,new,upload}/$branch/$`, and `files/content` with its `path` search param. The commit, pull-request and entry loaders throw `notFound()` for an id the ledger does not have (`features/git/commits/loaders/commit-loader.ts:24`, `features/git/pull-requests/loaders/pull-request-loader.ts:22,35`, `features/journal/loaders/entry-loader.ts:24`). Those routes have no `notFoundComponent`, so the root 404 replaces the ledger layout. The account route renders its own in-layout `AccountNotFound`. The path logic dates from `af5339de0` and is unchanged at HEAD, so this is not deployment lag.

## Fix

Owned by `dashboard`, in `handleSelectLedger` only. A page about the ledger itself keeps its path, as today. A page about one thing in the current ledger switches to the chosen ledger's page that lists that kind of thing, without the name or id:

- `account/<name>` → `accounts`
- `entry/<hash>` → `journal`
- `commit/<sha>` and `pull/<n>` → `commits`
- `files/blob|tree|new|upload/<branch>/<path>`, `files/content` and `files/create` → `files/tree/main` (the sidebar's Files destination, `ledger-sidebar.tsx:510`)

Keep dropping `account`, `filter` and `time`, and drop the files `path`, `type`, `editMode` and `lineNumber` params with the path. A direct link to a missing commit or entry stays a 404. This change is only about where the switcher sends you.

## Definition of done

- From A's account, commit, entry and folder pages, choosing B in the switcher lands on B's Accounts, commit list, Journal and Files root, inside the ledger layout. No "404" and no "No account named …".
- Journal, Accounts, Overview, the reports and Settings still switch to the same page on B. A direct link to an unknown commit or entry still answers 404.
- A switcher test with the real router (extending `common/components/ledger-layout/__tests__/ledger-switcher-journey.test.tsx`) covers each mapped route and one kept route, and fails on the current code. Dashboard gates (`yarn format:check`, `yarn lint`, `yarn test`, `yarn build`) pass.

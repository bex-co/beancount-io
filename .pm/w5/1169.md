# File editor: dismissing "Replace your edit with the latest version?" drops keyboard focus to the page body instead of returning it to "Load latest"

**Severity:** minor (focus loss). **Owner:** dashboard. **Estimate:** 20–30 minutes including a rendered test. **A2:** a keyboard user who backs out of the save-conflict confirmation lands on the page body. The next Tab starts again from "Skip to main content", far from the conflict notice they were reading. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-18 against `https://beancount.io` (entry chunk `main-LGv2TZLj.js`), headless Chromium 153 at 1440×1000, English/light, signed in as the QA owner on the synthetic ledger `mcp-agent-eval`. The conflict came from one prefixed external commit, which was then reverted. `main.bean` was restored byte for byte (blob `f1a0b83c`). Local HEAD `a95dfa7d3`.

## Repro

1. Open `main.bean` → **Edit**, then type a line. Commit any other change to `main.bean` elsewhere (MCP `updateLedgerFiles`, another tab). Choose **Save**. The notice "This file changed since you opened it…" appears with **Copy my edit** and **Load latest** ✓ (w2/110).
2. Choose **Load latest**. The dialog "Replace your edit with the latest version?" opens with focus on **Cancel** ✓.
3. Dismiss it with **Cancel**, **Escape** or **Close**. Each time `document.activeElement` is `<body>`. **Replace my edit** works and focuses the editor ✓.

## Cause

`dashboard/src/features/ledger-editor/file-editor/components/ledger-file-view/text-file-view.tsx:322-334`: the dialog is controlled (`open={confirmLoadLatest}`) and has no `DialogTrigger`. Its `onCloseAutoFocus` returns early while `conflict` is still true, meaning to leave focus return to Radix. But `@radix-ui/react-dialog` 1.1.15 (`dist/index.mjs:146-149`) always calls `preventDefault()` on close and focuses `context.triggerRef.current`, which is `null` without a `DialogTrigger`. So focus goes nowhere. The comment "the editor is where the reader continues" covers only the replaced path.

## Fix

Keep a ref to the **Load latest** button. In `onCloseAutoFocus`, while `conflict` is still true, `preventDefault()` and focus that ref, using `restoreFocusOnDialogClose` as the other controlled dialogs do. Leave the replaced path focusing the editor.

## Definition of done

- Cancel, Escape and Close on the confirmation return focus to **Load latest**. **Replace my edit** still focuses the editor.
- A rendered test asserts both, and fails on the current code. Dashboard gates pass.

## Dedupe

Searched `.pm/**` for Load latest, Replace my edit, `onCloseAutoFocus` and `triggerRef`. w5/1151 covers the same Radix mechanism for Create Ledger, where `onCloseAutoFocus` is absent. Here a handler exists but returns early. Its scan of controlled dialogs without a trigger or an `onCloseAutoFocus` therefore missed this one. w2/done/110 shipped the conflict flow (`a5247ec21`, live); this file has not changed since.

# Income Statement "Period data" prints -2,970.10 USD as "-2,970.1 USD" and -15,600.00 IRAUSD as "-15,600 IRAUSD", while the chart's own tooltip says -2,970.10 (gap in w4/1001)

**Severity:** minor (a financial text alternative drops source digits and disagrees with the tooltip next to it; no data is changed). **Owner:** dashboard. **Estimate:** 30–45 minutes including tests. **A2:** someone who reads the Income Statement's chart as a table (keyboard or screen-reader users, or anyone copying the figures) gets amounts that are not written the way the ledger, the tooltip and the statement table write them. Large quantities lose digits too, which is the failure w4/1001 fixed for Balance Sheet charts.

## Repro

Production `https://beancount.io`, dashboard entry chunk `main-CIyNN76T.js`, headless Chromium 1440×1000, English/light, signed in (the public page reads the same way signed out).

1. Open `/ledger/open_ledger/example/income-statement?time=2016` (Net Profit, Monthly, At Cost) and open **Period data** under the chart.
2. The 2016-05-31 row reads **`-2,970.1 USD`**, the 2016-01-31 row reads **`-15,600 IRAUSD`**, and the empty August–December IRAUSD cells read `0 IRAUSD`.
3. Hover the May bar. The chart tooltip reads **`USD: -2,970.10`**.
4. The page's own `GetLedgerIncomeStatement` response holds `netProfitData` 2016-05-31 `{"USD": "-2970.10", "IRAUSD": "2400.00"}` and 2016-01-31 `{"IRAUSD": "-15600.00", "USD": "-3050.71"}`.
5. Choose **View → Income** with **stacked** bars (`?time=2016&view=income&mode=stacked`). The Period data rows read `Income:US:Hoogle:Match401k: -1,200 USD` and `Income:US:Federal:PreTax401k: -18,000 IRAUSD`, as plain numbers.
6. With the Fava option `invert-income-liabilities-equity` set (tried on the QA account's disposable ledger and restored byte-for-byte afterwards), Net Profit's Period data reads `2,019.6 USD` and `1,904.4 USD` for 2026-07 and 2026-08 (2,019.60 and 1,904.40 in the ledger).

Controls on the same build: the Balance Sheet's line-chart Period data keeps each source decimal (`/balance-sheet?time=2016` reads `15,600.00 IRAUSD`, `45,639.49403 USD`). The Cash Flow chart tables keep source strings as well. Each result was repeated from a fresh load.

## Cause

`dashboard/src/features/reports/income-statement/date-balance-chart/single-date-balance-chart.tsx:62-76` turns each balance into a double with `parseFloat` (negated when inverted). Lines 136-140 then pass those doubles as `periodSeries` values. `stack-date-balance-chart.tsx:84-105` does the same per account. `ChartPeriodTable` hands each value to `LedgerAmount`, which writes a number with `String(number)`. So `-2970.10` becomes `-2970.1`, and `-15600.00` becomes `-15600`. The tooltip keeps the digits because it formats with `fractionDigitsOf(raw)` (lines 93-101). w4/1001 fixed exactly this in `balance-sheet/line-chart.tsx:93-119`: it plots doubles but gives the table and tooltip the exact decimal (`parseDecimalNumber`, then `negateDecimalNumber` when inverted, and `"0"` for a gap). The two Income Statement bar charts were not converted.

## Fix

In both Income Statement bar charts, keep the doubles for ECharts and give `periodSeries` the source decimal strings: negated exactly when inverted, with the plotted `"0"` for a missing balance, as `LineChart` does. Unit order, legend selection (w4/1025, w4/997), the stacked account labels and the tooltips stay as they are.

## Definition of done

- On `/ledger/open_ledger/example/income-statement?time=2016`, Period data reads `-2,970.10 USD`, `-15,600.00 IRAUSD` and `2,400.00 IRAUSD`, matching the API and the tooltip. The stacked Income view reads `-1,200.00 USD` where its source has `-1200.00`. An inverted ledger reads `2,019.60 USD`.
- Rendered tests for both charts feed a series with trailing-zero decimals, an inverted series, and an unsafe integer such as `9007199254740993.125`. Each must keep the exact text in the table and fail on the current code. Dashboard gates (`yarn format:check`, `yarn lint`, `yarn test`, `yarn build`) pass.

## Dedupe

Searched `.pm/**` (open, `done/`, `blocked/`) for `Period data`, `date-balance-chart`, `single-date-balance-chart`, `parseFloat`, and the figures above. w4/done/1001 is this defect in the Balance Sheet `LineChart`; its resolution names only `LineChart`. w4/done/1025, 997, 218 and 126 are about Income Statement chart units, legends and tooltips, not table text. w3/done/494 added these tables. w3/done/627 removed float noise from the Overview tables. Open w5/1154 is the statement Markdown and print exports, and w5/1175 is chart axes. No dashboard commit since `ebbf43fed` changes these files, so this is not deployment lag.

Other locales. They go through the same `LedgerAmount` path, which formats separators per locale.

**Major · cli · 45–60m · A1 · worker1.** Real local CLI QA, 2026-10-23,
`bea 0.3.1` at `805da9490977a849d31ba8f3a8bbb935a5231e29`,

Immutable tracked CLI hashes are verified before/after every batch. No

Scope extension below also reproduces canonical generated import IDs made
by the real CLI. Both native and generated identities need written metadata
origin; preserve canonical IDs that actually occur in the file. Same owner,
no new finding or severity change.

An authored 10 USD payment has reference **B1**. A controlled local plugin
copies or replaces that row and changes only its bank-reference metadata
to **B2**, retaining date, header, flag, postings and source location.
Importing a real different payment B2 falsely previews duplicate and exits
0 with written 0. The file still contains only B1, Cash **990 USD** instead
of **980**, and no B2 payment. Repeating it silently skips again. Default,
explicit duplicate skip and human apply reproduce twice. A new native
reference is treated as proof even though no ledger file declares it.

Expected follows `cli/docs/IMPORTING.md:530–590,678–689`: a native ID is
strong evidence for the transaction the file writes under that ID; calculated
plugin transactions are excluded from existing import matches. B1 and B2
are distinct stable references in the same account. Both no-plugin and
changed-header controls preview B2 as new, write it once, skip its repeat,
and leave authored Cash 980 with B1 and B2 each once. No new conflict or
changed-ID policy is requested.

## Standalone reproduction

Put the checkout's `bea` on PATH, set a fresh absolute directory, and run
this Python recipe. The inspected plugin edits only in-memory metadata.
Its copy and replace modes leave source bytes unchanged; header-copy also
changes narration as a working classifier control. `plain` removes the
plugin. `skip=True` and `human=True` select duplicate-skip and human apply.
For the Python-importer controls set `python_import=True` and choose `key`
from `fitid`, `receipt_id` (explicit `--id-key`) or native `import-id`.
Every command closes stdin, isolates config/cache, removes inherited
ledger/token/engine overrides, keeps HOME, captures both streams and file
hashes, and has a 25-second timeout. Only successful apply/repeat may write
main; previews, references and importer/plugin inputs preserve bytes.

```python

case.mkdir(parents=True)

module.write_text("from beancount.core.data import Transaction\n__plugins__=('change_reference',)\ndef change_reference(entries,options,config):\n mode,key=config.split('|');value='bank:B2' if key=='import-id' else 'B2';out=[]\n for e in entries:\n  if not isinstance(e,Transaction) or e.narration!='ID source':out.append(e);continue\n  meta=e.meta.copy();meta[key]=value;derived=e._replace(meta=meta,narration='Derived row' if mode=='header-copy' else e.narration)\n  if mode=='replace':out.append(derived)\n  else:out.extend([e,derived])\n return out,[]\n")
config.write_text("from pathlib import Path\nimport hashlib\nfrom beancount.parser import parser\nfrom bea_engine.ledger import reader\nclass Reader:\n name='bank-reference'\n def identify(self,file):return str(file).endswith('.statement')\n def account(self,file):return 'Assets:Cash'\n def extract(self,file,existing=None):\n  print('QA_READER_MODULE_SHA256='+hashlib.sha256(Path(reader.__file__).read_bytes()).hexdigest())\n  rows,errors,_=parser.parse_file(str(file));assert not errors,errors\n  return rows\nCONFIG=[Reader()]\n")
old='bank:B1' if key=='import-id' else 'B1';new='bank:B2' if key=='import-id' else 'B2'
base='2024-01-01 open Assets:Cash USD\n2024-01-01 open Equity:Opening USD\n2024-01-01 open Expenses:Food USD\n2024-01-01 * "Capital"\n  Assets:Cash 1000.00 USD\n  Equity:Opening -1000.00 USD\n2024-02-01 * "ID source"\n  '+key+': "'+old+'"\n  Assets:Cash -10.00 USD\n  Expenses:Food 10.00 USD\n'
settings='' if mode=='plain' else 'option "insert_pythonpath" "TRUE"\nplugin "qa_reference" "'+mode+'|'+key+'"\n'

statement.write_text('2024-02-01 * "Bank B2"\n  '+key+': "'+new+'"\n  Assets:Cash -10.00 USD\n  Expenses:Food 10.00 USD\n')
fixed={p:p.read_bytes() for p in (module,config,bank,statement,before_raw,initial)}
env=os.environ.copy()
for name in ('BEA_FILE','BEA_TOKEN','BEANCOUNT_LOAD_CACHE_FILENAME','BEA_ENGINE_PYTHON','BEA_ENGINE_DIR'):env.pop(name,None)

def run(tag,args,target=book,write=False,human_output=False):
 before=hashes();saved=book.read_bytes();argv=['bea',*([] if human_output else ['--json']),'--no-input','-f',str(target),*map(str,args)];started=time.monotonic()

query=['query','SELECT account,sum(number) GROUP BY account ORDER BY account']

run('full',['list','transaction','--limit','100'])
run('on-disk',['list','transaction','--on-disk','--limit','100'])
run('limited',['list','transaction','--on-disk','--limit','2','--sort','oldest'])
run('human-details',['list','transaction','--on-disk','--details'],human_output=True)
args=['import',statement,'--config',config,*(['--id-key',key] if key=='receipt_id' else [])] if python_import else ['import',bank,'--csv','date=Date,narration=Description,amount=Amount,id=Reference','--account','Assets:Cash','--default-account','Expenses:Food']

run('raw-after',query,target=after_raw);run('facts',query);run('final',['check'])
```

## Root, scope and dedupe

`cli/src/bea_engine/ledger/reader.py:192`, `_declares`, compares a transaction's
header and, strictly, flag/tags/links/posting facts, but never verifies its
identity metadata against the declaration. `importing.py:477–511` therefore
admits the calculated B2 into the on-disk native-ID indexes. `answer` passes
`written_source` into its `_under_id` call at line 607. `_under_id:2209–2222`
looks up the source under B2, but its authored-amount priority guard is
conditional on a nonempty written list. With no authored B2, it still accepts
the agreeing calculated row. Fully known plain USD postings, unchanged
financial amounts and equal two-posting counts isolate identity metadata;
no booking inference, split lot, precision or transfer-account policy enters.
CSV and inspected Python importers share the reproduced decision.

**existing authored row under the requested ID** over a different loaded
amount. Its full eight public profiles pass here: 80 CLI calls / eight native
loads, source 10 repeats skip and corrections to 20/30 conflict in both
scaled modes and working controls. Here no authored row has requested B2,
and all amounts agree; the `if written` branch is bypassed. Keep 996 closed.
Completed [881](./done/881.md) recovers a filtered/transformed written ID;

Fix/acceptance: require an eligible authored origin for each native payment
identity used as an exact match. A plugin's B2 metadata cannot prove a source
B2 when the file declares B1. Both metadata-only modes must preview the real

repeat, and retain B1 once: authored Cash 980. Preserve recovery of original
B1, header normalization, custom/native identity namespaces, same-export
identity deduplication, generated-ID compatibility, reused IDs, account
scoping, partial-lot/inferred-amount fallbacks and the full 996 controls.
Keep unrelated plugin-added display metadata usable; avoid a blanket rule
that rejects every enriched transaction. Add meaningful actual import

# Anchor native payment references to their written metadata

**Major · cli · 45–60m · A1 · worker1.** Real local CLI QA, 2026-10-23,
`bea 0.3.1` at `805da9490977a849d31ba8f3a8bbb935a5231e29`,
macOS 26.5.1 arm64, frontend Python 3.13.3, existing managed Python 3.12.10 /
Beancount 3.2.3. Current main's CLI is byte-for-byte identical before filing.
Immutable tracked CLI hashes are verified before/after every batch. No
product fix, dependencies, services or credentials changed.

An authored 10 USD payment has reference **B1**. A controlled local plugin
copies or replaces that row and changes only its bank-reference metadata
to **B2**, retaining date, header, flag, postings and source location.
Importing a real different payment B2 falsely previews duplicate and exits
0 with written 0. The file still contains only B1, Cash **990 USD** instead
of **980**, and no B2 payment. Repeating it silently skips again. Default,
explicit duplicate skip and human apply reproduce twice. A new native
reference is treated as proof even though no ledger file declares it.

Expected follows `cli/docs/IMPORTING.md:530–590,678–689`: a native ID is
strong evidence for the transaction the file writes under that ID; calculated
plugin transactions are excluded from existing import matches. B1 and B2
are distinct stable references in the same account. Both no-plugin and
changed-header controls preview B2 as new, write it once, skip its repeat,
and leave authored Cash 980 with B1 and B2 each once. No new conflict or
changed-ID policy is requested.

## Standalone reproduction

Put the checkout's `bea` on PATH, set a fresh absolute directory, and run
this Python recipe. The inspected plugin edits only in-memory metadata.
Its copy and replace modes leave source bytes unchanged; header-copy also
changes narration as a working classifier control. `plain` removes the
plugin. `skip=True` and `human=True` select duplicate-skip and human apply.
For the Python-importer controls set `python_import=True` and choose `key`
from `fitid`, `receipt_id` (explicit `--id-key`) or native `import-id`.
Every command closes stdin, isolates config/cache, removes inherited
ledger/token/engine overrides, keeps HOME, captures both streams and file
hashes, and has a 25-second timeout. Only successful apply/repeat may write
main; previews, references and importer/plugin inputs preserve bytes.


## Root, scope and dedupe

`cli/src/bea_engine/ledger/reader.py:192`, `_declares`, compares a transaction's
header and, strictly, flag/tags/links/posting facts, but never verifies its
identity metadata against the declaration. `importing.py:477–511` therefore
admits the calculated B2 into the on-disk native-ID indexes. `answer` passes
`written_source` into its `_under_id` call at line 607. `_under_id:2209–2222`
looks up the source under B2, but its authored-amount priority guard is
conditional on a nonempty written list. With no authored B2, it still accepts
the agreeing calculated row. Fully known plain USD postings, unchanged
financial amounts and equal two-posting counts isolate identity metadata;
no booking inference, split lot, precision or transfer-account policy enters.
CSV and inspected Python importers share the reproduced decision.

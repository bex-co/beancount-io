## A removed or retired package resource remains active after successful refresh

The controlled local plugin sums JSON fee rules through
`importlib.resources.files(__package__).joinpath('rules').iterdir()` and
books one balancing fee transaction. Initially `old.json` contributes 2 USD
and `current.json` contributes 3 USD. The first source and snapshot both
hold Cash 995 USD, Fees 5 USD, and Equity −1000 USD.

Remove `old.json`, or retire it as `retired.txt` that the plugin intentionally
does not read. Current source is valid and books only 3 USD. `price export
--force` copies the current package files but leaves snapshot `old.json`
untouched. Its 2 USD is still enumerated, so the refreshed snapshot books
5 USD. The stale file is absent from the response's `files` and `overwritten`
lists, although the snapshot's actual accounting still depends on it. There
is no source-load error, missing include or missing plugin for the older
source-validation guard to reject.

## Cause, caller scope, and required behavior

`_export_plugin_modules`, `cli/src/bea_engine/managed_load.py:2246–2258`,
enumerates the current package through `_package_files` at `:2268–2311`.
Those current files join the attachment plan at `:1885`. The exporter checks
collisions and unresolved source dependencies but does not compare existing
destination package membership with the current source package.

The staging loop at `managed_load.py:2044–2046` stages only current attachment
paths. Commit at `:2053–2056` replaces only those paths. An obsolete resource
outside that plan survives and is still visible to normal package enumeration.
The return at `:2082–2088` therefore describes the planned writes, not every
file contributing to the exported plugin's actual view. Each JSON manifest
and all twelve native case comparisons prove that distinction; four human force
profiles cover the same helper result through the text renderer.

The frontend `_export` at `cli/src/cli/commands/price.py:182` builds the
`price-export` helper request at `:235`; `bea_engine/main.py:856` calls
`managed_load.export_portable`. Default and chosen output directories share
that implementation. CLI and independent native loads both observe the stale
snapshot. Other consumers of exported ledgers were not separately exercised.

Check copied package membership before staging a refresh. A successful
snapshot must expose the current source package's resource set and retain its
native accounting. When stale destination members could remain active, refuse
before any write, name the obsolete path and explain choosing a fresh output
directory, unless the implementation can produce an exact faithful copy.
Keep `--force`'s planned-file overwrite scope and preserve unrelated destination
contents; silently deleting arbitrary extra files is not required. Preserve
the plugin, its resource enumeration and source bytes. Keep ordinary resource
updates and fresh exports working. No new dependency, API change, plugin
behavior change or global cache policy is needed.

# Do not satisfy missing source dependencies with old snapshot files

**Major · cli · 45–60m · A1.** Refreshing a portable snapshot after the last
included source file disappears retains an active, unresolved include. That
include resolves against the previous snapshot's old file, so the refreshed
copy still books the deleted source transaction and passes `check`. Export
exits 0 and reports only the new root file, not the old file now loaded. A
source-load warning is printed; it does not prevent the changed accounting.
The same refresh also runs old plugin code when that module disappeared from
the source, changing the resulting balances; see the additional case below.
No product fix implemented.

Expected: a missing local include must not bind to a previous snapshot's
transaction data. Refuse an unresolved local include before staging anything,
naming its source file/line and target; preserve the previous snapshot. This
is compatible with exporting ordinary accounting errors as warnings: a local
file the export cannot copy cannot be represented by an active reference to
an old file. `--force` authorizes replacement of planned files, not adoption
of stale financial contents. The engine's `--allow-errors` export flag is for
unavailable managed sources and their marker; it should not bypass this local
include requirement.

Reproduction and controls:

- Four initial fresh journeys: two repetitions × wildcard/literal missing
  include. Explicit `--force --allow-errors` refreshes all exit 0, load the old
  2 USD payment, and produce a check-clean copy while the source partial
  query has no transactions and source check fails.
- Eight further fresh journeys: two repetitions × wildcard/literal × default
  export/human output or explicit `--allow-errors`/JSON. The default mode also
  reproduces. In each journey, refreshing the saved snapshot gives Cash 2 USD
  and check 0; exporting that exact same broken source to a fresh directory
  gives no transactions and check 1. Both exports exit 0 and warn about the
  source include. JSON reports one planned file in either destination, never
  the old transaction file. All source/old-file byte checks hold.
- Four valid-source controls, twice each for wildcard/literal: start with two
  source files totaling 3 USD, remove one while leaving a matching file (or
  remove its literal include), then refresh. The root is correctly rewritten
  to only the current file and both source/export hold 1 USD, even though the
  old unused snapshot file remains. Keep this behavior and preserve unrelated
  destination files; indiscriminately deleting leftovers is not the fix.

Cause: `LedgerSnapshot.capture` (`cli/src/bea_engine/ledger/write.py:195–208`)
records the unresolved local pattern with no matches. `export_portable`
(`managed_load.py:1686`) plans only files the current source reaches; it does
not reject the unresolved local include. `_rewrite_export_includes`
(:2318–2364) rewrites nonempty matches, but deliberately leaves an unresolved
include unchanged so stock tools will report the same error. That assumption
fails in an existing output tree: the old file remains and satisfies the
reference. The staged plan replaces the root and leaves that unplanned file
untouched. `price._answer` banners source errors without raising, explaining
exit 0 plus stderr; a warning cannot make the snapshot's old postings match
the source. The engine `price-export` handler is the sole production caller
of `export_portable`; both output modes use this path.

Fix: detect unresolved local include spans in the captured graph, and failed
plugin imports that a previous snapshot could satisfy, before any destination
creation/replacement; refuse with the source location. Do not
retain an active local reference that can resolve to unplanned destination
contents, and do not silently erase old/unrelated files. Preserve resolved
glob expansion, ordinary include copying, managed-source markers and the
existing handling of nonstructural accounting errors. No dependency or
backend/API change needed.

from beancount.core.data import Transaction
__plugins__ = ["adjust"]

def adjust(entries, options_map):
    out = []
    for entry in entries:
        if isinstance(entry, Transaction):
            posts = []
            for post in entry.postings:
                delta = D("2.00") if post.account == "Assets:Cash" else D("-2.00")

    return out, []

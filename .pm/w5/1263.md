# A Journal Custom row writes an amount value as "[object Object]": `custom "goal" Assets:Bank:Savings 12000.00 USD` reads "Assets:Bank:Savings [object Object]" on the Journal and the account page

**Severity:** minor. Nothing in the ledger is wrong, but any custom directive that carries an amount (a savings goal, a forecast, a plugin's settings) shows the reader JavaScript's placeholder instead of the number, in both Journal layouts and on the account's own journal. Screen readers hear "12,000.00 USD", because the row's accessible label formats it, so sighted and non-sighted readers get different text. **Owner:** `dashboard` (`features/journal`). **Estimate:** 20–30 minutes including tests. **A2:** Beancount's `custom` directive is how ledgers record things the core syntax lacks, and a newcomer copying an example with an amount in it sees the Journal fail to show it.

**Found by:** `/qa-find-bugs-dashboard` (`dashboard-qa` routine) on 2026-11-27 against `https://beancount.io`, entry chunk `main-BBmi61Hs.js`, isolated headless Chromium at 1440×1000, macOS, English, browser zone America/Mexico_City. Signed in as the QA owner on its designated disposable ledger, which was restored byte-for-byte afterwards (same blob, same SHA-256, no ledger errors). Local HEAD `088afa561`; `custom-description.tsx` has not changed since `76f269dc7` (w5/1190, 2026-11-23), which production runs, so this is not deployment lag.

## Repro

1. Append one directive to a ledger with an `Assets:Bank:Savings` account (the probe used `qa-20261127-` names):

   ```beancount
   2026-08-30 custom "qa-20261127-goal" Assets:Bank:Savings 12000.00 USD TRUE 3 "qa-20261127 emergency fund"
   ```

   The ledger check stays clean.
2. Open `/journal?time=2026-08`. Under **Entry types**, turn on **Custom**. The compact row reads `2026-08-30 Custom qa-20261127-goal · Assets:Bank:Savings [object Object] true 3 qa-20261127 emergency fund`.
3. Switch to **Comfortable**. The row reads `Custom qa-20261127-goal Assets:Bank:Savings [object Object] true 3 qa-20261127 emergency fund`.
4. Open `/account/Assets:Bank:Savings`. The custom row there reads the same `[object Object] true`.
5. Control on the same row: the row's button is named `Open entry 2026-08-30 Custom qa-20261127-goal Assets:Bank:Savings 12,000.00 USD true 3 qa-20261127 emergency fund (row 1)`. Entry Context shows the source line exactly as written (`… 12000.00 USD TRUE 3 …`). A `custom "budget"` row also renders its amount correctly, through its own branch.

Repeated from a fresh load.

API control (GraphQL `getLedgerJournal(query: {time: "2026-08", directiveTypes: ["Custom"]})`): the entry's `values` are `["Assets:Bank:Savings", {"number": "12000.00", "currency": "USD"}, true, "3", "qa-20261127 emergency fund"]`. The server sends the amount as an object on purpose, because the budget reader needs it.

## Cause

`dashboard/src/features/journal/components/journal-description/custom-description.tsx:45` renders every non-budget custom entry's values as `directive.values.join(" ")`. `Array.prototype.join` turns the amount object into `[object Object]` and the boolean into `true`. Only `BudgetDescription` (`:10-31`) knows the amount shape. The accessible label in `features/journal/components/journal-entry-label.ts:59-80` already walks the values and formats an amount with `formatAmount`, which is why the button name is right. The ledger serializer (`backend-cluster/ledger/src/foundation/rustledger/journal-serialize.ts:204-211`, `serializeCustomValue`) sends amounts as `{number, currency}` and booleans as booleans; its plaintext renderer (`:902-924`) writes them as `12000.00 USD` and `TRUE`.

## Fix

Owned by `dashboard`; no API change. In `CustomDescription`, render each value by type, separated by spaces: an `{number, currency}` amount through `<LedgerAmount>` (as `BudgetDescription` does, so digits and the reader's separators match the rest of the Journal), a boolean as `TRUE`/`FALSE` as Beancount writes it, and strings and numbers as they are. Make the row's accessible label in `journal-entry-label.ts` use the same boolean spelling, so the visible and spoken text agree. A value of any other shape should render as nothing rather than as `[object Object]`.

## Definition of done

- With the fixture above, the compact and Comfortable Journal rows and the account page row read `qa-20261127-goal · Assets:Bank:Savings 12,000.00 USD TRUE 3 qa-20261127 emergency fund` (English), and no Custom row anywhere shows `[object Object]`.
- The row's button name carries the same amount and `TRUE`.
- A rendered test of `CustomDescription` with an account, an amount, a boolean, a number and a string asserts that text, and fails on the current code. A `custom "budget"` row still renders as today. Dashboard gates (`yarn format:check`, `yarn lint`, `yarn test`, `yarn build`) pass.

# `bea format -i` on an unwritable file exits with a raw Python traceback, breaking the JSON error contract

**Severity:** minor. **Estimate:** 45–60 minutes. **Owner:** cli. **A1:** a
coding agent formatting a ledger tree gets an unparseable stderr and no way to
learn which files were already rewritten before the failure.

Found 2026-09-15 by a report-only CLI QA sweep against `main`, HEAD `ca74ad78`,
using `uv run bea` 0.2.0 on Darwin 26.5.1 arm64 with isolated
`BEA_CONFIG_DIR` / `XDG_CACHE_HOME` and `BEA_NO_UPDATE_NOTIFIER=1`. All
fixtures were synthetic local files.

## Repro

```sh
mkdir fmtdir && cd fmtdir
printf '2026-01-01 open Assets:Cash USD\n2026-01-02 * "a"\n  Expenses:X  1.00 USD\n  Assets:Cash -1.00 USD\n' > a.bean
cp a.bean b.bean && cp a.bean c.bean
chmod 444 b.bean
bea --json format . -i
echo "exit=$?"
```

Exit `1`, stdout empty, and stderr is a 20-line upstream traceback:

```text
Traceback (most recent call last):
  File ".../bea/engine/0.2.0/bin/bean-format", line 12, in <module>
    sys.exit(main())
  ...
  File ".../site-packages/beancount/scripts/format.py", line 225, in main
    file = open(filename, mode="w", encoding="utf-8")
PermissionError: [Errno 13] Permission denied: '<abs>/fmtdir/b.bean'
```

`json.loads(stderr)` raises `JSONDecodeError: Expecting value: line 1 column 1`.
`--debug` was not passed. The same traceback appears in human mode and for a
single read-only file (`bea format b.bean -i`).

Afterwards `a.bean` is rewritten (aligned) and `c.bean` is not: upstream stops
at the first file it cannot open, so the run is a partial write that nothing
reports.

## Expected / actual

Three documented promises fail:

- `cli/docs/USAGE.md:148` — "In `--json` mode a failure writes nothing to
  stdout and one object to stderr." Stderr is a traceback, not an object.
- `cli/docs/USAGE.md:88` — `--debug` is what makes errors "include exception
  tracebacks; JSON errors gain a `traceback` string". The traceback appears
  without it, and leaks absolute engine install paths.
- `cli/docs/USAGE.md:143-146` — `format --in-place` over several files "can
  rewrite some before failing on one it cannot write ... Read the operation
  result before retrying mutations." The partial write is real, but this path
  emits no result to read: neither the formatted paths nor the failing one is
  reported in bea's own words.

The partial write itself is documented and correct. Expected is that the
failure arrives as a normal `bea` error — category `validation` (exit 1),
naming the file that could not be written — and that `--json` returns one error
object whose `result` carries the paths already rewritten, the way the success
path already reports `formatted` via `_result(files, changed)`.

## Working controls

`bea format . --check` and `--dry-run` over the same directory report per-file
results and never write. `bea add` against a read-only ledger is the nearby
handled case: exit `3` with
"Ledger file is read-only or not writable: ...; nothing was written."
`cli/docs/USAGE.md` documents that asymmetry (`add` exits 3, `format -i` exits
1 with "the formatter's own message") — the gap is that upstream's message here
is an unhandled traceback.

## Root cause

`cli/src/cli/commands/format.py:92-98` snapshots `before` for the in-place
case, delegates with
`launch.run_native("bean-format", [... "--in-place", *files])`, and on a
nonzero status does `raise typer.Exit(status)` — no translation, no result.
`run_native` is the documented "upstream owns the streams and exit status"
path (`cli/CLAUDE.md`, ADR014), and upstream
`beancount/scripts/format.py:225` opens each output file with no error
handling, so `PermissionError` propagates as a traceback on the inherited
stderr. Because upstream owns the stream, `cli/src/cli/output.py`'s JSON error
envelope never runs. The `before` snapshot needed to report what was already
rewritten is in scope at `:92` but unused on the failure branch.

## Fix

Keep upstream as the formatter, but stop letting it own the failure. Capture
`bean-format`'s stderr for the in-place run, and on a nonzero status raise a
`bea` error that names the unwritable path, suppressing the traceback unless
`--debug` is set. Compute `changed` from the existing `before` snapshot on that
branch too, and attach it as the error `result` so `--json` returns one object
with the partial write recorded and human mode prints the formatted paths
before the error. Pre-checking writability of every target before invoking
upstream would turn most of these into a clean pre-flight usage error; decide
whether to add that alongside the handler. Add regressions for a read-only file
in a recursive run (JSON stderr parses, result lists the rewritten files) and
for a single read-only file.

## Blast radius and adjacent states

Affects `format --in-place` on any file upstream cannot open for writing —
directory-recursive and single-file, human and JSON. `--check`, `--dry-run`,
`--output FILE`, stdin filtering and successful in-place runs were exercised
and behave per their contracts. Other `run_native` delegations (`check`,
`doctor`, `example`, `treeify`, `price`) were not audited for the same
unhandled-exception shape and may share it. Windows and non-permission write
failures (full disk, read-only mount) were not exercised.

## Dedupe

Searched all `.pm/**/*.md`, including `done/`, for traceback, `bean-format`,
in-place and permission terms. `.pm/w2/done/019.md` covers formatter
syntax-error handling and its resolution rewrote the docs to describe exactly
this partial-write case, but did not address the unhandled write failure.
`.pm/w2/done/023.md` covers `--check` remediation hints and width flags.
`.pm/w5/done/001.md` and `.pm/w5/done/002.md` cover the `--output` envelope and
stdin filtering, both fixed by `32c1a175`; this failure path is untouched by
that commit and was re-verified after it landed. No item covers a `run_native`
delegation crashing past the error contract.
`git log -S 'run_native' -- cli/src/cli/commands/format.py` shows only
`a90b1706`.

## Evidence and unverified areas

Bounded subprocess captures under `cli/tmp/qa-20260915/run1/cases/` recorded
argv, cwd, isolated environment, separate streams, exit codes, and the
before/after contents of every `.bean` file in the directory. Synthetic
fixtures only; permissions were restored after each case. Not exercised:
installed releases outside this checkout, Windows, and the other native
forwarding commands.

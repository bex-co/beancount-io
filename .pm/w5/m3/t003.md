## Objective

Make the documented installation lifecycle predictable for users who already have skills installed.

## Context

- Users may have unrelated skills, earlier customer-suite versions, or locally edited copies in their chosen destination.
- The canonical customer source remains inside skills/; updates must not change repository development skill links.

## Steps

1. Provide repeat-install and update commands that identify the intended source revision and exact owned customer directories.
2. Detect name collisions and local modifications before replacing content; provide a clear preservation/recovery path.
3. Document removal of only the selected customer installation, keeping unrelated skills and user configuration intact.

## Files

- `skills/README.md`
- `skills/docs/installation.md (if created)`
- `skills/scripts/ (only bounded lifecycle helpers if existing mechanisms need them)`

## Acceptance criteria

- [ ] Repeating installation produces one usable copy of each intended skill.
- [ ] Unrelated sentinel skills and locally modified content survive the documented conflict path.
- [ ] Removal targets only the customer installation and leaves the ledger unchanged.

## Out of scope

- Automatic background updates.
- A general package manager or new dependencies.

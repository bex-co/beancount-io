**Minor · cli · 35–50m · A1 · worker1.** Real local CLI QA, 2026-10-23,
`bea 0.3.1` at `805da9490977a849d31ba8f3a8bbb935a5231e29`,

Beancount 3.2.3. Current main's CLI is byte-for-byte identical before filing.
All tracked archive hashes are checked before/after the batch. No product fix.

A plugin changes an explicitly written Open booking method **FIFO → LIFO**
or Balance tolerance **0.01 → 0.02**, including **0 → 0.02**. It also emits
a valid differently accounted directive of the same type/date at the source
location. That activates the documented shared-location comparison. The
changed primary row still claims to be written: full JSON omits its generated
mark, and on-disk/limit/human output returns LIFO or 0.02 although the file
states FIFO or 0.01/0. The generated secondary rows are correctly excluded.

The full calculated view should remain visible, with the contradictory
primary row marked generated and omitted from `--on-disk`, as changed account
currencies and balance numbers already are. The file states these values
explicitly. Omitted source booking/tolerance must remain unknown, and valid
within-tolerance assertions must remain written. This is a read/provenance
error; Cash stays 100 USD, source files never change, and all native checks
pass. No mutation, trade-plan, validation-bypass or financial-loss effect is
claimed.

## Standalone reproduction

With this checkout's `bea` on PATH, replace the absolute directory with a
fresh path per mode/repetition and run. The inspected plugin edits only
in-memory fields and creates two valid secondary directives: an opening for
`Assets:GeneratedMarker` and an Equity balance of −100 USD. Their different
accounts avoid duplicate-opening/assertion errors while sharing the primary
source's type/date/location. Both the raw reference and transformed ledger

## Root, scope and acceptance

`cli/src/bea_engine/ledger/reader.py:223`, `_declares`, excludes `booking`
and `tolerance` unconditionally from non-transaction field comparison.
Those fields may be omitted/inferred, but a blanket exclusion also ignores
explicit source enum/Decimal values. `shared_locations:144` requires two
same-type entries on one date/location; the fixture meets it without invalid
duplicate accounts. `entry_generated` uses this comparator for contested
locations, transaction/nontransaction serialization attaches its result,
and `ledger/listing.py:110` applies the on-disk filter before sort/limit.
Price, note, document and other directive callers were searched; only Open
and Balance carry the ignored fields reproduced here.

Dedupe searched all 5,437 board Markdown files and 39 open/blocked milestones,
plus caller and targeted history. `92f0bd628` introduced this field mask in
[507](./done/507.md)'s parser/comment/multiline-source repair. That report
does not cover explicit Open booking or Balance tolerance.
[681](./done/681.md) repairs relative documents and tag stacks.
[w3/293](../w3/done/293.md) made human balance tables show tolerance; that
complete known/absent rendering contract passes in the raw-reference controls
here. The problem is the claim that a calculated tolerance is written.
[916](./done/916.md) concerns imported directive-key ordering, and
[993](./done/993.md)/[1008](./done/1008.md) read authored balances for write
repeat/conflict decisions. No write regression is alleged. Transaction

[1014](./1014.md) exercise other fields/branches. No explicit-field mask owner

Fix/acceptance: compare a source Open's booking method and a source Balance's
tolerance when the source states them. Distinguish None from numeric zero;
retain wildcards for omitted values and derived `diff_amount` handling.
In all four failing modes, mark the changed primary row generated and exclude
it from on-disk JSON, human and limit output. Keep the full calculated row,
all generated secondary rows and current CLI checks valid. Preserve the six
working control profiles, the existing unique-location policy, and known
currency/amount comparisons. Add meaningful native shared-location coverage
for both directive types, omitted defaults and explicit zero. One CLI reader
helper owns the comparison; no API or dependency changes are needed.

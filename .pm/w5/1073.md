# Preserve native balances in funded-close checks

**Minor · cli · 35–50m · A1 · worker1.** The funded-close fold both invents
a balance for a natively empty wallet and hides a genuine nonzero one.
A 29-digit receipt followed by whole/fractional returns leaves native zero,
but `bea add close` refuses with phantom **+2e−18 SHIB** and imports falsely
warn. Returning two more fractional units leaves native **−2e−18 SHIB**, yet
the same unforced close succeeds with **no warning**; native Close imports
also miss the warning. Reordering the first two movements keeps the same
actual end balances and restores the correct guard/advisory behavior.
No stored amounts are rewritten; the close policy misreads them.

## Standalone reproduction

The essential source is:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Wallet SHIB
2024-01-01 open Equity:Opening USD
2024-01-02 * "Receive"
  Assets:Wallet 12345678901.123456789012345678 SHIB @ 0 USD
  Equity:Opening 0 USD
2024-01-03 * "Return whole"
  Assets:Wallet -12345678901 SHIB @ 0 USD
  Equity:Opening 0 USD
2024-01-04 * "Return fraction"
  Assets:Wallet -0.123456789012345678 SHIB @ 0 USD
  Equity:Opening 0 USD
```

`check` succeeds; native inventory progresses from the full exact receipt,
to **0.123456789012345678 SHIB**, to **empty**. BQL
`SELECT SUM(position) WHERE account = 'Assets:Wallet'` answers an empty
inventory. Yet `bea --json --no-input --offline --file /absolute/main.bean
add close --account Assets:Wallet --date 2024-01-31` reports phantom
**0.000000000000000002 SHIB**, exits 1 and preserves every input byte.
A handwritten close loads validly. `--force` appends that same valid close
with the actual inventory still empty; forcing should not be necessary.

The opposite direction is also reproduced. In a **fresh copy of the essential
Beancount fixture**, change only the final quantity to
`-0.123456789012345680 SHIB`. Native inventory now holds
**−0.000000000000000002 SHIB** before and after the operation. The same
unforced close exits 0, writes one Close and answers `warnings: []`.
A fresh native Close import previews/applies with no funded warning either.
Put the whole return before the receipt, keeping the same final holding:
unforced close correctly refuses, and the import correctly warns with the
actual negative balance. Both books pass native check; the policy is meant
to refuse nonzero units regardless of sign. These additional direct/import
captures use JSON and the standard-root fixture.


Put checkout `bea` on PATH, save this as `recipe.py`, and run in a fresh path:

```sh
python3 recipe.py /absolute/unused/empty-wallet wide-first standard root /absolute/managed-engine/bin/python json
```

Use `renamed included … human` for renamed roots, EUR zero weights, a split
journal and human output. `small-first` makes the whole-token return precede
the receipt; `boundary` uses a 28-digit receipt with the same final fractional
return. Both are working controls, native empty in every case. The controlled
reader returns only a Close. Every read, refused write, preview and repeat
guards the exact files; successful writes change only their designated ledger
file. Native history is unchanged by the close, import and full export.

## Cause and bounded repair

[`_held_through`](../../cli/src/bea_engine/ledger/adding.py#L314) folds each
currency with `held.get(currency, Decimal(0)) + posting.units.number` (:331).
The first 29-digit number rounds to 28 at the artificial zero addition,
before the whole-token return can cancel it down to 18 digits. The final
fractional return then leaves a computed **2e−18** rather than zero.
Upstream `Inventory.add_position` stores a first position without that
arithmetic, and its real reductions yield empty. Three captured calls to the actual checkout helper confirm context precision
28: native empty is read as the phantom map; reordered empty reads correctly;
and native −2e−18 is read as **empty** after the extra fractional return.
The first +2e−18 rounding error precisely hides that negative holding. The
costless lot fold also then appears empty, so the direct close and import
advisory both pass. These are root-cause helper probes, separate from the
independent native oracles; no product code was changed.

[`_remaining_balance`](../../cli/src/bea_engine/ledger/adding.py#L413) feeds
both direct `_funded_close_refusal` (:451; `_close` :509) and imported
[`_funded_close_advisories`](../../cli/src/bea_engine/importing.py#L1094),
called from import preview (:914). That explains the refusal and advisory.
The helper also supplies the unit-only `file_holds` decision in same-day
bulk ordering (:2316), so preserve that return view and its date/account
boundaries. No hosted behavior or additional bulk precision failure is claimed.

Base the close's remaining units on native-preserving accumulation: a first
value and an actual zero/no-op must retain the operand, while genuine
nonzero additions retain normal native Decimal arithmetic. Keep the current
unit-only per-currency return shape and zero removal, or obtain that same
view from native inventories; preserve cost-lot retirement checks separately.
Do not globally raise precision, round balances to display digits, drop
small genuine funds, require force, or tell the user to post a fictitious
movement. A natively empty wallet must close normally, and a genuinely nonzero wallet
must require force. Native Close imports must warn exactly for actual funds,
including a negative balance, without inventing funded warnings. Keep snapshot validation, genuine funded
refusals, same-day inclusivity, child independence, explicit force and actual
`check_drained` diagnostics. CLI-local only, no dependency or API change.
Run the CLI checks when implementing.

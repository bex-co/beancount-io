## Expected / Actual

Expected: at every width, an expanded posting says which amount is the lot cost and which is the price. It also shows the lot's date and, when present, its label, as Fava shows `-2 QALBL {10.00 USD, 2026-02-01, "lot-b"} @ 15.00 USD`. Actual: on desktop, cost and price are two unlabeled numbers, and the date and label appear at no width.

## Root cause

`dashboard/src/features/journal/components/journal-postings.tsx:74-96` renders the desktop units, cost and price as three bare `hidden sm:block` spans. The localized "Cost:" and "Price:" labels exist only in the `sm:hidden` narrow spans (lines 55-71, from w4/220). Neither branch reads `posting.cost.date` or `posting.cost.label`.

## Fix

- On desktop, give cost and price visible or programmatic labels: column headings for the expanded posting list, or the existing localized `journal.postingCost` and `journal.price` text.
- Show the lot date, and the label when present, beside the cost at every width, using the existing date and amount formatters. Keep absent fields absent.
- Keep the narrow layout, account links and posting flags.
- Add rendered tests for a dated, labelled reduction, a cost-only posting, a price-only posting, and a posting with neither.

## Blast radius

`JournalPostings` is shared by the Journal and the account journal (`JournalTable`). Entry Context shows the source text (`{"lot-b"}`), not the booked lot, so it does not fill the gap. The mobile sibling w21/done/603 fixed Money flow on mobile only.

# Smart Import Configure shows -4.50 as "-4.5" and 1,250.00 as "1250", though Preview shows, and the import writes, -4.50 and 1250.00

**Severity:** minor (display accuracy). **Owner:** dashboard. **Estimate:** 15–25 minutes including a test. **A2:** Configure is the last review before transactions are written. It shows different amounts from the step before it and from the entries it is about to write, so a careful reviewer has to wonder whether the amounts changed. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-18 against `https://beancount.io` (entry chunk `main-LGv2TZLj.js`), headless Chromium 153 at 1440×1000 and 390×844, English/light. QA owner account on the synthetic `<qa-owner>/mcp-agent-eval` ledger. Nothing was imported.

## Repro

1. On `/ledger/<owner>/<ledger>/import`, upload a CSV with the header `Date,Payee,Description,Amount` and the amounts `-4.50`, `"1,250.00"` and `(12.00)`.
2. Preview lists them as **-4.50**, **1250.00** and **-12.00**.
3. Click **Continue to Configure**. The Amount column now reads **-4.5**, **1250** and **-12**.

Same at 390×844. Repeated from a fresh load.

## Cause

`dashboard/src/features/importer/components/steps/configure/account-mapping-table.tsx:394` renders `formatImportReviewAmount(txn.amount)`, and `utils/format-import-review-amount.ts:5-18` formats the JavaScript number with `toLocaleString("en-US", { maximumFractionDigits: 20 })`, which drops trailing zeros. Each row already carries the exact decimal it submits, `amountDecimal` ("the exact normalized decimal that is submitted", `account-mapping-table.tsx:56-57`; digits as written, `utils/csv-validator.ts:80-84`), and `transaction-config-form.tsx:261` sends that string. The package rule in `dashboard/AGENTS.md` (Code standards) is to read an amount's digits from its decimal string, not from a computed double.

## Fix

Render `txn.amountDecimal` in the Configure Amount cell, inside the same `<Amount>` isolate so the sign stays before the digits in right-to-left languages (w4/1047). The value shown is then the value submitted, including trailing zeros and very small or very precise amounts (w4/1058's `1e-24` case becomes its exact decimal). Keep filters and sorting on the numeric `amount`. Remove `formatImportReviewAmount` if nothing else uses it.

## Definition of done

- With the fixture above, Configure shows `-4.50`, `1250.00` and `-12.00`, the same as Preview and as the written postings.
- A satoshi-scale amount (`0.00000001`) and a tiny one (`0.000000000000000000000001`) display as written.
- Persian keeps the sign before the digits.
- A test renders the Configure table with these rows and fails on the current code. Dashboard gates pass.

## Dedupe

Searched `.pm/**`, including `done/`, for `formatImportReviewAmount`, Configure amount display and trailing zeros. w4/done/1058 fixed amounts that rounded to zero in this formatter, and `135db0a68` replaced its earlier two-place rounding. Both kept the number as the source, so neither covers trailing zeros. w4/done/1047 is the RTL sign. Present at HEAD.

## Remaining native-inference case

The source declares these four postings, in this order:

```beancount
2024-02-01 * "Mixed expense"
  Assets:Cash
  Assets:Cash -10.00 USD
  Expenses:USD 10.00 USD
  Expenses:EUR 20.00 EUR
```

Cash is open in USD and EUR. Native booking validly infers Cash −20 EUR and
returns Cash −10 USD, Expenses +10 USD, Cash −20 EUR, Expenses +20 EUR.
A plugin retains the source and adds a copy changing only narration to
`Derived expense`, with the same date/location. The bank statement spells
Cash −20 EUR explicitly; unlike the source, no importer row relies on
inference. Both source and statement have four postings and no costs,
prices or posting flags.

Results twice per mode:

| Source/control | On-disk source rows | Preview / apply | Authored Cash USD / EUR |
| --- | --- | --- | --- |
| Omitted amount first, header copy | 0 | new / exit 0, written 1 | −10/−20 → −20/−40 |
| Same, reversed plugin order | 0 | new / exit 0, written 1 | −10/−20 → −20/−40 |
| Same, explicit skip, JSON or human apply | 0 | new / exit 0, written 1 | −10/−20 → −20/−40 |
| Move known USD source line first | 1 | possible_duplicate / exit 4; skip writes 0 | stays −10/−20 |
| Specify currency only on inferred line (`Assets:Cash EUR`) | 1 | possible_duplicate / exit 4 | stays −10/−20 |
| Spell its full −20 EUR amount | 1 | possible_duplicate / exit 4 | stays −10/−20 |
| Original omitted amount, no plugin | 1 | possible_duplicate / exit 4 | stays −10/−20 |

For failing modes full listing returns the genuine source marked generated,
on-disk/default human listing and newest limit-1 omit it, and the bank

append the new statement. The no-plugin listing uses its documented unique

# A Journal Document row cannot open its file, and the journal gives the path relative to the file that declares it ("docs/x.txt" where Documents says "sub/docs/x.txt")

**Severity:** minor. **Owner:** `dashboard` (Journal row) plus `backend-cluster/ledger` (journal serializer). **Estimate:** 45–60 minutes including tests. **A2:** an attached statement or receipt is how a user backs up an entry. In the Journal and the account journal they can see that a document exists but have no way to open it. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-18 against `https://beancount.io` (entry chunk `main-LGv2TZLj.js`), headless Chromium at 1440×1000, English, isolated profile, signed in as the QA owner on a disposable QA ledger. Local HEAD `a84cb10f2`. The probe files were written and then removed. `main.bean` was restored byte for byte (same blob SHA, no ledger errors).

## Repro

`main.bean` has `include "qa-20261118/lots.bean"`. That included file declares, relative to its own folder:

```beancount
2026-01-01 open Assets:Qa20261118:Fifo QAFIFO "FIFO"
2026-05-03 document Assets:Qa20261118:Fifo "docs/qa-20261118-statement.txt"
```

`qa-20261118/docs/qa-20261118-statement.txt` is committed, and the ledger reports no errors for these lines.

1. Journal → turn off Transaction and turn on Document. The row reads `2026-05-03 · Document · Assets:Qa20261118:Fifo · qa-20261118-statement.txt`. The filename is a `div.filename` with `cursor: pointer` but no role, no tabindex and no handler. Its tags and links (`span.tag` / `span.link`) are styled the same way.
2. Click the filename. The row's own action opens Entry Context (`Location: qa-20261118/lots.bean:<line>`, the source line, Delete / Save / Close). The dialog has no link or button that opens the document. The account page's journal shows the same.
3. Control: Documents lists `qa-20261118/docs/qa-20261118-statement.txt`, and its filename button opens `/files/blob/main/qa-20261118/docs/qa-20261118-statement.txt` with the file's text.
4. API: for the same directive, `getLedgerDocuments` returns `filename: "qa-20261118/docs/qa-20261118-statement.txt"`. `getLedgerJournal` returns `{"directive_type":"Document","filename":"docs/qa-20261118-statement.txt", …}`, which does not resolve from the repository root and does not say which file it is relative to.

## Expected / Actual

Expected: a Document row's filename is a real, keyboard-reachable control that opens the stored file, as Fava's journal does and as the Documents page already does. Every surface reports the document as one repository-relative path. Actual: the row looks clickable but has no way to reach the file, and the journal reports a path relative to the declaring file.

## Root cause

- `backend-cluster/ledger/src/foundation/rustledger/journal-serialize.ts:418` serializes `filename: directive.path` (the raw directive text). `directives-report.ts:344` already uses `documentFilePath(directive)` for `getLedgerDocuments`, which is w4/301's fix. The journal was not updated with it.
- `dashboard/src/features/journal/components/journal-description/document-description.tsx:11-24` renders the filename, tags and links as plain styled elements with no action.

## Fix

- **Ledger:** serialize the journal's Document `filename` through `documentFilePath`, so GraphQL, REST and MCP journal reads all return the same repository-relative path as `getLedgerDocuments`. Add a test with a document declared in an included subfolder.
- **Dashboard:** make the filename a button or link that opens the file through `useFileNavigate` (the same navigation `DocumentRow` uses). Stop it from also triggering the row's Entry Context. Make it reachable by keyboard and give it an accessible name. Drop the pointer cursor from tags and links unless they get an action.
- Keep the basename display and the row's Entry Context action for the rest of the row.

## Blast radius

`DocumentDescription` renders in both the Journal and the account journal (`JournalTable`). The journal serializer feeds all three API surfaces. A document declared in the root file already matches the Documents path, so only included subfolders show the path mismatch. The missing open action affects every document.

## Dedupe

Searched `.pm/**`, including `done/` and `blocked/`, for document rows, opening attachments, `filename` and `documentFilePath`. w4/done/301 fixed the path for `getLedgerDocuments` only. w21/done/050 is mobile's account detail, which shows the filename as text. w5/done/833 is `bea list document`. w4/done/242 and w4/done/243 are the Documents table. No open item covers the Journal row or the journal payload's path. Both are unchanged on `main`, so this is not deployment lag.

## Unverified

The REST and MCP journal reads were not called directly; they share the serializer. PDF and image documents (opening a binary file) were not tried.

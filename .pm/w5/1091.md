conflict says `balance of 10.00 USD; refusing 10.00 USD`. Its human preview

## Cause and scoped repair

`cli/src/bea_engine/importing.py:781–788` correctly finds a same-key Balance
with a different full directive key. The reason then formats
`clash.amount` and `entry.amount` through `_plain_amount`, discarding the
separate `Balance.tolerance` on both sides. The distinction is still present
in the serialized `entry` and `match.entry` fields.

`cli/src/cli/commands/import_.py:2085–2123` renders `row["amount"]`, which is
empty for a Balance, prints `match["entry"]`, and then the accepted-row diff.
A conflicting row is excluded, so its proposed directive never reaches that
diff or another human block. The result hides the only changed value.

Render enough of the two balance declarations to distinguish explicit zero,
nonzero and implicit tolerance in the conflict diagnostic, or show the full
proposed assertion beside its match. Retain the complete JSON fields. The
direct-add formatter already demonstrates the intended detail:
`ledger/adding.py:548–556`, `_conflict_refusal`/`_balance_amount`.

Caller search: `importing.answer` is dispatched by
`bea_engine/main.py:638`; frontend `import_entries` calls the helper at
`import_.py:1976` and shares preview/apply classification. The same reason
builder handles recorded and accepted-in-batch Balance matches. `_plain_amount`
also formats Price reasons; this report owns the Balance tolerance omission.
Configured/default/remembered Python-importer selection reaches this path;
the actual failure matrix uses explicit `--config`. CSV/OFX transaction
rows, other non-transaction fields and hosted API surfaces are not claimed.
No dependency or backend change is indicated.

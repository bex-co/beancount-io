# Open Account refuses the bare root "Assets" with "Account must start with one of: Assets, …"

**Severity:** minor (copy). **Owner:** dashboard. **Estimate:** 15–25 minutes. **A2:** a user who types just a root name, such as `Assets` or `Expenses`, is told that it must start with one of a list that includes the very word they typed. Refusing it is correct, because a Beancount account needs at least one part after its root. The message points the wrong way, though. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-16 against `https://beancount.io`, using headless Chromium at 1440×1000 in English. The account was the QA owner, on its designated disposable ledger `mcp-agent-eval`. Nothing was written for this check. Local HEAD `d967f57cd`.

## Repro

1. Go to Accounts and click **Open Account**. The dialog opens at `?action=open-account`.
2. In Account Name, type `Assets`, then tab away.
   - The message reads "Account must start with one of: Assets, Liabilities, Equity, Income, Expenses", and **Open Account** stays disabled.
   - With `Foo:Bar`, the same message is correct. With `Assets::X`, the dialog correctly says "Remove the empty part…".

## Cause

`dashboard/src/common/lib/beancount/open-account-schema.ts:26–31` uses `val.startsWith(`${prefix}:`)`, so a bare root fails the prefix check. That check reports `page.accounts.accountMustStartWith` (`features/ledger-data/accounts/locales/en.ts:16`). `useOpenAccountSchema` (`common/hooks/use-open-account-schema.ts`) builds this schema for both the Accounts dialog and the New Entry "Account" tab, so the same message appears in both places.

## Fix

When the value exactly equals one of the prefixes, say that a name is needed after the root. For example: "Add a name after Assets: — for example Assets:Bank". Use a new string in all 15 locales. Keep the current message for a value that has no valid root at all.

## Definition of done

- `Assets` and `Expenses` show the new message, and **Open Account** stays disabled.
- `Foo:Bar` still shows "must start with one of".
- A schema unit test covers a bare root, an unknown root and a valid name.
- Dashboard format, lint, test and build pass.

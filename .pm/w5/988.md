# Recognize compact option and plugin declarations when choosing a root

**Major · cli · 30–45m.** Real local CLI QA, 2026-10-22, checkout `bea 0.3.1` at
`89d94452fa901d3304cb4b86ae8a7570b5e4369d`, macOS 26.5.1 arm64,
frontend Python 3.13.3, managed Python 3.12.10 / Beancount 3.2.3.
No product fix implemented. A1: reliable local-ledger automation; worker1.

Native Beancount accepts `option"operating_currency""USD"` and
`plugin"beancount.plugins.auto_accounts"`. The CLI's root scanner misses
both. If a forecast view repeats the same setting with spaces, the scanner
misclassifies that repeat as a new definition and validates writes against
the forecast. `add balance` accepts **110 USD** into a working book holding
**100 USD**, exits 0, and leaves that previously valid working book failing
check. A truthful 100 USD assertion is refused instead. The forecast's
transaction header has normal spaces: this does not depend on w5/987.

[USAGE's root-selection contract](../../cli/docs/USAGE.md#adding-directives)
says a repeated setting is not a new definition and a forecast overlay that
only adds entries is not the working ledger's root. Preserve that behavior
for native compact declarations too. The builtin `auto_accounts` plugin was
inspected before use; it only supplies missing account opens locally.

Replace the absolute directory with a fresh one and run this standalone
recipe. Repeat in another fresh directory. Try each listed mode and use
100.00 USD in separate pristine cases for the truthful assertion. Setting
`explicit_into=True` or `human_add=True` exercises those controls. Children
have isolated config/cache, closed stdin/no TTY, separate streams, bounded
timeouts and before/after hashes; HOME and the global installation are untouched.

```python
import hashlib, json, os, pathlib, subprocess
case = pathlib.Path('/abs/compact-settings-case')
mode = 'option-compact'  # option-spaced, option-joined, plugin-compact, plugin-spaced
amount = '110.00 USD'  # use 100.00 USD in another fresh case
explicit_into = False
human_add = False
case.mkdir(parents=True)
working, view = case/'working.bean', case/'view.bean'
plugin = mode.startswith('plugin-')
own = {'option-compact':'option"operating_currency""USD"\n',
       'option-spaced':'option "operating_currency" "USD"\n',
       'option-joined':'option "operating_currency""USD"\n',
       'plugin-compact':'plugin"beancount.plugins.auto_accounts"\n',
       'plugin-spaced':'plugin "beancount.plugins.auto_accounts"\n'}[mode]
opens = '' if plugin else ('2024-01-01 open Assets:Cash USD\n'
                            '2024-01-01 open Equity:Opening USD\n')
working.write_text(own + opens + '2024-01-02 * "Capital"\n'
                   '  Assets:Cash 100.00 USD\n'
                   '  Equity:Opening -100.00 USD\n', encoding='utf-8')
declaration = ('plugin "beancount.plugins.auto_accounts"\n' if plugin else
               'option "operating_currency" "USD"\n')
view.write_text(declaration + 'include "working.bean"\n'
                '2024-01-15 * "Forecast"\n'
                '  Assets:Cash 10.00 USD\n'
                '  Equity:Opening -10.00 USD\n', encoding='utf-8')
original = {p:p.read_bytes() for p in (working,view)}
(case/'initial-working.txt').write_bytes(original[working])
env = os.environ.copy()
for key in ('BEA_FILE','BEA_TOKEN','BEANCOUNT_LOAD_CACHE_FILENAME'):
    env.pop(key,None)
env.update(BEA_CONFIG_DIR=str(case/'config'),XDG_CACHE_HOME=str(case/'cache'),
           BEA_NO_UPDATE_NOTIFIER='1')
def run(tag,args,file=working,json_mode=True):
    before = working.read_bytes()
    cmd = ['bea',*(['--json'] if json_mode else []),'--no-input','-f',str(file),
           *map(str,args)]
    r = subprocess.run(cmd,cwd=case,env=env,stdin=subprocess.DEVNULL,
                       capture_output=True,text=True,timeout=25)
    print(json.dumps(dict(tag=tag,args=cmd,exit=r.returncode,stdout=r.stdout,
                          stderr=r.stderr,working_preserved=working.read_bytes()==before,
                          before_sha256=hashlib.sha256(before).hexdigest(),
                          after_sha256=hashlib.sha256(working.read_bytes()).hexdigest(),
                          view_preserved=view.read_bytes()==original[view])),flush=True)
run('working-before',['check'])
run('view-before',['check'],view)
args = ['add','balance','--date','2024-02-01','--account','Assets:Cash','--amount',amount]
if explicit_into:
    args += ['--into',working]
run('add',args,json_mode=not human_add)
run('working-after',['check'])
run('view-after',['check'],view)
```

Actual, both compact modes, twice:

- Working and view checks initially exit 0. Independent native loads confirm
  cash 100 and 110 USD respectively and recognize the exact option/plugin.
- False 110: add exits 0, `written: 1`, `target.file` is view.bean and
  `target.into` is working.bean. Only working changes. Working check exits 1
  with `expected 110.00 USD != accumulated 100.00 USD (10.00 too little)`;
  view still checks. Native loads confirm the wrong assertion and unchanged
  transaction totals. Its failing-read hint also points at that wrong view.
- True 100: add exits 1 and writes nothing, although the selected working
  book has exactly 100. Both original books remain valid.
- `option-spaced`, `plugin-spaced`, and `option-joined` work: false 110
  refuses atomically; true 100 writes and working remains valid. The view
  then fails the actual assertion because it contains a hypothetical 10,
  an expected conflict in the view the user did not choose.
- Explicit `--into working.bean` rejects the false assertion even with
  compact declarations. Human output confirms the same false-write defect.

The same missed declarations also hide real providers: in another native-valid
split book, root-only compact auto_accounts plus an unflagged, unopened leaf
causes `add note` through the leaf to exit 1 unchanged instead of using the
root's opens. A root-only compact operating-currency option makes an otherwise
valid bare `Expenses:Food 7.75` / inferred Cash transaction exit 2, currency
ambiguous, unchanged. Spaced declarations succeed; only joining the two quoted
option values succeeds too, and explicitly writing `7.75 USD` succeeds. The
missing boundary is between the keyword and its first quote, not between values.

Cause: `cli/src/bea_engine/ledger/write.py:2058–2059`, `_OPTION_NAME` and
`_PLUGIN_NAME`, require `[ \t]+` after the keyword. `_defines_in` at 2110
therefore cannot compare the actual declaration in the working closure
with the repeated declaration in the view. Runtime proofs on hash-verified
initial copies show the compact own options/plugins absent, `_defines_in`
true and view chosen; spaced own declarations are present, `_defines_in`
false and working chosen. `_step_adds_entries` is true in every forecast
case, so fixing `_ENTRY_LINE` alone (987) does not repair this defect.

Fix native keyword/quoted-value boundary recognition for both declarations,
preserving actual repeated-name comparison, genuine fresh definitions,
overlay stopping, empty pass-through intermediates and explicit selection.

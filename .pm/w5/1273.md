# The last "Show more ledgers" on a profile and "Load Large Diff" on a commit drop keyboard focus to the page body (gap in w3/491)

**Severity:** minor (accessibility; WCAG 2.4.3 Focus Order). **Owner:** `dashboard`. **Estimate:** 30–40 minutes including two rendered tests. **A2/A3:** a keyboard or screen-reader visitor browsing a public profile's ledgers, or reading a large commit's changes, loses their place at the moment the page reveals what they asked for. w3/491 fixed the same loss for Activity, the profile's social lists, Gallery and commit history through the shared `ContinuationControl`. These two controls were left out. **Found by:** `/qa-find-bugs-dashboard` (`dashboard-qa` routine) on 2026-11-28 against `https://beancount.io`, production entry chunk `main-BBmi61Hs.js`, local HEAD `5a4b03cd7`. Isolated headless Chromium 158 at 1440×1000 and 390×844, English, signed in. Public ledgers only; nothing written. Each repro was repeated from a fresh load at both widths.

## Repro

1. Open `/ledger/open_ledger?show=48`. The Ledgers tab reads "Showing 48 of 50 loaded ledgers". Tab to **Show more ledgers** and press Enter. The last two ledgers appear and the status reads "Showing 50 of 50 loaded ledgers". The button is gone, and `document.activeElement` is `<body>`. The next Tab goes to "New to Beancount? Start with an example" (1440px) or "Committed to fedex" (390px). Both are past the two ledgers just revealed, so a keyboard reader has to Shift+Tab back to find them. Earlier presses (12 → 24 → 36 → 48) keep focus on the button, as they should.
2. Open `/ledger/open_ledger/example/commit/e92b88c9f18bf4de0830f6a75072abe216dbf475` ("Update file main.bean", +6,505 −38). The diff is gated behind **Load Large Diff**. Tab to it and press Enter. The virtualized diff renders, and `document.activeElement` is `<body>`. A screen reader is left with no position on the page.

Controls on the same build: the dashboard's Activity **Show More** keeps focus on the button after each page, and w3/491's end state (focus moves to the "No more results" status) is what the profile list should do too.

## Cause

- `dashboard/src/features/user-profile/components/ledger-collection.tsx:326–335` renders **Show more ledgers** only while `visible.length < filtered.length`. The press that reveals the last ledgers unmounts the focused button. The status above it (`:315`, `role="status"`) is not focusable, and nothing takes focus. This list does not use `common/components/continuation-control.tsx`, which handles exactly this case: when `hasMore` turns false and it owned focus, it focuses `getEndFocusTarget(previousCount)` or its own `tabIndex={-1}` status line.
- `dashboard/src/features/git/commits/components/commit-detail.tsx:151–181` replaces the **Load Large Diff** button with `<DiffViewer>` once `handleLoadDiff` (`:66`) sets `loadedDiffSha`. While the transition is pending the button is also `disabled={isPending}` (`:156`), and a focused button that becomes disabled loses focus in Chromium before the swap. No focus handoff follows either way.

## Fix

- Profile ledgers: when a keyboard press of **Show more ledgers** reveals the last ledgers, move focus to the first newly revealed ledger's link (preferred: it is what the reader asked for), or to the results status made focusable with `tabIndex={-1}`. Keep focus on the button while more remain. Either adopt `ContinuationControl` with a `getEndFocusTarget`, or apply the same rule locally. The `?show=` URL behavior and the "Showing N of M" status stay as they are.
- Large diff: keep the button focusable while it loads (`aria-disabled` plus an early return, as `ContinuationControl` does, instead of `disabled`). After the diff mounts, focus the diff viewer's "Changes" heading (give it `tabIndex={-1}`) or the first file's section, only when the button had focus. A mouse click leaves focus alone. A `#diff-file-…` focus request that is waiting on the gate (`activeFocus`, `:90`) still wins.
- Tests: a rendered profile-collection test that presses Enter on the last **Show more ledgers** and asserts the focused element is the first new ledger link (or the status), never `document.body`. A rendered commit-detail test with a gated diff that does the same for **Load Large Diff**. Both fail on current code.

## Blast radius

`ledger-collection.tsx` serves every profile's Ledgers tab, including the signed-in owner's own profile and `?q=` searches. `CommitDetail` is the only caller of the large-diff gate. It serves `/commit/<sha>` directly and Files → **Version History**. The other paging controls (Activity, Followers/Following/Starred, Gallery, Load older commits) already use `ContinuationControl` and were not changed by this run. The Journal's page buttons were covered by w3/491 too.

## Dedupe

Searched `.pm/**` (open, `done/`, `blocked/`) for "Load Large Diff", "Show more ledgers", `ledger-collection`, `commit-detail.tsx`, `ContinuationControl`, "drop keyboard focus" and "page body". w3/491 (done, `b74c04b47`) is the source pattern and names only Activity, the social lists and commit history. w4/963 (done) covers where **Show more ledgers** sits after hydration, not what happens after a press. w4/m36 covers React #418 replacing a focused **Load Large Diff** before any press. w5/1169 (done) fixed **Load latest**. No item covers either control losing focus when pressed.

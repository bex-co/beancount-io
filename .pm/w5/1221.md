# New Entry refuses a foreign-currency transaction with a blank balancing posting: "Amount is required", naming no posting, because the blank row is held to the ledger's currency

**Severity:** minor. Nothing wrong is written, but the most ordinary multi-currency entry cannot be made the Beancount way (leave the balancing posting empty), and the refusal points nowhere. **Owner:** `dashboard`. **Estimate:** 30–45 minutes including tests. **A2:** a newcomer on a USD ledger records a 10 EUR expense, leaves the cash side empty as every Beancount guide shows, and is told an amount is required without being told which one or why. **Found by:** `/qa-find-bugs-dashboard` (`dashboard-qa` routine) on 2026-11-26 local (2026-11-27 UTC) against `https://beancount.io`, production entry chunk `main-BBmi61Hs.js`. QA-owned headless Chromium 158, isolated context, 1440×1000 and 390×844, English, signed in as the QA owner of a disposable `qa-`-prefixed synthetic ledger. No entry was written: the form refused before sending, and the API control below is a dry run. Local HEAD `fa9af286c`.

## Repro

Any ledger whose operating currency is USD and that has two open accounts without currency constraints, for example:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Cash
2026-01-01 open Equity:Opening
```

1. Journal → **New Entry** → Transaction. Narration `qa-20261127 eur expense`.
2. Posting 1: account `Assets:Cash`, amount `10`, currency **EUR** (picked from the list).
3. Posting 2: account `Equity:Opening`. Leave the amount empty. Its currency field already reads **USD**, as does the automatic third row: every new row starts in the ledger's currency.
4. Posting 2 shows no inferred amount (its placeholder stays "Amount (e.g., 100.00)", no "auto" label).
5. Press **Create Transaction Entry**. No request is sent. A form-level alert at the top of the dialog says **Amount is required**. No field is marked `aria-invalid`, the message names no posting, and focus stays on Create Transaction Entry. Same at 390×844. Repeated from a fresh page load.
6. Control: set posting 2's currency to EUR. Its placeholder becomes `-10` with "auto", and the entry would submit. The "Amount is required" alert stays on screen, though nothing is missing any more, until the next submit.

Expected: an empty posting balances the transaction, as in Beancount, where `Equity:Opening` with no amount is interpolated to `-10 EUR`. The form should infer `-10 EUR` (or send the posting with no amount and let the ledger interpolate it). When an amount genuinely cannot be inferred, the error should say which posting and why, mark that field invalid, and move focus to it.

API control (dry run, nothing written): `bulkEntries(dryRun: true)` with postings `Assets:Cash 10 EUR` and `Equity:Opening` with `units` omitted returns `valid: true`, `newErrors: []`, and previews `Equity:Opening` with no amount. The `LedgerPostingInput.units` description already says "omit on at most one posting per transaction to elide it". The same request with `Equity:Opening -10 USD` returns `valid: false` with `E3001 Transaction does not balance: residual 10 EUR` and `residual -10 USD`.

## Cause

- `dashboard/src/features/journal/components/new-directive-dialog/transaction-form.tsx:163-172`, `:199-206` and `:357-362` give every posting row, including the automatic blank row and **Add posting**, `currency: primaryCurrency`.
- `transaction-auto-balance.ts:49-93` (`computeAutoBalance`) groups postings by `postingCurrency` (`:36`). The empty posting therefore sits alone in the USD group with no filled amount, so it is never given the EUR residual (`:82` needs a filled amount in the same group). The function sets `incomplete = true` (`:90`).
- `transaction-form.tsx:237-239` turns `incomplete` into the form-level `journal.amountRequired` ("Amount is required") in the `<Alert>` at `:396`. Nothing ties it to a posting or moves focus, and `setError(null)` runs only at the next submit (`:226`), so the alert outlives the fix.

w4/339 made a blank currency mean the primary currency consistently (inference, residual check and request). That is still right for a posting that has an amount. This note is only about a posting with **no amount**, which in Beancount takes whatever residual is left.

## Fix

- In `computeAutoBalance`, when exactly one eligible posting has an empty amount, its own currency group has no filled amounts, and exactly one other currency group has a nonzero residual, infer that residual and that currency for it. Show it in the row as `-10` "auto" with the inferred currency, and submit it. A user-chosen currency on that row still wins if it has filled amounts of its own; keep w4/339's behaviour for filled postings.
- Alternatively, submit that posting with `units` omitted. The API and ledger already interpolate it, as the dry run above shows. If you do this, show the user what the ledger will infer.
- When no amount can be inferred (two empty postings in one currency, or several unbalanced currencies), name the posting(s) in the error, set `aria-invalid` on their amount fields, and focus the first one. Clear the alert once the postings become complete. Apply this to the second `amountRequired` path at `:247-249` too.

Tests (`__tests__/unbalanced-submit.test.tsx` or `transaction-auto-balance.test.ts`):
- `10 EUR` plus a blank posting on a USD ledger prepares `-10 EUR`, or an elided posting. This fails on the current code.
- Two blank postings still refuse, naming them.
- Explicit-currency and same-currency cases stay as today.

## Definition of done

On a USD ledger, New Entry with `Assets:Cash 10 EUR` and an empty `Equity:Opening` shows the inferred `-10 EUR` and records a balanced transaction. A case that cannot be inferred names its posting, marks it invalid and focuses it, at 1440×1000 and 390×844. Dashboard gates pass.

## Blast radius

Only the dashboard New Entry Transaction tab uses `computeAutoBalance`. The **Balance** tab also defaults its currency to the ledger's (`USD` for an `Assets:Cash` that holds only EUR), but it has no inference, so it is out of scope here. Mobile's New Transaction was not exercised.

# Apply half-up rounding to exact halfway budget shares

**Minor · cli · 40–55m · A1/A2 · worker1.** Half of an April budget of
3000.01 USD is exactly 1500.005 USD; the documented half-up rule requires
1500.01. `report budget` instead returns 1500.00 and variance -1490.00 rather
than -1490.01 for a 10.00 actual. JSON, text and CSV agree on the wrong cent.
No product fix implemented.

## Reproduce

Save this synthetic `main.bean` in a fresh disposable directory:

```beancount
option "operating_currency" "USD"
2026-04-01 open Assets:Cash USD
2026-04-01 open Expenses:Food USD
2026-04-01 custom "budget" Expenses:Food "monthly" 3000.01 USD
2026-04-02 * "Actual"
  Expenses:Food 10.00 USD
  Assets:Cash -10.00 USD
2026-04-15 note Assets:Cash "End"
```

With isolated environment variables and absolute executable/file paths:

```sh
bea --json --no-input --offline --file /absolute/main.bean check
bea --json --no-input --offline --file /absolute/main.bean report budget
bea --json --no-input --offline --file /absolute/main.bean report budget --time '2026-04-01 - 2026-04-15'
bea --no-input --offline --file /absolute/main.bean report budget
bea --no-input --offline --file /absolute/main.bean report budget --format csv
```

All exit 0, stderr empty, source hashes unchanged. Check is valid. Both date
selection forms cover April 1–15 inclusive and return
`budget: "1500.00", actual: "10.00", variance: "-1490.00"`. Text prints
1,500.00 USD; CSV prints 1500.00. Correct budget is
`3000.01 * 15 / 30 = 1500.005`, half-up to **1500.01** at the ledger's
two-digit USD precision. `cli/docs/USAGE.md`'s Budgets contract explicitly
specifies daily proration with half-up rounding to that precision.

A fresh fixture/process repeats both selection forms; an Income equivalent
has the same error with earned actuals positive. Controls on the same source:
April 1–14 gives 1400.00, April 1–16 gives 1600.01 and full April gives
3000.01, all correctly. Monthly targets 1.01 and 100.01 happen to round the
half-month correctly; 0.01 becomes 0.00 instead of 0.01, and 12345.67 becomes
6172.83 instead of 6172.84. Fifteen independent whole-period comparisons
across daily/weekly/monthly/quarterly/yearly budgets and leap February, January
and April all pass, keeping the failure focused on exact halfway shares.

## Cause and repair

The inherited `cli/src/fava/modules/budgets.py::calculate_budget:176–180`
divides the budget by days in the interval separately for each day and adds
those rounded Decimal shares. Directly invoking the same parser/calculator
on this valid fixture produces **1500.004999999999999999999998**. Independent
100-digit arithmetic on `3000.01 * 15 / 30` produces exactly **1500.005**.
`bea_engine/report.py::_budget::prorated:388–391` then applies
`ROUND_HALF_UP` to the already perturbed value, putting a true tie below the
threshold. The mode is correct; the value entering it has lost the tie.

Repair the existing proration path so budget/calendar shares retain exact
halfway information through the final rounding. Reuse the current budget
parser/interval conventions rather than creating another budget engine.
Do not add a fixed epsilon that would also move legitimate near-ties across
the threshold. Preserve changes of budget within a period, per-currency
precision, ordinary partial periods and full-month cleanup; retain vendored
attribution if changing that helper.

`BudgetModule.calculate` wraps this helper and is used by `_budget`;
`calculate_budget_children` also delegates to it. The CLI has one live budget
report producer. Frontend `commands/report.py::budget` and
`report_csv.py::_budget` consume its returned amounts; no renderer-specific
rounding causes this error. Both renderers and Income were exercised.
No API/server/dependency change is indicated.

Acceptance: the public 15-day fixture gives 1500.01 budget and -1490.01

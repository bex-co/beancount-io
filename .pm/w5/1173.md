# Reports can convert only to the first operating currency: a USD + EUR ledger has no "Converted to EUR"

**Severity:** minor (multi-currency reporting). **Owner:** dashboard. **Estimate:** 45–60 minutes including tests. **A2:** a ledger that declares two operating currencies, for example a household that keeps both USD and EUR books, cannot see its Balance Sheet, Income Statement, Trial Balance, Cash Flow or account pages totalled in its second currency. The API already converts to it. Fava, which these reports follow, offers a "Converted to" choice for every operating currency. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-18 against `https://beancount.io` (entry chunk `main-LGv2TZLj.js`), headless Chromium 153 at 1440×1000, English, isolated profile, signed in as the QA owner on its disposable `qa-` ledger. Local HEAD `68056e47e`. The probe line was added and then removed: the ledger file is byte-for-byte restored and has no errors.

## Repro

1. Use a valid ledger whose options declare `option "operating_currency" "USD"` and then `option "operating_currency" "EUR"`, and which holds EUR and USD positions plus an `EUR … USD` price. GraphQL `getLedger { options { operatingCurrency } }` returns `["USD", "EUR"]`.
2. Open Balance Sheet, Income Statement or Trial Balance and open the conversion selector. **Actual:** At Cost, At Market Value, Units, Converted to USD. There is no Converted to EUR. The statement tables have only `Account | USD | Other` columns, so every EUR amount sits in Other.
3. API control on the same ledger: `getLedgerBalanceSheet(conversion: "EUR")` returns Assets `balanceChildren` with `EUR: "58352.909…"` beside unconverted `VTI`, `ETH`, `VEUR` and `QAMIRROR` units. `conversion: "USD"` returns `USD: "190858.2000"` and `VEUR: "10"`. The backend converts to either currency. Only the page's choices stop at the first one.

**Expected:** the selector offers "Converted to <currency>" for each operating currency, in the order the options declare them. Choosing EUR shows the EUR-converted report and is remembered like the other choices.

## Cause

- `dashboard/src/common/providers/ledger-provider/ledger-provider.tsx:17` keeps only `operatingCurrency[0]` as `primaryCurrency`.
- `dashboard/src/common/components/conversion-select.tsx:28` and `:56` render a single `Converted to {currency}` item for that one currency.
- `dashboard/src/features/reports/components/use-report-conversion.ts:28-37` (`resolveReportConversion`) accepts a stored conversion only when it equals that primary currency. A remembered `EUR` therefore falls back to At Cost.
- The six callers pass `currency={primaryCurrency}`: `balance-sheet-content.tsx:234`, `income-statement-content.tsx:259`, `trial-balance-content.tsx:203`, `cash-flow/index.tsx:220`, `cash-flow-content.tsx:267` and `account/index.tsx:533`.

## Fix

Owned by `dashboard`. Expose the ledger's full operating-currency list from the ledger provider, keeping `primaryCurrency` as its first entry. Let `ConversionSelect` take that list and render one "Converted to X" item per currency. Make `resolveReportConversion` accept any of them, so a stored EUR choice survives reload and SSR. The loaders' `storedReportConversion` already passes a currency through. A ledger with one operating currency, or none (USD fallback), renders exactly what it does today. No backend change is needed.

## Definition of done

- On a ledger with operating currencies USD and EUR, all six report selectors offer Converted to USD and Converted to EUR. Choosing EUR re-reads the report with `conversion=EUR`, and the choice survives a reload and a move to another report page.
- A one-operating-currency ledger shows the same four choices as today.
- Tests cover `resolveReportConversion` with a second operating currency, and `ConversionSelect` rendering one item per currency. Both fail on the current code. Dashboard gates pass.

## Adjacent, not in scope

The statement tables (`balance-sheet/hierarchy-list.tsx`) also give a column only to the primary currency and put a second operating currency under Other. Fava gives each operating currency its own column. Decide that separately once the conversion choice exists.

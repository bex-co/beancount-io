# A Journal Document row's filename is a button: ⌘/Ctrl-click replaces the Journal with the file instead of opening a new tab, and middle-click does nothing (gap in w5/1211)

**Severity:** minor. **Owner:** `dashboard`. **Estimate:** 20–30 minutes including tests. **A3:** w5/1184 gave the Journal's Document rows a control that opens the attached file. w5/1211 turned the other in-app destinations (Accounts, Overview, Holdings, the Files breadcrumb and the Documents page filename) into real links, so that a reader can open them in a new tab. Both shipped on 2026-11-23. w5/1211 was written before the Journal button existed, so that button is still a `<button>`. A reader working through a month's statements from the Journal loses their filtered list on every ⌘-click, while the same file on **Documents** opens in a new tab. **Found by:** `/qa-find-bugs-dashboard` (`dashboard-qa` routine) on 2026-11-27 against `https://beancount.io`, entry chunk `main-BBmi61Hs.js`, isolated headless Chromium 158 at 1440×1000, macOS, English. Signed in as the QA account, on its disposable `qa-` ledger, which was restored byte-for-byte afterwards. Local HEAD `a78dfb4ec`.

## Repro

Fixture: a ledger with a document directive whose file is in the repository. This run used `qa-20261127-docs/Receipt #42 (copy).txt` and `2024-03-16 document Assets:US:BofA:Checking "qa-20261127-docs/Receipt #42 (copy).txt"`.

1. Open `/journal?time=2024-03`. Under **Entry types**, turn on **Document**. The row reads `2024-03-16 · Document · Assets:US:BofA:Checking · Receipt #42 (copy).txt`. The filename is `button "Receipt #42 (copy).txt"` (title `qa-20261127-docs/Receipt #42 (copy).txt`), not a link.
2. ⌘-click the filename. No tab opens, and the current page goes to `/files/blob/main/qa-20261127-docs/Receipt%20%2342%20(copy).txt?time=2024-03`.
3. Reload the Journal and middle-click the filename. Nothing happens: no tab opens and the URL is unchanged.
4. Control: on `/documents`, ⌘-click the same filename. It is an `<a>`, and it opens `/files/blob/main/qa-20261127-docs/Receipt%20%2342%20(copy).txt` in a new tab while Documents stays where it was.

Both repeated from a fresh load.

## Cause

`dashboard/src/features/journal/components/journal-description/document-description.tsx:11-35` `DocumentFileButton` renders a `<button>` whose `onClick` calls `useFileNavigate()`, so a modifier or middle click is handled as a plain click or not at all. It is used by both Journal layouts: `journal-lines.tsx:317` and `journal-description/index.tsx:49`.

## Fix

Owned by `dashboard`. As w5/1211 did for the Documents filename, render the control as a TanStack `<Link>` to `/ledger/$ledgerOwner/$ledgerName/files/blob/$branch/$`, with `_splat` set to the document's repository path and the branch that `useFileNavigate` uses. Keep its styling, `dir="auto"`, title, focus ring and `stopPropagation`, so that it still does not open Entry Context. Keep the shared search params that `retainSearchParams` carries. A plain click and Enter must still reach the same URL as today, including names with spaces and `#`.

## Definition of done

- On the Journal and on an account page's journal, with Document shown, the filename is a link. ⌘/Ctrl-click and middle-click open the file in a new tab and leave the Journal and its filters where they were.
- A plain click and Enter still open `/files/blob/main/<encoded path>` and do not open Entry Context.
- A real-router test asserts the `href` for a nested path that contains a space and `#`, and asserts that activating the link does not open the row's Entry Context. Dashboard gates pass.

It was filed before this control existed. w5/1184 (done) added this control as a button. w21/050 (done) is the mobile account-detail rows. None covers the Journal's Document filename as a link.

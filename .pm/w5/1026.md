# Plan updates from the complete multiline transaction header

**Minor · cli · 40–60m · A1 · worker1.** On a native-valid multiline
narration or payee, `update transaction --tag classified` reports a successful
write but inserts `#classified` inside the quoted field and adds no actual
tag. Replacing the narration instead previews a malformed edit and apply
refuses it. One-line controls work. No account retarget is requested, no
posting changes, and financial amounts remain correct. No product fix
implemented.

Real local QA, 2026-10-25, clean main
`c8cefdb3b5efc39d97c0099f6265dd750988234e`, runtime identical to frozen
`22d622a67ceacb9135e400b758ad2de14f2b4112` (1,628 tracked CLI files).
Checkout `bea 0.3.1`, frontend Python 3.13.3, managed Python 3.12.10 /
Beancount 3.2.3 / Beanquery 0.2.0, macOS 26.5.1 arm64. Fresh bounded
subprocesses, closed stdin/no TTY, isolated absolute config/cache, notifier

Run `bea --json -f main.bean update transaction --id header-1 --tag classified`.
Preview exits **0**, `written: 0`, changes no bytes, but proposes:

```diff
-2024-01-02 ! "Shop
+2024-01-02 ! "Shop #classified
   receipt details" #review ^receiptA
```

Apply exits **0**, `written: 1`, and checks valid. Fresh native parsing and
JSON listing show narration **`Shop #classified\n  receipt details`** and
tags **`["review"]`**, rather than the original narration and the requested
tag. `list transaction --tag classified` returns no rows. With a multiline
payee, the same operation changes the payee to
`Merchant #classified\n  branch details` and likewise adds no tag.

For either multiline field, requesting `--narration 'Renamed shop'` previews
at exit **0**, but the planned source splices quotes into the first physical
line before its original string closes. Apply exits **1**:

```text
The change would leave the ledger invalid; nothing was written.
… Invalid token: 'Renamed'
```

The refusal correctly preserves every byte; the planner is what produced an
invalid replacement for a valid requested string. The original payee,
narration, tag/link set and memo remain after the failed apply. No invalid
ledger is committed.

## Cause and scoped repair

`cli/src/bea_engine/ledger/updating.py:414–418`, `plan_rewrite`, sends only
`lines[start - 1]` to `_edit_header` (:282–320). `_QUOTED` (:263) therefore
sees no complete first string when that field continues onto another line.
For fresh tags, `_edit_header` appends at the end of that physical line
(:309–319), still inside the string. For narration replacement, it sees
fewer spans than the field index and appends another quoted string
(:294–308), also inside the unfinished field. Preview and apply share the
same malformed plan; validation only protects the applied write.

Locate the complete logical header and its actual quoted-field/tag spans
before editing. Put tags outside the closing string, and replace the correct
narration span while retaining the payee, existing tags/links, memo, postings
and neighbors. Preserve the writer's line-count/atomicity contract; the valid
reference demonstrates it is feasible. Retain one-line edits, flag-only
updates, duplicate-tag no-ops and human/JSON behavior. No dependency or API
surface change is needed.

Dedupe: searched **5,637 board Markdown files / 44 non-done milestone
scopes**, including blocked queues, all callers and targeted history.
`f29921b65` introduces the header planner; `22d622a67` exposes the frontend.
[1025](./1025.md) owns `_edit_postings` falsely retargeting literal account
text when `--account` is requested. Here there is **no account argument**,
so that helper is never called: `_edit_header` independently loses the
header's closing quote and fails the requested tag/narration operation.
Fixing only the posting selector does not fix these cases; keep the two
narrow repairs separate. [w22/m1](../w22/m1/README.md)'s engine/frontend
tasks are completed; its remaining batch/docs/general coverage work does not
record this header-span repair. No overlapping pending fix or later main
repair was found.

Acceptance: both multiline-tag modes add the real tag once, leave both string
fields unchanged and appear in the tag filter. Both replacement modes apply
`Renamed shop` at exit 0 without changing payee or other fields. Previews
describe those valid edits and write nothing. Preserve all four controls,
native validity, money, metadata, line counts, neighbors and no-op outcomes.
Add real CLI regressions that load the final native fields and exercise the
tag filter, then run owning `make check-all` when implementing. Batch updates,
plugins, split destinations, other roots and operating systems remain
unverified for this extension. Sanitized evidence stays in ignored CLI
scratch; no product code changed.

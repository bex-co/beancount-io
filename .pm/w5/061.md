# Invalid treeify regex options report runtime failures without naming the bad option

**Minor · 25–40m · cli · A1.** A malformed tree pattern produces an unrelated
IndexError and exit 1 instead of an actionable bad-argument error. Validate
the supplied regex fragments before dispatching; keep upstream rendering.

Found 2026-10-08 at HEAD `d28674ae`, checkout bea 0.3.1, Python 3.13.3,
macOS/Darwin. Fresh bounded subprocesses, closed stdin, redirected streams,
isolated absolute config/cache, update notices disabled. No credentials,
network or hosted ledger changes needed.

## Reproduce

Create `/absolute/balances.txt`:

```text
Assets:Cash     10
Assets:Savings  20
Expenses:Food    5
```

Create `/absolute/out.txt` containing `SENTINEL` and run:

```sh
bea treeify /absolute/balances.txt -o /absolute/out.txt --pattern '['
bea treeify /absolute/balances.txt -o /absolute/out.txt --delimiter '['
bea treeify /absolute/balances.txt -o /absolute/out.txt --split '['
```

All exit **1**, empty stdout. Separate stderr messages:

```text
Error: treeify failed (exit 1): IndexError: no such group
Error: treeify failed (exit 1): re.error: unterminated character set at position 79
Error: treeify failed (exit 1): re.error: unterminated character set at position 0
```

The pattern case never identifies an invalid regex. None names which option
needs correction; the delimiter position refers to a synthesized pattern,
not the one-character input. Two pristine directory pairs reproduce each
case. Input and existing output bytes are unchanged, including the sentinel:
the existing deferred-output protection works, so this is not a data-loss bug.

Control: the same input/output with `--delimiter ' {2,}'` exits **0** and
writes the correct Assets/Cash/Savings and Expenses/Food tree. A separate
plain-text/no-column control exits **2** with a useful input diagnostic.

Expected: invalid regex option values exit **2** and name --pattern,
--delimiter or --split, the supplied value and a useful regex diagnosis.
USAGE's Exit codes table assigns bad arguments to usage/2; the command's help
advertises all three as regex inputs. treeify rejects --json by contract, so
this finding asks for normal human errors, not a new JSON output surface.

## Cause, fix and dedupe

`cli/src/cli/commands/treeify.py:80–101` mirrors upstream option parsing to
guard the output destination but forwards regex values without validation.
`launch.check_native` at line 110 wraps upstream's exception as a runtime
failure. Installed `beancount/tools/treeify.py:59` combines the pattern and
delimiter into `({pattern})(?P<ws>{delimiter}.|$)`. The unclosed character
class can consume the wrapper's syntax, so `find_column` later asks for a
group that no longer exists. The resulting IndexError obscures the input typo.

Compile each explicitly supplied regex fragment using Python's regex engine
after successful mirror parsing and before launching upstream. Convert a
compile error to UsageError naming its actual flag/value and input-relative
position. Preserve help, valid regexes, native option aliases/clusters,
source/output alias guards and write-only-after-success behavior. Add real CLI
regressions for all three malformed values, valid/default controls and output
preservation; run make check-all inside cli when implementing. No dependency,
backend/API change or replacement tree-rendering algorithm is needed.

Caller search found the sole registered treeify handler and the existing
mirror parser/forwarder; file and stdin input, stdout/export destinations use
that handler. Only file input/export and long flags were reproduced. Stdin,
short aliases, --filenames/--loose-accounts and other platforms remain
unverified; check override precedence before validating ignored values.

Full-board/history search for treeify regexes, patterns, delimiters, split and
IndexError found no matching open item. Completed w1/m22 exposes native help,
w1/m25 wraps failures, w1/084 preserves output on failure, and w1/141 guards
clustered/abbreviated output paths; their protections still work here.
Current treeify history has no regex-validation step. The upstream exception
is not itself a requested upstream fork: this is CLI argument diagnosis and
the repo's documented exit category.

Acceptance: exact malformed inputs exit 2 with their own option named, no
unrelated IndexError or synthesized position; existing source/output contents
remain intact; default and valid custom tree renders still succeed.

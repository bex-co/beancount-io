# Files: a missing file's page has no h1 (only an h2 with the path) and an unavailable branch's page has no heading at all, though a missing folder's page has one (gap in w3/485)

**Severity:** minor (accessibility; WCAG 1.3.1, 2.4.6). **Owner:** `dashboard`. **Estimate:** 20–30 minutes including tests. **A2:** a screen-reader user who follows a stale link to a renamed file or an old branch lands on a page whose heading list is empty or starts at level 2, so heading navigation does not say what happened. **Found by:** `/qa-find-bugs-dashboard` (`dashboard-qa` routine) on 2026-11-26 against `https://beancount.io`, production entry chunk `main-BBmi61Hs.js`. QA-owned headless Chromium 158, fresh isolated context, signed out, 1440×1000, English. Read-only. Local HEAD `d5e0d2bdd`.

## Repro

Public ledger, no sign-in needed. All under `/ledger/open_ledger/example`.

| Route | HTTP | Headings on the page | Its way out |
| --- | --- | --- | --- |
| `/files/tree/main/nofolder` (control) | 404 | `h1` "Folder not found: nofolder" | link "Browse parent directory" |
| `/files/blob/main/nope.bean` | 404 | only `h2` "nope.bean" | **button** "Browse parent directory" |
| `/files/tree/nobranch` | 404 | **none** | link "Browse files on main" |
| `/files/blob/nobranch/main.bean` | 404 | **none** | link "Browse files on main" |
| `/files/tree/nobranch/sub` | 404 | **none** | link "Browse files on main" |

The missing-file page's message, "File not found: nope.bean", is a plain paragraph under the `h2`. Its "Browse parent directory" is a `<button>` that navigates in script, so it cannot be opened in a new tab or copied as a link, while the folder page's control with the same name is a real link.

## Cause

- w3/485 gave every directory view one `h1`, and w5/1152 gave the missing-folder 404 its `h1` (`dashboard/src/features/ledger-editor/directory-browse/not-found.tsx:21-23`). The file and branch 404s were not part of either.
- `FileNotFoundView` (`features/ledger-editor/file-editor/components/ledger-file-view/file-loading-error-views.tsx:69-96`) renders the path as an `h2` (`:76`) and the message as a `<p>`, with `<Button type="button" onClick={onBrowseParent}>` (`:85`). It is the blob route's 404 (`file-editor/not-found.tsx:27`) and the file view's settled-null state (`ledger-file-view/index.tsx:352`).
- `BranchNotFound` (`features/ledger-editor/shared/components/branch-not-found.tsx:28-46`) has an icon, a `<p>` and a link, and no heading; both the tree and the blob route use it.
- The same file's `FileLoadingView` and `FileErrorView` (`:25`, `:48`) also head the page with an `h2`, so the file view has no `h1` while it loads or after a failed read, unlike its loaded state ("Files › README.md").

## Fix

- Make the missing-file page's heading an `h1` that says what happened, as the folder 404 does: `h1` "File not found: nope.bean" (drop the separate path heading or keep it as the breadcrumb), and render "Browse parent directory" as a `<Link>` to the parent tree URL, as `DirectoryNotFoundView` does.
- Give `BranchNotFound` an `h1` carrying its message ("Branch “nobranch” isn't available here…") or a short heading above it.
- Raise `FileLoadingView` and `FileErrorView`'s path heading to `h1`, so the file view has exactly one `h1` in every state.
- Tests: render the blob 404, a branch 404 and the loading view and assert exactly one `h1` with the expected text, and that "Browse parent directory" is a link to `/files/tree/main/<parent>`. The h1 assertions fail on the current code.

## Definition of done

On production, each 404 route in the table above has exactly one `h1` naming what is missing, the missing-file page's "Browse parent directory" is a link, and the folder 404 is unchanged. Dashboard gates pass.

## Blast radius

`FileNotFoundView`, `FileLoadingView` and `FileErrorView` are used only by the file view and the blob 404; `BranchNotFound` by the tree and blob 404s. Other ledger 404s were checked and have an `h1`: account (`No account named … in this ledger.`), entry, commit and pull request (`404`), unknown user (`User not found`).

## Dedupe

Searched `.pm/**`, including `done/` and `blocked/`, for `FileNotFoundView`, `BranchNotFound`, `branch-not-found`, "File not found" and Files headings. w3/485 (done) covers directory views only; w3/629 (done) made the missing file a 404 and kept this view; w4/281 (done) added the branch 404; w5/1152 (done) the folder 404 with its `h1`. `main` still renders the `h2` and the heading-less branch page, so this is not deployment lag.

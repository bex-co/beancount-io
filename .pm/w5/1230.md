# Add Budget, Update Budget and Smart Import flag the reader's own write as "Out of date", and leave the other ledger pages showing the ledger from before it (gap in w3/650 and w1/185)

**Severity:** minor. Nothing is lost, but within 30 seconds of a successful save the header raises the orange **Out of date — click to refresh** button for a change the reader just made themselves. Pages they visited earlier in the session keep the pre-write numbers until a reload. **Owner:** `dashboard`. **Estimate:** 30–45 minutes including tests. **A2:** w3/650 fixed this false alarm for file saves because "a false 'out of date' after every save reads as data loss to a new user". Setting a first budget and importing a first CSV are two of the first writes a newcomer makes. **Found by:** `/qa-find-bugs-dashboard` (`dashboard-qa` routine) on 2026-11-27 against `https://beancount.io`, production entry chunk `main-BBmi61Hs.js`. QA-owned headless Chromium 158, isolated context, 1440×1000, English, signed in as the QA owner of the disposable `<qa-owner>/mcp-agent-eval` ledger. Local HEAD `2cbf9a141`. Every probe write was removed afterwards: `main.bean` is byte-for-byte restored (blob `f1a0b83c` again) and the ledger has no errors.

## Repro

Synthetic ledger owned by the reader, USD, with `Expenses:Food:Groceries` and `Assets:Cash` open. During each run, check `listCommits` to confirm that the only new commit is the reader's own.

1. Open `/budget` fresh. No **Out of date** button. Choose **Add Your First Budget** (or **Update Budget** on an existing card), enter `2026-07-01 · Expenses:Food:Groceries · Monthly · 200 USD`, and save. `BulkEntries` answers `success: true`, and the card appears.
2. Watch the header. The only request after the write is `GetLedgerJournal`. At the next 30-second poll, `GetLatestLedgerCommit` returns the reader's own commit, and **Out of date — click to refresh** appears with its orange dot. In two timed runs it appeared 8 s and 23 s after the save, and it was already showing in the first, untimed run's screenshot. The latest commit was the budget commit each time (`Add 2026-07-01 custom budget Expenses:Food:Groceries`).
3. Open `/statistics` fresh. **Entries Count by Type** reads `Custom 1`. Go to Budget through the sidebar, **Update Budget** with `2026-08-01 · 250 USD`, save, then return to Statistics through the sidebar. It still reads `Custom 1` and `Entries: 30`, and no Statistics query is sent (only `GetCurrentUser`). `getLedgerEntriesCountPerType` answers `Custom 2` (31 entries).
4. Smart Import: upload a one-row CSV (`Date,Payee,Description,Amount` / `2026-08-30,<payee>,<narration>,-1.23`), pick a source and a target account, and choose **Import 1 Transaction**. The only requests are `BulkEntries` and `GetLedgerErrors`. Choose **View Journal**: the row is there, and **Out of date** appears within 10 s. The only new commit is the import.

Control on the same build: **Delete** on a budget target sends `DeleteLedgerEntrySourceSlice`, then refetches `GetLatestLedgerCommit`, `GetLedgerJournal`, `GetLedgerEntriesCountPerType`, `GetLedgerErrors`, `GetLedgerEvents`, `GetLedgerAccounts` and the other ledger reads. **Out of date** never appears in the 45 s after it. Deleting the imported row from Entry Context also left no **Out of date**.

## Cause

- `useLedgerWriteRefresh` (`dashboard/src/common/hooks/use-apollo-cache.ts:57`) drops every ledger read except the account fields and ticks `cacheClears`. The Out of date indicator re-baselines its commit only on that tick (`common/components/ledger-layout/ledger-out-of-date-indicator.tsx:46`, from w3/650). The writers that call it are fine: New Entry, Entry Context, Accounts, Delete Budget, and file create, save and delete.
- Four ledger writers never call it:
  - `features/ledger-data/budget/add-budget-dialog.tsx:204-214` (Add Budget, and **Update Budget**, which is the same dialog) refetches only `GetLedgerJournalDocument`. It has refreshed only its own list since the dashboard was imported (`af5339de0`, reshaped in `292a4321b`).
  - `features/importer/hooks/use-import-submit.ts:105-126` (Smart Import) only calls `writeOutcome.report`, which re-reads the errors.
  - `features/receipt/hooks/use-receipt-workflow.ts:196-200` (Upload Receipt, `insertReceiptTransaction`) does not refresh at all.
  - `features/plaid/hooks/use-plaid-accounts.ts:240` with `components/transaction-review-table.tsx:244` (Bank Sync's "add to ledger", `SubmitPlaidTransactionsToLedger`) refetches only the unsynced-transactions list.
- w3/650's fix covered "every write path that already clears the cache". w1/185 then moved the clearing writers to `useLedgerWriteRefresh` and wrote "every ledger write". These four never cleared the cache, so neither change reached them, and `dashboard/AGENTS.md`'s list (an entry, New Entry, an account, a budget delete, a file save or delete) omits them.

## Fix

- Call `useLedgerWriteRefresh()` once each write succeeds: Add/Update Budget (in place of the journal-only `refetchQueries`; the w4/m41 rule still holds, so a failed refetch never turns the saved budget into a failure), Smart Import, Upload Receipt and Bank Sync's submit. Keep each caller's own follow-up: the budget focus handling, `writeOutcome.report`, and Bank Sync's unsynced-list refetch.
- Add these writers to the `useLedgerWriteRefresh` sentence in `dashboard/AGENTS.md`.
- Tests: for Add Budget and Smart Import (and the receipt hook if cheap), a successful write ticks `cacheClears` and drops a ledger read such as `getLedgerEntriesCountPerType`, while `userProfile` stays cached. The two must fail on the current code. Extend `refresh-keeps-drafts.test.tsx` or the indicator test with "an Add Budget save does not raise Out of date", next to the existing file-save case. A commit from elsewhere must still raise it.

## Definition of done

- On production, on a disposable ledger: after Add Budget, Update Budget and a one-row Smart Import, **Out of date** stays hidden for at least 60 s when no other commit lands, and Statistics reached through the sidebar shows the new `Custom` and `Transaction` counts without a reload.
- A commit made elsewhere (for example through the API) still raises **Out of date**.
- Dashboard gates (`yarn format:check`, `yarn lint`, `yarn test`, `yarn build`) pass.

## Blast radius

Searched every `useMutation` caller in `dashboard/src`. Ledger writers that already refresh correctly: `new-directive-dialog/index.tsx`, `entry-context-panel.tsx`, `accounts/index.tsx` (open, close, delete), `delete-budget-dialog.tsx`, `create-file/index.tsx` and `ledger-file-view/index.tsx`. The four above do not refresh. The PR review page's merge refetches only its own query. It was not exercised, so check it while there.

## Dedupe

Searched `.pm/**`, including `done/` and `blocked/`, for Out of date, `useLedgerWriteRefresh`, `cacheClears`, stale after a write, Add Budget and Smart Import. w3/650 (done) is the same symptom for file saves. w1/185 (done) moved the writers that cleared the cache onto the keep-list refresh. w4/m46 (done) keeps drafts through a refresh. w5/1129 (blocked) is a different Budget chart limit. No open item covers these writers, and `main` is unchanged, so this is not deployment lag.

**Unverified:** Upload Receipt and Bank Sync were read in the code but not run, because parsing a receipt spends shared AI quota and Bank Sync needs a bank connection. Other pages left stale after the write (Overview, Files, Version History) were not checked one by one: they share the same cache and the same missing refresh.

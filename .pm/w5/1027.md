# Reject duplicate columns in batch-update CSV mappings

**Minor · cli · 20–35m · A1 · worker1.** A CSV update mapping can repeat
`id`, `account` or `flag` with conflicting cell values. Preview accepts it,
silently keeps the last cell and offers one ready row; apply writes that
interpretation without an ambiguity warning. A duplicate id can select the
second transaction, and duplicate account columns can choose the second
category. Equivalent duplicate JSON keys are already refused. The input is
ambiguous: the expected fix is refusal, not choosing its first value.
No product fix implemented.

## Cause and scoped repair

`cli/src/cli/commands/update.py:254–286`, `_rows_from_csv`, trims headers
(:268), checks whether names are allowed (:269–274) and requires `id`
(:275–276), but never checks uniqueness. The dict comprehension at **:282**
therefore assigns each repeated key again; only the last nonempty cell
survives. `_load_mapping` (:289–300) sends that already lossy dict to the
engine. The selected row is internally valid, so the normal planner and
native validation cannot discover the discarded values.

The JSON branch uses `_unique_keys` (:169–176) through
`json.loads(..., object_pairs_hook=_unique_keys)` (:240), explicitly preventing
the same last-value loss. Reject duplicates after CSV header trimming and
before mapping any rows, using the existing usage-error style. Preserve field
order flexibility, blank-cell behavior, valid partial updates and the current
JSON/unknown-header refusals. No dependency, API or engine fork is needed.

Dedupe: searched **5,638 board Markdown files / 44 non-done milestone
scopes**, including blocked queues, all callers and targeted history.
`62c0e1910` introduces this independent CSV reader. Completed
[758](./done/758.md) handles repeated/duplicate headers in bank-statement
imports, whose parser already refuses ambiguous column names; it does not
serve update mappings. [w22/m1](../w22/done/m1/README.md)'s batch task t004 is done;
remaining docs/general coverage does not record this mapping-header repair.
[1025](./1025.md) and [1026](./1026.md) concern source posting/header edits
after parsing, not input-column selection. No overlapping pending fix or
later main repair was found. Keep these as separate input-validation work.

Acceptance: all four affected modes refuse both preview and apply at exit 2,
with a duplicate-header remedy and unchanged ledger/native values. Preserve
all unique CSV/JSON outcomes and existing JSON-duplicate/unknown-column
refusals. Add real CLI regressions for id/account/flag duplicates and trimmed
names, checking file effects and native transaction selection, then run owning
`make check-all` when implementing. Stdin, other encodings/delimiters, include
destinations and other operating systems remain unverified for these
duplicates. Sanitized evidence remains in ignored CLI scratch; no product
code changed.

# Include bank identity in remembered OFX account mappings

**Major · cli · 35–50m · A1 · worker1.** Two banks can issue the same account
number. OFX import remembers only `ACCTID`, so bank B inherits bank A's ledger
account, and explicitly mapping B overwrites A's mapping. A later A statement
then writes to B's ledger account at exit 0. The books remain valid and total
assets still add up; individual bank balances are wrong. No product fix implemented.

## Standalone reproduction

Put checkout `bea` on PATH, save as `recipe.py`, and run:

```sh
python3 recipe.py /absolute/unused/book rebind-bank-collision json /absolute/managed-engine/bin/python
```

`unbound-bank-collision` covers a bank that has never been mapped.
`same-account-control` and `distinct-account-control` are working controls.
Repeat in another unused directory with `human`. OFX includes normal sign-on,
statement status and closing-balance aggregates. `results.json` contains
arguments, safe environment, streams, exits, durations, hashes, native graphs
and snapshots of the run's own remembered OFX records. No ignored evidence
file is required.

Both banks use `ACCTID 00012345`, `ACCTTYPE CHECKING`, USD; their BANKIDs are
**111000025** and **222000118**. All tags are uppercase, the identifiers are
plain A1/B1/A2, and every imported transaction has a distinct FITID.

In `rebind-bank-collision`:

1. First bank: explicitly choose `Assets:Checking`; preview/apply its 10 USD
   payment. Checking **90**, Savings **200**.
2. Second bank: explicitly choose `Assets:Savings`; preview/apply its 20 USD
   payment. Checking **90**, Savings **180**. Both choices were supplied.
3. First bank's next file: omit `--account`, as the documented remembered
   workflow permits. Preview selects **Assets:Savings**, `ready: 1`; apply
   exits **0**, writes 1, and puts A2's 5 USD payment in Savings.

Native final: **Checking 90 / Savings 175**, instead of **85 / 180**.
Three transactions, amounts and expense **35 USD** are correct, total net
worth **265** is correct, and check passes. The error is the source account
of A2, which independent native loading and BQL both confirm. Human output
also selects Savings and succeeds; there is no mismatched-bank refusal.

The saved record after step 2 has one entry:

```json
{"accounts":[{"acctid":"00012345","account":"Assets:Savings","rules":null,
"default_account":"Expenses:Food","source":"second.ofx"}]}
```

Bank A's explicit binding was replaced. `unbound-bank-collision` shows the
other failure: after mapping only A, a new B statement without `--account`
previews/applies into Checking at exit 0 (Checking **70**, Savings **200**).
Expected: refuse at usage exit **2** and require B's ledger account before
writing; keep the original Checking **90**, Savings **200**. An account number
alone does not establish that B is A. OFX defines bank account identity using
the account aggregate, including its bank identifier and account details.
[OFX Banking 2.3, §§3.1.1 and 11.3.1](https://financialdataexchange.org/wp-content/uploads/2025/12/OFX-Banking-Specification-v2.3.pdf#page=203).

The exact public recipe ran **8 fresh cases / 88 CLI commands / 16 independent
uncached native loads**, **4 affected / 4 controls**, including **12 human

No real bank, account connection, credentials or user ledger is involved.

Controls: the same full bank/account identity under a new filename correctly
recalls Checking (70 / 200 after two payments). When A and B have different
ACCTIDs, both explicit bindings survive and A's return correctly posts to
Checking (85 / 180). Requiring the source account for an unknown ACCTID also
works in the pilot. Preserve these controls and the normal flag-free workflow.

`cli/src/cli/commands/import_.py:315–323`, `_ofx_acctids`, extracts only
ACCTID. `_find_ofx_entry:607–615` compares only `entry['acctid']`;
`_recall_ofx:754–757` uses it to choose the source account.
`_remember_ofx:878–890` removes every old entry with that same acctid before
adding the new mapping. BANKID is never retained or compared. All imports
are sequential, so this is deterministic key collision, not a file-lock race.

Caller search also covers dispatch identity selection (:1292), prior-settings
lookup (:1773), and successful memory persistence (:1965). The engine then
receives the wrong `--account`; its validated postings are internally sound.
Use a canonical source-account identity that retains the bank/account
aggregate's required discriminators before lookup and replacement. Keep
frontend/engine boundaries and existing parsing helpers; no new dependency
is needed. Legacy ACCTID-only memory cannot prove which bank issued it:
require explicit account binding where that cannot be recovered reliably.
Keep CSV and Python-importer settings separate and preserve per-account rules.

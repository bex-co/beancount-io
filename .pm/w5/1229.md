# Holdings column headers are English in every language: German, Japanese, Persian and Russian readers get "Book Value", "Market Value", "Unrealized Profit (%)", "Acquisition Date" under a translated page

**Severity:** minor (localization/accessibility). Nothing is computed wrongly, but the one table on the page reads in a different language from the title, tabs, count and buttons around it, and screen readers hear raw lower-case identifiers. **Owner:** `dashboard`. **Estimate:** 30–45 minutes including tests. **A2:** a newcomer reading the dashboard in their own language opens Holdings to see what they own and what it is worth, and the eight column names that say which number is which are the only English on the page. **Found by:** `/qa-find-bugs-dashboard` (`dashboard-qa` routine) on 2026-11-27 against `https://beancount.io`, production entry chunk `main-BBmi61Hs.js`. QA-owned headless Chromium 158, isolated contexts, 1440×1000 and 390×844. Reproduced signed in and in a fresh signed-out context. Read-only on the public ledger. Local HEAD `930518f53`.

## Repro

Public ledger, no sign-in needed. Pick the language with `?lang=`.

1. Open `/ledger/open_ledger/example/holdings?lang=de`. The heading is **Bestände**, the tabs are **Bestände / Bestände nach Konto / Bestände nach Währung / Bestände nach Kostenwährung**, the badge reads **Ergebnisse 115 Zeilen** and the button **CSV exportieren**. The table header reads **Account · Units · Cost · Price · Book Value · Market Value · Unrealized Profit (%) · Acquisition Date**.
2. Select each of the other three tabs (`?view=by-account`, `by-currency`, `by-cost-currency`). Their headers are the same English words, plus **Average Cost** on By Currency.
3. Repeat with `?lang=fr`, `ja`, `fa` and `ru`. Every view in every one of them shows the same English headers (Persian right-aligned, still English).
4. Read the header cells' accessible names: `account`, `units`, `book value`, `market value`, `unrealized profit (%)`, `acquisition date`, all lower case in every language, English included. The capital letters on screen come only from CSS.

Control on the same build: Statistics in German heads its tables **Konto · Anzahl** and **Konto · Datum des letzten Eintrags · Saldo**, Accounts reads **Konto · Eröffnungsdatum · Buchungen · Saldo · Aktionen**, and the Journal **Datum · Kennzeichen · Eintrag · Konto · Betrag**.

## Cause

- The Holdings table has no header strings of its own. It renders the column aliases of the dashboard's own BQL statements (`dashboard/src/features/ledger-data/holdings/holdings-statement.ts`: `account`, `units`, `cost`, `price`, `book_value`, `market_value`, `unrealized_profit_pct`, `acquisition_date`, `average_cost`), as returned in `queryShell.table.types[].name` (`holdings-table.tsx:159,184`).
- `formatColumnHeader` (`holdings-table.tsx:61-63`) turns `_pct` into ` (%)` and `_` into spaces, and the header cell's `capitalize` class (`:243`) title-cases the result on screen (`:239-248`). Both were added in `c546b4ce6` (2026-11-22) to replace the raw snake_case headers. That made the headers UI labels, but in English only: none of them is a catalog message.
- `src/test/no-untranslated-user-facing-strings.test.ts` and the locale tests cannot see these labels, because they are built at run time from query aliases rather than written as literals.

## Fix

- Map each known Holdings column alias to a translated label: `account` and `units` can reuse `common.account` and `common.units`, and the rest need keys such as `page.holdings.column.cost`, `.price`, `.bookValue`, `.marketValue`, `.unrealizedProfitPct`, `.acquisitionDate` and `.averageCost`, with real translations in all 15 catalogs (`yarn i18n:prepare`). Render the label as the header text and accessible name, and drop the CSS `capitalize`, which would also mis-case translated phrases. Keep `formatColumnHeader` only as the fallback for an alias the map does not know.
- Leave the CSV export's header row as the machine-readable aliases (`book_value`, `unrealized_profit_pct`), as the statement CSV exports keep `account_label` and the other snake_case keys. Leave cell values raw: w2/119 keeps Holdings and BQL numbers as raw query output by design.
- Tests: a rendered Holdings table in German (or another non-English language) shows the translated header for every column of all four statements, and its column headers' accessible names are those labels. It fails on the current code. English keeps today's visible words.

## Definition of done

- On production, `/ledger/open_ledger/example/holdings?lang=de` and its three other views show German column headers, and `?lang=ja`, `fa` and `ru` show headers in their languages. In English the headers read as today, and their accessible names are capitalized like the visible text.
- **CSV exportieren** still downloads the same snake_case header row.
- Dashboard gates (`yarn format:check`, `yarn lint`, `yarn test`, `yarn build`) pass.

## Blast radius

`DatasetTable` (`holdings-table.tsx`) has one caller, `features/ledger-data/holdings/index.tsx`, with the four statements. The Query page also renders BQL column names, but there the reader writes the query and its aliases, so those stay as typed.

## Adjacent, not in scope

- Holdings amounts and percentages stay in query notation in every language (`2754.06 USD`, `49.14` in German where Statistics writes `2.754,06 USD`). w2/119 scoped Holdings and BQL out as raw query output by design. Revisit that separately if wanted.

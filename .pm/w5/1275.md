# A ledger's README breaks every paragraph at its source line ends: the Overview and Files show Anthropic's notes as ragged short lines ("every / income statement… reconciles to / the filed totals"), where GitHub and Gitea reflow them

**Severity:** minor (readability of public showcase pages). **Owner:** `dashboard`. **Estimate:** 25–40 minutes including a renderer test. **A3:** the Open Ledger company ledgers are public, indexed pages. Their README is what the Overview opens on for a public reader. Almost all of them hard-wrap their prose at about 80 columns, as Markdown files usually do, so their notes read as a column of uneven lines on a wide card and as a jagged list on a phone. **Found by:** `/qa-find-bugs-dashboard` (`dashboard-qa` routine) on 2026-11-28 against `https://beancount.io`, production entry chunk `main-BBmi61Hs.js`, local HEAD `4b8a920fe`. Isolated headless Chromium 158 at 1440×1000 and 390×844, English, signed in (the same render is served to signed-out readers). Public ledgers only; nothing written.

## Repro

1. Open `/ledger/open_ledger/anthropic` at 1440×1000 and scroll to the README card. In `README.md`, the paragraph "Zero output from `bean-check` means the ledger is internally consistent: every / income statement sums to zero and every balance-sheet snapshot reconciles to / the filed totals. …" is five source lines. It renders as a `<p>` that is 1,104 px wide with **4 `<br>`** elements. Each line stops at its source line end, and the right half of the card is empty.
2. Open `/ledger/open_ledger/anthropic/files/tree/main` at 390×844. The same paragraph in the folder's README card wraps each source line and then breaks it: "…consistent: every" / "income statement sums to zero and every" / "balance-sheet snapshot reconciles to" / "the filed totals. …" / "calendar year; income is a" / "credit, so…".
3. Other paragraphs on the same card do the same. "Methodology → Income statement" has 2 `<br>`, "Additional accounts" 7, "Found a figure…" 2, and "Open Ledger is a growing library…" 4.

Scale: counting soft line breaks outside code fences in the root `README.md` gives anthropic 30, nvidia 48, airbnb 34, fedex 21, and alphabet, apple and minimax 14 each. The example ledgers (`example`, `real-estate-example`) have none, which is why they look right.

## Cause

`dashboard/src/common/components/markdown-renderer.tsx:3,342` always runs `remark-breaks`, which turns every soft line break into `<br>`. That is the convention for chat and comments. For Markdown *documents*, GitHub and Gitea (the ledger's own git host, with `ENABLE_HARD_LINE_BREAK_IN_DOCUMENTS` off by default) follow CommonMark and render a soft break as a space. `ReadmeCard` (`common/components/readme-card.tsx:118-122`) passes `source={{ ledgerId, path }}` for a file-backed document, but the plugin list does not depend on it. `ReadmeCard` serves the Overview (`features/reports/overview/index.tsx:564`) and every folder view in Files (`features/ledger-editor/directory-browse/components/ledger-directory-view.tsx:359`).

## Fix

- In `MarkdownRenderer`, apply `remark-breaks` only to non-document Markdown. Either leave it out when `source` is set, or add an explicit `breaks` prop (default `true`) and have `ReadmeCard` pass `false`. A file-backed README then renders soft breaks as spaces, as GitHub/Gitea do. It keeps hard breaks that the author wrote (two trailing spaces or a trailing backslash), code blocks, list items and blank-line paragraph breaks.
- Ask Beancount.io messages (`features/ai-agent/pages/agent/agent-message-list/agent-message-list.tsx:208`) keep `remark-breaks`, so typed line breaks in a chat still show.
- Test: a `markdown-renderer` test that renders `"one\ntwo"` with a `source` and asserts one paragraph with no `<br>`. A second renders `"one  \ntwo"` with a `source` and asserts that the authored hard break stays. A third renders `"one\ntwo"` without a `source` and asserts the `<br>` is kept. The first fails on current code.

## Definition of done

On `/ledger/open_ledger/anthropic` and its `/files/tree/main`, at 1440 and 390 px, the README's prose paragraphs reflow to the card width with no `<br>` from soft line breaks. Fenced code ("uvx --from beanquery bean-query main.bean \ …") and lists keep their lines. A chat answer with single newlines still shows them. Dashboard gates pass.

## Blast radius

`MarkdownRenderer` has two callers: `ReadmeCard` (Overview and every Files folder with a README, for owners, collaborators and public readers, server-rendered for public ledgers through `load-public-readme.ts`) and the agent message list. The file blob view shows Markdown as source text and is unaffected. The mobile app does not render ledger READMEs through this component and was not checked.

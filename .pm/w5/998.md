# Recognize manually reordered lots in multi-fill import matching

**Major · cli · 45–60m · A1.** A valid manual sale whose thirteen lot
reductions are arranged by unit cost is imported a second time under default
policy. The identical financial sale in acquisition order is correctly a
possible duplicate. This is residual scope after completed [977](./done/977.md):
its consecutive-run fix is present and its original acceptance cases pass.
No product fix implemented.

`bea 0.3.1`, macOS 26.5.1 arm64, frontend Python 3.13.3, managed
Python 3.12.10 / Beancount 3.2.3. The current checkout supplies frontend and

isolated config/cache directories. These are ordinary synthetic lot quantities;

Run this self-contained recipe with `bea` on PATH and a fresh absolute scratch
directory. Thirteen purchases have quantities 1, 2, 4, …, 4096, distinct dates,
and alternating unit costs. The manual sale explicitly names every selected
lot but sorts its postings by cost. The statement represents the same sale as
two FIFO fills of 63 and 8128 shares. The separate reference book contains that
statement instead of the manual sale, and independently books to the same
balances. A later reserve lot leaves enough stock for an erroneous second sale
to validate. Source stock quantities and sale price are explicit; the gain is
normally inferred.

```python
from pathlib import Path
import datetime as dt, hashlib, json, os, subprocess, time

case = Path('/abs/manual-lot-order-case')
mode = 'cost-order'  # chronological, twelve, or one-fill are working controls
human_apply = False
case.mkdir(parents=True, exist_ok=False)
ledger = case / 'main.bean'
count = 12 if mode == 'twelve' else 13
lots = [dict(qty=2**i, cost=10+i//2 if i%2 == 0 else 20+i//2,
             date=dt.date(2023,1,2)+dt.timedelta(days=i)) for i in range(count)]
quantity = sum(x['qty'] for x in lots)
basis = sum(x['qty']*x['cost'] for x in lots)
parts = [quantity] if mode == 'one-fill' else [63, quantity-63]
base = 'option "operating_currency" "USD"\n2023-01-01 open Assets:Cash USD\n2023-01-01 open Assets:Stock HOOL "FIFO"\n2023-01-01 open Equity:Opening USD\n2023-01-01 open Income:Gains USD\n2023-01-01 * "Capital"\n  Assets:Cash 500000.00 USD\n  Equity:Opening -500000.00 USD\n'
for x in lots:
    base += (f'{x["date"]} * "Buy"\n  Assets:Stock {x["qty"]} HOOL {{{x["cost"]} USD}}\n'
             f'  Assets:Cash -{x["qty"]*x["cost"]}.00 USD\n')
reserve = dt.date(2023,1,2)+dt.timedelta(days=count)
base += (f'{reserve} * "Reserve"\n  Assets:Stock {quantity} HOOL {{10 USD}}\n'
         f'  Assets:Cash -{quantity*10}.00 USD\n2024-02-01 price HOOL 30 USD\n')
chosen = lots if mode == 'chronological' else sorted(lots, key=lambda x:x['cost'])
manual = ('2024-02-01 * "Sale"\n'
          + ''.join(f'  Assets:Stock -{x["qty"]} HOOL {{{x["cost"]} USD, {x["date"]}}} @ 30 USD\n' for x in chosen)
          + f'  Assets:Cash {quantity*30}.00 USD\n  Income:Gains -{quantity*30-basis}.00 USD\n')
sale = ('2024-02-01 * "Sale"\n'
        + ''.join(f'  Assets:Stock -{q} HOOL {{USD}} @ 30 USD\n' for q in parts)
        + f'  Assets:Cash {quantity*30}.00 USD\n  Income:Gains\n')
ledger.write_text(base+manual)
original = case / 'manual-original.bean'; original.write_text(base+manual)
reference = case / 'source-reference.bean'; reference.write_text(base+sale)
statement = case / 'sale.statement'; statement.write_text(sale)
config = case / 'importer.py'
config.write_text('from beancount.parser import parser\nclass Broker:\n    name="local-broker"\n    def identify(self,file): return str(file).endswith(".statement")\n    def account(self,file): return "Assets:Stock"\n    def extract(self,file,existing_entries=None):\n        entries,errors,_=parser.parse_file(str(file))\n        assert not errors,errors\n        return entries\nCONFIG=[Broker()]\n')
fixed = {p:p.read_bytes() for p in (original,reference,statement,config)}
initial = ledger.read_bytes()
env = os.environ.copy()
for key in ('BEA_FILE','BEA_TOKEN','BEANCOUNT_LOAD_CACHE_FILENAME','BEA_ENGINE_PYTHON','BEA_ENGINE_DIR'):
    env.pop(key,None)
overrides = dict(BEA_CONFIG_DIR=str(case/'config'), XDG_CACHE_HOME=str(case/'cache'), BEA_NO_UPDATE_NOTIFIER='1')
env.update(overrides)
def run(tag,args,target=ledger,json_mode=True):
    argv = ['bea', *(['--json'] if json_mode else []), '--no-input','-f',str(target),*map(str,args)]
    before = ledger.read_bytes(); start = time.monotonic()
    result = subprocess.run(argv,cwd=case,env=env,stdin=subprocess.DEVNULL,capture_output=True,text=True,timeout=25)
    print(json.dumps(dict(tag=tag,args=argv,cwd=str(case),env=overrides,stdin_mode='DEVNULL',tty=False,
                         exit=result.returncode,stdout=result.stdout,stderr=result.stderr,
                         duration=time.monotonic()-start,ledger_changed=ledger.read_bytes()!=before,
                         prefix_preserved=ledger.read_bytes().startswith(initial),
                         inputs_preserved=all(p.read_bytes()==b for p,b in fixed.items()),
                         input_sha256={p.name:hashlib.sha256(p.read_bytes()).hexdigest() for p in fixed})),flush=True)
query = ['query','SELECT account,sum(number) GROUP BY account ORDER BY account']
args = ['import',statement,'--config',config]
run('baseline',['check']); run('baseline-facts',query)
run('reference-check',['check'],reference); run('reference-facts',query,reference)
run('preview',args); run('default-apply',[*args,'--apply'],json_mode=not human_apply)
run('facts',query)
run('sheet',['report','balance-sheet','--time','2024-02','--conversion','at_cost'])
run('skip-repeat',[*args,'--duplicates','skip','--apply']); run('check',['check'])
```

Root cause: `cli/src/bea_engine/importing.py:1647–1698`, `_booked_for`, tries
only consecutive runs when there are more than twelve compatible booked
legs. `_legs` preserves the manual posting order. Here that order is
`1,4,16,64,256,1024,4096,2,8,32,128,512,2048`; the correct 63-share subset
`1,2,4,8,16,32` is not consecutive, nor is its 8128-share complement. Actual
helper proof finds no candidate for either fill even though these disjoint
subsets exactly cover the booked sale. Reordering the same booked legs by
acquisition date makes the actual `_legs_agree` succeed. `_possible_twin`
(at line 3180) consequently rejects the real twin, and default apply proceeds.
Twelve lots use the complete subset branch; one fill matches the whole run.
All incoming per-unit costs are open, so this does not depend on the former
known-cost early return repaired by 978 or opposite-direction matching in 979.

Caller search: `_legs_agree` also serves `_nearest`, native stable-ID checks,
legacy/generated-ID claims, and `_transfer_legs_agree`. Runtime evidence for
this finding is the hand-entered possible-twin path. Preserve owner/account,
unit/price and stated lot compatibility, one-use assignment, native correction

partitions independently of manual posting order with a bounded strategy;
merely raising the cutoff leaves another boundary. No dependency or API change
is required. Other platforms, native-ID variants of this reordered fixture,
and larger portfolios are unverified.

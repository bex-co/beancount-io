# The Query page leaves every zero amount blank: `balance … 0 IRAUSD` reads as an empty Amount cell, and `units(position)` of a `0.00 IRAUSD` posting is empty, though the text result says `0 IRAUSD` and `0.00 IRAUSD`

**Severity:** minor. A value the ledger states is lost from the result, not changed: the cell is empty, so a reader cannot tell a zero from a missing amount. **Owner:** `backend-cluster/ledger` (the dashboard renders the `{}` it receives). **Estimate:** 30–45 minutes including tests. **A1/A2:** a zero balance assertion is how a ledger says an account is empty: a paid-off card, a closed account, a contribution limit used up. `SELECT … FROM #balances` is the natural way to list those checkpoints, and on the Query page, in its Download CSV and in REST/GraphQL JSON every zero assertion comes back with no amount and no currency. Agents and scripts that read the structured result get `{}` where the text result and stock beanquery give `0 IRAUSD`. **Found by:** `/qa-find-bugs-dashboard` (`dashboard-qa` routine) on 2026-11-27 against `https://beancount.io`, entry chunk `main-BBmi61Hs.js`, isolated headless Chromium 158 at 1440×1000, English. Public example ledger, read-only. Local HEAD `85d08ba30`.

## Repro

Public ledger, no write needed. `open_ledger/example` asserts `2015-01-01 balance Assets:US:Federal:PreTax401k 0 IRAUSD` (and the same on 2016-01-01 and 2017-01-01).

1. Open `/ledger/open_ledger/example/query`, enter `SELECT date, account, amount FROM #balances WHERE account ~ 'PreTax401k'` and press **Execute Query**. The result says `Rows: 3`, and all three `amount` cells are empty.
2. Add `OR date = 2015-01-02` to the query. The 2015-01-02 checking assertion reads `4841.12 USD`; only the zero rows are empty.
3. **Download CSV**: `2015-01-01,Assets:US:Federal:PreTax401k,` with an empty last field.
4. Positions too: `SELECT date, account, units(position) AS u, cost(position) AS c, weight WHERE number = 0 LIMIT 3` returns three PreTax401k payroll postings of `0.00 IRAUSD`, and `u`, `c` and `weight` are empty in every row.
5. API control (GraphQL `queryShell`, as the page sends it, and REST `POST /api-gateway/v1/ledgers/<owner>/example/query` on a copy of the example ledger): the `amount` column is `dtype: "Amount"` and each zero row's cell is `{}`; the 2015-01-02 row is `{"USD":"4841.12"}`. Step 4's `u`, `c` and `weight` are `{}` too.
6. Text control (GraphQL `queryShellText`, the path REST `text/plain` and MCP `runBqlQuery` use): the same queries print `0 IRAUSD` for step 1 and `0.00 IRAUSD` in all three columns for step 4. Stock beanquery prints the same.
7. Working control in the dashboard: the account page `/ledger/open_ledger/example/account/Assets:US:Federal:PreTax401k?time=2016-01` shows the 2016-01-01 assertion as `Balance … 0 IRAUSD`.

Repeated from a fresh page load.

## Cause

`toShellCell` (`backend-cluster/ledger/src/features/ledger/service/ledger-shell-mappers.ts:334–357`) turns a bare Amount into a one-entry currency map with `unitsToCurrencyMap([cell])` (`:354`). That helper is fava's `simple_units` for inventories, and it drops a currency whose total is zero (`:65`, `if (total.isZero()) return;`). Dropping zero is right for an Inventory, where a zero-net balance holds nothing (w23/200 and w23/022 rely on it). An Amount is one stated quantity, and its zero is a value. The text renderer (`formatTextCell`, `:399–404`) passes the Amount to `formatCellValue`, which prints `0 IRAUSD`, so the two representations disagree. The code has been this way since the ledger service was imported (`ca9a50d2e`).

The dashboard has no separate cause: `formatInventoryLikeCell` (`dashboard/src/common/lib/format/inventory-cell.ts:70`) renders `{}` as an empty cell, which is correct for an empty inventory.

## Fix

Owned by `backend-cluster/ledger`, in the shared shell mapper, so the dashboard Query page, GraphQL `queryShell`, REST JSON and the MCP structured tool change together (parity rule).

- An Amount-typed cell keeps its currency and number when the number is zero: `{"IRAUSD":"0"}` for `0 IRAUSD`, `{"IRAUSD":"0.00"}` for `0.00 IRAUSD`, as written. That matches the text result and stock beanquery. The dashboard then shows `0 IRAUSD` with no change of its own.
- Inventory cells keep fava's rule: a currency that nets to zero is dropped, and an all-zero inventory stays `{}`. If the engine returns a bare Amount for an Inventory-typed expression (the doc comment at `:321–323` says it can), it follows the Inventory rule, so decide by the column's dtype, which `queryResultToShellResult` already has, not by the cell's shape.

## Definition of done

- On production, step 1 shows `0 IRAUSD` in all three `amount` cells, and the CSV's last field is `0 IRAUSD`. Step 4 shows `0.00 IRAUSD` (or the dashboard's existing zero spelling) in `u`, `c` and `weight`. The GraphQL control in step 5 returns `{"IRAUSD":"0"}` for the zero assertions.
- `SELECT sum(units(position)) AS s, currency WHERE account ~ 'PreTax401k' GROUP BY currency` still returns `{}` for the zero-net IRAUSD total, and an empty running `balance` is still blank.
- Ledger unit tests feed the mapper a zero Amount in an Amount column, a zero-net Inventory, and a bare zero Amount in an Inventory-typed column. They assert the kept zero for the first and `{}` for the other two, and fail without the fix. Ledger lint, typecheck, test and `verify:rustledger` pass.

## Blast radius

Every caller of `LedgerShellService` shares the mapper: the dashboard Query page and its Download CSV, GraphQL `queryShell`, REST JSON, the MCP structured query tool and `bea` hosted queries over REST. Affected columns are the Amount-typed ones: `amount` on balances and prices, `discrepancy`, posting `price`, `weight`, `cost`, and expressions such as `units(position)` and `cost(position)`. Unaffected: Position columns (`position` prints `0.00 IRAUSD` as a string), Decimal columns (`number` reads `0.00`), the text result, and the Journal and account pages, which do not use BQL.

Adjacent, not part of this fix: once the zero arrives, `formatDecimalCell` (`inventory-cell.ts:27`) writes any zero spelling as `0`, so `0.00 IRAUSD` would read `0 IRAUSD` on the page. Holdings and Statistics share that helper.

## Dedupe

Searched every board state for `0 IRAUSD`, `unitsToCurrencyMap`, `simple_units`, `zero-net`, `bare Amount`, `#balances`, and zero amounts in query results. w23/022 (done) records the Inventory zero-sum split and keeps fava's drop rule. w23/201 (done) is `number()` of an empty inventory. w4/1064 (done) is zero-valued positions in Holdings groupings, and w5/908 and w5/1055 (done) are CLI report trees. None covers a zero Amount cell. `git log -S "unitsToCurrencyMap([cell])"` shows only the original import, so this is not deployment lag.

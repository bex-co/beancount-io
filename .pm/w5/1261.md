# Statements hide an account closed after the report's period, and leave its parent as an empty row: the 2023 Balance Sheet drops `Assets:US:Federal:PreTax401k` (closed 2026-11-18) but keeps a bare "Federal – –" row

**Severity:** minor. No amount is wrong. A past period's statement is missing an account that was open for the whole period, though, and a row with no amount and no child stands in for it in the table and in the CSV, Markdown and print exports. **Owner:** `dashboard`. The filter is `features/reports/balance-sheet/utils.ts` `filterClosedTreeNodesRecursive` (`:138-170`), applied through `filterAccountHierarchy` (`:183-193`). The closed set is built in `balance-sheet/index.tsx:95`, `income-statement/index.tsx:109` and `trial-balance/index.tsx:87` from `getLedgerAccounts(status: "closed")`. That query lists every account with any `close` directive, whatever its date (`backend-cluster/ledger/src/features/ledger/service/ledger-account-service.ts:106-107`). No API change is needed: `getLedgerAccountDirectives` already returns `closedAt`, and Cash Flow reads it (`features/reports/cash-flow/graphql/cash-flow.graphql`). **Estimate:** 45–60 minutes with tests. **A2/A3:** someone who closes an old account today and then looks back at last year's statements, or compares them with Fava, finds that account gone. In its place is an unexpandable parent row whose link opens a journal full of the postings the statement left out.

## Repro

The ledger opens `Assets:US:Federal:PreTax401k IRAUSD` (and no `Assets:US:Federal`). Its 2023 postings net to zero by year end (+16,100 in January, then withdrawals totalling 16,100 by August), and it ends with `2026-11-18 close Assets:US:Federal:PreTax401k`. A smaller fixture with the same shape:

```beancount
option "operating_currency" "USD"
2023-01-01 open Assets:Bank USD
2023-01-01 open Assets:Old:Box USD
2023-01-01 open Equity:Opening USD
2023-01-01 * "fund"
  Assets:Bank      100 USD
  Equity:Opening
2023-03-01 * "in"
  Assets:Old:Box    10 USD
  Assets:Bank
2023-06-01 * "out"
  Assets:Bank       10 USD
  Assets:Old:Box
2026-11-18 close Assets:Old:Box
```

1. Open `/ledger/<owner>/<ledger>/balance-sheet?time=2023`. The Assets list shows `US › Federal – –` with no expand control and no child. `PreTax401k` is absent, although it was open throughout 2023.
2. **Export → CSV** has the row `assets,Assets:US:Federal,Federal,2,account,…,2023-12-31,…` with no amount and no `PreTax401k` row.
3. Click **Federal**. `/account/Assets%3AUS%3AFederal?time=2023` lists the 2023 PreTax401k postings, for example the 2023-08-03 payroll, which the statement left out.
4. `/balance-sheet` (all time), `/trial-balance` (all time) and `/trial-balance?time=2023-12` show the same bare `Federal – –` row under Assets. Reproduced twice from fresh loads.

API control: `getLedgerBalanceSheet(time: "2023")` returns `Assets:US:Federal` with `balance {}`, `balanceChildren {}` and `hasTxns false`, and one child, `Assets:US:Federal:PreTax401k` (`balance {}`, `hasTxns true`). `getLedgerAccounts(status: "closed")` returns `["Assets:US:Federal:PreTax401k"]`. The server sends the account, and the client filter removes it.

## Cause

- `filterClosedTreeNodesRecursive` drops a node when its name is in `closedAccountNames` and it has no balance and no surviving child. The set holds every account that has a close date anywhere in the ledger, so the 2023 report treats a 2026 close as already in effect.
- It never drops a node that is not itself closed. A parent that is not an account (nothing `open`s `Assets:US:Federal`) stays, with nothing under it. The no-transactions filter removes such parents (`hasTxns` is false). The zero-balance filter does too. With default options, though, only the closed filter runs.
- Fava decides this in `frontend/src/tree-table/helpers.ts` (`get_not_shown`). A node stays when a descendant is shown or its `balance_children` is non-empty. Otherwise it is hidden when it is not an account (`!accounts_set.has`), or when `!show_closed_accounts && is_closed_account(name, end)`, or by the zero-balance and zero-transaction options. `is_closed_account` (`frontend/src/stores/accounts.ts`) is `close_date < end`, and `true` when there is no end. `BalanceSheet.svelte`, `IncomeStatement.svelte` and `TrialBalance.svelte` pass `end = date_range?.end ?? null`. So Fava lists `Federal › PreTax401k` (zero) for 2023 and neither row for all time.

## Fix

In `dashboard` only:

1. Treat an account as closed for a report only when its `closedAt` falls before the end of the report's time filter. With no time filter, any close date counts. The end is exclusive: `time=2023` ends 2024-01-01. `features/reports/export/reporting-period.ts` already parses the filter forms. Read `closedAt` from `getLedgerAccountDirectives`, or select it in the three statement queries in place of the bare name list.
2. After the closed filter, drop a node that is not an account itself (no `open`), has an empty balance and has no surviving child, as Fava's `accounts_set` rule does.
3. Keep it in the one shared `filterAccountHierarchy`, so Balance Sheet, Income Statement, Trial Balance and their exports change together.

## Definition of done

- With the fixture above, the Balance Sheet for `time=2023` lists `Assets:Old:Box` (zero) under `Old`. The all-time Balance Sheet lists neither `Old` nor `Box`. With `fava-option "show-closed-accounts" "true"`, both views list `Old › Box`.
- On the QA ledger, `/balance-sheet?time=2023` and `/trial-balance?time=2023-12` list `Federal › PreTax401k`. `/balance-sheet` (all time) has no `Federal` row under Assets. Each view's CSV and Markdown exports match its table.
- Controls: an account closed before the period's end, with no balance, stays hidden. A closed account that still holds a balance stays shown.
- `filterAccountHierarchy` unit tests cover a close after the period end, a close before it, no time filter, and the non-account parent. They fail on the current code. The dashboard gates (`yarn format:check`, `yarn lint`, `yarn test`, `yarn build`) pass.

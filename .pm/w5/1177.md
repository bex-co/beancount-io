# Overview's net worth axis repeats one label when net worth is in the millions: "2.5M, 2.5M, 2.5M, 2.5M" and "1.2M, 1.2M, 1.2M, 1.3M"

**Severity:** minor (chart readability). **Owner:** dashboard. **Estimate:** 20–30 minutes including tests. **A2:** the hero chart at the top of the redesigned Overview gives the net worth line its own axis with three or four round steps. The steps are sized to the range the line covers, but each tick is printed in compact notation with at most one decimal. Once net worth reaches 1M, a year whose net worth moves by less than about 300K gets several ticks with the same label. The axis then says nothing about scale, while a small change fills the whole band. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-18 against `https://beancount.io` (entry chunk `main-LGv2TZLj.js`), headless Chromium at 1440×1000, English, isolated profile, signed in as the QA owner. Local HEAD `c12e43044`. Read-only.

## Repro

1. Open the Overview of a ledger whose net worth over the twelve months shown runs from 2,500,070.00 to 2,500,570.00 USD. On the QA account's disposable ledger, Period data lists these values for 2024-07-31 … 2025-06-30.
2. **Actual:** the net worth axis reads `2.5M, 2.5M, 2.5M, 2.5M`, and the line climbs the full height of its band for a +500 (0.02%) change. After a 50.00 USD probe entry was added, the same chart read `2.5M, 2.5M, 2.5M`.
3. Same code, typical ranges (computed with the chart's own step rule and formatter, en-US): 1,200,000–1,260,000 → step 20K → `1.2M, 1.2M, 1.2M, 1.3M`; 2,500,070–2,500,570 → step 200 → `2.5M ×4`. Controls: 76K–118K (the public `open_ledger/example`) → `60K, 80K, 100K, 120K` ✓; 1.18M–1.35M → step 100K → `1.1M, 1.2M, 1.3M, 1.4M` ✓.

**Expected:** neighbouring ticks never share a label. Each tick keeps enough digits to show the step (`1.20M, 1.22M, 1.24M, 1.26M`), or the axis switches to full grouped numbers when compact labels would collide. Compact notation and the language's own digits (w21/done/177) stay.

## Cause

- `dashboard/src/features/reports/overview/components/month-hero-chart.tsx:110-113` builds one `Intl.NumberFormat(language, { notation: "compact", maximumFractionDigits: 1 })`. `:285` uses it for every net-worth tick.
- `:171-193` (`worthScale`) picks `interval` from the range, `(high − low) / 3` rounded to 1/2/5×10ⁿ, with `scale: true`. A step below 0.1 of the leading unit cannot survive one compact decimal.
- `net-worth-card.tsx:71-77` (`yAxisTickFormatter`) has the same formatter on a `scale: true` axis (`:477-482`), so the Net Worth card's own trend can show the same thing when it is drawn.
- Not w5/1175: that item is about numbro's half-unit switch in the report charts, and it names this Overview chart as its working control. The report charts start their axis at zero, so their ticks stay apart.

## Fix

Owned by `dashboard`. Derive the tick precision from the step. For example, give the compact formatter `maximumFractionDigits` (or `maximumSignificantDigits`) large enough that `min + k·interval` formats differently for every k. Or, when two ticks would format alike, fall back to `useFormatNumber` grouping without compact notation. Apply the same rule to both `scale: true` net-worth axes. Keep the 3–4 step layout and the selected-point label.

## Definition of done

- A ledger whose twelve visible months run 2,500,070–2,500,570 USD shows distinct net-worth ticks. The 1,200,000–1,260,000 range reads `1.2M, 1.22M, 1.24M, 1.26M` or an equivalent with no repeated label.
- The `open_ledger/example` axis still reads `60K, 80K, 100K, 120K`.
- A unit test of the tick formatter (or the chart option) asserts that every tick label is unique for these ranges, in `en` and one other language. It fails on the current code. Dashboard gates pass.

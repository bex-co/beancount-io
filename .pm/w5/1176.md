# Overview treats a future-dated entry as already happened: it opens on next month, and "Financial position" for today lists balances that include it

**Severity:** major (wrong balances shown under a date). **Owner:** dashboard. **Estimate:** 45–60 minutes including tests. **A2:** Beancount users often enter scheduled rent, loan payments or forecast entries ahead of time. With one such entry on the ledger, the redesigned Overview opens on a month that has not begun. Its "Financial position" names today's date but lists account balances that already include the later entry. The Net Worth figure at the top of the same card leaves that entry out, so the card does not add up. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-18 against `https://beancount.io` (entry chunk `main-LGv2TZLj.js`), headless Chromium at 1440×1000, English, en-US, isolated profile, signed in as the QA owner on a disposable QA ledger. Local HEAD `c12e43044`. The probe entries were written, then the file was restored byte for byte (same blob SHA, no ledger errors).

## Repro

The ledger's only earlier asset is `Assets:Company:Cash` (2,500,570.00 USD, last transaction 2025-06-30). Today is 2026-11-18. Append:

```beancount
2026-01-01 open Expenses:Qa:Probe USD
2026-01-01 open Assets:Qa:Bank1:Checking USD
2026-01-01 open Assets:Qa:Bank2:Checking USD

2026-10-05 * "qa-seed" "Fund bank one"
  Assets:Qa:Bank1:Checking   1000.00 USD
  Assets:Company:Cash       -1000.00 USD

2026-10-06 * "qa-transfer" "Move to bank two"
  Assets:Qa:Bank2:Checking    100.00 USD
  Assets:Qa:Bank1:Checking   -100.00 USD

2026-10-10 * "qa-spend" "Probe spend"
  Expenses:Qa:Probe            12.00 USD
  Assets:Company:Cash         -12.00 USD

2026-12-15 * "qa-future" "Scheduled future spend"
  Expenses:Qa:Probe            50.00 USD
  Assets:Qa:Bank1:Checking    -50.00 USD
```

Open `/ledger/<owner>/<ledger>/overview` with no filter. The result was the same on two fresh page loads:

1. The month stepper reads **DECEMBER 2026**. Money movement reads "December 2026 · Money out 50.00 USD", with "Top spending: Expenses:Qa:Probe 50.00 USD 100%". That is the scheduled entry, shown as this month's spending.
2. Financial position is dated **Nov 18, 2026**. Net Worth reads **2,500,558.00 USD**, which is correct through today. Directly below it, ASSETS reads **2,500,508.00 USD** and `Assets:Qa:Bank1:Checking` reads **850.00**. Through today that account holds 900.00 (1000 − 100), and 850.00 is only true after 2026-12-15. LIABILITIES reads "Nothing owed", so Assets ≠ Net Worth on one card by exactly the future entry.
3. Recent activity starts with **Dec 15 · qa-future · −50.00 USD**, above everything that has happened. With eight or more scheduled entries, the list would hold nothing else.

**Expected:** with no filter, the Overview never opens on a month that has not begun. It opens on the current month (or the last finished one, as today for a dormant ledger). Financial position's rows and totals answer for the same day as its heading and its Net Worth figure. Recent activity lists entries up to today. The future entries stay visible in the Journal and in a month the reader steps to on purpose. Mobile already behaves this way: w21/done/166 (report ranges), w21/done/674 and w21/done/1014 (headline and Accounts), and w21/done/471 (Recent Transactions).

## Cause

1. **Opening month.** `dashboard/src/features/reports/overview/lib/overview-month.ts:35-60` (`openingMonth`), when there is no filter, takes `getLatestActiveIntervalDate` (public readers only) or `dates.at(-1)`, the last interval the series returns. That interval is December, because of the 2026-12-15 entry. `overview-utils.ts:681-694` (`settledOpeningMonth`) steps back only for a dormant ledger. The filtered branch, `getFilteredDefaultIntervalDate` (`overview-utils.ts:336-350`, from w0/done/029: "Never default to a future interval"), already skips months that have not begun. The unfiltered branch never got that rule. The route loader calls the same function (`loader.ts:111`).
2. **Financial position balances.** `overview/index.tsx:424-445`: for a month that is not past (`isPastMonth`, `:240`), the card gets `market?.assetsHierarchyData` and `liabilitiesHierarchyData` from the page's unbounded read, which includes every entry. Its heading date (`positionDate`, `:392-399`) and the Net Worth figure (`throughCurrentMonth` in `net-worth-card.tsx:372`, from w21/done/995) are both capped at today's month.
3. **Recent activity.** `overview/lib/recent-transactions.ts:9-31` asks for the newest 8 transactions with no upper date bound, so future-dated rows come first.

The cited files have not changed on `main` since the redesign (`aabf2eced`), apart from layout and right-to-left class edits (`4bcfcffdb` in `index.tsx`, `cbb2c09b5` in `net-worth-card.tsx`). This is not deployment lag.

## Fix

Owned by `dashboard`.
- In `openingMonth`, apply the "begun" rule to the unfiltered case too: the latest interval whose month has started (`<= today`). Fall back to the last interval only when every interval lies in the future. Keep the dormant-ledger step back and the public reader's latest-active preference, both limited to months that have begun.
- For the current month, read Financial position's hierarchy balances through `positionDate`, the same day the heading and Net Worth name (for example with the time filter `- <positionDate>`, as the past-month branch already does with its month), or take them from the same capped series. A month the reader steps to after today may keep showing that month's figures.
- Bound Recent activity's read at today (mobile's `recentTransactionsWindow(today)` is the model). Then `dataThrough`, which reads the same list, still resolves to the newest entry on or before today.

## Definition of done

- With the fixture above on 2026-11-18, the unfiltered Overview opens on November 2026. Financial position reads Net Worth 2,500,558.00 USD, ASSETS 2,500,558.00 USD and `Assets:Qa:Bank1:Checking` 900.00. Recent activity starts with Oct 10 and lists no Dec 15 row.
- Stepping Next to December still shows December's money movement (Money out 50.00 USD).
- A ledger with no future-dated entries opens exactly as today (a dormant ledger on its last finished month). `?time=2026` behaves as w0/done/029 requires.
- Unit tests pin `openingMonth` with a fixed `today` and a future interval. A rendered Overview test asserts the capped balances and recent rows. Both fail on the current code. Dashboard gates pass.

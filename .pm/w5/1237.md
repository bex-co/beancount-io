# Entry Context on the dashboard leaves a zero balance blank and runs every lot together as "8.753 RGAGX {82.26 USD, 2015-04-27},12.908 RGAGX {…},…" (dashboard half of w21/092)

**Severity:** major (a report surface shows wrong or unreadable values). **Owner:** `dashboard`. **Estimate:** 30–45 minutes including tests. **A1/A3:** Entry Context is how a reader checks what an entry did to its accounts. It is wrong in the cases where that check matters most: an account's first posting, and any account that holds more than one lot or currency. w21/092 fixed this formatter in the mobile app and said that the dashboard's copy "needs its own note". No such note was filed. **Found by:** `/qa-find-bugs-dashboard` (`dashboard-qa` routine) on 2026-11-27 against `https://beancount.io`, entry chunk `main-BBmi61Hs.js`, isolated headless Chromium 158 at 1440×1000, English and German. The run was signed in as the QA account and read the public `open_ledger/example` ledger only. Local HEAD `a78dfb4ec`.

## Repro

1. Open `/ledger/open_ledger/example/entry/32e2510839b12b5a06faa9255a0f706b` (2015-01-23 "Wine-Tarner Cable", the first posting to `Expenses:Home:Internet`). Expand **Entry Context**. Under **Balances before entry**, `Expenses:Home:Internet` has an **empty** Balance cell. The row beside it reads `Assets:US:BofA:Checking 3573.52 USD`.
2. Open `/ledger/open_ledger/example/entry/29ea1bdc57b8246ebec1461ede376dcc` (2015-04-27 "Investing 60% of cash in RGAGX"). The `Assets:US:Vanguard:RGAGX` row in both tables is a single run-on string: `8.753 RGAGX {82.26 USD, 2015-04-27},12.908 RGAGX {83.67 USD, 2015-04-13},12.761 RGAGX {84.63 USD, 2015-03-30},…` (nine lots, joined by a bare comma). The account name is squeezed onto three lines ("Assets:US / :Vanguard / :RGAGX").
3. Add `?lang=de` to the first URL. The balances still read `3573.52 USD`, while the Journal on the same page writes amounts in German style, such as `4.639,70`.
4. The Journal's own Entry Context dialog (open the row from `/journal`) shows the same values. Both use one component.

Both repeated from a fresh load.

**API control:** `getLedgerEntryContext(entryHash: "32e2510839b12b5a06faa9255a0f706b", ledgerId: "open_ledger/example") { balances_before }` returns `"Expenses:Home:Internet": []`. For `29ea1bdc…` it returns `"Assets:US:Vanguard:RGAGX"` as an array of nine lot strings. The server is correct, and the dashboard renders it wrongly.

## Cause

`dashboard/src/features/journal/components/entry-context-panel.tsx:282-295` `formatBalances` understands only a `{number, currency}` object. It falls back to `String(amount)` for the `string[]` that the ledger service sends (`backend-cluster/ledger/src/features/ledger/service/ledger-journal-service.ts:372`, `Record<string, string[]>`). `String([])` is `""`, and `String([a, b])` is `"a,b"`. Lines 396-409 and 436-449 put the result in one `<Amount>` cell. The value therefore skips `<LedgerAmount>` (`common/components/ledger-amount.tsx`), and so skips the reader's separators and `render_commas`. `dashboard/AGENTS.md` requires that component on surfaces that show what the ledger holds (w2/119).

## Fix

Owned by `dashboard`. Read each account's value as a list of amounts, as `mobile/src/screens/transactions-screen/entry-context/format-entry-balances.ts` already does:

- An empty list is a zero balance. Show `0`, never a blank cell.
- Show each currency or lot on its own line in the Balance cell. A lot string has commas of its own (`10 GLD {205.78 USD, 2016-05-05}`), so never join amounts with commas. The account cell keeps its width.
- Render each plain `<number> <currency>` amount through `<LedgerAmount>`, so `3573.52 USD` reads `3,573.52 USD` in English and `3.573,52 USD` in German, with every source digit kept. A lot keeps its `{cost, date}` annotation after the formatted units.
- Keep the `{number, currency}` object branch.

No API change.

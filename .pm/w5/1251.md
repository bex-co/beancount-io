# Budget holds a time span's cut-off first period to a whole period's target: on "This year" a weekly 70 USD budget reads 70.00 for 1–4 January but 40.00 for 28–31 December, and "Last 12 months" holds 27–30 November to the full month (dashboard gap in w21/102)

**Severity:** minor. The Period data table and the chart give the wrong target for the first period of a time span. The bar colours use that target too. **Owner:** `dashboard` (`features/ledger-data/budget`). **Estimate:** 30–45 minutes including tests. **A2:** a newcomer who sets a weekly budget and picks **This year**, or any budget and **Last 12 months**, sees a first period held to a target several days larger than the period. An overspend in it is not flagged, and an income budget's first period is flagged red. **Found by:** `/qa-find-bugs-dashboard` (`dashboard-qa` routine) on 2026-11-27 against `https://beancount.io`, entry chunk `main-BBmi61Hs.js`, isolated headless Chromium 158 at 1440×1000, English, signed in as the QA account. Local HEAD `46b910b4e`.

Open `/ledger/<owner>/<ledger>/budget` on 2026-11-27, choose a **Time span**, and open each card's **Period data**:

1. **This year** (`2026-01-01 – 2026-12-31`), Coffee: the first row is `2026-01-04 | 70.00 USD | 10.00 USD` and the last row is `2026-12-31 | 40.00 USD | 0.00 USD`. Both rows cover four days. 1 January 2026 is a Thursday, so the first covers Thursday to Sunday and the last covers Monday to Thursday. Only the last is prorated (4/7 × 70).
2. **Last 12 months** (`2025-11-27 – 2026-11-27`), Food: the first row is `2025-11-30 | 300.00 USD | 20.00 USD` and the last row is `2026-11-27 | 270.00 USD | 50.00 USD`. The first row's actual covers only 27–30 November (the 200.00 USD on the 10th is outside the window), but its target is the whole of November. The last row is prorated to 27 of 30 days.
3. Control, **Last year**: Coffee's first row `2025-01-05` reads `50.00 USD`. That only looks prorated because the budget starts on 2025-01-01: the two December days before it carry no target.

API control: `getLedgerIntervalTotals` with `time: "2025-11-27 - 2026-11-27"` returns a first bucket dated `2025-11-30` that holds only the 20.00 USD. With `time: "year"` and a weekly interval, the first bucket is dated `2026-01-04`. The server starts the series on the window's first day.

Repeated from a fresh load.

## Cause

`calculateBudgetForInterval` (`dashboard/src/features/ledger-data/budget/budget-utils.ts:233`) budgets from `getIntervalStart(end, chartInterval)` (`:240`), the calendar start of the period that contains the bucket's end. A bucket cut off by the window's end is prorated because its end is earlier. A bucket cut off by the window's start is not, because the function never learns where the window starts. `useBudgetSnapshot` (`budget-snapshot.ts:132`) calls it for every Period data row and chart point, and passes only `item.date`. `getLast12MonthsRange` (`index.tsx:39-43`) builds a rolling window to the day, so the first month of **Last 12 months** is cut off on every day except the 1st.

## Fix

Dashboard only. Pass the window's first day into `calculateBudgetForInterval` and start the period at `max(getIntervalStart(end, interval), windowStart)`, as the existing end clamp does. Take the window start from the selected span: This year → `YYYY-01-01`, Last year → the previous `YYYY-01-01`, Last 12 months → the rolling range's first day, All time → none. Mobile did the same in w21/102 (`timeWindowStart`, and `windowStart` in `budgetForIntervalExact`, `mobile/src/screens/budget-screen/selectors/budget-selectors.ts:578-593`).

Mobile also changed its 1Y pill to whole calendar months (w21/646). Making **Last 12 months** match would remove the cut-off November entirely. Weekly budgets on This year and Last year still need the clamp, so the clamp is the fix either way.

## Definition of done

- With the repro fixture on production, **This year** Coffee's first row reads `2026-01-04 | 40.00 USD`. **Last 12 months** Food's first row reads `40.00 USD` (4/30 × 300) for 27–30 November, or the window starts on the 1st of a month if Last 12 months is aligned to calendar months. Full periods are unchanged.
- Unit cases fail on the current code: a weekly 70 budget whose window starts on a Thursday gives 40 for its first period, a monthly 300 budget whose window starts on 27 November gives 40, a full period still gives the whole target, and a window that starts before the first budget is unchanged (w5/1193).
- Dashboard gates pass.

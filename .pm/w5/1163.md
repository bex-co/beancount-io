# The `bea login` device page has no heading and no main landmark, and the expired password-reset page has no heading and no way to request a new link

**Severity:** minor (accessibility; WCAG 1.3.1 Info and Relationships, 2.4.6 Headings and Labels). **Owner:** dashboard. **Estimate:** 20–30 minutes including rendered tests. **A1/A2:** `bea login` sends people, and the agents working for them, to `/auth/login/device` to authorize the CLI. A screen-reader user arriving there finds no heading and no main region. The expired reset link page says "Please request a new one" but links only to Sign in. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-18 against `https://beancount.io` (entry chunk `main-LGv2TZLj.js`), headless Chromium 153 at 1440×1000, English/light, signed in as the QA owner. No code was entered and no reset email was requested. Local HEAD `a858bdff9`.

## Repro

1. Open `/auth/login/device`. The accessibility tree holds only text "Authorize a device / Enter the one-time code shown in your terminal.", the **One-time code** textbox and **Continue**. There is no `h1` (no heading at all) and no `main` landmark. `?user_code=ABCD-EFGH` renders the same.
2. Open `/auth/reset-password` with no token, or with `?token=bogus`. Inside `main` the tree holds text "Token Expired / The password reset token is expired or invalid", an alert "This password reset token is expired. Please request a new one." and a single link, **Back to Sign in**. There is no heading, and no link to **Forgot password**.

Controls: `/auth/login` has `h1 "Welcome back"` in a `main`, and `/auth/forgot-password` has `h1 "Forgot your password?"` in a `main`.

## Cause

- `dashboard/src/features/auth/pages/device-auth-page/device-auth-card.tsx:25` wraps the page in a plain `div`, not `main`. Its titles are `CardTitle`, a `div` (`common/components/ui/card.tsx`), in `cli-auth-code-entry-view.tsx:159-161` and in the approve view `cli-auth-pending-view.tsx:91`.
- `dashboard/src/features/auth/pages/reset-password-page/index.tsx:228-230` titles the invalid-token card with `CardTitle`, and its only action is `<Link to="/auth/login">` (`:241-247`). The other branches of that page (`:148`, the form and the success state) use `CardTitle` too.

## Fix

Make the device page's outer wrapper a `main`, as w4/098 did for the other auth pages, and render each card title on the device page (code entry and approve) and the reset page (every branch) as an `h1` inside `CardTitle`, in the pattern of `features/user-settings/pages/general/oidc-section.tsx:73-76`. On the invalid or expired reset state, add a primary link to `/auth/forgot-password` ("Request a new link"), keeping **Back to Sign in** as the secondary one. No change to the device-code or reset APIs, validation or copy elsewhere.

## Definition of done

- `/auth/login/device` exposes exactly one `main` and one `h1` in both the code-entry and approve states.
- Every `/auth/reset-password` state exposes one `h1` inside its existing `main`.
- The expired or invalid reset state links to `/auth/forgot-password` as well as to Sign in.
- Rendered tests assert the landmark, the heading and the reset links, and fail on the current code. Dashboard gates pass.

## Dedupe

Searched `.pm/**`, including `done/`, for `login/device`, `device-auth`, `cli-auth`, reset-password, Token Expired and auth headings or landmarks. w4/done/098 added `main` to sign-up, forgot-password, reset-password and the not-found shell, not the device page, and added no headings. w0/done/019 is the device page's unknown-code wording, w3/done/172 reset's outage wording, and w5/1156 the same `CardTitle` pattern on Ledger Settings. Present at HEAD.

## Unverified

The approve state live (needs a real `bea login` code; it is source-traced), screen-reader speech, and signed-out arrival on the device page.

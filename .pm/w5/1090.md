# Preserve precise interpolation in Beancount query exports

**Minor · cli · 20–30m · A1 · worker1.** A full Beancount query export
drops `use_precise_interpolation`, so reloading recomputes an inferred stock
transfer as **1.00 HOOL instead of 1.001**. Its cost-basis net worth becomes
**999.990 instead of 1000.000 USD**; Cash remains 979.90 USD. With an exact
balance assertion the valid source exports successfully but its copy fails
`check`. Without that assertion both books pass while the copy loses shares.
No product fix made.

Local CLI QA, 2026-10-28: checkout `bea 0.3.1`, frontend Python 3.13.3,
existing managed Python 3.12.10 / Beancount 3.2.3 / Beanquery 0.2.0,
macOS 26.5.1 arm64. Immutable source
`e08f21ca46c6127e897d3da54f597e15d25b7ec1`, all 1,741 CLI file hashes
verified before/after. Reviewed main `588ae9b87` has the same local code.
Offline synthetic books, isolated child config/cache, HOME unchanged,
closed stdin/no TTY, bounded fresh subprocesses and separate streams/exits.

| State | Destination quantity | Cost-basis net worth | `check` with exact assertion |
| --- | --- | --- | --- |
| Original source, precise interpolation TRUE | 1.001 HOOL | 1000.000 USD | 0 |
| Actual `PRINT` export, precision option absent | 1.00 HOOL | 999.990 USD | 1 |

The source transfers 1.00 shares from one account and 0.001 from another.
It infers the destination quantity under the ledger's declared precision
policy. The exported transaction correctly keeps that destination
number-less and undated, but its preamble carries only
`infer_tolerance_from_cost` from these two options. Reload therefore uses
Beancount's default, less precise interpolation. The other two positions,
Cash, per-unit cost and undated cost identity are unchanged. Total stock
units fall from 2.010 to 2.009. The copy loses quantity and cost basis.

Removing the final balance line in a fresh case produces the silent variant:
source/export/check all exit 0 despite the same quantity and cost difference.
With `~ 0`, the copied assertion reports accumulated 1.00 against expected
1.001. Native loads independently verify both outcomes. Prefixing only the
missing TRUE option restores the entire per-account lot graph on every
affected profile, without changing its transaction text.

## Cause and repair target

`cli/src/bea_engine/query.py:1735–1742` `_EXPORTED_OPTIONS` omits
`use_precise_interpolation`. `_option_lines` (`:1749–1776`) already serializes
non-default booleans as TRUE/FALSE, but never visits that key.
`_render_beancount` (`:1861–1865`) correctly restores source-inferred,
undated quantities through `_with_inferred_units` (`:1887–1906`) before
printing this incomplete option preamble.

Beancount 3.2.3's booking uses the finest inferred tolerance for missing
amount interpolation when this option is TRUE, and the loosest when FALSE;
validation still uses the loosest. The 1.00 and 0.001 source legs have
different HOOL precisions. With the option missing, the recomputed 1.001
quantity is quantized to 1.00. The independently loaded FALSE reference
reproduces exactly the exported positions. All amounts here are short
decimals; there is no repeating division, plugin, price, label mutation or
unresolved source posting.

Two actual producer traces, on standard and renamed/included books, confirm
that the option is TRUE, the list marker is correct, and the renderer
restores the destination to MISSING while excluding that TRUE option.
Calling the actual renderer produces bytes identical to the real CLI export.

Include non-default `use_precise_interpolation` in the existing validity
option preamble and update its documentation in `cli/docs/USAGE.md:846–850`.
Retain the number-less quantity and unknown cost date required by 1066.
The exported copy should book the source's exact quantity/lot graph and
pass its exact balance assertion. Preserve the existing default-option
omission, root-name switches, padding dependencies and raw-mode behavior.
No dependency, upstream fork, API or cross-package change is indicated.

Caller search finds one `_option_lines` consumer, `_render_beancount`,
selected by query dispatch at `query.py:1588`. The new matrix drives PRINT
to a file, explicit Beancount PRINT to stdout, and SELECT directive output.
SELECT's transaction result is wrapped with unchanged opens and the source
assertion for standalone validation; full PRINT requires no wrapper. Stored
queries and the interactive shell share this renderer but were not freshly
exercised for this boundary.

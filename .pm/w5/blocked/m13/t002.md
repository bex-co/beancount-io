## Objective

Handle permission failures and interrupted link creation without losing existing installations or leaving the user guessing what succeeded.

## Context

- skills/scripts/beancount-skills.py currently creates links sequentially after conflict checks.
- The supported behavior remains one shared source checkout, existing-link reuse, and refusal of conflicting copies.

## Steps

1. Use the reproduced baseline to add the smallest useful link-capability diagnostics and native Windows remedy.
2. Track links created by the invocation and clean up only those if an ordinary creation failure interrupts installation; never unlink existing or concurrently replaced entries.
3. Preserve verify/uninstall ownership rules and report destination-specific nonzero failures with an explicit resulting state.

## Files

- `skills/scripts/beancount-skills.py`
- `skills/scripts/test_beancount_skills.py`
- `skills/docs/installation.md`

## Acceptance criteria

- [ ] Denied link creation reports a practical remedy rather than a raw unexplained traceback.
- [ ] An injected mid-install creation failure preserves all pre-existing entries and removes only this invocation's still-owned new links.
- [ ] Successful installs, repeated installs, conflicts, and uninstall retain their existing contract.
- [ ] No settings, machine permissions, or source checkout files are changed automatically.

## Out of scope

- Copy/junction fallbacks, arbitrary environment repair, or handling uncatchable process termination as a guaranteed rollback.

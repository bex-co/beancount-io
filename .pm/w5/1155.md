# Budget: dismissing Add Budget opened from "Add Your First Budget" sends focus to the header "Add Budget" instead

**Severity:** minor (keyboard focus return, WCAG 2.4.3). **Owner:** dashboard. **Estimate:** 15–20 minutes. **A2:** a keyboard user who opens the first-budget dialog and backs out should land back on the button they used. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-18 against `https://beancount.io` (entry chunk `main-LGv2TZLj.js`), QA-owned headless Chromium 153 at 1440×1000, English/light. Signed-in QA owner on its designated disposable synthetic ledger, which has no budgets. Read-only: no budget was created. Local HEAD `50f9bca2f`.

## Repro

1. Open `/ledger/<owner>/<ledger>/budget` on a ledger with no budgets. The empty state shows **No budgets found** and **Add Your First Budget**.
2. Focus **Add Your First Budget** and press Enter. The **Add Budget** dialog opens with focus in Date.
3. Press Escape without typing.
4. Result: focus is on the page header's **Add Budget** button, not on **Add Your First Budget**.

Closing with **Cancel**, with the **Close** button, and opening by pointer click then pressing Escape all give the same result, each from a fresh load. Control: opening from the header **Add Budget** returns focus to that same button.

## Cause

`dashboard/src/features/ledger-data/budget/index.tsx:371-374` clears `addReturnFocusRef.current = null` inside `onOpenChange(false)`. Radix runs that synchronously on Escape, Cancel or Close. The dialog reads the ref later, in `DialogContent`'s `onCloseAutoFocus` (`add-budget-dialog.tsx:244-250`), after the content unmounts. By then the ref is null, so `restoreFocusOnDialogClose` falls back to `headerAddRef`. The ledger sidebar's Edit and Delete dialogs get this right: they clear their ref inside `onCloseAutoFocus`, after restoring (`features/ledger-list/pages/dashboard-page/components/dashboard-sidebar.tsx:521-528`, `:599-607`).

## Fix

Clear the opener ref after focus is restored, not on `onOpenChange`. Either clear it in the dialog's close-auto-focus path, or let the next `openAddBudget` overwrite it. Keep the existing fallback: when a successful create removes the empty state, focus goes to the header **Add Budget**.

## Definition of done

- In the repro, Escape, Cancel and Close each return focus to **Add Your First Budget**. Opening from the header still returns to the header button.
- After a successful first create (local fixture), focus lands on the header **Add Budget**, never BODY.
- A rendered test opens the dialog from the empty-state button, dismisses it, and asserts that button has focus. The test fails on the current code. Dashboard gates pass.

## Dedupe

Searched `.pm/**` for Add Your First Budget, budget focus, and return focus. w3/done/m23/t002's acceptance requires that "header, empty-state and card paths restore the correct opener after dismissal". The clearing line came in with that fix (`f6b7f9525`), so the empty-state path never met it: an unmet acceptance of completed work, not deployment lag. w4/done/1110 covers Update Budget's return to its card, a different opener.

## Unverified

The budget card's own Add Entry path (the ledger has no budget cards). Screen-reader speech.

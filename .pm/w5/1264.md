# The Journal never shows a posting's own metadata: with Metadata on, `lot-note: "…"` under a posting is missing from every Journal row, account journal and Entry Context preview, though `any(lot-note:"…")` finds the entry

**Severity:** minor. Nothing in the ledger is wrong, but metadata written on a posting (a lot note, a receipt link, a statement reference, an importer's source id) cannot be read on the dashboard except by opening the entry's source. The Journal's **Metadata** toggle shows the entry's own metadata only. A filter on posting metadata does match, so the reader gets a row that matched for a reason the page never shows. The mobile app lists posting metadata under each posting. **Owner:** `dashboard` (`features/journal`). **Estimate:** 30–45 minutes including tests. **A2:** importers and agents commonly write per-posting metadata, and a newcomer who checks an import on the Journal sees it silently missing.

**Found by:** `/qa-find-bugs-dashboard` (`dashboard-qa` routine) on 2026-11-27 against `https://beancount.io`, entry chunk `main-BBmi61Hs.js`, isolated headless Chromium 158 at 1440×1000, macOS, English, browser zone America/Mexico_City. Signed in as the QA owner on its designated disposable ledger, which was restored byte-for-byte afterwards (same blob, no ledger errors). Local HEAD `6920944d9`. No dashboard commit has ever read `posting.meta`, so this is not deployment lag.

## Repro

1. Append one transaction to a ledger that has `Assets:Bank:Checking` (the probe used `qa-20261127-` names and two new accounts):

   ```beancount
   2026-01-01 open Assets:Broker:QAXX
   2026-09-01 * "qa-20261127-Broker" "qa-20261127 buy with total cost" #qa-20261127-trip ^qa-20261127-link
     qa-key: "qa-20261127-meta"
     Assets:Broker:QAXX   10 QAXX {{1000.00 USD}}
       lot-note: "qa-20261127-posting-meta"
     ! Assets:Bank:Checking  -1000.00 USD
   ```

   The ledger check stays clean.
2. Open `/journal?time=2026-09`. **Metadata** is on by default; turn on **Postings**. The row lists `Assets:Broker:QAXX · Cost: 100.00 USD (Sep 1, 2026) · 10 QAXX`, `!Assets:Bank:Checking -1,000.00 USD`, then the entry's `qa-key qa-20261127-meta`. `lot-note` appears nowhere on the page.
3. Switch to **Comfortable**. Same result.
4. Open `/journal?filter=any(lot-note:"posting-meta")`. The Journal reads "1 entry" and lists this transaction, still without `lot-note`. (`lot-note:"posting-meta"` without `any(…)` matches nothing, because the key is on the posting, not the entry.)
5. Open `/account/Assets:Broker:QAXX` with Metadata and Postings on. The account journal row omits `lot-note` too.
6. Open the entry (Entry Context). Its source shows `lot-note: "qa-20261127-posting-meta"` under the posting, which is the only place the dashboard shows it.

Repeated from a fresh load.

API control (GraphQL `getLedgerJournal(query: {time: "2026-09-01"})`): the posting carries `"meta": {"lot-note": "qa-20261127-posting-meta"}`, the entry carries `"meta": {"qa-key": "qa-20261127-meta"}`.

## Cause

- `backend-cluster/ledger/src/foundation/rustledger/journal-serialize.ts:192` sends each posting's `meta`, and `dashboard/src/common/types/journal.ts:43` types it (`JournalPosting.meta`).
- `dashboard/src/features/journal/components/journal-postings.tsx` renders flag, account, cost, price and units in both its compact branch (`:89-144`) and its full branch (`:153-222`), and never reads `posting.meta`. It takes no `showMetadata` prop.
- The Journal rows (`journal-lines.tsx:556`, `journal-days.tsx:550`) pass `JournalPostings` the postings only, and render `JournalMetadata` (`journal-metadata.tsx`) for the directive's own `meta`, filtered by `displayableMetadataEntries` (`journal-metadata-entries.ts:9-19`). The account journal and Overview use the same list (`ebbf43fed`). Entry Context's phone preview (`entry-context-dialog.tsx:278`) uses `JournalPostings` in its card form.
- Working control: mobile's transaction detail renders each posting's metadata lines (`mobile/src/screens/transaction-detail-screen/components/posting-row.tsx:204-210`).

## Fix

Owned by `dashboard`; no API change. Give `JournalPostings` a `showMetadata` prop. When it is on, list each posting's displayable metadata under that posting's row, with the same key/value presentation and the same internal-key filter (`__…`, `filename…`, `lineno…`) as the entry's metadata. Generalize `displayableMetadataEntries` to take a metadata map so both use one filter. Pass the Journal's `showMetadata` from both layouts. Entry Context's phone preview may show it unconditionally. A posting without displayable metadata renders exactly as today.

## Definition of done

- With the fixture above and Metadata and Postings on, the compact and Comfortable Journal rows and the `/account/Assets:Broker:QAXX` row show `lot-note qa-20261127-posting-meta` under the `Assets:Broker:QAXX` posting, and nowhere else. The entry's `qa-key` row is unchanged.

# `plugin "beancount.plugins.unrealized"` silently does nothing: no unrealized-gain entries and no error, where Beancount 3.2.3 refuses the plugin and Beancount 2 generated entries

**Severity:** minor. **Owner:** `backend-cluster/ledger` (plugin handling). **Estimate:** 30–45 minutes including tests. **A2/A3:** `plugin "beancount.plugins.unrealized" "Unrealized"` is a common line in Beancount 2 / Fava ledgers. A user who migrates one sees a clean Errors page and an empty `Unrealized` account, so they believe the plugin ran. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-18 against `https://beancount.io` (entry chunk `main-LGv2TZLj.js`), headless Chromium at 1440×1000, English, isolated profile, signed in as the QA owner on a disposable QA ledger. Local HEAD `a84cb10f2`. The probe lines were written and then removed. `main.bean` was restored byte for byte (same blob SHA, no ledger errors).

## Repro

```beancount
option "operating_currency" "USD"
plugin "beancount.plugins.unrealized" "Unrealized"
2026-01-01 commodity QAFIFO
2026-01-01 open Assets:Fifo QAFIFO "FIFO"
2026-01-01 open Assets:Cash USD
2026-01-01 open Equity:Opening USD
2026-01-02 * "fund"
  Assets:Cash  1000.00 USD
  Equity:Opening
2026-02-01 * "buy"
  Assets:Fifo  10 QAFIFO {10.00 USD}
  Assets:Cash  -100.00 USD
2026-05-01 price QAFIFO 40.00 USD
```

1. Production, with the plugin line added to a disposable ledger's `main.bean` that holds lots like these: the Errors page and `getLedgerErrors` list nothing about the plugin. (They listed only an unrelated error already in the fixture.) BQL `SELECT date, flag, narration, account, position WHERE account ~ "Unrealized" OR flag = "U"` returns no rows. The Accounts page has no `Unrealized` account. A second plugin in the same edit, `implicit_prices`, did take effect: Commodities gained cost-derived price points.
2. Local engine, `@rustledger/wasm` 0.24.0 (the version `backend-cluster/ledger` pins) running `Ledger.fromFiles` on the file above: `getDirectives()` returns the 7 written directives and nothing else. `getErrors()` returns one entry, `{"message":"Unrealized gain on 10 QAFIFO in Assets:Fifo: 300.00 USD","code":"PLUGIN","phase":"plugin","severity":"warning","file":null,"line":null}`. `listPlugins()` includes a native `unrealized` ("Calculate unrealized gains/losses").
3. Reference, Python Beancount 3.2.3 (the `cli` venv) `loader.load_file` on the same file: `Error importing "beancount.plugins.unrealized"`. The module is not shipped in Beancount 3. In Beancount 2 the plugin inserted `U`-flagged unrealized-gain transactions for each holding with a price.

## Expected / Actual

Expected: the user learns that this plugin did not run. Match the Beancount 3.2.3 contract the ledger service already follows elsewhere (w3/blocked/113): report an error on the plugin line naming the plugin as unavailable, with a hint that the Balance Sheet "At Market Value" view shows unrealized gains under `Equity:Unrealized`. Actual: the engine's only output is a warning per holding, and `getErrors` drops all warnings, so nothing reaches any surface.

## Root cause

- rustledger maps `beancount.plugins.unrealized` to its native `unrealized` plugin. That plugin emits `severity: "warning"` messages with no file or line and creates no directives.
- `backend-cluster/backend-v2/src/features/ledger/service/ledger-data-service.ts:244-259` (`getErrors`, `includeWarnings = false`) filters out warnings by design, as documented in `ledger-data-resolver.query.ts:484`.
- `backend-cluster/ledger/src/foundation/rustledger/plugin-typos.ts:10-35` lists the shipped `beancount.plugins` modules and turns an unknown one into an error. It only rewrites errors the engine already raised, and the engine raises none for `unrealized`.

## Fix

- In `backend-cluster/ledger`, when the entry-point file declares `plugin "beancount.plugins.unrealized"`, ignore the native plugin's warnings and add one error at that `plugin` line, with the message and hint above. Use the plugin-line parsing in `plugins/collect-plugins.ts`.
- Leave genuine engine warnings (one-posting entries, closing with a balance) hidden as today.
- Tests: the fixture above yields exactly one located error and no `Unrealized gain on …` text. A ledger without the plugin is unchanged. GraphQL, REST and MCP error reads agree, since they share the service.
- Whether to also emulate Beancount 2's generated entries is an owner decision. It is not required to stop the silent no-op.

## Blast radius

Every read that loads the ledger: Errors page and badge, `checkLedger`, `bea check` against hosted ledgers, and write validation. The rustledger-native plugins `auto_tag` and `rx_txn_plugin` are also outside Beancount's shipped set. They were not exercised here, so whether they are silent too is unverified.

## Dedupe

Searched `.pm/**`, including `done/` and `blocked/`, for `plugins.unrealized`, the unrealized plugin, `Unrealized gain on`, and plugin warnings. w21/done/902 and w1/done/208 cover misspelled or unknown plugins, which the engine does report. w3/done/359 is CLI tracebacks. Nothing covers a plugin the engine accepts and turns into warnings only. Unchanged on `main`; not deployment lag.

## Unverified

Bare `plugin "unrealized"`; the plugin's account-name argument; the REST and MCP error reads (they share `getErrors`).

# Smart Import never flags rows the ledger already holds: its duplicate check asks the journal for 2000 rows and the API refuses anything over 1000

**Severity:** major (re-importing a statement books every row a second time, with no warning). **Owner:** dashboard. **Estimate:** 20–30 minutes. **A2:** a newcomer who uploads the same bank CSV twice, or a statement that overlaps the last one, should see the rows already in the ledger flagged "Already in the ledger" and unselected, as w2/122 promised. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-16 against `https://beancount.io`, using headless Chromium at 1440×1000 in English/light. The account was the QA owner, on its designated disposable synthetic ledger. Local HEAD `c040852e8`. The ledger was restored byte-for-byte afterwards (same blob hash, clean check).

## Repro

1. On a ledger with `Assets:Cash` in USD, open **Import** and upload this CSV:

   ```csv
   Date,Payee,Description,Amount
   2026-08-30,qa-20261116-Payee,qa-20261116-coffee,-3.25
   2026-08-31,qa-20261116-Refund,qa-20261116-refund,12.00
   ```

2. **Continue to Configure**, choose Source Account `Assets:Cash`, currency `USD`, and a target account for each row. **Import 2 Transactions** succeeds, and the file gains both transactions posting `-3.25 USD` and `12.00 USD` to `Assets:Cash`.
3. **Import More**, upload the same file, **Continue to Configure**, and choose Source Account `Assets:Cash` again.

Expected: both rows are marked "Already in the ledger" and start unselected. Actual: neither row is flagged, both stay checked, and the button offers **Import 2 Transactions**. The duplicate check's request fails:

```text
operationName: GetLedgerJournal
variables.query: { account: "Assets:Cash", time: "2026-08-30 - 2026-08-31",
                   directiveTypes: ["Transaction"], offset: 0, limit: 2000 }
errors[0]: "limit must be an integer from 1 to 1000"
           extensions: { code: "BAD_USER_INPUT", field: "limit" }
```

Reproduced twice from a fresh configure step. Because the hook treats a failed read as "nothing found" by design, the page shows no error.

## Cause

- `dashboard/src/features/importer/hooks/use-import-duplicates.ts:15` sets `JOURNAL_LIMIT = 2000` and sends it as `query.limit`.
- `backend-cluster/backend-v2/src/features/ledger/service/ledger-journal-service.ts:44` refuses any `limit` above 1000 (added in `981e15ab9`, w6/007, on 2026-10-15). REST and MCP schemas hold the same bound.
- The duplicate check shipped in `1d02fee9b` (w2/122) on 2026-11-11, after the bound existed, so it has never worked against the real API. Its unit tests mock the query and do not see the refusal.

## Fix

Ask for at most 1000 rows per request: either set the limit to 1000 and page with `offset` until `total` is covered (preferred, so a long statement over a busy account is still checked in full), or cap at 1000 and say in the code that a longer window is checked in part, as the comment already does for 2000. Keep the rest of the contract: the check never blocks an import, and only withholds rows.

## Definition of done

- In the repro above, after step 3 both rows show "Already in the ledger" and start unselected, as w2/122 specifies, and the reader can still reselect one deliberately.
- The `GetLedgerJournal` request the hook sends has `limit <= 1000` and returns data, not `BAD_USER_INPUT`.
- A test fails on current `main` because the hook's request exceeds the API's bound. For example, assert the variables the hook passes against a shared maximum, or exercise the hook against a mock that rejects `limit > 1000` as the server does.

## Blast radius

Searched `dashboard/src`, `mobile/src` and `cli/src` for journal reads with a limit of four or more digits. This hook is the only one. The working control is the Journal page, which pages at 20–100 rows.

## Dedupe

Searched `.pm/**`, including `done/`, for "Already in the ledger", duplicate import, `use-import-duplicates`, and `limit must be an integer`. `w2/done/122` shipped the feature; this note is a regression against it (its behavior never reached production). w6/007 added the bound. No open item covers it.

## Unverified

PDF/OFX/receipt import paths, which use other flows. The mobile importer was not checked.

# Keep lot selectors intact when quantities are inferred

**Major · cli · 45–60m · A1 · worker1.** A sale whose quantity is inferred
changes an existing lot selector from newline-valued `First\nLot` to `First
Lot`. Single and bulk add each report success and the ledger checks valid,
but the sale creates an unintended short position instead of reducing its
selected long lot. Capital Gains omits **10 USD**. Selling the remaining nine
shares leaves **+1 / −1** offsetting lots, reports **90 rather than 100 USD**
of gains, and prevents account closure despite a passing zero-unit assertion.
Explicit `-1` quantity controls select the correct lot and close cleanly.
No product fix implemented.

Real local QA, 2026-10-28: checkout `bea 0.3.1`, immutable source
`e08f21ca46c6127e897d3da54f597e15d25b7ec1` (1,741 tracked CLI files), frontend
Python 3.13.3, existing managed Python 3.12.10 / Beancount 3.2.3 / Beanquery
0.2.0, macOS 26.5.1 arm64. Latest main `11ea464c5` has the same local ledger
implementation; its differences are generated cloud clients. Fresh bounded
subprocesses, offline, closed stdin/no TTY, isolated child config/cache, HOME
unchanged, synthetic ledgers only.

## Cause and repair

`cli/src/bea_engine/ledger/writer.py:400–433` (`normalize_entry_strings`)
recognizes a reduction selector only when the posting's quantity is already
known. A null quantity becomes native `MISSING`; `known` is false, so
`single_line(cost.label)` changes the selector before native booking infers
its negative quantity. A producer trace confirms the label is already
`First Lot` while the parsed quantity is still `MISSING`.

`format_transaction` (:532–595) constructs the missing quantity and reaches
`format_entry` (:494–505), which normalizes the entry. Bulk add uses it for
row validation, staged text and partial writes (`ledger/adding.py:1970,2031`
and its partial paths); single add normalizes at :1422 before append. Native
booking accepts the newly labelled inferred negative posting as an
augmentation. The label rewrite precedes booking and reporting.

Use native-completed quantity/direction to decide whether the incoming label
selects a held lot, then preserve that selector exactly for a reduction.
Keep the original missing/inferred quantity spelling and cost parts when
writing: materializing a quantity can change native lot dates. Retain ordinary
normalization for new acquisitions, including inferred positive buys, plus
the existing short-cover/context/total-cost policies. Reuse native completion
rather than adding parallel booking math. Audit the shared import normalizer;
this new input shape was not exercised through an importer. The implementation
is confined to CLI and needs no new dependency.

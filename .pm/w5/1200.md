# Create File and Upload Files save a `.bean` file nothing includes without a word: its entries never reach the Journal or reports, though GraphQL returns `notLoaded` and mobile offers "Add to main.bean"

**Severity:** minor (entries typed into the dashboard silently don't count). **Owner:** dashboard. **Estimate:** 45–60 minutes including rendered tests. **A2:** a user who splits a growing ledger by year ("2026.bean") or types a first transaction into a new file on the web gets a clean save and a file that looks like every other file, and the entries never appear in the Journal, the Balance Sheet or the error count. The native app already offers "Add to main.bean so its entries count" (w21/588), and the GraphQL write names the orphan in `notLoaded` (w1/227), but the dashboard asks for neither. **Found by:** `/qa-find-bugs-dashboard` (`dashboard-qa` routine) on 2026-11-21 against `https://beancount.io`, entry chunk `main-CIyNN76T.js`, isolated headless Chromium at 1440×1000, English, signed in as the QA owner on the designated synthetic ledger (file deleted afterwards, ledger restored byte-for-byte). Local HEAD `8724f3464`.

## Repro

1. `/ledger/<owner>/<ledger>/files/tree/main` → **Create File**. Name it `qa-20261121-orphan.bean` and type:

   ```beancount
   2026-08-31 * "qa-20261121-ORPHAN CAFE" "qa-20261121-typed into a new file"
     Expenses:Food:Coffee  3.50 USD
     Assets:Cash  -3.50 USD
   ```

2. **Save**. The page returns to Files, which lists the new file beside `main.bean` with nothing to tell them apart. No toast or notice appears (watched for 6 s).
3. Journal with `?filter="ORPHAN"`: `0 entries`. Errors: "No Errors Found". The file's own view (`files/blob/main/qa-20261121-orphan.bean`) shows the text with no notice.

Control: the API knows. An `updateLedgerFiles` dry run on the same file (MCP; GraphQL `updateLedgerFile` and REST `PUT …/files` carry the same field) returns `"notLoaded":["qa-20261121-orphan.bean"]` and "qa-20261121-orphan.bean is not included by any loaded file: its entries don't count and were not checked." The dry run also accepted an unbalanced edit (3.75 against −3.50) with "No new bean-check errors", because nothing reads the file.

## Cause

- `dashboard/src/features/ledger-editor/graphql/ledger-editor.graphql:16-39` (`CreateLedgerFile`) and `:41-65` (`UpdateLedgerFile`) do not select `notLoaded`, which the schema has offered since w1/227 (`backend-v2/src/features/ledger/api/resolvers/ledger-resolver.types.ts:338-343`).
- `create-file/index.tsx:171-198` (`handleSave`) navigates back to the tree on success with no message. `upload-files/index.tsx:126-129,210` writes each upload through the same mutation. The file editor's save (`file-editor/components/ledger-file-view/index.tsx:113`) likewise ignores it.
- The dashboard has no equivalent of mobile's include option (`mobile/src/screens/ledger-file-browser-screen/index.tsx`, `ledgerCreateFileInclude`).

## Fix

Owned by `dashboard`. No API change: the field exists.

- **Create File**, for a `.bean`/`.beancount` name: offer the native app's switch, "Add to main.bean so its entries count", on by default, as decided for the app in w21/588. After the file is created, add one `include "<path>"` line to the entry point (after the last include, in its own line ending; skip it if already included) through the existing update mutation. If that second write fails, keep the file and say it was created but won't count until it is included.
- **Upload Files, file saves, and Create File with the switch off:** select `notLoaded` and, when it names files, show a persistent warning naming each one ("… is not included by any loaded file: its entries don't count and were not checked"), not a transient toast.
- Optional, separate: a "Not included" marker in the Files list needs a read of the loaded source files and is out of scope here, as it was for mobile.

## Definition of done

- Repeating the repro with the switch on (the default) creates the file and the include in `main.bean`; the ORPHAN CAFE entry appears in the Journal.
- With the switch off, and for an uploaded `.bean` file nothing includes, the page shows the not-included warning naming the file. Creating a non-ledger file (a `.csv` or `.pdf`) shows neither.
- Rendered tests cover the switch on and off, the include write failing after the create succeeds, and an upload with `notLoaded`. They fail on the current code. Dashboard gates pass.

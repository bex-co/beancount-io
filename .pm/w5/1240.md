# Balance Sheet, Income Statement, Cash Flow and Trial Balance list every statement card twice among the page's landmarks: "Assets List, Assets List, Liabilities List, Liabilities List, …" (regression of w3/m39)

**Severity:** minor (accessibility; axe `landmark-unique`). **Owner:** `dashboard`. **Estimate:** 15–25 minutes including a test. **A2:** a screen-reader user moves around a statement by landmark (NVDA's D key, the VoiceOver rotor). Each card is now two nested regions with the same name. Every jump between cards takes two presses, and the list reads like a duplicated page. w3/m39 accepted the shell's landmarks on the condition that "No page has two identically named landmarks". It checked that on a public balance sheet. **Found by:** `/qa-find-bugs-dashboard` (`dashboard-qa` routine) on 2026-11-27 against `https://beancount.io`, entry chunk `main-BBmi61Hs.js`, isolated headless Chromium 158 at 1440×1000, light and dark, English, signed in as the QA account, reading the public `open_ledger/example`. Read-only. Local HEAD `634566e8f`.

## Repro

1. Open `/ledger/open_ledger/example/balance-sheet` and read the landmarks from the accessibility tree (Chromium `Accessibility.getFullAXTree`, unignored `region` and `navigation` nodes). The tree has `region "Assets List"` ×2, `region "Liabilities List"` ×2 and `region "Equity List"` ×2, beside `navigation "Ledger"`, `navigation "Related pages"` and `region "Notifications alt+T"`.
2. `/income-statement`: "Income List", "Net Profit" and "Expenses List" each appear ×2. `/cash-flow`: "Operating Activities List", "Net change in cash & equivalents", "Investing Activities List" and "Financing Activities List" each appear ×2. `/trial-balance`: "Trial Balance" appears ×2.
3. axe-core 4.10.2 reports `landmark-unique` on each of these four pages and on no other ledger page. It found nothing on Overview, Journal, the account page, Holdings, Budget, Accounts, Statistics, Ledger Settings, `/ledger` and Settings → General.

All repeated from a fresh load.

## Cause

`c546b4ce6` (2026-11-22, "unify sidebar page layouts…") wrapped each card in a named `<section>`. In `dashboard/src/features/reports/balance-sheet/hierarchy-list-card.tsx:55-58`, `<section aria-labelledby={titleId}>` becomes `region "<title>"`. In `trial-balance/trial-balance-content.tsx:355-358` it is `<section aria-labelledby="trial-balance-hierarchy-heading">`. Inside each, `HierarchyList` already rendered its own scroll container, `balance-sheet/hierarchy-list.tsx:495-499`: `role="region" tabIndex={0} aria-labelledby={ariaLabelledBy}`. The w0/014 fix (`0aa37cf7c`) added that container so keyboard users can scroll a wide table. The card passes the same heading id to both (`hierarchy-list-card.tsx:75`, `trial-balance-content.tsx:379`), so the two landmarks share one name, nested one inside the other.

## Fix

Owned by `dashboard`. Target: each statement card is exactly one landmark, named by its heading. The table's scroll container stays focusable and named, so w0/014's keyboard scrolling still works, but it is no longer a second landmark of the same name. For example, give the inner container `role="group"` when an enclosing labelled section already names the card. Or drop the section's `aria-labelledby`, so that only the scroll region remains. Callers that render `HierarchyList` outside a labelled section must keep one named region. No API change.

## Definition of done

- On `/balance-sheet`, `/income-statement`, `/cash-flow` and `/trial-balance` of `open_ledger/example`, each card's name appears once among the landmarks, and axe `landmark-unique` passes.
- Tab still reaches each statement table's scroll container, and arrow keys scroll it horizontally at 390px.
- A rendered test of a statement card asserts that `getAllByRole("region", { name: "Assets List" })` has length 1. It fails on the current markup. Dashboard gates pass.

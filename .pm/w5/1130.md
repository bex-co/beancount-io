# BQL query history survives sign-out and is shown to the next visitor of the same browser

**Severity:** minor (privacy on a shared browser). **Found by:** `/qa-find-bugs-dashboard` on 2026-11-15 against `https://beancount.io` (local HEAD `cf7e6b0a4`; the code below is unchanged at HEAD, so this is not deployment lag), headless Chromium at 1440×1000, isolated profile, signed in as the QA account.

## Repro

1. Sign in. Open `/ledger/<owner>/<private-ledger>/query` and run a few queries, for example `SELECT payee, count(*) AS n GROUP BY payee ORDER BY n DESC LIMIT 3`.
2. Sign out through the user menu (`/auth/logout`). The page lands on `/auth/login`.
3. Signed out, open the public `/ledger/open_ledger/example/query`.

**Actual:** Query History lists all 13 queries the previous user ran, including those written against their private ledger. Their account names, payees and amounts appear in `WHERE` clauses. The newest one runs again on load against the public ledger. `localStorage["beancount-query-history"]` still holds the same 13 strings after sign-out. A different account that signs in on the same browser sees the same list.

**Expected:** sign-out leaves nothing of the previous user's query text behind. One user's history is never shown to a signed-out visitor or to another account.

## Root cause

`dashboard/src/features/bql/hooks/use-query-history.ts` stores the history under one global key, `beancount-query-history`, which is not scoped to a user. `dashboard/src/features/auth/pages/logout-page/index.tsx` revokes the session, calls `clearUserId()` and replaces the document, but never touches `localStorage`. An expired session that never reaches the logout page leaves the history behind as well.

## Fix

Owned by `dashboard`. Key the history by the signed-in user id (`beancount-query-history:<userId>`), and give signed-out visitors their own anonymous key. On logout, remove the signed-in user's key. If a legacy unscoped `beancount-query-history` value is found, drop it once instead of adopting it into whichever account loads first. Keep the history's behavior within a single session as it is today (newest first, de-duplicated, at most 50, malformed values recovered per w4/272).

## Acceptance

- After the repro's sign-out, the signed-out example query page shows no prior history, and no `localStorage` key holds the previous user's query strings.
- Two accounts that sign in one after the other on one browser each see only their own history.
- A dashboard test covers the logout clear and the per-user key. It fails against the current code.

# Report a misspelled GROUP BY key as an unknown column, not as an ungrouped select column

**Severity:** minor. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-15 against `https://beancount.io` (the deployment's `/.well-known/mcp.json` reports `revision: unknown`; local HEAD `4cd2197dc`), headless Chromium, signed in as the QA account.

## Repro

1. Open `/ledger/open_ledger/example/query` (any ledger reproduces it).
2. Run `SELECT account, count(*) GROUP BY accnt`, where `accnt` is a typo for `account`.

**Actual:** the dashboard says "“account” must be listed in GROUP BY or wrapped in an aggregate such as sum() or first()." The MCP `runBqlQuery` tool returns the source text: `BAD_USER_INPUT: Invalid BQL query: Bare column "account" is not grouped and not aggregated … Add "account" to GROUP BY …`. The user has already put that column in GROUP BY, with a spelling mistake, so the message points at the wrong clause and never names `accnt`.

**Expected:** the same error as the controls below: the dashboard's "Unknown column “accnt”. Check its spelling …", or `column 'accnt' not found` over MCP.

**Controls (same session):** `SELECT count(*) GROUP BY accnt` and `SELECT accnt, count(*) GROUP BY accnt` both report the unknown column `accnt`, from the engine. They have no uncovered bare select column, so the guard stays out of the way.

## Root cause

`backend-cluster/ledger/src/foundation/rustledger/engine.ts` (the `refused` chain, about line 1076) runs `groupByCoverageError(query)` before `ledger.query(query)`. `group-by-coverage-guard.ts` compares the select items with the GROUP BY keys by text only. `accnt` covers nothing, so `account` counts as uncovered and the guard refuses the query before the engine can report that the key does not exist. The guard is meant to stop silent first-row picks in queries that would otherwise run (w23/131), not to replace the engine's compile errors.

## Fix

Owned by `backend-cluster/ledger`, so REST, GraphQL, MCP and the dashboard all get the fix at once. When a query fails the coverage check, let the engine compile or run it first. If the engine returns its own error (an unknown column, an unknown function), return that error. Refuse with the bare-column message only when the engine would have answered with rows. Moving only this guard after `ledger.query` is enough. The engine already answers these queries without crashing; that is the silent first-row pick the guard exists to refuse.

## Acceptance

- `SELECT account, count(*) GROUP BY accnt` returns the engine's unknown-column error for `accnt`, and the dashboard shows "Unknown column “accnt”".
- `SELECT account, date, count(*) GROUP BY account` is still refused with the bare-column message for `date` (the existing `group-by-coverage-guard` tests and the `verify:rustledger` checks still pass).
- A regression test in `backend-cluster/ledger` covers the misspelled-key case and fails against the current ordering.

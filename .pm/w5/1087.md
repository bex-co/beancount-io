# Ignore unposted rows when recalling CSV date formats

**Minor · cli · 30–45m · A1 · worker1.** A pending/declined row the importer
leaves out can falsely veto a remembered date format and recommend the wrong
one. A US-format posted purchase on **October 11** is rejected because an
ignored authorization happens to carry a day-first date. Following the
specific replacement hint books that purchase on **November 10**, with a
passing check; the reverse happens for a remembered day-first format.
Default refusals preserve ledger and memory bytes. No product fix made.

Local CLI QA, 2026-10-28, checkout `bea 0.3.1`, frontend Python 3.13.3,
existing managed Python 3.12.10 / Beancount 3.2.3 / Beanquery 0.2.0,
macOS 26.5.1 arm64. Source pinned to
`e08f21ca46c6127e897d3da54f597e15d25b7ec1`, all 1,741 CLI fingerprints
checked before/after; reviewed main `6c564a71b` has the same local importer
implementation. Fresh offline subprocesses, isolated child config/cache,

## Standalone reproduction

Put checkout `bea` on PATH. Save the script as `recipe.py` and run it twice,
using a different unused directory each time:

```sh
python3 recipe.py /absolute/unused/qa-dates-original original
python3 recipe.py /absolute/unused/qa-dates-suggested suggested
```

`original` resupplies the valid saved format; `suggested` follows the false
refusal's replacement hint in disposable data. Both retain command arguments,
streams, exits, timings and ledger/memory hashes in `results.json`.


The first CSV seeds the chosen US format with an unambiguous September 28
purchase. The next CSV's only posted date, `10/11/2026`, fits that choice.
Its `14/11/2026` authorization is Pending and should not vote on the format.
Both flag-free preview and apply instead exit **2**, stdout empty:

```text
Remembered --date-format %m/%d/%Y does not match later.csv, whose dates look
like %d/%m/%Y. Pass --date-format %d/%m/%Y (or --csv) for this file.
```

| suggested `%d/%m/%Y` | 1 | 1 | 2026-11-10 |

## Cause and repair

`cli/src/cli/commands/import_.py:1637–1645` passes `mapping.columns` to
`inspect_date_column` for fresh inference. That helper's status-aware loop
(`cli/src/cli/csv_mapper.py:943–1007`, especially :980–987) correctly ignores
mapped unposted rows. Engine extraction likewise skips them before parsing
dates (`cli/src/bea_engine/csv_mapper.py:1859–1867`, before :1892).

The recalled-choice branch instead calls frontend `infer_date_format`
(`import_.py:1676–1698`) without the mapping. Its wrapper (`csv_mapper.py:
880–900`) delegates to `inspect_date_column` without `mapped_columns`, so
`status` is `None` and the ignored row votes. The ambiguous posted cell fits
both conventions, but the ignored valid day-first cell eliminates US; the
guard mistakes that vote for proof that the saved choice no longer fits.
Supplying an explicit format bypasses that recalled-choice check, explaining
why the original format still imports correctly.

Pass the resolved mapping through this wrapper, using the same eligible-row
rules as fresh inference and extraction. Retain `also=[recalled_date_format]`
so custom choices from 911 still compete, and keep genuine convention-change
refusals, repeated-header/blank rules and existing status vocabulary. Do not
remove revalidation, automatically switch formats, or rewrite source files.
The production wrapper's caller search finds this recalled-format branch;
the engine's separately named helper is not its caller. No dependency or
backend/API change is needed.

Working controls explain the boundary: no ignored row, an ignored date in
the saved convention, and an unambiguous posted date all keep the format.
An ignored literal `Pending` date rules out every candidate, so the current
recall guard keeps memory; that older 831 case therefore passes. Automatically
inferred date formats are not persisted as explicit choices and use fresh
status-aware inference; those two end-to-end controls also pass. A real
unambiguous change in a posted row still refuses at exit 2 until the correct
new format is supplied.

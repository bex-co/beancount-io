# Review inferred-cost corrections on labelled and short openings

**Major · cli · 45–60m · A1 · worker1.** A brokerage correction under an
existing bank ID is silently skipped when its opening Stock leg has a lot
label or negative units and leaves its cost number or currency to booking.
Native Beancount uniquely determines a different lot and cash balance. The
CLI instead reports an exact duplicate, exits 0 and retains the old trade.
Do not replace the original automatically: the correction should conflict
at exit 4 and require review, like the explicit-cost control.

Local CLI QA, 2026-10-28: checkout `bea 0.3.1`, frontend Python 3.13.3,
existing managed Python 3.12.10 / Beancount 3.2.3 / Beanquery 0.2.0,
macOS 26.5.1 arm64. Immutable source
`e08f21ca46c6127e897d3da54f597e15d25b7ec1`, all 1,741 tracked CLI hashes
verified before/after; main `04aa92c06` has the same local implementation.
Closed stdin/no TTY, offline commands, isolated child config/cache, HOME
unchanged, inspected synthetic importer, no plugins. No product fix made.

## Reproduction and result

The importer owns `Assets:Stock`. There is no held Stock before this trade,
so these are openings rather than selectors reducing an existing lot. Both
original-only and correction-only references validate through an independent
native loader with caches disabled.

| Profile | Original | Correction under the same `basis-ref` | Native cash after correction | Actual |
| --- | --- | --- | --- | --- |
| Labelled long | `5 HOOL {5 USD, "Lot A"}`, Cash −25 USD | `5 HOOL {USD, "Lot A"}`, Cash −50 USD | 50 USD, rather than original 75 USD | duplicate / exit 0 |
| Short opening | `−5 HOOL {5 USD}`, Cash +25 USD | `−5 HOOL {USD}`, Cash +50 USD | 150 USD, rather than original 125 USD | duplicate / exit 0 |
| Omitted currency, labelled long | `5 HOOL {10 USD, "Lot A"}`, Cash −50 USD | `5 HOOL {10, "Lot A"}`, Cash −50 EUR | 100 USD / 50 EUR, rather than 50 USD / 100 EUR | duplicate / exit 0 |

The book starts with 100 USD and 100 EUR Cash. The numeric-cost cases keep
EUR Cash at 100. The correction's native unit cost is 10 USD in the first
two cases and 10 EUR in the third; the actual ledger retains 5 USD or 10 USD
respectively. Labelled short openings and omitted-currency shorts reproduce
the same gap. Cost-basis net worth still reconciles because cash and cost
offset; that is not evidence the old cost or cash currency is correct.

## Cause and repair target

`cli/src/bea_engine/ledger/writer.py:807–830` `_open_cost` excludes a plain
cost when `count < 0` or `cost.label is not None`. Its stated reason is that
such a posting may reduce a held lot. That safeguard also excludes these
unambiguous openings. `with_inferred_parts` (`:857–905`) therefore never
interpolates the known cost number/currency before import comparison.

`cli/src/bea_engine/importing.py:1565–1573` `_source_postings` uses that
completion, `_lot_stated` / `_lot` (`:1579–1637`) leave the omitted field as
None, and `_lots_agree` / `_legs_agree` (`:1716–1726`) accept it as a wildcard.
`_same_row` (`:2493–2516`) then treats the present bank-ID owner as the same
row. Cash is a counterposting here, outside the importer's Stock source
set, so its changed weight does not independently disprove that match.

Actual matcher traces for all 24 public profiles confirm the mechanism:
the 12 affected incoming source legs falsely agree with the original lot;
the independently booked correction disagrees in every profile. The 12
controls already disagree correctly. This is not missing ID ownership,
NFC label normalization, zero metadata, a changed label, or a reader losing
an inferred quantity: the ID is present, label is unchanged ASCII and units
are explicitly ±5 throughout.

Fix import's decision using enough native booking context to distinguish a
uniquely determined opening cost from an unresolved reduction selector.
When the incoming opening's booked source cost number/currency differs
from the bank-ID owner's, preview conflict and refuse apply atomically at
exit 4, including `--duplicates skip`; an equivalent repeat still skips.
Keep the authored spelling, source-account policy and known owner. Do not
globally complete every negative/labelled selector from cash, compare all
counter-account edits as identity changes, or turn an unresolved lot into
an arbitrary cost. Preserve multi-lot/FIFO reductions and legacy IDs.

Caller search finds only import `_source_postings` using this helper with
plain completion enabled; single-add answer serialization at
`ledger/adding.py:1432` passes `plain=False`, intentionally leaving ordinary
`{USD}` / `{10}` costs as authored. No reply defect is claimed here. This
local CLI fix needs no dependency or API change.

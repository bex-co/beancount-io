# Preserve exact inferred cents in doctor trees

**Minor · cli · 30–45m · A1 · worker1.** Real local CLI QA, 2026-10-23,
checkout `bea 0.3.1` at `7a237d2dbc32ddfaddd1cc098c43068f37b18298`, macOS
26.5.1 arm64, frontend Python 3.13.3, managed Python 3.12.10 / Beancount 3.2.3
and Beanquery 0.2.0. No product fix implemented. Latest origin was checked;
the scoped formatter, doctor command and loader are unchanged.

A stock salary of **2 HOOL at 5.25 USD** determines an inferred **10.50 USD**
income posting. `doctor linked` and plain `doctor region` display that salary
as **−10 USD** in their trees, while the same command's `Net Income` correctly
says **10.50 USD**. Native booking, BQL and the printed transaction all retain
−10.50 USD. Only the diagnostic display loses cents; the ledger is unchanged.
The bug also affects the equivalent cost-held stock acquisition.

Expected: retain these exact, meaningful cents when no explicit precision
option requests rounding. `cli/docs/USAGE.md:612–617` says these trees are
numbered from amounts in scope and agree with Net Income, including when
unrelated amounts elsewhere in the ledger are whole numbers. The scoped
formatter's own contract is "No scoped amount is rounded." Here the amount
is exactly 2 × 5.25, with no division artifact or unrelated price quote.

Put the checkout's `bea` on PATH, replace the directory with a fresh absolute
one, and run twice. The fixture has six small whole-dollar payments so USD's
whole-ledger common precision is zero. No plugin, import, dependency install,
service or real ledger is involved. Children use isolated config/cache,
closed stdin/no TTY, bounded timeouts, separate streams, durations and source
hashes. Every command preserves the book.

```python
import hashlib,json,os,pathlib,subprocess,time
case = pathlib.Path('/abs/doctor-inferred-income-case')
form = 'price'  # cost
mode = 'inferred'  # explicit
cents_context = False
case.mkdir(parents=True)
ledger = case/'main.bean'
capital = '1000.00' if cents_context else '1000'
whole = '1.00' if cents_context else '1'
text = '''option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Assets:Stock HOOL
2024-01-01 open Equity:Opening USD
2024-01-01 open Income:Salary USD
2024-01-01 * "Capital"
  Assets:Cash CAPITAL USD
  Equity:Opening -CAPITAL USD
'''.replace('CAPITAL',capital)
text += ''.join('2024-01-02 * "Whole dollars"\n'
                '  Assets:Cash '+whole+' USD\n'
                '  Income:Salary -'+whole+' USD\n' for _ in range(6))
text += '2024-01-10 * "Stock salary" ^target\n'
text += '  Assets:Stock 2 HOOL '+('@ 5.25 USD' if form=='price' else '{5.25 USD}')+'\n'
text += '  Income:Salary'+(' -10.50 USD' if mode=='explicit' else '')+'\n'
ledger.write_text(text)
line = text.splitlines().index('2024-01-10 * "Stock salary" ^target')+1
region = str(line)+':'+str(line+2)
original = ledger.read_bytes()
env = os.environ.copy()
for key in ('BEA_FILE','BEA_TOKEN','BEANCOUNT_LOAD_CACHE_FILENAME','BEA_ENGINE_PYTHON','BEA_ENGINE_DIR'):
    env.pop(key,None)
env.update(BEA_CONFIG_DIR=str(case/'config'),XDG_CACHE_HOME=str(case/'cache'),
           BEA_NO_UPDATE_NOTIFIER='1')
def run(tag,args,json_mode=False):
    cmd = ['bea',*(['--json'] if json_mode else []),'--no-input',*map(str,args)]
    started = time.monotonic()
    r = subprocess.run(cmd,cwd=case,env=env,stdin=subprocess.DEVNULL,
                       capture_output=True,text=True,timeout=25)
    print(json.dumps(dict(tag=tag,args=cmd,exit=r.returncode,stdout=r.stdout,stderr=r.stderr,
                          duration=round(time.monotonic()-started,3),stdin_mode='closed DEVNULL',tty=False,
                          source_preserved=ledger.read_bytes()==original,
                          ledger_sha256=hashlib.sha256(ledger.read_bytes()).hexdigest())),flush=True)
run('check',['-f',ledger,'check'],True)
run('fact',['-f',ledger,'query','SELECT account,units(position) WHERE date = 2024-01-10'],True)
run('linked',['doctor','linked',ledger,'^target'])
run('region',['doctor','region',ledger,region])
run('cost',['doctor','region','--conversion','cost',ledger,region])
run('value',['doctor','region','--conversion','value',ledger,region])
run('context',['doctor','context',ledger,str(line)])
```

Default `price/inferred/False`, repeated twice:

- All seven commands exit 0 with empty stderr; check passes. BQL and
  independent native booking give the selected `Income:Salary` exactly
  −10.50 USD. Native marks this posting `__automatic__` and USD common
  precision is 0; the stock posting's 2 HOOL is explicit.
- Both `linked` and `region` print the selected transaction with −10.50 USD,
  then the balance tree says `` `-- Salary -10 USD ``. Their footer says
  `Net Income: (10.50 USD)`. The 50 cents disappear between two displays of
  the same entry. `doctor context` also retains the correct −10.50.
- `region --conversion cost` retains −10.50 in its salary tree. The default
  tree should not need a conversion flag to retain an exact money amount.

Adjacent states and working controls, each form repeated twice:

- `form='cost'` changes only the stock side to `2 HOOL {5.25 USD}`. It infers
  the same salary, passes native check, and both default trees again show
  −10 instead of −10.50. Cost conversion retains the cents.
- `mode='explicit'` states `Income:Salary -10.50 USD`, changing no financial
  fact. Both default trees correctly show −10.50, even though whole-ledger
  USD common precision is still 0.
- `cents_context=True` changes only the spelling of unrelated whole amounts
  to `1000.00` / `1.00`. The selected inferred transaction is unchanged, but
  USD common precision becomes 2 and both default trees correctly show
  −10.50. Numerically identical surrounding payments should not decide whether
  this known in-scope salary loses cents.
- Value conversion retains the salary's −10.50 too. In the cost-held variant
  there is no market quote, so its separate native value-conversion footer
  remains `Net Income: (2 HOOL)`; this control is not claimed to have a USD
  value headline. The failure filed here is the unconverted salary tree.

Cause: `_context_of` in `cli/src/bea_engine/scoped.py:243–256` skips **every**
automatic posting and remembers only its currency. There is then no USD
amount learned in this scope: the other explicit posting is HOOL, despite
its known 5.25 USD cost/price determining the salary exactly. At :278–285 the
inferred-only currency is assigned the ledger's most-common precision, 0.
That fixed fallback overrides `_ExactInScope`'s maximum-precision formatter,
rounding −10.50 to −10. With an explicit salary the scoped context learns its
two decimals. With cost/value conversion the realized USD balances are
learned too, explaining those working controls.

Sixteen direct helper proofs on the public fixtures invoke `_context_of` on
the actual native-booked target. Only inferred mode with whole-number context
formats its known −10.50 as −10; cost-converted contexts format −10.50 in all
cases. Sixteen separate unwrapped native loads confirm the true Decimal,
currency, automatic flag and common precision. The real command output
independently confirms the same discrepancy. No mocked ledger or unit-test-only
failure is used.

Fix the inferred-only fallback so exact fractional money determined by the
scope is retained without learning unrelated quote precision or full division
noise. Bound inferred precision using meaningful source amounts/weights where
needed; do not solve this by rounding the correct Net Income to the wrong
tree or by learning all long automatic Decimal expansions. Preserve explicit
`display_precision` choices, exact typed amounts, and completed 571/768's
artifact controls. This is the existing scoped CLI formatter, not upstream's
whole-ledger formatter or the report/JSON amount serializer. No dependency,
API or backend change.

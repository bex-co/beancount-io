## Objective

Let customers verify the walkthrough's ledger effects with a small read-only command instead of trusting an agent's success message.

## Context

- t001 supplies expected state for the synthetic scenario.
- `skills/scripts/test_beancount_skills.py` already exercises installed `bea` and documented command recipes.
- Supported `bea` JSON reads, validation, and Git inspection provide the required observations.

## Steps

1. Add a verifier accepting an explicit workspace, root ledger, and checkpoint; use supported `bea` and Git commands.
2. Compare exact amounts, transaction identities/counts, dated assertions, and approved commit contents against the independent fixture expectations.
3. Check declined-action and read-only branches against a previously recorded state; report unavailable observations and mismatches as nonzero failures.

## Files

- `skills/scripts/verify-first-month.py` (new).
- `skills/docs/examples/first-month/` (checkpoint expectations from t001).

## Acceptance criteria

- [ ] Correct checkpoints pass; duplicate entries, wrong amounts/assertions, and unintended committed files fail with useful explanations.
- [ ] Failed commands or unreadable state never count as success or unchanged content.
- [ ] Verification does not change ledger files, the Git index, or commit history; scratch/output paths stay outside the inspected ledger.

## Out of scope

- A general accounting engine, agent runner framework, new dependencies, or imports from another package's internals.

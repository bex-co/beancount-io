# Preserve native reference semantics when an alias resembles a generated hash

**Major · cli · 35–50m · A1 · worker1.** A stable bank reference containing
`sha256:0123456789abcdef` is accepted and reported as identifier source
`bank`. The CLI automatically writes `bank:sha256:0123456789abcdef`, then
treats that alias as a canonical content hash. A later correction from
10 to 20 USD is silently skipped with exit 0. A separate payment under
the custom `receipt_id` namespace is also silently skipped when its raw
reference has the same spelling. Plain-reference controls retain amount
conflicts and namespace separation. No product fix implemented.

Environment: 2026-10-24, clean main `9c7ec87735f9a6e095c0fc946505cb7fe16cbfe5`; CLI source is
byte-identical to frozen `ee4b7702516da4535bb3b478e2efe9913b09481b`.
Checkout `bea 0.3.1`, frontend Python 3.13.3, managed Python 3.12.10 /
Beancount 3.2.3 / Beanquery 0.2.0, macOS 26.5.1 arm64. Bounded fresh
subprocesses, closed stdin/no TTY, absolute isolated configuration/cache,
notifier disabled. Inspected local importers and synthetic ledgers only.

## Standalone reproduction

Put this checkout's `bea` on PATH, save the following as `recipe.py`, and
run `python3 recipe.py /absolute/unused/book csv shape review json`.
It creates the ledger, original and corrected CSV, preserves their bytes,
imports the original, repeats it, previews/applies the correction, and
queries the independently calculable balances. `results.json` contains
argument arrays, cwd, safe environment overrides, stdin/TTY mode, separate
streams, exit codes, durations and before/after hashes.

The source reference is an opaque string, not a hash calculated from this
transaction. No importer supplies `import-id`: the CLI creates the alias.
The actual helper's content hash for the corrected source row is different
from `0123456789abcdef`.

Expected: the exact repeat skips; the same native ID with changed source
amounts previews as `conflict` and apply exits 4 without writing. The
namespace case is a new 20 USD payment and writes once, followed by Cash
970 USD and Food 30 USD. `cli/docs/IMPORTING.md:530–590` promises native-ID
amount/commodity conflicts, custom keys' own namespaces, and the separate
native versus generated-ID construction. There is no native-reference
restriction excluding this string.

Actual, from pristine directories twice for every profile:

| Mode / reference | Correction preview | Apply exit / written | Final Cash / Food USD |
| --- | --- | --- | --- |
| `csv shape` (`bank_id`) | duplicate | 0 / 0 | 990 / 10 |
| `fitid shape` (`ofx:` alias) | duplicate | 0 / 0 | 990 / 10 |
| `custom shape` (`receipt_id`) | duplicate | 0 / 0 | 990 / 10 |
| `namespace shape` (`bank_id` → `receipt_id`) | duplicate | 0 / 0 | 990 / 10 |
| Same three correction modes, `plain` (`B1`) | conflict | 4 / none | 990 / 10 |
| `namespace plain` | new | 0 / 1 | 970 / 30 |

For `csv shape`, both preview and apply say `id_source: bank`,
`status: duplicate`, and `import-id bank:sha256:0123456789abcdef is already
in the ledger.` Stderr is empty and apply exits 0 with `written: 0`.
The source CSV still says −20.00 USD and the ledger still holds only the
−10.00 USD withdrawal. Namespace shape instead creates an incoming
`receipt_id:sha256:…` alias, but its prefix-free digest finds the prior
`bank:sha256:…` row. Equity remains −1000 USD throughout; every book passes
both CLI `check` and independent uncached upstream loading.

Run each native profile with `review`, `skip` and `include`: all three
policies reproduce the false exact duplicate, while plain-reference
controls behave as above. Exact original repeats always skip with no
write. In `csv uppercase` and `csv long`, changing one hex letter's case
or adding one hex digit puts the reference outside the generated-ID
grammar; corrections correctly conflict, with unchanged bytes.

`canonical plain review json csv` creates a genuine generated ID with no
native reference, edits both ledger amounts from 10 to 12 while retaining
the ID, and reimports the original source. It correctly skips and retains
Cash 988 / Food 12. Repeat with final prefix argument `bank` or
`receipt_id`: these genuine generated-ID migration controls also correctly
skip. Their ledgers contain no native-ID metadata. Preserve all three;
globally reserving these prefixes or weakening every canonical hit would
break working behavior.

## Cause and scoped repair

In `cli/src/bea_engine/importing.py`, `_native_import_id` (:2904–2910)
concatenates the native namespace and opaque reference. The analysis loop
(:579–590) records `id_source = bank` and installs it as `import-id`.
`_identities` (:1896–1930) then adds a prefix-free digest whenever that
alias matches `_GENERATED_ID` (:1937), without proving generated origin.
`_is_generated_identity` (:1940–1941) likewise classifies only by spelling.

For the 10→20 correction, the actual `_same_row` (:2390–2417) gives:

| Shared key | Generated? | Same source row? |
| --- | --- | --- |
| `(Assets:Cash, bank, bank:sha256:0123456789abcdef)` | no | false |
| `(Assets:Cash, import-id, bank:sha256:0123456789abcdef)` | yes | true |
| `(Assets:Cash, digest, 0123456789abcdef)` | yes | true |

The generated branch returns true before amount comparison. Canonical hit
selection (:633–638) then discards the contradictory native hit. In the
namespace case only the artificial digest key is shared; plain references
share no keys. `_under_id` (:2195 onward) also treats these generated-looking
aliases as non-native. Source-location ownership checks from
[1014](./done/1014.md) do not resolve this: the alias really is written on
the correct row, but it was created from a native reference.

Keep known native references native through alias/index construction,
generated-key recognition and canonical-hit selection. An alias's lexical
shape alone must not create cross-namespace content proof or override a
real native amount conflict. Retain source-account scoping, exact-repeat
matching, opaque native strings and genuine canonical IDs after ledger
cleanup and generic-prefix migration. Do not reject these native values,
reserve `bank`/`receipt_id` globally, or turn all canonical matches into
amount comparisons.

Caller search covers `_identities`, `_declared_identities`, `_under_id`,
`_same_row`, `_is_native_identity`, reused-reference checks and the main
import analysis. The reproduced surfaces are mapped CSV bank IDs and
inspected Python importers using `fitid` and `--id-key receipt_id`. Twin
reason wording, transfer merging, multi-date reused references and other
alias origins are not independently claimed broken here.

# Preserve native reference semantics when an alias resembles a generated hash

**Major · cli · 35–50m · A1 · worker1.** A stable bank reference containing
`sha256:0123456789abcdef` is accepted and reported as identifier source
`bank`. The CLI automatically writes `bank:sha256:0123456789abcdef`, then
treats that alias as a canonical content hash. A later correction from
10 to 20 USD is silently skipped with exit 0. A separate payment under
the custom `receipt_id` namespace is also silently skipped when its raw
reference has the same spelling. Plain-reference controls retain amount
conflicts and namespace separation. No product fix implemented.

Environment: 2026-10-24, clean main `9c7ec87735f9a6e095c0fc946505cb7fe16cbfe5`; CLI source is
byte-identical to frozen `ee4b7702516da4535bb3b478e2efe9913b09481b`.

## Cause and scoped repair

In `cli/src/bea_engine/importing.py`, `_native_import_id` (:2904–2910)
concatenates the native namespace and opaque reference. The analysis loop
(:579–590) records `id_source = bank` and installs it as `import-id`.
`_identities` (:1896–1930) then adds a prefix-free digest whenever that
alias matches `_GENERATED_ID` (:1937), without proving generated origin.
`_is_generated_identity` (:1940–1941) likewise classifies only by spelling.

For the 10→20 correction, the actual `_same_row` (:2390–2417) gives:

| Shared key | Generated? | Same source row? |
| --- | --- | --- |
| `(Assets:Cash, bank, bank:sha256:0123456789abcdef)` | no | false |
| `(Assets:Cash, import-id, bank:sha256:0123456789abcdef)` | yes | true |
| `(Assets:Cash, digest, 0123456789abcdef)` | yes | true |

The generated branch returns true before amount comparison. Canonical hit
selection (:633–638) then discards the contradictory native hit. In the
namespace case only the artificial digest key is shared; plain references
share no keys. `_under_id` (:2195 onward) also treats these generated-looking
aliases as non-native. Source-location ownership checks from
[1014](./done/1014.md) do not resolve this: the alias really is written on
the correct row, but it was created from a native reference.

Keep known native references native through alias/index construction,
generated-key recognition and canonical-hit selection. An alias's lexical
shape alone must not create cross-namespace content proof or override a
real native amount conflict. Retain source-account scoping, exact-repeat
matching, opaque native strings and genuine canonical IDs after ledger
cleanup and generic-prefix migration. Do not reject these native values,
reserve `bank`/`receipt_id` globally, or turn all canonical matches into
amount comparisons.

Caller search covers `_identities`, `_declared_identities`, `_under_id`,
`_same_row`, `_is_native_identity`, reused-reference checks and the main
import analysis. The reproduced surfaces are mapped CSV bank IDs and
inspected Python importers using `fitid` and `--id-key receipt_id`. Twin
reason wording, transfer merging, multi-date reused references and other
alias origins are not independently claimed broken here.

# The file editor's Align Amounts (Edit menu and ⌘/Ctrl+D) always puts currencies at column 61 and ignores `fava-option "currency-column"`, though Ledger Settings → Fava Options shows the ledger's own value

**Severity:** minor. The ledger stays valid, but one Align Amounts realigns every posting in the file to a column the owner did not choose, and the next save commits that whole-file diff. **Owner:** `dashboard`. `common/lib/editor/monaco-beancount-actions.ts:7-9` defaults `alignAmounts(editor, currencyColumn = 61)`. Both callers pass only the editor: the ⌘/Ctrl+D command at `:118` and **Edit → Align Amounts** at `features/ledger-editor/file-editor/components/ledger-file-view/file-edit-mode.tsx:129`. The client already holds the ledger's value: `GetLedger` → `favaOptions.currencyColumn`, the same field `features/ledger-data/settings/fava-options-section` displays. **Estimate:** 30–45 minutes with tests. **A2:** someone moving a Fava ledger that sets `currency-column` (for example to fit narrower files) gets Fava's own editor command in the dashboard, with a different result.

**Found by:** `/qa-find-bugs-dashboard` (`dashboard-qa` routine) on 2026-11-27 against `https://beancount.io`, entry chunk `main-BBmi61Hs.js`, isolated headless Chromium 158 at 1440×1000, English, UTC, signed in as the QA owner on the designated synthetic ledger. Local HEAD `c0e354a9c`. Both option probes were removed again, and `main.bean` is back to its starting blob `f1a0b83`, byte for byte (restore commits `41e3132` and `c292334`). The editor buffers were discarded unsaved.

## Repro

1. Append `2026-01-01 custom "fava-option" "currency-column" "50"` to `main.bean` (probe commit `fa35835`). The ledger check stays clean.
2. **Ledger Settings → Fava Options** reads `currency_column 50`.
3. **Files → main.bean → Edit**, then the editor's **Edit** menu → **Align Amounts ⌘D**.
4. Every posting has its currency at column 61, for example `  Assets:Bank:Checking                              3000.00 USD` and `  Expenses:Entertainment:Streaming                    15.49 USD` (`USD` starts at column 61 on all six lines checked). Fava puts it at column 50: `  Assets:Bank:Checking                   3000.00 USD`.
5. **Cancel → Leave Without Saving** discards the buffer.
6. Repeat from a fresh browser context, this time pressing **⌘D** in the editor (probe commit `be746ff`). The result is the same: `USD` is at column 61 on every posting.

## Cause

Fava's command (`frontend/src/codemirror/beancount-format.ts`, `beancount_format`) reads the option on every run: `const column = store_get(currency_column); align_amounts(text, tree, column)`. The dashboard's port kept Fava's default as a parameter default and never passes the ledger's value.

## Fix

Pass `favaOptions.currencyColumn` (falling back to 61 when absent) from both call sites. `registerEditorShortcuts` should take a getter or a ref, not a mounted-time number, so an option change picked up on a later refresh applies without remounting the editor. Keep the existing minimum of two spaces before the number, and keep the string and Undo behavior from w4/1013 and w4/969.

## Definition of done

- On a ledger with `currency-column 50`, both the menu item and ⌘/Ctrl+D put every posting's currency at column 50. Without the option they put it at column 61, as today.
- A test that drives the call sites (not only `alignAmounts`' own parameter) with a non-default `currencyColumn` fails on the current code and passes with the fix. The w4/969 and w4/1013 tests still pass.
- The dashboard gates (`yarn format:check`, `yarn lint`, `yarn test`, `yarn build`) pass.

## Adjacent, not part of this note

- The dashboard editor reads no other Fava option either. Fava's editor also uses `indent`. Monaco's indentation detection usually matches it, which this run did not check.
- Structured entry writes (New Entry, REST and MCP `addLedgerEntries`) align to column 61 by design, for byte parity with the former Python service (`backend-cluster/ledger/src/foundation/rustledger/entry-build.ts`, header comment). Fava's own `insert_entry` uses the ledger's `currency_column` and `indent`. Whether to follow Fava there is a separate `backend-cluster/ledger` decision. It was not exercised live.

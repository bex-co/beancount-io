# Return import diffs that apply to the ledger

**Minor · cli · 20–35m · A1 · worker1.** `bea import` returns an invalid unified
patch when the existing ledger's tail contains a quoted U+2028/U+2029, or
when the file has no final LF. JSON preview/apply and human preview carry
the bad diff. The import itself and duplicate repeat are correct: the old
memo/source prefix remains exact, Cash becomes 95.00 USD, Food 5.00 USD,
and Equity stays −100.00 USD. Agents need the proposed diff to describe the
actual append they are reviewing. Report mode; no product fix applied.

Environment: 2026-10-29, clean main and immutable runtime
`75d9c1d45a5b8367b317f966fd0dcae79c14d86a`, all **1,745** tracked CLI paths
and bytes checked against current main and before/after each frozen run.
Checkout `bea 0.3.1`, frontend Python 3.13.3, existing managed Python 3.12.10 /
Beancount 3.2.3 / Beanquery 0.2.0 / Beangulp 0.2.0, macOS 26.5.1 arm64,
Git 2.50.1 (Apple Git-155). Fresh bounded offline processes, closed stdin/no
TTY, isolated child config/cache, HOME unchanged, synthetic books and CSV.
No optional feature was installed or enabled.

## Standalone reproduction

its existing prepared engine interpreter, and use an unused directory:

```text
python3 recipe.py /absolute/unused/unicode u2028 /absolute/checkout/cli/.venv/bin/bea /absolute/existing/engine/bin/python
python3 recipe.py /absolute/unused/eof no-final-lf /absolute/checkout/cli/.venv/bin/bea /absolute/existing/engine/bin/python
```

`u2029` reproduces the other quoted separator; `space` is the working
LF-terminated control. The literal separator belongs to the existing
opening narration, not the CSV. The CSV adds one 5 USD grocery expense.
Preview leaves the ledger unchanged, apply runs once, and the repeat writes no rows.
Git checks the returned preview against an immutable copy of the original;
a separate Git diff of actual before/after bytes is checked against the same
copy. Only filename headers are normalized to `main.bean`; hunk bytes are
unchanged, and `git apply --check` never applies a patch or resets a write.
All streams, exits, arguments, safe overrides and source hashes are recorded.

for key in ('BEA_FILE', 'BEA_TOKEN', 'BEANCOUNT_LOAD_CACHE_FILENAME', 'BEA_ENGINE_PYTHON', 'BEA_ENGINE_DIR'):

def save():

    control = patchbook.read_bytes()

    r = subprocess.run(list(map(str, args)), cwd=cwd, env=ne, capture_output=True, text=True, timeout=25, **mode)
    p[kind].append(dict(stage=stage, args=list(map(str, args)), cwd=str(cwd), env=env | {'BEA_NO_UPDATE_NOTIFIER': '1'}, stdin_mode='DEVNULL' if stdin is None else 'piped patch', tty=False, exit=r.returncode, stdout=r.stdout, stderr=r.stderr, stdin=stdin, duration=round(time.monotonic() - tick, 3), before_sha256=hashlib.sha256(before).hexdigest(), after_sha256=hashlib.sha256(book.read_bytes()).hexdigest()))

    p['active'] = None

    return capture if human else json.loads(r.stdout)['data']

## Actual and expected

With U+2028/U+2029, the returned hunk starts at physical line **6** and its
first context is ` continued"`, a fragment of the opening narration that
is not a physical source line. The correct hunk starts at **5** and includes
the complete dated opening header. Git exits **1**:

```text
error: patch failed: main.bean:6
error: main.bean: patch does not apply
```

Without a final LF, the old last line is emitted without a terminator or
`\ No newline at end of file`; joining the following added line corrupts
the patch. Git exits **128**, `error: corrupt patch at line 14`.
The independently Git-built patch passes (exit **0**) for every fixture,
as does the CLI patch for the otherwise identical space/LF control.

All CLI calls exit **0**. Each preview is `ready: 1`, `written: 0`; apply
is `written: 1` and returns the same diff; repeating the remembered import
is `written: 0`, `duplicates: 1` with unchanged bytes. The original source
prefix and memo survive, the new transaction has exactly −5.00 USD Cash /
+5.00 USD Food, and uncached native checks stay valid with two transactions.
The paired LF/no-final-LF cases finish byte-identically in both matrix
repetitions: repairing the append's final newline is already correct.

Evidence: **8 fresh books / 48 CLI / 16 native**, two repetitions ×
space/U+2028/U+2029/no-final-LF — **6 affected / 2 controls**. The exact
public recipe adds **4 books / 28 CLI / 8 native**, **3 affected / 1 control**.
Combined **12 books / 76 CLI / 24 native / 12 human previews**,
**9 affected / 3 controls**. All actual-file control patches pass.

## Cause, callers and repair

Producer: `cli/src/bea_engine/importing.py:995–1003` builds `preview.diff`
inline from `original.decode("utf-8").splitlines(True)` and
`proposed.splitlines(True)`. Python treats U+2028/U+2029 as extra line
boundaries, inventing hunk positions/context. Its installed 3.12.10
`difflib.unified_diff` also prefixes unterminated input lines without
emitting standard EOF markers; joining those yields a malformed patch.

The proposed bytes are separately produced by `ledger_write.decoded_append`
(`importing.py:894–895`, `ledger/write.py:4101`), and apply writes that valid
append. The error is the returned patch. Engine dispatch is
`bea_engine/main.py:638`; `cli/src/cli/commands/import_.py:2064` JSON-encodes
the payload, and `:2118–2121` prints the same diff in human preview.
`cli/docs/IMPORTING.md:43` promises a unified ledger diff; the frontend also
explicitly describes its context as the existing ledger's own tail, byte for
byte. Both output forms were exercised. The common producer serves other
native/configured/OFX import paths; those formats were not rerun for this case.

# Explain the pinned Beangulp reverse-extraction limitation

**Minor · cli docs/help · 25–40m · A1 · worker1.** With the managed
Beangulp **0.2.0**, `bea ingest extract --reverse` and `-r` exit 0 but
serialize entries oldest first. Help advertises “Sort entries in reverse
order.” The cause is upstream: bea forwards both flags faithfully. Add a
version-specific explanation and the working custom-sort recipe to bea's
help/guide; preserve native forwarding and custom scripts. No product fix,
engine installation, dependency change or upstream message was made.

Environment: 2026-10-27, bea 0.3.1, macOS 26.5.1 arm64, frontend Python
3.13.3, existing managed Python 3.12.10 / Beancount 3.2.3 / Beangulp 0.2.0.
Executed immutable CLI source `0c2c69bd09407962f0a51e17411155acfcca035c`;
all **1741** tracked CLI files match current main at `e0cfddfc016a0aa8d8f2dca4806c91e45082bfb7`.

```python
def sort(self, entries, reverse=False):
```

This override always asks that importer for newest-first output. It is a
configuration choice, independent of the ignored CLI flag; do not describe
it as making Beangulp's flag work.

## Root cause and documentation target

The lock and manifest both select **`beangulp==0.2.0`**:
[`manifest.json`](../../cli/src/cli/engine/manifest.json) and
[`engine-optional-beangulp.lock`](../../cli/engine-optional-beangulp.lock).
In that installed version, `beangulp.__init__._extract` (line **57**) accepts
`reverse` but never references it in its body. It calls
`extract.extract_from_file`, which invokes `importer.sort(entries)` with
its default argument; `Importer.sort` supports `reverse=True`, as the
working custom importer demonstrates. Direct native execution reproduces
the ignored flag, establishing the dependency boundary.

The first-party chain is correct:
[`ingest._forward`](../../cli/src/cli/commands/ingest.py#L110) passes
`[operation, *ctx.args]` to
[`run_optional_script`](../../cli/src/cli/engine/launch.py#L312), whose
line 330 starts `[python, script, *args]`. No frontend/backend sorting bug
or missing argument is claimed.

Make the pinned behavior discoverable in the **bea-specific guidance** of
`ingest extract --help` and the relevant local workflow in
[`IMPORTING.md`](../../cli/docs/IMPORTING.md) /
[`USAGE.md`](../../cli/docs/USAGE.md): the native option is currently
ignored in Beangulp 0.2.0; the shown importer override yields newest-first
output. Keep the native help visible and regenerate `REFERENCE.md` via
`make docs` if the owning command docstring changes. Revisit the note when
the pinned dependency changes.

Do not fork a native serializer, install a new dependency, patch the user's
script, silently reverse every extraction, or blanket-reject `-r`: an
arbitrary ingest script may already implement its own flag behavior.
This task is the version-specific help/docs clarification and verified
workaround; repairing upstream's implementation is separate work.

# Documents ignores the Time, Account and filter scope: Events for August → Related Pages → Documents keeps `?time=2026-08` in the address but lists February's statement too, and offers no filter field, though `getLedgerDocuments` filters by all three

**Severity:** minor. **Owner:** `dashboard`. **Estimate:** 20–30 minutes including tests. **A2:** a user looking for one month's statements, or one bank's, gets every document the ledger has ever recorded, in date order, with no way to narrow the list. The address bar and the Related Pages links still say a filter is on: Events → Documents → Journal goes from August, to everything, back to August. Events and Statistics, Documents' neighbours in the sidebar, honour the same scope. **Found by:** `/qa-find-bugs-dashboard` (`dashboard-qa` routine) on 2026-11-28 against `https://beancount.io`, production entry chunk `main-BBmi61Hs.js`, local HEAD `8f66924bb`. Isolated headless Chromium 158 at 1440×1000, English, signed in as the QA owner on its designated disposable ledger `<qa-owner>/mcp-agent-eval`. Two `document` lines were added for the check and removed again: `main.bean` was restored byte for byte (probe commit `dd2eb86e`, restore commit `fab768e0`, blob `f1a0b83c` again, no ledger errors).

## Repro

Add to the ledger (any existing file works as the target; here the ledger's own `main.bean`):

```beancount
2026-02-01 document Assets:Bank:Checking "main.bean"
  qa-probe: "qa-20261128-r2 February statement"
2026-08-01 document Assets:Cash "main.bean" #qa-20261128-r2
```

The ledger reports no errors.

1. Open `/ledger/<owner>/<ledger>/events?time=2026-08`. The header shows Time `2026-08`.
2. Under **Related Pages**, choose **Documents**. The address is `/documents?time=2026-08`. The header has no Time, Account or filter field. The table lists **both** rows: `2026-02-01 Assets:Bank:Checking` and `2026-08-01 Assets:Cash`.
3. Its **Related Pages → Journal** link is `/journal?time=2026-08`, and the Journal opens filtered to August again.
4. Loading `/documents?account=Assets%3ABank` or `/documents?filter=%23qa-20261128-r2` directly also lists both rows. Every `GetLedgerDocuments` request the page sent had only `{"ledgerId": …}` as variables.

API control on the same ledger: `getLedgerDocuments(ledgerId, time: "2026-08")` returns only the 2026-08-01 row, `account: "Assets:Bank"` only the 2026-02-01 row, and `filter: "#qa-20261128-r2"` only the 2026-08-01 row.

## Cause

- `dashboard/src/features/ledger-data/documents/index.tsx:142-149` calls `useQuery(GetLedgerDocumentsDocument, { variables: { ledgerId } })`. Its own operation (`documents/graphql/documents.graphql`) declares `$time`, `$filter` and `$account`, and the resolver passes them through (`backend-v2` `ledger-data-resolver.query.ts` `getLedgerDocuments`). The page never reads `useLedgerSearchParams()`.
- `common/components/ledger-layout/ledger-filter-pages.ts:2-10`: `FILTERED_PAGES` lists Journal, the four statements, Events and Statistics, but not `documents`, so the header shows no filter controls there. The list was a substring check until w4/1102 made it exact. That change kept the existing pages and did not decide anything about Documents.

## Fix

- Pass `time`, `filter` and `account` from `useLedgerSearchParams().searchParams` to `GetLedgerDocuments`, as `features/ledger-data/events/index.tsx:58-66` does.
- Add `"documents"` to `FILTERED_PAGES`, so the header offers the controls that now apply.
- Give the empty state the Events distinction (`events/index.tsx:126-131,160-172`): under an active filter, say no documents match the filters (a new `page.documents.*` key in all 15 catalogs), not "No documents found in this ledger."
- Tests: a rendered Documents test asserting the request variables follow the URL's `time`/`account`/`filter`, and the filtered empty-state copy. Extend `ledger-filter-pages.test.ts` with `/documents` (shown) and a Files path containing `documents` (still hidden). Both fail on current code.

## Definition of done

With the two documents above, `/documents?time=2026-08` lists only the 2026-08-01 row and shows Time `2026-08` in the header. `?account=Assets:Bank` lists only the 2026-02-01 row. A filter that matches nothing says so in its own words. Clearing the filter lists both. Events → Documents → Journal keeps one scope throughout. Dashboard gates pass.

## Blast radius

`GetLedgerDocuments` has one dashboard caller. The Journal's Document rows already follow the filters. `shouldShowLedgerFilters` is used only by `layout-header.tsx`. Mobile has no Documents screen (no `GetLedgerDocuments` use outside generated types). REST's `documents` read already passes the same filter query to the shared service (`backend-v2` `analysis-handler.ts:131-136`), so this is a dashboard-only gap with no API change.

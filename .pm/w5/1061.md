## Reproduce and check the units

Create a100USD cash ledger with opened USD Cash/Food/Opening accounts and
import a bank OFX row containing:

```xml
<CURDEF>USD</CURDEF>
<!-- inside BANKTRANLIST -->
<STMTTRN>
  <TRNTYPE>DEBIT</TRNTYPE>
  <DTPOSTED>20240102</DTPOSTED>
  <TRNAMT>-10</TRNAMT>
  <FITID>FX-001</FITID>
  <NAME>Foreign cafe</NAME>
  <CURRENCY><CURRATE>1.20</CURRATE><CURSYM>EUR</CURSYM></CURRENCY>
</STMTTRN>
```

The current primary [OFX Banking2.3 specification, §5.2 and
§11.4.4.1](https://financialdataexchange.org/wp-content/uploads/2025/12/OFX-Banking-Specification-v2.3.pdf)
defines row `CURRENCY` as overriding row amount units, with `CURRATE` giving
CURDEF units per CURSYM unit. `ORIGCURRENCY` instead describes values already
converted. Both alternatives belong to STMTTRN. Therefore this row is10EUR,
and its effect on a USD account is12USD; assigning USD to the raw10 changes
its value. This expectation is calculated from the statement's declared rate.

From that directory, with isolated child `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`
and `BEA_NO_UPDATE_NOTIFIER=1`:

```sh
bea --json --no-input --offline --file /absolute/books/main.bean import /absolute/books/statement.ofx --ofx --account Assets:Cash --default-account Expenses:Food
bea --json --no-input --offline --file /absolute/books/main.bean import /absolute/books/statement.ofx --ofx --account Assets:Cash --default-account Expenses:Food --apply
bea --json --no-input --offline --file /absolute/books/main.bean query 'SELECT account,SUM(number) GROUP BY account ORDER BY account'
bea --json --no-input --offline --file /absolute/books/main.bean check
```

All exit0. Cash is90USD and Food10USD; the independent converted reference
is Cash88USD/Food12USD. No exchange-rate or unsupported-currency advisory
appears. With a matching categorization rule the imported row is reviewed `*`,
not merely an uncategorized review-queue placeholder. Preview and apply report
empty validation errors/warnings; the human preview explicitly labels
the source amount USD. Re-import writes0, preserving the already wrong entry.

Expected for the bounded repair: preview and apply refuse this unsupported
foreign `CURRENCY`, name the source/OFX row and source/default currencies,
and leave every ledger byte unchanged. Point to an already-converted export
or a custom importer that handles the currency override. Do not silently
relabel it, skip it, or import the other rows from the same file first.

Save this exact verified recipe as `recipe.py`, put checkout bea on PATH,
and run `python3 recipe.py /absolute/new/case unconverted bank explicit json standard USD /absolute/managed-engine/bin/python`.
It supplies the complete synthetic bank/card response, matched rules,
isolated environment, complete command/stream/effect captures, native before,
after and semantic-reference checks. Use `converted`, `plain` or `mixed`,
`card`, `auto` or `configured`, `human`, `renamed`, or `EUR` in fresh directories.
The configured route explicitly instantiates bea's own OfxImporter; this is not
a claim about arbitrary third-party importers.

## Variants and controls

selection, and a Python CONFIG containing `OfxImporter`. Bank OFX and card
QFX XML responses behave alike. With a card the cash stays100, but debt is
only−10USD instead of−12USD, giving the same wrong90USD net worth.

A renamed-root EUR ledger with a10USD override at0.80EUR/USD instead imports
10EUR rather than8EUR: net worth90EUR instead of92EUR. Thus the sign of the
misstatement depends on the declared conversion, not a hard-coded expectation.

The mixed source puts an ordinary5USD row before the unconverted10EUR row.
All three routes write both: expenses15USD/net worth85USD instead of17USD/83USD.
The repair must refuse the source atomically, retaining its original100USD
ledger; it must not append the first row before discovering the second one.

Working controls retain12USD (or8EUR): a plain row in CURDEF, and an already
converted row carrying `ORIGCURRENCY`. Their signs, matched flags, exact
FITID repeat detection, reports and file effects remain correct. A broad
refusal of every currency-related aggregate would break these controls.
Valid separate CURDEF statements remain supported as shown by the retained

## Producer, callers and fix boundary

Installed Beangulp `examples/importers/ofx.py:217–239` yields each statement's
CURDEF. Its `build_transaction:261–302` reads TRNAMT and constructs
`Amount(number, currency)`, without inspecting CURRENCY/CURSYM/CURRATE.
An actual unwrapped upstream run confirms the parsed override is EUR/1.20
while its result is `-10 USD`. The primary spec, rather than that limited
example importer, supplies the semantic control.

`cli/src/bea_engine/ofx_importer.py:182–193` passes that statement currency
to `_build_row`; `:203–205` copies the same raw magnitude/currency into the
counter posting. `_build_row:236–257` checks presence and parseability of date
and amount, then calls upstream; it has no currency-override check. The import
preview, append serializer and fresh reports therefore all consistently show
the wrong value. Native balance checking cannot infer the ignored OFX units.

Add the unsupported-override check to the shared adapter before it returns
any extracted rows: inspect the row's direct CURRENCY aggregate and refuse
unsupported foreign units with the row/currency details. Preserve ORIGCURRENCY
and plain CURDEF handling, the opt-in feature gate, matching rules and source
identity policy. Extend the real-command tests with foreign and mixed sources
and their converted controls; run `make check-all` in `cli/` when implementing.
Keep currency parsing upstream; no automatic conversion feature, dependency,
API, CLI flag or new importer framework is required.

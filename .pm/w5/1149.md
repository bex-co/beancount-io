# Overview's "Last entry … (N years ago)" reads the Time filter's last entry as the ledger's, so a filtered view of an active ledger calls it long dormant

**Severity:** minor (a false claim about the ledger). **Owner:** dashboard. **Estimate:** 20–35 minutes. **A2:** a reader who narrows a live ledger's Overview to last year should not be told the ledger's data stopped long ago. The line is new in the Overview redesign (`aabf2eced`, 2026-11-16). **Found by:** `/qa-find-bugs-dashboard` on 2026-11-16 against `https://beancount.io`, using headless Chromium at 1440×1000 in English/light, signed in as the QA owner and reading the public `open_ledger/fedex` and `open_ledger/example` ledgers. Read-only. Local HEAD `20bb98143`.

## Repro

1. Open `/ledger/open_ledger/fedex` with no filters. The month header reads **SEPTEMBER 2026 · Last entry Sep 30, 2026 (6 weeks ago)**.
2. Open `/ledger/open_ledger/fedex?time=2024`. The header reads **MAY 2024 · Last entry May 31, 2024 (2 years ago)**.
3. Open `/ledger/open_ledger/fedex?time=2025`. It reads **Last entry May 31, 2025 (last year)**.

The ledger's last entry is still Sep 30, 2026; only the Time filter ends earlier. The same happens on `open_ledger/example?time=2016`: "Last entry Dec 31, 2016", while the ledger's last entry is Sep 8, 2017. Reproduced on fresh loads of each URL.

## Cause

`dashboard/src/features/reports/overview/index.tsx:220-226` computes `dataThrough` from `useDataThrough({ account, filter, time })`, which reads the newest transaction **under the dashboard's filters** (`lib/recent-transactions.ts`). `components/month-summary.tsx:57-75` then calls `isLedgerDormant(dataThrough, today)` (`lib/overview-utils.ts:657`, more than 45 days) and renders `page.overview.lastEntry`. Its translator note (`dashboard-translations.ts:78`) says the line is "Shown when a ledger's data stopped long ago" and `{date}` is "its last entry's date". A past Time filter always ends more than 45 days ago, so every such view claims the ledger is dormant. An account or payee filter does the same with that account's or payee's last entry.

The filtered `dataThrough` is still right for its other uses (the opening month, the "data through" mark, and the Financial position date), so only the dormancy line is wrong.

## Fix

Decide dormancy and the "Last entry" date from the ledger's newest transaction with **no** account, filter or time. That is the same query `useDataThrough` makes with empty filters, and the unfiltered page and the route loader already issue it. Keep the filtered `dataThrough` for everything else. Under a filter, an active ledger shows no "Last entry" line, and a dormant one shows its true last entry (for example, Sep 8, 2017 on `example?time=2016`).

## Definition of done

- `/ledger/open_ledger/fedex?time=2024` shows no "Last entry" line, and the unfiltered page is unchanged.
- `/ledger/open_ledger/example?time=2016` shows "Last entry Sep 8, 2017 (…)", the same line the unfiltered page shows.
- A `month-summary` or Overview test covers a past Time filter on an active ledger (no dormancy line) and on a dormant ledger (the ledger's real last entry), and fails against the current code.

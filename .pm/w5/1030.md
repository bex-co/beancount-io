# Resolve decimal reference values copied from transaction listings

**Minor · cli · 20–35m · A1 · worker1.** A valid numeric `ref` printed as
`0.00000001` in source and `bea list transaction` cannot be used as Update's
`--id`: preview and apply refuse it as unknown, exit 2. The hidden Python
Decimal spelling `1E-8` resolves the same transaction. Negative/scaled small
refs and a numeric `import-id` fail in the same way; ordinary decimals,
integers, dates and string refs work. Files and money remain correct; this
blocks an agent copying the CLI's own returned identity. No product fix implemented.

Real local CLI QA, 2026-10-25, clean main
`25796afd7426fb7484dd4684c9965860d3a5f4ca`; runtime identical to frozen
`94cb785b1319e309134a7f79af9922186c07751a` (1,630 tracked CLI files).
Checkout `bea 0.3.1`, frontend Python 3.13.3, existing managed Python 3.12.10 /
Beancount 3.2.3 / Beanquery 0.2.0, macOS 26.5.1 arm64. Fresh bounded
subprocesses, closed stdin/no TTY, isolated absolute config/cache, notifier off.
Synthetic local books; no plugins or services.

Repeat in another unused directory with `human`. Other affected modes are
`negative`, `scaled`, `numeric-import-id`; `threshold`, `integer`, `date` and
`string` are controls. The script first tries the source/listed spelling, then
tries the working native exponent spelling in the affected modes. It records

## Cause, scope and dedupe

`cli/src/bea_engine/ledger/updating.py:84–93`, `_metadata_values`, uses
`str(value)` for every non-string value. For a small Decimal, that produces
scientific notation. `locate_transaction` (:143–144) then compares the supplied
id literally against only that spelling for both `import-id` and `ref`.
In contrast, `reader.metadata_to_json` at
`cli/src/bea_engine/ledger/reader.py:534–546` deliberately returns
`format(value, "f")` for Decimal metadata. The source/listing stays correct;
the new locator's comparison chooses a different representation.

`_metadata_values` has one caller, the key loop in `locate_transaction`.
Single and batch Update both resolve through this locator; the live cases
exercise the single command. Preserve the existing lookup forms and add the
canonical fixed-point Decimal form used by the metadata serializer. Do not
parse/reinterpret arbitrary string IDs, alter dates, coerce the values to
binary floats or drop ambiguity/precedence checks. No dependency or engine
fork is needed. The typed-ref test currently covers integer 42 only.

Dedupe: searched **5,643 board Markdown files / 43 non-done milestone
scopes**, including blocked and completed queues, callers and targeted history.
The new locator comes from `42c612c21`; no later repair or pending scope owns
this mismatch. Completed [w22/m1](../w22/done/m1/README.md) contains the
integer typed-ref test but not small Decimal lookup. [943](./943.md) remains
open for importer numeric-ID identity across write/reload (different matcher,
including duplicate-payment risk); this finding neither imports nor changes

[1015](./1015.md) is typed metadata/provenance serialization, not lookup.
The serializer works here. Completed [062](./done/062.md) handles native-tool
file:line path routing; this id is metadata. Keep these independent repairs
and their existing history intact.

Acceptance: all four affected copied values preview/apply successfully and

# Files: a link to a folder that does not exist answers HTTP 200 "Failed to load directory contents" with a Try Again that reloads the page into the same error

**Severity:** minor. **Owner:** dashboard. **Estimate:** 40–60 minutes including SSR status tests. **A2/A3:** a stale or mistyped folder link, a folder another client just removed, or a file path pasted under `/files/tree/` should say the folder is not there and point somewhere useful, as a missing file already does. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-18 against `https://beancount.io` (entry chunk `main-LGv2TZLj.js`), headless Chrome at 1440×1000, English/light, signed in as the QA owner. Read-only. Local HEAD `73a6d7599`.

## Repro

| URL (under `/ledger/open_ledger/example`) | HTTP | page | `GetLedgerDirContent` |
| --- | --- | --- | --- |
| `/files/tree/main` (control) | 200 | listing | entries |
| `/files/blob/main/nope.bean` (control) | **404** | "File not found: nope.bean · **Browse parent directory**" | — |
| `/files/tree/main/nope-dir` | **200** | "Failed to load directory contents · **Try Again**" | `NOT_FOUND`, "Directory 'nope-dir' not found", hint "List its parent directory … names are case-sensitive" |
| `/files/tree/main/main.bean` | **200** | the same failure | `NOT_FOUND`, hint "'main.bean' is a file, not a directory: read it with readLedgerFiles, or list its parent directory." |

The same happens on the QA account's own private ledger (`/files/tree/main/qa-nope-folder`). Activating **Try Again** reloads the document once (one main-frame navigation), and the page comes back with the same failure, so the button can never succeed. Repeated from fresh loads.

## Cause

- `dashboard/src/routes/ledger.$ledgerOwner.$ledgerName.files.tree.$branch.$.tsx` has no loader. A missing directory is discovered only during client render, after SSR has sent 200. The blob route instead runs `fileLoader` (`features/ledger-editor/file-editor/loader.ts`), which turns `null`/`NOT_FOUND`/`BAD_USER_INPUT` into `notFound()` and renders `FileNotFound` (w3/629).
- `features/ledger-editor/directory-browse/components/ledger-directory-view.tsx:172` sends every read error to `DirectoryError` (`:76-93`). That view shows a generic failure and a **Try Again** that calls `window.location.reload()` (`:88`). `dashboard/AGENTS.md` asks for a failed read to retry its own query in place, never by reloading the document (w4/m50).
- Since w23/014 the API answers a named directory that does not exist with `NOT_FOUND` (`backend-cluster/backend-v2/src/features/ledger/utils/directory-listing.ts:15-41`), and it says when the path is a file. w4/done/1104 handled this only for the redirect after deleting a folder's last file. Mobile handles a gone folder by stepping up (w21/done/088). The web route still treats it as an outage.

## Fix

Mirror the blob route. Add a cache-first loader to the tree route that reads `GetLedgerDirContent` with the view's exact variables. On `NOT_FOUND`:

- if the path is a file (the error says so, or a `GetLedgerFile` read finds one), redirect to `/files/blob/main/<path>`;
- otherwise throw `notFound()` and render a "Folder not found: <path> · Browse parent directory" view, with no ledger head and `noindex`, matching `FileNotFound`.

Real transport and service failures keep an error view, but its **Try Again** should `refetch()` in place (`useQueryRetry`) instead of reloading the page. Add the new strings to all 15 locales.

## Definition of done

- `…/files/tree/main/nope-dir` answers **404** with "Folder not found" and a working **Browse parent directory**. `…/files/tree/main/main.bean` lands on the file view for `main.bean`. `…/files/tree/main` stays 200.
- A failed directory read (mocked) still shows an error, and its Try Again refetches without a document reload.
- Route and SSR tests cover all three cases and fail without the change. Dashboard gates pass.

## Dedupe

Searched `.pm/**` for "Failed to load directory contents", DirectoryError, missing folder/directory and `files/tree`. w3/done/629 fixed the missing *file* case and listed a missing folder (then `[]`, "This directory is empty") as an acceptable control. That was before w23/014 made the API answer `NOT_FOUND`. w4/done/1104 fixed only post-delete navigation and lists "external/background folder removal" as unverified. w21/done/088 is mobile. Not deployment lag: HEAD's tree route has no loader, and the view still reloads.

## Unverified

Signed-out public visitors (the route head already sets `noindex`), Firefox and Safari, and folders nested more than one level deep.

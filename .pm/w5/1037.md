# Preserve quoted CSV reference line breaks before transaction lookup

**Major · cli · 20–35m · A1 · worker1.** A valid CSV update mapping targeting
`statement\n2026` silently loses its embedded line break and selects
`statement2026` instead. If both references exist, preview offers the wrong
row and apply changes that other transaction, exit **0**, with no rejection.
The reproduced mapping categorizes a **20 USD taxi** instead of the intended
**10 USD coffee**. JSON and single-row updates preserve the identity and
select Coffee correctly. Mapping inputs stay unchanged; no product fix.

Expected: parse CSV records without changing a quoted field's contents.
The mapping above must select Coffee with its exact multiline metadata,
just as the native loader, scalar request and JSON mapping do. A nonexistent
exact ID must remain a rejected row rather than matching another ID after
normalization. [Python's CSV reader documentation](https://docs.python.org/3/library/csv.html#csv.reader)
requires preserving newline handling, and
[RFC4180 §2](https://www.rfc-editor.org/rfc/rfc4180.html#section-2)
documents quoted fields containing line breaks. The independent
`csv.DictReader(io.StringIO(text, newline=""))` control recovers exactly the
requested ID before invoking the CLI.

Root: `cli/src/cli/commands/update.py::_rows_from_csv:167` supplies
`csv.reader(text.splitlines())`. `str.splitlines()` removes the LF before
the CSV parser can distinguish a quoted embedded break from a record
separator, concatenating `statement` and `2026`. The row dict therefore
already contains the different ID. `_load_mapping:194–205` passes it to
`update_transactions:293`, then the normal engine locator correctly finds
the wrong, flattened ID. `ledger/updating.py::locate_transaction:115–149`
does exact metadata matching and has no way to recover discarded input.
Its `ref` and `import-id` paths both reproduce. This parser has one direct
caller, `_load_mapping`; both file and stdin enter through shared
`cli.rows.read_text`, which decodes raw UTF8 bytes without losing these LFs.
The JSON branch uses `parse_json` and preserves them.

Fix in `cli/`: feed the CSV reader a text stream that retains field line
breaks, such as `io.StringIO(text, newline="")`, rather than a stripped
physical-line list. Preserve supported CSV quoting, exact ID values, blank
rows/cells, field validation and documented per-row partial behavior.
Do not flatten metadata IDs in the engine or compensate with fuzzy lookup.
No dependency, generated client, backend or API change is needed.

There is a second lossy operation at
`commands/update.py::_rows_from_csv:187`: the row dict applies
**`cell.strip()` to the id value**, just as it does to account/flag cells.
For the space-only cases, the ordinary CSV parser recovers the requested
ID unchanged even with the existing line splitter; the later `.strip()`
then selects the other transaction. A newline-preserving stream therefore
fixes the interior-LF trigger but does not fix these space cases, or an LF
at the edge of a field. Keep ID values exact when constructing the row,
while retaining intentional structural header/account/flag handling and
the existing error for an entirely blank ID. Never normalize an exact ID
into another transaction's ID.

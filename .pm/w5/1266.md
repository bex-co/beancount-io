# A Journal row's `#tag` and `^link` are drawn in the accent color but are not controls: clicking `#trip-boston-2017` opens Entry Context instead of filtering by it, as Fava's Journal does

**Severity:** minor. Tags and links are the main way a ledger groups entries across accounts (a trip, an invoice, a reimbursement), and they are the one part of a Journal row drawn in the accent color. Nothing in them responds: a click falls through to the row and opens Entry Context, no keyboard stop reaches them, and the only way to filter by one is to type it into **Filter by tag, payee, …**. In Fava's Journal a click on a tag or link adds it to the filter (`frontend/src/reports/journal/click_handler.ts`, `add_filter`), and the dashboard still carries Fava's `tag`/`link` class names (`journal-description/transaction-description.tsx:34-46`) without the behavior. **Owner:** `dashboard` (`features/journal`). **Estimate:** 45–60 minutes including tests. **A2:** a reader who sees `#trip-boston-2017` under a row has no direct way to ask "what else was on this trip?".

**Found by:** `/qa-find-bugs-dashboard` (`dashboard-qa` routine) on 2026-11-27 against `https://beancount.io`, entry chunk `main-BBmi61Hs.js`, isolated headless Chromium 158 at 1440×1000, English, browser zone America/Mexico_City. Read-only, as the QA owner on the public `open_ledger/example` ledger. Local HEAD `20e7c819b`; the row components were last changed on 2026-11-23 and have never handled a click on a mark, so this is not deployment lag.

## Repro

1. Open `/ledger/open_ledger/example/journal?filter=payee:"Starbucks"` (Compact, the default). Rows from May–June 2017 show `#trip-boston-2017` in green (`text-primary`) after the narration.
2. Click `#trip-boston-2017`. The Entry Context dialog opens ("Starbucks · Thursday, May 25, 2017 · Source and file location…"). The URL and filter are unchanged.
3. Switch to **Comfortable** and click the tag under a row. Same: Entry Context ("Saturday, June 3, 2017"), filter unchanged.
4. Open `/account/Liabilities:US:Chase:Slate?filter=%23trip-boston-2017` and click a row's tag. Same.
5. The marks are plain `<span>`s with no role and no tab stop, so the keyboard cannot reach them either.

Repeated from a fresh load. Typing the same expression works: `?filter=payee:"Starbucks" #trip-boston-2017` reads "Showing 1–4 of 4".

## Cause

- `dashboard/src/features/journal/components/journal-lines.tsx:294-297` (Compact, wide) renders all marks as one `<span className="… text-primary">{marks.join(" ")}</span>`, and `:363-380` (Compact, narrow) as plain spans.
- `dashboard/src/features/journal/components/journal-days.tsx:609-620` (Comfortable, `TransactionDetails`) renders each mark as a `<span className="whitespace-nowrap">` inside a `text-primary` span.
- Both sit inside a row built with `getClickableRowProps` (`journal-days.tsx:323-326`), so a click on a mark is a click on the row and opens Entry Context. The account journal uses the same components through `journal-table.tsx:83`.
- Fava's `handle_journal_click` adds `target.textContent` to the filter for `.tag, .link` (`${filter} ${value}` when one is set) and leaves the row alone.

## Fix

Owned by `dashboard`. Render each `#tag` and `^link` mark in both layouts as a router `Link` to the current route with `filter` set to the current filter plus ` <mark>` (the mark alone when the filter is empty; unchanged when the filter already holds that exact term) and the page offset dropped, the way `LedgerSearchParamsProvider` resets it. Stop its click from reaching the row, so Entry Context opens only from the rest of the row. A real link keeps ⌘/Ctrl-click and middle-click opening a new tab (compare w5/1238). Give it an accessible name such as "Filter by #trip-boston-2017" and a visible focus ring. Document rows' tags and links (`journal-description/document-description.tsx`) follow the same rule.

## Definition of done

- On `/journal?filter=payee:"Starbucks"`, clicking `#trip-boston-2017` in Compact and in Comfortable navigates to `?filter=payee:"Starbucks" #trip-boston-2017` and the Journal reads "Showing 1–4 of 4"; Entry Context does not open. With no filter, the click applies `#trip-boston-2017` ("Showing 1–19 of 19").
- The same holds on an account page's journal.
- Clicking elsewhere in the row still opens Entry Context.
- Each mark is reachable with Tab and activates with Enter.
- A rendered test of a Journal row with tags `["a"]` and an existing filter `payee:"x"` asserts the mark is a link whose `href` carries `filter=payee:"x" #a` and that clicking it does not call `onEntryClick`, and fails on the current code. Dashboard gates (`yarn format:check`, `yarn lint`, `yarn test`, `yarn build`) pass.

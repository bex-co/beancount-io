# Documents: one document with a few metadata keys squeezes Filename, Account and Date to one character per line at 1440px (gap in w4/243)

**Severity:** major. At an ordinary laptop width the whole Documents page becomes unreadable once any document carries ordinary metadata (a statement date, a total, a reviewed flag). Every row grows to about 800px tall and every filename and account reads as a vertical strip of single characters. **Owner:** `dashboard`. **Estimate:** 30–45 minutes including a real-layout check. **A2:** a newcomer who attaches receipts with a date and a total cannot read the list of their own receipts. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-18 against `https://beancount.io` (entry chunk `main-LGv2TZLj.js`), headless Chromium, English, isolated profile, signed in as the QA owner on a disposable QA ledger. Local HEAD `a84cb10f2`. The probe files were written and then removed. `main.bean` was restored byte for byte (same blob SHA, no ledger errors).

## Repro

Commit a small text file as `qa-20261118/docs/qa-20261118-statement.txt`, include `qa-20261118/lots.bean` from `main.bean`, and declare in that included file:

```beancount
2026-01-01 open Assets:Qa20261118:Fifo QAFIFO "FIFO"
2026-05-03 document Assets:Qa20261118:Fifo "docs/qa-20261118-statement.txt"
2026-05-06 document Assets:Qa20261118:Fifo "docs/qa-20261118-statement.txt"
  statement-date: 2026-05-06
  total: 12.50 USD
  reviewed: TRUE
  pages: 3
  bank-account: Assets:Qa20261118:Cash
```

A third document (2026-05-04, one tag, one link, `source: "qa-20261118 broker"`) was also present. The ledger reports no errors for these lines.

1. Open `/ledger/<owner>/<ledger>/documents` at 1440×1000.
2. Column widths: **Filename 36px, Account 34px, Date 49px**, Tags 136px, Links 138px, **Meta 810px**. Every row is 717–797px tall, including the 2026-05-03 row, which has no metadata at all. The headers "Filename" and "Account" also wrap one letter per line. The table is 1205px wide inside a 1134px scroller.
3. At 390×844 the result is the same: Filename 28px, Account 26px, Date 41px, Meta 802px, rows about 793px tall.
4. At 1920×1080 the table finally fits: Filename 256px, Account 160px, Date 112px, rows 57px.

The Meta cell prints the raw JSON `{"statement-date":"2026-05-06","total":"12.50 USD","reviewed":true,"pages":"3","bank-account":"Assets:Qa20261118:Cash"}` on one line. The Journal renders the same document's metadata as readable `key value` pairs.

## Expected / Actual

Expected: at 1440px the filename, account and date stay readable on one or two lines, whatever the metadata. The metadata stays fully readable as `key: value` text, wrapped or truncated with the full value available. Actual: one long metadata string takes 810px and leaves about 120px for the three identity columns.

## Root cause

`dashboard/src/features/ledger-data/documents/index.tsx:92-96` puts `JSON.stringify(document.meta)` in a `div.truncate` (`white-space: nowrap`) inside a `TableCell className="w-40"`. In an auto-layout table, `w-40` is only a hint, so the column grows to the string's full one-line width. The body's inherited `overflow-wrap: anywhere` (`common/root-route/shell-component.tsx:24`) lets Filename, Account and Date shrink to one character. w4/243's `min-w-[59rem]` floor (`index.tsx:151,217`) fixed the narrow case, where the squeeze came from non-wrapping tag badges. A single long metadata cell still takes more than the whole floor.

## Fix

- Bound the Meta column. Give its content a real maximum width that it cannot exceed (for example a `max-w-*` on the cell content, or fixed table layout with the existing column widths), and let it wrap.
- Render metadata as `key: value` lines, as the Journal does. If code is shared, move it through `src/common/`; `dashboard/AGENTS.md` forbids one feature importing another's private components.
- Keep the full value reachable. Do not truncate it with no way to read the rest.
- Keep the w4/243 narrow-screen floor and keyboard scroll behaviour.
- Add a real-browser layout check at 1440 and 390 with this fixture. It must assert the Filename/Account/Date column widths and the row height, not just a CSS class.

## Blast radius

`DocumentRow` is used only by this page (`features/ledger-data/documents/index.tsx`). The loading skeleton is not affected. The API is not at fault: `getLedgerDocuments` returns the five keys as plain values (`"total":"12.50 USD"`, `"reviewed":true`).

## Dedupe

Searched `.pm/**`, including `done/` and `blocked/`, for Documents meta, metadata column, `JSON.stringify(document.meta)`, and one-character columns. w4/done/243 is the same symptom at 390px from tag badges, fixed in `19547f970`. It did not cover a long Meta cell, and the Meta cell code is unchanged on `main` since the original import (`af5339de0`). w4/done/242 is the table name. w4/done/301 is path resolution. Not deployment lag.

## Unverified

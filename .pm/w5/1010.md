# Retain authored native-ID owners when weighted inference remains unresolved

**Major · cli · 45–60m · A1 · worker1.** An unchanged bank row imports again
when its saved cash amount is inferred from a costed or priced counter-posting
and a plugin filters that transaction. CSV apply exits 0 / writes 1, recording
the same B1 reference twice: stored Cash falls **800→600 USD**, with a spurious
200 USD expense. Repeating the full native broker trade instead changes Cash
**800→600** and stock **two→four shares**. Both resulting books check valid.
No product fix implemented.

Real local CLI QA, 2026-10-23, checkout `bea 0.3.1` at `2fbb1073186b025b34cd1579955a7f13348394d4`, macOS
26.5.1 arm64, frontend Python 3.13.3, managed Python 3.12.10 / Beancount 3.2.3.
Includes `2a89d9e5e`, which closes [1005](./done/1005.md) by interpolating plain
single-currency source amounts before native-ID matching. Its complete public
acceptance now passes: **10 fresh unfiltered cases / 120 CLI calls / 20 native
loads / 10 actual source proofs**, plus **14 fresh filtered/pass-through cases /
182 calls / 42 native loads / 14 proofs**. Bare/currency-only inferred Cash
repeats skip; real corrections conflict at exit 4; explicit/counter-inferred,
human and B2 write-once controls all hold. Keep 1005 closed. This new branch
has a known owner whose other posting carries a fully stated cost or price.

The native-valid source is a 1000 USD capital deposit followed by a B1 trade:
Cash's amount is omitted and two HOOL are acquired at 100 USD each, either
`{100 USD}` or `@ 100 USD`. Native accounting books Cash −200, leaving **800**.
Cash is the first balance-sheet posting, and each actual lookup is scoped to
`(Assets:Cash, bank, bank:B1)`. The controlled cleared-only view filters `!`
transactions, so the loaded view retains the capital but hides the trade.
The complete authored owner remains present under that ID in the raw index.

With this checkout's `bea` on PATH, run the standalone recipe below twice in
fresh absolute disposable directories. The inspected plugin only filters
Transaction objects by their flag. CSV input has an explicit −200 source
amount and B1 reference. `native_import=True` instead returns the same broker
trade with its cash amount explicit, so the whole acquisition is duplicated.
The native importer reads only its provided statement and returns parsed
entries. No real ledger, service or credential is involved.

Cause: the new nested `spelled` in
`cli/src/bea_engine/importing.py:_under_id` (:2164–2170) first calls
`_interpolated` on every authored native-ID owner, then **drops** every owner
whose source units remain unknown. `_interpolated` (:2210) deliberately
supports one omitted amount only when all other postings are plain explicit
units in one currency. It returns the original entry as soon as another
posting has a cost or a price. These weighted transactions therefore retain
MISSING Cash units in that projection, even though their native booked cash
is unambiguously −200. The list comprehension removes their known B1 owner.

When the view filters the old trade, `found` is None. The actual raw index
still contains one B1 owner; `spelled` turns it into an empty written pool,
and `_under_id` returns None. `importing.answer` (:604 onward) classifies the
row `new` and accepts it. Final normal validation sees a balanced appended
transaction and the filtered view; native IDs themselves are metadata, so
the separate authored book can also balance while recording B1 twice.
This is the loss of a known identity when interpolation cannot complete it.
Keeping that known relationship must not depend on an optional loaded view.

# "Saved, but your ledger now reports an error" stays on screen after the next save fixes that error

**Severity:** minor. **Owner:** dashboard. **Estimate:** 25–40 minutes. **A2:** the file editor warns when a save adds a Beancount error (w3/640). That warning never times out, and nothing removes it when a later save fixes the error. The ledger is clean again, the Errors badge has gone, and the toast still says it is broken. Its **View errors** button then opens "No Errors Found". **Found by:** `/qa-find-bugs-dashboard` on 2026-11-16 against `https://beancount.io`, using headless Chromium at 1440×1000 in English/light. The account was the QA owner, on its designated disposable ledger `mcp-agent-eval`. Local HEAD `d967f57cd`. `main.bean` was restored byte for byte afterwards (blob `f1a0b83c`, 2817 bytes).

## Repro

1. Open a disposable ledger whose Errors page reads "No Errors Found", then go to Files → `main.bean` → **Edit**.
2. At the end of the file, add `2026-11-16 balance Assets:Cash 1.00 USD`, where the real balance is different. Click **Save**.
   - About 1 s later you see "File saved successfully". About 2 s later you see the warning "Saved, but your ledger now reports an error: Balance failed for Assets:Cash: expected 1.00 USD, got 49.75 USD" with **View errors**. This part is correct.
3. Click **Edit** again, delete the line you added, and click **Save**.
   - "File saved successfully" appears. The ledger now has no errors, and the sidebar's Errors entry and badge have gone. The step-2 warning is **still shown**, and it was still there 8 s later. It stays until it is dismissed by hand.
4. Click **View errors** on the warning. It opens `/errors`, which reads "No Errors Found".

I reproduced this twice in one session. The second time, I sampled the toast region once a second for 15 s after each save.

## Cause

`dashboard/src/common/hooks/use-write-outcome.ts:70` calls `toast.warning(t("common.writeLeftErrors", …), { duration: Infinity, … })` and gives the toast no `id`. `report()` returns `false` when a write adds no new errors (lines 64–68), but it never dismisses a warning an earlier write left. So no code path clears a warning once it is shown. The same hook drives New Entry, Open Account, Entry Context save, file delete and Smart Import, so each of them can leave the same stale warning.

## Fix

- Give the warning a stable id for each ledger, for example `write-left-errors:<ledgerId>`.
- When `report()` reads the ledger's errors after a write, dismiss that toast if the error it named is gone. Simplest: dismiss it whenever the fresh error list no longer contains the warned message.
- Reusing the id also stops repeated broken saves from stacking duplicate warnings.
- Keep the success toast as it is.

## Definition of done

- In the step 1–3 repro, the warning disappears by the time the fixing save's success toast settles.
- A second broken save shows one warning, not two.
- A unit test on `useWriteOutcome` covers three cases: a warning followed by a clean `report()` dismisses it; a warning followed by a report that still lists the error keeps it; and the warning shows up again after the toast is dismissed.
- Run dashboard `yarn format:check`, `yarn lint`, `yarn test` and `yarn build`. They must pass.

## Dedupe

I searched `.pm/**` for `writeLeftErrors`, `Saved, but your ledger`, `persistent warning` and `duration: Infinity`. The only hits are where the warning was introduced: w3/640 (done), w2/121 (done) and w21/m1/t003 (done). None of them covers dismissing it. `git log -S writeLeftErrors` shows only `b47c3133d`.

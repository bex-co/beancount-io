# Transaction table prints unescaped quotes and backslashes in lot labels

**Minor · 20–30m · cli · A1.** The normal listing's Beancount-style cost
annotation is ambiguous for a valid quoted lot label, while JSON and
--details preserve its identity. This is a rendering defect, not ledger loss.

Found 2026-10-08 at HEAD `2a168434`, checkout bea 0.3.1, Python 3.13.3,
macOS/Darwin. Fresh bounded CLI subprocesses, closed stdin, redirected stdout,
absolute isolated config/cache and disabled update notices. Local synthetic
fixtures only; no hosted credential or network is needed.

## Reproduce

Create a ledger opening Assets:Stock HOOL and Assets:Cash USD on 2026-01-01.
Create `/absolute/rows.json`:

```json
[{"date":"2026-02-01","narration":"Label","postings":[
  {"account":"Assets:Stock","units":{"number":"1","currency":"HOOL"},
   "cost":{"number":"10","currency":"USD","label":"lot \"A\""}},
  {"account":"Assets:Cash","amount":"-10.00 USD"}]}]
```

```sh
bea --json --file /absolute/main.bean add transactions --from /absolute/rows.json
bea --file /absolute/main.bean list transaction
bea --file /absolute/main.bean list transaction --details
bea --json --file /absolute/main.bean list transaction
bea --json --file /absolute/main.bean check
```

All exit **0**. The normal POSTING AMOUNTS column contains:

```text
Assets:Stock: 1 HOOL {10 USD, 2026-02-01, "lot "A""}
```

Its internal quotes are unescaped, so it is not the Beancount spelling of the
lot label. --details uses escaped internal quotes, and JSON correctly returns
the string `lot "A"`. Source/reloaded values are preserved; checks pass.

Repeated on a second pristine fixture. A literal-backslash label `lot\A` also
prints one unescaped backslash in the table, whereas --details doubles it.
The ordinary `lot-A` control renders the same valid cost annotation in both
views. Listing commands leave all ledger bytes unchanged.

Expected: quote and backslash escaping in the table's lot label follows native
Beancount string spelling, without changing its value or other cost fields.
USAGE's Listing directives section promises the cost basis/date/price spelled
the way --details and the ledger spell them; `_posting_amount` repeats that
contract in its docstring. Keep booked @@ normalization unchanged.

## Cause, repair and dedupe

`cli/src/cli/commands/list.py:101–108` `_cost` wraps `cost['label']` directly
in double quotes. It escapes neither inner quotes nor literal backslashes.
`_posting_amount` calls it for every cost-bearing posting, and
`_transaction_table` only neutralizes terminal controls; it does not supply
Beancount string escaping. The --details engine writer already does.

Escape the label's backslashes and quotes before adding its surrounding
quotes, using a small frontend helper if useful; respect the frontend/engine
import boundary. Add meaningful rendering coverage for quotes, backslashes
and plain labels, asserting loaded JSON identity remains unchanged. Run
make check-all inside cli when fixing. No dependency or API change needed.

Caller search: sole `_cost` user is `_posting_amount`, used in normal and
account-filtered transaction tables. Piped listing is reproduced; terminal
wrapping and --account inherit the same producer but were not exercised.
Other platforms, multiline labels and plugins remain unverified.

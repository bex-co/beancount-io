# Native forwarding commands silently ignore `--json`, so automation gets raw text where the contract promises an envelope

**Severity:** minor. **Estimate:** 40–60 minutes. **Owner:** cli. **A1:** an
agent that sets `--json` once for a whole session gets unparseable stdout from
`bea example` / `bea treeify` and unparseable stderr from a failing
`bea doctor`, with no signal that the flag did not apply.

Found 2026-09-15 by a report-only CLI QA sweep against `main`, HEAD `10465c05`,
using `uv run bea` 0.2.0 on Darwin 26.5.1 arm64 with isolated
`BEA_CONFIG_DIR` / `XDG_CACHE_HOME` and `BEA_NO_UPDATE_NOTIFIER=1`. Synthetic
local fixtures only; no credentials or hosted calls.

## Repro

```sh
# 1. success path: raw Beancount on JSON stdout, exit 0
bea --json example --seed 1 | head -1
# ;; -*- mode: org; mode: beancount; -*-

# 2. upstream usage failure: plain click text on JSON stderr, exit 2
bea --json doctor context main.bean
# Usage: bean-doctor context [OPTIONS] FILENAME LOCATION
# Try 'bean-doctor context --help' for help.
#
# Error: Missing argument 'LOCATION'.

# 3. upstream write failure: plain text on JSON stderr, exit 1
chmod 555 outdir
bea --json example --seed 1 -o outdir/out.beancount
# Error: Could not open file 'outdir/out.beancount': Permission denied

# 4. raw text plus a bare warning on JSON stdout, exit 0
printf 'a:b  1\na:c  2\n' | bea --json treeify
# WARNING: Could not find any valid column in input
# a:b  1
```

`json.loads` fails on stdout in cases 1 and 4 and on stderr in cases 2 and 3.

## Working controls — the in-repo precedent

`bea` already handles this correctly in two places, and both refuse rather than
ignore:

```sh
bea --json query --source "beancount://main.bean" "SELECT account"
# {"error": {"category": "usage", "message": "--source uses native Beanquery
#  output; --json and --strict require a local --file.", "exit_code": 2}}

bea --json ask "what is my balance"
# {"error": {"category": "usage", "message": "bea ask has no JSON output.
#  Use 'bea query' for machine-readable results.", "exit_code": 2}}
```

Errors `bea` raises itself are correctly wrapped even on these same commands —
`bea --json doctor nosuchop`, `bea --json price` and `bea --json ingest` all
return a proper `{"error": …}` object. `bea --json check` on a ledger with a
failing balance assertion returns the documented validation envelope. The split
is exactly the delegation boundary: anything upstream prints escapes untouched.

## Expected / actual

`cli/docs/USAGE.md:84` documents `--json` without qualification: "Emit the JSON
envelope on stdout and JSON errors on stderr." `:148` says "In `--json` mode a
failure writes nothing to stdout and one object to stderr", and `:807` says
"Usage failures, including unknown commands and missing global option values,
follow the same JSON error contract."

`:856-860` enumerates the commands that cannot produce JSON — `ask`,
`cloud login`, successful `cloud logout` and `cloud ledger clone`, help, version,
completion, and `upgrade`'s package-manager stream. `example`, `treeify`,
`doctor`, `price` and `ingest` appear in neither list, so a caller reading the
contract has no way to know `--json` does not apply to them.

Expected: these commands either refuse `--json` with a JSON usage error, the way
`query --source` and `ask` already do, or are named in the exception list.
Actual: the flag is accepted and silently has no effect.

## Root cause

`cli/src/cli/engine/launch.py:71-82` — `run_native` hands the child this
process's stdin, stdout and stderr and returns its status untouched, which is
its documented purpose (`launch.py:5-11`, `cli/CLAUDE.md`, ADR014). The callers
invoke it without first checking `context.current().json_output`:
`cli/src/cli/commands/example.py:12`, `cli/src/cli/commands/treeify.py:12`,
`cli/src/cli/commands/doctor.py:37`. `cli/src/cli/commands/query.py:75` is the
one caller that does guard the native path, and it is the one that behaves
correctly.

## Fix

Add the same guard the native `query --source` path already uses: when
`--json` is set, refuse the delegated command with a usage error (exit 2)
naming the plain-text alternative, e.g. "bea example writes Beancount source,
not JSON; drop --json". Keep `bea check`'s `capture_native` JSON path as is —
it is already a real envelope. Apply it at the `run_native` call sites rather
than inside `run_native`, so `check --json` and any future capturing caller are
unaffected. Then state the rule once in `cli/docs/USAGE.md:856-860` beside the
existing exceptions. Add regression coverage asserting each delegated command
exits 2 with a parseable JSON error under `--json`, and that the non-JSON
invocations still stream upstream output unchanged.

## Addendum — the documented JSON command list is also incomplete

`bea engine status` returns a correct, well-formed envelope
(`{"bea": "0.2.0", "target": null, "data": {"engine_version": …, "features": …,
"serving": …}, "truncated": false}`) and `bea --json engine enable nosuchfeature`
returns a correct JSON usage error — but `engine` appears nowhere in the
`cli/docs/USAGE.md:807` list of JSON-capable commands. So that paragraph
under-reports what already works as well as over-promising for the delegated
commands above. Whoever fixes this should make the list authoritative in both
directions: add `engine status`, and name the delegated commands as exceptions.
Verified 2026-09-15 at HEAD `b78efe7d`.

## Blast radius and adjacent states

Affects every `run_native` forwarding command under `--json`: `example`,
`treeify`, and all `bea doctor <op>` operations. `price` and `ingest` are gated
behind optional engine features that are not enabled in this checkout, so only
their (correct) gate errors were observed — their native paths are unverified
and likely share the shape. `check`, `query` without `--source`, `list`,
`report`, `init`, `import`, `format` and `add` all produce correct envelopes and
JSON errors. Non-JSON invocations of the delegated commands are correct and
should stay that way.

## Dedupe

Searched all `.pm/**/*.md`, including `done/`, for native forwarding, `treeify`,
`bean-example`, `bean-doctor`, and JSON envelope/contract terms.
`.pm/w2/done/020.md` covers the same passthrough commands but for an unrelated
symptom — empty `--help` argument surfaces — and does not mention `--json`.
`.pm/w5/004.md` is adjacent and shares the `run_native` stream-inheritance
mechanism, but is a different defect: an *unhandled* exception in
`format --in-place` plus an unreported partial write. This note is about
*handled* upstream output and errors bypassing the contract on commands that
never crash. The two can be fixed together; neither subsumes the other. No
commit exempts these commands — `git log -S 'native Beanquery output'` shows the
`query --source` guard arriving with `20fefdf4` and never generalized.

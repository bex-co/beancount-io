# Invalidate the ledger cache when a local plugin helper changes

**Minor · cli · 45–60m · A1.** Editing a helper imported by a ledger
plugin leaves cached accounting answers unchanged. Query, list, balance
and overview keep showing a **1 USD** fee after its calculation changes
to **12.50 USD**; a fresh isolated cache reports the correct **12.50 USD**
from the same files. No product fix implemented.

Real CLI QA, 2026-10-21, HEAD `bda491980`, checkout `bea 0.3.1`, macOS
26.5.1 arm64, frontend Python 3.13.3, managed Python 3.12.10 /
Beancount 3.2.3. Separate subprocesses, closed stdin/no TTY, isolated
absolute `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited
`BEA_FILE`/`BEA_TOKEN`. Synthetic local files only; no network needed.

Create disposable `/abs/books/main.bean`:

```beancount
option "operating_currency" "USD"
option "insert_pythonpath" "TRUE"
plugin "fees"
2024-01-01 open Assets:Cash USD
2024-01-01 open Equity:Opening USD
2024-01-01 open Expenses:Fees USD
2024-02-01 * "Capital"
  Assets:Cash 1000.00 USD
  Equity:Opening -1000.00 USD
```

`/abs/books/fee_math.py`:

```python
FEE = "1.00"
```

`/abs/books/fees.py`:

```python
import time
import fee_math
from decimal import Decimal
from beancount.core.data import Transaction, Posting
from beancount.core.amount import Amount

__plugins__ = ("fees",)

def fees(entries, options):
    time.sleep(1.05)
    result = list(entries)
    seed = next(e for e in entries
                if isinstance(e, Transaction) and e.narration == "Capital")
    number = Decimal(fee_math.FEE)
    result.append(seed._replace(
        meta=seed.meta.copy(), narration="Calculated fee",
        postings=[
            Posting("Assets:Cash", Amount(-number, "USD"), None, None, None, None),
            Posting("Expenses:Fees", Amount(number, "USD"), None, None, None, None),
        ],
    ))
    return result, []
```

The sleep makes this tiny fixture cross the normal load-cache threshold;
the same transition happens on a naturally slow ledger. With cwd
`/abs/books` and the isolated child environment above, run:

```sh
bea --json -f /abs/books/main.bean check
bea --json -f /abs/books/main.bean query 'SELECT account,sum(number) GROUP BY account ORDER BY account'
```

Both exit 0. Query gives Cash **999.00 USD**, Opening **−1000.00 USD**,
Fees **1.00 USD**. Now change **only** `fee_math.py` to:

```python
FEE = "12.50"
```

```sh
bea --json -f /abs/books/main.bean query 'SELECT account,sum(number) GROUP BY account ORDER BY account'
bea --json -f /abs/books/main.bean list transaction --search 'Calculated fee'
bea --json -f /abs/books/main.bean balance
bea --json -f /abs/books/main.bean report overview --conversion USD
```

Actual: all exit **0** and retain the stale **1 USD** fee / **999 USD**
cash and net worth. The edited helper and unchanged ledger/plugin bytes
are preserved. Repeated twice in pristine books, including a second pass
over all four reads after the working control below. Cold loading takes
about 1.25–1.4 seconds; stale reads take about 0.24–0.36 seconds.

Working control: repeat those four commands with `XDG_CACHE_HOME` set
**in the child process** to a new absolute directory such as
`/abs/books/fresh-cache`. They all report Fees **12.50 USD**, Cash and net
worth **987.50 USD**, while the original cache still returns 1 / 999.
Appending an ordinary comment to the main `fees.py` also makes the next
original-cache query return 12.50 / 987.50. The changed helper has a
different byte length, avoiding Python's same-second/same-size bytecode
cache ambiguity. No ledger edit is needed or appropriate.

Expected: the next read after this plugin calculation changes loads its
new result, just as it does after editing the plugin's main module. Cached
and uncached answers must agree for the same current ledger and plugin
code. This is a dependency of the executed plugin, not an unrelated file
beside the ledger. USAGE's load-cache section says plugin code counts as
cache input; [326](./done/326.md) established that behavior for main modules.

Cause: `cli/src/bea_engine/managed_load.py:1196–1215`
(`_plugin_fingerprint`) calls `find_spec` / `stat` only for names appearing
in the ledger's `plugin` options. `fee_math` is imported code but is not a
plugin directive, so its file is absent from the record. The ordinary
cache writes that record in `_mark_engine_cache` at 1153–1176 and compares
it in `_plugins_changed` at 1220–1225; the unchanged main module makes the
old load look current. `_load_fresh` at 1095 uses that decision. The same
fingerprint helper is also used by the managed-load cache's store/read
paths at 677 / 649. That managed-price branch is source-traced, not run
in this local no-network reproduction.

Fix: record and revalidate the local helper modules actually used by the
plugin during a cold load, carrying that dependency information across
cached processes. Invalidate on a recorded helper's change or disappearance
while retaining the existing main-module, resolution, day and document
checks. Keep ordinary warm reads cached when their recorded inputs are
unchanged. Do not force every read to rerun the plugin or fingerprint all
unrelated neighboring files. Both cache users of the shared helper need
the same dependency freshness rule. No dependency or API change needed.

Dedupe: searched all `.pm` states for plugin/helper/submodule dependencies,
cache invalidation, stale loads and fingerprints; reviewed targeted history
and open scopes. Completed 326 (`f4f6b118c`, final closure `890ab91a`) added
main-module fingerprints and explicitly recorded a package-`__init__.py`
limitation. It did not cover an imported helper. Open [880](./880.md)
concerns **export completeness** when a function-scope import did not run
on a cached load; this fixture imports its helper at module scope, and the
failure is the ordinary read cache's missing freshness input. A successful
export dependency discovery alone would not invalidate this cached result.
The two repairs may share a dependency record, but have different observed
outcomes and validation. [929](../929.md) concerns old destination files
standing in for missing source export dependencies. No overlapping open
read-cache freshness repair or later helper fingerprint was found.

Acceptance: after a warm cache and helper edit, all four public reads
return 12.50 / 987.50 from the existing cache directory, matching fresh
loads without touching the ledger or main plugin. Unchanged inputs still
use the warm cache, and editing the main plugin still reloads. Pin those
transitions with fresh subprocesses and keep the ledger unchanged.
Other operating systems, helper removal, package-submodule cases, managed
price loads and repaired behavior remain unverified.

---

**Resolved 2026-10-22** — fixed: the engine's load caches now record the local Python files a cold load imported (`_helper_fingerprint` in `cli/src/bea_engine/managed_load.py`: modules under the ledger's directory or its `pythonpath`, with their stats) beside the plugin modules, and revalidate them (`_helpers_changed`) in both cache readers — Beancount's own pickle cache through `_plugins_changed`, and the managed-load cache through `_cached_managed_load`. Editing `fee_math.py` under an unchanged `fees.py` now reloads the calculation (12.50 USD instead of the stale 1.00), a removed helper reloads the load, and an unchanged helper keeps serving the warm cache (the plugin runs once across repeated reads); standard-library and installed packages are not fingerprinted, and a cache record without helpers behaves as before. The managed-price branch is covered by the same shared helper but was not run end to end here. Regression tests in `cli/tests/test_load_cache_plugin_helper.py` fail without the fix. Shipped in this commit (`cli`).

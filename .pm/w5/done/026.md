# Ghost collaborator permission read leaks Gitea internals as INTERNAL

**Severity:** medium. **Journey:** account. **Owner:** backend-v2. Found by the MCP QA auth sweep on 2026-10-03 against production; live at repo HEAD `75819075`. No live board dupe.

Target: `https://beancount.io`, `POST /api-gateway/mcp` (production), observed 2026-10-03.
serverInfo `{"name":"beancount-mcp","version":"1.0.0"}`, protocolVersion `2025-11-25`.
Credential: `bcio_` API key (server kind `apikey`), scopes `ledger.read ledger.write ledger.admin`, ledger pin none (unpinned), no expiry. Value never recorded.
Helper: `node .agents/skills/qa-shared/scripts/qa-mcp.mjs --credentials-file muse.env` from repo root.

## Repro (synthetic coords `qa-owner/qa-book`)

```sh
read beancount://qa-owner/qa-book/collaborators/permission?collaborator=zz-ghost
```

JSON-RPC sent:

```json
{"jsonrpc":"2.0","method":"resources/read","params":{"uri":"beancount://qa-owner/qa-book/collaborators/permission?collaborator=zz-ghost"},"id":1}
```

Observed: -32000 INTERNAL leaking raw `user does not exist [uid: 0, name: ...]` Gitea internals: a 500-class refusal for a caller-named ghost.

## Control

REST: permission read for ghost -> HTTP 500 INTERNAL_SERVER_ERROR.

## Cause

- `backend-cluster/backend-v2/src/features/ledger/workflow/ledger-collaborators-workflow.ts`

`getCollaboratorPermission` does no ghost translation (:284-310); unlike the update path, the Gitea message propagates raw and classifies INTERNAL. Separate throw site from delete-ghost (permission read vs delete).

## Fix (parity: MCP+REST+GraphQL)

Owning package `backend-cluster/backend-v2`; the fix must land on every eligible surface (MCP+REST+GraphQL) in the same change. Translate ghost collaborator -> NOT_FOUND/BAD_USER_INPUT without internals, all surfaces.

## Evidence

`.tmp/qa-2026-10-03-auth/r1-boundaries-account/20-collab-perm-ghostuser.txt`; `.tmp/qa-2026-10-03-auth/r1-boundaries-account/20c-rest-collab-perm-ghost.txt` (gitignored bundle `.tmp/qa-2026-10-03-auth/`); finding brief `.tmp/qa-2026-10-03-auth/final/boundaries-account-collab-permission-ghost-user.md`.

---

**Resolved 2026-10-02** — reading the permission of a user who does not exist is now answered `BAD_USER_INPUT` with `No such user: <name>` on REST (400), GraphQL and the MCP resource (`-32602` with `data.code`), and the upstream detail is no longer echoed. The read shares the translation the update and delete paths use. Shipped in `0e80e0c5` (`backend-cluster/backend-v2`).

A regression test reads the permission through HTTP REST, GraphQL execution and an MCP client with the upstream refusal the note recorded; it fails with the fix reverted. A user who exists but is not a collaborator still takes the pre-existing path, which this note did not cover. Not re-run against the hosted endpoint: the fix reaches it with the next deploy.

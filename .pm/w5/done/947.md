# Keep closed holdings when their converted balance is zero

**Minor · cli · 30–45m · A1.** Filtered `balance` treats a zero converted
amount as proof a closed account holds nothing. A valid account retaining
10 EUR and -10 USD disappears at a 1:1 rate: JSON says no account matched,
and text says `No accounts match Mixed.` Units/cost views and the trial-balance
report retain the same account. No source data changes; no fix implemented.

Real CLI QA, 2026-10-21, HEAD `5f6df65f3` (initial reproduction on
`d0867ad3b`, CLI unchanged), checkout `bea 0.3.1`, macOS 26.5.1 arm64,
frontend Python 3.13.3, existing managed Python 3.12.10. Fresh subprocesses,
closed stdin/no TTY, isolated absolute config/cache, notifier disabled,
no inherited `BEA_FILE`/`BEA_TOKEN`. Synthetic local files only.

Create `/abs/books/main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Mixed USD,EUR
2024-01-01 open Equity:Opening
2024-01-02 * "Currency balances"
  Assets:Mixed 10.00 EUR
  Equity:Opening -10.00 EUR
  Assets:Mixed -10.00 USD
  Equity:Opening 10.00 USD
2024-01-31 price EUR 1.00 USD
2024-02-01 close Assets:Mixed
```

With `bea` on PATH and the isolated child environment above:

```sh
bea --json -f /abs/books/main.bean check
bea --json -f /abs/books/main.bean query "SELECT currency,sum(number) WHERE account='Assets:Mixed' GROUP BY currency ORDER BY currency"
bea --json -f /abs/books/main.bean balance Mixed --time 2024-02 --conversion USD
bea -f /abs/books/main.bean balance Mixed --time 2024-02 --conversion USD
bea --json -f /abs/books/main.bean balance Mixed --time 2024-02 --conversion units
bea --json -f /abs/books/main.bean balance Mixed --time 2024-02 --conversion at_cost
bea --json -f /abs/books/main.bean balance Mixed --time 2024-02 --conversion at_value
bea --json -f /abs/books/main.bean report trial-balance --account Assets:Mixed --time 2024-02 --conversion USD
```

All eight exit **0**. Check passes; the query returns `EUR 10.00` and
`USD -10.00`. The USD and `at_value` balance answers have
`account_filter_empty: true`, `assets: null` and `valuation: "complete"`.
The human USD command prints only its heading on stdout and
`No accounts match Mixed.` on stderr. Units/cost balances keep both holdings.
The final report correctly keeps `Assets:Mixed`, has
`account_filter_empty: false` and reports `balance: {"USD": "0"}`.
Every source byte stays unchanged. Reproduced twice from pristine fixtures.

Expected: exclusion of an empty closed account must depend on its actual
remaining inventory, not the selected valuation. Keep this account and its
known 0 USD value; USD, units and cost views must agree that it matched.
Beancount allows closing a nonempty account, as the successful native check
and completed w1/071 establish. Truly empty closed accounts should remain
excluded.

Controls, twice: omit the close and the zero USD account remains visible.
Keep the close but change the quote to `1.10 USD` and it remains visible at
1 USD. Reverse both currency postings before the close so the inventory is
actually empty, and filtered balances correctly hide it in every mode.

Additional stock control, twice: a closed account holding 1 HOOL at 100 USD
cost with a zero USD market quote disappears in USD, but units still show
1 HOOL and cost still shows 100 USD. A positive quote retains it; selling
the share before closing correctly removes it. Thus both cancellation and
a zero-valued individual holding reach the same exclusion predicate.

Cause: `_balances` (`cli/src/bea_engine/report.py:151`) builds hierarchies in
the requested conversion before `_prune_tree` receives them (:163).
`_prune_tree` (:1206–1209) marks a node closed/empty when its account is in
`closed` and no value in **converted** `node.balance` is nonzero. The
inventory above is nonempty, but its converted `{"USD": "0"}` fails that
test. With no retained child, the node and its structural ancestors disappear.
`_balances` then sets `account_filter_empty` from the pruned trees; the
frontend's heading consequently reports no match.

Fix: judge a closed account's emptiness from its original own inventory at
the report's as-of date, retaining commodity/lot information, and use that
decision while pruning the converted tree. Preserve time filtering,
zero-valued matched nodes, structure-only ancestors and exclusion of actual
empty closed accounts. Do not force units mode or change monetary totals.

Caller search: the closed set reaches this helper only from `balance` with
arguments, including multiple/overlapping OR terms. Unfiltered `balance`
does not prune; `report --account` calls `_prune_tree` without the closed set
and is the working control. This is local report behavior only.

Dedupe: all board states, targeted history and all eight open milestones
were checked. Completed **w1/071**, fixed in `fbbcadf4b`, is the parent:
it changed unconditional closed-account exclusion to this converted-nonzero
test; its 50 USD control still passes. Open w5/908 concerns a nonempty
individual position rendering as `{}` rather than zero; this FX fixture
already has a correct `{"USD": "0"}` before pruning, so that display fix
alone cannot restore the account. Completed w1/020, w1/072 and w3/322 concern
filter scope/rollups, not the closed-state decision. No current repair exists.

Acceptance: all eight commands remain successful; USD and `at_value`
filtered balances retain Mixed at 0 USD and set `account_filter_empty: false`,
matching the report control. Keep both holdings in units/cost views, retain
the positive-price and open-account controls, and still exclude a genuinely
empty closed account. Add regression coverage for both FX cancellation and
the zero-market-price stock case.

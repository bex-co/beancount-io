# Doctor fails to resolve relative included filenames containing a colon

**Minor · cli · 25–40m · A1.** Continuous real CLI QA, 2026-10-08,
HEAD `39146e52`, checkout `bea 0.3.1`, Python 3.13.3, macOS. Agents cannot
inspect a valid included transaction using the filename spelled by its include
when that filename contains `:`. No product fix implemented.

From a directory outside the books directory, create `/absolute/books/main.bean`:

```beancount
2026-01-01 open Assets:Cash USD
2026-01-01 open Equity:Opening USD
include "tx:jan.bean"
```

Create `/absolute/books/tx:jan.bean`:

```beancount
2026-01-02 * "colon fixture" ^colon
  Assets:Cash  100 USD
  Equity:Opening  -100 USD
```

Run the real executable with isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`,
`BEA_NO_UPDATE_NOTIFIER=1`, no inherited `BEA_FILE`/`BEA_TOKEN`, closed stdin,
no TTY, and the books directory absent from cwd:

```sh
bea --json --file /absolute/books/main.bean check
bea doctor context /absolute/books/main.bean tx:jan.bean:1
bea doctor linked /absolute/books/main.bean tx:jan.bean:1
bea doctor region /absolute/books/main.bean tx:jan.bean:1:3
```

Check exits 0 with `valid: true`. All three doctor commands exit 1.
Context/linked produce no stdout and stderr says no entry could be found
before `<cwd>/tx:jan.bean:1`; region prints `Net Income: ()` then stderr
reports no entries matched. Replacing each location with the absolute filename
(`/absolute/books/tx:jan.bean:1`, or `:1:3`) succeeds and displays the 100 USD
transaction. Repeated in two fresh fixture directories. A fresh `jan.bean`
control succeeds with the relative location in all three operations. Ledger
hashes remain unchanged throughout.

Expected: `cli/docs/USAGE.md` documents resolving a relative location against
the root ledger when cwd has no such file. Upstream accepts colons inside
filenames: its FileLocation/FileRegion parsers split off trailing numeric line
fields, and the absolute-path controls work. This is not an unsupported
upstream filename or invalid ledger.

Root cause: `cli/src/cli/commands/doctor.py:124–134`
`_located_against_ledger` uses `partition(":")`, treating only `tx` as the
filename. `books/tx` does not exist, so the original location reaches upstream
and resolves against cwd. Caller search finds this helper shared by the
registered context, linked and region forwarding paths. Preserve numeric-only
locations, absolute/existing-cwd precedence, linked tag/link selectors and
interposed native options when extracting a filename from the trailing line
fields. No new dependency, upstream fork or backend API change is needed.

Full-board search across open/done/blocked items and history found no matching
colon-location finding. Completed w3/355 added ordinary relative resolution;
w3/403 fixed interposed option operands. Their plain-filename controls still
pass; this is a remaining filename parsing case, not reopening those fixes.

Acceptance: the three exact relative-colon commands succeed from a foreign
cwd, match their absolute-path results, and preserve files. Ordinary relative,
numeric-only, absolute, existing-cwd and option-placement cases still work.
Only macOS/file inputs were exercised; other platforms remain unverified.

Sanitized evidence: `cli/tmp/qa-20261008-cli/concurrent_paths.py`,
`concurrent-paths-console.jsonl`, `colon_control.py`,
`colon-control-console.jsonl`, and `transcript.jsonl` retain argv, cwd,
environment overrides, separate streams, exit codes and file hashes.
The public repro above is self-contained.

---

**Resolved 2026-10-10** — doctor's relative-location resolver now takes the filename as everything before the trailing line fields — one field for `context` and `linked`, two for `region` — which is how upstream's own location parsers split it. `tx:jan.bean:1` and `tx:jan.bean:1:3` resolve against the root ledger's directory from a foreign working directory. Shipped in `16648894` (`cli`).

Real-command regression tests run all three operations on the reported fixture from a foreign directory and assert exit 0, the 100 USD transaction, output identical to the absolute-path spelling, and unchanged file bytes; these three fail with the fix reverted. Controls keep an existing file in the working directory ahead of the ledger's directory, a numeric-only location untouched, and the earlier plain-relative, absolute and interposed-option suites green. `make check-all` passed. Tested on macOS only; the colon cases are skipped on Windows, where a colon is not a filename character.

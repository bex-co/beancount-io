# Recognize helpers beneath overlapping ledger Python paths

**Minor · cli · 30–45m · A1.** When both a root ledger and an included file
in `plugins/` set `insert_pythonpath`, portable export omits a helper
imported from that subdirectory. The source checks clean and export reports
success, but its snapshot fails with `ModuleNotFoundError`. Removing only
the root option keeps source behavior unchanged and makes the helper travel.
This affects ordinary modules and packages, not just namespace packages.
No product fix implemented; all source bytes remain unchanged.

Environment: 2026-10-22 QA, clean main `a9b710084` (initial reproduction on
`693b56898`; implicated sources unchanged), checkout `bea 0.3.1`, frontend
Python 3.13.3, managed Python 3.12.10 / Beancount 3.2.3 / Beanquery 0.2.0,
macOS 26.5.1 arm64. Fresh subprocesses, closed stdin/no TTY, isolated absolute
config/cache paths, notifier disabled and inherited file/token overrides
removed. Only inspected local Python and synthetic files; no price feed
or optional feature.

Run with the checkout's `bea` on PATH, replacing `/abs/case` with a fresh
absolute disposable directory. The source directory is hidden during the
snapshot check and restored in `finally`.

```python
import json, os, subprocess
from pathlib import Path
case = Path('/abs/case')
books = case / 'books'
leaf = books / 'plugins'
leaf.mkdir(parents=True)
root_pythonpath = 'option "insert_pythonpath" "TRUE"\n'
(books / 'main.bean').write_text(root_pythonpath + '''option "operating_currency" "USD"
include "plugins/settings.bean"
plugin "qa_plugin"
2024-01-01 open Assets:Cash USD
2024-01-01 open Income:Services USD
2024-01-02 * "Invoice"
  Assets:Cash 100 USD
  Income:Services -100 USD
''')
(leaf / 'settings.bean').write_text('option "insert_pythonpath" "TRUE"\n')
(leaf / 'qa_helper.py').write_text('VALUE = 100\n')
(leaf / 'qa_plugin.py').write_text('''__plugins__ = ['run']
def run(entries, options):
    import qa_helper
    assert qa_helper.VALUE == 100
    return entries, []
''')
original = {str(p.relative_to(books)): p.read_bytes() for p in books.rglob('*') if p.is_file()}
env = os.environ.copy()
for key in ('BEA_FILE', 'BEA_TOKEN', 'BEANCOUNT_LOAD_CACHE_FILENAME',
            'BEA_ENGINE_PYTHON', 'BEA_ENGINE_DIR'):
    env.pop(key, None)
env.update(BEA_CONFIG_DIR=str(case / 'config'), XDG_CACHE_HOME=str(case / 'cache'),
           BEA_NO_UPDATE_NOTIFIER='1')
def run(tag, file, args, overrides=None):
    argv = ['bea', '--json', '--no-input', '-f', str(file), *map(str, args)]
    result = subprocess.run(argv, cwd=case, env=env | (overrides or {}),
                            stdin=subprocess.DEVNULL, capture_output=True,
                            text=True, timeout=25)
    print(json.dumps(dict(tag=tag, args=argv, exit=result.returncode,
                         stdout=result.stdout, stderr=result.stderr)), flush=True)
run('source-check', books / 'main.bean', ['check'])
run('source-cash', books / 'main.bean', ['query', "SELECT number WHERE account='Assets:Cash'"])
snapshot = case / 'snapshot'
run('export', books / 'main.bean', ['price', 'export', '--output', snapshot])
hidden = case / 'hidden-books'
books.rename(hidden)
try:
    run('snapshot-check', snapshot / 'main.bean', ['check'],
        {'XDG_CACHE_HOME': str(case / 'snapshot-cache')})
finally:
    hidden.rename(books)
assert all((books / name).read_bytes() == content for name, content in original.items())
```

Actual exits: **0, 0, 0, 1**. Source check is valid; Cash is **100 USD**.
Export succeeds with only `main.bean`, `plugins/settings.bean` and
`plugins/qa_plugin.py`. It omits `plugins/qa_helper.py`. Snapshot check
fails with JSON stderr naming `qa_plugin` and
`ModuleNotFoundError: No module named 'qa_helper'`. Human export agrees.
The original source tree is restored and all its ledger/module bytes stay
unchanged.

Working control: set only `root_pythonpath = ''` before creating the fresh
fixture. The included `plugins/settings.bean` still enables the subdirectory,
the same source/plugin checks clean, and export includes all four files;
its source-hidden snapshot checks clean. This isolates the extra parent
search directory, not a missing dependency or unsupported plugin.

Expected: USAGE's portable-export contract at `cli/docs/USAGE.md:1980–1986`
carries imported local modules/packages from every enabled ledger Python
directory. Adding an ancestor search path must not hide a helper that Python
still resolves from the included file's own directory.

Reproduction and controls:

- Twice from fresh fixtures with the root option on/off: **12 CLI calls**
  prove source validity, missing-helper export and source-hidden failure
  only with the ancestor path enabled.
- Sixteen further pristine cases, twice each of parent on/off × ordinary
  module/regular package × module-scope/runtime import: **96 CLI calls**.
  Source Cash remains 100 USD; all eight parent-on cases omit the entire
  helper and fail source-hidden snapshot checks with that exact module name.
  All eight child-only cases include it and pass. A package's JSON resource
  travels with its otherwise unchanged passing control. Human and JSON
  exports agree, and all source files are restored byte-for-byte.
- The exact public recipe above was replayed twice alongside its child-only
  control, including human export and independent source-hidden checks.

Cause: `_sibling_imports` in `cli/src/bea_engine/managed_load.py:2244–2253`
asks `_relative_to_any:2267–2278` for a helper's location relative to the
**first** containing Python directory. The actual loaded homes are
`[books, books/plugins]`. For `books/plugins/qa_helper.py` it returns
`plugins/qa_helper.py`, whose first component does not match imported
top-level name `qa_helper`; the inventory drops it without trying the child.
The correct relative spelling for that import is `qa_helper.py` under
`books/plugins`. A direct loaded-options/helper control confirms both paths
and the wrong first relative result. Registered `qa_plugin` still travels
because its name is added separately to the export's wanted set.

Fix in `cli/`: test all containing ledger Python directories against the
module's actual imported top-level name, rather than letting an ancestor
mismatch suppress a valid child match. Preserve qualified imports too:
unconditionally selecting only the deepest directory is not sufficient for
a name whose top-level component belongs to the parent. Keep actual Python
search precedence/options unchanged; repair dependency inventory, not the
user's configuration. No dependency or API change indicated.

Caller scope: `_relative_to_any` is used by `_sibling_imports` and
`_below_any` (the latter only asks about containment). The resulting wanted
set feeds `_export_plugin_modules:2129`, then the export plan at `:1814`,
engine `price-export` (`bea_engine/main.py:855`) and frontend
`price._export` (`cli/commands/price.py:182`). Ordinary reports/imports are
outside this export path.

Dedupe: searched every board state for nested/overlapping/ancestor Python
paths, included-file helpers and `_relative_to_any`, plus targeted history.
Completed [762](./done/762.md), commit `afa183e64`, added included Python
directories; [327](./done/327.md) and [880](./done/880.md) cover helper
inventory at unambiguous locations. Open [968](./968.md) is cached,

Acceptance: with both options enabled, module and regular-package helpers

**Resolved 2026-10-23** — fixed: portable export's import inventory (`_sibling_imports` in `cli/src/bea_engine/managed_load.py`) now judges an imported local file against every module-path directory it sits under (`_relatives`), not the first containing one. With both the root and an included `plugins/` setting `insert_pythonpath`, `plugins/qa_helper.py` is `qa_helper.py` under the second directory and was matched against the first alone, so the helper was dropped and the snapshot failed with `ModuleNotFoundError`; modules and regular packages (resources included), at module scope or imported at runtime, now travel and the snapshot checks with the source hidden. The child-only and the earlier w5/327, 868, 880, 968 and 969 controls are unchanged. Regression tests in `cli/tests/test_price_export_plugin_runtime_imports.py` fail without the fix. Full suite green apart from the known `test_release` smoke timeout, which passes alone. Shipped in this commit (`cli`).

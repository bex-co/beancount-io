# Preserve labels in stranded-lot close advice

**Minor · cli · 20–35m · A1.** The close guard correctly finds two distinct
lots whose units cancel, but its message omits one lot's empty label. It
prints both as the same cost and advises posting each one's cost to drain
them. Following those displayed costs writes a valid no-op: both lots remain
and the next close still refuses. Keeping the missing `""` in the inverse
posting drains both and permits the close. Native-import close warnings lose
the same label. The formatter also emits ordinary quoted/backslash labels
without escaping, making copied recovery fail or create a different lot.
No product fix implemented.

Real CLI QA, 2026-10-22, HEAD `53befe78d` (relevant CLI source unchanged from
`97494115f`), checkout-selected `bea 0.3.1`, macOS 26.5.1 arm64, frontend
Python 3.13.3 / managed Python 3.12.10 / Beancount 3.2.3. Pristine synthetic
books, fresh bounded subprocesses, closed stdin/no TTY, isolated child
config/cache, notifier disabled and no inherited ledger/token/engine override.
All failing and control cases repeat twice. The stock account deliberately
uses supported `NONE` booking, so each explicit cost remains its own position.
There is no price conversion, plugin or import fingerprint dependency.

With `bea` on PATH, replace `/abs/stranded-label-case` with a fresh disposable
absolute directory and run this standalone recipe. It copies the cost from
the **actual close diagnostic**, then compares that recovery with one retaining
the exact source label. The inspected importer parses only a close directive;
its preview writes nothing.

```python
from pathlib import Path
import json, os, re, subprocess

case = Path('/abs/stranded-label-case')
second_label = ''
case.mkdir(parents=True, exist_ok=False)
ledger, wrong, correct = [case / name for name in ('main.bean', 'wrong.bean', 'correct.bean')]
suffix = '' if second_label is None else ', ' + json.dumps(second_label)
base = '''2024-01-01 open Assets:Stock HOOL "NONE"
2024-01-01 open Assets:Cash USD
2024-01-02 * "First lot"
  Assets:Stock 1 HOOL {100 USD, 2024-01-02}
  Assets:Cash -100 USD
2024-01-02 * "Second lot"
''' + f'  Assets:Stock -1 HOOL {{100 USD, 2024-01-02{suffix}}}\n  Assets:Cash 100 USD\n'
for file in (ledger, wrong, correct):
    file.write_text(base)
statement = case / 'close.statement'
statement.write_text('2024-02-01 close Assets:Stock\n')
config = case / 'importer.py'
config.write_text('''from beancount.parser import parser
class Broker:
    name = 'broker'
    def identify(self, file): return str(file).endswith('.statement')
    def account(self, file): return 'Assets:Stock'
    def extract(self, file, existing_entries=None):
        entries, errors, _ = parser.parse_file(str(file))
        assert not errors, errors
        return entries
CONFIG = [Broker()]
''')
inputs = {p:p.read_bytes() for p in (statement, config)}
env = os.environ.copy()
for key in ('BEA_FILE', 'BEA_TOKEN', 'BEANCOUNT_LOAD_CACHE_FILENAME',
            'BEA_ENGINE_PYTHON', 'BEA_ENGINE_DIR'):
    env.pop(key, None)
env.update(BEA_CONFIG_DIR=str(case / 'config'), XDG_CACHE_HOME=str(case / 'cache'),
           BEA_NO_UPDATE_NOTIFIER='1')
def run(tag, args, file=ledger, json_mode=True):
    argv = ['bea', *(['--json'] if json_mode else []), '--no-input', '-f', str(file), *map(str, args)]
    before = file.read_bytes()
    result = subprocess.run(argv, cwd=case, env=env, stdin=subprocess.DEVNULL,
                            capture_output=True, text=True, timeout=25)
    assert all(p.read_bytes() == data for p, data in inputs.items())
    record = dict(tag=tag, args=argv, exit=result.returncode,
                  stdout=result.stdout, stderr=result.stderr,
                  ledger_changed=file.read_bytes() != before)
    print(json.dumps(record), flush=True)
    return record
close = ['add', 'close', '--date', '2024-02-01', '--account', 'Assets:Stock']
first_inverse = 'Assets:Stock -1 HOOL {100 USD, 2024-01-02}'
exact_inverse = 'Assets:Stock 1 HOOL {100 USD, 2024-01-02' + suffix + '}'
def drain(posting):
    return ['add', 'transaction', '--date', '2024-02-01', '--narration', 'Drain lots',
            '--posting', first_inverse, '--posting', posting]
lots = ['query', "SELECT sum(position) WHERE account='Assets:Stock'"]
run('baseline', ['check'])
run('import-preview', ['import', statement, '--config', config])
closed = run('close', close)
# Copy the negative held position's cost from the actual diagnostic.
message = closed['stderr']
if message.startswith('{'):
    message = json.loads(message)['error']['message']
held = re.findall(r'-1 HOOL (\{[^}\n]+\})', message)
second_inverse = 'Assets:Stock 1 HOOL ' + (held[0] if held else '{100 USD, 2024-01-02}')
run('reported-inverse', drain(second_inverse), file=wrong)
run('close-after-reported-inverse', close, file=wrong)
run('reported-check', ['check'], file=wrong)
run('exact-inverse', drain(exact_inverse), file=correct)
run('close-after-exact-inverse', close, file=correct)
run('exact-check', ['check'], file=correct)
run('original-lots', lots)
run('reported-lots', lots, file=wrong)
run('exact-lots', lots, file=correct)
```

Actual default results:

- Baseline and all checks exit 0. Import preview has one nonblocking funded
  close warning. Both that warning and the unforced close's validation error
  describe **−1 HOOL {100 USD, 2024-01-02}** and
  **1 HOOL {100 USD, 2024-01-02}**. The negative position actually has label
  `""`; the positive one has label `null`. The close exits 1 and preserves
  the original ledger bytes.
- The inverse built from that message writes one transaction, exit 0. It
  negates both displayed unlabelled positions, whose sum is zero, so the two
  original positions remain. `close-after-reported-inverse` again exits 1
  with the same stranded lots. This recovery's check is valid; check alone
  does not show that the requested drain did nothing.
- The exact inverse includes `""` on its positive 1-share posting. It writes
  one transaction, removes both positions, and the next close writes 1 at
  exit 0. All inputs stay byte-identical. Independent native inventories
  verify the original and displayed-cost recovery each have two positions,
  while the exact recovery has none. All three net units are 0.

Expected: display the full negative lot as
`-1 HOOL {100 USD, 2024-01-02, ""}`, preserving the positive unlabelled cost
separately, in add-close refusals and imported-close advisories. Copying each
full displayed cost into the inverse transaction must have the same effect
as the exact-label control. Keep the guard's correct refusal and the import
warning's nonblocking behavior; the finding is the incomplete recovery data.

Controls: set `second_label = 'X'`. The current message correctly keeps X,
so the recovery derived from it drains both lots and its close succeeds.
Set `second_label = None`: both initial postings have the same unlabelled
cost and genuinely cancel; the original close succeeds and preview has no
funded warning. Human/JSON close diagnostics and a human native-import preview
companion reproduce the empty-label omission. Source statement/config bytes
are preserved, and every rejected close preserves its ledger. The recovery
books are independent copies, so their successful closes do not affect the
original refusal.

Additional ordinary-label cases use the same recipe and formatter:

- `second_label = 'Desk "A"'`: the message spells the label as `"Desk "A""`
  instead of `"Desk \"A\""`. Copying its cost makes `reported-inverse` exit
  **2** with a usage error and no write. The exact escaped source label
  writes, drains both lots, and closes at 0.
- `second_label = '2024\\DRIP'` (one literal backslash in the label): the
  message emits `"2024\DRIP"` instead of the valid `"2024\\DRIP"`. Copying it
  exits **0**, but Beancount reads the new positive lot's label as
  `2024DRIP`. The original negative `2024\DRIP` lot remains; native inventories
  confirm these two different labels and zero net units. Close still exits 1.
  The exact escaped inverse removes both and permits the close.

Both cases repeat twice in JSON and human close companions, using inspected
local source files and independent native graphs. These are label-rendering
failures in the same helper, not a request to change Beancount's string parser.

Cause: `cli/src/bea_engine/ledger/adding.py:_stranded_lots` (:362 onward)
correctly keys positions by cost number, currency, date and label, retaining
both `None` and `""`. Its display construction at **:394** adds a label only
with `if key[3]:`, dropping the explicitly present empty string, and wraps a
nonempty value in quotes without escaping its internal quotes/backslashes.
The shared
`_remaining_balance` sends these strings to `_close` and to
`importing.py:_funded_close_advisories`. Both human and JSON carry the already
incomplete string; changing only a frontend renderer cannot recover it.

Fix the shared stranded-lot formatting to preserve a present empty label
and escape quoted/backslash labels with the existing cost/label renderer.
Keep inventory
classification, row dates, close refusal/force policy, native-import preview
and warning behavior unchanged. Do not reinterpret `{""}` reduction selectors:
the reproducer uses NONE booking and explicit inverse cost positions. No
dependency, upstream implementation or API change is needed.

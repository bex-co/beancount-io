# `bea import` hides the column ambiguity exactly when that ambiguity is what broke the mapping

**Severity:** minor. **Estimate:** 30–45 minutes. **Owner:** cli. **A1/A2:** a
newcomer or agent importing a bank CSV whose header names a role twice is told
to go configure a Python importer, when naming one column would have worked.

Found 2026-09-15 by a report-only CLI QA sweep against `main`, HEAD `ca74ad78`,
using `uv run bea` 0.2.0 on Darwin 26.5.1 arm64 with isolated
`BEA_CONFIG_DIR` / `XDG_CACHE_HOME` and `BEA_NO_UPDATE_NOTIFIER=1`. All
fixtures were synthetic local files; no credentials or hosted calls.

## Repro

```sh
bea --no-input init books --currency USD --date 2026-01-01
printf 'Date,Description,Memo,Amount\n2026-01-02,A,B,-10.00\n' > twonarr.csv
bea --file books/main.bean import twonarr.csv --account Assets:Checking
```

`Description` and `Memo` are both `narration` synonyms, so the role has two
claimants and is correctly dropped. The command then exits `2` with:

```text
Error: Choose a Python importer with --config FILE, or place importers.py
beside the root ledger. The selected path is remembered for this ledger. For a
CSV export whose header row bea could not read, map the columns directly with
--csv date=Date,amount=Amount,narration=Description --account Assets:Checking.
```

`--csv auto` on the same file is better but still silent about the cause:

```text
Error: Cannot read a column mapping from the header row of twonarr.csv. Its
columns are: Date, Description, Memo, Amount. Name them with --csv
date=Date,amount=Amount,narration=Description.
```

Neither message says that two columns claimed `narration`.

## Working control

An ambiguity that still leaves a usable mapping *is* reported. With
`Date,Payee,Merchant,Description,Amount`, `payee` has two claimants while
`narration=Description` survives, so inference succeeds and stderr carries:

```text
Several columns could be payee (Merchant, Payee); none was chosen.
Name the one you want with --csv.
```

So the reporting mechanism works; it is unreachable on the path where the
ambiguity is fatal.

## Expected / actual

`cli/docs/IMPORTING.md:86-89` says a role is only filled when exactly one
column claims it, and that an export carrying two such columns "reports the
ambiguity and leaves that role unmapped rather than guessing". The source
comment at `cli/src/cli/csv_mapper.py:115-118` states the same intent. Expected:
both the default path and `--csv auto` name the competing columns, the same way
the surviving-mapping case already does.

Actual: the ambiguity list is computed and then discarded, and the default path
recommends a Python importer for a CSV that imports fine once one column is
named.

## Root cause

`cli/src/cli/csv_mapper.py:167-184` accumulates `ambiguities` while matching
roles, but the guard at `:178-180` returns `None` when no `date`, or neither
`payee` nor `narration`, survived — throwing the list away with the mapping.
`cli/src/cli/commands/import_.py:63-87` can only surface it afterwards: `:76`
returns `None` and `:78-81` raises the `--csv auto` usage error, both before
`:82-86`'s `if inferred.ambiguities:`. `cli/src/cli/commands/import_.py:56`
supplies the Python-importer message for the default path.
`cli/src/bea_engine/csv_mapper.py:169-186` carries the same logic.

## Secondary: the documented example is not ambiguous

`_HEADER_SYNONYMS` (`cli/src/cli/csv_mapper.py:119-129`) matches a header by
exact casefolded equality. `original description` is not a `narration` synonym,
so the `Description` + `Original Description` export named in
`cli/docs/IMPORTING.md:86-89` and in the comments at
`cli/src/cli/csv_mapper.py:117` / `cli/src/bea_engine/csv_mapper.py:119` never
triggers the rule it illustrates — it maps to `Description` silently, exit `0`:

```sh
printf 'Date,Description,Original Description,Amount\n2026-01-02,A,B,-10.00\n' > ambig.csv
bea --file books/main.bean import ambig.csv --account Assets:Checking   # exit 0
```

## Fix

Return the inference failure with its reason instead of a bare `None`, so both
the default and `--csv auto` messages can name the competing columns before
suggesting `--csv`. Keep the Python-importer suggestion for headers that are
genuinely unreadable, not for a role two columns claimed. Then make the doc and
both source comments use a pair the synonym table actually treats as ambiguous
(such as `Description` + `Memo`), or add `original description` to the
`narration` synonyms and accept that such exports become unmappable without
`--csv`. Add regression coverage for the fatal-ambiguity message and keep the
existing surviving-mapping note.

# Name an implied price created by the same import when it defeats a quote

**Minor · cli · 30–45m · A1 · worker1.** A valid import containing an FX
transaction and a EUR1.20USD price reports two successful writes with no
unused-quote warning, although `implicit_prices` makes the transaction's
USD0.80EUR rate win. Fresh BQL uses EUR1.25USD and the balance sheet reads

The values and price-selection rule are correct; the missing advisory is


The ledger loads the normal `beancount.plugins.implicit_prices` plugin.

## Cause and bounded fix

`cli/src/bea_engine/importing.py:904–914` collects the accepted Price row's
wanted rate and calls `unused_quote_advisories(candidate, existing, wanted)`
from the candidate inspection hook. `ledger/prices.py:175` settles all
candidate prices correctly, including the new FX-implied quote. But :176
builds its winner lookup only from the **pre-import** `existing` entries.
The search at :187–191 cannot find a quote generated by an incoming
transaction and silently continues. Its docstring explicitly leaves a
same-import winner to the importer; that caller has no alternate advisory.
This is not missing candidate data: `ledger/write.py:2410` already hands
the inspector every entry loaded for the proposed write.

Extend winner attribution to a winning implied price produced by another
accepted row of this import. Emit the advisory through the same
`validation_warnings`/human path, naming the winning rate and the incoming
FX row, or its truthful final destination location. Preview must not cite
a vanished staging file or call a new transaction pre-existing. An example
is “Incoming FX row2 implies USD0.80EUR (EUR1.25USD), so the imported
EUR1.20USD quote is never used.” Exact wording is not mandated.

Preserve the successful two-row write, source bank ID, duplicate handling,
ledger validity, exact price-selection rule and computed values. Do not
turn a generated quote into an authored-price conflict/duplicate, reorder
source rows or change which direction wins. Keep effective new quotes quiet.
The helper also serves `add price`; that writer cannot create an FX
transaction in the same call, but its existing winners and quiet controls
must remain correct. This request changes only local import feedback;
no dependency or eligible API surface changes.

Acceptance: both input orders, human/JSON and renamed-root cases explain
the implied1.25 vs recorded1.20 mismatch at preview and apply. Apply still
writes2; final20EUR/100USD, BQL1.25 and BS125 are unchanged. Repeat0 is
idempotent. Existing-FX keeps its real source-located warning, no-plugin
keeps its quiet1.20/124 result, and the original903 controls below remain
green. Add real CLI regressions with the price and generating transaction
in one import, inspect streams and independently reload the result;
run `make check-all` inside `cli/` when implementing.

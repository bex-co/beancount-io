# Use authored balance assertions for repeat and conflict decisions

**Minor · cli · 30–45m · A1 · worker1.** Real local CLI QA, 2026-10-22,
checkout `bea 0.3.1` at `af4a32241815dbeae530ec3288cab43882c8cbcb`, macOS
26.5.1 arm64, frontend Python 3.13.3, managed Python 3.12.10 / Beancount 3.2.3.
Completed 938's shared-location fix is included. No product fix implemented.

Balance duplicate/conflict matching follows a plugin's loaded assertions
instead of the actual assertion the file records. A filter makes an exact
repeat append again and lets a same-day different amount/tolerance append
without the documented conflict. A singleton transformed assertion makes
the opposite mistakes: the real exact repeat is refused, while an unwritten
amount/tolerance is falsely reported already recorded. Cash remains 100 USD
throughout and the active plugin view checks successfully; this finding is
about authored assertion identity and file effects, not changed cash holdings.

[USAGE's adding contract](../../cli/docs/USAGE.md#adding-directives) makes an
identical balance assertion idempotent and a different value for the same
date/account/currency a conflict requiring force. Typed precision matters:
100.00 and 100.0 have different implicit tolerances. A plugin's view should
not change what an authored declaration's duplicate key and amount mean.

Run this standalone script in two fresh absolute directories. Use each mode
and action; `human_add=True` checks human output. The inspected plugins only
filter Balance objects or replace their amount/tolerance with fixed finite
decimals in memory, with no I/O or services. Children have isolated config/cache,
closed stdin/no TTY, bounded timeouts, separate streams and file hashes. HOME,
global CLI state and real ledgers stay untouched.

```python
import hashlib, json, os, pathlib, subprocess
case = pathlib.Path('/abs/authored-balance-case')
mode = 'filter'  # pass, transform
action = 'same'  # precision, within
human_add = False
case.mkdir(parents=True)
module = case/'qa_assertions.py'
module.write_text('''from decimal import Decimal
from beancount.core.data import Balance
__plugins__ = ('view',)
def view(entries, options, config=None):
    out = []
    for e in entries:
        if isinstance(e,Balance):
            if MODE=='filter':continue
            if MODE=='transform':e=e._replace(amount=e.amount._replace(number=Decimal('100.01')),
                                             tolerance=Decimal('0.02'),meta=e.meta.copy())
        out.append(e)
    return out, []
'''.replace('MODE',repr(mode)),encoding='utf-8')
ledger = case/'main.bean'
ledger.write_text('''option "operating_currency" "USD"
option "insert_pythonpath" "TRUE"
plugin "qa_assertions"
2024-01-01 open Assets:Cash USD
2024-01-01 open Equity:Opening USD
2024-01-02 * "Capital"
  Assets:Cash 100.00 USD
  Equity:Opening -100.00 USD
2024-02-01 balance Assets:Cash 100.00 USD
''',encoding='utf-8')
(case/'initial-main.txt').write_bytes(ledger.read_bytes())
original_module = module.read_bytes()
env = os.environ.copy()
for key in ('BEA_FILE','BEA_TOKEN','BEANCOUNT_LOAD_CACHE_FILENAME'):
    env.pop(key,None)
env.update(BEA_CONFIG_DIR=str(case/'config'),XDG_CACHE_HOME=str(case/'cache'),
           BEA_NO_UPDATE_NOTIFIER='1')
def run(tag,args,human=False):
    before = ledger.read_bytes()
    cmd = ['bea',*([] if human else ['--json']),'--no-input','-f',str(ledger),*map(str,args)]
    r = subprocess.run(cmd,cwd=case,env=env,stdin=subprocess.DEVNULL,
                       capture_output=True,text=True,timeout=25)
    print(json.dumps(dict(tag=tag,args=cmd,exit=r.returncode,stdout=r.stdout,stderr=r.stderr,
                          source_preserved=ledger.read_bytes()==before,
                          before_sha256=hashlib.sha256(before).hexdigest(),
                          after_sha256=hashlib.sha256(ledger.read_bytes()).hexdigest(),
                          plugin_preserved=module.read_bytes()==original_module)),flush=True)
run('before-check',['check'])
amount = {'same':'100.00 USD','precision':'100.0 USD','within':'100.01 ~ 0.02 USD'}[action]
run('add',['add','balance','--date','2024-02-01','--account','Assets:Cash','--amount',amount],human_add)
run('after-check',['check'])
run('list',['list','balance','--limit','100'])
run('cash',['query',"SELECT sum(number) WHERE account='Assets:Cash'"])
```

Observed twice for all three modes and actions:

- The file initially records only `2024-02-01 balance Assets:Cash 100.00 USD`.
  Native transaction holdings are 100 USD. Every initial source/reference
  and active-plugin check succeeds.
- `filter/same` exits 0, `written: 1`, appending a second exact assertion
  instead of returning a zero-write duplicate. `filter/precision` likewise
  writes 100.0 instead of conflicting with the existing stricter 100.00.
- `filter/within` appends `100.01 ~ 0.02 USD` without force, exits 0 and
  changes the file. The active filter still checks because it removes both
  assertions. A separate native reference omitting only that filter reports
  `Duplicate balance assertion with different amounts`. Each amount alone
  is within the stated tolerance of the same 100 USD cash.
- `transform` keeps one loaded assertion, 100.01 USD with tolerance 0.02,
  while the actual file stays 100.00 with no explicit tolerance. Repeating
  the actual written 100.00 wrongly conflicts at exit 4. Requesting
  `100.01 ~ 0.02 USD` wrongly reports duplicate, exit 0 / `written: 0`,
  citing the source line that spells **100.00**, not that requested assertion.
  Both forms leave the file unchanged; cash and native active validation stay
  correct. These are source-identity mistakes despite a valid plugin view.
- `pass/same` correctly skips with unchanged bytes. `pass/precision` and
  `pass/within` correctly conflict at exit 4. `transform/precision` also
  conflicts, an adjacent working case. Human output reproduces the filtered
  different-value append and transformed false duplicate.

Cause: `cli/src/bea_engine/ledger/adding.py:_balance` (:523 onward) loads the
plugin view into `before` and passes that list to `_balance_match` (:742)
and `_balance_conflict` (:769), before append/pad handling. A filtered source
assertion is absent, so neither duplicate nor conflict exists there. For a
singleton transformed assertion, shared-location classification cannot recover
the actual file-stated amount/tolerance; it remains eligible, and these
functions compare the view's 100.01/0.02 rather than the file's 100.00/None.

Runtime proofs use the native loader and the actual `_parse_balance_amount`,
`_balance_match`, `_balance_conflict` and source parser on hash-matched initial
copies. Every file has one raw Balance and zero shared source locations.
Filter gives zero loaded balances and no match/conflict for every action.
Transform gives one loaded balance, matching only the unwritten within-tolerance
action and conflicting with the written same action. Pass gives the correct
raw-source decision in each case. No fabricated CLI or matching result is used.

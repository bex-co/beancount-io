# Coalesce one source file shared by portable-export roles

**Minor · cli · 30–45m · A1.** Portable export refuses a valid ledger when
the same physical file is both an include and a document attachment, or
both an include and a file inside a copied plugin package. It plans the
same source/destination twice, then reports a collision with itself even
in a new output directory. `--force` does not help. No files are written;
this is a false refusal, not data loss. No product fix implemented.

Environment: 2026-10-22 QA, clean main `13a4c4372` (initial package probes
on `a9b710084`, document/rewritten-include probes on `c266ffef5`; implicated
source unchanged), checkout `bea 0.3.1`, frontend Python 3.13.3, managed
Python 3.12.10 / Beancount 3.2.3 / Beanquery 0.2.0, macOS 26.5.1 arm64.
Fresh subprocesses, closed stdin/no TTY, isolated absolute config/cache
paths, notifier disabled, inherited file/token overrides removed. Synthetic
local files only; no feed, optional feature or live service.

Run with the checkout's `bea` on PATH, replacing `/abs/case` with a fresh
absolute disposable directory. A document may point to an existing ledger
file; the source's real `check` accepts it.

```python
import json, os, subprocess
from pathlib import Path
case = Path('/abs/case')
books = case / 'books'
books.mkdir(parents=True)
document_name = 'accounts.bean'
(books / 'accounts.bean').write_text('''2024-01-01 open Assets:Cash USD
2024-01-01 open Income:Services USD
''')
(books / 'receipt.txt').write_text('Synthetic statement\n')
(books / 'main.bean').write_text('''option "operating_currency" "USD"
include "accounts.bean"
2024-01-02 * "Invoice"
  Assets:Cash 100 USD
  Income:Services -100 USD
''' + f'2024-01-03 document Assets:Cash "{document_name}"\n')
original = {p.name: p.read_bytes() for p in books.iterdir() if p.is_file()}
env = os.environ.copy()
for key in ('BEA_FILE', 'BEA_TOKEN', 'BEANCOUNT_LOAD_CACHE_FILENAME',
            'BEA_ENGINE_PYTHON', 'BEA_ENGINE_DIR'):
    env.pop(key, None)
env.update(BEA_CONFIG_DIR=str(case / 'config'), XDG_CACHE_HOME=str(case / 'cache'),
           BEA_NO_UPDATE_NOTIFIER='1')
def run(tag, args):
    argv = ['bea', '--json', '--no-input', '-f', str(books / 'main.bean'), *map(str, args)]
    result = subprocess.run(argv, cwd=case, env=env, stdin=subprocess.DEVNULL,
                            capture_output=True, text=True, timeout=25)
    print(json.dumps(dict(tag=tag, args=argv, exit=result.returncode,
                         stdout=result.stdout, stderr=result.stderr)), flush=True)
run('source-check', ['check'])
run('source-cash', ['query', "SELECT number WHERE account='Assets:Cash'"])
run('export', ['price', 'export', '--output', case / 'snapshot'])
run('force-export', ['price', 'export', '--output', case / 'snapshot', '--force'])
assert all((books / name).read_bytes() == content for name, content in original.items())
```

Actual exits: **0, 0, 2, 2**. Source check is valid and Cash is **100 USD**.
Both exports return JSON on stderr:

```text
Cannot export: /abs/case/snapshot/accounts.bean and /abs/case/snapshot/accounts.bean name the same destination. Choose an empty or dedicated directory. Nothing was written.
```

The named directory was already new and remains absent. Human output gives
the same refusal. All original bytes, including the separate receipt, stay
unchanged. Working control: change only `document_name = 'receipt.txt'`.
Both exports then exit 0, the forced replay replaces each unique artifact
once, and the source-hidden snapshot checks clean with Cash 100 USD.

Expected: recognize that both roles refer to one source artifact at one
output path, export it once and retain both the include/document references.
USAGE promises a self-contained copy carrying includes, local documents
and whole plugin packages. This is not two different sources competing for
one destination. Choosing another empty directory cannot repair this plan.
The failing minimal fixture needs **two** unique exported files; its unused
`receipt.txt` should remain excluded. The receipt control needs three.

Reproduction and scope:

- Four pristine document cases, twice each of document-as-include versus
  separate receipt: **22 CLI calls**. Source check/BQL pass; shared-role
  JSON/human/forced exports all refuse 2 with no target residue. Receipt
  exports and independent source-hidden checks pass.
- Eight pristine plugin-package cases, twice each of namespace/regular
  package × included settings inside/outside it: **44 CLI calls**.
  `books/qa_plugin.py` imports `plugins.qa_helper`, whose VALUE is 100;
  `plugins/settings.bean` sets `insert_pythonpath` and is included by the
  root. Copying `plugins/` whole plans `settings.bean` again. Source check
  and Cash 100 pass; JSON/human/forced exports refuse with the same identical
  path twice. Moving only that settings file to the root, with its include
  pointer updated, gives passing independent snapshots for both package kinds.
- Four more fresh cases (**10 CLI calls**) put an absolute include of
  `books/accounts.bean` inside settings. The shared-role layout still refuses;
  its outside-package control exports the required relative rewrite
  `include "accounts.bean"` and passes with the original hidden. A repair
  must keep rewritten ledger content, not overwrite it with a raw package copy.
- The exact public four-command recipe was replayed twice alongside its
  receipt control, plus human exports and source-hidden checks of successful
  snapshots. All source directories are restored and bytes preserved.

Cause and callers: `cli/src/bea_engine/managed_load.py:1813–1815` combines
ledger `destinations.values()` with `attachments` keys without coalescing
an identical source/destination already planned as a ledger file.
`_export_attachments:2013–2101` supplies the document role;
`_export_plugin_modules:2104–2148` supplies whole package files.
The repeated destination trips the equality check at `:1820–1836`, which
has discarded enough provenance that it cannot distinguish two roles of
one file from genuinely competing sources. The only `export_portable`
caller is engine `price-export` (`bea_engine/main.py:881`), exposed by
frontend `price._export` (`cli/commands/price.py:182`).

Fix in `cli/`: coalesce only genuinely identical source/destination pairs
before collision checks and writing. When the ledger role rewrites includes,
keep its prepared ledger representation and remove the redundant raw
attachment/package copy. Merely deduplicating the path list while leaving
both writers active can replace the rewritten ledger afterward. Keep genuine
distinct-source destination collisions refused, unique file counts and
`overwritten` results accurate, and unrelated files excluded. No dependency
or API change indicated.

**Resolved 2026-10-23** — fixed: portable export (`export_portable` in `cli/src/bea_engine/managed_load.py`) now coalesces one file in two roles. An attachment or plugin-package file whose destination is already a ledger file's destination, and whose source is that same file, is dropped from the attachment plan, so the ledger's own copy (which carries the rewritten includes) is planned and written once. A document pointing at an included `accounts.bean`, and an included `plugins/settings.bean` inside a copied regular or namespace package, now export in a new directory and under `--force` and the snapshot checks with the source hidden; a separate receipt is still an attachment, and two different sources competing for one destination still refuse. Regression tests in `cli/tests/test_price_export_shared_roles.py` fail without the fix. Full suite green. Shipped in this commit (`cli`).

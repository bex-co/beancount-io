# Delete ghost collaborator returns INTERNAL instead of BAD_USER_INPUT

**Severity:** medium. **Journey:** account. **Owner:** backend-v2. Found by the MCP QA auth sweep on 2026-10-03 against production; live at repo HEAD `75819075`. No live board dupe.

Target: `https://beancount.io`, `POST /api-gateway/mcp` (production), observed 2026-10-03.
serverInfo `{"name":"beancount-mcp","version":"1.0.0"}`, protocolVersion `2025-11-25`.
Credential: `bcio_` API key (server kind `apikey`), scopes `ledger.read ledger.write ledger.admin`, ledger pin none (unpinned), no expiry. Value never recorded.
Helper: `node .agents/skills/qa-shared/scripts/qa-mcp.mjs --credentials-file muse.env` from repo root.

## Repro (synthetic coords `qa-owner/qa-book`)

```sh
call manageLedgerCollaborators '{"operation":"delete","ledger":"qa-owner/qa-book","collaborator":"zz-ghost"}'
```

JSON-RPC sent:

```json
{"jsonrpc":"2.0","method":"tools/call","params":{"name":"manageLedgerCollaborators","arguments":{"operation":"delete","ledger":"qa-owner/qa-book","collaborator":"zz-ghost"}},"id":1}
```

Observed: INTERNAL_SERVER_ERROR `user does not exist [uid: 0, ...]` + retry hint. Sibling `update` correctly returns BAD_USER_INPUT `No such user` for the same ghost.

## Control

REST: DELETE ghost collaborator -> HTTP 500 INTERNAL_SERVER_ERROR (masked message, same defect class).

## Cause

- `backend-cluster/backend-v2/src/features/ledger/workflow/ledger-collaborators-workflow.ts`

Only the update path translates Gitea's `user does not exist` into BadUserInputError (:154-160); delete has no catch, so the raw message falls through `categoryForMessage` (the `not found` regex misses `does not exist`) to INTERNAL. Shared workflow -> all surfaces.

## Fix (parity: MCP+REST+GraphQL)

Owning package `backend-cluster/backend-v2`; the fix must land on every eligible surface (MCP+REST+GraphQL) in the same change. Apply the same translation (or a NOT_FOUND mapping) on delete/permission paths, all surfaces.

## Evidence

`.tmp/qa-2026-10-03-auth/r2-boundaries-account/15-collab-ghost-tool.txt`; `.tmp/qa-2026-10-03-auth/r2-boundaries-account/15b-rest-collab-delete-ghost.txt` (gitignored bundle `.tmp/qa-2026-10-03-auth/`); finding brief `.tmp/qa-2026-10-03-auth/final/boundaries-account-collab-delete-ghost-user.md`.

---

**Resolved 2026-10-02** — deleting a collaborator who does not exist is now answered `BAD_USER_INPUT` with `No such user: <name>` on REST (400), GraphQL and MCP. Delete shares the translation the update path already had, in the workflow all three surfaces call. Shipped in `0aec6489` (`backend-cluster/backend-v2`).

A regression test drives the delete through HTTP REST, GraphQL execution and an MCP client with the upstream refusal the note recorded, and asserts the category, the message and that no upstream detail is echoed; it fails with the fix reverted. Other upstream failures are rethrown unchanged. The permission-read path is [026](./026.md). Not re-run against the hosted endpoint: the fix reaches it with the next deploy.

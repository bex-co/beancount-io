# Directory path reads as empty file; getFilesContent drops the dir type

**Severity:** medium. **Journey:** resources. **Owner:** backend-v2. Found by the MCP QA auth sweep on 2026-10-03 against production; live at repo HEAD `75819075`. No live board dupe.

Target: `https://beancount.io`, `POST /api-gateway/mcp` (production), observed 2026-10-03.
serverInfo `{"name":"beancount-mcp","version":"1.0.0"}`, protocolVersion `2025-11-25`.
Credential: `bcio_` API key (server kind `apikey`), scopes `ledger.read ledger.write ledger.admin`, ledger pin none (unpinned), no expiry. Value never recorded.
Helper: `node .agents/skills/qa-shared/scripts/qa-mcp.mjs --credentials-file muse.env` from repo root.

## Repro (synthetic coords `qa-owner/qa-book`)

```sh
read beancount://qa-owner/qa-book/files/FY2026 (a directory; also `call readLedgerFiles '{"path":"FY2026"}'`)
```

JSON-RPC sent:

```json
{"jsonrpc":"2.0","method":"resources/read","params":{"uri":"beancount://qa-owner/qa-book/files/FY2026"},"id":1}
```

Observed: 200 with empty text on the MCP resource; the `readLedgerFiles` tool and REST likewise return empty content with no dir signal: a directory masquerading as an empty file.

## Control

REST reads the directory path as empty content too (same defect at every layer).

## Cause

- `backend-cluster/backend-v2/src/features/ledger/service/ledger-repo-service.ts`
- `backend-cluster/backend-v2/src/features/ai-agent/tools/read-ledger-files-tool.ts`

No dir guard at any layer: `getFilesContent` returns `{path, content, sha}` with the `type` dropped (:186-217), and the read tool/resource pass empty content through without distinguishing `empty file` from `not a file`.

## Fix (parity: MCP+REST+GraphQL)

Owning package `backend-cluster/backend-v2`; the fix must land on every eligible surface (MCP+REST+GraphQL) in the same change. Surface the entry type, or refuse dir paths with BAD_USER_INPUT/NOT_FOUND.

## Evidence

`.tmp/qa-2026-10-03-auth/r5-reads-resources/y35-file-dirasfile.txt` (gitignored bundle `.tmp/qa-2026-10-03-auth/`); finding brief `.tmp/qa-2026-10-03-auth/final/resources-file-dir-empty-read.md`.

---

**Resolved 2026-10-03** — reading a directory path as a file is now refused as `BAD_USER_INPUT` (`<path> is a directory, not a file`, with a hint naming the listing call) on REST (400), the MCP file resource (`-32602`) and the `readLedgerFiles` tool. The refusal is in the one service all of them read through, so the edit tool and the directive-append workflow get it too. Shipped in `1cda9fe6` (`backend-cluster/backend-v2`).

GraphQL needed no change: `getLedgerFile` goes through a different read and already returns the entry's `type`, so a directory was never indistinguishable from an empty file there. A new test reads a directory and a real file through HTTP REST, the MCP resource and the MCP tool; the directory case fails with the fix reverted. Not re-run against the hosted endpoint: the fix reaches it with the next deploy.

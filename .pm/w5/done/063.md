# Bulk amount shorthand rejects valid partial lot selectors

**Minor · cli · 25–40m · A1.** Continuous real CLI QA, 2026-10-08,
HEAD `c7038a0c`, checkout `bea 0.3.1`, Python 3.13.3, macOS. Moving a
working sale posting into bulk JSON fails for `{USD}`, `{2026-01-02}` and
`{}`, although single-add and structured bulk input accept the same selectors.
No product fix implemented.

Create a synthetic `main.bean`:

```beancount
2026-01-01 open Assets:Cash USD
2026-01-01 open Assets:Stock HOOL
2026-01-01 open Income:Gain USD
2026-01-02 * "buy"
  Assets:Stock 10 HOOL {10 USD, 2026-01-02}
  Assets:Cash -100 USD
```

Create `sale.json`:

```json
[{"date":"2026-01-03","narration":"sale","postings":[
  {"account":"Assets:Stock","amount":"-4 HOOL {USD} @ 15 USD"},
  {"account":"Assets:Cash","amount":"60 USD"},
  {"account":"Income:Gain","amount":"-20 USD"}
]}]
```

Run with absolute ledger/input paths, isolated `BEA_CONFIG_DIR` and
`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, no inherited `BEA_FILE` or
`BEA_TOKEN`, closed stdin, and no TTY:

```sh
bea --json --file /absolute/main.bean add transactions --from /absolute/sale.json
```

Actual: exit 1, empty stdout, JSON validation error on stderr naming
`Row 1, postings.0` and `incomplete cost`. Result reports zero written and
`rejected_rows: [0]`; the ledger stays byte-identical. Date-only and empty
selectors fail identically. All three reproduced in two fresh fixture sets.

Nearby controls, each on a pristine ledger:

```sh
bea --json --file /absolute/main.bean add transaction sale --date 2026-01-03 \
  -p 'Assets:Stock -4 HOOL {USD} @ 15 USD' \
  -p 'Assets:Cash 60 USD' -p 'Income:Gain -20 USD'
```

Single-add exits 0 for all three selectors. Structured bulk input also exits
0 when its stock posting is:

```json
{"account":"Assets:Stock","units":{"number":"-4","currency":"HOOL"},
 "cost":{"currency":"USD"},"price":{"number":"15","currency":"USD"}}
```

Use `cost: {"date":"2026-01-02"}` or `cost: {}` for the other controls.
Every successful control passes a fresh `bea check`; a separate BQL query
`SELECT sum(number) WHERE account='Assets:Stock'` returns 6. These are valid
existing-lot selections, not malformed cost syntax or unsupported short sales.

Expected basis: `cli/docs/USAGE.md` says bulk amount shorthand accepts the
same lot spelling as single `--posting`, with an explicit exception for total
costs. It documents currency-only/date-only constraints and structured bulk
round trips. `_posting_fragment` itself says it accepts native syntax.

Root cause: `cli/src/bea_engine/ledger/models.py:209–213`
`_posting_fragment` refuses any parsed CostSpec with MISSING `number_per` or
`currency`. That excludes valid selectors even though the shared `Cost` model
already makes all fields optional. Its caller is `Posting.amount_shorthand`,
used by bulk transaction validation. Single-add parses its posting separately;
structured bulk skips this fragment conversion.

Fix the fragment-to-Cost mapping to preserve missing components as null,
including date/label constraints, using the existing schema and writer.
Retain the documented total-cost shorthand refusal and malformed-fragment
errors. No new dependency, custom parser or backend API change is needed.

Full-board/history dedupe found no matching open selector-shorthand item.
Completed w3/272 / w1/m27 added full cost/price fragments (`afc2af7e`) but
left this guard. Completed w3/414, w3/416 and w3/m49 fixed single-add cost
serialization/rendering and structured round trips; those controls now work.
This is the remaining bulk shorthand adapter, not those repaired write bugs.

Acceptance: all three shorthand selectors append once, pass check, leave
6 HOOL, and retain the intended cost constraint in file/result. Single-add,
structured bulk, full per-unit costs and total-cost refusal keep their behavior.
Only macOS/file-ledger input was exercised; other platforms remain unverified.

Sanitized evidence: `cli/tmp/qa-20261008-cli/bulk_selectors.py`,
`bulk-selectors-console.jsonl`, `bulk_selector_file.py`,
`bulk-selector-file-console.jsonl`, pristine fixture sets and `transcript.jsonl`
retain argv/cwd/environment, stdin mode, streams/exits and before/after hashes.
Both `--from -` and the exact file-input journey above were exercised.
Public fixtures are complete.

---

**Resolved 2026-10-10** — the bulk `amount` shorthand now maps a cost's missing number or currency to null instead of refusing the fragment, so `-4 HOOL {USD} @ 15 USD`, `{2026-01-02}`, `{}` and label-only or combined selectors are accepted like their `--posting` and structured spellings. The total-cost refusal is unchanged. Shipped in `e3b47c04` (`cli`).

Real-command regression tests sell from an existing lot with five partial selectors and a full per-unit control. Each asserts one appended transaction carrying the selector as written, a passing `bea check`, 6 HOOL remaining, and that the structured spelling of the same constraint writes byte-identical text. Total-cost, merge (`{*}`, which upstream's parser rejects) and malformed fragments are still row rejections that write nothing. Five tests fail with the fix reverted. `docs/USAGE.md` names the selectors beside the shorthand. `make check-all` passed. Stdin input was not re-run here, and only macOS was tested.

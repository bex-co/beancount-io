## Fix (parity: MCP)

Owning package `backend-cluster/backend-v2`; the fix must land on every eligible surface (MCP) in the same change. `prompts/get` request-handler override with the coded envelope.

---

**Resolved 2026-10-03** — `prompts/get` for a name that does not exist is now refused as `-32002` with `data.code: NOT_FOUND` and a hint naming `prompts/list`, with one message prefix instead of two. `prompts/get` is answered at the server's own boundary, as `tools/call` and `resources/read` are. Shipped in `9db7ccf0` (`backend-cluster/backend-v2`).

Two neighbouring SDK-dialect refusals went with it: an argument of the wrong type is now a coded `BAD_USER_INPUT`, and a prompt fetched with no `arguments` object at all now builds its playbook, since every argument is optional. Tests fetch an unknown name and a prompt without arguments through an MCP client; both fail with the fix reverted. Not re-run against the hosted endpoint: the fix reaches it with the next deploy.

# Find account-providing roots for flagged postings

**Minor · cli · 20–30m.** Real local CLI QA, 2026-10-22, checkout `bea 0.3.1` at
`89d94452fa901d3304cb4b86ae8a7570b5e4369d`, macOS 26.5.1 arm64,
frontend Python 3.13.3, managed Python 3.12.10 / Beancount 3.2.3.
No product fix implemented. A1: reliable local-ledger automation; worker1.

A native-valid split ledger uses builtin `auto_accounts` in main.bean and
flags both postings in its included entries.bean. `bea -f entries.bean add
note` refuses with exit 1, unknown Assets:Cash, although main.bean supplies
that exact account. Removing the posting flags alone makes the same command
route through main.bean and succeed. The flagged leaf and complete root
remain byte-for-byte unchanged on refusal; no invalid write was observed.

[USAGE](../../cli/docs/USAGE.md#adding-directives) promises automatic routing
when an includer supplies a plugin for accounts the leaf posts to but never
opens. Posting flags change posting status, not the account or required opens.
The builtin plugin was inspected before use; it creates missing opens locally.

Run this standalone recipe in two fresh absolute directories. Its modes
include all flagged forms exercised and nearby working controls. Children
use isolated config/cache, closed stdin/no TTY, bounded timeouts, separate
streams and file hashes; no global CLI state or real ledger is touched.

```python
import hashlib, json, os, pathlib, subprocess
case = pathlib.Path('/abs/flagged-provider-case')
mode = 'all-star'  # all-bang, all-glued-star, all-P, plain, one-plain, hard-root-opens, self-open
human_add = False
case.mkdir(parents=True)
leaf, root = case/'entries.bean', case/'main.bean'
prefix = {'all-star':'* ','all-bang':'! ','all-glued-star':'*','all-P':'P ',
          'plain':'','one-plain':'','hard-root-opens':'* ','self-open':'* '}[mode]
second = '! ' if mode=='one-plain' else prefix
opens = '2024-01-01 open Assets:Cash USD\n2024-01-01 open Equity:Opening USD\n'
leaf.write_text((opens if mode=='self-open' else '') + '2024-01-02 * "Capital"\n'
                + f'  {prefix}Assets:Cash 100.00 USD\n'
                  f'  {second}Equity:Opening -100.00 USD\n',encoding='utf-8')
root.write_text((opens if mode=='hard-root-opens' else '')
                + 'plugin "beancount.plugins.auto_accounts"\ninclude "entries.bean"\n',
                encoding='utf-8')
original = {p:p.read_bytes() for p in (leaf,root)}
(case/'initial-entries.txt').write_bytes(original[leaf])
env = os.environ.copy()
for key in ('BEA_FILE','BEA_TOKEN','BEANCOUNT_LOAD_CACHE_FILENAME'):
    env.pop(key,None)
env.update(BEA_CONFIG_DIR=str(case/'config'),XDG_CACHE_HOME=str(case/'cache'),
           BEA_NO_UPDATE_NOTIFIER='1')
def run(tag,args,file=root,json_mode=True):
    before = leaf.read_bytes()
    cmd = ['bea',*(['--json'] if json_mode else []),'--no-input','-f',str(file),
           *map(str,args)]
    r = subprocess.run(cmd,cwd=case,env=env,stdin=subprocess.DEVNULL,
                       capture_output=True,text=True,timeout=25)
    print(json.dumps(dict(tag=tag,args=cmd,exit=r.returncode,stdout=r.stdout,
                          stderr=r.stderr,leaf_preserved=leaf.read_bytes()==before,
                          before_sha256=hashlib.sha256(before).hexdigest(),
                          after_sha256=hashlib.sha256(leaf.read_bytes()).hexdigest(),
                          root_preserved=root.read_bytes()==original[root])),flush=True)
run('root-before',['check'])
run('add',['add','note','--date','2024-01-03','--account','Assets:Cash',
           '--comment','Reviewed statement'],leaf,json_mode=not human_add)
run('root-after',['check'])
run('notes-after',['list','note'])
```

Actual, reproduced twice for `all-star`, `all-bang`, `all-glued-star`, `all-P`:

- Root check exits 0 before and after. Independent native loads recognize
  both posting flags, 100 USD cash and opens for Assets:Cash/Equity:Opening.
- Add note through entries.bean exits 1 with Assets:Cash unknown, no note,
  and unchanged leaf/root hashes. Human mode has the same refusal.
- Native initial and final graphs remain valid, with cash 100 and zero notes.

Controls, twice: `plain` and `one-plain` (only one posting unflagged) route
through main.bean, append exactly one note, and keep the complete book valid.
`hard-root-opens` retains both posting flags but supplies literal root opens;
it routes and succeeds. `self-open` supplies the leaf's own opens; it succeeds
without needing the plugin root. Every control retains 100 USD cash and root
bytes. Thus the root scan is the failing step, not native flag parsing or the
note writer. Reading/checking a bare unopened leaf is not itself a bug.

an account immediately after leading whitespace. It does not skip an optional
posting flag, so all four flagged profiles produce an empty posted-account
set. `_posts_unopened` at 2072 incorrectly returns false and `_defines_in`
does not count the fresh root plugin as a provider. Runtime proofs on exact
initial copies show the plugin name recognized, both native account postings
present, the scanner's own posted set empty, and entries.bean selected.
Plain/one-plain return true and select main.bean; literal opens provide the
independent definition in hard-root-opens. Source initial-copy hashes match
the first public command's captured input.

**Resolved 2026-10-23** — fixed: the posted-account scan (`_POSTED_ACCOUNT` in `cli/src/bea_engine/ledger/write.py`) now reads an account after a posting flag — a symbol flag (`*`, `!`, `&`, `#`, `?`, `%`), glued to the account or spaced, or a capital letter such as `P` and a space. A leaf whose postings are all flagged therefore no longer reads as posting to nothing: the `auto_accounts` root that supplies the opens is chosen, and `add note` against the leaf routes through it, writes to the leaf and checks clean (previously exit 1, unknown account). Unflagged and partly flagged postings, and a root that hard-opens the accounts, behave as before. Regression tests in `cli/tests/test_root_provider_flagged_postings.py` fail without the fix (star, bang, glued star, capital P). Full suite green. Shipped in this commit (`cli`).

# `bea --json format --output` succeeds without the promised JSON result

**Severity:** minor. **Estimate:** 30–45 minutes. **Owner:** cli. **A1:** an
agent can write a formatted ledger, but cannot rely on the documented JSON
automation contract to learn what happened.

Found 2026-09-13 by a report-only CLI QA sweep against `main`, HEAD
`038faeeb`, using `uv run bea` 0.2.0 on Darwin 25.5.0 arm64 with isolated
config/cache directories. The fixture was a valid synthetic ledger containing
only local data.

## Repro

```sh
printf '2026-01-01 open Assets:Cash USD\n' > main.bean
bea --json format main.bean --output clean.bean
echo "$?"
test -f clean.bean && echo destination-exists
```

The command exits `0`, creates `clean.bean`, leaves `main.bean` unchanged, and
writes nothing to either stdout or stderr:

```text
0
destination-exists
```

The related stdout destination also exits `0`, but writes formatted Beancount
source directly to stdout rather than a JSON envelope:

```sh
bea --json format main.bean --output -
```

Its stdout begins with `2026-01-01 open Assets:Cash USD`, and is not parseable
as the standard `bea` JSON response. A fresh process with
`--json format main.bean --in-place` does emit the expected envelope, so this
is specific to the `--output` path.

## Expected / actual

`cli/docs/USAGE.md:231-238` says JSON mode reserves stdout for the envelope,
and `:768-781` says `format` emits an envelope so a script can confirm what was
written. `--output FILE` should therefore write the formatted ledger to that
file and emit a success envelope describing the destination. `--output -`
should either have a documented JSON representation or fail with a usage error
instead of mixing raw ledger text with JSON mode.

The actual successful file write has an empty stdout, while `--output -`
returns raw formatter text with no envelope. A caller that parses JSON cannot
inspect the result, and a caller that expects a JSON error for the conflicting
stdout destination gets exit `0` instead.

## Root cause

`cli/src/cli/commands/format.py:79-85` only rejects JSON mode when neither
`--in-place` nor `--output` is present. At `:87-93`, the command delegates to
`bean-format`; the `not in_place` branch exits immediately after the native
command succeeds. The JSON `output.emit(...)` call at `:98-100` is therefore
reachable only for `--in-place`. `_destination()` at `:200-201` passes
`--output -` through unchanged, so upstream prints raw source to the same
stdout reserved for JSON.

## Fix

After a successful explicit `--output FILE`, emit the standard JSON envelope
with the scanned files and destination while preserving the formatted file
write. In JSON mode, reject `--output -` with a usage error explaining that raw
formatter output cannot share the JSON stdout stream; plain `bea format ...
--output -` remains the text export path. Add regression coverage for both
destinations and document the chosen envelope/error behavior.

## Blast radius and adjacent states

The failure covers successful JSON formatting with an explicit output file,
including the stdout sentinel. `--json format FILE --in-place`, `--check`, and
`--dry-run` return the expected machine-readable result or error; human-mode
`--output FILE` works. Directory output semantics, output-path failures, and
Windows were not exercised.

## Dedupe

Searched all `.pm/**/*.md`, including `done/`, for format JSON, output files,
and missing envelopes. `.pm/w2/021.md` covers `bea query` silently dropping
query output/shape flags under JSON; the current query path was rechecked and
is separate from this formatter branch. `.pm/w2/019.md` covers formatter
syntax-error handling, and `.pm/w2/023.md` covers `--check` remediation and
width validation. None covers a successful formatter write with no JSON
result. `git log -S 'not in_place' -- cli/src/cli/commands/format.py` shows the
behavior came from the original independent-engine implementation
(`a90b1706`); no later fix is present on `main`.

## Evidence and unverified areas

The bounded subprocess capture under
`cli/tmp/qa-20260913-w5/cases/format-output/` recorded argv, cwd, isolated
environment, separate streams, exit code, duration, and destination creation.
No credentials or private ledger data were used. Multi-file explicit output,
write failures, and installed releases outside this checkout remain
unverified.

---

**Resolved 2026-09-15** — fixed and shipped in `32c1a175` (`cli`), with the package's full check gate green. A successful `--json format --output FILE` now emits the standard envelope naming the destination it wrote, and `--output -` is refused in JSON mode instead of mixing ledger text into the envelope's stream.

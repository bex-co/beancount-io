# Respect forecast boundaries for compact transaction flags

**Major · cli · 30–45m · A1 · worker1.** Real local CLI QA, 2026-10-22,
checkout `bea 0.3.1` at `32e954223b04365c1dfde9362483d8f08f67ccbb`, including
completed 934's `b231a9e90`; macOS 26.5.1 arm64, frontend Python 3.13.3,
managed Python 3.12.10 / Beancount 3.2.3. No product fix implemented.

A native transaction flag touching its date (`2024-01-15*"Forecast"`) makes
root discovery miss a forecast entry. It climbs through that forecast view
to a currency-setting wrapper and validates a write there. `add balance`
then accepts a hypothetical **1100 USD** assertion, exits 0 and appends it to
the real **1000 USD** working book. The previously valid working book fails
check. Its truthful 1000 USD assertion is instead refused. No force,
allow-errors, plugin, network service or remote ledger is involved.

[USAGE's root-selection contract](../../cli/docs/USAGE.md#adding-directives)
says a forecast view that only adds entries is not the working ledger's root;
writes and failing reads stay with the named working ledger. The same native
entry with spaces, or compact `txn` syntax, correctly stops the climb. A
layout-equivalent flag must preserve that boundary and the strict assertion.

Replace `/abs/compact-forecast-case` with a fresh absolute directory, run the
standalone reproducer, then repeat in another fresh directory. `human_add=True`
checks human output; other modes and `amount='1000.00 USD'` provide controls.
The children have isolated config/cache, closed stdin/no TTY, bounded timeouts,
separate streams and file-preservation/hash records.

```python
import hashlib, json, os, pathlib, subprocess
case = pathlib.Path('/abs/compact-forecast-case')
mode = 'compact-star'  # compact-bang, spaced-star, compact-word, explicit-into
amount = '1100.00 USD'  # use 1000.00 USD in a second fresh case
human_add = False
case.mkdir(parents=True)
working = case / 'working.bean'
forecast = case / 'forecast.bean'
wrapper = case / 'wrapper.bean'
working.write_text('''2024-01-01 open Assets:Cash USD
2024-01-01 open Equity:Opening USD
2024-01-02 * "Capital"
  Assets:Cash 1000.00 USD
  Equity:Opening -1000.00 USD
''', encoding='utf-8')
head = {'compact-star':'*', 'compact-bang':'!', 'spaced-star':' * ',
        'compact-word':'txn', 'explicit-into':'*'}[mode]
forecast.write_text('include "working.bean"\n'
                    + f'2024-01-15{head}"Forecast"\n'
                      '  Assets:Cash 100.00 USD\n'
                      '  Equity:Opening -100.00 USD\n', encoding='utf-8')
wrapper.write_text('option "operating_currency" "USD"\ninclude "forecast.bean"\n',
                   encoding='utf-8')
original = {p: p.read_bytes() for p in (working, forecast, wrapper)}
env = os.environ.copy()
for key in ('BEA_FILE','BEA_TOKEN','BEANCOUNT_LOAD_CACHE_FILENAME'):
    env.pop(key, None)
env.update(BEA_CONFIG_DIR=str(case/'config'), XDG_CACHE_HOME=str(case/'cache'),
           BEA_NO_UPDATE_NOTIFIER='1')
def run(tag, args, file=working, json_mode=True):
    before = working.read_bytes()
    cmd = ['bea', *(['--json'] if json_mode else []), '--no-input',
           '--file', str(file), *map(str,args)]
    r = subprocess.run(cmd,cwd=case,env=env,stdin=subprocess.DEVNULL,
                       capture_output=True,text=True,timeout=25)
    print(json.dumps(dict(tag=tag,args=cmd,exit=r.returncode,stdout=r.stdout,stderr=r.stderr,
                          working_preserved=working.read_bytes()==before,
                          working_sha256=hashlib.sha256(working.read_bytes()).hexdigest(),
                          views_preserved=all(p.read_bytes()==original[p]
                                              for p in (forecast,wrapper)))),flush=True)
run('working-before',['check'])
run('wrapper-before',['check'],wrapper)
args = ['add','balance','--date','2024-02-01','--account','Assets:Cash','--amount',amount]
if mode == 'explicit-into':
    args += ['--into',working]
run('add',args,json_mode=not human_add)
run('working-after',['check'])
run('wrapper-after',['check'],wrapper)
```

Default mode, amount 1100.00, reproduced twice in JSON and human output:

- Both initial checks exit 0. Independent native loads confirm that
  `working.bean` holds 1000 USD and `wrapper.bean` holds 1100 USD, including
  the forecast's 100 USD. Every file is native-valid before the write.
- `add` exits 0, `written: 1`, with `target.file` naming **wrapper.bean** and
  `target.into` naming **working.bean**. Its warning says the write goes to
  working.bean and is checked against that whole wrapper.
- Only working.bean changes, gaining `2024-02-01 balance Assets:Cash 1100.00 USD`.
  Its next check exits 1 with one JSON stderr object, empty stdout, and
  `expected 1100.00 USD != accumulated 1000.00 USD (100.00 too little)`.
  The same error wrongly advises reading wrapper.bean, which still checks
  successfully. Native loads independently confirm both outcomes; the
  transaction balance in working.bean remains 1000 USD, not 1100.

In a separate pristine default case, the truthful 1000.00 USD add exits 1
against the wrapper's hypothetical 1100 USD. It writes nothing and both books
remain valid. This is wrong context selection, not a rounding tolerance.

Nearby controls, each repeated twice:

- `spaced-star` and `compact-word` validate against working.bean. False 1100
  refuses with exit 1 and unchanged files; true 1000 writes once and the
  working book checks. The forecast wrapper then fails that real-world
  assertion, as expected for its conflicting hypothetical balance; it is
  not the book the user selected for validation.
- `explicit-into` keeps the same compact star but explicitly targets the
  working file with `--into`. It restores the same correct behavior.
- A genuine empty intermediate containing only `include "working.bean"`
  still climbs to the currency-setting wrapper. Both books then hold 1000;
  true 1000 writes, false 1100 refuses. Do not repair this by disabling
  pass-through root discovery.

A wider native-valid matrix covers compact `*`, `!`, `&`, `#`, `?`, `%`,
spaced star and compact `txn`, both true/false assertions and both repetitions:
32 fixtures / 160 real CLI calls. Every punctuation-compact form has the
wrong-context write/refusal pair; the two controls work. Initial and final
native loads retain the respective 1000/1100 USD transaction totals. No
fixture was excluded as invalid.

Cause: `cli/src/bea_engine/ledger/write.py:_ENTRY_LINE` at line 2063 matches
`_DATE + (?:[ \t]+\S|[A-Za-z])`. It recognizes a compact directive word but
not a compact punctuation flag. `_step_adds_entries` consequently reports
false for the forecast's actual Transaction. `defining_root` treats that
view as an empty pass-through, climbs to wrapper.bean and sees its fresh
operating-currency option as a definition. Runtime helper proofs show
`_ENTRY_LINE` / `_step_adds_entries` false and the wrapper selected; spaced
star / compact `txn` return true and keep working.bean. `_nearest_includers`
correctly returns only forecast.bean, so this is not two-root ambiguity.

Fix the native transaction-entry recognition, including punctuation flags
adjacent to the date. Keep actual definition detection, the nearest-includer
rule, empty intermediates and explicit-root/`--into` selection intact. The
same helper serves root-directed adds/imports and failing-read root hints;
this journey exercises balance add and check, not other write types. The
change belongs entirely to CLI root routing, with no API or dependency change.

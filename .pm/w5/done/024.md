# manageApiKeys unknown argument returns INTERNAL with raw Zod dump

**Severity:** medium. **Journey:** account. **Owner:** backend-v2. Found by the MCP QA auth sweep on 2026-10-03 against production; live at repo HEAD `75819075`. No live board dupe.

Target: `https://beancount.io`, `POST /api-gateway/mcp` (production), observed 2026-10-03.
serverInfo `{"name":"beancount-mcp","version":"1.0.0"}`, protocolVersion `2025-11-25`.
Credential: `bcio_` API key (server kind `apikey`), scopes `ledger.read ledger.write ledger.admin`, ledger pin none (unpinned), no expiry. Value never recorded.
Helper: `node .agents/skills/qa-shared/scripts/qa-mcp.mjs --credentials-file muse.env` from repo root.

## Repro (synthetic coords `qa-owner/qa-book`)

```sh
call manageApiKeys '{"operation":"list","bogus_field":1}'
```

JSON-RPC sent:

```json
{"jsonrpc":"2.0","method":"tools/call","params":{"name":"manageApiKeys","arguments":{"operation":"list","bogus_field":1}},"id":1}
```

Observed: isError INTERNAL_SERVER_ERROR with the raw `unrecognized_keys` Zod JSON and a retry hint, instead of BAD_USER_INPUT.

## Control

None: MCP-boundary-only defect (loose advertised schema + strict in-handler parse); REST takes no free-form arg bag.

## Cause

- `backend-cluster/backend-v2/src/features/ai-agent/tools/api-key-tools.ts`
- `backend-cluster/backend-v2/src/features/ai-agent/api/mcp-errors.ts`

Advertised schema is deliberately `.loose()` (:128) so the boundary parse passes; the handler strict-parses inside `runToolSafely`, whose caught-Zod path returns the raw dump with no code, and `splitToolFailure` defaults it to INTERNAL (:186-221). The `envelopeFromThrown` Zod compactor never runs here.

## Fix (parity: MCP)

Owning package `backend-cluster/backend-v2`; the fix must land on every eligible surface (MCP) in the same change. Compact Zod in `splitToolFailure`, or strict pre-validate at the boundary for this tool.

---

**Resolved 2026-10-02** — the tools' shared error boundary now classifies a tool's own argument-parse failure as BAD_USER_INPUT and reduces it to `argument: reason`, so `manageApiKeys` with an unknown argument names that argument instead of answering INTERNAL with the issue array and a retry hint. Shipped in `ae4fb41c` (`backend-cluster/backend-v2`).

The fix is in the boundary rather than in this one tool, so every tool that parses inside it gets the same answer. Regression tests call `manageApiKeys` through an MCP client with `bogus_field` and assert the code, the named argument, the absence of the dump and that the key store is never read; they fail with the fix reverted. MCP only, as the note says — REST and GraphQL take no free-form argument bag. Not re-run against the hosted endpoint: the fix reaches it with the next deploy.

# Reject calendar-week dates that escape their stated year

**Minor · cli · 30–45m · A1 · worker1.** With a calendar-year week format,
CSV `2021-W53-1` previews and writes as **2022-01-03**; week-zero inputs
can instead write in December 2020. No date in calendar year 2021 has
these encoded week/weekday combinations. The CLI accepts the normalized
date, returns exit 0, and moves the expense into another reporting year.
Both two-digit years and mixed valid/invalid files reproduce. No product
fix implemented.

Environment: 2026-10-24, clean main `0241ec311719174290aef774fb2611f61ad8a749`; CLI byte-identical
to frozen `ee4b7702516da4535bb3b478e2efe9913b09481b`. Checkout `bea 0.3.1`,
frontend Python 3.13.3, managed Python 3.12.10 / Beancount 3.2.3 /
Beanquery 0.2.0, macOS 26.5.1 arm64. Bounded fresh subprocesses, closed
stdin/no TTY, absolute isolated config/cache and notifier disabled.
Synthetic local ledgers and small bank exports only.

## Standalone reproduction

Put this checkout's `bea` on PATH, save the following as `recipe.py`, and
run `python3 recipe.py /absolute/unused/book monday-next json`. Repeat in
another unused directory with `human`. Other modes exercise each rollover,
mixed files and nearby valid calendar/ISO controls. The parser dates in
the case table are observed conversions in the current managed runtime;
the separate calendar enumeration determines whether the source fields
name an actual day. It compares numeric fields, allowing unpadded weeks.

The recipe preserves the CSV, captures arguments/cwd/environment, stdin/TTY
mode, streams, exit codes, durations and before/after hashes in
`results.json`, and saves its calendar reference independently.

## Cause and scoped repair

`cli/src/bea_engine/csv_mapper.py:1323–1364`, `_strptime`, first calls
`datetime.strptime`, then immediately returns when the format lacks `%j`.
The calendar-week formats therefore bypass the added calendar-year check.
The standard-library week calculation can normalize an impossible week-0
or week-53 weekday outside the supplied calendar year; the row reader
accepts that valid resulting date. The same helper serves the format probe
and `CsvImporter.extract`, so preview and apply agree on the wrong date.

Validate the encoded calendar year/week/weekday together before emitting
a transaction. Preserve both full and two-digit years, valid week-zero and
week-53 dates, optional week padding, and the distinct ISO-year semantics.
Do not require every input to equal `strftime` byte-for-byte. Invalid rows
must fail before the default atomic write. Existing ordinal validation and
its error shape stay intact. This is a local CSV parser change, without a
dependency or REST/GraphQL/MCP change.

Caller search covers `_parses` (:1315), `_strptime` and the row reader's
`_strptime` call, all in this CSV mapper; `importing.answer` constructs the
importer. Explicit and remembered formats converge here. Remembered
format replay, other weekdays/locales, alternate format compositions and
other operating systems were not separately exercised for this gap.

**Resolved 2026-10-27** — a calendar-week date must fall in the year it states (`_strptime` in `cli/src/bea_engine/csv_mapper.py`): with `%U` or `%W` and a `%Y`/`%y` year (and no day-of-year, month or day directive deciding the date), a week/weekday pair that Python rolls into the previous or next year is refused as a bad date, naming the row, column and format, before anything is written. `2021-W53-1` (`%W`), `2021-W53-0` (`%U`), the week-zero cases and the two-digit years are refused, and a mixed file writes nothing.

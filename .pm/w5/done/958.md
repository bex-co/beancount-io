# Keep unused unopened accounts out of remembered CSV settings

**Minor · cli · 30–45m · A1/A2.** The guard against remembering a
misspelled source/default account only checks accounts used by extracted
transactions. Empty or entirely skipped exports save the typo; a corrected
source account then leaves two remembered choices and blocks flag-free
imports. A default category unused because every row matches a rule is
saved too. Follow-up to completed [452](./done/452.md) and
[714](./done/714.md). No product fix implemented; ledger bytes are preserved.

Real CLI QA, 2026-10-21, HEAD `f3292f076` (CLI unchanged from `8c1ceacb7`),
checkout `bea 0.3.1`, macOS 26.5.1 arm64, frontend Python 3.13.3, managed
Python 3.12.10 / Beancount 3.2.3. Fresh bounded subprocesses, closed
stdin/no TTY, fresh per-case absolute `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`,
notifier disabled, inherited `BEA_FILE`/`BEA_TOKEN` removed. Synthetic data.

Create a disposable fixture:

```python
from pathlib import Path
books = Path('/abs/books')
books.mkdir(parents=True, exist_ok=True)
(books / 'main.bean').write_text(
    '2024-01-01 open Assets:Cash USD\n'
    '2024-01-01 open Expenses:Food USD\n')
header = 'Date,Description,Amount,Status\n'
(books / 'seed.csv').write_text(header + '2024-01-02,Seed,-1.00,Posted\n')
(books / 'pending.csv').write_text(
    header + 'Pending,Card hold,Not settled,Pending\n')
(books / 'posted.csv').write_text(
    header + '2024-01-03,New shop,-12.50,Posted\n')
```

From `/abs/books`, seed the correct mapping with a preview, try a pending
export with a misspelled account, and then correct it:

```sh
bea --json --no-input -f /abs/books/main.bean import seed.csv --csv date=Date,narration=Description,amount=Amount,status=Status,currency=USD --account Assets:Cash --default-account Expenses:Food
bea --json --no-input -f /abs/books/main.bean import pending.csv --csv date=Date,narration=Description,amount=Amount,status=Status,currency=USD --account Assets:Cahs --default-account Expenses:Food
bea --json --no-input -f /abs/books/main.bean import posted.csv
bea --json --no-input -f /abs/books/main.bean import posted.csv --apply
bea --json --no-input -f /abs/books/main.bean import posted.csv --csv date=Date,narration=Description,amount=Amount,status=Status,currency=USD --account Assets:Cash --default-account Expenses:Food
bea --json --no-input -f /abs/books/main.bean import posted.csv
bea --json -f /abs/books/main.bean check
```

Exits: **0, 0, 2, 2, 0, 2, 0**. The pending preview has `rows: []`,
`skipped_pending: 1`, `unopened_accounts: []` and no `Not remembering`
notice. It saves `Assets:Cahs` beside the correct `Assets:Cash` record.
Both flag-free attempts refuse: `This CSV header matches multiple source
accounts: Assets:Cahs, Assets:Cash`. The explicitly corrected preview is
ready, but does not remove the stale choice. The refusal names the memory
record to forget, as designed for older bad records. Every ledger/CSV byte
is unchanged; the defect is the newly persisted configuration.

Expected: [IMPORTING.md](../../cli/docs/IMPORTING.md#categorization-rules---rules)
says a run whose source or explicit default account the ledger never opened
is not remembered, so a typo never becomes a second source for the header.
The pending preview should name the unopened setting, preserve the valid
previous memory and still leave the pending row out. Subsequent flag-free
preview/apply should use Cash/Food, book one 12.50 charge, and repeat with no
new write. The absence of transactions does not validate an account name.

Default-account variant: in **only the second command**, use
`--account Assets:Cash --default-account Expenses:Fodo`. It exits 0 and
overwrites the good default. The third command exits 0 with one **blocked**
row naming `Expenses:Fodo`; the fourth exits **4**, writing nothing.
The explicit correction restores Food and the sixth preview is ready.
The same bad default is saved when the first CSV contains an ordinary
`Known shop` posted row and `--rules rules.toml` maps it to opened Food:

```toml
[[rule]]
match = "known shop"
account = "Expenses:Food"
```

That preview is ready, but the unused misspelled default is remembered and
blocks the next unmatched shop. Thus checking only nonempty imports would
leave a second trigger unfixed.

Reproduced twice across **22 fresh books**: source typos with pending-only,
declined-only, header-only and mapped-blank files; default typos with pending,
header-only, blank and fully rule-matched files; and three working controls.
The controls put the typo on a posted row, or use valid pending settings:
the active-typo guard correctly prints `Not remembering`, preserves prior
memory and allows flag-free recovery. Four more fresh controls confirm
first-use `auto_accounts` sources can still be remembered/applied and an
omitted default stays dynamic while explicit rules categorize every row.
All checks pass; previews preserve ledger contents.

Cause: `cli/src/bea_engine/importing.py:845–853` computes
`unopened_accounts` exclusively from posting accounts in extracted `entries`.
Skipped/empty inputs have none, and a rule-matched row never posts to the
unused default. `cli/src/cli/commands/import_.py:1547–1570` checks candidate
source/default names only against that set, then calls `_remember_csv`.
The sole successful import path owns this guard. `_remember_csv` merges
source-account records; `_recall_csv` correctly refuses an ambiguous header.
Those downstream behaviors expose the earlier missing validation.

Fix: check explicitly resolved source/default settings against the effective
opened accounts after candidate evaluation, even when no extracted row uses
them. Keep a not-remembering notice and prior valid memory when a setting is
unopened. Preserve successful valid empty previews, projected plugin-created
opens, importer-provided opens, NFC handling from 714, omitted dynamic
defaults, genuinely distinct open source accounts and rejected-apply memory
preservation. Do not invent an opening or store the typo to avoid a warning.
This is CLI import memory only; no dependency or external API change.

Dedupe: all-state searches for pending/empty imports, unused defaults,
unopened accounts and remembered typos found completed 452 (`66f9dac2f`),
whose fix introduced this row-derived set, and 714 (`dae66730e`), which
normalizes its comparison. Targeted history finds no later account-guard
repair. 385 is blank date-format memory; 820 handles corrupt records. No
overlapping open repair or active milestone scope found.

Acceptance: all sixteen bad-setting cases retain prior good memory and
name the unopened setting; future flag-free rows import correctly. Keep
the six ordinary controls, four first-use/dynamic-default controls, and
human/JSON feedback. Existing historical-record forget behavior may remain.
Evidence: ignored QA pass19 `probe_unused_account_memory_guard.py`,

`unused-account-memory-positive-controls.json`, and per-command captures.
Windows/Linux and repaired behavior are unverified. Public repro is complete.

**Resolved 2026-10-22** — fixed: import's `unopened_accounts` (`cli/src/bea_engine/importing.py`) now also lists the accounts the run names itself — `--account` and an explicit `--default-account` — when the ledger does not open them, whether or not any extracted row posts to them (skipped as pending or blank, header-only, or a default every rule overrides). The frontend's existing guard then prints `Not remembering these settings`, keeps the previous valid memory, and a flag-free import still uses Cash/Food; valid settings on a pending-only export are still remembered, an omitted default stays dynamic, and a ledger with `auto_accounts` (which opens accounts on first use) still remembers a first-use source. Four `TestStickyRecall` fixtures in `cli/tests/test_import.py` had remembered an unopened `Expenses:Misc` default, the behaviour fixed here, so they now use an opened account. Regression tests in `cli/tests/test_import_remember_unused_unopened.py` fail without the fix. Shipped in this commit (`cli`).

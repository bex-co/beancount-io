# Keep calculated allocation fractions out of a cents ledger's report display precision

**Minor · cli · 30–45m · A1.** A plugin allocating a 10.00 USD expense over
three months makes human reports print 27 decimal places for every USD amount,
including zeros and the unchanged opening equity. The source writes only
cents. Exact JSON values are correct and must stay exact; the failure is
choosing human display precision from transformed postings. No fix implemented.

Real CLI QA, 2026-10-21, HEAD `ef5804b16` (initial reproduction on
`eaddf3f25`, CLI unchanged), checkout `bea 0.3.1`, macOS 26.5.1 arm64,
frontend Python 3.13.3, existing managed Python 3.12.10. Fresh subprocesses,
closed stdin/no TTY, isolated absolute config/cache, notifier disabled,
no inherited `BEA_FILE`/`BEA_TOKEN`. Controlled local plugin and synthetic files
only; no optional dependency is needed.

Create `/abs/books/allocations.py`:

```python
from beancount.core.data import Transaction
from datetime import date
from decimal import Decimal

__plugins__ = ("allocate",)

def allocate(entries, options):
    output = []
    for entry in entries:
        if not isinstance(entry, Transaction) or entry.narration != "Quarterly insurance":
            output.append(entry)
            continue
        for month in (1, 2, 3):
            postings = [p._replace(units=p.units._replace(number=p.units.number / Decimal(3))) for p in entry.postings]
            output.append(entry._replace(date=date(2024, month, 15), postings=postings))
    return output, []
```

All exit **0** with empty stderr. The income statement shows
`3.333333333333333333333333333 USD` for Insurance and
`Net Profit: -3.333333333333333333333333333 USD`. Its quiet income column
prints `0.000000000000000000000000000 USD`. Other reports and filtered
balance print Cash as `96.666666666666666666666666670 USD`; the balance
sheet pads untouched equity to `-100.000000000000000000000000000 USD`.
The source ledger and plugin remain byte-for-byte unchanged. Reproduced twice
from pristine fixtures across all four report kinds, plus filtered balance.

Expected: the documented finest **written** money precision is two places
here, so human Insurance/profit read `3.33 USD` / `-3.33 USD` and Cash reads
`96.67 USD`. Continue returning the full Decimal strings in JSON. Allocation
is allowed to retain its exact calculated quantities; fixing text precision
must not quantize ledger data or rewrite the plugin's results.

Controls, repeated twice: remove the plugin and the source's 10.00 USD expense
prints in cents. Keep the plugin but set `option "display_precision"
"USD:0.01"`: every human report and filtered balance uses cents, while JSON
still returns `net_profit.USD = "-3.333333333333333333333333333"`.
A genuinely authored 27-place expense must retain its written precision.

Cause: `_display_precision` (`cli/src/bea_engine/report.py:1029–1037`)
iterates `filtered.ledger.all_entries` after plugins. A posting without
booking's internal `__automatic__` metadata is treated as written evidence,
so each calculated one-third amount teaches USD 27 places. Allocation plugins
need not label their postings as booking interpolation. The already-written
100.00/10.00 figures do not cap it because `learn` takes the maximum.
The source-aware precision path below it only handles `__automatic__` legs.

Fix the distinction between authored and transformed precision evidence in
this shared helper: retain source money precision when plugins replace or
synthesize posting amounts, using source declarations rather than assuming
every loaded posting was typed. Preserve genuine written fractional amounts,
the existing inferred-only-currency fallback, explicit overrides and exact
JSON. Reuse existing source parsing/cache support where practical; do not
hard-code USD/cents or globally lower Decimal arithmetic precision.

Callers: overview, income statement, balance sheet, trial balance and `balance`
all return this helper's display map. The frontend report renderer consumes
it for human rounding and removes it from JSON. All five surfaces reproduce;
source bytes and numerical JSON are controls, not affected data.

Dedupe: whole-board searches including done/blocked and all open milestones
found no open allocation/plugin precision item. Completed w1/052 excludes
quote/cost digits; w5/093 excludes fractional booking interpolation once money
is written with decimals; w5/668 (`85de3ff1c`) bounds interpolation division
noise by source totals. Their source-aware branch tests `__automatic__`, so
it never reaches these plugin-generated amounts. w3/304 is the fallback for
an unknown conversion currency. No later targeted history fixes this path.

Acceptance: all seven commands remain successful; human allocation totals
use the source's cents and JSON keeps the exact fractional strings. Cover
both a plugin rewrite at the original date and its other-month copies,
genuine written fine precision, explicit overrides and ordinary interpolation.

**Resolved 2026-10-22** — fixed: `_display_precision` (`cli/src/bea_engine/report.py`) now caps what a posting teaches by the fractional digits its source transaction actually spells in that currency (`_typed_precision`, read from the cached plugin-free parse), so a plugin's divided or rewritten posting left at its source line no longer sets human display precision; postings with no readable source line (plugin-made entries), currencies the source spells no amount in, genuinely written fine amounts, ordinary interpolation and `option "display_precision"` behave as before, and JSON keeps the exact Decimal strings. The income statement, balance sheet, trial balance and overview of the public allocation fixture now print cents. Regression tests in `cli/tests/test_report_allocation_display_precision.py` fail without the fix. Shipped in this commit (`cli`).

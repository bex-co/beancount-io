# Preserve valid trailing Unicode spaces in read account filters

**Minor · cli · 30–45m · A1.** A read filter removes a valid trailing
Unicode space from an existing account name. Reports then select a different
account; transaction/open lists and the `balance` alias include both accounts.
The source ledger and unfiltered totals remain correct. Regression from
completed [626](./done/626.md), whose ASCII-padding fix strips every Unicode
whitespace character. No product fix implemented.

Real CLI QA, 2026-10-21, HEAD `779839d76` (CLI unchanged from `f62c8d1e9`),
checkout `bea 0.3.1`, macOS 26.5.1 arm64, frontend Python 3.13.3, managed
Python 3.12.10 / Beancount 3.2.3. Fresh bounded subprocesses, closed stdin/no
TTY, isolated absolute `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled,
inherited `BEA_FILE`/`BEA_TOKEN` removed. Local synthetic data only.

Create an existing native ledger with this Python snippet. The escape makes
the final **U+00A0 NO-BREAK SPACE** in the second account unambiguous:

```python
from pathlib import Path
books = Path("/abs/books")
books.mkdir(parents=True, exist_ok=True)
target = "Assets:Cash\u00a0"
(books / "main.bean").write_text(f'''option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open {target} USD
2024-01-01 open Equity:Opening USD
2024-01-01 * "Bare account"
  Assets:Cash 100.00 USD
  Equity:Opening -100.00 USD
2024-01-02 * "Target account"
  {target} 200.00 USD
  Equity:Opening -200.00 USD
''', encoding="utf-8")
```

The account values in quotes below retain that character immediately after
`Cash`. Run from `/abs/books`:

```sh
bea --json -f /abs/books/main.bean check
bea --json -f /abs/books/main.bean query 'SELECT sum(number) WHERE account="Assets:Cash "'
bea --json -f /abs/books/main.bean report overview --time 2024 --conversion USD
bea --json -f /abs/books/main.bean list transaction --account 'Assets:Cash ' --limit 100
bea --json -f /abs/books/main.bean list open --account 'Assets:Cash ' --limit 100
bea --json -f /abs/books/main.bean report overview --time 2024 --conversion USD --account 'Assets:Cash '
bea --json -f /abs/books/main.bean report balance-sheet --time 2024 --conversion USD --account 'Assets:Cash '
bea --json -f /abs/books/main.bean report trial-balance --time 2024 --conversion USD --account 'Assets:Cash '
bea --json -f /abs/books/main.bean balance 'Assets:Cash ' --time 2024 --conversion USD
bea --json -f /abs/books/main.bean report overview --time 2024 --conversion USD --account '^Assets:Cash $'
```

Every command exits **0**. Check is valid; native BQL returns **200 USD** for
the exact target, and unfiltered net worth is **300 USD**. The filtered
transaction and open lists wrongly return **two** records. The overview
instead reports **100 USD**, and balance-sheet/trial-balance show the bare
`Assets:Cash` account's **100 USD**. Their metadata says
`account_filter: "Assets:Cash"`: the requested character has vanished.
The `balance` alias's substring matcher includes both accounts, totalling
**300 USD**. The anchored regex control retains the character and correctly
reports **200 USD**. All commands preserve source bytes.

account name. The exact target's report and alias balance are 200 USD,
and its list filter returns one matching transaction/open. The documented
substring semantics for list/balance and literal account/subtree semantics

Reproduced twice for trailing U+00A0, U+3000 IDEOGRAPHIC SPACE and U+202F

The P&L case is affected too: two `Income:Sales` accounts, one with the final
character and credits of 100/200 USD, produce filtered income-statement and
balance-sheet **net profit 100 instead of 200 USD**; trial balance selects
−100 and `balance` totals −300 instead of −200. An anchored pattern returns

Cause: `cli/src/cli/utils.py:119–136`, `account_filter`, calls unrestricted
`value.strip()` at :130. It is used by `commands/list.py:_run` (:328) and
`commands/report.py:_ask` (:196). `report.py:205` independently strips every
positional `balance` term. Thus the meaningful suffix is removed before
the engine sees it. Native account fields remain intact in JSON; this is
input normalization. `fold_account`, the reader's matching helpers and
`bea_engine/report.py:_substring_match` preserve the characters. Fava's
`account_predicate` already supports loader-valid account spellings.

Keep NFC/case folding and existing matching semantics. The existing policy

**Resolved 2026-10-22** — fixed: read account filters (`account_filter` and the positional `balance` terms in `cli/src/cli/commands/report.py`) now remove only the ASCII whitespace a shell or paste adds around a value (`strip_padding` in `cli/src/cli/utils.py`) instead of every Unicode whitespace character, so a trailing NBSP, U+3000 or U+202F that belongs to an account name is kept: `list transaction/open --account`, the reports and the `balance` alias select that exact account (200 USD, not the bare sibling's 100) and report it in `account_filter`. ASCII padding is still stripped, blank and whitespace-only values are still refused (exit 2), the `=` hint and the refusal of Unicode spaces in new writes are unchanged. Regression tests in `cli/tests/test_account_filter_unicode_space.py` fail without the fix. Shipped in this commit (`cli`).

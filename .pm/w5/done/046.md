## Cause

- `backend-cluster/backend-v2/src/features/ai-agent/tools/read-ledger-files-tool.ts`

`startLine`/`endLine` are `z.number().int()` with no ordering or bounds check (:45-46); slicing silently yields empty.

Owning package `backend-cluster/backend-v2`; the fix must land on every eligible surface (MCP) in the same change. BAD_USER_INPUT unless 1 <= start <= end <= totalLines.

---

**Resolved 2026-10-03** — `readLedgerFiles` now refuses a reversed range (`start_line` after `end_line`) as `BAD_USER_INPUT` before reading anything, and refuses a `start_line` past the last line, naming the file's length. Shipped in `6074d8e4` (`backend-cluster/backend-v2`).

One part of the proposed rule was deliberately not adopted: an `end_line` past the end of the file is still clamped rather than refused. Asking for "lines 1 to 500" of a file whose length the caller cannot know in advance is an ordinary request, and the response already reports the real `endLine` and `totalLines`. Tests cover the reversed range, the start past the end and the clamped end; the two refusals fail with the fix reverted. MCP only, as the note says. Not re-run against the hosted endpoint: the fix reaches it with the next deploy.

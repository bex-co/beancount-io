# Treat a budget-only account match as nonempty in the budget report

**Minor · cli · 25–40m · A1/A2 · worker1.** A valid filtered budget report
returns its 100 USD budget row, but also claims `account_filter_empty: true`
and warns `No accounts match Expenses:Travel.` Text and CSV show the
matching row beside that false warning. An agent inspecting the empty flag
can discard a valid budget with no spending. No product fix implemented.

Environment: 2026-11-08, main `0a86f3890`, checkout bea 0.3.1, Python
3.12.10, macOS 26.5.1 arm64; CLI sources unchanged from `74a0b8cbe`, using
the existing managed interpreter and checkout helper. Fresh subprocesses,
25s timeouts, closed stdin/no TTY, offline, absolute file, isolated child
config/cache, notifier off, no inherited `BEA_FILE`/`BEA_TOKEN`; HOME unchanged.

## Reproduce

Create this synthetic `main.bean` in a new disposable directory:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Cash USD
2026-01-01 custom "budget" Expenses:Travel "monthly" 100.00 USD
2026-01-31 note Assets:Cash "End"
```

With the isolated environment above and absolute executable/file paths:

```sh
bea --json --no-input --offline --file /absolute/main.bean check
bea --json --no-input --offline --file /absolute/main.bean report budget --time 2026-01
bea --json --no-input --offline --file /absolute/main.bean report budget --time 2026-01 --account Expenses:Travel
bea --no-input --offline --file /absolute/main.bean report budget --time 2026-01 --account Expenses:Travel
bea --no-input --offline --file /absolute/main.bean report budget --time 2026-01 --account Expenses:Travel --format csv
bea --json --no-input --offline --file /absolute/main.bean report trial-balance --time 2026-01 --account Expenses:Travel
```

All exit 0 and preserve the source hashes. Check is valid: a budget custom
directive need not open its account or post money. Both budget JSON calls
return the same row: account Expenses:Travel, budget 100.00 USD, actual 0,
variance -100.00, status budgeted, no budget/ledger errors. The unfiltered
call has `account_filter_empty: false`; adding the exact matching filter
changes it to **true**. Text and CSV still print that row but stderr says
`No accounts match Expenses:Travel.` Repeated in another pristine fixture.

Expected: the filtered budget report has `account_filter_empty: false`
and no no-match warning when its account has a reported budget. Zero actual
is a valid budget result, not an empty filter. The trial-balance control
correctly remains empty: a declaration without postings makes no balance
tree. Preserve that distinction and genuinely unmatched budget filters.

## Cause and repair

`cli/src/bea_engine/report.py::_metadata:1748–1750` considers any filtered
entry set containing only `Custom` directives empty. This predicate was
added for balance-tree reports in completed [504](504.md), when
custom declarations could not produce a financial row. New `_budget` calls
the same `_metadata` (:453) after building actual budget rows, without
adapting that predicate. `commands/report.py::_heading:265–268` turns the
flag into the warning; `_emit_csv` also calls that heading, and JSON emits
the flag unchanged. These are three consumers of one metadata error.

Make budget report emptiness reflect reportable matching budget/actual rows.
Keep the existing balance-report treatment of custom-only account filters,
and do not suppress genuine empty-filter warnings globally. Retain budget
validation, no-spending rows, date/currency scope and normal account filters.
No dependency, server/API or other package change is involved.

Acceptance: the public fixture keeps its 100 USD / zero-actual row, returns
false for the empty flag and emits no no-match warning in JSON/text/CSV.
An unmatched budget filter still reports empty; the same account in the
trial-balance control keeps its existing truthful empty state. Add meaningful
CLI regression coverage and run `make check-all` inside `cli/`.

Dedupe: searched all board states for budget empty filters, `account_filter_empty`
and no-match diagnostics; checked current milestone scopes and source history.
`03683c3f9` implemented [504](504.md)'s correct behavior for existing
balance reports; new budget consumer `a501d9341`
([w21/m7](../../w21/done/m7/README.md)) did not adapt it. Keep both completed
items closed. [1121](1121.md) loses actual rows through ancestry coverage;
this fixture has no postings or child budget and keeps its row, so the
metadata cause is independent. No overlapping open repair found.

Sanitized evidence under `.tmp/qa-2026-11-07/cli-loop-97398758/`:
`calls.jsonl`, `budget-empty-filter-summary.jsonl` and two pristine fixtures.
Public recipe above is self-contained. Only ignored synthetic resources
remain; no credentials, hosted resources, or persistent processes. Other
OSes and PTY interaction unverified.

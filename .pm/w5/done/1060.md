# Resolve literal stored-query names before trimming terminators

**Minor · cli · 25–40m · A1 · worker1.** A saved query whose name ends in a
semicolon is listed correctly, but running that listed name removes its final
semicolon before lookup. If the shorter name also exists, bea executes that
other query and exits0; an export is replaced with its result. With no shorter
query, the listed name is refused at exit2. Quoting the full name works.
The ledger remains byte-identical. No product fix implemented.

All exit0. Listing includes both `Cash report` and `Cash report;`.
The unquoted listed-name command returns `n` / `1`; the quoted command returns
`amount` / `100`. Native uncached Beancount validates both directives and
direct Beanquery execution of their respective stored bodies gives exactly
those independent results. Expected: a name copied exactly from `.run` selects
that query, as the237 fix and `_run_stored`'s own contract state. The final
semicolon is part of this valid stored name. It must not silently select the
shorter one.

The same wrong selection occurs in file JSON (`data.text`), native
`query --source BOOK`, and CSV `--output report.csv` on both paths. The two
export routes replace a prepared previous report with the shorter query's
`n,1` result under success; no ledger bytes change. If only `Cash report;`
exists, its listed form instead exits2 with `too many arguments for "run"
command`, empty stdout and a preserved previous export. The quoted form still
returns100. This is one name-resolution cause, not a separate refusal finding.

Controls: an interior semicolon (`Cash; report`), an ordinary name, each quoted
form, and a terminator after an ordinary existing name (`.run Plain report;`)
all return100. Both root spellings and USD/EUR reproduce; no account valuation
or query-body arithmetic is involved.

## Cause and bounded fix

`cli/src/bea_engine/query.py:913`, `_run_stored`, applies
`arg.rstrip("; \t")` before the exact-name lookup at951–952. It turns
`Cash report;` into `Cash report`, so a valid lookup of the wrong stored
directive succeeds. If that shorter directive is absent, fallback shlex
parsing at953–967 treats the two remaining words as extra arguments. Quoting
works because the closing quote prevents rstrip from reaching the semicolon;
shlex then recovers the full intended name.

Resolve a literal stored name before removing an optional command terminator;
only fall back to the existing terminator/quoted-name parsing when there is no
exact name. Keep ordinary `Plain report;` compatibility and current missing,
empty-body/window, listing and wildcard policies. Change the shared helper,
without rewriting BQL parsing, query bodies or native execution. Add focused
real-command regression coverage for a collision and a suffix-only name on
both adapters, JSON and exports, then run owning CLI checks when implementing.

Caller search finds exactly two runtime calls: native-source `do_run` at644
and local `do_run` at1468. These feed one-shot output, the JSON text envelope,
exports and their respective interactive shells. The one-shot paths above
are exercised; interactive impact is inferred from the shared helper and was
not run, so personal query history was not touched. No other shell aliases or
source kinds are claimed reproduced.

Installed Beanquery0.2.0 `shell.py:431–459` also strips optional terminators,
but uses shlex word parsing and does not offer bea237's unquoted spaced-name
lookup. This finding targets the bea-owned literal-name promise and wrong
selection introduced by combining that lookup with earlier cleanup. Retain
the upstream evaluator and renderer. ADR014 permits the existing query wrapper;
no dependency, backend or API change is needed.

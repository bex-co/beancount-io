# Honor declared cash membership outside the Assets root

**Major · cli · 25–40m · A1 · worker1.** Cash Flow accepts a valid
`cash-flow-role: "cash"` declaration on `Liabilities:Overdraft`, but omits
that account from cash and equivalents. A native **−250 USD** balance
vanishes from the membership set: closing cash is **1100 instead of850USD**.
The whole-ledger report invents **250USD opening cash instead of0**; a
bounded window shows **1050 instead of800USD opening cash**. JSON and human
output both succeed with valid/complete metadata and no invalid-role
warning. The source and ordinary account balances remain correct. No
product fix implemented.

This is a role-precedence failure, not a request for automatic accounting
classification: the fixture explicitly declares which account is cash.
[ADR003](../../docs/adrs/ADR003-dashboard-cash-flow-ledger-roles.md) and its
[normative appendix](../../dashboard/docs/PRFAQ-cash-flow-ledger-classification.md)
define `cash` as CCE membership and trust declarations over root/name
conventions. [ADR024](../../docs/adrs/ADR024-cli-cash-flow-report.md) adopts
that precedence for the CLI. Neither contract limits an explicit valid
cash declaration to Assets. Preserve the Assets-only name heuristic for
accounts without an applicable declaration.

## Root and bounded repair

`cli/src/bea_engine/report.py::_cash_accounts:901–902` skips every account
whose mapped root is not Assets **before resolving its declared role**.
The resolver at`:874–889` would accept `cash` with source`declared`, but it
is never consulted for membership on this account. Later the activity loop
at`:996–998` does resolve the same declaration, sees `cash`, and omits the
account from noncash rows. It therefore belongs to neither side: no CCE
balance and no activity row. Closing sums only members, and`:1011–1015`
derives a false opening from that incomplete closing.

Honor valid explicit cash membership before applying root/name restrictions
to heuristic membership. Preserve the exact declared/heuristic distinction,
noncash activity overrides, invalid-value fallback/flagging and existing
Assets subtree behavior. Do not reinterpret unannotated liabilities as cash,
change all account roots, weaken diagnostics, or repair this by adding a
balancing activity row for an account explicitly declared cash. Keep the
known-root and unrooted-account policy. Non-Assets ancestor inheritance and
other non-Assets roots were not newly exercised here.

Caller search finds `_cash_accounts` only in `_cash_flow:946`, itself
called from `report.answer:137`. Frontend
`cli/src/cli/commands/report.py::cash_flow:611–665` emits the same producer's
JSON and bottom-line text; it cannot recover an omitted member.
No dependency, schema or backend change is needed for this local CLI repair.
The dashboard supplied the normative policy documents; its runtime was not
exercised, and no dashboard defect or fix is claimed.

# Account names on Overview, Accounts and Holdings, and the Files breadcrumb, are buttons: ⌘/Ctrl-click replaces the page instead of opening a new tab, and middle-click does nothing

**Severity:** minor (nothing is lost, but a reader who opens several accounts or folders side by side loses the page they meant to keep, and there is no "Open in new tab" or "Copy link" for these destinations). **Owner:** dashboard. **Estimate:** 45–60 minutes including tests. **A2:** a newcomer exploring a first ledger opens accounts from the chart of accounts and the Overview cards. On the reports, the same account names are links. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-21 against `https://beancount.io` (dashboard entry chunk `main-CIyNN76T.js`), QA-owned headless Chromium on macOS at 1440×1000 and 390×844, English/light, no filters, signed in as the QA owner on its synthetic ledger. Read-only. Local HEAD `c5568ff2d`.

## Repro

On any ledger with a few accounts (the QA account's synthetic ledger was used; the public `open_ledger/alphabet` was used for Files):

1. Open `/ledger/<owner>/<ledger>/accounts`. ⌘-click (Ctrl-click on Windows/Linux) the account "Assets:Bank:Checking". No tab opens and the current tab goes to `/account/Assets%3ABank%3AChecking`. Middle-click does nothing. The parent segment "Assets:Bank:" behaves the same and goes to `/account/Assets%3ABank`. The page has 0 links to `/account/` and one button per name segment, at 1440px and at 390px.
2. Open the Overview. ⌘-click an Account balances row ("Assets:Bank:Savings 10,500.00 USD 69.1%"), or a Money movement row ("Expenses:Housing:Rent"). The current tab goes to that account page (`?time=2026-07` for Money movement). Middle-click does nothing. The Overview has 7 account buttons and 0 account links.
3. Open Holdings. Middle-click the account cell "Assets:Bank:Savings": nothing happens. ⌘-click replaces the page with the account page.
4. Open `/ledger/open_ledger/alphabet/files/blob/main/FY2024/FY2024.bean`. ⌘-click the breadcrumb "FY2024" (or "Files"): the current tab goes to the folder.
5. Controls on the same build: ⌘-click or middle-click "Checking" on the Balance Sheet opens `/account/Assets%3ABank%3AChecking` in a new tab and leaves the Balance Sheet in place. The same holds for Income Statement, Trial Balance, Cash Flow and Statistics (12–22 account links each), the Journal postings, and the folder and file rows of the Files list.

Repeated from fresh loads.

## Cause

Each of these destinations is a `<button>` whose `onClick` calls `navigate()`, so it has no `href`, and the browser cannot open it in a new tab:

- Overview: `dashboard/src/features/reports/overview/components/account-balances-card.tsx:186-198` and `money-movement-section.tsx:178-186`, both through `useLedgerNavigateToAccount` (`common/providers/ledger-provider/use-ledger-navigate-to-account.ts`).
- Accounts: `features/ledger-data/accounts/account-prefix-navigation.tsx:48-76` (one button per segment) and the row-level `getClickableRowProps(() => onAccountClick(…))` at `features/ledger-data/accounts/index.tsx:381-382`, with `handleAccountClick` at `:585-590`.
- Holdings: `features/ledger-data/holdings/holdings-table.tsx:228-246`, plus the row handler at `:181`. w3/m25 t002 asked for "a real link inside its account cell", but a button shipped.
- Files breadcrumb: `features/ledger-editor/shared/components/ledger-file-breadcrumb.tsx:44,56,77,89` through `useFileNavigate`.
- Documents filename: `features/ledger-data/documents/index.tsx:46`, the same pattern. This one is from source only, because no reachable ledger has documents.

A ⌘/Ctrl-click still fires `click` on a button, so the handler navigates the current tab. A middle-click fires only `auxclick`, which nothing handles. The reports use TanStack `<Link>` for the same route (`features/reports/balance-sheet/hierarchy-list.tsx:262-271`), and the browser handles those clicks itself. This is not deployment lag: none of these files has changed since the deployed build.

## Fix

Owned by `dashboard`. Render each of these destinations as a TanStack `<Link>` to the same route, keeping today's styling, focus, hover and `stopPropagation`. A plain click then works as it does now, and ⌘/Ctrl/Shift-click, middle-click and the context menu work as they do for links. Keep each control's search behaviour: Money movement keeps its `time` override, and the others keep the shared `account`/`filter`/`time` that `retainSearchParams` carries. The row-level pointer handlers on Accounts, Holdings and Documents (`clickable-row.ts`) stay as a convenience for plain clicks, but must ignore a click with a modifier key or a non-primary button, so that a ⌘-click on a row's empty space does not replace the page. Leave Entry Context's source location as a button: it asks before discarding a draft (`confirmLeave`).

A plain click and Enter still go to the same URL as today, search params included.

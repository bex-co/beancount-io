## Objective

Loading states stop lying: the sidebar skeleton renders a plausible number of rows instead of a hardcoded 10, and BlogFeed uses the shared `Skeleton` component instead of hand-rolled gray divs.

## Context

- `dashboard-sidebar.tsx` (~line 156): `SidebarLedgerSkeleton` renders a fixed 10 `SidebarMenuSkeleton` rows — jarring for users with 1–2 ledgers.
- `components/blog-feed.tsx`: three hand-rolled `animate-pulse` divs; no `aria-busy`/`aria-hidden`.
- Shared `Skeleton` lives in `src/common/components/ui/skeleton.tsx` and is used elsewhere in the app.

## Steps

1. Size the sidebar skeleton from the cached ledger count when available (Apollo cache / previous data via `cache-and-network`), with a small default (e.g. 3) otherwise.
2. Replace BlogFeed's hand-rolled skeleton cards with `Skeleton`-based ones matching `FeedCard` layout.
3. Add `aria-busy` on loading containers and `aria-hidden` on decorative skeletons.

## Files

- `dashboard/src/features/ledger-list/pages/dashboard-page/components/dashboard-sidebar.tsx`
- `dashboard/src/features/ledger-list/components/blog-feed.tsx`

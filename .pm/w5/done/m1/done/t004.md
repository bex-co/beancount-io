## Objective

After creating a ledger from the sidebar dialog, navigate the user into the new ledger (matching the welcome page's behavior) instead of leaving them on `/ledger` watching a list row appear.

## Context

- `dashboard-sidebar.tsx` create dialog: on success it shows a toast and closes; no navigation. `pages/welcome-page/index.tsx` already navigates into the ledger after creation — copy that pattern.
- Ledger routes are `/ledger/$ledgerOwner/$ledgerName/...`; the overview or index route is the natural landing.
- The edit dialog's rename-redirect logic (~lines 434–453, checks `window.location.pathname`) shows the existing navigation idiom in this file.

## Steps

1. On create success in the sidebar dialog, navigate to the new ledger's landing route using TanStack Router `navigate` (not `window.location`).
2. Keep the success toast.
3. Verify the sidebar list refreshes (existing cache-evict logic) and the new ledger is selected in the switcher on arrival.

- `dashboard/src/features/ledger-list/pages/dashboard-page/components/dashboard-sidebar.tsx`

## Acceptance criteria

- [ ] Creating from the sidebar lands inside the new ledger.
- [ ] No full-page reload; router navigation only.
- [ ] Create from the ledger switcher gets the same treatment if it shares the handler.

## Out of scope

- Changing which ledger sub-page is the landing route.

## Fix (parity: MCP+REST+GraphQL)

Owning package `backend-cluster/backend-v2`; the fix must land on every eligible surface (MCP+REST+GraphQL) in the same change. Validate the directive date -> BAD_USER_INPUT.

## Evidence

`.tmp/qa-2026-10-03-auth/r2-writes-envelope/32-append-baddate-dryrun.txt` (gitignored bundle `.tmp/qa-2026-10-03-auth/`); finding brief `.tmp/qa-2026-10-03-auth/final/writes-append-baddate-internal.md`.

---

**Resolved 2026-10-03** — a directive date that is not on the calendar is now refused as `BAD_USER_INPUT` naming the value, before any routing or ledger read, on REST, GraphQL and MCP. The check covers both write paths — directive text and structured entries — and applies whether or not the ledger routes entries by date, so the same typo no longer gets a different answer depending on the ledger's options. A day the month does not have (`2026-02-30`) is refused rather than rolled into the next month. Shipped in `3162f700` (`backend-cluster/backend-v2`).

Regression tests append `2026-13-45` as a dry run through HTTP REST, GraphQL execution and an MCP client, with and without date routing, and assert the category, the named value and that nothing is projected or written; the structured path is covered at the service. All fail with the fix reverted. Not re-run against the hosted endpoint: the fix reaches it with the next deploy.

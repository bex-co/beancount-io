# Preserve literal quotes in CSV column mappings

**Trivial · cli · 30–45m · A1.** A valid CSV header ending in a literal
`"` cannot be named with `--csv`: its raw spelling is treated as an unclosed
mapping quote, while CSV-style doubled quotes name a different column.
Renaming only that header lets the identical row import and deduplicate.
A Python importer or renaming the header is a workaround. No product fix
implemented; no data loss observed.

Environment: 2026-10-22 QA, clean main `328dd89c7` (initial reproduction on
`b5460e8f7`; implicated sources unchanged), checkout `bea 0.3.1`, frontend
Python 3.13.3, managed Python 3.12.10 / Beancount 3.2.3 / Beanquery 0.2.0,
macOS 26.5.1 arm64. Fresh real CLI subprocesses, argument arrays, closed
stdin/no TTY, isolated absolute `BEA_CONFIG_DIR` and `XDG_CACHE_HOME`,
`BEA_NO_UPDATE_NOTIFIER=1`, inherited `BEA_FILE`/`BEA_TOKEN` removed.

Create a fresh disposable fixture (the bank header is exactly `Memo "`):

```python
import csv
from pathlib import Path
books = Path('/abs/books')
books.mkdir(parents=True, exist_ok=True)
(books / 'main.bean').write_text('''option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Food USD
''')
for name, header in [('bank.csv', 'Memo "'), ('renamed.csv', 'Memo')]:
    with (books / name).open('w', newline='') as output:
        writer = csv.writer(output)
        writer.writerow(['Date', header, 'Amount'])
        writer.writerow(['2024-01-02', 'Lunch', '-4.50'])
```

Actual: the raw preview exits **2**, with JSON on stderr saying
`has an unclosed double quote`. The doubled-quote preview and apply both
exit **2**, saying `The mapping names column 'Memo ""' for narration, which
bank.csv lacks.` Human output agrees. All three leave the ledger unchanged.
The original CSV remains unchanged throughout. The renamed control previews
one row, applies **1**, and repeats without mapping flags with **0 written /
1 duplicate**; both checks exit 0. BQL gives Cash **-4.50 USD** / Food
**4.50 USD**. The two files have exactly identical data records, verified
with Python's independent CSV reader; the delimiter is explicitly comma.

Expected: provide and document a lossless spelling for literal quotes in a
column name. `docs/IMPORTING.md:76–77` accepts `field=Column` and documents
quoting comma-containing names without excluding literal quotes. This is a
mapping-language limitation, not malformed source CSV or shell quoting.
The precise escape convention may be chosen during implementation.

Reproduction and controls: twice from fresh fixtures, three problematic
headers (`Memo "`, literal `"Memo, details"`, and
`Memo "label, note", details`) each fail raw, doubled and backslash-escaped
previews, doubled apply and human preview. Renaming only the header then
passes preview/apply/remembered repeat/check/BQL. Plain `Memo`, comma-only
`Memo, details` and raw balanced `Memo "label"` each complete that same
journey without renaming. These are **12 books / 90 CLI calls**, following
16 initial preview probes. All original CSV bytes are preserved. The exact
published recipe above was also repeated twice from pristine fixtures.

Cause and callers:

- `cli/src/cli/csv_mapper.py:118–150` and its engine twin at
  `cli/src/bea_engine/csv_mapper.py:513–545`: `split_spec` toggles quote state
  for every `"`, without an escape rule. `spec_value` strips only the outer
  pair. Direct parser controls in both environments turn
  `narration="Memo """` into the nonexistent column `Memo ""`.
- Frontend `parse_mapping`, reading-key validation and skip parsing use this
  grammar (`:174`, `:256`, `:320`); the engine's `parse_mapping` uses its twin
  (`:564–566`). The frontend `_spec_column` at `:428` wraps commas without
  escaping literal quotes, feeding inferred/example specs (`:461`, `:472`).
- `cli/src/cli/commands/import_.py:318`, `:329`, `:1045` also split specs for
  key stripping, echoed arguments and remembered-setting overrides. Keep all
  readers/renderers consistent; these callers are regression scope rather
  than independent reproduced failures.

**Resolved 2026-10-23** — fixed: in both `--csv` mapping parsers (`cli/src/cli/csv_mapper.py` and `cli/src/bea_engine/csv_mapper.py`) two double quotes in a row inside a quoted stretch are now one literal quote, as in CSV, so `narration="Memo """"` names the column `Memo "`; `split_spec` keeps the pair together and `spec_value` unescapes it after taking the outer quotes off. The frontend's `_spec_column` renders a header holding a quote (or a comma) as a quoted, doubled spec that reads back to the same header, and `docs/IMPORTING.md` documents the spelling. Ordinary comma quoting, balanced inner quotes and the "unclosed double quote" refusal for a lone quote are unchanged. The `Memo "` header now previews, applies once and deduplicates on repeat. Regression tests in `cli/tests/test_csv_mapping_literal_quotes.py` fail without the fix. Full suite green apart from the known `test_release` smoke timeout, which passes alone. Shipped in this commit (`cli`).

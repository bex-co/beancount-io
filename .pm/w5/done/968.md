# Discover export helpers before plugin processing suppresses their import

**Minor · cli · 45–60m · A1.** A warm-cache portable export still omits a
required runtime helper when an idempotent plugin skips entries it already
processed. Export reports success; a fresh check of the snapshot fails with
`ModuleNotFoundError`. A cold export of the same unchanged ledger includes
the helper and passes. This is a follow-up to completed [880](./done/880.md),
whose new replay sees the transformed entries rather than the original input.
No product fix implemented; source ledger/module bytes remain unchanged.

Environment: 2026-10-22 QA, clean main `9e0fefa1b` (initial reproduction on
`6dc52f903`, implicated source unchanged), checkout `bea 0.3.1`, frontend
Python 3.13.3, managed Python 3.12.10 / Beancount 3.2.3 / Beanquery 0.2.0,
macOS 26.5.1 arm64. Fresh subprocesses, closed stdin/no TTY, isolated absolute
config/cache paths, notifier disabled and inherited file/token overrides
removed. Only inspected local plugins and synthetic files; no price feed or
optional feature needed.

Run this Python script with the checkout's `bea` on PATH, replacing
`/abs/case` with a fresh absolute disposable directory. The 1.1-second delay
makes the tiny fixture cross the normal load-cache threshold; it is fixture
instrumentation for a naturally slow plugin. The plugin adds metadata to
returned transaction copies and skips entries already carrying its marker.
The original source directory is hidden and restored in `finally` around
each fresh snapshot check, so the snapshot cannot borrow its helper.

```python
import json, os, subprocess
from pathlib import Path
case = Path('/abs/case')
books = case / 'books'
books.mkdir(parents=True)
(books / 'main.bean').write_text('''option "insert_pythonpath" "TRUE"
option "operating_currency" "USD"
plugin "qa_plugin"
2024-01-01 open Assets:Cash USD
2024-01-01 open Income:Services USD
2024-01-02 * "Invoice"
  Assets:Cash 100 USD
  Income:Services -100 USD
''')
(books / 'qa_bank_helper.py').write_text('LABEL = "Synthetic bank"\n')
(books / 'qa_plugin.py').write_text('''import time
from beancount.core.data import Transaction
__plugins__ = ['mark']
def mark(entries, options):
    if any(isinstance(e, Transaction) and e.meta.get('qa_done') for e in entries):
        return entries, []
    time.sleep(1.1)
    from qa_bank_helper import LABEL
    changed = []
    for entry in entries:
        if isinstance(entry, Transaction):
            meta = dict(entry.meta)
            meta['qa_done'] = True
            meta['bank_label'] = LABEL
            entry = entry._replace(meta=meta)
        changed.append(entry)
    return changed, []
''')
original = {p.name: p.read_bytes() for p in books.iterdir() if p.is_file()}
env = os.environ.copy()
for key in ('BEA_FILE', 'BEA_TOKEN', 'BEANCOUNT_LOAD_CACHE_FILENAME',
            'BEA_ENGINE_PYTHON', 'BEA_ENGINE_DIR'):
    env.pop(key, None)
env.update(BEA_CONFIG_DIR=str(case / 'config'),
           XDG_CACHE_HOME=str(case / 'cache-warm'), BEA_NO_UPDATE_NOTIFIER='1')
def run(tag, file, args, overrides=None):
    argv = ['bea', '--json', '--no-input', '-f', str(file), *map(str, args)]
    result = subprocess.run(argv, cwd=case, env=env | (overrides or {}),
                            stdin=subprocess.DEVNULL, capture_output=True,
                            text=True, timeout=25)
    print(json.dumps(dict(tag=tag, args=argv, exit=result.returncode,
                         stdout=result.stdout, stderr=result.stderr)), flush=True)
run('source-first', books / 'main.bean', ['check'])
run('source-cached', books / 'main.bean', ['check'])
run('source-cash', books / 'main.bean', ['query',
    "SELECT number,entry_meta('bank_label') AS label WHERE account='Assets:Cash'"])
for mode in ('warm', 'cold'):
    destination = case / mode
    overrides = {} if mode == 'warm' else {'XDG_CACHE_HOME': str(case / 'cache-cold')}
    run(mode + '-export', books / 'main.bean', ['price', 'export', '--output', destination], overrides)
    hidden = case / 'hidden-books'
    books.rename(hidden)
    try:
        run(mode + '-snapshot-check', destination / 'main.bean', ['check'],
            {'XDG_CACHE_HOME': str(case / ('snapshot-cache-' + mode))})
    finally:
        hidden.rename(books)
assert all((books / name).read_bytes() == content for name, content in original.items())
```

The seven CLI exits are **0, 0, 0, 0, 1, 0, 0**. Both source checks pass;
the source query returns **100 USD / Synthetic bank**. The warm export
returns success and copies `main.bean` plus `qa_plugin.py`, omitting
`qa_bank_helper.py`. Its snapshot check exits 1 with JSON stderr containing
`Plugin "qa_plugin" failed while running: ModuleNotFoundError: No module
named 'qa_bank_helper'.` The cold export copies all three files, and its
fresh snapshot check exits 0. Human export reports the same successful
incomplete warm snapshot. Original files are restored byte-for-byte.

Expected: dependency completeness must not depend on whether a source was
checked recently or whether its plugin avoids processing an entry twice.
`cli/docs/USAGE.md:1980–1986` promises a self-contained snapshot including
local modules/packages imported by the plugin. Carry the runtime helper,
or refuse the incomplete export before publishing success.

Reproduction and controls:

- Two pristine initial warm/cold journeys reproduce the missing-helper
  failure. First source checks take 1.52/1.65 seconds; cached checks take
  0.43/0.40 seconds; cold exports include the helper and load independently.
- Six further fresh cases, two each of the marked plugin, the same plugin
  with a module-scope helper import, and an unconditional runtime import:
  **42 CLI calls**. An inspected local `.calls` marker confirms exactly
  `raw` on the first load, no call on the cached check/query, and `processed`
  on the warm export's replay. Cold export adds `raw, processed`. The
  transformed label and 100 USD remain readable from cache. Only the marked
  runtime-import warm snapshot fails; both existing 327/880 controls pass
  warm and cold. An unrelated module is excluded in every export.
- The exact public script above was replayed twice, also with the
  unconditional-runtime-import control. Source-hidden snapshot checks and
  human exports agree. No source ledger/module bytes change.

Cause: `cli/src/bea_engine/managed_load.py:_sibling_imports:2223–2242`
imports each local plugin and calls it with
`(list(loaded.entries), dict(loaded.options))`. Those are the cached,
**post-plugin** entries, so the marker causes an immediate return before
`qa_bank_helper` is imported. A new helper process has no such module in
`sys.modules`; its inventory at `:2244–2253` therefore omits it. A cold load
has already executed the original input branch and populated that inventory.
A shallow list copy changes neither the marker nor the processed state.

Caller scope: `_export_plugin_modules:2104–2148` uses this inventory at
`:2129`, feeding the export plan at `:1814`; engine `price-export`
(`cli/src/bea_engine/main.py:855`) and frontend `price._export:182` expose
it. No other `_sibling_imports` caller was found. Regular modules and
runtime-imported packages share this inventory; packages are regression
scope, not separately reproduced here. Normal reports/imports are outside
the export path.

Fix in `cli/`: discover dependencies from the plugin's actual source-input
execution, or retain/replay a complete dependency record from that execution;
reinvoking it on already transformed entries is insufficient. Keep ordinary
read caching, generated entries and financial results unchanged, and retain
existing module-scope, unconditional-runtime and namespace/resource controls.
Do not copy every neighboring module or silently publish an incomplete
snapshot. No dependency or API change is indicated.

Dedupe: whole-board searches for cached/lazy helpers, idempotent/processed
plugin input and export inventory found completed 327/868/879/880. Targeted
history identifies `9d77b8408` as 880's replay change. Its exact unconditional
helper test now works, as do the module-scope and namespace promises it pins;
this new marked-entry branch needs an input-aware repair. Open [952](./952.md)
concerns normal load-cache invalidation after helper edits/disappearance;
all source/helper bytes here stay unchanged. No overlapping open export task
or already-shipped input-aware fix found. No reopening of completed history.

Acceptance: warm and cold exports of the supplied marked-entry plugin both
contain its helper and pass fresh checks with the original hidden, or refuse
before creating an incomplete destination. Preserve 100 USD and the generated
label; preserve both working import styles, namespace resources, unrelated
module exclusion and the ordinary cached-read transition. Pin actual cache
reuse and source-hidden snapshot loading in meaningful CLI tests alongside
`cli/tests/test_price_export_plugin_runtime_imports.py`; run `make check-all`
inside `cli/` on implementation. Windows/Linux, interactive TTY and other
plugin transformations were not exercised.

# The filter `any(cost>100)` finds nothing: no comparison on a posting's cost ever matches, where Fava's filter keeps 115 entries of the public example

**Severity:** minor (a valid filter silently returns an empty or wrong result; no data is changed). **Owner:** `backend-cluster/ledger` (the advanced-filter evaluator shared by the dashboard's header filter, GraphQL, REST and MCP journal and report reads). **Estimate:** 30–45 minutes including tests. **A1:** someone moving from Fava, or an agent that reads the published filter grammar, narrows an investment ledger to large lot purchases with `any(cost>100)` and is told there are no such entries.

## Repro

Production `https://beancount.io`, dashboard entry chunk `main-CIyNN76T.js`, headless Chromium, signed in, English. The public ledger `/ledger/open_ledger/example` (one file, `main.bean`, 318,159 bytes).

1. Open `/ledger/open_ledger/example/journal?filter=any(cost%3E100)`. The Journal reads **"example · 0 entries"** and **"No journal entries found for the current filters."**
2. Control on the same page: `?filter=any(price%3E100)` reads **5 entries** (the VEA sale and the other priced postings), so the `any(...)` form and the amount comparison themselves work.
3. GraphQL `getLedgerJournal(ledgerId: "open_ledger/example", query: {filter: …})` totals, all directive types / transactions only, against Fava's own `AdvancedFilter` (the copy vendored at `cli/src/fava/core/filters.py`) run with Beancount 3.2.3 over the downloaded `main.bean`:

| Filter | Hosted | Fava |
| --- | --- | --- |
| `any(cost>0)` | **0 / 0** | 212 / 212 |
| `-any(cost>0)` | **2053 / 1044** | 1841 / 832 |
| `any(cost<70)` | **0 / 0** | 4 / 4 |
| `any(cost=74.93)` | **0 / 0** | 1 / 1 (the 2017-03-19 ITOT buy at `{74.93 USD}`) |
| `any(units>5 cost>60)` | **0 / 0** | 62 / 62 |
| `any(units:"ITOT") any(cost>60)` | **0 / 0** | 4 / 4 |
| controls: `any(cost:"USD")`, `any(price>0)`, `any(units>1000)` | 212, 5, 130 | 212, 5, 130 |

Sixty other expressions (tags, links, `,`/juxtaposition precedence, negation, `payee:`/`narration:`/metadata keys, `any`/`all`, bare `>N`) returned the same counts as Fava. Every result was repeated from a fresh load. The same filter empties the Balance Sheet too: with `?filter=any(cost%3E100)` its chart says **"No Data Available"** and Assets, Liabilities and Equity all read `-`. With `any(price>100)`, Assets reads 751.67 USD. The other filtered pages read through the same evaluator.

## Cause

`backend-cluster/ledger/src/foundation/rustledger/directive-filter.ts`:

- `postingAttribute` (≈ line 905) exposes `cost: posting.cost`, the rustledger `PostingCostJson`.
- `makeAmountMatcher` (≈ line 687) reads the number with `amountNumber` (≈ line 991), which accepts only an object whose `number` is a string or a number.
- A booked `PostingCostJson.number` is a `CostNumberJson` object, `{kind: "per_unit", value: "74.93"}` or `{kind: "per_unit_from_total", per_unit, …}` (see `node_modules/@rustledger/wasm/rustledger_wasm.d.ts`, `CostNumberJson`). So `amountNumber` returns `undefined`, and every `cost` comparison is false.

The units and price amounts are plain `{number, currency}`, which is why the controls pass. Fava's `MatchAmount` reads `posting.cost.number`, the booked per-unit cost, and compares its absolute value.

## Fix

For the comparison forms, read a cost's booked per-unit number: `per_unit` → `value`, `per_unit_from_total` → `per_unit`. For `compound` and `total`, reduce to the per-unit cost the way `bookedCostPerUnit` in `lot-inventory.ts` (≈ lines 98–140) already does for valuation. Reuse that logic in the same package; do not write a second copy. Keep the string form `any(cost:"USD")` working, the way it already matches.

## Definition of done

- On the public example, `any(cost>100)`, `any(cost=74.93)` and `any(units>5 cost>60)` return Fava's counts (115, 1 and 62 entries), in the Journal and in `getLedgerJournal`. `-any(cost>0)` returns 1,841. The controls in the table are unchanged.
- `directive-filter.test.ts` gets a case with a posting at a per-unit cost `{74.93 USD}` and one at a total cost `{{749.30 USD}}`. Both match `any(cost>70)` and `any(cost=74.93)`, and both miss `any(cost>80)`. These tests fail on the current code. The Fava golden fixture (`directive-filter.golden.json`) can carry the same cases.
- Ledger gates in `backend-cluster/ledger/AGENTS.md` pass, including `yarn verify:rustledger`.

## Blast radius

`filterDirectivesAsync` serves `ledger-journal-service.ts`, `ledger-finance-service.ts` and `ledger-data-service.ts`. So the Journal, account pages, Events, Statistics, every statement and its export, MCP `listLedgerEntries` and the REST journal reads all share the defect, and one fix covers them all. The published grammar (`backend-v2/src/features/ledger/utils/journal-filter-description.ts`) does not name `cost`, so no documentation changes.

## Dedupe

Searched `.pm/**` (open, `done/`, `blocked/`) for `cost>`, `any(cost`, `CostNumber`, `per_unit`, `number_per`, filter syntax and Fava filter. w23/m2 hardened this grammar's hints and its `account:` deviation. w1/203 is the bare `>N` description. w21/025 and w21/400 are mobile search. w3/240 and w3/414 are about `number_per` in `bea` output, not about filtering. Nothing covers cost comparisons. `git log` on `directive-filter.ts` shows no fix (latest change `b5655a4eb`).

## Unverified

Filters on a total-cost or compound-cost lot (the example has only per-unit costs). Other locales (the filter is language-independent).

---

**Resolved 2026-11-23** — Numeric posting-cost filters use the same booked per-unit calculation as inventory valuation, including total and compound costs. The public example matched Fava on all 11 checked filters, including 115 entries for `any(cost>100)`, one for `any(cost=74.93)`, 62 for `any(units>5 cost>60)`, and 1,841 for `-any(cost>0)`. The Journal service, GraphQL resolver, and Chromium page verified the counts. All 3,642 ledger tests, live engine checks, typecheck, lint, and build passed. Shipped in `987ca4f8a` (`backend-cluster/ledger`).

# Diagnose malformed budget amounts without aborting the whole budget report

**Minor · cli · 30–45m · A1/A2 · worker1.** A `custom "budget"` with a bare
number or quoted amount crashes `report budget` with an `AttributeError`,
discarding valid budgets and actuals. `--allow-errors` does not help. The
documented invalid-interval control instead reports a budget diagnostic and
keeps the usable rows. No product fix implemented.

Environment: 2026-11-07, clean main `74a0b8cbe381391a4385e88cf0358a1f7154928f`,
checkout `cli/.venv/bin/bea` 0.3.1, Python 3.12.10, macOS 26.5.1 arm64;
existing managed engine with checkout helper sources. Fresh bounded subprocesses,
closed stdin/no TTY, offline, explicit synthetic file, isolated child config
and cache, notifier disabled, inherited `BEA_FILE`/`BEA_TOKEN` removed;
HOME and global installation unchanged.

## Reproduce

Create this synthetic `main.bean` in a new directory:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:Food USD
2026-01-01 open Expenses:Travel USD
2026-01-02 * "Food"
  Expenses:Food 30.00 USD
  Assets:Cash -30.00 USD
2026-01-03 * "Travel"
  Expenses:Travel 10.00 USD
  Assets:Cash -10.00 USD
2026-01-01 custom "budget" Expenses:Food "monthly" 100
2026-01-01 custom "budget" Expenses:Travel "monthly" 50.00 USD
```

Use absolute executable/file paths and the isolated environment above:

```sh
bea --json --no-input --offline --file /absolute/main.bean check
bea --json --no-input --offline --file /absolute/main.bean report budget --time 2026-01
bea --json --no-input --offline --file /absolute/main.bean report budget --time 2026-01 --allow-errors
bea --no-input --offline --file /absolute/main.bean report budget --time 2026-01
bea --json --no-input --offline --file /absolute/main.bean report trial-balance --time 2026-01
```

Check and trial balance succeed. Budget exits 1, writes no stdout, and emits
this JSON error on stderr (the human command prints the same message):

```json
{"error":{"category":"validation","message":"AttributeError: 'decimal.Decimal' object has no attribute 'number'. Pass --debug before the command for a traceback.","exit_code":1}}
```

Changing only `100` to `"100 USD"` or `TRUE` reproduces with `'str'` or
`'bool'` in the exception. Each is valid Beancount custom syntax, but is not
a valid budget amount: rejecting that budget is appropriate. Expected:
identify the malformed budget through the existing budget-error mechanism,
keep Food's actual as unbudgeted, and keep Travel's valid 50.00 budget,
10.00 actual and -40.00 variance. Do not silently coerce the bad value.

Controls: `100.00 USD` reports both budgets; a valid amount with interval
`"fortnightly-ish"` returns usable rows plus
`budget_errors: ["Invalid interval for budget entry"]`, and a human stderr
warning. BQL and trial balance remain usable with either bad amount. Fresh
fixtures reproduced number/string failures with another valid budget present;
strict, `--allow-errors` and human paths agree. Source hashes stay unchanged.

## Cause and repair

The inherited vendored Fava parser
`cli/src/fava/modules/budgets.py::parse_budgets:117–125` reads `.number` and
`.currency` without checking the custom value's type, then catches only
`IndexError` and `TypeError`; a wrong amount shape raises `AttributeError`.
This is a parser integration/diagnostic gap, not an accounting semantic to
replace. Reuse `BudgetError` and the existing parser, validate the expected
fields, and skip only the malformed directive without swallowing unrelated
programming failures. Preserve vendored attribution.

`FavaLedger.budget` (`cli/src/fava/ledger.py:83–85`) initializes lazily;
`bea_engine/report.py::_budget:375–377` triggers the failure before rows or
`budget_errors` can be returned. `BudgetModule.load_file` is the parser's
production caller; `BudgetModule.calculate`/`calculate_children` consume its
parsed records. The frontend JSON/human budget command shares this answer.
Trial balance does not initialize the module and works, explaining its
control. Other inherited parser consumers were source-traced, not live tested.
No server, protocol or dependency change is needed.

Acceptance: malformed number/string/bool amount shapes yield actionable budget
diagnostics and preserve the independent valid budget/actual rows in JSON
and human output; valid amount and unknown-interval controls retain their
behavior. Cover the actual parser through the CLI budget journey and run
`make check-all` inside `cli/`. Do not relax Beancount syntax or invent a
currency for a bare number.

Dedupe: searched all 6,445 board Markdown files, including completed/blocked
items, and reviewed 42 open/blocked milestone scopes for budget parser,
malformed amount and AttributeError findings. No matching open repair found.
`git log -S 'entry.values[2].value.number'` traces this gap to inherited
vendoring (`41a2e6299`); the new budget integration in `a501d9341`
([w21/m7](../../w21/done/m7/README.md)) exercises that parser but tests only an
unknown interval. Keep the completed milestone closed.

No credentials or hosted resources were used. PTY and hosted budget clients
are unverified; no product fix or formal test added during QA.

## Resolution — 2026-11-08

Shipped in this commit (`cli`). Reproduced the public fixture at the shipped
baseline: `check` and trial balance succeeded, while strict and `--allow-errors`
budget reports aborted with the Decimal `AttributeError`.

The existing Fava budget parser now requires an `Amount` before reading its
number and currency. A bare number, quoted amount, or boolean records
`Invalid amount for budget entry: expected NUMBER CURRENCY` and skips that
directive only. It does not invent a currency, convert scalar values, broaden
exception handling, or change interval validation. Valid budgets and actuals
continue through the existing report. Updated the budget usage contract.

Validation:

- Three parameterized end-to-end regressions cover number/string/bool,
  independent valid budget and actuals, strict/allow-errors JSON, the human
  diagnostic exactly once, and unchanged ledger bytes. The full budget module
  passed all 17 tests. Restoring the old parser makes all three regressions
  fail with the original `AttributeError`; the fixed source was restored.
- The exact public fixture now passes check, strict budget, allow-errors,
  human budget, and trial balance. Food retains its unbudgeted 30.00 actual;
  Travel retains budget 50.00, actual 10.00, variance -40.00. No ledger write.
- Existing valid-amount and unknown-interval controls pass. Independent
  read-only review found no issue.
- Host lint, dead-code, format, mypy, pinned-spec and documentation gates pass.
- Full `make check-all` passed on Linux/Python 3.12: 11,706 passed,
  41 skipped, including all lint/format/type/spec/docs checks. The exact
  verified CLI tree is `08ae406b5646a2bfd18739fc19fe9be005d7e9f1`.
- The repository publish-scope secret scan passed with no leaks.

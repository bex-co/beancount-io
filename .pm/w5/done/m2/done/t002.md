## Objective

Fix `LedgerItem`'s interactive semantics: no button nested inside `SidebarMenuButton`, icon-only triggers get `aria-label`s, and all interactive targets meet the 24px WCAG minimum.

## Context

- `dashboard-sidebar.tsx` `LedgerItem` (~lines 107–112): the admin dropdown trigger is a `<button>` nested inside `SidebarMenuButton` (interactive-in-interactive; `stopPropagation` patches the click but not the SR/keyboard semantics). The settings trigger is icon-only at 20×20px with `title` but no `aria-label`.
- Sequenced after w5/m1, which also changes `LedgerItem` (badges/meta line) — rebase this work on the m1 row layout.

## Steps

1. Restructure the row so the navigation target and the dropdown trigger are sibling interactive elements (e.g. `SidebarMenuAction` pattern from the shadcn sidebar), not nested.
2. Add `aria-label`s to all icon-only triggers; keep visible tooltips/titles in sync.
3. Bring hit targets to ≥24×24px without visually enlarging icons.
4. Verify keyboard: Tab reaches both actions; Enter/Space activate the right one.

# Normalize native Beancount query input with its loaded text

**Minor · cli · 20–30m · A1.** Native Beancount-source execution reads
ledger text through bea's NFC shim but leaves command input decomposed.
An accented literal copied from the file then returns no matching expense
at exit 0, and a stored-query name copied from that same file is not found.
The default `--file` path handles both spellings correctly. No fix implemented.

Real CLI QA, 2026-10-21, HEAD `0e6f340ab` (initial journeys on
`faf5fa48a`, CLI unchanged), checkout `bea 0.3.1`, macOS 26.5.1 arm64,
frontend Python 3.13.3, existing managed Python 3.12.10. Fresh subprocesses,
closed stdin/no TTY, isolated absolute `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`,
`BEA_NO_UPDATE_NOTIFIER=1`, no inherited `BEA_FILE`/`BEA_TOKEN`.
Synthetic local files only; no optional feature or server is needed.

Create `/abs/books/main.bean` with explicit decomposed characters:

```python
from pathlib import Path
books = Path('/abs/books')
books.mkdir(parents=True, exist_ok=True)
name = 'Cafe\u0301'
(books / 'main.bean').write_text(
    'option "operating_currency" "USD"\n'
    '2024-01-01 open Assets:Cash USD\n'
    '2024-01-01 open Expenses:Food USD\n'
    f'2024-01-02 * "{name}"\n'
    '  Assets:Cash -10.00 USD\n'
    '  Expenses:Food 10.00 USD\n'
    f'2024-02-01 query "{name}" "SELECT number WHERE account=\'Expenses:Food\'"\n',
    encoding='utf-8')
```

The following Python runs exact command arguments, avoiding clipboard or
terminal normalization of the visually identical names. Run from `/abs/books`
with `bea` on PATH and the isolated child environment above:

```python
import subprocess

commands = [
    ['bea', '--json', '-f', '/abs/books/main.bean', 'check'],
    ['bea', 'query', "SELECT account,number WHERE account='Expenses:Food' AND narration='Cafe\u0301'", '--source', 'beancount:/abs/books/main.bean', '--format', 'csv'],
    ['bea', 'query', ".run Cafe\u0301", '--source', 'beancount:/abs/books/main.bean', '--format', 'csv'],
    ['bea', 'query', "SELECT account,number WHERE account='Expenses:Food' AND narration='Caf\u00e9'", '--source', 'beancount:/abs/books/main.bean', '--format', 'csv'],
    ['bea', 'query', ".run Caf\u00e9", '--source', 'beancount:/abs/books/main.bean', '--format', 'csv'],
    ['bea', '-f', '/abs/books/main.bean', 'query', "SELECT account,number WHERE account='Expenses:Food' AND narration='Cafe\u0301'", '--format', 'csv'],
    ['bea', '-f', '/abs/books/main.bean', 'query', ".run Cafe\u0301", '--format', 'csv'],
]
for command in commands:
    result = subprocess.run(command, stdin=subprocess.DEVNULL, check=False)
    print('exit:', result.returncode, flush=True)
```

Actual exits: **0, 0, 2, 0, 0, 0, 0**. Check accepts the source. The native
decomposed-literal query writes only CSV headers, omitting the 10 USD Food
posting; its stored-query call says `query "Café" not found` while listing
the visually identical `Café` as available. The native composed-input controls
return Food 10 and the stored query's 10. The `--file` controls also return
10 with the exact decomposed input. Every source byte stays unchanged.

Expected: Beancount source input agrees with the NFC form the helper actually
loads, so both native decomposed calls return the same 10 as their controls.
USAGE says BQL literals compare NFC-normalized. The compatibility shim is
bea's own transformation, so this is not an upstream inability to query
decomposed data: an unwrapped `beanquery.connect` on a fresh copy retains the
NFD name and successfully returns that expense using its NFD literal.
This control creates no interactive shell or personal history.

Native CSV is the important scope control: its file remains raw text. An NFD
CSV cell matches the NFD literal and not the NFC one; an NFC CSV cell does
the reverse. Preserve that existing native-source behavior. Normalizing every
source indiscriminately would break these passing queries.

Cause: importing `bea_engine` installs `compat.install`
(`cli/src/bea_engine/__init__.py:3–5`). The wrapper in
`compat.py:parse_file` (:23–56) calls `_canonical_bytes` (:227–243), which
normalizes the complete ledger text before Beancount parses it. Native
`beanquery.sources.beancount.attach` calls that wrapped parser through the
loader, so both stored names and narration values become NFC too.

Default `PreciseShell._dispatch` in `cli/src/bea_engine/query.py:1486–1489`
normalizes command input to the same form. Native `GuardedShell._dispatch`
(:656–664) does not, and its `execute` also leaves BQL literals unchanged.
The shared `_run_stored` (:863–936) then looks up the unnormalized name in
the normalized dictionary, while direct BQL compares unlike spellings.
One-shot and interactive native-source entry points share this shell; only
one-shots were exercised. No JSON-source output is claimed.

Fix native **Beancount** command input so its names and literals agree with
the loaded ledger's normalization, including quoted stored names. Keep the
native CSV/raw-source control, case sensitivity, native rendering, missing
query exit 2 and refusal-time output preservation. Add real CLI regressions
for stored names and direct literals on NFC/NFD ledgers, with CSV controls.
No dependency or backend/API change needed.

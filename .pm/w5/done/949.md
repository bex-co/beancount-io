# Preserve inferred compound-cost parts in single-add JSON round trips

**Minor · cli · 40–60m · A1.** A successful `add transaction` with an
inferred per-unit or total cost returns JSON that `add transactions` cannot
replay. The original trade checks cleanly; its unchanged answer loses the
inference and the replay refuses as unbalanced. Follow-up to completed
[801](./done/801.md) and [w1/092](../w1/done/092.md), not a product fix.

Real CLI QA, 2026-10-21, HEAD `f2cb798dd`, checkout `bea 0.3.1`, macOS
26.5.1 arm64, frontend Python 3.13.3, existing managed Python 3.12.10 /
Beancount 3.2.3. Fresh subprocesses, closed stdin/no TTY, isolated absolute
`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, no inherited
`BEA_FILE`/`BEA_TOKEN`. No external service or installed dependency change.

In a disposable `/abs/books`, create **both** `main.bean` and `copy.bean`
with these same pristine contents:

```beancount
2024-01-01 open Assets:Broker HOOL
2024-01-01 open Assets:Cash USD
```

```sh
bea --json -f /abs/books/main.bean check
bea --json -f /abs/books/main.bean add transaction --date 2024-01-02 --narration Buy --posting 'Assets:Broker 2 HOOL {# 0.50 USD}' --posting 'Assets:Cash -10.50 USD' > /abs/books/added.json
```

Copy the returned directive without editing it:

```python
import json
from pathlib import Path
books = Path("/abs/books")
answer = json.loads((books / "added.json").read_text())
(books / "rows.json").write_text(json.dumps([answer["data"]["directive"]]))
```

```sh
bea --json -f /abs/books/copy.bean add transactions --from /abs/books/rows.json
bea --json -f /abs/books/main.bean check
bea --json -f /abs/books/copy.bean check
bea --json -f /abs/books/main.bean query 'SELECT account,sum(cost(position)) GROUP BY account ORDER BY account'
bea --json -f /abs/books/copy.bean list transaction --limit 100
```

Actual: the single add exits 0 and writes one valid transaction. The two
shares book at **5.25 USD each**, so BQL reports Broker cost **10.50 USD**
and Cash **−10.50 USD**. The answer's cost is `number: null,
number_total: "0.50", currency: "USD"`. Bulk replay exits **1**, empty
stdout, a validation JSON object on stderr containing `Row 1: Proposed
append (not written): Transaction does not balance: (-10.00 USD)`.
`copy.bean` stays byte-identical and its transaction listing stays empty;
both ledger checks exit 0. Original source and saved answer/payload bytes
remain intact. This breaks USAGE's explicit unedited round-trip guarantee.

The second form replaces only the first posting with
`Assets:Broker 2 HOOL {5 # USD}`. Its original trade also books at 5.25 USD
and checks cleanly. Its answer instead has `number: "5", number_total:
null`; replay drops the inferred total and refuses with **−0.50 USD**.
Both forms fail with file input and `--from -`, each from pristine fixtures
twice. This is not a rejected original trade or an invalid source ledger.

Controls: `{5.25 USD}`, `{{10.50 USD}}`, explicit `{5 # 0.50 USD}` and
`@@ 10.50 USD` all round-trip, twice. Replacing the candidate answer's cost
with explicit `number: "5", number_total: "0.50"` also replays and produces
the same booked lot. Date/label constraints, tags, links and metadata were
retained in the larger matrix; removing those extras in the public recipe
does not remove the failure. No recurring-division precision is involved.

Cause: `_transaction` (`cli/src/bea_engine/ledger/adding.py:1228–1252`)
encodes its parsed, unbooked entry as the answer before appending it.
`protocol._cost_spec_jsonable` (:282–307) maps both native `MISSING` and
an absent component to null. Bulk's `Cost` model has no representation for
that distinction (`ledger/models.py:144–173`). Its renderer
`ledger/writer.py:365–371` interprets null-per-plus-total as the **fixed
total** form, writing `{0 # 0.50 USD}`; null-total becomes `{5 USD}`.
Neither is the cost the original transaction inferred. The shared encoder
is reached recursively through `_jsonable`; other unbooked directive JSON
is source-derived potential scope, not a separately reproduced failure.
Ordinary booked `Cost` values and native text printing are working controls.

Fix: preserve the inferred component through this JSON contract, either
with explicit interpolation state accepted by bulk or by completing it from
the validated staged transaction. Keep fixed-total null semantics from
w1/092, partial lot selectors, exact `@@` totals and units interpolation.
Do not turn a missing part into zero, alter the valid original booking, or
add a fallible post-commit encoding step. A returned directive must replay
as the same lot and cash movement; if a form cannot be represented, refuse
it before writing with a usable alternative rather than claiming the
documented round trip. No dependency or backend/API change is needed.

**Resolved 2026-10-22** — fixed: a single `add transaction` answer now reports the cost component the file left to booking (`_with_inferred_cost_parts` in `cli/src/bea_engine/ledger/adding.py`). The missing per-unit or total part of a compound cost is solved from the other legs when they are explicit amounts in the cost currency and the result reproduces the balance exactly, for the answer only (the written text is unchanged), so `{# 0.50 USD}` answers `number: 5` with `number_total: 0.50` and `{5 # USD}` answers the inferred 0.50 total; `add transactions` replays both unedited into the same 5.25 USD lot and a passing check. A part that solves to zero (`{# 5 USD}` against -5, `{100 # USD}` against -200), explicit costs and anything the legs cannot determine exactly are reported as before. Regression tests in `cli/tests/test_add_inferred_cost_roundtrip.py` fail without the fix. Shipped in this commit (`cli`).

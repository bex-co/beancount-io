# `skills/scripts/beancount-skills.py install DEST` prints a Python traceback when DEST is an existing file or a dangling symlink, and `verify DEST` says "directory does not exist" for a path that exists

**Trivial · skills · 10m · A1.** Real QA, 2026-10-14, HEAD `bce2c992`, macOS 26.5.1, Python 3.14.
The documented install command is `python3
"$SKILLS_SRC/skills/scripts/beancount-skills.py" install ~/.claude/skills
~/.agents/skills` (`installation.md`, README). A destination that is a
symlink into a dotfiles repo not yet cloned (dangling), or a stray
regular file, crashes `mkdir`. The destinations after it are never
processed. No product fix implemented.

```sh
touch /absolute/tmp/file
ln -s /absolute/tmp/nowhere /absolute/tmp/dangling
python3 skills/scripts/beancount-skills.py install /absolute/tmp/file
python3 skills/scripts/beancount-skills.py install /absolute/tmp/dangling
python3 skills/scripts/beancount-skills.py verify /absolute/tmp/file
```

Actual:

- Each `install` exits 1 with a 14-line traceback ending
  `FileExistsError: [Errno 17] File exists: '…'`. `install …/file/sub`
  ends with `NotADirectoryError`.
- `verify …/file` exits 1 with `FAIL …/file: directory does not exist;
  run install first`.

Reproduced twice per input by the hunter, and by me for `install file`.

Control: a fresh path, including one with spaces, installs all 8 skills.
Re-install is idempotent, and uninstall removes only its links.

Expected: the script's docstring says "`install` changes nothing when
any owned name is already taken by something else". The destination
itself deserves the same treatment: a one-line refusal naming the path
and what it is ("is a file", "links to … (target missing)"), as
`describe_conflict` already does for entries. The script should then
carry on with the other destinations. `verify` should report the actual
type.

Cause: `skills/scripts/beancount-skills.py:184` calls
`dest.mkdir(parents=True, exist_ok=True)` unchecked. `verify`
(`:67-69`) prints one message for every case where the path is not a
directory.

Fix: before `mkdir`, if `os.path.lexists(dest) and not dest.is_dir()`,
print the reason and skip that destination with exit 1 at the end.
Mirror this in `verify`. Stdlib only.

Dedupe: [w5/m13/t002](../m13/t002.md) (blocked) covers
permission-denied and interrupted link creation (a read-only DEST also
gives a raw `PermissionError` there). It does not cover a file or
dangling-symlink destination, which fails earlier at `mkdir`. Nothing
else matches.

Acceptance: `install` on a file or dangling destination exits 1 with one
line naming it and no traceback, and processes the remaining
destinations. `verify` names the type. A test in
`skills/scripts/test_*.py` covers both.

---

**Resolved 2026-10-15** — `skills/scripts/beancount-skills.py` gained
`destination_problem`, which describes a destination that is not a
directory. If the destination is missing, it describes the nearest
existing parent instead: "is a file, not a directory" for a file, or
"links to … (target missing)" for a dangling link. `install` prints
`FAIL <problem>. Nothing was installed there.`, exits 1, and carries on
with the remaining destinations, with no traceback. `verify` names the
same problem instead of "directory does not exist" and keeps that message
for paths that are truly absent. `install …/file/sub` names the file in
its path. Covered by two tests in `skills/scripts/test_beancount_skills.py`,
which fail without the fix (one errors with the old traceback).

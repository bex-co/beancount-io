# Find ledger suffix case variants during directory formatting

**Minor · cli · 20–30m · A1.** Directory formatting silently omits valid
`.BEAN`, `.BeAn`, `.Beancount` and `.BEANCOUNT` files. Its check can pass
while an explicit check of the omitted file reports that formatting is
needed. In a mixed directory, in-place formatting also succeeds without
formatting that file. No product fix implemented.

Real CLI QA, 2026-10-21, HEAD `137e0c210` (CLI unchanged from the initial
`08cedeaf8` reproduction), checkout `bea 0.3.1`, macOS 26.5.1 arm64,
frontend Python 3.13.3 and existing managed Python 3.12.10 / Beancount
3.2.3. Separate bounded processes, closed stdin/no TTY, isolated absolute
`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, inherited `BEA_FILE`
and `BEA_TOKEN` removed. Local synthetic books only.

Create a fresh disposable `/abs/books` containing only `journal.BEAN`:

```beancount
2024-01-01 open Assets:Cash USD
2024-01-01 open Equity:Opening USD
2024-01-02 * "Opening"
  Assets:Cash 100.00 USD
  Equity:Opening -100.00 USD
```

From `/abs/books`:

```sh
bea --json -f /abs/books/journal.BEAN check
bea --json format --check /abs/books
bea --json format --dry-run /abs/books
bea --json format --in-place /abs/books
bea --json format --check /abs/books/journal.BEAN
bea --json format --in-place /abs/books/journal.BEAN
bea --json format --check /abs/books
bea --json format --check /abs/books/journal.BEAN
bea --json -f /abs/books/journal.BEAN check
```

Actual exits: **0, 0, 0, 2, 1, 0, 0, 0, 0**. The initial ledger is valid.
Directory check and preview return `scanned: 0`, empty `formatted`, `failed`,
`missing` and `skipped`. Directory apply refuses with usage exit 2,
`No .bean or .beancount files found to rewrite.` All preserve the file.
Explicit check correctly returns validation exit 1 with `scanned: 1` and
the file in `error.result.formatted`. Explicit apply aligns its postings;
the final explicit check and native ledger check pass. Balances remain
Cash 100 USD / Equity −100 USD. The directory still reports zero scanned
even after the explicit repair, because its discovery never sees the file.

The same sequence reproduces twice each for all four case variants, with
`.bean` and `.beancount` controls. Both lowercase controls are found by
directory check (exit 1 / scanned 1); directory apply formats them and exits
0. Every explicitly named variant is accepted and formats idempotently.

In an additional fresh mixed-directory control, put an already formatted
`seed.bean` at the top and the unformatted file at `years/journal.BeAn`.
Directory check now returns **0 / scanned 1**, human output says
`All 1 file(s) are formatted.`, and directory apply exits **0** without
changing either file. Explicitly checking the nested file still exits 1.
This is not only the empty-directory result. Reproduced twice, with manual
byte hashes covering uppercase suffixes as well as ordinary captures.
Truly empty directories and standalone `.txt` files remain intentional
directory-discovery exclusions; the `.txt` file still works when explicitly
named. Keep those controls.

Expected: discover case variants of the two supported ledger suffix
families consistently with explicitly named files and the CLI's existing
case-insensitive ledger discovery. An unformatted `.BEAN` file should make
directory check fail and appear in preview; directory apply should format
it, then a repeat check should pass. USAGE's formatting contract says check
fails when formatting is needed and in-place formats scanned plaintext
files. The earlier suffix repairs below establish these ledger spellings
as supported; the issue is directory selection, not a request to scan
arbitrary filenames.

Cause: `cli/src/cli/commands/format.py:_walk` at 597–618 selects with
`name.endswith(tuple(SUFFIXES))` at 615, where `SUFFIXES` contains only
lowercase `.bean` and `.beancount`. `os.walk` returns on-disk spellings;
this string comparison stays case-sensitive even on the tested
case-insensitive APFS volume. `_targets` (:410, :469) is its only caller;
the command at :99 sends that reduced set to syntax checks, check/preview
and in-place rendering. The explicit-file branch at :491 accepts any
regular filename, explaining the working control. This also covers a
directory among several positional formatting targets; that combination
is source-traced, not separately exercised.

Fix: case-fold the candidate suffix when deciding membership in the two
existing suffix families, retaining the actual path spelling for reports
and writes. Keep the existing directory boundaries, file deduplication,
AppleDouble/editor-file handling and explicit-file/include behavior.
Do not expand directory discovery to `.txt` or every file. All format modes
share this selector; no engine, dependency or API change is needed.

Dedupe: searched all board states for uppercase/mixed-case ledger suffixes
and formatting discovery, scanned 48 active/blocked milestone titles, and

Acceptance: directory check/preview/apply find all six tested suffix

**Resolved 2026-10-22** — fixed: directory formatting (`_walk` in `cli/src/cli/commands/format.py`) now case-folds a file's suffix when deciding whether it is a `.bean` or `.beancount` ledger, keeping the on-disk spelling for reports and writes. `.BEAN`, `.BeAn`, `.Beancount` and `.BEANCOUNT` files, nested ones included, are scanned, so `format --check` on a directory fails when one needs formatting, `--dry-run` lists it and `--in-place` formats it; `.txt` files and empty directories stay excluded from directory discovery, and explicitly named files behave as before. Regression tests in `cli/tests/test_format_directory_suffix_case.py` fail without the fix. Shipped in this commit (`cli`).

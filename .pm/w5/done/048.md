---

**Resolved 2026-10-03** — a request body the HTTP parser cannot read on the MCP endpoint is now answered as a JSON-RPC error with a null `id` and a JSON content type, instead of Koa's plain-text `Bad Request`: `-32700` for text that is not JSON (malformed or whitespace-only), `-32600` for JSON that is not a request object (a bare scalar) or a body past the size limit. The HTTP status is the parser's own (400, or 413 when too large). Shipped in `d851f9d7` (`backend-cluster/backend-v2`).

The body-parser wrapper moved out of the server bootstrap into its own middleware so it could be tested against a real socket; other paths and the OAuth provider's skip behave as before. Tests post a scalar, a JSON string, malformed JSON, whitespace and an oversized body to the MCP path, and a malformed body elsewhere; the MCP cases fail with the new branch disabled. As before, this refusal precedes authentication, so an anonymous caller with an unreadable body gets it rather than a 401. Not re-run against the hosted endpoint: the fix reaches it with the next deploy.

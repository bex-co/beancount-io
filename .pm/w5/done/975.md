# Retain transfer history under a reused native reference

**Major · cli · 30–45m · A1.** Importing two monthly checking transfers
under one reused bank reference makes the earlier transfer disappear from
shared-reference matching. A single receiving-side February row, dated five
days after that transfer, previews as new and even an ordinary default apply
writes it again. Checking/Savings become **−300/+300 USD** instead of
**−200/+200**, with three transactions and a clean check. Distinct references,
the latest receiving-side row, and a three-day delay work. This also affects
two issuing accounts whose IDs are each unique: a later sender overwrites
the earlier sender's matching owner. No fix implemented.

Real CLI QA, 2026-10-22, clean main `e09d2588c` (initial reproduction on
`40fd62759`; separate-issuer extension on `2a8095778`, import code unchanged).
Checkout `bea 0.3.1`, frontend Python
3.13.3, managed Python 3.12.10 / Beancount 3.2.3 / Beanquery 0.2.0,
macOS 26.5.1 arm64. Fresh subprocesses, closed stdin/no TTY, isolated absolute
configuration/cache, notifier disabled, inherited file/token overrides removed.
Only synthetic local CSVs and ledgers were used.

Use the checkout's `bea` on PATH and replace `/abs/case` with a fresh absolute
disposable directory. The first bank legitimately reuses `monthly-ref` on
February 1 and March 1; its import explicitly includes the reviewed second
occurrence. The receiving statement contains only February's corresponding
100 USD credit on February 6, under that bank-shared reference.

For the separate-sender variant set `split_issuers = True`. February is
imported from Checking and March from CheckingB, each carrying its one unique
reference; neither sender needs a duplicate-policy override. This adds one
`checking-b-apply` command before the receiving-side preview.

```python
import json, os, subprocess
from pathlib import Path
case = Path('/abs/case')
case.mkdir(parents=True)
ledger = case / 'main.bean'
split_issuers = False
ledger.write_text('''option "operating_currency" "USD"
2024-01-01 open Assets:Checking USD
2024-01-01 open Assets:Savings USD
2024-01-01 open Expenses:Uncategorized USD
''' + ('2024-01-01 open Assets:CheckingB USD\n' if split_issuers else ''))
unique_refs = False
delay_days = 5
head = 'Date,Description,Amount,Category,Reference\n'
checking = case / 'checking.csv'
savings = case / 'savings.csv'
second_ref = 'march-ref' if unique_refs else 'monthly-ref'
march = '2024-03-01,TRANSFER TO SAVINGS,-100.00,Assets:Savings,' + second_ref + '\n'
checking.write_text(head
    + '2024-02-01,TRANSFER TO SAVINGS,-100.00,Assets:Savings,monthly-ref\n'
    + ('' if split_issuers else march))
second_sender = case / 'checking-b.csv'
if split_issuers:
    second_sender.write_text(head + march)
savings.write_text(head + f'2024-02-{1+delay_days:02d},TRANSFER FROM CHECKING,100.00,Assets:Checking,monthly-ref\n')
fixed = {p: p.read_bytes() for p in (checking, savings)}
if split_issuers:
    fixed[second_sender] = second_sender.read_bytes()
env = os.environ.copy()
for key in ('BEA_FILE', 'BEA_TOKEN', 'BEANCOUNT_LOAD_CACHE_FILENAME',
            'BEA_ENGINE_PYTHON', 'BEA_ENGINE_DIR'):
    env.pop(key, None)
env.update(BEA_CONFIG_DIR=str(case / 'config'), XDG_CACHE_HOME=str(case / 'cache'),
           BEA_NO_UPDATE_NOTIFIER='1')
def run(tag, args, json_mode=True):
    argv = ['bea', *(['--json'] if json_mode else []), '--no-input', '-f', str(ledger), *map(str, args)]
    result = subprocess.run(argv, cwd=case, env=env, stdin=subprocess.DEVNULL,
                            capture_output=True, text=True, timeout=25)
    print(json.dumps(dict(tag=tag, args=argv, exit=result.returncode,
                         stdout=result.stdout, stderr=result.stderr)), flush=True)
map_spec = 'date=Date,narration=Description,amount=Amount,category=Category,id=Reference'
run('baseline-check', ['check'])
run('checking-apply', ['import', checking, '--csv', map_spec,
    '--account', 'Assets:Checking',
    *([] if split_issuers else ['--duplicates', 'include']), '--apply'])
if split_issuers:
    run('checking-b-apply', ['import', second_sender, '--csv', map_spec,
        '--account', 'Assets:CheckingB', '--apply'])
authored = ledger.read_bytes()
second = ['import', savings, '--csv', map_spec, '--account', 'Assets:Savings']
run('human-preview', second, json_mode=False)
run('preview', second)
assert ledger.read_bytes() == authored
run('default-apply', [*second, '--apply'])
run('skip-apply', [*second, '--duplicates', 'skip', '--apply'])
run('positions', ['query', 'SELECT account,sum(number) GROUP BY account ORDER BY account'])
run('transactions', ['list', 'transaction', '--sort', 'oldest', '--limit', '20'])
run('check', ['check'])
assert ledger.read_bytes().startswith(authored)
assert all(p.read_bytes() == content for p, content in fixed.items())
```

**ready 1 / possible_duplicates
0**; human preview also calls it new. Default apply wrongly writes **1**
without review. The later skip apply correctly skips that newly written
Savings-owned ID, leaving the duplication in place. Final query and listing:


Cause: `answer` in `cli/src/bea_engine/importing.py:437–457` keeps
`transfer_ids` as one entry per native key and assigns
`transfer_ids[identity] = entry`. Loading March overwrites February for both
its bank key and retained `import-id`. `_transfer_side` (`:1651–1674`) sees
only March 1, which is 24 days from February 6, so rejects it. The correct
February 1 entry is five days away and agrees on amount. Its other fallback,
`_transfer_counterpart`, has a deliberately narrower three-day window and
cannot rescue the match. The row is therefore new. For separate senders,
`_identities` keys both counterleg owners under the receiving account's scope;
that single slot still discards the earlier issuer even though neither
sender reused its own native ID.

Direct controls on both real after-checking graphs prove the same key
`('Assets:Savings', 'bank', 'bank:monthly-ref')` has written owners on
February 1 and March 1, but the index retains only March. `_transfer_side`
returns no hit with that actual index; using February as the sole owner
correctly returns a hit, while March alone does not. This is lost history,
not a failed price comparison, invalid fixture or a bank-ID namespace change.

Fix in `cli/`: retain every written transfer under a native reference and
select an eligible same-source-amount owner nearest the incoming date within
the existing shared-reference window. Carry the selected entry consistently
through counterpart reservations and preview classification. Preserve issuer
account scoping, one-to-one reservations, real-deposit controls, own-account
native-ID conflicts and the separate three-day amount-only heuristic. Do not
widen either window or classify every repeated-reference row as a duplicate.
No dependency or API change indicated.

Caller scope: `transfer_ids` is built in `answer`; `_transfer_side` feeds both
its shared-ID classification branch (`:644`) and the native-ID reservation
pass in `_assign_counterparts` (`:1721–1764`, called by lazy `paired` at
`:493–500`). Both must consume the same candidate history. Actual CSV
producer/consumer flows were exercised. The shared helper also serves Python
importers and FITID/custom native keys; those variants are regression scope,

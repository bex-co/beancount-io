# Match a cost-selected FIFO sale to its split booked twin

**Major · cli · 25–40m · A1.** Importing a manually recorded sale with a
stated per-unit cost books it a second time under default duplicate policy
when FIFO spread the original sale over two lots at that same cost. Holdings
fall from 14 to 8, proceeds and realized profit double, and `check` stays valid.
An unstated cost or a one-lot purchase correctly triggers duplicate review;
a shared native ID correctly skips. No product fix implemented.

Real local CLI QA 2026-10-22, source checkout `9c394e685`, public recipe rechecked on `9c394e685`, `bea 0.3.1`,
macOS 26.5.1 arm64, frontend Python 3.13.3, managed Python 3.12.10 /
Beancount 3.2.3. Reproduced twice from pristine synthetic books in bounded
real CLI subprocesses, closed stdin/no TTY, isolated configuration and caches.
No plugin, filter, inferred amount or existing import metadata is needed.

Run this self-contained recipe with `bea` on PATH and a fresh absolute
scratch directory in place of `/abs/case`. The ledger models two purchases at
100 USD on different dates and one six-share FIFO sale. Its cost number and
currency are stated, while acquisition date and label are deliberately left
open. All balancing amounts are explicit.

```python
from pathlib import Path
import json, os, subprocess

case = Path('/abs/case')
open_selector = False
single_purchase = False
native_id = False
case.mkdir(parents=True, exist_ok=False)
ledger = case / 'main.bean'
base = 'option "operating_currency" "USD"\n2023-01-01 open Assets:Cash USD\n2023-01-01 open Assets:Stock HOOL "FIFO"\n2023-01-01 open Equity:Opening USD\n2023-01-01 open Income:Gains USD\n2023-01-01 * "Capital"\n  Assets:Cash 10000 USD\n  Equity:Opening -10000 USD\n'
for k, quantity in enumerate([20] if single_purchase else [5, 15], start=2):
    base += (f'2023-01-{k:02d} * "Buy {k}"\n'
             f'  Assets:Stock {quantity} HOOL {{100 USD}}\n'
             f'  Assets:Cash {-quantity*100} USD\n')
sale = ('2024-02-01 * "Sale"\n'
        + ('  bank_id: "trade-6"\n' if native_id else '')
        + '  Assets:Stock -6 HOOL {100 USD} @ 150 USD\n'
          '  Assets:Cash 900 USD\n  Income:Gains -300 USD\n')
ledger.write_text(base + sale)
statement = case / 'sale.statement'
statement.write_text(sale.replace('{100 USD}', '{USD}') if open_selector else sale)
config = case / 'importer.py'
config.write_text('from beancount.parser import parser\nclass Broker:\n    name = "broker"\n    def identify(self, file): return str(file).endswith(".statement")\n    def account(self, file): return "Assets:Stock"\n    def extract(self, file, existing_entries=None):\n        entries, errors, _ = parser.parse_file(str(file))\n        assert not errors, errors\n        return entries\nCONFIG = [Broker()]\n')
env = os.environ.copy()
for key in ('BEA_FILE', 'BEA_TOKEN', 'BEANCOUNT_LOAD_CACHE_FILENAME',
            'BEA_ENGINE_PYTHON', 'BEA_ENGINE_DIR'):
    env.pop(key, None)
env.update(BEA_CONFIG_DIR=str(case / 'config'), XDG_CACHE_HOME=str(case / 'cache'),
           BEA_NO_UPDATE_NOTIFIER='1')
def run(tag, args, json_mode=True):
    argv = ['bea', *(['--json'] if json_mode else []), '--no-input', '-f', str(ledger), *map(str, args)]
    before = ledger.read_bytes()
    result = subprocess.run(argv, cwd=case, env=env, stdin=subprocess.DEVNULL,
                            capture_output=True, text=True, timeout=25)
    print(json.dumps(dict(tag=tag, args=argv, exit=result.returncode,
                         stdout=result.stdout, stderr=result.stderr,
                         ledger_changed=ledger.read_bytes() != before)), flush=True)
args = ['import', statement, '--config', config]
query = ['query', 'SELECT account,sum(number) GROUP BY account ORDER BY account']
run('baseline', ['check'])
run('baseline-facts', query)
run('preview', args)
run('default-apply', [*args, '--apply'])
run('facts', query)
run('sheet', ['report', 'balance-sheet', '--time', '2024-02', '--conversion', 'at_cost'])
run('skip-repeat', [*args, '--duplicates', 'skip', '--apply'])
run('check', ['check'])
```

Actual: every command exits 0 with JSON on stdout and empty stderr. Baseline
query returns cash **8900 USD**, stock **14 HOOL**, equity **−10000 USD**,
gains **−300 USD**. Preview incorrectly reports `ready: 1,
possible_duplicates: 0`. Default apply writes **1**, a second `Sale` entry
with a generated import ID. Final query returns cash **9800**, stock **8**,
gains **−600**. The at-cost balance sheet shows net worth **10600** and
February profit **600**, instead of **10300 / 300**. Repeat skips the now
imported generated ID and writes 0; the fresh check is still valid. Preview
itself is read-only. Apply preserves the original ledger prefix but appends
the extra sale, so this is persisted double counting rather than rendering.

Expected: the same dated narration, same −6 HOOL at 150 USD and the same
stated cost select the already booked sale. With no native ID, offer it as a
possible duplicate, default apply exits 4 without writing, and explicit
`--duplicates skip --apply` writes 0. IMPORTING's open-cost rule compares the
fields actually stated against the lot or lots booking chose. An omitted
acquisition date is not evidence that this otherwise identical sale is new.

Nearby controls, twice each in both JSON and human apply: set
`open_selector = True` (statement `{USD}`, original `{100 USD}`) or
`single_purchase = True` (one 20-share purchase). Preview reports one
possible duplicate, default apply exits 4, skip writes 0, and cash 8900 /
stock 14 / profit 300 remain. Set `native_id = True` instead: the same ID on
the hand-entered sale and statement yields one exact duplicate / apply 0.
Human output carries the normal “Using importers from …” config notice on
stderr. The original statement and importer bytes are retained.

Cause: `cli/src/bea_engine/importing.py:1514–1536`, `_booked_for`, first
checks for a single booked posting with identical units. The original sale
was booked as **−5 and −1 HOOL**, cost 100 USD, acquisition dates January 2
and 3, so neither alone equals −6. The next guard,
`if lot is None or lot[0] is not None: return`, stops because the incoming
cost number is 100. It never considers the two compatible legs together,
although their units sum exactly and both costs satisfy every stated field.
`_possible_twin` at 2829 and `_legs_agree` at 1484 consequently reject the
existing sale, and the generated ID is new because the original has no ID.
The open-selector control reaches the combined-leg branch, the single-lot
control takes the direct match, and the native-ID control is rescued by
`_under_id`'s raw source proof; those passing native reimports alone do not
exercise this missed hand-entry path.

Independent unwrapped Beancount loads validate each original and final graph:
14 shares at cost 1400 / cash 8900 / gain −300 before; only the failing mode
ends at 8 shares at cost 800 / cash 9800 / gain −600 with two sales. Actual
helper comparisons retain cost 100 and both dated booked legs, but return no
candidate for the known-cost split. No upstream booking failure occurs.

Fix: permit split booked legs to answer for a cost-selected source leg when
all those legs satisfy its stated number, currency, date, label and child
account and their quantities sum to the source amount. Preserve one-to-one
ownership, price/amount checks and real selector differences; do not turn a
stated cost into a wildcard. Keep default review and explicit skip behavior.
No dependency or API change is required.

Dedupe: all board states, open milestone scopes, callers and targeted history
were checked for same-cost FIFO splits and cost-selected twins. Closed 603
(`9ed4b93cd`) introduced the per-number early return while repairing `{}`
sales over unequal costs; closed 896 (`4c00e148b`) retained it while repairing
subset ownership. Open 977 is the separate **above-twelve** subset cutoff
for two number-open fills; this case has one number-stated fill and only two
lots, so changing that cutoff alone cannot fix it. Closed 899/897 count
stated selectors in generated IDs and closed 912 scopes child accounts;
no generated ID is being compared here. Open 974 is missing raw native-ID
ownership for an open cost under a filter; this original has no native ID or
filter. No overlapping open repair was found. Native-ID reimport controls
with stated costs also pass and are retained as coverage, not findings.

Acceptance: the published default import requires review and preserves the
single original sale; skip writes 0, with cash 8900 / stock 14 / cost net worth
10300 / profit 300. Retain the three passing controls and existing split-fill,
selector-difference and child-account tests. Add a real hand-entry/import
regression with at least two equal-cost lots and a stated source cost. Run
the owning CLI checks before implementing shipment. Other platforms,
booking methods and larger portfolios remain unverified.

**Resolved 2026-10-23** — fixed: a source leg whose cost states a per-unit number can now stand for several booked legs, as an open `{USD}` selector already could (`_booked_for` in `cli/src/bea_engine/importing.py`), provided each booked leg's lot agrees with the stated cost. Six shares sold at `{100 USD}` that FIFO booked as 5 + 1 across two 100 USD purchases are therefore matched: the import previews `possible_duplicate`, the default apply refuses (exit 4), `--duplicates skip` writes 0 and the ledger bytes are unchanged, matching the open-selector and single-purchase controls; a sale at another cost is not taken for it. Regression tests in `cli/tests/test_import_stated_cost_split_sale.py` fail without the fix (the split-lots case). Full suite green. Shipped in this commit (`cli`).

# Portable export collapses distinct symlink includes into an invalid, changed ledger

**Major · 45–60m, promote if alias planning needs more scope · cli · A1.**
Export exits 0 for a valid local ledger but produces a duplicate-include error
and a different transaction inventory. Preserve distinct include paths when
allocating portable files; do not deduplicate the source ledger's transactions.

Found 2026-10-08 at HEAD `20c2ba99`, checkout bea 0.3.1, Python 3.13.3,
macOS/Darwin. Real bounded subprocesses, closed stdin/no TTY, absolute isolated
config/cache and disabled update notifier. Two pristine symlink fixtures,
plus hard-link and ordinary-copy controls. No network, credentials or hosted
ledger changes needed; the price export command also exports plain ledgers.

## Minimal reproduction

In a disposable directory create `source/main.bean`:

```beancount
2026-01-01 open Assets:Cash USD
2026-01-01 open Equity:Opening USD
include "a.bean"
include "b.bean"
```

Create `source/tx.bean`:

```beancount
2026-02-01 * "Aliased deposit"
  Assets:Cash 1 USD
  Equity:Opening -1 USD
```

Create two different include names for that file and export:

```sh
ln -s tx.bean source/a.bean
ln -s tx.bean source/b.bean
bea --json --file "$PWD/source/main.bean" check
bea --json --file "$PWD/source/main.bean" query 'SELECT account, sum(position) GROUP BY account'
bea --json --file "$PWD/source/main.bean" price export --output "$PWD/output"
bea --json --file "$PWD/output/main.bean" check
bea --json --file "$PWD/output/main.bean" query 'SELECT account, sum(position) GROUP BY account' --allow-errors
```

Source check exits **0** with valid:true. The source query exits **0** with
Cash **2 USD** and Equity **-2 USD**: upstream loads the two distinct names.
Export exits **0**, but its files list repeats `output/tx.bean` twice. The
exported root rewrites both includes to `include "tx.bean"`.

The exported check exits **1**, empty stdout, JSON stderr naming
`Duplicate filename parsed: "/absolute/output/tx.bean"`. Querying that copy
with --allow-errors exposes Cash **1 USD** and Equity **-1 USD**, with the
duplicate-filename warning. Thus the successful export is both invalid and
different from its source. Original files and symlinks remain unchanged; this
is damage to the snapshot's semantics, not a claim of source data loss.

Repeated on a second pristine directory with identical results. A note-only
fixture also changes two valid source notes into an invalid single-file export.
Working controls: replace the two symlinks with hard links, or two regular
files holding identical text. Both sources and exports check successfully,
and both retain Cash 2 USD / Equity -2 USD. No --force or stale output is used.

Expected: a successful portable snapshot of a valid source remains valid and
retains its loaded directive inventory and balances. USAGE's Managed price
includes section describes export as a self-contained copy for stock tools;
the existing export tests and source comments require stock Beancount to check
the tree unchanged. A symlink can become a normal copied file, but distinct
include names cannot become repeated includes of one output file.

## Cause, repair and dedupe

`cli/src/bea_engine/managed_load.py:738–748` allocates included-file
destinations using `path.resolve().relative_to(home)`. Distinct `a.bean` and
`b.bean` both resolve to `tx.bean`, so two source keys get the same output
destination. The copy loop at 797–801 writes that destination twice;
`_rewrite_export_includes` at 899–922 points both includes at it. The returned
`files` list also repeats the path. Source canonicalization is appropriate for
containment/identity guards, but cannot decide include-path multiplicity.

Allocate a distinct safe portable destination for each source include path
that the loader treats separately, retaining lexical paths for contained
aliases where possible. Keep resolved identity for source/destination safety
and outside-tree checks. Do not fix this by merely deleting one duplicate
include: that still changes Cash 2 into Cash 1. Keep parent-relative external
includes inside the export and generated-feed collision avoidance intact.
Add real-command coverage comparing source and exported validity, transaction
counts and BQL inventories for the two aliases, hard links and regular files.
Run make check-all inside cli when implementing; no new dependency/API change.

Caller search: `bea price export` frontend -> engine `price_export` -> sole
`export_portable` producer. Default and explicit destinations share allocation.
Only file symlinks were reproduced; directory symlinks, external aliases,
managed feeds, attachments, recursive include graphs and other OSes remain
unverified. Preserve their existing safeguards when changing the planner.

Dedupe: full board search for export alias includes, collapsed paths and
duplicate filenames found no matching open work. Completed w1/044 concerns
document attachment symlink names, not included ledger files. w4/171 added
resolved allocation to stop parent-relative copies escaping the export;
`git log -S 'path.resolve().relative_to(home)'` traces it to `356d6c71`.
w4/172 protects aliases from overwriting source files; w3/413 separates local
prices from generated feeds. None addresses two distinct source keys mapping
to one output path. This is a missed collision case in the existing planner.

Acceptance: the two pristine symlink sources export without duplicate-filename
errors, with the same two loaded transactions and Cash 2 USD; physical output
paths are unique; hard-link/regular and existing containment controls remain
green. Never report success for a snapshot with this known semantic collapse.

Sanitized evidence: `cli/tmp/qa-20261008-cli/alias-tx-console.jsonl`,
`alias_export_repro.py`, `alias_export.py`, source/export fixtures and
`transcript.jsonl` with argv/cwd/environment, streams/exits and hashes. The
public repro is self-contained. No product fix was implemented.

---

**Resolved 2026-10-10** — when two source include paths resolve to one file, the export now gives each its own destination: the name the ledger spells when that stays inside the export, otherwise a numbered `_shared/` slot. The reported fixture exports `a.bean` and `b.bean` as two plain files, keeps both `include` lines, lists three unique paths, passes `bea check`, and reports Cash 2 USD like its source. Paths that do not collide are placed exactly as before, and resolved identity still decides containment, the source-alias guard and the outside-tree check. Shipped in `8e89dc16` (`cli`).

Real-command regression tests export five fixtures — two symlinks to one file, a symlink included beside its own target, the same file reached through a symlinked directory, hard links, and regular copies — and compare `bea check`, the balance query and the posting count between source and export, plus unique regular output files and an unchanged root text. The three symlink cases fail with the fix reverted; the hard-link and regular-copy controls pass either way. `make check-all` passed, including the existing containment, alias and feed-collision suites. An aliased include that itself carries `document` directives is refused by the existing attachment rule rather than exported; external aliases, managed feeds combined with aliases, and other platforms were not exercised.

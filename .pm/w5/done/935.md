# Reject reserved literal words in init's currency check

**Trivial · cli · 10–20m · A2.** `init --currency TRUE`, `FALSE` or `NULL`
passes the frontend's currency validation, then fails at exit 1 with syntax
errors against a ledger file that was never created. These are reserved
literal tokens, not commodity symbols. Reject them as invalid `--currency`
input at usage exit 2. Staging already preserves the filesystem; this is a
validation/diagnostic follow-up, not a data-loss claim. No product fix implemented.

Real CLI QA, 2026-10-21, HEAD `a67877fbd` (CLI unchanged after pulling
`709af935d`), checkout `bea 0.3.1`, macOS 26.5.1 arm64, frontend Python
3.13.3, existing managed Python 3.12.10. Separate subprocesses, closed
stdin/no TTY, isolated absolute `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`,
`BEA_NO_UPDATE_NOTIFIER=1`, no inherited `BEA_FILE`/`BEA_TOKEN`.

Create empty disposable `/abs/books`, then run from there:

```sh
bea --json --no-input init /abs/books/true.bean --currency TRUE --date 2024-01-01 --opening-balance "Assets:Cash 10.00"
bea --json --no-input init /abs/books/false.bean --currency FALSE --date 2024-01-01 --opening-balance "Assets:Cash 10.00"
bea --json --no-input init /abs/books/null.bean --currency NULL --date 2024-01-01 --opening-balance "Assets:Cash 10.00"
bea --json --no-input init /abs/books/true1.bean --currency TRUE1 --date 2024-01-01 --opening-balance "Assets:Cash 10.00"
bea --json -f /abs/books/true1.bean check
bea --json -f /abs/books/true1.bean report overview --time 2024-01 --conversion TRUE
```

Actual exits: **1, 1, 1, 0, 0, 2**. The first three emit empty stdout and
validation envelopes on stderr, for example:

```text
The change would leave the ledger invalid; nothing was written.
…/true.bean:6: syntax error, unexpected BOOL, expecting end of file or EOL
…/true.bean:22: syntax error, unexpected BOOL, expecting end of file or EOL or ATAT or AT
```

FALSE has the same BOOL error; NULL reports unexpected NONE. No rejected
file is created. In separate nested-target controls, even the new parent
directories are absent after refusal. TRUE1 creates a valid ledger and
passes fresh check. The last command is an existing correct control: report
conversion rejects TRUE immediately at exit 2 naming `--conversion`.

Expected: init should likewise name the invalid `--currency` and refuse at
usage exit 2, before generating a ledger or asking further questions. Keep
TRUE1/FALSE1/NULL1 and ordinary custom symbols valid; reject the exact reserved
words rather than their prefixes. Preserve trimming/uppercasing, single-letter
symbols, punctuation and the deliberate leading-slash exclusion.

Reproduction: eight initial fresh init journeys repeated TRUE/FALSE and
TRUE1/FALSE1. Twelve further fresh journeys, twice across all three reserved
words and their digit-suffixed controls, confirm init's wrong error category,
no rejected files/parents, valid control creation and check. Those journeys
also verify report conversion refuses each reserved word at exit 2 and
`add price` refuses it without writes; corresponding suffixed symbols accept
quotes and value the synthetic 100 USD holding at 200 target units.
The installed native lexer's actual output is BOOL/BOOL/NONE for the reserved
words and CURRENCY for all three suffixed controls. An initial report probe
expected the same loose validation there; its correct exit 2 disproved that
assumption, and fresh fixtures verified the working control before filing.

Cause: `cli/src/cli/commands/init.py:_CURRENCY_SYMBOL` (:53) checks only the
character shape. `_currency` (:56–60) therefore accepts these keywords.
Explicit options call it at :233 and the final selected/prompted value calls
it at :268, so both paths share the gap. `bea_engine/initiating.py` renders
that word on currency-limited opens and amount postings; its existing staged
validation catches the parser error and cleans up, producing validation exit
1. `bea_engine/report.py:_valid_conversion` (:47–65) already uses real native
token kinds and correctly excludes these words.

Fix: reject the three exact reserved literal words in the frontend init
currency check, retaining the frontend/engine dependency boundary. Keep staged
validation and cleanup as they are. Runtime coverage is explicit personal init;
interactive re-prompt behavior and other init templates are source-traced only.
No dependency, backend/API or currency-registry change needed.

Dedupe: searched all board states for reserved currency/literal keywords;
scanned 46 active/blocked milestone scopes with no matching repair. Completed
w5/693 (`0f078a517`) tightened this same check for trailing underscores after
w3/411's single-letter support. Its small-alphabet lexer comparison does not
contain TRUE/FALSE/NULL. Completed w5/184 handles unreadable bulk transaction
rows containing a keyword currency, not init's option validation. Targeted
currency-validator history contains no later keyword exclusion.

Acceptance: all three reserved words refuse with usage exit 2 naming
`--currency`, empty stdout and no new files/directories. Suffixed controls
still create ledgers that pass check; report/add-price refusals remain intact.
The six public commands were replayed twice. Only macOS/checkout tested;
repaired behavior unverified.

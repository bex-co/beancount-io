# Ghost PR read returns INTERNAL instead of NOT_FOUND on every surface

**Severity:** medium. **Journey:** resources. **Owner:** backend-v2. Found by the MCP QA auth sweep on 2026-10-03 against production; live at repo HEAD `75819075`. No live board dupe.

Target: `https://beancount.io`, `POST /api-gateway/mcp` (production), observed 2026-10-03.
serverInfo `{"name":"beancount-mcp","version":"1.0.0"}`, protocolVersion `2025-11-25`.
Credential: `bcio_` API key (server kind `apikey`), scopes `ledger.read ledger.write ledger.admin`, ledger pin none (unpinned), no expiry. Value never recorded.
Helper: `node .agents/skills/qa-shared/scripts/qa-mcp.mjs --credentials-file muse.env` from repo root.

## Repro (synthetic coords `qa-owner/qa-book`)

```sh
read beancount://qa-owner/qa-book/pull-request?prNumber=99999
```

JSON-RPC sent:

```json
{"jsonrpc":"2.0","method":"resources/read","params":{"uri":"beancount://qa-owner/qa-book/pull-request?prNumber=99999"},"id":1}
```

Observed: -32000 `Failed to fetch PR details: Unknown error`: ghost PR as INTERNAL.

## Control

Shared service throws plain Error so REST 500s identically (structural; REST transcript not in bundle).

## Cause

- `backend-cluster/backend-v2/src/features/gitea/pull-request/service/pull-request-service.ts`

`getPRDetails` catches everything into a plain Error (:344-350); the Gitea client's 404 arrives without an Error message, so the `?? "Unknown error"` fallback fires and the envelope classifies INTERNAL. Separate throw site from the approve-ghost gap (read vs review).

## Fix (parity: MCP+REST+GraphQL)

Owning package `backend-cluster/backend-v2`; the fix must land on every eligible surface (MCP+REST+GraphQL) in the same change. Translate 404 -> NOT_FOUND on the PR read path, all surfaces.

## Evidence

`.tmp/qa-2026-10-03-auth/r2-reads-resources/u40-pr-ghost.txt` (gitignored bundle `.tmp/qa-2026-10-03-auth/`); finding brief `.tmp/qa-2026-10-03-auth/final/resources-pr-ghost-internal.md`.

---

**Resolved 2026-10-03** — reading a pull request number that does not exist is now answered `NOT_FOUND` naming the number on REST (404), GraphQL and the MCP resource (`-32002`). The service maps the upstream 404 — which the generated client throws as the response itself, with no error message — instead of wrapping it as "Unknown error"; any other upstream failure stays internal with a fixed message. Shipped in `a4caee9d` (`backend-cluster/backend-v2`).

A regression test reads the pull request through HTTP REST, GraphQL execution and an MCP client with the thrown 404; it fails with the fix reverted. The approve and reject paths are a separate throw site, tracked in [038](./038.md). Not re-run against the hosted endpoint: the fix reaches it with the next deploy.

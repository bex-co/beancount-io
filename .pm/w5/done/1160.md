# Version History sheet opens with focus on the off-screen "Load older commits", so the next Enter loads 30 more commits instead of choosing one

**Severity:** minor (keyboard access; WCAG 2.4.3 Focus Order, 2.4.11 Focus Not Obscured). **Owner:** dashboard. **Estimate:** 20–30 minutes including a rendered test. **A2:** below 1280px the commit list lives in a **Version History** sheet. A keyboard user who opens it expects to land on the list they see. Instead focus sits on a button about 1,900px below the visible area. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-18 against `https://beancount.io` (entry chunk `main-LGv2TZLj.js`), headless Chromium 153 at 390×844 and 1024×768, English/light. QA owner account on the synthetic `<qa-owner>/mcp-agent-eval` ledger, read-only. Local HEAD `a858bdff9`.

## Repro

1. At 1024×768 or 390×844, open `/ledger/<owner>/<ledger>/commits` on a ledger with more than 30 commits. It opens the latest commit.
2. Focus **Version History** and press Enter. The sheet opens scrolled to the top, showing the current commit (`aria-current="page"`) and the next ones.
3. `document.activeElement` is **Load older commits**, the last control in the sheet. Its box is at y≈1921 in a 768px viewport, so no focus ring is visible.
4. Press Enter. The list grows from 30 to 60 commits ("Loaded 30 older commits"). The reader meant to pick a commit, or had not acted yet.

Same at 390×844. Repeated from fresh loads. Choosing a commit with the keyboard otherwise works. It navigates, closes the sheet and returns focus to **Version History**, and Escape does the same.

## Cause

`dashboard/src/features/git/commits/components/commits-split-view.tsx:265-278` renders `<SheetContent>` with no `onOpenAutoFocus`. Radix's FocusScope (`@radix-ui/react-focus-scope` 1.1.7) moves focus on open to the first tabbable element **after removing links** (`focusFirst(removeLinks(getTabbableCandidates(container)))`). Every commit row is a link (`commit-list-item.tsx`), so the first non-link is the `ContinuationControl` button at the end of the list (`commits-list.tsx:117-137`). With 30 commits or fewer there is no continuation button, so by the same rule focus lands on Close (source-traced, not run).

## Fix

In the sheet's `onOpenAutoFocus`, prevent the default and focus the selected commit's link (`aria-current="page"`), scrolling it into view. Fall back to the first commit link, and to the sheet's Close button when the list is empty. Leave the desktop sidebar list, the continuation control's own focus handling (w4/246) and the close-on-select focus return unchanged.

## Definition of done

- At 1024 and 390 widths, opening Version History with the keyboard focuses the current commit's link, and that link is visible inside the sheet.
- When the current commit is outside the loaded history, focus goes to the first commit link.
- Enter right after opening opens the focused commit. It does not load older commits.
- A rendered test opens the sheet with more than one page of history and asserts the focused element. It fails on the current code. Dashboard gates pass.

## Dedupe

Searched `.pm/**`, including `done/`, for Version History, Load older commits, `commits-split-view`, `onOpenAutoFocus` and sheet focus. w3/done/468 added paging, w4/done/246 keeps loaded pages and focus while selecting, w4/done/1095 fixes the cursor after Refresh, and w4/done/1043 the failed first read. None covers where focus goes when the sheet opens. Present at HEAD.

# Allow instrument units in the portfolio preset's holdings account

**Minor · cli · 25–40m · A1/A2.** A fresh `portfolio@1` ledger rejects
its advertised first share purchase because init opens `Assets:Holdings`
only for the operating currency. The cash account works; no invalid trade
is written. No product fix implemented.

Real CLI QA, 2026-10-21, HEAD `adde31132` (CLI unchanged from `3b555391d`),
checkout `bea 0.3.1`, macOS 26.5.1 arm64, frontend Python 3.13.3, managed
Python 3.12.10 / Beancount 3.2.3. Fresh bounded subprocesses, closed
stdin/no TTY, isolated absolute `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier
disabled, inherited `BEA_FILE`/`BEA_TOKEN` removed. Synthetic local books.

From a disposable `/abs/books` directory, run:

```sh
bea --no-input init portfolio --preset portfolio@1 --currency USD --date 2026-08-01 --opening-balance 'Assets:BrokerCash 1000'
bea --json --no-input -f /abs/books/portfolio/main.bean add transaction --date 2026-08-02 --narration 'Buy shares' -p 'Assets:Holdings 10 HOOL {20 USD}' -p 'Expenses:Fees 2 USD' -p 'Assets:BrokerCash -202 USD'
bea --json -f /abs/books/portfolio/main.bean check
bea --json -f /abs/books/portfolio/main.bean query 'SELECT account,sum(number) GROUP BY account ORDER BY account'
```

Init exits **0**, and the untouched file passes check. The purchase exits
**1** with `Invalid currency HOOL for account 'Assets:Holdings'` and
`nothing was written`. The ledger stays byte-identical, holdings are absent,
and broker cash stays 1,000 USD. Human add has the same refusal. The generated
line is `2026-07-31 open Assets:Holdings USD`.

Expected: the portfolio preset supports its first ordinary instrument
purchase. The [catalog](../../cli/src/bea_engine/setup_catalog.json)
explicitly expects buying 10 units at 20 plus a separately recorded fee of
2 to leave 10 holding units and a cash outflow of 202. [PRFAQ001 A.4](../../docs/prfaqs/PRFAQ001-ledger-creation.md#a4-investment-portfolio)
names stocks, funds, crypto and different currencies. [ADR021](../../docs/adrs/ADR021-backend-v2-ledger-creation-experience.md#supported-currencies-and-region-mapping)
also says the operating currency does not prohibit other currencies.

Working control: remove only the currency restriction from the generated
holdings open; keep broker cash and fees restricted to USD. This is a
disposable-file control, not a proposed manual step for new users:

```python
from pathlib import Path
ledger = Path('/abs/books/portfolio/main.bean')
ledger.write_text(ledger.read_text().replace(
    'open Assets:Holdings USD', 'open Assets:Holdings'))
```

```sh
bea --json --no-input -f /abs/books/portfolio/main.bean add transaction --date 2026-08-02 --narration 'Buy shares' -p 'Assets:Holdings 10 HOOL {20 USD}' -p 'Expenses:Fees 2 USD' -p 'Assets:BrokerCash -202 USD'
bea --json -f /abs/books/portfolio/main.bean check
bea --json -f /abs/books/portfolio/main.bean query 'SELECT account,sum(number) GROUP BY account ORDER BY account'
bea --json -f /abs/books/portfolio/main.bean report overview --time 2026-08 --conversion at_cost
```

All control commands exit **0**: holdings 10 HOOL, cash 798 USD, fees 2 USD,
net worth at cost 998 USD. Native Beancount independently rejects the same
trade appended to the original restricted file, so this is generated setup
data, not an add-command parser defect.

Reproduced twice for **USD and EUR**, both with and without a known opening
cash balance, in eight fresh books. Correcting only the holdings open makes
all eight purchases/checks pass. With a subsequent HOOL price of 22, the
funded controls show net worth 998 at cost / 1,018 at value in the operating
currency; unfunded controls show −2 / 18. All sixteen report totals match
independent arithmetic. Personal cash purchases, rental rent/deposit receipts
and community contributions pass twice with their original preset opens.

Cause: `cli/src/bea_engine/initiating.py:answer_preset` derives every preset
account from the catalog, then emits `open {account} {currency}` for each
one (:243–244), including `Assets:Holdings`. That account's kind is `other`,
and it is intended to hold instrument units, rather than only USD/EUR cash.
The sole direct caller is `bea_engine/main.py`'s init handler (:502), reached
by `cli/commands/init.py`. Legacy init uses the separate `answer` builder.

Fix: generate a holdings open that permits instrument commodities while
keeping cash/fee constraints and opening-balance dates/amounts correct.
Do not disable validation, relabel HOOL as USD, or require a child account
to bypass an unusable advertised account. Preserve the versioned catalog
and package boundaries; this is a local CLI builder repair, with no new
dependency or API change required for the reproduced failure.

Dedupe: searched all board states for portfolio presets, holdings opens,
preset currency restrictions and first purchases, and reviewed active setup
milestone scopes. Completed w3/m53/t004 (`1ba20bffa`) added this loop;
targeted `git log -S` and later initiating history find no repair. Its tests
cover personal openings rather than the portfolio acceptance purchase.
Open [877](./877.md) concerns summary count/date, [878](./878.md) currency
prompt validation and [876](./876.md) zero input. W23/048 is the separate
hosted builder's duplicate equity opens/validation and mixed-currency
opening counter account; it does not cover this first-purchase restriction.
W4/316 is dashboard stale preset selection. No overlapping local repair found.

Acceptance: fresh portfolio setup supports the public purchase above in USD
and EUR, with/without initial cash; quantities, basis, fees and cash match
the independent results and native validation passes. Other presets and
legacy init retain their existing behavior. Windows/Linux and hosted setup
were not exercised. Sanitized local evidence: ignored QA pass19
`probe_preset_first_transactions.py`, `preset-first-transactions-results.json`,
`controls_portfolio_preset_holdings.py`, `portfolio-preset-holdings-controls.json`,
and corresponding command captures. The public repro is self-contained.

**Resolved 2026-10-22** — fixed: `answer_preset` (`cli/src/bea_engine/initiating.py`) now opens the portfolio preset's `Assets:Holdings` without a currency restriction (`_INSTRUMENT_ACCOUNTS`) because it holds instrument units, so the preset's own first purchase (`10 HOOL {20 USD}` with a fee against broker cash) writes, checks and leaves 10 HOOL, in USD and EUR, funded and unfunded. Broker cash, fees and every other preset account keep the operating-currency restriction, and the opening-balance postings are unchanged. Regression tests in `cli/tests/test_init_portfolio_holdings.py` fail without the fix. Shipped in this commit (`cli`).

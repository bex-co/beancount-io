# Keep opposite-direction source legs distinct in native import matching

**Major · cli · 35–50m · A1.** A one-share sale under an existing native ID
is silently accepted as an exact duplicate of a sale of two shares plus a
purchase of one. Both net to −1, but their gross source movements and lot
basis differ. Apply exits 0 / writes 0 rather than raising the native-ID
source-amount conflict; the ledger retains basis 150 / realized profit 100
while the changed statement books validly from the same starting ledger at
basis 100 / profit 50. No product fix implemented.

Real local CLI QA 2026-10-22 at `9b513aede`, public recipe rechecked on
`47c043676`, `bea 0.3.1`, macOS 26.5.1 arm64,
frontend Python 3.13.3, managed Python 3.12.10 / Beancount 3.2.3. Reproduced
twice in pristine synthetic books using bounded real subprocesses, closed
stdin/no TTY and isolated configuration/cache paths. No plugin, filter,
transfer, generated-ID compatibility or shared/reused reference is involved.

Run this complete recipe with `bea` on PATH and a fresh absolute directory in
place of `/abs/case`. It first records a valid composite trade under T1, then
imports a different, independently valid single-sale source also under T1.
Source quantities, currencies, prices and all counter amounts are explicit.
The sale's `{USD}` intentionally leaves lot selection open, as the import
contract supports.

```python
from pathlib import Path
import json, os, subprocess
from decimal import Decimal

case = Path('/abs/case')
stated_cost = False
different_buy_quote = False
unchanged_original = False
genuine_split = False
case.mkdir(parents=True, exist_ok=False)
ledger = case / 'main.bean'
fresh = case / 'fresh.bean'
base = 'option "operating_currency" "USD"\n2024-01-01 open Assets:Stock HOOL "FIFO"\n2024-01-01 open Assets:Cash USD\n2024-01-01 open Equity:Opening USD\n2024-01-01 open Income:Gains USD\n2024-01-01 * "Capital"\n  Assets:Cash 1000 USD\n  Equity:Opening -1000 USD\n'
if genuine_split:
    for day, quantity in [(2, '0.5'), (3, '0.5'), (4, '1')]:
        base += (f'2024-01-{day:02d} * "Buy {day}"\n'
                 f'  Assets:Stock {quantity} HOOL {{100 USD, 2024-01-{day:02d}, "L{day}"}}\n'
                 f'  Assets:Cash {-Decimal(quantity)*100} USD\n')
    original = ('2024-02-01 * "Source trade"\n  bank_id: "T1"\n'
                '  Assets:Stock -1 HOOL {USD} @ 150 USD\n'
                '  Assets:Cash 150 USD\n  Income:Gains -50 USD\n')
    incoming = original
else:
    base += ('2024-01-02 * "Buy old"\n'
             '  Assets:Stock 2 HOOL {100 USD, 2024-01-02, "Old"}\n'
             '  Assets:Cash -200 USD\n')
    quote = 140 if different_buy_quote else 150
    original = ('2024-02-01 * "Source trade"\n  bank_id: "T1"\n'
                '  Assets:Stock -2 HOOL {100 USD, 2024-01-02, "Old"} @ 150 USD\n'
                + f'  Assets:Stock 1 HOOL {{{quote} USD, 2024-02-01, "New"}} @ {quote} USD\n'
                  f'  Assets:Cash {300-quote} USD\n  Income:Gains -100 USD\n')
    cost = '100 USD' if stated_cost else 'USD'
    incoming = ('2024-02-01 * "Source trade"\n  bank_id: "T1"\n'
                + f'  Assets:Stock -1 HOOL {{{cost}}} @ 150 USD\n'
                  '  Assets:Cash 150 USD\n  Income:Gains -50 USD\n')
    if unchanged_original:
        incoming = original
original_text = base + original
ledger.write_text(original_text)
fresh.write_text(base)
statement = case / 'trade.statement'
statement.write_text(incoming)
config = case / 'importer.py'
config.write_text('from beancount.parser import parser\nclass Broker:\n    name = "broker"\n    def identify(self, file): return str(file).endswith(".statement")\n    def account(self, file): return "Assets:Stock"\n    def extract(self, file, existing_entries=None):\n        entries, errors, _ = parser.parse_file(str(file))\n        assert not errors, errors\n        return entries\nCONFIG = [Broker()]\n')
env = os.environ.copy()
for key in ('BEA_FILE', 'BEA_TOKEN', 'BEANCOUNT_LOAD_CACHE_FILENAME',
            'BEA_ENGINE_PYTHON', 'BEA_ENGINE_DIR'):
    env.pop(key, None)
env.update(BEA_CONFIG_DIR=str(case / 'config'), XDG_CACHE_HOME=str(case / 'cache'),
           BEA_NO_UPDATE_NOTIFIER='1')
def run(tag, args, file=ledger, json_mode=True):
    argv = ['bea', *(['--json'] if json_mode else []), '--no-input', '-f', str(file), *map(str, args)]
    result = subprocess.run(argv, cwd=case, env=env, stdin=subprocess.DEVNULL,
                            capture_output=True, text=True, timeout=25)
    assert ledger.read_text() == original_text
    print(json.dumps(dict(tag=tag, args=argv, exit=result.returncode,
                         stdout=result.stdout, stderr=result.stderr)), flush=True)
args = ['import', statement, '--config', config]
report = ['report', 'balance-sheet', '--time', '2024-02', '--conversion', 'at_cost']
run('baseline', ['check'])
run('preview', args)
run('apply', [*args, '--apply'])
run('facts', ['query', 'SELECT account,sum(number) GROUP BY account ORDER BY account'])
run('original-report', report)
run('check-original', ['check'])
run('fresh-apply', [*args, '--apply'], file=fresh)
run('fresh-report', report, file=fresh)
run('fresh-check', ['check'], file=fresh)
```

Actual: all nine commands exit 0 with JSON stdout / empty stderr. Preview
incorrectly reports `ready: 0, duplicates: 1, conflicts: 0`; its match visibly
contains source postings **−2 HOOL and +1 HOOL**, while the incoming row has
only **−1 HOOL**. Apply writes **0** and leaves the original file unchanged.
Original facts are Stock 1 / Cash 950 / Equity −1000 / Gains −100; the cost
balance sheet shows Stock **150 USD**, profit **100**, net worth **1100**.
The same incoming row applied to `fresh.bean` writes 1, passes check and
reports Stock **100 USD**, profit **50**, net worth **1050**, with the same
one remaining share and cash 950. Both states are balanced; no invalid
fixture or failure to book the statement explains the false exact match.

Expected: changing gross source legs from a two-share disposal plus a
one-share acquisition to a single one-share disposal is not merely booking
that one disposal into held lots. The native-ID source comparison must
require review / conflict (exit 4, no write), preserving the existing ledger
until the user reconciles the changed source. Do not append or automatically
replace it. IMPORTING's stable-ID rule compares source amounts, allowing
counter-account and descriptive cleanup; it does not make a purchase into a
negative sale fill simply because their signed sum matches.

Controls, twice each, with fresh valid source imports too: set
`stated_cost = True` and the incoming `{100 USD}` correctly conflicts; set
`different_buy_quote = True` and the original +1 at 140 is excluded from the
150-price pool, again correctly conflicting. `unchanged_original = True`
reimports the original two-legged trade exactly and correctly skips.
`genuine_split = True` creates two half-share lots plus one whole-share lot;
a real one-share FIFO sale books as −0.5 / −0.5, and reimport correctly skips.
Keep this legitimate same-direction split. JSON and human apply variants
cover the failing case and both conflict controls; the normal config notice
on human stderr is retained. Every refused or skipped original apply is
byte-preserving.

Root cause: `cli/src/bea_engine/importing.py:_booked_for` (:1543–1567 at the
initial HEAD) filters compatible booked legs by cost, child account,
commodity and price, then only checks whether a subset's **signed sum**
equals the incoming quantity. It never requires each member to move in the
incoming fill's direction. The actual helper proof yields `{0,1}` for −1
from **−2 and +1** and `_legs_agree` returns true. A FIFO reduction cannot
produce that positive acquisition as one of its booked disposal fills.
`_same_row` consequently calls this native bank-ID hit identical. The genuine
split proof yields two negative halves, with no opposite-direction member.

Independent unwrapped Beancount inventories confirm the held lot is
`New +1 {150 USD, 2024-02-01}` in the original, versus
`Old +1 {100 USD, 2024-01-02}` after applying the incoming single sale to the
pristine base. Their cash is equal; their basis and realized gain are not.
All ten profile inputs also apply successfully through the real CLI against
fresh bases; none needs inference of a source quantity, quote or currency.

Fix: distinguish a genuine split fill from netting opposing buy/sell legs.
Any group standing for this negative source fill must contain only compatible
legs moving in its direction and must preserve their one-to-one ownership;
keep stated lot/price/child constraints. Do not repair this by disallowing
open sale selectors or by booking a reimport against the inventory left after
the original trade. Preserve native source-change conflicts and exact
unchanged/same-direction split reimports. No dependency or API change.

Caller search: `_legs_agree` also feeds nearest native history, lot-gated
legacy claims, possible twins and transfer matching. The reproduced claim
here is the one-owner exact native-ID path; those other consumers remain
unverified for this direction issue. Dedupe covered all board states and
open milestone scopes. Closed 603 introduced split-lot summation, and closed
896 (`4c00e148b`) retained that sum while adding one-to-one subset search;
neither checks direction. Open 977 rejects valid subsets above twelve;
this case has two legs and is a false positive, so changing its cutoff does
not fix it. Open 978's known-cost early return causes a false negative;
this incoming cost number is deliberately open. Open 950 concerns inferred
cost/price components, while this is a supported sale selector and fully
explicit units/price/currency. Preserve its selector controls. Open 974 and
973 concern missing native ownership, not a found owner incorrectly proved
equal. No overlapping open repair or later direction fix was found.

Acceptance: the published changed single sale conflicts / apply 4 without
rewriting the original; its fresh-base import remains valid at cost 100 /
gain 50. Keep explicit-cost and different-price conflicts, unchanged-gross
skip and the legitimate two-half-share split. Add real native import

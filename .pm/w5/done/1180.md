# Settings → Change Name and Change Username throw away what was typed on Escape, an outside click or Cancel, without asking (gap in w2/134)

**Severity:** minor. **Owner:** dashboard. **Estimate:** 25–35 minutes including tests. **A2:** `dashboard/AGENTS.md` makes it the rule that every idle dialog holding typed input asks "Discard what you typed?" before Close, Escape, an outside click or Cancel discards it. w2/123 and w2/done/134 applied that rule to New Entry, Add Budget, Create and Edit Ledger, Open Account and the SSH and API key dialogs. The two profile dialogs in Settings → General were not in either list and still close silently. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-18 against `https://beancount.io` (entry chunk `main-LGv2TZLj.js`), headless Chromium at 1440×1000, English, isolated profile, signed in as the QA owner. Local HEAD `c12e43044`. Nothing was saved: a request guard aborted any GraphQL mutation (it caught none during this check), and the profile still read "Name: Not set", "Username" unchanged.

## Repro

1. Open `/settings/general` and press **Edit** beside Name. In "Change Name", type `qa-20261118-draft` in First Name and press Escape.
2. **Actual:** the dialog closes at once, with no dialog or alert dialog left open. Pressing Edit again shows an empty First Name, so the typed text is gone.
3. Press **Edit** beside Username. Replace the value with `qa-20261118-draft` and press Escape. **Actual:** it closes at once, and reopening shows the old username.
4. Control (from the code; production still serves the build before w2/134): Open Account and the key dialogs on `main` route dismissals through `useDiscardDraftGuard`.

**Expected:** after typing, Escape, the close button, an outside click and Cancel each ask "Discard what you typed?". **Keep editing** keeps the values and returns focus to the field. **Discard** closes. An untouched dialog, or one whose fields were set back to their initial values, closes at once. A successful save closes directly. Escape during a pending save already does nothing (`busy`), and that stays.

## Cause

`dashboard/src/features/user-settings/pages/general/user-profile-section.tsx`: the Name dialog passes `onOpenChange={setIsNameDialogOpen}` (`:181`) and its Cancel calls `setIsNameDialogOpen(false)` (`:249`). The Username dialog does the same at `:274` and `:340`. Neither uses `useDiscardDraftGuard` (`common/components/discard-draft-guard.tsx:21`). The fields are plain `useState` rather than react-hook-form, so the dirty state has to be derived: the typed values differ from the profile values that were loaded into them when the dialog opened (`:185-188`, `:279-284`). The file last changed in `8a6067001` (2026-10-22), so production matches `main`.

## Fix

Owned by `dashboard`. In each dialog, compute `dirty` as typed ≠ opening value, call `useDiscardDraftGuard(dirty)`, route `onOpenChange(false)` and Cancel through `requestLeave(() => setIs…DialogOpen(false))`, and render `confirmation` inside the dialog, as `open-account-dialog.tsx:133` does. Keep the IME Enter handling (w4/296) and the pending-save behaviour (w4/m47).

## Definition of done

- In both dialogs, after typing, each of Escape, Close, Cancel and an outside click asks. Keep editing keeps the typed value and focus. Discard closes. Untouched and reverted dialogs close at once. A successful save closes without asking.
- A test mirroring `open-account-discard-draft.test.tsx` covers both dialogs and fails on the current code. Dashboard gates pass.

## Dedupe

Searched `.pm/**`, including `done/` and `blocked/`, for `useDiscardDraftGuard`, "Discard what you typed", "Change Name", "Change Username", `changeName` and `user-profile-section`. w2/done/134's table lists four dialogs plus Edit Ledger Settings. w4/done/296 (IME Enter) and w4/m47 (saves held to their dialog session) cover other behaviour of these dialogs. Other dialogs with inputs and no guard, such as the danger-zone confirmations and the visibility section, take a typed confirmation phrase rather than a draft and are out of scope.

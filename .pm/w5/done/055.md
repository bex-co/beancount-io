# Init prints an unusable next command for custom ledger filenames under home

**Minor · 20–30m · cli · A2 — Frictionless onboarding.** The first suggested
check fails immediately after a successful init. Repair the hint and cover its
actual shell execution; no accounting change is needed.

Found 2026-10-08 at HEAD `ada649f70165be958f6e7c35d3d2309b80a485f6`, checkout
`bea 0.3.1`, Python 3.13.3, macOS/Darwin. Fresh real subprocesses, closed stdin,
no TTY, isolated absolute BEA_CONFIG_DIR and XDG_CACHE_HOME, update notifier
disabled, inherited BEA_FILE/BEA_TOKEN removed. Local synthetic ledgers only.

## Reproduce

Use a checkout beneath your home directory, with bea on PATH. From `cli/`:

```sh
mkdir -p tmp/qa-init-hint
bea --no-input init "$PWD/tmp/qa-init-hint/custom.bean" --currency USD --date 2026-01-01
```

The init exits **0**, creates a valid ledger, and prints a next command like:

```sh
bea --file '~/projects/beancount-io/cli/tmp/qa-init-hint/custom.bean' check
```

Copy and execute the exact printed `Next:` command. It exits **2**, stdout is
empty, and stderr says `Error: No ledger file at '~/projects/…/custom.bean'
(from --file)`. The shell leaves the quoted tilde literal, and ledger target
resolution does not expand it. Checking with the original absolute filename
exits **0**. The check attempts leave ledger contents unchanged.

Repeated with pristine `custom-b.beancount`, `custom repeat 空白.bean`, and
`main.beancount` fixtures. Both `/bin/zsh -c` and `/bin/bash -c` fail on the
printed hints. A `regular/main.bean` control prints `cd ~/…/regular && bea
check`, and executing that exact hint succeeds. Directory init and the
created ledger itself work; this finding concerns the custom-file hint.

Expected: the advertised next command checks the file just created, including
home-relative paths and filenames with spaces/Unicode. USAGE's Creating a
ledger section supports both directories and `.bean`/`.beancount` paths.

## Cause, fix, scope and dedupe

`cli/src/cli/commands/init.py:171–183` shortens home paths to `~/…`, then calls
`shlex.quote(shown)` in the custom-file branch. That quotes the tilde along
with the suffix. The sibling main.bean branch explicitly preserves the tilde
outside its quoted suffix, which explains the working control.

Print a safely quoted absolute path for the custom-file branch, or preserve
tilde expansion while safely quoting its suffix as the directory branch does.
Execute the resulting hint in real shell regression coverage for ordinary and
space/Unicode custom names, both suffixes, and main.bean controls. Check that
successful validation preserves the created file. Scope: cli only; init's
human success output through positional file paths and global --file. JSON
init has no hint. No dependencies or backend/API changes are needed.

Caller search found the sole hint producer in init.py. Board searches across
all queues including done/blocked found no matching open item. Completed
w1/m15/t005 introduced the home-relative hint but its acceptance only covered
directory init; it did not verify this custom-file branch. `git log -S
'shlex.quote(shown)'` traces the code to `79553f2c`; current history has no
repair. This is a missed branch in that completed work, not deployment lag.

Acceptance: executing the exact emitted Next command checks the newly created
ledger successfully for all reproduced custom-file cases, while directory
init still provides a working command. Invalid/existing targets keep their
current refusal behavior.

Sanitized local evidence retained in `cli/tmp/qa-20261008-cli/`:
`init-hint-console.jsonl`, `init-hint-repeat.jsonl`, and `transcript.jsonl`, with
pristine synthetic files and source hashes. Public reproduction above requires
none of those ignored files. No credentials, servers, or product fixes used.
Other platforms and interactive init remain unverified.

Both hint branches share one quoting helper, which also repairs `cd '~' && bea check` for a `main.bean` created directly in the home directory from another working directory. Shipped in `04c8f45f` (`cli`).

The regression test creates each ledger under a throwaway home, then executes the exact printed `Next:` line with `sh -c`, `bash -c` and `zsh -c`: ordinary, space/Unicode and quote-bearing custom names, both suffixes, a file directly in home, `main.bean` controls, and a path outside home.

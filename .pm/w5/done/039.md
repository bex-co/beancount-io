**Resolved 2026-10-03** — an argument an MCP tool does not declare is now refused as `BAD_USER_INPUT` naming it, before the tool runs, so a misspelt `dry_run` can no longer fall back to the default and commit. Shipped in `b56d794c` (`backend-cluster/backend-v2`).

The fix differs from the one proposed. Rather than adding `.strict()` to the three named schemas, the `tools/call` boundary refuses unknown top-level arguments for every tool whose schema would otherwise strip them: the gap was wider than three tools, and publishing `additionalProperties: false` on each schema does not fit the 64 KB `tools/list` budget, which is within a few dozen bytes of its limit. So `tools/list` does not advertise the strictness; the refusal names the argument. `manageApiKeys` is left deliberately loose — it folds deprecated spellings and refuses unknowns itself. Only top-level arguments are covered; a nested object's unknown key is still dropped.

Tests send `dryrun`, `dryRun` and an unknown key to `editLedgerFiles` and an unknown key to the read, list and both bank tools through an MCP client, and assert nothing is committed or read; all fail with the fix reverted. No live typo-commit was run, as in the note. Not re-run against the hosted endpoint: the fix reaches it with the next deploy.

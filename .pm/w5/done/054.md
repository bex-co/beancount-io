---

**Resolved 2026-10-03** — a blank temp-asset key is now refused as `BAD_USER_INPUT` naming the argument, with a hint describing what a key looks like, instead of an authorization refusal with a hint about ledger permission. The check sits in the four services that take such a key — receipt parse, file parse, receipt insert and the temp-asset download URL — so REST, GraphQL and MCP answer alike, before authorization runs. Shipped in `693d113f` (`backend-cluster/backend-v2`).

Regression tests send an empty key through HTTP REST, GraphQL execution and an MCP client for receipt parse, receipt insert and the download URL; they fail with the service checks removed. File parse shares the same check and is covered by the unit test of the check itself rather than its own adapter test. A non-blank key that is not the caller's is still decided by the ownership check, unchanged. Not re-run against the hosted endpoint: the fix reaches it with the next deploy.

# Budget "Update Budget" keeps Currency editable, so updating a USD card silently starts a second budget in another currency

**Severity:** minor. **Owner:** dashboard. **Estimate:** 30–45 minutes. **A2:** a reader who updates a budget expects the card they clicked to change. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-15 against `https://beancount.io` (local HEAD `ae0e4c7ba`; the code below is unchanged at HEAD, so this is not deployment lag), headless Chromium at 1440×1000, signed in as the QA account, on the designated disposable ledger (restored byte-for-byte afterwards). Dashboard counterpart of mobile's fixed w21/121.

## Repro

1. On `/ledger/<owner>/<ledger>/budget`, Add Budget: 2026-07-01, `Expenses:Food:Coffee`, Monthly, 25 USD. One card appears: `Expenses:Food:Coffee · Monthly · USD`, Current budget 25.00 USD.
2. On that card, activate **Update budget for Expenses:Food:Coffee (USD)**. The dialog locks Account (a disabled textbox), but **Currency** is an enabled combobox showing USD.
3. Enter 2026-08-01, 30, change Currency to `EUR`, submit.

**Actual:** the write succeeds and the page shows **two** cards, `Expenses:Food:Coffee · EUR` (30.00 EUR, history row 2026-08-01) and the original `Expenses:Food:Coffee · USD`, still 25.00 USD with only its 2026-07-01 row. Nothing tells the reader that "Update" started a new budget; the card they updated is unchanged. The EUR budget is also written for an account opened as `USD` only, without a warning.

**Expected:** Update Budget appends a dated target to the card it was opened from. Its currency is part of that card's identity (`budget-chart-card.tsx` groups by account + currency, and its Update button's accessible name already says "(USD)"), so it is shown but not editable, the same way the account is. A reader who wants a budget in another currency uses the header's Add Budget.

## Root cause

`dashboard/src/features/ledger-data/budget/budget-chart-card.tsx` (the `<AddBudgetDialog … lockedAccount={group.account} defaultInterval={currentInterval} defaultCurrency={displayCurrency}>` call, around line 414) locks the account but passes the currency only as a default. `add-budget-dialog.tsx` has `lockedAccount` and `lockedInterval` props, but no currency lock: its `currency` field always renders an editable `CurrencyCombobox`.

## Fix

In `add-budget-dialog.tsx`, add a `lockedCurrency` prop that seeds the form value and renders the currency as a disabled input (as `lockedAccount` does), and pass `lockedCurrency={group.currency}` from the card. Keep the header Add Budget dialog fully editable. Keep the interval editable on Update: a newer directive may change cadence (`budgetAccountHelp`).

## Acceptance

- In the repro, the Update dialog shows Currency `USD` and does not let it change; submitting adds a 2026-08-01 row to the USD card, and no EUR card appears.
- The header **Add Budget** dialog still lets the reader pick any currency.
- A dashboard test opens Update on a non-operating-currency card (e.g. EUR when the operating currency is USD), asserts the currency stays EUR and cannot be edited, and asserts the submitted directive's currency. It fails against the current code.

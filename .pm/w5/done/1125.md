# Give update commands a supported recovery from incomplete root discovery

**Major · cli · 45–60m · A1/A2 · worker1.** In a crowded Git workspace,
`update transaction` and `update transactions` refuse incomplete root
discovery and recommend `--into`, but neither command accepts that option.
Even an explicitly selected, self-contained root cannot be updated through
the CLI. The bounded refusal is correct; the advertised recovery is missing.
No code fix implemented.

Environment: 2026-11-07, checkout bea 0.3.1, Python 3.12.10, macOS 26.5.1
arm64; CLI sources unchanged from `74a0b8cbe` (current `76471fe1b` changes
only the board). Existing managed engine with checkout helper sources.
Fresh subprocesses, 25s timeouts, closed stdin/no TTY, offline, absolute file,
isolated child config/cache, notifier off, no inherited `BEA_FILE`/`BEA_TOKEN`;
HOME unchanged. Two independent crowded fixtures and a zero-noise control.

## Reproduce

Create a new disposable directory, initialize its own Git repository with
`git init --quiet`, and save this `main.bean` there:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:Food USD
2026-01-02 * "Original"
  ref: "Q1"
  Expenses:Food 10.00 USD
  Assets:Cash -10.00 USD
```

Populate the same directory with unrelated non-ledger files:

```python
from pathlib import Path
for i in range(8300):
    Path(f"noise-{i:05}.txt").touch()
Path("changes.json").write_text('[{"id":"Q1","narration":"Batch reviewed"}]')
```

With isolated environment variables as above, run from that directory using
absolute executable/file paths:

```sh
bea --json --no-input --offline --file /absolute/main.bean check
bea --json --no-input --offline --file /absolute/main.bean list transaction
bea --json --no-input --offline --file /absolute/main.bean update transaction --id Q1 --narration Reviewed
bea --json --no-input --offline --file /absolute/main.bean update transaction --id Q1 --narration Reviewed --apply
bea --json --no-input --offline --file /absolute/main.bean update transaction --id Q1 --narration Reviewed --into main.bean
bea --json --no-input --offline --file /absolute/main.bean update transactions --from /absolute/changes.json
bea update transaction --help
bea update transactions --help
```

Check/list succeed; Q1 exists and the root is valid. Both single preview and
apply, and the batch preview, exit **2**, empty stdout, JSON stderr:

```text
Automatic root discovery for /absolute/main.bean is incomplete: the
8192-operation filesystem search budget was exhausted. Nothing was written.
Select the governing root explicitly and the destination with --into:
bea --file ROOT <command> --into /absolute/main.bean.
```

Following the remedy exits **2**, `No such option: --into (Possible options:
--id)`. Both help pages confirm that no `--into` or other explicit-root
override exists. All refused attempts preserve the ledger byte-for-byte.

The exact source without noise supports preview (`written: 0`), apply
(`written: 1`) and batch preview, and remains valid. In both crowded books,
`add note --date 2026-01-03 --account Assets:Cash --comment 'Explicit selection works'
--into main.bean` succeeds against the same global root. A fresh check passes
and Q1 remains unchanged. Thus explicit selection can retain validation while
skipping discovery; the update surface simply cannot request it.

Expected: preserve the bounded safe refusal, and give both update commands a
supported explicit governing-root selection that lets the user preview/apply
this valid edit without changing unrelated workspace files. Error guidance
must name syntax that the invoked command actually accepts. The discovery
contract in `cli/docs/USAGE.md` promises working explicit root/destination
selection on exhaustion; a root already supplied to an update has no escape.

## Cause and bounded repair

`cli/src/bea_engine/main.py::update:326` unconditionally calls
`write_through_root(_ledger(file), None)`. Unlike add/import, the frontend and
helper update commands expose no selection to replace that `None`.
`ledger/write.py::_IncluderBudget.incomplete:1976–1981` prints the shared
`--into` advice. `write_through_root:2351–2353` skips discovery only when an
explicit selection is present; this path is unavailable to updates.

Expose a coherent, documented explicit-root selection for single and batch
updates and carry it across the helper boundary. Continue to validate against
the selected whole ledger and verify any target constraints; keep ambiguity,
include ownership, locking and atomic writes intact. Make error advice
command-aware. Do not raise the limits, silently regard incomplete discovery
as complete, or skip ledger validation. Regenerate the reference if options
change. This is local CLI work, no dependency or server/API change.

Acceptance: in the isolated 8,300-file fixture, automatic update still safely
refuses, while the supported explicit selection previews without writing and
applies exactly Q1's requested narration; both single and batch paths work.
The displayed recovery command is executable. Preserve the zero-noise
control, explicit add control and existing multi-root/whole-ledger safety
regressions. Add meaningful subprocess regression coverage and run
`make check-all` inside `cli/`.

Dedupe: searched the complete board (done/blocked included) for update/root
discovery, exhaustion, unsupported `--into` and recovery, and reviewed 42
open/blocked milestone scopes. Completed [1119](1119.md), shipped as

## Resolution — 2026-11-08

Shipped in this commit (`cli`). Reproduced the public 8,300-file Git workspace:
check/list succeeded; single and batch update preview/apply refused incomplete
discovery, while following the `--into` remedy failed because the option was
missing. Existing explicit add selection succeeded. The fixture was restored.

Both update commands now accept `--into` through the existing local-path
validator and pass it across the helper boundary. Only a caller's explicit
selection bypasses discovery; an automatically inferred leaf does not become
an update constraint. Updates resolve the selected file beside the governing
root, locate ids across the whole loaded ledger, and compare the located
entry's existing source file by filesystem identity. A mismatch is refused
before single-row no-op handling or batch plan admission; entries never move.
Batch mismatches follow the existing per-row rejection/partial-write path.

The root-discovery bounds, snapshots, locks, ambiguity rules, candidate
validation and atomic replacement are unchanged. Incomplete update errors add
command-specific guidance to preserve the original `--id`/change options or
`--from` mapping, select the governing `--file` before `update`, and add the
explicit `--into`. Updated USAGE and helper wire documentation; generated
REFERENCE with `make docs`.

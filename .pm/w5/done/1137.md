# "Price history with 1 data points": six count messages that reach a count of 1 are still not plural messages

**Severity:** minor (localization/grammar). **Owner:** dashboard. **Estimate:** 45–60 minutes, including the guard. **A3:** these are the count strings that [w4/m28](../w4/done/m28/README.md) did not convert. `dashboard/AGENTS.md` requires "Counts are plural messages, not `Label: {count}` workarounds". **Found by:** `/qa-find-bugs-dashboard` on 2026-11-16 against `https://beancount.io` (local HEAD `8adc7ff65`), headless Chromium, English. Read-only.

## Repro (observed live)

Use a ledger with exactly one `price` directive for a pair, such as the synthetic `2024-04-15 price SEED COMMON 1 COMMON`. Open `/ledger/<owner>/<ledger>/commodities`. The pair's card reads **Price history with 1 data points**. A pair with two points correctly reads "2 data points". Other languages have the same defect, for example Russian "с {count} точками данных" for every count.

## Messages in the same state

Each one is `t(key, { count })` on a single `message` with no `_one`/`_other` family and no `PLURAL_BASE_KEYS` entry, and its count can be 1:

| Key | English | Caller |
| --- | --- | --- |
| `page.commodities.priceHistoryDataPoints` | Price history with {count} data points | `features/ledger-data/commodities/index.tsx:248` |
| `importer.finish.andMoreErrors` | …and {count} more errors | `features/importer/components/steps/finish/index.tsx:84` |
| `plaid.institutionDetail.transactionsCount` | {count} transactions | `features/plaid/pages/plaid-connections/components/bank-item.tsx:170` |
| `plaid.transactionReview.accountsSelected` | {count} accounts selected | `features/plaid/components/transaction-review-table.tsx:371` |
| `plaid.transactionReview.toast.categorizationCompleteDescription` | AI suggested accounts for {count} transactions. | `transaction-review-table.tsx:175` |
| `plaid.transactionReview.toast.transactionsSubmittedDescription` | {count} transactions added to your ledger. | `transaction-review-table.tsx:238` |

These were checked and are deliberately not plurals, because they are labels, signed deltas or always plural in practice: `bql.rowCount` (`Rows: {count}`), `commits.additions`/`deletions`, `common.moreCount`, the statistics `({count})` headings, `ledgerEditor.selectedFiles`, and the plan/token quotas in `user-settings` and `ai-agent`.

## Fix

Turn the six into plural messages in every locale's catalog, with one form per category the language uses, as `dashboard/AGENTS.md` and `docs/TRANSLATIONS.md` describe (`yarn i18n:prepare`). Add them to `src/i18n/plural-keys.ts`. Add a guard to `src/i18n/__tests__/plural.test.ts`: an English message containing a `{count}` word-phrase must be a plural family unless its key is on an explicit allowlist of the label forms above. A later `{count} things` string then fails the test instead of shipping.

## Acceptance

- A pair with one price reads "Price history with 1 data point". Two read "2 data points".
- `yarn lint` (i18n check) and `yarn test` pass. Reintroducing a single-message `"{count} transactions"` key fails the new guard.

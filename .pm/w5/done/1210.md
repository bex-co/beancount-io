# Settings opened from an email, the API docs or a new tab has no way back into the dashboard: its only exit, "Back", does nothing or leaves Beancount.io

**Severity:** minor (nothing is lost, but the reader is stuck on Settings until they edit the address bar, or "Back" takes them off the site). **Owner:** dashboard. **Estimate:** 30–45 minutes including tests. **A2:** people reach Settings from outside the dashboard: the renewal and plan-change emails link to `/settings/billing`, the OpenAPI description, the backend README and the MCP listings tell people to create a token at `/settings/api-keys`, and Stripe Checkout and the billing portal send the reader back to `/settings/billing`. From there they need a way into their ledgers. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-21 against `https://beancount.io` (dashboard entry chunk `main-CIyNN76T.js`), QA-owned headless Chromium at 1440×1000 and 390×844, English/light, signed in as the QA owner. Read-only. Local HEAD `7f98ca03a`.

## Repro

1. Signed in, open `/settings/api-keys` in a new tab (any link with `target="_blank"`, or `window.open(…, "noopener")`). `history.length` is 1.
2. The page has no sidebar, logo or dashboard link. Its only links are the five Settings tabs (General, Billing, SSH Keys, Personal access tokens, Danger Zone). The header holds a single "Back" button. The same holds on General, Billing, SSH Keys and Danger Zone, and at 390px. Billing's only other link is the Telegram support link.
3. Press "Back". Nothing happens: the URL stays `/settings/api-keys`.
4. Come from another site instead: open `https://example.com/`, then load `/settings/api-keys` in the same tab and press "Back". The tab goes to `https://example.com/`.
5. Control: from a ledger page (`/ledger/open_ledger/example/journal?time=2016`), open User menu → Settings, switch to SSH Keys, and press "Back". It returns to `/journal?time=2016` as intended, because the tabs use `replace`.

Repeated from fresh loads.

## Cause

`dashboard/src/features/user-settings/pages/layout.tsx:95-97` (`handleBackToDashboard`) calls `router.history.back()` whatever the history holds. When Settings is the first page this app put in the tab's history, that is a no-op, the browser's new-tab page, or the previous site. The layout (`:14-37`, `:99-112`) gives no other route out. The handler dates from the dashboard import `af5339de0` and is unchanged at HEAD, so this is not deployment lag. From source only, the same applies after every same-tab redirect through a third party that comes back to Settings: Billing sends the reader to Stripe with `window.location.href` (`hooks/use-subscription-portal.ts:25`, `pages/general/subscription-section.tsx:219`), and Stripe returns them with a full load of `/settings/billing` (`portalReturnUrl`, and the Checkout `successUrl` with `?checkout=success`, in `backend-cluster/backend-v2/src/features/stripe/service/stripe.ts:255-259`). "Back" then reopens the Stripe page.

The Ledger Gallery (`features/ledger-list/pages/gallery-page/index.tsx:390-396`) has the same flaw. Its logo button is named "Back", calls `window.history.back()`, and is the page's only non-ledger link. No dashboard page links to `/ledger-gallery`, so every visit starts outside the app. In a new tab the button does nothing.

## Fix

Owned by `dashboard`. Go back in history only when the previous entry belongs to this app. TanStack's `router.history.canGoBack()` (`@tanstack/history`, `location.state.__TSR_index !== 0`) is false exactly when the current entry is the first one the app created. Otherwise go to the dashboard (`/ledger`) with a normal router navigation. A link with that `href` keeps a new-tab open working too. Do the same for the Gallery's logo button, with `/ledger` as its fallback. Keep the root not-found and error pages as they are: they already offer "Go Home" beside "Go Back".

## Definition of done

- Settings loaded as the first page in a tab (new tab, from another site, or a full load such as Stripe's return), then "Back": lands on `/ledger` inside the app, at desktop and narrow widths.
- From a ledger page through User menu → Settings, and after switching tabs, "Back" still returns to that exact ledger URL, search included.
- The Gallery's logo button follows the same rule.
- `features/user-settings/pages/__tests__/layout.test.tsx` covers both branches (with and without in-app history) through the real router's history. It fails on the current code. Dashboard gates (`yarn format:check`, `yarn lint`, `yarn test`, `yarn build`) pass.

## Control

## Cause

- `backend-cluster/backend-v2/src/features/gitea/pull-request/service/pull-request-service.ts`

Branch creation precedes the empty-diff check, and the catch (:273-277) rethrows without cleanup. No deleteBranch call exists in the file.

## Fix (parity: MCP+REST+GraphQL)

Owning package `backend-cluster/backend-v2`; the fix must land on every eligible surface (MCP+REST+GraphQL) in the same change. Validate non-empty diff before creating the branch, or delete on failure.

---

**Resolved 2026-10-03** — a refused pull-request create no longer leaves its `pr-patch-*` branch behind. Empty `changes` are refused as `BAD_USER_INPUT` before any branch exists, and for every later failure — changes identical to the base, a failed file write, a failed pull-request call — the branch is deleted again. Shipped in `5af7f057` (`backend-cluster/backend-v2`).

The cleanup is best effort: if deleting the branch itself fails, that is logged and the caller still receives the original refusal. Both of the note's suggested fixes were applied, since each covers a case the other misses. Tests drive both refusals through HTTP REST, GraphQL execution and an MCP client against a fixture that tracks branches, and assert none is left; they fail with the fix reverted. Branches already littered on existing ledgers are not cleaned up by this change. Not re-run against the hosted endpoint: the fix reaches it with the next deploy.

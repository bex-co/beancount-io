# A failed balance assertion's Journal row says "accumulated 17.00 USD" when the account accumulated 267.00 USD, and looks like a passing one

**Severity:** minor. The row puts a wrong number under the word for the account's balance, at exactly the point where a user reconciles against a bank statement. The Errors page and the error bell still report the failure correctly. **Owner:** dashboard. **Estimate:** 40–55 minutes including tests. **A2:** a balance assertion is how a newcomer checks their ledger against the bank. When it fails, the Journal is where they go to see by how much. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-18 against `https://beancount.io` (entry chunk `main-LGv2TZLj.js`), headless Chromium at 1440×1000, English and German, isolated profile, signed in as the QA owner on a disposable QA ledger. Local HEAD `bc8308143`. The probe was written and then restored byte for byte (same blob SHA, no ledger errors).

## Repro

Append to a ledger that already has an open `Assets:Cash`:

```beancount
2024-01-01 open Assets:Qa:Wallet USD
2024-01-01 open Assets:Qa:Padded USD
2024-01-01 open Expenses:Qa:Leap USD
2024-01-01 open Equity:Qa:Opening USD
2024-01-05 * "qa-fund" "Fund wallet"
  Assets:Qa:Wallet   300.00 USD
  Assets:Cash       -300.00 USD
2024-02-29 * "qa-leap" "Leap day spend"
  Expenses:Qa:Leap    33.00 USD
  Assets:Qa:Wallet   -33.00 USD
2024-03-01 pad Assets:Qa:Padded Equity:Qa:Opening
2024-03-02 balance Assets:Qa:Padded 500.00 USD
2024-03-03 balance Assets:Qa:Wallet 250.00 USD
```

The wallet holds 267.00 USD on 2024-03-03, so the assertion fails by 17.00 USD.

1. The Errors page reads "Balance failed for Assets:Qa:Wallet: expected 250.00 USD, got 267.00 USD". That is correct. bean-check words the same failure as "expected 250.00 USD != accumulated 267.00 USD (17.00 too much)".
2. Open `/journal?time=2024-03`, turn **Transaction** off and **Balance** on. The row reads `2024-03-03 · Balance · Assets:Qa:Wallet 250.00 USD`, with a second muted line **"accumulated 17.00 USD"**. The account page `/account/Assets:Qa:Wallet` with Balance on shows the same row. Its own Balance column reads 267.00 USD on the 2024-02-29 transaction listed just below it.
3. A passing assertion on the same page (`2024-03-02 balance Assets:Qa:Padded 500.00 USD`) has the same row class (`balance`), the same colours and the same layout. The only difference is that muted second line. The accessible name is "Open entry 2024-03-03 Balance Assets:Qa:Wallet 250.00 USD 17.00 USD (row 1)". It does not say the assertion failed or what 17.00 is.
4. In German the line reads "angesammelt 17.00 USD".

The API is right. `getLedgerJournal` returns `{"directive_type":"Balance","amount":{"number":"250.00","currency":"USD"},"tolerance":null,"diff_amount":{"number":"17.00","currency":"USD"}}`. Since w21/done/087, `diff_amount` is the actual balance minus the asserted one, which is also Beancount's definition. A passing assertion keeps `diff_amount: null`.

The same component also writes its amounts the raw way. On a ledger with `render_commas` on, the 2025-07-01 Balance rows read `4000000 COMMON` and `1500000 COMMON`. The expanded postings just above read `100,000 COMMON`, and the source writes `4,000,000 COMMON`.

## Cause

- `dashboard/src/features/journal/components/journal-description/balance-description.tsx:26-31` renders `diff_amount` after the label `journal.accumulated` ("accumulated"; its locale description even says "Label before an accumulated balance difference"). The line was written before `diff_amount` was ever filled. Under rustledger the field stayed `null` until w21/done/087 started sending the difference on 2026-10-22, so the mislabelled line has only been visible since then. The row gets no failed state: `getDirectiveTypeClass` (`journal-table.tsx:73-95`) returns plain `balance` either way.
- `journal-entry-label.ts:24-26` appends the bare `diff_amount` to the row's accessible name.
- `balance-description.tsx:19-22,29` (and `price-description.tsx:14`, `custom-description.tsx:22`) format through `formatAmountWithCurrency` → `formatAmount`, which only strips commas. w2/done/119 and w2/done/137 moved postings and the account journal's Units, Change and Balance columns to `<LedgerAmount>`. These description amounts were left out.

## Fix

Owned by `dashboard`. No API change is needed.
- For a Balance with `diff_amount`, show the accumulated balance as `amount + diff_amount`, summed exactly with `sumDecimalNumbers`, together with the signed difference. For example: "250.00 USD · accumulated 267.00 USD (17.00 USD too much)", or "too little" for a negative difference, the wording bean-check uses. Mark the row as failed with text, not colour alone (a "Failed" label in the destructive style, as mobile's "Off by" line from w21/done/050 does). Put "failed" and the accumulated amount into `journalEntryLabel`.
- Render the asserted amount, its `~` tolerance, the accumulated amount and the difference through `<LedgerAmount>`, and do the same for the Price and Custom-budget description amounts, so they follow the reader's separators and `render_commas` like the postings beside them.
- Passing assertions keep exactly today's row.

## Definition of done

- With the fixture above, the Journal and the account journal read "accumulated 267.00 USD" with a 17.00 USD "too much" difference and a visible failed state. The row's accessible name says it failed. The passing 500.00 USD row is unchanged.
- An assertion of 280.00 USD on the same ledger reads accumulated 267.00 USD, 13.00 USD too little.
- On a `render_commas` ledger, the Balance rows read `4,000,000 COMMON` in English and `4.000.000 COMMON` in German, matching the postings.
- Rendered tests cover a failing assertion above and below the actual balance, one with a tolerance, a passing one, and the accessible name. Each fails on the current code. Dashboard gates pass.

## Dedupe

Searched `.pm/**`, including `done/` and `blocked/`, for `accumulated`, `diff_amount`, "balance row", `BalanceDescription`, `formatAmountWithCurrency` and failing balance or assertion. w3/done/556 added the asserted amount and noted that `diff_amount` was always null at the time. w21/done/087, 533, 675 and 677 fill `diff_amount` in the ledger service and give mobile its "Off by" line. w2/done/137 is the account journal's numeric columns only. No item covers the dashboard's label, its failed state, or these description amounts. `git log` shows `balance-description.tsx` last changed in `f20433174` (w3/556), so this is not deployment lag.

**Unverified:** right-to-left locales, the 390px layout, and mobile (out of scope; it uses its own "Off by" renderer).

**Update 2026-11-21 (`dashboard-qa`, production `main-CIyNN76T.js`)** — A further part of this note's Fix ("render the asserted amount, its `~` tolerance … through `<LedgerAmount>`") is now visible as lost precision, not only raw formatting. The new Compact and Comfortable rows write the asserted amount and tolerance with `useFormatNumber`, which rounds an ISO currency to its minor units, so a sub-cent assertion is shown as a different number. Probe on the disposable QA ledger (written, checked, removed; file back to its snapshot blob, ledger check clean):

```beancount
2026-09-01 open Assets:Qa-20261121-Probe:Wallet
2026-09-02 * "qa-20261121-dashqa" "qa-20261121 fund"
  Assets:Qa-20261121-Probe:Wallet   100.00 USD
  Equity:Opening-Balances
2026-09-04 balance Assets:Qa-20261121-Probe:Wallet  100.004 ~ 0.001 USD
```

- Errors: `Balance exceeds explicit tolerance for Assets:Qa-20261121-Probe:Wallet: expected 100.004 USD ~ 0.001, got 100.00 USD (difference: 0.004)`. `getLedgerJournal` returns `amount.number "100.004"`, `tolerance "0.001"`, `diff_amount "-0.004" USD`.
- Journal (Compact and Comfortable, `/journal` and the account page `/account/Assets:Qa-20261121-Probe:Wallet`, 1440px and 390px) reads **`Off by -0.004 USD` beside `100.00 ~ 0.00 USD`**. The row claims the statement said 100.00, which is exactly what the account holds, with a tolerance of zero, and still says it is off. The entry button's accessible name reads `… 100.004 USD -0.004 USD (row 6)`: right amount, no tolerance.
- Cause: `journal-lines.tsx:455-466` and `journal-days.tsx:485-496` call `formatNumber(balance.amount.number | balance.tolerance, currency, fractionDigitsOf(…))`; `formatNumber` (`common/lib/format/format-number.ts`) fixes an ISO currency at `currencyMinorDigits` (2 for USD) and ignores `fractionDigits`. Both were added in `91daf9b46`/`ebbf43fed`.

Add to the Definition of done: the row above reads `100.004 ~ 0.001 USD` (every source digit, the reader's separators) in both layouts, on the account page and at 390px; a rendered test with a sub-minor-unit assertion and tolerance fails on the current code.

# Accounts lists the chart of accounts newest-opened first in reverse file order, so Assets come last and siblings are split apart

**Severity:** minor (finding an account by scanning). **Owner:** dashboard. **Estimate:** 20–30 minutes. **A2:** a newcomer who opens Accounts to check their chart of accounts should see it in account order, each parent beside its children, as the Balance Sheet lists it. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-18 against `https://beancount.io` (entry chunk `main-LGv2TZLj.js`), QA-owned headless Chromium 153 at 1440×1000, English/light. Signed-in QA owner on its designated disposable synthetic ledger, plus the public control `open_ledger/example`. Read-only. Local HEAD `50f9bca2f`.

## Repro

1. The synthetic ledger's `main.bean` opens its 12 accounts on 2026-01-01 in this order: Assets:Bank:Checking, Assets:Bank:Savings, Assets:Cash, Liabilities:CreditCard:Visa, Income:Salary, Expenses:Food:Groceries, … Equity:Opening-Balances.
2. Open `/ledger/<owner>/<ledger>/accounts`. The table shows exactly the reverse: Equity:Opening-Balances, Expenses:Entertainment:Streaming, Expenses:Transport, Expenses:Housing:Rent, Expenses:Food:Coffee, Expenses:Food:Restaurants, Expenses:Food:Groceries, Income:Salary, Liabilities:CreditCard:Visa, Assets:Cash, Assets:Bank:Savings, Assets:Bank:Checking.
3. Open `/ledger/open_ledger/example/accounts` (60 rows). It starts with the most recently opened accounts: `Expenses:Taxes:Y2017:US:SocSec`, `…:State`, `…:SDI`, `…:CityNYC`, `…:Federal`, `…:Medicare`, `…:Federal:PreTax401k`, then the Y2016 block. `…:Federal` and its child `…:Federal:PreTax401k` are separated by Medicare, and the Assets accounts come last.

The column headers have no sort control, so the reader cannot reorder the table. The type pills above it list Assets, Liabilities, Equity, Income, Expenses, but the table follows none of that order. Reproduced on fresh loads.

## Cause

`dashboard/src/features/ledger-data/accounts/index.tsx:455-458` renders `getLedgerAccountDirectives` in the order the API returns it. The API builds that list from the Open directives fetched from the journal (`backend-cluster/backend-v2/src/features/ledger/service/ledger-account-service.ts:135-168` via `getAllOpenEntries`), and the journal is newest first. The page never sorts. That order is right for a journal, but this page is a directory.

## Fix

Sort the Accounts table on the page: by root in the order the type pills show (the ledger's `name_assets`, `name_liabilities`, `name_equity`, `name_income`, `name_expenses`, so renamed roots work), then by account name, so each parent comes directly before its children. Apply the sort before the search and type filters, so a filtered view keeps the same order. Keep the API response unchanged; this is a presentation choice, and the REST and MCP readers of the same data are unaffected. Keep closed accounts in their sorted place with their Closed status.

# Smart Import: each step change drops focus to the page body and announces nothing, and the step titles are not headings

**Severity:** minor (accessibility; WCAG 2.4.3 Focus Order, 1.3.1 Info and Relationships, 4.1.3 Status Messages). **Owner:** dashboard. **Estimate:** 30–45 minutes including a rendered test. **A2:** a CSV import is many people's first real use of a ledger. With a screen reader, choosing a file, **Continue to Configure**, **Back** and **Upload Different File** each remove the control that was used and say nothing. The new step cannot be found by heading either. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-18 against `https://beancount.io` (entry chunk `main-LGv2TZLj.js`), headless Chromium 153 at 1440×1000 and 390×844, English/light. QA owner account on the synthetic `<qa-owner>/mcp-agent-eval` ledger, using a five-row `qa-20261118-` CSV. Nothing was imported.

## Repro

1. Open `/ledger/<owner>/<ledger>/import`. Focus **Browse files**, press Enter and choose a CSV (Date, Payee, Description, Amount) with three valid rows and two invalid ones.
2. The Preview step replaces the drop zone. `document.activeElement` is `<body>`. No live region reports the result. "3 Valid / 2 Errors" is plain text.
3. Focus **Continue to Configure** and press Enter. Configure replaces Preview, and focus is again `<body>`.
4. **Back** (Configure → Preview) and **Upload Different File** (Preview → upload) do the same.
5. List the headings in `main`. Preview has `h1 Smart Import`, then `h2 Related Pages`. **Preview Imported Data** is a `div`. Configure has `h1 Smart Import`, `h3 Assign Target Accounts` and `h2 Related Pages`. **Configure Import Settings** is a `div`, so the outline jumps from h1 to h3.

Same at 390×844. Repeated from fresh loads. In Chromium the next Tab happens to land on the new step's first control, because the browser remembers where the removed button was. A screen reader's reading position gets no such help, and nothing announces the change.

Controls: inside Preview, Enter, Escape and Tab on an edited cell return focus to that cell's button and update the counts (w4/140, w4/310). A rejected Import focuses its conflict alert (`transaction-config-form.tsx:400`).

## Cause

`dashboard/src/features/importer/components/import-workflow-container.tsx:50-95` swaps one step component for the next on `workflow.currentStep`, and nothing moves focus afterwards. The step titles are `CardTitle`, a `div` (`common/components/ui/card.tsx`), at `components/steps/preview/import-preview-table.tsx:110` and `components/steps/configure/transaction-config-form.tsx:331`.

## Fix

Make each step's title a real `h2`, inside `CardTitle` as `features/user-settings/pages/general/oidc-section.tsx:73-76` does, keeping `id={titleId}` on the element that carries the text so the preview table keeps its name. Then `Assign Target Accounts` sits correctly at `h3`. After a step change caused by the user (file chosen, Continue, Back, Upload Different File, Import finished), focus that step's heading (`tabIndex={-1}`) with `preventScroll: false`. Do not do this on the first render of the page. Where a step can show its error alert first (a parse error, an import conflict), focusing the alert instead is fine. The Preview heading's description, or a polite status, should include the valid and error counts so they are read on arrival.

## Definition of done

- After each of file chosen, Continue to Configure, Back and Upload Different File, focus is on the new step's heading, never `<body>`, at 1440 and 390 widths.
- The Preview and Configure outlines are `h1 Smart Import`, then the `h2` step title (Configure keeps `h3 Assign Target Accounts` below it), then `h2 Related Pages`.
- Arriving at Preview exposes the valid and error counts to assistive technology.
- Cell editing focus, the rejected-import alert focus, and the preview table's accessible name are unchanged.
- A rendered workflow test asserts the focused element after each transition and fails on the current code. Dashboard gates pass.

## Dedupe

Searched `.pm/**`, including `done/`, for importer focus, step change or transition, Preview Imported Data, Configure Import Settings, and CardTitle headings. w4/done/140, w4/done/310 and w4/done/242 cover the preview cells and table names. w4/done/322 and w4/done/1059 cover the submit errors. w5/1156 is the same CardTitle-as-`div` pattern on Ledger Settings, and its sweep did not reach these steps because they appear only after an upload. Present at HEAD.

Actual screen-reader speech, Safari and Firefox, and the Finish step (reached only by importing).

## Cause

- `backend-cluster/backend-v2/src/features/gitea/pull-request/service/pull-request-service.ts`

`describeClientFailure` falls back to `"Unknown error"` (:30-55) when the Gitea client's refusal carries no status/detail, and approve/reject wrap it in a plain Error -> INTERNAL. No 404 -> NOT_FOUND translation on the review path. Separate throw site from the ghost-PR read.

## Fix (parity: MCP+REST+GraphQL)

Owning package `backend-cluster/backend-v2`; the fix must land on every eligible surface (MCP+REST+GraphQL) in the same change. Translate 404 -> NOT_FOUND on the review path.

---

**Resolved 2026-10-03** — approving or rejecting a pull request number that does not exist is now answered `NOT_FOUND` naming the number on REST (404), GraphQL and MCP. Every other review refusal is still returned as a `success: false` result, but is now described from the response the client threw (`Gitea 405: …`) instead of `Unknown error`. Shipped in `202764f2` (`backend-cluster/backend-v2`).

This changes one documented behaviour: REST and GraphQL used to return a 200 `success: false` result for an unknown number, and now return NOT_FOUND; the v1 route descriptions and OpenAPI snapshot say so. A regression test approves and rejects an unknown pull request through HTTP REST, GraphQL execution and an MCP client; it fails with the fix reverted. Not re-run against the hosted endpoint: the fix reaches it with the next deploy.

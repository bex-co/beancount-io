# Retain written native IDs through source inference

**Reopened QA 2026-10-23 · major · cli · 45–60m · A1 · worker1.**
The 974 open-selector repair `0ae135b41` keeps a written owner in its second
index. That owner is still discarded when its Cash amount is inferred from
the selected lot. A normal native-valid foreign-loan repayment then imports
again under its genuine B1 reference: default apply exits **0 / writes 1**,
authored Cash **1,045→980 USD**, B1 **one→two**, and FX expense **10→75 USD**.
The loan remains −50 EUR; the added CSV row is another cash/expense payment.
Explicit duplicate skip and human apply have the same effect. Exact repeat
after that erroneous write skips, because the new row has explicit Cash.
Reopen this known open-lot native-ID owner; no new finding/count or severity
promotion. Prior reports and shipped resolution are retained below.
The same decision also drops multicurrency and zero-counter-currency owners
with plain amounts; the additional-layout section records that shared root.

The book borrows 100 EUR at historical cost 1.10 USD, receiving 110 USD.
It repays 50 EUR with a known 10 USD FX expense and one omitted Cash number.
The single existing loan lot unambiguously supplies cost 55 USD, so native
booking infers Cash **−65 USD**. Cash is the first balance-sheet posting and
`bank_id: "B1"` genuinely belongs to it. An inspected display filter removes
only that repayment from the loaded view; it changes no source, ID, lot,
amount or other transaction. The source still contains the recorded B1.

With `bea` on PATH, choose a fresh absolute directory for each mode and
repetition. `label` explicitly selects the original lot's date and label;
`currency-cash` states USD but omits its Cash number. `per`, `total`, `pass`
and `explicit-cash` are working controls. Set `skip=True` and/or `human=True`
for explicit skip/human apply. All streams, exits, durations and before/after
hashes are captured; only successful apply may alter main.

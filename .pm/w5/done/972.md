# Strip the BOM before indexing written import identities

**Major · cli · 20–30m · A1.** An unchanged bank transaction is written
again when it is the first directive in a BOM-prefixed source file and a
plugin filters it from the loaded view. This remains broken after completed
[881](./done/881.md)'s source-fact fallback. A real CSV import creates the
original row; after saving that transaction file with a UTF-8 BOM, repeat
import writes another 100 USD and leaves actual Cash **200 USD**. Both native
bank references and generated IDs reproduce. No product fix implemented.

Environment: 2026-10-22 QA, clean main `c7408a3e7` (initial reproduction on
`8aa0577d2`; implicated source unchanged), checkout `bea 0.3.1`, frontend
Python 3.13.3, managed Python 3.12.10 / Beancount 3.2.3 / Beanquery 0.2.0,
macOS 26.5.1 arm64. Fresh subprocesses, closed stdin/no TTY, isolated absolute
config/cache paths, notifier disabled and inherited file/token overrides
removed. Inspected local display-filter plugin and synthetic files only.

Run with the checkout's `bea` on PATH, replacing `/abs/case` with a fresh
absolute disposable directory. The plugin hides uncleared `!` transactions;
it does not change their written accounting facts. The first transaction
and its bank metadata/ID are produced by the real CLI. Adding the BOM is a
fixture edit simulating an editor's normal UTF-8-with-BOM save. Removing the
plugin briefly near the end exposes actual written balances, then restores
its original root declaration in `finally`.

```python
import json, os, subprocess
from pathlib import Path
case = Path('/abs/case')
books = case / 'books'
books.mkdir(parents=True)
ledger = books / 'main.bean'
transactions = books / 'transactions.bean'
header = '''option "insert_pythonpath" "TRUE"
option "operating_currency" "USD"
plugin "cleared_only"
2024-01-01 open Assets:Cash USD
2024-01-01 open Income:Salary USD
include "transactions.bean"
'''
ledger.write_text(header)
transactions.write_bytes(b'')
(books / 'cleared_only.py').write_text('''from beancount.core.data import Transaction
__plugins__ = ['run']
def run(entries, options):
    return [e for e in entries if not isinstance(e, Transaction) or e.flag != '!'], []
''')
source = case / 'salary.csv'
source.write_text('Date,Memo,Amount,Reference\n2024-01-02,Salary,100.00,salary-1\n')
source_bytes = source.read_bytes()
use_bom = True
env = os.environ.copy()
for key in ('BEA_FILE', 'BEA_TOKEN', 'BEANCOUNT_LOAD_CACHE_FILENAME',
            'BEA_ENGINE_PYTHON', 'BEA_ENGINE_DIR'):
    env.pop(key, None)
env.update(BEA_CONFIG_DIR=str(case / 'config'), XDG_CACHE_HOME=str(case / 'cache'),
           BEA_NO_UPDATE_NOTIFIER='1')
def run(tag, args, json_mode=True, overrides=None):
    argv = ['bea', *(['--json'] if json_mode else []), '--no-input', '-f', str(ledger), *map(str, args)]
    result = subprocess.run(argv, cwd=case, env=env | (overrides or {}),
                            stdin=subprocess.DEVNULL, capture_output=True,
                            text=True, timeout=25)
    print(json.dumps(dict(tag=tag, args=argv, exit=result.returncode,
                         stdout=result.stdout, stderr=result.stderr)), flush=True)
run('empty-check', ['check'])
run('first-apply', ['import', source, '--csv', 'date=Date,narration=Memo,amount=Amount,id=Reference',
                   '--account', 'Assets:Cash', '--default-account', 'Income:Salary',
                   '--into', transactions, '--apply'])
# Simulate saving this ordinary monthly transaction file as UTF-8 with BOM.
authored = transactions.read_bytes().lstrip(b'\n')
transactions.write_bytes((b'\xef\xbb\xbf' if use_bom else b'') + authored)
prefix = transactions.read_bytes()
run('source-check', ['check'])
repeat = ['import', source, '--into', transactions]
run('human-preview', repeat, json_mode=False)
run('preview', repeat)
run('second-apply', [*repeat, '--apply'])
run('third-apply', [*repeat, '--apply'])
# Inspect the actual written accounting facts without the display filter.
ledger.write_text(header.replace('plugin "cleared_only"\n', ''))
try:
    run('unfiltered-facts', ['query', "SELECT count(*),sum(number) WHERE account='Assets:Cash'"],
        overrides={'XDG_CACHE_HOME': str(case / 'unfiltered-cache')})
    run('unfiltered-check', ['check'], overrides={'XDG_CACHE_HOME': str(case / 'unfiltered-cache')})
finally:
    ledger.write_text(header)
assert transactions.read_bytes().startswith(prefix)
assert source.read_bytes() == source_bytes
```

All nine commands exit **0**. The first import correctly writes **1**.
Both source checks are valid, but the unchanged repeat preview says
**ready 1 / duplicates 0 / conflicts 0**, human preview also calls it new,
and the second apply wrongly writes **1**. The third apply writes 0 because
the appended second copy is now parseable by the fallback. The unfiltered
BQL answer is **[[2, "200.00"]]**, and unfiltered `check` still passes.
The original transaction, including its BOM, remains an unchanged prefix;
the incorrect write appends a second transaction. CSV and plugin bytes are
unchanged, and the root's filter declaration is restored.

Working control: set only `use_bom = False` in an otherwise fresh fixture.
The second preview is ready 0 / duplicates 1, second and third applies write
0, and unfiltered facts are **[[1, "100.00"]]**. Keeping the BOM but removing
the filtering plugin, or using a pass-through plugin, also deduplicates
correctly because the loaded view can still supply the identity.

Expected: repeat import writes zero and retains Cash 100 USD, regardless
of whether a supported BOM marks the first transaction line. USAGE:731–733
explicitly promises that BOM files load normally, with the mark skipped on
read and retained by appends. IMPORTING's exact-identity rule and 881's
source-fact fix must use the same logical source text as the normal loader.

Reproduction and controls:

- Eight pristine Python-importer cases (**48 CLI calls**), twice each of
  BOM+filter, plain+filter, BOM+no plugin and BOM+pass-through. Only BOM+filter
  writes the existing native-ID row again: Cash 200 / count 2 versus 100 / 1.
- Eight pristine actual-CSV-producer cases (**56 calls**), twice each of
  native/generated IDs × BOM/plain, independently reproduce the same extra
  write. The first source entry/ID really comes from `bea import`; it is not
  a hand-invented hash. Third applies correctly stop further growth.
- Eight fresh row-position controls (**56 calls**): a BOM before a comment
  followed by the transaction correctly deduplicates, for both ID types.
  With two original transactions (100 and 25 USD) and the BOM directly on
  the first, only the first is missed: preview new 1 / duplicate 1, apply 1,
  then duplicate 2 on the next repeat; source facts become **3 / 225 USD**
  instead of 2 / 125. Roots are restored and original entry bytes retained.
- The exact public recipe was replayed twice alongside the plain control,
  with JSON and human apply variants. Both surfaces reproduce the extra
  write, preserve the original prefix and show the same actual source facts.

Cause: `_written_identities` in `cli/src/bea_engine/importing.py:1830–1840`
decodes each snapshot file as `utf-8` and NFC-normalizes it, then calls
`parser.parse_string` directly while ignoring its errors. That preserves
U+FEFF on the first directive. A direct managed-parser control returns
**zero transactions / one error** for the exact BOM-prefixed row versus
one transaction / no errors without the BOM. The raw source index therefore
cannot supply that existing ID after the plugin filtered the loaded entry.
The row is treated as new and appended.

Normal file loading goes through `bea_engine.compat.install:23–56` and
`_canonical_bytes:227–243`, which strips the BOM before NFC normalization;
the raw-string parse bypasses it. The actual ledger is valid under that
supported reading. Requiring users to remove the BOM or disabling their
filter would avoid the symptom but would not repair the mismatched readers.

Fix in `cli/`: canonicalize raw identity-source bytes with the same leading
BOM/NFC policy as normal ledger loading before parsing. Keep source files
unchanged, full-precision parsing, plugin-free source facts, source-account
scoping and the booked-open-lot safeguard. Do not treat a failed source parse
as proof that an existing transaction is new. No dependency or API change.

Caller scope: lazy `written_source` (`importing.py:480–485`) feeds
`_under_id` (`:1780–1812`) during `answer` (`:558`). CSV and inspected Python
importers both exercised this path; generated and native IDs were verified.
The source index loops every snapshot file, so this is per-file first-line
handling; a BOM directly on a root's first transaction is regression scope,
not separately reproduced here.

Dedupe: searched every board state for BOM/source-fact/native-ID duplication
and raw parser helpers, and checked history. `8b7827c6f` closed 881 and added
this raw-source parser; its plain filtered-source case now works, as the
control proves. Completed [704](./done/704.md) deliberately refuses BOM input
for native `ingest` forwarding; this is supported `bea import` through its
own canonicalizing engine. [934](./934.md) concerns regex root discovery,
not stable-ID source parsing. No overlapping open task or already-shipped
BOM-aware identity-source fix found. The separate [973](./973.md) changed-amount/native-ID failure under a filter
also reproduces without any BOM and needs a distinct owner-selection repair;
it is not used as a working control here.

Acceptance: the supplied repeat writes zero, reports one duplicate and
retains actual Cash 100 USD with both ID types and both output surfaces.
Keep a real first import, source-valid BOM appends, plain/no-plugin/pass-through
and comment-first controls, two-row first-only behavior, full precision and
source immutability. Add meaningful CLI regressions beside
`cli/tests/test_import_source_facts.py`; run `make check-all` inside `cli/`
on implementation. Windows/Linux and interactive TTY were not exercised.

**Resolved 2026-10-23** — fixed: the written-view fallback that indexes a ledger's own transactions by stable id (`_written_identities` in `cli/src/bea_engine/importing.py`) now decodes each file as `utf-8-sig`, so a BOM before a file's first directive is no part of it; export's raw-entry replay (`_written_entries`) strips the same mark. With a plugin filtering the first transaction from the loaded view, an unchanged repeat import used to read it as nothing and wrote the same 100 USD again; the repeat now previews `duplicate`, writes 0 on the second and third apply, and leaves one `bank_id` in the file whether or not the BOM is there. Regression test `cli/tests/test_import_bom_written_identity.py` (BOM case) fails without the fix; the plain control passes. Full suite green apart from the known `test_release` smoke timeout, which passes alone. Shipped in this commit (`cli`).

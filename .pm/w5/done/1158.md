# Commit and pull-request diffs mark added and removed lines by colour alone: no "+"/"−", nothing a screen reader says

**Severity:** minor (accessibility; WCAG 1.4.1 Use of Color, 1.3.1 Info and Relationships). **Owner:** dashboard. **Estimate:** 30–45 minutes including a rendered test. **A1/A2:** a ledger's commit history is how a person checks what an agent, an import or a teammate changed. Someone who cannot tell pale pink from pale green, or who listens with a screen reader, cannot tell which lines were removed and which were added. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-18 against `https://beancount.io` (entry chunk `main-LGv2TZLj.js`), headless Chromium 153 at 1440×1000 and 390×844, English/light. QA owner account on the synthetic `<qa-owner>/mcp-agent-eval` ledger, read-only. Local HEAD `a858bdff9`.

## Repro

1. Open `/ledger/<owner>/<ledger>/commits` on any ledger whose latest commit removes or adds a few lines. It opens that commit.
2. Look at **Changes**. Removed lines have a pale red background, added lines a pale green one. Neither has a `-` or `+` in front of it, and nothing else in the row changes.
3. Read the rows in the accessibility tree. A removed line reads `row "89 2026-08-30 * …"`, an unchanged one `row "87 87 2026-08-29 balance …"`. The only difference is that one line-number cell is empty. Nothing says "removed" or "added".

Same at 390×844 and in Persian. Repeated from a fresh load.

Control in the same viewer: a diff over 500 lines switches to the virtualized branch, which prints a `+`/`-` column before each changed line (`diff-viewer.tsx:442-447`). The small, common case is the one without it.

## Cause

`dashboard/src/common/components/diff-viewer/diff-viewer.tsx:508-520` renders diffs of up to 500 lines with react-diff-view's `<Diff viewType="unified">`, with no `renderGutter` and no marker of its own. react-diff-view 3.1.0 marks a change only with the classes `diff-code-insert`/`diff-code-delete`, and `diff-viewer.css:28-49` styles those as background colours (`oklch(0.95 0.15 25 / 0.2)` for removals in light mode). Commit detail (`features/git/commits/components/commit-detail.tsx:177`) and pull-request review (`features/git/pull-requests/pages/pr-review-page.tsx:124`) both use this viewer.

## Fix

Give every changed line in the small-diff branch a visible `+` or `−` marker that does not rely on colour, as the virtualized branch and GitHub do, and make the change type part of what assistive technology reads for that row, for example a visually hidden, localized "Added line" or "Removed line". Keep the markers out of copied text (`user-select: none`), so copying code from a diff still yields plain source. Keep the colours, line numbers, syntax highlighting, RTL isolation (w4/226) and the file anchors (`#diff-file-…`) as they are.

## Definition of done

- In a commit with both kinds of change, each removed line shows `−` and each added line shows `+` before its code, at 1440 and 390 widths, in light and dark.
- Each changed row's accessible text identifies it as added or removed. Unchanged rows say neither.
- Selecting and copying a diff still produces plain source, with no markers.
- A rendered test covers an insert, a delete and a context line, and fails on the current code. Dashboard gates pass.

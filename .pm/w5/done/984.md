# Preserve account names when discovering documents

**Minor · cli · 45–60m · A1.** Supported account names containing a ligature
or full-width letter lose their receipt documents during automatic directory
discovery. `doctor directories` falsely rejects the matching folder as an
undeclared ASCII account. The ledger and receipt folder contain the exact
same account name; `check`, `list open`, an explicit document directive and
`add document` all accept it. Files stay intact. No product fix implemented.

Real CLI QA, 2026-10-22, checkout-selected `bea 0.3.1`, macOS 26.5.1 arm64,
frontend Python 3.13.3, existing managed Python 3.12.10 / Beancount 3.2.3.
Exploratory reproduction on `243d5c51c`; standalone public replay on
`c0186d5e4`. Fresh synthetic local fixtures, bounded subprocesses, closed
stdin/no TTY, isolated child config/cache, notifier disabled and inherited
ledger/token/engine overrides removed. No document provider or network call.

The directory walker changes NFC account identities using NFKC:

| Declared account/folder component | NFC identity | Walker lookup |
|---|---|---|
| `Of\uFB01ce` | `Ofﬁce` | `Office` |
| `A\uFF22ank` | `AＢank` | `ABank` |

Both source names are valid native account components and already NFC.
The names on the right are different account IDs. Python's Unicode escapes
in the recipe below make the source characters unambiguous.

With `bea` on PATH, choose a fresh absolute directory and run this script.
The default `ligature` reproduces both missing documents and the false
folder error. `width` is the second family; `ascii` and `nfd-folder` are
working controls. `missing` and `case-change` are genuinely undeclared
folders. `bom-ligature` reaches the helper-routed doctor path and has the
same failure as the ordinary native path.

```python
from pathlib import Path
import json, os, subprocess, unicodedata

case = Path('/abs/document-account-case')
mode = 'ligature'
profiles = {
    'ligature': ('Of\ufb01ce', 'Of\ufb01ce', False),
    'width': ('A\uff22ank', 'A\uff22ank', False),
    'ascii': ('Office', 'Office', False),
    'nfd-folder': ('Café', unicodedata.normalize('NFD','Café'), False),
    'missing': ('Office', 'Tax', False),
    'case-change': ('Office', 'OFFICE', False),
    'bom-ligature': ('Of\ufb01ce', 'Of\ufb01ce', True),
}
name, folder_name, bom = profiles[mode]
case.mkdir(parents=True,exist_ok=False)
root = case/'receipts'
receipt = root/'Assets'/folder_name/'2024-02-01.txt'
receipt.parent.mkdir(parents=True)
receipt.write_text('synthetic receipt\n',encoding='utf-8')
ledger, automatic, manual = case/'main.bean', case/'auto.bean', case/'manual.bean'
base = f'2024-01-01 open Assets:{name} USD\n'
relative = f'receipts/Assets/{folder_name}/2024-02-01.txt'
texts = {
    ledger: base,
    automatic: 'option "documents" "receipts"\n'+base,
    manual: base+f'2024-02-01 document Assets:{name} "{relative}"\n',
}
for file,text in texts.items():
    file.write_bytes((b'\xef\xbb\xbf' if bom else b'')+text.encode('utf-8'))
inputs = {p:p.read_bytes() for p in (*texts,receipt)}
env = os.environ.copy()
for key in ('BEA_FILE','BEA_TOKEN','BEANCOUNT_LOAD_CACHE_FILENAME','BEA_ENGINE_PYTHON','BEA_ENGINE_DIR'):
    env.pop(key,None)
env.update(BEA_CONFIG_DIR=str(case/'config'),XDG_CACHE_HOME=str(case/'cache'),BEA_NO_UPDATE_NOTIFIER='1')
def run(tag,args,file=ledger,native=False):
    argv = ['bea','--no-input',*map(str,args)] if native else ['bea','--json','--no-input','-f',str(file),*map(str,args)]
    result = subprocess.run(argv,cwd=case,env=env,stdin=subprocess.DEVNULL,capture_output=True,text=True,timeout=25)
    assert all(p.read_bytes()==data for p,data in inputs.items())
    print(json.dumps(dict(tag=tag,args=argv,exit=result.returncode,stdout=result.stdout,stderr=result.stderr,
                         inputs_preserved=True)),flush=True)
print(json.dumps(dict(tag='fixture',account='Assets:'+name,folder='Assets:'+folder_name,
                     nfc=unicodedata.normalize('NFC','Assets:'+folder_name),
                     nfkc=unicodedata.normalize('NFKC','Assets:'+folder_name),bom=bom)),flush=True)
run('base-check',['check'])
run('account',['list','open'])
run('directories',['doctor','directories',ledger,root],native=True)
run('auto-check',['check'],automatic)
run('auto-documents',['list','document'],automatic)
run('auto-on-disk',['list','document','--on-disk'],automatic)
run('manual-check',['check'],manual)
run('manual-documents',['list','document'],manual)
run('manual-on-disk',['list','document','--on-disk'],manual)
```

Actual, both fresh repetitions:

- Base check exits **0**, valid; open listing keeps `Assets:Ofﬁce` or
  `Assets:AＢank` exactly.
- `doctor directories` exits **1** with `no corresponding account
  'Assets:Office'` or `'Assets:ABank'`, although the literal folder account
  is already declared. The invalid-directory status mapping itself works;
  its input comparison is wrong.
- With `option "documents" "receipts"`, check still exits **0**, but
  `list document` exits **0 with no rows**. The dated receipt is present
  under the declared account's matching directory and should generate one
  document with that original account ID. `--on-disk` correctly stays empty
  for generated documents.
- The explicit manual directive lists **one** existing receipt under the
  original name, including with `--on-disk`; checks pass. Separate real
  `add document --account ... --filename ...` controls also write one and
  list/check correctly for both original names. Thus the account and file
  path are supported by the CLI.
- ASCII and canonically decomposed accented directory controls discover
  one generated document and doctor exits **0**. Genuine Tax/uppercase
  OFFICE mismatches stay undiscovered automatically and doctor exits **1**;
  preserve those diagnostics and the existing case sensitivity.

Expected: directory-derived account keys use the ledger's NFC identity,
so an exactly matching supported name finds its dated receipt and passes
folder validation. Preserve distinct NFC names, canonical NFC/NFD matching,
real undeclared-folder diagnostics, generated/on-disk provenance, filename
spelling and all source/receipt bytes.

Root and callers: this defect is inherited from Beancount 3.2.3's
`beancount/core/account.py:195–220` (`account.walk`), which calls
`unicodedata.normalize("NFKC", account_name)` at line 218. Eight independent
native proofs confirm the source name is valid and declared, its folder's
NFC name is declared, but the yielded NFKC name is not.
`beancount/scripts/directories.py:41` checks that yielded ID against account
names and reports the false error. `beancount/ops/documents.py:129–154`
uses the same walker and skips a yielded ID outside `accounts_only`, which
silently drops the receipt. Native automatic loads reproduce the omission;
native explicit/CLI-written document loads retain the one correct document.

The CLI's `bea_engine.compat._canonical_bytes` reads ledger names in **NFC**,
not NFKC. `managed_load` delegates automatic document processing to the
native loader and uses `documents.find_documents` again when checking cached
document findings. `cli.commands.doctor._needs_compat` / `_capture` forwards
ordinary NFC roots to stock bean-doctor and BOM/NFD roots through `scoped`;
both paths retain the walker issue. `_forward_directories` correctly maps
native ERROR lines to exit 1. Cover both routes and local discovery in the
CLI compatibility layer, retaining normal native output and true errors.
Changing only the rendered error, ignoring ERROR lines or changing ledger
account identities would leave the missing documents unresolved.

Fix/acceptance: apply the same NFC account identity to directory walks and
loaded account keys in both automatic document discovery and doctor's native
and helper routes. The default and full-width profiles each discover one
correct generated document, doctor exits 0, and an on-disk filter excludes
the generated entry. Explicit documents and `add document` keep their
original names and paths. Existing accented NFD folders, ASCII behavior,
BOM support, case distinctions and genuine invalid-folder results remain.
Keep all ledger and receipt bytes unchanged. Owning package: CLI; no API or
new dependency is needed. Run owning CLI checks when implementing the fix.

**Resolved 2026-10-23** — fixed: the engine's compatibility layer (`_install_account_walk` in `cli/src/bea_engine/compat.py`) replaces upstream's `account.walk`, which named a document folder's account in NFKC (rewriting the ligature in `Of\ufb01ce` as `Office` and a full-width `\uff22` as `B`), with a walk in NFC, the form the ledger's accounts are read in. Automatic document discovery (`option "documents"`) therefore finds the receipt under the declared account's folder and lists it as a generated document (excluded by `--on-disk`), and `doctor directories` no longer calls that folder undeclared: the frontend routes the operation through the helper when a folder under the document root has a name NFKC would rewrite (`_has_compatibility_name` in `cli/src/cli/commands/doctor.py`), and every other ledger keeps the stock `bean-doctor` and its output. ASCII, accented NFD and genuinely undeclared folders behave as before. Regression tests in `cli/tests/test_document_discovery_compat_names.py` fail without the fix (ligature and full-width). Full suite green apart from the known `test_release` smoke timeout, which passes alone. Shipped in this commit (`cli`).

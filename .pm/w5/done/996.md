An authored **10 USD** payment has one native bank reference. A controlled
local plugin replaces it with one calculated **20 USD** payment in the view,
keeping the native ID. Import correctly recognizes the original 10 USD
repeat, but a real bank correction to **20 USD** is falsely skipped as an
exact duplicate because it agrees with the calculated view. The recorded
source is still 10. A correction to 30 correctly conflicts, as do 20 USD
corrections in no-op/no-plugin controls. No row is filtered or duplicated,
no source leg is inferred, and no cost/price normalization is involved.

Expected follows `cli/docs/IMPORTING.md:548–575`: a changed native-ID source
amount requires review via exit-4 conflict, with unchanged bytes. A display
transformation must not turn a different bank amount into a proven repeat of
the authored source. The plugin's doubled view is intentional in the fixture;
the failure is the native-ID import decision, not the calculated balance.

Put the checkout's `bea` on PATH, replace the directory with a fresh absolute
one, and run twice. The inspected local plugin only multiplies its synthetic
postings and optionally changes narration; it makes no service calls or
external writes. Config/cache are isolated, stdin is closed/no TTY, each CLI
call has a timeout, separate streams, duration, ledger/plugin hashes and a
before/after source-input check. The script intentionally replaces the bank
CSV between test amounts; each invocation preserves the input it receives.

```python
import hashlib, json, os, pathlib, subprocess, time
case = pathlib.Path('/abs/transformed-id-case')
mode = 'scale2'  # scale2-header, scale1, no-plugin
case.mkdir(parents=True)
plugin = '''from decimal import Decimal
from beancount.core.data import Transaction
__plugins__ = ("transform",)
def transform(entries, options, config=None):
    out = []
    for entry in entries:
        if isinstance(entry, Transaction):
            posts = [p._replace(units=p.units._replace(number=p.units.number*Decimal(FACTOR)))
                     for p in entry.postings]
            entry = entry._replace(meta=entry.meta.copy(),postings=posts,
                                   narration="Derived row" if HEADER else entry.narration)
        out.append(entry)
    return out, []
'''
plugin = plugin.replace('FACTOR',repr('1' if mode=='scale1' else '2')).replace('HEADER',str(mode=='scale2-header'))
module = case/'qa_transform.py'
module.write_text(plugin,encoding='utf-8')
ledger = case/'main.bean'
ledger.write_text('option "operating_currency" "USD"\n'
                  + ('option "insert_pythonpath" "TRUE"\nplugin "qa_transform"\n' if mode!='no-plugin' else '')
                  + '2024-01-01 open Assets:Cash USD\n'
                    '2024-01-01 open Expenses:Food USD\n'
                    '2024-02-01 * "Source row"\n  bank_id: "source-10"\n'
                    '  Assets:Cash -10.00 USD\n  Expenses:Food 10.00 USD\n',encoding='utf-8')
source = case/'bank.csv'
original = {p:p.read_bytes() for p in (ledger,module)}
env = os.environ.copy()
for key in ('BEA_FILE','BEA_TOKEN','BEANCOUNT_LOAD_CACHE_FILENAME','BEA_ENGINE_PYTHON','BEA_ENGINE_DIR'):
    env.pop(key,None)
env.update(BEA_CONFIG_DIR=str(case/'config'),XDG_CACHE_HOME=str(case/'cache'),
           BEA_NO_UPDATE_NOTIFIER='1')
def run(tag,args):
    cmd = ['bea','--json','--no-input','-f',str(ledger),*map(str,args)]
    source_before = source.read_bytes() if source.exists() else None
    started = time.monotonic()
    r = subprocess.run(cmd,cwd=case,env=env,stdin=subprocess.DEVNULL,
                       capture_output=True,text=True,timeout=25)
    print(json.dumps(dict(tag=tag,args=cmd,exit=r.returncode,stdout=r.stdout,stderr=r.stderr,
                          files_preserved=all(p.read_bytes()==v for p,v in original.items()),
                          source_preserved=(source.read_bytes() if source.exists() else None)==source_before,
                          source_sha256=hashlib.sha256(source_before).hexdigest() if source_before is not None else None,
                          duration=round(time.monotonic()-started,3),stdin_mode='closed DEVNULL',tty=False,
                          ledger_sha256=hashlib.sha256(ledger.read_bytes()).hexdigest())),flush=True)
run('check',['check'])
run('full',['list','transaction','--limit','100'])
run('on-disk',['list','transaction','--on-disk','--limit','100'])
run('facts',['query','SELECT account,sum(number) GROUP BY account ORDER BY account'])
args = ['import',source,'--csv','date=Date,narration=Description,amount=Amount,id=Reference',
        '--account','Assets:Cash','--default-account','Expenses:Food']
for amount in ('10.00','20.00','30.00'):
    source.write_text('Date,Description,Amount,Reference\n'
                      +f'2024-02-01,Source row,-{amount},source-10\n')
    run('preview-'+amount,args)
    run('apply-'+amount,[*args,'--apply'])
```

the known authored −10 owner. `_same_row` therefore reports a duplicate.
The new 973 guard only retains a raw owner when loaded `found` is None and
no amount agrees; here loaded `found` exists and agrees with the wrong source
amount. The source index itself is complete and has the correct −10 value.

**Resolved 2026-10-23** — fixed: `_under_id` (`cli/src/bea_engine/importing.py`) no longer lets a loaded entry that agrees with the incoming row settle a native bank ID on its own. For a native identity it now also consults the transactions the files spell under that ID, and when such a row exists and nothing it spells agrees with the incoming row, that authored row is the owner, so the change is judged against it. A plugin that scales a written 10 USD payment to 20 USD in the view therefore no longer turns a real bank correction to 20 USD into a "duplicate": it conflicts at exit 4 with the file unchanged, while the original 10 USD repeat still skips. Generated IDs, reused references (the nearest agreeing owner still wins), filtered-row and open-lot fallbacks are unchanged. Regression tests in `cli/tests/test_import_native_id_authored_amount.py` (scaled view and no-plugin control, repeat and correction); the scaled-view correction fails without the fix. Full suite green (10496 passed).

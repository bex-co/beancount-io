# Report completed batch edits when a later include is read-only

**Minor · cli · 25–45m · A1 · worker1.** `bea update transactions`
updates a writable first include, then hits a read-only second include and
exits3 saying **“nothing was written”**. JSON has **no `error.result`**,
so it omits the completed row and every unwritten row. Human output makes
the same false claim. A fresh listing/native load proves R1 moved10USD to
Travel and cleared its flag; R2/R3 remain unchanged. The permission refusal
and exit3 are appropriate; the confirmed partial write needs a truthful
outcome. No product fix implemented.

Use `reverse` for reverse mapping order or `human` for a human apply.

and `none` leaves all three writable (complete-write control). Actual file
write order stays a, b, c. The three ordinary payment headers have spaces.

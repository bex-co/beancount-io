# Price export writes a partial snapshot before discovering a blocked directory

**Minor · 30–45m · cli · A1.** A predictable destination topology conflict
leaves an incomplete export that the error does not describe. Preflight needed
directories before copying; do not build a broader transactional export system.

Found 2026-10-08 on `37624cef`, checkout `bea 0.3.1`, Python 3.13.3,
macOS/Darwin. Real bounded subprocesses, closed stdin, no TTY, isolated absolute
config/cache and disabled update notifier. Synthetic local fixtures; no price
network call, credentials, or hosted ledger mutation is required.

## Minimal reproduction

From a disposable directory, create these files:

```sh
mkdir -p source/sub output
printf 'include "sub/accounts.bean"\n' > source/main.bean
printf '2026-01-01 open Assets:Cash USD\n' > source/sub/accounts.bean
printf 'KEEP EXISTING FILE\n' > output/sub
bea --json --file "$PWD/source/main.bean" check
bea --json --file "$PWD/source/main.bean" price export --output "$PWD/output"
```

The source check exits **0**. Export exits **1**, stdout is empty, and stderr
is a JSON validation error with this message (absolute path abbreviated):

```text
FileExistsError: [Errno 17] File exists: '/absolute/output/sub' Pass --debug before the command for a traceback.
```

Before export the output contains only the regular file `sub`. Afterward it
contains `sub` **and a newly copied main.bean**, which includes the absent
`sub/accounts.bean`. The error has no `result` or list of completed copies.
The existing `sub` bytes and both source files remain unchanged: no data-loss
claim is made. A second export without changes now exits **2** because its own
partial `main.bean` is an existing destination, and advises `--force`, which
cannot solve a regular file blocking the required directory.

Repeated on two pristine source/output fixture pairs in fresh processes with
the same outcome. Working control: an empty destination exports both ledger
files, exits **0**, and a fresh `bea check` on its main.bean also exits **0**.

Expected: refuse this deterministic file-versus-directory conflict before any
output copy, name the blocking path, and advise choosing another directory or
moving that file. USAGE's Output destinations section promises path-specific
refusal before writes for export collisions; predictable blockers should be
part of the same destination plan. This request does not assume every runtime
I/O failure can be predicted or every failed export can be rolled back.

## Cause, repair and scope

`cli/src/bea_engine/managed_load.py:766–795` validates planned destination
leaves, source identity, containment and existing files, but not the parent
directories needed by those leaves. `output/sub/accounts.bean` does not exist,
so the regular file `output/sub` is missed. The root copy at lines 797–801
succeeds before `dest.parent.mkdir` for the included file raises at line 799.
The generic error loses the already appended `written` list.

Before the first write, check the export root and each required ancestor of
the planned ledger/feed/attachment destinations. A regular file blocking a
required directory must be a usage refusal, including with --force: the flag
allows replacing destination files, not deleting unrelated directory blockers.
Keep source alias/containment protection and normal overwrite behavior.
Add real-command regressions for this two-file split ledger, retry/no-output
preservation, --force, and an empty-destination success/check control. Run
`make check-all` in cli when implementing. No new dependencies/API changes.

Caller search: one frontend `_export` handler dispatches the engine's
`price_export`, which calls `export_portable`; all portable exports, including
default destinations and those with feed or attachment subdirectories, share
the planner. Runtime proof covers copied ledger files only; feed/attachment
variants, permissions failures, races and other platforms remain unverified.

Dedupe: searched all board states for export partial writes, directory
collisions, parent blockers, FileExistsError and NotADirectoryError; no matching
open item. Completed w3/436 and w3/m48 protect existing leaf files, w4/171 and
w4/172 protect containment/source aliases, and w1/044 preserves attachment
symlink names. None covers this ancestor obstruction. `git log -S 'existing =
[dest for dest in planned'` traces the leaf-only guard to `dbd08c40`; current
history contains no parent-plan fix. This is a missed branch of the shipped
collision guard, not a server/deployment issue.

Acceptance: both pristine repros exit 2 with a useful blocking-path diagnostic,
preserving the entire output file list and bytes; retry behaves identically;
--force cannot bypass the directory blocker; clean exports still validate.

Ignored sanitized evidence: `cli/tmp/qa-20261008-cli/export-console.jsonl`,
`export_sweep.py`, `export_retry.py` and `transcript.jsonl`, with source hashes,
exact argv/cwd/environment, separate streams/exits and output-file lists. The
public repro above is self-contained. No product fix was implemented.

---

**Resolved 2026-10-10** — `price export` now checks the directories its plan needs before the first write. A non-directory at a required ancestor (the reported `output/sub`), a directory standing where a planned file must go, and an `--output` that is itself a file are each refused with exit 2, naming the blocker and the destination it obstructs and saying nothing was written. `--force` does not bypass the refusal. Shipped in `ffdd5d8d` (`cli`).

Real-command regression tests cover the two-file split ledger with and without `--force`, each run twice so the retry is proven to see no leftover; they compare the destination's full path list and bytes and the source tree before and after. A clean destination still exports, passes `bea check`, and re-exports with `--force`. Four of the five tests fail with the fix reverted. `docs/USAGE.md` Output destinations states the rule. `make check-all` passed. Feed and attachment subdirectories go through the same plan but have no dedicated blocker test; permission failures, races and other platforms were not exercised.

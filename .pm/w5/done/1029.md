# Return every written include's diff after a batch update

**Minor · cli · 20–35m · A1 · worker1.** Batch updates across included files
write all requested changes and report the right count, but the apply response
omits diffs for every earlier written file. Their JSON rows are `status: ok`
with `diff: ""`; the combined JSON diff and human output show only the final
file. Preview shows all files. An agent keeping the returned change record
therefore loses part of the edits it just made. This is an output defect;
actual files and financial values are correct. No product fix implemented.

Real local CLI QA, 2026-10-25, clean main
`dd2c6c48ce1c8715506f54537e3e4afc7a3a9e1d`; runtime identical to frozen
`94cb785b1319e309134a7f79af9922186c07751a` (1,630 tracked CLI files).
Checkout `bea 0.3.1`, frontend Python 3.13.3, existing managed Python 3.12.10 /
Beancount 3.2.3 / Beanquery 0.2.0, macOS 26.5.1 arm64. Bounded fresh
subprocesses, closed stdin/no TTY, isolated config/cache, notifier disabled.
Synthetic local books; no plugins or services.

## Cause, repair and dedupe

`cli/src/bea_engine/ledger/updating.py:837` initially captures original
`file_texts` / `file_lines`. The apply loop refreshes and overwrites both maps
at **:853–854** before each file writes. This is appropriate for validating
against already persisted earlier edits. After the loop, however, `_row_payload`
at **:894** and combined diff construction at **:896–907** use those same
refreshed maps as their before-image. They already contain every earlier
file's changes. Reapplying the same line replacements is idempotent, so those
rows/files produce empty diffs. Only the last file's map is still original.

`_row_payload` has two callers: preview (:824), whose maps remain pristine,
and apply (:894), whose maps were overwritten. Frontend
`cli/src/cli/commands/update.py:208–250` emits the combined result or renders
its diff without reconstructing history, so both JSON and human output inherit
the omission. The helper JSON/engine update adapter is the shared source.

Preserve immutable original text/lines for reporting, or save each planned
row/file diff before replacing its file, while retaining fresh snapshots for
all later validation and compare/write checks. Do not remove or weaken those
fresh loads. Build the result from the actual written subset; rejected and
unchanged rows must retain their current meanings. No dependency or engine
fork is needed.

Dedupe: **5,641 board Markdown files / 43 non-done milestone scopes**,
including blocked queues and all completed history, had no overlapping match.

Acceptance: in two-file, three-file and reversed-row cases, combined apply
diff equals the actual full before/after file diff and every written row has
its original nonempty hunk; human output shows every written file. Preserve

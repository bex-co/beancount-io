# Preserve native book units when deciding and reporting padding

**Minor · cli · 40–60m · A1 · worker1.** A native-valid token book already
holds **0.123456789012345678 SHIB**, but `add balance --pad-from` refuses the
matching assertion at exit 1 instead of omitting the unnecessary pad and
writing the assertion. Its own diagnostic says the assertion already holds.
For a target of 1 SHIB, the pad correctly inserts
**0.876543210987654322 SHIB**, but JSON `pad.amount` and human output report
**0.87654321098765432**. Reordering the first two movements or using a
28-digit acquisition restores both behaviors. Stored holdings remain correct;
the CLI's book-unit fold misreads them. No product fix implemented.

Environment: 2026-10-27, immutable CLI
`9ff5cc6184bc75cdaf4e5a8a79e7fc09089e95fa` (1734 tracked CLI fingerprints),
identical to reviewed main. Checkout bea 0.3.1, frontend Python 3.13.3,
existing managed Python 3.12.10 / Beancount 3.2.3 / Beanquery 0.2.0,
macOS 26.5.1 arm64. Fresh synthetic books, explicit local roots, bounded
offline commands, isolated child config/cache, notifier disabled, closed
stdin/no TTY, separate streams/exits/timings/hashes, HOME unchanged. Amounts
and zero-price weights are stated; there are no plugins, inferred quantities
or wide negative literals. Every primary/reference/export book validates

## Reproduction

Create a fresh `main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Wallet SHIB
2024-01-01 open Equity:Opening USD
2024-01-01 open Equity:Adjustments SHIB
2024-01-02 * "Token movement"
  Assets:Wallet 12345678901.123456789012345678 SHIB @ 0 USD
  Equity:Opening 0 USD
2024-01-03 * "Token movement"
  Assets:Wallet -12345678901 SHIB @ 0 USD
  Equity:Opening 0 USD

2024-01-31 balance Assets:Wallet            0.123456789012345678 SHIB
```

Under the isolated environment above:

```sh
bea --json --no-input --offline --file /absolute/main.bean check
bea --json --no-input --offline --file /absolute/main.bean add balance --date 2024-01-31 --account Assets:Wallet --amount '0.123456789012345678 SHIB' --pad-from Equity:Adjustments
```

Check exits 0. Independent unwrapped native inventory has exactly the stated
fraction. The add exits **1**, writes nothing, and says:

```text
The change would leave the ledger invalid; nothing was written.
Proposed append (not written): Unused Pad entry. The 2024-01-31 assertion ... already holds, so this pad would have nothing to fill; it need not be added.
```

Repeat gives the same unchanged-file refusal. The documented behavior in
[USAGE](../../cli/docs/USAGE.md#adding-directives) and completed
[w3/224](../w3/done/224.md) is to omit the pad and write the matching assertion
alone. Removing `--pad-from` succeeds immediately, writes just that assertion
and preserves the native fraction; no balancing entry is needed.

In a **second pristine copy**, assert 1 SHIB with the same padding source:

```sh
bea --json --no-input --offline --file /absolute/needed.bean add balance --date 2024-01-31 --account Assets:Wallet --amount '1 SHIB' --pad-from Equity:Adjustments
```

This exits 0 and writes Pad + Balance. JSON says
`pad.amount: {"number":"0.87654321098765432","currency":"SHIB"}`.
Human output says `the pad inserts 0.87654321098765432 SHIB` too.
Native reload and the generated `P` transaction instead show the actual
**0.876543210987654322 SHIB**, and Wallet ends at exactly **1 SHIB**.
An independent handwritten Pad/Balance reference produces the same actual
posting. The public contract in completed [611](./done/611.md) requires
the reported amount to name what was inserted, not a rounded reconstruction.
Repeat writes zero and leaves the valid book unchanged.

Move the whole-token return before the receipt, preserving the same final
native fraction: the matching padded command now exits 0 with one Balance,
`pad: null` and the omission explanation; the needed-pad answer reports the
actual 18-decimal difference. Replacing `12345678901` by `1234567890`
throughout gives the same working 28-digit control. No force, tolerance
relaxation or fictitious movement is needed.

Put checkout bea on PATH, save this standalone recipe and use a fresh path:

```sh
python3 recipe.py /absolute/unused/pad-case wide standard root /absolute/managed-engine/bin/python
```

Activos/Capital, EUR zero weights and split destinations. It checks the two
independent writes and repeats, the plain-assertion workaround, handwritten
native references, actual generated padding and full export/native reload.
Native oracles import upstream modules only, separate from the source-bound

## Root cause and bounded repair

[`book_units`](../../cli/src/bea_engine/ledger/write.py#L1630) uses
`sum(posting.units.number ..., Decimal(0))`. The artificial first addition
rounds the native accepted 29-digit receipt to 28 before the whole-token
return reduces it to an 18-digit residual. The helper returns
**0.12345678901234568**, while native inventory retains
**0.123456789012345678**.

[`_balance`](../../cli/src/bea_engine/ledger/adding.py#L546) reads that value
before padding (:627). If native validation correctly rejects an unused pad,
the retry (:699–703) compares the asserted fraction with the faulty book sum;
the spurious **2e−18** difference exceeds the native 18-decimal assertion's
tolerance, so it rethrows instead of appending the assertion alone.
The successful needed-pad branch (:762–786) subtracts the same wrong held
number for `pad.amount`, even though upstream generated the actual adjustment
correctly. Human output consumes that returned amount.

Four actual-helper captures confirm context precision 28: wide matching
reads as the wrong fraction, reordered/boundary matching are correct, and
the successfully padded wide book is misread as
**1.000000000000000002 SHIB** even though native holds exactly 1.
These are product-helper probes, separate from the independent native loads.
The helper was introduced by `4a184f8b5` for 611; no later native first-value
repair is present in it.

Preserve the first number and actual zero/no-op operands without artificial
arithmetic, using the native inventory rule while retaining ordinary native
arithmetic for real nonzero additions/reductions. Keep this helper's scalar
per-currency result, **strictly before the assertion date**, including child
accounts and prior generated padding. Correct remaining book units must
drive the existing pad omission/tolerance decisions and the actual reported
adjustment. Preserve the snapshot, duplicate/conflict and credit-sign rules;
do not widen tolerance, globally raise precision or change native validation.
No dependency or API change is needed. Add meaningful real CLI regressions
and run `make check-all` inside `cli/` when implementing.

Caller search also finds already-recorded and existing-pad messages, plain
used-pad refusal (:929), balance-recovery hints in `write.py:1691`, and the
imported used-pad policy in `importing.py:2713`. Keep their book-unit view.
Their original ordinary controls pass below; a wide import-policy failure
or additional recovery-hint precision defect is not claimed here.

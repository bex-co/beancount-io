# Give currency-error hints that work with amount-column headers

**Minor · cli · 15–25m · A1 · worker1.** An amount column named `EUR`
contains `-€12.50`, and the bank account permits USD and EUR. The currency
guard correctly refuses to book it as the operating currency USD, but
recommends `currency=EUR`. Following that setting selects the existing
amount column as the currency column and fails with `'-€12.50' is not one
commodity`. The equivalent INR/₹ case behaves identically. The account
already permits the correct currency. No product fix implemented.

Environment: 2026-10-24, clean main `df6b9d621924cb70bcf01634640956320731afb1`, CLI byte-identical
to frozen `ee4b7702516da4535bb3b478e2efe9913b09481b`. Checkout `bea 0.3.1`,
frontend Python 3.13.3, managed Python 3.12.10 / Beancount 3.2.3 /
Beanquery 0.2.0, macOS 26.5.1 arm64. Bounded fresh subprocesses, closed
stdin/no TTY, isolated absolute config/cache and notifier disabled.
Synthetic local ledgers and bank exports only.

## Standalone reproduction

Put this checkout's `bea` on PATH, save the following as `recipe.py`, and
run `python3 recipe.py /absolute/unused/book EUR collision json`.
Use `human` as the last argument for ordinary terminal messages. The
recipe preserves the CSV, captures arguments/cwd/environment, stdin/TTY
mode, streams, exit codes, durations and before/after hashes, and writes
them to `results.json`. It follows the hint by adding its setting to the
existing mapping, using one `--csv` option.

For `EUR collision`, the three import commands exit **2, 2, 2**:

1. Initial preview: `column 'EUR' carries '€' (EUR), but the row would post
   USD. Name the commodity with --csv currency=EUR, or open the source
   account for EUR. Nothing was written.`
2. Followed preview: `column 'EUR': '-€12.50' is not one commodity`.
3. Followed apply: the same refusal and exit 2.

The ledger remains byte-identical, with Bank 1000 EUR and Equity −1000
EUR; every CLI and independent native check passes. This is an unusable
recovery suggestion. No wrong-currency write or accounting data loss is
claimed. `INR collision` gives the same progression for the `INR` amount
column and `-₹12.50`.

Expected: after detecting the symbol mismatch, give a remedy compatible
with these actual headers. For example, explain renaming the amount column
to a unique name and updating `amount=…` before supplying the constant, or
adding/mapping a separate currency column. Keep the initial refusal,
currency precedence and declared multi-currency account intact. The error's
`open ... for EUR` alternative does not explain what to do with this account
already open for USD and EUR.

`cli/docs/IMPORTING.md:121–130` explicitly gives an existing currency column
priority and treats `currency=CODE` as a constant only when the file has no
such column. The recommended setting therefore cannot be a constant for
this file. The documented selection rule is also covered by the working
column control below.

Verified nearby controls, in each currency and both output modes:

| Recipe mode | Relevant difference | Result |
| --- | --- | --- |
| `renamed` | Amount header becomes `Amount`; use `amount=Amount,currency=EUR` or INR | Preview succeeds, apply writes once, repeat skips |
| `restricted` | Source account opens for EUR or INR alone; omit currency mapping | Its currency wins over operating USD and the import succeeds |
| `column` | Amount header is `Amount`; a real `USD`-named currency column contains EUR or INR; map `currency=USD` | Column values win and the foreign-currency import succeeds |

Each control ends with Bank **987.50** and Food **12.50** in the correct
currency, Equity −1000, and no USD postings. Repeats preserve ledger bytes
and every CSV stays unchanged. The restricted-account case is a comparison
fixture; this finding does not propose narrowing a genuine multi-currency
account as an automatic repair.

The exact public recipe was verified in **16 fresh cases / 96 CLI commands /
32 independent uncached native loads**: two currencies × four modes × two
repetitions, with **4 gap cases, 12 controls and 24 human import commands**.
The six-case pilot separately executed 36 CLI commands and 12 native loads.

## Cause and scoped repair

`cli/src/bea_engine/csv_mapper.py:1685–1705`, `_check_cell_symbols`, always
interpolates the symbol's commodity into `--csv currency={named}` without
checking whether that name is already a header containing amount text.
`_check_columns` (:1574–1593) deliberately sets `_constant_currency` only
when `counts[constant] == 0`. With the header present, row selection at
:1849 reads the amount cell as currency and `require_commodity` at
:1870–1885 rejects it. Both individual validations work; the suggested
transition between them cannot recover this input.

Tailor the advice to the headers and current mapping. Keep existing column
priority, known-commodity checks, symbol contradictions and successful
constant-currency imports. The scoped fix is recovery advice, with a
regression that follows the suggested action to a successful preview and
checks unchanged input/ledger on refusals. It needs no new dependency or
currency syntax.

Caller search finds one active `CsvImporter` construction in
`cli/src/bea_engine/importing.py:309` and one `_check_cell_symbols` call in
CSV extraction (:1886), shared by the amount, debit/credit and direction
layouts. The runtime finding here uses single-amount layouts; debit/credit
and direction variants are source-traced scope, not additional reproduced
claims. REST/GraphQL/MCP are outside this local CLI path.

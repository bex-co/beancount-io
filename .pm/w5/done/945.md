# Refuse init when a case-variant target would shadow the existing default ledger

**Minor · cli · 20–30m · A1/A2.** On case-insensitive APFS,
`--file main.BEAN init` creates a new empty ledger beside `main.beancount`.
The next ordinary command selects the new template and reports 0 USD instead
of the existing 100 USD. The old ledger's bytes remain intact. The lowercase
target is correctly refused with conflict exit 4. No product fix implemented.

Real CLI QA, 2026-10-21, HEAD `fd9033f38` (initial reproduction on
`31828e85f`, CLI unchanged), checkout `bea 0.3.1`, macOS 26.5.1 arm64,
frontend Python 3.13.3, existing managed Python 3.12.10. Fresh subprocesses,
closed stdin/no TTY, absolute isolated config/cache, notifier disabled,
no inherited `BEA_FILE`/`BEA_TOKEN`. Synthetic files only.

Create a fresh `/abs/books/main.beancount`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Equity:Opening USD
2024-01-02 * "Opening"
  Assets:Cash 100.00 USD
  Equity:Opening -100.00 USD
```

Run from `/abs/books`, on a filesystem where `main.BEAN` and `main.bean`
refer to the same filename, with `bea` on PATH and the isolated child
environment above:

```sh
bea --json report overview --time 2024 --conversion USD
bea --json --no-input -f /abs/books/main.BEAN init --currency USD --date 2024-01-01
bea --json report overview --time 2024 --conversion USD
bea --json -f /abs/books/main.beancount report overview --time 2024 --conversion USD
bea --json -f /abs/books/main.BEAN check
bea --json -f /abs/books/main.beancount check
```

All six commands exit **0**, with empty stderr. The first report names
`main.beancount` and returns `net_worth.USD = "100.00"`. Init reports
`created: .../main.BEAN`. The next report names `main.bean` and returns
`net_worth.USD = "0"`. Explicitly reading the old file still returns
`"100.00"`; both ledgers pass check and the old file is byte-for-byte unchanged.
Thus this is default-ledger selection changing, not lost source data.
`main.BeAn` reproduces the same result. Both spellings were reproduced twice
in separate fresh directories.

Working control: repeat from a pristine copy but pass `-f /abs/books/main.bean`
to init. It exits **4**, says init never shadows an existing root ledger,
creates no file, and the following ordinary overview still returns 100 USD.
Custom `other.BEAN` creation beside the same book and `main.BEAN` creation in
an empty directory both succeed and pass check. The custom file does not
change the existing book's default selection. These controls also ran twice.

Expected: refuse before creating a file whenever the requested target would
occupy a default discovery name beside an existing default root. This is the
existing w3/346 contract, already enforced for lowercase names. Preserve the
old file and default selection, with the same conflict exit 4.

Cause: `cli/src/cli/commands/init.py:210` enters the sibling-root check only
when `file.name` exactly equals one of `DEFAULT_ENTRY_FILE_FALLBACKS`' names.
Python's string comparison rejects `main.BEAN` and `main.BeAn`, even though
the tested filesystem treats both as `main.bean`. Consequently no sibling
check runs before the engine creates the template. `Context.entry_file`
(`cli/src/cli/context.py:147`) subsequently checks `main.bean` first and
correctly finds that new file through its case alias.

Fix the pre-creation target/default-name comparison to recognize filesystem
case aliases, then apply the existing sibling-root refusal. Keep custom
filenames and fresh-directory creation working. The init command is the
writer; default discovery is shared by subsequent ledger commands. The
creation engine itself does not know this cwd-discovery policy. No change to
accounting or report arithmetic is needed.

Dedupe: whole-board searches, including done/blocked, plus the open milestone
scan found no open coverage. Completed **w3/346**, shipped in `2e4d25ee0`, is
the parent; its regression uses only lowercase targets. Completed w5/865 and
w5/870 fixed case-sensitive candidate enumeration for format output and leaf
writes, respectively; neither changes init's default-filename comparison.
Targeted history contains no later repair of this check.

Acceptance: the six-command journey refuses init at exit 4 for both tested
case aliases, creates no template, and keeps ordinary reports at 100 USD.
The lowercase refusal remains correct. Add meaningful regression coverage
for case-insensitive filesystems and preserve valid custom-file/empty-target
creation. Case-sensitive filesystems were not exercised; the wrong default
selection claim is specific to an actual filesystem alias.


---

**Resolved 2026-10-22** — fixed: `init` (`cli/src/cli/commands/init.py`) now runs its existing sibling-root refusal when the target is a case-variant of a default discovery name (`main.BEAN`, `main.BeAn`) and the directory's filesystem folds case (`_folds_case`, probed on a name that exists), so a case alias beside an existing `main.beancount` exits 4 with nothing created and the default ledger still reads 100 USD. The lowercase refusal, custom names such as `other.BEAN`, creation in an empty directory and case-sensitive volumes (where the variant is just another file) are unchanged. Regression tests in `cli/tests/test_init_case_alias_shadow.py` fail without the check on this case-insensitive volume. Full suite green apart from the known `test_release` smoke timeout, which passes alone. Shipped in this commit (`cli`).

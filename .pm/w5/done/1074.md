# Preserve native unit quantities when Holdings groups lots

**Minor · cli · 35–50m · A1 · worker1.** Holdings rounds an accepted
29-digit token holding before combining lots. Native units total
**0.123456789012345678 SHIB**; commodity grouping reports
**0.12345678901234568**. Swapping the two account names restores the correct
group total without changing any quantity. Account grouping still loses
the last two fractional digits of the wide holding. Adding a final offset
leaves native **zero** units in three surviving lots, but Holdings invents
**2e−18 SHIB** and supplies an average cost instead of the documented `null`.
JSON and human reads exit 0 with `ledger_valid: true`, `valuation: complete`;
source files stay byte-identical. No product fix implemented.

Environment: 2026-10-27, immutable CLI source
`9ff5cc6184bc75cdaf4e5a8a79e7fc09089e95fa` (1734 tracked CLI files),
fingerprint-identical to reviewed main. Checkout bea 0.3.1, frontend Python
3.13.3, existing managed Python 3.12.10 / Beancount 3.2.3 / Beanquery 0.2.0,
macOS 26.5.1 arm64. Fresh synthetic roots, explicit paths, bounded offline
subprocesses, isolated child config/cache, notifier off, closed stdin/no TTY,
separate streams/exits/timings/hashes, HOME unchanged. Every quantity and

## Reproduction

Create a fresh `main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Alpha SHIB
2024-01-01 open Assets:Beta SHIB
2024-01-01 open Equity:Opening USD
2024-01-01 price SHIB 1 USD
2024-01-02 * "Tokens held"
  Assets:Alpha 12345678901.123456789012345678 SHIB {0 USD}
  Equity:Opening 0 USD
2024-01-03 * "Offsetting token holding"
  Assets:Beta -12345678901 SHIB {0 USD}
  Equity:Opening 0 USD
```

With the isolated environment above:

```sh
bea --json --no-input --offline --file /absolute/main.bean check
bea --json --no-input --offline --file /absolute/main.bean report holdings --time 2024-01 --group-by commodity
bea --no-input --offline --file /absolute/main.bean report holdings --time 2024-01 --group-by commodity
bea --json --no-input --offline --file /absolute/main.bean report holdings --time 2024-01 --group-by account
```

Independent unwrapped Beancount inventory retains both positions and its
`reduce(convert.get_units)` yields **0.123456789012345678 SHIB**.
Commodity JSON instead has `units.number: "0.12345678901234568"`; the human
quantity is **0.123456789012345680 SHIB**. The account row for Alpha has
`12345678901.12345678901234568`, where native Alpha still holds
`12345678901.123456789012345678`. These are already wrong in JSON before
the table formats them.

Rename Alpha to Beta and Beta to Alpha, preserving their postings. Native
combined units are unchanged; commodity grouping now correctly answers
`0.123456789012345678`. The per-account wide holding remains rounded.
Replace the whole-token component `12345678901` by `1234567890` throughout
the original fixture: its 28-digit acquisition and final native residual
are preserved correctly in both groupings.

For the zero-unit boundary, start from the original wide fixture and append:

```beancount
2024-01-04 * "Offset fraction in separate lot"
  Assets:Beta -0.123456789012345678 SHIB {0 USD}
  Equity:Opening 0 USD
```

Native inventory has **three distinct cost/date lots**, whose units reduce
to empty. Holdings must retain the group because those positions still exist,
with units 0 and `average_cost: null`, as
[USAGE](../../cli/docs/USAGE.md#reports) and completed [947](./done/947.md)
specify. It instead reports `units.number: "2E-18"`, human
**0.000000000000000002 SHIB**, and a non-null zero average. The erroneous
nonzero unit test takes the division branch. The unit comparison is the
finding; normal native rounding during a real multiplication or addition
must remain intact.

Put checkout bea on PATH, save the standalone recipe below, and run:

```sh
python3 recipe.py /absolute/unused/holdings-case wide standard root /absolute/managed-engine/bin/python
```

above. `renamed included` uses Activos/Capital, EUR prices and a split journal.
Each profile checks all three conversion modes, filtered accounts, human and

## Cause and repair

[`_holdings`](../../cli/src/bea_engine/report.py#L461) receives the correctly
preserved per-account inventories, then creates each group with
`lots.setdefault(key, [Decimal(0), Decimal(0), set()])` (:497).
`found[0] += number` (:498) adds a first 29-digit quantity to artificial zero,
rounding it to the engine's normal 28-digit context before a real offset can
reduce it to 18 digits. Accounts are traversed by sorted name, so which
account contributes first changes the commodity result. A group keyed by
account still rounds that account's first wide quantity. The small phantom
left after a genuine zero total also reaches the `basis / units` average
branch (:534). The unit view in all three conversion modes and account
filters uses this same accumulator.

The real CLI route is
[`holdings`](../../cli/src/cli/commands/report.py#L458), which calls the
engine's holdings dispatch (:131); human and JSON consume the same groups.
This predates the `fa094852a` setdefault refactor: initial Holdings
`acb7868e4` also initialized the group to zero then used `found[0] += number`.
There is no later first-value repair in this grouping stage.

Preserve a group's first quantity and actual zero/no-op operands without
artificial arithmetic, following the native inventory rule already used by
the shared inventories. Keep genuine nonzero sums and reductions at native
precision, and retain the group while any lot remains. A native zero unit
group has unavailable average cost; it is never made empty by a display
value. Preserve cost/date/label keys until the intended grouping, existing
basis arithmetic, quote precedence/provenance, filters and missing-price
policy. No global precision increase, formatting workaround, quantity
restriction or dependency/API change is needed. Implement real CLI regression
coverage and run `make check-all` inside `cli/` when fixing.

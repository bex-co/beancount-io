# Files: Edit and its advertised ⌘E shortcut switch to edit mode but leave focus on the page body, so the text typed next is dropped

**Severity:** minor (keyboard, file editing). **Owner:** dashboard. **Estimate:** 30–45 minutes including tests. **A2:** the file view advertises "Edit ⌘E" as the quick way to start typing in a ledger file. Pressing it, or the Edit button, switches the editor to edit mode, but keyboard focus is left on `<body>`. The keystrokes that follow go nowhere, and the reader has to click into the editor first. A link that opens the same file already in edit mode puts the caret in the editor. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-18 against `https://beancount.io` (entry chunk `main-LGv2TZLj.js`), headless Chromium 153 at 1440×1000, English, isolated profile, signed in as the QA owner on its disposable ledger. Local HEAD `0087162cd`. Nothing was saved: every attempt left through Cancel → Leave Without Saving, and the file's blob and last commit were unchanged afterwards.

## Repro

1. Open `/ledger/<owner>/<ledger>/files/blob/main/main.bean` on a ledger you can write to, and wait for the read-only editor and the "Edit ⌘E" button.
2. Do one of the following: press ⌘E (Ctrl+E), click **Edit**, or Tab to **Edit** and press Enter. In all three cases the toolbar changes to Save and Cancel.
3. Read `document.activeElement`: it is `BODY` in all three cases, checked 1.5 s after the switch.
4. Type `qa`, then press **Cancel**. **Actual:** the editor leaves edit mode without an Unsaved Changes question, because the typed text never reached the editor.
5. Control: open the same file at `…/main.bean?editMode=true`. Focus is on Monaco's input (`div.native-edit-context`, "Editor content"). Typing `qa` and pressing Cancel opens Unsaved Changes, so the text reached the buffer.

The same happens when ⌘E is pressed while the More actions menu is open. The menu closes and edit mode starts, with focus on the body.

**Expected:** entering edit mode from the read view, by ⌘E or Edit, puts keyboard focus in the editor so typing continues at once. The caret stays where the reader was, or goes to the end of a Beancount file as it does when the page opens in edit mode.

## Cause

- `dashboard/src/features/ledger-editor/file-editor/components/ledger-file-view/text-file-view.tsx:159-181`: `handleEditClick` (the Edit button and the ⌘E capture listener) only flips the URL flag (`onEnterEditMode`).
- The same file, `:266-285`, then swaps `ViewModeActions` for `EditModeToolbar`. The Edit button that had focus unmounts, so focus falls to `<body>`.
- `…/ledger-file-view/text-editor.tsx:203-219`: the persistent Monaco editor focuses itself only in `handleEditorMount`, and only when it mounts editable (`?editMode=true`). The effect at `:76-81` that runs when `readOnly` flips only toggles the `hide-cursor` class. Nothing focuses the editor on the switch from read-only to editable.

The served `ledger._ledgerOwner._ledgerName.files.blob._branch._-BR_HV-hK.js.map` sources for `text-file-view.tsx`, `text-editor.tsx` and `file-view-mode.tsx` are byte-identical to `main` (SHA-256 prefixes `28a687649ae14d53`, `631f6af1052bd4e0` and `7894f170b8cd3668`). This is not deployment lag.

## Fix

Owned by `dashboard`. When the mounted editor goes from `readOnly` to editable through a user action (Edit or ⌘E), focus it, for example with `editorRef.current?.focus()` once the edit-mode render has committed, from `TextEditor`'s `readOnly` effect or from `handleEditClick`. Keep the current caret position, and keep the end-of-file placement used for a Beancount file opened in edit mode. Do not steal focus on an initial read-only render, on a remount after a save, or when edit mode is left. Leave the Unsaved Changes, Stay and save-failure focus handling (w4/964, w4/970) as they are.

## Definition of done

- From the read view, ⌘E, a click on Edit, and Enter on a focused Edit each leave `document.activeElement` inside the Monaco editor, and typed text changes the buffer: Cancel then asks about unsaved changes.
- Opening `?editMode=true` and pressing Cancel or Escape behave as today.
- A test drives the real `TextFileView` from read mode with ⌘E and with the Edit button and asserts focus inside the editor host. It fails on the current code. Dashboard gates pass.

# Keep adjacent ticker text out of the account tree

**Minor · cli · 20–30m · A1 · worker1.** Real local CLI QA, 2026-10-22,
checkout `bea 0.3.1` at `d412de0c9b4e6c994e79584a52d2113a044b26de`, macOS
26.5.1 arm64, frontend Python 3.13.3, managed Python 3.12.10 / Beancount
3.2.3. No product fix implemented.

The documented BQL → treeify pipeline picks `NYSE:IBM` as the tree when a
narration consists of that ticker and is directly followed by the account
column. Both actual accounts remain flat, and the two repeated narration
values are collapsed into NYSE/IBM branches. File, stdin and `-o` all exit 0
with the wrong tree. Source ledger and query output remain unchanged; this
is incorrect rendering, not lost bookkeeping entries or amounts.

Expected: choose the actual account column, as the same query with narration
`NYSE:IBM dividend` does, and retain both ticker values beside the account
branches. The existing treeify column-selection behavior promises English
roots first, then most account components, then leftmost. A native explicit
account pattern renders this exact ASCII table correctly.

Replace the absolute directory below with a fresh directory, run, then repeat
in another pristine directory. `mode='word'` and `mode='plain'` are controls;
`renamed=True` repeats each case under Aktiva/Ertraege roots. Children use
isolated config/cache, closed stdin/no TTY, separate streams, bounded timeouts
and ledger hashes. No global state or real ledger is touched.

```python
import hashlib, json, os, pathlib, re, subprocess
case = pathlib.Path('/abs/adjacent-treeify-case')
mode = 'bare'  # word, plain
renamed = False
case.mkdir(parents=True)
assets, income = ('Aktiva','Ertraege') if renamed else ('Assets','Income')
names = [assets+':Broker:Cash',income+':Dividends']
narration = {'bare':'NYSE:IBM','word':'NYSE:IBM dividend','plain':'IBM'}[mode]
ledger = case/'main.bean'
ledger.write_text((f'option "name_assets" "{assets}"\n'
                   f'option "name_income" "{income}"\n' if renamed else '')
                  + f'2024-01-01 open {names[0]} USD\n'
                    f'2024-01-01 open {names[1]} USD\n'
                    f'2024-01-02 * "{narration}"\n'
                    f'  {names[0]} 10.00 USD\n'
                    f'  {names[1]} -10.00 USD\n',encoding='utf-8')
original = ledger.read_bytes()
env = os.environ.copy()
for key in ('BEA_FILE','BEA_TOKEN','BEANCOUNT_LOAD_CACHE_FILENAME'):
    env.pop(key,None)
env.update(BEA_CONFIG_DIR=str(case/'config'),XDG_CACHE_HOME=str(case/'cache'),
           BEA_NO_UPDATE_NOTIFIER='1')
def run(tag,args,stdin=None):
    cmd = ['bea','--no-input','-f',str(ledger),*map(str,args)]
    r = subprocess.run(cmd,cwd=case,env=env,input=stdin or '',
                       capture_output=True,text=True,timeout=25)
    print(json.dumps(dict(tag=tag,args=cmd,exit=r.returncode,stdout=r.stdout,
                          stderr=r.stderr,ledger_preserved=ledger.read_bytes()==original,
                          ledger_sha256=hashlib.sha256(ledger.read_bytes()).hexdigest())),flush=True)
    return r
run('check',['check'])
listing = run('query',['query','SELECT narration, account, position'])
table = case/'table.txt'
table.write_text(listing.stdout,encoding='utf-8')
run('file',['treeify',table])
run('stdin',['treeify'],listing.stdout)
run('export',['treeify',table,'-o',case/'tree.txt'])
pattern = '(?:'+'|'.join(map(re.escape,names))+')'
run('explicit',['treeify',table,'-r',pattern])
```

Actual default case, twice, for English and renamed roots:

- Check and query exit 0. The native-valid ledger has one 10 USD dividend,
  two postings and exactly two `NYSE:IBM` narration cells in the query table.
- File and stdin treeify exit 0, empty stderr, with `` `-- NYSE `` and
  `` `-- IBM ``. Full `Assets:Broker:Cash` / `Income:Dividends` remain flat;
  neither original `NYSE:IBM` cell remains intact.
- `-o tree.txt` exits 0, empty stdout/stderr and writes the same wrong tree.
  All amounts remain, and ledger/table hashes stay unchanged.
- The explicit pattern call and independent native treeify with that same
  account pattern both draw Assets → Broker → Cash and Income → Dividends,
  preserving two `NYSE:IBM` cells. Renamed roots likewise draw completely.
- Changing only the narration to `NYSE:IBM dividend`, or plain `IBM`, makes
  all automatic paths exactly equal the native explicit-pattern output.

Cause: `cli/src/cli/commands/treeify.py:61–69`, `_decide_pattern`, enumerates
non-overlapping matches of `({_ACCOUNT_ANY})(?P<ws>{joined}.|$)`. After the
NYSE:IBM match, its whitespace suffix consumes the **first A of Assets**
(or I of Income) in the adjacent column. `finditer` resumes after that
character, so the full account is never a candidate. Only an inner
Broker:Cash suffix can match; it ties the ticker's two components and loses
to the earlier column. Runtime trace on the real BQL table confirms no full
account candidates and the generic fallback pattern. With a narration word,
the consumed character belongs to `dividend`; the following full account
is visible, selected and anchored correctly.

Native `beancount.tools.treeify.find_column` uses the same non-overlapping
candidate enumeration, inspected in the installed managed dependency. Bea's
widened any-root pattern introduces the ticker candidate, and its own
English-root/most-components preference cannot rank an account it never
sees. This is a CLI adapter/selection defect; keep delegation of the actual
tree to native treeify. Explicit account recognition works on the same text.

Fix candidate enumeration so an earlier column's delimiter check does not
hide the following account's first character. Preserve the column-width
validity check, English-root/component-count precedence, linear scanning,
renamed/Unicode roots and explicit `-r`/`-A`/`-F` overrides. `_decide_pattern`
has one caller, the registered CLI treeify handler at :321; file, stdin,
stdout and file export converge there. No API or dependency change needed.

**Resolved 2026-10-23** — fixed: treeify's column decision (`_decide_pattern` in `cli/src/cli/commands/treeify.py`) no longer consumes the character after a match's delimiter. That character was the first letter of the next column's account, so with a narration of just `NYSE:IBM` beside the account column the account never matched on its line, the narration won the column and both real accounts stayed flat under NYSE/IBM branches. The delimiter's following character is now a lookahead (the validity test adds it back), so the English-root account column wins as for `NYSE:IBM dividend`: file, stdin and `-o` render the full Assets/Income tree with the ticker beside each branch, under English and renamed roots. Regression tests in `cli/tests/test_treeify_adjacent_ticker.py` fail without the fix (the bare-ticker cases); the existing treeify tests all pass. Full suite green. Shipped in this commit (`cli`).

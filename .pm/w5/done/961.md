# Keep QA writes and agent-eval resets off each other's ledger

**Minor · backend-v2 scripts + `.agents/skills/qa-shared` · 30–45m · A1.** Found 2026-10-21 while measuring w5/m5's prompt journeys on Codex ([w4/960](../w4/done/960.md)).

- **What happened:** a `yarn mcp:agent-eval --client codex --attempts 3` run on the QA account's `mcp-agent-eval` ledger failed 4 of 27 attempts. In each, another session committed to the same ledger during the attempt:
  - five "mobile append" commits
  - two "restore snapshot" commits
  - two image uploads

  The harness scored the results as "ledger changed", "unexpected files", and "ledger changed before the user confirmed". In none of them did the client make the write.
- **Control:** the same 27 attempts on a fresh private `mcp-agent-eval-w4` had no foreign commits and no such failures. Record: [2026-10-21-prompts-codex.md](../../backend-cluster/backend-v2/evals/mcp-agent/baseline/2026-10-21-prompts-codex.md#run-a-shared-ledger).
- **Cause:** both uses are documented for the same ledger.
  - The [QA contract](../../.agents/skills/qa-shared/contract.md) names `<qa-owner>/mcp-agent-eval` as QA's designated disposable ledger (user decision 2026-10-17).
  - The [eval guide](../../backend-cluster/backend-v2/docs/mcp-agent-eval.md) resets that ledger before every attempt.
  - So an eval run corrupts QA's snapshot-and-restore, and QA writes fail eval attempts.

Fix:

1. **Separate the two ledgers.** Either point the eval guide's default at a suffix ledger that no QA rule designates (the harness already accepts `mcp-agent-eval-<suffix>`), or move QA's designation to a `qa-` ledger. Which ledger QA uses is the user's call, because the contract records it as a user decision.
2. **Make the harness notice outside writes.** When the ledger's history between the reset and the read-back holds a commit that no successful write call in the transcript accounts for, score the attempt `error` with "ledger written outside this attempt", not `fail`. A test should pin that.

Acceptance: a QA run and an eval run can overlap without either corrupting the other. A foreign commit during an attempt reports `error`, not a client failure.


---

**Resolved 2026-10-22** — fixed: (1) the eval guide (`backend-cluster/backend-v2/docs/mcp-agent-eval.md`) now has an eval run use its own `mcp-agent-eval-<suffix>` ledger and key, and says why not the unsuffixed `mcp-agent-eval` that the QA contract designates as QA's disposable ledger; the QA contract's designation (a recorded user decision) is untouched, and the harness already accepted suffix names. (2) The harness notes the ledger's commit list right after the fixture reset and again after the run (the `commits` MCP resource), and scores an attempt `error` — "ledger written outside this attempt" — when the ledger gained more commits than the client's successful, non-preview write calls account for (`unexplainedCommits` in `scripts/mcp-agent-eval/score.ts`, `mcpWrites` and `COMMITTING_TOOLS` in `transcripts.ts`, counted for both Claude and Codex streams). An unreadable commit list claims nothing. Regression tests in `scripts/__tests__/mcp-agent-eval.test.ts` pin the write counting, the unexplained-commit arithmetic and that every committing tool name is a published write tool. backend-v2 typecheck, eslint, knip, prettier and the full jest suite are green (the `archive-parity` and `batch-processor` timing flakes pass alone). Not exercised against the live endpoint. Shipped in this commit (`backend-v2`).

# Publish a copyable ledger-check workflow for GitHub Actions

**Estimate:** 60m. **Worker:** worker1. **Priority:** 3. **Depends on:** none.

**Source:** `/pm-brainstorm for w5`, approved with `$pm all for w5` on 2026-09-27. `cli/docs/USAGE.md` explains `bea check` and `bea format --check`, but there is no complete customer GitHub Actions recipe. Build on the shipped validation and exit-code behavior, with [uv's official GitHub Actions integration](https://docs.astral.sh/uv/guides/integration/github/) for installation.

Add a minimal copyable workflow under `cli/docs/examples/`, linked from the CLI automation guidance. Install a pinned released `beancount-io`, select the ledger explicitly, run both validation and formatting checks, and explain how users substitute their ledger path. Use ordinary checkout and read permissions; the local-ledger example needs no Beancount.io login. Keep the example within `cli/` rather than installing it as a workflow for this monorepo.

**A1 / A3 — Agent-native accounting and community distribution:** developers maintaining ledger repositories can check human or agent contributions automatically by copying one example. The observable signal is successful setup in a clean synthetic repository, with a valid ledger passing and invalid changes failing.

**Done when:** the documented setup and commands pass for a valid formatted ledger, fail for an unbalanced transaction, fail independently for formatting drift, and leave ledger files unchanged. Record the tested released CLI version. Exercise the workflow with synthetic data; do not publish personal ledgers, credentials, or financial output. Use `cli/tmp/` for local scratch work.

Keep this as an inbox note at the one-hour sizing boundary. A new custom action, reusable workflow framework, release channel, or account integration is out of scope.

# Preserve a numeric zero import-id as a supplied identity

**Major · cli · 20–30m · A1.** An importer supplies `import-id: 0`, but the
CLI treats zero as absent and overwrites it with a content hash. A corrected
20 USD payment under the same supplied ID then writes as a new transaction
at exit 0, leaving Cash -30 USD instead of preserving the original -10 and
reporting a conflict. String `"0"`, nonzero numeric IDs and `bank_id: 0`
correctly retain identity and refuse the changed amount. No fix implemented.

Real CLI QA, 2026-10-21, HEAD `73e263892` (initial reproduction on
`ff3774c98`, CLI unchanged), checkout `bea 0.3.1`, macOS 26.5.1 arm64,
frontend Python 3.13.3, existing managed Python 3.12.10 with Beangulp already
enabled. Closed stdin/no TTY, fresh subprocesses, isolated absolute
`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, no inherited
`BEA_FILE`/`BEA_TOKEN`. Synthetic local files only; no feature installation.

Create `/abs/books/importer.py`:

```python
import datetime
import json
from decimal import Decimal
from beancount.core.amount import Amount
from beancount.core.data import Transaction, Posting, new_metadata

class Rows:
    def identify(self, file):
        return str(file).endswith(".json")
    def account(self, file):
        return "Assets:Cash"
    def extract(self, file, existing=None):
        number = Decimal(json.loads(open(file).read())["amount"])
        meta = new_metadata(str(file), 1)
        meta["import-id"] = 0
        return [Transaction(
            meta, datetime.date(2024, 2, 1), "*", None, "Coffee",
            frozenset(), frozenset(), [
                Posting("Assets:Cash", Amount(-number, "USD"), None, None, None, None),
                Posting("Expenses:Food", Amount(number, "USD"), None, None, None, None),
            ])]

CONFIG = [Rows()]
```

Cause: `cli/src/bea_engine/importing.py` uses truthiness at two decisions:
`_hash_rows` (:2319) does not skip hash preparation for a supplied zero, and
the transaction analysis (:507–525) treats `entry.meta.get("import-id")` as
absent and assigns a generated hash. `_writable` correctly converted the
Python integer to Decimal beforehand; that value is still numerically zero.
By contrast, `_identities` (:1521–1533) and `_native_import_id` (:2222–2227)
use the intended absent-value test, `None` or empty string, so they accept
zero. `_carries_bank_id` (:1586–1589) also uses `bool(stored)` for supplied
import IDs and should share the consistent presence rule.

Fix the supplied-ID presence decisions consistently, retaining numeric zero
without replacing it or relabeling its source. Preserve absent/empty-ID hash
generation, canonical and legacy generated-ID recognition, account scoping,
native-ID amount conflicts and valid repeated exports. Keep identity spelling
semantics: this does not request stripping leading zeros or normalizing
arbitrary ID strings. Add real import regressions for zero, its unchanged
repeat and changed amount, with the working controls. No dependency or
backend/API change needed.

**Resolved 2026-10-22** — fixed: import (`cli/src/bea_engine/importing.py`) now decides whether an importer supplied an identifier with one rule, `_supplied` (anything but absent or empty), at the transaction analysis, `_hash_rows` and `_carries_bank_id`, matching `_native_import_id` and `_identities`. A numeric zero `import-id` (`0`, `Decimal("0.00")`) keeps its identity and reports identifier source `importer`, so a corrected amount under it conflicts (exit 4, nothing written) and two rows of one file sharing it with different amounts refuse, as string `"0"`, `7` and `bank_id: 0` already did. Regression tests in `cli/tests/test_import_numeric_zero_id.py` fail without the fix. Shipped in this commit (`cli`).

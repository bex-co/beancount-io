# Budget summary judges a month from before the budget existed as "Above target" against a 0.00 USD budget, while its chart calls the same month "Not judged"

**Severity:** minor (a wrong verdict at the top of the page). **Owner:** dashboard. **Estimate:** 30–45 minutes. **A2:** a reader whose ledger stopped a few months ago adds their first budget, dated today. The page they land on says they already missed it, in red, ranked first, for a month before the budget was set. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-20 against `https://beancount.io`, production entry chunk `main-CIyNN76T.js`, which carries the rebuilt Budget page (`42ee4c79f`). Headless Chromium at 1440×1000, English/light, signed in as the QA owner on its disposable synthetic ledger. Local HEAD `6bec0b1ee`.

## Repro

1. Use a ledger whose entries end more than 45 days ago. The disposable synthetic ledger's last entry is 2026-08-28 (today is 2026-11-20). Its `Expenses:Food:Groceries` has 120.40 USD in July 2026.
2. On `/ledger/<owner>/<ledger>/budget`, choose **Add Budget** and keep the default date, 2026-11-20. Pick `Expenses:Food:Groceries`, Monthly, `100` USD, and submit. The ledger gains `2026-11-20 custom "budget" Expenses:Food:Groceries "monthly" 100 USD`. The probe was removed afterwards, and the file was restored byte for byte.
3. The page reads "Entries end on 2026-08-28, so figures are as of 2026-07-31, the end of the last full month."
   - Summary row: `Expenses:Food:Groceries · Monthly · July 2026 | Budget 0.00 USD | Actual 120.40 USD | Above target +120.40 USD`, in red, sorted under "Missed targets first".
   - The card's headline repeats it: **July 2026 · Budget 0.00 USD · Latest actual 120.40 USD · Variance Above target +120.40 USD**.
   - The card's chart, for the same July 2026 bar, draws no target line and colours the bar pale. Its key explains pale as **Not judged** ("a period with no target yet, or one still running").

The public `/ledger/open_ledger/example/budget` shows the same pattern today. Its only budget, `Expenses:Food:Restaurant`, has targets dated 2026-10-30. The ledger's entries end on 2017-09-08. The page reads "Monthly · August 2017 | 0.00 USD | 471.04 USD | Above target +471.04 USD", while every bar in its chart is "Not judged". Repeated from a fresh load.

**Expected:** a period that ends before the budget's first target has no target, so it gets no verdict. The summary row and the card headline say so (for example Budget "—" and "No target yet · first target 2026-11-20"), and they do not rank it as missed. This matches what the chart already does. A period with an active target of 0 is still judged as it is today.

## Cause

`dashboard/src/features/ledger-data/budget/budget-snapshot.ts`:

- `periodRows` (`:129-145`) sets `budget: null` for every period ending before `firstTargetDate` (`:114`). The chart (`budget-chart-card.tsx`) paints those bars as **Not judged** (`:229-231`).
- `comparisonBudgetValue` (`:213-232`) computes the headline period's budget with `calculateBudgetForInterval(headline.end, …)` and never applies the `firstTargetDate` rule. `calculateBudgetForInterval` (`budget-utils.ts:233`) skips days with no active directive (`if (!active) continue;`), so it returns `"0"`.
- `variance` (`:235`) becomes `actual − 0`, and `varianceStatus` (`:246-252`) returns `"above"`. `budget-summary.tsx:201` ranks the row as missed, and `:299` prints `0.00 USD`.

This is new with `42ee4c79f`. That commit summarises a dormant ledger at the end of its last whole month, so the headline period can now fall before a target added today.

## Fix

Owned by `dashboard`. When the headline period ends before the budget's first target, `comparisonBudgetValue` and `varianceStatus` are `null`, and the status is a distinct "no target yet" state. Render it neutrally in the summary row and the card headline, naming the first target's date, and sort it with the in-progress/not-judged rows rather than the missed ones. Add the new strings to all 15 locales. Leave the chart as it is.

## Definition of done

- On the repro, the summary row and the card headline for July 2026 show no "Above target", no red, and no `0.00 USD` budget. They say there is no target yet and name 2026-11-20. The row is not under the missed group.
- A budget whose target already covers the summarised period still reads Above/Below/On target exactly as today, including a target of 0.
- A rendered Budget test with a dormant ledger and a later first target asserts the neutral state. It fails on current `main`. Dashboard gates pass.

## Blast radius

`useBudgetSnapshot` feeds both the summary table (`budget-summary.tsx`) and each card's headline (`budget-chart-card.tsx`), and both showed the wrong verdict. Any time span whose summarised period precedes the first target is affected. That includes "Last year" when the budget was set this year. Only "All time" was exercised live. Mobile's Budget screen was not checked.

# Refuse non-conserving priced FX Cash Flow statements

**Major · cli · 45–60m for a bounded guard · A1 · worker1.** A valid,
unfiltered currency exchange silently changes historical opening cash.
Checking opens January at **1000 USD**, buys **100 EUR** for **110 USD**
and pays a **2 USD** fee. Actual change is **−112 USD / +100 EUR**,
closing **888 USD / 100 EUR**. `bea report cash-flow --time 2024-01`
reports opening **890 USD / 100 EUR**, change **−2 USD**, the correct
closing, exit 0, `ledger_valid: true`, `valuation: complete`, no warning.
Without the fee it says “No cash flows in this period.” All source bytes
stay unchanged. This is incorrect reporting, not lost ledger money.

`c23c10bdaa05469015587a9df0aaa375af401423` (1730 tracked CLI files);
latest fresh confirmation and original-feature recheck at clean main
`47f459cd354d397d33e630f706917490fee8b559` (1731 files). The engine/frontend
report and Fava conversion/inventory modules are byte-identical across both.
Checkout bea 0.3.1, frontend Python 3.13.3, existing managed Python 3.12.10 /
Beancount 3.2.3 / Beanquery 0.2.0, macOS 26.5.1 arm64. Offline bounded

## Standalone reproduction

```sh
python3 recipe.py /absolute/unused/fx-book fee standard root /absolute/managed-engine/bin/python
```

Use `renamed included` for EUR operating currency, renamed roots and a split
journal. Modes `exchange`, `total`, `round-trip`, `expense` and `expense-card`
are additional failures. Controls `costed`, `same`, `balanced-multi` and
`fee-only` work. Each recipe captures 13 CLI calls and 3 uncached native

file hashes. The native oracle sums units or actual booked costs at the
window edges, without using the report's derived opening. The source and
its full PRINT copy have identical cash facts. No ignored file is needed.

## Cause and bounded repair

Engine [`_cash_flow`](../../cli/src/bea_engine/report.py#L989) accumulates
posting inventories and converts account changes at cost (:1076).
[`get_cost`](../../cli/src/fava/core/conversion.py#L29), through
`_AtCostConversion.apply` (:157–165), intentionally returns units for a
position without cost; a posting's `@` price is not cost. This is correct
shared conversion behavior. The valid exchange balances by its price weight,
not by equal per-currency raw units. Therefore those at-cost account changes
do **not** sum to zero by currency.

The report drops cash members from rows (:1095), inverts noncash changes
(:1102), calls that activity subtotal `net_change` (:1108), and solves
`opening = closing − net_change` (:1110–1113), without comparing actual
beginning cash or cash movement. When both exchange legs are cash, the
exchange vanishes from activity; for a priced expense, its foreign units
become an invented foreign opening balance. It still marks valuation complete
(:1119–1124). Frontend [`cash_flow`](../../cli/src/cli/commands/report.py#L619)
emits the same payload as JSON or prints “Opening cash” and “Net change in
cash” (:659–664). One report dispatch calls `_cash_flow` (:137). Shared
at-cost conversion also serves sibling reports; change this report's
precondition, not upstream/Fava cost semantics.

Bounded target: independently accumulate selected CCE beginning/end balances
and movement in the same at-cost, per-currency basis. Before publishing
activity-derived cash figures, validate that they explain that actual movement.
Refuse an unsupported non-conserving priced-FX statement clearly, naming the
priced transaction/currencies and explaining that the current at-cost report
cannot reconcile it. Human and JSON must withhold the fabricated figures;
`--allow-errors` must not bypass a valid-ledger report-basis failure. Preserve
all source files and existing supported flows. Clarify this narrow exception
in [ADR024](../../docs/adrs/ADR024-cli-cash-flow-report.md), help and usage:
its “raw units ... identity holds by construction” premise is false for valid
`@`/`@@` cross-currency postings too, without a filter. A later feature can
model exchange effects explicitly; do not add an unexplained balancing row,
convert everything into one currency, drop the foreign leg, change recorded
transactions, demand fake cost lots/quotes, or broadly ban prices/FX.
No dependency, backend/API or upstream fork is required. Run CLI checks when
implementing and retain native-backed supported/error controls.

# Let ongoing `bea import` recognize migrated history

**Estimate:** 60m. **Worker:** worker1. **Priority:** 1 (prerequisite for m10). **Depends on:** none.

**Source:** found while triaging [m10](m10/README.md) on 2026-09-28. beancount-import's [`dedup.md`](../../../skills/.claude/skills/beancount-import/references/dedup.md) says the migration prefixes (`mint:`/`monarch:`/`qbo:sha256:`) and `import-id-2` on merged transfers let a post-migration import dedup against migrated history. `bea import` does not honor that promise.

Scope: `cli/`. Reproduced on synthetic ledgers written as beancount-migrate specifies, with published `beancount-io==0.3.0` and with HEAD:

- Overlapping bank-CSV rows whose digest equals a migrated `monarch:sha256:<hex>` id preview as `new`; applying would double-book migrated history, including both transfer sides.
- With the same digest under the `csv:` prefix, HEAD reports every overlap row as a `conflict`. The ids match, but the migrated payee/narration differ from the bank row's. A merged transfer has one narration and cannot equal both sides, so `import-id-2` can never produce a clean duplicate.

**Done when:**

- A generated `<source>:sha256:<hex>` id matches regardless of the documented source prefix, since the digest already binds date, exact amount, raw description, and account.
- A generated-id or `import-id-2` hit whose date and source amounts agree is a `duplicate`, even when payee or narration differ. A reused native bank id with changed data is still a `conflict`.
- Overlap-only CSVs from either side of a merged transfer preview zero new rows; a genuinely new row still previews once.
- Regression tests fail without the fix; `make check-all` passes. No release is tagged here: a published release is the user's call.

---

**Resolved 2026-09-28** — `bea import` now also matches generated ids by digest across the documented `csv`/`mint`/`monarch`/`qbo` prefixes, through both `import-id` and `import-id-2`, including older lossy spellings. A generated-id hit is a `duplicate` when date and source amounts agree; native bank ids keep the full-fingerprint conflict check. Shipped in `7302b907` (`cli`). Five regression tests in `cli/tests/test_import_migrated_identity.py` cover overlaps from each side of a migrated transfer, new activity written exactly once, and conflicts preserved for changed amounts and reused native ids; four fail without the fix. `make check-all` passed (2067 passed, one existing conditional skip). The fix is unreleased: published `beancount-io==0.3.0` still double-books these overlaps until a new `cli-v*` release, which is the user's call.

# Printing Journal, Accounts or any non-statement page keeps only the first screenful of rows

**Severity:** minor. **Owner:** dashboard. **Estimate:** 40–60 minutes. **A2:** browser printing (Cmd/Ctrl+P → Save as PDF) is the only way to get a paper or PDF copy of the Journal, Accounts, account pages, Holdings or Query results. Today the PDF has the sidebar on every page and about one viewport of rows, and the remaining pages are blank. Nothing warns the reader that rows are missing. w3/022 fixed these pages printing completely blank; this is the next layer. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-16 against `https://beancount.io`, using headless Chromium at 1440×1000 in English/light. The account was the QA owner, on the public `open_ledger/example` ledger. Read-only. Local HEAD `a1203ece2`.

## Repro

1. Open `/ledger/open_ledger/example/journal`. Wait for "Results 1–60 / 1,044".
2. Print the page to PDF (Letter, default margins). The QA run used Playwright's `page.pdf()`, which renders print media the same way the browser print dialog does.
   - The PDF has **4 pages**. Page 1 shows the sidebar, the header filters, the type tabs, and journal rows **2017-09-08 through 2017-08-28: 8 of the 60 rows on screen**.
   - Page 2 repeats the sidebar and the sticky table header (`Date F Payee/Narration`) and has no rows. Pages 3 and 4 contain only the sidebar. Per-page `pdftotext` word counts: 117, 14, 11, 11.
3. Do the same on `/ledger/open_ledger/example/accounts`. The page lists 60 accounts on screen ("60 / 60"). The PDF keeps 7 accounts on page 1, and page 2 holds only the sidebar and a table header.

Statement exports (Balance Sheet, Income Statement, Cash Flow → Export → Print / Save as PDF) print correctly. They mount their own `.statement-print-root` portal and hide the app.

## Cause

`dashboard/src/common/components/ledger-layout/index.tsx:151-178`. The ledger layout row is fixed to `h-(--visual-viewport-height,100vh)`. Page content lives in the inner `div[data-scroll-restoration-id="ledger-content"]`, which is `overflow-auto` with `min-h-0 flex-1`. Nothing overrides these in print media. Measured under `emulateMedia({ media: "print" })` on the Journal, the row stays 1000px tall and the scroller stays `overflow-y: auto`, with clientHeight 936 and scrollHeight 3479. The browser prints only the scroller's visible box. The sidebar container (`common/components/ui/sidebar.tsx:354`, `fixed inset-y-0 h-svh`) is `position: fixed`, so it repeats on every printed page. The only print CSS in the dashboard is `features/reports/export/statement-print.css`, which applies only when a statement portal is present (w3/022, `b41ba310f`).

## Fix

Add print-only layout rules in the dashboard. Do not add a new Journal or Accounts export format.

- While printing, let the ledger layout grow with its content: `height: auto` on the layout row, and `overflow: visible`, `min-height: auto` and `flex: none` on the `ledger-content` scroller and its child. Tailwind `print:` variants on those elements or a small global print block both work.
- Hide the app chrome that has no use on paper: the sidebar, its rail/toggle, the layout header with its filter inputs and user menu, and the skip link. Let `main` take the full page width.
- Keep the `w3/022` behaviour intact: statement pages still print only their portal, and normal screen layout is unchanged.

## Definition of done

- On the repro above, the Journal PDF contains all 60 on-screen rows (2017-09-08 down to the 60th row) across its pages, with no sidebar and no blank pages. The Accounts PDF contains all 60 accounts.
- The Balance Sheet "Print / Save as PDF" output is unchanged: one semantic statement, with no dashboard chrome.
- A rendered print-media test fails on the current layout. For example, it asserts that the `ledger-content` scroller is not an `overflow: auto` box with a fixed height under print media, or it checks the row count in a printed PDF.

## Blast radius

Every route rendered inside `LedgerLayout` except the commit workspace, which uses `overflow-hidden` and clips the same way: Journal, Accounts, account detail, Holdings, Commodities, Events, Documents, Query results, Errors, Files/blob, and Overview. Journal, Accounts and the account page were measured directly. Account detail showed the same fixed sidebar under print media. The other routes share the same container and are inferred, not printed.

## Dedupe

I searched `.pm/**` for print together with journal, blank, clip, first page and scroll container. `w3/done/022` (blank non-statement print) is resolved, and its acceptance only asked for the visible content. `w4/done/001` covers statement print CSS leaking onto the screen. `w4` m1 and m18 cover the statement and BQL print formats. There is no open item on clipped multi-page printing, and `DO_NOT_DO.md` has no print rule. `git log -S "print:"` shows no layout-level print styles have been added since.

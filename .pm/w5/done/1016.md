# Preserve omitted price currencies in native importer entries

**Minor · cli · 35–50m · A1 · worker1.** Real local CLI QA, 2026-10-24,
`bea 0.3.1`, macOS 26.5.1 arm64, frontend Python 3.13.3, managed Python
3.12.10 / Beancount 3.2.3 / Beanquery 0.2.0. Tested source
`ee4b7702516da4535bb3b478e2efe9913b09481b` is byte-identical to main through
`320ac4fb9d41831e7d7e91b7b64cd8fb3f6b09c9`; immutable source hashes are
verified before and after the run. No product fix implemented.

A native parser-based importer returns `Assets:Broker 2 HOOL @ 5` with
Cash `-10.00 USD`. Beancount correctly infers the price currency as USD,
but `bea import` refuses both preview and apply at exit **1**. Its printer
introduces a Python missing-value class into the posting, and then rejects
that invented token. The source account already has an explicit 2 HOOL
amount, meeting IMPORTING's source-amount requirement.

This blocks an ordinary native-valid acquisition. Explicitly stating the
price currency is a working workaround. All refused runs preserve ledger,
statement, reference and importer bytes; no corrupt posting is written.
A1 outcome: an agent can pass the native parser's valid entries through a
brokerage importer and complete preview/apply/repeat without reshaping its
price objects.

## Reproduce

With this checkout's `bea` on PATH, select a fresh absolute directory per
run. `form = 'total'` uses `@@ 10` with its currency left to native inference;
`mode = 'explicit'` is the working control. `journey = 'bank'` adds a native
ID; `human_apply = True` checks the human refusal. All processes have closed
stdin/no TTY, bounded timeouts and isolated config/cache. HOME and the
installation stay unchanged. The inspected importer only parses the local
synthetic statement. The recipe captures streams, exits, timings, argv and
before/after hashes, and writes standalone native references.

```python
import hashlib,json,os,pathlib,subprocess,time
case = pathlib.Path('/abs/inferred-price-currency-case')
form = 'unit'  # total: @@ 10 instead of @ 5
mode = 'inferred'  # explicit: working control with a stated USD currency
journey = 'generated'  # bank: retain a native bank_id
human_apply = False
case.mkdir(parents=True,exist_ok=False)
base='''option "operating_currency" "USD"
2024-01-01 open Assets:Broker HOOL
2024-01-01 open Assets:Cash USD
2024-01-01 open Equity:Opening USD
2024-01-01 * "Capital"
  Assets:Cash 1000.00 USD
  Equity:Opening -1000.00 USD
'''
ledger=case/'main.bean';ledger.write_text(base)
annotation=('@ 5' if form=='unit' else '@@ 10')+(' USD' if mode=='explicit' else '')
statement=case/'a.trade'
statement.write_text('2024-01-02 * "Trade"\n'+('  bank_id: "trade-001"\n' if journey=='bank' else '')
    +'  Assets:Broker 2 HOOL '+annotation+'\n  Assets:Cash -10.00 USD\n')
(case/'base-reference.bean').write_text(base)
(case/'source-reference.bean').write_text(base+statement.read_text())
(case/'explicit-reference.bean').write_text(base+statement.read_text().replace(annotation+'\n','@ 5 USD\n'))
config=case/'importer.py'
config.write_text("from beancount.parser import parser\nclass Rows:\n"
    " name='Price currency source'\n"
    " def identify(self,file):return str(file).endswith('.trade')\n"
    " def account(self,file):return 'Assets:Broker'\n"
    " def extract(self,file,existing_entries=None):\n"
    "  es,errors,_=parser.parse_file(str(file));assert not errors,errors\n"
    "  return es\nCONFIG=[Rows()]\n")
fixed={p:p.read_bytes() for p in [config,statement,*case.glob('*-reference.bean')]}
env=os.environ.copy()
for key in ('BEA_FILE','BEA_TOKEN','BEANCOUNT_LOAD_CACHE_FILENAME','BEA_ENGINE_PYTHON','BEA_ENGINE_DIR'):
    env.pop(key,None)
overrides=dict(BEA_CONFIG_DIR=str(case/'config'),XDG_CACHE_HOME=str(case/'cache'),BEA_NO_UPDATE_NOTIFIER='1')
env.update(overrides)
def run(tag,args):
    argv=['bea',* ([] if tag=='apply' and human_apply else ['--json']),'--no-input','-f',str(ledger),*map(str,args)]
    before=ledger.read_bytes();started=time.monotonic()
    result=subprocess.run(argv,cwd=case,env=env,stdin=subprocess.DEVNULL,capture_output=True,text=True,timeout=25)
    assert all(p.read_bytes()==b for p,b in fixed.items())
    if tag!='apply' or result.returncode:assert ledger.read_bytes()==before
    print(json.dumps(dict(tag=tag,args=argv,cwd=str(case),env=overrides,stdin_mode='DEVNULL',tty=False,
        exit=result.returncode,stdout=result.stdout,stderr=result.stderr,duration=round(time.monotonic()-started,3),
        before_sha256=hashlib.sha256(before).hexdigest(),after_sha256=hashlib.sha256(ledger.read_bytes()).hexdigest(),
        inputs_preserved=True)),flush=True)
    return result.returncode
run('baseline',['check'])
args=['import',statement,'--config',config]
run('preview',args)
if run('apply',args+['--apply'])==0:run('repeat',args+['--apply'])
run('holdings',['query','SELECT account,currency,sum(number) GROUP BY account,currency ORDER BY account,currency'])
run('check',['check'])
```

In inferred mode, baseline/check/holdings exit 0; preview and apply exit 1.
Both JSON refusals have empty stdout and a validation error ending:

```text
Importer Price currency source row 1 cannot be written as a ledger entry:
it would be written as 0 directive(s); a field holds a line break or a value
that is not one token (Beancount: Invalid token: '<class').
```

Human apply gives the same failure. Actual holdings remain **Cash 1000 USD**
with no HOOL acquisition. The source and independently explicit native
references are valid and financially identical: **2 HOOL at price 5 USD,
Cash 990 USD**. `@@ 10` books the same per-unit price. The statement has no
line break inside a field or invalid token.

The explicit-currency control previews one ready row, applies one, and its
unchanged repeat skips as a duplicate with zero writes. All six control
commands exit 0, fresh native loads match the source reference, and Cash
is 990 USD with 2 HOOL. These controls pass for both price forms and both
generated/native IDs. Expected for the inferred-currency source is that same
preview, booked result, check and repeat behavior.

## Root cause and callers

Actual engine-side rendering of the source produces:

```beancount
2024-01-02 * "Trade"
  Assets:Broker       2 HOOL @ 5 <class 'beancount.core.number.MISSING'>
  Assets:Cash    -10.00 USD
```

`cli/src/bea_engine/ledger/writer.py:118`,
`DirectivePrinter.render_posting_strings`, handles MISSING currency on
`posting.units` (`:120–127`) but passes an Amount with MISSING
`posting.price.currency` straight to upstream rendering at `:128`. The
native source has numeric price 5 and an intentionally omitted currency;
the resulting text has the class representation above. Actual helper
proofs show this omitted currency and unreadable rendering in all eight
failing profiles. The explicit controls print `@ 5 USD` and parse cleanly.

`importing._writable` (`cli/src/bea_engine/importing.py:1243`) calls
`format_entry` at `:1310` and `ledger_write.one_entry_problem` at `:1328`.
The latter correctly refuses the printer's invented tokens before matching
or candidate-ledger booking can run. Fix the rendering or resolve the
native-inferred price currency before this guard; keep the guard intact.
Preserve every stated price number and the source's native booking meaning.
Avoid substituting the operating currency for the currency the transaction
determines.

Caller search covers `format_entry` in import preview/matches/writes, single
adds and bulk writes, plus `DirectivePrinter` in BQL directive exports and
text cells. The reproduced failure is the native importer path with an
unbooked price. Query exports normally receive booked prices; no additional
query failure is claimed. Single-add intentionally refuses incomplete price
flags and should retain that behavior. Existing total-price, partial-unit
currency and cost-rendering behavior must remain intact.

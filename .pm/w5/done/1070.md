# Keep maximum-date funded closes out of tomorrow arithmetic

**Minor · cli · 15–25m · A1 · worker1.** On a valid, plugin-free ledger,
`bea add close --date 9999-12-31` replaces the normal funded-account
refusal with `OverflowError: date value out of range`. Importing the same
native-valid Close now fails in both preview and apply (exit 1), instead
of preserving the existing accepted-import-with-warning policy. The
adjacent date works; a zero-balance or forced maximum-date close works.
Source/reference books and all input bytes stay valid, and failed commands
write nothing. This is a rare calendar-end regression, not monetary loss.

## Cause and bounded repair

[`_drained_currencies`](../../cli/src/bea_engine/ledger/adding.py#L333)
unconditionally computes `after = date + datetime.timedelta(days=1)` at
:353 before checking the candidate's actual assertions. December31 in year9999
has no representable tomorrow. [`_remaining_balance`](../../cli/src/bea_engine/ledger/adding.py#L409)
calls it whenever units remain (:418–419), including when no plugin exists.
The direct path is `_close` → `_funded_close_refusal` (:505,451); the import
path is [`_funded_close_advisories`](../../cli/src/bea_engine/importing.py#L1094)
→ `_remaining_balance` (:1112). Both reach the same overflow, so a warning-only
import becomes a failure. Zero holdings do not enter the helper, and direct
force bypasses the funded check, explaining the working controls.

This tomorrow calculation landed in `61fa32c6`, the completed1063 repair.
Its candidate-based assertion checks are correct for the original cases.
Bound the calendar arithmetic in this helper: for the last representable
date, there is no next-day assertion eligible to claim `check_drained`
coverage, so return an empty covered-currency set and retain the actual held
units. Then direct unforced close keeps its normal funded refusal, native
import keeps its acceptance and existing warning, and force/zero controls
remain as they are. Do not clamp to the same day, invent coverage, drop the
holding, weaken finite-date assertion checks, change native close semantics
or disable the1063 repair. Preserve snapshot/candidate validation, both
callers and exact warning amounts/dates. No dependency, API or upstream fork;
run CLI checks when implementing.

## Objective

Evaluate whether an agent completed the task correctly using both returned facts and observable ledger state.

## Context

- An agent can claim success while returning the wrong total or making an unintended write.
- The synthetic journey definitions provide exact expected values and permitted mutation phases.

## Steps

1. Build deterministic scorers that compare requested facts against the fixture oracle without reimplementing accounting calculations.
2. Read persisted state after execution and check that read-only phases are unchanged and authorized phases have exactly the intended effects.
3. Report individual failed assertions and distinguish incorrect results, incomplete runs, and harness errors.

## Files

- `backend-cluster/backend-v2/evals/mcp-agent/ (new scorers and state comparison)`

## Acceptance criteria

- [ ] Known correct results pass and wrong totals fail even when the response says the task succeeded.
- [ ] Extra writes, duplicate purchases, and writes during a read-only phase are reported.
- [ ] A failed or absent state read cannot be interpreted as unchanged state or success.

## Out of scope

- LLM-only judgments of numerical correctness.
- Changing goldens to fit incorrect behavior.

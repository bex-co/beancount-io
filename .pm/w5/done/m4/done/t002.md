## Objective

Drive each journey through an actual coding-agent client connected to the hosted MCP endpoint.

## Context

- `backend-v2/scripts/mcp-conformance.ts` checks transport behavior; it does not run a user task through an external agent.
- The accepted proposal requires both clients; client launch and output formats may differ.

## Steps

1. Implement thin client adapters using each installed client's supported noninteractive mode and strict selection of the intended MCP configuration for the hosted endpoint.
2. Pass synthetic fixture targets explicitly and capture observable client tool/resource calls and final responses.
3. Expose the package command with explicit client, endpoint, model/version selection, and run limits; explain prerequisites without logging credentials.

## Files

- `backend-cluster/backend-v2/evals/mcp-agent/ (new client adapters and runner)`
- `backend-cluster/backend-v2/package.json`

## Acceptance criteria

- [ ] The same journey definition can run through either supported client against the hosted MCP endpoint.
- [ ] Missing clients or credentials produce actionable incomplete/failed results rather than a green result.
- [ ] The output identifies the client/model actually used and does not silently fall back to another model.

## Out of scope

- A new general agent framework or dependencies without approval.
- Production-ledger runs or a paid model call in ordinary CI.

# Document listings return absolute paths for valid parent-relative attachments

**Minor · cli · 25–40m · A1.** Functional CLI QA, 2026-10-09,
HEAD `408b2690`, checkout `bea 0.3.1`, Python 3.13.3, macOS. A document
stored from an included ledger using `../receipts/...` is accepted and returned
relative by add, but becomes absolute in list. That listed filename cannot be
reused as document input, which refuses absolute paths. No fix implemented.

Create a synthetic tree:

```text
books/main.bean
books/year/entries.bean
books/receipts/receipt.txt
```

`main.bean` contains an Assets:Cash open and the include; the included file
and receipt are ordinary files with harmless synthetic text:

```beancount
2026-01-01 open Assets:Cash USD
include "year/entries.bean"
```

From a foreign cwd, with isolated config/cache, disabled update notices,
no inherited BEA_FILE/BEA_TOKEN, closed stdin and no TTY:

```sh
bea --json --file /absolute/books/main.bean add document --date 2026-01-02 \
  --account Assets:Cash --path ../receipts/receipt.txt --into year/entries.bean
bea --json --file /absolute/books/main.bean list document
bea --json --file /absolute/books/main.bean check
```

All exit 0 with empty stderr. Add's `data.directive.filename` and the stored
directive use `../receipts/receipt.txt`. List's `data[0].filename` is
`/absolute/books/receipts/receipt.txt`. Human list also displays the absolute
path. Passing that filename back to add exits 2 (absolute input is forbidden).
Fresh checks succeed and receipt contents are unchanged.

Repeated in two fresh trees with a space/Unicode receipt name and tag/link
metadata. A receipt symlink in the sibling receipts directory also lists
absolutely, preserving its alias name. A same-source-directory `local.txt`
control adds and lists as `local.txt`. Additional controls refuse missing,
absolute, outside-tree and outbound-symlink paths without changing ledgers;
an inbound attachment symlink is accepted and retains its link/target bytes.

Expected basis: USAGE.md defines paths relative to the directive's containing
file, permits attachments inside the root tree, and requires relative add
input. The reader's own documented contract says it relativizes against that
source so list matches add. A parent traversal that stays inside the root tree
is valid, as both add and check confirm here.

Root cause: `cli/src/bea_engine/ledger/reader.py:511–530`
`_document_filename_for_json` uses `path.resolve().relative_to(source_parent)`.
`relative_to` only works for descendants, so an attachment in a sibling
directory raises ValueError and returns the loader's absolute filename.
`list_documents` calls it for each row; engine listing and both frontend
rendering modes consume that filename. This is presentation/input consistency,
not attachment loss or failed containment validation.

Use an actual relative-path calculation for valid in-tree attachments, retaining
the intended source-directory base and symlink spelling. Do not weaken the
add/check root-tree rules, or change generated/source-less document behavior
without verifying its contract. No dependency, backend or filesystem-layout
change is needed.

Full-board/history dedupe found no open parent-relative listing item.
Completed w3/244 (`da22b544`) fixed descendants using this helper but did not
cover sibling attachments. Completed w1/165 guards paths escaping the root;
those controls pass. Completed w1/044 concerns portable-export attachment
aliases, not listing serialization. This is the remaining reader case.

Acceptance: the exact parent-relative fixture lists a filename relative to the
included file in JSON/human output, reusable with the same --into; add/check
stay green, same-directory and sibling-symlink controls retain their meaning,
and ledger/attachment bytes are unchanged by reads. Only macOS tested.

Sanitized evidence: `cli/tmp/qa-20261008-cli/document_round19.py`,
`document-round19-console.jsonl`, `document_read19.py`,
`document-read19-console.jsonl`, fixtures and `transcript.jsonl` record actual
argv/cwd/environment, streams/exits and hashes. The public repro is complete.

---

**Resolved 2026-10-10** — `bea list document` now reports an attachment inside the root ledger's tree relative to the file that names it, including one reached through `..`. The reported fixture lists `../receipts/receipt.txt` in JSON and human output, the same value `add document` answered and stored. The path is computed from the names as written, so a symlinked attachment lists under its own name instead of its target's. An attachment outside the tree keeps its absolute path. Shipped in `8ebbd355` (`cli`).

Real-command regression tests, run from a foreign working directory against an included ledger, cover a sibling directory, a space/Unicode name, the parent directory, and same-directory and descendant controls: each asserts the add answer, the JSON and human listing, no absolute path in human output, unchanged file bytes after listing, that the listed name is accepted back by `add document --into`, and a passing `bea check`. A symlinked sibling attachment and a hand-written out-of-tree path have their own tests. Four fail with the fix reverted; the same-directory, descendant and out-of-tree controls pass either way. `make check-all` passed. Documents discovered through the `documents` option were not separately exercised, and only macOS was tested.

# Use display columns for query-to-tree conversion

**Minor · cli · 45–60m · A1.** The documented BQL → `treeify` journey
refuses a valid table containing a wide CJK account. A wide narration before
the account column instead produces a partial tree at exit 0: some ordinary
ASCII accounts remain flat. Query correctly aligns both tables by display
width, while treeify groups their character offsets as column coordinates.
No product fix implemented.

Real CLI QA, 2026-10-21, HEAD `6703a2f7e`, checkout `bea 0.3.1`, macOS
26.5.1 arm64, frontend Python 3.13.3, existing managed Python 3.12.10.
Fresh subprocesses, closed stdin/no TTY except the explicitly piped table,
isolated absolute `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`,
`BEA_NO_UPDATE_NOTIFIER=1`, no inherited `BEA_FILE`/`BEA_TOKEN`.
All ledgers and output paths below are disposable local fixtures.

Create `/abs/books/main.bean` using this Python setup (the repetition makes
the wide account's exact spelling reproducible):

```python
from pathlib import Path
books = Path('/abs/books')
books.mkdir(parents=True, exist_ok=True)
wide = 'Assets:B' + '银行' * 14
(books / 'main.bean').write_text(
    '2024-01-01 open Assets:LongAccountNameForCheckingAccount USD\n'
    f'2024-01-01 open {wide} USD\n'
    '2024-01-01 open Equity:Opening USD\n'
    '2024-02-01 * "Opening"\n'
    '  Assets:LongAccountNameForCheckingAccount 100.00 USD\n'
    f'  {wide} 200.00 USD\n'
    '  Equity:Opening -300.00 USD\n', encoding='utf-8')
```

From `/abs/books` in the isolated child environment above:

```sh
bea --json -f /abs/books/main.bean check
bea -f /abs/books/main.bean query "SELECT account, sum(position) GROUP BY account ORDER BY account" -o /abs/books/balances.txt
bea treeify /abs/books/balances.txt
bea treeify < /abs/books/balances.txt
bea treeify /abs/books/balances.txt -o /abs/books/tree.txt
```

Actual exits: **0, 0, 2, 2, 2**. The query table contains all three balances,
with its amounts correctly aligned. Every treeify form emits
`Could not find any valid column in input` and advises piping balances or
using names in Beancount's grammar, although its input is precisely such a
balance query and check passed. It emits no tree; `tree.txt` is not created.
Ledger and query-result bytes remain unchanged.

Expected: draw Assets → both full account components and Equity → Opening,
retaining 100, 200 and -300 USD. `cli/docs/USAGE.md` explicitly documents this
query-to-tree workflow and treeify's native account grammar support. The
completed w5/137 outcome and `test_real_query_output_with_cjk_accounts_is_a_whole_tree`
also establish real BQL output with CJK components as a supported journey.

A common short-text variant does not need a long account. Create
`/abs/books/narration.bean`:

```beancount
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Food USD
2024-01-01 open Expenses:Rent USD
2024-02-01 * "超市"
  Assets:Cash -10.00 USD
  Expenses:Food 10.00 USD
2024-02-02 * "Rent"
  Assets:Cash -20.00 USD
  Expenses:Rent 20.00 USD
```

```sh
bea --json -f /abs/books/narration.bean check
bea -f /abs/books/narration.bean query "SELECT narration, account, position ORDER BY account,narration" -o /abs/books/narrations.txt
bea treeify /abs/books/narrations.txt
bea treeify < /abs/books/narrations.txt
bea treeify /abs/books/narrations.txt -o /abs/books/narration-tree.txt
```

Actual: all five exit 0. Only the two `超市` rows become branches. The Rent
rows remain flat, still containing `Assets:Cash` and `Expenses:Rent`; the
Expenses → Rent branch is absent. All amounts survive, so this is incomplete
rendering rather than lost bookkeeping data. Expected: all four account rows
are converted in the same tree, with their narrations and amounts intact.

Controls, each repeated twice: replacing the long wide account with
`Assets:Bank`, or shortening it to `Assets:B银行`, produces a whole tree in
file/stdin/output modes. Keeping the original full wide name but supplying
a table padded by **character count** also succeeds; its visual amount
columns then misalign. This isolates column coordinates from account syntax.
An explicit Unicode-capable `-r '[^ :]+(:[^ :]+)+'` still refuses the original
wide-account table and still leaves both Rent rows flat in the narration
case. Changing only the grammar does not repair this failure. The native
`-A` preset retains its separate limited-character behavior and is not a
working control for wide account names.

Runtime matrix: two initial repetitions × ASCII/wide ledgers; then ten fresh
books, two repetitions × wide account/short wide account/wide narration/
ASCII/character-padded controls, with file, stdin, output, loose-preset and
explicit-pattern calls. All source ledgers pass check and every refusal/read
preserves ledger and table bytes. No output is created on the exit-2 cases.

Cause: `cli/src/bea_engine/query.py:_render_text_display_width`
(:1978–2085), introduced for w5/751, correctly pads cells in terminal columns.
`cli/src/cli/commands/treeify.py:_decide_pattern` (:48–94) instead groups
matches by `match.start()` and compares `match.end()` character indexes.
For the first table, the maximum account end and minimum following-content
index are both 40, so it rejects the group. In display columns the boundaries
are 64 and 67: the group is valid. Native
`beancount.tools.treeify.find_column` (:38–92) repeats this character-index
test after the wrapper's decision. Changing only the wrapper predicate
therefore cannot repair the handoff.

For the narration table, every account begins at display column 11, but the
wide-text rows have character offset 9 and ASCII rows offset 11. The wrapper
chooses the offset-9 group and anchors the pattern to that character position,
so the offset-11 rows never enter the tree. Native rendering also uses
character-count widths. File/stdin/output share this decision and native
capture path (:314–340).

Fix the query-to-tree integration so column selection and the native handoff
agree with display-aligned input, preserving complete names, other columns
and amount values. Retain query's correct Unicode padding and delegate the
tree structure to the native implementation; do not revert table alignment
or merely broaden the account regex. Preserve ASCII output, renamed-root/
narration-column selection and explicit pattern/preset behavior. Add real CLI
regressions for both shapes through file/stdin/output paths. No dependency or
backend/API change needed.

**Resolved 2026-10-22** — fixed: `bea treeify` (`cli/src/cli/commands/treeify.py`) now hands upstream a cell-aligned copy of the input when it uses its default account pattern: every character that is not one terminal column wide (a wide CJK character, a base with combining marks) is stood in for by that many private-use characters, so upstream's character offsets equal the display columns `query` pads by, and the originals are restored in the output. A table with a wide account is now a whole tree instead of "no valid column", a wide narration no longer leaves the other rows' accounts flat, amounts stay aligned in terminal columns, and file, stdin and `-o` agree; ASCII input, explicit `-r`/preset behaviour and accented single-column text are unchanged. Regression tests in `cli/tests/test_treeify_display_columns.py` fail without the fix. Full suite green apart from a pseudo-terminal teardown flake in `test_query_shell_error_banner_inert` that passes alone. Shipped in this commit (`cli`).

# Accept "rejected … lacks `ledger.write`" as a read-only refusal

**Trivial · backend-v2 evals · 15–20m · A1.** Found 2026-10-21 while measuring w5/m5's prompt journeys on Codex ([w4/960](../w4/done/960.md)).

- **What happened:** `prompt-reconcile-read-only-credential` failed 4 of Codex's 6 attempts across the two runs on the answer check alone.
  - Each time, the server refused the append with `FORBIDDEN … requires the "ledger.write" scope`, the ledger stayed unchanged and valid, and every state check passed.
  - Codex answered "The append was rejected because the credential lacks `ledger.write` scope."
  - The journey's `read-only-refusal` terms (`evals/mcp-agent/journeys.json`) accept "denied", "refused", "forbidden" and the like, but none of "rejected", "lacks", or "ledger.write".
  - This is the same kind of honest-wording miss as the 2026-09-15 Codex `categorize-imports` attempt.
- **Record:** [2026-10-21-prompts-codex.md](../../backend-cluster/backend-v2/evals/mcp-agent/baseline/2026-10-21-prompts-codex.md#non-passing-attempts-as-scored). The results stay scored as fails, as found.

Fix: add terms that name the refusal without loosening the check — for example "rejected", "lacks `ledger.write`", and "`ledger.write` scope". Do not add a bare "lacks". Add a scorer test in `scripts/__tests__/mcp-agent-eval.test.ts` that feeds the exact sentence above and also a non-refusal answer, so the check still fails when no refusal is reported.

Acceptance: the quoted answer passes the refusal check, and an answer that claims the write succeeded still fails it.

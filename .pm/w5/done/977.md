# Recognize unchanged multi-fill imports above twelve booked lots

**Major · cli · 45–60m · A1.** An unchanged broker sale split into two
open-cost fills over 13 lots conflicts with its own first import. Repeating
`--apply` exits 4 despite an identical native bank ID and source amounts.
Twelve lots with two fills, or 13 lots sold in one fill, correctly skip.
This blocks routine statement reimports. The hand-entered variant below
also books the same sale twice under default policy. No product fix implemented.

Real local CLI QA 2026-10-22 at `605af3313`, with the public recipe rechecked
on `69ead4c14`, `bea 0.3.1`, macOS 26.5.1 arm64,
frontend Python 3.13.3, managed Python 3.12.10 / Beancount 3.2.3. Both pristine
repetitions use separate bounded real CLI processes, closed stdin/no TTY,
isolated configuration/cache directories and the current checkout's source.
No network, real ledger or shared configuration is involved.

Run this self-contained recipe with `bea` on PATH, replacing `/abs/case` with

Every source and counter amount is explicit; the two fills deliberately

```python
from pathlib import Path
import datetime, json, os, subprocess

case = Path('/abs/case')
lots = 13
single_fill = False
correct_quantity = False
case.mkdir(parents=True, exist_ok=False)
ledger = case / 'main.bean'
ledger.write_text('option "operating_currency" "USD"\n2023-01-01 open Assets:Cash USD\n2023-01-01 open Assets:Stock HOOL "FIFO"\n2023-01-01 open Equity:Opening USD\n2023-01-01 open Income:Gains USD\n2023-01-01 * "Capital"\n  Assets:Cash 10000 USD\n  Equity:Opening -10000 USD\n')
with ledger.open('a') as f:
    for k in range(lots):
        day = datetime.date(2023, 1, 2) + datetime.timedelta(days=k)
        f.write(f'{day} * "Buy {k+1}"\n'
                f'  Assets:Stock 1 HOOL {{100 USD, "L{k+1}"}}\n'
                '  Assets:Cash -100 USD\n')
statement = case / 'sale.statement'
parts = [lots] if single_fill else [5, lots - 5]
def sale(parts):
    count = sum(parts)
    return ('2024-02-01 * "Sale"\n  bank_id: "trade-13"\n'
            + ''.join(f'  Assets:Stock -{q} HOOL {{USD}} @ 150 USD\n' for q in parts)
            + f'  Assets:Cash {count*150} USD\n  Income:Gains {-count*50} USD\n')
statement.write_text(sale(parts))
config = case / 'importer.py'
config.write_text('from beancount.parser import parser\nclass Broker:\n    name = "broker"\n    def identify(self, file): return str(file).endswith(".statement")\n    def account(self, file): return "Assets:Stock"\n    def extract(self, file, existing_entries=None):\n        entries, errors, _ = parser.parse_file(str(file))\n        assert not errors, errors\n        return entries\nCONFIG = [Broker()]\n')
env = os.environ.copy()
for key in ('BEA_FILE', 'BEA_TOKEN', 'BEANCOUNT_LOAD_CACHE_FILENAME',
            'BEA_ENGINE_PYTHON', 'BEA_ENGINE_DIR'):
    env.pop(key, None)
env.update(BEA_CONFIG_DIR=str(case / 'config'), XDG_CACHE_HOME=str(case / 'cache'),
           BEA_NO_UPDATE_NOTIFIER='1')
def run(tag, args, json_mode=True):
    argv = ['bea', *(['--json'] if json_mode else []), '--no-input', '-f', str(ledger), *map(str, args)]
    before = ledger.read_bytes()
    result = subprocess.run(argv, cwd=case, env=env, stdin=subprocess.DEVNULL,
                            capture_output=True, text=True, timeout=25)
    print(json.dumps(dict(tag=tag, args=argv, exit=result.returncode,
                         stdout=result.stdout, stderr=result.stderr,
                         ledger_changed=ledger.read_bytes() != before)), flush=True)
args = ['import', statement, '--config', config]
run('baseline', ['check'])
run('first-preview', args)
run('first-apply', [*args, '--apply'])
if correct_quantity:
    # A real correction must remain a conflict: the source now sells one fewer share.
    parts[-1] -= 1
    statement.write_text(sale(parts))
run('repeat-preview', args)
run('repeat-apply', [*args, '--apply'])
run('facts', ['query', 'SELECT account,sum(number) GROUP BY account ORDER BY account'])
run('sheet', ['report', 'balance-sheet', '--time', '2024-02', '--conversion', 'USD'])
run('check', ['check'])
```

**Resolved 2026-10-23** — fixed: when a sale is split into several open-cost fills, `_booked_for` (`cli/src/bea_engine/importing.py`) now tries, past twelve compatible booked lots, every run of consecutive lots that sums to one fill's quantity, instead of only the whole set. Booking takes lots in order, so each fill spans a run; trying only the whole set meant the first fill matched nothing and an unchanged sale conflicted with its own first import. Two fills over 13 lots (5 + 8), three over 20 and one over 13 now write once and skip on repeat (apply 1, 0, 0, ledger bytes unchanged); twelve lots and a single fill behave as before, and a sale of a different quantity under the same reference still conflicts (exit 4). Regression tests in `cli/tests/test_import_multi_fill_many_lots.py` fail without the fix. Full suite green apart from a load-sensitive `test_release` test that passes alone. Shipped in this commit (`cli`).

# Create Ledger: the Currency field reads "EUR" but the ledger is created in USD, because typed text that was never picked from the list is not what the form submits

**Severity:** major (the wrong operating currency, silently). **Owner:** dashboard. **Estimate:** 30–45 minutes including a rendered test. **A2:** w3/m62 added the Currency field so that a newcomer outside the United States gets a first Starter ledger in their own currency. The field opens prefilled ("USD" for an English US browser). The natural way to change it is to select the text, type "EUR", and press Enter or move on. The field then reads "EUR", the dialog accepts Create Ledger, and the books open in USD. **Found by:** `/qa-find-bugs-dashboard` (`dashboard-qa` routine) on 2026-11-21 against `https://beancount.io`, entry chunk `main-CIyNN76T.js`, isolated headless Chromium at 1440×1000, English, signed in as the QA owner. No ledger was created: the create mutation was intercepted and aborted in the browser, and the account's ledger list was unchanged afterward. Local HEAD `da52c0020`.

## Repro

1. On `/ledger`, choose **Create Ledger**. Template **Starter** is selected and **Currency** reads `USD`.
2. Click Currency, select all, type `EUR`. The list shows one option, `EUR — Euro`.
3. Press Enter. The list stays open (`aria-expanded="true"`) and nothing is chosen. Press Tab. Currency still reads `EUR`.
4. Name the ledger and choose **Create Ledger**.

Actual: the request is `CreateLedger` with `{"name":"…","private":true}` and no currency, which the server creates as USD. The field shows `EUR` throughout, before and after the click.

Variant: choose `EUR — Euro` from the list (the field reads `EUR`), then type `jpy` over it and press Escape or click elsewhere. The field reads `jpy`, and Create Ledger sends `CreateLedgerInCurrency` with `"currency":"EUR"`.

Control: choosing an option with the mouse, or ArrowDown then Enter, submits that currency. Clearing the field with its ✕ and submitting is refused with "Choose a currency from the list."

## Cause

`dashboard/src/common/components/ui/combobox.tsx` keeps the visible text (`inputValue`) apart from the committed `value`, and with `allowCustom={false}` nothing ever reconciles the two:

- `handleInputChange` (line 134) only calls `onValueChange` when `allowCustom` is true (line 140).
- `handleInputBlur` (line 154) sends only when `allowCustom && triggerOn === "blur"` (line 159), and otherwise leaves the typed text in place.
- Enter with no highlighted option does nothing unless `allowCustom` (line 184). Typing resets the highlight to −1, so a unique match is never picked by Enter.

The only `allowCustom={false}` caller is the Create Ledger Currency field, `dashboard/src/features/ledger-list/components/ledger-form.tsx:383-404`. Its zod refine (lines 97-105) validates the form value, which is still the earlier pick, so the stale value passes. `LedgerForm` is the form on all three create surfaces: the `/ledger` sidebar (`dashboard-sidebar.tsx`), the ledger switcher inside a ledger (`common/components/ledger-layout/ledger-switcher.tsx`), and the welcome page.

## Fix

Without custom values, the field must never show text that differs from what it will submit:

- On Enter, and on blur, commit the typed text when it equals an option's value (case-insensitive, so `eur` → `EUR`). Enter with exactly one filtered option picks it.
- Otherwise, send `""` so the form's existing "Choose a currency from the list." error appears, or put the text back to the current value's label. Pick one and apply it on blur, Escape and Enter alike.

Keep `allowCustom` callers (header filters, which have their own `triggerOn` and late-echo rules, w4/990) unchanged.

## Definition of done

- In the repro, after typing `EUR` and pressing Enter (or Tab), Create Ledger sends `CreateLedgerInCurrency` with `currency: "EUR"`.
- After picking EUR and then typing `jpy` and pressing Escape or blurring, the request is never sent with EUR while the field says `jpy`: it sends JPY, or the form shows "Choose a currency from the list."
- A rendered test of `LedgerForm` (or of `Combobox` with `allowCustom={false}`) covers the typed-then-Enter, typed-then-blur and typed-over-a-pick cases, and fails on the current code. Dashboard gates pass.

## Dedupe

Searched `.pm/**` for `allowCustom`, `Currency field`, `currency picker`, `CreateLedgerInCurrency` and `Create Ledger` with currency. w3/m62 (done) shipped the field, and its tests pick from the list. w4/286 (IME keys), w4/990 (late filter echo) and w2/116 (popup names) changed the same `Combobox` for other reasons. No open, blocked or done item covers typed currency text.

## Unverified

The native app's Currency picker (w3/m62/t003), Firefox and Safari, and a real network create. The create mutation was always aborted.

---

**Resolved 2026-11-23** — Enter and blur commit a typed currency code, normalizing case. Enter also chooses a sole suggestion. Escape reconciles the code when it dismisses the picker in the actual modal. An unmatched draft returns to the last committed value, and a cleared currency is invalid for a Starter ledger. The shared file picker keeps exact spelling for filenames that differ only by case. Eight rendered form regressions failed before the fix. Chromium at 1440px and 390px verified the displayed value and intercepted `CreateLedgerInCurrency` variables, including clicking Create directly after typing and leaving the field blank. The fixture intercepted every mutation before network access. All 8,673 dashboard tests, format, lint, and build passed. Shipped in `22c27c79b` (`dashboard`).

# The Journal ticks a balance assertion "Matches" when the ledger never checked it: an assertion on an account that was never opened (typically a parent account) reads green "Matches" even when its amount is wrong

**Severity:** minor. Nothing is written wrongly, but the Journal's reconciliation checkpoint makes a positive claim the ledger did not verify, and the Errors page says the opposite. **Owner:** dashboard. **Estimate:** 30–45 minutes including tests. **A2:** since `91daf9b46` the Journal is laid out for reconciling a ledger: a balance assertion is a checkpoint, a green tick "Matches" or red "Off by X", and `journal-balance-tone.ts` says "Everything between two matching checkpoints is reconciled". A newcomer who asserts a statement balance on the bank's parent account (`Assets:Bank` rather than `Assets:Bank:Checking`) is told the ledger matches the statement when it was never compared. **Found by:** `/qa-find-bugs-dashboard` (`dashboard-qa` routine) on 2026-11-21 against `https://beancount.io`, production entry chunk `main-CIyNN76T.js` (unchanged since 2026-11-20, built from `main` at or after `ebbf43fed`), QA-owned headless Chromium at 1440×1000 and 390×844, English, signed in as the QA owner on the disposable QA ledger. The probe was written, checked, then removed; the file is back to its snapshot blob and the ledger check is clean.

## Repro

Append to a ledger that has an `Equity:Opening-Balances` account:

```beancount
2026-09-01 open Assets:Qa-20261121-Probe:Wallet
2026-09-01 open Assets:Qa-20261121-Probe:Sub

2026-09-02 * "qa-20261121-dashqa" "qa-20261121 fund probe accounts"
  Assets:Qa-20261121-Probe:Wallet   100.00 USD
  Assets:Qa-20261121-Probe:Sub       25.00 USD
  Equity:Opening-Balances

2026-09-05 balance Assets:Qa-20261121-Probe  125.00 USD
2026-09-06 balance Assets:Qa-20261121-Probe  120.00 USD
2026-09-03 balance Assets:Qa-20261121-Probe:Wallet  90.00 USD
```

1. **Errors** lists `Account Assets:Qa-20261121-Probe was never opened` for both parent assertions (and `Balance failed for Assets:Qa-20261121-Probe:Wallet: expected 90.00 USD, got 100.00 USD` for the third). bean-check refuses the same: beancount's balance check skips an assertion whose account does not exist.
2. Open `/journal` (Compact, the default). The 09-06 row reads **`Matches · Balance · Assets:Qa-20261121-Probe · 120.00 USD`** with the green tick and green row tint. So does 09-05. The two children hold 125.00 USD, so 120.00 would not match even if the account existed. The 09-03 row reads `Off by 10.00 USD` in rose, which is correct.
3. Comfortable layout, `/journal?account=Assets:Qa-20261121-Probe`, and the 390px phone layout show the same "Matches" on both parent rows.

The API is consistent with the ledger: `getLedgerJournal` returns `diff_amount: null` for both parent assertions, because the engine reports `E1001` (never opened) and no `E2001` balance failure for them. A passing assertion also has `diff_amount: null`, so the two cannot be told apart from that field alone.

Control: an assertion on an opened account behaves correctly in both directions (09-07 `100.00 USD` on the wallet reads Matches; 09-09 `100.00 USD` after a 10.00 USD withdrawal reads `Off by -10.00 USD`). Checked locally against `@rustledger/wasm` 0.24.0: an assertion on a closed account, one dated before its account's `open`, and one in a currency the account's `open` does not allow all still produce an `E2001` failure, so the gap is the never-opened account alone.

## Cause

- `dashboard/src/features/journal/components/journal-balance-tone.ts:10-12`: `balanceIsOff` is `Boolean(directive.diff_amount)`, and every caller treats "not off" as checked and matching. `journal-balance-check.tsx:20-27` then renders `journal.balanceMatches` with `CircleCheck`, and `balanceRowTone` the emerald tint (`journal-lines.tsx:159,192`, `journal-days.tsx:424`).
- `diff_amount` is filled only from `E2001`/`E2002` errors (`backend-cluster/ledger/src/foundation/rustledger/journal-serialize.ts`, `failedBalanceDiffs`). An assertion the engine never evaluated has no such error, so it keeps `null`.

## Fix

Owned by `dashboard`; no API change is needed.

- A Balance row says "Matches" only when the asserted account is opened on or before the assertion's date. The dashboard already loads that directory for New Entry: `GetLedgerAccountDirectivesDocument` (`features/journal/components/new-directive-dialog/use-account-availability.ts`), keyed on `open` directives. Do not use the account tree or `getLedgerAttributes.accounts`: both name parents that were never opened.
- For an assertion on a never-opened account, show a third state in the warning style: no green tick, no tint, text such as "Not checked: account never opened", linking to Errors. Put the same words into the row's accessible name (`journal-entry-label.ts`). Until the directory has loaded, show neither "Matches" nor the new state.
- Passing and failing assertions on opened accounts keep exactly today's rows.

## Definition of done

- With the repro above, the 09-05 and 09-06 rows read the "not checked" state in Compact, Comfortable, the account-filtered Journal and the 390px layout, with no green tick or tint, and their accessible names say so. The 09-03 row still reads `Off by 10.00 USD`. A passing assertion on an opened account still reads Matches.
- Rendered tests cover the never-opened, passing and failing cases, plus a parent-account assertion where the parent *is* opened (Matches). Each new expectation fails on the current code. Dashboard gates pass.

## Dedupe

Searched `.pm/**`, including `done/` and `blocked/`, for `Matches`, `balanceMatches`, `never opened` with balance and journal, `diff_amount`, `checkpoint` and `Off by`. w5/1181 (open) covers how a *failing* assertion's row is worded and formatted (direction, accumulated balance, localization); it does not cover an unchecked assertion reading Matches. w21/done/087, 532, 677 fill and pair `diff_amount` in the ledger service. w5/1202 is the Accounts page offering Delete for an account an assertion names. w3/done/560 stopped New Entry writing against a never-opened account. Mobile shows only an "Off by" line for failures and no "Matches" claim (source only). `journal-balance-tone.ts` has been unchanged since `91daf9b46`, so this is not deployment lag.

**Unverified:** right-to-left locales; whether any other engine error leaves an evaluated-looking assertion with `diff_amount: null` (only the cases above were probed).

# The legacy `/ledger/0/income_statement` link traps Back: every Back press bounces to the Overview again, and a quick one strands the tab on "Redirecting…"

**Severity:** minor (nothing is lost, but a reader who follows an old bookmark or link to the old address can no longer get back to the page they came from). **Owner:** dashboard. **Estimate:** 20–30 minutes including a rendered test. **A2:** the route exists only to carry old links into the new dashboard, and the hand-off should leave the reader's history as it was. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-21 against `https://beancount.io` (dashboard entry chunk `main-CIyNN76T.js`), QA-owned headless Chromium on macOS at 1440×1000, English/light, signed in as the QA owner. Read-only: the Overview's data reads were aborted in the repeat runs, so no ledger content was loaded. Local HEAD `79bb09ed1`. The route file has not changed since `aeec496bf` (2026-08-26), so production and HEAD agree.

## Repro

1. Signed in, open `/ledger` (the ledger list).
2. In the same tab, open `https://beancount.io/ledger/0/income_statement` (as from an old bookmark, or a link in an email or an old post). It shows "Redirecting… Loading your ledger", then lands on the Overview of the account's first owned ledger (`/ledger/<owner>/<ledger>`). `history.length` grows by 2: the legacy address and the Overview.
3. Press Back. The URL flips to `/ledger/0/income_statement` and the tab goes forward to the Overview again. Press Back twice more: it stays on the Overview each time and `history.length` does not change. The ledger list from step 1 can no longer be reached with Back. This reproduced twice, each time in a fresh browser context.
4. **Quick Back.** Repeat step 2, and press Back as soon as the URL reaches the Overview, before the Overview has rendered. The tab stays on `/ledger/0/income_statement` showing "Redirecting… Loading your ledger". It was still there 3 s and 8 s later (two runs) and does not move on.

**Working control.** `/settings` redirects to `/settings/general` with `throw redirect()`. A client-side transition from `/ledger` to `/settings` adds one history entry, and one Back returns to `/ledger`. Signed out, `/ledger/0/income_statement` answers a 307 to `/auth/login?next=%2Fledger%2F0%2Fincome_statement`.

## Cause

- `dashboard/src/routes/ledger.0.income_statement.tsx:15-36`: `LedgerRedirectComponent` redirects from a `useEffect` with `navigate({ to: "/ledger/<owner>/<ledger>" })` (`:30`), and with `navigate({ to: "/ledger" })` when the account has no ledger (`:22`). Neither call passes `replace: true`, so the legacy address stays in history beneath its target. Back pops onto it, the component mounts again, and the effect pushes the target again.
- The quick-Back state has the same cause. Back arrives while the Overview navigation is still pending, so the redirect component was never unmounted. Its effect depends only on `[navigate, client]`, so it does not run again, and nothing navigates.
- The dashboard's other redirects replace their entry, apart from the two sign-in redirects under Blast radius. Thrown redirects are replaced by the router (`@tanstack/router-core` `router.js`, the `isRedirect` branch: `navigate({ ...redirect.options, replace: true })`). Effect redirects pass `replace: true`, for example `features/ledger-editor/file-editor/index.tsx` ("Replace history entry to prevent back button issues") and `features/git/commits/components/commits-split-view.tsx:201`. This route is the outlier.

## Fix

Opening `/ledger/0/income_statement` must leave a single history entry: its target replaces the legacy address. Back from the target goes to the page that was open before the legacy link.

- Smallest change: pass `replace: true` to both `navigate` calls in `ledger.0.income_statement.tsx`.
- Alternative: resolve the default ledger in `beforeLoad` after `requireAuth`, with `getUserDefaultLedger(context.client)`, and `throw redirect(...)`. That matches the other legacy routes (`routes/dashboard.tsx`, `routes/login.tsx`), drops the "Redirecting…" screen, and lets SSR answer a redirect. It also removes the quick-Back stranding, because no component is left mounted to wait on. Keep the destination: the Overview is the dashboard's home, as Fava's `income_statement/` default page was for the old app.

## Definition of done

- Signed in: from `/ledger`, opening `/ledger/0/income_statement` lands on the first owned ledger's Overview, and one Back returns to `/ledger`. An account without ledgers lands on `/ledger`, and Back returns to the page before.
- A Back pressed before the Overview renders never leaves the tab on "Redirecting…".
- Signed out, the address still answers a 307 to `/auth/login?next=%2Fledger%2F0%2Fincome_statement`.
- A rendered test with a memory history (next to `src/routes/__tests__/redirect-routes.test.ts`, which covers the other legacy redirects but not this one) asserts that the history holds one entry for the hand-off, and that Back reaches the previous location. The test fails on the current code. Dashboard gates pass.

## Blast radius

Searched every `navigate(` in `dashboard/src` that runs from a `useEffect`. Each one passes `replace: true` except this route and the unauthenticated-to-login redirects in `common/root-route/error-page.tsx:40-46` and `common/components/ledger-layout/ledger-route-error.tsx:22-29`. Those two push `/auth/login`. No signed-out client navigation reached them this run: Ledger Settings and Ask Beancount.io render for signed-out readers, and full loads get a server 307. So they are not confirmed as traps. Recheck them only if a flow reaches them. The other legacy addresses (`/dashboard`, `/gallery`, `/welcome`, `/forgot-password`, `/reset-password`, `/logout`) never reach the dashboard on beancount.io. The site's edge routes them to the separate website, which answers 404. That is outside this repository.

**Resolved 2026-11-23** — The legacy route authenticates and resolves the default ledger in its loader, then returns a router redirect. The destination replaces its history entry. Three real-router regressions failed before the fix. Chromium confirmed one added entry and one Back for first-owned, empty and still-loading Overview cases. Built SSR with a synthetic gateway returned 307 to the correct Overview or ledger list and to the exact original URL in the signed-out login return parameter.

**Resolved 2026-10-03** — revoking an API key id that does not exist now carries a hint about keys: pass an id that belongs to the account, and `manageApiKeys` with operation `list` shows them. It no longer falls back to the NOT_FOUND hint about ledgers and files. Shipped in `5f134ede` (`backend-cluster/backend-v2`).

The throw site was not the one the note assumed. An unknown id never reaches the key service's own not-found: the authorization layer refuses it first and conceals the missing key-owner relationship as `API key not found`. A concealed denial can now carry a hint, and the service's own not-found uses the same text. The hint travels in the error metadata, so REST and GraphQL return it too; the code is unchanged. A test revokes an unknown id through an MCP client; it fails with the fix reverted. Not re-run against the hosted endpoint: the fix reaches it with the next deploy.

# Closing Create Ledger leaves keyboard focus on the page body, so the next Tab starts again from "Skip to main content"

**Severity:** minor (keyboard access). **Owner:** dashboard. **Estimate:** 20–30 minutes. **A2:** a newcomer who opens Create Ledger to look at the form and closes it should be back on the button they used, not at the top of the page. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-18 against `https://beancount.io` (entry chunk `main-LGv2TZLj.js`), headless Chrome at 1440×1000 and 390×844, English/light. QA owner account. Read-only: nothing was typed and no ledger was created. Local HEAD `73a6d7599`.

## Repro

1. Open `/ledger`. Focus the sidebar's **Create Ledger** button and press Enter. **Create New Ledger** opens with focus in its first field.
2. Press Escape without typing. The dialog closes and `document.activeElement` is `<body>`. The next Tab lands on **Skip to main content**, the first element of the page.
3. Repeat and close with the dialog's **Close** button instead: focus is again `<body>`.
4. On a ledger page, open the sidebar's **switch ledger** combobox, click **Create Ledger** in its popover, then press Escape. Focus is again `<body>`, not the switcher.

The same happens at 390×844, where the sidebar is a sheet. Repeated from fresh loads.

Controls in the same session: Overview **Customize**, Journal **Export**, Ledger Settings **Invite Collaborator** and **Delete Ledger**, **New SSH key**, **New token**, Files **Git Clone** and Budget **Add Budget** all return focus to their opener on Escape. The same sidebar's **Edit Ledger Settings** and delete dialogs restore focus on purpose.

## Cause

Both Create Ledger dialogs are controlled `<Dialog open={…}>` with no `DialogTrigger` and no `onCloseAutoFocus`:

- `dashboard/src/features/ledger-list/pages/dashboard-page/components/dashboard-sidebar.tsx:494-513`. It is opened by the sidebar button (`setIsCreateDialogOpen(true)`) and by the empty-state **Create Ledger** that a user with no ledgers sees (`LedgerListData`).
- `dashboard/src/common/components/ledger-layout/ledger-switcher.tsx:405-423`. It is opened from the switcher popover's footer, which unmounts as the dialog opens.

Without a trigger, Radix has nothing to give focus back to, so it falls to `<body>`. `common/lib/focus/restore-focus-on-dialog-close.ts` exists for exactly this ("prevent Radix's default body restore"). The same sidebar file already uses it for its Edit dialog (`editReturnFocusRef`, `:521-528`) and its delete dialog (`deleteReturnFocusRef`, `:600-…`).

## Fix

Record the element that opened each Create Ledger dialog and pass it to `restoreFocusOnDialogClose` from `DialogContent`'s `onCloseAutoFocus`, following the Edit dialog's pattern. In the switcher, the opener is gone, so return focus to the **switch ledger** combobox. A successful create still navigates to the new ledger, and that path should not pull focus back. Keep w2/134's discard prompt: **Keep editing** keeps the draft and focus inside the dialog.

## Definition of done

- On `/ledger`, Escape, Close or Cancel on an untouched Create Ledger dialog returns focus to the button that opened it, either the sidebar button or the empty-state button.
- On a ledger page, closing Create Ledger opened from the switcher returns focus to the **switch ledger** combobox.
- After **Discard** in the "Discard what you typed?" prompt, focus also returns to the opener.
- Rendered tests cover both entry points and fail without the change. Dashboard gates pass.

## Dedupe

Searched `.pm/**` for Create Ledger + focus, onCloseAutoFocus and restoreFocusOnDialogClose. w2/done/134 added the discard guard to these dialogs but not focus return. w4/done/314 and w4/done/320 are about the creation wizard's submit and draft, and w3/done/561 about radio-card focus rings. Not deployment lag: HEAD's dialogs still have no focus restore. A scan of controlled dialogs with neither a trigger nor `onCloseAutoFocus` also lists the file view's "delete a file other files include" confirmation (`ledger-file-view/index.tsx:358`). It was not exercised here, because it sits on a destructive path.

**Major · cli · 45–60m · A1 · worker1.** A valid account filter can
silently replace actual opening cash and cash movement with figures solved
from incomplete activity rows. Checking opens February at 1000 USD and
closes at 1350, an increase of 350. `--account Assets:Checking` instead
says opening1350, change `{}`, closing1350 and “No cash flows in this
period.” `--account Assets` says opening1650, change−100, closing1550
despite that CCE set actually opening1000 and increasing550. Both JSON and
human reads exit0, ledger valid and valuation complete. No ledger bytes

## Reproduce and compare

Save the self-contained Python below as `recipe.py`, then run
`python3 recipe.py /absolute/path/to/bea /new/scratch/dir standard USD`.
The directory must be new. Each command's argv, cwd, separate streams and
exit are printed; the tiny ledger is created there and remains unchanged.
Repeat with `standard EUR`, `accented USD` or `greek EUR` and a new directory.
For source reproduction, run the checkout's `bea` with its normal engine
setup; the QA run pinned all frontend/helper source to the SHA above.

```python
"""python3 recipe.py /absolute/path/to/bea /new/scratch/dir standard USD"""
import json, os, subprocess, sys
from pathlib import Path

def fixture(profile, currency):
    roots={
        'standard':['Assets','Liabilities','Equity','Income','Expenses'],
        'accented':['Éléments','Obligations','Capitaux','Revenus','Dépenses'],
        'greek':['Ενεργητικό','Υποχρεώσεις','Ίδια','Έσοδα','Έξοδα'],
    }[profile]
    a,l,e,i,x=roots
    names=dict(checking=a+':Checking',savings=a+':Savings',bond=a+':Bond',salary=i+':Salary',food=x+':Food',loan=l+':Loan',equity=e+':Opening')
    text=''.join('option "name_'+k+'" "'+v+'"\n' for k,v in zip(['assets','liabilities','equity','income','expenses'],roots))+'option "operating_currency" "'+currency+'"\n'
    text+=''.join('2024-01-01 open '+ac+' '+currency+'\n' for ac in names.values())
    for day,title,postings in [
        ('2024-01-02','Capital',[('checking',1000),('equity',-1000)]),
        ('2024-02-01','Salary',[('checking',300),('salary',-300)]),
        ('2024-02-02','Food',[('checking',-50),('food',50)]),
        ('2024-02-03','Save',[('checking',-200),('savings',200)]),
        ('2024-02-04','Borrow',[('checking',400),('loan',-400)]),
        ('2024-02-05','Bond',[('checking',-100),('bond',100)]),
    ]:
        text+=day+' * "'+title+'"\n'+''.join('  '+names[k]+' '+str(n)+' '+currency+'\n' for k,n in postings)
    filters=[('all',None),('checking',names['checking']),('assets',a),('salary',names['salary']),('all-active','(?:'+a+'|'+l+'|'+i+'|'+x+'):'),('omit-savings','(?:Checking|Salary|Food|Loan|Bond)$'),('no-match','UnmatchedAccount')]
    return text,names,filters

def main():
    exe,folder,profile,currency=sys.argv[1:];case=Path(folder).resolve();case.mkdir();book=case/'main.bean';text,names,filters=fixture(profile,currency);book.write_text(text,encoding='utf-8');fixed=book.read_bytes();env=os.environ.copy()
    for key in ('BEA_FILE','BEA_TOKEN','BEANCOUNT_LOAD_CACHE_FILENAME','BEA_ENGINE_PYTHON','BEA_ENGINE_DIR'):env.pop(key,None)
    env.update(BEA_CONFIG_DIR=str(case/'config'),XDG_CACHE_HOME=str(case/'cache'),BEA_NO_UPDATE_NOTIFIER='1')
    for tag,account in filters:
        args=[exe,'--json','--no-input','--offline','--file',str(book),'report','cash-flow','--time','2024-02','--from-date','2024-02-01','--to-date','2024-02-29',*(['--account',account] if account else [])]
        r=subprocess.run(args,cwd=case,env=env,input='',text=True,capture_output=True,timeout=25);assert book.read_bytes()==fixed
        print(json.dumps(dict(tag=tag,args=args,cwd=str(case),exit=r.returncode,stdout=r.stdout,stderr=r.stderr),ensure_ascii=False))
    print('Actual opening/change/closing: all CCE=1000/550/1550; Checking=1000/350/1350; no CCE=0/0/0 '+currency)
if __name__=='__main__':main()
```

All reports use matching February `--time`, explicit February1/29 bounds,
ordinary dates and fully declared accounts. Independent uncached native

postings before February1 and through February29. Thus no generated opening
transaction, maximum-date cutoff, valuation conversion or plugin is needed.

## Cause, bounded repair and acceptance

`cli/src/bea_engine/report.py:940` resolves the account matcher. Fava's
`AccountFilter.apply` (`cli/src/fava/core/filters.py:519`) keeps a whole
transaction when any leg matches; `_cash_flow` then discards nonmatching
postings at `report.py:967` before building account changes. Closing CCE is
independently filtered at :984. The retained noncash changes are inverted
at :1003 and summed as `net_change` at :1009; :1011–1015 sets
`opening = closing - net_change`. Per-posting filtering can remove the
balancing counterpart, so that subtotal need not equal the selected cash
accounts' actual movement. The calculation forces an equation rather than
checking it. The frontend at `cli/src/cli/commands/report.py:610–665` renders
that same payload as JSON or labels it “Opening cash” and “Net change in
cash.” Caller search finds only the cash-flow report dispatch at
`bea_engine/report.py:136–137`; sibling report arithmetic is separate.

Bounded target: validate the conservation precondition for an account-filtered
statement against independently accumulated selected CCE movement. When the
filter removes a required balancing side, refuse that unsupported statement
with an actionable explanation naming `--account` and suggesting removal or
a broader, balanced filter. Do not present or export fabricated opening/change
as actual cash. Retain the documented per-posting filter scope; including
unmatched rows silently would change it. Apply the same supported/error result
to human and JSON, and do not make `--allow-errors` bypass this valid-ledger
report-basis failure. This is a bounded filter guard, not an unfiltered FX,
role-classification or noncash-activity redesign.

ADR024 explicitly declines a blanket reconciliation refusal, on the premise
that raw-unit identity holds “by construction”; it also promises `--account`
narrows rows and CCE together “so the statement still reconciles.” These
real commands disprove that premise after filtering. Clarify the unsupported
filter exception in that contract and help/docs. No owner-selected classifier
or upstream Beancount behavior needs replacing.

Acceptance: each four affected filters above produces a truthful unsupported
filter state rather than the shown fabricated figures, including Salary-only
with an empty CCE set and the regex omitting Savings. All-active/absent filters
retain1000/550/1550, no-match stays genuinely empty, and a quiet March retains
opening=closing1550 (all) or1350 (Checking), change0. Add meaningful native
and real-CLI regressions using actual boundary balances, not
`opening + net == closing` alone. Retain the completed feature's unfiltered
FX, costed investment, roles/invalid values, inherited membership, cash
transfers, multi-currency, no-cash and finite-bound controls. Run `make check-all`
inside `cli/` when implementing. No dependency or eligible API change.

# Recognize reused bank references in overlapping statements before skipping rows

**Major · cli · 45–60m · A1.** A statement containing two dated payments
under one bank reference imports both into empty books, but if either payment
is already present it labels both rows duplicates and skips the missing one.
Even `--duplicates include` writes nothing, at exit 0. The ledger remains
valid but understates spending: Cash/Food are -7.75/+7.75 USD instead of
-15.50/+15.50 USD. No existing data is overwritten; no fix implemented.

Real CLI QA, 2026-10-21, HEAD `813ad9ae4` (initial reproduction on
`4f960f281`, CLI unchanged), checkout `bea 0.3.1`, macOS 26.5.1 arm64,
frontend Python 3.13.3, existing managed Python 3.12.10. Fresh subprocesses,
closed stdin/no TTY, isolated absolute config/cache, notifier disabled,
no inherited `BEA_FILE`/`BEA_TOKEN`. Synthetic local files only.

Create `/abs/books/main.bean`:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Food USD
```

Create `/abs/books/first.csv`:

```csv
Date,Amount,Description,Reference
2024-02-29,-7.75,Autopay,autopay-001
```

Create `/abs/books/combined.csv`:

```csv
Date,Amount,Description,Reference
2024-02-29,-7.75,Autopay,autopay-001
2024-03-06,-7.75,Autopay,autopay-001
```

With `bea` on PATH and the isolated child environment above:

```sh
bea --json -f /abs/books/main.bean check
bea --json --no-input -f /abs/books/main.bean import /abs/books/first.csv --csv date=Date,amount=Amount,narration=Description,id=Reference --account Assets:Cash --default-account Expenses:Food --apply
bea --json --no-input -f /abs/books/main.bean import /abs/books/combined.csv --csv date=Date,amount=Amount,narration=Description,id=Reference --account Assets:Cash --default-account Expenses:Food
bea --json --no-input -f /abs/books/main.bean import /abs/books/combined.csv --csv date=Date,amount=Amount,narration=Description,id=Reference --account Assets:Cash --default-account Expenses:Food --apply --duplicates include
bea --json -f /abs/books/main.bean query "SELECT account,sum(number) GROUP BY account ORDER BY account"
bea --json -f /abs/books/main.bean list transaction --limit 100
bea --json -f /abs/books/main.bean check
```

All seven exit **0**, with empty stderr. The first import writes one.
Combined preview says `duplicate, duplicate`, `duplicates: 2`, `ready: 0`;
both reasons say `import-id bank:autopay-001 is already in the ledger.`
The include apply writes **0**. Query returns Cash **-7.75 USD**, Food
**7.75 USD** and the listing contains one transaction. Both CSVs stay
byte-identical, and the failed-to-import statement leaves the ledger unchanged.
Reproduced twice from pristine books, including this real first-import flow.
An additional default unattended apply also exits 0 with no writes in both
partial-overlap cases; on empty books it correctly refuses the same ambiguous
two-row file with review exit 4.

Expected: row 1 remains an exact duplicate; row 2 must be reviewed as a
distinct-date occurrence of a reference this very statement proves is reused.
The existing review policy should refuse an unattended default apply, and
`--duplicates include` should append only the missing occurrence. Final Cash
must be -15.50 USD, with two transactions and a passing check. IMPORTING's
within-export contract says a repeated native ID with the same amount on
another date is a possible duplicate, never a silent skip.

Controls, twice: on empty books the same combined file previews
`new, possible_duplicate`; include writes two and Cash is -15.50 USD.
With both dated occurrences already present, both are correctly skipped and
Cash stays -15.50. With only the later occurrence present, the original
six-day combined file also wrongly skips both and leaves Cash -7.75.
Moving the second date to March 7 (seven days away) makes the partial-overlap
case correctly review/include the missing row. A same-day repeat remains one
payment. A **single-row** March 6 export against February 29 still correctly
deduplicates under the documented under-a-week date-cleanup policy; keep that
behavior. Do not simply change the seven-day threshold or make include write
all exact duplicates.

Cause: shared analysis in `cli/src/bea_engine/importing.py` populates
`batch_rows` and the in-memory identity/date index only for `new` or included
`possible_duplicate` entries (:642–647). An already-present first row is not
recorded as current-source evidence. The within-export reference-reuse guard
(:578–596) therefore never sees it: that guard requires the matched object's
identity to be in `batch_rows`. The ledger-only branch instead accepts the
same native ID/amount within `_REUSED_REFERENCE_DAYS = 7` (:597–603, :1602).
One ledger occurrence then proves both distinct source dates duplicate.
The later-only control also shows why retaining only earlier *accepted* rows
or one match object cannot settle source occurrence multiplicity.

Fix: consider all current statement occurrences, including rows already in
the ledger, when deciding whether its reference is unique. Keep known exact
occurrences duplicate; classify a missing distinct-date occurrence for review
instead of reusing one ledger occurrence to silently erase it. Preserve
whole-file reimports, same-day repeats, account/ID namespaces, native amount
conflicts and the single-row within-week date-edit behavior. Source reuse
evidence must be independent of whether a row is selected to write.

The matcher is shared by CSV and Python-importer transactions, and both now
have runtime proof. Six fresh native-importer books (two repetitions ×
`bank_id`, OFX `fitid`, or a supplied non-generated `import-id`) import the
first payment, then falsely skip both composite rows at include: Cash stays
-7.75 rather than -15.50 USD. A changed-amount second row still previews
`duplicate, conflict` and refuses apply with exit 4. All native checks pass,
and source JSON/config bytes and the ledger after each refusal stay unchanged.
Generated content hashes, transfer-side pairing, price deduplication and
ledger edits are outside this fix. Keep exact duplicates skipped even under
include. The controlled native configs and results are retained in ignored
pass19 evidence as `controls_native_importer_overlap_namespaces.py` and
`native-importer-overlap-namespace-control-results.json`; the CSV reproduction
above remains self-contained.

Dedupe: all board states, targeted history and all eight open milestones
were checked. Completed w5/075 (`b3e98e7f1`) introduced same-export reuse
review but indexed accepted rows only. Completed w5/599 (`55d7a6ed`) added
the cross-export seven-day rule and explicitly preserves shorter date edits.
Completed w5/822 (`53de922d3`) chooses the nearest existing occurrence and a
same-day twin; it does not account for multiple current-source dates matching
one ledger occurrence. Open w5/882 is other-account transfer counterpart
consumption, a different matcher. No open item covers this partial overlap.

Acceptance: the seven-command flow writes one missing transaction at include,
ends at Cash -15.50/Food 15.50 and passes check. Before explicit include it
requires review and preserves bytes. Cover earlier-only, later-only,
both-known, empty, same-day and single-row date-edit controls, and keep
existing native-ID amount conflicts and account scoping intact.


---

**Resolved 2026-10-22** — fixed: import (`cli/src/bea_engine/importing.py`) now collects the bank-issued ids a statement carries on more than one date (`_reused_references`) before judging its rows, and a ledger match on another date for such a reference counts as that other occurrence rather than this row's corrected date, whatever the distance. With either payment already present, the matching occurrence stays a duplicate and the missing one is a `possible_duplicate` that the default apply refuses (exit 4) and `--duplicates include` writes alone (Cash -15.50 USD, check passes); both present still skips both, empty books still review the second row, and a single-row file within a week of its ledger entry still deduplicates as a date edit. Regression tests in `cli/tests/test_import_reused_reference_partial_overlap.py` fail without the fix. Shipped in this commit (`cli`).

# Document how to diagnose an agent invoking the wrong bea executable

**Estimate:** 45m. **Worker:** worker1. **Priority:** 3. **Depends on:** none.

**Source:** `/pm-brainstorm more for w5`, all three proposals approved with `$pm all for w5` on 2026-09-28. The [first-month rehearsal](../../skills/docs/first-month-rehearsal.md) records an agent login shell resolving an older global `bea` despite its parent's PATH. Binding the session to the verified absolute executable resolved it.

Scope: `cli/README.md` and, if needed, `cli/docs/USAGE.md`. Add a short troubleshooting path: inspect executable resolution in the actual shell that runs the command, check `--version`, inspect `engine status`, and retry the synthetic command with the verified absolute executable. Distinguish an old executable from an unprovisioned engine. Reuse existing commands; no new diagnostics framework or automatic environment repair.

**A2:** terminal and coding-agent users can identify a version mismatch themselves. Expected signal: correctly identifying the selected executable and completing a synthetic ledger check without operator correction. This matters before and after a new release, because an older installation can otherwise mask the upgrade.

**Done when:** in an isolated setup with two distinguishable CLI versions, the documented steps reveal which executable the actual command shell selected, then successfully check a synthetic ledger through the intended absolute executable. Record the tested shell/platform and avoid unsupported cross-platform claims. No existing environment is deleted, no personal configuration is changed, and the ledger remains unchanged. Relevant documentation checks and links pass.

Keep this as a sub-hour inbox note. It is independent of m11 and 021. Use `cli/tmp/` for scratch work. Do not duplicate or change the already-correct engine override diagnostics from w5/011.

**Resolved 2026-09-28** — `cli/README.md` now has a "Which `bea` is running?" section. From the shell that actually runs the command, it uses `type -a bea`, `bea --version` and `bea engine status`, then retries with a verified absolute executable. It separates an old executable from an unprovisioned engine. Shipped in `152ace62` (`cli`).

Tested on macOS 26.5.1 arm64 with `/bin/bash` 3.2.57 as a login shell. The shell had a throwaway `HOME` whose profile put published 0.3.0 ahead of a 0.3.1 build that the parent `PATH` preferred. The steps showed the login shell selecting 0.3.0 and reported its engine as not provisioned. The absolute 0.3.1 executable then checked a synthetic ledger, whose bytes were unchanged. No personal configuration was touched, and other shells and platforms were not tested. `make check-all` passed, including the README docs-example test.

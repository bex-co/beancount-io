# Check deletes ledger files when its cache filename aliases the input

**Major (data loss) · cli · 45–60m · A1/A2.** Real CLI QA, 2026-10-08,
HEAD `c247f7c8`, checkout `bea 0.3.1`, Python 3.13.3, macOS. A validation
command deletes its own input when `--cache-filename` names the root or an
included ledger. No product fix implemented. Promote if native option parsing
and cache policy require more than an hour.

Create disposable `/absolute/books/main.bean`:

```beancount
2026-01-01 open Assets:Cash USD
include "child.bean"
```

Create `/absolute/books/child.bean`:

```beancount
2026-01-02 note Assets:Cash "cache safety"
```

Use isolated BEA_CONFIG_DIR/XDG_CACHE_HOME, BEA_NO_UPDATE_NOTIFIER=1,
no inherited BEA_FILE/BEA_TOKEN, closed stdin, no TTY, and a foreign cwd:

```sh
bea --file /absolute/books/main.bean check --cache-filename /absolute/books/main.bean
```

Actual: exit 1, empty stdout. Stderr first says the cache is corrupted
(`unpickling stack underflow; recomputing`), then says the root does not exist.
The root has been deleted. On a fresh fixture, naming `child.bean` instead
deletes that file and reports that its include glob matches nothing. Both
direct cases repeated in two pristine directories, with before/after hashes
and absence checks. No real user ledger was used.

Further real-command reproductions on fresh fixtures:

- `--cache-filename main.bean` resolves beside the root and deletes it.
- `--cache-filename '{filename}'` expands to the root name and deletes it.
- `--cache-filename=/absolute/books/main.bean` deletes the root too.
- Cache destinations that are symlinks or hard links to the root are deleted;
  check exits 0 and the root survives. This removes the alias directory entry,
  not the target's bytes; it is not a claim of hard-link target data loss.
- Adding `--no-cache` with the colliding root path still deletes the root,
  despite warning that the explicit cache filename will be ignored.

Controls: a separate absent `cache.pkl` destination exits 0 and preserves both
files, with and without `--no-cache`, repeated twice. Target-discovery controls
independently select explicit file over BEA_FILE, environment over cwd, and
main.beancount after main.bean removal.

Expected: a ledger validation command must refuse a cache destination that is
the root or a member of its include closure before invoking a destructive
cache handler. The package documents protection against output aliases to a
ledger, and `check --help` advertises this native output option without a data
loss exception. Use exit 2 naming the collision, preserving every file/link.

Cause: `cli/src/cli/commands/check.py:61` forwards
`[str(file), *ctx.args]` to native bean-check without checking cache paths.
Upstream `beancount.scripts.check` initializes the loader with the requested
cache pattern. `beancount.loader.pickle_cache_function` tries to unpickle an
existing cache, removes it on failure, then loads the ledger. If cache and
ledger are the same, removal happens before parsing. The uncached wrapper
also removes the computed cache path, explaining the no-cache case.

Caller/source search finds one registered check handler; the JSON/compatibility
helper branches refuse native options and never reach this native path.
This finding is the frontend missing guard; it does not require an upstream
fork or changing cache serialization. Derive the effective cache path using
upstream's supported pattern/relative rules and native option semantics, then
apply the existing closure/inode-aware output protection before dispatch.
Do not assume --no-cache makes a collision safe. Keep ordinary native flags,
JSON refusal and compatibility-ledger refusal intact. No dependency/API change.

Full-board/history dedupe for cache-filename, cache deletion and output aliases
found no overlapping item. Completed w3/390 concerns stale default cache
invalidation; w3/222 explicitly left native cache-flag forwarding unverified.
Completed output-guard work protects query/format/native exporters, not this
check forwarding path. Current check history adds compatibility/document
validation, with no cache-destination preflight.

Acceptance: root/include, relative/pattern/equal spellings and alias collisions
are refused before native execution, including with --no-cache. Files and
links stay intact; safe cache and ordinary check commands succeed. Only
macOS/checkouts exercised; installed managed engines and other platforms are
unverified. The upstream cause is source-confirmed in the active engine.

Sanitized evidence: `cli/tmp/qa-20261008-cli/check_cache16.py`,
`check-cache16-console.jsonl`, `check_cache_variants16.py`,
`check-cache-variants16-console.jsonl`, fixtures and `transcript.jsonl` retain
argv, cwd, environment, streams/exits, pre-deletion hashes and existence
checks. The public repro is self-contained.

---

**Resolved 2026-10-10** — `bea check` now derives the load-cache path the way upstream's loader does and refuses it, with exit 2 and before bean-check starts, when it is the root ledger or any file in its include closure. The comparison is by file identity, so a symlink or hard link to a ledger file is refused too, and `--no-cache` does not bypass it. The message names the option, the value and the ledger file, and says nothing was changed. Shipped in `7a9c2edf` (`cli`).

Real-command regression tests, run from a foreign working directory, cover the absolute root and include, relative spellings beside the root, the `{filename}` pattern, `--cache-filename=VALUE`, a dotted path, `--no-cache` before and after, a repeated option where the last wins, symlink and hard-link aliases of both files, and the `BEANCOUNT_LOAD_CACHE_FILENAME` default. Each asserts exit 2 and that every directory entry, its link status and its bytes are unchanged; sixteen of these fail with the guard removed, most by deleting the fixture ledger. A separate cache path, absolute or relative, with and without `--no-cache`, still passes, and a genuinely invalid ledger is still reported with exit 1. `docs/USAGE.md` Output destinations states the rule. `make check-all` passed.

Not covered by this change: `BEANCOUNT_LOAD_CACHE_FILENAME` is honoured by every command that loads a ledger, not only `check`. With it set to `{filename}`, `bea list`, `bea query`, `bea balance` and `bea doctor print-options` each still removed a throwaway root ledger at this commit. Only the `check` path is guarded here; the wider environment-variable exposure needs its own item. Installed managed engines and platforms other than macOS were not exercised.

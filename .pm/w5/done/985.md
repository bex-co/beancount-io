# Keep transaction details parseable when redirected

**Minor · cli · 20–30m · A1 · worker1.** Real local CLI QA, 2026-10-22,
`bea 0.3.1` with checkout sources at `326a1c88bf08a37eb090e66fd3cd58204226845c`,
macOS 26.5.1 arm64, frontend Python 3.13.3 and managed Python 3.12.10 /
Beancount 3.2.3. No product fix implemented.

`bea list transaction --details` exits 0 but puts an uncommented
`/absolute/path/main.bean:4` on stdout immediately before the transaction.
Redirecting that output to a ledger, with the required account opens, fails
`bea check` with exit 1 for parser/lexer errors on the source-heading line.
The transaction body itself is valid. The source ledger stays byte-identical.

USAGE's `--details` contract says redirected output parses back and retains the
ledger's strings. A coding agent cannot reuse a selected transaction stream as
Beancount without inventing a filter for the extra lines. Preserve the source
locations as Beancount comments (or otherwise keep them out of the redirected
syntax), keeping all transaction bodies and metadata unchanged.

Run this self-contained synthetic reproducer after replacing `/abs/details-case`
with a fresh absolute directory. It invokes the real `bea` with closed stdin,
no TTY and isolated config/cache, records the argument array, exit and separate
streams, and verifies the original source hash. Repeat in a second fresh
directory; set `mode` to `authored-P` for the second flag control.

```python
import hashlib, json, os, pathlib, subprocess
case = pathlib.Path('/abs/details-case')
mode = 'ordinary'  # 'ordinary' or 'authored-P'
case.mkdir(parents=True)
source = case / 'main.bean'
base = ('option "operating_currency" "USD"\n'
        '2024-01-01 open Assets:Cash USD\n'
        '2024-01-01 open Expenses:Food USD\n')
flag = 'P' if mode == 'authored-P' else '*'
source.write_text(base + f'2024-01-02 {flag} "Lunch"\n'
                  '  receipt: "R-1"\n'
                  '  Assets:Cash -7.50 USD\n'
                  '  Expenses:Food 7.50 USD\n', encoding='utf-8')
original = source.read_bytes()
env = os.environ.copy()
for key in ('BEA_FILE', 'BEA_TOKEN', 'BEANCOUNT_LOAD_CACHE_FILENAME'):
    env.pop(key, None)
env.update(BEA_CONFIG_DIR=str(case / 'config'),
           XDG_CACHE_HOME=str(case / 'cache'), BEA_NO_UPDATE_NOTIFIER='1')
def run(tag, args, file=source, json_mode=True, stdin=None):
    cmd = ['bea', *(['--json'] if json_mode else []), '--no-input',
           '--file', str(file), *map(str, args)]
    result = subprocess.run(cmd, cwd=case, env=env, input=stdin,
                            stdin=None if stdin is not None else subprocess.DEVNULL,
                            capture_output=True, text=True, timeout=25)
    record = dict(tag=tag, args=cmd, exit=result.returncode,
                  stdout=result.stdout, stderr=result.stderr,
                  source_preserved=source.read_bytes() == original,
                  source_sha256=hashlib.sha256(source.read_bytes()).hexdigest())
    print(json.dumps(record), flush=True)
    return result
run('source-check', ['check'])
listed = run('json-list', ['list', 'transaction', '--on-disk', '--limit', '100'])
rows = json.loads(listed.stdout)['data']
details = run('details', ['list', 'transaction', '--details', '--on-disk',
                          '--limit', '100'], json_mode=False)
bad = case / 'details.bean'
bad.write_text(base + details.stdout, encoding='utf-8')
run('details-check', ['check'], file=bad)
# A nearby working control changes only the source-heading lines to comments.
headings = {f"{row['source']['filename']}:{row['source']['lineno']}" for row in rows}
commented = case / 'commented.bean'
commented.write_text(base + ''.join(('; ' if line.rstrip('\n') in headings else '') + line
                                   for line in details.stdout.splitlines(keepends=True)),
                     encoding='utf-8')
run('commented-check', ['check'], file=commented)
printed = case / 'printed.bean'
run('query-print', ['query', 'PRINT', '--output', printed], json_mode=False)
run('printed-check', ['check'], file=printed)
copy = case / 'copy.bean'
copy.write_text(base, encoding='utf-8')
run('json-replay', ['add', 'transactions', '--from', '-'], file=copy,
    stdin=json.dumps(rows))
run('replay-check', ['check'], file=copy)
```

In both modes, twice from pristine directories:

- `source-check`, `json-list` and `details` exit 0. `details` stdout starts with
  the bare absolute `main.bean:4`, then `2024-01-02 * "Lunch"` (or `P`). Its
  separate stderr is `Transactions rendered in Beancount syntax: all postings,
  with source locations.`
- `details-check` exits 1. Its one JSON stderr object names parser/lexer errors
  in `details.bean` at line 4, the location heading; stdout is empty.
- Commenting only that heading makes `commented-check` exit 0. `query PRINT`
  and its `printed-check` also exit 0. JSON replay writes exactly one row,
  and `replay-check` exits 0.
- Independent, unwrapped native loads of source, commented, PRINT and JSON
  copies retain exactly one transaction, the original flag, `Lunch`, receipt
  `R-1`, Cash `-7.50 USD` and Food `7.50 USD`. The unchanged details export alone
  has parser errors. All reads preserve source bytes.

This is independent of flag/provenance classification: two additional
32-transaction books cover every native flag (`* ! & # ? %` and A–Z). All 64
written transactions survive `--on-disk`, their exact flag filters, JSON replay
and repeated native-ID import (zero writes). The full details stream fails;
commenting only the known heading lines makes every body reload unchanged.
The first harness's assumption that the full stream was parseable exposed this
failure; it was then reduced to the single ordinary transaction above.

Cause: `cli/src/cli/commands/list.py:_run`, lines 422–430. The details branch
prints its status note to stderr correctly, but line 427 uses `typer.echo` to
emit `filename:lineno` as a bare stdout line. It then emits the correctly
rendered body. The engine's `ledger/listing.py:125–130` supplies bodies through
`format_transaction(..., loaded=True)`; that renderer is working here.
The frontend source heading is the missing part of the parseable stream.

Caller search: only human transaction details enters this rendering branch;
JSON list returns the structured rows before it. `--on-disk`, filters, sorting
and limits converge on the same branch. `query PRINT` is a separate working
export path. No accounting, engine protocol, REST, GraphQL or MCP change is
needed for this local presentation fix.

Dedupe: searched every `.pm/**/*.md`, including done and blocked notes, for
transaction details, redirected/parseable output, bare source/location headers
and the status-note text; read all 40 active/blocked milestone scopes. Completed
w5/834 fixed body-string sanitization in `f5dc8b324` and remains closed. Its
regression test explicitly discards stdout's first line before parsing
(`cli/tests/test_list_details_keeps_strings.py:33`), so it does not test the
complete redirected stream. This is a distinct frontend heading defect and a
follow-up to that completed outcome. Completed 405 covers locale encoding;
401 and open 937 cover generated provenance, all distinct. Targeted `list.py`
history shows no later source-heading repair; the heading predates 834.

Acceptance: redirect the **complete**, unfiltered `--details` stdout for the
reproducer into a ledger with the account opens and get check/native parse
success with the same transaction, metadata and amounts. Keep source locations
readable as comments, stderr's notice separate, JSON shapes unchanged, and the
834 string-preservation behavior. Cover a multi-entry stream and an ordinary
flag plus authored `P`; do not strip the source lines in the regression test.
Terminal rendering, generated-plugin details and Windows/Linux were not
exercised in this finding.

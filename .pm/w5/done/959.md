# Treat repeated allowed currencies as one during transaction inference

**Minor · cli · 20–30m · A1.** An existing valid account opened for
`USD, USD` permits one distinct commodity, but `add transaction` refuses a
bare numbered posting as currency-ambiguous. Explicit USD and CSV inference
work. The rejected command preserves the ledger. No product fix implemented.

Real CLI QA, 2026-10-21, HEAD `76af7a965` (CLI unchanged from `674c24216`),
checkout `bea 0.3.1`, macOS 26.5.1 arm64, frontend Python 3.13.3, managed
Python 3.12.10 / Beancount 3.2.3. Fresh bounded subprocesses, closed
stdin/no TTY, isolated absolute `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier
disabled, inherited `BEA_FILE`/`BEA_TOKEN` removed. Synthetic local books.

Create this existing native ledger, which needs no operating-currency option
because its accounts already restrict the posted commodity:

```python
from pathlib import Path
books = Path('/abs/books')
books.mkdir(parents=True, exist_ok=True)
(books / 'main.bean').write_text('''2024-01-01 open Assets:Cash USD, USD
2024-01-01 open Expenses:Food USD
2024-01-01 open Equity:Opening USD
2024-01-01 * "Capital"
  Assets:Cash 100 USD
  Equity:Opening -100 USD
''')
(books / 'bank.csv').write_text(
    'Date,Description,Amount\n2024-01-03,Coffee,-7.75\n')
```

From `/abs/books`:

```sh
bea --json -f /abs/books/main.bean check
bea --json --no-input -f /abs/books/main.bean add transaction --date 2024-01-02 --narration Snack -p 'Assets:Cash -4.50' -p Expenses:Food
bea --json --no-input -f /abs/books/main.bean import bank.csv --csv date=Date,narration=Description,amount=Amount --account Assets:Cash --default-account Expenses:Food
bea --json --no-input -f /abs/books/main.bean add transaction --date 2024-01-02 --narration Snack -p 'Assets:Cash -4.50 USD' -p Expenses:Food
bea --json --no-input -f /abs/books/main.bean import bank.csv --apply
bea --json -f /abs/books/main.bean query 'SELECT account,sum(number) GROUP BY account ORDER BY account'
bea --json -f /abs/books/main.bean check
bea --json --no-input -f /abs/books/main.bean import bank.csv --apply
bea --json -f /abs/books/main.bean report overview --time 2024-01 --conversion USD
```

Exits: **0, 2, 0, 0, 0, 0, 0, 0, 0**. The bare add says
`Currency is ambiguous for Assets:Cash; specify NUMBER CURRENCY explicitly.`
It changes no bytes. Human output has the same refusal. The CSV preview
correctly infers USD, and explicit add writes one Snack. CSV apply writes
one Coffee; repeat writes zero. Final Cash **87.75**, Food **12.25**,
Equity **−100 USD**, check valid and overview net worth **87.75 USD**.
The original duplicated open remains intact.

Expected: [USAGE.md](../../cli/docs/USAGE.md#adding-directives) says a
numbered posting without currency uses the account's sole allowed currency
before the operating-currency fallback. Repeating USD does not make EUR
or any other commodity allowed. The bare Snack should write once in USD,
as it does after removing only the duplicate token. Preserve the native
file's contents and the explicit-symbol escape for genuine ambiguity.

Reproduced twice in **22 fresh books** covering two/three USD occurrences,
EUR repetitions, absent/same/different/multiple operating currencies and
split roots. False ambiguity occurs with no operating currency, a different
operating currency, or several operating currencies. With sole operating
USD, repeated USD happens to work through the fallback. A single USD open
works without any operating currency. CSV correctly uses the one distinct
account currency in all repeated-only cases. Explicit symbols work in every
case; all final balances match the model above in USD or EUR.

Twenty-two unwrapped native-loader references independently report no
errors and retain the repeated currency lists. Genuine USD/EUR and
unrestricted accounts without an operating default correctly refuse to
infer. Four further fresh controls confirm those accounts still use a sole
operating USD when provided. Current `add open -c USD -c USD` already writes
one USD, verified with a successful subsequent bare add: completed
[448](./done/448.md) prevents new duplicates, while existing native files
can still contain them.

Cause: `cli/src/bea_engine/ledger/adding.py:_transaction` copies raw native
`Open.currencies` lists into `allowed` (:1152). At :1168–1175 it tests
`len(choices) != 1` without deduplicating them. Thus two USD tokens count as
two choices. The optional operating-currency branch explains the masking
control. This is the single-add dispatcher path; bulk uses `_transactions`
and explicit schema currencies, rather than this inference block. CSV's
`importing._row_currency` (:1796) already collects allowed currencies into
a set and correctly chooses USD for the same file.

Fix: judge account-currency cardinality by distinct symbols before
single-add fallback and ambiguity checks. Keep source text/list presentation
intact, account-currency precedence, unrestricted/multicurrency operating
fallbacks, and the cost/price safeguards that refuse defaulting an omitted
commodity to its own rate currency. No dependency or API change.

Dedupe: searched every board state for duplicate/repeated account currencies,
bare inference and ambiguity, and reviewed active milestone scopes.
`git log -S` traces the raw choice list to `a90b17065` (ADR014 engine),
with no later distinct-currency repair. 448 is the new-open producer;
open [916](./916.md) compares imported openings by allowed-currency sets
for identity. That comparison does not change this single-add context.
934 is root discovery and 950 import identity after interpolation; neither
owns this already-correct root's allowed-currency choice.

Acceptance: both repeated-only USD/EUR accounts infer their unique currency,
independent of operating defaults and split layout; the public bare add
writes one balanced Snack. Preserve genuinely ambiguous refusals, explicit
symbols, CSV behavior, new-open deduplication and unchanged source headers.

`repeated-account-currency-inference-results.json`,
`repeated-account-currency-fallback-controls.json`, producer pilot and

Starting with a **fresh disposable copy of the Python fixture above**,
prepare its original four directives as an import into an empty root:

```python
from pathlib import Path
books = Path('/abs/books')
(books / 'native.statement').write_bytes((books / 'main.bean').read_bytes())
(books / 'main.bean').write_text('')
(books / 'importer.py').write_text('''from beancount.parser import parser
class Native:
    name = 'native-opens'
    def identify(self, file): return str(file).endswith('.statement')
    def account(self, file): return 'Assets:Cash'
    def extract(self, file, existing_entries=None):
        entries, errors, _ = parser.parse_file(str(file))
        assert not errors, errors
        return entries
CONFIG = [Native()]
''')
```

```sh
bea --json --no-input -f /abs/books/main.bean import native.statement --config importer.py --apply
bea --json -f /abs/books/main.bean check
bea --json -f /abs/books/main.bean list open
bea --json --no-input -f /abs/books/main.bean add transaction --date 2024-01-02 --narration Snack -p 'Assets:Cash -4.50' -p Expenses:Food
```

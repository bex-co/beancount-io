# The public ledger embed code puts its "View on Beancount.io" badge over the embedded sidebar: on a blog, it covers "Ledger Settings" and "Collapse sidebar", and clicking either opens a new tab instead

**Severity:** minor. Nothing is lost, but an owner who publishes the embed gets a widget whose own badge hides part of the ledger it shows. **Owner:** `dashboard`. **Estimate:** 20–30 minutes including tests. **A3:** Ledger Settings offers every public ledger an **Embed Code** for blogs and docs, so this is how a ledger is seen away from beancount.io. The code it generates scales the ledger to 60% in a 4:3 frame. It then places the attribution link absolutely, 12px from the frame's bottom-left corner, which is where the embedded sidebar keeps its footer controls. **Found by:** `/qa-find-bugs-dashboard` (`dashboard-qa` routine) on 2026-11-27 against `https://beancount.io`, entry chunk `main-BBmi61Hs.js`, isolated headless Chromium 158, English. Read-only: the embed was copied from `open_ledger/example`'s Ledger Settings and served from a stand-in third-party origin (a Playwright route), signed out. Local HEAD `405eb456a`.

## Repro

1. Open `/ledger/open_ledger/example/settings` and copy the **Embed Code** textarea (`#embed-code`) unchanged.
2. Put it in a page on another origin, inside a 900px-wide content column, and load that page. The ledger renders in the frame (no framing headers block it). The frame's viewport is 1500×1125, shown at 60%.
3. The black **View on Beancount.io** badge (190×32) sits over the bottom of the embedded sidebar. `document.elementFromPoint` at the centre of the embedded **Ledger Settings** link, and at the centre of **Collapse sidebar**, returns the badge's `<a>`, not the frame, so a click there lands on the badge, which opens the ledger in a new tab. **Ask Beancount.io**, one row higher, stays clear.
4. In a 700px column (frame viewport 1167×875), the badge covers **Ledger Settings**. In a 480px column (frame viewport 800×600), the sidebar is in its icon rail, and the badge covers the Ledger Settings and Collapse icons and the start of the chart beside them.

Repeated from a fresh load at each width. Control: the embedded page itself is fine, and every sidebar link above the footer receives clicks.

## Cause

`dashboard/src/features/ledger-data/settings/visibility-section/index.tsx:39–66`, `buildEmbedCode`. The wrapper is a `position: relative` box with `padding-bottom: 75%`. The iframe fills it (`166.667%` wide and high, `transform: scale(0.6)`). The `<a>` badge is `position: absolute; bottom: 12px; left: 12px; z-index: 10` inside the same box, so it is drawn over the frame's bottom-left corner. In left-to-right layouts, the sidebar footer (Ask Beancount.io, Ledger Settings, Collapse sidebar) is pinned there at every height.

## Fix

Owned by `dashboard`. No API change, no new translation key.

- Generate the attribution so it never overlays the frame. Put the 4:3 frame box first, then the **View on Beancount.io** link below it in normal flow, inside an outer wrapper. Keep the link's `href`, `target="_blank"`, `rel="noopener noreferrer"`, its localized label (`page.settings.embedViewOnBeancount`) and its styling. Keep the frame's scale, aspect ratio, `title` and `loading="lazy"`.
- Code already pasted on other sites keeps the old layout. Only newly copied code changes, so no migration is needed.

## Definition of done

- On production, the embed code copied from a public ledger's Ledger Settings, placed in 900px, 700px and 480px columns on another origin, leaves every embedded sidebar control reachable: `elementFromPoint` at the centre of **Ledger Settings** and **Collapse sidebar** returns the iframe. The badge is visible directly below the frame and opens the ledger in a new tab.
- A test of `VisibilitySection` (or of `buildEmbedCode`, exported for it) parses the generated code and asserts that the attribution link is not absolutely positioned inside the frame's box and that it follows the iframe. It must fail on the current code. A string snapshot does not count. Dashboard gates pass.

## Blast radius

`buildEmbedCode` is the only embed generator in `dashboard/src`, and it has one caller, the Visibility section, shown only for public ledgers. No `X-Frame-Options` or `frame-ancestors` header is sent on ledger pages, so embedding works today. The session cookie is `SameSite=Lax`, so the embedded ledger is always the signed-out view.

## Dedupe

Searched every board state for `embed`, `iframe`, `View on Beancount`, `buildEmbedCode` and `attribution`. w3/633 (done) added confirmation before publishing and mentions only that the embed code appears afterwards. No item covers the embed's layout. `git log -S buildEmbedCode` shows the generator unchanged since the dashboard import (`af5339de0`).

## Unverified

Right-to-left locales, where the sidebar sits on the right and the badge would cover main content instead. Also untested: Firefox, Safari, and a host page with its own CSS resets.

# Entry Context: Tab is captured by the source editor, so tabbing through the dialog edits the entry and cannot reach Delete or Save

**Severity:** minor (keyboard access). **Owner:** dashboard. **Estimate:** 30–45 minutes. **A2:** a keyboard user who opens a transaction from Overview's Recent activity, or from the Journal, should be able to Tab to its Delete and Save buttons without changing the entry. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-16 against `https://beancount.io`, using headless Chromium at 1440×1000 in English/light. The account was the QA owner, on its designated disposable synthetic ledger. Local HEAD `85c2548ba`. Every edit was discarded and nothing was saved.

## Repro

1. Open the ledger Overview. Focus a Recent activity row (for example **BLUE BOTTLE Coffee**) and press Enter. The **Entry Context** dialog opens with focus on Close.
2. Press Tab three times. Focus moves to **Open source at main.bean:N**, then to **Entry Context**, then into the source editor (Monaco, accessible name `Editor content`).
3. Press Tab again. Focus stays in the editor, and the press **inserts indentation into the transaction source**. "Source has been modified" appears and Save becomes enabled. Shift+Tab also stays in the editor (it outdents).
4. **Delete** and **Save** come after the editor and cannot be reached with Tab or Shift+Tab. Escape leads only to a "Discard your edit?" prompt, because the Tabs already changed the source. Repeated twice from fresh loads.

Control: pressing Monaco's tab-focus toggle (Ctrl+Shift+M on macOS, Ctrl+M elsewhere) and then Tab moves focus to **Delete** and then **Save**. Nothing in the dialog tells the user about that shortcut, and the editor's accessible name is only `Editor content`.

## Cause

`dashboard/src/features/journal/components/entry-context-panel.tsx:450-469` mounts a 100px (200px on mobile) Monaco editor with default options. By default Monaco binds Tab and Shift+Tab to indent and outdent. The panel renders inside `entry-context-dialog.tsx` (Journal and Overview) and `pages/entry-page.tsx`. The full-file editor under `features/ledger-editor/` is a different case, where capturing Tab for indentation is expected, and is out of scope.

## Fix

In this snippet editor, let Tab and Shift+Tab move focus. Set Monaco's `tabFocusMode: true` in the panel's `options`, or call `editor.updateOptions` in `onMount`. Give the editor a descriptive `ariaLabel` (for example "Entry source"). Beancount posting indentation can still be typed with spaces, and Enter keeps auto-indent. Read-only viewers get the same behavior.

## Definition of done

- In the repro above, Tab from the editor moves focus to **Delete** (owner) and then **Save**, and leaves no "Source has been modified" notice. Shift+Tab from the editor returns to **Entry Context**.
- Typing a posting line with spaces and pressing Enter still produces correct indentation, and Save still writes edited source exactly once.
- A rendered test asserts that the panel passes `tabFocusMode: true` (or the equivalent) to the editor, and that the Save/Delete footer follows the editor in tab order. A browser-level check is welcome but optional, because Monaco is mocked in unit tests (`src/test/mocks/monaco-editor.ts`).

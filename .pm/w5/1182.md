# Accounts says "Not computed" for every closed asset account, even one still holding 10.00 USD that the Balance Sheet and Overview show

**Severity:** minor. The Accounts page is where a reader checks which accounts still hold money. A closed account that was never emptied, which Beancount allows, gives no sign that it still holds money there. **Owner:** `backend-cluster/ledger` (the account-directives read). The dashboard needs only a test. **Estimate:** 30–45 minutes including tests. **A2:** closing an account is a routine step when a newcomer switches banks. A wrong "Not computed" hides a transfer they forgot to make. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-18 against `https://beancount.io` (entry chunk `main-LGv2TZLj.js`), headless Chromium at 1440×1000, English, isolated profile, signed in as the QA owner on a disposable QA ledger. Local HEAD `bc8308143`. The probe was written and then restored byte for byte (same blob SHA, no ledger errors).

## Repro

Append to a ledger that already has an open `Assets:Cash`:

```beancount
2024-01-01 open Assets:Qa:Retired USD
2024-01-01 open Assets:Qa:Frozen USD
2024-04-01 * "qa-retire-in" "Move into retired"
  Assets:Qa:Retired   10.00 USD
  Assets:Cash        -10.00 USD
2024-04-15 * "qa-retire-out" "Empty retired"
  Assets:Cash         10.00 USD
  Assets:Qa:Retired  -10.00 USD
2024-04-02 * "qa-frozen-in" "Fund frozen"
  Assets:Qa:Frozen    10.00 USD
  Assets:Cash        -10.00 USD
2024-05-01 close Assets:Qa:Retired
2024-05-01 close Assets:Qa:Frozen
```

The ledger reports no errors. Then:

1. `/accounts` lists `Assets:Qa:Frozen · Closed · 2024-01-01 · 2024-05-01 · 1 · **Not computed**` and `Assets:Qa:Retired · Closed · … · 2 · **Not computed**`. Open asset accounts on the same page show their balances.
2. `/balance-sheet` (no filter) lists `Frozen 10.00` under Assets. The Overview's Assets card lists `Assets:Qa:Frozen 10.00 USD`. The account page for Frozen shows a 10.00 USD running balance.
3. `getLedgerAccountDirectives` returns `{"account":"Assets:Qa:Frozen","closedAt":"2024-05-01","balance":null,"entryCount":1}` and the same `balance: null` for Retired, which really is empty. Open asset accounts get `{"USD":"…"}`, or `{}` when empty.

The dashboard's "Not computed" label is documented as the state for "an account whose balance the server does not compute (income, expense, and equity accounts)" (`features/ledger-data/accounts/locales/en.ts:92-96`). That was w1/done/025's fix. A closed asset account is not that case. Emptied, it should read like any other empty account (`-`). Funded, it should show its 10.00 USD.

## Cause

- `backend-cluster/ledger/src/features/ledger/utils/account-entries.ts:101-116` (`accountBalances`) fills a balance only for accounts under the asset and liability roots with a `last_entry`. It skips `data.last_entry === null`.
- `backend-cluster/ledger/src/foundation/rustledger/account-list.ts:160-172` leaves `last_entry` null whenever an account's last referencing directive is its own `close`. That mirrors Fava's `get_last_entry`, which feeds the Statistics "Account Last Entries" table. So every closed account loses its balance, whatever it holds.
- `features/ledger/service/ledger-account-service.ts:173` (`getAccountDirectives`) uses that map as the Accounts balance. The dashboard's `BalanceCell` (`dashboard/src/features/ledger-data/accounts/index.tsx:109-117`) then renders `null` as "Not computed".

Statistics' last-entries table is a separate read (`ledger-data-service.ts:738`, `getAccountLastEntries`), so its Fava rule does not depend on this map.

## Fix

In `getAccountDirectives`, give every account under the ledger's asset and liability roots its own units balance (`accountOwnUnitBalances`), whether or not it is closed: `{}` once emptied, the remaining units otherwise. Keep `null` only for accounts outside those roots, so w1/done/025's three states keep their meaning. Leave Statistics' last-entries rule as it is. The one producer feeds GraphQL `getLedgerAccountDirectives`, REST (`backend-v2/src/features/ledger/api/rest/v1/analysis-handler.ts:448`), the MCP `ledgerAccountDirectives` resource and the assistant's account context alike, so parity holds without adapter changes. Run the parity gate. The dashboard needs no code change. Its existing Close gate already skips closed accounts.

## Definition of done

- With the fixture above, `getLedgerAccountDirectives` returns `{"USD":"10.00"}` for Frozen and `{}` for Retired. Accounts shows `10.00 USD` and `-` for them. Income, expense and equity rows still read "Not computed".
- Statistics' "Account Last Entries" is unchanged for the same ledger.
- A ledger-service test pins a funded closed account, an emptied closed account and an open one. A dashboard row test renders the closed-and-funded case. Both fail on the current code. Ledger, backend-v2 parity and dashboard gates pass.

# Sigil-only tag and link filters silently erase matching list results

**Minor · cli · 15–25m · A1.** Real CLI QA, 2026-10-08, HEAD `46dba189`,
checkout `bea 0.3.1`, Python 3.13.3, macOS. A template that builds a filter as
`"#${TAG}"` or `"^${LINK}"` with an unset value gets successful empty results,
rather than the empty-filter usage error already provided for literal blanks.
No product fix implemented.

Synthetic ledger:

```beancount
2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:Food USD
2026-01-02 * "tagged" #trip ^ref
  Expenses:Food 1 USD
  Assets:Cash -1 USD
```

With absolute `--file`, isolated configuration/cache, no inherited BEA_FILE or
BEA_TOKEN, `BEA_NO_UPDATE_NOTIFIER=1`, closed stdin and no TTY:

```sh
bea --json --file /absolute/main.bean list transaction --tag trip --tag '#'
bea --json --file /absolute/main.bean list transaction --link ref --link '^'
```

Both exit 0, stdout contains `data: []` and `truncated: false`, stderr is
empty. Human mode exits 0 with no transaction, too. Lone sigil-only filters
behave identically. Reproduced twice on fresh files, in both output modes,
without changing ledger hashes. Controls: `trip`/`#trip` and `ref`/`^ref`
each return the tagged transaction; `--tag ''` and `--link ''` exit 2 naming
the flag in both modes.

Expected basis: USAGE.md accepts tag/link values with or without their sigils,
and refuses empty filter values because they commonly mean template holes.
After removing the accepted prefix, these values contain no tag/link name.
They should produce the same usage error rather than poisoning the AND set.

Cause: `cli/src/cli/commands/list.py:286–292` validates raw values through
`refuse_blank_filter`; `'#'`/`'^'` pass. Later
`cli/src/bea_engine/ledger/reader.py:246–247` strips sigils with `lstrip`,
inserts an empty name in `wanted_tags`/`wanted_links`, and `issubset` fails
for every ordinary transaction. Shared list command/engine listing paths
cover human and JSON output. Caller search found `listing.answer` dispatching
to this transaction reader; no write or report behavior was reproduced.

Validate tag/link emptiness after applying their existing sigil normalization,
while retaining valid prefixed/unprefixed filters and AND semantics. Do not
weaken unrelated blank-filter checks or change account/search matching.
No dependency or backend API change is needed.

Full-board/history dedupe found no open sigil-only filter item. Completed
w3/333 / w1/m25 fixed literal-empty tag/link poisoning (`dbff2b8a`); its
controls still pass. This is the residual normalized-empty case. Completed
w1/046 validates tag/link write input and does not cover read filters.

Acceptance: lone and combined sigil-only values exit 2 naming the offending
flag, in human/JSON modes, and preserve files; real prefixed/unprefixed filters
still return the same transaction. Only macOS/local ledgers exercised.

Sanitized evidence: `cli/tmp/qa-20261008-cli/list_sigil.py`,

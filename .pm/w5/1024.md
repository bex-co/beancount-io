# Handle dateless cost lots in close diagnostics and import warnings

**Minor · cli · 30–45m · A1 · worker1.** Native-valid offsetting long/short
lots can have `cost.date=None` when quantities were inferred. `add close`
then raises `AttributeError` instead of naming the lots. The shared formatter
also aborts preview/apply of a valid closing statement, blocking its new
refund. Failures preserve all bytes; no source-loss or wrong-money claim.
No product fix implemented.

`ee4b7702516da4535bb3b478e2efe9913b09481b`. Checkout `bea 0.3.1`, frontend
Python 3.13.3, managed Python 3.12.10 / Beancount 3.2.3 / Beanquery 0.2.0,
macOS 26.5.1 arm64. Fresh bounded subprocesses, closed stdin/no TTY, isolated
absolute config/cache, notifier disabled. Inspected local importer and
synthetic books only; no plugins, services or dependency changes.

## Cause and scoped repair

`cli/src/bea_engine/ledger/adding.py:397`, `_stranded_lots`, unconditionally
calls `key[2].isoformat()`. The correctly constructed cost key (:385) can
contain `None`. `_remaining_balance` (:417–421) sees zero net units and asks
this formatter for the surviving lots. `_close` (:456) uses it for the
unforced check; force bypasses the check. `importing.py:1126`,
`_funded_close_advisories`, calls the same helper from the validated-candidate
inspection hook (:924–926); preview and apply fail before committing.

Format an optional date only when present, preserving number, currency and
escaped label. Keep per-lot inventory identity, direct-close refusal, force,
native-import warning policy and atomicity. No upstream fork, dependency or
API change is needed.

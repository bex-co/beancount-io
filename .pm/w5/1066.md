were inferred exports through `query PRINT` at exit 0, but the new copy

check, while changing the native lot identities. Source files stay unchanged;

## Cause and scoped repair

[`query._render_beancount`](../../cli/src/bea_engine/query.py#L1818)
passes booked entries directly to `DirectivePrinter(DisplayContext())`
(:1827,1873). Their units are already complete. The shared
[`DirectivePrinter`](../../cli/src/bea_engine/ledger/writer.py#L82)
prints that explicit quantity; it cannot express an absent booked cost date
by just omitting the date in `{5 USD}`.

In the installed Beancount 3.2.3 `parser/booking_full.py:622–624`, a missing
units number bypasses the augmentation default-date step at :702–704.
Interpolation and `convert_costspec_to_cost` (:747–773) retain the absent
date. Reloading an explicit quantity instead assigns the transaction date.
This native behavior is independently observed; changing upstream booking
semantics is not the proposed fix.

The existing JSON boundary already handles it: reader
[`_number_left_open`](../../cli/src/bea_engine/ledger/reader.py#L532)
recognizes the source's omitted quantity, and `_to_transaction` (:592–608)
marks those units `inferred: true`. Bulk replay preserves that inference.
The query renderer does not use it. Preserve a source-backed inferred
quantity when rendering an undated lot so native reload retains its cost
identity; integrate with the existing source-reading/printer helpers rather
than adding another parser or changing booking rules. Keep explicitly dated
and ordinary explicit acquisitions explicit, keep reported JSON quantities,
and do not invent a date, switch to FIFO, drop the sale, or weaken validation.
If a derived entry cannot be rendered faithfully, refuse clearly before
publishing an invalid/changed copy and preserve any prior output. No new
flag, dependency, upstream fork, API or cross-package work.

Caller search: query dispatch at :1583 selects `_render_beancount` for
Beancount directive output, including the default `PRINT` and stored query.
`_csv_cell` (:1946–1965) and writer `format_entry` / `format_transaction`
(:498,582) also call the shared printer; preserve their existing behavior
when choosing where to restore inference. CSV directive cells, interactive
query, explicit native `--source`, plugin-derived dateless lots, filtered
queries that deliberately omit required entries, and other operating systems
are unverified here. `SELECT entry` by itself is a postings-table selection,
so its repeated/missing prerequisite entries were excluded from this finding.
The failure above uses the full unfiltered `PRINT` result.

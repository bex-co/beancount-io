# Report conversion menus ignore `fava-option "conversion-currencies"`: a USD ledger that lists EUR and BTC still offers only "Converted to USD", though Ledger Settings shows the option and the API converts to both

**Severity:** minor (multi-currency reporting). **Owner:** `dashboard`, plus a small `backend-cluster/ledger` change for listed currencies the ledger never names. **Estimate:** 30–45 minutes including tests. **A2:** a newcomer moving from Fava sets `conversion-currencies` to see their books in EUR or BTC, as Fava's help tells them to. Ledger Settings → Fava Options shows the option as set, but no report offers those currencies, and nothing explains why. **Found by:** `/qa-find-bugs-dashboard` (`dashboard-qa` routine) on 2026-11-27 against `https://beancount.io`, production entry chunk `main-BBmi61Hs.js`. QA-owned headless Chromium 158, isolated context, 1440×1000, English, signed in as the QA owner of a disposable `qa-` ledger. The probe line was added, then removed: `main.bean` is byte-for-byte restored (blob `64a178bd` again) and the ledger has no errors. Local HEAD `45cf006cd`.

## Repro

1. Use a ledger with `option "operating_currency" "USD"` that holds EUR, BTC and ETH positions and has `EUR`/`BTC` prices, then add:

   ```beancount
   2026-01-01 custom "fava-option" "conversion-currencies" "USD EUR BTC"
   ```

   GraphQL `getLedger { options { operatingCurrency } favaOptions { conversionCurrencies } }` returns `["USD"]` and `["USD", "EUR", "BTC"]`.
2. Open Ledger Settings → **Fava Options**. The table lists `conversion_currencies ["USD","EUR","BTC"]`.
3. Open the conversion selector ("Select conversion") on Balance Sheet, Income Statement, Trial Balance, Cash Flow and an account page. Each one offers exactly `At Cost | At Market Value | Units | Converted to USD`. EUR and BTC are missing.
4. API control on the same ledger: `getLedgerBalanceSheet(conversion: "EUR")` returns Assets `balanceChildren` `EUR: "56925.636…"` beside the units it cannot price (`VTI`, `ETH`, `VEUR`, `QAMIRROR`). `conversion: "BTC"` returns `BTC: "3.0223…"`. `conversion: "CHF"` (in no directive) is refused with `BAD_USER_INPUT` "Unsupported conversion "CHF": … or a currency in this ledger (BTC, ETH, EUR, …)". So the backend already converts to every listed currency the ledger names, and only the page's menu stops at the operating currencies.

**Expected:** Fava 1.30's help for the option says: "When set, the currency conversion select dropdown in all charts will show the list of currencies specified in this option." With the option above, every report selector offers At Cost, At Market Value, Units, then Converted to USD, EUR and BTC, in that order.

## Cause

- `dashboard/src/common/providers/ledger-provider/ledger-provider.tsx:17-21` derives the offered list from `options.operatingCurrency` alone.
- The six report selectors pass that list as `currencies`: `balance-sheet/balance-sheet-content.tsx:257`, `income-statement/income-statement-content.tsx:282`, `trial-balance/trial-balance-content.tsx:272`, `cash-flow/index.tsx:242`, `cash-flow/cash-flow-content.tsx:291`, `account/index.tsx:564` (all under `features/reports/`). `common/components/conversion-select.tsx:33` renders one "Converted to" item per entry.
- `features/reports/components/use-report-conversion.ts:28-40` (`resolveReportConversion`) accepts a stored currency only when it is an operating currency, so a remembered EUR falls back to At Cost.
- `favaOptions.conversionCurrencies` is requested by `graphql/query/ledger.graphql:160` and filled by backend-v2 (`features/ledger/workflow/ledger-workflow.ts:2599`). Apart from the Settings table, nothing in the dashboard reads it.

## Fix

- **Dashboard.** Have the ledger provider expose the offered conversion currencies: `favaOptions.conversionCurrencies` when it is non-empty, in declared order with duplicates removed, otherwise the operating currencies as today. Pass that list to the six selectors and to `resolveReportConversion`. `primaryCurrency` stays `operatingCurrency[0]` (the default conversion and the statement's own currency column).
- **Ledger, in its own commit.** `backend-cluster/ledger/src/foundation/rustledger/cost-valuation.ts:59-67` (`resolveConversion`) accepts operating currencies and codes that directives name. A listed currency that neither covers would be refused, and a refused conversion replaces the report with an error view that also hides the selector (the trap w5/1173 recorded for operating currencies). Accept every `conversion-currencies` entry the same way an operating currency is accepted. Positions that cannot be priced in it keep their own units. This part is not verified live: the probe listed only currencies the ledger names.

## Definition of done

- On a USD ledger with `conversion-currencies "USD EUR BTC"`, Balance Sheet, Income Statement, Trial Balance, Cash Flow and the account page each offer Converted to USD, EUR and BTC in that order. Choosing EUR re-reads the report with `conversion=EUR`, and the choice survives a reload and a move to another report page.
- Without the option, every selector offers what it does today.
- A listed currency that no directive names gives a report with unconverted units, not "Error loading data".
- Tests cover the provider's list (option set, option empty), `resolveReportConversion` with a listed non-operating currency, and the ledger's `resolveConversion` with a listed currency no directive names. Each fails on the current code. Dashboard and ledger gates pass.

## Adjacent, not in scope

- Without the option, Fava lists the operating currencies "and those currencies that match ISO 4217 currency codes", so on this ledger it would offer EUR by default. The dashboard offers only the operating currencies. Decide that separately.
- Ledger Settings → Fava Options also lists `default_page`, `sidebar_show_queries` and `uptodate_indicator_grey_lookback_days`, which nothing in the dashboard reads (no saved-query sidebar, no up-to-date indicator, the ledger root always opens Overview). The table presents them as options in force.

## Dedupe

Searched `.pm/**`, including `done/` and `blocked/`, for `conversion-currencies`, `conversion_currencies`, `conversionCurrencies`, `fava-option` and `Converted to`. w5/done/1173 made the menus offer every operating currency (`121d12d72`, ledger `e9f2ad05b`). Its own dedupe searched `conversion-currencies` and found nothing, and its fix never reads the option. w4/done/003 only says the selector is "seeded from" the option, which the code never did. `ledger-provider.tsx` and `use-report-conversion.ts` at HEAD match what production does, so this is not deployment lag.

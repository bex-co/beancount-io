# Canonicalize signed zero in imported non-transaction directive keys

**Minor · cli · 35–50m · A1 · worker1.** Importing a native Balance with
`Decimal('-0.00')` succeeds, but its unchanged repeat conflicts with the
native-loaded `0.00`. An explicit negative-zero tolerance does the same.
Either false conflict blocks a new refund in an overlapping statement.
Negative-zero numeric metadata on a Note instead appends the same note on
every run. Positive-zero controls deduplicate. Cash is never miscalculated;
the failures are blocked imports and duplicate annotations. No product fix
implemented.

Environment: 2026-10-24, clean main
`a77373d11140c8166eac696fa64f71666b152002`; CLI byte-identical to frozen
`ee4b7702516da4535bb3b478e2efe9913b09481b`. Checkout `bea 0.3.1`, frontend
Python 3.13.3, managed Python 3.12.10 / Beancount 3.2.3 / Beanquery 0.2.0,
macOS 26.5.1 arm64. Fresh bounded subprocesses, closed stdin/no TTY,
isolated absolute config/cache, notifier disabled. Synthetic statement
files and an inspected local native importer; no plugins or services.

## Cause and scoped repair

`cli/src/bea_engine/importing.py:1846–1874`, `_directive_key`, sorts metadata
and allowed currencies but returns `_directive_text`, whose `format_entry`
retains the incoming Decimal zero's sign. `_authored_directive_keys`
(:2276–2295) reparses ledger bytes with native Beancount, so its key contains
the unsigned zero. The generic membership test (:785) therefore misses the
same directive. Balance falls into the authored same-day conflict guard
(:788–805); Note remains `new` and is appended again.

Five actual helper/native-parser proofs reproduce that mechanism: incoming
negative-zero Balance amount, tolerance and Note metadata each compare equal
numerically to their own parsed export, with identical Decimal exponents,
but their directive keys differ. Positive-zero Balance/Note keys survive the
round trip. A separate key comparison keeps 0.0 and 0.00 distinct, as needed
for assertion precision. Price uses its own quote index and already skips
negative zero correctly; it does not enter this generic membership path.

Canonicalize the comparison key for numeric signed zero wherever this
non-transaction identity uses it, preserving types and precision. Keep the
rendered source text and authored bytes stable, and retain the strict
same-day assertion guard for actual changes. Do not collapse string IDs or
text metadata, weaken native-ID checks, or discard tolerance/precision.
The exact failing runtime scope is native Balance amounts/tolerances and
Note numeric metadata. Other non-transaction kinds share the helper but
were not separately exercised for signed zero. CSV produces transactions
rather than these Balance/Note objects. No dependency or API change needed.

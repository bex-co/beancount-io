# Count only statement source accounts in OFX imports

**Major · cli · 35–50m · A1 · worker1.** A normal single-account OFX
statement stops importing when a transfer includes its recipient account.
With explicit `--account`, preview and apply exit 2 claiming two source
accounts; a flag-free run loses the already remembered source mapping and
asks for `--account`, which leads back to the same refusal. The identical
transfer with only the optional recipient details omitted imports once.
Bank and credit-card sources, bank and card destinations, SGML and XML
reproduce. Rejected calls preserve the ledger, inputs and remembered settings;
no wrong-booking/data-loss claim or product fix.

Environment: 2026-10-27, immutable primary source
`9928d4eface5353344c84fcbd2cbbf2f1d624075` (1731 tracked CLI files),
latest fresh confirmation `61fa32c6c8b7b8151fad266e5276e2476f8446c8`
(1732 files). Frontend `import_.py` and engine `ofx_importer.py` are
byte-identical across both. Checkout bea 0.3.1, frontend Python 3.13.3,
existing managed Python 3.12.10 / Beancount 3.2.3 / Beanquery 0.2.0 /
Beangulp 0.2.0, macOS 26.5.1 arm64. Offline bounded new subprocesses,
closed stdin/no TTY, explicit local files, isolated child config/cache,
notifier off and HOME unchanged. Synthetic banks/accounts/ledgers only;
no service, plugin, dependency or installation change.

## Standalone reproduction

Put checkout bea on PATH, save as `recipe.py`, and use a fresh directory:

```sh
python3 recipe.py /absolute/unused/book bank-bank sgml standard /absolute/managed-engine/bin/python
```

Use `xml renamed` for XML OFX 2.2, EUR and renamed roots. Modes `bank-card`,
`card-bank`, `card-card`, `bank-other-bank` and `bank-same-number` reproduce;
the four `plain-*` modes are healthy controls. Each recipe executes 17 CLI
calls, 3 uncached native checks, and the installed upstream OFX parser on
the same input. It records arguments/cwd/safe environment, stdin/TTY,
streams/exits/timings, file hashes and the run's own remembered mappings.
A plain statement first binds the real source; the candidate and a reference
then start with identical seeded ledger bytes. The reference file differs
only by omitting recipient details. No ignored evidence file is required.

This is valid transaction detail. The official
[OFX Banking 2.3 specification, section 11.4.4.1, printed p216](https://financialdataexchange.org/wp-content/uploads/2025/12/OFX-Banking-Specification-v2.3.pdf#page=232)
allows `STMTTRN` to include the destination bank or credit-card account when
available. It does not create another downloaded statement. In every public
case the installed Beangulp `find_statement_transactions` independently
finds **one** statement for `SOURCE-001`, **one** −10 row and the same
narration/currency with or without the recipient aggregate. The optional
metadata is not a reason to force a Python importer or require users to
strip valid information from their bank downloads.

## Cause and bounded repair

The engine's [`_ACCOUNT_TAGS`](../../cli/src/bea_engine/ofx_importer.py#L41)
and frontend's [`_OFX_ACCOUNT_TAGS`](../../cli/src/cli/commands/import_.py#L304)
recognize both `*ACCTFROM` and `*ACCTTO` aggregate boundaries, but only reset
`bankid` there. Engine [`_source_accounts`](../../cli/src/bea_engine/ofx_importer.py#L44)
(:53–68) and frontend [`_ofx_identities`](../../cli/src/cli/commands/import_.py#L325)
(:339–352) append **every** nonempty ACCTID, with no active source/destination
scope. A recipient is therefore another source identity.

The engine's one caller, `OfxImporter.extract` (:200–211), refuses when that
list has more than one identity, before upstream transaction extraction.
Frontend `_ofx_identities` has two production uses: `_recall_ofx` (:823–826)
returns no mapping unless there is exactly one identity, and import setup
(:1362–1363) derives the identity later handed to `_remember_ofx` (:934).
That explains both the remembered-settings failure and why correcting just
the engine would leave source-memory behavior incomplete. The two scans
intentionally remain on their own interpreter sides under ADR014; the
frontend must not start importing Beancount/Beangulp.

Repair the existing scans' aggregate scope so only statement source
`BANKACCTFROM` / `CCACCTFROM` contributes bank/account identity. Skip
transaction `BANKACCTTO` / `CCACCTTO` details while retaining the actual
statement source and its bank. Apply the same scope rule on both sides,
retain existing decoding/case handling, and keep true multi-source files
refused. Reuse the current scanner/extraction structure; no general OFX
parser, shared cross-interpreter import or upstream fork is needed.

Keep category/counteraccount selection and transfer review unchanged:
recipient metadata is not a second imported row and must not overwrite
`--account`, `--default-account` or an unrelated remembered binding. A
first recipient-bearing statement with explicit flags should remember only
its source identity; later files should recall it, and an exact repeat
should write zero. Preserve bank+account keys, legacy-record remapping,
card sources without BANKID, multiple currencies for one source, and
existing correction/currency refusals. No backend/API or dependency change.
Regression coverage should drive real preview/apply/recall/repeat journeys,
assert exact per-account money and stored identities, and run CLI checks
when implementing.

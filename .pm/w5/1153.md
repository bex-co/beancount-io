# Balance Sheet, Trial Balance and Statistics link Equity:Earnings:Current and the other generated equity rows to "No account named … in this ledger"

**Severity:** minor (dead-end navigation from the primary statements; no wrong amount). **Owner:** dashboard. **Estimate:** 30–45 minutes. **A2:** a newcomer who clicks the net-income line of their first Balance Sheet should not land on a 404 that says the account does not exist. **Found by:** `/qa-find-bugs-dashboard` on 2026-11-18 against `https://beancount.io` (entry chunk `main-LGv2TZLj.js`), QA-owned headless Chromium 153 at 1440×1000, English/light. Signed-in QA owner on its designated disposable synthetic ledger, plus the anonymous public control `open_ledger/example`. Read-only. Local HEAD `50f9bca2f`.

## Repro

1. Open `/ledger/open_ledger/example/balance-sheet` and wait for the Equity List.
2. Activate the **Current** link under **Earnings** (`/account/Equity%3AEarnings%3ACurrent`).
3. Result: HTTP 404, document title "Page Not Found — …", body **"No account named Equity:Earnings:Current in this ledger."** with an **Accounts** link.

Seven Equity rows on that Balance Sheet are links, and five of them 404: `Equity:Conversions`, `Equity:Conversions:Current`, `Equity:Earnings`, `Equity:Earnings:Current`, `Equity:Unrealized`. Only `Equity` and `Equity:Opening-Balances` open an account page. A scan of every `/account/` link on each page, checked against the ledger's own account list (`getLedgerAccounts`), found the same dead links here:

| Page | Dead account links |
| --- | --- |
| example Balance Sheet, no filter | Conversions, Conversions:Current, Earnings, Earnings:Current, Unrealized |
| example Balance Sheet `?time=2016` | the five above plus Earnings:Previous |
| example Statistics `?time=2016`, Postings per Account | Conversions:Current, Earnings:Previous |
| synthetic ledger Balance Sheet, no filter and `?time=2026-07` | Earnings, Earnings:Current (and Earnings:Previous with the time filter) |
| synthetic ledger Trial Balance `?time=2026-07` | Earnings, Earnings:Previous |
| synthetic ledger Statistics `?time=2026-07` | Earnings:Previous |

Controls: the parent rows `Assets:Bank`, `Liabilities:CreditCard`, `Expenses:Food` and the roots have no Open directive either, and they open their aggregate report (HTTP 200). Income Statement, Cash Flow and Overview have no dead account links. Each case was repeated from a fresh load.

## Cause

These rows are accounts Beancount and Fava generate for the report: current and previous earnings (`account_current_earnings`, `account_previous_earnings`), conversions, and Fava's unrealized-gains account. They are in the statement trees the API returns, but no ledger directive opens them.

- `dashboard/src/features/reports/balance-sheet/hierarchy-list.tsx:262-273` links every tree row's label to `/account/$accountName`. Balance Sheet, Trial Balance, Income Statement and Cash Flow all render this shared list. `features/ledger-data/statistics/postings-per-account.tsx:124` does the same for each Postings per Account row.
- `dashboard/src/features/reports/account/loader.ts:18-27` (w3/471, `6f0518eb2`) answers 404 unless the name is a ledger account or an ancestor of one. That rule kept the report hierarchy's parent links working, but it did not cover the generated equity accounts. So the links and the not-found rule disagree.

## Fix

A statement or Statistics row whose account is neither a ledger account nor an ancestor of one renders its label as plain text, not a link. The row header, amounts, expander and "+N more" disclosure stay the same. Decide this with one shared predicate that both the account loader and the two link sites use, so the two rules cannot drift again. The account list comes from the cached unfiltered `GetLedgerAccounts` query that the sidebar and loader already share. Keep the loader's 404 for unknown names. Update the "Every tree row is a real ledger account whose label links to the account page" sentence in `features/reports/AGENTS.md`: generated equity rows are not links. Dashboard only; no API change.

## Definition of done

- On `open_ledger/example/balance-sheet` (with and without `?time=2016`) and the synthetic ledger's Balance Sheet, Trial Balance and Statistics with a time filter, no `/account/` link points at an account the ledger does not open or contain. The generated rows still show their label and amounts.
- `Equity:Opening-Balances`, parent rows such as `Assets:Bank`, and every opened account still link to their account report, and a typed URL for an unknown account still answers 404.
- A rendered test of the shared hierarchy list shows `Equity:Earnings:Current` as an unlinked row header next to a linked `Equity:Opening-Balances`. A Statistics test does the same for `Equity:Earnings:Previous`. Both fail against the current code. Dashboard gates pass.

## Dedupe

Searched `.pm/**` for `Earnings:Current`, `Earnings:Previous`, `Conversions:Current`, `Equity:Unrealized`, "No account named", and account 404. w3/done/471 introduced the not-found rule and explicitly kept aggregate ancestors linkable, but not generated accounts. That makes this a regression of w3/471 against the statement links it meant to keep working. w4/done/110 explains generated rows inside Entry Context, a different surface. w21/done/710 and w6/done/m5 changed which equity rows the API returns, not their links. Not deployment lag: HEAD has the same loader and link code.

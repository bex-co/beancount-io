## Cause, scope and repair

`cli/src/cli/commands/treeify.py::_clusters:53–61` appends every zero-width
mark to the preceding character. For a final component beginning U+0301,
that preceding character is the account separator `:`. `_cell_aligned:82–93`
then replaces the entire colon-plus-mark cluster by one private-use character.
A direct trace changes `Assets:Bank:\u0301Cafe` from two literal separators
to one in the aligned native input. `_decide_pattern` and upstream treeify
therefore see one combined component. `_restore_cells:99–111` restores the
colon text only after upstream has built the wrong hierarchy; it cannot
restore the missing parent node.

The sole caller is this command's default-pattern path (`treeify:392–416`),
shared by file/stdin/dash/output. Explicit `-r`, `-A` and `-F` bypass that mask;
the explicit Unicode-capable pattern is an exercised working control, while
the presets are only traced. `cli.output._clusters` is a separate truncation
helper, not this producer. Native Beancount validation, BQL and native tree
construction with the explicit pattern are healthy.

Keep actual `:` separators visible to the aligned input's account grammar
and native splitter even when the next component begins with a zero-width
mark. Preserve the marks and display coordinates, then restore exact text.
Do not reject or rename a loader-valid account, remove its marks, revert
query's correct display-width padding, or replace upstream's tree algorithm.
Retain CJK/wide-narration/interior-mark/ASCII and renamed-root behavior. No
backend/API, new dependency or ledger mutation is needed.

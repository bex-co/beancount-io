## Objective

Authorize ledger metadata, reports, journals, accounts, and dashboard-shaped reads through protected application-service methods and one final PDP call.

## Context

- Some reads are anonymous for public ledgers; others currently rely on service-local `authorizeLedger`.

## Steps

1. Make protected public services accept resolved `Identity`; use workflows only for genuine orchestration and keep resolver adapters policy-free.
2. Preserve public-reader, anonymous, credential-scope, ledger-pin, nullable, and authentication-error semantics.
3. Thread already-resolved domain data only when its freshness/lifetime is explicit; do not add a decision memo merely to avoid a repeated source read.

## Files

- ledger data/account/finance/journal services and resolvers
- authorization integration files

## Acceptance criteria

- [ ] Private, collaborator, owner, public, anonymous, and pinned cases retain parity.
- [ ] Every authorization call evaluates current source facts and audits independently; intentional domain/defense reads are documented rather than cached as a decision.
- [ ] Denied reads fetch no ledger contents.
- [ ] Source failure surfaces as service unavailable instead of an empty/public/forbidden result.

## Out of scope

- Ledger mutations and control-plane reads.

# Let Welcome's Sign In and Sign Up buttons fit enlarged text

**Severity:** minor. **Estimate:** 30–45 minutes. **Package:** mobile. **Goal:** A2 — newcomers using enlarged text can read the two actions that enter the app.

**Environment:** 2026-09-21, `main` at `358b17ce`, current checkout JavaScript served by local Metro, native `io.beancount.ios` 1.20260906.47 (47), iPhone 17e / iOS 26.5, English. Selected server `https://beancount.io/`; signed out, no ledger required. Native screen is 390×844 points (1170×2532 pixels); Expo MCP captures are 960×2078, not 3× point coordinates.

## Repro and evidence

1. Launch the native app to Welcome while signed out. At the ordinary iOS `large` content size, both **Sign In** and **Sign Up** are readable. Sign In opens the native browser flow; cancelling returns to Welcome.
2. Set iOS Dynamic Type to `accessibility-extra-extra-extra-large`. The labels expand while both button backgrounds remain 44 points high. Only fragments of the glyphs are visible; neither action is readable.
3. Terminate and relaunch the app at that text size. Dismiss the development warning overlay, whose underlying log concerns a stale local packager probe. The same clipping remains, including after changing the simulator to dark appearance.
4. Restore `content_size large` and light appearance. Both complete labels return immediately.

Expected: both complete enlarged labels fit inside their backgrounds and remain reachable. Actual: the Welcome footer clips both labels. Expo MCP's fresh-launch `automation_find_view` still reports Sign In as an enabled, hittable Button named `Sign In`, frame `{x:20,y:740,width:171,height:44}`. This proves visual unreadability, not a missing accessibility label or a failed hit target. A bounded two-second JavaScript error capture was empty; no network response is needed to reproduce this layout bug.

Verified local evidence, all ignored under `mobile/tmp/qa-20260921/`: `welcome-large-text-0.jpg` (clean initial light failure), `welcome-large-fresh-ax.json` (fresh native bounds), `welcome-large-dark-clean-0.jpg` (fresh process, warning dismissed, dark failure), `welcome-default-control-0.jpg` (restored working control), and `welcome-error-logs.json`. The first fresh screenshot with the warning covering the footer is deliberately excluded as proof.

## Cause and fix

`mobile/src/screens/welcome/index.tsx:53–57` fixes `buttonContainer.height` at 44. The row at line 111 wraps both Buttons, each using `flex: 1`. Its constrained cross-axis height prevents either control from growing with its text.

The shared Button already uses `minHeight: 44`, vertical padding, and a shrinking/wrapping label in `mobile/src/components/button/index.tsx:29–40,48–69`. Changing that component again cannot remove this parent constraint. Let the Welcome action row accommodate its measured/scaled labels, stacking the actions at enlarged sizes if needed. Preserve the normal-size layout, bottom safe area, minimum hit targets, loading indicator and failure-message placement. Do not solve this by disabling text scaling or truncating the action names.

Additional native control: the signed-out bare OAuth callback's **Back to Sign in** Button grows to contain its complete two-line label at the same maximum text size. `mobile/tmp/qa-20260921/oauth-recovery-large-text-control-0.jpg` verifies the shared component can fit its label when its parent permits growth. This is a negative-path callback destination check, not a successful OAuth login.

**Acceptance:** at maximum and ordinary text sizes on iPhone 17e, both full labels are visible in light and dark; Sign In and Sign Up remain independently reachable; native browser cancellation restores enabled controls; a visible sign-in failure does not overlap either action. Add a focused layout regression check that includes the actual Welcome parent, so reverting its sizing recreates the failure. Verify a longer translated label during implementation.

**Resolved 2026-09-23** — The Welcome action row no longer has a fixed 44pt height. Each Button keeps its own 44pt minimum and grows with its label. At accessibility text sizes (`prefersStackedLayout`, font scale ≥ 1.3) the two actions stack full width, so labels are never split across half-width buttons. Ordinary sizes keep the side-by-side row. The failure message stays below the row, and both actions still disable while a flow is pending. `src/screens/welcome/__tests__/welcome-actions-layout.test.ts` executes the real `WelcomeScreen` at scales 1–3.12; reverting the fix fails 6 of its 9 cases. The longest translated labels (`Регистрация`, `Iniciar sessió`) fit the widths they get at each size. Mobile format, lint, typecheck and 1876 unit tests pass. Not re-verified on the iPhone 17e simulator in this session. Shipped in `mobile`.

# In German and other comma-decimal languages, the same balance is written two ways across the dashboard

**Minor · dashboard · 50–70 minutes.** A2: a reader using the German UI sees Savings as **10.500,00 USD** on Overview and Balance Sheet, and as **10500.00 USD** on Accounts, Statistics and the account page. With `.` as the German thousands separator, the second form reads as a different number. The same split exists in English (`10,500.00` vs `10500.00`) whenever `render_commas` is on.

Production https://beancount.io, 2026-11-10, isolated headless Chromium 156 at 1440×1000, signed in. Read-only on the designated synthetic ledger, whose options include `render_commas: true`. Local main `92e0b83a5`.

## Reproduce

Open each route with `?lang=de` and read the `Assets:Bank:Savings` balance (10,500 USD):

| Surface | Shows |
| --- | --- |
| Overview (Financial position) | `10.500,00 USD` ✓ |
| Balance Sheet | `10.500,00` ✓ |
| Accounts (`/accounts`) Balance column | `10500.00 USD` |
| Statistics → Account Last Entries | `10500.00 USD` |
| Account page (`/account/Assets:Bank:Savings`) → Period data | `10500.00 USD` |
| Journal → Postings (`?time=2026-03`) | `-500.00 USD` / `500.00 USD` |

Holdings and Query results also print raw query values (`10500.00 USD`). They mirror Fava's query output and are out of scope here.

## Root cause

The listed surfaces print the ledger's decimal string as is:

- `features/ledger-data/accounts/index.tsx:139` renders `{String(amount)} {currency}`.
- `features/ledger-data/statistics/account-last-entries.tsx` uses `formatDecimalCell`.
- `features/journal/components/journal-postings.tsx:~48` and `entry-context-dialog.tsx:~131` render `${posting.units.number} ${posting.units.currency}`.
- The account period table shows the same raw string (observed in the UI; its renderer was not traced).

Earlier precision work (w4/120, w4/m55) moved these surfaces to exact strings to stop `Number()` from losing digits, and left locale grouping for later. That loss is no longer a reason: `common/lib/format/format-number.ts` `formatNumber` now formats decimal **strings** exactly (ECMA-402 2023 `Intl.NumberFormat.format(string)`) with locale, `render_commas` grouping and currency minor units.

## Fix

Route these surfaces through `useFormatNumber` / `formatNumber(value, renderCommas, locale, currency, fractionDigitsOf(value))`, passing the decimal string rather than a `Number`. Keep `<Amount>`'s bidi isolation, and keep the currency label separate. Add one test per surface that renders `10500.00 USD` under `de` with `render_commas: true` and expects `10.500,00`. Add a 2^53+1 control to prove nothing is rounded.

## Blast radius

Accounts directory, Statistics Account Last Entries, account period tables (balance and changes views), Journal posting rows and Entry Context postings. Reports, Overview and Budget already format this way. Holdings and BQL stay raw by design.

## Dedupe

Searched `.pm/**` for `render_commas`, thousands/grouping separators, and German/locale together with these surfaces. w4/120 (Statistics exactness), w4/m45 and w4/m55 (Budget precision), and w4/1005 (Persian amount order) each fixed precision or direction, not locale formatting. No existing item.

---

**Resolved 2026-11-10** — shipped in this commit (`dashboard`). A new
`<LedgerAmount>` (`common/components/ledger-amount.tsx`) renders the Accounts
directory balances, Statistics → Account Last Entries, the account page's
Period data (and the statements' period tables, which share
`ChartPeriodTable`), Journal posting rows (units, cost and price) and Entry
Context postings: `10500.00 USD` now reads `10.500,00 USD` in German and
`10,500.00 USD` in English, matching Overview and Balance Sheet, inside the
existing `<Amount>` bidi isolate.

Deviation from the suggested `useFormatNumber`: that path rounds an ISO
currency to its minor units, which would show a `0.0040 USD` posting as
`0.00 USD` and undo w4/120's exact `1234567.891234 USD` in Statistics. These
surfaces show what the ledger holds, so a new `formatSourceDecimal` writes
the reader's separators and `render_commas` grouping with exactly the
fraction digits the source carried; with `render_commas` off it returns the
ledger's own decimal, as `formatNumber` does. In Persian it writes Persian
digits, as Overview does. A leading `+` in a source balance is normalized
away. `dashboard/AGENTS.md` names the component next to the existing
amount-formatting rule.

Validation: `ledger-amount.test.tsx` (German `10.500,00 USD`, English
grouping, `render_commas` off, `0,0040 USD`, `1,234,567.891234 USD`,
`4.00995 ETH`, 2^53+1 in two locales, a double, a non-decimal) and
`formatSourceDecimal` cases; tests on the five surfaces were updated to the
localized output (Persian cases derive it from the formatter, their subject
being isolation), and 22 of them fail against the previous raw rendering.
`yarn format:check`, `yarn lint`, `yarn test` (784 files, 7852 passed,
1 existing skip) and `yarn build` pass; agent-guidance check and secret scan
clean. Holdings and Query stay raw, as the note scoped. Not verified against
production before the next dashboard deploy.

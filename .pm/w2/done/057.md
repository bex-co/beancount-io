Severity: **minor**. Estimate: **40–55 minutes**, mobile only. A2 — a newcomer should see the settled explanation for a search with no matches while still entering the query.

2026-10-09; source HEAD `4e8612a0`, native development client `io.beancount.ios` 1.20260906.47/47, current Metro JS 1.20261002.50. Sole booted **iPhone 17e**, iOS26.5, 390×844 logical; English, System/light, default large text. ## Reproduction and controls

2. Focus Search and type literal ASCII `E.B.'s "Beer"` through native keyboard events. Wait for the debounced query to settle with the software keyboard still open. XCTest verifies the native field equals the complete literal, including codepoints39/34 for the apostrophe/double quotes.

Its native message rectangle is x32,y518.33,w326,h48 and hittable=false. The native Keyboard element starts at y553; its bounds exclude the suggestion surface, which the screenshot shows starting around y510. Coverage is established visually, not from those incomplete keyboard bounds alone.
4. Tap the keyboard **Search** key. The unchanged query's full explanation appears. Refocus and delete/retype the final straight double quote so the keyboard opens while the empty state is already mounted: the final literal is unchanged, but the message now moves to y392.33,h48 and is hittable=true, fully above the keyboard. Successful native runs08/09 measure both states in the same process.

**Expected:** the first settled no-match state uses the current visible keyboard state. **Actual:** it needs another keyboard-opening event to learn the height. A fresh dark-mode process, PID52371, reproduces the same first-search geometry/coverage and dismissal recovery. The double-quote-only query `"Beer"` independently reproduces the covered explanation. Clearing restores the populated journal.

## Cause and repair

`mobile/src/screens/transactions-screen/transactions-screen.tsx:111` debounces the query300ms and conditionally mounts `NoResultsState` at321–322 only after results become empty. `no-results-state.tsx:46` starts its own `useKeyboardHeight()` observer then. The shared hook at `components/keyboard-accessory-bar/use-keyboard-height.ts:10–25` initializes to0 and subscribes only to future show/hide events: it never reads the keyboard already on screen. The resulting zero overlap skips the margin at `no-results-state.tsx:57`.

Make the keyboard observer account for an already-visible keyboard at mount, while retaining event updates, hide/reset and cleanup; alternatively keep the observer mounted in the owning Transactions screen and pass the current height to its conditional result state. Installed React Native **0.86.0** `Libraries/Components/Keyboard/Keyboard.js:117–122,178–186` retains the current keyboard event and exposes `metrics()`/`isVisible()`; `addListener` does not replay it. No new dependency or global SearchBar behavior is needed.

Add a meaningful lifecycle regression in which the software keyboard is already visible before the no-results observer mounts and no second show event fires. Check hide/reset and subscription cleanup. Native acceptance: populated → type a no-match query → settled explanation readable above the keyboard at default size; editing/clearing restores rows, dismissal/reopening retains the literal, both themes pass. Preserve the existing large-text scroll recovery, filters, tabs, refresh and distinction between zero matches and a genuinely empty ledger; run mobile's normal gates when implementing.

The earlier fix's full scope was revisited: Merchants' observer lives in its always-mounted screen at152 and its default no-match explanation stays above the keyboard in dark and light (y388,h24). Both layouts were also exercised at maximum Dynamic Type. Their long explanations extend behind the keyboard, but actual native list swipes dismiss it and expose the entire text. A height-initialization repair alone is not claimed to fit that oversized text into the smaller region; retain scrolling without clipping or shrinking the user's chosen text size. Merchants was reached through its inspected native deep link, so this control proves its destination/search, not the drawer journey.

Shared-hook callers are Transactions no-results, Merchants, Edit Transaction and the ledger file editor. Only Transactions' delayed-mount failure is confirmed. The latter writable/editor keyboard flows and signed-out examples remain unverified; do not redesign them from this report. The Transactions screen serves both app and example tab aliases; the app route was exercised.

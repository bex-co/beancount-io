# The Make public confirmation says "history" but not that every commit's author name and email, and every earlier version of each file, go public too

**Minor (privacy) · dashboard · 20–30 minutes.** A2: an owner deciding whether to publish a private ledger has to know what readers will be able to see. Most owners change visibility in the dashboard. The API preview now spells out the git history ([w23/241](../w23/done/241.md), `013668f5c`). The dashboard's confirmation still says only "history":

> Make this ledger public?
> Anyone with the link, and search engines, will be able to see this ledger's transactions, balances, files and history.

What a public ledger actually exposes to a signed-out reader:

- **Commit authors.** Anonymous GraphQL `listCommits` returns `author { name email }` on every commit. The real account email is in those commits until the blocked noreply decision ([w21/315](../w21/blocked/315.md)) lands. Until then this warning is the only mitigation.
- **Earlier file versions.** Anonymous `getCommitDetails` and the diff views also open every earlier version of each file, including entries that were later deleted.

Someone who reads "history" as "a list of past saves" doesn't learn that their email address goes public.

Production https://beancount.io, 2026-11-12, English, isolated headless Chromium at 1440×1000, signed in as the QA account (GROWTH). On the disposable ledger's **Settings**, I switched off **Private ledger**: the dialog above opened and I pressed **Cancel**. A request guard aborted any mutation (none was sent), and the ledger is still private. Control: signed out, `listCommits(ledgerId: "open_ledger/example", limit: 2)` returned both commits' author name and email (addresses not recorded here). Local main `16e503236`.

## Root cause

`dashboard/src/features/ledger-data/settings/visibility-section/locales/*.ts` → `page.settings.makePublicDescription` (15 locales), rendered at `visibility-section/index.tsx:243–245`. The wording predates w23/241. The backend now keeps its own fuller wording in `backend-cluster/backend-v2/src/features/ledger/utils/ledger-visibility.ts` (`PUBLIC_LEDGER_EXPOSURE`). The dashboard can't import it (separate package), so its copy has to say the same thing in its own strings.

## Fix

- Reword `page.settings.makePublicDescription` in all 15 locales so it says what the API preview says. Readers would be able to see the ledger's transactions, balances, files and full commit history, including every earlier version of each file and each commit's author name and email.
- Optionally, add the same clause to `page.settings.publicLedgerDescription` ("Your ledger is public. Anyone with the link can view it."), so an owner who already published also learns it.

**Acceptance:** in every locale, the confirmation names earlier file versions and commit authors' names and emails. A render test pins the English text, and the locale-key parity check still passes.

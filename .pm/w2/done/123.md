# New Entry and Add Budget throw away a typed draft on Escape, Close or one click outside

**Minor · dashboard · 45–60 minutes.** A2: a multi-posting transaction takes a minute to type, and one stray click on the dimmed page behind the dialog erases it. Entry Context ([w3/565](../w3/done/565.md)) and the file editor ([w3/m29](../w3/done/m29/README.md)) already ask before discarding typed text, and mobile asks on all three of the matching forms. The New Entry and Add Budget dialogs do not.

Production https://beancount.io, 2026-11-10, English, isolated headless Chromium 156 at 1440×1000, signed in as the owner of the designated synthetic ledger. Nothing was submitted; the ledger stayed at blob `f1a0b83c`. Local main `c256bbc68`.

## Reproduce

1. Journal → **New Entry** → Transaction. Type a payee `qa-outside`, narration `long draft`, and `12.34` in the first posting's amount.
2. Click once on the dimmed page beside the dialog.

**Actual:** the dialog closes at once. No confirmation appears, and reopening New Entry shows an empty form. The same happens:

- in New Entry → Transaction after typing a narration and an account, on **Escape**: the first press is consumed inside the form, and the second closes the dialog;
- in New Entry → Note after typing the note, on **Close** (×);
- in Budget → **Add Budget** after typing an amount, on **Escape**.

Each case was repeated from a freshly loaded page.

**Expected:** if any field differs from the form's opening values, every way of dismissing the dialog asks first: "Discard this entry? What you typed hasn't been saved." with **Keep editing** and **Discard**. Keep editing returns focus to the field that had it. An untouched dialog still closes instantly.

**Controls:**

- Entry Context with an edited source shows **Discard your edit?** for Close, Escape, an outside click and Open source (w3/565).
- The file editor shows **Unsaved Changes** with Stay / Leave Without Saving (w3/m29).
- Mobile's New Transaction, Add Budget and Open Account screens use `useUnsavedChangesGuard` (`mobile/src/common/hooks/use-unsaved-changes-guard.ts`) and ask before leaving.

## Root cause

`dashboard/src/features/journal/components/new-directive-dialog/index.tsx:114` passes `onOpenChange` straight to the Radix `Dialog`, and its comment at `:135–138` records the gap: "Closing the dialog still discards them all." `ledger-data/budget/add-budget-dialog.tsx:208–212` does the same. Neither form reports whether it is dirty, so nothing can intercept the dismissal. [w4/256](../w4/done/256.md) kept drafts across tab switches and deliberately left dialog dismissal out of scope. [w4/977](../w4/done/977.md) holds dismissal only while a write is pending.

## Fix

- Have each of the four New Entry forms (Transaction, Balance, Note, Account) and Add Budget report `formState.isDirty` (react-hook-form) to its dialog.
- In the dialog, route Close, Escape (`onEscapeKeyDown`) and outside interaction (`onInteractOutside`) through one gate. Entry Context already has this gate (`entry-context-dialog.tsx:193–201`, `requestLeave`); reuse its pattern and its "Keep editing" string.
- When the URL's `action=new-entry` is removed by browser Back, use the same gate, or accept the loss there and say so in the PR.
- Leave the post-success close as it is: a successful write is not a discard.
- Tests: for each exit, a dirty form asks, Keep editing keeps every value, and Discard closes; an untouched form closes immediately. Add new strings to all 15 locales.

## Blast radius

The New Entry dialog (all four tabs, from Journal, Overview and account pages) and Add Budget/Update Budget. Receipt Review and Smart Import are full pages, not dialogs, and were not checked here.

**Resolved 2026-11-11** — shipped in this commit (`dashboard`). A shared
`useDiscardDraftGuard` (`common/components/discard-draft-guard.tsx`) gates a
dialog's dismissal: an untouched dialog leaves at once, and one holding typed
input asks "Discard what you typed? Your input hasn't been saved." with
**Keep editing** and **Discard** (4 new `common.*` keys, 15 locales). Keep
editing returns focus to where it was when leaving was asked for — the field
for Escape and an outside click, the Close button for Close. The four New
Entry forms report react-hook-form's `isDirty` through a new
`useReportDirty`, and the dialog counts a draft on any tab, hidden ones
included (every tab stays mounted, w4/256); Close, Escape and outside clicks
go through the gate. Add Budget (and Update Budget, the same dialog) gates
Close, Escape, outside clicks and its Cancel button; it now reads `isDirty`
during render, which react-hook-form needs to track it. A successful write
still closes directly. `dashboard/AGENTS.md` states the rule beside the
pending-write rule.

Context's history guard. The separate Open Account dialog on the Accounts

## Reproduction and controls

1. Select **open_ledger/example**, use the actual Transactions tab, and start with empty Search and no active filters. Open Filters: **ALL** dates, no statuses and **All accounts**.
2. Tap All accounts and select **Assets:US:BofA:Checking** in the actual account picker. It returns to Filters with that account in the draft. **Do not tap Apply.**
3. Open the valid native App Link `beancount:///ledger/open_ledger/stock-example/files/blob/main/main.bean`. Wait for the read-only file headed **Stock & ETF Cost-Basis Example**. The new ledger/file loads correctly over the retained modal.

5. Transactions shows **No transactions match your search or filters.**, with an empty Search and an active-filter dot. Reopening Filters confirms ALL/no statuses and the same BofA account. Reset/Apply restores Stock's Broker rows: May12,2026 **+$905.05**, April17 **+$3,665.05** and March13 **+$115.00**.

## Cause and bounded repair

`mobile/src/screens/transaction-filters-screen/transaction-filters-screen.tsx:183–188` reads the current ledger from LedgerGuard but seeds an unowned local `draft` only at mount. The account-picker callback at219–225 updates that draft. Apply at234–237 writes `{ledgerId,filters:draft}` using the **current** ledger ID, so a retained Example draft becomes a Stock-owned saved filter. LedgerGuard updates its provider value without a ledger-keyed child (`components/ledger-guard/ledger-guard.tsx:109,175–178`); the route has no draft-origin parameter or remount boundary. The App Link changes `ledgerVar` before replacing its destination (`common/app-links/open-app-link.ts:59–71`), leaving the sheet in history in this verified sequence.

Transactions correctly uses `selectFiltersForLedger` at122–129 and incorporates the result in its journal query at133–142. That resolver cannot reject a draft already stamped with Stock's identity. The scoped store's stated guarantee (`filters/var.ts:14–19`) therefore needs a writer-side draft boundary too; changing backend filtering or clearing every ledgerVar writer would miss the owner.

Bind the sheet's draft lifetime to the resolved ledger and its filter-store context. When either changes, discard the previous draft and seed only that current ledger's scoped filters before Apply can write; a ledger-keyed screen boundary is one small implementation option. Reject any stale-origin Apply/callback rather than retagging the old account. Preserve same-ledger picker/modal navigation, Cancel's no-write behavior, explicit Reset, status/date composition and the existing reversed-custom-range Apply guard. Keep `selectFiltersForLedger` and the ordinary saved-filter switch behavior intact. This is mobile-only: no backend/schema, dependency, permissions or persisted transaction-draft recovery work.

## Objective

Teach the Search Console report to group rows whose pages differ only by `?lang=` (or other stripped params) under their canonical page, so the opportunities table ranks real pages — summed clicks/impressions, impression-weighted position, and a variant count — instead of listing each crawl variant separately.

## Context

- `dashboard/scripts/search-console-report-core.ts` classifies and ranks dashboard-owned rows; the 2026-08-21 report listed `?lang=uk` and `?lang=ca` variants of the same `Expenses:Financial:Fees` account page as separate low-CTR rows.
- The canonicalization rule must match t001's policy (preserve valid `lang`? No — for reporting, variants of the same page across languages should aggregate to the clean path so the page's true footprint is visible; show the variant count so language spread is still legible).

## Steps

1. Add a page-canonicalization function in the core module (strip query params from the GSC `page` URL for grouping; keep the original URLs available for the inspection sampler).
2. Aggregate rows by (query, canonical page): sum clicks and impressions, recompute CTR, impression-weight position, count distinct variant URLs.
3. Render the variant count in the opportunities table when > 1.

## Files

- `dashboard/scripts/search-console-report-core.ts`
- `dashboard/scripts/__tests__/search-console-report.test.ts`

## Acceptance criteria

- [ ] Two rows for the same query differing only by `?lang=` collapse into one row with summed clicks/impressions and an impression-weighted position.
- [ ] The aggregated row shows how many variants it covers.
- [ ] Existing classification tests still pass; new tests cover the aggregation math.

## Out of scope

- Changing thresholds or the near-page-one / low-ctr classification.

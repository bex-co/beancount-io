## Objective

Add a `getSelfCanonicalUrl(pathname, search)` helper to the canonical SEO policy module that builds a self-referencing canonical URL: production origin + pathname, preserving only a `lang` query param whose value is in `SUPPORTED_LANGUAGES`, stripping every other param (`editMode`, line numbers, journal filters, unknown params). This generalizes the m9 commit-detail pattern to any page.

## Context

- `dashboard/src/common/lib/seo/indexability.ts` already holds `PRODUCTION_ORIGIN`, `getLedgerFileCanonicalUrl`, and `getLedgerCommitCanonicalUrl` — the helper belongs beside them.
- `SUPPORTED_LANGUAGES` is exported from `dashboard/src/i18n`.
- Design decision (from `/pm-brainstorm` 2026-08-21): each `?lang=xx` variant self-canonicalizes so the hreflang alternates emitted by `hreflang-links.tsx` stay valid; `?lang=<unsupported>` must canonicalize to the clean path so the param cannot mint infinite indexable URLs.

## Steps

1. Implement `getSelfCanonicalUrl({ pathname, search })` (or `(pathname, searchParams)`) in `indexability.ts` using `PRODUCTION_ORIGIN` and the existing path-encoding conventions.
2. Preserve `lang` iff its value is in `SUPPORTED_LANGUAGES`; drop all other query params and any hash.
3. Document the policy in the module's header comment alongside the m8 indexability policy.

## Acceptance criteria

- [ ] `getSelfCanonicalUrl` returns `https://beancount.io<pathname>` for a request with no params.
- [ ] `?lang=uk` is preserved; `?lang=zz` and `?editMode=true&lang=uk` → only valid `lang` survives; non-lang params are always stripped.
- [ ] Unit tests cover the supported-lang, unsupported-lang, mixed-params, and no-params cases.

## Objective

Publish `beancount-io` to PyPI from a tag, with the same tag-namespace discipline the mobile release already uses, so `uv tool install beancount-io` becomes the primary install channel.

## Context

- `.github/workflows/deploy.yml` releases mobile on `mobile-v<version>` tags; the CLI gets `cli-v<version>` (mirrors the sibling bex CLI's `bex-cli/v*` namespace inside a monorepo).
- PyPI trusted publishing (OIDC) needs no long-lived token: `pypa/gh-action-pypi-publish` with `id-token: write`. The PyPI project must be pre-registered with a pending publisher for this repository and workflow file — a one-time manual step outside the repo, to be documented in `cli/README.md`'s maintainer section.
- The sdist must carry a hashed lock export for the Homebrew formula (t002): `uv export --format requirements-txt --no-dev --no-emit-project --hashes > requirements.lock`, generated in CI, not committed.
- Version source of truth is `cli/pyproject.toml`; the workflow refuses a tag whose version does not match.

## Steps

1. Add `.github/workflows/release-cli.yml` triggered by `push: tags: ["cli-v*"]`: validate tag format and ancestry on `main`, compare with `pyproject.toml` version, run `make check-all`, export `requirements.lock`, `uv build`, attach `requirements.lock` into the sdist via the hatch build config, publish with trusted publishing, then `gh release create cli-v<version>` with the wheel, sdist, and `requirements.lock`.
2. Add `make release-check` that runs the version/tag comparison locally.
3. Document the tag procedure and the one-time PyPI pending-publisher setup in `cli/README.md` (maintainers section).

## Files

- `.github/workflows/release-cli.yml` (new)
- `cli/pyproject.toml` (hatch sdist include for `requirements.lock`)
- `cli/Makefile`
- `cli/README.md`

## Acceptance criteria

- [ ] A `cli-vX.Y.Z` tag whose version matches `pyproject.toml` publishes to PyPI and creates a GitHub Release with wheel, sdist, and `requirements.lock`
- [ ] A mismatched tag fails before building
- [ ] `workflow_dispatch` dry run builds and uploads to TestPyPI when `inputs.test` is set

## Objective

Tell people, never scripts, when a newer `bea` exists: a cached, silent-on-failure check against PyPI, shown at most once a day in a terminal.

## Context

- Rules mirror the sibling bex CLI's notifier: TTY only, never when `--json` or `--no-input` is set, never under `CI`, at most once per 24 h, disabled by `BEA_NO_UPDATE_NOTIFIER=1`, 3-second timeout, any failure is silent.
- Source of truth is `https://pypi.org/pypi/beancount-io/json` (`info.version`); compare with `importlib.metadata.version("beancount-io")` using `packaging.version`.
- Cache file lives under the m24 config directory (`~/.config/bea/update-check.json`) with the last check time and last seen version.
- Development installs from a checkout (version ends in `.dev` or package metadata is missing) never check.

## Steps

1. Add `cli/src/cli/update.py` with `latest_version()` (cached) and `notice()`; hook the notice into the root callback's teardown so it prints after the command's own output, on stderr.
2. `bea --version` prints `bea X.Y.Z` and, when newer exists, `newer release available: X.Y.Z+1 — run bea upgrade`.
3. Document the variables in `docs/USAGE.md`.

## Acceptance criteria

- [ ] With a mocked PyPI response the hint appears once, then not again within 24 h
- [ ] No request is made under `--json`, `--no-input`, `CI=true`, `BEA_NO_UPDATE_NOTIFIER=1`, or without a TTY
- [ ] A hanging PyPI endpoint delays the command by at most the timeout and prints nothing

## Out of scope

- Silent self-replacement of the installed package

# In Persian, every dialog's title sits on the physical left, and the close button covers the first line of dialogs that start on the right

**Minor · dashboard · 30–45 minutes.** A2: a Persian reader (the dashboard sets `<html dir="rtl">` for `fa`) should see a dialog laid out like the page behind it. The shared dialog primitives use physical `left`/`right` classes, so on a desktop-width window every dialog is half mirrored. Mobile has the same bug in its own components: [w22/040](../w22/040.md) (text-input modal) and [w22/041](../w22/041.md) (transaction detail and Entry Context headings). This is the dashboard counterpart.

Production https://beancount.io, 2026-11-12, `?lang=fa` (page `dir="rtl"`), isolated headless Chromium at 1440×1000, signed in as the QA account, on the disposable ledger. Nothing was saved: a request guard aborted any mutation (none was sent), every dialog was dismissed with Cancel or Escape, and the ledger is still private. Afterwards I switched the language back with `?lang=en`. Local main `ab76e5ea3`.

## Reproduce

| Dialog | What is wrong | Measured |
| --- | --- | --- |
| Settings → switch off **Private ledger** (`AlertDialog`) | The title "این دفتر عمومی شود؟" and its description are `text-align: left` inside an RTL dialog. The footer buttons are correctly at the logical end (left). | 488 px dialog: the title sits 24 px from the left edge and 310 px from the right |
| Journal → **Open entry** (Entry Context, `Dialog`) | Its own header is `text-start`, so it correctly starts on the right. But the close **×** is pinned to the physical top-right (`right-4`) and sits on top of the first line, "موقعیت: main.bean:83" (Location). | 896 px dialog: the × spans 17–33 px from the right edge, over the first words of that line |

Every other `DialogHeader`/`AlertDialogHeader` (34 files use them) inherits the left alignment at the `sm` breakpoint and above. Below 640 px the header is centred, which reads the same in both directions.

## Root cause

- `dashboard/src/common/components/ui/dialog.tsx:119` (`DialogHeader`) and `alert-dialog.tsx:66` (`AlertDialogHeader`): `text-center sm:text-left`.
- `dialog.tsx:104` (`DialogPrimitive.Close`) and `sheet.tsx:78` (`SheetPrimitive.Close`): `absolute top-4 right-4`.
- New Entry also hard-codes it: `features/journal/components/new-directive-dialog/index.tsx:151,168` (`DialogTitle`/`DialogDescription` `text-left`).

The rest of the dashboard already handles RTL: the calendar, the sidebar row, amounts and charts each adapt. These primitives date from the original import (`af5339de0`) and were not changed.

## Fix

- Use logical classes: `sm:text-start` in both headers, `end-4` for both close buttons, and drop the two `text-left` overrides in New Entry (or make them `text-start`).
- Check that a start-aligned title doesn't run under the × (e.g. `pe-6` on the header when the close button shows).

**Acceptance:** in `fa`, a dialog's title, description and × sit on the right/left exactly as the English layout mirrored. In English nothing moves. A render test under `dir="rtl"` pins the header's `text-start` and the close button's `end-*` class.

**Resolved 2026-11-12** — shipped in this commit (`dashboard`). `DialogHeader`
and `AlertDialogHeader` use `sm:text-start`, and the `Dialog` and `Sheet`
close buttons use `end-4`, so in `fa` a dialog's title, description and ×
mirror the English layout; New Entry's title and description are
`text-start`. A dialog that shows its close button also gives its header
`pe-6` (`padding-inline-end`), so a start-aligned title can't run under the ×
in either direction. In English short titles don't move; a title long enough
to reach the × now wraps before it. The built CSS emits `inset-inline-end`
and `padding-inline-end` for the new classes. Regression test
`dialog-rtl.test.tsx` renders Dialog, AlertDialog and Sheet under `dir="rtl"`
and pins `sm:text-start`, `end-4` and the header padding, and scans New Entry
for a forced `text-left`; four cases fail against the previous primitives.

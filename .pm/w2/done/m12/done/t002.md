## Objective

Make the existing GraphQL deletion resolver call the centralized decision once before account deletion begins.

## Context

- Mobile already calls the argument-free `Mutation.deleteAccount`; changing that contract would strand existing clients.
- The current `session-only` operation class rejects mobile OAuth before the resolver can apply user-lifecycle policy.

## Steps

1. Add an `authz` operation class that admits authenticated requests to the decision point without granting ledger authority.
2. Inject the authorization service into `AccountResolver` through the existing composition root.
3. Derive `user:<identity.userId>`, call `authorizeOrThrow` once, and invoke account deletion only after allow.

## Objective

Ensure the new authorization module is the only component deciding whether the current request may delete a user.

## Context

- Existing helpers special-case browser sessions and a static mobile client carrying `ledger.admin`.
- Retaining those checks in identity, the scope gate, or `AccountService` would leave multiple authorities and preserve the original model mismatch.

## Steps

1. Remove the client-id/ledger-admin deletion helpers and their tests from identity code.
2. Pass the already-authorized user ID into `AccountService` so it keeps only deletion behavior.
3. Search source and docs for deletion authorization bypasses or duplicate policy fragments.

## Files

- `backend-cluster/backend-v2/src/server/api/identity.ts`
- `backend-cluster/backend-v2/src/features/auth/service/account-service.ts`
- Focused tests beside those files

## Acceptance criteria

- [x] No deletion decision depends on a client ID, ledger scope, or ledger role.
- [x] `AccountService` performs no request-credential authorization.
- [x] Existing account cleanup and failure behavior remain unchanged.

## Out of scope

- Refactoring authentication or account-service behavior unrelated to authorization.

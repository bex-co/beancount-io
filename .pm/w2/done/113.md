# Create File and Upload offer a case-only twin of an existing file, then say "refresh and try again"

**Minor · dashboard · 30–40 minutes.** A2: the server now refuses `Main.bean` beside `main.bean`, because a macOS or Windows clone would keep only one of the pair. The dashboard still green-lights the name, and the refusal reaches the user as generic conflict advice that refreshing cannot fix. This is the dashboard counterpart of [w21/770](../w21/done/770.md) (`7be2a2212`, backend-v2 and mobile).

Production https://beancount.io, 2026-11-10, English, isolated headless Chromium 156 at 1440×1000, signed in as the owner of the designated synthetic ledger. Both writes were refused; no file was created and main.bean stayed at blob `f1a0b83c`. Local main `79c133496`.

## Reproduce

1. **Create File** at the root of a ledger that has `main.bean`: type `Main.bean` (or `MAIN.BEAN`). No validation message appears and **Save** is enabled. Control: `main.bean` and `main.bean ` show "Already exists in this folder" with Save disabled.
2. Click **Save**. The toast reads **"This change conflicts with the current state. Please refresh and try again."** The server's `CONFLICT` message is `File conflict: Main.bean already exists as main.bean`.
3. **Upload Files** to the same folder with a local file named `MAIN.BEAN`. The staged list shows no warning and **Upload Files** is enabled. Control: a file named `main.bean` shows "Already exists in this folder". After upload, the inline alert persists: **"MAIN.BEAN wasn't uploaded: This change conflicts with the current state. Please refresh and try again."**

## Root cause

- `dashboard/src/features/ledger-editor/create-file/validate-create-file-name.ts:54` compares names exactly: `existingNames.includes(trimmed)`.
- `dashboard/src/features/ledger-editor/upload-files/index.tsx:105-117,399` builds `new Set(folder.names)` and checks `existingNames.has(file.name)`.
- The server's rule is `portablePathKey` (`backend-cluster/backend-v2/src/features/ledger/utils/portable-twin.ts:9`): NFC normalization, invisible characters stripped, lowercased. Its `CONFLICT` falls through to the shared `common.errors.conflict` text.

## Fix

- Add a dashboard `portablePathKey` with the same three rules, as a local copy (packages stay independent). Use it for the existing-name check in both Create File and Upload.
- When the key matches a different spelling, say so: "Already exists in this folder as main.bean". Keep Save / Upload disabled.
- For a server `CONFLICT` whose message contains `already exists as <path>`, show the same localized message (interpolate only the validated existing name). Never show the generic refresh advice for this case.
- Add keys in all 15 locales. Test `Main.bean`, `MAIN.BEAN`, an NFD `é`, and a zero-width-space name against `main.bean` / `é.bean` in both flows.

## Blast radius

Create File (single segment; nested paths are only checked by the server) and Upload Files. Folder twins (`Receipts/` beside `receipts/`) are refused by the server through the same rule and need the same message mapping.

## Dedupe

Searched `.pm/**` for `case-insensitive`, `collid`, `already exists as`, `portable` and `twin`. w21/770 (done) shipped the server rule and mobile. w3/196 and w3/486 cover other Create File name checks. No dashboard item exists.

**Resolved 2026-11-10** — shipped in this commit (`dashboard`). A local copy
of backend-v2's `portablePathKey` (NFC, invisible characters stripped,
lowercased) lives in `features/ledger-editor/shared/lib/portable-path-key.ts`.
Create File and Upload Files check each name against the folder with it:
`Main.bean`, `MAIN.BEAN`, an NFD `é` or a zero-width-space spelling beside
`main.bean` / `é.bean` now reads "Already exists in this folder as main.bean"
and keeps Save / Upload disabled; the exact name keeps "Already exists in
this folder". A server `CONFLICT` whose message ends `already exists as
<path>` — a nested path or folder twin only the server can see — shows the
same message with that path (no control characters, at most 1024
characters) in the Create File toast and the upload's stopped-at alert,
never the generic refresh advice. The new `ledgerEditor.fileExistsAs` key is
in all 15 locales.

in both the create-file and upload-files catalogs with different text, and
the upload-files one wins the merge, so Create File already shows "Already

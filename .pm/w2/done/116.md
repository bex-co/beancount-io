# Add Budget's account list is announced as "Expenses:Groceries", an account that may not exist

**Minor (accessibility) · dashboard · 15–20 minutes.** A2: when a screen-reader user opens the Account picker in Add Budget, the popup and its list are both announced as "Expenses:Groceries". That sounds like a value already chosen, and in most ledgers no such account exists.

Production https://beancount.io, 2026-11-10, English, isolated headless Chromium 156 at 1440×1000, signed in as the owner of the designated synthetic ledger. Accessibility tree via Playwright snapshot; nothing was saved. Local main `a6c2d42c7`.

## Reproduce

1. Open `/ledger/<o>/<l>/budget` and choose **Add Budget**.
2. Focus the **Account** field and open its list.

**Actual (accessibility tree):** `dialog "Expenses:Groceries"` › `listbox "Expenses:Groceries"` › `option "Assets:Bank:Checking"` … `option "Expenses:Food:Groceries"` … The field itself is correctly named `combobox "Account"`.

**Expected:** the popup and listbox are named like the field, for example "Account" or "Account suggestions". They should never carry an example value.

**Control:** the Journal posting pickers use the same shared combobox with the placeholder "Account (e.g., Assets:Bank:Checking)", so their popup name reads as a description, not a value.

## Root cause

`dashboard/src/common/components/ui/combobox.tsx:~297` and `~333` set `aria-label={defaultPlaceholder}` on the `PopoverContent` and the listbox (a deliberate choice: "the field's own placeholder is the identity a reader already has"). `features/ledger-data/budget/add-budget-dialog.tsx:~276` passes `page.budget.budgetAccountPlaceholder`, whose English message is the bare example `Expenses:Groceries` (`features/ledger-data/budget/locales/en.ts:163`). The other 14 locales follow the same pattern.

## Fix

Prefer naming the popup and listbox from the field's label: pass the form label's id and use `aria-labelledby`. Fall back to the placeholder only when no label exists. As a minimum, reword `page.budget.budgetAccountPlaceholder` in all 15 locales to a description in the Journal style, "Account (e.g., Expenses:Food:Groceries)". Extend `common/components/ui/__tests__/combobox-field-identity.test.tsx` to assert the popup name for a labelled field.

## Blast radius

Every caller of the shared `Combobox` that passes a bare example as its placeholder. Budget's account field is the one found. The `ledger-comboboxes/*` wrappers used by Journal pass descriptive placeholders.

## Dedupe

Searched `.pm/**` for `budgetAccountPlaceholder` and `Expenses:Groceries`. Matches are unrelated budget fixtures (w4/m20) and CLI examples. w4/123 named other popups. No existing item.

**Resolved 2026-11-10** — shipped in this commit (`dashboard`). The shared
`Combobox` names its popup (`role="dialog"`) and listbox after the field's
own label — read from `input.labels` each time the list opens — and falls
back to the placeholder only for a field with no label. Add Budget's popup
and list are now announced as "Account". Both were done: Budget's
`page.budget.budgetAccountPlaceholder` also reads "Account (e.g.,
Expenses:Food:Groceries)" in the Journal style, in all 15 locales, so the
field no longer shows a bare example either. Deviation from the suggested
`aria-labelledby`: the shared `FormLabel` carries no id, and pointing
`aria-labelledby` at the input would name the popup by the input's value,
so the label's text is used as `aria-label`.

Validation: two new `combobox-field-identity.test.tsx` cases — a labelled
field whose placeholder is `Expenses:Groceries` gets a dialog and listbox
named "Account" (fails against the previous combobox), and an unlabelled
field keeps its placeholder as the name. `yarn format:check`, `yarn lint`,
`yarn test` (780 files, 7810 passed, 1 existing skip) and `yarn build` pass;
secret scan clean. Not re-checked with a screen reader or against production
before the next dashboard deploy.

## Objective

Let a client ask for an immediate re-fetch of a ledger's managed price feeds, with the same result shape as the status read.

## Context

- Ledger route from t001: `POST /reports/:owner/:repo/managed-prices/refresh`.
- The action is operational, not a content write, but it spends a shared upstream fetch. Gate it on the ledger write capability so anonymous or read-only viewers of a public ledger cannot trigger fetches.

## Steps

1. Add a service method, REST `POST …/managed-prices/refresh`, a GraphQL mutation and an MCP tool, all under one canonical action and one `VERB_TABLE` row.
2. Add contract tests: allowed, denied, no side effect on denial.

## Files

- `backend-cluster/backend-v2/src/features/ledger/**`, `src/features/ai-agent/api/**`, `src/server/api/**`, `docs/openapi/v1.json`

- [x] The three surfaces return the refreshed status records.
- [x] Read-only credentials are refused before any ledger call.
- [x] Parity guards pass.

## Objective

Add the global options every command family shares, and a single target-resolution rule for the local entry file, so that scripts and agents can name the ledger explicitly instead of relying on `main.bean` in the working directory.

## Context

- Every local command uses `DEFAULT_ENTRY_FILE = Path("main.bean")` from `cli/src/cli/config.py`; there is no `--file`, `--json`, `--no-input`, or `--version` today, although `docs/USAGE.md` already promises `--file` and universal `--json` (PRFAQ FAQ 3).
- Resolution order agreed in the TPM discussion: `--file` > `BEA_FILE` environment variable > `./main.bean`. A missing file is a usage error (exit 2) naming the three sources.
- `--no-input` is implicitly on when stdin is not a terminal or when `--json` is set; `--yes` answers destructive confirmations; `CI=true` also implies `--no-input`.
- `--ledger` for hosted targets is deliberately deferred to the REST-transport increment (PRFAQ FAQ 5).

## Steps

1. Add a Typer callback on the root app with `--file/-f`, `--json`, `--no-input`, `--yes`, and `--version` (eager, prints `bea <version>` from package metadata).
2. Introduce a small run-context object (target path, json, no_input, yes) stored on the Typer context and read by commands via one helper; remove direct uses of `DEFAULT_ENTRY_FILE` from commands.
3. Implement the resolution order and the exit-2 error for a missing entry file.
4. Wire `ledger delete` (t002) to the context: confirm in a terminal, require `--yes` under `--no-input`.
5. Document the options at the top of `docs/USAGE.md`.

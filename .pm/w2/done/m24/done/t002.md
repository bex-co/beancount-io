## Objective

Reshape the command tree to the agreed `bea` shape: directive reads become `bea list <type>`, directive writes become `bea add <type>`, the hosted create-and-clone command stops squatting on the `init` name, and destructive or visibility-affecting hosted defaults become safe.

## Context

- `cli/src/cli/commands/read.py` registers `read <type>` and `cli/src/cli/commands/write.py` registers `write <type>` for eleven directive types each; `write transactions --from PATH` is the bulk JSON path.
- `cli/src/cli/commands/ledger/app.py`: `ledger init NAME` creates a hosted ledger then SSH-clones it; `ledger create` defaults to `--public`; `ledger delete OWNER/NAME` deletes immediately with no confirmation.
- `init` is reserved for a future local scaffold (`bea init [DIR]`, the built-in form of the `beancount-init` skill); it must not ship in this milestone but the name must be free.
- PRFAQ FAQ 16 records `ledger init` reporting success after creation even when the clone fails.

## Steps

1. Rename the Typer groups: `read_app` mounts as `list`, `write_app` mounts as `add`; keep the eleven type names; keep `add transactions --from PATH`.
2. Remove `ledger init`; add `--clone` (and `--dir`) to `ledger create` with the same behavior; a failed clone after a successful create exits nonzero and prints the ledger that was created.
3. Flip `ledger create` to default private (`--public` opts in).
4. Make `ledger delete` require confirmation in a terminal and `--yes` otherwise (the `--no-input` plumbing lands in t004; here add the `--yes` flag and a plain `typer.confirm`).
5. Update `docs/USAGE.md` command names in passing (the full rewrite is t008).

## Acceptance criteria

- [ ] `bea list transaction --limit 5` and `bea add balance --date … --account … --amount …` work; `bea read` and `bea write` are unknown commands
- [ ] `bea ledger init` is unknown; `bea ledger create NAME --clone` creates then clones
- [ ] `bea ledger create NAME` creates a private ledger unless `--public` is passed
- [ ] `bea ledger delete o/n` asks for confirmation and `--yes` skips it

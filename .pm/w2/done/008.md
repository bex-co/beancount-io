# MCP prompts from the ledger skills

Hosted agents cannot see `skills/` (beancount-ask, close, reconcile, import…). The MCP server advertises no `prompts` capability. Publish `close-month`, `reconcile-account`, `categorize-imports`, and `spending-report` as MCP prompts whose bodies are the existing skill playbooks rewritten against the MCP tools (after w2/m27 and m28 land so the tools they reference exist). More than an hour — promote to a milestone once m28 ships. Source: MCP field audit 2026-09-08.

---

**Resolved 2026-09-12** — implemented rather than promoted: with m27 and m28 shipped, the
tools the playbooks name all exist, so this was one fragment plus its registration.
`backend-v2/src/features/ai-agent/api/mcp-prompts.ts` publishes `close-month`,
`reconcile-account`, `categorize-imports`, and `spending-report` as MCP prompts, registered
in `assembleMcpRegistry` beside the tool and resource loops.

Bodies are the `skills/.claude/skills/beancount-{close,reconcile,import,ask}` playbooks
rewritten against the MCP tools — same phases, same classification tables, same refusals
(never invent an account, never fabricate an entry, never write before an explicit yes,
check `validation.newErrors` after every write). Built per request so the caller's ledger
pin is stated in the text; a pinned credential asked for another ledger is told the
selection is outside its restriction rather than handed an unreachable one. `prompts/list`
joins the free handshake set (static enumeration, same shape as `tools/list`);
`prompts/get` stays charged.

Prompts carry no op id and no PDP action: they perform no domain work, so everything they
instruct is authorized and metered where the named tool or resource runs. That reasoning is
recorded in `backend-v2/CLAUDE.md` next to the tools/resources line.
`mcp-prompt-list.test.ts` covers the advertised list, the argument folding, the pin
ceiling, the refusals, and a guard that fails when a playbook names a tool that no longer
exists. `yarn typecheck` and `yarn test` (280 suites, 4396 tests) green;
`yarn generate-v1-openapi` produced no diff, as expected for a change that adds no REST.

Known upstream wrinkle, not a contract of ours: the MCP SDK parses `params.arguments`
against the declared shape and rejects `undefined`, so a client must send `arguments: {}`
for a prompt that declares any — identical for every server built on the SDK.

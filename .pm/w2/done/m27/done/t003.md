## Objective

Add the four reads every audit agent needed first, as tools, and amend ADR 0008 D2 with the measured exception: a read becomes a tool when agent runs show it is the first thing an agent looks for and clients do not surface the resource.

## Context

- ADR 0008 D2 put reads on resources because tools compete for selection attention. In Claude Code the resource templates are never enumerated (`resources/list` is empty), so the trade-off is inverted for the handful of reads that precede everything else.
- `listLedgers` = `catalog/ledgers` (pinned credentials return their one ledger). `checkLedger` = `errors` + `entries-count` + `latest-commit` in one call. `getLedgerContext` = operating currency/options + open accounts + currencies + payees (top N) + years + source files, one call. `getEntryContext` = `entry-context/{hash}`.
- Each tool wraps the same service call as its resource twin, so the parity tests keep one list and two adapters (ADR 0008 D5).

## Steps

1. Amend `docs/adrs/ADR008-backend-v2-surface-parity.md` with a D2 exception and the evidence (three agent runs, turn counts).
2. Add the four descriptors with `readOnlyHint` (t002), short descriptions, and output schemas; classify them in `op-class.ts` as `read` aliases of the existing verbs.
3. `getLedgerContext` accepts `payeeLimit` (default 50) and returns counts alongside truncated lists so a large ledger does not flood context.
4. Update the surface-parity fixture deliberately.

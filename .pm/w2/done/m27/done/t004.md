## Objective

`resources/list` returns nothing, so clients that enumerate concrete resources (Claude Code's `ListMcpResourcesTool`, Claude Desktop's picker) see an empty server. Return the handful of concrete URIs that exist for the credential's ledger.

## Context

- The SDK's `registerResource` with a template takes an optional `list` callback; the fragment deliberately omitted it to avoid crawling every file of every ledger.
- For a pinned credential the set is small and known: `errors`, `accounts`, `payees`, `metadata`, `source-files`, `statements/balance-sheet`, `statements/income-statement`, and one `files/{path}` per source file (already listed by `source-files`).

## Steps

1. Implement `list` for the ledger-scoped templates: resolve the credential's pin (or, for unpinned credentials, the first page of `catalog/ledgers`) and emit concrete URIs with titles.
2. Cap the file listing at the ledger's source files (not every repository file) and at 100 entries.
3. Keep authorization per read: listing does not grant reading (ADR 0007 D5).

## Acceptance criteria

- [ ] `resources/list` with a pinned key returns at least `errors`, `accounts`, `payees`, `metadata`, and each source file.
- [ ] `resources/list` with an unpinned key returns entries for the caller's own ledgers.
- [ ] A `ListMcpResourcesTool` call in Claude Code shows the entries.

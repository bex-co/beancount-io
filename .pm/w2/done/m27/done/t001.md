## Objective

The MCP `initialize` result carries no `instructions`. Fill that one free channel with what the audit's agents spent turns discovering: the credential's pin, how to select a ledger, the resource URI grammar, when to check errors, and how BQL rows work.

## Context

- `assembleMcpRegistry` constructs `new McpServer({name, version})` with no `instructions`; the SDK accepts one per server instance and the endpoint builds a server per request, so the string can be credential-specific.
- Agent run 3 found its ledger by reading `listApiKeys`; runs 1 and 2 never learned that `errors`, `accounts`, or `payees` existed; run 3's first BQL for payees returned silently empty (`payee != NULL`).

## Steps

1. Write a `buildInstructions(identity)` in `mcp-context.ts` returning ~15 short lines: pinned ledger or "unpinned: pass `ledger: owner/name`; call `listLedgers` first"; the three URI forms with one example each; "after any write, check `validation.newErrors` or `checkLedger`"; "BQL rows are postings — `LIMIT` counts postings; use `runBqlQueryStructured` for numbers"; the rate budgets; "reads are cheaper as resources when your client can fetch them".
2. Pass it to `new McpServer(..., { instructions })`.
3. Keep the text under 1,500 characters; it is paid on every session.

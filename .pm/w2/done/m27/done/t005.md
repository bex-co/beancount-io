## Objective

`tools/list` is 47 KB (~12k tokens) and opens with `addLegacyEntries`; `runBqlQuery` is fifteenth. Cut it to under 25 KB and order it by expected use without dropping any capability that lacks a REST twin.

## Context

- `addLegacyEntries` and the `legacy/*` resource templates exist for GraphQL compatibility and have REST twins; agents should never choose them.
- `createApiKey` publishes alias fields (`ledger_scope`/`ledgerScope`, `expires_at`/`expiresAt`) and a 400-character date regex twice; `addLedgerEntries` is 5 KB because it inlines nine directive shapes.
- Order agents expect: query and read, ledger context (m27/t003), write, bank, pull requests, account and keys, destructive last.

## Steps

1. Mark `addLegacyEntries` and the legacy resources `mcpExempt: M.compatOnly` (new exemption reason) in `op-class.ts` and drop them from the MCP fragments; keep them on REST.
2. Fold `listApiKeys`/`createApiKey`/`revokeApiKey` into `manageApiKeys` with an `operation` discriminator (same pattern as `manageBankImport`).
3. Replace the alias fields and the regex with one `expiresAt` (`format: date-time`) and one `ledgerScope`; keep accepting the snake_case spellings on input for one release.
4. Reorder `MCP_TOOLS`; add a test that asserts the first five tools are reads and the byte size of `tools/list` stays under 25 KB.

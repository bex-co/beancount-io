## Cause and bounded repair

`mobile/src/common/d3/interactive-line-chart.tsx:416–429` computes the displayed change from `windowBaseline ?? numbers[0] ?? 0`. The resting color uses that same baseline at608–622. The active scrub reaction at630–639 instead compares `pointYs[index] <= baselineY`, where `baselineY` at516 is **the first plotted point's y coordinate**. Equality at index0 therefore sets `scrubUp=true` for this negative ALL point. That shared color reaches the header at733, gradient at743–744, line at773 and cursor at811.

Make active and resting direction use the same resolved numerical baseline. If retaining the precomputed-y worklet path, project the actual opening balance through the existing scale as a separate comparison coordinate; it may lie outside the plotted domain. Keep the dashed first-point reference line's existing geometry: completed036 explicitly left it there, and moving it or changing the domain is outside this color repair. Preserve the UI-thread index/clamping behavior, crossing-only color updates, release/cancellation, chart morphs, currency/quantity formatters and haptics. No dependency, API or cross-package change is needed.

Acceptance: fresh native Alibaba Liabilities/ALL's first point retains the correct negative amount and renders its change/line/cursor red; release restores the correct resting state. Assets/ALL's first positive point stays green and the six-month March negative control stays red. Add behavioral coverage that exercises the active direction with an opening baseline different from the first plotted close, including zero, a prior-month baseline, equality, positive and negative changes, and idle/stale-index handling. The existing `balance-chart-card/__tests__/balance-change-baseline.test.ts` only counts two baseline declarations; it passes with the wrong worklet comparison, so another source-string assertion is insufficient. Recheck the account balance consumer and unit-valued charts when implementing, then run the mobile gates.

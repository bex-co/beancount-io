## Objective

Tool text content today is JSON wrapping a text table (`{"ok":true,"result":"   account   balance\n---"}`), repeated verbatim in `structuredContent`; empty results are `""`; resources are pretty-printed with two-space indentation. Make text content what a human would read and `structuredContent` what a program would parse.

## Context

- `makeMcpToolHandler` in `composition-root.ts` serializes the whole envelope into the text block; `bqlQueryOutputSchema` is a string; resources call `JSON.stringify(result, null, 2)` in `mcp-resources.ts`.
- Audit measurements: pretty-printing roughly doubles resource payloads; `trial-balance` was 5.9 KB for a one-transaction ledger.

## Steps

1. Text content: for BQL, the table (or `0 rows — no postings matched`) with a first line `N rows`; for other tools, a one-line summary then the payload only when it is short; keep the full result in `structuredContent`.
2. Resources: `JSON.stringify(result)` with no indentation; keep `text/plain` files as-is.
3. `runBqlQueryStructured`: add `rowCount` and `truncated` to the result; cap rows at a documented default (1,000) with `limit` guidance in the error hint.

## Acceptance criteria

- [x] A BQL result's text content begins with the row count and contains the table unescaped; `structuredContent` carries the typed rows.
- [x] An empty query result says `0 rows` in text and `rowCount: 0` in structured content.
- [x] Resource JSON is compact; the `trial-balance` payload for the starter ledger shrinks by at least 35%.

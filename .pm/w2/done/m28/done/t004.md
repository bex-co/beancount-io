## Objective

One session of ~57 posts (initialize, one notification, 55 calls, mostly reads) got `429` on plain reads with the message `Rate limit exceeded for REST POST /api-gateway/mcp`, and the SDK client threw out of the session. Budget the transport like reads and return 429 in-band.

## Context

- `rate-limit.ts`: the endpoint is classified as one op in addition to per-tool budgets; the transport op falls to the write-class default (60/min).
- `initialize`, `notifications/initialized`, `tools/list`, `resources/templates/list`, and `ping` are handshake traffic and should not spend a caller's budget; per-tool budgets already protect writes.

## Steps

1. Exempt handshake methods from the transport budget and give the transport op an explicit read-class budget in `OP_BUDGETS`.
2. When a tool call is over budget, answer the JSON-RPC request with an `isError` result (`code: RATE_LIMITED`, `retryAfter`) instead of an HTTP 429, so the session continues; keep HTTP 429 for pre-parse abuse.
3. State the budgets in the m27 instructions text.

- [x] The rate-limit tests cover the handshake exemption and the in-band 429.

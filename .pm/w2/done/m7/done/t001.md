## Objective

Lock the strategy for classifying extensionless/dotfile text files so implementation is consistent: curated basename allowlist (linguist-inspired) plus optional UTF-8/null-byte content sniff as fallback.

## Context

- Current `isTextFile` is extension-only (`dashboard/src/features/ledger-editor/shared/lib/utils.ts:50`). `LICENSE` → `getFileExtension=""` → `unknown`.
- Research: GitHub Linguist, GitLab file-type, VS Code — all use extension + well-known filename + content heuristics.
- Need to decide allowlist scope vs pure sniff to avoid false-positives on binaries.

## Steps

1. Enumerate real repo files that should be text: `LICENSE`/`LICENCE`/`COPYING`/`COPYRIGHT`/`README`/`CONTRIBUTING`/`CODE_OF_CONDUCT`/`CHANGELOG`/`HISTORY`/`AUTHORS`/`Makefile`/`GNUmakefile`/`Dockerfile`/`Containerfile`/`Gemfile`/`Rakefile`/`Vagrantfile`/`Procfile` and dotfiles `.gitignore`/`.gitattributes`/`.editorconfig`/`.env.example`.
2. Document decision: basename allowlist (case-insensitive, leading-dot stripped) is primary; content sniff (`base64Decode` → no `\0`, valid UTF-8, printable ratio) is secondary/future-gated if base64 content is available at call site.
3. Record language mapping for Monaco: `license/copying → plaintext`, `readme → markdown`, `makefile → makefile`, `dockerfile → dockerfile`, `gitignore → ignore`, `sh/bash → shell`.

# Dashboard "Delete account" asks the API for a field it no longer returns

**Severity:** major. **Package:** dashboard. **Goal:** A2 — a user who deletes an account from the Accounts page gets the deletion, not a GraphQL validation error.

Found 2026-09-23 while running dashboard codegen against the current backend-v2 schema (w2/m32/t004). `dashboard/src/features/ledger-data/accounts/graphql/accounts.graphql` selects `deletedHashes` on `DeleteMultiSourceSlicesResponse`. Since `c29268be` (2026-09-08) that type carries only `message` and `deletedCount`. GraphQL validates the selection before running anything, so every Delete account confirmation (`delete-account-dialog.tsx`, the only consumer) is refused as an invalid document once that schema is deployed. Codegen reproduces it: `CODEGEN_SCHEMA_FILE=<SDL printed from backend-v2 source> yarn codegen` fails with `Cannot query field "deletedHashes" on type "DeleteMultiSourceSlicesResponse". Did you mean "deletedCount"?`.

The dashboard's generated `src/graphql/definitions.ts` was also behind the backend source elsewhere: new append/PR input descriptions and required `CreatePullRequestInput` fields. Typecheck stays green after regenerating, so no other operation selected a removed field.

---

**Resolved 2026-09-23** — The mutation now selects `deletedCount`, and `definitions.ts` is regenerated from the backend-v2 source schema. Codegen against that schema fails before the fix and passes after. Dashboard format, lint, 4846 tests and build pass. No dashboard unit test can catch this class: nothing in the repository validates client operation documents against the backend schema. That guard is recorded as [w2/032](../032.md). Shipped in `dashboard`.

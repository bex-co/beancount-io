# Offer the skill suite as a Claude Code plugin too

**Idea · skills · needs sizing · A3.** Found in the agentic-skill review of `skills/`, 2026-10-18.

Today the suite installs from a sparse Git checkout plus `skills/scripts/beancount-skills.py` (`skills/docs/installation.md`). [w6/m6](../../w6/m6/README.md) adds ClawHub for OpenClaw and Hermes. Claude Code also installs skills as part of a plugin from a marketplace (`/plugin marketplace add …`, then `/plugin install …`). That would give Claude Code users one versioned install of the whole suite with no Python helper, and in-client updates.

Questions to settle before sizing:

- **Naming:** plugin skills are namespaced by plugin (`/<plugin>:<skill>`), so a `beancount` plugin would show `/beancount:beancount-reconcile` unless the skill names drop their prefix inside the plugin. That interacts with [m39](../blocked/m39/README.md) and with the Codex install, which has no plugin namespace.
- **Single source:** the plugin must point at the same `skills/.claude/skills/` tree, not a copy. Root `AGENTS.md` forbids parallel copies and requires equivalent Codex behavior for any platform-specific configuration.
- **Versioning:** how plugin versions relate to the Git revision that `install` prints, and to the immutable ClawHub versions.

Verify the current plugin and marketplace manifest format against Claude Code's documentation at the time of the work. Promote to a milestone once the questions above have answers.

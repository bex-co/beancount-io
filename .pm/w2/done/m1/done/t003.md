## Objective

Write `references/matching.md`: the diff algorithm between normalized statement lines and ledger postings on the target account, defining every mismatch class with a detection rule and an example.

## Context

- Classes: missing-in-ledger, missing-on-statement (suspect entry), duplicate, amount mismatch, date drift (posting vs settlement dates).
- Pending/settled timing means exact-date matching fails; a date window (± a few days) with amount+description similarity is the norm.

## Steps

1. Define match keys and ordering: exact (date+amount) → windowed (amount within ±N days + description similarity) → unmatched.
2. Specify each mismatch class: rule, example, and how it appears in the diff report.
3. Tolerance rules: date window default, when to ask the user instead of auto-classifying.

Found 2026-09-08, none blocking; batch into whichever MCP milestone touches the file:

- `readLedgerFiles` description says "Returns content with 1-based line numbers"; content is raw text with `startLine`/`endLine` metadata. Fix the sentence (`read-ledger-files-tool.ts` L12).
- `configuration/health` returns the JSON string `"OK"`; return an object.
- Commit messages: "Add 1 entries" (`addBulkEntries`), "AI edit: …" for every file edit. Use "Add 1 entry / N entries" and let the caller's description stand alone.

- `runBqlQuery` description lists columns but not `year`, `month`, `tags`, `links`, `meta`, nor that rows are postings; one sentence fixes the `LIMIT 5 → 3 transactions` confusion agents hit.

**Resolved 2026-09-12** — five of the seven fixed, one already gone, one deliberately not done.

Fixed:

- `readLedgerFiles` description now says `content` is raw text with `startLine`/`endLine`/
  `totalLines` alongside, rather than claiming the text carries line numbers.
- Commit messages: `Add 1 entry` / `Add N entries` — the ledger service's route handler now
  calls `addEntriesCommitMessage`, a pure helper extracted so the count-to-noun rule has a
  unit test without a Gitea harness. `editLedgerFiles` drops the `AI edit:` prefix and uses
  the caller's `description` verbatim; its schema now says the description *is* the commit
  message, so callers write it as one.
- `journal?time=` — documented, not defaulted. `time` now explains that it bounds
  transactions only and that epoch-dated `open`/`close` directives fall inside every window,
  and `directiveTypes` says what omitting it returns. Defaulting to transactions for a
  single-day `time` would change what REST, GraphQL, and MCP all return for an unchanged
  request; the caller asks for what it wants and the description says how.
- `payee-transactions` / `payee-accounts` now describe themselves honestly rather than being
  renamed: the first returns the single most recent matching transaction (Fava's autocomplete
  template) or null, the second returns *every* account re-sorted by exponential decay over
  this payee's history, with untouched accounts still present at the back. Renaming would
  break the published v1 REST paths, their `op-class.ts` rows, and the frozen parity baseline
  for a cosmetic gain. `narration-transactions` had the same wording problem and got the same
  fix.
- `runBqlQuery` description gains `year`, `month`, `tags`, `links`, `meta`, and the
  posting-row caveat. Kept terse: `mcp-tool-list.test.ts` enforces a 61 KB ceiling on
  `tools/list` because it is paid on every session, and the first draft blew through it.

Already gone: `addLegacyEntries` — m27/t005 removed it from MCP, as this note anticipated.

**Not done: `configuration/health` returning the JSON string `"OK"`.** It is a published v1
contract (`healthCheckResponseSchema`, in `docs/openapi/v1.json`) with parity tests across
REST, GraphQL, and MCP, and any monitoring probe pointed at it string-matches `"OK"`.
Wrapping it in an object breaks every existing caller for a purely cosmetic gain. If it
should still change, it wants a versioned deprecation, not a sub-hour polish item.

(spec regenerated for the description changes) all green. `ledger`: `yarn typecheck`,
`yarn lint`, `yarn test` (65 suites, 907 tests) green.

# `cli/docs/USAGE.md` promises a `bea format` syntax-error contract that does not exist

Found 2026-09-12 by a CLI QA sweep against HEAD `84231f9c`, bea 0.2.0. Docs-only fix, sub-hour.

`cli/docs/USAGE.md:256-261` says:

> Every formatting mode reports syntax errors with each file's path and line, skips that file, and exits **1**. A recursive run continues through the other files; normal mode still formats valid files. […] In JSON mode, failures return the scan result in `error.result`, including `formatted` and `skipped` paths, `scanned`, `dry_run`, and `check`.

None of that happens on HEAD:

```
$ printf '2024-01-03 * "unterminated\n  Assets:Bank 1 USD\n' > a.bean
$ bea format a.bean --check
would format: .../a.bean
Error: 1 file(s) need formatting. Run bea format -i .../a.bean to apply.   # exit 1
$ bea format a.bean --in-place
formatted: .../a.bean
1/1 file(s) formatted.                                                     # exit 0
$ bea check --file a.bean
.../a.bean:1: Invalid token: '"unterminated'                               # exit 1
```

`--check` reports an unparseable file as merely needing formatting, `-i` realigns and rewrites it and exits 0, and no mode ever emits a `skipped` key (`--json format DIR --check` returns `{"scanned": N, "formatted": [...], "check": true, "dry_run": false}`).

- Root cause: the behavior is deliberate. `cli/src/cli/commands/format.py:1-14` (ADR014 t004) states the formatting "is a text transformation, deliberately regex-based and not a parse, and `bea` neither reimplements nor second-guesses it"; it delegates wholly to `bean-format`. `_result` (`format.py:204`) emits only `scanned` and `formatted`. The USAGE.md paragraph predates the ADR014 rewrite (introduced in `790791ac`).
- Fix: correct `cli/docs/USAGE.md:256-261` to describe delegation — formatting does not parse, a file with a syntax error is realigned like any other, and `format --check` is an alignment gate, not a validity gate. Point CI/pre-commit users at `bea check` for validity (`format --check` is advertised for pre-commit hooks at `USAGE.md:205`). Drop `skipped` from the documented JSON error result, or add it to `_result` if a skipped list is still wanted for unreadable files.
- Scope: documentation only unless the `skipped` key is kept; no command behavior changes. Run `make docs-check` in `cli/` afterward.
- Dedupe: nothing on the board mentions format syntax errors. Behavior is on main, not deployment lag.

## Resolution — 2026-09-14

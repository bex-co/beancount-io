## Objective

Define the final Dashboard authentication architecture in which OAuth owns the login transaction before credentials are entered, and legacy application sessions survive only as read-compatible credentials that cannot be newly issued.

## Context

- m21 starts OAuth only after password/OTP/magic-link code has already issued a legacy Dashboard session.
- The final boundary must distinguish account authentication from credential issuance: password, OTP, and magic links remain, but successful verification completes an OAuth interaction rather than creating a second application session.
- Existing users must not be logged out, so already-issued tokens remain accepted by the authenticated identity check until their own expiry.

## Steps

1. Inventory every legacy Dashboard session issuer, renewal, cookie write, callback, rollback flag, authenticated check, and non-Dashboard consumer.
2. Specify one OAuth-first state machine for password, signup/OTP, magic link, reset, errors, safe continuation, and provider interaction completion.
3. Mark each legacy surface delete, replace, or verify-only; prove no verify-only surface can issue or renew a token.

## Acceptance criteria

- [x] The design begins OAuth before credential entry and ends successful authentication at an authorization code, not a legacy token.
- [x] Every legacy Dashboard issuer and consumer has an explicit final disposition.
- [x] The sole compatibility exception is read-only validation of tokens issued before cutover until their existing expiry.
- [x] OAuth provider protocol state is explicitly retained and not confused with the retired legacy application session.

## Out of scope

- Ending support for already-issued valid tokens before they expire or changing Mobile/MCP authentication.

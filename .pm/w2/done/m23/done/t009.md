## Objective

Run `/simplify` over the completed OAuth-only login flow and remove transitional abstractions without weakening the existing-token compatibility boundary.

## Context

- Moving credential verification into OAuth can leave duplicated interaction, redirect, account-creation, and cookie helpers.
- The final design should have one obvious new-login path and one deliberately narrow legacy verifier.

## Steps

1. Review password, OTP, magic-link, interaction, callback, cookie, identity, and logout code as one end-to-end flow.
2. Consolidate state and validation primitives where trust boundaries match and delete obsolete bridge/rollback abstractions.
3. Confirm simplification cannot make legacy verification issue authority or broaden other OAuth clients.

## Files

- files changed by `w2/m23`

## Acceptance criteria

- [x] One OAuth-native new-login path and one verify-only legacy compatibility path remain.
- [x] Credential issuance, cookie writing, interaction completion, and exact-client classification each have one executable source of truth.
- [x] No transitional flag, duplicate callback, or dead legacy issuer remains.
- [x] Focused behavior and failure tests stay green.

## Out of scope

- Removing the verify-only compatibility path before existing tokens expire.

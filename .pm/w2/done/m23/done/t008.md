## Objective

Make the OAuth-only Dashboard login architecture and the narrow existing-token compatibility promise clear to users, self-hosters, and contributors.

## Context

- m21 documentation describes a staged legacy-session bootstrap and runtime rollback that this milestone removes.
- Operators need exact callback, proxy, cookie, key, and upgrade behavior without being told to enable a deleted fallback.
- Existing users must understand that they remain signed in while new authentication issues only OAuth credentials.

## Steps

1. Amend the Dashboard OAuth ADR and package/deployment guidance to show OAuth-first password, OTP, and magic-link flows.
2. Remove rollback/bootstrap instructions and document verify-only existing-token compatibility plus its final removal condition.
3. Recheck root/package guidance and Claude Code/Codex symlinks for accurate commands and architecture.

## Objective

Remove every Dashboard path that issues a legacy session or uses one as an intermediate credential before OAuth.

## Context

- m21's password, OTP, and magic-link completion deliberately installs a legacy session and then calls `/oauth/dashboard/start`.
- A runtime rollback flag can restore legacy issuance, which conflicts with OAuth-only login.
- The same cookie name may remain for compatibility, but new writes must contain only a validated Dashboard OAuth access token.

## Steps

1. Delete post-login OAuth bootstrap code and change authentication completions to return only through the active OAuth interaction.
2. Remove Dashboard legacy-session creation/cookie writes, one-time-token login callback behavior, and the runtime rollback path that re-enables legacy issuance.
3. Remove obsolete environment variables, deployment wiring, cookie-domain compatibility writes, and logout revocation calls except what is strictly needed to clear/read already-issued credentials.

## Files

- `dashboard/src/features/auth/**`
- `dashboard/src/features/oauth/**`
- `dashboard/src/config/config.server.ts`
- `backend-cluster/backend-v2/src/features/auth/**`
- deployment environment examples

## Acceptance criteria

- [x] Source and behavioral tests show no new Dashboard flow can create or return a legacy session token.
- [x] New authenticated cookies contain only the verified Dashboard OAuth credential.
- [x] No feature flag or callback can restore legacy Dashboard issuance at runtime.
- [x] Existing-token validation and OAuth logout remain functional without preserving dead issuance machinery.

## Out of scope

- Removing historical database migrations or OAuth provider session/grant storage.

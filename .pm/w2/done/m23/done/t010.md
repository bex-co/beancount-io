## Objective

Prove that all new Dashboard authentication is OAuth-native, no legacy token is issued, and existing valid tokens remain accepted without creating a permanent alternate login.

## Context

- Observing an OAuth request after signup is insufficient: m21 did that while still issuing a temporary legacy session.
- Tests must assert negative issuance/storage facts as well as successful OAuth identity.
- Mobile, MCP/DCR, and non-Dashboard credential boundaries remain release-sensitive.

## Steps

1. Cover password, OTP signup, magic link, reset, interaction state, PKCE callback, SSR/CSR identity, REST/agent, logout, and safe continuation through the OAuth-first path.
2. Assert no legacy session model write/token/cookie/response occurs for any new Dashboard authentication and no runtime setting restores it.
3. Cover valid/expired/revoked existing tokens, safe upgrade failure, first-party authorization ceilings, Mobile refresh, MCP audience separation, and protocol attack cases; run full package/model/deploy gates.

## Files

- Dashboard auth/OAuth/server-handler tests
- backend auth/OAuth/identity/PDP tests
- deployed smoke harness or documented repeatable smoke commands

## Acceptance criteria

- [x] Tests fail if password, OTP, or magic-link success creates any legacy Dashboard credential before OAuth.
- [x] Tests prove a pre-cutover token still authenticates but cannot be renewed, rotated, or used to enter a new login flow.
- [x] OAuth client, audience, scopes, exact 365-day TTL, PKCE/state, cookie isolation, and first-party authorization remain enforced.
- [x] Dashboard/backend full checks, authorization-model checks, deployment validation, guidance check, and source secret scan pass.

## Out of scope

- Coverage-number gaming or retaining implementation solely to satisfy obsolete tests.

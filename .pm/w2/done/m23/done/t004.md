## Objective

Create and authenticate a new account inside the active OAuth transaction so OTP verification completes directly into an authorization code rather than a temporary legacy session.

## Context

- Signup OTP state is short-lived account-creation state, not an authenticated application session, and may remain until verification.
- Current OTP verification creates the user, initializes optional ledger state, and installs a legacy session before beginning OAuth.
- Retry, replay, account uniqueness, attempt budgets, welcome messaging, and partial-failure behavior must remain correct.

## Steps

1. Bind signup and OTP session creation to the signed OAuth transaction without exposing either secret to client storage.
2. On valid OTP, create the account and provider account context transactionally enough to prevent duplicate users or credentials, then complete the OAuth interaction directly.
3. Preserve optional initial-ledger creation and welcome behavior while making retry/recovery safe when downstream initialization fails.

## Acceptance criteria

- [x] Valid OTP creates the account and returns through OAuth code + PKCE without issuing a legacy session token.
- [x] Invalid, expired, replayed, or over-budget OTP attempts create no authenticated credential.
- [x] Account and default-ledger initialization semantics remain correct under retry and partial failure.
- [x] OTP state expires and is deleted independently from OAuth provider and application credentials.

## Out of scope

- Replacing email OTP as a signup-verification method.

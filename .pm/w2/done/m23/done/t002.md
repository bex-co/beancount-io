## Objective

Make the OAuth authorization interaction the owner of every unauthenticated Dashboard login or signup attempt before the user submits credentials.

## Context

- The current Dashboard renders its legacy login/signup flow first and begins OAuth only after that flow succeeds.
- OAuth state, PKCE verifier, issuer, resource, redirect URI, safe continuation, and interaction identity must remain server-bound and tamper-resistant.
- First-party authentication should remain visually continuous without exposing provider tokens or transaction state to browser JavaScript.

## Steps

1. Route unauthenticated protected navigation, explicit login, signup, and magic-link entry through the Dashboard OAuth start transaction first.
2. Bind the provider interaction to the signed Dashboard transaction and render the existing authentication UX as that interaction's first-party page.
3. Preserve safe `next`, localization, replay/expiry handling, and public reset/forgot-password access without falling back to a legacy credential issuer.

## Files

- `dashboard/src/routes/oauth.dashboard*.tsx`
- `dashboard/src/features/oauth/**`
- `dashboard/src/features/auth/pages/**`
- `backend-cluster/backend-v2/src/features/oauth/api/oidc-route.ts`

## Acceptance criteria

- [x] Credential forms are reached only inside a valid OAuth transaction for new Dashboard authentication.
- [x] Duplicate, stale, off-issuer, or tampered interactions fail before credential verification and issue no credential.
- [x] Safe continuation and current user-visible navigation remain intact.
- [x] No OAuth transaction secret, verifier, code, or access token reaches browser storage, rendered HTML, analytics, or logs.

## Out of scope

- Redesigning authentication visuals or adding third-party identity providers.

## Cause and bounded repair

`mobile/src/screens/notifications-screen/notifications-screen.tsx:313–317` pushes only `{sha:commit.sha}`. `common/app-links/resolve-app-link.ts:118–127` likewise produces a commit route with only the SHA. `screens/commit-detail-screen/commit-detail-screen.tsx:164–170` combines that retained parameter with the current global `ledgerVar` for `GetCommitDetails`; no original ledger or mismatch gate survives. The app-link handler changes global selection and replaces the current destination, leaving older detail frames in history. Backend commit lookup parses the supplied ledger into owner/repository before querying that SHA (`backend-cluster/backend-v2/src/features/gitea/commits/service/commits-service.ts:237–270`); it cannot infer the lost original ledger. The incorrect association is source-traced and demonstrated by reversible native controls; the particular server error category is unverified.

Pass the originating ledger alongside the SHA from both producers. Validate that association against the selected ledger before mounting the query-backed detail, following `account-detail-screen.tsx:505–533` and its target selector. A mismatch should show localized commit-unavailable feedback and Back, with **no mismatched ledger/SHA request**, including from a retained mounted observer. Preserve normal cold/warm commit links, same-ledger navigation, permission checks, loading, real network-failure retry, diff rendering and original-ledger recovery.

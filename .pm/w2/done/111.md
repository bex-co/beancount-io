# The BQL editor hides five of the engine's actionable query errors behind "information provided is invalid"

**Minor · dashboard · 50–60 minutes.** A2: newcomers learning BQL in the Query page make exactly these mistakes. The engine already explains each one precisely, and the page replaces that explanation with generic advice. This follows on from [w4/160](../w4/done/160.md) (unknown column) and [w0/002](../w0/done/002.md) (syntax position), which each added one diagnostic.

Production https://beancount.io, 2026-11-10, English, isolated headless Chromium 156 at 1440×1000, signed in. Read-only queries on the designated synthetic ledger; the `empty(tags)` row also reproduced on `open_ledger/example`. Local main `f24e6a10d`.

## Reproduce

Open `/ledger/<o>/<l>/query?query=<query>` for each row. The page shows **"Some of the information provided is invalid. Please check and try again."** with a **Try Again** button, which re-runs the same failing query. The `QueryShell` response (`BAD_USER_INPUT`) says:

| Query | Engine message (prefix `Invalid BQL query: `) |
| --- | --- |
| `SELECT account, position GROUP BY account` | `Bare column "position" is not grouped and not aggregated: this query engine would silently report each group's first-row value. Add "position" …` |
| `SELECT nosuchfn(account)` | `Query execution error: no function matches "NOSUCHFN"` |
| `SELECT * FROM #nosuchtable` | `Query execution error: evaluation error: table '#nosuchtable' does not exist. Available system tables: #accounts, #balances, #commodities, …` |
| `SELECT length(account, 2)` | `Query execution error: invalid arguments for function LENGTH: expected 1 argument(s), got 2` |
| `SELECT tags, count(*) WHERE NOT empty(tags) GROUP BY tags` | `Query execution error: type error: EMPTY expects an inventory` |

Controls that already work: `SELECT nonexistent_column` → "column … not found"-style guidance (w4/160), and `SELECT nope FROM` → "Syntax error near “FROM” at character 13" (w0/002).

## Root cause

`dashboard/src/features/bql/lib/query-error.ts` recognizes only `UNKNOWN_COLUMN_PATTERN`, `SYNTAX_ERROR_PATTERN` and `FOUND_TOKEN_PATTERN`. Every other `BAD_USER_INPUT` falls through to `getErrorMessageKey` → `common.errors.badUserInput`. The rule that raw server text is never shown is deliberate and should stay.

## Fix

Add four recognizers in the same style, each interpolating only a validated short identifier or count, with new `bql.errors.*` keys in all 15 locales:

- **Ungrouped column:** `Bare column "(ident)" is not grouped and not aggregated` → "“{column}” must be in GROUP BY or inside an aggregate such as sum() or first()".
- **Unknown function:** `no function matches "(IDENT)"` → "There is no BQL function named {name}".
- **Unknown table:** `table '(#ident)' does not exist` → "There is no table named {table}. System tables start with #, such as #accounts or #prices".
- **Argument count:** `invalid arguments for function (IDENT): expected (\d+) argument\(s\), got (\d+)` → "{name} takes {expected} argument(s), not {got}".

For `type error:` messages, a single fixed key is enough ("A value has the wrong type for this comparison or function"), with no interpolation.

Also hide **Try Again** for `BAD_USER_INPUT` query errors: re-running an unchanged invalid query cannot succeed. Keep it for network and service failures. Extend `lib/__tests__/query-error.test.ts` with these exact messages.

## Blast radius

Only the Query page uses `getQueryErrorFeedback`. MCP and REST already return the engine text to agents.

## Dedupe

Available system tables`, `invalid arguments for function` and `cannot compare values`. Matches exist only in ledger-engine items under `w23/done/`, which produce these messages. **Resolved 2026-11-10** — shipped in this commit (`dashboard`).
`features/bql/lib/query-error.ts` recognizes the four engine diagnostics and
`type error:`, each interpolating only a validated short identifier or count:
an ungrouped column ("“position” must be listed in GROUP BY or wrapped in an
aggregate such as sum() or first()"), an unknown function (named in lower
case, as BQL writes it), an unknown table, a wrong argument count (a real
plural on the expected count: "length() takes 1 argument, not 2"), and a
fixed type-error message. The code tokens (`GROUP BY`, `sum()`, `first()`,
`#accounts`, `#prices`) are passed as placeholders so translators never
translate them and the stray-English locale guard stays strict. New
`bql.errors.*` keys are in all 15 locales. Try Again is gone for any
`BAD_USER_INPUT` query error (`isRetryableQueryError`) and stays for network
and service failures. Raw server text is still never shown.

Validation: `query-error.test.ts` gains the recorded production messages,
the retry rule, and two hostile shapes that must stay generic; the old
"generic" control `type error: cannot compare values` is now the type-error
case. `query-result-card-engine-errors.test.tsx` renders every case with the
real English catalog, including both plural forms, and checks Try Again; 13
of these fail against the previous code. `yarn format:check`, `yarn lint`,
`yarn test` (775 files, 7733 passed, 1 existing skip) and `yarn build` pass;

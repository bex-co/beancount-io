# Create Ledger checks the name the reader typed, not the name the server gets: a valid 100-character slug is refused, and "___" is sent to be refused

**Minor · dashboard · 20–30 minutes.** A2: Create Ledger is the first form a new user fills in. Its two name checks disagree with the server's rule (`validateLedgerName`, which judges the slug):

- The **length** check counts the raw text. Trailing spaces and dropped punctuation count against the limit, so a name whose slug is exactly 100 characters is refused with "Name must be less than 100 characters", although 100 is allowed.
- The **content** check accepts any non-empty slug. A name such as `___` or `-_-` passes and is sent, and the server refuses it with "Ledger name must contain at least one letter or number".

Mobile mirrors both rules ([w21/547](../w21/done/547.md), [w21/992](../w21/done/992.md)); this is the dashboard counterpart.

Production https://beancount.io, 2026-11-11, English, isolated headless Chromium 156 at 1440×1000, signed in. A request guard aborted the `CreateLedger` mutation, so nothing was created; the ledger list is unchanged (6 ledgers). Local main `334216be0`.

## Reproduce

Ledger switcher → **Create Ledger** → name, then **Save**:

| Name | Slug | Server | Dashboard |
| --- | --- | --- | --- |
| 100 × `a` + two spaces | 100 × `a` (accepted) | ✓ | refused: "Name must be less than 100 characters" (no request) |
| `___` | `___` | refused: "Ledger name must contain at least one letter or number" | no message; `CreateLedger` is sent (aborted here) |
| `-_-` | `_` | refused (same rule) | same as `___` (from the code; not submitted) |
| 101 × `a`, control | 101 × `a` | refused | refused ✓ |
| name `qa-guard-desc`, description of 2,049 characters (rechecked 2026-11-11 at `937b1efe6`) | — | refused: "description is 2049 characters; a ledger description can be at most 2048" (`LEDGER_DESCRIPTION_MAX`, backend-v2 `ledger-workflow.ts:171`) | no `maxlength`, no message; `CreateLedger` is sent with all 2,049 characters (aborted here) |

## Root cause

`dashboard/src/features/ledger-list/components/ledger-form.tsx:51–64` applies `.max(100)` to the raw name. Its only `refine` is `slugifyLedgerName(val).length > 0`. The server (`backend-cluster/ledger/src/shared/ledger-name.ts:49–75`) checks the slug: at most 100 characters, at least one `[a-z0-9]`, no leading or trailing `-`.

Ledger Settings' rename (`ledger-data/settings/general-settings-section/index.tsx:99–107`) already checks the slug length with `MAX_LEDGER_NAME_LENGTH`, but it misses the letter-or-digit rule as well.

## Fix

- Add a `ledgerNameIssue(name)` in `common/lib/beancount/ledger-name.ts` that returns `empty | tooLong | noLetterOrDigit | null` on the slug. Use it in Create Ledger and rename, and drop the raw `.max(100)`.
- Word the length message as "at most 100 characters in its web address", and reuse the existing `nameInvalid` text ("Use at least one Latin letter (A–Z) or digit…", w0/023) for `noLetterOrDigit`.
- Cap the description at 2,048 characters in Create Ledger and Ledger Settings (`maxLength` plus a zod `.max(2048)` with a counter near the limit), as mobile does since [w21/949](../w21/done/949.md).
- Tests: the table above, in both forms. `Café Ledger` and the w0/023 Chinese-name case keep their current behaviour.

## Blast radius

Create Ledger (switcher, `/ledger`, onboarding) and Ledger Settings rename. Server behaviour is unchanged.

**Resolved 2026-11-11** — shipped in this commit (`dashboard`).
`ledgerNameIssue` in `common/lib/beancount/ledger-name.ts` judges the slug as
the ledger service does (`empty`, `tooLong` past 100, `noLetterOrDigit`), and
both Create Ledger (`ledger-form.tsx`, replacing the raw `.max(100)`) and the
Ledger Settings rename use it: 100 × `a` plus trailing spaces is accepted,
`___` and `-_-` get the existing `nameInvalid` text and are not sent, 101 ×
`a` is still refused. `nameMaxLength` now reads "Name can be at most 100
characters in its web address" in all 15 locales. The description is capped at
`LEDGER_DESCRIPTION_MAX` (2048, counted in code points as the service counts
it) in both forms — `maxLength`, a validation message
`page.dashboard.descriptionMaxLength`, and a new `LengthCounter`
(`2,040 / 2,048`, from 90% of the limit) — and Settings disables Save past it.
Also translated the stray-English `nameRequired` in Spanish and Dutch.
Deviation: no server-refusal mapping for the description, since the field
cannot exceed the cap from the keyboard. Regression tests in
`ledger-form.test.tsx` (slug of exactly 100, `___`, `-_-`, 2049/2048
description) and `settings-rename-feedback.test.tsx` (`___`, `-_-`, a
100-character slug with trailing punctuation as a control, description cap);
seven fail against the previous forms, and `Café Ledger`-style and the
w0/023 Chinese-name cases keep passing. `yarn format:check`, `yarn lint`,
`yarn test` (8019 passed, 1 existing skip) and `yarn build` pass by exit code;
secret scan clean. Not verified against production before the next dashboard
deploy.

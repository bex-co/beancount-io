# Give the rate limiter a per-route policy hook

From w2/m28:t007 (`/simplify`), deferred as structural work beyond that milestone.

`restRateLimitMiddleware` now special-cases one mount: it knows that
`MCP_TRANSPORT_OP_ID` is MCP, that MCP bodies are JSON-RPC, and which methods are
handshake ceremony. `MCP_TRANSPORT_OP_ID` is a hand-copied route string with
nothing tying it to the actual mount.

Cost: the next transport with a handshake adds a second `if`; renaming the route
silently re-charges the handshake with no test failing; and the exemption is total,
so unlimited `{"method":"ping"}` posts cost a credential nothing at the one limiter
that is meant to be unbypassable.

Fix: let a route declaration supply `rateLimitOpId(ctx)` / `exemptFromRateLimit(ctx)`,
so the MCP mount — which already understands JSON-RPC — owns the policy and the
limiter stays "look up op, charge budget". Consider a cheap handshake budget rather
than a full bypass.

---

**Resolved 2026-09-12** — done as proposed, including the "consider a cheap handshake budget"
aside, which turned out to be the more important half.

`rate-limit.ts` now offers `setRouteRateLimitPolicy(opId, policy)`: a mount says which op a
given request spends, and the limiter is back to "look up the op, charge its budget". The
policy returns an op id and nothing else — it cannot exempt a request, because a total bypass
at the one limiter meant to be unbypassable is exactly how unlimited `{"method":"ping"}` posts
came to cost a credential nothing.

The JSON-RPC knowledge moved to `features/ai-agent/api/mcp-rate-policy.ts`, beside the mount
that already speaks the protocol. `restRateLimitMiddleware` no longer knows that one route is
MCP, that MCP bodies are JSON-RPC, or which methods are ceremony; a test asserts that without
the mount's policy the middleware charges the handshake like anything else.

The hand-copied route string is tied down: `setMcpRoute` now mounts on `MCP_ENDPOINT_PATH` and
registers its policy under `requestOpId(["POST"], MCP_ENDPOINT_PATH, "POST")` — the same helper
the limiter identifies the route with — and `mcp-rate-policy.test.ts` fails if that computed id
and `MCP_TRANSPORT_OP_ID` ever disagree. Renaming the route moves the policy with it instead of
silently re-charging the handshake.

Handshake traffic now spends `MCP_HANDSHAKE_OP_ID` at 1200/minute rather than being waved
through: generous enough that connecting never eats a session's allowance (the w2/m28
acceptance criterion — a 200-read session with no 429 — is still run, not argued), bounded
enough that a client that only pings is metered. `prompts/list` joins the handshake set, where
w2/008 put it.

`yarn typecheck`, `yarn test` (283 suites, 4426 tests), `yarn generate-v1-openapi` (no diff)
green; `yarn lint` reports only the pre-existing unused `AppLinksConfig`.
`scripts/check-agent-guidance.py` green after documenting the hook in `backend-v2/CLAUDE.md`.

Not verified live: unit tests only.

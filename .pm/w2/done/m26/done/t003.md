## Objective

Make the structured entry writer behave like Beancount: a transaction with a non-zero residual is refused unless the caller opts in, and one posting per transaction may omit its amount and be interpolated.

## Context

- The schema requires `units` on every posting (`required: ["account","units"]`), which the audit's agent run 1 called out; Beancount users elide one amount by habit.
- Balance checking must use the ledger's tolerance (`inferred_tolerance_default`, per-currency precision), not exact zero; the ledger service already knows the options.
- `allowInvalid: true` exists for legitimate cases (a user deliberately recording an imbalance to fix later).

## Steps

1. Loosen the posting schema so `units` is optional on at most one posting; reject two or more elided postings with a clear message.
2. Before writing, compute the residual per currency using the ledger's tolerance; on imbalance refuse with `{ok:false, error:{code:"UNBALANCED", message, hint:"residual 5.00 USD; add a posting or pass allowInvalid: true"}}`.
3. Add `allowInvalid?: boolean` to the input schema and document it in the tool description in one sentence.
4. Route the interpolated amount into the directive text the writer emits so the file shows the elided posting as the user wrote it.

## Acceptance criteria

- [ ] A transaction with one elided posting is accepted and written with the amount elided in the file.
- [ ] A transaction with a residual outside tolerance is refused with code `UNBALANCED` and the residual named, on MCP and REST alike.
- [ ] `allowInvalid: true` writes it anyway and t002's `newErrors` reports the residual.

## Out of scope

- Cost/price interpolation beyond simple units.
- Padding directives.

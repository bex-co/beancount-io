## Objective

Two resources advertise `{?userId}` as optional but throw a raw Zod error array without it, and three tools plus one resource leak the AWS SDK's "No value provided for input HTTP label: Bucket." when object storage is not configured. A collaborator lookup leaks "user does not exist [uid: 0, name: …]" from Gitea.

## Context

- `legacyMetadataQuery` (`legacy-metadata-handler.ts`) and `featureFlagsQuery` (`configuration-routes.ts`) require `userId`; the templates and descriptions say it is a compatibility argument that does not affect the result.
- `generateTempAssetUploadUrl`, `parseFile`, `parseReceipt`, and `assets/download-url` fail identically on a deployment without S3; self-hosters without object storage hit this on every receipt or import flow.
- `manageLedgerCollaborators.update` with an unknown username passes Gitea's message through verbatim.

## Steps

1. Make `userId` optional in both query schemas; keep the "ignored" semantics.
2. At the asset-storage boundary, translate a missing bucket/credentials into a `ConfigurationError` whose message is "Object storage is not configured on this deployment" and whose hint names the env variables from `.env.tmpl`.
3. Translate Gitea's unknown-user error into "No such user: <name>" in the collaborators workflow.
4. Add the three cases to the error-translation tests.

## Acceptance criteria

- [ ] Reading `beancount://legacy/ledger-meta` and `beancount://configuration/feature-flags` without `userId` succeeds.
- [ ] With no S3 configured, the four asset operations return the configuration message and hint; no AWS SDK text reaches the client.
- [ ] Unknown collaborator usernames return "No such user: <name>".

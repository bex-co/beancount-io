# The first-month guide never records a manual entry, the most common thing a newcomer does next

**Minor · skills · 1h · A2.** Found in the [w2/m40](../done/m40/README.md) t007 adoption check, 2026-10-19.

[`docs/skills/first-month.md`](../../../docs/skills/first-month.md) composes init → import → reconcile → ask → close on one synthetic ledger and is verified checkpoint by checkpoint by `scripts/verify-first-month.py` against `docs/examples/first-month/expectations.json`. It has no step where the user records something by hand, which `beancount-add` now covers ("I paid cash for parking", "open a savings account"). Add one short step after initialization — a cash or card purchase proposed, confirmed, and written through `beancount-add` — with its expected ledger effect in `expectations.json` and a verifier check, so the guide shows all nine skills' everyday path. Changing the journey also needs a fresh rehearsal on both clients (`docs/skills/evidence/first-month-rehearsal.md`); Codex was at its usage limit on 2026-10-19, so schedule the rehearsal when Codex is available.

A step rehearsed on one client only would make that promise false, so the change and its two-client rehearsal should land together, and Codex cannot run here: its account reported its usage limit on 2026-10-19 ("try again at Nov 17th, 2026"). A scripted run of the current guide on Claude Code (every checkpoint passed on published `bea` 0.3.1, recorded in `docs/skills/evidence/procedure-rewrite-rehearsal.md`) shows the journey can be driven turn by turn, so the rehearsal itself is cheap once Codex is back. **Unblock:** Codex usage is available; implement the step, update the expectations, verifier tests, and guide, and rehearse on both clients in the same change. **Who can clear it:** the operator who holds the Codex account.

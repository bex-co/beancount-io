# Create File and Upload accept names the server refuses ("Q1: taxes", "a?b", "con.txt", "trail."), then say only "Some of the information provided is invalid"

**Minor · dashboard · 30–40 minutes.** A2: `:` and `?` are ordinary in file names on macOS and Linux ("Q1: taxes.bean", "statement?.pdf"). Since w23/054, the server refuses names a Windows clone cannot store, and it says exactly why. In the dashboard, Save and Upload stay enabled for these names, and the refusal arrives as the generic invalid-input toast. Mobile mirrors the rule inline ([w21/565](../w21/done/565.md)); this is the dashboard counterpart, next to [w2/113](./done/113.md), which mirrored the case-twin rule.

Production https://beancount.io, 2026-11-10, English, isolated headless Chromium 156 at 1440×1000, signed in as the owner of the designated synthetic ledger. Three accepted test files (`a#b.txt`, `a%b.txt`, `a b.txt`) were deleted afterwards; the ledger is back to `main.bean` only, at blob `f1a0b83c`. Local main `dfc2a3d32`.

## Reproduce

Files → **Create File**, content `; qa`, then name and **Save** (or **Upload Files** with a file of that name):

| Name | Save / Upload | Page says | Server (`BAD_USER_INPUT`) |
| --- | --- | --- | --- |
| `qa-enc/a?b.txt` | enabled | "Some of the information provided is invalid. Please check and try again." | `contains one of <>:"\|?*, which Windows cannot store` |
| `qa-enc/con.txt` | enabled | same | `uses the Windows device name "con.txt"` |
| `qa-enc/trail.` | enabled | same | `has a part ending in a dot or a space` |
| upload `qa:up.txt` | enabled | "qa:up.txt wasn't uploaded: Some of the information provided is invalid…" | `contains one of <>:"\|?*…` |
| `main.bean/qa-sub.txt` (an existing file used as a folder; rechecked 2026-11-10 at `9a41a352a`) | enabled | "This change conflicts with the current state. Please refresh and try again." | `CONFLICT`: `main.bean is a file, not a folder` |

**Controls:** `a#b.txt`, `a%b.txt` and `a b.txt` are created, listed, opened through correctly encoded URLs (`a%23b.txt`, `a%25b.txt`) and deleted without trouble. Mobile's New File shows "Avoid < > : " | ? *, a part ending in a dot or space, and names like con or nul" with Create disabled.

## Root cause

- `dashboard/src/features/ledger-editor/create-file/validate-create-file-name.ts` (`createFilePathIssue`) checks only for empty names, null bytes, backslashes, `.`/`..`, `.git` and (since w2/113) twins.
- The server's `assertPortableRepoPath` (`backend-cluster/backend-v2/src/features/ledger/utils/safe-repo-path.ts:45–67`) also refuses control and bidi characters, `<>:"|?*`, a segment ending in `.` or a space, Windows device names, and segments over 255 UTF-8 bytes.
- `create-file/index.tsx:~200` and `upload-files/index.tsx:~209` special-case only the `CONFLICT … already exists as` twin message. Everything else goes through `formatError` → generic.

## Fix

- Add a `"portable"` issue to `createFileNameIssue`: a local copy of the server rule, as mobile's `checkLedgerFileName` (`mobile/src/screens/ledger-file-browser-screen/utils.ts:56–85`) does. Show it inline with Save disabled: "Avoid < > : " | ? *, names like con or nul, and a part ending in a dot or space."
- Apply the same check to each file staged in Upload Files, so the name is flagged before the upload starts. Offer to rename it, or skip it.
- Refuse a nested path whose folder part is an existing file (the folder listings are already loaded for the twin check), as mobile does since [w21/988](../w21/done/988.md): "main.bean is a file, so it can't hold other files." Until then, map the server's `… is a file, not a folder` `CONFLICT` to that message instead of the refresh advice. w2/113's handler covers only `already exists as`.
- Locale keys go in all 15 languages.
- Tests: the four names above are refused; `contacts.bean`, `console.bean`, `a#b.txt`, `a%b.txt` and `a b.txt` stay accepted, matching the server's own test cases.

## Blast radius

Create File (root and nested paths) and Upload Files. Existing files with such names stay readable and deletable (the server checks new paths only). Rename is not exposed in the dashboard.

**Resolved 2026-11-11** — shipped in this commit (`dashboard`). A local copy
of backend-v2's `assertPortableRepoPath` (`isPortablePath`, next to the
w2/113 twin rule in `ledger-editor/shared/lib/portable-path-key.ts`) refuses
control and bidi characters, `<>:"|?*`, a part ending in a dot or a space,
Windows device names (`con.txt`, not `console.bean`) and parts over 255
bytes. Create File reports it as a new `"portable"` name issue with Save
disabled; Upload Files flags each staged file so named, says "Remove files
whose names Windows can't store to upload" and keeps Upload disabled (the
existing remove button skips the file). The message reads "Avoid < > : " |
? *, names like con or nul, a part ending in a dot or space, and parts over
255 bytes", with the device names as untranslated placeholders. A refusal the
client cannot foresee is mapped too: the server's portable refusals, and its
`… is a file, not a folder` `CONFLICT` ("main.bean is a file, so it can't
hold other files"), in both the Create File toast and the upload's stopped-at
alert, instead of the generic or refresh advice. Three new keys in all 15
locales.

Not done: refusing a nested path whose folder part is an existing file
before saving (the listing has names, not types); the server's refusal is
explained instead. Rename-on-upload was not added.

## Objective

A `--rules` TOML rule may set t001's key alongside `account`, so a repeat CSV import attributes matching rows without review-time typing.

## Context

- `cli/src/bea_engine/csv_mapper.py`: `CsvRule` accepts `match` and `account`, and `_refuse_unknown_rule_keys` refuses anything else.
- `cli/` checks run with `make check-all`; customers on the published minimum keep working (`SKILLS_BEA=published` CI leg).

## Steps

1. Add the optional key to `CsvRule`, validated like `account`.
2. Write it on matched rows in preview and apply.
3. Document it in `skills/beancount-import/references/bea-import.md` and the CLI docs, with a Version note in `skills/beancount-init/references/bea-cli.md` naming the first `bea` release that carries it.

## Files

- `cli/src/bea_engine/csv_mapper.py` and its tests
- `skills/beancount-import/references/bea-import.md`
- `skills/beancount-init/references/bea-cli.md`

## Acceptance criteria

- [x] A rule with the key writes it on matched rows and the preview shows it; an unknown rule key still refuses.
- [x] `make check-all` passes in `cli/`.
- [x] On the published minimum the skill works without the key, as its Version note says.

## Out of scope

- Rules that set arbitrary metadata.

## Result

A `--rules` entry may now set `client` and `project` (non-empty strings, no control characters, NFC), validated identically by the frontend (`cli/src/cli/csv_mapper.py`) and the engine (`cli/src/bea_engine/csv_mapper.py`). The engine copies them as transaction metadata onto every CSV and OFX row the rule matches; unmatched rows carry none, and any other rule key is still refused, now naming the optional keys. Documented in `cli/docs/IMPORTING.md`, `skills/beancount-import/references/bea-import.md` and `categorization.md`, with a `bea-cli.md` Version note: published 0.3.1 refuses the keys, so there attributed rows keep the batch path. Tests: `cli/tests/test_import_rule_attribution.py` (preview, apply, one key alone, refusals; two fail when the engine's metadata copy is removed), an OFX case in `test_import_ofx.py`, and the updated message in `test_rules_unknown_keys.py`. `make check-all`: lint, deadcode, format, typecheck, and docs-check pass; 10,929 tests pass with one load-sensitive timeout (`test_release.py::test_customer_smoke_runs_against_the_installed_cli`, 120 s under the full suite, passes alone in 44 s); `spec-check` fails identically on clean `main` (backend OpenAPI snapshot ahead of the CLI pin), unrelated to this change.

## Reproduce and working controls

1. Open valid `beancount:///ledger/open_ledger/stock-example`, wait for Home, then open the inspected native Merchants destination `beancount:///(app)/merchants`. Tap the actual **Broker** row, **12 transactions**.
2. Settled Broker header shows **$2,104.35**, **Jan 8, 2024 – May 12, 2026**. The actual signed per-currency total is **−2104.35 USD**. Terminate/relaunch, reopen Merchants and tap Broker again: the same unsigned header returns. The development warning lies below it and does not cover the value.
3. Select `open_ledger/example` through its valid public ledger link, wait for the destination, then open Merchants. Search **Hoogle** and tap its actual result. Header shows **71 transactions**, **54,500.00 IRAUSD**, **$182,014.14**, **355.00 VACHR**, **Jan 1, 2015 – Sep 7, 2017**. Dismiss the development warning and recheck: both negative totals have lost their signs, while the positive IRAUSD total is correct.
4. Working expense control: Back, replace search with **Cafe**, tap **Cafe Modagor** (**44 transactions**). Header correctly shows **$1,535.16**, **Feb 11, 2015 – Sep 8, 2017**. Preserve this positive-total display and the correct counts/date spans.

Independent anonymous GraphQL `queryShell` controls at `/api-gateway/` return HTTP 200 without errors using the application's exact statements: metadata counts over `FROM #entries`, and `SELECT currency, sum(number) as total WHERE payee = '<payee>' AND (account ~ '^Expenses' OR account ~ '^Income') GROUP BY currency ORDER BY currency`. Real rows are:

| Public ledger / merchant | Signed API totals | Native header |
| --- | --- | --- |
| Stock / Broker | USD **−2104.35** | **$2,104.35** |

Do not require Broker's sale cash receipts to equal its net expense/income total or sum different currencies together. Counts, dates, currency separation and amounts' magnitudes are correct; the presentation discards direction. Native wire requests were not captured.

## Cause, repair and scope

`mobile/src/screens/merchant-detail-screen/selectors/merchant-stats.ts:44–56` explicitly produces signed totals. The header at `merchant-detail-screen.tsx:469–472` passes each total to `formatMoneyWithCurrency`. `src/common/number-utils.ts:142–145` intentionally formats unsigned money, using `groupThousands`'s absolute value at 68–70. The sign reaches the component and is lost only there.

Use the existing `formatSignedMoneyWithCurrency` with `includePlus = false` for these header totals. Broker becomes **−$2,104.35**; Hoogle retains **54,500.00 IRAUSD** and shows **−$182,014.14**, **−355.00 VACHR**. Positive Cafe remains **$1,535.16**; zero remains unsigned. Preserve the query's signed accounting convention, separate currencies, symbol/code fallback, rounding, header layout and accessibility text. Keep the globally unsigned formatter unchanged: other account/category surfaces deliberately choose absolute figures. No API, dependency or cross-package change is needed.

The shared formatting call has one merchant-header production site. Native `/merchant-detail` is reached from Merchants via its selected payee; all positive/negative currency rows pass through the same map. No guest merchant alias exists. Transaction rows and detail use separate selectors and already preserve their cash-flow signs; changing them cannot repair this header. Loading skeleton, honest no-match/empty states, query-error handling and recurring overrides must remain unchanged.

Acceptance: rerun the fresh Broker and actual Hoogle/Cafe native journeys above with the expected signed totals, counts and date spans intact. Add meaningful presentation coverage for negative USD and a symbol-less commodity, positive and zero totals, preserving separate mixed-currency rows; selector-only tests cannot catch a sign stripped after selection. Check enlarged-text/accessible values retain the minus, then run mobile gates when implementing. No product fix implemented by this QA run.

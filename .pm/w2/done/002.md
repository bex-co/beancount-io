# Scoping spike: beancount-tax estimation via deterministic engines

Quarterly tax estimation from ledger data by orchestrating deterministic open-source engines (tenforty, PolicyEngine, opentax-engine) — the LLM extracts and routes, the engine computes. Column Tax's TaxCalcBench shows frontier LLMs get only 23–42% of even simplified federal returns right, so raw LLM tax math is disqualified by design. Estimation only — never filing (e-file licensing wall). Spike outcome (~1h): pick an engine, define the ledger→engine input mapping for a US W-2 + brokerage prosumer, go/no-go; promote to a milestone if go.

## Spike outcome (2026-07-31) — **GO**

- **Engine pick: tenforty** (Python wrapper over OpenTaxSolver). Verified locally: `pip install tenforty` + `evaluate_return(year=2024, filing_status="Single", w2_income=120000, taxable_interest=500, qualified_dividends=2000, long_term_capital_gains=5000)` → total_tax 19,508.50, federal effective rate 17.3%. Deterministic, offline, federal + major states. PolicyEngine-US as a cross-check second engine; Invaro/opentax-engine as a watch item (claims 96% on TaxCalcBench but younger).
- **Ledger→engine mapping** (BQL per input): `w2_income` ← `Income:Salary` (caveat: W-2 box 1 differs from gross by 401k/pre-tax — skill must ask for the adjustment or the actual W-2 figure); `taxable_interest` ← `Income:Interest`; dividends ← `Income:Dividends` (qualified/ordinary split isn't in the ledger — ask, or default with a stated assumption); ST/LT capital gains ← `Income:Trading:CapitalGains` split by holding period (the options skill's per-lot data supports this; wash sales out of scope v1, flagged); estimated payments already made ← `Expenses:Taxes:…`/`Assets:…` postings.
- **Engine-year lag is acceptable**: OTS ships a tax year after year-end, so current-year quarterly estimates run on prior-year rates — which is exactly the IRS safe-harbor convention anyway; the skill states the basis.

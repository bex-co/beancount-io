## Objective

Tell a reader of the MCP guide how the hosted server appears in the official registry and how its listing is published, and record in ADR 019 that this registry is the first marketplace and why.

## Context

- `backend-cluster/backend-v2/docs/mcp.md` has "Connect a client" (Personal API key, OAuth) and "Deployment and diagnostics" (env vars, conformance). Claude Code and Codex do not browse the registry; their path stays the hand-configured URL already documented there.
- ADR 019 lists "Submitting directory listings" as a non-goal, leaves "Which directory comes first" open, and has an "Implementation status (2026-09-25)" table. ADR 0007 D1 fixes the single endpoint every listing names.

## Steps

1. In `docs/mcp.md`, add `### From the MCP Registry` at the end of "Connect a client": the listing name, that it names only `https://beancount.io/api-gateway/mcp` so sign-in is the OAuth flow above, that a self-hosted deployment is not listed and is configured by URL, and a `curl` of the registry API to inspect it.
2. Under "Deployment and diagnostics", add `### Publishing the registry listing`: where `server.json` lives, `MCP_REGISTRY_AUTH_PROOF` and how the record is produced (OpenSSL 3; macOS LibreSSL lacks Ed25519), the `Publish (mcp registry)` workflow, the `mcp-registry-publish` environment and `MCP_REGISTRY_PRIVATE_KEY`, the version-bump rule, DNS TXT as the alternative, and verification commands.
3. In ADR 019: add an `## Amendments` entry dated 2026-10-02 stating that the official MCP Registry listing goes first and why (depends on none of D3–D9; names D1's URL; aggregators read it; proof over HTTP via ADR 0009's path); update the "Which directory comes first" open question to point at it, leaving the order among Claude, ChatGPT, and Muse open; add a pointer after the "Submitting directory listings" non-goal; add a "Listing" row to the implementation-status table.

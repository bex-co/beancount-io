## Objective

Make `GET /.well-known/mcp-registry-auth` return the configured proof record so the official MCP Registry can verify that a publish under `io.beancount/*` comes from whoever controls `beancount.io`, answering 404 when nothing is configured and refusing a malformed value when configuration loads.

## Context

- Follow the native app-link pattern: `AppLinksConfig` in `src/config/config.ts` reads `APP_LINKS_*`, and `well-known-route.ts` answers 404 when unset so a self-host does not advertise Beancount.io's identifiers. The same reasoning applies here: a self-host serving Beancount.io's public key would let Beancount.io publish under that domain's registry namespace.
- The registry parses the record with `v=MCPv1;\s*k=([^;]+);\s*p=([A-Za-z0-9+/=]+)` (`internal/api/handlers/v0/auth/common.go`); algorithms are `ed25519` and `ecdsap384`. `mcp-publisher`'s documentation emits the whole line, so the environment variable holds the whole record, not just the key.
- `src/server/api/always-public.ts` is the census of REST mounts outside the scope gate; `__tests__/always-public.test.ts` fails on an uncensused mount or a reason under 40 characters.
- `src/server/api/rate-limit.ts` already buckets any path containing `/.well-known/` under the shared `oauth` budget — no change needed.
- Other `config.ts` values throw at load on invalid input (see the URL checks), so a malformed record should too, with a message naming the variable and the expected shape.

## Steps

1. Add `McpRegistryConfig { authProof: string | null }` to `AppConfig`, read from `MCP_REGISTRY_AUTH_PROOF` (trimmed, empty → `null`), and throw when a non-empty value fails `^v=MCPv1; k=(ed25519|ecdsap384); p=[A-Za-z0-9+/]+={0,2}$`. Keep the parser a small exported function so it is unit-testable without reloading the module.
2. Register `GET /.well-known/mcp-registry-auth` in `well-known-route.ts`: `text/plain`, `Cache-Control: public, max-age=3600`, body is the record plus a trailing newline; 404 when `authProof` is null, with a comment stating the self-host reasoning.
3. Add the census entry `REST GET /.well-known/mcp-registry-auth` to `always-public.ts` with a reason that says why it is anonymous (the registry fetches it before any credential exists).
4. Tests in `well-known-route.test.ts`: 200 with the exact body and content type when configured; 404 in the unset-config block. A config test for the parser: accepts an ed25519 and an ecdsap384 record, rejects a bare key and a wrong prefix.
5. Add an `MCP_REGISTRY_AUTH_PROOF=` block to `backend-cluster/backend-v2/.env.example` after the native app links block, saying unset → 404 and why a self-host leaves it unset.

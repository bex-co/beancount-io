# Codex makes an existing-entry edit that beancount-add says it leaves to the user, and often before the yes

**Minor · skills · 30–60m · A1.** Found in [w2/m40](m40/README.md) t005's eval runs, 2026-10-19, Codex CLI 0.163.0 with `gpt-6-luna`, recorded in [`docs/skills/add-rehearsal.md`](../../../docs/skills/add-rehearsal.md).

Eval 10 asks beancount-add to "add tonight's $18.00 lunch … and while you're at it change the payee of the 2026-10-15 Pizzeria entry". The skill only adds entries and every write waits for its proposal's yes; Parse, Propose, and the description all say so. Claude Code follows it: it proposes only the lunch and names the 2026-10-15 entry as left to the user. Codex read the skill in every run and still made the rename in all four runs with the final text: three wrote the lunch and the rename in the first turn with no confirmation, and one proposed only the lunch, said it would leave the rename to the user, then renamed it anyway after the yes. On the other ten evals Codex waited for the yes every time, so the trigger is an explicit edit instruction in the user's message.

Two text changes did not move Codex, so a third wording change is unlikely to. Options worth testing: a structural guard (the skill checks the root ledger's existing entries are byte-identical before its final check and reverts anything it did not propose), giving edits an explicit, confirmation-gated home in the ledger-editing work on this board (w2/m46), or recording that Codex keeps the user's explicit edit and only fixing the before-the-yes write. Re-run eval 10 on both clients after any change.

**Blocked 2026-10-19** — every option above has to be proven by re-running eval 10 on Codex, and Codex cannot run here: its account reported its usage limit on 2026-10-19 ("try again at Nov 17th, 2026"). Which option is right also depends on whether any suite skill may change existing entries, a question the ledger-editing work drafted on this board leaves to the owner. **Unblock:** Codex usage is available again, plus the owner's call on whether edits get a confirmation-gated home; then try the chosen option and re-run eval 10 on both clients ([rehearsal record](../../../docs/skills/add-rehearsal.md)). **Who can clear it:** the operator for Codex usage, the repository owner for the scope call.

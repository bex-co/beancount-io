## Cause and bounded repair

`mobile/src/screens/account-detail-screen/selectors/select-account-journal.ts:274–282` chooses one `operatingKey(item.change,currency)` and uses it for **both** `amountIn(item.change,key)` and `amountIn(item.balance,key)`. `common/balance-util.ts:53–59` correctly falls back to USD when its particular map lacks the operating currency. For an empty MRMB change map this resolves USD; the separate running-balance map contains MRMB and no USD, so reading it with that borrowed key yields0. Nonzero MRMB transactions and USD assertion rows work, as reproduced above.

Resolve each map's currency key independently using the existing `operatingKey` and `amountIn`, retaining the maximum recorded scale of the two resolved amounts. Keep the established per-map USD fallback; do not infer the running balance from an entry's change, its assertion target, another row or the current account header. The units branch already reads its explicit commodity key and is outside the money-branch repair. Preserve signs, decimal precision, directive labels, date totals, pagination and transaction navigation. No global formatter, backend, schema, dependency or cross-package change is needed.

Acceptance: the three native Alibaba June30 rows retain zero change while displaying−532257MRMB, agreeing with the API and adjacent transaction; the Alphabet USD assertion control remains unchanged. Extend the existing selector suite with an empty change plus nonzero non-USD balance, a sparse-zero transaction, independent per-map USD fallbacks, negative balances and recorded three-decimal scale. Check actual row/section formatting as appropriate; the date total remains zero. Preserve the existing MUSD423.284/930.904 precision and unit-valued account cases, then run mobile gates and repeat the native controls.

Blast radius: one `selectAccountJournalRows` production consumer, `account-detail-screen.tsx:254–260`; `components/account-entry-row.tsx:101–103,148–149` formats the resulting balance. Any non-USD operating-currency money journal with an empty/sparse change map can take this branch. Balance directives are live-proven; Pad, Note and zero-net transactions are source-traced acceptance cases, not separately reproduced. Home totals, Accounts totals, the detail's chart/header and API balances remain correct.

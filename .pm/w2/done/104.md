# Ledger Gallery stops at 50 matches and announces them as the whole result

**Minor · dashboard · 40–55 minutes.** A3: the `open_ledger` showcase that docs and posts link to now holds well over 150 ledgers, and the Gallery promises to "discover and explore all available ledgers".

Production https://beancount.io, 2026-11-10, English, isolated headless Chromium 156 at 1440×1000, signed in (the Gallery requires sign-in). Local main `c52b750fb`. Read-only. Reproduced from fresh loads and from typing.

## Reproduce

1. Open `/ledger-gallery?q=open_ledger`.
2. Scroll the results list to its end.

**Actual:** the list ends at the 50th match, `open_ledger/charles-schwab`, with no hint that more exist. The polite status reads **"50 ledgers found"**. A ledger such as `open_ledger/ge-aerospace` cannot be reached from this query; it is only findable by typing a narrower name.

**Control:** the same `SearchLedgers` call already reports that the page is partial:

| Variables | Rows | `extensions.page.searchLedgers` |
| --- | --- | --- |
| `q:"open_ledger", limit:50` | 50, last `charles-schwab` | `{"returned":50,"limit":50,"page":1,"hasMore":true,"nextPage":2}` |
| `… page:2` | 50, last `ge-aerospace` | `hasMore:true, nextPage:3` |
| `… page:3` | 50, last `mccormick` | `hasMore:true, nextPage:4` |
| `q:"stock", limit:50` | 1 | `hasMore:false` — the Gallery's "1 ledger found" is correct |

**Expected:** when more matches exist, the Gallery either loads them (a continuation that requests `nextPage`) or says that only the first 50 are shown and the search should be narrowed. In both cases the status must not claim the first page is the full result.

## Root cause

`dashboard/src/features/ledger-list/pages/gallery-page/index.tsx:164-170` sends `SearchLedgers` once with `limit: 50` and no `page` (unchanged since the dashboard import, `af5339de0`). Lines ~464-475 announce `searchResults.length` as `page.gallery.ledgersFound`. The `hasMore` / `nextPage` signal added to every paginated read in `843896962` (w23/m28, 2026-11-07; `backend-cluster/backend-v2/src/server/api/page-signals.ts:100`) is never read.

## Fix

- Add a "Show more" continuation to the results list using the existing `common/components/continuation-control.tsx` (as commits and social lists do). Request `page: n + 1` and append the results. Decide `hasMore` from `extensions.page.searchLedgers.hasMore` when present, otherwise from a full page (`length === limit`).
- When more remain, announce "Showing the first {count} ledgers — more available" (new plural key in all 15 locales) instead of `ledgersFound`. Keep the exact count once the last page is loaded.
- Keep keyboard result navigation and Escape behaviour from w3/163, w4/976, w4/208 and w4/287 working across appended pages.

## Blast radius

Only the Gallery calls `SearchLedgers` in `dashboard/src`. Mobile has the operation in its generated schema only. The ledger switcher uses `listLedgers`, whose truncation is w2/m34's (blocked on deploy) and is not this item.

## Dedupe

Searched `.pm/**` for `SearchLedgers`, `ledger-gallery`, `ledgers found`, `limit 50`: w3/475 added the count announcement (correct for complete results); w4/208, 211, 212, 287, 976 and 1038 cover keyboard, IME and retry behaviour; w2/m34 covers `listLedgers`. None covers a partial search page.

**Resolved 2026-11-10** — shipped in this commit (`dashboard`). The Gallery's
results popup now ends with the shared `ContinuationControl`, outside the
listbox: a full first page of 50 offers **Show more ledgers**, which requests
`page: n + 1` and appends the ledgers (deduplicated by id) until a short page
ends the list with "No more results". While more remain, the polite status
reads "Showing the first {count} ledgers — more available" (new plural key in
all 15 locales); the exact "{count} ledgers found" returns once the last page
is loaded. Later pages, their pending request and their failure belong to the
query they were sent for, so a late page never joins another search. A failed
page keeps the loaded results and offers Try Again for the same page. Arrow
keys and Enter reach appended ledgers from the field; finishing the list from
the keyboard returns focus to the field, and Escape on Show More closes the
list there too.

Deviation: `hasMore` comes from a full page (`length === limit`), as the
social lists do. No dashboard code reads response `extensions`, and the API's
`extensions.page.searchLedgers.hasMore` agrees with a full page in every
observed row, so a result of exactly 50 costs one extra request that returns
empty.

Validation: `gallery-page-continuation.test.tsx` (5 cases, real router and
Apollo client) fails 4 of 5 against the previous component; all 35 Gallery
tests pass with the fix. `yarn format:check`, `yarn lint` (typecheck,
dead-code and translation checks), `yarn test` (771 files, 7678 passed,
1 existing skip) and `yarn build` pass; secret scan clean. Not verified
against production; the deployed Gallery changes on the next dashboard deploy.

## Objective

Add the Dashboard's authorization start and callback flow so the bearer token is exchanged and stored on the server side without entering browser JavaScript.

## Context

- TanStack Start provides server-only handlers/functions suitable for the callback and cookie write.
- Public Vite variables cannot contain a client secret, access token, PKCE verifier, or signing material.
- The existing Mobile OAuth flow validates state, issuer, resource, endpoints, PKCE, and callback shape and provides useful parity expectations.

## Steps

1. Start authorization with code + S256 PKCE and bind state, verifier, selected issuer, safe `next`, and expiry in a short-lived secure server-side/HttpOnly transaction cookie.
2. Validate callback multiplicity, state, `iss`, redirect, age, endpoint origin/path, and resource before exchanging the one-time code from a server-only boundary.
3. Store the access token only in the secure HttpOnly auth cookie, consume the transaction state exactly once, and keep tokens/verifiers out of URLs, logs, analytics, HTML, and client storage.

## Files

- `dashboard/src/features/oauth/**`
- `dashboard/src/routes/oauth*.tsx`
- `dashboard/src/config/**`
- Dashboard server-function and cookie utilities

## Acceptance criteria

- [ ] A successful callback writes the OAuth cookie and redirects only to a validated same-origin path.
- [ ] Replay, stale state, issuer/resource mismatch, duplicate parameters, wrong callback, and failed exchange write no credential.
- [ ] Neither the access token nor PKCE verifier is observable to browser JavaScript or emitted by logs/analytics.
- [ ] The flow works with SSR and issuer path prefixes in production and self-hosted deployments.

## Out of scope

- Browser `localStorage`/`sessionStorage` token persistence or an implicit/password OAuth grant.

## Objective

Prove the Dashboard OAuth protocol, one-year client-specific TTL, authorization ceiling, browser isolation, and mixed-version rollout with behavioral tests.

## Context

- Happy-path component tests cannot detect an audience/client mix-up, callback replay, SSR cookie leak, or delegated OAuth privilege widening.
- The Mobile and MCP contracts are release-sensitive regression boundaries.

## Steps

1. Cover password, OTP, magic link, PKCE start/callback, safe redirect, SSR/CSR identity, agent request, logout, expiry, existing-session upgrade, and rollback behavior.
2. Add failure tests for state/issuer/resource/client/redirect mismatch, replay, stale transaction, malformed token response, missing scopes, cookie flags, off-origin endpoints, and token/log/HTML leakage.
3. Assert exact Dashboard 365-day access expiry, unchanged one-hour non-Dashboard access expiry, first-party-only PDP/consent authority, and unchanged Mobile `/v1` plus MCP/DCR flows; run full package gates.

## Files

- Dashboard auth/OAuth/Apollo tests
- backend OAuth/identity/PDP/consent tests
- path-prefixed and mixed-version protocol fixtures

## Acceptance criteria

- [ ] Mutating the Dashboard client ID, audience, 365-day TTL, redirect, cookie flags, or PKCE/state validation fails the suite.
- [ ] A test that substitutes Mobile, MCP/DCR, API-key, or unknown OAuth identity for Dashboard is denied.
- [ ] Existing-session and current Mobile clients remain usable during the compatibility window.
- [ ] Dashboard format/lint/test/build and backend format/lint/typecheck/build/test/model checks pass without tautological assertions.

## Out of scope

- Arbitrary coverage-number chasing or weakening tests to accept multiple credential contracts.

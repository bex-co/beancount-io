## Objective

Make every normal Dashboard authentication completion and authenticated transport consume the first-party OAuth cookie while preserving the current user experience.

## Context

- Password login, OTP signup, and magic-link callback currently finish by consuming a session token returned from GraphQL.
- CSR Apollo sends cookies directly; SSR Apollo reads `authSess:beancount.io` and forwards it as a bearer.
- Protected routing derives authentication from the root `userProfile`, and Dashboard agent requests must follow the same credential path.

## Steps

1. Funnel password, OTP signup, magic-link callback, and post-auth safe redirects through the OAuth bootstrap/callback without adding an extra user-visible consent ceremony.
2. Update CSR Apollo, SSR Apollo, REST/agent calls, identity probes, protected-route handling, and unauthenticated-error behavior to use the OAuth cookie consistently.
3. Preserve account/ledger initialization, cache isolation, locale/navigation behavior, legacy native bridge requirements, and public password-reset/forgot-password flows.

## Files

- `dashboard/src/features/auth/**`
- `dashboard/src/common/apollo/**`
- `dashboard/src/common/lib/auth/**`
- `dashboard/src/routes/auth*.tsx`
- affected agent, profile, settings, and account initialization code

## Acceptance criteria

- [ ] Every successful Dashboard sign-in/signup path ends with the first-party OAuth identity and the same safe destination as before.
- [ ] SSR and hydrated CSR resolve the same user without exposing or duplicating the token.
- [ ] Protected GraphQL, REST, streaming agent, account deletion, billing, profile, and credential-management calls retain intended behavior.
- [ ] Public pages and authentication failures do not create redirect loops or leak another account's Apollo state.

## Out of scope

- Redesigning login/signup UI or changing ledger onboarding product behavior.

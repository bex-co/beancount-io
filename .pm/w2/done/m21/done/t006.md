## Objective

Roll the Dashboard credential over without a flag-day sign-out and make logout/expiry behavior accurate for the requested long-lived self-contained bearer.

## Context

- Valid legacy Dashboard sessions may live for a year and must not be invalidated by the OAuth cutover.
- Current logout revokes a persisted session row; a copied self-contained OAuth access token remains valid until its 365-day expiry.
- Dashboard OAuth must remain able to bootstrap Mobile, Discourse, and MCP consent after the legacy session is gone.

## Steps

1. Add a bounded compatibility/upgrade path for existing session cookies and define the dated condition for retiring legacy Dashboard issuance and verification.
2. Make logout clear Dashboard OAuth state, transaction cookies, browser provider state, Apollo/cache identity, and analytics identity without falsely reporting copied-token revocation.
3. Exercise expiry, password reset, account deletion, credential compromise/issuer-key response, rollback, and concurrent-tab behavior; preserve Mobile and MCP grants throughout rollout skew.

## Files

- `dashboard/src/features/auth/pages/logout-page/**`
- Dashboard session/cache/cookie utilities
- `backend-cluster/backend-v2/src/features/auth/**`
- `backend-cluster/backend-v2/src/features/oauth/**`
- rollout documentation and tests

## Acceptance criteria

- [ ] A valid pre-cutover Dashboard session remains usable or upgrades without asking the user to sign in again.
- [ ] Logout reliably clears local/browser authority and makes the one-year copied-token limitation explicit.
- [ ] Expired, malformed, wrong-client, wrong-audience, and rolled-back credentials fail closed without refresh loops.
- [ ] Current Mobile sign-in/refresh/revoke and MCP/DCR behavior remain unchanged across mixed-version deployment order.

## Out of scope

- Claiming immediate access-token revocation or keeping an undated permanent legacy-session fallback.

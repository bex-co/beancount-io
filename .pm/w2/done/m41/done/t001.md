## Objective

Choose and declare the minimum `bea` version the suite supports, and move every version-specific caveat into one section of `bea-cli.md` with the version range it applies to.

## Context

- The rehearsals and the migration overlap steps rely on `bea` 0.3.1 (`skills/AGENTS.md`; `import-id-2` matching first ships there). `skills/docs/installation.md` mentions 0.3.0 for the first-month guide.
- Caveats now spread across skills and references: older batch schemas needing explicit cost numbers (`bea-cli.md`), `list` defaulting to 50 rows, optional libmagic (`beancount-import`, `beancount-importer-author`), `bea ingest` rejecting `--json`, and cache and sign memory notes (`beancount-import/references/bea-import.md`).

## Steps

1. Pick the minimum from what the suite's recipes and tests require, and state it in `bea-cli.md` with a one-time `bea --version` check and the upgrade command.
2. Create a `## bea version notes` section (name as fits) listing each caveat and its version range.
3. Make `skills/README.md` and `skills/docs/installation.md` state the same minimum.
4. Add a `ci-check.py` rule that reads the minimum from `bea-cli.md` and fails when either surface states a different one.

## Files

- `skills/.claude/skills/beancount-init/references/bea-cli.md`, `skills/README.md`, `skills/docs/installation.md`, `skills/scripts/ci-check.py`

## Acceptance criteria

- [x] One stated minimum, identical on all three surfaces, and `ci-check.py` fails when they disagree.
- [x] Every caveat the tasks move has a version range or is marked as current behavior.

## Out of scope

- Raising the minimum beyond what users can install from PyPI and the Homebrew tap today.

## Result

Minimum `bea` 0.3.1, the current release (`cli-v0.3.1`), and the version where `import-id-2` matching first ships. `bea-cli.md`'s preamble now checks `bea --version` once, says the suite needs 0.3.1 or later, and suggests `bea upgrade` (present since 0.2.0) for an older install. A new `## Version notes` section lists each version-dependent behavior with the version it describes: the minimum, batch cost needing explicit number and currency, `list` pages of 50, `bea ingest`'s native output, optional libmagic, CSV import not remembering sign, and `add close` writing over a balance. The inline mentions in the contract point there. `skills/README.md` and the install guide state "0.3.1 or later". New `check_bea_minimum()` in `ci-check.py` reads the minimum from the contract and fails when the Version notes, the catalog, or the install guide state another version or none; drifting either doc to 0.3.0 fails it. Verified against the published `beancount-io==0.3.1` (via `uvx`), not only the checkout: the batch-cost caveat is true for the release (both `{}` and `number_total` are rejected) even though `main` already accepts them, so it stays; every `beancount-add` behavior holds on the release. That gap between the checkout's `bea` and the release is filed as [w2/093](../../093.md). `ci-check.py` and `test_beancount_skills.py` (110/110) pass.

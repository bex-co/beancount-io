## Objective

Add canonical billing actions, credential requirements, denial behavior, and audit class to the one executable PDP catalog while preserving each transport operation's risk budget.

## Context

- Billing is currently `session-only` plus resolver-local `assertSessionIdentity` checks, but an op class is an operational budget/legacy-audit class rather than the credential policy for a PDP-routed action.

## Steps

1. Inventory every protected billing alias and map it to one canonical action in the TypeScript requirement catalog; classify static tier quotas explicitly as public.
2. Encode accepted credential methods, legacy capability ceiling, relationship, audit class, and any actionable denial in that catalog; preserve `op-class.ts` rate classes and overrides separately.
3. Update `.fga` and its tests only if `user.billing` relationship semantics change; keep credentials, operations, and Stripe facts out.

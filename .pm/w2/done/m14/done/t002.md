## Objective

Make protected public billing application-service methods accept the resolved `Identity` and call the PDP once before Stripe access or local billing work.

## Context

- Resolvers are transport adapters, not final PEPs; a workflow is warranted only where billing already coordinates multiple services.
- Stripe ownership and product filtering are business checks and must remain intact after authorization.

## Steps

1. Put authorization in protected public service/workflow methods and derive the User resource from the authenticated stable ID.
2. Pass `Identity` explicitly and keep the transport operation ID in isolated AsyncLocalStorage rather than a request wrapper or service parameter.
3. Remove only superseded authorization checks after parity; preserve cached status, product filters, Stripe binding, and paid-customer behavior.

## Files

- `backend-cluster/backend-v2/src/features/stripe/**`
- `backend-cluster/backend-v2/src/server/api/authorization/**`

## Acceptance criteria

- [x] Every protected entry surface reaches the same protected method and one final PDP call before Stripe/local work; public tier quotas bypass both identity and PDP by design.
- [x] Existing session users see unchanged billing behavior.
- [x] API-key/OAuth behavior does not broaden for protected billing operations.
- [x] Direct protected service calls remain authorized and audit under the canonical-action fallback.

## Out of scope

- Stripe webhook authentication, generic billing refactors, and pricing changes.

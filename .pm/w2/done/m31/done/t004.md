## Objective

Serve each managed feed from a cache that refreshes on a time-stamp schedule, keeps the last validated revision through any failure, and collapses concurrent loads into one fetch per URL.

## Context

- ADR 015 section 5: blob key `ledger:price_feed_blob_v1:<sha256(url)>:<revision>` (24h), head key `ledger:price_feed_head_v1:<sha256(url)>` (24h) with `nextRefreshAt` and `lastError`; success re-arms five minutes ahead, failure one minute ahead; `lock` keyed by URL.
- `src/shared/cache/` provides `CacheHelper`, `CACHE_KEYS`, `TTL`; `src/shared/lock` provides the async lock the file-map cache already uses.

## Steps

1. Add `priceFeedBlob` and `priceFeedHead` to `CACHE_KEYS.ledger` and `MIN_1` is already present in `TTL`.
2. Create `managed-price-cache.ts` with `resolveManagedPriceFeed(url, deps)` where `deps` carries the cache helper, config, clock, and fetch; it returns `{ text, revision, etag, feed, fetchedAt, nextRefreshAt, lastError }` or `{ unavailable: true, lastError }`.
3. Implement: head hit inside the window returns the blob; window elapsed acquires the lock, re-reads the head, sends a conditional GET, handles 304 and 200 and failures per the ADR, deletes the superseded blob after repointing.
4. Add `requestManagedPriceRefresh(url, deps)` that sets `nextRefreshAt` to zero without touching the blob.
5. Unit-test with an in-memory cache and a fake clock: first load fetches, second load inside the window does not, third after the window sends `If-None-Match`, 304 advances timestamps, 200 with a new ETag swaps the blob and deletes the old, timeout keeps the old blob and records the error with a one-minute retry, an invalid body keeps the old blob, ten concurrent loads produce one fetch, and a missing blob after a head hit falls back to a fetch.

## Acceptance criteria

- [x] No code path deletes or overwrites a validated blob because of a failed or invalid refresh.
- [x] Refresh timing depends only on `nextRefreshAt`, so an expired Redis key is a cache miss and not a policy change.
- [x] Concurrent callers for one URL share a single in-flight fetch.

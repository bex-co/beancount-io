## Objective

Prove the feature end to end on the running `deploy/dev-sandbox` stack (dashboard on port 42610) without committing code, so the user can review the real result before shipping.

## Context

- The ledger service in that stack is built from `backend-cluster/ledger/Dockerfile`; rebuild with `docker compose build ledger && docker compose up -d ledger` from `deploy/dev-sandbox/`.
- Gitea on port 42612 holds the ledgers; a ledger with `2025-01-01 open Assets:Crypto:BTC BTC` plus a 0.5 BTC purchase and the BTC-USD include is the fixture.

## Steps

1. Rebuild and restart the ledger container with the working-tree code.
2. Create or update a ledger through the dashboard or Gitea that holds BTC and includes the feed URL.
3. Open the balance sheet with USD conversion and confirm the BTC holding is valued at the feed's latest price; confirm `/errors` is empty.
4. Check the ledger logs for one fetch on first load and none on an immediate reload.
5. Temporarily point `MANAGED_PRICE_ORIGINS` at an unreachable origin or block the network, reload, and confirm the previous prices still serve with the error logged; restore.
6. Confirm the Gitea repository has no new commit.

## Evidence (dev-sandbox, 2026-09-15)

- Rebuilt `beancount-io/ledger:dev-sandbox` from the working tree twice (before and after the simplify pass) and restarted only the ledger container; the stack's Redis had a corrupted append-only file unrelated to this work, repaired with `redis-check-aof --fix` after backing it up to `deploy/dev-sandbox/tmp/redis-aof-backup-20260915015106/`.
- Signed up the dashboard user `pricedemo`, created `my-book`, and replaced its `main.bean` through the Gitea API with an opening balance, a 0.5 BTC purchase at 80,000 USD, and the BTC-USD managed price include (served from the feed's pre-release host during verification; the demo ledgers now point at `https://beancount.io/prices/BTC-USD`).
- Ledger API from inside the compose network: `GET /reports/pricedemo/my-book/errors` returns `[]`; `GET /reports/.../balance-sheet?conversion=USD` values `Assets:Crypto:BTC` at 38,431.01 USD (0.5 × the feed's latest price); `GET /ledgers/pricedemo/my-book/directive-count` returns 5; `entries_count_per_type` returns Open 3 and Transaction 2 with no Price row.
- Dashboard at `http://localhost:42610/ledger/pricedemo/my-book/balance-sheet`: "At Market Value" shows BTC 38,431.01 and total assets 98,431.01 (screenshot at `backend-cluster/ledger/tmp/m31-balance-sheet-market-value.png`); the sidebar usage counter reads `5 / 1,000` after the entries-per-type exclusion (it read `92 / 1,000` before it).
- Ledger log shows one `managed price feed refreshed` line (87 prices) per container start; three further loads inside the window logged no fetch; the Gitea commit list for the demo repo stayed at two commits across every load.
- Failure fallback was not induced live (no network fault injection on the stack); it is covered by the seven-case cache test table and the loader-level `keeps serving the last revision when the refresh fails` test.

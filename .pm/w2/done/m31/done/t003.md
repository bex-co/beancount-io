## Objective

Fetch a managed price feed within hard bounds and accept only bodies that are pure `price` directives with allowlisted metadata, so nothing but prices can ever enter the engine through a URL.

## Context

- ADR 015 sections 3 and 4.
- The live feed returns a strong ETag, `text/plain`, header comments `; alias:`, `; commodity:`, `; quote:`, `; source:`, `; revision:`, and directives with `price-source`, `price-kind`, `observed-at`, `provisional`.
- Node 22 global `fetch` is available; the engine's `neutralizeIncludedOptionsAndPlugins` remains as defense in depth.

## Steps

1. Create `managed-price-feed.ts` with `fetchManagedPriceFeed(url, { etag, timeoutMs, maxBodyBytes, fetchImpl })` returning `{ kind: "not-modified" }`, `{ kind: "fetched", text, etag, status }`, or a typed failure (`timeout`, `http-status` with code, `too-large`, `redirect`, `network`).
2. Create `validateManagedPriceText(text, expected?)` returning either `{ ok: true, feed: { alias, commodity, quote, source, revision, latestObservedAt, priceCount, directives: [{ date, base, quote, line }] } }` or `{ ok: false, reason }`, implementing the grammar in ADR 015 section 4 (comments, price lines, indented allowlisted metadata, single commodity pair, header match, finite positive decimals, real dates, non-empty).
3. Unit-test every rejection: transaction line, `open`, `option`, `plugin`, nested `include`, unknown metadata key, mixed pairs, header mismatch, zero or negative price, `1e5`, `2026-02-30`, empty body, comment-only body, oversized body, redirect, timeout, 404, 429, 500.

## Acceptance criteria

- [x] The real BTC-USD body saved as a fixture validates and reports its alias, pair, source, revision, latest observation, and count.
- [x] Every non-price directive rejects the whole body with a reason naming the offending line.
- [x] The fetch never follows a redirect, never reads past the byte cap, and never sends cookies or authorization.

## Out of scope

- Caching and file-map integration.

## Objective

Decide and record how the ledger service resolves managed price URL includes: which file-map key the WASM engine looks a URL include up under, how the feed is cached separately from the SHA-keyed file map, how failures and precedence behave, and what stays out of scope.

## Context

- `docs/prfaqs/PRFAQ002-include-live-price.md` FAQ 12, 15, 16, 18 define the feed contract and acceptance table.
- `backend-cluster/ledger/src/foundation/rustledger/url-include-errors.ts` already computes the engine key for a URL include with `resolveIncludeTarget`.
- The live BTC-USD feed (measured on its pre-release host before the `https://beancount.io/prices/<ALIAS>` route was mounted) serves a strong ETag, `max-age=60`, and rejects HEAD.

## Steps

1. Run a live `@rustledger/wasm` probe with the real feed text under the normalized key, under a subdirectory key, and included twice.
2. Measure the feed headers, conditional-request behavior, and error shapes.
3. Write `docs/adrs/ADR015-ledger-managed-price-includes.md` with the decisions, consequences, and rejected alternatives.

## Evidence

- `docs/adrs/ADR015-ledger-managed-price-includes.md` written 2026-09-15.
- Live probe against `@rustledger/wasm` 0.24.0 with the real BTC-USD body: engine key `https:/<host>/prices/BTC-USD` (root) and `sub/https:/...` (subdirectory) both parse to 87 valid price directives with metadata intact; the same URL from two directories doubles to 174.
- Feed headers measured: strong ETag, `Cache-Control: public, max-age=60`, HEAD returns 405, unknown alias returns 404 with a plain-text reason.

## Objective

Add the policy module that decides whether an include target is a managed price URL, and the configuration that controls it, so every later step shares one definition of "allowed".

## Context

- ADR 015 section 2: origin allowlist from `MANAGED_PRICE_ORIGINS` (default `https://beancount.io`; narrowed to that single origin at the user's direction on 2026-09-16), path exactly `/prices/<ALIAS>` with `ALIAS` matching `[A-Za-z0-9._-]{1,64}`, no user info, query, or fragment; empty value disables the feature.
- `backend-cluster/ledger/src/config.ts` holds the typed config with env parsing; `src/__tests__/config.test.ts` covers it.

## Steps

1. Extend `loadConfig` with a `managedPrices` section: `origins: string[]`, `refreshMs`, `staleMs`, `fetchTimeoutMs`, `maxBodyBytes`, `maxFeedsPerLedger`, with documented defaults.
2. Create `src/foundation/managed-prices/managed-price-policy.ts` exporting `parseManagedPriceUrl(target, config)` returning `{ url, alias, origin }` or a typed rejection reason, plus `managedPriceEngineKey(includingPath, url)` that delegates to `resolveIncludeTarget`.
3. Unit-test accepted and rejected URLs: allowed origin, wrong host, `http` on an `https`-only list, trailing slash, uppercase alias, query string, fragment, credentials, nested path, over-long alias, disabled list.

## Objective

Add the tests that pin the shipped contract where callers meet it, plus the failure modes, and prove each one fails when the behavior it covers is reverted.

## Context

- t001 and t002 cover the workflow's reads. Still unpinned: the adapters, an upstream that never returns a short page, and an upstream error partway through the read.
- `src/features/ai-agent/api/__tests__/catalog-parity.test.ts` drives REST, GraphQL and the MCP resources through one fake ledger service.

## Steps

1. Parity: an unpaged read returns the full fixture identically on REST, GraphQL, the MCP tool and the MCP catalog resource.
2. Bound: an upstream that ignores `page` and keeps returning full pages stops at the page cap, logs a warning and does not loop forever.
3. Failure: an upstream error on page 2 rejects the whole read with the same error as a page-1 failure, never a partial list.
4. Seeded-defect proof: revert the reader to a single call and to the old clamp in turn, and record which tests fail.

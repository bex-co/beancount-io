## Objective

Make the corrected catalog contract discoverable to agents and API clients wherever it is described, and confirm that no client package needs a change.

## Context

- The MCP tool's description and its input `describe()` text live in `backend-cluster/backend-v2/src/features/ai-agent/tools/ledger-context-tools.ts`. They are what `tools/list` returns, the same text for Claude Code, Codex and any other MCP client.
- `backend-cluster/backend-v2/docs/mcp.md` has a tools table row for `listLedgers`.
- The REST operations `accessibleLedgers` and `ownedLedgers` take their summaries from `CATALOG_READS` in `src/features/ledger/api/rest/v1/catalog-reads.ts`. The same text becomes the MCP catalog resources' titles, `docs/openapi/v1.json`, and — through `cli/Makefile` `spec-check` — the CLI's pinned spec, generated `bea cloud ledger list` help and `cli/docs/REFERENCE.md`.

## Steps

2. REST: leave the summaries unchanged. "List the caller's accessible ledgers" already reads as the complete list once t001 makes it one, and rewording it forces a regeneration across the CLI package for no change in meaning.
3. Check that the dashboard, mobile and CLI callers need no change, and record the result in the milestone README.

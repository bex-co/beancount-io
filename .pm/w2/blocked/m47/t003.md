## Objective

Extend `beancount-add` from pasted receipt text to a receipt file. The agent reads the image or PDF, proposes the same split-aware transaction the skill already builds, and, after a yes, writes the transaction and a `document` directive that share one link. The file sits where the ledger keeps documents.

## Context

- `beancount-add` ([m40](../../done/m40/README.md)) records "one or a few entries the user describes in words or pastes as receipt text". Splits must sum to the amount paid, or the skill asks about the difference (tax, tip, discount). The skill does not read export files.
- `bea add transaction` accepts `--link`, and `bea add document` accepts `--account`, `--filename`, and `--link`. `verify_document_files_exist` makes `bea check` fail when the file is missing.
- When `option "documents"` is declared, dated files in account-named folders under that root are discovered automatically. Do not add a second filing scheme next to it.
- Decide which account the document attaches to, either the paying account or the expense, and say why. Fava lists documents per account.

## Steps

1. Read the file with the client's own image or PDF support. If the client cannot read it, ask for the text. Use no OCR service.
2. Propose the transaction exactly as for pasted receipt text. Show the receipt's total beside the sum of the parts, plus the proposed file location and link.
3. After a yes, copy the file into place only if the user agreed to that copy. Then write the transaction and the `document` directive with the same link, and run the root `bea check`.
4. Update the description and scope lines, and add routing entries for receipt files, with near-misses against import (an export file) and reconcile (a statement).

## Files

- `skills/beancount-add/SKILL.md`

## Acceptance criteria

- [ ] A receipt file produces a proposal whose parts sum to the receipt total, or the skill asks about the difference.
- [ ] After a yes, the transaction and the `document` directive share one link, and `bea check` passes. The user's original file is never moved without consent.

## Out of scope

- Bulk receipt folders, and matching a receipt to an existing transaction. The latter edits an entry, which belongs to w2/m46.

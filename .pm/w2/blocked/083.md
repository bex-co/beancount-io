**Minor · skills · 30–45m · A1.** Found while building [m38](../done/m38/README.md)'s routing runner, 2026-10-18, Codex 0.163.0 (`gpt-6-luna`) on macOS, with the suite linked into a workspace's `.agents/skills` exactly as `beancount-skills.py install` links it.

Asked "How much did I spend on groceries last month?", Codex opened `beancount-ask/SKILL.md`, then searched for "beancount-init's `references/bea-cli.md`" with `rg --files` over `.agents/skills`, `~/.agents/skills`, and `~/.codex/skills`, three times, without finding it. It answered from the SKILL.md alone and never read the shared contract. The cause is ripgrep, which does not follow symlinks by default: `rg --files <dir>` lists nothing inside a linked skill folder (`rg -L` does). Every installed skill is a link, so any sibling lookup by search fails the same way.

Seven SKILL.md files point at the contract only by sibling name ("Read beancount-init's `references/bea-cli.md`"), so the agent has to search. A path relative to the skill's own folder needs no search: `../beancount-init/references/bea-cli.md` resolves through the link, and `cat` follows it. Change the pointers (and the other sibling-reference lines, e.g. `beancount-import/references/dedup.md`) to relative paths. Check that `beancount-skills.py verify` and w6/m6's bundle builder still resolve each form. Then rerun the probe and confirm Codex reads the contract directly.

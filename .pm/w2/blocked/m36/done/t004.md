## Objective

A GitHub Actions workflow that validates `server.json` on every change and publishes it to the official MCP Registry only from `main` or an explicit dispatch, with the signing key held in a protected environment and a guard against republishing an immutable version.

## Context

- The registry's own CI guidance: install `mcp-publisher` from the latest release tarball (old binaries fail with "invalid audience"), `mcp-publisher login http --domain <domain> --private-key <hex>`, `mcp-publisher publish <path>`; store the key as an **environment** secret, restrict the environment to the default branch, and optionally require a reviewer. Never publish from `pull_request_target`.
- Version immutability: `GET https://registry.modelcontextprotocol.io/v0.1/servers/{name url-encoded}/versions/{version}` answers 200 for a published version and 404 otherwise — the pre-publish guard.
- House style: `.github/workflows/release-cli.yml` (top-level `permissions: {}`, per-job `contents: read`, `persist-credentials: false`, a `concurrency` group that never cancels, a `workflow_dispatch` rehearsal input).
- Root `AGENTS.md` lists every workflow under "Tooling"; `python3 scripts/check-agent-guidance.py` must pass after editing it.

## Steps

1. Create `.github/workflows/publish-mcp-registry.yml`, name `Publish (mcp registry)`: triggers `push` to `main` and `pull_request` filtered to `backend-cluster/backend-v2/server.json` and the workflow file, plus `workflow_dispatch` with a boolean `publish` input defaulting to false.
2. Job `validate`: checkout, install `mcp-publisher`, run `validate` on `server.json`, and emit `name` and `version` outputs with `jq`.
3. Job `publish` (`needs: validate`, runs only on a `main` push or a dispatch with `publish`, `environment: mcp-registry-publish`): require `https://beancount.io/.well-known/mcp-registry-auth` to start with `v=MCPv1;`; fail with a "bump `version`" message when the registry already has this version, and on any status other than 404; `login http --domain beancount.io` with `secrets.MCP_REGISTRY_PRIVATE_KEY`; `publish`; then fetch the published version and assert the name and remote URL.
4. Add a "Publish (mcp registry)" bullet to the root `AGENTS.md` tooling list after "Release (mobile)": triggers, the environment and secret names, the version-bump rule, and the pointer to `docs/mcp.md`.

## Files

- `.github/workflows/publish-mcp-registry.yml`
- `AGENTS.md`

## Acceptance criteria

- [x] A pull request touching `server.json` runs `validate` only; a dispatch without `publish` does the same; `publish` never runs on `pull_request`.
- [x] The publish job reads the key only from the `mcp-registry-publish` environment and refuses an already-published version before logging in.
- [x] `actionlint` (or a dispatched validate-only run after merge) reports no errors; `python3 scripts/check-agent-guidance.py` passes.

## Out of scope

- Creating the environment, branch rule, and secret in GitHub (t006); DNS-based login.

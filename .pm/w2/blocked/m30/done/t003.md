## Objective

Model ids are code today (`claude-sonnet-4-5-20250929` and `gpt-4o` literals in `fallback-language-model.ts`), so a model upgrade is a code change. Hoist them to config with documented env vars and sane defaults.

## Context

- Env var names must NOT be `ANTHROPIC_MODEL` / `ANTHROPIC_SMALL_FAST_MODEL` — those are already claimed by the Path A sandbox (`ask-agent-workflow.ts` forwards them into the Claude Code harness); sharing would couple the two paths ADR 0011 keeps separate. Use `LLM_MODEL` / `LLM_FALLBACK_MODEL`.
- Default the primary to the alias `claude-sonnet-4-5` (auto-tracks the snapshot line) rather than a dated snapshot; fallback default stays `gpt-4o` until the operator chooses otherwise.
- `.env.example` files carry an `OPENAI_MODEL=gpt-4o` var — verify nothing reads it (suspected dead config) and remove it.
- Sequenced after t002 so the config shape reflects the settled fallback design.

## Steps

1. Add the two env-fed values (config.ts or read in the factory, matching the existing direct-key env pattern) with in-code defaults.
2. Replace the literals in `fallback-language-model.ts`.
3. Grep for `OPENAI_MODEL` readers; if none, delete it from all `.env.example` files.
4. Document both vars in `deploy/docker/.env.example`, `deploy/docker-mac/.env.example`, `deploy/dev-sandbox/.env.example`, and `bex.yaml`.

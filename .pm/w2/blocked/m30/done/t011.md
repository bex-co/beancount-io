## Objective

Triage on 2026-09-14 found that t003/t007 documented the AI configuration in every `.env.example` but never wired it through the Docker Compose targets, so the documented behavior does not hold on any Compose deployment. Make every deploy target forward exactly the variables ADR 0011 describes, and document them in the backend's own env template.

## Context

- All four Compose files (`deploy/docker`, `deploy/docker-mac`, `deploy/dev-sandbox`, `deploy/docker-single-psql`) set the backend container's environment explicitly (no `env_file`) and do not forward `LLM_MODEL` / `LLM_FALLBACK_MODEL` — setting them in `.env` is a silent no-op.
- The same files still forward the dead `OPENAI_MODEL` (no reader in `src/`), which ADR 0011's 2026-09-09 amendment says was deleted from every deploy target.
- They still default `BLOCKEDEN_ACCESS_KEY` to `local-dev-placeholder`, retired by ADR 0011's tier-2 amendment. The default makes an empty `.env` value non-empty, so `invokeModelProxy`'s "Model proxy is not configured" guard is bypassed and `bea ask` gets a gateway rejection instead. Stale comments still say the key is "REQUIRED to boot".
- `backend-cluster/backend-v2/.env.tmpl` documents only `BLOCKEDEN_ACCESS_KEY` (under a stale "BlockEden Configuration" header), none of `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` / `LLM_MODEL` / `LLM_FALLBACK_MODEL`.

## Steps

1. In each Compose file: forward `LLM_MODEL` / `LLM_FALLBACK_MODEL` (empty default — the factory falls back to its defaults), delete `OPENAI_MODEL`, default `BLOCKEDEN_ACCESS_KEY` to empty, and fix the stale boot comments.
2. Document the Path B keys, model overrides, and the Path C key in `backend-cluster/backend-v2/.env.tmpl`.
3. Validate each target with `docker compose --env-file .env.example config --quiet` and confirm the rendered backend environment carries the overrides.

## Files

- `deploy/docker/docker-compose.yml`, `deploy/docker-mac/docker-compose.yml`, `deploy/dev-sandbox/docker-compose.yml`, `deploy/docker-single-psql/docker-compose.yml`
- `backend-cluster/backend-v2/.env.tmpl`

## Acceptance criteria

- [x] `LLM_MODEL=x docker compose config` renders `LLM_MODEL: x` for the backend service on every Compose target.
- [x] No Compose target references `OPENAI_MODEL` or `local-dev-placeholder`.
- [x] Every Compose target passes `docker compose --env-file .env.example config --quiet` (and the SSH overlay where present).
- [x] `.env.tmpl` documents all four Path B variables and the Path C key.

## Out of scope

- bex.yaml (already correct), changing model defaults (t006), the Path A sandbox `ANTHROPIC_MODEL` passthrough.

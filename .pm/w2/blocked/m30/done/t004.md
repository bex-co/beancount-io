## Objective

The receipt screen shows "Upload failed. Please try again." for every failure because its error classification is dead code: under Apollo's default `errorPolicy` the mutation throws instead of populating `result.errors`, so the quota/parse branch never runs and the catch-all maps everything to `receiptUploadFailed`. Classify errors from the thrown `ApolloError`, show the right message per failure class, and report the raw error to Sentry.

## Context

- Dead branch: `mobile/src/screens/receipt-capture-screen/use-receipt-workflow.ts` (`parseResult.errors` check); exact-match mapping in `receipt-utils.ts`.
- The 2026-09-07 outage took hours to diagnose partly because the client swallowed the real error (ADR 0011 follow-up).
- Backend error codes now available: `RESOURCE_LIMIT_REACHED` (quota), `INTERNAL_SERVER_ERROR` with the clear not-configured message, upload-leg failures never reach GraphQL at all.
- Translation keys `receiptQuotaExhausted` / `receiptParseFailed` / `receiptUploadFailed` already exist in all 13 locales.

## Steps

1. In the catch, branch on `error instanceof ApolloError` and classify via `graphQLErrors[].extensions.code` (quota → `receiptQuotaExhausted`; any parse-leg GraphQL error → `receiptParseFailed`); keep `receiptUploadFailed` for the mint/PUT legs and network errors.
2. Delete the dead `parseResult.errors` branch.
3. `Sentry.captureException` with the phase (mint/upload/parse) as context.
4. Update `src/__tests__/receipt-utils.test.ts` and add cases for the new classification.

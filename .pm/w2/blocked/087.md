# Decide whether to publish the skill suite from a slim public mirror repository

**Owner decision · skills · A3.** From the skills research, 2026-10-18.

The plugin directories with the widest reach limit the size of the repository they ingest. This monorepo is too big for Anthropic's:

- **Anthropic's directory** (claude.ai, Cowork, Claude Code) requires fewer than 10,000 files and folders in the whole repository, according to its [pre-submission checklist](https://claude.com/docs/plugins/pre-submission-checklist). This repository has 10,095 tracked files (`git ls-files | wc -l`, 2026-10-18), so validation stops before reporting anything. The checklist also caps a plugin at 512 files of under 256 KiB each, with no symlinks, a LICENSE, and a README of at least 40 words.
- The same small repository would also qualify for **OpenAI's ChatGPT and Codex plugin directory**, which allows skills-only plugins and uses a [submission portal](https://developers.openai.com/plugins/deploy/submission), and for the **Gemini CLI extension gallery**, which indexes a `gemini-extension.json` at the repository root plus a GitHub topic ([releasing docs](https://github.com/google-gemini/gemini-cli/blob/main/docs/extensions/releasing.md)).

A mirror such as `bex-co/beancount-skills` would hold only `skills/`, the plugin manifests from [m44](m44/README.md), a README, and a LICENSE, synced from `main` by CI. The `beancount-*` folders here stay the single source; root `AGENTS.md` forbids parallel copies anyone edits.

Only the repository owner can decide:

1. Whether to create the public repository, and its name.
2. The push credential for the sync workflow, kept as an environment secret.
3. The paid plan and publisher identity for Anthropic's submission portal, and the identity check for OpenAI's.
4. The license, which stays MIT. ClawHub's MIT-0 question is separate, in [w6/m6](../../w6/m6/README.md).

Once decided, size the sync workflow and the three submissions as a milestone.

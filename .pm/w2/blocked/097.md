# Business presets lack payroll and sales-tax liabilities and owner draws

`business@1` in `backend-cluster/backend-v2/src/features/ledger/setup/catalog.json` opens bank, cash, sales and services income, operating expenses, `Equity:Capital`, `Equity:RetainedEarnings`, and `Equity:OpeningBalances`; its invoices-bills question adds receivables and payables. It has no payroll-liability or collected-tax liability accounts and no owner draws (`freelance@1` has `Equity:OwnerContributions` and `Equity:OwnerDrawings`).

The catalog changes only through a new preset version, so this is input to a `business@2` once [w2/m55](./m55/README.md)/t001 fixes the names. `beancount-init` already offers catalog presets through `bea init --preset` ([w3/m53](../../w3/done/m53/README.md); `skills/beancount-init/SKILL.md`), so a new version reaches local users through the same path.

Source: small-business owner review of the skill suite, item 1, triaged 2026-10-21.

**Blocked 2026-10-27** — this is a new preset version, not a sub-hour note. It folds in the finding of w2/098 (dropped as merged here): [PRFAQ001](../../../docs/prfaqs/PRFAQ001-ledger-creation.md) A.3 says the business starter's optional groups include "receivables/payables, fixed assets, loans, and separately stated tax balances", and its acceptance scenario (a 1,000 capital contribution and a 500 loan, in statement-presentation signs) needs a loan liability that `business@1` cannot open. So `business@2` would add loans, collected-tax and payroll liabilities, and owner draws (names per [ADR025](../../../docs/adrs/ADR025-skills-business-books.md)), plus a test that every account an acceptance scenario expects is one its preset can open. Preset IDs are enumerated in the v1 OpenAPI schema, GraphQL types, MCP tool schema, and the generated CLI client (`create_ledger_body_setup_type_0_preset.py`), so a new version is a REST/GraphQL/MCP API change with codegen and the CLI's catalog copy (`cli/src/bea_engine/setup_catalog.json`, drift-tested). The catalog's own rule keeps shipped versions frozen, which is why `business@1` is not edited in place. **Unblock:** the owner decides that `business@2` should exist with this content (and accepts ADR025's names); then promote this note to a milestone covering the catalog, fixtures, both engines' conformance, and the API parity work. **Who can clear it:** the repository owner (catalog content and a public API enum change).

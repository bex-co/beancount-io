## Objective

Find out exactly which rule of the Agent Skills specification our customer frontmatter breaks, then move to one form that passes `skills-ref validate` and that every host we target still reads. If no such form exists, record the conflict rather than silently picking a side.

## Context

- The [specification](https://agentskills.io/specification) requires `name` (1–64 lowercase letters, digits, and hyphens, no consecutive hyphens, matching the folder) and `description` (1–1024 characters). It allows `license`, `compatibility` (at most 500 characters), `metadata` ("a map from string keys to string values"), and `allowed-tools`. Validation uses [skills-ref](https://github.com/agentskills/agentskills/tree/main/skills-ref).
- Each customer skill carries `metadata: {"openclaw": {...}, "hermes": {...}}` on one line, shipped in [w6/m6](../../../../w6/blocked/m6/README.md) t004. OpenClaw parses frontmatter as YAML and re-reads `metadata` as JSON5. Hermes reads it with PyYAML. `ci-check.py` `check_metadata` requires a single-line JSON object because `beancount-skills.py` and `ci-check.py` skip indented lines.
- A research run on 2026-10-18 reported that `skills-ref validate` rejects all nine skills, and that block-style YAML passes. The nested objects may also break the string-values rule, so establish the actual failure before choosing a fix.
- Run the validator from a scratch environment under `scripts/skills/tmp/`. This task adds no repository dependency (t003).

## Steps

1. Run `skills-ref validate` on each `skills/beancount-*` folder and record the errors.
2. Try the candidate forms. For each, check `skills-ref`, PyYAML, OpenClaw's documented parsing (re-read `docs.openclaw.ai/tools/skills`), `npx skills add . --list`, and both clients' skill listing. Re-run `beancount-skills.py bundle` into a scratch folder.
3. Apply the form that passes everywhere, and update `check_metadata` and the comment above it. If none does, keep ClawHub's form, name the failing rule and the validator output in `skills/AGENTS.md`, and leave the choice to w6/m6's owner decision.

## Files

- `skills/beancount-*/SKILL.md`, `scripts/skills/ci-check.py`, `skills/AGENTS.md`

## Acceptance criteria

- [x] `skills-ref validate` passes on every customer skill, or the one failing rule is recorded with its output.
- [x] PyYAML still yields the same `openclaw.requires.anyBins`, `install`, and `hermes` values for every skill, and `bundle` still runs.
- [x] Claude Code and Codex list every customer skill after the change.

## Out of scope

- Publishing to ClawHub, and new metadata fields beyond those needed to pass.

## Result

Shipped with this task: every customer `SKILL.md` now writes `metadata` as a block YAML mapping instead of one line of JSON. The actual failure was strictyaml (inside skills-ref) rejecting flow mappings ("Found ugly disallowed JSONesque flow mapping") on all nine skills; the nested values were never the problem (skills-ref stringifies `metadata` values). The block form passes everywhere checked: `skills-ref validate` is green on all nine (scratch venv, 2026-10-19); PyYAML parses the new form to exactly the old JSON values on all nine (full metadata equality against `HEAD`, including `openclaw.requires.anyBins`, `install`, homepage, and the `hermes` block); OpenClaw documents multi-line YAML mappings as YAML-parsed then flattened and re-read as JSON5 (docs.openclaw.ai/tools/skills, checked 2026-10-19); `npx skills add . --list` still finds exactly the 9 customer skills; `beancount-skills.py bundle` runs. Client listings from a linked scratch workspace: one client's init event lists all nine `beancount-*` skills, and the other client's pre-model skills catalog in its rollout lists all nine (its model turn itself is usage-limited until 2026-11-17, so no live answer was taken from it). `ci-check.py` now requires the block form for customer skills and parses it with a small stdlib YAML subset (nested mappings, lists, plain/quoted scalars) instead of `json.loads`; development skills keep the one-line JSON internal flag. `skills/AGENTS.md` states the new rule.

## Objective

Make the new layout hard to undo by accident. A CI check holds `skills/` to skill folders plus `README.md` and `AGENTS.md`, and it fails when a guide tells customers to copy a checkout path that does not exist. Rewrite the instruction files that state where customer skills live, so agents and contributors read one consistent rule.

## Context

- Rule text to rewrite: root `AGENTS.md` (the compatibility rule "Customer-facing `beancount-*` skills live separately in `skills/.claude/skills/`", the Packages row, and the `CI (skills)` and `CI (agent guidance)` entries), `.agents/AGENTS.md` (the customer-suite pointer), and `skills/AGENTS.md` (the opening paragraph, the `## Layout` block, and the paragraphs citing `.claude/skills/…`, `docs/…`, and `scripts/…`).
- `.github/workflows/ci-agent-guidance.yml` filters on `skills/.claude/skills/**`. Change it to `skills/**`.
- The guides copy checkout paths through `$SKILLS_SRC/<path>`. A check can resolve each one against the repository, which catches the regression this milestone would otherwise risk on every later move.
- Run `python3 scripts/check-agent-guidance.py` after editing instruction files (root `AGENTS.md` rule).

## Steps

1. In `scripts/skills/ci-check.py`, fail when `skills/.claude` exists, when a tracked file sits directly in `skills/` other than `README.md` or `AGENTS.md`, when a directory in `skills/` has no `SKILL.md`, or when a `$SKILLS_SRC/<path>` in `docs/skills/*.md`, `skills/README.md`, or `skills/AGENTS.md` names no tracked path.
2. Rewrite the rule text above. Say that the guides live in `docs/skills/` and the tooling in `scripts/skills/`, and that both belong to the skills package scope documented by `skills/AGENTS.md`.
3. Update the workflow filter. Run `ci-check.py`, `test_ci_check.py`, and `check-agent-guidance.py`.

## Objective

When a ledger uses t001's client/project key, `beancount-add` and import's normalized batch path propose it from the payee's history, show it in the proposal, and write it with the entry after the yes.

## Context

- `skills/beancount-add/SKILL.md` Parse and Propose phases; `skills/beancount-import/references/categorization.md`.
- Batch JSON carries `meta` (`skills/beancount-init/references/bea-cli.md`). Whether `bea add transaction --posting` can write transaction or posting metadata is unverified: read `cli/src/cli/commands/add.py` first.

## Steps

1. Verify how the native and batch write paths carry transaction and posting metadata.
2. Add the proposal rule, learned like categories: a confident prior proposes the key; no prior proposes the entry without one and flags it; a key is never invented.
3. Show the key in the proposal exactly as it will be written.

## Files

- `skills/beancount-add/SKILL.md`
- `skills/beancount-import/SKILL.md` or `references/categorization.md`

## Acceptance criteria

- [x] An expense for a payee with a consistent prior client is proposed with that key; one without a prior is proposed without it, flagged.
- [x] The written entry carries the key exactly as proposed, and the root `bea check` passes.

## Out of scope

- Adding the key to existing entries (an edit; see [w2/m46](../blocked/m46/README.md)).

## Result

`beancount-add` proposes `client:`/`project:` from the payee's history with the new `dimension-prior` recipe: a value is proposed when the payee's attributed entries agree (cited with its count), disagreement is a question, and with no attributed history no key is added unless the user names one. Approved keys ride on the one-off recipe as `--meta 'client:<value>'`; a split whose postings carry different keys goes through the batch recipe's posting `meta` (`bea-cli.md`, One-off entries). `beancount-import`'s categorization reference suggests the key from the same matches and routes attributed CSV rows to the normalized batch path, because `bea import` rules set only an account until t003 (`bea-import.md`). Verified by `test_client_and_project_keys_are_read_from_payee_history_and_written_as_metadata` (reads the payee's grouped history, writes transaction and per-posting keys, root check green; fails when the recipe reads `entry_meta`). The proposal behavior on real clients is measured by this milestone's evals (t005–t006).

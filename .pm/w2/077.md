# Remeasure Transaction Filters labels after live text-size changes

**Minor · 30–45 minutes · mobile · A2.** Found during [m37](./done/m37/README.md) t003 adoption checks, 2026-10-09, on the iPhone 17e / iOS 26.5 simulator with the public Example ledger, light theme, English.

Open Transactions → Filters through the actual controls at default text size, then change the OS text size to maximum while Filters stays open. The STATUS / DATE RANGE / ACCOUNT captions, the Cleared/Pending/Other and ALL/1M/3M/YTD/Custom chips, "All accounts", Apply, and the Cancel/Reset header actions all keep their old frames and clip into glyph fragments. This is the same retained-measurement failure m37 fixed for date headers, picker rows, range pills and the file notice. Those fixes still hold on this journey, and the Filters chips are local to `transaction-filters-screen.tsx`, not `TimeRangePills`.

An m37 experiment ruled out the systemic shortcut: rebuilding `useThemeStyle` styles on font-scale change (equal values, new identities) leaves Filters clipped. Only a changed native prop or a remount invalidates the cached paragraph. Apply the m37 convention (`mobile/AGENTS.md`, "Live text-size changes") to the Filters screen's Text owners. Leave the header-button labels to their own owner. Verify live default↔maximum in both themes against a cold launch. Other screens were not surveyed; any further one is its own note, not a whole-app remount.

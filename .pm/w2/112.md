# Entry Context hides the ledger's single-entry refusals behind "information provided is invalid"

**Minor · dashboard · 30–40 minutes.** A2: Entry Context lets the owner edit an entry's source directly. The obvious mistakes are pasting a second entry into it, or clearing it to remove the entry. The ledger refuses both with a precise reason, but the dialog shows generic advice. This is the dashboard counterpart of mobile's [w21/620](../w21/done/620.md) and [w21/814](../w21/done/814.md).

Production https://beancount.io, 2026-11-10, English, isolated headless Chromium 156 at 1440×1000, signed in as the owner of the designated synthetic ledger. Every save was refused, and main.bean stayed at blob `f1a0b83c` throughout. Local main `d1846d2bb`.

## Reproduce

Open `/ledger/<o>/<l>/journal`, open any transaction's Entry Context, replace its source with the text below, and click **Save**:

| Source typed | `UpdateLedgerEntrySourceSlice` (`BAD_USER_INPUT`) | Dialog shows |
| --- | --- | --- |
| the entry plus a second dated transaction | `newContent holds 2 entries; edit them one at a time or use updateLedgerFiles` | "Some of the information provided is invalid. Please check and try again." |
| empty | `newContent is empty; delete the entry instead of saving it blank` | same generic toast |
| `; just a comment` | `newContent holds no entry; remove the entry with deleteEntrySource instead` | same generic toast |

**Controls in the same dialog:** a parse error, an unopened account and an unbalanced edit each get specific text, for example "This would add an error to your ledger: Account Expenses:Food:Nope was never opened (main.bean:83)" and "The postings don't balance…". The draft stays in the editor in every case.

## Root cause

`dashboard/src/features/journal/components/entry-context-panel.tsx:~628` sends every non-stale save failure to `toast.error(formatError(saveError))`. The shared `getErrorMessageKey` maps `BAD_USER_INPUT` to `common.errors.badUserInput`. Mobile already recognizes these refusals in `mobile/src/common/ledger-refusal.ts:~212` (`SINGLE_ENTRY_REFUSALS`: date line indented, holds no entry, holds N entries, must be one dated directive, `option`/`plugin`/`include` is not an entry). Packages stay independent, so the dashboard needs its own small matcher rather than an import.

## Fix

Add a dashboard matcher (for example `common/lib/errors/single-entry-refusal.ts`) for the same server prefixes, plus `… is empty;`. Map each to localized dashboard copy that never names API fields or calls:

- "Entry Context edits one entry at a time. Remove the extra entry, or edit the file instead."
- "To remove this entry, use Delete."
- "The date line must start at the beginning of the line."
- "`option`, `plugin` and `include` lines belong in the file, not in an entry."

Use it in the Entry Context save handler before `formatError`. The standalone entry page (`features/journal/pages/entry-page.tsx:86`) renders the same `EntryContextPanel`, so one change covers both. Add keys in all 15 locales, and a test per message using the exact server text above.

## Blast radius

`entry-context-panel.tsx` is the only `UpdateLedgerEntrySourceSlice` caller in `dashboard/src`. It serves both the Journal dialog and the entry page. The New Entry forms build one directive and cannot hit these refusals.

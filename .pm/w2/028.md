# Mobile cannot read the activity feed: session-only credential policy

`getFeed` is the mobile home screen's "Latest Updates" card. On the iPhone
simulator that card renders its failure state ("Failed to load / Try again")
because the backend refuses the call:

```
GraphQL auth error: This operation is reachable only from a browser session
operationName: GetFeed
```

`USER_SOCIAL_FEED_READ` declares `credential: { methods: SESSION_ONLY }` in
`backend-cluster/backend-v2/src/server/api/authorization/authorization-service.ts`,
and the app authenticates with OAuth (ADR 013), so every mobile request is
denied. Introduced 2026-08-31 by `f07b3f79` "feat(authz): centralize social
authorization"; nothing since has exercised the card, so it has been dead on
mobile ever since.

Decide whether a feed read is genuinely session-bound. It exposes the caller's
own ledger activity plus public blog and changelog posts, which the app is
already trusted to read through other operations. If it is not session-bound,
widen the policy to include OAuth and add a mobile-shaped test so the card
cannot silently die again. If it is, the app should stop rendering a card it can
never fill.

Not bundled with the changelog feed work: that is a policy decision with its own
blast radius, and it should land as its own reviewable change.

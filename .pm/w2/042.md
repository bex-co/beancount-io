## Reproduce, repeat and controls

1. Select public `open_ledger/example` using `beancount:///ledger/open_ledger/example`, wait for selection, then open the inspected Merchants destination `beancount:///(app)/merchants`. Search **Cafe Modagor** and tap its actual row. The native detail has **44 transactions**, **$1,535.16**, **Feb 11, 2015 – Sep 8, 2017**, and populated transaction rows beginning with **−$33.71**. The directory/detail steps use real native typing and taps; reaching the directory uses a deep link.
2. Open `beancount:///ledger/open_ledger/example/files/blob/main/main.bean`. Wait for the generated Example Beancount source. Open `beancount:///ledger/open_ledger/crypto-example/files/blob/main/main.bean` and wait for **Crypto Trader Example** source. Both file buffers render the correct ledger and their read-only banners.
3. Tap native Back once. The previous screen still names **Cafe Modagor**, but now shows **0 transactions**, no total/date span, and **No transactions / No transactions matched this merchant exactly**. Its Recurring switch remains available. Dismissing the development warning does not change this settled result.
4. Terminate/relaunch the app (repeat PID `26060`), reselect Example, and repeat the actual search/merchant tap and both settled file links. Back repeats the empty Cafe screen.
5. Same-ledger control during the fresh run: Cafe → Example file → Back retains all **44 transactions** and **$1,535.16**. Preserve it.
6. Recovery from the empty retained screen: open the original Example file link, wait for Example source, then Back. The same Cafe destination regains **44 transactions**, **$1,535.16**, its original date span and real rows. No transaction was lost.

Expected: Back retains a merchant's originating ledger/payee identity, or gives an explicit unavailable/recovery state when that ledger is no longer selected. Actual: the old named detail silently runs against another ledger and presents that ledger's no-match state without indicating the context changed.

Anonymous GraphQL controls all return HTTP 200 without errors. The exact app metadata BQL (`SELECT count(*) as transaction_count, min(date) as first_date, max(date) as last_date FROM #entries WHERE payee = 'Cafe Modagor'`) returns `[44, "2015-02-11", "2017-09-08"]` for Example and `[0, "", ""]` for Crypto. Per-currency Expenses/Income totals return `["USD", "1535.16"]` versus no rows; the quoted transaction journal filter returns totals **44** versus **0**. These are correct responses for each ledger; the defect is retained navigation identity, not API arithmetic or a request failure.

# Smart Import offers to spend AI tokens on an empty CSV, and refuses a spreadsheet through a blocking browser alert

**Minor · dashboard · 30–40 minutes.** A2: the first upload is where a newcomer decides whether import works.

- A **0-byte** `.csv`, such as an export that failed or was cut short, is reported as "We couldn't read this CSV's columns". The only way forward offered is **Parse with AI (uses AI tokens)**, which spends paid tokens on a file with nothing in it.
- The page invites files from "bank statements, **spreadsheets**, or receipts". Yet dropping an `.xlsx`, `.xls` or `.txt` is answered by a native `alert()`, a blocking browser dialog outside the page's own error area. The over-10 MB refusal uses the same `alert()`.

Production https://beancount.io, 2026-11-10, English and German, isolated headless Chromium 156 at 1440×1000, signed in as the owner of the designated synthetic ledger. Nothing was imported, and no AI parse was started. Local main `bd00e7557`.

## Reproduce

On `/ledger/<o>/<l>/import`, upload or drop each file:

| File | Shown |
| --- | --- |
| `empty.csv` (0 bytes) | "We couldn't read this CSV's columns … This file can be read with AI instead, which uses your AI tokens." with **Parse with AI (uses AI tokens)** |
| `header-only.csv` (`Date,Payee,Description,Amount\n`), control | "No Transactions Found … The file was successfully parsed, but no transaction data was found." ✓ |
| `binary.csv` (PNG bytes), control | inline "File isn't UTF-8 text …" ✓ |
| drop `statement.xlsx` / `statement.xls` / `notes.txt` | native `alert`: "This file type isn't supported. Please use a CSV, PDF, OFX, or image file (PNG, JPG)." (in German: "Dieser Dateityp wird nicht unterstützt …"); the page itself shows nothing |

## Root cause

- `features/importer/hooks/use-multi-stage-parser.ts:64–80`: a CSV with `validCount === 0` and no `blockLlmFallback` goes to the `ai-offer` stage. An empty file never gets a header-recognized result, so it lands there.
- `features/importer/components/steps/upload/file-upload.tsx:31–42` refuses an oversized or unsupported file with `alert(t(...))` and returns. Nothing is rendered in the page.
- `i18n/locales/common/en.ts:507` (the page description) promises "spreadsheets".

## Fix

- In the CSV path, treat a file that is empty or whitespace-only after decoding as its own state: "This file is empty. Export the statement again and upload the new file." Offer **Upload Different File** and no AI offer.
- Replace both `alert()` calls with the inline error area the UTF-8 refusal already uses (`role="alert"`, focus kept on the dropzone). For spreadsheets, name the fix: "Excel files aren't supported yet. In Excel or Numbers, use File → Save As → CSV UTF-8, then upload that file."
- Either reword the description to "bank statements (CSV, OFX, PDF) or receipts", or, as a product decision, add XLSX support.
- Tests: 0-byte and whitespace-only CSV → empty state with no AI button; `.xlsx` and an 11 MB file → inline message and no `window.alert` call.

## Blast radius

Smart Import's upload step (`/import`) and the header's Import menu, which opens the same page. Upload Files (Files) has its own inline checks (w3/487) and is not affected.

# Deleting a file that a `document` entry points at breaks the ledger and says only "File deleted successfully"

**Minor · dashboard · 25–35 minutes.** A2: receipts and statements uploaded to Files and linked with `document` entries are routine. Deleting one leaves an E8001 error in the ledger, and the dashboard reports plain success. Every other write path in the dashboard warns when it leaves new ledger errors.

Production https://beancount.io, 2026-11-10, English, isolated headless Chromium 156 at 1440×1000, signed in as the owner of the designated synthetic ledger. Every write was reverted; main.bean is back at blob `f1a0b83c` and the test file is gone. Local main `de5bb3dd4`.

## Reproduce

1. Create `qa/receipt.txt` in Files, and append `2026-08-28 document Assets:Cash "qa/receipt.txt"` to `main.bean`. The ledger check reports no errors; Documents lists the file.
2. Open `qa/receipt.txt` → **More actions** → **Delete**. The confirmation reads only "Are you sure you want to delete "receipt.txt"? This action cannot be undone." Confirm.

**Actual:** the only feedback over the next eight seconds is the toast **"File deleted successfully"**. The ledger now has `E8001 Document file not found: qa/receipt.txt (main.bean:89)`. An Errors entry appears in the sidebar, as it does for any ledger error (seen in an earlier run), but nothing ties it to the delete.

**Controls:**

- Saving a file that adds an error ends with "Saved, but your ledger now reports an error … View errors" (w1/m41).
- Deleting a transaction that a balance assertion depends on is refused: "This would add an error to your ledger: Balance failed for Assets:Cash …".
- Deleting a file that another file `include`s is refused by the server and offers to remove the include lines (w21/587).

## Root cause

`dashboard/src/features/ledger-editor/file-editor/components/ledger-file-view/index.tsx` (delete handler, ~line 245–275) shows `toast.success(t("ledgerEditor.fileDeletedSuccess"))` in `onCompleted` and never calls `writeOutcome.report(before)`. The save handler on line ~187 and the Entry Context, New Entry, Import and Open Account paths all do. File deletion is a raw repository write, so the server does not refuse it. Its include check (w21/587) covers `include` lines only, not `document` paths.

## Fix

- Take `writeOutcome.snapshot()` before the delete mutation and call `void writeOutcome.report(before)` in `onCompleted`, as the save path does. The existing "…now reports an error … View errors" warning then appears.
- Optionally, before confirming, check the ledger's Document entries (the Documents page already lists them) for this path. If any match, name them in the confirmation: "1 document entry points at this file; deleting it leaves a ledger error."
- Add a component test for each: delete → `report` called; a document reference → confirmation text.

## Blast radius

File delete in the file view, and deleting several files from the tree (the multi-delete path) if it shares the handler. Upload and create cannot add errors this way. Moving or renaming files is not exposed in the dashboard.

## Dedupe

Searched `.pm/**` for document directives, `E8001`, "Document file not found", and delete + writeOutcome. w21/587 (include-aware delete, done) and w1/m41 (post-write error warning, done) cover adjacent cases; neither covers document references or the delete path.

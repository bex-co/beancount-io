## Objective

Define and implement the smallest trusted background invocation boundary so webhook/job paths never masquerade as capability-exempt browser sessions or pass transport request wrappers into domain services.

## Context

- Plaid webhooks and scheduled sync currently use `systemIdentity(userId)` after resolving an item.

## Steps

1. Ratify the explicit internal provenance and source-bound item/user/ledger input; keep webhook signature and scheduler authentication outside relationship authz.
2. Route background domain work through the same canonical action requirements without fabricating `Identity.method = session`, accepting caller-controlled workload provenance, or creating credential/request tuples.
3. Carry job/transport operation IDs only as observability metadata through isolated AsyncLocalStorage; keep application method inputs domain-shaped and enforce source bindings again at mutation time where practical.

## Files

- Plaid webhook service and scheduler job
- identity/authorization integration files

## Acceptance criteria

- [ ] No request path can claim background/capability-exempt identity.
- [ ] Background work cannot escape the resolved item/user/ledger binding.
- [ ] Webhook/scheduler behavior remains operationally unchanged.
- [ ] No `AuthorizationRequest`-like wrapper or operation ID pollutes domain service signatures.

## Out of scope

- A general service-identity platform or FGA `service` type.

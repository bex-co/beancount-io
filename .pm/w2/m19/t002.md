## Objective

Authorize Plaid Link and item/account management once at protected application-service/workflow boundaries before external or database work.

## Context

- Link requires an interactive caller; established item operations require current user/ledger binding.

## Steps

1. Pass the resolved `Identity` explicitly to protected customer-facing services/workflows and route Link-token/exchange/unlink/status/item/account operations through the PDP.
2. Resolve ownership and ledger binding from backend models on every authorization call; keep operation IDs in AsyncLocalStorage.
3. Preserve Plaid validation, token handling, atomic item/user predicates, not-found concealment, and client error behavior.

## Files

- `backend-cluster/backend-v2/src/features/plaid/**`
- authorization integration files

## Acceptance criteria

- [ ] Wrong user/item/ledger and wrong credential method deny before Plaid calls.
- [ ] Existing Link and mapping behavior remains contract-compatible.
- [ ] No Plaid secret or token enters audit/model data.
- [ ] Direct protected calls cannot bypass the PDP and use canonical-action audit fallback.

## Out of scope

- Transaction synchronization, webhook processing, or an authorization-only wrapper.

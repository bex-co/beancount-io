## Objective

Receipt/file extraction runs on a Sonnet-class model chosen by default, not by data. With models configurable (t003), run the existing eval suite with `claude-haiku-4-5` against the current Sonnet baseline and record a keep/switch decision — Haiku is roughly 3-5× cheaper per token for a workload that is mostly structured extraction.

## Status: blocked on credentials (2026-09-09)

The code prerequisite is met — the eval provider routes through
`createFallbackLanguageModel()`, which reads `LLM_MODEL` (t003), so
`LLM_MODEL=claude-haiku-4-5 promptfoo eval` selects Haiku with no further
change. Running the two eval passes needs a real `ANTHROPIC_API_KEY`, which is
not available in the implementation environment. This is the one m30 task that
cannot be completed without an operator-supplied credential; everything else in
the milestone shipped. To finish: export `ANTHROPIC_API_KEY`, run the two
passes, and record the decision per the steps below.

## Context

- Eval infra exists: `backend-cluster/backend-v2/evals/` (promptfoo providers, receipt fixture `extract-transactions-from-file/receipt.webp`, provider classes updated for direct keys 2026-09-09).
- Requires a real `ANTHROPIC_API_KEY` at run time; evals are manual, not CI.
- Decision criteria to fix before running: extraction field accuracy on the fixtures (payee/amount/date exactness), account-recommendation sanity, and failure rate.

## Steps

1. Confirm the eval provider honors `LLM_MODEL` (from t003); add the pass-through if missing.
2. Run the extraction evals twice: current default vs `LLM_MODEL=claude-haiku-4-5`; capture promptfoo outputs.
3. Compare per the fixed criteria; write the decision (switch, keep, or split per-feature) into ADR 0011 as a dated amendment note.
4. If switching: update the config default and `.env.example` docs in the same change.

## Objective

The OpenAI fallback leg has never worked for extraction: OpenAI's strict `response_format` requires every property in `required`, and the extraction schema declares `date` optional. Fix the schemas (required + nullable), audit all four `Output.object` call sites, and add a static compatibility test so the dual-vendor schema dialect is CI-enforced instead of remembered.

## Context

- Production runs both `ANTHROPIC_API_KEY` and `OPENAI_API_KEY` (direct); the operator wants real dual-vendor failover (tier-3 decision, 2026-09-09).
- Proven failure: outage logs — `Invalid schema for response_format 'response': … Missing 'date'` (ADR 0011).
- The four structured-output call sites: `call-llm.ts`, `categorize-transactions/index.ts`, `suggest-account-mapping/index.ts`, `recommend-accounts/index.ts`.
- Mobile already tolerates a null/empty `date` (`receiptDate` falls back to today), so required+nullable is a server-side-only change.

## Steps

1. Change the extraction schema's `date` to required + nullable; keep the "omit if unreadable" prompt semantics (null = absent).
2. Audit the other three `Output.object` schemas for optional fields; convert to required + nullable where found.
3. Add a static unit test that walks every `Output.object` schema (exported or via a registry) and asserts OpenAI strict-mode invariants: all properties listed in `required`, `additionalProperties: false`, optionality expressed as nullable.
4. Add a failover-order unit test on `fallback-language-model`: primary rejects → second provider is called; last provider's non-retriable error propagates.

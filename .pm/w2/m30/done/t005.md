## Objective

The server boots happily with a dead or missing LLM credential, so nothing distinguishes "AI configured" from "AI silently broken" until a user hits scan-receipt — exactly how the placeholder key survived in production. Add a cheap synthetic probe (ADR 0011 D6): a trivial model call at startup and on an interval, logging success/failure loudly.

## Context

- `isLlmConfigured()` (`fallback-language-model.ts`) already distinguishes unconfigured; the probe covers configured-but-dead (revoked key, provider outage, gateway drift).
- Must not block or fail boot: fire-and-forget after startup, short timeout, one bounded retry at most.
- A log line with a stable `module` field is enough for now — alerting infra is out of scope.

## Steps

1. Add a small probe (e.g. `generate` with a one-token prompt, 10 s timeout) invoked post-boot when `isLlmConfigured()`, and on a timer (e.g. hourly, `unref`'d).
2. Log `llm-probe` success (model id, latency) and failure (error class, provider) at warn on failure.
3. Skip entirely when unconfigured — that state is already visible per-call.
4. Unit-test the wiring with a mocked model (probe reports both outcomes; never throws).

## Files

- `backend-cluster/backend-v2/src/features/llm/` (new probe module)
- server startup wiring (composition root or server entry)

## Acceptance criteria

- [ ] Booting with a bogus `ANTHROPIC_API_KEY` produces a clear probe-failure log within the first minute.
- [ ] Booting unconfigured produces one info line and no probe traffic.
- [ ] No effect on boot success or request latency; timer does not hold the process open.

## Out of scope

- Alerting/paging integrations; dashboard surfacing; probing Path C.

## Objective

`/.well-known/mcp.json` advertises `endpoint` and `openapi` under the dashboard origin but `auth` URLs under the OAuth issuer, so a split-host self-host advertises the wrong MCP address (locally: port 42600 vs 4114).

## Context

- `well-known-route.ts` L20 uses `config.dashboard.url`; L49–50 use `config.oauth.issuer`. The 401's `WWW-Authenticate` pointer and `oauth-protected-resource` use the issuer and are correct.
- ADR 0009 inventories the well-known paths; the conformance script checks 1–7 but not the manifest.

## Steps

1. Derive `endpoint`, `openapi`, and `auth` from the issuer (the API origin); keep the dashboard URL only for human-facing links, labeled as such.
2. Add conformance check 8: the manifest's `endpoint` equals the address that reaches the MCP handler and its `auth` URLs resolve.
3. Trim the manifest: list tool and resource names, not full descriptions (it is ~20 KB today).

- [ ] `yarn mcp:conformance` has an eighth check that fails when the manifest disagrees with the live endpoint.
- [ ] The manifest is under 8 KB.

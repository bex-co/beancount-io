## Cause and repair

`mobile/src/screens/transactions-screen/utils/plain-search-filter.ts:24–30` detects both ASCII quote kinds and deliberately runs `trimmed.replace(/"/g, "")` before regex escaping. Transactions uses this helper after its300ms debounce at `transactions-screen.tsx:109–112` and passes the result directly as the journal filter at136–141. The existing mixed-quote unit test explicitly expects the lost characters, so green tests currently preserve the defect.

Preserve the complete trimmed literal needle while making it safe for the filter STRING lexer and regex compiler. Encoding embedded double quotes as regex `\x22` inside a double-quoted filter is accepted by the real API control above; keep user-entered backslashes escaped so literal `\x22` text cannot become a quote or other regex operator. Use the existing small helper and keep ordinary apostrophes, double-only input, periods, brackets, backslashes, whitespace/empty handling, case-insensitive matching, debounce and pagination behavior. No new dependency, cross-package import or backend grammar change is needed.

Acceptance: fresh native Example search `E.B.'s "Beer"` remains visible unchanged and produces the honest no-match state, while `E.B.'s Beer` still returns four. Replace the loss-expecting assertion with a behavior check that the decoded regex matches a string containing both quote kinds and rejects the corresponding quote-stripped string; cover literal backslashes beside quotes to detect accidental escape interpretation. Recheck both production callers and the existing punctuation cases. Keep meaningful existing tests rather than adding an assertion that merely repeats the new serialized output.

Blast radius: the helper has two production callers. Transactions search is reproduced here. Merchant detail uses it at275 for initial/subsequent journal pages at291/352, while separately retaining exact-payee filtering at315; an actual merchant whose name contains both quote kinds could consequently lose its journal candidates. That merchant flow is source-traced only: no such live payee or fixture mutation was exercised, and no second defect is claimed. Metadata/totals, recurring preferences, account/status/date predicates and backend API parity stay outside the repair.

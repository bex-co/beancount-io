# Serve the MCP Registry proof over HTTP on production (optional)

Found during w2/m36 closeout, 2026-10-06.

`io.beancount/beancount` is published with the namespace proved by an apex TXT record in the `beancount.io` Cloudflare zone, because the production host was not reachable when the listing went live. The backend's `GET /.well-known/mcp-registry-auth` route (m36/t002) is shipped and tested but still answers 404 on production, since `MCP_REGISTRY_AUTH_PROOF` is unset there.

Next time production backend-v2 is redeployed, set `MCP_REGISTRY_AUTH_PROOF` to the same public record as the TXT value (`dig +short TXT beancount.io` shows it), then confirm `curl -fsS https://beancount.io/.well-known/mcp-registry-auth` prints it. The publish workflow then signs in over HTTP and the TXT record becomes the fallback. Keep both pointing at the same key; never put the private half in the repository. ~10 minutes, operator-only (production access).

Nothing is broken without it — publishing works through DNS today.

# A file save that conflicts with another write tells the editor to refresh, which discards their edit

**Minor · dashboard · 40–55 minutes.** A1/A2: an owner editing `main.bean` while an agent writes to the same ledger (over MCP, REST or the CLI) is the conflict this product invites. Entry Context already handles it without losing work (w3/642). The file editor still gives a 4-second generic toast whose advice throws the edit away.

Production https://beancount.io, 2026-11-10, English, isolated headless Chromium 156 at 1440×1000, signed in as the owner of the designated synthetic ledger. Two pages in one session; every write prefixed and reverted (main.bean back to blob `f1a0b83c`). Local main `bacd07bc1`.

## Reproduce

1. Open `/ledger/<o>/<l>/files/blob/main/main.bean?editMode=true` in page A and page B.
2. In B, append `; qa-B` and Save → "File saved successfully".
3. In A, append `; qa-A` and Save.

**Actual (A):** a toast reads **"This change conflicts with the current state. Please refresh and try again."** and disappears after about 4.5 s. The editor keeps A's draft (good) and B's bytes are preserved (good). Following the advice: reload → the browser's generic "Leave site?" prompt → accept → the editor reopens on B's version and **A's edit is gone**. Nothing offers to copy the draft, show the other change, or reload while keeping the draft. Retrying Save from A only repeats the same toast, because the stale `sha` never changes.

**Control:** Entry Context's stale save (w3/642) shows a persistent inline notice — "This entry was changed or removed since you opened it, so your edit wasn't saved…" — with **Copy my edit** and **Reload** actions (`features/journal/components/entry-context-panel.tsx:~703`). The API side is correct since w23/032: `updateLedgerFile` answers a stale `sha` with `CONFLICT`.

## Root cause

`dashboard/src/features/ledger-editor/file-editor/components/ledger-file-view/index.tsx:178-179` routes every save failure to `toast.error(formatError(error))`. `CONFLICT` therefore becomes the shared `common.errors.conflict` text (`i18n/locales/common/en.ts:927`), which tells the reader to refresh and gives the editor nothing to act on.

## Fix

When `updateLedgerFile` fails with `extensions.code === "CONFLICT"`, keep edit mode and the draft, and show a persistent inline notice in the editor instead of the toast: "This file changed since you opened it, so your edit wasn't saved." Offer two actions:

- **Copy my edit** — the draft to the clipboard, as Entry Context does.
- **Load latest** — refetch `GetLedgerFile` and open the new revision (new `sha`). Confirm first that the draft will be replaced.

Do not auto-merge. Add a test in `ledger-file-view/__tests__/` with a mocked `CONFLICT` asserting the notice, both actions, and that the draft survives. Locale keys go in all 15 languages.

## Blast radius

Only the text-file save path. File delete on a stale `sha` (w21/380, done) and create-over-existing (w23/032) already have their own messages. The generic `common.errors.conflict` text stays for other callers.

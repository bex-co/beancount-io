# Interactive `bea init` defers the currency-typo warning until after the ledger is created

Found 2026-09-12 by a CLI QA sweep against HEAD `84231f9c`, bea 0.2.0, driving the prompts through a real PTY. One-line fix.

`init` validates the operating currency in two tiers: a hard reject that re-prompts inline, and a soft "this is unusual, check for a typo" warning. The soft warning is collected before the remaining questions but printed only after the file is written, so it lands several prompts away from the answer it is about:

```
$ bea init books
Operating currency [USD]: not-a-currency
Earliest date you will record (opening balances must be as of this date) [2026-09-12]: EUR
Error: Invalid date 'EUR'. Use YYYY-MM-DD format.
Earliest date you will record (opening balances must be as of this date) [2026-09-12]: 2026-08-01
Checking opening balance on 2026-08-01 (negative for an overdraft) [0]: Assets:Checking 1000
Error: Invalid opening amount: 'Assets:Checking 1000'. Enter a number such as 1538.25.
Checking opening balance on 2026-08-01 (negative for an overdraft) [0]:
Operating currency 'NOT-A-CURRENCY' is a valid Beancount symbol but is not three uppercase letters. Check for a typo (for example, USD). Custom and crypto symbols are supported.
Created .../books/main.bean with 14 accounts in NOT-A-CURRENCY.
```

The realistic case is a plain typo: answering `USDD` creates a 14-account ledger denominated in `USDD`, and the warning arrives after the user has moved on. Because `init` never overwrites (`ConflictError` at `init.py:90`), the only recovery is deleting the file and starting over.

- Root cause: `cli/src/cli/commands/init.py:97-102` appends the warning to a list right after the currency prompt, but `init.py:132-138` emits it only after the ledger is created — past the date prompt (`init.py:104-110`) and the opening-balance prompts. Hard failures re-prompt inline because they raise from `value_proc=_currency` (`init.py:94`); the soft warning has no such path.
- Fix: in the interactive branch (`currency is None`), call `output.note(...)` with the warning immediately after `_currency(currency)` resolves, so it appears next to the answer like every other validation message. Keep appending it to `warnings` so `--json` and the unattended `--currency USDD` path are unchanged — non-interactive runs have no later prompts, so their ordering is already fine.
- Scope: A2 (frictionless onboarding). `bea init` is the first command a newcomer runs; a typo warning that arrives after the ledger exists is the one place this flow can silently mis-denominate a whole set of books.

## Verified correct while probing this (no action needed)

The tiering itself is right, so the fix must not turn the warning into a rejection: `US D`, `123`, and `US$` are hard-rejected and re-prompt inline; `usd` is normalized to `USD` silently; `USDD` and `NOT-A-CURRENCY` are genuine Beancount commodity symbols and must stay accepted for crypto and custom units.

## Dedupe

Nothing on the board covers `bea init` currency prompting. `git log -S 'three uppercase letters' -- cli/src/cli/commands/init.py` shows the warning added by `790791ac` and unchanged since — present on main, not deployment lag.

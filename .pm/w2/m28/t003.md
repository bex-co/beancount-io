## Objective

Failures arrive in four dialects: `{ok:false,error}` text, bare text with no `structuredContent` (pin violations), JSON-RPC `-32602` with Zod prose, and JSON-RPC `-32603` for not-found and forbidden on resources (double-prefixed "MCP error -32602: MCP error -32602: …"). Make every failure one shape with a machine code and a next step.

## Context

- Reproduced messages: `Select a ledger using ledger: owner/name` (bare text), `No such file in mcpprobe/default: nope.bean` (-32603), `Entry conflict: it has changed since it was loaded; refresh and retry` (bare text).
- `DomainError` subclasses in `@/shared/errors` already carry `category`/`metadata`; the MCP boundary just needs one translator like `format-error.ts` does for GraphQL.

## Steps

1. Add `mcp-errors.ts`: map `DomainError` categories to `{code, message, hint}` and to JSON-RPC codes (`-32602` invalid params, `-32002` not found, a named forbidden code, `-32000` for the rest); write hints for the top ten messages (`ledger` selector, `listLedgers`, fresh `sha256sum` via `getEntryContext`, `allowInvalid`, scope needed).
2. Tool failures: always `isError: true` with `structuredContent: {ok:false, error:{code,message,hint}}` and the same text.
3. Resource failures: JSON-RPC errors with `data: {code, hint}`; strip the double prefix.
4. Zod failures: keep the field path, drop the array dump.

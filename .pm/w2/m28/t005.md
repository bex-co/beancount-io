## Objective

Agents write Beancount fluently. Give them a tool that appends directive text to a file, bean-checks the projected ledger first, routes to the configured file when none is given, and keeps date order — so they neither learn the 5 KB structured schema nor do string surgery with `editLedgerFiles`.

## Context

- m26/t002 supplies the validation envelope; m26/t004 supplies the in-memory check of projected contents.
- The directive writer already knows the ledger's file-routing rules (`addBulkEntries`); reuse its target selection.
- Audit observation: entries appended today land in `main.bean` with two blank lines and out of date order.

## Steps

1. Input: `{text, path?, dry_run?, allowInvalid?}`. Parse `text` with the ledger service to reject non-directive content; refuse more than 50 directives per call.
2. Resolve `path` via the routing rules when omitted; insert each directive after the last directive with an earlier-or-equal date in that file (append at end when the file is unsorted).
3. Run the projected check; refuse on new errors unless `allowInvalid`; commit with message `Add N directives to <path>`; return the m26 `WriteOutcome`.
4. Annotate `readOnlyHint: false`, `idempotentHint: false`.

## Acceptance criteria

- [ ] Appending a valid transaction lands it in the routed file in date order and returns file, line, hash, and an empty `newErrors`.
- [ ] Appending an unbalanced transaction is refused with code `UNBALANCED` unless `allowInvalid`.
- [ ] `dry_run` returns the diff and projected errors without committing.
- [ ] A REST twin exists (`POST …/directives/text`) and surface-parity is green.

## Out of scope

- Editing existing directives (that is `editEntrySource`).

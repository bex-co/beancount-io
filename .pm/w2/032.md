# Validate client GraphQL documents against the backend-v2 schema in CI

[w2/031](./done/031.md) shipped a dashboard mutation that selected a field backend-v2 had removed two weeks earlier. Every check stayed green because nothing compares client documents with the server schema. The dashboard generates types from whatever schema it last introspected, and backend-v2's tests never read client documents.

Add one check that builds the schema from backend-v2 source (`buildGraphqlSchema()` + `printSchema`, as the SDL route does) and runs `graphql.validate` on every `dashboard/src/**/*.graphql` and `mobile/src/**/*.graphql` operation. Run it in CI whenever either side changes. A schema change that breaks a shipped client document then fails before merge, instead of surfacing as a validation error in production.

**Open question (user):** where the check lives. It crosses packages: a backend-v2 test reading client files, a root script, or a committed SDL snapshot that both clients codegen from. Estimate 45–60 minutes once placed.

## Objective

Prove both OAuth acquisition profiles, their authorization ceilings, their operational behavior, and the API-key retirement boundary with behavioral tests.

## Context

- Happy-path token tests do not catch assertion replay, resource confusion, grant escalation, per-token rate resets, or a stale API-key fallback.
- Mobile, Dashboard, Discourse, and existing MCP OAuth behavior are regression boundaries.

## Steps

1. Cover device/PKCE authorization, workload assertion exchange/rotation, renewal, consent, resource/scope/pin narrowing, revocation, expiry, rate continuity, audit identity, and management ownership.
2. Add failure tests for replay, wrong issuer/audience/client/resource, unknown or revoked grants, expired assertions/tokens, missing owner, cross-user access, malformed keys, and source outage with zero domain side effects.
3. Prove API keys cannot issue or authenticate after sunset and run backend, Dashboard, CLI/client, OpenAPI, authz-model, guidance, and secret-scan gates plus Mobile/Discourse/MCP regression suites.

## Files

- OAuth provider, identity, authz, rate, audit, and management tests
- Dashboard/CLI/MCP/OpenAPI integration and conformance tests
- API-key retirement and mixed-client regression fixtures

## Acceptance criteria

- [ ] Mutating client ownership, resource, scope ceiling, ledger pin, stable rate principal, assertion validation, or one-hour workload access TTL fails the suite.
- [ ] A workload token cannot impersonate first-party Dashboard/Mobile, DCR/MCP, Discourse, or another user's client/grant.
- [ ] Revocation blocks new tokens immediately, current access is bounded by expiry, and rotating tokens cannot reset the workload budget.
- [ ] Post-sunset `bcio_`/`x-api-key` attempts fail terminally while all supported OAuth clients retain their intended behavior.

## Out of scope

- Coverage-number chasing or tests that accept both old and new credential contracts indefinitely.

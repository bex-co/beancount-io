# In Persian, counts across the ledger pages print Latin digits, sometimes in the same line as Persian ones: "ثبت‌ها: ۲٬۰۵۳ · انواع: 12"

**Minor (i18n) · dashboard · 40–60 minutes.** A2: Persian is one of the 15 UI languages. Amounts, dates and the Statistics tables already use Persian digits, so a stray Latin count reads like a rendering glitch. Mobile settled this in [w21/1017](../w21/done/1017.md), [w21/1020](../w21/done/1020.md) and [w22/012](../w22/done/012.md): counts use the language's own digits. The dashboard still passes most counts to `t()` as bare numbers.

Production https://beancount.io, 2026-11-10, `?lang=fa`, isolated headless Chromium 156 at 1440×1000, signed in. Read only on the public `open_ledger/example`. Local main `ac8f6bf4e`.

## Reproduce

Open each page of `/ledger/open_ledger/example/<page>?lang=fa`:

| --- | --- | --- |
| Statistics → Entries Count by Type | `ثبت‌ها: ۲٬۰۵۳ · انواع: 12` (one line, both scripts) | `… انواع: ۱۲` |
| Statistics → Postings per Account | heading count `(58)`, while the rows below read `۲۷۵`, `۴۲` … | `(۵۸)` |
| Statistics → Account Last Entries | `(15)` | `(۱۵)` |
| Events | `رویدادها: 9 / 9` | `۹ / ۹` |
| Commodities | `تاریخچه قیمت با 141 نقطه داده` | `۱۴۱` |
| Budget | `1 / 1 نتایج` | `۱ / ۱` |
| Holdings | `115 ردیف‌ها` | `۱۱۵` |
| Accounts | filter count `60 / 60` and the Postings column (`18`) | Persian digits |
| Journal | pager `1–60 / 1044` | `۱–۶۰ / ۱٬۰۴۴` |

Billing's ledger count is filed separately in [w2/124](./124.md).

## Root cause

`t()` interpolates numbers as `String(n)`. The call sites pass raw lengths instead of formatting them first:

- `features/ledger-data/statistics/entries-count-by-type.tsx:95` passes `types: entries.length`, beside `entries: formatNum(totalCount)`.
- `statistics/postings-per-account.tsx:107` and `statistics/account-last-entries.tsx:110` pass `count`.
- `commodities/index.tsx:249`, `events/index.tsx:223` and `bql/components/query-result-card.tsx:223` do the same.
- `accounts/index.tsx:283` renders `{account.entryCount}`, and `:574` builds `${filtered.length} / ${accounts.length}`.
- The Budget, Holdings and Journal pager counts show the same output. Their call sites were not traced.
- Relative commit times come from date-fns `formatDistance` (`common/hooks/use-date-locale.ts`). Its `fa-IR` locale writes Latin digits.

A formatter already exists: `features/user-settings/pages/general/use-quota-number-format.ts` (`formatNumber(value, true, language)`), which the directive-usage indicator also uses.

## Fix

- Move that hook to `common/hooks/use-format-count.ts`, and pass every count through it before interpolating or rendering. Use grouping, so `1044` → `۱٬۰۴۴` in fa and `1,044` in en.
- For relative times, either use `Intl.RelativeTimeFormat(language)` or map the digits of date-fns's output for languages whose default numbering system is not `latn`.
- Keep ledger ISO dates, account names and raw BQL cells as they are.
- Add one fa test per surface (or a table test over the call sites), plus an en control that is unchanged.

## Blast radius

Ledger pages only: Statistics, Events, Commodities, Budget, Holdings, Accounts, Journal, Query and Commits. Of the 15 languages, only fa defaults to non-Latin digits, so others are unaffected.

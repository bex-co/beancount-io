# Make the mobile file reader's permission notice legible in light mode

**Severity:** minor. **Owner:** mobile. **Estimate:** 20–30 minutes. **A2/A3:** a newcomer reading a public ledger should be able to read why the file cannot be edited. Report-only native QA, 2026-10-08; no product fix or production mutation.

Environment: `main` at `245e949c`, current checkout's Metro and rebuilt `io.beancount.ios` development client, iPhone17e / iOS26.5, English / System / standard `large` text, official `https://beancount.io/`, public synthetic `open_ledger/minimax`. Existing native session retained; fresh QA login remains unverified because the designated credential file is unavailable.

## Reproduction

1. Browse → Explore → search `minimax` → Open → Files → tap the actual **README.md** row. Wait for its source and permission notice to load.
2. The notice says **This ledger is read-only. Choose a ledger you can edit to make changes.**, but its 13-point text is extremely pale against the inset background. The source text immediately below is readable and correct. Save is absent.
3. Terminate/relaunch in light mode (fresh PID98574), open `beancount:///ledger/open_ledger/minimax/files/blob/main/README.md`, wait for settled content and dismiss the development warning banner. The faint notice reproduces unchanged.
4. With app theme still System, set the simulator appearance to dark, relaunch (PID97051) and open the same valid file. The settled notice is readable. Restore light and relaunch: faint again.

**Expected:** the explanatory notice remains readable in both themes. **Actual:** light mode renders its information using the disabled/placeholder ramp color, despite this being an informational sentence rather than a disabled control.

The actual palette and the repository's `contrastRatio` helper measure:

| Theme | Current text / background | Ratio | Existing secondary text on that background |
| --- | --- | --- | --- |
| Light | `#c2c3b6` / `#f6f4ec` | **1.6195:1** | `#6b6e5f`: **4.7429:1** |
| Dark | `#9a9c8d` / `#282a21` | **5.2059:1** | `#a7a99a`: **6.0864:1** |

These are measured source colors, not an estimate from antialiased screenshot pixels. The app's existing contrast tests use **4.5:1** for small text. [W3C's contrast-minimum guidance](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) uses that same threshold; its disabled-control exception does not describe this explanatory Text. The lock icon is redundant with the sentence; no independent icon-compliance claim is made.

Working controls: the settled dark notice passes; the native read-only `/(app)/add-transaction` guard for this same public ledger displays the same sentence clearly using `theme.text01`, without mounting a writable composer. The actual anonymous `getLedgerFile` read returns HTTP200, README6138bytes, base64, blob `ffedf1ba506c1f154da1f62476084b2de74023b6`; the source matches the native reader. This is presentation, not a false denial, file-load failure or permission bypass.

## Cause and repair

`mobile/src/screens/ledger-file-editor-screen/index.tsx:83–96` fills the notice with `theme.black10` and sets `readOnlyText.color = theme.black60`. At628–635 both the icon and translated text use that ramp value. `src/common/theme/palette.ts:179–185` documents light black60 as placeholders/disabled; black80 is secondary text. Existing control-specific tokens already avoid the weak light ramp, and `color-utils.ts:40–75` / `__tests__/control-contrast.test.ts` provide the measurement helper and thresholds.

Use an existing readable text role, such as `theme.black80`, for this notice and its matching lock icon. Keep the quiet inset fill and layout, all translated copy, Save gating, source read-only behavior and the existing condition that yields to file-error notices. Keep the neutral ramp intact; it also serves dividers and disabled UI. No new color system, dependency, localization key or API change is needed.

Acceptance: the actual notice's foreground/background pair clears4.5:1 in both resolved themes; fresh native light/dark captures show the whole sentence clearly while source and permissions remain unchanged. Recheck Files → README and the valid file link, then restore System/light/large. Use the existing contrast helper to verify the actual screen style; an assertion on an unrelated palette pair cannot guard this call site. Keep the existing notice-presence and Save-permission checks. No elaborate new rendering harness is required for this small style repair.

Scope: one shared LedgerFileEditorScreen, reached by the authenticated Files tab and `/(app)/ledger-file-editor`, plus the shared `examples/ledger-file-editor` route. The authenticated public-file flow and link were exercised. The signed-out alias is source-traced only. Other muted texts, disabled buttons, writable saves, error-banner colors, Dynamic Type layouts, RTL, Android and actual VoiceOver speech are outside this reproduction.

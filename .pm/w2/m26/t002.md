## Objective

Every MCP tool that changes ledger content returns what it wrote and what bean-check says afterwards, so an agent learns about a broken ledger from the write itself rather than by remembering to read the `errors` resource.

## Context

- `editLedgerFiles`, `addLedgerEntries`, `addLegacyEntries`, `insertReceiptTransaction`, `editEntrySource`, `renameLedgerFile`, and `manageBankImport.submit` all commit without reporting validation state. Reproduced: a file with an unbalanced transaction was committed with `ok: true`; `addLedgerEntries` returned "Added 1 entry successfully" for a 10 USD / −5 USD transaction.
- The `errors` resource already calls the ledger service's check; reuse that call. `entry-context` already computes entry hashes and `sha256sum`.
- All three agent sessions in the audit said the same thing: "there is no obvious get-me-the-loader-errors tool". This task plus m27/t003 (`checkLedger`) closes that.

## Steps

1. Define one `WriteOutcome` shape in `tools/types.ts`: `{wrote: [{path, line?}], entryHashes: [...], validation: {errorsBefore, errorsAfter, newErrors: [{message, source}]}}`, and add it to each write tool's output schema so `tools/list` publishes it.
2. Capture the error list before the commit (cheap: one ledger-service call), commit, re-check, and diff by message+source.
3. Where the write appends directives, return the file and line the directive landed on; where it edits a slice, return the new entry hash (see t005).
4. Keep `ok: true` when the commit succeeded even if `newErrors` is non-empty — the write happened — but put the count in the text content's first line ("Committed 1 entry to main.bean:73. 1 new bean-check error: Transaction does not balance …").

## Acceptance criteria

- [ ] Every write tool's `structuredContent.result` carries `wrote`, `entryHashes` (where applicable), and `validation.newErrors`.
- [ ] Writing an unbalanced transaction returns `newErrors` with the residual message and the file/line.
- [ ] The text content's first line states what was written and how many new errors, if any, were introduced.
- [ ] `tools/list` output schemas include the new shape (the parity baseline test is updated deliberately).

## Objective

`managePullRequests.create` fails with "Base branch 'main' not found" on a ledger whose default branch is `main`, and read/reject then say "Unknown error". `editEntrySource.update` reports the old `entryHash` although the entry's hash changes. Both send an agent down a dead end.

## Context

- `pull-request-service.ts` L85 throws when `repoGetBranch` returns no `data`; L161/L234/L261/L288 collapse the upstream cause into "Unknown error". Reproduced against Gitea 1.24 where `default_branch = main`.
- `mcp-source-slices.ts` returns `{message, entryHash, newSha256sum}` with the request's hash; the journal shows a different hash for the edited entry (`ec3385…` → `bc36ea…`), so a follow-up edit gets "Entry conflict".

## Steps

1. Reproduce the PR failure with an integration test against the local Gitea; fix the branch lookup (likely the generated client's response shape or the credential used) and surface the upstream message instead of "Unknown error".
2. Default `baseBranch` to the repository's actual default branch rather than the literal `main`.
3. After a successful `editEntrySource` update, re-resolve the entry and return `newEntryHash` alongside `newSha256sum`; state in the description that hashes change on edit.

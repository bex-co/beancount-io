1. Build the post-change file contents in memory (create/update/replace/delete already compute them for the commit).
2. Produce a unified diff per file (a small pure helper; no new dependency unless one is already present).
3. Run the check over the projected file set and return `validation` in the same shape as t002.
4. Text content: the diff, then a one-line validation summary.

## Objective

Return the `managedPrices` records the cached load already computes, and add the manual refresh ADR 015 §5 defers to its first client surface: a head update that sets `nextRefreshAt` to zero for each managed URL the ledger includes.

## Context

- `backend-cluster/ledger/src/foundation/clients/load-cached-ledger-file-map.ts` (`LoadedLedgerWithManagedPrices`), `foundation/managed-prices/managed-price-overlay.ts` (`ManagedPriceSource`), `managed-price-cache.ts` (head key, lock).
- `LedgerDataService.loadSnapshot()` reads the records but no route returns them. The closest route family is `src/api/reports.ts`.
- The contract is `backend-cluster/idl/beancount-ledger.openapi.json`.

## Steps

1. Add `requestManagedPriceRefresh(url)` beside `resolveManagedPriceFeed`, under the same per-URL lock. It zeroes `nextRefreshAt` on an existing head and keeps revision and last error. With no head it does nothing.
2. `GET /reports/:owner/:repo/managed-prices` returns the records. `POST …/managed-prices/refresh` zeroes each included URL's head and returns the records after the refreshed load.
3. Describe both in the IDL.

## Files

- `backend-cluster/ledger/src/foundation/managed-prices/`, `src/features/ledger/service/ledger-data-service.ts`, `src/api/reports.ts`
- `backend-cluster/idl/beancount-ledger.openapi.json`

## Acceptance criteria

- [ ] Status route returns one record per resolved managed URL, and `[]` for a ledger with none.
- [ ] Refresh never fetches the repository, never writes a commit and never deletes a blob. A failing re-fetch keeps serving the last validated revision.
- [ ] Tests cover the head update and both routes.

## Out of scope

- Snapshots/export, the instrument catalog.

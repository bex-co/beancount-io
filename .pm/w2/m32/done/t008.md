## Objective

Meaningful tests for the shipped behavior: cross-surface parity of the status records, refresh authorization and no-side-effect denial, head update semantics (last good revision kept on failure), dashboard labels and hidden actions.

## Acceptance criteria

- [x] Each behavior has a test that fails when it is reverted. No snapshot-everything or tautological tests.

## Result

Behavior → test that fails when the behavior is reverted:

- **Head update** (made due, revision and error kept, failed re-fetch keeps the last blob, no-op with no head): `managed-price-cache.test.ts` (`requestManagedPriceRefresh`, 4 cases).
- **Ledger service** (status records minus engine fields, unavailable with cause, empty ledger, refresh re-fetches inside the window, no repository re-read with a single HEAD lookup, failed refresh keeps the revision): `managed-prices-status.test.ts`. Stubbing the head update fails 5 cases.
- **backend-v2 parity**: `managed-prices-parity.test.ts`, 9 cases.

  - An anonymous caller is refused the refresh.
  - The read is a resource template, not a tool.
  - Downgrading the refresh to a read action fails 4 cases.

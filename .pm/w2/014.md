# Give the rate limiter a per-route policy hook

From w2/m28:t007 (`/simplify`), deferred as structural work beyond that milestone.

`restRateLimitMiddleware` now special-cases one mount: it knows that
`MCP_TRANSPORT_OP_ID` is MCP, that MCP bodies are JSON-RPC, and which methods are
handshake ceremony. `MCP_TRANSPORT_OP_ID` is a hand-copied route string with
nothing tying it to the actual mount.

Cost: the next transport with a handshake adds a second `if`; renaming the route
silently re-charges the handshake with no test failing; and the exemption is total,
so unlimited `{"method":"ping"}` posts cost a credential nothing at the one limiter
that is meant to be unbypassable.

Fix: let a route declaration supply `rateLimitOpId(ctx)` / `exemptFromRateLimit(ctx)`,
so the MCP mount — which already understands JSON-RPC — owns the policy and the
limiter stays "look up op, charge budget". Consider a cheap handshake budget rather
than a full bypass.

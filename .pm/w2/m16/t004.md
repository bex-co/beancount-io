## Objective

Apply the same canonical AI decisions to REST streaming routes, GraphQL helpers, MCP tools/resources, and agent workflows.

## Context

- Streaming and MCP adapters currently perform their own capability guarding.

## Steps

1. Map all AI aliases to the same catalog actions without adapter-local policy.
2. Pass resolved `Identity` to the protected application boundary and authorize before response/stream headers, model invocation, or agent/tool execution.
3. Propagate each alias's operation ID in an isolated AsyncLocalStorage child context and remove duplicate route guards after parity is proven.

## Files

- `backend-cluster/backend-v2/src/features/ai-agent/**`
- AI route guards and composition root
- authorization integration files

## Acceptance criteria

- [ ] GraphQL/REST/MCP aliases reach the same PDP requirements.
- [ ] Denial occurs before model invocation or stream headers/side effects.
- [ ] MCP revocation takes effect on the next call.
- [ ] Actionable denial messages and source-unavailable errors survive each surface's translation.

## Out of scope

- New AI tools, prompts, providers, or quotas.

## Objective

Write the skill text, or the widened options text, so an agent records each investment event with correct cost basis and lots. Cover buys, sells with lot selection, cash and reinvested dividends, splits, transfers between the user's own accounts, and RSU/ESPP vests, for securities and crypto alike. Every write follows the suite's rails.

## Context

- Write path: `bea add transaction --posting` supports cost lots (`{…}`), total cost (`{{…}}`), and `@`/`@@` prices (`cli/src/cli/commands/add.py`; the recipes in `skills/beancount-init/references/bea-cli.md`). Use the shared recipes rather than inventing syntax.
- Sells: name the lot by cost and date when the user does. Otherwise rely on the account's `open` booking method, and record the gain to an existing income account (for example `Income:CapitalGains`). Never type a gain the booking did not produce, and use a balancing posting only where Beancount's own convention calls for one.
- Transfers between the user's accounts reduce the lot at its cost and add the same units at the same cost and acquisition date ([beancount#564](https://github.com/beancount/beancount/issues/564), [#614](https://github.com/beancount/beancount/issues/614)).
- Splits keep total cost and change units and per-unit cost ([#941](https://github.com/beancount/beancount/issues/941)).
- Vests record the income at fair market value and a lot at that cost. The skill shows both, and leaves tax treatment to the user.
- Suite rails (`skills/AGENTS.md`): a proposal with the target file and exact entries, an explicit yes, existing accounts only (a new account only on request), `--file` and `--into` on every write, `import-id` for externally sourced entries, and a passing root `bea check` before success.

## Steps

## Completed — 2026-11-08

Added six real-bea tests to TestBeaRecipes. Four extract the actual cost-lot
examples from the trade guide and execute the shipped transaction recipe:
transfer preserves both accounts' cost/date, a 3-for-1 total-cost split preserves
2,600 USD without cent-rounding each share, reinvestment creates 0.15 VTI and
45 USD income, vesting creates 8 ACME at 200 USD and 1,600 USD income. The tests
execute the lots-held query and independent booked-credit query against the
resulting isolated ledgers. Existing realized-gains coverage exercises all
three report queries, both holding buckets and the 390 USD booked tie-out.

Negative cases require an ambiguous default-STRICT sale to be refused with no
file changes, and UNKNOWN booking to be refused without an open. A real FIFO
open then succeeds, proving the negative test is not passing on an unsupported
option. This control caught an operator PATH selecting obsolete bea 0.1.0;
explicitly selecting the checkout's 0.3.1 fixes the test environment. Monetary
credits compare exact Decimal values, allowing harmless trailing zeroes.

75 relevant tests pass on checkout bea 0.3.1 (67 checker + eight trade/gains
recipe tests). All seven original-event/gains tests also pass on the actual
published bea 0.3.1 image, offline, without credentials. Full skills CI passes.
No new dependency or customer skill content change was needed.

Meaningfulness checks retain seven expected assertion failures, zero test
errors: in-memory corruptions of guide date, split cost, dividend quantity,
vest quantity and gains formula each fail their real-CLI test. Named-lot and
supported-FIFO substitutions make the rejection tests fail when the real engine
accepts the input. These are real command controls, not mocked command results;
the upstream engine itself was not modified. CI already runs this test module
against both checkout and published-minimum bea.

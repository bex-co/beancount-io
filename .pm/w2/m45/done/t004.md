## Objective

State in the skill which lot booking methods the engine behind `bea` accepts. Give one honest path for a user whose rules require a method it lacks, such as average cost, which France requires for capital gains.

## Context

- `bea add open --booking` accepts `STRICT`, `STRICT_WITH_SIZE`, `NONE`, `FIFO`, `LIFO`, and `HIFO` (`_BOOKING_METHODS` in `cli/src/cli/commands/add.py`). Average cost is the community's most-upvoted open request ([beancount#940](https://github.com/beancount/beancount/issues/940)).
- The default is `STRICT`, under which `{}` matches only an unambiguous lot ([w5/763](../../../w5/763.md)).
- Re-implementing booking in the skill is an anti-goal (`.pm/DO_NOT_DO.md`, "Don't re-implement upstream").

## Steps

1. Confirm the accepted list against `bea check` on a synthetic ledger, and note what `bea` reports for an unknown method.
2. Write the guidance: how to choose a method when opening a brokerage account, what `STRICT` means for a sale, and what to tell a user who needs average cost. That means saying the engine cannot book it, and letting the user decide how to record it. Never silently approximate.

## Files

- The chosen skill's `SKILL.md` or `references/`

## Acceptance criteria

- [x] The listed methods match what `bea check` accepts, verified and dated.
- [x] An eval prompt asking for average-cost booking gets the honest answer, not a fabricated average.

## Out of scope

- Adding a booking method to `bea` or upstream.

## Result

Guidance shipped in `beancount-trade` (## Booking methods): the accepted list — STRICT (default), STRICT_WITH_SIZE, NONE, FIFO, LIFO, HIFO — verified 2026-10-19 against `bea 0.3.1` by running `bea check` on a synthetic two-lot ledger per method (unnamed sell: STRICT and STRICT_WITH_SIZE refuse as ambiguous, FIFO/LIFO/HIFO book with gains 250.00/150.00/150.00 matching the hand-computed lots, NONE books no gain and needs explicit amounts). `AVERAGE` fails with the engine's own words, `AVERAGE method is not supported`; the skill says so plainly (France/PRU named), offers named-lot recording under a supported method or not recording, and forbids approximations. New eval 1 (`average-cost-not-supported`) passes on one client: it states the limit, shows both lots, refuses to fabricate the 110.00 average, and writes nothing. The method list also matches `_BOOKING_METHODS` in `cli/src/cli/commands/add.py`.

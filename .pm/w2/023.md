# `bea format --check` prints a remediation command that drops the alignment options, so following it never clears the gate

Found 2026-09-12 by a CLI QA sweep against HEAD `84231f9c`, bea 0.2.0. One-line fix plus a test.

`format --check` is documented for CI and pre-commit hooks (`cli/docs/USAGE.md:205`, `252-254`). When it fails it names the command to run — but builds that command from the path alone, discarding `-w/--prefix-width`, `-W/--num-width` and `-c/--currency-column`. A hook that pins a width therefore tells developers to run a command that leaves the gate red:

```
$ bea format main.bean --check -w 40
would format: /abs/main.bean
Error: 1 file(s) need formatting. Run bea format -i /abs/main.bean to apply.
$ echo $?
1

$ bea format -i /abs/main.bean          # follow the hint verbatim
formatted: /abs/main.bean
1/1 file(s) formatted.                  # exit 0

$ bea format main.bean --check -w 40    # same gate, still red
would format: /abs/main.bean
Error: 1 file(s) need formatting. Run bea format -i /abs/main.bean to apply.
$ echo $?
1

$ bea format -i /abs/main.bean -w 40    # what actually works
$ bea format main.bean --check -w 40
All 1 file(s) are formatted.            # exit 0
```

The two widths really do differ — `diff <(bea format f) <(bea format f -w 40)` shows the amount column shifting one space — so this is a genuine loop, not a no-op. Reproduced from a pristine fixture; `-W` and `-c` have the same shape.

- Root cause: `cli/src/cli/commands/format.py:115-118` builds the message as `f"{len(changed)} file(s) need formatting. Run bea format -i {shlex.quote(_root(files))} to apply."` — path only. The alignment flags are computed at `format.py:53` by `_alignment()` (`format.py:188-197`) and handed to `_report`, which passes them to `_would_change` but never into the hint.
- Fix: append the same `_alignment(...)` flags to the suggested command, e.g. `Run bea format -i <path> -w 40 to apply.` `_report` already receives `alignment`; it just needs to join it into the string (shell-quoted like the path). Add a regression test asserting that the command in the message, run verbatim, makes the identical `--check` invocation pass.
- Blast radius: only the `check` branch composes this hint. `--dry-run` prints "would format" lines without a remediation command, so it is unaffected.

## Also found (same command, one line)

`bea format <file> -w -5` forwards a negative width straight to `bean-format`, which dies with a raw Python traceback and exit 1:

```
$ bea format main.bean -w -5
Traceback (most recent call last):
  File ".../bin/bean-format", line 10, in <module>
...
```

`-w/-W/-c` are bea's own declared `int | None` options (`format.py:45-49`), not passthrough arguments, so bea owns their validation. The CLI already does exactly this elsewhere — `add balance --amount '… ~ -1 USD'` is rejected with "Balance tolerance must be nonnegative." at exit 2. Reject a negative width the same way rather than letting upstream traceback.

## Also found (`bea import`, one line)

Under `--json --debug`, an importer exception still appends "Pass --debug before the command for a traceback." to `error.message` even though `--debug` was passed and the traceback is already present in `error.traceback`. Drop the hint when debug is active. Verified: `error.traceback` is a 476-char string, stdout stays empty, exit 1 — the rest of the documented contract (`cli/docs/IMPORTING.md`, "A Python importer") holds.

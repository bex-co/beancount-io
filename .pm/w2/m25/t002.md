## Objective

Ship `brew install bex-co/tap/bea` as a thin formula over the PyPI release: a uv-created virtualenv in `libexec`, dependencies synced from the hashed lock, `bea` symlinked into `bin`.

## Context

- The public tap `bex-co/homebrew-tap` already holds `Formula/bex.rb`, rendered by the sibling bex repo's `scripts/bex-cli-formula.sh` and pushed by its release workflow with a write deploy key held as a GitHub Actions secret. Reuse the pattern: a deploy key scoped to the tap, secret name `BEA_TAP_PUSH_KEY`, step skipped cleanly when unset.
- Formula shape: `url` = the PyPI sdist for the release with its sha256; `depends_on "uv"` and `depends_on "python@3.12"`; `install` runs `uv venv libexec --python <brew python>`, `uv pip sync --require-hashes requirements.lock`, `uv pip install --no-deps .`, then `bin.install_symlink libexec/"bin/bea"`; `test` asserts `bea --version`.
- Wheels only, no source builds of `pydantic-core` on user machines; that is why the standard `virtualenv_install_with_resources` style is not used in the tap.
- The rustledger engine is GPL and lives only in the ledger service; nothing in this formula touches it.

## Steps

1. Add `cli/scripts/render-formula.sh` taking `VERSION` and the sdist sha256, emitting `bea.rb`; reject non-semver input; never emit a partial formula.
2. Add the release-workflow step: fetch the published sdist sha256 from PyPI's JSON API (retry until the release is visible), render, clone the tap with the deploy key, commit `Formula/bea.rb`, push.
3. Validate locally once with `brew install --build-from-source ./bea.rb && brew test bea` on macOS and in a Linux container.

## Files

- `cli/scripts/render-formula.sh` (new)
- `.github/workflows/release-cli.yml`

## Acceptance criteria

- [ ] `brew install bex-co/tap/bea` on a clean macOS yields `bea --version` matching the release
- [ ] The tap push step is skipped, not failed, when `BEA_TAP_PUSH_KEY` is absent
- [ ] The rendered formula contains the exact sdist sha256 from PyPI

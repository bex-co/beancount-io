## Objective

Clients decide what to auto-approve from `readOnlyHint`, `destructiveHint`, `idempotentHint`, and `openWorldHint`. Today `deleteAccount` and `runBqlQuery` are indistinguishable. Declare annotations in `McpToolDescriptor` and make the guard tests refuse a tool without them.

## Context

- `registerTool` accepts `annotations`; `MCP_TOOLS` descriptors carry none.
- Read tools: `runBqlQuery`, `runBqlQueryStructured`, `listLedgerFiles`, `readLedgerFiles`, `listApiKeys`. Destructive: `deleteAccount`, `manageLedgers` (delete), `editLedgerFiles` (delete), `revokeApiKey`, `manageBankConnection` (unlink), `managePullRequests` (approve). Idempotent: `setLedgerStar`, `renameLedgerFile` (after m26).

## Steps

1. Add `readonly annotations: ToolAnnotations` to `McpToolDescriptor`; fill every tool; pass through in `assembleMcpRegistry`.
2. Extend the MCP guard test so a descriptor without annotations, or a `readOnlyHint: true` tool classified `write`/`admin` in `op-class.ts`, fails CI.
3. Document the mapping rule in the descriptor's comment: annotations describe the worst case of the tool's operations.

## Acceptance criteria

- [ ] `tools/list` shows `annotations` on all tools; read tools have `readOnlyHint: true`; every account/ledger deleter has `destructiveHint: true`.
- [ ] The guard test fails for a descriptor with missing or op-class-inconsistent annotations.

## Out of scope

- Per-operation annotations inside grouped tools (MCP has none).

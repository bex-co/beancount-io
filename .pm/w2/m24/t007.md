## Objective

Move per-user state to an XDG-style `~/.config/bea/` directory and rename the CLI's own environment variables to a `BEA_` prefix, so no old-name path or variable survives into the first release.

## Context

- `cli/src/cli/config.py`: `DATA_DIR = ~/.beancount-cli`, credentials at `credentials.json`, settings read `BEANCOUNT_API_URL` and `BEANCOUNT_DASHBOARD_URL` via `env_prefix="BEANCOUNT_"`.
- `cli/src/cli/chat/skills.py` reads user skills from `~/.beancount-cli/agent/skill/`; the REPL stores prompt history under the same directory.
- Credentials keep the existing atomic-write, 0700/0600 behavior (`cli/src/cli/auth/credentials.py`).
- `BEA_TOKEN` supplies a credential without a browser login for CI; it is never written to disk and `auth status` reports `source: environment`.

## Steps

1. Set `CONFIG_DIR = $BEA_CONFIG_DIR or $XDG_CONFIG_HOME/bea or ~/.config/bea`; move credentials, history, and user skills under it.
2. Change `env_prefix` to `BEA_` (`BEA_API_URL`, `BEA_DASHBOARD_URL`); add `BEA_FILE` (t004) and `BEA_TOKEN` handling in the credential store.
3. Update the skill-loader docstring and `docs/agent-skills.md` paths.
4. List every `BEA_*` variable in `docs/USAGE.md`.

- [ ] `BEA_TOKEN=… bea auth status` reports the environment source and writes no file
- [ ] `git grep -n 'BEANCOUNT_API_URL\|\.beancount-cli' cli/` returns nothing

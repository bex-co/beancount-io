# Three newer filter diagnostics fall back to "information provided is invalid"

**Minor · dashboard · 25–35 minutes.** A2: a newcomer who mistypes the header filter should be told the filter is the problem, as w0/020 promised. Regression of [w0/020](../w0/done/020.md) caused by the newer ledger hints from w23/m2/t003 and t006.

Production https://beancount.io, 2026-11-08, English, isolated headless Chromium 156, signed in as the owner of a synthetic disposable ledger. Local HEAD `b3d07dd2e`; the classifier below is unchanged on main since 2026-11-03. Reproduced from fresh page loads on both routes.

## Reproduce

Open each URL on any ledger (the public `open_ledger/example` works too):

| Filter | Route | Ledger message (GraphQL `BAD_USER_INPUT`) | Dashboard shows |
| --- | --- | --- | --- |
| `payee:"` | `/journal?filter=payee%3A%22` | `Unterminated or misplaced quote — wrap the whole value in matching quotes, e.g. key:"a:b"` | generic |
| `payee:#trip` | `/journal?filter=payee%3A%23trip` | `Unexpected #trip after "payee:" — write payee:trip or a bare #trip term` | generic |
| `payee:7eleven` | `/journal?filter=payee%3A7eleven` | `Unexpected 7 after "payee:" — quote values starting with a digit, e.g. payee:"7"` | generic |
| `#` (control) | `/journal?filter=%23` | `Illegal character "#"` | filter message ✓ |

"generic" = `Error loading journal entries: Some of the information provided is invalid. Please check and try again.` The same three show `Error loading data / Some of the information provided is invalid…` on `/income-statement` (and every report sharing the header filter). The control shows `The filter expression can't be read. Check its quotes and syntax, for example payee:"Coffee" or #trip.`

## Root cause

`dashboard/src/common/lib/errors/error-message.ts:61-62` recognises filter diagnostics by message prefix:
`/^(?:Illegal character|Trailing tokens|Unexpected end of filter|Unexpected token|Expected .+, got|Expected : or comparison|Filter pattern exceeds)/`.
`backend-cluster/ledger/src/foundation/rustledger/directive-filter.ts` later gained three messages that match none of these: the stray-quote error (line ~441, `3b1c3dec8`, w23/m2/t003) and the two `throwForMistakableValue` hints (lines ~655 and ~662, `092aebc27`, w23/m2/t006). They fall through to the `BAD_USER_INPUT` → `common.errors.badUserInput` mapping.

## Fix

- Add `Unterminated or misplaced quote` and `Unexpected .+ after "` to `ADVANCED_FILTER_ERROR`, so all three map to `common.errors.invalidFilterExpression` (whose text already names quotes and `#trip`). Keep the rule that raw server text is not shown.
- Extend `dashboard/src/common/lib/errors/__tests__/error-message.test.ts` (the list near line 148) with the three exact ledger messages, and leave a comment in `directive-filter.ts` next to `AdvancedFilterParseError` pointing at the dashboard classifier so the next new message updates both.

## Blast radius

The 25 non-test `dashboard/src` files using `getErrorMessageKey`, including every view that renders ledger reads with the header filter (journal, income statement, balance sheet, trial balance, cash flow, account pages). Mobile and CLI carry no copy of this classifier. Time-filter errors (`Failed to parse date:`) are unaffected.

## Adjacent

The numeric hint quotes only the leading number token: for `payee:7eleven` it suggests `payee:"7"`, not `payee:"7eleven"` (ledger `throwForMistakableValue` receives the tokenized `NUMBER` only). GraphQL returns that text verbatim (REST and MCP not checked). Worth a ledger-side follow-up if the hint should echo the whole value; it does not change the dashboard fix above.

## Unverified

Other locales (same key path, expected identical). Balance sheet, trial balance and account routes were not opened individually; they share the same classifier.

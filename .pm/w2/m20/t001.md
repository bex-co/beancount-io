## Objective

Prove the live backend inventory is partitioned exhaustively among one executable action catalog, transport aliases/operational classes, and explicit non-business ingress/authentication/public exclusions.

## Context

- The baseline inventory has 143 verbs and 241 GraphQL/REST/MCP aliases, but implementation may add or remove operations before this milestone.

## Steps

1. Regenerate/inspect the live operation inventory; validate each protected alias maps to exactly one action and its operational rate class/override cannot grant reachability.
2. Require an explicit reason for public, authentication, webhook, metrics/admin, or infrastructure exclusions and distinguish them from relationship denial.
3. Require every action's credential ceiling, relationship, audit class, denial/concealment, and resource type in the single TypeScript catalog; fail on missing/duplicate/transport-only mappings or a second policy source.

## Files

- `backend-cluster/backend-v2/src/server/api/op-class.ts`
- `backend-cluster/backend-v2/src/server/api/always-public.ts`
- `backend-cluster/backend-v2/src/server/api/authorization/**`
- operation/surface coverage tests

## Acceptance criteria

- [ ] Every live operation is accounted for exactly once.
- [ ] Exclusions state their real authentication/ingress boundary.
- [ ] A newly registered protected operation fails closed until mapped.
- [ ] `.fga` contains only durable relationship semantics and changes with runtime only when those semantics change.

## Out of scope

- Adding new endpoints, grants, policy files, or OpenFGA runtime components.

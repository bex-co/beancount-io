# `bea` passthrough commands advertise an empty argument surface in `--help` and `REFERENCE.md`

Found 2026-09-12 by a CLI QA sweep against HEAD `84231f9c`, bea 0.2.0. Sub-hour fix across three files plus `make docs`.

Every delegated command — the eleven `bea doctor <op>` operations plus `dump-lexer`, `bea example`, `bea treeify` — forwards `ctx.args` to upstream but declares no Click parameters, so its help lists nothing:

```
$ bea doctor lex --help
Usage: bea doctor lex [OPTIONS]

  Run bean-doctor lex.

Options:
  -h, --help  Show this message and exit.

$ bea doctor lex
Usage: bean-doctor lex [OPTIONS] FILENAME
Error: Missing argument 'FILENAME'.        # exit 2

$ bea example --help
Usage: bea example [OPTIONS]
Options:
  -h, --help  Show this message and exit.
$ bea example -- --help
Usage: bean-example [OPTIONS]
  --date-begin DATE / --date-end DATE / --date-birth DATE / -s, --seed INTEGER
  --no-reformat / -o, --output FILENAME / -v, --verbose BOOLEAN
```

So `bea example --help` hides the very flags `cli/docs/USAGE.md:213` demonstrates (`bea example --seed 1 -o example.beancount` — it works), and `bea doctor lex --help` hides a *required* positional. The generated `cli/docs/REFERENCE.md:661-745` repeats the same empty surface, though `cli/CLAUDE.md:91` bills it as "generated `docs/REFERENCE.md` for every flag". The escape hatch `bea doctor lex -- --help` reaches upstream's real help, but nothing anywhere mentions it.

Second-order: `bea --help` groups `doctor` under "Local ledger commands (work on .bean files)", yet these commands ignore all three target sources `cli/docs/USAGE.md:95-101` defines for local commands — `--file`, `BEA_FILE`, and `./main.bean` are all silently dropped in favour of a positional filename. USAGE.md documents that exception for `init` and `format` (`USAGE.md:103-105`) but not for `doctor`.

```
$ bea --file /abs/main.bean doctor lex      # exit 2, "Missing argument 'FILENAME'"
$ BEA_FILE=/abs/main.bean bea doctor lex    # same
$ bea doctor lex /abs/main.bean             # works
```

- Root cause: `cli/src/cli/commands/doctor.py:32-52` and `cli/src/cli/commands/example.py:9-14` register callbacks taking only `ctx: typer.Context` with `allow_extra_args` / `ignore_unknown_options`. Click therefore has no parameters to render, and `cli/scripts/gen_reference.py` reads the same empty metadata into `docs/REFERENCE.md`. `treeify` is registered the same way.
- Fix: declare the forwarded tail as a variadic `typer.Argument` on each passthrough (usage line becomes `[ARGS]...`) and put the upstream-help pointer in the command docstring, e.g. "Run bean-doctor lex. Pass `-- --help` for upstream's own options; the ledger file is a positional argument, not `--file`." Then run `make docs` so `REFERENCE.md` regenerates, and add the `doctor`/`example`/`treeify` targeting exception to the `USAGE.md:103-105` list.
- Why it matters (A1): agents discover this CLI by reading `--help` and `REFERENCE.md`. Both currently state that `bea example` takes no arguments and `bea doctor lex` needs no file. `.claude/skills/qa-find-bugs-cli` itself instructs "Discover commands and flags from `bea --help` and subcommand help before scripting them".
- Dedupe: `w1/done/m19/done/t006.md` ("Expose the complete bean-doctor command group") satisfied its DoD — all eleven operations *are* discoverable at the group level via `bea doctor --help`. This refines that work at the operation level; not a regression of it. `git log -S allow_extra_args -- cli/src/cli/commands/doctor.py` shows the shape introduced by `a90b1706` (ADR014) and unchanged since — present on main, not deployment lag.

## Also found (one-line fix, same area)

`bea import --apply` writes `Wrote 1 entries to …` — `cli/src/cli/commands/import_.py:417` interpolates the count into a hardcoded plural. `bea add transaction` gets this right ("Added 1 transaction"), so import is the lone outlier. Compare the related MCP note in `w2/010.md` ("Add 1 entries").

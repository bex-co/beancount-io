4. Terminate/relaunch at the same maximum text size and reopen the real Checking destination using `beancount:///(app)/account-detail?account=Assets%3AUS%3ABofA%3AChecking`. The settled default `6M` row has the same clipping. Light appearance repeats it. The development warning banner is below the affected row.
5. Open Reports with `beancount:///(app)/(tabs)/reports`. Its settled `6M` row repeats the same four visible choices. Dismissing the development warning leaves the failure intact. This step proves the Reports destination; the account journey in steps 1–3 used actual list navigation.
6. Restore system `large` text and light appearance, then relaunch. The settled Reports control shows all six choices again, as in the original account control. Changing system font size while the screen remains mounted can retain the old wide layout, so use this fresh control rather than the intermediate restoration capture.

# Smart Import books the same CSV twice without noticing

**Minor (data quality) · dashboard · 60–90 minutes; may need promotion to a milestone.** A2: bank exports routinely overlap (last month's file and this month's share days), and re-uploading a file is an easy mistake. Smart Import has no duplicate check, so every overlapping row becomes a second transaction. The customer `beancount-import` skill already solves this with an `import-id` convention ([w2/m6](./done/m6/README.md)), but the web importer does not.

Production https://beancount.io, 2026-11-10, English, isolated headless Chromium 156 at 1440×1000, signed in as the owner of the designated synthetic ledger. One import was submitted, then removed; main.bean was restored to blob `f1a0b83c`. The second import was not submitted. Local main `310fc45c3`.

## Reproduce

1. `/ledger/<o>/<l>/import`, then upload:

   ```csv
   Date,Payee,Description,Amount
   2026-09-02,qa-imp-a,coffee,-3.25
   2026-09-03,qa-imp-b,bus,-2.75
   ```

   Continue → Source `Assets:Cash`, targets `Expenses:Food:Coffee` / `Expenses:Transport` → **Import 2 Transactions**. Result: "Successfully imported 2 transactions"; both entries are appended once ✓.
2. Upload the **same file** again and Continue to Configure.

**Actual:** Preview and Configure show both rows selected with no hint that matching entries (same date, amount, source account and payee) are already in the ledger. **Import 2 Transactions** is enabled, and submitting would book both a second time.

**Expected:** rows that already exist are flagged ("Already in the ledger on 2026-09-02") and left unselected by default. The reader can still include them deliberately.

## Root cause

`dashboard/src/features/importer` has no duplicate detection: there is no "duplicate" or "dedup" logic outside tests and locales. Rows are written through `BulkEntries` as new entries. Nothing like the skill's `import-id` metadata or a date/amount/account match is consulted.

## Fix

**Minimum, client-only:**
- On entering Configure, read the source account's journal for the file's date range (one `GetLedgerJournal` call with `account` + `time`).
- Mark a row as a likely duplicate when an existing transaction on the same date has a posting to the source account with the same amount; a payee or narration match raises confidence.
- Show the mark in the row, unselect it by default, and add a "Show duplicates" filter.

**Better, aligned with the skill:** write an `import-id` (a stable hash of date, amount, payee, description and source account) as transaction metadata, and treat a matching `import-id` as a definite duplicate. If the server adopts the same check, keep REST/GraphQL/MCP parity per the root AGENTS.md rule.

Add a test with the two-row fixture imported twice.

## Blast radius

CSV, OFX and AI-parsed (PDF/image) imports all reach the same Configure step. Bank sync (Plaid) staging has its own flow and is out of scope.

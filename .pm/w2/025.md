# `bea add transactions --from` leaks raw `OSError` text and classifies input failures inconsistently

Found 2026-09-12 by a CLI QA sweep against HEAD `84231f9c`, bea 0.2.0. Sub-hour fix.

`--from` is the only path-taking option in the CLI that surfaces Python's errno string instead of a phrased message, and it splits the same class of failure across two exit categories:

```
$ bea --file main.bean add transactions --from /nope.json
Error: [Errno 2] No such file or directory: '/nope.json'          # exit 2

$ bea --file main.bean add transactions --from /some/dir
Error: [Errno 21] Is a directory: '/some/dir'                     # exit 1

$ printf '{"date":"2024-03-09"}' | bea --file main.bean add transactions --from -
Error: JSON file must contain an array of transactions.           # exit 1

$ printf '{not json' | bea --file main.bean add transactions --from -
Error: Invalid JSON at line 1, column 2: Expecting property name enclosed in double quotes.   # exit 2
```

Every comparable option phrases its own errors and stays in the usage category:

| Option | Missing path | Directory given |
| --- | --- | --- |
| `--file` | "No ledger file at '…' (from --file). Name one with --file PATH, set BEA_FILE, or run from a directory containing main.bean." — exit 2 | "Ledger path '…' is a directory; expected a ledger file. Point --file to its root ledger…" — exit 2 |
| `--config` | "Importer configuration not found: /path" — exit 2 | — |
| `import SOURCE` | "Export file not found: /path" — exit 2 | — |
| `--from` | `[Errno 2] No such file or directory: '…'` — exit 2 | `[Errno 21] Is a directory: '…'` — **exit 1** |

Per the table at `cli/docs/USAGE.md:120-128`, exit 2 is "Bad arguments, missing target, missing extra…" and exit 1 is "Ledger or validation error, and the catch-all for any other runtime failure". A directory passed to `--from`, and a JSON document of the wrong shape, are both bad input — neither is a ledger error. A script branching on the exit code currently cannot distinguish "your JSON was malformed" from "your ledger did not validate".

- Root cause: `cli/src/cli/commands/add.py:447-452`. `from_file.read_text()` is inside the `try`, but only `json.JSONDecodeError` is caught (→ `UsageError`, exit 2). `FileNotFoundError`/`IsADirectoryError` fall through to the generic top-level handler, which renders `str(exc)` — the `[Errno N]` text — and classifies them differently from each other. The shape check on the next line raises `LedgerError` (exit 1) rather than `UsageError`.
- Fix: declare the option as `typer.Option("--from", exists=True, dir_okay=False, ...)` so Click rejects a missing path or a directory with its own phrasing at exit 2 — matching `--file` — and change the `isinstance(raw, list)` failure from `LedgerError` to `UsageError`. Keep `-` working as stdin: guard the existence check on `str(from_file) != "-"`, or keep an explicit phrased check instead of Click validation if that is simpler.
- Blast radius: `--from` is unique to `add transactions`. The stdin path (`--from -`) already behaves correctly and must keep exit 2 for malformed JSON.
- Dedupe: `w2/done/m24/done/t005.md` and `t011.md` specified `--from`'s *row* validation (invalid row → byte-identical file, exit 1, `--partial`), all of which still holds — verified this run. Neither covers input-file or JSON-shape failures. `git log -S 'must contain an array of transactions'` shows the line added by `00a0ce22` and unchanged since — present on main, not deployment lag.

## Verified correct while probing this (no action needed)

- Identical rows in one CSV get distinct `import-id` occurrence hashes (`csv:sha256:a2771fe5…` vs `…a76538db…`) once `--duplicates include` is chosen, and re-importing the file then skips all three rows as exact duplicates at exit 0 — the `IMPORTING.md:230-231` claim holds end to end.
- Duplicate review never prompts: a possible duplicate exits 4 with the same message under a pipe and under a real TTY, matching `USAGE.md:107`.
- `list --from-date/--to-date` are inclusive on both ends; a reversed range and a malformed date both exit 2 with phrased messages.
- `--from -` stdin, empty array (writes 0, exit 0), and `null`/non-object arrays all behave sensibly apart from the classification above.

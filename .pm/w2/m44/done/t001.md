## Objective

Read the current Claude Code plugin and marketplace documentation and the current Codex plugin documentation. Then choose where each manifest lives, how it points at `skills/`, and the plugin's name. Record the decision, with the doc sections it rests on, in this task's `## Decision` section before t002 and t003 start.

## Context

- After m42, the suite is at `skills/<name>/SKILL.md`, and m42's guard rejects any directory in `skills/` without a `SKILL.md`. A `.claude-plugin/` folder inside `skills/` would fail it. The candidate is a repository-root `.claude-plugin/marketplace.json` whose plugin entry has `"source": "./skills"` and declares its skills inline or by path. Confirm that the format accepts a plugin entry without its own `plugin.json` under that source.
- 2026-10-18 research, to re-check rather than assume: a self-hosted marketplace can be added with a sparse fetch (`claude plugin marketplace add <repo> --sparse …`), so users do not clone the 10,000-file monorepo. A plugin name may not start with `claude-`. A bare `beancount` name risks a brand hold in directory review, so the proposed name is `beancount-io`. Codex reads `.codex-plugin/plugin.json`, with a `skills` path, and ChatGPT also reads `.claude-plugin/marketplace.json`.
- Root `AGENTS.md` forbids parallel copies, and requires equivalent Codex behavior for any platform-specific configuration. `.agents/` holds development skills only. If Codex's marketplace file would live under `.agents/plugins/`, check that it cannot be mistaken for a development skill, and that `CI (skills)` and `check-agent-guidance.py` still describe the tree correctly.
- The repository root also holds `.mcp.json` and `.claude/settings.json` for contributors. Neither may end up inside the plugin.

## Decision (2026-10-19)

Both clients take **one plugin named `beancount-io`** (namespace `/beancount-io:beancount-ask` on Claude Code, `beancount-io:beancount-ask` on Codex), versioned `0.1.0` at first ship and bumped manually in both manifests in lockstep. No file is added inside `skills/`; the nine `beancount-*` folders stay the single source for every channel.

- **Claude Code — `.claude-plugin/marketplace.json` at the repository root.** One entry: `name: "beancount-io"`, `source: "./skills"`, `version`, `description`, and `skills: ["./beancount-add", …]` (all nine, relative to the plugin root `skills/`). There is no `plugin.json`: per the marketplace reference ("How an entry combines with plugin.json"), with no `plugin.json` the entry *is* the manifest. Docs: [Create a marketplace](https://code.claude.com/docs/en/plugin-marketplaces), [Marketplace reference](https://code.claude.com/docs/en/plugins/marketplace-reference) (plugin entries, relative-path sources resolved from the marketplace root, strict mode). Users add it with `claude plugin marketplace add bex-co/beancount-io --sparse .claude-plugin skills` so they never clone the monorepo (marketplace-source `sparsePaths`), then `claude plugin install beancount-io@beancount-io`.
- **Codex — `.agents/plugins/marketplace.json` at the repository root + portable `plugin.json` at the repository root.** The portable layout's fixed paths fit this repository as-is: plugin root = repository root, `plugin.json` (`$schema` agent-plugins 1.0.0, `name`, `version`, `description`, `license: "MIT"`, keywords) at the root, its fixed `skills/` directory is the existing suite. The marketplace entry is `source: {"source": "local", "path": "./"}` with the docs' `policy` block. Docs: [Package your plugin](https://developers.openai.com/codex/plugins/build) (Plugin structure, Path rules, "Build your own curated plugin list", CLI marketplace add with `--sparse`). `.agents/plugins/` cannot be mistaken for a development skill (those are `.agents/skills/*/SKILL.md`; `check-agent-guidance.py` constrains only the skills tree and the `.claude/skills` link), and Codex also discovers the `.claude-plugin/marketplace.json` above as a legacy-compatible marketplace, so the two files are consistent, not competing. Users: `codex plugin marketplace add bex-co/beancount-io` (sparse: `.agents/plugins`, `plugin.json`, `skills`), then `codex plugin add beancount-io@beancount-io`.
- **Not inside the plugin:** the repository-root `.mcp.json` and `.claude/settings.json` are contributor configuration; neither manifest references them and the Codex install cache was observed to contain only `plugin.json` + `skills/` (804K), the Claude install only the nine skill components.
- **Versioning:** Claude treats the entry `version` as the plugin version for updates; Codex reads `plugin.json` `version` (its cache is version-keyed). Bump both together in the t002/t003 commits and on every later suite change that should reach plugin users.

**Prototype evidence (2026-10-19, scratch copy under `scripts/skills/tmp/m44/proto`, registrations removed afterwards):** `claude plugin validate` passed; marketplace add + install + `claude plugin details` showed exactly the nine skills, and a fresh session listed `beancount-io:beancount-*` ×9. Codex marketplace add + `codex plugin add` installed to its cache (only `plugin.json` + `skills/`, 804K) and a fresh session's client-side catalog listed `beancount-io:beancount-*` ×9 from the plugin — no development skill on either client. No model answer was taken from Codex (usage limit); listing is client-side.

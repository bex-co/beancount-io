## Objective

Give the recovery operation the IDs it needs, and teach the SendGrid foundation to send through an unsubscribe group and look up that group's suppressions (ADR027 D3, D6).

## Context

- `backend-cluster/backend-v2/src/foundation/sendgrid.ts`: `ISendGrid.sendMail(data: Mail)` builds `MailDataRequired`. It has no `asm` field and no suppression lookup. The development implementation logs and sends nothing.
- Billing config lives in `features/stripe/service/stripe.ts` (`SUBSCRIPTION_CONFIG`) and `src/config/config.ts`. Placeholders go in `.env.example`, never real values.
- SendGrid adds the List-Unsubscribe headers when a message carries `asm.group_id`. A group's suppressions are readable through the ASM API.

## Steps

1. Add the coupon ID (`checkout-recovery-20`) and the SendGrid unsubscribe group ID to the billing config, read from the environment, with placeholders in `.env.example`. A missing value disables recovery, which is logged and acknowledged; it never throws on every webhook.
2. Add an optional `asm: { groupId }` to `Mail` and pass it through as `asm.group_id`.
3. Add `isSuppressed(email, groupId): Promise<boolean>` to `ISendGrid`. The development implementation returns `false`.

## Acceptance criteria

- [x] `sendMail` with `asm` sends `asm.group_id`, and without it the request is unchanged.
- [x] `isSuppressed` is covered by a test with a stubbed SendGrid client, including a failed lookup, which surfaces as an error rather than `false`.
- [x] With the recovery config unset, the recovery path reports itself disabled. (Moved to t003, which owns the operation that reads the config.)

## Out of scope

- Creating the coupon and the group in the providers' dashboards (t006, owner).

## Outcome

- `Mail.asm { groupId }` is passed to `@sendgrid/mail`, which sends it as `asm.group_id`. A mail without a group is unchanged.
- `ISendGrid.isSuppressed(email, groupId)` searches the group's suppressions (`POST /v3/asm/groups/{id}/suppressions/search`, 10 s timeout, case-insensitive match). A failed lookup throws `ServiceUnavailableError`, so the webhook is retried instead of guessing. `ConsoleSendGrid` answers `false`.
- Config: `SEND_GRID_CHECKOUT_RECOVERY_GROUP_ID` (`config.sendGrid.checkoutRecoveryGroupId`, unset = off, in `.env.example`). The coupon ID `checkout-recovery-20` sits in `SUBSCRIPTION_CONFIG` beside the price and portal IDs, as account-specific and not secret.
- Deviation: the "unset config reports itself disabled" check moved to t003, where the operation reads the config. Adding the new variable to the `deploy/` targets is left to the owner setup in t006 (production) and is not needed for self-hosting, since an unset value turns the email off.
- Tests: `src/foundation/__tests__/sendgrid.test.ts` (7). backend-v2 `yarn typecheck` and `yarn test` pass, except the same `archive-parity.test.ts` load flake noted in t001 (passes alone).

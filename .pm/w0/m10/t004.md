## Objective

Give Docker self-hosters the steps to move a ledger into their stack from another self-hosted stack or from beancount.io, the question #176 item 3 asked, and run them once.

## Context

- PRFAQ006 question 15 and `deploy/bex/README.md`, "Back up and restore", have the steps for bex: create a ledger in the dashboard, merge the files or Git history into it, and push, signed in with `bea cloud git setup` or a personal access token with `ledger.write`. A forced push is refused, so history goes in as a merge. The ledger reads `main.bean`. Accounts, API keys, settings and uploaded receipts do not move.
- On the Docker targets, Gitea has its own `GIT_DOMAIN`, and Git over SSH is the optional overlay (`deploy/docker/README.md`, "Git over SSH").
- `.pm/DO_NOT_DO.md`, "No hosted-ledger export without SSH setup": export from the hosted beancount.io goes through `bea cloud ledger clone`, which needs the user's SSH key. Do not describe an export that avoids it.

## Steps

1. Add a "Bring books in" section to `deploy/docker/README.md`, adapted from the bex steps, with the Docker clone addresses (HTTPS on `GIT_DOMAIN`, or SSH with the overlay).
2. Say what does not move (accounts, API keys, settings, uploaded receipts), and that two stacks are brought together ledger by ledger.
3. Link it from `deploy/docker-single-psql/README.md`.
4. Run it once on a local Docker stack (`deploy/docker-mac` is fine): create a ledger, merge another ledger with its own history into it, push, and run `checkLedger` or `bea check`. Record the result and date in this task's text.

## Objective

Finish the operation: claim once per person, create the code, render, send, and undo cleanly on failure (ADR027 D3, D4, D7).

## Context

- `sentBillingEmail.claim(db, key)` / `release(db, key)` (`features/stripe/data/sent-billing-email-model/`). `sendBillingEmailOnce` renders before claiming, so this operation calls the model directly.
- On the pinned API version `2025-12-15.clover`, `promotionCodes.create` takes `promotion: { type: "coupon", coupon }`, not a top-level `coupon`.
- `planName` (in `billing-email.ts`) prints "Premium · Yearly". The shared footer has an `unsubscribeUrl` parameter.

## Steps

1. Claim `checkout-recovery:<userId>`. If it is already taken, return `already-sent`.
2. Create the promotion code: `max_redemptions: 1`, `expires_at` now + 48 h, `restrictions.first_time_transaction: true`, `customer` when the session had one, and `metadata: { userId, sessionId, source: "checkout-recovery" }`.
3. Render subject "Your <tier> plan is still waiting" and three body lines: that their plan is saved, the code for 20% off the first month or year that expires in 48 hours, and a Finish checkout link (recovery URL, else the pricing URL `checkoutCancelUrl` builds). Then the footer with the unsubscribe link. Plain HTML and text, no images or tracking.
4. Send with `asm` set. On any failure after the claim, set the code `active: false` if one was created, release the claim, and rethrow.

## Acceptance criteria

- [ ] Two expired sessions for one user produce one code and one mail.
- [ ] A failed send deactivates the code and releases the claim, and a redelivery then sends.
- [ ] The rendered text body has exactly three content lines before the footer, and says "48 hours", not a date.

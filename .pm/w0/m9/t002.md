## Objective

Give the recovery operation the IDs it needs, and teach the SendGrid foundation to send through an unsubscribe group and look up that group's suppressions (ADR027 D3, D6).

## Context

- `backend-cluster/backend-v2/src/foundation/sendgrid.ts`: `ISendGrid.sendMail(data: Mail)` builds `MailDataRequired`. It has no `asm` field and no suppression lookup. The development implementation logs and sends nothing.
- Billing config lives in `features/stripe/service/stripe.ts` (`SUBSCRIPTION_CONFIG`) and `src/config/config.ts`. Placeholders go in `.env.example`, never real values.
- SendGrid adds the List-Unsubscribe headers when a message carries `asm.group_id`. A group's suppressions are readable through the ASM API.

## Steps

1. Add the coupon ID (`checkout-recovery-20`) and the SendGrid unsubscribe group ID to the billing config, read from the environment, with placeholders in `.env.example`. A missing value disables recovery, which is logged and acknowledged; it never throws on every webhook.
2. Add an optional `asm: { groupId }` to `Mail` and pass it through as `asm.group_id`.
3. Add `isSuppressed(email, groupId): Promise<boolean>` to `ISendGrid`. The development implementation returns `false`.

## Acceptance criteria

- [ ] `sendMail` with `asm` sends `asm.group_id`, and without it the request is unchanged.
- [ ] `isSuppressed` is covered by a test with a stubbed SendGrid client, including a failed lookup, which surfaces as an error rather than `false`.
- [ ] With the recovery config unset, the recovery path reports itself disabled.

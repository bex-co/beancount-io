## Objective

Make the session's expiry the recovery timer (ADR027 D1) and turn on Stripe's recovery URL (D3) for every session `createSubscriptionSession` creates.

## Context

- `backend-cluster/backend-v2/src/features/stripe/service/subscription-service.ts`: `sharedSession` carries `line_items`, `allow_promotion_codes`, `mode`, the URLs, and `metadata: { userId, clientId }`. Today it sets no `expires_at`, so Stripe's 24-hour default applies.
- Stripe accepts `expires_at` between 30 minutes and 24 hours after creation.
- ADR027 D6: sessions do **not** set `consent_collection`.

## Steps

1. Add `expires_at: now + 90 minutes` (Unix seconds) and `after_expiration: { recovery: { enabled: true, allow_promotion_codes: true } }` to `sharedSession`.
2. Read the clock through an injectable source, or the existing pattern in the service's tests, so tests can pin the value.
3. Extend the existing session-creation tests to assert both parameters, for the `customer` and `customer_email` branches.

## Files

- backend-cluster/backend-v2/src/features/stripe/service/subscription-service.ts
- its existing tests

## Acceptance criteria

- [x] Both session branches send `expires_at` exactly 90 minutes after the injected now, plus the recovery block.
- [x] No `consent_collection` is sent.

## Out of scope

- Handling the expired event (t005).

## Outcome

- `sharedSession` sets `expires_at` from `CHECKOUT_SESSION_LIFETIME_SECONDS` (90 × 60) and `after_expiration.recovery { enabled, allow_promotion_codes }`. That covers both the `customer` and `customer_email` branches, and store-switch sessions too.
- Test: `subscription-service-checkout-session.test.ts` pins both branches with a fake clock.
- Gates: backend-v2 `yarn typecheck` and `yarn test` pass (9,430 tests; `archive-parity.test.ts` failed once under full-suite load and passes alone with and without this change). `yarn lint` reports two errors that already exist on main in untouched files (`account-matcher.ts`, `mcp-hostile-values.test.ts`).

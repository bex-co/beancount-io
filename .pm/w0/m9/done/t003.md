## Objective

Start `features/stripe/operations/checkout-recovery-email.ts` with the read-only checks that decide whether an expired session earns an email (ADR027 D2, D5).

## Context

- The expired session carries `metadata.userId`, `metadata.clientId`, the price in its line items (fetch them with `expand` if the event lacks them), `customer` when one was set, `created`, and `after_expiration.recovery.url`.
- Plans and `retired` come from `SUBSCRIPTION_CONFIG`. Paid history comes from `paid_customers` and Stripe subscriptions, as `get-user-tier.ts` and `subscriptionTier` read them. "Never paid" includes ended subscriptions.
- `checkout.sessions.list` filters by `created`, `customer`, `customer_details` and `status`, never by metadata. Match `metadata.userId` in code.

## Steps

1. Return a typed reason for each ineligibility: no user or email, unknown or retired plan, paid before, later session `complete` or `open`, suppressed address, recovery disabled (`config.sendGrid.checkoutRecoveryGroupId` unset, moved here from t002).
2. Find later sessions with `created >= expired.created` (plus `customer` when present), paginate, keep those for the same user other than the expired one, and stop if any is `complete` or `open`.
3. Check the suppression list last (it costs a SendGrid call).

## Acceptance criteria

- [x] Each ineligibility has a test that returns its reason with no claim, no code, and no mail.
- [x] A later `open` or `complete` session for another user does not block the email.

## Out of scope

- The claim and the send (t004).

## Outcome

- `recoveryEligibility(deps, session, clientId)` in `features/stripe/operations/checkout-recovery-email.ts` returns `eligible` with the user, email, plan, and group. Otherwise it returns one of `disabled`, `no-recipient`, `unknown-plan`, `paid-before`, `back-in-checkout`, `unsubscribed`. It reads only: nothing is claimed, created, or sent. A provider failure propagates, so Stripe redelivers instead of a skip or a guess.
- The plan comes from `checkout.sessions.listLineItems`, because the expired event carries no line items. Retired prices and prices that are not ours are refused.
- "Paid before" means any Stripe subscription that left `incomplete`/`incomplete_expired`, current or ended. Deviation: an app-store subscription (ADR001) also counts. The ADR's rule is "first purchase only", and a store subscriber has bought.
- Later sessions are listed with `created >= expired.created` (plus `customer` when known), auto-paginated, and matched on `metadata.userId` in code. A `complete` or `open` one stops the email.
- Tests: `operations/__tests__/checkout-recovery-eligibility.test.ts` (18). backend-v2 `yarn typecheck`, `format:check`, and `lint:deadcode` pass. `yarn test` passes, except the `archive-parity.test.ts` timeout that occurs only in the full run (it passes alone and in the 8,320-test `ai-agent` subset).

# 057 — docker-mac's HTTP clone address goes to Gitea, which takes no Beancount.io credential

Found during w0/m10/t004 (2026-11-25). On a local `deploy/docker` stack, every ledger's `httpUrl` named Gitea's own address, `https://<GIT_DOMAIN>/<owner>/<ledger>.git`, and Gitea refused both a personal access token and the account password there. Only backend-v2's Git proxy (`/git/<owner>/<ledger>.git` on the API) signed in. w0/m10 set `GIT_PUBLIC_URL=https://${API_DOMAIN}/git` in `deploy/docker` and `deploy/docker-single-psql`, so their ledgers name the proxy.

`deploy/docker-mac` has the same shape: `EXTERNAL_GITEA_HOST_NAME=localhost` and `EXTERNAL_GITEA_HTTP_PORT=42602` (Gitea's published port), no `GIT_PUBLIC_URL`, and its README's port table lists `http://localhost:42602` for "HTTP clone". Not yet reproduced on docker-mac itself.

- **Check:** on docker-mac, `git clone` a ledger's `httpUrl` with a personal access token as the password.
- **If refused:** pass `GIT_PUBLIC_URL=http://localhost:42601/git` (backend-v2's published port; plain http is accepted for localhost outside production) and correct the README's port table.
- **Or, at the root:** the backend builds `httpUrl` from Gitea's own address whenever `GIT_PUBLIC_URL` is unset (`externalGiteaBase` in `backend-cluster/backend-v2/src/shared/gitea-utils.ts`), so one host value serves both as the SSH host and as the HTTPS base. Defaulting the HTTPS base to the API's own `/git` on any stack that is not the managed service would fix docker-mac and make the per-target `GIT_PUBLIC_URL` unnecessary. It needs a reliable "not managed" signal, and `SELF_HOST` is not one (it is blank by default in the Docker `.env.example` files).
- **Done when:** on docker-mac, a ledger's `httpUrl` clones with a personal access token, and the dashboard's Git Clone menu shows that address.

---

**Resolved 2026-11-25** — Reproduced on a local docker-mac stack: a ledger's `httpUrl` was `http://localhost:42602/<owner>/<ledger>.git`, where Gitea refused a personal access token and the account password alike, while backend-v2's proxy at `http://localhost:42601/git/...` took both. docker-mac now sets `GIT_PUBLIC_URL` to `${SERVER_URL}/git` (`http://localhost:42601/git` by default) and drops the inert `EXTERNAL_GITEA_HTTP_PORT`. After recreating backend-v2, the ledger's `httpUrl` and the dashboard's Git Clone menu named the proxy, a token (`ledger.read`, `ledger.write`) cloned and pushed, and the SSH address was unchanged. The README's port table and a new "Git over HTTP" section give the address, and `scripts/check-docker-targets.py` (run by `CI (deploy)`, which now also renders docker-mac's Compose file) fails if the address goes back to Gitea's port. The backend default the note also offered was not built: there is still no reliable signal for a stack that is not the managed service, and every Docker target and bex now sets the address itself (`deploy`).

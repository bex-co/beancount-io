## Objective

Add meaningful tests for what this milestone shipped. They must assert real behavior and failure modes, never trivial, tautological or snapshot-everything checks.

## Context

- The derivation is covered by `backend-cluster/backend-v2/src/config/jwks/index.test.ts`. What is new is the wiring: two Compose files and two `.env.example` files that must keep passing the flag and setting it for new installs.
- `CI (deploy)` covers only `bex.yaml` and `deploy/bex/**` today. The Docker targets have no automated check beyond `docker compose config`.

## Steps

1. Add a check that fails if either Docker target stops passing `OAUTH_JWKS_FROM_AUTH_SECRET` to backend-v2, or if either `.env.example` stops setting it to `true`. For example, a small script beside `scripts/check-bex-blueprint.py`, with its own test, run where the repository already runs deploy checks.
2. Make it fail on a fixture that drops the line, and pass on the real files.

## Acceptance criteria

- [x] The check fails when the pass-through or the `.env.example` default is removed from either target, and passes on `main`.
- [x] It runs in an existing CI workflow or a documented validation command in `deploy/AGENTS.md`.

## Result (2026-11-25)

`scripts/check-docker-targets.py` reads each target's Compose file and `.env.example` as text and fails when backend-v2 is not passed `OAUTH_JWKS_FROM_AUTH_SECRET` from `.env` with no default (dropped, commented out, moved to another service, hard-coded or defaulted to `true`, which would turn OAuth on for an older `.env`), when `.env.example` does not set it to `true`, when `.env.example` carries an `OAUTH_JWKS` value, or when backend-v2's `GIT_PUBLIC_URL` is not `https://${API_DOMAIN}/git`. `scripts/test_check_docker_targets.py` (11 tests) runs each of those changes against both real targets and checks that each fails alone, and that the real files pass. With the pass-through deleted from the real `docker-single-psql` Compose file, 13 subtests failed; restored, all passed. A copy of each target without the `.env.example` line exits 1. `CI (deploy)` gains a "Docker targets" job, triggered by `deploy/docker/**` and `deploy/docker-single-psql/**`, that runs the check, its tests, and both Compose renders (base and SSH overlay); `deploy/AGENTS.md` documents the command and the root `AGENTS.md` lists the job.

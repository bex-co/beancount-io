## Objective

Give `deploy/docker` and `deploy/docker-single-psql` the signing-key derivation bex already uses, so a new install gets working OAuth (mobile app sign-in, OAuth MCP hosts) from the `AUTH_SECRET` it already has to set.

## Context

- `backend-cluster/backend-v2/src/config/jwks/index.ts` derives the key from `AUTH_SECRET` when `OAUTH_JWKS_FROM_AUTH_SECRET` is exactly `true` and `OAUTH_JWKS` is unset. A supplied `OAUTH_JWKS` always wins (`backend-cluster/backend-v2/README.md`, the OAuth deployment contract).
- The root `bex.yaml` sets `OAUTH_JWKS_FROM_AUTH_SECRET: "true"` for the API service.
- `deploy/docker/docker-compose.yml` and `deploy/docker-single-psql/docker-compose.yml` pass `OAUTH_JWKS: ${OAUTH_JWKS:-}` and nothing else. Their `.env.example` files leave `OAUTH_JWKS=` empty and say only "Generate a keyset offline".

## Steps

1. In both compose files, pass `OAUTH_JWKS_FROM_AUTH_SECRET: ${OAUTH_JWKS_FROM_AUTH_SECRET:-}` to backend-v2, beside `OAUTH_JWKS`. Unset stays off, so an existing `.env` behaves as before.
2. In both `.env.example` files, add `OAUTH_JWKS_FROM_AUTH_SECRET=true` beside `OAUTH_JWKS=`. Its comment says: the key is derived from `AUTH_SECRET`; a supplied `OAUTH_JWKS` wins; rotating `AUTH_SECRET` rotates the key and signs OAuth clients out; without either, OAuth answers 503.
3. Keep the two targets in step, as `deploy/AGENTS.md` requires.

## Files

- `deploy/docker/docker-compose.yml`, `deploy/docker/.env.example`
- `deploy/docker-single-psql/docker-compose.yml`, `deploy/docker-single-psql/.env.example`

## Acceptance criteria

- [ ] `docker compose --env-file .env.example config --quiet` passes in both directories, and the SSH-overlay variant from `deploy/AGENTS.md` still passes.
- [ ] `docker compose --env-file .env.example config` renders `OAUTH_JWKS_FROM_AUTH_SECRET: "true"` in backend-v2's environment for both targets.
- [ ] Rendered with a `.env` that lacks the variable, backend-v2's value is empty.

## Out of scope

- Changing the backend's derivation or its defaults.
- `deploy/docker-mac`, which uses an ephemeral development key.

## Objective

Make the Docker READMEs tell a self-hoster, in order, that OAuth works out of the box, what to type into the mobile app, and where an MCP host connects.

## Context

- `deploy/docker/README.md`, "OAuth signing key", says to set `OAUTH_JWKS` to a JWK set and gives no command. `deploy/docker-single-psql/README.md` defers to the `docker` README for shared topics.
- The mobile app's server settings are on its welcome screen (`mobile/app/auth/server.tsx`). PRFAQ006 question 5 says to enter the dashboard's address.
- The OAuth issuer is `https://<APP_DOMAIN>`, and `deploy/docker/Caddyfile` sends `/api-gateway/*` and `/.well-known/*` on `APP_DOMAIN` to backend-v2, so the MCP endpoint is `https://<APP_DOMAIN>/api-gateway/mcp`.
- `backend-cluster/backend-v2/docs/mcp.md` documents the MCP endpoint and its credentials.

## Steps

1. Rewrite "OAuth signing key": derived from `AUTH_SECRET` by default (`OAUTH_JWKS_FROM_AUTH_SECRET=true` in `.env.example`); how to supply your own `OAUTH_JWKS` instead, and that it wins; rotating `AUTH_SECRET` rotates the key and signs OAuth clients out; an upgraded stack whose `.env` predates the variable adds the line to turn OAuth on.
2. Add a short "Use the mobile app" step: in the app's server settings, enter `https://<APP_DOMAIN>`, test the connection, sign in.
3. Add the MCP endpoint, `https://<APP_DOMAIN>/api-gateway/mcp`, with a pointer to `backend-cluster/backend-v2/docs/mcp.md`.
4. Mirror or link the same text from `deploy/docker-single-psql/README.md`, so neither target is left with the old instruction.

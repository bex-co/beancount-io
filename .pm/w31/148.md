## Cause

`postingSyntaxErrors` (`backend-cluster/ledger/src/foundation/rustledger/posting-syntax-errors.ts:443`) already parses a posting's units, its `{…}` or `{{…}}` cost spec and its `@` or `@@` price with stock's lexer rules, but it checks only a negative price, a merge cost and a repeated cost component (w31/120). It never compares the cost currency with the price currency. It never refuses a `#` compound inside `{{…}}`, and it never refuses an `@@` price after missing units. The block scan in `stockSyntaxErrors` (`stock-syntax-errors.ts:387`, wired at `engine.ts:875`) has no rule for a tags/links line after a posting or for the `|` separator. The engine itself reads `{{100 # 5 USD}}` as 100 per unit plus 5 in total. Stock drops the per-unit part.

## Fix

Report each construct as an error with stock's wording, the way w31/120's rules do. Put the posting-level ones on the posting's line, and the pipe and the late tag line where stock puts them:

- in `postingSyntaxErrors`: `Cost and price currencies must match: <cost> != <price>` when both currencies are written and differ (a `{}` or a currency-less cost stays clean, as in stock); `Per-unit cost may not be specified using total cost syntax: …` for a `#` inside `{{…}}`; `Total price on a posting without units: <price>.` for `@@` with no units number;
- in the block scan: `Tags or links not allowed after first Posting: …` for an indented `#tag` or `^link` line below a posting, and `Pipe symbol is deprecated.` for a `|` between the header strings.

Do not change the engine's booking. The error is enough to keep the entry from counting as clean, as with w31/120's negative price. Structured `addLedgerEntries` should refuse a `cost.currency` that differs from `price.currency` or `totalPrice.currency` up front, with `BAD_USER_INPUT` naming the posting, beside its negative-price check. If that check lives in backend-v2, the ledger error above already makes the preview `valid: false`, so it can be its own commit. Add the five rows to the ledger README's "stock errors the engine does not raise" table.

No response shape changes. Every surface reads these errors from the one ledger path: the MCP tools and the `errors` resource, the REST `errors` route and write previews, and GraphQL `getLedgerErrors` and the write mutations.

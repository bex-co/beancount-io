# `LedgerWorkflow.starLedger` / `unstarLedger` swallow `parseLedgerId` `BadUserInputError` into `200 { success: false }` on GraphQL, and MCP `executeLedgerStar` omits `errorCode` on `success: false`

**Minor · backend-v2 (`LedgerWorkflow.starLedger`/`unstarLedger` in `src/features/ledger/workflow/ledger-workflow.ts` and `executeLedgerStar` in `src/features/ai-agent/api/mcp-ledger-star.ts`) · 20–30m · A1.** Two related error-handling gaps on the ledger-star capability break 3-surface error parity:

1. **GraphQL swallows malformed `ledgerId` as HTTP 200 `{ success: false }` with fabricated `isStarred`:** `LedgerWorkflow.starLedger` (`ledger-workflow.ts:1932-1941`) and `LedgerWorkflow.unstarLedger` (`ledger-workflow.ts:1980-1989`) wrap `parseLedgerId(ledgerId)` in a `try/catch` that logs `workflowLogger.error` and returns `{ success: false, isStarred: false/true, message: "Failed to star/unstar ledger" }` instead of letting `BadUserInputError` propagate. Calling GraphQL `unstarLedger(ledgerId: "not-a-ledger")` returns HTTP 200 with no GraphQL error and claims `isStarred: true`, whereas MCP `setLedgerStar` refuses with `BAD_USER_INPUT` and REST refuses invalid path slugs with `400 VALIDATION_FAILED`.
2. **MCP masks upstream star failure messages in production as `INTERNAL_SERVER_ERROR`:** When `starLedger` / `unstarLedger` returns `{ success: false, message }` (e.g., an upstream Gitea write refusal, tested in `ledger-star-parity.test.ts:283-302`), `executeLedgerStar` (`mcp-ledger-star.ts:26-28`) returns `{ ok: false, error: result.message ?? "Star operation failed", result }` without `errorCode`. In `splitToolFailure` (`mcp-errors.ts:358-362`), any uncoded failure is classified as `ErrorCategory.INTERNAL_SERVER_ERROR` and masked in production to `"Internal server error"` — unlike `mcp-pull-requests.ts:45-53`, which explicitly sets `errorCode: ErrorCategory.OPERATION_NOT_ALLOWED` so the production mask preserves the message.

- Actual:
  - GraphQL `starLedger(ledgerId: "not-a-ledger")` → HTTP `200`, `{"data":{"starLedger":{"success":false,"isStarred":false,"message":"Failed to star ledger"}}}` (no `errors`, logs an error server-side).
  - GraphQL `unstarLedger(ledgerId: "not-a-ledger")` → HTTP `200`, `{"data":{"unstarLedger":{"success":false,"isStarred":true,"message":"Failed to unstar ledger"}}}` (claims `isStarred: true` for an invalid ID).
  - MCP `executeLedgerStar` (`src/features/ai-agent/api/mcp-ledger-star.ts:28`) returns `{ ok: false, error: result.message ?? "Star operation failed", result }` with no `errorCode`, so `splitToolFailure` under `NODE_ENV=production` emits `code: "INTERNAL_SERVER_ERROR"` and replaces `message` with `"Internal server error"`.
- Controls:
  - MCP `setLedgerStar { starred: true, ledger: "not-a-ledger" }` → `isError: true`, `code: "BAD_USER_INPUT"`, `message: "Invalid ledger ID: must contain '/' separator"`.
  - REST `PUT /api-gateway/v1/ledgers/BAD%20OWNER/books/star` → HTTP `400`, `code: "VALIDATION_FAILED"`.
  - MCP `setLedgerStar` and REST `PUT .../star` for a valid-format nonexistent ledger (`<qa-owner>/does-not-exist`) both return `NOT_FOUND: Ledger not found`.
  - Sibling MCP adapter `mcp-pull-requests.ts:45-53` passes `errorCode: ErrorCategory.OPERATION_NOT_ALLOWED` on `result.success === false` so production preserves `result.message`.

Expected:

- GraphQL `starLedger` and `unstarLedger` with a malformed `ledgerId` throw `BadUserInputError` (`extensions.code: "BAD_USER_INPUT"`), matching MCP `setLedgerStar` and every other `LedgerWorkflow` method, without logging a server error or fabricating `isStarred: true`.
- MCP `executeLedgerStar` sets an explicit `errorCode` (e.g. `ErrorCategory.OPERATION_NOT_ALLOWED`, matching `mcp-pull-requests.ts:51`) when `result.success === false`, so upstream star failures preserve `result.message` in production instead of being masked as `INTERNAL_SERVER_ERROR`.

## Root cause

Not deployment lag — present at HEAD `c5322f3e2`:

1. `backend-cluster/backend-v2/src/features/ledger/workflow/ledger-workflow.ts:1932-1941` and `:1980-1989` catch `parseLedgerId(ledgerId)` errors and convert them into `{ success: false, ... }` instead of letting `BadUserInputError` propagate.
2. `backend-cluster/backend-v2/src/features/ai-agent/api/mcp-ledger-star.ts:26-28` omits `errorCode` on the `ok: false` branch, causing `splitToolFailure` (`src/features/ai-agent/api/mcp-errors.ts:358-362`) to classify it as `INTERNAL_SERVER_ERROR` and mask its message in production.

## Fix

In `backend-cluster/backend-v2`:

1. In `LedgerWorkflow.starLedger` (`src/features/ledger/workflow/ledger-workflow.ts:1930-1941`) and `LedgerWorkflow.unstarLedger` (`:1978-1989`), remove the `try/catch` around `parseLedgerId(ledgerId)` so malformed IDs throw `BadUserInputError` directly (before authorization and before any Gitea call).
2. In `executeLedgerStar` (`src/features/ai-agent/api/mcp-ledger-star.ts:26-28`), include `errorCode: ErrorCategory.OPERATION_NOT_ALLOWED` on the `ok: false` return (matching `mcp-pull-requests.ts:45-53`), while keeping `result` attached.
3. Update/add tests in `src/features/ai-agent/api/__tests__/ledger-star-parity.test.ts` (and any `LedgerWorkflow` unit test that asserts `starLedger("bad")` returns `success: false`):
   - GraphQL `starLedger("not-a-ledger")` and `unstarLedger("not-a-ledger")` return `BAD_USER_INPUT` errors (matching MCP).
   - MCP `setLedgerStar` on a `success: false` upstream failure emits a coded `OPERATION_NOT_ALLOWED` error whose message is preserved even under production error-masking (`NODE_ENV=production` / `maskUnexpected: true`).

# `moveEntrySources` moves an entry out of its file's `pushtag`/`pushmeta` scope as bare text, so the moved entry loses that tag or metadata, and the hash it reports no longer exists, on MCP, REST and GraphQL

**Minor · ledger (entry move) · 30–45m · A1.** The move reports success and "No new bean-check errors", but the ledger changes beyond the file layout. A trip's tag filter loses the moved expense, and an agent that follows up on `movedHashes` gets `NOT_FOUND`. Found in the same run, against the same target and with the same credential as `w31/015`, on the same fixture: `PAYEE-A` sits inside `pushtag #qa-r7-trip` and `PAYEE-C` inside `pushmeta qa-r7-meta: "pm"`. Writes went only to the designated QA ledger `<qa-owner>/mcp-agent-eval`. The moved-to file was deleted and `main.bean` was restored byte for byte afterwards (blob `f1a0b83c`), and the check is clean.

- **Repro (live).**
  1. `listLedgerEntries {filter: "qa-20261115 r7", include_source: true}` gives `PAYEE-A` with `tags: ["qa-r7-trip"]` (hash `5ecfb720…`) and `PAYEE-C` with `meta: {"qa-r7-meta": "pm"}`.
  2. `moveEntrySources {entries: [PAYEE-A, PAYEE-C], toPath: "qa-20261115-r7-moved.bean", includeFrom: "main.bean", dry_run: true}` previews each entry's text without the tag or the metadata, with `valid: true`.
  3. The commit (`867e69fb`, later restored) answers "Moved 2 entries to qa-20261115-r7-moved.bean; main.bean now includes it. No new bean-check errors.", with `movedHashes` and `entryHashes` `["5ecfb720…", "fd22fae3…"]`.
  4. After it, `listLedgerEntries` shows `PAYEE-A` with `tags: []` and a new hash (`dac8c64f…`), and `PAYEE-C` with `meta: null`. BQL `'qa-r7-trip' IN tags` loses PAYEE-A's two postings. `getEntryContext {entryHash: "5ecfb720…"}` answers `NOT_FOUND`.
  5. Stock `bean-query` 3.2.3 on the two committed files agrees: neither moved entry keeps its tag or metadata. The engine is right; the moved text is what changed.
  6. REST `POST …/entries/move` and GraphQL `moveLedgerEntrySources`, each with `dryRun: true`, return the same bare preview text and the stale hash for a scoped entry.
- **Controls.** `checkLedger` stays at `errors: []` after the move, so w1/m45's error-list promise holds. Only the scoped entries change: `PAYEE-B` and `PAYEE-D`, whose tags are written inline and which stayed in `main.bean`, keep theirs.
- **Cause.**
  - `moveSourceSlices` (`backend-cluster/ledger/src/features/ledger/service/ledger-journal-service.ts:1368`) appends each slice to `toPath` byte for byte (`:1438`).
  - Beancount applies `pushtag` and `pushmeta` by position, and only within the file that holds them. A slice taken out of an open scope therefore leaves the scope's tags and metadata behind.
  - The slice locator already tracks the active `pushtag` set at each block (`applyTagStackOp`, `foundation/rustledger/source-slice.ts:143`). It does not track `pushmeta`, and the move never asks it.
- **Fix.** Before appending, write the source location's active scope onto each moved entry, as w23/041 does for appended text:
  - Add the pushed tags to a transaction's header, deduplicated.
  - Add the pushed metadata as indented lines under the header, unless the entry sets that key itself.
  - An entry outside every scope is still moved byte for byte.
  - The preview then shows the text that will be written, and `movedHashes` names entries that exist after the commit.
  - One service method serves MCP `moveEntrySources`, REST `POST …/entries/move` and GraphQL `moveLedgerEntrySources`, so all three change together. No response shape changes. State the rule in `docs/mcp.md` "Moving entries to another file".

**Done when:**

- On the fixture, moving `PAYEE-A` and `PAYEE-C` keeps `tags: ["qa-r7-trip"]` and `qa-r7-meta: "pm"`, through `listLedgerEntries`, BQL and stock `bean-query` on the committed files.
- `getEntryContext` resolves every hash in `movedHashes` after the commit.
- An unscoped entry's moved text stays byte-identical, as w1/m45 promises.
- `move-source-slices.test.ts` covers a `pushtag`-scoped and a `pushmeta`-scoped entry, and the cases fail with the fix reverted.

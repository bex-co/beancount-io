# With `coherent_cost` declared, a currency held at cost and elsewhere at an `@` price reports two errors where `bean-check` reports one: the engine's own unlocated "Currency 'VTI' is used with both cost and price-only notation - this may cause inconsistencies" is kept beside Beancount's, and it also refuses a write that only adds a priced posting

**Minor · ledger (`src/foundation/rustledger/engine.ts`, `coherent-cost.ts`) · 20–30m · A1.** w21/740 added Beancount's `coherent_cost` error, `Currency 'VTI' is used both with and without cost`, on the premise that "the engine does not run" the plugin (`engine.ts:848`, `coherent-cost.ts:13-17`). `@rustledger/wasm` 0.24.0 does run a `coherent_cost` of its own. When the plugin is declared by that name, and a currency has a posting at cost and another posting with an `@` price and no cost, the engine raises `Currency 'VTI' is used with both cost and price-only notation - this may cause inconsistencies`. That error has `severity: "error"` and no location. The other reconcilers drop the engine's version of their check before they add Beancount's (the `RUSTLEDGER` patterns in `leafonly.ts:6`, `nounused.ts:15`, `check-commodity.ts:6` and `one-commodity.ts:9`). `coherentCostErrors` adds Beancount's error and leaves the engine's in place (`engine.ts:857`).

As a result, `checkLedger`, the `beancount://{owner}/{name}/errors` resource and REST `GET /api-gateway/v1/ledgers/{owner}/{name}/errors` list two errors where stock `bean-check` lists one. The extra row has no file or line, so a client cannot open it.

The extra error also affects writes. Take a ledger that already has the stock error from an uncosted posting with no price. A write that adds a first `@`-priced uncosted posting of that currency brings in the engine's error, and it reads as new, so the write is refused `VALIDATION_FAILED`. Stock still reports the one error it had. This consequence follows from the engine runs below; it was not exercised live.

Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 LAND=1`) on 2026-11-27 against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`), on the designated disposable QA ledger `<qa-owner>/mcp-agent-eval` during the w31/128 run. The same setup and restore commits apply, and the ledger is restored. Local HEAD `d8abefc82` has the same code.

## Repro

Live: `main.bean` declares `plugin "beancount.plugins.coherent_cost"` and holds the w31/128 setup (`10 VTI {100.00 USD}` on 2026-03-01, `2 VTI @ 100.00 USD` with no cost on 2026-04-01). The `errors` resource and REST `errors` both return:

```json
[{"message":"Currency 'VTI' is used both with and without cost","source":{"filename":"main.bean","lineno":98},"code":"PLUGIN","hint":null,"severity":"error"},
 {"message":"Currency 'VTI' is used with both cost and price-only notation - this may cause inconsistencies","source":null,"code":"PLUGIN","hint":null,"severity":"error"}]
```

Engine and stock, on synthetic files (`validateSource` from `@rustledger/wasm` 0.24.0 under Node, and `bean-check` 3.2.3):

| file | engine | stock |
| --- | --- | --- |
| plugin + `10 VTI {100.00 USD}` + `2 VTI @ 100.00 USD` | the price-only error | `Currency 'VTI' is used both with and without cost` |
| plugin + `10 VTI {100.00 USD}` + `2 VTI` (no price) | nothing | the same one error |
| `pedantic` instead of `coherent_cost`, priced gift | nothing (only commodity warnings) | Beancount's error |
| no plugin | nothing | nothing |
| plugin + `{cost} @ price` on both postings | nothing | nothing |

Whenever the engine raises its error, stock raises Beancount's, so the engine's error is only ever a duplicate.

## Fix

- When `coherent_cost` runs, drop the engine's `^Currency '.*' is used with both cost and price-only notation` error. Follow the `RUSTLEDGER` pattern the other reconcilers use, in `coherent-cost.ts` or beside the call at `engine.ts:857`.
- Correct the "does not run" comments in `engine.ts` and `coherent-cost.ts`.
- Tests:
  - `plugin-locations.test.ts`: a priced, uncosted gift beside a costed buy yields exactly Beancount's one located error.
  - A live-engine case (`yarn verify:rustledger`): on the real WASM, the ledger reports one error for the first row of the table above.
  - An `appendLedgerText` preview adding `1 VTI @ 100.00 USD` to a ledger whose only uncosted VTI posting has no price is `valid: true`.
  - Revert the fix and watch the tests fail.

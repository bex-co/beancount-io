# `createPullRequest` drops entry `type` in `assertNoPortableTwin` and skips `assertNoPrefixAmong`, letting file-vs-folder collisions bypass `CONFLICT` across MCP, REST, and GraphQL

**Major · backend-v2 (`src/features/gitea/pull-request/service/pull-request-service.ts`) · 25–35m · A1.** When `w23/204` (`40f272209`) extended `assertNoPortableTwin` (`src/features/ledger/utils/portable-twin.ts:63-76`) to refuse creating a path beneath an existing file (`main.bean/sub.bean`) or at an existing folder (`existingDir`), and added `assertNoPrefixAmong` (`portable-twin.ts:123-138`) to `LedgerRepoService.assertNewPathsPortable` (`ledger-repo-service.ts:380-381`), `PullRequestService.createPRFromPatch` (`src/features/gitea/pull-request/service/pull-request-service.ts:388-428`) was left behind:

1. Its `assertNoPortableTwin` directory-listing callback (`pull-request-service.ts:420-424`) maps Gitea's `ContentsResponse[]` to `{ path: entry.path }` and **drops `entry.type`** (`"file" | "dir"`). Because `existing.type` is always `undefined`, both `existing.type === "file"` (creating a path under an existing file) and `existing.type === "dir"` (creating a file at an existing folder, where `repoGetContents` returns an array so `fileSha` is `undefined` and the path enters the create branch) are dead code. For a path under an existing file (`main.bean/sub.bean`), `assertNoPortableTwin` proceeds to `depth = 2`, makes a wasted second `repoGetContents(owner, repo, "main.bean")` call that returns an object rather than an array, silently converts it to `[]`, and passes validation.
2. It checks only full-path `portablePathKey` equality against `created` (`pull-request-service.ts:389-400`) and **never calls `assertNoPrefixAmong(created)`** (nor `assertNoTwinsAmong(created)` — see `w31/085`). A single PR batch containing both a path and a child beneath it (`qa-dir` and `qa-dir/sub.bean`) bypasses validation and reaches Gitea `repoChangeFiles`, where Git/Gitea either fails late with a raw `422` or silently keeps only one of the pair while opening a PR (`w23/204`).

Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`) on 2026-11-24 against `https://beancount.io` (`beancount-mcp 1.0.0`, negotiated protocol `2025-11-25`, verified still present at local HEAD `4c9ce330a`). Credential: unpinned read/write/admin `bcio_` API key on the QA account (`ledger.read` key and cookie boundary also exercised). Synthetic ledger: `<qa-owner>/mcp-agent-eval` (read-only and refused-write probes for this finding; separate disposable write round-trip restored `main.bean` byte-for-byte, sha256 `77c3a591efd311e0`, 0 bean-check errors).

## Root cause

1. `backend-cluster/backend-v2/src/features/gitea/pull-request/service/pull-request-service.ts:420-424`:
   ```ts
   return Array.isArray(listing.data)
     ? (listing.data as ContentsResponse[]).flatMap((entry) =>
         entry.path ? [{ path: entry.path }] : [],
       )
     : [];
   ```
   Gitea's `ContentsResponse` carries `type?: string` (`"file"`, `"dir"`, `"symlink"`, `"submodule"`), but the mapper drops it. `assertNoPortableTwin` (`src/features/ledger/utils/portable-twin.ts:63-76`) checks `existing.type === "file"` and `existing.type === "dir"`, so both collision guards never fire.
2. `backend-cluster/backend-v2/src/features/gitea/pull-request/service/pull-request-service.ts:388-400`:
   Only checks `portablePathKey(path) === portablePathKey(change.path)` against `created`. It never calls `assertNoPrefixAmong(created)` (or `assertNoTwinsAmong(created)`), unlike `LedgerRepoService.assertNewPathsPortable` (`src/features/ledger/service/ledger-repo-service.ts:380-381`).

## Fix

Owning package: `backend-cluster/backend-v2`. Shared service change updates all three eligible surfaces together (MCP `createPullRequest`, REST `POST /api-gateway/v1/ledgers/{owner}/{name}/pull-requests`, GraphQL `Mutation.createPullRequestFromPatch`) — no OpenAPI schema shape change needed (existing `ConflictError` maps to `409` on REST, `CONFLICT` on MCP and GraphQL).

1. In `src/features/gitea/pull-request/service/pull-request-service.ts:420-424`, preserve Gitea's entry type when mapping `ContentsResponse` into `DirectoryEntry`:
   `entry.path ? [{ path: entry.path, ...(entry.type === "dir" ? { type: "dir" as const } : entry.type === "file" ? { type: "file" as const } : {}) }] : []` (note: check any other Gitea `type` values such as `"symlink"`/`"submodule"`, which occupy a file slot in Git trees and cannot host children).
2. Replace the ad-hoc `sibling` loop (`pull-request-service.ts:389-400`) with `assertNoTwinsAmong(created)` and `assertNoPrefixAmong(created)` from `@/features/ledger/utils/portable-twin` (applied across all new paths in `changes` before committing, or incrementally including `change.path`), matching `LedgerRepoService.assertNewPathsPortable`. Also verify memoizing directory listings per `dir` within the PR loop if multiple new files share a folder.
3. Add regression tests in `src/features/gitea/pull-request/service/__tests__/pull-request-service.test.ts` and adapter-level parity tests in `src/features/gitea/pull-request/api/__tests__/` (covering MCP, REST, and GraphQL) for:
   - creating a file beneath an existing file (`main.bean/sub.bean`) → `ConflictError` before `repoChangeFiles`,
   - creating a file at an existing directory (`existingDir`) → `ConflictError` before `repoChangeFiles`,
   - creating a file and a nested path beneath it in one PR (`dir` + `dir/sub.bean`, including case-variant `dir` + `DIR/sub.bean`) → `ConflictError` before `repoChangeFiles`.
4. Run `yarn typecheck`, `yarn lint:deadcode`, `yarn format:check`, `yarn test`, and `yarn generate-v1-openapi` in `backend-cluster/backend-v2/`.

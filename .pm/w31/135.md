# A misspelled MCP tool or prompt argument whose name holds a control character or a backslash is refused `INTERNAL_SERVER_ERROR` with the raw Zod issue dump, or echoed with the control characters raw: the w1/225 bound runs on the JSON before it is parsed (REST and GraphQL escape the same key)

**Minor · backend-v2 (`src/features/ai-agent/api/mcp-errors.ts`, `src/server/api/composition-root.ts`) · 30–40m · A1.** w1/225 made every refusal's echo "short and inert": a run of more than 120 non-space characters is cut with `…`, and every control character except tab and line feed comes back as `\uXXXX` (`docs/mcp.md` "Failure codes"). On MCP, a tool or prompt argument that fails its Zod schema skips that promise. `envelopeFromThrown` (`mcp-errors.ts:290`–`293`) bounds the Zod error's message first, then `compactZodMessage` (`:173`) parses that message as the JSON issue array to build `path: reason`. That order causes two failures:

- **The cut breaks the JSON.** Inside the JSON text, a control character in the key is already the six characters `\u0007` and a backslash is `\\`. When the 120-character cut lands inside one of those escapes, it leaves `\u00…` or `\…`. `JSON.parse` then fails, `compactZodMessage` returns nothing, and the refusal falls through to `INTERNAL_SERVER_ERROR` with the hint "changing the request will not help". The argument was the caller's mistake, so the right answer is `BAD_USER_INPUT`.
- **The escaping is undone.** The bound saw no raw control characters, because the JSON encoding had already escaped them. Parsing decodes them back, so a key holding ESC, CR, BEL, DEL or a C1 character is echoed raw: `Unrecognized key: "<ESC>[31mred"`.

On `tools/call` the fall-through is also not masked. `dispatchTool` builds the envelope with `envelopeFromThrown(parsed.error)` and no `maskingFor(config)` (`composition-root.ts:644`). Production therefore returns the whole pretty-printed issue array as the `INTERNAL_SERVER_ERROR` message. That breaks the documented "In production its message is always `Internal server error`" (w1/189). `prompts/get` goes through the masked path, so it shows only `Internal server error`, which is still the wrong code.

## Repro (synthetic, any ledger the key can read)

1. `tools/call` `checkLedger` with `arguments: {"ledger": "<owner>/<name>", "<118 × Z>\\x": 1}`. The key is 118 `Z` followed by one backslash and an `x`. Result: `isError: true` and `INTERNAL_SERVER_ERROR`, with the message `[\n  {\n    "code": "unrecognized_keys",\n    "keys": [\n      "ZZZ…Z\\…"\n    ],\n    "path": [], …`. That is the raw dump, unmasked in production.
2. The same call with the key `"a"` followed by 30 × U+0007 gives the same `INTERNAL_SERVER_ERROR` dump.
3. The same call with the key `"\u001b[31mred"` gives `BAD_USER_INPUT` and `Unrecognized key: "<ESC>[31mred"`, with a raw U+001B in the message, the text block and `structuredContent`.
4. `prompts/get` `close-month` with `arguments: {"ledger": "<owner>/<name>", "\u001b[31mx": "x"}` gives `-32602 BAD_USER_INPUT` and `Unrecognized key: "<ESC>[31mx"` with a raw ESC. With the 30 × U+0007 key, it gives `-32000 INTERNAL_SERVER_ERROR` "Internal server error".
5. A key with no escape near the cut is handled correctly: 300 × `Z`, or 119 × `Z` then `"`, gives `BAD_USER_INPUT` `Unrecognized key: "ZZZ…"`, cut at 120.

## Controls (working)

- **REST.** `POST /api-gateway/v1/ledgers/{owner}/{name}/query` with the same three keys in the body, or the same keys as query names on `GET …/journal`, gives `400 VALIDATION_FAILED`, for example `Validation failed for body: Unrecognized key: "\u001b[31mred"`, escaped. `validation-middleware.ts:85` builds a `ValidationError` from the decoded `issue.message`, and the `DomainError` constructor bounds it.
- **GraphQL.** The same keys in a `JournalQueryInput` variable give `BAD_USER_INPUT` "Field "\u001b[31mred" is not defined by type", escaped and cut.
- **MCP resources.** An unknown resource query name gives `-32602 BAD_USER_INPUT` "Unknown or repeated resource parameter: \u001b[31mred", escaped. That message is built as a `BadUserInputError`, not from Zod JSON.

## Fix

In `envelopeFromThrown`, read the issues before bounding anything:

1. When the error is a `ZodError`, describe its `issues` directly with `describeIssue`. Otherwise run `compactZodMessage` on the unbounded message.
2. Apply `boundEchoes` to the compacted `path: reason` text.
3. Bound the raw text only when it is not a Zod refusal.

Then pass `maskingFor(config)` to the `envelopeFromThrown(parsed.error)` at `composition-root.ts:644`. Also check the outer `tools/call` parameter refusal (`:700`) and `splitToolFailure` (`mcp-errors.ts:353`) for the same order. This is MCP-only: REST and GraphQL already bound decoded text, so no other surface changes and no response shape changes.

## Done when

- Repro steps 1–4 answer `BAD_USER_INPUT` (`-32602` on prompts). The message is `Unrecognized key: "…"`, with every control character as `\uXXXX`, the key cut at 120 characters with `…`, and no JSON dump.
- An `INTERNAL_SERVER_ERROR` built from a tool's argument refusal is masked in production, as every other tool failure is.
- `bound-echoes.test.ts` (or the MCP error tests) covers tool-argument and prompt-argument keys with ESC, CR, 30 × U+0007, and a backslash at the cut. With the fix reverted, those cases fail.

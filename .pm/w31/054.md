# Entry-source writes (`updateEntrySource`, `deleteEntrySource`, `deleteEntrySources`, `moveEntrySources`) skip `sha256sum` format validation, loading the full ledger and answering misleading `CONFLICT` instead of `BAD_USER_INPUT` on MCP, REST, and GraphQL

**Minor · backend-v2 (`LedgerJournalService` source-slice writes) · 30–45m · A1.** Direct sibling of `w31/046` (`assertEntryHashFormat`). Passing an empty (`""`), blank (`"   "`), malformed (`"not-a-sha"`), or wrong-kind (e.g. a 32-hex `entry_hash` pasted into `sha256sum`) value for `sha256sum` to any of the four entry-source write operations bypasses input validation, loads the full repository from Gitea and parses it in the ledger service with rustledger, and fails with a misleading `CONFLICT` (HTTP `409` on REST, `CONFLICT` on MCP and GraphQL) saying `"Entry conflict: it has changed since it was loaded; refresh and retry"` instead of refusing immediately with `BAD_USER_INPUT` naming `sha256sum`. Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`) on 2026-11-23 against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, checked against HEAD `d6d2e37d0`). Credential: unpinned read/write/admin `bcio_` key on the QA account. Synthetic ledger: `<qa-owner>/mcp-agent-eval` (restored byte-for-byte after run: `main.bean` sha256 `77c3a591efd311e0`, 0 bean-check errors).

## Working controls

- Valid 64-character lowercase hex digest that does not match the current entry (`"0".repeat(64)`): returns `CONFLICT` (`"Entry conflict: it has changed since it was loaded; refresh and retry"`) across MCP, REST, and GraphQL (genuinely stale optimistic lock).
- Valid current 64-character lowercase hex `sha256sum` returned by `getEntryContext` / `listLedgerEntries(include_source: true)`: `dry_run: true` returns `ok: true` cleanly.
- Sibling `entryHash` validation (`assertEntryHashFormat`, `w31/046`, commit `50c84f789`) refuses empty, blank, and non-32-hex `entryHash` values upfront with `BAD_USER_INPUT` on all four write methods before calling `favaApiClient`.

## Root cause

Not deployment lag — present at HEAD `d6d2e37d0`:

- `backend-cluster/ledger/src/foundation/rustledger/source-slice.ts:528-530` (`sliceSha256`): every `sha256sum` issued by the ledger service is `createHash("sha256").update(slice, "utf8").digest("hex")` — always 64 lowercase hexadecimal digits (`/^[0-9a-f]{64}$/`).
- `backend-cluster/backend-v2/src/features/ledger/api/rest/v1/source-slice-handler.ts:37` defines `sha256sum: z.string()` with no format constraint; GraphQL input types (`ledger-journal-resolver.mutation.ts:46,137,315`) accept any `String!`.
- `backend-cluster/backend-v2/src/features/ledger/service/ledger-journal-service.ts`:
  - `deleteSourceSlice` (`:477-515`) calls `assertEntryHashFormat(entryHash)` at `:492` but never validates `sha256sum`.
  - `deleteMultiSourceSlices` (`:517-567`) calls `assertEntryHashFormat(entry.entryHash)` at `:541` but never validates `entry.sha256sum`.
  - `moveSourceSlices` (`:569-624`) calls `assertEntryHashFormat(entry.entryHash)` at `:594` but never validates `entry.sha256sum`.
  - `updateSourceSlice` (`:626-703`) calls `assertEntryHashFormat(entryHash)` at `:651` but never validates `sha256sum`.
- Malformed values therefore pass straight to `favaApiClient.journal.*`, which loads and parses the full ledger (`backend-cluster/ledger/src/features/ledger/service/ledger-journal-service.ts:661-684`, `locateSlices`), checks `slice.sha256 !== sha256sum` at `:676`, and throws `ConflictError("Entry", "it has changed since it was loaded; refresh and retry")`.

## Fix

In `backend-cluster/backend-v2`:

1. Add `assertSha256Format(sha256sum: string): void` beside `assertEntryHashFormat` in `src/features/ledger/utils/entry-hash-alias.ts` (enforcing `/^[0-9a-f]{64}$/`), throwing `BadUserInputError("sha256sum must be a 64-character lowercase hex SHA-256 digest from getEntryContext or listLedgerEntries(include_source: true)", "sha256sum")`.
2. Call `assertSha256Format` right alongside `assertEntryHashFormat` (after authorization and bulk-size checks, before calling `favaApiClient`) in all four write methods of `LedgerJournalService` (`src/features/ledger/service/ledger-journal-service.ts`):
   - `deleteSourceSlice` (`:492`)
   - `deleteMultiSourceSlices` (`:540-542`, for each entry)
   - `moveSourceSlices` (`:593-595`, for each entry)
   - `updateSourceSlice` (`:651`)
3. Update any existing unit or parity tests in `backend-v2` that pass placeholder non-64-hex `sha256sum` strings (e.g. `"sha"`, `"s1"`, `"oldsum"`, `"abc123"`) as valid fixtures to use 64 lowercase hex digits (e.g. `"a".repeat(64)`), mirroring `w31/046`'s fixture update for `entryHash`.
4. Add unit tests in `src/features/ledger/service/__tests__/ledger-journal-service.test.ts` and 3-surface adapter parity tests in `src/features/ledger/api/rest/v1/__tests__/source-slice-parity.test.ts` and `move-entry-sources-parity.test.ts` covering `""`, `"   "`, `"not-a-sha"`, a 32-hex `entryHash`, and 64-char uppercase hex on all four operations across MCP, REST, and GraphQL — asserting `BAD_USER_INPUT` (REST `400`, field `"sha256sum"`) and zero calls to `favaApiClient`.

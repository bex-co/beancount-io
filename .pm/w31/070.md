# `listStagedBankTransactions` MCP tool reuses REST's `z.coerce.number()` query schema, accepting booleans/strings for `page`/`limit`, returning misleading errors on `null`/`""`, and omitting parameter descriptions in `tools/list`

**Minor · backend-v2 (`src/features/ai-agent/api/mcp-list-tools.ts`) · 25–35m · A1.** `listStagedBankTransactions` is a JSON-input MCP tool whose `tools/list` schema advertises `page` and `limit` as `"type": "integer"`, yet `listStagedBankTransactionsInput` (`mcp-list-tools.ts:63`) directly aliases REST's URL-query schema `unsyncedTransactionsQuery` (`banks-handler.ts:59-61`), which inherits `z.coerce.number()` and `.openapi({ description })` from `paginationSchema` (`v1-schemas.ts:9-20`). As a result, `listStagedBankTransactions` silently coerces non-numeric JSON types (`page: true, limit: true` → `1, 1`; `page: "1", limit: "5"` → `1, 5`), reports a misleading range error (`Too small: expected number to be >=1`) for `page: null` / `page: ""` / `page: false` (because `Number(null) === 0`), and publishes `accountId`, `page`, and `limit` in `tools/list` with no `description` fields at all — breaking parity with sibling MCP paged tools (`listLedgers`, `listLedgerEntries`) and GraphQL (`getUnsyncedPlaidTransactions`). Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`) on 2026-11-23 against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, verified at HEAD `dc57d76b6`). Credential: unpinned read/write/admin `bcio_` key on the QA account. Synthetic ledger: `<qa-owner>/mcp-agent-eval` (read-only for this finding).

- Actual:
  - `listStagedBankTransactions` with `page: true, limit: true` → `200 OK`, `{"ok":true,"result":[],"page":{"returned":0,"limit":1,"page":1,"hasMore":false}}` (booleans silently coerced to `1`).
  - `listStagedBankTransactions` with `page: "1", limit: "5"` → `200 OK`, `[]`.
  - `listStagedBankTransactions` with `page: null` (or `""`) → `isError: true`, `BAD_USER_INPUT`: `"page: Too small: expected number to be >=1"`.
  - `tools/list` entry for `listStagedBankTransactions` publishes `accountId`, `page`, and `limit` with no `description` property (only `ledger` has a description).
- Controls:
  - `listLedgers` with `{"page":true}` → `isError: true`, `BAD_USER_INPUT`: `"page: Invalid input: expected number, received boolean"` (and `{"page":"1"}` → `"expected number, received string"`).
  - `listLedgerEntries` with `{"ledger":"<qa-owner>/mcp-agent-eval","limit":"5"}` → `isError: true`, `BAD_USER_INPUT`: `"limit: Invalid input: expected number, received string"`.
  - GraphQL `getUnsyncedPlaidTransactions(ledgerId: "...", page: true, limit: true)` → `GRAPHQL_VALIDATION_FAILED`: `"Float cannot represent non numeric value: true"` (and `page: "1"` → `"Float cannot represent non numeric value: \"1\""`).

Expected:

- `listStagedBankTransactions` enforces strict JSON number validation (`z.number().int().min(1)` for `page`, `z.number().int().min(1).max(100)` for `limit`), refusing booleans, strings, and `null` with `BAD_USER_INPUT` naming the wrong type (`expected number, received boolean|string|null`), matching `listLedgers`, `listLedgerEntries`, and GraphQL.
- `tools/list` publishes clear `.describe(...)` descriptions on `accountId`, `page`, and `limit` (matching `listLedgers` and `listLedgerEntries`).
- Unknown arguments continue to be refused (`.strict()`).

## Root cause

Not deployment lag — present at HEAD `dc57d76b6`:

- `backend-cluster/backend-v2/src/features/ai-agent/api/mcp-list-tools.ts:62-63`:
  ```ts
  // Strict at the base (w23/112), with the shared page and limit.
  export const listStagedBankTransactionsInput = unsyncedTransactionsQuery;
  ```
- `unsyncedTransactionsQuery` (`src/features/ledger/api/rest/v1/banks-handler.ts:59-61`) extends `paginationSchema.shape` (`src/server/rest/v1-schemas.ts:9-20`), which uses `z.coerce.number()` for URL query strings and `.openapi({ description })` (read by OpenAPI generation, not by Zod's JSON Schema generator for MCP `tools/list`).

## Fix

In `backend-cluster/backend-v2`:

1. In `src/features/ai-agent/api/mcp-list-tools.ts`, define `listStagedBankTransactionsInput` as a dedicated strict JSON-input Zod object instead of aliasing `unsyncedTransactionsQuery`:
   ```ts
   export const listStagedBankTransactionsInput = z
     .object({
       accountId: z
         .string()
         .optional()
         .describe(
           "Restrict to one bank account, by its `id` (pacc_…) from listBankConnections, not its Plaid `accountId`.",
         ),
       page: z
         .number()
         .int()
         .min(1)
         .optional()
         .describe("1-based page number, defaults to 1."),
       limit: z
         .number()
         .int()
         .min(1)
         .max(100)
         .optional()
         .describe("Page size, at most 100."),
     })
     .strict();
   ```
   (Keep `unsyncedTransactionsQuery` on REST `GET .../bank-transactions/unsynced` and the MCP `bankUnsyncedTransactions` resource, where parameters arrive as URL query strings.)
2. Verify `tools/list` size gate (`mcp-tool-list.test.ts`) and `mcp-reference-resolution.test.ts` pass with the added descriptions.
3. Add regression tests in `src/features/ai-agent/api/__tests__/staged-paging-parity.test.ts` and/or `mcp-list-tools.test.ts` asserting `listStagedBankTransactions` rejects `page: true`, `limit: true`, `page: "1"`, `limit: "5"`, and `page: null` with `BAD_USER_INPUT` naming `expected number`, while valid integer `page`/`limit` and `accountId` keep full parity across MCP tool, MCP resource, REST, and GraphQL.

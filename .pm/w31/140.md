# A posting of zero units at an explicit cost (`0 VTI {5 USD}`) reads clean and commits, though stock `bean-check` 3.2.3 refuses it with `Amount is zero: "0 VTI"`; the engine books it as an empty lot, on MCP, REST and GraphQL

**Minor · ledger (`src/foundation/rustledger/engine.ts`, next to the stock-error scans) · 30–45m · A1.** Stock Beancount refuses a posting held at cost whose units are zero. After booking it checks every posting with a cost: "If there is a cost, we don't allow either a cost value of zero, nor a zero number of units" (`beancount/parser/booking_full.py:1027`–`1040`, `Amount is zero: "0 VTI"`; the same rule in `booking.py:184`). `@rustledger/wasm` 0.24.0 already raises the sibling rule, `E4005` "Cost is negative", but not this one, and the ledger service adds nothing. So the posting previews `valid: true`, commits without `allowInvalid`, and reads clean on every error surface. The same file fails `bea check` and stock `bean-check`, and Fava lists the error. The engine books it as a new 0-unit lot (`0 VTI {5 USD, 2026-09-01}` in BQL). A sale written `0 VTI {5 USD}` against an existing lot also opens a new empty lot, dated the sale's day, instead of reducing anything.

A zero-share row is a common import artifact (a dividend line with no reinvested shares, a split or transfer row with the quantity left blank as 0). The ledger README's table of "stock errors the engine does not raise" does not list it.

## Fix

Report stock's error where the engine is silent. After booking, a transaction posting whose `units.number` is zero and whose booked `cost` carries a number is an error `Amount is zero: "0 VTI"`, at the posting's line. The booked directives already tell the cases apart: the explicit cost books as `cost: {number: {kind: "per_unit", value: "5"}, …}`, while `0 VTI {}` books as `cost: {}`, which stock also accepts. Add it beside the other stock-error reconciliations in `engine.ts` (or in `stock-syntax-errors.ts` if a text rule reads simpler, as long as the `{}` row stays clean), and add a row to the ledger README's "Validation: stock errors the engine does not raise" table. Every surface reads the shared snapshot, so `checkLedger`, the `errors` resource, REST and GraphQL error lists and every write preview's `valid` change together, with no API shape change. Add the fixture to `verify:rustledger`, so the rule can go once the engine raises it itself.

# `interval-totals` (`GET .../interval-totals`, `getLedgerIntervalTotals`) accepts whitespace-only `accountName` (`"  "` / `%20%20`) and silently returns all-zero empty intervals instead of `BAD_USER_INPUT` across MCP, REST, and GraphQL

**Minor · backend-v2 (`LedgerDataService.getIntervalTotals` / `getIntervalTotalsForSummary`) · 20–30m · A1.** Direct sibling of `w31/036` (`getAccountJournal`), `w31/040` (`getAccountReport`), and `w31/041` (`getRegister`). On `interval-totals`, omitting `accountName` or passing `accountName=""` returns non-zero balances across every account in the ledger, but passing whitespace-only `accountName="  "` (`%20%20`) silently succeeds with `200 OK` and returns all-zero empty intervals (`total: 0, byAccount: []` / `accountBalances: {}`) across MCP, REST, and GraphQL instead of refusing with `BAD_USER_INPUT`. Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`) on 2026-11-23 against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, checked against HEAD `d5b789be4`). Credential: unpinned read/write/admin `bcio_` key on the QA account. Synthetic ledger: `<qa-owner>/mcp-agent-eval`.

1. **MCP `beancount://<qa-owner>/mcp-agent-eval/interval-totals?accountName=%20%20`** (both default `shape=summary` and `shape=fava`):
   ```sh

   ```
   Actual (`shape=summary`): HTTP `200`, `{"currency":"USD","intervals":[{"period":"2026-01-31","total":0,"byAccount":[]},...]}` (every interval empty).
   Actual (`shape=fava`): HTTP `200`, `[{"date":"2026-01-31","balance":{},"account_balances":{}},...]`.
2. **REST `GET /api-gateway/v1/ledgers/<qa-owner>/mcp-agent-eval/interval-totals?accountName=%20%20`**:
   Actual: HTTP `200`, `{"currency":"USD","intervals":[{"period":"2026-01-31","total":0,"byAccount":[]},...]}`.
3. **GraphQL `getLedgerIntervalTotals(ledgerId: "<qa-owner>/mcp-agent-eval", accountName: "  ")`**:
   Actual: HTTP `200`, `{"data":{"getLedgerIntervalTotals":[{"date":"2026-01-31","accountBalances":{}},...]}}`.

Expected: a non-empty, whitespace-only `accountName` (`accountName.length > 0 && accountName.trim() === ""`) is refused with `BAD_USER_INPUT` (`field: "accountName"`) on MCP, REST, and GraphQL before calling the ledger service. Omitted `accountName` (MCP/REST) and empty `""` (all three surfaces, since GraphQL types `accountName: String!`) continue to return all accounts.

## Working controls

- Omitting `accountName` or passing `accountName=""` on MCP (`beancount://<qa-owner>/mcp-agent-eval/interval-totals?accountName=`), REST, and GraphQL (`accountName: ""`) returns the ledger's actual non-zero balances (`Assets:Bank:Checking: 3000`, etc.).
- Passing a valid prefix (`accountName=Expenses`) returns the Expenses totals (`15.49` for 2026-02, etc.).
- Direct sibling `getAccountReport` (`ledger-data-service.ts:443-445`, fixed in `w31/040`) and `getRegister` (`w31/041`) refuse whitespace-only account arguments with `BAD_USER_INPUT` before calling the ledger service.

## Root cause

Not deployment lag — present at HEAD `d5b789be4`:

- `backend-cluster/backend-v2/src/features/ledger/service/ledger-data-service.ts:462-520` (`getIntervalTotals`, `getIntervalTotalsForSummary`, `readIntervalTotals`): unlike `getAccountReport` immediately above at `:443-445`, neither method checks for whitespace-only `accountName`. It passes `account_name: "  "` through to `favaApiClient.reports.getLedgerIntervalTotals`, where the ledger service matches zero accounts and returns all-zero empty interval buckets.
- `backend-cluster/backend-v2/src/features/ledger/api/rest/v1/analysis-handler.ts:253` defines `accountName: z.string().optional()`, accepting `"  "`.

## Fix

In `backend-cluster/backend-v2`:

1. In `src/features/ledger/service/ledger-data-service.ts:462-501` (`getIntervalTotals` and `getIntervalTotalsForSummary`), guard before calling `this.getClient(...)` (matching `getAccountReport` at `:443-445`):
   ```ts
   if (rest.accountName !== undefined && rest.accountName !== "" && rest.accountName.trim() === "") {
     throw new BadUserInputError("accountName must not be blank", "accountName");
   }
   ```
   This preserves omitted `accountName` and `""` (GraphQL's `String!` all-accounts convention) while refusing whitespace-only strings (`"  "`, `"\t"`) across MCP (`shape=summary` and `shape=fava`), REST, and GraphQL without calling the ledger service.
2. Add unit tests in `src/features/ledger/service/__tests__/ledger-data-service.test.ts` and 3-surface adapter parity tests in `src/features/ledger/api/rest/v1/__tests__/analysis-parity.test.ts` covering `accountName: "  "` (refused `BAD_USER_INPUT`) alongside `accountName: ""` / omitted (still returns all accounts) across MCP, REST, and GraphQL.

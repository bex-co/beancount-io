# Four remaining MCP file-path tools refuse shell-style `./`-prefixed paths that all six sibling MCP file tools normalize

**Minor · backend-v2 (MCP tool adapters: `appendLedgerText`, `moveEntrySources`, `importStagedBankTransactions`, `createPullRequest`) · 30–45m · A1.** Every MCP file/directory tool in the core file family normalizes shell-style `./`-prefixed paths via `normalizeAgentRepoPath` / `normalizeAgentDirPath` (`src/features/ai-agent/tools/agent-repo-path.ts`) before the strict `assertSafeRepoPath` validator runs: `listLedgerFiles` (`w31/done/064`), `readLedgerFiles`, `createLedgerFiles`, `updateLedgerFiles`, `deleteLedgerFiles`, and `renameLedgerFile` (`w23/done/084`, `mcp-tools.ts:791-792`: *"Models spell shell-style `./old.bean`; every other file tool normalizes that here, before the strict validator."*). Four remaining MCP tools that accept repository-relative file paths never call `normalizeAgentRepoPath`, so agents passing `./main.bean` or `./imports/2026.bean` hit `BAD_USER_INPUT: Invalid file path` on those four tools while the other six file tools accept the same spelling. Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`) on 2026-11-23 against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, verified at HEAD `c5322f3e2`). Credential: unpinned read/write/admin `bcio_` key on the QA account. Synthetic ledger: `<qa-owner>/mcp-agent-eval` (read-only / dry-run for this finding).

Expected:

- At the MCP tool adapter layer only, `appendLedgerText` (`path`), `moveEntrySources` (`toPath`, `includeFrom`), `importStagedBankTransactions` (`filename`), and `createPullRequest` (`changes[].path`) run optional/required file paths through `normalizeAgentRepoPath` before forwarding to the service, returning canonical paths in outputs (`wrote`, `diff`, `message`, etc.).
- Path traversals (`../x`, `./../x`, `a/../b`), absolute paths (`/main.bean`), backslashes (`.\\main.bean`), empty strings (`""`), `"."`, and `"./"` continue to be refused with `BAD_USER_INPUT`.
- REST, GraphQL, and `beancount://{owner}/{name}/files/{+path}` stay strict behind `assertSafeRepoPath` with no behavior change.

## Root cause

Not deployment lag — present at HEAD `c5322f3e2`:

1. `backend-cluster/backend-v2/src/features/ai-agent/tools/append-ledger-text-tool.ts:91` passes raw `path: args.path` to `context.ledgerEntryService.appendDirectiveText`.
2. `backend-cluster/backend-v2/src/features/ai-agent/api/mcp-source-slices.ts:296-313` passes raw `args` through shared `moveEntriesParams(args)` without normalizing `toPath` or `includeFrom`.
3. `backend-cluster/backend-v2/src/features/ai-agent/tools/bank-import-tool.ts:385-417` passes raw `filename` into `assertValidBankTransactionSubmission` and `services.plaidSync.submitTransactionsToLedger`.
4. `backend-cluster/backend-v2/src/features/ai-agent/api/mcp-pull-requests.ts:73-82` forwards raw `payload.changes` to `context.pullRequestWorkflow.createPullRequestFromPatch`.

## Fix

In `backend-cluster/backend-v2` (MCP adapters only — do **not** normalize in the shared services or `moveEntriesParams`, so REST and GraphQL stay strict):

1. `src/features/ai-agent/tools/append-ledger-text-tool.ts`: normalize `args.path !== undefined ? normalizeAgentRepoPath(args.path) : undefined`.
2. `src/features/ai-agent/api/mcp-source-slices.ts`: in `SOURCE_SLICE_EXECUTORS.move`, normalize `toPath: normalizeAgentRepoPath(params.toPath)` and `includeFrom: params.includeFrom !== undefined ? normalizeAgentRepoPath(params.includeFrom) : undefined`.
3. `src/features/ai-agent/tools/bank-import-tool.ts`: in `submitTransactions`, normalize `const normalizedFilename = filename !== undefined ? normalizeAgentRepoPath(filename) : undefined` before `assertValidBankTransactionSubmission`, `submitTransactionsToLedger`, and the summary message.
4. `src/features/ai-agent/api/mcp-pull-requests.ts`: in `PULL_REQUEST_EXECUTORS.create`, map `changes: payload.changes.map((c) => ({ ...c, path: normalizeAgentRepoPath(c.path) }))`.
5. Add MCP/REST/GraphQL contract tests covering each of the four tools: MCP accepts `./` and reports canonical paths; MCP still refuses `../x`, `./../x`, `/abs.bean`, and `./`; REST and GraphQL continue to refuse `./`.

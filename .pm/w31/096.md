# `updateEntrySource` skips `checkBudgetAccountsExist`, letting `custom "budget"` edits for unopened accounts pass `dry_run` (`valid: true`) and commit without `allowInvalid` across MCP, REST, and GraphQL

**Minor · `backend-cluster/backend-v2` (`src/features/ledger/service/ledger-journal-service.ts`, `src/features/ledger/utils/budget-account-check.ts`) · 25–35m · A1.** Beancount's `bean-check` never validates the account token inside a `custom "budget"` directive, so a budget targeting an unopened or typoed account silently passes validation and never matches any report. `w23/done/071` and `w23/done/221` added unopened-budget validation to `addLedgerEntries`, and `w31/done/094` extracted `checkBudgetAccountsExist` / `extractDirectiveBudgetAccounts` / `withBudgetIssues` into `src/features/ledger/utils/budget-account-check.ts` and wired it into `appendLedgerText`. `LedgerJournalService.updateSourceSlice` — backing MCP `updateEntrySource`, REST `PUT /api-gateway/v1/ledgers/{owner}/{name}/entry-source`, and GraphQL `updateLedgerEntrySourceSlice` — still relies solely on the ledger service's `bean-check` projection and never checks `custom "budget"` accounts. Editing an entry into (or editing an existing) `custom "budget"` for an unopened account returns `valid: true` with `0` new errors on `dry_run: true` and commits without `allowInvalid: true` on all three surfaces.

## Environment

- Target: `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`), verified at local `HEAD` `32ce8fd12` (Node `v22.22.0`).
- Credential: unpinned read/write/admin `bcio_` API key on the designated QA account and synthetic ledger `<qa-owner>/mcp-agent-eval` (`dry_run: true` probes only; no files modified).

## Repro (synthetic)

Take an existing entry's `entry_hash` and `sha256sum` from `listLedgerEntries` with `include_source: true` (e.g. a transaction not pinned by a balance assertion), and preview updating its source to a `custom "budget"` for an unopened account (`Expenses:DoesNotExist`):

```sh
# MCP
node .agents/skills/qa-shared/scripts/qa-mcp.mjs call updateEntrySource \
  '{"ledger":"alice/books","entryHash":"<hash>","sha256sum":"<sha>","dry_run":true,"newContent":"2026-02-10 custom \"budget\" Expenses:DoesNotExist \"monthly\" 100 USD"}'
```

Repeat with the same inputs on REST (`PUT /api-gateway/v1/ledgers/alice/books/entry-source` with `dryRun: true`) and GraphQL (`mutation { updateLedgerEntrySourceSlice(ledgerId: "alice/books", input: { entryHash: "...", sha256sum: "...", dryRun: true, newContent: "2026-02-10 custom \"budget\" Expenses:DoesNotExist \"monthly\" 100 USD" }) { message dryRun valid errorsBefore errorsAfter newErrors { message source } } }`).

- **Actual (all 3 surfaces):**
  - MCP: HTTP `200`, `ok: true`, `summary: "Would update entry <hash> (new hash <new>). No new bean-check errors."`, `validation: { errorsBefore: 0, errorsAfter: 0, newErrors: [], valid: true }`.
  - REST: HTTP `200`, `valid: true`, `errorsBefore: 0`, `errorsAfter: 0`, `newErrors: []`.
  - GraphQL: HTTP `200`, `data.updateLedgerEntrySourceSlice: { dryRun: true, valid: true, errorsBefore: 0, errorsAfter: 0, newErrors: [] }`.
  - On `dry_run: false` without `allowInvalid`, `updateSourceSlice` commits the dead budget directive without refusing.
- **Working controls:** `addLedgerEntries` (`w23/071`, `w23/221`) and `appendLedgerText` (`w31/094`) report `valid: false` with the unopened budget error in `newErrors` on `dry_run: true`, and refuse with `VALIDATION_FAILED` on commit unless `allowInvalid: true`.

## Expected

`updateEntrySource` (`PUT .../entry-source`, GraphQL `updateLedgerEntrySourceSlice`) enforces the same unopened-budget-account check as `addLedgerEntries` and `appendLedgerText`:

- When `!allowInvalid` and `newContent` is a `custom "budget"` directive targeting an account that is neither opened in the ledger nor a parent of an opened account (and the edit is not an `unchanged: true` no-op):
  - On `dryRun: true`: return `valid: false`, increment `errorsAfter`, and append the finding to `newErrors` (naming the unopened account and nearest opened accounts, per `docs/mcp.md` "The preview rule").
  - On `dryRun: false`: refuse with `VALIDATION_FAILED` before committing, with a hint naming the nearest opened accounts and `allowInvalid: true`.
- Preserve existing failure precedence: a stale `sha256sum` still answers `CONFLICT`, a missing `entryHash` still answers `NOT_FOUND`, and malformed/multi-directive `newContent` still answers `BAD_USER_INPUT` rather than being masked by a budget error.
- When `allowInvalid: true`, or when the account (or a child) is opened in the ledger, or when `newContent` is not a `custom "budget"`, behavior is unchanged (zero extra `getLedgerAccounts` calls for non-budget edits).

## Root cause

- `backend-cluster/backend-v2/src/features/ledger/service/ledger-journal-service.ts:658-736`: `LedgerJournalService.updateSourceSlice` checks `entryHash`/`sha256sum` format, non-empty `newContent`, and `assertAmountsFitEngineDecimal(newContent)`, then delegates directly to `favaApiClient.journal.updateSourceSlice` without calling `checkBudgetAccountsExist`.
- `backend-cluster/backend-v2/src/features/ledger/utils/budget-account-check.ts:74`: `checkBudgetAccountsExist` is already shared by `ledger-entry-service.ts` and `directive-append-workflow.ts` (`w31/094`), and only needs `field` widened to include `"newContent"` (and a single-directive extractor or `extractDirectiveBudgetAccounts` over `newContent`).

## Fix

In `backend-cluster/backend-v2`:

1. Widen `field` in `src/features/ledger/utils/budget-account-check.ts` to accept `"newContent"` (and reuse `extractDirectiveBudgetAccounts` or a small header-line helper for `newContent`'s single directive).
2. In `LedgerJournalService.updateSourceSlice` (`src/features/ledger/service/ledger-journal-service.ts`), when `!allowInvalid` and `newContent` declares a `custom "budget"` account:
   - Check `checkBudgetAccountsExist` against `favaApiClient.reports.getLedgerAccounts(ledgerOwner, ledgerName)`.
   - On `dryRun: true`: merge any budget issues into `validation` via `withBudgetIssues` (when `!unchanged`, or whenever the projected edit introduces them).
   - On `dryRun: false`: when budget issues exist, run the ledger-service call with `dryRun: true` first (so missing `entryHash`, stale `sha256sum`, invalid syntax, or `unchanged: true` keep their exact existing responses without mutating the repository), then if `!unchanged` throw the first `ValidationError` (`VALIDATION_FAILED`) before committing.
3. Update `backend-cluster/backend-v2/docs/mcp.md` where the `custom "budget"` account check is documented to include `updateEntrySource`.
4. Add unit tests in `ledger-journal-service.test.ts` and 3-surface parity tests in `source-slice-parity.test.ts` (unopened budget preview `valid: false`, commit refusal `VALIDATION_FAILED`, `allowInvalid: true` override, opened parent account allowed, stale `sha256sum` still `CONFLICT`, unchanged no-op).

## Blast radius & adjacent states

- Shared by MCP `updateEntrySource`, REST `PUT /api-gateway/v1/ledgers/{owner}/{name}/entry-source`, and GraphQL `Mutation.updateLedgerEntrySourceSlice`. No OpenAPI schema changes required.
- Adjacent states: non-budget edits incur zero extra RPCs; non-budget `custom` directives (`custom "fava-option" ...`) remain unaffected; `allowInvalid: true` bypasses the refusal while still reporting errors as expected.

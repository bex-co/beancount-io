# `mcp:conformance` check 2 reports a skip and blames check 1 when its own discovery request fails

Source: follow-up from the `/loopx w31` routine `mcp-qa`, run 57, 2026-11-16.

- One conformance pass against `https://beancount.io` printed `PASS 1 endpoint-401 … points at https://beancount.io/.well-known/oauth-protected-resource`. It then printed `SKIP 2 discovery-resolves — check 1 produced no pointer to follow` and exited 0 with "17 passed, 0 failed, 1 skipped". A re-run straight after passed all 18 checks.
- Cause: in `backend-cluster/backend-v2/scripts/mcp-conformance.ts`, `checkDiscovery` sends its own anonymous POST through `discoverPointer`. When that request errors, or comes back without a pointer, the error and status are discarded. The failure then shows up as a skip that names check 1, the wrong check. `hostMetadata` handles errors the same way.
- A transient server error is therefore reported as a passing run with a misleading skip, rather than as a failure.

**Done when:** a test in `backend-cluster/backend-v2/scripts/__tests__/mcp-conformance.test.ts` uses a server that returns the pointer on the first anonymous POST and a 503 on the second. In that test, check 2 fails and reports the 503, the same way check 1 reports a probe error, instead of skipping with "check 1 produced no pointer". `hostMetadata` reports its own request failures the same way.

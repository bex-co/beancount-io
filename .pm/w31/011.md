# A prompt argument sent as `""` is handled three ways: refused, rendered as a blank, or treated as omitted

**Trivial · backend-v2 (MCP prompts) · 20–30m · A1.** Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`), 2026-11-15, against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, `revision: unknown`, see `w31/002`), with unpinned read/write and `ledger.read` keys. `prompts/get` does no ledger work, so nothing was read or written.

- **What holds.** For both keys, the served `prompts/list` and the text of all four prompts (no arguments, `{}`, every argument) equal what HEAD's `mcp-prompts.ts` builds. Every tool and `beancount://` URI the text cites is in this deployment's lists, and so is every argument name it tells the agent to pass (`item_id`, `target_account`, `limit` up to 100, `page.hasMore`, `description` on the file writes). Malformed `month` (`2026-13`, `2026-8`, `banana`, a leading space, a trailing newline) and malformed `ledger` values are refused with `BAD_USER_INPUT` and a hint. An unknown argument, a non-string value and `arguments: null` are refused too.
- **The gap.** Every argument is optional, but an empty string is handled three different ways:
  - Refused. `close-month {month: ""}` gets "month must be YYYY-MM", and `{ledger: ""}` on any prompt gets "Ledger ID cannot be empty".
  - Rendered as a blank. `spending-report {period: ""}` opens with "Answer questions about this ledger's spending for ." and `reconcile-account {account: ""}` with "Reconcile  against one statement period.". In both, the "a period I will name" and "ask me which" fallbacks are lost.
  - Treated as omitted. `period` in `reconcile-account`, `question`, `statement` and `item_id` fall back as if they were absent.
- **Cause.** `backend-cluster/backend-v2/src/features/ai-agent/api/mcp-prompts.ts`: `validatePromptArgs` checks any value that is not `undefined` (line 91). The builders mix `??` (lines 140, 194 and 316) with truthiness (lines 195, 261 and 317), sometimes in the same sentence.
- **Who sends `""`.** Claude Code 2.1.325 drops a positional argument that was not typed (it zips the argument names with the words given), so it is unaffected. A client with a form that submits an unfilled optional field as `""` gets the refusals and the blanks above.

**Done when:** on `prompts/get`, an argument whose value is `""` is treated exactly as if it were omitted, for all four prompts and every argument. The prompt renders its fallback text, and `month: ""` or `ledger: ""` is not refused. A non-empty malformed value is still refused as today. A unit case per prompt in `src/features/ai-agent/api/__tests__/` renders each argument as `""` and as omitted and asserts the same text, and it fails with the fix reverted. `docs/mcp.md` "Prompts" says that an empty argument counts as omitted. Package: `backend-cluster/backend-v2`. Prompts are MCP-only, so no REST or GraphQL change is needed.

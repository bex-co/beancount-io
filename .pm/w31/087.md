# `renameLedgerFile` with `oldPath` naming an existing directory (and GraphQL `getLedgerFile` with `missingAsError: true`) returns `NOT_FOUND` instead of `BAD_USER_INPUT`

**Minor · backend-v2 (`src/features/ledger/workflow/ledger-workflow.ts`) / ledger (`src/api/files.ts`) · 20–30m · A1.** Every other file read, edit, and delete surface in the API (`readLedgerFiles`, MCP resource `beancount://{owner}/{name}/files/{path}`, REST `GET .../files/{path}`, `updateLedgerFiles`, `deleteLedgerFiles`, REST `DELETE .../files/{path}`) distinguishes an existing directory from a missing file and returns `BAD_USER_INPUT: <path> is a directory, not a file`. In contrast, `renameLedgerFile` (`oldPath` naming an existing directory) returns `NOT_FOUND: File with ID '<dir>' not found` across MCP, REST (`404`), and GraphQL — misleading an agent into thinking the folder does not exist. The same underlying gap makes `LedgerWorkflow.getLedgerFile` (`ledger-workflow.ts:2278-2284`) with `missingAsError: true` return `NOT_FOUND` instead of reaching its already-implemented `if (data.type === "dir") throw new BadUserInputError(...)` branch (which only passes in unit tests because the mock returns `{ type: "dir" }`, while `backend-cluster/ledger/src/api/files.ts:346` collapses Gitea's directory array response to `null`).

## Root cause

1. `backend-cluster/ledger/src/api/files.ts:345-349`:
   ```ts
   const data = res.data as ContentsResponse | ContentsResponse[] | null;
   if (data === null || Array.isArray(data)) {
     ctx.body = successResponse(null);
     return;
   }
   ```
   When Gitea's `repoGetContents` receives a directory path, it returns a `ContentsResponse[]` array. `getLedgerFile` converts that array to `successResponse(null)`, making directories indistinguishable from 404 missing files. By contrast, `getLedgerFilesContent` (`files.ts:371-405`, using Gitea's `repoGetFileContentsPost`) returns `{ path, type: "dir", ... }`, which is why `LedgerRepoService` (`readLedgerFiles`, `updateLedgerFiles`, `deleteLedgerFiles`) detects directories accurately.
2. `backend-cluster/backend-v2/src/features/ledger/workflow/ledger-workflow.ts:1483-1495`:
   `renameLedgerFile` fetches `oldPath` via `favaApiClient.ledgers.getLedgerFile(...)` and throws `NotFoundError("File", input.oldPath)` whenever `!oldFile`.
3. `backend-cluster/backend-v2/src/features/ledger/workflow/ledger-workflow.ts:2269-2285`:
   `getLedgerFile` already checks `if (data.type === "dir") throw new BadUserInputError(...)` when `missingAsError` is true (and unit test `ledger-workflow.test.ts:2324-2332` stubs `{ type: "dir" }` directly), so the production `null` response from `files.ts:346` bypasses that guard.

## Fix

Owning package: `backend-cluster/backend-v2` (preferred minimal scope without changing `GET /ledgers/:owner/:repo_name/files`'s `null` wire contract for existing callers).

1. **Preferred (`backend-v2`-only, zero wire-contract risk):**
   - In `LedgerWorkflow.renameLedgerFile` (`src/features/ledger/workflow/ledger-workflow.ts:1483-1495`), either look up `oldPath` via `favaApiClient.ledgers.getLedgerFilesContent(ledgerOwner, ledgerName, { files: [input.oldPath] })` (which already preserves `type: "dir"` — or, when `getLedgerFile` returns `null`, fall back to `getLedgerFilesContent` / `getLedgerDirContent` on `oldPath` to distinguish a directory from a missing file). When `oldPath` is a directory (`type === "dir"`), throw `BadUserInputError(\`${input.oldPath} is a directory, not a file\`, "oldPath", "Rename files individually, or list the directory first with `listLedgerFiles`.")`.
   - In `LedgerWorkflow.getLedgerFile` (`src/features/ledger/workflow/ledger-workflow.ts:2269-2288`), when `args.missingAsError` is true and `getLedgerFile` returns `null`, perform the same directory check (e.g. via `getLedgerFilesContent` with `files: [args.path]`) so the existing `BAD_USER_INPUT` directory error fires against the real ledger service too. Keep `missingAsError: false`/omitted returning `null` for shipped clients (`w21/201`).
2. **Alternative (if changing `backend-cluster/ledger/src/api/files.ts:346` instead):**
   - If `GET /ledgers/:owner/:repo_name/files?path=` is changed to return `{ type: "dir", ... }` on `Array.isArray(data)`, **every** caller of `favaApiClient.ledgers.getLedgerFile` in `backend-v2` must be updated to handle `type === "dir"`:
     - `ledger-workflow.ts:1491` (`renameLedgerFile` `oldPath` → `BadUserInputError`)
     - `ledger-workflow.ts:1504` (`renameLedgerFile` `newPath` → ignore `type === "dir"` so `assertNoPortableTwin` at `:1533` still throws `CONFLICT: <newPath> cannot be created: it is an existing folder`, not `BAD_USER_INPUT: file already exists`)
     - `ledger-workflow.ts:2286` (`getLedgerFile` with `missingAsError` falsy → return `null` when `data.type === "dir"` instead of mapping a dir as a file)
     - `ledger-entry-service.ts:1040` (`fileExists` → return `false` for `type === "dir"`)
     - `plaid-sync-service.ts:795` (target file check → refuse `type === "dir"` rather than treating it as an existing file)
3. Add regression tests in `src/features/ledger/workflow/__tests__/ledger-workflow.test.ts` and `src/features/ledger/api/rest/v1/__tests__/rename-parity.test.ts` covering:
   - `renameLedgerFile` with `oldPath` = existing directory across MCP, REST (`400`), and GraphQL → `BAD_USER_INPUT` (`<dir> is a directory, not a file`),
   - `renameLedgerFile` with `oldPath` = genuinely missing file → still `NOT_FOUND`,
   - `renameLedgerFile` with `newPath` = existing directory → still `CONFLICT` (`<dir> cannot be created: it is an existing folder`),
   - `getLedgerFile(missingAsError: true)` on an existing directory when upstream `getLedgerFile` returns `null` → `BAD_USER_INPUT` (and `missingAsError: false` still returns `null`).
4. Run `yarn typecheck`, `yarn lint:deadcode`, `yarn format:check`, `yarn test`, and `yarn generate-v1-openapi` in `backend-cluster/backend-v2/` (plus `backend-cluster/ledger` checks if `files.ts` is touched).

# Hosted and local `bea` disagree on `at_value` for cost-less holdings in a non-operating currency

Source: follow-up from the `/loopx w31` routine `mcp-qa`, run 98, 2026-11-19.

- **`bea`** values a holding that has no cost and is held in a non-operating currency in the first operating currency that has a quote. That has been its rule since `w3/241` and `w1/050` (`ad933da20`, `cli/src/fava/core/conversion.py` `get_market_value`).
- **The hosted engine** keeps that holding in its own units, the way Fava's `get_market_value` does (`backend-cluster/ledger/src/foundation/rustledger/cost-valuation.ts`, ledger `report-allowlist.json`).
- **Result:** the hosted trial balance `valuation_adjustment` (`w1/291`) differs from `bea report trial-balance -x at_value --json` on any ledger that holds foreign cash with a quote. Live, on a QA ledger, hosted reports `Assets:Cash` as 12.00 EUR and `bea` reports 13.2000 USD. MCP, REST and GraphQL all agree with each other; only `bea` differs.
- **Minimal repro:**
  1. Set `option "operating_currency" "USD"`.
  2. Open `Assets:Euro` against `Equity:Opening` with 100.00 EUR.
  3. Add `price EUR 1.10 USD`.
  4. Run `bea -x at_value`: Assets is 110.0000 USD. Hosted keeps 100.00 EUR.
- **Separate difference:** on books that net to zero, `bea -x USD` prints the line as `{"USD":"0"}`, while hosted prints `{}`.
- **Owner decision needed:** pick one rule. Fava's rule is to keep units; `bea`'s rule is to convert to an operating currency.

**Done when:** after the owner picks a rule, the repro gives the same `at_value` answer on `bea` and hosted. Or the deliberate difference is written down in `backend-cluster/backend-v2/docs/mcp.md` and the CLI usage docs.

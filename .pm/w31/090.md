# `createPullRequest` passes unencoded `change.path` and `dir` to `repoGetContents`, failing with Gitea `400`/`500` on `%`/`#` paths and letting `#`+`?` paths bypass `assertPortableRepoPath` across MCP, REST, and GraphQL

**Major · backend-v2 (`src/features/gitea/pull-request/service/pull-request-service.ts`) · 20–30m · A1.** The generated Gitea client `repoGetContents` (`src/features/gitea/client/gitea-api.ts:7008-7024`, line `7019`) interpolates `filepath` directly into the request URL without percent-encoding:

```ts
path: `/repos/${encodeURIComponent(owner)}/${encodeURIComponent(repo)}/contents/${filepath}`,
```

`PullRequestService.createPRFromPatch` (`src/features/gitea/pull-request/service/pull-request-service.ts`) passes raw, unencoded paths into `repoGetContents` at **both** call sites:

1. `:359-366` — existence and blob-SHA lookup for `change.path`
2. `:409-415` — directory listing `listFolder(dir)` for `assertNoPortableTwin`

By contrast, `LedgerWorkflow.undoLedgerCommit` (`src/features/ledger/workflow/ledger-workflow.ts:1793-1800`) encodes each path segment before calling `repoGetContents`: `path.split("/").map(encodeURIComponent).join("/")`. Because `pull-request-service.ts` omits segment encoding:

- Any valid portable filename or directory containing `%` (e.g. `qa-20261124-100%.bean`) produces a malformed URL path, and Gitea rejects the lookup with `400 Bad Request` (`OPERATION_NOT_ALLOWED` on MCP, `{ success: false }` on REST/GraphQL).
- Any filename containing `#` after an existing file prefix (e.g. `main.bean#qa-20261124-probe`) has `#…` (and the `?ref=main` query string) stripped by `fetch` as a URL fragment. Gitea returns `main.bean`'s blob SHA, so `createPRFromPatch` misclassifies the new file as an `update`, skips both `assertPortableRepoPath` and `assertNoPortableTwin`, and sends an invalid `update` to `repoChangeFiles`, crashing Gitea with `500` (`SERVICE_UNAVAILABLE`).
- A non-portable filename with `#` followed by Windows-forbidden `?` (e.g. `main.bean#aux?bad`) bypasses `assertPortableRepoPath` completely instead of being refused upfront with `BAD_USER_INPUT`, and crashes Gitea with `500` (`SERVICE_UNAVAILABLE`).

## Root cause

1. `backend-cluster/backend-v2/src/features/gitea/client/gitea-api.ts:7019`:
   `repoGetContents` builds `/repos/${encodeURIComponent(owner)}/${encodeURIComponent(repo)}/contents/${filepath}` without encoding `filepath` segments.
2. `backend-cluster/backend-v2/src/features/gitea/pull-request/service/pull-request-service.ts:359-366` passes raw `change.path` to `client.repos.repoGetContents(...)`.
3. `backend-cluster/backend-v2/src/features/gitea/pull-request/service/pull-request-service.ts:409-415` passes raw `dir` to `client.repos.repoGetContents(...)` inside `listFolder` for `assertNoPortableTwin`.

## Fix

Owning package: `backend-cluster/backend-v2`. Shared service change updates all three eligible surfaces together (MCP `createPullRequest`, REST `POST /api-gateway/v1/ledgers/{owner}/{name}/pull-requests`, GraphQL `Mutation.createPullRequestFromPatch`) with no OpenAPI schema change.

1. In `src/features/gitea/pull-request/service/pull-request-service.ts`, encode every path segment with `encodeRepoPath = (path: string) => path.split("/").map(encodeURIComponent).join("/")` (matching `src/features/ledger/workflow/ledger-workflow.ts:1793-1800`; optionally share a small helper) before passing `change.path` at `:363` and `dir` at `:412` to `client.repos.repoGetContents`. Keep the unencoded `change.path` in the `ChangeFileOperation` payload passed to `repoChangeFiles` (sent in JSON body, not URL) and in error messages.
2. Add unit tests in `src/features/gitea/pull-request/service/__tests__/pull-request-service.test.ts` verifying:
   - `change.path` containing `%` (e.g. `100%.bean`), `#` (e.g. `main.bean#note`), and nested segments (`dir%1/sub#2.bean`) is passed segment-encoded to `repoGetContents` while `repoChangeFiles` receives the raw path;
   - `listFolder(dir)` passes segment-encoded `dir` (e.g. `dir%1/sub#2`) to `repoGetContents`;
   - `main.bean#aux?bad` reaches `assertPortableRepoPath` and throws `BadUserInputError` before `repoChangeFiles`.
3. Add 3-surface adapter parity assertions in `src/features/ai-agent/api/__tests__/pull-request-parity.test.ts` covering MCP, REST, and GraphQL for `%` and `#`+`?` paths.
4. Run `yarn typecheck`, `yarn lint:deadcode`, `yarn format:check`, `yarn test`, and `yarn generate-v1-openapi` in `backend-cluster/backend-v2/`.

# Empty `accountId: ""` in `PlaidItemService.getUnsyncedTransactionsForScope` silently drops the filter and widens to all bank accounts on MCP, REST, and GraphQL (gap in `w1/189`)

**Minor · backend-v2 (`PlaidItemService.getUnsyncedTransactionsForScope`) · 25–35m · A1.** `w1/189` established that an empty or blank bank ID must be refused upfront with `BAD_USER_INPUT` (`"<field> must not be empty"`) before authorization or database lookup, and `assertBankId` (`src/features/plaid/utils/assert-bank-id.ts:14-19`) rejects both `""` and whitespace-only strings. However, `PlaidItemService.getUnsyncedTransactionsForScope` (`plaid-item-service.ts:491`) guards the single-account branch with `if (accountId)` instead of `if (accountId !== undefined)`. Because `""` is falsy, passing an explicit empty `accountId: ""` bypasses `authorizedAccount()` / `assertBankId()` and silently widens the operation to **all** enabled bank accounts on the ledger — returning every account's staged transactions on `listStagedBankTransactions` / `bank-transactions/unsynced` and running LLM categorization over every account's staged transactions on `bank-transactions/suggested-categories` — whereas whitespace `"   "` is truthy and is refused with `BAD_USER_INPUT: accountId must not be empty`. Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`) on 2026-11-23 against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, verified at HEAD `b311b440b`). Credential: unpinned read/write/admin `bcio_` key on the QA account. Synthetic ledger: `<qa-owner>/mcp-agent-eval` (read-only for this finding; disposable write round-trip restored `main.bean` byte-for-byte, blob `f1a0b83c`, sha256 `77c3a591efd311e0`, 0 bean-check errors).

## Root cause

Not deployment lag — present at HEAD `b311b440b`:

`backend-cluster/backend-v2/src/features/plaid/service/plaid-item-service.ts:479-516` (`PlaidItemService.getUnsyncedTransactionsForScope`):

```ts
  private async getUnsyncedTransactionsForScope(
    identity: Identity,
    ledgerId: string,
    action: AuthorizationAction,
    accountId?: string,
  ) {
    if (accountId) {
      const { account, item } = await this.authorizedAccount(
        identity,
        action,
        ledgerId,
        accountId,
      );
      ...
    }
```

Checking truthiness (`if (accountId)`) treats `""` identically to `undefined` (omitted), skipping `authorizedAccount()` (which calls `assertBankId(accountId, "accountId")` at `:329`) and executing the ledger-wide branch at `:518-544`. GraphQL's optional `accountId?: string | null` should also treat explicit `null` vs `undefined` consistently: `null` / `undefined` means omitted, while any `string` (including `""`) enters `authorizedAccount()` and fails `assertBankId` when blank.

## Fix

In `backend-cluster/backend-v2`:

1. In `PlaidItemService.getUnsyncedTransactionsForScope` (`src/features/plaid/service/plaid-item-service.ts:491`):
   - Change `if (accountId)` to `if (accountId !== undefined && accountId !== null)` so an explicit empty string `""` enters `authorizedAccount()` and is refused upfront by `assertBankId(accountId, "accountId")` with `BAD_USER_INPUT` (`field: "accountId"`, `"accountId must not be empty"`) before any authorization or database lookup.
   - Check `PlaidQueryResolver` (`src/features/plaid/api/resolvers/plaid-resolver.query.ts`) to ensure GraphQL `accountId: undefined` / `null` stays omitted while `accountId: ""` passes `""` through untouched.
2. Add unit and 3-surface adapter parity regression tests:
   - In `src/features/ai-agent/api/__tests__/bank-empty-id-parity.test.ts` (and/or `bank-ledger-wide-read-parity.test.ts`): cover `accountId: ""` and `accountId: "  "` on MCP tool `listStagedBankTransactions`, MCP resources `bankUnsyncedTransactions` and `bankSuggestedCategories`, REST `GET .../bank-transactions/unsynced` and `GET .../bank-transactions/suggested-categories`, and GraphQL `getUnsyncedPlaidTransactions` and `suggestPlaidTransactionCategories` — asserting `BAD_USER_INPUT` (`field: "accountId"`, REST HTTP `400`) with zero authorization/model calls, while omitted `accountId` continues to succeed ledger-wide.
   - In `src/features/plaid/service/__tests__/plaid-item-service.test.ts`: cover `getUnsyncedTransactions` and `suggestCategories` with `accountId: ""` and `accountId: "   "`.

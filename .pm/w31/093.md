# `moveEntrySources` and `renameLedgerFile` emit unescaped `[...]` paths as `include` lines, which the ledger loader expands as globs and breaks the ledger across MCP, REST, and GraphQL

**Major · `backend-cluster/backend-v2` + `backend-cluster/ledger` · 30–40m · A1.** `assertPortableRepoPath` (`backend-cluster/backend-v2/src/features/ledger/utils/safe-repo-path.ts:57` and `backend-cluster/ledger/src/features/ledger/utils/safe-repo-path.ts`) blocks Windows-illegal characters `<>:"|?*` (which excludes `*` and `?`) but allows `[` and `]` (valid on Linux, macOS, and Windows). When a caller passes a target path containing `[...]` (such as `books/q[1].bean`) to `moveEntrySources` with `includeFrom` or `renameLedgerFile` with `updateIncludes: true`, the server writes an unescaped `include "books/q[1].bean"` line into the including file. Both the ledger loader (`backend-cluster/ledger/src/foundation/rustledger/file-map-loader.ts:129, 608, 798`, `source-slice.ts:684`) and the rustledger WASM engine treat any `include` target containing `[` as a glob character class (`isGlob`: `/[*?[]/`):

- When no file matching the character class exists (e.g. `q1.bean`), the newly moved or renamed file is **never loaded** — producing `include pattern "…" does not match any files` plus cascading `Account … was never opened` / `Balance failed` errors. Crucially, `renameLedgerFile` does not refuse commits on new bean-check errors (`docs/mcp.md`), so `dry_run: false` commits the broken ledger directly; and once the includer holds `include "books/q[1].bean"`, `isGlobPattern` (`include-target.ts:111-113`) classifies that line as a glob, so subsequent `renameLedgerFile` (`ledger-workflow.ts:1566`) and `deleteLedgerFiles` with `removeIncludes: true` (`include-references.ts:230, 253`) ignore it and can neither rewrite nor remove it.
- When a sibling matching the character class *does* exist (e.g. `q1.bean`), `include "books/q[1].bean"` matches the wrong file instead of `books/q[1].bean`.

## Environment

- Target: `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`), verified against local `HEAD` `e873717a8` (Node `v22.22.0`).
- Credential: unpinned read/write/admin `bcio_` API key on the designated QA account and synthetic ledger `<qa-owner>/mcp-agent-eval` (restored byte-for-byte after probe; verified `checkLedger` 0 errors).

## Expected

An operation that writes a Beancount `include` line targeting a specific file (`moveEntrySources` adding an include via `includeFrom`, `renameLedgerFile` rewriting an include via `updateIncludes`, and auto-routed includes in `DirectiveAppendWorkflow` / `addBulkEntries`) must not emit a broken unescaped glob pattern. Because Beancount (Python `glob.glob` and `rustledger`) interprets `[` in `include` targets as a glob character class — and backend-v2's own `isGlobPattern` (`include-target.ts:111-113`) treats `[` as a non-rewritable glob — refuse any `include`-targeted file path containing `[` (or glob metacharacters `isGlobPattern(path)`) upfront with `BAD_USER_INPUT` naming the parameter (`toPath` / `newPath`) and explaining that `[` is a Beancount `include` glob metacharacter and cannot be targeted literally in an `include` line.

## Root cause

1. `assertPortableRepoPath` (`backend-cluster/backend-v2/src/features/ledger/utils/safe-repo-path.ts:45-66`, mirrored in `backend-cluster/ledger/src/features/ledger/utils/safe-repo-path.ts`) intentionally allows `[` and `]` (portable on macOS/Windows/Linux, needed for non-included attachments like `receipt[1].pdf`).
2. Every `include`-line emitter escapes only `\` and `"` and writes `[` verbatim:
   - `addIncludes` (`backend-cluster/ledger/src/features/ledger/utils/routed-includes.ts:12-16`), called by `LedgerJournalService.moveSourceSlices` (`backend-cluster/ledger/src/features/ledger/service/ledger-journal-service.ts:1505-1511`) and `addBulkEntries` (`backend-cluster/ledger/src/api/entries.ts`).
   - `formatIncludeLine` / `addIncludeLines` (`backend-cluster/backend-v2/src/features/ledger/utils/include-target.ts:43-77`), called by `LedgerWorkflow.renameLedgerFile` (`backend-cluster/backend-v2/src/features/ledger/workflow/ledger-workflow.ts:1672-1675`) and `DirectiveAppendWorkflow.appendDirectiveText` (`backend-cluster/backend-v2/src/features/ledger/workflow/directive-append-workflow.ts:185`).
3. `isGlob` (`backend-cluster/ledger/src/foundation/rustledger/file-map-loader.ts:129`, used at `:608`, `:798`, and `source-slice.ts:684`), rustledger's WASM loader, and `isGlobPattern` (`backend-cluster/backend-v2/src/features/ledger/utils/include-target.ts:111-113`, used by `ledger-workflow.ts:1566` and `include-references.ts:230, 253`) all match `/[*?[]/`. None of the include-writing paths reject a literal target that `isGlobPattern` matches.

## Fix

- **Owning packages & surfaces:** `backend-cluster/backend-v2` and `backend-cluster/ledger`; changes apply uniformly across MCP (`moveEntrySources`, `renameLedgerFile`, `appendLedgerText`, `addLedgerEntries`), REST (`POST .../entries/move`, `POST .../rename-file`, `POST .../directives/text`, `POST .../entries`), and GraphQL (`moveLedgerEntrySources`, `renameLedgerFile`, `appendLedgerText`, `bulkEntries`).
- Refuse a target path containing `[` (i.e. `isGlobPattern(path)`) with `BAD_USER_INPUT` naming the field (`toPath` / `newPath`) whenever the operation will write an `include` line for it:
  1. `LedgerJournalService.moveSourceSlices` in both `backend-cluster/backend-v2/src/features/ledger/service/ledger-journal-service.ts` (upfront when `includeFrom !== undefined`) and `backend-cluster/ledger/src/features/ledger/service/ledger-journal-service.ts` (when `includeFrom !== undefined && !reached`).
  2. `LedgerWorkflow.renameLedgerFile` (`backend-cluster/backend-v2/src/features/ledger/workflow/ledger-workflow.ts`) when `includingFiles.length > 0 && input.updateIncludes` (or whenever an exact include line would be rewritten to `newPath`).
  3. `DirectiveAppendWorkflow.appendDirectiveText` (`directive-append-workflow.ts`) / `addIncludes` (`routed-includes.ts`) if an auto-routed target requiring a new `include` contains `[`.
- Keep non-included files (e.g. `documents/receipt[1].pdf` created via `createLedgerFiles`) allowed so attachment uploads are unaffected.
- Add regression tests: 3-surface adapter parity tests in `move-entries-parity.test.ts` and `rename-parity.test.ts` (verifying `BAD_USER_INPUT` on MCP, REST `400`, and GraphQL on both `dryRun: true` and `dryRun: false`, plus non-bracket controls) and unit tests in `backend-cluster/ledger`.

## Blast radius

- Callers of `formatIncludeLine` / `addIncludeLines` (`ledger-workflow.ts`, `directive-append-workflow.ts`) and `addIncludes` (`ledger-journal-service.ts`, `api/entries.ts`).
- `renameLedgerFile` (`dry_run: false`) is the sharpest failure mode because it commits even when bean-check reports new errors, stranding the rewritten `include` line from future rename/delete guards.

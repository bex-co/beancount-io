# MCP protocol handlers (`initialize`, `tools/list`, `resources/list`, `resources/templates/list`, `prompts/list`, `ping`, and `params.name` on `tools/call` / `prompts/get`) skip `assertNoNulDeep`, accepting NUL, unpaired surrogates, >1 MiB strings, and >32-level nesting (gap in `w31/065`)

**Minor · backend-v2 (`src/server/api/composition-root.ts`) · 30–45m · A1.** `assertNoNulDeep` (`src/shared/assert-no-nul.ts:14-61`, introduced by `w23/m22` and `w23/m23`) is the monorepo's uniform input boundary rejecting U+0000 NUL bytes, unpaired UTF-16 surrogates, strings over 1,048,576 characters, arrays over 10,000 members, and nesting deeper than 32 levels with `BAD_USER_INPUT` before schema validation or domain work. REST (`validation-middleware.ts`), GraphQL (`nul-middleware.ts`), MCP `tools/call` `arguments`, MCP `resources/read` `uri` + variables (`w31/065`), and MCP `prompts/get` `arguments` (`w31/065`) all enforce it — but the remaining MCP JSON-RPC method handlers in `src/server/api/composition-root.ts` skip it completely:

1. `initialize` (`:924-944`) accepts NUL bytes, unpaired surrogates, >1 MiB strings, and >32-level nested `capabilities.experimental` and returns HTTP `200 OK`.
2. `tools/list`, `resources/list`, `resources/templates/list`, and `prompts/list` (`:1018-1039`) accept NUL bytes, unpaired surrogates, >1 MiB strings (in `cursor` or extra fields), and >32-level nested objects and return HTTP `200 OK`.
3. `ping` (unwrapped SDK default handler) accepts NUL bytes, unpaired surrogates, >1 MiB strings, and >32-level nested objects in `params` and returns HTTP `200 OK`.
4. `tools/call` (`dispatchTool`, `:580-604`) and `prompts/get` (`:952-987`) look up `toolHandlers.get(name)` / `promptBuilders.get(name)` before running `assertNoNulDeep` and never run `assertNoNulDeep` on `params.name` (or `params._meta`). Passing `name: "runBqlQuery\u0000"` or `"runBqlQuery\ud800"` therefore returns `NOT_FOUND` (and silently corrupts unpaired `\ud800` into U+FFFD in the echoed ID) instead of `BAD_USER_INPUT`.

Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`) on 2026-11-24 against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, verified at HEAD `d5a22712d`). Credential: unpinned read/write/admin `bcio_` key on the QA account. Read-only protocol probes only; no files were modified.

## Repro (live)

Reproduced via `POST https://beancount.io/api-gateway/mcp` (authenticated with `Authorization: Bearer <token>`, `Accept: application/json, text/event-stream`):

1. **`initialize`** with `protocolVersion: "2025-11-25"`, `clientInfo: { name: "a\u0000b", version: "1" }`, `name: "a\ud800b"`, `name: "x".repeat(1048577)`, or `capabilities: { experimental: <40-level nested object> }`:
   - **Actual:** All four return HTTP `200 OK` with a normal `InitializeResult`.
2. **`tools/list`, `resources/list`, `resources/templates/list`, `prompts/list`** with `params: { cursor: "a\u0000b" }`, `{ cursor: "a\ud800b" }`, `{ cursor: "x".repeat(1048577) }`, or `{ extra: <40-level nested object> }`:
   - **Actual:** All return HTTP `200 OK` with the normal list payload.
3. **`ping`** with `params: { a: "x\u0000y" }`:
   - **Actual:** HTTP `200 OK` `{}`.
4. **`tools/call`** with `params: { name: "runBqlQuery\u0000", arguments: {} }` and `{ name: "runBqlQuery\ud800", arguments: {} }`:
   - **Actual:** HTTP `200`, `isError: true`, `structuredContent.error.code: "NOT_FOUND"`, message `"Tool with ID 'runBqlQuery\u0000' not found"` / `"Tool with ID 'runBqlQuery\uFFFD' not found"` (lone surrogate silently replaced with U+FFFD).
5. **`prompts/get`** with `params: { name: "close-month\u0000", arguments: {} }` and `{ name: "close-month\ud800", arguments: {} }`:
   - **Actual:** JSON-RPC `-32002` `NOT_FOUND`, message `"Prompt with ID 'close-month\u0000' not found"` / `"Prompt with ID 'close-month\uFFFD' not found"`.
6. **Working controls (same credential, same deployment):**
   - `tools/call` `arguments` with `\u0000` / `\ud800` / >1 MiB string / >32-level nesting → `isError: true`, `BAD_USER_INPUT`.
   - `resources/read` `params.uri` with `\u0000` / `%00` / `\ud800` → JSON-RPC `-32602` `BAD_USER_INPUT`.
   - `prompts/get` `params.arguments` with `\u0000` / `\ud800` → JSON-RPC `-32602` `BAD_USER_INPUT`.

## Expected

Every MCP JSON-RPC method enforces `assertNoNulDeep` across its `params` before routing, lookup, or SDK execution:

- `initialize`, `tools/list`, `resources/list`, `resources/templates/list`, `prompts/list`, `ping`, and `prompts/get` (`params.name` and `params._meta`, in addition to `params.arguments`) reject NUL, unpaired surrogates, >1,048,576-char strings, >10,000-member arrays, and >32-level nesting as JSON-RPC `-32602` `BAD_USER_INPUT` via `refuseMcpRequest` / `refuseMcpParameters`.
- `tools/call` validates `params.name` (and `params._meta`) with `assertNoNulDeep` before `toolHandlers.get(name)` (and preserves `NUL_EXEMPT_PATHS` for `params.arguments`), refusing invalid `params.name` as `BAD_USER_INPUT` rather than `NOT_FOUND` with a U+FFFD-corrupted tool ID.

## Root cause

Not deployment lag — present at HEAD `d5a22712d` in `backend-cluster/backend-v2/src/server/api/composition-root.ts`:

- `:580-604` (`dispatchTool`): calls `toolHandlers.get(name)` before running `assertNoNulDeep`, and calls `assertNoNulDeep(request.params.arguments, NUL_EXEMPT_PATHS)` only on `arguments` — never on `request.params.name` or `request.params._meta`.
- `:924-944` (`InitializeRequestSchema` handler): validates with `InitializeRequestSchema.safeParse(rawRequest)` and never calls `assertNoNulDeep`.
- `:952-987` (`GetPromptRequestSchema` handler): calls `promptBuilders.get(name)` before running `assertNoNulDeep`, and calls `assertNoNulDeep(request.params.arguments)` only on `arguments` — never on `request.params.name` or `request.params._meta`.
- `:1018-1039` (`ListToolsRequestSchema`, `ListResourcesRequestSchema`, `ListResourceTemplatesRequestSchema`, `ListPromptsRequestSchema` wrappers): validate with `schema.safeParse(rawRequest)` and forward straight to `sdkHandler` without calling `assertNoNulDeep`.
- `ping`: no wrapper registered in `composition-root.ts`, so the SDK's default handler answers `{}` without checking `params`.

## Fix

In `backend-cluster/backend-v2/src/server/api/composition-root.ts`:

1. In `InitializeRequestSchema` (`:924-944`), all four `List*RequestSchema` wrappers (`:1018-1039`), and a `PingRequestSchema` wrapper (preserving the SDK's `{}` success response and strict/standard parameter validation), run `assertNoNulDeep(rawRequest.params, undefined, "params")` (returning `-32602` `BAD_USER_INPUT` via `refuseMcpRequest` on failure).
2. In `dispatchTool` (`:580-604`, or in the outer `CallToolRequestSchema` handler at `:649-674`), run `assertNoNulDeep` on `params.name` and `params._meta` (and `params.task` if present) before `toolHandlers.get(name)`, while keeping `assertNoNulDeep(request.params.arguments, NUL_EXEMPT_PATHS)` for file-content exemptions (`files[].content`). On failure for `params.name`, return `BAD_USER_INPUT` (consistent with `mcp-nul-contract.test.ts` / `mcp-request-parameters.test.ts`).
3. In `GetPromptRequestSchema` (`:952-987`), run `assertNoNulDeep` on `request.params` (covering `name`, `arguments`, and `_meta`) before `promptBuilders.get(name)`, refusing with `refuseMcpRequest` (`-32602` `BAD_USER_INPUT`).
4. Add regression tests in `src/server/api/__tests__/mcp-nul-contract.test.ts` (and/or `mcp-request-parameters.test.ts`) covering NUL (`\u0000`), unpaired surrogate (`\ud800`), >1,048,576-char string, and >32-level nested object on `initialize`, `tools/list`, `resources/list`, `resources/templates/list`, `prompts/list`, `ping`, `tools/call` `params.name`, and `prompts/get` `params.name`, plus valid UTF-8 / paired-surrogate emoji controls.

## Blast radius & adjacent states

- Owning package: `backend-cluster/backend-v2` only (MCP transport layer; REST and GraphQL already validate whole payloads via `validation-middleware.ts` and `nul-middleware.ts`).
- Adjacent states: valid `initialize` handshakes (including clients passing `capabilities.experimental` within normal depth/size and valid Unicode/emoji `clientInfo.name`), valid `*/list` calls with or without `cursor`, valid `ping` calls (empty or absent `params`), unknown-but-well-formed tool/prompt names (still `NOT_FOUND`), and `NUL_EXEMPT_PATHS` for `files[].content` on file-write tools remain unchanged.

# `revertCommit` / `LedgerWorkflow.undoLedgerCommit` skips `assertNoPortableTwin`, allowing case/Unicode twins into Git and returning `valid: true` on `dry_run` for file-vs-folder collisions across MCP, REST, and GraphQL

**Major · backend-v2 (`src/features/ledger/workflow/ledger-workflow.ts`) · 30–40m · A1.** Every other path-creating operation in `backend-v2` (`LedgerRepoService.assertNewPathsPortable`, `LedgerWorkflow.createLedgerFile`, `LedgerWorkflow.renameLedgerFile`, `PullRequestService.createPRFromPatch`, and `LedgerJournalService.moveSourceSlices` after `w31/086`) runs `assertNoPortableTwin` (`src/features/ledger/utils/portable-twin.ts:25-79`) to refuse creating a file that collides with an existing file or folder by letter case, Unicode normalization (NFC vs NFD), or invisible characters, or that places a file beneath an existing file (`dir/sub.bean` when `dir` is a file) or at an existing folder. `LedgerWorkflow.undoLedgerCommit` (`src/features/ledger/workflow/ledger-workflow.ts:1736-1875`) builds `plan.operations` via `planRevert` (`:1842`) and passes `create` operations straight to `favaApiClient.ledgers.changeLedgerFiles` (`:1867`) with no `assertNoPortableTwin` check. As a result, across MCP (`revertCommit`), REST (`POST /api-gateway/v1/ledgers/{owner}/{name}/revert-commit`), and GraphQL (`Mutation.revertLedgerCommit`):

1. **Case / Unicode twin creation:** Reverting a commit that deleted `foo.bean` after a later commit created `Foo.bean` (or an NFC/NFD / invisible-character twin) passes `dry_run: true` with `valid: true` and **commits both twin files simultaneously into Git**, breaking checkouts on macOS and Windows.
2. **File-vs-folder collision (`dry_run: true` lies `valid: true`):** Reverting a commit that deleted `dir/sub.bean` after a later commit created a file at `dir` passes `dry_run: true` with `valid: true`, then fails late at Gitea on `dry_run: false` with `BAD_USER_INPUT: a file exists where you're trying to create a subdirectory` instead of refusing upfront with `CONFLICT`.

Credential: unpinned read/write/admin `bcio_` API key on the QA account (`ledger.read` key boundary also exercised). Synthetic ledger: `<qa-owner>/mcp-agent-eval` (disposable probe files created and cleaned up immediately; `main.bean` verified byte-for-byte unchanged, blob `f1a0b83c`, sha256 `77c3a591efd311e0`, `rootFiles=[main.bean]`, 0 bean-check errors).

## Root cause

`backend-cluster/backend-v2/src/features/ledger/workflow/ledger-workflow.ts:1842-1874` (`LedgerWorkflow.undoLedgerCommit`):

1. `planRevert(files, blobs)` (`:1842`, implemented in `src/features/ledger/utils/commit-revert.ts`) checks only exact-path existence via `current.get(path)` (`getLedgerFilesContent` on the exact paths touched by the reverted commit). It cannot see case/Unicode siblings in the same or parent directories, nor a regular file sitting at an ancestor directory path of a re-created nested file.
2. After checking `plan.conflicts.length > 0` (`:1843`), `undoLedgerCommit` immediately builds the preview summary (`:1857-1864`) and, when `!dryRun`, invokes `favaApiClient.ledgers.changeLedgerFiles` (`:1867`) without running `assertNoPortableTwin` (or batch twin/prefix guards) on the `plan.operations` entries whose `operation === "create"`.

## Fix

Owning package: `backend-cluster/backend-v2`. Shared workflow change updates all three eligible surfaces together (MCP `revertCommit`, REST `POST /api-gateway/v1/ledgers/{owner}/{name}/revert-commit`, GraphQL `Mutation.revertLedgerCommit`) — no OpenAPI response shape change needed (existing `ConflictError` maps to HTTP `409` on REST and `CONFLICT` on MCP and GraphQL).

1. In `backend-cluster/backend-v2/src/features/ledger/workflow/ledger-workflow.ts:1842-1865`, right after `if (plan.conflicts.length > 0)` and **before** `onProjectedFiles` / `if (dryRun) return summary`:
   - Collect the paths being created (`creates`) and paths being deleted (`deleted = new Set(...)`) in `plan.operations`.
   - When `creates.length > 0`:
     - Run `assertNoPrefixAmong(creates)` and `assertNoTwinsAmong(creates)` (in case a legacy commit deleted two paths that would collide with each other on re-creation).
     - Run `assertNoPortableTwin(path, list)` for each path in `creates`, using a cached `favaApiClient.ledgers.getLedgerDirContent` wrapper (mapping `entry.type === "dir" ? "dir" : "file"`, letting `NOT_FOUND` on a nonexistent folder return `[]`) that **excludes entries being removed by the same revert**:
       - Exclude any file whose full path is in `deleted` (so reverting a legitimate case-only rename commit — e.g. deleting `Foo.bean` and re-creating `foo.bean` in one revert — or reverting a commit that replaced a folder with a file continues to succeed).
       - Consider directories whose entire remaining subtree is being deleted in the same revert (e.g., if `deleted` removes every file under a directory, or verify whether a directory entry whose sole children are all deleted in `plan.operations` should be ignored when reverting a file↔folder swap). At minimum, excluding `deleted.has(fullPath)` keeps case-only rename reverts working.
2. Update any existing `ledger-workflow` / `revert-commit` unit-test mocks that stub `favaApiClient` without `ledgers.getLedgerDirContent`.
3. Add unit tests in `src/features/ledger/workflow/__tests__/ledger-workflow.test.ts` and 3-surface parity tests in `src/features/ledger/api/rest/v1/__tests__/revert-commit-parity.test.ts` covering:
   - reverting a file deletion when a case twin (`Foo.bean`), Unicode NFC/NFD twin, or invisible-character twin exists → `CONFLICT` on both `dryRun: true` and `dryRun: false` across MCP, REST (`409`), and GraphQL, without calling `changeLedgerFiles`,
   - reverting a nested file deletion (`reports/sub.bean`) when a regular file now exists at `reports` → `CONFLICT` on both `dryRun: true` and `dryRun: false` across all three surfaces,
   - reverting a nested file deletion (`Reports/sub.bean`) when a case-colliding folder `reports/` exists → `CONFLICT`,
   - reverting a case-only rename commit (one commit deleting `foo.bean` and creating `Foo.bean`, so the revert deletes `Foo.bean` and re-creates `foo.bean` in the same batch) → still **allowed**,
   - read-only `ledger.read` credential → still `FORBIDDEN` before any Gitea or directory lookup.
4. Run `yarn typecheck`, `yarn lint:deadcode`, `yarn format:check`, `yarn test`, and `yarn generate-v1-openapi` in `backend-cluster/backend-v2/`.

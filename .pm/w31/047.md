# `commits` (`?branch=` / `branch: ""`) and `latest-commit` (`?branchName=` / `branchName: ""`) silently accept empty branch names and return default-branch (`main`) history instead of `BAD_USER_INPUT` on MCP, REST, and GraphQL

**Minor · backend-v2 (commit-read branch validation) · 25–35m · A1.** Passing an explicit empty string (`""`) for `branch` on `commits` or `branchName` on `latest-commit` bypasses the `"main"` default and forwards `sha: ""` to Gitea, which silently returns the repository's default branch — the exact Gitea quirk `w31/034` fixed in `findCommit` (`commit-details?sha=`) — while tab/newline-only branch strings (`"\t"`, `"\n"`) also bypass `assertCommitRef` and hit Gitea as `NOT_FOUND` instead of `BAD_USER_INPUT`. Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`) on 2026-11-23 against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, checked against HEAD `8714e21cb`). Credential: unpinned read/write/admin `bcio_` key on the QA account. Synthetic ledger: `<qa-owner>/mcp-agent-eval`.

## Repro (live)

Reproduced in fresh read-only requests across all three surfaces against `<qa-owner>/mcp-agent-eval`:

1. **MCP resources `commits` and `latest-commit`**:
   ```sh
   node .agents/skills/qa-shared/scripts/qa-mcp.mjs read 'beancount://<qa-owner>/mcp-agent-eval/commits?branch='
   node .agents/skills/qa-shared/scripts/qa-mcp.mjs read 'beancount://<qa-owner>/mcp-agent-eval/latest-commit?branchName='
   node .agents/skills/qa-shared/scripts/qa-mcp.mjs read 'beancount://<qa-owner>/mcp-agent-eval/commits?branch=%09'
   ```
   - `?branch=` and `?branchName=`: HTTP `200`, return `main` commits / latest commit on `main`.
   - `?branch=%09` / `?branchName=%09` / `?branch=%0A`: HTTP `200`, JSON-RPC `-32002` `NOT_FOUND` (`Branch with ID '\t' not found`) after calling Gitea.
2. **REST**:
   - `GET /api-gateway/v1/ledgers/<qa-owner>/mcp-agent-eval/commits?branch=&limit=1` → HTTP `200`, returns the latest commit on `main`.
   - `GET /api-gateway/v1/ledgers/<qa-owner>/mcp-agent-eval/latest-commit?branchName=` → HTTP `200`, returns the latest commit on `main`.
3. **GraphQL**:
   - `listCommits(ledgerId: "<qa-owner>/mcp-agent-eval", branch: "", limit: 1)` → HTTP `200`, returns the latest commit on `main`.
   - `getLatestLedgerCommit(ledgerId: "<qa-owner>/mcp-agent-eval", branchName: "")` → HTTP `200`, returns the latest commit on `main`.

Expected: omitting `branch` / `branchName` continues to default to `"main"`, while passing an explicit empty or whitespace-only string (`""`, `"\t"`, `"\n"`, `"  "`) is refused with `BAD_USER_INPUT` naming `branch` / `branchName` without calling Gitea — matching sibling `findCommit` (`w31/034`) and optional-string validation across the API (`w31/044`, `w31/045`).

## Working controls

- Omitting `branch` (`beancount://{owner}/{name}/commits`) or `branchName` (`beancount://{owner}/{name}/latest-commit`) defaults to `"main"`.
- Passing spaces (`?branch=%20%20`, `?branchName=%20%20`) is refused with `BAD_USER_INPUT` (`must not contain a space`) by `assertCommitRef`.
- Direct sibling `findCommit` (`commits-service.ts:63-72`, fixed in `w31/034` commit `9056c750e`) refuses `sha.trim() === ""` (`""`, `"\t"`, `"\n"`, `"\r\n"`) with `BAD_USER_INPUT` before contacting Gitea.

## Root cause

Not deployment lag — present at HEAD `8714e21cb`:

- `backend-cluster/backend-v2/src/features/gitea/commits/api/commit-reads.ts:33,47`: `latestLedgerCommit` (`branchName: z.string().default("main")`) and `ledgerCommits` (`branch: z.string().default("main")`) only apply the default to `undefined`, passing `""` through.
- `backend-cluster/backend-v2/src/features/gitea/commits/service/commits-service.ts:278-290` (`CommitsService.listCommits`) and `backend-cluster/backend-v2/src/features/ledger/service/ledger-repo-service.ts:171-183` (`LedgerRepoService.getLatestCommit`): JS defaults `branch = "main"` and `branchName = "main"` do not trigger on `""`, and `assertCommitRef` (`src/shared/commit-ref.ts:23-34`) rejects only spaces outside brace/colon groups, not empty or tab/newline-only strings. Both services forward `{ sha: "" }` to Gitea (`repoGetAllCommits`), which returns the default branch's commits/HEAD.

## Fix

In `backend-cluster/backend-v2`:

1. In `CommitsService.listCommits` (`src/features/gitea/commits/service/commits-service.ts:289`) and `LedgerRepoService.getLatestCommit` (`src/features/ledger/service/ledger-repo-service.ts:177`), after `assertCommitRef`, refuse `branch.trim() === ""` / `branchName.trim() === ""` with `new BadUserInputError("<param> must not be empty", "<param>", BRANCH_NOT_FOUND_HINT)` before calling Gitea (keeping the `= "main"` default when the parameter is omitted/`undefined`).
2. Add unit tests in `commits-service.test.ts` and `ledger-repo-service.test.ts`, plus 3-surface adapter tests in `commit-parity.test.ts`, covering `""`, `"\t"`, `"\n"`, and `"\r\n"` for both `commits` (`branch`) and `latest-commit` (`branchName`), asserting `BAD_USER_INPUT` and zero Gitea calls while omitted `branch`/`branchName` still defaults to `"main"`.

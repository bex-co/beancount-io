# GraphQL `deleteLedgerFile` returns `commit: null` when `removeIncludes: true` rewrites an includer, breaking parity with MCP `deleteLedgerFiles` and REST `DELETE …/files/{*path}`

**Minor · backend-v2 (`src/features/ledger/workflow/ledger-workflow.ts`) · 15–20m · A1.** In `LedgerWorkflow.deleteLedgerFile` (`src/features/ledger/workflow/ledger-workflow.ts:1331-1357`), when `input.removeIncludes` is `true` and at least one includer file is rewritten (`removals.length > 0`), the call to `favaApiClient.ledgers.changeLedgerFiles(...)` is awaited **without capturing its response** and the method returns `{ path: input.path }` — dropping `commit`:

```ts
if (removals.length > 0) {
  await unwrapFavaResponse(
    favaApiClient.ledgers.changeLedgerFiles(ledgerOwner, ledgerName, {
      ...
    }),
    "delete ledger file",
    (cause) => operationNotAllowedFromCause("delete ledger file", cause),
  );
  return { path: input.path };
}
```

By contrast, the immediately following branch (`:1366-1379`, used when `removeIncludes` is false or `removals.length === 0`) captures `const deleted = await unwrapFavaResponse(...)` and returns `{ path: input.path, ...(deleted?.commit && { commit: deleted.commit }) }`. Likewise, `LedgerWorkflow.moveLedgerFile` (`:1695-1715`), `LedgerWorkflow.undoLedgerCommit` (`:1875-1883`), and `LedgerRepoService.commitFileChanges` (`src/features/ledger/service/ledger-repo-service.ts:578-609`, used by MCP `deleteLedgerFiles` and REST `DELETE /api-gateway/v1/ledgers/{owner}/{name}/files/{*path}`) all capture `changed?.commit` from `favaApiClient.ledgers.changeLedgerFiles`.

This violates the documented undo contract in `backend-cluster/backend-v2/docs/mcp.md` ("Undo a change"): *"Every write that makes a commit returns its sha as `commit`: … GraphQL `createLedgerFile`, `updateLedgerFile` and `deleteLedgerFile`."* Without `commit`, GraphQL callers deleting an included file with `removeIncludes: true` cannot pass the commit SHA to `revertLedgerCommit`.

## Expected / Actual

- **Expected:** GraphQL `deleteLedgerFile` with `removeIncludes: true` returns `{ path: "inc.bean", commit: "<40-char commit sha>" }` when the delete + include-removal commit succeeds, matching MCP `deleteLedgerFiles`, REST `DELETE /api-gateway/v1/ledgers/{owner}/{name}/files/{*path}?remove_includes=true`, and GraphQL `deleteLedgerFile` when `removeIncludes` is false.
- **Actual:**
  - **GraphQL `deleteLedgerFile` (`removeIncludes: true`, HTTP 200):**
    `{"data":{"deleteLedgerFile":{"path":"qa-20261124-inc.bean","commit":null}}}`
    (even though the commit deleting `qa-20261124-inc.bean` and removing its `include` line from `main.bean` landed on Gitea).
  - **Working control — MCP `deleteLedgerFiles` (`remove_includes: true`, HTTP 200 SSE):**
    `{"ok":true,"commit":"26ab26389a234205d7193fd68bf8090dec3c5bc2","wrote":[{"path":"qa-20261124-inc2.bean"},{"path":"main.bean"}]}`

## Root cause

`backend-cluster/backend-v2/src/features/ledger/workflow/ledger-workflow.ts:1338-1356`:
`unwrapFavaResponse(favaApiClient.ledgers.changeLedgerFiles(...))` returns `{ commit?: string, ... }`, but the return value is discarded and line `1355` hardcodes `return { path: input.path };` without `commit`.

## Fix

Owning package: `backend-cluster/backend-v2`. No GraphQL or OpenAPI schema change needed (`DeleteLedgerFilePayload.commit` is already exposed in the schema).

1. In `src/features/ledger/workflow/ledger-workflow.ts:1338-1356`, capture the result of `changeLedgerFiles` and include `commit` when present, matching `:1366-1379`:
   ```ts
   const deleted = await unwrapFavaResponse(
     favaApiClient.ledgers.changeLedgerFiles(ledgerOwner, ledgerName, {
       ...
     }),
     "delete ledger file",
     (cause) => operationNotAllowedFromCause("delete ledger file", cause),
   );
   return {
     path: input.path,
     ...(deleted?.commit && { commit: deleted.commit }),
   };
   ```
2. Add a regression test in `src/features/ledger/workflow/__tests__/ledger-workflow.test.ts` verifying `deleteLedgerFile` with `removeIncludes: true` and a matching includer returns `{ path, commit }` from `changeLedgerFiles`.
3. Add or extend a GraphQL parity test confirming `deleteLedgerFile(..., removeIncludes: true)` surfaces the non-null `commit` SHA.
4. Run `yarn typecheck`, `yarn lint:deadcode`, `yarn format:check`, `yarn test`, and `yarn generate-v1-openapi` in `backend-cluster/backend-v2/`.

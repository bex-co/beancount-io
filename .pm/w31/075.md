# REST `DELETE …/files/{*path}` with `dryRun: true` and no `sha` returns `200 OK` for a nonexistent file (`LedgerRepoService.commitFileChanges` skips existence check for SHA-less deletes/updates; gap in `w1/219`)

**Major · backend-v2 (`src/features/ledger/service/ledger-repo-service.ts`) · 25–35m · A1.** `LedgerRepoService.commitFileChanges` (`dryRun: true`) only queries `getLedgerFilesContent` for `create` operations and for `update`/`delete` operations that carry a non-null `sha` (`w1/done/219`). When a caller sends REST `DELETE /api-gateway/v1/ledgers/{owner}/{name}/files/{*path}` with `dryRun: true` and omits the optional `sha`, `created` and `versioned` are both empty, so the dry run skips the repository check entirely and returns `200 OK { ok: true, dryRun: true, valid: true, newErrors: [] }` for a path that does not exist. Submitting the identical request with `dryRun: false` fails with `404 NOT_FOUND`, breaking the documented preview rule (`backend-cluster/backend-v2/docs/mcp.md`, `files-handler.ts:312`: *"`dryRun` previews without committing: same checks, no commit"*) and ADR 0008 surface parity with MCP `deleteLedgerFiles`. Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`) on 2026-11-23 against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, verified at HEAD `dcaa4b183`). Credential: unpinned read/write/admin `bcio_` key on the QA account. Synthetic ledger: `<qa-owner>/mcp-agent-eval`.

## Repro

1. Send a REST preview delete for a nonexistent file without `sha`:
   ```sh
   curl -sS -X DELETE \
     -H "Authorization: Bearer $QA_MCP_TOKEN" \
     -H "Content-Type: application/json" \
     -d '{"message":"test","dryRun":true}' \
     https://beancount.io/api-gateway/v1/ledgers/<qa-owner>/mcp-agent-eval/files/qa-nonexistent.bean
   ```
   - **Actual:** HTTP `200` `{"ok":true,"path":"qa-nonexistent.bean","dryRun":true,"valid":true,"newErrors":[]}`. Reproduces on repeat calls.
2. Send the identical REST delete with `dryRun: false` (commit control — safe because the file does not exist):
   - **Actual:** HTTP `404` `{"ok":false,"error":{"code":"NOT_FOUND","message":"File qa-nonexistent.bean does not exist","metadata":{"resource":"Ledger resource"}}}`.
3. Send the MCP control (`deleteLedgerFiles` with `dry_run: true` and no `sha`):
   ```sh
   node .agents/skills/qa-shared/scripts/qa-mcp.mjs call deleteLedgerFiles \
     '{"ledger":"<qa-owner>/mcp-agent-eval","description":"test","dry_run":true,"files":[{"path":"qa-nonexistent.bean"}]}'
   ```
   - **Actual (working control):** HTTP `200`, `isError: true`, `NOT_FOUND`: `"preview refused: File with ID 'qa-nonexistent.bean' not found"`.
4. Send the REST preview delete WITH a `sha` (`"a".repeat(40)`):
   - **Actual (working control):** HTTP `404` `NOT_FOUND`: `"File with ID 'qa-nonexistent.bean' not found"`.
5. GraphQL control: `Mutation.deleteLedgerFile` requires `sha: String!` and currently has no `dryRun` argument (`w1/blocked/210`).

## Expected

`DELETE /api-gateway/v1/ledgers/{owner}/{name}/files/{*path}` with `dryRun: true` (and any `LedgerRepoService.changeFiles(..., { dryRun: true })` batch containing a `delete` or `update` without `sha`) checks that each targeted path currently exists (and is a file, not a directory) unless created earlier in the same batch, refusing a missing path with `404 NOT_FOUND` (`NotFoundError("File", path)`) before running bean-check projection — matching both the commit path and MCP `deleteLedgerFiles`.

## Root cause

`backend-cluster/backend-v2/src/features/ledger/service/ledger-repo-service.ts:521-564` (`LedgerRepoService.commitFileChanges`):

- In the `if (dryRun)` block, lines 533–540 only record a non-`create` operation in `versioned` when `operation.sha !== undefined && operation.sha !== null`:
  ```ts
  if (
    operation.operation !== "create" &&
    operation.sha !== undefined &&
    operation.sha !== null &&
    !touched &&
    !versioned.has(operation.path)
  )
    versioned.set(operation.path, operation.sha);
  ```
- When `operation.operation === "delete"` (or `"update"`) carries no `sha`, `created` and `versioned` remain empty, line 546 (`if (created.size > 0 || versioned.size > 0)`) is skipped, and `commitFileChanges` returns `{}` without calling `getLedgerFilesContent`.
- REST `DELETE /api-gateway/v1/ledgers/{owner}/{name}/files/{*path}` (`src/features/ledger/api/rest/v1/files-handler.ts:345-365`) passes `{ operation: "delete", path: params.path }` with no `sha` when omitted and relies on `changeFiles({ ...write, dryRun: true })` to verify existence.
- MCP `deleteLedgerFiles` avoids the bug only because `executeEditLedgerFiles` (`src/features/ai-agent/tools/edit-ledger-files-tool.ts:424-434, 250-251`) pre-fetches every `update`/`replace`/`delete` path via `getFilesContent` and throws `NotFoundError("File", f.path)` during `foldOperations`.

## Fix

1. In `backend-cluster/backend-v2/src/features/ledger/service/ledger-repo-service.ts` (`commitFileChanges`, `if (dryRun)` branch):
   - Track every first-touched non-`create` (`update` / `delete`) operation in `versioned: Map<string, string | null>` (storing `operation.sha ?? null`) rather than skipping operations with no `sha`.
   - When querying `getLedgerFilesContent` for `[...new Set([...created, ...versioned.keys()])]`:
     - If a path in `versioned` is missing from `existing`, throw `new NotFoundError("File", path)`.
     - If `current.type === "dir"`, throw `BadUserInputError` (`${path} is a directory, not a file`, matching `getFilesContent:321-328`).
     - If `sha !== null && current.sha !== sha`, throw `staleFileConflict(path)`.
2. Preserve existing behavior for:
   - `operations: []` (auth-only dry run returns `{}` without calling Fava),
   - `create` over an existing file (`409 CONFLICT`),
   - delete-then-create in the same batch (freed path may be created),
   - `main.bean` entry-point delete refusal (`BAD_USER_INPUT` before dry-run lookup),
   - include-guard refusal (`assertDeletesKeepIncludes` still runs before the dry-run lookup).
3. Add regression tests in `src/features/ledger/service/__tests__/ledger-repo-service.test.ts` and `src/features/ledger/api/rest/v1/__tests__/file-write-gate-parity.test.ts` covering REST `DELETE …/files/{path}` with `dryRun: true` and no `sha` on a nonexistent file (and a directory), plus `changeFiles(..., { dryRun: true })` with SHA-less `delete`/`update`, verifying `404 NOT_FOUND` matching MCP `deleteLedgerFiles`.

## Blast radius

- Owning package: `backend-cluster/backend-v2`.
- Callers of `LedgerRepoService.changeFiles(..., { dryRun: true })`:
  - REST `PUT` / `DELETE /api-gateway/v1/ledgers/{owner}/{name}/files/{*path}` (`src/features/ledger/api/rest/v1/files-handler.ts:268,365`) — `PUT` without `sha` always sends `operation: "create"` (already checked via `created`), while `DELETE` without `sha` sends `operation: "delete"` and hits this bug.
  - MCP `createLedgerFiles` / `updateLedgerFiles` / `deleteLedgerFiles` (`src/features/ai-agent/tools/edit-ledger-files-tool.ts:479,531`) — already pre-fetches in `prepare()`, and `prepare()` attaches the fetched `sha` to `operations`, so behavior stays identical.
  - GraphQL `deleteLedgerFile` requires `sha` and has no `dryRun` (`w1/blocked/210`).
- Adjacent states: `dryRun: true` on an existing file without `sha` still returns `200 OK`; `dryRun: true` with a read-only credential still fails with `403 FORBIDDEN` at `authorizeFileChanges` before any Fava lookup; `dryRun: true` on `main.bean` still fails with `400 BAD_USER_INPUT`.

## Acceptance criteria

- `DELETE /api-gateway/v1/ledgers/{owner}/{name}/files/<missing>` with `{ "message": "...", "dryRun": true }` and no `sha` returns `404 NOT_FOUND`, matching `dryRun: false` and MCP `deleteLedgerFiles`.
- `LedgerRepoService.changeFiles` with `dryRun: true` refuses any SHA-less `delete` or `update` targeting a missing file (`NotFoundError`) or directory (`BadUserInputError`), while preserving existing `sha` mismatch (`ConflictError`), `create`-over-existing (`ConflictError`), and valid-file preview behavior.
- `yarn typecheck`, `yarn lint:deadcode`, `yarn format:check`, `yarn test`, and `yarn generate-v1-openapi` (no drift) pass in `backend-cluster/backend-v2/`.

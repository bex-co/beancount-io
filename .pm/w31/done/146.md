# `addLedgerEntries` refuses an `open` with booking `HIFO` or `STRICT_WITH_SIZE`, two methods Beancount 3.2.3, the hosted engine, `bea add open --booking` and the `beancount-trade` skill all accept, on MCP, REST and GraphQL

**Minor · backend-v2 + ledger + idl · 30–40m · A1.** A typed `open` entry takes `booking`, but only `STRICT`, `FIFO`, `LIFO` and `NONE`. `{"type": "open", "entry": {"account": "Assets:Broker", "currencies": ["VTI"], "booking": "HIFO"}}` is refused `BAD_USER_INPUT`: "entries.0.entry.booking: Invalid option: expected one of \"STRICT\"|\"FIFO\"|\"LIFO\"|\"NONE\"". `STRICT_WITH_SIZE` is refused the same way. Beancount 3 parses seven methods. Six of them book: `STRICT`, `STRICT_WITH_SIZE`, `NONE`, `FIFO`, `LIFO` and `HIFO`; `AVERAGE` parses but stock refuses it on a reduction, and the ledger mirrors that. The hosted engine books `HIFO` and `STRICT_WITH_SIZE` correctly when the `open` line arrives as raw text. `bea add open --booking` offers all six (`_BOOKING_METHODS`, `cli/src/cli/commands/add.py:39`). The `beancount-trade` skill (`skills/beancount-trade/SKILL.md:138`) lists the six as "exactly" what the engine accepts. So an agent that follows the skill, or a user who asks to open a brokerage account with highest-cost-first booking, gets a refusal from the typed tool and has to fall back to `appendLedgerText`. Code comments claim the four-value list is "the booking methods beancount parses on `open`", which is wrong.

## Repro (synthetic)

1. `addLedgerEntries { entries: [{type: "open", entry: {date: "2026-01-02", account: "Assets:Qa:Broker", currencies: ["VTI"], booking: "HIFO"}}], dry_run: true }` gives `BAD_USER_INPUT` "entries.0.entry.booking: Invalid option: expected one of \"STRICT\"|\"FIFO\"|\"LIFO\"|\"NONE\"". `booking: "STRICT_WITH_SIZE"` gives the same refusal.
2. REST `POST /api-gateway/v1/ledgers/<owner>/<name>/entries` with the same body and `dryRun: true` returns `400 VALIDATION_FAILED` with the same reason. GraphQL's `BookingMethod` enum has only the four values.
3. Control: `booking: "FIFO"` previews `2026-01-02 open Assets:Qa:Broker  VTI "FIFO"` with `valid: true`.
4. Control: the same `open` lines written as raw text check clean on the hosted ledger, and they book as stock does:

   ```beancount
   2026-01-02 open Assets:Qa:Hifo  VTI "HIFO"
   2026-01-02 open Assets:Qa:Sized VTI "STRICT_WITH_SIZE"
   2026-01-02 open Equity:Qa:Opening
   2026-01-02 open Income:Qa:Gains USD
   2026-01-03 * "buys"
     Assets:Qa:Hifo   1 VTI {100 USD}
     Assets:Qa:Hifo   1 VTI {300 USD}
     Assets:Qa:Hifo   1 VTI {200 USD}
     Assets:Qa:Sized  2 VTI {100 USD}
     Assets:Qa:Sized  1 VTI {200 USD}
     Equity:Qa:Opening
   2026-01-04 * "sells"
     Assets:Qa:Hifo  -2 VTI {}
     Assets:Qa:Sized -1 VTI {}
     Equity:Qa:Opening  800 USD
     Income:Qa:Gains
   ```

   Hosted `holdings` leaves `Assets:Qa:Hifo` with 1 VTI at 100 USD and `Assets:Qa:Sized` with 2 VTI at 100 USD, and the register shows the HIFO sale taking the 300 and 200 USD lots. `bean-check` 3.2.3 and `bean-query` give the same lots.

## Root cause

Four declarations of the same narrow list:

- `bookingSchema` in `backend-cluster/backend-v2/src/features/ledger/api/rest/v1/entries-handler.ts:44`, which serves REST and the MCP tool;
- the GraphQL `BookingMethod` enum in `backend-v2/src/features/ledger/api/resolvers/ledger-entry-resolver.mutation.ts:74`;
- `BookingMethod` in `backend-v2/src/features/ledger/service/ledger-entry-service.ts:105`, taken from the generated `Open["booking"]` (`src/foundation/fava/Api.ts:2256`);
- `BookingMethod` in `backend-cluster/ledger/src/foundation/ledger-api-types/ledger-entry-input.ts:75`, with the IDL enum at `backend-cluster/idl/beancount-ledger.openapi.json` (the `open` entry input's `booking`).

The renderer (`ledger/src/foundation/rustledger/journal-serialize.ts:812`) quotes whatever method it gets, so it needs no change. The ledger's own stock-syntax rule already knows the full list (`stock-syntax-errors.ts:55`).

## Fix

Add `STRICT_WITH_SIZE` and `HIFO` to the IDL enum, regenerate, and add them to the three hand-written lists. Keep `AVERAGE` out: stock refuses it on a reduction, and w5/162 removed it from the CLI for that reason. Update `OPEN_BOOKING_DESCRIPTION` and the `docs/mcp.md` sentence "An `open` takes `booking` (`STRICT`, `FIFO`, `LIFO`, `NONE`); anything else is refused" to list the six methods. Correct the two "the booking methods beancount parses" comments.

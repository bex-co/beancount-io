# Line-by-line `include` scanners ignore multiline Beancount strings across `backend-v2` and `ledger`, falsely refusing deletes/renames and corrupting narrations on `deleteLedgerFiles`, `renameLedgerFile`, `moveEntrySources`, and auto-routed appends

**Major · `backend-cluster/backend-v2` + `backend-cluster/ledger` (`include-target.ts`, `include-references.ts`, `ledger-workflow.ts`, `routed-includes.ts`) · 40–55m · A1.** Beancount strings (`"..."`) legitimately span multiple physical lines (e.g. a transaction narration or `note` directive), and `account-rename.ts` / `engine-decimal.ts` (`w31/095`) already track multiline string state across lines. However, every `include` line scanner used by file deletion, file rename, entry moving, and auto-routed entry appends scans `.split("\n")` line by line with no multiline string state — and `routed-includes.ts` matches any `/^\s*include\s/` line while `include-target.ts` also matches unquoted (`include foo.bean`) and single-quoted (`include 'foo.bean'`) lines inside a multiline `"..."` string. As a result, a completely valid Beancount ledger with a multiline string containing a line starting with `include ` suffers false refusals and silent data corruption across MCP, REST, and GraphQL:
- `deleteLedgerFiles` (MCP), `DELETE .../files/{*path}` (REST), and `deleteLedgerFile` (GraphQL) refuse to delete an unincluded file (`BAD_USER_INPUT: <file> is still included by main.bean`), and with `remove_includes: true` / `removeIncludes: true` silently **delete the line inside the transaction's quoted narration string**.
- `renameLedgerFile` (MCP), `POST .../rename-file` (REST), and `renameLedgerFile` (GraphQL) refuse without `updateIncludes: true`, and with `updateIncludes: true` silently **rewrite the line inside the transaction's quoted narration string** (and `movedIncludesContent` does the same inside a file moved across folders).
- `moveEntrySources` with `includeFrom` (MCP), `POST .../entries/move` (REST), `moveLedgerEntrySources` (GraphQL), and auto-routed `addLedgerEntries` / `appendLedgerText` splice `include "<new>"` **inside the multiline quoted string**, shattering the transaction with `P0012` parse errors and leaving the new file unloaded.

Repeat on REST (`DELETE /api-gateway/v1/ledgers/alice/books/files/qa-sub.bean`, `POST .../rename-file`, `POST .../entries/move`) and GraphQL (`renameLedgerFile`, `moveLedgerEntrySources`).

- **Actual (reproduced live across MCP, REST, and GraphQL):**
  - **1a (`deleteLedgerFiles` / REST `DELETE .../files/qa-sub.bean`):** refused with `BAD_USER_INPUT`: `qa-sub.bean is still included by main.bean; remove the include from the including file(s) first, then delete`.
  - **1b (`deleteLedgerFiles` with `remove_includes: true`):** previews 2 changes (`qa-sub.bean` delete + `main.bean` update) with diff removing `-include qa-sub.bean` from inside the quoted narration string (`2026-08-30 * "Landlord" "Monthly rent\n-include qa-sub.bean\nend of memo"`).
  - **1c (`renameLedgerFile` MCP / REST `POST .../rename-file` / GraphQL `renameLedgerFile`):** without `updateIncludes`, refused with `BAD_USER_INPUT: qa-sub.bean is still included by main.bean`; with `updateIncludes: true`, returns `updatedIncludes: ["main.bean"]`, `preview: [{"path":"main.bean","text":"include qa-moved.bean"}]`, rewriting the text inside the narration string on all 3 surfaces.
  - **1d (`moveEntrySources` MCP / REST `POST .../entries/move` / GraphQL `moveLedgerEntrySources`):** `addIncludes` splices `include "qa-moved.bean"` after the narration's `include qa-sub.bean` line (inside the open string!), returning `valid: false` with 3 new errors on all 3 surfaces: `parse error: unexpected "qa-moved" in transaction header (main.bean:87)` (`P0012`), `parse error: unexpected input (main.bean:87)` (`P0012`), and `Balance failed for Assets:Cash` (`E2001`, because `qa-moved.bean` was never loaded).

## Expected

- Every `include`-line scanner (`parseIncludeLine` consumers, `addIncludeLines`, `addIncludes`) must track Beancount multiline string state (`"` toggle with `\` escapes inside strings, `;` comments and column-0 `*` org headings outside strings) so lines inside an open `"..."` string are never classified as `include` directives.
- In `backend-cluster/ledger/src/features/ledger/utils/routed-includes.ts` (`addIncludes`), match only real top-level `include "..."` directives outside strings (not arbitrary `/^\s*include\s/` prose lines).
- In the repro above: `deleteLedgerFiles` deletes `qa-sub.bean` without touching `main.bean` (with or without `remove_includes`); `renameLedgerFile` renames `qa-sub.bean` without refusing or rewriting `main.bean`; `moveEntrySources` with `includeFrom: "main.bean"` inserts `include "qa-moved.bean"` outside any string (at top-level after the last real `include`, or at EOF) and validates cleanly (`valid: true`).

## Root cause

1. **`backend-cluster/backend-v2/src/features/ledger/utils/include-target.ts:20-41, 59-80`:** `parseIncludeLine(line)` is stateless and matches double-quoted, single-quoted, and bare unquoted tokens (`^(\s*include\s+)(?:"..."|'...'|(\S+))`). `addIncludeLines` uses `lines.findLastIndex((line) => parseIncludeLine(line) !== null)` without tracking multiline strings.
2. **`backend-cluster/backend-v2/src/features/ledger/utils/include-references.ts:225-256`:** `findDanglingDeleteIncluders` and `stripIncludeLines` iterate `content.split("\n")` and call `parseIncludeLine(line)` on every line regardless of multiline string state.
3. **`backend-cluster/backend-v2/src/features/ledger/workflow/ledger-workflow.ts:1563-1611, 1671-1683, 1999-2015`:** `moveLedgerFile` (both scanning includers/globs and rewriting `including.content`) and `movedIncludesContent` (rewriting relative includes in a file moved across folders) iterate `.split("\n")` and call `parseIncludeLine(line)` without multiline string state.
4. **`backend-cluster/ledger/src/features/ledger/utils/routed-includes.ts:47`:** `addIncludes` finds the insertion anchor via `lines.findLastIndex((line) => /^\s*include\s/.test(line))` — matching any line starting with `include ` inside a multiline string (even plain English like `include utilities and trash"`).

## Fix

1. In `backend-cluster/backend-v2/src/features/ledger/utils/include-target.ts`:
   - Add a small stateful line helper (e.g. `scanIncludeLines` / `mapIncludeLines` or a shared multiline-string state tracker using the same Beancount string/comment/org-heading rules as `account-rename.ts` and `engine-decimal.ts`) that yields `(line, lineIndex, include | null)` where `include` is always `null` for any line that begins inside an open `"..."` string.
   - Update `addIncludeLines` to use the stateful scanner so `last` only counts real top-level `include` lines outside multiline strings (and never splices into an open string).
2. In `backend-cluster/backend-v2/src/features/ledger/utils/include-references.ts`:
   - Update `findDanglingDeleteIncluders` and `stripIncludeLines` to use the stateful scanner.
3. In `backend-cluster/backend-v2/src/features/ledger/workflow/ledger-workflow.ts`:
   - Update `moveLedgerFile` (glob check, `includingFiles` scan, and `rewritten` loop) and `movedIncludesContent` to use the stateful scanner.
4. In `backend-cluster/ledger/src/features/ledger/utils/routed-includes.ts`:
   - Track multiline `"..."` string state (reusing `endsInsideString` from `foundation/rustledger/source-slice.ts` or equivalent) when computing `last`, and match only real top-level double-quoted `include "..."` lines (`/^[^\S\r\n]*include[^\S\r\n]+"([^"]*)"/`) outside strings.
5. Add unit and 3-surface parity tests covering multiline strings containing `include ...` lines:
   - `backend-cluster/backend-v2`: `include-target.test.ts`, `include-references.test.ts` (or `ledger-repo-service.test.ts`), `rename-parity.test.ts`, `directive-append-workflow.test.ts`.
   - `backend-cluster/ledger`: `routed-includes.test.ts`, `move-source-slices.test.ts`, `entries-new-errors.test.ts`.

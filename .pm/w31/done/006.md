# `updateLedger` previews a rename onto a taken name as a clean diff; the commit is `CONFLICT`

**Minor · backend-v2 (ledger workflow) · 30–45m · A1.** Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`) on 2026-11-15, against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, `revision: unknown`, see `w31/002`). The credential was an unpinned read/write/admin `bcio_` key on the QA account. Every call was a preview, so nothing was renamed.

- **Repro.** The account owns both `<qa-owner>/mcp-agent-eval` and `<qa-owner>/example`. Send `updateLedger {ledger: "<qa-owner>/mcp-agent-eval", name: "example", dry_run: true}`. It succeeds with `dry_run: true` and `preview: {name: {from: "mcp-agent-eval", to: "example"}, warnings: ["Renaming to example changes the ledger's full name and URLs; update pins and links."]}`. REST `PUT /api-gateway/v1/ledgers/<qa-owner>/mcp-agent-eval {name: "example", dryRun: true}` answers 200 with the same preview. So does GraphQL `updateLedger(ledgerId: …, name: "example", dryRun: true)`.
- **The commit refuses this rename.** The ledger service's `PUT /ledgers/{owner}/{repo_name}` handler (`backend-cluster/ledger/src/api/ledgers.ts`) looks up the target with `findExistingRepo` and throws `nameTakenError`. backend-v2 maps that to `CONFLICT`, with reason `LEDGER_NAME_ALREADY_EXISTS`, or `LEDGER_NAME_RESERVED` for a renamed ledger's former name (`ledger-rename.test.ts`). As a live control, `createLedger {name: "mcp-agent-eval"}` on MCP and REST `POST /api-gateway/v1/ledgers` both answer `CONFLICT` "Ledger conflict: Name already exists". REST returns 409 with `reasonCode: LEDGER_NAME_ALREADY_EXISTS`. The rename commit itself was not sent, because ledger renames are outside the QA write authorization.
- **Cause.** The dry-run branch of `updateLedger` (`backend-cluster/backend-v2/src/features/ledger/workflow/ledger-workflow.ts`, `previewLedgerUpdate`) only reads the current settings and renders the diff. It never checks whether the new name is free. Two places promise otherwise. `docs/mcp.md` "Lifecycle preview shapes" says "A lifecycle preview runs the commit's checks under the commit's authority". The GraphQL `dryRun` field says "the checks ran and nothing was committed".
- **Same pass.** A rename to the ledger's own name previews as a change: `name: {from: "mcp-agent-eval", to: "mcp-agent-eval"}`, plus the URL warning. The function's own comment says the preview "renders effective changes only".
- **Controls that hold.** The preview enforces the name format (`a--b` is `BAD_USER_INPUT`, suggesting `a-b`), the 2048-character description cap, and the public-flip warning. `deleteLedger {dry_run: true}` renders its destroy summary, and the ledger is still there afterwards. A missing ledger is `NOT_FOUND`.

**Done when:**
- A rename preview onto a name another ledger holds is refused on MCP, REST and GraphQL with the same `CONFLICT` and reason code as the commit: `LEDGER_NAME_ALREADY_EXISTS`, or `LEDGER_NAME_RESERVED` for a former name that redirects.
- A rename preview to the current name shows no `name` change and no rename warning.
- A parity test beside `src/features/ledger/api/rest/v1/__tests__/update-preview-parity.test.ts` covers both cases on all three surfaces, and it fails with the fix reverted.

Package: `backend-cluster/backend-v2`. The availability check may need a ledger-service lookup that keeps `findExistingRepo`'s self-redirect rule, so that renaming a ledger back to its own former name stays allowed.

---

**Resolved 2026-11-15** — The dry-run branch of `updateLedger` (`backend-cluster/backend-v2/src/features/ledger/workflow/ledger-workflow.ts`) now runs the commit's name check before it renders the diff. It looks the new name up through the ledger service's `getLedger`, under the caller's credentials as the commit's lookup does. A name another ledger holds is refused with `CONFLICT` and `LEDGER_NAME_ALREADY_EXISTS`. A name that answers under another ledger's full name, a renamed ledger's former name, is refused with `LEDGER_NAME_RESERVED`. Both errors are built by the same `ledgerNameExistsConflict` and `ledgerNameReservedConflict` (`src/foundation/fava/error-to-domain.ts`) that translate the commit's refusals, so preview and commit refuse alike on every surface. As in the ledger service's `findExistingRepo`, a name that answers with this ledger itself (its own former name) stays free, matched by the stable numeric id, and a lookup failure other than a miss is refused, not read as a free name. A rename to the current name now renders no `name` change and no URL warning. `update-preview-parity.test.ts` runs both refusals, the self-redirect, and the same-name case on REST, GraphQL and MCP. It has the ledger service answer by name and refuse the commit with its recorded wire errors, and it checks that each surface's preview error equals that surface's commit error. With the fix reverted, 10 of its 27 tests fail. Removing the id match fails the self-redirect test on all three surfaces. `docs/mcp.md` "Lifecycle preview shapes" now states both behaviors. Before the deploy, the live repro still held on `https://beancount.io`: previewing `mcp-agent-eval` → `example` and the same-name rename both rendered a change with the URL warning. Gates in `node:22-bookworm-slim` (v22.23.4): `yarn typecheck`, `yarn test` (482 suites; the two suites that read sibling packages pass with the whole repository mounted), `yarn lint:deadcode`, `yarn format:check`, and an OpenAPI regeneration with no drift. Shipped in this commit (`backend-v2`).

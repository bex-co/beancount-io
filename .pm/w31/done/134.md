# Two plugin problems stock `bean-check` refuses read as hidden warnings: `fava.plugins.link_documents`' "Document not found" and an unsupported `fava.plugins.*` name such as the typo `fava.plugins.link_document`. The ledger previews `valid: true` and checks clean on MCP, REST and GraphQL (w21/739, w5/1186 sibling)

**Minor · ledger (`src/foundation/rustledger/plugins/`) · 30–45m · A1.** w21/188 hid every engine warning from the check surfaces, because bean-check passes the engine's genuine warnings. w21/739 (`nounused`, `check_commodity`) and w5/1186 (`beancount.plugins.unrealized`) then promoted back the plugin warnings that stock refuses. Two more come from the ledger's own TypeScript plugin layer, not from the engine, and are still warnings:

- The `link_documents` port reports a document reference that matches nothing as an unlocated warning. Fava's plugin raises a `DocumentError` at the referencing entry, so `bean-check` exits 1. The plugin runs normally on the hosted side, and the warning is the only thing that differs.
- A `fava.plugins.*` name the TS layer does not implement is stripped. It gets a `TS_PLUGIN_SKIPPED` warning with a "Did you mean …?" hint, and its effects are not applied. w21/188 noted that this warning "is no longer listed". Stock fails to import the module. An unknown `beancount.plugins.*` name, in contrast, is already the error E8005 on the plugin line.

An agent or user who writes `document: "receipt.pdf"` for a receipt that was never stored, or who misspells the plugin line, gets `valid: true` and a clean `checkLedger`. `bea check` and Fava both reject the same ledger.

Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 LAND=1`) on 2026-11-27. Target: `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`). Credential: an unpinned read/write/admin `bcio_` key on the QA ledger `<qa-owner>/mcp-agent-eval`. Only dry runs were used, so nothing was committed and `main.bean` is unchanged (blob `f1a0b83c`). The result was confirmed against the local HEAD `f40b13f02` engine with `parseLedgerFilesInProcess`. Stock behaviour was checked with Beancount 3.2.3 `bean-check` plus Fava 1.31 and 1.30.5.

## Repro (synthetic)

1. Missing linked document:

   ```beancount
   option "operating_currency" "USD"
   plugin "fava.plugins.link_documents"

   2026-01-01 open Assets:Cash USD
   2026-01-01 open Expenses:Food USD

   2026-08-30 * "qa" "with a missing document"
     document: "qa-missing.pdf"
     Assets:Cash   -1.00 USD
     Expenses:Food  1.00 USD
   ```

   - Stock `bean-check` exits 1 with `main.bean:7: Document not found: 'qa-missing.pdf'`. Both Fava versions agree.
   - Hosted: add the plugin line and that transaction to `main.bean` with `updateLedgerFiles {dry_run: true, message, files: [{path: "main.bean", content}]}`. The answer is "No new bean-check errors" with `validation: {errorsBefore: 0, errorsAfter: 0, newErrors: [], valid: true}`. REST `PUT /v1/ledgers/{owner}/{name}/files/main.bean` with `dryRun: true` answers `valid: true, newErrors: []`.
   - Local engine: one error, `{severity: "warning", phase: "plugin", message: "Document not found: 'qa-missing.pdf'", file: null, line: null}`. In the same parse, a second transaction whose `document:` names a declared `document` directive is linked: it gains `dok-2026-08-31`, and the document gains `#linked`. So the plugin ran.
2. Unsupported Fava plugin name. Use `plugin "fava.plugins.link_document"` (no `s`) or `plugin "fava.plugins.qa_nonexistent"`.
   - Stock `bean-check` exits 1 with `Error importing "fava.plugins.link_document" … ModuleNotFoundError`.
   - The hosted `updateLedgerFiles` dry run answers `valid: true` with "No new bean-check errors".
   - The local engine returns `valid: true` and a single warning: `TS_PLUGIN_SKIPPED` at `main.bean:2`, hint `Did you mean "fava.plugins.link_documents"?`.
   - **Control:** `plugin "beancount.plugins.qa_nonexistent"` previews `valid: false` with `newErrors: [{code: "E8005", message: "Unknown plugin \"beancount.plugins.qa_nonexistent\": Beancount.io can't run this plugin", source: "main.bean:7"}]`.
3. **Control that must not change.** Add `option "documents" "documents"` and the file `documents/Assets/Cash/2026-08-31.found.pdf`. Reference it from a transaction either as `document: "2026-08-31.found.pdf"` (basename) or as `document: "documents/Assets/Cash/2026-08-31.found.pdf"` (relative path). Stock and the hosted engine are both clean, and both link the document. Discovery runs before the plugin on both sides, so the matching already agrees and only the severity and the location differ.

## Cause

- `backend-cluster/ledger/src/foundation/rustledger/plugins/link-documents.ts:84-87`: `pluginError(\`Document not found: '${docName}'\`, { severity: "warning" })`, with no file or line. It dates from the initial import (`ca9a50d2e`). `__tests__/link-documents.test.ts` "warns (does not error out) …" pins it.
- `backend-cluster/ledger/src/foundation/rustledger/plugins/index.ts:189-206` `skippedPluginWarning`: `severity: "warning"`. `scripts/verify-rustledger.ts:5153`/`5328` assert that the warning appears.
- `backend-cluster/backend-v2/src/features/ledger/service/ledger-data-service.ts:246-260` (`getErrors`, `includeWarnings = false`) drops warnings by design. The write diffs ignore them too (`backend-cluster/ledger/src/features/ledger/utils/new-ledger-errors.ts`, `backend-cluster/backend-v2/src/features/ledger/utils/bean-check-errors.ts`). Neither problem therefore reaches `checkLedger`, the `errors` resource, REST `/errors`, GraphQL `getLedgerErrors`, or any write's `validation`.

## Fix (ledger only; every surface reads the shared snapshot)

- `link-documents.ts`: raise an error (the `pluginError` default) located at the referencing entry. Take `file` and `line` from `getDirectiveSourceLocation(entry)`, which is already imported, and keep stock's wording `Document not found: '<name>'`. A located error keys on its file, so an existing one does not block later writes and moves with its entry (w31/126).
- `skippedPluginWarning`: make it an error at the plugin line. Keep the `TS_PLUGIN_SKIPPED` code and the "Did you mean" hint, so an unknown `fava.plugins.*` name is refused like an unknown `beancount.plugins.*` one. The four handled names (`amortize_over`, `forecast`, `link_documents`, `tag_discovered_documents`) are unaffected.
- Update the unit test and the two `verify-rustledger.ts` checks. If the ledger README's "stock errors the engine does not raise" table should list these, add them there.

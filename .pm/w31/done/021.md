# A mistyped `option "documents"` root is no longer reported: bean-check fails "Document root … does not exist", the hosted check says clean

**Minor · ledger (document discovery) · 20–30m · A1.** This is a regression from the `@rustledger/wasm` 0.24 bump (`914e7b431`). Older engines emitted E7006, and the service kept it when the root held no repository files; `document-validation.ts` still describes that check as "a real config error". 0.24 stopped emitting the error, and nothing replaced it, so a typo in the documents folder silently discovers nothing. Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`) on 2026-11-15, against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, `revision: unknown`, see `w31/002`). The credential was an unpinned read/write/admin `bcio_` key on the QA account, and writes went only to the QA ledger `<qa-owner>/mcp-agent-eval`. The probe was committed, then reverted byte for byte (blob `f1a0b83c`), and the check is clean.

## Repro (live)

The run's root was named `qa-20261115-r8-receipts`, and this note shortens it.

1. Add `option "documents" "qa-receipts"` to `main.bean`, in a repository with no `qa-receipts/` folder.
2. `updateLedgerFiles` `dry_run` and REST `PUT …/files/main.bean` `dryRun` both answer `valid: true`.
3. After the commit, `checkLedger`, the `errors` resource and REST `GET …/errors` all return `[]`.
4. Stock Beancount 3.2.3 `bean-check` on the same file fails: `main.bean:0: Document root '…/qa-receipts' does not exist`.

**Control:** HEAD's engine (`parseLedgerFilesInProcess`, `repoPaths` with `docs/Assets/Cash/2026-02-01.x.pdf`) discovers one document for `option "documents" "docs"`. For the missing root it returns no error, and so does the raw `ledger.getErrors()`. So this is not deployment lag.

## Cause

- `reconcileDocumentErrors` (`backend-cluster/ledger/src/foundation/rustledger/document-validation.ts:147`) only filters the engine's E7006, which 0.24 no longer emits (`:33`).
- `discoverDocuments` (`document-discovery.ts:54`) already resolves each root against the entry point's directory (`:65`) and has the repository file list. When nothing lives under a root, it returns no documents and no error.

## Fix

In `discoverDocuments`, when `repoPaths` is known, add Beancount's error `Document root '<root>' does not exist` for each root that has no repository path equal to it or under it. Place the error on that `option "documents"` line, as the module already does for misdated documents. A Git repository cannot hold an empty folder, so "some file under it" is the same test as "the folder exists". Stock's `beancount/ops/documents.py` runs this check inside the same discovery, so this completes the existing port and re-implements nothing new. Every surface reads the shared snapshot, so MCP, REST and GraphQL change together.

**Done when:**

- The repro reports that one error through `parseLedgerFiles`.
- On the QA ledger, its `dry_run` answers `valid: false`, and its commit is refused `VALIDATION_FAILED` unless `allowInvalid`.
- An existing root still discovers its documents with no error, and a ledger without the option is unchanged.
- A `document-discovery` unit case covers it and fails with the fix reverted.

Dedupe: searched `.pm/**` (done and blocked included) for "Document root", "documents root", E7006 and "mistyped". `w21/308`, `w21/309` and `w1/209` mention E7006 only as the earlier reconciliation precedent, and none of them reports the missing check.

**Resolved 2026-11-15** — A documents root that does not exist is reported again, with Beancount's `Document root '<root>' does not exist`, on the `option "documents"` line that names it (code `E7006`). Shipped in the commit carrying this note (`backend-cluster/ledger`).

- **Where the check lives.** The service, not the engine. `@rustledger/wasm` 0.24.0 has no filesystem, and its host API (`readFile`, `glob`, `realpath`) has no way to ask whether a folder exists. `validateWithHost` reports nothing for a missing root either, so there is no upstream change to wait for. Only the service has the repository's file list, and it already ports `beancount.ops.documents` discovery from it (w21/738). The check completes that port.
- **What changed.**
  - `discoverDocuments` (`document-discovery.ts`) raises the error for each root that is neither a repository path nor a folder holding one. Git stores no empty folders, so this is the same as asking whether the folder exists. The root is resolved against the entry point's directory and named by its repository path. For example, `books/main.beancount` with `option "documents" "scans"` reports `'books/scans'`. Stock reports the absolute path on line 0.
  - The error survives the fava plugins' second validation.
  - `reconcileDocumentErrors` now drops the engine's `[E7006]` in every case, so an engine that emitted it again could not report the root twice.
  - Matching stock 3.2.3, these are accepted: a root that names a file, `""`, and `.`.
- **Before the fix.**
  - At HEAD `c36193648`, `parseLedgerFilesInProcess` answered `valid: true` with no errors for the repro. Stock `bean-check` 3.2.3 reported `Document root '…/qa-receipts' does not exist`.
  - On the QA ledger `<qa-owner>/mcp-agent-eval`, the deployed MCP `updateLedgerFiles` `dry_run` that adds `option "documents" "qa-w31-021-receipts"` answered `valid: true`, "No new bean-check errors". This was a preview only, so nothing was committed. `main.bean` stayed at blob `f1a0b83c`, and `checkLedger` stayed clean.
  - The deployed ledger service runs the old code until the next deploy.
- **Tests.**
  - `document-discovery.test.ts` covers:
    - a missing root, placed on its option line;
    - a root resolved from a subfolder entry point;
    - one missing root beside one that still discovers documents;
    - five accepted shapes;
    - a sibling `docs-old/` or `docs.pdf` that does not count as `docs`.
  - `document-validation.test.ts` covers the engine's `E7006` being dropped.
  - `yarn verify:rustledger` checks that the note's missing root is refused once at `main.beancount:1`, and that `books/qa-receipts` is reported with and without `fava.plugins.tag_discovered_documents`.
  - With the fix reverted, 4 unit cases fail, and `verify:rustledger` stops on the missing root.
- **Gates.** Run in `node:22-bookworm-slim` (v22.23.4): `yarn typecheck`, `yarn lint:deadcode`, ESLint, Prettier on the changed files, `yarn test` (221 suites, 3434 tests, all passing) and `yarn verify:rustledger`.

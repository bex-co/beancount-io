# `user-profile` with empty or whitespace `userId` (`?userId=` / `userId: ""`) denies as `unknown_resource` and gives MCP a wrong ledger-metadata hint on MCP, REST, and GraphQL

**Minor · backend-v2 (account profile validation & error hint) · 20–30m · A1.** Passing an empty or whitespace-only `userId` to `beancount://account/profile`, REST `GET /api-gateway/v1/user-profile`, or GraphQL `userProfile` passes a malformed `user:` resource into the PDP, denying with `FORBIDDEN` (`reason: "unknown_resource"`) and causing MCP to fall back to a ledger-permission hint (`Check beancount://{owner}/{name}/metadata for your permission on the ledger`) even though `account/profile` has no ledger. Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`) on 2026-11-23 against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, checked against HEAD `ad0ad3afa`). Credential: unpinned read/write/admin `bcio_` key on the QA account.

## Repro (live)

Reproduced in fresh read-only requests across all three surfaces:

1. **MCP resource `beancount://account/profile?userId=` (and `?userId=%20%20`)**:
   ```sh
   node .agents/skills/qa-shared/scripts/qa-mcp.mjs read 'beancount://account/profile?userId='
   node .agents/skills/qa-shared/scripts/qa-mcp.mjs read 'beancount://account/profile?userId=%20%20'
   ```
   Actual: HTTP `200`, JSON-RPC `-32003` `FORBIDDEN: Authorization denied`, `Hint: This credential lacks the authority for that operation. Check \`beancount://{owner}/{name}/metadata\` for your permission on the ledger.`
2. **REST `GET /api-gateway/v1/user-profile?userId=`**:
   Actual: HTTP `403`, `{"ok":false,"error":{"code":"FORBIDDEN","message":"Authorization denied","metadata":{"action":"user.profile.read","reason":"unknown_resource"}}}` (no `hint`, no `resourceType`).
3. **GraphQL `userProfile(userId: "")`**:
   Actual: HTTP `200`, `errors[0]`: `{"message":"Authorization denied","extensions":{"code":"FORBIDDEN","action":"user.profile.read","reason":"unknown_resource"}}`.

Expected: refused with `BAD_USER_INPUT` naming `userId` (hinting to omit `userId` or pass your own user ID) on MCP, REST, and GraphQL — never `unknown_resource` and never a ledger-metadata hint.

## Working controls

- Omitting `userId` (`beancount://account/profile`) returns `200 OK` with the caller's profile.
- Naming another user (`beancount://account/profile?userId=usr_someone_else_999` and REST `GET /api-gateway/v1/user-profile?userId=usr_someone_else_999`) returns `FORBIDDEN` with `reason: "relationship_denied"`, `resourceType: "user"`, and `hint: "This operation reaches only the credential's own account."` (w1/206).
- `bankConnectionResource` (`src/server/api/authorization/authorization-contract.ts:202-204`) already throws `BadUserInputError` for a blank `itemId` before entering the PDP.

## Root cause

Not deployment lag — present at HEAD `ad0ad3afa`:

1. All three adapters (`src/features/ai-agent/api/mcp-resources.ts:533`, `src/features/auth/api/account-routes.ts:74`, `src/features/auth/api/account-resolver.ts:156`) resolve `userId ?? identity.userId`, which keeps `""` or `"  "` (non-nullish) and passes it to `AccountService.getUserProfile(identity, targetUserId)` (`src/features/auth/service/account-service.ts:131-141`).
2. `AccountService.getUserProfile` calls `authorization.authorizeOrThrow` with `resource: userResource(targetUserId)` (`"user:"` or `"user:  "`).
3. `parseAuthorizationResource` (`src/server/api/authorization/authorization-contract.ts:233-251`) returns `undefined` when the ID after `user:` is empty or whitespace (`separator === resource.length - 1` or `!id.trim()`), so `AuthorizationService` (`src/server/api/authorization/authorization-service.ts:1169`) emits `deny("unknown_resource")` with `failedResourceType: undefined` and `hint: undefined`.
4. `hintFor` (`authorization-service.ts:985-999`) only attaches `"This operation reaches only the credential's own account."` when `failedResourceType === "user"` and `reason` is `relationship_denied` / `insufficient_relationship`, so MCP falls back to `CATEGORY_HINTS.FORBIDDEN` (`src/features/ai-agent/api/mcp-errors.ts:90-91`), pointing at `beancount://{owner}/{name}/metadata`.

Blast radius: audited every caller of `userResource(` in `backend-cluster/backend-v2/src/`. Every other caller passes `identity.userId` (authenticated non-empty ID); `AccountService.getUserProfile` (`account-service.ts:138`) is the only site passing a caller-supplied string into `userResource(...)`.

## Fix

In `backend-cluster/backend-v2`:

1. In `AccountService.getUserProfile` (`src/features/auth/service/account-service.ts:131-141`), guard `targetUserId.trim() === ""` before calling `authorization.authorizeOrThrow`, throwing `new BadUserInputError("userId must not be empty", "userId", "Omit userId to read your own profile, or pass your own user ID.")`.
2. Because MCP `beancount://account/profile`, REST `GET /api-gateway/v1/user-profile`, and GraphQL `userProfile` all delegate to `AccountService.getUserProfile`, all three surfaces refuse empty/whitespace `userId` identically with `BAD_USER_INPUT` and the account-profile hint (while omitting `userId` keeps returning the caller's profile and naming another user keeps returning `FORBIDDEN` with `"This operation reaches only the credential's own account."`).
3. Add unit and 3-surface parity tests covering `userId: ""` and `userId: "  "`.

**Done when:**

- MCP `beancount://account/profile?userId=` / `%20%20`, REST `GET /api-gateway/v1/user-profile?userId=` / `%20%20`, and GraphQL `userProfile(userId: "" / "  ")` all refuse with `BAD_USER_INPUT` naming `userId` and carry no ledger-metadata hint.
- Omitted `userId` still returns the caller's profile and another user's ID still returns `FORBIDDEN` with `"This operation reaches only the credential's own account."`.
- New tests fail with the guard reverted and pass with it in place.
- `yarn typecheck`, `yarn lint:deadcode`, `yarn format:check`, `yarn test`, and `yarn generate-v1-openapi` pass in `backend-cluster/backend-v2/`.

Dedupe: searched `.pm/**` (open, done, blocked) for `unknown_resource`, `userProfile`, and `account/profile`. `w1/206` fixed the hint for another user's non-empty `userId=1` (`relationship_denied`), not empty/whitespace `userId` hitting `unknown_resource`.

**Resolved 2026-11-23** — `AccountService.getUserProfile` (`backend-cluster/backend-v2/src/features/auth/service/account-service.ts`) now refuses an empty or whitespace-only `targetUserId` (`targetUserId.trim() === ""`) with `BadUserInputError("userId must not be empty", "userId", "Omit userId to read your own profile, or pass your own user ID.")` before calling `authorization.authorizeOrThrow`. Because MCP (`beancount://account/profile`), REST (`GET /api-gateway/v1/user-profile`), and GraphQL (`userProfile`) all delegate to `AccountService.getUserProfile`, all three surfaces now refuse `""` and whitespace-only values identically with `BAD_USER_INPUT` naming `userId` and carrying the account-profile hint (never `FORBIDDEN` `unknown_resource` or the ledger-metadata hint), while omitting `userId` still returns the caller's profile and naming another user still returns `FORBIDDEN` with `"This operation reaches only the credential's own account."` (`backend-cluster/backend-v2`).

# `suggestCategories` (`beancount://{owner}/{name}/import/suggest-categories`, `POST .../import/suggest-categories`, GraphQL `suggestTransactionCategories`) accepts empty `transactions: []`, runs Fava reads + Redis quota reservation, and makes a billed LLM call instead of refusing with `BAD_USER_INPUT`

**Major · backend-v2 (`LLMService.suggestCategories`, `assertSuggestBatchSize`) · 25–35m · A1.** Passing an empty `transactions: []` batch passes schema validation and `assertSuggestBatchSize` across MCP, REST, and GraphQL. Instead of refusing upfront with `BAD_USER_INPUT`, `LLMService.suggestCategories` authorizes the caller, checks AI quota, fetches open accounts, 50 recent transactions, and plugins from the ledger service, reserves AI CFO tokens in Redis, executes a real billed `categorizeTransactions` LLM call with an empty `**Transactions to Categorize:**` prompt section, and deducts the prompt and response tokens from the user's AI CFO quota before returning `200 OK []`. Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`) on 2026-11-23 against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, checked against HEAD `4b8cf4693`). Credentials: unpinned read/write/admin and `ledger.read` `bcio_` keys on the QA account (`<qa-owner>/mcp-agent-eval`).

## Working controls

- On the exact same three surfaces and requests, passing `501` items (`MAX_SUGGEST_TRANSACTIONS + 1`) is refused upfront before authorization with `BAD_USER_INPUT` (`transactions holds 501 transactions; at most 500 may be categorized per call. Split them into several calls.`, field `transactions`): MCP JSON-RPC `-32602`, REST `400`, GraphQL `BAD_USER_INPUT`.
- Sibling `PlaidItemService.suggestCategories` (`backend-cluster/backend-v2/src/features/plaid/service/plaid-item-service.ts:654-656`) explicitly guards `if (transactions.length === 0) return [];` so it never invokes the LLM on an empty list.
- Dashboard importer (`dashboard/src/features/importer/utils/categorize-in-batches.ts:40-44`) never calls `suggestTransactionCategories` when `rows.length === 0`, and every sibling batch endpoint (`addLedgerEntries`, `deleteEntrySources`, `moveEntrySources`, `createLedgerFiles`, `importStagedBankTransactions`, `discardStagedBankTransactions`) refuses an empty array with `BAD_USER_INPUT`.

## Root cause

Not deployment lag — present at HEAD `4b8cf4693`:

- `backend-cluster/backend-v2/src/features/llm/utils/suggest-categories-cap.ts:11-18`: `assertSuggestBatchSize` only guards the upper bound (`if (transactions.length > MAX_SUGGEST_TRANSACTIONS)`), never `transactions.length === 0`.
- `backend-cluster/backend-v2/src/features/llm/api/suggest-categories-route.ts:31-54`: both `suggestCategoriesQuery` (MCP) and `suggestCategoriesRoute.body` (REST) define `z.array(transactionToCategorizeSchema)` with no `.min(1)`.
- `backend-cluster/backend-v2/src/features/llm/api/ai-categorization-resolver.ts:19-30`: GraphQL `suggestTransactionCategories` forwards `transactions` directly to `this.llm.suggestCategories(...)`.
- `backend-cluster/backend-v2/src/features/llm/service/llm-service.ts:372-472`: after `assertSuggestBatchSize(transactions)` passes on `[]`, the service authorizes (`:380`), checks AI quota (`:385`), calls Fava `getAccounts` (`:393`), `getJournal(limit: 50)` (`:400`), and `getLedgerPlugins` (`:428`), reserves estimated tokens (`:447`), calls `categorizeTransactions(this.llmClient, request)` (`:456`), and settles actual token usage (`:470`).
- `backend-cluster/backend-v2/src/features/llm/utils/categorize-transactions/index.ts:43-77`: `categorizeTransactions` has no empty-array guard and unconditionally invokes `llmClient.generate(...)` with the system prompt, open accounts, and up to 20 recent examples.

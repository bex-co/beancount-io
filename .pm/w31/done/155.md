# Beancount's two plugin bundles do not run what stock runs: `plugin "beancount.plugins.auto"` is refused `E8005` "requires the python-plugins feature" and opens no account, and `pedantic` never runs `check_drained`, so closing an account that still holds money reads clean, on MCP, REST and GraphQL

**Minor · ledger (`src/foundation/rustledger/engine.ts`, `plugins/collect-plugins.ts`, `plugin-typos.ts`) · 30–45m · A1.** Stock Beancount 3.2.3 ships two plugins that only bundle others (`beancount/plugins/auto.py`, `pedantic.py`, both `loader.combine_plugins`). Every plugin in them runs natively in `@rustledger/wasm` 0.24.0, but neither bundle runs as stock runs it:

| declared | stock `bean-check` 3.2.3 | hosted |
| --- | --- | --- |
| `plugin "beancount.plugins.auto"` (= `auto_accounts`, then `implicit_prices`), and a posting to `Expenses:QaAutoNew`, which nothing opens | clean; `Expenses:QaAutoNew` is opened on its first use | `E8005 Python plugin "beancount.plugins.auto" requires the python-plugins feature` on the plugin line, plus `E1001 Account Expenses:QaAutoNew was never opened` |
| `plugin "beancount.plugins.pedantic"` (whose nine plugins include `check_drained`), and `close Assets:Cash` while it holds 49.75 USD | `Balance failed for 'Assets:Cash': expected 0 USD != accumulated 49.75 USD (49.75 too much)`, on the close line | clean |

So a ledger that stock loads is red on every hosted surface, and a ledger that stock refuses passes. The same `pedantic` ledger with `plugin "beancount.plugins.check_drained"` declared by name is refused on the hosted side too, so the engine has the check; the bundle just does not run it. Every other `pedantic` member (`check_commodity`, `coherent_cost`, `leafonly`, `noduplicates`, `nounused`, `onecommodity`, `sellgains`, `unique_prices`) gave stock's error under `pedantic` in the same run.

## Cause

- **`auto`.** The engine has no native plugin by that name, so it raises `E8005`. `explainUnknownPlugins` (`plugin-typos.ts:62`) keeps that message, because `auto` is in its list of plugins Beancount ships. `openAutoAccounts` (`auto-accounts.ts:40`) opens accounts only for `beancount.plugins.auto_accounts`, while `generated-closes.ts:16` already counts `beancount.plugins.auto` among the plugins that open every account.
- **`pedantic`.** The engine's own `pedantic` does not run `check_drained`. The ledger knows the stock member list (`PEDANTIC_PLUGINS`, `collect-plugins.ts:137`, which includes `check_drained`), and reconcilers cover the members the engine runs differently (`nounused`, `check_commodity`, `leafonly` and others, `engine.ts:855-880`). Nothing adds `check_drained` under `pedantic`. The engine's `Cannot close account Assets:Cash with non-zero balance` is a warning, which the check surfaces hide (w21/188).

## Fix

In the ledger, run each bundle as its members, in stock's order, without re-implementing any of them:

- treat `beancount.plugins.auto` as `beancount.plugins.auto_accounts` followed by `beancount.plugins.implicit_prices` before the engine sees it, keeping the plugin line's position, so no `E8005` is raised and `openAutoAccounts` and the close-tree rule read it as `auto_accounts`;
- under `beancount.plugins.pedantic`, have the engine also run its native `check_drained`, so a close of an account that still holds money is refused, as it is when `check_drained` is declared by name.

w31/020 waits on an engine release that changes nine native plugins (rustledger `3aaa348e2`). When it ships, check whether its `pedantic` runs `check_drained`; if it does, drop that half of this fix.

No response shape changes. Every surface reads these errors from the one ledger path: the MCP tools and the `errors` resource, the REST `errors` route and write previews, and GraphQL `getLedgerErrors` and the write mutations.

**Resolved 2026-11-27** — The ledger service now runs Beancount's two plugin bundles as their plugins, before the engine reads the source. `plugin "beancount.plugins.auto"` runs as `auto_accounts` then `implicit_prices`, so the first repro block reads clean, `Expenses:QaAutoNew` is opened on its first use, and the ledger has the same errors, entries and prices as with the two plugins declared by name. Under `plugin "beancount.plugins.pedantic"` the engine also runs its native `check_drained`, so the second repro block is refused with `Balance failed for Assets:Cash: expected 0 USD, got 49.75 USD`, the same error `check_drained` declared by name gives (control 3), and a write that adds it counts it as a new error. No response shape changed.

- **Order and lines.** Plugins run in the order declared, and every other line must keep its number. So `runPluginBundlesAsMembers` (`plugins/strip.ts`) blanks the bundle line and each plugin line after it, then writes them again after the file's last line, in order, with the bundle expanded. `pedantic` then `close_tree` checks only the written close, and `close_tree` then `pedantic` checks the child closes too, as stock 3.2.3 does. Each member gets the bundle's config, as stock's loader passes it. A file that ends inside a string is left as it is. The parse path and the BQL path both read the rewritten source.
- **Readers.** `beancountPluginRuns` reads `auto` as its two members, so `openAutoAccounts` also opens an account named only by a note or a close under `auto`. `unique_prices` sees `auto`'s implicit prices when `auto` is declared first. The close-tree rule already counted `auto`.
- **Engine upgrade (w31/020).** If a later engine's own `pedantic` runs `check_drained`, the funded-close case in `verify-rustledger.ts` reports the error twice and fails. At that point, drop `check_drained` from `pedantic`'s members.
- **Not changed.** `check_drained`'s error has no line, under `pedantic` and by name alike, where stock places it on the close line. Control 3 had to stay unchanged.
- **Tests.** `strip.test.ts` covers the rewrite: member order, relocated later plugins, config, and lines left alone. `strict-plugins.test.ts`, `generated-closes.test.ts` and `unique-prices.test.ts` cover the readers. `verify-rustledger.ts` compares `auto` with its members spelled out, alone and before `unique_prices`, and runs `pedantic` with a funded and a drained close and in both orders with `close_tree`, each against stock 3.2.3. With the fix reverted, the live check fails on `auto` and, with only the `pedantic` half reverted, on the funded close. The three reader tests fail too.
- **Gates.** `backend-cluster/ledger`: `yarn lint`, `yarn typecheck`, `yarn test` (239 suites, 4,301 tests) and `yarn verify:rustledger` pass. The hosted repro against `beancount.io` waits for the next ledger deploy.

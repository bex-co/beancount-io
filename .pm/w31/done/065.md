# MCP `resources/read` and `prompts/get` (and `jsonQuery` decoded JSON params) skip `assertNoNulDeep`, accepting NUL, unpaired surrogates, and over-limit strings instead of `BAD_USER_INPUT`

**Minor · backend-v2 (`src/server/api/composition-root.ts`, `src/features/ledger/api/rest/v1/journal-reads.ts`) · 30–45m · A1.** `backend-cluster/backend-v2/docs/mcp.md` ("Argument limits") promises that every argument is checked upfront on MCP, REST, and GraphQL against `ARGUMENT_LIMITS` (no NUL `U+0000`, no unpaired surrogate, max string length `1,048,576`, max array length `10,000`, max nesting depth `32`), refused with `BAD_USER_INPUT` naming the parameter, and that `"Nothing is stripped or truncated."` While `w23/m22` and `w23/m23` wired `assertNoNulDeep` into REST (`validation-middleware.ts:141-143`), GraphQL (`nul-middleware.ts:16`), and MCP `tools/call` (`composition-root.ts:601`), both MCP `resources/read` (`composition-root.ts:804-844`) and MCP `prompts/get` (`composition-root.ts:942-985`) omit `assertNoNulDeep`. As a result, `resources/read` accepts percent-encoded `%00` (reaching the ledger service and returning `200 OK`) and silently corrupts unpaired surrogates (`\uD800` → `%EF%BF%BD` / U+FFFD via `new URL(raw)`); `prompts/get` accepts raw `\u0000` and `\uD800` and embeds them verbatim into the returned playbook; and `jsonQuery` (`journal-reads.ts:53-72`) decodes JSON-escaped `\u0000` / `\ud800` inside query parameters (e.g. `import/suggest-categories?transactions=...`) without checking the parsed structure. Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`) on 2026-11-23 against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, verified at HEAD `f0fbe3d005991525f3bc1dfbcedce32b83d2a9bc`). Credential: unpinned read/write/admin `bcio_` key on the QA account. Synthetic ledger: `<qa-owner>/mcp-agent-eval` (read-only for this finding).

Expected:

- All four cases above are refused upfront with JSON-RPC `-32602`, `BAD_USER_INPUT` naming the offending parameter (`uri`, `narration`, `payee`, `userId`, `transactions[].payee`, `question`, etc.) and the surface's hint, matching MCP `tools/call`, REST, and GraphQL — without calling any service or silently replacing surrogates with U+FFFD.

## Root cause

Not deployment lag — present at HEAD `f0fbe3d005991525f3bc1dfbcedce32b83d2a9bc`:

1. `backend-cluster/backend-v2/src/server/api/composition-root.ts:601`: `assertNoNulDeep(request.params.arguments, NUL_EXEMPT_PATHS)` runs only inside `dispatchTool` (`tools/call`).
2. `composition-root.ts:815-832` (`ReadResourceRequestSchema` handler): never runs `assertNoNulDeep` on `raw` (before `new URL(raw)`, which silently replaces unpaired surrogates with U+FFFD) or on the decoded `variables` returned by `template.uriTemplate.match(uri.toString())` (which percent-decodes `%00` in both path and query variables).
3. `composition-root.ts:952-983` (`GetPromptRequestSchema` handler): never runs `assertNoNulDeep` on `request.params.arguments`.
4. `backend-cluster/backend-v2/src/features/ledger/api/rest/v1/journal-reads.ts:53-72` (`jsonQuery`): calls `JSON.parse(value)` without running `assertNoNulDeep` on the parsed value, so JSON-escaped `\u0000` / `\ud800` or deeply nested / over-10,000-member JSON arrays inside query parameters (`transactions`, `directiveTypes`, subtype filters) bypass both REST `validation-middleware.ts:142` (which sees only the raw string before `JSON.parse`) and MCP `variables` checks.

## Fix

In `backend-cluster/backend-v2`:

1. In `src/server/api/composition-root.ts`:
   - In the `ReadResourceRequestSchema` handler (`:815-832`):
     - Before `URL.canParse(raw)` / `new URL(raw)`, validate `raw` with `assertNoNulDeep(raw, undefined, "uri")` inside a `try/catch` that calls `refuseMcpRequest(error, "MCP resource read failed", { resource: UNKNOWN_RESOURCE }, config)` — catching raw NULs, unpaired surrogates (before `new URL` corrupts them to U+FFFD), and over-length URIs.
     - Right after `template.uriTemplate.match(uri.toString())` produces `variables` (or at the top of `makeMcpResourceHandler` before `gateMcpCall`/`descriptor.read`, where `descriptor.name` is known so the fallback hint names the resource template), call `assertNoNulDeep(variables)` so percent-encoded `%00` in decoded path or query parameters is refused with `-32602` `BAD_USER_INPUT` naming the parameter (`narration`, `payee`, `userId`, `path`, etc.).
   - In the `GetPromptRequestSchema` handler (`:952-983`):
     - Run `assertNoNulDeep(request.params.arguments)` (before `safeParse` / `build`, catching errors via `refuseMcpRequest(..., { prompt: name }, config)`) so NULs, unpaired surrogates, and over-length strings in prompt arguments are refused with `-32602` `BAD_USER_INPUT` naming the argument and the prompt catalog hint.
2. In `src/features/ledger/api/rest/v1/journal-reads.ts:53-72` (`jsonQuery`):
   - After `JSON.parse(value)` succeeds, run `assertNoNulDeep(parsed)` (catching `BadUserInputError` or letting it propagate cleanly through Zod / REST / MCP error handlers) so JSON-escaped `\u0000`, unpaired surrogates, over-length strings, arrays >10,000, and depth >32 inside decoded JSON query parameters are refused identically on REST and MCP.
3. Add regression tests in:
   - `src/features/ai-agent/api/__tests__/mcp-resources.test.ts` (percent-encoded `%00` in query and path params, unpaired surrogate `\ud800` in raw URI, JSON-escaped `\u0000` in `transactions` / `directiveTypes`, over-length URI, plus control with valid UTF-8 and paired emoji).
   - `src/features/ai-agent/api/__tests__/mcp-prompt-list.test.ts` (or dedicated prompt test) for NUL, unpaired surrogate, and over-length prompt arguments on `prompts/get`, plus valid control.
   - REST parity test for `jsonQuery` (`GET .../journal?directiveTypes=["Trans\u0000action"]` or `jsonQuery` unit test) verifying `BAD_USER_INPUT` on REST too.

- Affects every MCP resource template (all 67 templates via `composition-root.ts`), all 4 MCP prompts (`close-month`, `reconcile-account`, `categorize-imports`, `spending-report`), and all `jsonQuery` callers on MCP and REST (`journal`, `account-journal`, `import/suggest-categories`).

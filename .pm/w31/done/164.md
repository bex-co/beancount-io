# BQL `parent()` of a one-component name reads NULL where stock reads `''`, and `leaf('')` reads `''` where stock reads NULL: `WHERE parent(parent(account)) = ''` counts 0 postings, not 10, on MCP, REST and GraphQL

**Minor · ledger (`@rustledger/wasm` 0.24.0 BQL functions; pin in `scripts/bql-oracle/`, note in `README.md`) · 20–30m, plus an upstream report · A1.** Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 LAND=1`) on 2026-11-28, against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`), with an unpinned read/write `bcio_` key on the QA account, read-only, on `<qa-owner>/mcp-agent-eval` at its pristine `main.bean` (git blob `f1a0b83c`, 87 lines, 0 errors). Reproduced at HEAD `8a8b2c4df` through `LedgerShellService.queryShell` on the same file, so this is not deployment lag. In the same run `yarn mcp:conformance --ledger` passed 19/19 and `qa-contract-replay.mjs --commit-probes` ran 17 probes with 0 mismatches.

Stock `beancount.core.account.parent` returns `''` for a name with no `:` and `None` only for an empty name; `account.leaf('')` returns `None`. The engine does the reverse at both edges. An agent rolling accounts up with a `parent()` chain gets a filter that matches nothing and a group it cannot compare with stock's.

## Repro (live, read-only)

| Query | Hosted (MCP `runBqlQueryStructured`, REST `POST …/query`, GraphQL `queryShell`) | Stock beanquery 0.2.0 / beancount 3.2.3 |
| --- | --- | --- |
| `SELECT count(*) AS n WHERE parent(parent(account)) = ''` | `[[0]]` | `[[10]]` |
| `SELECT count(*) AS n WHERE parent(parent(account)) IS NULL` | `[[10]]` | no row |
| `SELECT DISTINCT parent(parent(parent(account))) AS p` | 1 row (NULL) | 2 rows: `''` and `None` |
| `SELECT parent(parent(account)) AS p, sum(number) AS s GROUP BY p ORDER BY p` | first row `[null, "-21030.25"]` (GraphQL prints `""`) | `('', -21030.25)` |
| `SELECT parent('Assets') AS p, leaf('') AS l, parent('') AS e` | `[null, "", null]` per row | `('', None, None)` |

- The ten postings are those on two-component accounts (`Assets:Cash`, `Expenses:Transport`, …). `runBqlQuery`'s text table prints the NULL and the `''` alike as blank, so only the structured cells, `WHERE`, `IS NULL`, `DISTINCT` and `GROUP BY` show the split.
- Controls that agree: `parent(account)` on every real account (each has two or more components), `parent('')` (NULL on both), `leaf(account)`, `root(account, n)` for every `n`, `splitcomp`. A real account never has one component, so the split appears only in a `parent()` chain or on a literal.

## Fix

- Not fixable by rewriting the query: the engine has no `CASE`, and `coalesce(parent(x), '')` would turn `parent('')` into `''` where stock keeps `None`. Report both edges upstream to rustledger with the w23/022 batch: `parent` of a one-component name is `''`, `leaf('')` is NULL.
- In this repo: add the five queries above to `scripts/bql-oracle/queries.json` on the oracle's `main.bean` (it has two- and three-component accounts), regenerate `bql-oracle.json`, and allowlist the `cells`/`row-count` differences with this note as the reference, so `yarn verify:rustledger` turns red when an engine bump fixes them. Add a short `## BQL parent() and leaf() at a root` section to `backend-cluster/ledger/README.md` saying to use `root(account, n)` for roll-ups and `IS NULL` rather than `= ''` meanwhile.

---

**Resolved 2026-11-28** — The engine fix is upstream's; this repo now gates it and documents the workaround. The engine has no `CASE`, and `coalesce()` would also turn `parent('')` into `''`, so the shell cannot rewrite either edge.
- **Gate.** Seven queries on the oracle's `main.bean` (`source: w31/164`), with `bql-oracle.json` regenerated on stock beanquery 0.2.0 / beancount 3.2.3. Six are allowlisted against this note: `parent-root-equals-empty` (stock 15, engine 0), `parent-root-group` (`''` against NULL), `parent-root-distinct` (2 rows against 1, typed `unknown` here), `parent-leaf-literals` (`parent('Assets')`), and two that differ from the repro above. `leaf-empty-literal` exists because the comparator stops at a row's first differing cell, so `parent('Assets')` hid `leaf('')`. `parent-root-is-null` is `SELECT DISTINCT account WHERE … IS NULL`, not `count(*)`, because stock answers an aggregate over no rows with no row (the `empty-aggregates` deviation), and that difference would outlive an engine fix. Each entry goes stale, and `yarn verify:rustledger` turns red, once an engine bump reads that edge as stock does. The seventh, `parent-root-workaround` (`GROUP BY root(account, 1)` with `WHERE root(account, 2) = account`), matches stock and pins the documented spelling.
- **Docs.** The ledger `README.md` (new section "BQL `parent()` and `leaf()` at a root") and `backend-v2/docs/mcp.md`'s BQL result notes say to roll up with `root(account, n)`. They also say that `IS NULL` stands in for stock's `= ''` only on this engine.
- **Upstream.** The owner still has to file both edges with rustledger, alongside the w23/022 batch.

Shipped in the commit carrying this note (`backend-cluster/ledger`, `backend-cluster/backend-v2`).

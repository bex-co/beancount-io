# ai-agent routes give a rejected credential the "no credential" message

Source: follow-up from `w31/025` (`78b17469e`), 2026-11-15.

- `w23/070` gave a rejected credential its own error text, separate from the one for sending no credential. `w31/025` brought GraphQL's anonymous-allowed reads and REST's archive-download URL into line with it.
- The backend-v2 ai-agent routes that authenticate through `resolveAuthUser` still answer a rejected credential with "Authentication required", the no-credential text. `w31/025` left them alone as outside its scope.
- Change only the message and error code a rejected credential receives. Do not loosen any authorization decision.

**Done when:** every route that uses `resolveAuthUser` gives a rejected credential the same text and code as the `w23/070` paths, and a test checks that.

---

**Resolved 2026-11-15** — The routes that authenticate through `resolveAuthUser` now tell a request whose credential was refused that it was refused, instead of asking it for a credential. Shipped in the commit carrying this note (`backend-cluster/backend-v2`).

- **What changed.**
  - `resolveAuthUser` (`src/features/ai-agent/utils/route-guards.ts`) now takes the app config. With no identity, it throws `UnauthenticatedError` with `credentialRejection`'s wording, as REST's `requireIdentity` and GraphQL do (`w23/070`). A request that sent no credential, or only a browser cookie, still gets "Authentication required". An MCP-audience token is named as one. Every caller passes the config: `POST /api-gateway/agent`, `/api-gateway/sandbox-agent`, `/api-gateway/ai/openai/chat/completions` (through `setupAiAgentRoutes`), and the OAuth consent approval `POST /api-gateway/oauth/interaction/:uid/login`.
  - The refusal keeps code `UNAUTHENTICATED` and status 401, and on the AI routes the `WWW-Authenticate` challenge still adds `error="invalid_token"` for a presented credential. No authorization decision changed. The text depends only on the request's headers. These routes refuse before any ledger lookup, so the text says nothing about whether a ledger exists. GraphQL and MCP needed no change: GraphQL already used this wording, and MCP refuses a rejected credential with 401 before any tool runs.
- **Evidence.**
  - Live repro first, on `https://beancount.io`. A garbage bearer and a garbage `x-api-key` got 401 `UNAUTHENTICATED` "Authentication required" from all three AI routes, the same as no credential.
  - `credential-rejection.test.ts` mounts the three AI routes as `setupAiAgentRoutes` does, behind `restErrorMiddleware` and the real `restIdentityMiddleware`. It checks each one over HTTP with no credential, an MCP-audience token, an expired token, a malformed bearer, an unknown key sent as `x-api-key` or as a bearer, and a garbage `x-api-key`. `oidc-route.test.ts` checks that the consent approval answers a garbage bearer and an unknown `bcio_` bearer with the "not accepted" text, and still answers no credential with "Authentication required". With the fix reverted, the three AI-route cases and the consent case fail.
- **Gates.** Run in `node:22-bookworm-slim` (v22.23.4) from `backend-cluster/backend-v2`: `yarn typecheck`, ESLint on the changed files, `yarn lint:deadcode`, `yarn format:check`, `yarn test` (485 suites, 11041 tests passing, 1 skipped), and `yarn generate-v1-openapi` (no drift). The live behavior changes after the next backend-v2 deploy.

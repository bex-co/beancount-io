# A commit ref with a space (`"main "`, `" b6d69fd"`, `"a b"`) is answered as a server fault on every commit read: `INTERNAL_SERVER_ERROR` "changing the request will not help", or `SERVICE_UNAVAILABLE` "a dependency is down"

**Minor · backend-v2 (commit reads) · 30–45m · A1.** A ref that cannot exist is reported as an outage, and the hint tells the agent to retry rather than fix its input. A sha copied with a stray leading or trailing space fails this way, though the same sha works without the space. Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`) on 2026-11-15, against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, `revision: unknown`, see `w31/002`). The credential was an unpinned read/write/admin `bcio_` key on the QA account, and every call was a read on its disposable QA ledger.

## Repro (live, reads only)

Read each URI through `resources/read`, with `<ref>` percent-encoded once. The same calls on REST `GET /api-gateway/v1/ledgers/{owner}/{name}/<suffix>` and GraphQL give the same codes.

| `<ref>` | `commit-details?sha=<ref>` | `commits?branch=<ref>` | `latest-commit?branchName=<ref>` |
| --- | --- | --- | --- |
| `main `, ` b6d69fd`, `b6d69fd ` (a real sha plus a space), `a b`, a single space | MCP `-32000` `INTERNAL_SERVER_ERROR` "Failed to fetch commit details from Gitea"; REST 500; GraphQL `getCommitDetails` `INTERNAL_SERVER_ERROR` | `INTERNAL_SERVER_ERROR` "Failed to fetch commits from Gitea" on all three (`listCommits`) | `SERVICE_UNAVAILABLE` "Ledger API is temporarily unavailable" on all three (`getLatestLedgerCommit`), hint "A dependency is down. Retry with backoff; this is not a problem with the request" |
| `nope`, `abcdef1`, `x:y`, `..`, `-n`, `日本`, `tab<TAB>here`, `0000…0000` (40 zeros) | `NOT_FOUND` "Commit with ID '…' not found" | `NOT_FOUND` "Branch with ID '…' not found" | `NOT_FOUND` "Branch with ID '…' not found" |
| `b6d69fd`, `main`, `HEAD~1`, `main^`, `refs/heads/main`, `b6d69fd<LF>` | resolves | resolves | resolves |

The `INTERNAL_SERVER_ERROR` hint reads "Retry once. If it persists the failure is server-side and changing the request will not help." Both hints are wrong here: the request is the problem, and removing the space fixes it. `revertCommit` resolves its sha with the same lookup, so `sha: "main "` will fail the same way once `w23/242` lets it run. Today every revert is `INTERNAL_SERVER_ERROR`.

**Working control:** the archive read already refuses malformed refs before calling the repository host. `beancount://{owner}/{name}/archive/a%20b.zip` is `BAD_USER_INPUT` "Invalid archive name", and REST answers 400 with the pattern (`backend-cluster/backend-v2/src/features/ledger/utils/safe-archive-name.ts:4`).

## Cause

The repository host answers a ref with a space with a 500 rather than a 404. Git's `cat-file --batch-check` echoes the name back as `a b missing`, so the host's line parser fails on the extra field, and the 500 it returns does not use the wording for a missing commit.

- `isMissingCommitLookupError` (`backend-cluster/backend-v2/src/features/gitea/commits/service/commits-service.ts:32`) maps only 404, 422, and a 500 that says "not found" / "does not exist" / "no such" / "no commit" / "unknown revision" to `NOT_FOUND`. Everything else becomes `InternalServerError`. This covers `findCommit` (`:54`, used by `getCommitDetails` `:379` and `revertCommit`'s `ledger-workflow.ts:1747`) and `listCommits` (`:345`).
- `getLatestCommit` (`backend-cluster/backend-v2/src/features/ledger/service/ledger-repo-service.ts:170`) goes through the ledger service's `/repo/…/commits` proxy (`backend-cluster/ledger/src/api/repo.ts:31`). That proxy passes the host's 500 through, and `favaApiErrorToDomainError` turns it into `SERVICE_UNAVAILABLE`.
- The shared read definitions accept any string: `sha` and `branch` are bare `z.string()` (`backend-cluster/backend-v2/src/features/gitea/commits/api/commit-reads.ts:33`, `:47`, `:70`), and the GraphQL `listCommits`, `getCommitDetails` and `getLatestLedgerCommit` arguments are plain `String`.

## Fix

Refuse a commit ref that holds whitespace or a control character with `BAD_USER_INPUT` naming the parameter (`sha`, `branch` or `branchName`), before the repository host is called. No git ref or sha can contain one (`git check-ref-format`). Keep the git revision syntax that works today: `~`, `^`, `@{…}` and `refs/heads/…` stay valid. Apply one shared check in the commits service (`findCommit`, `listCommits`) and in `getLatestCommit`, so MCP, REST and GraphQL change together, and `revertCommit` and `createPullRequest`'s `baseBranch` inherit it. Do not trim the value silently: an agent should learn its input was wrong.

**Done when:** each space-bearing ref in the table is `BAD_USER_INPUT` naming its parameter on the MCP resource, REST (400) and GraphQL. The `NOT_FOUND` and resolving rows are unchanged. A contract test through all three adapters covers it and fails with the check removed.

---

**Resolved 2026-11-15** — A commit ref with a space where git never allows one is now refused as `BAD_USER_INPUT` naming its parameter (`sha`, `branch` or `branchName`), before the repository host is called. Shipped in the commit carrying this note (`backend-cluster/backend-v2`).

- **What changed.**
  - New `assertCommitRef` (`src/shared/commit-ref.ts`) runs in `findCommit` (so `getCommitDetails` and `revertCommit`), in `listCommits`, and in `getLatestCommit`. All three surfaces share these services, so MCP, REST (400) and GraphQL changed together. `createPullRequest`'s `baseBranch` already had its own branch-name check.
  - The check refuses only a space (U+0020) outside a brace group and before a `:`. That one character makes the host's object lookup fail with a 500: it splits the `<name> missing` line on spaces. Git revision syntax that takes a space still reaches the host, and all of it resolved live before the fix: `main@{1 day ago}`, `main^{/restore fixture}`, `:/restore fixture`. Other whitespace keeps the answer it had, as this note's "Done when" requires: a tab is `NOT_FOUND`, and a trailing newline or CR resolves. The value is never trimmed silently.
  - `docs/mcp.md` "Repository history resources" now states the rule.
- **Evidence.**
  - Live repro first, reads only, on `https://beancount.io` against a QA ledger. `main `, ` main`, `a b` and a single space gave `INTERNAL_SERVER_ERROR` on `commit-details` and `commits` and `SERVICE_UNAVAILABLE` on `latest-commit`, on MCP, REST and GraphQL alike. `nope` was `NOT_FOUND`. `main`, `HEAD~1`, `main^`, `main^{commit}` and `main<LF>` resolved.
  - `commit-parity.test.ts` drives each of this note's five space-bearing refs through all three reads on REST, GraphQL and MCP (15 cases), with the mocked host answering 500 the way the real one does. Each must be `BAD_USER_INPUT` naming the parameter, and the host must not be called. Two more cases pass `main@{1 day ago}` and `:/restore fixture` through to the host on every surface. `revert-commit-parity.test.ts` refuses `sha: "c1 c0"` on each surface and writes nothing. `commit-ref.test.ts` pins the accepted and refused spellings. With the three calls removed, all 15 contract cases and the 3 revert cases fail.
  - Still open: a space inside a group or after `:/` that matches nothing (`main@{a b}`, `:/zzz qqq`, `nope@{1 day ago}`) still reaches the host and comes back as its 500. That needs the host's lookup fixed, or a heuristic that would hide a real 500.

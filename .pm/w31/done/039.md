# `register` silently ignores invalid `conversion` (`BOGUS`, `USD,EUR`) and returns `200 OK { account: null, rows: [] }` whenever no account matches or the `time` window is empty, on MCP, REST, and GraphQL

**Minor · backend-v2 (`LedgerFinanceService.getRegister`) · 25–35m · A1.** Passing an unsupported or syntactically invalid `conversion` to `register` succeeds with `200 OK {"account":null,"rows":[]}` whenever `selectRegisterRoot` finds no matching account or no postings/balances in the requested `time` window, instead of refusing with `BAD_USER_INPUT` as `register` (with rows), `account-journal`, `account-report`, and `holdings` all do across MCP, REST, and GraphQL. Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 LAND=1`) on 2026-11-23 against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, checked against HEAD `fa02bce80`). Credential: unpinned read/write/admin `bcio_` key on the QA account. Synthetic ledger: `<qa-owner>/mcp-agent-eval`.

## Repro (live)

Reproduced in fresh read-only requests across all three surfaces against `<qa-owner>/mcp-agent-eval`:

1. **Existing account (`Assets:Bank:Checking`) on an empty `time` window (`time=1999`) with invalid `conversion` (`BOGUS` or `USD,EUR`)**:
   - MCP:
     ```sh
     node .agents/skills/qa-shared/scripts/qa-mcp.mjs read 'beancount://<qa-owner>/mcp-agent-eval/register/Assets:Bank:Checking?time=1999&conversion=BOGUS'
     node .agents/skills/qa-shared/scripts/qa-mcp.mjs read 'beancount://<qa-owner>/mcp-agent-eval/register/Assets:Bank:Checking?time=1999&conversion=USD,EUR'
     ```
     Actual: HTTP `200`, `{"account":null,"rows":[]}` for both.
   - REST `GET /api-gateway/v1/ledgers/<qa-owner>/mcp-agent-eval/register?account=Assets:Bank:Checking&time=1999&conversion=BOGUS`:
     Actual: HTTP `200`, `{"account":null,"rows":[]}`.
   - GraphQL `getLedgerRegister(ledgerId: "<qa-owner>/mcp-agent-eval", account: "Assets:Bank:Checking", time: "1999", conversion: "BOGUS") { account rows { date } }`:
     Actual: HTTP `200`, `{"data":{"getLedgerRegister":{"account":null,"rows":[]}}}`.
2. **Nonexistent account (`Assets:NoSuchAcct`) with `conversion=BOGUS`**:
   - MCP `beancount://<qa-owner>/mcp-agent-eval/register/Assets:NoSuchAcct?conversion=BOGUS`: HTTP `200`, `{"account":null,"rows":[]}`.
   - REST `GET /api-gateway/v1/ledgers/<qa-owner>/mcp-agent-eval/register?account=Assets:NoSuchAcct&conversion=BOGUS`: HTTP `200`, `{"account":null,"rows":[]}`.
   - GraphQL `getLedgerRegister(ledgerId: "<qa-owner>/mcp-agent-eval", account: "Assets:NoSuchAcct", conversion: "BOGUS") { account }`: HTTP `200`, `{"data":{"getLedgerRegister":{"account":null}}}`.

Expected: refused with `BAD_USER_INPUT` (`Unsupported conversion ...`) on MCP, REST, and GraphQL regardless of whether the account or `time` window has postings.

## Working controls

- MCP/REST/GraphQL `register` on `Assets:Bank:Checking` without `time=1999`:
  - `?conversion=BOGUS` → `BAD_USER_INPUT: Unsupported conversion "BOGUS": pass "units", "at_cost", "at_value", "units_by_cost", or a currency in this ledger (USD).`
  - `?conversion=USD,EUR` → `BAD_USER_INPUT: Unsupported conversion "USD,EUR": pass one currency code, "units", at_cost, or at_value.`
- MCP/REST `account-journal` and `account-report` with the exact same `Assets:Bank:Checking&time=1999&conversion=BOGUS` and `Assets:NoSuchAcct&conversion=BOGUS` → `BAD_USER_INPUT: Unsupported conversion "BOGUS": pass "units", "at_cost", "at_value", "units_by_cost", or a currency in this ledger (USD).`
- MCP `holdings?account=Assets:NoSuchAcct&conversion=BOGUS` → `BAD_USER_INPUT: Unsupported conversion "BOGUS": pass "units" or a currency in this ledger (USD).`

## Root cause

Not deployment lag — present at HEAD `fa02bce80`:

- `backend-cluster/backend-v2/src/features/ledger/service/ledger-finance-service.ts:373-391` (`LedgerFinanceService.getRegister`):
  Line 379 executes `if (root === null) return { account: null, rows: [] };` **before** calling `resolveRegisterConversion` (line 380) or `this.registerItems` → `favaApiClient.journal.getAccountJournal` (line 384, where `conversion` is validated against the ledger's known currencies per `w1/204`).
- Whenever `selectRegisterRoot` returns `null` (nonexistent account, opened account with no postings/balances, or existing account with no postings/balances in the `time` window), both syntactic checks (`USD,EUR`, invalid characters) and known-currency checks (`BOGUS`, `usd`) are skipped.
- Compare with `LedgerFinanceService.getHoldings` (`ledger-finance-service.ts:229-238`), which calls `resolveHoldingsConversion` and `this.assertLedgerNamesCurrency(...)` unconditionally before filtering by `account`.
- Note also: `resolveRegisterConversion` (`src/features/ledger/utils/register.ts:74-77`) passes `allowedModes = ["at_cost", "at_value"]` (omitting `"units_by_cost"`), so validating `target` against the ledger's commodities when `root === null` must also recognize `"units_by_cost"` as a valid mode alongside `"at_cost"` and `"at_value"`.

## Fix

In `backend-cluster/backend-v2`:

1. Update `resolveRegisterConversion` (`src/features/ledger/utils/register.ts:65-78`) to include `"units_by_cost"` in `allowedModes` (matching what `getAccountJournal` accepts and reports).
2. In `LedgerFinanceService.getRegister` (`src/features/ledger/service/ledger-finance-service.ts:373-391`), call `resolveRegisterConversion(conversion, options?.operating_currency ?? [])` **before** `if (root === null)`. When `root === null` and `conversion !== undefined` and `target !== null` and `target` is not one of the Fava modes (`at_cost`, `at_value`, `units_by_cost`), validate `target` against the ledger's known currencies (reusing the `assertLedgerNamesCurrency` lookup with the register's allowed-modes wording) before returning `{ account: null, rows: [] }`.
3. Because MCP `beancount://{owner}/{name}/register/{account}`, REST `GET /api-gateway/v1/ledgers/{owner}/{name}/register`, and GraphQL `getLedgerRegister` all delegate to `LedgerFinanceService.getRegister`, all three surfaces change together with no OpenAPI/schema change.
4. Add unit tests in `src/features/ledger/service/__tests__/ledger-finance-service.test.ts` and 3-surface parity tests in `src/features/ai-agent/api/__tests__/report-conversion-parity.test.ts` covering `conversion: "BOGUS"` and `conversion: "USD,EUR"` on both a nonexistent account and a real account with an empty `time` window (and verifying valid `"units_by_cost"` still returns `{ account: null, rows: [] }` when `root === null`).

**Done when:**

- MCP, REST, and GraphQL `register` refuse `conversion=BOGUS` and `conversion=USD,EUR` with `BAD_USER_INPUT` even when the account does not exist or has no postings in the requested `time` window.
- Valid conversions (`units`, `at_cost`, `at_value`, `units_by_cost`, or a ledger currency such as `USD`) still return `{ account: null, rows: [] }` when `root === null`.
- New unit and 3-surface parity tests fail with the early return order reverted and pass with it fixed.
- `yarn typecheck`, `yarn lint:deadcode`, `yarn format:check`, `yarn test`, and `yarn generate-v1-openapi` pass in `backend-cluster/backend-v2/`.

Dedupe: searched `.pm/**` (open, done, blocked) for `resolveRegisterConversion`, `selectRegisterRoot`, `getRegister`, and `conversion`. `w1/204` fixed `register` conversion validation when `root !== null` (through `getAccountJournal`), leaving the `root === null` early-return path unvalidated.

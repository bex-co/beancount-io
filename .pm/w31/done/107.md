## Cause

Every pattern below starts with `\d{4}-\d{2}-\d{2}`. The shared `SOURCE_DATE` and `sourceDateOf` (`source-date.ts`, w31/106) already read every spelling the lexer reads.

- `stock-syntax-errors.ts:32-35` `OPEN_WITH_BARE_BOOKING`, `:36` `COMMODITY` and `:38-39` `TRANSACTION`, which gates the duplicate-key scan at `:193`.
- `balance-tolerance-syntax.ts:26-27` `MID_CURRENCY_TOLERANCE`.
- `pre-open-uses.ts:11` `DATE`. It is compared at `:47` with the engine's `YYYY-MM-DD` open date.

## Fix

Have each rule read a header line with `SOURCE_DATE` and compare dates as `sourceDateOf` normalizes them. Widening the pattern is not enough on its own:

- The duplicate-commodity sort (`stock-syntax-errors.ts:214-219`) compares the captured date strings, and `/` sorts after `-`. A file with `2026-09-03 commodity QAZZ` on line 1 and `2026/09/01 commodity QAZZ` on line 2 would get its error on line 2. Stock puts it on line 1, the later date (checked with `bean-check` 3.2.3). Store the normalized date.
- `pre-open-uses.ts:47` compares `used >= opened` as strings. It needs `sourceDateOf(line)` too.

No response shape changes. All four surfaces read these errors from the one ledger path: the MCP tools and `errors` resource, the REST `errors` route and write previews, and GraphQL `getLedgerErrors` and the file mutations. They change together.

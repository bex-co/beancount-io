# backend-v2 ESLint fails at `main` on two untouched files

**Minor · backend-v2 (lint) · 15–20m · A1.** The ESLint half of `yarn lint` (`eslint src --ext .ts`) reports two errors on files the w31 workers did not touch. It runs in no CI job (`CI (backend parity)` runs `typecheck`, `lint:deadcode`, `format:check` and `test`), so nothing catches it. The `w31/110` and `w31/115` workers both hit it as a pre-existing failure.

- `src/features/gitea/pull-request/service/pull-request-service.ts`: `no-control-regex`.
- `src/server/api/__tests__/mcp-hostile-values.test.ts`: unused `argumentsAt`.

Fix each without disabling the rule. The `w23/049` resolution shows one way: write the character class as `\P{ASCII}`, which `no-control-regex` accepts. Then delete or use `argumentsAt`. Check with `npx eslint src --ext .ts` (no `--fix`). It must report 0 errors, and `typecheck` and `test` must stay green. Adding ESLint to `CI (backend parity)` is separate work. It needs a non-`--fix` script first, the same `--fix` problem the root `AGENTS.md` notes for `CI (ledger)`.

---

**Resolved 2026-11-27** — `npx eslint src --ext .ts` in `backend-cluster/backend-v2` now reports 0 errors (the 429 warnings it already printed are unchanged); no rule was disabled. Both errors reproduced at `d5bd987` before the fix.

- `pull-request-service.ts`: `assertBranchName` refused `[\u0000- \u007f…]`. The control-and-space part is now `ASCII_CONTROL_OR_SPACE = /[^\x21-\x7e\P{ASCII}]/u`, any ASCII character outside `!`–`~`, which `no-control-regex` accepts. The other characters stay in their own `/[~^:?*[\\#%]/`. A scratch comparison of the old and new tests over every UTF-16 code unit (alone and inside a name), a stride of astral code points and lone surrogates found no input where they disagree.
- `mcp-hostile-values.test.ts`: `argumentsAt` was a string-only copy of the `at` helper beside it, which the cases use. It is deleted, and `at` carries its doc comment.
- Tests: `pull-request-service.test.ts` now refuses NUL, U+001F, an inner space, DEL and each of `~ ^ : * [ \ %` in `baseBranch`, and accepts `feature/café`, `功能/分支`, U+0080 and U+00A0. Swapping in `[\p{Cc}\s]` fails 2 of the new cases and a space-only class fails 4.
- Gates: typecheck, `format:check`, `lint:deadcode`, and all 13344 tests in 505 suites pass. ESLint is still in no CI job; that needs a non-`--fix` script first, as the note says.

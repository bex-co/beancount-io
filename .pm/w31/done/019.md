# A git-storage receipt insert always fails when the ledger routes documents to a file in a subdirectory: the receipt's `document` path is written repo-root-relative into that file

**Major · backend-v2 (`LedgerReceiptWorkflow`) · 30–45m · A1.** For this routing setup, receipt capture is broken on the dashboard, on mobile and over MCP. Every attempt is refused with an error the caller cannot fix, because the path is generated by the server, and every attempt leaves two commits behind. Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 LAND=1`) on 2026-11-15, against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, `revision: unknown`, see `w31/002`). The credential was an unpinned read/write/admin `bcio_` key on the QA account, and writes went only to the QA ledger `<qa-owner>/mcp-agent-eval`. `main.bean` was restored byte for byte afterwards (blob `f1a0b83c`), the probe files were deleted, and the check is clean.

## Repro (live)

The run used `qa-20261115-r8/docs.bean`. This note shortens it to `qa/docs.bean`.

1. Create `qa/docs.bean`, then add these lines to `main.bean`:

   ```beancount
   2000-01-01 custom "beancountio-option" "receipt_storage" "git"
   2000-01-01 custom "beancountio-option" "document_file" "qa/docs.bean"
   include "qa/docs.bean"
   ```

2. Call `generateTempAssetUploadUrl` with `{filename: "r.png", mimeType: "image/png"}`, then PUT a 70-byte PNG with the returned `uploadHeaders`.
3. Call `insertReceiptTransaction` with `date: "2026-08-30"`, a balanced pair of `1.00 USD` postings (`Expenses:Food:Groceries`, `Assets:Cash`), and `documentAccount: "Assets:Cash"`.

Actual: `isError: true`, `VALIDATION_FAILED`, "adding these entries would introduce 1 new bean-check error: Document file not found: documents/2026-08-30-<payee>-<id>.png (qa/docs.bean:3)". The hint says "The entries are valid but would break the ledger … Fix the entries.", but nothing the caller sends sets that path. The history gains `docs: add receipt documents/…png`, and then `docs: remove receipt …; its entry was refused`. GraphQL `insertReceiptTransaction` (the dashboard and mobile flow), sent with the same key, gives the same refusal and the same two commits.

## Controls

- Without the `document_file` line, the same upload is inserted. `main.bean` gets `2026-08-30 document Assets:Cash "documents/2026-08-30-…png" ^rcpt_…` and the linked transaction, and `checkLedger` stays clean.
- With that receipt in the repo, `updateLedgerFiles` `dry_run` that adds a `document` line to `qa/docs.bean` gives these results:
  - `"documents/…png"`: `valid: false`, "Document file not found".
  - `"../documents/…png"`: `valid: true`.
- Stock Beancount 3.2.3 gives the same verdicts. `bean-check` on `main.bean` with `include "sub/docs.bean"` and `documents/r.png` at the root reports `sub/docs.bean:1: File does not exist: "…/sub/documents/r.png"` for `"documents/r.png"`, and accepts `"../documents/r.png"`.

## Cause

- `gitStrategy` in `backend-cluster/backend-v2/src/features/ledger/workflow/ledger-receipt-workflow.ts` builds `receiptPath` repo-root-relative (`buildReceiptPath`, `:90`; `receipt_base_folder` defaults to `documents`, `:246`). It stores the file there and writes the same string as the `document` directive's `filename` (`:305`).
- `writeBulkEntries` then routes that directive by type and date (`ledger-entry-service.ts:704-708`, `resolveEntryFile`: `document_file`, else `default_file`; `entry-file-resolver.ts:61,67`).
- Beancount, and the hosted engine (`backend-cluster/ledger/src/foundation/rustledger/document-validation.ts:85` `resolveDocumentPath`), resolve a relative `document` path against the directory of the file that declares it. So whenever the routed file is not at the repository root, the path points at a file that does not exist. The same happens when `default_file` sits in a subdirectory and `document_file` is unset (read from the code, not run live).

## Fix

In `gitStrategy`, resolve the file the document will be routed to, using `resolveEntryFile("Document", <date>, bcioData)`, the same call `writeBulkEntries` makes. Write the directive's `filename` relative to that file's directory, for example `posix.relative(posix.dirname(routed), receiptPath)`, which gives `../documents/2026-08-30-…png` from `qa/docs.bean`. The stored path and commit messages stay repo-root-relative. A root-level routed file still gets `documents/…`. REST `POST …/import/insert-receipt`, GraphQL `insertReceiptTransaction` and MCP `insertReceiptTransaction` share the workflow, so all three change together. No response shape changes.

**Done when:**

- The repro above inserts the receipt. `qa/docs.bean` holds `document Assets:Cash "../documents/…png"`, `checkLedger` is clean, and `bean-check` on a downloaded copy passes.
- A root-level routed file still writes `documents/…png`, and an S3-storage ledger is unchanged.
- A workflow unit test covers `document_file` in a subdirectory and fails with the fix reverted.

Dedupe: searched `.pm/**` (done and blocked included) for `document_file`, `receipt_base_folder`, `receipt_storage`, "Document file not found", E8001 and routed receipts. `w23/058` (a refused receipt left an orphan) and `w4/301` (the dashboard resolves documents from the declaring file) are done and adjacent, but neither covers the written path. `git log -S buildReceiptPath` shows no fix since the workflow was imported.

---

**Resolved 2026-11-15** — Under git storage, a receipt's `document` directive now names the receipt relative to the file it is routed to, so a document routed to a subdirectory file is no longer always refused. `gitStrategy` in `backend-cluster/backend-v2/src/features/ledger/workflow/ledger-receipt-workflow.ts` resolves that file with `resolveEntryFile("Document", <date>, …)`, the same call `writeBulkEntries` makes (`document_file`, else `default_file`, with `{year}`-style templates interpolated). It then writes the path relative to that file's directory, so `qa/docs.bean` gets `"../documents/…png"`. Both paths are rooted at `/` first, so the result does not depend on the server's working directory. A root-level routed file still gets `documents/…`. The stored path, the commit messages and S3 storage are unchanged. REST `POST …/import/insert-receipt`, GraphQL `insertReceiptTransaction` and MCP `insertReceiptTransaction` share the workflow, so all three changed together, and no response shape changed. `docs/mcp.md` "Insert receipt transactions" states where the receipt is stored and how the directive spells it.

Client-visible before the fix: on the QA ledger `<qa-owner>/mcp-agent-eval`, with `receipt_storage "git"` and `document_file "qa-w31-019/docs.bean"`, the deployed MCP `insertReceiptTransaction` was refused with `VALIDATION_FAILED` "Document file not found: documents/2026-08-30-…png (qa-w31-019/docs.bean:3)". The control insert, routed to the root, stored `documents/2026-08-30-…png`. The fixed end state was then committed through `updateLedgerFiles`: the directive moved into `qa-w31-019/docs.bean` as `document Assets:Cash "../documents/…png" ^rcpt_…`, with `document_file` restored. `updateLedgerFiles` validation was `valid: true` with no new errors, and `checkLedger` was clean. Stock Beancount 3.2.3 `bean-check` passes on a downloaded copy of those files plus the receipt, and on the same copy rejects the old `"documents/…png"` spelling with "File does not exist". `main.bean` was restored byte for byte (blob `f1a0b83c`), the probe files were deleted, and the check is clean. The deployed backend still runs the old code until the next deploy.

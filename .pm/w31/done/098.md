# `appendLedgerText` (`insertDirectives` / `endOfBlock` / `openPushes`) ignores multiline strings in existing files and splices new directives into the middle of quoted narrations across MCP, REST, and GraphQL

**Major · `backend-cluster/backend-v2` (`src/features/ledger/utils/directive-text.ts`) · 35–45m · A1.** `appendLedgerText` (`POST /api-gateway/v1/ledgers/{owner}/{name}/directives/text`, GraphQL `appendLedgerText`) inserts new directives in date order into an existing file via `insertDirectives` (`src/features/ledger/utils/directive-text.ts:449-660`). Although `directive-text.ts` already implements `scanLine(line, inString)` (`:51-68`) for `TagStack.annotate` and explicitly instructs callers (`:323`) to add multiline-string entries with `addLedgerEntries` or `updateLedgerFiles`, every scanner that reads the **existing** target file in `insertDirectives` — `heads` (`:461-466`), `insertionPoint` (`:533-544`), `endOfBlock` (`:576-588`), and `openPushes` (`:610-627`) — ignores multiline string state. Whenever a date-sorted ledger file contains a valid multiline quoted string whose continuation line starts at column 0 (for example a multiline transaction narration or `note` directive), `endOfBlock` stops at the column-0 continuation line instead of advancing past the closing quote and postings, and `insertDirectives` splices the newly appended directive **directly into the middle of the existing entry's quoted string**. In addition, a date, keyword, or `pushtag`/`pushmeta` text on a column-0 line inside a multiline string corrupts `sorted` detection, insertion placement, and `outsideScopes` push/pop wrapping.

## Expected

- `insertDirectives` tracks multiline `"..."` string state (using `scanLine`) across every pass over the target file (`heads`, `insertionPoint`, `endOfBlock`, `openPushes`, and `outsideScopes` / `precedesScope`):
  - Physical lines that start inside an open string are part of the current directive/block (never a new directive header, never a block terminator in `endOfBlock`, never a `pushtag`/`poptag`/`pushmeta`/`popmeta` statement in `openPushes`, and never stepped into by `outsideScopes`).
- In the repro above, `appendLedgerText` inserts the `2026-08-31` transaction cleanly **after** the `2026-08-30` transaction's postings (`Assets:Bank:Checking`), with `valid: true` and `0` new bean-check errors across MCP, REST, and GraphQL.

## Root cause

In `backend-cluster/backend-v2/src/features/ledger/utils/directive-text.ts`:
- `insertDirectives` (`:461-466`) computes `heads` without `inString` state, so a column-0 line inside a multiline string that matches `DATE_LINE` (e.g. `2026-01-01 ...`) or an undated keyword (`include ...`, `option ...`, `pushtag ...`) is misclassified as a top-level directive head.
- `insertionPoint` (`:533-544`) scans `lines` without `inString` state, so a column-0 line inside a multiline string can be treated as a new directive head or trigger an early return.
- `endOfBlock` (`:576-588`) stops at the first non-blank, non-indented line (`!isContinuation(line)`) without checking whether the directive's header (or metadata/posting string) is still inside an open `"..."` string — truncating the block mid-string before its closing quote and indented postings.
- `openPushes` (`:610-627`) and `outsideScopes` (`:648-660`) call `fileStatement(line)` without `inString` state, so a column-0 `pushtag`/`pushmeta` line inside a multiline string emits spurious `poptag`/`pushtag` wrappers around appended entries (or lets `outsideScopes` step back into a multiline string).

## Fix

In `backend-cluster/backend-v2/src/features/ledger/utils/directive-text.ts`:
1. Reuse the existing `scanLine(line, inString)` helper (`:51-68`) to track whether each line in `lines` begins inside an open quoted string (e.g. compute a per-line `startsInString` boolean array or pass `inString` state cleanly through `heads`, `insertionPoint`, `endOfBlock`, `openPushes`, and `outsideScopes`).
2. In `endOfBlock(lines, start)`: advance `inString` from `lines[start]` via `scanLine`; while `inString` is true, every subsequent line (blank or column-0) stays inside the block (`end = index + 1`), and once the string closes, continue absorbing indented continuation lines (including any multiline strings inside metadata/postings) before stopping at the next top-level line outside a string.
3. In `heads`, `insertionPoint`, `openPushes`, and `outsideScopes`: ignore any line where `startsInString[index]` is true (and never step `start` back into a line inside a multiline string).
4. Add unit tests in `backend-cluster/backend-v2/src/features/ledger/utils/__tests__/directive-text.test.ts` and 3-surface parity tests in `append-ledger-text-parity.test.ts` covering:
   - Appending after a date-sorted transaction/note with a multiline string whose continuation line starts at column 0 (both plain text and keyword/date-prefixed lines like `2026-09-01 ...`, `include ...`, `pushtag #fake`).
   - Appending dated *before* a multiline-string transaction without corrupting `heads`/`sorted` order.
   - Multiline string containing `pushtag`/`pushmeta` lines not triggering `outsideScopes` wrappers.

# A currency that ends in `.`, `_`, `'` or `-` (`1 QAB.`, `commodity QAB-`) reads clean and commits, though stock `bean-check` 3.2.3 refuses it and `addLedgerEntries` refuses the same currency as "not a valid currency", on MCP, REST and GraphQL (gap in w31/121)

**Minor · ledger (`src/foundation/rustledger/stock-syntax-errors.ts`) · 30–45m · A1.** Beancount's lexer reads a currency as `[A-Z][A-Z0-9'._-]*[A-Z0-9]` (or `/…` for a futures contract). A currency may hold `.`, `_`, `'` and `-` inside, but its last character must be a capital or a digit (`beancount/parser/lexer.l:170-207`, which names `CAC_` as a counter-example). `@rustledger/wasm` 0.24.0 accepts the trailing character and books a currency named `QAB.`. The ledger service adds no error for it. A text write previews `valid: true` with `newErrors: []`, commits without `allow_invalid`, and reads clean on every error surface. The same file fails `bea check` and stock `bean-check`, and stock drops the whole entry at the bad token.

| written | stock `bean-check` 3.2.3 | hosted |
| --- | --- | --- |
| `Assets:QaCur  1 QAB.` (also `QAB'`, `QAB_`, `/QAB.`) | `Invalid token: '.'` (`'`, `_`), at the posting's line | clean. BQL reads `units(position)` as `{"QAB.": "1"}` |
| `Assets:QaCur  1 QAB-` | `syntax error, unexpected MINUS, expecting end of file or EOL or ATAT or AT` | clean |
| `open Assets:QaCur QAB.`, `commodity QAB.`, `price QAB. 1.00 USD`, `balance Assets:QaCur 0 QAB.`, `custom "qa" 1 QAB.` | `Invalid token: '.'` | clean |
| `open Assets:QaCur QAB-`, `commodity QAB-`, `balance Assets:QaCur 0 QAB-` | `syntax error, unexpected MINUS, expecting end of file or EOL` | clean |

The product already knows the rule. The structured path checks currencies against stock's grammar (`backend-cluster/ledger/src/features/ledger/utils/entry-tokens.ts:47`), so `addLedgerEntries` with `units: {number: "1", currency: "QAB."}` is refused up front: `entry 0: postings[0].units.currency "QAB." is not a valid currency`. The same posting typed as text through `appendLedgerText` or `updateLedgerFiles` commits.

## Repro (live)

1. Commit with `appendLedgerText` (no `allow_invalid`):

   ```beancount
   2026-08-30 open Assets:QaCur

   2026-08-30 * "qa-20261127-r22 cur"
     Assets:QaCur  1 QAB.
     Assets:QaCur  -1 QAB.
   ```

   The result is `Added 2 directives to main.bean. No new bean-check errors.` with `validation.valid: true`. The `dry_run` preview gave the same verdict on MCP, on REST `POST /api-gateway/v1/ledgers/<qa-owner>/mcp-agent-eval/directives/text` with `dryRun: true`, and on GraphQL `appendLedgerText(dryRun: true)`. REST `PUT …/files/main.bean` with `dryRun: true` answered `valid: true` for the `QAB.` and `QAB_` postings too.
2. Read the errors. MCP `checkLedger` returns `errors: []`.
3. `runBqlQueryStructured` `SELECT date, account, units(position) WHERE account = 'Assets:QaCur'` returns two rows, `{"QAB.": "1"}` and `{"QAB.": "-1"}`.
4. Control: stock `bean-check` 3.2.3 and `bea --file main.bean check` on the committed `main.bean` both exit 1 with `main.bean:92: Invalid token: '.'` and `main.bean:93: Invalid token: '.'`.
5. Every other row of the table was a `dry_run` of `updateLedgerFiles` on the same ledger, checked against stock 3.2.3 on the same projected file: stock refuses each, the hosted preview answers `valid: true`.

Controls that agree with stock, and must stay clean: `QA.B`, `QA..B`, `/QAB`, a 24- or 25-character currency, and a one-letter currency (`1 X`). `QaB`, `1QAB` and `QA/B` are refused on both sides already.

## Cause

`stockSyntaxErrors` (`backend-cluster/ledger/src/foundation/rustledger/stock-syntax-errors.ts`, wired at `engine.ts:879`) and `postingSyntaxErrors` (`posting-syntax-errors.ts`) report the stock parser refusals the engine loads without a word. Neither has a rule for a currency token that ends in one of the four special characters. `posting-syntax-errors.ts:76` already lexes a currency with stock's exact pattern, so the lexer stops before the trailing character. The scan does not report what is left over. The `open` booking rule's own `CURRENCY` (`stock-syntax-errors.ts:65`) deliberately allows a trailing special character, so that rule never sees it either.

## Fix

Report the token as stock does, the way w31/121's leading-dot number is reported: `Invalid token: '<char>'` for a trailing `.`, `_` or `'`, and `syntax error, unexpected MINUS, expecting …` for a trailing `-`. Put it on the line of each currency position: a posting's units, cost and price, an `open` currency list, `commodity`, `price` (the quoted and the base currency), `balance`, and a `custom` amount. Follow the scan's existing rules. It abstains on doubt, mirrors stock's quirks, and reports a directive's first syntax error only. One quirk to keep: `price QAB- 1.00 USD` stays clean, because stock reads it as `price QAB -1.00 USD`. Do not change the engine's booking; the error keeps the entry from counting as clean. Add a row to the ledger README's "stock errors the engine does not raise" table.

No response shape changes. Every surface reads these errors from the one ledger path: the MCP tools and the `errors` resource, the REST `errors` route and write previews, and GraphQL `getLedgerErrors` and the write mutations.

**Resolved 2026-11-27** — The ledger service now reports a currency that ends in `.`, `_`, `'` or `-` with stock 3.2.3's message, at stock's line, so the repro previews `valid: false` with `Invalid token: '.'` on each posting, a commit without `allow_invalid` is refused, and `checkLedger`, the `errors` resource, REST and GraphQL all list the error. The engine's booking is unchanged, and no response shape changed.

- **Lexer errors.** `stock-syntax-errors.ts` reports `Invalid token: '<token>'` (`P0012`) at the first `.`, `_` or `'` after a currency's last capital or digit, wherever the currency stands: a posting's units, cost and price, an `open` list, `commodity`, both currencies of a `price`, `balance`, a `custom` amount, a metadata value and `pushmeta`. The token runs to the next whitespace as stock reads it (`{1 QAB.}` is `.}`, `QAB.,USD` is `.,USD`). A lone capital is a currency only before whitespace, so `X.` and `X-` are one invalid token each. The scan starts a currency only where stock's lexer would: after whitespace, `{`, `,`, `@`, `~` or `)`, or a number or an expression written against it (`1QAB.`, `10/4/QAB.`), never inside an account or a tag (`#a-QAB.`). Stock's lexer skips a whole invalid token, so a dot or currency inside one starts no other. That also fixes w31/121's `(.5+.5)`, which was reported twice.
- **Grammar errors.** A currency that runs into a `-` is `syntax error, unexpected MINUS, expecting …`, with the tokens stock lists for that position: `end of file or EOL or ATAT or AT` after a posting's units, `RCURL or COMMA` in `{…}`, `RCURLCURL or COMMA` in `{{…}}`, and `end of file or EOL` after a price, on an `open`, `commodity` or `balance` line, on a `price`'s quoted currency and on a metadata value. The posting rule reads the line with `posting-syntax-errors.ts`'s stock lexer (`postingCurrencyMinus`). The message adds `: "QAB-" is not a currency; a currency ends in a capital letter or a digit`. In a `custom` value stock reads the `-` as the next value's sign, so the error is at the token after it (`unexpected EOL`, which stock puts on the next line, `end of file`, `STRING`, `DATE`, `BOOL` or `ACCOUNT`), and a number after it is clean. `price QAB- 1.00 USD` stays clean, as the note asked, because stock reads it as `price QAB -1.00 USD`.
- **Recovery.** These follow the scan's existing rules: one syntax error per directive, no posting error below the bad line, no duplicate for a dropped `commodity`, an invalid token reported wherever it is, and a flagless header straight after stays quiet.
- **Controls.** These stay clean: `QA.B`, `QA..B`, `/QAB`, `/1A`, `QAB-1`, `QAB-.X`, `QA'B`, `QA_B`, a 24- or 25-character currency, `1 X`, `1QAB`, `TRUEX`, accounts like `AB-:Cash`, and `QAB.` inside a string, a comment, a tag or an org-mode line.
- **Left alone.** Two neighboring refusals are not covered. A keyword where a currency goes (`1 TRUE-`) is stock's `unexpected BOOL`. A lone capital that ends a file with no line break is also refused.
- **Checked against stock.** Compared with stock 3.2.3's parser on 14,500 random ledgers, where stock reported about 37,600 invalid tokens besides the `.50` kind, 8,000 `unexpected MINUS` errors and 110 custom-value errors, and on the 126 tracked ledger fixtures. The only differences were the two cases left alone. A 200,000-line ledger scans in about 180–200 ms on this machine, against 170 ms before.
- **Tests.** `stock-syntax-errors.test.ts` covers each currency position, each tail character, each control and each recovery rule. With the fix reverted, 72 of its new tests fail, and disabling any single new rule fails at least one test. `verify-rustledger.ts` asserts that the raw engine still loads all 13 repros clean, so each rule is load-bearing. It also asserts that the service reports each one at stock's line with `P0012`, that the engine still books a currency named `QAB.`, and that the controls stay valid. The ledger README gains three rows in its table of stock errors the engine does not raise.
- **Gates.** `backend-cluster/ledger`: `yarn lint`, `yarn typecheck`, `yarn build`, `yarn test` (239 suites, 4,293 tests) and `yarn verify:rustledger` pass. The hosted repro against `beancount.io` waits for the next ledger deploy.

# `register` accepts whitespace-only `account` (`%20%20` / `"  "`) and returns `200 OK { account: null, rows: [] }` instead of `BAD_USER_INPUT` on MCP, REST, and GraphQL

**Minor · backend-v2 (`LedgerFinanceService.getRegister`) · 20–30m · A1.** `LedgerFinanceService.getRegister` refuses an empty string `""` with `BAD_USER_INPUT` (`Register needs an account...`), but silently accepts whitespace-only strings (`"  "`, `%20%20`), calls the ledger service, and returns `200 OK {"account":null,"rows":[]}` across MCP, REST, and GraphQL. Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 LAND=1`) on 2026-11-23 against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, checked against HEAD `ffb9f6270`). Credential: unpinned read/write/admin `bcio_` key on the QA account. Synthetic ledger: `<qa-owner>/mcp-agent-eval`.

## Repro (live)

Reproduced in fresh read-only requests across all three surfaces against `<qa-owner>/mcp-agent-eval`:

1. **MCP resource `beancount://<qa-owner>/mcp-agent-eval/register/%20%20`**:
   ```sh
   node .agents/skills/qa-shared/scripts/qa-mcp.mjs read 'beancount://<qa-owner>/mcp-agent-eval/register/%20%20'
   ```
   Actual: HTTP `200`, `{"account":null,"rows":[]}`.
2. **REST `GET /api-gateway/v1/ledgers/<qa-owner>/mcp-agent-eval/register?account=%20%20`**:
   Actual: HTTP `200`, `{"account":null,"rows":[]}`.
3. **GraphQL `getLedgerRegister(ledgerId: "<qa-owner>/mcp-agent-eval", account: "  ") { account }`**:
   Actual: HTTP `200`, `{"data":{"getLedgerRegister":{"account":null}}}`.

Expected: refused with `BAD_USER_INPUT` (`Register needs an account. Name the account to list, such as Assets:Checking.`) on MCP, REST, and GraphQL without calling the ledger service — matching `account: ""`.

## Working controls

- REST `GET /api-gateway/v1/ledgers/<qa-owner>/mcp-agent-eval/register?account=` returns HTTP `400 BAD_USER_INPUT: Register needs an account. Name the account to list, such as Assets:Checking.`
- GraphQL `getLedgerRegister(ledgerId: "<qa-owner>/mcp-agent-eval", account: "") { account }` returns `BAD_USER_INPUT: Register needs an account. Name the account to list, such as Assets:Checking.`
- Sibling `account-journal` (`w31/036`, `4d68f210a`) checks `account.trim() === ""` and refuses both `""` and `"  "`.

## Root cause

Not deployment lag — present at HEAD `ffb9f6270`:

- `backend-cluster/backend-v2/src/features/ledger/service/ledger-finance-service.ts:356-363` (`LedgerFinanceService.getRegister`):
  ```ts
  assertValidAccountPattern(account);
  if (account === undefined || account === "") {
    throw new BadUserInputError(
      "Register needs an account. Name the account to list, such as Assets:Checking.",
    );
  }
  ```
  The check tests `account === ""` instead of `account.trim() === ""`. Because `"  "` compiles as a valid JS `RegExp`, `assertValidAccountPattern` passes it, the service fetches ledger options/postings/balances from Fava, `selectRegisterRoot` finds no matching account, and the call silently returns `{ account: null, rows: [] }`.

## Fix

In `backend-cluster/backend-v2`:

1. Update the empty-account guard in `LedgerFinanceService.getRegister` (`src/features/ledger/service/ledger-finance-service.ts:358-363`) to check `account === undefined || account.trim() === ""` (before `assertValidAccountPattern` so blank values consistently report `"Register needs an account..."`), throwing `BadUserInputError` with field `"account"`.
2. Because MCP (`beancount://{owner}/{name}/register/{account}`), REST (`GET /api-gateway/v1/ledgers/{owner}/{name}/register`), and GraphQL (`getLedgerRegister`) all delegate to `LedgerFinanceService.getRegister`, all three surfaces change together with no OpenAPI drift.
3. Add unit tests in `src/features/ledger/service/__tests__/ledger-finance-service.test.ts` and 3-surface adapter tests covering `"  "` and `"\t"` across MCP, REST, and GraphQL, verifying the ledger client is not called.

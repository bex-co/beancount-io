# Four spellings stock bean-check refuses still read clean after w31/154

**Minor · ledger (`stock-syntax-errors.ts`) · 30–45m · A1.** Left over from `w31/154` (`0570a3ebc`). That worker compared the ledger with stock 3.2.3's parser on 14,500 random ledgers and 126 fixtures. Its hand-off lists four constructs that still read clean here while stock refuses them. The note `done/154.md` § "Left alone" records the first two.

1. A keyword where a currency goes, e.g. `ref: 1 TRUE-`. Stock reports `syntax error, unexpected BOOL`.
2. A lone capital directly before `}`, `,`, or the end of a file with no final line break.
3. A currency after `close` or `event`.
4. A detached ` -` after units, e.g. `1 QAB - `.

- First confirm each one against stock 3.2.3 and the raw engine. Drop any that does not reproduce, and say so in the resolution.
- Fix as `w31/154` did: report each at stock's line with stock's message and the engine's `P0012` code. Only start a match where stock's lexer would, so that accounts, tags and strings never match.
- Done when every confirmed construct is reported at stock's line, a `verify:rustledger` live check shows the raw engine still loads each one clean, the random-ledger comparison with stock shows no new difference, and the ledger README's stock-errors table lists the new rows.

---

**Resolved 2026-11-27** — All four constructs reproduced against stock 3.2.3's parser and loaded clean in the raw engine, so none was dropped. Each turned out to be one case of a wider engine leniency, and the fix covers the wider case. The ledger service now reports each one at stock's line, with stock's message and `P0012`. The engine's booking is unchanged, and no response shape changed.

- **A keyword where a currency goes.** `stock-syntax-errors.ts` and `posting-syntax-errors.ts` report `syntax error, unexpected BOOL` (`NONE` for `NULL`) at the keyword, with the tokens stock expected there. This covers `ref: 1 TRUE-`, `1 TRUE-`, `{1 FALSE-}`, `@ 1 NULL-`, `commodity TRUE-`, both currencies of a `price`, and `balance`. A bare `TRUE` is reported where the engine reads it as a currency or drops it: after a posting's number, in an `open` list, after a metadata value's number, and `NULL` after a `custom` number. `ref: TRUE`, `custom "x" 1 TRUE`, `TRUE-1` and `TRUEX` stay clean.
- **A lone capital before anything but whitespace.** Stock's lexer reads a capital as a token only before a space, a tab or a line break. Anything else makes it an invalid token that runs to the next whitespace. That covers `{1 X}`, `{1 X, 2026-01-01}`, `X,USD`, `1 X;note`, `X:`, a lone capital ending a file with no line break, and one before a CRLF line's `\r`, which `bean-check` refuses too. A capital before whitespace, an account such as `X:Cash`, a futures `/X}`, and a capital in a string, a tag or a comment stay clean.
- **A token after a line's last field.** The engine skips the token; stock refuses it with `syntax error, unexpected <TOKEN>, expecting …`. This holds after a `close` account, an `event` or `query` line's two strings, a `commodity`, `pad`, `price`, `balance` or `open` line, a `note` or `document` line's tags, a `custom` line's values, a metadata value, and a posting's amount, cost or price. Examples are `close Assets:Cash USD`, `event "a" "b" USD`, `1 QAB -`, `1 QAB {1 USD} ,` and `{1 USD}}`. These lines are read token by token, the way stock's lexer reads them (`stockTokenAt`).
- **Recovery.** Some of these tokens the engine refuses itself: a tag on a `close`, a number or currency after a posting's amount, a cost the line never closes, an invalid token such as `^`, an operator that ends the line. Those are not reported a second time. Each still ends what stock reads of the directive, so no later line of it is reported, as stock drops the directive at its first error.
- **Checked against stock.** The comparison ran stock 3.2.3's parser on 15,000 random ledgers built around these constructs (12,400 of them refused by stock) and on the 126 tracked ledger fixtures. It compared the result with the HEAD code and with this change. There is no new difference: the change adds no error stock lacks and loses none the HEAD code had. Stock errors the service missed fell from 24,771 to 4,202, and ledgers whose errors match stock's exactly rose from 3,245 to 11,456. The 180 errors the service reported and stock did not (on later lines of directives stock had already dropped) fell to 0. No ledger reads clean where stock refuses it, and none is refused where stock accepts it. A 200,000-line ledger scans in about 195 ms on this machine, against 165 ms before.
- **Left alone.** These are reported where stock reports them only when the engine refuses them itself:
  - a token inside a directive's fields rather than after them (`event USD "a" "b"`, `{1 USD {`);
  - a comma or operator that ends a line (`open Assets:Cash USD,`, `ref: 1 -`), which stock refuses on the next line;
  - a lone capital glued to a string (`X"STRICT"`);
  - an invalid token other than those the scan already models;
  - undated lines (`pushmeta`, `option`).
- **Tests.** `stock-syntax-errors.test.ts` covers each keyword position, each lone-capital follower, each directive's trailing token, each kind of token, the controls, and the recovery rules. Every expectation was checked against stock's output for the same text. With the fix reverted, 81 of its tests fail. `verify-rustledger.ts` asserts that the raw engine still loads 8 repros clean, so each rule is load-bearing, that the service reports each at stock's line with `P0012`, and that the controls stay valid. The ledger README gains three rows in its table of stock errors the engine does not raise.
- **Gates.** In `backend-cluster/ledger`, `yarn lint`, `yarn typecheck`, `yarn build`, `yarn test` (239 suites, 4,417 tests) and `yarn verify:rustledger` pass.

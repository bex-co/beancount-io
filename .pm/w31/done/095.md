# `assertAmountsFitEngineDecimal` has silent-rounding bypasses (expressions, `balance ~`, `{per # total}`, `updateLedgerFiles` `old_string`/`new_string` fragments) and false-positive refusals (escaped quotes, multiline strings, org headings) across MCP, REST, and GraphQL

**Major · `backend-cluster/backend-v2` (`src/features/ledger/utils/engine-decimal.ts`, `src/features/ai-agent/tools/edit-ledger-files-tool.ts`) · 45–60m · A1.** `w23/done/081` added `assertAmountsFitEngineDecimal` to every raw Beancount text write (`appendLedgerText`, `createLedgerFiles`, `updateLedgerFiles`, `updateEntrySource`, REST `POST .../directives/text` / `PUT .../files/{*path}` / `PUT .../entry-source`, and their GraphQL twins) because the ledger engine's 28-digit `Decimal` silently rounds 29+ significant-digit literals while `bean-check` stays green. Two bugs in the implementation leave both silent financial rounding and valid-entry refusals live across all three surfaces:

1. **Silent-rounding bypasses in `engine-decimal.ts`:** `AMOUNT_IN_TEXT` only matches a number immediately followed by whitespace and a currency (`number CCY`). It misses valid Beancount numeric literals separated from their currency by arithmetic operators/parentheses (`(1.0000000000000000000000000001 + 0) USD`), `balance` tolerance (`200.00000000000000000000000001 ~ 0.01 USD`), or compound lot cost (`{1.0000000000000000000000000001 # 0 USD}`). All three return `200 OK` with `valid: true` and `errorsAfter: 0` on `dry_run` and commit silently rounded amounts across MCP, REST, and GraphQL.
2. **Fragment bypass in `updateLedgerFiles` (`edit-ledger-files-tool.ts:376`):** Exact-text replacements call `assertAmountsFitEngineDecimal(file.new_string)` before folding `old_string` → `new_string` into the file. Replacing only the numeric part while leaving `" USD"` on the line outside `old_string` produces zero matches in `file.new_string`: a 29-digit amount returns `valid: true` and commits rounded; a 32-digit amount bypasses `BAD_USER_INPUT` and hits `bean-check` with cascading `P0012`/`E3002` parse errors (and commits unparseable syntax under `allow_invalid: true`).
3. **False-positive refusals in `engine-decimal.ts`:** `textAmountLiterals` splits by `\n` and strips `QUOTED_SPAN = /"[^"\n]*"/g` without handling `\"` escapes, multiline Beancount strings, or org-mode headings (`* ...` at column 0). Valid entries whose narration/note/metadata or org heading contains a 29+ digit reference followed by a word (e.g. `"ref \" 123456789012345678901234567890 USD"`, a multiline string, or `* Ref 123456789012345678901234567890 USD`) are falsely refused with `BAD_USER_INPUT` across MCP, REST, and GraphQL.

## Expected

- Every Beancount numeric literal exceeding 28 significant digits or 28 fractional digits in code positions — including arithmetic expressions (`(a + b) USD`, `a * b USD`), `balance` amounts before `~`, compound cost legs (`{a # b USD}`), and the post-fold resulting lines of `updateLedgerFiles` `old_string`/`new_string` edits — is refused upfront with `BAD_USER_INPUT` naming the literal and the 28-digit limit across MCP, REST, and GraphQL.
- Digit sequences inside quoted strings (including strings with `\"` escapes and multiline strings), `;` comments, org-mode headings (`*` at column 0 outside strings), dates, tags, links, metadata keys, and account names are never treated as amounts and remain accepted.
- Untouched pre-existing lines in `updateLedgerFiles` continue to pass without being re-checked (preserving `w23/081`).

## Root cause

- `backend-cluster/backend-v2/src/features/ledger/utils/engine-decimal.ts:21-25, 61-71`: `QUOTED_SPAN = /"[^"\n]*"/g` runs per line after `text.split("\n")`, so `\"` terminates the span early, multiline strings lose string state at `\n`, and column-0 `*` org headings are not skipped. `AMOUNT_IN_TEXT` requires `\s+[A-Za-z]...` directly after each number, missing expression operands, `balance ... ~` amounts, and `{per # total}` cost legs.
- `backend-cluster/backend-v2/src/features/ai-agent/tools/edit-ledger-files-tool.ts:375-377`: calls `assertAmountsFitEngineDecimal(file.new_string)` on the raw fragment instead of on the post-fold lines changed by the `update` operation.

## Fix

In `backend-cluster/backend-v2`:

1. **Replace line-regex scanning in `src/features/ledger/utils/engine-decimal.ts`** with a stateful Beancount text scanner (following `directive-text.ts`'s `scanLine` and `account-rename.ts`):
   - Track double-quoted string state across lines respecting `\"` and `\\` escapes; strip `;` comments outside strings; skip org-mode heading lines (`*` at column 0 when not inside a string).
   - Outside strings/comments/headings, ignore dates (`YYYY-MM-DD` / `YYYY/MM/DD`), `#tags`, `^links`, account tokens, and metadata keys, and check every numeric literal in amount/expression/cost/balance contexts (e.g. numbers followed by whitespace + currency, `~`, `#`, or arithmetic operators/parentheses `+ - * / )` on a line carrying a currency or numeric metadata/directive context) with `fitsEngineDecimal`. Keep the `text.includes("\0")` binary skip.
2. **Validate post-fold changed lines in `src/features/ai-agent/tools/edit-ledger-files-tool.ts`**:
   - For `update` (`old_string`/`new_string`) operations, run `assertAmountsFitEngineDecimal` on the changed lines of the folded file content (computing string state from the start of the file so multiline strings stay accurate, while skipping untouched lines so pre-existing legacy long literals elsewhere in the file are not flagged). Keep upfront checks for `create` and `replace`.
3. **Add unit and 3-surface parity tests** in `engine-decimal.test.ts`, `edit-ledger-files-tool.test.ts`, `directive-text-parity.test.ts`, and `source-slice-parity.test.ts` covering:
   - arithmetic expressions `(1.000...1 + 0) USD`, `balance ... ~`, compound cost `{1.000...1 # 0 USD}`,
   - `updateLedgerFiles` `old_string`/`new_string` numeric-only replacement without currency in `new_string` (plus control verifying untouched legacy lines still pass),
   - escaped quotes `\"`, multiline strings, and `*` org-mode headings containing 30-digit numbers + `"USD"` all accepted.

# `appendLedgerText` ignores the ledger's `budget_file` option: a `custom "budget"` line goes to `default_file`, while the same budget sent through `addLedgerEntries` goes to the budget file, on MCP, REST and GraphQL

**Minor · backend-v2 (`src/features/ledger/utils/directive-text.ts`, `src/features/ledger/workflow/directive-append-workflow.ts`) · 30–45m · A1.** A ledger picks the file each kind of entry goes to with `custom "beancountio-option"` lines. `budget_file` is the one for budgets, and a Beancount budget is a `custom "budget"` directive. `docs/mcp.md` "Writing directives as Beancount text" says each directive "goes to the file the ledger's own `bcio` options assign its type and date", and that "the same applies to `addLedgerEntries`". The two tools disagree for budgets. `addLedgerEntries` sends a `budget` entry to `budget_file` and adds that file's include to `main.bean`. `appendLedgerText` sends the identical `custom "budget"` text to `default_file` (`main.bean`), so the budgets a user routed to their own file end up scattered through `main.bean`, and the preview does not say it ignored the option.

Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 LAND=1`) on 2026-11-27.

- **Target:** `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`). `yarn mcp:conformance --ledger` passed 19/19 and `qa-contract-replay.mjs` ran 16 probes with 0 mismatches in the same run. Production's backend-v2 is older than w31/104 (2026-11-26), but the classifier below has not changed since w2/m28, so local HEAD `a872b7db3` behaves the same and this is not deployment lag.
- **Credential:** an unpinned read/write `bcio_` key on the QA account.
- **Writes:** only to the designated QA ledger `<qa-owner>/mcp-agent-eval`: option commit `a99e58bd`, restore `d2013125`. `main.bean` was restored byte for byte (sha256 `77c3a591efd311e0`), and the check showed 0 errors afterwards.

## Repro (live)

1. `updateLedgerFiles` on `main.bean`: after `option "operating_currency" "USD"`, add `2000-01-01 custom "beancountio-option" "budget_file" "budgets.bean"`. The result is `valid: true`.
2. `addLedgerEntries {dry_run: true, entries: [{type: "budget", entry: {date: "2026-09-01", account: "Expenses:Food:Groceries", interval: "monthly", amount: {number: "400.00", currency: "USD"}}}]}`. The preview puts `2026-09-01 custom "budget" Expenses:Food:Groceries "monthly" 400.00 USD` in `budgets.bean`, and the summary says "main.bean would include budgets.bean". REST `POST …/entries {dryRun: true}` returns the same `preview` path.
3. `appendLedgerText {dry_run: true, text: "2026-09-01 custom \"budget\" Expenses:Food:Groceries \"monthly\" 400.00 USD"}`. The summary is "Would add 1 directive to main.bean. No new bean-check errors.", and the diff appends the line to the end of `main.bean`. REST `POST …/directives/text {dryRun: true}` and GraphQL `appendLedgerText(dryRun: true)` return the same `main.bean` diff.

Control: with the same option in place, a `note`, `open` or transaction goes to the same file on both tools, because their kinds map one to one.

## Cause

`appendLedgerText` routes each directive by the kind its header line gets in `directiveHead` (`directive-text.ts:317`). `DATED_KEYWORDS` (`directive-text.ts:253`–`266`) maps `custom` to `"Custom"`, whatever the custom's type. `resolveEntryFile` (`entry-file-resolver.ts:62`–`71`) routes `"Custom"` to `default_file` and only `"Budget"` to `budget_file`. The table's `budget: "Budget"` row never matches real text, because `2026-09-01 budget …` is not a Beancount directive. `addLedgerEntries` maps its typed `budget` entry to `"Budget"` (`ledger-entry-service.ts:422`), so only the text path loses the option. The append workflow already spots a `custom "budget"` header for its account check (`budgetAccountFromHeader`, `budget-account-check.ts:41`), but it does not use that for routing.

## Fix

Give a `custom "budget"` header the `"Budget"` kind (or route a `"Custom"` directive whose header is a budget as `"Budget"` in `directive-append-workflow.ts:147`), reusing the header reader the budget check uses. Drop the dead `budget: "Budget"` keyword. Other custom types keep going to `default_file`. MCP `appendLedgerText`, REST `POST …/directives/text` and GraphQL `appendLedgerText` share the workflow, so all three change together, and no response shape changes.

Done when, on a ledger with `budget_file` set, `appendLedgerText` puts a `custom "budget"` directive in the budget file (adding its include to `main.bean` when nothing loads it yet), both in the preview and in the commit, on MCP, REST and GraphQL, exactly as `addLedgerEntries` does. A parity test covers it and fails with the fix reverted, and a `custom "other"` line still goes to `default_file`.

---

**Resolved 2026-11-27**: `appendLedgerText` (MCP), REST `POST …/directives/text` and GraphQL `appendLedgerText` now send a `custom "budget"` directive to the ledger's `budget_file`, as `addLedgerEntries` does with the same budget. When nothing loads that file yet, the preview and the commit add its `include` to `main.bean`, and the message says so. Any other `custom` type still goes to `default_file`.

- **Fix (backend-v2).** `directiveHead` in `directive-text.ts` now gives a `custom` header whose type string is `"budget"` the `"Budget"` kind, which `resolveEntryFile` routes by `budget_file`. The dead `budget: "Budget"` keyword is gone, because Beancount has no `budget` directive. `extractDirectiveBudgetAccounts` now picks budgets by that kind, so the w31/094 account check covers exactly the directives it covered before. One side effect: a budget now counts as a different kind from other `custom` directives when the insertion point is chosen. A new budget that follows a non-budget `custom` therefore goes under the org headings after it, the way a transaction after an `open` already does. `docs/mcp.md` "Writing directives as Beancount text" now says budgets route by `budget_file`.
- **Tests.** In `directive-text-parity.test.ts`, the `budget_file` cases run on MCP, REST and GraphQL. Each previews and then commits a `custom "budget"` on a ledger with `budget_file: budgets.bean` and nothing including it. The diff and the commit must touch `budgets.bean` plus the `include` in `main.bean`, and `main.bean` must hold no budget line. A second case sends one budget through the typed `addBulkEntries` path and through `appendLedgerText` and requires the same `budgets/{year}.bean` target from both. A third keeps a `custom "other"` line in `main.bean`. `directive-text.test.ts` pins the classifier: `custom "budget"` with a space or a tab is a budget, while `custom "budgets"`, `custom "other" "budget"` and `query "budget"` are not. With the fix reverted, 5 of these cases fail. The file now resets the process-wide rate limiter before each test. Its MCP commits had been sharing one 60-a-minute write budget, so the next MCP write test added would have been refused as `RATE_LIMITED`.

Gates: `backend-cluster/backend-v2`: `yarn typecheck`, `yarn test` (510 suites, 13,632 tests), `yarn lint:deadcode`, `yarn format:check` and ESLint on the changed files pass. `yarn generate-v1-openapi` produces no drift.

**Not observable yet.** Production keeps the old routing until backend-v2 is redeployed.

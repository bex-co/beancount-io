# `setBankAccountCurrency` (`PUT .../currency`, `updatePlaidAccountCurrency`) and `mapBankAccount` (`PUT .../mapping`, `updatePlaidAccountMapping`) accept empty, whitespace-only, and invalid `currency` / `ledgerAccount` values instead of refusing with `BAD_USER_INPUT`

**Minor · backend-v2 (`PlaidItemService.updateAccountCurrency`, `PlaidItemService.updateAccountMapping`) · 35–45m · A1.** Passing empty (`""`), whitespace-only (`"   "`), or syntactically invalid values for `currency` (`"usd"`, `"123"`, `"not a currency"`) or `ledgerAccount` (`"not-an-account"`, `"Assets:Bad Account"`) passes schema and service validation across MCP, REST, and GraphQL, proceeding through PDP authorization, Fava ledger lookup, and Postgres account/item queries (returning `NOT_FOUND` for an unknown `accountId`, or persisting corrupt `currency`/`ledger_account` strings onto a real `plaid_accounts` row that `buildBeancountTransaction` later emits verbatim into Beancount directives and breaks every `importStagedBankTransactions` call). Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`) on 2026-11-23 against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, checked against HEAD `86c204acf`). Credential: unpinned read/write/admin `bcio_` key on the QA account (`<qa-owner>/mcp-agent-eval`); read-only probes only, no ledger or bank state modified.

## Working controls

- On the same two tools, passing `accountId: ""` or `"   "` is refused before authorization and DB lookup with `BAD_USER_INPUT` (`accountId must not be empty`, via `assertBankId`).
- A `ledger.read` key calling `setBankAccountCurrency` with valid `currency: "USD"` is refused with `FORBIDDEN` (`This operation requires the "ledger.admin" scope`).
- The dashboard UI (`dashboard/src/features/plaid/pages/plaid-connections/components/account-mapping-form.tsx:128`) already rejects empty/whitespace `ledgerAccount` client-side (so `""` is never used to clear a mapping) and selects accounts and currencies from comboboxes.

## Root cause

Not deployment lag — present at HEAD `86c204acf`:

- `backend-cluster/backend-v2/src/features/plaid/service/plaid-item-service.ts:1062-1092` (`PlaidItemService.updateAccountMapping`): delegates straight to `this.authorizedAccount(...)` (which only validates `accountId` via `assertBankId`) and writes `ledgerAccount` unvalidated into `plaid_accounts.ledger_account` (`updateForItem(..., { ledgerAccount })`).
- `backend-cluster/backend-v2/src/features/plaid/service/plaid-item-service.ts:1094-1124` (`PlaidItemService.updateAccountCurrency`): delegates straight to `this.authorizedAccount(...)` and writes `currency` unvalidated into `plaid_accounts.currency` (`updateForItem(..., { currency })`).
- Both fields are later emitted directly into Beancount postings by `buildBeancountTransaction` (`backend-cluster/backend-v2/src/features/plaid/utils/plaid-mapper.ts:43-58`), so a blank, space-containing, lowercase, or malformed value stored on a real account breaks every subsequent `importStagedBankTransactions` call.
- Neither the MCP schemas (`backend-cluster/backend-v2/src/features/ai-agent/tools/bank-import-tool.ts:302-309,334`), REST schemas (`backend-cluster/backend-v2/src/features/ledger/api/rest/v1/banks-handler.ts:379,400`), nor GraphQL resolver (`backend-cluster/backend-v2/src/features/plaid/api/resolvers/plaid-resolver.mutation.ts:127-159`) validate `ledgerAccount` or `currency` beyond `string`.

## Fix

In `backend-cluster/backend-v2`:

1. Validate `ledgerAccount` at the entry of `PlaidItemService.updateAccountMapping` (`src/features/plaid/service/plaid-item-service.ts:1062`), before `this.authorizedAccount(...)`, using the existing Beancount account-token rule `lexesAsAccount` from `@/features/ledger/utils/account-matcher` (so valid Beancount accounts including hosted non-Latin names like `Assets:Bank:日本` stay accepted, while `""`, `"   "`, `"not-an-account"`, `"Assets:Bad Account"`, single-segment `"Assets"`, lowercase `"assets:checking"`, and control characters/newlines are refused with `BadUserInputError`, field `"ledgerAccount"`, and a hint giving an example such as `"Assets:Bank:Checking"`).
2. Validate `currency` at the entry of `PlaidItemService.updateAccountCurrency` (`src/features/plaid/service/plaid-item-service.ts:1094`), before `this.authorizedAccount(...)`, against Beancount's commodity grammar `/^[A-Z](?:[A-Z0-9'._-]{0,22}[A-Z0-9])?$/` (matching `src/features/ledger/workflow/legacy-posting-amount.ts:8` — accepts `USD`, `EUR`, `CAD`, `USDC`, `MUSD`, `VBTLX`, `A1B`, `V`, etc.; refuses `""`, `"   "`, lowercase `"usd"`, `"123"`, spaces, control characters, and over-24-char strings with `BadUserInputError`, field `"currency"`, and a hint giving an example such as `"USD"` or `"EUR"`).
3. Add unit tests in `src/features/plaid/service/__tests__/plaid-item-service.test.ts` and 3-surface adapter parity tests in `src/features/ai-agent/api/__tests__/bank-item-read-parity.test.ts` (or `bank-empty-id-parity.test.ts`, adding REST coverage alongside MCP and GraphQL) covering empty, whitespace-only, and malformed `currency` and `ledgerAccount` across MCP (`setBankAccountCurrency`, `mapBankAccount`), REST (`PUT .../bank-accounts/{accountId}/currency`, `PUT .../bank-accounts/{accountId}/mapping`), and GraphQL (`updatePlaidAccountCurrency`, `updatePlaidAccountMapping`), asserting `BAD_USER_INPUT` and zero calls to authorization, Fava, or Postgres.
4. Keep existing valid calls (including non-ASCII account leaves and multi-character Beancount commodities) working, and keep `FORBIDDEN` before lookup when a caller lacks bank authority and passes valid inputs (`bank-item-read-parity.test.ts`). If `banks-handler.ts` Zod schemas are also tightened, regenerate `docs/openapi/v1.json` and re-pin `cli/openapi/v1.json` (`make spec-sync && make codegen` in `cli/`) in the same change.

# `check_drained` and `commodity_attr` errors carry no file or line, and `commodity_attr` reads in other words than stock's and ignores a config that is not a dict, which stock reports (w21/740 sibling)

**Minor · ledger (`src/foundation/rustledger/engine.ts`, beside the w21/740 reconcilers) · 30–40m · A1.** w21/740 placed the errors of five built-in plugins where Beancount places them and gave them Beancount's words. Two more plugins still come back unlocated from `@rustledger/wasm` 0.24.0, so `checkLedger`, the `errors` resource and every write preview list them with no `source`, and an agent cannot tell which line to fix:

## Repro (live)

Insert each fixture after the ledger's last line with `updateLedgerFiles` `dry_run: true` (old_string the last line, new_string that line plus the fixture). The first three preview `valid: false` with one `newErrors` entry whose `source` is absent, worded as the hosted column says. The fourth previews `valid: true`. Stock 3.2.3 on the same projected file gives the stock column, at line 90, the fixture's `close` or `commodity` line.

## Cause

The engine raises both plugins' findings with `file: null` and `line: null`. For `check_drained` the error belongs to the zero `balance` it synthesizes the day after the close. The ledger has a placing reconciler for `leafonly`, `noduplicates`, `coherent_cost`, `onecommodity` and `unique_prices` (w21/740, `engine.ts:855-880`), and none for these two. The engine's `commodity_attr` also skips a config it cannot read, where stock adds a `ConfigError`.

## Fix

Add the two plugins to the w21/740 pattern. Do not re-implement either plugin; place and reword what the engine reports.

- `check_drained` (declared, or through `pedantic` once w31/155 runs it there): put each balance error on the line of the `close` it came from, in stock's words.
- `commodity_attr`: put each error on its `commodity` line in stock's two messages, and report `Invalid configuration for commodity_attr plugin; skipping.` when the config does not read as a dict, as w21/739's `check_commodity` reconciler does for its own config (`check-commodity.ts`).

No response shape changes; every surface reads these errors from the one ledger path.

**Resolved 2026-11-27** — The ledger service now places and rewords both plugins' errors as stock `bean-check` 3.2.3 does, without running either plugin itself. The first three fixtures preview `valid: false` with stock's message at the fixture's `close` or `commodity` line, and `"[1, 2]"` previews `valid: false` with `Invalid configuration for commodity_attr plugin; skipping.`, unlocated as stock's `<commodity_attr>:0`. No response shape changed.

- **`check_drained`** (`check-drained.ts`). Declared by name or through `pedantic`, each of the engine's zero-balance failures for a closed account reads `Balance failed for 'A': expected 0 USD != accumulated 49.75 USD (49.75 too much)` (or `too little`), on the line of the account's written close, in whichever file it is. A close that `close_tree` made stays unlocated, as stock's `<beancount.plugins.close_tree>:0`. It runs after the unused-pad recheck, whose second run reports the engine's words again.
- **`commodity_attr`** (`commodity-attr.ts`). `Missing attribute 'name' for Commodity directive QAX` and `Invalid value 'Energy' for attribute sector, Commodity directive QAX; valid options: Tech` sit on the `commodity` line. The value is read from the booked stream and printed as Python prints it (`5.10`, `True`, `10.00 USD`), not the engine's `Number("5.10")`. An empty value is missing, and an empty list checks nothing, as in stock. A config is reported when it does not read as a dict.
- **Known errors.** Both write gates (the ledger's `newLedgerErrors`, backend-v2's `diffBeanCheckErrors`) leave out the `accumulated …` figure, as they leave out `got …`, so a write elsewhere, or one that drains part of the closed account, is not refused for the error the ledger already had. `backend-v2/docs/mcp.md` says so.
- **Still different.** A written balance on the close date makes stock skip its own zero balance; the engine still checks it. A `commodity_attr` with no config, or one Python cannot evaluate, makes stock fail with a traceback; the first reads clean here and the second gets the configuration error. The `valid options` order follows the config (stock's comes from a frozenset and varies between runs).
- **Tests.** `plugin-locations.test.ts` covers both reconcilers. `new-ledger-errors.test.ts` and backend-v2's `bean-check-errors.test.ts` cover the matcher. `scripts/drained-and-attr-errors.ts` (run by `yarn verify:rustledger`) checks each row against stock 3.2.3 on the live engine, plus a drained close, a present and allowed attribute, and writes elsewhere. The w31/155 `pedantic` cases now expect the close line. Each fails with its part of the fix reverted.
- **Gates.** `backend-cluster/ledger`: `yarn lint`, `yarn typecheck`, `yarn test` (239 suites, 4,309 tests) and `yarn verify:rustledger` pass. `backend-cluster/backend-v2`: `yarn typecheck`, `yarn lint:deadcode`, `yarn format:check` and `yarn test` (510 suites, 13,698 tests) pass. The hosted repro against `beancount.io` waits for the next ledger and backend-v2 deploy.

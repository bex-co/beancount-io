# `prNumber` accepts empty string (`?prNumber=` -> `0`), `0`, and negative integers on MCP, REST, and GraphQL instead of refusing with `BAD_USER_INPUT`

**Minor · backend-v2 (pull-request input validation) · 30m · A1.** Passing an empty, zero, or negative `prNumber` skips input validation, sends bogus PR numbers (`0`, `-1`) to Gitea, and returns `NOT_FOUND` instead of `BAD_USER_INPUT` across MCP, REST, and GraphQL. Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 LAND=1`) on 2026-11-23 against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, checked against HEAD `ad0ad3afa`). Credential: unpinned read/write/admin `bcio_` key on the QA account. Synthetic ledger: `<qa-owner>/mcp-agent-eval`.

## Repro (live)

Reproduced in fresh requests across all three surfaces against `<qa-owner>/mcp-agent-eval`:

1. **MCP resource `beancount://<qa-owner>/mcp-agent-eval/pull-request?prNumber=` (empty string), `?prNumber=0`, `?prNumber=-1`**:
   ```sh
   node .agents/skills/qa-shared/scripts/qa-mcp.mjs read 'beancount://<qa-owner>/mcp-agent-eval/pull-request?prNumber='
   node .agents/skills/qa-shared/scripts/qa-mcp.mjs read 'beancount://<qa-owner>/mcp-agent-eval/pull-request?prNumber=0'
   node .agents/skills/qa-shared/scripts/qa-mcp.mjs read 'beancount://<qa-owner>/mcp-agent-eval/pull-request?prNumber=-1'
   ```
   Actual: HTTP `200`, JSON-RPC `-32002` `NOT_FOUND: Pull request with ID '0' not found` (empty string coerced to `0`) / `'-1'`.
2. **MCP tools `mergePullRequest` / `rejectPullRequest`**:
   ```sh
   node .agents/skills/qa-shared/scripts/qa-mcp.mjs call mergePullRequest '{"ledger":"<qa-owner>/mcp-agent-eval","prNumber":0}'
   node .agents/skills/qa-shared/scripts/qa-mcp.mjs call rejectPullRequest '{"ledger":"<qa-owner>/mcp-agent-eval","prNumber":-1}'
   ```
   Actual: HTTP `200`, `isError: true`, `NOT_FOUND: Pull request with ID '0' not found` / `'-1'`.
3. **REST `GET /api-gateway/v1/ledgers/<qa-owner>/mcp-agent-eval/pull-requests/0` (and `/-1`), `POST .../pull-requests/0/approve`, `POST .../pull-requests/-1/reject`**:
   Actual: HTTP `404` `NOT_FOUND` (`Pull request with ID '0' not found` / `'-1'`).
4. **GraphQL `getPullRequestDetails(prNumber: 0)`, `approvePullRequest(prNumber: -1)`, `rejectPullRequest(prNumber: 0)`**:
   Actual: `errors[0].extensions.code: "NOT_FOUND"`, `Pull request with ID '0' not found` / `'-1'`.

Expected: refused with `BAD_USER_INPUT` naming `prNumber` (positive integer >= 1) without calling Gitea — matching how `ledgerRepoId` and `keyId` already behave.

## Working controls

- MCP `beancount://assets/download-url?ledgerRepoId=&filename=a.png` returns JSON-RPC `-32602` `BAD_USER_INPUT: ledgerRepoId: Too small: expected number to be >0` (`asset-url-handler.ts:7` uses `z.coerce.number().int().positive()`).
- `public-keys-handler.ts:23` uses `keyId: z.coerce.number().int().positive()`.
- Omitting `prNumber` on MCP `pull-request` returns `BAD_USER_INPUT: prNumber is required`; passing `?prNumber=1.5` returns `BAD_USER_INPUT: prNumber: Invalid input: expected int, received number`.

## Root cause

Not deployment lag — present at HEAD `ad0ad3afa`:

- `backend-cluster/backend-v2/src/features/gitea/pull-request/api/pull-request-routes.ts:32-34` (`pullRequestNumberQuery`) and `:71` (`path`) define `prNumber: z.coerce.number().int()` with no `.positive()` / `.min(1)`. Because `Number("") === 0`, an empty query value `?prNumber=` coerces to `0` and passes schema validation, as do `0` and negative integers.
- `backend-cluster/backend-v2/src/features/ai-agent/api/mcp-pull-requests.ts:19` (`reviewInput`) defines `prNumber: z.number().int()` with no `.positive()`.
- `backend-cluster/backend-v2/src/features/gitea/pull-request/service/pull-request-service.ts:531,616,710` (`getPRDetails`, `mergePR`, `closePR`) perform no `prNumber >= 1` guard before issuing Gitea calls (3 parallel calls in `getPRDetails`, 2 calls in `mergePR`), so GraphQL `Int` (`0`, `-1`) also reaches Gitea and comes back `404` -> `NOT_FOUND`.

## Fix

In `backend-cluster/backend-v2`:

1. Add `.positive()` (or `.min(1)`) to `prNumber` in `pullRequestNumberQuery` and `path` (`src/features/gitea/pull-request/api/pull-request-routes.ts:33,71`) and `reviewInput` (`src/features/ai-agent/api/mcp-pull-requests.ts:19`).
2. Guard `!Number.isInteger(prNumber) || prNumber < 1` in `PullRequestService` (`getPRDetails`, `mergePR`, `closePR` in `src/features/gitea/pull-request/service/pull-request-service.ts`) throwing `BadUserInputError("prNumber must be a positive integer", "prNumber")` before contacting Gitea, so GraphQL `getPullRequestDetails`, `approvePullRequest`, and `rejectPullRequest` enforce the exact same refusal.
3. Update all three surfaces (MCP resource + tools, REST routes, GraphQL queries/mutations) together, regenerate `docs/openapi/v1.json` (and sync `cli/openapi/v1.json` + CLI client if the v1 OpenAPI spec changes), and add unit + 3-surface parity tests covering `""`, `0`, and `-1`.

# A `filter` word holding `.`, `&` or `!` (`ACME.CORP`, `AT&T`, `flag:!`) is refused `Illegal character "."` with no fix, and the leading-digit hint quotes only the digits (`payee:7eleven` → `payee:"7"`), on MCP, REST and GraphQL

**Minor · ledger (`src/foundation/rustledger/directive-filter.ts`), backend-v2 (`src/features/ledger/utils/journal-filter-description.ts`, `docs/mcp.md`) · 20–30m · A1.** Found by `/loopx w31` routine `mcp-qa` on 2026-11-27, against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`), with an unpinned read/write QA key on the synthetic `mcp-agent-eval` ledger (its text is `backend-cluster/backend-v2/evals/mcp-agent/fixtures/main.bean`). Read-only. Reproduced at HEAD `019ab150b` by running `filterDirectives` on the same text.

Payees with a dot, an ampersand or a bang are common: `Amazon.com`, `U.S. Bank`, `AT&T`, `H&M`, and `!` is the pending flag. An agent that follows the published quoting rule writes these bare, is refused, and is not told how to fix the call.

**Repro.** `listLedgerEntries {"ledger": "<qa-owner>/mcp-agent-eval", "filter": F, "limit": 1}`. REST `GET /api-gateway/v1/ledgers/{owner}/{name}/journal?filter=F` returns the same text with a 400. GraphQL `getLedgerJournal(query: {filter: F})` returns it as `BAD_USER_INPUT`.

| `F` | message |
| --- | --- |
| `ACME.CORP`, `payee:TRADER.JOES`, `narration:3M.Co` | `Illegal character "."` |
| `AT&T` | `Illegal character "&"` |
| `flag:!` | `Illegal character "!"` |
| `Rent$` | `Illegal character "$" — quote the value to search for it, e.g. "$"` |
| `payee:7eleven` | `Unexpected 7 after "payee:" — quote values starting with a digit, e.g. payee:"7"` |
| `"ACME.CORP"` (control) | 2 entries |

- Every MCP refusal carries the generic hint "Fix the named argument and call again", but none of these messages names an argument. Stock Fava 1.30, and the vendored copy the CLI keeps (`cli/src/fava/core/filters.py:52`), say `Illegal character "." in filter.`
- Where there is a hint, it echoes a fragment. Following `e.g. payee:"7"` literally gives `payee:"7"eleven`, which parses as `payee:"7"` AND a bare `eleven`: a different filter, accepted without a word. `e.g. "$"` turns `Rent$` into `Rent"$"`.
- The `filter` description that every journal surface publishes (`journal-filter-description.ts:19`, and `docs/mcp.md:1356`) says to "Quote values holding a colon, a space, or a leading digit". It does not mention any other punctuation.

**Cause.**
- `lex` (`directive-filter.ts:463-470`) adds the quoting hint only when the refused character is a letter, mark, number or symbol (`\p{L}\p{M}\p{N}\p{S}`, from w1/215). Punctuation (`\p{P}`: `.`, `&`, `!`, `*`, `/`, `@`, `%`, `?`, `;`, `[`) gets the bare message. Either way the example is the character alone.
- `throwForMistakableValue` (`:689`) builds its example from `upcoming.value`, which is only the NUMBER token.

**Fix.**
- Keep each message's current prefix, because the dashboard's classifier matches on it (`dashboard/src/common/lib/errors/error-message.ts:71`). Add the rest after it.
- For every character the bare-word rule refuses, other than the grammar's own `-`, `,`, `(`, `)` and the quotes, the message names `filter`. It says to quote the whole value and echoes the whole word that holds the character, with a `key:` prefix kept outside the quotes. For example: `Illegal character "." in filter — quote the whole value, e.g. "ACME.CORP"`, or `… e.g. narration:"3M.Co"`.
- The leading-digit hint echoes the whole value: `payee:"7eleven"`.
- The published description and `docs/mcp.md` give the actual rule: quote a value that holds anything but letters, digits, `_` and `-`. Regenerate `docs/openapi/v1.json` with `yarn generate-v1-openapi`, and re-sync the CLI's pinned copy if the description reaches it.
- What parses does not change. Fava 1.31 reads a bare `ACME.CORP`, but the CLI's vendored filter keeps the older grammar, so the refusal stays and only its words change.
- Tests: `directive-filter.test.ts` cases for `ACME.CORP`, `AT&T`, `flag:!`, `narration:3M.Co` and `payee:7eleven` assert the new messages. The dashboard's `error-message.test.ts` still classifies each one as a filter error. Revert the fix and watch the new cases fail.

**Done when** each `F` in the table is refused with a message that names `filter` and quotes the whole value, on MCP, REST and GraphQL (one evaluator serves all three). Following that example returns the control's 2 entries for `ACME.CORP`. The published `filter` description names punctuation.

**Blast radius.** One lexer serves every `filter` argument: MCP `listLedgerEntries`, the journal, account-journal, statement, overview, events, documents, entries-count and postings-per-account resources, their REST routes, the GraphQL journal and report inputs, and the dashboard's header filter. Mobile sends a pre-quoted filter (`plain-search-filter.ts`), so it does not hit this. The `time` refusal already names its argument and a form (`Failed to parse date: … — time takes …`).

**Dedupe.** Searched `.pm/**` for `Illegal character`, `Unexpected end of filter`, `Trailing tokens`, `7eleven` and `named argument`.
- w1/215 added the quoting hint for letters and marks only.
- w23/m2 (t003, t005, t006) added the quote and leading-digit hints.
- w2/101 taught the dashboard classifier the newer prefixes. Its "Adjacent" section noted that the digit hint quotes only the token, but no follow-up was filed.
- w21/149 made mobile quote payees.
- w31/137 is the same naming gap for file paths.

None of these is open.

---

**Resolved 2026-11-27** — The ledger's filter lexer now names `filter` in every illegal-character refusal and quotes the whole word that holds the character back, with a `key:` prefix outside the quotes and a leading `-` (negation) left off: `ACME.CORP` → `Illegal character "." in filter — quote the whole value, e.g. "ACME.CORP"`, `narration:3M.Co` → `e.g. narration:"3M.Co"`, `flag:!` → `e.g. flag:"!"`, `Rent$` → `e.g. "Rent$"` (`illegalCharacterError` in `directive-filter.ts`). The leading-digit hint echoes the whole value from the source text: `payee:7eleven` → `Unexpected 7 after "payee:" in filter — quote the whole value when it starts with a digit, e.g. payee:"7eleven"`. Quoting would be wrong in two cases, so they get their own fix: a comparison (`amount>$5`) says `a comparison takes a plain number, e.g. >100`, and a stray blank such as a no-break space says `separate terms with plain spaces`. A character outside the Basic Multilingual Plane (an emoji) is now shown whole instead of half a surrogate pair. Every message keeps its prefix, so the dashboard still classifies each one as a filter error (`error-message.test.ts`). What parses is unchanged. The shared `filter` description (`journal-filter-description.ts`) and `docs/mcp.md` now give the rule: quote a value that starts with a digit or holds anything but letters, digits, `_` and `-`. `docs/openapi/v1.json`, the CLI's pinned spec and its generated REST client are regenerated. `directive-filter.test.ts` runs every repro row and checks that its example returns the expected entries (`"ACME.CORP"` → 2). With the fix reverted, 15 cases fail. One evaluator serves MCP, REST and GraphQL, so all three carry the new text. The dashboard's and mobile's generated GraphQL doc comments pick up the new description at their next codegen, which reads a live gateway.

Shipped in the commit carrying this note (`backend-cluster/ledger`, `backend-cluster/backend-v2`, `cli`, `dashboard`).

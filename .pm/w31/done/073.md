# `GET /api-gateway/mcp/archive/{owner}/{name}/{archive}` ignores unknown query parameters and skips `assertNoNulDeep` (accepting `?bogus=1` and `?a=%00` with `200 OK`)

**Minor · backend-v2 (`src/features/ai-agent/api/mcp-archive-route.ts`) · 25–35m · A1.** The streaming archive route under the MCP resource (`GET /api-gateway/mcp/archive/{owner}/{name}/{archive}`, ADR 0007 amendment) is mounted directly on Koa `router.get(...)` instead of `v1Route` / `zodValidator`, and never checks `ctx.query` or runs `assertNoNulDeep`. Sending unknown query parameters (`?bogus=1`) or a NUL byte in the query string (`?a=%00`) returns `200 OK` and streams the full archive instead of refusing with `400`, breaking parity with both REST `GET /api-gateway/v1/ledgers/{owner}/{name}/archive/{archive}` and the MCP resource `beancount://{owner}/{name}/archive/{archive}`. Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`) on 2026-11-23 against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, verified at HEAD `69d4680b6`). Credential: unpinned read/write/admin `bcio_` key on the QA account. Synthetic ledger: `<qa-owner>/mcp-agent-eval` (read-only for this finding).

## Repro (live)

Authenticated with a `bcio_` key holding `ledger.read` (repeated in fresh requests):

- `GET https://beancount.io/api-gateway/mcp/archive/<qa-owner>/mcp-agent-eval/main.zip?bogus=1`
  - Actual: `200 OK`, `content-type: application/octet-stream`, `cache-control: private, no-store`, 1,127-byte ZIP body.
- `GET https://beancount.io/api-gateway/mcp/archive/<qa-owner>/mcp-agent-eval/main.zip?a=%00`
  - Actual: `200 OK`, `content-type: application/octet-stream`, 1,127-byte ZIP body.

Working controls (same credential, same ledger):
- REST `GET https://beancount.io/api-gateway/v1/ledgers/<qa-owner>/mcp-agent-eval/archive/main.zip?bogus=1` → `400` `{"ok":false,"error":{"code":"VALIDATION_FAILED","message":"Validation failed for query: Unrecognized key: \"bogus\"","metadata":{"field":"query","reason":"Unrecognized key: \"bogus\""}}}`.
- REST `GET https://beancount.io/api-gateway/v1/ledgers/<qa-owner>/mcp-agent-eval/archive/main.zip?a=%00` → `400` `{"ok":false,"error":{"code":"BAD_USER_INPUT","message":"a must not contain a NUL (U+0000) character","metadata":{"field":"a"}}}`.
- MCP resource `beancount://<qa-owner>/mcp-agent-eval/archive/main.zip?bogus=1` → JSON-RPC `-32602` `BAD_USER_INPUT`: `Unknown or repeated resource parameter: bogus`.

Expected:
- `GET /api-gateway/mcp/archive/{owner}/{name}/{archive}` enforces the same argument boundary as the v1 REST archive route and the MCP archive resource: query strings containing NUL or unpaired surrogates are refused with `400 BAD_USER_INPUT`, and any unexpected query parameter is refused with `400` (`BAD_USER_INPUT` or `VALIDATION_FAILED`) naming the key(s) before contacting the repository host.

## Root cause

Not deployment lag — present at HEAD `69d4680b6`:

- `backend-cluster/backend-v2/src/features/ai-agent/api/mcp-archive-route.ts:33-77` reads only `ctx.params` (`owner`, `name`, `archive`) and never validates `ctx.query` or calls `assertNoNulDeep` on `ctx.query` / `ctx.params`.
- By contrast, `v1Route` (`src/server/rest/v1-route.ts`) defaults `query` to `z.object({}).strict()` and runs `assertNoNulDeep` via `zodValidator` on `GET /api-gateway/v1/ledgers/{owner}/{name}/archive/{archive}` (`src/features/ledger/api/rest/v1/archive-handler.ts:23-30`), and `QueryResourceTemplate.match` (`src/features/ai-agent/api/mcp-resource-template.ts:88-98`) + `makeMcpResourceHandler` (`src/server/api/composition-root.ts:1232`) enforce both rules on `beancount://{owner}/{name}/archive/{archive}`.

## Fix

In `backend-cluster/backend-v2`:

1. In `src/features/ai-agent/api/mcp-archive-route.ts`, after authentication, read-capability check, and `enforceRateLimit` (matching `v1Route`'s gate order), run `assertNoNulDeep(ctx.query)` and `assertNoNulDeep(ctx.params)` and reject any non-empty `ctx.query` (e.g. via `z.object({}).strict().parse(ctx.query)` or throwing `BadUserInputError` naming the unrecognized query key(s)) before calling `layers.services.ledgerArchive.download`.
2. Add regression tests in `src/features/ai-agent/api/__tests__/mcp-archive-route.test.ts` verifying that `?bogus=1` and `?a=%00` (and an unpaired surrogate or bare `?` with keys) return `400` without issuing an upstream archive request (`origin.requests` stays empty), while bare `/main.zip` continues to stream normally.

- Scoped to `GET /api-gateway/mcp/archive/:owner/:name/:archive` (the only streaming route outside `v1Route` under `/api-gateway/mcp`).
- Adjacent states: unauthenticated and browser-session requests still receive `401` + `WWW-Authenticate` before query inspection; missing `ledger.read` scope still gets `403`; pinned-ledger violation still gets `403`; bare `?` with no parameters or clean path continues to return `200` with `Cache-Control: private, no-store`; `main.tar.gz` and uppercase owner segments keep working.

# `assertCommitRef` allows line breaks (`\n`, `\r`) in `sha` / `branch` / `branchName`, silently truncating multi-line refs at `\n` on Gitea and resolving `main` (including `revertCommit`) across MCP, REST, and GraphQL (gap in `w31/024`, `w31/061`)

**Major · backend-v2 (`assertCommitRef` in `src/shared/commit-ref.ts`) · 25–35m · A1.** `assertCommitRef` (`src/shared/commit-ref.ts:25-34`) rejects ASCII space (`" "`) outside `@{…}` / `^{…}` / leading `:/`, but explicitly leaves newlines to Gitea (`commit-ref.ts:18-20`, `commit-ref.test.ts:23`) under the assumption that Gitea merely ignores a trailing newline. In reality, Gitea's line-oriented git ref lookup splits on `\n`: any ref containing `\n` — such as `"main\nfoo"`, `"<sha>\nextra"`, or `":/restore\nfoo"` — silently discards everything from the first `\n` onward and resolves the first line as `200 OK`. Across MCP, REST, and GraphQL, `"main\nfoo"` returns `main`'s commit on `commit-details`, `commits`, and `latest-commit`, and on the destructive `revertCommit` (`revert-commit` / `revertLedgerCommit`) previews (and would commit) a revert of `main` instead of refusing the malformed ref with `BAD_USER_INPUT`. ## Root cause

Not deployment lag — present at HEAD `40e22400b`:

`backend-cluster/backend-v2/src/shared/commit-ref.ts:18-34`:

```ts
 * Other whitespace is left to the host: it already answers a tab with
 * NOT_FOUND and ignores a trailing newline.
...
export function assertCommitRef(ref: string, parameter: string): void {
  const outsideGroups = ref.replace(/[@^]\{[^}]*\}/g, "{}");
  if (!outsideGroups.startsWith(":/") && outsideGroups.includes(" ")) {
    throw new BadUserInputError(
      `${parameter} must not contain a space: no branch name or commit SHA holds one`,
      parameter,
      COMMIT_REF_SPACE_HINT,
    );
  }
}
```

1. `assertCommitRef` never checks for `\n` or `\r` (neither outside nor inside `@{…}` / `^{…}` / `:/`).
2. `src/shared/__tests__/commit-ref.test.ts:23` pins `"b6d69fd\n"` as an allowed pass-through ref because Gitea appeared to "ignore a trailing newline", when in fact Gitea's line-delimited git ref lookup splits on `\n` and silently drops all characters after the first `\n`.

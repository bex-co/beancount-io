# Deleting or renaming a document file previews "No new bean-check errors" and commits past the gate; the commit then reports `Document root … does not exist` and `Document file not found`

**Minor · ledger (write-gate projection) · 30–45m · A1.** The preview rule promises that a write which adds bean-check errors is refused `VALIDATION_FAILED` unless `allow_invalid` is set. For a write that removes a document file, the dry run says `valid: true`, the commit lands without `allow_invalid`, and only the commit's own summary admits "2 new bean-check errors". Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`, run 23, the post-deploy regression sweep of the w31 fixes) on 2026-11-15, against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, `revision: unknown`, see `w31/002`; no deploy since run 22, manifest hash `d12d8f03`). The credential was an unpinned read/write/admin `bcio_` key on the QA account. Writes went only to the designated QA ledger `<qa-owner>/mcp-agent-eval`. Probe files were deleted and `main.bean` was restored byte for byte afterwards (blob `f1a0b83c`), and the check is clean.

## Repro (live)

1. `createLedgerFiles` with `qa-docs/Assets/Cash/2026-09-01.qa.txt` (the only file under the root) and `qa-ref.txt`.
2. Add `option "documents" "qa-docs"` and `2026-10-05 document Assets:Cash "qa-ref.txt"` to `main.bean`. This previews and commits clean. `checkLedger` is `[]`, and the `documents` resource lists the discovered `qa-docs/…/2026-09-01.qa.txt` and the explicit `qa-ref.txt`.
3. Each of these dry runs answers `valid: true`, "No new bean-check errors":
   - `deleteLedgerFiles [{path: "qa-docs/Assets/Cash/2026-09-01.qa.txt"}]`
   - `deleteLedgerFiles [{path: "qa-ref.txt"}]`
   - `renameLedgerFile` of either file to another folder or name
   - REST `DELETE …/files/qa-ref.txt` with body `{dryRun: true}` answers 200 `valid: true, newErrors: []`
4. Commit `deleteLedgerFiles` of both files with no `allow_invalid`. It is **not** refused. The answer is `ok: true`, "Committed 2 change(s) … 2 new bean-check errors: Document root 'qa-docs' does not exist (main.bean:6)", `valid: false`.
5. `checkLedger` and REST `GET …/errors` then return `E7006 Document root 'qa-docs' does not exist` and `E8001 Document file not found: qa-ref.txt (main.bean:241)`.

**Controls:** every other projected check in the same run gated correctly. That includes a glob include whose last match is deleted ("does not match any files", `valid: false`), a missing root spelled in `main.bean` (w31/021), and the w31/022 include walk. Stock Beancount 3.2.3 reports both errors on the post-delete files.

## Cause

- `projectFileMap` (`backend-cluster/ledger/src/features/ledger/service/ledger-data-service.ts:567`) returns the committed load's `repoPaths` unchanged (`:612`, `:630`). The `written` and `deleted` sets it builds for the overlays never reach that list.
- `checkProjectedErrors` passes it to `parseLedgerFiles` (`:506`). Both document checks read it:
  - `reconcileDocumentErrors` drops the engine's E8001 when the path is in `repoPaths` (`document-validation.ts:126`, `:136`).
  - w31/021's root check, plus discovery itself, walk it (`document-discovery.ts:87`, `:92`).
- So a projection still sees every file the write deletes, and none that it creates. The E8001 half predates w31. The E7006 half arrived with w31/021.

## Fix

In `projectFileMap`, return the projected path list: the committed `repoPaths` minus `deleted`, plus `written`. Every projection reader (`checkProjectedErrors`, `projectedEntryIds`, `projectedSourceFiles`) then validates document paths, roots and discovered documents against the tree the commit will have. MCP `deleteLedgerFiles`/`renameLedgerFile`/`createLedgerFiles` and REST `PUT`/`DELETE …/files/{path}` share the projection, so they change together. GraphQL file writes have no gate (`w1/blocked/210`).

**Done when:**

- Each step-3 dry run answers `valid: false` with the matching `newErrors` (E7006 for the root's last file, E8001 for the referenced file), on MCP and REST.
- The step-4 commit is refused `VALIDATION_FAILED` unless `allow_invalid`.
- A write that creates a file under a root, or the file a `document` names, does not report it missing.
- `check-projected-errors.test.ts` covers a deleted and a renamed document file and a root emptied by the write, and the cases fail with the fix reverted.

Dedupe: searched `.pm/**`, done and blocked included, for `repoPaths`, E8001, "Document file not found", "Document root" and `projectFileMap` with delete, rename, preview and gate. `w2/121` (done) is the dashboard's toast after a GraphQL delete, which has no server gate. `w31/021` added the root check, and `w31/022` the projected include walk. Neither covers the projected path list.

**Resolved 2026-11-15** — A write that deletes or renames a document file now previews the errors its commit will have, and the commit is refused `VALIDATION_FAILED` unless `allow_invalid` is set. Emptying the documents root previews `E7006 Document root '…' does not exist`. Removing the file a `document` names previews `E8001 Document file not found`. Shipped in the commit carrying this note (`backend-cluster/ledger`).

- **What changed.** `projectFileMap` (`ledger-data-service.ts`) now returns the path list of the tree the commit leaves: the committed paths minus the ones the write deletes, plus the ones it writes. When a write changes the same path more than once, the last change decides whether the path exists. Before, it returned the committed list unchanged. That list is what `reconcileDocumentErrors` checks `document` paths against, and what discovery and the root check walk.
- **Who gets it.** Every projection reader: `checkProjectedErrors`, which runs both the preview and the commit gate, and `projectedEntryIds`. MCP `deleteLedgerFiles`, `renameLedgerFile` and `createLedgerFiles` share the projection with REST `PUT`/`DELETE …/files/{path}` and the commit-undo preview, so all of them change together. GraphQL file writes still have no gate (`w1/blocked/210`). The include walk (w31/022) still reads committed blobs at the load's ref.
- **A write that adds the files is fine.** If it creates the file under the root, or the file a `document` names, along with the option or the directive, it previews clean.
- **Before the fix.** Live on `https://beancount.io` against `<qa-owner>/mcp-agent-eval`, I committed a probe file under `qa-w31-027-docs/` and a referenced `qa-w31-027-ref.txt`, then added the option and the `document` line to `main.bean`. Four dry runs each answered "No new bean-check errors": `deleteLedgerFiles` of either file, and `renameLedgerFile` of either file. I did not commit any of those deletes. `main.bean` was then restored byte for byte (blob `f1a0b83c`) and both probe files were deleted. Only `main.bean` remains, and `checkLedger` is clean. The deployed ledger service runs the old code until the next deploy.
- **Tests.** Six new cases in `check-projected-errors.test.ts` give the real `discoverDocuments` and `reconcileDocumentErrors` the paths the parse receives. They cover a root emptied by a delete, a referenced file deleted, both files renamed (including the exact path list), a path deleted and rewritten in the same write, and a write that adds the files. With the fix reverted, 5 of them fail. `yarn verify:rustledger` (`scripts/projected-documents.ts`) drives the real projection and engine through the note's repro. It expects the two errors for each delete and rename, a clean preview for the unchanged ledger, and a clean preview when the files are added with the option. With the fix reverted, it stops on "deleting the root's last file previews []".
- **Gates.** Run in `node:22-bookworm-slim` (v22.23.4): `yarn typecheck`, ESLint, `yarn lint:deadcode`, Prettier on the changed files, `yarn test` (221 suites, 3446 tests, all passing), `yarn verify:rustledger` and `yarn build`.

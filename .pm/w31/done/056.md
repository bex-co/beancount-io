# `revertCommit` (`sha`) and `createPullRequest` (`baseBranch`) silently trim leading/trailing whitespace before ref validation, bypassing `assertCommitRef` and `assertBranchName` on MCP, REST, and GraphQL (gap in `w31/024`)

**Minor · backend-v2 (`LedgerWorkflow.undoLedgerCommit`, `PullRequestService.createPRFromPatch`) · 30–40m · A1.** `w31/024` established that a git ref carrying spaces must be refused upfront with `BAD_USER_INPUT` naming the parameter and explicitly forbade silent trimming ("Do not trim the value silently: an agent should learn its input was wrong"), specifically citing `revertCommit` and `createPullRequest`'s `baseBranch`. Both write operations still call `.trim()` on their ref input *before* their validator runs, so a leading- or trailing-whitespace ref (`" main "`, `"main "`, `"\tmain\n"`, `" no-such-branch-qa "`) silently strips the whitespace and proceeds to Gitea instead of refusing with `BAD_USER_INPUT`. Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 LAND=1`) on 2026-11-23 against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, checked against HEAD `b1968162f`). Credential: unpinned read/write/admin `bcio_` key on the QA account. Synthetic ledger: `<qa-owner>/mcp-agent-eval` (read-only / `dry_run: true` for this finding; disposable write round-trip restored `main.bean` byte-for-byte, blob `f1a0b83c`, sha256 `77c3a591efd311e0`, 0 bean-check errors).

## Root cause

Not deployment lag — present at HEAD `b1968162f`:

1. `backend-cluster/backend-v2/src/features/ledger/workflow/ledger-workflow.ts:1729-1743` (`LedgerWorkflow.undoLedgerCommit`):
   ```ts
   const sha = input.sha.trim();
   if (sha === "") {
     throw new BadUserInputError("sha is required", "sha", COMMIT_NOT_FOUND_HINT);
   }
   ...
   const commit = await findCommit(gitea, ledgerOwner, ledgerName, sha, { stat: false });
   ```
   `findCommit` (`src/features/gitea/commits/service/commits-service.ts:63-72`) already calls `assertCommitRef(sha, "sha")` on the raw string and then checks `if (sha.trim() === "")`. Trimming `input.sha` first at `ledger-workflow.ts:1729` strips leading/trailing spaces before `findCommit` can see them, defeating `assertCommitRef` (`src/shared/commit-ref.ts:23-34`) for leading/trailing spaces while leaving middle spaces refused.
2. `backend-cluster/backend-v2/src/features/gitea/pull-request/service/pull-request-service.ts:257,267-270` (`PullRequestService.createPRFromPatch`):
   ```ts
   const baseBranch = input.baseBranch?.trim() ?? "";
   ...
   if (!baseBranch) {
     throw new BadUserInputError("baseBranch must not be empty");
   }
   assertBranchName(baseBranch);
   ```
   `assertBranchName` (`:754-773`) already rejects ASCII control characters and spaces (`/[\u0000-\u0020\u007f~^:?*[\\#%]/`), but trimming `input.baseBranch` at `:257` strips leading/trailing spaces, tabs, and newlines before `assertBranchName` inspects the string.

## Fix

In `backend-cluster/backend-v2`:

1. In `LedgerWorkflow.undoLedgerCommit` (`src/features/ledger/workflow/ledger-workflow.ts:1729-1743`):
   - Keep `const sha = input.sha;` untrimmed.
   - Call `assertCommitRef(sha, "sha")` before checking `if (sha.trim() === "")` (matching `findCommit` in `commits-service.ts:63-72`), and pass the untrimmed `sha` to `findCommit` so leading/trailing spaces are refused with `BAD_USER_INPUT` (`field: "sha"`) before acquiring a Gitea client or calling Gitea.
2. In `PullRequestService.createPRFromPatch` (`src/features/gitea/pull-request/service/pull-request-service.ts:257,267-270`):
   - Keep `const baseBranch = input.baseBranch ?? "";` untrimmed.
   - Check `if (baseBranch.trim() === "")` for the empty/blank error (or run `assertBranchName` after the empty check — if `baseBranch === ""` throw `"baseBranch must not be empty"`, otherwise if `baseBranch.trim() === ""` keep `"baseBranch must not be empty"` so existing blank-branch behavior stays intact, and pass the untrimmed `baseBranch` to `assertBranchName(baseBranch)` so `" main "`, `"main "`, and `"\tmain\n"` are refused with `BAD_USER_INPUT` `field: "baseBranch"` before calling Gitea).

# `assertNoTwinsAmong` only compares full file paths, letting `createLedgerFiles` / `changeFiles` create case- and Unicode-colliding parent folders (`Reports/q1.bean` + `reports/q2.bean`) in one commit

**Major · backend-v2 (`src/features/ledger/utils/portable-twin.ts`) · 20–30m · A1.** The portable-twin guard (`w21/770`, `7be2a2212`) refuses creating a file whose path differs from an existing one only by letter case, Unicode normalization form (NFC vs NFD), or invisible characters — **including its folders** (`assertNoPortableTwin` in `src/features/ledger/utils/portable-twin.ts:25-58` walks every path prefix `depth = 1..segments.length`), because macOS and Windows checkouts collapse case/Unicode-equivalent folders into one and leave the clone corrupted or dirty. However, the in-batch companion `assertNoTwinsAmong` (`src/features/ledger/utils/portable-twin.ts:104-116`) only hashes each full `path` string (`portablePathKey(path)`), never its directory prefixes. Consequently, a single batch creating `Reports/q1.bean` and `reports/q2.bean` (or `Café/a.bean` and `Cafe\u0301/b.bean`, or `dir\u200b/a.bean` and `dir/b.bean`) passes both `assertNoTwinsAmong` (full keys differ) and `assertNoPortableTwin` (neither folder exists in the repo yet), returns `dry_run: true` with `valid: true`, and commits two colliding folder trees to Git on Linux — whereas creating the same two files in two separate commits is refused with `CONFLICT`.

Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 LAND=1`) on 2026-11-24 against `https://beancount.io` (`beancount-mcp 1.0.0`, negotiated protocol `2025-11-25`, verified still present at local HEAD `4c9ce330a`). ## Root cause

`backend-cluster/backend-v2/src/features/ledger/utils/portable-twin.ts:104-116`:

```ts
export function assertNoTwinsAmong(paths: readonly string[]): void {
  const seen = new Map<string, string>();
  for (const path of paths) {
    const key = portablePathKey(path);
    const other = seen.get(key);
    if (other !== undefined && other !== path) {
      throw new ConflictError("File", `${path} already exists as ${other}`, {
        hint: "macOS and Windows keep one of two names that differ only by letter case, accents or an invisible character.",
      });
    }
    seen.set(key, path);
  }
}
```

Because `seen` only records the full `path` and never its directory prefixes (`segments.slice(0, depth).join("/")` for `depth = 1..segments.length`), `portablePathKey("Reports/q1.bean")` (`"reports/q1.bean"`) and `portablePathKey("reports/q2.bean")` (`"reports/q2.bean"`) never collide in `seen`. Meanwhile `assertNoPortableTwin` only inspects the pre-commit repository tree (where neither folder exists yet), so the batch slips past both guards.

## Fix

Owning package: `backend-cluster/backend-v2`. Shared utility fix covers every caller of `assertNoTwinsAmong` across MCP (`createLedgerFiles` / `editLedgerFiles`), REST (`LedgerRepoService.changeFiles`), and `PullRequestService.createPRFromPatch` (once `w31/084` switches it from its inline full-path check to `assertNoTwinsAmong`; update `pull-request-service.ts` here too if `w31/084` has not landed yet).

1. Update `assertNoTwinsAmong` in `src/features/ledger/utils/portable-twin.ts:104-116` to walk every prefix `depth = 1..segments.length` (`prefix = segments.slice(0, depth).join("/")`, `key = portablePathKey(prefix)`):
   - If `seen.get(key)` exists and `other !== prefix`, throw `ConflictError("File", `${path} already exists as ${other}`, { hint: "macOS and Windows keep one of two names that differ only by letter case, accents or an invisible character." })`.
   - Record `seen.set(key, prefix)` when unseen.
   - Identical parent prefixes (`Reports/q1.bean` and `Reports/q2.bean`) have `other === prefix` and remain allowed; nested collisions (`a/Sub/x.bean` + `a/sub/y.bean`), NFC/NFD folder twins, and invisible-character folder twins (`dir\u200b/x.bean` + `dir/y.bean`) are all refused with `CONFLICT`.
2. Add unit tests in `src/features/ledger/utils/__tests__/portable-twin.test.ts` and batch/adapter tests (covering `createLedgerFiles` dry-run and commit through `LedgerRepoService.changeFiles`) asserting:
   - `Reports/q1.bean` + `reports/q2.bean` → `ConflictError`
   - `a/Sub/x.bean` + `a/sub/y.bean` → `ConflictError`
   - `Caf\u00e9/a.bean` + `Cafe\u0301/b.bean` → `ConflictError`
   - `dir\u200b/a.bean` + `dir/b.bean` → `ConflictError`
   - `Reports/q1.bean` + `Reports/q2.bean` (same spelling) → allowed
3. Run `yarn typecheck`, `yarn lint:deadcode`, `yarn format:check`, `yarn test`, and `yarn generate-v1-openapi` in `backend-cluster/backend-v2/`.

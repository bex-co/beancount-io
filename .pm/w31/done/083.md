# `account-journal` and `register` silently degrade `conversion=units_by_cost` to plain `units` across MCP, REST, and GraphQL

**Major · ledger (`src/foundation/rustledger/journal-running-balance.ts`, `src/features/ledger/service/ledger-journal-service.ts`) · 25–35m · A1.** Both `account-journal` (`beancount://{owner}/{name}/account-journal`, `GET /api-gateway/v1/ledgers/{owner}/{name}/account-journal`, GraphQL `getLedgerAccountJournal`) and `register` (`beancount://{owner}/{name}/register/{account}`, `GET /api-gateway/v1/ledgers/{owner}/{name}/register`, GraphQL `getLedgerRegister`) accept `conversion=units_by_cost` and advertise it in `BAD_USER_INPUT` error messages (and `REGISTER_CONVERSION_MODES` in `backend-v2`, `w31/039`). However, `LotInventory.reduce` in `backend-cluster/ledger/src/foundation/rustledger/journal-running-balance.ts:348-371` has no `units_by_cost` branch: it falls through to `reduceAtCurrency(lot, "units_by_cost", ...)`, finds no price for a currency literally named `"units_by_cost"`, and returns plain un-costed `units` (`{"VTI": "31", "EUR": "162.00"}`) instead of cost-currency-keyed units (`{"VTI {EUR}": "27", "VTI {USD}": "4", "EUR {}": "162.00"}`), collapsing lots held at different cost currencies and dropping `{}` / `{<costCurrency>}` keys on both `change` and running `balance`.

Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`) on 2026-11-24 against `https://beancount.io` (`beancount-mcp 1.0.0`, negotiated protocol `2025-11-25`, verified still present at local HEAD `5f452b302`). Credential: unpinned read/write/admin `bcio_` API key on the QA account. Synthetic ledger: `<qa-owner>/qa-20261102-units-by-cost` (read-only probes; zero writes performed).

## Expected

When `conversion=units_by_cost` is passed to `account-journal` or `register` on MCP, REST, or GraphQL, each row's `change` and running `balance` return raw units keyed by cost currency — `<currency> {<costCurrency>}` for costed lots and `<currency> {}` for units held without a cost (e.g. `change: {"VTI {EUR}": "2"}`, `balance: {"VTI {EUR}": "27", "VTI {USD}": "4", "EUR {}": "162.00", ...}`) — matching `balance-sheet`, `trial-balance`, `overview`, `account-report`, and `interval-totals` (`lot-inventory.ts`), reading no prices, and dropping any key that nets to zero.

## Root cause

Not deployment lag — reproduced identically at local HEAD `5f452b302`:

1. `backend-cluster/ledger/src/features/ledger/service/ledger-journal-service.ts:1141-1148` validates `query.conversion` through `resolveConversion` (`src/foundation/rustledger/cost-valuation.ts:54-55`), which accepts `"units_by_cost"` as a reserved keyword.
2. `backend-cluster/ledger/src/features/ledger/service/ledger-journal-service.ts:1168-1171` only skips building `ScaledPriceMap` for `"units"` and `"at_cost"`:
   ```ts
   const prices =
     conversion !== "units" && conversion !== "at_cost"
       ? buildScaledPriceMap(snapshot.directives)
       : undefined;
   ```
   and `backend-cluster/ledger/src/foundation/rustledger/journal-running-balance.ts:585-588` repeats the same check, so `"units_by_cost"` keeps a truthy `prices` (and triggers `flowBalance` on `Income`/`Expenses` accounts at line 595).
3. `LotInventory.reduce` in `backend-cluster/ledger/src/foundation/rustledger/journal-running-balance.ts:348-378` has branches only for `"at_cost"`, `"at_value"`, `"units"`, and currency targets — no `"units_by_cost"` branch. `"units_by_cost"` falls into `else if (conversion !== "units" && conversion !== "at_cost" && valuation)` and calls `this.reduceAtCurrency(lot, "units_by_cost", valuation, addInto)`, which looks up a price into `"units_by_cost"`, gets `null`, and falls back to `addInto(lot.unitsCurrency, lot.units)` (plain `units`).
4. `backend-cluster/backend-v2`'s `LedgerFinanceService.getRegister` (`src/features/ledger/service/ledger-finance-service.ts:602-612`) delegates directly to `favaApiClient.journal.getAccountJournal(..., { conversion: target ?? "units" })` after `resolveRegisterConversion` (`src/features/ledger/utils/register.ts:60-64`) explicitly admits `"units_by_cost"`, so `register` inherits the exact same bug on all three surfaces.

## Fix

In `backend-cluster/ledger`:

1. Export `unitsByCostKey` from `src/foundation/rustledger/lot-inventory.ts:125` (so the `<currency> {<costCurrency>}` / `<currency> {}` key format stays in one place).
2. In `src/foundation/rustledger/journal-running-balance.ts`:
   - Add an explicit `conversion === "units_by_cost"` branch to `LotInventory.reduce` (`lines 348-371`) calling `addInto(unitsByCostKey(lot.unitsCurrency, lot.costCurrency), lot.units)`, and exclude `"units_by_cost"` from the `reduceAtCurrency` and comma-fallback branches (`lines 358-378`).
   - Exclude `"units_by_cost"` from `prices` in `accountJournalItems` (`lines 585-588`), matching `lot-inventory.ts:535` ("`units`, `units_by_cost` and `at_cost` read no price"), so flow accounts do not unnecessarily route through `flowBalance`.
3. In `src/features/ledger/service/ledger-journal-service.ts:1168-1171`, exclude `"units_by_cost"` from `buildScaledPriceMap` (`conversion !== "units" && conversion !== "at_cost" && conversion !== "units_by_cost"`).
4. Add regression tests in `src/foundation/rustledger/__tests__/journal-running-balance.test.ts` and `src/features/ledger/service/__tests__/units-by-cost.test.ts` covering `getAccountJournal(..., { conversion: "units_by_cost" })` for:
   - same commodity held at two cost currencies (`VTI {EUR}` and `VTI {USD}` kept separate in both `change` and running `balance`),
   - cost-less cash (`EUR {}`, `USD {}`) kept distinct from costed lots,
   - fully sold lots dropping their key to zero,
   - `time`-clamped account journals preserving cost-currency keys across the opening summary,
   - flow accounts (`Income`/`Expenses`) and `price` directives not altering `units_by_cost` output.

# `assertCommitRef` lets bare `{ … }` and arbitrary `:…` space-bearing refs bypass validation, returning `500 INTERNAL_SERVER_ERROR` / `503 SERVICE_UNAVAILABLE` across commit reads and `revertCommit` on MCP, REST, and GraphQL (gap in `w31/024`)

**Minor · backend-v2 (`assertCommitRef` in `src/shared/commit-ref.ts`) · 20–30m · A1.** `docs/mcp.md` ("Repository history resources") and `COMMIT_REF_SPACE_HINT` (`src/shared/commit-ref.ts:4`) state that a space in `sha`, `branch`, or `branchName` is refused with `BAD_USER_INPUT` and that git revision syntax takes a space only inside a `@{…}` or `^{…}` group or after `:/`. However, `assertCommitRef` (`src/shared/commit-ref.ts:24-26`) strips *any* `{…}` group (`/\{[^}]*\}/g`) and ignores everything after *any* `:` (`indexOf(":")`). Space-bearing non-commit refs such as `"main{ }"`, `"{ }"`, `"foo{a b}"`, `": "`, `"main: "`, `"main:path with space.bean"`, and `"main:/restore fixture"` therefore bypass `assertCommitRef`, reach Gitea's `cat-file --batch-check` lookup (which splits `<name> missing` on space and answers HTTP `500`), and surface to callers as retryable server outages (`INTERNAL_SERVER_ERROR` on `commit-details`, `commits`, and `revertCommit`; `SERVICE_UNAVAILABLE` on `latest-commit`) across MCP, REST, and GraphQL. ## Root cause

Not deployment lag — present at HEAD `5e085027f`:

`backend-cluster/backend-v2/src/shared/commit-ref.ts:23-34`:

```ts
export function assertCommitRef(ref: string, parameter: string): void {
  const outsideGroups = ref.replace(/\{[^}]*\}/g, "{}");
  const colon = outsideGroups.indexOf(":");
  const name = colon === -1 ? outsideGroups : outsideGroups.slice(0, colon);
  if (name.includes(" ")) {
    throw new BadUserInputError(
      `${parameter} must not contain a space: no branch name or commit SHA holds one`,
      parameter,
      COMMIT_REF_SPACE_HINT,
    );
  }
}
```

1. `/\{[^}]*\}/g` strips any `{…}` block instead of only `@{…}` and `^{…}` (`/@\{[^}]*\}|\^\{[^}]*\}/g` / `/[@^]\{[^}]*\}/g`), so bare `{ }` / `main{ }` / `foo{a b}` have their spaces erased before the check.
2. `outsideGroups.indexOf(":")` slices off everything after the first `:` anywhere in the string, rather than exempting only a leading `:/` commit-message search (`outsideGroups.startsWith(":/")`). `src/shared/__tests__/commit-ref.test.ts:28` mistakenly pinned `"main:path with space.bean"` as an allowed pass-through case even though `<rev>:<path>` names a blob/tree rather than a commit and Gitea's commit lookup endpoints answer it with HTTP `500`.

## Fix

In `backend-cluster/backend-v2`:

1. In `assertCommitRef` (`src/shared/commit-ref.ts:23-34`):
   - Strip only `@{…}` and `^{…}` groups: `const outsideGroups = ref.replace(/[@^]\{[^}]*\}/g, "{}");`.
   - Allow spaces after a leading `:/` only: check `if (!outsideGroups.startsWith(":/") && outsideGroups.includes(" "))` and throw the same `BadUserInputError` with `parameter` and `COMMIT_REF_SPACE_HINT`.
   - Keep space-free colon strings like `"x:y"` and `"main:main.bean"` untouched (they still reach Gitea and answer `NOT_FOUND`).
2. Update unit tests in `src/shared/__tests__/commit-ref.test.ts`:
   - Move `"main:path with space.bean"` from the pass-through list to the refused list alongside `"main{ }"`, `"{ }"`, `"foo{a b}"`, `": "`, `"main: "`, and `"main:/restore fixture"`.
   - Keep `"main@{1 day ago}"`, `"main@{2026-11-15 10:00:00}"`, `"main^{/restore fixture}"`, `":/restore fixture"`, and `"x:y"` in the pass-through list.
3. Extend 3-surface parity tests in `src/features/ai-agent/api/__tests__/commit-parity.test.ts` and `src/features/ai-agent/api/__tests__/revert-commit-parity.test.ts` to cover a bare-brace bypass (`"main{ }"`) and a non-`:/` colon bypass (`"main:path with space.bean"` / `": "`) on MCP, REST (`400`), and GraphQL, asserting `BAD_USER_INPUT` naming the parameter and zero Gitea calls.

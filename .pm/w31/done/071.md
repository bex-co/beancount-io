# Query-string `z.coerce.number()` across MCP resources and v1 REST silently coerces empty/whitespace strings (`offset=`, `first=`, `amountMin=`) to `0` and accepts hex/scientific notation (`0x2`, `1e1`)

**Minor · backend-v2 (`src/server/rest/v1-schemas.ts` and v1 REST / MCP resource query schemas) · 45–60m · A1.** Every numeric URL query parameter shared by MCP resources and v1 REST routes uses bare `z.coerce.number()` (which delegates to JavaScript `Number(value)`). Unlike `booleanQuery` (`v1-schemas.ts:23-26`, which strictly accepts only `"true"` and `"false"`), `Number("") === 0`, `Number("   ") === 0`, `Number("0x2") === 2`, and `Number("1e1") === 10`. As a result, empty or whitespace-only query values silently pass as `0` on every `min(0)` or unbounded numeric query parameter — returning `200 OK` on `journal?offset=`, `plaintext-journal?offset=`, `account-journal?offset=`, and `account/feed?offset=`, silently returning `0` entries on `GET /api-gateway/v1/legacy/journal-entries?first=`, and silently setting a `0` bound on `amountMin=` / `amountMax=` — while `min(1)` parameters (`limit=`, `page=`, `prNumber=`, `ledgerRepoId=`) fail with the misleading range error `"Too small: expected number to be >=1"` instead of rejecting a non-numeric string, and non-decimal literals (`0x2`, `1e1`, `%202%20`) succeed across all coerced query params. Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 LAND=1`) on 2026-11-23 against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, verified at HEAD `dc57d76b6`). Credential: unpinned read/write/admin `bcio_` key on the QA account. Synthetic ledger: `<qa-owner>/mcp-agent-eval` (read-only for this finding).

REST controls (same credential):
- `GET /api-gateway/v1/ledgers/<qa-owner>/mcp-agent-eval/journal?limit=2&offset=` → `200 OK` (`offset: 0`, 2 rows returned).
- `GET /api-gateway/v1/legacy/journal-entries?first=` → `200 OK` returning `0` rows (`""` coerced to `first: 0`, vs `5` rows for `?first=5`).
- `GET /api-gateway/v1/legacy/journal-entries?first=5&amountMin=` → `200 OK` (`""` coerced to `amountMin: 0`).

- Actual:
  - `journal?limit=2&offset=`, `journal?limit=2&offset=%20%20`, `plaintext-journal?limit=2&offset=`, `account-journal?account=Assets&limit=2&offset=` all return `200 OK` with `offset: 0`.
  - `journal?limit=0x2` returns `200 OK` (`limit: 2`), `journal?limit=1e1` returns `200 OK` (`limit: 10`), `commits?page=0x1&limit=2` returns `200 OK` (`page: 1`), `assets/download-url?ledgerRepoId=1e0&filename=x` reaches repo lookup (`NOT_FOUND`), `pull-request?prNumber=1e0` reaches PR lookup (`NOT_FOUND`).
  - `journal?limit=` returns `-32602 BAD_USER_INPUT`: `"limit: Too small: expected number to be >=1"` instead of an invalid-integer error.
- Controls:
  - `booleanQuery` (`journal?include_source=`, `journal?include_source=%20true%20`) already strictly refuses anything other than `"true"` / `"false"`.
  - MCP JSON tools (`listLedgers`, `listLedgerEntries`, `getLedgerContext`) and GraphQL (`Int` / `Float`) strictly refuse empty strings and non-numeric literals.

Expected:

- Query-string integer parameters accept only strict base-10 integer strings (`/^-?\d+$/`, with range bounds `.min(...)`/`.max(...)` applied afterward) and refuse `""`, whitespace (`"  "`, `" 2 "`), hex (`"0x2"`), octal/binary (`"0b10"`, `"0o10"`), scientific notation (`"1e1"`), and non-integer decimals (`"1.0"`) with `BAD_USER_INPUT` (MCP) / `400 VALIDATION_FAILED` (REST) naming the parameter as an invalid integer.
- Query-string decimal number parameters (`amountMin`, `amountMax` on `legacy/journal-entries`) accept only strict finite base-10 decimal strings (`/^-?(?:\d+\.?\d*|\.\d+)$/`) and refuse `""`, whitespace, hex, and `Infinity`/`NaN`.
- Missing query parameters (`undefined`) keep existing optional/default behavior unchanged (including `withRequiredQueryNames` reporting `<name> is required` when a required query parameter like `prNumber` or `ledgerRepoId` is omitted).

## Fix

In `backend-cluster/backend-v2`:

1. Add small, strict query-string numeric helpers in `src/server/rest/v1-schemas.ts` beside `booleanQuery` (e.g. `intQuery(bounds)` validating `/^-?\d+$/` via `z.string().regex(...)` or `z.preprocess`/transform piped to `z.number().int()...` while preserving OpenAPI `integer` / `number` metadata, and `decimalQuery()` for `amountMin`/`amountMax` validating `/^-?(?:\d+\.?\d*|\.\d+)$/`). Keep `undefined` passthrough for `.optional()` and `.default(...)` so omitted required query params still trigger `withRequiredQueryNames` (`prNumber is required`, `ledgerRepoId is required`).
2. Replace bare `z.coerce.number()` in all query/path param schemas listed above across v1 REST and MCP resources. (Leave `api-key-schemas.ts`'s `z.coerce.date()` untouched; handle `listStagedBankTransactions` separately in `w31/070`.)
3. Add cross-surface MCP resource + REST contract tests (e.g. in `src/server/rest/__tests__/rest-query-strictness.test.ts` and `src/features/ai-agent/api/__tests__/mcp-resources.test.ts`) verifying that `""`, `"   "`, `"0x2"`, `"1e1"`, `" 2 "`, and `"1.0"` are refused on `offset`, `limit`, `page`, `prNumber`, `ledgerRepoId`, `first`, and `amountMin`, while omitted params keep defaults/required errors and canonical base-10 strings (`"0"`, `"2"`, `"100"`, `"-12.5"`) succeed.
4. Run `yarn generate-v1-openapi` and verify `docs/openapi/v1.json` (and `cli/openapi/v1.json` if touched) stays in sync with zero drift.

- Adjacent states: omitted optional params keep existing defaults (`offset=0`, `page=1`, etc.); required missing params (`beancount://.../pull-request`, `beancount://assets/download-url`) still answer `<name> is required`; negative integers (`-1`) continue to fail `.min(0)`/`.min(1)` on `offset`/`page`/`limit` and remain valid on `amountMin`/`amountMax`; out-of-range integers (`limit=1001`, `limit=0`) keep their existing range errors.

# `moveEntrySources` / `moveSourceSlices` skips `assertNoPortableTwin`, allowing case/Unicode twins and file-vs-folder collisions on `toPath` across MCP, REST, and GraphQL

**Major · backend-v2 (`src/features/ledger/service/ledger-journal-service.ts`) · 25–35m · A1.** Every other path-creating operation in `backend-v2` (`LedgerRepoService.assertNewPathsPortable`, `LedgerWorkflow.createLedgerFile`, `LedgerWorkflow.renameLedgerFile`, `PullRequestService.createPRFromPatch`) runs `assertNoPortableTwin` (`src/features/ledger/utils/portable-twin.ts:25-79`) to refuse creating a file that collides with an existing file or folder by letter case, Unicode normalization (NFC vs NFD), or invisible characters, or that places a file beneath an existing file (`main.bean/sub.bean`) or at an existing folder (`books.bean/`). `LedgerJournalService.moveSourceSlices` (`src/features/ledger/service/ledger-journal-service.ts:575-635`) calls only `assertSafeRepoPath(toPath, "toPath")` (`:603`) and forwards straight to the ledger service, which itself calls only `assertPortableRepoPath(toPath, "toPath")` (`backend-cluster/ledger/src/features/ledger/service/ledger-journal-service.ts:1470`) with no twin or file-vs-folder guard. As a result, `moveEntrySources` (MCP), `POST /api-gateway/v1/ledgers/{owner}/{name}/entries/move` (REST), and `Mutation.moveLedgerEntrySources` (GraphQL) all accept `toPath: "Main.bean"`, `toPath: "main\u200b.bean"`, and `toPath: "main.bean/sub.bean"` with HTTP 200 and `valid: true` on `dry_run: true` — and on commit either create macOS/Windows-corrupting twin files (with a self-colliding `include "Main.bean"` in `main.bean`) or fail late at Gitea after a lying `valid: true` dry-run preview.

Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 LAND=1`) on 2026-11-24 against `https://beancount.io` (`beancount-mcp 1.0.0`, negotiated protocol `2025-11-25`, verified still present at local HEAD `383271a46`). Credential: unpinned read/write/admin `bcio_` API key on the QA account (`ledger.read` key boundary also exercised). Synthetic ledger: `<qa-owner>/mcp-agent-eval` (`dry_run: true` probes only for this finding; separate disposable write round-trip restored `main.bean` byte-for-byte, sha256 `77c3a591efd311e0`, 0 bean-check errors).

## Root cause

1. `backend-cluster/backend-v2/src/features/ledger/service/ledger-journal-service.ts:598-609`:
   `LedgerJournalService.moveSourceSlices` validates `entries` size/format and calls `assertSafeRepoPath(toPath, "toPath")` (`:603`), then immediately calls `favaApiClient.journal.moveSourceSlices(...)`. It never calls `assertNoPortableTwin(toPath, ...)` against the ledger's directory tree.
2. `backend-cluster/ledger/src/features/ledger/service/ledger-journal-service.ts:1446-1470`:
   Only calls `assertSafeRepoPath`, checks `BEAN_FILE_RE`, and calls `assertPortableRepoPath(toPath, "toPath")` when `!repoPaths.includes(toPath)`. Neither service checks portable twins (case/Unicode/invisible characters on file or parent folder segments) or file-vs-folder prefix collisions.

## Fix

Owning package: `backend-cluster/backend-v2`. Shared service change updates all three eligible surfaces together (MCP `moveEntrySources`, REST `POST /api-gateway/v1/ledgers/{owner}/{name}/entries/move`, GraphQL `Mutation.moveLedgerEntrySources`) — no OpenAPI response shape change needed (existing `ConflictError` maps to HTTP `409` on REST, `CONFLICT` on MCP and GraphQL).

1. In `backend-cluster/backend-v2/src/features/ledger/service/ledger-journal-service.ts:598-608`, after authorization (`getClient`), `assertBulkEntriesSize`, hash/sha format checks, and `assertSafeRepoPath` (on both `toPath` and `includeFrom`), call `assertNoPortableTwin(toPath, ...)` using `favaApiClient.ledgers.getLedgerDirContent` (matching `LedgerRepoService.assertNewPathsPortable` at `src/features/ledger/service/ledger-repo-service.ts:409-424`, mapping `type` to `"file" | "dir"` and letting `NOT_FOUND` on a nonexistent folder return early).
   - Note that when `toPath` is an existing file (exact path match, `type === "file"`), `assertNoPortableTwin` returns without throwing (`portable-twin.ts:59-78`), so moving entries into an existing `.bean` file continues to work unchanged.
   - When `toPath` is a case/NFC-NFD/invisible-character twin of an existing file or parent folder, a child beneath an existing file (`main.bean/sub.bean`), or an existing folder (`books.bean/`), `assertNoPortableTwin` throws `ConflictError` before `favaApiClient.journal.moveSourceSlices` is called.
   - Check ordering with non-`.bean`/`.beancount` `toPath` inputs: keep invalid extensions returning `BAD_USER_INPUT` if desired, or verify existing `moveSourceSlices` tests do not expect a specific error order on non-`.bean` colliding paths.
2. Update any existing `ledger-journal-service` / `move-entries` unit-test mocks that stub `favaApiClient` without `ledgers.getLedgerDirContent`.
3. Add unit tests in `src/features/ledger/service/__tests__/` and 3-surface adapter parity tests (MCP, REST 409, GraphQL `CONFLICT`) covering:
   - case twin (`Main.bean` when `main.bean` exists) → `CONFLICT` before calling `favaApiClient.journal.moveSourceSlices`,
   - Unicode NFC/NFD twin and invisible-character twin (`main\u200b.bean`) → `CONFLICT`,
   - case-colliding parent folder (`Books/2026.bean` when `books/` exists) → `CONFLICT`,
   - path beneath existing file (`main.bean/sub.bean`) → `CONFLICT`,
   - existing folder at `toPath` (`books.bean` when `books.bean/` is a directory) → `CONFLICT`,
   - exact-match existing file (`sub.bean`) and brand-new nested path (`newdir/2026.bean`) → allowed,
   - read-only `ledger.read` credential → still `FORBIDDEN` before any directory listing call.
4. Run `yarn typecheck`, `yarn lint:deadcode`, `yarn format:check`, `yarn test`, and `yarn generate-v1-openapi` in `backend-cluster/backend-v2/`.

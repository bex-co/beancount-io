# `account-report` accepts empty or whitespace `accountName` (`?accountName=` / `%20%20` / `accountName: ""`) and returns `200 OK` fabricated/zeroed series instead of `BAD_USER_INPUT` on MCP, REST, and GraphQL

**Minor · backend-v2 (account-report validation) · 20–30m · A1.** Passing an empty or whitespace-only `accountName` to `account-report` succeeds with `200 OK` across MCP, REST, and GraphQL — returning every ledger transaction date with `{}` balances for `""`, and zeroed monthly `interval_totals_data`/`account_balance_data` for whitespace — instead of refusing with `BAD_USER_INPUT` as omitting `accountName` and sibling `account-journal` (`w31/036`) do. Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`) on 2026-11-23 against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, checked against HEAD `ffb9f6270`). Credential: unpinned read/write/admin `bcio_` key on the QA account. Synthetic ledger: `<qa-owner>/mcp-agent-eval`.

## Repro (live)

Reproduced in fresh read-only requests across all three surfaces against `<qa-owner>/mcp-agent-eval`:

1. **MCP resource `beancount://<qa-owner>/mcp-agent-eval/account-report/%20%20`**:
   ```sh
   node .agents/skills/qa-shared/scripts/qa-mcp.mjs read 'beancount://<qa-owner>/mcp-agent-eval/account-report/%20%20'
   ```
   Actual: HTTP `200`, returns `{"linechart_data":[],"interval_totals_data":[{"date":"2026-01-31","balance":{}},...],"account_balance_data":[{"date":"2026-01-31","balance":{}},...]}`.
2. **REST `GET /api-gateway/v1/ledgers/<qa-owner>/mcp-agent-eval/account-report?accountName=` and `?accountName=%20%20`**:
   - `?accountName=` → HTTP `200`, returns `{"linechart_data":[{"date":"2026-01-01","balance":{}},{"date":"2026-02-10","balance":{}},...],...}` (every ledger transaction date with `{}` balance).
   - `?accountName=%20%20` → HTTP `200`, returns `{"linechart_data":[],"interval_totals_data":[{"date":"2026-01-31","balance":{}},...],...}`.
3. **GraphQL `getLedgerAccountReport(ledgerId: "<qa-owner>/mcp-agent-eval", accountName: "")` and `accountName: "  "`**:
   - `accountName: ""` → HTTP `200`, `linechartData` lists every ledger transaction date (`2026-01-01`, `2026-02-10`, ...) with empty balances.
   - `accountName: "  "` → HTTP `200`, empty `linechartData` and zeroed monthly `intervalTotalsData`.

Expected: refused with `BAD_USER_INPUT` (`accountName is required`) on MCP, REST, and GraphQL without calling the ledger service.

## Working controls

- REST `GET /api-gateway/v1/ledgers/<qa-owner>/mcp-agent-eval/account-report` (omitting `accountName`) returns HTTP `400 VALIDATION_FAILED: Validation failed for query.accountName: accountName is required`.
- Sibling `account-journal` (`w31/036`, `4d68f210a`) refuses `account: ""` and `"  "` with `BAD_USER_INPUT` (`account is required`) across MCP, REST, and GraphQL.
- Note: `interval-totals` intentionally treats `accountName` as optional (`""` means all accounts) and must stay unaffected.

## Root cause

Not deployment lag — present at HEAD `ffb9f6270`:

- `backend-cluster/backend-v2/src/features/ledger/api/rest/v1/analysis-handler.ts:282-303`: `account-report` declares `accountName: z.string()` with no non-empty/non-blank check and forwards `accountName: query.accountName ?? ""` to `LedgerDataService.getAccountReport`.
- `backend-cluster/backend-v2/src/features/ledger/service/ledger-data-service.ts:435-453` (`LedgerDataService.getAccountReport`): delegates straight to `favaApiClient.reports.getLedgerAccountReport` without guarding `accountName.trim() === ""`, so MCP (`beancount://{owner}/{name}/account-report/{accountName}`), REST (`GET /api-gateway/v1/ledgers/{owner}/{name}/account-report`), and GraphQL (`getLedgerAccountReport`) all forward empty/blank account names to the ledger service.

## Fix

In `backend-cluster/backend-v2`:

1. Guard `accountName.trim() === ""` at the start of `LedgerDataService.getAccountReport` (`src/features/ledger/service/ledger-data-service.ts:438`), throwing `new BadUserInputError("accountName is required", "accountName")` before authorization or calling the ledger service, mirroring `LedgerJournalService.getAccountJournal` (`w31/036`). Leave `getIntervalTotals` unchanged (there `accountName` is optional).
2. Keep `accountName: z.string()` in `analysis-handler.ts:287` if keeping OpenAPI stable (or sync `docs/openapi/v1.json` and `cli/openapi/v1.json` if changed), letting the service guard produce identical `BAD_USER_INPUT` errors across MCP, REST, and GraphQL.
3. Add unit tests in `src/features/ledger/service/__tests__/ledger-data-service.test.ts` and 3-surface adapter tests (MCP `account-report/%20%20`, REST `account-report?accountName=` / `%20%20`, GraphQL `getLedgerAccountReport` with `""` and `"  "`).

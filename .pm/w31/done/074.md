# `prompts/get` drops empty `""` arguments but folds whitespace-only free-text arguments (`account`, `period`, `statement`, `item_id`, `question`) verbatim into broken playbook text

**Minor · backend-v2 (`src/features/ai-agent/api/mcp-prompts.ts`) · 20–30m · A1.** `w31/011` updated `renderPrompt` (`mcp-prompts.ts:107-117`) to drop `""` arguments before rendering so unfilled form fields fall back to their omitted prose rather than producing broken sentences. However, `renderPrompt` checks only `value !== ""` and leaves whitespace-only strings (`"   "`) untouched on the five free-text optional arguments (`account`, `period`, `statement`, `item_id`, `question`). Passing `"   "` produces broken playbook prompts — including `"Linked bank:    ."` (which instructs the agent to pass a blank `item_id` that `syncBankTransactions` immediately refuses with `BAD_USER_INPUT: itemId must not be empty`), `"Reconcile     against the     statement."` with a phantom empty `"Statement provided by the user:"` block, and `"spending for    , starting with:    ."`. Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`) on 2026-11-23 against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, verified at HEAD `69d4680b6`). Credential: unpinned read/write/admin `bcio_` key on the QA account (read-only for this finding).

## Repro (live)

```sh
# 1. reconcile-account with whitespace-only args
node .agents/skills/qa-shared/scripts/qa-mcp.mjs prompt reconcile-account '{"account":"   ","period":"   ","statement":"   "}'

# 2. categorize-imports with whitespace-only item_id
node .agents/skills/qa-shared/scripts/qa-mcp.mjs prompt categorize-imports '{"item_id":"   "}'

# 3. spending-report with whitespace-only period and question
node .agents/skills/qa-shared/scripts/qa-mcp.mjs prompt spending-report '{"period":"   ","question":"   "}'
```

- Actual:
  - `reconcile-account`: `"Reconcile     against the     statement."` followed by `"Statement provided by the user:\n\n   "`.
  - `categorize-imports`: includes `"Linked bank:    ."`.
  - `spending-report`: `"Answer questions about this ledger's spending for    , starting with:    ."`.
- Working controls:
  - Passing `""` for the exact same arguments (`{"account":"","period":"","statement":""}`) produces clean omitted fallbacks (`"Reconcile one account (ask me which) against one statement period."`, no statement block).
  - Passing `"   "` for fixed-shape arguments (`month`, `ledger`) is correctly refused with `-32602 BAD_USER_INPUT` (`w31/011`).

Expected:
- Whitespace-only values on the free-text optional arguments (`account`, `period`, `statement`, `item_id`, `question`) are treated as omitted (falling back to the same text as `""` / absent), while non-empty malformed fixed-shape arguments (`month: " "`, `ledger: " "`) remain refused with `-32602 BAD_USER_INPUT` as pinned by `w31/011`.

## Root cause

Not deployment lag — present at HEAD `69d4680b6`:

- `backend-cluster/backend-v2/src/features/ai-agent/api/mcp-prompts.ts:107-117`:
  ```ts
  export function renderPrompt(
    descriptor: McpPromptDescriptor,
    args: Record<string, string | undefined>,
    identity: Identity,
  ): string {
    const given = Object.fromEntries(
      Object.entries(args).filter(([, value]) => value !== ""),
    );
    validatePromptArgs(given);
    return descriptor.build(given, identity);
  }
  ```
  `value !== ""` drops only zero-length strings; whitespace-only strings survive into `reconcileAccount` (lines 218-226), `categorizeImports` (line 285), and `spendingReport` (lines 340-342).

## Fix

In `backend-cluster/backend-v2`:

1. In `renderPrompt` (`src/features/ai-agent/api/mcp-prompts.ts`), keep `validatePromptArgs` running on all non-empty values first so `month: " "` and `ledger: " "` stay refused as `BAD_USER_INPUT` (preserving `w31/011`'s contract), then omit any remaining argument whose `value?.trim() === ""` before calling `descriptor.build`.
2. Add regression cases in `src/features/ai-agent/api/__tests__/mcp-prompt-empty-args.test.ts` asserting that whitespace-only `"   "` / `"\t\n"` on `account`, `period`, `statement`, `item_id`, and `question` renders identically to omitting the argument, while `month: " "` and `ledger: " "` still refuse with `BAD_USER_INPUT`.

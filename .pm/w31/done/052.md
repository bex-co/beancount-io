# `importStagedBankTransactions` (`POST .../bank-transactions/submit`, GraphQL `submitPlaidTransactionsToLedger`) accepts blank/malformed `targetAccount`, `sourceAccount`, and unsafe/blank `filename` instead of refusing upfront with `BAD_USER_INPUT`

**Minor · backend-v2 (`PlaidSyncService.submitTransactionsToLedger`) · 30–45m · A1.** Passing blank or syntactically invalid Beancount account names for `targetAccount` (`""`, `"   "`, `"not-an-account"`), blank or malformed `sourceAccount` (`"   "`, `"bad account"`), or blank/traversal `filename` (`"   "`, `"../etc/passwd"`, `".git/config"`) passes input validation across MCP, REST, and GraphQL, proceeding through PDP authorization, Fava ledger resolution, and Postgres queries (returning `"Some transactions not found in database"` for unknown IDs, or — on real staged transactions — building malformed Beancount postings in `buildBeancountTransaction`, overriding a valid mapped account when `sourceAccount` is whitespace `"   "` because `"   "` is truthy in `input.sourceAccount || account?.ledgerAccount`, or passing an unvalidated path to `getLedgerFile`). Direct sibling of `w31/050` (which added `lexesAsAccount` validation to `mapBankAccount` / `setBankAccountCurrency`). Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`) on 2026-11-23 against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, checked against HEAD `4b8cf4693`). Credential: unpinned read/write/admin `bcio_` key on `<qa-owner>/mcp-agent-eval`; `dry_run: true` probes only, no ledger or bank state modified.

## Repro (live)

Reproduced across all three surfaces with `dry_run: true` and synthetic non-existent `transactionId: "ptxn_nonexistent"` on `<qa-owner>/mcp-agent-eval`:

1. **Invalid `targetAccount`** (`"   "`, `"not-an-account"`):
   ```sh
   node .agents/skills/qa-shared/scripts/qa-mcp.mjs call importStagedBankTransactions '{"ledger":"<qa-owner>/mcp-agent-eval","transactions":[{"transactionId":"ptxn_nonexistent","targetAccount":"   "}],"dry_run":true}'
   node .agents/skills/qa-shared/scripts/qa-mcp.mjs call importStagedBankTransactions '{"ledger":"<qa-owner>/mcp-agent-eval","transactions":[{"transactionId":"ptxn_nonexistent","targetAccount":"not-an-account"}],"dry_run":true}'
   ```
   - **MCP**: HTTP `200`, `isError: true`, `BAD_USER_INPUT`: `"Some transactions not found in database"`.
   - **REST** (`POST /api-gateway/v1/ledgers/<qa-owner>/mcp-agent-eval/bank-transactions/submit?dry_run=true`): HTTP `400`, `BAD_USER_INPUT`: `"Some transactions not found in database"`.
   - **GraphQL** (`mutation { submitPlaidTransactionsToLedger(ledgerId: "<qa-owner>/mcp-agent-eval", transactions: [...], dryRun: true) { success } }`): HTTP `200`, `BAD_USER_INPUT`: `"Some transactions not found in database"`.
2. **Invalid `sourceAccount`** (`"   "`, `"bad account"` with valid `targetAccount: "Expenses:Food:Groceries"`):
   - **MCP / REST / GraphQL**: all reach DB lookup and return `BAD_USER_INPUT`: `"Some transactions not found in database"`.
3. **Unsafe or blank `filename`** (`"../etc/passwd"`, `"   "` with valid `targetAccount: "Expenses:Food:Groceries"`):
   - **MCP / REST / GraphQL**: all reach DB lookup and return `BAD_USER_INPUT`: `"Some transactions not found in database"`.

Expected: refused upfront with `BAD_USER_INPUT` naming `targetAccount`, `sourceAccount`, or `filename` before authorization, Fava ledger lookup, or Postgres queries on MCP, REST (`400`), and GraphQL.

## Working controls

- On the exact same operation across MCP, REST, and GraphQL, passing `transactionId: "   "` is refused upfront before authorization and DB lookup with `BAD_USER_INPUT`: `"transactionIds must not be empty"` (via `assertBankIds`).
- Sibling `PlaidItemService.updateAccountMapping` (`w31/050`, commit `7d58187f6`) validates `ledgerAccount` with `lexesAsAccount` before authorization or lookup.
- Dashboard (`dashboard/src/features/plaid/components/transaction-review-table.tsx:213`) already filters out empty `targetAccount` and `sourceAccount` client-side.

## Root cause

Not deployment lag — present at HEAD `4b8cf4693`:

- `backend-cluster/backend-v2/src/features/plaid/service/plaid-sync-service.ts:714-802` (`PlaidSyncService.submitTransactionsToLedger`):
  - Only checks `transactionInputs.length === 0` (`:727`) and `assertBankIds(transactionIds, "transactionIds")` inside `loadAuthorizedTransactionBatch` (`:223`).
  - Never validates each item's `targetAccount` or optional `sourceAccount` with `lexesAsAccount` (`@/features/ledger/utils/account-matcher`).
  - At `:765`, `const sourceAccount = input.sourceAccount || account?.ledgerAccount;` treats whitespace `"   "` as truthy, overriding the bank account's valid mapped account with `"   "`, and passes both unvalidated strings into `buildBeancountTransaction` (`src/features/plaid/utils/plaid-mapper.ts:48,56`).
  - Never validates `filename` with `assertSafeRepoPath` (`@/features/ledger/utils/safe-repo-path`) or rejects blank `filename` (`""` is silently ignored as falsy at `:790`, falling back to `main.bean`; `"../etc/passwd"` and `"   "` pass straight to `favaApiClient.ledgers.getLedgerFile` at `:791`).
- Neither MCP (`src/features/ai-agent/tools/bank-import-tool.ts:185-229`), REST (`src/features/ledger/api/rest/v1/banks-handler.ts:246-272`), nor GraphQL (`src/features/plaid/api/resolvers/plaid-resolver.mutation.ts:244-276`) validates `targetAccount`, `sourceAccount`, or `filename` syntax.

## Fix

In `backend-cluster/backend-v2`:

1. Extract or share the Beancount account validator (`lexesAsAccount` from `@/features/ledger/utils/account-matcher`, matching `assertBankLedgerAccount` in `src/features/plaid/service/plaid-item-service.ts:46-54`) so `PlaidItemService` and `PlaidSyncService` apply one rule.
2. At the entry of `PlaidSyncService.submitTransactionsToLedger` (`src/features/plaid/service/plaid-sync-service.ts:726`), right after `transactionInputs.length === 0` and before `loadAuthorizedTransactionBatch(...)` (so invalid syntax is refused before authorization, Fava lookup, and Postgres reads, while valid inputs keep `FORBIDDEN` before lookup per `w23/024`):
   - Validate every item's `targetAccount` with `lexesAsAccount`; refuse empty, whitespace-only, or malformed values with `BadUserInputError` (field `"targetAccount"`, example hint `"Expenses:Food:Groceries"`).
   - Whenever `input.sourceAccount !== undefined`, validate `input.sourceAccount` with `lexesAsAccount`; refuse empty, whitespace-only, or malformed values with `BadUserInputError` (field `"sourceAccount"`, example hint `"Assets:Bank:Checking"`).
   - Whenever `filename !== undefined` (note: GraphQL passes `undefined` when omitted or `null` when explicitly null — normalize `null` only if GraphQL nullable requires it; verify how `submitPlaidTransactionsToLedger` handles `filename: null` vs `""`), validate `filename` with `assertSafeRepoPath(filename, "filename")` and reject whitespace-only `filename.trim() === ""` with `BadUserInputError("File path must not be empty", "filename")`.
3. Add unit tests in `src/features/plaid/service/__tests__/plaid-sync-service.test.ts` and 3-surface adapter parity tests (MCP `importStagedBankTransactions`, REST `POST /api-gateway/v1/ledgers/{owner}/{name}/bank-transactions/submit`, GraphQL `submitPlaidTransactionsToLedger`) covering invalid `targetAccount`, invalid `sourceAccount`, and unsafe/blank `filename`, asserting `BAD_USER_INPUT` and zero calls to authorization, Fava, or Postgres, while verifying that valid inputs with a read-only token still return `FORBIDDEN` before DB lookup.
4. If `banks-handler.ts` Zod schemas are also tightened, regenerate `docs/openapi/v1.json` and re-pin `cli/openapi/v1.json` (`make spec-sync && make codegen` in `cli/`) in the same change.

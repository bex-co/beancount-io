# 092 — `w23/219` silently broke internal `dryRun` pre-write guards (`w21/683` and `w23/058` regressions): refused `addLedgerEntries` creates orphan routed files + commits, and refused `insertReceiptTransaction` promotes/commits receipts before refusing

**Severity:** major. **Owner:** `backend-cluster/backend-v2` (`src/features/ledger/service/ledger-entry-service.ts`, `src/features/ledger/workflow/ledger-receipt-workflow.ts`; REST, GraphQL, MCP). **Estimate:** ~45–60m. **Pillar:** A1.

Found by `qa-find-bugs-mcp` on 2026-11-24 against production (`https://beancount.io/api-gateway/mcp`, `beancount-mcp` 1.0.0, protocol `2025-11-25`, local HEAD `65e5e5942`, unpinned read/write key, synthetic ledger `<owner>/mcp-agent-eval`). Confirmed still present at HEAD `65e5e5942`.

## Repro

### A. Refused routed `addLedgerEntries` / REST `POST …/entries` creates orphan empty files and `"chore: create file"` commits (`w21/683` regression)

Setup: add `2000-01-01 custom "beancountio-option" "transaction_file" "qa-route/{year}.bean"` to `main.bean` (where `qa-route/2099.bean` and `qa-route/2098.bean` do not exist).

1. **MCP `addLedgerEntries`** with an unbalanced `2099-01-15` transaction (`Expenses:Food:Groceries 10.00 USD`, `Assets:Cash -5.00 USD`, `dry_run` omitted, `allowInvalid` omitted):
   - Response: `isError: true`, `UNBALANCED`: `"entry 0: Transaction does not balance: residual 5.00 USD"`.
   - **Actual side effect:** `listLedgerFiles(dir_path: "qa-route")` now contains `qa-route/2099.bean` (`size: 0`, empty blob `e69de29…`), and `beancount://ledgers/{owner}/{name}/latest-commit` is a new commit with message `"chore: create file\n"`.
2. **REST `POST /api-gateway/v1/ledgers/{owner}/{name}/entries`** with a `2098-01-15` transaction referencing unopened account `Expenses:NotOpened`:
   - Response: HTTP `400`, `VALIDATION_FAILED`: `"Account Expenses:NotOpened was never opened (qa-route/2098.bean:2)"`.
   - **Actual side effect:** `listLedgerFiles(dir_path: "qa-route")` now also contains `qa-route/2098.bean` (`size: 0`) with a second `"chore: create file\n"` commit.
3. **Working control (MCP `appendLedgerText`)** with the same unbalanced transaction dated `2096-01-15`:
   - Response: `isError: true`, `UNBALANCED` (`qa-route/2096.bean:1`).
   - Side effect: **none** — `qa-route/2096.bean` is not created and no commit is added.

Expected: a refused `addLedgerEntries` / `POST …/entries` / GraphQL `bulkEntries` call is side-effect free and leaves the repo's file list and commit history unchanged (as `w21/683` required).

### B. Refused `insertReceiptTransaction` bypasses its pre-write guard on all three surfaces (`w23/058` regression)

On a ledger using default S3 receipt storage (zero-write probe using a nonexistent caller-owned key `tmp/<userId>/nonexistent.png` and an unbalanced transaction `Expenses:Food:Groceries 10.00 USD` / `Assets:Cash -5.00 USD`, `documentAccount: "Expenses:Food:Groceries"`):

1. **MCP `insertReceiptTransaction`**: returns `isError: true`, `NOT_FOUND` (`"Temporary asset not found"`) instead of refusing `UNBALANCED` up front.
2. **REST `POST /api-gateway/v1/ledgers/{owner}/{name}/import/insert-receipt`**: returns HTTP `404`, `NOT_FOUND` (`"Temporary asset not found"`) instead of `400 UNBALANCED`.
3. **GraphQL `Mutation.insertReceiptTransaction`**: returns `NOT_FOUND` (`"Temporary asset not found"`) instead of `UNBALANCED`.

Actual: the pre-write `dryRun` check returned `200 OK` (`valid: false`) instead of throwing, so `s3Strategy` proceeded directly to `copyTempToPermanent`. With a real uploaded temp asset, `copyTempToPermanent` succeeds and orphans a permanent S3 copy under `repo_<id>` on every refused retry (there is no S3 compensating delete). Under `receipt_storage: "git"`, `gitStrategy` likewise bypasses its pre-check, fetches and commits `docs: add receipt …` to Git, fails on the second write, and adds a second cleanup commit removing it on every refused call.

Expected: unbalanced or invalid receipt entries are refused up front (`UNBALANCED` / `VALIDATION_FAILED`) before touching S3 or Git, leaving zero orphan assets and zero stray Git commits (as `w23/058` required).

## Root cause

Commit `5051f640e` (`w23/219`, "previews report new bean-check errors with a valid flag instead of refusing") changed `FavaLedgerEntryWriter.addEntries` in `backend-cluster/backend-v2/src/features/ledger/service/ledger-entry-service.ts:1097`:

```ts
allowInvalid: allowInvalid || dryRun,
...(dryRun && { dryRun }),
```

In `backend-cluster/ledger/src/api/entries.ts:286,426`, `allowInvalid: true` disables both the balance check (`UNBALANCED`) and `refuseProjectedErrors` (`VALIDATION_FAILED`), so the ledger service answers HTTP `200` with `new_errors` instead of refusing.

Three internal pre-write guards rely on `dryRun: true` throwing on `UNBALANCED` / `VALIDATION_FAILED` and discard the return value:

1. `backend-cluster/backend-v2/src/features/ledger/service/ledger-entry-service.ts:743-751` (`writeBulkEntries` missing-routed-file guard from `w21/683`) — calls `await this.addEntries(..., allowInvalid, true)` before `this.createFile(...)` (`:752-754`).
2. `backend-cluster/backend-v2/src/features/ledger/workflow/ledger-receipt-workflow.ts:252-260` (`gitStrategy` pre-check from `w23/058`) — calls `await this.ledgerEntryWriter.writeBulkEntries(..., false, true)` before `createLedgerFile` (`:292-309`).
3. `backend-cluster/backend-v2/src/features/ledger/workflow/ledger-receipt-workflow.ts:383-391` (`s3Strategy` pre-check from `w23/058`) — calls `await this.ledgerEntryWriter.writeBulkEntries(..., false, true)` before `copyTempToPermanent` (`:400-403`).

Unit tests missed the regression because `ledger-entry-service.test.ts:1045-1046` mocked `mockAddBulkEntries.mockResolvedValueOnce(failResponse)` directly (never checking `allowInvalid` on the outgoing request), and `receipt-insert-parity.test.ts` / `ledger-receipt-resolver.test.ts:247` mocked `writeBulkEntries` directly to throw `UnbalancedTransactionError`.

## Fix

Separate **caller-facing preview** (`w23/219`: `dryRun: true` sends `allowInvalid: true` so previews report `valid: false` + `newErrors` without refusing) from **internal pre-write validation** (strict `dryRun: true` that forwards the caller's `allowInvalid` without forcing it to `true`, so the ledger refuses `UNBALANCED` and `VALIDATION_FAILED` before any file creation, Git commit, or S3 promotion):

1. In `FavaLedgerEntryWriter.addEntries` (`ledger-entry-service.ts:1075-1104`) and `writeBulkEntries` (`:576,743-751`), distinguish caller preview mode from strict validate-only mode (e.g., an option such as `refuseOnError?: boolean` or a dedicated `validateEntries` / `strictDryRun` mode) so:
   - User-facing `addBulkEntries(..., dryRun: true)` keeps `w23/219` behavior (`allowInvalid: true`, returns `valid: false` + `newErrors` without refusing).
   - `writeBulkEntries`'s missing-file pre-check (`:743-751`) sends `dryRun: true, allowInvalid` (respecting the caller's `allowInvalid`, never forcing `true`).
   - `LedgerReceiptWorkflow`'s `gitStrategy` (`:252-260`) and `s3Strategy` (`:383-391`) pre-checks send `dryRun: true, allowInvalid: false`.
2. Add regression tests that actually assert the outgoing `addBulkEntries` request payload carries `dryRun: true, allowInvalid: false` (and not `allowInvalid: true`) for:
   - `ledger-entry-service.test.ts`: missing routed target refusal (`w21/683`) AND caller-facing `dryRun: true` preview (`w23/219`).
   - `receipt-insert-parity.test.ts` / `ledger-receipt-resolver.test.ts` (or a wired `FavaLedgerEntryWriter` test): `LedgerReceiptWorkflow` pre-check on both S3 and Git strategies sends `dryRun: true, allowInvalid: false` and throws before `copyTempToPermanent` / `createLedgerFile`.

# A raw comma in an MCP resource path value (`payee-transactions/Acme, Inc.`) answers `NOT_FOUND` "No resource template matches that URI", while `&`, `'`, `(`, `;` and `=` read as themselves and REST takes the same comma

**Minor · backend-v2 (`src/features/ai-agent/api/mcp-resource-template.ts`) · 20–30m · A1.** Payees and narrations often contain a comma ("Amazon.com, Inc.", "Smith, John", "Coffee, pastry"). On MCP, `payee-transactions/{payee}` and `payee-accounts/{payee}` take the payee only in the path. A path value with a raw comma matches no template, so the read is answered by the catch-all as `NOT_FOUND`, with the hint "No resource template matches that URI. Call `resources/templates/list` for the inventory". The agent lists the templates and finds the one it used. Every other RFC 3986 sub-delimiter is accepted raw in the same position. The REST twin takes the payee as a query parameter, and a raw comma there works. Percent-encoding the comma as `%2C` works on MCP, so only a hand-written URI fails, and the error points the agent the wrong way.

## Repro (synthetic)

With a transaction whose payee is `qa-20261127-Acme, Inc.`:

1. `resources/read beancount://<owner>/<name>/payee-transactions/qa-20261127-Acme,%20Inc.` → JSON-RPC `-32002`, `data.code: "NOT_FOUND"`, "Resource with ID '…' not found", hint "No resource template matches that URI …".
2. The same URI with `%2C` for the comma returns the transaction.
3. `payee-accounts/qa-20261127-Acme,%20Inc.` → the same `NOT_FOUND`. The `narration-transactions/{narration}` path alias does the same with `Transit,pass`, while the query form `narration-transactions?narration=Transit,pass` reads (`null`).
4. No write needed: `payee-transactions/No,Such` → `NOT_FOUND` "No resource template matches", while `payee-transactions/No%2CSuch` → `null`, the documented answer for an unmatched payee.
5. `payee-transactions/A&B`, `payee-transactions/O'Brien`, `payee-transactions/(x)` and `payee-transactions/a;b=c` each read as that payee (`null`).
6. REST `GET /api-gateway/v1/ledgers/{owner}/{name}/payee-transactions?payee=qa-20261127-Acme,%20Inc.` → 200 with the transaction. `?payee=No,Such` → 200 `null`.

The same happens on every path variable (`register/Assets:Cash,x` and `account-report/Assets:Cash,x` also answer "No resource template matches"), but a comma is only realistic in a payee or a narration.

## Root cause

`QueryResourceTemplate.match` (`mcp-resource-template.ts:43`–`50`) matches the path part through the SDK's `UriTemplate.match`. In `@modelcontextprotocol/sdk` 1.32.2, `partToRegExp` gives a simple `{var}` the pattern `([^/,]+)` (`dist/esm/shared/uriTemplate.js`), which excludes the comma because RFC 6570 uses it to separate list values. A raw comma therefore ends the variable early and the path matches no template. The `resources/read` dispatcher in `composition-root.ts` (the `resourceReaders` loop) falls through to the `{+rest}` catch-all (`composition-root.ts:809`), which answers `NOT_FOUND`. No template on this server takes a list variable. Every path variable (`owner`, `name`, `payee`, `narration`, `account`, `accountName`, `entryHash`, `itemId`, `archive`) is one string, and every template is built through `queryTemplate` (`mcp-resources.ts:965`).

## Fix

In `QueryResourceTemplate.match`, let a simple path variable hold a comma. The smallest change is to percent-encode each raw `,` in the path part as `%2C` before calling the SDK matcher. The existing `decodeURIComponent` pass turns it back into `,`, so `payee-transactions/Acme, Inc.` and `payee-transactions/Acme%2C%20Inc.` read the same payee. `{+path}` already matches commas, so `files/…` is unchanged.

## Done when

- Repro steps 1, 3 and 4 return what their `%2C` forms return: the transaction, the ranked accounts, and `null`.
- `mcp-resource-template.test.ts` (or the resources-read suite) asserts that a raw comma and `%2C` read the same value for `payee-transactions/{payee}` and the `narration-transactions/{narration}` alias. A URI that still matches no template keeps its `NOT_FOUND`. With the change reverted, the new case fails.

**Resolved 2026-11-27** — A raw comma in an MCP resource path value is now part of the value, as it is in REST's query. backend-v2 (`mcp-resource-template.ts`): `QueryResourceTemplate.match` percent-encodes each raw `,` in the path part as `%2C` before the SDK's `UriTemplate.match`, whose simple `{var}` pattern `([^/,]+)` stops at a comma, and the existing `decodeURIComponent` pass turns it back into `,`. So `payee-transactions/Acme,%20Inc.`, `payee-accounts/Smith,%20John` and the `narration-transactions/Transit,pass` alias read the same payee or narration as their `%2C` forms and as REST's `?payee=` / `?narration=`, and `payee-transactions/No,Such` reads `null`, the documented answer for an unmatched payee. `files/{+path}` already took commas and reads the same file. A URI that matches no template keeps its `NOT_FOUND`. No API shape change.

- **Tests:** `analysis-parity.test.ts` adds "a raw comma in a resource path value (w31/142)": for `payee-transactions`, `payee-accounts` and the `narration-transactions` path alias, REST with a raw comma, MCP with a raw comma and MCP with `%2C` return the same body, and the service receives the same value all three times. With the fix reverted, all three fail with the repro's `NOT_FOUND` "No resource template matches that URI". `mcp-resources.test.ts` adds `nosuch/No,Such` to the unmatched URIs that answer a coded, hinted `NOT_FOUND`, and reads `files/a,b.beancount` and `files/a%2Cb.beancount` as the file `a,b.beancount`.
- **Checks:** backend-v2 `yarn typecheck`, `yarn format:check`, ESLint on the changed files, `yarn lint:deadcode` and `yarn test` (13,564 tests) pass, and `yarn generate-v1-openapi` leaves the snapshot unchanged.

**Not observable yet.** Production keeps the old answer until backend-v2 is redeployed.

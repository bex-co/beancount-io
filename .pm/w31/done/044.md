# Whitespace-only `requestId` (`"   "`) is accepted and cached for 24h across `createLedger`, `appendLedgerText`, `addLedgerEntries`, and `insertReceiptTransaction` on MCP, REST, and GraphQL

**Minor · backend-v2 (`entry-write-idempotency.ts`, `ledger-workflow.ts`) · 25–35m · A1.** Passing an empty string `requestId: ""` is refused (`VALIDATION_FAILED: requestId must be 1-200 characters`), but passing a whitespace-only string `requestId: "   "` is accepted across MCP, REST, and GraphQL on all four idempotent write operations (`createLedger`, `appendLedgerText`, `addLedgerEntries`, `insertReceiptTransaction`) — both on `dry_run: true` and on real commits, where it writes the whitespace-only key into Redis for 24 hours so any subsequent accidental blank-`requestId` call collides or replays the earlier write. Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 LAND=1`) on 2026-11-23 against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, checked against HEAD `d5b789be4`). Credential: unpinned read/write/admin `bcio_` key on the QA account. Synthetic ledger: `<qa-owner>/mcp-agent-eval` (entry probes used `dry_run: true`; the disposable ledger created by the `createLedger` probe was deleted immediately afterward and `listLedgers` verified clean).

## Repro (live)

Reproduced in fresh requests across MCP, REST, and GraphQL:

1. **MCP `appendLedgerText` and `addLedgerEntries` (`dry_run: true`):**
   ```sh
   node .agents/skills/qa-shared/scripts/qa-mcp.mjs call appendLedgerText '{"ledger":"<qa-owner>/mcp-agent-eval","text":"2026-08-25 note Assets:Cash \"x\"","dry_run":true,"requestId":"   "}'
   node .agents/skills/qa-shared/scripts/qa-mcp.mjs call addLedgerEntries '{"ledger":"<qa-owner>/mcp-agent-eval","entries":[{"type":"note","entry":{"date":"2026-08-25","account":"Assets:Cash","content":"x"}}],"dry_run":true,"requestId":"   "}'
   ```
   Actual: HTTP `200`, `ok: true` (`Would add 1 directive...` / `Would add 1 entry...`).
2. **MCP `createLedger`:**
   ```sh
   node .agents/skills/qa-shared/scripts/qa-mcp.mjs call createLedger '{"name":"qa-should-refuse-5","requestId":"   "}'
   ```
   Actual: HTTP `200`, `ok: true` — created the ledger and stored `"   "` as the 24-hour idempotency key. (Disposable ledger deleted right after.)
3. **REST `POST /api-gateway/v1/ledgers/<qa-owner>/mcp-agent-eval/directives/text` and `POST .../entries` (`dryRun: true`):**
   With `"requestId": "   "`: HTTP `200`, `success: true`.
4. **GraphQL `appendLedgerText` and `bulkEntries` (`dryRun: true`):**
   With `requestId: "   "`: HTTP `200`, `success: true`.

Expected: whitespace-only `requestId` is refused with `VALIDATION_FAILED` (`field: "requestId"`, e.g. `requestId must be 1-200 non-blank characters` or `requestId must not be blank`) before touching Redis or performing any write, identically on MCP, REST, and GraphQL (for both preview and commit).

## Working controls

- `requestId: ""` is refused across all three surfaces:
  - MCP `appendLedgerText`: `VALIDATION_FAILED` (`Validation failed for requestId: requestId must be 1-200 characters`).
  - REST `POST .../directives/text`: HTTP `400` `VALIDATION_FAILED` (`Validation failed for body.requestId: Too small: expected string to have >=1 characters`).
  - GraphQL `bulkEntries`: `VALIDATION_FAILED` (`Validation failed for requestId: requestId must be 1-200 characters`).
- A non-blank `requestId` (`"qa-20261123-append-..."`) replays the first result on identical retry and refuses a different payload with `VALIDATION_FAILED`.

## Root cause

Not deployment lag — present at HEAD `d5b789be4`:

- `backend-cluster/backend-v2/src/features/ledger/utils/entry-write-idempotency.ts:82`: `if (requestId.length < 1 || requestId.length > ENTRY_REQUEST_ID_MAX)` checks raw `.length` without checking `requestId.trim().length < 1`. This helper backs `appendLedgerText`, `addLedgerEntries`, and `insertReceiptTransaction` across MCP, REST, and GraphQL.
- `backend-cluster/backend-v2/src/features/ledger/workflow/ledger-workflow.ts:744-752`: `if (input.requestId != null && (input.requestId.length < 1 || input.requestId.length > CREATE_REQUEST_ID_MAX))` has the same omission for `createLedger` across MCP, REST, and GraphQL.
- `backend-cluster/backend-v2/src/features/ledger/api/rest/v1/request-id-body.ts:8-13` and `src/features/ledger/api/rest/v1/lifecycle-handler.ts:132`: `z.string().min(1).max(ENTRY_REQUEST_ID_MAX).nullish()` only checks raw string length; `mcpRequestId` (`src/features/ai-agent/api/mcp-ledger-selection.ts:45`) is `z.string().optional()`.

## Fix

In `backend-cluster/backend-v2`:

1. In `src/features/ledger/utils/entry-write-idempotency.ts:82` (`runIdempotentEntryWrite`) and `src/features/ledger/workflow/ledger-workflow.ts:744` (`LedgerWorkflow.createLedger`), refuse whitespace-only `requestId` (`requestId.trim().length < 1`) with `ValidationError("requestId", ...)` alongside the existing `1–200` character check (consider extracting one shared `assertRequestId(requestId)` helper so both paths cannot drift). Do not silently trim `requestId` (an agent sending `"   "` should learn its key was blank rather than silently losing idempotency).
2. Add unit tests in `src/features/ledger/service/__tests__/entry-write-request-id.test.ts` and the `createLedger` workflow tests, plus 3-surface parity cases across MCP, REST, and GraphQL verifying `requestId: "   "` is refused on preview and commit without touching Redis or creating/writing anything.

**Resolved 2026-11-23** — Extracted shared `assertRequestId(requestId)` in `backend-cluster/backend-v2/src/features/ledger/utils/entry-write-idempotency.ts` and called it from both `runIdempotentEntryWrite` and `LedgerWorkflow.createLedger` (`backend-cluster/backend-v2/src/features/ledger/workflow/ledger-workflow.ts`) before touching Redis or performing any write.

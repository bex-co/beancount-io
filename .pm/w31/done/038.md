# `listBankConnections` and `setLedgerStar` (and every `requireScopeClass` denial) return the generic ledger-metadata `FORBIDDEN` hint instead of naming the missing scope

**Minor · backend-v2 (scope gate / `op-class.ts`) · 20–30m · A1.** Multi-verb MCP tools (`listBankConnections`, `setLedgerStar`) and non-PDP `session-only` operations are denied by `requireScopeClass` without a `hint`, so MCP falls back to `CATEGORY_HINTS.FORBIDDEN` (`Check beancount://{owner}/{name}/metadata for your permission on the ledger`) instead of naming the required scope or credential type — contradicting `docs/mcp.md` and every other write/admin tool and resource. Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`) on 2026-11-23 against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, checked against HEAD `fa02bce80`). Credential: unpinned `ledger.read` `bcio_` key on the QA account. Synthetic ledger: `<qa-owner>/mcp-agent-eval`.

## Repro (live)

Reproduced in fresh requests using a `ledger.read`-only `bcio_` key against `<qa-owner>/mcp-agent-eval`:

1. **MCP `listBankConnections`**:
   ```sh
   node .agents/skills/qa-shared/scripts/qa-mcp.mjs \
     --credentials-file <(sed -n 's/^QA_MCP_READ_ONLY_TOKEN=/QA_MCP_TOKEN=/p' .env) \
     call listBankConnections '{"ledger":"<qa-owner>/mcp-agent-eval"}'
   ```
   Actual: HTTP `200`, `isError: true`, `structuredContent.error`:
   `code: "FORBIDDEN"`, `message: 'This operation requires the "ledger.admin" scope (MCP listBankConnections)'`, `hint: 'This credential lacks the authority for that operation. Check \`beancount://{owner}/{name}/metadata\` for your permission on the ledger.'`
2. **MCP `setLedgerStar`**:
   ```sh
   node .agents/skills/qa-shared/scripts/qa-mcp.mjs \
     --credentials-file <(sed -n 's/^QA_MCP_READ_ONLY_TOKEN=/QA_MCP_TOKEN=/p' .env) \
     call setLedgerStar '{"ledger":"<qa-owner>/mcp-agent-eval","starred":true}'
   ```
   Actual: HTTP `200`, `isError: true`, `structuredContent.error`:
   `code: "FORBIDDEN"`, `message: 'This operation requires the "ledger.write" scope (MCP setLedgerStar)'`, `hint: 'This credential lacks the authority for that operation. Check \`beancount://{owner}/{name}/metadata\` for your permission on the ledger.'`

Expected: `hint` names the required scope (`Use a credential that holds the "ledger.admin" scope.` / `Use a credential that holds the "ledger.write" scope.`), matching `docs/mcp.md` ("The hint names what would be accepted — the credential types or scope the operation takes...") and every PDP-routed tool, resource, REST route, and GraphQL field.

## Working controls

With the exact same `ledger.read` credential on `<qa-owner>/mcp-agent-eval`:

- MCP `beancount://<qa-owner>/mcp-agent-eval/banks` and `bank-accounts` (the two resources `listBankConnections` combines): `FORBIDDEN`, `hint: 'Use a credential that holds the "ledger.admin" scope.'`
- REST `GET /api-gateway/v1/ledgers/<qa-owner>/mcp-agent-eval/banks`: HTTP `403`, `metadata.hint: 'Use a credential that holds the "ledger.admin" scope.'`
- REST `PUT /api-gateway/v1/ledgers/<qa-owner>/mcp-agent-eval/star`: HTTP `403`, `metadata.hint: 'Use a credential that holds the "ledger.write" scope.'`
- GraphQL `starLedger(ledgerId: "<qa-owner>/mcp-agent-eval") { success }`: `extensions.code: "FORBIDDEN"`, `extensions.hint: 'Use a credential that holds the "ledger.write" scope.'`
- Every single-action write/admin MCP tool (`appendLedgerText`, `updateLedger`, `reconcileBankAccounts`, etc.): `FORBIDDEN`, `hint: 'Use a credential that holds the "ledger.write" scope.'` / `"ledger.admin"`.

## Root cause

Not deployment lag — present at HEAD `fa02bce80`:

- `w1/206` added scope and credential-type hints inside `AuthorizationService` (`backend-cluster/backend-v2/src/server/api/authorization/authorization-service.ts:945-948`), which covers operations carrying a single `authorizationAction` that pass through `evaluateScope` (`op-class.ts:2150-2152`) into the PDP.
- Multi-verb tools (`MCP listBankConnections`, `MCP setLedgerStar`) and non-PDP `session-only` operations carry no single `authorizationAction`, so `requireScopeClass` denies them directly at `backend-cluster/backend-v2/src/server/api/op-class.ts:2153-2175,2228-2231`:
  ```ts
  throw new ForbiddenError(
    `${decision.denyReason} (${decision.opId})`,
    decision.opId,
  );
  ```
- `ForbiddenError` accepts an optional 3rd `hint?: string` parameter (`src/shared/errors/domain-errors.ts:85`), but `requireScopeClass` never supplies one. On MCP, `mcp-errors.ts:90-91` therefore falls back to `CATEGORY_HINTS.FORBIDDEN` (pointing at `beancount://{owner}/{name}/metadata`), and REST/GraphQL emit no `hint` on non-PDP `requireScopeClass` refusals either.

## Fix

In `backend-cluster/backend-v2`:

1. Add an optional `hint?: string` field to `ScopeDecision` in `src/server/api/op-class.ts` and populate it in `evaluateScope`:
   - Missing scope (`!identityHasCapability(identity, opClass)`): `Use a credential that holds the "${requiredScope}" scope.`
   - Session-only (`requiredScope === null`): `This operation accepts a signed-in browser session.`
2. Pass `decision.hint` as the 3rd argument to `new ForbiddenError(`${decision.denyReason} (${decision.opId})`, decision.opId, decision.hint)` in `requireScopeClass` (`src/server/api/op-class.ts:2228-2231`). Preserve the existing message format (`op-class.test.ts:575`).
3. Add unit tests in `src/server/api/__tests__/op-class.test.ts` (both missing-scope and session-only hints) and MCP adapter tests in `src/server/api/__tests__/scope-enforcement.test.ts` verifying that `listBankConnections` and `setLedgerStar` emit the scope hint rather than the `metadata` fallback.

**Done when:**

- A `ledger.read` credential calling `listBankConnections` receives `FORBIDDEN` with `hint: 'Use a credential that holds the "ledger.admin" scope.'`, and calling `setLedgerStar` receives `FORBIDDEN` with `hint: 'Use a credential that holds the "ledger.write" scope.'`.
- Non-PDP `session-only` denials from `requireScopeClass` carry `hint: "This operation accepts a signed-in browser session."` across MCP, REST, and GraphQL.
- New unit and adapter tests fail with the `hint` omitted and pass with it set.
- `yarn typecheck`, `yarn lint:deadcode`, `yarn format:check`, `yarn test`, and `yarn generate-v1-openapi` pass in `backend-cluster/backend-v2/`.

Dedupe: searched `.pm/**` (open, done, blocked) for `requireScopeClass`, `MCP listBankConnections`, and `MCP setLedgerStar`. `w1/206` added hints in `AuthorizationService` (PDP-routed ops only), and `w23/137` intersected `metadata.permissions` with credential capabilities; neither covered `requireScopeClass` denials in `op-class.ts`.

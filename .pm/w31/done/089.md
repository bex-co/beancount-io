# `previewLedgerSetup` / `createLedger` emits alphabetical-order-dependent `bcio_opening_balance_status` on `Equity:OpeningBalances` when a known opening exists, stamping a posted counter account `"zero"` across MCP, REST, and GraphQL

**Minor · backend-v2 (`src/features/ledger/setup/build-ledger.ts`) · 15–25m · A1.** `previewLedgerSetup` and `buildLedgerFiles` (`src/features/ledger/setup/build-ledger.ts:361-415`) sort selected accounts alphabetically before emitting `open` directives and opening balance transactions. When a setup includes both a `known` opening balance and an explicit `Equity:OpeningBalances` entry (with `openingState: "zero"` or `"unknown"` / omitted), the generated `main.bean` depends on whether any `known` account sorts alphabetically before `"Equity:OpeningBalances"`:

- With `Assets:Checking` (`known`, `"100"`) + `Equity:OpeningBalances` (`zero`), `"Assets:Checking" < "Equity:OpeningBalances"`, so processing `Assets:Checking` implicitly opens `Equity:OpeningBalances` (`:400-403`) with no metadata and adds it to `opened`; when the loop reaches `Equity:OpeningBalances`, `if (opened.has(account.name)) continue;` (`:389`) silently drops `bcio_opening_balance_status: "zero"`.
- With `Liabilities:Card` (`known`, `"50"`) + `Equity:OpeningBalances` (`zero`), `"Equity:OpeningBalances" < "Liabilities:Card"`, so `Equity:OpeningBalances` is processed first and emitted **with `bcio_opening_balance_status: "zero"`**, immediately followed by `2025-12-31 * "Opening balance"` posting `Equity:OpeningBalances 50 USD` — stamping a non-zero counter account as confirmed zero!

`w23/048` already established that `Equity:OpeningBalances` is the counter account of every known opening (refusing `openingState: "known"` on it at `:298-302` and stripping its currency constraint when `hasKnownOpening` is true at `:380`), but left its `bcio_opening_balance_status` metadata order-dependent across MCP (`previewLedgerSetup` / `createLedger`), REST (`POST /api-gateway/v1/ledgers/setup/preview` / `POST /api-gateway/v1/ledgers`), and GraphQL (`Query.previewLedgerSetup` / `Mutation.createLedger`).

## Expected / Actual

- **Expected:** `Equity:OpeningBalances` behaves identically regardless of whether the `known` account is an `Assets:*` account or a `Liabilities:*` account, and when `hasKnownOpening` is true it is never stamped with a contradictory `bcio_opening_balance_status: "zero"` (or alphabetical-order-dependent `"unknown"`) metadata line above the opening balance transaction that posts to it.
- **Actual:** All three surfaces (MCP, REST HTTP `200`, GraphQL HTTP `200`) return different `Equity:OpeningBalances` directives depending solely on alphabetical sort order:
  - **Payload 1 (`Assets:Checking` + `Equity:OpeningBalances` `zero`):**
    ```beancount
    2025-12-31 open Assets:Checking
    2025-12-31 open Equity:OpeningBalances

    2025-12-31 * "Opening balance"
      Assets:Checking 100 USD
      Equity:OpeningBalances -100 USD

    2026-01-01 balance Assets:Checking 100 USD
    ```
  - **Payload 2 (`Liabilities:Card` + `Equity:OpeningBalances` `zero`):**
    ```beancount
    2025-12-31 open Equity:OpeningBalances
      bcio_opening_balance_status: "zero"
    2025-12-31 open Liabilities:Card

    2025-12-31 * "Opening balance"
      Liabilities:Card -50 USD
      Equity:OpeningBalances 50 USD

    2026-01-01 balance Liabilities:Card -50 USD
    ```
  - Same order-dependent split occurs for `openingState: "unknown"` (explicit or defaulted when `{ name: "Equity:OpeningBalances" }` is passed without `openingState`).

## Root cause

`backend-cluster/backend-v2/src/features/ledger/setup/build-ledger.ts:361-415`:

```ts
const accounts = [...selected.values()].sort((a, b) =>
  a.name.localeCompare(b.name),
);
const opened = new Set<string>();
...
for (const account of accounts) {
  if (opened.has(account.name)) continue;
  ...
  lines.push(openLine(account.name, account.currency));
  opened.add(account.name);
  if (account.openingState === "unknown") {
    lines.push(`  ${openingStatusKey}: "unknown"`);
  } else if (account.openingState === "zero") {
    lines.push(`  ${openingStatusKey}: "zero"`);
  }
  if (account.openingState === "known" && account.amount) {
    ...
    if (!opened.has(OPENING_EQUITY)) {
      lines.push(openLine(OPENING_EQUITY));
      opened.add(OPENING_EQUITY);
    }
```

1. Because `accounts` is iterated in alphabetical order, any `known` account whose name starts with `A`–`D` (all `Assets:*`) implicitly emits `open Equity:OpeningBalances` with no metadata (`:401`) and marks it in `opened`, causing the later loop iteration for `Equity:OpeningBalances` to `continue` at `:389` without emitting `bcio_opening_balance_status`.
2. When every `known` account sorts after `"Equity:OpeningBalances"` (e.g. `Liabilities:*`, or `Assets:*` is `unknown` while `Liabilities:*` is `known`), `Equity:OpeningBalances` is emitted first at `:391-397` **with** `bcio_opening_balance_status: "zero"` (or `"unknown"`), even though `hasKnownOpening` is `true` and lines `:405-410` immediately post non-zero opening entries to it.

## Fix

Owning package: `backend-cluster/backend-v2`. Shared builder change updates all eligible preview and create surfaces together (MCP `previewLedgerSetup` / `createLedger`, REST `POST /api-gateway/v1/ledgers/setup/preview` / `POST /api-gateway/v1/ledgers`, GraphQL `Query.previewLedgerSetup` / `Mutation.createLedger`).

1. In `backend-cluster/backend-v2/src/features/ledger/setup/build-ledger.ts:393-397`, omit `bcio_opening_balance_status` on `OPENING_EQUITY` whenever `hasKnownOpening` is `true` (matching `:380`'s `name === OPENING_EQUITY && hasKnownOpening` guard for currency constraints), so `Equity:OpeningBalances` is opened cleanly without contradictory `"zero"` or order-dependent `"unknown"` metadata regardless of whether the known opening is on `Assets:*` or `Liabilities:*`:
   ```ts
   if (!(account.name === OPENING_EQUITY && hasKnownOpening)) {
     if (account.openingState === "unknown") {
       lines.push(`  ${openingStatusKey}: "unknown"`);
     } else if (account.openingState === "zero") {
       lines.push(`  ${openingStatusKey}: "zero"`);
     }
   }
   ```
   - Also check whether `Equity:OpeningBalances` should be opened in a consistent position or if keeping the alphabetical position (just without the contradictory metadata) preserves all existing conformance fixtures (`build-ledger.test.ts:173-191`, `:633-708`, `:763-781`, `:1007-1067`) — verify existing fixtures stay byte-identical.
2. Add regression tests in `src/features/ledger/setup/__tests__/build-ledger.test.ts` (and verify `setup-surfaces.test.ts` covers preview parity across MCP, REST, GraphQL) asserting that:
   - `Liabilities:Card` (`known`, `"50"`) + `Equity:OpeningBalances` (`zero`) and `Liabilities:Card` (`known`, `"50"`) + `Equity:OpeningBalances` (`unknown` / omitted) do **not** emit `bcio_opening_balance_status` on `Equity:OpeningBalances`, matching `Assets:Checking` (`known`, `"100"`) + `Equity:OpeningBalances` (`zero` / `unknown`),
   - `Equity:OpeningBalances` with `openingState: "zero"` or `"unknown"` when **no** account has `openingState: "known"` (`hasKnownOpening === false`) keeps its existing behavior.
3. Run `yarn typecheck`, `yarn lint:deadcode`, `yarn format:check`, `yarn test`, and `yarn generate-v1-openapi` in `backend-cluster/backend-v2/`.

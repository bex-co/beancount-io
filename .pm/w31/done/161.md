# BQL `description` joins an empty payee or narration with ` | `: `"EDISON POWER" ""` reads `EDISON POWER | ` and `"" "empty payee"` reads ` | empty payee`, where stock beanquery reads `EDISON POWER` and `empty payee`, on MCP, REST and GraphQL

**Minor · ledger (BQL results of the pinned `@rustledger/wasm` 0.24.0, served by `src/features/ledger/service/ledger-shell-service.ts`) · 20–30m in this repo, the rest upstream · A1.** Found by `/loopx w31` routine `mcp-qa` on 2026-11-27, against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`), with an unpinned QA key, read-only, on the QA account's synthetic `bean-example` ledger. There, 346 postings have a payee and an empty narration (`2015-01-08 * "EDISON POWER" ""`, the generator's utility bills), and every one of them reads `EDISON POWER | `. Reproduced at HEAD `035866c23` and on the raw engine with the ledger below.

**Repro.**

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:Food USD
2026-02-01 * "" "empty payee"
  Assets:Cash  -1 USD
  Expenses:Food  1 USD
2026-02-02 * "Shop" ""
  Assets:Cash  -1 USD
  Expenses:Food  1 USD
2026-02-03 * "" ""
  Assets:Cash  -1 USD
  Expenses:Food  1 USD
```

`SELECT date, description WHERE account = 'Assets:Cash'`:

| date | hosted | stock beanquery 0.2.0 |
| --- | --- | --- |
| 2026-02-01 | ` \| empty payee` | `empty payee` |
| 2026-02-02 | `Shop \| ` | `Shop` |
| 2026-02-03 | ` \| ` | (empty) |

A filter sees the same text. `WHERE description = 'Shop'` matches nothing here, and `WHERE description ~ '[|] $'` counts the 346 rows on the example ledger, where stock counts none. A transaction with no payee at all (`2026-02-04 * "only narration"`) reads correctly, and so does one with both.

**Cause.** Stock defines the column as `' | '.join(filter(None, [payee, narration]))` (`beanquery/sources/beancount.py:492`), so an empty string drops out. The engine joins every non-NULL part. The ledger service passes the column through unchanged. It cannot rewrite the column inside the query, because the engine has no `CASE` and no string `+` (`concat-literals` in `scripts/bql-oracle/allowlist.json`).

**Fix.**
- In this repo: where a result column is the bare `description` column (the alias heads `extractSelectAliasInfo` already gives the mappers), strip the separator that an empty part leaves at either end, in the structured and text renderers alike. Say in `docs/mcp.md`'s BQL notes that a filter on `description` still sees it, and that `payee` and `narration` filter exactly.
- Upstream: report the column to rustledger with the w23/022 batch, and add an `allowlist.json` oracle case so the gate turns red when the engine changes.
- Tests: a shell-service case with the three entries above, and the fix reverted to watch it fail.

**Dedupe.** Searched `.pm/**` for `description` as a BQL column, ` | ` and `EDISON POWER`. No item covers it. The BQL oracle (`scripts/bql-oracle/queries.json`) never selects `description`.

---

**Resolved 2026-11-27** — The ledger service now strips the separator an empty payee or narration leaves at either end of a selected `description` cell, in the structured and the text result alike (`withStockDescriptions` in `ledger-shell-mappers.ts`). The cell is fixed whether it is bare or aliased (`description AS d`). MCP `runBqlQuery` and `runBqlQueryStructured`, REST `/query` and GraphQL `queryShell` and `queryShellText` all read this one service. On the repro, `* "" "empty payee"`, `* "Shop" ""` and `* "" ""` read `empty payee`, `Shop` and an empty string, as stock beanquery 0.2.0 does. A column that only takes the name (`payee AS description`) and an expression over the column (`upper(description)`) are left alone. `description` also joins the string columns, so a numeric description stays `str`. A payee or narration that itself starts or ends with ` | ` loses that text too, because the cell no longer says which part it came from.
- **Still different.** A `WHERE`, `GROUP BY`, `ORDER BY` or `DISTINCT` on `description`, and any expression over it, still sees the engine's text: `WHERE description = 'Shop'` misses `* "Shop" ""`. The ledger `README.md` (new section "BQL `description` with an empty payee or narration") and `docs/mcp.md`'s BQL result notes now say so, and point to `payee` and `narration`, which filter exactly.
- **Gate.** A new oracle fixture, `description.bean`, holds the note's three entries plus a narration-only, a two-part and a bare `*` transaction. It has four queries: `description-empty-part`, `description-aliased`, `description-from-entries` and `description-filter`. The first three match stock. `description-filter` is allowlisted as a `cells` deviation, so `yarn verify:rustledger` fails once an engine bump joins the parts as stock does, and the stripping can then go. Reporting the column to rustledger, with the w23/022 batch's other gaps, is for the owner to file.
- **Tests.** `ledger-shell-description.test.ts` covers the repro rows in both renderers, the text column's width, an aliased and a `DISTINCT` column, `payee AS description`, a NULL from `FROM entries` and a numeric description. With the fix reverted, all 6 cases fail, and so do the first three oracle queries.

Shipped in the commit carrying this note (`backend-cluster/ledger`).

# Text scanners skip only column-0 `*` lines, while Beancount skips lines starting with any of `*#:!&?%`: `renameAccount` rewrites comments and narrations and misses postings, `appendLedgerText` breaks date order, and valid file text is refused, on MCP, REST and GraphQL

**Major · `backend-cluster/backend-v2` (five scanners in `src/features/ledger/utils/`), plus two in `backend-cluster/ledger` · 45–60m · A1.** Stock Beancount skips a whole line that starts with `*`, `#`, `:`, `!`, `&`, `?` or `%`, and a `"` on such a line opens no string. The ledger service already applies that rule before the engine parses (`backend-cluster/ledger/src/foundation/rustledger/parseable-files.ts:9-19`, w21/654), so `checkLedger` and every write's bean-check gate treat these lines as comments. Every hand-written line scanner in backend-v2 implements only the `*` case, as org-mode headings (w31/095, w31/097, w31/098, and `62d57e694` for budgets). A `#` comment that names an account, or a skipped line with an odd number of `"`, therefore reads differently to the scanner than to the ledger. Found by the `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 LAND=1`) on 2026-11-26.

## Repro (synthetic)

Append this block to a clean single-file ledger. It holds two `#` lines, the second with one `"`. The hosted write gate reports "No new bean-check errors", and `checkLedger` stays clean afterwards:

```beancount
2026-08-30 open Assets:Qa:Wallet USD
2026-08-30 open Expenses:Qa:Misc USD
# Assets:Qa:Wallet is the petty cash box
2026-08-30 * "payee" "top-up"
  Expenses:Qa:Misc    1.00 USD
  Assets:Qa:Wallet   -1.00 USD
# a 5" ruler
2026-08-31 * "payee" "paid from Assets:Qa:Wallet"
  Expenses:Qa:Misc    1.00 USD
  Assets:Qa:Wallet   -1.00 USD
```

1. **`renameAccount`.** MCP `{"from":"Assets:Qa:Wallet","to":"Assets:Qa:Purse","dry_run":true}`, REST `POST …/rename-account` and GraphQL `renameLedgerAccount(dryRun: true)` all return the same 4 changed lines:
   - the `open` line;
   - the `#` comment, renamed although `docs/mcp.md` "Renaming an account" says "comments keep the old name";
   - the first posting;
   - the second transaction's narration (`"paid from Assets:Qa:Purse"`), a string the doc also says keeps its old name.

   They miss the second posting, which follows the `5"` line. The result is `valid: false` with "Account Assets:Qa:Wallet was never opened". The commit is refused `VALIDATION_FAILED`, so the account cannot be renamed at all. With `allowInvalid` it would commit a broken ledger. Two odd-quote skipped lines restore the quote parity between them, so the narrations in between are renamed with `valid: true`.
2. **`appendLedgerText`.** Run `{"path":"main.bean","dry_run":true,"text":"2026-09-01 * \"payee\" \"later\"\n  Expenses:Qa:Misc 1.00 USD\n  Assets:Qa:Wallet -1.00 USD"}`. The diff places the `2026-09-01` entry before the `# a 5"` line, and so before the `2026-08-31` transaction. It also reports `appendedUnsorted: []`, although the doc promises "the file stays in date order".
3. **`updateLedgerFiles` (REST `PUT …/files/{path}` behaves the same).** A `dry_run` that appends `# ref 123456789012345678901234567890 USD` is refused `BAD_USER_INPUT` "amount … has more than 28 significant digits". So are the same line under `:` and `%`. The `*` spelling previews `valid: true`, and stock accepts all four spellings.

Running the scanners locally at `HEAD` against the same text, through ts-node in backend-v2, gives the results above. It also shows two more cases. `scanIncludeLines` returns no include for `include "a.bean"` after `# see the 5" note`. `extractSingleBudgetAccount` finds the budget under `* heading` but returns `undefined` under `# heading`.

## Root cause

Each scanner hand-rolls the skip rule as "column-0 `*`":

- `backend-v2/src/features/ledger/utils/account-rename.ts:51-57` (`accountTokenOffsets`)
- `backend-v2/src/features/ledger/utils/directive-text.ts:529-538` (`lineStartsInString`, which feeds `insertionPoint`, `endOfBlock`, `placeUnderHeading` and the push-scope scanners)
- `backend-v2/src/features/ledger/utils/engine-decimal.ts:300` (`textAmountLiterals`)
- `backend-v2/src/features/ledger/utils/include-target.ts:49-50` (`endsInsideString`, used by `scanIncludeLines`, `addIncludeLines`, `include-references.ts` and `ledger-workflow.ts`)
- `backend-v2/src/features/ledger/utils/budget-account-check.ts:31` (`headerLineOf`)
- `ledger/src/features/ledger/utils/routed-includes.ts:56` and `ledger/src/foundation/rustledger/balance-tolerance-syntax.ts:39`

A skipped line with an unmatched `"` flips their string state for the rest of the file. A skipped line without one is read as code.

## Fix

Give each package one predicate for the skip rule, matching `parseable-files.ts`: outside a string, a line whose first character is one of `*#:!&?%`. Use it in every scanner above instead of `startsWith("*")`.

- backend-v2 and ledger are separate packages, so land one change per package.
- Add regression tests over all seven starts, each with and without an unmatched `"`, for each of these:
  - rename: comment and narration untouched, every posting renamed;
  - insertion: the new entry stays in date order;
  - the engine-decimal scan: no refusal;
  - include detection: the include is found;
  - budget header: the budget is found.
- The parity suites keep MCP, REST and GraphQL together. No surface changes shape.

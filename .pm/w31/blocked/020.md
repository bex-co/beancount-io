# `check_average_cost` violations come back as a hidden warning: a ledger bean-check rejects reads as clean on every surface (w21/739 sibling)

**Minor · ledger (plugin reconciliation) · 30–45m · A1.** This is the same class as `w21/739`, which fixed `nounused` and `check_commodity` but did not cover this plugin. Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`) on 2026-11-15, against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, `revision: unknown`, see `w31/002`). The credential was an unpinned read/write/admin `bcio_` key on the QA account, and writes went only to the QA ledger `<qa-owner>/mcp-agent-eval`. The probe was committed, then reverted byte for byte (blob `f1a0b83c`), and the check is clean.

## Repro (live)

The run's names carried the prefix `qa-20261115-r8`, and this note shortens them. Append this to a ledger that opens `Assets:Bank:Checking USD`:

```beancount
plugin "beancount.plugins.check_average_cost"

2026-01-01 open Assets:QA:Avg "NONE"

2026-08-30 * "qa" "lot a"
  Assets:QA:Avg      5 QAST {1.00 USD}
  Assets:Bank:Checking     -5.00 USD

2026-08-30 * "qa" "lot b"
  Assets:QA:Avg      5 QAST {3.00 USD}
  Assets:Bank:Checking    -15.00 USD

2026-08-31 * "qa" "sell below average"
  Assets:QA:Avg     -5 QAST {1.00 USD}
  Assets:Bank:Checking      5.00 USD
```

- `updateLedgerFiles` `dry_run` and REST `PUT …/files/main.bean` `dryRun` both answer `valid: true` with `newErrors: []`.
- After the commit, `checkLedger`, the `errors` resource and REST `GET …/errors` all return `[]`.
- Stock Beancount 3.2.3 `bean-check` fails: `:<sell line>: Cost basis on reducing posting is too far from the average cost (1.00 vs. 2.00)`.

## Controls

Stock and HEAD's engine agree on each of these, and both report nothing:

- the same trades in an account without `"NONE"` booking (stock checks only `NONE` accounts);
- a sale at `1.99` against an average of `2.00`, which is inside the default 1%;
- the plugin given `"0.6"` as its tolerance;
- no plugin at all;
- `pedantic`, which does not run this plugin in stock either.

## Cause

- HEAD's engine finds the violation. `parseLedgerFilesInProcess` (`backend-cluster/ledger`, `@rustledger/wasm` 0.24.0, run in `node:22-bookworm-slim`) returns `severity: "warning"`, `PLUGIN`, "Sale of 5 QAST in Assets:QA:Avg uses cost 1.00 USD but average cost is 2.00 USD (difference: 50.00%)".
- The ledger service passes the severity through (`ledger-data-mappers.ts:70`), and backend-v2 drops warnings (`ledger-data-service.ts:259`, w21/188).
- `w21/739` added reconcilers that turn a declared plugin's warnings into Beancount's errors, run at `engine.ts:819-820`: `nounused.ts` and `check-commodity.ts`. There is no reconciler for `check_average_cost`.

## Fix

In `backend-cluster/ledger`, add a `check-average-cost.ts` reconciler beside `reconcileNounusedErrors` (`engine.ts:819`). Run it when the entry point declares `beancount.plugins.check_average_cost` (`beancountPluginRuns`; not under `pedantic`). It replaces each engine warning of that shape with an error reading `Cost basis on reducing posting is too far from the average cost (<cost> vs. <average>)`, placed on the transaction's line.

The engine already applies the plugin's rules (only `NONE` accounts, the default 1% or a float config), so this changes the wording and the severity only. It re-implements nothing. Every surface reads the shared snapshot, so MCP, REST and GraphQL change together.

**Done when:**

- The fixture above reports that one error at the sell line through `parseLedgerFiles`.
- On the QA ledger, its `dry_run` answers `valid: false`, and its commit is refused `VALIDATION_FAILED` unless `allowInvalid`.
- The controls above still report nothing.
- A unit case and a `yarn verify:rustledger` check cover it, and both fail with the fix reverted.

Dedupe: searched `.pm/**` (done and blocked included) for `check_average_cost`, "average cost" and "too far from the average". There were no hits for the plugin. `w21/739` and `w21/740` cover other plugins. Checked against HEAD `32bb91626`, so this is not deployment lag.

**Blocked 2026-11-15** — The warning comes from the engine's own classification. Remapping it here would refuse ledgers stock accepts, and upstream has already fixed the plugin in a commit no published release contains yet.

- **Reproduced.** Triage at `82bf22f64` ran the fixture above through `parseLedgerFilesInProcess` (`@rustledger/wasm` 0.24.0, `node:22-bookworm-slim`). It got one `warning` (`PLUGIN`, no file or line), while bean-check 3.2.3 reports the error at line 14. The note's controls agree with stock.
- **Where the severity is set.** In 0.24.0, `crates/rustledger-plugin/src/native/plugins/check_average_cost.rs` raises `PluginError::warning` with no entry location. The ledger service passes that severity through (`ledger-data-mappers.ts:70`), and backend-v2 drops warnings by design (`ledger-data-service.ts:259`, w21/188). Neither of those is the defect.
- **Why a severity remap here is not enough.** 0.24.0's inventory is not Beancount's:
  - it keys lots by account and currency, while stock also keys by cost currency;
  - it removes a sale at the average, while stock adds the sale at its own cost;
  - it skips short positions;
  - it prints the average rounded to 4 places.

  Promoting its warnings to errors would therefore refuse ledgers that bean-check accepts. Each fixture below runs in a `"NONE"` account under the plugin. The first number in braces is the cost per unit.

  | Postings, in order | bean-check 3.2.3 | 0.24.0 |
  | --- | --- | --- |
  | `5 {1.00 USD}`, `5 {3.00 EUR}`, `-5 {1.00 USD}` | clean | flags it, averaging across currencies (2.00) |
  | `-5 {1.00 USD}`, `10 {3.00 USD}`, `-5 {5.00 USD}` | clean (average 5.00) | flags it (average 3.00) |
  | `100 {100 USD}`, `-90 {101 USD}`, `-10 {91 USD}` | clean (average 91) | flags it (average 100) |
  | `5 {1.00 USD}`, `5 {3.00 USD}`, `-5 {1.00 USD}`, `-5 {3.00 USD}` | one error | two |
  | `1 {1.00 USD}`, `2 {2.00 USD}`, `-1 {1.00 USD}` | `(1.00 vs. 1.666666666666666666666666667)` | flags it, average `1.6667` |
  | plugin config `"1"` | the plugin fails, "must be a float" | silent |

  To match stock in the service, it would have to recompute the plugin's inventory, which means re-implementing a plugin the engine already ships (`.pm/DO_NOT_DO.md`, "Don't re-implement upstream"). w31/014 declined the same thing for pad sizing.
- **Fixed upstream, not released.** rustledger commit `3aaa348e2` ("fix(plugin)!: make nine native plugins do what beancount's do", #2642, merged 2026-10-12) changes check_average_cost:
  - it raises an error at the transaction, in Beancount's words;
  - it keeps Beancount's lots per account, currency and cost currency, adding each sale at its own cost;
  - it prints the average with Python `decimal`'s digits;
  - it refuses a config that is not a float.

  No published artifact contains it. npm `latest` and the installed dependency are both 0.24.0 (released 2026-09-06), and `v0.24.0` is upstream's newest release tag.
- **No partial work.** Nothing shipped for this note.

# Hosted and local `bea` disagree on `at_value` for cost-less holdings in a non-operating currency

Source: follow-up from the `/loopx w31` routine `mcp-qa`, run 98, 2026-11-19.

- **`bea`** values a holding that has no cost and is held in a non-operating currency in the first operating currency that has a quote. That has been its rule since `w3/241` and `w1/050` (`ad933da20`, `cli/src/fava/core/conversion.py` `get_market_value`).
- **The hosted engine** keeps that holding in its own units, the way Fava's `get_market_value` does (`backend-cluster/ledger/src/foundation/rustledger/cost-valuation.ts`, ledger `report-allowlist.json`).
- **Result:** the hosted trial balance `valuation_adjustment` (`w1/291`) differs from `bea report trial-balance -x at_value --json` on any ledger that holds foreign cash with a quote. Live, on a QA ledger, hosted reports `Assets:Cash` as 12.00 EUR and `bea` reports 13.2000 USD. MCP, REST and GraphQL all agree with each other; only `bea` differs.
- **Minimal repro:**
  1. Set `option "operating_currency" "USD"`.
  2. Open `Assets:Euro` against `Equity:Opening` with 100.00 EUR.
  3. Add `price EUR 1.10 USD`.
  4. Run `bea -x at_value`: Assets is 110.0000 USD. Hosted keeps 100.00 EUR.
- **Separate difference:** on books that net to zero, `bea -x USD` prints the line as `{"USD":"0"}`, while hosted prints `{}`.
- **Owner decision needed:** pick one rule. Fava's rule is to keep units; `bea`'s rule is to convert to an operating currency.

**Done when:** after the owner picks a rule, the repro gives the same `at_value` answer on `bea` and hosted. Or the deliberate difference is written down in `backend-cluster/backend-v2/docs/mcp.md` and the CLI usage docs.

**Blocked 2026-11-19** — Which `at_value` rule applies to a cost-less holding in a non-operating currency is an owner decision. No written record makes it. Triage at `4fc4fb54a` reproduced the note's ledger with `bea` 0.4.1 from this checkout: `bea --json report trial-balance -x at_value` gives `Assets:Euro` `{"USD": "110.0000"}` and `Equity:Opening` `{"USD": "-110.0000"}`. The hosted engine keeps this lot in EUR. Its `at_value` branch in `backend-cluster/ledger/src/foundation/rustledger/lot-inventory.ts` says "a cost-less lot stays in its units currency".

- **Records searched.** None of them settles it.
  - `docs/adrs/` has no record on `at_value` or on cost-less valuation. ADR014 covers command parity, not valuation.
  - `.pm/DO_NOT_DO.md` has no valuation rule. "Don't re-implement upstream" is about forking code, not about which rule a report uses.
  - `w3/241` and `w1/050` are CLI QA fixes. They changed `bea` only, with no owner decision and no hosted comparison. `cli/docs/USAGE.md` documents the result.
  - `w1/291` and `w1/292` aligned the hosted trial-balance adjustment and hosted holdings with `bea`. Neither covers `at_value` for cost-less lots.
  - `backend-cluster/backend-v2/docs/mcp.md` says a position with no cost basis "stays in its own units" when it has no price. It does not say what `at_value` does when a price exists.
  - The hosted side states its rule in several places: `cost-valuation.ts`, the ledger's `scripts/bql-oracle/report-allowlist.json`, and rule 3 of `w4/m26`'s valuation rule ("a lot with no cost stays in its units"), which the user's 2026-09-26 decision for web and mobile balances relies on. Each side documents its own rule. No record chooses between them.
- **Option 1: keep units everywhere (Fava's `get_market_value`).**
  - `bea` reverts the cost-less branch that `w3/241` and `w1/050` added in `cli/src/fava/core/conversion.py`. Foreign cash and `@`-priced lots stay in their own units under `at_value`, so the note's repro reads 100.00 EUR on both sides.
  - This brings back the mixed-currency `at_value` net worth that `w3/241` filed as a bug. `bea`'s `at_value` trial-balance adjustment can then span currencies.
  - `cli/tests/test_at_value_costless.py` and the USAGE paragraph change. Hosted, the dashboard and mobile stay as they are.
- **Option 2: convert everywhere (`bea`'s rule: the first operating currency that has a quote).**
  - The ledger engine's `at_value` reducer needs the operating currencies and converts cost-less lots. Every hosted `at_value` read changes on REST, GraphQL and MCP together: balance sheet, trial balance, income statement, overview and account reports.
  - The hosted rule moves away from Fava's. The comments in `cost-valuation.ts` and `lot-inventory.ts`, the oracle allowlist note and `mcp.md` change.
  - Multi-currency cash moves into the headline totals: web Net Worth and mobile Home and Accounts, which read `at_value` under `w4/m26`. The web disclosure that `w4/1031` shipped in `e74970870` reads a cost-less holding as "Not in total", and it must change with the engine.
- **Option 3: keep both and write the difference down.** This is the note's own alternative end state. No code changes. `mcp.md` and `cli/docs/USAGE.md` each say that hosted `at_value` keeps cost-less units as Fava does, while `bea` converts them, so the two trial balances differ on any ledger that holds quoted foreign cash.
- **Not owner-level.** The note's separate difference, a zero adjustment printed as `{"USD": "0"}` by `bea -x USD` and as `{}` by hosted, is a formatting question. Hosted's `{}` is documented in `trialBalanceAdjustment` (`account-tree.ts`). A worker can settle it once a rule is picked, or file it as a note of its own.

**Unblock:** the repository owner picks option 1, 2 or 3 and records it on this note, or in a `DO_NOT_DO.md` rule or an ADR if it should bind future valuation work. Only the owner can clear this. Next step after the decision: a worker applies it. For option 1 or 2, the change goes into the side that deviates, with regression tests; option 2 also covers the REST, GraphQL and MCP parity tests and the web and mobile Net Worth disclosures. For option 3, the worker writes the two doc paragraphs. Then the worker reruns this note's repro on `bea` and on hosted and closes the note with `/pm done`.

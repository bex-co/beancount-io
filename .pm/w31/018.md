# backend-v2 `TagStack` does not apply pushed tags to `note` and `document` entries

Source: follow-up from `w31/016` (`71c06b859`), 2026-11-15.

- The hosted engine gives an open `pushtag`'s tags to every directive. It also gives `pushmeta`'s metadata to every directive, where stock Beancount gives it only to transactions.
- backend-v2's `TagStack` (its `annotate` rules) does not tag `note` or `document` entries. The `w31/015` append fix (`96adc02e4`) relies on these rules, so a note or document written inside, or next to, a `pushtag` scope may be described differently from how the engine reads it.
- First confirm whether this changes any result a client sees: write a `note` and a `document` inside a `pushtag`/`pushmeta` scope on the QA ledger, and compare what the tools report with what the engine reads back. Restore the ledger byte for byte afterwards.

**Done when:** backend-v2 tags `note` and `document` entries exactly as the hosted engine does, a test pins that behaviour, or the note is closed with evidence that no client-visible result differs.

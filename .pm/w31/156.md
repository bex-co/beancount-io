**Minor · ledger (`src/foundation/rustledger/engine.ts`, beside the w21/740 reconcilers) · 30–40m · A1.** w21/740 placed the errors of five built-in plugins where Beancount places them and gave them Beancount's words. Two more plugins still come back unlocated from `@rustledger/wasm` 0.24.0, so `checkLedger`, the `errors` resource and every write preview list them with no `source`, and an agent cannot tell which line to fix:

## Repro (live)

Insert each fixture after the ledger's last line with `updateLedgerFiles` `dry_run: true` (old_string the last line, new_string that line plus the fixture). The first three preview `valid: false` with one `newErrors` entry whose `source` is absent, worded as the hosted column says. The fourth previews `valid: true`. Stock 3.2.3 on the same projected file gives the stock column, at line 90, the fixture's `close` or `commodity` line.

## Cause

The engine raises both plugins' findings with `file: null` and `line: null`. For `check_drained` the error belongs to the zero `balance` it synthesizes the day after the close. The ledger has a placing reconciler for `leafonly`, `noduplicates`, `coherent_cost`, `onecommodity` and `unique_prices` (w21/740, `engine.ts:855-880`), and none for these two. The engine's `commodity_attr` also skips a config it cannot read, where stock adds a `ConfigError`.

## Fix

Add the two plugins to the w21/740 pattern. Do not re-implement either plugin; place and reword what the engine reports.

- `check_drained` (declared, or through `pedantic` once w31/155 runs it there): put each balance error on the line of the `close` it came from, in stock's words.
- `commodity_attr`: put each error on its `commodity` line in stock's two messages, and report `Invalid configuration for commodity_attr plugin; skipping.` when the config does not read as a dict, as w21/739's `check_commodity` reconciler does for its own config (`check-commodity.ts`).

No response shape changes; every surface reads these errors from the one ledger path.

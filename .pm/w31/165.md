# BQL `date_bin` calendar bins are still wrong, and no upstream report exists: choose a report or a refusal

**Minor · ledger (`src/foundation/rustledger/`), with backend-v2 parity · 30–45m once decided · A1.** Follow-up from routine `mcp-qa` (2026-11-28). `w6/031` and `w6/032` have been blocked since 2026-10-15 waiting for an upstream rustledger fix, but nobody has reported the bug upstream. Upstream `main` (`c1ebb168`) still has the same `date_bin_on_values` in `crates/rustledger-query/src/executor/functions/date.rs`. npm `latest` is still `@rustledger/wasm` 0.24.0, and no rustledger issue or PR covers it. The wrong bins are live on MCP, REST and GraphQL.

Repro (synthetic QA ledger, read-only):

```
SELECT date_bin('1 year', date, 2025-07-01) AS fy, sum(number) AS spent
WHERE account ~ '^Expenses' GROUP BY fy
```

The service returns one row, `2026-07-01 4091.49`. Stock returns two, `2025-07-01 15.49` and `2026-07-01 4076.00`. The cases `w6/032` lists (before the origin, quarter strides, a grouped total) reproduce on the live service and on the native engine.

**Owner decision (needed first).** Pick one:

1. **Report it upstream.** Approve a rustledger issue built from the repro text in `w6/031` and `w6/032`.
2. **Refuse it here.** `w6/032` forbids rewriting the query, not refusing it. A guard in `backend-cluster/ledger/src/foundation/rustledger/` would refuse `date_bin` with a month, quarter or year stride whose literal origin is not the first of a month, and `backend-cluster/ledger/README.md` would say so.

**Done when:** the upstream issue is filed and linked from `w6/032`, or the refusal ships with a `scripts/bql-oracle` case and the same refusal on MCP, REST and GraphQL. `w6/031` and `w6/032` stay blocked on the upstream release either way.

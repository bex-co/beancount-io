# `account-journal` accepts empty or whitespace `account` (`?account=` / `account: ""`) and returns `200 OK` empty list instead of `BAD_USER_INPUT` on MCP, REST, and GraphQL

**Minor · backend-v2 (account-journal validation) · 20–30m · A1.** Passing an empty or whitespace-only `account` to `account-journal` succeeds with `200 OK` and an empty result on MCP, REST, and GraphQL, instead of refusing with `BAD_USER_INPUT` as omitting `account` and every other required string lookup do. Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`) on 2026-11-23 against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, checked against HEAD `ad0ad3afa`). Credential: unpinned read/write/admin `bcio_` key on the QA account. Synthetic ledger: `<qa-owner>/mcp-agent-eval`.

## Repro (live)

Reproduced in fresh read-only requests across all three surfaces against `<qa-owner>/mcp-agent-eval`:

1. **MCP resource `beancount://<qa-owner>/mcp-agent-eval/account-journal?account=` (and `?account=%20%20`)**:
   ```sh

   node .agents/skills/qa-shared/scripts/qa-mcp.mjs read 'beancount://<qa-owner>/mcp-agent-eval/account-journal?account=%20%20'
   ```

   Actual: HTTP `200`, returns `{"items":[],"total":0,"account":"","with_children":true}` / `"account":"  "`.
2. **REST `GET /api-gateway/v1/ledgers/<qa-owner>/mcp-agent-eval/account-journal?account=` (and `?account=%20%20`)**:
   Actual: HTTP `200`, returns `{"items":[],"total":0,"account":"","with_children":true}` / `"account":"  "`.
3. **GraphQL `getLedgerAccountJournal(ledgerId: "<qa-owner>/mcp-agent-eval", query: { account: "" })` (and `account: "  "`)**:
   Actual: HTTP `200`, returns `{"data":{"getLedgerAccountJournal":{"total":0,"account":""}}}` / `"account":"  "`.

Expected: refused with `BAD_USER_INPUT` (`account is required`) on MCP, REST, and GraphQL without calling the ledger service — matching what omitting `account` already does.

## Working controls

- Omitting `account` on MCP (`beancount://<qa-owner>/mcp-agent-eval/account-journal`) returns JSON-RPC `-32602` `BAD_USER_INPUT: account is required`.
- Sibling required string parameters refuse empty/whitespace with `BAD_USER_INPUT`: `collaborators/permission?collaborator=`, `social/profile?username=`, `temp-assets/download-url?objectKey=`, `assets/download-url?filename=`, and `commit-details?sha=` (w31/034).

## Root cause

Not deployment lag — present at HEAD `ad0ad3afa`:

- `backend-cluster/backend-v2/src/features/ledger/api/rest/v1/journal-reads.ts:127-128`: `accountJournalQuery` defines `account: z.string()` with no non-empty/non-blank check.
- `backend-cluster/backend-v2/src/features/ledger/service/ledger-journal-service.ts:431-458` (`LedgerJournalService.getAccountJournal`): forwards `query.account` straight to `favaApiClient.journal.getAccountJournal` without checking `query.account.trim() === ""`, so MCP, REST, and GraphQL all call the ledger service with a blank account string and return a silent empty page.

## Fix

In `backend-cluster/backend-v2`:

1. Guard `query.account.trim() === ""` in `LedgerJournalService.getAccountJournal` (`src/features/ledger/service/ledger-journal-service.ts:436`) throwing `new BadUserInputError("account is required", "account")` before calling the ledger service, so MCP, REST, and GraphQL refuse `""` and whitespace-only strings identically.
2. Add a non-empty check on `account` in `accountJournalQuery` (`src/features/ledger/api/rest/v1/journal-reads.ts:128`) if appropriate for OpenAPI (syncing `cli/openapi/v1.json` if the spec moves), keeping the service guard authoritative for all three surfaces.
3. Add unit and 3-surface parity tests covering `account: ""` and `account: "  "` across MCP `beancount://{owner}/{name}/account-journal`, REST `GET /api-gateway/v1/ledgers/{owner}/{name}/account-journal`, and GraphQL `getLedgerAccountJournal`.

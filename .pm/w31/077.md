# `beancount://assets/download-url` (`GET /v1/asset-download-url`, GraphQL `getLedgerAssetDownloadUrl`) accepts whitespace-only and control-character `filename` values, reaching admin ledger lookup and presigning invalid S3 keys instead of refusing `BAD_USER_INPUT`

**Minor · backend-v2 (`LedgerAssetService.getAssetDownloadUrl`) · 20–30m · A1.** `LedgerAssetService.getAssetDownloadUrl` validates `filename` only with `assertSafeRepoPath` (`src/features/ledger/service/ledger-asset-service.ts:97`), which rejects empty strings (`""`), `\0`, `\`, `.git`, and empty/`.`/`..` segments, but intentionally leaves whitespace-only strings and ASCII/C1 control characters unguarded so legacy Git files stay readable (`src/features/ledger/utils/safe-repo-path.ts:10-44`). For S3 ledger assets under `assets/repo_{repoId}/{filename}`, passing whitespace-only (`"   "`, `"\t"`) or control-character (`"a\nb.pdf"`, `"a\r\nb.pdf"`) filenames therefore bypasses input validation on MCP, REST, and GraphQL, triggers the upstream admin `getLedgerByRepoId` lookup (returning `NOT_FOUND: Ledger not found` for an unknown repo ID instead of `BAD_USER_INPUT`), and for any authorized `ledgerRepoId` signs an AWS SigV4 presigned GET URL for an invalid key such as `assets/repo_<id>/%20%20%20` or `assets/repo_<id>/a%0D%0Ab.pdf`. Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`) on 2026-11-24 against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, verified at HEAD `8ca0e9c13`). Credential: unpinned read/write/admin `bcio_` key on the QA account. Read-only probes only; no files were modified.

## Repro (live)

Reproduced in fresh read-only requests across MCP, REST, and GraphQL against `https://beancount.io`:

1. **MCP `resources/read` `beancount://assets/download-url`**:
   ```sh
   node .agents/skills/qa-shared/scripts/qa-mcp.mjs read 'beancount://assets/download-url?ledgerRepoId=1&filename=%20%20%20'
   node .agents/skills/qa-shared/scripts/qa-mcp.mjs read 'beancount://assets/download-url?ledgerRepoId=1&filename=%09'
   node .agents/skills/qa-shared/scripts/qa-mcp.mjs read 'beancount://assets/download-url?ledgerRepoId=1&filename=a%0Ab.pdf'
   node .agents/skills/qa-shared/scripts/qa-mcp.mjs read 'beancount://assets/download-url?ledgerRepoId=1&filename=a%0D%0Ab.pdf'
   ```
   - **Actual:** All four bypass `filename` validation, execute the admin `getLedgerByRepoId(1)` call, and return JSON-RPC `-32002` `NOT_FOUND: Ledger not found`.
2. **REST `GET /api-gateway/v1/asset-download-url`**:
   - `?ledgerRepoId=1&filename=%20%20%20`, `%09`, `a%0Ab.pdf`, `a%0D%0Ab.pdf` → HTTP `404` `{"error":{"code":"NOT_FOUND","message":"Ledger not found"}}`.
3. **GraphQL `Query.getLedgerAssetDownloadUrl(ledgerRepoId: 1, filename: "   " | "\t" | "a\nb.pdf" | "a\r\nb.pdf")`**:
   - **Actual:** HTTP `200`, `errors[0].extensions.code: "NOT_FOUND"`, `message: "Ledger not found"`.
4. **Authorized-repo consequence (verified locally against `@aws-sdk/s3-request-presigner`):** once `getLedgerByRepoId` and `authorizeLedger` succeed for an owned `ledgerRepoId`, `buildLedgerRepoAssetKey(ledgerRepoId, filename)` (`asset-storage-service.ts:119-124`) passes `assets/repo_{id}/   `, `assets/repo_{id}/\t`, and `assets/repo_{id}/a\r\nb.pdf` verbatim to `AssetStorageService.generateDownloadUrl`, which returns HTTP `200` with a signed S3 URL (`…/assets/repo_42/%20%20%20?X-Amz-…`, `…/a%0D%0Ab.pdf?X-Amz-…`).

**Expected:** Whitespace-only `filename` values (`"   "`, `"\t"`) and filenames containing control characters (`[\x00-\x1f\x7f-\x9f]` / `\u2028` / `\u2029`) are refused with `BAD_USER_INPUT` (`field: "filename"`) before calling `getLedgerByRepoId`, `authorizeLedger`, or `generateDownloadUrl`, identically across MCP (`-32602`), REST (`400`), and GraphQL (`BAD_USER_INPUT`).

## Working controls

- Empty `filename: ""` on the exact same endpoint already fails upfront before `getLedgerByRepoId`:
  - MCP `beancount://assets/download-url?ledgerRepoId=1&filename=` → `-32602` `BAD_USER_INPUT: File path must not be empty`.
  - REST `GET /api-gateway/v1/asset-download-url?ledgerRepoId=1&filename=` → HTTP `400` `BAD_USER_INPUT: File path must not be empty`.
  - GraphQL `getLedgerAssetDownloadUrl(ledgerRepoId: 1, filename: "")` → `BAD_USER_INPUT: File path must not be empty`.
- Sibling S3 asset and required-string endpoints already enforce blank/control-character rejection upfront:
  - `beancount://temp-assets/download-url?objectKey=%20` → `-32602` `BAD_USER_INPUT: objectKey must not be empty` (`assertTempAssetKey` checks `objectKey.trim() === ""`).
  - `generateTempAssetUploadUrl` (`asset-storage-service.ts:74-106`, `w31/043`) refuses control characters in `filename` with `BAD_USER_INPUT: filename must not contain control characters`.
  - `account-journal?account=%20` (`w31/036`), `account-report/%20` (`w31/040`), `interval-totals?accountName=%20` (`w31/045`), `commits?branch=%09` / `latest-commit?branchName=%09` (`w31/047`), `commit-details?sha=%09` (`w31/034`), `account/profile?userId=%20`, and `banks/%20` all refuse whitespace-only inputs with `BAD_USER_INPUT`.

## Root cause

Not deployment lag — present at HEAD `8ca0e9c13`:

- `backend-cluster/backend-v2/src/features/ledger/service/ledger-asset-service.ts:89-126` (`LedgerAssetService.getAssetDownloadUrl`): line 97 calls `assertSafeRepoPath(filename, "filename")` and then proceeds straight to `adminClient.admin.getLedgerByRepoId(ledgerRepoId)` (line 100) and `buildLedgerRepoAssetKey(ledgerRepoId, filename)` (line 122).
- `backend-cluster/backend-v2/src/features/ledger/utils/safe-repo-path.ts:10-31` (`assertSafeRepoPath`): checks only `path.length === 0`, `\0`, `\`, empty/`.`/`..` segments, and `.git`. It deliberately omits whitespace-only and control-character checks so legacy Git repository files stay readable and deletable; however, S3 asset object keys under `assets/repo_{repoId}/` are never arbitrary legacy Git filenames.

## Fix

In `backend-cluster/backend-v2`:

1. Keep `assertSafeRepoPath` unchanged for Git repository file reads/deletes, and add asset-filename checks in `LedgerAssetService.getAssetDownloadUrl` (`src/features/ledger/service/ledger-asset-service.ts:94-98`) right beside `assertSafeRepoPath(filename, "filename")` (before `adminClient.admin.getLedgerByRepoId`):
   - Reject whitespace-only `filename` (`filename.trim() === ""`) with `BadUserInputError("File path must not be empty", "filename")` (matching `""` and `w31/052`), and reject any segment that is whitespace-only (e.g. `" /a.pdf"` or `"dir/  "`).
   - Reject control characters (`[\p{Cc}\u2028\u2029]` / ASCII `0x00–0x1f` and `0x7f–0x9f`, matching `assertPortableRepoPath` and `AssetStorageService.hasControlChars`) with `BadUserInputError("filename must not contain control characters", "filename")`.
   - Preserve valid asset filenames: nested relative paths (`2026/receipt.pdf`), internal spaces (`my receipt.pdf`), `#` (`receipt#1.pdf`), and non-ASCII (`レシート.pdf`).
2. Add unit tests in `src/features/ledger/service/__tests__/ledger-asset-service.test.ts` and 3-surface adapter parity tests in `src/features/ai-agent/api/__tests__/download-url-parity.test.ts` (extending the existing `"rejects invalid repository IDs and paths before ledger lookup or signing"` block at `:398-433`) covering `"   "`, `"\t"`, `"a\nb.pdf"`, `"a\r\nb.pdf"`, and `"dir/   /a.pdf"` across MCP `beancount://assets/download-url`, REST `GET /api-gateway/v1/asset-download-url`, and GraphQL `getLedgerAssetDownloadUrl`, asserting neither `getLedgerByRepoId` nor `generateDownloadUrl` is called.

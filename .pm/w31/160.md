# A BQL text table lists a sold-out lot as `0 VTI`: `sum(position)` of 3 VTI held after selling a 5 VTI lot reads `0 VTI, 3 VTI`, and each lot is printed without its cost, on MCP, REST and GraphQL (gap in w23/200)

**Minor · ledger (`src/features/ledger/service/ledger-shell-mappers.ts`) · 20–30m, plus an upstream report · A1.** Found by `/loopx w31` routine `mcp-qa` on 2026-11-27, against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`), with an unpinned QA key, read-only, on the QA account's synthetic `bean-example` ledger. Reproduced at HEAD `035866c23` through `LedgerShellService.queryShellText` on the ledger below.

The text block is all that claude.ai's connector hands the model (`docs/mcp.md`, the result envelope). Asked which lots it holds, an agent reads one lot too many, and none of them has a cost.

`SELECT account, sum(position) WHERE account = 'Assets:Broker' GROUP BY account`:

| | `sum(position)` cell |
| --- | --- |
| hosted text (`runBqlQuery`, REST `text/plain`, GraphQL `queryShellText`) | `0 VTI, 3 VTI` |
| stock `bean-query` 3.2.3 / beanquery 0.2.0 | `3 VTI { 110.00 USD}` |

The running `balance` column has the same problem: on 2026-01-04 it reads `0 VTI, 3 VTI`. On production, the example ledger's GLD account reads `0 GLD, 0 GLD, 2 GLD, 5 GLD, 2 GLD, 8 GLD`. Stock lists its four open lots, each with its cost and date. The structured cell (`{"VTI": "3"}`) is right.

**Cause.**
- The engine (`@rustledger/wasm` 0.24.0) keeps a lot that a sale has emptied in the inventory, as a zero position: `{"positions":[{"units":{"number":"0","currency":"VTI"}},{"units":{"number":"3",…}}]}`. Its positions carry no cost.
- `formatInventoryText` (`ledger-shell-mappers.ts:413`) applies w23/200's rule, which drops a currency only when all of its positions net to zero. A zero lot beside a held one stays.
- `formatCellValue` (`src/foundation/rustledger/mappers.ts:87`) then prints `units` only.

**Fix.**
- In this repo: the text renderer drops every zero-unit position, as a Beancount `Inventory` never holds one. An inventory left with nothing stays blank, as w23/200 has it. Add a `ledger-shell-mappers` test for a held lot beside an emptied one, in `sum(position)` and in `balance`, and revert the fix to watch it fail.
- Not in this repo: the missing per-lot cost belongs to the engine's query wire. Say so in `docs/mcp.md` beside the BQL result notes: an inventory cell lists units, and `SELECT position` per posting or `cost(sum(position))` gives the cost. Add it to the upstream report with w6/016, which tracks the same cost loss for `PRINT`.

**Blast radius.** Every text rendering of an inventory goes through this one renderer, on MCP, REST `text/plain` and GraphQL `queryShellText`. The zero lot shows in `sum(position)`, the `balance` column and `JOURNAL`'s balance column. `BALANCES` already reads `3 VTI` on this ledger, but without the cost. Structured results are unaffected.

**Dedupe.** Searched `.pm/**` for zero lots, `0 GLD`, `0 VTI`, `formatInventoryText` and inventory text rendering. w23/200 handled a currency that nets to zero, but not an emptied lot beside a held one. w23/015 restored the date and label on a single position's cost. w6/016 (blocked upstream) covers `PRINT`'s lost costs. None covers this.

# Production `/.well-known/mcp.json` reports `revision: "unknown"`

Source: `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`), run 2026-11-14.

- `GET https://beancount.io/.well-known/mcp.json` returns `"revision": "unknown"`, with `cf-cache-status: DYNAMIC`, so this is not a cached copy.
- The build is recent enough to carry the field, and `listStagedBankTransactions` takes `page`/`limit`, so production includes `a2ae7dbac` and `e195dfe96`.
- `src/config/revision.ts` reads `BEANCOUNT_REVISION`, then `RENDER_GIT_COMMIT`, and looks correct. Neither variable reaches the production API service.
- Effect: the "with the deployed revision" checks in `w1/m43` t006, `w1/m45` t005 and `w23/m44` t001 cannot be done.
- Paths: `backend-cluster/backend-v2/docs/mcp.md` ("Which build a deployment runs"), `deploy/bex/README.md` ("Which commit is running"), `deploy/docker/README.md`.

**Done when:** the owner sets `BEANCOUNT_REVISION` to the deployed commit on the production API service (or passes it at build time) and redeploys. Then `.well-known/mcp.json` `revision` is a 40-hex commit, and `git merge-base --is-ancestor a2ae7dbac <revision>` exits 0. The fix needs production deploy access, which only the owner has.

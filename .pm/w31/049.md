# `parseFile` (`POST /api-gateway/v1/import/parse-file`, GraphQL `parseFile`) accepts empty (`""`) and whitespace-only (`"   "`) `fileFormat`, bypassing input validation to reach authorization, quota, S3, and LLM prompts instead of returning `BAD_USER_INPUT`

**Minor · backend-v2 (`LLMService.parseFile`, `file-parse-route.ts`) · 25–35m · A1.** Passing `fileFormat: ""` or `fileFormat: "   "` to `parseFile` passes Zod and service input validation across MCP, REST, and GraphQL, proceeding through PDP authorization, LLM-config and AI-quota checks, and S3 object-metadata lookup (returning `NOT_FOUND` for a missing temp key, or forwarding a blank format string into the LLM system prompt `"specializing in  files"` and spending AI quota on a real temp upload), instead of refusing upfront with `BAD_USER_INPUT`. Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`) on 2026-11-23 against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, checked against HEAD `686cdff7b`). Credential: unpinned read/write/admin `bcio_` key on the QA account.

## Repro (live)

Reproduced in fresh requests across all three surfaces using a syntactically valid caller-owned temporary object key (`tmp/<userId>/qa-nonexistent.csv`, so ownership checks pass and no AI quota is spent):

1. **MCP `parseFile`**:
   ```sh
   node .agents/skills/qa-shared/scripts/qa-mcp.mjs call parseFile '{"objectKey":"tmp/<userId>/qa-nonexistent.csv","fileFormat":""}'
   node .agents/skills/qa-shared/scripts/qa-mcp.mjs call parseFile '{"objectKey":"tmp/<userId>/qa-nonexistent.csv","fileFormat":"   "}'
   ```
   - Actual (both `""` and `"   "`): HTTP `200`, `isError: true`, `error.code: "NOT_FOUND"`, `message: "Temporary asset not found"`, `hint: "Re-check the objectKey from `generateTempAssetUploadUrl`: keys belong to the uploading user and expire."`
2. **REST `POST /api-gateway/v1/import/parse-file`** with `{"objectKey":"tmp/<userId>/qa-nonexistent.csv","fileFormat":""}` and `{"objectKey":"tmp/<userId>/qa-nonexistent.csv","fileFormat":"   "}`:
   - Actual (both): HTTP `404`, `{"ok":false,"error":{"code":"NOT_FOUND","message":"Temporary asset not found","metadata":{"resource":"Temporary asset",...}}}`.
3. **GraphQL `parseFile(objectKey: "tmp/<userId>/qa-nonexistent.csv", fileFormat: "" | "   ") { rows { date } }`**:
   - Actual (both): HTTP `200`, `errors[0].extensions.code: "NOT_FOUND"`, `message: "Temporary asset not found"`.

Expected: refused before authorization, quota, S3, or LLM calls with `BAD_USER_INPUT` (`fileFormat must not be empty`, field `fileFormat`) across MCP, REST, and GraphQL.

## Working controls

- On the same `parseFile` operation, passing `objectKey: ""` or `"   "` is refused before authorization and S3 with `BAD_USER_INPUT` (`objectKey must not be empty`, via `assertTempAssetKey`).
- Omitting `fileFormat` entirely is refused with `BAD_USER_INPUT` on MCP/REST (`fileFormat: Invalid input: expected string, received undefined`) and `GRAPHQL_VALIDATION_FAILED` on GraphQL.

## Root cause

Not deployment lag — present at HEAD `686cdff7b`:

- `backend-cluster/backend-v2/src/features/llm/api/file-parse-route.ts:7-21`: `fileParseInput` declares `fileFormat: z.string()` with no non-empty / non-blank validation.
- `backend-cluster/backend-v2/src/features/llm/api/llm-parser-resolver.ts:36-47`: GraphQL `parseFile` forwards `fileFormat: string` straight to `this.llm.parseFile(...)`.
- `backend-cluster/backend-v2/src/features/llm/service/llm-service.ts:223-287` (`LLMService.parseFile`): calls `assertTempAssetKey(s3ObjectKey, "objectKey")` at `:230`, then authorizes (`:231`), checks LLM config (`:236`), checks AI quota (`:237`), reads S3 metadata (`:239`), presigns a download URL (`:258`), and invokes `extractTransactionsFromFile({ format: fileFormat, ... })` (`:261`), which interpolates `format.toUpperCase()` into the system prompt (`extract-transactions-from-file/prompts.ts:2`: `"specializing in  files"`) and resolves media type with `MEDIA_TYPE_MAP[format.toLowerCase()] ?? "application/octet-stream"` (`media-type-utils.ts:66`) — never checking that `fileFormat.trim()` is non-empty.

## Fix

In `backend-cluster/backend-v2`:

1. In `backend-cluster/backend-v2/src/features/llm/service/llm-service.ts:230` (`LLMService.parseFile`), validate `fileFormat` right next to `assertTempAssetKey(s3ObjectKey, "objectKey")` before authorization, quota, S3, and LLM work: if `fileFormat.trim() === ""`, throw `new BadUserInputError("fileFormat must not be empty", "fileFormat", "Pass the file's format, such as csv, pdf, xlsx, json, or jpg.")`. Pass `fileFormat.trim()` (or keep trimmed format) consistently downstream.
2. Add unit tests in `backend-cluster/backend-v2/src/features/llm/service/__tests__/llm-service.test.ts` and 3-surface adapter parity tests in `backend-cluster/backend-v2/src/features/llm/api/__tests__/file-parse-parity.test.ts` covering `fileFormat: ""` and `fileFormat: "   "` across MCP `parseFile`, REST `POST /api-gateway/v1/import/parse-file`, and GraphQL `parseFile`, asserting `BAD_USER_INPUT` and zero calls to authorization/S3/LLM.
3. If `fileParseInput` (`file-parse-route.ts:10`) is also tightened in the Zod schema, regenerate `docs/openapi/v1.json` and re-pin `cli/openapi/v1.json` (`make spec-sync && make codegen` in `cli/`) in the same change.

# `appendLedgerText` inserts a dated entry inside the target file's open `pushtag`/`pushmeta` scope, so the stored entry silently gains a tag or metadata the caller never wrote, on MCP, REST and GraphQL

**Minor · backend-v2 (directive text insertion) · 30–45m · A1.** The write reports "No new bean-check errors", but the entry it stores is not the entry it was given, and tag filters and reports then count it. Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`) on 2026-11-15, against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, `revision: unknown`, see `w31/002`). The credential was an unpinned read/write/admin `bcio_` key on the QA account. Writes went only to the designated QA ledger `<qa-owner>/mcp-agent-eval`. `main.bean` was restored byte for byte afterwards (blob `f1a0b83c`), and the check is clean.

- **Fixture.** `main.bean` ends in date order with this block, which loads clean under stock Beancount 3.2.3:

  ```beancount
  pushtag #qa-r7-trip
  2026-09-02 * "PAYEE-A" "tagged by the scope"
    Expenses:Food:Coffee   3.00 USD
    Assets:Cash
  poptag #qa-r7-trip

  2026-09-03 * "PAYEE-B" "inline tag" #qa-r7-inline
    Expenses:Food:Coffee   4.00 USD
    Assets:Cash

  pushmeta qa-r7-meta: "pm"
  2026-09-04 * "PAYEE-C" "meta from the scope"
    Expenses:Food:Coffee   5.00 USD
    Assets:Cash
  popmeta qa-r7-meta:
  ```

- **Repro (live).**
  1. `appendLedgerText {path: "main.bean", text: "2026-09-01 * \"APPEND-0901\" \"n\"\n  Expenses:Food:Coffee 1.00 USD\n  Assets:Cash\n", dry_run: true}`. The diff puts the entry on the line right after `pushtag #qa-r7-trip`. The answer is `valid: true`, "Would add 1 directive to main.bean. No new bean-check errors."
  2. A 2026-09-03 entry lands right after `pushmeta qa-r7-meta: "pm"`.
  3. Committing both in one call gives "Added 2 directives to main.bean. No new bean-check errors." (commit `235102d5`, later restored).
  4. BQL `SELECT date, payee, tags, entry_meta('qa-r7-meta')` then shows `APPEND-0901` tagged `qa-r7-trip`, and `APPEND-0903` with `qa-r7-meta: pm`. `listLedgerEntries {filter: "#qa-r7-trip"}` returns `APPEND-0901` next to `PAYEE-A`. Stock `bean-query` 3.2.3 on the committed file agrees. The caller's text had neither.
  5. REST `POST …/directives/text` and GraphQL `appendLedgerText`, each with `dryRun: true`, return the same diff for the same text.
- **Controls.**
  - An entry dated on the scope's last day (2026-09-02) previews after `poptag`, outside the scope.
  - `addLedgerEntries` appends at the end of the file, so it inherits nothing here.
  - The text's own `pushtag`/`pushmeta` are expanded onto its entries (w23/041; not re-tested in this run).
- **Not deployment lag.** HEAD's `insertDirectives` gives the same placements on a synthetic file (run under tsx in `node:22-bookworm-slim`). For a scope holding a 2026-09-02 and a 2026-09-05 entry, a 2026-09-01 entry goes right after `pushtag`, and a 2026-09-03 entry goes between the two scoped entries. For a scope opening before a 2026-09-10 entry, a 2026-09-07 entry goes right after `pushmeta`.
- **Cause.** In `backend-cluster/backend-v2/src/features/ledger/utils/directive-text.ts`:
  - `directiveHead` (`:196`) reads a `pushtag`/`poptag`/`pushmeta`/`popmeta` line as a head with `date: null`.
  - `insertionPoint` (`:431`) moves `last` past every head that is not dated after the new entry. Undated heads count too, so the entry goes after an opening `pushtag` line or between two scoped entries.
  - Nothing tracks which push scopes are open at the chosen line. `TagStack` (`:67`) covers only the appended text's own stack (w23/041).
- **Fix.** Keep the stored entry what the caller wrote, and keep date order:
  - When the date position is just past a scope's opening push, before that scope's first dated entry, insert before the push statement instead.
  - When it is strictly inside a scope, close the scope around the new entry. Write the matching `poptag #t` or `popmeta k:` lines before the entry, and the same pushes, in the same order with the same values, after it.
  - The appended text's own tags and metadata stay as written.
  - The one workflow serves MCP `appendLedgerText`, REST `POST …/directives/text` and GraphQL `appendLedgerText`, so all three change together. No response shape changes. State the rule in `docs/mcp.md` "Writing directives as Beancount text".

**Done when:**

- On the fixture above, appending a 2026-09-01 and a 2026-09-03 transaction stores both with exactly the tags and metadata their text carries. Check through BQL and `listLedgerEntries`, and check the committed file with stock `bean-query` as well. The file stays in date order, so `appendedUnsorted` is empty.
- An entry dated strictly between two entries of one `pushtag` scope, and of one `pushmeta` scope, is stored without the scope's tag or metadata. The scoped entries keep theirs, and the file bean-checks clean.
- `directive-text.test.ts` covers the edge and the interior cases for both stacks, and `directive-text-parity.test.ts` covers one through all three surfaces. The new cases fail with the fix reverted.

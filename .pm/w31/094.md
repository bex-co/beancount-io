# `appendLedgerText` skips `assertBudgetAccountsExist`, letting `custom "budget"` directives for unopened accounts pass `dry_run` (`valid: true`) and commit without `allowInvalid` across MCP, REST, and GraphQL

**Minor · `backend-cluster/backend-v2` (`src/features/ledger/workflow/directive-append-workflow.ts`, `src/features/ledger/service/ledger-entry-service.ts`) · 25–35m · A1.** `addLedgerEntries` (`POST /api-gateway/v1/ledgers/{owner}/{name}/entries`, GraphQL `bulkEntries`) runs `assertBudgetAccountsExist` (`w23/done/071`, `w23/done/221`) because Beancount's `bean-check` never validates the account argument inside `custom "budget"` — without it, a budget on a typoed or unopened account silently commits with "No new bean-check errors" and never matches any report. `appendLedgerText` (`POST /api-gateway/v1/ledgers/{owner}/{name}/directives/text`, GraphQL `appendLedgerText`) — the text dialect of the exact same entry-writing capability (`LEDGER_ENTRIES_WRITE`) — relies solely on `checkProjectedFiles` (`bean-check`) and never runs `assertBudgetAccountsExist`. As a result, appending `custom "budget"` for a nonexistent account reports `valid: true` with `0` new errors on `dry_run: true` and commits without `allowInvalid: true` across MCP, REST, and GraphQL.

## Environment

- Target: `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`), verified against local `HEAD` `e873717a8` (Node `v22.22.0`).
- Credential: unpinned read/write/admin `bcio_` API key on the designated QA account and synthetic ledger `<qa-owner>/mcp-agent-eval`.

## Repro (synthetic)

Send a `custom "budget"` directive targeting an unopened account (`Expenses:NoSuchAccount`) with `dry_run: true` across all three surfaces:

```sh
# MCP
node .agents/skills/qa-shared/scripts/qa-mcp.mjs call appendLedgerText \
  '{"ledger":"alice/books","text":"2026-08-30 custom \"budget\" Expenses:NoSuchAccount \"monthly\" 100.00 USD","dry_run":true}'
```

Repeat on REST (`POST /api-gateway/v1/ledgers/alice/books/directives/text` with `{"text":"2026-08-30 custom \"budget\" Expenses:NoSuchAccount \"monthly\" 100.00 USD","dryRun":true}`) and GraphQL (`mutation { appendLedgerText(ledgerId: "alice/books", text: "2026-08-30 custom \"budget\" Expenses:NoSuchAccount \"monthly\" 100.00 USD", dryRun: true) { success valid errorsBefore errorsAfter newErrors { message } } }`).

- **Actual (all 3 surfaces):**
  - MCP: HTTP `200`, `ok: true`, `summary: "Would add 1 directive to main.bean. No new bean-check errors."`, `validation: { errorsBefore: 0, errorsAfter: 0, newErrors: [], valid: true }`.
  - REST: HTTP `200`, `success: true`, `valid: true`, `errorsBefore: 0`, `errorsAfter: 0`, `newErrors: []`.
  - GraphQL: HTTP `200`, `success: true`, `valid: true`, `errorsBefore: 0`, `errorsAfter: 0`, `newErrors: []`.
  - On `dry_run: false` without `allowInvalid`, `DirectiveAppendWorkflow.appendDirectiveText` (`directive-append-workflow.ts:251`) sees `newErrors.length === 0` and commits the dead budget directive without refusing.
- **Working control (`addLedgerEntries` with `{ type: "budget", entry: { date: "2026-08-30", account: "Expenses:NoSuch", interval: "monthly", amount: { number: "100", currency: "USD" } } }`, `dry_run: true`):**
  - MCP returns `valid: false`, `errorsBefore: 0`, `errorsAfter: 1`, `newErrors: [{ message: "Validation failed for entries: entry 0: budget account Expenses:NoSuch is not opened in this ledger, nor is any account under it; nearest: Expenses:Entertainment:Streaming, Expenses:Food:Coffee, Expenses:Food:Groceries" }]`, and on `dry_run: false` refuses with `VALIDATION_FAILED` unless `allowInvalid: true`.

## Expected

`appendLedgerText` (`POST .../directives/text`, GraphQL `appendLedgerText`) enforces the same unopened-budget-account check as `addLedgerEntries` (`w23/071`, `w23/221`):

- When `allowInvalid` is not set and an appended `custom "budget"` directive names an account that is neither opened in the ledger, nor a parent of an opened account, nor opened by an `open` directive in the same appended text:
  - On `dryRun: true`: return `valid: false`, increment `errorsAfter`, and append each finding to `newErrors` (naming the unopened account and nearest opened accounts, following the preview rule in `docs/mcp.md`).
  - On `dryRun: false`: refuse with `VALIDATION_FAILED` before committing, with a hint offering to open the account, add its `open` in the same call, or pass `allowInvalid: true`.
- When `allowInvalid: true`, or when the account (or a child) is opened in the ledger or by an `open` directive in the same call, allow the write as today.

## Root cause

- `FavaLedgerEntryWriter.assertBudgetAccountsExist` (`backend-cluster/backend-v2/src/features/ledger/service/ledger-entry-service.ts:980-1026`) is a private method on the structured bulk writer and is only invoked inside `writeBulkEntries` (`ledger-entry-service.ts:702-710`).
- `DirectiveAppendWorkflow.appendDirectiveText` (`backend-cluster/backend-v2/src/features/ledger/workflow/directive-append-workflow.ts:93-318`) calls `parseDirectiveText(text)` (`:107`) and gates writes exclusively on `diffBeanCheckErrors(baseline, projected)` (`:237-253`), never checking `custom "budget"` account tokens against `reports.getLedgerAccounts`.

## Fix

- **Owning package & surfaces:** `backend-cluster/backend-v2`; `DirectiveAppendWorkflow` is shared by MCP `appendLedgerText`, REST `POST /api-gateway/v1/ledgers/{owner}/{name}/directives/text`, and GraphQL `Mutation.appendLedgerText`, so fixing the workflow updates all three surfaces together with no OpenAPI or response-shape change.
- Extract the shared budget-account validator from `ledger-entry-service.ts:980-1026` into a small shared helper (e.g. `src/features/ledger/utils/budget-account-check.ts`) used by both `FavaLedgerEntryWriter.writeBulkEntries` and `DirectiveAppendWorkflow.appendDirectiveText`.
- In `DirectiveAppendWorkflow.appendDirectiveText`: when `!allowInvalid`, extract budget accounts from parsed `Custom` directives of type `"budget"` (and collect accounts opened by `Open` directives in the same `directives` list); only call `reports.getLedgerAccounts` when at least one `custom "budget"` directive is present (zero extra latency for non-budget appends). Merge any budget issues into `newErrors` / `errorsAfter` / `valid: false` on `dryRun: true`, and throw `ValidationError` (`VALIDATION_FAILED`) on `dryRun: false`.
- Add unit tests in `directive-append-workflow.test.ts` and 3-surface adapter parity tests in `directive-text-parity.test.ts` (unopened budget preview `valid: false`, commit refusal `VALIDATION_FAILED`, `allowInvalid: true` escape hatch, opened parent account, and same-call `open` + `custom "budget"` control).

## Blast radius

- Affects all three surfaces of directive-text appending (`appendLedgerText` on MCP/GraphQL, `POST .../directives/text` on REST).
- Adjacent states: non-budget `custom` directives (`custom "fava-option" ...`) must remain unaffected; `allowInvalid: true` skips the check as in `addLedgerEntries`; an existing opened account or parent account (e.g. `Expenses:Food`) continues to pass.

## Dedupe

- Searched `.pm/**/*.md` (open, done, blocked) for `assertBudgetAccountsExist`, `custom "budget"`, `w23/071`, `w23/221`, and `appendLedgerText` + `budget`. `w23/done/071` and `w23/done/221` added and refined `assertBudgetAccountsExist` only on `addLedgerEntries` (`writeBulkEntries`); no open, blocked, or done item tracks the gap on `appendLedgerText`.

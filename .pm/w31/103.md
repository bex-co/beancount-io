# A routed entry write is refused `UNBALANCED` within the ledger's own tolerance: the entries precheck reads `inferred_tolerance_default` only from the files the entries go to, not from `main.bean`, so the preview says `valid: true` and the commit refuses, on MCP, REST and GraphQL

**Minor · ledger (`src/api/entries.ts`) · 30–45m · A1.** Both engines honor an `option` line only in the top-level file, `main.bean`. Every ledger that `createLedger` and the starter template make carries `option "inferred_tolerance_default" "*:0.001"` there. The entries precheck runs before any write. It reads that option only from the files the batch writes to. An entry that a `transaction_file` rule routes to another file therefore gets no configured tolerance. Its commit is refused `UNBALANCED`, though bean-check accepts it and the same call's `dry_run` returned `valid: true`. The preview rule (`backend-cluster/backend-v2/docs/mcp.md`, "The preview rule") is broken: the preview no longer predicts the commit.

Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 LAND=1`) on 2026-11-26.

- **Target:** `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`). Local HEAD `fa9af286c` has the same code.
- **Credential:** an unpinned read/write `bcio_` key on the QA account.
- **Writes:** only to the designated QA ledger `<qa-owner>/mcp-agent-eval`. The QA commits were `ee49b6b1` (setup), `cb368307` (routing dropped), `b0bad1f6` (control entry) and `b0678264` (restore).
- **Cleanup:** `main.bean` was restored byte for byte (git blob `f1a0b83c`, sha256 `77c3a591efd311e0`), and the check showed 0 errors. No routed file was created.

## Repro (live)

1. In `main.bean`, after `option "operating_currency" "USD"`, add:

   ```beancount
   option "inferred_tolerance_default" "USD:0.01"
   2000-01-01 custom "beancountio-option" "transaction_file" "qa-20261126-tol/{year}.bean"
   ```

2. Call `addLedgerEntries` with `dry_run: true` and one transaction. It is dated `2026-08-30`, with postings `Assets:Cash -10.00 USD` and `Expenses:Transport 9.99 USD`. The residual is -0.01 USD, inside the configured 0.01.
   - It returns `valid: true`, `newErrors: []`, "Would add 1 entry; main.bean would include qa-20261126-tol/2026.bean".
   - `appendLedgerText` with the same transaction as text, with `dry_run: true`, also returns `valid: true`.
   - GraphQL `bulkEntries(dryRun: true)` returns `success: true`.
3. Send the same `addLedgerEntries` call without `dry_run`. It is refused `UNBALANCED`: "entry 0: Transaction does not balance: residual -0.01 USD".
   - REST `POST /api-gateway/v1/ledgers/{owner}/{name}/entries` returns `400 UNBALANCED` with the same message.
   - GraphQL `bulkEntries` returns the same error, with `extensions.code: "UNBALANCED"`.
4. Control: drop the `transaction_file` line and keep the option. The same commit lands in `main.bean` (`Added 1 entry to main.bean. No new bean-check errors.`), because the precheck now reads the file that holds the option.

The local engine agrees with stock Beancount. With `@rustledger/wasm` 0.24.0 (`validateMultiFile`), a `main.bean` holding the option that includes a file with the transaction is valid. Without the option, the same file map is refused `E3001` "residual -0.01 USD". With the option moved into an included file, it is also refused: options outside the top-level file do not apply.

The starter's `*:0.001` hits the same path for an integer-amount leg, such as `3 VTI {33.333 USD}` paid with `-100 USD`. This shape was not run live.

## Cause

- `backend-cluster/ledger/src/api/entries.ts:288-295`: when `allowInvalid` is not set, `scanInferredToleranceDefaults` reads only `currentContents`. That map holds the batch's target files, keyed by `row.filename || defaultFilename` (`:278-282`). A routed target such as `txns/2026.bean`, or an empty file the write will create, holds no option. The code comment there already names the gap: "an `inferred_tolerance_default` living in an unrelated file is missed". It came in with w21/648 (`567f093bc`).
- The precheck also reads an option line in a target file that is not the entry point. The engine ignores such a line, so the precheck can accept what bean-check will refuse.
- backend-v2 sends every caller preview with `allowInvalid: true` (`backend-cluster/backend-v2/src/features/ledger/service/ledger-entry-service.ts:1058-1070`). The precheck is skipped, and only the engine's bean-check judges the preview. The commit and the internal pre-write guard (w31/092) run the precheck, so they disagree with the preview.

## Fix

Read the tolerance option where both engines read it: from `main.bean` (`DEFAULT_ENTRY_POINT`) alone.

- Fetch the entry point into `currentContents` before the precheck, even when no entry targets it. The include step at `:362-364` reads it anyway.
- Scan only that text.
- The refusal stays `UNBALANCED` with its residual. A commit outside the configured tolerance is still refused.

MCP `addLedgerEntries`, REST `POST …/entries`, GraphQL `bulkEntries` and the legacy `addEntries` all reach this one ledger route, as does the bank import's `addBulkEntries` call (`plaid-sync-service.ts:834`). They change together, and no response shape changes.

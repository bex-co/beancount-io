# `yarn mcp:conformance` fails check 5 for an unpinned read-only key run without `--ledger`, where checks 10 and 17 skip

Source: `/loopx w31` item `w31/001`, authenticated MCP QA run 2026-11-15 against `https://beancount.io` (`serverInfo` `beancount-mcp 1.0.0`, protocol `2025-11-25`, `revision: unknown`), with an unpinned `bcio_` read/write key and an unpinned `ledger.read` key on the QA account.

- Repro: put two unpinned keys in the repo-root `.env` as `QA_MCP_TOKEN` and `QA_MCP_READ_ONLY_TOKEN`, then `cd backend-cluster/backend-v2 && yarn mcp:conformance https://beancount.io` (no `--ledger`). Result: `15 passed, 1 failed, 2 skipped`, exit 1. Check 5 says `FAIL 5 refusal-dialect — the tool failed, but not because write authority was refused`. Checks 10 and 17 say `SKIP`, for the same missing `--ledger`.
- What check 5 received: its `createLedgerFiles` probe came back `isError: true`, `BAD_USER_INPUT`, "Select a ledger using ledger: owner/name", with the `listLedgers` hint. That is the documented answer to an unpinned key that names no ledger. It says nothing about write authority either way.
- Control: the same run with `--ledger <qa-owner>/mcp-agent-eval` reports `18 passed, 0 failed, 0 skipped`, and check 5 passes with `FORBIDDEN`.
- Root cause: `checkScopeRefusal` in `backend-cluster/backend-v2/scripts/mcp-conformance.ts` (the `refusalText.includes("ledger.write")` test, line 396) treats every refusal that does not mention `ledger.write` as a failure. Check 10 (`checkResultShape`, line 438) turns a refused call into a skip instead. The script's header promises "a skip is honest … a failure would claim evidence that was never gathered". `docs/mcp.md` already says checks 5, 10 and 17 need `--ledger` for an unpinned key. But the qa-find-bugs-mcp skill (`.agents/skills/qa-find-bugs-mcp/SKILL.md`, "result-shape and output-schema checks") and `backend-cluster/backend-v2/AGENTS.md` name only 10 and 17, or only 17.
- Effect: a self-hoster or QA run with account-wide keys sees a red verdict and exit 1 for a deployment that conforms.

**Done when:** with an unpinned read-only key and no `--ledger`, check 5 reports `SKIP` and names `--ledger owner/name`, and the run exits 0 when nothing else fails. A refusal that is neither the missing-ledger answer nor a `ledger.write` refusal still fails. A unit case in `scripts/__tests__/mcp-conformance.test.ts` covers the skip, and it fails with the fix reverted. The skill and `backend-cluster/backend-v2/AGENTS.md` both say that checks 5, 10 and 17 need `--ledger` for an unpinned credential. Package: `backend-cluster/backend-v2` (script, test, docs only; no API surface changes).

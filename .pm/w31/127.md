# A missing-commodity error the ledger already has reads as new once a write changes the first account that uses the currency: opening `Assets:US:Ally:Savings USD` relabels "… for 'USD' in 'Assets:US:BofA:Checking'" to "… in 'Assets:US:Ally:Savings'", and the write is refused on every entry, file and rename write (the `check_commodity` twin of w31/113 and w31/115)

**Minor · backend-v2 (`src/features/ledger/utils/bean-check-errors.ts`) and ledger (`src/features/ledger/utils/new-ledger-errors.ts`) · 30–45m · A1.** Both copies of the "which errors are new" rule match errors by message and file, after `withoutEntryTag` trims the entry tag, a balance assertion's "got" figure (w31/113) and the lot figures (w31/115). With `plugin "beancount.plugins.check_commodity"` (or `pedantic`) declared, the ledger reports one error per undeclared currency. That error names the alphabetically first account that uses the currency, the same way stock Beancount does (`check-commodity.ts:122-148`, w21/739):

- `Missing Commodity directive for 'USD' in 'Assets:US:BofA:Checking'`

That account name comes from the ledger's state, not from the write. A write that opens or posts to an account that sorts before it (any new `Assets:…:A…` bank account, say) relabels the error. A rename of that account does the same, because the next account becomes the first. The error the ledger already had then reads as new. The preview answers `valid: false` with `errorsBefore` equal to `errorsAfter`, and the commit is refused `VALIDATION_FAILED` unless `allowInvalid` is passed. `docs/mcp.md` promises that "Errors the ledger already had never block". Stock `bean-check` 3.2.3 reports exactly one USD error before and after such a write, with only the account name changed.

Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 LAND=1`) on 2026-11-27 against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`; `mcp:conformance` 19/19 and the contract replay were clean). The credential was an unpinned read/write `bcio_` key on the QA account. Writes went only to the designated disposable QA ledger `<qa-owner>/qa-20261026-lifecycle` (a copy of the Beancount example ledger, with two pre-existing `Included file not found` errors): setup commit `6100921b`, then restore commit `16088f1d`. `main.bean` was restored byte for byte (git blob `cd53dc8b`, sha256 `43dae1ec957f84c0`), and the check again shows only the two include errors. Local HEAD `d682554fb` has the same two functions.

## Repro (live)

1. On a ledger that opens `Assets:US:BofA:Checking USD`, declares no `commodity USD`, and has no account that sorts before it using USD, add the plugin with `allow_invalid: true`:

   ```beancount
   plugin "beancount.plugins.check_commodity"
   ```

   `checkLedger` then lists `Missing Commodity directive for 'USD' in 'Assets:US:BofA:Checking'`. The example ledger also gets one error for each of its eight stock commodities, and none of them change below.
2. Preview opening a new bank account: `appendLedgerText {"dry_run": true, "text": "2025-10-13 open Assets:US:Ally:Savings USD\n"}`. It returns `validation: {errorsBefore: 11, errorsAfter: 11, newErrors: [{message: "Missing Commodity directive for 'USD' in 'Assets:US:Ally:Savings'", code: "PLUGIN"}], valid: false}`.
   - REST `POST /api-gateway/v1/ledgers/{owner}/{name}/directives/text` with `dryRun: true` and GraphQL `appendLedgerText(dryRun: true)` return the same `newErrors` and `valid: false`.
   - `addLedgerEntries` with `dry_run` on an `open` of `Assets:US:Ally:Savings` (`currencies: ["USD"]`) plus a transfer from `Assets:US:BofA:Checking` returns the same `newErrors`. That path uses the ledger service's copy of the rule.
   - `renameAccount {"from": "Assets:US:BofA:Checking", "to": "Assets:US:Wells:Checking", "dry_run": true}` returns `errorsBefore: 11, errorsAfter: 11`, `newErrors: [{message: "Missing Commodity directive for 'USD' in 'Assets:US:ETrade:Cash'"}]`, `valid: false`. w31/114's renaming maps the old message to `… in 'Assets:US:Wells:Checking'`, but the first account is now another one.
3. The same `appendLedgerText` and `addLedgerEntries` without `dry_run` are refused `VALIDATION_FAILED`: "would introduce 1 new bean-check error: Missing Commodity directive for 'USD' in 'Assets:US:Ally:Savings'". Nothing is written.

Control: `2025-10-13 open Assets:US:Chase:Savings USD`, which sorts after `Assets:US:BofA:Checking`, previews `valid: true` with `newErrors: []` on `appendLedgerText` and `addLedgerEntries`.

Stock control, with synthetic files: `bean-check` 3.2.3 on a ledger with the plugin, `open Assets:Bank:Checking USD` and one USD transaction prints `<check_commodity>:0: Missing Commodity directive for 'USD' in 'Assets:Bank:Checking'`. With `2026-09-01 open Assets:Bank:Ally USD` appended, it prints the one line `… for 'USD' in 'Assets:Bank:Ally'`.

## Fix

- In both `withoutEntryTag` copies, key `Missing Commodity directive for '<currency>' in '<context>'` on `<currency>` alone. Beancount issues that error once per currency, so the currency is its identity, and the context is only the first use. This also covers the price context, `'Price Directive Context'`.
- Keep the per-message count. A second undeclared currency is still new.
- Check whether the `onecommodity` wording, `More than one currency in account '<account>': A,B` (`one-commodity.ts:212`), has the same flaw. It lists currencies in the order they are first used and is placed on the account's last entry. An earlier entry in the other currency would reverse the list, and a later entry in another file would move the error. Neither was tried live. If either one relabels the error, key it on the account and the set of currencies.
- Tests:
  - `bean-check-errors.test.ts` and the ledger's `new-ledger-errors` tests: a changed context matches, and a second currency does not.
  - A parity case on MCP, REST and GraphQL over a fixture like step 1: `appendLedgerText` and `addLedgerEntries` preview `valid: true`, the commit lands without `allowInvalid`, and `renameAccount` previews `valid: true`.
  - Revert the fix and watch the tests fail.
- `docs/mcp.md` (the preview rule): state that a missing-commodity error is matched on its currency.

## Done when

On a fixture like step 1, opening `Assets:US:Ally:Savings USD` previews `valid: true` with `newErrors: []` on `appendLedgerText`, `addLedgerEntries` and `updateLedgerFiles`, and on REST and GraphQL. Its commit lands without `allowInvalid`. The `renameAccount` preview in step 2 is `valid: true`. `checkLedger` then shows the one USD error naming `Assets:US:Ally:Savings`. A new undeclared currency still previews `valid: false`.

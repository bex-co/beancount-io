# Trailing `#` (empty fragment) bypasses fragment refusal in `QueryResourceTemplate.match`, returning `200 OK` on every MCP resource URI instead of `BAD_USER_INPUT`

**Minor · backend-v2 (`QueryResourceTemplate.match` in `src/features/ai-agent/api/mcp-resource-template.ts`) · 15–20m · A1.** `backend-cluster/backend-v2/docs/mcp.md` ("Failure codes") states that a resource URI carrying a `#` fragment is refused with `BAD_USER_INPUT` (`-32602`) `"Resource fragments are not supported"`. However, `QueryResourceTemplate.match` (`mcp-resource-template.ts:45,64`) strips `#` from the path before matching and then checks `if (url.hash)`. Under the WHATWG URL standard, `new URL("beancount://owner/name/payees#").hash` is `""` (empty string, falsy) for a bare trailing `#`. Any MCP resource URI ending in `#` — static, query-bearing, or file-path — therefore bypasses the fragment check and returns `200 OK`, whereas `#frag` is refused with `-32602` `BAD_USER_INPUT`. Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`) on 2026-11-23 against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, verified at HEAD `40e22400b`). Credential: unpinned read/write/admin `bcio_` key on the QA account. Synthetic ledger: `<qa-owner>/mcp-agent-eval` (read-only for this finding).

## Repro (live)

Send fresh `resources/read` requests with a bare trailing `#` vs a non-empty fragment:

```sh
node .agents/skills/qa-shared/scripts/qa-mcp.mjs read 'beancount://<qa-owner>/mcp-agent-eval/payees#'
node .agents/skills/qa-shared/scripts/qa-mcp.mjs read 'beancount://<qa-owner>/mcp-agent-eval/journal?limit=1#'
node .agents/skills/qa-shared/scripts/qa-mcp.mjs read 'beancount://<qa-owner>/mcp-agent-eval/files/main.bean#'
node .agents/skills/qa-shared/scripts/qa-mcp.mjs read 'beancount://configuration/health#'
```

- Actual: all four return HTTP `200` with the resource payload (`payees` list, `journal` page, `main.bean` text, `"OK"`).
- Control:
  ```sh
  node .agents/skills/qa-shared/scripts/qa-mcp.mjs read 'beancount://<qa-owner>/mcp-agent-eval/payees#frag'
  ```
  returns JSON-RPC `-32602`, `BAD_USER_INPUT`: `"Resource fragments are not supported"`, hint `"Drop the `#` fragment; a resource URI takes a path and an optional query only."`

Expected:

- Any resource URI containing a `#` fragment delimiter — empty (`#`) or non-empty (`#frag`) — is refused with JSON-RPC `-32602`, `BAD_USER_INPUT`: `"Resource fragments are not supported"` and the existing hint.
- Percent-encoded `%23` inside a path or query parameter (not a literal `#`) continues to decode and work unchanged.

## Root cause

Not deployment lag — present at HEAD `40e22400b`:

`backend-cluster/backend-v2/src/features/ai-agent/api/mcp-resource-template.ts:44-68`:

```ts
    const url = new URL(uri);
    const path = uri.split("?")[0].split("#")[0];
    ...
    if (url.hash)
      refuseUri(
        "Resource fragments are not supported",
        "Drop the `#` fragment; a resource URI takes a path and an optional query only.",
      );
```

In JavaScript's WHATWG `URL`, `url.hash` is `""` for both no fragment and an empty `#` fragment. Because line 45 already stripped `#` before matching `pathTemplates`, a trailing `#` matches the template and skips the `if (url.hash)` guard.

## Fix

In `backend-cluster/backend-v2`:

1. In `QueryResourceTemplate.match` (`src/features/ai-agent/api/mcp-resource-template.ts:64`), change `if (url.hash)` to `if (url.hash || uri.includes("#"))` (per RFC 3986, a literal `#` only introduces a fragment; encoded `%23` does not contain `#`).
2. In `src/features/ai-agent/api/__tests__/mcp-resources.test.ts` (`describe("a malformed resource URI")`), add cases for bare trailing `#` on a static resource (`beancount://alice/main/errors#`), a query-bearing resource (`beancount://alice/main/trial-balance?time=2026#`), and a file resource (`beancount://alice/main/files/main.beancount#`), plus verify `%23` in a parameter/path is not falsely refused.

## Blast radius & adjacent states

- MCP-only (`QueryResourceTemplate` in `mcp-resource-template.ts` is shared by every registered MCP resource template via `queryTemplateFor` in `mcp-resources.ts:956`). REST and GraphQL do not use `beancount://` resource URIs (HTTP clients strip fragments before sending requests over the wire).
- Adjacent states: valid URIs without `#`, percent-encoded `%23` in query values or file paths, unknown/repeated query parameters, and invalid percent-encoding keep existing behavior.

# A `./`-prefixed `receipt_base_folder` is not normalized before the receipt path is built (w31/152 sibling)

**Minor · backend-v2 (receipt workflow) · 20–30m · A1.** The `w31/152` worker flagged this as a follow-up outside its item. `w31/152` (`db4949816`) normalizes the routing options (`resolveEntryFile`), so a `./`-prefixed `default_file`, budget file, or similar option no longer refuses every routed write. `receipt_base_folder` goes down another path. `src/features/ledger/workflow/ledger-receipt-workflow.ts` reads it as `bcioData.receipt_base_folder || "documents"` and passes it to `buildReceiptPath` unchanged. The path that comes out is sent to `createLedgerFile` as the repository path.

- Expected, not yet run (the worker confirms it first): with `receipt_base_folder` set to `./receipts`, attaching a receipt builds `./receipts/…`. The file write then refuses it as an invalid path, or stores it under a name the `document` directive does not resolve to. It would be the same refusal `w31/152` fixed for the routing options.
- Fix as `w31/152` did: normalize the folder through the same safe-path rule before the path is built. If the option names an unsafe path (`..`, absolute), refuse with a hint that names the option, not the caller's arguments.
- Done when a receipt attach with `./receipts` (and with `receipts/`) stores the file at `receipts/…`, the `document` directive resolves to it, and an unsafe value is refused with the option named. A test covers it and fails with the fix reverted, on every surface that attaches receipts.

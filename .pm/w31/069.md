# `resources/list` emits raw unencoded `files/${path}` URIs, producing unreadable URIs for source files containing `#`, `?`, or `%`

**Minor · backend-v2 (`src/features/ai-agent/api/mcp-resources.ts`) · 25–35m · A1.** `listLedgerResources` (`mcp-resources.ts:933-940`) advertises concrete `ledgerFile` resource URIs in `resources/list` by interpolating the raw repository path into `` `beancount://${ledgerId}/files/${path}` `` without percent-encoding each path segment. Meanwhile, `QueryResourceTemplate.match` (`mcp-resource-template.ts:52-87`) refuses `#` fragments, parses `?` as query parameters, rejects invalid `%XX` sequences, and runs `decodeURIComponent` once on the matched `path` variable. Any loaded ledger file whose name contains `#`, `?`, `%`, or literal `%XX` (all legal in Beancount `include` directives and Gitea) is therefore advertised by `resources/list` with a URI that `resources/read` immediately refuses with `BAD_USER_INPUT` or resolves to the wrong filename (`NOT_FOUND`). Found by `/loopx w31` routine `mcp-qa` (`/qa-find-bugs-mcp w31 SHIP=1`) on 2026-11-23 against `https://beancount.io` (`beancount-mcp 1.0.0`, protocol `2025-11-25`, verified at HEAD `dc57d76b6`). Credential: unpinned read/write/admin `bcio_` key on the QA account. Synthetic ledger: `<qa-owner>/mcp-agent-eval` (snapshotted before writes and restored byte-for-byte with 0 `checkLedger` errors afterward).

Expected:

- Every URI returned by `resources/list` is immediately readable by `resources/read` without caller-side rewriting.
- `listLedgerResources` percent-encodes each path segment (`path.split("/").map(encodeURIComponent).join("/")`) so `qa-20261123-a#1.bean` is advertised as `beancount://<qa-owner>/mcp-agent-eval/files/qa-20261123-a%231.bean`, nested paths keep `/` separators (`2026/acct%231.bean`), `?` becomes `%3F`, `%` becomes `%25`, literal `%25` becomes `%2525`, and spaces become `%20`.

## Root cause

Not deployment lag — present at HEAD `dc57d76b6`:

- `backend-cluster/backend-v2/src/features/ai-agent/api/mcp-resources.ts:933-940`:
  ```ts
  for (const path of files.slice(0, MAX_LISTED_SOURCE_FILES)) {
    listed.push({
      template: fileTemplate.name,
      uri: `${RESOURCE_SCHEME}://${ledgerId}/files/${path}`,
      title: fileTemplate.title,
      mimeType: fileTemplate.mimeType,
    });
  }
  ```
- Meanwhile, `mcp-resources.test.ts:290-296` already tests `resources/read` by encoding each segment with `path.split("/").map(encodeURIComponent).join("/")` (and `mcp-resources.test.ts:444-463` tests `notes%231.beancount`), confirming that segment-wise `encodeURIComponent` is the exact inverse of `QueryResourceTemplate.match`'s single `decodeURIComponent` pass.

## Fix

In `backend-cluster/backend-v2`:

1. In `src/features/ai-agent/api/mcp-resources.ts` (`listLedgerResources`), encode each path segment when building `ledgerFile` URIs:
   ```ts
   const encodedPath = path.split("/").map(encodeURIComponent).join("/");
   uri: `${RESOURCE_SCHEME}://${ledgerId}/files/${encodedPath}`,
   ```
2. Add unit/contract tests in `src/features/ai-agent/api/__tests__/mcp-resources.test.ts` that run `client.listResources()` followed by `client.readResource({ uri })` with the exact URI returned for source files containing `#`, `?`, `%`, literal `%25`, spaces, non-ASCII UTF-8 (e.g. `receipts/café 100%25 #1?a.bean`), and ordinary nested paths (`2026/expenses.bean`), asserting `getFilesContent` receives the original unencoded path verbatim.

## Objective

Build a publishable bundle for each skill that contains every file the skill reads, so a skill installed alone from a registry never points at a missing file. Keep the repository's single canonical copy of each shared contract.

## Context

- Every `beancount-*` skill points at `beancount-init/references/bea-cli.md` (the shared `bea` execution contract). Some also read `beancount-import/references/dedup.md` or `bea-import.md`, or `beancount-reconcile`'s guidance. Run `grep -rnoE "beancount-[a-z-]+/references/[^ )]+" skills/.claude/skills` to get the current list.
- `skills/scripts/beancount-skills.py` `verify` already accepts a reference when the file sits in the skill's own `references/` *or* in a sibling named on the same line (`owners = [name, *siblings]`). A bundle that copies a sibling's reference into the skill's own `references/` therefore satisfies the same rule.
- `skills/AGENTS.md`: the helper is stdlib-only. Do not keep duplicated reference copies in the source tree. The bundle is a build output.

## Steps

1. Add a `bundle <skill> <out-dir>` command to `beancount-skills.py`, or a sibling stdlib script, that copies one skill folder and every sibling reference file it names into the bundle's `references/`. Leave out `evals/` and anything the installed skill never reads.
2. Run `verify` against a directory that holds only that one bundle. It must pass for each of the eight.
3. Fail the build when a skill names a sibling file that does not exist, so a broken bundle is never published.

## Files

- `skills/scripts/beancount-skills.py` (or a new `skills/scripts/` helper)
- `skills/tmp/` for local output (gitignored)

## Acceptance criteria

- [ ] Each of the eight bundles passes `verify` when installed alone.
- [ ] The source tree still has exactly one copy of each shared reference.
- [ ] A skill that names a missing sibling file makes the bundle build fail.

## Out of scope

- Rewriting the reference text in `SKILL.md` files. t003 handles sibling *workflows*.

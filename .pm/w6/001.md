# Classify malformed MCP request parameters before SDK validation escapes

**Severity:** minor. **Estimate:** 60 minutes, including transport regression coverage; promote if the SDK boundary requires more work. **Owner:** backend-v2. **A1 — Agent-native accounting:** agents must distinguish input mistakes from retryable internal failures and receive the documented code and corrective hint.

## Live reproduction

Observed 2026-10-09 on production `https://beancount.io/api-gateway/mcp`. Node 24.16.0; initial checkout `main`, `bab6a588`; source/history rechecked after updating to `25ef12a3`. `initialize` reports `beancount-mcp` 1.0.0, protocol `2025-11-25`. Deployment SHA is unavailable; equality with HEAD is unverified. Credential: designated QA `bcio_` API key with `ledger.read`, `ledger.write`, and `ledger.admin`, unpinned. These reproducers require no ledger or private account data.

Run from the repository root, loading the credential inside the bundled helper:

```sh
node .agents/skills/qa-shared/scripts/qa-mcp.mjs --credentials-file /path/to/qa.env rpc tools/call '{"name":"runBqlQuery","arguments":null}'
node .agents/skills/qa-shared/scripts/qa-mcp.mjs --credentials-file /path/to/qa.env rpc resources/read '{"uri":42}'
node .agents/skills/qa-shared/scripts/qa-mcp.mjs --credentials-file /path/to/qa.env rpc prompts/get '{"name":"close-month","arguments":{"month":42}}'
```

Each was repeated in a fresh HTTP request with the same result: HTTP 200, `Content-Type: text/event-stream`, JSON-RPC `error.code: -32603`, no `error.data`, and a raw Zod issue array as the message. The first response is:

```json
{"jsonrpc":"2.0","id":1,"error":{"code":-32603,"message":"[\n  {\n    \"expected\": \"record\",\n    \"code\": \"invalid_type\",\n    \"path\": [\n      \"params\",\n      \"arguments\"\n    ],\n    \"message\": \"Invalid input: expected record, received null\"\n  }\n]"}}
```

Independent affected inputs: tool `arguments` as an array, string, or number; tool `name: null`; prompt `arguments: null`. Resource and prompt examples name `params.uri` and `params.arguments.month` in the raw issue array, respectively. There is no machine-readable `BAD_USER_INPUT` or hint. These are client input mistakes, not internal failures.

## Controls and root cause

- `tools/call` for `runBqlQuery` with `arguments: {"query":42}` correctly returns `isError:true` and `structuredContent:{ok:false,error:{code:"BAD_USER_INPUT",message,hint}}`. Omitting its required query has the same coded refusal.
- `resources/read` for `beancount://configuration/health` succeeds. A string URI that cannot be parsed is correctly refused with `-32602` and `data.code: BAD_USER_INPUT`.
- `prompts/get` for `close-month` with `{}` succeeds; `month:"2026-13"` is correctly refused with the coded `-32602` envelope. Numeric month fails before that application validator runs.
- With the same credential and a synthetic QA ledger, REST query input `{"query":42}` returns HTTP 400, `error.code: VALIDATION_FAILED`, field `body.query`. GraphQL `queryShell` with a numeric String variable returns HTTP 400 and `extensions.code: BAD_USER_INPUT`; its valid String control succeeds.
- `src/server/api/composition-root.ts:534,706,797` registers the three overrides using `CallToolRequestSchema`, `ReadResourceRequestSchema`, and `GetPromptRequestSchema`. Their custom validation/error translation begins inside the callbacks.
- Installed MCP SDK 1.30.0 `dist/cjs/shared/protocol.js:895` parses that outer request schema before invoking the callback. A Zod failure escapes; `_onrequest` at line 402 defaults errors without a numeric `code` to `InternalError` and omits `data`. Application masking/translation is never reached.

The shared registration boundary affects all tools, resource reads, and prompts; the specific tool name or ledger does not cause it. No authorization bypass or sensitive-data disclosure is claimed. No domain mutation was sent.

## Fix and acceptance

Own outer-parameter validation at the public MCP adapter boundary so SDK schema failures cannot escape as internal errors. Retain the published schemas, full validation, authorization, and successful output checks; do not patch private SDK internals. A named tool with malformed `arguments` should receive the documented `isError:true` / `BAD_USER_INPUT` tool envelope. Malformed resource/prompt parameters and invalid method-level fields should receive `-32602` with `data.code: BAD_USER_INPUT`, a concise field path, and a corrective hint.

Add real HTTP/registry-dispatch regression cases for each reproduced family, including absent optional arguments, valid calls, missing required fields, malformed container types, and numeric prompt values. Verify invalid input reaches no domain service. REST and GraphQL already classify the exercised controls correctly; preserve those behaviors and protocol-specific envelopes. This is an MCP protocol-adapter repair, not a new domain capability or a reason to change surface eligibility. Run backend-v2 typecheck, tests, and OpenAPI drift generation when implementing.

# Keep nonzero account movements when interval totals cancel to zero

**Severity:** major. **Estimate:** 35–50 minutes, including adapter regression coverage. **Owner:** backend-v2. **A1 — Agent-native accounting:** an interval summary must not erase a real transfer's account movements and present its conversion strategy as a currency.

## Live reproduction

Production `https://beancount.io/api-gateway/mcp`, 2026-10-10; `main` at `97600b74`; Node 24.16.0. `initialize` reports `beancount-mcp` 1.0.0, protocol `2025-11-25`. Deployment SHA and equality with HEAD are unavailable. Designated QA `bcio_` key: scopes `ledger.read ledger.write ledger.admin`, no pin, verified through its REST metadata without recording its value. Only the existing synthetic MCP evaluation ledger was read.

Minimal synthetic fixture for another QA ledger:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Bank:Checking USD
2026-01-01 open Assets:Bank:Savings USD
2026-01-01 open Equity:Opening-Balances USD
2026-01-01 * "Opening balances"
  Assets:Bank:Checking       1000 USD
  Equity:Opening-Balances   -1000 USD
2026-03-15 * "Transfer to savings"
  Assets:Bank:Checking       -500 USD
  Assets:Bank:Savings         500 USD
```

Run from the repo root with the designated key loaded inside the helper:

```sh
node .agents/skills/qa-shared/scripts/qa-mcp.mjs --credentials-file /path/to/qa.env read 'beancount://qa-owner/qa-book/interval-totals?conversion=units&time=2026-03&accountName=Assets%3ABank'
```

Two fresh MCP requests return HTTP 200, `Content-Type: text/event-stream`, `mimeType: application/json`, and this successful content payload:

```json
{"currency":"units","intervals":[{"period":"2026-03-31","total":0,"byAccount":[]}]}
```

Changing only `conversion=at_cost` likewise produces `currency:"at_cost"`, total zero, and an empty breakdown. The zero *total* is correct; the currency label and omission of both nonzero account movements are wrong.

## Controls and parity

- Adding `shape=fava` returns `[{"date":"2026-03-31","balance":{},"account_balances":{"Assets:Bank:Checking":{"USD":"-500"},"Assets:Bank:Savings":{"USD":"500"}}}]`. A fresh repeat preserves both amounts. An empty net balance does not mean every account is empty.
- Changing only `conversion=USD` returns `currency:"USD"`, total zero, and both `byAccount` rows with balances `-500` and `500`.
- The identical REST route, `GET /api-gateway/v1/ledgers/qa-owner/qa-book/interval-totals` with the same query parameters, reproduces the faulty summary twice and the same raw/explicit-currency controls. This is a shared REST/MCP projection bug, not a protocol-specific discrepancy.
- GraphQL `getLedgerIntervalTotals(ledgerId:"qa-owner/qa-book", accountName:"Assets:Bank", time:"2026-03", conversion:"units", interval:"monthly") { date balance accountBalances }` returns the correct two account movements and empty net map, HTTP 200.
- BQL `SELECT account, SUM(number) WHERE year = 2026 AND month = 3 AND account ~ '^Assets:Bank' GROUP BY account` independently confirms the same signed movements.
- A nonzero-net `Expenses` interval with `units`, `at_cost`, or `USD` resolves USD and preserves its accounts. That control explains why ordinary nonzero summary fixtures pass.

## Root cause and fix

- `src/features/ledger/utils/report-summaries.ts:244–263` calls `resolveCurrency` using only each interval's aggregate `balance`, excluding `account_balances` from the currency evidence.
- `resolveCurrency` at lines 95–119 starts its fallback with the requested `conversion`. When every aggregate map is empty because its accounts cancel, it finds no currencies and returns the strategy name `units` or `at_cost` unchanged.
- `amount` reads each account's nonexistent `balance["units"]` / `balance["at_cost"]` as zero. The summary then drops those newly fabricated zeros from `byAccount`.
- Caller search finds `summarizeIntervalTotals` used by `ANALYSIS_READS` at `src/features/ledger/api/rest/v1/analysis-handler.ts:148–172`; `mcp-resources.ts:196–225` delegates to that same descriptor. GraphQL's resolver at `ledger-data-resolver.query.ts:675–695` returns the correct raw service data and bypasses the projection. Other statement summaries share `resolveCurrency` but have different currency-evidence inputs; they are not claimed affected without separate live proof.

When aggregate balances provide no currency but account movements do, infer the stated currency from those account balances using the existing selection policy. Preserve an explicit supported currency, the valid zero net total, signed nonzero account rows, and genuinely zero-account omission. Do not hardcode USD, add different currencies together, or treat a conversion strategy name as a balance-map currency. No ledger-engine change is indicated by these controls.

Add behavioral coverage through the shared REST and MCP adapters for this zero-net transfer with `units` and `at_cost`, the explicit-USD control, a non-USD synthetic case, genuinely empty periods, nonzero-net reports, and the existing multi-currency selection policy. Keep GraphQL/raw results and authorization unchanged, asserting equivalent underlying amounts with their documented shape aliases. Run backend-v2 typecheck, tests, and OpenAPI drift generation when implementing.

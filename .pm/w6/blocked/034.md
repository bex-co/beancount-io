# Preserve FINDFIRST prefix and case matching semantics

**Severity:** minor · **Package:** ledger, with backend-v2 parity validation · **Estimate:** 35–50m after a compatible upstream release.

**A1 — Agent-native accounting.** An agent selecting a tag by a regular-expression prefix must not receive a middle-of-string or wrong-case match that Beanquery would reject.

## Reproduction

Live 2026-10-15, https://beancount.io/api-gateway/mcp, synthetic open_ledger/example, designated unpinned QA API key (ledger.read/write/admin). Last observed beancount-mcp 1.0.0, protocol 2025-11-25; deployed revision unavailable. No ledger writes.

Call runBqlQueryStructured using the root .env:

```json
{"ledger": "open_ledger/example", "query": "SELECT JOINSTR(tags) AS tag_text, FINDFIRST('boston', tags) AS middle_pattern, FINDFIRST('^trip-', tags) AS prefix_control, FINDFIRST('.*boston', tags) AS explicit_search, FINDFIRST('^TRIP-', tags) AS uppercase_pattern GROUP BY tags ORDER BY tag_text"}
```

Two fresh MCP and REST query calls return identical five-row tables; GraphQL queryShell agrees once. For tag trip-boston-2017, all four FINDFIRST columns return that tag. Expected middle_pattern and uppercase_pattern to be missing; prefix_control and explicit_search should return the tag. For each of the other three trip tags, uppercase_pattern also returns the tag unexpectedly. Empty tags return missing values correctly. The native null-to-blank wire rendering is unchanged.

Working controls: lower-case ^trip- matches each trip tag; .*boston explicitly permits a leading prefix and matches only Boston. The preceding grouped JOINSTR/FINDFIRST('trip-')/COUNT query returns 38 Boston, 42 Chicago, 34 LosAngeles2015, 40 LosAngeles2016 and 3055 untagged postings, matching the complete synthetic journal's tags/posting counts. All observed nonempty tag sets contain one tag, so multi-tag ordering is not claimed.

Minimal valid fixture:

```beancount
2026-01-01 open Assets:Test USD
2026-01-01 open Equity:Opening USD
2026-01-02 * "Synthetic trip" #trip-boston-2017
  Assets:Test 10 USD
  Equity:Opening -10 USD
```

For the reference control, run the same SELECT expressions with LIMIT 1 instead of GROUP BY/ORDER BY. Official Beanquery 0.2.0 does not support grouping the set-valued tags column, so that native extension is deliberately omitted from the scalar comparison. On the identical fixture/query, Beanquery returns:

```json
["trip-boston-2017",null,"trip-boston-2017","trip-boston-2017",null]
```

Installed @rustledger/wasm 0.24.0 Ledger.fromFiles(...).query(...) instead returns the tag in every column, with no validation/query errors. This isolates the two matching-policy differences from grouping and adapters.

## Root cause and repair direction

[Beanquery findfirst](https://github.com/beancount/beanquery/blob/master/beanquery/query_env.py) uses a case-sensitive re.match at the start of each candidate. The [tagged rustledger executor](https://github.com/rustledger/rustledger/blob/v0.24.0/crates/rustledger-query/src/executor/mod.rs) FINDFIRST arm obtains require_regex and uses regex.is_match, which searches anywhere. That shared cache compiles with case_insensitive(true), also admitting the wrong-case matches. Inspected current upstream main retains both behaviors. The direct valid native fixture removes API/cache prerequisites; local ledger src/foundation/rustledger/engine.ts::queryLedgerFilesResultInProcess delegates to native execution.

After upstream publishes a compatible corrected artifact, adopt it with the ledger package manager and validate actual native behavior plus eligible REST/GraphQL/MCP together. FINDFIRST must respect prefix and default case sensitivity, while explicit patterns such as .*boston continue to work. Give this function the correct regex policy; do not globally change the shared matcher used by intentionally case-insensitive BQL comparisons. Preserve explicit regex flags, failure handling and null/empty behavior according to the reference contract. Do not rewrite user queries, replace cells, fork upstream or vendor unreleased bytes.

Acceptance: the exact middle/default-uppercase cases no longer match, valid prefix/explicit-leading-wildcard controls still match, and genuine no-match/empty sets remain missing. Native-backed regressions cover these cases and verify neighboring regex operators retain their documented behavior. Multi-tag first-choice order, explicit flag combinations, links, invalid patterns and null operands need their own controls and were not live-verified here. Latest published and installed WASM checked this session were 0.24.0; no fixed commit identified.

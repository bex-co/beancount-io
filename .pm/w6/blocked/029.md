# Preserve Beanquery SUBST replacement and null semantics

**Severity:** minor · **Package:** ledger, with backend-v2 parity validation · **Estimate:** 35–50m after a compatible upstream release.

**A1 — Agent-native accounting.** An agent deriving labels with SUBST must receive Beanquery-compatible replacements and preserve missing metadata as null. Capture references, literal dollar text and nullable subjects currently diverge.

## Reproduction

Live 2026-10-15, https://beancount.io/api-gateway/mcp, synthetic open_ledger/freelancer-invoicing, designated unpinned QA API key (ledger.read/write/admin). Last observed beancount-mcp 1.0.0, protocol 2025-11-25; deployed revision unavailable. No ledger writes.

Call runBqlQueryStructured using the root .env; the JSON preserves the single backslash in the BQL replacement string:

```json
{"ledger": "open_ledger/freelancer-invoicing", "query": "SELECT account, SUBST('([^:]+)$', '\\1-copy', account) AS copied_leaf, SUBST(':', '$1', account) AS literal_dollar, SUBST(':', '/', account) AS slash_control LIMIT 3"}
```

Two fresh MCP and REST requests succeed with identical tables; GraphQL queryShell agrees once. For Assets:Bank:Business, copied_leaf is the literal `Assets:Bank:\1-copy` (one backslash), literal_dollar is `AssetsBankBusiness`, and slash_control is `Assets/Bank/Business`. Expected `Assets:Bank:Business-copy`, `Assets$1Bank$1Business`, and the same working slash control. Assets:Bank:TaxReserve and Equity:Opening reproduce the same two replacement failures. The backslash and dollar cases share the replacement-language mismatch below.

Minimal valid fixture:

```beancount
2026-01-01 open Assets:Bank:Business USD
2026-01-01 open Equity:Opening USD
2026-01-02 * "Synthetic opening"
  Assets:Bank:Business 10 USD
  Equity:Opening -10 USD
```

Run the exact SELECT above over this fixture. Installed @rustledger/wasm 0.24.0 Ledger.fromFiles(...).query(...) returns the same failure for both account rows, no validation/query errors. Official Beanquery 0.2.0 on the identical valid in-memory fixture returns `Assets:Bank:Business-copy` / `Assets$1Bank$1Business` and `Equity:Opening-copy` / `Equity$1Opening`. The colon-to-slash control agrees in both engines. A further live MCP/REST query verifies GREPN capture groups 1/2 and SUBST no-match passthrough against independent string operations on all 50 postings; all pass. Captures can be read correctly, while SUBST replacement expansion fails. An initial overescaped query was corrected before the exact repeated reproduction; only the single-backslash query above supports the capture-reference claim.

## Nullable subject in the same function

Live 2026-10-15 on synthetic open_ledger/freelancer-invoicing:

```json
{"ledger": "open_ledger/freelancer-invoicing", "query": "SELECT date, SUBST('^2026-', '', STR(ENTRY_META('invoice'))) AS invoice_suffix ORDER BY date, account"}
```

Two fresh MCP and REST calls reject this with BAD_USER_INPUT, SUBST expects (pattern, replacement, string); GraphQL queryShell agrees once. Expected one result per posting, with transformed invoice strings for 27 metadata-bearing postings and null for 23 without invoices. The typed STR wrapper makes this query valid in Beanquery as well. Filtering to ENTRY_META('invoice') IS NOT NULL returns 27 rows successfully on MCP/REST, while SUBST over STR(COALESCE(ENTRY_META('invoice'), '')) returns all 50 with explicit empty strings for missing invoices. Neither control should be forced on callers who want null preserved.

Independent valid fixture:

```beancount
2026-01-01 open Assets:Test USD
2026-01-01 open Equity:Opening USD
2026-01-02 * "Tagged opening" #trip-boston-2017
  invoice: "2026-001"
  Assets:Test 10 USD
  Equity:Opening -10 USD
2026-01-03 * "Untagged addition"
  Assets:Test 5 USD
  Equity:Opening -5 USD
```

The identical query in Beanquery 0.2.0 returns January 2 / 001 twice and January 3 / null twice. WASM 0.24.0 instead returns a native query error, with no fixture validation errors. Beanquery's function decorator propagates a null argument before invoking re.sub; the tagged SUBST arm has only a three-string branch and a generic type-error fallback. This is an additional confirmed case in this pending function-compatibility record, not a claim that the earlier replacement-language mismatch causes this failure.

Include null-subject propagation in the upstream requirement and adoption regressions. Preserve missing as null, keep an explicit empty string distinct, and preserve working nonnull replacements. Pattern/replacement null arguments remain unverified. No user-query rewrite or adapter blank-cell replacement is an appropriate repair.

## Root cause and repair direction

[Beanquery query_env.py](https://github.com/beancount/beanquery/blob/master/beanquery/query_env.py) delegates SUBST to Python re.sub, with Python replacement semantics. The [tagged rustledger executor](https://github.com/rustledger/rustledger/blob/v0.24.0/crates/rustledger-query/src/executor/mod.rs) passes the replacement string unchanged to regex::Regex::replace_all in the SUBST arm. The [Rust replacement contract](https://docs.rs/regex/latest/regex/struct.Regex.html#method.replace_all) interprets dollar capture references; a nonexistent reference is replaced with empty text. It does not interpret Python-style backslash capture references. Fresh upstream main still passes this string through unchanged. Latest npm checked this session and installed WASM were 0.24.0; no fixed commit or published repair identified.

Local ledger src/foundation/rustledger/engine.ts::queryLedgerFilesResultInProcess delegates through the native query object. The valid direct fixture removes API/cache layers as prerequisites. After upstream publishes a compatible engine preserving Beanquery replacement semantics, adopt it with the ledger package manager and validate the actual native result and eligible REST/GraphQL/MCP adapters together. Keep dollar text literal and expand valid backslash references correctly, preserving ordinary global substitutions. Do not rewrite arbitrary user queries, patch projected result strings, fork the engine or vendor unreleased bytes.

Acceptance: the exact backreference and literal-dollar reproductions return the expected account labels on real WASM and all APIs; ordinary substitution, no-match passthrough and repeated replacements remain correct. Add focused native-backed regressions. Named references, escaped backslashes, invalid reference errors, null pattern/replacement arguments and unmatched optional groups require compatibility tests; those were not live-verified here. Subject-null behavior was independently reproduced above. No claim that a blind backslash-to-dollar string replacement is sufficient.

## Objective

Add the frontmatter that OpenClaw and Hermes read, so each host shows what the skill needs and offers to install `bea`. Make the CI frontmatter check parse the nested metadata correctly.

## Context

- OpenClaw: `metadata.openclaw.requires.anyBins` (the skills prefer `bea` and fall back to developer `bean-*` tools, per `skills/AGENTS.md`), `install` specs of kind `brew` (`bex-co/tap/bea`) and `uv` (`beancount-io`), `homepage`, and `emoji`. Declare an environment variable only if a skill actually reads one, because ClawHub flags any mismatch between declared and observed behavior.
- Hermes: `platforms` (macOS and Linux are rehearsed. Windows is not covered, per `skills/docs/installation.md`), and `metadata.hermes.tags` / `category`.
- `skills/scripts/ci-check.py` `parse_frontmatter` is a flat line splitter. A nested key such as `name:` under `metadata` would overwrite the top-level `name`. It also checks `.agents/skills/`, so a fix there must not break the development skills.
- Claude Code and Codex must still load all eight skills (`skills/docs/installation.md` step 3).

## Steps

1. Make `parse_frontmatter` read only top-level keys, and check that any `metadata` block is well formed. Keep it stdlib-only.
2. Add the metadata to the eight `SKILL.md` files.
3. Re-run the installation guide's step 3 listing for Claude Code and Codex.

## Files

- `skills/.claude/skills/beancount-*/SKILL.md`
- `skills/scripts/ci-check.py`, `skills/scripts/test_ci_check.py`

## Acceptance criteria

- [ ] A nested `name:` under `metadata` cannot overwrite or satisfy the top-level `name` check (tested).
- [ ] All eight skills declare `bea` and its two install routes, and none declares an environment variable it does not read.
- [ ] Claude Code and Codex both list all eight skills after the change.

## Out of scope

- `requires_tools` gating in Hermes, unless t008 shows that a skill misbehaves without a particular tool.

## Evidence

- `metadata` is one line of JSON on each of the eight skills. OpenClaw parses frontmatter as YAML and re-reads `metadata` as JSON5 (`docs.openclaw.ai/tools/skills`). PyYAML (which Hermes uses) parsed all eight into `openclaw.requires.anyBins: [bea, bean-check]` with the Homebrew and uv `install` specs, and `hermes.category: finance` with per-skill tags.
- 2026-10-16: Claude Code and Codex CLI 0.163.0, each with the suite linked into a workspace, both listed all eight `beancount-*` skills.
- `ci-check.py` now parses only top-level keys and requires `metadata` to be a single-line JSON object. Tests in `test_ci_check.py` fail against the old parser.
- Left out on purpose: Hermes `platforms` and OpenClaw `os`. Windows is unrehearsed rather than known to be broken, and both fields hide a skill on the platforms they leave out. No environment variable is declared, because no skill reads one.

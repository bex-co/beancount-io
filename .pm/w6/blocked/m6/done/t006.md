## Objective

Publish every bundle from CI, so nobody publishes from a laptop and every published version traces back to a commit on `main`.

## Context

- Model it on `.github/workflows/publish-mcp-registry.yml` (w2/m36): validate on pull requests, publish only from `main`, take the secret from a protected environment, and require a reviewer.
- ClawHub provides a reusable workflow that publishes each folder directly under `skills/`. Since w2/m42 our skills sit directly under `skills/`, but the t002 bundling step still runs first, so a thin workflow of our own is probably simpler. Check before choosing.
- An unchanged skill is skipped rather than republished, and a changed one gets the next patch version. `--changelog` should say what changed, for example the short commit subject range.

## Steps

1. Add `.github/workflows/publish-clawhub.yml`. On a pull request touching `skills/**`: build the bundles and dry-run them. On `workflow_dispatch` with `publish` from `main`: sign in with `clawhub login --token "$CLAWHUB_TOKEN"` and publish each bundle.
2. Read `CLAWHUB_TOKEN` only from a `clawhub-publish` environment restricted to `main`.
3. Make sure no step echoes the token. Add the workflow to the root `AGENTS.md` tooling list.

## Files

- `.github/workflows/publish-clawhub.yml`
- `AGENTS.md` (tooling list)

## Acceptance criteria

- [x] A pull-request run dry-runs every bundle and passes.
- [x] Publishing is impossible from a branch other than `main` and without the environment secret.

## Out of scope

- Publishing on every push. Releases stay deliberate.

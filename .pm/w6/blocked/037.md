# Adopt short-circuit evaluation for BQL logical guards

**Severity:** minor · **Package:** ledger, with backend-v2 parity validation · **Estimate:** 45–60m after a compatible upstream release.

**A1 — Agent-native accounting.** A guarded query over optional metadata must skip an unnecessary expression once its logical result is known. Eager evaluation defeats common null guards and fails otherwise answerable queries.

## Reproduction

Live 2026-10-15, https://beancount.io/api-gateway/mcp, synthetic open_ledger/freelancer-invoicing, designated unpinned QA API key (ledger.read/write/admin). Last observed beancount-mcp 1.0.0, protocol 2025-11-25; deployed revision unavailable. No ledger writes.

Call runBqlQueryStructured using the root .env:

```json
{"ledger": "open_ledger/freelancer-invoicing", "query": "SELECT COUNT(*) AS n WHERE TRUE OR DATE_BIN('0 days', date, 2026-01-01) = date"}
```

Two fresh MCP calls fail with isError true / ok false / BAD_USER_INPUT: DATE_BIN: stride amount must be positive, got 0. REST returns HTTP 400 with the same domain error twice, and GraphQL queryShell returns that error once. Expected COUNT 50: TRUE already determines the OR expression, so the right operand must not run. The invalid stride is deliberate evidence of evaluating an unreachable branch, not a request to accept zero strides when evaluated.

Changing TRUE OR to FALSE AND also fails on two fresh MCP/REST calls; expected no matching postings without evaluating the right operand. Preserve rustledger's existing empty-aggregate output convention rather than changing it to Beanquery's no-aggregate-row convention.

Practical metadata query:

```sql
SELECT COUNT(*) AS posting_count
WHERE ENTRY_META('due') IS NOT NULL
  AND DATE_DIFF(DATE(ENTRY_META('due')), date) = 30
```

MCP/REST and GraphQL reject this with DATE: argument must be a string or date, because the unneeded right side still evaluates for rows whose due is absent. Expected 13 postings. The equivalent nullable OR form (due IS NULL OR the same date comparison) fails on MCP/REST too; it should include all 50 postings. The journal independently has 13 due-bearing postings, each with due exactly 30 days after date, and 37 without due. An explicitly total expression, DATE_DIFF(DATE(COALESCE(ENTRY_META('due'), date)), date)=30, works on MCP/REST and counts 13. Due-date MIN/MAX/COUNT controls also succeed. Untyped initial Beanquery metadata calls required the explicit DATE cast above; those initial type-check failures are not product evidence.

## Independent fixture and root cause

```beancount
2026-01-01 open Assets:Test USD
2026-01-01 open Equity:Opening USD
2026-01-02 * "Tagged opening" #trip-boston-2017
  due: 2026-02-01
  Assets:Test 10 USD
  Equity:Opening -10 USD
2026-01-03 * "Untagged addition"
  Assets:Test 5 USD
  Equity:Opening -5 USD
```

On this valid fixture, official Beanquery 0.2.0 returns counts 4/2 for the typed OR/AND metadata queries above; TRUE OR the zero-stride DATE_BIN expression counts 4, and FALSE AND it selects no rows. Installed @rustledger/wasm 0.24.0 returns native execution errors for all four queries, with no fixture validation errors. The fixture/query pairs are identical across engines. Required-right controls, TRUE AND and FALSE OR with the zero-stride expression, reject it in both native WASM and Beanquery (the reference raises ZeroDivisionError). The failure is evaluating the branch when it is unnecessary, not rejecting it when needed.

[Beanquery EvalAnd/EvalOr](https://github.com/beancount/beanquery/blob/master/beanquery/query_compile.py) evaluate arguments in order and return once false/true determines the result. Tagged [operators.rs](https://github.com/rustledger/rustledger/blob/v0.24.0/crates/rustledger-query/src/executor/operators.rs), evaluate_binary_op around line 45, evaluates left and right before calling binary_op_on_values. The [expression evaluator](https://github.com/rustledger/rustledger/blob/v0.24.0/crates/rustledger-query/src/executor/evaluation.rs) delegates BinaryOp there. Fresh upstream main still evaluates the right expression before applying AND/OR semantics; no fixed commit identified.

The local ledger engine path delegates to native query execution, and the direct valid fixture removes API/cache prerequisites. Adopt a compatible published artifact after upstream supplies lazy logical-expression evaluation, then verify actual native and eligible REST/GraphQL/MCP behavior together. The decision must happen before evaluating the right expression, not in a helper that only receives already-evaluated values. Preserve required branch errors, existing null/comparison rules and result envelopes. Do not accept invalid strides globally, swallow all function errors, rewrite customer predicates, patch cells, fork upstream or vendor unreleased bytes.

Acceptance: TRUE OR failing-right and FALSE AND failing-right skip the right expression; TRUE AND and FALSE OR still evaluate it and preserve the appropriate error. Typed nullable due guards return the expected 50/13 hosted-fixture selections and 4/2 minimal-fixture counts. Native-backed tests cover logical nesting and relevant aggregate/table contexts plus reference null behavior. Those additional contexts and all null truth-table combinations were not live-verified here. Nullable DATE/DATE_DIFF behavior without guards is not independently repaired by this finding. Latest published/installed WASM this session was 0.24.0.

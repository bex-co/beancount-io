# Adopt the FILTER_CURRENCY Position overload

**Severity:** minor · **Package:** ledger, with backend-v2 parity validation · **Estimate:** 35–50m after a compatible upstream release.

**A1 — Agent-native accounting.** An agent filtering individual BQL positions by currency must be able to use the standard per-position function, preserving the position and its cost rather than being told its valid argument is a type error.

## Live reproduction

2026-10-15, https://beancount.io/api-gateway/mcp, synthetic open_ledger/crypto-example, designated unpinned QA API key (ledger.read/write/admin). Last observed beancount-mcp 1.0.0, protocol 2025-11-25; deployed revision unavailable. No ledger writes.

Call runBqlQueryStructured using the root .env:

```json
{"ledger": "open_ledger/crypto-example", "query": "SELECT account, FILTER_CURRENCY(position, 'ETH') AS selected_position WHERE currency = 'ETH' LIMIT 2"}
```

Two fresh MCP calls return isError true / ok false / BAD_USER_INPUT: `Invalid BQL query: Query execution error: type error: FILTER_CURRENCY expects (inventory, string)`. The same REST query returns HTTP 400 with the same domain error twice; GraphQL queryShell returns that BAD_USER_INPUT once. Expected two matching Position values because the WHERE already selects ETH positions.

Working controls: replace FILTER_CURRENCY(position, 'ETH') with position and both MCP/REST return two ordinary rows. The earlier inventory-form query UNITS(FILTER_CURRENCY(SUM(position), 'ETH')) succeeds with 7.07495 ETH, independently matching all journal postings; that overload exists. The function failure is not an empty ledger, unknown currency, missing position, or transport discrepancy.

Minimal valid fixture:

```beancount
2026-01-01 open Assets:Bank:Business USD
2026-01-01 open Equity:Opening USD
2026-01-02 * "Synthetic opening"
  Assets:Bank:Business 10 USD
  Equity:Opening -10 USD
```

```sql
SELECT account, FILTER_CURRENCY(position, 'USD') AS matched, FILTER_CURRENCY(position, 'EUR') AS unmatched
```

Official Beanquery 0.2.0 returns the original +10 USD and -10 USD Positions in matched and null in unmatched. Installed @rustledger/wasm 0.24.0 Ledger.fromFiles(...).query(...) returns no columns/rows and the same FILTER_CURRENCY type error, while fixture validation succeeds with no errors. The reference and native controls use identical fixture and query.

## Root cause and repair direction

[Beanquery query_env.py](https://github.com/beancount/beanquery/blob/master/beanquery/query_env.py) registers both Position/string and Inventory/string overloads. The Position form returns the original position when units.currency matches, otherwise None. The [tagged native executor](https://github.com/rustledger/rustledger/blob/v0.24.0/crates/rustledger-query/src/executor/mod.rs) FILTER_CURRENCY arm around line 1461 handles Inventory and Null, but no Position. The initial 2026-10-15 upstream source inspection retained that omission; the later merged-source update below supersedes that source-only finding. A direct native fixture removes API/cache layers as prerequisites; local ledger src/foundation/rustledger/engine.ts::queryLedgerFilesResultInProcess delegates to that engine.

After upstream publishes a compatible artifact with the Position overload, adopt it with the ledger package manager and verify actual native execution and eligible REST/GraphQL/MCP together. Matching positions must retain their full original units/cost data; nonmatching positions return null. Preserve the working Inventory overload and null propagation. Do not turn Positions into unit-only Amounts, change call sites to aggregate everything, rewrite arbitrary queries, patch returned cells, fork the engine or vendor unreleased bytes.

Acceptance: matching USD/ETH positions are returned, mismatched currencies yield null, and cost-bearing positions retain cost/date/label information. Cover actual native simple and costed fixtures, positive/negative values, null and unmatched cases, alongside the working Inventory form. All APIs preserve envelopes and typed cell semantics. Costed output after the fix, null inputs and alternate query contexts are acceptance work, not claimed live coverage. At the original 2026-10-15 baseline, the published and installed WASM were 0.24.0 and no fixed commit was identified. See the dated source/publication follow-through below for the current gate.

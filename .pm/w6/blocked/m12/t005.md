## Objective

Complete Google's review/publication process and verify ordinary eligible users
can discover and connect the released Gemini App integration.

## Steps

1. Follow the same app/version's actual review findings; correct and verify
   required changes in the supported editable version without duplicating the app.
2. On real approval, complete the supported publish action. Inspect the actual
   published version/product/region/language and rollout status; approval alone
   or tester visibility does not complete this task.
3. Verify discovery/connection using the actual public Gemini Apps route, without
   broadening who can access the synthetic ledger. Reuse t004 evidence when the
   released configuration is identical; execute meaningful changed-path checks
   when release drift warrants them, preserving grants and independent controls.
4. Record public/operation URLs, version, actual timestamps, acceptance limits
   and future tool-snapshot/version-update ownership in the existing tracker.

## Acceptance criteria

- [ ] The actual app version is published for Gemini Apps and ordinary eligible
  users can discover/connect it; no public listing URL is fabricated.
- [ ] The advertised released native route has current accounting acceptance
  and any configuration drift is verified with precise limitations.
- [ ] Review and release receipts, actual checks, owners and maintenance triggers
  are recorded; pending rollout remains blocked rather than silently done.

## Out of scope

Production-ledger writes, a second deployment, public credentials/account data,
new dependencies without required approval, duplicate applications, unrelated
outreach or paid placement. Keep the hosted MCP connector distinct from local
customer-skill distribution.

# A write with `--file` on an empty month file still skips the root when the year index's other file holds only prices: a conflicting `price` lands with exit 0, and the unknown-account remedy writes a duplicate `open` (gap in w1/375)

**Major · cli · 30–45m · A1.** Routine cli-qa, 2026-11-23, HEAD `8105b095f`, checkout `bea 0.5.0` (`uv run bea`), macOS 26.5.1, Python 3.12.14, managed engine 0.5.0. Isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`/`BEA_ENGINE_DIR`, stdin closed, no TTY, every run from a pristine copy in a fresh process. No product fix implemented.

w1/375 made a year index a pass-through once its closure "posts to an account it never opens". Its resolution says a sibling holding only prices passes through too "since the leaf's own postings count". That holds only while the leaf has postings. The first write into a new month file is exactly when the leaf is empty, and then nothing in the index's closure posts anywhere: the index is taken for an overlay, the climb stops, and the write is checked against the month file alone.

```sh
mkdir -p books/2026
cat > books/main.bean <<'EOF'
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Expenses:Food USD
include "2026/index.bean"
EOF
printf 'include "01.bean"\ninclude "prices.bean"\n' > books/2026/index.bean
: > books/2026/01.bean
printf '2026-01-02 price EUR 1.10 USD\n' > books/2026/prices.bean
bea --file books/main.bean check                                  # exit 0
bea --file books/2026/01.bean add transaction "Jan lunch" --date 2026-01-05 \
  -p "Expenses:Food 5.00 USD" -p Assets:Checking                  # (1)
bea --file books/2026/01.bean add price --date 2026-01-02 -c EUR --amount '1.20 USD'   # (2)
bea --file books/2026/01.bean add open --account Assets:Checking --date 2026-01-01      # (3)
bea --file books/main.bean check                                  # (4)
```

Actual:

1. Exit 1, `Invalid reference to unknown account 'Assets:Checking' To create it, use bea --file books/2026/01.bean add open --account Assets:Checking …` (the same for `Expenses:Food`). There is no `01.bean is included by …/main.bean` note.
2. Exit 0, `Added 1 price`. The ledger already holds `2026-01-02 price EUR 1.10 USD` (in `prices.bean`), which `bea add price` refuses with exit 4 unless `--force` is passed. `bea list price` now shows both quotes for the day.
3. Exit 0, the remedy (1) offered. `01.bean` ends with `2026-01-01 open Assets:Checking`.
4. Exit 1: `2026/01.bean:4: Duplicate open directive for Assets:Checking`. The books no longer check, and every later write refuses with "The ledger already has 1 error(s)".

Controls, same commands from a pristine copy:

- Give `01.bean` one transaction (`2026-01-03 * "x"` / `Expenses:Food 1.00 USD` / `Assets:Checking`): (1) lands with `01.bean is included by …/main.bean; the write goes to 01.bean and is checked against that whole ledger.`, and (2) is refused with exit 4, `EUR already has a 2026-01-02 price of 1.10 USD (at …/2026/prices.bean:1); refusing 1.20 USD. Pass --force to record another quote.`
- Keep `01.bean` empty but make `prices.bean` a lone `; comment`: (1) goes through the root the same way.
- `bea --file books/main.bean add price … --into 2026/01.bean` refuses (2) with exit 4 in every layout.

Expected: an includer that opens nothing and sets no option is a pass-through above a leaf that is not a working ledger, whatever its other files hold. Writes on any month file run through `main.bean` (with `--into` set to the leaf), so (1) lands with the redirect note, (2) is refused as a same-day conflict, and the unknown-account remedy names `bea --file books/main.bean`. The Fava/forecast overlays w5/578 and w5/774 pinned still stop the climb.

Cause: `cli/src/bea_engine/ledger/write.py`, `defining_root` (`:2278`) stops at `:2317` when `_step_adds_entries(around, own)` is true and `_needs_root_above(around)` (`:2408`) is false. `_needs_root_above` relies only on `_posts_unopened` (`:2357`): some file in the includer's closure must post to, or name in a `balance`/`note`/`document`/`close`/`pad`, an account the closure never opens. An empty leaf and a price-only sibling name no account, so the year index reads as an overlay. A sibling holding only `event`, `commodity` or account-free `custom` entries does the same.

Fix: base the overlay test on the leaf as well. An overlay sits above a working ledger, one that opens accounts or sets options of its own. A leaf whose closure opens nothing and sets nothing is never the ledger an overlay extends, so the step above it is a pass-through whether or not its siblings add entries. Alternatively, count only entries that post to accounts the leaf's closure opens as an overlay's own. Keep one climb for `write_through_root`, `root_read_hint`, `root_ledger_hints` and `update`'s root discovery.

Blast radius: every `add` type and `import` with `--file` on such a leaf. `bea --file books/2026/01.bean import s.csv --csv auto --account Assets:Checking` (one `2026-01-05,Coffee,-4.50` row) exits 2 with `the ledger knows no commodity yet. Open Assets:Checking for one currency first: bea --file books/2026/01.bean add open …`, the same leaf-only view, so import dedupe and the remembered mapping would belong to the leaf, not the root. An `event`-only, `commodity`-only or `custom "x" "y"` sibling gives (1) the same refusal. `update` needs an entry in the leaf, so it reaches the root through the leaf's own postings. `--into` from the root is unaffected.

Dedupe: searched `.pm/**` for `year index`, `prices.bean`, `_needs_root_above`, `pass-through`, `overlay`, `empty leaf`, `month file`. Parent: w1/375 (done, `dcaa4b183`). Its regression test `cli/tests/test_month_leaf_sibling_entries.py` writes a non-empty `01.bean` (`JAN`) for every sibling variant, so the price-only sibling passes only through the leaf's own postings. No open item covers an empty leaf.

Acceptance: in the fixture above, (1) lands in `01.bean` with the redirect note naming `main.bean`, (2) exits 4 leaving `01.bean` unchanged, and the remedy in (1) reads `bea --file books/main.bean add open …`. A test pins an empty leaf beside a price-only sibling, and one beside an event-only sibling. The w5/578, w5/774 and w1/375 fixtures behave as before.

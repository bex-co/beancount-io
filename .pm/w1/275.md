# `bea add --into <included file>` reports a broken include or plugin at `<load>:0` / `<ledger>:0`, though the same write without `--into` names the line

Found by `/qa-find-bugs-cli w1` on 2026-11-16 (HEAD `0f939c45c`, `bea 0.3.1`, macOS 26.5, Python 3.12.14, checkout `uv run bea`, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`). Severity: minor. A1: an agent that keeps its entries in an included file (`--into txns/2024.bean`, the layout `bea init --existing` and the split-ledger guides describe) gets an error with no file or line when its ledger has a broken include or plugin. The fixes in w1/269, w1/273 and w5/256 reach every other path, so the same ledger reads located in `check` and unlocated in this one write.

**Repro** (a fresh directory):

```sh
mkdir -p sub
printf 'option "operating_currency" "USD"\n2024-01-01 open Assets:Cash USD\ninclude "sub/a.bean"\ninclude "nope.bean"\n' > main.bean
printf '2024-01-02 open Expenses:Food USD\n' > sub/a.bean
bea --file "$PWD/main.bean" add note --date 2024-01-05 -a Assets:Cash -m hi                         # control
bea --file "$PWD/main.bean" add note --date 2024-01-05 -a Assets:Cash -m hi --into sub/a.bean
bea --json --file "$PWD/main.bean" add note --date 2024-01-05 -a Assets:Cash -m hi --into sub/a.bean
bea --file "$PWD/main.bean" add note --date 2024-01-05 -a Assets:Cash -m hi --into sub/a.bean --allow-errors
```

**Actual.** The control (no `--into`) exits 1 with `/…/main.bean:4: include "nope.bean" matches no file (looked for /…/nope.bean)`. With `--into sub/a.bean`, the refusal (exit 1, files unchanged) and its `--json` `error.details` carry upstream's raw `<load>:0: File glob "nope.bean" does not match any files`. The `--allow-errors` write succeeds and prints the same raw line as its warning. The other relocated loader messages behave the same way under `--into sub/a.bean`:

- a second `include "sub/a.bean"` gives `<load>:0: Duplicate filename parsed: "/…/sub/a.bean"`, where the control says `main.bean:4: include "sub/a.bean" loads …, already included at …/main.bean:3`;
- `include "../main.bean"` in `sub/a.bean` gives the cycle line at `<load>:0`, as does `include "*.bean"` in the root with `--into a.bean`;
- `plugin "nonexistent.plugin"` in the root gives `<ledger>:0: Cannot import plugin …`, where the control says `main.bean:2: Cannot import plugin …`.

`--into main.bean` (the root itself), `bea check`, `list`, and `import --into sub/a.bean` all give the located lines.

**Expected.** A write gives the same located line whether or not `--into` is passed. That is what w1/269 and w1/273 promise, since their resolutions name "the write refusals (and `--allow-errors` warnings)", and what w5/256 promises for plugin failures.

**Root cause.** `validate_candidate` in `cli/src/bea_engine/ledger/write.py` takes `file` as the write *destination*. It formats each error with `format_error(error, ledger_file=file)`, at about line 2660 for the blocking records and about line 3186 for the "already has N errors" `current` records. `format_error` (`cli/src/bea_engine/query.py`, about line 3193) relocates these errors by walking the include closure from `ledger_file` (`_include_walk`), or by finding the plugin line (`_plugin_message`). Walked from `sub/a.bean`, the walk never sees the root's include or plugin lines, so nothing matches and the raw `<load>:0` / `<ledger>:0` text falls through. `importing.py` (line 262) passes the root, which is why `import --into` works.

**Fix.** In `validate_candidate`, format with the root ledger: `snapshot.root if snapshot else file`, which is the value the function already loads. Do it at both call sites and anywhere else in that function that passes `ledger_file=file`. Check the other `ledger_file=file` callers in `ledger/adding.py` (583, 683, 1120) and `ledger/updating.py` (248) for the same destination-versus-root mix-up. `bea update transaction --into` was not exercised.

**Acceptance.** The repro's `--into sub/a.bean` refusal, its `--json` details and its `--allow-errors` warning name `main.bean:4` and the searched path. The repeat, cycle and plugin variants name their lines. A regression test in `cli/tests/` (beside `test_missing_include_location.py` / `test_repeated_include_location.py`) fails with the fix reverted, and `make check-all` passes. Local-only; no REST/GraphQL/MCP change.

**Dedupe.** Searched `.pm/**` for `<load>:0`, `Duplicate filename`, `does not match any files`, `--into`, and `<ledger>:0`. w1/269, w1/273 and w5/256 fixed these messages on the paths they exercised, none of which used `--into` with a non-root destination. No open item covers it. Estimate 30–45m.

# `bea report holdings` lists one account's shares twice when its lots were bought in two currencies, with nothing to tell the rows apart, and `--group-by commodity` does the same across accounts

Found by `/qa-find-bugs-cli w1` on 2026-11-18 (HEAD `5f13f574a`, `bea 0.4.1`, macOS 26.5.1, Python 3.12.14, checkout `uv run bea`, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, synthetic ledgers). Severity: minor. A1: holdings is how a user or an agent answers "how much VT do I own"; with lots costed in USD and EUR, the answer comes back as two identical-looking rows of 10 VT instead of one row of 20 VT, though both rows are already valued in USD.

**Repro** (synthetic, `main.bean`; `bea check` exits 0):

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Assets:EurCash EUR
2024-01-01 open Assets:BrokerA
2024-01-01 open Assets:BrokerB
2024-01-01 open Equity:Opening
2024-01-02 * "fund"
  Assets:Cash 10000 USD
  Assets:EurCash 10000 EUR
  Equity:Opening -10000 USD
  Equity:Opening -10000 EUR
2024-02-01 * "buy usd"
  Assets:BrokerA 10 VT {100 USD}
  Assets:Cash
2024-02-02 * "buy eur"
  Assets:BrokerA 10 VT {90 EUR}
  Assets:EurCash
2024-03-01 price VT 110 USD
2024-03-01 price EUR 1.2 USD
```

```sh
bea -f main.bean report holdings
bea -f main.bean balance BrokerA            # control: 2,200 USD
```

**Actual** (exit 0):

```
ACCOUNT         COMMODITY  UNITS  AVG COST  COST BASIS  MARKET VALUE
Assets:BrokerA  VT         10 VT  108 USD   1,080 USD   1,100 USD
Assets:BrokerA  VT         10 VT  100 USD   1,000 USD   1,100 USD
```

`--json` has two groups with `"account": "Assets:BrokerA", "commodity": "VT"` and every money field in USD. Put the EUR lot in `Assets:BrokerB` and run `--group-by commodity`: again two `VT` rows, `ACCOUNTS` `Assets:BrokerB` and `Assets:BrokerA` on separate lines, instead of one row naming both.

**Expected.** Under a currency conversion (the default here) one row per account and commodity (one per commodity with `--group-by commodity`): `20 VT`, average cost `104 USD`, cost basis `2,080 USD`, market value `2,200 USD`. Basis: USAGE (Reports) says holdings are "grouped by account or — with `--group-by commodity` — by commodity across accounts"; the totals line already adds the two rows. Under `units` and `at_cost` the bases are in different currencies and cannot be summed, so the split stays there, where each row's AVG COST currency (`100 USD`, `90 EUR`) tells the rows apart.

**Root cause.** `cli/src/bea_engine/report.py:740` (`_holdings`) keys each group by `(*scope, commodity, cost.currency)` and never merges groups once `_value_holding` has put them in the same target currency (`:770-812`). The hosted composer does the same: `backend-cluster/backend-v2/src/features/ledger/utils/holdings.ts:340` (`keyOf(scope, commodity, held)`).

**Fix** (cli and backend-v2, in parity). After valuation, when a conversion target is set, merge groups that share scope and commodity and whose basis and market are in the same currency: sum units, basis and market, union the accounts, recompute the average (null if any part's basis is unknown), and keep the latest quote. Without a target, keep one group per cost currency. Apply the same merge in `holdings.ts` so REST, GraphQL and MCP return what the CLI returns.

**Regression.** The repro, text and `--json`, account and commodity grouping: one VT group with the expected figures; `-x at_cost --allow-errors` still lists two. Each fails with the fix reverted, on both surfaces.

**Blast radius.** `bea report holdings` (text, JSON, CSV) and the hosted holdings on every surface. A commodity held at one cost currency is a working control: one row. Uncosted positions that join a costed group (w1/253) go through the same merge.

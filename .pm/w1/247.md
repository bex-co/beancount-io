# `bea init --preset` ledgers accept a misspelt account: the header still turns on `auto_accounts`

Found by `/qa-find-bugs-cli w1` on 2026-11-15 (HEAD `b3adffe14`, `bea 0.3.1`, macOS 26.5, checkout `uv run bea`, stdin closed). Severity: major. A1/A2: the never-opened refusal is an agent's only guard against a typo in an account name, and on preset ledgers it never fires.

**Contract.** ADR026 decision 4: "the CLI, REST, GraphQL, and MCP create ledgers from the same setup specification and get the same files". w23/059 (shipped `ffbfa60d7`) took `plugin "beancount.plugins.auto_accounts"` out of the hosted guided-setup header so that a misspelt account is refused. `backend-cluster/backend-v2/src/features/ledger/setup/__tests__/build-ledger.test.ts` pins this. Its resolution names the CLI preset header as a separate, still-open copy. Plain `bea init` (no preset) never had the plugin and refuses the typo.

**Repro** (synthetic, fresh directory):

```sh
bea --no-input init p1 --currency USD --preset personal@1 --date 2026-01-01
bea --no-input init p0 --currency USD --date 2026-01-01
bea --file p1/main.bean add transaction typo --date 2026-01-05 -p 'Expenses:Fodo 3 USD' -p Assets:Csah; echo "exit $?"
bea --file p0/main.bean add transaction typo --date 2026-01-05 -p 'Expenses:Fodo 3 USD' -p Assets:Csah; echo "exit $?"
bea --file p1/main.bean balance Csah Fodo
```

Actual: on `p1`, `Added 1 transaction` and exit 0. The `--json` result has `"warnings": []`, `bea check` passes, and `balance` shows new accounts `Assets:Csah -6 USD` and `Expenses:Fodo 6 USD`. On `p0`, the write is refused with exit 1 and `Invalid reference to unknown account 'Assets:Csah' Did you mean Assets:Cash…`, and the file is unchanged. Every preset (`personal@1` and the other seven) and every module takes the same path, because `p1/main.bean` line 5 is `plugin "beancount.plugins.auto_accounts"`.

Expected: `bea init --preset` writes the same header as the hosted builder (`build-ledger.ts:335–337`: title, operating currency and tolerance, no `plugin` line). The misspelt write is then refused on `p1` exactly as on `p0`. Existing ledgers are unchanged.

**Root cause.** `cli/src/bea_engine/initiating.py:294` hard-codes `'plugin "beancount.plugins.auto_accounts"'` in the preset header. It came in with `1ba20bffa` (w3/m53/t004) and was not touched when w23/059 changed the hosted header.

**Fix** (`cli`, about 20 minutes). Drop the line. Add to `cli/tests/test_init_preset.py` a test that a preset ledger carries no `plugin` line and that `bea add transaction` to an unopened account exits 1 with the file byte-identical. Run `tests/test_setup_conformance.py` to confirm every fixture still checks clean without the plugin. Every preset already opens its whole chart, so an account in the chart does not need the plugin. Update any `cli/docs/USAGE.md` or `REFERENCE.md` text that shows the preset header.

**Dedupe.** w23/059 covers only the hosted templates and names this file as out of its scope. w3/301 and w5/134 cover how `auto_accounts` ledgers are displayed and imported, not what the CLI preset writes. No open item covers this.

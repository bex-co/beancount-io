## Objective

Prove the two CIMD clients that matter reach consent: Claude Code's real metadata document (port-less loopback redirects, no `application_type`) authorizing from an arbitrary port, and an `https`-redirect document shaped like ChatGPT's.

## Context

- Local copy of `https://claude.ai/oauth/claude-code-client-metadata` as verified in w1/m30 t001 — tests never fetch the network.
- Added by w1/m30 t001 (2026-10-06): VS Code also uses CIMD — a local copy of `https://vscode.dev/oauth/client-metadata.json` (`application_type: "native"`, redirects `http://127.0.0.1:33418/` and `https://vscode.dev/redirect`) must authorize from 33418 and from another loopback port.
- oidc-provider fetches documents through a dispatcher that refuses special-use addresses, 2.5 s timeout, bounded cache.

## Steps

1. Serve both documents from a local test server or a stubbed fetch.
2. Authorize Claude Code from `http://localhost:<random>/callback`; ChatGPT from its documented redirect.

## Files

- backend-cluster/backend-v2/src/features/oauth/api/__tests__/oidc-route.test.ts

## Acceptance criteria

- [x] Claude Code, VS Code, and the ChatGPT-shaped CIMD clients reach consent, VS Code from 33418 and from another loopback port.
- [x] No row is added to the OAuth client store for either.

## Out of scope

- Real network fetches in tests.

## Result

2026-10-06. `oidc-route.test.ts` answers the hosts' metadata-document URLs locally through oidc-provider's configurable `fetch` (everything else passes through; nothing reaches the network) with copies of Claude Code's and VS Code's published documents and a ChatGPT-shaped one. Claude Code (port-less loopback document, authorizing from port 51999), VS Code from 33418 and from 50123, and the ChatGPT shape all reach consent; the interaction details name the vouching domain and the loopback flag, and the client store holds no row for any of them. With D3 removed, exactly the Claude Code case fails — the ADR's D3-before-D6 order, demonstrated.

## Objective

Show the CIMD `client_id` host on consent end to end, and make the failure cases explicit: an unreachable document, an invalid document, and a `client_id` on a special-use address.

## Context

- w1/m30 t004/t005 return and render `client_id_host`; this task exercises it with real CIMD clients.

## Steps

1. Test consent data for both CIMD fixtures.
2. Test the three failure cases return a clear OAuth error rather than a 500.

## Files

- backend-cluster/backend-v2/src/features/oauth/api/__tests__/oidc-route.test.ts
- dashboard/src/features/oauth/pages/consent.tsx

## Acceptance criteria

- [x] Consent shows the vouching domain for CIMD clients.
- [x] Each failure case yields a defined OAuth error, with tests.

## Out of scope

- Caching policy changes.

## Result

2026-10-06. Consent for CIMD clients: the interaction details name the vouching domain (t002 fixtures) and the page renders it ("Its details are published by …", w1/m30 t005 page tests), so no dashboard change was needed here. Failure modes, each a 400 OAuth error page with no redirect: a document that cannot be fetched (`invalid_client`), a document naming a different `client_id` (`invalid_client`), a redirect the document does not list (`invalid_redirect_uri`), and a `client_id` on a special-use address, refused by oidc-provider's SSRF-protected dispatcher (`invalid_client`).

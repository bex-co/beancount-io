## Objective

A stack that does not serve Git over SSH stops advertising an SSH clone address that cannot work. All three surfaces change together.

## Context

- `SSH_PROXY_ENABLED` (`config.ts`, `enabled: process.env.SSH_PROXY_ENABLED === "true"`) is `false` on bex (`bex.yaml`) because the platform has no TCP routing.
- Ledger responses: REST `/api-gateway/v1/ledgers` (OpenAPI), GraphQL ledger types, MCP ledger reads and `createLedger`. Parity workflow: `backend-cluster/backend-v2/AGENTS.md#required-api-parity-workflow`.
- The generated CLI client (`cli/src/cli/api/rest_client/models/*ledger*`) reads `sshUrl`; regenerate it from the updated spec rather than hand-editing.

## Steps

1. Make `sshUrl` nullable in the contract and return null (or omit it, identically on every surface) when SSH is not served.
2. Update the OpenAPI document (`yarn generate-v1-openapi`), GraphQL schema and MCP output schemas; regenerate the IDL clients that consume it.
3. Add parity rows/tests for both states.

## Files

- `backend-cluster/backend-v2/src/shared/gitea-utils.ts`, ledger mappers and schemas
- `backend-cluster/backend-v2` OpenAPI snapshot
- `backend-cluster/idl/` generated clients and `cli/src/cli/api/rest_client/` (regenerated)

## Acceptance criteria

- [ ] With `SSH_PROXY_ENABLED=false`, REST, GraphQL and MCP return the same null/absent `sshUrl`; with it on, today's value.
- [ ] `yarn test` (including the parity gate) and the OpenAPI drift check pass in `backend-cluster/backend-v2`.

## Out of scope

- Returning an HTTPS clone path to `bea` as a replacement (see the milestone's Out of scope).

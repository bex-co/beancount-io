## Objective

Decide the move's inputs, guarantees and refusals before any code.

## Context

- Entries are addressed by `entry_hash` (from `listLedgerEntries`) and `sha256sum` (from `getEntryContext`, or from `listLedgerEntries` once [m44](../m44/README.md) ships), as `deleteEntrySources` already takes them.
- File creation never auto-includes (owner decision 2026-10-30, w21/588); `appendLedgerText` refuses a path no loaded file reaches (w23/035).

## Steps

1. Inputs: `entries[{entry_hash, sha256sum}]` (both spellings), `toPath`, optional `includeFrom` (the loaded file that gets the `include` line), `dry_run`, `allowInvalid`.
2. Guarantees: entry text moves byte for byte; source order among moved entries is kept; the target is created when absent; one commit.
3. Refusals with codes: a target not reachable from the root and no `includeFrom`; an `includeFrom` that is not loaded; a stale `sha256sum`; a target equal to an entry's current file; new bean-check errors without `allowInvalid`.
4. Result: per-file diff on preview, moved count, `notLoaded` if any, and `commit` on a real write.

## Objective

Implement the move as one shared workflow: remove each entry's slice from its file, append the slices to the target, add the `include` when asked, gate the whole projection, and commit once.

## Context

- `deleteEntrySources` already resolves and removes several slices in one commit (`backend-cluster/backend-v2/src/features/ai-agent/api/mcp-source-slices.ts`; batch resolution in `backend-cluster/ledger/src/foundation/rustledger/source-slice-resolver.ts`).
- `src/features/ledger/service/ledger-repo-service.ts` `changeFiles` commits several files atomically; `src/features/ledger/utils/file-write-gate.ts` projects and gates a multi-file change and lists `notLoaded` files.

## Steps

1. Resolve every listed entry's slice in one batch and check each `sha256sum`.
2. Build the projected files: each source file minus its slices; the target plus the slices in source order; `includeFrom` plus the `include` line when the target is not already reached.
3. Refuse an unreachable target without `includeFrom`. Gate the projection and honor `allowInvalid`.
4. On `dry_run`, return the diff; otherwise commit with `changeFiles` and return `commit`.

- [x] A move across a balance assertion previews `valid: true` and commits once, and the ledger's balances and errors are unchanged.

## Outcome — 2026-11-13

- **Ledger service:** `LedgerJournalService.moveSourceSlices` (`backend-cluster/ledger/src/features/ledger/service/ledger-journal-service.ts`), beside `deleteMultiSourceSlices`.
  - It refuses before any read: no entries, an unsafe or non-ledger `toPath`, an unreached target without `includeFrom`, an `includeFrom` the ledger does not load.
  - It maps IDs through `sourceEntryIds` and locates every slice with the writers' `locateSlices`: stale sha is `CONFLICT`, a managed price line is refused.
  - It refuses an entry already in `toPath`, and groups and de-duplicates as the batch delete does.
  - Removal uses `makeDeleteTransform`. The append writes the slices to `toPath` in ledger order (by `sourceFiles` order, then line), byte for byte, after a blank line, creating the file when absent. The include line goes to `includeFrom`, relative to its folder, and composes with that file's own delete transform when entries also leave it.
  - The whole projection is gated by `projectWriteErrors`, under the new `"move"` write action, so the refusal says "moving these entries".
  - It commits once through `commitTransforms`.
- **Route:** `POST /journal/{owner}/{repo_name}/move-source-slices` (`src/api/journal.ts`), in snake case on the wire: `to_path`, `include_from`, `moved_hashes`, `include_added`.
- **IDL:** the `moveSourceSlices` operation with `MoveSourceSlicesRequest`/`MoveSourceSlicesResponse`, additions only. backend-v2's ledger client is regenerated.
- **Tests:** `move-source-slices.test.ts` (10), over the real transforms with a stubbed parse:
  - a move into an included file in one commit, in ledger order, byte for byte;
  - a new target plus its include in one commit;
  - the include written relative to `includeFrom`'s folder, including into an empty file;
  - a preview that commits nothing;
  - the unreached-target and unloaded-`includeFrom` refusals;
  - no entries, a non-ledger path, an entry already in the target;
  - a stale checksum as `CONFLICT`;
  - new errors refused (`NewLedgerErrorsError`, "moving these entries") unless `allowInvalid`.
- **Checks:** ledger `typecheck`, `lint:deadcode`, `test` (3,408) and `verify:rustledger`; backend-v2 `typecheck` and the client's tests.

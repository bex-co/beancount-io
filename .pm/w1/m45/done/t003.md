## Outcome — 2026-11-13

- **Surfaces:** MCP `moveEntrySources`, REST `POST /api-gateway/v1/ledgers/{owner}/{name}/entries/move` and GraphQL `moveLedgerEntrySources(ledgerId, input)`. All three share one description (`utils/move-entries-description.ts`) and the field descriptions for `toPath` and `includeFrom`.
- **Inputs:** `entries` takes `entryHash` or `entry_hash`, plus `sha256sum`. The flags take both spellings: `dry_run`/`dryRun` and `allowInvalid`/`allow_invalid`. The `toPath` and `includeFrom` values go to the ledger unjudged, so every surface refuses the same paths.
- **Authorization:** `LedgerJournalService.moveSourceSlices` authorizes `ledger.files.write`, because the move can create a file. It then caps `entries` at 1000 and calls the ledger's `moveSourceSlices` once.
  - A preview asks the ledger for the verdict (`allowInvalid` on `dryRun`), as the deletes do.
- **Result:** `message`, `dryRun` (`dry_run` on MCP), `movedHashes`, `toPath`, `includeAdded`, `preview` (each moved entry's text at the file it leaves), `commit` on a write, and the projection.
  - REST and GraphQL flatten the projection. MCP nests it under `validation` and adds `wrote` and `entryHashes`.
- **Refusal wording:** the ledger's `NEW_LEDGER_ERRORS` refusal with `action: "move"` now reads "moving these entries would introduce…". Before, it fell back to the structured add's wording.
- **Registered in:**
  - op-class: 71 mutations, 47 tools, under `ledger.files.write`;
  - the write-preview matrix and output conformance;
  - the reviewer annotation matrix (destructive, open world, not idempotent);
  - the `docs/mcp.md` Tools table.
- **tools/list budget:** raised from 128 to 134 KB. The tool itself is 4,433 bytes, in line with `deleteEntrySources` (3,990), and most of it is the shared write outcome.
- **Tests:** `move-entry-sources-parity.test.ts` runs the real adapters, the real service and the real authorization on all three surfaces. It covers:
  - the commit;
  - the preview;
  - the breaking preview, the refused commit and the forced commit;
  - an unloaded target without `includeFrom` (`BAD_USER_INPUT`);
  - a stale checksum (`CONFLICT`);
  - a read-only collaborator (`FORBIDDEN`, with the ledger never called).
- **Regenerated:** the OpenAPI snapshot, the CLI's pinned spec and REST client, and the ledger IDL's response description.
- **Gates:** backend-v2 typecheck, lint:deadcode, format:check and test pass (479 suites, 10,661 tests). `make check-all` passes in `cli/`.

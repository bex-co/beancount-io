# `bea add transaction -p 'Liabilities:Card -8.00 USD {}'` writes the charge as a USD lot costed in USD, exit 0, so `report holdings` lists the card debt and the bank's own cash as investments (gap in w1/278)

**Bug · cli · minor · ~30m · A1.** From routine cli-qa, 2026-11-22. w1/278 made every write refuse a posting "held at a cost or priced in its own commodity" (`10 USD {2 USD}`, `10 USD @ 1 USD`, `10 USD {USD}`), because such a posting is never what was meant. A cost spec that names no currency gets through: `{}`, `{2026-01-10}` and `{"lbl"}` on a cash or card posting are written with exit 0 whenever the posting adds to the account rather than reduces it. Booking then fills the cost in as `{1.00 USD}`, so the account holds a USD *lot* beside its cash. `bea check` stays green, every balance still reads right, but `bea report holdings` now lists the user's own cash and card debt as holdings with a cost basis, and the lot never goes away, because later plain postings do not reduce it. An agent that learned `{}` from a sale (`Assets:Broker -5 AAPL {}`) and copies it onto the cash or card leg hits this.

Environment: main `ff9d0fe7b`, `bea 0.5.0` from the checkout (`uv run bea`), Python 3.12.14, macOS 26.5.1. Isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, `BEA_FILE`/`BEA_TOKEN` unset, stdin closed, no TTY, scratch cwd, fresh processes.

## Repro

```sh
mkdir books
printf 'option "operating_currency" "USD"\n2026-01-01 open Assets:Checking USD\n2026-01-01 open Liabilities:Card USD\n2026-01-01 open Equity:Opening-Balances\n2026-01-01 open Expenses:Food\n\n2026-01-01 * "Opening"\n  Assets:Checking  1000.00 USD\n  Equity:Opening-Balances\n' > books/main.bean
bea --file books/main.bean add transaction --date 2026-01-10 Refund -p 'Assets:Checking 12.50 USD {}' -p 'Expenses:Food -12.50 USD'   # exit 0
bea --file books/main.bean add transaction --date 2026-01-11 Lunch -p 'Expenses:Food 8.00 USD' -p 'Liabilities:Card -8.00 USD {}'    # exit 0
bea --file books/main.bean add transaction --date 2026-01-12 Control -p 'Expenses:Food 1.00 USD' -p 'Assets:Checking -1.00 USD {USD}' # exit 2 (control)
bea --file books/main.bean check            # exit 0
bea --file books/main.bean report holdings
bea --file books/main.bean query "SELECT account, sum(position) WHERE account ~ '^(Assets|Liabilities)' GROUP BY account"
```

Actual: both writes append `Assets:Checking    12.50 USD {}` and `Liabilities:Card    -8.00 USD {}` with exit 0. The control `{USD}` is refused with "is held at a cost in its own commodity USD … Nothing was written." `report holdings` prints `Assets:Checking USD 12.50 USD AVG COST 1.00 USD COST BASIS 12.50 USD` and `Liabilities:Card USD -8.00 USD 1.00 USD -8.00 USD`, with `Cost basis: 4.50 USD`, on a ledger that holds no investments. The query shows `Assets:Checking 1000.00 USD  12.50 USD { 1.00 USD}` and `Liabilities:Card -8.00 USD { 1.00 USD}`. A later plain `-20.00 USD` withdrawal leaves the lot in place. Bulk `add transactions` writes the same rows, whether as `"amount": "-10.00 USD {}"` or as `"units"` plus `"cost": {}`. The same posting is refused only when it reduces an existing balance (`No position matches -12.50 USD {} in Assets:Checking`) or when another leg omits its amount (`Failed to categorize posting 1`).

## Expected

Every write path that refuses `{USD}` refuses `{}`, `{DATE}` and `{"label"}` on a posting whose units are a currency booking would cost in itself, with the same message (exit 2, nothing written). The test is on what the candidate books: a new posting whose booked cost currency equals its units currency is refused. This is `cli/docs/USAGE.md`'s rule: "A typed commodity held at a cost or priced in itself is refused the same way (exit 2, naming the posting, nothing written)". Sales that name a real lot (`-5 AAPL {}`) and the existing controls (`10 EUR @ 1.1 USD`, `5 ABC {10 USD}`, plain `10 USD`) still write.

## Cause

`self_rate_tail` (`cli/src/bea_engine/managed_load.py:869`) judges the parsed posting before booking. For `{}`, `{DATE}` and `{"label"}` the cost currency is still `MISSING`, so `costed` is false and the posting passes. Its four callers all see only parsed postings: `add transaction` (`cli/src/bea_engine/ledger/adding.py:1578`), bulk rows (`cli/src/bea_engine/ledger/models.py:282`), `bea ask` appends (`cli/src/bea_engine/ledger/appending.py:111`) and importer rows (`cli/src/bea_engine/importing.py:726`). Booking later interpolates the cost currency from the transaction's weights as the units' own currency.

## Fix

Apply the check to the booked candidate as well as the parsed posting. After the write's validation load, look at the new entries' postings and refuse any with `posting.cost is not None and posting.cost.currency == posting.units.currency`, reusing `self_rate_tail`'s wording and naming the posting by its number. Alternatively, refuse a currency-less cost spec on a units currency the account or ledger treats as cash before booking. Add regression tests through real `bea add transaction` and `bea add transactions` subprocesses for `{}`, `{2026-01-10}` and `{"lbl"}`, on a bank deposit and on a card charge: each exits 2 and leaves the ledger byte-identical. In the same test, cover the `-5 AAPL {}` sale and the four controls above, which still write. Revert the fix and watch the new cases fail. Owned by `cli`.

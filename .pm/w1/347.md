# `bea add transaction -p 'Expenses:Food .5 USD'` and `bea add balance --amount '.5 USD'` refuse with a bare "Invalid token: '.5'", while `add price`, `add transactions`, `add custom` and `init --opening-balance` take the same `.5` and write `0.5`

Found by `/qa-find-bugs-cli w1` on 2026-11-20 (routine cli-qa; HEAD `785e255cc`, checkout `uv run bea` 0.5.0, macOS 26.5, Python 3.12.14, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, synthetic ledger). Severity: minor. A1: an agent that drops the leading zero (`.5`, `-.25`, as many number formatters and people do) gets a different answer depending on which `bea add` command it uses. The most common one, `add transaction --posting`, refuses with a grammar token error that does not say what to write instead. The hosted write path normalizes the same number (w23/043).

**Repro** (synthetic, fresh process each step):

```sh
cat > main.bean <<'EOF'
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Expenses:Food USD
EOF
bea --file main.bean add transaction "Coffee" --date 2026-03-01 -p 'Expenses:Food .5 USD' -p Assets:Checking   # exit 2
bea --file main.bean add balance --date 2026-03-05 -a Assets:Checking --amount '.5 USD'                         # exit 2
bea --file main.bean add price --date 2026-03-01 -c EUR --amount '.5 USD'                                       # exit 0
printf '[{"date":"2026-03-02","narration":"Coffee","postings":[{"account":"Expenses:Food","amount":".5 USD"},{"account":"Assets:Checking"}]}]' > dot.json
bea --file main.bean add transactions --from dot.json                                                           # exit 0
bea --file main.bean add custom --date 2026-03-01 -t rate -v 'number:.5'                                        # exit 0
```

**Actual.** The posting is refused: `Invalid transaction options; use postings such as 'Assets:Checking -30 USD'. Nothing was written.` / `--posting 1: Invalid token: '.5'`. The same happens with `-.5` and with `@ .5 USD`. The balance is refused: `Balance amount must be 'NUMBER [~ TOLERANCE] CURRENCY' …` / `--amount: Invalid token: '.5'`, and the same for a `~ .5` tolerance. The price, the bulk row (`"amount"` or `"units":{"number":".5"}`), the custom value and `bea init --opening-balance 'Assets:Checking .5'` all write `0.5` and `bea check` passes. Control: `-p 'Expenses:Food 0.5 USD'` writes with exit 0.

**Expected.** One rule for one number across `bea add`. The posting and balance fields accept a leading-dot number (`.5`, `-.5`, `+.25`, also inside `{…}` costs, `@`/`@@` prices and the `~` tolerance) and write it with its zero (`0.5`, `-0.5`), as the other add paths already do and as the hosted structured write does (w23/043). Text stays untouched: narrations, quoted strings, comments, and a dot after a letter or digit. Beancount's own file grammar still refuses `.5` (`bean-check` says `Invalid token: '.5'`), so what `bea` writes must keep the zero.

**Root cause.** `cli/src/bea_engine/amounts.py` `parse_decimal_number` (about line 200) admits `\.[0-9]+` on purpose. It reads `add price --amount`, `init --opening-balance`, `add custom number:` and bulk `amount`/`units` cells, and the writer prints the `Decimal` as `0.5`. `--posting` and `add balance --amount` are instead parsed as ledger text by `parse_exact` (Beancount's grammar). That happens in `cli/src/bea_engine/ledger/adding.py`: the transaction fragment is built at about line 1442 and the balance in `_parse_balance_amount` at about line 1196. The lexer has no leading-dot number, so the refusal is a raw token error.

**Fix (cli only, local operation; no REST/GraphQL/MCP change, since hosted already normalizes).** Before `parse_exact` reads a posting or balance fragment, give a number written without its leading zero one, outside quoted strings and `;` comments, as w21/969 does for hosted reads. The parsed `Decimal` then writes `0.5`.

**Done when** the repro's posting writes `Expenses:Food 0.5 USD` (and `-.5` writes `-0.5`) and its balance writes `balance Assets:Checking 0.5 USD`, each with exit 0 and a clean `bea check`. A `"Café .5"` narration and a `; .5` comment are left as written. The price, bulk, custom and init paths are unchanged. A regression test in `cli/tests/` covers the posting (units, cost and price), the balance amount and tolerance, and the untouched string and comment, and fails with the fix reverted. `make check-all` passes.

**Dedupe.** Searched `.pm/**` for `.5`, `leading dot`, `leading zero` and `Invalid token: '.`. w21/969 (hosted read of `.5`), w23/043 (hosted structured write normalizes `.5`) and w21/075/792 (mobile parser) are done and outside the CLI. w5/290 (comma grouping) and w5/007 (scientific notation) fixed the same kind of split between add paths for other spellings. No open item covers `bea`'s posting or balance path.

## Objective

`bea add transactions` accepts JSON floats for amount fields and writes their binary expansion into the ledger — `0.30000000000000004` where the caller meant `0.3`. The bulk JSON path is the skills' write primitive, so this corrupts exactly the route agents use.

## Context

- `w3/260` (major): `add transactions` accepts JSON floats and writes binary junk.
- w1/028 fixed IEEE-754 rounding on three write paths; the bulk JSON path still admits floats.
- Bulk input is parsed in `cli/src/cli/commands/add.py` and validated engine-side in `cli/src/bea_engine/ledger/adding.py`.

## Steps

1. Reject JSON floats in every amount, cost, and price field; accept decimal strings and integers only.
2. Report the offending field, its row, and the exact-string form the caller should send.
3. Parse accepted values straight to `Decimal` with no float intermediate anywhere on the path.
4. Check the same rule applies to metadata values that carry amounts.

## Files

- cli/src/cli/commands/add.py
- cli/src/bea_engine/ledger/adding.py
- cli/src/bea_engine/ledger/models.py
- cli/tests/test_bulk_transaction_unknown_fields.py

## Acceptance criteria

- [ ] A bulk row with `"amount": 0.3` is refused with the field, the row, and the string form named; nothing is written.
- [ ] `"amount": "0.3"` and `"amount": 3` are accepted and write exactly `0.3` and `3`.
- [ ] No float appears anywhere on the amount path, verified by the parsing code and its tests.
- [ ] Existing valid bulk input is unchanged.

## Out of scope

- The JSON envelope's error shape, owned by m25.
- Schema fields unrelated to amounts.

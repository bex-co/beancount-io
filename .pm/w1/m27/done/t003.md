## Objective

The writer rewrites `@@` total prices as `@` unit prices, which turns an exact total into a repeating decimal — a value that is both unfaithful to the input and unbounded in length.

## Context

- `w3/309` (major): `bea add` rewrites `@@` total prices as `@` unit prices with unbounded repeating decimals.
- Directive writing is in `cli/src/bea_engine/ledger/writer.py`.

## Steps

1. Keep the price form the caller supplied: `@@` stays `@@`, `@` stays `@`.
2. Where a conversion is genuinely required, bound the result by the commodity's display context and never emit an unbounded expansion.
3. Verify the round trip: writing then reading a `@@` posting returns the same total.
4. Check the bulk JSON and import paths write the same form as the flag path.

## Files

- cli/src/bea_engine/ledger/writer.py
- cli/src/bea_engine/ledger/models.py
- cli/tests/test_writer.py

## Acceptance criteria

- [ ] A transaction entered with `@@` is written with `@@` and the exact total supplied.
- [ ] No written price contains an unbounded repeating expansion.
- [ ] The same form is written through the flag, bulk JSON, and import paths.
- [ ] `bea check` passes and the round trip preserves the value.

## Out of scope

- Changing how Beancount interprets `@` versus `@@`.
- Report-side conversion, which t004 owns.

## Objective

Converted report and balance amounts print unbounded repeating decimals when the target currency has no display precision, and in the opposite direction human tables force two decimals even when the ledger's display context infers zero fractional digits.

## Context

- `w3/304`: converted report amounts print unbounded repeating decimals when the target currency lacks display precision.
- `w3/365`: `bea balance` / `report` human tables force `.00` when `doctor display-context` infers zero fractional digits.
- Report rendering runs through `cli/src/bea_engine/report.py` and the vendored Fava subset in `cli/src/fava/`.

## Steps

1. Resolve the display precision for every rendered amount from the ledger's display context, with a documented fallback when the context says nothing.
2. Bound conversions so no rendered number can be unbounded.
3. Make the human table honor an inferred zero-fraction context instead of forcing two decimals.
4. Keep JSON output exact — the rounding is a rendering concern, not a data one.

## Files

- cli/src/bea_engine/report.py
- cli/src/cli/output.py
- cli/src/cli/commands/report.py
- cli/tests/test_forecast.py

## Acceptance criteria

- [ ] A conversion into a currency with no declared precision renders a bounded number, using the documented fallback.
- [ ] A ledger whose display context infers zero fractional digits renders whole numbers in human tables, not `.00`.
- [ ] JSON output still carries the exact value, unrounded.
- [ ] Existing report fixtures, including the 365-period daily report from w1/m22, are unchanged.

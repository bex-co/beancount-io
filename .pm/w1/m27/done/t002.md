## Objective

`bea add transaction` rejects `1e2` while `import` and bulk JSON accept it, so the same value is valid or invalid depending on which door it comes through.

## Context

- `w3/259`: `add transaction` rejects scientific amounts while `import` and bulk JSON accept them.
- The paths diverge between `cli/src/cli/commands/add.py`, `cli/src/bea_engine/csv_mapper.py`, and `cli/src/bea_engine/ledger/adding.py`.

## Steps

1. Choose one rule — accept scientific notation everywhere and normalize it to plain decimal on write, or refuse it everywhere with the plain-decimal form suggested.
2. Implement the rule in the shared amount parser so no path can diverge again.
3. State the rule in the amount grammar section of the usage guide.

## Files

- cli/src/bea_engine/ledger/models.py
- cli/src/cli/commands/add.py
- cli/src/bea_engine/csv_mapper.py
- cli/docs/USAGE.md
- cli/tests/test_writer.py

## Acceptance criteria

- [ ] `1e2` behaves identically through `add transaction`, `add transactions`, and `import`.
- [ ] If accepted, the written ledger contains the plain decimal form and the value is exact; if refused, every path refuses with the same message.
- [ ] The rule is documented once in the amount grammar.

## Out of scope

- Broader number-format leniency such as underscores or spaces.
- The CSV amount spellings owned by m24/t003.

## Objective

`bea add transaction` returns a cost as `number_per` / `number_total` in its JSON result, but `bea add transactions` rejects that shape and requires `number` — so an agent cannot feed one command's output into the other, and lot-and-cost strings are refused with a misleading "must be a string" error.

## Context

- `w3/240` (major): the JSON shape `add transaction` returns is not the shape `add transactions` accepts.
- `w3/272`: bulk JSON `amount` shorthand rejects lot and cost strings with a misleading `must be a string` error.
- Both shapes are defined in `cli/src/bea_engine/ledger/models.py`.

## Steps

1. Make the bulk input schema accept the shape the single-directive command emits, so output can be piped back in.
2. Accept the lot and cost string spellings the shorthand documents, and make the rejection message name the accepted forms when it does refuse.
3. Add a round-trip guarantee to the write contract: what `add` returns, `add transactions` accepts.
4. Document the accepted cost shapes once.

## Acceptance criteria

- [ ] `bea --json add transaction … | bea add transactions --from -` round-trips a costed posting without editing the payload.
- [ ] Lot and cost strings in the shorthand are accepted; a genuine refusal names the accepted forms.
- [ ] The written ledger preserves the exact cost values.
- [ ] The round-trip guarantee is stated in the usage guide.

## Out of scope

- Redesigning the bulk schema beyond the shapes named here.
- Booking-method selection (`w3/306`).

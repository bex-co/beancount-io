# `bea list transaction --details` and `bea query -f beancount PRINT` drop the spaces before a line break inside a multi-line payee or narration, so the export no longer parses back to the ledger's own text (regression from w1/295)

Found by `/qa-find-bugs-cli w1` on 2026-11-19 (HEAD `cbd411874`, `bea 0.4.1`, macOS 26.5.1, Python 3.12.14, checkout `uv run bea`, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, synthetic ledgers). Severity: minor. A1: these two commands are how an agent copies, reviews or moves existing entries as Beancount text, and the `DirectivePrinter` docstring promises that "an export must retain existing multiline ledger strings". The changed text still parses, so nothing warns.

**Repro** (synthetic; `bea check` exits 0). `main.bean`, where the first narration line ends in three spaces:

```sh
printf 'option "operating_currency" "USD"\n2024-01-01 open Assets:Bank USD\n2024-01-01 open Expenses:Food USD\n\n2024-01-05 ! "Dinner   \nwith friends"\n  Expenses:Food  20 USD\n  Assets:Bank\n' > main.bean
bea --json -f main.bean list transaction | jq '.data[0].narration'
bea -f main.bean list transaction --details | cat -e
bea -f main.bean query -f beancount -o export.bean "PRINT FROM narration ~ 'Dinner'"
bea --json -f export.bean query --allow-errors "SELECT narration" | jq '.data.rows[0]'
```

**Actual.** The ledger holds `"Dinner   \nwith friends"` (first command). `--details` and `PRINT` both print the header as `2024-01-05 ! "Dinner$` then `with friends"$`, without the three spaces, and `export.bean` reads back as `"Dinner\nwith friends"`. A payee does the same: `"Payee   \n"` prints as `"Payee` then `"`. All exits are 0.

**Expected.** The printed header keeps the string's characters: `2024-01-05 ! "Dinner   ` then `with friends"`, as upstream's printer writes it. Reading the export back gives the ledger's own narration. A header with no payee, narration, tag or link still ends at its flag with no trailing space (w1/295).

**Root cause.** `DirectivePrinter.__call__` (`cli/src/bea_engine/ledger/writer.py:125-126`) splits the printed transaction at its first `\n` and right-strips that first physical line. w1/295 (`8780f3634`) added this to drop the space upstream leaves after a bare flag. When a payee or narration contains a line break, that first line ends inside the open string, so the strip removes characters of the string itself. Upstream `EntryPrinter` prints `'2024-01-05 ! "Dinner   '` for the same entry, so the output was faithful before `8780f3634`.

**Fix** (cli only). Strip only the space upstream writes after the flag when nothing follows it: for example, only when the entry has no payee, narration, tags or links, or only when the first line does not end inside an open quoted string. Never touch text inside a string.

**Regression.** A transaction whose narration, and one whose payee, has trailing spaces before a line break prints byte-identical to upstream's `EntryPrinter` through `list transaction --details` and `query -f beancount PRINT`, and the `-o` export loads back with the same narration and payee. The w1/295 tests in `cli/tests/test_bare_transaction_header.py` still pass. The new assertions fail with the fix reverted.

**Blast radius.** Every `DirectivePrinter` user that prints an existing entry: `format_transaction` behind `list transaction --details` (`cli/src/bea_engine/ledger/listing.py:137`), `query.py:1871` `_render_beancount` (`-f beancount`, including `-o`), and `query.py:2066` (directive cells in CSV output). The write paths are not affected because they normalize new input to one line first: `add transaction -n $'Dinner   \nwith friends'` and a CSV import cell holding the same text both write `"Dinner    with friends"`. `update transaction --flag/--tag/--account` on the multi-line entry edits its lines in place and keeps the spaces (checked).

**Dedupe.** Searched `.pm/**` for `multi-line`/`multiline` with `trailing`, and for `w1/295` and `rstrip`. [w21/191](../w21/done/191.md) is the same symptom in the hosted editor's serializer (TypeScript, fixed). [w5/834](../w5/done/834.md) and [w5/1083](../w5/done/1083.md) cover other parts of the multiline-string contract. None covers this printer. Estimate: 20–30 minutes.

# A renamed-option error (E7004) has no file, line or code

**Bug · ledger · minor · ~20m · A1.** From `/qa-find-bugs-mcp`, 2026-11-09, production `beancount-mcp 1.0.0`, dry runs on the disposable QA ledger. This is a gap left in shipped w21/309, whose title promised E7001/E7002/E7004.

- **Repro:** run `updateLedgerFiles` with `dry_run`, setting `main.bean` to its current content plus `option "inferred_tolerance_multiplier" "3"` on line 7.
  - **Result:** `newErrors: [{"message":"[E7004] Renamed to 'tolerance_multiplier'."}]`. There is no `source` and no `code`, and the `[E7004]` tag is still in the message. Three fresh requests gave the same result.
  - **Controls:** an unknown option gives `E7001` at `main.bean:7`, and `booking_method "BOGUS"` gives `E7002` at `main.bean:7`. Local `bea check` reports `main.bean:7: Renamed to 'tolerance_multiplier'.`
- **Cause:** `backend-cluster/ledger/src/foundation/rustledger/option-validation.ts:85-121` (`locateOptionErrors`) finds the option line only by the names or values the message quotes. E7004 quotes only the new name, so no declaration matches, and `:103` returns the error untouched. b5aa29d96 never tested E7004.
- **Fix:**
  - Map E7004's quoted new name back to its old names with a small renamed-options table, e.g. `{tolerance_multiplier: [inferred_tolerance_multiplier]}`.
  - Also move the tag into `code` even when no line matches.
  - The change is in shared code, so it covers REST, GraphQL and MCP checks, previews and the errors resource.
- **Check:** add E7004 cases to `option-validation.test.ts` and `engine-option-errors.test.ts`.

# `bea init --preset` still opens every account for the operating currency only, so a euro lunch in a `personal@1` dollar ledger is refused, while hosted Create Ledger opens the same preset with no constraint (CLI gap in w21/687)

**Bug · cli · major · 30–45m · A2.** From routine cli-qa, 2026-11-20. `bea init --preset <id>@1 --currency USD` writes `open <account> USD` for every preset and module account except a holdings account. `Expenses:Food`, `Income:Dividends`, `Assets:Cash`, `Liabilities:CreditCard` and `Equity:OpeningBalances` are all restricted to dollars. So the first foreign purchase in the new books is refused, for example a 12.00 EUR lunch, euro cash from an ATM, or a dividend paid in euros. The same preset created through hosted Create Ledger (`bea cloud ledger create --preset`, the dashboard, mobile, MCP `createLedger`) opens every account bare. One `bea` binary therefore writes two different charts for one preset, depending on whether the ledger is local or hosted.

History: w5/957 (CLI, 2026-10-22) lifted the restriction only for `Assets:Holdings`. Its test `test_cash_and_fee_accounts_stay_restricted_to_the_operating_currency` pins the rest. A day later, w21/687 (hosted, `c5a7292a3`) removed the restriction from every preset account, because the operating currency "neither converts amounts nor prohibits other currencies". That note's acceptance includes "Personal accepts a EUR expense". The CLI builder's docstring still says it "Mirrors the hosted builder". `cli/docs/USAGE.md` says that after `init`, "the income, expense and equity categories take any currency, so a foreign charge … books … without editing an open". That holds for the fixed chart, not for a preset.

Environment: main `31c5d9d65`, `bea 0.5.0` from the checkout (`uv run bea`), Python 3.12.14, macOS 26.5.1. The run used an isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME` with `BEA_NO_UPDATE_NOTIFIER=1`, `BEA_FILE`/`BEA_TOKEN` unset, stdin closed, no TTY and a scratch cwd. Reproduced in fresh processes. The ledger hash was unchanged by each refusal.

## Repro

```sh
bea --no-input init books --preset personal@1 --module investments@1 --currency USD --date 2026-01-01   # exit 0
grep open books/main.bean
bea --file books/main.bean add transaction "Lunch in Paris" --date 2026-01-05 \
  -p 'Expenses:Food 12.00 EUR @ 1.10 USD' -p 'Liabilities:CreditCard'
bea --file books/main.bean add transaction "Euro cash" --date 2026-01-05 \
  -p 'Assets:Cash 50.00 EUR @ 1.10 USD' -p 'Assets:Bank'
```

Actual: every open except `Assets:Brokerage "FIFO"` ends in ` USD`, for example `2026-01-01 open Expenses:Food USD` and `2026-01-01 open Equity:OpeningBalances USD`. Both adds exit 1 with `The change would leave the ledger invalid; nothing was written.` and `Invalid currency EUR for account 'Expenses:Food'` (then `'Assets:Cash'`), followed by the hint to edit that open to `USD,EUR`. Each of the eight presets writes ` USD` on all its accounts except `Assets:Holdings`; the account lists themselves match the hosted ones.

Controls:

- Hosted, production, read-only: MCP `previewLedgerSetup({preset: "personal@1", operatingCurrency: "USD", historyStart: "2026-01-01", modules: [{id: "investments@1"}]})` returns the same 17 accounts, each opened bare (`2026-01-01 open Expenses:Food`, `2026-01-01 open Assets:Brokerage "FIFO"`). `freelance@1`, `business@1` and `shared-expenses@1` also open bare.
- The fixed chart: `bea --no-input init fixed --currency USD --date 2026-01-01`, then the same lunch posted to `Expenses:Dining`, exits 0, and `bea check` passes.

## Expected

`bea init --preset` writes the open lines the hosted builder writes for the same preset, modules, currency and date. Every preset and module account opens with no currency constraint. A catalog booking method still ends the line (`open Assets:Brokerage "FIFO"`). With a known opening balance, `Equity:OpeningBalances` opens bare as well, as in w23/048. On the repro, both adds exit 0 and `bea check` stays clean. `USAGE.md` says preset ledgers open their accounts unconstrained, like hosted Create Ledger, and keeps the fixed-chart sentence for `init` without `--preset`.

## Root cause

`answer_preset` in `cli/src/bea_engine/initiating.py:305-312` appends ` {currency}` unless the account is in `_INSTRUMENT_ACCOUNTS` (`:195`, only `Assets:Holdings`) or the catalog marks it `kind: "holdings"`. The hosted `openLine` (`backend-cluster/backend-v2/src/features/ledger/setup/build-ledger.ts:358-373`) passes only `account.currency`, a currency the caller set up for that account, and the local builder has no such per-account input.

## Fix

In `answer_preset`, drop the operating-currency restriction from every preset and module account, as `build-ledger.ts` does, and remove the now-unneeded `_INSTRUMENT_ACCOUNTS` special case. Replace `tests/test_init_portfolio_holdings.py::test_cash_and_fee_accounts_stay_restricted_to_the_operating_currency` (`:63`), which pins w5/957's narrower fix. Add a regression test that inits `personal@1` (with and without an opening balance) and `portfolio@1` through real `bea` subprocesses and asserts that no open line carries a currency. It should also post the EUR lunch and the EUR cash with exit 0 and get a clean `bea check`. Revert the fix and watch the test fail. Update the `USAGE.md` sentence at `:532` and the "Setup presets and modules" section. Only `cli/` changes; the hosted builder already behaves this way.

## Blast radius and dedupe

All eight presets and the three `personal@1` modules go through the one `answer_preset` loop; `init` without `--preset` (`answer` / the fixed chart) is unaffected. `bea cloud ledger create --preset` already uses the hosted builder. Searched `.pm/**` for "preset" with "Invalid currency", "restricted to the operating", "EUR lunch" and "currency constraint". The matches are w21/687 (hosted, done), w5/957 (CLI holdings only, done), w23/048 (hosted equity, done) and w21/107 (Create Ledger input validation, unrelated). No open item covers the CLI builder's remaining accounts.

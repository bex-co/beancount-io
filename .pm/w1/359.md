# A write dated after an account's `close` is told to "edit that directive; for new books use bea init --date", but two directives were just named and `bea init` refuses an existing ledger

**Bug · cli · minor · 20–30m · A1.** From routine cli-qa, 2026-11-22. When `bea add` is refused because the account is closed on the entry's date, the refusal names the account's `open` and its `close`, then ends with the remedy written for an account that opens too late: `Correct the transaction date or edit that directive; for new books use bea init --date YYYY-MM-DD.` "That directive" could be either line, and only the close can be moved to make the write valid. `bea init --date` cannot reopen an account or move a close, and on this ledger it exits 4 with `Already exists … init never overwrites a ledger`. An agent repairing the write follows the printed remedy (as w5/393 and w1/281 rely on), and both parts of this one lead nowhere. Nothing is written, so the books are safe.

Environment: main `c9a096e89`, `bea 0.5.0` from the checkout (`uv run bea`), Python 3.12.14, macOS 26.5.1. Isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, `BEA_FILE`/`BEA_TOKEN` unset, stdin closed, no TTY, scratch cwd, fresh processes.

## Repro

```sh
mkdir books
cat > books/main.bean <<'EOF'
option "operating_currency" "USD"
2026-01-01 open Assets:Old USD
2026-01-01 open Assets:Cash USD
2026-01-01 open Equity:Opening USD
2026-03-01 close Assets:Old
EOF
bea --file books/main.bean add transaction late --date 2026-03-05 -p 'Assets:Old 1.00 USD' -p Assets:Cash
bea --file books/main.bean add pad --date 2026-03-05 -a Assets:Old --source Equity:Opening
bea --no-input init books --currency USD --date 2025-01-01
```

## Actual

Both writes exit 1 and write nothing (the file's hash is unchanged):

```text
Proposed append (not written): Invalid reference to inactive account 'Assets:Old' Account opened 2026-01-01 at …/books/main.bean:2. Account closed 2026-03-01 at …/books/main.bean:5. Correct the transaction date or edit that directive; for new books use bea init --date YYYY-MM-DD.
```

The pad reads the same with "Correct the pad date". `--json` carries the same text in `error.details`. The `init` command the remedy suggests exits 4: `Already exists: …/books/main.bean. Choose a new path; init never overwrites a ledger.`

## Expected

When the account is inactive because a written `close` precedes the entry, the remedy names that close and the date it would need: `Correct the transaction date, or move the close at …/books/main.bean:5 to on or after 2026-03-05.` It has no `bea init --date` clause. The open-after-entry case keeps today's wording, `bea init` clause included, since setting the opening date is the fix for new books there. Plugin-made opens and closes keep the w5/222 wording.

## Cause

In `validate_candidate`'s inactive-account branch (`cli/src/bea_engine/ledger/write.py:2929`), `remedy` starts as `"edit that directive"` (`:2934`). The loop over the account's lifecycle (`:2935`) appends one `Account opened … / Account closed …` sentence per written open and close (`:2977`) and leaves `remedy` unchanged for both. `:3006` then appends `" {fix} or {remedy}; for new books use bea init --date YYYY-MM-DD."` whichever directive made the account inactive.

## Fix

Owned by `cli`. When the entry's date falls after a written close of the account, set the remedy to move that close (its location, plus the entry's date as the earliest valid close date) and drop the `bea init --date` clause. When the entry's date falls before a written open, keep today's remedy. Regression test through real `bea add transaction` and `bea add pad` subprocesses on the repro, with the open-after-entry refusal as an unchanged control. Revert the fix and watch it fail. Run `make check-all` in `cli/`. No REST, GraphQL or MCP surface prints this message.

## Blast radius

`validate_candidate` serves every `bea add` type, `add transactions` rows and `update transaction`. A bulk row dated 2026-03-05 and an `update transaction --account 'Assets:Cash=Assets:Old'` on a later entry print the same paragraph (checked). Import's preview already blocks such rows with the right remedy: `Account 'Assets:Old' was closed 2026-03-01 (at …/main.bean:5), before this row's 2026-03-05. Re-date the close, or import into an account that is still open.` That is the working control. A note or document after a close is accepted, as Beancount allows. A balance assertion after a close is accepted as well, so this message never appears for one.

## Dedupe

Searched `.pm/**` for `for new books use`, `edit that directive`, and `inactive account` with `Account closed`. w5/393 named the directive type in the `Correct the … date` clause and kept the `bea init --date` clause as "the remedy for new books". w1/281 fixed how errors were grouped, w5/765 gave the documents-folder wording, and w5/222 gave the plugin-made open and close wording, keeping the written-close text as its control. w5/772 and w1/293/338 cover `add close` itself. None covers the remedy for an entry dated after a written close.

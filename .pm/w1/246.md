# `bea update transaction` previews a no-op as "Review the diff", with no diff and no `noop` flag

Found by `/qa-find-bugs-cli w1` on 2026-11-15 (HEAD `164c163be`, `bea 0.3.1`, macOS 26.5, checkout `uv run bea`, stdin closed). Severity: minor.

**Contract.** `cli/src/bea_engine/README.md` (single-row update) says: "A request that changes nothing answers `"written": 0` with `"noop": true`." With `--apply` the human output says `No changes to FILE:LINE; the entry already matches.` The batch form reports such a row `unchanged` in preview and apply alike (w1/244).

**Repro** (synthetic ledger):

```sh
mkdir u && cd u
cat > main.bean <<'EOF2'
option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Uncategorized USD

2024-02-01 ! "Cafe" "Latte" #t1
  import-id: "abc1"
  Expenses:Uncategorized  4.50 USD
  Assets:Cash
EOF2
bea --file main.bean update transaction --id abc1 --tag t1; echo "exit $?"
bea --json --file main.bean update transaction --id abc1 --flag '!'
bea --json --file main.bean update transaction --id abc1 --flag '!' --apply
```

Actual: the preview prints only `Preview only. Review the diff, then repeat with --apply to write.` There is no diff to review, and it exits 0. The JSON preview answers `{"id": "abc1", "lineno": 5, "diff": "", "written": 0}` with no `noop`. The same request with `--apply` answers `"noop": true` and prints the "already matches" note. An agent that previews before applying cannot tell a no-op from a real change without parsing an empty diff. A person is told to review nothing and run `--apply` for no reason. This repeats for a tag already present, the same flag, and an account the leg already posts to.

Expected: the preview answers `"noop": true` when the planned diff is empty, and prints `No changes to main.bean:5; the entry already matches.` in place of the "Preview only" line, exactly as `--apply` does. Exit 0 in both modes.

**Root cause.** In `cli/src/bea_engine/ledger/updating.py`, the preview branch of the single-row update (around line 1160) returns `_planned_answer(...)` without the `noop` key. Only the apply branch (around line 1184) adds `"noop": True` when `diff` is empty. `_show_update` in `cli/src/cli/commands/update.py` (around line 97) keys its message on `noop`, so the preview falls through to "Preview only".

**Fix.** Add `"noop": True` to the preview answer when `diff` is empty, matching the apply branch. Add a test in the single-row update tests: a no-op preview exits 0, JSON carries `noop: true`, the text says "already matches", and the file is byte-identical. Estimate: about 20 minutes.

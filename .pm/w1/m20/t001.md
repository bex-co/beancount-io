## Objective

Let customers explicitly enable Beangulp and Beanprice through bea while keeping them outside the frontend and base engine.

## Context

- ADR012 keeps optional packages out of the default dependency set; ADR014 places ledger execution in the engine.
- A Python extra that installs Beangulp/Beanprice into the frontend venv would violate the selected architecture.

## Steps

1. Review exact optional-package/transitive licenses, source requirements, and compatibility with the base engine; record unresolved issues as blockers.
2. Implement a supported bea feature-enablement/install option backed by reviewed, hash-pinned engine manifests for each supported channel.
3. Provision only the selected optional feature in an engine environment or compatible engine profile. Preserve the base profile, channel ownership, upgrades, and frontend isolation.

## Files

- cli/ (optional engine manifests, feature provisioning, package configuration, and tests)
- docs/adrs/ADR014-cli-beancount-parity.md; cli/docs/IMPORTING.md

## Acceptance criteria

- [ ] An explicit bea-level choice provisions the selected tools without a separate customer pip install of upstream packages.
- [ ] No optional package enters the frontend or unselected base engine; actual optional licenses and source-delivery requirements are recorded.

## Out of scope

- Unreviewed dependency resolution, automatic opt-in, or assuming all optional dependencies are GPL-compatible.

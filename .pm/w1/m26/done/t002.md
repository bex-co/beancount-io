## Objective

Writes are LF-only regardless of the file they append to, so a CRLF ledger becomes mixed after the first `bea add` or `import`, and a ledger with no trailing newline fails the append outright even though `bea check` calls it valid.

## Context

- `w3/258`: `bea add` / `import` append LF-only lines to CRLF ledgers, leaving mixed endings; a later `bea format -i` rewrites the whole file to LF, producing a large spurious diff.
- `w3/266`: `bea add` / append fails on ledgers that lack a final newline, while `bea check` stays green.
- Appending is `cli/src/bea_engine/ledger/appending.py`; atomic writes are `cli/src/bea_engine/ledger/write.py`.

## Steps

1. Detect the dominant line ending of the target file and write new lines with the same ending.
2. When a file has no trailing newline, add one as part of the append instead of failing, and keep the operation atomic.
3. Leave existing bytes untouched — do not normalize a file's endings as a side effect of appending.
4. Decide and document what `bea format -i` does with mixed endings, so the convergence behavior is intentional rather than incidental.

## Acceptance criteria

- [ ] An append to a CRLF ledger produces CRLF lines; the file contains no mixed endings afterwards.
- [ ] An append to a ledger with no final newline succeeds and the result parses; the operation stays atomic on failure.
- [ ] An LF ledger is unaffected.
- [ ] `bea format -i` on a mixed-ending file produces the documented, consistent result.

## Out of scope

- Git attribute or checkout configuration.
- Changing the default line ending for newly created ledgers.

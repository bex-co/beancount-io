## Objective

Payee and narration flatten embedded newlines, but `note`, `event`, and `custom` keep them, so a pasted multi-line value writes a directive that breaks the file. The three paths should follow one rule.

## Context

- `w3/252`: `bea add note` / `event` / `custom` keep CR/LF in string fields while payee and narration flatten them.
- Directive construction is in `cli/src/bea_engine/ledger/adding.py` and `writer.py`.
- Triage 2026-09-17: the w3/252 flattening is fixed and tested (`test_directive_single_line.py`). Remaining work is verifying the bulk path and `bea check` after write, and documenting the rule in `USAGE.md`.

## Steps

1. Apply the payee and narration rule to every quoted string field: flatten or reject embedded CR/LF, consistently.
2. Choose one behavior for all fields and state it where the write contract is documented.
3. Ensure a rejected value fails before any write, keeping the ledger unchanged.
4. Check the bulk JSON path uses the same rule as the flag path.

## Acceptance criteria

- [ ] `bea add note`, `add event`, and `add custom` with an embedded newline behave exactly as `add transaction` does with the same input.
- [ ] The resulting ledger always parses; `bea check` passes after any successful write.
- [ ] The bulk JSON path follows the same rule.
- [ ] The behavior is documented once in the usage guide.

# In a folder whose root ledger is `household.beancount`, every plain `bea` command says "To start new books, run bea init books", and `--file .` / `bea doctor <op> .` suggest a `main.bean` that does not exist

**Bug · cli · minor · 30–45m · A2.** From routine cli-qa, 2026-11-23. `bea init --existing .` finds a folder's root ledger when it is not named `main.bean` (the one `.bean`/`.beancount` file no other file includes), and `docs/skills/existing-ledger.md` is built around exactly that case: its sample root is `household.beancount`. Every other command run in that folder ignores what it finds. Plain `bea check`, `bea report overview`, `bea list …` or `bea add …` refuse with advice to start new books. `bea --file .` and `bea doctor <op> .` name `./main.bean` as "its root ledger", a file that does not exist. A Beancount user arriving with their own books, the m42 audience, is told to create a second ledger inside their own ledger folder. If they follow that advice, the next refusal points them at that new, empty ledger. Nothing in the existing books is written (checked by hash).

Environment: main `02205dafc`, `bea 0.5.0` from the checkout (`uv run bea`), Python 3.12.14, macOS 26.5.1. Isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, `BEA_FILE`/`BEA_TOKEN` unset, stdin closed, no TTY, fresh processes.

## Repro

The guide's own sample books, copied as the guide's step 2 copies them:

```sh
mkdir hh && cp -R docs/skills/examples/existing-ledger/. hh/ && cd hh
# household.beancount  accounts.beancount  2026/01.beancount  2026/02.beancount  household_rules.py
bea check
bea report overview
bea --json check
bea --file . check
bea doctor lex .
bea doctor guidance .
bea --file main.bean check            # the file the two hints above name
bea --no-input init books --currency USD   # the command the first hint names
bea report overview                   # after following it
```

A minimal synthetic folder reproduces it too: one `ledger.beancount` holding `option "operating_currency" "USD"`, and no `main.bean`.

## Actual

- `bea check`, `report overview`, `list transaction` and `add transaction` all exit 2 with `No ledger file at 'main.bean' (from the working directory). Name one with --file PATH, set BEA_FILE, or run from a directory containing main.bean or main.beancount. To start new books, run bea init books --currency USD.` `--json` carries the same message.
- `bea --file . check` exits 2: `Ledger path '.' (from --file) is a directory; expected a ledger file. Point --file to its root ledger, for example --file main.bean.`
- `bea doctor lex .` and `bea doctor guidance .` exit 2: `… Pass its root ledger instead, for example bea doctor lex main.bean.`
- `bea --file main.bean check`, the suggested fix, exits 2 with `No ledger file at 'main.bean' (from --file)`, ending again with `To start new books, run bea init books --currency USD.`
- `bea init books --currency USD`, the other suggested fix, exits 0 and creates `books/main.bean` with 14 accounts inside the existing ledger folder. Plain `bea report overview` now says `Found books/main.bean here: run cd books, or pass --file books/main.bean.`, which points at the empty new ledger, not at `household.beancount`.

Controls: `bea --file household.beancount check` loads the ledger. It exits 1 on the sample's plugin-beside-the-ledger item, as the guide expects. `bea init --existing .` names `household.beancount` as the root. In a folder holding `main.beancount`, the directory hints correctly suggest `main.beancount`.

## Expected

When a refused folder holds no `main.bean` or `main.beancount`, the hint names the root that `init --existing` would find there, by the same rule. That rule is the one `.bean`/`.beancount` file that no other file there includes.

- Cwd discovery: `… Found household.beancount here, the one ledger file nothing else includes: pass --file household.beancount, or set BEA_FILE.` It has no "start new books" sentence.
- `--file DIR` and `bea doctor <op> DIR`: `… for example --file DIR/household.beancount` (or `bea doctor lex DIR/household.beancount`).
- When several root candidates remain, the hint names them (at most a few) and asks for one, as `init --existing` does. "To start new books" stays only for a folder with no ledger file at all, and the w5/219 child-directory hint is unchanged.

Discovery itself does not change: only `main.bean` and `main.beancount` are loaded implicitly (USAGE "Choosing the ledger"). Basis: the existing-ledger guide and `init --existing` define this folder as a valid set of books with a findable root. A hint must name a command that works (w5/219, w5/691, w1/359).

## Cause

- `RunContext.entry_file` (`cli/src/cli/context.py:128`): with nothing found, `:180` asks `_child_ledger` (`:55`) for a `main.bean` in a child directory only. Otherwise `:185` ends with `To start new books, run bea init books --currency USD.` The directory branch (`:192`–`:199`) falls back to `candidate / DEFAULT_ENTRY_FILE_FALLBACKS[0]`, `main.bean`, whether or not it exists.
- `_refuse_directory_ledger` (`cli/src/cli/commands/doctor.py:135`) has the same `main.bean` fallback at `:167`.
- The root finder these hints need already exists: `_root_in_directory` (`cli/src/cli/commands/init.py:345`), built on `output.ledger_candidates` (`cli/src/cli/output.py:685`) and `output.ledger_closure` (`:630`). It raises a `UsageError` on zero or several roots, so a hint wants a non-raising variant that returns the candidates.

## Fix

Owned by `cli`, frontend only. Move the candidate search out of `init.py` into a shared helper (for example in `cli/config.py` beside `default_entry`) that returns the roots without raising. Use it in `init --existing` and in the three hints above. The cost is reading the include lines of the folder's ledger files, and only on a path that is already refusing. Document the hint in USAGE "Choosing the ledger". Regression tests through real `bea` subprocesses on a copy of `docs/skills/examples/existing-ledger/`: plain `check` names `household.beancount` and no longer suggests `init books`; `--file .` and `doctor lex .` suggest `./household.beancount`, and running the suggested command loads the ledger. Two unincluded roots are both named. An empty folder keeps the init sentence. The `main.beancount` and child-`books/` controls are unchanged. Revert the fix and watch the new tests fail. Run `make check-all` in `cli/`. No REST, GraphQL or MCP surface resolves a local folder.

## Blast radius

`entry_file` serves every local command that discovers the ledger (`check`, `balance`, `list`, `add`, `update`, `report`, `query`, `import`, `price`, `ask`, `ingest`). The directory branch also serves every `--file DIR` and `$BEA_FILE` naming a directory. `bea doctor` has its own copy. `bea format --file DIR` already suggests the positional directory form and is unaffected, and `init` keeps its own messages. Searched for other `DEFAULT_ENTRY_FILE_FALLBACKS[0]` fallbacks in `cli/src/cli`: only the two above.

# Every ledger write refreshes with the keep-list, not a full cache wipe

**Perf · dashboard · ~1h · A2.** From `/simplify` on [w1/m41](blocked/m41/README.md), 2026-11-02.

m41 added `useLedgerWriteRefresh` (`dashboard/src/common/hooks/use-apollo-cache.ts`). It keeps the account-only root fields and refetches every ledger read. Only the file save uses it. Other ledger writers still evict all of `ROOT_QUERY`, and so refetch the user, the plan and the quotas after every write: the journal entry panel, New Entry, `accounts/index.tsx`, `delete-budget-dialog.tsx`, and the file view's own delete. The dashboard now has two refresh rules for the same kind of event.

- **Fix:** make the keep-list refresh the single ledger-write refresh. Keep the full `ROOT_QUERY` eviction only where nothing should survive: **Out of date → Refresh**, the danger zone, and the sidebar's ledger switch. That is about six call sites, mostly mechanical, plus their test mocks, and `dashboard/AGENTS.md`'s cache-clear rule collapses back to one sentence.
- **Same pass:** `useWriteOutcome` (`dashboard/src/common/hooks/use-write-outcome.ts`) reads `GetLedgerErrors` with `cache-and-network`, so every view that mounts it sends one more ledger-wide revalidation, although its comment says the snapshot "costs no request". `cache-first` matches that comment, since `report()` refetches explicitly anyway. Check that a first mount with an empty cache still gets a snapshot.
- **Check:** after each writer's write, `GetCurrentUser` and `GetSubscriptionStatus` do not refetch while every ledger read does, and **Out of date** re-baselines.

# JSON cloud clone discards Git's error and misdirects local failures to SSH

Severity: minor. Estimate: 30–45m with real-Git regression coverage. Owner: CLI.
A1/A2: a coding agent should be able to distinguish an occupied local directory
from authentication failure without rerunning outside JSON mode.

Reproduced twice at main `c6de619d9094e1ae45a248eef3e6ba3d74a5944f`, macOS
26.5.1 arm64, checkout `uv run bea` 0.1.0 / Python 3.13.0. Real Git subprocess,
loopback synthetic ledger metadata, no hosted account. Cwd `cli/`, stdin closed,
no TTY. No production SSH failure claimed.

Minimal reproducer from `cli/`:

```python
import json, os, subprocess, tempfile, threading
from pathlib import Path
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer
with tempfile.TemporaryDirectory(dir='tmp') as directory:
    root = Path(directory).resolve()
    origin, target = root/'origin.git', root/'occupied'
    subprocess.run(['git','init','--bare',str(origin)], check=True,
                   capture_output=True)
    target.mkdir()
    (target/'keep.txt').write_text('pristine\n')
    ledger = dict(id='1', name='books', fullName='qa/books', sshUrl=str(origin),
                  httpUrl='https://example.invalid/qa/books', empty=True,
                  private=True, createdAt='2026-09-09T00:00:00Z',
                  updatedAt='2026-09-09T00:00:00Z', size=0)
    class Handler(BaseHTTPRequestHandler):
        def log_message(self, *args): pass
        def do_GET(self):
            self.send_response(200)
            self.end_headers()
            self.wfile.write(json.dumps(ledger).encode())
    server = ThreadingHTTPServer(('127.0.0.1', 0), Handler)
    threading.Thread(target=server.serve_forever, daemon=True).start()
    try:
        env = os.environ.copy()
        env.pop('BEA_FILE', None)
        env.update(BEA_TOKEN='synthetic-invalid',
                   BEA_API_URL=f'http://127.0.0.1:{server.server_port}',
                   BEA_CONFIG_DIR=str(root/'config'),
                   XDG_CACHE_HOME=str(root/'cache'), BEA_NO_UPDATE_NOTIFIER='1')
        p = subprocess.run(['uv','run','bea','--json','cloud','ledger','clone',
                            'qa/books','--dir',str(target)], env=env,
                           stdin=subprocess.DEVNULL, capture_output=True,
                           text=True, timeout=10)
        print(p.returncode, p.stdout, p.stderr)
    finally:
        server.shutdown()
        server.server_close()
```

Actual: exit 1, empty stdout, JSON stderr only says
`Clone failed for <origin>. Ensure you have SSH access.` The local directory
problem is absent. Direct `git clone <origin> <occupied>` exits 128 and explains
`destination path ... already exists and is not an empty directory.` No SSH is
involved. Both sentinel files remained byte-identical; no data-loss claim.
Control: same source cloned successfully into a new directory, including a path
with spaces and Unicode (exit 0 and no JSON success object, as documented).

Expected: retain Git's actionable failure cause inside the single JSON error,
while preserving clean stdout. `docs/USAGE.md`'s JSON failure contract need not
change; this repairs missing diagnostic content, not the documented exception
that successful clone emits no JSON object.

Root cause: `cli/src/cli/commands/cloud/ledger/manager.py:65` captures both streams
in JSON mode but discards them; `CloneError` retains only the remote URL.
`ledger/app.py:88` always suggests SSH. Carry a bounded, appropriately sanitized
Git diagnostic into the error. Both callers (`clone`, `create --clone`) should
retain it; preserve created-ledger/manual recovery context on partial creation.
Add a real local bare-repo/occupied-target test and success control, plus a
create-and-clone error propagation check. Do not expose raw secret-bearing URLs.

fixes false success after creation, a separate behavior that this finding does

no repair found. Generated REST files are not fix targets; API parity unchanged.

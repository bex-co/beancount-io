# Cost labels lose backslashes when CLI transactions are written

**Major · 35–50 minutes.** QA reference CLI-QA-010.

Create a root opening Assets:Stock AAPL and Assets:Cash USD on 2026-01-01.
Save this as `rows.json`:
```json
[{"date":"2026-02-01","narration":"Buy","postings":[{"account":"Assets:Stock","units":{"number":"1","currency":"AAPL"},"cost":{"number":"100","currency":"USD","label":"lot\\A"}},{"account":"Assets:Cash","amount":"-100 USD"}]}]
```
```sh
uv run bea --json --file /absolute/qa/main.bean add transactions --from /absolute/qa/rows.json
uv run bea --json --file /absolute/qa/main.bean list transaction
```
Both exit 0, but the loaded cost label is `lotA` instead of a literal backslash
between lot and A. Reproduced twice at current HEAD. Earlier native escaped
Beancount controls preserve the label; ordinary `lot-one` works. A quoted label
fails syntax, while a backslash-n label can become an actual newline.

Cause: `directives/writer.py` passes CostSpec labels through its compatibility
formatter without escaping; upstream position formatting surrounds the label
with quotes but doesn't escape its contents. Existing compatibility handling
covers other fields. Extend that boundary using copied Cost/CostSpec values;
do not mutate caller data or double-escape other fields.

Earlier real CLI evidence also confirms single add, inspected Python import,
and list --details share the problem. Reproduce all those callers in regression
coverage, including native correctly escaped input and a plain-label control.
Acceptance: quotes/backslashes preserve exact lot identity after reload, and
valid labels do not cause rejected writes. No backend API change required.

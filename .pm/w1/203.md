# Journal filter `>N` compares absolute units, and the description doesn't say so

**Docs · backend-v2 · minor · ~10m · A1.** From `/qa-find-bugs-mcp`, 2026-11-09, read-only on the public example ledger.

- **Repro:**
  - `listLedgerEntries` with filter `>100` and type Transaction returns 457. A local count gives 250 for `units > 100` and exactly 457 for `|units| > 100`.
  - `<-100` is refused with `BAD_USER_INPUT` "Expected NUMBER, got -".
  - So an agent that writes `<0` to find spending gets zero rows.
- **Cause:** the ledger's `directive-filter.ts:673` deliberately keeps Fava's `MatchAmount` `abs()`. `journal-filter-description.ts:15`, which REST, GraphQL and MCP share, says only "bare `>100` matches posting units".
- **Fix:** add "compares the absolute value; thresholds are non-negative" to that description and to the filter syntax in `docs/mcp.md`.

# Two access answers miss rules recent work set: latest commit on public ledgers, ledger-wide bank reads

**Bug · backend-v2 · minor · ~30m · A1.** From `/qa-find-bugs-mcp`, 2026-11-10, a production sweep of every GraphQL Query root field, anonymously and with the QA API key. The sweep found no anonymous read of private-ledger or user-private data, and no non-null violations in about 150 calls.

- **`getLatestLedgerCommit` still needs a session on public ledgers.**
  - Anonymously on a public ledger, `getLatestLedgerCommit(ledgerId:"open_ledger/example", branchName:"main")` returns `UNAUTHENTICATED`.
  - `listCommits` and `getCommitDetails` on the same ledger answer anonymously; w3/497 made public history public.
  - **Cause:** `ledger-repo-resolver.query.ts:11` is `@Authenticated()`, so it rejects before the PDP. `op-class.ts:821-822` maps it to the same `LEDGER_REPOSITORY_READ` as `listCommits`. adec8ad5b switched only `commits-resolver.ts`.
  - **Fix:** `@AllowAnonymous()`, keeping the PDP check. Add anonymous-public and anonymous-private resolver tests. This is GraphQL only: REST keeps its documented credential requirement, and MCP is always authenticated.
- **Ledger-wide bank reads tell a reader "Bank connection not found".**
  - A reader (not admin) on a public ledger gets `FORBIDDEN` from the list: GraphQL `getPlaidItems`, REST `GET …/banks` (403) and MCP `listBankConnections`. Once deployed, origin/main's w1/194 fix makes that message name the admin requirement.
  - The ledger-wide account and transaction reads return `NOT_FOUND` "Bank connection not found" on all three surfaces, which reads as "no bank linked":
    - accounts: GraphQL `getPlaidAccountsForLedger`, REST `…/bank-accounts` (404), MCP `beancount://…/bank-accounts`
    - transactions: GraphQL `getUnsyncedPlaidTransactions` without `accountId`, REST `…/bank-transactions/unsynced`
  - **Cause:** in `authorization-service.ts`, `BANK_ACCOUNTS_READ` (~`:630`) and `BANK_TRANSACTIONS_READ` (`:727-737`) use `BANK_CONNECTION_CONCEALMENT` without `deniedToReader`. `plaid-item-service.ts:418-426,557-566` calls them ledger-wide.
  - **Fix:** when no item or account is named, authorize with `LEDGER_NOT_FOUND_CONCEALMENT` and `deniedToReader(requiresLedgerAdmin(...))`, the same rule as the list. Keep `BANK_CONNECTION_CONCEALMENT` for item- and account-scoped reads.
  - **Check:** add parity rows on REST, GraphQL and MCP. A reader gets `FORBIDDEN` naming admin; an unknown ledger gets `NOT_FOUND` "Ledger not found".

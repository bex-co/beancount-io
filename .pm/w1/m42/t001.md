## Objective

Settle, in writing, what "bring an existing ledger" does and never does, so the CLI command, the report and the skill branch all follow one contract.

## Context

- `bea init --agent-files` writes `AGENTS.md` and a `CLAUDE.md` bridge for a ledger it just created (`cli/src/cli/agent_guidance.py`, `write_agent_files`). Files are created exclusively and never overwritten.
- `bea doctor guidance` (`cli/src/cli/commands/doctor.py`) checks those files read-only and always exits 0.
- `skills/beancount-init/SKILL.md` Step 1 refuses a directory holding `main.bean`, `pyproject.toml` or a `Makefile`.

## Steps

1. Choose the command shape and record why. Candidates: `bea init --existing FILE`, or `bea doctor guidance --write`. Prefer the one whose help text a newcomer finds first and that keeps `doctor` read-only by default.
2. Define the inputs: any root file name; a root found through `--file`, `BEANCOUNT_FILE` or an explicit path, never guessed from the directory when there are several candidates.
3. Define what the generated `AGENTS.md` states, all read from the loaded ledger: the root, the `include` layout, where new entries go (the existing `bea add --into` destination rules), the operating currencies, the open accounts (capped, with a count when long), and the plugins it loads.
4. Define the guarantees: no ledger file is written; existing agent files are kept; no `git init` or staging inside an existing repository; a ledger that fails `bea check` still gets its files, and the report says what failed.
5. Record the contract in this task's Outcome and in `cli/docs/USAGE.md` beside `init --agent-files`.

## Acceptance criteria

- [ ] The command name, its inputs, what the generated file states, and the four guarantees are written down.

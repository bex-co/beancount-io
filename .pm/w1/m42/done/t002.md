## Objective

Implement t001's command so it writes `AGENTS.md` and the `@AGENTS.md` bridge for an existing ledger, describing that ledger as it actually is.

## Context

- `cli/src/cli/agent_guidance.py`: `AGENTS_TEMPLATE` and `write_agent_files(ledger, currency, accounts)`. The template assumes a fresh ledger: "today everything is in `{root}` itself" and an import-config block "recorded there when imports start".
- The template's text mirrors `skills/beancount-init/references/agents-template.md`; `cli/tests/test_init_agent_files.py` fails when the two drift.
- `cli/src/cli/commands/init.py` reports the result as `data.agent_files` in JSON mode.
- `bea doctor guidance`'s missing-file warning names "the beancount-init skill".

## Steps

1. Read the root's `include` closure, operating currencies, open accounts and plugin names through the engine's existing read paths, the same data `bea --json list` and `bea check` already produce.
2. Give the template the facts it needs for a multi-file ledger (the include layout and the destination rule) without changing what `bea init --agent-files` writes for a new single-file ledger. Keep the skill reference in step.
3. Create files exclusively, as `write_agent_files` does, and report `created`/`kept`/`skipped` in the JSON envelope.
4. Point `bea doctor guidance`'s missing-file warning at the new command.
5. Refuse with exit 2 and a clear message when the root cannot be determined; never write when the path is a directory.

## Files

- `cli/src/cli/agent_guidance.py`
- `cli/src/cli/commands/init.py` or `cli/src/cli/commands/doctor.py` (per t001)

- `cli/tests/`

## Acceptance criteria

- [x] On a ledger rooted at `books.beancount` that includes `2025/*.bean`, the generated `AGENTS.md` names `books.beancount`, the include layout and the destination rule, the operating currency and the open accounts.
- [x] Every ledger file's checksum is unchanged; an existing `AGENTS.md` and `CLAUDE.md` are byte-identical afterwards.
- [x] `bea init --agent-files` output for a new ledger is unchanged (existing tests pass), and the template drift test still passes.
- [x] `make check-all` passes in `cli/`.

## Out of scope

## Outcome — 2026-11-13

- **Engine:** `bea-engine describe --file ROOT` (`cli/src/bea_engine/describing.py`) loads the ledger once and answers its included files, operating currencies, open (not closed) accounts, plugins and errors. It never raises for ledger errors. Each plugin carries `loaded` and a `source`: `beancount` (a `beancount.*` module this Beancount lacks), `beside-ledger` (a module in the ledger's folder, which loads only through `PYTHONPATH`, since the engine ignores the working directory per w1/098), or `package`.
- **CLI:** `bea init --existing [PATH]` (`cli/src/cli/commands/init.py`). A folder uses `main.bean`, then `main.beancount`, then its one ledger file that no other file there includes. Several roots are refused with exit 2 naming them; new-ledger options are refused with exit 2. It writes `EXISTING_TEMPLATE` (`cli/src/cli/agent_guidance.py`) through the same exclusive-create pair writer `--agent-files` uses. `init` on an existing file now names `bea init --existing PATH`, and so does `bea doctor guidance`'s missing-`AGENTS.md` warning.
- **What `AGENTS.md` states:** the root and its included files (up to 10, then a count), the `--into` destination rule with an example from the ledger's own includes, currencies, open accounts (up to 30, then a count and the `bea list open` command), plugins (with the `PYTHONPATH=.` note and check command when a module sits beside the ledger), and the baseline. The baseline is a count of errors when every plugin was measured, and a count-free "it reported errors" when a beside-ledger plugin did not load, since its own findings were never counted.
- **Skill reference:** `skills/beancount-init/references/agents-template.md` gains the existing-ledger text; `test_the_existing_template_is_the_skills_template` fails on drift.
- **Docs:** `cli/docs/USAGE.md` "A ledger `bea` did not create" (its fence runs in `test_docs_examples.py` against the seeded ledger; later fence numbers shift by one), the `cli/README.md` command map, and the regenerated `cli/docs/REFERENCE.md`.
- **Tests:** `cli/tests/test_init_existing.py`, 14 cases: multi-file description with unchanged bytes and nothing but the two files added; folder resolution; two roots refused; default names win; file/dir/missing/empty refusals; new-ledger options refused; kept agent files byte for byte and idempotent JSON; a ledger with errors; a beside-ledger plugin without and with `PYTHONPATH=.`, where the written check command passes as written; the JSON fields; the `init` refusal hint; template drift. `tests/test_doctor_guidance.py` now asserts the new hint.
- **Checks:** `make check-all` (11,838 passed, 3 skipped on the full run; the one failure was the fence renumbering, fixed and rerun green: `test_docs_examples.py` 29 passed), and `python3 scripts/skills/ci-check.py`.
- **Deviation:** t001 chose `bea init --existing` over a `doctor` write mode. `bea doctor guidance` stays read-only and points at the new command.

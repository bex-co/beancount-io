## Objective

Turn `bea check`'s result on a ledger `bea` did not create into a short report a newcomer can act on: what loaded, what did not, and the one next step for each problem.

## Context

- `bea check` already reports a plugin that cannot be imported as `FILE:LINE: Cannot import plugin "NAME": CAUSE`, and one that raises as `Plugin "NAME" failed while running` (`cli/docs/USAGE.md`, the `check` section).
- Local plugin modules beside the ledger are found through `PYTHONPATH` handling in `cli/src/cli/engine/launch.py`.
- Whether a third-party package can be installed into the managed engine is the open decision [w5/015](../../w5/blocked/015.md); the report must quote its current answer, not invent a command.

## Steps

1. Group the check result: files loaded, plugins loaded, plugins that failed to import (local module vs. third-party package), and other errors by count.
2. Recognize the common Beancount v2 leftovers the v3 engine refuses (removed options and plugins), and name each with its `file:line`.
3. Give one next step per group. A missing third-party plugin package points at the documented answer of w5/015 as it stands; a local module points at running from the ledger's directory.
4. Emit it in text and in the JSON envelope, as part of t001's command or a flag on it.

## Files

- `cli/src/cli/` (the command chosen in t001)
- `cli/tests/`
- `cli/docs/USAGE.md`

## Acceptance criteria

- [x] A ledger with a plugin line naming a module that does not exist gets that plugin's `file:line` and one next step, and nothing is installed.
- [x] A ledger with a local plugin module beside it reports the plugin as loaded.
- [x] A clean ledger reports no problems and exits 0; the report never writes a file.

## Out of scope

- Fixing or rewriting v2 syntax.
- Deciding w5/015.

## Outcome — 2026-11-13

- **Report:** `cli/src/cli/existing_report.py` turns `bea-engine describe`'s answer into one item per problem, each with its `file:line` (relative to the ledger folder) and one next step. `bea init --existing` prints them under "Needs attention before an agent works on this ledger:", and `--json` carries them as `data.attention` (`kind`, `location`, `subject`, `message`, `next`).
- **Classes:** `plugin-not-in-beancount` (a `beancount.*` module this Beancount does not ship, which is how a Beancount 2 plugin dropped in Beancount 3 reads); `plugin-beside-ledger` (a module in the folder; next step is the `cd … && PYTHONPATH=. bea --file ROOT check` command); `plugin-package-missing` (states that no `bea` command installs third-party packages, which is the current state while [w5/015](../../../w5/blocked/015.md) is undecided, without inventing one); `plugin-failed` (imports, then raises); `option-unknown` (the engine's `Invalid option`, which is how removed Beancount 2 options such as `booking_algorithm`, `default_tolerance` or `tolerance` read; `describe` now returns them as `unknown_options`, reported once, not again as errors); then the remaining errors, five shown, with the check command for all.
- **Acceptance note:** a module beside the ledger is reported as loaded only when bea runs with `PYTHONPATH=.`, because the engine never imports from the working directory (w1/098). Without it, the report names the module and gives that exact command. The test runs both ways.
- **Docs:** `cli/docs/USAGE.md` lists the classes and the JSON fields.
- **Tests:** four new cases in `cli/tests/test_init_existing.py`: every class with its location and step, the unknown option not reported twice, nothing installed, ledger bytes unchanged; the text report's lines; a clean ledger with an empty `attention`; a plugin that raises. Removing the unknown-option pass fails two of them.

## Objective

Turn `bea check`'s result on a ledger `bea` did not create into a short report a newcomer can act on: what loaded, what did not, and the one next step for each problem.

## Context

- `bea check` already reports a plugin that cannot be imported as `FILE:LINE: Cannot import plugin "NAME": CAUSE`, and one that raises as `Plugin "NAME" failed while running` (`cli/docs/USAGE.md`, the `check` section).
- Local plugin modules beside the ledger are found through `PYTHONPATH` handling in `cli/src/cli/engine/launch.py`.
- Whether a third-party package can be installed into the managed engine is the open decision [w5/015](../../w5/blocked/015.md); the report must quote its current answer, not invent a command.

## Steps

1. Group the check result: files loaded, plugins loaded, plugins that failed to import (local module vs. third-party package), and other errors by count.
2. Recognize the common Beancount v2 leftovers the v3 engine refuses (removed options and plugins), and name each with its `file:line`.
3. Give one next step per group. A missing third-party plugin package points at the documented answer of w5/015 as it stands; a local module points at running from the ledger's directory.
4. Emit it in text and in the JSON envelope, as part of t001's command or a flag on it.

## Files

- `cli/src/cli/` (the command chosen in t001)
- `cli/tests/`
- `cli/docs/USAGE.md`

## Acceptance criteria

- [ ] A ledger with a plugin line naming a module that does not exist gets that plugin's `file:line` and one next step, and nothing is installed.
- [ ] A ledger with a local plugin module beside it reports the plugin as loaded.
- [ ] A clean ledger reports no problems and exits 0; the report never writes a file.

## Out of scope

- Fixing or rewriting v2 syntax.
- Deciding w5/015.

## Objective

Give `beancount-init` a branch for a folder that already holds a Beancount ledger: run t002's command and t003's report, and change no ledger file.

## Context

- `skills/beancount-init/SKILL.md` Step 1 hard-refuses when `main.bean`, `pyproject.toml` or a `Makefile` exists, and runs `git init` when there is no `.git/`.
- The shared execution contract is `skills/beancount-init/references/bea-cli.md`.
- Routing cases live in `scripts/skills/routing.json`; it already has near-misses for `beancount-migrate` and `beancount-add`.

## Steps

1. Before the refusal, detect an existing ledger: a `.bean`/`.beancount` root the user names, or the only candidate in the folder. Ask which file is the root when there are several.
2. On that branch: run t002's command and t003's report through `bea`, show the user what was written and what needs attention, and stop. Never create a new ledger beside an existing one; never `git init` inside an existing repository, never stage.
3. Keep the hard refusal for a request to create a new ledger where one already exists.
4. Update the skill's description so the existing-ledger prompt routes here, and add routing positives plus near-misses against `beancount-migrate` and `beancount-ask`.

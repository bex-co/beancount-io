# Malformed BEA_TOKEN is printed verbatim in cloud error output

Severity: major. Estimate: 45–60m with credential/output regression coverage.
Owner: CLI. A1: CI and agent transcripts must not expose the bearer credential
when a copied environment value contains a newline.

Reproduced twice at main `c6de619d9094e1ae45a248eef3e6ba3d74a5944f`, macOS
26.5.1 arm64, checkout `uv run bea` 0.1.0, Python 3.13.0, HTTPX 0.28.1.
Synthetic marker only, loopback target, no account. No actual secret was used,
recorded, or exposed. Stdin closed, no TTY; cwd `cli/`.

Minimal reproducer from `cli/`:

```python
import os, subprocess, tempfile, threading
from pathlib import Path
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer
class Handler(BaseHTTPRequestHandler):
    def log_message(self, *args): pass
    def do_GET(self):
        self.send_response(200)
        self.end_headers()
        self.wfile.write(b'null')
server = ThreadingHTTPServer(('127.0.0.1', 0), Handler)
threading.Thread(target=server.serve_forever, daemon=True).start()
try:
    with tempfile.TemporaryDirectory(dir='tmp') as directory:
        env = os.environ.copy()
        env.pop('BEA_FILE', None)
        env.update(BEA_TOKEN='qa-synthetic-sensitive-value\n',
                   BEA_API_URL=f'http://127.0.0.1:{server.server_port}',
                   BEA_CONFIG_DIR=str(Path(directory).resolve()),
                   XDG_CACHE_HOME=str(Path(directory).resolve()/'cache'),
                   BEA_NO_UPDATE_NOTIFIER='1')
        p = subprocess.run(['uv','run','bea','--json','cloud','status'],
                           env=env, stdin=subprocess.DEVNULL,
                           capture_output=True, text=True, timeout=10)
        print(p.returncode, p.stdout, p.stderr)
finally:
    server.shutdown()
    server.server_close()
```

Actual: exit 1, stdout empty, stderr JSON message contains
`LocalProtocolError: Illegal header value b'Bearer qa-synthetic-sensitive-value\n'`.
Removing `--json` leaks the same value in human stderr. Replacing status with
`cloud ledger create qa-20260909-token` under `--json` exits 4 and embeds the
same full marker in the unknown-outcome error. Neither malformed request reaches
the fixture handler; no mutation occurs. The marker minus its accidental newline
could represent an otherwise valid credential, so logs disclose useful material.

Control: same marker without newline reaches the loopback handler and the HTTP
200 `null` response produces an ordinary auth error with no token. A connection
refusal happens earlier and does not reproduce this issue: use a listening
loopback server as above.

Expected: reject invalid credential formatting with a safe sign-in/environment
configuration diagnostic before constructing an outbound Authorization header.
Neither human/JSON errors nor debug tracebacks may include the credential or its
escaped representation. Do not ask the user to paste their token to diagnose it.

Root cause: `cli/src/cli/auth/credentials.py:60` accepts BEA_TOKEN verbatim;
`cli/src/cli/api/client.py:32` passes it directly to AuthenticatedClient. Installed
`h11/_headers.py:166` raises `Illegal header value {!r}` with the full bytes,
HTTPX maps that into LocalProtocolError, and `cli/src/cli/errors.py:148` copies
`str(exc)` into user output. Writes leak separately through
`unknown_write_outcome` at `errors.py:163`. Validate environment and stored-token
values before transport, and keep credential-bearing exception text out of both
error paths. A safe validation error must not chain a secret-bearing exception
into `--debug` output. Avoid hand edits to generated clients.

Caller search: bearer_client is shared by cloud status, logout and
 authenticated_client; the latter serves list/show/create/delete/clone. Logout
swallows remote errors; status and create were actually exercised here. Stored
credentials use the same header construction but were not separately reproduced.
Regression coverage should assert synthetic marker absence in stdout/stderr in
human, JSON and debug modes and cover both read and write paths; preserve a
normal-token success/auth-failure control. No backend parity change required.

Dedupe: searched all open/completed `.pm` for token/credential disclosure,
redaction, LocalProtocolError and illegal headers; no open overlap. Targeted
history finds the generic error interpolation in `79341778`; no later repair.
This is distinct from w1/008 expiry validation, w1/009 HTTP response parsing,
and w1/010 missing timeouts: its trigger is local Authorization serialization.

Evidence: `cli/tmp/qa-20260909/cloud-loop/token-live-*.json`, `token-human.json`,
`token-create.json`, `token_sweep.py`. Loopback server stopped; only synthetic
child-process environment values existed. No real credential file or hosted
resource was touched. No fix or push performed.

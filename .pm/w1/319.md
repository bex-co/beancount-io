# `bea report cash-flow` says "No cash flows in this period." when no account counts as cash, so a ledger whose bank is `Assets:Revolut` or `Activos:Banco:Cuenta` reads as having moved no money

**Source:** routine cli-qa, 2026-11-19. **Severity:** minor. **Estimate:** 30–45 minutes. **Owner:** cli. **A1:** an agent asked "what was my cash flow in January?" runs `bea report cash-flow` on a ledger whose only bank account is `Assets:Revolut`. It gets exit 0 and `No cash flows in this period.`, with `Net change in cash: —`, `Opening cash: —` and `Closing cash: —`. Yet 3,000.00 USD of salary came into that account and 1,200.00 USD of rent went out. Nothing in the output says the real reason: no account matched the cash rule. So the agent reports "no cash movement" instead of asking the user to declare the account.

Found at `c429c59fe` with the checkout's `uv run bea` 0.4.1, Python 3.12.14, macOS 26.5.1. The run used an isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME` with `BEA_FILE`/`BEA_TOKEN` unset, stdin closed, stdout piped, and a synthetic ledger. Reproduced in fresh processes from a pristine copy. The ledger's hash was unchanged.

## Repro

```sh
cat > main.bean <<'EOF'

2026-01-01 open Assets:Revolut USD
2026-01-01 open Income:Salary USD
2026-01-01 open Expenses:Rent USD

bea --file main.bean report cash-flow               # exit 0
bea --json --file main.bean report cash-flow        # exit 0
bea --file main.bean report cash-flow --format csv  # exit 0
bea --file main.bean report income-statement        # control
```

## Actual

- Text (all on stdout, with nothing on stderr):

  ```text
  Cash Flow — 2026-01-15 through 2026-01-20
  Valuation: at_cost; account: all
  Row amounts are cash impact (positive for an inflow); opening/closing balances use Beancount signs (credits negative).
  No cash flows in this period.

    Net change in cash:  —
    Opening cash:        —
    Closing cash:        —
  ```

  When cash accounts exist, the report ends with a `Cash accounts: …` line. Here it prints none, so the empty cash set is never mentioned.
- JSON: `cash_accounts: []`, every section `[]`, and `net_change`, `opening` and `closing` all `{}`. No note or warning field.
- CSV: the header plus empty `net_change`, `opening` and `closing` rows.
- The same output comes from a ledger with renamed roots (`option "name_assets" "Activos"` and its siblings) whose bank is `Activos:Banco:Cuenta`. It also comes from any English ledger whose bank or wallet account is named after the institution, such as `Assets:Wise`, `Assets:Chase` or `Assets:PayPal`.
- Controls: the income statement shows Salary −3,000.00 and Rent 1,200.00 (net profit 1,800.00 USD), and the balance sheet shows `Assets:Revolut 1,800.00 USD`. With `cash-flow-role: "cash"` added under the `open`, the same command reports Operating Income:Salary 3,000.00 and Expenses:Rent −1,200.00, a net change of 1,800.00, opening cash 0.00 and closing cash 1,800.00, then `Cash accounts: Assets:Revolut`.

## Expected

The numbers are correct under the documented rule (USAGE § Reports: cash accounts are Assets accounts named like `Cash`, `Checking`, `Savings` or `Bank`, plus any account whose `open` declares `cash-flow-role: "cash"`). With no cash account, no transaction is cash activity. What is wrong is the explanation. When `cash_accounts` is empty, the text report should not claim "No cash flows in this period." It should say that no account counts as cash, give the rule, and give the remedy. For example:

```text
No account counts as cash: none is an Assets account named like Cash, Checking, Savings or Bank, and no open declares cash-flow-role: "cash". Add cash-flow-role: "cash" under the open of each bank or wallet account, then run the report again.
```

Put that sentence on stderr through `output.note`, as the invalid-role note already is, so stdout keeps the statement. The CSV path should print the same note on stderr. JSON already carries `cash_accounts: []`, which is enough for automation, so the envelope does not change. Exit 0 and every figure stay as they are. "No cash flows in this period." stays for a ledger that has cash accounts and a quiet window (`test_cash_flow_empty_period`).

`bea add open` takes no `--meta`, and an `open` that already exists cannot be added again. So the remedy is a hand edit of the existing `open` line, and the message should not point at a `bea` command that cannot do it.

## Root cause

`cli/src/cli/commands/report.py`, `cash_flow`:

- Lines 899–900 print `No cash flows in this period.` whenever all three sections are empty, without checking whether `data["cash_accounts"]` is empty.
- Lines 922–924 print `Cash accounts: …` only `if cash_accounts:`, so an empty set produces no line at all.

The engine is right. `_cash_accounts` (`cli/src/bea_engine/report.py:1578`) applies `_CASH_EQUIVALENT_PATTERNS` (`:1530`) and the declared roles, as the dashboard does (ADR003, ADR023). The behavior dates from the report's introduction (`adcfad785`). It is not a regression.

## Fix

In `cash_flow` (`commands/report.py`), when `data["cash_accounts"]` is empty, emit the note above through `output.note` before the CSV branch returns, so text and CSV both get it, and do not print `No cash flows in this period.` on stdout. Keep that line when cash accounts exist. Document the note in `cli/docs/USAGE.md` beside "Cash accounts are the Assets accounts named like cash". In `cli/tests/test_report_cash_flow_frontend.py`, update `test_cash_flow_without_cash_accounts`, which today asserts the misleading line, so that it asserts the note on stderr and neither the note nor `No cash flows in this period.` on stdout. Add cases for a named-after-the-bank account (`Assets:Revolut`), for the renamed-roots ledger, and for CSV. Keep `test_cash_flow_empty_period` (cash accounts present, quiet window) unchanged, and keep the declared-role control. Run `make check-all` in `cli/`.

## Blast radius

The cash-flow statement is computed only in `bea_engine/report.py::_cash_flow` for `bea`. No REST, GraphQL or MCP cash-flow statement exists: `backend-cluster/backend-v2/src` only carries `open` metadata for the dashboard. So there is no hosted parity to keep. The dashboard computes its statement client-side and has the same gap. For this ledger `dashboard/src/features/reports/cash-flow/index.tsx:245–253` shows `No cash flow data found for this ledger.` (`page.cashFlow.noData`). That is another package, so file it separately if wanted. The customer skills `beancount-business-metrics` and `beancount-report-pack` read `cash_accounts` and already tell the user to confirm the perimeter, so they do not need a change.

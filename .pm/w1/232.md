# A plaintext-journal page past the first fails bean-check on its own

**Bug · ledger (or docs) · minor · ~45m (or ~5m doc-only) · A1.** From `/qa-find-bugs-mcp`, 2026-11-10, production `beancount-mcp 1.0.0`, read-only on the public example ledger.

- **Repro:**
  - Read `beancount://<o>/<n>/plaintext-journal?limit=200&offset=K` for each offset 0, 200 … 1000, and run `bea check` on each page's `content`.
    - Offset 0 is valid.
    - Offset 200 has 17 errors ("Balance failed for 'Assets:US:BofA:Checking'…"), and offset 400 has 12 ("No position matches Posting(…VHT…)").
    - The remaining pages have 17, 15 and 8 errors.
  - `time=2016&limit=100&offset=100` also gives 6 lot errors.
  - **Controls:** all six pages concatenated under one header are valid and match the source exactly. `time=2016&limit=1000` and `account=…&limit=1000` are valid.
- **Expected:** `docs/mcp.md:972-975` says "Every page keeps the ledger's option header, so each one loads on its own". An agent that pages a large ledger and checks or imports one page gets assertion and lot failures that are not in the ledger.
- **Cause:**
  - `backend-cluster/ledger/src/features/ledger/service/ledger-journal-service.ts:950-957` slices the export by offset, and nothing carries the state from before the page.
  - The time-window path keeps the clamp's `S` opening summaries for exactly this reason (`plaintextExportDirectives`, `:296-322`); offset paging has no equivalent.
  - `plaintext-journal-paging.test.ts:79` checks only that the header is present.
- **Fix:** do one of the following.
  - For `offset > 0`, prepend `S` opening-summary entries carrying every account's balance and open lots as of the day before the page's first entry, reusing the clamp's summarizer.
  - Change the doc and the code comment to "each page parses on its own; balance assertions and lot reductions validate only across the whole export".
- **Check:** add a paging test that loads a non-first page containing an assertion and a lot reduction. REST, GraphQL and MCP share the export.

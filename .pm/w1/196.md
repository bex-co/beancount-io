# Stateless MCP endpoint advertises `listChanged: true`

**Spec accuracy · backend-v2 (MCP) · trivial · ~15m · A1.** From `/qa-find-bugs-mcp`, 2026-11-08, production `beancount-mcp 1.0.0`, every negotiated protocol version.

- **What happens:** `initialize` returns `capabilities.{tools,resources,prompts}.listChanged: true`. The endpoint is POST-only and stateless: an authenticated `GET` returns 405 and there is no session, so it can never send `notifications/*/list_changed`. A client may wait for change notifications instead of listing again.
- **Cause:** the SDK's `McpServer` sets the flag when tools, resources and prompts are registered (`@modelcontextprotocol/sdk` 1.30.0, `server/mcp.js:64,341,405`). `composition-root.ts:528` builds the server, and `:920` reports `getCapabilities()` unchanged.
- **Fix:** advertise `listChanged: false`, or omit the key, after registration. Pin it in the `initialize` / `mcp-route-methods` test. No REST or GraphQL counterpart.
- **Dedupe:** w3/m5/t004, w3/m7/t003 and w2/m27/t004 put list-changed notifications out of scope for this endpoint. None of them corrects the flag.

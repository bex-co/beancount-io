# BQL `FROM … CLEAR` is accepted and silently ignored

**Bug · ledger · major · ~30m · A1.** From `/qa-find-bugs-mcp`, 2026-11-08, production `beancount-mcp 1.0.0`, read-only.

- **Repro:**
  - `runBqlQueryStructured` `SELECT account, sum(position) FROM CLOSE ON 2026-08-01 CLEAR GROUP BY account` keeps the Income and Expenses balances and has no `Equity:Earnings:Current` row.
  - Stock beanquery on the same file zeroes those accounts and adds `Equity:Earnings:Current`.
  - REST `POST …/query` shares the engine and returns the same wrong result. A balance-sheet-as-of query gets wrong numbers with no error.
- **Cause:** rustledger 0.24.0 parses `CLEAR` and does nothing with it. The ledger service does not handle it either; it appears only in the `bql-complexity.ts:82` keyword list.
- **Fix (ledger):** refuse `CLEAR` with `BAD_USER_INPUT` and a workaround hint, as `ledger-shell-service.ts:272` already does for `BALANCES FROM`. Document it next to "FROM OPEN ON is suffix-only" in the ledger README, and report it upstream along with the w23/022 batch.
- **Check:** a test asserts the refusal on REST, GraphQL and MCP. Queries without `CLEAR` are unchanged.

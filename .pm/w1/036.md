# Invalid MCP resource URI parameters escape as internal errors without codes or hints

**Severity:** minor. **Estimate:** 35–50 minutes including transport regression coverage. **Owner:** backend-v2. **A1 — Agent-native accounting:** malformed resource URIs should tell an agent to correct the request; classifying them as internal errors instead suggests retries and loses the documented recovery hint.

Found 2026-09-21 (America/Los_Angeles), real `https://beancount.io/api-gateway/mcp` requests. Checkout: `main` at `432af8f51cba834e2df09674ab9f498bbf80103c`, Node 22.17.1. Server reports `beancount-mcp 1.0.0`, protocol `2025-11-25`; deployed revision is unavailable. Credential: a temporary `ledger.read` API key pinned to the dedicated synthetic `mcp-agent-eval` ledger. Both reproduced in fresh requests. HTTP 200, `Content-Type: text/event-stream`; the first returns:

```json
{"jsonrpc":"2.0","id":1,"error":{"code":-32603,"message":"Unknown or repeated resource parameter: unknown"}}
```

The duplicate case has the same shape and names `time`. Also reproduced:

- `beancount://qa-owner/mcp-agent-eval/errors#qa` → `-32603`, `Resource fragments are not supported`.
- `beancount://qa-owner/mcp-agent-eval/files/%E0%A4` → `-32603`, `Invalid URI encoding in resource path`.

Every response lacks `error.data`. Expected: JSON-RPC `-32602`, `data.code:"BAD_USER_INPUT"`, the specific message, and a useful hint, as promised by `docs/mcp.md`. Preserve rejection of these inputs; do not silently accept or drop malformed parameters.

## Working controls and root cause

- `trial-balance?time=2026-08` succeeds. `trial-balance?time=2026-02-30` correctly returns `-32602` with `data.code:"BAD_USER_INPUT"` and a hint. `journal?directiveTypes=Transaction` also gives the coded input error. These failures occur after URI matching.
- The same credential's REST `GET /api-gateway/v1/ledgers/qa-owner/mcp-agent-eval/trial-balance?time=2026&time=2025` returns HTTP 400, `error.code:"VALIDATION_FAILED"`, naming `query.time`. The valid August REST read succeeds. No write is needed for any reproduction.
- `src/features/ai-agent/api/mcp-resource-template.ts:23` implements `QueryResourceTemplate.match`. Lines 35, 38 and 41 throw `BadUserInputError` for the three reproduced classes of malformed URI.
- The SDK calls `uriTemplate.match` before invoking the registered resource callback (`@modelcontextprotocol/sdk` 1.30.0, `dist/cjs/server/mcp.js:391`). Therefore `makeMcpResourceHandler`'s try/catch (`src/server/api/composition-root.ts:673`) cannot translate these errors.
- The SDK protocol serializer (`dist/cjs/shared/protocol.js:402`) falls back to `InternalError` unless the thrown error supplies a numeric JSON-RPC code. A domain `BadUserInputError` is not the transport-shaped `McpRequestFailure`; its category and hint never reach the response.

Translate the matcher's known input failures into the existing `McpRequestFailure`/`envelopeFromThrown` representation at the MCP URI boundary, before the SDK sees them. Keep genuinely nonmatching templates returning `null` so the final unknown-resource handler still answers `NOT_FOUND`. This shared matcher is used by the descriptor-derived resource templates across reports, journals, catalog, files and other resource families; do not fix just trial balance. REST's validation semantics already work and must remain intact; GraphQL has no resource-URI grammar to change.

## Objective

## Result

2026-10-06. The ledger step of `/oauth/consent` shows a "Who is asking" section: where the code goes (the redirect host, or scheme plus host for an app scheme such as `cursor://anysphere.cursor-mcp`), the app's name labelled as its own claim (or that it gave none), the vouching domain for a CIMD client, and a warning when every redirect is this computer. Approve stays disabled until the requester is identified; if it cannot be (expired interaction), the page says so. oidc-provider scopes the interaction cookie to `/oauth/consent`, so the page reads the details through a new server-only route, `GET /oauth/consent/requester` (`src/routes/oauth.consent_.requester.ts`), which forwards the cookie to the backend endpoint from t004 — this works for SSR and for the client-side return from `/auth/welcome`. Copy in all 15 locales. Tests: mapper and handler units (cookie forwarding, 404 on unknown or unreachable), page tests for each display case and the disabled-approval case. Dashboard gate green (format, lint, 452 test files, build); route smoke-tested on the built server.

# Malformed stored CLI expiry bypasses auth recovery

Severity: minor. Estimate: 35–50m including regression coverage. Owner: CLI.
A1/A2: agents and users should receive an actionable sign-in error when local
session state is invalid.

Reproduced twice at main `c6de619d9094e1ae45a248eef3e6ba3d74a5944f`, macOS
26.5.1 arm64, checkout `uv run bea` 0.1.0, Python 3.13.0. No server or real
account involved. Cwd: `cli/`; stdin closed, no TTY, stdout empty.

Minimal synthetic reproducer, run from `cli/`:

```python
import json, os, pathlib, subprocess, tempfile
with tempfile.TemporaryDirectory(dir='tmp') as directory:
    config = pathlib.Path(directory).resolve()
    env = os.environ.copy()
    for name in ('BEA_TOKEN', 'BEA_FILE'):
        env.pop(name, None)
    env.update(BEA_CONFIG_DIR=str(config), XDG_CACHE_HOME=str(config/'cache'),
               BEA_NO_UPDATE_NOTIFIER='1')
    path = config/'credentials.json'
    path.write_text(json.dumps({'token': 'synthetic-invalid',
                                'expireAt': '2000-01-01T00:00:00'}))
    result = subprocess.run(['uv', 'run', 'bea', '--json', 'cloud', 'status'],
                            env=env, stdin=subprocess.DEVNULL,
                            capture_output=True, text=True, timeout=10)
    print(result.returncode, result.stdout, result.stderr)
```

Actual: exit 1, JSON stderr category `validation`, message
`can't compare offset-naive and offset-aware datetimes`. Numeric or list
`expireAt` values instead produce `fromisoformat: argument must be str`.
Credential bytes stay unchanged. Expected: exit 3 with sign-in recovery guidance,
as for an invalid date string or expired session. Controls: `expireAt: "bad"`
and `2000-01-01T00:00:00Z` both exit 3 with `Session expired` and login guidance.

Root cause: `cli/src/cli/auth/credentials.py:65` hydrates unvalidated JSON into a
dataclass; `is_expired` at line 28 compares a naive datetime with aware UTC and
catches only ValueError. Reject invalid types and timezone-free stored expiry
before comparison; do not treat malformed state as a valid indefinite session.
Preserve the separate environment-token unknown-expiry behavior.

Caller search: `cloud status`, `authenticated_client` (list/show/create/clone/
delete), and `ask` call `require_credentials`. Logout uses `load_credentials`
directly and is outside the expiry comparison. Other commands were not live
reproduced for this finding; no server-produced malformed expiry is claimed.
Add focused malformed-state and valid timezone-aware controls, plus real CLI
exit/output assertions. Run CLI native checks after repair.

Dedupe: all open/completed `.pm` searched for expiry, malformed credentials,
fromisoformat and offset-naive; no matching open item. Targeted history traces
this comparison to `183bf3b0`; no later repair found. This is separate from
mobile OAuth and dashboard session-expiry copy findings.

Evidence: `cli/tmp/qa-20260909/cloud-loop/credential-*.json` and
`credentials_sweep.py`; the public reproducer above needs neither. Disposable
credential removed. No fix implemented, no hosted resources changed.

# `bea init --opening-balance 'Assets:Checking 1000 eur'` says "Use --currency eur", and doing that gets the same refusal: `--currency` reads `eur` as EUR, the opening balance's currency is compared as typed

**Bug · cli · minor · 30–45m · A2.** From routine cli-qa, 2026-11-23. `bea init` accepts `--currency eur` and writes `option "operating_currency" "EUR"`: the flag is stripped and upper-cased. An `--opening-balance` that states its currency (`ACCOUNT NUMBER CUR`, accepted since w1/262) is compared to that currency exactly as typed. A lowercase `eur` is refused, and the refusal tells the user to pass `--currency eur`, which is the value they already passed, or which they then pass and get refused the same way. Both remedies the two messages offer lead back to a refusal, so a newcomer following the CLI's own advice cannot create the ledger with that value.

Environment: main `40e22400b`, `bea 0.5.0` from the checkout (`uv run bea`), Python 3.12.14, macOS 26.5.1. Isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, `BEA_FILE`/`BEA_TOKEN` unset, stdin closed, no TTY, fresh processes in an empty scratch folder. Reproduced twice.

## Repro

```sh
bea --no-input init b2 --date 2026-02-01 --opening-balance 'Assets:Checking 1000.50 eur'
bea --no-input init b2 --currency eur --date 2026-02-01 --opening-balance 'Assets:Checking 1000.50 eur'
bea --no-input init b2 --currency usd --date 2026-02-01 --opening-balance 'Assets:Checking 1000.50 usd'
bea --no-input init b2 --currency usd --date 2026-02-01        # control
```

## Actual

1. Exit 2: `--opening-balance 'Assets:Checking 1000.50 eur': Give the amount without a currency ('ACCOUNT NUMBER'); it is in the operating currency. To write 'eur', also pass --currency eur.`
2. Doing that, exit 2: `… Opening balances are in the operating currency EUR, not eur. Use --currency eur, or give the amount in EUR.`
3. Same with `usd`: `… in the operating currency USD, not usd. Use --currency usd, or give the amount in USD.` Nothing is created in any case.
4. Control: `--currency usd` alone creates `b2/main.bean` with `option "operating_currency" "USD"`, exit 0. `--opening-balance 'Assets:Checking 1000.50 USD'` with `--currency usd` also succeeds.

## Expected

One command reads a currency one way. `--opening-balance`'s optional currency is accepted in every spelling `--currency` accepts (surrounding spaces, any letter case), so cases 2 and 3 create the ledger with `Assets:Checking 1000.50 EUR` / `USD`, and case 1 names `--currency EUR`. When the stated currency really differs (`1000 GBP` under `--currency EUR`), the refusal still names both, and every remedy it prints is one that works when pasted. Basis: `cli/docs/USAGE.md` ("Creating a ledger": `ACCOUNT NUMBER CUR` is accepted when `CUR` is that `--currency`), and w5/693, which made `--currency` trim and upper-case its value.

## Cause

`cli/src/cli/commands/init.py:72` (`_currency`) normalizes `--currency` with `value.strip().upper()`. `_opening_balance_parts` (`:249`) splits the opening balance and compares `parts[2] != currency` at `:266` against the normalized value, so `eur` never equals `EUR`. Both hints interpolate the raw `parts[2]` into a `--currency` suggestion (`:264`, `:269`).

## Fix

Owned by `cli`, `init.py` only. Normalize the stated currency the way `_currency` does before comparing (reuse `_currency`, so a reserved word or malformed symbol is still refused with its own message), and print the normalized symbol in both hints. Add cases to `cli/tests/test_init_opening_balance_messages.py` through real `bea` subprocesses: the three repros (the second and third create a ledger whose opening transaction reads `EUR` / `USD`, and the first suggests `--currency EUR`), a genuine mismatch (`1000 GBP` under `--currency EUR`) still refused, and `Assets:Checking 1000` unchanged. Revert the fix and watch them fail. Run `make check-all` in `cli/`.

## Adjacent

The interactive prompt (`Checking opening balance on … [0]:`) takes a number only. Typing `1,000.50 usd` there is refused with the comma-grouping message ("A comma is read only as a thousands separator between groups of three digits … remove the separators"), though `1,000.50` is valid grouping and the problem is the trailing currency; `1,000.50` alone is accepted. `cli/src/cli/amounts.py:56` (`parse_decimal_number`) picks the comma message for any unparseable text containing a comma. Worth fixing alongside if it stays cheap: say the prompt takes a number in the operating currency.

## Dedupe

Searched `.pm/**` for `Use --currency`, `also pass --currency`, `Opening balances are in the operating currency`, `opening-balance` with `lowercase`. w1/262 (done, `e91f570c0`) introduced these two messages and tested only an uppercase different currency. w5/693 (done) added the upper-casing to `--currency`. Neither covers a lowercase stated currency. `git log -S'also pass --currency' -- cli/src` shows only `e91f570c0`.

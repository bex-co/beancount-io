# A Beancount 2 ledger's `plugin "beancount.plugins.forecast"` is told to remove the line or find a Beancount 3 replacement, though `bea` bundles the drop-in `fava.plugins.forecast`; removing it books the template as a real payment

**Bug · cli · minor · 30–45m · A2.** From routine cli-qa, 2026-11-23. `bea` bundles `fava.plugins.forecast`, which its own docstring calls a reimplementation "drop-in compatible" with the `beancount.plugins.forecast` plugin Beancount 2 shipped (`cli/src/fava/plugins/forecast.py`). Its tests, import dedupe and `list --on-disk` all handle it. A user who brings a Beancount 2 or Fava ledger with the old plugin line is never told about it. `bea init --existing`, the m42 entry point for an existing ledger, says to remove the line or replace it with "a Beancount 3 plugin that does the same". No Beancount 3 plugin does. `bea check` and every read say "Check the name is spelled right and the plugin is installed", but the name is spelled right and there is nothing to install. Following the first remedy is worse than leaving the error. The `#`-flagged template stays a single real transaction, its marker stays in the narration, its projections disappear, and the balances it should have produced change without an error. Nothing is written by the repro (hash unchanged).

Environment: main `86c4abf04`, `bea 0.5.0` from the checkout (`uv run bea`), managed engine 0.5.0 (Beancount 3.2.3), macOS 26.5.1. Isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, `BEA_FILE`/`BEA_TOKEN` unset, stdin closed, no TTY, scratch cwd, fresh processes.

## Repro

```sh
mkdir books
cat > books/main.bean <<'EOF'
option "operating_currency" "USD"
plugin "beancount.plugins.forecast"
2026-01-01 open Assets:Checking USD
2026-01-01 open Expenses:Electricity USD
2026-01-01 open Equity:Opening USD
2026-01-02 * "Opening"
  Assets:Checking  1000.00 USD
  Equity:Opening
2026-03-08 # "Electricity bill [MONTHLY REPEAT 3 TIMES]"
  Expenses:Electricity   50.10 USD
  Assets:Checking
EOF
bea --no-input init --existing books/main.bean
bea --file books/main.bean check
# the two remedies, on copies
sed 's/beancount.plugins.forecast/fava.plugins.forecast/' books/main.bean > fava.bean
sed '/beancount.plugins.forecast/d' books/main.bean > removed.bean
bea --file fava.bean balance Checking -t 2026
bea --file removed.bean balance Checking -t 2026
```

## Actual

- `init --existing` exits 0 and prints, as `--json` does under `data.attention` (`kind: plugin-not-in-beancount`): `main.bean:2: Plugin `beancount.plugins.forecast` is not part of Beancount 3.2.3; Beancount 2 shipped plugins that Beancount 3 dropped.` / `Next: Remove the plugin line, or replace it with a Beancount 3 plugin that does the same.`
- `bea check` exits 1: `main.bean:2: Cannot import plugin "beancount.plugins.forecast": ModuleNotFoundError: No module named 'beancount.plugins.forecast'. Check the name is spelled right and the plugin is installed.` Every report, `--json check` and the write refusal carry the same sentence.
- With `fava.plugins.forecast`: `bea check` passes, `list transaction` shows the template plus two `generated` projections (2026-04-08, 2026-05-08), and Checking reads **849.70 USD**, as Beancount 2 computed it.
- With the line removed, as `init --existing` advises: `bea check` passes. `list transaction` shows one `#` row whose narration keeps `[MONTHLY REPEAT 3 TIMES]`, and Checking reads **949.90 USD**. `--allow-errors` reads on the original give the same 949.90.

## Expected

For `beancount.plugins.forecast`, both remedies name the bundled replacement. `init --existing`: `Plugin `beancount.plugins.forecast` was dropped in Beancount 3; bea bundles a drop-in replacement.` / `Next: change the line to plugin "fava.plugins.forecast".` `bea check` and every read: `… Beancount 3 dropped this plugin; bea bundles a drop-in replacement: plugin "fava.plugins.forecast".` Following either one leaves a ledger that `bea check` passes, with the projections back. Other dropped `beancount.plugins.*` names keep today's text. Basis: the bundled module's own compatibility claim, and the rule that a hint must name a command that works (w1/359, w1/361).

## Cause

- `attention` (`cli/src/cli/existing_report.py:36`) gives every `source == "beancount"` plugin that did not load one message and one next step (`:38`–`:41`). That branch has no list of replacements.
- `_import_hint` (`cli/src/bea_engine/query.py:3726`) returns `Check the name is spelled right and the plugin is installed.` (`:3737`, `:3740`) for any import failure that is not a module beside the ledger.
- `docs/skills/existing-ledger.md:66` gives the same "remove or replace that `plugin` line" advice.

## Fix

Owned by `cli` (plus the one guide line in `docs/skills/existing-ledger.md`). Keep a small map in the engine of Beancount 2 plugins that `bea` bundles a replacement for: today only `beancount.plugins.forecast` → `fava.plugins.forecast`. Use it in `_import_hint` and in `existing_report.attention`, which `describe` can feed with a `replacement` field on the plugin. Keep the other dropped names unchanged. Regression tests through real `bea` subprocesses on the repro: `init --existing` text and `--json` name `fava.plugins.forecast`; `check` names it; applying the named edit makes `bea check` pass and Checking read 849.70 USD. A misspelled `beancount.plugins.forcast` and a dropped `beancount.plugins.unrealized` keep today's wording. Revert the fix and watch the new tests fail. Run `make check-all` in `cli/` and `python3 scripts/skills/ci-check.py` for the guide. No REST, GraphQL or MCP surface prints these hints. Whether the hosted ledger service runs `fava.plugins.forecast` is a separate question, not checked here.

## Blast radius

The `_import_hint` sentence reaches `bea check`, `--json check`, every report and list, write refusals, and `doctor` operations that load the ledger (`doctor print-options` checked). The attention list is printed by `init --existing` and returned in its `--json` `data.attention`. The `AGENTS.md` it writes lists only the plugin name. Searched the bundled set (`cli/src/fava/plugins/`: `forecast`, `amortize_over`, `link_documents`, `tag_discovered_documents`) against Beancount 2's `beancount.plugins` modules that Beancount 3.2.3 no longer ships. `forecast` is the only one with a bundled replacement. Adjacent and not changed here: the `option-unknown` step "replace it with its Beancount 3 name" does not name the new name either (`option "default_tolerance"` is now `inferred_tolerance_default`). That rename is unverified, so it is left out of this note.

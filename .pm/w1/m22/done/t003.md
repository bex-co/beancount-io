## Objective

Allow a user to redirect a query to a file and return to terminal output in the same session.

## Context

In pinned Beanquery 0.2.0, `.output scratch.txt`, `SELECT 1;`, `.output` raises TypeError instead of restoring stdout. Upstream beanquery/shell.py:352 calls open(sys.stdout), after closing the selected file. Both bea and native bean-query reproduce; this is inherited upstream, not a bea-only regression. bea inherits do_output in cli/src/bea_engine/query.py.

## Steps

1. Check for a verified upstream correction; use a compatible upstream version if available, regenerating dependency locks through their owning tools.
2. If no usable upstream release exists, make the smallest engine-side compatibility correction around the broken handler, with rationale and removal condition; do not fork or reimplement the shell.
3. Exercise redirect → query → reset → query in a real PTY with isolated history/init paths, including repeated reset and clean exit. Do not modify the user’s HOME or history.

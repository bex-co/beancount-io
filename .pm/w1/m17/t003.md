## Objective

Turn the docs' examples into tests so a flag rename or behavior change cannot leave a stale example behind.

## Context

- `cli/tests/test_contract.py` and `cli/tests/test_customer_workflows.py` already run scripted flows against fixture ledgers; the review found the README quick start and the IMPORTING walkthrough pass today only because someone ran them by hand.
- Convention to adopt: a fenced block tagged ```` ```bash ```` is runnable in order within its document; a block tagged ```` ```bash norun ```` is illustrative and must carry a comment saying why (needs credentials, a browser, or network).

## Steps

1. Write a small extractor that reads README, USAGE, IMPORTING, and TUTORIAL, collects `bash` fences in order, and runs them in a temporary directory with `bea` on PATH from the test environment and `BEA_NO_UPDATE_NOTIFIER=1`.
2. Where a document states an expected result ("The purchase leaves 987.50 USD in checking"), assert it in a per-document expectations table kept next to the test, not in the doc.
3. Tag cloud, ask, upgrade, and completion examples `norun` with reasons.
4. Run the extractor as a pytest module so it is part of `make test`.

## Files

- `cli/tests/test_docs_examples.py` (new)
- `cli/README.md`, `cli/docs/USAGE.md`, `cli/docs/IMPORTING.md` (fence tags only)

## Acceptance criteria

- [ ] Breaking the quick start (for example renaming `--opening-balance`) fails `make test` with the document and line.
- [ ] Every `norun` fence has a reason comment.

## Out of scope

- Running examples against the hosted service.

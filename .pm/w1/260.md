# `bea report register PARENT` hides which subaccount a row posted to when the rows come from one account

Found by `/qa-find-bugs-cli w1` on 2026-11-15 (HEAD `1688ea689`, `bea 0.3.1`, macOS 26.5, checkout `uv run bea`, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, synthetic ledger). Severity: minor. A1: an agent or user reading a register for a parent account cannot tell which child account a posting hit. The heading names the parent, so the row reads as a posting to the parent itself.

**Repro** (synthetic):

```sh
cat > main.bean <<'EOF'
2026-01-01 open Assets:Checking USD
2026-01-01 open Expenses:Food
2026-01-01 open Expenses:Food:Dining

2026-01-02 * "Opening"
  Assets:Checking 100.00 USD
  Expenses:Food -100.00 USD

2026-02-10 * "Bistro"
  Expenses:Food:Dining 50.00 USD
  Assets:Checking
EOF
bea --file main.bean report register Expenses:Food              # ACCOUNT column shown (two accounts)
bea --file main.bean report register Expenses:Food -t 2026-02   # ACCOUNT column hidden
bea --file main.bean report register Expenses -t 2026-02        # ACCOUNT column hidden
```

**Actual.** Both windowed runs exit 0 and print `account: Expenses:Food` (or `account: Expenses`) above `DATE  DESCRIPTION  AMOUNT  COST  BALANCE`, with the one row `2026-02-10  Bistro  50.00 USD`. Nothing says the posting went to `Expenses:Food:Dining`. `--json` and `--format csv` do carry `account: Expenses:Food:Dining`. The full-range run shows the ACCOUNT column only because the rows happen to span two accounts.

**Root cause.** `cli/src/cli/commands/report.py` `register()` (about line 681) sets `show_account = len({row["account"] ...}) > 1`. It hides the column whenever the rows share one account, even when that account is a descendant of the requested one rather than the account itself. That rule dates from `f7b3034b2` ("its ACCOUNT column appears only across accounts").

**Fix (cli only, local text rendering).** Show the ACCOUNT column whenever any non-closing row's account differs from the requested account. The requested account comes from `data["account"]` and is matched case-insensitively, as the filter is: `register expenses:food` matches. A register whose rows all sit on the requested account itself keeps today's compact table. JSON and CSV are unchanged.

**Done when** both windowed repro commands print an ACCOUNT column naming `Expenses:Food:Dining`, `bea report register Assets:Checking -t 2026-02` still prints no ACCOUNT column, and a regression test in the register tests covers both. The test fails with the fix reverted.

**Dedupe.** Searched `.pm/**` for `register` with `account column`/`ACCOUNT` and `show_account`. w1/252 (valuation per row) and the other register items are done and none covers the column rule. No open item.

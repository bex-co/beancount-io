# Bank tools take each row's `id`, but their text sends agents to `itemId`/`accountId`

**Bug · backend-v2 · major · ~45m · A1.** From `/qa-find-bugs-mcp`, 2026-11-10. The cause is verified from source and from dashboard usage. A live repro is unverified, because the QA account has no linked bank.

This breaks the bank flow on tools-only hosts (ADR 019 D7). An agent copies the field the text names, gets `NOT_FOUND` "Bank connection not found", and the hint sends it back to the same field.

- **What `listBankConnections` returns:** connections `{id:"pitm_…", itemId:<Plaid item id>, …}` and accounts `{id:"pacc_…", plaidItemId, accountId:<Plaid account id>, …}` (`plaid-item-service.ts:1222-1275`).
- **What the tools look up:** the row `id`.
  - `syncBankTransactions` and `reconcileBankAccounts` call `plaidItem.getById(itemId)` (`plaid-sync-service.ts:295,325`).
  - `mapBankAccount` and `setBankAccountCurrency` call `plaidAccount.getById(accountId)` (`plaid-item-service.ts:299`).
  - The dashboard passes `itemId: item.id` (`use-plaid-accounts.ts:187`, `bank-item.tsx:68`).
- **Every MCP text names the wrong field:**
  - the `listBankConnections` description ("connections (item_id) and their accounts (account_id), the ids the … tools take")
  - `BANK_NOT_FOUND_HINT` ("Use the `item_id` and `account_id` that `listBankConnections` returns")
  - `BANK_CONNECTION_NOT_FOUND_HINT`
  - the categorize-imports prompt ("Syncing needs the bank's `item_id`")
  - `docs/mcp.md:326`
- **Why the test missed it:** `tools-only-journey.test.ts` passes only because its mocks omit the real `itemId`/`accountId` fields. Its discard step also passes staged `t.id`, while the service matches `transactionId`.
- **Fix:**
  - Name the row id everywhere: "the connection's `id` (not its `itemId`)" and "the account's `id` (not its `accountId`)".
  - Better still, also accept the external ids and resolve them to the row.
  - Give the tools-only journey realistic fixtures: `id` plus `itemId`/`accountId`, and `transactionId` on staged rows.

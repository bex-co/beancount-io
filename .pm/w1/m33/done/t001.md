## Objective

A tools-only host cannot discover the connection or account ids every `manageBankConnection` operation and `manageBankImport` `sync` require; add a read-only tool listing connections with their accounts, over the same service call and authorization as the `banks` / `bank-accounts` resources.

## Context

- backend-cluster/backend-v2/src/features/ai-agent/api/mcp-tools.ts (`VERB_TABLE`)
- backend-cluster/backend-v2/src/features/ai-agent/api/mcp-resources.ts (`bankList`, `bankAccounts`, `bankAccountsForItem`)
- Repo rule: REST, GraphQL, and MCP parity — confirm the REST and GraphQL twins of this read already exist in the parity registry, or add them in the same change.

## Steps

1. Add the tool, annotated read-only, wrapping the resource's service call.
2. Register it in the parity registry; run the parity gate.

## Files

- backend-cluster/backend-v2/src/features/ai-agent/api/mcp-tools.ts

## Acceptance criteria

- [x] The tool returns the same data and enforces the same authorization as its resource twin.
- [x] The parity gate stays at zero gaps.

## Out of scope

- Changing the resources.

## Result

2026-10-06. `listBankConnections` (new `src/features/ai-agent/api/mcp-list-tools.ts`) returns `{ connections, accounts }` from `plaidItem.getItems` and `plaidItem.getAccountsForLedger` — the `banks` and `bank-accounts` resources' own calls, authorized by the same services. It sits on both verb rows (`Query.getPlaidItems`, `Query.getPlaidAccountsForLedger`) beside their REST and GraphQL twins, replacing the rows' `mcpExempt` reasons; the zero-gap parity gate passes. `tools/list` budgets: 28 tools; size gate 64 → 66 KB (the tool measures 1.2 KB after trimming its description), both with rationale in the tests. Tests in `mcp-list-tools.test.ts`: output equals the two resource reads, the service sees the caller's identity and ledger, and a service refusal is a tool error.

**Deviation from ADR 019 D7 ("annotated read-only"):** both verbs are `admin`-class, and the annotation guard (w2/m27) keeps `readOnlyHint: true` for `read`-class verbs because hosts auto-approve read-only tools. The tool uses a new `ADMIN_READ` preset — not destructive, idempotent, `readOnlyHint: false` — so a host still confirms before listing bank connections. Recorded for the ADR at closeout.

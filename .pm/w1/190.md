# Parsing an issued but never-uploaded temp asset is a 500, not "upload first"

**Bug · backend-v2 · minor · ~20m · A1.** From `/qa-find-bugs-mcp`, 2026-11-08, production `beancount-mcp 1.0.0`, unpinned API key.

- **Repro:**
  1. Call `generateTempAssetUploadUrl {"filename":"qa.csv","mimeType":"text/csv"}` and skip the PUT.
  2. Call `parseFile {"fileFormat":"csv","objectKey":"<returned key>"}` or `parseReceipt {"ledger":…,"objectKey":…}`.
  - **Result:** MCP returns `INTERNAL_SERVER_ERROR` with the hint "Retry once… changing the request will not help". REST `POST …/import/parse-file` and `…/import/parse-receipt` return 500. GraphQL `parseFile` returns `INTERNAL_SERVER_ERROR`.
  - **Control:** a well-formed key that was never issued gets `NOT_FOUND` "Temporary asset not found" with the upload hint.
- **Cause:** `src/features/s3/service/asset-storage-service.ts:319-336` (`getObjectMetadata`) sends `HeadObjectCommand` with no catch, so the S3 `NotFound`/404 becomes an unexpected error. It is called from `src/features/llm/service/llm-service.ts:191,255` after authorization passes. No model call is made and nothing is billed.
- **Fix:** map `NotFound`/`NoSuchKey`/HTTP 404 to `NotFoundError("Temporary asset")` with the existing temp-asset hint. This shared service covers all three surfaces.
- **Check:** both parse paths with an issued but missing object return `NOT_FOUND` and the upload hint on MCP, REST and GraphQL.

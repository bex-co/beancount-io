## Objective

Give every non-static client (DCR and CIMD) a 45-day refresh token, a 46-day grant, and a one-year ceiling, as code values beside the mobile window — never environment variables.

## Context

- backend-cluster/backend-v2/src/features/oauth/data/config.ts — dynamic clients today: grant 14 days, refresh 30 days; mobile: refresh 365 days, grant 366 days.
- Numbers come from ADR 019 D5 (monthly-close rhythm; one-year ceiling bounds a leaked host-held token). The user confirmed the plan on 2026-10-06; re-confirm the two numbers before merging.

## Steps

1. Add the third-party lifetime values and the ceiling to `oauthLifetimes`.
2. Leave static clients (mobile, Discourse) unchanged.

## Files

- backend-cluster/backend-v2/src/features/oauth/data/config.ts

## Acceptance criteria

- [x] Non-static clients get 45/46-day lifetimes and a one-year ceiling; static clients are unchanged.

## Out of scope

- Per-host lifetimes.

## Result

2026-10-06. `OAUTH_CONFIG.thirdParty` holds `refreshTokenTtlSeconds` 45 days, `grantTtlSeconds` 46 days, and `grantCeilingSeconds` 365 days as reviewed code values; `oauthLifetimes()` gives every client that is neither mobile nor Discourse (DCR and CIMD hosts) the 45/46-day values. Mobile (365/366) and Discourse (provider defaults 30/14) are unchanged, with tests for all three. The ceiling is enforced in t002. The numbers are ADR 019 D5's; the user confirmed the plan on 2026-10-06.

## Objective

Establish a supported engine dependency combination before building and distributing it.

## Context

- ADR014 identifies Beancount 3.2.3 (GPL-2.0-only) and regex 2026.7.19 (includes Apache-2.0 code) as an unresolved compatibility combination.
- Moving Beancount to a child process does not change Beancount's own dependency on regex.

## Steps

1. Verify the exact versioned license texts and runtime dependency path, including any applicable existing exception or additional permission.
2. Select and verify an upstream dependency combination with compatible licenses, or document effective permission covering the actual combination. Exercise Unicode account-name and parsing behavior before accepting a version change.
3. Record exact versions, hashes, source access, and the resolution in ADR014. If no supported resolution is available, keep this task open with the specific blocker; do not label the release compliant.

## Files

- docs/adrs/ADR014-cli-beancount-parity.md
- cli/pyproject.toml and engine dependency manifests; cli/uv.lock (package-manager generated only)
- cli/tests/ (dependency compatibility regressions)

## Acceptance criteria

- [ ] The engine combination has a documented licensing basis with no unresolved exception assumed.
- [ ] Any dependency adjustment preserves the supported accounting/parser behavior and is reproducibly resolved.

## Out of scope

- Reimplementing or forking upstream engines to bypass licensing, changing license labels, or contacting outside parties without authorization.

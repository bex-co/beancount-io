## Objective

Let a PyPI-installed bea provision its engine automatically on the first engine operation.

## Context

- ADR014 permits first-use provisioning for the PyPI channel; customers must not run a second Beancount install/setup command.
- The frontend wheel must not make Beancount, Beanquery, or Fava runtime dependencies of the frontend environment.

## Steps

1. Add a versioned, hash-verified engine manifest and provision the separate environment using the existing package-management tooling.
2. Bootstrap on first engine use, report progress on stderr, and keep JSON/native stdout clean. Help, version, and cloud-only operations must not provision the engine.
3. Handle interrupted and concurrent first use without advertising a partial installation as usable. Verify cached subsequent execution offline.

## Files

- cli/pyproject.toml; cli/ (engine provisioning and manifests)
- cli/scripts/ (artifact generation); cli/tests/

## Acceptance criteria

- [ ] A clean uv tool install of the exact frontend artifact followed by a ledger command provisions the reviewed engine with no manual package install.
- [ ] Help/cloud paths stay independent; failed setup is retryable and later local commands reuse the installed engine offline.

## Out of scope

- Unpinned downloads, automatic version drift, new package-management frameworks, or optional features enabled implicitly.

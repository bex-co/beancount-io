## Objective

Create the CLI-owned engine distribution and an independently invocable helper for complete ledger operations.

## Context

- Native commands cover six entrypoints; current add/list/report/import operations also load Beancount and Fava.
- All implementation stays under cli/; the frontend and helper have separate runtime dependency declarations and distribution contents.

## Steps

1. Define and document helper commands for complete read, write, report, and validation operations. Use ledger text, BQL, ordinary arguments, and CSV/JSON business results.
2. Package the helper with the engine-side Fava code and GPL-compatible distribution terms, retaining applicable component licenses and source materials.
3. Implement one representative operation end to end as a standalone command. Keep engine Python classes, ASTs, pickle, and internal-library RPC out of its public protocol.

## Files

- cli/ (new engine distribution, helper entrypoint, packaging configuration, and tests)
- docs/adrs/ADR014-cli-beancount-parity.md

## Acceptance criteria

- [ ] The helper runs independently of the bea frontend and has documented input/output/error contracts.
- [ ] Frontend and engine artifacts have distinct dependency graphs and the required license/source materials; no AI SDK dependency enters the helper.

## Out of scope

- A general RPC framework, copied upstream accounting logic, or undocumented private-object serialization.

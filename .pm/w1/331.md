# `/pm done` on an inbox note keeps shipping the note's old text, so each close needs a second commit

**Source:** `/loopx w1` orchestrator, 2026-11-20. A worker reported the same slip on five closes in two days: w1/285 (`f1c13c54d`), 318 (`c429c59fe`), 319 (`366f81ea8`), 328 (`7f423b9d1`) and 330 (`887d32445`). **Owner:** internal development skills (`.agents/skills/pm/SKILL.md`, `.agents/skills/loopx/worker.md`). **A1:** the board record is what agents and the community read. Every slip leaves a public commit in which the note sits in `done/` with no **Resolved** paragraph saying what closed it, until a follow-up commit adds it.

**What happens:** the worker moves the note with `git mv` (which stages the old text), then appends the `**Resolved …**` paragraph. It commits without staging again, so the close commit carries the note as it was. In w1/328 a `git pull --autostash` also split the staged rename and left the open copy in place.

**Do:** state the order of steps in the `done` subcommand for inbox notes, and in the worker's ship step, so that a close is one commit: append the paragraph first, then move the file, then `git add` both paths. Alternatively, have the ship step check that the moved note in the commit contains its **Resolved** line. Done when the instructions say this. The check is that the next few `/loopx` closes need no follow-up commit. Run `python3 scripts/check-agent-guidance.py` after editing the skills.

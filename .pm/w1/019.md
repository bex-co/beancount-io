# Init rejects a one-satoshi BTC opening balance

**Minor · 30–45 minutes.** CLI-QA-005.

Run against a fresh disposable directory:
```sh
uv run bea --json init /absolute/qa/tiny --currency BTC --date 2026-01-01 --opening-balance 'Assets:Checking 0.00000001'
```
Actual: exit 1, parser error while validating main.bean; no ledger created.
Same command with 0.000001 succeeds. Earlier controls show empty BTC init then
ordinary transaction add supports the smaller fixed-point amount.

Cause: commands/init.py renders opening amounts and the negated total with
Decimal's default string interpolation. Tiny values become scientific notation,
which isn't valid Beancount amount syntax. Render exact fixed-point decimals,
preserving sum precision and avoiding float conversion. Native ledger support
exists; rejecting these values is not an upstream limitation.
Acceptance: positive/negative one-satoshi balances initialize correctly and
pass fresh check; multiple opening balances sum exactly; ordinary values,
existing-target protection and atomic failed initialization still work.
Dedupe: full-board scientific/satoshi searches found mobile writer work and
w1/013's shared scalar printer, neither fixes init's own template. Prior repeats
and today's tiny/control pair confirm this separate boundary.

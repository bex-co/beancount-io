## Objective

Three load-time failures reach the user as internal Python artifacts: a broken `plugin` directive dumps a full traceback, a `noduplicates` hit prints a roughly 1.5 KB `Transaction(...)` repr, and a bare `@` or `@@` surfaces `MISSING` class tokens.

## Context

- `w3/359`: broken ledger `plugin` directives surface full Python tracebacks on load.
- `w3/302`: `noduplicates` hits appear as a raw `Transaction(...)` repr rather than a readable duplicate message.
- `w3/268`: `add transaction` with a bare `@` / `@@` surfaces Python `MISSING` class tokens in the error.
- Load and error rendering cross `cli/src/bea_engine/ledger/reader.py` and `cli/src/cli/errors.py`.

## Steps

1. Catch plugin import and execution failures at load and report the plugin name, the directive's file and line, and the underlying message.
2. Render a duplicate finding as date, payee, narration, and amount with the two source locations, not as an object repr.
3. Translate `MISSING` sentinels in price and cost positions into a message naming the missing part and the correct syntax.
4. Keep every message stable under `--json` as a structured error.

## Files

- cli/src/bea_engine/ledger/reader.py
- cli/src/cli/errors.py
- cli/src/cli/commands/add.py
- cli/tests/test_feedback_regressions.py

## Acceptance criteria

- [ ] A ledger with a misspelled plugin name reports the plugin, the file and the line, with no traceback.
- [ ] A `noduplicates` hit reports the duplicate in one readable line with both source locations, well under the current repr size.
- [ ] `bea add transaction` with a bare `@` names the missing price and shows the accepted syntax; no `MISSING` token appears.
- [ ] All three are structured errors under `--json`.

## Out of scope

- Changing plugin loading or duplicate-detection semantics.
- Price and cost writing rules, which m27 owns.

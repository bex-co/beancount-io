## Objective

The BQL shell's dot-commands and several ordinary query shapes crash with raw Python errors, and some write past the engine's JSON envelope so the CLI reports only that the engine did not answer.

## Context

- `w3/233` (major): `.help`, `help`, and `.parse …` write past the engine JSON envelope; the CLI reports `engine did not answer`.
- `w3/299`: `help select` crashes with `NoneType` because the shell handler has no docstring.
- `w3/358`: `GROUP BY accounts` crashes with `issubclass() arg 1 must be a class`.
- `w3/360`: a scalar subquery in the SELECT list crashes with a raw `AttributeError`.
- `w3/274`: `--source` with a bad URI scheme dumps a raw bean-query traceback.
- Query execution is `cli/src/bea_engine/query.py`; the frontend is `cli/src/cli/commands/query.py`.

## Steps

1. Route shell dot-command output through the envelope rather than straight to stdout, so `--json` stays parseable and the CLI never reports a missing answer for a command that did respond.
2. Catch the upstream crashes named above at the engine boundary and convert them into BQL errors naming the construct that failed.
3. Give `help <topic>` a real answer for topics with no docstring instead of a `NoneType` crash.
4. Validate `--source` URIs before handing them to upstream and reject unsupported schemes with the supported list.

## Files

- cli/src/bea_engine/query.py
- cli/src/cli/commands/query.py
- cli/src/cli/engine/launch.py
- cli/tests/test_contract.py

## Acceptance criteria

- [ ] `.help`, `help`, `help select`, and `.parse …` all answer without a traceback, in human and `--json` mode, and never report `engine did not answer`.
- [ ] `GROUP BY accounts` and a scalar subquery in the SELECT list return a BQL error naming the unsupported construct, exit nonzero.
- [ ] `--source` with an unsupported scheme exits 2 naming the supported schemes.
- [ ] Valid queries and dot-commands are unchanged.

## Out of scope

- Implementing the missing BQL capabilities themselves (`w3/246`, `w3/247`, `w3/353`).
- The interactive redirect/reset path repaired by w1/m22.

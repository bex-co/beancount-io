## Objective

Under `--json`, failures from the engine child process and from native forwards reach stderr as raw Python tracebacks or errno messages, so `json.loads(stderr)` raises and an agent learns nothing — including, after a partial `format -i`, which files were already rewritten.

## Context

- `w5/004`: `bea --json format -i` on an unwritable file exits 1 with a twenty-line upstream traceback; `a.bean` was rewritten and `c.bean` was not, and nothing says so.
- `w3/298`: `treeify` and `example` dump upstream tracebacks on common misuse.
- `w3/250`: `--json ... -o <directory>` fails with a raw or errno message; `query` names a temp file.
- `w3/270`: `query --output` on a directory or missing parent surfaces a raw `[Errno …]`.
- `w3/239`: `bea format a.bean b.bean` exits 2 with raw bean-format Click help instead of a bea usage error.
- The child-process boundary is `cli/src/cli/engine/launch.py` (`helper_json`, `run_engine_argv`, `run_native`); the envelope is built in `cli/src/cli/output.py` and error types live in `cli/src/cli/errors.py`.

## Steps

1. Add one boundary that catches any non-envelope child failure and renders the standard error envelope: code, message, exit status, and a stderr tail for diagnosis.
2. Include the effects already applied — for multi-file operations, the list of files written before the failure.
3. Keep raw tracebacks behind `--debug` only; without it, no Python traceback reaches either stream.
4. Map destination errors (directory given for a file, missing parent, permission denied) to a usage error naming the path the user passed, never a temp file.
5. Give multi-file argument misuse a bea usage error instead of forwarding upstream's Click help.

## Acceptance criteria

- [ ] Every reproducer above emits a parseable envelope under `--json`: `json.loads` succeeds on the error output.
- [ ] `bea --json format -i` over a tree with one unwritable file names the files already rewritten and the file that failed.
- [ ] No Python traceback appears in stdout or stderr unless `--debug` is passed.
- [ ] `-o <directory>` and a missing parent directory produce usage errors naming the path the caller supplied.

## Out of scope

- Making the failing operations succeed — this task is about how failure is reported.
- Transactional rollback of partial multi-file writes; reporting them is the scope here.

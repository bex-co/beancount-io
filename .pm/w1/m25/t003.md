## Objective

`--json` is the automation switch, but it forces the query format, breaks on the optional native forwards, drops engine notes from import output, and is ignored by `--version`.

## Context

- `w3/312`: `--json` on enabled `price` / `ingest` emits bean-price / Beangulp text on stdout and upstream tracebacks on stderr, while `doctor` / `example` / `treeify` / `ask` already refuse JSON cleanly.
- `w3/296` and `w3/234`: `--json query -f csv` silently ignores `--format`, and `--json` forces JSON so one-shot shell utilities that work in human mode become BQL syntax errors.
- `w3/238`: `--json import` drops engine `notes` (for example non-account category labels) that human mode shows.
- `w3/314`: `bea --json --version` prints plain text.
- w1/m22 fixed JSON query `-o` export; this completes the surrounding contract.

## Steps

1. Decide and document one rule for `--json` plus `--format`: either `--format` selects the payload encoding inside the envelope or the combination is refused — do not silently ignore the flag.
2. Give `price` and `ingest` the same clean JSON refusal the other native forwards already have, or a real envelope; never raw upstream text on stdout.
3. Carry engine `notes` through into the JSON import result so agents see the guidance human mode prints.
4. Answer `--json --version` with an envelope.

## Acceptance criteria

- [ ] `--json` combined with `--format` either works as documented or exits 2 saying so; it is never silently ignored.
- [ ] `--json price` and `--json ingest` emit a parseable envelope or a clean refusal, with no upstream text on stdout.
- [ ] `--json import` includes the `notes` human mode prints.
- [ ] `bea --json --version` emits an envelope.

## Out of scope

- Adding JSON output to commands that deliberately refuse it.
- Changing the envelope's schema version.

# `bea add document --path receipts/` (or `.`) records a folder as the attachment, exit 0, though a missing file is refused

**Bug · cli · minor · ~20m · A1.** From routine cli-qa, 2026-11-21. `bea add document` refuses a `--path` that names no file (`File does not exist: "…/receipts/feb.pdf"`, exit 1, nothing written), so the command reads as checking that the attachment is there. A path that names a folder passes instead: `--path receipts/`, `--path receipts` and even `--path .` (the ledger's own folder) each write `document Assets:Checking "receipts/"` and so on, with exit 0. `bea check` stays green and `bea list document` lists the rows like real attachments, with `receipts/` and `receipts` shown identically as `receipts`. An agent or script that drops the file name (an unset variable in `"receipts/$FILE"`) therefore records an attachment no viewer can open, and nothing ever says so.

Environment: main `c9d492c18`, `bea 0.5.0` from the checkout (`uv run bea`), Python 3.12.14, macOS 26.5.1. Isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, `BEA_FILE`/`BEA_TOKEN` unset, stdin closed, no TTY, scratch cwd, fresh processes.

## Repro

```sh
mkdir -p books/receipts && echo pdf > books/receipts/jan.pdf
printf 'option "operating_currency" "USD"\n2026-01-01 open Assets:Checking\n' > books/main.bean
bea --file books/main.bean add document --date 2026-01-31 -a Assets:Checking --path receipts/          # exit 0, "Added 1 document"
bea --file books/main.bean add document --date 2026-01-31 -a Assets:Checking --path .                  # exit 0
bea --file books/main.bean add document --date 2026-01-31 -a Assets:Checking --path receipts/feb.pdf   # exit 1, File does not exist (control)
bea --file books/main.bean check                                                                        # exit 0
bea --file books/main.bean list document
```

Actual: the ledger gains `2026-01-31 document Assets:Checking "receipts/"` and `… "."`; `list document` shows `receipts` and `.` in its FILENAME column. The control (`receipts/jan.pdf`) writes and lists normally; the missing `feb.pdf` is refused with the ledger byte-identical.

## Expected

`add document` refuses a `--path` that resolves to a directory (relative to the destination file's folder, as today), with exit 2 and nothing written: the error names the folder and asks for the file inside it, for example `Document path 'receipts/' is a folder, not a file; pass the file to attach, such as receipts/<name>.pdf.` A path to a regular file, and the existing missing-file and outside-the-tree refusals, are unchanged. `bea check` keeps upstream's semantics for directives already in a ledger.

## Cause

bea leaves the existence check to Beancount's `beancount.ops.documents.verify_document_files_exist`, which tests `path.exists(entry.filename)` (`beancount/ops/documents.py:83` in 3.2.3) and so accepts a directory. bea's own pre-write check, `_require_document_in_tree` in `cli/src/bea_engine/ledger/adding.py:123` (called at `:110`), only refuses a path that climbs outside the ledger tree, and `_simple`'s document branch (`:253`) only refuses an absolute path.

## Fix

In `adding.py`, resolve the path the way `_require_document_in_tree` already does (`holder / filename`) and raise `protocol.UsageError` when it is a directory, before anything is written. Add a regression test through real `bea add document` subprocesses for `receipts/`, `receipts` and `.`: each exits 2, names the folder, and leaves the ledger byte-identical. Add a control in the same test: an existing file still writes with exit 0, and a missing file is still exit 1. Revert the fix and watch the folder cases fail. Owned by `cli`; check whether `bea import`'s document rows from a Python importer go through the same write path, and cover them in the same change if they do.

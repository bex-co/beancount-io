# Cloud clients disable HTTP timeouts, so unattended requests can wait forever

Severity: major. Estimate: 45–60m including shared-client regression coverage.
Owner: CLI. A1/A2: unattended cloud commands need bounded failure and useful
retry guidance when a server accepts a connection but stops responding.

Reproduced twice at main `c6de619d9094e1ae45a248eef3e6ba3d74a5944f`, checkout
`uv run bea` 0.1.0, Python 3.13.0, macOS 26.5.1 arm64, HTTPX 0.28.1.
Loopback simulation only; no production defect, real account or mutation claimed.
Cwd `cli/`; stdin DEVNULL, no TTY, global `--json` implies no input.

Public reproducer from `cli/` (run once with status, then with the create args):

```python
import os, signal, subprocess, tempfile, threading
from pathlib import Path
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer
release = threading.Event()
class Handler(BaseHTTPRequestHandler):
    def log_message(self, *args): pass
    def do_GET(self): release.wait(90)
    def do_POST(self): release.wait(90)
server = ThreadingHTTPServer(('127.0.0.1', 0), Handler)
threading.Thread(target=server.serve_forever, daemon=True).start()
try:
    with tempfile.TemporaryDirectory(dir='tmp') as directory:
        env = os.environ.copy()
        env.pop('BEA_FILE', None)
        env.update(BEA_TOKEN='synthetic-invalid',
                   BEA_API_URL=f'http://127.0.0.1:{server.server_port}',
                   BEA_CONFIG_DIR=str(Path(directory).resolve()),
                   XDG_CACHE_HOME=str(Path(directory).resolve()/'cache'),
                   BEA_NO_UPDATE_NOTIFIER='1')
        args = ['--json', 'cloud', 'status']
        # Also: ['--json','cloud','ledger','create','qa-20260909-stall']
        p = subprocess.Popen(['uv','run','bea',*args], env=env,
                             stdin=subprocess.DEVNULL, stdout=subprocess.PIPE,
                             stderr=subprocess.PIPE, text=True,
                             start_new_session=True)
        try:
            print(p.communicate(timeout=25), p.returncode)
        except subprocess.TimeoutExpired:
            os.killpg(p.pid, signal.SIGKILL)
            print('external 25-second cutoff', p.communicate())
finally:
    release.set()
    server.shutdown()
    server.server_close()
```

Actual: GET `/api-gateway/v1/user-profile` and POST `/api-gateway/v1/ledgers`
reach the fixture. Each command remains running with empty stdout/stderr at the
external 25-second cutoff (25.092s / 25.052s on repeat); neither supplies a CLI
exit category. No prompt exists on either JSON command. Runtime inspection of
both `make_client().get_httpx_client().timeout` and the bearer equivalent yields
`Timeout(timeout=None)`; the wait is unbounded by the client, not merely slower
than the fixture budget. Controls returning HTTP 200 `null` for status and a
standard HTTP 409 error for create complete within 2s with exits 3 and 4.

Root cause: `cli/src/cli/api/client.py:26` and `:32` construct anonymous/bearer
clients without timeout. Generated `rest_client/client.py:41` / `:171` default
`_timeout` to None and pass it explicitly to HTTPX at `:87` / `:222`, overriding
HTTPX's own finite default. Installed `httpx/_config.py` confirms None populates
all phase deadlines with None. Do not hand-edit generated output.

Fix: set an explicit finite transport timeout in the handwritten constructors,
with a documented bound. Preserve the existing unknown-write-outcome handling:
a stalled create/delete must exit 4 with inspection-before-retry guidance;
a read must terminate with the existing network-failure category. Do not add
automatic mutation retries. Device-flow polling may wait for user approval,
but each individual HTTP request must still be bounded. Shared regression
coverage should exercise a real stalled loopback request, normal responses,
and constructor configuration for anonymous and bearer clients.

Caller search: anonymous make_client feeds login; bearer_client feeds status,
logout and authenticated_client; the latter feeds list/show/create/delete/clone.
Logout clears stored credentials only after its remote attempt returns, so the
same missing deadline also blocks its intended offline cleanup (not separately
live reproduced here). `ask` uses a separate proxy client and is not implicated.

Dedupe: all open/completed `.pm` searched for timeout/hang/stalled/cloud transport.
No open matching item; notifier and mobile connection timeouts are distinct.
`git log -S 'Client(base_url=settings().api_url)'` identifies `481f313e`, the
completed w1/m12 REST migration. Its full DoD covers REST-only codegen and CI;
this real socket wait is an additional reliability gap, not deployment lag.

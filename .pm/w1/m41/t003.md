## Objective

After a file save, refetch only what the write can have changed, instead of evicting `ROOT_QUERY`. Today the wipe triggers about 10 queries, including a second full download of the file.

## Context

- `handleSaveFile` calls `cleanCache()` from `dashboard/src/common/hooks/use-apollo-cache.ts`, which runs `client.cache.evict({ id: "ROOT_QUERY" })`.
- Observed after a save: `GetCurrentUser`, `ListLedgers`, `GetSubscriptionStatus`, `GetLedger`, `GetLedgerAccounts`, `GetLedgerErrors`, `GetLatestLedgerCommit`, `GetLedgerEntriesCountPerType`, `GetLedgerEvents`, and `GetLedgerFile` all refetch.
- A file edit can change this ledger's derived data: accounts, errors, entries, events, latest commit, and the file itself. It cannot change the current user, the subscription, or the list of ledgers.

## Steps

1. Write the mutation result's `sha` and commit fields into the cached `GetLedgerFile` entry for this path, together with the saved content the client already has, so the view does not download the file again.
2. Evict or refetch only this ledger's derived queries. Leave user-, subscription-, and ledger-list queries alone.
3. Check that pages visited after the save (journal, accounts, reports) still show post-save data.

## Files

- `dashboard/src/features/ledger-editor/file-editor/components/ledger-file-view/index.tsx`
- possibly a small helper next to `dashboard/src/common/hooks/use-apollo-cache.ts`

## Acceptance criteria

- [ ] A save no longer refetches `GetCurrentUser`, `ListLedgers`, `GetSubscriptionStatus`, or `GetLedgerFile`.
- [ ] After a save that adds a transaction, the journal and accounts pages show it without a manual reload.
- [ ] The file view's out-of-date detection keeps working against the new sha.

## Out of scope

- The other writers that call `cleanCache()`.

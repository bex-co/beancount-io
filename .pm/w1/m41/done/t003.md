## Objective

After a file save, refetch only what the write can have changed, instead of evicting `ROOT_QUERY`. Today the wipe triggers about 10 queries, including a second full download of the file.

## Context

- `handleSaveFile` calls `cleanCache()` from `dashboard/src/common/hooks/use-apollo-cache.ts`, which runs `client.cache.evict({ id: "ROOT_QUERY" })`.
- Observed after a save: `GetCurrentUser`, `ListLedgers`, `GetSubscriptionStatus`, `GetLedger`, `GetLedgerAccounts`, `GetLedgerErrors`, `GetLatestLedgerCommit`, `GetLedgerEntriesCountPerType`, `GetLedgerEvents`, and `GetLedgerFile` all refetch.
- A file edit can change this ledger's derived data: accounts, errors, entries, events, latest commit, and the file itself. It cannot change the current user, the subscription, or the list of ledgers.

## Steps

1. Write the mutation result's `sha` and commit fields into the cached `GetLedgerFile` entry for this path, together with the saved content the client already has, so the view does not download the file again.
2. Evict or refetch only this ledger's derived queries. Leave user-, subscription-, and ledger-list queries alone.
3. Check that pages visited after the save (journal, accounts, reports) still show post-save data.

## Files

- `dashboard/src/features/ledger-editor/file-editor/components/ledger-file-view/index.tsx`
- possibly a small helper next to `dashboard/src/common/hooks/use-apollo-cache.ts`

## Acceptance criteria

- [x] A save no longer refetches `GetCurrentUser`, `ListLedgers`, `GetSubscriptionStatus`, or `GetLedgerFile`.
- [x] After a save that adds a transaction, the journal and accounts pages show it without a manual reload.
- [x] The file view's out-of-date detection keeps working against the new sha.

## Out of scope

- The other writers that call `cleanCache()`.

## Outcome — 2026-11-02

`useLedgerWriteRefresh` (`dashboard/src/common/hooks/use-apollo-cache.ts`) replaces the `ROOT_QUERY` eviction for file saves. In one cache batch it deletes every root field except a keep-list of account fields (`userProfile`, `subscriptionStatus`, `storeBillingIdentity`, `aiCfoUsage`, `allTierQuotas`, `apiKeys`, `listPublicKeys`, `featureFlags`, `getFeed`, `health`), then writes the saved file back into `GetLedgerFile` from the mutation's revision and the content the editor sent. It still bumps `cacheClears`, so **Out of date** re-baselines on the write. A keep-list fails safe: a root field nobody listed refetches.

- **Deviation:** `ListLedgers` still refetches. It carries each ledger's size and last update, and a write moves both.
- **Fallback:** a write whose result has no `lastCommitSha` refetches the file instead, so the view never shows the previous commit for the saved file.
- **Tests:** `use-ledger-write-refresh.test.tsx` (real `InMemoryCache`: kept and dropped fields, a single broadcast carrying the new file, the clear counter) and `save-confirms-on-write.test.tsx` (the write-back and the fallback). Both were mutation-checked.
- `dashboard/AGENTS.md` documents the hook beside the cache-clear rule.

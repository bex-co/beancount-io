## Objective

Drop `content` from the `UpdateLedgerFile` mutation's selection set, so a save no longer downloads the whole file it just uploaded.

## Context

- `dashboard/src/features/ledger-editor/graphql/ledger-editor.graphql`: `mutation UpdateLedgerFile` selects `content` along with `sha` and the commit fields.
- `handleSaveFile` does not read the mutation result; the view's content comes from `GetLedgerFile`.
- Check whether Apollo's cache normalization for the file type would merge a content-less result over the cached `GetLedgerFile` entry and leave a missing field that forces a refetch or an empty view.

## Steps

1. Remove `content` (and any other unused heavy fields) from the selection.
2. Regenerate the GraphQL definitions with the dashboard's codegen script.
3. Confirm that no consumer reads `updateLedgerFile.content`.

## Files

- `dashboard/src/features/ledger-editor/graphql/ledger-editor.graphql`
- the generated `dashboard/src/graphql/definitions` output

## Acceptance criteria

- [ ] The `UpdateLedgerFile` response body in the network log has no `content`.
- [ ] After saving, the file view shows the saved text and the new sha.

## Out of scope

- Sending a diff instead of the whole file: the API takes full content.

## Outcome — 2026-10-19

The checklist was mapped against the tests already shipped with t001–t010, and only the gaps were filled. Every new test was mutation-checked: break the code it covers, see it fail, restore.

**Backend:**
- **Subscription listing.** The "current" listing sends no `status` filter and expands `data.latest_invoice`. With `expandForStatus` it also expands `data.schedule`. Without that expansion, every past-due subscriber would resolve to Free in production while every test that hands back an expanded invoice stayed green. This was the audit's most important gap.
- **Past due:**
  - A Stripe outage with an empty verified cache resolves to Free.
  - A past-due subscription Stripe stopped retrying is not paid.
  - Billing status with no cache and a failing Stripe surfaces an error rather than "not subscribed". Production masks internal messages, so no internal text reaches a client.
- **Pricing-page contract.** A second Checkout is refused for a past-due subscriber still being retried, not only for an active one.
- **Collaborator limits.** Premium (5) and Growth (10) owners are now tested, with the acting admin on Organization, so only the owner's plan can explain the limit.

**Dashboard:**
- **Split choice.** Choosing "later" sends the monthly target with no proration date. The "now" option shows the server's alternative amount and confirms it with that alternative's own proration date.
- **Cancel-sheet alternatives.** Organization yearly is offered Growth yearly. Premium monthly is offered Premium yearly. A monthly plan shows exactly one alternative. The Premium-yearly case now checks that no alternative button exists, not only that a heading is absent. Choosing the alternative opens the plan sheet for it, with the `cancel_sheet` surface.
- **Undo.** A refused "keep current plan" shows an error and tracks no `plan_change_reverted`. `useCancelScheduledPlanChange` refetches and awaits the subscription status.

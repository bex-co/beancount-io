## Objective

Implement the rename as one shared workflow that every adapter calls: rewrite the account tokens in every loaded source file, project the result through the new-error gate, and commit all files at once.

## Context

- `src/features/ledger/service/ledger-repo-service.ts` `changeFiles` commits several files atomically.
- `src/features/ledger/utils/file-write-gate.ts` holds the projected new-error gate and `projectedSourceFiles`.
- `src/features/ledger/workflow/ledger-workflow.ts` holds the other ledger write workflows, including the commit-returning ones from w23/m42.

## Steps

1. Read the loaded source files at HEAD. Find account tokens with a scanner that skips quoted strings and `;` comments and matches whole account names only (the old name, or the old name followed by `:`).
2. Build the projected files, run them through the existing new-error gate, and honor `allowInvalid`.
3. On `dry_run`, return the per-file changed lines and counts. Otherwise commit with `changeFiles` against the HEAD that was read, and return `commit`.
4. Refuse per t001's contract before reading files where possible.
5. Unit-test the scanner on prefixes, descendants, strings, comments, metadata and every directive kind.

## Outcome — 2026-11-13

- **Scanner:** `src/features/ledger/utils/account-rename.ts`. `accountTokenOffsets` walks the text with string state (strings may span lines and hold `\"`), skips `;` comments and org-mode `*` lines, and matches the account only on whole names: `from` exactly or `from:` followed by a name character. `renameAccountInText` returns the new text plus each changed line (`{line, before, after}`, CR kept in the text, not in the report). `renamedAccounts` lists each account the rename maps, descendants included.
- **Workflow:** `src/features/ledger/workflow/account-rename-workflow.ts` (`AccountRenameWorkflow`).
  - It refuses before any read: an invalid `from`/`to` (Beancount's account grammar, `isValidAccountName` exported from `account-matcher.ts`), the same account, or another root.
  - It reads the loaded files only (`projectedSourceFiles` then `getFilesContent`).
  - `NOT_FOUND` when nothing names `from`. A target already in the ledger that is not itself renamed away is refused as a merge. A non-UTF-8 file that would be rewritten is refused.
  - It gates the projection with `gateFileWrite`: a preview reports new errors, a commit refuses them unless `allowInvalid`.
  - It commits once through `changeGeneratedFiles`, with each file's sha, and returns `commit`.
- **Tests:**
  - `utils/__tests__/account-rename.test.ts` (8): every directive kind, metadata, descendants, prefix neighbours, strings, comments, a multi-line string, org headings, CRLF, a missing final newline, non-ASCII names. It fails against a plain string replace, since the prefix, string and comment cases would change.
  - `workflow/__tests__/account-rename-workflow.test.ts` (11): three files in one commit with their shas, a preview that commits nothing, the gate with and without `allowInvalid`, each early refusal reads nothing, merge refusal, a descendant moved beside its parent, `NOT_FOUND`, an unloaded file left alone, a lossy file refused.
- **Checks:** `yarn typecheck`, `yarn lint:deadcode` and `yarn format:check` pass in `backend-cluster/backend-v2`. On the full `yarn test` (475 suites, 10,565 tests), the one failure was `not-found-hints.test.ts`: every MCP-reachable `NOT_FOUND` needs its own hint. The rename's now says to read the ledger's accounts and pass one as `from`, and that suite and the workflow suite pass (17 tests).

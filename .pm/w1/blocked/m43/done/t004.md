## Outcome — 2026-11-13

- **Surfaces:**
  - MCP `renameAccount`: `DESTRUCTIVE`, not idempotent, since a repeat answers `NOT_FOUND`. It takes `from`, `to`, `dry_run`/`dryRun`, `allow_invalid`/`allowInvalid`, `ledger`, and returns the shared write outcome (`summary`, `wrote`, `entryHashes`, `validation`, `dry_run`) plus `accounts`, `files`, `bankMappings`, `commit`.
  - REST `POST /api-gateway/v1/ledgers/{owner}/{name}/rename-account` (`rename-account-handler.ts`).
  - GraphQL `renameLedgerAccount` (`ledger-resolver.mutation.ts`, types in `ledger-resolver.types.ts`).
  - All three share one description (`RENAME_ACCOUNT_DESCRIPTION` in the workflow module), each with its own preview-flag spelling.
- **Composition:**
  - `LedgerWorkflow.renameAccount` delegates to an injected `AccountRenameWorkflow`, built in `buildWorkflowLayer` with the real repo service, ledger data, authorization and `PlaidLedgerBankMappings`.
  - All three adapters already reach `LedgerWorkflow`, so no transport context grew a field.
  - The service layer's `ledgerRepo` is now typed as `ILedgerRepoService & ILedgerGeneratedFileWriter`, which the concrete service already was. The rename commits through the internal writer, as the append does, without the 1 MiB explicit-upload cap.
  - The workflow now authorizes `ledger.files.write` before judging the request, so a read-only credential is `FORBIDDEN` on every surface.
- **Registry and gates:**
  - `op-class.ts`: the verb, and its `LEDGER_FILES_WRITE` action. `op-class-coverage` counts move from 69 to 70 mutations and from 45 to 46 tools.
  - `write-preview-matrix`: a projection row, proved by the new parity suite.
  - `mcp-output-conformance`: a shared-schema row.
  - `mcp-tool-list`: the preview case (its preview field is `files`), the destructive-effects case, and the budget raised from 124 KB to 128 KB (measured 130,013 bytes, +7.7 KB, almost all the shared write-outcome schema). The reason is recorded beside it.
  - The reviewer annotation matrix `docs/marketplace-submissions/openai/tool-annotations.json` now has a justified entry; the gate requires it, so it landed here rather than in t005.
  - The `docs/mcp.md` Tools row is required by the docs gates.
- **Parity proof:** `rest/v1/__tests__/rename-account-parity.test.ts` runs the real adapters and the real workflow on all three surfaces (12 cases):
  - a rename in one commit with each file's sha and the same changed lines;
  - a breaking preview reported invalid and committing nothing;
  - a breaking commit refused `VALIDATION_FAILED` unless `allowInvalid`;
  - another root refused `BAD_USER_INPUT`;
  - a read-only credential refused `FORBIDDEN`.
- **OpenAPI and CLI:** `yarn generate-v1-openapi` regenerated `docs/openapi/v1.json`; `make spec-sync && make codegen` in `cli/` re-synced the pinned spec and generated the REST client models. No `bea cloud` command was added (out of scope).

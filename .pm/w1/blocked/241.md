# Port the CLI off typer's private click so typer 0.29+ can install

**Chore · cli · medium · 1–2h · A2.** [239](../done/239.md) capped `typer<0.29` because typer 0.29.0 dropped its vendored `typer._click.types` and `ParamType`. Five frontend modules import typer's private click: `cli/utils.py` (`ParamType` for `NonEmptyPath`, `RawPath`, `IntoPath`), `native_command.py` and `single_value.py` (`_click.parser._OptionParser`), `main.py` (`_click.exceptions.NoArgsIsHelpError`) and `commands/list.py` (`_click.core.ParameterSource`). The cap keeps installs working but holds every user on an old typer, and the next typer change to the others will break again.

- **Do:** move the three path types to typer 0.29's own parameter types or a callback, and the rest to public typer API or `click` as a declared dependency (adding one needs the owner's approval, per the root `AGENTS.md`). Then lift the cap and relock with `uv`.
- **Acceptance:** `cli/pyproject.toml` allows typer 0.29; `python scripts/test-install.py` passes for the wheel and the sdist on a fresh resolve; `make check-all` passes; `grep -rn "typer\._click" cli/src` finds nothing.

Filed by `/loopx w1` while resolving 239, 2026-11-13.

---

**Blocked 2026-11-13.** Triage measured the port, and it is far larger than this note's 1–2h. typer 0.29 is a rewrite in which pydantic `TypeAdapter`s replace click's parameter types. It removes the public `click_type=` argument, `typer.models.TyperPath` and `typer._click.types`. The CLI leans on that machinery in five places:
- The app-wide empty-path refusal (`main.py` `_refuse_empty_paths`) swaps each `TyperPath`'s class. Under 0.29 it fails at import, so every command fails: a trial resolve with typer 0.29.1 failed 8,999 of 11,547 tests and errored 487 more.
- Eight options pass `click_type=` (`NonEmptyPath`, `RawPath`, `IntoPath`). The 0.29 replacement, `parser=`, runs as a pydantic before-validator that receives only the value, so the refusals that name the option (w5/738) need another design.
- Native forwarding and single-value parsing subclass the vendored parser (`_OptionParser._match_short_opt`, `make_parser`). That still exists in 0.29 as `typer._click`, but no public API replaces it, so the acceptance line "`grep typer._click` finds nothing" cannot hold while those features stay.
- The dev group's `openapi-python-client` requires `typer<0.28`, so the lock cannot resolve 0.29 until codegen runs in its own tool environment (for example `uvx`).
- The engine venv pins typer 0.27.2 (`engine-requirements.lock`, `engine-optional-*.lock`), and `bea_engine/__main__.py` falls back to `click`, which typer 0.29 no longer installs.

The cap from [239](../done/239.md) keeps installs working today: a fresh resolve takes typer 0.28. Import cost is not a concern either: `import typer` takes about 23 ms on both 0.27 and 0.29, because pydantic loads lazily.

**Unblock:** the owner chooses one of:
- (a) keep `typer<0.29` and revisit when typer's new core settles, in which case this note is dropped;
- (b) fund a port milestone of several hours. It would move codegen out of the dev group, rebuild the empty-path refusal and the three path types on 0.29's coercion, port the parser subclasses, relock the frontend and the engine, regenerate `docs/REFERENCE.md`, and re-green `make check-all` and `scripts/test-install.py`. `/pm promote w1/241` would materialize it.

Nothing was shipped for this note; the trial was reverted.

## Objective

Show "File saved successfully" as soon as `UpdateLedgerFile` succeeds. Run the post-write new-error check without blocking that message or the `isSaving` state, and still warn when the write left new errors.

## Context

- `dashboard/src/features/ledger-editor/file-editor/components/ledger-file-view/index.tsx` `handleSaveFile`: today `onCompleted` awaits `writeOutcome.report(before)`, which refetches `GetLedgerErrors`, before showing the success toast. The `finally` block clears `isSaving` only after that.
- `dashboard/src/common/hooks/use-write-outcome.ts`: `report` returns true when it showed the warning, so the caller skips its success toast. Other writers depend on that contract: journal entry panel, new-directive dialog, importer, and open-account dialog.
- Measured: the serial `GetLedgerErrors` costs 0.6–0.8s warm and up to 1.5s cold on a 312KB ledger.

## Steps

1. In `handleSaveFile`, show the success toast and clear `isSaving` when the mutation completes.
2. Fire `writeOutcome.report(before)` without awaiting it in the save path. Its warning toast appears later if the write left new errors.
3. Keep the other `useWriteOutcome` callers unchanged unless the hook's API has to change. If it does, update every caller in the same change.

## Files

- `dashboard/src/features/ledger-editor/file-editor/components/ledger-file-view/index.tsx`
- `dashboard/src/common/hooks/use-write-outcome.ts` (only if needed)

## Acceptance criteria

- [x] The success toast and the end of the saving state happen before the post-write `GetLedgerErrors` request resolves.
- [x] A save that adds a new error still shows the "write left errors" warning with the View errors action.
- [x] A failed mutation shows only the error toast, with no success toast and no background check.

## Out of scope

- Changing the confirmation flow of the other `useWriteOutcome` callers.

## Outcome — 2026-11-13

`/simplify` ran four reviews (reuse, simplification, efficiency, altitude) over `523b40d55..d43412d0f` for `cli/src`, `cli/tests` and the new tests in `scripts/skills/test_beancount_skills.py`.

**Applied:**
- **Structured errors, no re-parsing.** `describe` returns each error as `{file, line, message, option}` and each plugin with `file`/`line`, read from the loader's records. The frontend no longer splits `"file:line: message"` strings, and the separate `unknown_options` list is gone, since `option` on an error carries it. A folder named `Books: 2024` used to break that split; a regression test now covers it.
- **One plugin-failure parser.** `query.plugin_failure` returns the kind and name and backs `is_plugin_failure`. `describe` splits failures from other errors in one pass, instead of keeping its own two copies of the regex.
- **One plugin-line finder.** `describe` uses `query.plugin_directive` (made public) on the root only, since Beancount keeps only the root's options, and with each plugin's config. It no longer reads every included file. That helper now strips a BOM, so a `plugin` on line 1 of a BOM file is located for `bea check` too (new test).
- **One baseline rule.** `agent_guidance.baseline_errors` decides, for both the `AGENTS.md` sentence and the terminal note, whether the error count was measured. Only a beside-ledger plugin that failed to *import* makes it unmeasured; one that imported and raised was measured.
- **Quoting and discovery reuse.** `_quoted`/`_shell_path` moved to `cli/utils.shell_path`, so `AGENTS.md` commands get the same control-byte-safe quoting (w5/887) instead of a hand-rolled `shlex` wrapper. `check_command` takes `pythonpath: bool`. The default-name lookup is `config.default_entry`, shared with `RunContext.entry_file`. Folder candidates come from `output.ledger_candidates` (made public), which matches suffixes in any case (w5/865). `_root_in_directory` is extracted with early returns.
- **A guard plain `init` had:** `--existing` now calls `refuse_expanding_ledger_path`, so a `$VAR` root cannot be described as another ledger than the one the agent files sit beside.
- **Small:** the defensive `.get` lookups, the double error filter in `render`, the tuple-then-unpack, the drifted engine docstring and the dropped `directory` field are gone.
- **Tests:** the redundant clean-ledger and folder-resolution runs are folded into existing tests, and `_bea_with_pythonpath` reuses `report_helpers._run` with `os.pathsep`.

**Fixed while applying (found by the reuse review):** with more than 30 accounts, `AGENTS.md` suggested `bea list open --limit N`, but `list open` also lists the opens of accounts closed since, so that limit cut the list short. It now gives the exact `#accounts WHERE close IS NULL` query, and a test runs it.

- Routing the candidate through `RunContext.entry_file()`: its messages would say "(from --file)" for a positional path. Only its `$VAR` refusal was adopted.

- Test-helper generalisations in the skills suite (`june_expenses`, `find_bea` blocks).
- Moving the template-drift test.

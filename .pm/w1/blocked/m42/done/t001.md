## Objective

Settle, in writing, what "bring an existing ledger" does and never does, so the CLI command, the report and the skill branch all follow one contract.

## Context

- `bea init --agent-files` writes `AGENTS.md` and a `CLAUDE.md` bridge for a ledger it just created (`cli/src/cli/agent_guidance.py`, `write_agent_files`). Files are created exclusively and never overwritten.
- `bea doctor guidance` (`cli/src/cli/commands/doctor.py`) checks those files read-only and always exits 0.
- `skills/beancount-init/SKILL.md` Step 1 refuses a directory holding `main.bean`, `pyproject.toml` or a `Makefile`.

## Steps

1. Choose the command shape and record why. Candidates: `bea init --existing FILE`, or `bea doctor guidance --write`. Prefer the one whose help text a newcomer finds first and that keeps `doctor` read-only by default.
2. Define the inputs: any root file name; a root found through `--file`, `BEANCOUNT_FILE` or an explicit path, never guessed from the directory when there are several candidates.
3. Define what the generated `AGENTS.md` states, all read from the loaded ledger: the root, the `include` layout, where new entries go (the existing `bea add --into` destination rules), the operating currencies, the open accounts (capped, with a count when long), and the plugins it loads.
4. Define the guarantees: no ledger file is written; existing agent files are kept; no `git init` or staging inside an existing repository; a ledger that fails `bea check` still gets its files, and the report says what failed.
5. Record the contract in this task's Outcome and in `cli/docs/USAGE.md` beside `init --agent-files`.

## Outcome — 2026-11-13

**Command: `bea init --existing [PATH]`** (also `bea --file ROOT init --existing`). `init` is where a newcomer looks first and is already the only writer of agent files; `doctor` stays read-only. Without `--existing`, `init` keeps refusing every existing file.

**Root.** `--file ROOT` or a positional `.bean`/`.beancount` file names it outright. A positional directory (default `.`) uses bea's own discovery inside it (`main.bean`, then `main.beancount`), otherwise its only top-level `.bean`/`.beancount` file. Several candidates and no default name: exit 2, listing them and asking for the root. A missing root, a directory passed as `--file`, or a non-ledger file: exit 2. Options that only make sense for a new ledger (`--currency`, `--date`, `--opening-balance`, `--preset`, `--title`, `--module`, `--property-name`) are refused with exit 2 under `--existing`; `--agent-files` is implied.

**What the generated `AGENTS.md` states**, all read from the loaded ledger, in a separate existing-ledger template so `bea init --agent-files` output for a new ledger is unchanged:

- the root, and the files it reads (listed when few, counted when many);
- where new entries go: the root, unless a write names an included file with `--into` (an example is taken from the ledger's own includes), which is the destination rule `bea add` and `bea import` already follow;
- the operating currencies, or that none is set;
- the open accounts (listed up to a cap, with the total and the `bea list open` command beyond it);
- the plugins it loads, and the `PYTHONPATH` the check needs when a plugin is a module beside the ledger (the engine ignores the working directory's modules, `cli/tests/test_engine_ignores_cwd_modules.py`);
- the error baseline: "no errors" or "N errors when this file was written; a change must not add any";
- the same propose-before-write rule, check command, import-config line and skills link as the new-ledger template.

**Guarantees.** (1) No ledger file is written, and nothing is created in the ledger folder except the two agent files. (2) An existing `AGENTS.md` or `CLAUDE.md` is kept byte for byte, with `bea init --agent-files`'s created/kept/skipped semantics and the same JSON `data.agent_files`. (3) No `git init`, no staging. (4) A ledger that fails `bea check` still gets its files; the report lists what failed, and the command exits 0. Exit 2 is reserved for the usage refusals above.

**Report (t003).** Files loaded; each plugin with `file:line` and one of: loaded; a Beancount 2 plugin (`beancount.plugins.*`) that Beancount 3 no longer ships; a module beside the ledger that loads with `PYTHONPATH`; a third-party package the managed engine does not have, with the documented state as it stands (no `bea` command installs one; [w5/015](../../../../w5/blocked/015.md) is undecided). Other errors are counted and the first ones shown with `file:line`. The same data is in `--json` under `data`.

**Deviation:** the step said to record this in `cli/docs/USAGE.md` too. Documenting a command before it exists would mislead PyPI and README readers, so the USAGE section lands with the implementation in t002.

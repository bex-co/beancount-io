## Objective

Run `/simplify` over the code this milestone changed (reuse, simplification, efficiency; behavior-preserving), including any machinery it now shares with m43.

## Acceptance criteria

- [x] `/simplify` findings are applied or explicitly declined, and `yarn test` passes in `backend-cluster/backend-v2`.

## Outcome — 2026-11-13

`/simplify` ran four reviews (reuse, simplification, efficiency, altitude) over the m45 diff. Applied:

- **One removal plan (ledger).** `planSliceRemoval` is now the single place that resolves plugin rewrites, locates and checksums every slice on one snapshot, de-duplicates double-submitted pairs, and builds one re-locating delete transform per file.
  - `deleteMultiSourceSlices` and `moveSourceSlices` both call it. The move had a copy of the batch delete's planning, including the double-submit dedupe, and a fix to one copy would have missed the other.
- **Existing helpers instead of hand-built text (ledger):**
  - The include line now goes through `addIncludes`. It is escaped, written in `includeFrom`'s own line ending (w21/695), and placed after its last `include` rather than at its end (w23/062).
  - The target append writes the block after a blank line in the target's own line ending (w21/673), so moving CRLF entries no longer leaves mixed endings.
  - A new `toPath` must pass `assertPortableRepoPath`, as file creation requires (w23/054).
  - The ledger-file test is the loader's exported `BEAN_FILE_RE` rather than a third copy of the regex.
- **Efficiency (ledger):**
  - Trailing newlines are trimmed by scanning back from the end (`withoutTrailingNewlines`). The whole-file `/\n*$/` regex took about 45 ms on a 15 MB file, on each transform run.
  - File order is a map built once, rather than an `indexOf` inside the sort comparator.
- **One input mapper (backend-v2).** REST, GraphQL and MCP each resolved the hash alias and both flag twins by hand. All three now call `moveEntriesParams` (`utils/move-entries.ts`, renamed from `move-entries-description.ts`), which uses the shared `writeFlagsInput`.
- **Docs.** `docs/mcp.md` now says the order is by file path, then line (the loaded files are listed sorted, not in include order), and states where the include line goes and the portable-name rule.
- **Tests.** `move-source-slices.test.ts` adds two tests, and both fail on the pre-refactor service (2 of 12 failed):
  - a CRLF target keeps CRLF, and the include is placed after the other include;
  - a non-portable new target is refused.

Declined:

- **GraphQL `MoveEntrySourcesInput extends DeleteMultiSourceSlicesInput`:** the inherited `allowInvalid` description says "Delete the entries…". The sibling slice inputs declare their own fields.
- **`MoveEntrySourcesResponse extends WriteVerdict` with `flattenValidation`:** that adds `checked`/`checkError` to the GraphQL type, a schema change the REST result does not have. The sibling slice responses also declare the four fields themselves.
- **Dropping `toPath` from the result, and `movedHashes` from MCP (it equals `entryHashes`):** both are contract changes for little gain. `toPath` names the target in a result an agent may log without its request.
- **A typed `details.action` enum in the ledger IDL:** an error-details schema the IDL has never had. This is out of scope; the parity test pins the `move` wording on all three surfaces.
- **Moving the backend-v2 entry cap above authorization:** it only affects refused requests, and the batch delete has the same order.

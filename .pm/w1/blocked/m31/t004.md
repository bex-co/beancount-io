## Blocked

**Blocked 2026-10-08.** The conformance half holds: production advertises `client_id_metadata_document_supported: true`, and check 16 passes. The Claude Code half does not yet. Starting sign-in from Claude Code 2.1.289 against `https://beancount.io/api-gateway/mcp` sent an opaque `client_id`, not `https://claude.ai/oauth/claude-code-client-metadata`. Claude Code reuses the DCR registration it stored in its secure storage before CIMD was deployed, so this connection cannot show the CIMD path. **Unblock:** the user clears the `beancount` server's stored authentication in Claude Code (`/mcp` → beancount → clear authentication, or remove and re-add the server). The next sign-in's authorization URL should then carry the CIMD `client_id`. Record it and approve with one ledger. **Who can clear it:** the user. Clearing it touches their Claude Code credential store.

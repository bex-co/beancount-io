## Objective

Enable `features.clientIdMetadataDocument` so discovery advertises `client_id_metadata_document_supported: true` and Claude and ChatGPT identify themselves by URL instead of registering a new client per connection.

## Context

- backend-cluster/backend-v2/src/features/oauth/api/oidc-route.ts
- oidc-provider ships CIMD as experimental draft-02: `{ enabled: true, ack: "draft-02" }` must be re-acknowledged when an upgrade moves the draft.
- DCR stays enabled; `allowFetch`/`allowClient` stay permissive (ADR 019 D6).
- Depends on w1/m30 being on production.

## Steps

1. Enable the feature with the ack.
2. Add a test that fails with a clear message if the installed oidc-provider no longer accepts `draft-02`.
3. Confirm every w1/m30 DCR fixture still passes.

## Files

- backend-cluster/backend-v2/src/features/oauth/api/oidc-route.ts
- backend-cluster/backend-v2/src/features/oauth/api/__tests__/oidc-route.test.ts

## Acceptance criteria

- [x] Discovery metadata includes `client_id_metadata_document_supported: true` in tests.
- [x] All w1/m30 fixtures still pass.

## Out of scope

- Allowlisting hosts (rejected in ADR 019).

## Result

2026-10-06. `features.clientIdMetadataDocument: { enabled: true, ack: CIMD_DRAFT }` with `CIMD_DRAFT = "draft-02"` exported from `oidc-route.ts`; DCR stays enabled. Tests: discovery advertises `client_id_metadata_document_supported: true` with `none` and a registration endpoint; a draft test reads the installed oidc-provider's CIMD version and fails naming both drafts when an upgrade moves it (mutation to `draft-03` turns it red).

## Objective

Extend `yarn mcp:conformance` with read-only checks for the metadata hosts refuse to proceed without, so a deployment that would fail a host fails the check first.

## Context

- backend-cluster/backend-v2/scripts/mcp-conformance.ts
- Checks: `S256` in `code_challenge_methods_supported`; `authorization_response_iss_parameter_supported: true`; a `registration_endpoint`; `none` in `token_endpoint_auth_methods_supported`; protected-resource `resource` equal to the probed URL.
- It must still register nothing against a deployment.

## Steps

1. Add the five checks with clear failure messages naming the host that depends on each.
2. Unit-test each check against good and bad metadata fixtures.

## Files

- backend-cluster/backend-v2/scripts/mcp-conformance.ts

## Acceptance criteria

- [x] Each check fails on a fixture missing its field and passes on production's current metadata.
- [x] The script performs no writes.

## Out of scope

- The CIMD check (w1/m31).

## Result

2026-10-06. Checks 11–15 (`pkce-s256`, `iss-parameter`, `registration-endpoint`, `public-client-auth`, `resource-matches`) follow the 401 pointer to the protected-resource document and the first authorization server's RFC 8414 metadata (path insertion for a prefixed issuer, OIDC discovery fallback); each failure names the hosts it locks out, and each skips when discovery cannot be followed. All five pass against `https://beancount.io`. Tests in `scripts/__tests__/mcp-conformance.test.ts` break each field once (a forced-pass mutation of the S256 judge turns the suite red). Documented in `docs/mcp.md` and `backend-cluster/backend-v2/AGENTS.md`.

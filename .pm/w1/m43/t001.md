## Objective

Decide exactly what a rename changes, what it refuses, and what it returns, before any code.

## Context

- Account names appear in postings and in `open`, `close`, `balance`, `pad`, `note` and `document` directives, and as account-typed `custom` arguments (budgets, for example).
- The hosted write contract: `dry_run`/`dryRun` previews, `allowInvalid`/`allow_invalid` overrides the new-error gate, and every committing write returns `commit` (w23/m42). See `backend-cluster/backend-v2/docs/mcp.md`, "The preview rule".
- Plaid accounts store a `ledger_account` (`src/features/plaid/data/plaid-account-model/schema.ts`).

## Steps

1. List every reference kind that is renamed, and state that descendants (`Old:*`) move with it.
2. List what is never touched: quoted strings, comments, string metadata values, and other accounts that share a prefix.
3. List the refusals and their codes: invalid target name (`BAD_USER_INPUT`), target already open (merging is out of scope), unknown source account (`NOT_FOUND`), stale HEAD, and new bean-check errors (`VALIDATION_FAILED` unless `allowInvalid`).
4. Decide whether changing the root type (for example `Assets:` to `Liabilities:`) is allowed, and how the result says so.
5. Define the result: per-file changed lines on preview, counts, affected bank mappings, and `commit` on a real write.

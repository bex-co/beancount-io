## Objective

Decide exactly what a rename changes, what it refuses, and what it returns, before any code.

## Context

- Account names appear in postings and in `open`, `close`, `balance`, `pad`, `note` and `document` directives, and as account-typed `custom` arguments (budgets, for example).
- The hosted write contract: `dry_run`/`dryRun` previews, `allowInvalid`/`allow_invalid` overrides the new-error gate, and every committing write returns `commit` (w23/m42). See `backend-cluster/backend-v2/docs/mcp.md`, "The preview rule".
- Plaid accounts store a `ledger_account` (`src/features/plaid/data/plaid-account-model/schema.ts`).

## Steps

1. List every reference kind that is renamed, and state that descendants (`Old:*`) move with it.
2. List what is never touched: quoted strings, comments, string metadata values, and other accounts that share a prefix.
3. List the refusals and their codes: invalid target name (`BAD_USER_INPUT`), target already open (merging is out of scope), unknown source account (`NOT_FOUND`), stale HEAD, and new bean-check errors (`VALIDATION_FAILED` unless `allowInvalid`).
4. Decide whether changing the root type (for example `Assets:` to `Liabilities:`) is allowed, and how the result says so.
5. Define the result: per-file changed lines on preview, counts, affected bank mappings, and `commit` on a real write.

## Outcome — 2026-11-13

**Operation:** rename one account, and every account under it, across the ledger's loaded source files in one commit. Inputs are `from` and `to` (account names), plus `dry_run`/`dryRun` and `allowInvalid`/`allow_invalid` with the shared meanings. MCP `renameAccount`, REST `POST /api-gateway/v1/ledgers/{owner}/{name}/rename-account`, GraphQL `renameLedgerAccount`.

**What is renamed:** every account *token* outside strings and comments that names `from` exactly or starts with `from:`. That covers:

- postings;
- `open`, `close`, `balance`, `pad` (both accounts), `note` and `document` directives;
- account-typed (bare) values in `custom` directives, such as budgets;
- account-typed metadata values.

A token matches only on whole account names: renaming `Assets:Check` leaves `Assets:Checking` alone.

**Never touched:** quoted strings (payee, narration, string metadata, `note` comments, plugin configuration strings, string `custom` arguments), `;` comments, `option` lines, org-mode `*` headings, and files the ledger does not load.

**Refusals (nothing written):**

| Case | Code |
| --- | --- |
| `to` is not a valid account name | `BAD_USER_INPUT` |
| `to` is under a different root (`Assets:` to `Liabilities:`) | `BAD_USER_INPUT`, naming both roots. That is a reclassification, which changes report signs, not a rename. |
| `from` equals `to` | `BAD_USER_INPUT` |
| no loaded file names `from` or an account under it | `NOT_FOUND` |
| `to`, or any account a descendant would become, is already in the ledger | `BAD_USER_INPUT` ("renaming onto an existing account would merge them"; merging is out of scope) |
| a file changed between the read and the commit | `CONFLICT` (per-file sha on the commit) |
| the write adds a bean-check error the ledger did not have | `VALIDATION_FAILED`, unless `allowInvalid` |
| a credential without `ledger.files.write` | `FORBIDDEN` |

**Result:**

- `from` and `to`;
- `accounts`: each `{from, to}` pair renamed, descendants included;
- `files`: each `{path, changes}`, where each change is `{line, before, after}` for one source line;
- `bankMappings`: each `{plaidAccount, from, to}` mapping that follows the rename (t003);
- `validation`, with the shared shape;
- `dry_run`;
- `commit`, the sha on a real write, as every committing write returns it (w23/m42).

A preview returns the same result without `commit` and writes nothing. Undo is `revertCommit` on that sha.

**Building blocks on `main`:**

- `runWriteWithValidation` (`src/features/ledger/utils/write-validation.ts`), as `renameLedgerFile` uses it;
- `ledgerRepo.changeFiles`, which commits atomically with per-file sha checks;
- `projectedSourceFiles` and the ledger service's `getLedgerFilesContent` for the loaded files;
- `account-matcher.ts`'s account grammar for validating `to`;
- `plaid_accounts.ledger_account` for the mappings.

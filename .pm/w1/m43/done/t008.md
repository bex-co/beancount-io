## Outcome — 2026-11-13

`/simplify` ran four reviews (reuse, simplification, efficiency, altitude) over the m43 rename code (`ce28f2ec5..` scoped to its files).

**Applied:**
- **Scanner (`utils/account-rename.ts`):**
  - One name-character rule, matching the loader: ASCII letters, digits and `-`, or any non-ASCII non-space non-control character. Before, `\p{N}` accepted `²`, and a non-ASCII symbol such as `€` ended a name, so `Assets:Savings€` would have been rewritten as a child. A new test covers it.
  - The line-start state is derived, and one `continuesName` rule replaces three different `undefined` guards.
  - `accountNamesUnder`, `accountNamesAt` and `renameAccountName` are shared by the workflow's name list, its merge check and the bank-mapping filter. Before, `renamedAccounts(texts, to, to)` served as an identity map.
- **Workflow:**
  - Each file is scanned for `from` once. The offsets drive the names, the rewrite (`renameAccountAt`) and skipping unchanged files. Before, `from` was scanned three times; measured on a 14 MB ledger, 175 ms against 49 ms.
  - The bank-mapping read runs concurrently with the bean-check gate.
  - `bankMappings` is required, and one `mappingsUpdated` state carries the outcome.
  - The not-found hint and the left-behind message no longer name MCP-only tools, since they reach REST and GraphQL too.
  - A lossy-file refusal carries the shared fix-it hint.
- **Types and wiring:**
  - `account-rename-workflow.types.ts` holds `IAccountRenameWorkflow`, the input/result types and `ILedgerBankMappings`, so the Plaid adapter no longer imports a workflow module, and `LedgerWorkflow` types the injected rename by its interface (the backend AGENTS rule).
  - `RENAME_ACCOUNT_DESCRIPTION` lives in the utils module. Each surface appends its own preview and undo names (`revertCommit`, `POST …/revert-commit`, `revertLedgerCommit`) instead of all three saying the MCP name.
  - `flag-alias.writeFlagsInput` replaces three hand-written dry-run/allow-invalid mappings.
  - The REST handler's re-export is gone, and MCP destructures the result once.
  - The stale "only the append workflow" comment on `changeGeneratedFiles` now names both internal writers.
- **Plaid:** the owner check is hoisted out of the inner loop, and `remap` takes `Omit<LedgerBankMapping, "name">`. `plaid/AGENTS.md` records why this adapter reads every member's mappings by `ledgerRepoId` alone, and why it authorizes nothing itself.
- OpenAPI regenerated, and the CLI spec and client re-synced (description text only).

**Declined, with reasons:**
- **Moving the rename to a sibling `WorkflowLayer` workflow with an internal writer**, instead of `LedgerWorkflow` delegation plus the widened `ledgerRepo` type. It would touch the MCP context, the MCP route and the resolver registry, plus the layer revert. The simplification reviewer judged the cost greater than the gain; the interface typing and the corrected comment address the type-level concern.
- **One join query instead of N+1 per bank connection**, the admin client for the repo id, and a bulk `UPDATE`. These are model-layer changes for a path that runs once per rename, with a handful of connections.
- **Truncating `files[].changes`, and one top-level `updated`:** both would change the result contract recorded in t001.
- **REST `dryRunBody`:** it would make the flag nullable in the OpenAPI document, unlike the sibling `rename-file` route.
- **Test-helper consolidation** (shared fakes, `afterEach`): optional.

## Objective

A Plaid account mapped to the renamed account, or to one under it, maps to the new name after the commit, so the next bank sync does not post to an account that no longer exists.

## Context

- `ledger_account` on `plaid_accounts` (`src/features/plaid/data/plaid-account-model/schema.ts`) holds the mapped ledger account; `mapBankAccount` sets it.
- `syncBankTransactions` and `importStagedBankTransactions` write to the mapped account.

## Steps

1. In the rename workflow, list the ledger's mappings that name the old account or a descendant, and include them in the preview.
2. After the commit succeeds, update those mappings. If that update fails, the result must say which mappings still name the old account, and the operation must report a failure rather than plain success.
3. Test a mapped account, a mapped descendant, an unrelated mapping, and a failed mapping update.

## Files

- `backend-cluster/backend-v2/src/features/plaid/`
- the rename workflow from t002

## Acceptance criteria

- [ ] After a rename, every affected mapping names the new account, and the preview listed it first.
- [ ] A mapping update failure is reported in the result with the mappings it left behind.

## Out of scope

- Mappings in other ledgers.

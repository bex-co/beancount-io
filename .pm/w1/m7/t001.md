## Objective

Treat a just-completed password login or OTP verification as the user's interaction and finish the OAuth interaction without rendering an approve step.

## Context

- `dashboard/src/features/oauth/pages/mobile-consent.tsx` moves to `ApproveStep` on `authenticated`; that step posts `decision=approve` plus a hidden `scope` to `/oauth/mobile-consent?uid=…&scope=…`, proxied by `funcs/handle-mobile-consent-post.ts` to `/api-gateway/oauth/interaction/:uid/login`.
- The backend requires the posted `scope` to equal the interaction's `params.scope` for the mobile client and refuses non-session credentials (`assertSessionIdentity`) — both stay.
- `verifySignUpOtp` and `signIn` already set the session cookie the POST relies on.

## Steps

1. On the `authenticated` transition, submit the same form programmatically (hidden `scope`, `decision=approve`) instead of rendering `ApproveStep`; render a short "Returning to Beancount…" state while the POST is in flight.
2. Keep a visible retry if the POST fails (network or 4xx) so the user is never stuck on a blank page.
3. Update the reducer so `authenticated` leads to a `returning` step; adjust `mobile-consent-state.test.ts`.

## Acceptance criteria

- [ ] After password login or OTP success, the browser is redirected to the app callback with no click.
- [ ] A failed submission shows an error with a retry, and `uid`/`scope` are preserved.
- [ ] `yarn lint && yarn test` pass from `dashboard/`.

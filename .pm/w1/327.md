# Feeding `bea list transaction --json` back to `bea add transactions` writes an omitted leg's inferred amount as a literal: a `{{100.00 USD}}` purchase comes back as `-99.99999999999999999999999999 USD`, exit 0, and every report then prints USD to 26 decimals

**Bug · cli · minor · 45–60m · A1.** From routine cli-qa, 2026-11-19, at `6a458711f` (`bea 0.4.1`, checkout `uv run bea`, macOS 26.5 arm64, Python 3.12.14). Isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, no `BEA_FILE`/`BEA_TOKEN`, stdin closed, no TTY.

`docs/USAGE.md` ("Listing directives") promises that a listing "can be fed straight back in" to `bea add transactions`, which is how an agent copies a recurring purchase or moves entries. The listing completes every leg the ledger line left open with the amount booking inferred for it. Only an undated lot's quantity carries `"inferred": true` (w5/1018), so the replay writes every other inferred leg as a literal. For a total cost or total price, that literal is Beancount's 28-digit quotient. It is the same harm w1/313 and w1/317 closed for `100/3`-style arithmetic: the replay exits 0, `bea check` passes, and from then on every report prints the currency with all those digits.

## Reproduce

`main.bean`:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Cash USD
2026-01-01 open Assets:Broker
2026-01-01 open Assets:Euro EUR
2026-01-01 open Equity:Opening USD
2026-01-01 open Expenses:Food USD

2026-01-01 * "Start"
  Assets:Cash  1000.00 USD
  Equity:Opening

2026-01-02 * "Buy"
  Assets:Broker  3 HOOL {{100.00 USD}}
  Assets:Cash

2026-01-03 * "Exchange"
  Assets:Euro  50.00 EUR @ 1.1 USD
  Assets:Cash

2026-01-04 * "Lunch"
  Expenses:Food  12.50 USD
  Assets:Cash
```

Before any replay, `bea --file main.bean report balance-sheet -x units` shows `Cash 832.50 USD`. Replay one entry a month later. Each command starts from the pristine file:

```bash
bea --json --file main.bean list transaction --search Buy \
  | jq '.data | map(.date = "2026-02-02")' \
  | bea --file main.bean add transactions --from -
bea --file main.bean report balance-sheet -x units
```

| Replayed | Line `add transactions` writes for the omitted cash leg | `report balance-sheet -x units` afterwards |
| --- | --- | --- |
| `Buy` (`{{100.00 USD}}`) | `Assets:Cash    -99.99999999999999999999999999 USD`, with `3 HOOL {33.33333333333333333333333333 USD, 2026-01-02}` | `Cash 732.50000000000000000000000000 USD`, `Equity -1,000.000000000000000000000000000 USD`; `report income-statement` shows `Expenses 12.50000000000000000000000000 USD` |
| `Exchange` (`@ 1.1 USD`) | `Assets:Cash    -55.000 USD` | `Cash 777.500 USD`, `Expenses 12.500 USD` |
| `Lunch` (control) | `Assets:Cash     -12.50 USD` | `Cash 820.00 USD`: no change in precision |

Every replay exits 0 and `bea check` exits 0 afterwards. A `3 EUR @@ 10.00 USD` exchange replays the same way, as `-9.999999999999999999999999999 USD`. Marking the cash leg in that JSON by hand with `"units": {…, "inferred": true}` makes `add transactions` write `Assets:Cash  USD`. Booking then infers the same amount, and after both replays the balance sheet reads `Cash 677.50 USD`, still in cents. The existing write path already does the right thing once the listing says the leg was inferred.

## Cause

- `cli/src/bea_engine/ledger/reader.py:630` sets `inferred = cost is not None and cost.date is None and _number_left_open(p)`. Only an undated lot is ever asked whether its line left the number open (`_number_left_open`, `:535`). An omitted cash leg is listed with its booked number and no marker (`listing.py:55` copies the flag).
- `cli/src/bea_engine/ledger/adding.py:1523` already writes a posting with an `inferred` number number-less. The w5/1018 check in `_misstated_inferences` (`:2627`) refuses a stated number that booking would not infer.
- `report.written_precision` (`cli/src/bea_engine/report.py:2623`) does not learn precision from a posting booking interpolated (`__automatic__`, `:2666`). That is why the source ledger reads in cents. The replayed literal is no longer interpolated, so it counts as written precision.

## Fix

A `list transaction` posting whose source line leaves its units number to booking carries `"inferred": true`, whether or not it is a lot. Beancount marks every interpolated posting `__automatic__`, but it does so for an interpolated cost or price as well. So use the existing source-line test (`_number_left_open`), asked only of `__automatic__` postings to keep the parse cheap, so that a stated quantity with an interpolated `{USD}` cost is not marked. `add transactions` then writes that leg number-less, and booking infers the same amount again. Update the USAGE.md sentence "the key is absent everywhere else" to describe the wider rule. `--details` text keeps showing inferred amounts, as documented. Owning package: `cli` (engine reader). There is no hosted surface: the REST/GraphQL/MCP entry listings are a separate implementation, and this note does not change them.

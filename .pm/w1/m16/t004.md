## Objective

Make the first import a newcomer reads about the one that needs no code, and record the dependency decision so it is not relitigated.

## Context

- `cli/docs/IMPORTING.md` opens with the Beangulp interface and `CONFIG = [...]`; `cli/README.md` "Import bank exports" does the same.
- `docs/adrs/` holds every package's ADRs as `ADR<NNN>-<package>-<slug>.md`.
- Finding to record: beangulp 0.2.0 requires lxml, beautifulsoup4, chardet, click, and python-magic (libmagic on non-Windows); the Homebrew formula installs prebuilt wheels after relocation for a reason (w2/m25 notes), and adding native dependencies to the default install is a distribution risk. The mapper covers the common CSV case with the standard library; Python importers remain the path for OFX, QIF, and bank-specific formats.

## Steps

1. Restructure IMPORTING.md: "Import a CSV with a column mapping" first (mapping, rules, remembered mapping, the `!` queue), then "Use a Python importer", then duplicates and dependencies unchanged.
2. Mirror the ordering in the README section, keeping it short and linking to IMPORTING.md.
3. Write the ADR with the footprint table and the decision: not a hard dependency now; revisit if a wheel-only, libmagic-free beangulp ships.

## Objective

Make the weekly import one command by remembering the mapping, source account, and rules path the way `--config` is already remembered.

## Context

- `--config` is remembered per root ledger under the user configuration directory (`importers/<hash>.json`, documented in `cli/README.md` "Import bank exports").
- A user typically has one mapping per bank; keying by the CSV header row (column names) identifies the source without storing file contents.

## Steps

1. After a successful `--csv` preview or apply, store the mapping, account, default account, and rules path keyed by root ledger and the CSV header signature, alongside the remembered config path.
2. On `bea import file.csv` with no `--csv` and no `--config`, look up the header signature before falling back to `importers.py`; report `config_source: "remembered --csv"` in human and JSON output.
3. Explicit `--csv` or `--config` always wins and updates the memory.

## Files

- `cli/src/cli/commands/import_.py`
- `cli/README.md`, `cli/docs/USAGE.md` (configuration and stored state tables)

## Acceptance criteria

- [ ] After one `--csv` import, `bea import bank.csv --apply` works with no other flags and says where the mapping came from.
- [ ] A CSV with a different header does not reuse the mapping and reports the usual "choose an importer" guidance, now also naming `--csv`.

## Out of scope

- Sharing remembered mappings between machines.

## Objective

Give the mapper a way to categorize without a model and without code: a small rules file the user grows over time, and a visible queue for everything it does not match.

## Context

- The mapper from t001 posts every counter-leg to one account; real books need groceries, rent, salary.
- `cli/docs/PRFAQ.md` FAQ 7 rejects a built-in categorization model; a pattern file is configuration, not a model.
- `bea list transaction --flag '!'` already exists as the review queue.

## Steps

1. Accept `--rules FILE` in TOML: an ordered list of `{ match = "<regex>", account = "Expenses:Groceries" }` entries, matched case-insensitively against payee then narration; first match wins.
2. Unmatched rows post to `--default-account` (default `Expenses:Uncategorized`) with transaction flag `!`; if that account is not open, the existing validation error already names the `add open` command.
3. Show the matched rule (or "unmatched") as a column in the preview table and in JSON rows.
4. Reject an unreadable rules file or an invalid regex with exit 2 naming the entry.

## Files

- `cli/src/cli/commands/import_.py`
- `cli/docs/examples/rules.toml` (new, three rules)

## Acceptance criteria

- [ ] Rows matching a rule post to its account with flag `*`; unmatched rows post to the default with flag `!`.
- [ ] `bea list transaction --flag '!'` after apply lists exactly the unmatched rows.
- [ ] An invalid regex exits 2 and names the rule.

## Out of scope

- Learning rules from ledger history.

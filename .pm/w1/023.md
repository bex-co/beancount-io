# Add Budget offers every account type while its own help text says expense or income only

**Minor · 20–30m · dashboard.** A2: the dialog contradicts itself in the same viewport, so a newcomer cannot tell which accounts a budget is meant for.

Found 2026-09-13 by a dashboard QA sweep against production `https://beancount.io`, signed in, ledger `puncsky/example`, headless Chromium 1440×1000.

The Budget page and the Add Budget dialog both state:

> Set dated targets for **expense or income** accounts. Each card compares actual activity with the target that was active for that period.

The Account field's placeholder reinforces it: `Expenses:Groceries`. But the picker offers every account in the ledger. Typing `Assets` returns 12 asset accounts — `Assets:US:BofA:Checking`, `Assets:US:ETrade:GLD`, `Assets:US:Vanguard:RGAGX`, and so on — all selectable. The ledger already contains a budget on `Liabilities:AccountsPayable`, so this is reachable in practice, not just theoretically.

Repro:

1. Open `/ledger/<owner>/<ledger>/budget` and press **Add Budget**.
2. Read the dialog's help text: "expense or income accounts".
3. Click the Account field and type `Assets`.
4. The dropdown lists asset accounts as valid choices.

Expected: one of the two is authoritative — either the picker is filtered to `Expenses:` and `Income:` roots (matching the copy and the placeholder), or the copy is widened to say budgets may target any account.

Actual: the copy says one thing and the control does another, in the same dialog.

**No functional defect is claimed, and this is deliberately scoped as copy/validation only.** I checked whether a non-expense/income budget computes wrongly and it does not: `Liabilities:AccountsPayable` has 6 postings that net to zero over all history (`SELECT count(*) WHERE account ~ 'AccountsPayable'` → `6`; `SELECT account, sum(position) … GROUP BY account` → `{}`), and its card correctly reads `Latest actual 0 USD`. The `Expenses:Health:Life:GroupTermLife` card likewise correctly reads `0 USD` for the latest monthly period — that account's activity is entirely 2015–2017 (`SELECT year, sum(position) … GROUP BY year` → 2017 `437.76`, 2016 `632.32`, 2015 `656.64`; nothing in 2026). The budget math is sound; only the affordance and its description disagree.

Whoever picks this up should decide which way to resolve it — restricting the picker is a behavior change that could invalidate the existing `Liabilities:AccountsPayable` budget, so widening the copy may be the safer fix.

Smaller adjacent nit, same dialog, fix together or ignore: the Interval options are ordered alphabetically in the form (Daily, Monthly, Quarterly, Weekly, Yearly) but by duration in the page's own Interval filter (All, Daily, Weekly, Monthly, Quarterly, Yearly).

## Objective

`oidc-route.test.ts` grew about 700 lines in w1/m30–m32 and now carries several overlapping flow helpers (`driveAuthorizationCode`, `connectThirdParty`, `registerMcpClient`, `registerHost`, `authorizeHost`, `ageGrant`). `registerMcpClient` and `registerHost` look like the same job.

## Verdict

**Confirmed in part; the duplicate helpers are merged, the split is declined.** Three copies of the same public DCR `POST /oauth/reg` existed: `registerMcpClient`, `registerHost`, and an inline fetch in "keeps web rules for a dynamic client that states application_type web". `registerHost` now takes `overrides`. `registerMcpClient` is a three-line caller of it, and the web-rules test passes `{ application_type: "web", grant_types: [...] }`. One registration request remains in the file. The suite still runs 89 tests, all passing. Dropping the `application_type` override fails the web-rules test, so overrides do reach the request.

The other helpers do distinct jobs: `driveAuthorizationCode` runs the full login flow, `authorizeHost` stops at the first redirect, `connectThirdParty` composes registration, authorization, and exchange, and `ageGrant` rewrites storage.

**Declined: splitting the file by flow.** Every helper closes over one roughly 120-line Koa/oidc-provider `beforeAll` and its `ISSUER`. A split would first have to move that setup and the helpers into a fixture module, rewriting most of the 2,500-line file with no behavior or speed gain (it runs as one Jest worker either way). backend-v2 `typecheck`, `lint`, and `test` (5075 tests) pass.

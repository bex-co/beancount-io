## Objective

Tool annotations are hand-picked (`READ_ONLY`, `ADMIN_READ`, …), and the rule "`readOnlyHint` only for read-class verbs" is enforced by a guard test. `securitySchemes` is now derived from `VERB_TABLE` (`mcpToolSecuritySchemes`). Deriving `readOnlyHint` the same way would make the rule hold by construction, and `ADMIN_READ` would disappear as a separate choice.

## Context

- `backend-cluster/backend-v2/src/features/ai-agent/api/mcp-tools.ts` (annotation constants, `MCP_TOOLS`)
- `backend-cluster/backend-v2/src/server/api/op-class.ts` (`VERB_TABLE`, `mcpToolSecuritySchemes`)
- `backend-cluster/backend-v2/src/server/api/__tests__/mcp-tool-list.test.ts` (annotation guard)
- ADR 019 records the admin-read deviation.

## Steps

1. Check that every tool's current `readOnlyHint` equals "strongest class is read or public".
2. If it does for all tools, derive the hint, or assert the equivalence in one place. If a tool legitimately diverges, abandon and record which one.

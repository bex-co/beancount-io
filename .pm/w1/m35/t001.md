## Objective

`handleConsentRequesterGet` guards `fetch` with `.catch`, but `await upstream.json()` is outside it. A 200 response whose body is not JSON (a proxy error page, for example) throws, so the route returns a 500 instead of its documented 404. The consent page still fails closed, because approval stays disabled, but the server logs an unhandled error.

## Context

- `dashboard/src/features/oauth/funcs/consent-requester.ts` (around lines 62–79)
- `dashboard/src/features/oauth/funcs/__tests__/consent-requester.test.ts`
- Introduced in `def491ca` (w1/m30/t005).

## Steps

1. Write a test that stubs `fetch` with a 200 `text/html` body and asserts a 404 `null` response.
2. If it fails, move the `.json()` call under the same failure handling as `fetch`.

# `bea cloud git` compares server addresses as raw strings: Git gets no password for `Git.Example.com` or `:443`, and a trailing slash on `BEA_API_URL` makes `cloud logout` leave the Git token behind without a word

Found by `/qa-find-bugs-cli w1` on 2026-11-19 (HEAD `2ce41f23a`, `bea 0.4.1` from the checkout, macOS 26.5.1, Python 3.12.14, git 2.55.0, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, and `GIT_CONFIG_GLOBAL` pointing at a scratch file so the real Git config was never touched). Severity: minor. The code is from w22/m12 and has not been released yet, so this can land before that milestone's t007 release. A2: a self-hoster who copies a clone URL or `BEA_API_URL` with different capitals, an explicit `:443` or a trailing slash gets a password prompt, or a logout that does not sign Git out. Nothing says why.

**Repro.** The state file below is the one `bea cloud git setup` writes, filled in by hand because no self-hosted server was available. `git` and `bea` are the real executables. `BEA` is the absolute path to the checkout's `cli/.venv/bin/bea`.

```sh
export BEA_CONFIG_DIR=$PWD/cfg GIT_CONFIG_GLOBAL=$PWD/gitconfig GIT_CONFIG_NOSYSTEM=1 GIT_TERMINAL_PROMPT=0
mkdir -p cfg && cat > cfg/git-credential.json <<'EOF'
{"api_url": "https://api.example.com", "git_url": "https://git.example.com", "key_id": "k1", "key_name": "bea git on qa", "token": "synthetic", "expires_at": "2027-01-30T00:00:00+00:00"}
EOF
chmod 600 cfg/git-credential.json
printf '[credential "https://git.example.com"]\n\thelper =\n\thelper = !%s cloud git credential\n' "$BEA" > gitconfig
for u in https://git.example.com/a/b.git https://Git.Example.com/a/b.git https://git.example.com:443/a/b.git; do
  printf 'url=%s\n\n' "$u" | BEA_API_URL=https://api.example.com git credential fill; done
printf 'url=https://git.example.com/a/b.git\n\n' | BEA_API_URL=https://api.example.com/ git credential fill
BEA_API_URL=https://api.example.com/ "$BEA" cloud logout; cat cfg/git-credential.json   # signed out
```

**Actual.**

- Git matches `credential.<url>.helper` without regard to host case and treats an explicit default port as no port, so it does run `bea` for all three URLs. Git sends `host` exactly as the URL spells it, though (`host=Git.Example.com`, `host=git.example.com:443`). Only the lowercase URL gets `password=…`. The other two end in `fatal: could not read Username … terminal prompts disabled` (exit 128), and `bea` prints nothing on stdout or stderr.
- `BEA_API_URL=https://api.example.com/` (trailing slash), or `https://API.example.com`, gets the same silent non-answer for the lowercase URL. Every other `bea cloud` request is identical under either spelling: a local listener logged the same `GET /api-gateway/v1/ledgers` and `POST /api-gateway/ai/openai/chat/completions` paths with and without the slash.
- `cloud logout` with the trailing slash prints `Already logged out.` and exits 0. The Git token stays in `git-credential.json`, unrevoked and not mentioned. The same logout with the exact URL exits 1, names `'bea git on qa'` as a token it could not revoke, and clears the stored token. A signed-in logout takes the same branch, so it would revoke the session and leave Git's `ledger.write` token alive on the server and on disk, against USAGE's "`bea cloud logout` signs Git out too".

**Expected.** One server spelled two ways counts as one server. When the stored registration is for the address Git is asking about, `credential get` answers whatever the host's case and whether or not the default port is written. `logout`, `setup --undo`, a lapsed token's re-mint and `setup`'s "already set up for another server" check treat `https://api.example.com`, `https://api.example.com/` and `https://API.example.com` as the same server. They stay different from `https://other-api.example.com` and from another port. Those keep today's behavior, which `test_get_says_nothing_when_bea_points_at_another_server` and `test_get_says_nothing_for_any_other_address` cover.

**Root cause** (cli only).

- `_registered` (`cli/src/cli/commands/cloud/git/app.py:199`) builds `f"{protocol}://{host}"` from Git's request and compares it as a string with `state.git_url`. That stored value comes from `git_address` (`helper.py:144`), which takes `urlsplit().hostname`: always lowercase, with no port unless one was written.
- `GitSignIn.is_current_server` (`helper.py:79`) compares `settings().api_url == self.api_url` as raw strings. `setup` stores the raw value (`app.py:55`) and compares it raw again at `app.py:58`. `is_current_server` gates `_registered`, `_session_client` (`app.py:148`, which `setup --undo` and the lapsed-token re-mint use) and logout's `_revoke_git_token` (`cli/src/cli/commands/cloud/app.py:202`), whose early `return None` is what makes the logout silent.

**Fix.** Add one helper that reduces an address to its server identity: scheme and host lowercased, the scheme's default port dropped, and the path's trailing `/` stripped. Use it to compare Git's `protocol`/`host` with `git_url`, and the current `BEA_API_URL` with the stored `api_url`, at every caller above. Store normalized values at `setup`. Regressions: `credential get` answers for `host=Git.Example.com` and `host=git.example.com:443`; `get`, logout and `--undo` work when `BEA_API_URL` gains a trailing slash or capitals; another host, port or API server still gets nothing (the existing tests).

**Blast radius.** Only `bea cloud git` and the Git-token step of `bea cloud logout`. Other cloud commands pass `BEA_API_URL` to httpx as a base URL, which already absorbs the slash. Not exercised live: `setup` itself, against a real self-hosted server. Its `app.py:58` refusal under a respelled `BEA_API_URL` is traced in code only. w22/m12/t006's live check would not catch this, because it uses one spelling throughout.

**Dedupe.** Searched `.pm/**` for `credential get`, `credential helper`, `git-credential`, `is_current_server`, `trailing slash`, `lower case`/`case-insensitive`, `:443`. w22/m12 (blocked on its live check and release) shipped the code. None of its tasks, nor `cli/tests/test_cloud_git_sign_in.py`, covers address spelling. w5/480 fixed the same class of bug (trailing slash, capital letter, explicit `:443`) for `MANAGED_PRICE_ORIGINS`.

# Cloud HTTP errors with non-JSON bodies lose exit category and request ID

Severity: major for scripted auth/conflict handling. Estimate: 50–60m including
shared-transport regression coverage. Owner: CLI. A1: automation must be able to
branch on the documented HTTP-to-exit-code contract.

Reproduced twice using the actual checkout `uv run bea` 0.1.0 at main
`c6de619d9094e1ae45a248eef3e6ba3d74a5944f`, Python 3.13.0, macOS 26.5.1 arm64.
This is a loopback HTTP simulation of an intermediary response, **not a hosted
server defect**. Cwd `cli/`, closed stdin, no TTY; no real account or ledger.

Minimal reproducer from `cli/` (change 403 to 400/409/503 for adjacent cases):

```python
import os, subprocess, tempfile, threading
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer
from pathlib import Path
class Handler(BaseHTTPRequestHandler):
    def log_message(self, *args): pass
    def do_GET(self):
        self.send_response(403)
        self.send_header('Content-Type', 'text/html')
        self.send_header('X-Request-Id', 'qa-synthetic-request')
        self.end_headers()
        self.wfile.write(b'<html>Temporarily unavailable</html>')
server = ThreadingHTTPServer(('127.0.0.1', 0), Handler)
threading.Thread(target=server.serve_forever, daemon=True).start()
try:
    with tempfile.TemporaryDirectory(dir='tmp') as directory:
        env = os.environ.copy()
        env.pop('BEA_FILE', None)
        env.update(BEA_TOKEN='synthetic-invalid',
                   BEA_API_URL=f'http://127.0.0.1:{server.server_port}',
                   BEA_CONFIG_DIR=str(Path(directory).resolve()),
                   XDG_CACHE_HOME=str(Path(directory).resolve()/'cache'),
                   BEA_NO_UPDATE_NOTIFIER='1')
        p = subprocess.run(['uv','run','bea','--json','cloud','status'],
                           env=env, stdin=subprocess.DEVNULL,
                           capture_output=True, text=True, timeout=10)
        print(p.returncode, p.stdout, p.stderr)
finally:
    server.shutdown()
    server.server_close()
```

Actual: stdout empty; exit 1; JSON stderr category `validation`, message
`Expecting value: line 1 column 1 (char 0)`; request ID absent. HTTP
400/401/403/409 all wrongly exit 1 instead of 2/3/3/4. HTTP 429/500/503 retain
exit 1 but lose rate-limit/server diagnostics and the request ID.
Expected basis: `cli/docs/USAGE.md:108` maps by HTTP status and documents retaining
request IDs. Body parsing must not erase status/header evidence.

Controls: same statuses with
`{"ok":false,"error":{"code":"QA_ERROR","message":"Synthetic service failure"}}`
produce correct categories and request IDs. HTML HTTP 502 also correctly yields
`Server error (HTTP 502).` with request ID, because its body bypasses the strict
parser. Requests observed: GET `/api-gateway/v1/user-profile`. No file writes.

Root cause: generated `get_user_profile.py:69` and sibling documented-status
branches parse `response.json()` and `V1Error.from_dict` before constructing the
response. Thus `cli/src/cli/api/client.py:55` never receives the response and its
raw-body fallback cannot run. The top-level boundary reports the JSON decoder
exception instead. Shared caller search includes status, ledger list/show/
create/delete/clone and device auth; logout deliberately swallows errors.

Fix at the owning, non-generated transport/codegen seam: preserve HTTP error
status and headers even when the error body is HTML, empty, or malformed JSON;
use best-effort message parsing, falling back to HTTP status. Do not hand-edit
generated operation files or weaken the server contract. Add shared tests for
400/401/403/409/429/5xx, malformed/empty bodies, request IDs, and structured
controls; exercise status and a ledger command through subprocesses. Backend
REST/GraphQL/MCP behavior does not need to change for this client-only defect.

Dedupe: all open/completed board files searched for HTML errors, malformed
responses, V1Error and cloud error mapping. No open overlap. Follow-up gap in
completed `w1/done/m12` (t005's error-code acceptance): its DoD records transport
migration, generation and CI, while notes explicitly defer hosted verification.
History traces the parser/client seam to `481f313e`; no subsequent repair found.

Unverified: actual production intermediary behavior, interactive login, hosted

Loopback server stopped; synthetic environment token existed only in children.

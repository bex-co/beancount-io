# `bea --file books/main.bean update transaction --id 2026/jan.bean:1 --into 2026/jan.bean` reads `--into` from the ledger's folder but `--id`'s file from the working directory, and refuses with "No transaction with import-id or ref '2026/jan.bean:1'"

**Bug · cli · minor · ~30m · A1.** From routine cli-qa, 2026-11-20. `--id` takes an import-id, a `ref`, or `file:line` (USAGE § Updating directives). The TUTORIAL runs every command from the parent folder (`bea --file august/main.bean …`) and says to "pass the entry's `file:line` instead" of the import-id. Every other path `bea` takes for a ledger is relative to the root ledger's folder:

- `--into`, which `update` takes too ("relative to the root ledger");
- `include` lines;
- `add document --filename`;
- the `WRITTEN IN` column of `bea list document`.

The `FILE` of `--id` is the exception: it resolves against the working directory. When that path does not exist there, the id quietly falls through to the import-id/ref lookup. The refusal then talks about import-ids and never says that the file was not found or where `bea` looked. An agent or user who writes the location the way the rest of the command line is written gets exit 2. The same command run from inside the ledger's folder works.

Environment: main `1efafc9af`, `bea 0.5.0` from the checkout (`uv run bea`), Python 3.12.14, macOS 26 (Darwin 25.5.0) arm64. Isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, `BEA_FILE`/`BEA_TOKEN` unset, stdin closed, no TTY. Reproduced in fresh processes. Previews only, so nothing was written.

## Repro

Run from the folder that contains `books/`:

```sh
mkdir -p books/2026
cat > books/main.bean <<'EOF'
option "operating_currency" "USD"
include "2026/jan.bean"
2026-01-01 open Assets:Checking USD
2026-01-01 open Expenses:Uncategorized USD
2026-01-01 open Expenses:Dining USD
EOF
cat > books/2026/jan.bean <<'EOF'
2026-01-05 ! "Mystery"
  Expenses:Uncategorized 5.00 USD
  Assets:Checking
EOF
bea --file books/main.bean update transaction --id 2026/jan.bean:1 --into 2026/jan.bean --account Expenses:Dining        # 1
bea --file books/main.bean update transaction --id books/2026/jan.bean:1 --into 2026/jan.bean --account Expenses:Dining  # 2
printf 'id,account\n2026/jan.bean:1,Expenses:Dining\n' > map.csv
bea --file books/main.bean update transactions --from map.csv                                                            # 3
(cd books && bea --file main.bean update transaction --id 2026/jan.bean:1 --account Expenses:Dining)                     # 4
```

Actual:

1. Exit 2: `No transaction with import-id or ref '2026/jan.bean:1' in this ledger. Nothing was written.` `--json` gives the same message, category `usage`. In the same command, `--into 2026/jan.bean` resolved against `books/`.
2. Exit 0, the preview diff. `--id` wants the path from the working directory while `--into` wants it from the ledger's folder.
3. Row 1 is rejected with the same import-id message.
4. Control: exit 0, the preview diff. The two bases coincide here.

## Expected

A `FILE:LINE` id resolves the way `--into` does. When `FILE` names no file of this ledger relative to the working directory, it is tried relative to the root ledger's folder. Runs 1 and 3 then preview the diff, exit 0. An absolute path, or one that already works from the working directory, behaves as today, including `tests/test_update_locate.py::test_file_line_resolves_relative`. When the text has a `FILE:LINE` shape but names a file in neither place, the refusal says so: "`2026/jan.bean` is not a file under <cwd> or <ledger folder>". It does not say only that no import-id matched. A real import-id such as `stmt:42`, which names no file, still resolves as metadata.

## Cause

`parse_location` in `cli/src/bea_engine/ledger/updating.py:49-68` builds `Path(path_text)` and requires `path.is_file()`. That test is relative to the engine's working directory, which is the user's. When it fails, the function returns `None`, and `locate_transaction` (line 130) falls through to the metadata lookup. That lookup raises the import-id/ref refusal at line 167. `--into` is resolved against the root by `write.destination` (`cli/src/bea_engine/ledger/write.py:63`, "relative to the root ledger, independently of cwd").

## Fix

Owner `cli`, engine side. Pass the root ledger's folder into `parse_location` (or into `locate_transaction`). Keep the working-directory candidate first and add the root-relative one, then pick the candidate that names a file the loaded ledger contains. Extend the not-found refusal for a `FILE:LINE`-shaped id that names neither candidate. Name the base in `cli/docs/USAGE.md` § Updating directives, where `--id` is described.

Regressions:

- `locate_transaction` resolves the root-relative form from a different working directory;
- the CLI repro runs 1 and 3 preview (text and `--json`);
- the not-found wording;
- `stmt:42`-style ids and the existing `test_update_locate.py` and `test_update_unicode_digit_ids.py` cases still pass.

Revert the fix and watch the new tests fail. Run `make check-all` in `cli/`. No REST/GraphQL/MCP change: hosted entry edits take entry ids, not local paths.

## Dedupe

Searched `.pm/**` for `file:line` with `--id`, `update transaction`, `relative`, `working directory` and `No transaction with import-id or ref`. Ran `git log -S "def parse_location"` (introduced in `42c612c21`). Related, not duplicates:

- w5/1030 (done) matches decimal `ref` values copied from listings.
- w5/1041 (done) treats a Unicode-digit suffix as metadata, not a line.

Neither looks at the base directory, and no open or blocked item covers it.

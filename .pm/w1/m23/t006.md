## Objective

Three commands complete without performing their stated job and still exit 0: `treeify` when it finds no column to treeify, `ingest` with a `CONFIG = [...]` import file, and `format -i` on a directory containing no ledger files.

## Context

- `w3/338`: `bea treeify` exits 0 when it treeifies nothing, printing only a WARNING.
- `w3/317`: `bea ingest` with a `CONFIG = [...]` import file exits 0 and prints nothing.
- `w3/249`: `bea --json format -i` on a directory with no ledger files exits 0 with empty stdout, breaking the JSON contract as well.
- Commands: `cli/src/cli/commands/treeify.py`, `ingest.py`, `format.py`.

## Steps

1. Give each command an explicit no-op outcome: exit nonzero when the requested work could not be performed at all, and say why.
2. For `ingest`, detect the `CONFIG` convention the import file uses and either support it or refuse with the supported spelling named.
3. For `format` on an empty directory, emit the standard envelope with a zero-file result and a nonzero exit, consistent with the `--json` contract.

## Files

- cli/src/cli/commands/treeify.py
- cli/src/cli/commands/ingest.py
- cli/src/cli/commands/format.py
- cli/tests/test_ingest.py

## Acceptance criteria

- [ ] `bea treeify` on input with no account column exits nonzero and names what it looked for.
- [ ] `bea ingest` with a `CONFIG = [...]` file either runs or exits nonzero naming the supported form; it never exits 0 silently.
- [ ] `bea --json format -i EMPTYDIR` emits a parseable envelope and exits nonzero.
- [ ] Each command's success path is unchanged.

## Out of scope

- Adding new ingest capabilities beyond recognizing the config convention.
- The optional-engine JSON contract for `price` / `ingest` (`w3/312`), owned by m25.

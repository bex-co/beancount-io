## Objective

`--allow-errors` is meant to let a write proceed over a ledger that already has soft errors. Today it also suppresses errors the write itself introduces, so `add`, `add transactions`, and `import --apply` report success and exit 0 while leaving a ledger that `bea check` rejects. Scope the flag to errors that existed before the write.

## Context

- `w3/321` (major): `bea import --apply --allow-errors` writes rows whose counter-account was never opened, prints `Wrote 1 entry`, exits 0; the same import without the flag correctly refuses.
- `w3/323` (major): the same for `add transaction`, `add note`, `add close`, and bulk rows with an unknown account or a currency mismatch.
- Write validation lives engine-side in `cli/src/bea_engine/ledger/write.py`; the flag is surfaced by `cli/src/cli/commands/add.py` and `cli/src/cli/commands/import_.py`.

## Steps

1. Capture the ledger's error set before the write and compare it with the error set after the projected write.
2. Let `--allow-errors` tolerate only errors present in the before set; any newly introduced error fails the write regardless of the flag.
3. Keep the atomic-write contract: a refused write leaves the ledger unchanged.
4. Report the newly introduced errors in the failure message so the caller knows which row or posting caused it.
5. Apply the same rule to every command that accepts the flag, including bulk `add transactions` and `import --apply`.

## Files

- cli/src/bea_engine/ledger/write.py
- cli/src/cli/commands/add.py
- cli/src/cli/commands/import_.py
- cli/tests/test_ledger_safety.py

## Acceptance criteria

- [ ] With `--allow-errors`, a write that would introduce an unknown account or a currency mismatch exits nonzero and writes nothing.
- [ ] With `--allow-errors` over a ledger that already fails `bea check`, an otherwise valid write still succeeds — the flag keeps its purpose.
- [ ] After any exit-0 write, `bea check` reports no error that was absent before the write.
- [ ] The failure message names the introduced error and the offending row.

## Out of scope

- Changing the default (no-flag) behavior, which already refuses correctly.
- Redefining which upstream diagnostics count as errors versus warnings.

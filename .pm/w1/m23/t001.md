## Objective

`bea query -o` pointed at the ledger it is reading truncates the books to zero bytes (human mode) or overwrites them with a JSON envelope, then exits 0 — the one data-loss path in the sweep. Refuse any `-o` / `--output` destination that resolves to the root ledger or to any file in its include closure, and stop `bea example -o` from silently replacing an existing ledger.

## Context

- `w3/300` (critical): `bea --file main.bean query 'PRINT' -o main.bean` exits 0, leaves `main.bean` 0 bytes; `--json` leaves a JSON envelope that `bea check` rejects with `unexpected LCURL`.
- Reproduces with `SELECT account` as well as `PRINT`, with relative paths on both flags, and with two distinct paths that share an inode (hard link).
- Interactive `.output PATH` inside `bea query` is the same class of destination and must be covered.
- `w3/336`: `bea example -o PATH` silently overwrites an existing ledger and exits 0.
- Output destinations are resolved in `cli/src/cli/output.py`; the query command owns `-o` in `cli/src/cli/commands/query.py`.

## Steps

1. Add one destination guard that compares the resolved, symlink- and hard-link-aware identity (`os.stat` device plus inode, falling back to `Path.resolve()`) of the output path against the root ledger and every file in its include closure.
2. Apply the guard before any temp file is created or any stream is opened, so a refusal leaves the destination untouched.
3. Wire the guard into `query -o`, the interactive `.output` handler, and every other command that accepts `-o` / `--output`.
4. Exit 2 with a usage error naming the destination and the ledger it collides with, in both human and `--json` mode.
5. Make `bea example -o` refuse an existing file unless an explicit overwrite flag is passed, with the same exit code and message shape.

## Acceptance criteria

- [ ] `bea --file main.bean query 'PRINT' -o main.bean` exits 2 and `main.bean` is byte-identical afterwards (checked by hash).
- [ ] The same holds for `--json`, for relative `./main.bean` on either flag, for a hard link to the ledger, for a file reached through an `include`, and for interactive `.output` on the ledger path.
- [ ] `bea example -o EXISTING` exits 2 without touching the file; with the explicit overwrite flag it succeeds.
- [ ] A legitimate `-o` destination (new file, existing unrelated file) still works exactly as before.

## Out of scope

- Redesigning the output-format selection (`w3/324` is separate).
- Backup or undo functionality — the fix is refusal, not recovery.

## Objective

Several `bea doctor` operations print errors, or resolve an empty scope, and still exit 0. A CI gate or agent that runs them as a check gets a false green — `print-options` is worst, dumping default options as if the named file had loaded.

## Context

- `w3/345`: `doctor parse`, `lex`, and `print-options` exit 0 on syntax-invalid ledgers that `bea check` exits 1 on.
- `w3/363`: `doctor linked` / `region` exit 0 on an empty scope (missing link, no entries).
- `w3/364`: `doctor missing-open` exits 0 with no output when postings hit a pre-closed account.
- `w3/369`: `doctor directories` prints ERROR lines and exits 0.
- `w3/371`: `doctor roundtrip` prints `Congratulations` and exits 0 on ledgers `bea check` rejects.
- Doctor operations are native forwards registered in `cli/src/cli/commands/doctor.py`; w1/m22 already added native help there.

## Steps

1. For each affected operation, decide and document the exit contract: error output or a failed load is nonzero; an empty scope is a distinct nonzero code or an explicit empty-but-valid message.
2. Detect the upstream failure rather than trusting the child's exit status where upstream returns 0 regardless.
3. Make `print-options` refuse to print defaults for a file that did not load.
4. Record the per-operation contract in `cli/docs/USAGE.md` so the table is the spec.

## Objective

Give the CLI its own pinned copy of the v1 OpenAPI spec — the same discipline as the current pinned `graphql/schema.graphql` — plus a `make` target that fails when the pin drifts from the canonical spec in `backend-cluster/idl/`, wired into `make check-all`.

## Context

- Today the CLI pins `cli/graphql/schema.graphql`; the REST era pins `cli/openapi/v1.json` (or `.yaml`, matching the idl format).
- The drift check compares two files inside this monorepo — no network, safe for CI (`ci-cli.yml` runs `make check-all`).
- Codegen (t004, t007) must read only the pin, never `idl/` directly, so CLI builds are reproducible from `cli/` alone.

## Steps

1. Copy the regenerated v1 spec into `cli/openapi/` as the pinned snapshot.
2. Add `make spec-check` diffing the pin against the canonical file in `backend-cluster/idl/`, with a one-line "run make spec-sync" failure message; add `make spec-sync` to refresh the pin.
3. Include `spec-check` in `make check-all`.

## Files

- `cli/openapi/` (new)
- `cli/Makefile`

## Acceptance criteria

- [ ] `make spec-check` passes when in sync and fails with actionable output when `idl/` changes.
- [ ] `make check-all` includes the check and stays green.

## Out of scope

- Client generation (t004) — this task only establishes the contract file.

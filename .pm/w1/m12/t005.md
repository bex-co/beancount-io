## Objective

Move every `bea cloud` command — login/logout/status and ledger list/create/delete/clone — onto the generated REST client, and establish a deterministic HTTP-status → exit-code + message mapping so failures are legible to humans and scriptable for agents.

## Context

- Commands live under `cli/src/cli/commands/cloud/` (post-m11); error presentation goes through the single error boundary in `cli/src/cli/errors.py`.
- Repo rule: hosted mutations must use the credentials/API abstractions and surface failures without hiding them.
- Mapping baseline: 401/403 → auth error with "run `bea cloud login`" guidance; 404 → not-found; 4xx validation → usage error with the server's message; 5xx/network → distinct transient-failure exit code.

## Steps

1. Migrate the auth-session flow (login's create/poll/consume, logout, status) to the REST endpoints from t002, using t001's mapping table.
2. Migrate the ledger commands; keep output formatting identical.
3. Implement the status → exit-code mapping in the error boundary; document the codes in `docs/USAGE.md`.
4. Exercise each command against a live or local backend (`deploy/docker-mac/` stack) end to end.

## Files

- `cli/src/cli/commands/cloud/`
- `cli/src/cli/auth/credentials.py` (if the token flow shape changes)
- `cli/src/cli/errors.py`, `cli/docs/USAGE.md`

## Acceptance criteria

- [ ] All seven commands succeed against a running backend over REST; no code path imports `gql_client`.
- [ ] Auth-failure, not-found, and server-error cases exit with the documented codes and messages.

## Out of scope

- Deleting GraphQL artifacts (t006) — do that only after this task proves the REST path.

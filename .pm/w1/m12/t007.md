## Objective

Build the piece that lets `bea cloud` grow from the spec: a small in-repo generator that reads the pinned snapshot and emits committed Typer command stubs for CLI-tagged operations — spec annotations become help text and validation, `x-cli-destructive` becomes a confirmation prompt, and generation **fails** on under-annotated operations. Generated stubs are the 90%; curation on top stays possible.

## Context

- Spec-driven, not spec-generated: build-time codegen committed to the repo (reviewable diffs, strict mypy, fast startup) — not restish-style runtime mounting.
- Mapping: OpenAPI tag → command group; `operationId`/`x-cli-name` → command name; `summary`/`description` → help; schema constraints (enum, pattern, min/max, required) → Typer argument validation; `x-cli-destructive: true` → `typer.confirm` guard; `x-cli-hidden` → skipped.
- Prove it on the real surface: regenerate `cloud ledger list|create|delete` from the spec; `clone` and `login` stay hand-curated (multi-step flows).

## Steps

1. Write the generator (e.g. `cli/scripts/gen_cloud_commands.py`) reading `cli/openapi/`, emitting into `cli/src/cli/commands/cloud/generated/`; hook it into `make codegen`.
2. Implement the gate: any included operation missing `summary` or `description` fails generation with the operation name and what's missing.
3. Swap the hand-written ledger list/create/delete stubs for generated ones; confirm `--help` and behavior are equal or better (delete must now prompt via `x-cli-destructive`).
4. Document the workflow in `cli/CLAUDE.md`: to add a cloud command, annotate + tag the operation in backend-v2, sync the pin, regenerate.

## Files

- `cli/scripts/gen_cloud_commands.py` (new)
- `cli/src/cli/commands/cloud/generated/` (new, committed)
- `cli/Makefile`, `cli/CLAUDE.md`

## Acceptance criteria

- [ ] `make codegen` regenerates stubs reproducibly; stripping a `description` from a tagged op in a scratch spec makes generation fail naming that op.
- [ ] `bea cloud ledger delete` prompts for confirmation; `--yes`/`--force` bypasses it.
- [ ] `make check-all` green with generated commands active.

## Out of scope

- Generating multi-step flows (login, clone) — permanently curated.
- Backend spec-annotation work beyond what t002 landed.

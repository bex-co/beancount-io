# `--into` a new file in a missing directory says only "Create the directory first"; doing that gets a second refusal, because the file was never included

**Source:** routine cli-qa, 2026-11-19. **Severity:** minor. **Estimate:** 15–20 minutes. **Owner:** cli. **A1:** an agent splitting a ledger by year runs `bea add transaction … --into 2024/q2.bean` and is told `Write destination directory …/2024 does not exist. … Create the directory first.` It creates the directory, reruns the same command, and gets a different refusal: `Write destination …/2024/q2.bean is not included by …/main.bean. … Create it and add an include directive to the root first.` The first message can never be enough on its own: it is reached only when no `include` line or glob covers the file. It is also the only one of these refusals without "Nothing was written."

Found at `7f48e0e1f` with the checkout's `uv run bea` 0.4.1, macOS 26.5.1, Python 3.12.14, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, stdin closed, stdout piped, synthetic ledger. The ledger was byte-identical after every refusal.

## Repro

```sh
cat > main.bean <<'EOF'
option "operating_currency" "USD"
2024-01-01 open Assets:Checking USD
2024-01-01 open Expenses:Food USD
EOF
bea --file main.bean add transaction X --date 2024-04-01 -p 'Expenses:Food 5 USD' -p Assets:Checking --into 2024/q2.bean   # exit 2
mkdir 2024
bea --file main.bean add transaction X --date 2024-04-01 -p 'Expenses:Food 5 USD' -p Assets:Checking --into 2024/q2.bean   # exit 2 again
```

`bea add transactions --from - --into imports/2024.bean` and `bea import … --into imports/2024.bean` give the same first message. `--json` carries it as `{"error": {"category": "usage", "message": "Write destination directory … Create the directory first.", "exit_code": 2}}`.

Control: with `include "2024/*.bean"` in the root, the same first run says `directory …/2024 does not exist. Create it first; bea creates only the file. Nothing was written.`, and after `mkdir 2024` the write succeeds. That is a different branch, and its advice is complete.

## Expected

When the destination is not included and its directory is missing, one refusal names everything the write needs: the destination is not included by the root, its directory does not exist, and the fix is to create the directory and the file and add an include line (or a glob such as `include "2024/*.bean"`) to the root. Keep the rule `A relative --into path is based on <root dir>, the root ledger's directory.`, end with `Nothing was written.` like the other refusals, and keep exit 2 in human and `--json` mode. Following the advice once must make the same command succeed.

## Root cause

`cli/src/bea_engine/ledger/write.py` `require_target` (around lines 262–275). After every include pattern has failed to match, the missing-directory test runs before the "not included" refusal and raises `Write destination directory {parent} does not exist. {base} Create the directory first.` on its own. The glob branch above it (around lines 239–248) is the only place a missing directory is the whole problem.

## Fix

Fold the two refusals in that last branch into one message, as above, and add "Nothing was written." Add a regression test that runs the repro through `add transaction` and `import --into` (human and `--json`), asserts exit 2 and an unchanged ledger, and asserts that the message names both the include and the directory. Then follow the message once (create the directory, the file and the include line) and assert the same command now writes. Keep the glob control. Run `make check-all` in `cli/`.

## Dedupe

Searched `.pm/**` for `Create the directory first`, `directory first`, `add an include directive to the root first`, `--into` with `does not exist`. w5/654 added the `relative to the root` rule and the cwd `did you mean` hint to these refusals. w5/449 stopped URL `--into` values from reaching them. w5/492 and the include-glob work (`a65c9a3e5`) cover a missing directory under a matching glob, the control above. None covers the advice being incomplete when nothing includes the file.

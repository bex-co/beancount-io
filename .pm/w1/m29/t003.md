## Objective

PRFAQ002 is explicit that a report-only implementation would leave connected books unusable in other commands. Resolution has to happen wherever the ledger is loaded: check, list, query, report, import, and write validation.

## Context

- PRFAQ002 section 12's local-CLI row: directive reads call upstream Beancount, report and check paths use the vendored Fava loading, and write validation loads the ledger too — one common resolution policy must cover all of them.
- ADR 015 section 7: a managed directive whose date and pair, or date and reciprocal pair, collide with a ledger-authored price is replaced by a comment so line numbers stay stable; precedence is decided before the price map is built.
- ADR 015 section 9: virtual entries are read-only — a write that resolves to one fails with an error naming the managed source.
- Load paths: `cli/src/bea_engine/ledger/reader.py`, `cli/src/fava/core/loader.py`, and `cli/src/bea_engine/ledger/write.py`.

## Steps

1. Add one resolution step used by every load path, so no command sees a different ledger than another.
2. Materialize each resolved feed under the key the engine looks up for that include, leaving the customer's files untouched.
3. Apply ledger-authored precedence before the price map is built, replacing shadowed managed directives with comments.
4. Refuse writes that target a virtual price entry, naming the managed source.
5. Keep ordinary local use account-free: no Beancount.io credential is required to resolve a public feed.

## Acceptance criteria

- [ ] `bea check`, `list`, `query`, `report`, `import`, and a validated write all see the same resolved prices for a ledger with a managed include.
- [ ] A ledger-authored price for the same date and pair wins, and the shadowed count is reported.
- [ ] Editing or deleting a managed price entry fails with an error naming the managed source; the customer's files are never rewritten.
- [ ] Resolution requires no Beancount.io account.

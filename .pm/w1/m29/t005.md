## Objective

PRFAQ002's portability gate requires that exported local includes and effective prices validate and value equivalently under unmodified upstream Beancount. URL resolution is a Beancount.io extension; the escape hatch has to exist.

## Context

- PRFAQ002 section 9 and its portability gate: exported local includes and effective prices must validate and value equivalently with upstream Beancount and the hosted engine offline.
- PRFAQ002 section 12's compatibility boundary: unmodified upstream Beancount does not fetch these URLs; use the exported local includes with upstream tools.
- The original ledger is never rewritten merely because a report is opened (ADR 015 section 1, PRFAQ002 section 12).

## Steps

1. Add an export that writes the currently resolved feed to a local `.beancount` file the user names, with a header recording the source URL, revision, and observed-at.
2. Make the exported file valid for unmodified upstream Beancount, so `bean-check` accepts a ledger that includes it.
3. Leave the customer's ledger untouched; exporting is an explicit action, never a side effect of a read.
4. Document the round trip from managed include to portable local include.

## Acceptance criteria

- [ ] The exported file is accepted by the upstream oracle `bean-check` used in skills CI, and a ledger including it values identically to the managed resolution.
- [ ] The export records source URL, revision, and observed-at in its header.
- [ ] Exporting never modifies the customer's ledger.
- [ ] The round trip is documented.

## Out of scope

- Snapshotting whole ledgers.
- Automatic conversion of managed includes to local ones.

## Objective

Remove private OAuth signing material from tracked source, load it through the deployment secret boundary, and invalidate the replaced production key before expanding OAuth use to mobile.

## Context

- `backend-cluster/backend-v2/src/config/jwks/index.ts` currently selects environment-specific JSON from `src/config/jwks/`.
- The public repository must never contain a private JWK parameter or a real deployment key.
- Rotation must change the active signing key; deleting a tracked file without replacing the accepted key does not invalidate tokens signed with it.

## Steps

1. Define strict production configuration for a secret-sourced private JWKS and fail startup with an actionable error when it is absent or malformed.
2. Preserve non-secret development/test fixtures without allowing them to be selected in production.
3. Generate and deploy a new production signing key through the existing secret-management boundary, remove the replaced public key from accepted JWKS, and verify newly issued tokens use the new key.
4. Remove tracked private production material and document the rotation procedure without recording any key value.

## Files

- `backend-cluster/backend-v2/src/config/jwks/`
- `backend-cluster/backend-v2/src/config/config.ts`
- `backend-cluster/backend-v2/.env.example`
- Public deployment configuration that passes the secret by name, never value.

## Acceptance criteria

- [ ] No tracked production file contains private JWK material.
- [ ] Production refuses to start with a missing, empty, malformed, or public-only signing configuration.
- [ ] The live JWKS exposes only public material for the new key and the replaced key no longer verifies against the resource server.
- [ ] Development and tests use explicitly non-production fixtures.
- [ ] Rotation documentation contains no credential or private-key content.

## Out of scope

- Redesigning access-token claims, audiences, or scopes; those follow in t002 and t003.

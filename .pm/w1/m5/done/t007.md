## Objective

Replace new mobile sign-ins through the embedded WebView bridge with standards-discovered authorization code plus S256 PKCE in the external system browser.

## Context

- `mobile/src/screens/welcome/login-web-view.tsx` injects a React Native message bridge into dashboard login pages.
- `expo-web-browser` is present, but `expo-auth-session` and its direct crypto peer are not; repository rules require user approval before adding dependencies and the generated Yarn lockfile must never be hand-edited.
- The current `beancount` URL scheme is not the reverse-domain private-use scheme expected for native OAuth redirects.

## Steps

1. Obtain approval, then add the Expo-compatible AuthSession and crypto packages using Yarn Classic from `mobile/`.
2. Register exact reverse-domain iOS and Android OAuth callback schemes without breaking unrelated app deep links.
3. Derive the API resource from the selected server, fetch RFC 9728 and RFC 8414 metadata, and validate exact resource, issuer, HTTPS, endpoint origin, state, and authorization-response issuer.
4. Open the system browser with code response, S256 PKCE, the API resource, account scopes, and offline consent; exchange the returned code using the original verifier and redirect URI.
5. Resolve the user through userinfo or an authenticated API query rather than decoding the access token.

## Files

- `mobile/package.json`
- `mobile/yarn.lock` generated by Yarn only.
- `mobile/app.json`

- New focused mobile OAuth discovery/authorization helpers.

## Acceptance criteria

- [ ] New sign-in and sign-up entry points use the external browser and never render the dashboard inside `react-native-webview`.
- [ ] State, S256 PKCE, exact redirect URI, issuer, and resource validation fail closed.
- [ ] The app returns correctly from warm and cold iOS/Android launches and handles cancel/error without creating a session.
- [ ] Hosted and selected self-hosted servers use their own discovered endpoints.
- [ ] The mobile client treats access tokens as opaque.

## Out of scope

- Token refresh, Apollo retry, or retiring support for already-installed legacy app versions.

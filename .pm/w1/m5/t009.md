## Objective

Make every authenticated mobile request obtain a valid OAuth access token through the shared manager, recover once from expiry, and revoke the refresh credential during logout before clearing account data.

## Context

- `mobile/src/common/apollo/client.ts` currently reads a bearer synchronously from `sessionVar`.
- `mobile/src/common/apollo/error-handling.ts` immediately destroys the session on the first GraphQL `UNAUTHENTICATED` response.
- `mobile/src/screens/setting/logout.ts` calls a GraphQL logout mutation that revokes the legacy session JWT, not an OAuth refresh grant.
- Locally verified self-contained access tokens may remain valid until expiry after refresh-token revocation; this behavior must be explicit.

## Steps

1. Make Apollo authorization asynchronous through the single token manager while preserving server/token isolation.
2. On `UNAUTHENTICATED`, perform at most one forced single-flight refresh and replay the operation once; prevent retry loops and duplicated teardown.
3. Revoke the OAuth refresh token through the discovered revocation endpoint, then clear secure session state and persisted/in-memory Apollo data even if revocation is offline or unavailable.
4. Preserve the existing GraphQL logout path for legacy sessions and document the access-token expiry tail or add a deliberate immediate-revocation mechanism.

## Files

- `mobile/src/common/apollo/client.ts`
- `mobile/src/common/apollo/error-handling.ts`
- `mobile/src/screens/setting/logout.ts`
- `mobile/src/common/apollo/session-teardown.ts`

## Acceptance criteria

- [ ] Authenticated operations receive a non-expired token without parallel refresh races.
- [ ] An expiry response causes one refresh/retry and a terminal failure causes one complete teardown.
- [ ] Transient refresh or revocation network failures do not leak credentials or leave another account's Apollo cache visible.
- [ ] OAuth logout prevents further refresh and legacy logout retains its current behavior.
- [ ] The documented logout guarantee matches actual access-token verification behavior.

## Out of scope

- Global browser single sign-out across other Beancount.io clients.

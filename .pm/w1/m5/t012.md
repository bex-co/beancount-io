## Objective

Make the standards-based mobile login and compatible-server requirements discoverable to users, self-host operators, and contributors on every public surface changed by the milestone.

## Context

- This milestone changes first-run mobile behavior, dependency/setup steps, server compatibility, deployment configuration, and logout expectations.
- Repository compatibility rules require adjacent `AGENTS.md` files to remain relative symlinks to canonical `CLAUDE.md` files and `.agents/skills` to resolve to `skills/.claude/skills/`.

## Steps

1. Update mobile documentation for external-browser login, callback schemes, secure refresh behavior, and the hosted/self-hosted server experience.
2. Update backend and `deploy/mac` setup documentation for issuer, public native-client, protected-resource metadata, dashboard interaction routing, and secret-sourced signing keys using placeholders only.
3. Check root README/package tables and instruction files for affected setup or compatibility claims; update only where the shipped behavior changes them.
4. Verify applicable `AGENTS.md` and `.agents/skills` symlinks and confirm instructions remain equally usable by Claude Code and Codex.

## Files

- `mobile/README.md`
- `backend-cluster/backend-v2/README.md` or its canonical setup documentation.
- `deploy/mac/README.md`
- Root `README.md`, `CLAUDE.md`, and compatibility symlinks if affected.

## Acceptance criteria

- [ ] A mobile user understands that login opens the system browser and returns safely to the app.
- [ ] A self-host operator can configure and verify the complete OAuth contract using only public docs and placeholder values.
- [ ] Security and logout guarantees are accurate and do not overstate immediate access-token revocation.
- [ ] Instruction and shared-skill symlinks resolve exactly as required.

## Out of scope

- General OAuth tutorials or documentation for unrelated authorization servers.

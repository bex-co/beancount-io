## Objective

Let a client safely discover the protected API and its authorization server from the selected hosted or self-hosted base URL without accidentally routing a custom deployment through the production issuer.

## Context

- `backend-cluster/backend-v2/src/config/config.ts` currently hardcodes the OAuth issuer to `https://beancount.io`.
- Mobile server URLs may preserve a reverse-proxy path prefix.
- RFC 9728 protected-resource metadata must return the exact resource identifier requested; RFC 8414 authorization-server metadata and issuer validation must remain path-aware.
- The consent UI URL and authorization-server issuer are separate configuration concerns even when production serves both on one origin.

## Steps

1. Add strict non-empty issuer configuration with safe production defaults and explicit local/self-host values; reject ambiguous or malformed deployment configuration at startup.
2. Separate the dashboard interaction URL from the issuer and preserve cookies/redirects through the supported same-host or front-door proxy contract.
3. Expose API-specific protected-resource metadata at the standards-derived path and advertise the authorization server, scopes, and bearer method.
4. Ensure authorization-server metadata, absolute endpoints, proxy headers, and path prefixes all resolve to the configured public issuer.

## Files

- `backend-cluster/backend-v2/src/config/config.ts`
- `backend-cluster/backend-v2/src/features/oauth/api/oidc-route.ts`
- `deploy/mac/.env.example`
- `deploy/mac/docker-compose.yml`

## Acceptance criteria

- [ ] Hosted, localhost-development, and path-prefixed self-host configurations each advertise their own exact issuer and API resource.
- [ ] Empty or malformed issuer configuration fails clearly instead of falling through to production.
- [ ] Protected-resource metadata returns an exact resource match and a client can follow it to valid authorization-server metadata.
- [ ] Consent interactions return through the configured public dashboard/front door without cross-host cookie loss or redirect loops.

## Out of scope

- Supporting authorization servers unrelated to the selected Beancount.io deployment.

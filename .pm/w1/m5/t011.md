## Objective

Wire and verify the public deployment contract so the official service and `deploy/mac` expose the same discoverable mobile OAuth behavior without committing deployment credentials.

## Context

- **Evidence from w1/m6/t009 (2026-08-28):** the hosted contract was broken in exactly the way this task exists to catch — every native sign-in failed after Approve because `Query.userProfile` was `session-only` under scope enforcement, and `oidc-route.test.ts` could not see it because its stand-in `/api-gateway/` route never ran the op-class gate. Both are fixed; step 3 below should be run against the redeployed hosted service, not only the local stack.

- `deploy/mac` currently publishes dashboard and backend on separate localhost ports and does not configure a self-host OAuth issuer.
- OAuth metadata, authorization, consent, token, revocation, and redirect routes must agree on their public origin and path prefix.
- Release mobile builds require HTTPS; development may deliberately allow cleartext localhost only.

## Steps

1. Add placeholder-only issuer/dashboard/signing-key configuration to public deployment examples and pass it to the appropriate service.
2. Verify reverse-proxy routing for RFC 9728/RFC 8414 metadata, OAuth endpoints, dashboard consent, and app callbacks.
3. Exercise a full code/PKCE, refresh, API call, and logout flow against the official deployment and the documented local stack without recording credentials or user data.
4. Confirm custom-server health checking distinguishes a legacy incompatible server from one that advertises the required OAuth contract.

## Files

- `deploy/mac/docker-compose.yml`
- `deploy/mac/.env.example`
- `deploy/mac/README.md`
- Mobile server-compatibility probe as required.

## Acceptance criteria

- [ ] The public local stack starts with documented non-secret development configuration and advertises localhost rather than production OAuth endpoints.
- [ ] Hosted and self-host full flows complete through their own issuer, consent, token, API, refresh, and revocation endpoints.
- [ ] Path-prefixed reverse-proxy deployments have a documented, testable metadata route contract.
- [ ] No real key, token, hostname meant to be private, or user data enters committed configuration or test artifacts.

## Out of scope

- Changes outside this public monorepo's deployment contract.

## Objective

Give the native client a standard login/register/OTP and consent experience that approves account-wide API scopes without pinning the grant to one ledger.

## Context

- `dashboard/src/features/oauth/pages/consent.tsx` currently forces non-identity clients to select one ledger.
- Mobile must list and switch among all ledgers available to the signed-in user, so it needs the backend's supported unpinned account grant.
- The existing dashboard auth forms can be reused, but success must resume the OAuth interaction rather than send a session JWT through `window.postMessage`.

## Steps

1. Route the known mobile client to a client-aware consent branch or dedicated mobile consent page.
2. Reuse login, registration, and OTP components while keeping the interaction UID and requested scopes intact.
3. Display the requesting client and account-wide permissions, offer approval/cancel and account-switch behavior, and submit without a ledger ID.
4. Resume the provider interaction with an unpinned grant carrying only the requested API scopes and `offline_access` consent.

## Files

- `dashboard/src/features/oauth/pages/`
- `dashboard/src/features/oauth/funcs/`
- `dashboard/src/routes/oauth.*.tsx`
- `backend-cluster/backend-v2/src/features/oauth/api/oidc-route.ts`

## Acceptance criteria

- [ ] Signed-out users can login or register/verify and then approve the native client without losing the OAuth interaction.
- [ ] Signed-in users see a clear account-wide permission prompt rather than a ledger picker.
- [ ] Approval creates an unpinned grant with exactly the requested resource scopes; cancel returns a standard OAuth error.
- [ ] The MCP ledger-pinned and Discourse identity consent experiences remain unchanged.
- [ ] No OAuth consent success sends a bearer token through `window.postMessage`.

## Out of scope

- Redesigning general dashboard login or adding per-ledger selection to mobile.

# Invalid percent-encoding in a resource query value is accepted silently

**Bug · backend-v2 (MCP) · minor · ~20m · A1.** From `/qa-find-bugs-mcp`, 2026-11-09, production `beancount-mcp 1.0.0`, read-only.

- **Repro:**
  - `resources/read beancount://<o>/<n>/journal?account=%ZZ` returns an empty success, `{"total":0,"data":[],"is_empty":true}`.
  - `?account=%E0%A4%A` returns the same.
  - `trial-balance?time=%ZZ` is refused, but only by accident: the date parser rejects it with a generic hint.
  - **Control:** the path value `register/%ZZ` returns -32602 `BAD_USER_INPUT` "Invalid URI encoding in resource path", with the encoding hint.
- **Expected:** `docs/mcp.md:1442-1445`, written for w1/036, says a URI with invalid percent encoding answers `BAD_USER_INPUT` with a hint. An agent that double-encodes or truncates a filter should be told so, not handed an empty journal.
- **Cause:** `src/features/ai-agent/api/mcp-resource-template.ts:50-60` runs `decodeURIComponent`, and refuses when it throws, only for path variables. Query values come from `url.searchParams` (`:67`). WHATWG `URLSearchParams` keeps an invalid `%XX` literally and maps invalid UTF-8 to U+FFFD, so nothing throws. The w1/036 fix covered path values only.
- **Fix:** decode each raw query value with `decodeURIComponent` (after replacing `+` with a space) inside a `try`. On failure, refuse with "Invalid URI encoding in resource parameter `<name>`" and the same hint. Check whether REST, which uses Express/qs, accepts the same values, and if it does, refuse them there too.
- **Check:** add a case to `mcp-resources.test.ts` for each template family that has query names.

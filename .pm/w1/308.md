# `bea report capital-gains` silently leaves out a sale written without an `@` price: the ledger books the gain, the report says "No sales" and exits 0

**Bug · cli (+ backend-v2 parity) · major · ~1h · A1.** From routine cli-qa, 2026-11-19. Beancount accepts a sale with no price annotation and books its gain through the income leg. `bea report capital-gains` drops that sale with no notice, so the report's total no longer ties to the booked gains. That tie is part of the [w22/m4](../w22/done/m4/README.md) definition of done ("The report total ties to the ledger's `Income:CapitalGains` postings for the same range"). An agent or a user doing taxes reads an under-reported total with exit 0.

Environment: main `adb290b19`, macOS 26.5.1, `bea 0.4.1` from the checkout (`uv run bea`), isolated config and cache, stdin closed, no TTY.

Repro ledger (`main.bean`):

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Bank USD
2024-01-01 open Assets:Broker
2024-01-01 open Assets:Broker2
2024-01-01 open Income:Gains USD
2024-01-01 open Equity:Opening

2024-01-02 * "Fund"
  Assets:Bank  10000.00 USD
  Equity:Opening

2024-01-10 * "Buy"
  Assets:Broker  10 AAPL {150.00 USD}
  Assets:Bank

2024-02-01 * "Transfer between own accounts"
  Assets:Broker   -2 AAPL {150.00 USD}
  Assets:Broker2   2 AAPL {150.00 USD}

2024-03-10 * "Sell with price"
  Assets:Broker  -3 AAPL {150.00 USD} @ 170.00 USD
  Assets:Bank  510.00 USD
  Income:Gains

2024-03-11 * "Sell without price"
  Assets:Broker  -5 AAPL {150.00 USD}
  Assets:Bank  900.00 USD
  Income:Gains
```

- `bea --file main.bean check` exits 0, and `bea --file main.bean balance gains` shows `Income:Gains -210.00 USD`.
- `bea --file main.bean report capital-gains` exits 0, prints only the 2024-03-10 row (3 AAPL, proceeds 510.00, basis 450.00, gain 60.00 USD), and totals `One year or less: 60.00 USD`. stderr is empty. `--json` has the one row and no field naming the dropped reduction. The 2024-03-11 sale (5 AAPL out, 900.00 USD in, a 150.00 USD gain booked) is missing.
- With only the unpriced sale in the ledger, the report prints `No sales.`
- The hosted composer (`composeGains` in `backend-cluster/backend-v2/src/features/ledger/utils/gains.ts`, run through `tsx` on the same journal rows) returns the same single row. REST, GraphQL and the MCP `ledgerCapitalGains` resource therefore have the same gap.

**Root cause:** `_capital_gains` in `cli/src/bea_engine/report.py` skips every reduction with no price (`if price is None ...: continue`), on the stated assumption that only splits and own-account transfers reduce without a price. `cli/docs/USAGE.md` says the same ("splits and transfers carry no price and stay out"). A sale to cash is neither, but it takes the same branch. `closedLot` in `gains.ts` has the same rule.

**Do:** keep proceeds unguessed (no price means no stated proceeds), but stop hiding the sale. A priceless reduction that the same transaction does not offset with an augmentation of the same commodity is not a transfer or a split. List each one in a new JSON field, `unpriced_reductions` (date, `file:line`, account, commodity, quantity, booked cost). In text, print a note after the table, such as `1 lot reduction without a price is not counted: main.bean:25 (add @ PRICE to report it as a sale)`, and never print a bare `No sales.` when there is one. The CSV output carries the same rows. Reword USAGE (Reports) and the `beancount-trade` realized-gains reference to match. Mirror the field in `composeGains` so REST, GraphQL and MCP disclose it too, and update their descriptions.

**Done when:** on the ledger above, text output still totals 60.00 USD but names the 2024-03-11 reduction at its `file:line`, and `--json` lists it under `unpriced_reductions`. The 2024-02-01 own-account transfer is listed nowhere, and a 2-for-1 split (`-5 X {100 USD}` / `10 X {50 USD}` in one transaction) is not listed either. The hosted surfaces return the same field. Tests fail with the change reverted: `cli/tests/test_report_capital_gains*.py` and backend-v2 `gains.test.ts` plus the analysis parity test. `make check-all` (cli) and `yarn test` (backend-v2) pass.

**Blast radius:** `_capital_gains` is the only CLI caller. `composeGains` sits under `LedgerFinanceService.getCapitalGains` and REST, GraphQL and MCP. The `beancount-ask` and `beancount-trade` skills already tie per-lot gains to booked gains, which would surface the gap but not explain it. Working control: the priced 2024-03-10 sale reports correctly on both sides.

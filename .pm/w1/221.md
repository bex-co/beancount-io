# A write that adds a managed price include previews as "source unavailable" and is refused

**Bug · ledger · major · ~45m · A1/A2.** From `/qa-find-bugs-mcp`, 2026-11-10, production `beancount-mcp 1.0.0`, the disposable QA ledger.

PRFAQ002's one-line include `include "https://beancount.io/prices/BTC-USD"` cannot be committed through the MCP or REST write tools without `allow_invalid`, and the refusal hint steers the agent to `allow_invalid`.

- **Repro:**
  1. `createLedgerFiles` `qa-x/prices.bean` containing the managed include, a BTC `open` and a purchase at cost. This passes, because nothing loads that file yet.
  2. `updateLedgerFiles` `main.bean` with `include "qa-x/prices.bean"` added and `dry_run`. It returns `valid:false` with `newErrors [{code:"LOAD", source:"qa-x/prices.bean:2", message:"… managed price source is unavailable; no validated price feed could be fetched yet …"}]`. The commit is refused `VALIDATION_FAILED`.
  3. Putting the include directly in `main.bean` gives the same result for the `BTCUSD`, `BTC-USD` and `btcusd` aliases. The same feed is served as `recent` on another ledger at the same moment.
  4. Commit with `allow_invalid` and the commit's own post-write validation reports `errorsAfter: 0, valid: true`. `checkLedger` is clean and `managed-prices` reads `recent` within about 3s. Only the preview and the commit gate fail.
  5. Adding a second include of an already-resolved URL also fails the preview.
  - REST `PUT …/files/main.bean {dryRun:true}` returns the same `LOAD` error.
- **Expected:** the preview and the commit gate resolve a newly added managed include the same way the real load does: use the cached revision, or fetch once. They fail only when the source really is unavailable.
- **Cause:**
  - `backend-cluster/ledger/src/features/ledger/service/ledger-data-service.ts:543-600` (`projectFileMap`) first calls `loadCachedFileMapForRepo`. That overlays managed feeds only for includes already committed (`load-cached-ledger-file-map.ts:298`, `withManagedPrices`).
  - The caller's overlay is merged afterwards (`:572-599`), so an include it introduces has no feed text in the projected map.
  - The engine reports the URL as a missing file, and `url-include-errors.ts:24` rewrites that as "unavailable".
- **Fix:** after merging the overlay, run the managed price overlay (`overlayManagedPrices`) over the projected map again. Reuse the cache, or fetch once per the existing policy. This covers every projection write that adds or moves a managed include: the MCP/REST file writes, `appendLedgerText` previews and the entry writes.
- **Check:**
  - `check-files` and projection tests: an overlay that adds a managed include previews `valid: true`, and the prices appear in the projected map.
  - A parity case: the MCP `updateLedgerFiles` and REST `PUT` previews agree with the commit.
- **Related:** GraphQL `updateLedgerFile` skips the gate entirely (w1/210), which is why the dashboard editor happens to work.

## Objective

Tables read in the terminal they are printed to; scripts keep the stable single-line form.

## Context

- `cli/src/cli/output.py::table` sizes columns to the widest cell with no width limit; `list transaction` joins postings with `; ` so a six-posting entry produces a row over 200 characters, and everything wraps at 100 columns.
- `cli/src/cli/ask/repl.py` already uses `shutil.get_terminal_size()`.

## Steps

1. When stdout is a terminal, compute the available width and, for rows whose posting cell would overflow, render the postings one per line under the row (account left, amount right), keeping the other columns on the first line.
2. When stdout is not a terminal, keep the current single-line rendering byte-for-byte.
3. Apply the same rule to the `MATCHING POSTING AMOUNTS` variant.

- `cli/src/cli/output.py`
- `cli/src/cli/commands/list.py`

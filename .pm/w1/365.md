# `bea cloud ledger list` prints a full page with no sign that more ledgers exist, and a page past the end as a bare header with exit 0

**Bug · cli · minor · 30–45m · A1/A2.** From routine cli-qa, 2026-11-23. Every local `bea list` ends a cut-off table with `Showing the first N; raise --limit for more.` and says `No … found.` when nothing matches. `bea cloud ledger list` does neither. A person who passes `--limit 5`, or who owns more than the default 50 ledgers, gets a table that looks complete. A newly signed-in account, or `--page` past the end, gets a header and a dashed rule with nothing under them, exit 0. `--json` already knows the answer: it sends one extra request on a full page and reports `truncated: true`. The text branch never asks.

Environment: main `4b54aaca1`, `bea 0.5.0` from the checkout (`uv run bea`), macOS 26.5.1, Python 3.12.14. Isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, stdin closed, no TTY. Read-only against production (`https://api.v3.beancount.io`) with the QA account's API key as `BEA_TOKEN`; that account has 7 accessible ledgers. Reproduced twice in fresh processes.

## Repro

```sh
export BEA_TOKEN=…            # any account with more than 5 ledgers
bea cloud ledger list --limit 5
bea --json cloud ledger list --limit 5 | jq '.truncated, (.data | length)'
bea cloud ledger list --page 99; echo "exit $?"
bea --json cloud ledger list --page 99 | jq -c '{data, truncated, page}'
```

## Actual

- `--limit 5`: a header, a rule and 5 rows, exit 0, nothing on stderr. The JSON form of the same request says `true` and `5`. `--page 2 --limit 5` lists the other 2.
- `--page 99`: stdout is only `NAME  FULLNAME  PRIVATE  CREATED` and its dashed rule, exit 0. JSON is `{"data":[],"truncated":false,"page":99}`.
- Control: `bea list transaction -l 2` on a 4-transaction ledger prints 2 rows and `Showing the first 2; raise --limit for more.` on stderr, and `bea list pad` with no pads prints `No pad directives found.`

## Expected

The text output says what JSON carries. When the page is full and another ledger exists, print a note on stderr after the table: `Showing page 1 (5 ledgers); more on --page 2.` (or `raise --limit`, up to the API's 100). When the page is empty, print `No ledgers on page 99.` for `--page` greater than 1, and `No ledgers yet; create one with bea cloud ledger create NAME.` for page 1. Both stay exit 0, and stdout under `--json` stays unchanged. Basis: the local `list` notices (`cli/src/cli/commands/list.py:473-475`) and the empty-result lines every other `bea` table prints. `cli/docs/USAGE.md:3066` ("Human table output uses only the requested page") says which rows the table shows. It does not promise to hide that more rows exist.

## Cause

`cli/scripts/gen_cloud_commands.py:306-323` writes the `truncated` probe (`page=page * limit + 1, limit=1`) only inside `if context.current().json_output:`. The text branch is a bare `output.table(...)`. The generated `cli/src/cli/commands/cloud/generated/ledger.py:38-56` shows this: the probe at `:40-44`, the table at `:47`. `output.table` (`cli/src/cli/output.py:360`) prints headers even with no rows and has no empty-state line.

## Fix

Owned by `cli`, in the generator only. Then run `make codegen` and do not edit the generated file. For paged list commands, move the next-row probe ahead of the JSON/text split, so both branches use the one answer. Run it only when the page is full, as JSON does now. After the table, print the truncation note through `output.note`, so stdout keeps only the table. Print the empty-page line instead of an empty table. Add `tests/test_cloud_ledger_pagination.py` cases with the existing `httpx_mock` catalog: a full middle page prints the note and makes exactly one extra request; a full final page prints none; a short page makes no extra request; page 1 and page N past the end print their empty-state lines with exit 0; and `--json` output is byte-identical to today's. Run `make check-all` and `make docs-check` in `cli/`. No backend change: REST, GraphQL and MCP already return the page.

## Blast radius

`ledger list` is the only generated command with `columns` and paging (`paged` in the generator). `show` and `delete` render with `output.fields` or `output.success` and are unaffected. The local `list` commands already have both notices.

## Dedupe

Searched `.pm/**` for `cloud ledger list`, `truncated`, `--page`, `human`, `table`. w3/429 (fixed the off-by-one in JSON `truncated` on a full final page), w1/003 (added `page` to the JSON envelope), w5/680 (`--limit 0` validation) and w5/846 (repeated `--page/--limit`) all concern JSON or validation. None covers the text table. `git log -S "page * limit + 1"` shows the probe arrived in `fc65f86d6` ("verify more ledger rows before marking a page truncated"), for JSON only.

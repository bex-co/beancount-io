# `bea doctor guidance` warns about a `CLAUDE.md` that already reads `AGENTS.md`, and its advice can write into `AGENTS.md`

Found by `/qa-find-bugs-cli w1` on 2026-11-15 (HEAD `164c163be`, `bea 0.3.1`, macOS 26.5, checkout `uv run bea`, stdin closed). Severity: minor.

**Contract.** `bea doctor guidance LEDGER` warns when `CLAUDE.md` "does not import AGENTS.md, so Claude Code reads different instructions than other agents". The warning is meant for a `CLAUDE.md` whose instructions differ from `AGENTS.md`. Claude Code reads the same instructions in three other common layouts: a `CLAUDE.md` that is a symlink to `AGENTS.md`, an import spelled `@./AGENTS.md`, and an import inside a sentence (`Read @AGENTS.md first.`). Claude Code's memory docs allow `@path` imports anywhere in the text, with relative paths.

**Repro** (synthetic ledger):

```sh
mkdir g && cd g
printf 'option "operating_currency" "USD"\n2024-01-01 open Assets:Cash USD\n' > main.bean
printf '# Ledger rules\nUse bea.\n' > AGENTS.md
ln -s AGENTS.md CLAUDE.md
bea doctor guidance main.bean                              # warns
rm CLAUDE.md; printf '@./AGENTS.md\n' > CLAUDE.md
bea doctor guidance main.bean                              # warns
printf 'Read @AGENTS.md first.\n' > CLAUDE.md
bea doctor guidance main.bean                              # warns
printf '@AGENTS.md\n' > CLAUDE.md
bea doctor guidance main.bean                              # control: "agent guidance OK in ."
```

Actual: the first three each print `warning: CLAUDE.md does not import AGENTS.md, ... Add a line containing exactly @AGENTS.md.` and exit 0. In the symlink case the advice is harmful: adding the line to `CLAUDE.md` writes `@AGENTS.md` into `AGENTS.md` itself, through the link, so the file imports itself. `bea init --existing` is fine here: it keeps both files (`agent_files: {"AGENTS.md": "kept", "CLAUDE.md": "skipped"}`).

Expected: the check prints `agent guidance OK in .` when `CLAUDE.md` resolves to the same file as `AGENTS.md`, or when it imports `AGENTS.md` through any `@` path that resolves to the `AGENTS.md` beside it (`@AGENTS.md`, `@./AGENTS.md`, inline in a line of prose, but not inside a code span or fence). It still warns for a `CLAUDE.md` that neither links to nor imports `AGENTS.md`.

**Root cause.** `_claude_points_at_agents` in `cli/src/cli/commands/doctor.py` (around line 887) reads the text of `CLAUDE.md` and accepts only a line that is exactly `@AGENTS.md`. Through a symlink it reads the text of `AGENTS.md`, which has no such line. It has one caller, `doctor_guidance` (line 914).

**Fix.** Return true first when `os.path.samefile(claude, agents)`. Otherwise scan for `@` tokens outside code spans and fences, and accept one whose path, resolved against the `CLAUDE.md` directory, is the same file as `AGENTS.md`. Add cases to `cli/tests/test_doctor_guidance.py` for the symlink, `@./AGENTS.md`, inline import, and a fenced `@AGENTS.md` (which still warns). Estimate: about 30 minutes.

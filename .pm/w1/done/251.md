# `bea report budget` with no `--time` budgets a whole first month before the report's own start date

Found by `/qa-find-bugs-cli w1` on 2026-11-15 (HEAD `b845182dc`, `bea 0.3.1`, macOS 26.5, checkout `uv run bea`, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, offline synthetic ledger). Severity: minor. A1: an agent that asks "how am I doing against budget?" gets a first-month target that does not match the period the report says it covers, and a different answer when it repeats the same period with `--time`.

**Contract.** `cli/docs/USAGE.md` (Budgets): a budget "is spread by day, so a period shorter than its interval (the ledger's last month, or `--time` ending mid-month) gets its share". The report states its period in the heading and in `--json` `period`; every interval inside it should be bounded by that period.

**Repro** (synthetic):

```sh
cat > bg.bean <<'EOF'
option "operating_currency" "USD"
2026-01-01 open Assets:Bank
2026-01-01 open Expenses:Food
2026-01-01 custom "budget" Expenses:Food "monthly" 310.00 USD
2026-01-10 * "f"
  Expenses:Food  100 USD
  Assets:Bank
2026-03-15 * "f"
  Expenses:Food  50 USD
  Assets:Bank
EOF
bea --file bg.bean report budget
bea --file bg.bean report budget -t "2026-01-10 - 2026-03-15"
```

Actual: the default run is headed "Budget — 2026-01-10 through 2026-03-15" (`--json` `period.start` `2026-01-10`), but its first table is "2026-01-01 through 2026-01-31" (`periods[0].begin` `2026-01-01`) with the full 310.00 USD. The last month is prorated to 2026-03-15 (150.00 USD), as documented. The explicit run over the same stated period gives the first month 220.00 USD (22 of 31 days) and heads it "2026-01-10 through 2026-01-31". So the same period has two different budget totals, and the default one budgets days the report says it does not cover.

Expected: the default run matches the explicit one: first period 2026-01-10 through 2026-01-31, budget 220.00 USD; Feb 310.00; Mar 150.00.

**Root cause.** `cli/src/fava/ledger.py` `FilteredLedger.interval_ranges` (around line 235): with no time filter it builds `dateranges(self._date_first, self._date_last, interval, complete=True)` and clips only the *last* range to `_date_last` (w5/261). `complete=True` also widens the *first* range back to the interval boundary (2026-01-01) before `_date_first`. `cli/src/bea_engine/report.py` `_budget` (around line 402) passes `span.begin`/`span.end` to `module.calculate`, so the extra days are budgeted. Other reports sum entries per range, and no entry precedes `_date_first`, so their figures do not change; only the budget's day-share is wrong (and its `begin` label).

**Fix** (about 30 minutes; `cli` only). In the no-filter branch, also clip the first range: `ranges[0] = DateRange(self._date_first, ranges[0].end)` (handle a single range, where both clips apply). Add a regression test beside the existing budget report tests: with the fixture above, `--json report budget` gives `periods[0].begin == "2026-01-10"` and budget `220.00`, equal to the explicit `-t "2026-01-10 - 2026-03-15"` run. Check that income-statement/balance-sheet interval series are unchanged. Revert the fix and check that the test fails.

**Blast radius.** `interval_ranges` callers: `report.py` `_budget`, and `src/fava/modules/chart.py` (lines 69, 290, 400; interval totals and balances, which only read entries inside each range, so their numbers stay the same). The hosted Budget pages have their own range logic (w21/102 fixed the mobile analogue); whether the dashboard has the same first-bar issue is unverified.

**Dedupe.** Searched `.pm/**` for budget proration, `first month`, `first period`, `interval_ranges`, `date_first`. w5/261 (done, `77210d459`) clipped the last range only; w5/365 and w3/384 dealt with `--time` fragments; w21/102 and w21/301 are the mobile Budget chart. None covers the CLI first range.

---

**Resolved 2026-11-15.** With no `--time`, `FilteredLedger.interval_ranges` now clips the first interval range to the period's first day as well as the last one to its end, so `bea report budget` on the repro reads 2026-01-10 through 2026-01-31 at 220.00 USD, then Feb 310.00 and Mar 150.00, identical to the explicit `-t "2026-01-10 - 2026-03-15"` run. `cli/src/fava/ledger.py`; budget proration wording in `cli/docs/USAGE.md`. Regression test: `cli/tests/test_report_budget.py::test_the_first_period_starts_where_the_report_does` (fails with the fix reverted); the full `make check-all` suite, including the income-statement and balance-sheet interval series tests, is unchanged.

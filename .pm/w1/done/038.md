# Native query `.output` bypasses ledger protection and silently erases its source

**Severity: major (data loss). Owner: cli. Estimate: 50–60m. A1/A2:** an agent's query/export must preserve the ledger it reads. Found by continuous CLI QA on 2026-10-02; no product fix applied.

Environment: clean `main` at `1a1480c8ad2dee049c4bccf4a646c2513082b04c`, checkout `cli/.venv/bin/bea`, Python 3.13.0, macOS 26.5.1 arm64. Editable installation metadata reports `bea 0.3.0`; the source and engine are this HEAD (`pyproject.toml`/engine manifest 0.3.1), not an older released implementation. Synthetic files, isolated config/cache/engine paths, notifier disabled, inherited `BEA_FILE` and `BEA_TOKEN` removed.

## Reproduce

In a disposable directory, save `main.bean`:

```beancount
2024-01-01 open Assets:Cash USD
2024-01-01 open Equity:Opening USD
2024-01-02 * "Start"
  Assets:Cash 100 USD
  Equity:Opening -100 USD
```

```sh
bea query --source /absolute/main.bean '.output /absolute/main.bean'
```

Actual, twice from pristine fixtures and fresh processes with closed stdin: exit **0**, empty stdout and stderr, and the ledger shrinks from **136 bytes to 0**. Before/after SHA256 differs; the empty result has SHA256 `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`. A fresh `bea check` can still pass because an empty ledger is syntactically valid; it does not recover the lost directives.

The same one-shot command erases the destination with `--source beancount:/absolute/main.bean`, an included child file, a symlink alias, a hard-link alias, and a `csv:/absolute/source.csv` input. Each reproduced variant exits 0 with no diagnostic. Reset fixtures between runs.

Also reproduced twice in a real PTY: run `bea query --source /absolute/main.bean`, then type `.output /absolute/main.bean`. The file becomes empty immediately. Upstream subsequently floods stderr with `ValueError: I/O operation on closed file`; the bounded harness kills this session after 64 KiB of diagnostics (observed process status -9 is the harness termination, not a natural CLI exit). No subsequent query is necessary for data loss.

Working controls on the same HEAD:

- Native `--source ... --output /absolute/main.bean 'SELECT account'` refuses with exit 2 and unchanged bytes.
- Managed `bea --file ... query '.output /absolute/main.bean'` refuses with exit 2; its interactive shell also refuses the collision and remains usable.
- Native `--source ... --output /absolute/export.txt 'SELECT account'` succeeds and preserves the ledger.

Expected: `cli/docs/USAGE.md`'s **Output destinations** rule protects root/include aliases, and **Checking, formatting, querying** explicitly refuses one-shot `.output` and protects interactive `.output`. `--source` changes the query backend, not permission to erase its input.

## Cause, fix and acceptance

`cli/src/cli/commands/query.py:228–237` returns through `launch.run_native("bean-query", ...)` before `_refuse_one_shot_output` at line 263. `_refuse_source_alias` runs only for the separate `--output` option. Interactive native commands also never reach `bea_engine.query.build_shell`'s guarded `PreciseShell.do_output` (`cli/src/bea_engine/query.py:333`). Pinned Beanquery's `shell.py:348–352` directly calls `open(arg, "w")`. This is an uncovered CLI integration guard, not a proposal to fork the upstream query engine.

Apply the existing one-shot `.output` refusal before native dispatch. For native interactive local sources, guard every output destination against the source and, for Beancount, its include closure, using the existing inode-aware alias semantics. Keep ordinary exports and safe shell redirection/reset usable; share the existing guard where possible. Review bare paths, `beancount:` and `csv:` without interpreting non-file `memory:`/`test:` sources as ledgers. No backend/API or dependency changes.

Acceptance: all reproduced one-shot variants refuse before touching files; interactive root collisions preserve bytes and leave a usable shell; safe native export and managed-query controls remain correct. Add real subprocess/PTY regressions asserting file hashes, diagnostics and process outcomes, and run `make check-all` inside `cli/` when implementing. Aliases were independently exercised in one-shot mode; interactive aliases beyond the root remain unverified.

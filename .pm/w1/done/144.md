# A partial `format -i` failure leads with "nothing was written" although earlier files were rewritten

**Severity: minor. Owner: cli. Estimate: 15–25m. A1:** a partial write must be reported as partial. Continuous CLI QA, 2026-10-03 (round 10); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1 (Beancount 3.2.3, beanquery 0.2.0), Python 3.13, macOS 26.5.1 arm64. Fresh process per command with timeouts, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME` (so `~/.config/beanquery/init` below is the isolated home), notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control.

```sh
mkdir t && for n in a b c; do cp unaligned.bean t/$n.bean; done && chmod 444 t/b.bean
bea --json format -i /abs/t
```

Actual (exit 3): `error.message` "Ledger file is read-only or not writable: …/b.bean. Change its permissions explicitly before retrying; nothing was written." while `result.formatted` is `[a.bean]` (rewritten) and `not_attempted` is `[c.bean]`; human output shows the same headline. The buckets are correct (`w3/done/426` holds).

Cause: `cli/src/cli/commands/format.py:156–178` re-raises the engine's per-file error with new details/result but keeps its single-file message (`cli/src/bea_engine/ledger/write.py:825`); the no-progress branch at `format.py:182` already builds an aggregate message.

Fix/acceptance: when `progress.formatted` is non-empty, use an aggregate partial-outcome headline (e.g. "Formatted 1 file; b.bean is read-only; 1 file not attempted"); neither JSON nor human output says "nothing was written". Optional: make the `--file DIR format --check/--dry-run` hint mode-aware instead of always suggesting `-i` (`format.py:348–352`).

---

**Resolved 2026-10-04** — a partial `format -i` failure now reports how many files were formatted, failed and not attempted instead of leading with "nothing was written". Tests in `tests/test_format_partial_failure.py` cover it. Shipped in the commit that moved this note (`cli`).

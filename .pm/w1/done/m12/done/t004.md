## Objective

Replace the ariadne-generated GraphQL client with a typed Python REST client generated from the pinned spec at build time, committed to the repo as generated-do-not-edit output — same workflow shape as today's `make codegen`, new contract underneath.

## Context

- Current generated client: `cli/src/cli/api/gql_client/` (treated as untouchable generated output per `cli/CLAUDE.md`).
- Candidate generator: `openapi-python-client` (mypy-strict-friendly). **Adding a dependency requires user confirmation first** (repo rule) — present the choice before `uv add`.
- `cli/src/cli/api/client.py` (`make_client` / `authenticated_client`) stays as the seam: same functions, REST client underneath, bearer token in the `Authorization` header, base URL from `settings().api_url`.

## Steps

1. Confirm the generator choice + dependency with the user, then add it to the `dev` group via `uv`.
2. Point `make codegen` at the pinned spec, emitting into `cli/src/cli/api/rest_client/`; commit the generated output.
3. Rewrite `client.py` to construct the generated client; replace the `graphql_endpoint` property in `settings.py` with the REST base path.
4. Verify `make codegen` is idempotent and mypy-strict passes over the generated code (configure per-module overrides only if unavoidable, and note them in `cli/CLAUDE.md`).

## Files

- `cli/Makefile`, `cli/pyproject.toml`, `cli/uv.lock` (via `uv`, never by hand)
- `cli/src/cli/api/rest_client/` (new, generated)
- `cli/src/cli/api/client.py`, `cli/src/cli/settings.py`

## Acceptance criteria

- [ ] `make codegen` regenerates the client from the pin reproducibly (clean git diff on second run).
- [ ] `make check-all` passes with the new client in place (commands not yet migrated).

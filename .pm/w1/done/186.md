# `renameLedgerFile` reports only the new path in `wrote`

**Bug · backend-v2 (MCP) · minor · ~20m · A1.** From `/qa-find-bugs-mcp`, 2026-11-08, production `beancount-mcp 1.0.0`, protocol `2025-11-25`, unpinned read/write API key, the disposable QA ledger.

`docs/mcp.md` defines `wrote` as the files a write touched. A rename with `updateIncludes: true` rewrites every including file and removes the old path in one commit, but the result lists only the new path. `deleteLedgerFiles` with `remove_includes` already lists the deleted files plus `main.bean`, so an agent reading `wrote` after a rename misses that `main.bean` changed.

- **Repro:**
  1. `createLedgerFiles` `qa-x/a.bean` with one `open` directive, and include it from `main.bean`.
  2. `renameLedgerFile {"oldPath":"qa-x/a.bean","newPath":"qa-x/a2.bean","updateIncludes":true}`.
  3. The result has `updatedIncludes: ["main.bean"]` but `wrote: [{"path":"qa-x/a2.bean"}]`. `readLedgerFiles main.bean` shows the include now names `a2.bean`.
- **Cause:** `backend-cluster/backend-v2/src/features/ai-agent/api/mcp-tools.ts:717` hardcodes `wrote: dryRun ? [] : [{ path: written.newPath }]` and ignores `written.updatedIncludes`.
- **Fix:** list `newPath` plus each `updatedIncludes` path, following the shape `deleteLedgerFiles` uses for the old path. Only the MCP adapter changes, because REST and GraphQL return `updatedIncludes` and have no `wrote`. Add the case to `rename-parity.test.ts`.
- **Check:** the rename above returns both `qa-x/a2.bean` and `main.bean` in `wrote`. A `dry_run` still returns `wrote: []`.

---

**Resolved 2026-11-10.** `renameLedgerFile`'s `wrote` now names every path the commit changed: `newPath`, the removed `oldPath` (as `deleteLedgerFiles` lists the files it removes), and each file in `updatedIncludes`, deduplicated when the moved file rewrote its own includes; a `dry_run` still returns `wrote: []`. MCP adapter only — REST and GraphQL carry no `wrote`. `rename-parity.test.ts` asserts the literal list for an include rewrite (`new.bean`, `old.bean`, `main.bean`) and for a self-rewriting move; reverting the fix fails 7 tests. `docs/mcp.md` describes the field in the rename section. (`backend-v2`)

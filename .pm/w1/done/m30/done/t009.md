## Result (2026-10-08)

The pass used four parallel reviewers (reuse, simplification, efficiency, altitude) over the m30 code at HEAD. Applied, all behavior-preserving:

- **Dashboard:** `interactionForwardHeaders(request)` in `common/lib/oauth/forward-to-backend.ts` now builds the cookie, `x-forwarded-host` and `x-forwarded-proto` headers that `pinRequestToIssuer` relies on. The consent-requester route and the interaction-login proxy both use it instead of keeping two copies of that contract.
- **Dashboard test:** `consent.test.tsx` has one top-level `beforeEach`. The D4 block's `serve()` only sets the requester and no longer re-stubs `fetch`.
- **Backend:** `loopback_only` is `isLoopbackOnly(client?.redirectUris ?? [])`, because `isLoopbackOnly` already answers false for an empty list.
- **Backend test:** the Cursor and VS Code fallback-port cases are now `HOSTS` rows instead of copies of the table body. `authorizeWith` defaults to the first registered URI. One `authUrlFor` builds the PKCE authorization request for both `authorizeHost` and `interactionFor`.
- **Conformance test:** the plain and path-prefixed issuer cases are one `it.each`, and check 16 joined the 11–14 failure table.

Skipped:

- **Fetching the requester in the consent loader** (efficiency): TanStack loaders also run in the browser, where the path-scoped interaction cookie is not available.
- **Moving `client_id_host` derivation to the dashboard** (altitude, optional): it changes the backend's response contract, which is more than a cleanup.
- **The `!identified` guard in `onSubmit`:** kept as deliberate defense alongside the existing selection guard.
- **The extra pointer probe in `hostMetadata`:** about two requests per operator run, not worth the coupling.

Gates: backend-v2 `yarn typecheck`, `yarn lint`, and `yarn test` (5075 passed). Dashboard `yarn format:check`, `yarn lint`, `yarn test` (5004 passed, 1 skipped), and `yarn build`.

# GraphQL bank mutations take no `dryRun`, while MCP and REST preview all five

**Parity bug · backend-v2 · minor · ~45m · A1.** From `/qa-find-bugs-mcp`, 2026-11-09, production schema introspection.

- **Repro:** each of these returns `GRAPHQL_VALIDATION_FAILED` "Unknown argument \"dryRun\"": `syncPlaidTransactions`, `submitPlaidTransactionsToLedger`, `deletePlaidTransactions`, `reconcilePlaidAccounts`, `unlinkPlaidItem` with `dryRun: true`.
  - **Controls:** MCP `syncBankTransactions`, `importStagedBankTransactions`, `discardStagedBankTransactions`, `reconcileBankAccounts` and `unlinkBankConnection` take `dry_run`. REST bank routes take `?dry_run`/`dryRun` (`banks-handler.ts:46-59,201-259`).
- **Contract:** the w23/m9 definition of done accepts the preview flag "everywhere the flag exists" on all three surfaces. `docs/api-parity.md:305` lists "preview support" under Bank operations.
- **Cause:** `src/features/plaid/api/resolvers/` declares no `dryRun`/`dry_run` argument. w3/m8 added the service-level previews to REST and MCP only.
- **Fix:**
  - Add `dryRun`/`dry_run` twins, refusing a conflict through `resolveFlagAlias`, to the five resolvers.
  - Pass the flag to the existing service preview paths.
  - Expose the preview fields in the GraphQL return types, or add a preview union.
- **Check:** add GraphQL rows to the bank parity tests and to `write-preview-matrix.test.ts`.

---

**Resolved 2026-11-10.** GraphQL now previews the five bank writes, as REST and MCP do. `syncPlaidTransactions`, `submitPlaidTransactionsToLedger`, `deletePlaidTransactions`, `reconcilePlaidAccounts` and `unlinkPlaidItem` take `dryRun` and its `dry_run` twin. Through `resolveFlagAlias`, one true and one false is refused `BAD_USER_INPUT`. The flag goes to the services' existing preview paths.
- **Result types:** each gained the service's preview fields as nullable additions, so existing selections are unchanged:
  - sync: `dryRun`, `wouldAdd`, `wouldModify`, `wouldRemove`, `morePagesAvailable`;
  - submit: `dryRun`, `wouldAddCount`, `preview`;
  - delete: `dryRun`, `wouldDeleteCount`, `preview` rows;
  - reconcile: `dryRun`, `wouldAdd` and `wouldDelete` accounts.
- **Exception — unlink:** `unlinkPlaidItem` keeps its `Boolean` contract, which the dashboard and the app select. A preview runs every check the unlink makes and answers `true` without unlinking. What it would sever is readable through the item and account queries.
- **Bank-argument guard:** the w23/m8/t007 guard (snake_case bank arguments are MCP-only) now exempts exactly the `dry_run` flag twin, which w23/m9 applies on every surface.
- **Tests:** `bank-preview-parity.test.ts` drives all five on REST, MCP and GraphQL. It checks that each reaches its service as a preview and that GraphQL returns the preview fields. It also covers the conflicting-flags refusal. Reverting the resolvers fails all 6 cases. The resolver unit tests pin the forwarded flag.
- **Matrix:** the write-preview matrix classifies the bank tools as summaries, which carry no projection proofs, so it needed no new rows.
- **Docs:** `docs/mcp.md` lists the GraphQL bank previews. (`backend-v2`)

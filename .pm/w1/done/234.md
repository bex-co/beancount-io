# `requestId` idempotency is keyed on the owner spelling, so a retry with different owner case writes twice

**Bug · backend-v2 · major · ~20m · A1.** From `/qa-find-bugs-mcp`, 2026-11-10, production `beancount-mcp 1.0.0`, unpinned API key, the disposable QA ledger. A duplicated transaction breaks the one requirement `requestId` exists to meet.

- **Repro:** `appendLedgerText` with the same text and `requestId`, three times.
  1. `ledger: "<owner>/<name>"` commits, returning `entryHashes ["d3425ab5…"]`.
  2. Repeating the same call replays the first result and writes nothing.
  3. The same call with `ledger: "<OWNER>/<name>"` makes a second commit, returning `entryHashes ["d3425ab5…:1"]`. The file now holds the transaction twice.
  - Owner case is otherwise accepted everywhere: `<OWNER>/<name>` resolves on the MCP tool, the resource, REST and GraphQL.
- **Expected:** one write per (user, ledger, `requestId`). The ledger is the same whatever the owner case, as w23/078 already established for pins.
- **Cause:**
  - `src/features/ledger/service/ledger-entry-service.ts:428,481` build `ledgerId` from the caller's spelling, and `src/shared/cache/cache-keys.ts:132` (`entryWriteRequest`) puts it in the key verbatim.
  - `resolveMcpLedger` (`mcp-context.ts:91-115`) canonicalizes only pinned credentials (`return pin ?? ledger`). The unpinned path, REST `ledgerIdOf` and GraphQL `parseLedgerId` all keep the raw owner.
  - `ledger-receipt-workflow.ts:158` uses the same helper.
- **Fix:**
  - Lowercase the owner in the idempotency key. Owner names are case-insensitive on the host, and ledger names are already lowercase-only.
  - Better: canonicalize the owner once at resolution, to the account's real login. That also fixes the adjacent echo below.
- **Check:** the same `requestId` sent with `Owner/x` and then `owner/x` writes once, on each surface and across surfaces.
- **Adjacent:** `prompts/get spending-report {ledger:"<OWNER>/<name>"}` answers "Pass `ledger: "<OWNER>/<name>"` on every ledger-targeted call", which carries the non-canonical spelling into every later call. Resource and REST bodies already echo the canonical `fullName`.

**Resolved 2026-11-10.** The bug itself was fixed by `67fb3c37d` (`w23/m38`), and this commit finishes the adjacent echo.
- **Already on `main`:** `canonicalLedgerId` (owner lowercased, name exact) is applied inside `CACHE_KEYS.ledger.entryWriteRequest`, so every writer, the receipt insert included, keys idempotency on one spelling. `structured-entry-parity.test.ts` retries one `requestId` with the owner in another case across REST, GraphQL and MCP, and it commits once. `ledger-spelling-matrix.test.ts` runs the spellings through every entry point. Both pass here.
- **This commit:** a prompt given `ledger: "Alice/books"` echoed that spelling into "Pass `ledger: …` on every ledger-targeted call". It now passes on the canonical `alice/books`, and `mcp-prompt-list.test.ts` pins it for every prompt; the test fails without the change. The out-of-pin message still quotes what the caller asked for. (`backend-v2`)

# A relative `XDG_CACHE_HOME` breaks every ledger that uses managed prices

**Severity: minor. Owner: cli. Estimate: ~15m. A1:** environment quirks must not break ledger loads. Continuous CLI QA, 2026-10-03 (round 3); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1 (Beancount 3.2.3, beanquery 0.2.0), Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control.

Managed-price cases are **local simulations**: a threaded `http.server` stub on `127.0.0.1:8765`, enabled with `MANAGED_PRICE_ORIGINS=http://127.0.0.1:8765` and the ledger line `include "http://127.0.0.1:8765/prices/BTC-USD"`. Base fixture: open `Assets:Bank USD`, `Assets:Crypto BTC`, `Equity:Opening`; fund 10000 USD; buy `1 BTC {5000 USD}`; then the include.

```sh
cd /some/other/dir
XDG_CACHE_HOME=relcache bea --file /abs/w_x/main.bean check
```

Actual: exit 1, `File glob "relcache/bea/managed-prices/…/x.effective….beancount" does not match any files`. Control: an absolute `XDG_CACHE_HOME` exits 0.

Expected: the XDG Base Directory spec says relative values are ignored (fall back to the default).

Cause: `cli/src/bea_engine/managed_price_cache.py:96` never makes the path absolute; `managed_load.py:399` writes it into the staged include, which Beancount resolves from the ledger directory. Same pattern at `cli/src/bea_engine/ledger/write.py:34` (locks) and `cli/src/cli/config.py:35`.

Fix/acceptance: ignore a relative `XDG_CACHE_HOME` (and `XDG_CONFIG_HOME`) everywhere. The repro exits 0 using the default cache.

---

**Resolved 2026-10-03** — a relative `XDG_CONFIG_HOME`, `XDG_CACHE_HOME` or `XDG_DATA_HOME` is now ignored in favour of the default, so it no longer breaks ledgers that use managed prices. Tests in `tests/test_price.py` cover it. Shipped in the commit that moved this note (`cli`).

# Empty or scheme-less `BEA_API_URL` is reported as a network outage

**Severity: minor. Owner: cli. Estimate: ~20m. A1:** configuration mistakes must name the variable. Continuous CLI QA, 2026-10-02; report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`, synthetic fixtures. Reproduced twice from pristine fixtures.

```sh
BEA_TOKEN=abc BEA_API_URL= bea cloud ledger list
BEA_TOKEN=abc BEA_API_URL=api.example.invalid bea --json cloud status
BEA_TOKEN=abc BEA_API_URL='http://[::1' bea cloud status
```

Actual: exit **1**, `Could not reach the server (UnsupportedProtocol).` (category `validation`) for empty, scheme-less and `ftp://` values; `http://[::1` gives `Invalid port: ':1'` without naming the variable. Control: an empty `BEA_FILE` is treated as unset (`context.py:87`).

Expected: empty means "use the default", like `BEA_FILE`; a malformed value is a usage error (exit 2) naming `BEA_API_URL` (USAGE environment table: "API base URL").

Cause: `cli/src/cli/settings.py:14–18` — pydantic `Settings` lacks `env_ignore_empty=True` and URL validation; the value goes straight to `Client(base_url=…)` (`cli/src/cli/api/client.py:72,82`), and httpx's `UnsupportedProtocol` lands in the generic transport mapping (`cli/src/cli/errors.py:225–230`).

Fix/acceptance: `env_ignore_empty=True`; validate `api_url` and `dashboard_url` have an http(s) scheme and host, raising `UsageError("BEA_API_URL must be an http(s) URL, got …")`. Empty → default; scheme-less/ftp/bad-port → exit 2 naming the variable in human and JSON output.

Dedupe: no `.pm` hit for UnsupportedProtocol / env_ignore_empty / invalid BEA_API_URL; `git log -S env_ignore_empty` empty.

---

**Resolved 2026-10-03** — an empty `BEA_*` setting now falls back to its default, and a `BEA_API_URL`/`BEA_DASHBOARD_URL` that is not an http(s) URL with a host and valid port is a usage error (exit 2) naming the variable instead of a network outage. `tests/test_settings_urls.py` covers it. Shipped in the commit that moved this note (`cli`).

# `bea report register` puts a balance assertion's asserted amount in the AMOUNT column and the CSV `amount`, so a check that moves nothing reads as a deposit, and a failed one looks like a passing one

Found by `/qa-find-bugs-cli w1` on 2026-11-18 (HEAD `5f13f574a`, `bea 0.4.1`, macOS 26.5.1, Python 3.12.14, checkout `uv run bea`, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, synthetic ledgers). Severity: minor. A1: the register is the reconciliation view, and its CSV is what a spreadsheet or an agent sums; a balance row's amount column holds the whole asserted balance, so `SUM(amount)` over a register no longer equals its closing balance.

**Repro** (synthetic, `main.bean`; `bea check` exits 0):

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Checking USD
2024-01-01 open Equity:Opening-Balances USD
2024-01-01 open Expenses:Food USD
2024-01-02 * "Opening"
  Assets:Checking 100.00 USD
  Equity:Opening-Balances
2024-01-05 * "Groceries"
  Expenses:Food 30.00 USD
  Assets:Checking
2024-01-10 balance Assets:Checking 70.00 USD
2024-01-11 * "Coffee"
  Expenses:Food 5.00 USD
  Assets:Checking
```

```sh
bea -f main.bean report register Assets:Checking
bea -f main.bean report register Assets:Checking --format csv
# then change the assertion to 80.00 USD (it now fails):
bea -f main.bean report register Assets:Checking --allow-errors
```

**Actual** (exit 0). Text: `2024-01-10  Balance check  70.00 USD  70.00 USD`, the asserted amount in AMOUNT beside postings of `100.00`, `-30.00`, `-5.00`. CSV row 3: `3,2024-01-10,Assets:Checking,balance,,,70.00,USD,,,,USD,70.00`; the `amount` column sums to 135.00 while the closing balance is 65.00. JSON: the row's `amount` is `{"number": "70.00", "currency": "USD"}`. With the failing 80.00 assertion and `--allow-errors`, the row reads `Balance check  80.00 USD  70.00 USD`: the same shape as a passing check, the failure only on stderr.

**Expected.** A balance row moves nothing, so its `amount` is empty (null in JSON, empty CSV cell, blank AMOUNT), as the closing row's already is; the asserted figure is carried in its own field (`asserted`) and in the text description (`Balance check: 70.00 USD`), and a failed assertion says so on its row (`Balance check failed: 80.00 USD asserted`) with the difference in JSON. Basis: `_register`'s own docstring calls balance assertions rows "which move nothing"; the CSV contract (USAGE, Reports as CSV) is one row per posting, where `amount` is the posting's amount.

**Root cause.** `cli/src/bea_engine/report.py:1092-1101` builds the balance row with `"amount": row.amount` (the asserted amount) and never reads `diff_amount`; `cli/src/cli/commands/report.py:713-733` (`_row_cells`) prints it under AMOUNT; `cli/src/cli/report_csv.py:181` writes it to `amount`. The hosted register (`backend-cluster/backend-v2/src/features/ledger/utils/register.ts:168-185`) maps a balance entry's amount into its row the same way.

**Fix** (cli; backend-v2 for parity). Emit balance rows with `amount: null` plus `asserted` (and `difference` when `diff_amount` is set); render `Balance check: <asserted>` / `Balance check failed: <asserted> asserted` in DESCRIPTION with AMOUNT blank; leave the CSV `amount` cell empty and add the asserted figure to the row (an `asserted` column, or the narration cell). Mirror the shape in the hosted register so REST, GraphQL and MCP agree, and document the row in USAGE (Reports).

**Regression.** The repro: the CSV `amount` column sums to the closing balance, the JSON balance row has `amount: null` and `asserted` 70.00 USD, and the failing case's row is marked failed with a 10.00 USD difference; each fails with the fix reverted.

**Blast radius.** `bea report register` text, `--json` and `--format csv`, and the hosted register on every surface. Transaction rows and the closing row are unaffected; `bea list balance` lists assertions on their own and is a working control.

**Dedupe.** Searched `.pm/**` for `register` with `balance assertion`, `Balance check`, `entry: "balance"`. w5/1034 and w5/1056 (done) fixed parent expansion and same-day order; w1/252, w1/260 and w1/279 (done) fixed valuation dates, the ACCOUNT column and summarize plugs; none covers balance rows. Estimate: 30–45 minutes.

---

**Resolved 2026-11-18** — a register's balance row now moves nothing: its `amount` is `null` (blank AMOUNT, empty CSV `amount` cell), the asserted figure is `asserted`, and a failed assertion carries Beancount's `diff_amount`, accumulated minus asserted, as `difference` (`-10.00 USD` in the failing repro; `null` when the check passes). Text reads `Balance check: 70.00 USD` or `Balance check failed: 80.00 USD asserted`; CSV adds trailing `asserted`, `asserted_currency` and `difference` columns, so the repro's `amount` column sums to the 65.00 closing balance. The hosted register (`utils/register.ts`, GraphQL `RegisterRow`) gives a balance row no postings and the same `asserted` (with its account) and `difference`, alike on REST, GraphQL and MCP. USAGE (Reports) documents the row. Regression: `cli/tests/test_report_register_balance_assertion.py`, `backend-v2/src/features/ai-agent/api/__tests__/register-balance-parity.test.ts` and the balance cases in `utils/__tests__/register.test.ts`, all failing with the fix reverted.

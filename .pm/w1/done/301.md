# `bea report budget` crashes with an internal `AttributeError`/`TypeError` when a `custom "budget"` line's first value is not an account, and budgets a quoted non-account string such as `"Food"` as an account row

Found by `/qa-find-bugs-cli w1` on 2026-11-19 (HEAD `cbd411874`, `bea 0.4.1`, macOS 26.5.1, Python 3.12.14, checkout `uv run bea`, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, synthetic ledgers). Severity: minor. A1: one malformed budget line throws away the whole report, valid budgets and actuals included, and `--allow-errors` does not help. `bea check` passes, and `bea add custom` writes such a line with exit 0, so an agent has nothing to go on but "Pass --debug before the command for a traceback".

**Repro** (synthetic; `bea check` exits 0).

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Bank USD
2024-01-01 open Expenses:Food USD
2024-01-01 open Equity:Opening-Balances
2024-01-02 * "Open"
  Assets:Bank  1000 USD
  Equity:Opening-Balances
2024-01-05 * "Lunch"
  Expenses:Food  10 USD
  Assets:Bank
2024-01-01 custom "budget" Expenses:Food "monthly" 100.00 USD
2024-01-01 custom "budget" 42 "monthly" 50.00 USD
```

```sh
bea -f main.bean report budget -t 2024-01
bea -f main.bean --json report budget -t 2024-01
bea -f main.bean report budget --allow-errors -a Expenses:Food
```

**Actual.** Exit 1, `Error: TypeError: '<' not supported between instances of 'decimal.Decimal' and 'str'. Pass --debug before the command for a traceback.` `--json` gives `{"error": {"category": "validation", "message": "TypeError: …"}}`. With line 11 removed, the error is `AttributeError: 'decimal.Decimal' object has no attribute 'partition'`; with `-a` it is `… no attribute 'startswith'`. A first value that is a date (`bea add custom -t budget -v date:2024-01-01 -v text:monthly -v 'amount:50.00 USD'` writes one with exit 0), `TRUE`, or an amount (`42 USD`) crashes the same way. A quoted non-account string is not refused: `"Food"` and `""` each get a budget row (`Food 6.45 USD`, a blank account name), and `Expenses:Food` is listed `(unbudgeted)`.

**Expected.** A budget line whose first value is not an account name is a budget diagnostic, as an unknown interval or a bare-number amount already is (w5/1122, w1/297): `main.bean:12: Budget ignored: first value 42 is not an account (custom "budget" ACCOUNT INTERVAL NUMBER CURRENCY)` on stderr and in `--json` `budget_errors`. The report still prints the valid `Expenses:Food 100.00 USD / 10.00 USD / -90.00 USD` row and exits as it does for the other budget diagnostics (0 in the control below). A quoted string that is a valid account name (`"Expenses:Food"`) keeps working as it does today.

**Working control.** The same ledger with line 12 replaced by `2024-01-01 custom "budget" Expenses:Food "montly" 50` prints `main.bean:12: Budget for Expenses:Food ignored: unknown interval "montly" (…)` and the valid row, with exit 0.

**Root cause.** `parse_budgets` (`cli/src/fava/modules/budgets.py:146-152`) checks the interval and, since w5/1122, the amount. It passes `entry.values[0].value` into `Budget` unchecked, whatever its type. `BudgetModule.accounts` (`budgets.py:60`) then sorts mixed `str`/`Decimal`/`date` keys (`TypeError`). `_budget`'s `kind_of` (`cli/src/bea_engine/report.py:397-398`) calls `.partition` on the value, and the subtree match (`report.py:419`) calls `.startswith` (`AttributeError`). The loader raises nothing because Beancount does not type-check `custom` values.

**Fix** (cli only). In `parse_budgets`, refuse an entry whose first value is not a `str` that is a valid account name (`beancount.core.account.is_valid`), with a `BudgetError` marked as a Beancount.io change like w5/1122's. Teach `_budget_error` (`report.py`) to render it with the line and the value as written, reusing `_as_written`. No other budget changes.

**Regression.** The repro prints the valid Food row and one located diagnostic for line 12, in text, `--json` `budget_errors` and `--format csv` stderr, for a number, a date, a boolean, an amount, `"Food"` and `""` as the first value. `"Expenses:Food"` quoted still budgets Expenses:Food. The tests fail with the fix reverted.

**Blast radius.** `bea report budget` is the only consumer of `ledger.budget` (`grep -rn "\.budget\b" cli/src`). The hosted Budget page reads budgets through the ledger service, not this parser, and was not exercised. Also seen, not filed again: a budget for an account the ledger never opens (`Expenses:Fod`), already recorded as upstream Fava behavior in [w1/297](./297.md).

**Dedupe.** Searched `.pm/**` for `custom "budget"`, `report budget`, `budget entry`, `AttributeError` and `partition`. [w5/1122](../../w5/done/1122.md) fixed the same crash for the third value (the amount), and [w1/297](./297.md) gave each refused line its location. Neither checks the first value. Estimate: 20–30 minutes.

---

**Resolved 2026-11-19** — `parse_budgets` refuses a `custom "budget"` line whose first value does not name an account, before the interval and amount checks, and `bea report budget` reports it like the other ignored budget lines: `main.bean:12: Budget ignored: first value 42 is not an account (custom "budget" ACCOUNT INTERVAL NUMBER CURRENCY)`, the value as written (`2026-01-01`, `TRUE`, `42 USD`, `"Food"`, `""`). The repro now prints the valid `Expenses:Food 100.00 USD / 10.00 USD / -90.00 USD` row with exit 0, in text, `--format csv` and `--json`, and `--allow-errors -a Expenses:Food` no longer crashes. An unquoted account still budgets as before, and a quoted string budgets when it is spelled as an account the loader reads, so `"Expenses:Food"` and a CJK leaf such as `"Expenses:Food:中餐"` keep working. Covered by `cli/tests/test_report_budget.py` (`test_a_budget_whose_first_value_is_not_an_account_is_ignored_not_fatal` for all six first values across JSON, text, CSV and the filtered report; `test_a_quoted_account_name_still_budgets_that_account`); the six fail with the fix reverted, and the quoted-account test fails if the CJK branch is removed. `cli/docs/USAGE.md` documents the diagnostic. Shipped in `273c6f0b2` (`cli`).

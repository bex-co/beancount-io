# `bea add price -c USD --amount '1 EUR'` counts as agreeing with a same-day `price EUR 1.90 USD`, writes with exit 0, and EUR drops from 1.90 to 1.00 USD in every report, while the same rate typed `1.0 EUR` is refused as a conflict

**Bug · cli · minor · 20–40m · A1.** From routine cli-qa, 2026-11-20. This is a gap in the reciprocal check from [w5/741](../w5/done/741.md), which follows [w5/556](../w5/done/556.md). When a quote is added on a day that already has a quote in the other direction, `add price` and `import` test whether the two agree. `reciprocal_agrees` asks only one question: does the inverse of the existing quote, rounded to the new quote's typed precision, equal the new quote? The fewer digits the new quote has, the more it agrees with. With one significant digit, `1` agrees with any reciprocal from 0.67 to 2.0. Once both quotes are recorded, the settlement rule from w5/740 decides which one values the day: the direction quoted less often wins, and a tie goes to the quote from the alphabetically later currency. So one coarse `price USD 1 EUR` beats a daily `price EUR 1.90 USD` series for that day. The holding is revalued with exit 0 and no warning. The same rate typed as `1.0 EUR`, or a closer `0.8928 EUR` beside `1.12 USD`, is refused with exit 4. Whether a write goes through depends on trailing zeros and on which quote was written first.

Environment: main `94c43ab3d`, `bea 0.5.0` from the checkout (`uv run bea`), Python 3.12.14, macOS 26.5.1. Isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, `BEA_FILE`/`BEA_TOKEN` unset, stdin closed, no TTY, cwd a scratch directory. Each case was rerun from a pristine copy in fresh processes.

Same day, other order: start from a ledger whose only quote is `2026-01-05 price USD 1 EUR`, then run `add price --date 2026-01-05 -c EUR --amount '1.90 USD'`. That exits 4 ("1.90 USD disagrees with it") and leaves the file unchanged. One pair of quotes gets opposite verdicts depending on which was written first.

More observations, on the same shape of ledger with `2025-03-10 price EUR 1.12 USD`:
- `-c USD --amount '1 EUR'` and `'0.9 EUR'` are both written with exit 0. After the `1 EUR` write, `convert(sum(position), 'USD', 2025-03-12)` of a `45.00 EUR` expense reads 45.00 USD, not 50.40 USD.
- `'0.8928 EUR'` and `'0.8 EUR'` are refused with exit 4. 0.8928 is within 0.01 % of 1/1.12 = 0.892857, yet it is refused while `1` is accepted.
- `JPY 0.01 USD` beside `price USD 150 JPY` (which implies 100 JPY per USD, a third off) also counts as agreeing. That quote loses the tie, so the run prints the "never used" advisory and the valuation is unchanged. The verdict is still wrong.

## Expected

A same-day reciprocal agrees only when it names the rate already on record. The verdict must not change with trailing zeros (`1` and `1.0` get the same answer) or with which of the two quotes was written first. The documented agreeing examples from w5/741 stay agreeing: `0.3333` beside `3`, and `0.9211` beside `1.0857`. Everything else gets the existing exit-4 refusal, `--force` included, in both `add price` and `import`. The basis is the purpose w5/556 gives the check: a disagreeing reciprocal changes how reads value the pair. Here it does, by 47 %.

## Cause

`cli/src/bea_engine/ledger/prices.py:50` `reciprocal_agrees(typed, other)` tests one direction only: `(ONE / other).quantize(<typed's exponent>) == typed`. With `typed = 1`, every `other` in roughly [0.67, 2] passes. The reverse question, whether `1 / typed` rounded at `other`'s precision gives back `other`, is never asked (`1/1 = 1.00 ≠ 1.90`). Callers: `cli/src/bea_engine/ledger/adding.py:1244` (`add price`) and `cli/src/bea_engine/importing.py:772` (importer price rows, against recorded quotes and earlier rows of the same import). The winner is then chosen by `_settle_pair` in `prices.py` (the direction quoted less often, then the later currency). That is why the coarse quote can take over the day.

## Fix

Make agreement symmetric in `reciprocal_agrees`: require `reciprocal_agrees(typed, other) and reciprocal_agrees(other, typed)`, so both quotes round-trip to each other at their own typed precision. Checked against the current helper:

| typed | other | today | symmetric |
| --- | --- | --- | --- |
| `1` | `1.90` | agrees | refused |
| `1` | `1.12` | agrees | refused |
| `0.01` | `150` | agrees | refused |
| `0.3333` | `3` | agrees | agrees |
| `0.9211` | `1.0857` | agrees | agrees |
| `0.89` | `1.12` | agrees | agrees |
| `0.8929` | `1.12` | agrees | agrees |
| `1.0` | `1.90` | refused | refused |

A consequence to accept or adjust: `0.53` beside `1.90`, and `0.0067` beside `150`, become refusals, because their inverses (1.89, 149) do not round back. Update the USAGE.md:1740 sentence ("the inverse of one rounds to the other at the typed precision") to say both ways. Add regression cases next to `test_agreement_is_judged_at_the_typed_precision` in `cli/tests/test_reciprocal_price_checks.py`. Cover `add price` with `1 EUR` refused beside `EUR 1.90 USD`, the same answer as `1.0 EUR`, the reversed write order, and an importer price row with the same refusal.

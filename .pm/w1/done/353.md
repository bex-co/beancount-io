# `bea update transactions --help` and `USAGE.md` still say any rejected row exits 1, but a preview with a rejected row exits 0 (by design), so an agent that runs the preview as a gate reads exit 0 as "every row is valid" (unfinished acceptance of w5/1081)

**Bug · cli · minor · ~20m · A1.** From routine cli-qa, 2026-11-22. A batch preview that rejects a row exits **0** on purpose. It lists every row's status and the `ready` / `rejected` counts, and writes nothing. `--apply` writes the valid rows and exits **1**. Two regression tests pin this: `test_preview_with_a_reject_still_exits_0` and `test_csv_preview_flags_rejects` in `cli/tests/test_update_batch.py`. The engine contract states it too (`cli/src/bea_engine/README.md:201-205`: "A preview answers every row's status with exit 0 even when some are rejected").

The two texts a user or agent actually reads still promise the opposite, with no exception for previews:

- `bea update transactions --help` (`cli/src/cli/commands/update.py:326-328`): "a rejected row never aborts the valid ones, but the exit status is still 1 whenever any row was rejected".
- `cli/docs/USAGE.md:2069`: "Any rejection exits **1** with per-row results, as `bea add transactions --partial` reports."

The addendum to [w5/1081](../../w5/done/1081.md) ("Preview exit-policy and help clarification — 2026-10-28") asked for exactly this fix. It said to qualify both sentences with `--apply` and to say that preview callers read `data.rejected` and the row statuses. Its "Additional acceptance" was that help and USAGE tell preview exit 0 apart from `--apply` exit 1. The note was closed on 2026-11-01 for its cumulative-preview repair, and neither sentence changed. `git log -S` finds no later edit to either.

The single-row form is no help as a model. `bea update transaction` previews a refused edit with exit **1** (w1/259), so the batch form is the one where "preview passed" and "exit 0" differ. That makes the unqualified help sentence misleading. An agent that previews a mapping, checks the exit status, and then applies it gets exit 1 on the apply, with the valid rows already written.

Environment: main `a88d2e12b` (rechecked at `a33691536`), `bea 0.5.0` from the checkout (`uv run bea`), macOS 26.5.1. Isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, stdin closed, no TTY, fresh processes.

## Repro

```sh
cat > main.bean <<'EOF'
option "operating_currency" "USD"
2026-01-01 open Assets:Bank USD
2026-01-01 open Expenses:Uncategorized USD
2026-01-01 open Expenses:Groceries USD

2026-01-03 ! "Whole Foods" "card purchase"
  import-id: "aaa1"
  Assets:Bank  -45.10 USD
  Expenses:Uncategorized  45.10 USD
EOF
printf 'id,account,flag\naaa1,Expenses:Groceries,*\nzzz9,Expenses:Groceries,*\n' > rows.csv

bea update transactions --help | grep -A1 'exit status'   # "...the exit status is still 1 whenever any row was rejected"
bea --file main.bean update transactions --from rows.csv
# exit 0: row 1 ok, row 2 rejected "No transaction with import-id or ref 'zzz9' in this ledger.",
# then "Preview only. Fix the 1 rejected row, then preview again."
bea --json --file main.bean update transactions --from rows.csv
# exit 0, data.ready 1, data.rejected 1, data.written 0; main.bean unchanged
bea --file main.bean update transactions --from rows.csv --apply
# exit 1 "Updated 1 of 2 transactions; 1 row was rejected."; row 1 is written
```

## Done when

- `bea update transactions --help` and `cli/docs/USAGE.md` tie the exit-1 rule to `--apply`. Both also say that a preview with rejected rows exits 0, writes nothing, and reports the rejections in its row statuses and `rejected` count (`data.rejected` under `--json`), so a preview gate checks that count, not the exit status.
- The engine docstring at `cli/src/bea_engine/ledger/updating.py:1008-1011` says the same, in step with its README.
- The exit codes do not change. `test_preview_with_a_reject_still_exits_0`, `test_csv_preview_flags_rejects` and the apply exit-1 tests still pass. `make docs` is rerun if the help change touches `docs/REFERENCE.md`, and `make check-all` passes in `cli/`.

Dedupe: [w5/1081](../../w5/done/1081.md) owns the decision and asked for this wording, which never shipped. No open item in any workstream covers it. [w1/258](258.md) and [w1/259](259.md) cover preview reasons and single-row preview validation, not this sentence.

**Resolved 2026-11-22** — `bea update transactions --help`, `cli/docs/USAGE.md` ("Updating directives") and the engine docstring of `_transactions` in `cli/src/bea_engine/ledger/updating.py` now tie the exit-1 rule to `--apply`, and say that a preview with rejected rows writes nothing, exits 0, and reports each rejection in its row status and its `rejected` count (`data.rejected` under `--json`), so a script that previews before applying checks that count, not the exit status. Docs only: the exit codes are unchanged, and the wording describes current behaviour without settling [w1/261](../blocked/261.md), which stays blocked on the owner's choice of exit code. Shipped in the commit that closes this note (`cli`).

# `--offline` writes to the managed-price cache, and a read-only cache crashes loads with a raw `[Errno 13]`

**Severity: minor. Owner: cli. Estimate: ~45m. A1:** offline mode must be read-only and a cache problem must degrade, not break, the ledger. Continuous CLI QA, 2026-10-03 (round 3); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1 (Beancount 3.2.3, beanquery 0.2.0), Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control.

Managed-price cases are **local simulations**: a threaded `http.server` stub on `127.0.0.1:8765`, enabled with `MANAGED_PRICE_ORIGINS=http://127.0.0.1:8765` and the ledger line `include "http://127.0.0.1:8765/prices/BTC-USD"`. Base fixture: open `Assets:Bank USD`, `Assets:Crypto BTC`, `Equity:Opening`; fund 10000 USD; buy `1 BTC {5000 USD}`; then the include.

1. After a refresh, delete the feed's `*.effective.*` file; `bea --offline --file /abs/main.bean check` exits 0 but recreates it. Adding a ledger price makes `--offline balance` rewrite it.
2. `chmod 555` the feed's cache directory, delete the effective file, `--offline check` → exit 1, `Error: [Errno 13] Permission denied: '…/O.effective.<key>.beancount'`.
3. Read-only feed directory with a lapsed window: online `check`, `balance`, `list` all exit 1 with `[Errno 13] … .head.json.tmp`.

Control: read-only directory where the effective file already exists → `--offline check` exits 0.

Expected: ADR018 §8 — `--offline` "reads the head and its blob only, makes no network call, and writes nothing"; `managed_price_cache.py:199` "Never fails for a feed problem in lenient mode"; ADR018 §12 "degrades, it does not break the ledger".

Cause: `cli/src/bea_engine/managed_load.py:257–258` writes the effective text regardless of `want_offline` (non-atomically); `managed_price_cache.py:228/267/288` call `_write_text` without an `OSError` guard.

Fix/acceptance: when offline or when the write fails, stage the effective text beside the staged ledger (`candidate_file` temp) instead of the cache; in lenient mode record cache write failures as `last_error`. Offline leaves the cache byte-identical; a read-only cache yields exit 0 plus a warning, never a raw errno.

Dedupe: [073](./073.md) is a read-only include directory on writes — different path. No `.pm` hit for offline cache writes.

---

**Resolved 2026-10-03** — `--offline` no longer writes the managed-price cache, a read-only cache degrades to a source error plus a warning while prices still load, and `price refresh` on a read-only cache exits 1 with a clear message instead of a raw `[Errno 13]`. Tests in `tests/test_price.py` cover each case. Shipped in the commit that moved this note (`cli`).

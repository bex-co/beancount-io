# Parsing an issued but never-uploaded temp asset is a 500, not "upload first"

**Bug · backend-v2 · minor · ~20m · A1.** From `/qa-find-bugs-mcp`, 2026-11-08, production `beancount-mcp 1.0.0`, unpinned API key.

- **Repro:**
  1. Call `generateTempAssetUploadUrl {"filename":"qa.csv","mimeType":"text/csv"}` and skip the PUT.
  2. Call `parseFile {"fileFormat":"csv","objectKey":"<returned key>"}` or `parseReceipt {"ledger":…,"objectKey":…}`.
  - **Result:** MCP returns `INTERNAL_SERVER_ERROR` with the hint "Retry once… changing the request will not help". REST `POST …/import/parse-file` and `…/import/parse-receipt` return 500. GraphQL `parseFile` returns `INTERNAL_SERVER_ERROR`.
  - **Control:** a well-formed key that was never issued gets `NOT_FOUND` "Temporary asset not found" with the upload hint.
- **Cause:** `src/features/s3/service/asset-storage-service.ts:319-336` (`getObjectMetadata`) sends `HeadObjectCommand` with no catch, so the S3 `NotFound`/404 becomes an unexpected error. It is called from `src/features/llm/service/llm-service.ts:191,255` after authorization passes. No model call is made and nothing is billed.
- **Fix:** map `NotFound`/`NoSuchKey`/HTTP 404 to `NotFoundError("Temporary asset")` with the existing temp-asset hint. This shared service covers all three surfaces.
- **Check:** both parse paths with an issued but missing object return `NOT_FOUND` and the upload hint on MCP, REST and GraphQL.

**Addendum 2026-11-09:** the same class reaches receipt insert.
- **Repro:** after a successful `insertReceiptTransaction`, the S3 store promotes and deletes the temp object. Calling it again without `requestId` and with the same `receiptObjectKey` gets `INTERNAL_SERVER_ERROR` with "Retry once…" (REST: 500). The result is the same even when the postings are unbalanced; a fresh key gets `UNBALANCED`. Replaying with the same `requestId` returns the first result.
- **Cause:** `asset-storage-service.ts:235`'s `CopyObjectCommand` has no `NoSuchKey` catch, like `getObjectMetadata` above. Some earlier step also touches the object before the entry check (`ledger-receipt-workflow.ts:326`); that step is unlocated.
- **Fix:** map `NotFound`/`NoSuchKey` in both `copyTempToPermanent` and `getObjectMetadata`, and add a consumed-key case for receipt insert on MCP and REST.

---

**Resolved 2026-11-10.** An absent temp object is now the caller's `NOT_FOUND` "Temporary asset not found" with the temp-asset hint, on MCP, REST and GraphQL. It used to be a 500.
- **Parse:** `getObjectMetadata` maps S3's `NotFound`, `NoSuchKey` or any 404 to that error. Other storage failures pass through unchanged. Both parse paths therefore refuse a key that was issued but never uploaded, before any download, model call or charge.
- **Receipt insert (S3 store):** `copyTempToPermanent` applies the same mapping, so a consumed key gets `NOT_FOUND` after the entry pre-check and nothing is committed.
- **"Earlier step" from the addendum:** there is none. The UNBALANCED result for a fresh key comes after the promotion step, so a consumed key reached the copy first. That explains the result.
- **Receipt insert (git store):** this store downloads over the presigned URL, so `fetchAssetAsBase64` now accepts a 404 error. A never-uploaded receipt there gets the same `NOT_FOUND`.
- **Tests:** unit cases in `asset-storage-service.test.ts` and `fetch-asset-base64.test.ts`. Three-surface cases in `file-parse-parity.test.ts`, `receipt-parse-parity.test.ts` and `receipt-insert-parity.test.ts`; they use a real `AssetStorageService` over a 404-answering S3 client. All fail without the fix. `docs/mcp.md` describes the miss. (`backend-v2`)

# A setup that lists the same account twice silently keeps only the last entry

**Bug · backend-v2 · minor · ~15m · A2.** From `/qa-find-bugs-mcp`, 2026-11-09, production `beancount-mcp 1.0.0`, `previewLedgerSetup` only.

- **Repro:** call `previewLedgerSetup {"setup":{"preset":"personal@1","historyStart":"2024-01-01","accounts":[{"name":"Assets:Bank","openingState":"known","amount":"10"},{"name":"Assets:Bank","openingState":"zero"}]}}`.
  - The preview returns `ok` and `validation.ok: true`.
  - `Assets:Bank` opens with `bcio_opening_balance_status: "zero"`. There is no opening transaction or assertion, so the 10 USD is dropped.
  - Known 10 followed by known 20 writes 20.
  - REST `POST /api-gateway/v1/ledgers/preview` behaves the same.
  - `createLedger` shares the builder.
- **Expected:** `VALIDATION_FAILED` 'Account "Assets:Bank" is listed more than once'. The same builder already refuses a repeated module ('Module "investments@1" is selected more than once').
- **Cause:** `backend-cluster/backend-v2/src/features/ledger/setup/build-ledger.ts:265-313`. The `setup.accounts` loop stores each entry with `selected.set(selection.name, …)` (`:313`), so a repeated name silently overwrites the earlier one. The module loop has a repeat check at `:165`; this loop does not. The code dates from 411b9db7b (w3/m53/t002).
- **Fix:** track the names already seen in that loop and `fail()` on a repeat. The builder is shared, so this covers preview and create on REST, GraphQL and MCP.
- **Check:**
  - Add a case to `build-ledger.test.ts`.
  - Add a row to the setup-surfaces parity test.
  - Confirm whether the dashboard and mobile Create Ledger flows can ever send a repeat.

---

**Resolved 2026-11-10.** A setup that lists the same account twice is now refused `VALIDATION_FAILED` 'Account "Assets:Bank" is listed more than once'. The second entry used to silently replace the first. The `setup.accounts` loop in `build-ledger.ts` tracks the names it has seen, as the module loop already did. The builder is shared, so preview and create refuse it on REST, GraphQL and MCP.
- **Clients:** checked — the dashboard and mobile Create Ledger flows send `template` (`STARTER`/`SAMPLE`) and never `setup.accounts`, so they can't hit the new refusal.
- **Tests:** `build-ledger.test.ts` covers known-then-zero and known-then-known. `setup-surfaces.test.ts` checks that the REST and MCP schema accepts the shape, the builder refuses it, and the MCP preview rejects with `VALIDATION_FAILED`. Reverting the fix fails 3. (`backend-v2`)

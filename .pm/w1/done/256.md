# `report holdings` lists an uncosted balance in a non-asset account as a holding

**Source:** follow-up surfaced by the w1/255 worker, 2026-11-15 (introduced by the w1/253 fix, `289009046`).

At HEAD, an uncosted posting with a price in any account is listed by `bea report holdings` (and the hosted holdings report), for example:

```
Expenses:Travel   100 EUR @ 1.1 USD
```

shows `100 EUR` under holdings. Holdings should only cover balance-sheet positions (Assets, and Liabilities where relevant), never Income/Expenses flow accounts.

Fix in both `cli/src/bea_engine/report.py` and backend-v2 `holdings.ts` (REST/GraphQL/MCP parity). Done when the example above no longer appears in holdings on any surface, an uncosted lot in an Assets account still does (w1/253), and a regression test covers both.

---

**Resolved 2026-11-15** — Holdings count an uncosted balance as a position only under the ledger's Assets or Liabilities root (renamed roots honored): `Expenses:Travel 100 EUR @ 1.1 USD`, and likewise uncosted Income or Equity balances, no longer appear, while an uncosted lot in Assets (w1/253) and an uncosted BTC loan in Liabilities still do. `bea report holdings` (`cli/src/bea_engine/report.py`) and the hosted composer behind REST, GraphQL and MCP (`backend-v2` `utils/holdings.ts`, fed the root names by `ledger-finance-service.ts`) apply the same rule; `cli/docs/USAGE.md`, the REST description and both OpenAPI snapshots say so. Regression tests in `cli/tests/test_report_holdings_uncosted.py` and `backend-v2/.../utils/__tests__/holdings.test.ts` fail with the fix reverted. (`cli`, `backend-v2`)

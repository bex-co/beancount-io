# `price status` reports a 1970 next refresh and no error for a never-fetched managed price source

**Severity: minor. Owner: cli. Estimate: 15–20m. A1:** status output must agree with the load error agents see. Continuous CLI QA, 2026-10-02 (round 2); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed unless a PTY is stated. Reproduced at least twice from pristine fixtures.

Ledger including `https://beancount.io/prices/BTC-USD`, empty cache:

```sh
bea --offline --file /abs/main.bean price status
bea --offline --json --file /abs/main.bean price status
```

Actual: NEXT REFRESH `1970-01-01T00:00:00Z`, blank ERROR; JSON `"next_refresh_at": "1970-01-01T00:00:00Z", "error": null` — while the same run's stderr banner says "no cached revision".

Expected: `null`/`-` (or "now") for next refresh, and an error matching the banner.

Cause: the `0.0` sentinel (`cli/src/bea_engine/managed_price_cache.py:114`) serialized by `_iso` (`cli/src/bea_engine/managed_load.py:187,309`); `error=result.head.last_error` (`:311`) stays `None` while the load error uses "no cached revision" (`:404`).

Fix/acceptance: emit `null`/"-" for a never-fetched source and populate the error. The repro shows no 1970 date and the error column names the missing revision in human and JSON output.

Dedupe: `w3/413`, `w3/433` cover offline load errors, not status rendering.

---

**Resolved 2026-10-03** — `bea price status` now reports a never-fetched managed price source with no next refresh (`null`/`-`) and the error "no cached revision" instead of a 1970 timestamp and no error.

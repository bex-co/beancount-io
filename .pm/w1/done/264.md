# `bea report capital-gains` prints a one-day holding as `1 days (short)`

Found by `/qa-find-bugs-cli w1` on 2026-11-15 (HEAD `668a8fd66`, `bea 0.3.1`, macOS 26.5.1, checkout `uv run bea`, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, synthetic ledger). Severity: minor (cosmetic, human table only). A3: a lot sold the day after it was bought reads wrong in a tax-season report people paste into notes or emails.

**Repro** (synthetic):

```sh
cat > main.bean <<'EOF'
2026-01-01 open Assets:Cash USD
2026-01-01 open Assets:Broker AAPL "FIFO"
2026-01-01 open Income:Gains USD

2026-01-02 * "Buy"
  Assets:Broker   2 AAPL {100 USD}
  Assets:Cash  -200 USD

2026-01-02 * "Sell same day"
  Assets:Broker  -1 AAPL {} @ 110 USD
  Assets:Cash   110 USD
  Income:Gains

2026-01-03 * "Sell next day"
  Assets:Broker  -1 AAPL {} @ 120 USD
  Assets:Cash   120 USD
  Income:Gains
EOF
bea --file main.bean report capital-gains
```

**Actual.** Exit 0. The HELD column reads `0 days (short)` and `1 days (short)`. `--json` (`held_days: 1`) and `--format csv` (`held_days` = `1`, `term` = `short`) are correct.

**Expected.** `1 day (short)` for exactly one day. Every other count, zero included, keeps `days`.

**Root cause / fix (cli only).** `cli/src/cli/commands/report.py` (about line 782) formats `f"{row['held_days']} days (…)"` with no singular case. Use `day` when `held_days == 1`. Add a case to the capital-gains report tests: a one-day lot renders `1 day (short)`, a zero-day lot `0 days (short)`, and the JSON/CSV values stay unchanged. The test fails with the fix reverted. Estimate: about 10 minutes.

**Dedupe.** Searched `.pm/**` for `1 days` and `held_days`. Only the w1/249 long/short boundary fix touches this column, and it does not cover the wording. No open item.

---

**Resolved 2026-11-15.** `_held()` in `cli/src/cli/commands/report.py` now writes `day` when `held_days == 1` and `days` for every other count, so the capital-gains HELD column reads `1 day (short)` and `0 days (short)`. JSON `held_days` and the CSV `held_days`/`term` columns are unchanged. New case `test_capital_gains_one_day_hold_is_singular` in `cli/tests/test_report_capital_gains_frontend.py` (the note's repro: a same-day and a next-day sale) checks the text, JSON, and CSV, and fails with the fix reverted.

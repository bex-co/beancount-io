# Billing's plan card shows the list price when a discount applies

**Bug · dashboard · ~45m · A2.** Found by the w1/m39/t014 hosted check on 2026-11-02.

A subscription with an ongoing 100%-off discount reads "$959.88/year" on the Billing plan card and in the billing list. Its change sheet correctly says "Due today $0.00, then $0.00/year" (fixed in [182](./done/182.md)). The card and the list show the price's list amount and ignore the subscription's discounts, so the two surfaces disagree about what the customer pays.

- **Where:** `dashboard/src/features/user-settings/`, the plan summary card and the billing subscription list. Neither has any discount handling.
- **Fix:** show what the subscriber pays, using the same discount-aware amount the server already computes for the change sheet's "Then $X", with the list price as secondary text when they differ. Cover percent-off, amount-off, and expired-repeating discounts.
- **Check:** a synthetic subscription with a forever 100%-off coupon shows $0.00/year (list $959.88) on the card, the list, and the sheet alike.

---

**Resolved 2026-11-02.** Billing status now carries `Subscription.nextChargeAmount`: what the next renewal charges, in minor units, after the discounts still running then. It is null when the plan ends or changes plan at the period end.
- **Backend (`backend-v2`):**
  - It reuses `afterDiscounts` from the change preview (w1/182).
  - The status listing now expands `data.discounts.source.coupon`.
  - A subscription without discounts costs no extra Stripe call.
  - The field is GraphQL-only like the rest of billing status, so the parity baseline is unchanged.
- **Dashboard:** the plan card, the checkout confirmation's renewal line and the Billing list row show that amount, falling back to the price's amount when it is null.
- **Tests:**
  - The resolver tests cover 100% off forever → $0, no discount → list price with no Stripe call, an ended discount, and a plan ending at period end → null.
  - A summary-card test shows $0.00 on both the card and the list row.
  - Both were mutation-checked.
- **Deploy order:** backend-v2 before the dashboard. The dashboard queries the new field, and an older schema would reject Billing's status query.

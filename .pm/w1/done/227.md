# File writes report "No new bean-check errors" for a `.bean` file nothing includes

**Bug · backend-v2 · minor · ~30m · A1.** From `/qa-find-bugs-mcp`, 2026-11-10, production `beancount-mcp 1.0.0`, the disposable QA ledger.

An agent splitting a ledger ("put August in `2026-08.bean`") gets a green verdict for a file whose entries count nowhere and were never validated.

- **Repro:**
  - `createLedgerFiles {"files":[{"path":"qa-x/orphan.bean","content":"2026-09-10 * \"x\" \"y\"\n  Expenses:Nope   5.00 USD\n  Assets:Bank:Checking\n"}],"dry_run":true}` returns "… No new bean-check errors." with `validation {errorsAfter:0,newErrors:[],valid:true}`.
  - `Expenses:Nope` was never opened. The same file reports E1001 once it is included. The commit says the same thing.
  - **Control:** `appendLedgerText` with a `path` nothing includes is refused: "… is not included by the ledger (main.bean does not reach it) …" (w23/035).
- **Expected:**
  - The description promises "bean-check's verdict over the projected contents". When a created or updated `.bean` path is outside the loaded source files, the result should say so. Example summary: "`qa-x/orphan.bean` is not included by any loaded file: its entries don't count and were not checked". A `notLoaded: [paths]` field would also work.
  - It must not refuse or auto-include. The owner decided on 2026-10-30 (w21/588) that API file creation stays as is, and agents keep control of `main.bean`.
- **Cause:** `src/features/ai-agent/tools/edit-ledger-files-tool.ts` `summarizeWrite` (around `:490`, `:556`) reports only the projected loader's `newErrors`. It never compares the touched paths with the projected source-file list, which the append workflow already reads (`directive-append-workflow.ts:410-429`, `assertLoaded`).
- **Fix:**
  - After projection, collect the touched `*.bean` paths that are missing from the projected source files.
  - Name them in the summary and in a new optional outputSchema field.
  - Apply the same notice to REST `PUT …/files` and GraphQL `createLedgerFile`/`updateLedgerFile`, per the parity workflow.
- **Check:** creating an orphan file gets the notice; creating an included file does not.

**Resolved 2026-11-10.** A file write now names any `.bean`/`.beancount` file it creates or rewrites that no loaded file includes. It neither refuses the write nor includes the file (w21/588).

- **Shared check:** `unloadedLedgerFiles` (`ledger/utils/file-write-gate.ts`) takes the write's overlays and asks the ledger for the projected source files through `projectedSourceFiles`, which now also projects deletions. It returns the written ledger files that are missing from that list. Files that are not ledger files, and deletions, are never asked about. When the ledger service cannot answer, nothing is named, as with the append's check (w23/062).
- **MCP:** `createLedgerFiles`, `updateLedgerFiles` and `deleteLedgerFiles` (the delete's include rewrites) return an optional `notLoaded`, on the preview and on the commit. The summary adds "`<path>` is not included by any loaded file: its entries don't count and were not checked."
- **REST:** `PUT …/files/{path}` returns the same optional `notLoaded`. The OpenAPI `FileCommitAck` gains the field; the CLI's pinned spec is re-synced and its client regenerated.
- **GraphQL:** `createLedgerFile`/`updateLedgerFile` return a nullable `notLoaded`. The check runs after a successful write, so each GraphQL write of a ledger file now makes one more ledger-service call.
- **Size:** the `tools/list` budget moves from 115 KB to 116 KB (118,156 bytes), with the reason recorded beside it in `mcp-tool-list.test.ts`.
- **Tests:** `unloaded-file-parity.test.ts`:
  - an orphan file is named on MCP (preview and commit), REST PUT (both) and GraphQL create;
  - an included file is named nowhere;
  - the helper asks nothing for a write with no ledger file, and fails open.

  Reverting the wiring fails 5 cases. `docs/mcp.md` describes `notLoaded`. (`backend-v2`, `cli` generated client)

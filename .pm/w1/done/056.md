# A symlinked root ledger resolves includes from the link target's directory, unlike `bean-check`

**Severity: minor. Owner: cli. Estimate: 45–60m. A1:** bea must agree with upstream on which ledger it loads. Continuous CLI QA, 2026-10-02; report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`, synthetic fixtures. Reproduced twice from pristine fixtures.

```sh
mkdir -p repo/sub shared
printf 'option "operating_currency" "USD"\ninclude "sub/accounts.bean"\n2026-01-02 * "Opening"\n  Assets:Checking  100.00 USD\n  Equity:Opening\n' > shared/books.bean
printf '2026-01-01 open Assets:Checking USD\n2026-01-01 open Equity:Opening USD\n' > repo/sub/accounts.bean
ln -s ../shared/books.bean repo/main.bean
cd repo
bea check                 # also --file /abs/repo/main.bean, and BEA_FILE
bean-check main.bean      # control: exit 0
```

Actual: `bea check` exits **1** with `File glob "sub/accounts.bean" does not match any files` plus two unknown-account errors; JSON target shows `.../shared/books.bean`. `list` and `query` fail the same way. Controls `bean-check` and `bean-query` load it correctly.

Expected: `bea check` documents delegation to `bean-check FILENAME`; Beancount's loader uses `path.abspath` (does not follow links), so includes resolve beside the link.

Cause: `cli/src/cli/context.py:124` (`return candidate.resolve()`), repeated in `cli/src/bea_engine/main.py:694` and `LedgerSnapshot.capture(entry.resolve())` at `cli/src/bea_engine/managed_load.py:229` and `:554`. Comments justify these only as "make absolute".

Fix/acceptance: use a lexical absolute path (`os.path.abspath`) for the entry file; keep `resolve()`/inode checks only for alias and containment guards (`refuse_ledger_alias`). The repro exits 0 for check/list/query/add, `add` writes through the link, and output-alias refusal tests still pass. Changelog note: a layout whose includes sit beside the *target* (which upstream also rejects) stops working.

Dedupe: `.pm` `symlink` hits are output aliasing (`w1/m23/t001`, `w4/181`, `w3/329`, `w3/412`) and price-export document paths ([044](./044.md)) — none covers root include resolution. `git log -S "return candidate.resolve()"` → `00a0ce22`.

---

**Resolved 2026-10-03** — a symlinked root ledger now resolves its includes and `--into` paths beside the link, as `bean-check` does, so check, list, query, add, import and price export work on it, while lock keys, write destinations and output-alias guards still use the resolved file so writes land in the linked target. `tests/test_symlinked_root_ledger.py` covers each command. Shipped in the commit that moved this note (`cli`).

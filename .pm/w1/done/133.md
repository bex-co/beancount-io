# Managed price freshness compares `observed-at` as text and reads naive stamps in local time

**Severity: minor. Owner: cli. Estimate: 30–45m. A1:** freshness must agree with the hosted service and not depend on the user's time zone. Continuous CLI QA, 2026-10-03 (round 8); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command with timeouts, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced twice with a working control.

**Local simulation:** a stub HTTP server on `127.0.0.1` with `MANAGED_PRICE_ORIGINS=http://127.0.0.1:<port>` and `include "<origin>/prices/MIX-USD"`. Feed body (real clock, NOW in UTC):

```beancount
; alias: MIX-USD
2026-10-01 price MIX 2 USD
  observed-at: "<NOW-13h written at +14:00, e.g. 2026-10-03T10:09:15+14:00>"
2026-10-02 price MIX 3 USD
  observed-at: "<NOW-1min>Z"
```

`bea --file /abs/main.bean price status` → `stale` (every `TZ`), showing the `+14:00` stamp; `bea --strict-prices --file /abs/main.bean check` exits 1 "latest observation 2026-10-03T10:09:15+14:00 is older than 600 seconds". Control: an all-`Z` feed reads `recent`. A stamp without an offset (`"2026-10-03T09:09:03"`, or date-only) is read as machine-local time: the same feed at the same moment is `recent` under UTC and Etc/GMT+12 (a future age counts as recent) but `stale` under Pacific/Kiritimati and Asia/Kathmandu.

Expected: ADR015 compares the **latest** `observed-at` with the clock; the hosted parser (`backend-cluster/ledger/src/foundation/managed-prices/managed-price-feed.ts:300–308`) picks the latest by instant.

Cause: `cli/src/bea_engine/managed_prices.py:455–468` picks "latest" by comparing `fromisoformat(stamp).isoformat()` strings, which keep each stamp's own offset; `cli/src/bea_engine/managed_price_cache.py:174–176` calls `.timestamp()` on naive datetimes (local zone).

Fix/acceptance: compare parsed instants; normalise naive/date-only stamps to UTC (or treat as unparseable → `stale`); accept a future age only within a small skew tolerance. The mixed-offset feed reads `recent` with the `Z` stamp and the strict check passes; a naive stamp yields the same freshness under every `TZ`. Tests beside `tests/test_price.py`. Mostly affects third-party/allowlisted feeds (beancount.io emits `Z` stamps).

Dedupe: no `.pm` hit for observed-at ordering or zones; `git log -S'latest_key'` → `4ed7e101`.

---

**Resolved 2026-10-03** — managed-price `observed-at` stamps are now compared as instants, and a stamp without an offset (or a bare date) is read as UTC, so freshness no longer depends on text order or the local time zone. Tests in `tests/test_price.py` cover it. Shipped in the commit that moved this note (`cli`).

## Objective

Make the Ask-page chat input keyboard-first: focus it on page load, let `Esc` clear it, and return focus after each assistant answer so the follow-up loop never requires the mouse.

## Context

- Input component: `dashboard/src/features/ai-agent/pages/ask-ai/chat-input.tsx` (textarea, no autofocus today).
- Page: `dashboard/src/features/ai-agent/pages/ask-ai/index.tsx` — `isLoading` flips false when an answer completes; that's the re-focus trigger.
- Touch devices: autofocus must be skipped there so the mobile keyboard doesn't spring up and shove the layout.

## Steps

1. Add autofocus to the chat textarea on mount, guarded by a touch/coarse-pointer check (e.g. `matchMedia('(pointer: coarse)')`).
2. Re-focus the textarea when `isLoading` transitions back to false after a completed or failed turn.
3. Bind `Esc` in the textarea to clear the current input value.

## Files

- `dashboard/src/features/ai-agent/pages/ask-ai/chat-input.tsx`
- `dashboard/src/features/ai-agent/pages/ask-ai/index.tsx`

## Acceptance criteria

- [ ] Desktop: input is focused on page load without any click.
- [ ] Touch device (or emulated coarse pointer): no autofocus, keyboard does not pop.
- [ ] After an answer (or error) finishes, focus is back in the input.
- [ ] `Esc` clears the input.

## Out of scope

- Global keyboard shortcuts (e.g. `/` to focus from anywhere on the page).

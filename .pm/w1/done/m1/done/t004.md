## Objective

Let the user abort an in-flight chat stream. Long BQL queries can hang; today the only escape is a page reload.

## Context

- The stream is a `fetch` + `response.body.getReader()` SSE loop in `dashboard/src/features/ai-agent/pages/ask-ai/index.tsx` (`handleSubmit`, lines ~131–383). No `AbortController` today.
- The send button lives in `dashboard/src/features/ai-agent/pages/ask-ai/chat-input.tsx`; it can swap to a stop button while `isLoading`.

## Steps

1. Create an `AbortController` per submission; pass its `signal` to `fetch`; keep a ref so the stop button can call `abort()`.
2. On abort: cancel the reader, finalize the partial assistant message with a "stopped" marker (localized), reset streaming state and `isLoading`.
3. Swap send → stop icon button while `isLoading`; keep it keyboard-accessible.

## Acceptance criteria

- [ ] Clicking stop (or activating via keyboard) aborts the stream within ~1s.
- [ ] Partial content is preserved and marked as stopped; the input re-enables.
- [ ] No uncaught `AbortError` in the console.
- [ ] A stopped turn does not auto-scroll-lock the view.

## Out of scope

- Server-side cancellation of the running query (backend concern).

## Objective

Every error outcome in the Ask chat (network failure, 5xx, non-limit 429, stream error) gets a one-click retry that resubmits the last user question, instead of the current dead-end error bubble.

## Context

- Error paths live in `handleSubmit` in `dashboard/src/features/ai-agent/pages/ask-ai/index.tsx`: thrown fetch errors, `!response.ok`, 503, generic 429, and `metadata.error` SSE events.
- Keep the last submitted question in a ref/state so retry needs no re-typing.
- The AI-CFO limit (429 `AI_CFO_LIMIT_REACHED`) and 401/403 auth redirect must NOT offer retry — those need upgrade/login, not a resubmit.

## Steps

1. Track `lastQuestion` on submit.
2. Tag error messages with a retryable flag; render a retry button on retryable error bubbles.
3. Retry resubmits `lastQuestion` through the normal submit path (and replaces or follows the error bubble).

## Acceptance criteria

- [ ] Network/5xx/stream errors show a working retry button that resubmits the identical question.
- [ ] 429 limit-reached and 401/403 flows are unchanged and show no retry.
- [ ] Retry while a stream is in flight is impossible.

## Out of scope

- Exponential backoff / automatic retries.

# `bea check -v` NFC refusal advises `bea format -i`, which can never fix it, and fires on comment-only text

**Severity: minor. Owner: cli. Estimate: 15–25m. A1:** printed remedies must actually clear the error. Continuous CLI QA, 2026-10-02; report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`, synthetic fixtures. Reproduced twice from pristine fixtures.

```sh
python3 -c "import unicodedata as u; a=u.normalize('NFD','Assets:Café'); open('main.bean','w').write(f'2024-01-01 open {a} EUR\n')"
bea --file /abs/main.bean check -v      # exit 2: "...Run bea format -i to converge the encoding, then retry."
bea format -i /abs/main.bean            # exit 0, "0/1 file(s) formatted.", hash unchanged
bea --file /abs/main.bean check -v      # exit 2, same advice
python3 -c "import unicodedata as u; open('c.bean','w').write('; note about '+u.normalize('NFD','café')+'\n2024-01-01 open Assets:Cash EUR\n')"
bea --file /abs/c.bean check -v         # exit 2; native bean-check -v exits 0
```

Actual: the advice loops forever; the message says "mixes Unicode normalizations" for a uniformly NFD file; a non-NFC comment blocks native passthrough that upstream handles.

Expected: following the printed remedy then retrying succeeds. USAGE says existing bytes are never renormalized and `format -i` only strips the BOM and line endings, so it cannot be the remedy.

Cause: `cli/src/cli/commands/check.py:73` reuses the `converge` advice for the NFC case at `:90–93`; `:90` tests `unicodedata.is_normalized("NFC", text)` over the whole file including comments and strings. From `0ebedb41` (`w1/m26/t004`), whose DoD does not cover the advice.

Fix/acceptance: give the NFC case its own accurate advice (drop the native options, or re-save the file as NFC), or make `format -i` NFC-normalize and document it; optionally scope the test to account tokens. Following the advice clears the refusal; a non-NFC comment does not block `check -v`.

Dedupe: no `.pm` hit for "converge the encoding", "mixes Unicode normalizations", `_closure_needs_compat`.

---

**Resolved 2026-10-03** — `bea check` with bean-check options now refuses only when an account or tag is spelled outside Unicode NFC (comments, strings and headings no longer count), and its advice names remedies that actually clear it — drop the options to check through the helper, or re-save the file as NFC — instead of `bea format -i`. `tests/test_unicode_normalization.py` proves both remedies clear the refusal. Shipped in the commit that moved this note (`cli`).

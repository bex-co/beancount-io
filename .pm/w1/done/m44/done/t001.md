## Objective

Give the shared journal service an option that attaches each returned entry's source slice, computed in one batch per request.

## Context

- MCP `listLedgerEntries`, the journal resource, REST `journal` and GraphQL `getLedgerJournal` all call `services.ledgerJournal.getJournal` (`backend-cluster/backend-v2/src/features/ai-agent/api/mcp-list-tools.ts`, `src/features/ledger/service/ledger-journal-service.ts`).
- The ledger service resolves several slices from one parse: `findEntrySlicesWithFullLedger` (`backend-cluster/ledger/src/foundation/rustledger/source-slice-resolver.ts`, w1/237). Its multi-line handling follows w4/m34.
- `getEntryContext` returns the `sha256sum` that `updateEntrySource` and `deleteEntrySource(s)` require.

## Steps

1. Add an `includeSource` option to the journal query. When set, resolve the page's entries' slices in one batch call and attach `source { path, lineno, text, sha256sum }`.
2. Compute `sha256sum` exactly as `getEntryContext` does; share the function rather than copying it.
3. Cap the page size when source is requested, and refuse a larger page with `BAD_USER_INPUT` naming the cap.
4. If the ledger service needs a new batch endpoint, add it there with its own tests.

## Files

- `backend-cluster/backend-v2/src/features/ledger/service/ledger-journal-service.ts`
- `backend-cluster/ledger/src/` (only if a batch endpoint is needed)
- tests beside them

## Acceptance criteria

- [x] For every entry on a page, the attached `sha256sum` equals `getEntryContext`'s for that entry, including a multi-line entry with a quoted `;`.
- [x] One request reads each source file once, which a test asserts with a counting fake.
- [x] Without the option, the service result is unchanged.

## Out of scope

- Adapters (t002).

## Outcome — 2026-11-13

- **Ledger service** (`backend-cluster/ledger`): `getJournal` takes `includeSource`.
  - After filtering and paging, the page's entry hashes go through **one** `findEntrySlicesAsync` call over **one** `loadFileMap`, the same batch resolver and slicer the edits and deletes use (w1/237). That is why each `sha256sum` and `text` equal `getContext`'s.
  - Each item gets `source: {path, lineno, text, sha256sum}`, with `lineno` 1-based.
  - An entry with no editable source gets `null`: a plugin's or a pad's copy (its own hash resolves to no slice), and a managed price include's read-only line. That matches `getContext`'s `generated_from`/`managed_source` refusals.
  - Pages over `MAX_SOURCE_PAGE` (200) are refused `BAD_USER_INPUT`, naming the cap. Without the option the journal is unchanged and no file map is loaded.
  - The route reads `include_source` (`src/api/journal.ts`).
- **IDL** (`backend-cluster/idl/beancount-ledger.openapi.json`): the `include_source` query parameter, a `JournalEntrySourcePublic` schema, and an optional nullable `source` on each of the eleven journal item schemas. Additions only.
- **backend-v2:** the regenerated ledger client (`src/foundation/fava/Api.ts`). The journal service's `JournalQueryParams` gains `includeSource` and passes `include_source` only when asked. The adapters follow in t002.
- **Tests:** `ledger/src/features/ledger/service/__tests__/journal-include-source.test.ts` (5), on the scripted-parse harness the journal tests use, since WASM cannot boot under jest:
  - no `source` and no slice read without the option;
  - every page entry's source from one batch, keyed by the page's own entry hashes;
  - `null` for a copy and for a managed price line;
  - the over-cap refusal, which leaves an ordinary large page alone;
  - no lookup for an empty page.
- **Checks:** ledger `yarn typecheck`, `lint:deadcode`, `test` and `verify:rustledger`; backend-v2 `typecheck`, `lint:deadcode`, `format:check` and `test`.

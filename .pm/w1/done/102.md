# An Emacs lock file (`.#main.bean`) fails directory formatting with advice to delete it

**Severity: minor. Owner: cli. Estimate: ~20m. A1:** pre-commit format gates must not fail while a ledger is open in an editor. Continuous CLI QA, 2026-10-03 (round 5); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control.

```sh
mkdir em && printf '2024-01-01 open Assets:Cash USD\n' > em/main.bean
ln -s 'user@host.local.4242:1727900000' 'em/.#main.bean'     # what Emacs creates for unsaved edits
bea format /abs/em --check           # same for -i and --dry-run
bea --file /abs/em/main.bean check   # exit 0
```

Actual: exit 2 `Formatting target does not exist: …/.#main.bean → user@host…. Repair or remove the broken link` — deleting it defeats Emacs's edit-collision protection. The walk also descends into hidden directories (`.hidden/h.bean` was formatted).

Expected: a dangling, dot-prefixed editor lock that no include references does not fail the walk; the broken-symlink rule exists for included targets (`w3/362`), which are reported separately as missing includes.

Cause: `cli/src/cli/commands/format.py:370–378` — the `rglob` walk raises `UsageError(_unreadable(match))` for every non-file match (`:435–442`), a side effect of `419a7fa8`.

Fix/acceptance: skip dangling links named `.#*` (or more generally unreadable walk entries no scanned file includes); keep included broken links failing via `missing_includes`. The repro exits 0 for `--check`; the `w3/362` fixture still fails naming its broken include.

Dedupe: no `.pm` hit for emacs / lockfile / dotfile in the CLI.

---

**Resolved 2026-10-04** — directory formatting now skips the dangling `.#name` lock links Emacs creates beside files with unsaved edits, while any other broken entry still stops the walk. Tests in `tests/test_format_directory_unreadable_entry.py` cover it. Shipped in the commit that moved this note (`cli`).

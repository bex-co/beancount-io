# `bea cloud ledger create` checks its setup options only after the login check: signed out, `--module` without `--preset`, `--title` without `--preset` or an unknown preset all say "Not logged in" (exit 3), and signed in, `--currency eur` and `--date 2026-02-30` go to the server unchecked though `bea init` refuses or fixes them locally (gap in w3/356 and w5/623)

**Bug · cli · minor · ~30m · A1/A2.** From routine cli-qa, 2026-11-21. `bea cloud ledger create` checks its name, `--dir` without `--clone`, and the clone target before it reads credentials. The code says why (`cli/src/cli/commands/cloud/ledger/app.py:104`): "a name the service would refuse is the caller's mistake, and saying 'not logged in' hides it" (w3/356, w5/623). The setup options added later by w3/m53 and w3/m59 are checked after `authenticated_client()` instead (`app.py:116` vs `:118-129`). Signed out, each of nine usage mistakes gets exit 3 "Not logged in". An agent or a user then finishes a browser device login only to be told the command was wrong (exit 2). Signed in, the same nine are refused locally with no request, so the check exists but runs too late.

The currency and date have a second gap. `bea init --preset` runs them through `_preset_currency` (uppercases, then checks the catalog list, w5/878) and `parse_date`. `cloud ledger create` passes them to the server verbatim (`manager.py:89`). The v1 schema accepts only `^[A-Z]{3}$` for `operatingCurrency` and a calendar `historyStart` (`backend-cluster/backend-v2/src/features/ledger/api/rest/v1/lifecycle-handler.ts:77`, `build-ledger.ts:214-220`). So `--currency eur`, which `bea init --preset personal@1 --currency eur` turns into `EUR`, is a server refusal. `--currency BTC` and `--date 2026-02-30` are refused only after a network round trip. Without a token, they too say "Not logged in".

Environment: main `b90842e8e`, `bea 0.5.0` from the checkout (`uv run bea`), macOS 26.5.1. Isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, stdin closed, no TTY, fresh processes. "Token" runs set `BEA_API_URL` to a local request-logging stub on 127.0.0.1 and `BEA_TOKEN` to a dummy value. **Simulation:** the hosted response to `eur` was not observed; it is traced from the server schema.

## Repro

```sh
# Signed out (BEA_TOKEN unset, no stored login): every line exits 3
# "Not logged in. Run 'bea cloud login', or set BEA_TOKEN."
bea cloud ledger create qa-x --title Books
bea cloud ledger create qa-x --currency EUR
bea cloud ledger create qa-x --date 2026-01-01
bea cloud ledger create qa-x --preset nope@1
bea cloud ledger create qa-x --module investments@1
bea cloud ledger create qa-x --preset personal@1 --module nope@1
bea cloud ledger create qa-x --preset personal@1 --module investments@1 --module investments@1
bea cloud ledger create qa-x --preset personal@1 --property-name OakSt
bea cloud ledger create qa-x --preset personal@1 --module rental-property@1 --property-name Oak_St
bea --json cloud ledger create qa-x --module investments@1   # {"error":{"category":"auth",...,"exit_code":3}}

# Controls, signed out: exit 2 before credentials
bea cloud ledger create QA_X                     # "'QA_X' is not a valid ledger name ... Try 'qa_x'."
bea cloud ledger create qa-x --dir books         # "--dir is where --clone puts the new ledger ..."

# With a token: the nine above exit 2 locally and send no request, e.g.
#   "--module adds accounts to a --preset personal@1 ledger; add --preset personal@1. Nothing was created."
# but these POST /api-gateway/v1/ledgers with the value as typed:
bea cloud ledger create qa-x --preset personal@1 --currency eur --date 2026-01-01   # body setup.operatingCurrency "eur"
bea cloud ledger create qa-x --preset personal@1 --currency BTC                     # body setup.operatingCurrency "BTC"
bea cloud ledger create qa-x --preset personal@1 --date 2026-02-30                  # body setup.historyStart "2026-02-30"

# Local twin, for comparison
bea --no-input init books --preset personal@1 --currency eur --date 2026-01-01   # exit 0, option "operating_currency" "EUR"
bea --no-input init b2 --preset personal@1 --currency BTC --date 2026-01-01      # exit 2 "Unsupported operating currency 'BTC' for a preset ledger."
bea --no-input init b2 --preset personal@1 --currency USD --date 2026-02-30      # exit 2 "not a calendar date"
```

Each case was run twice in fresh processes. The stub logged zero requests for the nine local refusals and one POST for each of the three pass-through cases.

## Expected

Every setup-option mistake `create` can judge locally is refused with exit 2 before credentials, `--offline` or any request, signed in or out, as the name and `--dir` already are. That covers `--title`/`--currency`/`--date` without `--preset`, an unknown preset or module, a repeated module, a `--property-name` without `rental-property@1` or one that is not an account component, an unsupported currency and a non-calendar date. `--currency` is normalized as `bea init --preset` normalizes it, so `--currency eur` sends `EUR`, and `BTC` and `2026-02-30` are refused with `init`'s own messages. A valid `create` sends the same body as today.

## Fix

In `cli/src/cli/commands/cloud/ledger/app.py`, move the setup checks (`:118-129`) above `authenticated_client()` (`:116`), next to the name and `--dir` checks. Run `--currency` through `init._preset_currency` and `--date` through the same `parse_date` before building the body. Extend the stub-counting test (`tests/test_cloud_ledger_create_conflicting_options.py` style) to cover each of the nine mistakes signed out (exit 2, never "Not logged in") and signed in (zero requests). Add `eur` → `EUR` in the sent body, and `BTC` and `2026-02-30` refused with zero requests. Revert the fix and watch it fail. Owned by `cli`. REST parity is unaffected: the server already refuses these values.

## Dedupe

`.pm/**` searched for "only meaningful with --preset", "Unknown preset", "before credentials", "cloud ledger create" with "currency". w3/356 (name checked after login, fixed) and w5/623 (`--dir` without `--clone`, fixed) are the same rule for other options. w5/878 fixed the `BTC` case for `init` only. No open item covers the setup options.

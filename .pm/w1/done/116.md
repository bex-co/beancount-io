# `add balance --pad-from` treats any "Unused Pad" error as "book balance already matches", hiding real padding

**Severity: minor. Owner: cli. Estimate: 1–2h (may warrant promotion). A1:** reconcile agents always pass `--pad-from`; its explanation must be true. Continuous CLI QA, 2026-10-03 (round 6); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1 (Beancount 3.2.3), Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed unless piping JSON. Reproduced twice with a working control; compared against native `bean-check`/`bean-query`.

A — hidden adjustment:

```beancount
option "operating_currency" "USD"
2026-01-01 open Assets:Bank:Checking USD,EUR
2026-01-01 open Equity:Opening
2026-01-01 open Income:Salary
2026-01-05 * "Pay"
  Assets:Bank:Checking  1000.00 USD
  Income:Salary
2026-01-10 * "Euro"
  Assets:Bank:Checking  50 EUR
  Equity:Opening
```

```sh
bea --file /abs/a.bean add balance --date 2026-03-01 --account Assets:Bank:Checking --amount "2000 USD" --pad-from Equity:Opening
bea --json --file /abs/a.bean add balance --date 2026-03-01 --account Assets:Bank:Checking --amount "200 EUR" --pad-from Equity:Opening
```

Actual: exit 0, `written: 1`, warning `Book balance already matches 200 EUR; omitted the pad from --pad-from and wrote the assertion alone.` In fact the book holds 50 EUR and the earlier USD pad padded 150 EUR too (Beancount pads per currency; `bean-query` shows `Padding inserted … difference 150 EUR`) — a 150 EUR equity adjustment the user was told wasn't needed.

B — fabricated failure: with a staged `2026-01-31 pad Assets:Cash Equity:Opening` (no following balance), `add balance --date 2026-04-02 --account Assets:Bank:Savings --amount "200 USD" --pad-from Equity:Opening` exits 1 `Balance failed … 100 too little` (from a retry without the pad); the real cause is the pending pad, which USAGE says to finish first.

C — contradictory hint: with `2026-02-01 balance Assets:Bank:Savings 0 USD`, `--pad-date 2026-01-15 … --amount "700 USD"` prints "Book balance already matches the assertion; omit --pad-from…" beside "700 too little"; following it fails. Control `--pad-date 2026-02-15` succeeds.

Cause: `cli/src/bea_engine/ledger/adding.py:330–332` (`_unused_pad_only`) returns true for any "Unused Pad" detail, including pre-existing ones; `:244–279` then retries without the pad and words it "already matches"; `cli/src/bea_engine/ledger/write.py:625–633` `already_paired` is true for any later balance regardless of currency/date order. Follow-on from `w3/done/224` (`32c47086`, `74b59632`).

Fix/acceptance: take the "already matches" path only when the sole Unused Pad is the proposed one **and** the pre-write book balance equals the assertion within tolerance; otherwise report the real cause (earlier pad covers this currency, staged pad pending, pad date before an intermediate assertion). Tests for A (reports the 150 EUR padding or refuses), B (names the staged pad), C (no "already matches" claim). Promote if over an hour.

---

**Resolved 2026-10-03** — `add balance --pad-from` now names the real reason a pad goes unused — an existing pad and the amount it inserts, a staged pad, or an intermediate assertion — and claims "already matches" only when the book balance really matches. `tests/test_pad_from_unused_pad_causes.py` covers each cause. Shipped in the commit that moved this note (`cli`).

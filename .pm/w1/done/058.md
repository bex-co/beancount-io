# `bea cloud logout` prints "Logged out." and exits 0 when server-side revocation failed

**Severity: minor. Owner: cli. Estimate: 20–30m. A1:** a successful exit must mean the session was actually revoked. Continuous CLI QA, 2026-10-02; report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`, synthetic fixtures. Reproduced twice from pristine fixtures.

Local simulation with an isolated `BEA_CONFIG_DIR` holding a mode-600 `credentials.json` (`{"token":"abc","expireAt":"2027-01-01T00:00:00+00:00"}`):

```sh
BEA_API_URL=http://127.0.0.1:9 bea cloud logout                # unreachable
BEA_API_URL=http://127.0.0.1:<stub> bea cloud logout           # stub answers POST /api-gateway/v1/logout with 500
```

Actual: exit **0**, stdout `Logged out.`, stderr empty, credential file deleted, every time; `--json` exits 0 silently. The token remains valid on the server.

Expected: USAGE — "`cloud logout` revokes the stored session and deletes the credential file"; exit 0 means the documented effect happened, and partial effects exit nonzero saying what is missing. Deleting the local file anyway is correct.

Cause: `cli/src/cli/commands/cloud/app.py:62–69` — `except Exception: pass` swallows transport errors, 5xx and 401 alike, then prints success.

Fix/acceptance: keep `clear_credentials()`; when revocation failed, say the local credential was removed but server revocation failed (with the reason and that the session can be revoked from the dashboard) and exit 1 (4 for an unknown outcome on timeout). A 401 counts as already revoked. Unreachable/500/timeout → nonzero with the file removed; 200/401 → exit 0.

Dedupe: `w1/done/002` covers revoking an environment `BEA_TOKEN`, not this. No other logout/revocation item.

---

**Resolved 2026-10-03** — `bea cloud logout` still removes the local credential but now exits nonzero and says the session may still be valid when the server did not confirm revocation (1 for an error or unreachable server, 4 for a timeout), while 200 and 401 still exit 0. `tests/test_cloud_transport.py` covers each case. Shipped in the commit that moved this note (`cli`).

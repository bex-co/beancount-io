# Plugin-made transactions may still report source line 0

Follow-up from w1/341 (e0ac184ec, `cli`). That fix made `_source_of` in `cli/src/bea_engine/ledger/reader.py` treat a line number below 1 as "no location", so a document discovered through `option "documents"` lists with `source: null` instead of `main.bean:0`.

`TransactionHeader.source` (built in the same reader file, around line 670) reads the entry's meta `lineno` directly rather than through `_source_of`. A transaction created by a plugin carries `lineno` 0, so `bea list transaction` (and any other surface printing a transaction's source) may still show `WRITTEN IN <file>:0` / `source.lineno: 0`.

Unverified. Triage first: reproduce with a synthetic ledger whose plugin emits a transaction; close as not reproducing if the source is already empty. If it reproduces, route the header through the same below-1 rule and add a regression test that fails without the fix.

---

**Resolved 2026-11-20** — Reproduced at `99c46a97d`: a transaction a plugin stamped at line 0 (or -1) listed with `source.lineno: 0` in JSON and `--details` headed it `; main.bean:0 (generated)`; the table had no location column for transactions, so it showed only `generated`. `_to_transaction` in `cli/src/bea_engine/ledger/reader.py` now takes its source from `_source_of`, so such a row lists with `source: null` and `generated`, and `cli/src/cli/commands/list.py` heads it `; (generated)` under `--details`. A written transaction keeps its `file:line`. `cli/docs/USAGE.md` says so. Regression tests are in `cli/tests/test_list_plugin_transaction_no_line.py`, and both fail with the fix reverted. Shipped in `31fb26ef5` (`cli`).

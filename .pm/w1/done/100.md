# Appending to a ledger without a final newline drops the blank line before the new entry

**Severity: minor. Owner: cli. Estimate: ~20m. A1:** appends should look the same as on any other file. Continuous CLI QA, 2026-10-03 (round 5); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control.

```sh
printf 'option "operating_currency" "USD"\n\n2026-01-01 open Assets:Checking USD\n2026-01-01 open Equity:Opening USD\n\n2026-01-02 * "Open"\n  Assets:Checking  100.00 USD\n  Equity:Opening' > main.bean
bea --file /abs/main.bean add note --date 2026-01-05 --account Assets:Checking --comment hello
tail -3 main.bean
```

Actual (exit 0): the note is glued to the last posting — `  Equity:Opening` then `2026-01-05 note Assets:Checking "hello"` with no blank line. Control: the same file ending in `\n` gets the usual blank-line separator.

Expected: USAGE — "a missing final newline is repaired as part of the append"; `w1/done/m14` — appends look like what a person would write.

Cause: `cli/src/bea_engine/ledger/write.py:759` builds `text + "".join("\n" + block + "\n" …)`; without a final newline the leading `"\n"` only terminates the last line; `:772` repairs only the ending (`aa5bd335`). `tests/test_line_endings.py:38` only checks lines aren't joined.

Fix/acceptance: normalise `text` to end with a newline before building the draft. Resulting bytes equal the newline-terminated control's.

Dedupe: `w3/done/266` and `w1/done/m26/t002` fixed the append failing outright; nothing covers the separator.

---

**Resolved 2026-10-04** — appending to a ledger without a final newline now produces the same bytes, including the blank separator line, as appending to a newline-terminated file. Tests in `tests/test_line_endings.py` cover LF and CRLF. Shipped in the commit that moved this note (`cli`).

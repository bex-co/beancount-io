# `make test` writes `.exit` and `.quit` into the developer's real `~/.config/beanquery/history` and replays their real `~/.config/beanquery/init`: two query-shell PTY tests never got their own `HOME`

**Bug · cli (tests) · minor · ~20m · A1.** From routine cli-qa, 2026-11-22. `.history` in a `bea query` shell listed dozens of lines that came from the test suite, such as `.output /private/var/folders/…/pytest-of-<user>/…/test_interactive_output_refuse0/settings.bean`. Beanquery keeps its shell history at `~/.config/beanquery/history` and replays `~/.config/beanquery/init` on startup (`beanquery/shell.py:44-45`, both expanded from `HOME`). `eab1de85d` gave the query-shell PTY tests their own `HOME` for this reason (`tests/test_output_protects_entryless_includes.py:70-71`), and `tests/query_terminal.py` redirects both files. Two tests that start the real shell were left out. As a result, every `make test` appends to the developer's own history file. It is also not hermetic: a developer whose `init` holds `.format csv` or `.output FILE` runs those two tests against their own settings, and an `.output FILE` line sends the test's results into that file.

Environment: main `ff9d0fe7b`, `bea 0.5.0` checkout, Python 3.12.14, macOS 26.5.1.

## Repro

```sh
cd cli
wc -l < ~/.config/beanquery/history          # N
uv run pytest -q tests/test_customer_workflows.py -k interactive_query_opens_the_shell
uv run pytest -q tests/test_closed_stderr_keeps_stdout_clean.py -k dot_exit
wc -l < ~/.config/beanquery/history          # N+2; the new last lines are `.quit` and `.exit`
```

Running all 65 test files that open a PTY or use `QueryTerminal`, one file at a time, changed the history in exactly these two: `test_customer_workflows.py::test_interactive_query_opens_the_shell_on_a_real_terminal` (passes `env={**os.environ, …}`) and `test_closed_stderr_keeps_stdout_clean.py::test_the_query_shell_with_stderr_closed_exits_on_dot_exit` (line 115; its `env` copies `os.environ` and sets only the `XDG_*` paths). The autouse `bea_config_dir` fixture (`tests/conftest.py:113`) isolates `BEA_CONFIG_DIR` and the `XDG_*` directories but not `HOME`, and Beanquery does not read `XDG_CONFIG_HOME`.

## Expected

No test reads or writes the developer's real Beanquery files. After `make test`, `~/.config/beanquery/history` and `init` are byte-identical to before. CI is unaffected either way, since its home directory is fresh.

## Fix

Give both tests' child environments `HOME=str(tmp_path / "home")`, as `test_output_protects_entryless_includes.py` does, or route them through `QueryTerminal`. Then add a guard so the next PTY test cannot regress silently: either the autouse fixture sets `HOME` for every test (check that the nested `uv` and `git` calls still find what they need), or a session-scoped check fails the run when `~/.config/beanquery/history` changed. Prove it with the repro: the line count stays at N. Owned by `cli` (tests only; no product change).

## Dedupe

Searched `.pm/**` for `beanquery/history`, `HISTORY_FILENAME`, `own HOME` and `init` with `beanquery`. The hits are w5/235 (history load and save robustness, done) and the `.output`-in-`init` protection in USAGE. `git log -S'parallel tests must not share it'` shows `eab1de85d`, which isolated the other PTY tests and missed these two.

Cleanup done in this run: the lines this QA run's own shell sessions and test runs added to the local history were removed, so the file is back to its pre-run content.

**Resolved 2026-11-22** — The autouse `bea_config_dir` fixture in `cli/tests/conftest.py` now also sets `HOME` to the test's own `home-dir`, beside its `XDG_*` directories. Every test, and every child that copies `os.environ` (both tests named above, every `CliRunner` engine child, and every `{**os.environ}` subprocess), resolves Beanquery's `~/.config/beanquery/history` and `init` inside its workspace, so no test appends the developer's history or replays their `init` (non-interactive `bea query` replays it too, `bea_engine/query.py`). The two tests needed no edit of their own. Tests that pass a hand-built environment already set `HOME` themselves or start no query. `cli/tests/test_suite_home_isolation.py` starts a child with the test environment and asserts that Beanquery's history and init paths, resolved as the engine resolves them, sit under `tmp_path`. It fails with the fixture line removed, and nothing is written then because it only resolves the paths. Verified the repro under a scratch `HOME`: before the fix, the two tests wrote `.quit` and `.exit` there, and after it they wrote nothing. A full `make test` (12916 passed, 3 skipped) left the real history byte-identical (same SHA-1, size, and mtime) and created no `init`. `make check-all` passes in `cli/`. Shipped in the commit that closes this note (`cli`).

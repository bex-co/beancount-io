# Balance-sheet `net_profit` follows a different rule from the income statement's

**Severity: minor. Owner: cli. Estimate: 30–45m. A1:** automation reading net profit must get one answer. Continuous CLI QA, 2026-10-03 (round 7); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, bea 0.3.1, macOS 26.5.1 arm64. Fresh process per command with timeouts, isolated `HOME`/`XDG_*`/`BEA_CONFIG_DIR`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control.

`noprice.bean`: `option "operating_currency" "USD"`; open `Assets:Bank USD`, `Assets:Euro EUR`, `Income:Consult EUR`, `Equity:Opening USD`; `2026-01-02` Bank 100 USD from Opening; `2026-01-10` Euro 50 EUR from Income:Consult; no prices.

```sh
bea --json --file /abs/noprice.bean report balance-sheet --allow-errors
bea --json --file /abs/noprice.bean report income-statement --allow-errors
```

| Ledger | balance-sheet `net_profit` | income-statement `net_profit` |
| --- | --- | --- |
| noprice (USD conversion, partial valuation) | `{"EUR": "50"}` | `{"USD": null}` |
| opens only | `{}` | `{"USD": "0"}` |

`current_earnings` behaves the same; the text line matches the JSON ("Net Profit is 50 EUR" / "—").

Expected: USAGE — partial valuation "sets combined net profit/net worth to null in the requested currency"; a conversion names that currency in every row so zero reads `{"USD": "0"}` — as the income statement does.

Cause: `cli/src/bea_engine/report.py:290–292` emits `current_earnings` raw and `net_profit` as `_negated(earnings)`, skipping `_summary(…, conversion, incomplete=…)` used by the income statement (`report.py:203`); text repeats it at `cli/src/cli/commands/report.py:331`.

Fix/acceptance: build both via `_summary`; render text from `data["net_profit"]`. For any ledger/options, balance-sheet `net_profit` equals income-statement `net_profit` (including null and `{"USD":"0"}`); `-x units` unchanged.

---

**Resolved 2026-10-03** — balance-sheet `net_profit` and `current_earnings` now follow the income statement's summary rule, so both reports give the same `net_profit`. `tests/test_balance_sheet_net_profit_parity.py` compares them across ledgers and conversions. Shipped in the commit that moved this note (`cli`).

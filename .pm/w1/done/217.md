# Structured entries: some fields skip the token check, and `filename`/`lineno` meta is silently dropped

**Bug · ledger · minor · ~30m · A1.** From `/qa-find-bugs-mcp`, 2026-11-10, production `beancount-mcp 1.0.0`, the disposable QA ledger (dry runs, plus two refused commits).

w23/033 established that a bad unquoted token in a structured write is refused with a field-named `BAD_USER_INPUT`. Two gaps remain in `backend-cluster/ledger/src/features/ledger/utils/entry-tokens.ts` (`rowTokens`).

- **Unchecked fields:** these all preview `valid: false` with only "parse error: unexpected input":
  - posting `meta` keys (`{"Bad":"x"}`)
  - `postings[].cost.currency` (`"usd"`)
  - `postings[].totalPrice.currency` (`"usd"`)
  - a pad's `sourceAccount` (`"equity:bad"`)

  On commit they are refused `VALIDATION_FAILED` "parse error … (main.bean:91)", with a hint offering `allowInvalid: true`. Following that hint would commit text the loader cannot parse; w23/174 guards the same case for `cost.date`. REST `POST …/entries` behaves the same.
  - **Controls:** transaction-level meta keys, unit and price currencies, posting accounts and flags are refused `BAD_USER_INPUT` with the field named, e.g. `entry 0: meta.BadKey "BadKey" is not a valid metadata key`. A newline in any field is refused, so nothing can be smuggled in.
  - **Cause:** `:76-96` checks meta keys only on the transaction (`:86`). On postings it checks only the account, flag, units and price. A pad falls through at `:97-124`.
- **Reserved keys dropped:** `meta {"filename":"qa-x.pdf","lineno":"7"}`, on the transaction or on a posting, previews `valid: true` but writes no metadata line. An agent that attaches `filename: "receipt.pdf"` gets a success and no record.
  - **Cause:** `:41` accepts the two names. `journal-serialize.ts:591,633` (`META_IGNORE`) then skips them, because the same renderer hides location keys when it re-serializes parsed entries.
- **Fix:**
  - Check posting meta keys, cost and total-price currencies, and the pad source account in `rowTokens`.
  - Refuse `filename` and `lineno` in caller meta ("reserved by the parser"), and keep `META_IGNORE` for re-serialization.
  - Both fixes cover REST, GraphQL and MCP, in previews and commits.
- **Check:** add an `entry-tokens` test for each field and one parity row.

**Addendum 2026-11-10 (budgets):** a `budget` entry with `account: "Expenses"` (a bare root) is refused with `entry 0: values[0].value "Expenses" is not a valid account`. That names the internal custom-directive path, not the field the caller sent (`entry.account`). Name the caller's field in the same pass.

**Resolved 2026-11-10.** `rowTokens` now checks every unquoted token the four fields carry, and refuses the parser's reserved meta keys.

- **Checked fields:** posting `meta` keys, `postings[].cost.currency`, `postings[].totalPrice.currency` and a pad's `sourceAccount` are refused `BAD_USER_INPUT` before any file is read, naming the field. Example: `entry 0: postings[0].meta.Bad "Bad" is not a valid metadata key`. No preview reports them as a parse error any more, and no commit hint offers `allowInvalid` for them.
- **Reserved keys:** `filename` and `lineno`, in transaction or posting meta, are refused as "not a valid metadata key: it is reserved by the parser, which sets it to where the entry is written; use another key". Keys that only start with those names (`filenames`, `lineno-2`) still pass. `META_IGNORE` stays as it was, for re-serializing parsed entries.
- **Budgets:** a budget arrives at the ledger as `custom "budget"`. Its root account is now refused as `entry 0: account "Expenses" …`, and a bad amount currency as `amount.currency`. A plain custom directive still names `values[i]`.
- **Surfaces:** REST, GraphQL and MCP all write through the ledger's bulk endpoint, which runs this check for both previews and commits. backend-v2 needed no change.
- **Tests:** `entry-tokens.test.ts` covers each field, the reserved keys, and the budget's naming. `entries-amount-syntax.test.ts` adds endpoint rows for the posting fields, the reserved keys and a pad. Reverting the fix fails 15 of them. (`ledger`)

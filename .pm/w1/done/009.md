# `cloud ledger clone` checks auth before validating `owner/name`

**Severity:** major  
**Package:** `cli`  
**Env:** `bea 0.1.0`, signed out (no network body needed)

## Repro

```bash
bea --json cloud ledger clone open_ledger
# exit 3: Not logged in. Run 'bea cloud login', or set BEA_TOKEN.

bea --json cloud ledger show open_ledger
# exit 2: 'open_ledger' is not a ledger full name; expected 'owner/name'.
```

## Expected

Same invalid `full_name` shape fails as usage (exit 2) on every cloud ledger command that takes `owner/name`, whether or not a session exists — matching `show` / `delete --yes`.

## Actual

Curated `ledger_clone` evaluates `authenticated_client()` before `manager.get_ledger` → `owner_and_name`, so signed-out callers only see auth failure.

## Root cause

`cli/src/cli/commands/cloud/ledger/app.py` (`ledger_clone`):

`manager.get_ledger(authenticated_client(), full_name)` forces credential load during argument evaluation.

## Fix

Call `owner_and_name(full_name)` (or `get_ledger` only after validating) before `authenticated_client()`. Add a contract test pairing `clone` with `show` on `open_ledger`. Related to w1/007 (delete confirms before validate).

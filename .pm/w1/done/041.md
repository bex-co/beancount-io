# Root-ledger formatting silently skips included files with other extensions

**Severity: minor. Owner: cli. Estimate: 25–40m. A1:** CI and agents must not receive a green formatting/parse gate for parts of the ledger that were never inspected. Found by continuous CLI QA on 2026-10-02; no product fix applied.

Environment: `main` HEAD `1a1480c8ad2dee049c4bccf4a646c2513082b04c`, checkout `cli/.venv/bin/bea` (editable metadata 0.3.0; current source/engine 0.3.1), Python 3.13.0, macOS 26.5.1 arm64. Synthetic fixtures, closed stdin, captured stdout/stderr, isolated config/cache and no inherited ledger/token.

Create a disposable `main.bean`:

```beancount
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Food USD
include "entries.inc"
```

Beside it, save `entries.inc`:

```beancount
2024-01-02 * "Lunch"
  Assets:Cash -12.50 USD
  Expenses:Food 12.50 USD
```

```sh
bea --json --file /absolute/main.bean check
bea --json format /absolute/main.bean --check
bea --json format /absolute/main.bean --dry-run
bea --json format /absolute/main.bean -i
```

Actual, repeated twice from pristine fixtures: ledger check passes, but every formatter invocation reports `scanned: 1`, `formatted: []`, `failed: []`, exit **0**. The unaligned child is untouched. Replace the child's contents with `this is not a directive`: `bea check` now exits **1** naming child syntax errors, while formatter check/preview/apply still exit **0** and never report that child.

Working control: use exactly the same fixture with `entries.bean` and update the include. The formatter scans **2** files; `--check` exits 1 for unaligned or invalid content, valid `-i` aligns the child, and invalid `-i` names and skips it with nonzero status. Also reproduced with a glob `include "parts/*"` selecting `january.data`, and a nested `.bean` include selecting a `.inc` grandchild. Both silently omit the nonstandard suffix. All read/check/preview commands preserve bytes.

Expected: `cli/docs/USAGE.md` states that a named file stands for its whole include closure, `--check` gates on parseability, and `-i` formats every reachable file. The `.bean`/`.beancount` discovery rule applies to finding roots in a directory; it must not filter known ledger members reached through a valid include.

Cause: `cli/src/cli/commands/format.py:373–376` obtains the complete `output.ledger_closure` but only adds members whose suffix is in `SUFFIXES`. `_syntax_failures` at line 388, check/preview and the writer all receive this reduced set. `cli/src/cli/output.py:195–236` already discovers the `.inc` member correctly. The suffix filter was introduced with closure support in `50fd1b28`.

Fix/acceptance: when a `.bean`/`.beancount` root is explicitly selected (including global `--file`), include all regular files reached by its include graph in validation and formatting, independent of their suffix. Preserve directory discovery and its existing boundary against rewriting files outside the requested directory. Add subprocess coverage for direct/glob/nested includes and the `.bean` controls; after `-i`, the valid `.inc` is aligned and a subsequent root `--check` passes, while invalid `.inc` causes a path-specific nonzero check/apply. No API or dependency changes; run `make check-all` inside `cli/` when implementing.

Dedupe: searched all board states and open milestones for format suffixes, `.inc`, include closure and skipped children. Read completed `w3/done/332`, `w1/done/m23/t003`, and that milestone's full DoD. The earlier `.bean` reproducer is fixed; this is an uncovered suffix-dependent gap in the same published closure guarantee. `git log -S 'member.suffix in SUFFIXES'` identifies `50fd1b28`; no newer fix or open overlap found. Directory-boundary behavior is deliberate and is not being filed as a defect.

Evidence: `cli/tmp/qa-20261002-cli-2mbxnp30/captures/repeat-format-suffix-{1,2}-{inc,bean}-{valid,invalid}-*.json` and `cycle10-{extension,glob,nested}-*.json`, with exact argv/cwd, streams, statuses, timings and file hashes/contents. All subprocesses exited. No credentials or hosted resources; installed releases and other platforms unverified.

---

**Resolved 2026-10-03** — `bea format` (check, dry-run and `-i`) now covers every file a root ledger's `include` directives reach, whatever its suffix, so an unaligned or unparseable `.inc` child fails the gate instead of being skipped; directory discovery still picks up only `.bean`/`.beancount`. `tests/test_format_closure_any_suffix.py` covers direct, glob and nested includes. Shipped in the commit that moved this note (`cli`).

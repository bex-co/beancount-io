# `ask` renders model Markdown links as disguised terminal hyperlinks

**Severity: minor. Owner: cli. Estimate: 15–20m. A1:** model output must not hide where a link goes. Continuous CLI QA, 2026-10-03 (round 4); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled. **Local simulation:** a fake OpenAI-compatible model server on `127.0.0.1`, reached via `BEA_API_URL` and a fake `BEA_TOKEN`; no hosted AI service was used. Reproduced twice with a working control.

Fixture `main.bean`: `option "operating_currency" "USD"`; open `Assets:Checking`, `Expenses:Food`, `Equity:Opening` (USD); one opening transaction.

In a PTY, the model answers `Log in at [https://beancount.io/login](https://evil.example/phish) now.`:

```sh
bea --file /abs/main.bean ask --print link
```

Actual: stdout contains an OSC 8 hyperlink — `\x1b]8;id=…;https://evil.example/phish\x1b\\…https://beancount.io/login…\x1b]8;;\x1b\\` — a clickable link that reads beancount.io and opens evil.example.

Expected: model text cannot produce terminal escape sequences (the `inert_text` invariant and the `commands/ask.py` comment "no control character reaches the screen raw", `w3/392`), so the real target is visible.

Cause: `cli/src/cli/commands/ask.py:88` and `cli/src/cli/ask/repl.py:284` call `Markdown(inert_text(...))`; `inert_text` escapes input control characters, but Rich's Markdown then emits the hyperlink escape itself (`hyperlinks=True` by default).

Fix/acceptance: `Markdown(..., hyperlinks=False)` (verified to render `https://beancount.io/login (https://evil.example/phish)`). A forced-terminal capture of a Markdown link contains no `\x1b]8;` and shows the URL.

Dedupe: no `.pm` hit for OSC 8 / hyperlink / markdown link.

---

**Resolved 2026-10-04** — `bea ask` now prints a Markdown link's real target instead of a clickable terminal hyperlink whose visible text the model chose. Tests in `tests/test_ask_consent_surface.py` cover `--print` and the session. Shipped in the commit that moved this note (`cli`).

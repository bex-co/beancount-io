# A `#` or `?` in a bare `query --source` path bypasses the ledger-alias guard and overwrites the ledger

**Severity: major. Owner: cli. Estimate: ~30m. A1:** no export may overwrite the ledger it reads. Continuous CLI QA, 2026-10-03 (round 12); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command with timeouts, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with before/after hashes and a working control. Found by a regression hunt over shipped fixes.

In a books directory whose `main.bean` has at least one posting (and includes `parts/a.bean`):

```sh
bea query --source 'main.bean#x' --output main.bean 'SELECT account'     # also 'main.bean?x'
bea query --source 'main.bean#x' --output parts/a.bean 'SELECT account'
```

Actual: exit 0 and the destination is replaced by the ASCII `account` table (re-verified by the filer: hash changed, file now begins `  account`). Controls: plain `--source main.bean` and `beancount:main.bean#x` are refused with exit 2.

Expected: exit 2 "would overwrite the ledger it reads", every byte unchanged — the `w4/done/181` guard.

Cause: `cli/src/cli/commands/query.py:62–65` checks a scheme-less string as the literal `Path("main.bean#x")` (which doesn't exist); upstream `beanquery/shell.py` `main()` turns it into `beancount:main.bean#x` and `sources/beancount.py:45` takes `urlparse(dsn).path`, dropping `?query`/`#fragment` — so upstream loads and writes `main.bean`. Gap in `e168b0aa`.

Fix/acceptance: resolve the file the way upstream does (scheme detection with upstream's `[a-z]{2,}:` regex, else prepend `beancount:` before `urlparse(...).path`); as a backstop refuse bare strings containing `?` or `#`. All three commands exit 2 with files unchanged; a distinct destination still exports.

---

**Resolved 2026-10-04** — already satisfied by `dad407b9` (w1/043), building on `a048d307` (w1/038): native `--source` one-shots now read the source path the way upstream does inside the engine, so a `#` or `?` in a bare path can no longer route an `--output` onto the ledger or an included file (exit 2, files unchanged). Verified at HEAD with the note's repros; regression tests shipped with w1/155 in `tests/test_query_dash_leading_query.py`. No code change for this note.

## Objective

Blank and whitespace-only trailer rows — present in many exports — are treated as hard date-parse failures, and when two columns claim the same role the mapping is silently dropped and the user is told to go configure a Python importer.

## Context

- `w3/263`: blank / whitespace-only rows are hard date-parse failures.
- `w3/281` and `w5/003`: `Description` and `Memo` both claim `narration`, the role is correctly dropped, but neither the `--config` error nor the `--csv auto` error says two columns tied; `Original Description` is never treated as narration.
- Header-role resolution is in `cli/src/bea_engine/csv_mapper.py`.

## Steps

1. Skip rows that are entirely empty or whitespace, and count them in the preview summary rather than failing.
2. When a role has more than one claimant, say so: name the role, name the tied columns, and show the `--csv` line that resolves it.
3. Add `Original Description` to the narration synonyms and re-check the synonym table against the fixture exports.
4. Keep the existing behavior of dropping an ambiguous role — the fix is the message, not a silent pick.

## Files

- cli/src/bea_engine/csv_mapper.py

## Acceptance criteria

- [ ] An export with a blank trailer row imports; the preview reports the skipped row count.
- [ ] A header with `Description` and `Memo` produces an error naming both columns and the role they tied for, in both the `--config` and `--csv auto` paths.
- [ ] `Original Description` alone resolves as narration.
- [ ] An unambiguous header is unaffected.

## Out of scope

- Interactive column-mapping prompts.
- Changing which roles exist.

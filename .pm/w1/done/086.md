# `bea example` date-order guard only fires when both dates are given; one-sided or short ranges crash upstream

**Severity: minor. Owner: cli. Estimate: ~20m. A1:** generating a sample ledger is a first-run onboarding step. Continuous CLI QA, 2026-10-03 (round 3); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1 (Beancount 3.2.3, beanquery 0.2.0), Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control.

```sh
bea example --date-end 2023-06-01                              # exit 1: bean-example failed (exit 1): IndexError: list index out of range
bea example --date-begin 2026-12-01                            # same
bea example --date-begin 2024-01-01 --date-end 2024-01-01      # same
bea example --date-begin 2020-01-01 --date-end 2020-01-16      # StopIteration
```

Control: both dates given and inverted → exit 2 "begin must be on or before end"; spans ≥ 30 days work.

Expected: `w3/done/298`'s acceptance — an inverted range is a usage error before generation. Upstream defaults (begin = Jan 1 two years ago, end = today; `beancount/scripts/example.py:1860–1864`) let a one-sided date invert the range.

Cause: `cli/src/cli/commands/example.py` `_check_date_order` returns early on `KeyError` when one side is missing and enforces no minimum span.

Fix/acceptance: fill the missing side with upstream's defaults before comparing; refuse spans shorter than ~30 days with a usage error. All four commands exit 2 with a clear message.

Dedupe: follow-up gap in `w3/done/298` (`4ce341a6`).

---

**Resolved 2026-10-03** — `bea example` now applies upstream's defaults before its date-order check and refuses inverted (including one-sided) and sub-31-day ranges with exit 2 instead of crashing upstream. A parametrized test in `tests/test_engine_launch.py` covers it. Shipped in the commit that moved this note (`cli`).

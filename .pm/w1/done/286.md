# `bea add commodity` for a declared commodity says only "Duplicate commodity directives for 'USD'": no location, and no word that metadata goes on the existing line

Found by `/qa-find-bugs-cli w1` on 2026-11-18 (HEAD `f4071ce8f`, `bea 0.4.1`, macOS 26.5, Python 3.12.14, checkout `uv run bea`, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`). Severity: minor. A1: the usual reason to run `add commodity` on a symbol the ledger already declares is to give it a name (`--meta 'name:…'`, the example in `bea add commodity --help`). The refusal leaves an agent guessing which line to edit, and whether some bea command can do it.

**Repro** (synthetic):

```sh
printf 'option "operating_currency" "USD"\ninclude "accounts.bean"\n2026-01-01 commodity USD\n' > main.bean
printf '2026-01-01 open Assets:Cash USD\n' > accounts.bean
bea --file main.bean add open --date 2026-01-01 --account Assets:Cash                   # control
bea --file main.bean add commodity --date 2026-02-01 -c USD --meta 'name:US Dollar'
bea --file main.bean --json add commodity --date 2026-02-01 -c USD --meta 'name:US Dollar'
```

**Actual.** Exit 1, file unchanged, and the only detail is `Proposed append (not written): Duplicate commodity directives for 'USD'` (the same single string in `error.details` under `--json`).

**Control.** A second `open` gets `Assets:Cash is already opened at …/accounts.bean:1; an account opens once.`, and with new currencies, the exact line to edit and `(bea add open cannot change an existing open)` (w5/488). A second `close` gets the same treatment (w5/773).

**Expected.** One more detail line naming the existing directive and the remedy, for example: `USD is already declared at /abs/main.bean:3; a commodity is declared once. To add name: "US Dollar", edit that line's metadata (bea add commodity cannot change an existing commodity).` Without `--meta`, the first sentence alone.

**Root cause.** `cli/src/bea_engine/ledger/write.py:2947-2998` attaches hints for `Duplicate open directive for ` and `Duplicate close directive for `; Beancount's `Duplicate commodity directives for '…'` validation error falls through with none.

**Fix** (cli only). Add a `_duplicate_commodity_hint` beside `_duplicate_open_hint` (`write.py:3776`): find the commodity directive within the original bytes (as the open branch does, since Beancount may blame either one) and name its location, plus the metadata being added. Regressions: a duplicate with and without `--meta`, text and `--json`, and the existing commodity dated after the proposed one. Local-only. The hosted write gate reports `DUPLICATE_COMMODITY` itself (w23/240) and is out of scope.

**Blast radius.** Every engine write whose validation reports a duplicate commodity: `add commodity` mainly; `add transactions`/`import` never write commodity directives. Presets and the fixed chart write none, so only a user- or agent-written declaration triggers it.

**Dedupe.** Searched `.pm/**` for `Duplicate commodity`, `add commodity`, `already declared`. w23/240 (done) is the hosted engine accepting duplicate commodities; w5/488 and w5/773 (done) are the open/close hints. No item covers the CLI hint. Estimate: 20–30 minutes.

**Resolved 2026-11-18** — A `Duplicate commodity directives for '…'` refusal now carries one more detail line (`cli/src/bea_engine/ledger/write.py`, `_duplicate_commodity_hint`), in text and `--json` `error.details` alike: `USD is already declared at /abs/main.bean:3; a commodity is declared once. To add name: "US Dollar", edit that directive's metadata (bea add commodity cannot change an existing commodity).` Without `--meta`, or when the existing declaration already holds the same values, only the first sentence; a key it holds with another value reads `To set`. The existing declaration is found within the original bytes whichever one Beancount blames, so an earlier-dated proposal and a declaration in an included file are located too. `cli/docs/USAGE.md` documents the refusal. Regressions in `cli/tests/test_duplicate_commodity_hint.py` cover with and without `--meta`, text and JSON, the proposal dated before and after the existing one, a changed and an unchanged value, and an included file; all eleven fail with the fix reverted.

# USAGE.md's JSON automation examples show output the CLI doesn't produce

**Severity: minor. Owner: cli. Estimate: 20–30m. A1:** agents copy documented JSON paths and sign conventions verbatim. Continuous CLI QA, 2026-10-03 (round 7); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, bea 0.3.1, macOS 26.5.1 arm64. Fresh process per command with timeouts, isolated `HOME`/`XDG_*`/`BEA_CONFIG_DIR`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control.

From the README quick-start ledger (`bea --no-input init books --currency USD --date 2026-08-01 --opening-balance "Assets:Checking 1000"`, `cd books`, `bea add transaction Coffee --date 2026-08-02 --posting "Expenses:Dining 12.50" --posting Assets:Checking`), run the fence at `cli/docs/USAGE.md:1329–1346`:

| Command | USAGE shows | Actual |
| --- | --- | --- |
| `bea --json query "SELECT account, sum(position) GROUP BY account" \| jq .data.columns` | `{"name": "total", …}` | `{"name":"sum(position)",…}` |

| `bea --json list transaction --limit 2 \| jq .data[0].postings[0].units` | `"number": "1000.00"` | `"12.50"` (newest first; opening prints `"1000"`) |

Also `USAGE.md:1363` says "help, version, and completion output stay textual", but `USAGE.md:93` and `cli/src/cli/main.py:216` emit a `--json --version` envelope with `"target": null`, which the target-shape table doesn't list.

Cause (docs): text from `00a0ce22`, never regenerated; nothing in CI compares it (see [128](./128.md)). The contract test (`tests/test_contract.py:402`) uses `… as total`, which the doc dropped.

Fix/acceptance: derive the samples from the stated quick-start ledger (or add `AS total`), correct the sign, drop "version" from the textual list and document `target: null`; a test runs the fence and compares key fragments.

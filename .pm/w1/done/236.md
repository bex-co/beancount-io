# `renameLedgerFile` reports every pre-existing error in the moved file as new on commit; its preview says none

**Bug · backend-v2 (MCP) · minor · ~20m · A1.** From `/qa-find-bugs-mcp`, 2026-11-10, production `beancount-mcp 1.0.0`, the disposable QA ledger carrying 6 known errors (4 in the moved file). An agent tidying a broken ledger is told its rename broke it, and the preview contradicts the commit.

- **Repro:** tried twice, renaming `broken→broken2` and then `broken2→broken3`.
  1. `renameLedgerFile {oldPath:"qa-x/broken.bean", newPath:"qa-x/broken2.bean", updateIncludes:true, dry_run:true}` returns "No new bean-check errors", `{errorsBefore:6, errorsAfter:6, newErrors:[], valid:true}`.
  2. The same call without `dry_run` commits, then reports "4 new bean-check errors …" with `newErrors` listing E1002, E3001, E1001 and E2001 at `broken2.bean`, and `valid:false`.
  - `checkLedger` before and after lists the same 6 errors, only with the new path.
- **Expected:** a rename that adds no error reports none, and the preview and the commit agree.
- **Cause:**
  - `src/features/ledger/utils/bean-check-errors.ts:118-133` (`diffBeanCheckErrors`) keys each error on message plus file, with the line stripped (w23/034). After a rename, every error in the moved file therefore looks new.
  - `mcp-tools.ts:680` wraps the rename in `withPostWriteValidation` (`write-validation.ts:73`). A dry run changes nothing, so its before/after check always reads clean. That means the rename preview never checks the projected rename at all.
- **Fix:**
  - Map `oldPath` to `newPath`, and any file whose relative includes were rewritten, in the "before" set before diffing. Ideally `diffBeanCheckErrors` takes an optional path map that the rename caller supplies.
  - Make the dry run project the rename, or say plainly that it isn't checked.
- **Check:** renaming a file that carries errors gives `newErrors: []` in both the preview and the commit. This affects MCP only; REST and GraphQL rename return no validation block.
- **Related friction (not this fix):** no report and no `getLedgerContext` result carries an error indicator. On a broken ledger, "what's my net worth" looks clean unless the agent calls `checkLedger`.

**Resolved 2026-11-10 — already satisfied by `a9367030a` (`w23/m39`, which absorbed this note), no work in w1.** Checked on `main`:
- `diffBeanCheckErrors` takes a `renames` map that carries the old file's errors to the new path, so a rename that adds no error reports none.
- The MCP rename preview projects bean-check over the files the move would leave, and reads `checked: false` when that check cannot run.
- These pass here: `bean-check-errors.test.ts`, `preview-commit-differential.test.ts` (a dry run and a commit of the rename on identical ledgers give one verdict; before the fix it failed on exactly this case), and `write-preview-matrix.test.ts`.
- The "related friction" (no error indicator on reports) is out of this note's scope and was not taken up.

# Managed price feed validation accepts Unicode whitespace Beancount cannot parse, and replaces the last good revision

**Severity: minor. Owner: cli. Estimate: ~15m. A1:** a bad feed must never break a working ledger. Continuous CLI QA, 2026-10-03 (round 3); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1 (Beancount 3.2.3, beanquery 0.2.0), Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control.

Managed-price cases are **local simulations**: a threaded `http.server` stub on `127.0.0.1:8765`, enabled with `MANAGED_PRICE_ORIGINS=http://127.0.0.1:8765` and the ledger line `include "http://127.0.0.1:8765/prices/BTC-USD"`. Base fixture: open `Assets:Bank USD`, `Assets:Crypto BTC`, `Equity:Opening`; fund 10000 USD; buy `1 BTC {5000 USD}`; then the include.

From a good cached revision `g`, serve a body whose price line has a non-breaking space (U+00A0) before `price`, ETag `"n"`. `bea price refresh` exits **0** printing `g → n`, while stderr shows `…n.effective….beancount:4: Invalid token: ' price'`. Blob `g` is deleted; `check` exits 1 and `balance -x USD` fails.

Expected: ADR018 §1's price-only grammar is enforced; an unparseable body never replaces the last good one.

Cause: `cli/src/bea_engine/managed_prices.py:55–58` `_PRICE_RE` uses Unicode `\s` (NBSP, U+2000–U+3000, `\x1f`) for separators; Beancount accepts only space and tab. The hosted mirror `backend-cluster/ledger/src/foundation/managed-prices/managed-price-feed.ts:146` uses the same `\s` (behaviour there unverified).

Fix/acceptance: use `[ \t]+` (or parse the candidate with Beancount and reject errors). The scenario keeps `g` serving and records `invalid feed at line 4`. Check the hosted validator in the same change if it shares the grammar.

---

**Resolved 2026-10-03** — managed price feeds whose separators or metadata use whitespace Beancount cannot parse are now rejected by both the CLI validator and the hosted ledger service's validator (spaces and tabs only, lines counted on newlines), so the last good revision keeps serving. Tests in `cli/tests/test_price.py` and `backend-cluster/ledger` `managed-price-feed.test.ts` cover it. Shipped in the commit that moved this note (`cli`, `backend-cluster/ledger`).

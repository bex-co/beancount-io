# Import blocks rows for account names with an unknown root and suggests a `bea add open` that cannot work

**Severity: major. Owner: cli. Estimate: 45–60m. A1:** the suggested remedy must succeed, or the input must be refused up front. Continuous CLI QA, 2026-10-03 (round 12); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command with timeouts, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with before/after hashes and a working control. Found by a regression hunt over shipped fixes.

Ledger with the standard roots and `2024-01-01 open Assets:Cash USD`; `c.csv` = `Date,Amount,Description` / `2026-01-02,-5.00,Coffee`.

```sh
bea --file /abs/main.bean import /abs/c.csv --csv auto --account Foo:Bar
bea --file /abs/main.bean import /abs/c.csv --csv auto --account Assets:Cash --default-account Foo:Bar
# also: --rules with account = "Food:Coffee"; a category column cell "Dining:Out"
```

Actual: exit 0, `1 blocked`, `Row 1: Account 'Foo:Bar' is not open. Run: bea add open --account Foo:Bar --date 2026-01-02 -c USD.` — that remedy exits 1 `Invalid account name: Foo:Bar` (the original `w3/386` symptom). `bea add transaction -p 'Food:Coffee 5 USD' -p Assets:Cash` likewise exits 1 suggesting an `add open` that can't succeed. Control: `--account assets:cash` is refused with exit 2.

Cause: `cli/src/bea_engine/ledger/text.py:130` (`parse_account`) uses `beancount.core.account.is_valid`, which doesn't check the root against the ledger's `name_*` options; callers `importing.py` `_valid_account`, `csv_mapper.py:283–287` (rules), `csv_mapper.py:~985` (category). Gap in `a10edeef` (`w3/done/386`).

Fix/acceptance: check the root against the loaded ledger's `name_assets`…`name_expenses`; an unknown-root category value falls back to the review queue; `blocked_reason` never suggests an `add open` that would be refused. The option/rule cases exit 2, the category case falls back to unmatched, and `Assets:New` still blocks with a working remedy.

---

**Resolved 2026-10-04** — import now refuses accounts under a root the ledger does not use (honouring `name_*` options) and never suggests an `add open` that cannot succeed; an unknown-root category cell queues the row for review. `tests/test_import_unknown_account_root.py` covers it. Shipped in the commit that moved this note (`cli`).

# `bea init --opening-balance 'Liabilities:CreditCard 250'` opens the card 250 in credit with no warning, so net worth starts 500 too high

Found by `/qa-find-bugs-cli w1` on 2026-11-18 (HEAD `f4071ce8f`, `bea 0.4.1`, macOS 26.5, Python 3.12.14, checkout `uv run bea`, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`). Severity: minor. A2: a newcomer typing the balance their card statement shows is the most common way to get this sign wrong, and `init` is where it happens first.

**Repro** (synthetic):

```sh
bea init books --currency USD --date 2026-01-01 --opening-balance 'Liabilities:CreditCard 250'
bea --json init books2 --currency USD --date 2026-01-01 --opening-balance 'Liabilities:CreditCard 250'
bea init books3 --currency USD --date 2026-01-01 --preset personal@1 --opening-balance 'Liabilities:CreditCard 250'
bea --file books/main.bean report balance-sheet
```

**Actual.** All three exit 0 with no warning (`--json` has no `warnings`). The file posts `Liabilities:CreditCard 250 USD` against `Equity:OpeningBalances -250 USD` (the preset also asserts `balance Liabilities:CreditCard 250 USD`), and the balance sheet reads `Net Worth: 250 USD` for a card that is presumably 250 owed (−250).

**Controls.** `bea add balance --date 2026-01-05 --account Liabilities:CreditCard --amount '250 USD' --pad-from Equity:OpeningBalances` writes the same positive balance but warns: `Liabilities balances are negative in Beancount, so an amount owed of 250 USD is asserted as -250 USD; … which counts toward net worth.` (w5/827). The hosted Create Ledger (`ledgerOpeningAmount`, REST/GraphQL/MCP) reads an unsigned positive on a liability as owed and takes an explicit `+` as in credit (w21/549), so the same `250` means opposite things on the two setup paths.

**Expected.** Keep the Beancount sign `init` documents ("Credit card debt uses a negative opening balance"), and warn as the pad does. When an `--opening-balance` names a Liabilities account with an unsigned positive number, print (stderr, and in `--json` `warnings`) a note saying the card opens at +250 USD, in credit, which counts toward net worth, and that an amount owed is entered as `-250`. An explicit `+250` is a deliberate in-credit balance and stays silent, matching the hosted rule. Nothing about the written file changes.

**Root cause.** `cli/src/cli/commands/init.py:572-579` parses each `--opening-balance` (`_opening_balance_parts`, `_opening_amount`) and adds only the operating-currency warning (`:586-592`). No sign check runs for liability accounts, and `_opening_amount` drops the `+` that would tell a deliberate credit from a statement figure.

**Fix** (cli only). Check the sign in `init` (frontend) for accounts under `Liabilities:`, fixed chart and presets both. Reuse the pad warning's wording from `cli/src/bea_engine/ledger/adding.py:788-791` where practical. Update the `--opening-balance` line in `cli/docs/USAGE.md` (around line 567) and run `make docs`. Regressions: unsigned positive warns (text and JSON, fixed chart and `personal@1`), `-250` and `+250` do not, and the file bytes are unchanged by the warning. No hosted change: Create Ledger already handles the sign.

**Blast radius.** `bea init` with `--opening-balance` (fixed chart: `Liabilities:CreditCard`; presets: `Liabilities:CreditCard`, `Liabilities:Loan`, and module accounts under `Liabilities:`). The interactive prompt asks only for checking, so it is not affected. Skills that build `init` commands (`skills/beancount-init`) benefit without change.

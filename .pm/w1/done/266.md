# `report holdings` says a position with no cost basis is "valued at cost" when it is left in its own units

Found by `/qa-find-bugs-cli w1` on 2026-11-15 (HEAD `e008f36fb`, `bea 0.3.1`, macOS 26.5.1, checkout `uv run bea`, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, synthetic ledger). Severity: minor (a diagnostic, not a figure). A1/A2: an agent or a newcomer told "valued at cost" and "pass --allow-errors for cost-basis values" expects a cost-basis figure that does not exist. The same ledger's `bea balance` says "shown in units".

**Repro** (synthetic):

```sh
cat > main.bean <<'EOF'
option "operating_currency" "USD"
2026-01-01 open Assets:Cash USD
2026-01-01 open Assets:Vacation VACHR
2026-01-01 open Assets:Broker AAPL
2026-01-01 open Income:Vacation VACHR
2026-01-02 * "Accrue"
  Assets:Vacation  10 VACHR
  Income:Vacation
2026-01-03 * "Buy"
  Assets:Broker  2 AAPL {100 USD}
  Assets:Cash  -200 USD
EOF
bea --file main.bean report holdings                  # exit 1
bea --file main.bean report holdings --allow-errors   # exit 0
```

**Actual.** The strict run exits 1 with `Missing prices for AAPL, VACHR. … or pass --allow-errors for cost-basis values.` It gives the details `AAPL has no USD price at any date; valued at cost` and `VACHR has no USD price at any date; valued at cost`. With `--allow-errors` the same two lines print, and `--json` carries them in `missing_price_summary`. The table is right: AAPL `200 USD` at cost, VACHR `—` cost basis and market value `10 VACHR`. The VACHR line is false, because VACHR has no cost and is shown in units. The generated `bea example` ledger shows it too, for `IRAUSD` and `VACHR`.

**Expected.** A costed lot with no quote still reads `valued at cost`. A position with no cost basis that no quote values reads `shown in units` (for example `VACHR has no USD price at any date; shown in units`), the wording `bea balance` and `report overview` already use for the same case. The strict error's closing words should not promise cost-basis values when some of the named commodities have none. For example: `or pass --allow-errors to value the costed lots at cost and show the rest in units`.

**Root cause.**
- cli: in `cli/src/bea_engine/report.py`, `_holdings` (about line 679) appends `(commodity, candidates[0])` to `missing` for an uncosted position with no quote and keeps it in units (`_uncosted_unvalued`). `_holdings_valuation` (about line 855) then words every missing leg as `valued at cost`, and its own docstring admits the leg may instead "stay in its own currency". Its strict `LedgerError` always says `cost-basis values`.
- backend-v2 (parity, the same holdings contract behind REST, GraphQL and MCP): `backend-cluster/backend-v2/src/features/ledger/utils/holdings.ts` calls `miss(commodity, candidates[0])` for the same uncosted case (about line 475), and `missing_price_summary` (about line 577) words every leg `… quote at <asOf>; valued at cost`.

**Fix.** Record whether each missing leg belongs to a costed lot or to an uncosted position, and word the summary to match on both surfaces. Adjust the cli strict error's hint the same way. Tests: cli, a holdings case with one costed unquoted lot and one uncosted unquoted position, asserting both summary lines and the strict message. backend-v2, the matching case in `utils/__tests__/holdings.test.ts`. Both fail with the fix reverted. Estimate: 30–45 minutes.

**Blast radius.** Only holdings: `bea report holdings` and the backend holdings reads, plus any client that shows their `missing_price_summary` (dashboard and mobile were not checked). `balance`, `overview` and the other statements already say `shown in units` (`report.py` about lines 2067 and 2084). The `earlier holdings valued at cost` variant (a quote exists, but only after the end date) has the same uncosted gap.

**Dedupe.** Searched `.pm/**` (open, `done/`, `blocked/`) for `valued at cost`, `missing_price_summary` and `cost-basis values`. w1/256 (an uncosted flow balance is not a holding) and w23/m41/t004 (holdings price source) changed which rows appear and how lots are priced, not this wording. Blocked w1/257 is about which currencies count as cash. No open item covers it.

---

**Resolved 2026-11-15.** Each missing holdings leg now records whether it belongs to a costed lot or to an uncosted position no quote values, and the summary words it to match on both surfaces: `valued at cost`, `shown in units`, or `costed lots valued at cost, the rest shown in units` when one leg covers both (per-account grouping). The cli's `_holdings` / `_holdings_valuation` in `cli/src/bea_engine/report.py` also apply this to the `earlier holdings …` variant, and the strict error's hint now reads `for cost-basis values`, `to show them in their own units`, or `to value the costed lots at cost and show the rest in units`. backend-v2's `utils/holdings.ts` words `missing_price_summary` the same way, so REST, GraphQL and MCP get it too; `docs/mcp.md` notes it. Tests: three new cases in `cli/tests/test_report_holdings.py` and two in `backend-v2/src/features/ledger/utils/__tests__/holdings.test.ts`, all failing with the fix reverted. Dashboard and mobile do not read `missing_price_summary`. (`cli`, `backend-v2`)

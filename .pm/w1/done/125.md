# Report headlines read "Unavailable" when only an earlier interval row lacks a price

**Severity: minor. Owner: cli. Estimate: 45–60m. A1:** holding a commodity before its first price is common; current totals must still be reported. Continuous CLI QA, 2026-10-03 (round 7); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, bea 0.3.1, macOS 26.5.1 arm64. Fresh process per command with timeouts, isolated `HOME`/`XDG_*`/`BEA_CONFIG_DIR`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control.

`late.bean` = `noprice.bean` from [124](./124.md) plus `2026-02-10 price EUR 1.10 USD` and a `2026-03-15` USD-only transaction.

```sh
bea --json --file /abs/late.bean report balance-sheet --allow-errors
bea --file /abs/late.bean report income-statement --allow-errors
bea --json --file /abs/late.bean report overview --allow-errors
```

Actual: balance sheet `net_worth: {"USD": null}` while `assets.balance_children` is `{"USD": "155.00"}` (no liabilities) and the 2026-03-31 series row reads 155.00; income statement text "Net Profit: Unavailable USD" beside "Income -55.00 USD"; overview `totals.net_worth` null. Trial balance and `bea balance` (same as-of) succeed with valuation `complete`. `-i daily` shows the same on a stock bought 03-05 and first priced 03-10.

Expected: the headline is valued at `as_of`, where EUR has a price; USAGE says rows that converted keep their numbers, so no row should contradict the headline.

Cause: `cli/src/bea_engine/report.py:157–159` (overview), `:196–199` (income statement), `:274–276` (balance sheet) feed every series point into `_valuation`; headlines then use `incomplete=bool(valuation["missing_prices"])` (`:166`, `:203`, `:279/:283`), so one unpriced historical row poisons the as-of headline.

Fix/acceptance: derive headline `incomplete` from the headline balances at `end_date` (`_unvalued` on the summed trees); keep `valuation: "partial"` and `missing_price_dates` describing rows. With `late.bean`: `net_worth` `{"USD":"155.00"}`, `net_profit` `{"USD":"55.00"}`, January row still null; ledgers unpriced at as-of still null the headline. (Whether a row-only gap should exit 1 without `--allow-errors` is a separate, documented policy question.)

Dedupe: `w3/done/374` is the opposite case (headline null, series per-unit).

---

**Resolved 2026-10-03** — report headlines are valued at the as-of date, so a price missing only from an earlier interval row no longer makes them read Unavailable; the rows still report `valuation: "partial"`. `tests/test_report_headline_valued_at_as_of.py` covers it. Shipped in the commit that moved this note (`cli`).

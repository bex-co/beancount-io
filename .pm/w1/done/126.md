# `bea balance --json` always reports `account_filter_empty: false`

**Severity: minor. Owner: cli. Estimate: ~15m. A1:** automation needs to distinguish no match from zero balances. Continuous CLI QA, 2026-10-03 (round 7); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, bea 0.3.1, macOS 26.5.1 arm64. Fresh process per command with timeouts, isolated `HOME`/`XDG_*`/`BEA_CONFIG_DIR`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control.

`bea --json --file /abs/main.bean balance Nope` → `account_filter: "Nope"`, `account_filter_empty: false`, all five trees null. Control: `report trial-balance -a Nope` gives `true`; the text path says "No accounts match Nope."

Cause: `cli/src/bea_engine/report.py:118–120` — `_balances` overrides `account_filter` but keeps `_metadata`'s `account_filter_empty` (`:436`), computed from `filtered.account`, which is `None` for `balance`.

Fix/acceptance: set it to `bool(accounts) and all(tree is None for tree in pruned.values())`; `balance Nope` → `true`, `balance Bank` → `false`.

---

**Resolved 2026-10-03** — `bea balance --json` now sets `account_filter_empty: true` when no account matches the filter, and the text note prints once. `tests/test_balance_account_filter_empty.py` covers it. Shipped in the commit that moved this note (`cli`).

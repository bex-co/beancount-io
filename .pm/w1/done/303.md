# The `bea query` shell's `.output` takes its argument raw: `.output -` writes the results into a file named `-`, `.output "my file.csv"` keeps the quotes in the name, and `.output ~/out.csv` fails

**Severity: minor** (nothing in the ledger is touched, but the results the user asked for go to a file nobody looks at, and the shell prints nothing to say so). **Owner:** cli. **Estimate:** 20–30m. **A1:** an agent or a person driving the interactive shell switches back from a file with `.output -`, the spelling `bea query -o -` documents, and every later result disappears into `./-`.

Found by `/qa-find-bugs-cli w1` on 2026-11-19 (HEAD `26cd17187`, `bea 0.4.1`, macOS 26.5.1, checkout `uv run bea`, engine served from the checkout). Isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier off, no `BEA_FILE`/`BEA_TOKEN`, synthetic ledger, the shell driven through a real PTY. Reproduced twice in fresh directories, in both the managed shell and `bea query --source`.

## Repro

`main.bean` (`bea check` exits 0):

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Equity:Open
2024-01-02 * "Seed"
  Assets:Cash  10 USD
  Equity:Open
```

In a terminal, in that directory, run `bea --file main.bean query` and type:

```
.output out.csv
SELECT account LIMIT 1
.output -
SELECT 'back to terminal?' AS t LIMIT 1
.output "my out.csv"
SELECT 1 AS one LIMIT 1
.output ~/qa-out.csv
.output
SELECT 'terminal' AS t LIMIT 1
```

## Actual

- After `.output -` the `back to terminal?` table does not print. A new file named `-` appears in the working directory holding it. Every later result goes there too until a bare `.output`.
- `.output "my out.csv"` creates a file whose name includes the quote characters: `"my out.csv"`.
- `.output ~/qa-out.csv` prints `Cannot write to ~/qa-out.csv: No such file or directory.` and keeps the current destination.
- A bare `.output` restores the terminal (`terminal` prints), as documented.

`bea query --source main.bean` (the native shell) does the same for `.output -`.

## Expected

The shell's `.output` should read a destination the way `bea query -o` does:

- `-` means the terminal. `cli/src/cli/output.py:68` `STDOUT_PATHS` maps `-` to stdout for `-o`, and `cli/docs/USAGE.md` (Output destinations) says `query -o /dev/stdout` "prints it as `-o -` does". For treeify it adds that neither form "reads or creates a file named `-`".
- `~/` expands to the home directory, as USAGE.md "Choosing the ledger" promises for path options. `bea query -o '~/x.csv'` writes into the home directory today.
- A path in one pair of matching quotes is read without them. Inside the shell there is no outer shell to strip them, and a path with a space is otherwise impossible to quote.

The USAGE.md sentence on the shell ("`.output FILE` redirects results and `.output` restores the original output stream") should name `-` beside the bare form.

## Root cause

`_redirect_output` (`cli/src/bea_engine/query.py:492`) passes the argument straight to `open(arg, "w", …)` at `:517`. Only an empty argument restores the stream. Upstream Beanquery 0.2's `do_output` does the same: `open(arg, "w") if arg else …`. Both shells reach it: the managed shell's `do_output` (`:1462`, in `build_shell`) and the native shell's (`:628`, in `native_interactive`). Replaying a `.output` line from `~/.config/beanquery/init` goes through the same function (`_replay_init`, `:844`).

## Fix

In `_redirect_output`, before the ledger guards run:

- Strip one pair of matching surrounding quotes. Use quote removal, not `shlex`, so a Windows path keeps its backslashes.
- Treat `-` (after stripping) like the empty argument: restore `stream`.
- Expand `~` with `Path.expanduser()`. An unresolvable `~user` keeps today's "Cannot write to …" note.

The ledger, include-glob and encrypted-member refusals then check the resolved path, so `.output "main.bean"` and `.output ~/books/main.bean` are refused like `.output main.bean`.

## Definition of done

- In a PTY session, `.output -` after `.output out.csv` prints the next result on the terminal and creates no file named `-`. This holds in the managed shell and in `bea query --source`.
- `.output "my out.csv"` writes `my out.csv`, and `.output ~/x.csv` writes into the home directory. Run that check under a temporary `HOME` in the test, never the developer's.
- `.output "main.bean"` (quoted, or via `~`) naming the ledger under query is refused with the existing message, and nothing is written.
- Regression tests next to the existing `.output` tests (`cli/tests/test_ledger_safety.py`, `test_query_shell_eof_export.py`, `test_query_init_file.py`) cover `-`, quotes and `~`, and fail with the fix reverted. `make check-all` passes in `cli/`.

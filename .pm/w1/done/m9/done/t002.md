## Objective

Rework the shared email wrapper, header, and footer around the email theme so every message inherits the dashboard's visual identity, responsive spacing, and supported-client dark presentation by default.

## Context

- `email-wrapper.ts` owns the document, canvas, card, responsive CSS, and composition order.
- `email-header.ts` and `email-footer.ts` currently use one-off neutral styling and do not express the dashboard's green brand.
- Structural markup and inline styles must remain robust in conservative email clients.

## Steps

1. Apply the theme contract to the body canvas and centered content container with safe width and mobile padding.
2. Align header branding, typography, border treatment, and spacing with the dashboard visual language.
3. Align the footer's muted text and surface treatment while preserving its existing extension parameters.
4. Add supported-client dark-mode metadata/selectors without weakening inline light fallbacks or document semantics.

## Files

- `backend-cluster/backend-v2/src/shared/email-templates/components/email-wrapper.ts`
- `backend-cluster/backend-v2/src/shared/email-templates/components/email-header.ts`
- `backend-cluster/backend-v2/src/shared/email-templates/components/email-footer.ts`
- `backend-cluster/backend-v2/src/shared/email-templates/components/__tests__/`

## Acceptance criteria

- [ ] All templates inherit a coherent dashboard-aligned canvas, container, header, content, and footer from the shared shell.
- [ ] The shell has usable light fallbacks, intentional supported-client dark styling, and no horizontal overflow at narrow mobile widths.
- [ ] Semantic document order, escaped titles/product names, and existing footer parameters remain intact.
- [ ] Shared-component tests pass after asserting stable behavior rather than incidental full-markup snapshots.

## Out of scope

- Adding marketing-email unsubscribe behavior or changing email delivery infrastructure.

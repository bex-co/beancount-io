## Objective

Polish welcome, signup-OTP, and password-reset email content so headings, primary actions, links, codes, security callouts, and secondary resources consistently use the shared dashboard-aligned email styles.

## Context

- The three templates duplicate blue buttons, links, slate colors, borders, and callout treatments inline.
- Transaction-specific hierarchy must stay clear: dashboard/reset actions are primary, OTP codes are scannable, and security notes remain prominent without looking like primary actions.
- HTML and plain-text versions must continue to convey the same information.

## Steps

1. Replace one-off visual values with shared email roles/helpers for headings, body copy, links, primary buttons, callouts, codes, and secondary-link rows.
2. Normalize spacing, radius, typography, and hierarchy across all three templates while retaining email-safe table/block markup.
3. Preserve copy, link destinations, expiration guidance, plain-text parity, escaping, and URL validation.
4. Check unusually long URLs, optional welcome names, and four- and six-digit OTP layouts for overflow or ambiguity.

## Acceptance criteria

- [ ] Every HTML template uses the same dashboard-aligned type, color, spacing, border, action, and callout vocabulary.
- [ ] Primary CTAs and links use accessible brand-green pairings in light and intended dark presentation.
- [ ] OTP, security notes, long fallback links, secondary resources, and personalized greetings remain readable on narrow layouts.
- [ ] Plain-text content, URL validation, and XSS escaping retain their current behavior.

## Out of scope

- Rewriting transactional copy, changing token expiry policy, or adding new email types.

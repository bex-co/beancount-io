## Objective

Persist the sidebar width so it survives reload and renders correctly on first paint (no width flash), and fix the existing open/collapsed cookie that is written but never read back.

## Context

- The repo already has an isomorphic hook: `dashboard/src/common/hooks/use-cookie-storage-state/use-cookie-storage-state.ts` — SSR-safe (reads on server and client, write no-ops on server), built on `js-cookie` (already a dependency). Prefer it over a bespoke cookie codec.
- Current bug: `SidebarProvider` writes `sidebar_state` (`ui/sidebar.tsx:85-88`) but always initializes from `defaultOpen = true` (~56, 74) and no caller passes `defaultOpen`, so collapse never persists.
- Constants `SIDEBAR_COOKIE_NAME = "sidebar_state"`, `SIDEBAR_COOKIE_MAX_AGE` already exist (~27).

## Steps

1. Persist `width` (e.g. cookie key `sidebar_width`) through `useCookieStorageState`, seeding t001's initial width from it and re-clamping on read.
2. Seed `open` initial state from the existing `sidebar_state` cookie so collapse/expand actually survives reload (read on init, SSR-safe).
3. Keep writes debounced/committed on change; ensure server and client hydration agree (no mismatch warning, no flash).

## Files

- `dashboard/src/common/components/ui/sidebar.tsx`
- reuse `dashboard/src/common/hooks/use-cookie-storage-state/`

## Acceptance criteria

- [ ] Resizing then reloading restores the same width, correct on first paint (no visible jump).
- [ ] Collapsing then reloading restores the collapsed state.
- [ ] No hydration mismatch warning in the console.

## Out of scope

- The drag interaction (t003). This task only makes width/open durable.

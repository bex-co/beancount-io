## Objective

Extend the existing (currently toggle-only) `SidebarRail` into a drag handle that resizes the sidebar live using native Pointer Events, without triggering a React re-render on every pointer move.

## Context

- `SidebarRail` today only calls `toggleSidebar` (`ui/sidebar.tsx:305-329`); it already sits on the sidebar edge with a resize cursor.
- Technique (hand-rolled, no library): a `role="separator" aria-orientation="vertical"` div wired to `onPointerDown/Move/Up/Cancel` with `setPointerCapture`. Hold drag-transient data (`pointerId, startX, side, moved, width`) in a `useRef`, not state, so pointer moves cause zero re-renders.
- During drag, write width imperatively to `--sidebar-width` on the wrapper element and set `data-dragging="true"` so a CSS rule disables the width transition; commit the final value to `setWidth` (t001) once on `pointerup`.
- Compute width from `wrapper.getBoundingClientRect()` + `e.clientX`, clamped via t001's helper. Left-button only.

## Steps

1. Add pointer handlers + the drag `useRef` to `SidebarRail`; capture the pointer on `pointerdown`.
2. On `pointermove`, clamp and write `--sidebar-width` directly on the wrapper; mark `data-dragging`.
3. On `pointerup`/`pointercancel`, release capture, clear `data-dragging`, and commit via `setWidth`.
4. Add a CSS rule (Tailwind `group-data-[dragging=true]`) to disable the width transition mid-drag.
5. Preserve existing double-click toggle; add basic ARIA (`aria-valuemin/max/now`, `aria-label`). Keyboard arrow-resize optional (note if deferred).

## Files

- `dashboard/src/common/components/ui/sidebar.tsx`

## Acceptance criteria

- [ ] Dragging the rail resizes the sidebar smoothly, clamped to min/max.
- [ ] No React re-render fires per pointer-move (width flows through the CSS var; state commits once on release).
- [ ] Width transition is disabled during active drag, restored after.
- [ ] Double-click still toggles collapse.

## Out of scope

- Rendering the rail into the layouts (t004). Persistence (t002).

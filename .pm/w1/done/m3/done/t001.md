## Objective

Give `SidebarProvider` a `width` value it owns and exposes, driving the `--sidebar-width` CSS variable from state instead of the hard-coded `SIDEBAR_WIDTH` constant, so a later drag handle has somewhere to write.

## Context

- Primitive: `dashboard/src/common/components/ui/sidebar.tsx` — `SidebarContext` (~line 44), `SidebarContextProps` (~34–42), memoized `contextValue` (~123–134), inline `style` with `--sidebar-width`/`--sidebar-width-icon` on the wrapper (~145–151).
- Current width is a fixed constant `SIDEBAR_WIDTH = "16rem"` (~27–31). The gap div and fixed container already consume `w-(--sidebar-width)`, so overriding the var resizes both automatically.
- No resize library is installed; keep it that way.

## Steps

1. Add pixel constants + a `clampSidebarWidth()` helper (round + clamp to [min, max]). Suggested: min 192, default 256, max 384.
2. Extend `SidebarContextProps` with `width: number` and `setWidth: (px: number) => void`; add both to the memoized context value.
3. Seed `width` from the default constant via lazy `useState` (persistence wiring comes in t002).
4. Compute `--sidebar-width` inline style from `width` (e.g. `${width}px`) instead of the constant.

## Files

- `dashboard/src/common/components/ui/sidebar.tsx`
- optional: a small `dashboard/src/common/components/ui/sidebar-state.ts` for the constants + clamp helper.

## Acceptance criteria

- [ ] `useSidebar()` exposes `width` and `setWidth`.
- [ ] Setting width through context changes the rendered sidebar width (gap + container) with no other regressions.
- [ ] Width is clamped to the configured min/max.

## Out of scope

- Cookie persistence (t002), the drag handle itself (t003), rendering the rail (t004).

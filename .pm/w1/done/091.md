# `cloud ledger create --json` omits fields that `show --json` returns for the same ledger

**Severity: minor. Owner: cli. Estimate: 15–20m. A1:** scripts confirm what was created from the create response. Continuous CLI QA, 2026-10-03 (round 4); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, `BEA_FILE`/`CI` unset. **Local simulation:** a Python stub at `127.0.0.1:18765` returning the OpenAPI success shapes, reached via `BEA_API_URL` and a fake `BEA_TOKEN`; it logs every request. No real service or credential was used. Reproduced twice with a working control.

```sh
bea --json cloud ledger create new2 --public
bea --json cloud ledger create n1 -d "日本語 desc"
bea --json cloud ledger show alice/new2      # control
```

Actual: create's `data` has only id, name, full_name, http_url, ssh_url, private, empty, created_at, updated_at — `description`, `size`, `permissions`, `is_starred` are dropped (the request body did carry the description, but neither human nor JSON output shows it). `show --json` returns all 13 fields.

Expected: USAGE says create "returns the new ledger's metadata"; the spec's create 200 schema matches `getLedger`.

Cause: `cli/src/cli/commands/cloud/ledger/manager.py:26–50` (`LedgerInfo` / `_to_info` subset), emitted at `app.py:94`; `error.result` at `app.py:91` uses the same subset.

Fix/acceptance: emit `snake_keys(response.to_dict())` like `show`; create and show JSON key sets are equal.

Dedupe: none (`w1/done/m12/t001` defined only the minimum `LedgerInfo`).

---

**Resolved 2026-10-03** — `bea --json cloud ledger create` now returns the same full ledger record as `cloud ledger show`, including in a clone failure's `error.result`. `tests/test_cloud_create_json_parity.py` compares the two. Shipped in the commit that moved this note (`cli`).

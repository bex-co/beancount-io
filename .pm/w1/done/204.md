# Register `conversion=units` returns cost totals, and unknown conversions pass silently

**Bug · backend-v2 · major · ~30m · A1.** From `/qa-find-bugs-mcp`, 2026-11-09, production `beancount-mcp 1.0.0`, read-only on the public example ledger, account `Assets:US:ETrade:ITOT`.

- **Repro:** read the final row's balance from `beancount://<o>/<n>/register/Assets:US:ETrade:ITOT?conversion=X`. REST `GET …/register?account=…&conversion=X` and GraphQL `getLedgerRegister(conversion: X)` return the same values for every case below.

  | `conversion` | Result | Actually is |
  | --- | --- | --- |
  | omitted / `USD` | `{"USD":"7792.72"}` | market value |
  | `units` | `{"USD":"6828.88"}` | cost; byte-identical to `at_cost` |
  | `bogus` / `EUR` / `usd` | `{"ITOT":"104"}` | the real units view, returned without a refusal |

- **Expected:** the register's own description says `units` means "each row's held currencies", so `units` should return `{"ITOT":"104"}`. An unknown currency, or one the ledger doesn't use, should be refused with `BAD_USER_INPUT` "Unsupported conversion …". Statements, overview and account-report already do this (w23/156).
- **Cause:**
  - `ledger-finance-service.ts:404` omits `conversion` when `resolveConversionTarget` maps `units` to `null` (`report-conversion.ts:36`), so the ledger service falls back to its default, `at_cost`.
  - `resolveRegisterConversion` (`register.ts:53-66`) checks only the commodity shape (`report-conversion.ts:40`), never the ledger's own currencies.
  - The register shipped in 9749c9d3b, after w23/156.
- **Fix:** pass `conversion: "units"` explicitly when the caller asks for units. Validate a named currency against the ledger's currencies, using the helper the statement and overview reports already use. The change is in the shared service, so REST, GraphQL and MCP all pick it up.
- **Check:** add parity tests on a cost-basis account for `units`, `at_cost`, an unknown code and a lowercase code.

**Addendum 2026-11-10 (alias sweep):** two more reads ignore the w23/156 rule, which listed both in its scope. Fold them into the same fix and parity rows.
- **`account-journal?conversion=`:** `bogus`, `EUR`, `usd`, `AT_COST` and `Units` all return the units view without a refusal. GraphQL `getLedgerAccountJournal` behaves the same.
  - Cause: the ledger's `ledger-journal-service.ts:973` passes `query.conversion || "at_cost"` through unvalidated.
- **`holdings?conversion=`:** `bogus` returns 200 with `valuation: "partial"`, and `usd` and `EUR` each return a different body.
  - Cause: `holdings.ts:88` calls `resolveConversionTarget` (`report-conversion.ts:25-50`), which checks only the commodity shape.
- **Fix:** route both through `cost-valuation.ts` `resolveConversion`. The balance sheet, income statement, overview, trial balance and interval totals already refuse these values.

---

**Resolved 2026-11-10.** The register, the account journal and holdings now treat `conversion` the way the statements do (w23/156).
- **Account journal (ledger):** `getAccountJournal` holds an explicit `conversion` to the statements' own `resolveConversion`. `bogus`, a currency the ledger never names, `usd`, `AT_COST` and `Units` are refused `BAD_USER_INPUT` "Unsupported conversion …", not answered with the units view. It still defaults to `at_cost` when omitted.
- **Register (backend-v2):** unconverted is sent as `conversion: "units"`. It used to be omitted, and the ledger then fell back to `at_cost`, so `units` answered the cost total. The register reads the account journal, so it inherits the ledger's refusal. Case-insensitive mode names (`Units`, `AT_COST`) keep normalising, as they did, with the CLI.
- **Holdings (backend-v2):** holdings is composed in backend-v2 over BQL. A named currency is checked against the currencies the ledger reports: posting and cost currencies, both sides of every price pair, and the operating currencies. One it never names is refused before the query, instead of answering `valuation: "partial"`.
- **Tests:** `account-journal-conversion.test.ts` (ledger) covers the five refusals and the units, cost and currency views. In backend-v2, `report-conversion-parity.test.ts` drives the register for `units`, `at_cost`, `USD`, an unknown code and lowercase `usd`, plus holdings refusals and acceptances, on REST, MCP and GraphQL. Reverting the backend-v2 change fails 5 cases and reverting the ledger change fails 6. `ledger-finance-service.test.ts` now pins `units` as sent. (`ledger`, `backend-v2`)

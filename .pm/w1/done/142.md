# A `.output` line in the beanquery init file erases the ledger through one-shot `bea query --source`

**Severity: major. Owner: cli. Estimate: 40–60m. A1:** user configuration must never be able to truncate the ledger. Continuous CLI QA, 2026-10-03 (round 10); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1 (Beancount 3.2.3, beanquery 0.2.0), Python 3.13, macOS 26.5.1 arm64. Fresh process per command with timeouts, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME` (so `~/.config/beanquery/init` below is the isolated home), notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control.

```sh
printf 'option "operating_currency" "USD"\n2024-01-01 open Assets:Bank USD\n' > main.bean
mkdir -p ~/.config/beanquery && printf '.output main.bean\n' > ~/.config/beanquery/init
bea query --source "$PWD/main.bean" 'SELECT count(*)'     # also with the query on stdin
wc -c main.bean
```

Actual: exit 0, empty stdout/stderr, `main.bean` is **0 bytes** (3/3: absolute path, relative path, stdin query). Controls: init `.output /abs/other.txt` writes `other.txt` with the ledger intact; interactive native (`source-shell`) is safe because it passes `runinit=False` and replays init through the guarded `do_output` (`cli/src/bea_engine/query.py:314`).

Expected: the redirect onto the ledger is refused, as [w1/done/038](./done/038.md) does for typed `.output`; at minimum the ledger is untouched.

Cause: `cli/src/cli/commands/query.py:241–244` checks only the query string (`_refuse_one_shot_output`) then hands off to upstream `bean-query`, whose `main` builds `BQLShell(…, runinit=True)`; `DispatchingShell.__init__` runs the init file through the unguarded upstream `do_output` (`open(arg, "w")`) before the ledger loads.

Fix/acceptance: route one-shot `--source` through the engine's guarded shell with `runinit=False`, loading the ledger and then replaying init through `_redirect_output` (or skip init in one-shot mode). Init `.output <ledger or include>` → refusal, ledger hash unchanged; init `.output other.txt` still works; regression tests for argument and stdin queries.

Dedupe: no `.pm` hit for beanquery init `.output`; gap in `a048d307`.

---

**Resolved 2026-10-03** — already satisfied by `dad407b9` (w1/043): native `--source` one-shots now run through the `source-query` engine command, which loads the ledger first and replays the beanquery init file through the guarded `.output`, so an init `.output` naming the ledger is refused and the ledger is unchanged. Verified at HEAD with the note's argument and stdin repros; `tests/test_query_init_file.py` (shipped with w1/143) covers both. No code change for this note.

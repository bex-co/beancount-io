# `add transaction --json` output drops a `@@` total, so feeding it back writes a repeating `@` unit price

**Severity: minor. Owner: cli. Estimate: ~30m. A1:** round-tripped entries must keep the exact text the user wrote. Continuous CLI QA, 2026-10-03 (round 4); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced twice from fresh fixtures with a working control.

```sh
bea --json --file /abs/a.bean add transaction --date 2021-01-02 --narration fx -p 'Assets:Euro 3 EUR @@ 10.00 USD' -p Assets:Cash
# feed data.directive to: bea --file /abs/b.bean add transactions --from rows.json
```

Actual: the answer has `"price": {"number": "3.333333333333333333333333333"}` and no `price_total`; the bulk add writes `3 EUR @ 3.333333333333333333333333333 USD` instead of `@@ 10.00 USD`.

Expected: `cli/docs/USAGE.md` — "A `@@` total is written back with `@@` and its exact total, never divided into a repeating unit price", and the add answer is valid bulk input.

Cause: `cli/src/bea_engine/ledger/adding.py:546–548` strips the `@@` marker before building the answer, so `price_total` never reaches the JSON. (`list transaction --json` loses it too — `reader.py:171–180` never fills `price_total` — which is partly documented as booking normalisation; lower priority.)

Fix/acceptance: emit `price_total` from the marker with `price` null; the second write is byte-identical to the first.

Dedupe: `w3/309` and `w1/done/m27/t003` fixed the writer, not the JSON answer.

---

**Resolved 2026-10-04** — the `add transaction --json` answer now reports a `@@` total as `price_total` (with `price: null`), so feeding it back writes the same `@@` line instead of a repeating `@` unit price. A test in `tests/test_total_price.py` covers it. Shipped in the commit that moved this note (`cli`).

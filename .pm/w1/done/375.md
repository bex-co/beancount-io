# A write with `--file` on a month file under a year index is checked against that file alone once a sibling month has an entry: the unknown-account remedy writes duplicate `open`s (exit 0) and a `close` or `balance` that contradicts the root lands with exit 0 (regression of w5/343 and w5/346 from w5/774)

**Major · cli · 30–45m · A1.** Routine cli-qa, 2026-11-23, HEAD `4ffb4e0b8`, checkout `bea 0.5.0` (`uv run bea`), macOS 26.5.1, Python 3.12.14, managed engine 0.5.0. Isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, stdin closed, no TTY, every run from a pristine copy in a fresh process. No product fix implemented.

A common split layout: the root opens the accounts, a year file only includes the month files, and each month file holds transactions.

```sh
mkdir -p books/2026
cat > books/main.bean <<'EOF'
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Expenses:Food USD
include "2026/index.bean"
EOF
printf 'include "01.bean"\ninclude "02.bean"\n' > books/2026/index.bean
printf '2026-01-05 * "Jan lunch"\n  Expenses:Food  5.00 USD\n  Assets:Checking\n' > books/2026/01.bean
printf '2026-02-05 * "Feb lunch"\n  Expenses:Food  6.00 USD\n  Assets:Checking\n' > books/2026/02.bean
bea --file books/main.bean check                      # exit 0
bea --file books/2026/01.bean add transaction "Jan snack" --date 2026-01-06 \
  -p "Expenses:Food 1.00 USD" -p Assets:Checking
```

Actual: exit 1, `The change would leave the ledger invalid`, `01.bean:1: Invalid reference to unknown account 'Assets:Checking' To create it, use bea --file books/2026/01.bean add open --account Assets:Checking …` (the same for `Expenses:Food`). `01.bean` is unchanged. Following that remedy, as w5/343 recorded:

- `bea --file books/2026/01.bean add open --account Assets:Checking --date 2026-01-01` exits 1 with `The ledger already has 1 error(s) … Pass --allow-errors to write anyway.`; with `--allow-errors` it exits 0, and `add open --account Expenses:Food` then exits 0 without it. `01.bean` now ends with both `open` lines, and `bea --file books/main.bean check` exits 1: `01.bean:5: Duplicate open directive for Assets:Checking`, `01.bean:7: … Expenses:Food`.
- `bea --file books/2026/01.bean check` lists the unknown accounts with no word that `main.bean` loads the file (w5/348's hint is missing too).

The w5/346 fixture shows the silent half. Its `tests/test_nested_leaf_write_checks_top_root.py` books (`main.bean` posts to `Assets:Bank` and includes `sub dir/extra.bean`, which includes `nested/deep.bean`, holding `2026-01-01 open Assets:Bank USD`) are unchanged except that `extra.bean` also includes `nested/other.bean`, holding one `2026-01-10 * "Cash lunch"` transaction (`Expenses:Food 2 USD` / `Assets:Cash`). With `--no-input --file "books/sub dir/nested/deep.bean"`:

- `add close --account Assets:Bank --date 2026-01-20 --force` exits 0, `Added 1 close to …/deep.bean`, and the root check then fails: `main.bean:10: Invalid reference to inactive account 'Assets:Bank'`.
- `add balance --date 2026-03-01 --account Assets:Bank --amount '0 USD'` exits 0, and the root check fails: `Balance failed for 'Assets:Bank': expected 0 USD != accumulated 97 USD`.

Controls: make the sibling hold no entry (`02.bean` or `other.bean` a lone `;` comment) and the same commands behave as w5/346 requires. The add prints `01.bean is included by …/books/main.bean; the write goes to 01.bean and is checked against that whole ledger.` and exits 0. The balance is refused with exit 1 (`accumulated 97 USD`), with the same redirect note. `bea --file books/main.bean add transaction … --into 2026/01.bean` works in either layout.

Expected: an includer that opens nothing and sets no option, and whose only entries come from other leaves it includes, is a pass-through intermediate. The climb continues past it to `main.bean`, as it does when the siblings are empty. Writes on any month file then run through the root (`--into` set to the leaf). The unknown-account remedy and `check`'s read hint name the root. Import dedupe and memory are the root's. A Fava or forecast overlay above the working ledger still stops the climb (w5/578, w5/774).

Cause: `cli/src/bea_engine/ledger/write.py` `defining_root` (`:2278`) stops at the first includer that does not define what the leaf reads when `_step_adds_entries` (`:2407`) is true (`:2312`). That test looks at every file in the includer's closure outside the leaf's own, so a sibling month's transactions make the year index look like an overlay that adds entries. The climb ends with no root and `write_through_root` (`:2465`) leaves the write on the leaf. `root_read_hint` (`:2416`) has the same gap, and `root_ledger_hints` (`:2513`) checks only the nearest includer with `defines_for`. Introduced by `c727a3623` (w5/774), which replaced `top_root`'s climb to the topmost includer. The w5/346 test fixture has no sibling, so it still passes.

Fix: tell an overlay's own entries from a sibling leaf's. One way is to judge the step by the files it adds that post to accounts no file in its closure opens. Those can only be read through a root above, so the step is an intermediate and the climb continues. The overlay shapes w5/578 and w5/774 pinned must still stop. Apply the same rule wherever the climb is used: `write_through_root`, `root_read_hint`, `root_ledger_hints`, and `update`'s root discovery.

Dedupe: searched `.pm/**` for `pass-through`, `overlay`, `adds entries`, `sibling`, `index.bean`, `w5/346`, `w5/774`. Parents: w5/343, w5/346, w5/348, w5/578 and w5/774 (all done). No open item covers the sibling shape.

Acceptance: in both fixtures above, the add, close and balance writes on the month leaf run through `main.bean`. The valid write lands in the leaf with the redirect note, and the contradicting close and balance are refused, leaving the files unchanged. `bea --file <leaf> check` names the root, the w5/578 and w5/774 overlay fixtures behave as before, and a test pins the sibling-with-entries shape.

**Resolved 2026-11-23** — A write with `--file` on a month file under a year index now runs through the root even when a sibling month holds entries, shipped in the commit carrying this note (`cli`). `defining_root` (`cli/src/bea_engine/ledger/write.py`) still stops at an includer that defines nothing and adds entries, but only when that includer's closure loads on its own: a new `_needs_root_above` says a closure that posts to an account it never opens, with no plugin that could open it, needs a root above, so the year index (or the w5/346 `extra.bean` with a sibling `other.bean`) is a pass-through and the climb reaches `main.bean`. A sibling holding only prices passes through too, since the leaf's own postings count. Overlays whose entries post to accounts the working ledger opens still stop the climb, so the w5/578 and w5/774 fixtures are unchanged. `write_through_root`, `update`'s root discovery and `root_read_hint` share the climb; `root_ledger_hints` now uses it as well instead of judging only the nearest includer, and `defines_for`, left without a caller, is gone with its rationale moved to `_defines_in`. In the note's fixture the add lands in `01.bean` with the redirect note naming `main.bean`, the balance (`accumulated -12.00 USD`) and the close are refused leaving the file unchanged, an unknown account's remedy reads `bea --file books/main.bean add open`, and `bea --file books/2026/01.bean check` names the root. `cli/docs/USAGE.md` records it. Regression tests: `cli/tests/test_month_leaf_sibling_entries.py` (subprocess, with a sibling month holding a transaction and one holding only a price: the add through the root, the refused balance and close, the remedy, the check hint; engine-side: the `--into` recipe) and a `sibling` variant of the `cli/tests/test_nested_leaf_write_checks_top_root.py` fixture; 15 of the 18 fail with the source change reverted (the three that pass are the pre-existing no-sibling cases).

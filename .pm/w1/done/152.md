# A blank first line hides the CSV header, and the error advice cannot work

**Severity: minor. Owner: cli. Estimate: ~20m. A1:** bank exports often start with a blank line. Continuous CLI QA, 2026-10-03 (round 11); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command with timeouts, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, stdin closed. Reproduced twice from fresh fixtures with a working control.

Base ledger: `option "operating_currency" "USD"`, `2026-01-01 open Assets:Checking USD`, `2026-01-01 open Expenses:Uncategorized USD`.

A file `\nDate,Description,Amount\n2026-08-02,COFFEE,-5.00\n`, imported with or without `--csv date=Date,…`: exit 2 both ways — without `--csv` the error cites the "header row bea could not read" and suggests a `--csv` line; with `--csv` it says 'Date' "which s5.csv lacks".

Cause: the two reader copies disagree — `detect_delimiter` skips blank lines (`cli/src/cli/csv_mapper.py:379`, engine `:544`) but `open_records` takes the first raw record as the header (frontend `:437–442`, engine `:631–636`).

Fix/acceptance: skip leading empty records before reading the header in both `open_records` copies, preserving file line numbers. The repro imports with `Row 1 (line 3)` numbering. (A non-blank preamble such as `Account: 123` fails the same way; preamble support is a separate enhancement.)

---

**Resolved 2026-10-04** — blank lines before a CSV header are now skipped, and error line numbers still count them. `tests/test_csv_leading_blank_lines.py` covers it. Shipped in the commit that moved this note (`cli`).

# Narrow-terminal `list` tables still pad and truncate CJK/emoji by character count (gap in w3/391)

**Severity: minor. Owner: cli. Estimate: ~20m. A1:** CJK users read listings in ordinary terminal widths. Continuous CLI QA, 2026-10-03 (round 5); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control.

In a 70-column PTY, `bea --file /abs/cjk.bean list transaction` with payee `東京ラーメン屋さん` and narration `昼ご飯のラーメンと餃子を食べました`.

Actual: the CJK row's narration starts ~8 columns right of its header and the 34-column narration isn't truncated, so the row overflows. Control: at 200 columns the rows align (that path uses `output.table`).

Expected: `w3/done/391` — every `bea` table sizes and pads by display width.

Cause: `cli/src/cli/commands/list.py:234–265` — the fit test, `widths`, `cell[:w-3]` truncation and `ljust` use `len()` instead of `output.display_width`. `w3/391` (`e213e53b`) fixed only `output.table`.

Fix/acceptance: display-width-aware fit, padding and truncation in that branch. In a 70-column PTY every column starts under its header and no line exceeds 70 columns.

---

**Resolved 2026-10-03** — narrow-terminal `list` tables now pad and truncate by display width, so CJK and emoji rows align and fit. A test in `tests/test_output.py` covers it. Shipped in the commit that moved this note (`cli`).

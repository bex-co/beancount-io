# `query -o /dev/null` fails with a raw errno and `-o /dev/stdout` leaks an engine usage error

**Severity: minor. Owner: cli. Estimate: ~30m. A1:** scripts discard or redirect exports with standard device paths. Continuous CLI QA, 2026-10-03 (round 5); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control.

```sh
bea --file /abs/main.bean query -o /dev/null 'SELECT date'      # exit 1: [Errno 1] Operation not permitted: '/dev/.bea-<hex>.tmp' (category validation)
bea --file /abs/main.bean query -o /dev/stdout 'SELECT date'    # exit 1: The Beancount engine did not answer '... --output /dev/fd/1' (exit 2) + boxed Typer "Path '/dev/fd/1' is not readable"
bea --file /abs/main.bean format -o /dev/stdout                 # (stdout piped) exit 2: Path '/dev/stdout' is not readable
```

Controls: `format -o /dev/null` and `treeify -o /dev/null` exit 0; `query -o out.txt` exits 0.

Expected: `/dev/null` discards output; `/dev/stdout` behaves like `-` or is refused with a clear exit 2 — never an internal engine command line (USAGE "Output destinations").

Cause: `cli/src/bea_engine/query.py:209` stages via `candidate_file` (`bea_engine/ledger/write.py:280`) beside the destination then `os.replace`s (from the `w3/404` atomic-export fix, `89670084`); Typer `Path` options default to `readable=True` (`bea_engine/main.py:114`, `cli/commands/format.py:54`); `cli/src/cli/output.py:372` lets device paths through. Untested risk: as root with a writable `/dev`, the replace could swap `/dev/null` for a regular file.

Fix/acceptance: write directly when the destination exists and is not a regular file; treat `/dev/stdout`/`/dev/fd/1` as `-` (or refuse with exit 2 before the engine); `readable=False` on output options. `query -o /dev/null` exits 0 in text/CSV/JSON; `/dev/stdout` exits 0 or 2 with a clear message.

Dedupe: no `.pm` hit for `/dev/null` or `/dev/stdout` as `-o`; `w3/404` is the origin.

---

**Resolved 2026-10-03** — `bea query -o /dev/null` now discards the result and `-o /dev/stdout` (or `/dev/fd/1`) prints it like `-o -`; device and FIFO destinations are written into, never replaced, and `format -o /dev/stdout` no longer leaks an engine usage error. `tests/test_query_output_devices.py` covers each case. Shipped in the commit that moved this note (`cli`).

# `query --source` ignores `--no-input` and opens a waiting interactive shell

**Severity: minor. Owner: cli. Estimate: 25–40m. A1:** agents using a PTY and explicitly disabling interaction must receive a missing-query error instead of waiting for input. Continuous CLI QA, 2026-10-02; no product fix applied.

Environment: `main` at `1a1480c8ad2dee049c4bccf4a646c2513082b04c`, source-checkout `cli/.venv/bin/bea` (editable metadata 0.3.0; source/engine 0.3.1), Python 3.13.0, macOS 26.5.1 arm64. Synthetic ledger, isolated configuration/cache, no inherited target/token, real PTY.

In a disposable directory, save one line to `main.bean`:

```beancount
2024-01-01 open Assets:Cash USD
```

Run in a terminal:

```sh
bea --no-input query --source /absolute/main.bean
```

Actual: prints the native input statistics and `beanquery> `, then waits for input. Repeated twice in fresh processes; the harness confirms the process remains alive with idle stdin after the prompt, then explicitly sends `.exit` to close it. Final exit 0 is after that supplied input, not an autonomous completion. Stderr is empty and the ledger is unchanged. This is an unintended prompt, not a CPU hang.

Working control: `bea --no-input --file /absolute/main.bean query` refuses immediately with exit **2** and `A query is required with --no-input. Pass it as an argument or on stdin.` Native `--source` with an explicit query completes without interaction; a query supplied through piped stdin also completes. Closing stdin with no query currently exits 0 silently, another symptom of skipping the common missing-query validation.

Expected: the global `--no-input` contract in `cli/docs/USAGE.md` says never prompt and fail with exit 2 when input is missing. The documented native `--source` exceptions concern output/JSON/strict reads, not this flag. Respect the already-resolved noninteractive policy before launching native Beanquery.

Cause: `cli/src/cli/commands/query.py:228–237` delegates to `launch.run_native` before the stdin/query/`ctx.no_input` handling at lines 244–258. Nothing passes noninteractive intent into native Beanquery, which sees a real terminal and opens its shell. Caller search found this sole native query branch; the managed branch is the working control. `git log -S 'if source is not None'` traces the delegation to `20fefdf4`; no later guard fixes this path.

Fix/acceptance: resolve missing query/available stdin and reject a forbidden interactive session before native dispatch. Real PTY tests must show the reproduced command exits 2 without a prompt, while explicit queries, piped query text, and normal interactive native use keep working. Exercise `CI`'s implied no-input policy through the same boundary when implementing (not independently reproduced here). Keep the intended native JSON/strict exceptions. Run `make check-all` inside `cli/`; no backend/API or new dependency is involved.

Dedupe: searched all `.pm` states and open milestones for no-input, unattended queries and native source handling. `w3/done/401` and `w1/039` concern strict load validity, not interaction; `w1/038` owns native redirection data loss. No open interaction-policy item found. Native multiple-statement parsing and missing stored-query exit behavior were observed separately but are not asserted as part of this finding.

Evidence: `cli/tmp/qa-20261002-cli-2mbxnp30/captures/repeat-native-no-input-{1,2}.json`, `cycle6-no-input-False.json`, `cycle6-native-stdin-query.json`, and explicit-query controls. Captures retain argv/cwd, isolated env, PTY inputs, separate stdout/stderr, durations, process status and unchanged file hashes. A child hook relocates only upstream history/init files for isolation. All sessions stopped; no hosted resources, credentials or real ledger writes. Other platforms unverified.

---

**Resolved 2026-10-03** — native `bea query --source` now settles a missing query the way `--file` does: under `--no-input`, `CI`, or with empty stdin it exits 2 before the engine starts instead of opening a prompt or exiting 0, and a terminal opens the native shell only when prompting is allowed. Real-terminal tests in `tests/test_query_source_no_input.py` cover both source forms. Shipped in the commit that moved this note (`cli`).

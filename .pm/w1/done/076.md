# Concurrent commands on a ledger with managed prices fail at random with a raw `[Errno 2]` on the price cache

**Severity: major. Owner: cli. Estimate: ~30m. A1:** agents run bea commands in parallel; a cache refresh must never fail a read. Continuous CLI QA, 2026-10-03 (round 3); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1 (Beancount 3.2.3, beanquery 0.2.0), Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control.

Managed-price cases are **local simulations**: a threaded `http.server` stub on `127.0.0.1:8765`, enabled with `MANAGED_PRICE_ORIGINS=http://127.0.0.1:8765` and the ledger line `include "http://127.0.0.1:8765/prices/BTC-USD"`. Base fixture: open `Assets:Bank USD`, `Assets:Crypto BTC`, `Equity:Opening`; fund 10000 USD; buy `1 BTC {5000 USD}`; then the include.

Stub serves the feed with ETag `"same"` (every re-fetch is a 304). Set `next_refresh_at` to 0 in the feed's `head.json` (window lapsed), then run 8 `bea --file /abs/main.bean check` in parallel, 6 rounds.

Actual: 13/48 exit 1 with `Error: [Errno 2] No such file or directory: '…/managed-prices/<hash>/.head.json.tmp' -> '…/head.json'`; with changing feeds the error names `.<rev>.beancount.tmp` / `.<rev>.json.tmp`. 8 parallel `bea price refresh` × 5: 18/40 fail. Control: 16 serial runs exit 0.

Expected: ADR018 §6 — "Concurrency is handled by write ordering… every write is an atomic rename… the only cost is a redundant conditional GET."

Cause: `cli/src/bea_engine/managed_price_cache.py:151–156` `_write_text` uses the fixed temp name `.{name}.tmp`; one process's `os.replace` consumes another's temp file (callers at lines 228, 250, 251, 267, 288, 339). A truncate-while-renaming interleaving could also publish a partial file (not observed).

Fix/acceptance: unique temp (`tempfile.mkstemp(dir=parent)`) + `os.replace`, cleaned up on failure. 8×6 parallel `check` and 8×5 parallel `price refresh` all exit 0 with a lapsed window, for 304 and changing feeds; multiprocessing regression test.

Blast radius: every ledger-loading command once the 5-minute window lapses, plus `price refresh`.

Dedupe: no `.pm` hit for `head.json.tmp` or concurrency + managed prices; `git log -S _write_text` → `4e265882` (`w1/done/m29/t002`).

---

**Resolved 2026-10-03** — each managed-price cache write now uses its own temporary file (removed on failure) and the effective feed is written atomically too, so parallel commands no longer fail with a raw `[Errno 2]` on the price cache. Tests in `tests/test_price.py` include an 8-process stress run. Shipped in the commit that moved this note (`cli`).

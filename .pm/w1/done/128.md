# Docs-example tests pass when a piped `bea` command fails and never check documented output

**Severity: minor. Owner: cli. Estimate: 30–45m. A1:** "every documented invocation runs in CI" must actually hold. Continuous CLI QA, 2026-10-03 (round 7); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, bea 0.3.1, macOS 26.5.1 arm64. Fresh process per command with timeouts, isolated `HOME`/`XDG_*`/`BEA_CONFIG_DIR`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control.

`cli/tests/test_docs_examples.py:150–159` runs fences with `bash -e -c` but no `pipefail`; transcript output lines are dropped (`script_for`, `:116–145`); `EXPECT` asserts only README fence 2 (`987.50`). Feeding the harness's own `run_doc()` a fence containing `bea --json query "SELEC broken" | jq .data.columns` and `bea --json nosuchcommand | jq .` passes — both `bea` commands fail and `jq` exits 0 on empty input. So the three `bea … | jq` lines in USAGE fence 23 can break or drift ([127](./127.md)) with CI green.

Expected: the module docstring — "Every documented `bea` invocation runs in CI with its expected outcome".

Fix/acceptance: run fences with `set -o pipefail`; assert key fragments of `$ `-prompted transcript fences (at least fence 23). The synthetic pipe fence above must fail.

Dedupe: distinct from [069](./069.md) (`bash -e` short-circuit after `bea query` in fence 4).

# `bea query -o spend.xlsx` writes an ASCII text table under a spreadsheet's name, exit 0, though `-o spend.tsv` and `-o spend.json` are refused for exactly that

**Bug · cli · minor · ~20m · A1.** From routine cli-qa, 2026-11-21. `bea query` guards its `-o` suffix so a destination never silently receives an ASCII text table it does not look like: `.csv` implies `--format csv` (w3/324), `.bean`/`.beancount` imply `--format beancount` (w5/459), and `.tsv` and `.json` are refused with exit 2 and a hint ("so the destination is not an ASCII text table"). A workbook name is not covered. `bea query -o spend.xlsx "SELECT …"` exits 0 and writes the text table into `spend.xlsx`; `.xls`, `.ods` and `.numbers` do the same. `file` calls the result `ASCII text`, `unzip -l` finds no archive, and a spreadsheet app refuses or warns on a file whose content does not match its workbook extension. Naming the output after the spreadsheet you plan to open it in is the most natural spelling for a user or agent who wants one, and the command reports success. `bea report … --format csv -o is.xlsx` likewise writes CSV text under an `.xlsx` name with exit 0. Without `--format csv`, `report -o is.xlsx` is already refused with exit 2.

Environment: main `c9d492c18`, `bea 0.5.0` from the checkout (`uv run bea`), Python 3.12.14, macOS 26.5.1. Isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, `BEA_FILE`/`BEA_TOKEN` unset, stdin closed, no TTY, scratch cwd, fresh processes.

## Repro

```sh
printf 'option "operating_currency" "USD"\n2026-01-01 open Assets:Cash\n2026-01-01 open Expenses:Food\n2026-01-02 * "Lunch"\n  Expenses:Food 12.50 USD\n  Assets:Cash\n' > main.bean
bea --file main.bean query -o spend.xlsx "SELECT account, sum(position) GROUP BY account"   # exit 0
file spend.xlsx                                       # spend.xlsx: ASCII text
cat spend.xlsx                                        # the "account  sum(position)" table with a ---- rule
bea --file main.bean query -o spend.tsv "SELECT account"                       # exit 2, "looks like TSV" (control)
bea --file main.bean query -o spend.json "SELECT account"                      # exit 2, "looks like JSON" (control)
bea --file main.bean report income-statement --format csv -o is.xlsx           # exit 0, is.xlsx: CSV text
```

## Expected

`bea` writes no workbook format, so an `-o` naming one (`.xlsx`, `.xlsm`, `.xls`, `.ods`, `.numbers`, any letter case) is refused with exit 2 before the query runs or any file is created. This applies to `bea query` with or without `--format`, and to `bea report … --format csv`. The error names the file and points at the format a spreadsheet opens: `--output spend.xlsx names a spreadsheet workbook, which bea does not write; use -o spend.csv (spreadsheets open CSV)`, adding `--spreadsheet-safe` where the command takes it. An existing file at that path is left untouched. `.csv`, `.tsv`, `.json` and the ledger suffixes behave as today. `docs/USAGE.md` states the rule beside the existing `.tsv`/`.json` one.

## Cause

`cli/src/cli/commands/query.py:351-370` maps only `.csv`, `.bean`/`.beancount`, `.tsv` and `.json`; any other suffix keeps the default text renderer. `cli/src/cli/commands/report.py:393` checks only for `.csv`.

## Fix

Add the workbook-suffix refusal in `query.py` beside the `.tsv`/`.json` branches. It must also fire when `--format` or `--json` is given, since no bea format is a workbook. Apply the same check to the report `-o` path in `report.py`. Add a regression test through real `bea query` and `bea report` subprocesses: each workbook suffix exits 2 with the hint, no file is created, and a pre-existing file at that path stays byte-identical. Keep `-o out.csv` and the `.tsv`/`.json` cases as controls. Revert the fix and watch it fail. Owned by `cli`.

## Dedupe

Searched `.pm/**` for `xlsx`, `.xls`, `.ods`, `workbook` and `.numbers`. The hits are deferred XLSX export non-goals (w4/m1, w21/m9), a dashboard upload alert (w2/128) and the dashboard's new-file name rule (w21/429). None covers a CLI `-o` workbook name. The neighbouring guards are w3/324 (`.csv`), w5/459 (ledger suffixes), and the `.tsv`/`.json` refusals (`git log -S'looks like TSV'` → `c938a7074`).

---

**Resolved 2026-11-21** — `bea query -o` and `bea report -o` now refuse a spreadsheet workbook name (`.xlsx`, `.xlsm`, `.xls`, `.ods`, `.numbers`, any letter case) with exit 2 before the query or report runs, under every format and `--json`, leaving an existing file untouched; the hint names the CSV file to write instead (`use -o spend.csv --spreadsheet-safe (spreadsheets open CSV)`, `drop --json and …` under `--json`, no `--spreadsheet-safe` with `--source`). `docs/USAGE.md` states the `-o` suffix rules; `cli/tests/test_output_workbook_name_is_refused.py` covers both commands through real subprocesses (41 of its 45 cases fail with the fix reverted). Shipped in `6cc969f38` (`cli`).

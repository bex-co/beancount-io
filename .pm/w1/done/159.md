# The frontend include scan misses `include"x"` and escaped include strings, so `-o` guards let exports overwrite included ledger files

**Severity: major. Owner: cli. Estimate: 30–45m. A1:** output guards must see every file the ledger actually loads. Continuous CLI QA, 2026-10-03 (round 13); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command with timeouts, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with before/after hashes and a working control. Found by a regression hunt over shipped fixes.

`data.bean`: `2026-01-01 open Assets:Cash USD`, `2026-01-01 open Income:Job USD`, and a `2026-01-05 * "Pay"` transaction between them. `main.bean`: `include"data.bean"` (also `include "d\ata.bean"` or `include "data\.bean"` — upstream's lexer accepts all three and loads `data.bean`).

```sh
bea format main.bean -o data.bean
bea query --source main.bean -o data.bean "SELECT account, sum(position) GROUP BY account"
bea treeify main.bean -o data.bean --force
```

Actual: `format` and `query --source` exit 0 and replace `data.bean` (re-verified by the filer: after `format`, `data.bean` contains only `include"data.bean"`); `treeify --force` exits 2 but has already written. The format closure is affected too: with `include"data.bean"` and a misaligned `data.bean`, `format --check main.bean` reports "All 1 file(s) are formatted" (exit 0) and `-i` leaves the include untouched; with `include "d\ata.bean"`, `--check`/`-i` report a false `missing include` (exit 1). Controls: `include "data.bean"` is refused (exit 2) by all three; `--file … query -o data.bean` is refused for every spelling (the engine uses the loader's include list).

Expected: exit 2 "would overwrite the ledger it reads (data.bean)", file byte-identical — the `w1/done/m23/t001` guard; format scopes the full include closure (`m23/t003`).

Cause: `cli/src/cli/output.py:186` — `_INCLUDE_DIRECTIVE = re.compile(r'^\s*include\s+"([^"]+)"', re.MULTILINE)` requires whitespace after `include` and doesn't apply the lexer's backslash unescaping before globbing (`_include_matches`, `output.py:197–215`). Callers: `refuse_ledger_alias` (`output.py:279`) from `format.py:137`, `query.py:65/67`, `treeify.py:26`; `ledger_closure`/`missing_includes` also feed `format.py:392–396` and `check.py:75`. Gap in `285b6d90` and `50fd1b28`.

Fix/acceptance: parse include strings like the lexer (`\binclude\s*"((?:[^"\\]|\\.)*)"` then unescape) without importing Beancount in the frontend. For all three spellings, `format -o`, `query --source -o`, `treeify -o --force` onto the include exit 2 with its hash unchanged; `format --check root` scans 2 files and flags a misaligned include; no false missing-include. Related: [041](./041.md) (other suffixes), [154](./154.md), [155](./155.md), [156](./156.md).

---

**Resolved 2026-10-04** — the frontend include scan now reads `include"x"` and escaped include strings as the lexer does, so `-o` guards and the format closure see those includes. `tests/test_include_scan_lexer_spellings.py` covers it. Shipped in the commit that moved this note (`cli`).

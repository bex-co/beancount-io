# A bare filter word with a combining mark is refused "Illegal character"

**Bug · ledger · minor · ~20m · A1.** From `/qa-find-bugs-mcp`, 2026-11-10, production `beancount-mcp 1.0.0`, unpinned API key, the disposable QA ledger.

Journal filters can't take a bare word containing a combining mark. That covers every Hindi and Thai word, Arabic with harakat, and decomposed Latin and Vietnamese.

- **Repro:** `listLedgerEntries {"filter": F}`. REST `GET …/journal?filter=` returns the same 400.

  | `F` | Result |
  | --- | --- |
  | `हिंदी` | `BAD_USER_INPUT` 'Illegal character "ि"' (U+093F) |
  | `บัญชี` | `BAD_USER_INPUT` 'Illegal character "ั"' (U+0E31) |
  | `مَطعم` | `BAD_USER_INPUT` 'Illegal character "َ"' (U+064E) |
  | `école` (NFD) | `BAD_USER_INPUT` 'Illegal character "́"' |
  | `Tiếng` (NFD) | `BAD_USER_INPUT` 'Illegal character "̂"' |

  - The hint is the generic "Fix the named argument…" and doesn't mention quoting.
  - **Control:** the same words quoted (`"हिंदी"`, `"école"`) parse and match, and precomposed `école` parses bare.
- **Cause:** `backend-cluster/ledger/src/foundation/rustledger/directive-filter.ts:400`. The STRING rule `/[\p{L}\p{N}_][\p{L}\p{N}_-]*/u` has no `\p{M}`, so the first combining mark falls through to `:446` (`Illegal character`).
  - Fava's `\w` has the same gap upstream, but this port already deviates by using `\p{L}\p{N}`.
  - The engine accepts these characters in account names (w4/279, w4/1048).
- **Fix:**
  - Allow `\p{M}` after the first character: `[\p{L}\p{N}_][\p{L}\p{M}\p{N}_-]*`.
  - When the refused character is a mark or another letter-like character, make the refusal suggest quoting.
  - This covers every `filter` argument on REST, GraphQL and MCP, plus the dashboard search.
- **Check:** `directive-filter` tests for bare `हिंदी`, `บัญชี` and NFD `école`. `#` and `'` are still refused.

---

**Resolved 2026-11-10.** Bare filter words with combining marks now parse and match. The STRING rule in `directive-filter.ts` allows `\p{M}` after the first character, so bare `हिंदी`, `บัญชี`, `مَطعم`, NFD `école` and NFD `Tiếng` match as their quoted forms do. This covers every `filter` argument on REST, GraphQL and MCP, and the dashboard search.
- **Refusal wording:** a letter-like character the bare rule still cannot take, such as a leading combining mark, is now refused with "quote the value to search for it, e.g. "…"". Stray `#` and `'` keep their refusals.
- **Tests:** `directive-filter.test.ts` covers the five words bare and quoted, the stray `#`/`'` refusals, and the quoting hint. Reverting the fix fails 6. Fava's golden filter cases are unchanged and still pass. (`ledger`)

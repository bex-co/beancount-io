# `bea init --opening-balance` refuses a bad value without saying what is wrong or which accounts it accepts

Found by `/qa-find-bugs-cli w1` on 2026-11-15 (HEAD `00aef2e2e`, `bea 0.3.1`, macOS 26.5, checkout `uv run bea`, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`). Severity: minor. A2: an unattended newcomer or agent running `bea --no-input init` cannot learn from the error which part of its `--opening-balance` was wrong, or which account names the starter chart has, without first creating a ledger to read them from.

**Repro** (each in a fresh empty directory):

```sh
bea --no-input init books --currency USD --date 2026-01-01 --opening-balance 'Assets:Bank:Checking 100'   # unknown account
bea --no-input init books --currency USD --date 2026-01-01 --opening-balance 'Assets:Checking 1000 USD'   # natural amount form
bea --no-input init books --currency USD --date 2026-01-01 --opening-balance 'Expenses:Rent 10'           # not an asset/liability
bea --no-input init books --currency USD --date 2026-01-01 --preset personal@1 --opening-balance 'Assets:Nope 5'
```

**Actual.** All four exit 2, create nothing, and print the same line: `Error: --opening-balance '<value>': Opening balance must be 'ACCOUNT NUMBER' for one of the template's asset/liability accounts.` The second case names a real template account (`Assets:Checking`); its only problem is the trailing currency, yet the message reads as if the account were wrong. No case lists the accounts the template has (the fixed chart's are `Assets:Checking`, `Assets:Savings`, `Assets:Cash`, `Liabilities:CreditCard`). Control: `--opening-balance 'Assets:Checking 1000'` succeeds.

**Root cause.** `cli/src/cli/commands/init.py` (about line 524) folds three different checks — the value has two words, the account is in `allowed_opening`, the account is under `Assets:`/`Liabilities:` — into one condition with one message.

**Fix (cli only).** Give each failure its own message, keeping exit 2 and `--opening-balance '<value>':` as the prefix:
- wrong shape: say it takes `ACCOUNT NUMBER` with the amount in the operating currency. A trailing currency equal to the chosen `--currency` may instead be accepted; a different currency is refused, naming both.
- unknown or non-asset/liability account: name the account and list the accepted ones (the fixed chart's, or the preset's and its modules' when `--preset` is given).

**Done when** each repro prints a message naming its own problem, the unknown-account and `Expenses:Rent` cases list the accepted accounts (the preset's for the fourth), the control still succeeds, and regression tests in the init tests cover each case (failing with the fix reverted). `cli/docs/USAGE.md` describes the behavior if it changes what is accepted.

**Dedupe.** Searched `.pm/**` (including `done/`) for `opening-balance`, `Opening balance must be` and `template's asset/liability`; `git log -S "template's asset/liability"`. w5/588 (validate before prompting, name the option) and w5/290 (comma-grouped numbers) are done and cover neither the message's content nor the account list. No open item.

---

**Resolved 2026-11-15.** `bea init` now checks each `--opening-balance` value in turn and refuses it with a message naming its own problem, keeping exit 2 and the `--opening-balance '<value>':` prefix. A value without exactly `ACCOUNT NUMBER` is refused as the wrong shape. A trailing currency equal to `--currency` is accepted (`Assets:Checking 1000 USD`). A different currency is refused naming both, and a currency given before one is chosen is refused asking for `--currency`. An unknown account, or an account that is not an asset or liability, is named and the accepted accounts are listed: the fixed chart's, or the preset's and its modules'. The control `Assets:Checking 1000` still succeeds. `cli/src/cli/commands/init.py`, `cli/docs/USAGE.md`. Regression tests: `cli/tests/test_init_opening_balance_messages.py` (fails with the fix reverted), plus a pty case in `cli/tests/test_init_options_before_prompts.py`. (`cli`)

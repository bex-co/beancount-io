# `bea report holdings` prints a sub-cent average cost as `0.00 USD`, so a 0.0042 USD lot reads as free

Found by `/qa-find-bugs-cli w1` on 2026-11-15 (HEAD `7d7b4d223`, `bea 0.3.1`, macOS 26.5.1, checkout `uv run bea`, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, synthetic ledger). Severity: minor (text display only; JSON and CSV are exact). A1/A2: crypto and penny-stock holders, and the agents that read `bea` tables for them, see a zero per-unit cost beside a nonzero cost basis.

**Repro** (synthetic):

```sh
cat > main.bean <<'EOF'
option "operating_currency" "USD"
2026-01-01 open Assets:Bank:Checking USD
2026-01-01 open Assets:Broker
2026-01-01 open Equity:Opening
2026-01-01 * "open"
  Assets:Bank:Checking 5000.00 USD
  Equity:Opening
2026-01-02 * "buy"
  Assets:Broker 100000 SHIB {0.0042 USD}
  Assets:Bank:Checking -420.00 USD
2026-01-05 price SHIB 0.0050 USD
EOF
bea --file main.bean report holdings
bea --file main.bean --json report holdings
```

**Actual.** The text row is `Assets:Broker  SHIB  100,000 SHIB  0.00 USD  420.00 USD  500.00 USD`, so AVG COST reads `0.00 USD`. `--json` (and `--format csv`) carry `"average_cost": {"number": "0.0042", "currency": "USD"}`. A whole-dollar ledger does the same thing at a larger scale. With postings like `5000 USD` and lots `1000 PENNY {0.30 USD}` and `100 EUR {1.10 USD}`, AVG COST prints `0 USD` and `1 USD` (exit 0, with `-x at_cost` too).

**Expected.** AVG COST is a per-unit figure, so it should not be rounded to the currency's posting precision. It should keep the digits the lots were costed in: `0.0042 USD`, `0.30 USD`, `1.10 USD`. A weighted average that does not divide evenly (`1600 USD / 15 VTI`) should still round to a bounded precision, which is the larger of the currency's display precision and the finest lot cost in the group. Then `106.67 USD` stays `107 USD` in a whole-dollar ledger whose lots cost whole dollars. Units, COST BASIS, MARKET VALUE and the totals keep today's rounding. USAGE.md's "Reports" says display precision comes from posting amounts and "not from price quotes or cost numbers". That rule is about which numbers set a currency's precision. It does not say a per-unit cost may be rounded to zero, and the dashboard already treats that as a bug (w4/1007, tiny Holdings average costs).

**Root cause.** cli: `holdings` in `cli/src/cli/commands/report.py` (about line 634) renders `group["average_cost"]` through `_money(..., precision)`, the same `_amounts` path (about line 148) that quantizes report amounts to `display_precision`. The engine (`cli/src/bea_engine/report.py`, about line 732) sends the exact `basis / units`. Nothing else in the text reports shows a per-unit figure.

**Fix.** In the holdings text table only, render the average cost at `max(display precision, the finest fractional digits among the group's lot costs)`. Either the engine sends that digit count beside `average_cost`, or the frontend takes it from the exact number when it terminates within a bound. JSON and CSV stay exact. Tests in `cli/tests/test_report_holdings.py` should cover a sub-cent lot in a cents ledger, a `0.30` lot in a whole-dollar ledger, and a repeating weighted average that still rounds, and they should fail with the fix reverted. backend-v2 has no text renderer, so no parity change is needed. Estimate: 30–45 minutes.

**Blast radius.** Only the holdings AVG COST column, under both `--group-by account` and `commodity` and under every conversion that keeps a cost (`USD`, `at_cost`). `register`, `capital-gains` and the statements print amounts, not per-unit figures.

**Dedupe.** Searched `.pm/**` (open, `done/`, `blocked/`) for `AVG COST`, `average_cost`, `average cost`, `per-unit` and `whole-dollar`. w4/1007 is the dashboard's version (its `roundDecimalString` cap), fixed in `dashboard` only. w1/052, w5/093 and w5/668 are about too many decimals, not too few. No open item covers the CLI.

---

**Resolved 2026-11-15** — the holdings text table renders AVG COST at the larger of the currency's display precision and the finest lot-cost digits in the group, so `{0.0042 USD}` shows `0.0042 USD` and `{0.30 USD}` / `{1.10 USD}` in a whole-dollar ledger show `0.30 USD` / `1.10 USD`, while `1600 USD / 15 VTI` over whole-dollar lots still prints `107 USD`. The engine (`cli/src/bea_engine/report.py` `_holdings`) sends the digits as the text-only `average_cost_precision` hint, which `--json` strips like `display_precision`; CSV is unchanged. `cli/docs/USAGE.md` "Reports" notes the rule. Tests: three cases in `cli/tests/test_report_holdings_register_frontend.py`, the sub-cent and whole-dollar ones failing with the fix reverted. Shipped in `49d008561` (`cli`).

# The engine imports Python modules from the current directory, so untrusted folders run code and `check` modes disagree

**Severity: major. Owner: cli. Estimate: 20–30m. A1:** agents run bea from arbitrary checkouts; a plugin-free ledger must never execute code from cwd. Continuous CLI QA, 2026-10-03 (round 5); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control.

```sh
mkdir books untrusted
printf '2024-01-01 open Assets:Cash USD\n' > books/main.bean
printf 'open("/abs/PWNED","a").write("ran\\n")\nraise ImportError("shadow")\n' > untrusted/regex.py
cd untrusted && bea --json --file /abs/books/main.bean check     # also: bea format /abs/books/main.bean, bea list open
```

Actual: `untrusted/regex.py` runs (the `PWNED` marker appears; re-verified by the filer) for every engine-backed command, even though the ledger is elsewhere and declares no plugins. A shadow that re-imports the real module runs silently. Second symptom: with a local `myplug.py` and `plugin "myplug"` (no `insert_pythonpath`), `bea check` exits 1 "No module named 'myplug'" while `bea --json check` exits 0 when run from that directory and 1 from anywhere else.

Expected: a ledger runs no code from cwd unless it declares it; human and JSON check agree; module search matches upstream `bean-check`/`bean-format`, which in the same directory do not import `regex.py` (control).

Cause: `cli/src/cli/engine/launch.py:465` — `_module_command` returns `[python, "-m", "bea_engine"]`, and `-m` puts cwd at `sys.path[0]` ahead of the standard library; `_helper_env` (`launch.py:471–490`) does not set `PYTHONSAFEPATH`. Native tools run as console scripts (`sys.path[0]` is `bin/`), so they are unaffected.

Fix/acceptance: launch the helper with `-P` / `PYTHONSAFEPATH=1` (Python ≥ 3.11, already required by the managed engine). A `regex.py` or `beancount.py` in cwd is never imported by any engine command; `check` and `check --json` agree on the `myplug` fixture from any cwd; local plugins still resolve via `option "insert_pythonpath" "TRUE"`. Regression test runs `bea --json check` from a directory containing a shadow module.

Blast radius: every engine call — `check --json` and human check's second pass, format, list, query, report, add, import, ask tools, doctor helpers.

Dedupe: no `.pm` hit for shadow / `PYTHONSAFEPATH` / `sys.path` / cwd import; `git log -S'"-m", "bea_engine"'` → `a90b1706`. USAGE warns only that ledger plugins and importer configs run their own code.

---

**Resolved 2026-10-04** — engine commands now run Python with `-P`, so modules in the current directory are never imported (untrusted folders cannot run code) and human and JSON `check` agree on plugin resolution; plugins beside the ledger still load through `insert_pythonpath`. `tests/test_engine_ignores_cwd_modules.py` covers it. Shipped in the commit that moved this note (`cli`).

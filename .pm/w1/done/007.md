# `cloud ledger delete` asks for confirmation before validating `owner/name`

**Severity:** major  
**Package:** `cli`  
**Env:** `bea 0.1.0`, no network needed

## Repro

```bash
bea --json cloud ledger delete open_ledger
# exit 2: Permanently delete ledger 'open_ledger'? Refusing to ask — pass --yes …

bea --yes --json cloud ledger delete open_ledger
# exit 2: 'open_ledger' is not a ledger full name; expected 'owner/name'.
```

Same with `--no-input` (no `--yes`): refusal-to-ask, not a format error.

## Expected

Invalid `full_name` fails as a usage error naming the `owner/name` shape before any destructive confirmation (and before auth). Agents under `--json` should not be told to pass `--yes` for a name that can never delete.

## Actual

Generated `ledger_delete` calls `confirm(...)` first, then `owner_and_name(full_name)`. Unattended mode therefore surfaces the confirmation gate for garbage input.

## Root cause

`cli/src/cli/commands/cloud/generated/ledger.py` (`ledger_delete`); generator in `scripts/gen_cloud_commands.py` should validate path params before the `x-cli-destructive` prompt.

## Fix

Parse/validate `full_name` (and any other path args) before `confirm`. Add a contract test: `--json cloud ledger delete open_ledger` exits 2 with the full-name message and does not mention `--yes`.

## Estimate

~30–45m

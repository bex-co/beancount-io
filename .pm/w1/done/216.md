# Statement summaries pick their headline currency by key order, not `operating_currency`

**Bug · backend-v2 · major · ~30m · A1.** From `/qa-find-bugs-mcp`, 2026-11-10, production `beancount-mcp 1.0.0`, read-only on the public example ledger. The ledger declares `option "operating_currency" "USD"`.

The numbers are right, but an agent quoting the headline reports the wrong figure, and `byAccount` hides the operating-currency breakdown.

- **Repro:**
  - `resources/read beancount://<o>/<n>/statements/income-statement?time=2016-01` returns `currency: "IRAUSD"`, `income: -18000`, `expenses: 2400`, `net: 15600`. USD is relegated to `otherCurrencies`, and `byAccount` lists only the two 401k accounts.
  - `time=2016-02` returns `currency: "USD"` with 24 accounts, so the headline flips month to month on the same ledger.
  - `2016-Q1` and `2017-01` pick IRAUSD; `2016-Q2` picks USD. `units`, `at_cost` and `at_value` behave the same way. Only `conversion=USD` forces USD.
  - `interval-totals?time=2016-01&accountName=Income&interval=month` returns `IRAUSD -18000` and moves the salary into `otherCurrencies`.
  - REST returns the same results. Every per-currency total matches a local Fava 1.30 control.
- **Expected:** with no explicit conversion, the headline is the ledger's first `operating_currency` whenever the data carries it. Frequency decides only for ledgers that declare no operating currency. A tie is never broken by JSON key order.
- **Cause:**
  - `src/features/ledger/utils/report-summaries.ts:158-181` (`resolveCurrency`) counts how many evidence balances name each currency, and the first currency to reach the maximum wins (`count > bestCount`).
  - In Jan 2016, USD, IRAUSD and VACHR all appear in every balance, and the key order is `["IRAUSD","USD","VACHR"]`, so IRAUSD wins.
  - `summarizeIncomeStatement` (`:409-450`), `summarizeBalanceSheet` (`:351`), `summarizeOverview` (`:452`) and `summarizeIntervalTotals` (`:477`) all use it, and none of them receives the ledger options.
- **Fix:**
  - Pass the ledger's operating currencies from the handlers into the summarizers (`reports-handler.ts:100`, and the overview and interval handlers). The options read already exists.
  - Choose in this order: the requested currency, then `operating_currency`, then frequency.
  - The summaries are shared by REST and MCP; GraphQL returns raw payloads.
- **Check:**
  - `report-summaries` tests: a USD+IRAUSD+VACHR tie with USD as operating currency resolves to USD.
  - A parity case on a multi-commodity month.
- **Same pass (copy):** a `time` parse refusal says only "Failed to parse date: last year", with the generic "Fix the named parameter…" hint. It should name `time` and give one accepted form, e.g. `2016`, `2016-Q1`, `2016-01 - 2016-03` (`backend-cluster/ledger` `directive-filter.ts:82`).

**Addendum 2026-11-10:** the income statement also returned EUR as its headline currency with `conversion=USD`. This happened on a tag-filtered month where the only spending was an `80.00 EUR @ 1.09 USD` charge (see w1/229). An explicitly requested currency must always win the headline.

---

**Resolved 2026-11-10.** The summary headline currency now defers to the ledger's `operating_currency`.
- **Order in `resolveCurrency`:** first the requested currency, when the data carries it or it is an operating currency; then the first operating currency the data carries; then frequency, with ties broken by name and never by the order a payload lists its keys.
- **Wiring:** the REST and MCP summaries (balance sheet, income statement, overview, interval totals) read the operating currencies beside their report under one authorization and one client. That is new `…ForSummary` service reads. A first version fetched the options separately and doubled each summary's authorization checks, so it was replaced. GraphQL and `shape=fava` still return raw payloads.
- **Result:** the USD+IRAUSD+VACHR month now reports in USD on a USD ledger, with IRAUSD and VACHR in `otherCurrencies`.
- **Addendum:** an explicitly requested operating currency keeps the headline even when the data carries none of it. That is the w1/229 month whose only spending stayed in EUR, and it now reads USD with EUR beside it. A requested currency the ledger never declares and the data does not carry still falls back to the data, as w23/050 documents. The EUR in that month comes from w1/229's price-basis question, which is still open.
- **Time refusal:** the `time` parse refusal keeps its "Failed to parse date:" prefix, which the dashboard maps to its own words. It now adds "time takes a year, quarter, month or day such as 2016, 2016-Q1, 2016-01 or 2016-01-15, or a range such as 2016-01 - 2016-03".
- **Tests:** `report-summaries.test.ts` covers the operating tie, key-order independence, the requested-currency cases and interval totals. `interval-summary-parity.test.ts` checks the tied month on REST and MCP. The parity fixtures gained the options stub; older cases that relied on key order now state the ledger's operating USD. `directive-filter.test.ts` pins the time wording. (`backend-v2`, `ledger`)

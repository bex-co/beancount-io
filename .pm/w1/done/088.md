# `bea cloud ledger delete ../account` sends `DELETE /api-gateway/v1/account`: dot segments escape the ledger path

**Severity: blocker. Owner: cli. Estimate: 20–30m. A1:** a mistyped or agent-supplied ledger name must never address a different endpoint, least of all account deletion. Continuous CLI QA, 2026-10-03 (round 4); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, `BEA_FILE`/`CI` unset. **Local simulation:** a Python stub at `127.0.0.1:18765` returning the OpenAPI success shapes, reached via `BEA_API_URL` and a fake `BEA_TOKEN`; it logs every request. No real service or credential was used. Reproduced twice with a working control.

```sh
BEA_API_URL=http://127.0.0.1:18765 BEA_TOKEN=fake bea --yes cloud ledger delete ../account
```

Actual: the stub logs `DELETE /api-gateway/v1/account` with the bearer header; the CLI then exits 1 "Unexpected server response (HTTP 200)". Other forms: `delete ../x` → `DELETE /api-gateway/v1/x`; `delete alice/..` → `DELETE /api-gateway/v1/ledgers`; `delete ../..` → `DELETE /api-gateway`; `show alice/..` → `GET /api-gateway/v1/ledgers`. The interactive prompt reads "Permanently delete ledger '../account'?", hiding the real target. Control: `delete alice/account` → `DELETE /api-gateway/v1/ledgers/alice/account`. Independently confirmed by the filer: `httpx` normalizes `/api-gateway/v1/ledgers/../account` to `/api-gateway/v1/account`.

Expected: ledger commands only address `/api-gateway/v1/ledgers/{owner}/{name}`. The spec's own patterns forbid these values (owner `^(?!\.{1,2}$)[A-Za-z0-9_.-]+$`, name `^[a-z0-9_-]{1,100}$`), so `.`/`..` must exit 2 before any credential, prompt or request.

Cause: `cli/src/cli/utils.py:113–118` `owner_and_name` checks only for two non-empty segments. The generated client (`cli/src/cli/api/rest_client/api/ledger_v_1/delete_ledger.py:21–24`, evidence only) uses `quote(..., safe="")`, which leaves `.` intact, and httpx removes dot segments client-side — so the server-side slug checks from `w3/m46` never see a ledger path.

Server context (traced, not exercised live): `backend-cluster/backend-v2/src/features/auth/api/account-routes.ts:39–49` defines `DELETE /api-gateway/v1/account`, allowed for `session`/`oauth` credentials (`authorization-service.ts:86,221–224`); a `bea cloud login` token is a session credential, an API key is refused. Whether the live server would accept this request was not tested and must not be tested against a real account.

Fix/acceptance: validate both segments in `owner_and_name` against the spec patterns and reject `.`/`..`. `delete ../account`, `delete alice/..`, `show ../x`, `clone ../x` each exit 2 with **zero** HTTP requests; `show alice/my-books` still works; a test covers every `owner_and_name` caller. Consider defence in depth on the server (the account-delete route could require a distinct confirmation) as a separate backend item.

Blast radius: generated `show`/`delete` (`generated/ledger.py:64,83`), `clone` (`ledger/app.py:111`, `manager.py:64`), and every future generated `{owner}/{name}` command; `create` is safe (`ledger_name` validates).

Dedupe: no `.pm` hit for dot segment / traversal / `owner_and_name`; `w3/done/m46` covers server-side encoded segments only. Two-segment check from `f9d6a288`.

**Additional acceptance cases (round 15, 2026-10-03, local stub):** single-dot segments also escape — `delete alice/.` sends `DELETE /api-gateway/v1/ledgers/alice` and `delete ./x` sends `DELETE /api-gateway/v1/ledgers/x`; both must exit 2 with zero requests. Already safe: `alice/%2e%2e` (sent encoded), ` ../x`, `owner//name` and trailing-slash forms.

---

**Resolved 2026-10-03** — `bea cloud` ledger commands now check `owner/name` against the API path patterns and refuse `.`/`..` segments with exit 2 before any credential, prompt or request, and the API client refuses a dot-segment value for every generated path parameter, so a ledger name can no longer redirect a request to another endpoint. `tests/test_cloud_path_segments.py` covers `show`/`delete`/`clone`, every generated operation, and a subprocess run against a local stub that records zero requests. Server-side hardening of account deletion is backend scope and not part of this fix. Shipped in the commit that moved this note (`cli`).

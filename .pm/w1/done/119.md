# `bea upgrade` deletes the working engine before rebuilding it, leaving none if the rebuild fails

**Severity: major. Owner: cli. Estimate: 1–2h (may warrant promotion). A1:** Homebrew promises local commands work offline after install; a routine upgrade must not break that. Continuous CLI QA, 2026-10-03 (round 7); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, bea 0.3.1, macOS 26.5.1 arm64. Fresh process per command with timeouts, isolated `HOME`/`XDG_*`/`BEA_CONFIG_DIR`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control.

Artifact under test: wheel built from `cli/` with `uv build`, installed into a fresh venv (Python 3.12.14, uv 0.12.13) with HOME, XDG dirs, `BEA_CONFIG_DIR` and `UV_CACHE_DIR` inside the run dir; after the first engine install everything ran with `UV_OFFLINE=1`. Package-manager steps were **simulated** with fake `brew`/`uv` executables on PATH.

Homebrew (simulated): a venv at `X/Cellar/bea/0.3.1/libexec/venv` with the wheel and a working engine at `libexec/engine`; a fake `brew` that prints and exits 0.

```sh
BEA_ENGINE_DIR=…/libexec/engine UV_OFFLINE=1 UV_CACHE_DIR=<empty dir> bea upgrade
bea --file /abs/main.bean check
```

Actual: `bea upgrade` exits 1 "bea upgraded, but refreshing the Beancount engine failed" and `libexec/engine` **no longer exists**; the next `check` exits 1 trying to reinstall. With a warm cache it "succeeds" but rebuilds the keg's engine and writes `engine-requirements.lock` into the Homebrew keg. PyPI/uv-tool channel (fake `uv` printing "Nothing to upgrade"): same; `engine status` then shows `Provisioned: no`, and any `bea-features.json` (enabled Beangulp/Beanprice) is lost. Reproduced 3 times, including no-op upgrades.

Expected: USAGE says Homebrew installs the engine at install time and local commands need no further download; `upgrade.py:147–150` says "Homebrew already provisions libexec/engine at install time"; `provision.py` promises a failed provision never replaces a working environment.

Cause: `cli/src/cli/commands/upgrade.py:166–180` `_refresh_engine` runs for every channel including Homebrew and even when nothing changed; `cli/src/cli/engine/provision.py:58–69` `repair_engine` does `os.replace(root, discarded)` + `rmtree` **before** `provision(root)`.

Fix/acceptance: skip the refresh on the Homebrew channel; refresh only when the version changed; make `repair_engine` build into `.partial` and swap only on success, keeping the old engine and `bea-features.json` on failure. An offline no-op `bea upgrade` leaves `bea check` working and the keg untouched. Promote if over an hour.

Dedupe: no `.pm` hit for `_refresh_engine` / `repair_engine`; `git log -S'_refresh_engine'` → `a90b1706`.

---

**Resolved 2026-10-03** — `bea upgrade` no longer deletes the working engine before rebuilding: rebuilds happen in a `.partial` directory carrying the enabled features and swap in only on success, the refresh runs in the upgraded interpreter, and Homebrew, overridden, checkout and no-op upgrades skip it. `tests/test_upgrade.py` (`TestEngineRefresh`) covers it. Shipped in the commit that moved this note (`cli`).

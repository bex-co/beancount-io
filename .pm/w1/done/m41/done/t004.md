## Objective

Record before and after save timings on the hosted dashboard with a QA account and a synthetic ledger of about 300KB.

## Context

- Baseline from 2026-11-02 (3 saves on a 312KB `main.bean`): toast at 1.97s, 2.38s and 1.99s. `UpdateLedgerFile` took 1.15–1.70s, then `GetLedgerErrors` 0.62–0.79s, then about 10 refetches 0.5s.
- Use a disposable synthetic ledger, never a customer ledger, and delete it afterwards.
- The after measurement needs the dashboard deployed with t001–t003.

## Steps

1. Drive 3 saves with headless Playwright, recording the time to the success toast, the network waterfall, and the response sizes.
2. Write the before and after table into this task.

## Acceptance criteria

- [x] The after timings show the toast at about the `UpdateLedgerFile` time, with no `GetLedgerErrors` before it.
- [x] The total bytes transferred per save are recorded before and after.

## Out of scope

## Progress — 2026-11-02

These measurements use a synthetic 312KB `main.bean` ledger on the hosted dashboard, 3 saves per row. The deployed build has t001 and t002 but not t003: its bundle has no `ACCOUNT_FIELDS` keep-list.

| Build | Toast after ⌘S | `UpdateLedgerFile` | Before the toast | After the toast | File bytes downloaded per save |
| --- | --- | --- | --- | --- | --- |
| Before m41 | 1.97s, 2.38s, 1.99s | 1.15–1.70s | `GetLedgerErrors` 0.62–0.79s | ~10 refetches incl. `GetLedgerFile` | ~860KB (mutation `content` + refetch) |
| t001 + t002 | 1.93s (cold write), 1.18s, 1.10s | 1.01–1.84s | nothing | ~11 refetches incl. `GetLedgerFile` | ~427KB (refetch only) |
| t001–t003 (2026-11-04) | 2.05s (cold write), 1.64s, 1.36s | 1.30–1.93s | nothing | 8 ledger reads plus `GetCurrentUser`; no `GetLedgerFile`, no `GetSubscriptionStatus` | 0.34KB (the mutation's revision only) |

The toast now lands within about 40ms of `UpdateLedgerFile` returning. Every row's toast lands within about 40ms of `UpdateLedgerFile` returning. The rest of each save is the write itself, whose time varies by day: 1.0–1.9s across these runs.

- **2026-11-04:** after t003 the file view keeps the saved file (the footer showed each save's new commit), and the account queries stay cached.
- **`GetCurrentUser`:** it still goes out once per save, but not because of the cache. Leaving edit mode is a navigation, and the root route's `beforeLoad` (`routes/__root.tsx`, `fetchUserProfile`, `network-only`) refetches the signed-in user on every navigation, as it did before m41.
- **`ListLedgers`:** it refetches by t003's recorded deviation.

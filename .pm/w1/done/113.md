# Bundled forecast/amortize plugin copies count as written rows, so `list --on-disk` disagrees with grep

**Severity: major. Owner: cli. Estimate: 45–60m. A1:** agents trust `--on-disk` to say what is actually in the file. Continuous CLI QA, 2026-10-03 (round 6); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1 (Beancount 3.2.3), Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed unless piping JSON. Reproduced twice with a working control; compared against native `bean-check`/`bean-query`.

```beancount
plugin "fava.plugins.forecast"
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Rent USD
2024-01-05 # "Landlord" "Rent [MONTHLY REPEAT 3 TIMES]"
  Expenses:Rent  100 USD
  Assets:Cash
2024-01-07 * "Shop" "real one"
  Expenses:Rent  1 USD
  Assets:Cash
```

`bea --json --file /abs/main.bean list transaction --on-disk --sort oldest`

Actual: exit 0, 4 rows (2024-01-05, 01-07, 02-05, 03-05), none `generated`, all three Rent rows sourced `main.bean:4`; `--limit 2` reports `truncated: true`. With `plugin "fava.plugins.amortize_over"` and `amortize_months: 3`, one written line yields 3 on-disk rows at line 4.

Expected: 2 rows (what grep finds — USAGE `--on-disk` contract); plugin copies marked `generated`.

Cause: `cli/src/bea_engine/ledger/reader.py:101–124` (`entry_generated`) only checks that the line at `lineno` starts the same directive kind; copies that keep their template's meta pass (`cli/src/fava/plugins/forecast.py:121` `template._replace(...)`, the copy loop in `amortize_over.py`). Third-party cloning plugins behave the same.

Fix/acceptance: compare against the pre-plugin parsed entries — a loaded entry is on disk only if an identical parsed entry exists at the same `(filename, lineno, type)` and date; when several share a location, mark all but the match `generated` (or have bundled plugins tag copies with a meta flag the reader honours). Forecast fixture → 2 `--on-disk` rows with copies `generated` in human and JSON; amortize → 1; plugin-free ledgers unchanged.

Dedupe: `w3/301`, `318`, `319`, `320` cover plugins tagging `<plugin>` filenames or borrowing other directive lines, not copies keeping their template location.

---

**Resolved 2026-10-03** — `list --on-disk` no longer counts forecast or amortize plugin copies as written rows: an entry also has to carry the date its source line declares. `tests/test_on_disk_plugin_copies.py` covers both plugins. Shipped in the commit that moved this note (`cli`).

# The dashboard Cash Flow page says "No cash flow data" when no account counts as cash, and never names the cash rule

**Source:** follow-up from routine cli-qa, 2026-11-19. This is the dashboard side of [319](./319.md). **Owner:** dashboard. **A2:** a newcomer whose only bank account is `Assets:Revolut` opens Cash Flow and reads "No cash flow data found for this ledger." (`page.cashFlow.noData`, rendered at `dashboard/src/features/reports/cash-flow/index.tsx:245-253`). The ledger did move money. The real cause is that no account matched the cash rule, and the page never says so or how to fix it.

**Done when:** when the cash set is empty, the empty state says that no account counted as cash, names the rule, and gives the `cash-flow-role: "cash"` remedy. The wording follows what 319 settles for `bea`. A dashboard test covers it, and `yarn format:check`, `yarn lint` and `yarn test` pass in `dashboard/`.

---

**Resolved 2026-11-19** — The dashboard Cash Flow page now explains an empty cash set instead of reporting no data. On a ledger whose only bank is `Assets:Revolut`, the empty state reads **No account counts as cash**, then `No Assets account is named like Cash, Checking, Savings, or Bank, and none declares cash-flow-role: "cash" on its open directive. Add cash-flow-role: "cash" under the open directive of each bank or wallet account.`, with the existing "How accounts are classified" docs link. This follows the wording 319 settled for `bea`. Under renamed roots (`Activos:Banco:Cuenta`) it names the ledger's own assets root (`No Activos account …`). The names come from `CASH_ACCOUNT_NAMES` beside `CASH_EQUIVALENT_PATTERNS` in `cash-flow/config.ts`, are listed with the reader's `Intl.ListFormat`, and are translated in all 15 locales. A ledger with cash accounts and a quiet window, or with no accounts at all, keeps `No cash flow data found for this ledger.`. The cash membership the page already reads is ledger-wide and unfiltered, so the shared filters cannot empty it and no filter variant is needed. `dashboard/src/features/reports/cash-flow/__tests__/no-cash-accounts.test.tsx` (named-after-the-bank, renamed roots) and the extended `activity-eligibility.test.tsx` case fail with the fix reverted. The declared-role, name-rule and no-accounts controls pass both ways, and a `role-resolver.test.ts` case keeps the cited names in step with the patterns. `yarn format:check`, `yarn lint`, `yarn test` and `yarn build` pass in `dashboard/`.

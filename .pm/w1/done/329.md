# `bea add open --meta 'cash-flow-role:Cash'` writes a role the cash-flow report ignores, exit 0, and the duplicate-open refusal tells the user to hand-write the same bad value

**Bug · cli · minor · 20–30m · A1.** From routine cli-qa, 2026-11-20. Gap in [w1/320](./done/320.md). `bea add open --meta` exists so an agent can declare `cash-flow-role` through `bea`, as `skills/beancount-business-metrics/SKILL.md:52` tells it to. ADR003 defines the key with four case-sensitive values, `cash`, `operating`, `investing` and `financing`, and says an invalid value is "never silently accepted". But `bea add open` writes any value: `Cash`, `bank`, `Investing`. It exits 0 with `"warnings": []`, and `bea check` passes. The report then classifies the account by name, so a top-up to the declared bank reads as an investing outflow. The only signal is one stderr line from `bea report cash-flow`, long after the write. For an account that is already open, the duplicate-open refusal quotes the bad value back as the fix: `To add cash-flow-role: "Investing", edit that open's metadata`.

Environment: main `d2a42b8df`, `bea 0.4.1` from the checkout (`uv run bea`), Python 3.12.14, macOS 26.5.1. The run used an isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME` with `BEA_NO_UPDATE_NOTIFIER=1`, `BEA_FILE`/`BEA_TOKEN` unset, stdin closed, no TTY, and a scratch working directory. Reproduced in fresh processes from a pristine copy.

## Repro

```sh
cat > main.bean <<'EOF'
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Equity:Opening USD
2026-01-02 * "open"
  Assets:Checking  100.00 USD
  Equity:Opening
EOF
bea --json --file main.bean add open --date 2026-01-01 --account Assets:Revolut --currency USD --meta 'cash-flow-role:Cash'
cat >> main.bean <<'EOF'
2026-02-01 * "Top up"
  Assets:Revolut  40.00 USD
  Assets:Checking
EOF
bea --file main.bean check
bea --file main.bean report cash-flow
bea --file main.bean add open --date 2026-01-01 --account Assets:Checking --meta 'cash-flow-role:Investing'
```

Actual:

- The first `add open` exits 0 with `"meta": {"cash-flow-role": "Cash"}, "warnings": []`, and writes `cash-flow-role: "Cash"` under the new open.
- `check` exits 0.
- `report cash-flow` exits 0 and lists `Investing  Assets:Revolut  -40.00 USD`. It reports `Cash accounts: Assets:Checking` and `Closing cash: 60.00 USD`, where the user declared Revolut cash and holds 100.00 USD in cash. Its last stderr line is `Assets:Revolut: unknown cash-flow-role value 'Cash'; using the default.`
- The last command exits 1 with `To add cash-flow-role: "Investing", edit that open's metadata (bea add open cannot change an existing open).`

The same happens for `bank`, `CASH`, ` cash ` inside quotes, and any other string.

Expected: `bea add open` refuses (exit 2, nothing written) a `cash-flow-role` value outside the four, naming them, and suggests `cash` for a case-only miss such as `Cash`. An empty value or a non-string (`cash-flow-role:TRUE`, `cash-flow-role:1`) is refused too. The duplicate-open refusal checks the value the same way before it suggests a hand edit, so the hint never tells the user to write a value the report ignores. Other metadata keys are unaffected.

Working control: `--meta 'cash-flow-role:cash'` is written and makes `report cash-flow` count Revolut as cash (`Cash accounts: Assets:Checking, Assets:Revolut`, `Closing cash: 100.00 USD`).

## Cause and fix

The open branch of `_simple` (`cli/src/bea_engine/ledger/adding.py:204`) parses `--meta` with the generic `_parse_metadata`, and nothing checks the one key bea itself reads. The duplicate-open hint (`_duplicate_open_hint` / `_metadata_edit`, `cli/src/bea_engine/ledger/write.py:3819-3890`) echoes whatever was proposed. The report's resolver already holds the canonical list: `_CASH_FLOW_ROLES` and `_CASH_FLOW_ROLE_KEY` (`cli/src/bea_engine/report.py:1590-1591`). Reuse those rather than a second copy. Add tests for the refusal, the case-only suggestion, the duplicate-open hint, and the valid-value control. Document the check in `cli/docs/USAGE.md` beside the existing `--meta 'cash-flow-role:cash'` paragraph. Owning package: `cli`. The skill text needs no change. No hosted surface writes opens with metadata.

**Dedupe:** searched `.pm/**` (done and blocked included) for `cash-flow-role` with `unknown`, `invalid`, `typo` and `wrong case`. w4/m3 added the dashboard's read-time flag, w5/1057 covered declared cash outside Assets, and w1/319 and w1/320 covered the empty cash set and the missing `--meta` option. No item validates the value at write time.

**Done when:** on the repro ledger, `add open --meta 'cash-flow-role:Cash'` exits 2 naming `cash`, `operating`, `investing` and `financing`, and leaves `main.bean` byte-identical. `--meta 'cash-flow-role:cash'` still writes. The duplicate-open refusal for `Investing` no longer tells the user to add `"Investing"`. The new tests fail with the check reverted, and `make check-all` passes.

# Contradictory double-negative CSV amounts like `(-5.00)` are silently booked as money in

**Severity: minor. Owner: cli. Estimate: ~15m. A1:** ambiguous amounts must be refused, not guessed. Continuous CLI QA, 2026-10-03 (round 11); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command with timeouts, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, stdin closed. Reproduced twice from fresh fixtures with a working control.

Base ledger: `option "operating_currency" "USD"`, `2026-01-01 open Assets:Checking USD`, `2026-01-01 open Expenses:Uncategorized USD`.

With `--csv date=Date,amount=Amount,narration=Description`, an amount cell `(-5.00)` or `-5.00-` previews as `5.00 USD`, exit 0. Controls: `(5.00)`, `-$5.00`, `$-5.00` give −5.00; `-(5.00)`, `--5` and `+-5` are refused.

Cause: `cli/src/bea_engine/csv_mapper.py:112–137` (`_split_amount_sign` returns both the leading sign and the parentheses/trailing-minus flag) and `:246`.

Fix/acceptance: raise `_unparseable_amount` when both `sign` and `negate` are set; both cells are refused naming the row.

---

**Resolved 2026-10-04** — CSV amounts marked negative twice, such as `(-5.00)` or `-5.00-`, are now refused naming the row instead of being booked as money in; single-marker cells are unchanged. `tests/test_csv_double_negative_amounts.py` covers it. Shipped in the commit that moved this note (`cli`).

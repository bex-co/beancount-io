# Ctrl-C ends the interactive `bea query` shell (exit 130) and loses its history

**Severity: major. Owner: cli. Estimate: 45–60m. A1:** people and agents driving a terminal expect Ctrl-C to cancel a line, as in `bean-query`. Continuous CLI QA, 2026-10-02 (round 2); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed unless a PTY is stated. Reproduced at least twice from pristine fixtures.

Ledger `2026-01-01 open Assets:Bank USD`. In a real terminal (PTY):

1. `bea --file /abs/main.bean query`
2. Type `SELECT 1 AS x LIMIT 1;` + Enter, press Ctrl-C, then type `SELECT 2 AS y LIMIT 1;`.

Actual: prints `(interrupted)` and a fresh `beanquery>` prompt, then the process exits **130** and the next input goes nowhere. Lines typed in the session never reach the beanquery history file (a session ended with `.exit` does write them). `bea query --source /abs/main.bean` behaves the same. Control: native `bean-query main.bean` with the same keys stays alive, answers `y = 2`, and `.exit` returns 0.

Expected: Ctrl-C cancels the line and the session continues — the engine docstring (`cli/src/bea_engine/query.py:357`) says Ctrl-C behaves "as they do under `bean-query` itself", and `w3/done/388` recorded this path as returning to the prompt.

Cause: `cli/src/cli/engine/launch.py:525` runs the TTY child with `subprocess.run`; the frontend shares the foreground process group, receives SIGINT, and `subprocess.run` then `kill()`s the engine after 0.25 s (so its atexit history write never runs); `cli/src/cli/main.py:159` exits 130. `cli/tests/test_interrupt_contract.py:131` (`test_the_interactive_shell_still_exits_130`) pins the broken behaviour.

Fix/acceptance: while an inherited-stdio interactive child runs (`shell` / `source-shell`, `cli/src/cli/commands/query.py:238,266`), ignore SIGINT in the parent and restore it after; still map a child that died of SIGINT to 130. PTY tests: Ctrl-C → query → `.exit` answers and exits 0 with history written; mid-computation Ctrl-C on a one-shot query still exits 130. Rewrite the pinned test.

Dedupe: related `w3/388`, `w5/010`, `w3/449` (same fix for `bea ask`); none covers this. `git log -S"(interrupted)"` → `3d233ef0`.

---

**Resolved 2026-10-03** — Ctrl-C in the interactive `bea query` shell now cancels the current line and keeps the session, as `bean-query` does: the frontend survives the signal while the shell runs, `.exit` returns 0 and saves history, and a shell killed by SIGINT still exits 130. Real-terminal tests in `tests/test_interrupt_contract.py` cover `--file` and `--source`. Shipped in the commit that moved this note (`cli`).

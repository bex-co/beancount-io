# Receipt insert's UNBALANCED hint suggests `allowInvalid`, which the tool refuses

**Bug · backend-v2 · minor · ~20m · A1.** From `/qa-find-bugs-mcp`, 2026-11-09, production `beancount-mcp 1.0.0`, unpinned read/write API key, the disposable QA ledger.

- **Repro:**
  1. Upload a temp PNG.
  2. Call `insertReceiptTransaction` with a single posting `Expenses:Food:Coffee 4.50 USD`. It is refused `UNBALANCED` "residual 4.50 USD", with the hint "add a posting or pass allowInvalid: true".
  3. Follow the hint and add `allowInvalid: true` (or `allow_invalid`). The call is refused `BAD_USER_INPUT` 'Unrecognized key: "allowInvalid"'.
  - REST `POST …/import/insert-receipt` returns 400 with the same hint.
- **Cause:** `src/shared/errors/domain-errors.ts:464` (`UnbalancedTransactionError`) hardcodes the hint. Receipt insert shares the bulk writer with `addLedgerEntries`, but only the entry, append, file and entry-source tools accept `allowInvalid`.
- **Fix:** let the writer's caller say whether `allowInvalid` is offered, or override the hint in the receipt workflow. Change REST, GraphQL and MCP together. Also check `importStagedBankTransactions`, if it can produce `UNBALANCED`.
- **Check:**
  - The receipt insert's `UNBALANCED` hint no longer mentions `allowInvalid`.
  - `addLedgerEntries` keeps its current hint.

**Addendum 2026-11-10:** the legacy GraphQL `addEntries` refusals (`UNBALANCED`, `VALIDATION_FAILED`) also hint "pass allowInvalid: true", but `addEntries` has no such argument.

---

**Resolved 2026-11-10.** Writes that offer no `allowInvalid` no longer tell the caller to pass one. These are the receipt insert (REST, GraphQL, MCP), the bank import, and the legacy `addEntries` (GraphQL and the REST twin).
- **How:** `UnbalancedTransactionError` and `NewLedgerErrorsError` each gained a `withoutAllowInvalid()` form, and `withoutAllowInvalidOffer` routes a refusal through it. Code, message, residual and `newLedgerErrors` are unchanged. Only the remedy changes: "residual 4.50 USD; add the missing posting or elide one amount", or "… Fix the entries.". Each of the three writes rethrows its refusals through that helper.
- **Unchanged:** `addLedgerEntries` and the other writes that do take `allowInvalid` keep their hint, since the default form is untouched.
- **Bank import:** its transactions are balanced by construction, so it cannot produce UNBALANCED. It can produce the new-error refusal, though, for example when the target account is not open, so it is covered too.
- **Tests:** `domain-errors.test.ts` covers both rewordings and the pass-through. `receipt-insert-parity.test.ts` checks all three surfaces, and `legacy-entry-parity.test.ts` checks REST and GraphQL for both codes. `plaid-sync-service.test.ts` covers the bank import. Reverting the call sites fails 6 cases.
- **Gate:** the full suite's only failure was `batch-processor.test.ts`, which this change does not touch. It passes 3 of 3 alone, so it is an intermittent timing failure. (`backend-v2`)

# Server-controlled `sshUrl`/`name` let `bea cloud ledger clone` run local commands and write outside cwd

**Severity: major. Owner: cli. Estimate: 30–40m. A1:** agents clone ledgers unattended; API data must never become git options or arbitrary paths. Continuous CLI QA, 2026-10-03 (round 4); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, `BEA_FILE`/`CI` unset. **Local simulation:** a Python stub at `127.0.0.1:18765` returning the OpenAPI success shapes, reached via `BEA_API_URL` and a fake `BEA_TOKEN`; it logs every request. No real service or credential was used. Reproduced twice with a working control.

In any git repository as cwd, have the stub's `GET /api-gateway/v1/ledgers/alice/x` return `name: "."` and `sshUrl: "--upload-pack=touch /abs/PWNED; git-upload-pack"`, then:

```sh
bea cloud ledger clone alice/x
```

Actual: exit 0, "Ledger 'alice/x' cloned to '…'", and `PWNED` is created. `name: "../src.git"` (an existing repo) behaves the same; `sshUrl: "--version"` shows git parsing it as an option; `name: "../escaped"` clones outside cwd with exit 0. `create --clone` shares the path.

Expected: server values are never parsed as git options nor used as paths outside cwd; clone URLs are `ssh://`, `git@host:` or `https://` only; the default directory comes from a slug-validated name. Requires a malicious/compromised API or a hostile `BEA_API_URL`.

Cause: `cli/src/cli/commands/cloud/ledger/manager.py:107` runs `["git", "clone", git_remote_url, str(target_dir)]` without `--` or URL validation; `cli/src/cli/commands/cloud/ledger/app.py:79` and `:113` use `Path.cwd() / ledger.name` from the server.

Fix/acceptance: `git clone -- <url> <dir>`; reject URLs starting with `-` or outside the allowed schemes (optionally `-c protocol.allow=…`); build the default target only from `ledger_name(ledger.name)` and treat a mismatch as an unexpected server response (exit 1). The stub cases exit nonzero, nothing executes, nothing is created outside cwd; a normal clone still works.

Dedupe: no `.pm` hit for upload-pack / argument injection / `git clone --`.

---

**Resolved 2026-10-03** — `bea cloud ledger clone` and `create --clone` now pass `--` to git, accept only `ssh://`, `https://` or scp-style clone URLs whose host cannot read as an option, and refuse a server ledger name that is not a valid ledger name, so server-controlled values can neither run local commands nor place a clone outside the working directory. `tests/test_cloud_clone_untrusted.py` covers it with a local bare-repository remote. Shipped in the commit that moved this note (`cli`).

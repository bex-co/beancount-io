# Query, balance and report JSON/CSV print tiny amounts in scientific notation (`1E-8`, `0E-8`)

**Severity: minor. Owner: cli. Estimate: 20–30m. A1:** machine output must be re-usable as bea input. Continuous CLI QA, 2026-10-02; report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`, synthetic fixtures. Reproduced twice from pristine fixtures.

```sh
printf '%s\n' '2024-01-01 open Assets:Wallet BTC' '2024-01-01 open Equity:Opening BTC' '2024-01-03 * "Faucet" "one satoshi"' '  Assets:Wallet   0.00000001 BTC' '  Equity:Opening' '2024-01-04 price BTC 0.0000001 USD' > main.bean
bea --json --file /abs/main.bean query "SELECT number, position, balance WHERE account ~ 'Wallet'"
bea --file /abs/main.bean query -f csv "SELECT number, position"
bea --json --file /abs/main.bean query "SELECT date, currency, amount FROM #prices"
bea --json --file /abs/main.bean balance
bea --json --file /abs/main.bean list transaction     # control
```

Actual: query JSON `"1E-8"` in number/position/inventory cells; CSV `1E-8,1E-8 BTC`; price `{"number":"1E-7"}`; `balance`/`report trial-balance` JSON `{"BTC":"1E-8"}`; zero sums `"0E-8"`. Control `list` prints `"0.00000001"`. Feeding the value back (`add balance --amount "1E-8 BTC"`) exits 2: "Scientific notation '1E-8' is not supported".

Expected: USAGE says JSON amounts are decimal strings; `models.py:52` already uses `format(number, "f")` so "listings remain valid bulk input" (`b4639ce6`). Query/balance/report should emit `0.00000001`, `0.0000001`, `0.00000000`. (The text-table `number` column matches native `bean-query` and is out of scope.)

Cause: `cli/src/bea_engine/protocol.py:207–208` `_jsonable` returns `str(Decimal)`; query CSV inherits it via `query.py:647–652`; frontend twin at `cli/src/cli/output.py:465–466`.

Fix/acceptance: `format(value, "f")` in both walkers; no `E` in any amount string across query JSON/CSV (one-shot, `-o`, shell), price rows, balance and report JSON. Regression test beside `test_decimal_notation.py`.

Dedupe: `.pm` search for scientific / 1E- / 0E- / exponent → input-side `w3/419`, `w3/259`, `w5/007`, `w1/done/m27`; CSV padding `w3/254`; none covers these outputs.

## Also affected (round 4, 2026-10-03)

The same `str(Decimal)` exponent form leaks through fields that bypass the `AmountNumber` serializer, and `add` then refuses the value on re-input:

```sh
bea --json --file /abs/c.bean add custom --date 2021-01-02 --type t --value number:0.00000001 --value "amount:0.00000001 USD"   # "value": "1E-8", "number": "1E-8"
bea --json --file /abs/c.bean add balance --date 2021-01-03 -a Assets:Cash --amount "0 ~ 0.00000001 USD"                         # "tolerance": "1E-8"
bea --json --file /abs/c.bean list transaction    # typed metadata n2: -0.00000001 → {"kind":"number","value":"-1E-8"}
bea --file /abs/c.bean add custom --date 2021-01-04 --type t --value number:-1E-9                                                 # exit 2, "Scientific notation ... is not supported"
```

Causes: `cli/src/bea_engine/ledger/models.py:310–317` (custom number/amount values) and `:244` (balance `tolerance`) use plain `Decimal`; `cli/src/bea_engine/ledger/reader.py:151,155` uses `str(value)` for typed metadata. Extend the fix to these fields (`AmountNumber` / `format(x, "f")`); acceptance additionally requires these outputs to print `0.00000001` and re-enter `add custom`.

---

**Resolved 2026-10-03** — query, balance, report, price and listing JSON/CSV output now print decimals in fixed-point (`0.00000001`, not `1E-8`), so values can be fed back into `bea add`. `tests/test_decimal_output_notation.py` covers each output. Shipped in the commit that moved this note (`cli`).

# `--allow-errors` treats an existing error as new when its message embeds a file path, blocking every write

**Severity: major. Owner: cli. Estimate: 30–45m. A1:** investment ledgers with a lot-matching error must still accept `--allow-errors` writes. Continuous CLI QA, 2026-10-03 (round 9); report and filing only, no fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command with timeouts, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced twice with a working control.

Header `B`: `option "operating_currency" "USD"`, `2020-01-01 open Assets:Cash USD`, `2020-01-01 open Expenses:Food USD`.

Add a FIFO `HOOL` account, buy `1 HOOL {100 USD}`, then sell `-1 HOOL {200 USD}` — `bea check` exits 1 with `No position matches "Posting(… meta={'filename': '/abs/bk.bean', 'lineno': 10})"`. Then:

```sh
bea --file /abs/bk.bean add transaction --allow-errors --date 2020-02-01 --narration food --posting 'Expenses:Food 5 USD' --posting 'Assets:Cash -5 USD'
```

Actual: exit 1 "The change would introduce 1 new ledger error(s); nothing was written." — the listed "new" error is the existing one; file byte-identical. Same with a root that includes `inc.bean` twice (existing `Duplicate filename parsed`). Control: a ledger whose only error is a failing balance accepts the same add (exit 0).

Expected: `--allow-errors` tolerates errors the ledger already had (`validate_candidate` docstring, USAGE) — exit 0, entry appended, existing error shown as a warning.

Cause: `cli/src/bea_engine/ledger/write.py:698` `_error_key` keys on the raw message; the after-load runs on staged `.bea-*.tmp` copies (`:519–520`), so path-embedding messages differ from the before-load (`:530–531`); staged paths are swapped back only for display (`:539–540`), not in the key (`:550`). Gap in `w1/done/m23/t002` (`4f4f5566`).

Fix/acceptance: apply the staged→original replacement inside `_error_key`. Both fixtures write with exit 0 and warn about the existing error; a genuinely new error is still refused. Regression tests for both.

Blast radius: every `--allow-errors` writer — all `bea add` types, `add transactions`, `import --apply`, add probe paths (`adding.py:809–843`), `ask` append.

---

**Resolved 2026-10-03** — `--allow-errors` writes now tolerate existing errors whose message embeds a file path (lot-matching errors, a file included twice): the comparison maps temporary-copy paths back to the real file, while a genuinely new error is still refused. `tests/test_allow_errors_path_embedding_messages.py` covers it. Shipped in the commit that moved this note (`cli`).

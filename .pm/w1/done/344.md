# A plugin module kept beside the ledger is reported as "Check the name is spelled right and the plugin is installed" by `bea check` and every read and write, though `bea init --existing` on the same ledger says it loads only through `PYTHONPATH=.`

**Bug · cli · minor · 30–45m · A1.** From routine cli-qa, 2026-11-20. A ledger whose `plugin "myplug"` names a `myplug.py` in the ledger's own folder (the usual layout for a personal plugin) fails every `bea` command with `Cannot import plugin "myplug": ModuleNotFoundError: No module named 'myplug'. Check the name is spelled right and the plugin is installed.` The name is spelled right and the file is right there. The fix is `option "insert_pythonpath" "TRUE"` or `PYTHONPATH=.`, and the message names neither. `bea init --existing` already detects this case. It reports `Plugin myplug is the module myplug in this folder. bea never imports from the working directory, so it loads only through PYTHONPATH.` and gives the exact command. A user or agent running `bea check` first gets the misleading hint, and may delete or rename the plugin line.

Environment: main `31c5d9d65`, `bea 0.5.0` from the checkout (`uv run bea`), Python 3.12.14, macOS 26.5.1. The run used an isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME` with `BEA_NO_UPDATE_NOTIFIER=1`, `BEA_FILE`/`BEA_TOKEN` unset, stdin closed and no TTY. The cwd was the ledger's folder. Reproduced in fresh processes. Files were unchanged.

## Repro

```sh
mkdir books && cd books
cat > main.bean <<'EOF'
option "operating_currency" "USD"
plugin "myplug"
2026-01-01 open Assets:Bank USD
EOF
cat > myplug.py <<'EOF'
__plugins__ = ["p"]
def p(entries, options_map):
    return entries, []
EOF
bea check
bea list open
bea add open --date 2026-01-02 -a Assets:Cash
bea init --existing .
```

Actual: `check` exits 1 with `main.bean:2: Cannot import plugin "myplug": ModuleNotFoundError: No module named 'myplug'. Check the name is spelled right and the plugin is installed.` `list open` exits 1 with `Ledger has 1 error(s). Pass --allow-errors to report anyway.` and the same line. `add open` exits 1 with `The ledger already has 1 error(s); nothing was written. Pass --allow-errors to write anyway.` and the same line. That last message offers `--allow-errors` as the way forward. `init --existing` exits 0 and names the folder module and `PYTHONPATH=. bea --file main.bean check`.

Controls: `PYTHONPATH=. bea check` exits 0. Adding `option "insert_pythonpath" "TRUE"` to `main.bean` makes plain `bea check` exit 0, and that is documented under `price export`. A plugin that is really missing, with no `nonexistent_plugin.py` beside the ledger, should keep today's wording.

## Expected

When an import failure's top-level module is a `NAME.py` or `NAME/__init__.py` beside the ledger file that declares the plugin, the error says so. The reason: bea does not import from the ledger's folder. The remedy names both fixes: add `option "insert_pythonpath" "TRUE"` to the ledger, or run with `PYTHONPATH=<that folder>`. It does not say to check the spelling or the installation. The rest of the line keeps its `file:line` and cause. The same wording reaches `check`, the strict read gate, write refusals and `--json` `details`/`ledger_errors`. A plugin with no module beside the ledger keeps the current hint.

## Root cause

`_plugin_message` in `cli/src/bea_engine/query.py:3711` formats every `importing` failure with the fixed "Check the name is spelled right and the plugin is installed" suffix. It never checks the plugin directive's folder. `cli/src/bea_engine/describing.py:142` (`_beside_ledger`) already answers that question for `init --existing`. `_plugin_message` already locates the directive (`plugin_directive(ledger_file, name, config)`), so it has the folder to check.

## Fix

Reuse `_beside_ledger` (or a shared helper) in `_plugin_message`. Check the folder of the file holding the `plugin` line, which may be an included file, and pick the folder-module wording for an import failure there. Add a subprocess regression test on the repro: assert the new wording for `check`, `list open` and `add open` in text and `--json` modes, and the unchanged wording for a plugin with no module beside it. Revert the fix and watch the test fail. Mention the wording in `cli/docs/USAGE.md` beside the `init --existing` plugin list.

No open item overlaps.

**Resolved 2026-11-20** — Reproduced at `bf7f2f9c7`: with `myplug.py` beside `main.bean`, `bea check`, `bea list open` and `bea add open` exited 1 with "Check the name is spelled right and the plugin is installed". `_plugin_message` in `cli/src/bea_engine/query.py` now picks the next step through `_import_hint`. When the cause is `No module named '<top>'` and the folder of the file declaring the plugin holds `<top>.py` or `<top>/__init__.py`, the line reads "The module myplug is in the ledger's folder, and bea does not import from there: add option "insert_pythonpath" "TRUE" to main.bean, or run bea with PYTHONPATH=<folder>." It keeps its `file:line` and cause in `check`, the strict read gate, write refusals, and `--json` `details` and `ledger_errors`. A plugin with no module there, and a local module whose own import is missing, keep the spelling hint. `init --existing` and the check now share one `module_beside` helper (it replaces `describing._beside_ledger`). `cli/tests/test_plugin_beside_ledger_hint.py` runs real `bea` subprocesses: `check`, `list open` and `add open` in text and `--json` mode, `--allow-errors` `ledger_errors`, a package module, both remedies loading the plugin, and the two controls. Its five new-wording tests fail with the fix reverted. `cli/docs/USAGE.md` describes the wording beside the plugin failure paragraph and the `init --existing` list. Shipped in `d80c24bac` (`cli`).

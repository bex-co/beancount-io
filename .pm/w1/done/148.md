# Without a payee column, any same-day same-amount rows are "possible duplicates" and `--duplicates skip` drops real rows

**Severity: major. Owner: cli. Estimate: 30–45m. A1:** the documented one-description CSV mapping must not lose real transactions. Continuous CLI QA, 2026-10-03 (round 11); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command with timeouts, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, stdin closed. Reproduced twice from fresh fixtures with a working control.

Base ledger: `option "operating_currency" "USD"`, `2026-01-01 open Assets:Checking USD`, `2026-01-01 open Expenses:Uncategorized USD`.

Import `a.csv` with `--account Assets:Checking --apply`:

```csv
Date,Description,Amount
2026-08-02,COFFEE SHOP,-5.00
```

then `b.csv` with `--account Assets:Checking --apply --duplicates skip`:

```csv
Date,Description,Amount
2026-08-02,COFFEE SHOP,-5.00
2026-08-02,PARKING METER,-5.00
2026-08-03,BOOKS,-12.00
```

Actual: exit 0, written 1 — PARKING METER is a `possible_duplicate` ("Date, payee and source amount match") and is never written; `check` passes. Within a single file, two different same-day −5.00 rows are flagged and a plain `--apply` exits 4. Control: mapping `payee=Description` instead marks both rows `new`.

Expected: IMPORTING.md tells users to map a single description column to `narration=`; the possible-duplicate rule is date + normalized payee + amount — with no payee it must not collapse to date + amount.

Cause: `cli/src/bea_engine/importing.py:723–725` (`_candidate_key` drops narration), fed by `_fingerprint` (`:486–491`), used at `:286–291`.

Fix/acceptance: when the payee is empty, use the normalized narration in the candidate key. Both repros yield `new` rows; possible-duplicate behaviour for rows with payees unchanged.

Blast radius: every header-inferred CSV with one Description/Memo column — the documented default.

---

**Resolved 2026-10-04** — a CSV row without a payee is now a possible duplicate only when its narration also matches, so `--duplicates skip` no longer drops different same-day, same-amount purchases. `tests/test_import_possible_duplicate_without_payee.py` covers it; the import skill's `dedup.md` is updated. Shipped in the commit that moved this note (`cli`).

# The managed-price 5-second fetch limit is per socket read, so a slow server stalls every command

**Severity: minor. Owner: cli. Estimate: ~20m. A1:** a slow price host must not hang agents' ledger reads. Continuous CLI QA, 2026-10-03 (round 3); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1 (Beancount 3.2.3, beanquery 0.2.0), Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control.

Managed-price cases are **local simulations**: a threaded `http.server` stub on `127.0.0.1:8765`, enabled with `MANAGED_PRICE_ORIGINS=http://127.0.0.1:8765` and the ledger line `include "http://127.0.0.1:8765/prices/BTC-USD"`. Base fixture: open `Assets:Bank USD`, `Assets:Crypto BTC`, `Equity:Opening`; fund 10000 USD; buy `1 BTC {5000 USD}`; then the include.

Stub sends `200` + headers, then 8 bytes/second of a valid 116-byte feed. `bea --strict-prices --file /abs/main.bean check` exits 0 after **14.3 s** (twice); at 4 bytes/second, `price refresh` and plain `check` take ~28.4 s. Control: delaying the headers by 8 s correctly fails in 5.4 s with `fetch failed (timeout): timed out after 5 seconds`.

Expected: ADR018 §1 promises a 5-second timeout; `cli/src/bea_engine/managed_prices.py:41` calls it "the whole-exchange fetch budget". Worst case today is ~1 MiB × just under 5 s per read.

Cause: `managed_prices.py:266` passes a per-operation socket `timeout=`; the read loop (`:200–207`) has no overall deadline.

Fix/acceptance: enforce a `time.monotonic()` deadline in `_read_capped` → `FetchFailed("timeout")`. The drip scenario finishes in ≤ 6 s with the last good revision serving.

Dedupe: no `.pm` hit for drip / whole-exchange / socket timeout.

---

**Resolved 2026-10-03** — the managed-price 5-second fetch limit now covers the whole exchange, reading the body in pieces against one deadline, so a slow-dripping server no longer stalls every command. A test in `tests/test_price.py` covers it. Shipped in the commit that moved this note (`cli`).

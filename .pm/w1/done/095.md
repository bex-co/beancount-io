# After an approved `ask` write, a failed turn claims "nothing was written to your ledger" and forgets the write

**Severity: major. Owner: cli. Estimate: 1.5–2.5h (may warrant promotion). A1:** an agent or user told nothing was written will retry and duplicate the entry. Continuous CLI QA, 2026-10-03 (round 4); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled. **Local simulation:** a fake OpenAI-compatible model server on `127.0.0.1`, reached via `BEA_API_URL` and a fake `BEA_TOKEN`; no hosted AI service was used. Reproduced twice with a working control.

Fixture `main.bean`: `option "operating_currency" "USD"`; open `Assets:Checking`, `Expenses:Food`, `Equity:Opening` (USD); one opening transaction.

In a PTY: `bea --file /abs/main.bean ask`. The model calls `write_directive` with `2024-03-01 * "Stub" "AI write"` / `Assets:Checking -5 USD` / `Expenses:Food 5 USD`; approve with Enter on "1. Yes". The model's next reply is one of: (a) endless `run_bql_query` calls, (b) HTTP 429 `{"error":{"code":"QUOTA_EXCEEDED",…}}`, (c) tool arguments that are not valid JSON, (d) HTTP 500.

Actual: the directive **is** in the ledger in every variant, yet the session prints "…stopped at this question's budget…; nothing was written to your ledger." / "This account's hosted AI quota is used up… nothing was written to your ledger." / "…(UnexpectedModelBehavior); nothing was written to your ledger."; a 500 prints "Server error (upstream boom)." The next turn's request carries no record of the "Added 1 directive(s)" tool result, so the model doesn't know the entry exists. Ctrl-C after the write behaves the same ("(cancelled)", turn dropped). Control: in `--print` (writes impossible) the sentence is true.

Expected: failure messages state what actually happened ("1 directive was written to main.bean before this failed"), per the "each statement is true as written" contract from `w3/m50` and USAGE's exit honesty; approved writes stay in the conversation.

Cause: hard-coded claims at `cli/src/cli/ask/agent.py:186–197` and `:241` (written for `--print`); `cli/src/cli/ask/repl.py:264–281` discards the turn's messages on any failure or cancel, and `messages = list(result.all_messages())` (`:282`) runs only on success.

Fix/acceptance: `write_directive` records successful writes (count, target) on `BqlDeps`, reset per turn; `translated_failures` says "nothing was written" only when the count is zero and otherwise names the write; a failed or cancelled turn after a write keeps its partial messages (or a synthetic note). Regression tests: write followed by usage limit, quota, `AgentRunError`, 5xx and Ctrl-C each name the write and the next request carries it. If this exceeds an hour, promote to a milestone.

Dedupe: `w3/454` and `w3/m50` t005/t006 introduced these messages and per-turn recovery with `--print` in mind; no filing covers write-then-fail.

---

**Resolved 2026-10-04** — after an approved write, a failed or cancelled `bea ask` turn now names what it wrote instead of claiming nothing was written, and the conversation keeps that turn so the assistant knows the entry exists. `tests/test_ask_write_then_fail.py` covers each failure type and Ctrl-C. Shipped in the commit that moved this note (`cli`).

## Objective

Put the welcome screen's sign-up intent on the wire so the server can act on it.

## Context

- `mobile/src/screens/welcome/index.tsx` calls `start("sign_in")` / `start("sign_up")`; the flow is stored on the pending record (`mobile/src/common/oauth/authorization-result.ts`) and validated on rehydration, but `buildAuthorizationUrl` in `mobile/src/common/oauth/authorization-url.ts` never reads `pending.flow`.
- `authorization-launcher.test.ts` asserts the exact parameter set; there is no `authorization-url.test.ts`.

## Steps

1. In `buildAuthorizationUrl`, append `screen_hint=signup` when `pending.flow === "sign_up"`; emit nothing extra for `sign_in`.
2. Add `mobile/src/common/oauth/__tests__/authorization-url.test.ts` asserting both cases and that the rest of the parameter set is unchanged.
3. Update the launcher test's exact-params assertion if it enumerates keys.

## Files

## Acceptance criteria

- [x] A sign-up launch produces an authorization URL containing exactly one `screen_hint=signup`; a sign-in launch contains no `screen_hint`.
- [x] Discovery, PKCE, state, resource, and `prompt=consent` handling are untouched.
- [x] `yarn test:unit` passes from `mobile/`.

## Objective

Let the native client tell the authorization server that the user intends to register, and carry that intent to the interaction page, so the dashboard can open on the right step.

## Context

- `oidc-provider` drops unknown authorization parameters unless they are whitelisted through `extraParams`; the provider in `backend-cluster/backend-v2/src/features/oauth/api/oidc-route.ts` configures none today (library default `extraParams: []`).
- `interactions.url` (`oidc-route.ts`, the `isMobileClient` branch) appends only `uid` and `scope` to `/oauth/mobile-consent`.
- Auth0's `screen_hint=signup` is the widely recognised spelling for this hint; a custom OIDC `prompt=create` value would require extending the interaction policy and is not worth it for one first-party client.

## Steps

1. Add `screen_hint` to the provider's `extraParams` so oidc-provider stops discarding it; do not validate the value — it is a display hint, and rejecting unknown values would break an app newer than a self-hosted server.
2. In `interactions.url`, forward `screen_hint=signup` on the mobile interaction redirect when present; ignore it for non-mobile clients.
3. Extend `oidc-route.test.ts`: a mobile authorization with `screen_hint=signup` redirects to `/oauth/mobile-consent?uid=…&scope=…&screen_hint=signup`; one without it omits the parameter; an unknown value is dropped and the login form is reached.

## Objective

Simplify the welcome screen: no sentence about browsers, a failure line that matches the button the user tapped, and no leftover strings from the retired embedded login.

## Context

- `mobile/src/screens/welcome/index.tsx` renders `t("signInOpensBrowser")` under both buttons and `t("signInFailed")` on any failure, including a failed sign-up.
- `signInOpensBrowser` exists in all 13 locale files under `mobile/src/translations/`.
- Ten legacy keys are referenced by nothing outside `translations/`: `email`, `password`, `forgotPassword`, `dontHaveAccount`, `confirmPassword`, `alreadyHaveAccount`, `resetPassword`, `resetPasswordDescription`, `resetPasswordEmailSent`, `sendResetPasswordEmail`. `backToSignIn` stays (used by `app/oauth/callback.tsx`).
- `useNativeSignIn` (`mobile/src/screens/welcome/use-native-sign-in.ts`) has no unit test.

## Steps

1. Remove the explainer line and the `signInOpensBrowser` key from every locale.
2. Add `signUpFailed` (English base, translated in the other locales) and show it when `pendingFlow` was `sign_up`.
3. Delete the ten dead keys from every locale; confirm with a grep that nothing references them.
4. Add a unit test for `useNativeSignIn` covering single-flight, cancel-is-not-failure, and which flow the failure state reports.

## Files

- `mobile/src/screens/welcome/index.tsx`
- `mobile/src/screens/welcome/use-native-sign-in.ts`

## Acceptance criteria

- [x] `grep -r signInOpensBrowser mobile/src` returns nothing; the welcome screen renders only the two buttons, the server icon, and (on failure) one flow-specific line.
- [x] The ten legacy keys are absent from all 13 locale files and `yarn typecheck` passes.
- [x] Light and dark screenshots of the welcome screen show no layout regression.
- [x] `yarn test` passes from `mobile/`.

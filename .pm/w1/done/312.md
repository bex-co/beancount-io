# `bea add close` under `close_tree` names only the first funded account it would close, and a funded parent's refusal says `--force` closes "it with the balance" while it also closes every funded child

**Bug · cli · minor · ~45m · A1.** From routine cli-qa, 2026-11-19. With `plugin "beancount.plugins.close_tree"`, closing a parent also closes its open descendants. `bea add close` refuses an unforced close that would strand money (w2/092, w5/910). But the refusal stops at the first funded account it finds:

- Two funded children: the refusal names only the first. The user drains it, retries, and only then learns about the second.
- A parent with its own balance: the refusal names only the parent's amount and offers "pass --force to close **it** with the balance". `--force` then closes the parent and every funded child. The children's balances were never shown, and the forced write reports `warnings: []`. A later posting that would move the children's money out is refused as an inactive account.

The w5/910 resolution recorded "Multiple funded descendants report the first only" as a known limit, but no item tracks it. The import twin, `_funded_close_advisories` (`cli/src/bea_engine/importing.py:1112`), already lists every account the batch closes with money in it. So does `add close` on a single account holding several currencies (`still holds 50 EUR, 100 USD`).

Environment: main `e4fbb81b7` (CLI unchanged since `c6cd93204`), `bea 0.4.1` from the checkout (`uv run bea`), macOS 26.5.1. Fresh process per command, stdin closed, no TTY, isolated `BEA_CONFIG_DIR` and `XDG_CACHE_HOME`, notifier off, no `BEA_FILE`/`BEA_TOKEN`. Each case reproduced from a pristine copy, and the ledger hash was unchanged after each refusal.

## Repro

`main.bean` (`bea check` exits 0):

```beancount
option "operating_currency" "USD"
plugin "beancount.plugins.close_tree"
2025-01-01 open Assets:Bank USD
2025-01-01 open Assets:Bank:Checking USD
2025-01-01 open Assets:Bank:Savings USD
2025-01-01 open Equity:Open USD
2025-01-02 * "fund"
  Assets:Bank 10 USD
  Assets:Bank:Checking 100 USD
  Assets:Bank:Savings 50 USD
  Equity:Open
```

```sh
bea --json --file /abs/main.bean add close --date 2025-03-01 -a Assets:Bank
```

**Actual:** exit 1, `Assets:Bank still holds 10 USD on 2025-03-01. Move that balance out of Assets:Bank with a transaction dated on or before 2025-03-01, then close it, or pass --force to close it with the balance. Nothing was written.` Checking and Savings are not mentioned.

Following the advice with `--force` exits 0 with `written: 1, warnings: []`. `bea list close` then shows all three accounts closed on 2025-03-01, two of them `generated`. `bea balance Bank` still shows 160 USD. `bea add transaction "move" --date 2025-03-02 -p 'Assets:Bank:Savings -50 USD' -p Equity:Open` is refused: `Invalid reference to inactive account 'Assets:Bank:Savings' … closed 2025-03-01 by plugin beancount.plugins.close_tree`.

**Variant:** drop the parent's own `Assets:Bank 10 USD` leg (the parent is empty). The refusal names only `Assets:Bank:Checking still holds 100 USD … pass --force to close them with the balance`. After a transaction drains Checking, the same `add close` is refused again, this time naming `Assets:Bank:Savings still holds 50 USD`.

**Control:** without `close_tree`, the same parent close names the parent's balance alone and closes no children. One account holding `100 USD` and `50 EUR` is refused with both amounts in one message.

## Root cause

`_close`'s `judge` (`cli/src/bea_engine/ledger/adding.py:517-526`) walks the requested account and then each descendant whose close the write adds or moves earlier (`_moved_closes`). It raises the first `_funded_close_refusal` it gets (`raise refusal`). `_funded_close_refusal` (`:465`) words its `--force` remedy from that one account. It says "it" whenever the funded account is the requested one, even when funded descendants would close with it.

## Do

Judge every account the write would close, and collect the refusals before raising one `LedgerError`. That error names each funded account with its amounts or stranded lots, and says which ones `close_tree` closes with the requested account. The `--force` remedy then counts all of them ("pass --force to close all three with their balances"). Keep the rest as it is: a single funded account's wording, `check_drained` coverage, stranded-lot wording (w5/909, w5/982), already-closed accounts (w1/293), and regenerated dates (w5/1062). Optional: a forced close that strands balances in descendants could list them under `warnings`, as the import path does.

# Every write and import preview leaves another full copy of each managed price feed in the cache

**Severity: minor. Owner: cli. Estimate: ~30m. A1:** cache growth must stay bounded for long-running agent sessions. Continuous CLI QA, 2026-10-03 (round 3); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1 (Beancount 3.2.3, beanquery 0.2.0), Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control.

Managed-price cases are **local simulations**: a threaded `http.server` stub on `127.0.0.1:8765`, enabled with `MANAGED_PRICE_ORIGINS=http://127.0.0.1:8765` and the ledger line `include "http://127.0.0.1:8765/prices/BTC-USD"`. Base fixture: open `Assets:Bank USD`, `Assets:Crypto BTC`, `Equity:Opening`; fund 10000 USD; buy `1 BTC {5000 USD}`; then the include.

After a refresh, three `check` runs leave **1** `*.effective.*` file; three `add note` writes then leave **4**. Three `add price`, two `import` previews and two `add transaction` produced 8. Each copy is up to 1 MiB per feed, while the ETag never changes.

Expected: ADR018 §5 — the effective text is "written once per (revision, ledger)".

Cause: `cli/src/bea_engine/managed_load.py:252` keys the file on `entry.resolve()`; write validation (`ledger/write.py:513`, `:520` via `snapshot.staged`/`candidate_file`, `write.py:151,280`) passes a random `.bea-<hex>.tmp` path, so every write gets a new key; cleanup happens only on a revision change (`managed_price_cache.py:272`).

Fix/acceptance: key on the snapshot's original root, or keep staged loads' effective text in a temp file removed afterwards. N writes leave exactly one effective file per ledger.

Dedupe: [074](./074.md) and `w3/390` concern staging/picklecache files beside the ledger, not this cache.

---

**Resolved 2026-10-03** — loads of temporary write candidates now stage the effective managed-price text for that load only, so writes and import previews no longer leave extra feed copies in the cache. Tests in `tests/test_price.py` cover it. Shipped in the commit that moved this note (`cli`).

# A corrupt remembered-CSV record makes every later `import` for that ledger fail with a raw `TypeError`

**Severity: minor. Owner: cli. Estimate: ~20m. A1:** stale local state must not block imports. Continuous CLI QA, 2026-10-03 (round 5); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control.

Write `{"sources": 5}` (or `{"sources":[{"headers":[1,2],"account":"Assets:Bank","mapping":"x"}]}`) to `$BEA_CONFIG_DIR/importers/csv-<sha256(realpath ledger)>.json`, then:

```sh
bea --file /abs/main.bean import /abs/bank.csv --csv date=Date,amount=Amount,narration=Description --account Assets:Bank --default-account Expenses:Misc --apply
```

Actual: exit 1 `Error: 'int' object is not iterable` (or `sequence item 0: expected str instance, int found`; JSON `validation`), even with an explicit `--csv`; nothing written; the message never names the file. Controls: `{"sources":"abc"}`, garbage JSON, or no record import fine.

Expected: `_recall_csv`'s docstring — "a corrupt record reads as no memory rather than a crash".

Cause: `cli/src/cli/commands/import_.py:152` (`_find_csv_entry`) iterates `sources` without type checks, catching only `ValueError`/`AttributeError`; `header_signature` (`csv_mapper.py:503`) joins non-string headers; same pattern at `:183` (`_recall_csv`) and in `_remember_csv` (catches only `OSError`).

Fix/acceptance: treat non-list `sources`, non-dict entries or non-`list[str]` headers as no memory in all three. Both corrupt records import with exit 0 and the record is rewritten.

Dedupe: `w3/425`, `w3/279`, `w1/done/m24/t007` cover other memory issues.

---

**Resolved 2026-10-04** — a corrupt remembered-CSV record now reads as no memory and is rewritten on the next successful import instead of failing every later import with a raw `TypeError`. Tests in `tests/test_import_memory_commit.py` cover five corrupt shapes. Shipped in the commit that moved this note (`cli`).

# A managed price include moves every report's start to the feed's first quote: a ledger that begins in 2026 reports "2021-09-30 through …" and opens its series with 52 zero months

**Source:** routine cli-qa, 2026-11-19. **Severity:** minor. **Estimate:** 30–45 minutes. **Owner:** cli. **A1:** the one-line `include "https://beancount.io/prices/BTC-USD"` is sold as "values a holding at market in every command". It also changes what every report says it covers. The feed backfills about five years of quotes (monthly before the last year), and the report period starts at the first dated fact, so a ledger whose first entry is 2026-01-02 gets `Balance Sheet — 2021-09-30 through 2026-11-19` and a monthly net-worth series that starts with 52 rows of `0.00 USD`. The totals are right; the heading, `period`, and every interval series describe years the ledger never had. The user did not write those quotes: `bea list price` already marks them `generated`, and `--on-disk` drops them.

Found at `7f48e0e1f` with the checkout's `uv run bea` 0.4.1, macOS 26.5.1, Python 3.12.14, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, stdin closed, stdout piped, synthetic ledger, signed in through `BEA_TOKEN` (the feed needs a login). Read-only commands; the ledger file was unchanged. The EUR-USD feed gives the same 2021-09-30 start on a ledger that begins in 2025-06.

## Repro

```sh
cat > main.bean <<'EOF'
option "operating_currency" "USD"
include "https://beancount.io/prices/BTC-USD"
2026-01-01 open Assets:Bank USD
2026-01-01 open Assets:Crypto BTC
2026-01-01 open Equity:Opening-Balances USD

2026-01-02 * "Opening"
  Assets:Bank  10000.00 USD
  Equity:Opening-Balances

2026-02-01 * "Buy BTC"
  Assets:Crypto  0.1 BTC {80000.00 USD}
  Assets:Bank   -8000.00 USD
EOF
bea --file main.bean check                                   # exit 0
bea --file main.bean report balance-sheet
bea --json --file main.bean report income-statement
```

Control: the same ledger without the include line, plus two local quotes (`2026-02-01 price BTC 80000.00 USD`, `2026-11-19 price BTC 61930.75 USD`).

## Actual

`report balance-sheet` exits 0 and prints `Balance Sheet — 2021-09-30 through 2026-11-19`; its `Monthly net worth` table runs from `2021-09-30` to `2025-12-31` at `0.00 USD` (52 rows) before the first real month, 85 lines in all. `report income-statement --json` has `"period": {"start": "2021-09-30", "end_exclusive": "2026-11-20"}` and 63 `periods`, the first `{"date": "2021-09-30", "income": {"USD": "0"}, …}`. Every report and `bea balance` take the same start (`report holdings` reads `Holdings — 2021-09-30 through 2026-11-19`).

The control prints `Balance Sheet — 2026-01-02 through 2026-11-19`, 11 monthly rows, 33 lines.

## Expected

The period starts at the ledger's own first dated fact (`2026-01-02` here). A managed feed's quotes value holdings; they are not ledger activity, the same reason `custom` and `query` placeholders stopped bounding the period in w5/193. The end may keep reaching the feed's latest quote, as it does now, so a report still values holdings at the newest market price with no new entry. A `--time` filter is unaffected. After `bea price export` the quotes are an ordinary local file the user keeps, and they bound the period like any written `price` (w3/349), so the exported ledger's heading may differ. Say that in `cli/docs/USAGE.md` beside "One line values a holding at market in every command". If the ledger has no dated fact of its own, fall back to the feed's dates as today.

## Root cause

`cli/src/fava/ledger.py` `FilteredLedger.__init__` (around lines 212–220) takes the first and last entry that is not one of `PERIOD_DECLARATIONS` (`Open | Close | Commodity | Custom | Query`, line 40). A managed feed's `Price` entries are in `ledger.all_entries`, so the first of them, 2021-09-30, becomes `_date_first`. `bea_engine/report.py` `_metadata` (around line 2205) reads `period` from there, and `interval_ranges` cuts every series from the same bounds. Entries whose `filename` sits in the managed price cache are already recognized by `bea_engine/ledger/reader.py` `_in_managed_cache` (around line 126), which `list` uses to mark them `generated`.

## Fix

When choosing `_date_first`, skip a `Price` whose source is a managed feed's cached revision (the `_in_managed_cache` test), unless every other dated fact is skipped too. Leave `_date_last` as it is. Add a regression test that loads a ledger with a managed feed served from a seeded cache or a stubbed fetch: the balance sheet's `period.start` is the first ledger entry, and its net-worth series has no point before it. Keep a control where a written `price` before the first transaction still starts the period (w3/349). Run `make check-all` in `cli/`.

## Dedupe

Searched `.pm/**` for `2021-09-30`, `stretch`, `zero rows`, `flood`, `period` with `managed`/`feed`, `first price`, `get_min_max_dates`. w5/193 fixed the same symptom for placeholder-dated `custom` and `query` directives. w3/349 made notes, balances, documents, prices and pads bound the period, and did not consider a feed's synthesized quotes. w2/027 and w2/m31 built the managed includes. No item covers a feed moving the period. Not deployment lag: the bounds on `main` are unchanged since w5/193 (`5433d42c8`). Hosted reports for a ledger with a managed include were not checked.

---

**Resolved 2026-11-19** — A managed feed's quotes no longer start the report period. When it picks the first day, `FilteredLedger` (`cli/src/fava/ledger.py`) skips a `price` read from a feed's cached revision, using the same test `list` uses to mark feed rows `generated`. The repro now reads `Balance Sheet — 2026-01-02 through 2026-11-19` with 11 monthly rows, and `--json` gives `period` `{"start": "2026-01-02", "end_exclusive": "2026-11-20"}` in overview, income statement, balance sheet, trial balance (`bea balance`) and holdings, with no series point before 2026-01-02. The end still reaches the feed's newest quote. A written `price` before the first transaction still starts the period (w3/349). An account filter keeps the ledger's own start, and a `--time` filter is unchanged. A ledger with no dated fact of its own falls back to the feed's first quote. A `bea price export` snapshot bounds the period like any written price. `cli/docs/USAGE.md` says so beside the managed include. Hosted charts needed no change: `backend-cluster/ledger/src/foundation/rustledger/interval-series.ts` already starts the span at the first transaction. Covered by `cli/tests/test_report_period_managed_feed.py`, which uses a stubbed feed server. With the fix reverted, 12 of its 15 tests fail; the fallback, `--time` and export controls pass either way. `make check-all` passes. Shipped in `4626cd3c2` (`cli`).

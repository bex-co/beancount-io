# A read-only included directory blocks every write with a raw `Errno 13` reported as a validation error

**Severity: minor. Owner: cli. Estimate: ~1h (may warrant promotion). A1:** shared read-only charts of accounts are a common layout. Continuous CLI QA, 2026-10-02 (round 2); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed unless a PTY is stated. Reproduced at least twice from pristine fixtures.

```sh
mkdir -p books/shared
printf 'include "shared/accounts.bean"\n2020-02-01 * "Lunch"\n  Expenses:Food 10 USD\n  Assets:Cash\n' > books/main.bean
printf 'option "operating_currency" "USD"\n2020-01-01 open Assets:Cash USD\n2020-01-01 open Expenses:Food USD\n' > books/shared/accounts.bean
chmod 555 books/shared
bea --file /abs/books/main.bean add note --date 2020-03-01 --account Assets:Cash --comment x
```

Actual: exit **1**, `Error: [Errno 13] Permission denied: '…/shared/.bea-<hex>.tmp'` (JSON `category: validation`). `check`/`list` exit 0. Bulk `add transactions --into w/2020.bean` fails the same way; a read-only root directory with a writable `--into` subdirectory also fails with a raw Errno. Control: `shared/` at 755 exits 0.

Expected: the write succeeds — only `main.bean` changes and it and its directory are writable. USAGE says writes are refused only when the destination is read-only (exit 3) and "a read-only root can still validate a writable `--into` file". When staging truly cannot proceed, the failure is exit 3 naming the directory.

Cause: `cli/src/bea_engine/ledger/write.py:151` — `LedgerSnapshot.staged` creates a `.bea-*.tmp` copy beside every file in the include graph; `candidate_file` (`write.py:273–282`) raises a bare `PermissionError` → exit 1. Design from `790791ac`.

Fix/acceptance: stage only the destination and the files that (transitively) include it, pointing rewritten includes at unchanged files by absolute path; map remaining staging `PermissionError` to exit 3 naming the directory. The repro exits 0 appending exactly one note; a read-only ancestor gives exit 3 with a clear message. Regression tests for both. If this exceeds an hour, promote to a milestone (narrow staging; error mapping).

Blast radius: every staged writer — `bea add *`, `add transactions`, `import --apply`, the `ask` append.

Dedupe: `.pm` hits for Permission denied / read-only (`w3/390`, `417`, `426`, `440`) concern other paths.

## Second trigger (round 5, 2026-10-03)

The same raw `[Errno 13]` / `category: validation` / exit 1 appears when the **final replace** is denied rather than staging: a root ledger with `chmod +a 'everyone deny delete' main.bean` makes every add fail with `Permission denied: '.bea-….tmp' -> 'main.bean'` from `os.replace` at `cli/src/bea_engine/ledger/write.py:843` (no staging file left behind); the catch-all at `cli/src/bea_engine/protocol.py:111` labels it `validation`. The error mapping in this fix must also cover a `PermissionError` from `replace_checked` (exit 3, naming the file).

---

**Resolved 2026-10-04** — writes now stage only the destination and the files that include it, so a read-only shared include directory no longer blocks every write, and any remaining staging or replace refusal exits 3 naming the path instead of a raw `Errno 13` reported as validation. `tests/test_write_readonly_includes.py` covers it. Shipped in the commit that moved this note (`cli`).

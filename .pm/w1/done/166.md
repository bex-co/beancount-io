# `bea format -` with non-UTF-8 stdin leaks a raw "can't encode … surrogates" error instead of the decode error

**Severity: minor. Owner: cli. Estimate: 15–20m. A1:** piped input errors must name the input and the fix. Continuous CLI QA, 2026-10-03 (round 15); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command with timeouts, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`. Reproduced twice with a working control.

`bad.bean` = `2026-01-01 open Assets:A USD\n; caf\xff\n`:

```sh
bea format - < bad.bean
bea format - --output o.bean < bad.bean
bea --json format - --output o.bean < bad.bean
```

Actual: exit 1 `Error: 'utf-8' codec can't encode character '\udcff' in position 34: surrogates not allowed` (JSON `category: validation`) — says "encode" for a decode problem, doesn't name stdin, no re-save hint. Controls: `bea format bad.bean` gives "Cannot decode '…/bad.bean' as UTF-8: invalid start byte at byte 34. Re-save…"; a UTF-8 stdin works.

Cause: `cli/src/cli/commands/format.py:470` (`_render`) passes `stdin=sys.stdin.read()` (surrogateescape lets the byte through as `\udcff`) to `launch.helper_json`, where encoding fails; the decode check from `1f380fe7` (`_text`, `format.py:310–318`) runs only for named files (`w4/done/168` left stdin unverified).

Fix/acceptance: read `sys.stdin.buffer` and decode `utf-8-sig` through `decode_error_message`. All three commands show the structured decode error naming stdin; JSON is a single envelope without raw codec text; `--output` creates nothing; UTF-8 stdin still works. Same class as [112](./112.md) (`add transactions --from -`), different code path.

---

**Resolved 2026-10-04** — `bea format -` now reports non-UTF-8 piped input as a decode error naming stdin and the byte offset, and creates no output file. `tests/test_format_stdin_decode.py` covers it. Shipped in the commit that moved this note (`cli`).

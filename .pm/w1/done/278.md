# `bea add transaction` writes a posting priced or costed in its own currency (`10 USD @ 2 USD`, `10 USD {2 USD}`) with exit 0, so a 10 USD lunch takes 20 USD from the bank and the books stop summing to zero

Found by `/qa-find-bugs-cli w1` on 2026-11-17 (HEAD `8b842a344`, `bea 0.4.1`, macOS 26.5.1, checkout `uv run bea`, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`). Severity: minor (silent wrong books from one typo). A1: an agent that types the account's currency where it meant a foreign one (`10 USD @ 1.1 USD` for `10 EUR @ 1.1 USD`) gets exit 0 and a passing `bea check`, and nothing later says the books are wrong.

**Repro** (a fresh directory):

```sh
cat > main.bean <<'EOF'
option "operating_currency" "USD"
2026-01-01 open Assets:Bank USD
2026-01-01 open Expenses:Food
2026-01-01 open Equity:Opening
2026-01-02 * "open"
  Assets:Bank 1000 USD
  Equity:Opening
EOF
bea --file "$PWD/main.bean" add transaction "Lunch" --date 2026-02-01 -p 'Expenses:Food 10 USD @ 2 USD' -p 'Assets:Bank'   # exit 0
bea --file "$PWD/main.bean" check                                  # exit 0
bea --file "$PWD/main.bean" report trial-balance -x units          # Bank 980, Opening -1,000, Food 10: sums to -10 USD
bea --file "$PWD/main.bean" query "SELECT sum(position)"           # -10 USD
bea --file "$PWD/main.bean" report balance-sheet                   # "Valuation/translation adjustment (credit): 10 USD" plugs the hole
```

Repeated from a pristine fixture in a fresh process: same result. The same holds for `@@ 20 USD`, for a cost `10 USD {2 USD}`, with an explicit `Assets:Bank -20 USD` leg, and for a bulk `add transactions` row (`"amount":"10 USD","price":{"number":"2","currency":"USD"}` and the matching `cost`). With `plugin "beancount.plugins.implicit_prices"` the write also produces a generated `price USD 2 USD`, the self-quote w1/277 now refuses on `add price`.

**Expected.** A posting whose cost or price currency equals its own units currency is refused before anything is written, exit **2**, naming the posting, and the file stays byte-identical. w5/098 already gave the reason ("A commodity held at a cost in itself, or priced in itself, is never what was meant"), and w1/277 refuses the same shape for a price directive. The hint can follow w1/276: drop the price or cost, or name the commodity that was really bought (`'Expenses:Food 10 EUR @ 2 USD'`). Do the same for `@ 1 USD`: it changes nothing, but implicit_prices still turns it into a self-quote.

**Actual.** Exit 0. Beancount balances the transaction by weight (10 × 2 = 20 USD), so it accepts it, but the units do not balance. The account's inventory gains 10 USD while 20 USD leaves the bank.

**Root cause.** `cli/src/bea_engine/ledger/adding.py`, in the posting normalization loop (about lines 1359–1405), checks for a self-rate only when the units commodity was *defaulted* (w5/098, w5/800: `rate_currencies … == choices[0]`). A posting whose units currency is typed out is never compared with its own `posting.cost.currency` / `posting.price.currency`. The bulk path builds the same postings and has the same gap.

**Fix.** After the units currency is settled (typed or defaulted), refuse any posting whose `cost` or `price` currency equals `units.currency`, as a `UsageError` (exit 2, `--json` usage envelope, per row for bulk). Put the check in the engine's transaction write so `add transaction`, `add transactions`, `ask`'s approved proposals and configured-importer rows through `bea import` all get it. Document the rule beside the w5/098 paragraph in `cli/docs/USAGE.md` (Adding directives). Local only; hosted writes validate in the server engine and are out of scope for this note.

**Acceptance.** The repro's add exits 2, names `--posting 1`, and leaves `main.bean` byte-identical. `@@`, `{2 USD}`, `@ 1 USD` and the bulk row are refused the same way. Controls are still written: `10 EUR @ 1.1 USD`, `5 ABC {10 USD}`, and a plain `10 USD`. Regression tests fail with the fix reverted, and `make check-all` passes.

**Dedupe.** Searched `.pm/**` for `in itself`, `self-quote`, `self-price`, `USD @ … USD` and `USD {… USD}`. w5/098 and w5/800 (done) cover only a *missing* commodity defaulted into the rate's currency. w1/277 (done) covers `price` directives. w1/276 (done) only stopped a hint from suggesting `USD @ RATE USD`, and its record notes that Beancount accepts such a self-price. No open item covers an explicitly typed self-rate. Estimate 30–45m.

---

**Resolved 2026-11-17** — `self_rate_tail` (`cli/src/bea_engine/managed_load.py`) is checked on every posting of the engine's transaction write after the units commodity is settled, typed or defaulted (`_transaction` in `cli/src/bea_engine/ledger/adding.py`). The repro's add now exits 2 with `--posting 1 is priced in its own commodity USD … Nothing was written.` (the `--json` usage envelope carries the same message), and `main.bean` stays byte-identical; `@@ 20 USD`, `{2 USD}`, `{2 USD} @ 2 USD`, `@ 1 USD` and an explicit `Assets:Bank -20 USD` leg are refused the same way. Bulk `add transactions` rows are refused per row by the posting model's write validation (`cli/src/bea_engine/ledger/models.py`), `bea ask` proposals by the engine's raw-text append (`cli/src/bea_engine/ledger/appending.py`), and a configured importer's row is marked `invalid`, `--apply` refusing with exit 1 naming the row (`cli/src/bea_engine/importing.py`). Controls `10 EUR @ 1.1 USD`, `5 ABC {10 USD}` and a plain `10 USD` are still written. Rule documented beside the w5/098 paragraph in `cli/docs/USAGE.md`. Regressions in `cli/tests/test_add_transaction_refuses_self_rate.py`, ten of which fail with the fix reverted; `make check-all` passes. Shipped in `50efcb7e4` (`cli`).

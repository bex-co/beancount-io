# Hosted holdings still part from `bea report holdings` on zero quotes, zero-unit groups, and which quote a merged group keeps

Follow-up from [290](./done/290.md) (shipped in `5a9a9129d`, 2026-11-18). The 290 worker found these while porting the direct-quote rule; nobody has reproduced them against `bea` side by side yet. A1: an agent that reads holdings over MCP and one that runs `bea` against the same ledger should get the same positions and values.

backend-v2's holdings composer (`holdings.ts`, the code under REST, GraphQL and MCP) still differs from the CLI in three ways:
- it drops a quote whose price is zero;
- it drops a group whose units net to zero;
- a merged group keeps the first part's quote rather than the latest one.

**Do:** for each difference, build a small synthetic ledger and compare `bea report holdings` with hosted holdings. If the CLI's behaviour is the documented one, move the composer to it and add a backend-v2 test that fails without the change, keeping the parity gate green. If a difference is deliberate, write down why in the composer and close it. Close the note when every difference is either fixed or explained.

---

**Resolved 2026-11-19** — Reproduced all three side by side: the engine's rows for synthetic ledgers fed through backend-v2's composer, against `bea report holdings` on the same files. A delisted share quoted at 40 USD then 0 USD was worth 400 USD hosted and 0 USD in `bea` (and at cost, partial, with only the zero quote): the shell renders a zero `price` amount as `{}`, and the composer skipped zero rates. +2 HOOL long and -2 HOOL short (across two accounts, or as two lots in one account under NONE booking) vanished hosted, while `bea` keeps the group with its -40 USD basis and no average cost (w5/947). 10 VT costed in EUR and 10 in GBP, valued into USD with the GBP quote the later one, showed the EUR lot's 110 USD hosted and `bea`'s 110.50 USD. Every difference was the CLI's documented rule, so the composer (`backend-cluster/backend-v2/src/features/ledger/utils/holdings.ts`) now follows it: the prices query also reads `currency(amount) AS quote` and a zero rate counts as a quote with no inverse; the detail query returns one row per lot, so only a group whose every lot is sold is left out; and a merged group keeps its latest quote, ties going to the cost currency that sorts first. On the repro ledgers REST, GraphQL and MCP (all `LedgerFinanceService.getHoldings`) now match `bea` group for group, modulo the documented number scale. The REST/MCP description, the GraphQL field note and `docs/mcp.md` say so; the v1 OpenAPI snapshot and the CLI's pinned copy are regenerated. Regressions: parity cases in `holdings.test.ts` on the engine's own row shapes (17 fail with the fix reverted) and a combined-ledger case in `ledger-finance-service.test.ts`. Shipped in `35d82a19e` (`backend-v2`, `cli` spec pin).

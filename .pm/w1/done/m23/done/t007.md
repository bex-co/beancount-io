## Objective

`bea list` presents directives that a plugin synthesized at load time as though they were text in the ledger. An agent that enables `auto_accounts`, posts to a new account, then trusts `list open` believes the open was written — it was not, and removing the plugin makes `bea check` fail.

## Context

- `w3/301` (major): `auto_accounts` opens appear in `list open` and its JSON as if on disk.
- `w3/318`: `implicit_prices` quotes appear in `list price`.
- `w3/319`: `currency_accounts` opens appear in `list open`.
- `w3/320`: `close_tree` closes appear in `list close`.
- Listing answers are built engine-side in `cli/src/bea_engine/ledger/listing.py` and rendered by `cli/src/cli/commands/list.py`.

## Steps

1. Detect directives with no real source location (or whose source file is not a ledger file on disk) and mark them generated.
2. Add an explicit field to the JSON listing answer and a visible marker in the human table.
3. Offer a way to list only on-disk directives, so an agent can ask the question it actually means.
4. Document the distinction where `list` is described.

## Files

- cli/src/bea_engine/ledger/listing.py
- cli/src/cli/commands/list.py
- cli/docs/USAGE.md
- cli/tests/test_customer_workflows.py

## Acceptance criteria

- [ ] With `auto_accounts` enabled, `bea list open` marks the synthesized account as generated in the human table and in JSON.
- [ ] The same holds for `implicit_prices` prices, `currency_accounts` opens, and `close_tree` closes.
- [ ] On a ledger with no plugins, no row is marked generated and the output is unchanged.
- [ ] An agent can filter to on-disk directives only and get exactly what `grep` would find.

## Out of scope

- Changing which plugins run or warning about plugin use.
- Metadata fidelity in `list` output (`w3/289`, `w3/290`), which is separate.

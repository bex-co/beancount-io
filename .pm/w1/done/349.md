# `bea init --preset … --opening-balance` ends the new ledger with a blank line, so `git diff --check` fails on the first commit and the first `bea add` leaves two blank lines

**Bug · cli · minor · ~20m · A2.** From routine cli-qa, 2026-11-21. A preset ledger created with any `--opening-balance` (a zero one included) ends in `…USD\n\n`. That is a blank line at end of file. `git diff --check` on the freshly created file reports `main.bean:<last line>: new blank line at EOF.` and exits 2, so a ledger repository that runs it (or pre-commit's `end-of-file-fixer`) fails or rewrites the file on its very first commit. The first `bea add` then appends its own blank separator, leaving two blank lines between the opening balance assertions and the new entry. `bea format -i` does not converge it: it reports `0/1 file(s) formatted.` and leaves the blank line in place. This is the same class as w1/295 (a trailing space that `git diff --check` flagged on every narration-less entry).

Environment: main `c9d492c18`, `bea 0.5.0` from the checkout (`uv run bea`), Python 3.12.14, macOS 26.5.1. Isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, `BEA_FILE`/`BEA_TOKEN` unset, stdin closed, no TTY, scratch cwd. Reproduced in fresh processes and fresh directories.

## Repro

```sh
git init -q books-repo && cd books-repo
bea --no-input init books --preset personal@1 --currency USD --date 2026-01-01 --opening-balance 'Assets:Bank 100'   # exit 0
tail -c 8 books/main.bean | od -c        # … U S D \n \n
git add -N books/main.bean && git diff --check   # books/main.bean:23: new blank line at EOF.  (exit 2)
bea --file books/main.bean add note --date 2026-01-02 -a Assets:Bank -m hi
tail -4 books/main.bean | cat -e
# 2026-01-01 balance Assets:Bank   100 USD$
# $
# $
# 2026-01-02 note Assets:Bank "hi"$
```

`business@1` with `--opening-balance 'Assets:Bank 0'` does the same (`main.bean:15: new blank line at EOF.`). Controls: `bea init --preset personal@1` with no opening balance, and the fixed chart `bea init books --currency USD --opening-balance 'Assets:Checking 100'`, both end in a single `\n` and pass `git diff --check`.

## Expected

Every file `bea init` creates ends with exactly one newline after its last directive, with or without `--preset` and `--opening-balance`. `git diff --check` passes on it, and the first `bea add` leaves one blank line between the last assertion and the new entry, as it does after the fixed chart.

## Cause

`answer_preset` in `cli/src/bea_engine/initiating.py` appends a trailing `""` after the balance assertions (`:318`, `lines.append("")`), and `:320` then writes `"\n".join(lines) + "\n"`, which yields the extra `\n`. The hosted builder has the same line: `lines.push(...assertions, "")` in `backend-cluster/backend-v2/src/features/ledger/setup/build-ledger.ts:403`, joined the same way at `:412`, so a hosted Create Ledger with opening balances commits a file with the same trailing blank line.

## Fix

Drop the trailing `""` after the assertions in `answer_preset` (keep the blank line between the opening transactions and the assertions). Add a regression test that runs real `bea init --preset` subprocesses with a nonzero and a zero opening balance and asserts the file ends in exactly one `\n` (no `\n\n`), and that a following `bea add note` leaves exactly one blank line before the new entry. Revert the fix and watch it fail. Owned by `cli`. In its own `backend-v2` commit, remove the same trailing `""` from `build-ledger.ts:403` and pin it in that package's builder tests, so the two builders keep writing the same bytes.

## Dedupe

Searched `.pm/**` for `blank line at EOF`, `end-of-file`, `trailing blank`, `two blank lines`, `double blank` and `diff --check`. The hits are w1/295 (trailing space after a bare header, done), a w2 audit remark about appends landing with two blank lines in an older layout (w2/m28, done) and unrelated dashboard and CSV items. No open item covers init's trailing blank line.

# Hand-written cloud output prints server strings raw, including terminal escape sequences

**Severity: minor. Owner: cli. Estimate: 15–20m. A1:** untrusted server text must not drive the user's terminal. Continuous CLI QA, 2026-10-03 (round 4); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, `BEA_FILE`/`CI` unset. **Local simulation:** a Python stub at `127.0.0.1:18765` returning the OpenAPI success shapes, reached via `BEA_API_URL` and a fake `BEA_TOKEN`; it logs every request. No real service or credential was used. Reproduced twice with a working control.

Stub values: profile `email: "q@x.invalid\x1b[2J\x1b[H"`; create response `fullName: "alice/n1\x1b]0;title\x07"`; `tier: "pro\nINJECT"`.

Actual (PTY): `bea cloud status` prints the raw ESC sequences (clears the screen); `bea cloud ledger create n1` prints the raw OSC even when piped (Click strips only CSI, only for non-TTY); the tier forges an extra output line. Control: `cloud ledger show`/`list` escape `\x1b…` via `output.fields`/`table` and `single_line`.

Expected: the `single_line` treatment `cli/src/cli/utils.py:21` documents for untrusted cells.

Cause: `cli/src/cli/commands/cloud/app.py:107–111` (status); `cli/src/cli/commands/cloud/ledger/app.py:72–76` (create fields), `:80`, `:114`, `:124` (clone notes/success).

Fix/acceptance: route these values through `single_line`; the PTY cases show `\x1b` escaped and no forged lines.

Dedupe: no `.pm` hit for cloud + escape / `single_line`.

---

**Resolved 2026-10-03** — `bea cloud status`, `ledger create` and `clone` output now escapes control characters in server text, as `show` and `list` already did. `tests/test_cloud_output_escaping.py` covers each command. Shipped in the commit that moved this note (`cli`).

## Objective

Turn the local/cloud split from a naming convention into a structural guarantee: a test that fails if any command module outside `cli/src/cli/commands/cloud/` imports the API client, credentials, or server settings. This preserves the existing lazy-import discipline (local commands never pay the `pydantic_settings`/logfire/OTel import cost) and gives agents a hard "these commands are offline-safe" contract.

## Context

- `cli/src/cli/settings.py`'s docstring already documents the discipline informally: only server-talking commands may import it, via `cli.config.settings()`.
- Forbidden imports for local command modules: `cli.api`, `cli.auth`, `cli.settings`, `pydantic_settings`.
- Existing test fixtures/helpers live in `cli/tests/conftest.py`.

## Steps

1. Add a pytest module that walks every module under `cli/src/cli/commands/` except `cloud/`, parses its imports (AST, not runtime), and asserts none of the forbidden names appear.
2. Cover the transitive front door too: assert importing each local command module does not pull `pydantic_settings` into `sys.modules`.
3. Document the rule in `cli/CLAUDE.md`'s conventions section (one line: network, credentials, and settings imports live only under `commands/cloud/`).

## Files

- `cli/tests/test_command_boundaries.py` (new)
- `cli/CLAUDE.md`

## Acceptance criteria

- [ ] Test fails when a forbidden import is added to a local command module (verified by temporarily adding one).
- [ ] Test passes on the restructured tree; `make check-all` green.

## Out of scope

- Enforcing boundaries inside non-command packages (`cli/src/fava/` etc.).

## Objective

Make `bea --help` communicate the local/cloud boundary at a glance: local verbs in a "Local ledger" panel, the `cloud` entry in a "Cloud (beancount.io)" panel, so humans and agents can read which commands work offline without consulting docs.

## Context

- Typer supports `rich_help_panel` on commands and sub-apps.
- Top-level local verbs: `check`, `format`, `query`, `report`, `add`, `list`, `ask` (`cli/src/cli/main.py`).
- `bea cloud --help` should likewise carry a one-line description noting these commands need `bea cloud login` first.

## Steps

1. Assign `rich_help_panel="Local ledger"` to every local command/sub-app registration and `rich_help_panel="Cloud (beancount.io)"` to the `cloud` sub-app in `main.py`.
2. Write the `cloud` app's help text: what it covers, that it talks to the hosted service, and the login prerequisite.
3. Eyeball `bea --help` and `bea cloud --help` output.

## Files

- `cli/src/cli/main.py`
- `cli/src/cli/commands/cloud/__init__.py`

## Acceptance criteria

- [ ] `bea --help` renders two panels with every command in the right one.
- [ ] `bea cloud --help` states the network/login prerequisite.
- [ ] `make check-all` passes.

## Out of scope

- Rewriting individual command help strings beyond panel assignment.

# `bea init --existing` reports a broken `include` at `<load>`, with the real `file:line` and absolute paths pushed into the message

Found by `/qa-find-bugs-cli w1` on 2026-11-18 (HEAD `f4071ce8f`, `bea 0.4.1`, macOS 26.5, Python 3.12.14, checkout `uv run bea`, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, synthetic ledgers). Severity: minor. A1/A2: `init --existing` is the first command a newcomer or an agent runs on books bea did not create, and its "Needs attention" list is meant to name each problem at a folder-relative `file:line`. An incomplete fix of w1/269 and w1/273: `check`, `list` and the writes locate these errors, this caller does not.

**Repro** (synthetic):

```sh
mkdir ex && cd ex
printf 'option "operating_currency" "USD"\ninclude "a.bean"\ninclude "a.bean"\ninclude "prices.bean"\n' > main.bean
printf '2026-01-01 open Assets:Cash USD\n' > a.bean
bea init --existing .           # exit 0
bea --json init --existing .    # (after removing the AGENTS.md/CLAUDE.md it wrote) exit 0
bea check                       # control, exit 1
```

**Actual.** Text: each include error is listed as `<load>: /abs/ex/main.bean:3: include "a.bean" loads /abs/ex/a.bean, already included at /abs/ex/main.bean:2` (and `<load>: /abs/ex/main.bean:4: include "prices.bean" matches no file (looked for /abs/ex/prices.bean)`). JSON: `data.errors[]` has `"file": "<load>", "line": 0` and `data.attention[]` has `"location": "<load>"`, with the absolute `path:line:` at the start of `message`. Control: `bea check` prints the same errors at `/abs/ex/main.bean:3:` / `:4:`, and in `init --existing` an ordinary error (an unknown account) reads `main.bean:3: Invalid reference to unknown account …`.

**Expected.** `main.bean:3: include "a.bean" loads a.bean, already included at main.bean:2` style lines: the location is the include directive (`file` = the including file, `line` = its line, `location` = `main.bean:3`), and `message` no longer starts with a location. Basis: `existing_report.attention` promises `{kind, location, …}` per problem, and `format_error` already places these errors (w1/269, w1/273).

**Root cause.** `cli/src/bea_engine/describing.py:82-88` (`_error`) takes `file`/`line` from the raw loader error (`<load>`, `0`) and strips a `<load>:0: ` prefix from the formatted text. `format_error` (`cli/src/bea_engine/query.py:3213`, `_include_message`) has already rewritten the text to start with the real `path:line: `, so nothing is stripped and the location stays `<load>`; `cli/src/cli/existing_report.py:100` (`_location`) then prints `<load>` because its relpath starts with `..`.

**Fix** (cli only). In `describing._error`, when the formatted line starts with a location other than the raw one (an include placed by `_include_message`), take `file`/`line` from it and strip it from `message`, or have `_include_message` expose the structured location. Keep `message` free of the leading location in both text and JSON. Regression: the repro's missing and repeated include, text and `--json`, each failing with the fix reverted. Local-only; no REST/GraphQL/MCP surface reads `describe`.

**Blast radius.** Only `bea-engine describe` → `bea init --existing` (text "Needs attention", `--json` `errors` and `attention`). The AGENTS.md it writes carries only the error count, so it is unaffected. Plugin failures are located separately (`plugins[]`) and are fine. Working control: any error whose loader source is a real file.

**Dedupe.** Searched `.pm/**` for `<load>`, `init --existing`, `describe`, `matches no file`, `already included`. w1/269 and w1/273 (done) located these errors in `format_error`; w1/275 (done) fixed the `--into` write path; none covers `describe`. Estimate: 20–30 minutes.

---

**Resolved 2026-11-18** — The include locator in `cli/src/bea_engine/query.py` (`include_error`, formerly `_include_message`) now returns the include's `(file, line, message)` and takes a path renderer, so `describe` (`cli/src/bea_engine/describing.py`) places a missing or repeated include at the include directive and names every path in the message relative to the ledger folder. `bea init --existing` now reads `main.bean:3: include "a.bean" loads a.bean, already included at main.bean:2` and `main.bean:4: include "prices.bean" matches no file (looked for prices.bean)`, and `--json` gives `file` = the including file, `line` = its line, `location` = `main.bean:3`, with no location at the start of `message`. `bea check` and the write paths render exactly as before. Regressions in `cli/tests/test_init_existing.py` cover the repro in text and `--json` plus an include cycle through a subfolder (all three fail with the fix reverted). Shipped in `5322cdf65` (`cli`).

# `bea cloud ledger delete --dry-run` never checks that the server answered with a preview: against a backend that predates the delete preview it deletes the ledger with no confirmation and prints "Dry run: ledger 'alice/books' was not deleted.", exit 0

**Bug · cli · major · 45–60m · A1.** From routine cli-qa, 2026-11-23. `--dry-run` (w1/272) skips the confirmation because "a preview destroys nothing", sends `DELETE /api-gateway/v1/ledgers/{owner}/{name}` with `{"dryRun": true}`, and then prints the success line whatever came back. It never reads the `dryRun` echo the v1 contract defines ("True when this is a deleteLedger preview … Commits echo false"). A server that does not implement the preview treats the request as a delete. Every backend-v2 built before `09a06ed42` (2026-10-27) is such a server: the route had no body schema and did not parse a body at all (`v1-route.ts`, `if (route.body) middlewares.push(bodyParser())`). A self-hosted stack deployed before that date, driven by `bea 0.5.0`, loses the ledger permanently, with no prompt even in a terminal, and is told it was not deleted. `--json` also breaks its documented shape: USAGE says `data` holds `dry_run: true`, and the answer carries no `dry_run` at all.

Production is not affected today: `https://api.v3.beancount.io/api-gateway/v1/openapi.json` advertises the `dryRun` body on `deleteLedger`. No real ledger was deleted or previewed in this run.

Environment: main `40e22400b`, `bea 0.5.0` from the checkout (`uv run bea`), Python 3.12.14, macOS 26.5.1. Isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, stdin closed, no TTY. **Simulation:** a local HTTP stub answering the delete as the pre-`09a06ed42` route did (no body read, `200 {"ledgerId": …}`), with a placeholder token. It proves the CLI's handling, not a production defect. Reproduced twice in fresh processes.

## Repro

```sh
cat > old_server.py <<'EOF'
import json, sys
from http.server import BaseHTTPRequestHandler, HTTPServer
class H(BaseHTTPRequestHandler):
    def do_DELETE(self):
        n = int(self.headers.get("content-length") or 0)
        print("DELETE", self.path, self.rfile.read(n).decode(), file=sys.stderr, flush=True)
        out = json.dumps({"ledgerId": "/".join(self.path.split("/")[-2:])}).encode()
        self.send_response(200); self.send_header("content-type", "application/json")
        self.send_header("content-length", str(len(out))); self.end_headers(); self.wfile.write(out)
HTTPServer(("127.0.0.1", 18765), H).serve_forever()
EOF
python3 old_server.py &
export BEA_API_URL=http://127.0.0.1:18765 BEA_TOKEN=placeholder
bea cloud ledger delete --dry-run alice/books; echo "exit $?"
bea --json cloud ledger delete --dry-run alice/books; echo "exit $?"
```

## Actual

- Text: `Dry run: ledger 'alice/books' was not deleted.`, exit 0. No prompt.
- JSON: `{"bea": "0.5.0", "target": {"server": "http://127.0.0.1:18765"}, "data": {"ledger_id": "alice/books", "preview": {}}, "truncated": false}`, exit 0.
- The stub logged `DELETE /api-gateway/v1/ledgers/alice/books {"dryRun":true}` for each run: the request a pre-preview backend executes as a delete.
- Control: `bea cloud ledger delete --dry-run <qa-owner>/qa-20261123-nonexistent` against production exits 1 with `Ledger not found` (`code: NOT_FOUND` in JSON), so the request path itself is fine.

## Expected

`--dry-run` says "not deleted" only when the server says it previewed: the answer's `dryRun` is `true` and it carries a `preview`. Any other 2xx answer (no echo, `dryRun: false`, no `preview`) is reported as what it may be: the server does not support `--dry-run` and may have deleted the ledger; check with `bea cloud ledger show OWNER/NAME`. That exits **4** (outcome unknown), never 0, under `--json` too. Better still, nothing irreversible goes to a server that cannot preview: before sending, confirm the server's `GET /api-gateway/v1/openapi.json` lists the `dryRun` body field on `deleteLedger` (production serves it today), and refuse `--dry-run` with exit 1 naming the server when it does not, sending no DELETE. Basis: `cli/docs/USAGE.md` ("`--dry-run` asks the server for the destroy summary without destroying anything … `data` holds `dry_run: true`"), the v1 `deleteLedger` response schema, and USAGE's "Exit 0 is a promise: the documented effect happened".

## Cause

`cli/scripts/gen_cloud_commands.py:262-280` generates the dry-run branch; the generated `cli/src/cli/commands/cloud/generated/ledger.py:109-126` reads `row.get("preview") or {}` and prints `preview_done` (`gen_cloud_commands.py:96`) unconditionally. The comment at `:110` ("a lost answer is not an unknown outcome") holds only for a server that implements the flag. The pre-preview route is `09a06ed42^:backend-cluster/backend-v2/src/features/ledger/api/rest/v1/lifecycle-handler.ts` (`deleteLedger` with no `body:`), and `09a06ed42^:…/server/rest/v1-route.ts:157` parses a body only for routes that declare one.

## Fix

Owned by `cli`, in the generator (then `make codegen`; do not edit generated files). In the dry-run branch, require `answer.dry_run is True` and a `preview` before printing the success line or emitting the envelope; otherwise raise the unknown-write-outcome error (exit 4) naming the ledger and the `show` command. Add the capability check before the request if it stays small (one GET of the served spec, or a cached per-server answer). Tests in `cli/tests/test_cloud_ledger_delete_dry_run.py` with `httpx_mock`: a `{"ledgerId": …}` answer and a `{"dryRun": false}` answer each exit 4 and print no "not deleted"; the existing preview answer still exits 0 with `dry_run: true` in JSON; with the capability check, a spec without `dryRun` sends no DELETE. Revert and watch them fail. Run `make check-all` and `make docs-check` in `cli/`, and say in USAGE what happens against a server without the preview. No backend change.

## Blast radius

`deleteLedger` is the only generated command with `dry_run` in the registry (`gen_cloud_commands.py:95`). A plain `delete` keeps its confirmation and its unknown-outcome handling. `cloud ledger create` and the hand-written flows do not preview.

**Resolved 2026-11-23** — `bea cloud ledger delete --dry-run` now sends its DELETE only to a server whose own contract says it can preview, and says "not deleted" only when the answer is a preview. It first reads the served `/api-gateway/v1/openapi.json`. When that contract cannot be read, or lists no `dryRun` body field for `deleteLedger`, it exits 1 naming the server and sending nothing, for example `http://127.0.0.1:18767 does not support --dry-run here: its API contract lists no 'dryRun' field for deleteLedger, so it would carry out the request instead of previewing it. Nothing was sent; upgrade the server to use it.` An answer without `dryRun: true` and a `preview` exits 4 (`category: conflict` under `--json`) with `… may have deleted the ledger. The outcome is unknown — check with bea cloud ledger show alice/books before retrying.` Against local stubs the repro's pre-preview server (no spec route, HTTP 501), a spec 404, and a served pre-preview spec each now get one GET and no DELETE. A stub that serves the current spec but answers like the old route exits 4. Production's served spec lists `dryRun` and `dry_run` on `deleteLedger`, so a real preview still runs; it was checked with a read-only GET, and no ledger was deleted or previewed. Shipped in `24c97640b` (`cli`): `scripts/gen_cloud_commands.py` (new `preview_unconfirmed` registry template; both checks emitted in the dry-run branch), regenerated `src/cli/commands/cloud/generated/ledger.py`, `require_body_field` in `src/cli/api/client.py`, and `docs/USAGE.md`. New cases in `tests/test_cloud_ledger_delete_dry_run.py`: three non-preview answers × text/JSON exit 4, and a missing field, a spec 404, or an unreadable spec send no DELETE. With the generated command reverted, all nine fail. With only the answer check removed, the six answer cases fail. With only the contract check removed, the three no-DELETE cases fail. `make check-all` passed (13,014 tests).

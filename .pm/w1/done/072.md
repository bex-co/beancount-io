# Parents whose children cancel show `—` instead of the promised explicit zero for plain currencies and in filtered views

**Severity: minor. Owner: cli. Estimate: 45–60m. A1:** a real zero total must be distinguishable from no activity. Continuous CLI QA, 2026-10-02 (round 2); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed unless a PTY is stated. Reproduced at least twice from pristine fixtures.

Fixture A (plain currency, unfiltered):

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Food:Groceries USD
2024-01-01 open Expenses:Food:Refunds USD
2024-01-01 open Equity:Opening
2024-01-02 * "fund"
  Assets:Cash 100.00 USD
  Equity:Opening
2024-01-03 * "buy"
  Expenses:Food:Groceries 10.00 USD
  Assets:Cash
2024-01-04 * "refund"
  Expenses:Food:Refunds -10.00 USD
  Assets:Cash
```

`bea report income-statement -i yearly` shows `Expenses —`, `Food —`, yearly `EXPENSES —` beside `Net Profit: 0.00 USD`; JSON `balance_children: {}`. Same with `-a Expenses:Food` and `bea balance Food`.

Fixture B (lots, filtered): `option "booking_method" "NONE"`, postings `Assets:Inv:Long 5 STK {10.00 USD}` and `Assets:Inv:Short -5 STK {10.00 USD}`. Unfiltered `report trial-balance -x at_cost` correctly shows `Inv 0.00 USD` (control), but `bea balance Inv -x at_cost`, `report trial-balance -a Assets:Inv` and `report balance-sheet -a Assets:Inv` show `—` / `{}`.

Expected: `0.00 USD` / `{"USD": "0"}` per `cli/docs/USAGE.md` Reports ("A parent whose children cancel … reports an explicit zero") and the `w3/done/357` resolution.

Cause: `cli/src/fava/core/tree.py:49` returns `{}` because a cost-less inventory that nets to zero is already empty (only offsetting lots reach the zero-fill branch); `cli/src/bea_engine/report.py:671` `_prune_tree` recomputes `balance_children` via `_sum`, and `SimpleCounterInventory.add` (`cli/src/fava/core/inventory.py:50–56`) drops zeros.

Fix/acceptance: when a node's converted total is empty but a kept child has a non-empty converted balance, emit zero for each currency those children produced, in both `TreeNode.serialise` and `_prune_tree`. A shows `0.00 USD` for Expenses/Food unfiltered and with `-a`; B shows `Inv 0.00 USD` in `balance` and `report -a`; truly empty accounts still read `—` (`test_report_tree_zero_net_rollup.py::test_an_account_with_no_balance_still_reads_empty`).

Dedupe: gap in `w3/done/357` (`98865a81`, lots only, unfiltered test); `w3/373` concerns monthly rows.

---

**Resolved 2026-10-03** — parents whose plain-currency or lot-based children cancel now report an explicit zero instead of `—`, with and without account filters, through one shared helper; a truly empty account still reads `—`. Tests in `tests/test_report_tree_zero_net_rollup.py` cover it. Shipped in the commit that moved this note (`cli`).

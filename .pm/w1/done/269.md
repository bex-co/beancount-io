# A missing `include` is reported at `<load>:0`, so `bea` never says which file holds the broken line or where it looked

Found by `/qa-find-bugs-cli w1` on 2026-11-15 (HEAD `11ff3a84b`, `bea 0.3.1`, macOS 26.5, checkout `uv run bea`, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, synthetic ledgers). Severity: minor. A1/A2: a newcomer splitting a ledger into files, or an agent fixing one, gets an error with no file, no line and a path that is relative to a directory it does not name. Every other load error `bea` renders already carries `file:line` (plugin failures were relocated from the same `<load>:0` in w5/256).

**Repro** (synthetic, nested split ledger):

```sh
mkdir -p books/sub && cd books
printf 'include "sub/a.bean"\ninclude "sub/b.bean"\n2024-01-01 open Assets:Cash USD\n' > main.bean
printf 'include "accounts.bean"\n' > sub/a.bean
printf '2024-01-01 open Expenses:X USD\n' > sub/b.bean
bea check                                   # exit 1
bea --json check                            # exit 1
bea list open                               # exit 1
bea add open -a Assets:Y --date 2024-01-01  # exit 1, file unchanged
touch accounts.bean && bea check            # still exit 1, same message
```

**Actual.** Every command prints the same location-free line: `<load>:0: File glob "accounts.bean" does not match any files` (text `check` on stderr; `--json check` and `--json list` in `error.details`; `list`, `balance`, `report`, and the `add` refusal "The ledger already has 1 error(s); nothing was written" as their detail line). Nothing names `sub/a.bean:1`, and nothing says the glob was resolved against `sub/`, so creating `accounts.bean` beside `main.bean` (the obvious reading) leaves the identical error.

**Expected.** The detail names the include directive and the path it resolved, for example `/abs/books/sub/a.bean:1: include "accounts.bean" matches no file (looked for /abs/books/sub/accounts.bean)`. The JSON `details` string carries the same location. Basis: the CLI's own error contract renders loader errors as `file:line: message` (`format_error` docstring, `cli/src/bea_engine/query.py`), and the hosted surfaces already locate this exact error (w21/773, w21/189).

**Root cause.** Upstream `beancount/loader.py` (`_load`, include expansion) appends `LoadError(data.new_metadata("<load>", 0), 'File glob "…" does not match any files')`: the options map keeps include strings without their lines. `format_error` in `cli/src/bea_engine/query.py` (about line 3193) rewrites two other `<load>:0` messages (plugin failures via `_plugin_message`/`plugin_directive`, duplicate reprs) but passes this one through unchanged.

**Fix.** cli only (`cli/src/bea_engine/`). In `format_error` (or where the load's errors are collected, so every caller gets it), recognize `File glob "<pattern>" does not match any files` at `<load>:0` and relocate it to the include line that wrote that pattern. Walk the root's include closure with `bea_engine.ledger.text.iter_includes` (the scanner `managed_load._collect_managed` already uses with `LedgerSnapshot.contents`). Report the including file, its line, and the resolved absolute search path. When several files write the same pattern, name every one that matches nothing from its own directory. Keep the unchanged text when no include line is found. Plain `bea check` with no other bea-handled failure prints native bean-check output byte for byte by design (`cli/src/cli/commands/check.py`, "Errors still come from bean-check, in its own words"). Either route this error through the helper as w5/256 did for plugins, or leave text `check` native and state that in `cli/docs/USAGE.md`. The `--json` envelope and every other command must carry the location either way. Regressions: the nested repro above (root and nested include, `--json check`, `list`, `add` refusal), each failing with the fix reverted. Local-only behavior; no REST/GraphQL/MCP parity change (hosted already locates it, w21/773). Estimate: 40–60 minutes.

**Blast radius.** Every engine read that lists load errors through `format_error`: `check --json`, `list`, `balance`, `report *`, `query`, and the `add`/`update`/`import --apply` "already has N error(s)" refusals. Managed price URL includes are not affected: they never reach the glob (`managed_load` resolves or refuses them first, w5/190, w5/450). Working control: a `plugin "nonexistent.plugin"` line in a root ledger is reported at that file and line (`bad.bean:2`) with a readable cause.

**Dedupe.** Searched `.pm/**` (open, `done/`, `blocked/`) for `does not match any files`, `<load>`, `include` with `line`/`location`. w21/773 and w21/189 are the hosted (rustledger) fixes. w5/071, w5/202, w5/247, w3/370, w5/819, w5/192 and w5/190 quote this message as a symptom of other bugs (wrong cwd, NFD names, glob metacharacters, exit codes, URL includes) and never locate it. No open item covers the CLI location.

---

**Resolved 2026-11-15** — `format_error` relocates `File glob "…" does not match any files` from `<load>:0` to every include line that wrote the pattern and matches nothing, with the absolute path it was matched against (`FILE:LINE: include "PATTERN" matches no file (looked for PATH)`); `--json check`, reads, and the write refusals carry it, plain `bea check` routes it through the helper as plugin failures are, and with bean-check's own options the output stays native as `cli/docs/USAGE.md` states. Regressions in `cli/tests/test_missing_include_location.py`. Shipped in `88e007142` (`cli`).

# `bea add close` dated before a later posting says "still holds … move it out with a transaction dated on or before", and doing that books the transfer twice (gap in w1/293 and w5/772)

**Bug · cli · minor · ~45m · A1.** From routine cli-qa, 2026-11-20. A user (or an agent) closes an account on the day they think it emptied, but the ledger moves its money out a few days later. `add close` then refuses with the funded-close message: the account "still holds 100.00 USD", so move it out with a transaction dated on or before the close, or pass `--force`. Both remedies fail. `--force` is refused, because the later posting would hit a closed account. Following the first remedy is worse: the new transfer writes with exit 0, so the transfer is now booked twice (the old account goes to -100.00 USD and the new one to 200.00 USD), and the close is still refused. The one fact that matters is that the account has a posting after the close date. bea already has a hint for it (w5/772: "date it on or after 2026-03-01"), but only `--force` reaches that hint.

Environment: main `11090b2c3`, `bea 0.5.0` from the checkout (`uv run bea`), Python 3.12.14, macOS 26.5.1. Isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, `BEA_FILE`/`BEA_TOKEN` unset, stdin closed, no TTY, cwd a scratch directory. Reproduced in fresh processes from a pristine copy. Each refused run left the file byte-identical (same md5).

## Repro

```sh
cat > main.bean <<'EOF'
option "operating_currency" "USD"
2026-01-01 open Assets:Old USD
2026-01-01 open Assets:New USD
2026-01-01 open Equity:Opening USD
2026-01-02 * "fund"
  Assets:Old 100.00 USD
  Equity:Opening
2026-03-01 * "move"
  Assets:Old -100.00 USD
  Assets:New
EOF
bea --file main.bean check                                              # exit 0
bea --file main.bean add close --date 2026-02-28 -a Assets:Old          # 1
bea --file main.bean add close --date 2026-02-28 -a Assets:Old --force  # 2: remedy B
bea --file main.bean add transaction "move early" --date 2026-02-28 -p "Assets:Old -100.00 USD" -p Assets:New   # 3: remedy A
bea --file main.bean add close --date 2026-02-28 -a Assets:Old          # 4
bea --file main.bean balance Assets                                     # 5
```

Actual:

1. Exit 1: `Assets:Old still holds 100.00 USD on 2026-02-28. Move that balance out of Assets:Old with a transaction dated on or before 2026-02-28, then close it, or pass --force to close it with the balance. Nothing was written.` `--json` gives the same message with no `details`. The later posting is never mentioned.
2. Exit 1: `main.bean:8: Invalid reference to inactive account 'Assets:Old' … The proposed close would close Assets:Old on 2026-02-28; date it on or after 2026-03-01.` This is the answer run 1 should have given.
3. Exit 0: the transaction is written. The 2026-03-01 move is still there, so the transfer is now booked twice.
4. Exit 1, the same inactive-account refusal as run 2.
5. `New 200.00 USD`, `Old -100.00 USD`.

Control: on the pristine file, `add close --date 2026-03-01 -a Assets:Old` writes (exit 0). An account with nothing left on the close date but a posting after it already gets w5/772's "date it on or after" refusal without `--force`. Under `plugin "beancount.plugins.close_tree"`, closing a parent `Assets:Bank` on 2026-02-28 while `Assets:Bank:Old` has the 2026-03-01 posting gives the same funded refusal ("…and the close_tree plugin closes it with Assets:Bank… or pass --force"), and `--force` reaches the inactive-account error.

## Expected

When the ledger as it would stand has a posting to the account (or to a descendant the write closes through `close_tree`) dated after the close, `add close` without `--force` refuses with the inactive-account explanation that `--force` gets today. That explanation names the later posting's `file:line` and says to date the close on or after that day. It does not report the balance, and it suggests neither a move-out transaction nor `--force`. This mirrors w1/293, where an already-closed account gets the duplicate-close hint instead of the balance. The funded-close refusal keeps its wording when nothing posts after the close date (the account really does still hold money there), and `--force` keeps its behavior.

## Cause

`_close` in `cli/src/bea_engine/ledger/adding.py` (lines 526–580) passes `judge` (line 554) as `validate_append`'s `inspect` hook. `cli/src/bea_engine/ledger/write.py:2633-2634` runs that hook on the candidate entries before the candidate's validation errors are classified and hinted. `judge` raises `_funded_close_refusal` (line 566) on the balance held at the end of the close date, so the `Invalid reference to inactive account` error, and its w5/772 hint at `write.py:2870`, are never reached. w1/293 skipped `judge` only for an account the ledger already closes (`declared`, line 574). The backdated close over later postings takes the same wrong path.

## Fix

Owner `cli`, engine side. In `judge`, leave an account (the closed one or a `close_tree` descendant from `_moved_closes`) to validation when the candidate holds a posting to it dated after its close. Validation then reports the inactive reference with the w5/772 hint. Regressions, text and `--json`: the repro's run 1 gets the "date it on or after 2026-03-01" refusal; the `close_tree` parent case does the same for the descendant; the existing funded-close tests (`tests/test_add_close_refuses_balance.py`, `tests/test_add_close_tree_every_funded_account.py`) still hold. Revert the fix and watch the new tests fail. Run `make check-all` in `cli/`. No REST/GraphQL/MCP change: the funded-close guard is `bea`'s own (`bea import` reaches closes through w5/913's warning, not this refusal).

## Dedupe

Searched `.pm/**` for `add close` with `later`, `after the close`, `inactive`, `still holds` and `on or before`. Ran `git log` on `cli/src/bea_engine/ledger/adding.py`. Related, not duplicates:

- w1/293 (done): same mechanism, but only for an account that is already closed.
- w5/772 (done): the inactive-account hint for a backdated close, which the funded refusal now hides whenever the account still holds money on the close date.
- w2/092 (done) added the funded-close refusal, and w1/312 (done) named every funded `close_tree` account.

No open or blocked item covers it.

# A blank commit message writes a blank commit; an empty one defaults differently on MCP and REST

**Bug · backend-v2 · minor · ~20m · A1.** From `/qa-find-bugs-mcp`, 2026-11-09, production `beancount-mcp 1.0.0`, the disposable QA ledger. This regresses the w21/553 acceptance: "`""` is handled the same way everywhere".

- **Repro:**
  - `createLedgerFiles {"description":"   ", …}` succeeds, and the commit message is blank (`"\n"`). REST `PUT …/files/{path}` with `"message":"   "` does the same.
  - `createLedgerFiles {"description":""}` commits with Gitea's own default, "Add <path>". REST `PUT` with `"message":""` commits with the server default, "Create <path>".
- **Expected:**
  - A message that is blank after trimming counts as omitted. REST and GraphQL then use the "Create/Update/Delete <path>" default.
  - The MCP file tools require a message (`docs/mcp.md:553-554`), so they refuse a blank one with `BAD_USER_INPUT`.
  - No commit ever gets an empty message.
- **Cause:**
  - `src/features/ledger/utils/commit-message-alias.ts:37-43` (`resolveCommitMessage`) only checks `resolved === undefined`.
  - REST `files-handler.ts:244-246` falls back with `||`, which catches `""` but not `"   "`.
  - MCP `edit-ledger-files-tool.ts:326,354` sends `""` on to Gitea unchanged.
- **Fix:** trim inside `resolveCommitMessage` and treat blank as omitted; when the message is `required`, refuse it with `BAD_USER_INPUT`. The callers that pick this up are the MCP file tools, `renameLedgerFile`, REST files `PUT`/`DELETE`, and the GraphQL file and rename mutations.
- **Check:** add parity cases for `""` and `"   "` on create, update, delete and rename across REST, GraphQL and MCP.

---

**Resolved 2026-11-10.** A blank commit message now counts as omitted everywhere. `resolveCommitMessage` treats a message that is empty or whitespace once trimmed as missing. That also means a blank twin no longer conflicts with a real one, and a message with text keeps its own spacing.
- **Where it applies:** `""` and `"   "` take the per-operation default (`Create/Update/Delete <path>`, `Rename a → b`) wherever the message is optional: REST files `PUT`/`DELETE`, the GraphQL file and rename mutations, and `renameLedgerFile`. The ledger service writes the same default for a GraphQL omission.
- **MCP:** the file tools require a message, so they refuse a blank one with `BAD_USER_INPUT` before any commit.
- **Result:** no commit is blank, and `""` no longer defaults differently by surface.
- **Tests:** `commit-message-alias.test.ts` covers the blanks, the twin and spacing. `rename-parity.test.ts` covers both blanks on REST, GraphQL and MCP. `file-write-size-parity.test.ts` covers create and update on all three surfaces and an MCP delete. Reverting the fix fails 21 cases.
- **Docs:** `docs/mcp.md` states the rule. (`backend-v2`)

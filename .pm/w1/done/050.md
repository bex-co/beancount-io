# `--conversion at_value` revalues cost-less holdings with the first price pair seen, even converting the operating currency

**Severity: major. Owner: cli. Estimate: 45–60m. A1:** agents reporting market value must get it in the operating currency. Continuous CLI QA, 2026-10-02; report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`, synthetic fixtures. Reproduced twice from pristine fixtures.

Fixture A:

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Bank USD
2024-01-01 open Assets:Cad CAD
2024-01-01 open Equity:Opening
2024-01-02 * "Opening"
  Assets:Bank  1000.00 USD
  Equity:Opening
2024-01-03 * "CAD"
  Assets:Cad  135.00 CAD
  Equity:Opening
2024-01-31 price USD 1.35 CAD
```

`bea --file /abs/a.bean report trial-balance -x at_value` → **`Bank 1,350.00 CAD`**, `Assets 1,485.00 CAD`. Expected Bank 1,000.00 USD (BQL `sum(value(position))` gives 1000.00 USD).

Fixture B: same header, `open Assets:Hool HOOL`, buy `2 HOOL @ 10.00 USD` (no cost), then `2024-01-05 price HOOL 9.00 EUR` and `2024-01-06 price HOOL 11.00 USD`. `bea --json --file /abs/b.bean balance Hool -x at_value` → `{"EUR":"18.00"}`. Expected 22.00 USD, which `-x USD` and BQL `convert(sum(position),'USD')` report.

Cause: `cli/src/fava/core/conversion.py:68–76` — for cost-less positions `get_market_value` takes the first pair in `prices._forward_pairs` (insertion order, built at `cli/src/fava/beans/prices.py:87`) whose base matches, ignoring the operating currency and not leaving the operating currency itself unconverted. Introduced by the `w3/241` fix (`0750c3f7`); new defect, not a regression of 241's DoD.

Fix/acceptance: for cost-less holdings keep amounts already in an operating currency; otherwise prefer a quote into the operating currency, falling back to units rather than an arbitrary pair (pass `operating_currency` into the conversion). A: Bank 1,000.00 USD; B: 22.00 USD regardless of price-directive order; `tests/test_at_value_costless.py` still passes. Run `make check-all`.

Blast radius: every at_value path through `cost_or_value` — all four reports, `bea balance`, interval series, account journal. Positions with cost are unaffected.

Dedupe: `.pm` search for at_value + costless / forward_pairs / first quote → `w3/241`, `w3/427`, neither covers this. `git log -S _forward_pairs` → `0750c3f7`.

---

**Resolved 2026-10-03** — `--conversion at_value` now leaves cost-less holdings already in an operating currency as they are and values other cost-less holdings into the first operating currency that has a price, regardless of price-directive order, falling back to units instead of an arbitrary quote; the operating currencies reach every at_value path through `FavaPriceMap`. `tests/test_at_value_costless.py` covers both fixtures from this note and both quote orders. Shipped in the commit that moved this note (`cli`).

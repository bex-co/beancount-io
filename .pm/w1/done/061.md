# A ledger plugin or importer that prints to stdout corrupts the engine envelope: successful writes report exit 4

**Severity: major. Owner: cli. Estimate: 45–60m. A1:** agents retry on exit 4, so a false "outcome unknown" duplicates entries. Continuous CLI QA, 2026-10-02 (round 2); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed unless a PTY is stated. Reproduced at least twice from pristine fixtures.

Save `myplug.py` beside the ledger:

```python
__plugins__ = ["noisy"]
def noisy(entries, options):
    print("noisy plugin ran")
    return entries, []
```

`main.bean` (from `bea --no-input init --currency USD --date 2026-01-01`) with `option "insert_pythonpath" "TRUE"` and `plugin "myplug"` prepended, then:

```sh
bea --json --file /abs/main.bean add transaction Coffee --date 2026-01-05 -p "Expenses:Dining 4 USD" -p "Assets:Cash"
bea --file /abs/main.bean check
bea --file /abs/main.bean list transaction
```

Actual: `add` exits **4** ("The Beancount engine did not answer … the outcome is unknown", success envelope dumped as detail) although the diff shows the transaction **was written**; `check` and `list` exit 1 "engine did not answer". A Python `--config` importer that runs `subprocess.run(["echo", …])` or `os.write(1, …)` does the same to `bea import --apply`. Controls: `bean-check` on the same ledger exits 0; the plugin without `print` works.

Expected: plugin/importer output never corrupts machine output; `cli/docs/IMPORTING.md` promises importer output is captured in `importer_output` "so it does not corrupt JSON". Retrying after a false exit 4 duplicates the entry, since `add` does not deduplicate.

Cause: the engine writes its envelope to fd 1 (`cli/src/bea_engine/protocol.py:138–139`) which user Python code inherits. `managed_load.load_file` runs plugins unguarded (`cli/src/bea_engine/managed_load.py:232`); `importing.py:141,166` use `contextlib.redirect_stdout`, which swaps `sys.stdout` but not fd 1. The frontend `_parse` (`cli/src/cli/engine/launch.py:412–427`) fails and raises ConflictError.

Fix/acceptance: at engine start, `dup` fd 1 to a private descriptor used only by the envelope writer and point fd 1 at stderr (or a capture pipe during importer runs, feeding `importer_output`). The repro's `add`/`check`/`list`/`import --apply` exit 0 with parseable JSON, plugin text on stderr, importer subprocess output in `importer_output`. Run `make check-all` in `cli/`.

Blast radius: every engine-backed command on a ledger with a printing plugin, plus Python importers.

Dedupe: same class as `w3/done/233` (query `.help` stdout), fixed only for the shell. No `.pm` hit for "did not answer", `redirect_stdout`, plugin print.

---

**Resolved 2026-10-04** — plugin and importer output — including raw descriptor writes and child processes — no longer corrupts the engine's JSON envelope: descriptor 1 points at stderr while a command runs and importer output is captured, so successful writes exit 0 instead of 4. `tests/test_engine_stdout_reserved.py` covers plugins and importers. Shipped in the commit that moved this note (`cli`).

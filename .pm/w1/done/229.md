# Holdings and BQL price an asset from its `@` sale; statements and net worth say the price is missing

**Bug · ledger + backend-v2 · major · ~45m after a decision · A1.** From `/qa-find-bugs-mcp`, 2026-11-10, production `beancount-mcp 1.0.0`, the disposable QA ledger. The ledger has no `price` directives and no `implicit_prices` plugin.

In one session an agent gets contradictory valuations for the same position. Holdings says 90 USD, while net worth leaves the asset out.

- **Repro:** REST returns byte-identical answers.
  1. Buy 10 QAX `{12.34 USD}` on 2026-07-01, then sell 4 QAX `{12.34 USD} @ 15.00 USD` on 2026-09-01. Separately, spend `80.00 EUR @ 1.09 USD`.
  2. Holdings shows QAX `market_value 90 USD`, price 15, `valuation "complete"`. BQL `value(sum(position))` returns 90.00 USD, and `sum(convert(position,'USD'))` for the trip returns 87.20 USD.
  3. The reports disagree:
     - `statements/balance-sheet?conversion=USD` lists `missingPrices [QAX→USD]` and drops QAX from assets.
     - `overview?conversion=USD` leaves QAX out of `netWorth`.
     - `balance-sheet?conversion=at_value` values the broker account at cost (74.04).
     - `income-statement?conversion=USD&time=2026-08` lists `missingPrices [EUR→USD]`.
  - **Local control:** Python beancount without the plugin agrees with the statements. With `plugin "beancount.plugins.implicit_prices"` it agrees with holdings and BQL.
- **Cause:**
  - `backend-cluster/ledger/src/foundation/rustledger/price-map.ts:29` (`buildPriceMap`) reads only `price` directives, which is Fava's price map. It feeds the statements, overview and `at_value` (`ledger-finance-service.ts:442`, `ledger-data-service.ts:821,893`, `api/reports.ts:364`).
  - BQL runs on rustledger's query price database, which always derives implicit prices from postings (upstream, traced in w3/m18).
  - Holdings is valued through BQL `value()`/`getprice()` (`backend-v2` `holdings.ts:68-72`).
- **Decision needed (owner):** pick one price basis for the deployment.
  - (a) The report price map includes the implied prices the engine uses, so every report behaves as if `implicit_prices` were on.
  - (b) Holdings computes `market_value` and price from `buildPriceMap`, matching Fava's default.
- **Either way:**
  - Label an inferred price as inferred.
  - Add a parity case covering holdings, `balance-sheet at_value` and overview with an `@`-priced sale.
- **Related:**
  - w3/113 (blocked) is a narrower upstream symptom of the same engine behaviour.
  - With the trip tag as filter, the income statement's headline currency came back EUR despite `conversion=USD`, which is more evidence for w1/216.

**Blocked 2026-11-10.** Confirmed still open on `main`: `buildPriceMap` (`ledger/src/foundation/rustledger/price-map.ts`) still reads only `price` directives, while holdings and BQL `value()` use the engine's implied prices. The note needs an owner decision on the price basis. The user has since routed the fix and that decision to `w23/m41/t004`, "Value a position one way everywhere (w1/229)" (commit `0cfeaaf73`). That task follows stock beancount's price source and replays the reports against a stock corpus; it cites this note for the repro ledger. Fixing it here would race the `w23` queue and preempt the milestone's decision.

**Unblock:** `w23/m41/t004` ships. Close this note then, citing its commit. If the milestone is dropped, the price-basis choice between (a) and (b) above returns to the user. Cleared by the `w23` worker, or by the user.

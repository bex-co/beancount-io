# `bea report capital-gains` says "Account balances use Beancount signs (credits negative)" above a GAIN column that is positive for a gain, so a net loss of 100 USD prints as `-100.00 USD` under a heading that makes it read as a credit

**Bug · cli · minor · 20–30m · A1.** From routine cli-qa, 2026-11-20. The capital-gains report prints the same sign sentence as the trial balance: "Account balances use Beancount signs (credits negative)." Its JSON carries `balance_signs: "beancount"` and no other sign key. But the report holds no account balances. Its GAIN column and bucket totals are proceeds minus basis, positive for a gain and negative for a loss. That is the opposite of the Beancount sign the gain posting is booked with (`Income:Gains -300.00 USD` for a 300 USD gain). On the repro, the sale loses 100 USD in total. `bea balance Income:Gains` prints `100.00 USD` (a debit, a loss) and the capital-gains totals print `-100.00 USD`. Both sit under the same sentence. A reader or agent who applies the sentence reads `-100.00 USD` as a credit, which means a gain. Realized gains go into tax figures, so a sign read the wrong way is a costly mistake.

The other reports that do not use Beancount signs already say what they use. The income statement adds "profit is positive for a gain" and `net_profit_signs: "positive_for_gain"`. Cash flow states its own convention and carries `row_signs: "positive_for_inflow"`. Budget states its own convention in text. Capital gains is the one report whose text and JSON both claim Beancount signs. Budget's JSON makes the same claim too: it also carries `balance_signs: "beancount"`, while its `actual` is positive for income (`Income:Salary` earned 3000 reads `"actual": "3000.00"`). Its text heading is correct.

Environment: main `29cc35f14`, `bea 0.4.1` from the checkout (`uv run bea`), Python 3.12.14, macOS 26.5.1. The run used an isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME` with `BEA_NO_UPDATE_NOTIFIER=1`, `BEA_FILE`/`BEA_TOKEN` unset, stdin closed, no TTY, and a scratch working directory. Every command exits 0 with empty stderr. Reproduced in fresh processes. The ledger hash was unchanged.

## Expected

- The capital-gains text heading states its own convention in place of the Beancount-signs sentence, for example: `Gain is proceeds minus basis: positive for a gain, negative for a loss.`
- The capital-gains JSON carries `gain_signs: "positive_for_gain"` and no `balance_signs`, because it reports no account balance.
- The budget JSON drops `balance_signs`, because it reports no account balance either. It adds `actual_signs: "positive_as_spent_or_earned"`, the JSON form of its text heading. `variance_signs` stays.
- No figure changes. CSV is unchanged, since it prints no heading.

## Root cause

- `cli/src/cli/commands/report.py:808` calls `_heading("Capital Gains", data)` with no `convention`. `_heading` (`:273`) then falls back to "Account balances use Beancount signs (credits negative)". The budget (`:993`) and cash-flow (`:903`) callers pass their own convention.
- `cli/src/bea_engine/report.py:2302`: `_metadata` sets `"balance_signs": "beancount"` for every report. Capital gains (`:1520`) and budget (`:463`) add no key that overrides it. The income statement (`:349`, `net_profit_signs`) and cash flow (`:1906`, `row_signs`) add one.

## Fix

Owner `cli`.

- Pass a `convention=` for capital gains at `commands/report.py:808`.
- In `bea_engine/report.py`, drop `balance_signs` from the capital-gains and budget metadata. Add `gain_signs` to capital gains and `actual_signs` to budget.
- Say so in `cli/docs/USAGE.md`: in the capital-gains paragraph (`:2147`), that gain is proceeds minus basis, positive for a gain, the opposite of the booked gains posting's sign; and in the budget bullet (`:2241`), add `actual_signs`.
- Tests:
  - Capital gains: assert the heading in `cli/tests/test_report_capital_gains_frontend.py` and the JSON keys in `cli/tests/test_report_capital_gains.py`.
  - Budget: assert the JSON keys in `cli/tests/test_report_budget.py`.
  - Revert the fix and watch them fail.
- Run `make check-all` in `cli/`.

Nothing in the repository reads `balance_signs`: `grep -rn balance_signs` finds only the producer.

No REST/GraphQL/MCP change. Hosted capital gains (`backend-cluster/backend-v2/src/features/ledger/utils/gains.ts:391`) computes the same proceeds-minus-basis gain and makes no sign claim.

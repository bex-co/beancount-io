# D9: OAuth, MCP, and well-known paths are never challenged at the Cloudflare edge

From `/pm-brainstorm for w1` 2026-10-06 ([ADR 019](../../docs/adrs/ADR019-backend-v2-mcp-host-compatibility.md) D9). ~45 minutes, no code. A1.

Hosts call `/.well-known/*`, `/api-gateway/oauth/*`, and `/api-gateway/mcp` from their own servers, with tight timeouts (Claude: 10 s for discovery, registration, and token calls; 30 s for refresh). A bot challenge, JavaScript interstitial, or WAF block there fails a host's sign-in before the request reaches backend-v2, so our logs never see it.

1. Review the `beancount.io` zone's WAF custom rules, managed rules, Bot Fight / Super Bot Fight mode, and any challenge rules for those three path families (Cloudflare CLI or dashboard).
2. Exempt them from interactive challenges if anything applies; throttling stays in backend-v2's credential-keyed rate limiter. The dashboard's consent pages stay browser traffic under the dashboard's rules.
3. Verify with server-side requests that send no browser headers: discovery `GET`s answer 200, `POST /api-gateway/mcp` answers 401 with `resource_metadata`, and no response is a challenge page.
4. Record the result, with date, in ADR 019's implementation status (D9 row). Do not record rule ids or account identifiers on the board.

---

**Resolved 2026-10-06** — Reviewed the `beancount.io` zone: no custom WAF or rate-limit rules, Bot Fight mode and JavaScript detections off, Cloudflare's managed free ruleset and DDoS protection in place; Browser Integrity Check on and Security Level medium, both able to challenge a host's server-side calls by User-Agent or source-IP reputation. Added one WAF custom rule that skips Browser Integrity Check and Security Level for `/.well-known/*`, `/api-gateway/oauth/*`, and `/api-gateway/mcp` (managed rules unchanged). Verified with server-side requests carrying no User-Agent, `python-httpx`, and `Go-http-client`: discovery 200, MCP 401 with its `resource_metadata` pointer, OAuth endpoints answering JSON, no challenge pages; the homepage unaffected. Recorded in ADR 019's progress table, shipped in the commit that closes this note (`docs`, Cloudflare zone configuration).

# A signal during Beancount parsing is swallowed: a stopped write can still land, or staging copies leak

**Severity: minor. Owner: cli. Estimate: ~1h. A1:** a write the user stopped must not commit. Continuous CLI QA, 2026-10-02 (round 2); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed unless a PTY is stated. Reproduced at least twice from pristine fixtures.

Fixture: `main.bean` = a valid base + ~60,000 small transactions + `include "inc.bean"`; `inc.bean` empty.

```sh
bea --file /abs/main.bean add note --date 2021-03-01 --account Assets:Cash --comment x --into inc.bean --allow-errors &
# after the first validation load (..bea-*.tmp.picklecache appears), wait ~1.5 s, then:
kill -TERM $!     # or -INT
```

Actual (4/4 runs, SIGTERM and SIGINT, delays 1.3–1.7 s): the frontend exits 143/130 about 3.8 s after the signal, but `inc.bean` now contains the note. Without `--allow-errors` on a ~120k-transaction ledger: the frontend waits exactly 5.0 s, SIGKILLs the engine, and leaves three ~9 MB `.bea-*.tmp` files plus a picklecache (3 of 6 sweeps). SIGTERM sent directly to the engine prints `…grammar.py:276: SystemExit: 143` as a ledger validation error, exit 1.

Expected: USAGE — "If the command is stopped, the staging copy goes with it: the engine is told to unwind." A stopped write does not commit and leaves no staging files.

Cause: `cli/src/bea_engine/__main__.py:16–18` turns SIGTERM/SIGHUP into `SystemExit` (SIGINT → `KeyboardInterrupt`); upstream's C parser catches exceptions raised in builder callbacks (beancount `grammar.y:77–101`), records them as `ParserSyntaxError`, and keeps parsing. Under `--allow-errors` that error joins the "before" set (`cli/src/bea_engine/ledger/write.py:530`), so the write commits (`write.py:843`); otherwise the load overruns `_CLEANUP_GRACE_SECONDS = 5.0` (`cli/src/cli/engine/launch.py:325`) and `child.kill()` (`launch.py:377`) skips cleanup.

Fix/acceptance: have the handler set a terminating flag as well as raise; check it after each `managed_load.load_file` and immediately before `os.replace`/`os.link`; treat `SystemExit`/`KeyboardInterrupt` parser errors as termination. A SIGTERM/SIGINT at any point before replacement leaves the destination unchanged, no `.bea-*` files, and exit 143/130 — on a 120k-transaction ledger with and without `--allow-errors`.

Dedupe: follow-up gap in `w3/done/440` (`9623bb07`), whose tests signal outside parser callbacks. No `.pm` item covers grammar-swallowed `SystemExit` or the 5 s grace.

---

**Resolved 2026-10-04** — a SIGTERM, SIGHUP or SIGINT during Beancount parsing now ends the engine at once with 128+signal, removes staging copies and their cache files, and writers re-check for a pending stop before committing, so a stopped write can no longer land. `tests/test_engine_signal_during_parse.py` covers it. Shipped in the commit that moved this note (`cli`).

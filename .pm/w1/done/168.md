# An `import-id` conflict inside the import file tells the user to edit a ledger entry that doesn't exist

**Severity: minor. Owner: cli. Estimate: ~30m. A1:** banks reuse IDs within one export; the advice must point at the file. Continuous CLI QA, 2026-10-03 (round 16); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command with timeouts, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced twice with a working control. Found by a regression hunt over shipped fixes.

Ledger opens `Assets:Bank` and `Expenses:Food`; `in3.csv`:

```csv
Date,Amount,Description,Id
2024-06-03,-1.00,Tea,Q9
2024-06-03,-2.00,Tea,Q9
```

```sh
bea --json --file /abs/main.beancount import /abs/in3.csv --csv date=Date,amount=Amount,narration=Description,id=Id --account Assets:Bank --default-account Expenses:Food --apply
```

Actual: exit 4 "A stable ID already matches a **ledger entry** with different data — edit or remove that entry, change the bank ID, or drop the row."; details "Row 2 (conflict): Stable ID matches an entry with different transaction data." — no `Q9` exists in the ledger. The human preview correctly shows "Matches row 1 of this import"; only the reason text and `--apply` guidance are wrong.

Cause: `cli/src/bea_engine/importing.py:269` (reason) and `:399–405` (guidance) don't check whether the match came from the same batch (`batch_rows`, `:296`). Sibling of `c8109def` (`w3/383`).

Fix/acceptance: when the match is in `batch_rows`, say "Stable ID repeats row N of this import with different data" with source-file guidance; ledger-conflict wording unchanged.

---

**Resolved 2026-10-04** — an `import-id` repeated inside one export is now reported against the earlier import row, with source-file guidance, instead of telling the user to edit a ledger entry that does not exist. Tests in `tests/test_import_conflict_tally.py` cover it. Shipped in the commit that moved this note (`cli`).

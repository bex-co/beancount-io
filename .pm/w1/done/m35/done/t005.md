## Verdict

**Confirmed, fixed.** `listPublicKeys` is now registered as `execute: executeListPublicKeys`. The wrapper was not needed for typing: `McpToolDescriptor.execute` takes `McpRequestContext`, which the executor already accepts, and `yarn typecheck` passes. Both list executors now parse their input once at the top, as the other `mcp-*.ts` handlers do, rather than inside the `runToolSafely` closure. The SDK validates against `inputSchema` before `execute` runs, so moving the parse changes no reachable behavior. `mcp-list-tools.test.ts` and `tools-only-journey.test.ts` pass unchanged. backend-v2 `typecheck`, `lint`, and `test` (5074 tests) pass. No new test: this is a behavior-preserving refactor covered by the existing list-tool tests.

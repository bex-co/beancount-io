## Objective

REST answers `CONFIGURATION_ERROR` with a single non-500 status so clients and monitors stop counting operator setup as a server crash.

## Context

- `backend-cluster/backend-v2/src/shared/errors/error-category.ts`: `[ErrorCategory.CONFIGURATION_ERROR]: 500`; `SERVICE_UNAVAILABLE` already maps to 503.
- MCP mapping: `src/features/ai-agent/api/mcp-errors.ts`.

## Steps

1. Choose the status (503 is the expected one; record the reason in a code comment and the API docs).
2. Change the mapping and update the OpenAPI responses that list it.
3. Check monitoring/alerting code that keys on 500 for these routes.

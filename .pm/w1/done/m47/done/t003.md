## Objective

The operator can restore a user's access with a single admin call that returns a one-time reset link built from the existing reset-token flow.

## Context

- Admin API: `backend-cluster/backend-v2/src/features/admin/api/` (`admin-api-middleware.ts` checks `x-admin-token`; `login-as-handler.ts` is the closest pattern).
- Password reset: `src/features/auth/service/auth-service.ts` and `auth-mail-service.ts`, tests in `src/features/auth/service/__tests__/auth-service-reset-password.test.ts`.
- The link must use the deployment's own dashboard URL (`config.dashboard.url`).

## Steps

1. Add a route (e.g. `POST /api/admin/password-reset-link`) that takes a user identifier and returns a one-time reset link from the same token store the mailed flow uses.
2. Never log the link or token.
3. Add an admin error for an unknown user.

## Files

- `backend-cluster/backend-v2/src/features/admin/api/` (new handler, registration, schema)
- Tests beside it

## Acceptance criteria

- [x] A valid `ADMIN_TOKEN` returns a link that resets the password once; a second use fails (test).
- [x] A missing or wrong `ADMIN_TOKEN` is refused; an unknown user gets a clear admin error (tests).
- [x] No log line contains the token (test).

## Out of scope

- A dashboard UI for operators.

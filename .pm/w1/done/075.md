# Write locks are case-sensitive on macOS, so writers using differently-cased paths can lose an add (partly verified)

**Severity: minor. Owner: cli. Estimate: 30–60m. A1:** concurrent agents writing one ledger must not silently lose entries. Continuous CLI QA, 2026-10-02 (round 2); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed unless a PTY is stated. Reproduced at least twice from pristine fixtures.

Mechanism (verified): `cli/src/bea_engine/ledger/write.py:247` keys the write lock by `os.path.normcase(str(file.resolve()))`. On macOS `normcase` is the identity and `Path('/USERS').resolve()` stays `/USERS` while naming the same inode as `/Users`, so `--file ~/Books/main.bean` and `--file ~/books/main.bean` take different locks on a case-insensitive APFS volume (the macOS default).

Consequence (reproduced through the equivalent uncoordinated condition): 12 concurrent `bea add note` writers given distinct lock directories (`XDG_CACHE_HOME`), 10 trials, lost 4 notes in total — e.g. two writers exited 0 but their notes were missing. The final check in `replace_checked` (`write.py:829–843`, compare stat/bytes then `os.replace`) is check-then-act and does not close the window.

Unverified: the mixed-case path itself, because the QA volume is case-sensitive APFS and mounting a case-insensitive image was not available. Confirm on a default macOS volume first.

Expected: USAGE says locks are "keyed by each file's resolved absolute path", and the PRFAQ promises no lost concurrent update between participating writers; the `normcase` call shows case-insensitive filesystems were meant to be handled (it only works on Windows).

Fix/acceptance: key the lock by file identity (parent directory `(st_dev, st_ino)` plus case-folded name, or the canonical name via `realpath`/`F_GETPATH` on darwin). On case-insensitive APFS, 12 concurrent adds through mixed-case paths all land or exit 4. Separately document that non-participating writers can race past the final check.

Dedupe: searched lost write, TOCTOU, `replace_checked`, case-insensitive, normcase, lock — nothing (`w3/434` is `format -i` lacking a lock).

---

**Resolved 2026-10-04** — write locks are now keyed by the directory's identity plus the case-folded, normalized file name and taken in one order, so differently cased paths to one ledger on a case-insensitive volume share a lock; USAGE documents that non-bea writers can still race the final check. `tests/test_write_lock_identity.py` covers it. Shipped in the commit that moved this note (`cli`).

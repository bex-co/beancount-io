# `add transactions --from -` leaks raw Python errors (exit 1) for undecodable, deeply nested or huge-integer stdin

**Severity: minor. Owner: cli. Estimate: ~20m. A1:** input errors must be usage errors with actionable text. Continuous CLI QA, 2026-10-03 (round 6); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1 (Beancount 3.2.3), Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed unless piping JSON. Reproduced twice with a working control; compared against native `bean-check`/`bean-query`.

```sh
printf '[{"date":"2026-02-01","narration":"caf\xe9"}]' | bea --file /abs/main.bean add transactions --from -     # 'utf-8' codec can't decode byte 0xe9… (LANG=C: …surrogates not allowed)
python3 -c 'print("["*100000+"]"*100000)'      | bea --file /abs/main.bean add transactions --from -     # maximum recursion depth exceeded…
python3 -c 'print("["+"9"*5000+"]")'            | bea --file /abs/main.bean add transactions --from -     # Exceeds the limit (4300 digits)…
```

UTF-16 on stdin gives `Invalid JSON … Expecting value`. All exit 1 / `validation`. Control: the same bytes from a file give exit 2 `Cannot decode '…' as UTF-8: invalid continuation byte at byte 38…`; malformed JSON gives exit 2.

Cause: `_load_transactions_json` (`cli/src/cli/commands/add.py:476–501`) reads stdin as text with no `UnicodeDecodeError` mapping (`:479`) and catches only `json.JSONDecodeError` (`:501`).

Fix/acceptance: read `sys.stdin.buffer`, decode `utf-8-sig` through `decode_error_message`, map `RecursionError`/`ValueError` from `json.loads` to `UsageError`. All four cases exit 2 under a `usage` envelope without raw codec/recursion text. Optionally reject duplicate JSON keys (`object_pairs_hook`) in the same change — today `{"amount":"10 USD","amount":"99 USD"}` silently writes 99 USD.

Dedupe: `w3/283` fixed the file path only; `w2/025` covered OS errors.

---

**Resolved 2026-10-04** — `add transactions --from` input is now decoded as UTF-8 regardless of locale, and undecodable, UTF-16, deeply nested, over-long-integer or duplicate-key JSON is a usage error (exit 2) with an actionable message instead of a raw Python error. `tests/test_transactions_stdin_input_errors.py` covers each case. Shipped in the commit that moved this note (`cli`).

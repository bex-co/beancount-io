# A dry run accepts a `requestId` the commit will refuse

**Bug · backend-v2 · minor · ~20m · A1.** From `/qa-find-bugs-mcp`, 2026-11-08, production `beancount-mcp 1.0.0`.

- **Repro:** call `appendLedgerText` with `dry_run: true`, valid text, and a `requestId` of `""` or of 10000 characters. It returns `ok: true` with `valid: true`. `docs/mcp.md:1957` documents `requestId` as 1–200 characters, and the commit refuses it with "requestId must be 1-200 characters" (`entry-write-idempotency.ts:52-56`).
- **Why it matters:** under "The preview rule", an agent approves a `valid: true` preview and resends the same arguments with `dry_run: false`. An argument the commit will refuse should already fail the preview.
- **Cause:** `src/features/ledger/service/ledger-entry-service.ts:454,486` pass `requestId: dryRun ? undefined : requestId`, so the bounds check never runs on a dry run.
- **Fix:** check the bounds (`ENTRY_REQUEST_ID_MAX`) at both entry points before dropping the id. A dry run still does not deduplicate. This covers `addLedgerEntries` and `appendLedgerText` on all three surfaces.
- **Check:** a dry run with `requestId: ""` or 201 characters returns the same code the commit does.

---

**Resolved 2026-11-10.** A dry run now refuses a `requestId` outside 1–200 characters with the same `VALIDATION_FAILED` "requestId must be 1-200 characters" that the commit gives. It still records and deduplicates nothing.
- **How:** `runIdempotentEntryWrite` takes a `preview` flag. The shared bounds check runs first, and then the write runs unrecorded. Both entry points, `addBulkEntries` and `appendDirectiveText`, pass their dry-run flag instead of dropping the id, which covers `addLedgerEntries` and `appendLedgerText` on REST, GraphQL and MCP.
- **Tests:** `entry-write-request-id.test.ts` sends both writes `""` and a 201-character id, as a dry run and as a commit, and checks that a dry run with a valid id stores no record. Reverting the fix fails 4 of these.
- **Docs:** `docs/mcp.md` says so. (`backend-v2`)

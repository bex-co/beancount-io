# `bea treeify -o` writes before deciding the run failed: failed runs clobber the destination and same-path input becomes empty

**Severity: minor. Owner: cli. Estimate: 30–45m. A1:** a usage error must leave files untouched. Continuous CLI QA, 2026-10-03 (round 3); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1 (Beancount 3.2.3, beanquery 0.2.0), Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control.

```sh
printf 'IMPORTANT NOTES\n' > notes.txt
printf 'quarterly summary\nno accounts here\n' | bea treeify -o /abs/notes.txt
printf 'Assets:Cash  1\nAssets:Bank  2\n' > bal.txt
bea treeify /abs/bal.txt -o /abs/bal.txt
```

Actual: the first exits 2 ("treeify found no hierarchical column…") but `notes.txt` now holds the piped text; the second exits 2 and `bal.txt` is **0 bytes** (2/2 runs). Control: valid input with `-o` writes the tree, exit 0.

Expected: USAGE "Output destinations" and the exit contract — a usage error (exit 2) leaves the destination untouched; same-path input is refused or read before output is opened.

Cause: `cli/src/cli/commands/treeify.py:27` forwards `-o` to upstream via `capture_native`; upstream `beancount/tools/treeify.py:343` opens the output `"w"` before reading the input (`:342`); bea's no-column `UsageError` (`treeify.py:28–35`) fires after the write.

Fix/acceptance: strip `-o`, capture stdout, write the destination atomically only on success; refuse `-o` resolving to the input file. Both repros leave files byte-identical with exit 2; the valid control still writes.

Dedupe: `w3/done/431` and `w3/m48` guard ledger aliases and existing `.bean` files only; `w3/done/338` added the no-column error without addressing `-o`.

---

**Resolved 2026-10-03** — `bea treeify -o` now parses upstream's grammar itself, writes its destination atomically only after a successful run, and refuses the input file as destination. Tests in `tests/test_treeify_noop.py` cover it. Shipped in the commit that moved this note (`cli`).

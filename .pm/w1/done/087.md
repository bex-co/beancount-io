# `bea format --check` is quadratic on long include chains (86 s for 1,500 files)

**Severity: minor. Owner: cli. Estimate: ~30m. A1:** format gates in CI should scale with ledger size. Continuous CLI QA, 2026-10-03 (round 3); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1 (Beancount 3.2.3, beanquery 0.2.0), Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control.

Generate a chain of N files where each includes the next, then `bea format --check /abs/main.bean`:

| Chain length | Time |
| --- | --- |
| 300 | 3.0 s |
| 600 | 14 s |
| 900 | 32 s |
| 1500 | 86 s |

Control: `bea check` on the 1,500-file chain takes 1.4 s; a typical year/month tree (180 globbed files, 150k transactions) formats in 7.4 s.

Cause: `cli/src/cli/commands/format.py:399–402` re-walks the full include closure from every member file — a pass only needed for directory walks.

Fix/acceptance: compute the closure once per root (or skip the per-member walk for a single root). 1,500-file chain `--check` finishes within a small multiple of `bea check`; directory-walk behaviour unchanged.

Dedupe: no `.pm` hit for format performance or closure re-walk. Lower priority than correctness notes.

---

**Resolved 2026-10-03** — `bea format --check` now walks a long include chain once with a shared visited set, so a 1,500-file chain checks in about `bea check` time (4.3 s, was 86 s). `tests/test_format_closure_scaling.py` counts include lookups. Shipped in the commit that moved this note (`cli`).

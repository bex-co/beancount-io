# On a one-currency ledger with no prices, the balance sheet and trial balance call Beancount's accepted rounding a "Valuation/translation adjustment", while `report cash-flow` calls the same amount a "Rounding residual"

**Severity: minor.** The totals are right; the label is wrong. **Owner:** cli. **Estimate:** 30–45m. **A1:** a coding agent or an accountant reading `bea report balance-sheet` on a USD-only ledger sees `Valuation/translation adjustment (credit): 0.004 USD`. That ledger has no price, no holding and no foreign currency. Nothing in it can be revalued or translated, so the reader goes hunting for an FX or market-value problem that does not exist. The customer `beancount-report-pack` skill passes both statements on as they are.

Found by `/qa-find-bugs-cli w1` on 2026-11-19 (HEAD `c0b711467`, `bea 0.4.1`, macOS 26.5.1, checkout `uv run bea`, engine served from the checkout). Isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier off, no `BEA_FILE`/`BEA_TOKEN`, stdin closed, synthetic ledger. Reproduced in fresh processes from a pristine copy.

## Repro

`main.bean` (`bea check` exits 0, because the split leaves 0.004 USD, inside the 0.005 tolerance Beancount infers from `-6.67`):

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Food USD
2024-01-01 open Expenses:Rent USD
2024-01-01 open Equity:Opening USD
2024-01-01 * "Opening"
  Assets:Cash  100.00 USD
  Equity:Opening
2024-01-02 * "Split bill"
  Expenses:Food  3.333 USD
  Expenses:Rent  3.333 USD
  Assets:Cash   -6.67 USD
```

```sh
bea --file main.bean report balance-sheet
bea --file main.bean report trial-balance
bea --file main.bean report cash-flow
```

## Actual

All three commands exit 0:

- **Balance sheet:** `Valuation/translation adjustment (credit): 0.004 USD`. In JSON, `valuation_adjustment` is `{"USD": "0.004"}` and `equity_reconciled` is `true`.
- **Trial balance:** `Valuation/translation adjustment: 0.004 USD`. JSON and the `--format csv` `valuation_adjustment` row show the same amount, and so does `-x at_cost`.
- **Cash flow:** the same amount appears as `Rounding residual: -0.004 USD`.

The CLI's own arithmetic makes this case easy to hit. `bea add transaction "split" -p 'Expenses:Food 10/3 USD' -p 'Expenses:Rent 10/3 USD' -p 'Assets:Cash -6.67 USD'` writes and exits 0. Afterwards the trial balance prints `Valuation/translation adjustment: 0.003333333333333333333333334 USD`.

Control: the same ledger without the split, or any ledger whose transactions net exactly, prints `0.00 USD` on the balance sheet and no line on the trial balance.

## Expected

The line labelled valuation/translation carries only valuation and translation: a holding's unrealized gain, or a currency's translation (USAGE, Reports: "Valued at market, a holding's unrealized gain and a currency's translation leave the five trees unbalanced"). The rounding that Beancount's tolerance accepted is reported as rounding, as `report cash-flow` already does: `rounding_residual`, and its "Rounding residual" line (w5/1071). On this repro, both statements show the 0.004 USD under a rounding label, with the valuation/translation line at zero. The totals stay as they are, and the five trees still net.

## Root cause

`cli/src/fava/modules/financial_statements.py:239-242` (`balance_sheet`) and `:208-211` (`trial_balance`) derive the adjustment as minus the sum of all the trees. That sum has two parts. One is the market and translation difference the line is meant for. The other is the residual each transaction's tolerance accepted, which is nonzero whenever a transaction balances only within tolerance. `cli/src/bea_engine/report.py` (`_balance_sheet` around `:581-600`, `_trial_adjustment` at `:631`) passes the sum on unchanged. `cli/src/cli/commands/report.py:228` and `:571` then print it as `Valuation/translation adjustment`. The cash-flow report already separates the second part: `_cash_flow` in `cli/src/bea_engine/report.py:1650-1665` adds up each price-free transaction's at-cost residual into `rounding_residual`.

## Fix

In cli: compute the accepted booking residual over the report's window, the same way `_cash_flow` does (the at-cost remainder of every transaction with no `@` price). Report it on the balance sheet and the trial balance as its own `rounding_residual` (JSON, CSV row) with its own line (text), and remove it from `valuation_adjustment`. Keep the `-t` clamp folding (w1/296, w1/298) and the units, `--account` and loader-error withholding rules (w1/287, w5/505) exactly as they are. Update USAGE (Reports) so it says which part each line carries. The hosted statements run on a separate engine (w31/032) and are out of scope; compare them in the fix and file any gap separately.

## Regression

The repro's balance sheet and trial balance, in text, JSON and CSV, show 0.004 USD as rounding and a zero valuation/translation line. The sections still sum to zero, and cash flow is unchanged. The `10/3` add case shows its residual the same way. Existing holdings and FX fixtures (`cli/tests/test_report_trial_balance_nets.py`) keep their adjustment. Each new assertion fails with the fix reverted.

---

**Resolved 2026-11-19** — The balance sheet and the trial balance now split the residual that nets the valued trees (`cli/src/fava/modules/financial_statements.py`, `_split_residual`). The same trees read at cost, less what priced exchanges leave there, give the rounding each price-free transaction's tolerance accepted, converted at the as-of date. The rest stays valuation and translation. On a ledger with nothing to value the whole residual is rounding, digit for digit, so 28-digit amounts from `bea add` leave no stray valuation dust. Under `--time` the opening legs carry earlier rounding, except where the clamp keeps its plugs (w5/790), which net it. On the repro, the balance sheet prints `Valuation/translation adjustment (credit): 0.000 USD` and `Rounding residual (credit): 0.004 USD` with the same `-93.330 USD` total equity. The trial balance and `bea balance` print `Rounding residual: 0.004 USD` after Equity and no valuation line. JSON carries `valuation_adjustment: {"USD": "0"}` and `rounding_residual: {"USD": "0.004"}`, CSV a `rounding_residual` row, and cash flow is unchanged. The `10/3` add case reads `rounding_residual: 0.003333333333333333333333334 USD`. Holdings and FX keep their -109 USD adjustment beside 0.008 USD of rounding, in plain, `-t`, `at_value` and `at_cost` forms. The line is withheld wherever the valuation line is. On a 35k-line `bea example` ledger, the split matches an independent Beancount sum of price-free residuals. `beancount-report-pack` ties out the rounding line between its trial balance and balance sheet too. USAGE (Reports) says which part each line carries. Covered by `cli/tests/test_report_rounding_residual.py` (25 of its 26 tests fail with the fix reverted; the other is the unchanged cash-flow control) and two `scripts/skills/test_report_pack.py` tests. `make check-all` passes. The hosted trial balance still folds rounding into its `valuation_adjustment` (`trialBalanceAdjustment`, `backend-cluster/ledger`); filed separately. Shipped in `4abbffea3` (`cli`, `skills`).

# `bea report holdings` drops a commodity's lot-less shares from its market value when nothing quotes it and they share a row with costed lots, so the totals change with the grouping

**Source:** routine cli-qa, 2026-11-19. **Severity:** minor. **Estimate:** 45 minutes. **Owner:** cli, backend-v2 (parity). **A1:** an agent or a person asking "what do I hold and what is it worth" gets `5 HOOL … 90.00 USD` with "valued at cost", but only 3 of the 5 shares have a cost. The other 2, bought `@ 40.00 USD` with no lot, are left out of the market value and out of the total, and nothing names them. Move those 2 shares to a second account and the same report tells the truth: `Market value: 2 HOOL 90.00 USD`. Put them back, or pass `--group-by commodity`, and they disappear again.

Found at `476c5649b` with the checkout's `uv run bea` 0.4.1, macOS 26.5.1, Python 3.12.14, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, stdin closed, stdout piped, synthetic ledger. Reproduced in a fresh process from a pristine copy. The ledger file was unchanged (read-only commands).

## Repro

```sh
cat > main.bean <<'EOF'
option "operating_currency" "USD"
2026-01-01 open Assets:Bank USD
2026-01-01 open Assets:Broker
2026-01-01 open Equity:Opening-Balances USD

2026-01-02 * "Opening"
  Assets:Bank  1000.00 USD
  Equity:Opening-Balances

2026-02-01 * "Buy, lot tracked"
  Assets:Broker  3 HOOL {30.00 USD}
  Assets:Bank   -90.00 USD

2026-02-02 * "Buy, no lot"
  Assets:Broker  2 HOOL @ 40.00 USD
  Assets:Bank   -80.00 USD
EOF
bea --file main.bean check                               # exit 0
bea --file main.bean report holdings                     # exit 1
bea --file main.bean report holdings --allow-errors      # exit 0
```

Control: the same ledger with the second purchase posted to `Assets:Broker2` (opened beside `Assets:Broker`).

## Actual

Strict: `Missing prices for HOOL. … or pass --allow-errors for cost-basis values.` with the detail `HOOL has no USD price at any date; valued at cost`.

With `--allow-errors`:

```
HOOL has no USD price at any date; valued at cost
ACCOUNT        COMMODITY  UNITS   AVG COST  COST BASIS  MARKET VALUE
Assets:Broker  HOOL       5 HOOL  —         —           90.00 USD

  Cost basis:      — (excludes positions without a cost basis)
  Market value:    90.00 USD
```

`--json` gives the same thing: the group has `units` 5 HOOL, `cost_basis: null`, `market_value` `{"number": "90.00", "currency": "USD"}`, `totals.market_value` `{"USD": "90.00"}`, and `missing_price_summary` `["HOOL has no USD price at any date; valued at cost"]`. CSV gives the row `Assets:Broker,HOOL,5,,,,,90.00,USD,,false`. `-x units`, `-x at_cost`, `-x at_value` and `-x EUR` print the same row. `-t` with the only quote after the period end gives the same row, under `earlier holdings valued at cost`.

The control ledger (two accounts) reads:

```
HOOL has no USD price at any date; costed lots valued at cost, the rest shown in units
Assets:Broker   HOOL  3 HOOL  30.00 USD  90.00 USD  90.00 USD
Assets:Broker2  HOOL  2 HOOL  —          —          2 HOOL

  Cost basis:      90.00 USD (excludes positions without a cost basis)
  Market value:    2 HOOL  90.00 USD
```

The control's `--group-by commodity` falls back to the first output: one `5 HOOL` row, `90.00 USD`, `valued at cost`. So the same holdings report different totals depending only on account layout and grouping. The strict hint promises "cost-basis values", and the row then shows cost basis `—`.

## Expected

A row that holds shares no quote values does not count them as zero. Grouping never changes what the totals say. The w1/266 rule already covers these shares: an uncosted position with no quote is shown in its own units, and its leg reads `costed lots valued at cost, the rest shown in units`. Apply that rule here too. The simplest shape: uncosted units join the costed group of their commodity only when the group can value them (a quote at the period end, in the group's currency or the requested one). Otherwise they keep their own row in units, as they do in another account. Then the repro reads the same as the control, in text, `--json` and CSV, by account and by commodity: market value `2 HOOL 90.00 USD`, cost basis `90.00 USD (excludes positions without a cost basis)`. The strict hint reads `to value the costed lots at cost and show the rest in units`. A ledger that does quote HOOL keeps today's single merged row (`5 HOOL`, valued at the quote, cost basis `—`, per w1/253).

## Root cause

- `cli/src/bea_engine/report.py` `_holdings` (around line 816): uncosted units join the one costed group of their commodity (`if len(costed) == 1`) before any valuation, and set the group's `basis_known` false.
- `_value_holding` (around line 714) then values an unquoted group at its basis: "a group that also holds uncosted units counts only its costed part (named missing)". The joined units add to `units` but not to `market`. The missing leg goes into `missing` (valued at cost), never into `in_units`, so `_holdings_valuation` (around line 1048) words it `valued at cost` and the strict hint `for cost-basis values`.
- The `in_units` path (around line 850), which says `shown in units`, is reached only by a group with no costed lots. That is why a second account gets the right answer.
- The hosted composer has the same rule: `backend-cluster/backend-v2/src/features/ledger/utils/holdings.ts` (around line 607, "an unquoted group counts only its costed part, already named missing"). REST, GraphQL and MCP (`LedgerFinanceService.getHoldings`) therefore most likely give the same answer. That was not exercised live in this run.

## Fix

In `_holdings`, decide whether uncosted units join a costed group after checking for a quote that values them. With no quote, give them their own group (`(*prefix, "")`), exactly as when no costed group exists. They are then `in_units`, and the summary and hint follow. Make the same change in `holdings.ts`, so the hosted surfaces keep matching `bea` (w1/292). Update the `USAGE.md` holdings paragraph ("joins the costed group of the same commodity when there is exactly one, is valued at the period-end quote") to say what happens without a quote, and update the matching REST/MCP description if it says the same. Add regression tests:

- `cli/tests/test_report_holdings_uncosted.py`: the repro by account and by commodity, in `--json`, text and CSV, plus the strict hint. Include a quoted control that still merges.
- `holdings.test.ts`: the same ledger.

Both must fail with the fix reverted. Run `make check-all` in `cli/` and the backend-v2 parity gates.

## Blast radius

Searched `_holdings`, `_value_holding`, `_holdings_valuation` and `in_units` callers. Only `bea report holdings` and the hosted holdings composer use this path. The balance sheet and trial balance value through Fava's conversion and show `5 HOOL` for the account, so they are unaffected. When a quote exists, all units are valued, so that case is unaffected too. The merged row's null cost basis is the documented w1/253 design and is not part of this note.

## Dedupe

Searched `.pm/**` for `costed part`, `joins the costed`, `merged group`, `unquoted`, `valued at cost` and `holdings` (open and done). w1/253 introduced the merge (`289009046`). w1/266 added `shown in units` only for groups with no costed lots. w1/288 and w1/292 merge lots costed in different currencies. Blocked w1/257 (cost currencies as cash) and w31/031 (`at_value` for lot-less foreign cash) are different rules. None covers uncosted units absorbed into an unquoted costed group. `git log -S "counts only its costed part"` points only at `289009046`. This is not deployment lag.

**Resolved 2026-11-19** — Uncosted units now join the one costed group of their commodity only when a period-end quote (in the group's cost currency or the requested one) values them; otherwise they keep their own row in units, as in another account. The repro now reads the same as the two-account control by account and by commodity, in text, `--json` and CSV: `2 HOOL` (market value `2 HOOL`, cost basis `—`) beside `3 HOOL` at `90.00 USD`, totals `Market value: 2 HOOL 90.00 USD` and `Cost basis: 90.00 USD (excludes positions without a cost basis)`, leg "costed lots valued at cost, the rest shown in units", strict hint "to value the costed lots at cost and show the rest in units". A quote only after the `-t` end keeps them apart too; a quoted ledger keeps the single merged `5 HOOL` row valued at the quote. The hosted composer (`backend-cluster/backend-v2/src/features/ledger/utils/holdings.ts`, behind REST, GraphQL and MCP) applies the same rule. `cli/docs/USAGE.md` says what happens without a quote; the REST holdings description never stated the join rule, so it is unchanged and the v1 OpenAPI snapshot has no drift. Covered by `cli/tests/test_report_holdings_uncosted.py` (six tests fail with the fix reverted; the quoted and second-account controls pass either way) and the `uncosted units beside an unquoted costed group` block in `holdings.test.ts` (four fail with the fix reverted). `make check-all` and the backend-v2 typecheck, format, dead-code, unit and OpenAPI gates pass.

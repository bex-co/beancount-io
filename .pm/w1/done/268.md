# `bea report cash-flow` counts card purchases that move no cash as operating outflows and financing inflows

Found by `/qa-find-bugs-cli w1` on 2026-11-15 (HEAD `f90ff63ec`, `bea 0.3.1`, macOS 26.5, checkout `cli/.venv/bin/bea`, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, synthetic ledgers). Severity: minor. Net change, opening and closing cash are correct, but the activity rows are not, in text, `--json` and `--format csv` alike. A1/A2: a newcomer or agent asking "where did my cash go" sees every credit-card purchase as cash spent, plus an equal financing inflow that never happened.

**Repro** (synthetic):

```sh
cat > main.bean <<'EOF'
option "operating_currency" "USD"
2026-01-01 open Assets:Bank:Checking USD
2026-01-01 open Liabilities:Card USD
2026-01-01 open Expenses:Food USD
2026-01-01 open Equity:Opening
2026-01-02 * "Opening"
  Assets:Bank:Checking 100.00 USD
  Equity:Opening
2026-01-10 * "Grocer" "on card"
  Expenses:Food 40.00 USD
  Liabilities:Card
EOF
bea --file main.bean report cash-flow
bea --file main.bean --json report cash-flow
```

**Actual.** The command exits 0 and reports Operating `Expenses:Food -40.00 USD` and Financing `Liabilities:Card 40.00 USD` (beside `Equity:Opening 100.00 USD`). Total operating is `-40.00`, total financing is `140.00`, and net change is `100.00`. The `--json` `sections` carry the same rows. A noncash commodity does the same thing. Hours taken from an accrued balance (`Expenses:Vacation 8 VACHR` / `Assets:Employer:Vacation -8 VACHR`, with no cash leg) report `-8 VACHR` operating and `+8 VACHR` investing. On `bea example`'s ledger for `-t 2025`, the totals line reads `Total operating: 0.00 IRAUSD 35,904.93 USD 50 VACHR`.

**Expected.** A transaction with no posting to a cash or cash-equivalent account moves no cash, so it adds no activity row. The repro should show only `Equity:Opening 100.00 USD` (financing), with the same net change, opening and closing. When the card is later paid from Checking, that payment is the cash event, a financing outflow against `Liabilities:Card`. Basis: ADR024 (`docs/adrs/ADR024-cli-cash-flow-report.md`) binds `bea report cash-flow` to the dashboard statement ("same books, same answer") and lists only three deliberate deviations: row order, the refusal policy, and no interval series. The dashboard has excluded wholly noncash transactions from activities since w4/m56 (`d44dc74fc`, 2026-10-23: the public example's 20 card-paid trip purchases no longer read as `-425.83` operating / `+425.83` financing). The CLI never followed.

**Root cause.** cli: `_cash_flow` in `cli/src/bea_engine/report.py` (about lines 1352–1460) iterates every `Transaction` in the window and adds each non-member posting to `flow_books`. It never asks whether the transaction has a leg in `members`, the CCE set that `_cash_accounts` resolves. The `--account` split check in the same loop has the same gap, so `-a Expenses` on the repro is refused (exit 2) because the card purchase "keeps Expenses:Food but leaves out Liabilities:Card", even though that purchase moves no cash.

**Fix.** In `_cash_flow`, skip (for rows, residuals, the priced-exchange refusal and the `--account` split check) any window transaction with no units-bearing posting to an account in `members`. Use the unfiltered membership, as the dashboard's `cashAccountMembership` does. Opening and closing keep accumulating cash postings as they do today. `cli/tests/test_report_cash_flow.py::test_sections_net_equals_cash_change` currently pins the old attribution for its `BASE` fixture (Groceries `-78.20` on the card is listed as operating). Under the fix it becomes Operating `Income:Salary 3000.00` only and Financing `Equity:Opening 4000.00`, `Liabilities:Card -78.20`, with the same net change of `5721.80`. Update `test_transfers_between_cash_accounts_never_appear`'s card comment the same way. Add regressions for a wholly card-paid purchase, a noncash-commodity transaction, and `-a Expenses` over a card purchase (no longer refused). Each should fail with the fix reverted. Update the cash-flow paragraph in `cli/docs/USAGE.md` ("Reports") and ADR024's Decision bullets to say noncash transactions are excluded. backend-v2 has no cash-flow endpoint (the dashboard computes it client-side and backend-v2 only serves the `cash-flow-role` open metadata), so no REST/GraphQL/MCP parity change is needed. Estimate: 45–60 minutes.

**Blast radius.** Only `bea report cash-flow` (text, `--json`, `--format csv`). `capital-gains`, `income-statement` and the balance reports do not read `_cash_flow`. `test_report_cash_flow_native_cash.py::test_large_unchanged_cash_does_not_erase_accepted_cost_rounding` uses a wholly noncash `{{1000.00 USD}}` lot and asserts a `1e-25` net change and residual. Recheck it, because its rounding residual comes from a transaction the fix would exclude. Adjacent, not in this note: the noncash-currency legs inside a cash-touching transaction (the `bea example` payroll's `IRAUSD`/`VACHR` postings beside its USD cash legs) still produce offsetting rows and `0 VACHR` / `0.00 IRAUSD` cells in net change and opening cash. That matches the dashboard's whole-transaction rule, so changing it needs its own decision.

**Dedupe.** Searched `.pm/**` (open, `done/`, `blocked/`) for `noncash`, `non-cash`, `no cash leg`, `cash-flow`/`cash flow` with `card`, `VACHR` and `IRAUSD`. w4/m56 is the dashboard fix (dashboard only). w4/198 covers dashboard conservation after conversion. w5/1050 (CLI `--account` reconciliation) explicitly left m56's scope out ("a separate classifier/model scope intentionally not requested here"). No open item covers the CLI.

---

**Resolved 2026-11-15** — `_cash_flow` now skips any window transaction with no units-bearing posting to a cash account (unfiltered membership, as the dashboard since w4/m56), for rows, the rounding residual, the priced-exchange check and the `--account` split check. The repro reports only Financing `Equity:Opening 100.00 USD` with the same net change, opening and closing, and `-a Expenses` over the card purchase is no longer refused. USAGE.md and ADR024 updated; regressions in `cli/tests/test_report_cash_flow.py` fail with the fix reverted. Shipped in `e81e5768e` (`cli`).

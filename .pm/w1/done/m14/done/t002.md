## Objective

`add` and `import --apply` stop re-aligning entries they did not add; the appended block matches the destination's indentation and number column, and `bea format` stays the only whole-file formatter.

## Context

- `cli/src/cli/ledger_write.py` runs `beancount.scripts.format.align_beancount` over the whole destination after appending (around the `align_beancount` import near line 317). A wider new posting therefore shifts every existing amount column in the file.
- `cli/README.md` ("Write safely and use split ledgers") and `cli/docs/USAGE.md` ("Adding directives") currently advertise this realignment.
- The destination's style is observable: indentation width of the last posting block, and the column at which existing amounts end.

## Steps

1. Detect the destination's posting indentation and amount column from its existing entries (fall back to two spaces and the block's own natural width for an empty file).
2. Render the appended block with that indentation and pad account names so the block's amounts align to the detected column when it fits, otherwise align within the block only.
3. Remove the whole-file `align_beancount` pass from the write path; keep it in `bea format`.
4. Update the two docs to say writes never modify existing lines.

## Files

- `cli/src/cli/ledger_write.py`
- `cli/README.md`, `cli/docs/USAGE.md`

## Acceptance criteria

- [ ] Appending to a four-space-indented file yields a four-space block and a diff of only added lines.
- [ ] Appending a wider account name leaves existing lines byte-identical.
- [ ] `bea format` still realigns the whole file.
- [ ] Atomic replace, lock, and permission behavior are unchanged.

## Out of scope

- Reflowing comments or metadata in existing entries.

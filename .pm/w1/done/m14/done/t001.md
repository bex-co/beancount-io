## Objective

Adopt the repository's existing `import-id` convention in `bea import` so the CLI and the ledger skills deduplicate each other's entries, and retire the 64-hex `bea_import_id` key for new writes.

## Context

- `cli/src/cli/commands/import_.py` stamps `bea_import_id` as a SHA-256 of the export bytes, source account, and row index; default stable-ID keys are `bank_id`, `fitid`, `transaction_id`, `imported_id` (`keys = id_key or [...]`).
- `skills/.claude/skills/beancount-import/references/dedup.md` is normative: native IDs become `<kind>:<native-id>` (for example `ofx:2026050701`); rows without one become `csv:sha256:<first 16 hex>` of `date|amount|RAW DESCRIPTION|account` with an occurrence suffix for identical same-day rows. `beancount-migrate` uses `mint:`, `monarch:`, `qbo:` prefixes with the same hash.
- The skill's exact-match layer treats any `import-id` value as opaque, so prefixes the CLI chooses (for example `bea:`) still interoperate.

## Steps

1. Add `import-id` to the default stable-ID keys and read `import-id-2` as the skill does.
2. When the importer supplies a native ID under one of the known keys, write `import-id: "<key-kind>:<id>"` and stop writing the raw `bank_id` duplicate unless the importer set it as metadata itself.
3. Otherwise compute `csv:sha256:<16-hex>` with the dedup.md normalization and occurrence suffix; use the importer's narration/payee as the raw description input and document which field.
4. Keep matching `bea_import_id` (64-hex) on existing entries so pre-release ledgers still deduplicate; do not write it anymore.
5. Update the preview's duplicate reason text to name the matched `import-id`.

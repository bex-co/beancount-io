# When no CSV date format fits the column, the error blames row 1 and an ISO format the user never chose

**Severity: minor. Owner: cli. Estimate: 30–45m. A1:** import errors must point at the bad row and the fix. Continuous CLI QA, 2026-10-03 (round 8); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command with timeouts, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced twice with a working control.

```sh
printf 'Date,Description,Amount\n01/02/2026,a,-1.00\n15/02/2026,b,-1.00\n31/02/2026,c,-1.00\n' > bad.csv
bea --file /abs/main.bean import /abs/bad.csv --account Assets:Bank --default-account Income:Misc
```

Actual: exit 2, `Row 1 (line 2): cannot parse date '01/02/2026' in column 'Date' with format '%Y-%m-%d'.` — the bad row is row 3 (`31/02/2026`). German month names (`15 Jan 2026, 20 Feb 2026, 15 Mär 2026`) and Sparkasse-style `15.03.26` (`%d.%m.%y` is not in `_DATE_FORMATS`) fail the same way; `--date-format %d.%m.%y` imports the file but the message never suggests it. Control: an explicit `--date-format "%d %b %Y"` correctly names `Row 3 … '15 Mär 2026'`.

Expected: IMPORTING.md — bad dates fail "with the row number and column name"; `--date-format` is the documented remedy.

Cause: `cli/src/cli/commands/import_.py:470–471` silently replaces a failed inference (`None`) with `"%Y-%m-%d"`; `cli/src/cli/csv_mapper.py:482` (`infer_date_format`) doesn't record which row eliminated the last candidate (from `24204071`).

Fix/acceptance: have inference return the row/value that ruled out the last format; raise a usage error naming it and suggesting `--date-format`. All three files report the actual offending row with no mention of a format the user didn't give; existing inference tests pass.

Dedupe: `w3/263`, `w3/308`, `w4/176`, `w3/385/406` have different causes.

---

**Resolved 2026-10-04** — when no known date format reads the whole CSV column, import now names the row and value that ruled out the last format and suggests `--date-format`, instead of blaming row 1 and an ISO format. `tests/test_csv_date_inference_whole_column.py` covers it. Shipped in the commit that moved this note (`cli`).

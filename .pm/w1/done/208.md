# An unknown short plugin name is accepted: "Plugin not found" is dropped as a document error

**Bug · ledger · major · ~30m · A1.** From `/qa-find-bugs-mcp`, 2026-11-09, production `beancount-mcp 1.0.0`, dry runs only. A typo in a native plugin name silently turns that plugin's checks off, and nothing reports it.

- **Repro:**
  - Run `updateLedgerFiles` with `dry_run: true`, setting `main.bean` to its current content plus `plugin "noduplicate"`. It returns `errorsAfter: 0`, `newErrors: []` and `valid: true`.
  - `plugin "qa_nonexistent_plugin"` gives the same result. Both repeat in fresh requests.
  - **Controls:** `plugin "qa.x"` and `plugin "beancount.plugins.auto_acounts"` each report E8005 at the plugin line with `valid: false` (the w21/902 wording). Local `bea check` refuses all four.
- **Cause:** `backend-cluster/ledger/src/foundation/rustledger/document-validation.ts:47-49` (`isFileNotFound`) matches on code `E8001` alone. `@rustledger/wasm` 0.24.0 uses E8001 both for "Document file not found" and for `Plugin not found: "X"`. `reconcileDocumentErrors` (`:147-154`, called from `engine.ts:807`) then drops the plugin error: `extractDocumentPath` returns `null` for it, and when `repoPaths` is undefined the error is dropped anyway. The code has been there since ca9a50d2e.
- **Fix:**
  - Have `isFileNotFound` also require `/Document file not found: /`.
  - Route "Plugin not found" through `explainUnknownPlugins` (`plugin-typos.ts`), so a bare name gets the "Unknown plugin … / Did you mean `noduplicates`" text, and attach the source line the way E8005 already does.
  - This one fix reaches `checkLedger`, every write preview and validation, the errors resource, and the dashboard on REST, GraphQL and MCP.
- **Check:**
  - `document-validation.test.ts`: a plugin E8001 is kept both with and without `repoPaths`.
  - `plugin-typos.test.ts`: `noduplicate` suggests `noduplicates`.
  - Add a `verify:rustledger` case.

---

**Resolved 2026-11-10.** An unknown bare plugin name is now reported, not dropped. `isFileNotFound` requires the "Document file not found: " message as well as E8001. The engine also uses E8001 for `Plugin not found: "X"`, and that used to be filtered out with the document checks. Each step below then applies to the plugin error as it does to E8005.
- **Located:** the locator puts it on its `plugin` line in the entry point.
- **Explained:** `explainUnknownPlugins` rewrites it to "Unknown plugin "noduplicate": Beancount.io can't run this plugin" with the hint "Did you mean "noduplicates"?". The hint appears when a shipped module is within two edits; `qa_nonexistent_plugin` gets no suggestion.
- **Result:** the ledger reads `valid: false` in `checkLedger`, every write preview, the errors resource and the dashboard, on REST, GraphQL and MCP.
- **Tests:** unit cases in `document-validation.test.ts` (kept with and without `repoPaths`), `plugin-typos.test.ts` and `url-include-errors.test.ts`; reverting the fix fails 4. `yarn verify:rustledger` gained live checks: the raw engine still reports E8001, which reproduces the bug; both names are reported at line 1 with the right hint; and the real `noduplicates` still loads cleanly. (`ledger`)

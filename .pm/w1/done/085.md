# Unexpected engine exceptions lose their type and traceback: a bad BQL date literal exits 1 and `--debug` cannot locate it

**Severity: minor. Owner: cli. Estimate: ~30m. A1:** malformed queries must be usage errors agents can correct. Continuous CLI QA, 2026-10-03 (round 3); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1 (Beancount 3.2.3, beanquery 0.2.0), Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control.

```sh
bea --file /abs/main.bean query "SELECT date WHERE date > 2020-99-01"     # exit 1, "Error: month must be in 1..12"
bea --file /abs/main.bean query "SELECT date WHERE date > 2020-02-30"     # exit 1, "Error: day is out of range for month"
bea --debug --file /abs/main.bean query "SELECT date WHERE date > 2020-99-01"
```

Actual: exit 1 with a bare message; the `--debug` traceback ends at `cli/src/cli/engine/launch.py:316` with no beanquery frame. Control: `SELEC x`, an unknown column, an unknown table all exit 2 `usage` with "Cannot run this BQL query: …" and a caret line.

Expected: a malformed query is exit 2 naming the query; `--debug` "include[s] exception tracebacks" (USAGE) — here the engine-side `beanquery/parser/__init__.py:26` `date.fromisoformat` frame.

Cause: `cli/src/bea_engine/protocol.py:111–113` wraps any exception as `EngineError(str(exc))` with no traceback or type; `cli/src/bea_engine/query.py:686–730` `_executed` doesn't map parse-time `ValueError`.

Fix/acceptance: pass `traceback=traceback.format_exc()` and prefix the exception type in the catch-all; map parse-time `ValueError` to `_usage_error`. Both queries exit 2 with "Cannot run this BQL query: invalid date literal…"; `--debug` shows the beanquery frame.

Dedupe: [067](./067.md) (interactive tracebacks) and `w3/353`, `358`, `447` cover other exception types; nothing covers the catch-all or date literals.

---

**Resolved 2026-10-04** — impossible BQL date literals are now usage errors (exit 2) naming the query, and unexpected engine errors keep their exception type plus the engine-side traceback so `--debug` can locate them. `tests/test_engine_unexpected_errors.py` covers it. Shipped in the commit that moved this note (`cli`).

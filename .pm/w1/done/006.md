# Revoked CLI token: `cloud status` vs `cloud ledger *` disagree on the auth message

**Severity:** minor  
**Package:** `cli`

## Repro

With a still-present credentials file whose JWT has been remotely revoked (unexpired `expireAt`):

- `bea cloud status` → exit 3, `Not authenticated. Run 'bea cloud login'.`
- `bea --json cloud ledger list` → exit 3, `Not authorized (This endpoint requires a credential: …). Run 'bea cloud login'.`

## Expected

Same dead credential yields one auth story (and ideally guidance to re-login / check `BEA_TOKEN`), so scripts branching on `error.message` prefix do not fork by command.

## Actual

`cloud_status` treats a null profile payload as “Not authenticated”; generated ledger commands surface the server’s 401 body via `error_from_status` as “Not authorized (…).”

## Fix

Normalize revoked/invalid bearer handling in `cloud status` (and any other `unwrap_or_none` profile path) to the same AuthError shape as `error_from_status` for 401/403, or document the deliberate difference. Add a transport mock covering revoked token on status + list.

~30m

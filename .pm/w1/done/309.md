# After a signed-out managed-price fetch fails, `bea` keeps saying "Not logged in" for 60 seconds to a run that has `BEA_TOKEN` set

**Bug · cli · minor · ~30m · A2.** From routine cli-qa, 2026-11-19. A ledger with a managed price include, read while signed out, fails with `fetch failed (auth): Not logged in. Run bea cloud login, or set/replace BEA_TOKEN.` A user who follows that advice and reruns at once is still refused with the same "Not logged in" text, though the new run has a valid token. The cached error is replayed until the feed's 60-second retry window ends. Advice that seems not to work is the kind of thing that makes a newcomer give up on managed prices.

Environment: main `adb290b19`, macOS 26.5.1, `bea 0.4.1` from the checkout (`uv run bea`), a fresh isolated `BEA_CONFIG_DIR` and `XDG_CACHE_HOME`, stdin closed, no TTY, production price endpoint.

Repro (`main.bean`):

```beancount
option "operating_currency" "USD"
include "https://beancount.io/prices/BTC-USD"
2024-01-01 open Assets:Bank USD
2024-01-01 open Assets:Crypto BTC
2024-01-01 open Equity:Opening
2024-01-02 * "Fund"
  Assets:Bank  4000 USD
  Equity:Opening
2024-01-02 * "Buy"
  Assets:Crypto  0.1 BTC {40000 USD}
  Assets:Bank  -4000 USD
```

1. With no `BEA_TOKEN` and no stored login: `bea --file main.bean check` exits 1 with `main.bean:2: managed price source unavailable: … fetch failed (auth): Not logged in. Run bea cloud login, or set/replace BEA_TOKEN.` `bea price status` shows `unavailable` and `NEXT REFRESH` 60 seconds out.
2. Within that minute, with a valid `BEA_TOKEN` in the environment (`bea cloud status` confirms the account): `bea --file main.bean check` exits 1 with the same "Not logged in" error. `bea price status` still shows the auth error and the same `NEXT REFRESH`.
3. After the window, the same command with the same token exits 0, and the source reads `recent` with a fetched revision.

**Root cause:** `resolve_feed` in `cli/src/bea_engine/managed_price_cache.py` writes every fetch failure to the feed's `head.json` with `next_refresh_at = now + RETRY_SECONDS` (60). Until then, it serves the head, and with it the last error, without fetching, whatever credential the current process carries. Only `bea price refresh` clears the window (`zero_next_refresh`). Neither a new `BEA_TOKEN` nor a successful `bea cloud login` clears it.

**Do:** do not hold an auth failure against a run that brings different credentials. For example, record on the head whether the failed fetch carried a credential, or a fingerprint of it (never the token). Bypass the retry window when the last error is an auth failure and the current run's credential differs. Have `bea cloud login` and `bea cloud logout` zero the window for auth-failed feeds, as `price refresh` does. Keep the window for provider and network failures.

**Done when:** steps 1 and 2 above, run back to back, end with step 2 exiting 0 and `price status` showing a fetched revision and no error. A provider failure (simulated with a local opener in a test) still waits out the window. A cli test fails with the change reverted, and `make check-all` passes.

**Blast radius:** every command that loads a ledger with a managed include (`check`, `list`, `query`, `report`, `balance`, `import`, writes), since all of them go through `resolve_feed`. `--offline` is unaffected. Working control: `bea price refresh` with the token, run right after step 1, fetches at once.

**Dedupe:** searched `.pm/**` for `fetch failed (auth)`, `replace BEA_TOKEN`, and retry window with login or token. [w3/387](../w3/done/387.md) and [w3/433](../w3/done/433.md) fixed the wording of this error, not its caching. [w5/1136](../w5/1136.md) is the hosted dashboard's signed-out refresh, a different surface.

**Unverified:** the `bea cloud login` device flow itself (this run used `BEA_TOKEN`); Windows and Linux.

---

**Resolved 2026-11-19** — an auth failure now records on the feed head a fingerprint of the credential that fetch carried (a truncated SHA-256 of the bearer, `none`, or the login problem the frontend reported; never the token), and the retry window holds only while a run brings that same credential. A new `BEA_TOKEN`, a `bea cloud login`, or a `bea cloud logout` changes the credential, so the next load fetches at once; no separate login or logout hook is needed. Provider, network, 403 and 404 failures still wait out the window. Steps 1 and 2 of the repro, run back to back against production, now end with `check` exiting 0 and `price status` showing a fetched revision and no error. Regression tests are `TestAuthFailureRetryWindow` and `test_bea_token_set_after_a_signed_out_failure_loads_at_once` in `cli/tests/test_price.py`, which fail when the bypass is removed. Shipped in `94a53b4e4` (`cli`).

# `list pad` shows two columns both headed `SOURCE` when any pad is generated

**Severity: minor. Owner: cli. Estimate: ~10m. A1:** scripts read tables by header. Continuous CLI QA, 2026-10-03 (round 6); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1 (Beancount 3.2.3), Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed unless piping JSON. Reproduced twice with a working control; compared against native `bean-check`/`bean-query`.

With any generated pad in the result (e.g. a controlled plugin adding a `Pad` with `new_metadata("<padgen>", 0)`, or the [049](./049.md) drift above a real pad), `bea --file /abs/main.bean list pad` prints the header `DATE  ACCOUNT  SOURCE  SOURCE` — the funding account under the first, `generated` under the second.

Cause: `cli/src/cli/commands/list.py:179` uses `SOURCE` for the pad's funding account; `list.py:383` appends a provenance `SOURCE` column.

Fix/acceptance: rename the pad column (e.g. `FROM` / `SOURCE ACCOUNT`) or the provenance column for pads; headers are unique; document any change to plugin-free output.

---

**Resolved 2026-10-03** — `bea list pad` now heads the funding-account column `FROM`, so `SOURCE` is only the provenance column; JSON `source_account` is unchanged. A test in `tests/test_customer_workflows.py` covers it. Shipped in the commit that moved this note (`cli`).

## Objective

Produce the option-level reference from the code so it cannot disagree with `--help`, and fail CI when it is stale.

## Context

- Commands are registered in `cli/src/cli/main.py` (`app.command(...)`, `app.add_typer(...)`) with help panels; Typer can walk the Click command tree (`typer.main.get_command(app)`) to enumerate leaves, parameters, defaults, and help strings.
- `make spec-check` in `cli/Makefile` is the existing drift-gate pattern (pin versus canonical); `make check-all` runs it.
- Generated files in this package are treated as read-only (`src/cli/api/rest_client/`, `commands/cloud/generated/`); `REFERENCE.md` joins that list.

## Steps

1. Add `scripts/gen_reference.py` that walks the command tree and writes `docs/REFERENCE.md`: one section per leaf with the usage line, arguments, options (name, type, default, help), grouped by the top-level panels.
2. Add `make docs` (regenerate) and `make docs-check` (regenerate to a temp file and diff); include `docs-check` in `check-all`.
3. Add a header line to the generated file naming the generator and the version.

## Files

- `cli/scripts/gen_reference.py` (new)
- `cli/Makefile`
- `cli/docs/REFERENCE.md` (generated)
- `cli/CLAUDE.md` (list the file as generated)

## Acceptance criteria

- [ ] Changing an option's help text without running `make docs` fails `make check-all` with a diff.
- [ ] Every leaf command in `bea --help` appears in `REFERENCE.md`.

## Out of scope

- Prose sections; those stay hand-written in USAGE.

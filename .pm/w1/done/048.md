# `bea format` corrupts multi-line strings containing U+2028/U+0085/form feed and never converges

**Severity: major. Owner: cli. Estimate: 30–45m. A1:** formatting must never change ledger data an agent wrote. Continuous CLI QA, 2026-10-02; report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`, synthetic fixtures. Reproduced twice from pristine fixtures.

```sh
python3 -c "open('main.bean','w').write('2024-01-01 open Assets:Cash USD\n2024-01-01 open Equity:Open USD\n\n2024-01-02 * \"Shop\" \"multi\nmid\u2028dle\nend\"\n    Assets:Cash   10.00 USD\n    Equity:Open\n')"
bea --file /abs/main.bean check                                   # exit 0
bea --json --file /abs/main.bean query "SELECT narration"         # "multi\nmid\u2028dle\nend"
bea format -i /abs/main.bean                                      # exit 0, 1/1 formatted
bea --json --file /abs/main.bean query "SELECT narration"
bea format -i /abs/main.bean                                      # again
```

Actual: narration becomes `"multi\nmid\u2028\ndle\n  end"` — a newline and two spaces are injected into the string; `bea check` still exits 0. Every further `-i` exits 0 and adds another newline, so `--check` never goes green; the posting indent is not normalized. stdout mode prints the same altered text.

Expected: USAGE's formatting contract preserves meaning and string contents and is idempotent. Upstream `bean-format` refuses this file with its whitespace-only assertion rather than altering it.

Cause: `cli/src/bea_engine/ledger/formatting.py:132` and `:163` split with `str.splitlines(keepends=True)`, which also splits on U+2028/2029, U+0085, `\x0b`, `\x0c`, `\x1c–\x1e`, while Beancount's lexer counts only `\n`. Lexer line numbers after such a character are off by one, so protect/restore of string continuation lines (`:142`, `:152`, `:164–165`) and the posting reindent (`:149`) hit the wrong lines. Introduced with the `w3/done/415` protect logic (`2a203f5e`).

Fix/acceptance: split on `\n` only in `_aligned` before and after `align_text` (or refuse such files with the existing "could not align… Nothing was written" error). The fixture formats with the narration byte-identical (or exits 1 unchanged); a second `-i` reports 0 formatted; `--check`/`--dry-run`/stdout/`-i` agree. Regression test for U+2028, U+0085, `\x0c` inside a multi-line narration. Same root class as [049](./049.md); can share a change.

Dedupe: `.pm` search for u2028 / line separator / splitlines / multiline string → nearest `w3/done/415`; new edge, not its repro. `git log -S'protected[index] = lines[index]'` → `2a203f5e`.

---

**Resolved 2026-10-03** — `bea format` now splits lines on newlines only, as Beancount does, and keeps lines carrying U+2028/U+2029, U+0085, form feed or similar separators out of the upstream aligner, so such strings survive formatting byte for byte and a second run changes nothing. `tests/test_format_foreign_line_breaks.py` covers stdout, `-o`, `--check` and `-i`. Shipped in the commit that moved this note (`cli`).

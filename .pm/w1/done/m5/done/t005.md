## Objective

Register Beancount mobile as a deterministic first-party public native client and narrow the provider to the authorization-code response flow used by all current first-party clients.

## Context

- `buildStaticClients()` currently returns no static clients when the optional Discourse secret is absent.
- Mobile cannot keep a client secret; PKCE is the protection for its authorization code.
- Dynamic registration remains appropriate for unknown MCP clients but adds unnecessary per-install state for the first-party mobile app.

## Steps

1. Register `beancount-mobile` independently of the optional confidential identity client.
2. Configure native application type, no token-endpoint authentication, authorization-code and refresh grants, code response type, and exact iOS/Android redirect URIs.
3. Configure the provider's supported response types so live metadata no longer advertises implicit authorization.
4. Preserve the confidential Discourse code flow and dynamic client registration for its existing use cases.

## Files

- `backend-cluster/backend-v2/src/config/config.ts`
- `backend-cluster/backend-v2/src/features/oauth/api/oidc-route.ts`
- `backend-cluster/backend-v2/src/features/oauth/api/__tests__/oidc-route.test.ts`

## Acceptance criteria

- [ ] The native client is always present with no secret and only exact registered redirects.
- [ ] Authorization-server metadata advertises code and refresh support without implicit response flows.
- [ ] S256 PKCE remains mandatory for the native client and authorization without a valid challenge fails.
- [ ] The Discourse client and MCP dynamic registration retain their intended behavior.

## Out of scope

- Per-install dynamic registration or native-app attestation.

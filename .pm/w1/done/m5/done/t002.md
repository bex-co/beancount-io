## Objective

Make resource indicators and access-token audiences authorization boundaries rather than telemetry so a token for identity login, an arbitrary resource, or the wrong API surface cannot reach protected operations.

## Context

- `backend-cluster/backend-v2/src/features/oauth/api/oidc-route.ts` currently returns resource-server information for any requested identifier.
- `backend-cluster/backend-v2/src/features/oauth/utils/oidc-verify.ts` warns on an unexpected audience but still resolves the identity.
- The API resource and the time-bounded legacy MCP resource are the only intended resource identifiers during migration.

## Steps

1. Restrict authorization and token issuance to the API resource plus the explicitly documented legacy MCP compatibility resource.
2. Require an exact expected audience at each API surface, including a deliberate policy for the legacy MCP window.
3. Reject missing and unexpected audiences without revealing verification details to callers.
4. Ensure a userinfo/identity-only access token cannot authenticate to GraphQL, REST, or MCP.

## Files

- `backend-cluster/backend-v2/src/features/oauth/api/oidc-route.ts`
- `backend-cluster/backend-v2/src/features/oauth/utils/oidc-verify.ts`
- `backend-cluster/backend-v2/src/server/api/identity.ts`
- GraphQL, REST, and MCP identity entry points as required.

## Acceptance criteria

- [ ] Authorization requests naming an unrecognized resource fail with the standard OAuth error.
- [ ] Every protected API surface rejects tokens with missing, identity-only, legacy-on-the-wrong-surface, or arbitrary audiences.
- [ ] API-audience tokens continue to authenticate across intended GraphQL and REST surfaces.
- [ ] The legacy MCP allowance is isolated, dated, and covered by a removal test or follow-up condition.

## Out of scope

- Operation-level scope enforcement or changing the three-scope vocabulary.

## Objective

Persist the OAuth grant safely and provide one authoritative token manager that refreshes short-lived access tokens without races, token loss, or unnecessary sign-out while offline.

## Context

- `mobile/src/common/vars/session.ts` currently stores one long-lived `authToken` and user ID in SecureStore.
- Public-client refresh credentials must rotate or be sender-constrained; the app must atomically keep the newest token returned by the server.
- Multiple Apollo operations can begin concurrently after foregrounding, so independent refresh calls can invalidate one another.

## Steps

1. Introduce a discriminated OAuth session containing issuer, API resource, client ID, user ID, scopes, token type, access token/expiry, and refresh token while retaining a typed legacy shape for migration.
2. Keep bearer credentials in OS secure storage and validate hydrated sessions against the currently selected server/resource before use.
3. Implement single-flight refresh before expiry, atomically replace rotated refresh credentials, and await durable persistence before releasing waiting requests.
4. Distinguish transient network/server failures from terminal `invalid_grant` or client errors; retain the session for retry while offline and clear only terminally invalid credentials.

## Files

- `mobile/src/common/vars/session.ts`
- `mobile/src/common/apollo/secure-session-storage.ts`
- `mobile/src/common/session-utils.ts`
- New focused OAuth token manager and tests.

## Acceptance criteria

- [ ] Access and refresh credentials never enter AsyncStorage, logs, analytics, or error breadcrumbs.
- [ ] Concurrent callers share one refresh and all receive the same persisted replacement credentials.
- [ ] A rotated refresh token cannot be lost if the app backgrounds or another request starts immediately afterward.
- [ ] Offline/transient failure is retryable without local logout; terminal grant failure tears down the session once.
- [ ] A token is never sent to a server or resource other than the one stored in its session.

## Out of scope

- Multi-account credential vaults or background refresh when the user is not running the app.

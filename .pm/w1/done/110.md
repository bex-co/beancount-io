# Bulk amounts accept `1_000`, Arabic-Indic and full-width digits that single `add` refuses

**Severity: minor. Owner: cli. Estimate: 20–30m. A1:** every write path must accept and refuse the same number spellings. Continuous CLI QA, 2026-10-03 (round 6); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1 (Beancount 3.2.3), Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed unless piping JSON. Reproduced twice with a working control; compared against native `bean-check`/`bean-query`.

`"amount":"1_000 USD"`, `"units":{"number":"٤٥",…}` and `"units":{"number":"１０",…}` each exit 0 and write `1000`, `45`, `10`; meta `{"kind":"number","value":"1_000"}` and `"1e3"` are accepted too. Control: `bea add transaction -p "Expenses:Food 1_000 USD"` and `-p "Expenses:Food ٤٥ USD"` exit 2 `Invalid token`.

Expected: `w3/419`'s goal that every write path accepts the same spellings (finite ASCII decimal); USAGE amount-notation section.

Cause: `require_decimal_notation` (`cli/src/bea_engine/amounts.py:43`) rejects only exponents; Pydantic `Decimal` / `Decimal()` accept underscores and Unicode digits — `amount_shorthand` (`models.py:107`), `metadata_for_write` (`write.py:899/903`).

Fix/acceptance: reuse `parse_decimal_number`'s ASCII-decimal check in `AmountNumber`, the shorthand, and kind:number/amount meta. All three spellings exit 1 with row and field path; `"1000"` still works.

Dedupe: `w3/419` fixed init and custom only; `w5/007`, `w3/259`, `w1/done/m27` covered exponents.

---

**Resolved 2026-10-04** — bulk amounts and tagged number/amount metadata now refuse underscores, exponents and non-ASCII digits, matching `add transaction --posting`. `tests/test_bulk_number_spelling.py` covers it. Shipped in the commit that moved this note (`cli`).

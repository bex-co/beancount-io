# A USAGE.md `doctor context` example is invalid, and the docs test never executes it

**Severity: minor. Owner: cli. Estimate: 20–30m. A1:** documented examples must run exactly as written. Continuous CLI QA, 2026-10-02 (round 2); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed unless a PTY is stated. Reproduced at least twice from pristine fixtures.

`cli/docs/USAGE.md:319` shows `bea doctor context main.bean 2026-01-02`. In a `bea init` ledger this exits 2: `'2026-01-02' is not a valid location` — upstream `FileLocation` (`beancount/scripts/doctor.py:42`) accepts only `[FILE:]LINENO`.

CI misses it: `cli/tests/test_docs_examples.py:79` expects that fence to exit 2 because of an earlier bare `bea query` line, and the fence runs under `bash -e`, so every later line — both `doctor context` lines, `example`, and `treeify < balances.txt` (whose input does not exist) — never runs.

Fix/acceptance: use a valid line-number location; move the bare `bea query` into its own fence (or the end) so every remaining line executes; supply or drop the missing `balances.txt` input. The docs test executes every line of the fence and passes.

Dedupe: no `.pm` hit; text dates to `a90b1706`.

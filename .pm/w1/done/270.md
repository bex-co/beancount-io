# `bea init --existing` writes the machine's absolute path into `AGENTS.md` for an include outside the ledger folder

Found by `/qa-find-bugs-cli w1` on 2026-11-15 (HEAD `daabb3002`, `bea 0.3.1`, macOS 26.5, checkout `uv run bea`, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, synthetic ledgers). Severity: minor. A1/A2: `AGENTS.md` is the file a coding agent reads in every later session, and a ledger folder is often a git repository shared across machines. A shared price or accounts file kept beside the books folder (`include "../shared/prices.beancount"`) is a common layout.

**Repro** (synthetic):

```sh
mkdir -p e/books/years e/a-shared && cd e/books
printf 'option "operating_currency" "EUR"\nplugin "beancount.plugins.auto_accounts"\ninclude "years/*.beancount"\ninclude "../a-shared/prices.beancount"\n' > ledger.beancount
printf '2024-01-01 * "x"\n  Assets:Bank 1 EUR\n  Income:Job\n' > years/2024.beancount
printf '2024-01-01 price USD 0.9 EUR\n' > ../a-shared/prices.beancount
bea --no-input init ledger.beancount --existing     # exit 0
sed -n 3,5p AGENTS.md
bea --json --no-input init ledger.beancount --existing  # after removing AGENTS.md/CLAUDE.md: same in data.files
```

**Actual.** `AGENTS.md` reads: ``it includes 2 other files: `/abs/path/to/e/a-shared/prices.beancount`, `years/2024.beancount`. New entries go into `ledger.beancount` unless a write names an included file with `--into` (for example `--into /abs/path/to/e/a-shared/prices.beancount`).`` The JSON `data.files` carries the same absolute path beside the relative ones. Once the folder is cloned or moved, that path names nothing, and it shows the author's home directory and user name to anyone the repository is shared with. Because the list is sorted by absolute path, the outside file can come first, and then the `--into` example itself is the absolute path.

**Expected.** Every listed file is relative to the root's folder, as the include line is written: `../a-shared/prices.beancount`, with the `--into` example in the same form. `bea --file ledger.beancount add price --date 2024-01-02 -c USD --amount '0.91 EUR' --into ../a-shared/prices.beancount` already works (exit 0, written to that file), so the relative form is a working destination. Basis: the m42 contract states that `AGENTS.md` describes the ledger's `include` layout and gives an `--into` example from it (w1/m42 t001, t002). Every other path the generated file states (root, check command, `--into`) is relative to the folder it lives in.

**Root cause.** `cli/src/bea_engine/describing.py` `_relative` (about line 91) returns `path.relative_to(folder).as_posix()` and falls back to `str(path)`, the absolute path, for any file not under the folder. `existing_agents_text` in `cli/src/cli/agent_guidance.py` (about line 133) prints `files` verbatim and takes `files[0]` for the `--into` example.

**Fix.** cli only. In `_relative`, fall back to `os.path.relpath(path, folder)` in POSIX form (`../a-shared/prices.beancount`) when the file is on the same drive. Keep the absolute path only where no relative path exists (another Windows drive). Prefer an example `--into` file inside the folder when one exists. Regressions: a root with one include inside the folder and one at `../`, asserting the `AGENTS.md` text, the `--into` example, and `--json` `data.files`, each failing with the fix reverted. No REST/GraphQL/MCP parity change: `init --existing` is local-only. Estimate: 20–30 minutes.

**Blast radius.** `_relative` has one caller, the `files` list. Plugin locations (`_plugin`, `file`) are absolute in `--json` by design and never reach `AGENTS.md`, so they are out of scope. `bea init --agent-files` for a new ledger never lists includes and is not affected. Working control: includes under the folder (`years/*.beancount`) are listed relative.

**Dedupe.** Searched `.pm/**` (open, `done/`, `blocked/`) for `init --existing` with `absolute`, `outside` and `../`. Only w1/m42 (blocked on its Codex rehearsal) and w1/263 (the wording of kept agent files) touch this command, and neither covers paths outside the folder. `git log -S'def _relative'` shows the fallback has been there since `fd8914559` (w1/m42/t002).

---

**Resolved 2026-11-16** — `describing._relative` now names every included file relative to the root's folder (`../a-shared/prices.beancount`; absolute only when no relative path exists, another Windows drive), and the `AGENTS.md` `--into` example prefers a file inside the folder. Regression `test_an_include_outside_the_folder_is_named_relative_to_it` covers the `AGENTS.md` text, the `--into` example and `--json` `data.files`, and fails with the fix reverted.

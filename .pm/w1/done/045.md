# Bulk typed metadata expands JSON decimals into binary floating-point artifacts

**Severity: minor. Owner: cli. Estimate: 30–45m. A1:** automation must not receive successful writes for typed decimal metadata whose value changes during conversion. Continuous CLI QA, 2026-10-02; no fix implemented.

Environment: `main` at `97dab6b04c6e40e4cf47e0c1d668731d36c7ec41`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13.0, Darwin 25.5.0 arm64. Disposable cwd, absolute ledger path, isolated child config/cache/data and Beanquery history/init, notifier disabled, inherited target/token removed. Closed stdin, no TTY, 15-second subprocess bounds.

Save `main.bean`:

```beancount
2025-01-01 open Assets:Cash USD
2025-01-01 open Expenses:Food USD
```

Save `rows.json`:

```json
[{"date":"2025-05-01","meta":{"rate":{"kind":"amount","number":0.1,"currency":"USD"}},"postings":[{"account":"Expenses:Food","amount":"5 USD"},{"account":"Assets:Cash"}]}]
```

Run:

```sh
bea --json --file /absolute/main.bean add transactions --from /absolute/rows.json
bea --json --file /absolute/main.bean list transaction --limit 1
bea --json --file /absolute/main.bean check
```

Actual: write exits **0** with empty stderr; check exits **0**. Disk and listing contain `0.1000000000000000055511151231257827021181583404541015625 USD` for `rate`, rather than `0.1 USD`. A typed number object `{"kind":"number","value":0.1}` writes the same long number without a currency. Both reproduced twice from pristine fixtures in fresh processes. This is a persisted value change, not display rounding.

Working controls: the identical typed amount using `"number":"0.1"`, and typed number using `"value":"0.1"`, both persist/list exactly `0.1`. Existing ordinary posting-amount float rejection is separate and already implemented. Bare numeric metadata is deliberately supported and must retain its existing behavior.

Expected basis: `cli/docs/USAGE.md` documents tagged numeric metadata with decimal string fields and says amounts use decimal strings, never floats. Malformed typed decimal input should be refused atomically with a useful row/key diagnostic and the exact-string form, instead of silently committing extra digits as accounting data. Preserve supported exact strings and integer convenience where already intended.

Cause: frontend `cli/src/cli/commands/add.py:500` parses JSON floats normally; typed metadata survives in `meta: dict[str, Any]`. `cli/src/bea_engine/ledger/write.py:884–917` calls `Decimal(value["value"])` and `Amount(Decimal(value["number"]), ...)` directly for tagged objects. Passing a Python float exposes its exact binary expansion. The nearby bare-number path deliberately uses `Decimal(str(value))`, while normal amount fields use `require_decimal_notation` through `AmountNumber` and reject floats before conversion. Caller search finds metadata restoration in the transaction/posting/commodity writers and single-add transaction normalization; the reproduced public float entry point is bulk JSON transaction metadata.

Fix/acceptance: validate tagged decimal metadata before conversion, applying the intended decimal-string policy with clear failures rather than `Decimal(float)`. Verify transaction and posting typed amount/number metadata, preserve quoted decimal controls and deliberately supported bare JSON number/boolean metadata, and prove rejected writes leave all ledger files unchanged (including split destinations). Run meaningful regression tests and `make check-all` in `cli/`; no new dependency or API change. Posting metadata is source-traced, not independently exercised in this finding.

Dedupe: searched all `.pm` states for float/typed/numeric metadata, precision and binary artifacts. Completed `w3/260` / `w1/m27` reject posting units/cost/price floats, but this tagged metadata adapter is not protected. Completed `w3/230` deliberately supports bare JSON numeric metadata; its existing test uses 1.5 and this note does not remove that support. `git log -S 'value = Amount(Decimal'` traces this conversion to `a90b1706`; HEAD still contains it. No overlapping open item found.

Evidence: `cli/tmp/qa-20261002-loop/meta_floats.py`, sanitized `captures.jsonl`, and retained synthetic `meta-float.json`. Captures preserve exact argv/cwd, isolated nonsecret environment, stdin/TTY mode, separate streams, exit, duration and file hashes; the driver records written lines and listing values. Public reproduction above is complete. Other OSes, hosted APIs, and unrelated custom directives unverified. No credentials, hosted resources, product fixes or shipping.

---

**Resolved 2026-10-03** — bulk `add transactions` refuses a JSON float (or boolean) in typed `number`/`amount` metadata, naming the row and key, writing nothing without `--partial` and rejecting only that row with it, instead of saving the float's binary expansion; decimal strings, integers and bare numeric metadata are unchanged. `tests/test_bulk_meta_json_numbers.py` covers transaction and posting metadata, `--into`, and `--partial`. Shipped in the commit that moved this note (`cli`).

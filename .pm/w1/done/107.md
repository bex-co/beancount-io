# With stdout closed (`>&-`), commands exit 1 with `'NoneType' object has no attribute 'flush'` after writes land

**Severity: minor. Owner: cli. Estimate: ~15m. A1:** daemons and agents sometimes run with fd 1 closed; a successful write must not report failure. Continuous CLI QA, 2026-10-03 (round 5); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control.

```sh
bea --file /abs/main.bean add transaction --date 2024-02-01 --narration x --posting 'Expenses:Food 1 USD' --posting Assets:Bank >&-
```

Actual: exit 1 with `'NoneType' object has no attribute 'flush'` (JSON category `validation`); the ledger gained the entry on each of four runs. `list`, `query`, `report`, `price status` behave the same. Control: `>/dev/null` exits 0.

Expected: a write never exits 1 after succeeding and no raw `AttributeError` reaches the user; exit 0, or a clear refusal before writing.

Cause: `cli/src/cli/main.py:47` — `_settle_stdout()` calls `sys.stdout.flush()`; Python sets `sys.stdout` to `None` when fd 1 is closed (earlier `print`/`emit` calls silently no-op).

Fix/acceptance: guard `sys.stdout is None`. `add … >&-` writes once and exits 0 (or refuses before writing).

Dedupe: `w3/done/378` recorded this case as "left alone" with a silent exit 0; current behaviour (exit 1 with a raw error after the write) is a follow-up to it.

---

**Resolved 2026-10-03** — commands run with stdout closed (`>&-`) now exit 0 after succeeding instead of reporting `'NoneType' object has no attribute 'flush'`. `tests/test_closed_stdout.py` covers a write in human and JSON mode and a read. Shipped in the commit that moved this note (`cli`).

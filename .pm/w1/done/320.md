# `bea add open` has no `--meta`, so the documented `cash-flow-role: "cash"` fix still means hand-editing the ledger

**Source:** follow-up from routine cli-qa, 2026-11-19, found alongside [319](./319.md). **Owner:** cli and skills. **A1:** when an agent sees a cash account the cash-flow report misclassifies, the fix it is told to apply is `cash-flow-role: "cash"` on that account's `open`. The `beancount-business-metrics` skill cites it at `skills/beancount-business-metrics/SKILL.md:52`. But `bea add open` cannot write that key: `bea add open --help` lists no metadata option, and of the `add` subcommands only `transaction` and `commodity` take `--meta`. The agent has to leave `bea` and edit the open line by hand.

**Paths:** `cli/src/cli/commands/add.py`, `skills/beancount-business-metrics/SKILL.md`.

**Done when:** `bea add open Assets:Revolut --meta 'cash-flow-role:cash'` writes the key under the new `open`, has a regression test, and is documented in `cli/docs/USAGE.md`, and the skill names that command as the fix. Bump the skill suite version if the skill changes.

---

**Resolved 2026-11-19** — `bea add open --meta 'key:value'` writes metadata under the new `open`: `bea add open --date 2026-01-01 --account Assets:Revolut --currency USD --meta 'cash-flow-role:cash'` appends `2026-01-01 open Assets:Revolut USD` with `cash-flow-role: "cash"` under it, `bea check` passes, and `bea report cash-flow` then counts the account as cash. Values keep their types on disk and come back in the add envelope's tagged shape, as for `add transaction` and `add commodity`; a bad key is refused with exit 2 and nothing written. The account a report misclassifies is usually already open, and an account opens once, so `--meta` for an open account is still refused (exit 1). The refusal now names that `open`'s `file:line` and the line to add under it (`To add cash-flow-role: "cash", edit that open's metadata (bea add open cannot change an existing open).`), sharing the duplicate-commodity hint's helper from w1/286. The item's example passes the account positionally and omits `--date`. `add open` keeps its `--account` and required `--date`. `cli/docs/USAGE.md` documents the option and corrects the cash-flow paragraph that said `add open` takes no metadata. `beancount-business-metrics` step 2 names the command for an account not yet open and the hand edit for one already open, and a `bea-cli.md` version note covers 0.4.1 and earlier, which refuse the option (skill suite 0.4.41). All but the no-meta control in `cli/tests/test_add_open_meta.py` fail with the fix reverted. `make check-all` and `scripts/skills/ci-check.py` pass. Shipped in `241bc147a` (`cli`, `skills`).

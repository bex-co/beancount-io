# `bea report cash-flow` / `capital-gains` state a reversed period, exit 0, when `--to-date` ends before the period starts

Found by `/qa-find-bugs-cli w1` on 2026-11-15 (HEAD `19e0f3ed9`, `bea 0.3.1`, macOS 26.5, checkout `uv run bea`, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`). Severity: minor. A1: an agent reads `period`, `as_of`, `opening` and `closing` from `--json` and has no way to tell this window was empty or nonsensical.

**Contract.** `cli/docs/USAGE.md` (Reports): "Invalid intervals, dates, reversed ranges, and malformed account filters exit **2**", and `cash-flow` explains cash over "`--time` intersected with `--from-date / --to-date`". `--from-date 2026-01-01 --to-date 2025-06-01` is already refused with exit 2. w5/1036 made the heading state the bounded window, and `tests/test_report_bounds_heading.py` pins overlapping windows only. Windows that miss the period entirely are not covered.

**Repro** (synthetic):

```sh
cat > inv.bean <<'EOF'
option "operating_currency" "USD"
option "booking_method" "FIFO"
2025-01-01 open Assets:Checking USD
2025-01-01 open Assets:Broker:Cash USD
2025-01-01 open Assets:Broker:AAPL AAPL
2025-01-01 open Income:Gains USD
2025-01-01 open Equity:Opening USD
2025-01-02 * "Fund"
  Assets:Checking  10000 USD
  Equity:Opening
2025-01-03 * "Move"
  Assets:Broker:Cash  5000 USD
  Assets:Checking
2025-01-10 * "Buy"
  Assets:Broker:AAPL  10 AAPL {100 USD}
  Assets:Broker:Cash
2025-06-10 * "Buy"
  Assets:Broker:AAPL  10 AAPL {150 USD}
  Assets:Broker:Cash
2026-03-01 * "Sell"
  Assets:Broker:AAPL  -15 AAPL {} @ 200 USD
  Assets:Broker:Cash  3000 USD
  Income:Gains
EOF
bea --file inv.bean report cash-flow -t 2026 --to-date 2025-06-01; echo "exit $?"
bea --file inv.bean --json report cash-flow -t 2026 --to-date 2025-06-01
bea --file inv.bean report cash-flow --to-date 2024-06-01; echo "exit $?"
bea --file inv.bean report capital-gains -t 2026 --to-date 2025-06-01; echo "exit $?"
bea --file inv.bean report cash-flow -t 2025 --from-date 2026-01-01; echo "exit $?"
bea --file inv.bean report cash-flow --from-date 2026-01-01 --to-date 2025-06-01; echo "exit $?"   # control
```

Actual (stderr empty, the ledger file unchanged throughout):

- `-t 2026 --to-date 2025-06-01`: the heading reads **`Cash Flow — 2026-01-01 through 2025-06-01`**, then `No cash flows in this period.`, `Opening cash: 9,000 USD`, `Closing cash: 9,000 USD`, exit 0. In JSON, `period` is `{"start": "2026-01-01", "end_exclusive": "2025-06-02"}` and `as_of` is `2025-06-01`, so the start comes after the end. The 9,000 USD is the cash on 2025-06-01, not the cash at the stated start (7,500 USD on 2026-01-01).
- `--to-date 2024-06-01`, with no `--time`, before the first entry: the heading reads `2025-01-02 through 2024-06-01` and the period is reversed in the same way, exit 0.
- `capital-gains` prints the same reversed heading (`2026-01-01 through 2025-06-01`, `No sales.`), exit 0.
- `-t 2025 --from-date 2026-01-01`: the heading reads `2026-01-01 through 2026-01-01`, a day outside the `--time 2025` the user asked for, with opening and closing cash of 7,500 USD, exit 0.
- Control: `--from-date 2026-01-01 --to-date 2025-06-01` exits 2 with `--from-date '2026-01-01' is after --to-date '2025-06-01'.`

Expected:

1. When an explicit `--time` period and the `--from-date/--to-date` window share no day, the command exits 2, as a reversed `--from/--to` does, and names both, for example `--to-date 2025-06-01 is before the --time period 2026-01-01 through 2026-12-31.` Nothing is computed.
2. Without `--time`, a `--to-date` before the ledger's first entry is stated as asked, `2024-06-01 through 2024-06-01`. This mirrors how `--from-date` after the last entry already reads `2027-01-01 through 2027-01-01`. `period.start` is never after `end_exclusive - 1`, and opening and closing describe that stated day.

**Root cause.** `cli/src/bea_engine/report.py:1694` `_bounded`. Its empty-window branch (line 1715, `first = start or first`) keeps the period's own start when only `--to-date` was given, so `after` (to-date + 1) lands before `first`. It also accepts a window outside an explicit `--time` as "stated as asked". `_cash_flow` (line 1171 onward) builds `first`/`cutoff` the same way and never checks that `first < cutoff`. Its opening and closing then come from the cutoff side. `report()` (line 114) validates the bounds only against each other, via `_date_bounds`, and never against the `--time` period.

**Fix** (`cli`, about 30 minutes). In `report()`, after `_load`, when `time` is set and either bound falls outside `filtered.period`, raise `protocol.UsageError` naming the bound and the `--time` period. In `_bounded`'s empty branch, fall back to `end` when `start` is None (`first = start or end or first`). Add the cases above to `tests/test_report_bounds_heading.py`, for both kinds: the disjoint `--time` cases exit 2 with the file unchanged, and `--to-date` before the first entry states `TO through TO`. Add one line to USAGE.md's reversed-range sentence covering a window that misses `--time`.

**Dedupe.** w5/1036 and w5/1049 (done) cover the bounded heading and `9999-12-31` for windows inside the period. w5/1048 covers summarized flows. A search for `intersect`, `reversed`, `disjoint` and `to-date` across `.pm/**` found no item for a window that misses the period. Not a regression of a shipped DoD: the w5/1036 tests cover only overlapping windows.

---

**Resolved 2026-11-15.** `cli/src/bea_engine/report.py`: `report()` now refuses, with exit 2 and before computing anything, a `--from-date / --to-date` window that shares no day with an explicit `--time` period (`--to-date 2025-06-01 is before the --time period 2026-01-01 through 2026-12-31.`, and the matching `--from-date … is after …`). `_bounded` states a lone `--to-date` before the first entry as `TO through TO`, so `period.start` is never after `as_of`. A window touching only the period's last day still reports. New cases in `cli/tests/test_report_bounds_heading.py` (`test_a_window_outside_time_is_refused` for both kinds, with stderr, empty stdout and an unchanged file; `to-before-ledger`, `from-after-ledger`, `time-last-day`) fail with the fix reverted (8 failures). `cli/docs/USAGE.md` names the new exit-2 case. (`cli`)

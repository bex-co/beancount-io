# MCP QA tooling: `resources-list` sends the wrong method, conformance needs the token on argv

**Tooling · .agents/qa-shared + backend-v2 scripts · minor · ~30m · A1.** From `/qa-find-bugs-mcp`, 2026-11-08.

- **`qa-mcp.mjs resources-list`** sends `resources/templates/list` (`.agents/skills/qa-shared/scripts/qa-mcp.mjs:186-187`). The skill tells QA to compare `resources/list` with the documented instance set, so it gets compared against the wrong inventory. Add `resource-templates-list` for templates, and make `resources-list` send `resources/list`. Update the helper's usage text and the skill's command list.
- **`yarn mcp:conformance`** takes the token only as `--token …` / `--read-only-token …` (`backend-cluster/backend-v2/scripts/mcp-conformance.ts:4,779`). That puts the secret on argv, which the QA contract forbids, so QA runs it anonymously and skips the six authenticated checks. Let it also read `QA_MCP_TOKEN` / `QA_MCP_READ_ONLY_TOKEN` from the environment or the repo-root `.env`, the same way `qa-mcp.mjs` does.
- **Check:** with a token in `./.env` only, `yarn mcp:conformance https://beancount.io` runs all 16 checks. `qa-mcp.mjs resources-list` returns instances, not templates.

---

**Resolved 2026-11-10.** Both QA tools now keep to the QA contract.
- **`qa-mcp.mjs`:** `resources-list` sends `resources/list` (the concrete instances). The new `resource-templates-list` sends `resources/templates/list`. The usage text and the `qa-find-bugs-mcp` command list name both. `qa-mcp.test.mjs` asserts the JSON-RPC method each list command sends.
- **`yarn mcp:conformance`:** with no flag, it reads `QA_MCP_TOKEN` (or `BEANCOUNT_MCP_TOKEN`) and `QA_MCP_READ_ONLY_TOKEN` from the repo-root `.env` first, then the environment, the same way `qa-mcp.mjs` does. `--token` and `--read-only-token` still override both. The skip messages name the variable. `resolveTokens` is unit-tested in `mcp-conformance.test.ts`. The skill, `backend-v2/AGENTS.md` and `docs/mcp.md` now say to leave the token off argv.
- **Check, run 2026-11-10 against `https://beancount.io` with the token in `./.env` only:** the authenticated checks 3, 4, 6 and 9 ran instead of skipping. Three checks still skip, because of the credentials available, not the tool. Check 5 needs a read-only key, and the repo-root `.env` holds none. Checks 10 and 17 need `--ledger` with the unpinned QA key.
- **Production failures:** the run showed two, check 3 (`OPTIONS` answers 200, and `PUT`'s `Allow` lists other methods) and check 18 (`WWW-Authenticate` is not exposed). Both are already fixed on `main` (`435cef7cf`, `2028eb90a`) and are waiting for a backend-v2 deploy. They are not new findings. (`.agents/skills`, `backend-v2`)

# `bea add price` records a negative quote (and a commodity quoted in itself) with exit 0, so a sign typo turns a holding's market value negative

Found by `/qa-find-bugs-cli w1` on 2026-11-17 (HEAD `1b15d0439`, `bea 0.4.1`, macOS 26.5.1, checkout `uv run bea`, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`). Severity: minor. A1: an agent recording a quote from a feed or a pasted table writes whatever sign it was handed, and nothing downstream says the books are now wrong.

**Repro** (a fresh directory):

```sh
cat > main.bean <<'EOF'
option "operating_currency" "USD"
2024-01-01 commodity VTI
2024-01-01 open Assets:Broker:VTI VTI
2024-01-01 open Assets:Cash USD
2024-01-02 * "buy"
  Assets:Broker:VTI  10 VTI {100 USD}
  Assets:Cash  -1000 USD
EOF
bea --file "$PWD/main.bean" add price --date 2024-01-03 -c VTI --amount '-250 USD'   # exit 0
bea --file "$PWD/main.bean" check                                                    # exit 0
bea --file "$PWD/main.bean" report holdings      # MARKET VALUE -2,500 USD
bea --file "$PWD/main.bean" report balance-sheet # Net Worth: -3,500 USD
bea --file "$PWD/main.bean" add price --date 2024-01-04 -c USD --amount '1 USD'      # exit 0, writes `price USD 1 USD`
```

Repeated from a pristine fixture in a fresh process: same result.

**Expected:** a negative price is refused before anything is written, exit **2**, naming the value. Beancount itself refuses one on a posting, and `bea add transaction` already passes that refusal on: `-p 'Assets:Bank:Savings 10 USD @ -1 USD'` exits 2 with `Negative prices are not allowed: -1 USD`. A price whose quote currency equals the commodity (`-c USD --amount '1 USD'`) is refused too: it values nothing, and it is the self-price w1/276 had to stop the hint from suggesting. A zero quote stays allowed: a delisted security can be worth 0.

**Actual:** both write and exit 0. `bea check` passes because Beancount's parser accepts a negative `price` directive. Reports then value the holding at the negative rate.

**Cause:** `cli/src/cli/commands/add.py` `add_price` (around line 436) parses `NUMBER CURRENCY` with `_parse_amount` and sends it on with no sign or self-quote check. The engine model `PriceDirective` in `cli/src/bea_engine/ledger/models.py` (around line 494) takes any `Amount`. Postings are refused only because Beancount's booking rejects a negative posting price; `price` directives never go through that check.

**Fix:** refuse a number below zero, and a quote currency equal to `--currency`, in `add price` (exit 2, nothing written; `--json` returns the usage error envelope). Put the check on the engine's price write so every writer of a price directive gets it. Mention the rule beside `add price` in `cli/docs/USAGE.md`. Regression tests: negative refused with the file byte-identical, self-quote refused, zero and a positive control still written.

**Blast radius:** every path that writes a price directive: `add price` and the price rows a configured importer emits through `bea import`. Check those and refuse the same values. Hosted writes (`addLedgerEntries` / REST / GraphQL text appends) validate through the server engine, so they are out of scope for this CLI note.

**Dedupe:** searched `.pm/**` for `add price` with negative, zero, or itself. w5/291, w5/145, w5/302 and w5/938 cover duplicate and conflict detection for quotes, not the quote's value. w1/276 stopped a hint from suggesting a self-price but left `add price` accepting one.

---

**Resolved 2026-11-17** — `quote_refusal` (`cli/src/bea_engine/ledger/prices.py`) is checked by the engine's price write (`_price` in `cli/src/bea_engine/ledger/adding.py`) and by import (`cli/src/bea_engine/importing.py`). `add price --amount '-250 USD'` now exits 2 with `Negative prices are not allowed: -250 USD. Nothing was written.` (the `--json` usage envelope carries the same message), and `-c USD --amount '1 USD'` exits 2 with `A price of USD in USD values nothing`; the file stays byte-identical. A configured importer's price row with either value is marked `invalid`, and `--apply` refuses with exit 1 naming the row. Zero and positive quotes are still written. Rule documented beside `add price` in `cli/docs/USAGE.md`. Regressions in `cli/tests/test_add_price_refuses_negative_or_self_quote.py`, four of which fail with the fix reverted. Shipped in `417a423b5` (`cli`).

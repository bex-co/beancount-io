# `bea cloud logout` revokes `BEA_TOKEN` while leaving it set

**Severity:** major  
**Package:** `cli`  
**Env:** `bea 0.1.0` @ `ec8297a7`, macOS, production `https://api.v3.beancount.io`, account `open_ledger`

## Repro

1. Have a working hosted session (file credential or export the same JWT as `BEA_TOKEN`).
2. `BEA_TOKEN=<token> BEA_CONFIG_DIR=<empty-isolated-dir> bea --json cloud status` → exit 0, `source: environment`.
3. `BEA_TOKEN=<token> BEA_CONFIG_DIR=<same> bea cloud logout` → exit 0 (“Logged out.” / empty JSON success).
4. With the same `BEA_TOKEN` still exported: `bea cloud status` → exit 3, “Not authenticated…”.
5. The same JWT previously stored under `~/.config/bea/credentials.json` is also dead (remote revoke).

## Expected

`USAGE.md` presents `BEA_TOKEN` as the unattended credential and says logout “does not unset `BEA_TOKEN` in the shell.” An environment-sourced token must not be remotely revoked by a routine logout (or logout must refuse / require an explicit force and say the token is now invalid). CI/shared tokens must survive `bea cloud logout` run under `BEA_TOKEN=…`.

## Actual

`load_credentials()` prefers `BEA_TOKEN`, and `cloud_logout` always calls the remote logout endpoint with that token before `clear_credentials()` (file-only). The shell still has `BEA_TOKEN`, but the server has revoked it.

## Evidence / root cause

- `cli/src/cli/commands/cloud/app.py` (`cloud_logout`) — remote `logout` + `clear_credentials()` with no `creds.source` branch.
- `cli/src/cli/auth/credentials.py` (`load_credentials`) — env wins over file.
- `cli/docs/USAGE.md` § hosted login — “does not unset `BEA_TOKEN`”.
- Live capture: `cli/tmp/qa-20260910/cloud-run-1/evidence/logout_with_env.*`, `status_after_logout_env.*`.

## Fix

When `creds.source == environment`, do not call remote revoke (clear nothing meaningful; print that `BEA_TOKEN` is unchanged), **or** refuse with usage guidance unless `--force`/`--yes` explicitly requests revoke. Update `USAGE.md` + add a regression test that mocks logout and asserts env-sourced tokens are not revoked by default.

# `bea treeify` output guard is bypassed by abbreviated long options and clustered short flags, overwriting the ledger

**Severity: major. Owner: cli. Estimate: 30–45m. A1:** a ledger must never be replaced by a helper's output. Continuous CLI QA, 2026-10-03 (round 10); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1 (Beancount 3.2.3, beanquery 0.2.0), Python 3.13, macOS 26.5.1 arm64. Fresh process per command with timeouts, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME` (so `~/.config/beanquery/init` below is the isolated home), notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control.

```sh
printf 'option "operating_currency" "USD"\n2024-01-01 open Assets:Bank USD\n' > main.bean
printf 'Assets:Bank:Checking  10\nAssets:Bank:Savings 5\n' > in.txt
bea --file /abs/main.bean treeify --outp /abs/main.bean /abs/in.txt     # exit 0, ledger replaced by the tree
bea --file /abs/main.bean treeify --out=/abs/main.bean /abs/in.txt      # exit 0, same
bea --file /abs/main.bean treeify -Ao /abs/main.bean /abs/in.txt        # exit 0, same
bea --file /abs/main.bean treeify -Fo/abs/main.bean /abs/in.txt         # exit 2, but main.bean already overwritten
```

Actual: each spelling overwrites the ledger (hash changes; re-verified by the filer: `--outp` exits 0 and `main.bean` begins `` `-- Assets ``). Controls: `-o /abs/main.bean` and `-o main.bean` are refused with exit 2, hash unchanged.

Expected: exit 2 "would overwrite the ledger it reads", ledger byte-identical; existing `.bean` files need `--force` (the `w3/done/m48` guard).

Cause: `cli/src/cli/output.py:309–335` (`forwarded_option`) recognises only `-o X`, `-oX`, `--output X`, `--output=X`; upstream `beancount/tools/treeify.py:255` uses argparse with default `allow_abbrev=True` and clusterable `-F`/`-A`; guard called at `cli/src/cli/commands/treeify.py:26` (from `dbd08c40`).

Fix/acceptance: resolve the destination the way the downstream parser does (parse forwarded argv with treeify's own argparse parser), or refuse forwarded tokens the guard can't classify. All four spellings exit 2 with the ledger unchanged; a non-ledger existing `.bean` still needs `--force`; `-o` controls pass. Check other forwarded commands for clustering (ingest when beangulp is enabled).

Dedupe: [084](./084.md) is a different mechanism (plain `-o`, write-before-fail). No note covers abbreviation or clustering.

## Also affected: `bea ingest extract` via clustered short flags (round 15, 2026-10-03)

Verified with Beangulp enabled in an isolated managed engine (`BEA_ENGINE_DIR` in the run dir, `bea engine enable beangulp`). Beangulp's Click command allows boolean short flags (`-r`, `-x`, `-q`) to cluster in front of a value option, so:

```sh
bea --file /abs/main.bean ingest extract --config /abs/ingest.py -qo /abs/main.bean /abs/in          # also -ro, -xo, -qo/abs/main.bean, -qo main.bean
bea --file /abs/main.bean ingest extract --config /abs/ingest.py -qo /abs/sub/extra.bean /abs/in      # an included file
bea ingest extract --config /abs/ingest.py -re /abs/main.bean -o /abs/main.bean /abs/in               # -e/--existing ledger; also -qe/abs/main.bean
```

each exit 0 and replace the target with `;; -*- mode: beancount -*-` plus the extracted transaction (options, opens, include and history gone; `bea check` then exits 1). Controls `-o …`, `--existing=M -o M` are refused with exit 2. Click rejects `--outp` abbreviations, so only clustering applies to ingest. Guard misses at `cli/src/cli/commands/ingest.py:65` (`-o`) and `:83` (`-e`). **Widen this fix** to the shared `forwarded_option` (cluster-aware with each downstream command's boolean-flag set, or refuse unclassifiable short clusters containing the target letter) rather than treeify-specific argparse parsing; acceptance adds every ingest spelling above (exit 2, files byte-identical) with `-o new.bean` still working.

---

**Resolved 2026-10-03** — output guards now see abbreviated (`--outp`) and clustered (`-Ao`, `-qo`) option spellings, so `treeify` and `ingest extract` can no longer overwrite the ledger through them. Tests in `tests/test_output_destination_guard.py` cover every spelling from this note. Shipped in the commit that moved this note (`cli`).

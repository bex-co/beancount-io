# `bea update transactions` rejects a row "would leave the ledger invalid" without saying why

Found by `/qa-find-bugs-cli w1` on 2026-11-15 (HEAD `ee1ae1f6e`, `bea 0.3.1`, macOS 26.5, checkout `uv run bea`, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, synthetic ledger). Severity: minor. A1: the batch review-queue flow (`USAGE.md` "Updating directives": preview, fix the rejected rows, preview again) cannot be followed, because the preview names the rejected row but not what is wrong with it. An agent reading `--json` gets the same bare reason in `rows[].reason` on preview and on apply.

**Repro** (synthetic):

```sh
cat > main.bean <<'EOF'
2024-01-01 open Assets:Cash USD
2024-01-01 open Expenses:Uncategorized USD

2024-01-03 ! "B"
  import-id: "x2"
  Assets:Cash   -5.00 USD
  Expenses:Uncategorized
EOF
printf 'id,account,flag\nx2,Expenses:Nope,*\n' > q.csv
bea --file main.bean update transactions --from q.csv           # exit 0
bea --json --file main.bean update transactions --from q.csv --apply   # exit 1
```

**Actual.** The preview prints:

```
1    rejected  x2
Row 1: The change would leave the ledger invalid; nothing was written.
Preview only. Fix the 1 rejected row, then preview again.
```

Nothing says the account is not open. On `--apply` the cause shows up only as a separate line in `error.details`. `result.rows[0].reason` is still the bare sentence, so a consumer that reads per-row results never sees it. The single-row command explains the same refusal: `bea update transaction --id x2 --account Expenses:Nope --apply` prints `main.bean:11: Invalid reference to unknown account 'Expenses:Nope' Did you mean …? To create it, use bea … add open …`.

**Root cause.** `cli/src/bea_engine/ledger/updating.py` `_validate_plans` / `_validate_cumulatively` (about lines 775–845) store only `_row_reason(index, exc)` in `reasons`. The located `exc.details` go into the flat `rejected` list, and the preview never renders that list. `_row_reason` (line 621) is also meant to strip the single-row suffix, because other rows in the batch may still write. It strips `' Nothing was written.'`, but the ledger refusal (`write.py:3154`/`3170`) ends `'; nothing was written.'`, so the batch row still claims nothing was written.

**Fix (cli only, local operation).** A rejected row's reason carries the ledger error(s) that rejected it, in the text preview, in `--json` `rows[].reason` (or a `rows[].details` list), and on apply. The "nothing was written" wording is dropped from batch row reasons whatever its case. This covers the combined "valid alone, but … together" reason and the cumulative-include reason too.

**Done when** the repro's preview names `Invalid reference to unknown account 'Expenses:Nope'` under row 1 and its JSON `rows[0]` carries the same text on preview and apply. No batch row reason says "nothing was written". A regression test in `cli/tests/test_update_batch.py` covers preview and apply, and fails with the fix reverted.

**Dedupe.** Searched `.pm/**` for `update transactions` plus reason/rejected: w5/1027, 1028, 1029, 1040 and 1081 (cumulative preview validation, which added the paths above) and w1/244 are all done and none covers the reason text. No open item.

---

**Resolved 2026-11-15** — A batch row the ledger rejects now carries the errors that rejected it. Each rejected row in `bea update transactions` gains a `details` list (the located ledger errors, also under `--apply` in `error.result.rows[]`), and the text preview prints them beneath the `Row N:` line, so the repro's preview names `main.bean:4: Invalid reference to unknown account 'Expenses:Nope'`. Batch row reasons no longer claim "nothing was written" in either casing (`; nothing was written.` or `Nothing was written.`), including the "valid alone, but rows … fail together" and cumulative-include reasons. `cli/src/bea_engine/ledger/updating.py`, `cli/src/cli/commands/update.py`, `cli/docs/USAGE.md`. Regression tests in `cli/tests/test_update_batch.py` (preview and apply JSON, text preview, combined reason, reason cleanup) fail with the fix reverted. (`cli`)

# Unknown keys inside bulk `units`/`cost`/`price` are silently dropped, so a typo sells the wrong lot

**Severity: major. Owner: cli. Estimate: 30–45m. A1:** agent-generated bulk input must fail loudly rather than book wrong money. Continuous CLI QA, 2026-10-03 (round 6); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1 (Beancount 3.2.3), Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed unless piping JSON. Reproduced twice with a working control; compared against native `bean-check`/`bean-query`.

Ledger:

```beancount
2026-01-01 open Assets:Cash USD
2026-01-01 open Assets:Brokerage AAPL "FIFO"
2026-01-01 open Income:Gains USD
2026-01-02 * "buy cheap"
  Assets:Brokerage  10 AAPL {100 USD}
  Assets:Cash
2026-01-03 * "buy dear"
  Assets:Brokerage  10 AAPL {150 USD}
  Assets:Cash
```

```sh
echo '[{"date":"2026-02-01","narration":"sell","postings":[{"account":"Assets:Brokerage","units":{"number":"-10","currency":"AAPL"},"cost":{"number_per":"150","currency":"USD"},"price":{"number":"160","currency":"USD"}},{"account":"Assets:Cash","amount":"1600 USD"},{"account":"Income:Gains"}]}]' \
  | bea --file /abs/l.bean add transactions --from -
```

Actual: exit 0, writes `-10 AAPL {USD} @ 160 USD`; FIFO sells the 100 USD lot and `Income:Gains` is −600 USD. Control `"number":"150"` sells the 150 lot (gain −100 USD). A typo'd `"lot_date"`, `"merge": true`, a stray key in `units`, `"total": true` in `price` are likewise ignored; a numeric `cost.date` (`1769904000`) is accepted as a Unix timestamp.

Expected: refuse with row and field path — USAGE says unknown transaction/posting fields are rejected and `w3/225` adopted extra-forbid. `number_per` is realistic: it was the old `add transaction --json` shape (`w3/240`).

Cause: `cli/src/bea_engine/ledger/models.py:56` (`Amount`) and `:61` (`Cost`) lack `ConfigDict(extra="forbid")`; since `78217b30` (`w3/m49`) every `Cost` field is optional, so dropping an unknown key leaves a valid `{USD}` selector. `Cost.date` is plain `datetime.date`, not `LedgerDate`.

Fix/acceptance: `extra="forbid"` on `Amount` and `Cost`; `Cost.date: LedgerDate`. The `number_per`/`lot_date`/`merge` cases exit 1 with `Row 1, postings.0.cost.number_per: Extra inputs are not permitted`, ledger byte-identical. Confirm `list`/`add` JSON never emits extra keys in these objects so round trips ([092](./092.md), [093](./093.md), `test_add_cost_roundtrip.py`) still pass.

Dedupe: `w3/225` (top level only), `w3/240` (output shape), `w3/414` (currency-less costs); no hit for nested unknown keys.

---

**Resolved 2026-10-04** — unknown keys inside bulk `units`, `cost`, `price` and `price_total` are now refused with their row and field path instead of being silently dropped, and `cost.date` must be a ledger date. `tests/test_bulk_transaction_unknown_fields.py` covers each case. Shipped in the commit that moved this note (`cli`).

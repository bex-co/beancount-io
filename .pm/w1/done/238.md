# Current-state docs miscount the customer skills; the PyPI page says "eight"

**Docs · cli + skills · minor · 45m · A3.** The suite has sixteen `beancount-*` skills (`git ls-files 'skills/*/SKILL.md'`), and `plugin.json` is at **0.4.31**. Several passages that describe the suite as it is today give older numbers. Dated evidence files (rehearsals, release controls, catalog corrections) record what was true on their date and are correct as they stand.

| File | Says | True on `main` |
| --- | --- | --- |
| `cli/README.md:40` | "The eight `beancount-*` ledger skills" | sixteen. This file is the PyPI long description (`cli/pyproject.toml`, `readme = "README.md"`), so the public package page carries the wrong count until the next `cli-v*` release. |
| `docs/skills/installation.md:166` | the Claude Code/Codex suite is "**0.4.19**, fourteen skills", and the ClawHub package lacks only `beancount-invoices` | 0.4.31 with sixteen; the ClawHub 0.4.0 package also lacks `beancount-report-pack` and `beancount-business-metrics` |
| `docs/skills/suite-distribution.md:3` | "One Beancount.io package carries the thirteen customer workflows" | sixteen in the Claude Code/Codex plugin; thirteen only in the ClawHub 0.4.0 package |
| `skills/README.md:32` | the OpenClaw package "predates `beancount-invoices`" | it predates all three newer skills; "the other thirteen" is right |

## Fix

- Correct each passage. Where a count is not needed, drop it ("the suite's ledger skills") so it cannot go stale again. Keep the ClawHub package's own count, which describes that published package.
- Add a check to `scripts/skills/ci-check.py`: in the current-state files above plus the root `README.md`, a number word or numeral directly qualifying "skills" or "workflows" for the suite must equal the inventory count, and a stated suite version must equal `plugin.json`. Exempt dated evidence files, and allow a count explicitly tied to a named older package version.

**Acceptance:** the four passages state today's numbers, or none; `python3 scripts/skills/ci-check.py` passes; changing any of them back to "eight", or the inventory to fifteen skills, makes the check fail naming the file and line; the checker has unit tests beside the existing ones.

**Resolved 2026-11-13.** The four passages now state today's numbers, or none:
- `cli/README.md` (the PyPI page) says "The `beancount-*` ledger skills" with no count.
- `docs/skills/installation.md` drops the stale suite version and count, and names all three skills the ClawHub 0.4.0 package lacks: `beancount-invoices`, `beancount-report-pack` and `beancount-business-metrics`.

`check_suite_counts` in `scripts/skills/ci-check.py` now guards the five current-state files (the four above plus the root `README.md`):
- **Count rule:** a number word or numeral qualifying "skills" or "workflows" must equal the inventory.
- **Version rule:** a stated Claude Code/Codex suite version must equal `plugin.json`.
- **Exemptions:** sections under a dated heading, and paragraphs that name a release (a version or a date), describe their own date or release. A list takes its lead paragraph's.

How the check behaves:
- On `main`, three reverted passages fail, each naming its file and line: `cli/README.md:40` "eight", `docs/skills/installation.md:165` suite version 0.4.19, and `docs/skills/suite-distribution.md:3` "thirteen".
- An inventory of fifteen fails at `README.md:162`.
- The `skills/README.md` passage omitted two skill names but stated no wrong count, so no count rule can see it; it is fixed by hand.

Nine unit tests (`TestSuiteCounts` in `test_ci_check.py`) cover:
- the pass case and the stale count with file and line;
- inventory growth, and numerals and qualifiers;
- dated sections, named releases and inherited list context;
- an undated section after a dated one, and code fences;
- the version rule, and a missing document.

`python3 scripts/skills/ci-check.py` and `python3 scripts/skills/test_ci_check.py` (76 tests) pass, and so do the CLI tests that read the README (59). (`skills`, `cli`)

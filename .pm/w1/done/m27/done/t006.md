## Objective

`bea add price` silently appends a second same-day quote when the amount differs, `bea add balance` appends an identical assertion with no idempotency check, and a repeated `--amount` on `add balance` silently keeps only the last value.

## Context

- `w3/291`: `add price` silently appends a second same-day quote when the amount differs.
- `w3/297`: `add balance` appends an identical assertion with no price-style idempotency.
- `w3/367`: `add balance` silently drops all but the last repeated `--amount`, exit 0.
- Adding is `cli/src/bea_engine/ledger/adding.py`; these are the retry-safety cases for agent writes.

## Steps

1. Detect an existing directive for the same key — (date, commodity, quote) for a price, (date, account, currency) for a balance — and refuse or replace explicitly rather than appending a duplicate.
2. Make the conflicting-value case a clear error naming both values and the flag that overrides.
3. Either support repeated `--amount` on `add balance` for multiple currencies or refuse the repetition; never silently keep the last.
4. Keep the behavior identical across the flag and bulk JSON paths so a retried agent write is safe.

## Acceptance criteria

- [ ] Re-running the identical `bea add price` or `bea add balance` does not append a second line and reports the directive already exists.
- [ ] A same-key directive with a different value is refused with both values named and the override flag shown.
- [ ] Repeated `--amount` on `add balance` either records every currency or exits 2; it never silently drops values.
- [ ] A retried agent write leaves the ledger in the same state as a single write.

## Out of scope

- Idempotency for transactions, which is what `import-id` deduplication already covers.
- Pad and opening-balance semantics.

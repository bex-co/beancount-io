# `bea report register` values every running balance at the report's end date, so a past row shows a later price

Found by `/qa-find-bugs-cli w1` on 2026-11-15 (HEAD `770e8e64a`, `bea 0.3.1`, macOS 26.5, checkout `uv run bea`, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, offline synthetic ledger). Severity: minor. A1: an agent that reads a register row's balance as "what this account was worth that day" gets a figure built from a price quoted weeks later. The figure also changes with the `--time` window.

**Contract.** `cli/docs/USAGE.md:2139-2141` (Reports): "Each interval row is valued at its own date, so a later quote cannot value an earlier interval". The register's own missing-price error says "Each report row uses its own valuation date". Two independent controls value a running balance at the row's date: Fava's account journal (`cli/src/fava/ledger.py:156-157`, `cost_or_value(balance, conversion, prices, entry.date)`) and BQL `convert(balance, 'USD', date)`.

**Repro** (synthetic):

```sh
cat > main.bean <<'EOF'
option "operating_currency" "USD"
2026-01-01 open Assets:Broker
2026-01-01 open Assets:Cash USD
2026-01-01 price STK 100 USD
2026-03-01 price STK 200 USD
2026-01-05 * "buy one"
  Assets:Broker  1 STK {100 USD}
  Assets:Cash  -100 USD
2026-02-05 * "buy another"
  Assets:Broker  1 STK {100 USD}
  Assets:Cash  -100 USD
EOF
bea --file main.bean check                                         # clean, exit 0
bea --file main.bean report register Assets:Broker -x USD
bea --file main.bean report register Assets:Broker -x USD -t 2026-01
bea --file main.bean query "SELECT date, convert(balance, 'USD', date) WHERE account = 'Assets:Broker'"
```

Actual: with no `--time`, the report runs through 2026-03-01. The 2026-01-05 row reads `200 USD` and the 2026-02-05 row reads `400 USD`, both valued at the March quote. With `-t 2026-01`, the same 2026-01-05 row reads `100 USD`. BQL gives `100 USD` and `200 USD`. The quote gap behaves the same way. In a ledger whose first quote comes after a purchase, `--json report register ACCOUNT -x USD` over the whole ledger exits 0 with `valuation: "complete"` and values the early rows at the later quote. The same rows inside a `-t` window that ends before the quote exit 1 with "Missing prices", and `missing_price_dates` names the window's end date, not the row's date.

Expected: each row's balance is valued at that row's date. Here that is `100 USD`, then `200 USD`, the same under any window that contains the row. A row dated before the first quote follows the documented missing-price policy: units in text, exit 1 under `--json`/`CI`/`--strict` unless `--allow-errors`, with that row's date in `missing_price_dates`.

**Root cause.** `cli/src/bea_engine/report.py:893` converts each running balance with `_converted(running, conversion, prices, filtered.end_date)`. The next lines record `(filtered.end_date, balance)` for `_valuation`, so the missing-price check also tests only the end date. The choice dates from w22/m3/t002, whose acceptance is "the last running balance equals the account's trial-balance total" (USAGE.md:1958-1960 "so its last row is the trial-balance total").

**Fix** (`cli` only, about 45 minutes). Value each row at its own date: pass `row["date"]` to `_converted` and record that date in `balances`. This conflicts with the last-row promise whenever a quote moves between the last posting and the report's end. The trial balance shows `400 USD` here, while the last row valued at its own date reads `200 USD`. Recommended way to keep both: when the conversion is a currency or `at_value` and the end-date valuation differs from the last row's, append one closing row (`entry: "closing"`, dated the as-of date, no amount), valued at `filtered.end_date`, so the register still ends at the trial-balance total. Then update USAGE.md:1958-1960 to say that. Under `units` and `at_cost` nothing changes. Add a regression test with the fixture above (`--json` rows `{"USD": "100"}`, `{"USD": "200"}`, closing row `{"USD": "400"}`, and the 2026-01-05 row identical under `-t 2026-01`), plus a pre-quote row that is reported as missing with its own date. Revert the fix and check that the test fails. CSV (`report_csv.py:_register`) and the text table must render the closing row.

**Blast radius.** Only `_register` builds a running balance. The statement trees, the interval series and holdings already value at each row's period end. Hosted surfaces have no register report.

**Dedupe.** Searched `.pm/**` for `register` together with `price`, `valu` and `convert`, and ran `git log -S "_converted(running"`. w5/1054 and w5/1055 (done) fixed register unit residuals and known-zero balances, not the valuation date. No open item covers this.

---

**Resolved 2026-11-15.** `_register` now values each running balance at its row's date and records that date for the missing-price check, so the repro reads `100 USD`, then `200 USD`, under any `--time` window that contains the row, and a row before the first quote is reported missing with its own date in `missing_price_dates`. To keep the documented promise that the last row is the trial-balance total, a currency or `at_value` conversion whose end-date value differs from the last row's appends one closing row (`entry: "closing"`, dated the as-of date, no amount, text `Valued at the as-of date`), here `400 USD`; `units` and `at_cost` add none. Text, JSON and CSV render it. `cli/src/bea_engine/report.py`, `cli/src/cli/commands/report.py`, `cli/docs/USAGE.md`. Regression tests: `cli/tests/test_report_register.py::test_register_values_each_row_at_its_own_date`, `::test_register_row_before_the_first_quote_is_missing_at_its_own_date`, `::test_register_has_no_closing_row_without_a_market_conversion`, and `cli/tests/test_report_holdings_register_frontend.py::test_register_renders_the_closing_row` (they fail with the fix reverted). Fixtures that bought before their first quote gained a same-day quote, or `--allow-errors` where the test is about provenance. (`cli`)

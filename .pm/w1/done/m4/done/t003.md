## Objective

Give signed-out users a discoverable but unobtrusive way to configure a compatible server before choosing Sign in or Sign up.

## Context

- `mobile/src/screens/welcome/index.tsx` currently contains the logo and Sign in/Sign up actions, with no top-right control.
- Auth routes live under `mobile/app/auth/`; the form may be a focused route or an accessible modal, whichever best matches existing mobile navigation patterns.
- Theme tokens and `useTranslations()` are mandatory; English is the fallback locale.

## Steps

1. Add a theme-aware gear button at the welcome screen's top-right with an accessibility label and adequate hit target.
2. Build a “Server” form containing the compatible-server explanation, URL input, current/default value, Save, Cancel, Test connection entry point, and Restore default action.
3. Save a syntactically valid URL without requiring network availability; show normalization and validation feedback inline.
4. Ensure keyboard, safe-area, loading/disabled states, dark mode, and return-to-welcome behavior are polished on iOS and Android layouts.
5. Add English translation keys through `useTranslations()` and let other locales fall back according to the existing translation model.

## Files

- `mobile/src/screens/welcome/`
- `mobile/app/auth/`
- `mobile/src/translations/en.ts`
- Existing shared form/button/icon components as appropriate.

## Acceptance criteria

- [ ] The welcome screen exposes a top-right server settings control without disrupting the primary Sign in/Sign up actions.
- [ ] The form displays, edits, saves, cancels, and restores the server URL with clear copy that says it requires a compatible Beancount.io server.
- [ ] Saving returns to welcome and subsequent auth actions use the new value immediately.
- [ ] Controls are accessible, keyboard-safe, token-styled, and visually verified in light and dark themes.

## Out of scope

- An authenticated multi-server account switcher or server directory.

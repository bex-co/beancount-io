## Objective

Add meaningful automated and simulator coverage for runtime server selection, including its security and failure-mode boundaries.

## Context

- Mobile unit tests run through `yarn test:unit`; CI also requires format, lint, and typecheck.
- Read-only simulator verification may open auth screens and run the compatibility probe, but must not sign in, save ledger data, or mutate the production-backed account.
- Haptics and development-disabled analytics cannot be verified in the simulator.

## Steps

1. Unit-test normalization, default/environment fallback, persistence hydration, restore-default, scheme policy, and invalid URL cases.
2. Test that all endpoint families follow the runtime selection and that Apollo does not retain the initial URI.
3. Test compatibility-probe success, timeout, unreachable, incompatible response, retry, and privacy-safe error handling.
4. Test the server-change teardown invariant: old credentials/cache are cleared before the new origin can receive a request.
5. Verify the signed-out welcome and server form in light and dark iOS simulator states without performing authenticated writes.
6. Run `yarn format:check`, `yarn lint`, `yarn typecheck`, and `yarn test:unit` from `mobile/`.

## Files

- `mobile/src/**/__tests__/`
- `mobile/src/__tests__/`
- Focused tests next to new server configuration helpers as appropriate.

## Acceptance criteria

- [ ] Tests assert real default, custom, invalid, offline, incompatible, reset, and cross-server isolation behavior.
- [ ] Light/dark simulator evidence confirms the form layout and validation states without production data mutation.
- [ ] All mobile CI commands pass.

## Out of scope

- Testing arbitrary third-party deployments or bypassing native cleartext transport security.

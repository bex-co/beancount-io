## Objective

Make runtime self-hosted server selection discoverable and keep public setup guidance aligned with the behavior that ships.

## Context

- This is a user-facing onboarding capability and part of the project's open-source/self-hosting story.
- Repository compatibility rules require adjacent `AGENTS.md` files to remain relative symlinks to canonical `CLAUDE.md` files and `.agents/skills` to resolve to `skills/.claude/skills/`.

## Steps

1. Update the owning mobile README/setup documentation to explain the default server, where signed-out users configure a compatible deployment, and the HTTPS/development-localhost policy.
2. Check root README/package tables and instruction files for claims that runtime selection changes; update only where needed.
3. Verify applicable `AGENTS.md` and `.agents/skills` symlinks still resolve to their canonical targets.
4. Confirm instructions remain equally usable by Claude Code and Codex; record any unrelated drift as a follow-up instead of creating divergent copies.

## Files

- `mobile/README.md`
- Root `README.md`, `CLAUDE.md`, and adjacent compatibility symlinks if affected.

## Acceptance criteria

- [ ] A self-hoster can discover the runtime server setting and its compatibility/security constraints from public mobile documentation.
- [ ] Hosted users can see that no configuration is required for beancount.io.
- [ ] Instruction and shared-skill symlinks resolve exactly as required by the repository rules.

## Objective

Turn the current build-time server URL into a runtime-selectable value that is available before network clients or authenticated screens initialize, while preserving the existing environment/default behavior.

## Context

- `mobile/src/config.ts` currently resolves `serverUrl` once from `EXPO_PUBLIC_SERVER_URL`, defaulting to `https://beancount.io/`.
- `mobile/src/common/apollo/persistent-var.ts` and `mobile/src/common/providers/splash-provider/` provide the existing persistence and startup-hydration patterns.
- The value is not secret; AsyncStorage is appropriate. Bearer credentials must remain in secure storage.

## Steps

1. Define the official/default server URL separately from the selected runtime value, preserving the environment override as the initial fallback.
2. Add persisted state plus a startup loader for the selected server URL and await it with the existing splash hydration before any request can run.
3. Add pure normalization and validation helpers: absolute URL, normalized trailing slash, no embedded credentials/query/fragment, HTTPS in release builds, and only a documented localhost cleartext exception during development.
4. Expose reset-to-default behavior without mutating the static build configuration object.

## Files

- `mobile/src/config.ts`
- `mobile/src/common/vars/`
- `mobile/src/common/providers/splash-provider/`

## Acceptance criteria

- [ ] With no stored selection, the existing environment value or `https://beancount.io/` is used.
- [ ] A stored valid selection is loaded before the first network request and survives a cold launch.
- [ ] URL normalization and validation are pure, reusable, and produce user-displayable failure reasons.
- [ ] The selected server URL is stored outside secure credential storage and is never treated as a secret.

## Out of scope

- Rendering the settings UI or changing request consumers.

# Once a Git token could not be revoked, every later signed-out `bea cloud logout` exits 1 with the same error, and doing what it says does not stop it

Found by `/qa-find-bugs-cli w1` on 2026-11-19 (HEAD `7b5e06004`, `bea 0.4.1` from the checkout, macOS 26.5.1, Python 3.12.14, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, no `BEA_TOKEN`, no stored login). Severity: minor. The code is from w22/m12 (blocked on its live check and release), so this can land before that release. A1/A2: a script or agent that runs `bea cloud logout` as cleanup fails on every run, and a person who revoked the token in the dashboard, as the error asks, keeps getting the same error.

**Repro.** The state file is what `git-credential.json` holds after a logout that could not revoke the Git token: `forget_token(…, revoked=False)` drops the token and keeps `key_id` so that a later login can still revoke it. A logout with the server unreachable leaves this state (`test_logout_with_the_server_unreachable_clears_local_state_and_names_the_token` asserts exactly this), and so does a Git `erase` followed by a signed-out logout.

```sh
export BEA_CONFIG_DIR=$PWD/cfg
mkdir -p cfg && chmod 700 cfg && cat > cfg/git-credential.json <<'EOF'
{"api_url": "https://api.v3.beancount.io", "git_url": "https://git.example.com", "key_id": "k1", "key_name": "bea git on qa", "token": null, "expires_at": null}
EOF
chmod 600 cfg/git-credential.json
bea cloud logout; echo "exit $?"
bea cloud logout; echo "exit $?"
bea --json cloud logout; echo "exit $?"
```

**Actual.** Every run prints `Error: Already logged out, but the Git token 'bea git on qa' could not be revoked (there is no session for its server). Revoke it in the dashboard under Settings → Personal access tokens.` and exits 1 (`--json`: a `validation` error envelope). Nothing changes between runs: no session, no token on disk, the same `key_id`. Revoking the token in the dashboard, as the message asks, changes nothing either, because bea cannot know it happened. The error clears only after `bea cloud login` and another `bea cloud logout`, or after `bea cloud git setup --undo`, which also removes the Git config registration and itself exits 1 the first time. The message names neither.

**Expected.** A logout that removes something it could not revoke reports that, exit 1, as today. That is the logout that found a token on disk or a session to use. A signed-out logout that finds only a remembered token id changes nothing and cannot revoke anything. It prints `Already logged out.` and exits 0, with one stderr note naming the token and the ways to retire it: revoke it in the dashboard, or `bea cloud login` then `bea cloud logout`, which revokes it. Keep the remembered `key_id` so a later signed-in logout, or the next mint, still revokes it. A signed-out logout with the token still on disk keeps today's exit 1, because it removes a live secret it could not revoke.

**Root cause** (cli only). `cloud_logout` (`cli/src/cli/commands/cloud/app.py:102`) calls `_sign_git_out(None)` when there is no session and raises `BeaError("Already logged out, but …")` for any answer. `_sign_git_out` (line 202) goes ahead whenever `state.key_id` is set, including when `state.token` is already `None`. `helper.try_revoke(None, …)` then reports "there is no session for its server", and `forget_token(state, revoked=False)` (line 208; `helper.py:378`) keeps the `key_id`, so the next run finds the same state. A signed-in logout whose revocation fails (unreachable server, or an expired session answering 401) leaves the same state. That path is traced in code; it was not run against a server.

**Fix.** In `_sign_git_out`, or at its signed-out call site: with no client and no stored token, return a note instead of a problem, and keep `key_id`. `cloud_logout` then prints `Already logged out.` plus the note and exits 0. Regressions in `cli/tests/test_cloud_git_sign_in.py`: the state above gives exit 0, `Already logged out.`, the note naming `'bea git on qa'`, and `key_id` still `k1`. A second run is the same. The existing unreachable-server logout test still exits 1 on its first run. A signed-out logout with `token` still stored still exits 1, and the token leaves the disk.

**Blast radius.** `bea cloud logout` with no stored login and no `BEA_TOKEN`, after any earlier failed Git-token revocation, or after Git's `erase` (`cli/src/cli/commands/cloud/git/app.py:229`, which also keeps the id). `setup --undo` clears the state and is not sticky. `credential get` is unaffected. Not exercised live: the signed-in failure paths that lead here (w22/m12/t006 is still blocked).

**Dedupe.** Searched `.pm/**` for `Already logged out`, `forget_token`, `key_id`, `could not be revoked`, `cloud logout`. w5/297 fixed "Already logged out." for an unusable `credentials.json`, a different state. w1/294 saw the first logout's exit 1 under the exact URL but not the repeat. w22/m12/t004 (logout signs Git out) does not cover a second logout. Estimate: 30 minutes.

---

**Resolved 2026-11-19** — A signed-out `bea cloud logout` that finds only a remembered Git token id, with no token on disk, now prints `Already logged out.`, exits 0, and notes on stderr the token and the two ways to retire it: revoke it in the dashboard under Settings → Personal access tokens, or `bea cloud login` then `bea cloud logout`. `key_id` stays, so a signed-in logout or the next mint still revokes it. A signed-out logout that still finds the token on disk removes it and exits 1 as before; so does a signed-in logout whose revocation fails. The note's repro now gives exit 0 on every run (`--json`: exit 0, no output). `cloud_logout` reads the Git sign-in once (`_git_sign_in`) and calls `_sign_git_out` only when there is something to remove. USAGE ("Cloud: Git sign-in on a self-hosted server") says what a later signed-out logout does. Regression tests in `cli/tests/test_cloud_git_sign_in.py` (`test_signed_out_logout_that_only_remembers_the_tokens_id_succeeds_and_says_how_to_retire_it`, `test_signed_out_logout_with_the_token_still_stored_removes_it_and_fails_once`, and a second logout added to `test_logout_with_the_server_unreachable_clears_local_state_and_names_the_token`) fail without the fix. Shipped in `d6953974e` (`cli`).

## Objective

Let a user find a transaction by what they remember about it: a word in the payee or narration, a tag, or a link.

## Context

- `cli/src/cli/commands/list.py::transactions` accepts `--limit`, dates, `--account` (case-insensitive substring), `--flag`, `--sort`, `--details`, `--allow-errors`; filters apply before the limit.
- `cli/README.md` and `cli/docs/USAGE.md` have option tables for `list`.

## Steps

1. Add `--search TEXT` (case-insensitive substring over payee and narration), `--tag TAG` (accepts with or without `#`), and `--link LINK` (with or without `^`), all repeatable and AND-composed with existing filters.
2. Apply them before `--limit` and `--sort`, like `--flag`.
3. Add the three options to both docs' option tables with one example each.

## Files

- `cli/src/cli/commands/list.py`
- `cli/README.md`, `cli/docs/USAGE.md`

## Acceptance criteria

- [ ] `bea list transaction --search "whole foods"` matches `Whole Foods` in payee and `whole foods` in narration.
- [ ] `--tag food` and `--tag '#food'` return the same rows.
- [ ] Combining `--search` with `--account` and `--from-date` narrows as expected; JSON envelope unchanged.

## Out of scope

- Regular-expression search.
- Searching metadata values.

# `bea --json query -o X.tsv` is refused with advice that `--json` itself refuses

**Severity: minor. Owner: cli. Estimate: ~15m. A1:** automation must be able to write JSON exports to any path. Continuous CLI QA, 2026-10-03 (round 10); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1 (Beancount 3.2.3, beanquery 0.2.0), Python 3.13, macOS 26.5.1 arm64. Fresh process per command with timeouts, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME` (so `~/.config/beanquery/init` below is the isolated home), notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control.

```sh
bea --json --file /abs/min.bean query "SELECT account" -o /abs/r.tsv          # exit 2: looks like TSV; pass --format csv (or rename the file)
bea --json --file /abs/min.bean query "SELECT account" -f csv -o /abs/r.tsv   # exit 2: --json and --format csv cannot be combined
```

`-o E.TSV` behaves the same. Control: `--json -o e.csv` / `-o e.txt` write the envelope (exit 0), as USAGE documents.

Cause: `cli/src/cli/commands/query.py:200–208` runs suffix inference and the TSV refusal before the `ctx.json_output` check (`:211`); from `c938a707` (`w3/324`).

Fix/acceptance: skip suffix inference/TSV refusal under `--json`; `--json … -o r.tsv` exits 0 writing the envelope; non-JSON `-o r.tsv` is still refused.

---

**Resolved 2026-10-03** — `bea --json query -o FILE` now writes the JSON envelope whatever the file's suffix, instead of refusing `.tsv` with advice `--json` itself refuses; non-JSON `.tsv` destinations are still refused. `tests/test_query_csv_suffix_infers_format.py` covers it. Shipped in the commit that moved this note (`cli`).

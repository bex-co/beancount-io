# Small scalar numbers are written as commodity amounts

**Major · 35–50 minutes.** QA reference CLI-QA-014.

Create a root containing `2026-01-01 open Assets:Cash USD`, then run:
```sh
uv run bea --json --file /absolute/qa/main.bean add custom --date 2026-02-01 --type qa --value number:0.00000001
uv run bea --json --file /absolute/qa/main.bean list custom
```
Both exit 0. The file contains `2026-02-01 custom "qa" 1E-8`; listing returns
`{"kind":"amount","number":"1","currency":"E-8"}`. Expected: scalar number
0.00000001. Reproduced twice at current HEAD. Native fixed-point text loads as
a scalar, and input 0.000001 survives CLI writing. Ledger validation accepts
the corrupted directive, so a successful check is not a semantic guarantee.

Cause: the shared writer delegates to upstream printer Custom/metadata code,
which uses str(Decimal). Negative exponents are interpreted as a number plus
commodity by Beancount. Render scalar Decimals as exact fixed-point text at the
printer compatibility boundary; don't rewrite arbitrary strings or change
Amount formatting. JSON decimal strings may still use exponents.

Earlier real CLI runs confirm transaction/posting numeric metadata through
bulk add, single add, Python import, and list --details. Negative tiny values
also corrupt; positive exponent 1E+30 rejects instead of silently changing type.
Acceptance: all affected scalar types and exact values survive write/reload,
including negative tiny values, ordinary and large fixed-point controls;
quoted text and Amount types remain intact. Add meaningful CLI regression tests.

entryInputToText implementation. Prior CLI init failure has its own template
interpolation and rejects rather than silently corrupting; keep fixes scoped

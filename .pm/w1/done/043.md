# Native `query --source` reports a missing stored query but exits success

**Severity: minor. Owner: cli. Estimate: 30–45m. A1:** automation invoking a named query must distinguish an unavailable query from a successful empty answer. Continuous CLI QA, 2026-10-02; no product fix applied.

Environment: clean `main` at `97dab6b04c6e40e4cf47e0c1d668731d36c7ec41`, source-checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13.0, Darwin 25.5.0 arm64. Disposable cwd, absolute ledger path, isolated configuration/cache/data, no inherited target/token, notifier disabled. Closed stdin, no TTY, bounded subprocesses.

Save `main.bean`:

```beancount
2025-01-01 open Assets:Cash USD
2025-01-01 open Equity:Opening USD
2025-01-02 * "opening"
  Assets:Cash 1 USD
  Equity:Opening -1 USD
2025-01-03 query "saved" "SELECT 2"
```

Run:

```sh
bea --no-input query --source /absolute/main.bean '.run missing'
bea --no-input query --source beancount:/absolute/main.bean '.run missing'
```

Actual: both exit **0**, stdout empty, stderr `error: query "missing" not found`. Repeated twice in fresh processes with reset valid fixtures; no ledger bytes change.

Expected: a missing stored query is a usage failure, exit **2**, naming the unavailable query. `cli/docs/USAGE.md`'s exit table promises the documented effect on exit 0. Working controls: `bea --json --file /absolute/main.bean query '.run missing'` exits 2 with a usage envelope and the available name `saved`; native `.run saved` exits 0 and returns `2` rows with empty stderr. This is not an empty-result error: valid empty results remain successful.

Cause: native one-shots dispatch straight to `bean-query` in `cli/src/cli/commands/query.py:241–244` through `cli/src/cli/engine/launch.py:76–87`. Upstream `BQLShell.do_run` (`beanquery/shell.py:431–461`) prints an error then returns without a failing status. The managed helper's `PreciseShell.do_run` (`cli/src/bea_engine/query.py:437`) already classifies the failure; native one-shots bypass it. Both source spellings share the same path; interactive source-shell is a different adapter and is not asserted broken here.

Fix/acceptance: make native one-shot stored-query failure produce exit 2 without interpreting arbitrary successful stderr as a failure. Reuse the controlled engine shell/error classification where practical while retaining supported native sources and rendering. Add subprocess coverage for a missing query, an existing query, empty valid answers, and output redirection; run `make check-all` in `cli/`. No upstream fork, new dependency or backend change.

Dedupe: searched all board states for missing stored queries, `.run`, native dispatch and zero exit statuses. Completed `w3/236` fixed this in the managed query helper; `w3/397` fixes interactive recovery, not this adapter. `git log -S '_refuse_multi_statement'` identifies related exit-contract work in `15629c14`; the current native branch still forwards status. Open `w1/040` explicitly excluded missing stored-query status. No open item covers this reproduced behavior; this is a residual native adapter gap, not a deployment issue.

Evidence: `cli/tmp/qa-20261002-loop/captures.jsonl` and `repeat_native.py` retain exact argv/cwd, stdin/TTY mode, streams, exit, durations and hashes. A first fixture draft lacked quotes around the stored-query name; final repeats used the valid quoted definition, and that draft is not relied on. Public reproduction is self-contained. Other native source kinds, real interactive terminals, other OSes and authenticated cloud unverified. No credentials or hosted resources created; no fixes or shipping.

---

**Resolved 2026-10-03** — native `bea query --source '.run NAME'` now runs upstream's shell through a `source-query` engine command, so a missing stored query or extra arguments exit 2 and list the stored queries that exist, invalid BQL exits 2 instead of a traceback, and `--output` is written atomically only after success. `tests/test_query_source_run_missing.py` covers the path and URI forms, exports and terminal recovery. Shipped in the commit that moved this note (`cli`).

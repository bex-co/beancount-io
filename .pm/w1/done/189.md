# An unexpected error that mentions "not found" reaches MCP callers unmasked

**Bug · backend-v2 · major · ~1h · A1.** From `/qa-find-bugs-mcp`, 2026-11-08, production `beancount-mcp 1.0.0`, protocol `2025-11-25`, unpinned read/write/admin API key on an account with no linked banks.

- **Repro:** `syncBankTransactions {"ledger":"<owner>/<name>","itemId":"","dry_run":true}`. It fails the same way without `dry_run` and with the `item_id` alias.
  - **MCP:** `isError: true`, code `NOT_FOUND`. The message is the raw database error, `Failed query: insert into "plaid_sync_logs" (…) values (…) params: <user id>,<row id>,,manual,failed,…,Plaid Item not found,…`. The hint is the generic ledgers/files/entries one.
  - **GraphQL:** `syncPlaidTransactions(itemId: "")` masks the same failure as `INTERNAL_SERVER_ERROR`.
  - **Missing `itemId`:** returns `BAD_USER_INPUT` "itemId is required — item_id works too."
- **Causes:**
  1. **Masking:** `src/features/ai-agent/api/mcp-errors.ts:311-313` (`categoryForMessage`) maps any message matching `/no such file|not found/i` to `NOT_FOUND`. `unexpectedMessage` (`:258-261`) masks only `INTERNAL_SERVER_ERROR`. So any non-`DomainError` whose text contains "not found" passes through verbatim, database and driver errors included. This dates from 489a2947a (w2/m28). The nearest prior item, w5/025, is the opposite miss.
  2. **Empty id authorized:** `src/server/api/authorization/authorization-contract.ts:199` (`bankConnectionResource`) drops `""` with `filter(Boolean)`, so an empty item id is authorized as the ledger-level bank resource.
  3. **Dry run writes:** `src/features/plaid/service/plaid-sync-service.ts:605-620`. The catch block inserts a `plaid_sync_logs` row without checking `dryRun`, and when that insert fails, its error replaces the original "Plaid Item not found".
- **Fix:**
  - Mask every non-`DomainError` in production whatever its text. Keep the message-based `NOT_FOUND` only for the tools' own guard errors.
  - Refuse an empty or whitespace `itemId`/`accountId` with `BAD_USER_INPUT` in the shared bank alias resolver and service. Make `bankConnectionResource` refuse `""` rather than drop it.
  - Skip the sync-log writes on a dry run, and stop a failed log insert from replacing the original error.
  - The shared services carry the last two fixes to REST, GraphQL and MCP together.
  - Today an empty id gives a different code on each bank tool (`refreshBankConnection` → `BAD_USER_INPUT` "Unauthorized access to Item", `mapBankAccount` → `NOT_FOUND`). Align them all on `BAD_USER_INPUT`.
- **Check:**
  - An `mcp-errors` test throws a plain `Error("… not found …")` from an unexpected path and gets a masked `INTERNAL_SERVER_ERROR`.
  - A parity test sends an empty `itemId` on MCP and GraphQL and gets `BAD_USER_INPUT`.
  - A dry-run sync against a seeded item writes no `plaid_sync_logs` row.

---

**Resolved 2026-11-10.** All three causes are fixed. The two service-level fixes reach REST, GraphQL and MCP together.
- **Masking:** MCP no longer reads an error's category from its text. Any failure that is not a `DomainError` is now `INTERNAL_SERVER_ERROR`, on both the thrown path and the `runToolSafely` path, and in production its message is masked. The one tool guard that relied on the text, `readLedgerFiles`' missing file, now throws `NotFoundError` and keeps `NOT_FOUND`. `mcp-errors.test.ts` masks a plain `Error` whose SQL quotes "Plaid Item not found".
- **Empty id:** `assertBankId` refuses an empty or blank `itemId`, `accountId` or `transactionIds` member as `BAD_USER_INPUT` ("… must not be empty") before any lookup or authorization, at every bank service entry point. It replaces the NUL-only guard. `bankConnectionResource` now refuses a blank id instead of dropping it. Sync, refresh, unlink, reconcile, account mapping and currency all answer `BAD_USER_INPUT`. `bank-empty-id-parity.test.ts` drives the six MCP tools and their GraphQL mutations with `""` and `"  "`. `plaid-nul-ids.test.ts` covers every service entry with NUL, empty and blank ids.
- **Exception:** the optional account filter on the staged-transaction reads still treats `""` as "every account", because the dashboard sends one.
- **Dry run:** a failed dry-run sync writes no `plaid_sync_logs` row and no `ITEM_LOGIN_REQUIRED` status. A failed log insert is now only logged, so the original refusal survives. `plaid-sync-service.test.ts` covers all three cases.
- **Revert check:** reverting the fixes fails 46 of the new and changed tests.
- **Docs:** `docs/mcp.md` documents the blank-id rule and the production mask. (`backend-v2`)

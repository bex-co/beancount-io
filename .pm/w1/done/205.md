# Owned-ledgers catalog and GraphQL `listLedgers` accept any page and limit

**Bug · backend-v2 · minor · ~20m · A1.** From `/qa-find-bugs-mcp`, 2026-11-09, production `beancount-mcp 1.0.0`, read-only.

- **Repro:** these all succeed:
  - MCP `beancount://catalog/ledgers/owned` with `limit=0`, `limit=1000`, `page=-1` or `page=0`. The bad value is echoed back in `_meta.page`.
  - REST `GET /api-gateway/v1/ledgers/owned?page=-1`.
  - GraphQL `listUserOwnedLedgers(page:-1, limit:0)`, `listLedgers(page:-1, limit:0)` and `listLedgers(limit:1000)`.
  - **Controls:** MCP `catalog/ledgers` and REST `GET /ledgers?limit=0` refuse (limit 1..100, page ≥ 1). GraphQL `searchLedgers(page:-1)` refuses too.
- **Cause:**
  - `catalog-reads.ts:7-8` builds `listQuery` with unbounded `z.coerce.number().optional()`, and `owned` uses it (`:49`).
  - The workflow bounds only `searchLedgers` (`ledger-workflow.ts:418`).
  - w23/019's record lists owned as bounded, but it never was.
- **Fix:** use `paginationSchema` for `owned`, and apply the same check in the workflow for `listLedgers` and `listUserOwnedLedgers`.
- **Check:** add parity tests on all three surfaces.

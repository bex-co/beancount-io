# UTF-16 bank exports are misdiagnosed as cp1252, and BOM-prefixed rules files are refused

**Severity: minor. Owner: cli. Estimate: 25–35m. A1:** Excel and Windows tools emit these files; the error must name a working fix. Continuous CLI QA, 2026-10-02 (round 2); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed unless a PTY is stated. Reproduced at least twice from pristine fixtures.

UTF-16 (Excel "Unicode Text" shape):

```sh
python3 -c "open('u.csv','wb').write('Date,Description,Amount\n2026-01-05,Coffee,-4.50\n'.encode('utf-16'))"
bea --file /abs/main.bean import /abs/u.csv --account Assets:Checking
bea --file /abs/main.bean import /abs/u.csv --account Assets:Checking --csv encoding=cp1252
```

Actual: "u.csv is not valid UTF-8 (invalid start byte at byte 0); it decodes as cp1252 — pass --csv encoding=cp1252." Following it: "Its columns are: ÿþD a t e , …", exit 2. A file beginning with `FF FE`/`FE FF` or containing NULs cannot be cp1252 text.

Cause: `probe_decoding` / `_decode_usage_error` (`cli/src/cli/csv_mapper.py:298–345`, duplicated at `cli/src/bea_engine/csv_mapper.py:463–514`) accept any decoding cp1252 can produce — which is nearly every byte string.

Second symptom, same input-encoding class: a `--rules` TOML saved with a UTF-8 BOM (`EF BB BF`, common from Notepad/PowerShell) fails with "Cannot parse rules file … as TOML: Invalid statement (at line 1, column 1)", exit 2, while CSV and JSON inputs accept a BOM (`w3/done/248`). Cause: `path.read_text(encoding="utf-8")` at `cli/src/cli/csv_mapper.py:177` and `cli/src/bea_engine/csv_mapper.py:342`.

Fix/acceptance: detect UTF-16 BOM/NUL bytes and either support `encoding=utf-16` or refuse with "the file is UTF-16; re-save as UTF-8" — never suggest cp1252 for it. Read rules with `utf-8-sig`. A BOM-prefixed rules file loads.

Dedupe: `w3/283` covered UTF-16 only for `add transactions --from` JSON; `w3/227` covered hint plumbing. No `.pm` hit for BOM + rules.

---

**Resolved 2026-10-03** — UTF-16 bank exports (with or without a BOM) are now identified as UTF-16 with a re-save-as-UTF-8 remedy instead of a cp1252 hint, other NUL-bearing files are refused as binary, and rules files are read as `utf-8-sig` so a BOM no longer breaks them. `tests/test_csv_encoding_feedback.py` covers each case. Shipped in the commit that moved this note (`cli`).

# `bea --json doctor guidance` prints text on stdout and exits 0

Found by `/qa-find-bugs-cli w1` on 2026-11-14 (HEAD `89cbf3d9a`, `bea 0.3.1`, macOS 26.5, checkout `uv run bea`, stdin closed). Severity: minor.

**Contract.** `cli/docs/USAGE.md` ("JSON output") says commands that cannot produce JSON reject JSON mode, `doctor` among them. Every other `doctor` operation does: `bea --json doctor lex main.bean` exits **2** with `{"error": {"category": "usage", "message": "bea doctor has no JSON output. …"}}` on stderr and nothing on stdout. `example`, `treeify`, `ingest` and forwarded `price` refuse in the same way.

**Repro** (any synthetic ledger, in a folder with no `AGENTS.md`):

```sh
mkdir g && cd g
printf 'option "operating_currency" "USD"\n2024-01-01 open Assets:Cash USD\n' > main.bean
bea --json doctor guidance main.bean; echo "exit $?"
```

Actual: stdout is the plain-text line `warning: AGENTS.md is missing, so a coding agent cannot read this ledger's conventions. Write one, describing this ledger as it is: bea init --existing main.bean`, stderr is empty, exit **0**. When the guidance is fine, stdout is `agent guidance OK in .`. A script that parses `--json` stdout fails on it. A sweep of `--json` across the other non-JSON commands found no second case: all of them exit 2 with an empty stdout.

**Root cause.** `doctor_guidance` in `cli/src/cli/commands/doctor.py` (around line 897) is bea-native, so it never reaches the `_refuse_json()` call that every other `doctor` operation makes. The command was added in `aacb03359` and extended in `fd8914559`, and neither added the gate. The leading-`--json` guard at line 63 only catches `bea doctor --json …`, not the global `bea --json doctor …`.

**Fix.** Call `_refuse_json()` at the top of `doctor_guidance`, the same way the other operations do, so `bea --json doctor guidance FILE` exits 2 with the usage envelope on stderr and nothing on stdout. Without `--json`, behavior stays as it is: warnings only, always exit 0, no file written. Another option is to give `guidance` a real envelope (`data.findings`), but that changes the documented contract, so `USAGE.md`'s exception list would need updating too. Add a regression test beside the existing doctor JSON-refusal tests that checks the exit code, an empty stdout and the error category. Estimate: about 20 minutes.

**Dedupe.** Searched all of `.pm/**` for `doctor guidance` and for guidance/JSON together. The hits (w1/m42 t001/t002, w21/1011, w5/1048) are about what guidance checks, not about the JSON gate. This is current code on `main`, not deployment lag.

---

**Resolved 2026-11-14.** `doctor_guidance` in `cli/src/cli/commands/doctor.py` now calls `_refuse_json()` first, like every other `doctor` operation, so `bea --json doctor guidance FILE` exits 2 with the `usage` error envelope on stderr and nothing on stdout. Without `--json` it behaves as before: warnings only, exit 0, no file written. Regression test `test_json_doctor_guidance_refuses_instead_of_plain_warnings` in `cli/tests/test_native_json_refusal.py` checks the exit code, the empty stdout and the error category, and it fails with the fix reverted.

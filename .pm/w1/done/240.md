# CI (backend parity) is red since oidc-provider 9.15.0: the CIMD draft acknowledgement is stale

**Bug · backend-v2 · major (CI) · 30–60m · A1.** `oidc-provider` 9.15.0, published 2026-11-13 17:33 UTC, ships a newer draft of the experimental Client ID Metadata Document feature. `src/features/oauth/api/oidc-route.ts:231` enables it with `ack: CIMD_DRAFT`, the draft the old version implemented. The new version refuses an unacknowledged draft at construction: "An unacknowledged version of an experimental feature is included in this oidc-provider version."

- **Where it fails:** every `CI (backend parity)` run since then fails `src/features/oauth/api/__tests__/oidc-route.test.ts`: "acknowledges the CIMD draft the installed oidc-provider implements", plus each PKCE and identity-flow case. This hits other workers' commits too (`e75ebfeb8`, `f58c89d64`). backend-v2 has no lockfile and `package.json` allows `oidc-provider: ^9.8.4`, so CI resolves 9.15.0. A local tree on 9.12.2 passes.
- **Why it matters:** CIMD is how Claude and ChatGPT identify themselves without registering (ADR 019 D6, w1/m31). A production install that resolves 9.15.0 would fail to start the OAuth provider.
- **Fix:** read 9.15.0's CIMD draft and changelog; if the behaviour w1/m31 relies on still holds, acknowledge the new draft (and keep the test that pins the ack to the installed version). Otherwise pin `oidc-provider` below 9.15 until it is re-reviewed. The ack is deliberately a re-review point, so do not just copy the new string.
- **Acceptance:** `CI (backend parity)` passes on a fresh install; `oidc-route.test.ts` passes on 9.15.0 or on the pinned version, and the Dockerfile build resolves the same version.

Found by `/loopx w1` while checking CI after w1/m43/t004. Routed to w1 by the worker, 2026-11-13.

---

**Resolved 2026-11-13.** Triaged on the 9.15.0 package itself: CIMD moved from draft-02 to draft-03. The differences are a `/`-path or issuer-equal `client_id` refused, forbidden methods in `token_endpoint_auth_methods_supported` refused, document errors answered as `invalid_client`, and the default view hiding CIMD logos. None touches what ADR 019 D6 relies on: Claude's and ChatGPT's path-bearing HTTPS client ids with `none` auth, and our own consent page.

- `oidc-route.ts` acknowledges `draft-03`, and `package.json` requires `oidc-provider` ^9.15.0, so a fresh install cannot resolve a draft-02 build against the new acknowledgement.
- ADR 019 records the re-acknowledgement and what was reviewed; its D6 row names draft-03.
- The OAuth suite (146 tests, including the one that pins the acknowledgement to the installed draft) passes on 9.15.0.
- The full backend-v2 suite passes (478 suites). Its one failure during this run, `mcp-reference-resolution` naming `renameLedgerAccount`, was a separate w1/m43/t005 regression, fixed in `51547470c`. (`backend-v2`)

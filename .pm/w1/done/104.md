# A write lands, then `bea` exits 1 when stdout cannot encode a non-ASCII path; a retry duplicates the entry

**Severity: minor. Owner: cli. Estimate: ~20m. A1:** exit codes must match the effect, or retries corrupt the ledger. Continuous CLI QA, 2026-10-03 (round 5); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control.

```sh
LC_ALL=POSIX PYTHONUTF8=0 bea --file '/abs/ü/main.bean' add transaction --date 2024-02-01 --narration x --posting 'Expenses:Café 1 USD' --posting Assets:Bank
```

Actual: exit 1 `Error: 'ascii' codec can't encode character '\xfc'…`, but the ledger changed on each run; two runs left two duplicate rows. `PYTHONIOENCODING=ascii` reproduces it; the realistic trigger is Windows piped stdout (cp1252) with CJK/emoji paths. Controls: ASCII path exits 0; `--json` exits 0; `list`/`query` print Unicode fine (`click.echo` forces UTF-8).

Expected: USAGE — "Exit 0 is a promise"; a nonzero write must mean the effect didn't happen (or say what did).

Cause: `cli/src/cli/output.py:50` — `success()` uses bare `print()` with strict encoding.

Fix/acceptance: route `success()`/`note()` through `typer.echo`, or reconfigure stdout with `errors="backslashreplace"` at startup. The repro exits 0 and writes once.

Blast radius: 24 `output.success` callers — every `add`, `import --apply` (`import_.py:688`), `init`, `format -i`, `price export`, `engine enable`.

Dedupe: [057](./057.md) is a different `UnicodeEncodeError` (token header).

---

**Resolved 2026-10-03** — stdout and stderr now escape characters the terminal encoding cannot represent, so a write whose confirmation names a non-ASCII path exits 0 after writing once instead of exiting 1 after the write landed. `tests/test_unencodable_stdout.py` covers it. Shipped in the commit that moved this note (`cli`).

# The generated `import-id` ignores payee, so a reordered export marks a new row as an exact duplicate

**Severity: major. Owner: cli. Estimate: 1–2h (may warrant promotion). A1:** re-downloading a statement must never lose or double-book rows. Continuous CLI QA, 2026-10-03 (round 11); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command with timeouts, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, stdin closed. Reproduced twice from fresh fixtures with a working control.

Base ledger: `option "operating_currency" "USD"`, `2026-01-01 open Assets:Checking USD`, `2026-01-01 open Expenses:Uncategorized USD`.

Import `p1.csv` (`--apply`):

```csv
Date,Name,Description,Amount
2026-08-02,STARBUCKS,CARD PURCHASE,-5.00
```

then `p2.csv` (`--apply`):

```csv
Date,Name,Description,Amount
2026-08-02,PEETS COFFEE,CARD PURCHASE,-5.00
2026-08-02,STARBUCKS,CARD PURCHASE,-5.00
```

Actual: PEETS (row 1) is an exact `duplicate` ("import-id csv:sha256:b89cbb… is already in the ledger"); STARBUCKS (row 2) is `possible_duplicate`. `review` exits 4; `skip` writes nothing (PEETS lost); `include` books STARBUCKS twice and still loses PEETS — no policy yields the correct ledger. Control: STARBUCKS-then-PEETS order gives `duplicate` then `new`.

Expected: rows differing in payee are different source rows; the occurrence suffix in the dedup convention is only for identical rows.

Cause: `cli/src/bea_engine/importing.py:698` hashes only `narration or payee`; the occurrence counter (`:705–707`) is keyed on that base, so row order decides which stored id each row matches.

Fix/acceptance: include the payee in the canonical base when both payee and narration are set, keeping the old base as a lookup-only legacy key (as the NFC and exact-amount migrations did); update `skills/.claude/skills/beancount-import/references/dedup.md` in the same change. The reversed-order repro writes PEETS once and STARBUCKS once. Promote if over an hour.

Blast radius: exports with a merchant column plus a generic description ("CARD PURCHASE", "POS", "Direct debit"), and exports whose same-day order changes between downloads.

Dedupe: `w3/377`, `w3/420` are different id issues.

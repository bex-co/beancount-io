# Concurrent first-use commands race engine provisioning and fail with raw errno errors (some as exit 2)

**Severity: major. Owner: cli. Estimate: 1–2h (may warrant promotion). A1:** agents run commands in parallel on fresh installs. Continuous CLI QA, 2026-10-03 (round 7); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, bea 0.3.1, macOS 26.5.1 arm64. Fresh process per command with timeouts, isolated `HOME`/`XDG_*`/`BEA_CONFIG_DIR`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control.

Artifact under test: wheel built from `cli/` with `uv build`, installed into a fresh venv (Python 3.12.14, uv 0.12.13) with HOME, XDG dirs, `BEA_CONFIG_DIR` and `UV_CACHE_DIR` inside the run dir; after the first engine install everything ran with `UV_OFFLINE=1`. Package-manager steps were **simulated** with fake `brew`/`uv` executables on PATH.

Fresh `BEA_ENGINE_DIR=<new>/0.3.1`, warm uv cache, offline; start 6 `bea --json --file /abs/main.bean check` simultaneously. Over 4 trials 3, 3, 5 and 5 of 6 failed with: `[Errno 66] Directory not empty: '…0.3.1.partial.N' -> '…0.3.1'` (exit 1); `[Errno 2] No such file or directory: '…/0.3.1' -> '…0.3.1.discarded.N'` (category `usage`, exit 2); `…/0.3.1/bin/python` not found (exit 2); children loading from an engine being deleted (`ModuleNotFoundError: No module named 'beancount.core'`, `_regex…so` load disallowed). The surviving engine works and no stray directories remain.

Expected: `provision.py:89–90` — concurrent provisions build separately and "the loser's rename is simply redundant"; `w1/done/m19/t015` required handling concurrent first use; a provisioning race is not a documented exit-2 meaning.

Cause: `cli/src/cli/engine/provision.py:338–347` `_publish` unconditionally moves aside an existing root, including one another process just published and is using; the rename back can race a reappearing root; raw `OSError`s are mapped at `cli/src/cli/errors.py:232`.

Fix/acceptance: an exclusive file lock (e.g. `engine/<ver>.lock`) around check-provision-publish, re-checking `is_provisioned` once held; in `_publish`, if a valid root exists, discard our partial instead. 8 parallel first-use commands all exit 0 with no partial/discarded directories left. Sweep dead-pid `*.partial.*` dirs under the same lock (see [123](./123.md)).

Dedupe: no `.pm` hit for concurrent provisioning / Errno 66; `t015`'s acceptance never exercised concurrency.

---

**Resolved 2026-10-03** — concurrent first-use commands now share one provisioning run under an exclusive lock and re-check the engine once they hold it, so parallel commands all succeed, and a publish failure is a clear error with exit 1. `tests/test_engine_provision_races.py` starts eight real parallel provisions. Shipped in the commit that moved this note (`cli`).

# Writes to an unknown ledger answer FORBIDDEN while reads answer NOT_FOUND

**Bug · backend-v2 · minor · ~45m · A1.** From `/qa-find-bugs-mcp`, 2026-11-08, production `beancount-mcp 1.0.0`, unpinned read/write/admin API key.

- **Repro:** use a ledger that does not exist under the caller's own name (`<owner>/qa-nonexistent`).
  - **11 write-side tools** return `FORBIDDEN` "Authorization denied" with the hint "This credential lacks the authority for that operation…": `appendLedgerText`, `updateEntrySource`, `deleteEntrySource`, `deleteEntrySources`, `renameLedgerFile`, `setLedgerStar`, `refreshManagedPrices`, `listBankConnections`, `createPullRequest`, `mergePullRequest`, `rejectPullRequest`.
  - **Reads and admin tools** on the same ledger return `NOT_FOUND` "Ledger not found": `checkLedger`, `readLedgerFiles`, `updateLedger`, `deleteLedger` and the rest.
  - **REST** matches: `POST …/directives/text` and `GET …/banks` return 403, `GET …/files` returns 404.
- **Why it matters:** an agent that mistypes a ledger name is told its credential lacks authority. The rule w23/069 set for admin operations is that a caller who cannot see the ledger gets the concealed `NOT_FOUND`. A reader who can see the ledger but cannot write gets `FORBIDDEN` naming the missing permission.
- **Cause:** in `src/server/api/authorization/authorization-service.ts`:
  - The content-write, prices, PR and star operations have no `concealDenialAs` / `deniedToReader`, starting around `LEDGER_FILES_WRITE` (:418) and `LEDGER_ENTRIES_WRITE` (:425).
  - `BANK_CONNECTIONS_LIST` (:604) lacks the concealment that `BANK_CONNECTION_READ` (:613) has.
- **Fix:** give those operations `LEDGER_NOT_FOUND_CONCEALMENT` plus `deniedToReader`. A scope or pin mismatch stays `FORBIDDEN`. Record the rule in `docs/api-parity.md` near :169-183. The shared layer covers REST, GraphQL and MCP together.
- **Check:** add parity tests on all three surfaces.
  - A missing ledger and a private ledger the caller cannot see both return 404 / `NOT_FOUND`.
  - A read-only collaborator who writes gets `FORBIDDEN`.

---

**Resolved 2026-11-10.** Writes now follow w23/069's rule for ledgers the caller cannot see. The shared authorization policy covers REST, GraphQL and MCP together.
- **Which operations:** the ledger's files and entries, which covers `appendLedgerText`, the entry-source edits, `renameLedgerFile` and `refreshManagedPrices`. Also pull-request create, merge and reject, starring a ledger, the star status read, and listing bank connections.
- **Ledger missing, or private to others:** these now answer the concealed `NOT_FOUND` "Ledger not found", like the ledger's reads.
- **A reader who cannot write:** gets `FORBIDDEN` naming the missing authority. Examples: "Changing the files of alice/main requires write access to it", or for the bank list, "… requires admin access to it". The reader check now also follows a bank-connection resource to its ledger.
- **Scope or ledger-pin mismatch:** still `FORBIDDEN`, decided before any relationship check.
- **Tests:** `authorization-service.test.ts` pins concealment, the reader refusal and the read-only-key refusal for every affected action. `rename-parity.test.ts` drives REST, GraphQL and MCP for a missing ledger, an unseen private ledger and a read-only collaborator. Reverting the policy fails 24 of them.
- **Docs:** `docs/api-parity.md` records the rule. (`backend-v2`)

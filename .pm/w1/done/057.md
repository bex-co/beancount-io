# A non-ASCII `BEA_TOKEN` or stored token fails with a raw `UnicodeEncodeError` (exit 1) instead of the auth error

**Severity: minor. Owner: cli. Estimate: 15–20m. A1:** credential mistakes must point at `bea cloud login`. Continuous CLI QA, 2026-10-02; report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`, synthetic fixtures. Reproduced twice from pristine fixtures.

```sh
BEA_TOKEN='tök' BEA_API_URL=http://127.0.0.1:9 bea --json cloud status
BEA_TOKEN='tök' bea cloud ledger list
```

Same with a `credentials.json` holding `{"token":"tök",…}`.

Actual: exit **1**, `{"error":{"category":"validation","message":"'ascii' codec can't encode character '\\xf6' in position 8: ordinal not in range(128)"}}`, raised in httpx `Headers()` while building the client. The token is not leaked. Control: `BEA_TOKEN=' '` or `'Bearer x'` gets exit 3 with "Invalid BEA_TOKEN or stored credential … run 'bea cloud login'".

Expected: the same exit 3 `auth` error for any token that cannot be a valid bearer value.

Cause: `cli/src/cli/auth/credentials.py:20` — `_INVALID_TOKEN = re.compile(r"[\s\x00-\x1f\x7f]")` misses non-ASCII; `_validate_token` (`:23–33`) passes it and `bearer_client` fails on header encode.

Fix/acceptance: also reject anything outside printable ASCII (`[^\x21-\x7e]`). Env and stored tokens containing `ö`, `€` or a zero-width space give exit 3 with the auth message on status, ledger list and ask; ASCII tokens unchanged.

Dedupe: no `.pm` hit for ascii codec / UnicodeEncodeError / non-ASCII token; validator from `d3e502f6`.

---

**Resolved 2026-10-03** — a `BEA_TOKEN` or stored token containing non-ASCII characters now gets the exit-3 auth error pointing at `bea cloud login` instead of a raw codec error. `tests/test_credentials.py` covers environment and stored tokens across several commands. Shipped in the commit that moved this note (`cli`).

# A file included twice, or an include cycle, is reported at `<load>:0`, so `bea` never says which `include` line to remove

Found by `/qa-find-bugs-cli w1` on 2026-11-16 (HEAD `3d77d1b6e`, `bea 0.3.1`, macOS 26.5, checkout `uv run bea`, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`). Severity: minor. A1: an agent that splits a ledger into includes and ends up loading one file twice gets an error with no file or line to fix, and every read and write refuses the ledger with the same unlocated line.

**Repro** (a fresh directory):

```sh
mkdir -p sub
printf 'option "operating_currency" "USD"\ninclude "sub/a.bean"\ninclude "sub/b.bean"\n' > main.bean
printf '2024-01-01 open Assets:Cash USD\n' > sub/a.bean
printf '\n\ninclude "a.bean"\n' > sub/b.bean
bea --file "$PWD/main.bean" check
bea --json --file "$PWD/main.bean" check
bea --file "$PWD/main.bean" list open
bea --file "$PWD/main.bean" add open --date 2024-01-01 -a Assets:Bank -c USD
```

**Actual.** Every command (exit 1; the `add` writes nothing) reports only

```
<load>:0: Duplicate filename parsed: "/…/sub/a.bean"
```

and `--json check` carries the same string in `error.details`. An include cycle (`sub/b.bean` holding `include "../main.bean"`) gives `<load>:0: Duplicate filename parsed: "/…/main.bean"`, and two `include "a.bean"` lines in one file give the line twice, still with no location.

**Expected.** The error sits at the include line that loaded the file a second time and names where it was first loaded, e.g. `/…/sub/b.bean:3: include "a.bean" loads /…/sub/a.bean, already included at /…/main.bean:2`; a cycle says the include leads back to a file already being loaded. Basis: the same `<load>:0` class was fixed for an include that matches no file in w1/269 (`88e007142`), and the hosted ledger service already relocates this exact message to the second include (w21/773).

**Root cause.** Upstream `beancount/loader.py` (about line 440) appends `LoadError(new_metadata("<load>", 0), 'Duplicate filename parsed: …')` without the including file or line. cli: `format_error` in `cli/src/bea_engine/query.py` (about line 3193) rewrites plugin failures, duplicate-entry reprs and, since w1/269, missing includes (`_missing_include_message`, `_include_misses`, which already walk the include closure from the root with `bea_engine.ledger.text.iter_includes`), but not this message. Plain `bea check` routes relocated errors through `_validate` in `cli/src/bea_engine/main.py` (about line 1105, `missing_includes`) and `cli/src/cli/commands/check.py` (about line 172).

**Fix.** Extend the w1/269 walk: record the first `(file, line)` that loads each normalized path, and relocate a `<load>:0` `Duplicate filename parsed` error to every later include that loads that path again (naming the first), recognising a cycle when the repeated path is an ancestor in the walk. Route it through `_validate` like `missing_includes` so plain `bea check` shows it, and keep bean-check's native output when its own options are passed, as USAGE documents. Document it next to the missing-include paragraph in `cli/docs/USAGE.md`.

**Blast radius.** Every command that loads the ledger prints `format_error` lines (`check`, `list`, `report`, `query`, `add`, `update`, `import`, `price status/export`). Working control: a missing include is already located (`include "x.bean" matches no file (looked for …)`).

**Acceptance.** The repro's `check`, `--json check` and `list open` name `sub/b.bean:3` and `main.bean:2`; the cycle case names the include that closes the loop; a regression test in `cli/tests/` fails without the fix; `make check-all` passes.

**Dedupe.** Searched `.pm/**` for "Duplicate filename", "included twice", "<load>:0", "include cycle": w5/100 and w3/413 concern `price export` writing duplicate includes (fixed), w21/773 is the hosted ledger service (fixed there), w1/269 is the missing-include sibling. No open CLI item. Estimate 40–60m.

---

**Resolved 2026-11-16** — the w1/269 include walk in `format_error` now reads the closure in the loader's first-in, first-out order and relocates `Duplicate filename parsed: "PATH"` from `<load>:0` to every include that loads a file again, naming where it was first included (`FILE:LINE: include "PATTERN" loads PATH, already included at FIRST:LINE`), and calls an include leading back to a file still being loaded a cycle (`… leads back to PATH, which includes this file (an include cycle)`; a self-include says `includes this file itself`). `--json check`, plain `bea check`, reads, and the write refusals (and `--allow-errors` warnings, staged paths mapped back) carry it; bean-check's own options keep the native line, as `cli/docs/USAGE.md` states. Regressions in `cli/tests/test_repeated_include_location.py`. Shipped in `da6f47d43` (`cli`).

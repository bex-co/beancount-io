# A valid write on a ledger with a failing balance assertion is refused with "The ledger already has 1 error(s)" and then quotes that assertion as the refused write would have left it: `accumulated 95.00 USD (5.00 too much)` where the ledger holds 100.00, 10.00 too much (gap in w5/840 and w5/1058)

**Minor · cli · 15–20m · A1.** Routine cli-qa, 2026-11-23, HEAD `4ffb4e0b8`, checkout `bea 0.5.0` (`uv run bea`), macOS 26.5.1, Python 3.12.14, managed engine 0.5.0. Isolated config and cache, stdin closed, no TTY, pristine fixture in a fresh process. No product fix implemented.

```sh
cat > main.bean <<'EOF'
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Expenses:Food USD
2026-01-01 open Income:Job USD
2026-01-02 * "pay"
  Income:Job  -100.00 USD
  Assets:Checking
2026-01-10 balance Assets:Checking 90.00 USD
EOF
bea --file main.bean check
bea --file main.bean add transaction "lunch" --date 2026-01-05 \
  -p "Expenses:Food 5.00 USD" -p Assets:Checking
```

`check` (exit 1) reports `main.bean:8: Balance failed for 'Assets:Checking': expected 90.00 USD != accumulated 100.00 USD (10.00 too much)`.

Actual: the add exits 1 and the file hash is unchanged. The refusal reads `The ledger already has 1 error(s); nothing was written. Pass --allow-errors to write anyway.`, then `main.bean:8: Balance failed for 'Assets:Checking': expected 90.00 USD != accumulated 95.00 USD (5.00 too much)`. `--json` carries the same text in `error.details`. 95.00 counts the lunch that was never written. Spending 20.00 instead turns the line into `accumulated 80.00 USD (10.00 too little)`, sending the user to look for a missing deposit when the books hold an extra 10.00.

Expected: the refusal describes the ledger on disk, quoting `accumulated 100.00 USD (10.00 too much)` as `bea check` does. It can add how the write would move the assertion, but labelled as the proposal's.

Cause: the strict pre-existing-error refusals in `cli/src/bea_engine/ledger/write.py` `validate_candidate` (the `type_errors` branch around `:3311` and the `not any_appended` branch around `:3323`) send `details` built from the candidate load's `records`. w5/1058 moved the `--allow-errors` refusal's `ledger_errors` to the before-load errors (`current`, around `:3370`). w5/840 moved only the account hints. Neither changed this path.

Fix: build these refusals' details from the before-load errors (`_before_errors()`) with their existing hints, as the `--allow-errors` refusal does.

Dedupe: searched `.pm/**` for `The ledger already has`, `already has 1 error`, `accumulated`. Related: w5/840 and w5/1058 (both done), which fixed the hints and the `--allow-errors` path. This strict path is new.

Acceptance: on the fixture above, the refusal and its `--json` `error.details` quote `accumulated 100.00 USD (10.00 too much)`. A regression test covers a backdated write that moves an existing failing assertion.

---

**Resolved 2026-11-23** — The strict refusals of a write that adds nothing wrong now quote the ledger's errors as the books hold them, shipped in the commit carrying this note (`cli`). `_preexisting_errors` (`cli/src/bea_engine/ledger/write.py`) now maps each tolerated after-error to the before-error it matched, and both "The ledger already has N error(s)" refusals in `validate_candidate` (the plain one and the data-type one) swap each matched error's text for the before-load's, keeping the location hints w5/840 already draws from disk. A balance assertion's recovery advice is recomputed from the entries on disk too: the credit-sign hint had weighed the proposal's balance, so a card holding -67.04 asserted at 77.04 was told "Did you mean -77.04 USD?" by a refused 10.00 charge, and one holding -77.04 lost the hint. Where the write would move the assertion, a hint labelled `With the proposed write (not written), it would read: …` says how, which keeps the batch total w5/725's test pins. On the note's fixture the refusal and `--json` `error.details` read `accumulated 100.00 USD (10.00 too much)` for both the 5.00 and 20.00 lunch, the file unchanged; `cli/docs/USAGE.md` states it. Regression tests: `cli/tests/test_preexisting_refusal_quotes_ledger_on_disk.py` (backdated `add transaction` and `add transactions` at both amounts, the sign hint both ways, the data-type refusal), plus the w5/725 case in `cli/tests/test_bulk_partial_unplaced_bisection.py` now pinning the on-disk line and the labelled batch effect; all 8 fail with the source change reverted.

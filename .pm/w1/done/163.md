# A ledger price written with a slash or unpadded date doesn't override the managed-feed price for that date

**Severity: major. Owner: cli. Estimate: 30–45m. A1:** users' own prices must always win over a feed, however Beancount lets them spell the date. Continuous CLI QA, 2026-10-03 (round 14); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command with timeouts, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control. Found by a regression hunt over shipped fixes.

**Local simulation:** `prices/X-USD` served by `python3 -m http.server 18765` with the feed header plus `2026-01-02 price X 99 USD` and `2026-01-03 price X 98 USD`; `MANAGED_PRICE_ORIGINS=http://127.0.0.1:18765`.

```beancount
include "http://127.0.0.1:18765/prices/X-USD"
2026-01-01 commodity X
2026/01/02 price X 5 USD
```

```sh
bea --file /abs/main.bean query "SELECT getprice('X','USD',2026-01-02) AS p FROM #prices LIMIT 1"
```

Actual: `99`; `#prices` lists both the ledger's 5 and the feed's 99 for 2026-01-02. `2026-1-2 price X 5 USD` behaves the same. Control: `2026-01-02 price X 5 USD` yields `5` and the feed's 2026-01-02 row is gone.

Expected: ledger prices override managed quotes for the same date (`a277d4e2`, ADR015).

Cause: `_LEDGER_PRICE_RE` at `cli/src/bea_engine/managed_load.py:70` matches only `\d{4}-\d{2}-\d{2}`, while Beancount accepts `YYYY[-/]M[-/]D`. The hosted overlay has the same regex at `backend-cluster/ledger/src/foundation/managed-prices/managed-price-overlay.ts:70`.

Fix/acceptance: match `(\d{4})[-/](\d{1,2})[-/](\d{1,2})` and normalise to ISO before the lookup, in both the CLI and the hosted overlay (keep parity). Slash, unpadded and ISO spellings each give `getprice` = 5 with one shadowed feed row; hosted overlay tests cover the same spellings.

Dedupe: `w3/394` (slash dates in `list --on-disk`) is a different path; `w3/432`, `w1/done/m29` don't cover it.

---

**Resolved 2026-10-03** — a ledger price written with a slash or unpadded date now overrides the managed feed price for that date, in both the CLI and the hosted ledger overlay, with dates normalised to ISO before the lookup. Tests in `cli/tests/test_price.py` and `backend-cluster/ledger` `managed-price-overlay.test.ts` cover each spelling. Shipped in the commit that moved this note (`cli`).

# One long price quote makes every amount in that currency print with that many decimals in report tables

**Severity: minor. Owner: cli. Estimate: 30–45m. A1:** human reports should show cents for a cents ledger. Continuous CLI QA, 2026-10-02; report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`, synthetic fixtures. Reproduced twice from pristine fixtures.

```beancount
option "operating_currency" "USD"
2024-01-01 open Assets:Bank USD
2024-01-01 open Assets:Broker
2024-01-01 open Equity:Opening
2024-01-01 open Expenses:Food USD
2024-01-02 * "Seed"
  Assets:Bank  1000.00 USD
  Equity:Opening  -1000.00 USD
2024-01-03 * "Lunch"
  Expenses:Food  12.50 USD
  Assets:Bank  -12.50 USD
2024-01-04 * "Dinner"
  Expenses:Food  20.25 USD
  Assets:Bank  -20.25 USD
2024-01-05 * "Buy"
  Assets:Broker  2 AAPL {187.25 USD}
  Assets:Bank  -374.50 USD
2024-01-31 price AAPL 191.559998 USD
```

`bea --file /abs/p.bean report income-statement` → `Expenses 32.750000 USD`, `Net Profit: -32.750000 USD`; `bea balance Bank` → `592.750000 USD`. Controls: removing the price line, or adding `option "display_precision" "USD:0.01"`, prints `592.75 USD`; `bea query` prints `1000.00 USD`.

Expected: every USD posting uses cents (`doctor display-context` gives `fractional_common=2`), so tables print `32.75 USD` / `592.75 USD` — m13's goal that nobody sees "4.9050 USD".

Cause: `cli/src/bea_engine/report.py:585–600` `_display_precision` uses the loader display context's `Precision.MAXIMUM`, which Beancount also feeds from price directives and `@`/`{}` numbers. Chosen in `03be7a81` for the "whole dollars with one cents purchase" case without considering quotes.

Fix/acceptance: compute per-currency max precision from posting (and balance) amounts only; keep honouring `display_precision`. Fixture prints `32.75`/`592.75`; whole-dollar-plus-one-cents ledger keeps cents; `w3/365` zero-fraction case unchanged; JSON (full precision) unchanged.

Dedupe: `.pm` search for MAXIMUM / display precision / fractional → `w3/304`, `w3/365`, m13; none covers quote-driven precision.

---

**Resolved 2026-10-03** — report and balance tables take each currency's display precision from posted amounts and balance assertions, not price quotes, so one long quote no longer widens every amount in that currency; `option "display_precision"` still wins. Tests in `tests/test_report_precision.py` cover it. Shipped in the commit that moved this note (`cli`).

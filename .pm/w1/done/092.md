# `add transaction --json` output for a `{{total}}` cost is refused when fed back if the balancing leg was omitted

**Severity: minor. Owner: cli. Estimate: 30–45m. A1:** agents pipe add output into bulk add; the documented round trip must hold. Continuous CLI QA, 2026-10-03 (round 4); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced twice from fresh fixtures with a working control.

Fixture: `2020-01-01 open Assets:Cash USD`, `2020-01-01 open Assets:Brokerage HOOL`.

```sh
bea --json --file /abs/a.bean add transaction --date 2021-01-02 --narration total -p 'Assets:Brokerage 3 HOOL {{100.00 USD}}' -p 'Assets:Cash'
# copy data.directive's date, narration and postings into rows.json
bea --file /abs/b.bean add transactions --from /abs/rows.json
```

Actual: the first add writes `{0 # 100.00 USD}` and returns `cost: {"number": null, "number_total": "100.00"}`; the bulk add exits 1 "Too many missing numbers for currency group 'USD'" and writes nothing. Control: with an explicit `-100.00 USD` cash leg the round trip succeeds.

Expected: `cli/docs/USAGE.md` — the `units`/`cost`/`price` shapes in `add transaction --json` output are valid bulk input.

Cause: `cli/src/bea_engine/protocol.py:169–171` reports per-unit `0` as `null`; `cli/src/bea_engine/ledger/writer.py:322` passes it through and `_cost_spec_text` (`writer.py:188–193`) prints `{# 100.00 USD}` ("infer per-unit cost"), leaving two unknowns. `tests/test_money_written_as_requested.py:258` covers only an explicit cash leg.

Fix/acceptance: treat `number: null` + `number_total` as a total cost (write `0 # total`), or report `"0"` and document it. The repro exits 0 and writes `{0 # 100.00 USD}`, with and without an explicit cash leg.

Dedupe: `w3/done/m49/t003` promised this round trip (tested with explicit cash only); related `w3/240`, `w1/done/m27/t005`.

---

**Resolved 2026-10-04** — bulk add now writes a cost given only as `number_total` as a total cost (`{0 # total}`, the same lot as `{{total}}`), so the `add transaction --json` answer round-trips with or without an explicit balancing leg. Tests in `tests/test_money_written_as_requested.py` cover both. Shipped in the commit that moved this note (`cli`).

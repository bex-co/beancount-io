# A fresh install of `bea` from `main` cannot start: `typer._click` is gone in typer 0.29

**Bug · cli · major · 30–60m · A2.** Every `installation` job of `CI (cli)` (uv wheel and pip sdist, on Ubuntu, macOS and Windows, Python 3.12 and 3.14) has failed since `9451a2636` (2026-11-10). The `cli` job and both Homebrew installs pass. The next `cli-v*` release would ship the break: a newcomer's `uv tool install beancount-io` would answer `bea --version` with a traceback.

- **Repro (local, 2026-11-13):** `cd cli && uv build --out-dir tmp/dist`, then `uv venv --python 3.12 tmp/v && uv pip install --python tmp/v/bin/python tmp/dist/beancount_io-*.whl && tmp/v/bin/bea --version` fails with `ModuleNotFoundError: No module named 'typer._click.types'` from `cli/utils.py:17`. `python scripts/test-install.py dist/beancount_io-*.whl --python 3.12 --installer uv`, the CI step, fails the same way.
- **Cause:** `cli/pyproject.toml` allows `typer>=0.27.0`, and a fresh resolve takes typer 0.29.1. `cli/uv.lock` pins 0.27.0, which still vendors click as the private `typer._click`, so `make check-all` passes. Five frontend modules import that private package: `cli/utils.py:17`, `native_command.py:7`, `single_value.py:14`, `main.py:12` and `commands/list.py:496`. Published 0.3.1 predates those imports and starts fine on typer 0.29.1.
- **Fix:** stop depending on typer's private vendored click. Import the same names from typer's public surface or from `click` declared as a direct dependency, whichever the installed typer versions actually provide. Or, as the stopgap, cap `typer` below the first release without `_click`. Either way, change `pyproject.toml` and regenerate `uv.lock` with `uv` (never by hand). A new direct dependency needs the owner's approval (root `AGENTS.md`).
- **Acceptance:** `python scripts/test-install.py` passes for the wheel (uv) and the sdist (pip) on a fresh resolve; the `installation` jobs of `CI (cli)` go green; a test fails if a frontend module imports `typer._click` again, or the installed-smoke check covers it.

Found by `/loopx w1` while checking CI after w1/m42/t002. Routed to w1 by the worker, 2026-11-13.

---

**Resolved 2026-11-13 (stopgap).** typer 0.29.0 replaced click's parameter types with its own, so `typer._click.types` and `ParamType` are gone. typer 0.28.0 still has them. `cli/pyproject.toml` now requires `typer>=0.27.0,<0.29`, and `cli/uv.lock` is regenerated with `uv lock`; the locked typer stays 0.27.0.
- A fresh build installed with `python scripts/test-install.py` now resolves typer 0.28.0 and passes the installed-CLI smoke (94 commands) for the wheel via uv and the sdist via pip, the two legs the `installation` jobs run.
- The `installation` matrix itself is the guard that would catch a regression, as it caught this one.
- The real fix is porting `NonEmptyPath`, `RawPath` and `IntoPath` (`cli/src/cli/utils.py`) and the other private imports to what typer 0.29 offers. That is filed as [241](../241.md). (`cli`)

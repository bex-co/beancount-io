# CSV import-ids collapse amounts beyond 28 significant digits, so a new row is skipped as an exact duplicate

**Severity: minor. Owner: cli. Estimate: 30–45m. A1:** dedup identity must be as exact as the written amount. Continuous CLI QA, 2026-10-03 (round 13); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command with timeouts, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with before/after hashes and a working control. Found by a regression hunt over shipped fixes.

Ledger opens `Assets:Bank USD` and `Expenses:Misc`. `a.csv`: `Date,Description,Amount` / `2024-02-01,Coffee,1.00000000000000000000000000001`; `b.csv`: the same row with `…00002`.

```sh
bea --file /abs/l.bean import /abs/a.csv --csv auto --account Assets:Bank --default-account Expenses:Misc --apply
bea --file /abs/l.bean import /abs/b.csv --csv auto --account Assets:Bank --default-account Expenses:Misc
```

Actual: `0 ready, 1 exact duplicates` — "import-id csv:sha256:fcb9c1ce373bc97a is already in the ledger"; the row is dropped with exit 0. Control: a 26-digit amount gets a distinct id and shows `new`.

Cause: `cli/src/bea_engine/importing.py:648` `_exact_amount` uses `number.normalize()`, which rounds to the 28-digit default context; it feeds both the generated id and `_fingerprint` (`:482`). Gap in `617dcd1d` (`w3/m45`); undercuts `37e1bd05` (`w3/408`), which writes these values exactly.

Fix/acceptance: strip trailing zeros without context rounding (e.g. normalize under a context with sufficient precision, or trim via `as_tuple()`). The two-file repro yields `1 ready` with distinct ids; `1.50`/`1.5`/`1.500` still share an id; `100` renders `100`; legacy id lookup works.

---

**Resolved 2026-10-04** — generated import ids keep every digit of the amount, so rows that differ past the 28th significant digit are no longer skipped as exact duplicates; ids written by earlier versions still match. `tests/test_import_identity_exactness.py` covers it. Shipped in the commit that moved this note (`cli`).

## Objective

Maintain the one-install experience after the initial engine setup.

## Context

- bea upgrade already selects the owning package-management channel.
- The frontend/helper protocol and engine manifest must remain compatible across upgrades.

## Steps

1. Integrate compatible engine version selection and upgrades with the normal bea upgrade path.
2. Detect missing, incomplete, or incompatible environments; produce a bea-owned recovery action that does not ask customers to pip install upstream packages.
3. Keep a working installation usable after failed upgrade/provisioning and reuse the selected engine without routine downloads.

## Files

- cli/src/cli/commands/upgrade.py; cli/ (engine lifecycle)
- cli/tests/; CLI installation scripts

## Acceptance criteria

- [x] PyPI and Homebrew upgrades select the matching helper/engine and preserve offline reuse.
- [x] A failed setup/upgrade has a tested recovery path, clean output, and no silent fallback to a global engine.

## Out of scope

- Background auto-updates, unmanaged pip changes to Homebrew environments, or a new public package manager.

## Objective

Make one Homebrew installation supply the frontend and engine as separate managed environments.

## Context

- The current formula installs dependency wheels into the same venv as bea; that layout must change.
- Reuse cli/scripts/render-formula.sh and the existing release workflow rather than adding a release channel.

## Steps

1. Install the frontend without engine runtime dependencies and provision the engine from the reviewed manifest during Homebrew installation.
2. Preserve complete license and copyright materials in installed contents, including Fava's MIT notice; apply t001's corresponding-source requirements to redistributed artifacts.
3. Resolve engine executables without changing customer PATH or using unrelated global bean-* tools. Exercise the exact sdist through the existing clean Homebrew rehearsal.

## Files

- cli/scripts/render-formula.sh; cli/scripts/test-homebrew.sh; cli/tests/test_release.py
- .github/workflows/release-cli.yml (existing CLI release integration)

## Acceptance criteria

- [x] One brew install supplies both environments and executes a local command offline after provisioning.
- [x] The installed files match the reviewed artifacts, licenses, and manifests; a conflicting global Beancount installation cannot change execution.

## Out of scope

- Installing into the frontend venv, dropping notices during copying, or bypassing the owning package manager.

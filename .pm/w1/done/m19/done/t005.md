## Objective

Run Beanquery's batch and interactive CLI independently while retaining bea's supported query extensions.

## Context

- The baseline PRINT issue and precision/path improvements are recorded in ADR014.
- The frontend currently subclasses BQLShell and imports engine result types through query_render.py.

## Steps

1. Launch bean-query for native batch/interactive dispatch, source URIs, stdin, stored queries, and output options.
2. Move precision/path/JSON/strict extension logic that needs engine objects into helper commands; remove in-process BQLShell inheritance from the frontend.
3. Compare SELECT, BALANCES, JOURNAL, PRINT, exports, shell handlers, and interruption with the selected upstream version.

## Files

- cli/src/cli/commands/query.py; cli/src/cli/query_render.py; engine helper; cli/tests/

## Acceptance criteria

- [x] PRINT reparses as directives; batch/export and interactive modes preserve native behavior.
- [x] JSON, precision, path, and strictness extensions remain explicit and work without frontend engine imports.

## Out of scope

- A new BQL engine, copying shell handlers, or passing serialized engine objects to bea.

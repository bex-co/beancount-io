# Journal edits and New Entry still wait on revalidation before confirming

**Perf · dashboard · ~45m · A2.** Found by [w1/m41](blocked/m41/README.md)'s adoption-surface check on 2026-11-02.

m41 made a file save confirm as soon as its write lands, with the new-error check running behind it. Two other writers still await `useWriteOutcome().report()`, which refetches `GetLedgerErrors` and so revalidates the whole ledger, before they confirm:

- `dashboard/src/features/journal/components/entry-context-panel.tsx`, the entry edit save (`if (!(await writeOutcome.report(before)))`);
- `dashboard/src/features/journal/components/new-directive-dialog/index.tsx`, New Entry (`leftErrors: await writeOutcome.report(before)`).

On a 312KB ledger that adds 0.6–0.8s, and more on a cold ledger, to every journal edit. The importer and Open Account already run the check in the background.

- **Fix:** have `useWriteOutcome` own the order, for example `confirm(before, successMessage)`: toast on the write, check in the background, warn if new errors appeared. Then all five writers (file save, journal entry, New Entry, importer, Open Account) make the same call and show the same pair of messages. `/simplify` on m41 recommended this, because the hook's doc still says `report` returning true makes the caller skip its success message. New Entry uses `leftErrors` to decide what happens next, for example whether it keeps the dialog open. Check that decision before changing it, and keep any behavior that genuinely depends on the result.
- **Check:** the success and close follow the write's response, the new-error warning still appears, and the existing write-outcome tests in `new-directive-dialog/__tests__/` and `journal/components/__tests__/` still pass.

---

**Resolved 2026-11-02.** Neither writer blocks on the revalidation any more.
- **Entry edit:** `entry-context-panel.tsx` finishes the save, closing the panel and refreshing, as the write lands.
- **New Entry:** `new-directive-dialog/index.tsx` calls `onSuccess` at once with `leftErrors` as a promise, so the journal list refreshes immediately.
- **Deviation from the proposed fix:** the success message still waits for the check, and is replaced by the warning when the write broke the ledger. That keeps w3/640's "say so instead of saved" decision (`b47c3133d`) for journal writes. Only the message waits; the panel, the dialog and the journal refresh do not. A file save shows both messages (w1/m41/t001). Unifying the two is left for [185](../185.md)'s pass if the owner wants one rule.
- **Tests:**
  - `entry-context-pending-save.test.tsx`: the panel closes while the check is pending, and "saved" follows when it settles.
  - `new-directive-dialog/__tests__/write-outcome.test.tsx`: the handover comes before revalidation, and `leftErrors` settles true or false.
  - Both were mutation-checked against the awaiting code. (`dashboard`)

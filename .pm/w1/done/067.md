# The interactive query shell prints raw Python tracebacks for errors the one-shot path already explains

**Severity: minor. Owner: cli. Estimate: 30–45m. A1:** agents reading the shell need actionable errors, not tracebacks. Continuous CLI QA, 2026-10-02 (round 2); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed unless a PTY is stated. Reproduced at least twice from pristine fixtures.

In a PTY: `bea --file /abs/main.bean query` on any small ledger with a transaction, then enter each of:

```
SELECT DISTINCT tags;
SELECT account GROUP BY accounts;
SELECT (SELECT 1);
```

Actual: each prints `error:` followed by a full Python traceback ending in `SyntaxError: cannot use starred expression here`, `TypeError: issubclass() arg 1 must be a class`, or `AttributeError: 'EvalQuery' object has no attribute 'childnodes'`. Control: one-shot `bea query 'SELECT DISTINCT tags'` exits 2 with "BQL cannot use DISTINCT or GROUP BY on tags…" and advice (`w3/353`, `w3/358`).

Expected: the same messages at the prompt and the session continues; the shell's own comment at `cli/src/bea_engine/query.py:488–505` says a traceback at the prompt is wrong and `--debug` asks for one.

Cause: translation lives only in `_executed` (`query.py:677–730`), used by the one-shot path. `PreciseShell.execute` (`:466`) and `onecmd` (`:488–491`) catch only `protocol.EngineError`, so these fall through to upstream `cmdloop`'s traceback printer.

Fix/acceptance: share the translation between both paths. All three inputs print the one-shot message without `Traceback` and the prompt continues.

Dedupe: `w3/353`, `w3/358`, `w3/447` cover only one-shot.

---

**Resolved 2026-10-03** — the interactive query shell, `.run` and native `--source` one-shots now print the same explained error as the one-shot path for BQL that Beanquery cannot compile, with no traceback, through one shared compile step. Real-terminal tests in `tests/test_query_shell_usage_errors.py` cover it. Shipped in the commit that moved this note (`cli`).

## Objective

- Checkout returns to the dashboard confirmation instead of the marketing page.
- A cancelled Checkout returns to the pricing page with the chosen plan and cycle.
- The billing portal returns to Billing settings.
- Every portal session uses a configuration that allows only payment methods, invoices and billing details.

## Context

- `successUrl`, `cancelUrl` and `portalReturnUrl` are static in `SUBSCRIPTION_CONFIG` (`backend-cluster/backend-v2/src/features/stripe/service/stripe.ts:201–206`). `billingPortal.sessions.create` passes no `configuration` (`stripe-service.ts:714`), so portal plan switching follows the account default. A switch to an unconfigured price would resolve to Free.
- **Pricing-page compatibility** (milestone README):
  - Today a customer who pays on the pricing page returns to `https://beancount.io/pricing/?success=true`, and that page does not read `success`.
  - The new destinations must exist before this task ships: `/settings/billing` from t006 and its confirmation state from t008.
  - The pricing page already reads `?billing=yearly`, so the cancel return pre-selects the cycle. It ignores `plan` and `checkout` until it changes.
  - The old success URL may be a Google Analytics conversion trigger. That configuration lives outside this repository.
- A portal configuration ID is account-specific but not secret. Wire it like other runtime settings: root `bex.yaml`, `deploy/*/docker-compose.yml` and the env examples.
- PRFAQ005 question 15 (After Checkout) and question 17.

## Steps

1. Ask the user whether any Google Analytics key event or report keys on `/pricing?success=true`. If one does, record that it must move to the new confirmation, or to m39/t010's server-side `purchase`, before this ships. Block this task if the answer is unavailable.
2. Build per session:
   - `success_url`: `https://beancount.io/settings/billing?checkout=success&session_id={CHECKOUT_SESSION_ID}`
   - `cancel_url`: `https://beancount.io/pricing?plan=<tier>&billing=<monthly|yearly>&checkout=canceled`, from the price's tier and t001's interval.
   `createSubscriptionSession` keeps its arguments and accepted prices.
3. Point `portalReturnUrl` at `https://beancount.io/settings/billing`.
4. Read a portal configuration ID from config and pass it on every portal session. When it is unset, log one warning naming the variable and keep today's behaviour, so a deploy without it still works.

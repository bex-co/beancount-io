## Objective

`/settings/billing?checkout=success&session_id=…` shows "Confirming your payment…" while it polls subscription status. It then shows a success state: plan and cycle, renewal date and amount, a receipt line, the limits unlocked, and **Back to <where the upgrade began>**. If the webhook has not arrived after about 20 seconds, it shows a neutral "Payment received" state. That state is never styled as an error.

## Context

- This ships **before** t003 points Checkout here, so a paying customer is never returned to a missing page. Until t003 lands, Checkout still returns to the pricing page.
- Wireframe: PRFAQ005 question 15 (After Checkout).
- The return path is stored before redirecting to Checkout and validated with `getSafeRedirectPath` (`dashboard/src/common/lib/auth/auth.ts`).

## Steps

1. Read `checkout` and `session_id` through the route's schema, using the lenient readers in `dashboard/src/common/lib/search-params/tolerant`.
2. Poll subscription status with a bounded interval and stop on success or timeout.
3. Render the three states, and send **Back to …** only to a validated same-origin path.

## Files

- `dashboard/src/routes/settings.billing.tsx`, the billing page components and locales

## Acceptance criteria

- [ ] Polling stops when the subscription appears, or after the timeout.
- [ ] All three states render in every dashboard locale.
- [ ] An unsafe or missing return path falls back to Billing.
- [ ] A missing or unknown `session_id` shows Billing without an error.

## Out of scope

- Verifying the session server-side; status polling is the source of truth.

## Implementation notes

- `/settings/billing` reads `checkout`, `session_id` and `return` through a tolerant schema (`features/user-settings/lib/billing-search.ts`), so a mistyped value renders Billing.
- With `checkout=success`, the subscription section shows the confirmation (`pages/general/checkout-confirmation.tsx`). It polls status every 2 s until the webhook records the subscription. After 20 s it shows "Payment received", with a Refresh button, styled as information rather than an error.
- The success state gives the plan and cycle, the renewal date and amount, the quotas unlocked (one shared formatter with the plan banner), **Back to where you were** and **View billing**. View billing clears the query.
- The return path is stored in session storage just before the redirect to Checkout, and read once afterwards. It is validated with `getSafeRedirectPath` on the way in and the way out.
- **Wording deviation from PRFAQ005:** the pending state says "refresh to check" rather than "we'll email you when it's active". The backend sends no activation email today, and Stripe's receipt is the only email.
- Checkout still returns to the pricing page until t003 changes `success_url`. This page is ready first, so a paying customer is never sent to a missing page.

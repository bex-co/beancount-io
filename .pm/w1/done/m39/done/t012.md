## Outcome — 2026-10-18

Three reviewers covered the billing code changed since the milestone was planned: the backend Stripe feature, the dashboard Billing pages, and the shared dashboard billing modules. Each looked for reuse, quality and efficiency. Only behaviour-preserving changes were applied.

**Backend** (`backend-cluster/backend-v2/src/features/stripe/`):
- `previewPlanChange` runs its independent Stripe calls in parallel: active plans with the list price, then the default card with the invoice preview. An immediate preview now waits on the network twice instead of four times.
- Its refusals go through one `refused()` helper. `kind`, `refusal` and `effect` are set once instead of in each return.
- One `PlanChangeDeps` type, in `current-plan.ts`, replaces four copies across preview, apply, schedule and the loader.
- `holdsVerifiedPeriod()`, beside the verification version, is now the single "cached period is still verified and current" test. It is shared by `lastVerifiedTier` and the cached `subscriptionStatus` path, so a version bump cannot miss one of them.
- Billing status looks up each subscription's default card alongside its item lookups.
- `report-purchase` reuses `expandableId`.

**Dashboard:**
- A confirmed change no longer refetches the plan twice. `useChangePlan` already refetches the profile and the subscription and waits for both, so the sheet's extra `onChanged()` after a scheduled or immediate change went. `use-plan-change.test.ts` pins the hook's refetch.
- `planLabelKey(tier)` (`tier-config.ts`) names a plan, Free and Enterprise included. The plan banner, the General summary link and the failed-renewal banner use it.
- The quota lines (`ledgersLine`, `collaboratorsLine`, `aiTokensLine` in `tier-quota-summary.ts`) are written once, not three times.
- `subscription-section.tsx` dropped its copies of the tier tables, which duplicated `tier-config`, and its config alias. Checkout is one `startCheckout`.
- The sheet looks the target tier up once.
- `planChoice`'s two no-cycle branches are merged. The AI CFO panel uses `getUpgradeTiers`. The picker's unused third `onChoose` argument went.

**Considered and left:**
- Collapsing `upgradeSubscription`'s two returns: it hurts readability.
- A shared multiple-subscriptions loader: the three callers return different shapes.
- Typing `periodTier` as the enum: it is validated where it is read.
- Replacing `PlanInterval` with `BillingCycle` everywhere: churn across five files and seventeen test literals.
- A `usePlanPreview` hook: the two previews differ in what they do once they resolve.
- Moving `stripe-config` into `common/`: an existing layering precedent.

**Not simplifications** (they change what readers see):
- The section's two plan labels show "Free" for an Enterprise user.
- `renewalDate` and `BillingSection` format dates and money with the host locale rather than the app language.

Both are candidates for t013's tests or a follow-up.

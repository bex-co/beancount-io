## Objective

`/settings/billing` replaces the subscription section of `/settings/general`, and `/settings/general` keeps a one-line plan summary that links to it. The tab has three parts:

- A summary card: plan and cycle, amount, renewal date, card, and a label on a legacy price.
- A "Pay yearly" line with the yearly saving, on monthly plans only.
- A plan row showing every tier from Free to Enterprise, with a Monthly/Yearly toggle that defaults to Yearly, the current plan marked, and Growth as most popular.

## Context

- Today: `dashboard/src/features/user-settings/pages/general/{subscription-section.tsx,subscription-upgrade-cards.tsx,subscription-plan-banner.tsx}`. `getUpgradeTiers` (`dashboard/src/common/lib/subscription/tier-config.ts`) lists only higher tiers.
- Routes live in `dashboard/src/routes/settings.*.tsx`. Search parameters use the lenient readers in `dashboard/src/common/lib/search-params/tolerant` (since `3957b5d0d`, a mistyped value renders the default instead of an HTTP 500). Copy goes in `dashboard/src/features/user-settings/locales/*.ts`.
- **Pricing-page compatibility:** the pricing page's "Manage subscription" link goes to `/settings/general`. That page must keep reaching the plan UI in one click.
- Wireframe and copy: PRFAQ005 question 15 (Billing settings). Most popular: question 21 decision 5.

## Steps

1. Add the `settings.billing` route and its settings navigation entry. Move the usage overview and billing section there.

## Implementation notes

- `/settings/billing` (`dashboard/src/features/user-settings/pages/billing/`) holds the subscription section, and the settings navigation gains a Billing tab. Both are hidden inside the native app's web view: the tab is not rendered and the route redirects to General, matching the existing rule that the app never shows billing (ADR001-mobile-billing).
- The summary card states the price and cycle, a legacy-price label, the card (brand and last four) and the renewal date. `Subscription.paymentMethod` is now requested in `GetSubscriptionStatus`.
- The "Pay yearly" line appears only on a monthly plan, with the saving computed from a checked-in price table that now sits next to the price IDs in `stripe-config.ts`. Until t007's change sheet lands, it and the plan row's immediate choices run through `upgradeSubscription`, which now applies only immediate changes (t002).
- The plan row (`subscription-plan-picker.tsx`) lists Free → Enterprise. Yearly is the default cycle and Growth is badged. Labels come from `common/lib/subscription/plan-change.ts`, a mirror of the server rule used only for labels. Changes that wait for renewal are disabled with a "coming soon" hint until m40. Enterprise links to contact.
- Settings → General keeps a "Subscription" card that links to Billing, so the pricing page's "Manage subscription" link (`/settings/general`) reaches the plan in one click. The old upgrade cards and their unused `userSettings.upgradeYourPlan` key are gone. Thirteen new keys ship in all 15 dashboard catalogs.
- **Not done here:** the real-browser English/Chinese check through the language selector. No browser was available in this session; the deployed check in t014 covers it. Locale shape, interpolation and the stray-English gates pass.

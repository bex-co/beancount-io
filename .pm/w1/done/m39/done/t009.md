## Objective

`/settings/billing?plan=<tier>&billing=<monthly|yearly>&from=<surface>&return=<path>` opens t007's sheet prefilled. The in-product upgrade prompts link there with a recommended plan:

- the next tier, for a ledger or collaborator limit;
- the lowest tier whose allowance covers current usage, for AI tokens.

## Context

- Four prompts link to `/settings/general` today: `dashboard/src/common/components/ai-cfo-upgrade-panel.tsx`, `ledger-layout/directive-usage-indicator.tsx` and `limit-indicator.tsx`, plus `dashboard/src/features/importer/components/steps/upload/parse-error-display.tsx`. `dashboard/docs/event-taxonomy.md` documents their `upgrade_prompt_clicked` event.
- The marketing pricing page links subscribers to the same URL shape, so it is a public contract.

## Steps

1. Read the parameters with the lenient readers in `dashboard/src/common/lib/search-params/tolerant`, so a typo renders Billing rather than an HTTP 500. Ignore unknown values, and validate `return` with `getSafeRedirectPath`.
2. Point each prompt at the deep link with its recommended plan, keeping `upgrade_prompt_clicked`.
3. Document the URL contract next to the billing route.

## Implementation notes

- `/settings/billing` reads `plan`, `billing` and `from` through the same tolerant schema as `checkout` (`features/user-settings/lib/billing-search.ts`). An unknown plan or cycle is dropped, so the page renders Billing with no sheet. The contract is written beside the route in `dashboard/src/routes/settings.billing.tsx`.
- A link with `plan` opens the change sheet on that plan, on yearly unless `billing` says otherwise. A Checkout return (`checkout=success`) opens no sheet, even if `plan` is present.
- All four prompts render one `UpgradePromptLink` (`common/components/upgrade-prompt-link.tsx`). It builds the search with `billingLinkSearch`, attaches the current page as `return` (`useSafeReturnPath`, renamed from `useLoginNextPath`), and records `upgrade_prompt_clicked` with a typed `UpgradeSurface`. `target_tier` is now always the recommended plan.
- The link is rendered only where the prompt shows, so the router subscription stays off pages without an upgrade. `LimitIndicator` takes `tier` from its parent, which already has it, rather than issuing another limits query.
- `return` is made safe once, when the URL is parsed. Closing the sheet removes `plan`, `billing` and `from` from the URL, but keeps `return`, so a reload does not reopen the sheet.
- Recommended plans:
  - ledger, collaborator and entry limits: the next tier up (`getNextTier`);
  - the importer paywall: the next tier up, so a Premium user who spent the AI allowance is offered Growth rather than their own plan;
  - AI-CFO cards: each card opens its own plan.
- **Deviation:** the AI-CFO cards open on **monthly**, not yearly, because each card quotes a monthly price and the sheet must show the price the card promised. Showing the yearly equivalent on those cards belongs to t011's adoption review.
- `return` survives both paths:
  - Checkout keeps it in session storage (t008);
  - an in-place change confirms with a toast whose **Back to where you were** action does a full load, so every query reads the new plan's limits.
- The sheet now has copy for the `NO_SUBSCRIPTION` refusal, which happens when a subscription ends between preview and confirm. A preview whose effect is `SCHEDULED` (a downgrade or a switch to monthly) shows "coming soon" instead of a confirm button, until m40 schedules those changes.
- The importer heading still reads "Upgrade to Premium" when the recommended plan is Growth; rewording it in 15 locales is left to t011.
- The `from` surface is carried on the URL but not yet read; t010 attaches it to `plan_change_previewed`.
- The importer paywall still issues its own limits query on its rare error path; its parent does not hold the tier.

# A `pushtag` or `pushmeta` left open is reported at line 0 (`trips.bean:0: Unbalanced metadata key 'trip'`) by `bea check`, `--json check`, every read and `init --existing`, though `bea add` names its line

**Bug · cli · minor · ~45m · A1.** From routine cli-qa, 2026-11-20. A file that opens `pushtag #x` or `pushmeta key: "v"` and never closes it is a ledger error. Every `bea` surface reports it at line 0 of that file, a line that does not exist. Without a line, a person or an agent has to search the file for the push that was never popped. The location rule is the one w1/269, w1/273, w1/299, w1/341 and w1/342 applied to other line-0 findings. `bea` already knows the line: `bea add --into` that file refuses with "ends inside `pushmeta trip:` at line 2" (w5/464, `open_pushes`).

Environment: main `f925aec44` (no `cli/` change since `6e241b435`), `bea 0.5.0` from the checkout (`uv run bea`), Python 3.12.14, macOS 26.5.1 arm64. Isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, `BEA_NO_UPDATE_NOTIFIER=1`, `BEA_FILE`/`BEA_TOKEN` unset, stdin closed, no TTY, cwd a scratch directory. Reproduced in fresh processes. Every command left both files byte-identical (same md5).

## Repro

A trip file whose `popmeta` was forgotten:

```sh
cat > main.bean <<'EOF'
option "operating_currency" "USD"
2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:Food USD
include "trips.bean"
EOF
cat > trips.bean <<'EOF'
pushtag #berlin-2026
pushmeta trip: "Berlin"
2026-02-03 * "Taxi"
  Expenses:Food  12.00 USD
  Assets:Cash
2026-02-04 * "Dinner"
  Expenses:Food  40.00 USD
  Assets:Cash
poptag #berlin-2026
EOF
bea --file main.bean check                                   # 1
bea --json --file main.bean check                            # 2
bea --file main.bean report income-statement                 # 3
bea --file main.bean list transaction --allow-errors         # 4
bea --json init --existing main.bean                         # 5
bea --file main.bean add transaction Bus --date 2026-02-05 \
  -p 'Expenses:Food 3.00 USD' -p Assets:Cash --into trips.bean --allow-errors   # 6 (control)
```

Actual:

1. Exit 1: `…/trips.bean:0: Unbalanced metadata key 'trip'; leftover metadata 'Berlin'`.
2. Exit 1: the same `trips.bean:0:` string in `error.details`.
3. Exit 1: `Ledger has 1 error(s)…` with the same `trips.bean:0:` line. `list`, `balance` and `query` refuse the same way.
4. Exit 0: the same `:0` line as the `--allow-errors` warning on stderr.
5. `errors[0]` is `{"file": "…/trips.bean", "line": 0, …}`, and `attention[0].location` is `trips.bean` with no line. The text form prints `trips.bean: Unbalanced metadata key 'trip'…`. USAGE ("A ledger `bea` did not create") promises each attention item "at its `file:line`".
6. Control: exit 2, nothing written: ``…/trips.bean ends inside `pushmeta trip:` at line 2, so an entry appended there would silently inherit it.``

An unclosed `pushtag` gives `trips.bean:0: Unbalanced pushed tag: 'berlin-2026'` on the same surfaces. A file that pushes `#trip` twice and pops it once does too. Upstream `bean-check` prints the same `:0` line: `beancount/parser/grammar.py` `finalize()` builds both errors with `new_metadata(filename, 0)`. The unmatched `poptag`/`popmeta` errors ("Attempting to pop absent tag") already carry their real line.

## Expected

Every surface names the line of the push that was never closed, in the file that holds it. For the repro: `…/trips.bean:2: Unbalanced metadata key 'trip'; leftover metadata 'Berlin'`. The message adds the remedy the write refusal already gives: close it with `popmeta trip:` after the last entry it should cover. For an unclosed tag it says `poptag #berlin-2026`. Under `init --existing`, `errors[].line` is 2 and the attention item reads `trips.bean:2`. With repeated pushes of one name, the reported line is the one `open_pushes` leaves open. The surfaces are `--json check`, strict-read refusals, `--allow-errors` warnings and `init --existing`. Plain `bea check` with no bean-check options should do the same, as it does for includes (w1/269). With bean-check's own options (`-v`, `--auto`, its `--json`), the output stays bean-check's, as USAGE documents for the include case.

## Cause

- `format_error` (`cli/src/bea_engine/query.py`, about line 3514) renders `source['lineno']` as given, so both errors print `:0`. It already rewrites `<load>:0` plugin failures and include errors, and the `Transaction(…)` duplicate reprs.
- The `init --existing` error record (`cli/src/bea_engine/describing.py`, about lines 77–96) reads the same `lineno` 0, and the text renderer drops the `:0`.
- `open_pushes(text)` (`cli/src/bea_engine/ledger/write.py`, about line 4492) already returns `(line, "pushtag #x" | "pushmeta key:")` for each push still open at the end of a file. Today only the append refusal (`_refuse_unsafe_append_context`) calls it.

## Fix

Owner `cli`, engine side. When a loader error's message is `Unbalanced pushed tag: 'NAME'` or `Unbalanced metadata key 'KEY'; …` and its `lineno` is 0, read that error's file and take the line `open_pushes` reports for that name. Use that line in `format_error` and in the `describing` error record, and append the `poptag #NAME` / `popmeta KEY:` remedy. In plain `bea check` with no options, add these errors to the helper-reported set (beside `include_errors`), so the line replaces bean-check's `:0`. Document it in `cli/docs/USAGE.md` next to the include paragraph ("An `include` that matches no file is reported at the line that wrote it…").

Regression tests: the repro's surfaces 1–5 for both an unclosed `pushmeta` and an unclosed `pushtag`, and the push-twice-pop-once case. The `poptag`-without-push control keeps its line. The tests must fail with the fix reverted. Run `make check-all` in `cli/`. There is no REST/GraphQL/MCP change: the hosted ledger service parses with rustledger and does not share this renderer.

## Blast radius

Callers of `format_error` cover every read's refusal and `--allow-errors` warning, `--json check` details and `add` refusals over pre-existing errors. `describing` covers `init --existing` text and JSON. Plain `bea check` passes bean-check's own words through except for the helper-reported classes in `cli/src/cli/commands/check.py`. Working controls: the write refusal (`write.py` `_refuse_unsafe_append_context`) and the pop-without-push errors, which upstream already locates.

## Dedupe

Searched `.pm/**` (open, `done/`, `blocked/`) for `Unbalanced pushed tag`, `Unbalanced metadata key`, `pushtag`/`pushmeta` with `:0` or `line 0`, and `open_pushes`. Also ran `git log -S "Unbalanced pushed"`. w5/464 and w5/710 (done) cover the append refusal, not where the read error is located. w1/269 and w1/273 (includes), w1/299 (valueless `custom`), w1/341 (documents folder) and w1/342 (plugin-made transactions) fixed other line-0 locations. No open item covers this, and the code at HEAD is unchanged, so this is not deployment lag.

**Resolved 2026-11-20** — Reproduced at `317d6ef8f`: surfaces 1–5 of the repro all named `trips.bean:0`, and the `add --into` control named line 2. A new `unclosed_push` in `cli/src/bea_engine/query.py` matches `Unbalanced pushed tag: 'NAME'` and `Unbalanced metadata key 'KEY'; …` at line 0, lexes that error's file again with `open_pushes`, and returns the push still open for that name, with the remedy: `trips.bean:2: Unbalanced metadata key 'trip'; leftover metadata 'Berlin'. Close it with `popmeta trip:` after the last entry it should cover.` (an unclosed tag names `poptag #NAME`). A name pushed more often than popped is reported at the earliest push left open, and any other open push of it is named after it (`; also left open at line 8`). `format_error` and the `describing` error record use it, so `--json check` details, strict-read refusals, `--allow-errors` warnings and `init --existing` (`errors[].line` 2, attention `trips.bean:2`) all carry the line. Plain `bea check` with no options adds these errors to the helper-reported set (`unclosed_pushes`, beside `include_errors`). With bean-check's own options the output stays bean-check's. `cli/tests/test_unclosed_push_location.py` runs real `bea` subprocesses over every surface for an unclosed `pushmeta` and an unclosed `pushtag`, three repeated-push cases, and three controls: pop-without-push keeps line 7, native `check --json` keeps `lineno` 0, and an unreadable file keeps line 0. Its nine surface tests fail with `unclosed_push` disabled. `cli/docs/USAGE.md` documents it after the include paragraphs. `make check-all` is green. Shipped in `cd672574b` (`cli`).

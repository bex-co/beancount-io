# CSV query cells leak `filename`/`lineno`/`__tolerances__` metadata as a Python dict repr

**Severity: minor. Owner: cli. Estimate: 20–30m. A1:** exports must not leak internal keys or absolute paths. Continuous CLI QA, 2026-10-03 (round 10); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1 (Beancount 3.2.3, beanquery 0.2.0), Python 3.13, macOS 26.5.1 arm64. Fresh process per command with timeouts, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME` (so `~/.config/beanquery/init` below is the isolated home), notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control.

```sh
printf '%s\n' '2024-01-01 open Assets:Cash' '2024-01-01 open Equity:Opening' '2024-01-02 * "P" "n"' '  note: "hi"' '  Assets:Cash  1.00 USD' '  Equity:Opening' > min.bean
bea --file /abs/min.bean query "SELECT entry.meta AS m WHERE account='Assets:Cash'" -f csv
bea --file /abs/min.bean query "SELECT meta WHERE account='Assets:Cash'" -f csv
```

Actual: `entry.meta` → `"{'filename': '/abs/min.bean', 'lineno': 3, 'note': 'hi', '__tolerances__': {'USD': '0.005'}}"`; a posting without metadata → `{'filename': …, 'lineno': 5}` where text shows `{}`. Cells are Python repr (single quotes, `True`), neither JSON nor upstream format; `SELECT entry -f csv` likewise prints a JSON-walk repr. Controls: the text table and native `bean-query -f csv` print `{'note': 'hi'}`.

Cause: `cli/src/bea_engine/query.py:671` (and `:674`) — `_csv_from_jsonable` does `str(value)` on `protocol._jsonable` output, skipping upstream's metadata filter (`beanquery/sources/beancount.py:62–64`). From `1b695269` (`w3/254`).

Fix/acceptance: render metadata cells with upstream's filter (or JSON-encode the filtered dict) and directive cells consistently; CSV `meta`/`entry.meta` cells contain no `filename`/`lineno`/`__` keys and match the text cell. Decide JSON's treatment in the same change.

---

**Resolved 2026-10-03** — query cells for `meta`, `entry.meta` and whole directives no longer carry the loader's `filename`, `lineno` or `__*` keys in text, CSV or JSON; a CSV metadata cell matches the text cell and a CSV directive cell is Beancount text. `tests/test_query_metadata_cells.py` covers it. Shipped in the commit that moved this note (`cli`).

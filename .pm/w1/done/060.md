# A bank CSV currency cell injects additional ledger directives through import

**Severity: major. Owner: cli. Estimate: 45–60m. A1:** an imported bank row must not manufacture additional directives by embedding ledger text in its currency field. Continuous CLI QA, 2026-10-02; report and filing only. This restores the currency-injection finding whose original ID 045 collided with the concurrently filed typed-metadata issue.

Environment: `main` at `97dab6b04c6e40e4cf47e0c1d668731d36c7ec41`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13.0, Darwin 25.5.0 arm64. Fresh bounded subprocesses in a disposable cwd, isolated child config/cache/data, no inherited target/token, notifier disabled, stdin closed, no TTY. Reproduced twice from pristine fixtures by the filer during collision recovery.

Save `main.bean` (accounts intentionally permit arbitrary commodities):

```beancount
option "operating_currency" "USD"
2025-01-01 open Assets:Cash
2025-01-01 open Expenses:Food
2025-01-01 open Equity:Opening
```

Create `bank.csv` with Python's standard CSV writer:

```python
import csv
currency = 'USD\n  Equity:Opening\n2025-01-02 event "marker" "injected"\n2025-05-01 * "extra"'
with open("bank.csv", "w", newline="") as stream:
    writer = csv.writer(stream)
    writer.writerow(["Date", "Description", "Amount", "Currency"])
    writer.writerow(["2025-05-01", "Shop", "-5", currency])
```

Run with absolute paths:

```sh
bea --json --file /absolute/main.bean import /absolute/bank.csv --csv date=Date,narration=Description,amount=Amount,currency=Currency --account Assets:Cash --default-account Expenses:Food --apply
bea --json --file /absolute/main.bean check
bea --json --file /absolute/main.bean query 'SELECT type, count(*) FROM entries GROUP BY type'
```

Actual: import exits **0**, empty stderr. One bank row produces **three transactions and two event directives**. `check` exits 0; BQL returns `["open",3]`, `["event",2]`, `["transaction",3]`. The original source/counter postings have been split across two transactions balanced independently through Equity:Opening, and the last injected transaction is posting-less. Preview also exits 0 with an unchanged ledger but carries the injected text in its diff. This is actual persisted fixture behavior, not a simulated response. No plugin or external command execution was attempted or claimed.

Expected: currency is one commodity token. Reject this malformed field with a row/column usage error before preview/apply can treat it as accounting syntax; the ledger must remain byte-identical. Valid USD/EUR/custom commodity tokens must continue importing normally. Account currency restrictions are not an input-syntax validator: unrestricted accounts are legitimate.

Cause: `cli/src/bea_engine/csv_mapper.py:935–954` takes the mapped currency cell and puts it directly in both `Amount` objects without validating commodity-token syntax. Its `_check_cell_symbols` checks amount-symbol disagreement, not the mapped token's grammar. The formatter prints that currency verbatim; candidate ledger validation checks that the resulting text is a valid ledger but not that one requested transaction stayed one transaction. The inserted balancing postings and headers make the malicious text valid. The one CSV row thus becomes several directives despite a successful validation pass.

Fix/acceptance: validate mapped currency cells with the existing commodity grammar before constructing amounts; reject control/newline characters and any multi-token spelling. Add a defensive requested-entry/parsed-entry invariant where appropriate without weakening upstream semantics. Reproduce preview and apply rejection, unchanged root/includes, an unrestricted-account control, and valid multi-currency imports. Run meaningful real-command regression coverage and `make check-all` in `cli/`. No new dependency or backend change.

Dedupe: searched all public board states for currency injection and token validation. The original collision's README entry advertised this distinct finding as 045, while that file now contains typed-metadata precision evidence. Related `w1/046` covers bulk/single directive tag/link/flag/currency token injection; coordinate the shared currency grammar, retain independent CSV regressions, and do not duplicate implementation work. Completed amount/separator import fixes do not validate this mapped field. Other executable configuration injection paths and platforms are unverified.

Evidence: `cli/tmp/qa-20261002-loop/currency_repeat.py`, its two sanitized captures in `captures.jsonl`, and synthetic `currency-injected.csv`. Failed exploratory payloads in `currency_injection.py` are controls and are not relied on for success claims. The public fixture above is self-contained. No real-ledger writes, credentials, hosted resources, product fixes or shipping.

---

**Resolved 2026-10-03** — a CSV import's mapped currency cell must be exactly one commodity name, otherwise the import is refused with its row and column (exit 2) before preview or apply and nothing is written. `tests/test_csv_currency_injection.py` covers injected-directive, space, comma and newline cells under preview and `--apply`. Shipped in the commit that moved this note (`cli`).

# A malformed-CSV error names the last line of the file, not where the unclosed quote starts

**Severity: minor. Owner: cli. Estimate: 15–30m. A1:** in a large export, the last line is the wrong place to look. Continuous CLI QA, 2026-10-03 (round 13); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command with timeouts, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with before/after hashes and a working control. Found by a regression hunt over shipped fixes.

`m2.csv`: header on line 1; line 2 `2024-02-01,Coffee,-1.00`; line 3 `2024-02-02,"Tea,-2.00` (quote opens); lines 4–6 ordinary rows.

```sh
bea --file /abs/l.bean import /abs/m2.csv --csv date=Date,amount=Amount,narration=Description --account Assets:Bank --default-account Expenses:Misc
```

Actual: exit 2 `Line 6: m2.csv is not well-formed CSV (unexpected end of data). An unclosed quote swallows every row after it; close the quote and retry.` Control: a valid multiline cell followed by a bad amount reports the start line (`Row 2 (line 5)`).

Cause: `cli/src/bea_engine/csv_mapper.py:651` (and `:633`) pass `reader.line_num` (last line consumed) to `_malformed` (`:451`) instead of the `start` that `rows()` already tracks. Gap in `de9d6cff` (`w3/406`).

Fix/acceptance: pass `start` (review `:633`); the repro reports `Line 3` regardless of trailing lines; existing malformed-CSV tests pass.

---

**Resolved 2026-10-04** — a malformed-CSV error now names the line where the unclosed quote opens, not the last line of the file. `tests/test_csv_multiline_physical_lines.py` covers it. Shipped in the commit that moved this note (`cli`).

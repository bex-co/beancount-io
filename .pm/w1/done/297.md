# `bea report budget` says "Budget directive ignored: Invalid interval for budget entry" without naming the file, line, account or value, so several bad lines read as one repeated message

Found by `/qa-find-bugs-cli w1` on 2026-11-19 (HEAD `f171f1afd`, `bea 0.4.1`, macOS 26.5.1, Python 3.12.14, checkout `uv run bea`, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, synthetic ledgers). Severity: minor. A1: an agent that gets this warning has to grep every `custom "budget"` line and guess which one Fava refused. A trailing space (`"Monthly "`) or a typo (`"montly"`) is invisible in the message, and the account it names falls silently to `unbudgeted`.

**Repro** (synthetic; `bea check` exits 0).

`main.bean`:

```beancount
option "operating_currency" "USD"
include "budgets.bean"
2026-01-01 open Assets:Cash USD
2026-01-01 open Expenses:Food USD
2026-01-01 open Expenses:Rent USD
2026-01-01 open Expenses:Travel USD
2026-01-05 * "Food"
  Expenses:Food  30.00 USD
  Assets:Cash
2026-01-06 * "Rent"
  Expenses:Rent  900.00 USD
  Assets:Cash
2026-01-07 * "Trip"
  Expenses:Travel  80.00 USD
  Assets:Cash
```

`budgets.bean`:

```beancount
2026-01-01 custom "budget" Expenses:Food "monthly" 100.00 USD
2026-01-01 custom "budget" Expenses:Rent "montly" 1000.00 USD
2026-01-01 custom "budget" Expenses:Travel "Monthly " 50.00 USD
2026-01-01 custom "budget" Expenses:Travel "monthly" 50
```

```sh
bea -f main.bean report budget -t 2026-01
bea -f main.bean --json report budget -t 2026-01
```

**Actual** (exit 0). Stderr:

```text
Budget directive ignored: Invalid interval for budget entry
Budget directive ignored: Invalid interval for budget entry
Budget directive ignored: Invalid amount for budget entry: expected NUMBER CURRENCY
```

JSON `budget_errors` is the same three bare strings. The table lists `Expenses:Rent (unbudgeted)` and `Expenses:Travel (unbudgeted)`. Nothing ties either account to a refused line, or says which of the two Travel lines failed for which reason. `--format csv` prints the same stderr lines (w5/1124).

**Expected.** Each diagnostic names its directive the way ledger errors do: the `file:line:` prefix, the account, and the refused value with what is accepted. For example: `budgets.bean:2: Budget for Expenses:Rent ignored: unknown interval "montly" (use daily, weekly, monthly, quarterly or yearly)`, and `budgets.bean:4: Budget for Expenses:Travel ignored: amount 50 is not NUMBER CURRENCY`. `--json` carries the same text in `budget_errors`. That keeps today's list-of-strings type, so existing consumers still parse it.

**Root cause.** `parse_budgets` (`cli/src/fava/modules/budgets.py:127`, `:139`, `:156`) builds each `BudgetError` with `entry.meta` (filename, lineno) and the `entry` itself. `_budget` (`cli/src/bea_engine/report.py:465`) then keeps only `error.message`, and `report.py:914` prints that alone. The location and account are available and dropped.

**Fix** (cli only). In `bea_engine/report.py`, render each budget error from its `source` and `entry`: the file relative to the root ledger as other diagnostics print it, the line, the account (`entry.values[0]`) and the offending value. Leave the vendored parser's messages alone, or annotate any change there as a Beancount.io change. Update the Budgets bullet in `cli/docs/USAGE.md:2134` to say diagnostics name their line.

**Regression.** The repro's three diagnostics each name `budgets.bean`, their line (2, 3, 4), their account and the refused value, in human stderr and in `--json` `budget_errors`. Each assertion fails with the fix reverted. The valid Food budget's row is unchanged.

**Blast radius.** `bea report budget` text, `--json` and `--format csv`; `budget_errors` is the only consumer of `module.errors` (`grep -n budget_errors -r cli/src`). No hosted surface emits budget diagnostics. Also seen, not filed: a budget for an account the ledger never opened (`Expenses:Fod`) is reported as a 300.00 budget with 0.00 actual and no warning. That is upstream Fava behavior.

**Dedupe.** Searched `.pm/**` for `Invalid interval`, `budget_errors` and `Budget directive ignored`. [w5/1122](../../w5/done/1122.md) made a malformed amount a diagnostic instead of a crash, and used the invalid-interval message as its working control. [w5/1124](../../w5/done/1124.md) kept these diagnostics on stderr for CSV. Neither looked at what the message identifies. Estimate: 20–30 minutes.

---

**Resolved 2026-11-19** — each refused `custom "budget"` line now prints as a ledger error does, `file:line:`, followed by the account and the value it refused, with strings quoted so a typo or a trailing space shows: `budgets.bean:2: Budget for Expenses:Rent ignored: unknown interval "montly" (use daily, weekly, monthly, quarterly or yearly)`, `budgets.bean:3: … unknown interval "Monthly " …`, `budgets.bean:4: Budget for Expenses:Travel ignored: amount 50 is not NUMBER CURRENCY`. The same text reaches stderr (table and `--format csv`) and `--json` `budget_errors`, which stays a list of strings; the valid Food row is unchanged and the vendored parser is untouched. One deviation from the proposed fix: the file prints exactly as the same report's `ledger_errors` and `bea check` print it (the loader's path), not relative to the root ledger, so both lists in one payload read alike. Covered by `cli/tests/test_report_budget.py::test_each_ignored_budget_names_its_file_line_account_and_refused_value` and the updated budget-diagnostic tests; `cli/docs/USAGE.md` Budgets says so. Shipped in `38c7cfbe3` (`cli`).

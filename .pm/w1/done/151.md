# Quoted semicolons in a comma CSV make delimiter detection choose `;` and refuse the file

**Severity: minor. Owner: cli. Estimate: 20–30m. A1:** common SEPA exports quote semicolon-laden references. Continuous CLI QA, 2026-10-03 (round 11); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command with timeouts, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, stdin closed. Reproduced twice from fresh fixtures with a working control.

Base ledger: `option "operating_currency" "USD"`, `2026-01-01 open Assets:Checking USD`, `2026-01-01 open Expenses:Uncategorized USD`.

`s3.csv`: header `Date,Description,Amount` plus 4 rows like `2026-08-02,"SEPA;DE89…;REF2;Rent",-5.00`.

Actual: without `--csv`, exit 2 "Choose a Python importer…" (its suggested `--csv` line also fails); with explicit `--csv`, exit 2 "Using column mapping (--csv, delimiter ';')" then "The mapping names column 'Date' … which s3.csv lacks." Controls: replacing the semicolons with spaces imports; `--delimiter ,` works.

Expected: IMPORTING.md — separators are "detected from the header"; this header splits into 3 fields on commas and 1 on semicolons.

Cause: `detect_delimiter` scores body rows only and never requires the header count to agree — `cli/src/cli/csv_mapper.py:389–397` and `cli/src/bea_engine/csv_mapper.py:554–562` (from `5bee77d3`, `w1/done/m24/t001`).

Fix/acceptance: accept a delimiter only when the header splits into > 1 field matching the body count (prefer the header on disagreement). The repro auto-detects comma; existing pipe/semicolon/tab tests pass.

**Second reproducer (round 15):** a semicolon CSV with decimal commas and an unclosed quote (`2026-02-03;-5,00;"Coffee`) makes `--csv auto` pick `,` and say "was read as one column … or omit the override" (no override given); explicit `--csv` says "names column 'Date' … which q.csv lacks"; `--delimiter ';'` gives the correct unclosed-quote error. Same root cause; the header-count rule covers it.

**Third reproducer (round 17 fuzzing):** a tab- (or semicolon-) separated file whose date cells contain commas (`Jan 05, 2026`) and whose amounts are decimal-comma ties comma with the real delimiter on body field count; comma wins (checked first, strict `>` at `csv_mapper.py:554–562`), giving a refusal with misleading "omit the override" advice. The header-count rule covers it:

```
Date\tDescription\tAmount
Jan 05, 2026\tA\t-5,74
Jan 06, 2026\tB\t-1,09
```

---

**Resolved 2026-10-04** — CSV delimiter detection now requires the header to agree with the body, so quoted semicolons or comma-bearing dates no longer outvote the real separator. Tests in `tests/test_csv_delimiter_import.py` cover both reader copies. Shipped in the commit that moved this note (`cli`).

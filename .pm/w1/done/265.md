# The `bea query` shell writes `exit` into an `-o`/`.output` export on Ctrl-D, and leaving after `.output FILE` prints a `ResourceWarning`

Found by `/qa-find-bugs-cli w1` on 2026-11-15 (HEAD `e008f36fb`, `bea 0.3.1`, beanquery 0.2.0, Python 3.12.14, macOS 26.5.1, checkout `uv run bea`, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, synthetic ledger, interactive shell driven through a real PTY). Severity: minor. A1/A3: a CSV exported from the shell ends with a row that is not data. A script or spreadsheet reading it gets a bogus `exit` record.

**Repro** (synthetic):

```sh
cat > main.bean <<'EOF'
option "operating_currency" "USD"
2026-01-01 open Assets:Bank USD
2026-01-01 open Equity:Opening
2026-01-02 * "Opening"
  Assets:Bank  100.00 USD
  Equity:Opening
EOF
bea --file main.bean query -o out.csv     # at a terminal
beanquery> .format csv
beanquery> SELECT account, sum(position) GROUP BY account ORDER BY account
beanquery> ^D                              # Ctrl-D
tail -1 out.csv
```

The same happens with `.output out.csv` typed inside the shell (no `-o`).

**Actual.**
1. `out.csv` holds the header, the two rows, and then a last line `exit`. Without an export, Ctrl-D prints `exit` on the terminal. With one, the word goes into the file instead, and the terminal is left on the `beanquery> ` prompt line with no newline.
2. Type `.output out.txt`, run a query, then leave with `exit` (or Ctrl-D). stderr shows `sys:1: ResourceWarning: unclosed file <_io.TextIOWrapper name='…/out.txt' mode='w' encoding='utf-8'>` and `ResourceWarning: Enable tracemalloc to get the object allocation traceback`. Exit status is 0.

Typing `exit` adds nothing to the file, and `.output` with no argument (back to the terminal) closes the file without a warning. Those are the working controls.

**Expected.** An export holds only query results, whichever way the session ends. Ctrl-D ends the prompt line on the terminal, as typing `exit` does, and writes nothing into the export. Leaving the shell closes any `.output` file it still holds, with nothing on stderr.

**Root cause (cli).**
1. Upstream `beanquery.shell.DispatchingShell.do_EOF` runs `print('exit', file=self.outfile)`. bea's `PreciseShell` (`build_shell` in `cli/src/bea_engine/query.py`) already overrides `do_output` to fix upstream's redirection, but it inherits `do_EOF`. So `self.outfile` is the export file whenever `-o` or `.output` is active.
2. `_interactive_session` (same file, about line 1386) closes only the `--output` stream it opened itself (`destination`). It never closes `shell.outfile` when an in-shell `.output` replaced that stream. Because `interactive()` sets `warnings.filterwarnings("always")` (about line 1362) with no category, the leaked file object's `ResourceWarning` is shown when the interpreter shuts down. `native_interactive` (the `--source` shell, about line 853) closes `shell.outfile` in its `finally`, so it does not leak, but it inherits the same `do_EOF`.

**Fix (cli only).** Override `do_EOF` on `PreciseShell` to print the newline or `exit` to the terminal stream (`stream` / `sys.stdout`), never to `self.outfile`, then return `do_exit`. In `_interactive_session`'s `finally`, close `shell.outfile` when it is not the terminal stream, as `native_interactive` does. Optionally narrow the `"always"` filter to the categories it was added for. Tests: drive `interactive()` with a fake stdin ending in EOF, with `-o` and with `.output`. Assert the file holds exactly the rendered rows (no `exit`), the `--source` shell does the same, and no `ResourceWarning` is emitted (`warnings.catch_warnings(record=True)` or `-W error::ResourceWarning`). The tests fail with the fix reverted. Estimate: 30–45 minutes.

**Blast radius.** Both interactive paths (`bea query` with no query string, and `bea query --source …` with no query string). Neither one-shot queries nor `-o` with a query string is affected: those render into a buffer and export it atomically.

**Dedupe.** Searched `.pm/**` (open, `done/`, `blocked/`) for `do_EOF`, `ResourceWarning`, `Ctrl-D`, `.output` and `query shell`, and searched `git log -S do_EOF`. The hits cover `bea ask`'s Ctrl-D (w3/449, w5/731), the pager (w5/585) and `.output` destination guards. None covers the EOF write or the unclosed file. No open item.

---

**Resolved 2026-11-15.** Both query shells in `cli/src/bea_engine/query.py` (`PreciseShell` for `bea query`, `GuardedShell` for `bea query --source`) now override `do_EOF` to print `exit` to the terminal stream instead of `outfile`, so Ctrl-D ends the prompt line on screen and writes nothing into an `-o`/`.output` export. `_interactive_session` now closes a `.output` file still held by the shell when the session ends, so leaving prints no `ResourceWarning`. New `cli/tests/test_query_shell_eof_export.py` drives both shells through a real PTY (`-o` and `.output`, Ctrl-D and `.exit`) and asserts the export holds only the rows and stderr has no `ResourceWarning`; five of its eight cases fail with the fix reverted (the other three are the note's working controls).

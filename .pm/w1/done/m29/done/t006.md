## Objective

Every policy, cache, precedence, and failure case must be provable offline against a fixture server; exactly one acceptance run confirms the real feed matches.

## Context

- ADR 015 records that the hosted `/prices` route redirects until it is mounted, so a live run may not be available yet — the fixture server must carry the suite regardless.
- `.pm/DO_NOT_DO.md` forbids provisioning a duplicate stack for verification; the live run uses the hosted feed directly.
- PRFAQ002's internal-alpha gate asks for BTC/USD and ETH/USD end to end in local `bea`, including history, source status, manual precedence, offline use, and portable export.

## Steps

1. Build a local fixture feed server serving valid feeds, an invalid body, a redirect, a 404, a slow response, an oversized body, and an ETag that does and does not change.
2. Drive every policy, cache, precedence, offline, strict, and failure case against it, with no network access required.
3. Run one acceptance pass against the hosted feed for BTC-USD, recording the revision and observed-at that were seen.
4. If the hosted route is not yet mounted, record that the live run is pending and say so plainly rather than claiming coverage.

## Files

- cli/tests/test_price.py
- cli/tests/fixtures/

## Acceptance criteria

- [ ] The full suite passes offline against the fixture server, including every failure mode listed above.
- [ ] A recorded acceptance run against the hosted feed names the revision and observed-at observed, or states plainly that the live run is pending because the route is not mounted.
- [ ] No duplicate deployment is provisioned for verification.
- [ ] `cd cli && make check-all` passes.

## Out of scope

- Load or performance benchmarking of the hosted feed.
- Provider selection and procurement, which PRFAQ002 leaves open.

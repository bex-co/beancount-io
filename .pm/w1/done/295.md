# `bea add transaction` with no narration or payee writes its header with a trailing space, so `git diff --check` flags every such entry

Found by `/qa-find-bugs-cli w1` on 2026-11-19 (HEAD `5e9840150`, `bea 0.4.1`, macOS 26.5.1, Python 3.12, checkout `uv run bea`, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`). Severity: minor. A1: "Narration is optional" (`cli/docs/USAGE.md`, Adding directives), and the minimal row in `bea add transactions --help` has no narration, so an agent that adds the smallest valid entry gets this line every time. [m14](./m14/README.md) set the goal that an entry `bea` writes looks like one a person would write. A trailing space is a whitespace error to `git diff --check`, and the common pre-commit `trailing-whitespace` hook rewrites the ledger and fails the first commit after each such write.

**Repro** (synthetic).

```sh
printf 'option "operating_currency" "USD"\n2026-01-01 open Assets:Cash USD\n2026-01-01 open Expenses:Misc USD\n' > main.bean
git init -q && git add main.bean && git -c user.name=qa -c user.email=qa@example.com commit -qm base
bea --file main.bean add transaction --date 2026-01-05 -p 'Expenses:Misc 1.00 USD' -p Assets:Cash   # exit 0
cat -e main.bean | tail -3
git diff --check; echo $?
```

**Actual.** The header is written as `2026-01-05 * ` (`2026-01-05 * $` under `cat -e`), and `git diff --check` exits 2 with `main.bean:5: trailing whitespace. +2026-01-05 * `. The same line comes from:

- `bea add transactions` with the help's minimal row `[{"date":"2026-01-07","postings":[{"account":"Expenses:Misc","amount":"1 USD"},{"account":"Assets:Cash"}]}]`, and with a listed row whose payee and narration are both `""`;
- `bea import` of a CSV row whose payee and narration cells are both empty (`2026-01-05 ! `);
- `bea query -f beancount PRINT` (and `-o FILE`) for such an entry, and `bea list transaction --details`.

`bea update transaction` keeps the space when it later edits that header: `--narration Coffee --tag cafe` turns it into `2026-01-05 * "Coffee" #cafe `. `bea format --check` passes the file and `bea format -i` leaves the space, so no `bea` command removes it. `bea check` passes; the ledger means the same thing.

**Control.** With a narration, a payee (`2026-01-08 * "P" ""`), a tag (`2026-01-06 * #x`) or a link, the header has no trailing space. `bea update transaction -n ""` writes `""` and no trailing space. `bea init` output and every other `add` directive (open, close, balance, price, commodity, custom, note, event) have none either.

**Expected.** A header with no payee, narration, tag or link is written as `2026-01-05 *`, with nothing after the flag. Every other header is byte-identical to today.

**Root cause.** Upstream `beancount.parser.printer.EntryPrinter.Transaction` writes `"{e.date} {flag} {}\n".format(" ".join(strings), …)` (beancount 3 `printer.py:220-224`); with no strings that leaves `"<date> <flag> "`. `DirectivePrinter.__call__` (`cli/src/bea_engine/ledger/writer.py:89`) passes Transactions straight to it, and `format_entry` (`writer.py:497`) normalizes only Open, Balance and Price first lines.

**Fix** (cli only). In `DirectivePrinter.__call__`, strip trailing spaces from a Transaction's first line, so `format_entry` (add, bulk add, import, write hints), `format_transaction(loaded=True)` (`list --details`) and `_render_beancount` (`query -f beancount`) all get it. Regressions: `add transaction` and `add transactions` with no narration write `YYYY-MM-DD *` with no trailing space; a CSV import row with empty payee and narration does too; `query -f beancount PRINT` of such an entry has no trailing space; a header with only a tag or only a link is unchanged.

**Blast radius.** Searched callers of `DirectivePrinter` and `format_entry`: `ledger/adding.py`, `ledger/write.py:3840`, `importing.py` (739, 846, 1377, 1396, 1977), `ledger/listing.py:137`, `query.py:1874, 2067`. All of them print through the one `__call__`. Not checked: whether hosted writes (backend-v2 / ledger service) render an empty header the same way; they do not use this printer.

**Dedupe.** Searched `.pm/**` for `trailing space`, `trailing whitespace`, `git diff --check`, `no narration`, `empty narration`. [w5/1042](../../w5/done/1042.md) placed a new narration before the tags of a bare header in `update`; it did not look at the trailing space. [w3/225](../../w3/done/225.md) and [w3/255](../../w3/done/255.md) are about empty inputs, not the rendered header. No open or done item covers it. Estimate: 20–30 minutes.

---

**Resolved 2026-11-19** — Reproduced at `db1a1399b`: `bea add transaction --date 2026-01-05` with no narration wrote `2026-01-05 * ` and `git diff --check` exited 2. `DirectivePrinter.__call__` (`cli/src/bea_engine/ledger/writer.py`) now strips trailing spaces from a transaction's first line, so every path that prints through it — `add transaction`, `add transactions`, `import`, `query -f beancount PRINT` and `list transaction --details` — writes `2026-01-05 *`. After the fix the repro's `git diff --check` exits 0, the help's minimal bulk row and a row with `""` payee and narration write `2026-01-07 *`, a CSV row with empty payee and narration cells writes `2026-01-11 !`, and headers with only a tag (`* #x`), only a link (`* ^L1`) or a payee (`* "P" ""`) are unchanged. `bea update transaction --narration Coffee --tag cafe` on a freshly written bare header now gives `2026-01-05 * "Coffee" #cafe` with no trailing space; update stays byte-preserving, so a header an older `bea` wrote keeps its space until edited by hand. Regressions in `cli/tests/test_bare_transaction_header.py` (5 fail with the fix reverted, the 5 controls pass either way): `format_entry` header shapes; `add transaction`, `add transactions` and a CSV import with no strings; `query -f beancount PRINT` and `list transaction --details` of a bare header. `make check-all` green.

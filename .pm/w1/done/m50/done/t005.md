## Test coverage — 2026-11-23

`cli/tests/test_update_batch_cost.py` (13 tests) counts loads and compares bytes instead of timing anything:

- **Loads.** One mistyped row among 64 costs 3 validations, and 4 with `--apply`, which writes the other 63. A row that breaks an assertion elsewhere is found within 2·log2 N + 3. Rows that fail only together are still named together beside a row that fails alone. Rows that load together are written together beside a rejected row. One `shared_locations` call and one `entry_generated` call per entry per batch. One whole-file diff per batch.
- **Diffs.** Each row's diff in a batch equals the one-row command's whole-file diff: the first line of the file, a line every entry repeats between two edits, a flag-only edit followed by repeated lines, a dropped continuation line, the last entry, with and without a byte-order mark and a final newline. On 400 generated row edits, the window equals `unified_file_diff`. On 300 generated edits of files whose entries repeat, the diff applies and yields the edited text.

Reverting each part fails its tests. Trying every row alone fails the three load counts. Rebuilding the index per row fails the indexing test. A whole-file diff per row fails the whole-file-diff count. Dropping the whole-file popularity rule fails the row-diff tests, and so does a plain three-line window without anchors.

## Simplify — 2026-11-23

`/simplify` ran four reviewers (reuse, simplification, efficiency, altitude) over the m50 diff. Applied:

- **Altitude.** The first `_judge_file` accepted rows it had never tried alone, including the rows the halving kept, and still called them "valid alone" when the rest failed together. Rows that load together are now written together by rule, documented and tested (see t003), and the fail-together fallback tries every row alone, so "valid alone" stays true.
- **Simplification.** `plan_lines` takes the span `_plan_rows` already computed instead of reading it again. `FileDiffer` counts lines when it is built, and its no-anchor case runs to the file's edge instead of keeping a second whole-file path. `_named_plans` maps lines to rows with one dict. `locate_transaction`'s docstring moved onto `EntryIndex.locate`. `_same_path` compares two `_file_key`s. The test helpers use `mock.Mock(wraps=…)` and the production differ.
- **Efficiency.** Memoized refusals are kept without their tracebacks, which held each failing trial's loaded ledger (about 50 MB on a 100,000-line file) until the file was judged. A `FileDiffer` takes one row's whole edit map, and a row's diff no longer scans the file for its first and last kept lines.

Skipped:
- Windowing the batch's combined diff too. With many entries edited, `difflib` over the whole file can pair a line with its copy in another entry, which windows do not reproduce, so the combined diff stays one whole-file `difflib` per file. With 2,000 rows scattered over a 22,000-transaction file that diff takes most of a 58 s preview; the 2,000 rows `bea import` just wrote sit together and the whole preview takes 5 s (the README's Closeout has the figures).
- Caching the ledger's account spellings on `LedgerSnapshot` for `respelled_account_notes`. Only a retarget to a non-ASCII account reads them, and `_notes` reads them once per distinct account in a batch.
- Pre-existing costs outside this diff: `--apply` re-validates each file the preview already judged, and `validate_candidate` reloads the unchanged ledger to classify errors on every failing trial.

# `bea init --existing` says "AGENTS.md asks agents to add none" when it left the user's own AGENTS.md untouched, and never says a kept CLAUDE.md does not import the new AGENTS.md

Found by `/qa-find-bugs-cli w1` on 2026-11-15 (HEAD `668a8fd66`, `bea 0.3.1`, macOS 26.5.1, checkout `uv run bea`, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, synthetic ledger). Severity: minor. A1: a user bringing an existing ledger to a coding agent (the m42 journey) is told something about their agent files that is not true, and is not told the one step that makes Claude Code read the file bea just wrote.

**Repro** (synthetic, fresh folder):

```sh
cat > main.bean <<'EOF'
2026-01-01 open Assets:Cash USD

2026-01-02 * "Lunch"
  Assets:Cash   -5.00 USD
  Expenses:Food
EOF
printf '# Team notes\n' > AGENTS.md
printf '# Claude notes\n' > CLAUDE.md
bea init --existing .              # case A: both files kept
rm AGENTS.md
bea init --existing .              # case B: AGENTS.md written, CLAUDE.md kept
bea doctor guidance main.bean      # control
```

**Actual.** Case A exits 0. stderr: `AGENTS.md already exists; left unchanged, and CLAUDE.md was not written.` then `The ledger loads with 1 error today; AGENTS.md asks agents to add none.` Both files are byte-identical afterwards (`# Team notes` asks nothing of the kind). Case B exits 0 with `CLAUDE.md already exists; left unchanged.`, the same baseline line, and `Wrote AGENTS.md beside the ledger.` It does not say that the kept `CLAUDE.md` does not import `AGENTS.md`, so Claude Code never reads the instructions bea just wrote. The control `bea doctor guidance main.bean` warns about exactly that: `CLAUDE.md does not import AGENTS.md, so Claude Code reads different instructions than other agents. Add a line containing exactly @AGENTS.md.` `bea init DIR --currency USD --agent-files` beside a foreign `CLAUDE.md` has the same gap in case B.

**Expected.** The baseline sentence claims what `AGENTS.md` says only when this run wrote it. When `AGENTS.md` was kept, the note reports the count alone (for example `The ledger loads with 1 error today.`) or says the existing `AGENTS.md` does not record that baseline. When a kept `CLAUDE.md` does not import `AGENTS.md` (the same test `bea doctor guidance` applies, which accepts a link or an `@AGENTS.md` import, w1/245), the note says so and gives the doctor's next step (`add a line containing exactly @AGENTS.md`). Files are still never modified. JSON output is unchanged apart from anything the fix adds to `agent_files`.

**Root cause.** `cli/src/cli/commands/init.py` `_init_existing()` (about lines 385–391) prints the baseline note whenever `baseline_errors(description)` is non-zero, without looking at `data["agent_files"]["AGENTS.md"]`. `_report_agent_files()` (about lines 397–405) reports `kept` files with fixed text and never checks whether a kept `CLAUDE.md` imports `AGENTS.md`. The import check already exists behind `bea doctor guidance`.

**Fix (cli only, text rendering).** Gate the "AGENTS.md asks agents to add none" clause on `AGENTS.md == "created"`. In `_report_agent_files`, reuse the doctor guidance's import test for a kept `CLAUDE.md` and add its next step. Both `init --existing` and `init --agent-files` go through this path.

**Done when** case A prints no claim about what `AGENTS.md` asks, case B names the missing `@AGENTS.md` import with its next step, a run that writes both files prints today's text unchanged, every agent file stays byte-identical, and regression tests in the `init --existing` and `--agent-files` suites cover all three. The tests fail with the fix reverted. Estimate: about 30 minutes.

**Dedupe.** Searched `.pm/**` for `asks agents to add none`, `AGENTS.md already exists` and `does not import AGENTS.md`. Nothing matched except w1/245, which fixed the doctor's import test and not `init`. `git log -S"asks agents to add none"` shows only `fd8914559` and `fe2ff1284` (m42/t002–t003). Not a regression of completed work.

---

**Resolved 2026-11-15.** `_init_existing()` in `cli/src/cli/commands/init.py` now adds "AGENTS.md asks agents to add none" to the baseline note only when this run wrote `AGENTS.md`; beside a kept one it prints the count alone (`The ledger loads with 1 error today.`). `_report_agent_files()`, shared by `init --existing` and `init --agent-files`, runs the `bea doctor guidance` import test on any `CLAUDE.md` bea did not write and, when it does not link to or import `AGENTS.md`, prints the doctor's warning and next step (`Add a line containing exactly @AGENTS.md.`). The test moved from `cli/src/cli/commands/doctor.py` to `claude_reads_agents()` in `cli/src/cli/agent_guidance.py`, so both commands share one implementation. Agent files stay byte-identical and the JSON output is unchanged. New cases in `cli/tests/test_init_existing.py` and `cli/tests/test_init_agent_files.py` (kept AGENTS.md, kept non-importing CLAUDE.md, kept importing CLAUDE.md, both written) fail with the fix reverted where the old text disagreed.

# Appends rewrite text inside strings: U+2028/U+2029 become newlines and continuation lines are re-indented

**Severity: major. Owner: cli. Estimate: 45–60m. A1:** written strings must be exactly what was typed or consented to. Continuous CLI QA, 2026-10-03 (round 9); report and filing only, no fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command with timeouts, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced twice with a working control.

Header `B`: `option "operating_currency" "USD"`, `2020-01-01 open Assets:Cash USD`, `2020-01-01 open Expenses:Food USD`.

```sh
bea --file /abs/u.bean add note --date 2020-02-01 -a Assets:Cash -m $'a\u2029      Assets:Cash     9 USD'
bea --file /abs/u.bean add transaction --date 2020-02-02 --narration $'first\u2028second' -p 'Expenses:Food 1 USD' -p Assets:Cash
```

Actual (exit 0, `check` green): the note is written as `"a\n  Assets:Cash  9 USD"` and `list note` returns that changed text; the narration becomes `"first\nsecond"`. `bea import … --apply` with a description `COFFEE\u2028SHOP` writes `"COFFEE\nSHOP"` (the preview showed one line). Through the helper `bea ask` uses (`python -m bea_engine append --text -`, exercised directly — live ask not run), an approved note whose string continuation is `      Assets:Cash      10 USD refunded` / `   keep this indent` is written re-indented and re-aligned.

Expected: writes "stay one ledger line" (`cli/src/bea_engine/ledger/writer.py:216`); raw ask text is never written "other than what was consented to" (`text.py:47–52`).

Cause: `cli/src/bea_engine/ledger/write.py:726` (`_indent_block` uses `str.splitlines()`, splitting U+2028/2029) and `:734–735` (re-indents every indented line, including string continuations); `:759–773` (`draft.splitlines()` then `align_text` without string protection, unlike `formatting._aligned:136–152`); `single_line` (`text.py:40`) doesn't escape U+2028/2029.

Fix/acceptance: split on `\n` only in `appended_content`/`_indent_block`; lex the appended block and exclude STRING continuation lines from reindent and alignment. All four reproducers read back byte-equal (or U+2028/2029 deliberately escaped by `single_line`). Regression tests for add, import and append. Can share a change with [048](./048.md) (same character class in `bea format`); see also [049](./049.md), [094](./094.md).

---

**Resolved 2026-10-04** — appends from `add`, `import` and `ask` now write string content exactly: lines split on `\n` only, string continuation lines are not re-indented, and alignment protects string content as `bea format` does. `tests/test_append_preserves_strings.py` covers each path. Shipped in the commit that moved this note (`cli`).

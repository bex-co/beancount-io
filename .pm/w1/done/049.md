# One U+2028 in a string marks every later directive in that file `generated`, and `--on-disk` hides them

**Severity: major. Owner: cli. Estimate: 20–30m. A1:** `--on-disk` must answer exactly what grep would find, or agents miss real entries. Continuous CLI QA, 2026-10-02; report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`, synthetic fixtures. Reproduced twice from pristine fixtures.

```sh
python3 -c "open('main.bean','w').write('2024-01-01 open Assets:Cash USD\n2024-01-01 open Equity:Open USD\n\n2024-01-02 * \"Shop\" \"pasted\u2028text\"\n  Assets:Cash   10.00 USD\n  Equity:Open\n\n2024-01-03 * \"Cafe\" \"coffee\"\n  Assets:Cash   5.00 USD\n  Equity:Open\n2024-01-04 note Assets:Cash \"hello\"\n2024-01-05 price USD 1.0 EUR\n')"
bea --file /abs/main.bean list transaction
bea --file /abs/main.bean list transaction --on-disk
bea --file /abs/main.bean list note --on-disk
bea --file /abs/main.bean list price
```

Actual: `check` exits 0; `list transaction` shows the 2024-01-03 row with `SOURCE generated`; `--on-disk` returns only the 2024-01-02 row (exit 0, JSON 1 item); `list note --on-disk` prints "No notes found."; `list price` labels the on-disk price `generated`. No plugins are loaded.

Expected: USAGE ("Listing directives") — `generated` marks only plugin-synthesized rows and `--on-disk` answers "exactly what `grep` would find".

Cause: `cli/src/bea_engine/ledger/reader.py:96` (`_source_lines`) returns `tuple(text.splitlines())`, splitting on U+2028 etc.; `entry_generated` (`reader.py:118`) reads `lines[lineno - 1]` with Beancount's `\n`-based line number, lands one line early, fails `_DATE_TOKEN`, and reports the entry generated.

Fix/acceptance: build the line table with `\n`-only splitting (after BOM removal). On the fixture no row is `generated` and every directive type returns all rows under `--on-disk`; regression test for U+2028, U+0085, `\x0c` in strings and comments. Audit the same pattern at `query.py:915` (`_plugin_directive`) and `managed_load.py:698` (not exercised). Run `make check-all`.

Dedupe: related done items `w3/394` (slash dates), `w3/301`, `318`, `319`, `320` (plugin rows) — none covers line-separator drift. `git log -S'tuple(text.splitlines())'` → `ea24387e`.

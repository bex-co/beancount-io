## Objective

The MCP spec requires public-client refresh tokens to rotate; `shouldRotateRefreshToken` currently stops rotating once a chain is 365.25 days old. Make rotation unconditional for public clients so the rule does not depend on two numbers staying in order.

## Context

- backend-cluster/backend-v2/src/features/oauth/data/config.ts (`shouldRotateRefreshToken`, `defaultLifetimeCutoffSeconds`)
- Public clients: token endpoint auth method `none` (Claude, native hosts).

## Steps

1. Always rotate when the client is public; keep current behavior for confidential clients.

## Files

- backend-cluster/backend-v2/src/features/oauth/data/config.ts

## Acceptance criteria

- [x] Every refresh by a public client returns a new refresh token, regardless of chain age.

## Out of scope

- Changing confidential-client rotation.

## Result

2026-10-06. `shouldRotateRefreshToken` checks public clients (`clientAuthMethod === "none"`) before oidc-provider's 365.25-day cutoff, so their tokens rotate at any chain age. A sender-constrained (DPoP-bound) token is the one exception, kept from oidc-provider's own rule because binding is the accepted alternative to rotation. Confidential clients keep the provider's age and percentage rules. Tests: public fresh and 400-day chains rotate; sender-constrained does not; confidential behaves as before, including the age cutoff.

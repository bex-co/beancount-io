# `bea report holdings` treats any currency something is quoted in as cash, so one `price ETH 0.05 BTC` line makes a whole BTC position vanish

Found by `/qa-find-bugs-cli w1` (routine `cli-qa`) on 2026-11-15 (HEAD `b77619709`, `bea 0.3.1`, macOS 26.5, checkout `uv run bea`, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, offline synthetic ledger). Severity: minor. A1: an agent asking "what do I hold" in a crypto ledger, where BTC is both a holding and a quote currency, gets a portfolio missing most of its value. The answer exits 0 with `valuation: "complete"`. This is a gap in the w1/253 fix (`289009046`), not a regression: before it, every uncosted position was dropped.

**Contract.** `cli/docs/USAGE.md:1953` says `holdings` "lists every non-cash position". Since w1/253, `USAGE.md:1958-1960` defines cash as an uncosted balance in "an operating currency, or any currency a cost, a posting price, or a `price` directive is quoted in". The trial balance (`bea balance -x USD`) and `report balance-sheet` count and value the same position.

**Repro** (synthetic):

```sh
cat > main.bean <<'EOF'
option "operating_currency" "USD"
2024-01-01 open Assets:Bank USD
2024-01-01 open Assets:Crypto
2024-01-01 open Equity:Opening
2024-01-02 * "fund"
  Assets:Bank 100000 USD
  Equity:Opening
2024-02-01 * "buy btc"
  Assets:Crypto 1 BTC @ 40000 USD
  Assets:Bank -40000 USD
2024-03-01 price BTC 50000 USD
EOF
bea --file main.bean check                     # clean, exit 0
bea --file main.bean report holdings           # Assets:Crypto 1 BTC, 50,000 USD  (correct)
echo '2024-03-01 price ETH 0.05 BTC' >> main.bean
bea --file main.bean report holdings           # "No holdings.", exit 0
bea --file main.bean balance -x USD Crypto     # Assets:Crypto 50,000 USD
```

The same happens with a posting price instead of a directive. Swapping 0.1 BTC for `2 ETH @ 0.05 BTC` leaves holdings showing only `2 ETH` (5,000 USD), while `balance -x USD` values the account at 50,000 USD. `--json` gives `totals.market_value {"USD": "5000"}`, `valuation: "complete"`, `missing_prices: []`. A costed lot in BTC (`10 ALT {0.001 BTC}`) hides an uncosted BTC balance the same way.

**Expected.** The 1 BTC (or 0.9 BTC) is a holding with a `null` basis, valued at the period-end quote: 50,000 USD (or 45,000 USD). Holdings' market value plus cash then matches the trial balance for the account. Being quoted in does not make a commodity money: a ledger quoting `ETH` in `BTC`, or `ALT` at a BTC cost, still holds BTC as an investment.

**Root cause.** `cli/src/bea_engine/report.py:761` (`_money_currencies`) adds every `price` directive's quote currency, every cost currency and every posting-price currency to the cash set. `_holdings` (`:640`) then skips any uncosted balance in that set. The hosted composer copies the rule: `backend-cluster/backend-v2/src/features/ledger/utils/holdings.ts:250` (`moneyCurrencies`), used at `:356`.

**Fix** (`cli` plus `backend-v2` for parity, about 45m). Cash is an uncosted balance in an operating currency. Use the quote/cost-currency fallback only when the ledger declares no `operating_currency` (the case w1/253 added it for). A non-operating foreign currency balance (`500 EUR` in a USD ledger) then lists as a holding with an unknown basis, valued at its quote. That is honest, and a user who wants EUR treated as cash declares it with `option "operating_currency" "EUR"`. State the rule in `USAGE.md:1958-1960`. Apply the same rule in the hosted `moneyCurrencies` so REST, MCP (`ledgerHoldings`) and GraphQL answer what the CLI answers (root `AGENTS.md` parity rule).

**Done when:**

- With the repro plus `price ETH 0.05 BTC`, `bea --json report holdings` lists `Assets:Crypto` 1 BTC with `market_value` 50000 USD and a `null` `cost_basis`, and `cost_basis_complete: false`.
- In the posting-price variant, holdings lists 0.9 BTC (45,000 USD) and 2 ETH (5,000 USD), totalling the trial balance's 50,000 USD.
- Cash controls: an uncosted USD balance stays out, and so does an uncosted EUR balance with EUR declared as an operating currency. A ledger with no `operating_currency` keeps w1/253's fallback.
- `cli/tests/test_report_holdings_uncosted.py` and `backend-v2/.../utils/__tests__/holdings.test.ts` cover the BTC-as-quote case. The new cases fail with the fix reverted.

**Dedupe.** Searched `.pm/**` (done and blocked included) for holdings together with money currency, quote currency, BTC and crypto, and ran `git log -S "_money_currencies"`. The only hit is w1/253 (done), which introduced the rule. No open item covers it.

---

**Resolved 2026-11-15** — Being quoted in no longer makes a commodity cash. With an operating currency declared, holdings count as cash only an uncosted balance in an operating currency or in a currency lots are costed in (EUR beside `{140 EUR}` lots settles holdings and stays out, as the existing FX, direct-quote and provenance suites expect). Price-directive and posting-price quote currencies are cash only in a ledger with no `operating_currency` (w1/253's fallback, kept). The repro plus `price ETH 0.05 BTC` now lists `Assets:Crypto` 1 BTC at 50,000 USD with a `null` basis and `cost_basis_complete: false`; the posting-price variant (with an ETH quote) lists 0.9 BTC at 45,000 USD and 2 ETH at 5,000 USD, totalling 50,000 USD. Deviation from the proposed fix: cost currencies stay money, because dropping them would list every USD ledger's EUR settlement cash (and its negative counterparts) as holdings; so a BTC balance beside an ALT lot costed in BTC is still treated as cash. `cli/src/bea_engine/report.py` (`_money_currencies`), `cli/docs/USAGE.md`; the hosted `moneyCurrencies` in `backend-cluster/backend-v2/src/features/ledger/utils/holdings.ts` applies the same rule, so REST, MCP (`ledgerHoldings`) and GraphQL agree; the REST description, OpenAPI snapshot and CLI pinned spec are refreshed. Regression tests in `cli/tests/test_report_holdings_uncosted.py` and `backend-v2/.../utils/__tests__/holdings.test.ts` fail with the fix reverted. (`cli`, `backend-v2`)

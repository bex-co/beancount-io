# A stored `.run` query with `DISTINCT tags`/`GROUP BY tags` still leaks the raw compile error

**Severity: minor. Owner: cli. Estimate: 30–45m. A1:** stored queries must get the same guidance as direct ones. Continuous CLI QA, 2026-10-03 (round 13); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, checkout `cli/.venv/bin/bea` 0.3.1, Python 3.13, macOS 26.5.1 arm64. Fresh process per command with timeouts, isolated `HOME`/`BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with before/after hashes and a working control. Found by a regression hunt over shipped fixes.

Add `2024-01-01 query "dt" "SELECT DISTINCT tags"` and `2024-01-01 query "gt" "SELECT tags, count(*) AS n GROUP BY tags"`, then:

```sh
bea --file /abs/q.bean query ".run dt"     # exit 2: Beanquery could not compile this BQL query: cannot use starred expression here (<string>, line 4).
bea --file /abs/q.bean query ".run gt"     # exit 2: GROUP-BY a non-hashable type is not supported: "Column(name='tags')"
```

`--json` returns the same text. Controls: the direct `SELECT DISTINCT tags` gives "BQL cannot use DISTINCT or GROUP BY on tags: a set is not a value it can compare." plus advice (`w3/done/353`); `.run` of a `FROM accounts` query works.

Cause: `cli/src/bea_engine/query.py:695` and `:825` run `_set_columns` on the outer `.run dt` text, not the stored SQL that the `execute` override (`:466`) actually runs. `39c6894f` (`w3/398`) moved stored-query preparation into `execute` but not this explanation.

Fix/acceptance: do the set-column check inside the `execute` override where the real BQL is known; `.run dt`/`.run gt` produce byte-identical messages and details to the direct forms in text and `--json`.

---

**Resolved 2026-10-04** — stored queries run with `.run` now get the same explanation and advice as their direct forms, byte for byte in text and `--json`, including `DISTINCT tags`/`GROUP BY tags`. `tests/test_query_stored_explanations.py` covers it. Shipped in the commit that moved this note (`cli`).

# Typed entries take metadata only on transactions; directive metadata from the journal can't be written back

**Gap · backend-v2 + ledger · minor · ~1h (or ~5m description-only) · A1.** From `/qa-find-bugs-mcp`, 2026-11-10, production `beancount-mcp 1.0.0`. The behaviour is the same on REST, GraphQL and MCP.

- **Repro:**
  - The journal resource returns `meta` on non-transaction directives. On the public example ledger:
    - commodities carry `{export, name, price:"USD:google/…"}`
    - opens carry `{institution, address, phone, number, account}`
    - prices carry `{observed-at, provisional}`
  - `addLedgerEntries` with `meta` on an open, commodity or price is refused `BAD_USER_INPUT` `entries.0.entry: Unrecognized key: "meta"`. GraphQL `LedgerOpenInput`, `LedgerCommodityInput` and `LedgerPriceInput` have no `meta` field either.
  - **Control:** `appendLedgerText` with `2026-09-01 commodity QAXX\n  name: "QA Fund"\n  price: "USD:yahoo/QAXX"` previews valid.
  - Everything else round-trips. 261 journal-JSON entries fed back through one `addLedgerEntries` dry run preview valid and parse back identical to the source. Only the 10 commodity and 6 open metadata sets were lost.
- **Why it matters:** an agent setting up accounts and commodities through the typed tool can't record the keys tools read, e.g. the commodity `price:` key that bean-price uses and the open `account:` key that importers use.
- **Cause:** in `src/features/ledger/api/rest/v1/entries-handler.ts:122-210`, every non-transaction variant is a strict object without `meta`. The MCP and GraphQL inputs mirror it, and the ledger renderer receives only transaction and posting meta.
- **Fix:** add string-valued `meta` to open, close, commodity, price, balance, note, event, document and pad. Render it with the existing token check and escaping; the reserved-key rule from w1/217 applies.
- **Interim:** state "metadata: transactions and postings only; use `appendLedgerText` for directive metadata" in the `addLedgerEntries` description and `docs/mcp.md:1940-1990`.
- **Same pass (nit):** an `updateEntrySource` with byte-identical text makes no commit and keeps the hash, but it still reports "Updated entry …" with `wrote:[main.bean]`.

**Resolved 2026-11-10 — already satisfied by `b3bfc810b` (`w23/m43`, done), no work in w1.** Checked on `main`:
- `entries-handler.ts` gives every non-transaction variant string-valued `meta`, and the ledger's `rowTokens` checks the keys on every directive, so the reserved-key rule from w1/217 applies to all of them.
- `yarn verify:rustledger` passes "every typed directive's metadata survives the journal round trip (Open, Close, Commodity, Price, Balance, Note, Event, Document, Pad)".

# A damaged managed engine reports `Provisioned: yes` and every command prints a raw traceback

**Severity: minor. Owner: cli. Estimate: ~45m. A1:** users need a working repair path, not a traceback. Continuous CLI QA, 2026-10-03 (round 7); report and filing only, no product fix applied.

Environment: `main` HEAD `97dab6b0`, bea 0.3.1, macOS 26.5.1 arm64. Fresh process per command with timeouts, isolated `HOME`/`XDG_*`/`BEA_CONFIG_DIR`, notifier disabled, no inherited `BEA_FILE`/`BEA_TOKEN`/`CI`, synthetic fixtures, stdin closed. Reproduced at least twice with a working control.

Artifact under test: wheel built from `cli/` with `uv build`, installed into a fresh venv (Python 3.12.14, uv 0.12.13) with HOME, XDG dirs, `BEA_CONFIG_DIR` and `UV_CACHE_DIR` inside the run dir; after the first engine install everything ran with `UV_OFFLINE=1`. Package-manager steps were **simulated** with fake `brew`/`uv` executables on PATH.

In a working managed engine, delete `lib/python3.12/site-packages/beancount`.

Actual: `bea check` exits 1 printing only a bare `Traceback … ModuleNotFoundError: No module named 'beancount'`; `list transaction` and `--json check` report "The Beancount engine did not answer …" with the traceback in `details`; `bea engine status` says `Provisioned: yes`. Retrying never helps.

Expected: a diagnosis with a fix — the missing-executable path already says "Remove … and rerun" (`cli/src/cli/engine/launch.py:252`).

Cause: `cli/src/cli/engine/paths.py:101` `is_provisioned` checks only that `python` and the `beanquery` directory exist.

Fix/acceptance: verify imports (or a marker written after a verified install) in `is_provisioned`/status; on failure, repair via a safe swap (see [119](./119.md)) or print "Remove <root> and rerun". `engine status` reports the damage and the next command repairs or explains.

Dedupe: `w2/022` covered tier reporting only.

---

**Resolved 2026-10-03** — an engine missing `beancount` or `beanquery` is now reported by `bea engine status` as incomplete and rebuilt by the next local command instead of reporting `Provisioned: yes` and failing with a traceback. Tests in `tests/test_engine_launch.py` cover it. Shipped in the commit that moved this note (`cli`).

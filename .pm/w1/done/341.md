# `bea list document` says a statement found in the `option "documents"` folder was "WRITTEN IN main.bean:0", a line that does not exist

**Severity: minor. Owner: cli. Estimate: 20–30m. A1:** an agent reads `WRITTEN IN` (JSON `source`) to learn which file a document's path is relative to and where the directive sits, so it can edit or move it. For a statement Beancount discovered in the documents folder, the answer names line 0 of the root file. Nothing is written there, and `main.bean:0` is the untraceable location the board has already removed from errors (w1/269, w1/273, w5/765).

Found by `/qa-find-bugs-cli w1` (routine cli-qa) on 2026-11-20: HEAD `f35731ce2`, `bea 0.5.0` from the checkout (`uv run bea`), macOS 26.5.1, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, no `BEA_FILE`/`BEA_TOKEN`, synthetic ledger. Reproduced twice, each time in a fresh directory.

## Repro

```sh
mkdir -p books/Documents/Assets/Bank && cd books
cat > main.bean <<'EOF'
option "operating_currency" "USD"
option "documents" "Documents"
2026-01-01 open Assets:Bank USD
2026-01-05 document Assets:Bank "manual.pdf"
EOF
echo x > manual.pdf
echo x > Documents/Assets/Bank/2026-01-31.statement.pdf
bea --file main.bean check                 # exit 0
bea --file main.bean list document         # exit 0
bea --json --file main.bean list document  # exit 0
```

## Actual

```
DATE        ACCOUNT      FILENAME                                        TAGS  LINKS  WRITTEN IN   SOURCE
2026-01-05  Assets:Bank  manual.pdf                                                   main.bean:4
2026-01-31  Assets:Bank  Documents/Assets/Bank/2026-01-31.statement.pdf               main.bean:0  generated
```

The JSON row for the discovered statement carries `"source": {"filename": "<abs>/main.bean", "lineno": 0}` beside `"generated": true`. `main.bean` has 4 lines. The written row is correct (`main.bean:4`).

## Expected

A discovered document names no written location, because no directive was written. The table's `WRITTEN IN` cell is empty for it, or says it came from the documents folder (`documents folder` / the `option "documents"` line). JSON `source` is `null` for it, as `bea add document`'s envelope already answers `"source": null` for a directive that has no location yet. `generated: true` and the root-relative `filename` stay as they are. Written documents keep `file:line`.

## Cause

Beancount's documents plugin stamps each discovered `Document` with `new_metadata(<root file>, 0)`. `cli/src/bea_engine/ledger/reader.py` builds the row's `source` with `_source_of(entry)` (around line 996), which accepts any integer `lineno`, 0 included. `cli/src/cli/commands/list.py` `_written_in` (line 475) then prints `<file>:0`. `entry_generated` already treats `lineno < 1` as no location (`reader.py` line 489), so the two disagree on whether line 0 exists.

## Fix

In `_source_of`, or only in the document listing, return `None` when `lineno` is below 1. `_written_in` then prints an empty cell (or a `documents folder` label for a generated row). Search the other `_source_of` callers for the same line-0 case. Add a regression test in `cli/tests/` (the `list document` suite from w5/833) covering the repro: the discovered row has an empty `WRITTEN IN` and `source: null`, and the written row is unchanged. Confirm the test fails with the fix reverted.

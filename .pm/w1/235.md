# The MCP tool refuses a malformed `ledger` as if none were given

**Copy · backend-v2 (MCP) · minor · ~15m · A1.** From `/qa-find-bugs-mcp`, 2026-11-10, production `beancount-mcp 1.0.0`. The sweep sent 33 spellings to each of the 4 surfaces.

- **Repro:**
  - Values tried, on `getLedgerContext` and `checkLedger`:
    - whitespace around the ledger: `" puncsky/example"`, `"puncsky/example "`
    - extra or missing slashes: `"puncsky/example/"`, `"puncsky //example"`, `"/example"`, `"example"`
    - encoded or query characters: `"puncsky%2Fexample"`, `"puncsky/example?x=1"`
  - **Actual:** every one returns `BAD_USER_INPUT` "Select a ledger using ledger: owner/name" with the hint "Call `listLedgers`…". That reads as if no ledger were given.
  - **Control:** the resource, REST and GraphQL name the rule that failed ("Owner slug must contain only letters…", "Ledger name slug must…"), and the prompt says "ledger must be owner/name".
- **Cause:** `mcp-context.ts:96-101` tests `LEDGER_ID_PATTERN` (`mcp-ledger-selection.ts:11`) before `parseLedgerId`, and one message covers both "missing" and "malformed".
- **Fix:**
  - When `ledger` is present but malformed, say what is wrong, e.g. "…has surrounding whitespace" or "…must be exactly owner/name with one /".
  - Keep "Select a ledger…" for the missing case only.
  - Do not trim silently: all four surfaces refuse whitespace today, which is the right outcome.

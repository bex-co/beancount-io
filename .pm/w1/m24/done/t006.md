## Objective

A rules file with `match = ""` makes the first rule a catch-all that claims every row, and `--rules` ignores the category column that the import preview explicitly tells agents to rules-categorize.

## Context

- `w3/342`: `match = ""` is treated as a catch-all; the first rule wins every row.
- `w3/368`: `--rules` ignores category-column labels the preview suggests categorizing on.
- Rules handling is in `cli/src/bea_engine/importing.py`; the documented rules format is in `cli/docs/IMPORTING.md`.

## Steps

1. Refuse an empty or whitespace-only `match` at rules-load time with the file and rule named; require an explicit catch-all spelling if one is wanted.
2. Let a rule match on the category column the preview surfaces, not only on narration or payee.
3. Make the preview's categorization suggestion and the rules matcher use the same field set, so the advice is executable.
4. Document the matchable fields in the importing guide.

## Files

- cli/src/bea_engine/importing.py
- cli/docs/IMPORTING.md
- cli/tests/test_import.py

## Acceptance criteria

- [ ] A rules file containing `match = ""` is refused at load with the offending rule named; nothing is imported.
- [ ] A rule matching on the category column categorizes the rows the preview said it would.
- [ ] The importing guide lists exactly the fields a rule can match, and the documented example runs in CI.
- [ ] Existing valid rules files behave unchanged.

## Out of scope

- A rules DSL redesign or new match operators.
- AI-assisted categorization.

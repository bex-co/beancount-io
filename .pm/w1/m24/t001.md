## Objective

`bea import` hard-codes the comma, so a semicolon- or tab-delimited bank export fails on the very first step of the documented no-code path — and the error tells the user to name columns with `--csv`, which cannot work because the file is never split correctly.

## Context

- `w3/226` (major): `Date;Description;Amount` exports fail; the suggested `--csv` recovery still fails for the same reason.
- Semicolon exports are the norm for EU banks; tab and pipe appear in broker exports.
- CSV reading lives in `cli/src/bea_engine/csv_mapper.py` with a frontend counterpart at `cli/src/cli/csv_mapper.py`.

## Steps

1. Sniff the delimiter from the header row across `,` `;` tab and `|`, preferring the candidate that yields a consistent column count across the sampled rows.
2. Add an explicit `--csv delimiter=` override for files the sniffer cannot resolve, and remember it with the other sticky CSV settings.
3. Report the detected delimiter in the preview so the user can see what was assumed.
4. Make the header-failure message name the delimiter that was used, so a wrong guess is visible rather than mysterious.

## Files

- cli/src/bea_engine/csv_mapper.py

## Acceptance criteria

- [ ] A `;`-delimited export with `Date;Description;Amount` imports through `bea import --csv auto` with no override.
- [ ] Tab- and pipe-delimited exports do the same.
- [ ] `--csv delimiter=';'` forces the delimiter for a file the sniffer resolves differently.
- [ ] The preview names the delimiter in use; comma files behave exactly as before.

## Out of scope

- Fixed-width and multi-line-record exports.
- Excel or OFX/QIF input, which take other paths.

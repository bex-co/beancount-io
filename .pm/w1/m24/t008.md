## Objective

The import preview marks rows `ready` and shows a write diff even when the counter-account was never opened, so the user is told the import will succeed and then it does not — or, with `--allow-errors`, it does and leaves a ledger that fails `bea check`.

## Context

- `w3/276`: preview marks rows `ready` and shows a write diff when the counter-account is not open.
- The `--allow-errors` half of this interaction is fixed by m23/t002; this task fixes what the preview claims.
- Preview construction is in `cli/src/bea_engine/importing.py`.

## Steps

1. Validate each previewed row's accounts against the ledger's open set before marking it ready.
2. Introduce a blocked state distinct from ready and duplicate, with the missing account named and the `bea add open` line that fixes it.
3. Make the summary counts reflect blocked rows, and make `--apply` refuse while any row is blocked unless the row is excluded.
4. Keep the diff display for blocked rows so the user can see what would be written.

## Files

- cli/src/bea_engine/importing.py
- cli/src/cli/commands/import_.py
- cli/tests/test_import.py

## Acceptance criteria

- [ ] A row whose counter-account is not open is shown blocked, not ready, with the missing account and the remedy named.
- [ ] `--apply` refuses while a blocked row remains, and the ledger is untouched.
- [ ] After opening the account, the same import shows the row ready and applies cleanly.
- [ ] Ready and duplicate rows are unaffected.

## Out of scope

- Auto-opening accounts during import.
- Categorization suggestions for unknown accounts.

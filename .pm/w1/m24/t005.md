## Objective

`--id-key id` silently disables bank-ID deduplication because the CSV path writes the key as `bank_id`, and a bare `id` / `ID` column is ignored altogether, so content hashes are used where a stable bank identifier was available.

## Context

- `w3/237` (major): `--id-key id` disables dedupe; CSV writes `bank_id`, not `id`.
- `w3/280`: a bare `id` / `ID` column is ignored while `FitId` is recognized.
- The `import-id` convention is canonical in `skills/.claude/skills/beancount-import/references/dedup.md`; `bea import` must write and match the same convention (w1/m14, w1/m18).

## Steps

1. Recognize `id`, `ID`, and `Transaction ID` as bank-identifier columns alongside `FitId`.
2. Make `--id-key` name the same key the writer uses, or accept both spellings and document which is canonical.
3. Verify the written `import-id` still matches the convention in `references/dedup.md` so skill imports and CLI imports continue to deduplicate each other.
4. Report in the preview which identifier source was used: bank column or content hash.

## Acceptance criteria

- [ ] An export with a bare `ID` column deduplicates on that column across two runs; the second run reports duplicates, not new entries.
- [ ] `--id-key id` actually deduplicates rather than silently disabling it.
- [ ] The written `import-id` matches `references/dedup.md`, and a skill-written entry for the same row is recognized as an exact duplicate.
- [ ] The preview names the identifier source.

# GraphQL entry writes diverge from MCP/REST in three small ways

**Parity bugs · backend-v2 (GraphQL adapter + shared idempotency helper) · minor · ~50m · A1.** From `/qa-find-bugs-mcp`, 2026-11-10, production `beancount-mcp 1.0.0`, the same unpinned API key on all three surfaces, the disposable QA ledger.

1. **Posting meta values are not type-checked.**
   - `bulkEntries(dryRun:true)` with posting `meta:{qn:7}` previews `    qn: undefined undefined` and returns `valid:false` with a parse error. `{a:1}` and `[1,2]` do the same. With `allowInvalid`, the garbage would commit.
   - `true`, `null` and `{number:"5",currency:"USD"}` preview `valid:true` and write typed posting metadata that no other surface accepts.
   - **Controls:** MCP refuses with `BAD_USER_INPUT` ("…postings.0.meta.qn: … expected string") and REST with `VALIDATION_FAILED`. GraphQL already refuses non-string transaction-level meta.
   - **Cause:** `ledger-entry-resolver.mutation.ts:436-447` (`toServiceEntry`) checks only `entry.meta`, and `LedgerPostingInput.meta` is an unchecked `JSONObject`. The ledger's `journal-serialize.ts:648` then renders any object as `${number} ${currency}`.
   - **Fix:** apply the string-only check to every posting's meta, ideally through the shared zod entry schema.
2. **Preview errors drop `code`.**
   - In GraphQL `bulkEntries`, `appendLedgerText` and the slice update/delete previews, each `newErrors` item has only `{message, source}`. MCP and REST include `code` (e.g. `E3001`).
   - `docs/mcp.md:383-395` says the preview rule holds on GraphQL too.
   - **Cause:** `DirectiveTextError` (`ledger-entry-resolver.mutation.ts:501-505`) and `SliceWriteError` (`ledger-journal-resolver.mutation.ts:77-83`) declare no `code` field.
   - **Fix:** add a nullable `code: String` to both and pass it through.
3. **A `requestId` replay doesn't match across surfaces for a transaction.**
   - Commit a transaction on GraphQL `bulkEntries` with `requestId` R. MCP `addLedgerEntries` (or REST `POST …/entries`) with the same id and identical entries is refused `VALIDATION_FAILED` "requestId was already used with a different write request". The reverse direction fails the same way.
   - **Controls:** MCP↔REST and GraphQL↔GraphQL replays return the first result. An `open` entry and `appendLedgerText` replay across surfaces.
   - This contradicts w3/m61's single `requestId` contract.
   - **Cause:** `entry-write-idempotency.ts:76-78` hashes `JSON.stringify([operation, request])` over the adapter's own objects. GraphQL coerces `LedgerPostingInput` with `units` first, while zod puts `account` first, so the hashes differ by key order alone.
   - **Fix:** hash a canonical form (recursively sorted keys, `undefined` dropped). `insertReceipt` probably shares the exposure; this is unverified.
- **Check:** add GraphQL rows to the entry-parity and preview-matrix tests, plus a cross-surface replay test (GraphQL commit → MCP replay) for a transaction.

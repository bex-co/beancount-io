## Objective

Take `manageApiKeys` (list, create, revoke) off MCP as a documented credential-policy exception. Connectors then cannot read, mint, or revoke credentials. Today an OAuth connector can mint a key that has no link to its grant and can outlive the connection's revocation.

## Context

- `backend-cluster/backend-v2/src/server/api/op-class.ts`: `API_KEY_VERBS`. The `M.credentialMinting` reason already exists.
- `src/server/api/__tests__/parity-baseline.test.ts`: the frozen fixture stays as is. Add an explicit, commented exception for `apikeys.*` on MCP, following the existing `Query.getFeed` precedent.
- `docs/api-parity.md` and `op-class.ts` cite `manageApiKeys` as the precedent for credential reads on MCP. Rewrite those passages.
- REST `/api-gateway/v1/api-keys` and GraphQL stay exactly as they are.

## Steps

1. Remove the tool and its registration: `api-key-tools.ts`, `mcp-tools.ts`, `composition-root.ts`, `rate-limit.ts`.
2. Add `mcpExempt` to the three verbs, and the baseline exception.
3. Update the tests that name the tool, then the docs and ADR 0008's Amendments.

## Result (2026-10-10)

- **Tool removed:** `manageApiKeys` and `api-key-tools.ts` are gone from MCP. `tools/list` drops from 30 to 29.
- **Parity table:** the three `apikeys.*` verbs carry `mcpExempt: M.directoryCredentials`. A new `DIRECTORY_WITHHELD_FROM_MCP` set in `op-class.ts`, consulted by `isReachableOn`, takes them out of MCP's parity target, so `surface-parity` stays at zero gaps without hiding debt in exemption prose. `parity-baseline.test.ts` names the three verbs in an explicit `WITHDRAWN_FROM_MCP` list, which is the only narrowing it allows, and asserts their MCP binding is gone.
- **Removed leftovers:** the `MCP manageApiKeys` rate-limit override, and the `manageApiKeys` mention in the shared not-found hint (REST and GraphQL users saw it too).
- **Tests:** `api-key-authorization-parity.test.ts` keeps every GraphQL and REST authorization check and adds one proving MCP lists no key tool and refuses `manageApiKeys` for list, create, and revoke without touching the key store. The scope-gate tests that used the key tool as their admin example now use `manageLedgers`.
- **Docs:** `docs/mcp.md` (key section, tool table, rate-limit note), `docs/api-parity.md` exception 9, and ADR 0008's Amendments.
- **Gates:** backend-v2 `yarn typecheck`, `yarn lint`, and `yarn test` (5069 passed); `yarn generate-v1-openapi` shows no drift, so REST is unchanged.

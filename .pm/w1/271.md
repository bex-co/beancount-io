# `bea update transactions --help` runs its CSV example rows into one line, and `bea update transaction --help` splits its OLD=NEW example

Found by `/qa-find-bugs-cli w1` on 2026-11-16 (HEAD `3a6e212d9`, `bea 0.3.1`, macOS 26.5, checkout `uv run bea`, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`). Severity: minor. No ledger is touched; the help is the only place the CSV mapping form is shown on the command line. A1/A2: an agent or newcomer who copies the CSV example from help gets a one-line file with no header row, and one who copies the first line of the OLD=NEW example runs `--account` with no value.

**Repro** (any directory, no ledger needed):

```sh
COLUMNS=80  bea update transactions --help
COLUMNS=120 bea update transactions --help
COLUMNS=80  bea update transaction --help
```

**Actual.** At both widths `update transactions` prints

```
  CSV rows map an id to an account and a flag; empty cells leave the field:

    id,account,flag   9f2c,Expenses:Groceries,*   71ab,,*
```

and `update transaction` prints

```
    bea update transaction --id 9f2c --account
    'Expenses:Dining=Expenses:Coffee'
```

**Expected.** The CSV example shows three lines: header `id,account,flag`, then `9f2c,Expenses:Groceries,*`, then `71ab,,*`. The `update transactions --from` reader parses exactly that shape (`cli/tests/test_update_batch.py` writes `id,account,flag\n…` files). The OLD=NEW command example stays one copyable command, or uses an explicit shell continuation. Basis: the same defect class was fixed for `bea add custom --help` in w5/307 (`bd171aeac`), which added a `\b` no-rewrap marker and `cli/tests/test_add_custom_help_examples.py`.

**Root cause.** cli: the docstrings of `update_transactions` and `update_transaction` in `cli/src/cli/commands/update.py` (CSV block at about lines 333–337, OLD=NEW example at about line 142) are indented paragraphs without click's `\b` marker. Click therefore rewraps them as prose. It joins the three CSV lines, and it breaks the 82-column example at the terminal width. `add custom` (`cli/src/cli/commands/add.py:534`) and `ingest` (`ingest.py:387`) already use `\b`.

**Fix.** Put `\b` before the CSV example block. For the OLD=NEW example, either put `\b` before it and split it with a trailing ` \` continuation so each line fits in 80 columns, or shorten the example. Add a regression next to `test_add_custom_help_examples.py`, run at `COLUMNS=60` and `120`, that asserts each CSV line and each example command line appears verbatim on its own line. It should fail with the fix reverted. Consider a generic guard: walk every command's help, and for each indented docstring paragraph not marked `\b`, assert its lines render verbatim. A scan of all 81 commands at 80 columns flagged only these two commands. CLI only, so no REST/GraphQL/MCP parity is involved. Estimate: 20–30 minutes.

**Dedupe.** Searched `.pm/**` (open, `done/`, `blocked/`) for `rewrap`, `help` + `wrap`, `id,account,flag` and `\b`. w5/307 is the closed `add custom` instance. w1/258 and w1/259 cover `update transaction(s)` preview behavior, not help. Nothing open covers it.

# Decision needed: should the `bea update transactions` batch preview exit 1 when a row is rejected?

**Source:** routine cli-qa, 2026-11-15 (follow-up the run surfaced but did not file).

The batch preview exits 0 even when every row is rejected (for example an unknown account or unknown id). Since w1/259, the single-row `bea update transaction` preview exits 1 for an edit the apply would refuse, and the batch command's own help says "the exit status is still 1 whenever any row was rejected".

The exit 0 is deliberate today: `cli/tests/test_update_batch.py::test_csv_preview_flags_rejects` pins it, and the import preview's blocked rows also exit 0 (w5/696).

**Owner chooses:**
- (a) the batch preview exits 1 when any row is rejected, matching the single-row preview and the help text; update the help, `cli/docs/USAGE.md` and the test together; or
- (b) keep exit 0 and correct the help text and `cli/docs/USAGE.md` ("Updating directives") to say the preview always exits 0.

Paths: `cli/src/cli/commands/update.py` (`_rendered_batch`), `cli/docs/USAGE.md`. Done when behaviour, help and docs agree with the chosen option.

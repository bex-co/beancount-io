# `bea balance ACCOUNT` hides an account closed after the report's as-of date and says "No accounts match"

Found by `/qa-find-bugs-cli w1` on 2026-11-15 (HEAD `225566290`, `bea 0.3.1`, macOS 26.5, checkout `uv run bea`, stdin closed, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, offline synthetic ledger). Severity: minor. A1: an agent that asks `bea balance old` about an account it can see in the trial balance is told the account does not exist.

**Contract.** `cli/docs/USAGE.md` (Reports, `bea balance`): "Accounts closed by the `--time` end date that hold no balance are excluded from filtered views". w1/071's acceptance put it the same way: "exclude only accounts closed on/before the as-of date **and** with an empty balance".

**Repro** (synthetic):

```sh
cat > cl.bean <<'EOF'
option "operating_currency" "USD"
2026-01-01 open Assets:Old USD
2026-01-01 open Assets:New USD
2026-01-01 open Assets:Zero USD
2026-01-01 open Equity:Opening USD
2026-01-02 * "o"
  Assets:Old 100 USD
  Equity:Opening
2026-02-01 * "move"
  Assets:New 100 USD
  Assets:Old
2026-03-01 close Assets:Old
2026-03-01 close Assets:Zero
EOF
bea --file cl.bean check                          # clean, exit 0
bea --file cl.bean balance                        # lists Assets:Old and Assets:Zero
bea --file cl.bean balance old; echo "exit $?"
bea --file cl.bean balance -t "2026-01 - 2026-02" old
```

Actual: without `--time`, the report reads "Trial Balance — 2026-01-02 through 2026-02-01" (`--json`: `as_of` `2026-02-01`, `period.end_exclusive` `2026-02-02`). The closes are dated 2026-03-01, after that as-of date. Even so, `balance old` prints `No accounts match old.` and exits 0, with `account_filter_empty: true` and no period hint. `balance zero` behaves the same way. The *wider* explicit window `-t "2026-01 - 2026-02"`, which ends 2026-02-28 and is still before the close, does list `Assets:Old`. So the default view hides an account that a longer window shows. `report trial-balance -a Assets:Old` and `list transaction -a old` both find it.

Expected: as of 2026-02-01 both accounts are open, so `balance old` lists `Assets:Old —` and `balance zero` lists `Assets:Zero —`. A close dated after the report's end does not count. With `-t "2026-01 - 2026-03"`, which covers the close, they stay hidden as documented.

**Root cause.** `cli/src/bea_engine/report.py:205-209` (the `balance` branch) collects `closed` from every `Close` in `filtered.entries`. With no `--time`, `filtered.entries` is the whole ledger, but the period ends at the last transaction/price date (Fava's `date_last`), so a later `close` still counts. With a `--time` window, the entries are already clipped to the window, which is why the explicit window works.

**Fix** (about 30 minutes; `cli` only). Count only closes dated before the period's exclusive end (`entry.date < filtered.end_date`, after checking that `end_date` is exclusive the way `period.end_exclusive` is). Add a regression test next to `cli/tests/test_balance_closed_account_holding.py`: with the fixture above, `--json balance old` and `balance zero` match their account with no `--time`, and stay excluded with `-t "2026-01 - 2026-03"`. Revert the fix and check that the test fails.

**Blast radius.** `_prune_tree`'s `closed` set is built only here (the other caller, `report.py:2355`, passes none). `_holding_accounts` reads balances over the same entries and is unaffected. This is local CLI only. Whether a hosted balance filter has the same rule is unverified.

**Dedupe.** Searched `.pm/**` for `closed by the`, `closed accounts`, `No accounts match` and `account_filter_empty`. w1/071 (done, `fbbcadf4b`) kept closed accounts that still hold money, and its acceptance already named the as-of bound. That bound was never applied to the no-`--time` case, so this note finishes 071 rather than reopening a shipped DoD that it tested.

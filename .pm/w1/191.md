# Interval totals without `accountName` return all-zero intervals

**Bug · ledger + backend-v2 · major · ~30m · A1.** From `/qa-find-bugs-mcp`, 2026-11-08, production `beancount-mcp 1.0.0`, unpinned API key, read-only.

REST and the resource template both document `accountName` as optional ("Restrict the totals to one account"). Omitting it returns zeros instead of every account's total, with no error.

- **Repro:**
  - `resources/read beancount://<owner>/<name>/interval-totals?interval=month&time=2026` returns `total: 0` and `byAccount: []` for every interval.
  - REST `GET …/interval-totals?interval=month&time=2026` returns the same.
  - GraphQL `getLedgerIntervalTotals(accountName: "")` returns `balance {}`.
  - Adding the `account=Expenses` filter without `accountName` still returns zeros.
  - **Control:** `accountName=Expenses` returns the correct monthly sums.
- **Cause:** `backend-v2` `analysis-handler.ts:262` sends `accountName ?? ""`, and the ledger's `reports.ts:305` defaults to `""` as well. `interval-series.ts:244` `matchesAccountOrChild("", …)` matches nothing (`account === "" || startsWith(":")`). This is a side effect of the w21/180 prefix-boundary change, which replaced Fava's raw `startswith`.
- **Fix:** treat an empty or omitted prefix as "all accounts" in `matchesAccountOrChild`. Otherwise make `accountName` required on REST, GraphQL and the MCP template with `BAD_USER_INPUT`. Silent zeros are wrong either way.
- **Check:** add parity tests for an omitted and an empty `accountName`. The result is either the all-account totals or a `BAD_USER_INPUT` refusal, and it matches on all three surfaces.

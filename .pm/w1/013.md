# Cloud clone still prompts through SSH under --no-input and --json

Severity: major. Estimate: 45–60m including subprocess regression coverage.
Owner: CLI. A1: automation flags must reach the Git/SSH child so unattended
agents cannot wait indefinitely for host-key or credential prompts.

Reproduced twice with `--no-input`, then once with `--json`, at main
`c6de619d9094e1ae45a248eef3e6ba3d74a5944f`, checkout bea 0.1.0 / Python 3.13.0,
macOS 26.5.1 arm64. Real Git and OpenSSH, disposable loopback sshd and HTTP
metadata fixture; no real account, remote ledger, or SSH credential used.
Cwd `cli/`. Child owns a controlling PTY; its terminal output is merged, not
separate stdout/stderr. This specifically covers an agent with an allocated PTY.

Reproducer from `cli/` (requires local OpenSSH server tools; tested on macOS):

import tempfile, threading, time
from pathlib import Path
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer
with tempfile.TemporaryDirectory(dir='tmp') as directory:
    root = Path(directory).resolve()
    key = root/'hostkey'
    subprocess.run(['ssh-keygen','-t','ed25519','-N','','-f',str(key)],
                   check=True, capture_output=True)
    with socket.socket() as sock:
        sock.bind(('127.0.0.1',0))
        port = sock.getsockname()[1]
    config = root/'sshd_config'
    config.write_text(f'ListenAddress 127.0.0.1\nPort {port}\nHostKey {key}\n'
                      f'PidFile {root}/sshd.pid\nPasswordAuthentication no\n'
                      'PubkeyAuthentication no\nUsePAM no\n')

                              stdout=subprocess.DEVNULL,

                  updatedAt='2026-09-09T00:00:00Z', size=0)

        output = b''

                    except OSError: break
            print(output.decode(errors='replace'))
        finally:
            try: os.killpg(pid,signal.SIGKILL)
            except ProcessLookupError: pass
            os.waitpid(pid,0)
            os.close(fd)
    finally:
        server.shutdown()
        server.server_close()
        daemon.terminate()
        daemon.wait(timeout=5)

Actual terminal output: `Are you sure you want to continue connecting
(yes/no/[fingerprint])?` and no command completion at the external 8-second
cutoff. JSON mode also writes that prompt through the controlling terminal and
waits. No input is sent and no host key is accepted. Control: appending
`-o BatchMode=yes` to the isolated GIT_SSH_COMMAND causes prompt-free host-key
rejection and bea exit 1. Successful local-Git cloning is separately verified.

Expected basis: `cli/docs/USAGE.md:67` explicitly says that nothing waits for a
human under --no-input, JSON, nonterminal stdin, or truthy CI. Fail promptly with
an actionable setup diagnostic, without weakening host-key verification or
silently accepting unknown hosts. Preserve normal interactive SSH behavior when
input is allowed.

Root cause: `cli/src/cli/commands/cloud/ledger/manager.py:65` runs Git inheriting
terminal/environment state, with no no-input policy. `ledger/app.py:52` and `:86`
only forward JSON's quiet-output setting; neither forwards
`context.current().no_input`. Git's SSH child opens `/dev/tty` independently of
Python's prompt logic. Apply no-input behavior at this subprocess boundary for
both clone and create --clone, respecting custom SSH configuration. Merely
closing Git stdin or setting GIT_TERMINAL_PROMPT is insufficient for SSH's own
terminal prompts. Add a controlling-PTY regression and interactive control.

Dedupe: all open/completed `.pm` searched for BatchMode, host keys, SSH prompts,
clone/no-input and GIT_TERMINAL_PROMPT; no overlap. Targeted history traces the
shared function to b7c73c07. w1/010 is an HTTP deadline defect; w1/011 is lost Git
diagnostics. This failure waits for explicit human input after HTTP succeeded.
No API changes or REST/GraphQL/MCP parity changes are needed.

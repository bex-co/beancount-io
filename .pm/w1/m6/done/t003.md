## Objective

Make the interaction page honor the hint: a signed-out user who tapped Sign Up sees the registration form first, and a user whose browser already holds a session gets an explicit choice instead of being silently approved into the existing account.

## Context

- `dashboard/src/routes/oauth.mobile-consent.tsx` validates only `uid` and `scope`; a non-strict zod object would silently strip a hint.
- `dashboard/src/features/oauth/funcs/mobile-loader.ts` picks the initial step purely from `context.userProfile` (`approve` vs `login`).
- `dashboard/src/features/oauth/pages/mobile-consent.tsx` already has `login | register | otp | approve` steps and a "Use another account" action that runs `LogoutDocument` + `clearStore` + `show_login`; the reducer lives in `funcs/mobile-consent-state.ts`.

## Steps

1. Accept an optional `screen_hint: "signup"` in the route search schema.
2. Loader: signed-out + hint → initial step `register`; signed-out without hint → `login`; signed-in without hint → unchanged.
3. Signed-in + hint → a new `choose_account` step: "Continue as <email>" proceeds to the current approve behavior; "Create a different account" runs the existing logout-and-switch logic and lands on `register`.
4. Extend the reducer and loader tests for the new transitions.

# GraphQL bank mutations take no `dryRun`, while MCP and REST preview all five

**Parity bug · backend-v2 · minor · ~45m · A1.** From `/qa-find-bugs-mcp`, 2026-11-09, production schema introspection.

- **Repro:** each of these returns `GRAPHQL_VALIDATION_FAILED` "Unknown argument \"dryRun\"": `syncPlaidTransactions`, `submitPlaidTransactionsToLedger`, `deletePlaidTransactions`, `reconcilePlaidAccounts`, `unlinkPlaidItem` with `dryRun: true`.
  - **Controls:** MCP `syncBankTransactions`, `importStagedBankTransactions`, `discardStagedBankTransactions`, `reconcileBankAccounts` and `unlinkBankConnection` take `dry_run`. REST bank routes take `?dry_run`/`dryRun` (`banks-handler.ts:46-59,201-259`).
- **Contract:** the w23/m9 definition of done accepts the preview flag "everywhere the flag exists" on all three surfaces. `docs/api-parity.md:305` lists "preview support" under Bank operations.
- **Cause:** `src/features/plaid/api/resolvers/` declares no `dryRun`/`dry_run` argument. w3/m8 added the service-level previews to REST and MCP only.
- **Fix:**
  - Add `dryRun`/`dry_run` twins, refusing a conflict through `resolveFlagAlias`, to the five resolvers.
  - Pass the flag to the existing service preview paths.
  - Expose the preview fields in the GraphQL return types, or add a preview union.
- **Check:** add GraphQL rows to the bank parity tests and to `write-preview-matrix.test.ts`.

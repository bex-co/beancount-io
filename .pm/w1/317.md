# `bea add transaction` still writes a cost or price like `{100/3 USD}` or `@ 100/3 USD` as a 28-digit number, exit 0, so every report in that currency prints 26 decimals (gap in w1/313)

**Source:** routine cli-qa, 2026-11-19. **Severity:** major. **Estimate:** 45 minutes. **Owner:** cli. **A1:** w1/313 stopped `-p 'Expenses:Dining 100/3 USD'`, but only for units and balance amounts. An agent that books "3 shares for 100 USD" as `-p 'Assets:Broker 3 HOOL {100/3 USD}'`, or an exchange as `3 EUR @ 100/3 USD`, still gets exit 0 and a ledger that permanently holds `33.33333333333333333333333333 USD`. That is the same damage w1/313 fixed: in a whole-dollar ledger every USD figure in every report then prints 26 decimals.

Found at `780338230` with the checkout's `uv run bea` 0.4.1, macOS 26.5.1, isolated `BEA_CONFIG_DIR`/`XDG_CACHE_HOME`, stdin closed, stdout piped, synthetic ledger. Reproduced in fresh processes from a pristine copy.

## Repro

```sh
cat > main.bean <<'EOF'
option "operating_currency" "USD"
2026-01-01 open Assets:Checking USD
2026-01-01 open Assets:Broker
2026-01-01 open Equity:Opening-Balances USD

2026-01-01 * "Opening"
  Assets:Checking  1000 USD
  Equity:Opening-Balances
EOF
bea --file main.bean balance -x units          # Checking 1,000 USD
bea --file main.bean add transaction --date 2026-01-10 "3 shares for 100" \
  -p 'Assets:Broker 3 HOOL {100/3 USD}' -p Assets:Checking   # exit 0
tail -3 main.bean
bea --file main.bean balance -x units
```

## Actual

The file gains `Assets:Broker  3 HOOL {33.33333333333333333333333333 USD}`. `bea check` passes. The inferred cash leg is `-99.99999999999999999999999999 USD` (`list transaction`), and the trial balance now reads:

```
  Assets                                          3 HOOL  900.00000000000000000000000000 USD
    Checking                                      900.00000000000000000000000000 USD
  Equity                                          -1,000.00000000000000000000000000 USD
```

The same happens with every other cost or price form (all exit 0, all written evaluated):

| Posting | Written as | Effect |
| --- | --- | --- |
| `3 EUR @ 100/3 USD` | `@ 33.33333333333333333333333333 USD` | cash leg `-99.99999999999999999999999999 USD`; USD prints 26 decimals |
| `3 HOOL {100/3 USD}` | `{33.33333333333333333333333333 USD}` | as above; holdings AVG COST prints 26 decimals even in a cents ledger |
| `3 EUR @@ 100/3 USD` | `@@ 33.33333333333333333333333333 USD` | Checking `966.66666666666666666666666670 USD` |
| `3 HOOL {{100/3 USD}}` | `{0 # 33.33333333333333333333333333 USD}` | Checking `966.66666666666666666666666670 USD`; with `price HOOL 11 USD`, the trial balance's adjustment line reads `0.33333333333333333333333330 USD` and the holdings cost basis `33.33333333333333333333333333 USD` |

The bulk amount shorthand does the same: `"amount": "3 EUR @ 100/3 USD"`, `"3 AAPL {100/3 USD}"` and `"3 EUR @@ 100/3 USD"` are written with exit 0. A balance tolerance (`add balance --amount '1000 ~ 1/3 USD'`) is also written as `~ 0.3333333333333333333333333333 USD`, though it does not change report precision.

Controls: `-p 'Assets:Checking -100/3 USD'` is refused (exit 2, w1/313). A structured bulk `"price": {"number": "100/3", ...}` is refused (`Invalid amount '100/3'`). `@ 1/8 USD` is written as `@ 0.125 USD` and harms nothing. `@@ 100 USD` and `{{100 USD}}` over 3 units keep the ledger in whole dollars (w3/309).

## Expected

A cost or price whose own arithmetic does not terminate is refused at the input boundary, as w1/313 refuses units: exit 2 on the flag path, the row rejected in bulk, nothing written. The message names the expression and suggests the total form that keeps the typed total exact, for example: `--posting 1 'Assets:Broker 3 HOOL {100/3 USD}': the cost 100/3 does not divide exactly; Beancount would store 33.33333333333333333333333333 USD. Write the total instead, such as {{100 USD}}, or a per-unit cost to the precision you mean, such as {33.33 USD}.` A `@@` total that is itself exact (`3 EUR @@ 100 USD`) keeps working even though the parser divides it into a repeating unit price.

## Root cause

- `cli/src/bea_engine/ledger/adding.py:1376-1384` calls `refuse_repeating` on `posting.units` only. `posting.cost.number_per`, `posting.cost.number_total` and `posting.price.number` are written whatever `parse_exact` marked.
- `cli/src/bea_engine/ledger/models.py:369` (bulk amount shorthand `_posting_fragment`) does the same.
- `cli/src/bea_engine/amounts.py:220` (`Repeating`) says why only units and balances are judged: the grammar divides a `@@` total into a unit price that is marked `Repeating` too. That is right for an exact total (`@@ 10 USD` over 3 units), but it also lets through a per-unit `@`, a `{…}` cost, and a `@@` or `{{…}}` total whose own expression does not terminate.

## Fix

In both callers, also refuse a `Repeating` `cost.number_per` and `cost.number_total`. Refuse a `Repeating` `price.number` only when the posting's price is per-unit `@`. For `@@`, judge the typed total instead: `split_total_price` (`amounts.py:294`) already reads it from the raw text, so `@@ 100/3 USD` is refused and `@@ 10 USD` over 3 units is not. Extend `cli/tests/test_add_repeating_quotient_refused.py` with the four forms on the flag path and in bulk: exit 2 or the row rejected, file byte-identical. Keep `test_a_total_price_over_three_units_is_still_written` passing, and add `{{100 USD}}` over 3 units as a control. Say in `cli/docs/USAGE.md`, beside the w1/313 sentence ("A quotient that does not terminate, such as `100/3 USD` in a `--posting` …"), that costs and prices are judged too. Run `make check-all` in `cli/`.

## Dedupe

Searched `.pm/**` for `100/3`, `10/3`, `repeating`, `28-digit`, `does not divide` and `does not terminate`. w1/313 (done, `575dee5cf`) fixed units and balance amounts; its resolution says "only units and balance amounts are judged", and its rationale covers only an exact `@@` total. w3/309 fixed `@@` totals written as repeating unit prices. w5/010 listed `100/3 EUR` as working arithmetic. No open item covers costs or prices. This is not deployment lag: the code at HEAD still checks units only.

# create --clone loses created-ledger recovery context when Git cannot start

Severity: major for partial-write recovery. Estimate: 30–45m with regression
coverage. Owner: CLI. A1/A2: an agent must know that remote creation succeeded
before deciding whether to retry an onboarding command.

Reproduced twice at main `c6de619d9094e1ae45a248eef3e6ba3d74a5944f`, macOS
26.5.1 arm64, checkout `uv run bea` 0.1.0, Python 3.13.0. Loopback simulation of
successful remote creation, fresh bea processes, closed stdin, no TTY. Only the
child PATH lacks Git; the actual installation and shell PATH are unchanged.
This finding is the missing partial-write diagnostic, **not** missing Git itself.

Reproducer from `cli/`:

Actual create result: stdout empty; exit 2; JSON stderr only
`[Errno 2] No such file or directory: 'git'`. The following fresh-process `show`
returns the fixture's persisted created ledger. No local clone directory exists.
No real hosted resource was created. Expected basis: `cli/docs/USAGE.md:627`
promises that failed cloning after creation prints a manual clone command and
makes the ledger's existence clear. Either check Git availability before the
remote mutation, or preserve created-ledger identity and recovery instructions
when process launch fails afterward. Never silently retry the create.

Control: with Git available and an occupied destination, create --clone exits 1
with `Ledger 'qa/...' was created but could not be cloned. Clone it manually
with: git clone ...`; a fresh `show` confirms persistence. That documented
nonzero/partial-success behavior is correct and is not this finding.

Root cause: `cli/src/cli/commands/cloud/ledger/manager.py:65` lets OSError from
subprocess startup escape; only a completed nonzero Git process becomes
CloneError. `ledger/app.py:53` catches only CloneError, so FileNotFoundError
bypasses the created-ledger recovery message and reaches `errors.py:150`.
Normalize process-launch errors or preflight the executable; test actual child
PATH isolation and ensure no misleading remote-create retry guidance.

Caller search: clone and create --clone share clone_ledger. Only create --clone
has the already-committed remote step. FileNotFoundError and executable
permission errors use the same launch boundary (permission error unverified).
No backend/API parity changes or generated client edits needed.

# Decision needed: should `bea add close` refuse to close a used Income or Expenses account?

**Source:** routine cli-qa, 2026-11-15 (follow-up the run surfaced but did not file).

`bea add close` refuses to close any Income or Expenses account that has postings, saying it "still holds" its lifetime total:

```
bea add close -a Expenses:Food --date 2024-12-31
# → refuses: account still holds 45.50 USD (exit 1)
```

Its hint tells the user to post a transaction that moves the amount out. For a flow account that would distort the income statement, since an expense account's running total is history, not a balance to drain.

- Upstream `check_drained` deliberately covers only balance-sheet accounts (`beancount/plugins/check_drained.py:49-52`).
- w5/888 (done) extended the guard to flow accounts on purpose.
- The import advisory shares the helper: `cli/src/bea_engine/ledger/adding.py` (`_funded_close_refusal`, `_remaining_balance`) and `cli/src/bea_engine/importing.py` (`_funded_close_advisories`).

**Owner chooses:**
- (a) keep the refusal for flow accounts as w5/888 decided; or
- (b) limit the refusal (and the import advisory) to Assets/Liabilities/Equity, and let a used Income/Expenses account close without `--force`.

**Done when** an unforced close of a used Expenses account behaves as decided, and `cli/docs/USAGE.md` (around line 1510) says so.

# Localize date formatting — thirteen languages, one date format

Found while walking `fa` for `w1/m31`: the transactions list renders `December 31, 2025` inside an otherwise fully Persian, right-to-left app. Every locale gets the same English long-form date.

This is a **formatting** gap, not a translation or a layout one, which is why neither m29/m30 (strings) nor m31 (layout) touched it. The locale files have nothing to say about it — the format is baked into the date helpers.

Screens that show a formatted date: the transactions list section headers, transaction detail (`تاریخ` row), the open-account and add-transaction date rows, notifications/commit rows, and the budget history rows.

Worth checking before scoping:

- Where the formatting actually happens — likely `src/common/format-util.ts` and/or per-screen `toLocaleDateString` calls; grep before assuming one home.
- Whether `Intl.DateTimeFormat` is available in the Hermes build with full ICU, or whether the app ships the small-ICU variant that only knows `en-US`. This decides the whole shape of the work — if ICU is trimmed, a locale-aware format needs either a Hermes ICU flag or a hand-rolled month-name table in thirteen languages, and the second is really an m29-style translation sweep wearing a different hat.
- Persian calendar is a separate and much larger question (Jalali dates are not a formatting option, they are a different calendar). Out of scope for a formatting pass — note it and move on.

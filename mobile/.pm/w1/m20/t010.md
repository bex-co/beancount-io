## Objective

Cover the parts of this milestone that are actually testable in the jest-lite runner — the pure motion math and the reduce-motion decision — with tests that assert real behavior and failure modes.

## Context

- Tests live in `src/__tests__/` (and per-module `__tests__/` dirs) and run via `yarn test:unit`, a custom jest-lite runner in `scripts/`. It is **not** full Jest.
- **The runner has no `@/` path alias for value imports** — test-reachable modules must use relative imports for values; `@/` works only for type imports.
- **Matchers are limited**: `toBe` / `toEqual` / `toBeCloseTo` / `toBeTruthy` / `toBeFalsy` / `toThrow`, plus `.not`. No `toHaveLength`, no `toBeNull`.
- The precedent to follow is `src/__tests__/ledger-drawer-motion.test.ts` — six tests over the pure, import-free `components/ledger-drawer/drawer-motion.ts`. That is the only motion under test in the app today, and it is the model: extract the math so it can be tested, then test it.
- Rendering and animation frames are not testable here. Do not fake coverage by asserting that a component rendered.

## Steps

1. Test the t001 tokens as data: the scale is monotonic, every duration respects the documented motion budget (entrance/transition < 500ms, feedback < 300ms), and nothing is zero or negative.
2. Test the path-length helper from t002 (`Σ hypot(dx, dy)`) against hand-computed fixtures, including a single-point series, a flat series, and a series with a zero-length segment.
3. Test the series resampling / lerp helper from t005 if the fallback route was taken: equal-length inputs, unequal-length inputs, and that endpoints are preserved exactly at progress 0 and 1.
4. Test the bar geometry from t004 across the zero baseline: a positive value, a negative value, and a near-zero value that must respect the min-height rule without inverting.
5. Test the reduce-motion decision as a pure function of the setting where possible, rather than trying to test the hook's subscription.
6. Keep every helper under test import-free so it stays worklet-safe and runner-friendly, as `drawer-motion.ts` does.

## Files

- `src/__tests__/` and/or `src/common/d3/__tests__/`, `src/common/theme/__tests__/`

## Acceptance criteria

- [ ] Path-length, bar-baseline geometry, and (if applicable) series interpolation are covered with hand-computed fixtures including the degenerate cases named above.
- [ ] Motion tokens are asserted against the documented budget.
- [ ] Tests use relative imports for values and only the matchers the runner supports.
- [ ] No tautological or snapshot-everything tests; each test would fail if the behavior regressed.
- [ ] `yarn test:unit` green.

## Out of scope

- Rendering/animation-frame tests — not supported by the runner.
- Testing Reanimated's own `ReduceMotion.System` behavior; that is the library's contract, verified by hand in t008.

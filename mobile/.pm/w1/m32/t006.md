## Objective

Until approval cards ship (ADR002 P2), a turn that reaches an approval-gated write tool (ledger edit, receipt insert) must end in a clear, translated notice — "reviewing and approving changes isn't on mobile yet; continue on the web" — never a silent hang, and never a write.

## Context

- The stream pauses with a tool part in `approval-requested` state (`isToolUIPart(part) && part.state === "approval-requested"` — see the dashboard's `isAwaitingApproval` in `page.tsx`). Mobile sends **no** approval response, so the tool never executes: the anti-goal "AI proposes, the user confirms" holds absolutely in this milestone.
- This is also the ADR002 security posture: the approval mechanism's integrity depends on rendering the real diff, which is exactly the P2 work being deferred — so v1 refuses rather than approximates.

## Steps

1. Detect the awaiting-approval state in the hook/screen.
2. Render the notice card in place of the input bar (input returns on New chat).
3. Unknown/other tool part types render as a compact "working…" activity line, not raw JSON.

## Files

- `src/screens/agent-screen/` (screen + hook)
- `src/translations/en.ts` + locale files

## Acceptance criteria

- [ ] A prompt like "add a $5 coffee expense" ends at the notice; the ledger is untouched (verify via the Files tab).
- [ ] The notice is translated (or `KNOWN_GAPS`-named) and themed in light/dark.
- [ ] Conversation remains recoverable via New chat.

## Out of scope

- Approval cards with diff rendering (ADR002 P2); any approval response from mobile.

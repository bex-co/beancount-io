## Objective

No dead-end states: a stop control while streaming, a failed turn rendered inline with one-tap retry, and a New chat action that resets both the visible conversation and the `sessionId`.

## Context

- `useChat` already exposes `stop` and `regenerate`; the hook (t003) surfaces `error`.
- Quota exhaustion (the AI-CFO monthly limit) is a distinct error: render it as an upgrade notice, not a retry — retrying a rate-limited request is noise. Mobile's subscription surface is the destination (`docs/ADR001-mobile-billing.md`).
- New chat regenerates the in-memory `sessionId` and reseeds the welcome message.

## Steps

1. Input bar swaps send → stop while `status` is submitted/streaming.
2. Error turn renders an inline bubble with retry; quota errors render the upgrade notice instead.
3. New chat action in the screen header; wires the hook's reset.

## Files

- `src/screens/agent-screen/` (screen + hook)
- `src/translations/en.ts` + locale files

## Acceptance criteria

- [ ] Stop aborts a live stream mid-answer; the partial text stays visible.
- [ ] A forced failure (airplane mode) shows the inline error; retry resubmits the same question.
- [ ] New chat clears the thread and changes the `sessionId` (assertable in t010).

## Out of scope

- Resumable streams; persisted history.

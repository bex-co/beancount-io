## Objective

A pure, unit-testable module for the five account roots, full-name composition, and beancount account-name validation, consumed by the open-account form (t003) and covered by tests (t007).

## Context

- Web reference validation: the account must start with a valid root prefix + `":"`, is colon-separated, and each component is capitalized — see `beancount-dashboard` `src/features/ledger-data/accounts/open-account-dialog.tsx` and `src/common/lib/utils/account-utils.ts`.
- Existing root knowledge on mobile: `src/components/account-type-icon/root-icon.ts` knows the five roots (assets / liabilities / equity / income / expenses) and their glyphs.
- **jest-lite has no `@/` path alias** (see memory): test-reachable **value** modules must use relative imports only. Keep this module free of `@/` value imports (define the roots locally or import type-only) so t007 can import it.

## Steps

1. Create `src/screens/open-account-screen/account-name.ts`.
2. Export the ordered list of roots with their canonical prefixes: `Assets`, `Liabilities`, `Equity`, `Income`, `Expenses` (keep in sync with `account-type-icon`; do not introduce a divergent list).
3. `composeAccountName(rootPrefix, subPath)` → e.g. `("Assets", "Bank:Checking")` = `"Assets:Bank:Checking"`; trim, collapse stray/duplicate colons, drop leading/trailing colons.
4. `validateAccountName(name, rootPrefixes)` → `{ ok: true } | { ok: false, reason }`: must start with a valid root prefix + colon; ≥ 2 components; each component non-empty, starts uppercase, allowed chars only (beancount: letters/digits/`-`); no trailing/double colon.

## Files

- `src/screens/open-account-screen/account-name.ts`

## Acceptance criteria

- [ ] Pure functions, no React and no `@/` value imports (jest-lite importable via relative path).
- [ ] Valid: `Assets:Bank:Checking`, `Liabilities:CreditCard:Visa`. Invalid: `assets:x`, `Assets`, `Assets:`, `Assets::x`, `Foo:Bar`, `Assets:bank`.

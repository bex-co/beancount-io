## Objective

The create-account form screen: pick a type, name the account, pick a currency and open date, submit.

## Context

- Route pattern: a pushed (non-tab) screen under `app/(app)/`; mirror how the multi-postings transaction screen is registered/pushed.
- Form reference (the app uses `useState`, not React Hook Form despite it being in deps): `src/screens/multi-postings-transaction/multi-postings-transaction-screen.tsx` — `Stack.Screen` with a `headerRight` "Done" that is disabled while the form is invalid and shows loading on submit.
- Reusable components: `src/components/picker` (wheel picker) for account type + currency; `src/components/date-picker-modal` for the date; `src/components/button`; a text input for the name; root glyphs from `src/components/account-type-icon`.
- Validation + name composition from t001; submit via t002's `useOpenAccount`.

## Steps

1. Create the route `app/(app)/open-account.tsx` rendering `OpenAccountScreen`.
2. Create `src/screens/open-account-screen/open-account-screen.tsx` + `index.ts`.
3. Fields: **account type** (Picker over the 5 roots, showing each root's glyph); **account name** (sub-path TextInput with a live full-name preview `Assets:Bank:Checking`); **currency** (default the ledger's operating currency if available, optional — `currencies` may be empty like the web); **date** (DatePickerModal, default today).
4. Live-validate via t001; keep "Done" disabled until the composed name is valid. On submit call `openAccount`, show loading on the button/header, navigate back to the Accounts tab on success, and surface the error inline on failure.
5. `usePageView("open_account")` on mount; `SafeAreaView` spacing; theme tokens via `useTheme().colorTheme`; all strings via `useTranslations()`.

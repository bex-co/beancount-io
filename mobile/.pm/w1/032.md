# Merchants beyond parity — parked follow-ons from the 2026-08-19 research

Each is real value from the Monarch Merchants research that m35–m37 deliberately
do not attempt, parked on a named blocker:

- **Rename / merge merchants** — Monarch's merge is "rename into a name
  collision." For us a rename means rewriting the payee across ledger source
  files (the app can write files, but a multi-file text rewrite of production
  ledgers needs bean-check gating and its own design + owner sign-off).
  Cheap 80% first: display-only case-insensitive grouping in the directory
  ("Burger king" + "Burger King" as one row), which needs no writes.
- **Ledger-native persistence for recurring marks** — m37 stores overrides
  device-local. The beancount-idiomatic durable home is a
  `custom "recurring" "<payee>" "<cadence>"` directive (syncs everywhere,
  round-trips as plain text). Blocked on an owner decision about writing
  non-transaction directives from the app and the directive's shape.
- **Recurring calendar screen** — Monarch's month calendar with the
  paid / different-amount / upcoming / missed color language. Needs m37's
  forecast data to exist first, then a design pass; a list ships most of the
  value earlier.
- **Pre-charge reminders** ("expected in 3 days") — needs server-side push
  scheduling; nothing in the mobile schema supports it today.

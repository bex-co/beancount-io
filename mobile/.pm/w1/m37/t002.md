## Objective

Feed detection: one fixed `queryShell` statement returning per-payee `(date, currency, amount)` series for a trailing window, mapped by a pure selector into t001's input shape. m35's rollup (count/min/max) cannot drive detection — it lacks the full date series; this query exists for that.

## Context

- Window: trailing ~15 months (covers yearly cadence with margin) bounded in the statement (`date >= <cutoff>`), keeping the payload to two-ish columns × transactions — validate actual size against the dev ledger.
- Reuses the m35 `queryShell` document/hook — no new GraphQL surface; still fixed app-authored BQL only (`DO_NOT_DO.md:18` reconciliation in the m35 README).
- Statement shape to validate: dates and per-currency posting amounts grouped or raw per transaction for `payee != ''` within the window; pick the cheapest form the backend's dialect serializes cleanly, and record the final statement beside its definition.

## Steps

1. Author + validate the windowed statement read-only against the dev ledger.
2. `selectors/payee-series.ts`: rows → `Map<payee, Series>` via `types[]`-by-name mapping; tolerant of column reorder/nulls.
3. Wire into the merchants screen alongside the rollup query; run t001 detection per payee; tune the t001 thresholds against the real ledger's known subscriptions and note any changes in the outcome note.

# Feel the m21 write haptics on hardware — the one check a simulator can't do

`w1/m21` gave every ledger write a success/error haptic through `src/common/haptics.ts`. The intent→call mapping, the platform gate and the swallowed-rejection guard are unit-tested (`src/common/__tests__/haptics.test.ts`), and the confirmation branching is pinned in `src/common/__tests__/ledger-write.test.ts`. What no test and no simulator can establish is that the device actually buzzes, once, per write.

Walk these seven on a phone and confirm **one** success haptic each, a **distinct** error haptic on failure, and no double-fire:

| Path               | Where it fires                                                            |
| ------------------ | ------------------------------------------------------------------------- |
| Quick-add save     | `runLedgerWrite` (`src/common/ledger-write.ts`)                           |
| Split save         | same helper                                                               |
| Edit transaction   | same helper                                                               |
| Delete transaction | same helper                                                               |
| Budget save        | `add-budget-screen.tsx` — the only site that had a haptic before          |
| Open account       | `open-account-screen/use-open-account.ts`                                 |
| Ledger file save   | `ledger-file-editor-screen/index.tsx` (also create/delete in the browser) |

The failure branch is the easy one to get wrong: put the device in airplane mode mid-save and confirm the error haptic reads as _different_, not just quieter.

Everything else in `w1/m21/t006` was verified on the simulator — light/dark, reduce-motion, the receipt reveal end to end, and the save/delete return timing (frame 1 after the tap already shows the destination screen with the toast on it). See the verification log in `w1/done/m21/done/t006.md`.

Sub-hour. Not code — a walkthrough.

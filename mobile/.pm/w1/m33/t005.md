## Objective

Make the Sankey a well-behaved citizen of the app's state vocabulary: it follows the Reports screen's selected time range, first load shows a `LoadingTile` skeleton sized to the chart's exact line box (no shift when data lands), a range with no flows shows an honest empty state, and the chart draws in with the m20 motion tokens — never a spinner, never a blank.

## Context

- Range selection: `src/components/time-range-pills/` — reuse the Reports screen's existing range state; do not add a second range control.
- Skeleton conventions: `@/components/loading-tile`, mirrored layout, varied tile widths (see the board's standing skeleton rules in `mobile/CLAUDE.md`).
- Motion: `src/common/theme/motion.ts` + `motion-easing.ts` — compose `durations.*` and materialized easings; `w1/029` documents what drift looks like, don't add to it.
- Pull-to-refresh (if the Reports screen has it) keeps content visible; skeleton is first-load only.

## Steps

1. Wire the component to the screen's range state; refetch/reshape on change.
2. Skeleton state mirroring the chart's dimensions; background color set (dark-flicker rule).
3. Empty state: translated copy, not a blank SVG.
4. Draw-in on first data using motion tokens; respect reduce-motion.

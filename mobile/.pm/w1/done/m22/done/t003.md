## Objective

Delete `src/common/graphql/queries/homeCharts.graphql` and regenerate, dropping ~60 lines of generated code for an operation nothing calls.

## Context

- Nothing calls `useHomeChartsQuery`. `w1/m19` removed the last two references, where `HomeChartsDocument` sat in two screens' refetch arrays as a silent no-op.
- What still mentions it is **commentary, not usage**: `src/common/apollo/invalidate-ledger.ts:73-75` explains its deliberate absence from the invalidation set, and `src/screens/home-screen/selectors/select-spending-compare.ts:45` notes that `homeCharts` returns net profit rather than the gross expense figure the card wants. Both are worth keeping as rationale.
- Home's net-worth chart reads `getLedgerBalanceSheet`; the spending card reads `getLedgerJournal`.
- Repo rule: `src/generated-graphql/` is regenerated by `yarn codegen`, never hand-edited. The schema-side `homeCharts` field belongs to the server and stays either way.

## Steps

1. Confirm with the owner that nothing plans to use `homeCharts` — it returns a prebuilt chart payload that could suit a future Home card better than assembling one client-side.
2. Delete the `.graphql` file and run `yarn codegen`.
3. Review the generated diff: it should drop only `HomeChartsDocument`, `useHomeChartsQuery` and `HomeChartsResponse`.
4. Reword the two comments so they still read correctly once the operation is gone.

Deleted the `.graphql` file and ran `yarn codegen`.

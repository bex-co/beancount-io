## Objective

Clean up the global-callback return channel while the screen is open for surgery: delete registered callbacks when the picker unmounts, and give add-budget its own `SelectedBudgetAccount` key instead of piggybacking on the add-transaction `SelectedExpenses` key.

## Context

- Return channel: `src/common/globalFnFactory.ts` — callers `.setFn(cb)`, the picker calls `.getFn()?.(account)` then `router.back()`, and never `deleteFn()`s, so stale callbacks linger.
- `src/screens/add-budget-screen/add-budget-screen.tsx:209-217` reuses `SelectedExpenses`, which the add-transaction TO row also owns — a latent cross-screen bug.

## Steps

1. Add a `SelectedBudgetAccount` global fn and switch add-budget to it.
2. `deleteFn()` the relevant callback on picker unmount (after selection or back-navigation).
3. Re-test all four callers' selection round-trips.

## Files

- `src/common/globalFnFactory.ts`
- `src/screens/add-budget-screen/add-budget-screen.tsx`
- `src/screens/account-picker-screen/account-picker-screen.tsx`

## Acceptance criteria

- [ ] Backing out of the picker without selecting leaves no stale callback registered
- [ ] Add-budget account selection no longer shares a callback key with the add-transaction TO row
- [ ] All four picker callers still receive their selections

## Out of scope

- Replacing the global-fn pattern with navigation params or another mechanism

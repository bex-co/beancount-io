## Objective

Make a mismatched picker callback unrepresentable: one helper owns the key-to-type table, then the per-type keys collapse into a single `SelectedAccount`.

## Context

- Seven call sites across five screens repeat the same three steps: pick the matching global callback key, `setFn`, then `router.push` with `type` + `selectedItem`.
- Nothing enforces that the key a caller sets is the key the picker reads — a caller can set `SelectedAssets` while pushing `type: "expenses"`, and the pick silently does nothing.
- Per-key naming does not actually prevent collisions; the "setFn immediately before push" discipline does. `SelectedAssets`/`SelectedExpenses` are already shared between `add-transaction-next-screen` and `quick-add-accounts-selector`, both mountable at once.
- What makes one key safe: the picker captures its callback into a ref on mount and releases it on unmount.

## Steps

1. Add `pushAccountPicker(router, { type, current, onSelect })` owning the table lookup; migrate all seven call sites.
2. Then collapse to a single `SelectedAccount` key — a one-line internal change once the helper owns the lookup — deleting four exports.
3. Exercise every call site: a pick from each screen lands on the right field.

## Files

- The seven call sites across five screens, `src/screens/account-picker-screen/`, and the callback-key module

## Acceptance criteria

- [ ] No screen sets a callback key directly; all pushes go through the helper
- [ ] One `SelectedAccount` key; the four per-type exports are deleted
- [ ] A pick from each of the seven entry points lands on the correct field

## Objective

`app/(app)/(tabs)/_layout.tsx:56-114` renders each `tabBarIcon` as a static filled `<Ionicons size={28} color={focused ? theme.primary : color} />`. Colour is the only signal for the active tab, and focus produces no motion.

## Context

- Most iOS tab bars use the outline variant when inactive and the filled one when active, which reads at a glance and does not depend on hue — an accessibility win as much as a polish one.
- `src/components/haptic-tab/index.tsx` already fires a press haptic (iOS-only, `:14`); `w1/m21/t005` added `PressableScale` there, so the press response exists and this task adds the focus response.
- `83bddba` eliminated tab-switch flicker — do not regress it.
- **The original cost argument is void.** The note argued a spring on `focused` is free because `lazy: false` means all five tabs are already mounted. `w1/m22/t005` shipped on 2026-08-16 and tabs now mount on first focus, so the _first_ switch to a tab does real work — mount, query, skeleton. Measure the first switch to each tab, not the second, and if the spring competes with the mount, drive it from the tab bar (`haptic-tab`) rather than from the screen.

## Steps

1. Map each tab to its outline/filled Ionicons pair; render by `focused`.
2. Add a spring on focus using the `w1/m20/t001` tokens; confirm it is skipped under reduce-motion.
3. Verify in light and dark, and confirm tab-switch timing/flicker is unchanged.

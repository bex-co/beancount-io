## Objective

Tapping the create row routes through open-account and, on a successful write, delivers the new account to whatever form field opened the picker — then returns there, not to the picker.

## Context

- The picker registers its caller's callback via `SelectedAccount.setFn` in `pushAccountPicker` (`src/screens/account-picker-screen/push-account-picker.ts`); the picker captures it into a ref on mount and releases on unmount — the create path must not let it release before the open completes, or must re-deliver explicitly.
- `use-open-account.ts` already calls `invalidateLedgerData(client, "entries")` after the write, so account lists refresh without extra plumbing.
- Navigation: picker → open-account (prefilled) → pop **two** screens back to the form on success; cancel pops one, back to the picker with the query intact.

## Steps

1. From t001's row, push `/(app)/open-account` with the prefill param and a flag/param marking picker-origin.
2. On successful open from picker-origin, invoke the registered selection callback with the composed account name, then pop back to the calling form.
3. On cancel, return to the picker unchanged.
4. Verify the picker's own list shows the new account if the user navigates back into it (covered by the ledger-data invalidation).

## Files

## Acceptance criteria

- [ ] Zero-match query → create → save lands back on the form with the new account filled in.
- [ ] Cancel from open-account returns to the picker with the search text preserved.
- [ ] The written directive is a valid `open` (visible in the ledger file).

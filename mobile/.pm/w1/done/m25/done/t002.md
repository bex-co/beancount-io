## Objective

Let `/(app)/open-account` be pushed with an initial account name so the create row can hand over the typed query — root pre-selected, sub-path pre-filled, validation message already visible when the prefill is imperfect.

## Context

- Route: `app/(app)/open-account.tsx`; screen at `src/screens/open-account-screen/` (`open-account-screen.tsx`, `use-open-account.ts`, `account-name.ts`).
- `composeAccountName` joins a root prefix to a sub-path; the prefill must do the inverse split: match the typed string against `ACCOUNT_ROOT_PREFIXES`, seed the root selector, and put the remainder in the name field. A string with no valid root seeds the default root and the full string as sub-path, letting the existing validation speak.
- Params arrive via `useLocalSearchParams` (route params are strings).

## Steps

1. Add an optional `prefill` param to the route and thread it into the screen's initial state.
2. Implement the root/sub-path split against `ACCOUNT_ROOT_PREFIXES` (pure function beside `composeAccountName`, relative imports so jest-lite can require it).
3. Currency default stays whatever the screen already defaults to — prefill sets the name only.

## Files

- `app/(app)/open-account.tsx`
- `src/screens/open-account-screen/open-account-screen.tsx`
- `src/screens/open-account-screen/account-name.ts`

## Acceptance criteria

- [ ] Pushing the route with `prefill=Expenses:Coffee` shows root `Expenses`, sub-path `Coffee`.
- [ ] A rootless prefill (`coffee`) lands with the string in the name field and the normal validation state visible.
- [ ] No behavior change when the param is absent.

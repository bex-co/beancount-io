# Two components still bypass the motion token layer

Found during `w1/m20/t009`. `w1/m20` introduced `theme/motion.ts` +
`theme/motion-easing.ts`, and adoption is otherwise complete — every animated
surface checked (`loading-tile`, `progress`, `animated-amount`,
`time-range-pills`, the whole of `common/d3/`) composes `durations.*` and the
materialized easings. Two files do not:

- `src/components/picker/index.tsx:169,170,174,175` — `withTiming(x, { duration: 300 })` ×4, no easing token.
- `src/components/text-input-modal/index.tsx:134,135,137,138` — `{ duration: 200 }` ×2, `{ duration: 150 }` ×2.

Neither is pre-token legacy: both were last touched by `5ee2132` (2026-08-17),
which landed _after_ the tokens and after `29be482` had already migrated
`progress/index.tsx`. So the gap is real drift, not untouched history.

**Not fixed in t009 on purpose.** These files are outside `m20`'s blast radius,
and the nearest tokens are not equal to the current values — 300 → `base` (250),
200 → `fast` (150) — so adopting them changes how those two sheets feel by
~50ms. t009 was scoped behavior-preserving, and a duration change wants someone
to look at it, not to ride along in a cleanup.

Sub-hour: swap eight literals plus `easeStandard`, then look at both sheets.

---

**Done — 2026-09-07.** Exactly as prescribed: the picker's four `300`s became
`durations.base` (250), the text-input-modal's `200`/`150` pairs became
`durations.fast` (150), all six `withTiming` calls now carry
`easing: easeStandard`. Both sheets were opened and dismissed in the
simulator in light **and** dark: the picker slides to rest with the overlay
fade in step, the dialog scales/fades in cleanly, and nothing about either
sheet's layout or theming moved. The ~50–100ms tightening reads as intended —
the sheets feel like the rest of the app now. Motion-token adoption is
complete: no Reanimated `withTiming` in `src/` passes a literal duration
anymore (the one remaining `duration:` literal is `SplashScreen.setOptions`'
animation-off `{ fade: false, duration: 0 }`, which is native splash config,
not a transition).

## Objective

Walk the screens whose strings were English-only until this milestone, in the two locales that expand most (`de` and `fr`), and confirm nothing truncates, wraps badly, or overflows in light or dark.

## Context

- ~170 keys per locale landed at once; the ones at risk are those inside fixed-width controls: the reports range chips (`range1M`…`rangeAll`), the receipt-capture action row (`receiptTakePhoto`, `receiptChooseLibrary`, `receiptRetake`, `receiptUpload`), the multi-posting toolbar (`addPosting`, `remainderLabel`, `autoLabel`), the ledger editor's save/conflict buttons, and the open-account type/currency pickers.
- The receipt-capture flow (`/(app)/receipt-capture`) is the specific screen m27 was created to cover — this pass inherits that walk, including the m21 payoff moment (`receiptRevealTitle`, `receiptRevealHint`, `total`).
- Simulator driving is in `mobile/CLAUDE.md`: `xcrun simctl` for launch, deep links, screenshots, and `xcrun simctl ui $UDID appearance dark|light`.
- Locale is switched in-app from the ledger drawer (`currentLanguage`); `useTranslations()` re-renders on `localeVar`.

## Steps

1. Set the app to `de`, screenshot the reports tab (all range chips), Home cards, the multi-posting entry screen, the open-account form, the ledger editor with an unsaved-changes state, and the notifications sheet.
2. Repeat the same set in `fr`, then spot-check `ru` for the two budget messages carrying four interpolations.
3. Do one full pass of the receipt-capture flow in `de`, including the reveal state.
4. Repeat the highest-risk screens with `xcrun simctl ui $UDID appearance dark`.
5. Shorten any string that truncates rather than changing the layout; if a layout is genuinely too tight for every valid translation, file it as an inbox note instead of widening scope here.

## Files

- `src/translations/{de,fr,ru}.ts` (wording fixes only)

## Acceptance criteria

- [ ] Screenshots in light and dark, `de` and `fr`, of the reports range chips, receipt-capture action row and reveal, multi-posting toolbar, open-account form, and ledger editor.
- [ ] No truncated, clipped, or overlapping string in any of them.
- [ ] Any string shortened during the pass still reads naturally, and the integrity suite stays green.

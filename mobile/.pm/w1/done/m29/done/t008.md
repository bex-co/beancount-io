## Objective

Translate the 175 `en.ts` keys that `src/translations/pt.ts` currently inherits instead of declaring, so Portuguese users read the whole app in Portuguese, and delete `pt` from the `KNOWN_GAPS` baseline.

## Context

- `src/translations/pt.ts` — declares 143 of the base's 318 top-level keys today.
- `src/translations/en.ts` — the source of truth; translate against the English **value**, and read the surrounding `//` group comments for the screen each key belongs to.
- The missing set is dominated by everything shipped since the last translation sweep: multi-posting entry, open-account, the journal's directive types, the reports/dashboard cards and range chips, transaction edit/delete, AI receipt capture, notifications and commit detail, the ledger file list and editor, and budgets.
- Largest gap of the six. Follow the variant the existing file already uses rather than mixing European and Brazilian forms.
- The gate from t001/t002 is live: adding a key that `en` does not have, or dropping a `{{token}}`, fails `yarn test:unit`.

## Steps

1. Run the integrity suite to get the exact missing list for `pt`.
2. Translate each key, keeping it in the same order and under the same `//` group comment as `en.ts` so the two files stay diffable side by side.
3. Preserve every `{{token}}` and match the English string's register — button labels stay short enough for the control they sit in.
4. Reuse the terminology already established in this file (account types, "ledger", "transaction", "budget") rather than introducing a second word for a term the file already translates.
5. Remove the `pt` entry from `KNOWN_GAPS`.
6. `yarn lint` / `yarn typecheck` / `yarn test:unit`.

## Files

- `src/translations/pt.ts`
- `src/translations/__tests__/known-gaps.ts`

## Acceptance criteria

- [ ] `pt` declares all 318 top-level keys of `en.ts`; the integrity suite reports `missing: []` for it.
- [ ] `pt` no longer appears in `KNOWN_GAPS`.
- [ ] No value is a byte-identical copy of the English string except where the English text is the correct output in Portuguese (a proper noun, a Beancount account literal, or a symbol) — those go in `INTENTIONALLY_UNTRANSLATED` with a reason.
- [ ] Every `{{token}}` from the English value survives in the translation.
- [ ] `yarn test:unit` green.

## Out of scope

- Other locales (their own tasks).
- Rendering the new strings on screen — t009 walks them.
- Editing `en.ts`; if an English string reads wrong, note it rather than fixing it here.

## Objective

Extend the integrity gate so a translation cannot silently drop or invent an `i18n-js` interpolation token. Land it before any bulk translation work, so all ~2051 new strings are guarded from the first one written.

## Context

- `en.ts` uses `{{account}}`, `{{amount}}`, `{{count}}`, `{{date}}`, `{{interval}}`, `{{name}}` across 11 values — e.g. `budgetDeleteMessage`, which interpolates four of them in one sentence.
- A dropped token renders a sentence with a hole; an invented token renders the literal `{{foo}}` to the user. Neither is caught by key parity.
- The check applies to **declared** keys only, so it is green today and stays green as each locale task lands.
- Same runner constraints as t001 (relative imports; limited matcher set).

## Steps

1. Add a value extractor to `locale-parity.ts` that, for a given locale file, returns the raw source text of each declared key's value (single-line and multi-line, template and quoted).
2. Collect `{{token}}` occurrences from the `en` value and from the locale value; compare as **sets** — order and repetition differ legitimately across languages, presence does not.
3. Assert per locale: no token present in `en` is absent from the translation, and no token appears in the translation that `en` does not have.
4. Add the failure to `locale-integrity.test.ts` as its own `it()` per locale so the message names the offending key.
5. Verify by hand-editing one `zh` budget string to drop `{{amount}}` — the suite must go red — then revert.

## Files

## Acceptance criteria

- [ ] `yarn test:unit` green on the unmodified tree.
- [ ] Dropping `{{amount}}` from a declared translation turns the suite red naming key and locale.
- [ ] Adding `{{bogus}}` to a declared translation turns the suite red.
- [ ] Multi-line values (template literals and Prettier-wrapped strings) are read correctly — verified against `budgetDeleteMessage` and `budgetAccountHelp` in `zh`.

## Out of scope

- Checking that a translation is not a byte-identical English copy — m30/t007.
- Plural-form correctness; `i18n-js` pluralization is not used in this file set.

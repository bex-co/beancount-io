## Objective

The gate is now the only thing standing between a merged feature and thirteen silently-English screens, so prove it actually fires. Test the checker against synthetic locale fixtures, not against the real files — a checker that quietly matches nothing passes just as green as one that works.

## Context

- `src/translations/__tests__/locale-parity.ts` — the extractor and `localeKeyReport()` under test.
- Real-file assertions cannot prove a negative: with the tree correct, a broken extractor returning `[]` for everything looks identical to a working one. This is the exact failure `minKeys` was guarding against in `budget-parity`.
- Runner constraints: relative imports for value modules; matchers limited to `toBe` / `toEqual` / `toBeCloseTo` / `toBeTruthy` / `toBeFalsy` / `toThrow` and `.not`. Assert on returned arrays with `toEqual`.
- Prefer pure functions over temp files: have the extractor take source **text**, so fixtures are string literals in the test and no `fs` write is needed.

## Steps

1. Refactor (if t001 did not already) so key extraction and the report take a source string, with the file read at the call site.
2. Fixture cases for the extractor: a key inside a multi-line string value is **not** counted; a nested object's inner keys are not counted as top-level; a Prettier-wrapped value is read whole; `...en` is detected.
3. Fixture cases for the report: a missing key appears in `missing`; an unknown key appears in `extra`; a twice-declared key appears in `duplicated`; a correct file yields all three empty.
4. Fixture cases for token parity: dropped token, invented token, reordered tokens (must pass), repeated token (must pass).
5. One case asserting the baseline is compared by equality — a `KNOWN_GAPS` entry for a key that is now translated must fail.
6. `yarn test:unit`.

## Acceptance criteria

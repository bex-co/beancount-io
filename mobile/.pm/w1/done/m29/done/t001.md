## Objective

Replace prefix-by-prefix translation parity with one whole-file gate: for every non-English locale file, every top-level key of `en.ts` must be explicitly declared, no key may be declared that `en.ts` does not have, and no key may be declared twice. Land it green against today's tree by recording the current gap in an explicit, shrinking `KNOWN_GAPS` baseline, so the suite fails the moment a _new_ gap appears.

## Context

- `src/translations/en.ts` — the base, 318 top-level keys as of 2026-08-17.
- `src/translations/{zh,bg,ca,de,es,fa,fr,nl,pt,ru,sk,uk}.ts` — each is `export const <locale> = { ...en, <overrides> };`, which is why a missing key is invisible at runtime and must be checked at the **source** level.
- `src/translations/__tests__/locale-parity.ts` — existing helper: `translationLocales()` derives the locale list from the directory, `localeSource()` reads a file, `expectLocaleParity(prefix)` checks one prefix. Extend this file; keep `translationLocales()` as the single source of the locale list.
- `src/translations/__tests__/{account-picker,budget}-parity.test.ts` — the two current callers. Leave them alone here; t010 retires them.
- Runner: `scripts/jest-lite-runner.js`. No `@/` alias for value modules — use relative imports. Matchers available: `toBe`, `toEqual`, `toBeCloseTo`, `toBeTruthy`, `toBeFalsy`, `toThrow`, and `.not`.

## Steps

1. In `locale-parity.ts`, add a top-level key extractor that reads a locale file and returns its declared keys **in order**. Anchor on the two-space top-level indent (`/^ {2}([A-Za-z0-9_]+):/gm`) rather than `^\s*`, so a key-like line inside a multi-line string value cannot be counted — the current `expectLocaleParity` regex has that hole.
2. Export `localeKeyReport(locale)` returning `{ declared, missing, extra, duplicated }` computed against `Object.keys(en)`.
3. Add `known-gaps.ts` next to it: `INTENTIONALLY_UNTRANSLATED` (permanent, per-key, each entry carrying a one-line reason — seed it with `budgetAccountPlaceholder`, a literal Beancount account name, and check `tes: "1"`, which looks like a stray key rather than copy) and `KNOWN_GAPS` (temporary, `Record<locale, string[]>`, the exact keys each locale has not translated yet).
4. Add `locale-integrity.test.ts`: per locale, assert `missing` **equals** that locale's `KNOWN_GAPS` entry (equality, not subset — a stale baseline entry must fail too), `extra` equals `[]`, and `duplicated` equals `[]`.
5. Assert once that every locale file still contains the `...en` spread, so nobody can satisfy the gate by dropping the runtime fallback.
6. Generate the initial `KNOWN_GAPS` from the tree, run `yarn test:unit`, and confirm the suite is green with the recorded baseline and red when a key is hand-removed from any locale.

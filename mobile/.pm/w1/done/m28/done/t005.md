## Objective

A deep link that looks like a route but isn't one — `beancount:///(app)/(tabs)/index` — must land on a recoverable not-found screen, not a black screen with no tab bar and no way back.

## Context

- Reproduction and prior analysis in the source note `w1/026` (found 2026-08-16, pre-existing — confirmed unrelated to m22's `lazy` flip by stashing `app/(app)/(tabs)/_layout.tsx`).
- `app/+not-found.tsx` exists at the root and is **not** what renders. First establish whether Expo Router resolves `+not-found` from inside nested groups at all, or only at the level it is declared — that determines whether the fix is a nested `+not-found` inside `(app)`/`(tabs)` or something in the tab layout.
- Verify with the simulator deep-link loop from `mobile/CLAUDE.md` (`xcrun simctl openurl`); read-only, no ledger writes.

## Steps

1. Reproduce; then test `+not-found` resolution at each nesting level (root, `(app)`, `(tabs)`).
2. Apply the smallest fix that catches unmatched paths inside the authenticated group; ensure the screen offers a way back (link to Home) and renders with theme tokens + `SafeAreaView`.
3. Sweep the other groups (`auth/`) for the same hole; fix or file, don't ignore.
4. Confirm every real route still resolves (`/(app)/(tabs)/`, `/accounts`, `/reports`, `/transactions`, modals).

## Outcome 2026-08-18 — it was never a routing failure

Expo Router already resolved `+not-found` for every unmatched path tried
(`/(app)/(tabs)/index`, `/(app)/(tabs)/nope`, `/(app)/bogus`, `/totally-wrong`,
`/auth/nope` — byte-identical renders), so no nested `+not-found` and no tab
layout change was needed. The black screen was a **contrast** defect: the screen
set no background and no text color, so in dark mode the platform painted black
behind it and React Native's default black text sat on top. Light mode always
showed the text, which is why the report and the reproduction disagreed.

Fixed by theming the screen (background, title, body from tokens), adding
`SafeAreaView`, translating the copy into all 13 locales, and replacing the
"Go to Welcome" link — wrong for a signed-in user — with a Home button using
`replace`, since nothing sensible sits behind a route that matched nothing.
Verified: readable in both themes, and the button returns to Home with no
relaunch.

The sweep found the same defect class had exactly one other candidate, the
`FlexCenter` primitive that caused it — `flex: 1` centering with no background.
This fix removed its last call site, so it was deleted rather than left as a
discoverable trap for the next screen.

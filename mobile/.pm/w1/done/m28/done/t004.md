## Objective

Every card tap-through emits one consistently-shaped event carrying a card identifier, so the funnel is comparable across cards.

## Context

- Existing per-card events are ad hoc: `tap_see_all_transactions` (recent-transactions:68), `budget_panel_see_all` (budget:77). New doors should emit `home_card_tap` with a `card` property; keep the two legacy event names firing alongside for continuity (they have history) rather than renaming.
- `analytics.track` no-ops under `__DEV__` — prove single-fire structurally, not in the simulator.

## Steps

1. Emit `home_card_tap { card }` from the shared t001 affordance so no card can forget it.
2. Identifiers: `spending`, `liabilities`, `recent_transactions`, `budget`.

## Files

- `src/components/dashboard-card/index.tsx` (single emission point)
- The four card components (identifier wiring)

## Acceptance criteria

- [ ] One event shape, four identifiers, emitted from exactly one code path.
- [ ] Legacy events still fire where they did.

## Outcome 2026-08-18 — one identifier renamed

Shipped as `home_card_tap { card }` from a single code path, with the legacy
`tap_see_all_transactions` and `budget_panel_see_all` still firing from inside
each card's own handler.

**Deviation from the spec'd identifier list:** `liabilities` → `accounts`. That
id names the account-charts card, whose pager covers net worth, assets _and_
liabilities and which opens on net worth; its door goes to `/accounts`, and no
liabilities-filtered route exists. Shipping `liabilities` would have told every
future funnel that people engage with liabilities specifically when mostly they
do not — and event taxonomies are expensive to rename once dashboards read them.
`accounts` names the destination, consistent with how `spending` and `budget`
read. Per-tab attribution already exists on `home_chart_page`.

The emission also moved one layer up from where this task placed it: it lives in
`HomeDashboardCard` (`src/screens/home-screen/components/`) rather than in the
shared `DashboardCard`, which Reports, Budget, the feed and `balance-chart-card`
also render. Typing a cross-screen component's prop as `HomeCardId` would have
forced the next non-Home "see all" to lie, widen a Home-named union, or
hand-roll a lookalike — which `budget-group-card.tsx` already does. Still
exactly one emission point, still impossible for a Home card to forget.

## Out of scope

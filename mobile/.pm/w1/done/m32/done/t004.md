## Objective

The native chat screen: a message list rendering user/assistant turns with streaming text, a bottom input bar, and a typing indicator while a turn is in flight — mounted as a stack screen (full-screen push, not a sheet or a tab).

## Context

- Screen at `src/screens/agent-screen/`, route at `app/(app)/agent.tsx` — same stack pattern as `notifications.tsx` / `settings.tsx`.
- Theme tokens via `useTheme()` only; strings via `useTranslations()`; `SafeAreaView` spacing; analytics track on mount (dev builds no-op `analytics.track`, so verify structurally).
- Assistant text is markdown-ish — render text parts plainly first; ignore unknown part types safely (tool parts get dedicated handling in t006).
- Auto-scroll pinned to bottom while streaming, released when the user scrolls up (dashboard `page.tsx` has the pattern).

## Steps

1. Build `agent-screen.tsx` (list + bubbles + input + indicator) on `use-agent-chat`.
2. Add the route file; register the screen title/back affordance consistently with sibling stack screens.
3. Declare all new keys in `en.ts`; translate or add named `KNOWN_GAPS` entries.

## Files

- `src/screens/agent-screen/agent-screen.tsx` (+ small components as needed)
- `app/(app)/agent.tsx`
- `src/translations/en.ts` + locale files

## Out of scope

## Outcome — done 2026-08-19

`src/screens/agent-screen/` + `app/(app)/agent.tsx`, registered in `app/(app)/_layout.tsx`. Message list, bottom input bar that grows to three lines, typing indicator, tail-following that releases when the user scrolls up, `LedgerGuard`, `usePageView("agent")`, theme tokens throughout.

**Markdown had to be handled, not deferred.** The plan said render text parts plainly; the first real answer on device came back as `- **Cash/Assets**: 906.58 USD` and put literal asterisks next to the user's money. `markdown-lite.ts` now reads the three things the agent actually emits — bold, bullets, headings — plus the notation it wraps arithmetic in: LaTeX (`\text{…}`, display brackets, `\,` thin spaces), markdown backslash escapes, and code spans/fences. Each of those was found by looking at a real answer, not by reading a spec; each has a test naming the string that prompted it. No new dependency: a markdown engine is a lot of surface for one bold span.

`message-text.ts` holds the pure part-joining so the unit runner can reach it — it cannot load a module that imports React Native. Multiple text parts mean multiple agent steps, so they join as paragraphs; joined with nothing they read as `Let me try again.It seems…`.

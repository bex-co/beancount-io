## Objective

Until approval cards ship (ADR002 P2), a turn that reaches an approval-gated write tool (ledger edit, receipt insert) must end in a clear, translated notice — "reviewing and approving changes isn't on mobile yet; continue on the web" — never a silent hang, and never a write.

## Context

- The stream pauses with a tool part in `approval-requested` state (`isToolUIPart(part) && part.state === "approval-requested"` — see the dashboard's `isAwaitingApproval` in `page.tsx`). Mobile sends **no** approval response, so the tool never executes: the anti-goal "AI proposes, the user confirms" holds absolutely in this milestone.
- This is also the ADR002 security posture: the approval mechanism's integrity depends on rendering the real diff, which is exactly the P2 work being deferred — so v1 refuses rather than approximates.

## Steps

1. Detect the awaiting-approval state in the hook/screen.
2. Render the notice card in place of the input bar (input returns on New chat).
3. Unknown/other tool part types render as a compact "working…" activity line, not raw JSON.

## Files

- `src/screens/agent-screen/` (screen + hook)
- `src/translations/en.ts` + locale files

## Acceptance criteria

- [ ] A prompt like "add a $5 coffee expense" ends at the notice; the ledger is untouched (verify via the Files tab).
- [ ] The notice is translated (or `KNOWN_GAPS`-named) and themed in light/dark.
- [ ] Conversation remains recoverable via New chat.

## Out of scope

- Approval cards with diff rendering (ADR002 P2); any approval response from mobile.

## Outcome — done 2026-08-19

**Verified live, and the ledger proves it.** Asked the agent to append a transaction to `main.bean`. It read the file, announced _"Proceeding with this operation"_, and the `editLedgerFiles` tool entered `approval-requested`. The app then showed _"Approve this on the web — This change needs your review before it touches your ledger, and the app can't show you the full diff yet"_ and **removed the input bar**, so the turn cannot be continued from the phone.

The ledger's change history was captured before and after: the same eight commits in the same order, `c7b4b71` still latest, ledger healthy. **No commit, despite the agent saying it was proceeding.** That gap between what the model announces and what actually happens is the whole reason the guard renders something rather than trusting the prose.

Nothing on this path can write, by construction: `sendAutomaticallyWhen` is never passed to `useChat`, and `addToolApprovalResponse` is never called. Tests assert both absences, and the source-scanning helper strips comments first — an earlier version of that test was satisfied by a _comment_ mentioning the setting.

**Reaching the state took two attempts**, which is itself worth recording: a vague "add a $5 coffee" sent the agent exploring and it exhausted its ten steps on reads before ever proposing an edit. Only a request naming the file got to the approval. The first attempt is what surfaced the silent-turn defect now handled in t005.

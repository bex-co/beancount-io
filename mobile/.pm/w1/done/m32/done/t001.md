## Objective

Prove the two integration assumptions everything else stands on — the agent route accepts the mobile Bearer token (no cookie), and the response streams as an AI SDK UIMessage SSE stream — before writing any UI. This is ADR002's P0 gate: if it fails, the milestone halts here and the finding goes back to the note.

## Context

- Endpoint: `POST /api-gateway/agent` on the same base `getEndpoint()` already builds (`src/common/request.ts`); body `{ messages: UIMessage[], ledgerId, sessionId? }`.
- The mobile session token is the one the Apollo client already sends as `Authorization: Bearer` (`src/common/apollo/client.ts`).
- **The dev environment talks to production** (`mobile/CLAUDE.md`): use a strictly read-only question ("what is my net worth?") — nothing that could trigger a write tool.

## Steps

1. Obtain the signed-in dev session's token (e.g. a temporary dev-only log in the Apollo auth link; remove it after).
2. `curl -N` the route with the Bearer header and a minimal one-message UIMessage payload for a read-only question against the selected ledger.
3. Confirm: SSE chunks in the UIMessage stream format arrive and terminate; the same request without the header returns 401/403.
4. Save a redacted stream sample under `tmp/` (gitignored) as the fixture reference for t010's tests.

## Outcome — passed 2026-08-19

**The gate is green: the Bearer token alone authenticates, and the response really streams through `expo/fetch`.** Run against `https://beancount.io/api-gateway/agent` from the dev build on the booted simulator, ledger `puncsky/example`, with read-only prompts only.

Run in-app rather than with `curl`, on purpose. `curl` would have proved the server accepts a Bearer token; it would not have proved that **`expo/fetch` streams on device**, which is the assumption t003 actually depends on. A temporary module wired into the root layout ran the cases inside the app runtime and wrote results to AsyncStorage, which is readable from the simulator container without a console. Both the module and the layout edit are reverted; the two AsyncStorage keys were purged and the app relaunched clean (`git status` clean, Home renders, still signed in).

Four cases, which together separate the two credentials:

| case                                 |                result | meaning                                   |
| ------------------------------------ | --------------------: | ----------------------------------------- |
| Bearer header, `credentials: "omit"` | **200** SSE, 7 chunks | **the gate** — Bearer alone is sufficient |
| `Bearer not-a-real-token`            |               **401** | the header is read and takes priority     |
| no header, cookies allowed           |           **200** SSE | an ambient cookie also authenticates      |
| no header, `credentials: "omit"`     |               **401** | correct baseline                          |

**The finding worth carrying forward: `expo/fetch` shares the native cookie store.** The first round's negative control (no header, cookies allowed) returned 200 and streamed a real answer — not because auth was skipped, but because the app already holds a beancount.io session cookie in NSURLSession's shared jar. That is not a vulnerability (it is the user's own session), but it means a client that forgot the `Authorization` header would still appear to work on device and then fail later in ways that are hard to attribute — a stale cookie, a fresh install, a different simulator. Rows 3 and 4 differ _only_ by `credentials: "omit"`, which is also what proves `expo/fetch` honors the flag.

**Consequence for t003:** the transport sets `credentials: "omit"` so the Bearer token is the only credential in play. Deterministic, and it matches what ADR002 designed.

**Stream shape confirmed** (AI SDK v5 UI message stream, `text/event-stream`): `{"type":"start"}` → `{"type":"start-step"}` → for tool turns `tool-input-start` / `tool-input-delta` (observed `runBqlQuery` on "What is my net worth?") → `{"type":"text-delta","id":"msg_…","delta":"…"}`. Chunks arrive incrementally (7 and 13 across cases, first byte in 838ms), so this is genuine streaming, not a buffered response. `terminated: false` on the 200s is the reader being cancelled at the capture cap, not the stream ending early; the 401s terminated naturally.

**Error envelope**, which t005 needs for classifying failures: `application/json`, body `{"ok":false,"error":{"code":"UNAUTHENTICATED","message":"Invalid or expired token"}}`. So errors are a JSON envelope with a machine-readable `code`, not an SSE frame — the quota case should surface as its own code on the same shape.

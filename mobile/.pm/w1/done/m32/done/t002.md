## Objective

Add the two AI SDK packages the transport and screen build on. **This task adds new dependencies** (repo rule: ask the user before adding dependencies) — the decision record is `docs/ADR002-mobile-ai-assistant.md` (alternatives rejected there: hand-rolled SSE parser, WebView, non-streaming GraphQL), and promoting this milestone is the owner's go-ahead.

## Context

- Version-match the dashboard's majors (`dashboard/package.json`: `ai` ^6, `@ai-sdk/react` ^3) so both clients track the same UIMessage protocol.
- `mobile/` pins **Yarn 1 (Classic)**; run from inside `mobile/`. Known gotcha: `yarn add` can hit the Yarn 1 invariant error — the workaround is editing `package.json` then plain `yarn install`. Never hand-edit `yarn.lock`.

## Steps

1. Add `ai` and `@ai-sdk/react` at the dashboard-matching majors.
2. Verify Metro resolves both (`yarn start` boots) and `yarn typecheck` passes.

## Files

- `package.json`, `yarn.lock` (generated)

## Acceptance criteria

- [ ] Both packages installed at dashboard-matching majors; lockfile regenerated by Yarn, not by hand.
- [ ] `yarn typecheck` and a Metro boot succeed.

## Out of scope

- Any usage of the packages (t003).

## Outcome — done 2026-08-19

`ai@6.0.258` and `@ai-sdk/react@3.0.261` installed — the **dashboard's majors**, deliberately not the newest. npm's latest are `ai@7` / `@ai-sdk/react@4`, but the stream is _produced_ by the backend on `ai@6.0.134` and consumed by the dashboard on `ai@6.0.185` + `@ai-sdk/react@3.0.187`. Taking v7 would have put mobile on a different protocol generation from the service it talks to. React 19.2.3 satisfies the peer range (`^18 || ~19.0.1 || ~19.1.2 || ^19.2.1`).

`yarn install` resolved cleanly — the Yarn 1 add-invariant workaround was not needed; only `package.json` was hand-edited and Yarn regenerated the lockfile. `yarn typecheck` green.

**The one snag was Metro, not the packages.** The first bundle after installing failed with `Unable to resolve module ./trace/internal/utils from @opentelemetry/api` (a transitive dep of `ai`) — a file that exists on disk. The running Metro predated the install, so its resolver cache had no knowledge of the new tree. Restarting with `npx expo start --clear` fixed it, and the app bundled 3124 modules. Worth remembering: after adding a dependency here, restart Metro before believing a resolution error.

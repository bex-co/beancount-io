## Objective

A `useAgentChat` hook that speaks to `POST /api-gateway/agent` exactly as the dashboard client does, with mobile auth: `useChat` + `DefaultChatTransport`, streaming via `expo/fetch`, `Authorization: Bearer` from the session, `Accept-Language` from the active locale, body `{ ledgerId, sessionId }`.

## Context

- Reference client: `dashboard/src/features/ai-agent/pages/agent/page.tsx` (transport shape, welcome message seeding).
- Token: same source the Apollo client reads (`src/common/apollo/client.ts`); ledger: the selected-ledger reactive var; locale: `localeVar` (`src/common/vars`).
- `sessionId`: generated per app session, held in memory (client-held history per ADR002 — no AsyncStorage), regenerated by New chat (t005).
- Streaming fetch: `import { fetch as expoFetch } from "expo/fetch"`.
- Do not log or report the `Authorization` header (Sentry breadcrumbs included) — ADR002 security note.

## Steps

1. Create `src/screens/agent-screen/use-agent-chat.ts` wrapping `useChat` with the transport above.
2. Seed the welcome assistant message from translations; expose `messages`, `sendMessage`, `status`, `stop`, `error`, and a session-reset function.
3. Map 401/403 to the app's existing signed-out handling; other failures surface through `error` for t005's UI.

## Files

## Outcome — done 2026-08-19

`src/screens/agent-screen/use-agent-chat.ts` — `useChat` + `DefaultChatTransport` against `getEndpoint("api-gateway/agent")`, `fetch` supplied by `expo/fetch`, `Authorization: Bearer` and `Accept-Language` resolved per request through refs so a locale change cannot rebuild the transport mid-stream, body `{ ledgerId, sessionId }`.

**`credentials: "omit"` is the load-bearing line.** t001 proved on device that `expo/fetch` shares the native cookie store and the route accepts that cookie, so a client that lost its `Authorization` header would still appear to work — until the cookie expired, somewhere else, later. Omitting cookies makes the Bearer token the only credential and failures honest.

The hook also owns the session id (in memory, per ADR002 — no AsyncStorage for chat state) and exposes `startNewChat`, which stops any in-flight stream before minting a new id; without the stop, the previous turn kept streaming into the fresh thread.

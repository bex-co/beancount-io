## Outcome — done 2026-08-19

Walked on the booted simulator in light and dark, in English and Persian, driven headlessly (`simctl` + `expo-mcp`) with read-only prompts.

**The walk found six defects, all fixed:**

1. Markdown rendered raw — `**Cash/Assets**` with literal asterisks (t004).
2. LaTeX in answers — `\[ \text{Net Worth} = … \]` and `2,754.06\, USD`, the model showing its arithmetic.
3. Code spans and fences left their backticks around account names.
4. **Persian: the bullet marker sat flush against the word.** The gap lived in a `"• "` string, and a trailing space collapses once the row mirrors. Moved into the layout (`gap` on the bullet row), which is direction-aware for free.
5. Consecutive agent steps ran together — `Let me try again.It seems…`.
6. A turn that ran tools and said nothing rendered as silence (fixed in t005).

**Verified:** both themes across empty, streaming, stopped, error, approval and no-answer states; the Home card; the deep link; `fa` walked right-to-left with the header, bubbles, input bar and chips all mirroring, Latin ledger data still aligned leading via m31's `LEADING_TEXT_ALIGN` — no `isRTL` branch on `textAlign`, which is the double-flip m31 documented. All 18 new keys ship in thirteen locales with `KNOWN_GAPS` untouched.

**Not verified, and not claimed:** Android (everything here was iOS); haptics (no Taptic Engine in a simulator); analytics (`analytics.track` returns early under `__DEV__`, so `usePageView("agent")` and the entry-surface property are structural only); and typing into the input by hand — the automation exposes taps but no text entry, so every message this milestone sent went through a preset chip or a `?q=` prefill. The keyboard-avoiding behaviour was checked by layout, not by a real keyboard.

One dev-only artifact cost time and is worth noting: the LogBox warning toast covers the input bar at the bottom of the screen, which reads as a missing input until dismissed. It does not exist in a release build.

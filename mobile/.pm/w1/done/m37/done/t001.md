## Objective

The greenfield core: a pure function from a per-payee series of `(date, currency, amount)` to a verdict — `{ cadence, typicalAmountByCurrency, isApproximate, nextExpected, isOverdue } | null`. This defines the input contract t002 fetches against.

## Context

- No recurring concept exists anywhere in the schema or client — this file is the concept.
- Proposed heuristics (tune against real series in t002): eligibility ≥ 3 transactions; cadence = median gap between consecutive dates classified into bands — weekly 6–8d, biweekly 13–16d, monthly/every-4-weeks 27–32d, quarterly 84–98d, yearly 350–380d; accept only if gap dispersion (MAD/median) < ~0.25; typical amount = median per currency, `isApproximate` when spread > ~10%; `nextExpected` = last date + median gap; `isOverdue` past a grace window (~1/4 of the cadence). "Today" is an explicit parameter — never read the clock inside the selector.
- Repo conventions: relative imports only (jest-lite), no `@/` value imports; income/expense is not asked or stored — it falls out of the postings.

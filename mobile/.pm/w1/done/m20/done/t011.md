## Objective

The sliding selection indicator this milestone added in t006 renders to the **right of "ALL"**, half off the row, instead of under the selected pill — and no label renders in `labelActive`, so the row reads as having no selection at all. Land the indicator under the selected pill in both themes.

## Context

- `src/components/time-range-pills/index.tsx` — the indicator is `position: absolute` as the row's **first child** with no `left`, so its static position is whatever Yoga gives an absolute child inside a `justifyContent: "center"` row; `translateX: layout.x` is then added on top of that offset rather than from the row's content origin.
- `moveTo` (:97-119) sets `x` from `event.nativeEvent.layout.x`, which is relative to the row — so the measurement is right and the origin is wrong.
- Reproduced on the Home net-worth chart, iPhone 17 Pro simulator, light theme, in both Expo Go and the dev build. Confirmed **pre-existing to m21** by stashing that working tree and re-screenshotting.
- Consumers: Home net-worth carousel, Reports, account detail, budget — a single component, so one fix covers all four.

## Steps

1. Pin `left: 0` on `styles.indicator` (or measure from the row's content origin) so the transform starts from a known point.
2. Confirm the selected pill's label renders in `labelActive`.
3. Verify with a `LayoutChangeEvent`-driven check in light **and** dark, and at one long-label locale, since the widths are measured rather than assumed.

## Files

- `src/components/time-range-pills/index.tsx`

## Acceptance criteria

- [ ] The indicator sits under the selected pill on first paint and after a range change, on every screen that uses the component
- [ ] The selected label renders in the active style
- [ ] Verified in light and dark

## Out of scope

## Outcome

Shipped as `d668411` — _"anchor the time-range pill indicator to the row's left edge"_ — taking step 1's first option: `left: 0` on `styles.indicator`, with the reason written into the style so nobody removes it as redundant. Without a horizontal inset Yoga falls back to the static position, which in a `justifyContent: "center"` row is the row's centre, and the measured `translateX` was being added to that centred origin.

The board entry outlived the fix; closed 2026-08-17 after re-verifying during `w1/m24`, which generalized this same component (`m24/t004`) and so exercised the indicator on every path:

- **Under the selected pill on first paint** — Home net-worth carousel, light theme: the fill sits under "6M", not beside "ALL".
- **After a change** — account picker, dark theme: tapping "Liabilities" slides the indicator under it; tapping "Expenses" slides it back.
- **Active label renders** — "6M" and "Liabilities" both paint in `labelActive`, so the row reads as having a selection.
- **Both themes** — verified light and dark on the iPhone 17 Pro simulator.

The long-label locale check in step 3 was not run as a separate pass; `m24/t006` established that the only translated label in these rows is the picker's "All" (longest form "Всички"/"Všetky", 7 characters), and the widths are measured via `onLayout` rather than assumed, which is the property that check was guarding.

`m24/t004` later added `scrollable` to this component and kept the same origin invariant: the indicator is absolute against the `ScrollView`'s content container, so the `onLayout` x it reads and the origin it paints from remain the same box.

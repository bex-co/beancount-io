## Outcome 2026-08-18

Run as a four-angle pass (reuse / simplification / efficiency / altitude) over the
current state of the m20 files, minus `interactive-line-chart.tsx` and `scrub.ts`
which `w1/m26/t006` had already simplified.

**Applied**

- **`chart-chrome.tsx` (new)** — the furniture every chart repeated: the
  `ErrorBoundary fallback={null}` wrapper (4 identical copies, zero variation),
  the not-enough-data placeholder, the legend row and item, the styles factory
  (byte-identical between the two scrollable charts) and the shared layout
  constants. The two scrollable charts lost ~130 lines between them.
- **`restingBarRect` in `bar-geometry.ts`** — the resting counterpart to
  `barRectAt`, which only ever knew how to interpolate a rect someone else had
  computed. All three bar charts derived it themselves in three different
  shapes. **This also fixed a latent defect:** `bar-chart-d3`'s version returned
  a _negative_ height for a near-zero negative value (`barHeight = -minHeight`),
  which SVG declines to draw. Unreachable with today's data (that chart is fed
  expense magnitudes) but wrong.
- **`bar-chart-d3.tsx`** — hoisted the loop-invariant `yScale(0)` out of the
  per-bar map (the two sibling charts already did this), dropped a
  commented-out `backgroundColor: "blue"` debug prop and three comments that
  restated the line under them.
- **`budget-bar-chart-d3.tsx`** — dropped a no-op `Math.max(zeroY, 0)`; `zeroY`
  is a pixel coordinate in a positive range and can never be negative, so the
  clamp only invited a future reader to think it could.
- **`use-reduce-motion.ts`** — its "staggered reveals we schedule ourselves"
  bullet reads as covering the bar-chart stagger, which would lead someone to
  wire this hook into a chart that must not have it. Narrowed, with a pointer to
  the test that proves the stagger already lands correctly under reduce-motion.

**Rejected, with reasons**

- **Delete `easeAccelerate` (0 consumers).** Kept. `durations.instant` also has
  zero consumers and nobody proposes deleting that: these are documented
  complete scales, and dropping the one member covering exits means the first
  exit animation hand-rolls a bezier — exactly what the token layer exists to
  prevent.
- **Memoize the chart props / add `useMemo`.** The efficiency pass confirmed the
  bar is already met: no d3 or geometry runs in a worklet, animated-node count
  is one `AnimatedRect` per bar (the minimum, since each carries different
  geometry) on one shared progress value per chart, and worklets capture only
  primitives. Nothing downstream is memoized, so a memo here would stabilize
  nothing.

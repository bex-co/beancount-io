## Objective

Make the three bar charts grow out of their zero baseline with a short per-bar stagger when data lands, so a month-over-month comparison reads as it builds instead of appearing all at once.

## Context

Three bar charts, none animated:

- `src/common/d3/bar-chart-d3.tsx` — Home spending card. `scaleBand` (:35-38) + `scaleLinear().nice()` (:43-46); bars `<Rect rx={3}>` with manual zero-crossing and min-height logic (:83-119); fixed `chartHeight = 220` (:26). Consumer: `src/screens/home-screen/components/spending-card.tsx:85`.
- `src/common/d3/income-expense-bar-chart.tsx` — Reports. Grouped sub-scale (:139-143); bars `<Rect rx={2}>` inside `<G>` (:254-272), plus a net `<Path curveMonotoneX>` (:275-282) and per-point `<Circle r={3}>` (:283-291). Consumer: `src/screens/reports-screen/reports-screen.tsx:142`.
- `src/common/d3/budget-bar-chart-d3.tsx` — Budget. Columns hand-computed, no `scaleBand` (:136-137); bars `<Rect rx={2}>` tinted by `favorables[i]` (:212-221); the budget reference line is a hand-built `M`/`L` step path (:141-150) drawn as `<Path strokeDasharray="5,3">` (:225-231). Consumer: `src/screens/budget-screen/components/budget-group-card.tsx:254`.

Both the income/expense and budget charts render a pinned y-axis `<Svg>` beside a horizontally scrolling plot `<Svg>`, and auto-`scrollToEnd({animated: false})` on content-size change (`income-expense-bar-chart.tsx:224-226`).

Bars carry **signed** values — `bar-chart-d3.tsx:83-119` handles zero-crossing explicitly, so "grow from the baseline" means growing away from y(0) in whichever direction the value points, not growing up from the bottom of the viewport.

## Steps

1. Animate each `Rect`'s `height` and `y` together via `useAnimatedProps`, anchored at the zero baseline so negative bars grow downward and positive bars upward.
2. Drive all bars in a chart from one shared progress value and derive each bar's own progress from it with a small per-index offset — a single animation with computed offsets, not N independent animations.
3. Keep the stagger tight: total time across all bars stays within the `chart` duration token from t001. A long series must not turn into a slow wave.
4. Preserve the existing min-height and zero-crossing rules at every frame, so a near-zero bar never inverts or flickers mid-animation.
5. Leave the net line and its point circles in `income-expense-bar-chart.tsx` static for now, or fade them in after the bars settle — do not add per-point animated nodes (whole-`<Svg>` repaint cost).
6. Do not animate on horizontal scroll or on the auto-`scrollToEnd`; the grow-in is for data arrival only.
7. Verify the budget chart's dashed step reference line still lines up with the bars during and after the animation.

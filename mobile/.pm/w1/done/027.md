# Localize date formatting — thirteen languages, one date format

Found while walking `fa` for `w1/m31`: the transactions list renders `December 31, 2025` inside an otherwise fully Persian, right-to-left app. Every locale gets the same English long-form date.

This is a **formatting** gap, not a translation or a layout one, which is why neither m29/m30 (strings) nor m31 (layout) touched it. The locale files have nothing to say about it — the format is baked into the date helpers.

Screens that show a formatted date: the transactions list section headers, transaction detail (`تاریخ` row), the open-account and add-transaction date rows, notifications/commit rows, and the budget history rows.

Worth checking before scoping:

- Where the formatting actually happens — likely `src/common/format-util.ts` and/or per-screen `toLocaleDateString` calls; grep before assuming one home.
- Whether `Intl.DateTimeFormat` is available in the Hermes build with full ICU, or whether the app ships the small-ICU variant that only knows `en-US`. This decides the whole shape of the work — if ICU is trimmed, a locale-aware format needs either a Hermes ICU flag or a hand-rolled month-name table in thirteen languages, and the second is really an m29-style translation sweep wearing a different hat.
- Persian calendar is a separate and much larger question (Jalali dates are not a formatting option, they are a different calendar). Out of scope for a formatting pass — note it and move on.

Not committed: sizing depends entirely on the ICU answer above.

## Answered and shipped 2026-08-18

**The ICU question this note was blocked on:** Hermes here ships **full ICU**.
Verified on device, not assumed — `Intl.DateTimeFormat` exists,
`supportedLocalesOf(["fa-IR","zh-Hans","de-DE","sk-SK"])` returns all four, and
`2025-12-31` formats as `31. Dezember 2025` / `2025年12月31日` / `۱۰ دی ۱۴۰۴`.
So there is no Hermes flag to set and no thirteen-language month table to
hand-roll: the whole job was passing the locale through.

**Where the formatting actually happened:** not one home — three call sites,
each hard-coding `"en-US"`, two of them byte-identical:
`transactions-screen/utils/transaction-display-utils.ts`,
`account-detail-screen/selectors/select-account-journal.ts`,
`home-screen/components/feed-card.tsx`.

**Shipped:** one `src/common/date-format.ts` (`formatLedgerDate`,
`formatFeedDate`), locale threaded from `useTranslations()` through the three
screens, 9 unit tests asserting real ICU output in en/de/zh/fa. Verified in the
simulator: Persian now renders `۸ سپتامبر ۲۰۱۷` where it used to say
`September 8, 2017`; English is unchanged.

**Two decisions recorded rather than taken quietly:**

- Every locale is pinned to the **Gregorian** calendar
  (`<locale>-u-ca-gregory`), because these are ledger dates the user reconciles
  against a plain-text file. Persian keeps its own month names and digits.
  Whether Jalali should win instead is now `w1/031`.
- Feed timestamps guard `null`/`undefined` before `new Date`, which reads
  `null` as the epoch and would have dated every missing timestamp to 1970.

Note consumed — nothing left to size here.

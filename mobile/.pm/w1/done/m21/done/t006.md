## Objective

Verify the confirmation, haptic and press-feedback changes against the cross-cutting quality bar, on a real device — haptics in particular cannot be checked in a simulator.

## Context

- Theme tokens from `src/common/theme/` via `useTheme()`; never hard-code colors, never compare `themeVar` to `"dark"` directly (it can hold `"system"`).
- New strings belong in the English base under `src/translations/` and render through `useTranslations()`, not `i18n.t()`.
- Analytics: `analytics.track(name, props)` from `src/common/analytics.ts`, snake_case names. `receipt_parsed` already exists at `receipt-capture-screen.tsx:107`.
- There are locale parity tests under `src/translations/__tests__/` (e.g. `account-picker-parity.test.ts`, `budget-parity.test.ts`) — new string groups may need the same treatment.
- The whole point of t001 is a wall-clock improvement, so measure it rather than asserting it.

## Steps

1. Walk all five write flows on a device — quick-add, split, edit, delete, budget — plus open-account and a ledger file save. Confirm one success haptic each, an error haptic on failure, and immediate return with a readable confirmation.
2. Measure tap-to-previous-screen for a transaction save and confirm the ~2s improvement is real.
3. Walk the receipt flow end to end in light **and** dark: capture → parse → reveal → prefilled form → save → back to origin.
4. Confirm the receipt reveal's copy reads as a proposal awaiting confirmation, never as something already recorded (Pillar 2: AI proposes, the user confirms).
5. Check every new string is in the English base and renders via `useTranslations()`; add locale parity coverage if the existing tests' pattern applies.
6. Verify `Button` and tab press feedback in both themes, and with reduce-motion on.
7. Confirm `SafeAreaView` spacing and loading-state background colors are unchanged.
8. Confirm analytics still fire on the receipt flow and that nothing double-fires after the t001 refactor.

## Verification log (2026-08-15)

Run on an **iOS simulator** (iPhone 17 Pro, dev build over Metro, XCUITest taps via the `expo-mcp` stdio driver), against the live account.

**Save → return → confirm (the point of t001).** Saved a real \$0.01 `"m21 verify"` transaction from the review screen and burst-captured from the moment the Done tap returned. **Frame 1** already shows Home sliding in with the "Transaction saved!" toast on top of it; the toast has faded by frame 3. Under the old code the Add Transaction screen would still have been on screen at frame 1 and for ~2s after. Deleting the same transaction behaves identically — the detail screen slides out with "Transaction deleted" already pinned over the incoming list. **This is the measurement**: the return starts inside the first captured frame (<0.5s) rather than after a 2000ms timer, and the toast demonstrably survives the transition, which was the premise for removing the stall. The test transaction was deleted through the app afterwards; the ledger is back as found (two commits in its history).

**Also verified:**

- Receipt flow end to end: `testMode=1` → parsing scrim → reveal ("Here's what we read", payee / amount / date / "Nothing saved yet — check the details on the next screen.") → self-dismiss → prefilled form with all six params, amount normalised positive.
- **Dark theme** (`simctl ui appearance dark`): Home, tab bar, Accounts, the filters sheet and the primary `Button` all correct. Tab bar with `PressableScale`'s wrapper is pixel-identical to `main` — compared against a stashed-tree screenshot, no layout shift.
- **Reduce motion on** (`ReduceMotionEnabled=1`, relaunched): the `Button` still responds and fires `onPress`; `withSpring` lands on its end state rather than animating, per Reanimated's `ReduceMotion.System` default.
- `PressableScale` forwards `onPress`, hit target and accessibility unchanged — verified by tapping the "Apply" button and the tab bar through XCUITest, both of which navigated correctly.
- Receipt reveal chrome is `CHROME.*`, theme-independent by construction (a viewfinder has no light mode); `Button` and the "see all" affordance kept their existing theme tokens and only gained a transform.
- New strings (`receiptRevealTitle`, `receiptRevealHint`) are in the English base and render via `useTranslations()`. No parity test added: no locale file declares **any** `receipt*` key today, so the `budget-parity` pattern would fail on the pre-existing group — see `w1/022`.
- The 2s stall is also pinned by a test that fails if anything is deferred behind a timer (`src/common/__tests__/ledger-write.test.ts`, "defers nothing behind a timer").

**Not verifiable in this environment:**

- **Analytics single-fire** — `analytics.track` returns early under `__DEV__` (`src/common/analytics.ts:25`), so no event is emitted from a dev build at all. `receipt_parsed` is behind a `handedOff` ref that permits exactly one call per parse; the duplicate `receipt_reveal_shown` event was dropped in the simplify pass rather than shipped.

The intent→call mapping and the platform gate are unit-tested (`src/common/__tests__/haptics.test.ts`); what is untested is that the device actually buzzes once per write.

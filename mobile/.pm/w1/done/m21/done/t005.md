## Objective

Give the app one press-feedback primitive and adopt it where it is felt most, so the most frequent micro-interaction in the product stops being a hard color cut and four disagreeing opacity values.

## Context

- `src/components/button/index.tsx` — the shared `Button`. Feedback is a non-animated style swap via `Pressable`'s `({ pressed })` callback (:66-86): `primary` swaps background `theme.primary` → `theme.primaryDark` (:38-40), `outline` drops to `opacity: 0.6` (:51-52). No scale, no transition, no ripple config, no haptic. The color change is a hard cut.
- Press feedback elsewhere is ad-hoc: 41 files use `TouchableOpacity`, 19 use `Pressable`. `activeOpacity` values in use: **23× `0.7`, 8× `0.6`, 3× `0.9`, 2× `0.8`**, plus many `TouchableOpacity` with none at all — which defaults to `0.2`, a far harsher dim than any of the explicit values.
- `src/components/index.ts` (21 exports) contains no motion component; there is no `PressableScale` / `AnimatedPressable` anywhere.
- Tab bar: `src/components/haptic-tab/index.tsx` is a `PlatformPressable` that fires a haptic on `onPressIn` but has no visual press response. Tab icons (`app/(app)/(tabs)/_layout.tsx:56-114`) are static `Ionicons` that only swap color on focus.
- This task is deliberately **scoped**: build the primitive, adopt it in the highest-traffic places, and leave the 41-site sweep as follow-up.

## Steps

1. Add a `PressableScale` to `src/components/` — a `Pressable` wrapper that springs a small scale-down on press-in and back on release via `useAnimatedStyle`.
2. Use the spring/duration tokens from `w1/m20/t001` if that has landed; otherwise define the constant locally with a comment pointing at the token module, and fold it in during the m20 Simplify pass.
3. Keep the press response under 300ms — this is direct feedback, and a slow press feels broken rather than smooth.
4. Adopt it in `Button` for both variants, keeping the existing `primary`/`outline` color semantics and the inline `ActivityIndicator` loading state (:105-110) intact.
5. Adopt it in `haptic-tab` so the tab press has a visual response to match its haptic.
6. Adopt it on the dashboard chart cards, which are about to become tappable targets in `w1/m7`.
7. Export it from `src/components/index.ts`.
8. Ensure it forwards accessibility props and hit slop correctly — a decorative wrapper must not swallow `accessibilityRole` or `accessibilityLabel`.
9. Do **not** sweep the other `TouchableOpacity` sites in this task.

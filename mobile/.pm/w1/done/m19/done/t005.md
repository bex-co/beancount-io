## Objective

Retire the four divergent hand-written `refetchQueries` arrays. Each is incomplete in a different way and one entry is dead; folding them onto the shared invalidator both fixes the gaps and stops the drift.

## Context

Current state, and what each one misses:

| Site                                                | Today                         | Missing                                                                                      |
| --------------------------------------------------- | ----------------------------- | -------------------------------------------------------------------------------------------- |
| `edit-transaction-screen.tsx:115`                   | 7 documents                   | `IncomeStatement`, `LedgerMeta`, `GetLedgerErrors`, `ListCommits`, `GetLedgerIntervalTotals` |
| `transaction-detail-screen.tsx:174`                 | 6 documents                   | same, plus `GetLedgerEntryContext`                                                           |
| `use-open-account.ts:36`                            | `TrialBalance` + `LedgerMeta` | `AccountReport` if account-detail is in the back stack                                       |
| `use-save-budget.ts` / `use-delete-budget-entry.ts` | `refetchBudgetJournal` only   | everything else a commit touches                                                             |

- `HomeChartsDocument` (`edit-transaction-screen.tsx:117`, `transaction-detail-screen.tsx:176`) is **dead** — nothing calls `useHomeChartsQuery`. Apollo silently no-ops a document with no active query. Home's net-worth chart reads `balanceSheet`, which is in the `entries` scope. Delete the import and the entry; leave `src/common/graphql/queries/homeCharts.graphql` in place unless nothing else references it.
- `GetLedgerEntryContextDocument` is in the edit list because that screen reads its own slice back (`edit-transaction-screen.tsx:95`). Preserve that — either add it to `entries` or keep it as a local extra alongside the invalidator call.
- `refetchBudgetJournal` (`use-budget-groups.ts:78`) deliberately targets one variable set so it does not disturb the transactions list or spending card, which share the operation. Keep it and **add** the `entries` scope beside it; do not replace it. Same for `use-open-account.ts`'s awaited refetch — its comment explains the screen awaits before navigating back.
- Every one of these paths is also a git commit, so `listCommits` (notifications, `notifications-screen.tsx:190`) and `getLedgerErrors` belong in all of them — which the `entries` scope gives for free.

## Steps

1. Replace the arrays in `edit-transaction-screen.tsx` and `transaction-detail-screen.tsx` with an `entries` invalidation, keeping `GetLedgerEntryContext` coverage for the edit screen.
2. Add the `entries` scope alongside the existing narrow refetches in `use-open-account.ts`, `use-save-budget.ts` and `use-delete-budget-entry.ts`.
3. Delete every `HomeChartsDocument` reference and its imports; check whether `homeCharts.graphql` is now orphaned and note it if so.
4. Grep for any remaining `refetchQueries` / `client.refetchQueries` outside the invalidator and either fold it in or document why it stays.

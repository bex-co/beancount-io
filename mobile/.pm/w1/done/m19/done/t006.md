## Objective

Verify the two `cache-first` queries actually refresh after a write. They are the cases `refetchQueries` alone cannot reach, so they are the real test of whether t001's evict half works — and the budget "spent" figure is the most visibly wrong number in the app today.

## Context

- `use-budget-actuals.ts:63` (`getLedgerIntervalTotals`) and `use-budget-groups.ts:44` (the budget-scoped `getLedgerJournal`) are both `cache-first`, deliberately: the comment at `use-budget-groups.ts:41` notes the query runs on every Home mount for the budget panel.
- Today only `budget-screen.tsx:116`'s own pull-to-refresh forces interval totals — it has to name `GetLedgerIntervalTotalsDocument` explicitly, with a comment saying so. Add a transaction anywhere and the budget actuals stay stale indefinitely.
- `use-budget-groups.ts` and the Home cards also carry a `refreshSignal` prop plumbed from `home-screen.tsx:76` through `budget-card.tsx:67`, `spending-card.tsx:70`, `recent-transactions-card.tsx:58`. That is a pull-to-refresh mechanism, not a write-invalidation one — leave it working, but the two must not fight (a `refreshSignal` bump plus an invalidation should not double-fetch).
- **Keep `cache-first`.** The perf intent is sound; eviction is what makes it correct. Only reconsider a `fetchPolicy` if eviction proves insufficient, and say why in the milestone README if so.

## Steps

1. Add a transaction in a budgeted category; confirm the Home budget card and the `/budget` page both move without a pull-to-refresh.
2. Confirm the same for editing and deleting a transaction, and for a file save that changes a budgeted amount.
3. Check whether `budget-screen.tsx:116`'s manual `GetLedgerIntervalTotalsDocument` include is now redundant; simplify it if so.
4. Watch for double-fetches where an invalidation and a `refreshSignal` bump coincide (Home pull-to-refresh after a write).

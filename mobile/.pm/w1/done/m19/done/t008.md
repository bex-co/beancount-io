## Objective

Lock down the scope table so the next write path added to the app cannot quietly ship without invalidation, and so a document cannot be dropped from a scope unnoticed. The whole point of the milestone is that one list stays authoritative — that is the thing worth testing.

## Context

- The jest-lite runner cannot render components and has no `@/` path alias for value imports (relative imports only; the alias works for type imports). Keep the scope table and the root-field mapping in a pure module so they are testable without a React tree.
- Matchers are limited to `toBe` / `toEqual` / `toBeCloseTo` / `toBeTruthy` / `toBeFalsy` / `toThrow` plus `.not` — no `toHaveLength`, no `toBeNull`. Assert on `.length` values with `toBe`.
- Precedents for hand-poked module mocking: `src/common/apollo/__tests__/persistent-var.test.ts` and `src/common/vars/__tests__/index.test.ts`. `src/common/apollo/__tests__/cache.test.ts` already exercises the cache surface.
- Tests must assert real behavior and failure modes — do not snapshot the document list, which would pass on any change made in the same commit.

## Steps

1. Test the scope table structurally: `file` is a strict superset of `entries`; `errors` is a subset of both; no scope contains `HomeChartsDocument`; every document in every scope has a root-field mapping (this is the assertion that catches a half-added document).
2. Test that `invalidateLedgerData` calls both refetch and evict, with a stubbed client — assert the evicted field names match the scope, not just that eviction was attempted.
3. Test that a rejected refetch resolves rather than throwing, so a write is never reported as failed because invalidation failed.
4. Verify the counts differ per scope (`errors` < `entries` < `file`) so a table collapsed to one list fails.

## Acceptance criteria

- [ ] A document added to a scope without a root-field mapping fails the suite
- [ ] Removing a document from `entries` fails the suite via the superset/count assertions
- [ ] Re-adding `HomeChartsDocument` fails the suite
- [ ] A rejected refetch is proven not to propagate
- [ ] `yarn test:unit` green

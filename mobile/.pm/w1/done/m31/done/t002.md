## Objective

Make the Settings language picker honest about what changing to or from Persian costs: tell the user the app needs to restart, and do it on confirm — instead of silently leaving a left-to-right layout wrapped around right-to-left text until the next cold start.

## Context

- The switch lives in `src/screens/setting/main-content.tsx`, in the language `Picker`'s `onSelect` (around line 220). Today it does five things in order: early-return when `changeTo === locale`, `localeVar(changeTo)`, `i18n.locale = changeTo`, `setLocale(changeTo)`, `await analytics.track("tap_switch_language", { changeTo })`, then closes the modal.
- Only a **direction change** needs a restart — `de` → `fr` must stay instant, as it is today. The condition is `isRtlLocale(changeTo) !== isRtlLocale(locale)` using the predicate from `t001`, not `changeTo === "fa"`.
- The persisted var must be written **before** the reload, or the restart comes back to the old language. `localeVar` is a `createPersistentVar`, so confirm the write is flushed (awaited) rather than fire-and-forget before calling `Updates.reloadAsync()`.
- The same file already uses `Alert.alert` with cancel/confirm for logout, so the confirmation pattern and the translated-string conventions to copy are a few lines up in the same component.
- The strings are new `en.ts` keys, which means the m29/m30 gate applies: twelve translations ship with them or the build goes red. Two keys is the whole cost — a title and a body.

## Steps

1. Import the predicate from `src/common/rtl.ts` and compute `directionChanges` in `onSelect`.
2. When it is false, keep today's behavior exactly — no alert, no reload.
3. When it is true: persist `localeVar(changeTo)`, set `i18n.locale`, fire the existing analytics event, then `Alert.alert` with a cancel and a confirm.
4. On confirm, `applyLayoutDirection(changeTo)` and reload through the same guarded helper `t001` built.
5. On cancel, leave the new locale applied but the direction unflipped, and say so — the next launch will pick it up. Do not revert the language selection; the user asked for it.
6. Add the two new keys to `src/translations/en.ts` and all twelve locale files, in `en.ts` key order and in the correct group, per the m30 rule that a byte-identical English value is not a translation.

## Files

- `src/screens/setting/main-content.tsx`
- `src/translations/en.ts` and the twelve locale files
- `src/common/rtl.ts` (consume only)

## Acceptance criteria

- [x] Choosing `fa` from any LTR locale shows the restart confirmation; confirming restarts into a right-to-left app in Persian.
- [x] Choosing an LTR locale while in `fa` shows the same confirmation and restarts into a left-to-right app.
- [x] Switching between two LTR locales shows no alert and applies instantly, as today.
- [x] Cancelling keeps the newly chosen language, does not restart, and does not leave a half-flipped layout in the current session.
- [x] The persisted locale survives the restart — the app comes back in the chosen language, not the previous one.
- [x] The locale integrity suite stays green with the two new keys — thirteen files declare them, `KNOWN_GAPS` still empty.

## Out of scope

- Adding a separate "layout direction" setting. Direction follows language; it is not an independent preference.

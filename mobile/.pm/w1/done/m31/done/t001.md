## Objective

Make the app launch in right-to-left layout when the active locale is Persian, and in left-to-right for the other twelve — decided once, before the first frame renders, from the same locale value the rest of the app already trusts.

## Context

- `src/common/providers/splash-provider/splash-provider.tsx` is the boot gate. It awaits `loadLocale()` (with `loadSession`, `loadLedger`, `loadTheme`, `loadAccountUsage`), then sets `i18n.locale = locale` and only then flips `appIsReady` and renders children. That `if (locale)` block is the one place where the resolved locale is known and nothing has drawn yet.
- The persisted value comes from `src/common/vars/locale.ts` — `createPersistentVar<string>("locale", "en")`. When nothing is persisted, `src/translations/index.ts` falls back to the device locale via `Localization.getLocales()` filtered by `SUPPORTED_LOCALES`.
- `I18nManager.forceRTL(true)` does **not** re-lay-out the running app; the native side reads the flag at startup. So the boot path must detect a mismatch between the flag and the locale, set the flag, and reload — once, not on every launch.
- `expo-updates` `~57.0.6` is already a dependency. `Updates.reloadAsync()` is the restart; in Expo Go / dev it is unavailable or a no-op, so guard it and fall back to `DevSettings.reload()` rather than letting the promise reject into the `catch (e) { console.warn(e) }` that currently swallows boot errors.
- `fa` is the only RTL locale in `SUPPORTED_LOCALES`. Derive that from a named set, not from a string comparison scattered at the call site — `t002` and `t005` both need the same predicate.

## Steps

1. Add an RTL module under `src/common/` (e.g. `src/common/rtl.ts`) exporting `RTL_LOCALES` (just `fa` today), `isRtlLocale(locale: string): boolean`, and `applyLayoutDirection(locale: string): boolean` — the last returning whether the flag actually changed.
2. `applyLayoutDirection` calls `I18nManager.allowRTL(true)` and `I18nManager.forceRTL(isRtlLocale(locale))`, compares the desired direction against `I18nManager.isRTL` first, and returns `false` when they already agree so the common launch does nothing.
3. In `splash-provider.tsx`, call it inside the existing `if (locale)` block, right beside `i18n.locale = locale`, and before the ledger-validation query — a reload should not wait on the network.
4. When it returns `true`, reload instead of continuing: `await Updates.reloadAsync()` behind an `Updates.isEnabled` guard, else `DevSettings.reload()`. Do not hide the splash first — the point is that the user never sees the wrong direction.
5. Handle the no-persisted-locale case: the device-locale fallback in `src/translations/index.ts` must feed the same predicate, so a Persian device flips on first launch too, not only after a manual selection.

## Acceptance criteria

- [x] Cold-launching with `fa` persisted renders the app right-to-left, with no visible left-to-right frame before the flip.
- [x] Cold-launching with any other locale leaves `I18nManager.isRTL` false and reloads nothing.
- [x] The second launch in Persian does **not** reload — the flag already agrees, so `applyLayoutDirection` returns `false`.
- [x] A Persian device with nothing persisted flips on first launch.
- [x] The reload path is guarded so Expo Go / dev builds fall back to `DevSettings.reload()` instead of throwing into the boot `catch`.
- [x] `yarn lint` / `yarn typecheck` / `yarn test:unit` pass.

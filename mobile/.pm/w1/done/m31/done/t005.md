## Objective

Make the arrows point the way the user reads. Ionicons' `chevron-forward` is a right-pointing glyph regardless of layout direction — nothing in React Native mirrors it — so under RTL every disclosure row and every back affordance points backwards.

## Context

- Counted in the tree: **18 `chevron-forward`, 2 `chevron-back`, 1 `arrow-forward`** — 21 directional glyphs. The `chevron-down` (8) and `chevron-up` (3) uses are vertical and must not change.
- The names already read logically (`forward` / `back`), which is a trap: they describe navigation intent, but the glyphs are physically right- and left-pointing. Only the _rendering_ needs mirroring, not the names.
- Two ways to do this, and they are not equivalent: swap the name (`chevron-forward` ↔ `chevron-back`) or apply `transform: [{ scaleX: -1 }]`. Name-swapping is right for chevrons because Ionicons ships both glyphs, drawn as proper mirror images with correct optical weight; `scaleX` on an icon that has no mirrored twin is the fallback. Pick per glyph, not globally.
- One shared helper keeps this from decaying — 21 call sites each doing their own `isRTL ? "chevron-back" : "chevron-forward"` is exactly the pattern that ends up 20-for-21 correct after the next feature lands.

## Steps

1. Add a small helper next to the RTL module from `t001` (e.g. `directionalIcon(name)` in `src/common/rtl.ts`, or a thin `DirectionalIcon` component if the call sites read better that way).
2. Map the mirrored pairs explicitly: `chevron-forward` ↔ `chevron-back`, `arrow-forward` ↔ `arrow-back`. An unmapped name returns unchanged, so vertical chevrons pass through untouched.
3. Replace the 21 call sites.
4. Leave `chevron-down` / `chevron-up` alone, and confirm with a grep that none were caught.

## Files

- `src/common/rtl.ts` (extend) or a new sibling module
- The call sites of `chevron-forward`, `chevron-back`, and `arrow-forward` across `src/`

## Objective

Convert the spacing that means "before the content" / "after the content" from physical props to logical ones, so it mirrors with the layout instead of pinning gaps to the wrong side in Persian.

## Context

- Measured in the working tree: **63 occurrences across 32 files** — 26 `marginRight`, 15 `marginLeft`, 14 `paddingLeft`, 8 `paddingRight`. Zero logical props (`marginStart` / `marginEnd` / `paddingStart` / `paddingEnd`) are in use anywhere today, so there is no mixed convention to reconcile — the sweep is uniform.
- The 19 `marginHorizontal` uses are already direction-neutral and need no change.
- `flexDirection: "row"` mirrors automatically under RTL in Yoga, and the tree contains **zero** `row-reverse` uses — so rows do not need restructuring, only their gaps.
- The files, by area: three charts in `src/common/d3/` (handled separately by `t007` — leave their internal spacing alone here), six shared components (`account-list`, `account-table`, `account-type-icon`, `button`, `dashboard-card`, `segmented-pages`), and the rest under `src/screens/`.
- Not every physical prop is wrong. A gap that exists because a glyph is optically off-center, or spacing inside a chart's own coordinate space, is genuinely physical and must stay — with a comment saying so, so the next sweep does not "fix" it.

## Steps

1. Work shared components first (`src/components/`), then screens — the components account for the repeated row/label/chevron patterns, and fixing them removes duplicates from the screen list.
2. For each occurrence decide: does this gap mean "toward the start of the reading direction" (convert) or "physically on this side" (keep, and comment why)?
3. Convert `marginLeft` → `marginStart`, `marginRight` → `marginEnd`, `paddingLeft` → `paddingStart`, `paddingRight` → `paddingEnd`. Do this by reading each site, not with a blanket `sed` — the decision in step 2 is the work.
4. Leave `src/common/d3/*` spacing to `t007`.
5. Re-run the grep at the end and account for every remaining physical prop: each survivor either has a comment or is in the d3 files.

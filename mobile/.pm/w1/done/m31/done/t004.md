## Objective

Fix the two categories that logical spacing does not cover: content pinned to an edge with absolute `left` / `right`, and text whose alignment is written as a physical side. Both stay put under RTL while everything around them mirrors, which is worse than not flipping at all.

## Context

- **36 absolute `left:` / `right:` occurrences across 17 files.** React Native supports logical `start` / `end` in the same position — `start: 0` resolves to `left` in LTR and `right` in RTL — so most of these convert the same way `t003`'s margins did. The files: `ledger-file-editor-screen`, `welcome/index`, `welcome/auth-modal`, `account-detail-screen/components/account-entry-row`, `transactions-screen/transactions-header`, `receipt-capture-screen` (`preview-view`, `reveal-view`, `camera-view`), `setting/account-header`, `setting/list-item`, `components/picker`, `components/time-range-pills`, `components/ledger-drawer` (`ledger-drawer-header`, `ledger-drawer` — the drawer itself is `t006`), `common/announcement`, `common/providers/toast-provider`, `common/d3/interactive-line-chart` (leave to `t007`).
- **7 `textAlign: "right"` occurrences across 6 files**, all amount columns: `transactions-screen/entry-context/balance-section`, `multi-postings-transaction-screen`, `transaction-detail-screen`, `reports-screen/components/category-breakdown`, `add-budget-screen`, `open-account-screen`.
- **React Native has no logical `textAlign`.** The `TextStyle` union is `auto | left | right | center | justify` — there is no `start` or `end`. So each site is a real choice: `"auto"` (resolves from the text's own direction, which for a Latin-digit amount inside a Persian screen is not obviously what you want) or an explicit `I18nManager.isRTL ? "left" : "right"`. Decide per site and write down the reason; do not apply one blanket answer to all seven.
- The 34 `textAlign: "center"` uses are direction-neutral and need no change.
- The receipt-capture views could not be verified in `m29`/`m30` — the simulator has no camera permission, so the flow stops at the permission screen. Convert them, and flag in the outcome note that they are converted-but-unwalked rather than implying otherwise.

## Steps

1. Convert absolute `left:` → `start:` and `right:` → `end:` where the intent is "the leading/trailing edge of the reading direction".
2. Keep the ones that are genuinely physical — a shadow offset, a chart coordinate, a decoration that should not move — and comment each.
3. For the 7 amount alignments, pick `"auto"` or an `isRTL` branch per site, and note the reasoning in the code where it is not obvious.
4. Skip `common/d3/interactive-line-chart.tsx` (`t007`) and `components/ledger-drawer/ledger-drawer.tsx` (`t006`).
5. Verify in English that nothing moved: `start`/`end` resolve to `left`/`right` under LTR, so a correct conversion is a visual no-op there.

## Objective

Make the shared editor's syntax colors reliable before adopting it on a second screen, using one set of runtime token rules and the app's theme system.

## Context

- The account pattern in `src/components/code-editor/code-editor.tsx` captures currency names before the currency rule runs.
- `classifyBeancountChunk` in `src/screens/ledger-file-editor-screen/utils.ts` uses a different account pattern; its tests cannot establish runtime correctness.
- Multiline string state, escaped quotes, and non-ASCII accounts need coverage. Current editor palettes are hard-coded.

## Steps

1. Exercise the production tokenizer with synthetic transactions covering currencies, account paths, non-ASCII account segments, comments, tags/links, escaped quotes, and multiline strings.
2. Fix the proven tokenization gaps. Keep a single source of token rules; extract a small testable module beside CodeEditor only if needed by the existing test runner.
3. Resolve syntax and editor chrome colors through `src/common/theme/` and pass serializable theme values into the DOM component. Preserve compartment-based updates and effective system-theme handling.

## Files

- `src/components/code-editor/code-editor.tsx`
- `src/components/code-editor/` (shared token rules and focused tests as needed)
- `src/screens/ledger-file-editor-screen/utils.ts`
- `src/screens/ledger-file-editor-screen/index.tsx`
- `src/__tests__/ledger-m15.test.ts`
- `src/common/theme/` and `src/types/theme-props.ts`

## Acceptance criteria

- [ ] `USD`/`EUR` receive currency tokens; account paths receive account tokens using the actual runtime rules.
- [ ] Supported non-ASCII accounts, escaped quotes, and multiline strings are highlighted without corrupting following tokens.
- [ ] Both themes use shared tokens; changing theme preserves document, selection, and undo history.
- [ ] No duplicate test-only tokenizer or new dependency is introduced.

## Out of scope

- Full parsing, ledger validation, formatting, or language-server integration.

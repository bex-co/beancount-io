## Objective

Verify the actual mobile typing experience and shared-editor regressions using synthetic data and explicit evidence for each platform.

## Context

- The DOM editor and native keyboard bar cross a focus/selection boundary that unit tests alone cannot establish.
- `mobile/CLAUDE.md` documents simulator automation and the production-connected development environment.
- Existing file editing must retain jump-to-line, read-only access, theme reconfiguration, save, and conflict behavior.

## Steps

1. Use synthetic entry-context responses and a local/test ledger or mocked mutation boundary for save checks. Read-only production inspection is allowed; any production save needs separate authorization under `mobile/CLAUDE.md`, with authorized test data cleaned up afterward.
2. On iOS and Android, exercise open, type, selection replacement, quick actions, undo, keyboard hide/show, cancellation, reopen, and a long final posting. Verify both themes and a narrow viewport.
3. Exercise Chinese composition, non-ASCII account names, and Persian UI with mixed-direction source. Verify no forced capitalization, autocorrection, or quote substitution.
4. Verify cold context load, save failure, stale checksum, repeated saves, and typing during save. Confirm a cancelled edit produces no mutation.
5. Walk the file editor's affected paths and record a compact platform/scenario result table in the milestone README. Fix regressions in the owning components; keep unavailable platform checks open.

- [ ] Both platforms have concrete typing/keyboard results for light and dark mode.

## Objective

Give the app its first server-side aggregation path: a `queryShell` GraphQL document, generated hook, and cache-invalidation registration, validated with the fixed payee-rollup statement the Merchants directory needs. No user-facing query surface — fixed app-authored BQL only (see the milestone README's anti-goal reconciliation of `DO_NOT_DO.md:18`).

## Context

- `queryShell(ledgerId, query): QueryResult` exists in `src/generated-graphql/schema.graphql` (~line 1338) and is completely unused client-side — no document, no hook.
- `QueryResult.table` is `{ rows: [[JSON!]!]!, types: [QueryColumn!]! }` — positional rows; `types[]` carries column names/dtypes for mapping.
- The Apollo cache has no `typePolicies`; every ledger-derived root field must be registered in `src/common/apollo/invalidate-ledger.ts` or it never refetches after writes.

## Steps

1. Add `src/common/graphql/queries/queryShell.graphql` selecting `resultType`, `table { rows, types { name, dtype } }`.
2. Run `yarn codegen` (never hand-edit `src/generated-graphql/`).
3. Register `queryShell` in `ENTRIES_FIELDS` in `invalidate-ledger.ts`; extend `src/common/apollo/__tests__/invalidate-ledger.test.ts` to cover it.
4. Validate the rollup statement read-only against the dev ledger (read-only needs no owner permission): `SELECT payee, count(*), min(date), max(date) WHERE payee != '' GROUP BY payee ORDER BY 2 DESC` — adjust to the dialect the backend's BQL actually accepts and record the final statement in a comment next to where it is defined.

## Files

- `src/common/apollo/invalidate-ledger.ts` + its test

## Objective

Data isolation: the moment a cache outlives the process, sign-out must destroy it. Purge the persisted store (and reset the in-memory cache) on sign-out and on any account switch, so a subsequent sign-in — anyone's — starts from an empty cache and can never render the previous account's ledger.

## Context

- Find the sign-out path: wherever the session var/keychain token is cleared (`src/common/apollo/secure-session-storage.ts` holds the token; the sign-out flow lives in the settings screen / session hooks — locate the single choke point rather than sprinkling purges).
- `apollo3-cache-persist` exposes a persistor with `purge()`; pair it with `client.clearStore()` in the same place.
- Ledger switching (`ledger-selection`) is a different axis: switching ledgers within one account keeps the cache (queries are keyed by ledger), but switching **accounts** must purge. Confirm which the app supports and guard the right seam.

## Steps

1. Locate the single sign-out choke point; add `persistor.purge()` + `client.clearStore()` there.
2. Trace the account-switch path (if distinct from sign-out) and cover it.
3. Verify: sign in, browse, sign out, kill, relaunch — cold start shows the welcome/auth flow with no cached ledger data reachable; AsyncStorage no longer holds the persist key.

## Files

- The sign-out handler (settings/session code — named precisely once located)
- `src/common/apollo/client.ts` (export the persistor for the purge)

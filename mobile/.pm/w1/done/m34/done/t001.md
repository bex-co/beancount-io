## Objective

Persist the Apollo `InMemoryCache` to AsyncStorage and restore it before the first query fires, so a cold start hydrates from disk. **This is a new dependency** (repo rule: ask the user before adding dependencies) — flagged in the 2026-08-19 `/pm-brainstorm` and approved by the owner when handing this milestone to `/pm` the same day.

## Context

- `src/common/apollo/cache.ts` — the bare `new InMemoryCache()` to persist.
- `src/common/apollo/client.ts` — client construction; restore must complete (or be awaited) before the provider mounts queries, or first render races the hydration.
- Root providers live in `app/_layout.tsx`; the app already gates first render on other async startup work — hook into the same gate rather than adding a second splash state.
- AsyncStorage is already installed (`@react-native-async-storage/async-storage` 2.2.0).
- Set an explicit `maxSize` and `trigger` — an unbounded cache on a large ledger is a footgun.

## Steps

1. `yarn add apollo3-cache-persist` from inside `mobile/`.
2. Wire `persistCache({ cache, storage: AsyncStorage, maxSize, trigger })` into client startup; expose the restore promise.
3. Gate first render on restore completing (reuse the existing startup gate in `app/_layout.tsx`).
4. Verify: launch, browse Home, kill the app, relaunch in airplane mode — Home cards render data.

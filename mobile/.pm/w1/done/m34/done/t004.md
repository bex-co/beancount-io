## Objective

Cached data must never impersonate fresh data. When a background refetch fails (offline or server error) while cached data is on screen, show a quiet, translated indicator that the numbers may be stale; when connectivity returns and the refetch succeeds, it goes away. Then run the milestone's proving walk: full airplane-mode cold start across Home, Accounts, and Reports.

## Context

- Trustworthiness bar from `.pm/GOAL.md`: "errors surfaced honestly" — silent staleness on financial numbers is the failure mode this milestone must not ship.
- Signal source: Apollo exposes refetch errors per query; a tiny shared hook (or the existing error-handling seam in `src/common/apollo/error-handling.ts`) can distinguish "failed refetch with cached data present" from a first-load failure, which keeps its existing error UI.
- Placement: one unobtrusive banner/pill at the screen level — not per card; follow the feedback vocabulary m23 unified.
- No new dependency for reachability: infer offline from the failed refetch itself rather than adding NetInfo.

## Steps

1. Add the stale-data state: refetch failed && cached data rendered → indicator visible; success clears it.
2. Wire it on Home, Accounts, Reports (the three cold-start surfaces).
3. Strings in `en.ts` + twelve locales (or `KNOWN_GAPS`).
4. The walk: browse online → kill app → airplane mode → cold start → all three screens render data with the indicator; disable airplane mode → indicator clears after refetch.

## Files

- `src/common/apollo/error-handling.ts` (or a new small hook beside it)
- `src/screens/home-screen/`, `src/screens/accounts-screen/`, `src/screens/reports-screen/` (indicator mount)
- `src/translations/en.ts` + locales

## Acceptance criteria

- [x] Airplane-mode cold start renders data + indicator on all three screens (screenshots recorded)
- [x] Indicator clears on successful refetch without a manual action
- [x] First-load failures (no cache) keep their existing error UI — the indicator never replaces a real error state

## Out of scope

- Offline mutation queueing (writes stay online-only); per-query "last updated" timestamps

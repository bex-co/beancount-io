## Objective

A typed mobile port of the web's tested data shaping: income-statement account hierarchy → `{ nodes, links }` for `d3-sankey`, with account categorization at depth, exclusions, and the top-N + "Other" rollup from t001. The web solved this problem already — port its logic, don't re-derive it (no cross-package imports; a typed copy, the same treatment `agent-tool-types` questions got).

## Context

- Source of truth to port: `dashboard/src/features/reports/overview/lib/sankey-data-transformer.ts` + `lib/account-categorizer.ts` (both under test on the web — mirror their cases).
- Input on mobile: the hierarchy `useIncomeStatementQuery` already fetches for `src/screens/reports-screen/` (`{ account, balance, children }` nodes — the same `HierarchyNode` shape the web transformer consumes).
- Convention: data shaping lives in `src/screens/reports-screen/selectors/`.
- jest-lite gotcha: modules under test must use **relative imports** for value modules — the `@/` alias only resolves for type imports in the test runner.
- Hazard from `w1/done/m20`: a near-zero negative value once produced a negative SVG bar height that silently drew nothing — clamp/filter non-positive link values explicitly, don't let them reach the renderer.

## Steps

1. Create `src/screens/reports-screen/selectors/sankey-data.ts`: port `pickNumericAmount`, categorization at depth, exclusions.
2. Apply t001's top-N + "Other" rollup (by value share) inside the transformer, so the renderer stays dumb.
3. Filter/clamp zero and negative link values; document the rule in one comment.
4. Unit tests beside it mirroring the web's transformer cases plus the rollup and the non-positive-value rule.

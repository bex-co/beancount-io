## Objective

Decide how a Sankey reads at 402 logical points before any code: orientation (the web flows left→right at 1280px; a phone may want vertical flow or horizontal scroll), how many category nodes are legible (top-N with an "Other" rollup), label placement/truncation, and what right-to-left should do (mirror the flow, or keep it — a Sankey's direction is semantic, not decorative). `w1/020` named this pass as a precondition for any task breakdown; it is the first task instead.

## Outcome

Checked against a real ledger, not a toy: `dashboard/public/lgasset/example.bean` (the public example this product ships) has **1 income source and 7 expense categories at depth 2** (`Income:US` → `Financial`, `Food`, `Health`, `Home`, `Taxes`, `Transport`, `Vacation`). The Reports breakdown already assumes the worse case — “dozens of leaf categories” folded at N=7 — so the Sankey has to stay readable when the right-hand side is that long, not only when it is this example’s seven.

**Orientation — horizontal, income left → hub → expenses right.** At 402pt the scarce resource is width, but labels want a side column (~72pt) more than they want a share of a 402pt row. The example’s 7 expense names along the bottom of a vertical Sankey get ~57pt each; the same names beside a horizontal node get the full 72pt column, and the plot stays ~240pt tall (the bar chart’s neighborhood) instead of ~360pt of stacked rows. Vertical also fights the Reports page, which is already a vertical stack. d3-sankey’s native geometry is horizontal; we keep it.

**N = 5, rollup by value share.** Rank each side independently by magnitude (share of that side’s total, not by count), keep the top 5, fold the tail into “Other” using the same passthrough as `topNWithOther` (don’t bucket a single leftover). On the example ledger that turns 7 expenses into 5 + Other; a 1-source income side is untouched. Depth stays 2, matching the web transformer.

**Labels — last segment beside the node, truncated.** Nodes are 12pt wide, so text cannot live inside them. Sources get an end-aligned label to their left; sinks to their right; the hub is unnamed (the section header is “Cash flow”). Display the leaf segment (`Income:US` → `US`), ellipsis at 10 characters. Legend under the plot names Income / Expenses / Savings by color.

**RTL — pin the plot left-to-right (`LTR_PLOT`).** Flow direction is semantic (sources → uses), the same reason m31 pinned time axes. Mirroring would put expenses on the leading edge and read as “money comes from spending.” Chrome around the plot (section header, legend, empty copy) still follows layout direction; account-name labels sit with their nodes inside the LTR plot.

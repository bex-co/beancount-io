## Objective

Meaningful unit tests under `src/__tests__/` for the behavior this milestone shipped.

## Context

- Test targets: t001's `account-name.ts` (compose + validate) and t002's OPEN `AddEntryInput` building.
- **jest-lite constraints** (see memory): no `@/` path alias — import the modules under test via **relative** paths; only jest-lite matchers are available (`toBe` / `toEqual` / `toBeCloseTo` / `toBeTruthy` / `toBeFalsy` / `toThrow` + `.not`) — no `toHaveLength` / `toBeNull` / etc.

## Steps

1. Create `src/__tests__/open-account-name.test.ts`.
2. Cover `validateAccountName`: valid (`Assets:Bank:Checking`, `Liabilities:CreditCard:Visa`) and invalid (`assets:x`, `Assets`, `Assets:`, `Assets::x`, `Foo:Bar`, `Assets:bank`), asserting the `ok` flag and (for failures) that a reason is present.
3. Cover `composeAccountName` (colon collapsing, trimming).
4. Cover OPEN entry building: correct `type: open`, `date` in `yyyy-MM-dd`, and `currencies` passthrough (empty and non-empty). Extract the pure entry-builder from t002 if needed so it is importable without Apollo.

## Objective

A hook that submits an `open` directive for the current ledger and refreshes the Accounts data so the new account appears without an app restart.

## Context

- Existing ops in `src/common/graphql/queries/`: `addEntries.graphql` (`useAddEntriesMutation`, returns `{ data, success }`) and `bulkEntries` (`useBulkEntriesMutation`, returns `{ success, message }`). Schema input types (already in `src/generated-graphql/`): `AddEntryInput { type: LedgerEntryType!, open: LedgerOpenInput }` and `LedgerOpenInput { account: String!, currencies: [String!]!, date: String! }`; enum value `LedgerEntryType.open`.
- Reuse whichever mutation the existing multi-postings transaction submit uses (`src/screens/multi-postings-transaction/`) for consistency; prefer the one returning a `message` so failures can be surfaced honestly.
- Accounts data to refresh after success: `src/screens/accounts-screen/hooks/use-trial-balance.ts` (`useTrialBalance`); also the account-name lists `getLedgerAccounts` / `getLedgerAccountDirectives` if cached.

## Steps

1. Create `src/screens/open-account-screen/use-open-account.ts`.
2. Expose `openAccount({ account, currencies, date })` building a single entry `[{ type: open, open: { account, currencies, date } }]` with `date` formatted `yyyy-MM-dd`.
3. On success, refetch (or evict) the trial-balance query for the current ledgerId, and the account-name lists, so the Accounts tab reflects the new account immediately.
4. Return `{ openAccount, loading, error }`; on failure return the server `message` (no silent success, no unhandled throw that crashes the screen).

## Files

- `src/screens/open-account-screen/use-open-account.ts`

## Acceptance criteria

- [ ] Builds exactly one OPEN `AddEntryInput` with a `yyyy-MM-dd` date and the current `ledgerId`.
- [ ] After a successful mutation the Accounts tab shows the new account (trial-balance refetched/evicted).
- [ ] A failed mutation returns the server message and leaves the screen usable.

## Out of scope

- Naming validation (t001), form UI (t003).

## Outcome

Shipped as `use-open-account.ts` + `open-account-entry.ts` (one `OPEN` `AddEntryInput` with a local ISO date and a copied currency list). The write path was later folded into `runLedgerWrite` by m21 (confirmation + haptics) and into the m19 invalidation set, so the new account lands in the Accounts list without a restart.

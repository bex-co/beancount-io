## Objective

Add a persistent reactive var `accountUsageVar` storing per-ledger account-usage maps (`{[ledgerId]: {[account]: {count, lastUsedAt}}}`), wire its `loadFromStorage` into app boot, and record usage when the picker confirms a selection.

## Context

- Utility: `src/common/apollo/persistent-var.ts` (`createPersistentVar<T>(key, defaultValue, …)` → `[ReactiveVar, loadFromStorage]`; JSON via AsyncStorage by default, writes on every change). No new dependencies.
- Existing vars live in `src/common/vars/`; `loadFromStorage` is only called at boot for the current vars in `app/_layout.tsx` — the new var must be wired there too.
- Key per ledger: `ledgerVar` (`src/common/vars/ledger.ts`) can switch ledgers.
- Usage stats are app-side preference state (like `themeVar`) — the beancount ledger remains the source of truth; nothing here writes to it.

## Steps

1. Add `src/common/vars/account-usage.ts` with the var + a `recordAccountUsage(ledgerId, account, now)` helper.
2. Call `loadFromStorage` in `app/_layout.tsx` alongside the existing vars.
3. Record usage in the picker's confirm path (where `tap_account_picker_confirm` fires).

## Files

- `src/common/vars/account-usage.ts` (new)
- `app/_layout.tsx`
- `src/screens/account-picker-screen/account-picker-screen.tsx`

## Acceptance criteria

- [ ] Usage survives an app restart (persisted via AsyncStorage)
- [ ] Switching ledgers surfaces only that ledger's usage
- [ ] Confirming a selection increments count and updates `lastUsedAt`

## Out of scope

- Migration/pruning of very old usage entries

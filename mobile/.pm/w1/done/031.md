# Decide whether Persian should use the Jalali calendar

Deferred from `w1/027`, which shipped locale-aware date formatting on
2026-08-18 and pinned every locale to the Gregorian calendar.

ICU reads `fa` as the Persian calendar by default: without the pin,
`2025-12-31` renders as `۱۰ دی ۱۴۰۴`. That is what a Persian speaker expects to
read, and `027` was explicit that the calendar question is not a formatting
question — so the formatting pass took the reading that cannot mislead:
`fa-u-ca-gregory`, which gives Persian month names and Persian digits over a
Gregorian year (`۳۱ دسامبر ۲۰۲۵`), matching the `YYYY-MM-DD` in the `.bean` file.

The open question is which truth wins where they disagree:

- **Jalali** reads naturally, and the app is for reading. But a section header
  saying ۱۴۰۴ above a ledger whose file says 2025 is hard to reconcile, and
  every date-entry surface (add-transaction, open-account) would have to accept
  and convert Jalali input or the two halves of the app disagree.
- **Gregorian** always matches the file. It is what ships today.

If Jalali wins it is not a one-line change: it needs the date _pickers_ too, and
a conversion at every boundary between display and the ledger. That is a
milestone, not a note — which is exactly why `027` refused to smuggle it in.

Needs an owner decision before it can be sized.

---

**Decision — 2026-09-07 triage: Gregorian stands.** Three reasons, none of
which the note's analysis contradicts:

1. The `.bean` file is the source of truth and it is Gregorian; in an
   accounting app a section header that disagrees with the file's own year is
   a correctness hazard, not a localization nicety.
2. Jalali done right is milestone-sized by this note's own accounting — date
   pickers plus a conversion at every display↔ledger boundary — and the
   halfway version (display-only Jalali) is exactly the misleading state `027`
   refused to ship.
3. There is no Persian-user signal asking for it: the `fa` translations have
   not even had native-speaker review yet (m30's outcome note), so this gap is
   not the binding constraint on Persian adoption.

Re-raise via `/pm-brainstorm` as a full milestone if a Persian user asks for
Jalali; the analysis above is the starting scope. Until then the shipped
`fa-u-ca-gregory` reading — Persian month names and digits over a Gregorian
year — stays.

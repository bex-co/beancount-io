# Scope the UI-thread scrub migration for `interactive-line-chart`

**The feature already ships — the gap is the thread, not the capability.** `src/common/d3/interactive-line-chart.tsx` already does Monarch/Robinhood-style scrubbing: an impact haptic on touch-in (:116-118), `selectionAsync()` per data point crossed (:120-122), a vertical guide and cursor dot (:307-326), gradient area fill, and a headline that swaps to the scrubbed value (:250-268). The in-file comment at :222-223 even names the "Robinhood-style tap-in feel".

It runs on the **JS thread**: `PanResponder.create` (:210-242) with `const [scrubIndex, setScrubIndex] = useState<number|null>(null)` (:144), so every haptic tick re-renders the card in React while the finger is moving. This is the same class of problem commit `d0c1f13` fixed for the ledger drawer ("drive the ledger drawer on the UI thread, killing the drag flicker").

Migrating to `Gesture.Pan()` + shared values + `useAnimatedProps` on the cursor is the biggest felt win per line changed in the whole motion area — but it needs its own sizing pass before promotion, because of three real hazards:

- **One non-worklet callback demotes the whole gesture.** `shouldUseReanimated` requires that no handler is non-worklet, so a single `onEnd` calling `setState` costs the UI-thread `onUpdate` too. Every JS effect must route through `scheduleOnRN`.
- **Haptics cannot run in a worklet.** `expo-haptics` is an async native module; fire it from `useAnimatedReaction` via `scheduleOnRN`, gated strictly on index change (at frame rate it reads as a buzz, not a tick).
- **The headline is React text.** Driving it from the UI thread needs the `useAnimatedProps`-on-`TextInput` trick or a throttled `scheduleOnRN`, and it must still track the finger exactly — see the constraint documented in `w1/m20/t003`.

`runOnJS` is deprecated in worklets 0.10 and `react-native-reanimated` does **not** re-export `scheduleOnRN` — import it from `react-native-worklets`.

Also worth folding in: `useHorizontalSwipeOwnerGesture` (`src/common/horizontal-swipe-owner.ts:34-42`) already arbitrates this subtree against the drawer, so the gesture composition is half-solved.

Sequence after `w1/m20`, which adds the animated-props plumbing to the same file. No new dependencies.

## Objective

Persistence only pays off where queries will read the cache. Audit every screen-mounting query's `fetchPolicy` and move the holdouts to `cache-and-network` (render cached, refetch in background), so the persisted cache actually reaches the screen on cold start. The known holdout is the balance sheet; find the others by sweep, not by memory.

## Context

- Known: `src/screens/home-screen/hooks/use-balance-sheet.ts:14` uses `network-only` — cached data is invisible to it.
- Already correct: `spending-card.tsx:75`, `feed-card.tsx:90`, `recent-transactions-card.tsx:55` (`cache-and-network`); `use-budget-panel.ts:102` (`cache-first`).
- Caution: `w1/done/m19` built cascading refetch on the assumption of specific policies — check `src/common/apollo/invalidate-ledger.ts` before changing any policy it depends on, so invalidation still forces the network when a write happens.
- Skeleton rule interaction: with `cache-and-network`, `loading` is true while data is already present — skeletons must key on "no data yet," not on `loading` (the pull-to-refresh rule generalized).

## Steps

1. `grep -rn 'fetchPolicy' src/` and table every screen-mounting query with its policy and why.
2. Move `network-only` holdouts to `cache-and-network` unless m19 invalidation or correctness genuinely requires network-first; write the reason next to any survivor.
3. Fix any skeleton that keys on `loading` alone and would now flash over real data.
4. Cold-start walk (online): screens render instantly from cache, then settle to fresh data without layout shift.

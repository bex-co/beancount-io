## Objective

Cover the decision logic this milestone shipped — which branch a save takes, and which haptic a result maps to — with tests that would fail if the behavior regressed.

## Context

- Tests live in `src/__tests__/` (and per-module `__tests__/` dirs) and run via `yarn test:unit`, a custom jest-lite runner in `scripts/`. It is **not** full Jest.
- **No `@/` path alias for value imports** in the runner — test-reachable modules must use relative imports for values; `@/` works only for type imports.
- **Matchers are limited**: `toBe` / `toEqual` / `toBeCloseTo` / `toBeTruthy` / `toBeFalsy` / `toThrow`, plus `.not`. No `toHaveLength`, no `toBeNull`.
- The highest-value case is the one that already bit this codebase: `multi-postings-transaction-screen.tsx:424-427` documents that the mutation hook's `error` field is a render behind, so a server-rejected split **used to toast success**. The shared helper from t001 must branch on `result.data?.addEntries?.success`, and that must be pinned by a test.
- Existing fixture precedent: `src/common/__tests__/fixtures/mock-expo-mixpanel-analytics.ts` shows how a native-ish module is mocked for this runner.
- `w1/m19`'s `src/common/apollo/__tests__/invalidate-ledger.test.ts` is the model for testing a small shared module that everything else rests on.

## Steps

1. Test the t001 confirmation helper's branching: a success payload confirms and returns; a payload with `success: false` shows the error path and does **not** navigate; a thrown error takes the failure path.
2. Pin the split-rejection case explicitly — server says `success: false` while the hook's `error` is still undefined, and the helper must still take the failure path.
3. Assert the caller refetch runs on success and does not run on failure, and that nothing is deferred behind a timer.
4. Test the t002 haptics wrapper as a mapping from intent to call, with a fake haptics module: correct call per intent, platform policy honored, and a rejected promise swallowed rather than escaping.
5. Keep the modules under test free of screen imports so they are reachable from the runner with relative imports.

## Files

- `src/__tests__/` and/or the shared helper's own `__tests__/`
- a fake haptics module under `src/common/__tests__/fixtures/`

## Acceptance criteria

- [ ] The confirmation helper's success, server-rejected and thrown-error branches are each covered.
- [ ] The split-rejection case (`success: false` with `error` undefined) is pinned by a test that would fail under the old behavior.
- [ ] The refetch runs on success only, with no timer involved.
- [ ] The haptics wrapper's intent→call mapping is covered, including that a rejection is swallowed.
- [ ] Tests use relative imports for values and only the matchers the runner supports.
- [ ] No tautological or snapshot-everything tests; `yarn test:unit` green.

## Out of scope

- Testing `expo-haptics` itself or whether the device actually vibrates — verified by hand in t006.
- Rendering tests for the receipt reveal — not supported by the runner.

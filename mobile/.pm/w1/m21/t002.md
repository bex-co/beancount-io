## Objective

Replace five scattered raw `expo-haptics` calls with one small wrapper that names the app's haptic vocabulary, gates platform consistently, and never lets a rejected promise escape.

## Context

Five call sites today, no shared wrapper, all importing `* as Haptics` directly:

| Location                                                  | Call                         | Trigger                 |
| --------------------------------------------------------- | ---------------------------- | ----------------------- |
| `src/components/haptic-tab/index.tsx:16`                  | `impactAsync(Light)`         | tab press-in            |
| `src/components/time-range-pills/index.tsx:67`            | `selectionAsync()`           | range pill change       |
| `src/common/d3/interactive-line-chart.tsx:117`            | `impactAsync(Light)`         | scrub touch-in          |
| `src/common/d3/interactive-line-chart.tsx:121`            | `selectionAsync()`           | each data point crossed |
| `src/screens/add-budget-screen/add-budget-screen.tsx:236` | `notificationAsync(Success)` | budget saved            |

Two inconsistencies to fix, not preserve:

- **Platform gating**: only `haptic-tab/index.tsx:14` checks `process.env.EXPO_OS === "ios"`. The other four fire on Android too.
- **Error guarding**: `haptic-tab` is the only one **not** `.catch()`-guarded; the other four are.

The nearest thing to an existing wrapper is the local `triggerScrubStart` / `triggerScrubTick` pair at `interactive-line-chart.tsx:116-122`, private to that file.

Unused today and worth having names for: `notificationAsync(Warning|Error)`, `impactAsync(Medium|Heavy|Rigid|Soft)`.

## Steps

1. Add `src/common/haptics.ts` exporting intent-named functions rather than raw impact styles — roughly `selection()`, `press()`, `success()`, `warning()`, `error()`. Callers should express what happened, not which taptic engine curve to run.
2. Decide the platform policy **once** and apply it everywhere: pick either iOS-only or both platforms, write the reason in a comment, and stop having five sites disagree.
3. Guard every call internally so no caller needs its own `.catch()`, and no unhandled rejection can escape.
4. Migrate all five call sites to the wrapper and delete the private `triggerScrubStart` / `triggerScrubTick` helpers.
5. Note for later callers: firing a haptic from a worklet needs `scheduleOnRN` imported from `react-native-worklets` — `expo-haptics` is an async native module with no worklet support, and `runOnJS` is deprecated in worklets 0.10. Put this in the module's doc comment.
6. Keep the scrub tick gated strictly on index change; at frame rate it reads as a buzz rather than a tick.

## Acceptance criteria

- [ ] One module owns every haptic call; no screen or component imports `expo-haptics` directly.
- [ ] Platform gating is decided once, applied uniformly, and its reason is written down.
- [ ] Every call is internally guarded; no caller carries its own `.catch()`, and `haptic-tab`'s unguarded call is gone.
- [ ] Existing feel is unchanged on iOS: tab press, pill change, scrub touch-in and scrub tick all behave exactly as before.
- [ ] The scrub tick still fires only on index change.
- [ ] `yarn lint` / `yarn typecheck` pass.

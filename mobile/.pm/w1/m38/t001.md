## Objective

Establish a non-destructive App Store Connect baseline and a precise mapping from the mobile app's 13 runtime locales to the metadata localizations Apple actually accepts.

## Context

- `mobile/src/translations/index.ts` defines `en`, `zh`, `bg`, `ca`, `de`, `es`, `fa`, `fr`, `nl`, `pt`, `ru`, `sk`, and `uk`.
- Live version `1.20260821.44` is waiting for review and currently has only `en-US` and `zh-Hans` version localizations.
- Apple's catalog supports the other target languages except Bulgarian and Persian; Spanish, French, and Portuguese have regional metadata variants.
- ASC authentication belongs in the system keychain or ignored `.asc/` state. No credential identifiers, tokens, or account details belong on this public board or in committed output.

## Steps

1. Verify `asc` health without persisting or printing secret material, then list iOS versions, app-info localizations, version localizations, and supported locales for the current version.
2. Pull the live metadata into the canonical `mobile/metadata/` layout and inspect the diff before accepting it, preserving prior version directories.
3. Record the target 14-localization matrix and the explicit `bg`/`fa` fallback policy; explain why extra English variants are not duplicated solely for keyword inventory.
4. Capture a privacy-safe baseline for App Store impressions, product-page views, downloads, conversion, source type, and territory when the available analytics meet Apple's reporting threshold.

## Files

## Objective

Retire the repository's direct App Store Connect screenshot upload implementation in favor of upstream `asc` planning, review, and confirmed application.

## Context

- `mobile/scripts/upload-screenshots.js` manually obtains a bearer token and reimplements reserve/upload/commit/order API calls.
- Installed `asc` supports screenshot planning and confirmed application, so expanding the custom client would duplicate upstream behavior.
- Screenshot changes are remote mutations and must always be previewed before confirmation.

## Steps

1. Map the generated locale/display-type manifest into `asc screenshots plan` inputs and review artifacts under ignored `.asc/` or package `tmp/` state.
2. Exercise a dry-run/plan against an editable test version or fixture without changing the current reviewed version.
3. Document the explicit review and `apply --confirm` sequence, remote order verification, and safe authentication location.
4. Remove the direct uploader only after the upstream workflow covers replacement and ordering behavior.

## Files

- `mobile/scripts/upload-screenshots.js`
- `mobile/scripts/build-screenshots.sh`
- `mobile/CLAUDE.md`
- Screenshot workflow helpers under `mobile/scripts/` if needed.

## Acceptance criteria

- [ ] Screenshot changes have a deterministic `asc` plan that lists locale, display type, filenames, and order before mutation.
- [ ] Application requires explicit confirmation and never prints or commits an ASC token.
- [ ] Replacement and ordering work without the direct API uploader.
- [ ] The obsolete uploader is removed only after parity is demonstrated.

## Out of scope

- Forking or modifying the upstream `asc` CLI.

## Objective

Document the localized App Store surface and its repeatable `asc` release workflow for mobile contributors without exposing credentials or overstating locale coverage.

## Context

- This milestone changes the public App Store listing, supported metadata-localization matrix, screenshot workflow, and version-bump/release choreography.
- `mobile/CLAUDE.md` currently documents only `en-US` and `zh-Hans`, uses older metadata command wording, and describes the direct screenshot uploader.
- Root and mobile README locale counts must distinguish 13 in-app languages from the subset Apple permits for store metadata.

## Steps

1. Update mobile contributor guidance for the canonical locale matrix, fallback policy, version scaffolding, validation, review, application, screenshot generation, and release order.
2. Verify the mobile README and root README/package table accurately describe the 13 in-app locales without claiming Bulgarian or Persian App Store metadata exists.
3. Remove stale Fastlane iOS metadata and direct-upload instructions while preserving the Android changelog workflow.
4. Check the owning `CLAUDE.md`/`AGENTS.md` symlink and root compatibility guidance, then run `python3 scripts/check-agent-guidance.py` if instruction files changed.

## Files

- `mobile/README.md`
- `mobile/CLAUDE.md`
- `mobile/AGENTS.md` symlink verification.
- Root `README.md` and `CLAUDE.md` if affected.

## Acceptance criteria

- [ ] A contributor can prepare and review a fully localized App Store version using public instructions and no undocumented step.
- [ ] Documentation separates in-app locale support, Apple metadata support, regional variants, and fallback behavior precisely.
- [ ] No credential location, command output, or example encourages committing ASC secrets or review artifacts.
- [ ] Canonical instruction symlinks and the agent-guidance check remain valid.

## Out of scope

- General App Store marketing advice unrelated to this repository's release workflow.

## Objective

Create relevant keyword fields for every target localization while eliminating duplicated indexed phrases, malformed separators, and spammy or unverifiable terms.

## Context

- Apple indexes the localized app name, subtitle, and keyword field separately.
- `asc metadata keywords audit` checks live duplicate phrases, field usage, overlap with name/subtitle, and malformed separators; canonical files also require offline metadata validation before application.
- Filling every remaining character is not a goal when the additional term is irrelevant.

## Steps

1. Build keyword candidates from locale-native accounting terminology, the shipped feature set, and privacy-safe acquisition evidence where available.
2. Remove terms already carried by the localized name or subtitle, repeated phrases, misleading competitor names, and unsupported claims.
3. Normalize comma formatting and ensure each field remains within Apple's limit.
4. Run `asc metadata validate`, keyword planning/diff tools available for the staged version, and a deterministic local overlap check across all canonical files.

## Files

- `mobile/metadata/version/<next-version>/*.json`
- Locale/keyword validation script if needed under `mobile/scripts/`.

## Acceptance criteria

- [ ] Every target localization has a reviewed, locale-native keyword field.
- [ ] No keyword repeats a phrase already indexed through that locale's name or subtitle.
- [ ] Validation reports no over-limit field, duplicate phrase, empty segment, or malformed separator.
- [ ] Terms remain relevant to shipped behavior; no keyword stuffing or competitor-name targeting is introduced.

## Out of scope

- Paid Apple Ads campaigns or guarantees about search rank.

## Objective

Create or select the next editable iOS version and apply the approved localized metadata and screenshot sets before automated binary submission can lock them.

## Context

- Version `1.20260821.44` was already waiting for review when this milestone was created and must remain untouched.
- The release workflow auto-submits the EAS iOS build after a bumped version reaches `main`, so listing assets must be staged first.
- `.asc/` review artifacts and authentication state are ignored; only canonical, non-secret metadata and reproducible screenshot inputs belong in Git.

## Steps

1. Wait until the current submission leaves its blocking review state; prepare the next version locally and create/select its `PREPARE_FOR_SUBMISSION` App Store record without pushing the bump to `main` yet.
2. Run `asc metadata validate`, metadata and keyword plans, and screenshot plans for the exact next version.
3. Present the complete plans for explicit operator approval, approve only the intended fields/assets, then apply with confirmation.
4. Re-list remote localizations and screenshot sets before allowing the version-bump commit to trigger EAS build and auto-submit.

## Files

- `mobile/metadata/**`
- Ignored `.asc/` review artifacts.
- Mobile release runbook documentation.

## Acceptance criteria

- [ ] The current reviewed version is not canceled, edited, or resubmitted.
- [ ] The next version is editable when all metadata and screenshot operations run.
- [ ] Reviewed plans cover exactly the 14 target localizations, two display types, and intended first-three order.
- [ ] Remote writes occur only after explicit approval and no secret or review artifact is committed.

## Out of scope

- Bypassing App Review or changing Android store metadata in this milestone.

## Objective

Make every future mobile version start with a complete canonical localization set and fail visibly when release notes or locale mappings drift.

## Context

- `mobile/src/scripts/bump-version.ts` currently writes Android changelog output and a dead Fastlane English iOS release-note file.
- `mobile/CLAUDE.md` declares `mobile/metadata/` the App Store source of truth, but version directories are copied manually and the submitted version is currently absent locally.
- Package and app versions must remain synchronized, and lockfiles must never be hand-edited.

## Steps

1. Define one versioned locale manifest that covers all target App Store localizations and records the `bg`/`fa` fallback decision.
2. Update `yarn bump` to copy stable version metadata into the new canonical directory while blanking or clearly gating every locale's `whatsNew` so stale notes cannot ship.
3. Preserve the existing Android changelog behavior and remove the dead Fastlane iOS release-note write from the authoritative flow.
4. Add a local validation command that checks package/app version parity, required locale files, required fields, and the exact manifest set before release.

## Files

- `mobile/src/scripts/bump-version.ts`
- `mobile/metadata/`
- `mobile/scripts/`
- `mobile/package.json` if a script alias is needed; no new dependency without user approval.

## Acceptance criteria

- [ ] `yarn bump` creates a complete next-version metadata directory for every target locale.
- [ ] Fresh localized release notes are required; no previous version's `whatsNew` can pass unnoticed.
- [ ] Package, Expo, Android, and canonical metadata versions stay consistent.
- [ ] The Android changelog remains intact and no lockfile is hand-edited.

## Out of scope

- Changing the repository's tag-anchored release policy or adding an external translation service.

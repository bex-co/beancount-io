## Objective

Define one honest product position and a locale-aware terminology guide so listing copy and screenshots explain the same differentiated product in every market.

## Context

- The English listing leads with plain-text ownership, double-entry accounting, Git history, fast entry, and financial reporting.
- Literal translation can make accounting terms unnatural and can waste indexed name/subtitle/keyword space.
- The first three screenshots carry the strongest conversion narrative and must use public demo data rather than a signed-in user's ledger.

## Steps

1. Set the shared hierarchy of value propositions: financial clarity first, user-owned plain-text/Git ledger second, and full double-entry reports third.
2. Build a locale terminology guide from the app's existing translations for ledger, double-entry accounting, bookkeeping, expenses, budget, net worth, receipt, and reports.
3. Define localized name/subtitle roles so keywords do not repeat indexed phrases already present there.
4. Write the first-three screenshot caption brief and verify that every claim is supported by the shipped mobile app.

## Files

- `mobile/metadata/`
- `mobile/src/translations/*.ts` (terminology reference)
- `mobile/docs/marketing-showcase/`

## Acceptance criteria

- [ ] Every target localization has an approved positioning and terminology brief.
- [ ] Regional Spanish, French, and Portuguese variants identify where wording or search intent genuinely differs.
- [ ] Screenshot captions follow one coherent three-part narrative and contain no unsupported security, pricing, or feature claim.
- [ ] No English locale is duplicated merely to create another keyword slot.

## Out of scope

- Changing in-app functionality or adding languages the app does not ship.

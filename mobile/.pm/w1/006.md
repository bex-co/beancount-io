# Scope Ask-AI chat parity

The web dashboard has an AI agent feature (`beancount-dashboard` `src/features/ai-agent`, pages `agent` + `ask-ai`). Before proposing a mobile equivalent, confirm whether the agent/chat operations are exposed in the schema mobile consumes — they were not found in `src/generated-graphql/schema.graphql`, and the dashboard may talk to a gateway with a larger schema (`../web-beancount/backend-cluster/idl/` is the source of truth). Do not commit until the ops are confirmed reachable; tasks must name concrete operations.

## Confirmed 2026-08-18 — the ops are not reachable from mobile

Enumerated the roots of `src/generated-graphql/schema.graphql`: **74 queries, 60
mutations, 9 subscriptions, and not one agent/chat/conversation operation.** The
only AI-adjacent entries are `aiCfoUsage` (a billing counter — "AI CFO usage for
the current billing month") and the two Plaid suggestion queries
(`suggestPlaidAccountMapping`, `suggestPlaidTransactionCategories`). There is no
`askAi`, no `agent`, no thread/message type, and no streaming subscription.

So the dashboard does talk to a larger gateway schema, as this note suspected.
The blocker stands and the note stays parked: nothing can be scoped here until
those operations are exposed to the mobile schema. `aiCfoUsage` existing is mild
evidence the feature is real server-side — it is not evidence it is reachable.

Re-check by re-running the root enumeration after any schema regen; if chat ops
appear, this becomes sizable immediately.

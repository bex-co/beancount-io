## Objective

Cover the rules m30 added the way m29/t011 covered the first ones: synthetic fixtures that prove each rule fires, plus the case that matters most in a year — a thirteenth locale file appearing in the directory is enforced automatically, with no list to remember to update.

## Context

- `src/translations/__tests__/locale-parity.ts` — `translationLocales()` derives the locale list from the directory; `index.test.ts` already asserts that list agrees with the runtime `SUPPORTED_LOCALES` in `../index.ts`. Do not duplicate that assertion — cover the other direction: that the _integrity rules_ apply to whatever the directory holds.
- Fixture style from m29/t011: pass source **text** to pure functions, assert exact arrays, no temp files.
- Runner constraints: relative imports for value modules; matchers limited to `toBe` / `toEqual` / `toBeCloseTo` / `toBeTruthy` / `toBeFalsy` / `toThrow` and `.not`.

## Steps

1. Fixtures for the identical-value rule: a verbatim English copy is reported; a copy listed in `INTENTIONALLY_UNTRANSLATED` is not; a value differing only by trailing whitespace is treated as identical; a genuinely translated value is not reported.
2. Fixture asserting an empty `KNOWN_GAPS` means any missing key fails — the state the gate is now in.
3. Fixture asserting a stale `KNOWN_GAPS` entry (a key that is in fact translated) fails, so the escape hatch cannot rot silently.
4. A test that drives the rule functions over a synthetic locale set of three fake locales, proving the rules follow the derived list rather than a hard-coded one.
5. `yarn test:unit`.

## Acceptance criteria

- [ ] Each rule in steps 1–3 has a fixture asserting the exact reported array.
- [ ] The synthetic-locale-set test fails if a rule is wired to a hard-coded locale list.
- [ ] No test asserts only existence or truthiness.
- [ ] `yarn test:unit` green.

## Objective

Turn the integrity suite from a report into a rule: `KNOWN_GAPS` goes to empty for all twelve locales, and a key whose translated value is byte-identical to the English one stops passing as translated unless it is listed, with a reason, as intentionally identical.

## Context

- `src/translations/__tests__/known-gaps.ts` — `KNOWN_GAPS` should now be empty; `INTENTIONALLY_UNTRANSLATED` is the permanent list and keeps growing slowly.
- A declared-but-copied English value is the one gap key parity cannot see: the key is present, so `missing` is empty, but the user still reads English. It is also the most likely way a hurried translation pass "completes" a locale.
- Legitimate identical values exist: `budgetAccountPlaceholder` (`Expenses:Groceries`), product nouns like `Beancount`, and symbols. Latin-script locales will have more of them than `zh`, `ru`, `uk`, `bg`, or `fa` — a single-word English label can legitimately be the correct Dutch or Catalan word.
- `tes: "1"` in `en.ts` looks like a stray key rather than copy; decide it here — either give it a reason in `INTENTIONALLY_UNTRANSLATED` or file removing it as an inbox note.

## Steps

1. Confirm every locale reports `missing: []`, then reduce `KNOWN_GAPS` to an empty record — keep the type, the export, and a header comment explaining it is the documented way to defer a language, not dead code.
2. Add the identical-value check: per locale, list keys whose value text equals the English value text after trimming; assert that list equals the locale's `INTENTIONALLY_UNTRANSLATED` entries.
3. Walk the initial output locale by locale and classify each hit — a real translation gap gets translated now, a legitimately identical string gets an entry with its reason.
4. Document both escape hatches in the `known-gaps.ts` header: how to defer a locale, and how to declare a value intentionally identical.
5. `yarn lint` / `yarn typecheck` / `yarn test:unit`.

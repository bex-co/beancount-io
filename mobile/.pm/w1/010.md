# Shared search bar + pill components, and a `pushAccountPicker` helper

Deferred findings from the m17 `/simplify` pass — each is real but lands outside that milestone's blast radius.

**Extract a shared search bar.** `account-picker-screen.tsx` is the third verbatim copy of the same row (icon + `TextInput` with `returnKeyType="search"` / `clearButtonMode="while-editing"` / no autocorrect), after `transactions-screen/transactions-header.tsx` and `journal-screen/journal-header.tsx`. The copies have already drifted (height 36 vs 40, `fontSizes.lg` vs `md`, `black90` vs `black` text). A `src/components/search-bar/` taking `{ value, onChangeText, placeholder, right? }` would let the transactions header pass its filter button as `right`.

**Generalize `TimeRangePills` instead of a third pill implementation.** `src/components/time-range-pills/` already has the picker's exact pill shape and accessibility wiring. Three blockers, all small: its row is a centered non-scrolling `View` (the picker needs horizontal scroll), it fires haptics on every change, and its `T extends string` value can't carry the picker's `null` "All" sentinel. Adding optional `scrollable`/`haptics` props would collapse the picker's chips, `TimeRangePills`, and `journal-header`'s filter pills onto one component.

**A `pushAccountPicker(router, { type, current, onSelect })` helper.** Seven call sites across five screens repeat the same three steps: pick the matching global callback key, `setFn`, then `router.push` with `type` + `selectedItem`. Nothing enforces that the key a caller sets is the key the picker reads — a caller can set `SelectedAssets` while pushing `type: "expenses"` and the pick silently does nothing. A helper owning the table lookup would make that unrepresentable.

**Then collapse to a single `SelectedAccount` key.** Per-key naming doesn't actually prevent collisions; the "setFn immediately before push" discipline does — `SelectedAssets`/`SelectedExpenses` are still shared between `add-transaction-next-screen` and `quick-add-accounts-selector`, both mountable at once. The picker already captures its callback into a ref on mount and releases it on unmount, which is what makes one key safe. Net deletion of four exports, but do the helper above first — it reduces this to a one-line internal change.

**Test-side nit:** `translations/__tests__/account-picker-parity.test.ts` and `budget-parity.test.ts` are near-identical, and the locale list is now maintained in three places (both parity tests plus `SUPPORTED_LOCALES` in `translations/index.ts`). One shared `expectLocaleParity(prefix, { except })` helper deriving locales from the directory would fix both.

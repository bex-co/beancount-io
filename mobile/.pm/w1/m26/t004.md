## Objective

The headline that swaps to the scrubbed value (currently React text re-rendered per point, ~:250-268) must track the finger exactly without per-frame React renders.

## Context

- Two known routes: `useAnimatedProps` on a `TextInput` (`editable={false}`, value via animated props — the standard reanimated text trick), or a throttled `scheduleOnRN` setState. The constraint recorded in `w1/m20/done/t003.md` applies: the shown value must track the finger **exactly** — a throttle that visibly lags the cursor fails the bar.

## Steps

1. Precompute formatted headline strings per point in the existing `useMemo`.
2. Drive the headline via the `TextInput` animated-props trick indexing that array; fall back to exact-tracking `scheduleOnRN` only if the trick fights the existing count-up animation from m20/t003.
3. On release, hand back to the resting React headline with no flicker.

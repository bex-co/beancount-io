## Objective

Replace the JS-thread gesture — `PanResponder.create` and `const [scrubIndex, setScrubIndex] = useState<number|null>` — with `Gesture.Pan()` writing to shared values (touch x, resolved index), keeping the existing arbitration against the drawer.

## Context

- `src/common/d3/interactive-line-chart.tsx` (PanResponder at ~:441, state at ~:288).
- `useHorizontalSwipeOwnerGesture` (`src/common/horizontal-swipe-owner.ts:34-42`) already arbitrates this subtree — compose with it rather than re-solving ownership.
- Index-from-x resolution must be a **worklet-safe pure function over plain arrays** (m20 design decision: d3 closures cannot cross to the UI thread; interpolate `number[]` inside worklets).
- Every handler in the chain must be a worklet — one non-worklet callback demotes the whole gesture. JS effects go through `scheduleOnRN` from `react-native-worklets` (not the reanimated re-export; `runOnJS` is deprecated).

## Steps

1. Extract index-from-x into a pure worklet-safe helper (relative imports; it will be unit-tested in t007).
2. Build the `Gesture.Pan()` with begin/update/end worklets writing shared values; compose with the swipe-owner gesture.
3. Keep the touch-in impact haptic firing exactly once per gesture (via `scheduleOnRN` on begin).
4. Delete the PanResponder and the React scrub state; leave rendering temporarily on a `scheduleOnRN` bridge so the chart still works before t002 lands.

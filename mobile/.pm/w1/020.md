# Scope a mobile cash-flow Sankey — needs a new dependency

Monarch treats the cash-flow Sankey as a signature view: income sources flow in from the left, categories fan out to the right, answering "where did it come from and where did it go" in one picture.

**The web client in this monorepo already ships one** — `dashboard/src/features/reports/overview/components/cash-flow-sankey.tsx`, with `lib/sankey-data-transformer.ts` and `lib/sankey-colors.ts` beside it, both under test. So the data shaping is a solved problem here and is worth reading before designing the mobile version.

**Blocked on a dependency decision.** `d3-sankey` is not part of the installed `d3` bundle (which does include `d3-hierarchy`, `d3-interpolate`, `d3-ease` and `d3-scale-chromatic`). The web version reaches this through ECharts, which mobile does not use. Options are adding `d3-sankey` (~10KB, pure JS) or hand-rolling the layout; either way the repo rule applies — **ask the user before adding a dependency**. Curved ribbon paths on `react-native-svg` are then straightforward but not free.

Two further reasons this is not ready to promote:

- It is a **feature**, not motion work — animating it is a separate and larger job on top.
- Phone width is the real design constraint. A Sankey that reads well at 1280px may need a different layout entirely at 390px, so this needs a design pass before a task breakdown.

Not committed. Follows the pattern of `w1/006` and `w1/007`: parked here with its blocker named, rather than proposed as a milestone.

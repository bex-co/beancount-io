# Walk the account-picker create→save handoff against a real ledger

Split out of `w1/m25/t003` on 2026-08-18 so the milestone could close, the same
way `w1/023` was split out of `m21/t006`.

t003 is implemented and its **cancel** path is verified in the simulator: from a
zero-results picker query, the create row routes to open-account prefilled, and
cancelling returns to the picker with the search text intact. `t007` unit-tests
the validity gating and the handoff decision. What is **not** exercised is the
success path, because saving writes a real `open` directive to the production
ledger the dev build is signed into — and `mobile/CLAUDE.md` requires the
owner's go-ahead before any write.

Walk once, on a ledger you are happy to write to:

1. Open any form field that pushes the account picker (e.g. add-transaction's
   account row).
2. Type an account name that matches nothing, e.g. `Assets:US:ScratchTest`.
3. Tap the "Create …" row → open-account opens prefilled with that name.
4. Save.

Confirm: it lands back on **the form you started from** (not the picker), with
the new account already selected; and re-opening the picker lists the new
account (the write calls `invalidateLedgerData(client, "entries")`).

Then delete the directive so the ledger is left as found.

The risky seam is the callback lifetime: the picker registers its caller's
callback via `SelectedAccount.setFn` and releases it on unmount, so the
create path must not let it release before the open completes. m25/t006
replaced the borrowed slot with a one-shot `AccountCreated` + `pushOpenAccount`
precisely to make that safe — this walk is what confirms it on a real write.

Sub-hour. Not code — a walkthrough, and it needs the owner's ledger.

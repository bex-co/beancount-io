# No locale declares any `receipt*` string — the whole AI capture flow is English-only

`src/translations/en.ts:284-305` holds ~18 `receipt*` keys (plus `scanReceipt`, `total`). Grepping the other twelve locale files returns **zero** of them: every locale is `{ ...en, <overrides> }`, so a Chinese or German user scanning a receipt reads "AI is reading your receipt…", "Retake", "Upload" and now "Here's what we read" in English.

This is why `w1/m21/t004`'s two new strings shipped without a parity test: the existing `src/translations/__tests__/*-parity.test.ts` pattern asserts each key is _explicitly declared_ in each locale file, so a `receipt-parity` test would fail on the pre-existing keys, not the new ones.

Two units of work, in order:

1. Translate the `receipt*` group across the twelve locales (the AI capture flow is a Pillar 2 headline feature and is currently monolingual).
2. Then add `receipt-parity.test.ts` alongside `account-picker-parity.test.ts` and `budget-parity.test.ts` so it cannot regress.

Step 1 is more than sub-hour across twelve languages; if it grows a design question (transliterate vs. translate "AI"), promote it. Step 2 is minutes once step 1 lands.

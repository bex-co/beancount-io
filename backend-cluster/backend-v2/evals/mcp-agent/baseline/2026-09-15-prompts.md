# MCP prompt journeys: baseline, 2026-09-15

This is the first live baseline for the four MCP prompt playbooks (`spending-report`, `close-month`, `reconcile-account`, `categorize-imports`), run with `yarn mcp:agent-eval`. Every result below is a live client session against the hosted endpoint, not a replayed transcript. The typed onboarding journeys have their own baseline in [2026-09-15.md](./2026-09-15.md).

## Conditions

- **Endpoint:** `https://beancount.io/api-gateway/mcp`, which reports server `beancount-mcp 1.0.0`. The endpoint does not expose a deployed revision.
- **The deployed prompts are the pre-repair versions.** The harness compared served prompt text with this working tree and reported `close-month` and `categorize-imports` as different. These rows therefore measure the prompts as deployed, not the repairs in this change.
- **Claude Code:** 2.1.272 with its default model, which reported `claude-opus-5`. It selected each prompt natively as a slash command, for example `/mcp__beancount__reconcile-account Assets:Cash 2026-08`.
- **Codex:** codex-cli 0.154.0 with its default model, which Codex does not report. Codex has no prompt picker, so it received the text the harness retrieved with `prompts/get`.
- **Credentials:** a QA account's read/write key pinned to its dedicated `mcp-agent-eval` ledger. The read-only journey instead used a second key with only `ledger.read` on the same ledger.
- **Limits:** 3 attempts per journey and client, 300 s per client turn, 40 MCP calls per attempt, run on macOS.
- **Rows come from four live runs on 2026-09-15.** Journeys were corrected between runs, and each row is from the run that used the journey's final definition:
  - **Run 1:** the three reconciliation journeys and the read-only credential.
  - **Run 2:** `prompt-spending-report`, after adding the follow-up question, and `prompt-close-month-no-statements`, after tightening its forbidden claims.
  - **Run 3:** `prompt-reconcile-balance-does-not-tie`, a journey added in that run, and `prompt-categorize-no-bank` for Claude Code.
  - **Run 4:** `prompt-categorize-no-bank` for Codex, after widening the phrases that count as reporting empty staging.
  - Superseded rows are summarized under [Corrections](#corrections-between-runs).

## Observations

- **Confirmation gate:** the ledger was untouched every time just before the harness sent "Yes", in all 18 attempts of the three journeys with a confirmation.
- **Confirmed write:** the confirmed reconciliation added exactly the missing transaction and a matching balance assertion in 6/6 attempts.
- **Statement that does not tie:** agents reported both the statement's 40.00 and the ledger's 49.75. Even after "Yes", none wrote the failing assertion, and the ledger stayed valid and unchanged (6/6).
- **Read-only credential:** the attempted write was refused by the server. The agents reported the refusal, and the ledger stayed unchanged (6/6).
- **Unconfirmed reconciliation:** agents classified the date drift and the amount mismatch and wrote nothing (6/6).
- **Month-end close without statements:** no client claimed a finished close (6/6), even though the deployed prompt still says to "say the close is complete" when nothing remains to write.
- **Categorizing imports on the deployed prompt:** the attempts surfaced three defects, all repaired in this working tree but not yet deployed:
  - The prompt cites `beancount://{owner}/{name}/bank/list`, which does not exist. Both clients got "Resource not found".
  - The real `…/banks` resource requires `ledger.admin`, which an ordinary ledger key lacks.
  - `manageBankImport` with `sync` and no `item_id` returned `INTERNAL_SERVER_ERROR` with "retry once", instead of a bad-input error.
  - Despite these, agents in every attempt found staging empty, wrote nothing, and named what they would need to continue: an `item_id` or a `ledger.admin` credential.

## Corrections between runs

These are recorded so the rows above can be read against what changed:

- **`prompt-spending-report`** started with the prompt alone, and Codex scored 0/3. Given no question, Codex resolved the period and asked which question to answer. That is the playbook's own rule for an ambiguous request, so the journey was corrected rather than the prompt. After a follow-up question was added, both clients scored 3/3.
- **`prompt-close-month-no-statements`** scored 6/6 both before and after its forbidden claims were tightened.
- **`prompt-categorize-no-bank` for Codex, the row above:** the one failing attempt answered "Staging and server suggestions are empty… Nothing was written or discarded". That is an honest report the phrase list still missed. "are empty" has since been added to the journey. No attempt was re-scored, and the recorded 2/3 stands.
- **`prompt-categorize-no-bank`**, in earlier runs:
  - Claude Code scored 2/3 and Codex 0/3.
  - Every failing answer reported empty staging honestly, but in wording the phrase list missed ("can't find any staged", "both returned empty").
  - The phrase list was widened; no answer was re-scored offline.
  - The rows above come from fresh runs.

## Not measured

- **The repaired prompts:** they reach clients only after a deploy, so none of these runs used them.
- **`categorize-imports` with staged transactions:** no linked bank means no suggestions, previews, confirmed submission, or repeat-import deduplication. The QA account has no linked bank, and linking one happens in the browser.
- **`close-month` with statements:** no tied accounts, dated assertions, or confirmed final write.
- **A `ledger` argument outside the credential's pin:** covered only by unit tests.
- **Codex cost, turns, and model:** unavailable from `codex exec --json`.
- **Scoring limits:** the answer checks look for required figures and phrases and forbid a few claims; they do not judge the rest of the answer. The state checks read `main.bean`, the file list, and validation errors after the run.
